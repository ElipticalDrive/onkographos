# Edge Groups

Also called: Edge Group Analysis

## Overview
Edge Groups is a classification framework for isosurface extraction methods that groups triangle configurations by the connectivity of the cell edges intersected by the isosurface, enabling systematic analysis and bounding of triangle quality [S1]. It partitions edge configurations into equivalence classes based on cubic cell symmetries, where the quality of an edge group is defined by the worst-case triangle quality generated within that group [S1]. Unlike prior approaches that rely on intuition to move sampling grid points or cut points, edge groups provide a formal combinatorial framework that explains why warping or connectivity modifications improve quality [S1]. It sets itself apart from siblings like [Snap Marching Cubes](2181-snap-marching-cubes.md) or [Preprocessed Marching Cubes](3765-preprocessed-marching-cubes.md) by focusing on the topological connectivity of active edges rather than geometric displacement or precomputed tables, serving as an analytical tool to identify and replace problematic triangulation cases in [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md).

## How it works
**Inputs and Outputs:**
*   **Input:** The standard Marching Cubes (MC) cell configuration (case index derived from vertex signs relative to an isovalue) and the geometric positions of the 8 vertices of the cubic cell.
*   **Output:** A classification of each generated triangle into one of 8 Edge Groups, and optionally, a modified MC lookup table where connectivity for problematic cases is replaced to avoid low-quality edge groups.

**Data Structures:**
*   **Edge Group Index:** An integer from 0 to 7 identifying the equivalence class of the triangle's active edges.
*   **Cut Point Parameters:** A vector $\mathbf{t} = (t_A, t_B, t_C)$ where each $t_i \in [0, 1]$ represents the normalized position of a cut point along an active edge.
*   **Quality Function:** $q: \mathbb{R}^n \to \mathbb{R}$, where $n$ is the number of active edges in the specific MC case (ranging from 3 to 12).

**Definitions:**
*   **Active Edge:** An edge of the cubic cell intersected by the isosurface.
*   **Cut Point:** The intersection point of the isosurface with an active edge.
*   **Edge Group:** A set of symmetrically equivalent edge configurations that define a triangle. Two edge configurations are equivalent if their representation can be transformed into each other by the symmetries of the cubic cell [S1].
*   **Triangle Quality Metric:** Radii-ratio, defined as the ratio of the incircle radius to the circumcircle radius of a triangle, normalized to $[0, 1]$. An equilateral triangle achieves the maximum quality of 1 [S1].

**Numbered Steps:**

1.  **Identify Active Edges:** For a given MC case, determine which of the 12 edges of the cubic cell are intersected by the isosurface. Let the set of active edges be $E_{active}$.
2.  **Determine Triangle Connectivity:** Based on the MC case index, determine which three active edges form each triangle in the cell. A cell may contain up to 5 triangles.
3.  **Classify into Edge Groups:** Map each triangle's set of three active edges to one of the 8 Edge Groups. This is done by identifying the geometric relationship between the three edges (e.g., whether they share a vertex, are parallel, or are skew) and applying cubic symmetries to find the canonical representative. There are exactly 8 distinct edge groups in MC [S1].
4.  **Parameterize Cut Points:** For a triangle defined by edges $A, B, C$, define the cut points $c_A, c_B, c_C$ using parameters $t_A, t_B, t_C \in [0, 1]$. The positions are calculated as:
    $$
    c_A = p_0 + t_A (p_3 - p_0)
    $$
    $$
    c_B = p_0 + t_B (p_1 - p_0)
    $$
    $$
    c_C = p_4 + t_C (p_5 - p_4)
    $$
    where $p_0, \dots, p_7$ are the vertices of the cubic cell [S1]. Note: The specific vertex indices depend on the labeling convention of the cube and the specific edges $A, B, C$. Generally, $t_i$ represents the normalized distance from one endpoint of the edge to the cut point.
5.  **Evaluate Quality Bounds:** For each Edge Group, analyze the function $q(\mathbf{t})$ over the parameter space $\Theta = [0, 1]^n$ (where $n$ is the number of active edges in the case) to find the minimum and maximum radii-ratio. This identifies the worst-case and best-case triangles for that group [S1].
6.  **Identify Problematic Groups:** Analyze the histograms of triangle quality for each group. Edge Group 2 is identified as the dominant source of degenerate triangles (quality approaching 0) and has a non-zero density of such triangles [S1]. Groups 0, 1, 3, and 6 can also produce degenerate triangles but with lower density or different characteristics. Groups 4, 5, and 7 do not produce degenerate triangles and share the same lower bound quality [S1].
7.  **Modify Lookup Table (Optional Improvement):** To improve mesh quality, replace the triangulation connectivity in MC cases that generate Edge Group 2 with an alternative triangulation that uses a different edge group (e.g., from Groups 4, 5, or 7). This exchange replaces a high-probability bad triangle with a slightly worse but non-degenerate one, improving overall mesh quality by an order of magnitude [S1].

def compute_radii_ratio_quality(p1, p2, p3):
    """
    Computes the radii-ratio quality of a triangle defined by vertices p1, p2, p3.
    
    Args:
        p1, p2, p3: 3D coordinates of the triangle vertices.
        
    Returns:
        quality: Float in [0, 1]. 1 for equilateral, 0 for degenerate.
    """
    # Calculate side lengths
    a = distance(p2, p3)
    b = distance(p1, p3)
    c = distance(p1, p2)
    
    # Calculate semi-perimeter
    s = (a + b + c) / 2.0
    
    # Calculate area using Heron's formula
    area_sq = s * (s - a) * (s - b) * (s - c)
    if area_sq <= 0:
        return 0.0
    area = sqrt(area_sq)
    
    # Calculate inradius r = Area / s
    r_in = area / s
    
    # Calculate circumradius R = (a * b * c) / (4 * Area)
    R_circ = (a * b * c) / (4.0 * area)
    
    if R_circ == 0:
        return 0.0
        
    # Radii-ratio
    return r_in / R_circ

**Parameters:**
*   **Cut point position parameter $t_i$:** A scalar value in the range $[0, 1]$ representing the normalized position of the $i$-th cut point along an active cell edge [S1].
*   **Isosurface Value:** Determines which edges are active.

**Edge Cases and Pitfalls:**
*   **Degenerate Triangles:** Edge Groups 0, 1, 2, 3, and 6 can produce degenerate triangles (quality 0). Edge Group 2 is the most problematic, having a non-zero density of degenerate triangles [S1].
*   **Symmetry Handling:** Correctly identifying edge groups requires careful handling of cubic cell symmetries. Misclassification can lead to incorrect quality bounds.
*   **Connectivity Consistency:** When modifying the MC table to avoid Edge Group 2, care must be taken to ensure that the new connectivity does not introduce non-manifold edges or holes in the mesh.

## Operating characteristics
*   **Time Complexity:** The classification of triangles into edge groups is $O(1)$ per triangle if a precomputed lookup table is used. The analysis of quality bounds is computationally expensive and is typically performed offline.
*   **Memory Complexity:** The edge group classification requires minimal additional memory (a small lookup table for group IDs). The modified MC table requires the same memory as the standard MC table.
*   **Measured Performance:** Replacing Edge Group 2 in MC cases improves the overall mesh quality by an order of magnitude in most tested datasets [S1].
*   **Strengths:** Provides a formal framework for understanding and improving mesh quality. Identifies the root cause of degenerate triangles (Edge Group 2).
*   **Limitations:** The analysis is specific to cubic cells and Marching Cubes. It does not directly apply to other isosurface extraction methods without adaptation. The improvement comes at the cost of potentially replacing good triangles with slightly worse ones (though still non-degenerate).
*   **When to Use:** When high-quality mesh topology is critical and degenerate triangles are unacceptable. It is particularly useful for post-processing or generating improved lookup tables for real-time rendering.
*   **When Not to Use:** When computational speed is the primary concern and some degenerate triangles are tolerable. Standard MC is faster and simpler.

## Background
Edge Groups was introduced by Carlos A. Dietrich, João L. D. Comba, Luciana P. Nedel, Carlos E. Scheidegger, and Cláudio T. Silva in the paper "Edge Groups: An Approach to Understanding the Mesh Quality of Marching Methods" [S1]. The paper was received on March 31, 2008, and accepted on August 11, 2008. It was published in the IEEE Transactions on Visualization and Computer Graphics. The work builds on the foundational Marching Cubes algorithm and aims to provide a theoretical basis for the empirical improvements seen in methods like Macet, which warps grid points to improve quality [S1].
