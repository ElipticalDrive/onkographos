# Simplified Marching Cubes

Also called: SMC discretization, binarized Marching Cubes

## Overview
Simplified Marching Cubes (SMC) is a surface extraction method that generates isosurfaces using only the vertices of the underlying regular 3D grid (cuberille), eliminating the need for linear interpolation and large lookup tables [S1]. It produces meshes with approximately half the vertices and triangles of standard Marching Cubes (MC) and Cuberille, significantly reducing memory usage while maintaining manifold topology [S1]. Unlike standard MC, which interpolates intersection points, SMC relies on integer arithmetic and a deterministic analysis of node counts and cumulative coordinates to classify configurations into eight reduced cases [S1].

## How it works
### Inputs and Outputs
*   **Input**: A scalar field $F(x, y, z)$ sampled on a regular 3D grid. A threshold value $\lambda$.
*   **Output**: A triangular mesh consisting of vertices from the grid and triangles connecting them.

### Data Structures
The algorithm processes the grid cell by cell. Each cube is defined by 8 vertices.
*   **Vertex Coordinates**: Each vertex $n$ ($n=0 \dots 7$) has normalized binary coordinates $c_x^n \in \{0, 1\}$ for axes $x \in \{i, j, k\}$. The index $n$ maps to coordinates via:
    $$ c_i^n = n \% 2, \quad c_j^n = (n \% 4) / 2, \quad c_k^n = n / 4 $$
*   **Vertex Status**: Vertices are classified as **nodes** (positive, value $\ge \lambda$) or **negative vertices** (value $< \lambda$).
*   **Memory Layout**:
    *   **Vertices**: 3 short integers (2 bytes each) per vertex, storing integer coordinates (must be $< 65535$) [S1].
    *   **Triangles**: 3 long integers (4 bytes each) per triangle, storing vertex indices [S1].
    *   **Per-Cube State**: For simulation updates, each cube may store a case indicator (1 byte, range 0-7) and coefficients for up to two planes ($hx + ky + lz + m = 0$), where $(h,k,l) \in \{-1,0,1\}^3$ and $m \in \mathbb{N}$. This totals 7 bytes per cube [S1].

### Definitions
*   **Binarization**: The scalar field is conceptually binarized:
    $$ F_B(x, y, z) = \begin{cases} 1 & \text{if } F(x, y, z) \geq \lambda \\ 0 & \text{else} \end{cases} $$
    Only the relative status (above/below threshold) is used; the magnitude of the difference is ignored [S1].
*   **Cumulative Coordinate ($C_x$)**: The sum of the coordinates of all positive vertices (nodes) along axis $x$:
    $$ C_x = \sum_{n \in \{\text{nodes}\}} c_x^n $$
*   **Neighbor Count ($N_x(n)$)**: The number of neighbors of vertex $n$ along axis $x$ in 6-connectivity. Using the complement $\overline{c}$ (where $\overline{0}=1, \overline{1}=0$):
    $$ N_i(n) = \overline{c_i^n} + 2 \times c_j^n + 4 \times c_k^n $$
    An **interface node** is a positive vertex with fewer than 3 node neighbors in 6-connectivity [S1].
*   **Triangle Type Criterion ($C_L$)**: An integer arithmetic criterion to distinguish triangle types based on vertex coordinates:
    $$ C_L(n_1, n_2, n_3) = \sum_{l=1}^3 \sum_{m=l+1}^3 \left( \sum_{x=i,j,k} (c_x^{n_l} - c_x^{n_m})^2 \right)^2 $$
    *   Type I (isosceles-right): $C_L = 6$
    *   Type II (right): $C_L = 14$
    *   Type III (equilateral): $C_L = 12$ [S1]

### Algorithm Steps
The algorithm iterates over every cube in the grid. For each cube, it determines the set of nodes (positive vertices). Let $N_{nodes}$ be the count of nodes.

1.  **Count Nodes**: Identify all vertices $n$ where $F(n) \ge \lambda$. Calculate $N_{nodes}$.
2.  **Trivial Cases**: If $N_{nodes} \in \{0, 1, 2, 8\}$, output no triangles. [S1]
3.  **Case 3 Nodes**:
    *   Check if $C_x = 0$ or $C_x = 3$ for any axis $x \in \{i, j, k\}$.
    *   If true, output **one Type I triangle** formed by the three nodes (they lie on a single cube face). [S1]
4.  **Case 4 Nodes**:
    *   **Subcase 8**: If $C_x = 0$ or $C_x = 4$ for any axis $x$, output **two Type I triangles** on the corresponding face. [S1]
    *   **Subcases 10/13**: If $C_x = 2$ for all axes $x \in \{i, j, k\}$, output **no triangles**. [S1]
    *   **Subcase 9**: Identify the single non-interface node (exhaustive test). Output **one Type III triangle** formed by the remaining three interface nodes. [S1]
    *   **Subcase 12**: Identify the singular node that has only negative neighbors. Switch its status to positive (conceptually). Re-process as Case 3 (Subcase 8) to build **one Type I triangle**. [S1]
    *   **Subcases 11/14**: Output **two Type II triangles**. Identify them by iterating over all pairs of nodes and checking connectivity/geometry. [S1]
5.  **Case 5 Nodes**:
    *   **Subcase 17**: If $C_x = 1$ or $C_x = 4$ for any axis $x$, output **two Type II triangles**. Identify by nested loops over nodes. [S1]
    *   **Subcase 15**: Identify the singular node with only negative neighbors. Switch its status. Re-process as Case 3 (Subcase 9) to build **one Type III triangle**. [S1]
    *   **Subcase 16**: Identify the Type III triangle using nested loops. Find the negative vertex that has node neighbors. Switch its status to positive. Re-process as Case 6 (Subcase 20) to build the remaining triangles (**two Type II, one Type III**). [S1]
6.  **Case 6 Nodes**:
    *   **Subcases 18/19**: Identify two negative vertices that have only node neighbors (exhaustive test). Build **two Type III triangles** formed by the neighbors of these negative vertices. [S1]
    *   **Subcase 20**: Output **two Type II triangles** formed by the correctly ordered interface nodes. [S1]
7.  **Case 7 Nodes**:
    *   Identify the single negative vertex. Form **one Type III triangle** using its three neighbors (which are interface nodes). [S1]

### Parameters
*   **Threshold ($\lambda$)**: The scalar value defining the isosurface. Only the binary status relative to $\lambda$ matters [S1].
*   **Vertex Memory**: 3 short integers (2 bytes) per vertex [S1].
*   **Triangle Memory**: 3 long integers (4 bytes) per triangle [S1].

### Edge Cases and Pitfalls
*   **Ambiguity**: Standard MC has ambiguous face configurations (e.g., Case 6) that can lead to non-manifold surfaces. SMC avoids this by using the "MC-patch" logic and treating configurations 11 and 14 as identical (symmetrical), ensuring topological consistency [S1].
*   **Bias**: SMC systematically produces negative volume biases for convex objects (negative surface bias) and positive surface bias for concave objects. The volume bias is larger than in MC or Cuberille [S1].
*   **Accuracy**: SMC accuracy is lower than standard MC but higher than Cuberille. For a discretized sphere, SMC surface error converges to 7%, while MC converges to ~0.4% [S1].
*   **Smooth Surfaces**: Approximation of smooth surfaces introduces a non-vanishing positive bias in surface estimation that does not decrease with increased sampling rate [S1].

## Operating characteristics
*   **Time Complexity**: Faster than standard MC. The speedup increases as the internal surface area of the volume increases [S1].
*   **Memory Complexity**: Uses half the memory of MC and Cuberille. The number of triangles and vertices is approximately cut by half [S1].
*   **Strengths**: Efficient for large images and moving boundary problems (e.g., deposition/ablation simulations). Guarantees manifold meshes. Uses integer arithmetic exclusively.
*   **Limitations**: Lower geometric accuracy compared to standard MC. Higher surface area bias for certain geometries.
*   **When to Use**: When memory and speed are critical, and the geometry is relatively simple or the bias is acceptable (e.g., porous media simulation, CVI modeling).
*   **When Not to Use**: When high geometric fidelity is required (use standard MC).

## Background
Simplified Marching Cubes was developed to address the computational demands of simulating deposition and ablation in complex media, such as in materials science (Chemical Vapor Infiltration and ablation modeling) [S1]. It was proposed as an efficient alternative to the popular Marching Cubes algorithm, which requires interpolation and large lookup tables [S1]. The method relies on the "MC-patch" configuration list to ensure topological consistency [S1].
