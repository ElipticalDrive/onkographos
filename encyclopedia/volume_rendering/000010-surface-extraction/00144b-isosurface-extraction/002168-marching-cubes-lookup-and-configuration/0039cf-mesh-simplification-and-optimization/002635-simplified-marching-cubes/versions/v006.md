# Simplified Marching Cubes

Also called: SMC discretization, binarized Marching Cubes

## Overview
Simplified Marching Cubes (SMC) is an isosurface extraction method that produces meshes using only vertices from the regular 3D grid, eliminating the need for linear interpolation and lookup tables [S1]. It achieves approximately half the memory and triangle count of standard Marching Cubes (MC) and Cuberille while maintaining intermediate accuracy [S1]. Unlike MC, which interpolates intersection points, SMC constructs triangles exclusively from grid nodes, ensuring manifold meshes without holes by resolving topological ambiguities through explicit node-status logic [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A scalar field $F(x, y, z)$ sampled on a regular 3D grid, and a threshold value $\lambda$.
*   **Output:** A mesh consisting of triangles defined by indices into the grid vertex array.

**Data Structures:**
*   **Vertex Storage:** Each vertex is stored as 3 short integers (2 bytes each), representing integer coordinates $(x, y, z)$. Coordinates must be $< 65535$ [S1].
*   **Triangle Storage:** Each triangle is stored as 3 long integers (4 bytes each), representing indices into the vertex array [S1].
*   **Cube Configuration Data:** For each cube, the algorithm determines a case indicator and plane coefficients. A compact representation uses 7 bytes: 1 byte for the case indicator, 2 bytes for normal coefficients $(h, k, l)$, and 4 bytes for the integer offset $m$ of the plane equation $hx + ky + lz + m = 0$ [S1].

**Vertex Classification:**
Vertices are binarized relative to $\lambda$. A vertex $v$ is a **node** (positive) if $F(v) \ge \lambda$, and **negative** otherwise [S1]. Only the relative status is used; magnitude differences are ignored [S1].

**Coordinate System:**
For a cube with vertices indexed $n=0..7$, the normalized coordinates $c_x^n \in \{0, 1\}$ for axes $x \in \{i, j, k\}$ are derived from the index:
$$ c_i^n = n \% 2 $$
$$ c_j^n = (n \% 4) / 2 $$
$$ c_k^n = n / 4 $$
where $/$ is integer division and $\%$ is the remainder [S1].

**Cumulative Coordinates:**
The cumulative coordinate $C_x$ for an axis $x$ is the sum of the coordinates of all positive vertices (nodes) in the cube:
$$ C_x = \sum_{n \in \{\text{nodes}\}} c_x^n $$
This value helps identify subcases without a lookup table [S1].

**Neighbor Count:**
The number of node neighbors $N_x(n)$ for a vertex $n$ along axis $x$ is computed to identify interface nodes. For axis $i$:
$$ N_i(n) = \overline{c_i^n} + 2 \times c_j^n + 4 \times c_k^n $$
where $\overline{c}$ is the bitwise complement to 1 ($1-c$) [S1]. An interface node is a positive vertex with at least one negative neighbor in 6-connectivity [S1].

**Triangle Types:**
SMC produces three types of triangles based on the edge lengths and geometry:
1.  **Type I:** Isosceles-right triangle.
2.  **Type II:** Right triangle.
3.  **Type III:** Equilateral triangle.

A criterion $C_L$ distinguishes these types using integer arithmetic:
$$ C_L(n_1, n_2, n_3) = \sum_{l=1}^3 \sum_{m=l+1}^3 \left( \sum_{x=i,j,k} (c_x^{n_l} - c_x^{n_m})^2 \right)^2 $$
Values are: Type I = 6, Type II = 14, Type III = 12 [S1].

**Algorithm Steps:**
The algorithm processes each cube independently. It first counts the number of nodes ($N_{nodes}$). Based on $N_{nodes}$, it applies specific logic to determine the output triangles.

1.  **Count Nodes:** Identify all positive vertices in the current cube. Compute $C_x$ for $x \in \{i, j, k\}$.
2.  **Case 0, 1, 2, 8 Nodes:** Output no triangles. (Cases 0, 1, 2, 4, 5, 6, 7, 22 in standard MC terminology map to these counts or are handled by symmetry/complement logic, but SMC explicitly outputs nothing for 0, 1, 2, and 8 nodes) [S1].
3.  **Case 3 Nodes:**
    *   If $C_x = 0$ or $3$ for any axis $x$, the three nodes lie on a single face. Output one **Type I** triangle [S1].
4.  **Case 4 Nodes:**
    *   If $C_x = 0$ or $4$ for any axis $x$, the four nodes lie on a single face. Output two **Type I** triangles [S1].
    *   If $C_x = 2$ for all axes $x$, output no triangles (Cases 10, 13) [S1].
    *   If one node is not an interface node (identified by exhaustive test of neighbors), output one **Type III** triangle formed by the remaining three interface nodes (Case 9) [S1].
    *   If one singular node has only negative neighbors, switch its status to positive, then re-process as 3 nodes (Case 8 logic) to build one **Type I** triangle (Case 12) [S1].
    *   Otherwise (Cases 11, 14), output two **Type II** triangles identified by nested loops over nodes [S1].
5.  **Case 5 Nodes:**
    *   If $C_x = 1$ or $4$ for any axis $x$, output two **Type II** triangles (Case 17) [S1].
    *   If one singular node has only negative neighbors, switch its status, then re-process as 3 nodes (Case 9 logic) to build one **Type III** triangle (Case 15) [S1].
    *   Otherwise (Case 16), identify the **Type III** triangle via nested loops. Find the negative vertex with node neighbors, switch its status, then re-process as 6 nodes (Case 20) to build the remaining triangles (two **Type II**, one **Type III**) [S1].
6.  **Case 6 Nodes:**
    *   If two negative vertices have only node neighbors (identified by exhaustive test), build two **Type III** triangles formed by their respective neighbors (Cases 18, 19) [S1].
    *   Otherwise (Case 20), output two **Type II** triangles formed by correctly ordered interface nodes [S1].
7.  **Case 7 Nodes:**
    *   Identify the single negative vertex. Form one **Type III** triangle using its three neighbors (which are interface nodes) [S1].

    """
    Extracts triangles from a single cube using Simplified Marching Cubes.
    vertices: list of 8 scalar values F(v0)...F(v7)
    threshold: float lambda
    Returns: list of triangles, where each triangle is a tuple of 3 vertex indices (0-7)
    """

    for n in range(8):
        if vertices[n] >= threshold:
            nodes.append(n)
            
    num_nodes = len(nodes)

    C_j = sum((n % 4) // 2 for n in nodes)
    C_k = sum(n // 4 for n in nodes)

                # Type I triangles are isosceles right.

                # Without explicit diagonal rule in source, we output 
                # the two triangles formed by the 4 nodes.

                # A square of side 1 has diagonal sqrt(2).

                triangles.append((nodes[0], nodes[1], nodes[2]))
                triangles.append((nodes[0], nodes[2], nodes[3]))

                triangles.append((nodes[0], nodes[1], nodes[2]))
                triangles.append((nodes[0], nodes[2], nodes[3]))

                triangles.append((nodes[0], nodes[2], nodes[3]))
        elif C_i == 2 and C_j == 2 and C_k == 2:

            pass

            # Or singular node with only negative neighbors (Case 12)
            # Or Cases 11, 14
            
            # Helper to check if node is interface
            def is_interface(n):

                neighbors = []
                if n % 2 == 0: neighbors.append(n+1)
                else: neighbors.append(n-1)
                if (n % 4) // 2 == 0: neighbors.append(n+2)
                else: neighbors.append(n-2)
                if n // 4 == 0: neighbors.append(n+4)
                else: neighbors.append(n-4)

                    if nb not in nodes:
                        return True
                return False

                triangles.append((interface_nodes[0], interface_nodes[1], interface_nodes[2]))

                # and others requiring loops.
                # [G] The source specifies "nested loops over nodes" for Type II.
                # Type II criterion CL = 14.
                
                # Check Case 11/14: Two Type II triangles
                # These cases have 4 nodes.

            for n in nodes:
                neighbors = []
                if n % 2 == 0: neighbors.append(n+1)
                else: neighbors.append(n-1)
                if (n % 4) // 2 == 0: neighbors.append(n+2)

                    neighbors = []
                    if nv % 2 == 0: neighbors.append(nv+1)

                neighbors = []
                if nv % 2 == 0: neighbors.append(nv+1)
                else: neighbors.append(nv-1)
                if (nv % 4) // 2 == 0: neighbors.append(nv+2)
                else: neighbors.append(nv-2)
                if nv // 4 == 0: neighbors.append(nv+4)
                else: neighbors.append(nv-4)
                # All neighbors are in nodes
                triangles.append((neighbors[0], neighbors[1], neighbors[2]))
        else:

            triangles.append((nodes[0], nodes[1], nodes[2]))
            triangles.append((nodes[0], nodes[2], nodes[3]))

    elif num_nodes == 7:

## Operating characteristics
*   **Memory:** SMC requires half the memory of MC and Cuberille. Vertices use 3 shorts (6 bytes) vs MC's 3 floats (12 bytes). Triangles use 3 longs (12 bytes) for all methods. The number of triangles and vertices is approximately halved [S1].
*   **Speed:** SMC is faster than standard MC, with speedup increasing as internal surface area increases. It avoids interpolation and large lookup table inversions [S1].
*   **Accuracy:** SMC accuracy is lower than MC but higher than Cuberille. For a discretized sphere, SMC surface error converges to 7%, while MC converges to ~0.4% [S1]. Normal RMS error for SMC is ~10-12 degrees, compared to ~4-6 degrees for MC on smooth images [S1].
*   **Bias:** SMC systematically produces negative volume biases for convex objects and positive surface bias for concave objects. The volume bias is larger than in MC or Cuberille [S1]. Approximation of smooth surfaces introduces a non-vanishing positive bias in surface estimation regardless of the method [S1].
*   **Topology:** SMC guarantees manifold meshes without holes by using "MC-patch" logic and treating configurations 11 and 14 as identical (symmetrical) [S1].

## Background
Simplified Marching Cubes was developed for materials science simulations, specifically for computing effective diffusivities in porous media and simulating matrix deposition in Chemical Vapor Infiltration (CVI) and ablation modeling [S1]. It was proposed as an efficient alternative to MC for large-scale simulations where memory and speed are critical, and where the exact interpolation of MC is less important than topological consistency and computational efficiency [S1]. The method relies on the binarization of the scalar field and the use of integer arithmetic [S1].
