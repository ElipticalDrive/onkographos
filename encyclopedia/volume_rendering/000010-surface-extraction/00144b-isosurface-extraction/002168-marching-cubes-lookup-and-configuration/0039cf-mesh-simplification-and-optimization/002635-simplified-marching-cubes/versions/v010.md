# Simplified Marching Cubes

Also called: SMC discretization, binarized Marching Cubes

## Overview
Simplified Marching Cubes (SMC) is an isosurface extraction method that produces meshes using only vertices from the regular 3D grid, eliminating the need for linear interpolation and lookup tables [S1]. It achieves approximately half the memory and triangle count of standard Marching Cubes (MC) and Cuberille while maintaining intermediate accuracy [S1]. Unlike MC, which interpolates intersection points, SMC constructs triangles exclusively from grid nodes, ensuring manifold meshes without holes by treating ambiguous configurations via "MC-patch" logic [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A scalar field $F(x, y, z)$ and a threshold $\lambda$.
*   **Output:** A set of triangles defined by indices into the grid vertex array.

**Data Structures:**
*   **Vertex Storage:** Each vertex is stored as 3 short (2-byte) integers representing integer coordinates $(x, y, z)$, where coordinates must be $< 65535$ [S1].
*   **Triangle Storage:** Each triangle is stored as 3 long (4-byte) integers representing vertex indices [S1].
*   **Cube Configuration:** For each cube, the algorithm determines the triangle topology based on the binary status of its 8 vertices relative to $\lambda$ [S1].

**Preprocessing:**
The scalar field is binarized into $F_B$ [S1]:
$$
F_B(x, y, z) = \begin{cases} 
1 & \text{if } F(x, y, z) \geq \lambda \\
0 & \text{else}
\end{cases}
$$
Positive vertices ($F_B=1$) are called "nodes". Negative vertices ($F_B=0$) are "fluid" or "void" vertices [S1].

**Vertex Indexing and Coordinates:**
Vertices in a cube are indexed $n \in \{0, \dots, 7\}$. Their normalized binary coordinates $c_x^n \in \{0, 1\}$ for axes $x \in \{i, j, k\}$ are derived from the index $n$ [S1]:
$$
c_i^n = n \% 2, \quad c_j^n = (n \% 4) / 2, \quad c_k^n = n / 4
$$
where `/` is integer division and `%` is the remainder operator [S1].

**Triangle Types:**
SMC produces three types of triangles, classified by a criterion $C_L$ [S1]:
1.  **Type I:** Isosceles-right triangle. $C_L = 6$.
2.  **Type II:** Right triangle. $C_L = 14$.
3.  **Type III:** Equilateral triangle. $C_L = 12$.

The criterion $C_L$ for a triangle with vertices $n_1, n_2, n_3$ is calculated as [S1]:
$$
C_L(n_1, n_2, n_3) = \sum_{l=1}^3 \sum_{m=l+1}^3 \left( \sum_{x=i,j,k} (c_x^{n_l} - c_x^{n_m})^2 \right)^2
$$

**Algorithm Steps:**
For each cube in the grid:
1.  Identify all positive vertices (nodes). Let $N_{nodes}$ be the count.
2.  Compute cumulative coordinates $C_x$ for each axis $x \in \{i, j, k\}$:
    $$
    C_x = \sum_{n \in \{\text{nodes}\}} c_x^n
    $$
3.  Determine the triangle output based on $N_{nodes}$ and $C_x$ [S1]:

    *   **$N_{nodes} \in \{0, 1, 2, 8\}$:** Output no triangles.
    *   **$N_{nodes} = 3$:**
        *   If $C_x = 0$ or $3$ for any axis $x$, output one **Type I** triangle. This corresponds to three nodes on a single cube face.
        *   Otherwise, output no triangles (degenerate/invalid in this context).
    *   **$N_{nodes} = 4$:**
        *   If $C_x = 0$ or $4$ for any axis $x$ (Case 8), output two **Type I** triangles on the corresponding face.
        *   If $C_x = 2$ for all axes $x$ (Cases 10/13), output no triangles.
        *   If one node is not an interface node (Case 9), identify it via exhaustive test. Output one **Type III** triangle formed by the remaining three interface nodes.
        *   If one singular node has only negative neighbors (Case 12), switch its status to positive (conceptually), then process as 3 nodes (Case 8) to build one **Type I** triangle.
        *   Otherwise (Cases 11/14), output two **Type II** triangles identified by nested loops over the nodes.
    *   **$N_{nodes} = 5$:**
        *   If $C_x = 1$ or $4$ for any axis $x$ (Case 17), output two **Type II** triangles identified by nested loops over nodes.
        *   If one singular node has only negative neighbors (Case 15), switch its status, then process as 3 nodes (Case 9) to build one **Type III** triangle.
        *   Otherwise (Case 16), identify the **Type III** triangle via nested loops. Find the negative vertex with node neighbors, switch its status, then process as 6 nodes (Case 20) to build the remaining triangles (two **Type II**, one **Type III**).
    *   **$N_{nodes} = 6$:**
        *   If two negative vertices have only node neighbors (Cases 18/19), identify them via exhaustive test. Build two **Type III** triangles formed by their respective neighbors.
        *   Otherwise (Case 20), output two **Type II** triangles formed by correctly ordered interface nodes.
    *   **$N_{nodes} = 7$:**
        *   Identify the single negative vertex. Form one **Type III** triangle using its three neighbors (which are interface nodes).

def is_interface_node(n, cube_vertices, threshold):
    # Node is positive. Check if it has at least one negative neighbor in 6-connectivity
    neighbors = get_neighbors(n)
    for nb in neighbors:
        if cube_vertices[nb] < threshold:
            return True
    return False

def has_only_negative_neighbors(n, cube_vertices, threshold):
    # n is a node (positive). Check if all its 6-neighbors are negative
    neighbors = get_neighbors(n)
    for nb in neighbors:
        if cube_vertices[nb] >= threshold:
            return False
    return True

def has_node_neighbors(n, nodes):
    # n is a negative vertex. Check if it has neighbors in 'nodes'
    neighbors = get_neighbors(n)
    for nb in neighbors:
        if nb in nodes:
            return True
    return False

def has_only_node_neighbors(n, nodes):
    # n is a negative vertex. Check if all its 6-neighbors are in 'nodes'
    neighbors = get_neighbors(n)
    for nb in neighbors:
        if nb not in nodes:
            return False
    return True

def get_neighbors(n):
    # Returns 6-connected neighbors of vertex n in a cube
    # n is 0-7.
    # Neighbors are n ^ 1, n ^ 2, n ^ 4
    return [n ^ 1, n ^ 2, n ^ 4]

## Operating characteristics
*   **Time Complexity:** Faster than standard MC, with speedup increasing as internal surface area increases [S1].
*   **Memory Complexity:** Half of MC and Cuberille. Vertex memory is 3 shorts (6 bytes) per vertex; triangle memory is 3 longs (12 bytes) per triangle [S1].
*   **Accuracy:** Lower than standard MC but higher than Cuberille. Surface area values lie between Cuberille and MC estimations [S1]. For a discretized sphere, SMC surface error converges to 7%, while MC converges to ~0.4% [S1]. Normal RMS error is ~10-12 degrees for SMC, compared to ~4-6 degrees for MC on smooth images [S1].
*   **Bias:** SMC systematically produces negative volume biases for convex objects (negative surface bias) and positive surface bias for concave objects. The volume bias is larger than in MC or Cuberille [S1].
*   **Strengths:** Integer arithmetic only; no interpolation; guaranteed manifold meshes; efficient for large images and moving boundary problems [S1].
*   **Limitations:** Lower accuracy than MC; non-vanishing positive bias in surface estimation for smooth surfaces regardless of sampling rate [S1].

## Background
SMC was developed for materials science simulations, specifically for computing effective diffusivities in porous media and simulating matrix deposition in Chemical Vapor Infiltration (CVI) and ablation modeling [S1]. It was proposed as an efficient alternative to MC for simulations of deposition/ablation in complex media, requiring less memory and computation time [S1]. The method relies on the "MC-patch" logic to resolve ambiguities, treating configurations 11 and 14 as symmetrical [S1].
