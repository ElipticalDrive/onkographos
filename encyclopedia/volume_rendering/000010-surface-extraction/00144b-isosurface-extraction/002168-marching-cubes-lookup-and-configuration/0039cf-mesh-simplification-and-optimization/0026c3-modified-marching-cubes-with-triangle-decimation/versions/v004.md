# Modified Marching Cubes with Triangle Decimation

Also called: 3D Isosurface Generation (Marching Cubes), Marching Cubes with Decimation

## Overview
This method generates an isosurface from 3D scalar field data using a modified Marching Cubes algorithm that explicitly resolves topological ambiguities [S1, unofficial]. It distinguishes itself from standard implementations by integrating a post-processing triangle decimation step that collapses redundant vertices to reduce mesh complexity and storage requirements while maintaining geometric fidelity [S1, unofficial].

## How it works
**Inputs:** A 3D scalar field defined on a structured grid (e.g., FDS grid), an isovalue threshold $L$, and the grid geometry.
**Outputs:** A triangle mesh representing the isosurface, where each vertex is associated with a smoothed normal vector.

### Data Structures
*   **Grid:** A regular 3D grid where each cell is a cube aligned with the coordinate axes.
*   **Cell State:** An 8-bit integer (0–255) representing the binary state of the 8 corners of a cube relative to the isovalue.
*   **Mesh:** A list of triangles, each defined by 3 vertices. Each vertex stores $(x, y, z)$ coordinates and a normal vector $(n_x, n_y, n_z)$.

### Algorithm Steps

1.  **Grid Partitioning:** Split the domain into cubes aligned with the underlying grid.
2.  **Cell Classification:** For each cube:
    *   Number corners 0 to 7.
    *   For each corner $i$, assign bit $b_i = 1$ if scalar value $T_i > L$, else $b_i = 0$.
    *   Compute case index $C = \sum_{i=0}^{7} b_i 2^i$.
    *   *Note on Ambiguity:* The source specifies a "modified" algorithm that removes ambiguities. While standard Marching Cubes uses 256 cases, the source notes a specific base-3 mapping for certain cases (0–80) but does not provide the full lookup table or the specific ambiguity resolution logic (e.g., tetrahedral splitting or specific edge configurations) beyond stating it is modified to remove them [S1, unofficial]. Implementers must consult the specific ambiguity resolution strategy implied by the "modified" designation, as the standard 256-case lookup is insufficient for ambiguous configurations without additional rules.
3.  **Triangulation:** Generate triangles for the cube surface based on case $C$. Store vertex locations and edge indices.
4.  **Triangle Decimation:** Reduce mesh density:
    *   Identify triangles where two or more vertices are closest to the same grid node.
    *   Remove these triangles.
    *   Compute a new vertex position as the average of the coordinates of the removed vertices.
    *   Re-triangulate the local region using this new averaged vertex [S1, unofficial].
5.  **Normal Estimation:** Compute vertex normals for shading:
    *   For each vertex, identify all connected triangles.
    *   Compute the unit normal for each triangle.
    *   Calculate a harmonic weighted average of these normals, where the weight for triangle $n$ is inversely proportional to its area $A_n$ [S1, unofficial].

### Formulas

**Uncertainty Bound:**
The uncertainty $\Delta x$ in the isosurface location between two data points $(x_1, T_1)$ and $(x_2, T_2)$ is bounded by:
$$ \left| \frac{\Delta x}{x_2 - x_1} \right| \leq \frac{\max(|\Delta T_1|, |\Delta T_2|)}{|T_2 - T_1|} $$
where $\Delta T_1$ and $\Delta T_2$ are the uncertainties in the scalar values $T_1$ and $T_2$ [S1, unofficial].

**Vertex Normal:**
The normal vector $V_i$ for vertex $i$ is:
$$ V_i = \frac{\sum_n \frac{U_n}{A_n}}{\sum_n \frac{1}{A_n}} = \frac{\sum_n \frac{u_n \times v_n}{\|u_n \times v_n\|^2}}{\sum_n \frac{1}{\|u_n \times v_n\|}} $$
where for triangle $n$, $u_n$ and $v_n$ are two edge vectors, $A_n = \|u_n \times v_n\|$ is the area, and $U_n$ is the unit normal [S1, unofficial].

## Operating characteristics
*   **Complexity:** Linear with respect to the number of grid cells for the marching cubes step. The decimation step adds overhead proportional to the number of triangles and the cost of re-triangulation.
*   **Performance:** The decimation step reduces the final triangle count, lowering storage requirements and potentially improving rendering performance [S1, unofficial].
*   **Limitations:** The source does not provide specific performance metrics or hardware scaling data. The ambiguity resolution is described as "modified" but the specific logic is not detailed, which may lead to implementation variance [S1, unofficial].

## Background
The method is described in the context of visualizing Fire Dynamics Simulation (FDS) data using Smokeview [S1, unofficial].
