# Marching Cubes with QEF Vertex Optimization

Also called: MC-QEF, Optimized Marching Cubes

## Overview
Marching Cubes with QEF Vertex Optimization is a surface extraction method that produces watertight meshes from voxel grids by combining fast 2D linear/binomial search for non-ambiguous cases with Quadric Error Function (QEF) minimization for ambiguous cases [S1, unofficial]. It sets itself apart from standard Marching Cubes by resolving topological ambiguities (saddle points) through geometric optimization rather than fixed lookup table triangulations, thereby preventing cracks and holes in the resulting mesh [S1, unofficial]. Unlike sibling methods that use simple linear interpolation or snap-to-vertex techniques, this method explicitly minimizes the distance to the isosurface planes defined by the voxel edges [S1, unofficial].

## How it works
The method processes voxel indices in two distinct groups based on their spatial location or complexity, applying different vertex computation strategies to each.

**Inputs and Outputs:**
*   **Input:** A scalar field defined on a 3D grid of size $G_x \times G_y \times G_z$. Binary occupancy grid `occs` derived from comparing scalar values to an isovalue $I$. Precomputed lookup tables: `edgeTable`, `triangleTable`, `axd_tab` (axis directions), `ax0_tab`, `ax1_tab`, `cas_tab` (case indices), and `lctab_2d` (2D lookup).
*   **Output:** A list of vertex positions `val_pnts` and triangle indices forming the mesh.

**Data Structures:**
*   `occs`: 3D boolean/integer array, shape $(G_x, G_y, G_z)$.
*   `val_pnts`: 1D array of 3D vectors, storing computed vertex positions.
*   `qvntab`: Lookup table mapping occupancy patterns and cases to vertex indices (used in QEF step).
*   `pfvtab`: Precomputed face/vertex table storing coordinates and edge indices.
*   `vitogi`: Mapping from vertex coordinates to edge indices.
*   `cstrtab`: Constraint table defining boundary planes for ray intersection.

**Parameters:**
*   `GRID`: Grid spacing (assumed uniform, often 1.0).
*   `GRID2`: $GRID^2$.
*   `GRID3`: $GRID^3$.
*   `ERR`: Epsilon threshold for degenerate edge detection (e.g., $10^{-6}$).
*   `QEF_REG`: Regularization weight for QEF least squares (e.g., $10^{-4}$).
*   `VERTICAL_RANGE`, `HORIZNTL_RANGE`: Search ranges for 2D optimization.
*   `VERTICAL_LINEAR_SEARCH`, `VERTICAL_BINARY_SEARCH`, `HORIZNTL_LINEAR_SEARCH`, `HORIZNTL_BINARY_SEARCH`: Boolean flags controlling search strategy.
*   `SEP`: Separation constant for ray intersection fallback.

**Algorithm Steps:**

1.  **Partition Indices:**
    Filter voxel indices `pidx1` into two groups:
    *   Group A (Fast): Indices in range $[3 \cdot GRID3, 9 \cdot GRID3)$.
    *   Group B (QEF): Indices $\ge 9 \cdot GRID3$.
    Initialize `start_idx` to 0 in `val_pnts`.

2.  **Process Group A (2D Search):**
    For each index in Group A:
    a.  **Compute Occupancy Pattern:** Calculate the 8-bit case index `val_` by summing weighted occupancy bits:
        $$ val\_ = occs[pidx3] + 2 \cdot occs[pidx3 + axis1] + 4 \cdot occs[pidx3 + axis0] + 8 \cdot occs[pidx3 + axis2] $$
        where `pidx3` is the 3D coordinate, and `axis0`, `axis1` are direction vectors from `ax0_tab` and `ax1_tab`.
    b.  **Ambiguity Correction:** If `amb_chks[pidx3]` is true (indicating an ambiguous case), correct the pattern:
        $$ val\_ = 15 - val\_ $$
    c.  **Vertex Computation:** Call `_2d_search(pidx3, axdir, axis0, axis1, val_, cases)` to compute vertex positions using linear/binomial search. Store results in `val_pnts` at `start_idx`.
    d.  **Increment:** `start_idx += count_idx` (number of vertices generated).

3.  **Process Group B (QEF Optimization):**
    For each index in Group B:
    a.  **Derive Case:** Compute `cases` from `pidx1 / GRID3 - 9`.
    b.  **Solve QEF:** Call `_solve_QEF(pidx3, val_, cases)` to compute vertex positions by minimizing the Quadric Error Function. Store results in `val_pnts` at `current start_idx`.

4.  **`_2d_search` Implementation Details:**
    a.  **Initial Estimate:** Use `lctab_2d` to get initial coordinates `lcord` and `rcord`. Compute midpoint `spnt = (lcord + rcord) / 2`.
    b.  **Normal Calculation:** Compute edge vector `hnorm = lcord - rcord`. Normalize `hnorm` using `ERR` threshold. Compute surface normal `vnorm` using cross products of grid axes and `hnorm`.
    c.  **Normal Correction:** Adjust `vnorm` based on occupancy of neighboring voxels (`chk0` to `chk3`) to ensure consistent orientation.
    d.  **Vertical Search:** Perform vertical line/binary search along `vnorm` to find intersection `left`.
    e.  **Horizontal Search:** Perform horizontal line/binary search along `hnorm` to refine intersection.
    f.  **Final Position:** Compute final vertex position using the intersection parameters. Handle degenerate cases by returning zero displacement.

5.  **`_solve_QEF` Implementation Details:**
    a.  **Retrieve Vertices:** For each vertex index `i` (3 to 7), find indices `idx` where `qvntab[val_, cases] == i`. Retrieve pre-computed vertex coordinates `vtcs` and edge indices `vitg`.
    b.  **Compute 3D Positions:** Calculate global vertex positions `pnti` using grid offsets and edge indices:
        $$ pnti = vitg[:,:,3] \cdot GRID3 + (pid3[:,0] + vitg[:,:,0]) \cdot GRID2 + (pid3[:,1] + vitg[:,:,1]) \cdot GRID + (pid3[:,2] + vitg[:,:,2]) $$
        Retrieve global indices `pidx` and pre-computed positions `vert = val_pnts[pidx]`. Add local offsets `vitg[:,:3]` to `vert`.
    c.  **Compute QEF Normals:** Calculate normals `qnrm` using cross products of edge vectors:
        $$ \_1vt = vert[:, 1::2] $$
        $$ qnrm = cross(\_1vt - vert[:, :-1:2], \_1vt - vert[:, 2::2]) $$
        Compute centroid `cntr = mean(\_1vt, dim=1)`.
    d.  **Handle Degeneracy:** Normalize `qnrm`. If edge length is below `ERR`, set length to 1.0. If all normals are degenerate, use `cntr` as the solution.
    e.  **Solve Least Squares:** Construct matrix $A$ and vector $b$:
        $$ A = [qnrm; QEF\_REG \cdot I] $$
        $$ b = [sum(\_1vt \cdot qnrm); QEF\_REG \cdot cntr] $$
        Solve $A \cdot x = b$ for $x$ (QEF solution `qefr`).
    f.  **Ray Intersection:** Compute ray direction `ctoq = qefr - cpnt` and length `leng`. Compute intersection parameter `t` with constraint planes defined by `cstrtab`. Concatenate boundary parameters $(1-cpnt)/ctoq$ and $-cpnt/ctoq$ with `t`. Handle NaNs and negative values by setting `t` to `leng + SEP`. Normalize by `leng` and clamp to $[0, 1]$.
    g.  **Final Vertex:** Compute final position `cpnt + t * ctoq`.

## Subtopics

### QEM-based Vertex Relocation
A vertex relocation method used in the Mesh Generation phase to move vertices to the isosurface, using the Quadric Error Metric (QEM) instead of full QEF minimization to reduce computational complexity and register usage on parallel hardware [S2, unofficial]. Unlike pseudoinverse QEF minimization which is complex and penalizes performance on parallel hardware due to register limits, QEM minimization is stable with supporting planes and produces accurate results sufficient for volume preservation [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** The method is generally $O(N)$ where $N$ is the number of voxels, but with a higher constant factor for ambiguous cases due to the least squares solve. The 2D search for non-ambiguous cases is fast, making the overall performance comparable to standard Marching Cubes for non-ambiguous regions.
*   **Memory Complexity:** Requires storage for the occupancy grid, lookup tables, and the output mesh. The QEF step requires additional temporary storage for normals and least squares matrices.
*   **Measured Performance:** Performance depends heavily on the ratio of ambiguous to non-ambiguous cases. The 2D search is optimized for speed, while the QEF step is more computationally intensive.
*   **Strengths:** Produces watertight meshes with fewer artifacts in ambiguous regions. Preserves volume accuracy better than simple linear interpolation.
*   **Limitations:** More complex to implement than standard Marching Cubes. The QEF step can be slower, especially on hardware with limited register usage.
*   **When to Use:** When high-quality, watertight meshes are required, especially in regions with topological ambiguities.
*   **When Not to Use:** When performance is critical and the input data has few ambiguous cases.

## Background
The method was introduced by the KAIST Visual AI Group in their ODC (Octree-based Densification and Compression) project [S1, unofficial]. It addresses the limitations of standard Marching Cubes in handling ambiguous cases, which can lead to topological errors. The QEF approach is inspired by previous work on mesh simplification and optimization, such as the Quadric Error Metric by Garland and Heckbert [S2, unofficial].
