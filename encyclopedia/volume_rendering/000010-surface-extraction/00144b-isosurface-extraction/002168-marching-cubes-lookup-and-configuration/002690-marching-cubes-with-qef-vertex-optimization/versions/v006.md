# Marching Cubes with QEF Vertex Optimization

Also called: MC-QEF, Optimized Marching Cubes

## Overview
Marching Cubes with QEF Vertex Optimization is a surface extraction method that produces a watertight mesh from a voxel grid by computing vertex positions via Quadric Error Function (QEF) minimization for ambiguous cases, while using a 2D linear/binomial search for non-ambiguous cases [S1, unofficial]. It builds on [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md) by replacing the standard linear interpolation of vertex positions with a geometric optimization that minimizes distance to surrounding constraint planes [S1, unofficial]. This approach specifically targets the topological ambiguities (saddle points) defined in the parent article, ensuring that vertices are placed consistently with the local geometry rather than relying on fixed triangulation heuristics [S1, unofficial].

## How it works
The method processes voxel indices in two distinct groups based on their case complexity, applying different vertex placement strategies to each [S1, unofficial].

### Inputs and Outputs
*   **Input**: A scalar field represented as a voxel grid. The grid is indexed by `pidx1` (1D linear index). The grid dimensions are defined by `GRID`, `GRID2` ($GRID^2$), and `GRID3` ($GRID^3$).
*   **Input**: Occupancy array `occs` containing binary or weighted values for each voxel.
*   **Input**: Precomputed lookup tables: `axd_tab`, `ax0_tab`, `ax1_tab`, `cas_tab` (derived from the parent's configuration), and `qvntab` (mapping case/vertex to edge indices).
*   **Input**: Ambiguity check table `amb_chks`.
*   **Input**: Constraint plane table `cstrtab` (not fully detailed in sources, assumed to define boundary planes for the cube).
*   **Output**: A list of vertex positions `val_pnts` and corresponding triangle indices.

### Data Structures
*   **`pidx1`**: 1D array of voxel indices.
*   **`pidx3`**: 3D array of voxel coordinates $(x, y, z)$ derived from `pidx1`.
*   **`val_`**: Integer occupancy pattern (0-255) for a voxel, computed from `occs`.
*   **`cases`**: Array of case indices for the current batch.
*   **`axdir`, `axis0`, `axis1`**: Direction vectors and basis axes for the 2D search plane.
*   **`val_pnts`**: Output array storing computed vertex positions.

### Algorithm Steps

1.  **Filter and Group Voxels**:
    Separate voxel indices `pidx1` into two groups:
    *   **Group 1 (Fast 2D Search)**: Indices in range $[3 \times GRID3, 9 \times GRID3)$. These correspond to non-ambiguous or simple cases.
    *   **Group 2 (QEF Optimization)**: Indices $\ge 9 \times GRID3$. These correspond to ambiguous cases requiring QEF minimization.
    Initialize `start_idx` to 0.

2.  **Process Group 1 (2D Search)**:
    For each voxel in Group 1:
    a.  Compute the 8-neighbor occupancy value `val_`:
        $$ val\_ = occs[pidx3] + 2 \cdot occs[pidx3 + axis1] + 4 \cdot occs[pidx3 + axis0] + 8 \cdot occs[pidx3 + axis2] $$
        where $axis0, axis1, axis2$ are basis vectors for the local coordinate system.
    b.  Apply ambiguity correction: If `amb_chks[pidx3]` is true, set $val\_ = 15 - val\_$.
    c.  Compute vertex positions using `_2d_search`:
        $$ pnt = \_2d\_search(pidx3, axdir, axis0, axis1, val\_, cases) $$
    d.  Store $pnt$ in `val_pnts` at `start_idx` and increment `start_idx` by the count of processed voxels.

3.  **Process Group 2 (QEF Optimization)**:
    For each voxel in Group 2:
    a.  Compute `val_` and `cases` as in Step 2.
    b.  Call `_solve_QEF(pidx3, val\_, cases)` to compute optimized vertex positions.
    c.  Store results in `val_pnts` at `start_idx`.

4.  **`_2d_search` Implementation**:
    This function computes the vertex position for non-ambiguous cases using a 2D linear/binomial search [S1, unofficial].
    a.  Determine the intersection point `spnt` on the cube face using linear interpolation of edge intersections `lcord` and `rcord`.
    b.  Compute the local normal `vnorm` by crossing the face normal with the edge direction `hnorm`.
    c.  Adjust `vnorm` based on occupancy differences at neighboring voxels to ensure consistency.
    d.  Perform a 1D search along `vnorm` to find the precise intersection, constrained by horizontal searches along `hnorm`.
    e.  Return the final position $spnt + rslt$.

5.  **`_solve_QEF` Implementation**:
    This function computes the vertex position for ambiguous cases by minimizing the Quadric Error Function [S1, unofficial].
    a.  For each vertex index $i$ (from 3 to 7) involved in the ambiguous case:
        i.  Find edge indices `idx` where `qvntab[val_, cases] == i`.
        ii. Retrieve pre-computed vertex positions `vert` from `val_pnts` for the edges.
        iii. Compute local offsets `vitg` and global positions `pnti`.
    b.  Compute QEF normals `qnrm` using cross products of edge vectors:
        $$ \_1vt = vert[:, 1::2] $$
        $$ qnrm = cross(\_1vt - vert[:, :-1:2], \_1vt - vert[:, 2::2]) $$
    c.  Compute the centroid `cntr` of the vertex positions:
        $$ cntr = mean(\_1vt, dim=1) $$
    d.  Normalize `qnrm`, handling zero-length edges with a threshold `ERR`.
    e.  Solve the QEF system using least squares:
        $$ A = cat(qnrm, QEF\_REG \cdot I) $$
        $$ b = cat(sum(\_1vt \cdot qnrm), QEF\_REG \cdot cntr) $$
        $$ qefr = lstsq(A, b).solution $$
        If all normals are degenerate, use `cntr` instead.
    f.  Compute the ray direction `ctoq = qefr - cpnt` and length `leng`.
    g.  Compute intersection parameter `t` with constraint planes defined by `cstrtab`.
    h.  Handle NaNs and negative values by setting `t` to $leng + SEP$, then normalize by `leng` and clamp to $[0, 1]$.
    i.  Final vertex is $cpnt + t \cdot ctoq$.

def _solve_QEF(pidx3, val_, cases, qvntab, cstrtab, QEF_REG, ERR, SEP):
    """
    Computes vertex positions for ambiguous cases using QEF minimization.
    """
    vertices = []
    
    for i in range(3, 8): # Vertex indices 3 to 7
        # Find edge indices for this vertex
        idx = find_edge_indices(val_, cases, i, qvntab)
        
        # Retrieve pre-computed vertex positions
        vert = get_vertex_positions(pidx3, idx, val_pnts)
        
        # Compute QEF normals
        _1vt = vert[:, 1::2]
        qnrm = cross(_1vt - vert[:, :-1:2], _1vt - vert[:, 2::2])
        
        # Compute centroid
        cntr = mean(_1vt, dim=1)
        
        # Normalize normals
        leng = norm(qnrm, dim=1, keepdim=True)
        cndt = leng < ERR
        leng[cndt] = 1.0
        qnrm = qnrm / leng
        
        # Solve QEF system
        A = concatenate([qnrm, QEF_REG * eye(qnrm.shape[1])], dim=1)
        b = concatenate([sum(_1vt * qnrm, dim=1), QEF_REG * cntr], dim=1)
        
        qefr = least_squares_solve(A, b)
        
        # Handle degenerate cases
        if all(cndt):
            qefr = cntr
            
        # Compute final vertex position
        cpnt = get_centroid(pidx3)
        ctoq = qefr - cpnt
        leng = norm(ctoq, dim=1)
        
        # Compute intersection parameter t
        t = compute_intersection_t(ctoq, cstrtab, cpnt, leng, SEP)
        
        # Clamp t to [0, 1]
        t = clamp(t, 0, 1)
        
        final_vertex = cpnt + t * ctoq
        vertices.append(final_vertex)
        
    return vertices

### Edge Cases and Pitfalls
*   **Degenerate Normals**: If all QEF normals are degenerate (length < `ERR`), the centroid is used instead of the least-squares solution [S1, unofficial].
*   **NaNs and Negative Values**: Intersection parameters `t` that are NaN or negative are handled by setting `t` to $leng + SEP$, then normalizing and clamping [S1, unofficial].
*   **Ambiguity Correction**: For ambiguous cases, the occupancy pattern `val_` is inverted ($15 - val\_$) if the ambiguity check flag is set [S1, unofficial].

## Subtopics

### QEM-based Vertex Relocation
A vertex relocation method used in the Mesh Generation phase to move vertices to the isosurface, using the Quadric Error Metric (QEM) instead of full QEF minimization to reduce computational complexity and register usage on parallel hardware [S2, unofficial]. Unlike pseudoinverse QEF minimization which is complex and penalizes performance on parallel hardware due to register limits, QEM minimization is stable with supporting planes and produces accurate results sufficient for volume preservation [S2, unofficial].

## Operating characteristics
*   **Time Complexity**: The method splits processing into two groups. Group 1 uses a 2D linear/binomial search, which is faster than QEF minimization. Group 2 uses QEF minimization, which involves solving a least-squares system for each vertex. The overall complexity depends on the ratio of ambiguous to non-ambiguous cases. Not given in the sources.
*   **Memory Complexity**: Requires storage for the voxel grid, occupancy array, lookup tables, and the output vertex array. The QEF method requires additional memory for storing normals and centroids during computation. Not given in the sources.
*   **Measured Performance**: QEM-based vertex relocation is noted to be less computationally complex and more performant on parallel hardware compared to full QEF minimization [S2, unofficial].
*   **Strengths**: Produces watertight meshes, handles ambiguous cases robustly, and preserves volume accuracy [S1, unofficial][S2, unofficial].
*   **Limitations**: QEF minimization is computationally expensive compared to linear interpolation [S2, unofficial].
*   **When to Use**: When high-quality, watertight meshes are required, especially in the presence of topological ambiguities [S1, unofficial].
*   **When Not to Use**: When performance on parallel hardware is critical and volume preservation is not the primary concern, QEM-based relocation may be preferred [S2, unofficial].

## Background
The method originates from the ODC (Octree-based Discrete Curve) project by the KAIST Visual AI Group [S1, unofficial]. It was developed to address the limitations of standard Marching Cubes in handling ambiguous cases, which can lead to cracks or holes in the mesh [S1, unofficial]. The QEF approach is inspired by the work on Quadric Error Metrics for mesh simplification [S2, unofficial], adapted for vertex placement in isosurface extraction.
