# Marching Cubes with QEF Vertex Optimization

Also called: MC-QEF, Optimized Marching Cubes

## Overview
Marching Cubes with QEF Vertex Optimization is a surface extraction method that computes vertex positions using a Quadric Error Function (QEF) minimization for ambiguous cases, while using a 2D linear/binomial search for non-ambiguous cases, to produce a watertight mesh from a voxel grid [S1, unofficial]. It builds on [Isosurface extraction](30-isosurface-extraction.md) by replacing the standard linear interpolation of classic Marching Cubes with a hybrid approach: fast geometric search for simple configurations and least-squares optimization for topologically ambiguous ones [S1, unofficial]. This distinguishes it from standard [Marching Cubes](30-isosurface-extraction.md) by reducing geometric error in complex regions, and from [Dual Contouring and Surface Nets](6319-dual-contouring-and-surface-nets.md) by retaining the simpler lookup-table topology while optimizing vertex placement only where necessary [S1, unofficial].

## How it works
The method operates on a regular 3D grid of occupancy values. It classifies grid cells into two groups based on their index to apply different vertex computation strategies: a fast 2D search for non-ambiguous cases and QEF minimization for ambiguous cases.

**Inputs:**
- `occs`: A 3D array of binary occupancy values (0 or 1) for the voxel grid.
- `GRID`, `GRID2`, `GRID3`: Constants representing the grid dimensions or scaling factors (e.g., $GRID = N_x$, $GRID2 = N_x N_y$, $GRID3 = N_x N_y N_z$).
- `isovalue`: Implicitly handled by binary occupancy; the surface is the boundary between 0 and 1.
- Lookup tables: `amb_chks` (ambiguity checks), `axd_tab`, `ax0_tab`, `ax1_tab`, `cas_tab`, `lctab_2d`, `pfvtab`, `vitogi`, `qvntab`, `cstrtab`.

**Outputs:**
- `val_pnts`: A list/array of computed vertex positions.
- Mesh connectivity derived from the lookup tables.

**Data Structures:**
- `pidx1`: Array of linear indices of cells requiring processing.
- `pidx3`: Array of 3D coordinates $(x, y, z)$ corresponding to `pidx1`.
- `val_`: Integer occupancy pattern for a cell, computed as a weighted sum of neighbor occupancies.
- `cases`: Integer case index derived from the occupancy pattern.

**Steps:**

1.  **Filter and Classify Cells:**
    Separate `pidx1` into two groups:
    - Group 1 (Fast): Indices in range $[3 \cdot GRID3, 9 \cdot GRID3)$.
    - Group 2 (QEF): Indices $\ge 9 \cdot GRID3$.
    Initialize `start_idx` to 0.

2.  **Process Group 1 (Non-Ambiguous/Fast Path):**
    For each cell index in Group 1:
    a.  Compute the 8-neighbor occupancy value `val_`:
        $$ val\_ = occs[pidx3] + 2 \cdot occs[pidx3 + axis1] + 4 \cdot occs[pidx3 + axis0] + 8 \cdot occs[pidx3 + axis2] $$
        where $axis0, axis1, axis2$ are axis direction vectors derived from lookup tables.
    b.  Apply ambiguity correction:
        If `amb_chks[pidx3]` is true, set $val\_ = 15 - val\_$.
    c.  Compute vertex positions using a 2D search function `_2d_search(pidx3, axdir, axis0, axis1, val_, cases)`. This function performs a linear/binomial search to find the intersection point on the cell edges.
    d.  Store results in `val_pnts` at `start_idx` and increment `start_idx` by the count of processed cells.

3.  **Process Group 2 (Ambiguous/QEF Path):**
    For each cell index in Group 2:
    a.  Compute `val_` similarly to Step 2a.
    b.  Determine the case index: $cases = pidx1 / GRID3 - 9$.
    c.  Call `_solve_QEF(pidx3, val_, cases)` to compute optimized vertex positions.
    d.  Store results in `val_pnts`.

    **Detailed `_solve_QEF` Algorithm:**
    a.  For each vertex index $i$ from 3 to 7:
        i.  Find indices `idx` where $qvntab[val\_, cases] == i$.
        ii. Retrieve vertex coordinates `vtcs` from $pfvtab[val0\_, cas, :2i+1]$.
        iii. Retrieve edge indices `vitg` from $vitogi[vtcs]$.
    b.  Compute 3D positions `pnti` for the vertices using grid offsets:
        $$ pnti = vitg[:,:,3] \cdot GRID3 + (pid3[:,0] + vitg[:,:,0]) \cdot GRID2 + (pid3[:,1] + vitg[:,:,1]) \cdot GRID + (pid3[:,2] + vitg[:,:,2]) $$
        Get global indices `pidx` and retrieve pre-computed vertex positions $vert = val\_pnts[pidx]$.
        Add local offsets: $vert \leftarrow vert + vitg[:,:3]$.
    c.  Compute QEF normals `qnrm` using cross products of edge vectors:
        $$ \_1vt = vert[:, 1::2] $$
        $$ qnrm = cross(\_1vt - vert[:, :-1:2], \_1vt - vert[:, 2::2]) $$
        Compute centroid $cntr = mean(\_1vt, dim=1)$.
        Normalize `qnrm`, handling zero-length edges with a threshold `ERR`.
    d.  Solve the QEF system using least squares:
        $$ A = cat(qnrm, QEF\_REG \cdot I) $$
        $$ b = cat(sum(\_1vt \cdot qnrm), QEF\_REG \cdot cntr) $$
        Solution $qefr = lstsq(A, b).solution$.
        If all normals are degenerate (`cndt` all true), use $cntr$ instead.
    e.  Compute ray direction $ctoq = qefr - cpnt$ and length $leng$.
    f.  Compute intersection parameter $t$ with constraint planes defined by `cstrtab`.
        Concatenate boundary parameters $(1-cpnt)/ctoq$ and $-cpnt/ctoq$ with $t$.
        Handle NaNs and negative values by setting $t$ to $leng + SEP$, then normalize by $leng$ and clamp to $[0, 1]$.
        Final vertex is $cpnt + t \cdot ctoq$.

**Edge Cases and Pitfalls:**
- **Degenerate Normals:** If all edge vectors are zero-length (degenerate cell), the QEF solution falls back to the centroid [S1, unofficial].
- **Ambiguity Correction:** The ambiguity check `amb_chks` must be applied correctly to flip the occupancy pattern for specific topological cases to ensure watertightness [S1, unofficial].
- **Precision:** Floating-point errors in normal computation and least-squares solving can lead to non-watertight meshes if not handled with thresholds like `ERR` [S1, unofficial].

## Subtopics

### QEM-based Vertex Relocation
A vertex relocation method used in the Mesh Generation phase to move vertices to the isosurface, using the Quadric Error Metric (QEM) instead of full QEF minimization to reduce computational complexity and register usage on parallel hardware [S2, unofficial]. Unlike pseudoinverse QEF minimization which is complex and penalizes performance on parallel hardware due to register limits, QEM minimization is stable with supporting planes and produces accurate results sufficient for volume preservation [S2, unofficial].

## Operating characteristics
- **Time Complexity:** The method is $O(N)$ where $N$ is the number of cells, but with a higher constant factor for ambiguous cells due to the least-squares solve. The fast path is $O(1)$ per cell.
- **Memory Complexity:** Requires storage for lookup tables and the output mesh. The QEF solve requires temporary storage for the $A$ and $b$ matrices, which is small per cell.
- **Performance:** The hybrid approach balances speed and accuracy. The fast path handles the majority of cells quickly, while the QEF path ensures accuracy in complex regions [S1, unofficial]. QEM-based variants offer better performance on parallel hardware by reducing register pressure [S2, unofficial].
- **Strengths:** Produces watertight meshes with reduced geometric error compared to standard linear interpolation. Efficient for large grids by limiting expensive QEF solves to ambiguous cases.
- **Limitations:** More complex to implement than standard Marching Cubes. The QEF solve can be numerically unstable if not handled carefully with regularization and degenerate case checks.

## Background
The method originates from the ODC (Octree-based Discrete Contouring) project by the KAIST Visual AI Group [S1, unofficial]. It was developed to address the limitations of standard Marching Cubes in producing accurate surfaces from voxel data, particularly in ambiguous topological configurations. The use of QEF minimization for vertex optimization is inspired by the work of Garland and Heckbert on Quadric Error Metrics [S2, unofficial], adapted for surface extraction.
