# Marching Cubes with QEF Vertex Optimization

Also called: MC-QEF, Optimized Marching Cubes

## Overview
Marching Cubes with QEF Vertex Optimization is a surface extraction method that computes vertex positions using a Quadric Error Function (QEF) minimization for ambiguous cases, while using a 2D linear/binomial search for non-ambiguous cases, to produce a watertight mesh from a voxel grid [S1, unofficial]. It builds on [Isosurface extraction](30-isosurface-extraction.md) by replacing the standard linear interpolation of [Marching Cubes](30-isosurface-extraction.md) with a constrained optimization step that preserves volume and handles topological ambiguities more robustly [S1, unofficial]. Unlike [Dual Contouring and Surface Nets](6319-dual-contouring-and-surface-nets.md), which place vertices in cell centers or dual nodes, this method places vertices on the edges or surfaces defined by the grid, optimizing their exact position to satisfy local geometric constraints [S1, unofficial].

## How it works
The algorithm processes voxel indices by splitting them into two groups based on their index value relative to grid dimensions: a "fast" group for non-ambiguous cases and a "slow" group for ambiguous cases requiring QEF optimization [S1, unofficial].

### Inputs and Outputs
*   **Input**:
    *   `occs`: A 3D array of occupancy bits (0 or 1) representing the voxel grid.
    *   `GRID`, `GRID2`, `GRID3`: Precomputed powers of the grid dimension size ($N, N^2, N^3$).
    *   `ERR`: A small threshold for numerical stability (e.g., $10^{-6}$).
    *   Lookup tables: `amb_chks` (ambiguity checks), `axd_tab`, `ax0_tab`, `ax1_tab`, `cas_tab`, `lctab_2d`, `qvntab`, `pfvtab`, `vitogi`, `cstrtab`.
*   **Output**:
    *   `val_pnts`: An array of 3D vertex positions.

### Data Structures
*   **Lookup Tables**:
    *   `amb_chks`: Boolean array indicating ambiguous configurations.
    *   `axd_tab`, `ax0_tab`, `ax1_tab`: Arrays mapping case indices to axis directions and basis vectors.
    *   `lctab_2d`: Lookup table for 2D linear/binomial search results.
    *   `pfvtab`: Precomputed face/vertex table for QEF normals.
    *   `vitogi`: Vertex-to-edge index mapping.
    *   `cstrtab`: Constraint plane definitions for ray intersection.

### Algorithm Steps

1.  **Filter Indices**:
    Separate voxel indices `pidx1` into two groups:
    *   Group 1 (Fast): Indices in range $[3 \cdot GRID3, 9 \cdot GRID3)$.
    *   Group 2 (QEF): Indices $\ge 9 \cdot GRID3$.

2.  **Process Group 1 (Non-Ambiguous)**:
    For each index in Group 1:
    a.  Compute the 8-neighbor occupancy value `val_`:
        $$ val\_ = occs[pidx3] + 2 \cdot occs[pidx3 + axis1] + 4 \cdot occs[pidx3 + axis0] + 8 \cdot occs[pidx3 + axis2] $$
        where `pidx3` is the 3D coordinate of the voxel, and `axis0`, `axis1`, `axis2` are direction vectors derived from lookup tables.
    b.  Apply ambiguity correction: If `amb_chks[pidx3]` is true, set `val_ = 15 - val_`.
    c.  Compute vertex positions using `_2d_search(pidx3, axdir, axis0, axis1, val_, cases)`.
    d.  Store results in `val_pnts` at `start_idx` and increment `start_idx`.

3.  **Process Group 2 (Ambiguous/QEF)**:
    For each index in Group 2:
    a.  Call `_solve_QEF(pidx3, val_, cases)` where `val_` is the integer occupancy pattern and `cases` is derived from `pidx1 / GRID3 - 9`.
    b.  Store results in `val_pnts` at `start_idx`.

#### `_2d_search` Implementation
This function computes vertex positions for non-ambiguous cases using linear/binomial search [S1, unofficial].

1.  Compute local coordinates `lcres` using `lctab_2d[val_, cases + 1]`.
2.  Update `cidx3` based on `lcres` and `axdir`.
3.  Determine edge direction `edir` and compute global index `cidx1`.
4.  Retrieve linear interpolation base `linv` from `val_pnts`.
5.  Compute reference coordinates `rcord` based on `lcres` and axis vectors.
6.  Compute midpoint `spnt = (lcord + rcord) / 2`.
7.  Get local occupancy `locc` at `spnt`.
8.  Compute horizontal normal `hnorm` and vertical normal `vnorm`:
    *   `hnorm` is the normalized difference between `lcord` and `rcord`.
    *   `vnorm` is the cross product of the grid axis and `hnorm`.
9.  Adjust `vnorm` based on occupancy differences at neighbors `chk0` to `chk3` to ensure correct side of the isosurface.
10. Perform vertical search `_2d_linbin` to find `left`.
11. Perform horizontal searches to find `lleft` and `rleft`.
12. Compute result `rslt` using the intersection of horizontal and vertical constraints:
    $$ rslt = \frac{0.5 \cdot (rh + lh) \cdot hnorm + vl \cdot vnorm}{rh - lh} \cdot leng $$
    where `lh`, `rh`, `vl` are dot products of search results with normals.
13. Clamp `rslt` to zero if it points in the wrong direction relative to `vnorm`.
14. Return `spnt + rslt`.

#### `_solve_QEF` Implementation
This function computes vertex positions for ambiguous cases using QEF minimization [S1, unofficial].

1.  For each vertex index `i` from 3 to 7:
    a.  Find indices `idx` where `qvntab[val_, cases] == i`.
    b.  Retrieve vertex coordinates `vtcs` from `pfvtab[val0_, cas, :2*i+1]`.
    c.  Retrieve edge indices `vitg` from `vitogi[vtcs]`.
2.  Compute 3D positions `pnti` for the vertices using grid offsets:
    $$ pnti = vitg[:,:,3] \cdot GRID3 + (pid3[:,0] + vitg[:,:,0]) \cdot GRID2 + (pid3[:,1] + vitg[:,:,1]) \cdot GRID + (pid3[:,2] + vitg[:,:,2]) $$
3.  Get global indices `pidx` and retrieve pre-computed vertex positions `vert = val_pnts[pidx]`.
4.  Add local offsets `vitg[:,:3]` to `vert`.
5.  Compute QEF normals `qnrm` using cross products of edge vectors:
    $$ \_1vt = vert[:, 1::2] $$
    $$ qnrm = cross(\_1vt - vert[:, :-1:2], \_1vt - vert[:, 2::2]) $$
6.  Compute centroid `cntr = mean(\_1vt, dim=1)`.
7.  Normalize `qnrm` handling zero-length edges with `ERR` threshold.
8.  Solve the QEF system using least squares:
    $$ A = cat(qnrm, QEF\_REG \cdot eye) $$
    $$ b = cat(sum(\_1vt \cdot qnrm), QEF\_REG \cdot cntr) $$
    $$ qefr = lstsq(A, b).solution $$
    If all normals are degenerate (`cndt` all true), use `cntr` instead.
9.  Compute ray direction `ctoq = qefr - cpnt` and length `leng`.
10. Compute intersection parameter `t` with constraint planes defined by `cstrtab`:
    *   Concatenate boundary parameters $(1-cpnt)/ctoq$ and $-cpnt/ctoq$ with `t`.
    *   Handle NaNs and negative values by setting `t` to `leng + SEP`.
    *   Normalize by `leng` and clamp to $[0, 1]$.
11. Final vertex is `cpnt + t * ctoq`.

### Parameters
*   `QEF_REG`: Regularization parameter for QEF least squares. Not given in the sources.
*   `SEP`: Separation constant for ray intersection. Not given in the sources.
*   `VERTICAL_RANGE`, `HORIZNTL_RANGE`: Search ranges for linear/binomial search. Not given in the sources.
*   `VERTICAL_LINEAR_SEARCH`, `VERTICAL_BINARY_SEARCH`, `HORIZNTL_LINEAR_SEARCH`, `HORIZNTL_BINARY_SEARCH`: Boolean flags controlling search strategy. Not given in the sources.

### Edge Cases and Pitfalls
*   **Degenerate Normals**: If all QEF normals are degenerate (zero length), the algorithm falls back to the centroid `cntr` [S1, unofficial].
*   **Numerical Stability**: The `ERR` threshold is used to handle zero-length edges and near-zero dot products to prevent division by zero [S1, unofficial].
*   **Ambiguity Correction**: The ambiguity correction (`val_ = 15 - val_`) is critical for handling topological ambiguities in the 2D search phase [S1, unofficial].

## Subtopics

### QEM-based Vertex Relocation
A vertex relocation method used in the Mesh Generation phase to move vertices to the isosurface, using the Quadric Error Metric (QEM) instead of full QEF minimization to reduce computational complexity and register usage on parallel hardware [S2, unofficial]. Unlike pseudoinverse QEF minimization which is complex and penalizes performance on parallel hardware due to register limits, QEM minimization is stable with supporting planes and produces accurate results sufficient for volume preservation [S2, unofficial].

## Operating characteristics
*   **Time Complexity**: The algorithm splits processing into two paths. The 2D search path is $O(1)$ per vertex for non-ambiguous cases. The QEF path involves solving a least squares system, which is $O(1)$ per vertex but with a higher constant factor due to matrix operations [S1, unofficial].
*   **Memory Complexity**: Requires storage for lookup tables (`amb_chks`, `axd_tab`, etc.) and the output vertex array `val_pnts` [S1, unofficial].
*   **Performance**: The QEF approach is more computationally intensive than standard Marching Cubes but provides better geometric accuracy for ambiguous cases [S1, unofficial]. The QEM variant offers a trade-off between speed and accuracy, suitable for parallel hardware where register usage is a constraint [S2, unofficial].
*   **Strengths**: Handles topological ambiguities robustly; produces watertight meshes; preserves volume [S1, unofficial][S2, unofficial].
*   **Limitations**: Higher computational cost than standard Marching Cubes; complex implementation due to multiple lookup tables and search strategies [S1, unofficial].

## Background
The method originates from the ODC (Octree-based Density Compression) project by the KAIST Visual AI Group, which implements a surface extraction technique combining 2D search for efficiency and QEF for accuracy [S1, unofficial]. The QEM variant is discussed in the context of generating smooth high-quality isosurfaces for interactive modeling and visualization of complex terrains, aiming to reduce computational complexity on parallel hardware [S2, unofficial].
