# Snap Marching Cubes

Also called: SnapMC, Snapping for Quality Mesh Generation

## Overview
Snap Marching Cubes (SnapMC) is an isosurface extraction algorithm that improves mesh quality by reducing the number of triangles and eliminating small angles, which are common artifacts in standard Marching Cubes [S1, unofficial]. It achieves this by modifying the scalar field to "snap" isosurface vertices that are geometrically close to grid vertices onto those grid vertices, causing nearby geometric elements to merge [S1, unofficial]. Unlike adaptive methods such as [Advancing Front Framework for Implicit Surfaces](819-advancing-front-framework-for-implicit-surfaces.md) or [DelIso](954-extended-clcir-plic-reconstruction.md), SnapMC is non-adaptive and operates on a uniform grid, offering a significant speedup over adaptive counterparts at the cost of potential topological errors and non-manifold surfaces [S1, unofficial].

## How it works
SnapMC extends the standard Marching Cubes algorithm by introducing a preprocessing step that alters the scalar field values based on a snapping threshold, followed by a postprocessing step to restore geometric accuracy for vertices that were snapped.

### Inputs and Outputs
- **Input**: A scalar grid $V$ of dimensions $N_x \times N_y \times N_z$, an isovalue $\sigma$, and a snap parameter $\gamma \in [0, 0.5]$. The grid edge length is $L$.
- **Output**: A triangle mesh representing the isosurface.

### Data Structures
1.  **Scalar Grid**: A 3D array storing scalar values at grid vertices.
2.  **Original Isosurface Vertices**: A list of 3D coordinates computed from the original scalar grid using standard Marching Cubes interpolation. This is required for the final repositioning step.
3.  **Extended Lookup Table**: A Marching Cubes lookup table that handles "zero" vertices (where the scalar value equals the isovalue). Standard Marching Cubes tables treat zero as positive or negative; SnapMC requires a table that distinguishes $+$, $-$, and $=$ states to correctly handle vertices where the scalar value has been reset to $\sigma$ [S1, unofficial].

### Parameters
-   **$\gamma$ (gamma)**: The snap parameter, typically $0.3$ [S1, unofficial]. It controls the snapping distance threshold as $\gamma L$. Smaller values result in less triangle reduction and fewer topological changes.
-   **$L$**: The length of the grid edges.
-   **$\sigma$**: The isovalue.

### Algorithm Steps
1.  **Compute Original Isosurface Vertices**:
    Run standard Marching Cubes on the original scalar grid $V$. For every bipolar edge (an edge connecting a vertex with value $<\sigma$ to one with value $>\sigma$), compute the intersection point using linear interpolation. Store these points in a list $P_{orig}$.
    $$ t = \frac{\sigma - f_a}{f_b - f_a} $$
    $$ P = V_a + t(V_b - V_a) $$
    where $V_a, V_b$ are grid vertices and $f_a, f_b$ are their scalar values.

2.  **Identify Snapping Candidates**:
    For each grid vertex $v$, check if any vertex in $P_{orig}$ lies within a distance $\gamma L$ of $v$.
    $$ \text{dist}(v, p) < \gamma L \quad \text{for some } p \in P_{orig} $$

3.  **Modify Scalar Field**:
    For every grid vertex $v$ identified in Step 2, reset its scalar value in the grid to the isovalue $\sigma$.
    $$ V[v] \leftarrow \sigma $$
    This creates "zero" vertices in the grid.

4.  **Run Extended Marching Cubes**:
    Execute the Marching Cubes algorithm on the modified scalar grid using the extended lookup table that supports zero-valued vertices. This generates a new set of isosurface vertices $P_{snap}$ and triangles.
    -   If an isosurface vertex $w$ lies exactly on a grid vertex $v$ (because $V[v] = \sigma$), its position is initially set to $v$.

5.  **Reposition Snapped Vertices**:
    For each isosurface vertex $w$ in the output mesh that lies on a grid vertex $v$ (i.e., $w = v$), find the closest vertex $p \in P_{orig}$ to $v$. Move $w$ to the position of $p$.
    $$ w \leftarrow \arg\min_{p \in P_{orig}} \text{dist}(v, p) $$
    This step ensures that the final mesh geometry approximates the original isosurface as closely as possible, while retaining the topological simplification (merged vertices/triangles) achieved in Step 4.

### Pseudocode

```python
def snap_marching_cubes(grid, isovalue, gamma):
    """
    grid: 3D array of scalar values
    isovalue: float sigma
    gamma: float in [0, 0.5]
    L: grid edge length (assumed uniform)
    """
    L = get_grid_edge_length(grid)
    threshold = gamma * L
    
    # Step 1: Compute original isosurface vertices
    # This requires a standard Marching Cubes implementation
    # Returns a list of 3D points P_orig
    P_orig = compute_marching_cubes_intersections(grid, isovalue)
    
    # Step 2 & 3: Identify and modify scalar field
    modified_grid = copy(grid)
    snapped_vertices = [] # List of grid indices that were snapped
    
    for v_index in grid.vertices:
        v_pos = grid.vertex_position(v_index)
        v_val = grid.value(v_index)
        
        # Check if any original isosurface vertex is close to this grid vertex
        is_snapped = False
        for p in P_orig:
            if distance(v_pos, p) < threshold:
                is_snapped = True
                break
        
        if is_snapped:
            modified_grid.value(v_index) = isovalue
            snapped_vertices.append(v_index)
            
    # Step 4: Run Extended Marching Cubes
    # Returns a mesh with vertices P_snap and triangles T
    # Note: The lookup table must handle '=' (zero) cases
    mesh_snap = extended_marching_cubes(modified_grid, isovalue)
    
    # Step 5: Reposition snapped vertices
    # Create a map from grid vertex index to its snapped original position
    # We need to find the closest P_orig for each snapped grid vertex
    snap_map = {}
    for v_index in snapped_vertices:
        v_pos = grid.vertex_position(v_index)
        closest_p = None
        min_dist = infinity
        for p in P_orig:
            d = distance(v_pos, p)
            if d < min_dist:
                min_dist = d
                closest_p = p
        snap_map[v_index] = closest_p
        
    # Update mesh vertices
    for vertex in mesh_snap.vertices:
        # If the vertex corresponds to a grid vertex that was snapped
        # (This requires knowing which mesh vertex maps to which grid vertex)
        # In standard MC, a vertex on a grid vertex has the grid vertex's index.
        if vertex.grid_vertex_index in snap_map:
            vertex.position = snap_map[vertex.grid_vertex_index]
            
    return mesh_snap
```

### Edge Cases and Pitfalls
-   **Topological Changes**: Snapping merges geometrically close vertices even if they are not connected by edges. This can eliminate small components, join separate components, or close loops in the isosurface [S1, unofficial].
-   **Non-Manifold Surfaces**: Because snapping merges vertices that may not share an edge, the resulting surface often becomes non-manifold. Facets glued together appear as duplicate triangles with opposite orientation [S1, unofficial]. This is problematic for simulation software which typically requires manifold meshes.
-   **Precision**: The snapping distance $\gamma L$ must be chosen carefully. If $\gamma$ is too large, excessive topological errors occur. If too small, the triangle reduction benefit is minimal.
-   **Lookup Table**: Standard Marching Cubes lookup tables do not handle zero-valued vertices correctly. An extended lookup table distinguishing $+$, $-$, and $=$ states is required [S1, unofficial].

## Operating characteristics
-   **Time Complexity**: SnapMC takes approximately twice as long as standard Marching Cubes due to the extra time spent in snapping scalar values and the repositioning step [S1, unofficial]. It runs an order of magnitude faster than adaptive methods like [Advancing Front Framework for Implicit Surfaces](819-advancing-front-framework-for-implicit-surfaces.md) and [DelIso](954-extended-clcir-plic-reconstruction.md) [S1, unofficial].
-   **Memory Complexity**: Requires storage for the original isosurface vertices ($P_{orig}$) and the modified scalar grid. This is $O(N)$ where $N$ is the number of grid vertices.
-   **Performance**:
    -   On a $256 \times 256 \times 256$ aneurism dataset ($\gamma=0.3$), SnapMC produced 106,356 triangles in 1.52s, reducing triangle count by ~39% compared to Regular MC (175,832 triangles, 0.71s) [S1, unofficial].
    -   On a $256 \times 256 \times 256$ bonsai dataset ($\gamma=0.3$), SnapMC produced 729,623 triangles in 2.19s, reducing triangle count by ~43% compared to Regular MC (1,284,542 triangles) [S1, unofficial].
    -   On the lobster dataset ($\gamma=0.3$), SnapMC produced 223K triangles in 0.8s with a minimum angle of 13.3 degrees [S1, unofficial].
-   **Mesh Quality**: SnapMC produces well-shaped triangles suitable for numerical simulation, with minimum angles typically above 13 degrees for $\gamma=0.3$ [S1, unofficial]. In contrast, DelIso often produces degenerate triangles with zero area or edge length and minimum angles of 0 degrees [S1, unofficial].
-   **Accuracy**: The directed Hausdorff distance from the SnapMC surface to the original surface is less than 1 for various datasets (e.g., 0.86 for the lobster dataset) [S1, unofficial].
-   **Strengths**: Significant triangle reduction (25-40%), improved minimum triangle angles, fast execution compared to adaptive methods.
-   **Limitations**: Produces non-manifold surfaces, potential topological errors, not adaptive (does not add detail in high-curvature areas).

## Background
Snap Marching Cubes was introduced by S. Raman and R. Wenger in the paper "Quality Isosurface Mesh Generation" [S1, unofficial]. The algorithm was developed to address the notorious issue of Marching Cubes producing isosurface triangles with small angles, which occur when two triangle vertices are very close to a grid vertex while the third is far away. The method modifies the scalar field to snap these close vertices onto grid vertices, thereby merging geometrically close elements. The source code and executables for SnapMC are publicly available at www.cse.ohio-state.edu/graphics/isotable [S1, unofficial].
