# Marching Cubes Vertex List Generation

Also called: Edge Vertex Calculation, Marching Cubes Vertex Interpolation, Vertex Interpolation for Marching Cubes

## Overview
This method computes the precise 3D positions of vertices on an isosurface within a voxel grid by linearly interpolating along the edges of a cube where the scalar field crosses a specified isolevel. It serves as the geometric refinement step following [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md), which determines *which* edges are intersected but does not compute the exact surface location. Unlike [Surface Nets](6419-surface-nets.md), which approximates the surface point using the grid vertex with the highest gradient, this method offers precise point placement via interpolation.

## How it works
**Inputs and Outputs:**
*   **Input:**
    *   `voxelLocalPosition`: The 3D world coordinate of the current voxel's origin (typically the minimum corner).
    *   `voxelDensities`: An array of 8 scalar values representing the field values at the 8 corners of the voxel.
    *   `isolevel`: The threshold scalar value defining the surface.
    *   `edgeIndex`: A 12-bit integer bitmask (from the `edgeTable` in the parent article) indicating which of the 12 cube edges are intersected by the isosurface.
    *   `EdgeIndexTable`: A lookup structure mapping edge indices to corner indices.
    *   `CubeCorners`: An array of 8 vectors representing the local coordinates of the cube's corners relative to its origin.
*   **Output:**
    *   `VertexList`: A list of 3D vectors containing the interpolated intersection points for each intersected edge.

**Data Structures:**
1.  **EdgeIndexTable**: An array of integers where entries at indices $2i$ and $2i+1$ give the indices of the two corners forming edge $i$ (for $i=0..11$). The corner indices are in the range $[0, 7]$, corresponding to the standard Marching Cubes vertex ordering.
2.  **CubeCorners**: An array of 8 `int3` (or `float3`) vectors representing the local coordinates of the 8 corners of a unit cube, indexed 0 to 7. Typically, these are $(0,0,0)$ through $(1,1,1)$ if working in normalized local space, or scaled by voxel size.

**Algorithm Steps:**
1.  Initialize an empty list `VertexList`.
2.  Iterate through each edge index $i$ from 0 to 11.
3.  Check if the $i$-th bit of `edgeIndex` is set.
    *   If the bit is **0**, skip this edge.
    *   If the bit is **1**, perform the following:
        a.  Retrieve the start and end corner indices from `EdgeIndexTable` at positions $2i$ and $2i+1$. Let these be $c_1$ and $c_2$.
        b.  Calculate the world positions of these corners:
            $$p_1 = \text{voxelLocalPosition} + \text{CubeCorners}[c_1]$$
            $$p_2 = \text{voxelLocalPosition} + \text{CubeCorners}[c_2]$$
        c.  Retrieve the scalar densities for these corners from `voxelDensities`: $v_1 = \text{voxelDensities}[c_1]$ and $v_2 = \text{voxelDensities}[c_2]$.
        d.  Normalize densities if necessary (e.g., if stored as bytes $[0, 255]$, divide by 255.0 to map to $[0, 1]$). Ensure `isolevel` is in the same scale.
        e.  Calculate the intersection point $p$ using linear interpolation:
            $$p = p_1 + \frac{(\text{isolevel} - v_1)}{(v_2 - v_1)} (p_2 - p_1)$$
        f.  Append $p$ to `VertexList`.

**Pseudocode:**
```python
def generate_vertex_list(voxel_local_position, voxel_densities, isolevel, edge_index, edge_index_table, cube_corners):
    """
    Generates a list of 3D vertices for the isosurface intersections within a single voxel.
    
    Args:
        voxel_local_position: vec3, world position of the voxel's origin (corner 0).
        voxel_densities: list of 8 floats, scalar values at corners 0-7.
        isolevel: float, the threshold value for the isosurface.
        edge_index: int, 12-bit bitmask indicating intersected edges.
        edge_index_table: list of 24 ints, pairs of corner indices for edges 0-11.
        cube_corners: list of 8 vec3, local coordinates of corners 0-7.
        
    Returns:
        list of vec3, the interpolated vertex positions.
    """
    vertex_list = []
    
    # Iterate over all 12 edges of the cube
    for i in range(12):
        # Check if the i-th bit is set in edge_index
        if (edge_index >> i) & 1:
            # Get corner indices for this edge from the lookup table
            # Edge i is defined by corners at edge_index_table[2*i] and edge_index_table[2*i+1]
            c1_idx = edge_index_table[2 * i]
            c2_idx = edge_index_table[2 * i + 1]
            
            # Get world positions of the corners
            p1 = voxel_local_position + cube_corners[c1_idx]
            p2 = voxel_local_position + cube_corners[c2_idx]
            
            # Get scalar densities at the corners
            v1 = voxel_densities[c1_idx]
            v2 = voxel_densities[c2_idx]
            
            # Handle degenerate case where densities are equal
            # If v1 == v2, the edge is parallel to the isosurface or lies on it.
            # Standard linear interpolation fails (division by zero).
            # [G] In practice, if v1 == v2, the intersection is undefined or the edge is skipped.
            # Some implementations return the midpoint or skip. Here we skip to avoid NaN.
            if v1 == v2:
                continue
                
            # Linear interpolation to find the intersection point
            # Formula: p = p1 + t * (p2 - p1)
            # where t = (isolevel - v1) / (v2 - v1)
            t = (isolevel - v1) / (v2 - v1)
            
            # Clamp t to [0, 1] for numerical stability, though theoretically it should be in range
            # if the isosurface actually crosses the edge.
            t = max(0.0, min(1.0, t))
            
            intersection_point = p1 + t * (p2 - p1)
            
            vertex_list.append(intersection_point)
            
    return vertex_list
```

**Parameters:**
*   `isolevel`: The density level where a surface is created. Densities below this are inside (solid), above are outside (air) [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Division by Zero**: Occurs if $v_1 = v_2$. The standard formula divides by $(v_2 - v_1)$. If the scalar values at both ends of an edge are exactly equal, the edge is parallel to the isosurface. The code must handle this, typically by skipping the edge or treating it as a degenerate case [S1, unofficial].
*   **Precision**: Floating-point precision issues may arise when $v_1$ and $v_2$ are very close but not equal, leading to large $t$ values or jitter. Clamping $t$ to $[0, 1]$ helps [G].
*   **Boundary Conditions**: If the voxel is at the boundary of the volume, corner indices must be handled carefully to avoid out-of-bounds access if the algorithm assumes a full 8-neighbor context.

## Subtopics

## Operating characteristics
*   **Time Complexity**: $O(1)$ per voxel. The algorithm iterates over a fixed 12 edges, performing constant-time arithmetic and lookups.
*   **Memory Complexity**: $O(1)$ per voxel. The output vertex list has a maximum size of 12 vertices (one per edge), though typically much smaller (max 5 triangles $\times$ 3 vertices = 15 vertices, but vertices are shared, so the list of *unique* edge intersections is at most 12).
*   **Strengths**: Simple, fast, and produces smooth surfaces due to linear interpolation. It is the standard approach for Marching Cubes.
*   **Limitations**: Computationally more expensive than [Surface Nets](6419-surface-nets.md) which uses existing grid vertices. Sensitive to the exact isolevel value; small changes can shift vertices.
*   **When to use**: When high-quality, smooth isosurfaces are required and computational resources allow for per-voxel interpolation.
*   **When not to use**: When performance is critical and approximate geometry is acceptable (use [Surface Nets](6419-surface-nets.md) instead).

## Background
The method is a core component of the Marching Cubes algorithm, originally published by William E. Lorensen and Harvey E. Cline in 1987 [S7, S8]. The specific step of interpolating vertices along edges is fundamental to the algorithm's ability to generate smooth surfaces from discrete voxel data. It is widely used in medical imaging, geological modeling, and real-time terrain generation.
