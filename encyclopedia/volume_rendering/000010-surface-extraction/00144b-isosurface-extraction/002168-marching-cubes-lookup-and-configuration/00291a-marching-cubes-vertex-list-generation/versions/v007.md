# Marching Cubes Vertex List Generation

Also called: Edge Vertex Calculation, Marching Cubes Vertex Interpolation, Vertex Interpolation for Marching Cubes

## Overview
Marching Cubes Vertex List Generation calculates the precise 3D positions of vertices where a scalar field intersects the edges of a voxel grid cell, based on a specified isovalue [S1, unofficial]. It serves as the geometric foundation for polygonal mesh generation by determining *where* the surface cuts through a cube, distinct from the topological decision of *which* triangles to form [30-isosurface-extraction.md]. Unlike [Marching Cubes Surface Point Extraction](6417-marching-cubes-surface-point-extraction.md), which aggregates multiple intersections into a single representative point per voxel for point-based rendering, this method generates a distinct vertex for every intersected edge to preserve topological connectivity for meshing [S1, unofficial].

## How it works
**Inputs:**
*   `voxelLocalPosition`: The 3D world coordinate of the current voxel's minimum corner (int3 or float3) [S1, unofficial].
*   `voxelDensities`: An array of 8 scalar values (e.g., bytes normalized to [0,1] or floats) representing the scalar field at the 8 corners of the voxel [S1, unofficial].
*   `edgeIndex`: A 12-bit integer (cube index) indicating which of the 12 edges are intersected by the isosurface [S1, unofficial].
*   `isolevel`: The threshold scalar value defining the surface [S1, unofficial].

**Outputs:**
*   `vertexList`: A list of 3D positions (float3) containing one entry for each intersected edge, ordered by edge index [S1, unofficial].

**Data Structures:**
*   `EdgeIndexTable`: A lookup table mapping edge indices $i \in [0, 11]$ to the indices of the two voxel corners that form that edge. The table is typically stored as a flat array where entries at indices $2i$ and $2i+1$ provide the start and end corner indices for edge $i$ [S1, unofficial].
*   `CubeCorners`: An array of 8 vectors (int3 or float3) representing the local coordinates of the 8 corners of a unit cube, indexed 0 to 7 [S1, unofficial].

**Algorithm Steps:**
1.  Initialize an empty list `vertexList`.
2.  Iterate through each edge index $i$ from 0 to 11.
3.  Check if the $i$-th bit of `edgeIndex` is set. If not, continue to the next edge.
4.  If the bit is set, retrieve the corner indices for edge $i$ from `EdgeIndexTable`:
    *   `startCornerIndex = EdgeIndexTable[2 * i]`
    *   `endCornerIndex = EdgeIndexTable[2 * i + 1]`
5.  Calculate the world positions of these corners:
    *   $p_1 = \text{voxelLocalPosition} + \text{CubeCorners}[\text{startCornerIndex}]$
    *   $p_2 = \text{voxelLocalPosition} + \text{CubeCorners}[\text{endCornerIndex}]$
6.  Retrieve the scalar densities at these corners from `voxelDensities`:
    *   $v_1 = \text{voxelDensities}[\text{startCornerIndex}]$
    *   $v_2 = \text{voxelDensities}[\text{endCornerIndex}]$
    *   *Note: If densities are stored as integers (e.g., 0-255), normalize them to [0,1] by dividing by the max value (e.g., 255f) before interpolation [S1, unofficial].*
7.  Calculate the intersection vertex position $p$ using linear interpolation:
    $$ p = p_1 + \frac{(\text{isolevel} - v_1)}{(v_2 - v_1)} (p_2 - p_1) $$
8.  Append $p$ to `vertexList`.
9.  Return `vertexList`.

**Pseudocode:**
```python
def generate_vertex_list(voxel_local_position, voxel_densities, edge_index, isolevel, edge_index_table, cube_corners):
    """
    Generates a list of vertex positions for intersected edges of a voxel.
    
    Args:
        voxel_local_position: float3, world position of the voxel's min corner.
        voxel_densities: list of 8 floats, scalar values at voxel corners.
        edge_index: int, 12-bit mask of intersected edges.
        isolevel: float, the threshold density.
        edge_index_table: list of 24 ints, mapping edge i to corners (2i, 2i+1).
        cube_corners: list of 8 float3, local corner positions of a unit cube.
        
    Returns:
        list of float3, vertices on intersected edges.
    """
    vertex_list = []
    
    for i in range(12):
        # Check if edge i is intersected
        if (edge_index >> i) & 1:
            # Get corner indices from lookup table
            start_idx = edge_index_table[2 * i]
            end_idx = edge_index_table[2 * i + 1]
            
            # Get world positions of corners
            p1 = voxel_local_position + cube_corners[start_idx]
            p2 = voxel_local_position + cube_corners[end_idx]
            
            # Get densities (assuming already normalized to [0,1] or handled externally)
            v1 = voxel_densities[start_idx]
            v2 = voxel_densities[end_idx]
            
            # Handle degenerate case where v1 == v2 to avoid division by zero
            # [G] If v1 equals v2, the edge is parallel to the isosurface or lies on it.
            # Standard implementation often skips or defaults to midpoint.
            if v2 == v1:
                vertex = (p1 + p2) / 2.0
            else:
                # Linear interpolation
                t = (isolevel - v1) / (v2 - v1)
                vertex = p1 + t * (p2 - p1)
            
            vertex_list.append(vertex)
            
    return vertex_list
```

**Parameters:**
*   `isolevel`: The scalar value at which the surface is defined. Values below this are considered "inside" (solid), and values above are "outside" (air) [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Division by Zero:** If $v_1 = v_2$, the denominator in the interpolation formula becomes zero [S1, unofficial]. This occurs when the edge is parallel to the isosurface or both endpoints lie exactly on the isosurface. The source code does not explicitly handle this, implying inputs are assumed distinct or the case is degenerate/unhandled [S1, unofficial]. Implementers should guard against this, typically by defaulting to the midpoint or skipping the vertex if the edge is not truly intersecting in a topological sense.
*   **Precision:** When densities are stored as integers (e.g., 8-bit bytes), normalization to floating-point [0,1] is required before interpolation to maintain precision [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per voxel, as it involves a fixed loop of 12 iterations and constant-time arithmetic operations [S1, unofficial].
*   **Memory Complexity:** $O(1)$ auxiliary space per voxel, storing a small list of vertices (max 12) [S1, unofficial].
*   **Strengths:** Simple, deterministic, and highly parallelizable. It provides the exact geometric intersection points required for high-quality meshing [S1, unofficial].
*   **Limitations:** Does not handle topology (triangle connectivity) itself; requires a separate step (e.g., lookup table) to generate triangles from the vertex list [30-isosurface-extraction.md]. Sensitive to degenerate cases where scalar values exactly match the isovalue [S1, unofficial].
*   **When to use:** When generating polygonal meshes (triangles/quads) from voxel data.
*   **When not to use:** When point-based rendering is sufficient, or when topological robustness in degenerate cases is critical without additional handling [6417-marching-cubes-surface-point-extraction.md].

## Background
The method is a core component of the Marching Cubes algorithm, originally introduced by Lorensen and Cline in 1987 [S1, unofficial]. It relies on the principle that if a scalar field crosses a threshold within a voxel, the intersection with the voxel's edges can be approximated linearly. The implementation details provided in the sources are from an unofficial Unity-based voxel terrain engine (Eldemarkki/Marching-Cubes-Terrain), which applies this standard technique in a job-based, parallel processing context [S1, unofficial].
