# Marching Cubes Vertex List Generation

Also called: Edge Vertex Calculation, Marching Cubes Vertex Interpolation, Vertex Interpolation for Marching Cubes

## Overview
This method calculates the precise 3D coordinates of vertices lying on the edges of a voxel cube where the scalar field crosses a specified isovalue, using linear interpolation between corner values [S1, unofficial]. It generates the list of vertices for the polygon(s) inside a voxel based on the cube index, serving as the geometric foundation for subsequent triangle assembly [S1, unofficial]. Unlike its sibling [Marching Cubes Surface Point Extraction](6417-marching-cubes-surface-point-extraction.md), which aggregates intersections into a single representative point per voxel for efficiency, this method preserves topological correctness by generating distinct vertices for each intersected edge, enabling proper polygonal connectivity [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Inputs**:
    *   `cubeIndex`: The 8-bit case index ($0 \le C \le 255$) derived from the voxel's corner signs relative to the isovalue.
    *   `cornerPositions`: The 3D world coordinates of the 8 vertices of the current voxel cube.
    *   `cornerDensities`: The scalar field values at the 8 vertices.
    *   `isolevel`: The threshold density value defining the surface.
    *   `edgeTable`: The 256-entry bitmask array from [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md) indicating which edges are intersected.
*   **Outputs**:
    *   `vertexList`: A list of 3D vectors containing the interpolated intersection points. The size is variable (0 to 12), determined by the number of set bits in `edgeTable[cubeIndex]`.

**Data Structures**
*   **EdgeIndexTable**: An array of integers where entries at indices $2i$ and $2i+1$ give the indices of the two corners forming edge $i$ (for $i=0..11$). This maps the abstract edge index to the specific voxel corner indices [S1, unofficial].
*   **CubeCorners**: An array of 8 3D vectors representing the local coordinates of the 8 corners of a unit cube, indexed 0 to 7. In implementation, these are often added to the voxel's base position to get world coordinates [S1, unofficial].

**Algorithm Steps**
1.  Initialize an empty list `vertexList`.
2.  Retrieve the intersection bitmask `edgeMask` from `edgeTable[cubeIndex]`.
3.  Iterate through each edge index $i$ from 0 to 11:
    a.  Check if the $i$-th bit of `edgeMask` is set.
    b.  If set, calculate the intersection vertex for edge $i$ and append it to `vertexList`.
4.  Return `vertexList`.

**Vertex Interpolation Formula**
For a given edge $i$ connecting corner $A$ and corner $B$:
1.  Retrieve corner indices $idx_A$ and $idx_B$ from `EdgeIndexTable` at positions $2i$ and $2i+1$.
2.  Get the world positions $p_A$ and $p_B$ for these corners.
3.  Get the scalar densities $v_A$ and $v_B$ at these corners.
4.  Calculate the intersection point $p$ using linear interpolation:
    $$ p = p_A + \frac{(isolevel - v_A)}{(v_B - v_A)} (p_B - p_A) $$
    Where:
    *   $p_A, p_B$ are the 3D positions of the edge endpoints.
    *   $v_A, v_B$ are the scalar field values at the endpoints.
    *   $isolevel$ is the threshold density.

**Pseudocode**
```python
def generate_vertex_list(cube_index, edge_table, edge_index_table, corner_positions, corner_densities, isolevel):
    """
    Generates a list of 3D vertices for the isosurface intersections within a single voxel.
    
    Args:
        cube_index (int): The 8-bit case index (0-255).
        edge_table (list[int]): 256-entry array of 12-bit bitmasks.
        edge_index_table (list[int]): Array mapping edge index i to corner indices (2i, 2i+1).
        corner_positions (list[Vec3]): 8 world positions of the voxel corners.
        corner_densities (list[float]): 8 scalar values at the voxel corners.
        isolevel (float): The threshold density.
        
    Returns:
        list[Vec3]: List of interpolated vertex positions.
    """
    vertex_list = []
    
    # Get the bitmask for the current cube configuration
    edge_mask = edge_table[cube_index]
    
    # Iterate over all 12 edges of the cube
    for i in range(12):
        # Check if the i-th bit is set in the mask
        if (edge_mask >> i) & 1:
            # Get the indices of the two corners forming this edge
            corner_idx_a = edge_index_table[2 * i]
            corner_idx_b = edge_index_table[2 * i + 1]
            
            # Get positions and densities
            pos_a = corner_positions[corner_idx_a]
            pos_b = corner_positions[corner_idx_b]
            dens_a = corner_densities[corner_idx_a]
            dens_b = corner_densities[corner_idx_b]
            
            # Calculate interpolation factor
            # Handle division by zero if densities are equal
            if dens_b == dens_a:
                # Degenerate case: edge is parallel to isosurface or density is constant.
                # Standard practice is to pick the midpoint or handle as no intersection.
                # Given the source implies distinct inputs, we default to midpoint [G].
                factor = 0.5
            else:
                factor = (isolevel - dens_a) / (dens_b - dens_a)
            
            # Linear interpolation
            vertex = pos_a + factor * (pos_b - pos_a)
            vertex_list.append(vertex)
            
    return vertex_list
```

**Parameters**
*   `isolevel`: The density level where a surface is created. Densities below this are typically considered inside (solid), and above are outside (air) [S1, unofficial].

**Edge Cases and Pitfalls**
*   **Division by Zero**: If $v_1 = v_2$ (densities at both ends of an edge are equal), the denominator in the interpolation formula becomes zero. The source code does not explicitly handle this, implying inputs are assumed distinct or the case is degenerate/unhandled [S1, unofficial]. In implementation, a guard clause should return the midpoint or skip the vertex to prevent NaN propagation.
*   **Boundary Conditions**: If the isovalue equals exactly one of the corner densities, the intersection lies exactly on the corner. The formula yields the corner position itself, which is correct but may lead to duplicate vertices if adjacent voxels share that corner.

## Subtopics

### [Marching Cubes Surface Point Extraction](6417-marching-cubes-surface-point-extraction.md)
Extracts a single 3D position per voxel using QEF, Centroid, or Blocky strategies. Choose this when computational efficiency on the GPU is prioritized over topological correctness and polygonal connectivity is not required.

## Operating characteristics
*   **Time Complexity**: $O(1)$ per voxel, as it involves a fixed loop over 12 edges and constant-time arithmetic operations.
*   **Memory Complexity**: $O(1)$ auxiliary space per voxel, storing up to 12 vertices.
*   **Strengths**: Provides exact geometric placement of vertices on the isosurface, ensuring high-fidelity mesh reconstruction.
*   **Limitations**: Does not resolve topological ambiguities (cases 46, 47, 98, 99, 210, 213, 214, 215) on its own; relies on the parent lookup table's fixed triangulation, which can cause cracks if adjacent voxels resolve ambiguities inconsistently.
*   **When to use**: Standard Marching Cubes implementation where mesh connectivity is required.
*   **When not to use**: When point-based rendering is sufficient, or when ambiguity handling is required (see [Topology and Ambiguity Handling](6547-topology-and-ambiguity-handling.md)).

## Background
The method is a core component of the Marching Cubes algorithm, originally published by Lorensen and Cline in 1987. It relies on the precomputed `edgeTable` and `triangleTable` structures described in [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md). The specific implementation details cited here are derived from modern GPU-accelerated voxel terrain generation systems [S1, unofficial].
