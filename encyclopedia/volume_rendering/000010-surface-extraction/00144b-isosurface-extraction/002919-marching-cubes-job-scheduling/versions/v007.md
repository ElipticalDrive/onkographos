# Marching Cubes Job Scheduling

Also called: Parallel Marching Cubes Job Scheduling, Chunk-based Marching Cubes Job Scheduling

## Overview
Marching Cubes Job Scheduling is a parallel execution strategy that decomposes a 3D voxel volume into spatial chunks and assigns each chunk to an independent computational job for isosurface extraction. It builds on [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md) by distributing the per-voxel lookup and triangle generation workload across multiple threads or processes. Unlike [GPU Acceleration and Parallel Pipelines](4136-gpu-acceleration-and-parallel-pipelines.md) which targets GPU architectures, this method is often implemented on CPU multi-core systems using job schedulers (e.g., Unity's Job System) to manage memory allocation and synchronization. It solves the problem of sequential processing bottlenecks in large volumetric datasets by enabling concurrent mesh generation.

## How it works
The method orchestrates the parallel extraction of isosurfaces by dividing the volume into manageable chunks, scheduling independent jobs for each, and aggregating results.

### Inputs and Outputs
*   **Inputs**:
    *   `VoxelData`: A 3D array or volume of scalar values (e.g., `byte` or `float`) representing the density field.
    *   `VoxelColors` (Optional): A 3D array of color values associated with voxels.
    *   `Isolevel`: The scalar threshold value for surface extraction.
    *   `ChunkSize`: The dimensions $(W, H, D)$ of each spatial chunk.
    *   `WorldSettings`: Global parameters including total volume dimensions and chunk size.
*   **Outputs**:
    *   `OutputVertices`: A dynamic list or array of vertex positions and attributes (e.g., normals, colors).
    *   `OutputTriangles`: A dynamic list or array of triangle indices (e.g., `ushort`).
    *   `JobHandle`: A synchronization primitive indicating when the job completes.

### Data Structures
The implementation relies on specific data structures to manage parallel state and memory.

1.  **`MarchingCubesJob` Struct**: Contains the data required for a single chunk's extraction.
    *   `VoxelData`: Reference to the voxel volume chunk (`VoxelDataVolume<byte>`).
    *   `VoxelColors`: Reference to the color volume chunk (`VoxelDataVolume<Color32>`).
    *   `Isolevel`: Float threshold.
    *   `VertexCountCounter`: A shared atomic counter (`NativeCounter`) to track the total number of vertices generated across all jobs.
    *   `OutputVertices`: A pre-allocated `NativeArray` of `MeshingVertexData`.
    *   `OutputTriangles`: A pre-allocated `NativeArray` of `ushort` indices.

2.  **`NativeCounter`**: An atomic integer used for thread-safe accumulation of vertex counts. Initialized with `Allocator.TempJob`.

3.  **Output Arrays**:
    *   `maxLength`: Calculated as $15 \times \text{voxelCount}$, where $\text{voxelCount} = W \times H \times D$. This upper bound accounts for the maximum 5 triangles per voxel (15 indices).
    *   `outputVertices`: `NativeArray` of size `maxLength`.
    *   `outputTriangles`: `NativeArray` of size `maxLength`.

### Numbered Steps

1.  **Chunk Retrieval**: For a given `chunkCoordinate`, attempt to retrieve the corresponding `VoxelData` and `VoxelColors` chunks. If either fails, return `null` or an empty handle.
2.  **Counter Initialization**: Allocate a `NativeCounter` (`vertexCountCounter`) using `Allocator.TempJob`. This counter will track the global vertex offset.
3.  **Memory Allocation**:
    *   Calculate `voxelCount` as the product of the chunk dimensions ($W \times H \times D$).
    *   Calculate `maxLength` as $15 \times \text{voxelCount}$.
    *   Allocate `outputVertices` as a `NativeArray` of `MeshingVertexData` with size `maxLength`.
    *   Allocate `outputTriangles` as a `NativeArray` of `ushort` with size `maxLength`.
4.  **Job Configuration**: Initialize a `MarchingCubesJob` struct instance with the following fields:
    *   `VoxelData`: The retrieved voxel data chunk.
    *   `VoxelColors`: The retrieved voxel color chunk.
    *   `Isolevel`: The global isovalue (default 0.5f).
    *   `VertexCountCounter`: The shared atomic counter.
    *   `OutputVertices`: The allocated vertex array.
    *   `OutputTriangles`: The allocated triangle array.
5.  **Job Scheduling**: Schedule the `MarchingCubesJob` using the job scheduler's `Schedule()` method. This returns a `JobHandle`.
6.  **Return Handle**: Wrap the `JobHandle` and job data in a `JobHandleWithData<IMesherJob>` structure and return it to the caller. The caller must wait on the handle before accessing the output arrays.

### Pseudocode

```python
# Assuming a job system interface similar to Unity's JobSystem
# or a generic parallel task queue.

class MarchingCubesJob:
    def __init__(self, voxel_data, voxel_colors, isolevel, vertex_count_counter, output_vertices, output_triangles):
        self.voxel_data = voxel_data
        self.voxel_colors = voxel_colors
        self.isolevel = isolevel
        self.vertex_count_counter = vertex_count_counter
        self.output_vertices = output_vertices
        self.output_triangles = output_triangles

    def execute(self):
        # 1. Iterate over all voxels in the chunk
        for z in range(chunk_height):
            for y in range(chunk_width):
                for x in range(chunk_depth):
                    # 2. Get voxel values
                    v0 = self.voxel_data[x, y, z]
                    # ... get v1..v7 based on local chunk coordinates
                    
                    # 3. Calculate case index C
                    # Bit i is set if v_i < isolevel (or >, depending on convention)
                    C = 0
                    for i in range(8):
                        if v_i < self.isolevel:
                            C |= (1 << i)
                    
                    # 4. Lookup edge intersections
                    edge_mask = edgeTable[C]
                    
                    # 5. If no intersection, continue
                    if edge_mask == 0:
                        continue
                    
                    # 6. Lookup triangle configuration
                    tri_config = triangleTable[C]
                    
                    # 7. Generate triangles
                    idx = 0
                    while tri_config[idx] != -1:
                        e1 = tri_config[idx]
                        e2 = tri_config[idx+1]
                        e3 = tri_config[idx+2]
                        
                        # Calculate intersection points on edges
                        p1 = interpolate_edge(v0..v7, e1, isolevel)
                        p2 = interpolate_edge(v0..v7, e2, isolevel)
                        p3 = interpolate_edge(v0..v7, e3, isolevel)
                        
                        # 8. Write to output arrays
                        # Use atomic counter for vertex offset if sharing arrays
                        offset = self.vertex_count_counter.add_and_get(3) # Assuming 3 vertices per triangle
                        
                        self.output_vertices[offset] = p1
                        self.output_vertices[offset+1] = p2
                        self.output_vertices[offset+2] = p3
                        
                        # Write triangle indices relative to the chunk's local vertex start
                        # Note: In a chunked system, boundary vertices must be handled carefully
                        # to avoid duplicates. This pseudocode assumes a simplified soup generation
                        # or that the caller handles boundary merging.
                        tri_idx = self.vertex_count_counter.get() # Current total count before this triangle
                        self.output_triangles.append(tri_idx)
                        self.output_triangles.append(tri_idx + 1)
                        self.output_triangles.append(tri_idx + 2)
                        
                        idx += 3

def create_mesh_job(chunk_coordinate, world_settings):
    # 1. Retrieve chunks
    voxel_data = get_voxel_chunk(chunk_coordinate)
    voxel_colors = get_voxel_color_chunk(chunk_coordinate)
    
    if voxel_data is None or voxel_colors is None:
        return None

    # 2. Initialize counter
    vertex_count_counter = NativeCounter(Allocator.TempJob)
    
    # 3. Calculate sizes
    chunk_size = world_settings.chunk_size
    voxel_count = chunk_size.x * chunk_size.y * chunk_size.z
    max_length = 15 * voxel_count
    
    # 4. Allocate arrays
    output_vertices = NativeArray(MeshingVertexData, max_length, Allocator.TempJob)
    output_triangles = NativeArray(ushort, max_length, Allocator.TempJob)
    
    # 5. Configure job
    job = MarchingCubesJob(
        voxel_data=voxel_data,
        voxel_colors=voxel_colors,
        isolevel=0.5f,
        vertex_count_counter=vertex_count_counter,
        output_vertices=output_vertices,
        output_triangles=output_triangles
    )
    
    # 6. Schedule
    job_handle = job.schedule()
    
    # 7. Return handle
    return JobHandleWithData(IMesherJob, job_handle, job)
```

### Parameters
*   `Isolevel`: The density threshold for surface extraction. Default value is 0.5f. Defined in `MarchingCubesMesher` with `[SerializeField, Range(0, 1)]` [S1, unofficial].
*   `ChunkSize`: The dimensions of the voxel chunk. Defined in `VoxelWorld.WorldSettings.ChunkSize` [S1, unofficial].

### Edge Cases and Pitfalls
*   **Boundary Vertices**: When processing chunks independently, vertices on the boundaries of adjacent chunks may be duplicated. The pseudocode above generates a "triangle soup" per chunk. A complete implementation must either merge vertices at chunk boundaries or use a global vertex buffer with careful indexing [G].
*   **Memory Allocation**: Using `Allocator.TempJob` requires careful management of job lifetimes. The output arrays must remain valid until the job completes and the results are copied or consumed.
*   **Atomic Contention**: The `VertexCountCounter` is shared across jobs if they write to a global buffer. High contention can reduce performance. Using per-job buffers and merging later is often more efficient [G].
*   **Precision**: Floating-point interpolation of edge intersections must be consistent across adjacent chunks to avoid cracks.

## Subtopics

### Multi-Process Ground Truth Generation
A variant that orchestrates parallel processing of 3D models to generate ground truth data using multiple worker processes and a queue for synchronization. It distributes object names across processes based on an even distribution list. Workers process subsets of objects, querying point clouds and generating ground truth inputs. The main loop waits for workers to exit and processes results from a queue with a timeout [S2, unofficial].

### Tandem Algorithm with Dumping
A strategy that enhances the tandem algorithm by reducing the number of generated triangles through a dumping mechanism, specifically handling disconnected components to allow interactive exploration. It drastically reduces the number of triangles compared to the classical brute-force approach. On a 1626x7028x2000 dataset, the parallel tandem approach extracted surfaces in 5 minutes using 56 processors, compared to more than 3 hours for the sequential version. It filters 18,111 initial disconnected components down to 328 based on geometric criteria (volume) [S3].

## Operating characteristics
*   **Time Complexity**: $O(N)$ where $N$ is the number of voxels, but with a constant factor reduced by parallelism. The speedup depends on the number of available cores and the overhead of job scheduling and memory allocation.
*   **Memory Complexity**: $O(N)$ for storing voxel data and output buffers. The `maxLength` allocation ($15 \times \text{voxelCount}$) ensures sufficient space for worst-case triangle generation per chunk.
*   **Measured Performance**: On a 1626x7028x2000 dataset (40 GB), the parallel tandem approach (a related scheduling strategy) extracted surfaces in 5 minutes using 56 processors, compared to more than 3 hours for the sequential tandem algorithm [S3].
*   **Strengths**: Scalable to large datasets by leveraging multi-core CPUs. Simple to implement using existing job schedulers.
*   **Limitations**: Requires careful management of memory and synchronization. Boundary handling between chunks can introduce artifacts or require post-processing.
*   **When to Use**: When processing large volumetric datasets on multi-core CPU systems where GPU acceleration is not available or suitable.
*   **When Not to Use**: For real-time applications on single-core CPUs or when memory bandwidth is the primary bottleneck.

## Background
The method is derived from implementations in voxel terrain generation, such as the `Eldemarkki/Marching-Cubes-Terrain` project, which uses Unity's Job System for parallel mesh generation [S1, unofficial]. The concept of parallel isosurface extraction has been explored in geophysics for large seismic datasets, where tandem algorithms and parallel processing are used to handle massive volumes (e.g., 40 GB datasets) [S3].
