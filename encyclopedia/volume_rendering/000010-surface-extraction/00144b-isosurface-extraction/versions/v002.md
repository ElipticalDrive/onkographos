# Isosurface extraction


## Overview
Isosurface extraction converts a discrete scalar field into a continuous polygonal mesh representing the surface where the scalar value equals a specific threshold (isovalue) [S2, unofficial][S3, unofficial]. It solves the problem of visualizing internal structures or boundaries within volumetric data by generating a triangle or quad mesh that approximates the implicit surface $f(x,y,z) = I$ [S2, unofficial]. What sets this family apart from direct volume rendering is that it produces an explicit geometric representation (mesh) rather than a rasterized image, allowing for lighting, collision detection, and further geometric processing [S2, unofficial]. Unlike [Blocky meshing](31-blocky-meshing.md), which produces voxel-aligned stair-step surfaces, isosurface methods typically interpolate between grid points to create smooth, curved surfaces [G].

## Shared principles
All isosurface extraction algorithms operate on a discretized domain, typically a regular grid (Cartesian, octree, or tetrahedral) where each cell contains scalar values at its vertices [S2, unofficial][S3, unofficial]. The core mechanism involves traversing the grid cells and evaluating the scalar field at cell vertices or edges [S2, unofficial][S3, unofficial]. For cubic grids, vertex values are compared against the isovalue to determine a topological configuration (e.g., a 256-case index) [S2, unofficial]. For tetrahedral or hybrid grids, the method identifies edges where the scalar field changes sign [S3, unofficial]. Intersection points are computed using inverse linear interpolation for the parameter and linear interpolation for 3D coordinates: $t = (I - f_a) / (f_b - f_a)$ and $P = V_a + t(V_b - V_a)$ [S3, unofficial]. The intersection points are then connected to form primitives (triangles, quads, or polygons) [S2, unofficial]. Adjacent cell primitives are merged into a coherent mesh, often requiring vertex merging to avoid duplicates [S2, unofficial].

## Subtopics

### [Marching Cubes](774-marching-cubes.md)
Marching Cubes is an isosurface extraction algorithm that generates a triangular mesh from a 3D scalar field by processing each voxel independently. It determines the topology of the isosurface intersection with the cube boundaries based on the scalar values at the cube's vertices relative to an isolevel. It builds on the general concept of [Isosurface extraction](30-isosurface-extraction.md) by providing a specific, table-driven method for the cubic grid case. Unlike [Dual Contouring](778-dual-contouring.md), which minimizes error to fit complex features, Marching Cubes uses a fixed lookup table to resolve intersections, making it simpler but prone to topological ambiguities in specific configurations.

### [Dual Contouring](778-dual-contouring.md)
Dual Contouring is an isosurface extraction algorithm that generates a mesh by placing a single vertex inside each grid cell intersected by the surface, rather than on the cell edges like Marching Cubes. It solves a Quadratic Error Function (QEF) to determine the optimal vertex position based on Hermite data (intersection points and surface normals) or Signed Distance Field (SDF) samples. This approach preserves sharp features and allows for watertight meshes on adaptive grids, distinguishing it from linear interpolation methods.

### [Advancing Front Framework for Implicit Surfaces](819-advancing-front-framework-for-implicit-surfaces.md)
An advancing front algorithm that begins with a seed point and grows a triangulation across an implicit surface. The front is the boundary of the already generated mesh. It is advanced by choosing an edge in the front and creating a new triangle attached to it.

### [MLS Projection](823-mls-projection.md)
An iterative algorithm to project a query point onto a surface defined by a set of input points and normals, fitting a local quadratic function.

### [Isosurface Extraction API](836-isosurface-extraction-api.md)
A standardized interface for invoking various extraction algorithms.

### [VESTA](900-vesta.md)
A method for extracting isosurfaces from 3D voxel data by constructing a wire frame of N-cycles (closed loops of voxel faces) that enclose active voxels, which are then triangulated into a non-degenerate, volume-enclosing surface.

### [Dual Marching Cubes](906-dual-marching-cubes.md)
Dual Marching Cubes (MC-Dual) extracts an iso-surface by constructing a dual mesh where each connected patch of triangulation in a primal cell becomes a vertex, and crossed grid edges yield quads connecting adjacent cells' patch vertices. It eliminates the poorly shaped triangles common in standard Marching Cubes isosurfaces while maintaining the same separating properties.

### [Marching Squares](918-marching-squares.md)
An algorithm that extracts isocontour line segments crossing 2D grid cells from a discrete 2D scalar field.

### [Surface Nets](921-surface-nets.md)
Extracts an iso-surface where each cell crossed by the surface gets one vertex placed at the centroid of the cell's edge intersections.

### [Extended CLCIR PLIC Reconstruction](954-extended-clcir-plic-reconstruction.md)
A method to reconstruct a Piecewise Linear Interface Concept (PLIC) plane in Volume of Fluid (VOF) simulations on arbitrary polyhedral grids by extracting an isosurface from an interpolated scalar field and computing a weighted normal vector.

### [MISE (Meshing Isosurfaces by Extracting)](977-mise-meshing-isosurfaces-by-extracting.md)
Generates a 3D mesh from a trained DVR model by querying an implicit occupancy field using the MISE algorithm for adaptive resolution.

### [Marching Cubes Lookup Tables](1106-marching-cubes-lookup-tables.md)
Marching Cubes Lookup Tables are precomputed data structures that map the 256 possible binary configurations of a voxel's corner signs relative to an isovalue to the specific edges intersected by the isosurface and the resulting triangle vertex indices. This method solves the problem of determining mesh topology without runtime branching logic, allowing for efficient traversal on both CPU and GPU architectures. Unlike [Dual Contouring](778-dual-contouring.md), which optimizes for vertex placement and normal accuracy, or [Surface Nets](921-surface-nets.md), which uses a different topological approach, the Lookup Table method strictly follows the original triangulation, prioritizing simplicity and topological consistency over geometric optimality [G].

### [Convex Contouring with Decision Trees](1201-convex-contouring-with-decision-trees.md)
A table-driven contouring method that produces topologically consistent surfaces with a local convexity property, where the polygonal contour inside each cell encloses a convex negative space.

### [Primal Grid Marching Cubes](1211-primal-grid-marching-cubes.md)
Primal Grid Marching Cubes is a GPU-accelerated isosurface extraction technique that processes a 3D scalar volume grid using a compute shader to output a triangle mesh. It adapts the classic Marching Cubes algorithm for parallel execution by utilizing precalculated triangle tables and atomic counters for buffer management, ensuring deterministic memory usage on the GPU. Unlike CPU implementations that may rely on linked lists or dynamic arrays, this method uses fixed-size buffers and a cleanup pass to manage memory, making it suitable for real-time or high-throughput implicit function (SDF) to mesh conversion.

### [Standard Interval Tree for Isosurface Extraction](1230-standard-interval-tree-for-isosurface-extraction.md)
A data structure used to obtain active cells for a particular isosurface with optimal query complexity $O(\log(n) + k)$.

### [Octree-based Isosurfacing](1247-octree-based-isosurfacing.md)
Using an octree as a spatial discretization structure instead of a Cartesian grid for isosurfacing methods like Marching Cubes and Dual Contouring. This allows for adaptive resolution but loses guarantees, potentially causing cracks in Marching Cubes if the octree is not adapted to the surface.

### [Binary Search IsoSurface Extraction](1316-binary-search-isosurface-extraction.md)
Approximates the position of an isosurface between two sample points (left and right) by iteratively halving the interval based on scalar field values.

### [High-Dimensional Triangulation Tables](1336-high-dimensional-triangulation-tables.md)
A method to generate triangulation tables for isosurface extraction in n-dimensional hypercubes, addressing the excessive simplex count produced by recursive contour-meshing which requires subdividing 4-cells into 4-simplices.

### [Marching Cubes Smoothing](1594-marching-cubes-smoothing.md)
A function that takes a 2D or 3D binary embedding array and produces a smooth version of it. It assigns negative values to areas where the binary array is 0, and positive values where the binary array is 1. This preserves fine details and thin structures that are often eroded by other smoothing methods.

### [Extended Trilinear Triangulation](1618-extended-trilinear-triangulation.md)
A method to generate a topologically correct, degenerate-free triangulation of the isosurface within a cube by tracking the connectivity of vertices and edges via positive/negative regions defined by the trilinear interpolant, using convex hulls of intersection points.

### [Extended Marching Cubes](1630-extended-marching-cubes.md)
A variant of Marching Cubes that modifies the field function to return three values (distance from contour on each axis) to compute exact intersection coordinates independently, and uses normal vectors with Quadric Error Functions (QEF) to reconstruct sharp features.

### Minimal Area Triangulation for Polygons
A method to triangulate non-convex or complex polygons resulting from isosurface extraction into triangles, minimizing the total area of the resulting triangles to reduce visual artifacts [S5, unofficial]. If the polygon is cofacial, it performs a fan triangulation from the centroid to avoid introducing new edges on cube faces [S5, unofficial]. For non-cofacial polygons, it uses `mat.GetTriangulation` to compute the minimal area triangulation and maps the triangle indices back to the original polygon vertex indices [S5, unofficial].

### Symmetry Mapping
Maps one of the 256 possible cube configurations to one of 23 canonical base cases using precomputed rotation and base case mappings to simplify triangle generation logic [S6, unofficial]. The `MapToBase` array maps index 0-255 to a BaseCase index and rotation, using 24 rotations to cover all symmetries [S6, unofficial].

### Point Cloud Extraction
A technique to convert isosurfaces to point clouds by evaluating chunks of voxels and extracting vertices at the center of edges where the isosurface passes, without generating face data [S7, unofficial]. It classifies the corners using `classify_corners(&values)` to get a cube index. If the cube index is not 0 and not 255, it calculates the point $p$ by linearly interpolating between `corners[0]` and `corners[6]` at 0.5 [S7, unofficial]. Unlike surface reconstruction methods, this method does not contain any surface data; surfaces have to be reconstructed, ideally on the GPU itself [S7, unofficial].

### Patch Boundary Detection
Process to detect patch boundaries as groups of rings of linear contours on cell faces for automatic construction of look-up tables [S8]. It constructs a single ring using face-tracing: starting from a cell edge with a sign change, facing the positive end, it looks for the next edge with a sign change by turning counter-clockwise on the face boundary until it returns to the starting edge, forming a closed ring [S8]. The linear contour on the cell face is oriented so that the negative region on that face lies to its left when looking from outside. Rings constructed around the same edge-connected component of positive corners are grouped to form the boundary of a single patch [S8].
