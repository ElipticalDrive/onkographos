# Moving Least Squares Implicit Surface Reconstruction

Also called: MLS implicit method

## Overview
Moving Least Squares (MLS) Implicit Surface Reconstruction is a technique for reconstructing a surface from an unordered 3D point cloud by creating an implicit function field using Moving Least Squares, from which isosurfaces are extracted [S1, unofficial]. It differs from its parent [MLS Projection](823-mls-projection.md) by constructing a global implicit field defined by local quadratic fits rather than iteratively projecting query points, and from its sibling [APSS](843-apss-approximate-projected-point-set-surfaces.md) by relying on a standard MLS approximation of the signed distance function rather than approximate projected point set surfaces.

## How it works
**Inputs:** An unordered 3D point cloud $V$ (vertices) and a neighbor count $k$ for normal estimation.
**Outputs:** A triangular mesh representing the isosurface.

**Data Structures:**
*   $V$: Matrix of size $N \times 3$, where $N$ is the number of input points.
*   $N_{norm}$: Matrix of size $N \times 3$, storing per-vertex normals.
*   $C$: Constraint points matrix. Size $(3N) \times 3$.
*   $D$: Constraint values vector. Size $3N$.
*   $k$: Number of nearest neighbors for PCA.
*   $\epsilon$: Small offset distance for constraint generation.
*   $nn\_dist$: Average distance to nearest neighbors (used for scaling $\epsilon$).

**Steps:**

1.  **Normal Estimation:** For each vertex $v_i \in V$, compute the normal $n_i$ using Principal Component Analysis (PCA) on its $k$-nearest neighbors.
    *   Find $k$ nearest neighbors of $v_i$.
    *   Compute the centroid $m$ of these neighbors.
    *   Center the neighbor points: $P_{centered} = P_{neighbors} - m$.
    *   Compute the covariance matrix $S = P_{centered}^T P_{centered}$.
    *   Perform eigenvalue decomposition on $S$.
    *   Select the eigenvector corresponding to the smallest eigenvalue as the normal $n_i$. [S1, unofficial]

2.  **Constraint Generation:** Generate constraints for the implicit function. For each vertex $v_i$ with normal $n_i$:
    *   **Constraint 1 (Vertex):** Point $c_1 = v_i$, Value $d_1 = 0$.
    *   **Constraint 2 (Outside):** Point $c_2 = v_i + \epsilon n_i$, Value $d_2 = \epsilon$.
    *   **Constraint 3 (Inside):** Point $c_3 = v_i - \epsilon n_i$, Value $d_3 = -\epsilon$.
    *   *Note:* The source code uses `eps` and `nn_dist` to compute the offset, suggesting $\epsilon$ may be scaled by local density [S1, unofficial].

3.  **Implicit Function Evaluation:** Evaluate the MLS implicit function $f(x)$ at grid vertices. The function is defined by minimizing the weighted least squares error of the constraints $C$ and $D$. For a query point $x$, the value $f(x)$ is derived from the local quadratic fit that best approximates the signed distance function defined by the constraints. The specific MLS formulation involves weighting constraints by distance to $x$ and solving a local linear system to determine the function value and gradient [S1, unofficial].

4.  **Isosurface Extraction:** Extract the zero-level set of the implicit function field using Marching Tetrahedra. This method divides the grid into tetrahedra and determines intersections with the isosurface within each tetrahedron, offering fewer configurations and no ambiguity compared to Marching Cubes [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Normal Orientation:** The PCA step yields normals without guaranteed consistent orientation across the surface. The source code does not show an orientation propagation step, which may lead to incorrect inside/outside constraints if the input normals are not already oriented or if the point cloud is not manifold [S1, unofficial].
*   **Boundary Effects:** Points near the boundary of the point cloud may have biased normals if the neighbor search is not handled carefully (e.g., using a half-space PCA).
*   **Precision:** The use of floating-point arithmetic in eigenvalue decomposition and least squares solving may introduce small errors in the implicit function values, affecting the accuracy of the extracted isosurface.

## Operating characteristics
*   **Time Complexity:** Normal estimation requires $O(N \cdot k \log N)$ or $O(N \cdot k)$ with a KD-tree. Constraint generation is $O(N)$. Implicit function evaluation requires $O(M \cdot 3N \cdot k)$ or $O(M \cdot 3N)$ where $M$ is the number of grid points, assuming a fixed number of constraints per point. Marching Tetrahedra is $O(M)$. Overall, it is dominated by the implicit function evaluation on the grid.
*   **Memory Complexity:** $O(N + M)$, where $N$ is the number of points and $M$ is the number of grid points. The constraints matrix $C$ and values $D$ take $O(N)$ space.
*   **Strengths:** Produces smooth surfaces. Marching Tetrahedra avoids the ambiguity issues of Marching Cubes.
*   **Limitations:** Requires a dense point cloud for accurate normal estimation. The quality of the reconstruction depends heavily on the choice of $k$ and $\epsilon$. The method is computationally expensive for high-resolution grids.
*   **When to use:** When a smooth, implicit representation is desired from a noisy or unordered point cloud, and computational resources allow for grid-based evaluation.
*   **When not to use:** For real-time applications or very large datasets where memory and time constraints are tight.

## Background
The method is described in the context of a minimal dependency implementation for 3D reconstruction using accelerated Moving Least Squares and Marching Tetrahedra [S1, unofficial]. The implementation uses Eigen for linear algebra and a custom KD-tree for neighbor search. It is presented as an alternative to more complex surface reconstruction techniques, emphasizing simplicity and the use of Marching Tetrahedra for unambiguous isosurface extraction.
