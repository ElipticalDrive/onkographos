# Domain Search Isosurface Extraction

Also called: Domain Search

## Overview
Domain Search Isosurface Extraction is a tetrahedral marching method that extracts an isosurface from a volumetric scalar field by decomposing the domain into tetrahedra and determining intersection points via linear interpolation [S1, unofficial]. It differs from cubic grid methods like Marching Cubes by operating directly on tetrahedral cells, avoiding the ambiguity issues associated with cubic cell configurations, while maintaining a straightforward lookup-table-based topology determination [S1, unofficial].

## How it works
**Inputs and Outputs**
- **Input**: A volumetric scalar field defined on a grid of dimensions $x_{axis} \times y_{axis} \times z_{axis}$ (typical: $256 \times 256 \times 256$) [S1, unofficial]. The field values are stored in an integer vector `col` for the current tetrahedron vertices [S1, unofficial].
- **Output**: A list of 3D vertices representing the isosurface, stored in an array `newvert` of type `Vector3f` [S1, unofficial].

**Data Structures**
- `Vertices`: An array of 8 `Vector3f` elements representing the 8 corners of the source cubic cell, which is decomposed into tetrahedra [S1, unofficial].
- `col`: A vector of 4 integers storing the scalar field values at the 4 vertices of the current tetrahedron being processed [S1, unofficial].
- `newvert`: An array of `Vector3f` with a maximum size of $256 \times 256 \times 400$ (or dynamically sized based on `ind`) to store the generated isosurface vertices [S1, unofficial].
- `index`: An unsigned char (8-bit integer) used to store the topological configuration of the tetrahedron relative to the isovalue [S1, unofficial].
- `p`: An integer index tracking the current position in the `newvert` array [S1, unofficial].
- `ind`: A constant defining the maximum capacity of the `newvert` array [S1, unofficial].

**Algorithm Steps**
1. **Tetrahedron Decomposition**: The volumetric grid is decomposed into tetrahedra. For each tetrahedron, identify its 4 vertices and their corresponding scalar field values.
2. **Index Calculation**: Compute the cell index by comparing each vertex's scalar value ($col[i]$) against the target isovalue (`isolevel`). If $col[i] < isolevel$, set the $i$-th bit of the index:
   $$ index = \sum_{i=0}^{3} (col[i] < isolevel) \cdot 2^i $$
   [S1, unofficial]
3. **Boundary Check**: Before processing the case, check if the current vertex buffer pointer `p` allows for safe writing. If $p < (ind - 20)$, proceed; otherwise, skip vertex generation to prevent buffer overflow [S1, unofficial].
4. **Case Handling**: Based on the calculated `index` (0x00 to 0x0F), determine the intersection points:
   - **Case 0x00 (0000)**: All vertices are outside ($col[i] \ge isolevel$). No intersection.
   - **Case 0x0F (1111)**: All vertices are inside ($col[i] < isolevel$). No intersection.
   - **Case 0x01 (0001)**: Only vertex 0 is inside. Generate 3 vertices by interpolating between vertex 0 and vertices 1, 3, and 2 respectively. Increment `p` by 3.
   - **Case 0x02 (0010)**: Only vertex 1 is inside. Generate 3 vertices by interpolating between vertex 1 and vertices 0, 2, and 3 respectively. Increment `p` by 3.
   - **Case 0x04 (0100)**: Only vertex 2 is inside. Generate 3 vertices by interpolating between vertex 2 and vertices 0, 3, and 1 respectively. Increment `p` by 3.
   - **Case 0x08 (1000)**: Only vertex 3 is inside. Generate 3 vertices by interpolating between vertex 3 and vertices 1, 2, and 0 respectively. Increment `p` by 3.
   - **Case 0x03 (0011)**: Vertices 0 and 1 are inside. Generate 6 vertices forming two triangles. Interpolate edges (0,3), (0,2), (1,3), (0,2), (2,1), (1,3). Increment `p` by 6.
   - **Case 0x05 (0101)**: Vertices 0 and 2 are inside. Generate 6 vertices. Interpolate edges (0,1), (0,3), (1,2), (2,1), (0,3), (3,2). Increment `p` by 6.
   - **Case 0x09 (1001)**: Vertices 0 and 3 are inside. Generate 6 vertices. Interpolate edges (0,1), (1,3), (0,2), (3,1), (2,3), (0,2). Increment `p` by 6.
   - **Case 0x06 (0110)**: Vertices 1 and 2 are inside. Generate 6 vertices. Interpolate edges (0,1), (1,3), (0,2), (0,2), (1,3), (3,2). Increment `p` by 6.
   - **Case 0x0C (1100)**: Vertices 2 and 3 are inside. Generate 6 vertices. Interpolate edges (3,1), (0,3), (0,2), (0,2), (1,3), (1,2). Increment `p` by 6.
   - **Case 0x0A (1010)**: Vertices 1 and 3 are inside. Generate 6 vertices. Interpolate edges (0,1), (0,3), (1,2), (2,3), (0,1), (3,2). Increment `p` by 6.
   - **Other Cases**: Cases 0x0B, 0x0D, 0x0E, 0x07, 0x01, etc., follow similar logic where the number of generated vertices depends on the number of inside vertices and the specific topology of the tetrahedron cut. The source code explicitly handles cases with 1 or 2 inside vertices, generating 3 or 6 vertices respectively. Cases with 3 inside vertices are topologically equivalent to cases with 1 outside vertex (complement), and cases with 3 outside vertices are equivalent to 1 inside vertex. The source code implies handling all 16 cases, but explicit code snippets are provided for specific configurations. For implementation completeness, the complement cases (e.g., 0x0E for 3 inside) should mirror the 1-inside cases by interpolating the outside vertex with the three inside vertices.

**Interpolation Formula**
To find the intersection point on an edge between two vertices with positions $P_a, P_b$ and scalar values $a, b$:
1. If $a == b$, the intersection is the midpoint:
   $$ P = \frac{P_a + P_b}{2} $$
   [S1, unofficial]
2. Otherwise, calculate the interpolation parameter $t$:
   $$ t = \left| \frac{isolevel - a}{b - a} \right| $$
   $$ P = P_a \cdot (1 - t) + P_b \cdot t $$
   [S1, unofficial]

def interpolate(x_a, x_b, isolevel, val_a, val_b):
    """
    Interpolate the position along an edge between two vertices.
    x_a, x_b: Scalar coordinate (x, y, or z) of the two vertices.
    isolevel: The target isovalue.
    val_a, val_b: Scalar field values at the two vertices.
    """
    if val_a == val_b:
        return (x_a + x_b) / 2.0
    else:
        # Calculate interpolation factor t
        # Using absolute value as per source, though standard linear interpolation
        # might not require abs if order is consistent. Source uses abs.
        t = abs((isolevel - val_a) / (val_b - val_a))
        return x_a * (1 - t) + x_b * t

**Parameters**
- `isolevel`: The scalar value defining the isosurface.
- `x_axis, y_axis, z_axis`: Dimensions of the volumetric grid. Typical value: $256 \times 256 \times 256$ [S1, unofficial].

**Edge Cases and Pitfalls**
- **Division by Zero**: If the scalar values at the two endpoints of an edge are equal ($a == b$), linear interpolation is undefined. The method uses the midpoint formula $(x+y)/2$ in this case [S1, unofficial].
- **Buffer Overflow**: The algorithm checks if the current vertex index `p` is within bounds ($p < ind - 20$) before writing to the `newvert` array to prevent out-of-bounds access [S1, unofficial].
- **Tetrahedron Decomposition**: The correctness of the method depends on the specific decomposition of the cubic grid into tetrahedra. The source code implies a specific decomposition, and the vertex indices (a, b, c, d) must map correctly to the cube vertices [S1, unofficial].

## Operating characteristics
- **Time Complexity**: Linear with respect to the number of tetrahedra in the domain. Each tetrahedron is processed in constant time.
- **Memory Complexity**: Linear with respect to the number of tetrahedra, as the output vertex buffer size is proportional to the surface area. The source uses a fixed-size buffer `newvert` of size $256 \times 256 \times 400$ [S1, unofficial].
- **Strengths**: Avoids the topological ambiguities of Marching Cubes by using tetrahedra. Simple implementation using lookup tables.
- **Limitations**: Requires tetrahedral decomposition of the grid. The source code's handling of 2-inside cases generating 6 vertices is non-standard and may require verification against the full source code. Buffer overflow protection is manual.
