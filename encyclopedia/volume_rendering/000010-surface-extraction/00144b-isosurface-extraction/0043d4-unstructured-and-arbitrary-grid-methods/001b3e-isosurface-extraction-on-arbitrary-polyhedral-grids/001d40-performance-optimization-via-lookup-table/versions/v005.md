# Performance Optimization via Lookup Table

Also called: Pre-computed connectivity

## Overview
This method accelerates isosurface extraction on arbitrary polyhedral grids by pre-computing vertex connectivity for all possible sign configurations and storing it in a lookup table for rapid access during extraction [S1]. Unlike standard methods constrained to specific cell geometries, it is geometry-agnostic, allowing the same optimization strategy to be applied to arbitrary cell types [S1].

## How it works
**Inputs and Outputs:**
The method takes a scalar field defined on an arbitrary polyhedral grid and an isovalue $\tilde{\phi}$ as input, and outputs a set of triangles representing the isosurface [G]. The core data structure is a lookup table mapping each possible vertex sign configuration to a pre-computed list of vertex indices (connectivity) that form the isosurface segments within that cell [S1].

**Pre-computation Phase:**
1. Identify the cell geometry and determine the number of vertices $N$ per cell [G].
2. Generate all $2^N$ possible sign patterns of vertex values relative to the isovalue [G].
3. For each pattern, compute the exact connectivity (which vertices are connected by the isosurface) using the specific geometric constraints of the cell [G].
4. Store these connectivity lists in a lookup table indexed by the sign pattern integer [S1].

**Extraction Phase:**
1. Iterate through each cell in the grid [G].
2. Evaluate the scalar field at each vertex of the cell [G].
3. Determine the sign of each vertex relative to the isovalue ($+1$ if $> \tilde{\phi}$, $-1$ if $< \tilde{\phi}$, $0$ if $= \tilde{\phi}$) [G].
4. Construct an integer index from these signs (e.g., treating signs as bits) [G].
5. Retrieve the pre-computed connectivity list from the lookup table using this index [S1].
6. Generate triangles using the vertex indices from the retrieved list [G].

**Formulas:**
The connectivity is determined by solving for the intersection of the isosurface with the cell edges [G]. For a linear interpolation, the intersection point $P$ on an edge between vertices $V_i$ and $V_j$ with values $\phi_i$ and $\phi_j$ is:
$$ P = V_i + \frac{\tilde{\phi} - \phi_i}{\phi_j - \phi_i} (V_j - V_i) $$
where $V_i$ and $V_j$ are the spatial coordinates of the cell vertices, $\phi_i$ and $\phi_j$ are their scalar field values, and $\tilde{\phi}$ is the target isovalue [G]. The lookup table stores the indices of vertices involved in these intersections [G].

**Parameters:**
The cell geometry defines the size of the lookup table ($2^N$ entries) [S1]. For a cube, $N=8$, resulting in 256 entries [S1]. Parallel execution using OpenMP (`-fopenmp`) can significantly speed up the extraction phase [S1].

**Edge Cases:**
Floating-point precision errors may cause sign flips [G]. A small epsilon tolerance is often used when comparing vertex values to the isovalue [G]. Degenerate cases where vertices lie exactly on the isosurface require explicit handling to avoid undefined connectivity [G].

**Pseudocode:**
```python
def precompute_connectivity(N):
    table = {}
    for pattern in range(1 << N):
        connectivity = compute_cell_connectivity(pattern, N)
        table[pattern] = connectivity
    return table

def extract_isosurface(grid, lookup_table, isovalue):
    triangles = []
    for cell in grid.cells:
        signs = []
        for vertex in cell.vertices:
            if vertex.value > isovalue:
                signs.append(1)
            elif vertex.value < isovalue:
                signs.append(-1)
            else:
                signs.append(0)
        index = 0
        for i, s in enumerate(signs):
            if s > 0:
                index |= (1 << i)
        connectivity = lookup_table[index]
        for tri in connectivity:
            triangles.append(tri)
    return triangles
```

## Subtopics

### [Tetrahedral Marching Cubes (5-tetrahedra method)](4547-tetrahedral-marching-cubes-5-tetrahedra-method.md)
Decomposes cubes into five tetrahedra to extract isosurfaces from regular voxel grids, covering all 81 sign patterns including degenerate cases. It is deterministic and topology-agnostic, solving $V - L = 0$ directly without ambiguity checks. Choose it when guaranteed manifold output is required without topology post-processing.

### [Tetrahedral Marching Cubes Neighbor Lookup](11620-tetrahedral-marching-cubes-neighbor-lookup.md)
A data structure that maps tetrahedra during extraction on unstructured or arbitrary polyhedral grids by providing anchor displacements and neighbor offsets for vertices around a cube corner [G]. It eliminates exhaustive tetrahedron searches during decomposition [G]. Choose it when processing highly irregular grids where neighbor traversal dominates runtime.

## Operating characteristics
Pre-computation is $O(2^N \cdot C)$ where $C$ is the cost of computing connectivity for one cell type [G]. Extraction is $O(1)$ per cell for table lookup, plus $O(V)$ for triangle generation [G]. Memory complexity is $O(2^N \cdot K)$ where $K$ is the average number of vertices per connectivity list, which remains small for standard cells like cubes [G]. On an iMac Pro (2017, 2.3 GHz Intel Xeon W), using OpenMP with all available threads achieves a $\times 6$ speedup compared to single-threaded execution [S1]. Without pre-computation, the method is on average 1.8 times slower than optimized Marching Cubes on cubes [S1]. The method is geometry-agnostic and fast, but pre-computation cost and exponential memory growth with vertex count per cell are limitations [G].

## Background
The method originated in the context of generalizing isosurface extraction to arbitrary grids to address the computational inefficiency of on-the-fly topological analysis for non-standard cell geometries [S1]. It builds on the principles of [Marching Cubes](52-marching-cubes.md) but extends the lookup table concept to arbitrary polyhedral cells [S1].
