# GPU-accelerated Marching Cubes with Distance Extraction

Also called: WebGL Signed Distance Function Mesher, glsl-marching-cubes

## Overview
This method extracts an STL mesh from a signed distance function (SDF) defined in a GLSL shader by extracting vertex distances from the GPU first, then processing the data on the CPU. It sets itself apart from pure GPU implementations by avoiding the high cost and difficulty of retrieving large volumes of geometry data back from the GPU, which was found to be too slow [S1, unofficial].

## How it works
**Inputs:**
- A signed distance function defined as a GLSL shader.
- Volume dimensions (`dims`): array of 3 integers.
- Volume bounds (`bounds`): array of 2 arrays of 3 floats (min and max coordinates).

**Outputs:**
- An STL mesh file.

**Data Structures:**
- `volume`: An object containing `dims` (array of 3 integers), `bounds` (array of 2 arrays of 3 floats), `vertexDims` (array of 3 integers), `vertexCount` (integer), and `size` (integer) [S1, unofficial].
- `blockPotentialBuffers`: An array of `ArrayBuffer` objects, each of size `volume.vertexCount * 4` bytes, storing `Float32` values [S1, unofficial].

**Parameters:**
- `maxSize`: The maximum texture size for the GPU rendering buffer, capped at 4096 [S1, unofficial].
- `numWorkers`: The number of worker threads used for parallel processing, set to 4 [S1, unofficial].
- `blocks`: The number of chunks to split the volume into for worker distribution, set to 256 [S1, unofficial].

**Steps:**
1.  **Subdivision**: Subdivide the volume to be marched into blocks small enough to fit the maximum texture size (`maxSize`) [S1, unofficial].
2.  **Distance Extraction**: Extract distances for each cube vertex from the GLSL shader. This is done by rendering the shader to a framebuffer and reading the pixels [S1, unofficial].
3.  **Skip Empty Blocks**: Skip any blocks which are entirely inside (negative distance) or outside (positive distance) the surface. This saves time for models with a lot of empty space [S1, unofficial].
4.  **CPU Marching Cubes**: Run the standard Marching Cubes algorithm on the CPU for the remaining blocks [S1, unofficial].

**Pseudocode:**
```python
def extract_mesh(shader, dims, bounds):
    # 1. Subdivision
    # Split volume into blocks fitting maxSize
    volumes = split_volume(dims, bounds, max_size=4096)
    
    all_potentials_buffers = []
    
    for volume in volumes:
        # 2. Distance Extraction
        # Create buffers for workers
        num_workers = 4
        block_potential_buffers = []
        block_potentials = []
        
        for i in range(num_workers):
            buffer = ArrayBuffer(volume.vertex_count * 4)
            potentials = Float32Array(buffer)
            block_potential_buffers.append(buffer)
            block_potentials.append(potentials)
            
        # Render shader to get distances
        # uniforms: boundsA, boundsB, dims
        render_shader(shader, volume.bounds[0], volume.bounds[1], volume.dims)
        
        # Read pixels from GPU
        pixels = read_pixels()
        
        # Check for geometry and distribute to workers
        contains_geometry = False
        previous_value = None
        
        for i in range(len(pixels)):
            value = unpack_float(pixels[i])
            
            # Check if surface crosses this vertex relative to previous
            # Note: Logic from source checks sign change
            if previous_value is not None and (value > 0) != (previous_value > 0):
                contains_geometry = True
            
            previous_value = value
            
            # Distribute value to all worker buffers
            for bl in range(num_workers):
                block_potentials[bl][i] = value
                
        if not contains_geometry:
            continue
            
        all_potentials_buffers.append(block_potential_buffers)
        
    # 3. CPU Marching Cubes
    # Initialize workers
    for buffer_set in all_potentials_buffers:
        for buffer in buffer_set:
            init_worker(buffer)
            
    # Process blocks
    blocks = 256
    for volume in volumes:
        cubes = volume.dims[0] * volume.dims[1] * volume.dims[2]
        start = 0
        end = 0
        current_blocks = blocks
        
        while current_blocks > 0:
            start = end
            end = start + floor((cubes - start) / current_blocks)
            
            # Send block range to workers
            # Workers process their assigned chunk of the volume
            process_block(start, end, all_potentials_buffers)
            
            current_blocks -= 1
            
    # Combine results
    mesh = combine_meshes()
    return mesh
```

**Edge Cases and Pitfalls:**
- Large meshes are saved in parts and must be re-combined externally (e.g., with MeshLab) [S1, unofficial].
- Missing triangles (holes) may appear in the resulting mesh [S1, unofficial].

## Operating characteristics
- **Time Complexity**: Depends on the number of blocks and the cost of GPU-CPU transfer. The method avoids the high cost of full GPU-side marching cubes data retrieval [S1, unofficial].
- **Memory Complexity**: Requires storing potential buffers for each worker per volume block. Buffer size is `volume.vertexCount * 4` bytes per worker [S1, unofficial].
- **Strengths**: Reduces GPU/CPU round trips by extracting distances first. Skips empty blocks efficiently [S1, unofficial].
- **Limitations**: Requires CPU processing for the actual mesh generation. Large meshes are split into parts. Potential for holes in the mesh [S1, unofficial].
- **When to use**: When extracting meshes from SDFs defined in shaders and pure GPU implementation is too slow due to data retrieval costs [S1, unofficial].

## Background
This method is associated with the `glsl-marching-cubes` project by tdhooper [S1, unofficial]. It was developed as a WebGL-based solution for extracting STL meshes from signed distance functions. The approach was chosen because running the entire marching cubes algorithm on the GPU was found to be too slow due to the cost and difficulty of getting data back onto the CPU [S1, unofficial]. The JavaScript implementation is based on `mikolalysenko/isosurface` [S1, unofficial].
