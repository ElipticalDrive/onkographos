# Marching Cubes for EB Generation

Also called: MC33, Marching-Cubes Geometry Generation

## Overview
Marching Cubes for EB Generation is an algorithm that produces Embedded Boundary (EB) geometry on 3D Cartesian grids by resolving a surface using the Marching Cubes 33 (MC33) lookup tables, computing volume/area fractions, centroids, normals, and connectivity [S1, unofficial]. It solves the problem of generating high-fidelity EB representations from implicit functions or STL files, offering significantly better geometric accuracy than the legacy EB construction methods [S1, unofficial]. Unlike standard isosurface extraction which outputs a mesh, this method integrates surface resolution directly into the Cartesian grid's fluid/structure classification, ensuring single-valued boundary representations compatible with finite-volume solvers [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Inputs:** A 3D Cartesian grid with cubic cells ($dx = dy = dz$); a geometry source defined as either an implicit function $f(\mathbf{x})$ or an STL mesh; runtime parameters controlling generation and cleanup.
*   **Outputs:** A complete single-valued EB dataset including volume fractions, area fractions, centroids, boundary normals, and connectivity for each cell and face.

**Data Structures**
*   **MCFab:** A data structure storing resolved MC33 face-connectivity decisions and cached edge intersections. The edge intersections are stored as normalized crossing locations (values in $[0, 1]$) along the cell edges. These cached values are shared by downstream geometry calculations, including MC vertices, face apertures, edge centroids, and cell moments [S1, unofficial].
*   **Geometry-Source Adapters:** Generic adapters (e.g., in `AMBeX_EB2_Level_MC.H/.cpp`) that wrap the geometry source. If the source provides its own MC sampling (like `STLtools`), it is used directly; otherwise, generic adapters reuse the shop's `fillFab` and `getIntercept` methods [S1, unofficial].

**Parameters**
*   `eb2.geometry_method = marching_cubes`: Selects the MC generator. Applies to built-in implicit functions, user-defined implicit functions (`EB2::makeShop`), and STL files. Ignored if `eb2.geom_type = chkpt_file` [S1, unofficial].
*   `eb2.mc_stl_file`: Optional path to write the MC triangulation as an ASCII STL file via `WriteEBSurfaceSTL` [S1, unofficial].
*   `eb2.small_volfrac`: Threshold for removing small cells during cleanup [S1, unofficial].
*   `eb2.maxiter`: Maximum iterations for cleanup [S1, unofficial].
*   `eb2.cover_multiple_cuts`: Controls whether unsupported faces and cells may be repaired (set to 1 to allow covering) [S1, unofficial].
*   `eb2.build_coarse_level_by_coarsening`: If 0, coarse levels are rebuilt from the geometry description; if 1, they are coarsened from fine levels (MC only applies to finest and rebuilt coarse levels) [S1, unofficial].

**Algorithm Steps**

1.  **Grid Validation:** Verify the grid is 3D and cubic ($dx == dy == dz$). Reject if non-cubic [S1, unofficial].
2.  **Level Set Construction:** Build a nodal level set from the geometry source.
    *   For implicit functions: Sample $f(\mathbf{x})$ at grid nodes without clamping sample positions to the domain. Snap nodes lying on the surface within roundoff to exact zero [S1, unofficial].
    *   For STL: Use a narrow-band level set where exact distance values are retained on cut-cell interpolation and vertex-normal stencils, while only inside/outside classification is retained farther from the interface [S1, unofficial].
3.  **Edge Intersection Resolution:** Compute exact Cartesian-edge intersections for all sign-changing edges. Do not rely on linear interpolation of sampled level-set values.
    *   For implicit functions: Find the crossing of every sign-changing edge using Brent root finding on the function $f(\mathbf{x})$ [S1, unofficial].
    *   For STL: Intersect the edge with the original triangles using `STLtools::fillMarchingCubesEdgeIntersections` [S1, unofficial].
    *   Fallback: If root finding fails, fall back to linear interpolation [S1, unofficial].
    *   Store these normalized crossing locations in the `MCFab` [S1, unofficial].
4.  **MC33 Lookup and Connectivity:** Resolve the surface within each cell using MC33 lookup tables.
    *   Determine the nodal sign configuration (256 cases) based on the level set values at the 8 vertices.
    *   Use the cached edge intersections from Step 3 to determine vertex positions and face connectivity.
    *   Store resolved MC33 face-connectivity decisions in `MCFab` to ensure ambiguous faces use consistent topology for both face apertures and MC triangle generation [S1, unofficial].
5.  **Geometry Computation:** Compute the complete single-valued EB dataset for each cell and face:
    *   Volume and area fractions.
    *   Centroids.
    *   Boundary normals.
    *   Connectivity [S1, unofficial].
6.  **Single-Valued Consistency Checks:** Because the EB representation is single-valued, check for:
    *   Faces containing more than one resolved fluid aperture.
    *   Cells with invalid MC topology, multiple fluid components, or MC33 "tunnel" tilings where fluid regions join only through the cell interior.
    *   Invalid face or cell geometry records.
    *   Cut cells with volume fraction below `eb2.small_volfrac` [S1, unofficial].
7.  **Cleanup and Repair:**
    *   Iteratively remove small cells and geometry unsupported by the single-valued representation by moving incident fluid nodes to the interface [S1, unofficial].
    *   If `eb2.cover_multiple_cuts = 1`, repair unsupported faces and cells that cannot be represented as a single-valued cell [S1, unofficial].
    *   Handle exact-zero nodal values and surfaces aligned with grid nodes or faces [S1, unofficial].
8.  **Optional Output:** If `eb2.mc_stl_file` is specified, write the MC triangulation as an ASCII STL file using `WriteEBSurfaceSTL` [S1, unofficial].

**Pseudocode**

```python
def generate_marching_cubes_eb(grid, geometry_source, params):
    """
    Generate Embedded Boundary geometry using Marching Cubes 33.
    
    Args:
        grid: 3D Cartesian grid with cubic cells (dx == dy == dz).
        geometry_source: Implicit function f(x) or STL mesh.
        params: Runtime parameters (eb2.geometry_method, eb2.small_volfrac, etc.)
    
    Returns:
        EB dataset: volume fractions, area fractions, centroids, normals, connectivity.
    """
    # Step 1: Validate Grid
    if grid.dim != 3 or not is_cubic(grid):
        raise ValueError("Marching Cubes EB generation requires 3D cubic grids.")
    
    # Step 2: Build Nodal Level Set
    level_set = build_nodal_level_set(grid, geometry_source)
    # Snap nodes on surface to exact zero
    for node in grid.nodes:
        if abs(level_set[node]) < ROUND_OFF_THRESHOLD:
            level_set[node] = 0.0
            
    # Step 3: Resolve Edge Intersections
    mcfab = MCFab()
    for edge in grid.edges:
        if sign_change(level_set, edge):
            if geometry_source.is_implicit():
                # Brent root finding on implicit function
                intersection = brent_root_finding(geometry_source, edge)
            elif geometry_source.is_stl():
                # Intersect edge with original STL triangles
                intersection = stltools_fill_marching_cubes_edge_intersections(edge, geometry_source.triangles)
            else:
                # Fallback to linear interpolation
                intersection = linear_interpolation(level_set, edge)
            
            # Store normalized crossing location in MCFab
            mcfab.set_edge_intersection(edge, intersection)
            
    # Step 4: MC33 Lookup and Connectivity
    for cell in grid.cells:
        # Determine nodal sign configuration
        config = get_nodal_sign_configuration(level_set, cell)
        
        # Resolve face connectivity using MC33 lookup tables
        # Use cached edge intersections from MCFab
        face_decisions = mc33_lookup(config, mcfab.get_edge_intersections(cell))
        
        # Store decisions in MCFab
        mcfab.set_face_decisions(cell, face_decisions)
        
    # Step 5: Compute Geometry
    eb_dataset = EB_Dataset()
    for cell in grid.cells:
        # Compute volume fraction, centroid, etc. using MCFab data
        eb_dataset.cell[cell] = compute_cell_geometry(cell, mcfab)
        
    for face in grid.faces:
        # Compute area fraction, normal, etc.
        eb_dataset.face[face] = compute_face_geometry(face, mcfab)
        
    # Step 6: Single-Valued Consistency Checks
    for face in grid.faces:
        if face.has_multiple_fluid_apertures(eb_dataset):
            mark_invalid(face)
            
    for cell in grid.cells:
        if cell.has_invalid_mc_topology(eb_dataset):
            mark_invalid(cell)
        if cell.volume_fraction < params.eb2_small_volfrac:
            mark_small(cell)
            
    # Step 7: Cleanup and Repair
    if params.eb2_cover_multiple_cuts:
        repair_unsupported_geometry(eb_dataset, grid)
        
    iter = 0
    while has_unsupported_geometry(eb_dataset) and iter < params.eb2_maxiter:
        move_fluid_nodes_to_interface(eb_dataset, grid)
        iter += 1
        
    # Step 8: Optional STL Output
    if params.eb2_mc_stl_file is not None:
        write_eb_surface_stl(eb_dataset, params.eb2_mc_stl_file)
        
    return eb_dataset
```

## Operating characteristics
*   **Time Complexity:** Linear in the number of cells and faces, as each cell is processed independently with a constant-time MC33 lookup. Root finding for implicit functions adds a small constant factor per sign-changing edge.
*   **Memory Complexity:** Proportional to the number of cells and faces, storing volume/area fractions, centroids, normals, and connectivity. The `MCFab` structure adds overhead for cached edge intersections.
*   **Measured Performance:** The EB produced by this method is significantly better than the legacy EB method [S1, unofficial]. Specific performance metrics (speed, memory usage) are not provided in the sources.
*   **Strengths:** High geometric accuracy; exact edge intersections avoid interpolation errors; integrated single-valued EB representation; supports implicit functions and STL.
*   **Limitations:** Restricted to 3D cubic Cartesian grids; incompatible with multi-valued cuts (`BuildMultiValuedMultiCut`); requires cleanup for unsupported geometries; root finding may fail for complex implicit functions (falls back to linear interpolation).
*   **When to Use:** When high-fidelity EB geometry is needed on 3D Cartesian grids with cubic cells, from implicit functions or STL files.
*   **When Not to Use:** On non-cubic grids; for multi-valued surfaces; when legacy EB compatibility is required.

## Background
This method was introduced in the AMReX framework via Pull Request #5607 by ankithadas in August 2026 [S1, unofficial]. It extends the Marching Cubes algorithm to Embedded Boundary generation, addressing limitations of the legacy EB construction. The implementation includes tests for various geometries (box, sphere, gyroid, STL files) and ensures consistency with AMReX's single-valued EB representation.
