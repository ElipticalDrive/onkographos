# SEVA (Surface Extraction with Volumetric Adaptivity)

Also called: two pass surface extraction algorithm

## Overview
SEVA is a two-pass algorithm for incremental surface extraction from hexahedral finite element meshes that accommodates volumetric adaptivity, such as element removal or failure [S1, unofficial]. It identifies paired internal surfaces by hashing local connectivity and nodal weights, then constructs a polygon list containing only external (unpaired) surfaces [S1, unofficial]. It is distinguished from standard marching cubes by its explicit handling of element removal via a master surface list counter, ensuring that previously hidden interior surfaces are correctly exposed as external surfaces when adjacent elements fail [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of active hexahedral elements, each defined by 8 nodes [S1, unofficial]. Each node has a global index $j$ and spatial coordinates [G]. An activity vector indicating element validity (for adaptivity) [S1, unofficial].
*   **Output:** A polygon vertex pointer list containing global node numbers and element material numbers, ready for vertex coordinate gathering and rendering [S1, unofficial].

**Data Structures:**
1.  **Hash Table:** An array of length $6 N_{hex}$, where $N_{hex}$ is the number of hexahedral elements [S1, unofficial]. Each entry stores:
    *   `hash_key`: The computed hash value for the face [S1, unofficial].
    *   `element_id`: The index of the hex element [S1, unofficial].
    *   `face_id`: The index of the face within the element (0-5) [S1, unofficial].
    *   Entries are added in sequential order as faces are processed [S1, unofficial].
2.  **Master Surface List:** A dynamic list constructed during Pass 1 [S1, unofficial]. Each entry contains:
    *   `hash_value`: The unique hash key [S1, unofficial].
    *   `surface_count`: Integer counter (max 2) [S1, unofficial].
    *   `element_ids`: List of element indices associated with this hash [S1, unofficial].
    *   `face_ids`: List of face indices associated with this hash [S1, unofficial].
3.  **Polygon Vertex Pointer List:** The final output structure containing global node indices and material IDs for rendering [S1, unofficial].

**Parameters:**
*   **Nodal Weight ($w_j$):** Defined as $w_j = 10^{(j-1)}$, where $j$ is the local node index within the element ($j \in [1, 8]$) [S1, unofficial]. This exponential weighting provides dispersion in hash keys to minimize collisions, though collisions are handled by the sorting step [S1, unofficial].

**Steps:**
1.  **Pass 1: Hashing and Sorting**
    1.  Initialize the Hash Table with $6 N_{hex}$ empty slots [S1, unofficial].
    2.  For each active hexahedral element $e$:
        a.  For each of the 6 faces $f$ of element $e$:
            i.  Identify the 4 nodes defining face $f$ [G].
            ii. Retrieve the global node indices $G_{k_m}$ for these local nodes [G].
            iii. Sort the global node indices in ascending order to form the sorted local surface connectivity vector $S_{ij} = [\min(G), \dots, \max(G)]$ [S1, unofficial].
            iv. Compute the hash key $H$ using the formula:
                $$ H = \text{hash}(S_{ij}, w_j) $$
                Where $w_j$ corresponds to the nodal weights of the nodes in $S_{ij}$ [S1, unofficial].
            v. Store $(H, e, f)$ in the next available slot in the Hash Table [S1, unofficial].
    3.  Perform an indexed heap sort on the Hash Table entries based on $H$ in ascending order [S1, unofficial]. This is an $O(N \log N)$ operation [S1, unofficial].
2.  **Pass 1 (Continued): Master Surface List Construction**
    1.  Initialize an empty Master Surface List [S1, unofficial].
    2.  Traverse the sorted Hash Table [S1, unofficial].
    3.  Identify groups of adjacent entries with identical hash keys $H$ [S1, unofficial].
    4.  For each group:
        a.  Create a new entry in the Master Surface List with `hash_value` = $H$ [S1, unofficial].
        b.  Set `surface_count` = number of entries in the group (typically 1 or 2) [S1, unofficial].
        c.  Populate `element_ids` and `face_ids` from the group entries [S1, unofficial].
        *   *Note:* A count of 2 indicates paired (internal) surfaces [S1, unofficial]. A count of 1 indicates an unpaired (external) surface [S1, unofficial].
3.  **Pass 2: Polygon List Generation**
    1.  Initialize an empty Polygon Vertex Pointer List [S1, unofficial].
    2.  Iterate through the Master Surface List [S1, unofficial].
    3.  For each entry where `surface_count` == 1:
        a.  This represents an external surface [S1, unofficial].
        b.  Retrieve the `element_id` and `face_id` [S1, unofficial].
        c.  Add the global node numbers for the 4 vertices of this face to the Polygon Vertex Pointer List, along with the element's material number [S1, unofficial].
    4.  Concatenate any active shell elements onto the Polygon Vertex Pointer list [S1, unofficial].
4.  **Volumetric Adaptivity Handling (Element Removal)**
    *   When an element fails or is removed:
        a.  Identify all faces of the failed element [S1, unofficial].
        b.  For each face, locate its corresponding entry in the Master Surface List (using the pre-computed hash or element/face mapping) [S1, unofficial].
        c.  Decrement the `surface_count` for that hash entry [S1, unofficial].
        d.  If `surface_count` becomes 1, the surface is now considered valid (exposed interior surface) and will be included in the Polygon Vertex Pointer List in the next Pass 2 execution [S1, unofficial].
    *   *Note:* The canonical local node numbering scheme for hex elements ensures that freshly exposed polygon normals face outwards, guaranteeing consistent lighting [S1, unofficial].

**Pseudocode:**

```python
def compute_face_hashes(element_local_nodes, global_nodes_map, element_id):
    """Computes hash keys for all 6 faces of a hexahedral element."""
    # Standard hexahedron face definitions (local node indices 0-7)
    face_definitions = [
        [0, 1, 2, 3], [4, 5, 6, 7], [0, 1, 5, 4],
        [2, 3, 7, 6], [0, 3, 7, 4], [1, 2, 6, 5]
    ]
    entries = []
    for face_idx, face_local_nodes in enumerate(face_definitions):
        # Retrieve global node indices
        global_indices = [global_nodes_map[(element_id, ln)] for ln in face_local_nodes]
        # Sort global indices for canonical representation
        sorted_global_indices = sorted(global_indices)
        # Compute nodal weights w_j = 10^(j-1) where j is 1-based local node index
        # ln is 0-based, so j-1 equals ln
        weights = [10 ** ln for ln in face_local_nodes]
        # Deterministic hash combining sorted connectivity and weights
        hash_key = hash((tuple(sorted_global_indices), tuple(weights)))
        entries.append({
            'hash_key': hash_key,
            'element_id': element_id,
            'face_id': face_idx,
            'global_nodes': sorted_global_indices
        })
    return entries

def seva_extract(elements, global_nodes_map, element_activity, shell_elements=None):
    """
    SEVA algorithm: two-pass surface extraction with volumetric adaptivity.
    elements: list of dicts with 'local_nodes' (8 ints).
    global_nodes_map: dict mapping (element_id, local_node_idx) -> global_node_idx.
    element_activity: list of booleans.
    shell_elements: optional list of shell element data.
    Returns: polygon_vertex_pointer_list.
    """
    # Pass 1: Hashing
    hash_table = []
    for elem_idx, element in enumerate(elements):
        if not element_activity[elem_idx]:
            continue
        hash_table.extend(compute_face_hashes(element['local_nodes'], global_nodes_map, elem_idx))

    # Pass 1: Sorting (Indexed heap sort, O(N log N))
    hash_table.sort(key=lambda x: x['hash_key'])

    # Pass 1: Master Surface List Construction
    master_list = []
    i = 0
    while i < len(hash_table):
        current_hash = hash_table[i]['hash_key']
        group = []
        while i < len(hash_table) and hash_table[i]['hash_key'] == current_hash:
            group.append(hash_table[i])
            i += 1
        master_list.append({
            'hash_value': current_hash,
            'surface_count': len(group),
            'entries': group
        })

    # Pass 2: Polygon List Generation
    polygon_list = []
    for entry in master_list:
        if entry['surface_count'] == 1:
            face_data = entry['entries'][0]
            polygon_list.append({
                'nodes': face_data['global_nodes'],
                'material': elements[face_data['element_id']].get('material_id', 0)
            })

    # Concatenate active shell elements
    if shell_elements:
        polygon_list.extend(shell_elements)

    return polygon_list

def handle_element_removal(master_list, failed_element_id):
    """
    Handles volumetric adaptivity by decrementing surface counts for a failed element.
    master_list: list of master surface entries.
    failed_element_id: int, index of the removed element.
    """
    for entry in master_list:
        for face_data in entry['entries']:
            if face_data['element_id'] == failed_element_id:
                entry['surface_count'] -= 1
                if entry['surface_count'] == 1:
                    # Surface is now exposed interior, will be included in next Pass 2
                    pass
```

## Operating characteristics
*   **Time Complexity:** The dominant operation is the heap sort of the hash table, which is $O(N \log N)$, where $N$ is the number of faces ($6 N_{hex}$) [S1, unofficial].
*   **Memory Complexity:** The hash table requires $6 N_{hex}$ entries [S1, unofficial]. The master surface list is at most $6 N_{hex}$ entries but typically much smaller due to pairing [S1, unofficial].
*   **Strengths:** Efficiently handles dynamic meshes where elements are added or removed (volumetric adaptivity) [S1, unofficial]. It correctly exposes internal surfaces when adjacent elements fail, which is critical for finite element simulations with failure criteria (e.g., DYNA3D) [S1, unofficial].
*   **Limitations:** Relies on a hash function that, while providing dispersion, does not guarantee uniqueness [S1, unofficial]. Collisions are resolved by the sorting and grouping step, but this requires careful implementation to ensure adjacent identical hashes are correctly identified as paired surfaces [S1, unofficial]. The algorithm is specific to hexahedral elements and their canonical numbering scheme [S1, unofficial].
*   **When to use:** Finite element data visualization, particularly for temporal interpolation ("in-betweening") and simulations involving element failure/sliding interfaces (e.g., TWEENER, GRIZ) [S1, unofficial].

## Background
SEVA was developed for visualizing high-resolution, transient, 3-D finite element situations [S1, unofficial]. It was initially implemented in a finite element data visualizer called TWEENER, used for interpolating between discrete states of simulation results for video animation ("in-betweening") [S1, unofficial]. A modified version is used in GRIZ [S1, unofficial]. The algorithm addresses the challenge of identifying paired internal surfaces in the presence of volumetric adaptivity, such as element removal based on maximum strain failure criteria in DYNA3D simulations [S1, unofficial].
