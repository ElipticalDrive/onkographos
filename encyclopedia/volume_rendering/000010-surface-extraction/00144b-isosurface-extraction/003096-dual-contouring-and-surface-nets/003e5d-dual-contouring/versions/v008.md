# Dual Contouring

Also called: Dual Contouring on a Uniform Grid, DualContourMesher, Hermite Dual Contouring, Ju's method, Octree-based Dual Contouring, algo.dualContouring

## Overview
Dual Contouring is a feature-preserving isosurface extraction method that generates a manifold mesh by placing a single vertex inside each grid cell intersected by the surface, rather than on the cell edges [S1][S2, unofficial][S3]. It solves the topological ambiguities and sharp-feature rounding inherent in Marching Cubes by utilizing Hermite data (intersection points and surface normals) to optimize vertex placement via Quadratic Error Function (QEF) minimization [S2, unofficial][S3][S34, unofficial]. Unlike its sibling Surface Nets, which places vertices at the centroid of edge intersections, Dual Contouring positions vertices to best fit the local surface geometry, allowing it to snap to creases and sharp features [S2, S34, unofficial]. It builds on [Dual Contouring and Surface Nets](6319-dual-contouring-and-surface-nets.md) by replacing simple averaging with least-squares optimization.

## How it works
**Inputs and Outputs:**
*   **Input:** A scalar field $f$ (typically a Signed Distance Field, SDF) defined on a regular 3D grid of resolution $N_x \times N_y \times N_z$. The field provides values $f(v)$ at grid vertices $v$. Optionally, an adaptive octree structure may be used to define the domain [S1][S11, unofficial][S28].
*   **Output:** A triangle or quadrilateral mesh consisting of vertices $V$ and indices $I$.

**Data Structures:**
1.  **Grid/Field:** A 3D array storing scalar values. For SDFs, values represent distance to the surface; for density fields, values represent opacity/density.
2.  **Hermite Data:** For each grid edge $e$ connecting vertices $v_a$ and $v_b$ where $f(v_a)$ and $f(v_b)$ have opposite signs, store:
    *   $p_e$: The 3D intersection point on the edge.
    *   $n_e$: The surface normal at $p_e$.
3.  **QEF Accumulators:** For each active cell $c$, store a symmetric $3 \times 3$ matrix $A_c$ (6 unique floats) and a 3D vector $b_c$ (3 floats) [S14, S30, unofficial].
4.  **Edge Map:** A mapping from grid edge coordinates to a unique integer index to facilitate quad generation [S17, S26, unofficial].

**Numbered Steps:**

1.  **Cell Traversal and Sign Classification:**
    Iterate over all grid cells $(x, y, z)$ in the domain. For each cell, evaluate $f$ at its 8 corners. A cell is "active" if there is at least one edge where the signs of the corner values differ [S2, S8, S13, unofficial].

2.  **Hermite Data Extraction:**
    For each active cell, iterate over its 12 edges. For each edge connecting vertices $v_0$ and $v_1$:
    *   Check if $f(v_0) \cdot f(v_1) < 0$. If not, skip.
    *   Compute the intersection parameter $t$:
        $$ t = \frac{0 - f(v_0)}{f(v_1) - f(v_0)} $$
        If $|f(v_1) - f(v_0)| < \epsilon$ (e.g., $10^{-12}$), set $t = 0.5$ [S30, unofficial].
    *   Compute the intersection point $p_e$:
        $$ p_e = (1-t)v_0 + t v_1 $$
    *   Compute the normal $n_e$. If the input is an SDF, $n_e = \nabla f(p_e)$. If only grid values are available, estimate the gradient at $p_e$ using central differences or linear interpolation of vertex gradients [S2, unofficial][S10][S43, unofficial].
    *   Store $(p_e, n_e)$ for this cell.

3.  **QEF Construction:**
    For each active cell $c$, initialize the QEF matrix $A_c$ to a $3 \times 3$ zero matrix and vector $b_c$ to a 3D zero vector [S14, unofficial].
    For each Hermite pair $(p_e, n_e)$ associated with cell $c$:
    *   Let $n = n_e$ and $p = p_e$.
    *   Compute the scalar projection $d = n \cdot p$.
    *   Update the matrix $A_c$ (symmetric):
        $$ A_c += n n^T $$
        Specifically, if $n = [n_x, n_y, n_z]^T$:
        $$ A_c[0,0] += n_x^2, \quad A_c[0,1] += n_x n_y, \quad A_c[0,2] += n_x n_z $$
        $$ A_c[1,1] += n_y^2, \quad A_c[1,2] += n_y n_z $$
        $$ A_c[2,2] += n_z^2 $$
        (Fill symmetric entries $A_c[1,0]=A_c[0,1]$, etc.) [S14, S30, unofficial].
    *   Update the vector $b_c$:
        $$ b_c += n \cdot d $$
        Specifically:
        $$ b_c[0] += n_x d, \quad b_c[1] += n_y d, \quad b_c[2] += n_z d $$ [S14, S30, unofficial].

4.  **QEF Solving (Vertex Placement):**
    Solve the linear system $A_c v_c = b_c$ for the vertex position $v_c$ [S19, S20, unofficial].
    *   **Standard Approach:** Use a linear solver (e.g., Cholesky decomposition, SVD, or conjugate gradient) [S2, S20, unofficial].
    *   **Regularization:** To handle collinear normals (where $A_c$ is singular), add a regularization term $\lambda I$ to $A_c$ and a bias term $\lambda c_{cell}$ to $b_c$, where $c_{cell}$ is the cell center and $\lambda$ is a small constant (e.g., $10^{-6}$) [S34, S35, unofficial]. Alternatively, clamp the solution $v_c$ to remain within the cell bounds [S14, unofficial].
    *   **Iterative Approach (GPU-friendly):** Start $v_c$ at the cell center. Iteratively average the vectors from $v_c$ to each plane defined by $(p_e, n_e)$ and move $v_c$ by $\alpha \approx 0.7$ of the resultant vector for a fixed number of iterations [S7, S43, unofficial].

5.  **Topology Construction (Quad Generation):**
    Iterate over all grid edges $e$ that have a sign change. Let the four cells sharing edge $e$ be $c_1, c_2, c_3, c_4$ [S4][S42, unofficial].
    *   Retrieve the computed vertex $v_i$ for each cell $c_i$.
    *   Create a quadrilateral face connecting $v_1, v_2, v_3, v_4$ in order around the edge [S4][S42, unofficial].
    *   *Note:* In implementations using triangles, the quad is split into two triangles. The winding order must be consistent to ensure a manifold mesh [S17, S42, unofficial].

**Edge Cases and Pitfalls:**
*   **Collinear Normals:** If all intersection normals in a cell are parallel (e.g., a flat face passing through the center), the matrix $A_c$ becomes singular. Regularization (Tikhonov) or clamping to the cell center is required [S1][S34, unofficial].
*   **Non-Manifold Geometry:** Dual Contouring can produce non-manifold vertices if multiple distinct surfaces pass through the same cell (e.g., two intersecting thin sheets). The single-vertex constraint forces them to merge [S1, S6].
*   **Precision:** Linear interpolation for $p_e$ assumes the surface is locally linear. For highly curved surfaces, higher-order interpolation or ray casting may be needed [S1, S3].
*   **Boundary Conditions:** Cells on the grid boundary have fewer neighbors. Quad generation must handle missing adjacent cells gracefully, often by capping the mesh or assuming a boundary condition [G].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of grid cells, assuming constant-time QEF solving. However, QEF solving is a local linear algebra operation (3x3 system), making it fast but more expensive per cell than Marching Cubes [S2, S34, unofficial].
*   **Memory Complexity:** $O(N)$ for storing the grid and Hermite data. The QEF accumulators are stored per active cell.
*   **Performance:** On a $128^3$ grid, Dual Contouring is typically 2-5x slower than Marching Cubes due to the QEF solve and gradient computation [S10][S34, unofficial]. GPU implementations can achieve real-time performance for moderate resolutions [S20, S24, unofficial].
*   **Strengths:** Preserves sharp features (creases, corners) better than Marching Cubes and Surface Nets. Produces regular quad meshes (if desired). Supports adaptive octrees for LOD [S3, S6][S27, unofficial].
*   **Limitations:** Can produce non-manifold geometry. Requires gradient/Hermite data. Sensitive to noise in the scalar field. The single-vertex-per-cell constraint can cause artifacts in complex topologies (e.g., intersecting sheets) [S1, S6].
*   **When to Use:** When sharp feature preservation is critical and the input is a smooth SDF or density field with known gradients. Ideal for retopology and LOD generation [S6, S29].
*   **When Not to Use:** For noisy data without smoothing, or when strict manifold topology is required without post-processing. Avoid if computational resources are extremely limited and feature preservation is not needed.

## Background
Dual Contouring was introduced by Tao Ju, Frank Losasso, Scott Schaefer, and Joe Warren in their 2002 SIGGRAPH paper "Dual Contouring of Hermite Data" [S2, unofficial][S3]. It was developed as an extension of Marching Cubes and Surface Nets, aiming to preserve sharp features that were rounded by previous methods. The method uses Hermite data (positions and normals) to optimize vertex placement via Quadratic Error Function (QEF) minimization [S3, S5]. It has since been extended to adaptive octrees [S11, S27, unofficial], GPU implementations [S20, S24, unofficial], and neural network-based variants [S4, S10]. It is widely used in 3D reconstruction, terrain rendering, and mesh retopology workflows [S6, S29].
