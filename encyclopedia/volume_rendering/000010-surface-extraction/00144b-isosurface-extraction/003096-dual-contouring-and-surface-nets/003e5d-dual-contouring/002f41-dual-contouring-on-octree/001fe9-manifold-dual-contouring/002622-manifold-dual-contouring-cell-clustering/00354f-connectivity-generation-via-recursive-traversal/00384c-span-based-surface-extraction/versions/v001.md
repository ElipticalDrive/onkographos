# Span-based Surface Extraction

Also called: Connected Surface Construction

## Overview
Span-based Surface Extraction is a method for extracting connected surface topology from voxelized particle data by identifying depth intervals (spans) in voxel columns and linking overlapping spans in neighboring columns [S1]. It builds on [Connectivity Generation via Recursive Traversal](7454-connectivity-generation-via-recursive-traversal.md) by converting the minimal edge connectivity into a continuous surface mesh representation suitable for filtering and rendering [S1]. Unlike dual contouring methods that rely on quadric error metrics and vertex optimization, this approach operates directly on compressed depth lists, making it highly memory-efficient for large-scale particle datasets [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A compressed list of depth values marking entry and exit points of the volume along each voxel column. These depths define "spans" (intervals between successive entry and exit depths) [S1].
*   **Output:** A set of surface connection links stored in parallel to the surface depth values, enabling traversal of the continuous surface [S1].

**Data Structures:**
*   **Span:** Defined by an entry depth ($d_{in}$) and an exit depth ($d_{out}$) within a specific voxel column.
*   **Link Storage:** For each pixel (voxel column), surface connection links to its four direct neighbors are packed into one 32-bit machine word [S1].
*   **Special Link Values:** Two special integer values are reserved to indicate links to subsequent or preceding entries/exits within the same column (handling bubbles or boundary cases) [S1].

**Algorithm Steps:**
1.  **Identify Spans:** Iterate through each voxel column to identify all spans formed by pairs of successive entry and exit depths [S1].
2.  **Find Neighbor Spans:** For each `current_span` in a column, identify relevant overlapping spans in the four direct neighboring columns [S1].
    *   `front_nb`: The first neighbor span where the neighbor's exit depth is greater than or equal to the current span's entry depth ($d_{nb, out} \ge d_{curr, in}$) [S1].
    *   `back_nb`: The last neighbor span where the neighbor's entry depth is less than or equal to the current span's exit depth ($d_{nb, in} \le d_{curr, out}$) [S1].
3.  **Link Entries (Front Connection):** Check if `front_nb` overlaps with `current_span` ($d_{nb, in} \le d_{curr, out}$) [S1].
    *   If `front_nb` is not connected to the previous span in the neighbor column ($d_{nb, in} > d_{prev, out}$), link `current_span.entry` to `front_nb.entry` [S1].
    *   Otherwise (the neighbor span is the same as the previous one, forming a bubble wall), link `current_span.entry` to `previous_span.exit` of the neighbor column [S1].
4.  **Link Exits (Back Connection):** Check if `back_nb` is not connected to the next span in the neighbor column ($d_{next, in} > d_{nb, out}$) [S1].
    *   If so, link `current_span.exit` to `back_nb.exit` [S1].
    *   Otherwise (the neighbor recurs in the next span, forming a bubble wall), link `current_span.exit` to `next_span.entry` of the neighbor column [S1].
5.  **Handle Non-Overlapping Cases:** If there is no overlapping neighbor span, link the entry and exit depths of the current span to each other [S1].
6.  **Handle Internal Bubbles:** Inner exit depths are connected to the subsequent entry depth in their own column, and inner entry depths are connected to the preceding exit depth [S1]. This accounts for bubbles inside the volume [S1].

**Pseudocode:**
```python
def link_entries(current_span, previous_span, front_nb):
    """
    Links entry points based on neighbor overlap and previous connection state.
    """
    # Check if neighbor overlaps with current span
    if front_nb.entry <= current_span.exit:
        # If neighbor not connected to previous span, link entries
        if front_nb.entry > previous_span.exit:
            link(current_span.entry, front_nb.entry)
        # Else: same neighbor as last time, forming a bubble wall
        else:
            link(current_span.entry, previous_span.exit)

def link_exits(current_span, next_span, back_nb):
    """
    Links exit points based on neighbor overlap and next connection state.
    """
    # If neighbor not connected to next span, link exits
    if next_span.entry > back_nb.exit:
        link(current_span.exit, back_nb.exit)
    # Else: neighbor recurs next time, forming a bubble wall
    else:
        link(current_span.exit, next_span.entry)

def process_span(current_span, previous_span, next_span, neighbors):
    """
    Main processing step for a single span in a voxel column.
    neighbors: dict mapping direction (e.g., 'N', 'S', 'E', 'W') to list of spans in that column.
    """
    # Find front neighbor: first span where exit >= current entry
    front_nb = None
    for nb_span in neighbors['N']: # Example direction
        if nb_span.exit >= current_span.entry:
            front_nb = nb_span
            break
    
    # Find back neighbor: last span where entry <= current exit
    back_nb = None
    for nb_span in neighbors['N']: # Example direction
        if nb_span.entry <= current_span.exit:
            back_nb = nb_span
    
    # Handle linking logic
    if front_nb is not None:
        link_entries(current_span, previous_span, front_nb)
    
    if back_nb is not None:
        # Note: next_span must be available from the iteration context
        link_exits(current_span, next_span, back_nb)
    else:
        # No overlapping neighbor span: link entry and exit to each other
        link(current_span.entry, current_span.exit)

# Global iteration structure
for column in columns:
    spans = get_spans(column)
    for i, current_span in enumerate(spans):
        previous_span = spans[i-1] if i > 0 else None
        next_span = spans[i+1] if i < len(spans)-1 else None
        
        # Get neighbor spans for the four direct neighbors
        neighbor_spans = get_neighbor_spans(column, i)
        
        # Process each neighbor direction
        for direction in ['N', 'S', 'E', 'W']:
            if neighbor_spans[direction]:
                process_span(current_span, previous_span, next_span, {direction: neighbor_spans[direction]})
```

**Parameters and Edge Cases:**
*   **Precision:** The method relies on exact depth comparisons. Precision issues may arise if depth values are not consistently quantized [S1].
*   **Bubbles:** The algorithm explicitly handles internal bubbles by linking inner exit to subsequent entry and inner entry to preceding exit within the same column [S1].
*   **Boundary Spans:** If a span has no overlapping neighbor, entry and exit are linked to each other, effectively closing the surface at boundaries [S1].
*   **State Change Detection:** Ray casting or state changes between inside and outside can be detected by checking the LSB of the layer index when entering a new column [S1].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of spans and neighbors. The linking process requires a single pass over the spans with constant-time neighbor lookups [S1].
*   **Memory Complexity:** Highly memory-efficient. Links are packed into 32-bit words per pixel, stored in parallel with depth values [S1]. No additional large data structures are required [S1].
*   **Strengths:** Suitable for large-scale particle data due to low memory footprint. Enables easy application of smoothing filters (e.g., blurring, curvature flow) via surface traversal [S1].
*   **Limitations:** Relies on compressed depth lists; performance depends on the efficiency of the preceding voxelization and compression steps [S1].

## Background
The method was introduced in the context of memory-efficient on-the-fly voxelization of particle data [S1]. It addresses the challenge of extracting connected surfaces from compressed voxel data without storing explicit mesh structures, enabling efficient filtering and rendering of complex particle systems [S1].
