# Dual Contouring with Octree

Also called: ContourBuilder, Dual Contouring Mesh Generation, Manifold Dual Contouring with Octree, Manifold dual contouring based octree method, Octree-based Dual Contouring, Octree-based Isosurface Extraction

## Overview
Dual Contouring with Octree is a surface extraction method that generates a mesh from an octree of nodes, where each node contains a Quadratic Error Function (QEF) solution and a corner encoding [S1, S2, unofficial]. It solves the problem of extracting isosurfaces from scalar fields by using a hierarchical grid structure to represent the field, allowing for adaptive resolution and mesh simplification based on error thresholds [S2, unofficial]. It sets itself apart from uniform grid dual contouring by reducing polygon count through adaptive subdivision, and from [Topologically Accurate Dual Isosurfacing Using Ray Intersection](800-topologically-accurate-dual-isosurfacing-using-ray-intersect.md) by relying on QEF minimization at cell boundaries rather than ray intersection for topological correctness [S2, unofficial].

## How it works
**Inputs:** A bounding box (Cuboid), a scalar density function (implicit function), its gradient function, an isovalue, and a refinement splitter (e.g., uniform or adaptive) [S1, unofficial][S3].
**Outputs:** A list of meshes (vertices and indices) representing the isosurface [S1, unofficial].

**Data Structures:**
*   `Octree<T>`:
    *   `bounds`: `Cuboid` (min/max vectors).
    *   `data`: `T` (e.g., `NodeData`).
    *   `children`: Array of 8 `Octree<T>` pointers, `null` if leaf [S1, unofficial].
*   `NodeData`:
    *   `qef`: `QEF` object (stores matrix/vector for least-squares system).
    *   `vertex`: `Vector3` (3D float position, solution to QEF).
    *   `cornerEncoding`: `int` (bitmask of crossing corners).
    *   `index`: `int` (mesh vertex index, initialized to -1).
    *   `size`: `float` (diagonal length of node bounds) [S1, unofficial].
*   `Cuboid`:
    *   `min`, `max`: `Vector3`.
    *   `size`: `max - min` [S1, unofficial].

**Parameters:**
*   `MAX_VERTS_PER_MESH`: Integer constant, typically 30000 [S1, unofficial].
*   `threshold`: Float for simplification error threshold. Typical values not specified in code, but paper mentions 1e0 for dragon example [S2, unofficial].
*   `isovalue`: Scalar value for extraction [S3].

**Steps:**

1.  **Build Octree:**
    *   Initialize root `Octree<NodeData>` with bounds [S1, unofficial].
    *   Recursively split nodes if depth < `maxOctreeDepth` or if refinement criteria met [S1, unofficial][S3].
    *   For each child, combine QEF matrices from valid children into parent's `grid.allQef` [S2, unofficial].
    *   At leaf nodes (depth == 1 or terminal), sample QEF from scalar field, mark as leaf, and solve for vertex position [S2, unofficial].
    *   *Refinement:* Use `Refine_one_eighth` (uniform) or `Refine_around_isovalue` (adaptive) splitters [S3].

2.  **Simplify Tree (Optional):**
    *   Traverse tree recursively [S2, unofficial].
    *   Check if node is `clusterable`: all children are clusterable AND faces between adjacent children allow cluster merging [S2, unofficial].
    *   If clusterable and approximation error < `threshold`, remove all children (set to `nullptr`) and mark node as leaf [S2, unofficial].

3.  **Contour Cells (Recursive Traversal):**
    *   Call `ContourCellProc(root)` [S1, unofficial].
    *   If node is leaf, return [S1, unofficial].
    *   Recursively call `ContourCellProc` on all 8 children [S1, unofficial].
    *   For each of the 12 edges of the cell:
        *   Get two adjacent face nodes using `cellProcFaceMask[i]` [S1, unofficial].
        *   Call `ContourFaceProc` on these face nodes [S1, unofficial].
    *   For each of the 6 faces of the cell:
        *   Get 4 adjacent edge nodes using `cellProcEdgeMask[i]` [S1, unofficial].
        *   Call `ContourEdgeProc` on these edge nodes [S1, unofficial].

4.  **Contour Faces:**
    *   `ContourFaceProc(nodes, direction)`:
        *   If `nodes[0]` or `nodes[1]` is `null`, return [S1, unofficial].
        *   If both nodes are leaves, return [S1, unofficial].
        *   For each of the 4 adjacent faces:
            *   Get 2 face nodes using `faceProcFaceMask` [S1, unofficial].
            *   Recursively call `ContourFaceProc` [S1, unofficial].
        *   For each of the 4 adjacent edges:
            *   Get 4 edge nodes using `faceProcEdgeMask` and `orders` table [S1, unofficial].
            *   Recursively call `ContourEdgeProc` [S1, unofficial].

5.  **Contour Edges:**
    *   `ContourEdgeProc(nodes, direction)`:
        *   If any node is `null`, return [S1, unofficial].
        *   If all 4 nodes are leaves, call `ContourProcessEdge` [S1, unofficial].
        *   Otherwise:
            *   For each of the 2 adjacent edges:
                *   Get 4 edge nodes using `edgeProcEdgeMask` [S1, unofficial].
                *   Recursively call `ContourEdgeProc` [S1, unofficial].

6.  **Process Edge (Vertex & Triangle Generation):**
    *   `ContourProcessEdge(nodes, direction)`:
        *   Get `processEdgeMask` and `edgevmap` tables [S1, unofficial].
        *   If `vertices.Count + 4 > MAX_VERTS_PER_MESH`, call `CreateMesh` to flush buffers [S1, unofficial].
        *   Initialize `ptrs` array to `{-1, -1, -1, -1}`, `signChange` array to `{false, false, false, false}` [S1, unofficial].
        *   Initialize `minSize` to `Infinity`, `minIndex` to `0`, `flip` to `false` [S1, unofficial].
        *   Loop `i` from 0 to 3:
            *   Get bounds and data for `nodes[i]` [S1, unofficial].
            *   Get edge index from `processEdgeMask[direction, i]` and encoding from `data.cornerEncoding` [S1, unofficial].
            *   Check sign change:
                *   `c0Sign = ((encoding >> edgevmap[edge, 0]) & 1) > 0`
                *   `c1Sign = ((encoding >> edgevmap[edge, 1]) & 1) > 0`
                *   `signChange[i] = c0Sign != c1Sign` [S1, unofficial].
            *   If `size < minSize`, update `minSize`, `minIndex`, and `flip = c0Sign` [S1, unofficial].
            *   If `data.index == -1`, set `data.index = vertices.Count`, add `data.vertex` to `vertices` [S1, unofficial].
            *   Set `ptrs[i] = data.index` [S1, unofficial].
        *   **Triangle Generation:**
            *   If `signChange[minIndex]` is `true`:
                *   Add triangles to indices [S1, unofficial].
            *   If `flip` is `true`:
                *   Add triangles `(ptrs[0], ptrs[1], ptrs[3])` and `(ptrs[0], ptrs[3], ptrs[2])` [S1, unofficial].
            *   Else:
                *   Add triangles `(ptrs[0], ptrs[3], ptrs[1])` and `(ptrs[0], ptrs[2], ptrs[3])` [S1, unofficial].

7.  **Extract Mesh:**
    *   Traverse tree. For leaf nodes, add their grid vertices to the mesh [S2, unofficial].
    *   Use an unordered set to index vertices and avoid duplicates [S2, unofficial].

**Pseudocode:**

```python
def run_dual_contour_octree(bounds, scalar_func, gradient_func, isovalue, max_depth):
    root = Octree(bounds)
    build_octree(root, scalar_func, gradient_func, isovalue, max_depth)
    simplify_tree(root, threshold=1e0)
    meshes = build_mesh(root)
    return meshes

def build_octree(node, scalar_func, gradient_func, isovalue, max_depth):
    if node.is_leaf():
        return
    
    # Subdivide if depth < max_depth or refinement criteria met
    if node.depth < max_depth:
        node.sub_divide()
        
        for child in node.children:
            if child is not None:
                build_octree(child, scalar_func, gradient_func, isovalue, max_depth)
                
        # Combine QEFs from children into parent if needed
        # (Implementation detail: aggregate QEF matrices)
        
    else:
        # Leaf processing
        if node.depth == 1:
            # Check if grid is signed; if not, delete node
            if not is_signed(node.bounds):
                node.delete_children_array()
                return
            
            # Sample QEF from scalar field
            qef = sample_qef(node.bounds, scalar_func, gradient_func, isovalue)
            node.data.qef = qef
            node.data.vertex = solve_qef(qef)
            node.data.corner_encoding = compute_corner_encoding(node.bounds, scalar_func, isovalue)
            node.data.index = -1
            node.data.size = node.bounds.diagonal_length()
            node.delete_children_array() # Mark as leaf

def simplify_tree(node, threshold):
    if node.is_leaf():
        return
    
    # Check clusterability
    all_children_clusterable = all(child.is_clusterable(threshold) for child in node.children if child is not None)
    faces_allow_merge = check_face_cluster_merge(node)
    
    if all_children_clusterable and faces_allow_merge:
        # Collapse children
        node.delete_children_array()
        # Re-solve QEF for the collapsed node if necessary
        node.data.vertex = solve_qef(node.data.qef)
    else:
        for child in node.children:
            if child is not None:
                simplify_tree(child, threshold)

def build_mesh(root):
    vertices = []
    indices = []
    mesh_list = []
    
    # Recursive contouring
    contour_cell_proc(root, vertices, indices)
    
    # Flush remaining vertices/indices if needed
    if vertices:
        mesh_list.append(create_mesh(vertices, indices))
        
    return mesh_list

def contour_cell_proc(node, vertices, indices):
    if node.is_leaf():
        return
    
    # Recurse children
    for child in node.children:
        if child is not None:
            contour_cell_proc(child, vertices, indices)
            
    # Process 12 edges
    for i in range(12):
        face_nodes = get_face_nodes(node, i, cell_proc_face_mask)
        contour_face_proc(face_nodes, i, vertices, indices)
        
    # Process 6 faces
    for i in range(6):
        edge_nodes = get_edge_nodes(node, i, cell_proc_edge_mask)
        contour_edge_proc(edge_nodes, i, vertices, indices)

def contour_face_proc(nodes, direction, vertices, indices):
    if nodes[0] is None or nodes[1] is None:
        return
    if nodes[0].is_leaf() and nodes[1].is_leaf():
        return
        
    # Subdivide face into 4 child faces
    for i in range(4):
        child_face_nodes = get_child_face_nodes(nodes, i, face_proc_face_mask)
        contour_face_proc(child_face_nodes, direction, vertices, indices)
        
    # Process 4 adjacent edges
    for i in range(4):
        child_edge_nodes = get_child_edge_nodes(nodes, i, face_proc_edge_mask)
        contour_edge_proc(child_edge_nodes, direction, vertices, indices)

def contour_edge_proc(nodes, direction, vertices, indices):
    if any(n is None for n in nodes):
        return
    if all(n.is_leaf() for n in nodes):
        contour_process_edge(nodes, direction, vertices, indices)
    else:
        # Subdivide edge into 2 child edges
        for i in range(2):
            child_edge_nodes = get_child_edge_nodes(nodes, i, edge_proc_edge_mask)
            contour_edge_proc(child_edge_nodes, direction, vertices, indices)

def contour_process_edge(nodes, direction, vertices, indices):
    if len(vertices) + 4 > MAX_VERTS_PER_MESH:
        flush_mesh(vertices, indices)
        
    ptrs = [-1, -1, -1, -1]
    sign_change = [False, False, False, False]
    min_size = float('inf')
    min_index = 0
    flip = False
    
    for i in range(4):
        node = nodes[i]
        encoding = node.data.corner_encoding
        size = node.data.size
        
        edge_idx = process_edge_mask[direction, i]
        edge_vmap = edge_vmap_table[edge_idx]
        
        c0_sign = (encoding >> edge_vmap[0]) & 1
        c1_sign = (encoding >> edge_vmap[1]) & 1
        sign_change[i] = c0_sign != c1_sign
        
        if size < min_size:
            min_size = size
            min_index = i
            flip = c0_sign
            
        if node.data.index == -1:
            node.data.index = len(vertices)
            vertices.append(node.data.vertex)
            
        ptrs[i] = node.data.index
        
    # Generate triangles
    if sign_change[min_index]:
        if flip:
            indices.extend([ptrs[0], ptrs[1], ptrs[3], ptrs[0], ptrs[3], ptrs[2]])
        else:
            indices.extend([ptrs[0], ptrs[3], ptrs[1], ptrs[0], ptrs[2], ptrs[3]])

def flush_mesh(vertices, indices):
    mesh_list.append(create_mesh(vertices, indices))
    vertices.clear()
    indices.clear()
```

## Subtopics

### [Manifold Dual Contouring](2138-manifold-dual-contouring.md)
Manifold Dual Contouring is a contouring and simplification method that constructs a manifold surface by integrating a topology constraint into an adaptive vertex clustering algorithm. It solves the problem of generating simplified, topologically correct iso-surfaces from Hermite data while allowing independent simplification of multiple contour components within an octree cell. Unlike Extended Dual Contouring, it places no restriction on the number of contour intersections on each octree cell edge, allowing the simplification of multiple layers of thin geometry. Builds on [Dual Contouring with Octree](1271-dual-contouring-with-octree.md).

### [Adaptive Contouring via Octree Vertex Clustering](2142-adaptive-contouring-via-octree-vertex-clustering.md)
Adaptive Contouring via Octree Vertex Clustering is a surface extraction method that constructs multi-resolution iso-surfaces by clustering vertices of child cells in an octree into a single vertex in a topologically safe manner. It allows an arbitrary number of vertices per cell, significantly reducing polygon count in flat regions compared to methods restricted to one vertex per cell. It sets itself apart from [Dual Contouring with Octree](1271-dual-contouring-with-octree.md) by permitting multiple vertices per cell through a clustering phase, and from [Manifold Dual Contouring](2138-manifold-dual-contouring.md) by its specific vertex-tree-based clustering mechanism which requires additional constraints to guarantee manifold topology.

### [Adaptive Dual Contouring](3664-adaptive-dual-contouring.md)
Adaptive Dual Contouring extracts a manifold mesh from a scalar density function by building an adaptive octree, solving Quadratic Error Functions (QEF) at nodes to determine vertex positions, and generating a mesh from the resulting constrained vertices. It solves a Quadratic Error Function (QEF) at each node to determine vertex positions, then recursively collapses internal octree nodes into 'pseudo-leaf' nodes if the resulting QEF error is below a threshold, preserving sharp features defined by the sign configuration of child nodes. Unlike standard Dual Contouring which places one vertex per leaf voxel, this method reduces vertex count by merging internal nodes, producing a coarser but topologically consistent mesh suitable for real-time rendering or further processing.

### [Kdtree-based Iso-surface Extraction](3816-kdtree-based-iso-surface-extraction.md)
Kdtree-based Iso-surface Extraction is a method for extracting iso-surfaces from scalar fields using a hierarchical K-d tree structure built upon an octree, utilizing Quadratic Error Function (QEF) for vertex optimization and clusterability checks for simplification. It differs from its sibling [Adaptive Dual Contouring](3664-adaptive-dual-contouring.md) by explicitly constructing a K-d tree to guide the traversal and subdivision, whereas the sibling relies on adaptive octree refinement without the explicit K-d tree hierarchy for mesh generation. It builds on [Dual Contouring with Octree](1271-dual-contouring-with-octree.md) by replacing the standard octree extraction path with a K-d tree variant when the 'kd' mode is active.

### Seam Generation for Adjacent Chunks
Generates mesh vertices and indices along the boundary between two adjacent octree chunks to eliminate seams common in dual contouring implementations [S4, unofficial].
*   **Step:** Initialize a `borderChildren` array of 8 pointers to `nullptr`, and an `idxs` array mapping chunk 0 to n1 and chunk 1 to n2 [S4, unofficial]. Iterate over both chunks (j=0,1). For each, retrieve its children array. If children are `null`, skip [S4, unofficial]. Loop i from 0 to 3. Fetch coordinates and edge index from `edgeIndexLookup[dir][j][i]`. Compute octree index, retrieve the child, store it in `borderChildren[edgeIdx]`, and generate vertex indices for that child [S4, unofficial]. Dispatch to the appropriate `FaceProc` function based on `dir`, passing the two octrees in the correct order to handle winding/normal consistency [S4, unofficial].
*   **Layout:** `edgeIndexLookup` is a 4D array of ints with shape `[6][2][4][4]`. The 6 dimensions correspond to directions (x+, x-, y+, y-, z+, z-). The 2 dimensions correspond to chunk index (old/new). The 4 dimensions iterate over border points. The innermost 4 values are `{x, y, z, edgeIdx}` used to index into the octree children array [S4, unofficial].

### Intersection-Free Dual Contouring
An intersection-free variant of dual contouring that avoids self-intersecting triangles by using non-intersecting tests and tessellation, as opposed to the original algorithm which may produce self-intersections [S5, unofficial].
*   **Step:** If the 'nointer' flag is present, call `mytree->genContourNoInter2(argv[2])` to generate the contour using the intersection-free algorithm [S5, unofficial]. If the 'nointer' flag is not present, call `mytree->genContour(argv[2])` to generate the contour using the original algorithm [S5, unofficial].
*   **Parameter:** `simplify_threshold`: A float parameter controlling the simplification threshold for the octree construction. Default value is -1 (not set) [S5, unofficial].
*   **History:** Introduced by Tao Ju in 2006, referenced as [Ju et al. 2006] for the intersection-free algorithm, while the original algorithm is referenced as [Ju et al. 2002] [S5, unofficial].

## Operating characteristics
*   **Time Complexity:** Depends on octree depth and refinement. Building the octree is $O(N)$ where $N$ is the number of leaf nodes. Contouring is proportional to the number of edges and faces processed.
*   **Memory Complexity:** Proportional to the number of octree nodes. Each node stores QEF data and vertex info.
*   **Measured Performance:** For the Stanford Dragon model, the octree method produced 35,836 triangles, compared to 309,962 for a uniform grid [S2, unofficial]. A k-d tree variant produced 22,608 triangles, showing the octree method produces more triangles than k-d tree but significantly fewer than uniform grid [S2, unofficial].
*   **Scaling:** Scales well with adaptive refinement; only subdivides regions near the isosurface.
*   **Strengths:** Adaptive resolution, manifold output (with proper QEF solving), handles complex topology.
*   **Limitations:** Can produce self-intersections if not using intersection-free variant [S5, unofficial]. Seam artifacts can occur between adjacent chunks if not handled [S4, unofficial].
*   **When to use:** When adaptive resolution is needed, or when the scalar field is expensive to evaluate and can be approximated coarsely in flat regions.
*   **When not to use:** When maximum triangle efficiency is required (k-d tree may be better) [S2, unofficial], or when strict non-intersection is required without additional checks [S5, unofficial].

## Background
Dual Contouring with Octree is based on the work of Schaefer et al. (Manifold dual contouring) [S2, unofficial]. The original dual contouring algorithm was introduced by Ju et al. in 2002 [S5, unofficial]. The intersection-free variant was introduced by Tao Ju in 2006 [S5, unofficial]. The method is used in various graphics applications for isosurface extraction, particularly in CSG modeling and medical imaging [S2, unofficial].
