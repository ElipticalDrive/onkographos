# Face Contouring for Dual Contouring

Also called: ContourFaceProc

## Overview
Face Contouring is the recursive procedure responsible for generating triangle indices by processing the faces of an octree structure during the mesh generation phase of Manifold Dual Contouring. It operates on pairs of octree nodes to determine how surface geometry crosses the boundary between them, recursing into children for internal nodes and invoking Edge Contouring for leaf nodes. It is distinct from Edge Contouring, which handles the 1D edges of the octree cells.

## How it works
**Inputs and Outputs:**
- `faceNodes`: An array of two `OctreeNode*` pointers representing the two octree nodes sharing the face being processed.
- `dir`: The face direction index (0, 1, or 2), corresponding to the axis perpendicular to the face.
- `indexBuffer`: A reference to the `IndexBuffer` (typically `std::vector<int>`) where generated triangle indices are appended.

**Data Structures:**
The method relies on two precomputed lookup tables defined in the source implementation [S1, unofficial]:

1.  `faceProcFaceMask[3][4][3]`:
    -   Dimensions: `[dir][face_index][component]`.
    -   `dir`: 0, 1, or 2.
    -   `face_index`: 0 to 3 (four faces per octree node).
    -   `component 0`: Child index for the first node (`faceNodes[0]`).
    -   `component 1`: Child index for the second node (`faceNodes[1]`).
    -   `component 2`: The sub-direction passed to the recursive `ContourFaceProc` call.

2.  `faceProcEdgeMask[3][4][6]`:
    -   Dimensions: `[dir][face_index][component]`.
    -   `component 0`: Order index (0 or 1), used to select the permutation array `orders`.
    -   `components 1-4`: Child indices for the four edge nodes involved in the edge contouring step.
    -   `component 5`: The sub-direction passed to `ContourEdgeProc`.

3.  `orders[2][4]`:
    -   A static array defining node access order: `{{0, 0, 1, 1}, {0, 1, 0, 1}}`.

**Algorithm Steps:**
1.  **Base Case:** If either `faceNodes[0]` or `faceNodes[1]` is `nullptr`, return immediately [S1, unofficial].
2.  **Internal Node Handling:** If either node is of type `Node_Internal`, iterate `i` from 0 to 3 (representing the four faces of the octree node):
    a.  Extract child indices: `c[0] = faceProcFaceMask[dir][i][0]` and `c[1] = faceProcFaceMask[dir][i][1]` [S1, unofficial].
    b.  Resolve node pointers: For `j` in {0, 1}, if `faceNodes[j]` is not internal, use `faceNodes[j]`; otherwise, use `faceNodes[j]->children[c[j]]` [S1, unofficial].
    c.  Recurse: Call `ContourFaceProc` with the resolved nodes, the sub-direction `faceProcFaceMask[dir][i][2]`, and the `indexBuffer` [S1, unofficial].
3.  **Edge Processing:** Define the order array `orders[2][4] = {{0,0,1,1}, {0,1,0,1}}` [S1, unofficial]. Iterate `i` from 0 to 3:
    a.  Get order index: `orderIdx = faceProcEdgeMask[dir][i][0]` [S1, unofficial].
    b.  Get child indices: `c[0..3]` from `faceProcEdgeMask[dir][i][1..4]` [S1, unofficial].
    c.  Get order pointer: `order = orders[orderIdx]` [S1, unofficial].
    d.  Resolve edge nodes: For `j` from 0 to 3:
        i.  If `faceNodes[order[j]]` is a leaf or pseudo-node, use it.
        ii. Else, use `faceNodes[order[j]]->children[c[j]]` [S1, unofficial].
    e.  Recurse: Call `ContourEdgeProc` with the four resolved edge nodes, the sub-direction `faceProcEdgeMask[dir][i][5]`, and the `indexBuffer` [S1, unofficial].

**Pseudocode:**
```python
def ContourFaceProc(faceNodes: list[OctreeNode], dir: int, indexBuffer: list[int]):
    # Base case: null check
    if faceNodes[0] is None or faceNodes[1] is None:
        return

    # Internal case: recurse into children faces
    if faceNodes[0].type == Node_Internal or faceNodes[1].type == Node_Internal:
        for i in range(4):
            # Extract child indices from mask
            c0 = faceProcFaceMask[dir][i][0]
            c1 = faceProcFaceMask[dir][i][1]
            sub_dir = faceProcFaceMask[dir][i][2]
            
            # Resolve node pointers
            node0 = faceNodes[0] if faceNodes[0].type != Node_Internal else faceNodes[0].children[c0]
            node1 = faceNodes[1] if faceNodes[1].type != Node_Internal else faceNodes[1].children[c1]
            
            # Recurse
            ContourFaceProc([node0, node1], sub_dir, indexBuffer)

    # Edge processing
    orders = [[0, 0, 1, 1], [0, 1, 0, 1]]
    
    for i in range(4):
        order_idx = faceProcEdgeMask[dir][i][0]
        child_indices = faceProcEdgeMask[dir][i][1:5]
        sub_dir = faceProcEdgeMask[dir][i][5]
        order = orders[order_idx]
        
        edge_nodes = [None] * 4
        for j in range(4):
            node_idx = order[j]
            child_idx = child_indices[j]
            
            if faceNodes[node_idx].type != Node_Internal:
                edge_nodes[j] = faceNodes[node_idx]
            else:
                edge_nodes[j] = faceNodes[node_idx].children[child_idx]
        
        # Recurse to edge contouring
        ContourEdgeProc(edge_nodes, sub_dir, indexBuffer)
```

**Parameters and Edge Cases:**
-   `faceProcFaceMask` and `faceProcEdgeMask` are static lookup tables. Their exact values are implementation-specific and not defined in the abstract notes, but their structure is fixed as described [S1, unofficial].
-   Pitfall: Accessing `children` on a non-internal node will cause a crash. The type check `Node_Internal` is mandatory before dereferencing `children` [S1, unofficial].
-   Pitfall: The `order` array indices must map correctly to the `faceNodes` array indices (0 or 1) to ensure the correct geometric relationship between the two nodes is maintained during edge resolution [S1, unofficial].

## Operating characteristics
-   **Time Complexity:** Proportional to the number of faces in the octree that intersect the isosurface. In the worst case (highly detailed surface), it visits every leaf face.
-   **Memory Complexity:** $O(1)$ auxiliary space per recursive call, excluding the call stack. The stack depth is bounded by the octree depth.
-   **Strengths:** Efficiently handles the octree hierarchy by skipping internal nodes that do not intersect the surface, only recursing where necessary.
-   **Limitations:** Requires the precomputed `faceProcFaceMask` and `faceProcEdgeMask` tables, which are specific to the manifold dual contouring topology rules.

## Background
This method is part of the Manifold Dual Contouring implementation by Tao Ju, as reproduced in the `DualContouringSample` repository. It is a critical component of the index generation phase, bridging the gap between vertex generation (QEF solving) and final triangle assembly.
