# Mass Point Centering for Dual Contouring

Also called: Centered QEF Solver, Centroid-Shifted Least Squares

## Overview
Mass Point Centering is a numerical stabilization technique for solving the Quadratic Error Function (QEF) in Dual Contouring. It addresses the ill-conditioning that arises when the local surface geometry is far from the coordinate origin by shifting the linear system to be centered around the centroid of the sample points. Unlike [Brute-Force QEF Solver](4403-brute-force-qef-solver.md) which may suffer from precision loss with large coordinates, this method ensures the solution space is well-conditioned without altering the geometric accuracy of the resulting dual vertex.

## How it works
The method transforms the standard least-squares problem $A^T A x = A^T b$ into a centered system. Let $P = \{p_1, \dots, p_n\}$ be the set of edge intersection points and $N = \{n_1, \dots, n_n\}$ be the corresponding surface normals. The QEF minimizes $\sum (n_i \cdot (x - p_i))^2$.

**Inputs:**
- `data.ata`: $3 \times 3$ symmetric matrix $A^T A$, stored as 6 floats $(m_{00}, m_{01}, m_{02}, m_{11}, m_{12}, m_{22})$ [S1, unofficial].
- `data.atb`: $3 \times 1$ vector $A^T b$, stored as 3 floats $(atb_x, atb_y, atb_z)$ [S1, unofficial].
- `data.numPoints`: Integer count of samples $n$.
- `data.massPoint`: Temporary storage for the centroid [S1, unofficial].

**Outputs:**
- `x`: The $3 \times 1$ solution vector (dual vertex position) [S1, unofficial].
- `hasSolution`: Boolean indicating if the solver converged [S1, unofficial].

**Data Structures:**
The symmetric matrix $A^T A$ is stored in a compact `SMat3` structure to save memory and improve cache locality:
```python
class SMat3:
    m00: float
    m01: float
    m02: float
    m11: float
    m12: float
    m22: float
```
The vector $A^T b$ is a standard 3D vector.

**Steps:**
1. **Validate Input:** If `data.numPoints` is 0, raise an `ArgumentException` [S1, unofficial].
2. **Compute Centroid:** Calculate the mass point (centroid) $C$ as the average of the input points. Note: The source code implies `data.massPoint` is pre-computed or provided, but the logic requires $C = \frac{1}{n} \sum p_i$. In the provided implementation, `massPoint` is loaded and scaled by $1.0/n$ [S1, unofficial].
3. **Setup Matrices:** Load $A^T A$ into `ata` and $A^T b$ into `atb` [S1, unofficial].
4. **Adjust Right-Hand Side:** Compute the correction term $t = (A^T A) C$. Subtract this from $A^T b$:
   $$ b' = b - (A^T A) C $$
   In code: `atb = atb - vmul_symmetric(ata, massPoint)` [S1, unofficial].
5. **Solve System:** Solve the shifted linear system $A^T A x' = b'$ for $x'$ using a symmetric solver (e.g., SVD) [S1, unofficial].
6. **Shift Solution:** Recover the true solution $x$ by adding the centroid back:
   $$ x = x' + C $$
   In code: `x = x + massPoint` [S1, unofficial].
7. **Reset State:** Reset `atb` to its original state if required by the caller's expectation of non-destructive reads, and return the result [S1, unofficial].

**Pseudocode:**
```python
def solve_mass_point_centered(ata: SMat3, atb: Vec3, num_points: int, centroid: Vec3) -> Vec3:
    if num_points == 0:
        raise ArgumentException("No points provided")
    
    # ata is A^T A, atb is A^T b
    # centroid is C = mean(points)
    
    # Compute t = (A^T A) * C
    t = vmul_symmetric(ata, centroid)
    
    # Adjust b' = b - t
    atb_adjusted = atb - t
    
    # Solve (A^T A) x' = b'
    # Using a symmetric solver like SVD
    x_prime = solve_symmetric(ata, atb_adjusted)
    
    # Shift back to original coordinate space
    x = x_prime + centroid
    
    return x
```

**Parameters:**
- `svd_tol`: Tolerance for SVD singularity detection. Not given in the sources.
- `svd_sweeps`: Number of sweeps for iterative SVD. Not given in the sources.
- `pinv_tol`: Tolerance for pseudo-inverse calculation. Not given in the sources.

**Edge Cases:**
- **Zero Points:** The method explicitly checks for `numPoints == 0` and throws an exception [S1, unofficial].
- **Precision:** Centering prevents loss of significance when coordinates are large, as the system is solved around the origin of the local sample cluster [S1, unofficial].

## Subtopics

## Operating characteristics
- **Time Complexity:** Dominated by the symmetric linear solver (e.g., SVD), typically $O(1)$ for fixed $3 \times 3$ systems, but with a higher constant factor than direct inversion due to stability checks.
- **Memory Complexity:** $O(1)$, storing only the $3 \times 3$ matrix and $3 \times 1$ vectors.
- **Strengths:** Significantly improves numerical stability for QEF systems where intersection points are far from the world origin. Prevents singular matrix errors in degenerate cases where points are nearly coplanar but poorly conditioned.
- **Limitations:** Requires pre-computation or storage of the centroid. Slightly more arithmetic operations than a direct solve.
- **When to Use:** Always preferred over brute-force solving for Dual Contouring QEFs, especially in large-scale scenes or when voxel coordinates are not normalized to $[0,1]$.

## Background
This technique is derived from standard numerical linear algebra practices for solving least-squares problems. It is implemented in the open-source C# Dual Contouring library by tuckbone [S1, unofficial]. The approach is a specific application of centering data to improve the condition number of the Hessian matrix in optimization problems.
