# Occupancy-Based Dual Contouring

Also called: ODC

## Overview
Occupancy-Based Dual Contouring (ODC) is a dual contouring method designed to extract meshes from neural implicit functions defined in continuous 3D space, such as Occupancy Networks, IM-NET, or DeepSDF [S1, unofficial]. It modifies the computation of grid edge points and grid cell points to avoid relying on distance information, which is often unavailable or unreliable in occupancy fields [S1, unofficial]. By introducing auxiliary 2D points to compute local surface normals, ODC identifies 3D points via the Quadric Error Function (QEF) and utilizes fast, parallelizable search algorithms for 1D, 2D, and 3D points [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** An implicit function $f: \mathbb{R}^3 \to \mathbb{R}$, bounding box $\mathcal{P}$ defined by `min_coord` and `max_coord`, grid resolution `num_grid`, isolevel, and search parameters.
*   **Output:** Vertices tensor $(N, 3)$ and triangles tensor $(N, 3)$ representing the extracted mesh.

**Data Structures:**
*   **pfvtab:** A lookup table for dual contouring vertex configurations. It is a list of 64 entries (indices 0-63). Each entry is a list of one or more lists of integers representing vertex indices. The integers range from 1 to 24. Example entry at index 1: `[[13, 2, 17, 3, 15, 1, 13]]` [S1, unofficial].

**Parameters:**
*   `min_coord`: Minimum coordinates of $\mathcal{P}$. Default: `[-0.5, -0.5, -0.5]` [S1, unofficial].
*   `max_coord`: Maximum coordinates of $\mathcal{P}$. Default: `[0.5, 0.5, 0.5]` [S1, unofficial].
*   `num_grid`: Resolution for each axis. Default: `128` [S1, unofficial].
*   `isolevel`: Iso-level to extract. Default: `0.0`. Use `0.5` for occupancy functions, `0.0` for SDF [S1, unofficial].
*   `imp_func_cplx`: GPU VRAM usage of the implicit function for querying one point. Default: `3` [S1, unofficial].
*   `outside`: Boolean flag. True if a larger value indicates outside. Default: `True` [S1, unofficial].
*   `BINARY_SEARCH`: Number of iterations for 1D point search. Default: `15` [S1, unofficial].
*   `VERTICAL_RANGE`: Range for step (1) of the 2D point search. Default: `0.8` [S1, unofficial].
*   `VERTICAL_LINEAR_SEARCH`: Number of linear iterations for step (1) of the 2D point search. Default: `4` [S1, unofficial].
*   `VERTICAL_BINARY_SEARCH`: Number of binary iterations for step (1) of the 2D point search. Default: `11` [S1, unofficial].
*   `HORIZNTL_RANGE`: Range for step (2) of the 2D point search. Default: `0.71` [S1, unofficial].
*   `HORIZNTL_LINEAR_SEARCH`: Number of linear iterations for step (2) of the 2D point search. Default: `3` [S1, unofficial].
*   `HORIZNTL_BINARY_SEARCH`: Number of binary iterations for step (2) of the 2D point search. Default: `12` [S1, unofficial].
*   `ERR`: Error level tolerance. Default: `3e-7` [S1, unofficial].
*   `SEP`: Minimum separation of a 3D point from the grid face. Default: `1e-3` [S1, unofficial].
*   `QEF_REG`: Regularization coefficient for QEF. Default: `0.05` [S1, unofficial].

**Algorithm Steps:**
The method processes the grid in parallel across edges, faces, and cells.

1.  **Grid Initialization:** Define the 3D grid within $\mathcal{P}$ with resolution `num_grid`. Evaluate the implicit function $f$ at all grid vertices to determine occupancy status relative to `isolevel`.
2.  **1D Point Search (Grid Edges):** For each grid edge intersecting the isosurface, search for the intersection point. The search uses `BINARY_SEARCH` iterations [S1, unofficial]. The point is constrained to the edge segment.
3.  **2D Point Search (Grid Faces):** For each grid face intersecting the isosurface, search for an auxiliary 2D point. This search consists of two steps:
    *   Step (1): Vertical search using `VERTICAL_LINEAR_SEARCH` linear iterations followed by `VERTICAL_BINARY_SEARCH` binary iterations within `VERTICAL_RANGE` [S1, unofficial].
    *   Step (2): Horizontal search using `HORIZNTL_LINEAR_SEARCH` linear iterations followed by `HORIZNTL_BINARY_SEARCH` binary iterations within `HORIZNTL_RANGE` [S1, unofficial].
    *   These 2D points are used to compute local surface normals along with the 1D points [S1, unofficial].
4.  **3D Point Search (Grid Cells):** For each grid cell containing the isosurface, search for the 3D vertex position. The search utilizes the 1D points and 2D points (and their associated normals) to formulate a Quadric Error Function (QEF). The QEF is solved with regularization coefficient `QEF_REG` [S1, unofficial]. The resulting point must satisfy the separation constraint `SEP` from the grid face [S1, unofficial].
5.  **Mesh Construction:** Use the `pfvtab` lookup table to determine the vertex configuration for each cell based on the occupancy status of its corners. Connect the computed 3D points to form triangles [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The method is designed for GPU parallelization, achieving computation times of a few seconds for typical resolutions [S1, unofficial].
*   **Memory Complexity:** Depends on `batch_size` (GPU capacity) and `imp_func_cplx` (VRAM usage per query) [S1, unofficial].
*   **Strengths:** Learning-free, state-of-the-art performance for occupancy functions, avoids staircase artifacts of Marching Cubes, and handles continuous 3D space effectively [S1, unofficial].
*   **Limitations:** Requires an implicit function that can be queried; performance depends on GPU VRAM [S1, unofficial].
*   **When to use:** When extracting meshes from neural occupancy fields (e.g., Occupancy Networks, DeepSDF) where distance information is not available or reliable [S1, unofficial].
*   **When not to use:** When SDFs are available and standard dual contouring or marching cubes are sufficient, or when GPU resources are severely limited [S1, unofficial].

## Background
Occupancy-Based Dual Contouring was introduced by the KAIST Visual AI Group [S1, unofficial]. It is based on Manifold Dual Contouring (MDC) but modified specifically for neural implicit representations [S1, unofficial]. The method addresses the bottleneck in converting occupancy functions to meshes, which traditional methods like Marching Cubes struggle with due to staircase artifacts [S1, unofficial].
