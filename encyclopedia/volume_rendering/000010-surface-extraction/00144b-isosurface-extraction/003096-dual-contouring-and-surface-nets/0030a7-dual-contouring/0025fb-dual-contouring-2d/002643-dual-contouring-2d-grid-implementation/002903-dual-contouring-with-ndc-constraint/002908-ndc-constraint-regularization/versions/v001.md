# NDC Constraint Regularization

Also called: NDC Bound Enforcement, NDC Least-Squares Clamping

## Overview
NDC Constraint Regularization is a post-processing step within the Dual Contouring pipeline that ensures extracted vertex coordinates remain within the normalized device coordinate (NDC) range $[0, 1]$ before mapping to grid indices. It solves this by augmenting the least-squares system with diagonal regularization terms that pull the solution toward a target position. It differs from standard dual contouring by explicitly handling boundary violations through an iterative scale adjustment and binary search mechanism rather than simple clamping or projection.

## How it works
**Inputs:**
- $x$: Current vertex position vector (3D).
- $A$: The least-squares constraint matrix (size $m \times 3$).
- $b$: The least-squares constraint vector (size $m$).
- $reference\_V\_len$: The number of existing constraints in $A$ and $b$ before adding the NDC regularization.

**Outputs:**
- $x_{new}$: The updated vertex position vector satisfying the NDC bounds.
- Updated $A$ and $b$ with regularization rows.

**Data Structures:**
The regularization is applied by appending three rows to $A$ and three elements to $b$.
- Rows $reference\_V\_len$ to $reference\_V\_len + 2$ of $A$ form a $3 \times 3$ diagonal matrix.
- Elements $reference\_V\_len$ to $reference\_V\_len + 2$ of $b$ form a vector.

**Parameters:**
- $reg\_scale$: Regularization strength scalar. Initial value is not specified in the source snippet but is implied to be non-zero.
- $reg\_pos$: Regularization target position vector, default $[0.5, 0.5, 0.5]$.
- $tmp\_scale$: Step size for adjusting $reg\_scale$, initial value $1$.
- Max limit for $reg\_scale$: $1000$.

**Algorithm Steps:**

1. **Initial Check:** If $\min(x) < 0$ or $\max(x) > 1$, proceed to iterative increase. Otherwise, skip to step 5.
2. **Iterative Increase:**
   - Initialize $tmp\_scale = 1$.
   - While $\min(x) < 0$ or $\max(x) > 1$:
     - If $reg\_scale > 1000$, break loop.
     - Increment $reg\_scale \leftarrow reg\_scale + tmp\_scale$.
     - Set $A[reference\_V\_len+0, :] = [reg\_scale, 0, 0]$.
     - Set $A[reference\_V\_len+1, :] = [0, reg\_scale, 0]$.
     - Set $A[reference\_V\_len+2, :] = [0, 0, reg\_scale]$.
     - Set $b[reference\_V\_len : reference\_V\_len+3] = reg\_pos \times reg\_scale$.
     - Solve $x = \text{lstsq}(A, b)[0]$.
3. **Reset Check:** If $reg\_scale > 1000$ after the loop:
   - Reset $reg\_scale \leftarrow 10^{-6}$.
   - Reset $reg\_pos \leftarrow [0.5, 0.5, 0.5]$.
   - Set $A[reference\_V\_len+0, :] = [reg\_scale, 0, 0]$.
   - Set $A[reference\_V\_len+1, :] = [0, reg\_scale, 0]$.
   - Set $A[reference\_V\_len+2, :] = [0, 0, reg\_scale]$.
   - Set $b[reference\_V\_len : reference\_V\_len+3] = reg\_pos \times reg\_scale$.
   - Solve $x = \text{lstsq}(A, b)[0]$.
   - If $x$ is still out of bounds ($\min(x) < 0$ or $\max(x) > 1$), proceed to binary search. Otherwise, finish.
4. **Binary Search:**
   - Initialize $tmp\_scale = 1$.
   - Iterate $c$ from $0$ to $9$:
     - $tmp\_scale \leftarrow tmp\_scale / 2$.
     - $reg\_scale \leftarrow reg\_scale - tmp\_scale$.
     - Set $A[reference\_V\_len+0, :] = [reg\_scale, 0, 0]$.
     - Set $A[reference\_V\_len+1, :] = [0, reg\_scale, 0]$.
     - Set $A[reference\_V\_len+2, :] = [0, 0, reg\_scale]$.
     - Set $b[reference\_V\_len : reference\_V\_len+3] = reg\_pos \times reg\_scale$.
     - Solve $x = \text{lstsq}(A, b)[0]$.
     - If $\min(x) < 0$ or $\max(x) > 1$, increment $reg\_scale \leftarrow reg\_scale + tmp\_scale$.
5. **Final Fallback:** If $x$ is still out of bounds after binary search:
   - Set $A[reference\_V\_len+0, :] = [reg\_scale, 0, 0]$.
   - Set $A[reference\_V\_len+1, :] = [0, reg\_scale, 0]$.
   - Set $A[reference\_V\_len+2, :] = [0, 0, reg\_scale]$.
   - Set $b[reference\_V\_len : reference\_V\_len+3] = reg\_pos \times reg\_scale$.
   - Solve $x = \text{lstsq}(A, b)[0]$.

**Pseudocode:**

```python
import numpy as np

def ndc_constraint_regularization(A, b, x, reference_V_len, reg_scale, reg_pos):
    """
    Enforces NDC bounds [0, 1] on vertex position x by adjusting regularization.
    
    Args:
        A: Constraint matrix (m x 3)
        b: Constraint vector (m)
        x: Current vertex position (3,)
        reference_V_len: Number of existing constraints
        reg_scale: Current regularization strength
        reg_pos: Current regularization target position (3,)
        
    Returns:
        A: Updated matrix
        b: Updated vector
        x: Updated position
        reg_scale: Updated scale
        reg_pos: Updated position
    """
    
    # Helper to apply regularization and solve
    def apply_and_solve(A, b, ref_len, rs, rp):
        # Set regularization rows
        A[ref_len, 0] = rs
        A[ref_len, 1] = 0.0
        A[ref_len, 2] = 0.0
        
        A[ref_len + 1, 0] = 0.0
        A[ref_len + 1, 1] = rs
        A[ref_len + 1, 2] = 0.0
        
        A[ref_len + 2, 0] = 0.0
        A[ref_len + 2, 1] = 0.0
        A[ref_len + 2, 2] = rs
        
        # Set regularization target
        b[ref_len] = rp[0] * rs
        b[ref_len + 1] = rp[1] * rs
        b[ref_len + 2] = rp[2] * rs
        
        # Solve least squares
        # Note: In practice, use numpy.linalg.lstsq or scipy.linalg.lstsq
        # Here we assume a generic solver that returns the solution vector
        x_new = np.linalg.lstsq(A, b, rcond=None)[0]
        return x_new

    # Check if bounds are violated
    if np.min(x) < 0 or np.max(x) > 1:
        tmp_scale = 1.0
        
        # Iterative increase phase
        while np.min(x) < 0 or np.max(x) > 1:
            if reg_scale > 1000:
                break
            
            reg_scale += tmp_scale
            x = apply_and_solve(A, b, reference_V_len, reg_scale, reg_pos)
            
        # Reset if scale exceeded limit
        if reg_scale > 1000:
            reg_scale = 1e-6
            reg_pos = np.array([0.5, 0.5, 0.5], dtype=np.float32)
            x = apply_and_solve(A, b, reference_V_len, reg_scale, reg_pos)
            
            # If still out of bounds, proceed to binary search
            if np.min(x) < 0 or np.max(x) > 1:
                tmp_scale = 1.0
                
                # Binary search phase
                for c in range(10):
                    tmp_scale /= 2.0
                    reg_scale -= tmp_scale
                    x = apply_and_solve(A, b, reference_V_len, reg_scale, reg_pos)
                    
                    if np.min(x) < 0 or np.max(x) > 1:
                        reg_scale += tmp_scale
                        
                # Final fallback if still out of bounds
                if np.min(x) < 0 or np.max(x) > 1:
                    x = apply_and_solve(A, b, reference_V_len, reg_scale, reg_pos)
                    
    return A, b, x, reg_scale, reg_pos
```

## Operating characteristics
- **Time Complexity:** Linear in the number of iterations of the while/for loops. The number of iterations is bounded (max 10 for binary search, plus initial increases). Each iteration involves a least-squares solve, which is typically $O(m^2)$ or $O(m^3)$ depending on the solver, where $m$ is the number of constraints.
- **Memory Complexity:** $O(1)$ additional memory, as it modifies $A$ and $b$ in place.
- **Strengths:** Ensures strict adherence to NDC bounds, preventing grid index mapping errors. The binary search allows for fine-tuning the regularization strength to minimize distortion while satisfying constraints.
- **Limitations:** May introduce slight distortion to the vertex position if the regularization strength becomes high. The reset mechanism might lead to suboptimal solutions if the initial constraints are incompatible with the NDC bounds.
- **When to use:** When extracting meshes from point clouds or signed distance fields where vertices must map to a specific grid range $[0, 1]$.
- **When not to use:** If the vertex positions are already guaranteed to be within bounds, or if strict NDC mapping is not required.

## Background
NDC Constraint Regularization is part of the Dual Contouring with NDC Constraint method, introduced in the repository `czq142857/NDC` [S1, unofficial]. It addresses the issue of vertex positions falling outside the normalized device coordinate space during the least-squares solving process in dual contouring. The method uses a combination of iterative scaling and binary search to find an appropriate regularization strength that keeps vertices within bounds.
