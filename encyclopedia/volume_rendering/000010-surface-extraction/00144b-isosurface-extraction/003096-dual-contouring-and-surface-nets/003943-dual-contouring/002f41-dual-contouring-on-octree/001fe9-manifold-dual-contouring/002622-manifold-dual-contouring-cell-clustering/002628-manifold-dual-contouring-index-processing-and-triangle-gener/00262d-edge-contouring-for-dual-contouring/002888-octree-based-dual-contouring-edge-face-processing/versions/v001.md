# Octree-based Dual Contouring Edge/Face Processing

Also called: DualContouringSample Octree, Tao Ju Octree Implementation

## Overview
This method is a recursive procedure that processes the edges and faces of an adaptive octree to generate triangle indices for a dual contouring mesh. It handles both leaf and pseudo-leaf nodes by descending into children when necessary, ensuring that geometry is generated only at the boundaries between solid and air regions. It builds on [Edge Contouring for Dual Contouring](3711-edge-contouring-for-dual-contouring.md) by providing the specific octree-aware traversal and edge processing logic required for adaptive volumetric data.

## How it works
### Inputs and Outputs
- **Input**: An adaptive octree where each node contains material flags for its 8 corners (`m_corners`), a size (`m_size`), and optional children (`m_children`). A scalar field sampler (`Sampler::Sample` or `Sampler::SampleCache`) is required to evaluate density at arbitrary positions.
- **Output**: An `IndexBuffer` containing triangle indices (triplets of vertex indices).

### Data Structures
- **Octree Node**:
  - `m_leaf` (bool): True if the node is a leaf.
  - `m_children` (pointer to `OctreeChildren`): Contains a `field` (uint8_t bitmask of existing children) and an array of 8 child pointers.
  - `m_corners` (int): Bit-packed material flags for the 8 corners of the node. Bit `i` corresponds to corner `i`.
  - `m_size` (int): The size of the node in world units (or grid units).
  - `m_index` (int): The vertex index assigned to this node's dual vertex.
- **OctreeChildren**:
  - `field` (uint8_t): Bitmask indicating which of the 8 children exist.
  - `children` (array of 8 pointers): Pointers to child `Octree` nodes.
- **Constants**:
  - `MATERIAL_AIR`: 0
  - `MATERIAL_SOLID`: 1
  - `QEF_ERROR`: 1e-6f (used in QEF solving, not directly in edge processing but part of the leaf construction context).
  - `minError`: 0.01f (early exit threshold for zero-crossing approximation).

### Helper Functions
1. **LeafOrChild(node, idx)**:
   - If `node` is a leaf, return `node`.
   - If `node` has children, return `node->children[idx]`.
   - Return `nullptr` if the child does not exist.

2. **ApproximateZeroCrossingPosition(p0, p1)**:
   - Finds the position on edge `p0-p1` where the scalar field is near zero.
   - Uses a binary search approach with 8 steps.
   - Start `currentT = 0.5`, `increment = 0.5`.
   - Loop 8 times:
     - `p = p0 + (p1 - p0) * currentT`
     - `density = abs(Sample(p))`
     - If `density < minError` (0.01f), return `p`.
     - If `density > 0`, `currentT -= increment`.
     - Else, `currentT += increment`.
     - `increment *= 0.5`.
   - Return `p0 + (p1 - p0) * currentT`.

### Main Traversal
1. **CellProc(node)**:
   - If `node` is a leaf, return.
   - Call `CellChildProc` for each of the 8 children.

2. **CellChildProc(node)**:
   - Process 4 X-faces, 4 Y-faces, 4 Z-faces, and 6 edges (XY, XZ, YZ) using predefined neighbor indices.
   - Recursively call `CellProc` on all 8 children.

### Face Processing
- **FaceProcX/Y/Z(n0, n1, n2, n3, indexBuffer)**:
  - Check if both adjacent nodes are leaves. If so, return (no geometry generated for internal faces between two solid/air leaves in this specific implementation logic).
  - If not, recursively process sub-faces and sub-edges by calling `FaceProc` on the appropriate children.

### Edge Processing
- **EdgeProcXY/XZ/YZ(n0, n1, n2, n3, indexBuffer)**:
  - Check if all 4 adjacent nodes are leaves.
  - If so, call `ProcessEdge(n0, n1, n2, n3, dir, indexBuffer)`.
  - If not, recursively call `EdgeProc` on specific child indices to descend into the octree.

### ProcessEdge(n0, n1, n2, n3, dir, indexBuffer)
1. Initialize `minSize` to infinity, `minIndex` to -1.
2. Initialize `indices` array of size 4.
3. For `i` from 0 to 3:
   - `node = [n0, n1, n2, n3][i]`
   - If `node` is `nullptr`, continue.
   - `edgeIdx = processEdgeMask[dir][i]`
   - `c1 = (node->m_corners >> edgeIdx[0]) & 1`
   - `c2 = (node->m_corners >> edgeIdx[1]) & 1`
   - `m1 = (c1 == 1) ? MATERIAL_SOLID : MATERIAL_AIR`
   - `m2 = (c2 == 1) ? MATERIAL_SOLID : MATERIAL_AIR`
   - `signChange = (m1 != m2)`
   - If `signChange`:
     - `indices[i] = node->m_index`
     - If `node->m_size < minSize`:
       - `minSize = node->m_size`
       - `minIndex = i`
     - `flip = (m1 == MATERIAL_SOLID)`
4. If `minIndex != -1`:
   - Generate 2 triangles (6 indices) using `indices[0..3]`.
   - If `flip` is false:
     - Add indices `(indices[0], indices[1], indices[3])`
     - Add indices `(indices[0], indices[3], indices[2])`
   - If `flip` is true:
     - Add indices `(indices[0], indices[3], indices[1])`
     - Add indices `(indices[0], indices[2], indices[3])`

    min_index = -1

        c2 = (node.m_corners >> edge_idx[1]) & 1

## Operating characteristics
- **Time Complexity**: Depends on the octree depth and the number of boundary voxels. Each edge is processed once, and recursion depth is proportional to the octree height.
- **Memory Complexity**: Proportional to the number of octree nodes. Each node stores a small amount of metadata.
- **Strengths**: Adaptive resolution allows for detailed geometry where needed and coarser geometry elsewhere. Efficient handling of large volumetric datasets.
- **Limitations**: May produce non-manifold geometry if not carefully implemented. The specific edge processing logic may require additional steps to ensure manifoldness.
- **When to Use**: Suitable for adaptive volumetric data where resolution varies significantly across the domain.
- **When Not to Use**: For uniform grids, simpler methods like Marching Cubes may be more efficient.

## Background
This method is based on the implementation found in the `DualContouringSample` project by Tao Ju [S1, unofficial]. It is designed to extract polygonal meshes from volumetric scalar fields using an adaptive octree structure. The approach is particularly useful for procedural generation and terrain modeling where adaptive resolution is beneficial.
