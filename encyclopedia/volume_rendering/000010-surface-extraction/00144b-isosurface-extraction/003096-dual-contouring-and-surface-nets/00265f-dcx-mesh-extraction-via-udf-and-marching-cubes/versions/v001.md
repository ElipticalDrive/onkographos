# DCX Mesh Extraction via UDF and Marching Cubes

Also called: BVH UDF to Mesh, UDF-based Marching Cubes

## Overview
DCX extracts a triangular mesh from a BVH (Bounding Volume Hierarchy) structure by computing an Unsigned Distance Field (UDF) on a regular grid, converting it to a Signed Distance Field (SDF) via flood fill, and applying Marching Cubes [S1, unofficial]. It differs from standard Marching Cubes by deriving the scalar field from geometric primitives via BVH queries rather than volumetric data, and from Dual Contouring by using a uniform grid with topological correction via flood fill instead of adaptive quadric optimization [S1, unofficial].

## How it works
**Inputs:**
- A BVH structure supporting unsigned distance queries.
- An integer `resolution` defining the grid dimensions $N \times N \times N$.
- Coordinate range $[-0.5, 0.5]$ for X, Y, Z axes.

**Outputs:**
- A `trimesh.Trimesh` object containing vertices, faces, and normals.

**Data Structures:**
- `udf`: 3D array of shape $(N, N, N)$, `float32`.
- `occ_mask`: 3D boolean array of shape $(N, N, N)$.
- `sdf`: 3D array of shape $(N, N, N)$, `float32`.

**Steps:**

1. **Grid Initialization**:
   Split the coordinate range $[-0.5, 0.5]$ into $N$ chunks. Create a meshgrid of points $P$ with shape $(N^3, 3)$.

2. **UDF Query**:
   Query the BVH for the unsigned distance at each point $P$. Store results in `udf`.
   $$ \text{udf}[i, j, k] = \text{BVH.unsigned\_distance}(P_{i,j,k}) $$

3. **Occupancy Determination**:
   Define occupancy threshold $T = 2 / N$.
   $$ \text{occ}[i, j, k] = (\text{udf}[i, j, k] < T) $$
   Perform a 3D flood fill on `occ` to identify connected components. Identify the label of the background (empty) region by checking the voxel at $(0, 0, 0)$.
   $$ \text{empty\_label} = \text{floodfill\_mask}[0, 0, 0] $$
   Create occupancy mask:
   $$ \text{occ\_mask}[i, j, k] = (\text{floodfill\_mask}[i, j, k] \neq \text{empty\_label}) $$

4. **SDF Conversion**:
   Initialize SDF with UDF values. Invert the sign for occupied regions:
   $$ \text{sdf}[i, j, k] = \begin{cases} -\text{udf}[i, j, k] & \text{if } \text{occ\_mask}[i, j, k] \\ \text{udf}[i, j, k] & \text{otherwise} \end{cases} $$

5. **Marching Cubes**:
   Apply Marching Cubes to `sdf` with isovalue $0$ and spacing $(1/N, 1/N, 1/N)$.
   $$ \text{verts}_{raw}, \text{faces}, \text{normals}, \text{values} = \text{marching\_cubes}(\text{sdf}, 0, \text{spacing}=(1/N, 1/N, 1/N)) $$

6. **Coordinate Adjustment**:
   Transform vertices from grid indices to the canonical $[-0.5, 0.5]$ space:
   $$ \text{verts} = \text{verts}_{raw} - 0.5 + \frac{0.5}{N-1} $$
   $$ \text{verts} = \text{verts} \times \frac{N}{N-1} $$

7. **Mesh Creation**:
   Construct the final mesh object.
   $$ \text{mesh} = \text{trimesh.Trimesh}(\text{verts}, \text{faces}) $$

**Pseudocode:**

```python
import numpy as np
import torch
from skimage import measure
import trimesh

def extract_mesh(bvh, resolution):
    N = resolution
    # 1. Grid Initialization
    xs = np.linspace(-0.5, 0.5, N)
    ys = np.linspace(-0.5, 0.5, N)
    zs = np.linspace(-0.5, 0.5, N)
    xx, yy, zz = np.meshgrid(xs, ys, zs, indexing='ij')
    points = np.stack([xx.ravel(), yy.ravel(), zz.ravel()], axis=-1).astype(np.float32)
    
    # 2. UDF Query
    # Assuming bvh.unsigned_distance returns distances for a batch of points
    udf_flat = bvh.unsigned_distance(points)
    udf = udf_flat.reshape(N, N, N)
    
    # 3. Occupancy Determination
    threshold = 2.0 / N
    occ = udf < threshold
    
    # Convert to torch tensor for CUDA flood fill if available, else CPU
    occ_tensor = torch.from_numpy(occ).cuda()
    # Placeholder for specific flood fill implementation details from cubvh library
    # floodfill_mask shape: (1, N, N, N)
    floodfill_mask = cubvh.floodfill(occ_tensor) 
    floodfill_mask = floodfill_mask.cpu().numpy()
    
    empty_label = floodfill_mask[0, 0, 0]
    empty_mask = (floodfill_mask == empty_label)
    occ_mask = ~empty_mask[0] # Remove batch dimension
    
    # 4. SDF Conversion
    sdf = udf.copy()
    sdf[occ_mask] *= -1
    
    # 5. Marching Cubes
    verts_raw, faces, normals, values = measure.marching_cubes(
        sdf, 
        level=0, 
        spacing=(1.0/N, 1.0/N, 1.0/N)
    )
    
    # 6. Coordinate Adjustment
    verts = verts_raw - 0.5 + (0.5 / (N - 1))
    verts = verts * (N / (N - 1))
    
    # 7. Mesh Creation
    mesh = trimesh.Trimesh(vertices=verts, faces=faces, normals=normals)
    return mesh
```

**Parameters:**
- `resolution`: Integer grid size $N$. Typical values depend on desired detail and memory constraints. Not given in the sources.

**Edge Cases and Pitfalls:**
- **Flood Fill Background**: The background label is determined by the voxel at $(0,0,0)$. If the object touches the boundary, this may incorrectly classify the interior as background [S1, unofficial].
- **Occupancy Threshold**: Voxels with UDF $< 2/N$ are considered inside. This small threshold helps define the surface boundary but may be sensitive to noise [S1, unofficial].
- **Precision**: UDF and SDF arrays use `float32`. Precision issues may arise at high resolutions or with very small features [S1, unofficial].

## Operating characteristics
- **Time Complexity**: Dominated by BVH queries for $N^3$ points and the flood fill operation. BVH query time is $O(\log P)$ per point where $P$ is the number of primitives. Total query time $O(N^3 \log P)$. Flood fill is $O(N^3)$.
- **Memory Complexity**: $O(N^3)$ for storing UDF, SDF, and occupancy masks. For `float32`, this is $4 N^3$ bytes per array.
- **Strengths**: Handles complex BVH structures efficiently; robust to noise via UDF smoothing; flood fill ensures watertightness.
- **Limitations**: Uniform grid resolution may be inefficient for sparse scenes; flood fill requires identifying background correctly; Marching Cubes may produce artifacts near sharp features.
- **When to use**: When extracting meshes from BVH-based representations (e.g., ray tracing scenes) where a volumetric field is not explicitly available.
- **When not to use**: For highly sparse data where sparse voxel grids are more efficient; when adaptive resolution is required.

## Background
The method is described in the unofficial repository `jjjkkyz/DCx` [S1, unofficial]. It combines techniques from geometric processing (BVH distance queries) and volume rendering (Marching Cubes) to create a pipeline for mesh extraction from hierarchical bounding volume structures.
