# Anchor Group

Also called: DCx Subgroup 2.2, DCx Subgroup 2.2: Anchor Group

## Overview
The Anchor Group is a specific subgroup within the Dual Contouring over Expanded Cubes (DCx) method covering three isotropic cases (4-6, 6-3, and 8) [S1]. Determining face patterns for these cases originally requires simultaneous evaluation of all neighboring expanded cubes, which leads to prohibitively high complexity [S1]. The method introduces an anchor point to decouple these interactions, lowering implementation complexity while handling intricate non-manifold structures [S1].

## How it works
### Inputs and Outputs
*   **Input:** The current expanded cube $C$ belonging to one of the three Anchor Group cases (4-6, 6-3, or 8); the set of all neighboring expanded cubes adjacent to $C$; the voxel topology data [S1].
*   **Output:** A set of planar faces and mesh primitives connecting the anchor point to vertices on the cube faces, forming the local surface representation for $C$ [S1].

### Data Structures
*   **Anchor Point ($A$):** A single 3D vector representing the position of the anchor [S1].
*   **Dual Vertices ($D_i$):** The set of dual vertices located inside the expanded cube $C$ [S1].
*   **External Voxels:** Voxels adjacent to a voxel in $C$ but not belonging to $C$, classified as face-adjacent or edge-adjacent [S1].

### Steps
1.  **Compute Anchor Point:** Calculate the anchor point $A$ as the arithmetic mean of all dual vertices $D_i$ contained within the current expanded cube $C$ [S1].
    $$ A = \frac{1}{N} \sum_{i=1}^{N} D_i $$
    where $N$ is the number of dual vertices in $C$ [S1].
2.  **Iterative Neighbor Evaluation:** The anchor point decouples the need for simultaneous multi-cube evaluation, allowing iterative examination of each adjacent expanded cube $C_{adj}$ [S1]. For each $C_{adj}$, connect the anchor $A$ to vertices on the corresponding shared face of $C$ [S1].
3.  **Case-Specific Primitive Generation:**
    *   **Case 4-6:** Generate planar faces only when adjacent expanded cubes are valid [S1]. A cube is valid if it contains more than 2 voxels [S1].
    *   **Case 6-3:** Identify the coplanar 3-voxel configuration in the adjacent expanded cube $C_{adj}$ [S1]. Apply the first primitive if this configuration does not produce a triangle; otherwise, apply the second primitive [S1].
    *   **Case 8:** Perform a thinning process to remove redundant voxels before generating faces [S1]. Define external voxels as those adjacent to a voxel in $C$ but outside $C$ [S1]. Evaluate each voxel $v$ in $C$: if $v$ has an edge-adjacent external voxel and lacks any face-adjacent external voxel that does not belong to Case 8, mark $v$ as valid; otherwise, mark $v$ for thinning [S1]. Perform thinning sequentially to prevent complete deletion of $C$ [S1]. When a voxel is thinned, its adjacent voxels skip evaluation for removal unless they belong to other Case 8 cubes [S1]. Generate faces based on the remaining valid structure [S1].
4.  **Finalize Mesh:** Combine the primitives generated from all adjacent expanded cubes to form the final mesh for $C$ [S1].

### Parameters
*   **Anchor Point Definition:** Average of all dual vertices inside the expanded cube [S1].

### Edge Cases and Pitfalls
*   **Non-Manifold Structures:** The Anchor Group cases frequently produce intricate non-manifold structures [S1]. The anchor point strategy is specifically designed to handle these, but incorrect handling of adjacency can lead to invalid geometry [S1].
*   **Case 8 Thinning:** Sequential thinning is required [S1]. If all voxels in a Case 8 cube are evaluated and removed simultaneously without sequential dependency checks, the entire cube may be deleted incorrectly [S1].
*   **Case 4-3 Interaction:** The coplanar 4-voxel case (Case 4-3) does not produce any faces if its neighboring expanded cube falls into Case 8 [S1]. This dependency must be checked during the neighbor evaluation step [S1].

### Pseudocode
```python
def compute_anchor_group_faces(expanded_cube, neighbors):
    # Step 1: Compute Anchor Point
    dual_vertices = expanded_cube.dual_vertices
    if not dual_vertices:
        return []
    anchor = sum(dual_vertices) / len(dual_vertices)

    faces = []
    thinned_set = set()

    # Step 2 & 3: Iterative neighbor evaluation with case-specific logic
    for neighbor in neighbors:
        if neighbor.case_type == "4-6":
            # Valid if > 2 voxels
            if neighbor.voxel_count > 2:
                faces.append(create_primitives(anchor, neighbor.shared_face_vertices))
        elif neighbor.case_type == "6-3":
            coplanar_3 = neighbor.coplanar_3_voxel
            if not produces_triangle(coplanar_3):
                faces.append(create_primitive_1(anchor, neighbor.shared_face_vertices))
            else:
                faces.append(create_primitive_2(anchor, neighbor.shared_face_vertices))
        elif neighbor.case_type == "8":
            # Thinning process
            valid_voxels = []
            for voxel in expanded_cube.voxels:
                if voxel in thinned_set:
                    continue
                face_adj_ext = [v for v in voxel.neighbors if not expanded_cube.contains(v) and is_face_adjacent(voxel, v)]
                edge_adj_ext = [v for v in voxel.neighbors if not expanded_cube.contains(v) and is_edge_adjacent(voxel, v)]
                has_invalid_face = any(v.case_type != "8" for v in face_adj_ext)
                if edge_adj_ext and not has_invalid_face:
                    valid_voxels.append(voxel)
                else:
                    thinned_set.add(voxel)
            if valid_voxels:
                faces.append(create_primitives(anchor, valid_voxels, neighbor.shared_face_vertices))
    return faces

# Helper definitions
def is_face_adjacent(v1, v2):
    return abs(v1.pos - v2.pos).sum() == 1.0

def is_edge_adjacent(v1, v2):
    return abs(v1.pos - v2.pos).sum() == 2.0

def produces_triangle(coplanar_3_voxel):
    return len(coplanar_3_voxel) == 3

def create_primitives(anchor, *args):
    # Standard mesh primitive generation connecting anchor to provided vertices
    return []

def create_primitive_1(anchor, vertices):
    return create_primitives(anchor, vertices)

def create_primitive_2(anchor, vertices):
    return create_primitives(anchor, vertices)
```

## Operating characteristics
*   **Complexity:** The method reduces complexity from "prohibitively high" (simultaneous evaluation of all neighbors) to a manageable iterative process [S1].
*   **Strengths:** Decouples adjacency relationships, allowing for the construction of fine-grained features and non-manifold structures that cannot be built from original vertices alone [S1].
*   **Limitations:** The generated meshes may be anisotropic despite the isotropic nature of the input cases [S1]. Requires careful handling of Case 8 thinning to avoid data loss [S1].

## Background
The Anchor Group is part of the Dual Contouring over Expanded Cubes (DCx) method for zero-level set extraction from Neural Unsigned Distance Functions [S1]. It was introduced to handle complex topological configurations (subgroup 2.2) that arise in DCx, specifically cases 4-6, 6-3, and 8 [S1]. The method relies on the concept of expanded cubes and dual vertices, building upon the mass point centering approach for dual vertex positioning [S1].
