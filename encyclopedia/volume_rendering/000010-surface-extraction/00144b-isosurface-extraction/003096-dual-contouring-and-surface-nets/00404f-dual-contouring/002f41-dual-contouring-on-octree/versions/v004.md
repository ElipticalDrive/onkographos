# Dual Contouring on Octree

Also called: Dual Contouring with Octree, Octree-based Dual Contouring

## Overview
Dual Contouring on Octree is a surface extraction method that generates a triangle mesh from a scalar field by traversing an adaptive octree hierarchy, solving Quadratic Error Functions (QEF) at nodes to determine vertex positions, and connecting these vertices via edge and face processing [S1, S2, S3, unofficial]. It differs from uniform grid dual contouring by allowing adaptive resolution, reducing polygon count in flat regions while preserving detail in complex areas [S3, unofficial]. Unlike standard Dual Contouring which places one vertex per leaf voxel, this method manages the mesh generation through a recursive traversal of cell faces and edges to handle topological transitions between nodes of varying depths [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A scalar field function $f(x,y,z)$, an isovalue $iso$, a bounding box (`Cuboid`), and a maximum octree depth [S1, S3, unofficial].
- **Output:** A list of triangle meshes containing vertices, normals, and indices [S1, S2, unofficial].

**Data Structures:**
1.  **Octree<T>:**
    -   `bounds`: `Cuboid` defining the spatial extent [S1, unofficial].
    -   `children`: Array of 8 `Octree<T>` pointers (null if leaf) [S1, unofficial].
    -   `data`: Generic type `T` (e.g., `NodeData` or `OctreeDrawInfo`) [S1, S2, unofficial].
    -   Construction: `SubDivide()` splits bounds into 8 equal children using bitmasks for offsets: `offset = ((i&1), (i&2), (i&4)) * (size/2)` [S1, unofficial].
2.  **NodeData (QEF-based implementations [S1, unofficial]):**
    -   `qef`: Quadratic Error Function object.
    -   `vertex`: `Vector3` position.
    -   `cornerEncoding`: Integer bitmask representing sign changes at corners.
    -   `index`: Mesh vertex index (initialized to -1) [S1, unofficial].
    -   `size`: Float diagonal length of node bounds [S1, unofficial].
3.  **OctreeDrawInfo (Traversal-based implementations [S2, unofficial]):**
    -   `position`: `Vector3`.
    -   `normal`: `Vector3`.
    -   `index`: Int.
    -   `corners`: Int bitmask.
    -   `size`: Float [S2, unofficial].
4.  **Lookup Tables [S1, S2, S3, unofficial]:**
    -   `edgevmap` (12x2): Maps edge index to two corner indices.
    -   `vertMap` (8x3): Maps corner index to (x,y,z) coordinates.
    -   `faceMap` (6x4): Maps face index to 4 corner indices.
    -   `cellProcFaceMask` (12x3): Maps cell face index to two child indices and a direction.
    -   `cellProcEdgeMask` (6x5): Maps cell edge index to four child indices and a direction.
    -   `faceProcFaceMask` (3x4x3): Maps face-level children to sub-children and directions.
    -   `faceProcEdgeMask` (3x4x6): Maps face-level children to sub-edges and directions.
    -   `edgeProcEdgeMask` (3x2x5): Maps edge-level children to sub-edges and directions.
    -   `processEdgeMask` (3x4): Maps edge directions to global edge indices.

**Pseudocode:**
```python
def ContourCellProc(node):
    if node is None or node.is_leaf(): return
    for child in node.children: ContourCellProc(child)
    for i in range(12):
        face_nodes = [node.children[cellProcFaceMask[i][0]], node.children[cellProcFaceMask[i][1]]]
        ContourFaceProc(face_nodes, cellProcFaceMask[i][2])
    for i in range(6):
        edge_nodes = [node.children[cellProcEdgeMask[i][j]] for j in range(4)]
        ContourEdgeProc(edge_nodes, cellProcEdgeMask[i][4])

def ContourFaceProc(nodes, direction):
    if nodes[0] is None or nodes[1] is None: return
    if nodes[0].is_leaf() and nodes[1].is_leaf(): return
    if nodes[0].is_internal() or nodes[1].is_internal():
        for i in range(4):
            face_nodes = [nodes[faceProcFaceMask[direction][i][0]], nodes[faceProcFaceMask[direction][i][1]]]
            ContourFaceProc(face_nodes, faceProcFaceMask[direction][i][2])
        for i in range(4):
            edge_nodes = [nodes[faceProcEdgeMask[direction][i][j]] for j in range(4)]
            ContourEdgeProc(edge_nodes, faceProcEdgeMask[direction][i][5])
    else:
        ContourProcessEdge(nodes, direction)

def ContourEdgeProc(nodes, direction):
    if any(n is None for n in nodes): return
    if all(n.is_leaf() or n.is_pseudo() for n in nodes):
        ContourProcessEdge(nodes, direction)
    else:
        for i in range(2):
            edge_nodes = [nodes[edgeProcEdgeMask[direction][i][j]] for j in range(4)]
            ContourEdgeProc(edge_nodes, edgeProcEdgeMask[direction][i][4])

def ContourProcessEdge(nodes, direction):
    if len(vertices) + 4 > MAX_VERTS_PER_MESH: flush_mesh()
    ptrs = [-1] * 4
    sign_change = [False] * 4
    min_size = float('inf')
    min_index = 0
    flip = False
    for i in range(4):
        node = nodes[i]
        edge_idx = processEdgeMask[direction][i]
        encoding = node.data.corner_encoding
        c0_sign = (encoding >> edgevmap[edge_idx][0]) & 1
        c1_sign = (encoding >> edgevmap[edge_idx][1]) & 1
        sign_change[i] = c0_sign != c1_sign
        if node.data.size < min_size:
            min_size = node.data.size
            min_index = i
            flip = c0_sign
        if node.data.index == -1:
            node.data.index = len(vertices)
            vertices.append(node.data.vertex)
        ptrs[i] = node.data.index
    if sign_change[min_index]:
        if flip:
            indices.extend([ptrs[0], ptrs[1], ptrs[3], ptrs[0], ptrs[3], ptrs[2]])
        else:
            indices.extend([ptrs[0], ptrs[3], ptrs[1], ptrs[0], ptrs[2], ptrs[3]])
```

**Parameters:**
-   `MAX_VERTS_PER_MESH`: Integer constant, typically 30,000 [S1, unofficial].
-   `threshold`: Float error threshold for simplification (e.g., 1e0) [S3, unofficial].

**Edge Cases and Pitfalls:**
-   **Duplicate Vertices:** Prevented by checking `data.index == -1` before adding to the vertex list; existing index is reused [S1, unofficial].
-   **Buffer Overflow:** Checked before processing an edge; triggers mesh flush if exceeded [S1, unofficial].
-   **Triangle Winding:** Depends on `flip` boolean, determined by corner bits at the minimum-size node [S2, unofficial]. Incorrect logic inverts normals [S2, unofficial].
-   **Pseudo-nodes:** Treated identically to leaf nodes during traversal and edge processing [S2, unofficial].

## Subtopics

### [Manifold Dual Contouring](2138-manifold-dual-contouring.md)
Manifold Dual Contouring is an extension of Dual Contouring that guarantees the generated mesh is a closed 2-manifold even under adaptive simplification, using an octree-based topology-preserving vertex-clustering algorithm. It differs from standard Dual Contouring by enforcing manifold constraints through explicit vertex collapsing and edge processing, ensuring the resulting mesh is a valid 2-manifold without non-manifold edges. Unlike Extended Dual Contouring, it places no restriction on the number of contour intersections on each octree cell edge because the vertex tree is separate from the octree, allowing simplification of multiple layers of thin geometry.

### [Adaptive Contouring via Octree Vertex Clustering](2142-adaptive-contouring-via-octree-vertex-clustering.md)
Adaptive Contouring via Octree Vertex Clustering is a surface extraction method that constructs multi-resolution iso-surfaces by clustering vertices of child cells in an octree into a single vertex in a topologically safe manner. It allows an arbitrary number of vertices per cell to significantly reduce polygon count in flat regions, addressing the restrictive single-vertex-per-cell limitation of standard Dual Contouring. Unlike its siblings, it explicitly builds a "vertex tree" to manage hierarchical simplification and uses QEF minimization to determine the position of clustered vertices.

### [Adaptive Dual Contouring](3664-adaptive-dual-contouring.md)
Adaptive Dual Contouring extracts a manifold mesh from a scalar density function by building an adaptive octree, solving Quadratic Error Functions (QEF) at nodes to determine vertex positions, and generating a mesh from the resulting constrained vertices. It solves a Quadratic Error Function (QEF) at each node to determine vertex positions, then recursively collapses internal octree nodes into 'pseudo-leaf' nodes if the resulting QEF error is below a threshold, preserving sharp features defined by the sign configuration of child nodes. Unlike standard Dual Contouring which places one vertex per leaf voxel, this method reduces vertex count by merging internal nodes, producing a coarser but topologically consistent mesh suitable for real-time rendering or further processing.

### [Kdtree-based Iso-surface Extraction](3816-kdtree-based-iso-surface-extraction.md)
Kdtree-based Iso-surface Extraction extracts iso-surfaces from scalar fields using a hierarchical K-d tree built upon an octree, applying Quadratic Error Function (QEF) optimization and clusterability checks for vertex simplification. It differs from sibling methods by explicitly constructing a K-d tree to guide traversal and subdivision, while supporting a fallback octree-only mode for standard extraction.

### [Mesh Extraction from K-D Tree](4607-mesh-extraction-from-k-d-tree.md)
Extracts a triangle mesh from a scalar field by traversing a hierarchical K-D tree structure, generating vertex indices, and performing contouring on cells, faces, and edges. It differs from standard marching cubes by operating directly on the hierarchical K-D tree structure, allowing for adaptive resolution and handling of complex topologies through recursive contour edge traversal.

### [Isomesh Octree Build and Clustering](4984-isomesh-octree-build-and-clustering.md)
Isomesh is a hierarchical mesh generation method that constructs an octree over a uniform grid to extract a surface mesh while preserving material properties and minimizing reconstruction error. It differs from standard dual contouring by recursively clustering vertices at every node level (leaves, edges, faces, and cells) using Disjoint Set Union (DSU) and Quadratic Error Function (QEF) solvers, ensuring topological consistency across the hierarchy.

### [Intersection-Free Dual Contouring](5313-intersection-free-dual-contouring.md)
Intersection-Free Dual Contouring is a variant of Dual Contouring that ensures the resulting mesh is manifold and free of self-intersections by detecting intersecting triangles and performing local tessellation or vertex splitting. It addresses the problem of self-intersecting triangles produced by the original Dual Contouring algorithm. It sets itself apart from siblings like [Manifold Dual Contouring](2138-manifold-dual-contouring.md) by using explicit pairwise intersection tests and post-processing tessellation rather than modifying the underlying optimization or constraint formulation to inherently prevent intersections.

### [Octree Construction for Dual Contouring](5913-octree-construction-for-dual-contouring.md)
This method constructs the spatial hierarchy required for Dual Contouring by recursively subdividing a volume into an octree, pruning branches that do not intersect the isosurface. It differs from sibling methods like [Mesh Extraction from K-D Tree](4607-mesh-extraction-from-k-d-tree.md) by using a fixed-depth hierarchical grid structure rather than a binary spatial partition, and from [Isomesh Octree Build and Clustering](4984-isomesh-octree-build-and-clustering.md) by focusing on single-vertex-per-leaf extraction logic rather than clustering [G]. It solves the problem of efficiently identifying which voxels contain surface geometry to minimize memory usage and processing time for sparse volumes [G].

### Seam Generation for Adjacent Chunks
Generates mesh vertices and indices along the boundary between two adjacent octree chunks to eliminate seams common in dual contouring implementations [S5, unofficial]. It initializes a `borderChildren` array and `idxs` mapping, iterates over chunk children, fetches coordinates and edge indices from `edgeIndexLookup` (a 4D array [6][2][4][4]), and dispatches to `FaceProc` functions with correct ordering to handle winding/normal consistency [S5, unofficial].

### Vertex Clustering for Adaptive DC
A vertex clustering approach for simplifying contours in adaptive octree-based Dual Contouring [S6, unofficial]. It maintains disconnected contour components during simplification to improve adaptivity [S6, unofficial]. However, it can still generate non-manifold edges and vertices in adaptive settings and requires non-trivial coding-vector operations [S6, unofficial]. It restricts the maximum number of intersections between the contour and each cell edge to 2, which is more restrictive than the proposed manifold method [S6, unofficial].

-   **Strengths:** Adaptive resolution reduces polygon count in flat regions [S3, unofficial]. Seam artifacts can occur between adjacent chunks if not handled explicitly [S5, unofficial].

## Background
The octree-based variant extends the original Dual Contouring algorithm by using a hierarchical grid structure to allow adaptive refinement, addressing the inefficiency of uniform grids for sparse data [S3, unofficial]. It builds on the original Dual Contouring algorithm [778-dual-contouring.md] and incorporates techniques from manifold dual contouring to ensure topological correctness [S6, unofficial].
