# MLS Projection

Also called: MLS projection via Hermite Point Set Surfaces, Moving Least Squares Surface, Parabolic Case Triangulation

## Overview
MLS Projection is an iterative algorithm that projects a query point onto a surface defined by a point set with associated normals (Hermite data) using Moving Least Squares [S2, unofficial]. It computes a local quadratic polynomial approximation weighted by neighbor distances to find the new point position and normal [S2, unofficial]. The method smooths noisy input data by evaluating the fitted polynomial at the query point, making it suitable for surface reconstruction from unstructured point clouds [S3]. Unlike grid-based isosurface extractors, it operates directly on point sets, often serving as a projection step in hybrid pipelines that combine point-set fitting with grid-based mesh extraction [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of points `inputPositions` with associated normals `inputNormals`, a query point `inputPoint`, a number of nearest neighbors `knn`, a kernel radius `radius`, a kernel type `kernel_type`, and a maximum number of iterations `numberOfIterations` [S2, unofficial].
*   **Output:** A projected point `outputPoint` on the surface and its corresponding normal `outputNormal` [S2, unofficial].

**Data Structures:**
*   **Point Set:** Two arrays of 3D vectors, `inputPositions` and `inputNormals`, indexed by integer IDs [S2, unofficial].
*   **K-D Tree:** A spatial index (`inputPointsetKdTree`) built on `inputPositions` to support $k$-nearest neighbor queries [S2, unofficial].
*   **Accumulators:** Floating-point scalars and 3D vectors used to store weighted sums during the fitting process [S2, unofficial].

**Parameters:**
*   $knn$: Number of nearest neighbors. Default: 20 [S2, unofficial].
*   $radius$: Radius for the kernel function [S2, unofficial].
*   $kernel\_type$: Selector for the kernel function (0=Gaussian, 1=Wendland, 2=Singular) [S2, unofficial].
*   $numberOfIterations$: Loop count for convergence [S2, unofficial].

**Step-by-Step Method:**
1.  **Initialization:** Set `outputPoint = inputPoint` [S2, unofficial].
2.  **Iteration Loop:** For $iter$ from 0 to $numberOfIterations - 1$:
    a.  **Neighbor Search:** Find the $knn$ nearest neighbors of `outputPoint` in the point set using the K-D tree. Retrieve their indices `id_nearest_neighbors` and squared distances `square_distances_to_neighbors` [S2, unofficial].
    b.  **Accumulator Initialization:** Initialize accumulators: `sum_weight = 0.0`, `sum_1 = 0.0`, `sum_2 = (0,0,0)`, `sum_3 = (0,0,0)`, `sum_4 = 0.0` [S2, unofficial].
    c.  **Weighted Accumulation:** For each neighbor $i$ from 0 to $knn-1$:
        *   Get neighbor position `neighbor = inputPositions[id_nearest_neighbors[i]]` [S2, unofficial].
        *   Get neighbor normal `neighborNormal = inputNormals[id_nearest_neighbors[i]]` [S2, unofficial].
        *   Compute weight $w = K(\sqrt{square\_distances\_to\_neighbors[i]}, radius, kernel\_type)$, where $K$ is the kernel function (see Kernel Functions for MLS) [S2, unofficial].
        *   Update accumulators:
            *   `sum_1 += w * dot(neighbor, neighborNormal)` [S2, unofficial].
            *   `sum_2 += w * neighbor` [S2, unofficial].
            *   `sum_3 += w * neighborNormal` [S2, unofficial].
            *   `sum_weight += w` [S2, unofficial].
            *   `sum_4 += w * dot(neighbor, neighbor)` [S2, unofficial].
    d.  **Polynomial Coefficient Calculation:** Solve for the coefficients of the local quadratic approximation $f(x) = u_0 + u_{123} \cdot x + u_4 (x \cdot x)$:
        *   $u_4 = 0.5 \cdot \frac{sum\_1 - \frac{sum\_2 \cdot sum\_3}{sum\_weight}}{sum\_4 - \frac{sum\_2 \cdot sum\_2}{sum\_weight}}$ [S2, unofficial].
        *   $u_{123} = \frac{sum\_3 - 2 \cdot u_4 \cdot sum\_2}{sum\_weight}$ [S2, unofficial].
        *   $u_0 = -\frac{sum\_2 \cdot u_{123} + u_4 \cdot sum\_4}{sum\_weight}$ [S2, unofficial].
    e.  **Normal and Position Update:**
        *   Compute the gradient (normal) at the current point: `outputNormal = u123 + 2 * u4 * outputPoint` [S2, unofficial].
        *   Normalize `outputNormal` [S2, unofficial].
        *   Compute the function value and step: `diff = (u0 + dot(u123, outputPoint) + u4 * dot(outputPoint, outputPoint)) * outputNormal` [S2, unofficial].
        *   Update point: `outputPoint = outputPoint - diff` [S2, unofficial].
3.  **Final Output:** Return `outputPoint` and `outputNormal` [S2, unofficial].

**Parabolic Case Handling:**
If the local quadratic form has one zero eigenvalue ($\lambda_1 > 0, \lambda_2 = 0$), the surface is parabolic [S1, unofficial]. The transformation from canonical form $p(\bar{x}, \bar{y}) = \bar{x}^2$ to the function $f$ is given by:
$$ \begin{pmatrix} x \\ y \end{pmatrix} = \begin{pmatrix} \frac{1}{\sqrt{\lambda_1}} e_{11} & 0 \\ \frac{1}{\sqrt{\lambda_1}} e_{12} & 0 \end{pmatrix} \begin{pmatrix} \bar{x} \\ \bar{y} \end{pmatrix} $$
where $e_1 = (e_{11}, e_{12})$ is the first normalized eigenvector [S1, unofficial]. The error profile for a line segment is determined by its projection onto $e_1$, with length at most $\sqrt{4\epsilon/\lambda_1}$ [S1, unofficial]. Vertices are placed below the surface by $\epsilon$ if $\lambda_1 > 0$, or above if $\lambda_1 < 0$ [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Degenerate Neighbors:** If neighbors are collinear or coplanar, the least squares system may be singular [G]. A small regularization term or fallback to a simpler projection should be used.
*   **Precision:** The calculation of $u_4$ involves division by a difference of sums, which can suffer from catastrophic cancellation if the point set is very uniform [G]. Use double precision for accumulators.
*   **Boundary:** Points near the boundary of the point set have fewer neighbors, potentially leading to biased normals [S2, unofficial].

**Pseudocode (Python-like):**
```python
import numpy as np

def get_kernel(kernel_type, r, h, w=2.0):
    if kernel_type == 0:  # Gaussian
        return np.exp(-(r**2) / (h**2))
    elif kernel_type == 1:  # Wendland
        if r < h:
            return (1 - r/h)**4 * (1 + 4*r/h)
        return 0.0
    elif kernel_type == 2:  # Singular
        return (r/h)**(-w)
    return 1.0

def mls_projection(input_point, input_positions, input_normals, kdtree, 
                   knn=20, radius=1.0, kernel_type=0, num_iterations=10):
    """
    Projects input_point onto the surface defined by input_positions/normals.
    """
    output_point = np.array(input_point, dtype=float)
    
    for _ in range(num_iterations):
        # 1. Find neighbors
        indices, sq_dists = kdtree.knearest(output_point, knn)
        
        sum_weight = 0.0
        sum_1 = 0.0
        sum_2 = np.zeros(3)
        sum_3 = np.zeros(3)
        sum_4 = 0.0
        
        for i in range(knn):
            idx = indices[i]
            p_i = input_positions[idx]
            n_i = input_normals[idx]
            r = np.sqrt(sq_dists[i])
            
            w = get_kernel(kernel_type, r, radius)
            
            sum_weight += w
            sum_1 += w * np.dot(p_i, n_i)
            sum_2 += w * p_i
            sum_3 += w * n_i
            sum_4 += w * np.dot(p_i, p_i)
            
        # 2. Solve for coefficients
        denom_u4 = sum_4 - np.dot(sum_2, sum_2) / sum_weight
        if abs(denom_u4) < 1e-9:
            break  # Degenerate case
            
        u4 = 0.5 * (sum_1 - np.dot(sum_2, sum_3) / sum_weight) / denom_u4
        u123 = (sum_3 - 2 * u4 * sum_2) / sum_weight
        u0 = -(np.dot(sum_2, u123) + u4 * sum_4) / sum_weight
        
        # 3. Update point and normal
        output_normal = u123 + 2 * u4 * output_point
        norm_len = np.linalg.norm(output_normal)
        if norm_len < 1e-9:
            break
        output_normal = output_normal / norm_len
        
        diff = (u0 + np.dot(u123, output_point) + u4 * np.dot(output_point, output_point)) * output_normal
        output_point = output_point - diff
        
    return output_point, output_normal
```

## Subtopics

### [APSS (Approximate Projected Point Set Surfaces)](843-apss-approximate-projected-point-set-surfaces.md)
APSS is an iterative method that builds on MLS Projection by computing a local coordinate system and higher-order approximations via weighted accumulators, explicitly tracking cross-product and dot-product terms for refined surface fitting. It is chosen when higher-order smoothness or more accurate normal estimation is required compared to standard MLS, at the cost of increased computational complexity per iteration [G].

### [Moving Least Squares Implicit Surface Reconstruction](5328-moving-least-squares-implicit-surface-reconstruction.md)
This technique reconstructs a surface from an unordered 3D point cloud by creating an implicit function field using MLS, from which isosurfaces are extracted. It differs from explicit reconstruction methods by defining the surface as a zero-level set of a scalar field, allowing robust handling of noisy data and topological changes without requiring explicit connectivity [G]. It is used when a continuous implicit representation is needed for further processing (e.g., CSG operations or volume rendering) rather than just a mesh [G].

### Kernel Functions for MLS
A set of kernel functions used to weight neighbors in MLS surface reconstruction based on distance $r$ and scale $h$ [S2, unofficial].
*   **Gaussian ($kernel\_type=0$):** $K(r) = e^{-r^2/h^2}$ [S2, unofficial].
*   **Wendland ($kernel\_type=1$):** $K(r) = (1 - r/h)^4 (1 + 4r/h)$ for $r < h$, else 0 [S2, unofficial].
*   **Singular ($kernel\_type=2$):** $K(r) = (r/h)^{-w}$ [S2, unofficial].
The choice affects the smoothness and locality of the fit; Gaussian is smooth but infinite support (truncated by radius), Wendland has compact support, and Singular can handle specific noise characteristics but may be unstable [G].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot k \cdot I)$ per query point, where $N$ is the number of neighbors retrieved, $k$ is the number of neighbors ($knn$), and $I$ is the number of iterations [G]. With a K-D tree, neighbor search is $O(\log N_{total})$ [G].
*   **Memory Complexity:** $O(N_{total})$ to store the point set and K-D tree [G].
*   **Performance:** Measured on a PC with dual-core AMD Opteron 2.25GHz, 4GB RAM [S3]. Performance scales with point density and the number of iterations [G].
*   **Strengths:** Robust to noise, handles unstructured data, produces smooth surfaces [G].
*   **Limitations:** Computationally expensive for dense point sets or high iteration counts; sensitive to the choice of radius and kernel; degenerate configurations (collinear points) can cause instability [G].
*   **When to use:** When input data is a noisy point cloud with normals, and a smooth implicit field or high-quality mesh is required [G].
*   **When not to use:** For real-time applications with very large datasets where speed is critical, or when the input is already a well-structured grid (use Marching Cubes or Dual Contouring directly) [G].

## Background
MLS Projection originated from the Moving Least Squares method for surface reconstruction from point clouds [S3]. It was adapted for Hermite Point Set Surfaces (HPSS) to handle point sets with normals, providing a robust way to project points onto the implicit surface defined by the data [S2, unofficial]. The method appears in multiresolution modeling frameworks where it is combined with grid-based mesh extraction techniques like Dual Contouring [S2, unofficial]. The parabolic case handling was detailed in multiresolution modeling literature to ensure correct triangulation of cluster regions [S1, unofficial].
