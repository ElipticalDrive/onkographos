# Parallel SurfaceNets


## Overview
Parallel SurfaceNets (PSN) is a high-performance, parallel discrete isocontouring algorithm that extracts a surface mesh from volumetric scalar fields, specifically segmented label maps [S1, unofficial]. It addresses the limitations of sequential algorithms like Marching Cubes (MC) and the memory bottlenecks of incremental allocation by using a four-pass parallel approach with computational edge trimming and pre-allocated output arrays [S1, unofficial]. Unlike MC, which produces duplicated polygons between adjacent labeled regions, PSN produces a mesh where boundaries between extracted objects are fully shared, and it extracts multiple segmented objects in a single execution rather than requiring separate passes per label [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A structured volumetric scalar field with scalar values $s_{i,j,k}$ associated with lattice points. The field contains a set of labeled regions $L$ and a background label $B$ (any scalar value not in $L$) [S1, unofficial].
*   **Output:** A triangular mesh representing the isosurfaces for all labels in $L$, with points and triangles fully shared between neighboring objects [S1, unofficial].

**Data Structures:**
1.  **Voxel Triad ($t_{i,j,k}$):** An 8-bit unsigned char associated with each voxel cell $v_{i,j,k}$. It stores 5 bits of classification information:
    *   1 bit: Scalar classification (inside labeled region $L$ or background $B$) [S1, unofficial].
    *   3 bits: Whether the x, y, and z voxel edges emanating from the cell origin intersect the isosurface [S1, unofficial].
    *   1 bit: Whether the voxel cell produces an output point (PRODUCE POINT bit) [S1, unofficial].
    *   The volume of triads is padded by one triad in each $\pm x, \pm y, \pm z$ direction, resulting in dimensions $(M+2) \times (N+2) \times (O+2)$ for a volume of size $M \times N \times O$ [S1, unofficial].
2.  **Volume X-Edge Metadata:** A 2D array of size $(N+2) \times (O+2)$ allocated for each padded volume x-edge $E_{j,k}$. It stores five values:
    *   Number of output points.
    *   Number of quadrilaterals.
    *   Number of smoothing stencil edges.
    *   IDs controlling output write positions (after prefix sum).
    *   Edge trim (starting and ending voxels along the row) [S1, unofficial].

**Algorithm Steps:**

**Pass 1: Process Volume X-Edges**
For each volume x-edge $E_{j,k}$, process independently and in parallel:
1.  Visit all voxel x-edges $e_{i,j,k}$ composing $E_{j,k}$.
2.  Mark edges where the interval intersects the isosurface $Q_i$.
3.  Determine the left and right trim positions $x_{L_{j,k}}$ and $x_{R_{j,k}}$, and the number of x-intersections along $E_{j,k}$ [S1, unofficial].
4.  Gather classification information for each triad (whether $s_{i,j,k} \in L$ or $s_{i,j,k} \in B$) [S1, unofficial].

**Pass 2: Process Y- and Z-Voxel-Cell Edges**
For each volume cell row $V_{j,k}$, process independently and in parallel:
1.  Visit triads between the trim interval $[x_{L_{j,k}}, x_{R_{j,k}})$ [S1, unofficial].
2.  Intersect y- and z-triad edges against $Q_i$.
3.  Adjust the trim interval to produce a final trim interval $[\bar{x}_{L_{j,k}}, \bar{x}_{R_{j,k}})$ based on classification [S1, unofficial].
4.  Use classification from Pass 1 to accelerate checks: if voxel edge endpoints $s_0, s_1$ are both in background $B$, no edge intersection exists [S1, unofficial].
    *   *Edge Case:* If the initial x-edge trim is empty but contours intersect only y- and/or z-cell edges, Pass 2 adjusts the trim to include these intersections [S1, unofficial].

**Pass 3: Configure Output**
For each voxel row $V_{j,k}$, process independently and in parallel:
1.  Compute the voxel edge case number $c_{e_{i,j,k}}$ by combining eight voxel triads forming the voxel cell $v_{i,j,k}$ [S1, unofficial].
2.  If $c_{e_{i,j,k}} = 0$, no point is generated. Otherwise, a point and smoothing stencil are produced. If any triad edges are intersected, a quadrilateral polygon is produced [S1, unofficial].
3.  Record the number of output points, quadrilaterals, and smoothing stencil edges as per-edge metadata [S1, unofficial].
4.  **Race Condition Avoidance:** Process voxel cell rows $V_{j,k}$ in a 2x2 checkerboard pattern. Group edges $E_{j,k}$ into bundles of four neighbors numbered 0-3. Process all edges numbered $n$ in order using four total threaded processing loops. This ensures no $t_{i,j,k}$ is modified (specifically the PRODUCE POINT bit) during the processing of that specific number, avoiding data races [S1, unofficial].
5.  Update metadata via a prefix sum operation to produce an indexing mapping input data to output primitives [S1, unofficial].
6.  Precisely allocate memory for output based on the prefix sum results [S1, unofficial].

**Pass 4: Generate Output**
For each $V_{j,k}$, process in parallel:
1.  Initialize a voxel row edge iterator with point IDs from the prefix sum operation [S1, unofficial].
2.  Advance point IDs along $V_{j,k}$ and immediate neighbors in $\pm j$ and $\pm k$ directions using a 3x3 iteration kernel [S1, unofficial].
3.  Query the PRODUCE POINT bit in $t_{i,j,k}$ for each of the nine voxel triads in the kernel; if set, increment the point ID [S1, unofficial].
4.  Use these IDs to define voxel center points, up to three quadrilaterals, and smoothing stencil edges [S1, unofficial].
5.  Write directly into pre-allocated output arrays without mutexes or locks [S1, unofficial].

**Smoothing Step:**
1.  Implement constrained Laplacian smoothing in parallel using double-buffering to avoid data races [S1, unofficial].
2.  Create two arrays of points $P_0$ and $P_1$. Initialize $P_0$ with output points from surface extraction [S1, unofficial].
3.  Compute $P_1$ from $P_0$ using the smoothing stencil. The position update is:
    $$ p_i = p_i + \lambda \Delta p_j $$
    where
    $$ \Delta p_j = \frac{1}{N} \sum_{j=0}^N (p_j - p_i) $$
    Here, $p_i$ is the current point position, $\lambda$ is the convergence factor, $N$ is the number of connected points in the stencil, and $p_j$ are the positions of the connected points [S1, unofficial].
4.  The total motion of $p_i$ is constrained relative to its generating voxel cell (e.g., via a constraint sphere centered at the voxel center) [S1, unofficial].
5.  Swap $P_0$ and $P_1$ and repeat. Typically 25 iterations are used [S1, unofficial].

**Triangulation Step:**
1.  Triangulate the mesh quadrilaterals in parallel by generating two triangles from each quadrilateral [S1, unofficial].
2.  Select the tessellating diagonal using methods such as greedy, shortest diagonal, minimum area, or most co-planar [S1, unofficial].

**Parameters:**
*   **Smoothing Iterations:** Typically 25 [S1, unofficial].
*   **Lambda ($\lambda$):** Convergence factor controlling motion amount [S1, unofficial].
*   **Threads:** Performance evaluated with 1, 2, 4, 8, and 16 threads [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Pathological Trims:** Initial x-edge trim may be empty if contours intersect only y- and/or z-cell edges. Pass 2 adjusts the trim interval to handle this [S1, unofficial].
*   **Data Races:** Setting the PRODUCE POINT bit in $t_{i,j,k}$ during threaded processing of neighboring voxel rows causes race conditions. Solved by 2x2 checkerboarding and processing edges by number (0-3) in separate loops [S1, unofficial].
*   **Memory Limits:** Large volumes (e.g., $2048^3$) can exceed main memory (e.g., 64 GB) due to billions of points/quads/stencils. PSN allows extraction of subsets of labeled regions to mitigate this [S1, unofficial].
*   **Memory Bus Saturation:** Parallel efficiency falls rapidly from 8 to 16 threads on 10-core CPUs due to high generation rates of output primitives impacting the memory bus [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Scalar classification is $O(1)$ for a single label ($N=1$) using cache, $O(N)$ for intermediate labels, and $O(\log(N))$ for large $N$ using a set [S1, unofficial]. The overall algorithm is parallelized over volume edges.
*   **Memory Complexity:** Requires pre-allocation of output arrays based on prefix sums. Memory usage scales with the number of output primitives. Large volumes may require significant RAM [S1, unofficial].
*   **Performance:** PSN is typically one to two orders of magnitude faster than sequential algorithms like MC on commodity CPU hardware [S1, unofficial].
    *   On the Allen Mouse Brain Atlas, PSN achieved a 312x speedup over MC [S1, unofficial].
    *   On the Connectome dataset (240 labels), PSN (16 threads) achieved a 37.95x speedup over MC (9.98s vs 378.60s) [S1, unofficial].
    *   On the Torso dataset, PSN (16 threads) achieved a 125.81x speedup over MC (0.405s vs 51.000s) [S1, unofficial].
*   **Strengths:**
    *   Fully shared boundaries between neighboring objects (no duplicate points/triangles) [S1, unofficial].
    *   Single execution for multiple labels [S1, unofficial].
    *   No incremental memory allocation or mutexes [S1, unofficial].
    *   Scalable via task stealing (e.g., TBB) [S1, unofficial].
*   **Limitations:**
    *   Assumes non-manifold surfaces (multiple materials can join in a single voxel) [S1, unofficial].
    *   Memory bus saturation at high thread counts on limited core hardware [S1, unofficial].
    *   Performance is sensitive to the number of labels and output density [S1, unofficial].
*   **When to Use:** Ideal for parallel extraction of discrete, segmented label maps where shared boundaries and high performance are required, especially on multi-core CPUs [S1, unofficial].
*   **When Not to Use:** When manifold surfaces are strictly required and the number of labels is small (FE may be faster) [S1, unofficial]. When memory is severely constrained for very large volumes without subsetting [S1, unofficial].

## Background
Parallel SurfaceNets was developed by Will Schroeder, Spiros Tsalikis, and others at Kitware and Brigham and Women's Hospital, building on the original SurfaceNets algorithm by Frisken (Multi-Material workflow) and concepts from the Flying Edges algorithm [S1, unofficial]. It was designed to address the inefficiencies of sequential discrete isocontouring methods like Marching Cubes when applied to large-scale medical and biological data, such as connectomics and anatomical atlases [S1, unofficial]. The algorithm is implemented in the Visualization Toolkit (VTK) as `vtkSurfaceNets3D` and used in software like 3D Slicer [S1, unofficial].
