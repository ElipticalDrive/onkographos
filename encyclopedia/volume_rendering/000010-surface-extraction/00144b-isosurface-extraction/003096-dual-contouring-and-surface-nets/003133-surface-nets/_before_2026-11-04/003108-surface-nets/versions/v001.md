# Surface Nets


## Overview
Surface Nets is a method to construct triangle meshes representing the surface of 3D scalar fields by associating intersection points with voxels and averaging them [S1, unofficial]. It differs from Marching Cubes by producing a single vertex per voxel (or per active voxel) rather than multiple vertices per cube, resulting in a more compact mesh with fewer triangles, though potentially less geometric fidelity at complex topologies [S1, unofficial].

## How it works
**Inputs:** A 3D scalar field (volume), an isosurface threshold value (`isoLevel`), and the voxel grid dimensions.
**Outputs:** A triangle mesh (vertices and indices) representing the isosurface.

**Data Structures:**
*   `voxelPoints`: A hash map mapping integer voxel coordinates (`Int3`) to summed float positions (`Float3`).
*   `voxelNumActiveEdges`: A hash map mapping integer voxel coordinates (`Int3`) to integer edge counts (`Integer`).
*   `edgeStartCoords`: A list of integer coordinates (`Int3`) storing the start coordinate of each intersected edge.
*   `edgeAxes`: A list of integers storing the axis index (0 for X, 1 for Y, 2 for Z) of each intersected edge.
*   `edgesPositiveDir`: A list of booleans storing the exterior status of the start point of each intersected edge.

**Steps:**

1.  **Initialize Data Structures:** Create empty `voxelPoints`, `voxelNumActiveEdges`, `edgeStartCoords`, `edgeAxes`, and `edgesPositiveDir` structures.
2.  **Iterate Voxels and Edges:** Loop over voxel grid coordinates $x, y, z$ from $0$ to $width/height/depth-1$. (Note: Source [S1, unofficial] mentions -1 to width-1, but standard voxel iteration is 0 to N-1; the logic below assumes standard 0-indexed grid access). For each voxel, get the start position `pStart` and scalar value `dStart`. Determine exterior status `pStartExterior = (dStart < isoLevel)`.
3.  **Process Positive Axes:** Loop over the 3 positive axes (X, Y, Z). For each axis, calculate the end coordinate `endCoord` by adding the axis offset to `pStart`. Get the end value `dEnd` and exterior status `pEndExterior = (dEnd < isoLevel)`.
4.  **Check Intersection:** If `pEndExterior != pStartExterior`, the edge intersects the surface.
    *   Compute the intersection point `vertex` using linear interpolation:
        $$ t = \frac{isoLevel - d_0}{d_1 - d_0} $$
        $$ vertex = p_0 + t(p_1 - p_0) $$
        where $p_0$ and $p_1$ are the endpoints of the edge, and $d_0, d_1$ are their scalar values. If $|d_1 - d_0| \le 0.00001$, return $p_0$ [S1, unofficial].
    *   Identify the 4 neighboring voxels sharing this edge using predefined `edgeNeighbourOffsets`.
    *   For each neighbor voxel coordinate `voxelCoord`:
        *   Add `vertex` to `voxelPoints[voxelCoord]`.
        *   Increment `voxelNumActiveEdges[voxelCoord]`.
    *   Store edge metadata: append `pStart` to `edgeStartCoords`, the axis index to `edgeAxes`, and `pStartExterior` to `edgesPositiveDir`.
5.  **Average Vertex Positions:** After processing all voxels and edges, iterate through `voxelPoints`. For each key, multiply the summed position by $1.0 / voxelNumActiveEdges.get(key)$ to get the averaged vertex position for that voxel [S1, unofficial].
6.  **Construct Quads:** Iterate through the stored edges.
    *   Determine the 4 voxel coordinates surrounding the edge based on the edge axis. These coordinates define the corners of a quad.
    *   Retrieve the averaged vertex positions for these 4 voxel coordinates.
    *   Construct a quad face. If `edgesPositiveDir` is true, use vertex order (0,1,2,3); otherwise, use (0,3,2,1) to ensure correct orientation [S1, unofficial].
    *   (Note: The source describes constructing a "quad face". Standard Surface Nets typically splits quads into two triangles. The source mentions `addQuadFace`, implying a quad primitive or immediate splitting. For a triangle mesh output, split the quad into two triangles.)

**Pseudocode:**

    edge_positive_dirs = [] # List[bool]

            return volume[x, y, z]

    # Step 1: Iterate voxels and edges

                d_start = get_value(x, y, z)
                if d_start is None: continue # Skip out-of-bounds if necessary [G]
                
                p_start_exterior = d_start < iso_level

                # Loop over 3 positive axes
                axes = [(1, 0, 0), (0, 1, 0), (0, 0, 1)]
                for axis_idx, (dx, dy, dz) in enumerate(axes):
                    end_x = x + dx
                    end_y = y + dy
                    end_z = z + dz

**Parameters:**
*   Precision threshold for division by zero check: $0.00001$ [S1, unofficial].
*   Precision threshold for diagonal length comparison: $0.0001$ [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Boundary Conditions:** The source iterates from -1 to width-1, which is non-standard. Standard implementation should handle boundaries by either clamping, reflecting, or skipping edges that go out of bounds. The pseudocode above skips out-of-bounds edges [G].
*   **Degenerate Cases:** If $d_1 - d_0$ is very small, the intersection calculation becomes unstable. The threshold $0.00001$ is used to handle this [S1, unofficial].
*   **Voxel Connectivity:** The method assumes a regular grid. Irregular grids require different neighbor lookup logic.

## Subtopics

### Marching Cubes Surface Point Extraction
Generates vertices by interpolating along edges based on the cube index. It produces more vertices per voxel than Surface Nets, leading to higher geometric accuracy but more triangles. Choose when fidelity is critical and performance is less constrained. [Marching Cubes Surface Point Extraction](6417-marching-cubes-surface-point-extraction.md)

### Marching Cubes Vertex List Generation
The parent method that generates the list of vertices for the polygon(s) inside a voxel based on the cube index. Surface Nets builds on this by averaging these points across voxels. [Marching Cubes Vertex List Generation](4447-marching-cubes-vertex-list-generation.md)

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of voxels, as each voxel and its edges are processed once.
*   **Memory Complexity:** $O(V)$ where $V$ is the number of active voxels, for storing `voxelPoints` and `voxelNumActiveEdges`.
*   **Performance:** The source provides timing statistics for "Surface generation time" but does not give specific numbers for Surface Nets alone, only as part of a larger application [S1, unofficial].
*   **Strengths:** Produces a mesh with fewer triangles than Marching Cubes, as each voxel contributes at most one vertex (and thus one quad/two triangles) instead of multiple.
*   **Limitations:** Can produce artifacts or inaccuracies in regions with complex topology or high curvature, as the single averaged vertex may not lie exactly on the true isosurface.
*   **When to Use:** When mesh compactness is important and the scalar field is relatively smooth.
*   **When Not to Use:** When high geometric accuracy is required, or the scalar field has sharp features.

## Background
Surface Nets was introduced as an alternative to Marching Cubes to reduce the number of triangles in the resulting mesh. It is often used in real-time applications where performance is critical. The method is described in the context of an open-source project for isosurface extraction [S1, unofficial].
