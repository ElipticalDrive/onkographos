# JSurfaceNets

Also called: Constrained Elastic Surface Nets, Naive Surface Nets, Smooth Mesh Generation, Surface Nets Smooth Mesh, SurfaceNets (JSurfaceNets variant)

## Overview
JSurfaceNets is a dual isosurface extraction algorithm that generates a quad-mesh by placing one vertex per surface-crossing grid cell at the centroid of its edge intersections, serving as a faster, lower-polygon alternative to Marching Cubes [S1][S3, unofficial]. Unlike the original Constrained Elastic Surface Nets which uses iterative energy minimization, this variant computes vertex positions analytically via linear interpolation, producing organic-looking meshes with significantly fewer primitives while maintaining topological correctness for scalar fields [S1][S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar field `data` of dimensions `dims = [width, height, depth]`. The isosurface is implicitly defined at value 0 (values < 0 are "inside", > 0 are "outside") [S1].
*   **Output:** A `Mesh` object containing a list of vertex coordinates (`vertices`) and a list of quad face indices (`faces`) [S1].

**Data Structures:**
1.  **`cube_edges`**: Static array of size 24, storing pairs of vertex indices for the 12 edges of a cube. Initialized by iterating `i` from 0 to 7 and `j` powers of 2, adding `(i, i^j)` if `i <= p` [S1].
2.  **`edge_table`**: Static array of size 256. For each mask `i`, it computes a bitmask `em` where bit `j/2` is set if the edge defined by `cube_edges[j]` and `cube_edges[j+1]` is crossed (signs of vertices differ) [S1].
3.  **`vertexBuffer`**: A dynamic integer array, resized to at least `R[2] * 2`. Stores vertex indices for the current and previous slices to facilitate quad generation [S1].
4.  **`R`**: Layout array for 1D indexing into `vertexBuffer`. `R[0]=1` (x stride), `R[1]=dims[0]+1` (y stride), `R[2]=±(dims[0]+1)*(dims[1]+1)` (z stride, toggles sign) [S1].
5.  **`vi_grid`** (Alternative Implementation): A `Vec<u32>` of size `size * size * size` (or `width * height * depth` for non-cubic grids), initialized to `u32::MAX`. `vi_grid[z * size * size + y * size + x]` stores the vertex index for the cell at `(x, y, z)` [S2, unofficial].

**Algorithm Steps:**

1.  **Initialization:**
    *   Initialize `cube_edges` and `edge_table` [S1].
    *   Initialize `vertexBuffer` with capacity `R[2] * 2` [S1].
    *   Initialize empty lists `vertices` and `faces` [S1].
    *   Initialize `buf_no = 1` and `R[2]` to positive value [S1].

2.  **Voxel Traversal (Phase 1 & 2):**
    Iterate through the grid cells $(x, y, z)$ where $0 \le x < width-1$, $0 \le y < height-1$, $0 \le z < depth-1$ [S1].
    
    *   **Cell Sampling:** Read the 8 corner values of the current cell. Compute the 8-bit `mask` where bit $k$ is set if `data[corner_k] < 0` [S1].
    *   **Early Termination:** If `mask == 0` or `mask == 0xFF`, the cell does not intersect the isosurface. Skip to the next cell [S1].
    *   **Vertex Placement:**
        *   Calculate `edge_mask = edge_table[mask]` [S1].
        *   Initialize sum vector `v = [0, 0, 0]` and counter `e_count = 0` [S1].
        *   For each edge $i$ from 0 to 11:
            *   If `!(edge_mask & (1 << i))`, continue [S1].
            *   Increment `e_count` [S1].
            *   Get edge endpoints $e_0, e_1$ from `cube_edges` [S1].
            *   Get scalar values $g_0, g_1$ at these endpoints [S1].
            *   Compute interpolation parameter $t$:
                $$ t = \frac{g_0}{g_0 - g_1} $$
                If $|g_0 - g_1| \le 10^{-6}$, skip this edge due to precision issues [S1].
            *   Accumulate the intersection point into `v`. For each axis $j \in \{0, 1, 2\}$:
                *   If the edge endpoints differ on bit $j$ (i.e., the edge crosses the axis $j$), add $t$ or $1-t$ to `v[j]` based on which endpoint is "inside" (bit 0) or "outside" (bit 1) [S1].
                *   If the edge is parallel to axis $j$, add the coordinate of the endpoint that is "inside" (0 or 1) to `v[j]` [S1].
        *   Compute the final vertex position relative to the cell origin:
            $$ P_{local}[j] = \frac{v[j]}{e\_count} $$
        *   The absolute vertex position is $P = (C + P_{local}) \times S + O$, where $C$ is the cell integer coordinates, $S$ is scale, and $O$ is offset [S1].
        *   Store this vertex in `vertices` and record its index.
        *   **Storage:**
            *   *Buffer Method:* Store the vertex index in `vertexBuffer` at the location determined by `R` and current $(x,y,z)$ [S1].
            *   *Grid Method:* Store the vertex index in `vi_grid[z * size * size + y * size + x]` [S2, unofficial].

3.  **Quad Generation (Phase 3):**
    Iterate through the grid edges that cross the surface [S2, unofficial].
    
    *   **Identify Cells:** For each crossing edge, identify the 4 cells sharing that edge [S2, unofficial].
    *   **Retrieve Indices:**
        *   *Buffer Method:* Retrieve vertex indices from `vertexBuffer` using the `R` layout for the 4 cells [S1].
        *   *Grid Method:* Retrieve indices from `vi_grid`. If any index is `u32::MAX`, skip (boundary check) [S2, unofficial].
    *   **Emit Quad:** If all 4 indices are valid, emit a quad connecting them [S2, unofficial].
    *   **Winding Order:** The order $(a,b,c,d)$ or $(d,c,b,a)$ is determined by the `mask` bit 1 (or the side of the edge that is solid) to ensure correct normal orientation [S1][S2, unofficial].
        *   *Specific Logic (Buffer Method):* For basis axis $i$, orthogonal axes $iu, iv$. If `mask & 1` is true, order is $(m, m-du, m-du-dv, m-dv)$. Else, order is $(m, m-dv, m-du-dv, m-du)$, where $m$ is the current buffer pointer and $du, dv$ are strides [S1].

4.  **Post-Processing (Optional):**
    *   **Laplacian Relaxation:** Apply Laplacian smoothing to vertex positions. For each vertex, compute the average position of its neighbors and move the vertex towards this average. Repeat for `iterations` (default 2) [S2, unofficial].
    *   **Normal Computation:** Compute smooth normals for each vertex based on the geometry of the emitted faces [S2, unofficial].

**Pseudocode:**

```python
def jsurfacenets(data, dims):
    width, height, depth = dims
    # Initialize static tables
    cube_edges = []
    for i in range(8):
        for j in [1, 2, 4]:
            p = i ^ j
            if i <= p:
                cube_edges.append((i, p))
                
    edge_table = [0] * 256
    for i in range(256):
        em = 0
        for j in range(0, 24, 2):
            a = bool(i & (1 << cube_edges[j][0]))
            b = bool(i & (1 << cube_edges[j][1]))
            if a != b:
                em |= (1 << (j // 2))
        edge_table[i] = em

    R = [1, width + 1, (width + 1) * (height + 1)]
    vertex_buffer = [0] * (R[2] * 2)
    vertices = []
    faces = []
    buf_no = 1
    R_z = R[2]

    for z in range(depth - 1):
        buf_no ^= 1
        R_z = -R_z
        R[2] = R_z
        m = 1 + (width + 1) * (1 + buf_no * (height + 1))

        for y in range(height - 1):
            m += 2
            for x in range(width - 1):
                # Read 8 corners and compute mask
                mask = 0
                grid_vals = [0.0] * 8
                idx = z * width * height + y * width + x
                g = 0
                for dz in range(2):
                    for dy in range(2):
                        for dx in range(2):
                            val = data[idx + dz * width * height + dy * width + dx]
                            grid_vals[g] = val
                            if val < 0:
                                mask |= (1 << g)
                            g += 1

                if mask == 0 or mask == 255:
                    continue

                edge_mask = edge_table[mask]
                v_sum = [0.0, 0.0, 0.0]
                e_count = 0

                for i in range(12):
                    if not (edge_mask & (1 << i)):
                        continue
                    e_count += 1
                    e0, e1 = cube_edges[i]
                    g0, g1 = grid_vals[e0], grid_vals[e1]
                    diff = g0 - g1
                    if abs(diff) <= 1e-6:
                        continue
                    t = g0 / diff

                    for axis in range(3):
                        bit_diff = (e0 ^ e1) & (1 << axis)
                        if bit_diff:
                            coord0 = (e0 >> axis) & 1
                            if coord0 == 0:
                                v_sum[axis] += t
                            else:
                                v_sum[axis] += (1.0 - t)
                        else:
                            if g0 < 0:
                                v_sum[axis] += ((e0 >> axis) & 1)
                            else:
                                v_sum[axis] += ((e1 >> axis) & 1)

                if e_count > 0:
                    v_avg = [v_sum[j] / e_count for j in range(3)]
                    pos = [x + v_avg[0], y + v_avg[1], z + v_avg[2]]
                    v_idx = len(vertices)
                    vertices.append(pos)
                    vertex_buffer[m] = v_idx

                    # Quad generation
                    for basis in range(3):
                        if not (edge_mask & (1 << basis)):
                            continue
                        iu = (basis + 1) % 3
                        iv = (basis + 2) % 3
                        if (iu == 0 and x == 0) or (iv == 0 and y == 0):
                            continue
                        du = R[iu]
                        dv = R[iv]
                        if mask & 1:
                            faces.append((vertex_buffer[m], vertex_buffer[m - du], vertex_buffer[m - du - dv], vertex_buffer[m - dv]))
                        else:
                            faces.append((vertex_buffer[m], vertex_buffer[m - dv], vertex_buffer[m - du - dv], vertex_buffer[m - du]))
                m += 1
    return vertices, faces
```

**Pitfalls:**
*   Without constraints, the energy minimization causes the surface net to shrink into a sphere and eventually collapse onto a single point [S1].
*   Can create non-manifold vertices, which may be a problem for some applications [S3, unofficial].
*   Boundary checks prevent invalid quad emission when accessing cells outside the grid bounds [S2, unofficial].
*   Precision guard `|g0 - g1| > 1e-6` prevents division by zero during interpolation [S1].

Extends JSurfaceNets to multi-label volumetric segmentations by storing material labels at cell corners and associating distinct labels with quad faces, preventing material blending at interfaces.

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of cells, as each cell is processed once and edges are traversed once [S3, unofficial].
*   **Memory Complexity:** $O(N)$ for storing vertex indices and the output mesh [S3, unofficial].
*   **Performance:** Faster than Marching Cubes and generates less than half as many facets (quads vs triangles) [S3, unofficial]. Performance is comparable to Marching Cubes for small geometries but wins on primitive count for complex isosurfaces [S3, unofficial].
*   **Strengths:** Simple implementation, fast execution, lower polygon count, organic appearance [S3, unofficial].
*   **Limitations:** Can create non-manifold vertices, which may be problematic for some applications [S3, unofficial].
*   **When to Use:** When a fast, low-poly quad-mesh is acceptable and the scalar field is smooth [S1][S3, unofficial].
*   **When Not to Use:** When manifold topology is strictly required or sharp features must be preserved without post-processing [S3, unofficial].

## Background
JSurfaceNets is based on the "Constrained Elastic Surface Nets" method proposed by Sarah Frisken Gibson in 1999 [S3, unofficial]. Gibson's original method formulated vertex placement as a global energy minimization problem using gradient descent [S3, unofficial]. The "Naive Surface Nets" variant, which JSurfaceNets implements, simplifies this by assuming trilinear interpolation and placing vertices at the center of mass of edge crossings [S3, unofficial]. This variant was popularized in online tutorials and JavaScript implementations (e.g., by Mikola Lysenko) as a simpler, faster alternative to Marching Cubes [S3, unofficial]. It is used in libraries like Mihosoft VRL for isosurface extraction and CSG operations [S1].
