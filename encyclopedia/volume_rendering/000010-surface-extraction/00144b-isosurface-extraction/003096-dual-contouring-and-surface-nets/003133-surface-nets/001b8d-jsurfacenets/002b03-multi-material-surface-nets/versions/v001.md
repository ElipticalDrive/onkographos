# Multi-Material Surface Nets

Also called: MMCellMap, Surface Nets for multi-label segmentations

## Overview
Multi-Material Surface Nets is an isosurface extraction algorithm that constructs closed, watertight quad-meshes from multi-label volumetric segmentations while preserving sharp boundaries between different materials [S1, unofficial]. It extends [JSurfaceNets](1040-jsurfacenets.md) by storing material labels at cell corners and associating labels with the top and bottom faces of generated quads, allowing distinct materials to share geometric boundaries without blending [S1, unofficial]. Unlike standard surface extraction methods that assume a single scalar field, this method operates directly on discrete label volumes, ensuring that interfaces between adjacent materials remain sharp and topologically consistent [S1, unofficial].

## How it works
**Inputs:** A 3D volumetric grid of integer labels (material IDs) with dimensions $N_x \times N_y \times N_z$, and a voxel size $v_x, v_y, v_z$.
**Outputs:** A set of vertices, a quad-mesh (list of quads), and per-quad material labels.

### Data Structures
The core data structure is `MMCellMap`, which manages the grid and extracted geometry [S1, unofficial].

**MMCellMap Layout:**
*   `m_arraySize[3]`: Integer array storing the dimensions of the *interior* grid $(N_x, N_y, N_z)$.
*   `m_voxelSize[3]`: Float array storing $(v_x, v_y, v_z)$.
*   `m_cellArray`: Pointer to an array of `Cell` structures. The array size is $(N_x+2) \times (N_y+2) \times (N_z+2)$ to accommodate padding.
*   `m_numVertices`: Integer count of extracted vertices.
*   `m_vertices`: Pointer to an array of `Vertex` structures.

**Cell Layout (stored in `m_cellArray`):**
*   `label` (`unsigned short`): The material label of the cell's bottom-left-back corner.
*   `flag` (`MMCellFlag`): A bitmask or struct indicating vertex type and face crossing types.
*   `vertexIndex` (`int`): Index into `m_vertices` if this cell contains a vertex, or -1 otherwise.
*   `vertexOffset[3]` (`float`): The local position of the vertex within the cell, relative to the cell's bottom-left-back corner. Values are in $[0, 1]$.

**Vertex Layout (stored in `m_vertices`):**
*   `cellIndex[3]`: The global integer index of the cell containing this vertex.
*   `position[3]`: The absolute world position of the vertex.

**Quad Output Layout:**
*   `quadCorners[12]`: Float array storing the 4 corner positions of the quad $(x_0, y_0, z_0, \dots, x_3, y_3, z_3)$.
*   `quadLabels[2]`: Integer array storing `[labelTopFaceOfQuad, labelBottomFaceOfQuad]`.

### Algorithm Steps

1.  **Initialization and Padding:**
    Allocate `m_cellArray` with dimensions $(N_x+2) \times (N_y+2) \times (N_z+2)$.
    Iterate over all cells. For interior cells $(1 \le i \le N_x, 1 \le j \le N_y, 1 \le k \le N_z)$, set `cell.label` to the input label at $(i-1, j-1, k-1)$. Set `cell.vertexOffset` to $(0, 0, 0)$.
    For boundary cells (indices 0 or $N+2$ in any dimension), set `cell.label` to a reserved padding label (e.g., `ReservedLabel::Padding`) and initialize offsets to $(0,0,0)$ [S1, unofficial].

2.  **Vertex Classification and Counting:**
    Iterate over all interior cells. Determine the `vertexType` for each cell based on edge crossings. A cell has a vertex if it contains an edge crossing between two different material labels.
    Count the total number of vertices `m_numVertices`.
    Allocate `m_vertices` array of size `m_numVertices`.
    Second pass: Assign a unique `vertexIndex` to each cell containing a vertex and store the cell's global index in the corresponding `Vertex` struct [S1, unofficial].

3.  **Relaxation (Fairing):**
    Perform `numRelaxIterations` iterations. In each iteration, update the position of each vertex to smooth the surface while preserving sharp features [S1, unofficial].
    
    For each vertex `idxVtx`:
    a. Retrieve the containing cell `pCell` and its global index `cellIdx[3]`.
    b. Initialize `avgP[3] = {0, 0, 0}` and `numNeighbors = 0`.
    c. If `pCell.flag.vertexType() == SurfaceVertex`:
       Iterate over the 6 faces of the cell (Left, Right, Bottom, Top, Front, Back).
       If `pCell.flag.faceCrossingType(face) != NoFaceCrossing`:
       Get the neighbor cell `nbrCell` and its global index `nbrIdx[3]`.
       Accumulate the neighbor's relative position:
       $$ avgP_x += nbrCell.vertexOffset_x + nbrIdx_x - cellIdx_x $$
       $$ avgP_y += nbrCell.vertexOffset_y + nbrIdx_y - cellIdx_y $$
       $$ avgP_z += nbrCell.vertexOffset_z + nbrIdx_z - cellIdx_z $$
       Increment `numNeighbors`.
    d. Else (if `vertexType` is not `SurfaceVertex`, implying a junction):
       Iterate over the 6 faces.
       If `pCell.flag.faceCrossingType(face) == JunctionFaceCrossing`:
       Get neighbor `nbrCell` and `nbrIdx`.
       Accumulate:
       $$ avgP_x += nbrCell.vertexOffset_x + nbrIdx_x - cellIdx_x $$
       $$ avgP_y += nbrCell.vertexOffset_y + nbrIdx_y - cellIdx_y $$
       $$ avgP_z += nbrCell.vertexOffset_z + nbrIdx_z - cellIdx_z $$
       Increment `numNeighbors`.
    e. If `numNeighbors > 0`:
       Average the accumulated positions:
       $$ avgP_x /= numNeighbors, \quad avgP_y /= numNeighbors, \quad avgP_z /= numNeighbors $$
       Update the vertex offset `p` (pointing to `pCell.vertexOffset`) using relaxation factor $\alpha$:
       $$ p_x = (1 - \alpha) p_x + \alpha \cdot avgP_x $$
       $$ p_y = (1 - \alpha) p_y + \alpha \cdot avgP_y $$
       $$ p_z = (1 - \alpha) p_z + \alpha \cdot avgP_z $$
       Constrain the position to the range $[0.5 - maxDist, 0.5 + maxDist]$ for each axis. If a coordinate is outside this range, clamp it to the nearest bound [S1, unofficial].

4.  **Quad Generation:**
    Iterate over all interior cells. For each edge of the cell that crosses between two different materials (isEdgeCrossing is true):
    a. Identify the two cells sharing this edge. Let them be `pCellFirst` and `pCellSecond`.
    b. Retrieve their labels: `pCellFirstLabel = pCellFirst.label`, `pCellSecondLabel = pCellSecond.label`.
    c. Identify the 4 cells surrounding this edge. These are the cells that share the edge or are adjacent to it in the plane perpendicular to the edge.
    d. Retrieve the vertices located in these 4 cells.
    e. Order the 4 vertices clockwise around the edge. The edge orientation convention is: Left-to-Right, Back-to-Front, Bottom-to-Top.
    f. Store the 4 vertex positions in `quadCorners[12]`.
    g. Store the material labels in `quadLabels[2]`:
       $$ quadLabels[0] = pCellFirstLabel $$
       $$ quadLabels[1] = pCellSecondLabel $$
       This assigns the label of the "first" cell to the top face of the quad and the "second" cell to the bottom face, preserving the material boundary [S1, unofficial].

*   `numRelaxIterations`: Number of relaxation iterations. Typical value: Not given in the sources.

### Edge Cases and Pitfalls
*   **Boundary Handling:** Boundary faces require padding to ensure closed shapes and sharp corners/edges at volume faces. This is handled by adding 2 to each dimension and filling padding cells with a reserved label [S1, unofficial].
*   **Precision:** Vertex positions are constrained to $[0.5 - maxDist, 0.5 + maxDist]$ to prevent them from drifting too far from the cell center, which could cause self-intersections or degenerate quads [S1, unofficial].
*   **Degenerate Input:** If the input volume has no edge crossings (e.g., a single uniform label), no vertices or quads are generated [S1, unofficial].

## Subtopics

### [OBJ Export for Multi-Label Surfaces](5824-obj-export-for-multi-label-surfaces.md)
Export as a set of surfaces, with each surface enclosing a single material. This variant generates separate OBJ files for each material label, allowing for individual rendering and manipulation of materials.

## Operating characteristics
*   **Time Complexity:** $O(N \cdot I)$, where $N$ is the number of cells and $I$ is the number of relaxation iterations. Quad generation is $O(N)$.
*   **Memory Complexity:** $O(N)$ for the cell array and vertex list.
*   **Measured Performance:** Not given in the sources.
*   **Strengths:** Preserves sharp boundaries between materials; generates watertight quad-meshes; simple to implement.
*   **Limitations:** Relies on relaxation which may smooth out fine details if parameters are not tuned; requires padding which increases memory usage by a factor of $(1+2/N)^3$.
*   **When to use:** Multi-label segmentations where sharp boundaries are important.
*   **When not to use:** Single-label volumes (use JSurfaceNets); volumes with very fine details that require more than relaxation to preserve.

## Background
Multi-Material Surface Nets was introduced by Sarah Frisken in 2022 in the paper "Surfacenets for multi-label segmentations with preservation of sharp boundaries" [S1, unofficial]. It extends the original Surface Nets algorithm to handle multiple material labels, addressing the need for sharp boundaries in medical imaging and other fields where multi-label segmentations are common.
