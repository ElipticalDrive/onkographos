# Dual Contouring Feature Point Iterative Projection

Also called: Feature Point Iterative Projection, Iterative Feature Point Projection

## Overview
This method computes the position of a single vertex (the "feature point") inside a voxel cell for Dual Contouring by iteratively projecting a point onto planes defined by intersecting edges and their normals [S1, S2, unofficial]. It solves the problem of finding a vertex that best represents the intersection of multiple surface constraints within a cell, avoiding the sharp corners or artifacts that can arise from simpler centroid-based placements [S1, S2, unofficial]. It differs from [Dual Contouring](778-dual-contouring.md) by using a fixed-iteration heuristic rather than solving a constrained least-squares system, and from [MLS Projection](823-mls-projection.md) by operating on planar constraints derived from edge intersections rather than local surface fitting [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A voxel cell (cube) with $k$ intersecting edges. For each intersecting edge $i$, the algorithm requires the edge midpoint $\mathbf{m}_i$ and the surface normal $\mathbf{n}_i$ at that midpoint. The normal $\mathbf{n}_i$ is typically normalized.
*   **Output:** A 3D point $\mathbf{c}$ representing the feature point vertex for the cell.

**Data Structures:**
*   **Plane:** Defined by a point (origin) $\mathbf{o}$ and a normal vector $\mathbf{n}$. The implicit equation is $\mathbf{n} \cdot (\mathbf{x} - \mathbf{o}) = 0$.
*   **Vector:** 3D floating-point vector $\mathbf{v} = (x, y, z)$.

**Parameters:**
*   **Iterations ($N$):** The number of projection steps. Sources use $N=5$ [S1, S2, unofficial].
*   **Step Size Factor ($\alpha$):** A multiplier for the averaged displacement vector. Sources use $\alpha = 0.7$ [S1, S2, unofficial]. Convergence may occur without scaling ($\alpha=1.0$), but scaling stabilizes the iteration [S1, S2, unofficial].

**Steps:**
1.  **Initialization:** Set the current point $\mathbf{c}$ to the center of the voxel cell [S1, S2, unofficial].
2.  **Plane Construction:** For each of the $k$ intersecting edges in the cell, create a plane $P_i$ where the origin is the edge midpoint $\mathbf{m}_i$ and the normal is the edge normal $\mathbf{n}_i$ [S1, S2, unofficial].
3.  **Iteration:** Repeat for $i = 0$ to $N-1$:
    a.  **Distance Calculation:** For each plane $P_j$ (where $j$ indexes the intersecting edges), calculate the signed distance from the current point $\mathbf{c}$ to the plane:
        $$ d_j = \mathbf{n}_j \cdot (\mathbf{c} - \mathbf{m}_j) $$
        [S1, S2, unofficial]
    b.  **Displacement Vector:** Calculate the shortest distance vector (displacement) for each plane:
        $$ \mathbf{v}_j = d_j \mathbf{n}_j $$
        [S1, S2, unofficial]
    c.  **Averaging:** Compute the average of all displacement vectors:
        $$ \mathbf{v}_{avg} = \frac{1}{k} \sum_{j=0}^{k-1} \mathbf{v}_j $$
        [S1, S2, unofficial]
    d.  **Update:** Update the point $\mathbf{c}$ by subtracting the averaged displacement vector scaled by $\alpha$:
        $$ \mathbf{c} \leftarrow \mathbf{c} - \alpha \mathbf{v}_{avg} $$
        [S1, S2, unofficial]
        *Note:* An equivalent formulation projects the point onto each plane individually and averages the projected points: $\mathbf{c}_{new} = \frac{1}{k} \sum_{j=0}^{k-1} (\mathbf{c} - d_j \mathbf{n}_j)$ [S1, S2, unofficial]. This is mathematically identical to the update rule above.

**Pseudocode:**
```python
def compute_feature_point(intersecting_edges, cell_center):
    """
    Computes the feature point for a voxel cell using iterative projection.
    
    Args:
        intersecting_edges: List of objects/tuples, each containing:
            - mid: Vector3 (edge midpoint)
            - normal: Vector3 (surface normal at midpoint, normalized)
        cell_center: Vector3 (center of the voxel)
        
    Returns:
        Vector3: The computed feature point
    """
    # Parameters
    iterations = 5
    alpha = 0.7
    
    # Initialize current point to cell center
    c = cell_center
    
    # Pre-convert edges to plane-like structures for clarity
    # Each plane is defined by origin (mid) and normal
    planes = []
    for edge in intersecting_edges:
        planes.append({
            'origin': edge.mid,
            'normal': edge.normal
        })
    
    num_planes = len(planes)
    
    # Iterative projection
    for _ in range(iterations):
        displacement_sum = Vector3(0, 0, 0)
        
        for plane in planes:
            # Calculate signed distance from c to plane
            # distance = dot(normal, c - origin)
            diff = c - plane['origin']
            distance = dot(plane['normal'], diff)
            
            # Calculate displacement vector: distance * normal
            displacement = plane['normal'] * distance
            displacement_sum += displacement
        
        # Average the displacement vectors
        avg_displacement = displacement_sum / num_planes
        
        # Update point: subtract scaled average displacement
        c = c - alpha * avg_displacement
        
    return c
```

**Edge Cases and Pitfalls:**
*   **Non-intersecting Planes:** The algorithm may fail or produce unstable results if the planes defined by the edge normals do not intersect in a common region [S1, S2, unofficial]. This can happen with noisy data or degenerate geometry.
*   **Direction of Update:** It is critical to *subtract* the averaged displacement vector. Adding it moves the point away from the intersection minimum [S1, S2, unofficial].
*   **Convergence:** While 5 iterations are suggested, the method is a heuristic. For highly curved surfaces, more iterations or a different solver (like the full Dual Contouring least-squares approach) may be needed [S1, S2, unofficial].
*   **Normal Consistency:** The normals must be consistently oriented (e.g., pointing out of the surface or towards the viewer) for the signed distance to correctly guide the point to the surface [S1, S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot k)$ per cell, where $N$ is the number of iterations and $k$ is the number of intersecting edges (typically 3 to 12 for a cube, but often 3-6 for simple features). This is very fast per cell.
*   **Memory Complexity:** $O(k)$ per cell to store plane data during computation. No global data structures are required beyond the grid.
*   **Performance:** Extremely fast and suitable for real-time applications [S1, S2, unofficial]. It avoids the overhead of solving linear systems.
*   **Strengths:** Simple to implement, robust for smooth surfaces, produces cleaner results than naive centroid placement [S1, S2, unofficial].
*   **Limitations:** Not guaranteed to converge to the optimal least-squares solution. Can produce artifacts if normals are inconsistent or if the surface has sharp features that are not well-represented by the edge midpoints [S1, S2, unofficial].
*   **When to Use:** When performance is critical and the surface is relatively smooth. When a quick approximation of the feature point is sufficient.
*   **When Not to Use:** When high-fidelity representation of sharp features is required (use full Dual Contouring [778-dual-contouring.md]). When normals are unreliable or noisy.

## Background
This method is a heuristic approach discussed in the context of implementing Dual Contouring for voxel-based games, particularly Minecraft-like environments [S1, S2, unofficial]. It was popularized in online game development forums as a simpler alternative to solving the constrained least-squares system required for optimal Dual Contouring [S1, S2, unofficial]. The specific iterative projection technique with a 0.7 step size was shared by community members to stabilize convergence [S1, S2, unofficial].
