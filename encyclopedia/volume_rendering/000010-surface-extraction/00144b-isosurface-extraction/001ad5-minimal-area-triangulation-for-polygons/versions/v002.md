# Minimal Area Triangulation for Polygons

Also called: Minimal Area Triangulation, Minimal Area Triangulation of Isopolygons, Polygon Triangulation

## Overview
Minimal Area Triangulation is a method for converting non-convex or complex 3D polygons (isopolygons) resulting from isosurface extraction into a set of triangles by minimizing the total surface area of the resulting mesh [S1, unofficial][S3, unofficial]. It solves the problem of generating a high-quality, artifact-free mesh from the closed loops extracted on the boundaries of convex octree nodes [S1, unofficial][S3, unofficial]. Unlike standard triangulation methods that may introduce self-intersections or excessive area, this method leverages the geometric property that isopolygons lie on the boundary of convex bodies to guarantee a homeomorphic-to-disk triangulation that is minimal in area [S1, unofficial][S3, unofficial]. It is distinguished from siblings like [Dual Contouring and Surface Nets](6319-dual-contouring-and-surface-nets.md) by its specific focus on optimal triangulation of the extracted polygonal contours rather than vertex placement or QEF optimization.

## How it works
**Inputs and Outputs:**
*   **Input:** A simple closed 3D polygon (isopolygon) $P = \{p_1, p_2, \dots, p_n\}$ defined by $n$ vertices in 3D space, where the vertices lie on the boundary of a convex body (e.g., an octree node) [S1, unofficial][S3, unofficial].
*   **Output:** A list of triangles forming the minimal area triangulation of $P$ [S1, unofficial][S3, unofficial].

**Data Structures:**
*   **Vertices:** An array of $n$ 3D points $p_i = (x_i, y_i, z_i)$.
*   **Dynamic Programming Table:** A 2D array `M` of size $n \times n$, where `M[i][j]` stores the minimal area of the sub-polygon defined by vertices from index $i$ to $j$ [S1, unofficial][S3, unofficial].
*   **Splitter Table:** A 2D array `K` of size $n \times n$, where `K[i][j]` stores the index $k$ that minimizes the recurrence relation for the sub-polygon $i, j$ [S1, unofficial][S3, unofficial].

**Formulas:**
Let $A(i, j, k)$ be the area of the triangle formed by vertices $p_i, p_j, p_k$. The area is calculated as half the magnitude of the cross product of two edge vectors:
$$ A(i, j, k) = \frac{1}{2} \| (p_j - p_i) \times (p_k - p_i) \| $$

Let $M(i, j)$ be the minimal area of the sub-polygon $P_{i,j}$ defined by vertices $p_i, \dots, p_j$. The recurrence is [S1, unofficial][S3, unofficial]:
$$
M(i, j) = 
\begin{cases} 
0 & \text{if } i = j \\
0 & \text{if } i = j + 1 \bmod n \\
\min_{k \in (j, i)} \{ M(i, k) + M(k, j) + A(i, j, k) \} & \text{otherwise}
\end{cases}
$$
Here, $k \in (j, i)$ denotes the set of vertices strictly between $j$ and $i$ in the cyclic order of the polygon [S1, unofficial][S3, unofficial].

**Algorithm Steps:**
1.  **Check for Cofacial Vertices:** Determine if all vertices of the polygon lie on the same cube face (are cofacial) [S2, unofficial].
    *   If **yes**: Perform a fan triangulation from the centroid to avoid introducing new edges on the cube face [S2, unofficial].
        *   Calculate the centroid $c = \frac{1}{n} \sum_{i=1}^n p_i$ [S2, unofficial].
        *   Create triangles $(p_i, p_{i+1}, c)$ for $i = 1 \dots n-1$ (with $p_{n+1} = p_1$) [S2, unofficial].
    *   If **no**: Proceed to dynamic programming [S2, unofficial].
2.  **Initialize DP Tables:** Initialize `M` and `K` arrays. Set `M[i][i] = 0` and `M[i][(i+1)%n] = 0` for all $i$ [S1, unofficial][S3, unofficial].
3.  **Compute Minimal Areas:** Iterate over the length of the sub-polygon `len` from 2 to $n-1$ [S1, unofficial][S3, unofficial].
    *   For each starting index `i` from 0 to $n-1$:
        *   Calculate ending index `j = (i + len) % n` [S1, unofficial][S3, unofficial].
        *   Initialize `min_val` to infinity and `best_k` to -1.
        *   Iterate over all possible split vertices `k` strictly between `j` and `i` in the cyclic order [S1, unofficial][S3, unofficial].
        *   Calculate `cost = M[i][k] + M[k][j] + A(i, j, k)` [S1, unofficial][S3, unofficial].
        *   If `cost < min_val`, update `min_val = cost` and `best_k = k` [S1, unofficial][S3, unofficial].
        *   Store `M[i][j] = min_val` and `K[i][j] = best_k` [S1, unofficial][S3, unofficial].
4.  **Reconstruct Triangles:** Start at the entry `M[0][n-1]` (or `M[1][2]` in 1-based indexing) [S1, unofficial][S3, unofficial].
    *   Use a recursive or iterative function `ExtractTriangles(i, j)`:
        *   If `j == (i + 1) % n`, return (base case, no triangle) [S1, unofficial][S3, unofficial].
        *   Let `k = K[i][j]` [S1, unofficial][S3, unofficial].
        *   Add triangle $(p_i, p_j, p_k)$ to the output list [S1, unofficial][S3, unofficial].
        *   Recursively call `ExtractTriangles(i, k)` and `ExtractTriangles(k, j)` [S1, unofficial][S3, unofficial].
5.  **Map Indices:** Map the triangle indices back to the original polygon vertex indices and add to the final triangle list [S2, unofficial].

    """Compute area of triangle defined by 3D points p1, p2, p3."""
    v1 = [p2[i] - p1[i] for i in range(3)]
    v2 = [p3[i] - p1[i] for i in range(3)]

            # The range (j, i) in cyclic order means starting from (j+1)%n up to (i-1+n)%n
            k = (j + 1) % n

        if j == (i + 1) % n:

        k = K[i][j]
        triangles.append((i, j, k))
        extract_triangles(i, k)
        extract_triangles(k, j)

    extract_triangles(0, n - 1)
    return triangles

**Parameters:**
*   **Isovalue:** Not directly used in triangulation, but determines the vertices of the isopolygon [30-isosurface-extraction.md].
*   **Octree Node Size:** Determines the scale of the isopolygon [S1, unofficial][S3, unofficial].

**Edge Cases and Pitfalls:**
*   **Cofacial Vertices:** If vertices lie on the same cube face, standard triangulation might create edges on the face, causing artifacts. Detected via `IsoVertex::CoFacial` and handled by fan triangulation from the centroid [S2, unofficial].
*   **Self-Intersections:** The method finds the minimal area *triangulation*, not necessarily the minimal area *surface*. Self-intersections are not theoretically guaranteed to be absent, though they are not observed in practice [S1, unofficial][S3, unofficial].
*   **Precision:** Floating-point errors in area calculations may affect the choice of $k$ in degenerate cases. [G] Use epsilon comparisons when checking `cost < min_val`.

## Subtopics

### [Merging Triangulations](3936-merging-triangulations.md)
Merging Triangulations is the final assembly step in hierarchical surface reconstruction methods that use adaptive clustering and piecewise polynomial approximation. It combines individual optimal triangulations generated for separate cluster regions into a single, watertight mesh by filling the gaps along cluster boundaries defined by a BSP tree hierarchy. Unlike methods that operate directly on raw data points, this approach exploits the connectivity of the clustering hierarchy to stitch pre-computed triangulations, ensuring that the resulting mesh approximates the underlying data within a prescribed error bound. It is distinguished from sibling methods by its reliance on a reverse-order subdivision process and its specific handling of boundary polygons to maintain geometric consistency across cluster interfaces.

## Operating characteristics
*   **Time Complexity:** $O(n^3)$, where $n$ is the number of vertices in the polygon [S1, unofficial][S3, unofficial].
*   **Space Complexity:** $O(n^2)$ for the caching arrays `M` and `K` [S1, unofficial][S3, unofficial].
*   **Strengths:** Produces a minimal area triangulation for isopolygons, reducing visual artifacts. It is well-suited for octree-based extraction where isopolygons are guaranteed to be simple closed curves on convex boundaries [S1, unofficial][S3, unofficial].
*   **Limitations:** Cubic time complexity makes it inefficient for polygons with a very large number of vertices. It does not guarantee a globally minimal area surface, only a minimal area triangulation [S1, unofficial][S3, unofficial].
*   **When to Use:** When extracting isosurfaces from octrees and the resulting polygons are relatively small (typical for adaptive refinement) and high-quality triangulation is required [S1, unofficial][S3, unofficial].
*   **When Not to Use:** For polygons with a very large number of vertices where performance is critical, or when the input is not a simple closed curve on a convex boundary.

## Background
The method was introduced by Hoppe et al. in the context of unconstrained isosurface extraction on arbitrary octrees [S1, unofficial][S3, unofficial]. It builds on the observation that isopolygons obtained from octree extraction are well-behaved, forming simple closed curves on the boundary of convex bodies [S1, unofficial][S3, unofficial]. The algorithm itself is based on a dynamic programming approach described in [BS95] [S1, unofficial][S3, unofficial]. The theoretical basis for the non-self-intersecting nature of the minimal area surface bounded by such curves comes from differential geometry work by [MY80, MY82] [S1, unofficial][S3, unofficial].
