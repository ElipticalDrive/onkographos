# Digital Surface Extraction via Khalimsky Space

Also called: Combinatorial manifold surface extraction, Digital Surface Extraction via Khalimsky Space and Surfel Adjacency, Digital boundary scanning, Dual surface to the digital boundary, Marching-cube like surface extracted using the combinatorial manifold structure of digital surfaces

## Overview
This method extracts a boundary surface from a digital image by constructing a Khalimsky space, defining a digital set based on intensity thresholds, and scanning the space to identify surfels (surface elements) using a specific adjacency rule [S1][S2, unofficial]. It differs from standard marching cubes by operating on the combinatorial manifold structure of digital surfaces rather than interpolating within grid cells, ensuring a topologically correct manifold without the ambiguity of cell configurations [S1][S2, unofficial]. It builds on [Isosurface extraction](30-isosurface-extraction.md) by replacing the geometric interpolation step with a discrete boundary scanning process.

## How it works
**Inputs:** A volumetric image (grid of scalar values), a minimum threshold `minThreshold`, a maximum threshold `maxThreshold`, and an adjacency flag `intAdjacency`.
**Outputs:** A polygonal or triangulated mesh representing the isosurface.

**Data Structures:**
1.  **DigitalSet:** A container storing voxels belonging to the shape. A voxel $v$ belongs to the shape if its intensity $I(v)$ satisfies: $\text{minThreshold} < I(v) \le \text{maxThreshold}$ [S1]. Note: The example code uses `minThreshold <= I(v) <= maxThreshold` [S2, unofficial].
2.  **Khalimsky Space (KSpace):** A topological space constructed from the image domain, representing the grid and its cells (vertices, edges, faces, volumes) with specific adjacency relations.
3.  **SurfelAdjacency:** Defines connectivity rules for surfels (boundary elements). `intAdjacency = 0` indicates interior adjacency (connects surface elements based on interior voxels); `intAdjacency = 1` indicates exterior adjacency [S1][S2, unofficial].
4.  **DigitalSurface:** A container holding the set of surfels that form the boundary.
5.  **CellEmbedder:** Maps digital cells to real-world coordinates. Uses a trivial embedder (canonical injection $\mathbb{Z}^n \to \mathbb{R}^n$) and an offset to avoid geometric ambiguity [S1][S2, unofficial].

**Steps:**
1.  **Read Image:** Load the volume file into an image structure [S1][S2, unofficial].
2.  **Create Digital Set:** Initialize a `DigitalSet` with the image domain. Append voxels whose intensity values fall within `[minThreshold, maxThreshold]` [S1][S2, unofficial].
3.  **Initialize Khalimsky Space:** Create a `KSpace` object and initialize it with the image domain's lower and upper bounds [S1][S2, unofficial].
4.  **Initialize Surfel Adjacency:** Instantiate `SurfelAdjacency` with the chosen adjacency type (`intAdjacency`) [S1][S2, unofficial].
5.  **Extract Boundary Surfels:**
    *   Initialize a `SetOfSurfels` container with the Khalimsky space and adjacency [S1][S2, unofficial].
    *   Call `Surfaces::sMakeBoundary` passing the Khalimsky space, the digital set, and the domain bounds to scan the space and identify boundary surfels [S1][S2, unofficial].
    *   Construct the `DigitalSurface` object from the populated `SetOfSurfels` [S1][S2, unofficial].
6.  **Initialize Cell Embedder:**
    *   Define a `CanonicEmbedder` for mapping integer coordinates to real coordinates [S1].
    *   Define an `ImageLinearCellEmbedder` using the Khalimsky space, image, and trivial embedder [S1].
    *   Initialize the `CellEmbedder` with an iso-surface level offset of $\text{minThreshold} + 0.5$ to avoid the isosurface passing exactly through voxel centers [S1][S2, unofficial].
7.  **Convert to Mesh:**
    *   **For Triangulated Surface:** Call `MeshHelpers::digitalSurface2DualTriangulatedSurface` passing the digital surface, cell embedder, a target `TriMesh`, and a `VertexMap` [S1]. Then convert to a viewable mesh using `MeshHelpers::triangulatedSurface2Mesh` [S1].
    *   **For Polygonal Surface:** Call `MeshHelpers::digitalSurface2DualPolygonalSurface` passing the digital surface, cell embedder, a target `PolygonMesh`, and a `VertexMap` [S2, unofficial]. Then convert to a viewable mesh using `MeshHelpers::polygonalSurface2Mesh` [S2, unofficial].

**Pseudocode:**
```python
def extract_surface_khalimsky(image, min_threshold, max_threshold, int_adjacency):
    # Step 1: Read Image
    # image is assumed to be loaded with domain bounds
    domain_lower = image.domain.lower_bound
    domain_upper = image.domain.upper_bound
    
    # Step 2: Create Digital Set
    digital_set = DigitalSet(domain_lower, domain_upper)
    for voxel in image.voxels:
        intensity = image.get_value(voxel)
        # Note: S1 uses strict inequality for min, S2 uses inclusive. 
        # Implementation should match the specific library version.
        if min_threshold <= intensity <= max_threshold:
            digital_set.append(voxel)
            
    # Step 3: Initialize Khalimsky Space
    ks = KSpace()
    space_ok = ks.init(domain_lower, domain_upper, True)
    if not space_ok:
        raise Error("Khalimsky space construction failed")
        
    # Step 4: Initialize Surfel Adjacency
    surf_adj = SurfelAdjacency(ks.dimension)
    surf_adj.set_interior_adjacency(int_adjacency == 0)
    
    # Step 5: Extract Boundary Surfels
    set_of_surfels = SetOfSurfels(ks, surf_adj)
    Surfaces.s_make_boundary(set_of_surfels.surfel_set(), ks, digital_set, 
                             domain_lower, domain_upper)
    digital_surface = DigitalSurface(set_of_surfels)
    
    # Step 6: Initialize Cell Embedder
    trivial_embedder = CanonicEmbedder()
    cell_embedder = ImageLinearCellEmbedder(ks, image, trivial_embedder)
    # Offset to avoid passing through voxel centers
    iso_level = min_threshold + 0.5
    cell_embedder.init(ks, image, trivial_embedder, iso_level)
    
    # Step 7: Convert to Mesh (Triangulated Example)
    trimesh = TriangulatedSurface()
    vertex_map = {}
    MeshHelpers.digital_surface2_dual_triangulated_surface(
        digital_surface, cell_embedder, trimesh, vertex_map)
    
    view_mesh = Mesh()
    MeshHelpers.triangulated_surface2_mesh(trimesh, view_mesh)
    
    return view_mesh
```

**Parameters:**
*   `minThreshold`: Minimum voxel intensity value for inclusion. Type: `unsigned int`. Typical: Command line argument [S2, unofficial].
*   `maxThreshold`: Maximum voxel intensity value for inclusion. Type: `unsigned int`. Typical: Command line argument [S2, unofficial].
*   `intAdjacency`: Boolean flag for surfel connectivity. `0` = interior adjacency, `1` = exterior adjacency [S1][S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Voxel Center Ambiguity:** For binary volumes, if the isosurface level equals an integer voxel value, the surface may pass exactly through voxel centers, causing geometric ambiguity or degeneracy [S1][S2, unofficial]. This is handled by adding 0.5 to the threshold during embedder initialization [S1][S2, unofficial].
*   **Adjacency Choice:** Incorrect adjacency choice can lead to non-manifold structures or disconnected surfaces. Interior adjacency is generally preferred for unambiguous connection based on interior voxels [S1][S2, unofficial].

## Subtopics

### Dual Triangulated Surface Generation
A variant that converts a digital surface (set of surfels) into a dual triangulated mesh. It uses an embedder to map digital cells to real coordinates and constructs a `TriangulatedSurface` [S1]. It is chosen when a triangular mesh is required for rendering or further geometric processing. It differs from the polygonal variant by explicitly triangulating the dual faces, potentially increasing vertex count but ensuring compatibility with standard triangle-based renderers [S1].

## Operating characteristics
*   **Time Complexity:** Not given in the sources. The example shows boundary extraction taking ~2757 ms and mesh conversion taking ~2381 ms for a 160,660 surfel surface [S2, unofficial].
*   **Memory Complexity:** Not given in the sources. Depends on the size of the Khalimsky space and the number of surfels.
*   **Measured Performance:** On a lobster.vol dataset, the method produced a surface with 160,660 vertices, 321,320 edges, and 160,524 faces, with an Euler characteristic of -136 [S2, unofficial].
*   **Strengths:** Topologically correct manifold extraction; avoids the ambiguity of marching cubes cell configurations; works directly on digital topology.
*   **Limitations:** Requires construction of Khalimsky space, which can be memory-intensive for large volumes; output is a dual mesh which may not be directly usable without conversion; limited to grid-based data.
*   **When to Use:** When topological correctness is critical and the input is a digital volume; when avoiding the "ambiguous cases" of marching cubes is necessary.
*   **When Not to Use:** When real-time performance is required and the overhead of Khalimsky space construction is prohibitive; when the input is not a regular grid.

## Background
The method originates from the DGtal library, which provides tools for digital geometry and topology [S1][S2, unofficial]. It is based on the theory of Khalimsky spaces, a topological framework for digital images that allows for rigorous definition of boundaries and connectivity [S1][S2, unofficial]. The approach was developed to provide a robust alternative to geometric isosurface extraction methods like marching cubes, particularly for binary and multi-label digital images [S1][S2, unofficial].
