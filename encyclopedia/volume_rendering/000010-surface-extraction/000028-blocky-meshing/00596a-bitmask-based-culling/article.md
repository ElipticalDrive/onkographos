# Bitmask-based Culling

Also called: Bitmask Culling, Bitwise Face Culling

## Overview
Bitmask-based Culling is a family of optimizations for blocky meshing that reduces triangle count by using bitwise operations to determine which voxel faces are visible, replacing explicit neighbor coordinate lookups with parallel integer math. It sets itself apart from sibling methods like [Face Culling](13637-face-culling.md) by operating on linear bitmasks to identify exposed surfaces in bulk, solving the performance bottleneck of naive neighbor-checking loops .

## Shared principles
The core mechanism relies on representing voxel states or geometric coverage as contiguous bitmasks (integers or arrays of integers). Visibility is determined by bitwise logical operations (AND, NOT, OR, XOR) and shifts, rather than iterative spatial checks.

**1. State Representation**
*   **Binary State:** A single bit per voxel indicates solid (1) or empty/air (0) .
*   **Coverage Mask:** For partial shapes, a bitmask (e.g., 16-bit for a 4x4 grid) represents the geometric coverage of a face .

**2. Visibility Logic**
*   **Binary:** A face is visible if the voxel is solid AND the neighbor is empty. This is computed as $M \ \& \ (\sim M_{shifted})$ .
*   **Coverage:** A face is visible if the current block's coverage mask has bits set that are not covered by the neighbor's mask. This is computed as $CurrentMask \ \& \ (\sim NeighborMask)$ .

**3. Implementation Constraints**
*   **Data Layout:** Requires data to be accessible in a linear or axis-aligned slice format to enable bitwise shifts .
*   **Precision:** The integer type must be large enough to hold the entire slice or chunk dimension. For large chunks, arrays of integers are required .

## Subtopics

### Face Coverage Mask Culling [3397-face-coverage-mask-culling.md]
Determines visibility by comparing precomputed bitmasks of geometric coverage between adjacent blocks. It solves the problem where simple boolean flags are insufficient for partial shapes (stairs, slabs) that have mixed visible/hidden areas on a single face. Unlike binary methods, it retains accuracy for partial geometry while avoiding full CSG .

### Binary Hidden-Face Culling [8747-binary-hidden-face-culling.md]
Reduces face count by removing faces completely hidden by adjacent voxels using bitwise operations on a linear bitmask. It solves the performance bottleneck of random memory access by replacing it with parallel bitwise math on 1D slices. Unlike general face culling, it operates on linear bitmasks without explicit spatial lookups .

### Buried Bitmask Optimization
A bitmask used to track which blocks in a chunk are 'buried' (fully surrounded by opaque blocks), allowing the renderer to skip mesh generation for those blocks [S1, unofficial].
1.  Reset the buried bitmask for the chunk [S1, unofficial].
2.  Create `MappedAdjacentChunks` for the current chunk position to access neighboring chunks [S1, unofficial].
3.  Iterate through all blocks in the chunk (0 to `CHUNK_SIZE`). For each block, determine if it is buried by calling `block->isBuried(...)` and set the corresponding flag in the bitmask [S1, unofficial].
4.  If all blocks in the chunk are buried (checked via `buriedBitmask->AreAllBlocksSet()`), mark the mesh as empty and skip mesh generation [S1, unofficial].
5.  When generating the mesh, skip any block that is air or has its buried flag set in the bitmask [S1, unofficial].

## Background
Originating from the optimization techniques used in voxel-based games like Minecraft, this method evolved to handle the massive triangle counts generated by naive meshing. The specific "Buried Bitmask" variant is documented in the unofficial repository [S1, unofficial]. The general bitwise approach for 1D slices is also described in unofficial sources .
