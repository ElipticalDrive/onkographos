# Dynamic Block Mesh Management

Also called: Dynamic Index Buffer Updating (for deformable models)

## Overview
Dynamic Block Mesh Management is a technique for maintaining a dynamic list of block indices organized by spatial coordinates, allowing for efficient addition and removal of individual block faces without rebuilding the entire mesh [S1, unofficial]. It solves the performance bottleneck of static mesh regeneration in voxel environments where the geometry changes frequently. Unlike [Static Mesh Caching](1138-static-mesh-caching.md), which assumes immutable geometry, this method updates the index buffer in real-time by managing block-level data structures [S1, unofficial].

## How it works
**Inputs:** Block placement/removal events (coordinates $x, y, z$ and face indices).
**Outputs:** Updated index buffer and spatial position arrays.

**Data Structures:**
1.  `blocksPos`: A 3-level nested array structure storing block coordinates.
    *   `blocksPos[i]`: Array of Y-Z planes at X-index `i`.
    *   `blocksPos[i][j]`: Array of Z-lines at Y-index `j`.
    *   `blocksPos[i][j][k]`: Array `[z_coord, indices_array]`.
2.  `blocksData`: A dictionary (hash map) mapping string keys `'x,y,z'` to arrays of vertex indices.
3.  `vertexSlots`: A stack (LIFO) of available vertex indices for memory reuse [S1, unofficial].
4.  `indicesLength`: Integer tracking the total number of indices in the buffer.

**Algorithm Steps:**

1.  **Initialization:**
    *   Initialize `blocksPos` as empty.
    *   Initialize `blocksData` as empty.
    *   Initialize `vertexSlots` as empty.
    *   Initialize `indicesLength` to 0.

2.  **Adding a Block Face:**
    *   Input: Coordinates $(x, y, z)$ and 6 vertex indices $(a, b, c, c, d, a)$ representing the face [S1, unofficial].
    *   Construct key `pos = "x,y,z"`.
    *   If `pos` not in `blocksData`:
        *   Create empty list `indices = []`.
        *   Store `blocksData[pos] = indices`.
        *   Call `updateBlocksPos(x, y, z, add=True, indices)` to insert into `blocksPos`.
    *   Append the 6 indices to `blocksData[pos]`.
    *   Increment `indicesLength` by 6.

3.  **Removing a Block Face:**
    *   Input: Coordinates $(x, y, z)$ and the specific 6 indices to remove.
    *   Retrieve `indices = blocksData[pos]`.
    *   Find and remove the specific 6 indices from the list.
    *   Decrement `indicesLength` by 6.
    *   If `indices` is empty:
        *   Remove `pos` from `blocksData`.
        *   Call `updateBlocksPos(x, y, z, add=False)` to remove from `blocksPos`.

4.  **Updating Spatial Position Arrays (`updateBlocksPos`):**
    *   Input: $x, y, z$, boolean `add`, and reference to `indices` list.
    *   **Insertion (`add=True`):**
        *   Iterate through `blocksPos` to find the correct insertion point for $x$.
        *   If $x$ does not exist, insert a new entry at index $i$.
        *   Within `blocksPos[i]`, find the correct insertion point for $y$.
        *   If $y$ does not exist, insert a new entry at index $j$.
        *   Within `blocksPos[i][j]`, find the correct insertion point for $z$.
        *   If $z$ does not exist, insert `[z, indices]` at index $k$.
    *   **Deletion (`add=False`):**
        *   Locate the entry `[z, indices]` in `blocksPos[i][j]`.
        *   Remove it.
        *   If `blocksPos[i][j]` has only 1 element left (or becomes empty depending on implementation logic for empty planes), remove the Y-plane.
        *   If `blocksPos[i]` has only 1 element left, remove the X-plane.
        *   If `blocksPos` has only 1 element left, remove the root.

**Pseudocode:**

```python
class DynamicBlockMesh:
    def __init__(self):
        self.blocks_pos = []  # 3D nested structure: blocks_pos[x][y][z] = [z_val, indices]
        self.blocks_data = {} # Map "x,y,z" -> [indices]
        self.vertex_slots = [] # Stack of free vertex indices
        self.indices_length = 0

    def add_face(self, x, y, z, a, b, c, d):
        """
        Adds a face defined by vertices a,b,c,d (two triangles: a,b,c and c,d,a)
        to the block at (x,y,z).
        """
        pos_key = f"{x},{y},{z}"
        
        # Get or create indices list
        if pos_key not in self.blocks_data:
            indices = []
            self.blocks_data[pos_key] = indices
            self._update_blocks_pos(x, y, z, add=True, indices=indices)
        else:
            indices = self.blocks_data[pos_key]

        # Append face indices
        indices.extend([a, b, c, c, d, a])
        self.indices_length += 6

    def remove_face(self, x, y, z, a, b, c, d):
        """
        Removes a specific face from the block at (x,y,z).
        Note: In a real implementation, one must identify which face corresponds 
        to the removal event. Here we assume the indices are known.
        """
        pos_key = f"{x},{y},{z}"
        if pos_key not in self.blocks_data:
            return

        indices = self.blocks_data[pos_key]
        
        # Remove the specific 6 indices
        # In practice, one might search for the sequence or maintain face-level tracking.
        # For this generic method, we assume we can identify and remove the 6 indices.
        face_indices = [a, b, c, c, d, a]
        
        # Simple removal: find and remove the sequence
        # Note: This is a simplified representation. Real implementation needs robust search.
        try:
            # Find start index of the face
            start_idx = indices.index(a)
            # Verify the sequence matches
            if indices[start_idx:start_idx+6] == face_indices:
                del indices[start_idx:start_idx+6]
                self.indices_length -= 6
            else:
                # Fallback: linear search for each element if order varies
                # This is inefficient but ensures correctness if order is not guaranteed
                for idx in face_indices:
                    if idx in indices:
                        indices.remove(idx)
                        self.indices_length -= 1
        except ValueError:
            pass

        # If empty, clean up
        if not indices:
            del self.blocks_data[pos_key]
            self._update_blocks_pos(x, y, z, add=False)

    def _update_blocks_pos(self, x, y, z, add, indices=None):
        """
        Maintains the sorted 3D structure of blocks_pos.
        """
        # Find X position
        x_idx = self._find_insertion_index(self.blocks_pos, x, axis=0)
        
        if add:
            if x_idx == len(self.blocks_pos):
                self.blocks_pos.append([])
                x_idx = len(self.blocks_pos) - 1
            
            # Find Y position within X plane
            y_plane = self.blocks_pos[x_idx]
            y_idx = self._find_insertion_index(y_plane, y, axis=1)
            
            if y_idx == len(y_plane):
                y_plane.append([])
                y_idx = len(y_plane) - 1
            
            # Find Z position within Y line
            z_line = y_plane[y_idx]
            z_idx = self._find_insertion_index(z_line, z, axis=2)
            
            if z_idx == len(z_line):
                z_line.append([z, indices])
                z_idx = len(z_line) - 1
        else:
            # Removal logic
            if x_idx < len(self.blocks_pos):
                y_plane = self.blocks_pos[x_idx]
                if y_idx < len(y_plane):
                    z_line = y_plane[y_idx]
                    if z_idx < len(z_line):
                        z_line.pop(z_idx)
                        # Cleanup empty lines/planes
                        if not z_line:
                            y_plane.pop(y_idx)
                        if not y_plane:
                            self.blocks_pos.pop(x_idx)

    def _find_insertion_index(self, arr, val, axis):
        """
        Finds the index where val should be inserted to maintain sorted order.
        Handles nested structures based on axis.
        """
        # This is a simplified binary search or linear scan placeholder.
        # In the source, it uses a loop: for k in range(len(arr)): if val <= arr[k]...
        for i, item in enumerate(arr):
            if axis == 0:
                if val <= item[0]: # item is [y, ...] or similar
                    return i
            elif axis == 1:
                # item is [z, indices]
                if val <= item[0]:
                    return i
            elif axis == 2:
                # item is [z, indices]
                if val <= item[0]:
                    return i
        return len(arr)
```

**Edge Cases and Pitfalls:**
*   **Precision:** Floating-point coordinates for block positions must be handled carefully. The source uses integer-like indexing for the structure, but if coordinates are floats, exact equality checks (`==`) may fail. Use a tolerance or quantize coordinates [S1, unofficial].
*   **Empty Lists:** When removing a block, ensure that empty lists are pruned from `blocks_pos` to prevent memory leaks and maintain efficient iteration [S1, unofficial].
*   **Vertex Reuse:** The `vertexSlots` stack is mentioned but not fully detailed in the core addition/removal logic. It is used to optimize memory by reusing vertex indices rather than allocating new ones [S1, unofficial].

## Subtopics

### [Thin Instance Management for Object Blocks](14154-thin-instance-management-for-object-blocks.md)
Thin Instance Management for Object Blocks manages a pool of thin instances per voxel block ID to render static object meshes efficiently, handling instance addition, removal, matrix updates, buffer resizing, and world rebasing. It builds on Dynamic Block Mesh Management by providing the specific data structures and update logic required to translate block-level changes into GPU-friendly instance buffers. It is chosen when rendering complex static objects within a voxel grid where instance count is high but geometry is static per block.

### Dynamic Index Buffer Updating
Dynamic Index Buffer Updating is a technique for handling deformable models by classifying triangles into groups based on surface normals and updating an index buffer in AGP memory dynamically to avoid traversing the whole model for each slab [S2, unofficial]. It is chosen when rendering deformable models in voxelization pipelines where static caching is insufficient. It differs from the standard block management by operating on triangle groups and using AGP memory for fast updates [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Addition and removal are $O(1)$ for dictionary lookups, but $O(N)$ for spatial array updates due to potential list insertions/deletions in `blocks_pos`, where $N$ is the number of blocks along an axis. In practice, with sparse grids, this is very fast.
*   **Memory Complexity:** Proportional to the number of active block faces. The `blocks_pos` structure adds overhead for spatial indexing.
*   **Performance:** Efficient for dynamic scenes with frequent block changes. Avoids the $O(V)$ cost of full mesh regeneration [S1, unofficial].
*   **Limitations:** Not suitable for highly deformable models without the additional Dynamic Index Buffer Updating variant [S2, unofficial]. Precision issues may arise with non-integer coordinates.

## Background
Dynamic Block Mesh Management originates from voxel-based game engines and simulation environments where real-time geometry modification is required. The specific implementation details are derived from the Exolands project, a voxel engine implementation [S1, unofficial]. The concept of dynamic index updating for deformable models in voxelization was also explored in research on real-time voxelization for complex models, which introduced the use of AGP memory for dynamic buffer updates [S2, unofficial].
