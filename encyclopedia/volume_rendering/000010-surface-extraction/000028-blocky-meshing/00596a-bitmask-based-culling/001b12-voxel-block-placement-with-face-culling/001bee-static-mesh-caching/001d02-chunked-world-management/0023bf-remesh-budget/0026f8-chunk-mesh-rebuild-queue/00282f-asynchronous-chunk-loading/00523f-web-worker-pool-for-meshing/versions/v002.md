# Web Worker Pool for Meshing

Also called: Asynchronous Meshing via Web Workers, Main-thread mesher plus worker pool, WasmMeshing Worker Pool, Web Worker Pool

## Overview
This method offloads the computationally expensive task of chunk mesh generation (specifically greedy meshing) from the main thread to a pool of Web Workers, ensuring the main thread remains responsive for gameplay and rendering [S1, unofficial]. It distinguishes itself by combining a background worker pool for bulk remeshing with a main-thread mesher for immediate edits, sharing a single WebAssembly voxel core to avoid memory duplication [S2, unofficial].

## How it works
### Inputs and Outputs
*   **Input:** A queue of `MeshInput` objects representing chunks marked as "dirty" (modified) [S1, unofficial]. Each input contains the chunk key and the voxel state buffer (`inp.state.buffer`) [S2, unofficial].
*   **Output:** `MeshData` objects posted by workers, containing the generated geometry for the chunk [S2, unofficial].

### Data Structures
The `WasmMeshing` class maintains the following fields [S2, unofficial]:
*   `mesher: Mesher`: The GreedyMesher instance running in the main thread for immediate edits.
*   `mem: WebAssembly.Memory`: The shared WebAssembly linear memory containing the voxel core [S2, unofficial].
*   `workers: Worker[]`: Array of `n` Web Worker instances [S2, unofficial].
*   `busy: number[]`: Array of length `n`, tracking the number of active jobs per worker [S2, unofficial].
*   `queue: MeshInput[]`: The priority queue of pending chunk rebuilds [S2, unofficial].
*   `pending: Set<number>`: Set of chunk keys currently being processed by workers [S2, unofficial].
*   `onResult: (d: MeshData) => void`: Callback invoked when a worker completes a job [S2, unofficial].
*   `rank: (key: number) => number`: Function determining job priority (nearest-first) [S2, unofficial].
*   `onDrop: (key: number) => void`: Callback invoked if a job is dropped due to high rank [S2, unofficial].

### Steps
1.  **Initialize Worker Pool:**
    *   Calculate the number of workers `n` using the formula:
        $$ n = \max(1, \min(4, (\text{navigator.hardwareConcurrency} \text{ or } 4) - 1)) $$
        This reserves one core for the main thread and caps the pool at 4 workers [S2, unofficial].
    *   Create `n` Web Workers using `new URL(..., import.meta.url)` to ensure compatibility with static hosting constraints (e.g., Vercel) [S1, unofficial].
    *   Send an `init` message to each worker containing the block table and the WebAssembly memory handle [S2, unofficial].

2.  **Dispatch Jobs (`pump`):**
    *   Iterate through the `queue` to find the job with the lowest rank (nearest-first) [S2, unofficial].
    *   If the job's rank is `Infinity`, drop the job by calling `onDrop(key)` and remove it from the queue [S2, unofficial].
    *   Find the least busy worker where `busy[i] < 2` [S2, unofficial].
    *   If a worker is available:
        *   Increment `busy[i]`.
        *   Add the chunk key to `pending`.
        *   Send the job to the worker via `postMessage`, transferring `inp.state.buffer` if present [S2, unofficial].

3.  **Handle Completion:**
    *   When a worker posts a `MeshData` message:
        *   Decrement `busy[i]` for the corresponding worker.
        *   Remove the chunk key from `pending`.
        *   Call `onResult(e.data)` to process the geometry [S2, unofficial].
        *   Trigger `pump()` to schedule the next job [S2, unofficial].

### Pseudocode
```python
class WasmMeshing:
    def __init__(self, on_result, rank_func, on_drop):
        self.mesher = Mesher()
        self.mem = get_wasm_memory()
        self.on_result = on_result
        self.rank = rank_func
        self.on_drop = on_drop

        hardware_cores = navigator.hardwareConcurrency or 4
        n = max(1, min(4, hardware_cores - 1))

        self.workers = []
        self.busy = [0] * n
        self.queue = []
        self.pending = set()

        for i in range(n):
            worker = Worker(URL('meshWorker.ts', import_meta_url), type='module')
            worker.onmessage = self.handle_worker_message
            worker.postMessage({'type': 'init', 'mem': self.mem, 'block_table': self.block_table})
            self.workers.append(worker)

    def mark_dirty(self, chunk_key, state_buffer):
        self.queue.append({'key': chunk_key, 'state': {'buffer': state_buffer}})
        self.pump()

    def pump(self):
        while self.queue and any(b < 2 for b in self.busy):
            job_index = min(range(len(self.queue)), key=lambda i: self.rank(self.queue[i]['key']))
            job = self.queue[job_index]

            if self.rank(job['key']) == float('inf'):
                self.on_drop(job['key'])
                self.queue.pop(job_index)
                continue

            worker_index = min(range(len(self.workers)), key=lambda i: self.busy[i])

            if self.busy[worker_index] < 2:
                self.busy[worker_index] += 1
                self.pending.add(job['key'])
                self.queue.pop(job_index)

                transferables = []
                if job['state'].get('buffer'):
                    transferables.append(job['state']['buffer'])

                self.workers[worker_index].postMessage({
                    'type': 'mesh',
                    'key': job['key'],
                    'state': job['state']
                }, transferables)

    def handle_worker_message(self, event):
        data = event.data
        worker_index = self.get_worker_index(event.source)

        self.busy[worker_index] -= 1
        self.pending.remove(data['key'])
        self.on_result(data)
        self.pump()
```

### Parameters
*   **Worker Count:** Clamped between 1 and 4, calculated as `navigator.hardwareConcurrency - 1` [S2, unofficial].
*   **Worker Load Limit:** Each worker accepts at most 2 simultaneous jobs to prevent latency spikes from long queues [S2, unofficial].

### Edge Cases and Pitfalls
*   **Edge Editing:** When a block is placed or broken at a chunk boundary, neighboring chunks must be invalidated (marked dirty) to ensure correct culling and meshing [S1, unofficial].
*   **Static Hosting:** Worker instantiation must use `new URL(..., import.meta.url)` to function correctly in static hosting environments like Vercel [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Meshing is offloaded, so main-thread frame time is reduced to queue management and result processing [S1, unofficial].
*   **Memory Complexity:** Shared WebAssembly memory avoids duplicating voxel data across workers [S2, unofficial].
*   **Strengths:** Keeps the main thread responsive for gameplay and rendering [S1, unofficial]. Compatible with static hosting [S1, unofficial].
*   **Limitations:** Limited to 4 workers maximum [S2, unofficial]. Requires careful handling of chunk boundary invalidation [S1, unofficial].

## Background
This method was implemented in the "blockbound" voxel engine project by Eduardo Lavall in October 2026, as part of Phase 2 development focusing on chunks, meshing, and editing [S1, unofficial]. It was designed to support a destructible voxel world rendered in the browser using Rust WASM, with constraints for static hosting on platforms like Vercel [S1, unofficial].
