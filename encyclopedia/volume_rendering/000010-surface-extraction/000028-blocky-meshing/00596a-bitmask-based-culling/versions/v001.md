# Bitmask-based Culling


## Overview
Bitmask-based Culling is a family of optimizations in blocky meshing that reduces triangle count by using bitwise operations to determine which voxel faces are visible, avoiding explicit neighbor coordinate lookups or complex geometric intersection tests. It sets itself apart from sibling methods like [Voxel Block Placement with Face Culling](923-voxel-block-placement-with-face-culling.md) by operating on linear or structured bitmasks rather than iterating through neighbor arrays, and from [Opacity-based Mesh Culling](8759-opacity-based-mesh-culling.md) by focusing on geometric coverage rather than material transparency properties.

## Shared principles
The core mechanism relies on representing voxel states or face coverages as bitmasks, where each bit corresponds to a specific voxel or grid cell. Visibility is determined by bitwise logic (AND, OR, NOT, SHIFT) applied to these masks, allowing bulk processing of multiple voxels or faces in parallel. This replaces random memory access patterns with sequential or vectorized bitwise math, significantly improving performance for large chunks. The method assumes a discrete grid structure where neighbors are aligned with bit positions.

## Subtopics

### [Face Coverage Mask Culling](3397-face-coverage-mask-culling.md)
Determines visibility by comparing precomputed 16-bit `FaceMask` integers representing 4x4 cell coverage on block faces. It handles partial shapes (stairs, slabs) where simple boolean flags fail, using bitwise AND with inverted neighbor masks to find visible portions. Choose when dealing with non-cube primitives that require sub-voxel accuracy.

### [Binary Hidden-Face Culling](8747-binary-hidden-face-culling.md)
Uses 1D bitmasks for linear slices of voxels, shifting and inverting masks to identify exposed faces (e.g., $L = M \ \& \ (\neg (M \gg 1))$). It eliminates neighbor lookups entirely by operating on flattened arrays. Choose for simple cube-based voxel worlds where performance is critical and partial face geometry is not required.

### Buried Bitmask Optimization
A bitmask tracks blocks fully surrounded by opaque neighbors, allowing the renderer to skip mesh generation for entirely buried chunks. It resets the bitmask per chunk, iterates blocks to set buried flags, and skips meshing if all blocks are buried or if a block's buried flag is set. [S1, unofficial]

## Background
Originating from optimizations in voxel-based games like Minecraft, bitmask culling evolved to handle the performance bottleneck of naive neighbor-checking loops. The binary approach leverages CPU bitwise instructions for bulk operations, while face coverage masks address the limitations of boolean occlusion for complex shapes. [S1, unofficial]
