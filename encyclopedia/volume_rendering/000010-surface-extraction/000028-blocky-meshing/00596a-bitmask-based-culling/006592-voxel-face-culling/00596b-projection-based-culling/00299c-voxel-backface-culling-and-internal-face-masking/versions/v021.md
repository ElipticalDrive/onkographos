# Voxel Backface Culling and Internal Face Masking

Also called: Internal Face Masking, Voxel Backface Culling

## Overview
Voxel Backface Culling and Internal Face Masking is a technique to reject invisible faces in voxel rendering by determining front/back orientation in projection space and masking faces shared between neighboring voxels [S1, unofficial]. It sets itself apart from sibling methods by operating directly on voxel primitives in the geometry shader stage, using a specific projection-space dot product to orient faces and a bitmask to eliminate internal geometry, rather than relying on mesh connectivity or external depth buffers [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input**: A voxel defined by eight corner positions ($c_{vCorner000}$ to $c_{vCorner111}$), a view direction vector ($v_{ViewDirection}$), a world-view matrix ($c_{mWorldView}$), and a 32-bit integer encoding visibility masks and position ($vs\_out\_VoxelCode[0]$).
*   **Output**: Vertices emitted for the visible front or back face of the voxel, with associated lighting and screen-space positions.

**Data Structures**
The visibility state is encoded in a single 32-bit integer ($vs\_out\_VoxelCode[0]$) [S1, unofficial]:
*   Bits 0-5: Mask for the six sides of the voxel (1 bit per side).
*   Bits 6-23: 3 * 8 bits for the 3D position (allowing addressing of $256^3$ positions).
*   Bits 24-25: Unused.
*   Bits 26-31: Unused.

**Steps**
1.  **Calculate Inverse Projection Diagonal**: Compute the vector $v_{InverseProjection}$ using the diagonal elements of the projection matrix $mProjection$:
    $$ v_{InverseProjection} = \left( \frac{1}{mProjection[0][0]}, \frac{1}{mProjection[1][1]}, \frac{1}{mProjection[2][2]} \right) $$
    This vector transforms directions from projection space to view space [S1, unofficial].

2.  **Determine Face Orientation**: Calculate the dot product of the sum of two opposite voxel corners (transformed by the inverse projection diagonal) and the view direction [S1, unofficial]:
    $$ D = \text{dot}\left( (c_{vCorner000}.xyz + c_{vCorner110}.xyz) * v_{InverseProjection}.xyz, v_{ViewDirection} \right) $$
    *   If $D > 0$, the front face is oriented towards the viewer.
    *   If $D \le 0$, the back face is oriented towards the viewer.

3.  **Check Internal Masking and Emit**:
    *   **Front Face Case** ($D > 0$): Check if bit `0x10` (bit 4) is set in $vs\_out\_VoxelCode[0]$ [S1, unofficial].
        *   If set, emit the front face vertices: $c_{vCorner000}, c_{vCorner100}, c_{vCorner010}, c_{vCorner110}$.
        *   Compute lighting using the normal $n = (0, 0, -1)$ transformed by the world-view matrix: $v_{Normal} = \text{normalize}((vec4(0,0,-1,0) * c_{mWorldView}).xyz)$.
    *   **Back Face Case** ($D \le 0$): Check if bit `0x20` (bit 5) is set in $vs\_out\_VoxelCode[0]$ [S1, unofficial].
        *   If set, emit the back face vertices: $c_{vCorner011}, c_{vCorner111}, c_{vCorner001}, c_{vCorner101}$.
        *   Compute lighting using the normal $n = (0, 0, 1)$ transformed by the world-view matrix: $v_{Normal} = \text{normalize}((vec4(0,0,1,0) * c_{mWorldView}).xyz)$.

**Pseudocode**
```python
def process_voxel(c_vCorner000, c_vCorner110, vs_out_VoxelCode, vViewDirection, c_mWorldView, mProjection):
    # Step 1: Calculate inverse projection diagonal
    inv_proj = (1.0 / mProjection[0][0], 1.0 / mProjection[1][1], 1.0 / mProjection[2][2])
    
    # Step 2: Determine orientation
    # Sum of corners transformed by inverse projection
    corner_sum = (c_vCorner000.x + c_vCorner110.x) * inv_proj.x, \
                 (c_vCorner000.y + c_vCorner110.y) * inv_proj.y, \
                 (c_vCorner000.z + c_vCorner110.z) * inv_proj.z
    
    dot_product = corner_sum[0] * vViewDirection.x + \
                  corner_sum[1] * vViewDirection.y + \
                  corner_sum[2] * vViewDirection.z
    
    # Step 3: Check masks and emit
    if dot_product > 0:
        # Front face
        if (vs_out_VoxelCode[0] & 0x10) != 0:
            # Normal (0,0,-1) transformed
            normal_vec = transform_vector(vec4(0, 0, -1, 0), c_mWorldView)
            normal = normalize(normal_vec.xyz)
            # Emit vertices: 000, 100, 010, 110
            emit_vertex(c_vCorner000)
            emit_vertex(c_vCorner100)
            emit_vertex(c_vCorner010)
            emit_vertex(c_vCorner110)
            compute_lighting(normal, vViewDirection)
    else:
        # Back face
        if (vs_out_VoxelCode[0] & 0x20) != 0:
            # Normal (0,0,1) transformed
            normal_vec = transform_vector(vec4(0, 0, 1, 0), c_mWorldView)
            normal = normalize(normal_vec.xyz)
            # Emit vertices: 011, 111, 001, 101
            emit_vertex(c_vCorner011)
            emit_vertex(c_vCorner111)
            emit_vertex(c_vCorner001)
            emit_vertex(c_vCorner101)
            compute_lighting(normal, vViewDirection)
```

**Parameters**
*   **Chunk Size**: $32^3$ voxels per chunk. This size is used for efficient memory management, LOD, and large-scale culling algorithms [S1, unofficial].

**Edge Cases and Pitfalls**
*   **Shared Faces**: Faces shared between two neighboring voxels are never visible. The masking bits (`0x10` and `0x20`) are specifically used to reject these invisible internal faces [S1, unofficial].
*   **Projection Space Limitations**: Backface culling cannot be done directly in projection space without the inverse projection diagonal trick; the direction must be transformed to view space first [S1, unofficial].
*   **Frustum Culling**: Voxels outside the viewing volume should be rejected before this step. A simple check involves comparing absolute coordinates against the w-component plus corner lengths [S1, unofficial].

## Operating characteristics
*   **Performance**: On a GeForce 640M LE, the method draws 32,368 voxels per millisecond [S1, unofficial].
*   **Complexity**: The method adds a constant-time dot product and bitwise check per voxel in the geometry shader. It avoids the overhead of mesh connectivity analysis or depth buffer lookups.
*   **Strengths**: Efficiently culls internal geometry that would otherwise be rendered and discarded by the depth test. Simple to implement in a geometry shader.
*   **Limitations**: Requires a specific projection matrix structure to compute the inverse diagonal. Relies on pre-computed voxel codes for masking. Performance is limited by geometry shader throughput on the target hardware.

## Background
This technique was described by Johannes Jendersie in a blog post on his developer blog, focusing on voxel rendering optimization using geometry shaders [S1, unofficial]. It was developed as part of a voxel beam/grid rendering system, aiming to improve performance by reducing the number of primitives sent to the rasterizer. The approach leverages the regular structure of voxels to simplify visibility testing.
