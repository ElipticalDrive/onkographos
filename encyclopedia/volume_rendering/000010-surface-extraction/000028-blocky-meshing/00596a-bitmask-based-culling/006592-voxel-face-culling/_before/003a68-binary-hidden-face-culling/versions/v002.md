# Binary Hidden-Face Culling

Also called: Bitmask Hidden-Face Culling, Visible-Face Culling

## Overview
Binary Hidden-Face Culling is a method for reducing the number of faces in a voxel mesh by removing those completely hidden between adjacent solid voxels, using bitwise operations on a bitmask representation of voxels to determine visible faces in bulk [S2, unofficial]. It replaces iterative neighbor checks with parallel bitwise logic, significantly improving performance for mesh generation [S2, unofficial]. It builds on [Bitmask-based Culling](16406-bitmask-based-culling.md) by applying its core principles to the specific case of binary (solid/empty) voxel states within a linear chunk.

## How it works
**Inputs and Outputs:**
*   **Input:** A linear array of bits representing a 1D slice of voxels (e.g., a row in a chunk), where `1` indicates a solid voxel and `0` indicates an empty/air voxel [S2, unofficial].
*   **Output:** A bitmask of the same length indicating which positions have visible faces in a specific direction (e.g., left or right) [S2, unofficial].

**Data Structures:**
*   **Voxel Bitmask:** An integer or array of integers where each bit corresponds to a voxel's state. For a chunk of width $W$, if $W \le 64$, a single 64-bit integer suffices. If $W > 64$, an array of integers is required [S2, unofficial].

**Steps:**
1.  **Represent Voxels:** Convert the voxel data for a specific axis-aligned slice into a bitmask $M$, where bit $i$ is `1` if voxel $i$ is solid, and `0` otherwise [S2, unofficial].
2.  **Determine Visible Left Faces:**
    *   Shift $M$ right by 1 position: $M_{right} = M \gg 1$. This represents the state of the neighbor to the left [S2, unofficial].
    *   Invert the result: $\sim M_{right}$. This identifies positions where the left neighbor is empty (air) [S2, unofficial].
    *   Perform bitwise AND with the original mask: $VisibleLeft = M \ \& \ (\sim M_{right})$. A bit is `1` in the result if the current voxel is solid AND the left neighbor is empty [S2, unofficial].
3.  **Determine Visible Right Faces:**
    *   Shift $M$ left by 1 position: $M_{left} = M \ll 1$. This represents the state of the neighbor to the right [S2, unofficial].
    *   Invert the result: $\sim M_{left}$. This identifies positions where the right neighbor is empty (air) [S2, unofficial].
    *   Perform bitwise AND with the original mask: $VisibleRight = M \ \& \ (\sim M_{left})$. A bit is `1` in the result if the current voxel is solid AND the right neighbor is empty [S2, unofficial].
4.  **Mesh Generation:** Use the resulting visibility masks to determine which faces to include in the mesh. Only voxels with a `1` in the corresponding visibility mask contribute their respective faces [S2, unofficial].

**Formulas:**
*   Visible Left Faces: $V_L = M \ \& \ (\sim (M \gg 1))$
*   Visible Right Faces: $V_R = M \ \& \ (\sim (M \ll 1))$
    *   $M$: Bitmask of current slice.
    *   $\gg$: Bitwise right shift.
    *   $\ll$: Bitwise left shift.
    *   $\sim$: Bitwise NOT (inversion).
    *   $\&$: Bitwise AND.

**Parameters:**
*   Chunk dimensions: The method is typically applied to chunks of fixed height and width, e.g., 16x16 [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Boundary Conditions:** The shift operations implicitly handle boundaries by shifting in zeros (air) from the outside, which correctly identifies faces on the chunk's exterior as visible [S2, unofficial].
*   **Performance:** The original approach of looping through neighbors and performing random memory access leads to very poor performance [S2, unofficial]. This method avoids that by using bulk bitwise operations [S2, unofficial].
*   **Precision:** The integer type must be large enough to hold the entire slice or chunk dimension. For large chunks, arrays of integers are required [S2, unofficial].

**Pseudocode:**
```python
def binary_hidden_face_culling_1d(voxel_bits: int, chunk_width: int) -> tuple:
    """
    Determines visible left and right faces for a 1D slice of voxels.
    
    Args:
        voxel_bits: An integer representing the voxel states (1=solid, 0=air).
        chunk_width: The width of the chunk (number of bits).
        
    Returns:
        A tuple (visible_left, visible_right) where each is a bitmask.
    """
    # Ensure the bitmask fits within the integer type.
    # For chunk_width > 64, this would require an array of integers.
    if chunk_width > 64:
        raise ValueError("This simple implementation assumes chunk_width <= 64.")

    # Step 1: Represent Voxels (already done via input)
    M = voxel_bits

    # Step 2: Determine Visible Left Faces
    # Shift right by 1 to represent the neighbor to the left
    M_right = M >> 1
    # Invert to find air positions on the left
    air_left = ~M_right
    # Visible if current is solid AND left is air
    visible_left = M & air_left

    # Step 3: Determine Visible Right Faces
    # Shift left by 1 to represent the neighbor to the right
    M_left = M << 1
    # Invert to find air positions on the right
    air_right = ~M_left
    # Visible if current is solid AND right is air
    visible_right = M & air_right

    # Step 4: Mask out bits beyond chunk width (optional, depending on implementation)
    # This ensures that shifts don't carry over from outside the chunk
    mask = (1 << chunk_width) - 1
    visible_left &= mask
    visible_right &= mask

    return visible_left, visible_right
```

## Operating characteristics
*   **Time Complexity:** $O(1)$ per slice for bitwise operations, assuming the slice fits in a machine word. For larger slices, it is $O(N/W)$ where $N$ is the number of voxels and $W$ is the word size.
*   **Memory Complexity:** $O(1)$ additional memory for the masks, proportional to the slice size.
*   **Measured Performance:** Significantly faster than iterative neighbor checks, which suffer from poor performance due to random memory access [S2, unofficial].
*   **Strengths:** High performance for binary voxel data; simple implementation; reduces draw calls by removing hidden faces [S1, unofficial][S2, unofficial].
*   **Limitations:** Only works for binary (solid/empty) voxel states; requires data to be accessible in a linear or axis-aligned slice format [S2, unofficial].
*   **When to use:** When generating meshes for binary voxel worlds (e.g., Minecraft-like) and performance is critical.
*   **When not to use:** For partial voxel shapes requiring coverage masks (use [Face Coverage Mask Culling](3397-face-coverage-mask-culling.md) instead) or when voxel states are not binary.

## Background
*   **Origin:** The technique is described in a devlog for the game "YNL - Vozel" by Yunasawa [S2, unofficial]. It is also mentioned in the context of a voxel engine implementation by Eduardo Lavall [S1, unofficial].
*   **History:** It was developed as an optimization over the naive approach of checking each of the six faces for every voxel, which involved looping through a huge number of voxels and performing random memory access [S2, unofficial].
*   **Usage:** Used in voxel-based games and simulations where efficient mesh generation is required [S1, unofficial][S2, unofficial].
