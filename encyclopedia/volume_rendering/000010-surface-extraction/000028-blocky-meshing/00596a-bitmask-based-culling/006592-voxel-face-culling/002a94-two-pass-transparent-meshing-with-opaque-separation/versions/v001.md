# Two-pass transparent meshing with opaque separation

Also called: Deferred-style Transparent Rendering, Transparent Block Rendering, Two-pass World Rendering

## Overview
A meshing strategy that separates opaque and transparent geometry into two distinct passes to ensure correct rendering order and reduce overdraw [S1, S2, unofficial]. It solves the problem of rendering non-opaque blocks by generating opaque faces between air/transparent blocks and transparent faces only for blocks touching air [S1, S2, unofficial]. This method sets itself apart from single-pass voxel meshing by explicitly decoupling the geometry generation for opaque and transparent materials, allowing the renderer to draw the opaque world first and then the semi-transparent world on top without clearing the frame buffer [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A voxel chunk containing block types classified as opaque, transparent, or air.
*   **Output:** Two separate mesh data structures (or "worlds"): one for opaque geometry and one for transparent geometry.

**Data Structures:**
*   **Opaque World:** A collection of vertices and indices representing faces between opaque blocks and non-opaque neighbors (air or transparent).
*   **Transparent World:** A collection of vertices and indices representing faces between transparent blocks and air.

**Parameters:**
*   **Block Classification:** Each block type must be pre-classified as `opaque`, `transparent`, or `air`.
*   **Chunk Metadata:** A boolean flag indicating if the chunk contains any transparent blocks.

**Steps:**

1.  **Check for Transparency:** Determine if the current chunk contains any transparent blocks. If no transparent blocks exist, skip the second pass entirely and render only the opaque mesh [S1, unofficial].
2.  **Separate Worlds:** Conceptually separate the blocks into two sets: opaque blocks and transparent blocks [S2, unofficial].
3.  **First Pass (Opaque):**
    *   Generate faces for opaque blocks.
    *   If the chunk contains transparent blocks, test for opaque blocks only (ignoring transparent and air blocks as neighbors) [S1, unofficial]. This ensures opaque faces are generated between air and transparent blocks.
    *   If the chunk does not contain transparent blocks, test for non-air blocks as neighbors [S1, unofficial].
    *   Add the generated faces to the **Opaque World** [S2, unofficial].
4.  **Second Pass (Transparent):**
    *   Test for non-air blocks to mark only transparent blocks [S1, unofficial].
    *   Generate faces for all transparent blocks touching air.
    *   Do **not** add faces between transparent and solid (opaque) blocks, as these faces are already handled by the opaque pass [S1, unofficial].
    *   Add the generated faces to the **Transparent World** [S2, unofficial].
5.  **Filter Solid Faces in Transparent Pass:**
    *   Before constructing attributes (such as Ambient Occlusion) or adding a block type to the mesh hashmap, check if the current operation is the transparent pass [S1, unofficial].
    *   If it is the transparent pass, ignore any block types that are not transparent (i.e., skip opaque blocks) [S1, unofficial]. This prevents solid faces from being incorrectly added to the transparent mesh [S1, unofficial].

**Pseudocode:**

```python
def mesh_chunk(chunk, is_transparent_pass=False):
    """
    Mesh a voxel chunk.
    :param chunk: The voxel data structure.
    :param is_transparent_pass: Boolean flag indicating if this is the second pass.
    :return: List of faces (vertices/indices) for the current pass.
    """
    faces = []
    
    # Optimization: If not the first pass, we only care about transparent blocks
    # If it is the first pass, we care about opaque blocks (if transparents exist) or all solids (if not)
    
    has_transparent_blocks = chunk.contains_transparent_blocks()
    
    for block in chunk.blocks:
        # Step 5: Filter solid faces in transparent pass
        if is_transparent_pass:
            if not block.is_transparent():
                continue
        
        # Determine neighbor visibility based on pass type
        # Step 3: First pass logic
        if not is_transparent_pass:
            if has_transparent_blocks:
                # Test for opaque blocks only (ignore transparent and air)
                # Generate faces where opaque block touches air or transparent
                if block.is_opaque():
                    faces.extend(generate_faces(block, neighbor_filter=NON_OPAQUE))
            else:
                # Test for non-air blocks
                if not block.is_air():
                    faces.extend(generate_faces(block, neighbor_filter=NON_AIR))
        else:
            # Step 4: Second pass logic
            # Test for non-air blocks to mark only transparent blocks
            if not block.is_air():
                # Generate faces for transparent blocks touching air
                # Do not add faces between transparent and solid blocks
                if block.is_transparent():
                    faces.extend(generate_faces(block, neighbor_filter=AIR_ONLY))
                    
    return faces

def render_chunk(chunk):
    """
    Render a chunk using two-pass transparent meshing with opaque separation.
    """
    # Step 1: Check if the chunk contains any transparent blocks
    if not chunk.contains_transparent_blocks():
        # No transparent blocks: skip second pass
        opaque_faces = mesh_chunk(chunk, is_transparent_pass=False)
        render_mesh(opaque_faces)
        return

    # Step 2: Separate opaque and transparent blocks into two worlds
    # Step 3: First pass (opaque)
    opaque_faces = mesh_chunk(chunk, is_transparent_pass=False)
    
    # Step 4: Second pass (transparent)
    transparent_faces = mesh_chunk(chunk, is_transparent_pass=True)
    
    # Step 2 (Rendering): Mesh the opaque world and the transparent world separately
    
    # Step 2 (Rendering): Render the opaque world first
    render_mesh(opaque_faces)
    
    # Step 2 (Rendering): Render the semi-transparent world on top of the opaque world 
    # without clearing the frame buffer
    render_mesh(transparent_faces, blend_mode=TRANSPARENT)
```

**Edge Cases and Pitfalls:**
*   **Overdraw:** Incorrect ordering (rendering transparent before opaque) will result in visual artifacts. The opaque world must always be rendered first [S2, unofficial].
*   **Double Counting:** Faces between opaque and transparent blocks must only be generated in the opaque pass. If generated in the transparent pass, they will be rendered twice (once opaque, once transparent), causing incorrect blending and performance loss [S1, unofficial].
*   **Performance:** While this method is simple, it may process the chunk twice if transparency is present. However, since transparency is often rare compared to opaque blocks, the overhead is typically negligible [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of blocks in the chunk, with a constant factor of up to 2 if transparent blocks are present.
*   **Memory Complexity:** $O(F)$ where $F$ is the number of faces, split between two mesh buffers.
*   **Strengths:** Correctly handles transparency sorting without complex depth sorting; reduces overdraw by separating opaque geometry; simple to implement [S1, S2, unofficial].
*   **Limitations:** Requires two passes through the voxel data if transparency is present; not as efficient as fully culling transparent faces if they are never visible (though this is rare in open worlds) [S1, unofficial].
*   **When to use:** When rendering voxel-based environments with mixed opaque and transparent materials (e.g., glass, water, foliage) where correct alpha blending is required [S2, unofficial].
*   **When not to use:** When the scene contains only opaque blocks (single pass is sufficient) or when performance is critical and transparency is negligible [S1, unofficial].

## Background
This method is inspired by deferred rendering techniques for transparent objects and is commonly used in games like Minecraft and GTA [S2, unofficial]. It addresses the limitations of standard greedy meshing, which does not inherently handle transparency sorting, by explicitly separating the geometry generation process [S1, S2, unofficial].
