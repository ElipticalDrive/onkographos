# Cube Mesh


## Overview
Cube Mesh is a voxel-based terrain rendering acceleration structure that replaces traditional polygonal meshes with a set of axis-aligned cubes enclosing height field data [S1]. It solves the convexity limitations of the Envelope method by using adaptive quadtree subdivision to generate a tight bounding volume hierarchy, enabling efficient ray casting with early ray termination [S1]. Unlike sibling methods that rely on full Constructive Solid Geometry (CSG) or complex polygonal level-of-detail selection, Cube Mesh precomputes transformed unit cubes to minimize CPU computation for view-frustum culling and level-of-detail selection [S1].

## How it works
**Inputs:** A height field terrain data set (grid of height values $p_{i,j}$) [S1].
**Outputs:** A set of transformed cubes (Cube Mesh) and a quadtree structure storing minimum and maximum height values for each leaf node [S1].

**Data Structures:**
1. **Quadtree:** Hierarchical structure where each node represents a block of the height field [S1]. Leaf nodes store `min_h` (minimum height), `max_h` (maximum height), and `xy_coords` (2D spatial coordinates/origin of the block) [S1].
2. **Cube Mesh:** A collection of axis-aligned bounding boxes (AABBs) [S1]. Each cube is defined by its minimum and maximum world coordinates $(x_{min}, y_{min}, z_{min})$ and $(x_{max}, y_{max}, z_{max})$ [S1].

**Algorithm Steps:**
1. **Preprocessing: Quadtree Construction and Error Calculation**
   For each block in the initial grid:
   a. Calculate the average height $\varsigma$ for all points $p_{i,j}$ in the block, where $i \in [0, M-1]$ and $j \in [0, N-1]$:
   $$ \varsigma = \frac{1}{MN} \sum_{j=0}^{N-1} \sum_{i=0}^{M-1} p_{i,j} $$
   b. Calculate the error value $\varepsilon_h$ (variance):
   $$ \varepsilon_h = \frac{\sum_{j=0}^{N-1} \sum_{i=0}^{M-1} (p_{i,j} - \varsigma)^2}{MN} $$
   c. Calculate the height difference $\Delta$:
   $$ \Delta = \max(p_{i,j}) - \min(p_{i,j}) $$
   d. Determine if the block should be subdivided. If $\frac{\Delta}{\varepsilon_h} \ge c$, where $c$ is a constant controlling partition level, recursively subdivide the block into four children [S1]. Otherwise, mark as a leaf node and store `min_h`, `max_h`, and `xy_coords` [S1].
2. **Cube Generation**
   For each leaf node in the quadtree:
   a. Create a unit cube of size $1 \times 1 \times 1$ [S1].
   b. Transform the unit cube into world coordinates by translating and scaling it based on the block's `xy_coords`, `min_h`, and `max_h` [S1].
   c. The resulting cube perfectly encloses the terrain surface for that block [S1]. Specifically, the $z$-extent of the cube corresponds to $[min\_h, max\_h]$, and the $x,y$-extent corresponds to the spatial bounds of the block [S1].
3. **Storage for Acceleration**
   Store `min_h` and `max_h` in each leaf node [S1]. These values define the entry and exit points for ray traversal, enabling early ray termination during rendering [S1].

**Pseudocode:**
```python
import math

def build_cube_mesh(height_field, threshold_c):
    """
    height_field: 2D array of height values p[i][j]
    threshold_c: constant c for partitioning condition
    Returns: list of cubes, quadtree_leaves
    """
    quadtree_leaves = []
    H, W = len(height_field), len(height_field[0])

    def process_block(y_start, y_end, x_start, x_end):
        # Extract height values for the current block
        block_heights = [height_field[y][x] for y in range(y_start, y_end) for x in range(x_start, x_end)]
        M = x_end - x_start
        N = y_end - y_start

        if M == 1 and N == 1:
            # Leaf node for single point
            min_h = block_heights[0]
            max_h = block_heights[0]
            create_cube_and_store(y_start, y_end, x_start, x_end, min_h, max_h, quadtree_leaves)
            return

        # Calculate statistics
        avg_h = sum(block_heights) / len(block_heights)
        epsilon_h = sum((p - avg_h)**2 for p in block_heights) / len(block_heights)  # Eq. (1) in source

        min_h = min(block_heights)
        max_h = max(block_heights)
        delta = max_h - min_h

        # Partitioning condition
        if epsilon_h > 0 and (delta / epsilon_h) >= threshold_c:
            # Subdivide into four children
            mid_y = (y_start + y_end) // 2
            mid_x = (x_start + x_end) // 2
            process_block(y_start, mid_y, x_start, mid_x)
            process_block(y_start, mid_y, mid_x, x_end)
            process_block(mid_y, y_end, x_start, mid_x)
            process_block(mid_y, y_end, mid_x, x_end)
        else:
            # Leaf node
            create_cube_and_store(y_start, y_end, x_start, x_end, min_h, max_h, quadtree_leaves)

    def create_cube_and_store(y_start, y_end, x_start, x_end, min_h, max_h, leaves):
        # Start with a unit cube of size 1x1x1
        unit_cube = {'x_min': 0, 'y_min': 0, 'z_min': 0, 'x_max': 1, 'y_max': 1, 'z_max': 1}
        # Scale and translate to world coordinates based on block bounds and height range
        scale_x = x_end - x_start
        scale_y = y_end - y_start
        scale_z = max_h - min_h
        translate_x = float(x_start)
        translate_y = float(y_start)
        translate_z = min_h

        transformed_cube = {
            'x_min': unit_cube['x_min'] * scale_x + translate_x,
            'y_min': unit_cube['y_min'] * scale_y + translate_y,
            'z_min': unit_cube['z_min'] * scale_z + translate_z,
            'x_max': unit_cube['x_max'] * scale_x + translate_x,
            'y_max': unit_cube['y_max'] * scale_y + translate_y,
            'z_max': unit_cube['z_max'] * scale_z + translate_z
        }
        leaves.append(transformed_cube)

    process_block(0, H, 0, W)
    return quadtree_leaves
```

**Parameters:**
*   $c$: Constant controlling partition level. Not given in the sources.
*   $M, N$: Block dimensions. Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Division by Zero:** If $\varepsilon_h = 0$ (all points in a block have the same height), the condition $\frac{\Delta}{\varepsilon_h}$ is undefined [G]. A safe implementation should check for $\varepsilon_h < \epsilon$ and treat it as a leaf node if $\Delta$ is also small, or force subdivision if $\Delta > 0$ [G].
*   **Precision:** Floating-point precision in calculating $\varepsilon_h$ and $\Delta$ may affect the partitioning boundary [G].
*   **Source Contradiction:** The source text labels $\varepsilon_h$ as "standard deviation" but provides the variance formula $\frac{\sum \sum (p_{i,j} - \varsigma)^2}{MN}$ [S1]. The implementation uses the variance formula as written in Eq. (1) [S1].

## Subtopics

### Early Ray Termination
An acceleration technique that uses the stored `min_h` and `max_h` values to determine the interval of each ray that contributes to the final image, skipping sampling and color computation outside this interval [S1].

### GPU Acceleration
The Cube Mesh method is designed for GPU-based rendering, exploiting the structure for efficient rasterization and view-frustum culling, reducing CPU computation compared to traditional polygonal methods [S1].

## Operating characteristics
*   **Time Complexity:** Preprocessing involves quadtree construction, which is generally $O(N \log N)$ for $N$ points, depending on the subdivision threshold [G]. Rendering time is reduced compared to the Envelope method, being approximately twice as fast in the reported experiments [S1].
*   **Memory Complexity:** The memory usage depends on the number of leaf nodes in the quadtree. Smaller blocks (higher subdivision) increase the number of cubes and memory usage but improve empty space skipping efficiency [S1].
*   **Measured Performance:** Tested on a PC with Pentium IV 3.0GHz CPU, 1GB RAM, and NVIDIA GeForce 6600 GPU. Used Puget height field data (512x512 resolution) and a 640x480 viewport. The method was about twice as fast as the Envelope method [S1].
*   **Strengths:** Efficient for walk-through applications; reduces CPU computation for view-frustum culling and LOD selection; tight bounding volumes improve ray casting acceleration [S1].
*   **Limitations:** Trade-off between block size and polygon count; smaller blocks increase rendering load due to more polygons [S1].

## Background
The Cube Mesh method was proposed by D.-S. Kang and B.-S. Shin in 2008 [S1]. It was developed to address the high CPU computation requirements of view-frustum culling and level-of-detail selection in previous terrain rendering approaches, making them unsuitable for real-time walk-through applications [S1]. The method expands on the conventional PARC (Polygon Assisted Ray Casing) algorithm by applying the Cube Mesh structure to accelerate GPU-based terrain rendering [S1].
