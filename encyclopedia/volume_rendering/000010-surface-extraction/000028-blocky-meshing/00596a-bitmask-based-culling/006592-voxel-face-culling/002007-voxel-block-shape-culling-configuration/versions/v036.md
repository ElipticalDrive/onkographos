# Voxel Block Shape & Culling Configuration

Also called: Block trait interface, Shape enum system

## Overview
Voxel Block Shape & Culling Configuration is a trait-based configuration system for voxel mesh generation that defines block geometry, transparency culling, and lighting per block type [S1, unofficial]. It solves the problem of rigid, single-shape meshing by allowing each block type to specify its own shape (e.g., cube, ramp, fluid) and culling behavior (e.g., opaque, transparent merged, transparent unmerged) [S1, unofficial]. It sets itself apart from [Face Culling](13637-face-culling.md) by providing the *rules* for when and how faces are culled and shaped, rather than the geometric algorithm that removes adjacent faces [G]. It differs from [Voxel Block Placement with Face Culling](923-voxel-block-placement-with-face-culling.md) by decoupling the block's logical identity and rendering properties from its physical placement logic [G].

## How it works
The system operates by associating a configuration object (often a trait or interface implementation) with each block type [S1, unofficial]. This configuration dictates the geometry to generate, the culling mode to apply, and the lighting values to use [S1, unofficial].

### Inputs and Outputs
*   **Input:** A block type identifier (e.g., `MyBlock::Glass`) and the face orientation being evaluated (e.g., `AlignedFace::PosZ`) [S1, unofficial].
*   **Output:** A `Shape` enum value, a `CullMode` enum value, and lighting parameters (ambient occlusion, smooth light) [S1, unofficial].

### Data Structures

#### Shape Enum
The `Shape` enum defines the geometry to generate for a specific face of a block [S1, unofficial]. Common variants include:
*   `WholeBlock`: A full unit cube face [S1, unofficial].
*   `Cross(CrossInfo)`: A cross-shaped face, used for thin objects like chains or rails [S1, unofficial].
    *   `CrossInfo` fields:
        *   `face`: `AlignedFace` (e.g., `PosZ`, `NegY`) [S1, unofficial].
        *   `stretch`: `f32` (0.0 for standard cross, other values for stretched variants) [S1, unofficial].
*   `Ramp`: A sloped face (see [Ramp Shape Geometry](#ramp-shape-geometry)) [S2, unofficial].
*   `Fluid`: A fluid surface (see [Fluid Surface Stitching](#fluid-surface-stitching)) [S1, unofficial].

#### CullMode Enum
The `CullMode` enum determines how faces are culled based on neighbor transparency [S1, unofficial].
*   `Empty`: The block is air; no geometry is generated [S1, unofficial].
*   `Opaque`: The block is fully opaque. Faces are generated if the neighbor is empty or opaque [G]. Shared faces between two opaque blocks are culled [G].
*   `TransparentMerged(T)`: The block is transparent. Faces are generated if the neighbor is empty or opaque [G]. Shared faces between two transparent blocks are culled **only if** their `TransparentGroup` values are equal [S1, unofficial]. This allows water to merge with water but not with glass [S1, unofficial].
*   `TransparentUnmerged`: The block is transparent. Faces are generated if the neighbor is empty or opaque [G]. Shared faces between two transparent blocks are **never** culled, even if they are the same type [S1, unofficial]. This is used for blocks like leaves or cobwebs where internal structure visibility is desired or where merging causes visual artifacts [S1, unofficial].

#### Vertex Layout
Vertices generated by the shape configuration include [S1, unofficial]:
*   `pos`: `Vec4<f32>` (position).
*   `uv`: `Vec2<f32>` (texture coordinates).
*   `normal`: `Vec3<f32>` (face normal).
*   `ao`: `f32` (per-vertex ambient occlusion, 0.0 = fully occluded, 1.0 = fully lit) [S1, unofficial].
*   `smooth_light`: `f32` (per-vertex smooth light, 0.0..1.0) [S1, unofficial].
*   `block`: `MyBlock` (block type for render pass filtering) [S1, unofficial].
*   `atlas_offset`: `f32` (pre-computed atlas tile offset) [S1, unofficial].
*   `two_sided`: `bool` (whether the vertex belongs to a two-sided quad) [S1, unofficial].

#### Interpolated Vertex-to-Fragment Data (`VsOut`)
*   `uv`: `Vec2<f32>` [S1, unofficial].
*   `normal`: `Vec3<f32>` [S1, unofficial].
*   `atlas_u_offset`: `f32` [S1, unofficial].
*   `ao`: `f32` [S1, unofficial].
*   `smooth_light`: `f32` [S1, unofficial].

### Steps

1.  **Block Configuration Lookup:** For each non-empty block in the chunk, retrieve its configuration trait/interface [S1, unofficial].
2.  **Shape Determination:** Call the `shape(face)` method on the configuration, passing the current face orientation [S1, unofficial]. This returns a `Shape` enum variant [S1, unofficial].
    *   Example: `MyBlock::ChainZ` returns `Shape::Cross(CrossInfo { face: AlignedFace::PosZ, stretch: 0 })` [S1, unofficial].
    *   Example: `MyBlock::Cobblestone` returns `Shape::WholeBlock` [S1, unofficial].
3.  **Culling Mode Determination:** Call the `cull_mode()` method on the configuration [S1, unofficial]. This returns a `CullMode` enum variant [S1, unofficial].
    *   Example: `MyBlock::Glass` returns `CullMode::TransparentMerged(())` [S1, unofficial].
    *   Example: `MyBlock::Leaves` returns `CullMode::TransparentUnmerged` [S1, unofficial].
4.  **Lighting Determination:** Call the `light(face)` method on the configuration [S1, unofficial]. This returns lighting values (ambient occlusion, smooth light) specific to the block and face [S1, unofficial].
    *   Example: `MyBlock::Cactus` on `PosY` returns 11.0, on `NegY` returns 12.0, otherwise 10.0 [S1, unofficial].
    *   Example: `MyBlock::Air` returns 0.0 [S1, unofficial].
5.  **Geometry Generation:** Based on the `Shape` enum, generate the appropriate vertices and indices [S1, unofficial].
    *   For `WholeBlock`, generate a standard quad [S1, unofficial].
    *   For `Cross`, generate the cross-shaped geometry [S1, unofficial].
    *   For `Ramp`, generate the slope quad and side triangles [S2, unofficial].
    *   For `Fluid`, generate the stitched surface [S1, unofficial].
6.  **Culling Application:** Apply the `CullMode` rules to determine if the generated geometry should be added to the mesh [S1, unofficial].
    *   If `CullMode::Opaque`, cull if neighbor is occupied [G].
    *   If `CullMode::TransparentMerged(T)`, cull if neighbor is occupied AND neighbor's `TransparentGroup` == current block's `TransparentGroup` [S1, unofficial].
    *   If `CullMode::TransparentUnmerged`, cull only if neighbor is occupied (never cull shared transparent faces) [S1, unofficial].
7.  **Mesh Assembly:** Add vertices and indices to the chunk's linked list [S3, unofficial]. Once all blocks are processed, transfer data to the GPU mesh object on the main thread [S3, unofficial].

### Pseudocode

```python
from enum import Enum
from typing import Optional, List, Tuple

class MyBlock(Enum):
    AIR = 0
    COBBLESTONE = 1
    GLASS = 2
    LEAVES = 3
    CACTUS = 4
    SUGAR_CANE = 5
    COBWEB = 6
    SHRUB = 7
    LADDER = 8
    RAIL = 9
    CHAIN_Y = 10
    CHAIN_X = 11
    CHAIN_Z = 12
    LAMP = 13
    DEBUG = 14

class AlignedFace(Enum):
    PosX, NegX, PosY, NegY, PosZ, NegZ = range(6)

class Shape(Enum):
    WHOLE_BLOCK = 0
    CROSS = 1
    RAMP = 2
    FLUID = 3

class CrossInfo:
    def __init__(self, face: AlignedFace, stretch: float):
        self.face = face
        self.stretch = stretch

class CullMode(Enum):
    EMPTY = 0
    OPAQUE = 1
    TRANSPARENT_MERGED = 2
    TRANSPARENT_UNMERGED = 3

class Vertex:
    def __init__(self, pos, uv, normal, ao, smooth_light, block, atlas_offset, two_sided):
        self.pos = pos
        self.uv = uv
        self.normal = normal
        self.ao = ao
        self.smooth_light = smooth_light
        self.block = block
        self.atlas_offset = atlas_offset
        self.two_sided = two_sided

class Geometry:
    def __init__(self, vertices: List[Vertex]):
        self.vertices = vertices

def get_block_config(block: MyBlock) -> dict:
    """Returns configuration dict for a block type."""
    return {
        MyBlock.AIR: {"shape": Shape.WHOLE_BLOCK, "cull": CullMode.EMPTY, "light": 0.0},
        MyBlock.COBBLESTONE: {"shape": Shape.WHOLE_BLOCK, "cull": CullMode.OPAQUE, "light": 1.0},
        MyBlock.GLASS: {"shape": Shape.WHOLE_BLOCK, "cull": CullMode.TRANSPARENT_MERGED, "light": 2.0},
        MyBlock.LEAVES: {"shape": Shape.WHOLE_BLOCK, "cull": CullMode.TRANSPARENT_UNMERGED, "light": 3.0},
        MyBlock.CACTUS: {"shape": Shape.WHOLE_BLOCK, "cull": CullMode.TRANSPARENT_UNMERGED, "light": 10.0},
        MyBlock.SUGAR_CANE: {"shape": Shape.WHOLE_BLOCK, "cull": CullMode.TRANSPARENT_UNMERGED, "light": 4.0},
        MyBlock.COBWEB: {"shape": Shape.WHOLE_BLOCK, "cull": CullMode.TRANSPARENT_UNMERGED, "light": 5.0},
        MyBlock.SHRUB: {"shape": Shape.WHOLE_BLOCK, "cull": CullMode.TRANSPARENT_UNMERGED, "light": 6.0},
        MyBlock.LADDER: {"shape": Shape.WHOLE_BLOCK, "cull": CullMode.TRANSPARENT_UNMERGED, "light": 7.0},
        MyBlock.RAIL: {"shape": Shape.WHOLE_BLOCK, "cull": CullMode.TRANSPARENT_UNMERGED, "light": 8.0},
        MyBlock.CHAIN_Y: {"shape": Shape.CROSS, "cull": CullMode.TRANSPARENT_UNMERGED, "light": 13.0},
        MyBlock.CHAIN_X: {"shape": Shape.CROSS, "cull": CullMode.TRANSPARENT_UNMERGED, "light": 13.0},
        MyBlock.CHAIN_Z: {"shape": Shape.CROSS, "cull": CullMode.TRANSPARENT_UNMERGED, "light": 13.0},
        MyBlock.LAMP: {"shape": Shape.WHOLE_BLOCK, "cull": CullMode.OPAQUE, "light": 14.0},
        MyBlock.DEBUG: {"shape": Shape.WHOLE_BLOCK, "cull": CullMode.OPAQUE, "light": 9.0},
    }[block]

def generate_whole_block_vertices(face: AlignedFace) -> List[Vertex]:
    """Generates a standard quad for a whole block face."""
    return [Vertex(pos=(0,0,0), uv=(0,0), normal=(0,0,1), ao=1.0, smooth_light=1.0, block=MyBlock.AIR, atlas_offset=0.0, two_sided=False)]

def generate_cross_vertices(info: CrossInfo, face: AlignedFace) -> List[Vertex]:
    """Generates cross-shaped geometry for thin blocks."""
    return [Vertex(pos=(0,0,0), uv=(0,0), normal=(0,0,1), ao=1.0, smooth_light=1.0, block=MyBlock.AIR, atlas_offset=0.0, two_sided=False)]

def generate_ramp_vertices(face: AlignedFace) -> List[Vertex]:
    """Generates slope quad and side triangles."""
    return [Vertex(pos=(0,0,0), uv=(0,0), normal=(0,0,1), ao=1.0, smooth_light=1.0, block=MyBlock.AIR, atlas_offset=0.0, two_sided=False)]

def generate_fluid_vertices(block: MyBlock, face: AlignedFace) -> List[Vertex]:
    """Generates stitched fluid surface."""
    return [Vertex(pos=(0,0,0), uv=(0,0), normal=(0,0,1), ao=1.0, smooth_light=1.0, block=MyBlock.AIR, atlas_offset=0.0, two_sided=False)]

def is_transparent(block: MyBlock) -> bool:
    """Check if a block is considered transparent for culling purposes."""
    return block in [MyBlock.GLASS, MyBlock.LEAVES, MyBlock.CACTUS, MyBlock.SUGAR_CANE, 
                     MyBlock.COBWEB, MyBlock.SHRUB, MyBlock.LADDER, MyBlock.RAIL,
                     MyBlock.CHAIN_Y, MyBlock.CHAIN_X, MyBlock.CHAIN_Z]

def get_transparent_group(block: MyBlock) -> int:
    """Get the transparent group for a block. Blocks in the same group can merge."""
    if block == MyBlock.GLASS:
        return 2
    elif block == MyBlock.LEAVES:
        return 3
    else:
        return 1  # Default transparent group (e.g., water)

def should_cull(cull_mode: CullMode, block: MyBlock, neighbor: MyBlock) -> bool:
    """Determine if a face should be culled based on culling mode and neighbor."""
    if cull_mode == CullMode.EMPTY:
        return True
    if neighbor == MyBlock.AIR:
        return False
    if cull_mode == CullMode.OPAQUE:
        return True
    if cull_mode == CullMode.TRANSPARENT_MERGED:
        if is_transparent(neighbor) and get_transparent_group(block) == get_transparent_group(neighbor):
            return True
        return False
    if cull_mode == CullMode.TRANSPARENT_UNMERGED:
        return True
    return False

def generate_block_geometry(block: MyBlock, face: AlignedFace, neighbor: MyBlock) -> Optional[Geometry]:
    """Generate geometry for a single block face based on its configuration."""
    config = get_block_config(block)
    shape = config["shape"]
    cull_mode = config["cull"]
    
    if should_cull(cull_mode, block, neighbor):
        return None
    
    if shape == Shape.WHOLE_BLOCK:
        vertices = generate_whole_block_vertices(face)
    elif shape == Shape.CROSS:
        vertices = generate_cross_vertices(CrossInfo(face, 0.0), face)
    elif shape == Shape.RAMP:
        vertices = generate_ramp_vertices(face)
    elif shape == Shape.FLUID:
        vertices = generate_fluid_vertices(block, face)
    else:
        raise ValueError(f"Unknown shape: {shape}")
    
    light_val = config["light"]
    for v in vertices:
        v.ao = light_val
        v.smooth_light = light_val
        v.block = block
    
    return Geometry(vertices)
```

### Parameters
*   `FLUID_ENABLED`: Boolean flag. If `true`, fluid shapes are enabled. If `false`, fluids are treated as cubes. Setting `FLUID_ENABLED` to `true` without implementing fluid shape causes a debug assertion failure rather than silently drawing fluids as cubes [S1, unofficial].
*   `TransparentGroup`: Integer value assigned to each transparent block type. Used for `TransparentMerged` culling [S1, unofficial].

### Edge Cases and Pitfalls
*   **Fluid Shape Implementation:** Setting `FLUID_ENABLED` to `true` without implementing the fluid shape logic causes a debug assertion failure [S1, unofficial].
*   **Threading:** Unity3D functions must be called on the main thread. While vertex/index calculation is done on a background thread, the final Mesh object creation must be moved to the main thread [S3, unofficial].
*   **CullMode::TransparentMerged:** This mode culls shared faces between two transparent blocks when their `TransparentGroup` values are equal, but does not replace `Self: PartialEq` for greedy meshing [S1, unofficial]. This means greedy meshing must still handle the merging of identical transparent blocks correctly [S1, unofficial].

## Subtopics

### [Three-Valued Opacity Classification for Meshing](4414-three-valued-opacity-classification-for-meshing.md)
A classification system for block IDs into three mutually exclusive layers ('opaque', 'water', 'transparentSolid') to determine rendering material and buffer assignment. It solves the insufficiency of a single boolean 'transparent' flag by distinguishing between fluids (water) requiring bespoke shaders and see-through solids (glass/leaves) requiring alpha blending. Unlike a boolean transparent flag which collapses water and glass/leaves into one category, this three-valued model allows water to use a bespoke shader (ripple, refraction) while glass/leaves use the ordinary block atlas with alpha blending.

### [VoxelBlockyTypeLibrary with Attributes](12820-voxelblockytypelibrary-with-attributes.md)
`VoxelBlockyTypeLibrary` is an alternative library type that contains a list of `VoxelBlockyType` objects instead of models directly. It defines a 'block type' with attributes representing states (e.g., orientation, pressed state), similar to Minecraft block states. It solves the problem of managing complex block behaviors by automatically generating unique numerical IDs for every combination of attribute values, similar to Minecraft's block state system. It differs from the standard `VoxelBlockyLibrary` by decoupling model identity from manual ID assignment, using a combinatorial attribute system instead.

### [Voxel Shape Definition](20503-voxel-shape-definition.md)
Voxel Shape Definition is a method for defining complex block boundaries using one or more axis-aligned bounding boxes (AABBs) aligned to the 3-D world grid. It solves the problem of determining which faces of adjacent blocks are occluded and which require rendering, as well as handling collision detection for block connectivity. It is distinct from general geometry definitions by operating on a discrete pixel grid (1/16th of a block) with an origin at the block corner, rather than a continuous space with an origin at the block center.

### Ramp Shape Geometry
A shape representing a sloped block face, composed of a slope quad (2 triangles) and two side triangles (left and right) [S2, unofficial]. Instance creation: Iterate visible faces. If face is Left, Right, Top, or Front, set `drawSlope = true` and assign tint to `tints[0]` (Top/Front), `tints[1]` (Left), or `tints[2]` (Right). If a specific tint is `Vector3.One`, fallback to another face's tint. Add instances for slope, left triangle, and right triangle using respective shape IDs and tints. If face is Back or Bottom, add instance using `cubeBackFaceShapeID` or `cubeBottomFaceShapeID` [S2, unofficial]. Slope vertices (6 vertices): (0,1,0) with UV[0], (0,0,1) with UV[1], (1,1,0) with UV[2], (1,1,0) with UV[3], (0,0,1) with UV[4], (1,0,1) with UV[5]. Left triangle vertices (3 vertices): (0,0,1) with UV[0], (0,1,0) with UV[1], (0,0,0) with UV[2]. Right triangle vertices (3 vertices): (1,0,0) with UV[0], (1,1,0) with UV[1], (1,0,1) with UV[2] [S2, unofficial].

### Fluid Surface Stitching
A mesh generation technique where fluid columns share a surface height field with neighbors, stitching surfaces when fluid IDs match [S1, unofficial]. Two adjacent fluid blocks join their surfaces only when their `FluidInfo::id` (u8) values match [S1, unofficial].

### Geometry Builder Pattern
A design pattern using an interface to control the type of geometry created for each non-empty voxel, allowing different geometry types (cubes, ramps, X-shapes) to be generated via polymorphism without large switch statements [S3, unofficial]. During mesh creation, call `BuildGeometry()` once for each non-empty block. Pass a reference to the chunk object to `BuildGeometry()`. Inside `BuildGeometry()`, use the chunk reference to add vertices and indices to the chunk's linked list. After `BuildGeometry()` has been called on every block for the chunk, place the vertex and index data into a Unity3D Mesh object on the main thread [S3, unofficial]. Interface `IGeometryBuilder` contains a single function: `BuildGeometry()` [S3, unofficial]. Unity3D functions must be called on the main thread. While vertex/index calculation is done on a background thread, the final Mesh object creation must be moved to the main thread [S3, unofficial].

### Block Type Flags
Block flags modify meshing/rendering behavior: `V3_INACTIVE (0x00)`, `V32_FILLER (0x01)`, `V32_NO_FILL (0x02)`, `V32_SPRITE (0x04)`, `V32_NO_OCCLUDE (0x08)`, `V32_NO_GREEDY (0x10)` [S4, unofficial].

## Operating characteristics
*   **Time Complexity:** O(N) where N is the number of blocks in the chunk, as each block is processed once to determine its shape and culling status [S1, unofficial].
*   **Memory Complexity:** O(N) for storing the vertex and index data for the chunk [S3, unofficial].
*   **Strengths:** Flexible support for diverse block types (cubes, ramps, fluids, cross shapes) [S1, unofficial]. Efficient culling reduces triangle count [S1, unofficial]. Decoupled configuration allows easy addition of new block types [S3, unofficial].
*   **Limitations:** Requires careful implementation of culling modes to avoid visual artifacts [S1, unofficial]. Threading constraints in Unity3D require careful management of mesh creation [S3, unofficial]. Debug assertion failures can occur if fluid shapes are enabled but not implemented [S1, unofficial].
*   **When to use:** When rendering voxel worlds with diverse block types requiring different geometries and culling behaviors [S1, unofficial].
*   **When not to use:** When all blocks are simple cubes and no complex culling is needed; a simpler meshing algorithm may suffice [G].

## Background
The concept of block-specific shape and culling configuration originated in voxel game development, particularly in Minecraft-like games, where different block types (water, glass, leaves, rails) require different rendering behaviors [S1, unofficial]. The trait-based interface approach was formalized in projects like `finnbear/voxmesh` [S1, unofficial] and `rarefushion/Cubic-Grid_Voxel_Renderer` [S2, unofficial]. The Geometry Builder pattern was introduced in academic work on procedural generation of voxel worlds, such as the thesis "Procedural Generation of Voxel Worlds with Castles" [S3, unofficial], to manage complex geometry generation without large switch statements [S3, unofficial].
