# Topology-based Mesh Initialization


## Overview
Topology-based Mesh Initialization generates initial 3D meshes for shape-from-projections optimization by parsing topology type and component/material counts from a dataset name string [S1, unofficial]. It differs from voxel-based blocky meshing methods by constructing parametric primitives (tori, icospheres) rather than extracting geometry from a density field [S1, unofficial]. This method is chosen when the target geometry is known to be composed of specific topological classes rather than arbitrary volumetric data.

## How it works
**Inputs and Outputs:**
*   **Input:** A `data` string encoding topology type (last character) and number of components (characters at indices -3 to -1) [S1, unofficial].
*   **Input:** `width_physical` (scene scale derived from detector spacing/count), `radius` (base radius factor, typically 0.4), `subdivision` (icosphere tessellation level, typically 3) [S1, unofficial].
*   **Input:** `nmaterials` (number of distinct attenuation values) [S1, unofficial].
*   **Output:** A list of meshes, each containing vertices, faces, and label pairs `[label_v, label_f]` [S1, unofficial].

**Data Structures:**
*   `cc`: A `10x3` numpy array of `float32` defining predefined center offsets for inner components, scaled by 0.5 [S1, unofficial].
*   `lf_list`: A list of label pairs `[label_v, label_f]` corresponding to each mesh component [S1, unofficial].

**Steps:**
1.  **Parse Data String:** Extract `topology_type` from `data[-1]` and `ncomponents` from `data[-3:-1]` [S1, unofficial].
    *   *Pitfall:* If `data[-1]` is not 'A'-'Z' or `data[-3:-1]` is not convertible to an integer, raise `NotImplementedError` [S1, unofficial].
2.  **Compute Radius:** Calculate `radius_ = width_physical * radius` [S1, unofficial].
3.  **Initialize Offsets:** Load predefined center coordinates `cc` (10 points) [S1, unofficial].
4.  **Branch on Topology Type:**
    *   **'A':** Create single/multiple tori or icospheres based on `ncomponents` [S1, unofficial].
    *   **'B':** Create `ncomponents` independent icospheres, offset by `cc` [S1, unofficial].
    *   **'C':** Create nested icospheres for recursive materials [S1, unofficial].
    *   **'D':** Create an outer shell with inner icospheres [S1, unofficial].
5.  **Generate Geometry:** For each component, generate vertices and faces using the specified `subdivision` level and `radius_` [S1, unofficial].
6.  **Assign Labels:** Assign material labels to vertices and faces based on `nmaterials` and topology structure [S1, unofficial].
7.  **Save:** Output meshes using `util_mesh.save_mesh` or `save_obj_meshes_labels` [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Depends on the number of components and subdivision level. Icosphere generation is $O(N)$ where $N$ is the number of vertices.
*   **Memory Complexity:** Proportional to the number of vertices and faces generated.
*   **Strengths:** Provides clean, manifold geometry suitable for optimization-based shape reconstruction.
*   **Limitations:** Limited to predefined topological classes (A-D). Cannot represent arbitrary shapes without complex nesting or combination.
*   **When to use:** When the target object is known to be a combination of simple topological primitives (tori, spheres) and shape-from-projections optimization is used.
*   **When not to use:** For arbitrary volumetric data or complex organic shapes not representable by the defined topology types.

## Background
This method originates from the ShapeFromProjections repository by Jake Young [S1, unofficial]. It is used in the context of differentiable volume rendering and shape-from-projections optimization, where initial mesh topology guides the optimization process. The method parses dataset names to automatically configure the initial geometry based on expected topology and component count.
