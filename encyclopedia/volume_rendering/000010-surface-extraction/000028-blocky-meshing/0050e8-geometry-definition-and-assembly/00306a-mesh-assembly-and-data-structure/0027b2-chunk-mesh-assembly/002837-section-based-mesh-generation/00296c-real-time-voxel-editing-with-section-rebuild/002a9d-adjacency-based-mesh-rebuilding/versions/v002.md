# Adjacency-Based Mesh Rebuilding

Also called: Incremental Section Mesh Update, Section Rebuild

## Overview
Adjacency-Based Mesh Rebuilding is a method for maintaining chunked voxel meshes by regenerating geometry only for the chunk containing a modified voxel and any immediately adjacent chunks that share a face with it [S1, unofficial]. It solves the problem of visual artifacts at chunk boundaries when internal topology changes, distinguishing itself from static meshing by its incremental nature and from full-scene rebuilds by its localized scope [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** The local coordinates $(lx, ly, lz)$ of the modified voxel within its chunk, the world coordinates $(wx, wy, wz)$ of that voxel, and the chunk dimensions $(CHUNK\_SIZE)$.
*   **Output:** Updated mesh data structures for the affected chunks.

**Data Structures:**
*   **Chunk:** A cubic block of voxels with dimensions $CHUNK\_SIZE \times CHUNK\_SIZE \times CHUNK\_SIZE$.
*   **Voxel Position:** Represented as local $(lx, ly, lz)$ relative to the chunk origin and world $(wx, wy, wz)$ relative to the global grid.

**Steps:**
1.  Determine the local position $(lx, ly, lz)$ of the voxel that was added or removed.
2.  Determine the world position $(wx, wy, wz)$ of the modified voxel.
3.  Check if the modification occurred on the X-axis boundary:
    *   If $lx == 0$, the voxel is on the negative X face. Rebuild the mesh of the adjacent chunk at world coordinates $(wx - 1, wy, wz)$.
    *   If $lx == CHUNK\_SIZE - 1$, the voxel is on the positive X face. Rebuild the mesh of the adjacent chunk at world coordinates $(wx + 1, wy, wz)$.
4.  Check if the modification occurred on the Y-axis boundary:
    *   If $ly == 0$, the voxel is on the negative Y face. Rebuild the mesh of the adjacent chunk at world coordinates $(wx, wy - 1, wz)$.
    *   If $ly == CHUNK\_SIZE - 1$, the voxel is on the positive Y face. Rebuild the mesh of the adjacent chunk at world coordinates $(wx, wy + 1, wz)$.
5.  Check if the modification occurred on the Z-axis boundary:
    *   If $lz == 0$, the voxel is on the negative Z face. Rebuild the mesh of the adjacent chunk at world coordinates $(wx, wy, wz - 1)$.
    *   If $lz == CHUNK\_SIZE - 1$, the voxel is on the positive Z face. Rebuild the mesh of the adjacent chunk at world coordinates $(wx, wy, wz + 1)$.
6.  Always rebuild the mesh of the chunk containing the modified voxel, regardless of boundary position.

**Pseudocode:**
```python
def rebuild_adjacent_chunks(modified_voxel_local_pos, modified_voxel_world_pos, chunk_size):
    lx, ly, lz = modified_voxel_local_pos
    wx, wy, wz = modified_voxel_world_pos

    # Rebuild the chunk containing the modified voxel
    rebuild_chunk_mesh(modified_voxel_world_pos)

    # Check X boundaries
    if lx == 0:
        rebuild_chunk_mesh((wx - 1, wy, wz))
    if lx == chunk_size - 1:
        rebuild_chunk_mesh((wx + 1, wy, wz))

    # Check Y boundaries
    if ly == 0:
        rebuild_chunk_mesh((wx, wy - 1, wz))
    if ly == chunk_size - 1:
        rebuild_chunk_mesh((wx, wy + 1, wz))

    # Check Z boundaries
    if lz == 0:
        rebuild_chunk_mesh((wx, wy, wz - 1))
    if lz == chunk_size - 1:
        rebuild_chunk_mesh((wx, wy, wz + 1))
```

**Parameters:**
*   $CHUNK\_SIZE$: The dimension of a single chunk in voxels. Typical values are 16 or 32. Not given in the sources.

**Edge Cases:**
*   **Boundary Checks:** The logic relies on exact equality with $0$ and $CHUNK\_SIZE - 1$. If a voxel is not on the boundary, no adjacent chunks are rebuilt.
*   **Degenerate Input:** If the chunk size is less than 2, the boundary conditions may overlap or behave unexpectedly. Not given in the sources.

## Operating characteristics
*   **Time Complexity:** $O(1)$ relative to the total world size, as it only processes a constant number of chunks (1 to 7) per modification.
*   **Memory Complexity:** $O(1)$ additional memory per modification, as it reuses existing chunk structures.
*   **Strengths:** Minimal computational overhead for frequent small edits; ensures visual consistency at chunk boundaries.
*   **Limitations:** Does not handle non-adjacent topology changes; requires careful synchronization if multiple edits occur simultaneously.
*   **When to use:** Real-time voxel editing where performance is critical and edits are localized.
*   **When not to use:** When large-scale topology changes occur that affect distant chunks or when lighting/vegetation updates are not required.

## Background
This method is derived from implementations in voxel-based games, specifically those mimicking Minecraft's chunk-based rendering system [S1, unofficial]. It addresses the need for efficient mesh updates in dynamic environments where voxels are frequently added or removed.
