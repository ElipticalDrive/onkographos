# VoxelMesher::build_mesh


## Overview
`VoxelMesher::build_mesh` constructs a Godot `ArrayMesh` from voxel buffer data, handling material assignment, surface assembly, and optional Transvoxel detail normal map generation [S1, unofficial]. It serves as the final assembly step in the blocky meshing pipeline, converting abstract voxel topology into renderable geometry [S1, unofficial]. It differs from [Section-based Mesh Generation](4220-section-based-mesh-generation.md) by assembling complete `ArrayMesh` objects with material handling rather than generating raw vertex buffers, and from [Chunk Region Meshing with Dirty Regions](4402-chunk-region-meshing-with-dirty-regions.md) by focusing on the mesh construction logic itself rather than the culling or region management [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A struct containing the voxel buffer, an optional generator (for Transvoxel), origin in voxels, LOD index, and flags for detail rendering [S1, unofficial].
*   **Output:** A struct containing a list of surfaces, each with primitive type, arrays (vertices, normals, indices, etc.), material index, and mesh flags [S1, unofficial].
*   **Return:** A Godot `ArrayMesh` instance [S1, unofficial].

**Data Structures:**
The method relies on internal lookup tables for topology [S1, unofficial]. Key constants include:
*   `g_side_normals[SIDE_COUNT]`: Normal vectors for the 6 cube faces. The source contains a documented bug where `LEFT` is defined as `(1, 0, 0)` instead of `(-1, 0, 0)` and `BACK` as `(0, 0, -1)` instead of `(0, 0, 1)` [S1, unofficial].
*   `g_side_corners[SIDE_COUNT][4]`: Vertex indices for each face [S1, unofficial].
*   `g_side_edges[SIDE_COUNT][4]`: Edge indices for each face [S1, unofficial].
*   `g_corner_inormals[CORNER_COUNT]`: Inverse normals for corners [S1, unofficial].
*   `g_edge_inormals[EDGE_COUNT]`: Inverse normals for edges [S1, unofficial].
*   `g_ordered_moore_area_3d[MOORE_AREA_3D_COUNT]`: 27 relative offsets for neighbor checks, ordered to avoid deadlocks in multithreaded contexts [S1, unofficial].

**Steps:**
1.  **Initialize Input and Output:** Create input and output structs. Initialize input with the voxel buffer, null generator, origin `(0,0,0)`, LOD index `0`, and three false flags [S1, unofficial].
2.  **Process Additional Data:** If `additional_data` is provided, extract `generator`, `origin_in_voxels`, and detail rendering settings [S1, unofficial]. Clamp `normalmap_max_deviation_degrees` to `MIN_DEVIATION_DEGREES` and `MAX_DEVIATION_DEGREES` [S1, unofficial]. Set `input.detail_texture_hint` based on the enabled flag [S1, unofficial].
3.  **Core Build:** Invoke the core build function with the prepared `input` and `output` structs [S1, unofficial].
4.  **Empty Check:** If `output.surfaces` is empty, return an empty `ArrayMesh` reference [S1, unofficial].
5.  **Mesh Assembly:** Instantiate an `ArrayMesh` [S1, unofficial]. Iterate over `output.surfaces`. Skip surfaces with empty arrays or non-triangulated data [S1, unofficial]. Assign material: prefer materials from the input array if the index is valid, otherwise fall back to `get_material_by_index(surface.material_index)` [S1, unofficial]. Add surface to mesh using `output.primitive_type`, arrays, empty extra arrays/dictionary, and `output.mesh_flags` [S1, unofficial]. Set surface material and increment index [S1, unofficial].
6.  **Transvoxel Detail (Optional):** If smooth meshing is enabled, detail textures are enabled, and a generator exists, cast the mesher to `VoxelMesherTransvoxel` [S1, unofficial]. Retrieve `mesh_arrays` and `cell_infos` from thread-local cache [S1, unofficial]. Create `TransvoxelCellIterator` [S1, unofficial]. Call `compute_detail_texture_data` with vertex/normal/index spans, tile resolution, generator, origin, voxel size, LOD, octahedral flag, and max deviation in radians [S1, unofficial].
7.  **Block Size Calculation:** Calculate `block_size` by subtracting minimum and maximum padding from the voxel buffer size [S1, unofficial].

**Pseudocode:**
```python
import math

MIN_DEVIATION_DEGREES = 0.0
MAX_DEVIATION_DEGREES = 90.0

def build_mesh(voxel_buffer, additional_data=None):
    # Step 1: Initialize Input and Output
    input_data = {
        'voxel_buffer': voxel_buffer,
        'generator': None,
        'origin': (0, 0, 0),
        'lod_index': 0,
        'flags': [False, False, False]
    }
    output_data = {'surfaces': []}

    # Step 2: Process Additional Data
    if additional_data is not None:
        input_data['generator'] = additional_data.get('generator')
        input_data['origin'] = additional_data.get('origin_in_voxels', (0, 0, 0))
        input_data['detail_texture_hint'] = additional_data.get('detail_enabled', False)
        deviation = additional_data.get('normalmap_max_deviation_degrees', 0.0)
        input_data['detail_max_deviation'] = max(MIN_DEVIATION_DEGREES, min(MAX_DEVIATION_DEGREES, deviation))

    # Step 3: Core Build
    # Populates output_data.surfaces with vertex, normal, index, material, and flag arrays
    # Implementation details not provided in sources
    core_build(input_data, output_data)

    # Step 4: Empty Check
    if not output_data['surfaces']:
        return []

    # Step 5: Mesh Assembly
    mesh = []
    material_index = 0
    for surface in output_data['surfaces']:
        # Check if arrays are empty or not triangulated (vertex count % 3 != 0)
        if not surface['arrays'] or len(surface['arrays']) % 3 != 0:
            continue

        # Material Assignment
        if input_data.get('materials') and surface['material_index'] < len(input_data['materials']):
            material = input_data['materials'][surface['material_index']]
        else:
            material = get_material_by_index(surface['material_index'])

        # Add Surface
        mesh.append({
            'primitive_type': output_data['primitive_type'],
            'arrays': surface['arrays'],
            'arrays_extra': [],
            'arrays_dictionary': {},
            'mesh_flags': output_data['mesh_flags'],
            'material': material
        })
        material_index += 1

    # Step 6: Transvoxel Detail
    if is_smooth_meshing_enabled() and is_detail_textures_enabled() and input_data['generator']:
        transvoxel_mesher = cast_to_VoxelMesherTransvoxel(self)
        mesh_arrays, cell_infos = get_thread_local_cache()
        iterator = TransvoxelCellIterator()
        for surf in output_data['surfaces']:
            compute_detail_texture_data(
                vertices=surf['vertices'],
                normals=surf['normals'],
                indices=surf['indices'],
                tile_resolution=transvoxel_mesher['tile_resolution'],
                generator=input_data['generator'],
                origin=input_data['origin'],
                voxel_size=input_data['voxel_buffer']['voxel_size'],
                lod=input_data['lod_index'],
                octahedral=transvoxel_mesher['octahedral'],
                max_deviation_radians=math.radians(input_data['detail_max_deviation'])
            )

    # Step 7: Block Size Calculation
    block_size = input_data['voxel_buffer']['size'] - input_data['voxel_buffer']['min_padding'] - input_data['voxel_buffer']['max_padding']

    return mesh
```

**Edge Cases and Pitfalls:**
*   **Bug in Normals:** The `g_side_normals` array has swapped signs for LEFT and BACK sides, which may cause incorrect culling or lighting if relied upon directly [S1, unofficial].
*   **Multithreading:** Neighbor checks use `g_ordered_moore_area_3d` to prevent deadlocks in multithreaded contexts [S1, unofficial].
*   **GDScript Limitation:** Custom meshers cannot be implemented in GDScript due to performance constraints [S2].

## Subtopics

### Custom Mesher Implementation
Custom meshing allows interpreting voxel data differently than standard ID-to-model mapping, supporting complex states, runtime rotations, separated properties, procedural shapes, or custom vertex packing [S2]. To create a custom mesher, one must create a C++ module inheriting the base class `VoxelMesher` and implement its virtual methods [S2]. This approach is ideal for full control and assumptions but requires compiling Godot [S2]. In contrast, a generic baked asset mesher is easier for asset management (one voxel = one model, variants for rotations/states) but requires bending needs to fit the pipeline and generating variants [S2]. GDScript cannot be used for custom meshers because scripts are too slow for individual polygonization; a development branch `mesher_script` exists but is not ready [S2].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Not given in the sources.
*   **Strengths:** Handles material assignment and surface assembly in a single pass; supports optional Transvoxel detail normal map generation [S1, unofficial].
*   **Limitations:** Relies on internal lookup tables with known bugs (normals); cannot be extended via GDScript [S1, unofficial][S2].
*   **When to use:** When using the standard Godot Voxel plugin and needing to convert voxel buffers to `ArrayMesh` objects [S1, unofficial].
*   **When not to use:** When custom vertex packing or procedural shape generation is required without C++ compilation [S2].

## Background
`VoxelMesher::build_mesh` is part of the Godot Voxel plugin, an unofficial voxel toolset for the Godot engine [S1, unofficial]. It is documented in the plugin's source code and associated documentation [S1, unofficial][S2]. The method is designed to integrate with Godot's rendering pipeline, specifically `ArrayMesh`, allowing for efficient rendering of voxel-based terrain [S1, unofficial].
