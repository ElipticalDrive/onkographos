# Mesh Plugin Architecture
Also called: IMeshingJob
## Overview
The Mesh Plugin Architecture provides an interface for pluggable meshing algorithms, allowing for extensibility within a voxel engine's meshing pipeline [S1, unofficial]. It decouples the mesh generation logic from the chunk management system, enabling the selection of different algorithms (e.g., greedy meshing for blocky voxels vs. Marching Cubes for smooth terrain) based on voxel type [S1, unofficial]. This approach sets it apart from monolithic meshing implementations by supporting multiple concurrent strategies through a unified interface.

## How it works
The architecture relies on a core interface and a resource-based storage system for mesh states.

**Inputs and Outputs:**
*   **Input:** Voxel data (blocky or smooth) and configuration parameters (material, density).
*   **Output:** `MeshInfo` structures containing opaque and translucent mesh data, stored in a resource.

**Data Structures:**
1.  **`IMeshingJob` Interface:** Defines the contract for meshing algorithms. Implementations must handle face culling (for blocky) or surface extraction (for smooth) [S1, unofficial].
2.  **`Mesh` Resource:** Stores a hash map mapping `(ChunkPosition, ZoomLevel)` to `MeshStatus` [S2, unofficial].
3.  **`MeshStatus` Enum:**
    *   `Meshing`: The chunk is currently being processed.
    *   `Meshed(Arc<MeshInfo>)`: The chunk has finished meshing; contains the result.
    *   `Empty`: The chunk contains no relevant voxels.
4.  **`MeshInfo` Structure:** Contains an optional opaque mesh and a vector of translucent meshes [S2, unofficial].

**Algorithm Selection:**
The `ChunkManager` performs smart mesher selection, determining whether to use a blocky or smooth algorithm based on the voxel data type [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Depends on the specific meshing algorithm (Greedy Meshing is generally faster for blocky voxels, Marching Cubes is more expensive for smooth terrain).
*   **Memory Complexity:** Reduced by using half-precision density (50% savings) [S1, unofficial].
*   **Performance:** Burst-compiled jobs with zero GC provide high performance [S1, unofficial].
*   **Strengths:** Extensibility, support for multiple meshing strategies, memory efficiency.
*   **Limitations:** Complexity of managing multiple job types, potential overhead of interface dispatch.
*   **When to Use:** When you need to support both blocky and smooth voxel types or want to easily swap meshing algorithms.
*   **When Not to Use:** For simple, single-type voxel engines where a single meshing algorithm suffices.

## Background
The Mesh Plugin Architecture was introduced as part of the foundational voxel engine implementation in the StraightFour project [S1, unofficial]. It was designed to support generic, terrain, and smooth voxel types, providing a flexible pipeline for mesh generation [S1, unofficial]. The architecture is also reflected in the Infinigen project, which uses similar concepts for block type definitions and world generation [S2, unofficial].
