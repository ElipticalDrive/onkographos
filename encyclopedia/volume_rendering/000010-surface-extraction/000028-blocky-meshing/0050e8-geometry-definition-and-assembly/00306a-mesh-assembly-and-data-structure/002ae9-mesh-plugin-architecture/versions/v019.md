# Mesh Plugin Architecture
Also called: IMeshingJob
## Overview
The Mesh Plugin Architecture provides an interface for pluggable meshing algorithms, allowing for extensibility within the geometry generation pipeline [S1, unofficial]. It decouples the meshing logic from the chunk management system, enabling the selection of specific algorithms (e.g., blocky vs. smooth) based on voxel data types [S1, unofficial]. This approach sets it apart from monolithic assembly methods by allowing runtime or configuration-time swapping of the meshing strategy without altering the underlying data structure or scheduling infrastructure.

## How it works
The architecture defines a contract (`IMeshingJob`) that concrete meshing algorithms must implement. The `ChunkManager` acts as the orchestrator, handling spatial hashing, job scheduling, and smart mesher selection [S1, unofficial].

**Inputs and Outputs:**
- **Input:** Voxel data (e.g., `VoxelData` containing material IDs or density fields) and chunk coordinates.
- **Output:** Mesh resources (vertices, indices, normals) stored in contiguous buffers, managed via `MeshStatus` and `MeshInfo` [S2, unofficial].

**Data Structures:**
1.  **IMeshingJob Interface:** Defines the method signature for executing the meshing algorithm. Specific implementations include:
    -   `GreedyMeshingJob`: Optimized for face culling in blocky voxels. Burst-compiled with zero garbage collection [S1, unofficial].
    -   `MarchingCubesJob`: A simplified prototype for smooth terrain using density fields. Burst-compiled with zero garbage collection. Full lookup tables are noted for future implementation [S1, unofficial].
2.  **MeshStatus Enum:** Tracks the state of a chunk's meshing process. Variants include:
    -   `Meshing`: The algorithm is currently running.
    -   `Meshed(Arc<MeshInfo>)`: Meshing is complete, holding a reference to the generated data.
    -   `Empty`: The chunk contains no geometry [S2, unofficial].
3.  **MeshInfo:** Contains the resulting geometry. It holds an optional opaque mesh and a vector of translucent meshes, supporting material-based sectioning [S2, unofficial].
4.  **Mesh Resource Store:** A hash map mapping `(ChunkPosition, ZoomLevel)` to `MeshStatus` [S2, unofficial].

**Steps:**
1.  **Voxel Registration:** The user registers voxels via `ChunkManager.SetVoxel`, specifying coordinates and data (solid material ID or smooth density) [S1, unofficial].
2.  **Smart Mesher Selection:** The `ChunkManager` analyzes the voxel data type to select the appropriate `IMeshingJob` implementation (e.g., `GreedyMeshingJob` for blocky, `MarchingCubesJob` for smooth) [S1, unofficial].
3.  **Job Scheduling:** The `ChunkManager` schedules the selected job, handling world-to-local coordinate conversion and spatial hashing [S1, unofficial].
4.  **Execution:** The selected job executes the meshing algorithm. For example, `GreedyMeshingJob` performs face culling, while `MarchingCubesJob` processes density fields [S1, unofficial].
5.  **Status Update:** Upon completion, the `MeshStatus` for the chunk is updated to `Meshed`, storing the `MeshInfo` in the resource store [S2, unofficial].
6.  **Resource Management:** The `MeshInfo` is accessed by the renderer. The system supports half-precision density storage to save memory (68KB vs 128KB per 32³ chunk) [S1, unofficial].

## Operating characteristics
- **Performance:** Implementations are burst-compiled with zero garbage collection, optimizing for high throughput in real-time applications [S1, unofficial].
- **Memory:** Supports half-precision density storage, reducing memory usage by 50% (68KB vs 128KB per 32³ chunk) [S1, unofficial].
- **Scalability:** The spatial hash and automatic job scheduling in `ChunkManager` allow for efficient handling of large worlds [S1, unofficial].
- **Limitations:** The `MarchingCubesJob` is currently a simplified prototype; full lookup tables are not yet implemented [S1, unofficial].

## Background
The Mesh Plugin Architecture was introduced as part of the foundational voxel engine development in the StraightFour project [S1, unofficial]. It was designed to support both generic, terrain, and smooth voxel types, providing a flexible foundation for various rendering needs [S1, unofficial]. The architecture is implemented in C# using Unity's Job System and Burst Compiler for performance [S1, unofficial].
