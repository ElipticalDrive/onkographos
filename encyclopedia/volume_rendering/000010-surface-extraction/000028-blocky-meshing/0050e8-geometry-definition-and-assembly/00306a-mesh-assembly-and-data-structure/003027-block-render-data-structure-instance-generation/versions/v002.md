# Block Render Data Structure & Instance Generation

Also called: BlockRenderData, Face Tint Mixing

## Overview
This method defines the data structure and generation logic for aggregating exposed axis-aligned faces from blocky meshing into a format suitable for instance-based rendering. It solves the problem of efficiently passing per-face material properties (texture IDs and color tints) to the GPU by bundling them into a single `BlockRenderData` record per voxel instance. It differs from sibling methods by explicitly handling directional face attributes and mixing base block tints with provided face tints before instance submission.

## How it works
**Inputs:**
- A list of exposed faces from [Blocky meshing](31-blocky-meshing.md), each associated with a voxel position and direction.
- A texture ID mapping (string name to integer index) [S1, unofficial].
- Base block tints (defaulting to white `Vector3(1, 1, 1)`) [S1, unofficial].
- Optional per-face tints provided by the meshing algorithm.
- A reference to the `IShape` geometry definition for the voxel [S1, unofficial].

**Outputs:**
- A collection of `BlockRenderData` instances, one per visible voxel face group, ready for GPU instance buffers.

**Data Structures:**
The core structure is `BlockRenderData`. It contains 13 fields:
1.  `faceBack`: `int` (Texture ID index)
2.  `faceFront`: `int` (Texture ID index)
3.  `faceTop`: `int` (Texture ID index)
4.  `faceBottom`: `int` (Texture ID index)
5.  `faceLeft`: `int` (Texture ID index)
6.  `faceRight`: `int` (Texture ID index)
7.  `tintBack`: `Vector3` (RGB tint)
8.  `tintFront`: `Vector3` (RGB tint)
9.  `tintTop`: `Vector3` (RGB tint)
10. `tintBottom`: `Vector3` (RGB tint)
11. `tintLeft`: `Vector3` (RGB tint)
12. `tintRight`: `Vector3` (RGB tint)
13. `shape`: `IShape` reference

**Steps:**
1.  **Initialize Texture Map:** Create a frozen dictionary mapping texture names to integer IDs based on the provided `TextureLoader.Texture[]` array [S1, unofficial].
2.  **Iterate Exposed Faces:** For each exposed face generated by the meshing algorithm:
    a. Determine the face direction (Back, Front, Top, Bottom, Left, Right).
    b. Fetch the base texture ID for that direction from the block's definition.
    c. Fetch the base tint for that direction (default `Vector3(1, 1, 1)` if not specified) [S1, unofficial].
    d. If per-face tints are provided, mix them with the base tints. The mixing operation is element-wise multiplication: $T_{final} = T_{base} \times T_{face}$ [S1, unofficial]. Alternatively, the source notes mention replacing base tints entirely; the primary implementation shown uses mixing [S1, unofficial].
    e. Construct a `BlockRenderData` instance for the voxel, populating the 6 texture ID fields and 6 tint fields according to the directions of all exposed faces of that voxel.
    f. Assign the `IShape` reference.
3.  **Generate Instances:** Pass the collection of `BlockRenderData` instances to the rendering engine's instance method for batching [S1, unofficial].

**Pseudocode:**
```python
class BlockRenderData:
    def __init__(self, face_back, face_front, face_top, face_bottom, face_left, face_right,
                 tint_back, tint_front, tint_top, tint_bottom, tint_left, tint_right, shape):
        self.face_back = face_back
        self.face_front = face_front
        self.face_top = face_top
        self.face_bottom = face_bottom
        self.face_left = face_left
        self.face_right = face_right
        self.tint_back = tint_back
        self.tint_front = tint_front
        self.tint_top = tint_top
        self.tint_bottom = tint_bottom
        self.tint_left = tint_left
        self.tint_right = tint_right
        self.shape = shape

def create_block_render_data(texture_name_to_id, base_tints, face_tints, shape, directions):
    """
    Creates a BlockRenderData instance for a voxel.
    directions: dict mapping direction name (e.g., 'Back') to exposed face info.
    base_tints: dict mapping direction name to base Vector3 tint.
    face_tints: dict mapping direction name to provided face Vector3 tint (optional).
    """
    data = {}
    for direction in ['Back', 'Front', 'Top', 'Bottom', 'Left', 'Right']:
        # Fetch texture ID
        texture_name = get_texture_name_for_direction(direction) # Implementation detail from meshing
        texture_id = texture_name_to_id[texture_name]
        data[f'face_{direction.lower()}'] = texture_id
        
        # Fetch and mix tints
        base_tint = base_tints.get(direction, Vector3(1, 1, 1))
        if direction in face_tints:
            # Element-wise multiplication
            final_tint = base_tint * face_tints[direction]
        else:
            final_tint = base_tint
        data[f'tint_{direction.lower()}'] = final_tint
    
    return BlockRenderData(
        face_back=data['face_back'], face_front=data['face_front'],
        face_top=data['face_top'], face_bottom=data['face_bottom'],
        face_left=data['face_left'], face_right=data['face_right'],
        tint_back=data['tint_back'], tint_front=data['tint_front'],
        tint_top=data['tint_top'], tint_bottom=data['tint_bottom'],
        tint_left=data['tint_left'], tint_right=data['tint_right'],
        shape=shape
    )
```

**Parameters:**
- Default tint: `Vector3(1, 1, 1)` (White) [S1, unofficial].

**Edge Cases:**
- Missing texture names: The source uses a `FrozenDictionary`, implying all texture names must be present in the map. Missing keys would raise an error [S1, unofficial].
- Tint mixing vs. replacement: The source notes mention both mixing and replacement. The code example uses mixing. Implementers should verify which behavior is intended for their specific engine [S1, unofficial].

## Subtopics

### Chunk Mesh Assembly
- **What it is:** A method for assembling meshes at the chunk level rather than per-voxel.
- **Difference:** Aggregates geometry into larger contiguous buffers, reducing draw calls compared to per-voxel instances.
- **When to choose:** When rendering large, static chunks where per-voxel instance overhead is prohibitive.
- **Link:** [Chunk Mesh Assembly](4100-chunk-mesh-assembly.md)

### Mesh Plugin Architecture
- **What it is:** A pluggable system for different meshing algorithms.
- **Difference:** Allows swapping the meshing strategy (blocky vs. smooth) without changing the data structure generation logic.
- **When to choose:** When supporting multiple voxel types or rendering styles.
- **Link:** [Mesh Plugin Architecture](4921-mesh-plugin-architecture.md)

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of exposed faces, as each face requires a dictionary lookup and vector operation.
- **Memory Complexity:** $O(N)$ for storing the `BlockRenderData` instances. Each instance is 13 fields (6 ints, 6 vectors, 1 reference).
- **Strengths:** Simple data layout; efficient for instance rendering; supports per-face tinting.
- **Limitations:** Per-voxel instance overhead can be high for dense scenes; texture ID lookups add CPU overhead.
- **When to use:** Small to medium voxel worlds; dynamic voxel changes; when per-face material variation is needed.
- **When not to use:** Very large static worlds where chunk-based assembly is more efficient.

## Background
This method originates from the `Cubic-Grid_Voxel_Renderer` project by rarefushion [S1, unofficial]. It is designed for real-time voxel rendering in game engines, leveraging instance rendering to handle large numbers of voxels efficiently.
