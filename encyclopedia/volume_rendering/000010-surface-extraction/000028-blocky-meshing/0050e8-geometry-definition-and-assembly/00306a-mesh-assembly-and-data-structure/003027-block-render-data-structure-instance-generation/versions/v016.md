# Block Render Data Structure & Instance Generation

Also called: BlockRenderData, Face Tint Mixing

## Overview
This method defines the data container for individual voxel blocks and the process of converting that data into GPU-drawable instances. It solves the problem of efficiently batching heterogeneous voxel geometry by decoupling block metadata (textures, tints, shape) from the mesh assembly phase [S1, unofficial]. Unlike sibling methods that handle bulk chunk assembly, this method focuses on per-block instance generation, allowing for fine-grained control over face-specific material properties before they are merged into the global vertex buffer [S1, unofficial].

## How it works

### Inputs and Outputs
**Inputs:**
- A mapping from texture names to integer IDs (`FrozenDictionary<string, int>`).
- A set of face specifications: six texture names (Back, Front, Top, Bottom, Left, Right) and six tint vectors (Back, Front, Top, Bottom, Left, Right).
- A reference to the geometric shape (`IShape`) defining the block's topology.

**Outputs:**
- A `BlockRenderData` struct instance containing resolved texture IDs, tint vectors, and the shape reference.

### Data Structures

The core data structure is `BlockRenderData`. It is a struct containing 13 fields: 6 integers for texture IDs, 6 vectors for tints, and 1 shape reference.

```csharp
public struct BlockRenderData {
    // Texture IDs for each face
    public int faceBack;
    public int faceFront;
    public int faceTop;
    public int faceBottom;
    public int faceLeft;
    public int faceRight;

    // Tint colors for each face (RGB)
    public Vector3 tintBack;
    public Vector3 tintFront;
    public Vector3 tintTop;
    public Vector3 tintBottom;
    public Vector3 tintLeft;
    public Vector3 tintRight;

    // Geometric definition
    public IShape shape;
}
```

### Steps

1.  **Initialize Texture Map:** Create a lookup table mapping texture names to unique integer IDs. This is typically done once during factory initialization [S1, unofficial].
2.  **Resolve Texture IDs:** For each of the six faces, look up the provided texture name in the map to get the corresponding integer ID. If a name is not found, the behavior is undefined in the source, but typically implies a fallback or error [S1, unofficial].
3.  **Apply Tints:** Assign the provided tint vectors to the corresponding face fields. If no specific tint is provided for a face, it defaults to white (`Vector3(1, 1, 1)`) [S1, unofficial].
4.  **Mix Tints (Optional):** If external face tints are provided alongside base block tints, they are mixed. The mixing method is element-wise multiplication: $T_{final} = T_{base} \times T_{external}$ [S1, unofficial]. Alternatively, external tints may completely replace base tints [S1, unofficial].
5.  **Construct Instance:** Create the `BlockRenderData` struct with the resolved IDs, mixed tints, and the shape reference. This struct is then passed to the instance generation phase of the mesh assembly pipeline [S1, unofficial].

### Pseudocode

```python
class BlockRenderDataFactory:
    def __init__(self, texture_names: List[str]):
        # Map texture names to integer IDs
        self.texture_id_map = {name: i for i, name in enumerate(texture_names)}
        self.white_tint = Vector3(1.0, 1.0, 1.0)

    def create_block_data(
        self,
        face_names: List[str], # [Back, Front, Top, Bottom, Left, Right]
        face_tints: List[Vector3], # [Back, Front, Top, Bottom, Left, Right]
        shape: IShape
    ) -> BlockRenderData:
        # Step 1: Resolve texture IDs
        face_ids = []
        for name in face_names:
            if name in self.texture_id_map:
                face_ids.append(self.texture_id_map[name])
            else:
                # Fallback: Not specified in sources. 
                # [G] Assume 0 or raise error. Using 0 for implementation safety.
                face_ids.append(0)

        # Step 2: Apply tints, defaulting to white if not provided
        tints = []
        for i in range(6):
            tint = face_tints[i] if i < len(face_tints) and face_tints[i] is not None else self.white_tint
            tints.append(tint)

        # Step 3: Mix tints (if external tints were passed separately, multiply here)
        # [G] Assuming face_tints are the final desired tints. 
        # If mixing is required, apply: tint = base_tint * external_tint

        # Step 4: Construct and return
        return BlockRenderData(
            faceBack=face_ids[0],
            faceFront=face_ids[1],
            faceTop=face_ids[2],
            faceBottom=face_ids[3],
            faceLeft=face_ids[4],
            faceRight=face_ids[5],
            tintBack=tints[0],
            tintFront=tints[1],
            tintTop=tints[2],
            tintBottom=tints[3],
            tintLeft=tints[4],
            tintRight=tints[5],
            shape=shape
        )
```

### Parameters and Edge Cases
- **Default Tint:** White (`1, 1, 1`) is used when no tint is specified [S1, unofficial].
- **Missing Texture:** The source does not specify behavior for missing texture names. [G] Implementers should handle this via a default texture or error logging.
- **Tint Mixing:** Two modes are mentioned: element-wise multiplication or complete replacement. The specific mode depends on the calling context [S1, unofficial].

## Operating characteristics

- **Time Complexity:** $O(1)$ per block for data structure creation, as it involves a fixed number of dictionary lookups and struct assignments.
- **Memory Complexity:** $O(1)$ per block instance. The `BlockRenderData` struct is small and stack-allocated or embedded in larger arrays.
- **Strengths:** Decouples material definition from geometry generation, allowing for flexible per-face material assignment.
- **Limitations:** Does not handle mesh optimization (culling, merging) itself; relies on the parent assembly method for that.
- **When to Use:** When per-block or per-face material customization is required before bulk mesh assembly.

## Background

This method originates from the `Cubic-Grid_Voxel_Renderer` project by rarefushion [S1, unofficial]. It represents a specific implementation choice for managing voxel material data in a C#-based voxel renderer, focusing on simplicity and direct mapping of texture names to IDs.
