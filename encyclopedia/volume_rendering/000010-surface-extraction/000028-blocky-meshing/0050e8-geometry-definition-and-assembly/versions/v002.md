# Geometry Definition and Assembly


## Overview
Geometry Definition and Assembly is the family of methods responsible for converting discrete 3D voxel occupancy data into contiguous, render-ready polygonal triangle meshes [G]. It solves the problem of rendering large, blocky volumes efficiently by culling internal faces between adjacent solid voxels, thereby reducing vertex count and draw calls compared to naive voxel rendering [G]. Unlike smooth surface extraction methods like Marching Cubes, this family produces a blocky, axis-aligned aesthetic suitable for voxel-art styles [G]. It differs from smooth extraction by emitting axis-aligned quads or triangles at voxel boundaries rather than interpolating geometry through the volume [G].

## Shared principles
The family operates on a 3D occupancy grid or density field [G]. The core mechanism involves iterating through voxels and determining which faces are "exposed" to empty space or a chunk boundary [G].

1.  **Neighbor Check**: For each solid voxel, the algorithm checks its 6 immediate neighbors (±X, ±Y, ±Z) [G].
    *   If a neighbor is empty (Air, density below threshold, or `visible=false`), the face is exposed [G].
    *   If a neighbor is out of chunk bounds, it is treated as empty/visible [G].
    *   *Translucency Rule*: For translucent voxels, a face is generated if the neighbor is empty; if the neighbor is opaque, the face is hidden [G].
2.  **Face Culling**: Internal faces between two adjacent solid voxels are discarded. This is the primary optimization that reduces geometry count [G].
3.  **Vertex/Quad Emission**: For each exposed face, a quad (two triangles) is generated. The vertices are calculated by adding the voxel's world position (scaled by `BlockSize`) to base quad vertices defined for the face direction [G].
4.  **Winding Order**: Triangle winding must be consistent (e.g., counter-clockwise) to ensure correct back-face culling [G]. A common pattern is `(0,1,2)` and `(3,2,1)` relative to the current vertex count [G].
5.  **Padding**: To simplify boundary checks, the voxel grid is often conceptually or physically padded with a constant empty boundary on all sides [G].

## Subtopics

### [Block face vertex layout](2374-block-face-vertex-layout.md)
Defines the static geometric primitives (vertices, indices, and attributes) for a unit cube, serving as the foundational template for generating blocky voxel meshes. It solves the problem of mapping discrete voxel occupancy data to renderable triangular geometry by providing a canonical set of face definitions that can be instantiated per exposed voxel face. Unlike smooth surface extraction methods such as [Marching Cubes](52-marching-cubes.md) which produce curved surfaces, this method preserves the discrete, axis-aligned nature of the voxel grid. It differs from [Voxel Mesh Generation (Cube Construction)](11001-voxel-mesh-generation-cube-construction.md) by defining the abstract vertex structure and indexing logic for a unit cube face, whereas the child article handles the complete assembly of a single voxel's 24 vertices and indices for immediate rendering. [G]

### [Mesh Assembly and Data Structure](6268-mesh-assembly-and-data-structure.md)
Aggregates raw geometric primitives (vertices, indices, normals) generated by voxel face culling into contiguous, GPU-ready buffer structures. It solves the problem of fragmented geometry by consolidating data from disparate voxel blocks or render layers into dense memory regions, optimizing bandwidth and reducing draw call overhead. It differs from [Block face vertex layout](2374-block-face-vertex-layout.md) and [Voxel Face and Geometry Generation](11724-voxel-face-and-geometry-generation.md) by focusing on the *aggregation* and *buffer management* phase rather than the geometric construction or vertex layout itself. [G]

### [Voxel Face and Geometry Generation](11724-voxel-face-and-geometry-generation.md)
A family of surface extraction algorithms that convert a discrete 3D voxel grid (occupancy or density field) into a triangular mesh by emitting geometry only for voxel faces exposed to empty space or chunk boundaries. It solves the problem of rendering large voxel worlds efficiently by culling internal faces between adjacent solid voxels, thereby reducing vertex count and draw calls compared to naive voxel rendering. Unlike smooth surface extraction methods like Marching Cubes, this method produces a blocky, axis-aligned aesthetic suitable for voxel-art styles. It differs from [Boolean Voxel Meshing](971-boolean-voxel-meshing.md) by focusing on simple neighbor-based face culling rather than combining multiple voxel sets via boolean operations. [G]

### [Topology-based Mesh Initialization](14744-topology-based-mesh-initialization.md)
Generates initial 3D meshes for shape-from-projections optimization by parsing topology type and component/material counts from a dataset name string. It differs from voxel-based blocky meshing methods by constructing parametric primitives (tori, icospheres) rather than extracting geometry from a density field. This method is chosen when the target geometry is known to be composed of specific topological classes rather than arbitrary volumetric data. [G]

### Box Geometry Definition
A command to add or remove a box-shaped geometry from a scene or volume, optionally styling the resulting surfaces [S1, unofficial].
- `position`: Array of three numbers `[x, y, z]` specifying the box's position [S1, unofficial].
- `size`: Array of three numbers `[width, height, depth]` or a single number for uniform size [S1, unofficial].
- `style`: Optional object to style the carved walls, e.g., `{ default: { fill: '#222' } }` [S1, unofficial].
