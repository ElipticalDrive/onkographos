# Snake-like Triangle Strip Generation

Also called: Grid Triangle Strip Generation, Snake-like Triangle Strip, Zigzag Triangle Strip

## Overview
Snake-like Triangle Strip Generation is a method for converting a 2D grid of vertices into a single, continuous triangle strip mesh [S1, unofficial]. It solves the problem of maintaining consistent face winding (orientation) across a rectangular grid without generating degenerate triangles or requiring explicit index buffers for connectivity [S1, unofficial]. It sets itself apart from standard triangle list generation by reducing draw calls and from other strip generation techniques by using a deterministic "snake" (boustrophedon) traversal pattern that guarantees valid strip continuity for any rectangular grid topology [S1, unofficial].

## How it works
**Inputs:**
- A 2D grid of vertices with positions, normals, and texture coordinates.
- Grid dimensions: $MESHNUM \times MESHNUM$ (square grid assumed in source, but logic generalizes to $W \times H$).
- Total vertex count: $MAPVERTS = MESHNUM \times MESHNUM$.

**Outputs:**
- An index array `m_Index` defining a single triangle strip.
- Vertex attributes (position, normal, texcoord) associated with each vertex in the grid.

**Data Structures:**
- `m_Verts`: Array of size $MAPVERTS$. Each element contains:
  - `pos`: 3D vector (float x, y, z).
  - `normal`: 3D vector (float x, y, z).
  - `texcoord`: 2D vector (float u, v).
- `m_Index`: Dynamic array of integers storing vertex indices for the strip.

**Parameters:**
- $MESHNUM$: Integer, number of vertices along one axis.
- $TEXMAG$: Scaling factor for texture coordinates, defined as $1.0 / MESHNUM$ [S1, unofficial].

**Algorithm Steps:**
1. **Initialization:**
   - Load vertex positions into `m_Verts` [S1, unofficial].
   - Compute $TEXMAG = 1.0 / MESHNUM$ [S1, unofficial].
   - Initialize `m_Index` as empty [S1, unofficial].

2. **Row Traversal:**
   - Loop $y$ from $0$ to $MESHNUM - 2$ [S1, unofficial].
   - **Forward Pass (even rows, $y$ is even):**
     - Loop $x$ from $0$ to $MESHNUM - 2$ [S1, unofficial].
     - Define triangle using vertices:
       - $V_0 = (y \cdot MESHNUM + x)$
       - $V_1 = (y \cdot MESHNUM + x + 1)$
       - $V_2 = ((y + 1) \cdot MESHNUM + x)$
     - Compute normal for triangle $(V_0, V_1, V_2)$ using `CalcNormalVector()` [S1, unofficial].
     - Assign normal to $V_0$ and $V_1$ [S1, unofficial].
     - Set texture coordinates:
       - $V_0$: $((x \cdot TEXMAG), (y \cdot TEXMAG))$
       - $V_1$: $((x \cdot TEXMAG), ((y + 1) \cdot TEXMAG))$
     - Push indices to `m_Index`: $(y + 1) \cdot MESHNUM + x$, then $y \cdot MESHNUM + x$ [S1, unofficial].
   - **Backward Pass (odd rows, $y$ is odd):**
     - Loop $x$ from $MESHNUM - 1$ down to $1$ [S1, unofficial].
     - Define triangle using vertices:
       - $V_0 = (y \cdot MESHNUM + x)$
       - $V_1 = (y \cdot MESHNUM + x - 1)$
       - $V_2 = ((y + 1) \cdot MESHNUM + x)$
     - Compute normal for triangle $(V_0, V_1, V_2)$ using `CalcNormalVector()` [S1, unofficial].
     - Assign normal to $V_0$ and $V_1$ [S1, unofficial].
     - Set texture coordinates:
       - $V_0$: $((x \cdot TEXMAG), (y \cdot TEXMAG))$
       - $V_1$: $((x \cdot TEXMAG), ((y + 1) \cdot TEXMAG))$
     - Push indices to `m_Index`: $y \cdot MESHNUM + x$, then $(y + 1) \cdot MESHNUM + x$ [S1, unofficial].

3. **Rendering:**
   - Issue a single draw call using `GL_TRIANGLE_STRIP` [S1, unofficial].
   - Iterate through `m_Index`, setting normal, texcoord, and position for each vertex [S1, unofficial].

**Pseudocode:**
```python
def snake_like_strip_generation(m_Verts, MESHNUM):
    """
    Generates a triangle strip index list for a 2D grid of vertices.
    m_Verts: List of Vertex objects with pos, normal, texcoord attributes.
    MESHNUM: Integer width/height of the square grid.
    Returns: List of integers representing the triangle strip indices.
    """
    m_Index = []
    TEXMAG = 1.0 / MESHNUM
    
    # Precompute vertex indices for clarity
    # Vertex at (x, y) has index: y * MESHNUM + x
    
    for y in range(MESHNUM - 1):
        if y % 2 == 0:
            # Forward pass: left to right
            for x in range(MESHNUM - 1):
                v0_idx = y * MESHNUM + x
                v1_idx = y * MESHNUM + x + 1
                v2_idx = (y + 1) * MESHNUM + x
                
                # Compute normal for triangle (v0, v1, v2)
                # Note: Source uses CalcNormalVector() on the triangle
                normal = calc_normal(m_Verts[v0_idx].pos, m_Verts[v1_idx].pos, m_Verts[v2_idx].pos)
                
                # Assign normal to first two vertices of the triangle
                m_Verts[v0_idx].normal = normal
                m_Verts[v1_idx].normal = normal
                
                # Set texture coordinates
                m_Verts[v0_idx].texcoord = vec2(x * TEXMAG, y * TEXMAG)
                m_Verts[v1_idx].texcoord = vec2(x * TEXMAG, (y + 1) * TEXMAG)
                
                # Push indices for triangle strip
                # Source pushes: v2, v0
                m_Index.append(v2_idx)
                m_Index.append(v0_idx)
                
        else:
            # Backward pass: right to left
            for x in range(MESHNUM - 1, 0, -1):
                v0_idx = y * MESHNUM + x
                v1_idx = y * MESHNUM + x - 1
                v2_idx = (y + 1) * MESHNUM + x
                
                # Compute normal for triangle (v0, v1, v2)
                normal = calc_normal(m_Verts[v0_idx].pos, m_Verts[v1_idx].pos, m_Verts[v2_idx].pos)
                
                # Assign normal to first two vertices of the triangle
                m_Verts[v0_idx].normal = normal
                m_Verts[v1_idx].normal = normal
                
                # Set texture coordinates
                m_Verts[v0_idx].texcoord = vec2(x * TEXMAG, y * TEXMAG)
                m_Verts[v1_idx].texcoord = vec2(x * TEXMAG, (y + 1) * TEXMAG)
                
                # Push indices for triangle strip
                # Source pushes: v0, v2
                m_Index.append(v0_idx)
                m_Index.append(v2_idx)
                
    return m_Index

def calc_normal(p0, p1, p2):
    """Calculates the normal vector of a triangle defined by three points."""
    v1 = p1 - p0
    v2 = p2 - p0
    return normalize(cross(v1, v2))
```

**Edge Cases and Pitfalls:**
- **Grid Dimensions:** The source assumes a square grid ($MESHNUM \times MESHNUM$) [S1, unofficial]. For non-square grids, the loop bounds and index calculations must be adjusted to $W \times H$ [G].
- **Degenerate Triangles:** The snake-like pattern avoids degenerate triangles by ensuring each new triangle shares an edge with the previous one in the strip [S1, unofficial].
- **Normal Assignment:** Normals are computed per triangle and assigned to the first two vertices of that triangle. This results in flat shading per triangle unless interpolated by the GPU [S1, unofficial].
- **Texture Coordinates:** Texture coordinates are set based on grid indices, not world space. This assumes a tiled texture mapping [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of vertices, as each vertex is processed a constant number of times [S1, unofficial].
- **Memory Complexity:** $O(N)$ for storing vertex attributes and the index array [S1, unofficial].
- **Performance:** Reduces draw calls to a single `GL_TRIANGLE_STRIP` call, which is more efficient than `GL_TRIANGLES` for large meshes [S1, unofficial].
- **Strengths:** Simple implementation, no need for complex strip generation algorithms, consistent winding [S1, unofficial].
- **Limitations:** Flat shading per triangle if normals are not interpolated or smoothed [S1, unofficial]. Assumes rectangular grid topology [S1, unofficial].

## Background
The method is described in the context of a cloud rendering project, specifically within a volume rendering pipeline that uses range grids for surface extraction [S1, unofficial]. It is part of a broader effort to visualize volumetric data using efficient mesh generation techniques [S1, unofficial].
