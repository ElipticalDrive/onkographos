# Double-Pass Voxel Mesh Update

Also called: CEWBS VoxelMesh update, transparent mesh pass

## Overview
The Double-Pass Voxel Mesh Update is a post-processing method that converts the raw, unoptimized triangle output of a greedy voxel mesher into a renderable BabylonJS mesh by explicitly handling vertex attributes and separating opaque and transparent geometry. It solves the problem of integrating greedy meshing results into a standard GPU rendering pipeline by mapping face-level metadata (colors) to per-vertex buffers and managing visibility states for transparency sorting. It differs from standard greedy meshing by adding a dedicated second pass for transparent faces, ensuring correct alpha blending order, whereas the parent method [Greedy Triangle Meshing](15263-greedy-triangle-meshing.md) focuses on the initial geometry generation.

## How it works
The method takes the output of a greedy mesher and processes it into two distinct BabylonJS `Mesh` objects: one for opaque geometry and one for transparent geometry. It relies on the parent [Greedy Triangle Meshing](15263-greedy-triangle-meshing.md) to provide the raw face data.

### Inputs and Outputs
**Inputs:**
1.  `voxelData`: An object containing:
    *   `dimensions`: An array `[x, y, z]` representing the voxel grid size.
    *   `voxels`: A flat array of length $x \times y \times z$. Each element is either `null` or an array `[id, meta]`.
    *   Index mapping for a position $(p_x, p_y, p_z)$ is:
        $$ index = p_x + p_y \cdot x + p_z \cdot x \cdot y $$
2.  `rawMesh`: The output of the greedy mesher, containing a list of `faces`. Each face `q` is an array where:
    *   `q[0], q[1], q[2]`: Vertex indices (integers).
    *   `q[3], q[4]`: Metadata indices used for color lookup.
3.  `evaluateFunction`: A function used by the mesher (passed during generation).
4.  `coloringFunction`: A function `coloringFunction(meta1, meta2)` that returns a color.
5.  `passID`: An integer (0 or 1) indicating the current update pass.

**Outputs:**
1.  `opaqueMesh`: A BabylonJS `Mesh` containing opaque geometry.
2.  `transparentMesh`: A BabylonJS `Mesh` containing transparent geometry.

### Data Structures
*   **Colors Array**: A flat array of floats. For $N$ vertices, the size is $4N$. The layout is `[r_0, g_0, b_0, a_0, r_1, g_1, b_1, a_1, ...]` where each component is normalized to $[0, 1]$.
*   **Indices Array**: A flat array of integers representing triangle vertex indices.
*   **BABYLON.VertexData**: A BabylonJS structure containing `positions`, `indices`, `normals`, and `colors`.

### Steps
1.  **Generate Raw Geometry**: Call the greedy mesher to obtain `rawMesh`.
    $$ rawMesh = \text{mesher}(voxelData.voxels, voxelData.dimensions, evaluateFunction, passID) $$
2.  **Initialize Buffers**: Create empty arrays `indices`, `positions`, `normals`, and `colors`.
3.  **Process Faces**: Iterate over each face `q` in `rawMesh.faces`:
    a.  **Indices**: Push vertex indices in reverse winding order to `indices`:
        $$ indices.push(q[2], q[1], q[0]) $$
    b.  **Color Lookup**: Retrieve color via `coloringFunction(q[3], q[4])`.
        *   If result is `null` or has $< 3$ components, default to `[300, 75, 300, 255]`.
        *   If result has exactly 3 components, append alpha `255`.
    c.  **Color Assignment**: For each vertex index `v_idx` in `[q[0], q[1], q[2]]`:
        *   Calculate offset in `colors` array: $offset = v\_idx \times 4$.
        *   Set `colors[offset]` to $R/255$, `colors[offset+1]` to $G/255$, `colors[offset+2]` to $B/255$, `colors[offset+3]` to $A/255$.
    d.  **Positions/Normals**: The source notes imply `positions` and `normals` are derived from the raw mesh structure, but specific coordinate generation logic is not detailed in the provided notes. [G] Typically, positions are derived from the voxel grid coordinates corresponding to the vertex indices, and normals are derived from the face orientation.
4.  **Construct Vertex Data**: Create a `BABYLON.VertexData` object using the populated `positions`, `indices`, `normals`, and `colors`.
5.  **Apply Based on Pass**:
    *   If `passID == 0`:
        *   Apply vertex data to `opaqueMesh`.
        *   If `positions.length > 0`, set `noVoxels = false` and restore `isVisible` from `oldVisibility`.
        *   If `hasTransparency` is true, recursively call `updateMesh(1)`.
    *   If `passID == 1`:
        *   Apply vertex data to `transparentMesh`.
        *   Mirror visibility logic: if `positions.length > 0`, set `transparentMesh.noVoxels = false` and restore `transparentMesh.isVisible` from `oldVisibility`.

### Pseudocode
```python
def update_mesh(voxel_data, mesher, coloring_function, evaluate_function, pass_id, has_transparency, old_visibility):
    # Step 1: Generate raw geometry
    raw_mesh = mesher(voxel_data.voxels, voxel_data.dimensions, evaluate_function, pass_id)
    
    # Step 2: Initialize buffers
    indices = []
    colors = []
    # Note: positions and normals are assumed to be generated by the mesher or derived from voxel coordinates
    # The source notes do not specify the exact position/normal generation, only that they are part of VertexData
    positions = [] 
    normals = []
    
    # Step 3: Process faces
    for face in raw_mesh.faces:
        # q[0], q[1], q[2] are vertex indices
        # q[3], q[4] are metadata for coloring
        
        # Push indices in reverse winding order
        indices.append(face[2])
        indices.append(face[1])
        indices.append(face[0])
        
        # Get color
        color = coloring_function(face[3], face[4])
        if color is None or len(color) < 3:
            color = [300, 75, 300, 255]
        elif len(color) == 3:
            color.append(255)
            
        # Assign color to each vertex of the face
        for v_idx in [face[0], face[1], face[2]]:
            offset = v_idx * 4
            # Normalize RGB to [0, 1]
            colors.append(color[0] / 255.0)
            colors.append(color[1] / 255.0)
            colors.append(color[2] / 255.0)
            colors.append(color[3] / 255.0)
            
    # Step 4: Construct VertexData
    # Note: The source notes do not specify how positions and normals are populated.
    # [G] Assuming the mesher provides them or they are computed from voxel indices.
    vertex_data = BABYLON.VertexData()
    vertex_data.positions = positions # Derived from raw_mesh
    vertex_data.normals = normals     # Derived from raw_mesh
    vertex_data.indices = indices
    vertex_data.colors = colors
    
    # Step 5: Apply based on pass
    if pass_id == 0:
        vertex_data.applyToMesh(opaque_mesh)
        if len(positions) > 0:
            opaque_mesh.noVoxels = False
            opaque_mesh.isVisible = old_visibility
        if has_transparency:
            update_mesh(voxel_data, mesher, coloring_function, evaluate_function, 1, has_transparency, old_visibility)
    elif pass_id == 1:
        vertex_data.applyToMesh(transparent_mesh)
        if len(positions) > 0:
            transparent_mesh.noVoxels = False
            transparent_mesh.isVisible = old_visibility
```

### Edge Cases and Pitfalls
*   **Color Defaulting**: If `coloringFunction` returns `null` or an incomplete array, the method defaults to magenta `[300, 75, 300, 255]`. This must be handled to avoid crashes.
*   **Transparency Handling**: The method explicitly checks `hasTransparency` to trigger the second pass. If transparency is present but the second pass is not executed, transparent faces will be rendered incorrectly (likely sorted incorrectly or blended improperly).
*   **Visibility Restoration**: The method restores `isVisible` from `oldVisibility`. If `oldVisibility` is not correctly tracked, meshes may remain hidden or visible incorrectly.
*   **Empty Meshes**: If `positions.length` is 0, `noVoxels` is not set to false, and visibility is not restored. This prevents rendering empty meshes.

## Operating characteristics
*   **Time Complexity**: Linear with respect to the number of faces generated by the greedy mesher. The second pass doubles the processing time if transparency is present.
*   **Memory Complexity**: Linear with respect to the number of vertices. The `colors` array size is $4 \times N$ floats.
*   **Performance**: The method is efficient for BabylonJS integration as it directly constructs `VertexData`. The separation of opaque and transparent meshes allows for correct rendering order without complex sorting.
*   **Strengths**: Simple integration with BabylonJS, handles transparency correctly via two passes, robust color defaulting.
*   **Limitations**: Relies on the parent greedy mesher for geometry generation. The exact position and normal generation logic is not detailed in the source notes, requiring implementation assumptions.

## Background
The method originates from the CEWBS (Customizable Environment for Web-Based Simulation) project, specifically its voxel animation and collision examples. It is designed to work with the BabylonJS engine. The "Double-Pass" aspect is a specific implementation detail to handle transparency in voxel meshes, which is a common challenge in voxel rendering.
