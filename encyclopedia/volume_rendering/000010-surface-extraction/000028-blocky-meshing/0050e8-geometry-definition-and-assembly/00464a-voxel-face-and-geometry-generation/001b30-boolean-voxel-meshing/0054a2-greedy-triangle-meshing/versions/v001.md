# Greedy Triangle Meshing

Also called: Greedy Voxel Meshing, Greedy Meshing for BabylonJS

## Overview
Greedy Triangle Meshing is a surface extraction algorithm that converts a boolean voxel occupancy grid into an optimized triangular mesh by merging adjacent coplanar faces into larger polygons, which are then triangulated. It solves the problem of high vertex and index counts in naive voxel rendering by reducing the number of draw calls and vertices. It differs from its siblings, such as [Voxel Occupancy Boundary Detection](1011-voxel-occupancy-boundary-detection.md) which typically outputs individual quads, by explicitly performing a greedy merging step to maximize face area before triangulation. It builds on [Boolean Voxel Meshing](971-boolean-voxel-meshing.md) by adding this optimization phase.

## How it works
**Inputs and Outputs:**
- **Input:** A voxel grid defined by dimensions $D = [x, y, z]$ and a flat array of voxel data. Each voxel is either empty (`null`) or contains an `id` and optional `meta` data.
- **Output:** A mesh structure containing `vertices`, `normals`, `indices`, and `colors`. The indices form triangles.

**Data Structures:**
The internal voxel storage is a flat 1D array `voxels` of size $x \cdot y \cdot z$. The element at index $i$ corresponds to voxel coordinates $(cx, cy, cz)$ where $i = cx + cy \cdot x + cz \cdot x \cdot y$. Each element is `null` (air) or an array `[id, meta]` [S1, unofficial].

**Algorithm Steps:**
1. **Initialization:** Create a `VoxelMesh` object. Set dimensions $D$ using `setDimensions([x,y,z])`. This must be done before adding any voxels [S1, unofficial].
2. **Voxel Population:** Populate the grid using `setVoxelAt([cx,cy,cz], id, meta)` or `setVoxelBatch(voxelArray, id, meta)` [S1, unofficial].
3. **Mesh Rebuild Trigger:** Call `updateMesh()` to trigger the greedy mesher [S1, unofficial].
4. **Greedy Extraction:** The mesher iterates through the voxel grid to detect boundaries. For each boundary face, it attempts to merge it with adjacent coplanar faces in the local plane to form larger polygons. These polygons are then triangulated. The output is a `rawMesh` object containing:
   - `faces`: An array where each face $q$ is an array `[v0, v1, v2, id, meta]`. Here, $v0, v1, v2$ are vertex indices in the global vertex buffer, and $id, meta$ are from the source voxel [S1, unofficial].
   - `vertices`: The geometric positions of the vertices.
   - `normals`: The normal vectors for the vertices.
5. **Index Construction:** Iterate over `rawMesh.faces`. For each face $q$, push the vertex indices to the index buffer in reverse winding order: `q[2], q[1], q[0]` [S1, unofficial].
6. **Coloring:** For each face $q$, compute the color by calling `coloringFunction(q[3], q[4])`.
   - If the result is `null` or has length $< 3$, default to `[300, 75, 300, 255]` [S1, unofficial].
   - If the result has length 3, append alpha 255 [S1, unofficial].
   - Assign the color to the vertex color array `colors` at indices `q[i]*4` to `q[i]*4+3` for each vertex $i \in \{0, 1, 2\}$, dividing RGB values by 255 [S1, unofficial].
7. **Transparency Handling:** If `hasTransparency` is true, call `updateMesh(1)` to render transparent parts to a separate `transparentMesh` [S1, unofficial].

        self.name = name
        self.scene = scene
        self.dimensions = None
        self.voxel_data = None  # Flat array of size x*y*z
        self.coloring_function = None
        self.has_transparency = False

    def set_dimensions(self, dims):
        """Set dimensions [x, y, z]. Must be called before adding voxels."""
        self.dimensions = dims
        self.voxel_data = [None] * (dims[0] * dims[1] * dims[2])

    def set_voxel_at(self, pos, id_val, meta=None):
        """Set a single voxel. pos is [x, y, z]."""
        if self.dimensions is None:
            raise Error("Dimensions not set")
        x, y, z = pos
        idx = x + y * self.dimensions[0] + z * self.dimensions[0] * self.dimensions[1]
        self.voxel_data[idx] = [id_val, meta]

    def update_mesh(self, pass_id=0):
        """Rebuild the mesh using greedy triangle meshing."""
        raw_mesh = self._greedy_extract(self.voxel_data, self.dimensions)
        
        indices = []
        colors = []
        
        for face in raw_mesh.faces:
            # face is [v0, v1, v2, id, meta]
            v0, v1, v2, id_val, meta = face
            
            # Reverse winding order for indices
            indices.append(v2)
            indices.append(v1)
            indices.append(v0)
            
            # Compute color
            color = self.coloring_function(id_val, meta)
            if color is None or len(color) < 3:
                color = [300, 75, 300, 255]
            elif len(color) == 3:
                color = color + [255]
            
            # Assign colors to vertices (assuming vertex buffer is built separately)
            # Note: In the source, colors are assigned to a global colors array
            # based on vertex indices. Here we assume vertex indices are 0..N-1
            # and we fill the color buffer for these specific vertices.
            for v_idx in [v0, v1, v2]:
                # Divide RGB by 255
                r, g, b, a = [c / 255.0 for c in color]
                # Store in colors array at v_idx * 4
                colors[v_idx * 4] = r
                colors[v_idx * 4 + 1] = g
                colors[v_idx * 4 + 2] = b
                colors[v_idx * 4 + 3] = a / 255.0

        # Return mesh data
        return {
            'indices': indices,
            'colors': colors,
            'vertices': raw_mesh.vertices,
            'normals': raw_mesh.normals
        }

**Parameters:**
- `evaluateFunction`: A function `function(id, meta) { return !!id; }` used to determine if a voxel is solid [S1, unofficial].
- `coloringFunction`: A function `function(id, meta)` that returns an RGB array `[0-255]` for voxel coloring. If it returns `null` or invalid, voxels render as bright pink `[300, 75, 300, 255]` [S1, unofficial].

**Edge Cases and Pitfalls:**
- Dimensions must be set before any voxel operations; otherwise, `setVoxelAt` returns an error [S1, unofficial].
- If `coloringFunction` returns `null` or an invalid color, voxels render as bright pink `[300, 75, 300, 255]` [S1, unofficial].
- Dynamic dimension changes are problematic because the internal storage is a flat array [S1, unofficial].

## Subtopics

### [Double-Pass Voxel Mesh Update](15268-double-pass-voxel-mesh-update.md)
Updates a BabylonJS mesh by extracting geometry from a greedy voxel mesher and distributing it into two separate meshes: an opaque main mesh and a transparent secondary mesh. It solves the problem of rendering volumetric data with mixed opacity levels by separating faces based on their alpha values, ensuring correct depth sorting and blending for transparent surfaces while maintaining performance for opaque ones. It differs from single-pass meshing by explicitly handling transparency segregation during the geometry assembly phase.

## Operating characteristics
- **Time Complexity:** Not given in the sources.
- **Memory Complexity:** Not given in the sources.
- **Performance:** Uses a flat array for internal storage instead of 3D arrays for speed [S1, unofficial].
- **Strengths:** Optimized triangle meshes reduce vertex and index counts. Suitable for BabylonJS integration.
- **Limitations:** Dynamic dimension changes are problematic due to flat array storage. Requires careful handling of transparency if mixed opacity is needed.
- **When to use:** When rendering voxel data in BabylonJS and performance optimization via face merging is required.
- **When not to use:** When dynamic resizing of the voxel grid is frequent, or when using a different rendering engine without specific integration.

## Background
Greedy Triangle Meshing in this context is implemented as part of the CEWBS library for BabylonJS, based on the work by Mikolaj Lysenko (http://mikolalysenko.github.io/MinecraftMeshes2/) [S1, unofficial]. It is designed to provide an efficient way to render voxel data in web-based 3D applications.
