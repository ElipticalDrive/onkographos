# Grid Boundary Detection
Also called: RegularGrid::isBoundary
## Overview
Grid Boundary Detection determines if a specific voxel at coordinates $(x,y,z)$ lies on the boundary of an occupied region within a 3D occupancy grid [S1, unofficial]. It solves the problem of identifying interface voxels by checking if any voxel in its local neighborhood is empty [S1, unofficial]. It differs from its parent, [Voxel Occupancy Boundary Detection](1011-voxel-occupancy-boundary-detection.md), which checks only the 8 corner neighbors to define a boundary voxel, by using a configurable neighborhood size to detect boundaries based on a broader context [S1, unofficial]. It differs from its sibling, [3D Chain Code Representation](15714-3d-chain-code-representation.md), which encodes surface topology, by returning a simple boolean status for a single voxel [S1, unofficial].
## How it works
**Inputs:**
- `x, y, z`: Integer coordinates of the voxel to test.
- `numDivs`: Integer, the total number of divisions (dimensions) of the grid.
- `neighbourhoodSize`: Integer, the size of the cubic neighborhood to check.
- `grid`: 3D array or lookup structure where `grid[i][j][k]` returns the voxel state (e.g., `VOXEL_EMPTY` or occupied).

**Outputs:**
- Boolean: `true` if the voxel is on the boundary (i.e., any voxel in the neighborhood is empty), `false` otherwise.

**Data Structures:**
- The grid is assumed to be indexed from $0$ to $\text{numDivs}-1$ in each dimension.
- Voxel states are discrete; `VOXEL_EMPTY` is the specific constant indicating unoccupied space [S1, unofficial].

**Steps:**
1. **Adjust Neighborhood Size:** If `neighbourhoodSize` is even, increment it by 1 to ensure odd dimensions for symmetric neighborhoods [S1, unofficial].
2. **Calculate Bounds:** Determine the minimum and maximum indices for the neighborhood in each dimension, clamped to the valid grid range $[0, \text{numDivs}-1]$ [S1, unofficial].
   - Let $h = \lfloor \text{neighbourhoodSize} / 2 \rfloor$.
   - $x_{min} = \max(0, x - h)$, $x_{max} = \min(\text{numDivs}-1, x + h)$.
   - Similarly for $y$ and $z$.
3. **Iterate and Check:** Iterate through all voxels in the range $[x_{min}, x_{max}] \times [y_{min}, y_{max}] \times [z_{min}, z_{max}]$ [S1, unofficial].
4. **Return Result:** If any voxel in this neighborhood is `VOXEL_EMPTY`, return `true` [S1, unofficial]. If the loop completes without finding an empty voxel, return `false` [S1, unofficial].

**Pseudocode:**
```python
def is_boundary(x, y, z, numDivs, neighbourhoodSize, grid):
    # Step 1: Ensure odd neighborhood size for symmetry
    if neighbourhoodSize % 2 == 0:
        neighbourhoodSize += 1
    
    # Step 2: Calculate half-size and bounds
    half = neighbourhoodSize // 2
    x_min = max(0, x - half)
    x_max = min(numDivs - 1, x + half)
    y_min = max(0, y - half)
    y_max = min(numDivs - 1, y + half)
    z_min = max(0, z - half)
    z_max = min(numDivs - 1, z + half)
    
    # Step 3 & 4: Iterate and check for empty voxels
    for i in range(x_min, x_max + 1):
        for j in range(y_min, y_max + 1):
            for k in range(z_min, z_max + 1):
                if grid[i][j][k] == VOXEL_EMPTY:
                    return True
    return False
```

**Parameters:**
- `neighbourhoodSize`: Typical value is 3 (checking immediate 26-connected neighbors) or 1 (checking only the voxel itself, though this is degenerate for boundary detection) [S1, unofficial]. Not given in the sources for other specific values.

**Edge Cases and Pitfalls:**
- **Even Neighborhood Size:** Using an even size results in asymmetric neighborhoods. The algorithm explicitly corrects this by incrementing the size [S1, unofficial].
- **Boundary Clamping:** Coordinates near the grid edges must be clamped to $[0, \text{numDivs}-1]$ to avoid out-of-bounds access [S1, unofficial].
- **Performance:** The complexity grows with the cube of the neighborhood size. Large neighborhoods are expensive [S1, unofficial].

## Subtopics

### [Algorithm SD (Surface Detection)](21991-algorithm-sd-surface-detection.md)
Computes a boundary surface by tracking faces between inside/outside voxels, outputting precise geometric properties (center, normal). Choose this when rendering geometry is required, rather than just identifying boundary voxels.

## Operating characteristics
**Time Complexity:** $O(N^3)$ where $N$ is the `neighbourhoodSize`, per voxel.
**Memory Complexity:** $O(1)$ auxiliary space, assuming grid access is $O(1)$.
**Strengths:** Simple to implement; configurable sensitivity to boundary definition via neighborhood size.
**Limitations:** Does not provide geometric primitives (normals, centers) for rendering; performance degrades with large neighborhoods.
**When to use:** When a quick boolean check for boundary status is needed, or as a preprocessing step for more complex surface extraction.
**When not to use:** When precise surface geometry is required for rendering (use Algorithm SD instead).
## Background
Originated in the context of voxel-based game engines and real-time rendering systems, specifically referenced in the VoxelFragmentML project [S1, unofficial]. It is a fundamental primitive for voxel-based meshing pipelines.
