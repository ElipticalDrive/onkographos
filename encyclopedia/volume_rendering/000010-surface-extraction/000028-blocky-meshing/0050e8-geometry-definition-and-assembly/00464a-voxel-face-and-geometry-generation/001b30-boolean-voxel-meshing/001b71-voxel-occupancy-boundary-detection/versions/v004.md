# Voxel Occupancy Boundary Detection

Also called: Boundary Detection

## Overview
Voxel Occupancy Boundary Detection identifies voxels in a 3D occupancy grid that lie on the interface between occupied and unoccupied space, producing a boundary mask used by Boolean Voxel Meshing to generate triangular geometry [S1, S2, unofficial]. It differs from sibling methods by operating directly on the raw boolean grid to flag boundary voxels via neighborhood checks, whereas [Octree Traversal for Surface Extraction](2113-octree-traversal-for-surface-extraction.md) traverses hierarchical structures, and [VoxelGrid Mesh Generation](2714-voxelgrid-mesh-generation.md) or [Greedy Triangle Meshing](15263-greedy-triangle-meshing.md) focus on immediate mesh assembly rather than explicit boundary flagging.

## How it works
**Inputs:**
- `grid`: A 3D boolean occupancy grid of shape $(D_x, D_y, D_z)$, where `True` indicates occupied and `False` indicates empty.
- `boundarySize`: An integer radius (in voxels) defining the width of the boundary region around the surface [S1, unofficial].

**Outputs:**
- `boundary_mask`: A 3D boolean grid of the same shape as `grid`, where `True` indicates a voxel is part of the detected boundary.

**Data Structures:**
- The grid is stored as a contiguous array or tensor. For GPU implementations, it is bound as a Shader Storage Buffer Object (SSBO) [S1, unofficial].

**Steps:**

1. **Compute Occupied Voxels:**
   A voxel is considered "strictly occupied" if all 8 of its corner neighbors are occupied. This requires checking the 8 adjacent cells in the grid. Let $O(x,y,z)$ be the occupancy value at $(x,y,z)$. The occupied mask $M_{occ}$ is computed as:
   $$
   M_{occ}[x,y,z] = O[x,y,z] \land O[x+1,y,z] \land O[x,y+1,z] \land O[x,y,z+1] \land O[x+1,y+1,z] \land O[x+1,y,z+1] \land O[x,y+1,z+1] \land O[x+1,y+1,z+1]
   $$
   This logic applies to all valid interior indices where the 8 neighbors exist [S2, unofficial].

2. **Compute Unoccupied Voxels:**
   A voxel is considered "strictly unoccupied" if all 8 of its corner neighbors are empty. Using De Morgan's laws, this is equivalent to the negation of the OR of the neighbors:
   $$
   M_{unocc}[x,y,z] = \neg (O[x,y,z] \lor O[x+1,y,z] \lor O[x,y+1,z] \lor O[x,y,z+1] \lor O[x+1,y+1,z] \lor O[x+1,y,z+1] \lor O[x,y+1,z+1] \lor O[x+1,y+1,z+1])
   $$
   This logic applies to all valid interior indices [S2, unofficial].

3. **Determine Boundary Voxels:**
   A voxel is on the boundary if it is neither strictly occupied nor strictly unoccupied. This is calculated as:
   $$
   M_{boundary}[x,y,z] = \neg M_{occ}[x,y,z] \land \neg M_{unocc}[x,y,z]
   $$
   This identifies voxels where the corner neighborhood is mixed [S2, unofficial].

4. **Expand Boundary (Optional):**
   If `boundarySize` > 1, the initial boundary mask is dilated by a radius of `boundarySize` voxels. This involves checking a neighborhood of size $(2 \cdot boundarySize + 1)^3$ around each voxel. If any voxel in this neighborhood is in $M_{boundary}$, the current voxel is marked as boundary [S1, unofficial].

**Pseudocode:**
```python
def voxel_occupancy_boundary_detection(grid, boundary_size=1):
    """
    Detects boundary voxels in a 3D boolean occupancy grid.
    
    Args:
        grid: 3D numpy array of booleans (True=occupied, False=empty).
        boundary_size: Integer radius for boundary expansion.
        
    Returns:
        boundary_mask: 3D numpy array of booleans.
    """
    # Pad grid to handle boundary conditions for neighbor checks
    # Padding of 1 is sufficient for the 8-corner check
    padded = np.pad(grid, pad_width=1, mode='constant', constant_values=False)
    
    # Compute strictly occupied mask
    # Check all 8 corners relative to the center of the 2x2x2 block
    # Note: The source logic implies checking the 8 voxels surrounding a 
    # conceptual point, but applied to voxel centers, it checks the 8 
    # neighbors of the voxel at (i,j,k) shifted by indices.
    # Based on S2: occ[..., :-1, :-1, :-1] & ... & occ[..., 1:, 1:, 1:]
    # This corresponds to checking the 8 neighbors of the voxel at index i,j,k
    # within the padded grid.
    
    # Extract 8 neighbors for each voxel in the original grid dimensions
    # The slicing logic in S2:
    # occ[..., :-1, :-1, :-1] -> neighbor at (i, j, k)
    # occ[..., :-1, :-1, 1:]  -> neighbor at (i, j, k+1)
    # ...
    # occ[..., 1:, 1:, 1:]    -> neighbor at (i+1, j+1, k+1)
    
    # We apply this to the padded grid to get the mask for the original grid size
    n1 = padded[:-1, :-1, :-1]
    n2 = padded[:-1, :-1, 1:]
    n3 = padded[:-1, 1:, :-1]
    n4 = padded[:-1, 1:, 1:]
    n5 = padded[1:, :-1, :-1]
    n6 = padded[1:, :-1, 1:]
    n7 = padded[1:, 1:, :-1]
    n8 = padded[1:, 1:, 1:]
    
    occupied = n1 & n2 & n3 & n4 & n5 & n6 & n7 & n8
    unoccupied = ~(n1 | n2 | n3 | n4 | n5 | n6 | n7 | n8)
    
    boundary = ~occupied & ~unoccupied
    
    # Expand boundary if necessary
    if boundary_size > 1:
        # Dilate the boundary mask
        # Simple dilation using max pooling or iterative neighbor check
        # For arbitrary radius, we check if any voxel in the neighborhood is True
        expanded_boundary = np.zeros_like(grid, dtype=bool)
        radius = boundary_size
        # Iterate over the neighborhood
        for dx in range(-radius, radius + 1):
            for dy in range(-radius, radius + 1):
                for dz in range(-radius, radius + 1):
                    # Shift the boundary mask
                    # Handle slicing carefully to stay within bounds
                    if dx >= 0 and dy >= 0 and dz >= 0:
                        s1 = boundary[:grid.shape[0]-dx, :grid.shape[1]-dy, :grid.shape[2]-dz]
                        s2 = expanded_boundary[dx:, dy:, dz:]
                        s2 |= s1
                    elif dx < 0 and dy < 0 and dz < 0:
                        s1 = boundary[-dx:, -dy:, -dz:]
                        s2 = expanded_boundary[:grid.shape[0]+dx, :grid.shape[1]+dy, :grid.shape[2]+dz]
                        s2 |= s1
                    # General case requires more complex slicing logic or convolution
                    # For simplicity, we assume a standard dilation kernel
                    pass
        
        # More robust dilation using scipy or manual loop for small radius
        # Since S1 mentions "neighborhoodSize", we implement a generic neighborhood check
        final_boundary = np.zeros_like(grid, dtype=bool)
        for x in range(grid.shape[0]):
            for y in range(grid.shape[1]):
                for z in range(grid.shape[2]):
                    # Check neighborhood
                    min_x = max(0, x - radius)
                    max_x = min(grid.shape[0], x + radius + 1)
                    min_y = max(0, y - radius)
                    max_y = min(grid.shape[1], y + radius + 1)
                    min_z = max(0, z - radius)
                    max_z = min(grid.shape[2], z + radius + 1)
                    
                    if np.any(boundary[min_x:max_x, min_y:max_y, min_z:max_z]):
                        final_boundary[x, y, z] = True
        boundary = final_boundary
        
    return boundary
```

**Parameters:**
- `boundarySize`: Integer radius (in voxels) from the surface to mark as boundary. Default is 1 [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Grid Boundaries:** The 8-neighbor check fails at the grid edges. Padding or clamping is required [S1, S2, unofficial].
- **Precision:** Boolean logic is exact, but floating-point occupancy grids must be thresholded before conversion [S2, unofficial].
- **Degenerate Input:** A completely empty or completely filled grid results in an empty boundary mask [S2, unofficial].

## Subtopics

### Binary Volume Cell Classification
Binary Volume Cell Classification determines if an isosurface intersects an octree leaf cell in a binary volume by checking its 8 corner voxels [S3, unofficial]. If all corners have the same value, the cell is homogeneous; if at least one corner differs, it is heterogeneous [S3, unofficial]. Heterogeneous cells contain bipolar edges (edges with endpoints of different values), which indicate isosurface intersection [S3, unofficial]. This method is used for hierarchical surface extraction where cell classification drives mesh generation [S3, unofficial].

### Grid Boundary Detection
Grid Boundary Detection determines if a voxel at $(x,y,z)$ is on the boundary of an occupied region by checking if any voxel in its neighborhood is empty [S1, unofficial]. If the neighborhood size is even, it is incremented by 1 to ensure symmetric dimensions [S1, unofficial]. The algorithm calculates min/max bounds clamped to grid dimensions and iterates through the neighborhood, returning true if any voxel is empty [S1, unofficial]. This is a simpler, neighborhood-based alternative to the 8-corner logic [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of voxels, as each voxel is processed once with a constant number of neighbor checks [S1, S2, unofficial].
- **Memory Complexity:** $O(N)$ for storing the input grid and output boundary mask [S1, unofficial].
- **Performance:** GPU implementations using compute shaders can process large grids efficiently by parallelizing the neighbor checks [S1, unofficial].
- **Strengths:** Simple, exact boolean logic; no interpolation required; suitable for binary volumes [S2, unofficial].
- **Limitations:** Only works for binary occupancy; does not handle partial voxel occupancy or scalar fields directly [S2, unofficial].
- **When to Use:** When a fast, exact boundary mask is needed for boolean meshing of binary voxel data [S1, S2, unofficial].
- **When Not to Use:** For scalar fields requiring marching cubes or for hierarchical octree-based extraction [S3, unofficial].

## Background
Voxel Occupancy Boundary Detection is a fundamental step in boolean voxel meshing, originating from the need to efficiently convert voxel grids to meshes [S1, unofficial]. It relies on the topological property that boundary voxels are those with mixed neighborhoods [S2, unofficial]. The method is widely used in GPU-based voxel processing pipelines, such as those in VoxelFragmentML [S1, unofficial], and differentiable volumetric rendering frameworks [S2, unofficial]. Binary cell classification variants are used in octree-based surface extraction for massive binary volumes [S3, unofficial].
