# Voxel Face Mesh Generation

Also called: Exposed Face Mesh Generation, Face-to-Vertex Generation with UV and Lighting, Visible Block Faces Meshing, Voxel Face Generation, Voxel Quad Generation

## Overview
Voxel Face Mesh Generation is a surface extraction algorithm that converts a 3D occupancy grid or density field into a blocky triangle mesh by emitting one quad (two triangles) for every voxel face exposed to empty space or a chunk boundary [S1, S3, unofficial][S9]. It solves the problem of rendering large voxel worlds efficiently by culling internal faces between adjacent solid voxels, thereby reducing vertex count and draw calls compared to rendering individual cubes [S1, S10, unofficial]. Unlike smooth surface extraction methods like Marching Cubes, this method preserves the axis-aligned, blocky aesthetic inherent to voxel data [S1, unofficial][S9]. It differs from its sibling [Boolean Voxel Meshing](971-boolean-voxel-meshing.md) by focusing on simple neighbor-based visibility checks rather than complex boolean operations on voxel sets.

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D voxel grid (occupancy array, density field, or block ID map) and optional metadata (block types, texture atlas indices). The grid may be conceptually or physically padded with a 1-voxel empty boundary to simplify neighbor lookups [S1, S3, S5, unofficial].
*   **Output:** A mesh data structure containing arrays of vertices (positions, normals, UVs, colors), triangle indices, and optionally tangents [S2, S4, S8, unofficial].

**Data Structures:**
*   **Voxel Grid:** Stored as a 1D array or 3D array. For a chunk of size $W \times H \times D$, the linear index is often $x + W(y + H z)$ [S8, unofficial].
*   **MeshData Buffer:** Dynamic arrays for vertices, indices, normals, UVs, and colors. Pre-allocation is common using an estimate like $ChunkWidth^2 \times ChunkHeight \times 6$ vertices [S8, unofficial].
*   **Face Definitions:** Constants defining the 4 corner vertices, 2 triangle index sets, and normal vector for each of the 6 face directions (Up, Down, North, South, East, West) [S2, S5, S7, unofficial].

**Numbered Steps:**

1.  **Initialize Mesh Buffers:** Clear or allocate memory for vertices, indices, normals, UVs, and colors [S8, unofficial]. Estimate capacity to avoid reallocation [S8, unofficial].
2.  **Iterate Voxels:** Loop through all voxels in the grid. If using padding, iterate only the interior voxels (indices $1$ to $Size-2$) to avoid boundary checks for neighbors [S3, unofficial]. If no padding, check bounds for every neighbor [S10, unofficial].
3.  **Check Solidity:** Determine if the current voxel is solid. For occupancy grids, this means the voxel is not "Air" or "Empty" [S8, unofficial]. For density fields, check if density $\ge$ iso_value [S6, unofficial].
4.  **Check Neighbors (Face Culling):** For each of the 6 face directions, check the immediate neighbor voxel [S1, unofficial][S9].
    *   Calculate neighbor coordinates: $neighbor\_pos = current\_pos + face\_normal$ [S3, S8, unofficial].
    *   Determine visibility:
        *   If the neighbor is out of bounds, treat it as empty/visible [S9][S10, unofficial].
        *   If the neighbor is empty (Air, density < iso_value, or `visible=false`), the face is exposed [S1, S6, unofficial].
        *   **Translucency Rule:** If the voxel is translucent, generate the face only if the neighbor is empty; if the neighbor is opaque, hide the face [S3, unofficial].
        *   If the neighbor is solid (and opaque), the face is internal and culled [S1, unofficial].
5.  **Generate Geometry for Exposed Faces:** For each exposed face:
    *   **Vertices:** Calculate the 4 corner positions. Base the positions on the voxel's world position ($pos = voxel\_index \times BlockSize$) and add the local offset defined for that face direction [S2, S5, unofficial].
        *   Example for Top Face: $pos + (0,1,0), pos + (1,1,0), pos + (1,1,1), pos + (0,1,1)$ [S5, unofficial].
    *   **Indices:** Add 6 indices to form two triangles. The winding order must be consistent (e.g., counter-clockwise) for back-face culling. A common pattern is $(0,1,2)$ and $(3,2,1)$ relative to the current vertex count [S2, S7, unofficial].
    *   **Normals:** Assign the face normal to all 4 vertices (e.g., $(0,1,0)$ for Top) [S2, S5, unofficial].
    *   **UVs:** Calculate texture coordinates based on the block type and face orientation. Use a texture atlas lookup to determine the UV tile, applying scaling and inversion if necessary for the specific face winding [S2, S4, unofficial].
    *   **Colors/Lighting:** Assign vertex colors. This may be a flat color, or interpolated lighting values sampled from neighbors (smooth lighting) [S1, S2, unofficial].
6.  **Upload Mesh:** Assign the populated vertex, index, normal, and UV arrays to the graphics API's mesh object [S1, S8, unofficial]. Recalculate bounds and tangents if required by the engine [S1, unofficial].

**Formulas:**
*   **Face Visibility:**
    $$
    \text{face\_needs\_mesh}(voxel, neighbor) = 
    \begin{cases} 
    \text{true} & \text{if } (voxel \in \text{Opaque} \land neighbor \in \text{Empty}) \\
    \text{true} & \text{if } (voxel \in \text{Translucent} \land neighbor \in \text{Empty}) \\
    \text{false} & \text{if } (voxel \in \text{Empty}) \lor (neighbor \in \text{Opaque}) \lor (voxel \in \text{Translucent} \land neighbor \in \text{Translucent})
    \end{cases}
    $$
    [S3, unofficial]
*   **Vertex Position:**
    $$
    V_{i} = P_{voxel} + O_{face, i} \times BlockSize
    $$
    Where $P_{voxel}$ is the voxel's world position, $O_{face, i}$ is the $i$-th local offset for the face direction, and $BlockSize$ is the voxel scale [S2, S5, unofficial].
*   **Linear Index (1D Array):**
    $$
    Index(x, y, z) = x + Width \times (y + Height \times z)
    $$
    [S8, unofficial]

**Parameters:**
*   **BlockSize:** World unit size of a voxel. Typical value: 1.0 [S2, unofficial].
*   **Iso_value:** Threshold for density fields. Typical value: 0.5 [S6, unofficial].
*   **Chunk Size:** Dimensions of the meshed region. Common values: $16 \times 64 \times 16$ [S10, unofficial].
*   **Atlas Size:** Resolution of the texture atlas (e.g., 16x16 tiles) [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Boundary Checks:** If the grid is not padded, out-of-bounds neighbor access must be handled explicitly to avoid crashes and ensure chunk edges are rendered [S10, unofficial].
*   **Winding Order:** Inconsistent triangle winding (e.g., mixing $(0,1,2)$ and $(0,2,1)$) causes back-face culling failures, resulting in holes or double-rendered geometry [S2, S1, unofficial].
*   **Memory Leaks (Editor):** In Unity, modifying `Mesh` directly in the editor creates duplicate assets; `SharedMesh` must be used [S1, unofficial].
*   **Cross-Chunk Consistency:** Faces at chunk boundaries must be generated by the owning chunk, and neighbor chunks must not generate overlapping geometry for the same face [S8, S10, unofficial].

**Pseudocode:**

```python
def generate_voxel_face_mesh(voxel_grid, chunk_width, chunk_height, chunk_depth, block_size, atlas_size):
    """
    Generates a mesh from a voxel grid by emitting quads for exposed faces.
    
    Args:
        voxel_grid: 3D array or 1D array of block IDs/densities.
        chunk_width, chunk_height, chunk_depth: Dimensions of the chunk.
        block_size: Scale factor for voxel positions.
        atlas_size: Number of tiles along one axis of the texture atlas.
        
    Returns:
        MeshData: Object containing vertices, indices, normals, UVs, colors.
    """
    # 1. Initialize buffers
    vertices = []
    indices = []
    normals = []
    uvs = []
    colors = []
    
    # Pre-allocate if possible (estimate: 6 faces per voxel * 4 verts)
    estimated_faces = chunk_width * chunk_height * chunk_depth * 6
    vertices.reserve(estimated_faces * 4)
    indices.reserve(estimated_faces * 6)
    
    # 2. Iterate through all voxels
    for z in range(chunk_depth):
        for y in range(chunk_height):
            for x in range(chunk_width):
                # Get block type/density
                block_id = get_block_at(voxel_grid, x, y, z)
                
                # Skip empty/air blocks
                if is_empty(block_id):
                    continue
                
                # 3. Check 6 neighbors
                for face_dir in [UP, DOWN, NORTH, SOUTH, EAST, WEST]:
                    neighbor_pos = get_neighbor_pos(x, y, z, face_dir)
                    
                    # Check if neighbor is out of bounds or empty
                    is_neighbor_empty = False
                    if is_out_of_bounds(neighbor_pos, chunk_width, chunk_height, chunk_depth):
                        is_neighbor_empty = True
                    else:
                        neighbor_id = get_block_at(voxel_grid, *neighbor_pos)
                        if is_empty(neighbor_id):
                            is_neighbor_empty = True
                        # Optional: Translucency logic
                        elif is_translucent(block_id) and is_opaque(neighbor_id):
                            is_neighbor_empty = False # Hide face
                            
                    if not is_neighbor_empty:
                        continue
                        
                    # 4. Generate Quad Geometry
                    base_vertex_count = len(vertices)
                    
                    # Get face-specific vertex offsets and normal
                    face_verts = get_face_vertices(face_dir) # Returns 4 local offsets
                    face_normal = get_face_normal(face_dir)
                    
                    # Calculate UVs for this block and face
                    uvi, uvj = get_atlas_uv(block_id, face_dir)
                    uv_size = 1.0 / atlas_size
                    
                    for i in range(4):
                        # Position
                        local_offset = face_verts[i]
                        world_pos = (x * block_size + local_offset.x,
                                     y * block_size + local_offset.y,
                                     z * block_size + local_offset.z)
                        vertices.append(world_pos)
                        
                        # Normal
                        normals.append(face_normal)
                        
                        # UV (with potential inversion/flip based on face)
                        # Simplified: assume standard atlas layout
                        u = (uvi + local_offset.u) * uv_size
                        v = (uvj + local_offset.v) * uv_size
                        uvs.append((u, v))
                        
                        # Color (e.g., flat gray or lighting)
                        colors.append((0.75, 0.75, 0.75, 1.0))
                    
                    # Indices (Winding: 0,1,2 and 3,2,1 for CCW)
                    indices.append(base_vertex_count + 0)
                    indices.append(base_vertex_count + 1)
                    indices.append(base_vertex_count + 2)
                    indices.append(base_vertex_count + 3)
                    indices.append(base_vertex_count + 2)
                    indices.append(base_vertex_count + 1)
                    
    return MeshData(vertices, indices, normals, uvs, colors)
```

## Subtopics

### [Texture Atlas UV Mapping](4238-texture-atlas-uv-mapping.md)
Maps block types to sub-regions of a shared texture atlas using a per-face lookup table, with UV inversion for correct winding order. It assigns UV coordinates to voxel face meshes based on block type and face orientation, enabling efficient single-material rendering of complex voxel worlds.

### [Face Direction and Quad Geometry](4881-face-direction-and-quad-geometry.md)
Defines the six axis-aligned face orientations on a voxel cube and provides the deterministic logic for generating quad geometry (positions, indices, UVs, and normals) for meshing. It solves the problem of converting abstract voxel face exposure data into concrete vertex buffer layouts suitable for standard rasterization pipelines.

### [Block Face Mesh Generation](10913-block-face-mesh-generation.md)
Generates a 6-vertex mesh data structure for a single exposed face of a voxel block, applying special geometric adjustments for specific block types (such as cactus) and packing vertex attributes for GPU consumption. It differs from its sibling [Face Direction and Quad Geometry](4881-face-direction-and-quad-geometry.md) by handling block-specific geometry modifications (like cactus insets) and attribute packing, rather than just providing generic face normals and UVs. It serves as the concrete implementation step within [Voxel Face Mesh Generation](4212-voxel-face-mesh-generation.md) that populates the `MeshData` buffer with the final vertex and index data for a specific block instance.

### [Voxel Meshing with Smooth Lighting](10951-voxel-meshing-with-smooth-lighting.md)
Extends the vertex data to include per-vertex lighting colors (sun and block light) and supports smooth lighting by sampling 8 neighboring voxels per face to create smoother lighting transitions. Unlike flat lighting which uses a single neighbor value, this method averages light from surrounding voxels to reduce the "blocky" appearance of shadows.

### [Chunk Mesh Creation](14967-chunk-mesh-creation.md)
Generates the final visible geometry for a voxel chunk by identifying exposed block faces and assembling them into a single draw call. It differs from its parent [Voxel Face Mesh Generation](4212-voxel-face-mesh-generation.md), which produces individual quads, by handling the spatial culling logic across chunk boundaries and combining multiple face meshes into one unified mesh structure.

## Operating characteristics
*   **Time Complexity:** $O(N)$, where $N$ is the number of voxels in the chunk. Each voxel is visited once, and 6 neighbor checks are performed [S1, unofficial][S9].
*   **Memory Complexity:** $O(F)$, where $F$ is the number of exposed faces. In the worst case (all faces exposed), this is $6N$ quads. In typical scenes, it is significantly less due to culling [S1, unofficial][S9].
*   **Measured Performance:** On a $16 \times 64 \times 16$ chunk, this method generates thousands of quads for sparse structures but reduces them to hundreds for dense terrain. It is significantly faster than greedy meshing but produces more geometry [S9].
*   **Strengths:** Simple to implement, fast execution, low memory overhead per face, preserves voxel aesthetic [S1, unofficial][S9].
*   **Limitations:** High triangle count compared to optimized meshing (greedy, marching cubes), no smooth surfaces, potential for overdraw if not sorted or if translucent blocks are present [S1, S3, unofficial].
*   **When to Use:** Real-time voxel games where performance is critical and blocky aesthetic is desired. Not suitable for smooth organic terrain or high-fidelity rendering [S1, unofficial][S9].

## Background
Voxel Face Mesh Generation is a foundational technique in voxel rendering, originating from early Minecraft clones and procedural terrain generators. It was popularized by the need to render large voxel worlds efficiently on limited hardware. The method relies on simple neighbor checking rather than complex algorithms like Marching Cubes, resulting in a blocky aesthetic [S1, unofficial][S9]. It is widely used in games like Minecraft, Terraria, and various voxel editors [S1, S10, unofficial].
