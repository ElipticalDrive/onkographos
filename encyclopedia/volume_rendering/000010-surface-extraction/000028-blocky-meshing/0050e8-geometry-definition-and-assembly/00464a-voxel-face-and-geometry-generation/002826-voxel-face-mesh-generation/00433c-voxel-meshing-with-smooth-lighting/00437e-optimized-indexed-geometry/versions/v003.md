# Optimized Indexed Geometry

Also called: Optimized Indexed Quad Surface Meshing

## Overview
Optimized Indexed Geometry is a voxel meshing technique that generates optimized indexed quad geometry for active voxels, resulting in 8 vertices per voxel [S1, unofficial]. It differs from standard Indexed Quad Meshing by reducing primitive count through optimization logic, likely leveraging heightfield data to minimize unnecessary geometry generation [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A `Chunk` object containing a 3D voxel grid, and a `Heightfield` parameter [S1, unofficial].
- Output: Vertex and index buffers for the chunk's visual mesh, and updated geometry statistics [S1, unofficial].

**Data Structures:**
- `Chunk`: Contains a 3D array `voxels[CHUNK_SIZE][CHUNK_SIZE][CHUNK_SIZE]` of `Block` objects [S1, unofficial].
- `Block`: Contains `activationState` (bool) and `blockType` (unsigned char) [S1, unofficial].
- `CHUNK_SIZE`: Constant integer value 16 [S1, unofficial].
- `Statistics`: A structure tracking mesh counts, where `vertices` stores the total vertex count [S1, unofficial].

**Steps:**
1. Initialize a local `voxel_counter` to 0 [S1, unofficial].
2. Iterate over all voxel coordinates $(x, y, z)$ where $0 \le x, y, z < \text{CHUNK\_SIZE}$ [S1, unofficial].
3. For each coordinate, check if the voxel is active using `chunk.IsVoxelActive(x, y, z)` [S1, unofficial].
4. If the voxel is active:
   a. Generate the optimized quad geometry for the active voxel [S1, unofficial].
   b. Increment `voxel_counter` by 1 [S1, unofficial].
5. After the loops complete, update global statistics by adding `voxel_counter * 8` to `statistics.vertices` [S1, unofficial].

**Pseudocode:**
```python
class Chunk:
    CHUNK_SIZE = 16
    def __init__(self, voxels):
        self.voxels = voxels
    def IsVoxelActive(self, x, y, z):
        return self.voxels[x][y][z]

def CreateOptimizedIndexedGeometry(chunk, heightfield):
    voxel_counter = 0
    statistics = {'vertices': 0}
    
    for x in range(Chunk.CHUNK_SIZE):
        for y in range(Chunk.CHUNK_SIZE):
            for z in range(Chunk.CHUNK_SIZE):
                if chunk.IsVoxelActive(x, y, z):
                    # Generate optimized quad geometry for the active voxel (sources do not provide implementation details [G])
                    voxel_counter += 1
                    
    statistics['vertices'] += voxel_counter * 8
    return statistics
```

**Parameters:**
- `Heightfield`: A parameter passed to `CreateOptimizedIndexedGeometry`, likely containing heightmap data for optimization logic [S1, unofficial].

**Edge Cases and Pitfalls:**
- The optimization logic relies on the `Heightfield` parameter; if not provided or invalid, the optimization may fail or degrade to standard meshing [S1, unofficial].

## Subtopics

### Indexed Quad Meshing
Indexed Quad Meshing is a voxel meshing technique that generates a full cube for every active voxel using indexed quads, resulting in 6 quads, 8 vertices, and 24 indices per voxel [S1, unofficial]. The steps involve iterating over all voxel coordinates, checking if the voxel is active, and calling `CreateQuadVoxel` for each active voxel [S1, unofficial]. Statistics are updated by adding `voxel_counter` to `statistics.x`, `voxel_counter * 6` to `statistics.y` (primitives), `voxel_counter * 8` to `statistics.z` (vertices), and `voxel_counter * 24` to `statistics.w` (indices) [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of voxels in the chunk, $O(\text{CHUNK\_SIZE}^3)$, as every voxel is checked [S1, unofficial].
- **Memory Complexity:** Proportional to the number of active voxels, with 8 vertices per voxel for Optimized Indexed Geometry and 8 vertices per voxel for Indexed Quad Meshing [S1, unofficial].
- **Performance:** Optimized Indexed Geometry reduces primitive count compared to Indexed Quad Meshing, which generates 6 quads per voxel [S1, unofficial].
- **Strengths:** Efficient vertex usage (8 vertices per voxel) and reduced primitive count through optimization [S1, unofficial].
- **Limitations:** Optimization logic depends on external heightfield data, which may not always be available or accurate [S1, unofficial].
