# Material Sampling

Also called: faceUV

## Overview
Material Sampling maps block identifiers to specific texture samplers and computes UV coordinates based on the face normal, enabling correct texturing of blocky meshes using a shared texture atlas. It differs from its parent [Texture Atlas UV Mapping](4238-texture-atlas-uv-mapping.md) by adding block-type-specific logic (such as grass top/side mixing and leaf tinting) rather than relying solely on geometric UV projection.

## How it works
**Inputs:**
- `blockID`: Integer identifier for the block type (e.g., 1 for grass, 5 for leaves).
- `localPos`: `vec3` position of the vertex within the voxel unit cube $[0, 1]^3$.
- `faceNormal`: `vec3` unit normal of the face being shaded.
- `cell`: `ivec3` integer coordinates of the voxel cell (used for procedural variation).
- `tileScale`: Scalar multiplier for UV coordinates (implementation detail, typically derived from atlas dimensions).
- `atlasLod`: Fixed to `0.0` to disable mip-map selection [S1, unofficial].

**Outputs:**
- `albedo`: `vec3` color value sampled from the appropriate texture atlas region.

**Data Structures:**
- Texture samplers: `samplerGrass`, `samplerGrassSide`, `samplerDirt`, `samplerStone`, `samplerWood`, `samplerWoodSide`, `samplerLeaves` [S1, unofficial].
- Helper function `hash12(vec2 p)`: Returns a pseudo-random float in $[0, 1]$ based on input coordinates [S1, unofficial].

**Steps:**

1. **Compute UV Coordinates:**
   Determine the 2D UV coordinates based on the dominant axis of the `faceNormal`. This projects the 3D local position onto the 2D plane defined by the face normal [S1, unofficial].
   $$
   \text{uv} = \begin{cases} 
   (z, y) \times \text{tileScale} & \text{if } |n_x| > 0.5 \\
   (x, z) \times \text{tileScale} & \text{if } |n_y| > 0.5 \\
   (x, y) \times \text{tileScale} & \text{otherwise}
   \end{cases}
   $$
   Where $\text{localPos} = (x, y, z)$ and $\text{faceNormal} = (n_x, n_y, n_z)$ [S1, unofficial].

2. **Sample Based on Block ID:**
   Apply block-specific sampling logic [S1, unofficial]:

   - **Grass (ID 1):**
     - If $n_y > 0$: Sample `samplerGrass` (top) and tint it by mixing with a fixed grass-side green color.
     - If $n_y < 0$: Sample `samplerDirt`.
     - Otherwise (side faces): Sample `samplerGrassSide`.

   - **Leaves (ID 5):**
     - Sample `samplerLeaves` using the computed UV.
     - Apply brightness variation using a hash of the cell coordinates: $v = \text{hash12}(\text{cell}.x \times 0.17, \text{cell}.y \times 0.29)$.
     - Modulate base color: $\text{base} \times (0.82 + 0.28 \times v)$.
     - If $n_y < 0$ (bottom face), darken the result by multiplying by $0.70$.
     - Mix the result with a fixed grass-side green color with a weight of $0.72$ [S1, unofficial].

   - **Wood (ID 4):**
     - If $|n_y| > 0$ (top or bottom): Sample `samplerWood` (log top).
     - Otherwise (sides): Sample `samplerWoodSide` (log side) [S1, unofficial].

   - **Other Blocks:**
     - Dirt (ID 2), Stone (ID 3), and others are sampled directly from their respective atlas regions using the UV computed in Step 1 [S1, unofficial].

**Pseudocode:**

```python
def material_sampling(block_id, local_pos, face_normal, cell, tile_scale, atlas_lod):
    # Step 1: Compute UV based on dominant normal axis
    x, y, z = local_pos
    nx, ny, nz = face_normal
    
    if abs(nx) > 0.5:
        uv = vec2(z, y) * tile_scale
    elif abs(ny) > 0.5:
        uv = vec2(x, z) * tile_scale
    else:
        uv = vec2(x, y) * tile_scale
        
    # Step 2: Sample based on block ID
    if block_id == 1: # Grass
        if ny > 0.0:
            # Top: Grass texture tinted by grass side green
            top_color = texture(samplerGrass, uv, atlas_lod).rgb
            grass_green = fetch_grass_side_green() # Fixed UV lookup
            tint_strength = 0.92
            result = mix(top_color, top_color * grass_green, tint_strength)
            return clamp(result, 0.0, 1.0)
        elif ny < 0.0:
            # Bottom: Dirt
            return texture(samplerDirt, uv, atlas_lod).rgb
        else:
            # Side: Grass side
            return texture(samplerGrassSide, uv, atlas_lod).rgb
            
    elif block_id == 5: # Leaves
        base = texture(samplerLeaves, uv, atlas_lod).rgb
        # Brightness variation
        v = hash12(vec2(float(cell.x) * 0.17, float(cell.y) * 0.29))
        base = base * (0.82 + 0.28 * v)
        # Darken bottom face
        if ny < 0.0:
            base = base * 0.70
        # Mix with grass green
        grass_green = fetch_grass_side_green()
        base = mix(base, grass_green * length(base), 0.72)
        return base
        
    elif block_id == 4: # Wood
        if abs(ny) > 0.0:
            return texture(samplerWood, uv, atlas_lod).rgb
        else:
            return texture(samplerWoodSide, uv, atlas_lod).rgb
            
    elif block_id == 2: # Dirt
        return texture(samplerDirt, uv, atlas_lod).rgb
        
    elif block_id == 3: # Stone
        return texture(samplerStone, uv, atlas_lod).rgb
        
    else:
        # Fallback or other blocks
        return texture(samplerDefault, uv, atlas_lod).rgb

def fetch_grass_side_green():
    # Hardcoded micro-optimization for a specific pixel in the atlas
    # UV coordinates derived from source: (110.0/256.0, 222.0/256.0)
    uv = vec2(110.0 / 256.0, 222.0 / 256.0)
    return texture(samplerGrassSide, uv).rgb

def hash12(p):
    # Standard pseudo-random hash for 2D vector
    # Implementation details not fully specified in source, 
    # assumed to be a standard GLSL hash function returning [0,1]
    return fract(sin(dot(p, vec2(12.9898, 78.233))) * 43758.5453)
```

**Parameters:**
- `atlasLod`: Fixed to `0.0` [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Precision:** The condition `abs(normal.x) > 0.5` assumes normalized normals. Degenerate normals (zero length) will fall through to the `else` case, potentially causing incorrect UV mapping [S1, unofficial].
- **Boundaries:** UV coordinates are not clamped in the `faceUV` function, relying on the texture sampler's wrapping mode or the atlas layout to handle boundaries [S1, unofficial].
- **Hardcoded Values:** The grass green tint uses a hardcoded UV `(110.0/256.0, 222.0/256.0)` which is fragile if the atlas layout changes [S1, unofficial].

## Subtopics

### Texture Atlas with Shader Wrapping
This variant handles the case where multiple block types share a single 2D atlas texture but require distinct UV regions. It involves splitting vertices shared by different block types and assigning distinct texture coordinates to each vertex copy, representing the top-left corner of the texture in the atlas or its index in an array texture. The shader must perform texture wrapping math manually because hardware sampling cannot handle arbitrary atlas regions directly [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ per fragment, involving a few comparisons, a hash lookup, and a texture sample.
- **Memory Complexity:** $O(1)$ additional memory, requiring only the texture samplers and a small amount of uniform data.
- **Strengths:** Efficient single-pass texturing for blocky worlds; reduces draw calls by using a single atlas.
- **Limitations:** Fixed LOD disables mip-mapping, potentially causing aliasing at distance; hardcoded UVs for specific colors (grass green) are brittle; hash-based variation is visible up close but may appear noisy [S1, unofficial].
- **When to use:** Real-time voxel rendering where performance is critical and block types are limited.
- **When not to use:** When high-quality mip-mapping is required or when the atlas layout is dynamic and cannot be hardcoded.

## Background
Originating from GLSL voxel world shaders, this method is used in real-time voxel engines to apply textures to blocky meshes efficiently. It builds on [Texture Atlas UV Mapping](4238-texture-atlas-uv-mapping.md) by adding semantic block-type handling. The technique is documented in community-driven repositories and game development forums [S1, S2, unofficial].
