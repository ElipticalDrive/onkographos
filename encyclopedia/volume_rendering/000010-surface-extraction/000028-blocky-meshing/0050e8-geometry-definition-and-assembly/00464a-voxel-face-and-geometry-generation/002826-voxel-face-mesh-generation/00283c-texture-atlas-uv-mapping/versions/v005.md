# Texture Atlas UV Mapping

Also called: Per-face lookup table UV mapping

## Overview
This method maps block types to sub-regions of a shared texture atlas using a per-face lookup table, with correct per-direction UV inversion for winding order [S1, unofficial]. A single material instance is applied to all 16 sections of a chunk [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Block type identifier, face direction.
*   **Output:** UV coordinates ($u, v$) for the quad vertices.

**Data Structures:**
*   **Per-face lookup table:** Maps `(block_type, face_direction)` pairs to atlas sub-region parameters and inversion flags. Exact layout is not given in the sources.

**Steps:**
1. Identify the block type and face direction for the voxel face.
2. Query the per-face lookup table to retrieve atlas sub-region coordinates (`atlas_u`, `atlas_v`), dimensions (`width`, `height`), and inversion flags [S1, unofficial].
3. Compute base UV coordinates from the local quad vertex position $(v_x, v_y) \in [0, 1]^2$:
   $$ u = atlas\_u + v_x \times width $$
   $$ v = atlas\_v + v_y \times height $$
4. Apply UV inversion for the specified axis if the lookup table indicates it is required for correct winding order [S1, unofficial]. If `invert_u` is true, set $u = atlas\_u + width - (v_x \times width)$.
5. Output the final UV coordinates and the associated material index.

**Pseudocode:**
```python
def compute_uv(block_type, face_direction, atlas_width, atlas_height):
    # Retrieve parameters from the per-face lookup table.
    # The exact table structure and population logic are not given in the sources.
    # params = lookup_table[block_type][face_direction]
    params = {'atlas_u': 0.0, 'atlas_v': 0.0, 'width': 1.0, 'height': 1.0, 'invert_u': False, 'invert_v': False} # [G]
    
    atlas_u = params['atlas_u']
    atlas_v = params['atlas_v']
    width = params['width']
    height = params['height']
    invert_u = params['invert_u']
    invert_v = params['invert_v']
    
    local_vertices = [(0.0, 0.0), (1.0, 0.0), (1.0, 1.0), (0.0, 1.0)]
    uv_coords = []
    
    for lx, ly in local_vertices:
        u = atlas_u + lx * width
        v = atlas_v + ly * height
        
        if invert_u:
            u = atlas_u + width - (lx * width)
        if invert_v:
            v = atlas_v + height - (ly * height)
            
        uv_coords.append((u, v))
        
    return uv_coords, params.get('material_index', 0)
```

**Parameters:**
*   **Atlas Size:** Not given in the sources.
*   **Block Type Count:** Not given in the sources.
*   **Face Directions:** 6 (±X, ±Y, ±Z) [G].

**Edge Cases and Pitfalls:**
*   **Winding Order:** Incorrect UV inversion leads to flipped textures. The method explicitly requires inversion for certain face directions to maintain consistent texture orientation [S1, unofficial].
*   **Atlas Bounds:** UV coordinates must remain within the atlas dimensions [G].
*   **Material Assignment:** A single material instance is applied to all 16 sections of a chunk, which limits per-block material variation [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per face for UV lookup and calculation [G].
*   **Memory Complexity:** $O(B \times F)$ for the lookup table, where $B$ is the number of block types and $F$ is the number of face directions [G].
*   **Performance:** Efficient due to shared atlas and simple arithmetic [G].
*   **Strengths:** Reduces texture memory usage, simplifies shader logic by using a single atlas [G].
*   **Limitations:** Requires careful atlas layout management. Limited flexibility for complex per-block materials without additional logic [G].
*   **When to Use:** Suitable for voxel-based games with a fixed set of block types [G].
*   **When Not to Use:** When dynamic texture generation or highly varied per-block materials are required [G].

## Background
This method is part of the voxel meshing pipeline in Unreal Engine 5 Minecraft clones, as implemented in the Manolo94/UE5MinecraftClone project [S1, unofficial]. It builds on the principles of texture atlasing and per-face geometry generation to optimize rendering performance.
