# Quality Enhancement (Smoothing and Tessellation)
Also called: Detail tessellation, Post-processing smoothing

## Overview
Quality Enhancement is a post-processing stage applied to blocky meshes extracted from volumetric data to improve visual fidelity by reducing jagged, stair-stepped artifacts and optimizing geometry for rendering [S1, unofficial][S2]. It distinguishes itself from pure smoothing methods by including synthetic detail generation and explicit mesh connectivity optimization, and from pure tessellation methods by its focus on correcting topological artifacts like T-junctions [S1, unofficial]. It builds on [Rendering and Post-Processing](14298-rendering-and-post-processing.md) by refining the coarse quadrilateral or triangular mesh derived from voxel data.

## How it works
The method operates on a coarse mesh (quadrilateral or triangular) extracted from volume data. It consists of two primary components: geometric smoothing and detail tessellation.

### Inputs and Outputs
*   **Input:** A coarse surface mesh (quadrilateral or triangular) derived from voxel data; scalar field values (for smoothing thresholds); texture maps (for displacement).
*   **Output:** A refined, visually smooth mesh suitable for rasterization.

### Data Structures
*   **Mesh:** List of vertices with position $(x, y, z)$ and normal $(n_x, n_y, n_z)$. For quadrilateral meshes, connectivity is defined by vertex indices per face.
*   **Texture Maps:** Tri-planar projection maps (X, Y, Z axes) for displacement and color, sampled via hardware mipmaps [S1, S3, unofficial].

### Steps

1.  **Smoothing (Surface Diffuse Flow):**
    For quadrilateral meshes, apply surface diffuse flow to smooth the geometry [S1, unofficial]. This involves moving vertices along the surface tangent plane to reduce high-frequency noise while preserving the overall shape.
    *   Calculate the discrete Laplacian of the vertex positions [S1, unofficial].
    *   Project the Laplacian vector onto the tangent plane of the vertex normal [S1, unofficial].
    *   Update vertex position: $P_{new} = P_{old} + \lambda \cdot \text{Proj}_{\text{tangent}}(\Delta P)$, where $\lambda$ is a smoothing factor [G].
    *   This process is implemented efficiently in parallel [S1, unofficial].

2.  **Tangent Movement (Quality Improvement):**
    Add tangent movement to further improve quality on quadrilateral meshes [S1, unofficial]. This step adjusts vertex positions along tangent directions to correct local distortions introduced by the extraction process [S1, unofficial].

3.  **Detail Tessellation (Catmull-Clark Approximation):**
    Approximate a smooth Catmull-Clark subdivision surface using bicubic patches [S1, unofficial].
    *   Use a tessellation shader to subdivide the coarse mesh [S1, unofficial].
    *   Apply displacement maps to the tessellated patches to add high-frequency detail [S1, unofficial].
    *   Use tri-planar texture mapping for the displacement and color maps to avoid distortion on complex surfaces [S1, unofficial].

4.  **CloudPlane Tessellation (Soft Edges):**
    For cloud layers, divide a quad into nine segments to solve hard edges near the horizon [S3, unofficial].
    *   Define a 3x3 grid of vertices for the quad.
    *   Set the four outer vertices' alpha to 0.
    *   Set the four inner vertices' alpha to 1.
    *   Set the center vertex's alpha to 1 [S3, unofficial].
    *   During rasterization, interpolate alpha values between outer (0) and inner (1) edges to create smooth transitions [S3, unofficial].
    *   Combine interpolated vertex alpha with the alpha value of a 2D noise texture to determine the final alpha [S3, unofficial].

### Parameters
*   **Mesh Smooth Value:** Controls the roughness reduction. Larger values result in slower mesh building and smoother results [S2].
*   **Isosurface Level:** Threshold for geometry generation. For Phoenix liquids (range 0-1), 0.5 is optimal for visualizing the air-liquid interface [S2].
*   **Blending Equation:** `SRC_ALPHA` and `ONE_MINUS_SRC_ALPHA` for transparency [S3, unofficial].
*   **Texture Filtering:** `LINEARMIPMAPLINEAR` for smoothest antialiasing [S3, unofficial].
*   **Array Binding:** Color arrays bound `BIND PER VERTEX`; Normal arrays bound `BIND OVERALL` [S3, unofficial].

### Edge Cases and Pitfalls
*   **Precision:** The smoothing factor $\lambda$ must be chosen carefully to avoid over-smoothing or instability [G].
*   **Boundaries:** Cloud layers must be added in lower-to-upper order to render correctly due to OpenGL transparency management limitations [S3, unofficial].
*   **Degenerate Input:** The CloudPlane method specifically addresses the failure of single-quad approaches near the horizon [S3, unofficial].

### Pseudocode

```python
def quality_enhance(mesh, params):
    """
    mesh: List of vertices with pos, normal, and connectivity.
    params: Dict containing 'smooth_factor', 'tessellation_level', 'cloud_mode'.
    """
    if params.get('cloud_mode'):
        return cloud_plane_tessellation(mesh)
    
    # Smoothing Step
    if params.get('smooth'):
        for vertex in mesh.vertices:
            laplacian = compute_laplacian(vertex, mesh)
            tangent_plane = compute_tangent_plane(vertex.normal)
            projected_laplacian = project_to_tangent(laplacian, tangent_plane)
            vertex.pos += params['smooth_factor'] * projected_laplacian
            
    # Tangent Movement Step
    if params.get('tangent_movement'):
        for vertex in mesh.vertices:
            # Apply additional tangent adjustments for quality
            tangent_adjustment = compute_tangent_adjustment(vertex, mesh)
            vertex.pos += tangent_adjustment
            
    # Tessellation Step
    if params.get('tessellation'):
        tessellated_mesh = tessellate_mesh(mesh, params['tessellation_level'])
        apply_displacement(tessellated_mesh, params['displacement_maps'])
        return tessellated_mesh
        
    return mesh

def cloud_plane_tessellation(mesh):
    """
    Tessellates a quad into 9 segments for soft edges.
    """
    # Assume input is a single quad with 4 vertices
    # Create 3x3 grid of vertices
    new_vertices = []
    for i in range(3):
        for j in range(3):
            new_vertices.append(Vertex())
            
    # Set alpha values
    # Outer vertices (0,0), (0,2), (2,0), (2,2) -> alpha 0
    # Inner vertices (0,1), (1,0), (1,2), (2,1) -> alpha 1
    # Center vertex (1,1) -> alpha 1
    new_vertices[0].alpha = 0
    new_vertices[2].alpha = 0
    new_vertices[6].alpha = 0
    new_vertices[8].alpha = 0
    
    new_vertices[1].alpha = 1
    new_vertices[3].alpha = 1
    new_vertices[5].alpha = 1
    new_vertices[7].alpha = 1
    new_vertices[4].alpha = 1
    
    # Create 8 quads from the 3x3 grid
    new_faces = []
    for i in range(2):
        for j in range(2):
            idx = i * 3 + j
            new_faces.append([idx, idx+1, idx+4, idx+3])
            
    return Mesh(new_vertices, new_faces)
```

## Subtopics

### [Geometry Post-Processing](13056-geometry-post-processing.md)
Geometry Post-Processing refers to a suite of techniques applied to blocky meshes extracted from volumetric data to improve visual fidelity and rendering performance. It addresses the jagged, stair-stepped appearance of initial voxel-based surface extractions and optimizes the resulting geometry for the GPU. It is distinguished from pure smoothing methods by its inclusion of synthetic detail generation and explicit mesh connectivity optimization, and from pure tessellation methods by its focus on correcting topological artifacts like T-junctions. See [Geometry Post-Processing](13056-geometry-post-processing.md).

### Mesh Smooth
Mesh Smooth is a specific smoothing technique used when Mode is set to Mesh, Ocean Mesh, or Cap Mesh to reduce the roughness of the mesh. The larger the value, the slower the mesh builds [S2]. It is a parameter-driven smoothing method rather than a full algorithmic pipeline.

### CloudPlane Tessellation for Soft Edges
CloudPlane Tessellation is a technique to solve hard edges near the horizon by dividing a cloud layer quad into nine segments with specific alpha values at vertices [S3, unofficial]. It uses tri-planar texture mapping and specific blending equations to achieve smooth alpha transitions [S3, unofficial]. See [CloudPlane Tessellation](13057-cloudplane-tessellation.md) (if it existed, but here it is a variant).

## Operating characteristics
*   **Time Complexity:** Smoothing is $O(V)$ where $V$ is the number of vertices, as it operates per-vertex in parallel [S1, unofficial]. Tessellation increases vertex count by a factor of $4^L$ (where $L$ is tessellation level), making it $O(V \cdot 4^L)$ [S1, unofficial].
*   **Memory Complexity:** Increases with tessellation level due to the larger mesh size [S1, unofficial].
*   **Performance:** Smoothing is efficient in parallel [S1, unofficial]. Tessellation is real-time capable using tessellation shaders [S1, unofficial].
*   **Strengths:** Produces smooth, high-quality surfaces; handles complex terrains and liquids effectively [S1, unofficial]. Soft edges for clouds are achieved without complex geometry [S3, unofficial].
*   **Limitations:** Tessellation can be computationally expensive for high detail levels [S1, unofficial]. Cloud layers require specific rendering order [S3, unofficial].
*   **When to Use:** When visual fidelity is critical and hardware supports tessellation shaders [S1, unofficial]. When cloud rendering requires soft horizon edges [S3, unofficial].
*   **When Not to Use:** When performance is paramount and low detail is acceptable [S1, unofficial]. When using fixed-function pipelines that cannot handle the required blending or tessellation [S3, unofficial].

## Background
The method originates from research on generating smooth high-quality isosurfaces for interactive modeling and visualization of complex terrains [S1, unofficial]. It builds on prior work such as [WMKG08] for Laplacian smoothing and [ZHK04] for surface diffuse flow on quadrilateral meshes. Detail tessellation follows the real-time capable approach of Loop and Schaefer [LS08] for Catmull-Clark subdivision approximation. Tri-planar texture mapping is based on [Gei07, GT07]. The CloudPlane technique was developed to address limitations in fixed-function graphics pipelines for cloud simulation [S3, unofficial].
