# Rendering and Post-Processing

Also called: Block Mesh Alpha Rendering, Quality Enhancement, Ocean Mesh Rendering

## Overview
Rendering and Post-Processing handles the visual presentation of blocky voxel meshes generated by [Blocky meshing](31-blocky-meshing.md), addressing transparency artifacts and geometric jaggedness. It sets itself apart from sibling methods like [Greedy face merging](8935-greedy-face-merging.md) by operating on pre-generated geometry to optimize rendering order or refine surface topology, rather than modifying the initial mesh extraction topology.

## Shared principles
The family shares the input of a coarse quadrilateral or triangular mesh derived from voxel data and the output of a rasterized image or refined mesh. Common mechanisms include:
*   **Spatial Sorting:** For transparent surfaces, rendering order is determined by camera-relative distance to ensure correct alpha blending [S1].
*   **Geometric Refinement:** Flat voxel faces are replaced with curved patches or subdivided surfaces to approximate smooth geometry [S1].
*   **Projection-Based Texturing:** Textures are applied using multi-axis projection to avoid distortion on complex or blocky surfaces [S1].

## Subtopics

### [Block Mesh Alpha Rendering](3569-block-mesh-alpha-rendering.md)
Sorts chunk meshes back-to-front relative to the camera's dominant viewing axis to enable correct alpha blending without full scene depth sorting. Choose this for transparent voxel environments where performance is critical and full depth sorting is too expensive.

### [Quality Enhancement (Smoothing and Tessellation)](10395-quality-enhancement-smoothing-and-tessellation.md)
Refines blocky meshes using surface diffuse flow smoothing and Catmull-Clark tessellation to approximate smooth surfaces. Choose this when visual fidelity is prioritized over the raw voxel aesthetic.

### Ocean Mesh Rendering
Extends grid content to a flat area fitting the camera's view, typically used with displacement textures like Phoenix FD Ocean Texture [S1]. The ocean surface generates only when liquid touches the sides and bottom of the grid, which act as a container [S1]. Mesh detail depends on camera resolution: one or several polygons per pixel are generated based on the Ocean Subdivisions option [S1].

## Background
The techniques described here originate from real-time rendering engines for voxel-based games (e.g., Minecraft clones) and fluid simulation post-processing in 3ds Max plugins (Phoenix FD) [S1]. Alpha sorting was developed to handle transparency in chunk-based engines without the overhead of global depth sorting [S1]. Smoothing and tessellation techniques adapt subdivision surface algorithms (Catmull-Clark) to voxel-derived quadrilateral meshes [S1].
