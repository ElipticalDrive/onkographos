# Block Mesh Alpha Rendering

Also called: ChunkMesh Alpha Rendering, Transparent Face Sorting & Rendering

## Overview
Block Mesh Alpha Rendering is a rendering technique for voxel-based environments that sorts visible chunk meshes back-to-front relative to the camera's primary viewing axis to enable correct alpha blending without requiring full scene depth sorting [S1, unofficial]. It sets itself apart from sibling methods like [Boolean Voxel Meshing](971-boolean-voxel-meshing.md) or [Greedy face merging](8935-greedy-face-merging.md) by operating on pre-generated chunk meshes and relying on a specific spatial traversal order to handle transparency artifacts, rather than modifying the mesh geometry itself [S1, unofficial].

## How it works
**Inputs:** Camera position $(x_c, y_c, z_c)$ in world units; camera view vector $(v_x, v_y, v_z)$ derived from rotation; a collection of chunk meshes, each containing a list of transparent faces indexed in a nested structure `blocksPos[greatestDir][secondary][tertiary][1]` [S1, unofficial].
**Outputs:** A sorted list of chunk indices for rendering, and updated vertex/index buffers for each chunk [S1, unofficial].

### Data Structures
*   **Vertex Packing:** Each vertex is stored as two 32-bit unsigned integers [S1, unofficial].
    *   `vertex0`: Position. Bits 0-9: $x$, Bits 10-19: $y$, Bits 20-31: $z$ [S1, unofficial].
    *   `vertex1`: Texture and shading. Bits 0-9: Texture layer; Bits 10-14: Texture $x$; Bits 15-19: Texture $y$; Bits 20-31: Shade data [S1, unofficial].
*   **Block Position Index (`blocksPos`):** A nested array structure where `blocksPos[greatestDir][secondary][tertiary]` is an array `[coordinate, [index_list]]`. The `index_list` contains the vertex indices for faces at that block position [S1, unofficial].

### Parameters
*   **Chunk Size:** 32x32x32 blocks [S1, unofficial].
*   **Fog Far Distance:** 256 units ($32 \times 8$) [S1, unofficial].
*   **Camera Matrix Scale:** $0.0625$ ($1/16$) to convert world units to chunk units [S1, unofficial].
*   **Alpha Discard Threshold:** Blocks with alpha $< 0.4$ are discarded in the fragment shader [S1, unofficial].

### Algorithm Steps

1.  **Determine Dominant Axis:**
    Calculate the absolute values of the camera's view vector components $|v_x|, |v_y|, |v_z|$ [S1, unofficial]. Identify `greatestDir` as the axis (X, Y, or Z) with the maximum absolute value [S1, unofficial].

2.  **Determine Traversal Direction:**
    Calculate `greatestMag` as the signed magnitude of the view vector component along `greatestDir` [S1, unofficial]. If `greatestMag` is negative, reverse the list of blocks along `greatestDir` to ensure traversal starts from the back relative to the camera [S1, unofficial].

3.  **Traverse Blocks (Forward Phase):**
    Iterate through the blocks along `greatestDir` [S1, unofficial]. For each block, iterate through the secondary axis blocks [S1, unofficial]. Use a rectilinear distance check against the camera's position on the other two axes (`otherPos`) [S1, unofficial].
    For each block in the secondary axis, iterate through the tertiary axis blocks [S1, unofficial]. If the block's coordinate is $\ge$ the camera's coordinate on the tertiary axis, break the inner loop and proceed to the reverse iteration of the tertiary axis for that secondary block [S1, unofficial].

4.  **Traverse Blocks (Reverse Phase - Tertiary):**
    After the forward iteration of the tertiary axis, perform a reverse iteration (from end to start) for the same secondary axis block [S1, unofficial]. Add indices for blocks whose coordinate is $<$ the camera's coordinate on the tertiary axis [S1, unofficial].

5.  **Traverse Blocks (Reverse Phase - Secondary):**
    After processing forward iterations for all secondary blocks, perform a reverse iteration of the secondary axis blocks [S1, unofficial]. For each, iterate forward and then backward through the tertiary axis blocks, applying the same coordinate comparison logic against `otherPos` [S1, unofficial].

6.  **Restore Order:**
    If the traversal direction was reversed in Step 2, reverse the `blocksPos` list back to its original order [S1, unofficial].

7.  **Chunk Sorting:**
    When the camera crosses chunk boundaries, calculate `chunkDistances` for all chunks using Manhattan distance:
    $$ \text{chunkDist} = | \text{chunk}.x \times 32 - x_c + 16 | + | \text{chunk}.y \times 32 - y_c + 16 | + | \text{chunk}.z \times 32 - z_c + 16 | $$
    Sort `shaders.alpha.chunkMeshes` in descending order of distance (far to near) [S1, unofficial].

8.  **Update Indices:**
    Call `ChunkMeshAlpha.processCameraData(camera)` to update indices for transparency based on the sorted order [S1, unofficial].

9.  **Render Setup:**
    Set blend function: `gl.blendFuncSeparate(gl.SRC_ALPHA, gl.ONE_MINUS_SRC_ALPHA, gl.ONE, gl.ONE_MINUS_SRC_ALPHA)` [S1, unofficial].

### Pseudocode

```python
def process_camera_data(camera, blocks_pos, chunks):
    indices = []
    
    # 1. Determine dominant axis
    vx, vy, vz = camera.view_vector
    abs_vx, abs_vy, abs_vz = abs(vx), abs(vy), abs(vz)
    
    if abs_vx >= abs_vy and abs_vx >= abs_vz:
        greatest_dir = 0
        greatest_mag = vx
    elif abs_vy >= abs_vx and abs_vy >= abs_vz:
        greatest_dir = 1
        greatest_mag = vy
    else:
        greatest_dir = 2
        greatest_mag = vz
        
    # 2. Determine traversal direction
    reversed_flag = False
    if greatest_mag < 0:
        reversed_flag = True
        blocks_pos[greatest_dir].reverse()
        
    # 3. Setup axes
    axes = [0, 1, 2]
    axes.remove(greatest_dir)
    secondary_axis, tertiary_axis = axes
    
    camera_terr_coord = camera.pos[tertiary_axis]
    
    # 4. Forward Iteration over greatest_dir
    for i in range(len(blocks_pos[greatest_dir])):
        block0 = blocks_pos[greatest_dir][i]
        # block0 structure: [coord, [secondary_blocks]]
        
        for j in range(1, len(block0[1])):
            block1 = block0[1][j]
            # block1 structure: [coord, [tertiary_blocks]]
            
            # Forward Tertiary
            for k in range(1, len(block1[1])):
                block2 = block1[1][k]
                coord2 = block2[0]
                
                if coord2 >= camera_terr_coord:
                    break
                indices.extend(block2[1])
                
            # Reverse Tertiary
            for k in range(len(block1[1]) - 1, 0, -1):
                block2 = block1[1][k]
                coord2 = block2[0]
                
                if coord2 < camera_terr_coord:
                    indices.extend(block2[1])
                
        # Reverse Secondary Iteration
        for j in range(len(block0[1]) - 1, 0, -1):
            block1 = block0[1][j]
            
            # Forward Tertiary
            for k in range(1, len(block1[1])):
                block2 = block1[1][k]
                coord2 = block2[0]
                
                if coord2 >= camera_terr_coord:
                    break
                indices.extend(block2[1])
                
            # Reverse Tertiary
            for k in range(len(block1[1]) - 1, 0, -1):
                block2 = block1[1][k]
                coord2 = block2[0]
                
                if coord2 < camera_terr_coord:
                    indices.extend(block2[1])

    # 5. Restore order
    if reversed_flag:
        blocks_pos[greatest_dir].reverse()

    # 6. Chunk Sorting
    chunk_distances = {}
    for chunk in chunks:
        dist = (abs(chunk.x * 32 - camera.x + 16) + 
                abs(chunk.y * 32 - camera.y + 16) + 
                abs(chunk.z * 32 - camera.z + 16))
        chunk_distances[chunk] = dist
        
    sorted_chunks = sorted(chunks, key=lambda c: chunk_distances[c], reverse=True)
    
    # 7. Update Buffers
    for chunk in sorted_chunks:
        chunk.update_index_buffer(indices)
```

### Edge Cases and Pitfalls
*   **Alpha Threshold:** Transparent blocks with alpha $< 0.4$ are discarded in the fragment shader to prevent rendering artifacts from semi-transparent surfaces that are effectively invisible [S1, unofficial].
*   **Data Structure Assumption:** The index generation algorithm assumes a specific nested array structure for `blocksPos`: `blocksPos[greatestDir][secondary][tertiary][1]` contains the list of indices for each block [S1, unofficial].
*   **Precision:** The vertex packing uses 10-bit integers for position, limiting coordinate precision to $2^{10}=1024$ units per chunk axis [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The sorting step is $O(N \log N)$ where $N$ is the number of chunks, based on the Manhattan distance calculation and sorting [S1, unofficial]. The index generation is linear with respect to the number of visible faces in the dominant traversal order [S1, unofficial].
*   **Memory Complexity:** Depends on the number of transparent faces stored in `blocksPos` [S1, unofficial]. The vertex packing reduces memory usage by storing vertices in two 32-bit integers per vertex [S1, unofficial].
*   **Strengths:** Avoids the high cost of full scene depth sorting for every transparent fragment. Efficiently handles large voxel worlds by sorting at the chunk level [S1, unofficial].
*   **Limitations:** Relies on a specific traversal order which may not be optimal for all camera angles or complex transparent geometries [S1, unofficial].
*   **When to use:** Suitable for voxel-based environments with significant transparency (e.g., glass, water) where chunk-based culling is already in place [S1, unofficial]. Not suitable for non-voxel or highly irregular transparent meshes [S1, unofficial].

## Background
The method is implemented in a voxel-based environment project [S1, unofficial]. It was developed as part of the optimization suite for handling transparent blocks in a web-based 3D environment, leveraging WebGL2 capabilities [S1, unofficial]. The method is described in the project's source code and documentation as a customized transparent face sorting algorithm [S1, unofficial].
