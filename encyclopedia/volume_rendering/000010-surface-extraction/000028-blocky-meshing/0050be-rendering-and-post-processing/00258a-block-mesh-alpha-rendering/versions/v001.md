# Block Mesh Alpha Rendering

Also called: ChunkMesh Alpha Rendering, Transparent Face Sorting & Rendering

## Overview
Block Mesh Alpha Rendering is a rendering technique for voxel-based environments that sorts visible faces back-to-front relative to the camera's primary viewing axis to enable correct alpha blending without full scene depth sorting [S1, unofficial]. It distinguishes itself from opaque block meshing methods by implementing a custom index ordering algorithm that traverses the voxel grid in a specific order determined by the camera's view vector, ensuring transparent surfaces are rendered in the correct depth order [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input**: A 3D voxel world divided into chunks (typically $32 \times 32 \times 32$). Each voxel has an occupancy state, material ID, and transparency value. The camera position and view vector are required.
*   **Output**: A set of rendered transparent faces with correct alpha blending, using a specific index buffer order that approximates back-to-front sorting.

**Data Structures**
The method relies on a nested array structure `blocksPos` to track visible transparent faces. The layout is defined as:
`blocksPos[greatestDir][secondary][tertiary][1]` contains the list of vertex indices for each block [S1, unofficial].
*   `greatestDir`: The axis (X, Y, or Z) with the largest absolute component in the camera's view vector.
*   `secondary`: The axis with the second-largest absolute component.
*   `tertiary`: The axis with the smallest absolute component.

**Vertex Packing**
Vertex data is packed into two 32-bit unsigned integers per vertex to optimize memory and bandwidth [S1, unofficial]:
*   **vertex0**: Contains position.
    *   Bits 0-9: $x$ coordinate (10 bits).
    *   Bits 10-19: $y$ coordinate (10 bits).
    *   Bits 20-31: $z$ coordinate (12 bits).
*   **vertex1**: Contains texture and shading data.
    *   Bits 0-9: Texture layer (10 bits).
    *   Bits 10-14: Texture coordinate $x$ (5 bits).
    *   Bits 15-19: Texture coordinate $y$ (5 bits).
    *   Bits 20-31: Shade data (12 bits).

**Algorithm Steps**

1.  **Determine Traversal Axis**:
    Calculate the camera's view vector components $(v_x, v_y, v_z)$. Identify `greatestDir` as the axis corresponding to $\max(|v_x|, |v_y|, |v_z|)$ [S1, unofficial]. Determine `greatestMag` as the signed magnitude of the view vector component along `greatestDir` [S1, unofficial].

2.  **Initialize Traversal Direction**:
    If `greatestMag` is negative, reverse the list of blocks along the `greatestDir` axis to ensure traversal starts from the back relative to the camera [S1, unofficial]. Let `reversed` track this state.

3.  **Generate Index Order**:
    Iterate through the blocks along the `greatestDir` axis. For each block, iterate through the secondary axis blocks. For each secondary block, iterate through the tertiary axis blocks. The order of iteration for the tertiary axis depends on the camera's position on the tertiary axis (`otherPos[2]`):
    *   **Forward Iteration**: Iterate tertiary indices $k$ from start to end. If the block's coordinate on the tertiary axis is $\ge$ `otherPos[2]`, add its indices to the output list. If the coordinate is $<$ `otherPos[2]`, break the forward loop [S1, unofficial].
    *   **Reverse Iteration**: After the forward loop, iterate tertiary indices $k$ from end to start. If the block's coordinate on the tertiary axis is $<$ `otherPos[2]`, add its indices to the output list. If the coordinate is $\ge$ `otherPos[2]`, break the reverse loop [S1, unofficial].
    
    After processing all secondary blocks in the forward direction, perform a reverse iteration of the secondary axis blocks. For each secondary block, repeat the forward and reverse tertiary iteration logic described above [S1, unofficial].

4.  **Finalize Order**:
    If `reversed` is true, reverse the `blocksPos` list back to its original order to maintain consistency for subsequent updates [S1, unofficial].

5.  **Chunk Sorting**:
    When the camera crosses chunk boundaries, calculate the distance to each chunk using Manhattan distance:
    $$ \text{chunkDist} = | \text{chunk}.x \cdot 32 - \text{camera}.x + 16 | + | \text{chunk}.y \cdot 32 - \text{camera}.y + 16 | + | \text{chunk}.z \cdot 32 - \text{camera}.z + 16 | $$
    Sort the chunk meshes in descending order of distance (far to near) [S1, unofficial].

6.  **Rendering**:
    Set the blend function to `gl.blendFuncSeparate(gl.SRC_ALPHA, gl.ONE_MINUS_SRC_ALPHA, gl.ONE, gl.ONE_MINUS_SRC_ALPHA)` [S1, unofficial]. Render the chunks in the sorted order.

**Pseudocode**

```python
def generate_transparent_index_order(camera_pos, view_vector, blocks_pos):
    """
    Generates an index order for transparent faces based on camera view.
    blocks_pos is a nested list: blocks_pos[greatest_dir][secondary][tertiary]
    Each element is [coordinate, [list_of_indices]].
    """
    # 1. Determine greatestDir
    vx, vy, vz = view_vector
    abs_vx, abs_vy, abs_vz = abs(vx), abs(vy), abs(vz)
    
    if abs_vx >= abs_vy and abs_vx >= abs_vz:
        greatest_dir = 0 # X
        greatest_mag = vx
        other_pos = [camera_pos[1], camera_pos[2]] # Y, Z
    elif abs_vy >= abs_vx and abs_vy >= abs_vz:
        greatest_dir = 1 # Y
        greatest_mag = vy
        other_pos = [camera_pos[0], camera_pos[2]] # X, Z
    else:
        greatest_dir = 2 # Z
        greatest_mag = vz
        other_pos = [camera_pos[0], camera_pos[1]] # X, Y

    # 2. Determine traversal direction
    reversed = False
    if greatest_mag < 0:
        blocks_pos.reverse()
        reversed = True

    indices = []
    
    # 3. Iterate through greatest_dir
    for i in range(len(blocks_pos)):
        secondary_blocks = blocks_pos[i]
        
        # Forward iteration of secondary axis
        for j in range(len(secondary_blocks)):
            tertiary_blocks = secondary_blocks[j]
            # Forward iteration of tertiary axis
            for k in range(len(tertiary_blocks)):
                coord = tertiary_blocks[k][0]
                if coord >= other_pos[2]:
                    indices.extend(tertiary_blocks[k][1])
                else:
                    break
            
            # Reverse iteration of tertiary axis
            for k in range(len(tertiary_blocks) - 1, -1, -1):
                coord = tertiary_blocks[k][0]
                if coord < other_pos[2]:
                    indices.extend(tertiary_blocks[k][1])
                else:
                    break
        
        # Reverse iteration of secondary axis
        for j in range(len(secondary_blocks) - 1, -1, -1):
            tertiary_blocks = secondary_blocks[j]
            # Forward iteration of tertiary axis
            for k in range(len(tertiary_blocks)):
                coord = tertiary_blocks[k][0]
                if coord >= other_pos[2]:
                    indices.extend(tertiary_blocks[k][1])
                else:
                    break
            
            # Reverse iteration of tertiary axis
            for k in range(len(tertiary_blocks) - 1, -1, -1):
                coord = tertiary_blocks[k][0]
                if coord < other_pos[2]:
                    indices.extend(tertiary_blocks[k][1])
                else:
                    break

    # 4. Finalize order
    if reversed:
        blocks_pos.reverse()
        
    return indices

def render_chunks(chunks, camera_pos):
    """
    Sorts chunks by Manhattan distance and renders them.
    """
    chunk_distances = {}
    for chunk in chunks:
        dist = (abs(chunk.x * 32 - camera_pos.x + 16) + 
                abs(chunk.y * 32 - camera_pos.y + 16) + 
                abs(chunk.z * 32 - camera_pos.z + 16))
        chunk_distances[chunk] = dist
    
    sorted_chunks = sorted(chunks, key=lambda c: chunk_distances[c], reverse=True)
    
    for chunk in sorted_chunks:
        render_chunk(chunk)
```

**Parameters**
*   **Fog Far Distance**: Set to $32 \times 8 = 256$ units [S1, unofficial].
*   **Camera Matrix Scale**: A scale factor of $0.0625$ ($1/16$) is used to convert world units to chunk units [S1, unofficial].

**Formulas**
*   **Shading Value**: Calculated from the packed vertex data:
    $$ \text{shadeData} = (\text{vertex1} \gg 20) \times 0.2 + 0.4 $$
    where `vertex1` is the second packed 32-bit integer [S1, unofficial].
*   **Fog Amount**: Calculated using smoothstep:
    $$ \text{fogAmount} = \text{smoothstep}(\text{fogFar} - 64.0, \text{fogFar}, \text{distance}) $$
    where `distance` is the length of the camera-space position vector [S1, unofficial].

**Edge Cases and Pitfalls**
*   **Transparency Threshold**: Transparent blocks with alpha $< 0.4$ are discarded in the fragment shader to prevent rendering artifacts from effectively invisible surfaces [S1, unofficial].
*   **Data Structure Assumption**: The index generation algorithm assumes `blocksPos[greatestDir][secondary][tertiary][1]` contains the list of indices. Deviations from this structure will cause errors [S1, unofficial].
*   **Precision**: The use of integer bit-packing for coordinates limits the maximum chunk size and coordinate range. For $32 \times 32 \times 32$ chunks, 10 bits for X and Y and 12 bits for Z are sufficient, but larger chunks or worlds may require re-evaluation of the packing scheme.

## Operating characteristics
*   **Time Complexity**: The sorting of chunks is $O(C \log C)$ where $C$ is the number of chunks. The index generation is $O(F)$ where $F$ is the number of transparent faces, as it iterates through the grid structure once.
*   **Memory Complexity**: $O(F)$ for storing the index buffer and vertex data. The `blocksPos` structure adds overhead proportional to the number of transparent blocks.
*   **Strengths**: Avoids the high cost of full depth sorting ($O(N \log N)$ for all fragments) by leveraging the spatial coherence of voxel grids. Efficient for dynamic scenes with frequent changes in transparency.
*   **Limitations**: The sorting is an approximation based on the primary viewing axis. It may not produce perfectly correct blending for faces that are close in depth but far apart in the secondary/tertiary axes. Performance degrades with a very high density of transparent faces.
*   **When to Use**: Suitable for voxel engines with significant transparent geometry (e.g., glass, water, foliage) where performance is critical and perfect blending accuracy is not required.
*   **When Not to Use**: For scenes with complex, non-voxel transparent geometry or where perfect alpha blending is mandatory.

## Background
Block Mesh Alpha Rendering is implemented in the Exolands project, an open-source voxel engine [S1, unofficial]. The technique was developed to handle transparency in a performant manner for real-time rendering in web-based environments. It builds upon the principles of blocky meshing, specifically face culling and chunk-based rendering, by adding a specialized sorting pass for transparent faces.
