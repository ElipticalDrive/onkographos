# Mask Projection Culling

Also called: Mesh Culling via Mask Projection

## Overview
Mask Projection Culling is a visibility optimization technique that filters mesh vertices and faces by projecting them into multiple camera views and checking if they fall within dilated binary masks, removing geometry not visible in any view [S1, unofficial]. It sets itself apart from sibling methods like [Face Coverage Mask Culling](3397-face-coverage-mask-culling.md) by operating in screen space using pre-computed or rendered masks rather than volumetric occupancy checks, and from [Voxel Backface Culling and Internal Face Masking](4569-voxel-backface-culling-and-internal-face-masking.md) by relying on multi-view consistency rather than local geometric orientation.

## How it works
**Inputs:**
*   `mesh`: A triangle mesh with vertices $V \in \mathbb{R}^{N \times 3}$ and faces $F \in \mathbb{R}^{M \times 3}$ (indices into $V$).
*   `cameras`: A collection of camera parameters including world-to-camera matrices ($P$), intrinsic matrices ($K$), and scale matrices ($S$).
*   `masks`: A set of binary masks $M_i \in \{0, 1\}^{H \times W}$ for each camera view $i$, where 1 indicates occupied/visible pixels.
*   `image_dims`: Width $W$ and Height $H$ of the mask images.

**Outputs:**
*   `filtered_mesh`: A mesh containing only vertices and faces that are visible in at least one camera view.

**Data Structures:**
*   `pix_coords`: Tensor of shape $(N, 2)$ storing normalized pixel coordinates for each vertex.
*   `valid`: Boolean tensor of shape $(N)$ indicating if a vertex is within the NDC bounds of the camera frustum.
*   `sampled_masks`: Tensor of shape $(N, C)$ storing the mask value sampled at each vertex's projected location across $C$ cameras.
*   `face_mask`: Boolean array of shape $(M)$ indicating if all three vertices of a face are valid across all cameras.

**Steps:**
1.  **Load Camera Parameters:** Extract scale matrices ($S$) and world matrices ($W$) from camera data. Compute the projection matrix $P = W \cdot S$. Decompose $P$ to obtain intrinsic matrix $K$ and pose matrix (world-to-camera) $C_{pose}$ [S1, unofficial].
2.  **Load Masks:** Load binary masks $M_i$ for each camera view $i$. Hard-code or retrieve image dimensions $W$ and $H$ [S1, unofficial].
3.  **Project Vertices:** For each camera view $i$:
    a. Compute the inverse pose matrix $C_{inv} = C_{pose}^{-1}$ [S1, unofficial].
    b. Transform vertices to camera space: $V_{cam} = K \cdot C_{inv} \cdot V_{world}$ [S1, unofficial].
    c. Compute pixel coordinates: $u, v = \frac{V_{cam}[0]}{V_{cam}[2] + \epsilon}, \frac{V_{cam}[1]}{V_{cam}[2] + \epsilon}$, where $\epsilon = 10^{-6}$ to prevent division by zero [S1, unofficial].
    d. Normalize to NDC space $[-1, 1]$:
       $$ u_{ndc} = \left( \frac{u}{W - 1} - 0.5 \right) \cdot 2 $$
       $$ v_{ndc} = \left( \frac{v}{H - 1} - 0.5 \right) \cdot 2 $$
    e. Compute validity mask: $valid_i = (u_{ndc} > -1) \land (u_{ndc} < 1) \land (v_{ndc} > -1) \land (v_{ndc} < 1)$ [S1, unofficial].
4.  **Sample Masks:**
    a. Dilate the binary mask $M_i$ using morphological dilation with a disk kernel of radius $r=24$ [S1, unofficial].
    b. Sample the dilated mask at the NDC coordinates $(u_{ndc}, v_{ndc})$ using nearest-neighbor interpolation with zero padding [S1, unofficial].
    c. Store the sampled value for each vertex in $sampled\_masks[:, i]$ [S1, unofficial].
5.  **Filter Geometry:**
    a. Combine validity and mask sampling: $mask_i = sampled\_masks[:, i] > 0$ AND $valid_i$ [S1, unofficial].
    b. A vertex is kept if it is valid in *any* camera view: $vertex\_keep = \bigvee_{i} mask_i$ [S1, unofficial].
    c. A face is kept if *all* its vertices are kept: $face\_keep = vertex\_keep[F[:, 0]] \land vertex\_keep[F[:, 1]] \land vertex\_keep[F[:, 2]]$ [S1, unofficial].
6.  **Transform and Export:**
    a. Apply the inverse scale transformation to the kept vertices to return them to world space: $V_{final} = S^{-1} \cdot V_{kept}$ [S1, unofficial].
    b. Export the filtered mesh [S1, unofficial].

**Pseudocode:**

```python
import torch
import numpy as np
import torchvision.transforms.functional as TF

def mask_projection_culling(mesh_vertices, mesh_faces, cameras, masks, W, H, dilation_radius=24):
    """
    Filters mesh vertices and faces based on multi-view mask projection.
    
    Args:
        mesh_vertices: Tensor (N, 3) in world space.
        mesh_faces: Tensor (M, 3) indices into mesh_vertices.
        cameras: List of dicts with keys 'world_mat', 'scale_mat', 'K'.
        masks: List of binary tensors (H, W) for each camera.
        W, H: Image dimensions.
        dilation_radius: Radius for morphological dilation.
        
    Returns:
        filtered_vertices: Tensor (N', 3) in world space.
        filtered_faces: Tensor (M', 3) indices into filtered_vertices.
    """
    N = mesh_vertices.shape[0]
    C = len(cameras)
    
    # Initialize mask validity: True if visible in ANY camera
    vertex_visible = torch.zeros(N, dtype=torch.bool, device=mesh_vertices.device)
    
    for i in range(C):
        cam = cameras[i]
        mask = masks[i]
        
        # 1. Compute Projection and Inverse Pose
        # P = world_mat @ scale_mat
        P = cam['world_mat'] @ cam['scale_mat']
        # Decompose P to get K and pose (world-to-camera)
        # Note: In practice, this uses a helper like rend_util.load_K_Rt_from_P
        # Here we assume K and pose are pre-computed or extracted
        K = cam['K']
        pose = cam['pose'] # World-to-Camera matrix
        
        # 2. Project Vertices
        # Add batch dimension for matrix multiplication: (1, N, 3) -> (1, N, 4) with w=1
        verts_hom = torch.cat([mesh_vertices, torch.ones(N, 1, device=mesh_vertices.device)], dim=1)
        verts_cam = pose @ verts_hom.T # (4, N)
        
        # Perspective divide
        z = verts_cam[2, :].unsqueeze(0) + 1e-6
        pix_coords = verts_cam[:2, :] / z # (2, N)
        
        # 3. Normalize to NDC [-1, 1]
        pix_coords[0, :] /= (W - 1)
        pix_coords[1, :] /= (H - 1)
        pix_coords = (pix_coords - 0.5) * 2
        
        # 4. Validity Mask (Inside Frustum)
        valid = ((pix_coords[0, :] > -1.0) & (pix_coords[0, :] < 1.0) &
                 (pix_coords[1, :] > -1.0) & (pix_coords[1, :] < 1.0))
        
        # 5. Sample Mask
        # Dilate mask
        # Note: torchvision.transforms.functional.dilation is not standard; 
        # using a placeholder for binary_dilation logic as per source description
        dilated_mask = binary_dilation(mask, radius=dilation_radius)
        
        # Convert to float tensor for grid_sample
        dilated_mask_float = dilated_mask.float().unsqueeze(0).unsqueeze(0) # (1, 1, H, W)
        
        # Prepare grid for grid_sample: (1, N, 1, 2)
        grid = pix_coords.permute(1, 0).unsqueeze(0).unsqueeze(0) # (1, 1, N, 2)
        
        # Sample using nearest neighbor
        sampled = torch.nn.functional.grid_sample(
            dilated_mask_float, 
            grid, 
            mode='nearest', 
            padding_mode='zeros', 
            align_corners=True
        ) # (1, 1, N, 1)
        
        sampled_values = sampled.squeeze() # (N,)
        
        # 6. Update Vertex Visibility
        # Vertex is visible if it is in frustum AND mask value > 0
        visible_in_view = valid & (sampled_values > 0.0)
        vertex_visible = vertex_visible | visible_in_view
        
    # 7. Filter Faces
    # Face is kept if all 3 vertices are visible
    face_vertices = mesh_faces[vertex_visible] # This step is tricky with indices
    # Correct way: Check if all vertices of each face are in vertex_visible
    face_mask = vertex_visible[mesh_faces[:, 0]] & vertex_visible[mesh_faces[:, 1]] & vertex_visible[mesh_faces[:, 2]]
    
    # 8. Transform Back to World Space
    # Apply inverse scale to kept vertices
    # Note: Source says transform using scale_mat[0,0] and scale_mat[:3,3]
    # Assuming uniform scale for simplicity, or full inverse matrix
    # Let's assume scale_mat is diagonal for uniform scaling as per common practice
    # If scale_mat is affine, use inverse
    scale_mat = cameras[0]['scale_mat'] # Assuming uniform scale across cameras or first one
    # Inverse scale transform
    # V_world = S^-1 * V_cam? No, vertices are already in world space in input.
    # The source says "transform vertices back to world space using scale_mat".
    # This implies the input vertices might be in a scaled space or the mask projection
    # was done in a specific coordinate system. 
    # Re-reading source: "transform vertices back to world space using scale_mat[0,0] and scale_mat[:3,3]"
    # This suggests the mesh vertices provided might be in a normalized or scaled coordinate system
    # relative to the camera's scale_mat. 
    # Let's assume the input mesh is in the coordinate system defined by the scale_mat.
    # To get back to "world" (or the canonical space), we might need to apply the scale.
    # However, the source says "transform vertices back to world space".
    # If the input mesh is already in world space, this step might be redundant or 
    # refers to undoing a normalization. 
    # Given the ambiguity, we apply the scale transformation as described.
    
    # Assuming scale_mat is a 4x4 matrix
    # V_final = scale_mat * V_input? Or inverse?
    # Source: "transform vertices back to world space using scale_mat[0,0] and scale_mat[:3,3]"
    # This usually means scaling by the diagonal and translating by the translation vector.
    # Let's assume the input vertices are in a "canonical" space and need to be scaled to world.
    
    # For the purpose of this implementation, we assume the input mesh is in the 
    # coordinate system that requires scaling by scale_mat to be in the final world space.
    
    # Extract scale and translation
    s = scale_mat[0, 0]
    t = scale_mat[:3, 3]
    
    # Apply scale and translation to kept vertices
    filtered_vertices = mesh_vertices[vertex_visible] * s + t
    
    # Filter faces
    filtered_faces = mesh_faces[face_mask]
    
    return filtered_vertices, filtered_faces

def binary_dilation(mask, radius):
    """
    Placeholder for morphological dilation.
    In PyTorch, this can be implemented using max pooling or convolution.
    """
    # Using max pooling as a proxy for dilation
    kernel_size = 2 * radius + 1
    # Pad mask to handle boundaries
    padded_mask = torch.nn.functional.pad(mask.float().unsqueeze(0).unsqueeze(0), (radius, radius, radius, radius), mode='constant', value=0)
    # Max pool
    dilated = torch.nn.functional.max_pool2d(padded_mask, kernel_size=kernel_size, stride=1)
    return (dilated > 0.5).squeeze()
```

**Edge Cases and Pitfalls:**
*   **Precision:** Division by zero in perspective divide is handled by $\epsilon = 10^{-6}$ [S1, unofficial].
*   **Boundaries:** Vertices exactly on the NDC boundary ($\pm 1$) are excluded by strict inequality checks ($>$ and $<$) [S1, unofficial].
*   **Dilation Radius:** The dilation radius ($r=24$) is hard-coded in the source [S1, unofficial]. A small radius may lead to over-culling if vertex projection is slightly off due to floating-point errors or camera calibration inaccuracies.
*   **Mask Alignment:** The mask must be perfectly aligned with the camera's projection. Misalignment will cause incorrect culling.
*   **Degenerate Input:** If a mesh has no vertices or faces, the algorithm returns empty results. If all vertices are outside the frustum or masks, the result is an empty mesh.

## Subtopics

### True Back-Face Culling via Group Masking
A back-face culling technique that splits chunk meshes into 6 vertex pool buckets based on face orientation (group 0-5) [S2, unofficial]. Draw calls are masked based on camera position relative to the chunk, preventing the draw call from being issued entirely rather than culling in the fragment shader [S2, unofficial]. It is chosen when driver overhead must be minimized compared to splitting chunks into 6 sub-meshes [S2, unofficial]. It sets itself apart from standard back-face culling by operating at the draw call level using vertex pool bucketing [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot C)$, where $N$ is the number of vertices and $C$ is the number of cameras. Projection and sampling are linear in vertices and cameras.
*   **Memory Complexity:** $O(N \cdot C)$ for storing sampled mask values, plus $O(H \cdot W \cdot C)$ for masks if not pre-dilated.
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Scales linearly with the number of cameras and vertices.
*   **Strengths:** Effective at removing geometry that is occluded or outside the view frustum across multiple views. Simple to implement with standard graphics libraries.
*   **Limitations:** Requires pre-computed or rendered masks. Sensitive to camera calibration and mask alignment. The hard-coded dilation radius may not be optimal for all scenes.
*   **When to use:** When multi-view data is available and geometry needs to be filtered based on visibility in specific camera views.
*   **When not to use:** When real-time culling is required without pre-computed masks, or when the scene is viewed from a single camera.
