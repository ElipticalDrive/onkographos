# Mask Projection Culling

Also called: Depth-Projected Mesh Culling, Mesh Culling via Mask Projection, point mask culling

## Overview
Mask Projection Culling is a visibility-based mesh filtering technique that removes vertices and faces not consistently observed across multiple camera poses by projecting 3D points into camera space and comparing their depth against rendered depth maps and binary masks [S1, S2, unofficial]. It differs from [Face Culling](8735-face-culling.md) and [Voxel Backface Culling and Internal Face Masking](4569-voxel-backface-culling-and-internal-face-mask.md) by operating on pre-generated mesh geometry using external camera views rather than local voxel adjacency rules, and from [Block Visibility Culling](5334-block-visibility-culling.md) by utilizing dense depth sampling and morphological dilation for robust occlusion handling [S1, S2, unofficial].

## How it works
**Inputs:**
- A mesh defined by vertices $V \in \mathbb{R}^{N \times 3}$ and faces $F \in \mathbb{R}^{M \times 3}$ (indices into $V$).
- A set of $V$ camera poses, each defined by a world-to-camera matrix $W2C$ and an intrinsic matrix $K$.
- Binary masks $M_i \in \{0, 1\}^{H \times W}$ for each camera view $i$, indicating valid regions.
- Rendered depth maps $D_i \in \mathbb{R}^{H \times W}$ for each camera view $i$.
- Parameters: `eps` (depth tolerance, typically 0.005 [S2, unofficial]), `points_batch_size` (typically $5 \times 10^5$ [S2, unofficial]), `remove_small_geometry_threshold` (typically 0.2 [S2, unofficial]).

**Data Structures:**
- `valid_counts`: Array of size $N$, initialized to 0, storing the number of views in which each vertex is visible.
- `face_mask`: Boolean array of size $M$, indicating if a face should be retained.

**Steps:**

1. **Preprocessing:**
   - For each camera $i$, ensure coordinate systems match. If using OpenGL conventions for the mesh but OpenCV for cameras, flip the Y and Z axes of the camera pose: $W2C_{corrected} = W2C \cdot \text{diag}(1, -1, -1, 1)$ [S2, unofficial].
   - Dilate each binary mask $M_i$ using morphology.binary_dilation with a disk of radius 24 to account for projection inaccuracies [S1, unofficial].

2. **Vertex Visibility Evaluation:**
   - Initialize `valid_counts` to zeros.
   - Process vertices in batches of size `points_batch_size` to limit GPU memory [S2, unofficial].
   - For each batch of vertices $V_{batch}$ and each camera view $i$:
     a. Transform vertices to camera space: $P_{cam} = W2C_i \cdot [V_{batch}; 1]$.
     b. Project to 2D: $uv = K \cdot P_{cam}$.
     c. Perform homogeneous division: $z = uv[:, 2] + \epsilon$, $u = uv[:, 0] / z$, $v = uv[:, 1] / z$ [S2, unofficial].
     d. Check frustum bounds: $in\_frustum = (u \ge 0) \land (u < W) \land (v \ge 0) \land (v < H) \land (z > 0)$ [S2, unofficial].
     e. Sample the dilated mask $M_i$ at $(u, v)$ using bilinear interpolation with `padding_mode='border'` to handle out-of-bounds queries safely [S1, S2, unofficial]. Let the sampled value be $m_{sample}$.
     f. Sample the depth map $D_i$ at $(u, v)$ using bilinear interpolation with `padding_mode='border'` [S2, unofficial]. Let the sampled value be $d_{sample}$.
     g. Determine if the point is in front of the surface: $is\_front = (d_{sample} > 0) \land (z < d_{sample} + \text{eps})$ [S2, unofficial].
     h. Update visibility: If $in\_frustum \land m_{sample} > 0 \land is\_front$, increment `valid_counts` for the corresponding vertices [S1, S2, unofficial].

3. **Face Filtering:**
   - A vertex is considered valid if `valid_counts` $\ge$ 20 (or a threshold based on total views) [S2, unofficial].
   - A face is valid if all three of its vertices are valid: $face\_mask[j] = \bigwedge_{k \in F[j]} (vertex\_valid[k])$ [S1, unofficial].
   - Optionally, remove small connected components if their area ratio is below `remove_small_geometry_threshold` [S2, unofficial].

4. **Output:**
   - Return the mesh with only valid vertices and faces. Transform vertices back to world space if necessary using the inverse of the scaling matrix applied during projection [S1, unofficial].

**Pseudocode:**

```python
import torch
import numpy as np

def mask_projection_culling(mesh_vertices, mesh_faces, cameras, masks, depth_maps, eps=0.005, batch_size=500000):
    """
    mesh_vertices: (N, 3)
    mesh_faces: (M, 3)
    cameras: list of dicts with 'w2c' (4,4), 'K' (3,3), 'W', 'H'
    masks: list of (H, W) uint8 arrays (dilated)
    depth_maps: list of (H, W) float32 arrays
    """
    N = mesh_vertices.shape[0]
    valid_counts = np.zeros(N, dtype=np.int32)
    
    # Convert to tensors for GPU processing
    vertices_tensor = torch.from_numpy(mesh_vertices).cuda()
    
    for i, cam in enumerate(cameras):
        w2c = cam['w2c'].cuda()
        K = cam['K'].cuda()
        H, W = cam['H'], cam['W']
        mask_tensor = torch.from_numpy(masks[i]).float().cuda().unsqueeze(0).unsqueeze(0) # (1, 1, H, W)
        depth_tensor = torch.from_numpy(depth_maps[i]).float().cuda().unsqueeze(0).unsqueeze(0) # (1, 1, H, W)
        
        # Process in batches
        for start in range(0, N, batch_size):
            end = min(start + batch_size, N)
            v_batch = vertices_tensor[start:end]
            
            # Add homogeneous coordinate
            v_hom = torch.cat([v_batch, torch.ones(end, 1).cuda()], dim=1) # (B, 4)
            
            # Transform to camera space
            p_cam = torch.matmul(w2c, v_hom.t()).t() # (B, 4)
            
            # Project
            uv = torch.matmul(K, p_cam[:, :3].t()).t() # (B, 3)
            z = uv[:, 2] + 1e-8
            u = uv[:, 0] / z
            v = uv[:, 1] / z
            
            # Check frustum
            in_frustum = (u >= 0) & (u < W) & (v >= 0) & (v < H) & (z > 0)
            
            # Normalize to [-1, 1] for grid_sample
            u_norm = (u / (W - 1)) * 2.0 - 1.0
            v_norm = (v / (H - 1)) * 2.0 - 1.0
            vgrid = torch.stack([u_norm, v_norm], dim=-1).unsqueeze(0).unsqueeze(0) # (1, 1, B, 2)
            
            # Sample mask and depth
            # padding_mode='border' handles out-of-bounds
            mask_sample = torch.nn.functional.grid_sample(mask_tensor, vgrid, mode='bilinear', padding_mode='border', align_corners=True).squeeze() # (B)
            depth_sample = torch.nn.functional.grid_sample(depth_tensor, vgrid, mode='bilinear', padding_mode='border', align_corners=True).squeeze() # (B)
            
            # Check visibility
            is_front = (depth_sample > 0) & (z < depth_sample + eps)
            visible = in_frustum & (mask_sample > 0) & is_front
            
            # Update counts
            valid_counts[start:end] += visible.cpu().numpy().astype(np.int32)
            
    # Filter faces
    vertex_valid = valid_counts >= 20 # Threshold from [S2, unofficial]
    face_mask = vertex_valid[mesh_faces].all(axis=1)
    
    valid_vertices = np.where(vertex_valid)[0]
    # Remap face indices
    vertex_map = np.full(N, -1, dtype=np.int32)
    vertex_map[valid_vertices] = np.arange(len(valid_vertices))
    valid_faces = vertex_map[mesh_faces[face_mask]]
    
    return mesh_vertices[valid_vertices], valid_faces
```

## Subtopics

### True Back-Face Culling via Group Masking
A back-face culling technique that splits chunk meshes into 6 vertex pool buckets based on face orientation (groups 0-5) [S3, unofficial]. Draw calls are masked based on the camera position relative to the chunk, preventing the draw call from being issued entirely rather than culling in the fragment shader [S3, unofficial]. It is chosen when driver overhead must be minimized compared to splitting chunks into 6 sub-meshes [S3, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N \cdot V \cdot B)$, where $N$ is the number of points, $V$ is the number of validation frames, and $B$ is the batch size [S2, unofficial].
- **Memory Complexity:** $O(N \cdot V)$ for intermediate masks and valid counts [S2, unofficial].
- **Strengths:** Robust to occlusions via depth comparison; handles complex geometry via multiple views; reduces geometry count significantly for scenes with sparse visibility [S1, S2, unofficial].
- **Limitations:** Requires pre-rendered depth maps and masks; sensitive to coordinate system mismatches (e.g., OpenGL vs OpenCV) [S2, unofficial]; performance depends on the number of validation frames [S2, unofficial].
- **When to use:** When filtering meshes generated from multi-view reconstruction or when external camera data is available.
- **When not to use:** For real-time voxel-based meshing where local adjacency culling is sufficient [S1, unofficial].

## Background
Mask Projection Culling originates from techniques used in 3D Gaussian Splatting and NeRF-based mesh extraction pipelines, where visibility is determined by projecting points into multiple camera views and checking against depth maps and masks [S1, S2, unofficial]. It is commonly used in post-processing steps of 3D reconstruction to clean up noisy meshes [S1, S2, unofficial].
