# Mask Projection Culling

Also called: Mesh Culling via Mask Projection

## Overview
Mask Projection Culling is a visibility optimization technique that filters mesh vertices and faces by projecting them into multiple camera views and checking if they fall within dilated binary masks, thereby removing geometry not visible in any view [S1, unofficial]. It differs from sibling methods like [Face Coverage Mask Culling](3397-face-coverage-mask-culling.md) by operating on the final mesh geometry via screen-space projection rather than pre-computing voxel-level coverage masks, and from [Voxel Backface Culling and Internal Face Masking](4569-voxel-backface-culling-and-internal-face-masking.md) by handling arbitrary mesh topology rather than just voxel adjacency.

## How it works
**Inputs:**
- A mesh defined by vertices $V \in \mathbb{R}^{N \times 3}$ and faces $F \in \mathbb{Z}^{M \times 3}$.
- Camera parameters: `world_mats` (4x4), `scale_mats` (4x4), and intrinsics.
- Binary masks for each view, stored as images in `mask_dir/*.png`.
- Image dimensions: Width $W=1600$, Height $H=1200$ [S1, unofficial].
- Dilate radius: $r=24$ pixels [S1, unofficial].

**Outputs:**
- A filtered mesh containing only vertices and faces visible in at least one view.

**Data Structures:**
- `valid`: Boolean tensor of shape $(N,)$ indicating if a vertex projects inside the NDC bounds.
- `sampled_masks`: Float tensor of shape $(N, K)$ where $K$ is the number of views, containing the sampled mask value for each vertex in each view.
- `face_mask`: Boolean array of shape $(M,)$ indicating if all three vertices of a face are valid and inside the dilated masks.

**Steps:**

1.  **Load Camera Parameters:**
    Extract `scale_mats` and `world_mats` from `cameras.npz`. Compute the projection matrix $P = \text{world\_mat} \times \text{scale\_mat}$. Extract intrinsics $K$ and pose $R, t$ using `rend_util.load_K_Rt_from_P(None, P)` [S1, unofficial].

2.  **Load Masks:**
    Load binary masks from `mask_dir/*.png`. Convert to float tensors. Hard-code dimensions $W=1600, H=1200$ [S1, unofficial].

3.  **Project Vertices:**
    For each view $i$:
    a. Compute inverse pose: $W2C = \text{inverse}(pose)$. Move to GPU if using CUDA [S1, unofficial].
    b. Transform vertices to camera space: $P_{cam} = K \times W2C \times V$.
    c. Compute pixel coordinates:
       $$
       pix\_coords = \frac{P_{cam}[0:2, :]}{P_{cam}[2, :] + \epsilon}
       $$
       where $\epsilon = 10^{-6}$ prevents division by zero [S1, unofficial].

4.  **Normalize to NDC:**
    Convert pixel coordinates to Normalized Device Coordinates (NDC) space $[-1, 1]$:
    $$
    pix\_coords[..., 0] = \frac{pix\_coords[..., 0]}{W - 1}
    $$
    $$
    pix\_coords[..., 1] = \frac{pix\_coords[..., 1]}{H - 1}
    $$
    $$
    pix\_coords = (pix\_coords - 0.5) \times 2
    $$
    [S1, unofficial]

5.  **Compute Validity Mask:**
    Determine if vertices are within the NDC bounds:
    $$
    valid = ((pix\_coords > -1.0) \land (pix\_coords < 1.0)).\text{all}(\text{dim}=-1).\text{float}()
    $$
    [S1, unofficial]

6.  **Dilate and Sample Masks:**
    a. Dilate the binary mask using `morphology.binary_dilation` with a disk of radius $r=24$. Convert to float tensor [S1, unofficial].
    b. Sample the dilated mask at the projected pixel coordinates using `F.grid_sample` with `mode='nearest'`, `padding_mode='zeros'`, and `align_corners=True` [S1, unofficial].
    c. Store the sampled values for each vertex in `sampled_masks`.

7.  **Filter Geometry:**
    a. Combine validity and mask sampling:
       $$
       mask = (\text{sampled\_masks} > 0.0).\text{all}(\text{dim}=-1).\text{cpu}().\text{numpy}()
       $$
       A vertex is kept if it is valid in NDC space AND inside the dilated mask for ALL views [S1, unofficial].
    b. Filter faces: A face is kept if all its vertices are kept:
       $$
       face\_mask = mask[\text{mesh.faces}].\text{all}(\text{axis}=1)
       $$
    c. Update mesh vertices and faces based on `face_mask` [S1, unofficial].

8.  **Transform and Export:**
    Transform vertices back to world space using `scale_mat[0,0]` for scaling and `scale_mat[:3,3]` for translation, then export the mesh [S1, unofficial].

**Pseudocode:**

```python
import torch
import numpy as np
import torchvision.transforms.functional as TF

def mask_projection_culling(mesh, cameras, mask_dir, W=1600, H=1200, dilate_radius=24):
    """
    Filters mesh vertices and faces based on visibility in multiple camera views.
    
    Args:
        mesh: Object with .vertices (N,3) and .faces (M,3) attributes.
        cameras: Dict or object containing 'world_mats', 'scale_mats', and intrinsic loading function.
        mask_dir: Path to directory containing mask images.
        W: Image width.
        H: Image height.
        dilate_radius: Radius for binary dilation.
        
    Returns:
        Filtered mesh vertices and faces.
    """
    vertices = mesh.vertices # (N, 3)
    faces = mesh.faces       # (M, 3)
    
    # Initialize mask for all vertices across all views
    # We want vertices that are valid in ALL views
    global_vertex_mask = np.ones(vertices.shape[0], dtype=bool)
    
    # Load masks for each view
    mask_images = load_masks(mask_dir, W, H) # Returns list of (H, W) binary arrays
    
    for i, (world_mat, scale_mat) in enumerate(zip(cameras.world_mats, cameras.scale_mats)):
        # 1. Compute Projection Matrix
        P = world_mat @ scale_mat
        
        # 2. Extract Intrinsics and Pose
        # Assuming rend_util.load_K_Rt_from_P is available
        K, R, t = load_K_Rt_from_P(None, P)
        
        # 3. Compute Inverse Pose (World to Camera)
        # Construct 4x4 pose matrix from R and t
        pose = np.eye(4)
        pose[:3, :3] = R
        pose[:3, 3] = t
        w2c = np.linalg.inv(pose)
        
        # 4. Project Vertices to Camera Space
        # Homogeneous coordinates
        vertices_homo = np.hstack([vertices, np.ones((vertices.shape[0], 1))]) # (N, 4)
        cam_points_homo = (w2c @ vertices_homo.T).T # (N, 4)
        
        # Apply Intrinsics
        # K is 3x3
        cam_points = (K @ cam_points_homo[:, :3].T).T # (N, 3)
        
        # 5. Compute Pixel Coordinates
        epsilon = 1e-6
        pix_coords = cam_points[:, :2] / (cam_points[:, 2:3] + epsilon) # (N, 2)
        
        # 6. Normalize to NDC [-1, 1]
        pix_coords[:, 0] /= (W - 1)
        pix_coords[:, 1] /= (H - 1)
        pix_coords = (pix_coords - 0.5) * 2
        
        # 7. Compute Validity Mask (Inside NDC bounds)
        valid = (pix_coords > -1.0) & (pix_coords < 1.0)
        valid = valid.all(axis=1) # (N,)
        
        # 8. Dilate and Sample Mask
        # Load mask for this view
        mask_img = mask_images[i] # (H, W) binary (0 or 1)
        
        # Dilate mask
        # Using scipy.ndimage.binary_dilation or similar
        from scipy.ndimage import binary_dilation
        from scipy.ndimage import generate_binary_structure
        struct = generate_binary_structure(2, 1) # 2D connectivity
        dilated_mask = binary_dilation(mask_img, structure=struct, iterations=dilate_radius)
        
        # Convert to float tensor for grid_sample
        mask_tensor = torch.from_numpy(dilated_mask.astype(np.float32)).unsqueeze(0).unsqueeze(0) # (1, 1, H, W)
        
        # Convert pix_coords to grid_sample format (batch, H, W, 2)
        # grid_sample expects normalized coordinates in [-1, 1]
        # pix_coords is already in [-1, 1]
        # Need to swap x/y and add batch dim
        grid = torch.zeros(1, H, W, 2)
        # Map pix_coords to grid indices
        # pix_coords[:, 0] is x, pix_coords[:, 1] is y
        # grid_sample uses (y, x) order for the last dimension? No, it uses (x, y) but the grid is indexed by (y, x)
        # Actually, grid_sample expects input grid of shape (N, H, W, 2) where grid[n, h, w, 0] is x and grid[n, h, w, 1] is y.
        # We need to sample at specific (x, y) coordinates.
        
        # Create a grid of coordinates
        y_coords, x_coords = torch.meshgrid(torch.linspace(-1, 1, H), torch.linspace(-1, 1, W), indexing='ij')
        grid[:, :, :, 0] = x_coords # x
        grid[:, :, :, 1] = y_coords # y
        
        # We want to sample at pix_coords.
        # Use F.grid_sample with the mask_tensor and a grid containing our pix_coords
        # But F.grid_sample samples the input tensor at the locations specified by the grid.
        # So we create a grid of shape (1, N, 1, 2) containing our pix_coords
        sample_grid = torch.zeros(1, vertices.shape[0], 1, 2)
        sample_grid[0, :, 0, 0] = pix_coords[:, 0] # x
        sample_grid[0, :, 0, 1] = pix_coords[:, 1] # y
        
        # Sample
        sampled = torch.nn.functional.grid_sample(
            mask_tensor, 
            sample_grid, 
            mode='nearest', 
            padding_mode='zeros', 
            align_corners=True
        ) # (1, N, 1, 1)
        
        sampled_values = sampled.squeeze().cpu().numpy() # (N,)
        
        # 9. Update Global Vertex Mask
        # Vertex is kept if valid AND sampled > 0
        view_mask = valid & (sampled_values > 0.0)
        global_vertex_mask = global_vertex_mask & view_mask
        
    # 10. Filter Faces
    # Face is kept if all its vertices are kept
    face_mask = global_vertex_mask[faces].all(axis=1)
    
    # 11. Transform Back to World Space
    # Use the first scale_mat for transformation (assuming all views share the same scale/translation relative to world)
    # Or average? The source uses scale_mat[0,0] and scale_mat[:3,3]
    scale_mat = cameras.scale_mats[0]
    scale_factor = scale_mat[0, 0]
    translation = scale_mat[:3, 3]
    
    filtered_vertices = vertices[global_vertex_mask]
    filtered_vertices = (filtered_vertices / scale_factor) - translation
    
    filtered_faces = faces[face_mask]
    
    return filtered_vertices, filtered_faces
```

**Edge Cases and Pitfalls:**
- **Precision:** Division by zero in pixel coordinate calculation is handled by adding $\epsilon = 10^{-6}$ [S1, unofficial].
- **Boundaries:** NDC bounds are strictly $(-1, 1)$. Vertices exactly on the boundary may be excluded depending on implementation details of `valid` calculation [S1, unofficial].
- **Dilation:** The choice of dilation radius $r=24$ is critical. Too small, and occlusion artifacts appear; too large, and invalid geometry is included. This value is hard-coded in the source [S1, unofficial].
- **Mask Alignment:** Masks must be aligned with the camera views. Misalignment leads to incorrect culling.

## Subtopics

### True Back-Face Culling via Group Masking
A back-face culling technique that splits chunk meshes into 6 vertex pool buckets based on face orientation (group 0-5). Draw calls are masked based on camera position relative to the chunk, preventing the draw call from being issued entirely rather than culling in the fragment shader [S2, unofficial]. It is chosen when driver overhead must be minimized and the mesh can be pre-partitioned by orientation. It differs from standard back-face culling by avoiding the fragment shader check entirely. Regular chunk meshing would require splitting a chunk into 6 sub-meshes, increasing driver overhead 6-fold, whereas this method uses the existing vertex pool bucketing [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N \cdot K)$ where $N$ is the number of vertices and $K$ is the number of views. Projection and sampling are linear in vertices.
- **Memory Complexity:** $O(N \cdot K)$ for storing sampled masks if processed per view, or $O(N)$ if processed sequentially.
- **Performance:** Reduces primitive count significantly by removing occluded geometry. Performance gain depends on the sparsity of the visible surface relative to the total mesh.
- **Strengths:** Effective for static scenes with known camera views. Simple to implement with standard graphics libraries.
- **Limitations:** Requires pre-computed masks. Not suitable for dynamic scenes with arbitrary camera movement unless masks are updated. Hard-coded parameters (resolution, dilation) may not generalize.

## Background
Originated in the context of optimizing Gaussian Splatting and mesh rendering pipelines, specifically in the `2d-gaussian-splatting` repository [S1, unofficial]. It addresses the need to reduce rendering load by removing geometry that does not contribute to the final image.
