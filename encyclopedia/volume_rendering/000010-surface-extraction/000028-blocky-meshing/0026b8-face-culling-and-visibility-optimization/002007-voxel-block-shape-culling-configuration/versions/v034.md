# Voxel Block Shape & Culling Configuration

Also called: Block trait interface, Shape enum system

## Overview
Voxel Block Shape & Culling Configuration is a trait-based system that defines block geometry, transparency culling modes, and lighting properties per block type [S1, unofficial]. It solves the problem of rigid, single-boolean transparency flags by allowing distinct culling behaviors (e.g., merging transparent faces vs. keeping them separate) and varied geometric shapes (e.g., ramps, fluids) within a unified mesh generation pipeline [S1, unofficial]. It sets itself apart from sibling methods like [Face Coverage Mask Culling](3397-face-coverage-mask-culling.md) by decoupling the *logical* block properties (shape, cull mode) from the *physical* mesh assembly, allowing polymorphic geometry generation rather than relying solely on bitmask arithmetic for all shape variations.

## How it works
The method operates by associating each logical block type with a configuration object (trait) that dictates how it contributes to the mesh. This configuration includes the geometric shape, the culling mode for face visibility, and lighting values.

### Inputs and Outputs
- **Input:** A list of non-empty voxel positions and their corresponding block types (e.g., `MyBlock::Glass`, `MyBlock::Water`).
- **Output:** A set of vertices and indices added to the chunk's mesh buffer, respecting the specific shape and culling rules of each block type.

### Data Structures

#### Block Trait Interface
Each block type implements a trait (or interface) that provides three key methods:
1.  `shape()`: Returns the geometric `Shape` enum for the block.
2.  `cull_mode()`: Returns the `CullMode` enum determining face visibility logic.
3.  `light()`: Returns lighting values (ambient occlusion or smooth light) for the block.

**Shape Enum:**
Defines the geometry of the block. Common variants include:
-   `WholeBlock`: A standard 1x1x1 cube.
-   `Cross(CrossInfo)`: A cross-shaped geometry (e.g., for chains or rails), defined by an `AlignedFace` and a `stretch` value [S1, unofficial].
-   `Ramp`: A sloped block face (see Subtopics).
-   `Fluid`: A fluid surface (see Subtopics).

**CullMode Enum:**
Determines how faces are culled based on neighbor occupancy and transparency.
-   `Empty`: The block is air; no faces are generated.
-   `Opaque`: Standard solid culling. A face is exposed if the neighbor is empty or out of bounds.
-   `TransparentMerged(T)`: Culls shared faces between two transparent blocks if their `TransparentGroup` values are equal. This merges adjacent transparent blocks of the same type into a single continuous surface [S1, unofficial].
-   `TransparentUnmerged`: Transparent blocks do not merge faces with neighbors; each exposed face is rendered individually. Used for blocks like leaves, cobwebs, or chains where internal structure should be visible [S1, unofficial].

**Lighting Data:**
-   Returns a `u8` or `f32` value representing light emission or occlusion. For example, `MyBlock::Air` returns `0.0`, while `MyBlock::Lamp` returns `14.0` [S1, unofficial].

### Numbered Steps

1.  **Initialize Mesh Buffers:** Create empty vertex and index lists for the chunk.
2.  **Iterate Voxels:** For each non-empty voxel at position $P$ with block type $B$:
    a. Retrieve the block trait $T_B$ for $B$.
    b. Call $T_B$.`cull_mode()` to determine the culling strategy.
    c. Call $T_B$.`shape()` to determine the geometric primitive(s) to generate.
3.  **Generate Geometry:**
    a. Based on the `Shape`, instantiate the corresponding geometry builder (e.g., `BoxBuilder`, `WaterBuilder`, `RampBuilder`).
    b. For each face of the block:
        i. Check neighbor occupancy at $P + d$ (where $d$ is the face direction).
        ii. Apply the `CullMode` logic:
            - If `Opaque`: Cull if neighbor is solid.
            - If `TransparentMerged(T)`: Cull if neighbor is solid OR if neighbor is transparent with the same `TransparentGroup` $T$.
            - If `TransparentUnmerged`: Cull only if neighbor is solid.
        iii. If the face is exposed, call the geometry builder's `BuildGeometry()` method, passing the chunk reference and face data.
    c. The `BuildGeometry()` method adds vertices and indices to the chunk's linked list [S3, unofficial].
4.  **Finalize Mesh:** After all voxels are processed, transfer the vertex and index data from the linked list to the final mesh object (e.g., Unity3D `Mesh` object) on the main thread [S3, unofficial].

### Formulas

**Culling Condition for TransparentMerged:**
A face in direction $d$ at position $P$ is culled if:
$$ \text{Neighbor}(P+d) \in \text{Solid} \lor (\text{Neighbor}(P+d) \in \text{Transparent} \land \text{Group}(\text{Neighbor}(P+d)) = \text{Group}(P)) $$

**Culling Condition for TransparentUnmerged:**
A face in direction $d$ at position $P$ is culled if:
$$ \text{Neighbor}(P+d) \in \text{Solid} $$

### Parameters
-   `FLUID_ENABLED`: Boolean flag. If `true`, fluid shapes are enabled. If `false`, fluids are treated as cubes or ignored. Setting this to `true` without implementing fluid shape causes a debug assertion failure [S1, unofficial].
-   `TransparentGroup`: An integer or hash value assigned to transparent blocks to determine mergeability.

### Edge Cases and Pitfalls
-   **Fluid Shape Implementation:** If `FLUID_ENABLED` is `true` but the fluid shape geometry is not implemented, the system will fail with a debug assertion rather than silently rendering fluids as cubes [S1, unofficial].
-   **Threading Constraints:** In engines like Unity3D, mesh creation functions must be called on the main thread. While vertex/index calculation can be done on a background thread, the final assembly into the `Mesh` object must be moved to the main thread [S3, unofficial].
-   **Ramp Tint Fallback:** For ramp shapes, if a specific tint is `Vector3.One`, the system should fallback to another face's tint to avoid visual artifacts [S2, unofficial].

class BlockTrait:
    def shape(self) -> Shape:
        raise NotImplementedError

    def cull_mode(self) -> CullMode:
        raise NotImplementedError

    def light(self) -> float:
        raise NotImplementedError

class Chunk:
    def __init__(self):
        self.vertices = []
        self.indices = []
        self.geometry_builders = {}

    def register_builder(self, shape: Shape, builder: GeometryBuilder):
        self.geometry_builders[shape] = builder

    def build_mesh(self, voxels: List[Voxel]):
        for voxel in voxels:
            if voxel.is_empty:
                continue
            
            block_type = voxel.block_type
            trait = get_trait(block_type)
            shape = trait.shape()
            cull_mode = trait.cull_mode()
            
            builder = self.geometry_builders.get(shape)
            if not builder:
                continue # Or handle error
            
            for face_direction in [UP, DOWN, LEFT, RIGHT, FRONT, BACK]:
                neighbor_pos = voxel.pos + face_direction
                neighbor = get_voxel(neighbor_pos)
                
                if is_face_culled(voxel, neighbor, cull_mode):
                    continue
                
                builder.build_geometry(self, voxel.pos, face_direction, trait)
        
        # Finalize mesh on main thread
        finalize_mesh_on_main_thread(self.vertices, self.indices)

def is_face_culled(voxel, neighbor, cull_mode):
    if cull_mode == CullMode.Empty:
        return True
    if cull_mode == CullMode.Opaque:
        return neighbor.is_solid
    if cull_mode == CullMode.TransparentMerged:
        if neighbor.is_solid:
            return True
        if neighbor.is_transparent and neighbor.transparent_group == voxel.transparent_group:
            return True
        return False
    if cull_mode == CullMode.TransparentUnmerged:
        return neighbor.is_solid
    return False

## Subtopics

### [Three-Valued Opacity Classification for Meshing](4414-three-valued-opacity-classification-for-meshing.md)
A classification system for block IDs into three mutually exclusive layers: 'opaque', 'water', and 'transparentSolid'. It solves the insufficiency of a single boolean 'transparent' flag by distinguishing between fluids (water) requiring bespoke shaders and see-through solids (glass/leaves) requiring alpha blending. Unlike a boolean transparent flag which collapses water and glass/leaves into one category, this three-valued model allows water to use a bespoke shader (ripple, refraction) while glass/leaves use the ordinary block atlas with alpha blending.

### [VoxelBlockyTypeLibrary with Attributes](12820-voxelblockytypelibrary-with-attributes.md)
`VoxelBlockyTypeLibrary` is a model management system for blocky voxel terrains that organizes meshes by logical "block types" with configurable state attributes, rather than storing individual model references directly. It solves the problem of managing complex block behaviors (e.g., orientation, powered state, connections) by automatically generating unique numerical IDs for every combination of attribute values, similar to Minecraft's block state system. It differs from the standard `VoxelBlockyLibrary` by decoupling model identity from manual ID assignment, using a combinatorial attribute system instead.

### Ramp Shape Geometry
A shape representing a sloped block face, composed of a slope quad (2 triangles) and two side triangles (left and right) [S2, unofficial]. Instance creation involves iterating visible faces; if the face is Left, Right, Top, or Front, `drawSlope` is set to `true` and tints are assigned from `tints[0]` (Top/Front), `tints[1]` (Left), or `tints[2]` (Right) [S2, unofficial]. If a specific tint is `Vector3.One`, it falls back to another face's tint [S2, unofficial]. Slope vertices are defined as: (0,1,0) with UV[0], (0,0,1) with UV[1], (1,1,0) with UV[2], (1,1,0) with UV[3], (0,0,1) with UV[4], (1,0,1) with UV[5] [S2, unofficial]. Left triangle vertices are: (0,0,1) with UV[0], (0,1,0) with UV[1], (0,0,0) with UV[2] [S2, unofficial]. Right triangle vertices are: (1,0,0) with UV[0], (1,1,0) with UV[1], (1,0,1) with UV[2] [S2, unofficial].

### Fluid Surface Stitching
A mesh generation technique where fluid columns share a surface height field with neighbors, stitching surfaces when fluid IDs match [S1, unofficial]. Two adjacent fluid blocks join their surfaces only when their `FluidInfo::id` (u8) values are equal [S1, unofficial].

### Geometry Builder Pattern
A design pattern using an interface to control the type of geometry created for each non-empty voxel, allowing different geometry types (cubes, ramps, X-shapes) to be generated via polymorphism without large switch statements [S3, unofficial]. The interface `IGeometryBuilder` contains a single function `BuildGeometry()` [S3, unofficial]. During mesh creation, `BuildGeometry()` is called once for each non-empty block, passing a reference to the chunk object [S3, unofficial]. Inside `BuildGeometry()`, vertices and indices are added to the chunk's linked list [S3, unofficial]. After all blocks are processed, the data is placed into the final mesh object on the main thread [S3, unofficial]. A pitfall is that Unity3D functions must be called on the main thread, so while calculation is done on a background thread, the final `Mesh` object creation must be moved to the main thread [S3, unofficial].

## Operating characteristics
-   **Time Complexity:** $O(N)$ where $N$ is the number of voxels, as each voxel is processed once to determine its contribution to the mesh. The culling check is $O(1)$ per face.
-   **Memory Complexity:** $O(V)$ where $V$ is the number of vertices in the final mesh. The linked list approach allows for dynamic resizing without pre-allocating a fixed buffer size.
-   **Strengths:** Flexible support for diverse block shapes (ramps, fluids, cross shapes) without modifying the core mesh generation loop. Efficient culling reduces triangle count significantly compared to naive cube rendering.
-   **Limitations:** Requires careful implementation of geometry builders for each shape type. Threading constraints in some engines (like Unity3D) require careful management of mesh finalization steps.
-   **When to use:** When the voxel world contains a variety of block types with different geometric and transparency requirements (e.g., Minecraft-like worlds).
-   **When not to use:** For simple, uniform voxel worlds where a single shape and culling mode suffice, as the overhead of the trait system may be unnecessary.

## Background
The concept of trait-based configuration for voxel mesh generation originated in implementations like `finnbear/voxmesh` [S1, unofficial], which introduced a system for defining block geometry, transparency culling, and lighting per block type. The Geometry Builder Pattern was further detailed in academic work on procedural generation of voxel worlds, such as the thesis "Procedural Generation of Voxel Worlds with Castles" [S3, unofficial], which described its use in Unity3D for managing complex voxel geometries. The Ramp Shape Geometry and Fluid Surface Stitching techniques are documented in projects like `rarefushion/Cubic-Grid_Voxel_Renderer` [S2, unofficial], which implemented these specific shape variations for enhanced visual fidelity.
