# Voxel Block Shape & Culling Configuration

Also called: Block trait interface, Shape enum system

## Overview
Voxel Block Shape & Culling Configuration is a trait-based system that defines the geometry, transparency culling behavior, and lighting properties for individual block types within a voxel mesh generator. It solves the problem of heterogeneous block rendering by allowing each block ID to specify its own shape (e.g., cube, ramp, cross) and culling mode (e.g., opaque, transparent merged, transparent unmerged) [S1, unofficial]. Unlike generic face culling which treats all solid voxels uniformly, this method decouples block identity from geometry generation, enabling complex shapes and varied transparency handling (such as distinguishing between water and glass) without modifying the core meshing loop [S1, unofficial]. It builds on [Face Culling and Visibility Optimization](3861-face-culling-and-visibility-optimization.md) by providing the per-block rules that determine *which* faces are generated and *how* they are culled.

## How it works
The method operates by associating a configuration trait with each block type. During mesh generation, the system queries this trait for every non-empty voxel to determine its shape and culling mode.

### Inputs and Outputs
*   **Input**: A voxel grid where each cell contains a block ID (e.g., `MyBlock::Glass`).
*   **Output**: A list of visible faces (vertices and indices) for the chunk, where each face is generated according to the block's specific shape and culling rules.

### Data Structures
The core configuration is defined via a trait or interface that exposes three key methods/fields:

1.  **Shape**: Defines the geometry of the block.
    *   `Shape::WholeBlock`: A standard 6-faced cube.
    *   `Shape::Cross(CrossInfo)`: A cross-shaped geometry (e.g., for ladders/chains), defined by an `AlignedFace` (direction) and `stretch` value.
    *   `Shape::Ramp`: A sloped geometry (see Subtopics).
    *   [S1, unofficial]

2.  **CullMode**: Defines how transparency is handled relative to neighbors.
    *   `CullMode::Empty`: The block is air; no faces are generated.
    *   `CullMode::Opaque`: The block is fully solid. Faces are generated if the neighbor is empty/transparent. Shared faces between two opaque blocks are culled.
    *   `CullMode::TransparentMerged(T)`: The block is transparent. Faces are generated if the neighbor is empty or has a different transparency group. Crucially, shared faces between two transparent blocks with the *same* `TransparentGroup` value `T` are culled (merged) [S1, unofficial].
    *   `CullMode::TransparentUnmerged`: The block is transparent. Faces are generated if the neighbor is empty or transparent, regardless of group. Shared faces between two transparent blocks are *not* culled, allowing both sides to be rendered (necessary for see-through objects like glass where internal reflections or double-sided rendering might be desired, or for specific shader requirements) [S1, unofficial].

3.  **Light**: Returns a lighting value (float or u8) for the block, potentially varying by face (e.g., cactus top vs. side) [S1, unofficial].

### Pseudocode
The following pseudocode illustrates the integration of shape and culling configuration into the mesh generation loop. It assumes a `BlockConfig` trait/interface.

```python
def generate_mesh_with_config(chunk_data, block_configs):
    """
    Generates a mesh using per-block shape and culling configuration.
    
    Args:
        chunk_data: A 3D array or hash map of block IDs.
        block_configs: A dictionary mapping block IDs to their configuration objects.
        
    Returns:
        A list of visible faces.
    """
    visible_faces = []
    directions = [
        (1, 0, 0),   # Right
        (-1, 0, 0),  # Left
        (0, 1, 0),   # Up
        (0, -1, 0),  # Down
        (0, 0, 1),   # Front
        (0, 0, -1)   # Back
    ]
    
    for voxel_pos, block_id in chunk_data.items():
        config = block_configs[block_id]
        
        # 1. Determine Cull Mode
        cull_mode = config.cull_mode()
        
        # If empty, skip entirely
        if cull_mode == CullMode.Empty:
            continue
            
        # 2. Determine Shape
        shape = config.shape()
        
        # 3. Iterate over potential faces based on shape
        # For WholeBlock, check all 6 directions. 
        # For Cross, check only the relevant direction(s).
        # For Ramp, check specific faces (see Subtopics).
        
        if shape == Shape.WholeBlock:
            faces_to_check = directions
        elif shape == Shape.Cross:
            # CrossInfo contains face direction
            faces_to_check = [shape.face.direction] 
        else:
            # Fallback or specific shape logic
            faces_to_check = directions 

        for dx, dy, dz in faces_to_check:
            neighbor_pos = voxel_pos + (dx, dy, dz)
            neighbor_id = chunk_data.get(neighbor_pos)
            
            # Get neighbor config if it exists
            neighbor_config = block_configs.get(neighbor_id) if neighbor_id else None
            neighbor_cull_mode = neighbor_config.cull_mode() if neighbor_config else CullMode.Empty
            
            # 4. Apply Culling Logic
            is_visible = False
            
            if cull_mode == CullMode.Opaque:
                # Opaque: Visible if neighbor is not opaque
                # Note: Standard opaque culling usually means visible if neighbor is empty/transparent
                is_visible = neighbor_cull_mode != CullMode.Opaque
                
            elif cull_mode == CullMode.TransparentMerged:
                # TransparentMerged: Visible if neighbor is empty OR 
                # neighbor is transparent but has a different group.
                # Shared faces between same-group transparents are culled.
                if neighbor_cull_mode == CullMode.Empty:
                    is_visible = True
                elif neighbor_cull_mode == CullMode.TransparentMerged:
                    # Compare groups
                    if config.transparent_group != neighbor_config.transparent_group:
                        is_visible = True
                    else:
                        is_visible = False # Merged
                else:
                    # Neighbor is Opaque or Unmerged
                    is_visible = True
                    
            elif cull_mode == CullMode.TransparentUnmerged:
                # Unmerged: Visible if neighbor is empty or transparent
                # Always render face if neighbor is not opaque? 
                # Or always render if neighbor is not same block?
                # Standard interpretation: Render if neighbor is not opaque.
                # However, "Unmerged" often implies rendering both sides of thin objects.
                # If neighbor is transparent, we still render the face.
                is_visible = neighbor_cull_mode != CullMode.Opaque
                
            else:
                is_visible = False # Default to false for safety

            if is_visible:
                # 5. Generate Geometry based on Shape
                face_vertices = generate_shape_geometry(shape, voxel_pos, dx, dy, dz)
                visible_faces.append(face_vertices)
                
    return visible_faces

def generate_shape_geometry(shape, pos, dx, dy, dz):
    """
    Generates vertex data based on the block's shape configuration.
    """
    if shape == Shape.WholeBlock:
        return create_cube_face(pos, dx, dy, dz)
    elif shape == Shape.Cross:
        return create_cross_face(pos, shape.face, shape.stretch)
    elif shape == Shape.Ramp:
        return create_ramp_face(pos, dx, dy, dz)
    else:
        return create_cube_face(pos, dx, dy, dz) # Fallback
```

### Parameters and Typical Values
*   **TransparentGroup**: An integer or enum identifier for `TransparentMerged` blocks. Typical values might be `0` for air, `1` for water, `2` for glass. [S1, unofficial]
*   **Light Value**: A float representing light emission or attenuation. Typical values range from `0.0` (dark) to `15.0` (bright, like Minecraft lava) [S1, unofficial].

### Edge Cases and Pitfalls
*   **Fluid Shape Assertion**: Setting a flag like `FLUID_ENABLED` to true without implementing the corresponding fluid shape geometry (e.g., `Shape::Fluid`) will cause a debug assertion failure rather than silently rendering fluids as cubes [S1, unofficial].
*   **Threading Constraints**: When using a Geometry Builder pattern (see Subtopics), vertex/index calculation can be done on a background thread, but the final assembly of the Mesh object (e.g., in Unity3D) must be done on the main thread [S3, unofficial].
*   **CullMode Ambiguity**: The distinction between `TransparentMerged` and `TransparentUnmerged` must be consistent. `TransparentMerged` reduces draw calls by merging adjacent transparent blocks of the same type, while `TransparentUnmerged` ensures all faces are rendered, which is necessary for objects like glass panes or leaves where internal visibility matters [S1, unofficial].

## Subtopics

### [Three-Valued Opacity Classification for Meshing](4414-three-valued-opacity-classification-for-meshing.md)
A classification system for block IDs into three mutually exclusive layers: 'opaque', 'water', and 'transparentSolid'. It solves the insufficiency of a single boolean 'transparent' flag by distinguishing between fluids (water) requiring bespoke shaders (ripple, refraction) and see-through solids (glass/leaves) requiring alpha blending. Unlike a boolean transparent flag which collapses water and glass/leaves into one category, this three-valued model allows water to use a bespoke shader while glass/leaves use the ordinary block atlas with alpha blending. Link: [Three-Valued Opacity Classification for Meshing](4414-three-valued-opacity-classification-for-meshing.md).

### [VoxelBlockyTypeLibrary with Attributes](12820-voxelblockytypelibrary-with-attributes.md)
`VoxelBlockyTypeLibrary` is a model management system for blocky voxel terrains that organizes meshes by logical "block types" with configurable state attributes, rather than storing individual model references directly. It solves the problem of managing complex block behaviors (e.g., orientation, powered state, connections) by automatically generating unique numerical IDs for every combination of attribute values, similar to Minecraft's block state system. It differs from the standard `VoxelBlockyLibrary` by decoupling model identity from manual ID assignment, using a combinatorial attribute system instead. Link: [VoxelBlockyTypeLibrary with Attributes](12820-voxelblockytypelibrary-with-attributes.md).

#### Ramp Shape Geometry
A shape representing a sloped block face, composed of a slope quad (2 triangles) and two side triangles (left and right) [S2, unofficial]. Instance creation involves iterating visible faces; if the face is Left, Right, Top, or Front, `drawSlope` is set to true and tints are assigned (`tints[0]` for Top/Front, `tints[1]` for Left, `tints[2]` for Right). If a specific tint is `Vector3.One`, it falls back to another face's tint. Instances for slope, left triangle, and right triangle are added using respective shape IDs and tints. If the face is Back or Bottom, the instance uses `cubeBackFaceShapeID` or `cubeBottomFaceShapeID` [S2, unofficial].
**Layout**:
*   Slope vertices (6 vertices): `(0,1,0)` UV[0], `(0,0,1)` UV[1], `(1,1,0)` UV[2], `(1,1,0)` UV[3], `(0,0,1)` UV[4], `(1,0,1)` UV[5].
*   Left triangle vertices (3 vertices): `(0,0,1)` UV[0], `(0,1,0)` UV[1], `(0,0,0)` UV[2].
*   Right triangle vertices (3 vertices): `(1,0,0)` UV[0], `(1,1,0)` UV[1], `(1,0,1)` UV[2]. [S2, unofficial]

#### Fluid Surface Stitching
A mesh generation technique where fluid columns share a surface height field with neighbors, stitching surfaces when fluid IDs match [S1, unofficial]. Two adjacent fluid blocks join their surfaces only when their `FluidInfo::id` (u8) values match [S1, unofficial].

#### Geometry Builder Pattern
A design pattern using an interface to control the type of geometry created for each non-empty voxel, allowing different geometry types (cubes, ramps, X-shapes) to be generated via polymorphism without large switch statements [S3, unofficial].
**Steps**:
1.  During mesh creation, call `BuildGeometry()` once for each non-empty block [S3, unofficial].
2.  Pass a reference to the chunk object to `BuildGeometry()` [S3, unofficial].
3.  Inside `BuildGeometry()`, use the chunk reference to add vertices and indices to the chunk's linked list [S3, unofficial].
4.  After `BuildGeometry()` has been called on every block for the chunk, place the vertex and index data into a Unity3D Mesh object on the main thread [S3, unofficial].
**Layout**: Interface `IGeometryBuilder` contains a single function: `BuildGeometry()` [S3, unofficial].
**Pitfall**: Unity3D functions must be called on the main thread. While vertex/index calculation is done on a background thread, the final Mesh object creation must be moved to the main thread [S3, unofficial].

## Operating characteristics
*   **Time Complexity**: $O(V \cdot F)$, where $V$ is the number of voxels and $F$ is the number of faces per shape (typically 6 for cubes, fewer for cross/ramp). The lookup for neighbor status is $O(1)$ with a hash set or array.
*   **Memory Complexity**: $O(V)$ for storing the voxel grid and block configurations. The output mesh size depends on the culling efficiency; opaque culling reduces geometry significantly, while transparent unmerged may retain more faces.
*   **Performance**: The original approach of checking each of the six faces by looping through neighbors and performing random memory access leads to very poor performance [S2, unofficial]. Using a hash set or contiguous array improves lookup speed. The trait-based approach adds minimal overhead per voxel compared to the geometry generation cost.
*   **Strengths**: Highly flexible; supports complex shapes and varied transparency behaviors without changing the core meshing algorithm. Efficient culling reduces draw calls.
*   **Limitations**: Requires careful implementation of shape geometries to avoid assertion failures. Threading constraints may apply depending on the rendering engine.
*   **When to use**: When rendering voxel worlds with heterogeneous block types (e.g., Minecraft-like games) that require different shapes (stairs, slabs, ladders) and transparency behaviors (water, glass, leaves).
*   **When not to use**: For simple, uniform voxel grids where all blocks are identical cubes, as the overhead of configuration lookup is unnecessary.

## Background
The concept of per-block configuration for shape and culling originated in voxel game development, particularly in games like Minecraft, where different block types require different geometries and rendering behaviors. The specific trait-based implementation described here is documented in the `finnbear/voxmesh` repository [S1, unofficial]. The Geometry Builder pattern is detailed in the thesis "Procedural Generation of Voxel Worlds with Castles" [S3, unofficial]. The Ramp Shape Geometry is described in the `rarefushion/Cubic-Grid_Voxel_Renderer` repository [S2, unofficial].
