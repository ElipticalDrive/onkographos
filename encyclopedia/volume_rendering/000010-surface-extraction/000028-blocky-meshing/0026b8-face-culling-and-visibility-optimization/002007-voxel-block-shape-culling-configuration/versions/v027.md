# Voxel Block Shape & Culling Configuration

Also called: Block trait interface, Shape enum system

## Overview
Voxel Block Shape & Culling Configuration is a trait-based system that defines the geometry, transparency culling behavior, and lighting properties for individual block types within a voxel mesh generator. It solves the problem of heterogeneous block rendering by allowing each block ID to specify its own shape (e.g., cube, ramp, fluid) and how it interacts with neighbors during face culling. Unlike the parent method's generic solid/empty check, this configuration enables advanced culling modes such as merging shared faces between transparent blocks of the same type, and supports non-cube geometries like slopes and fluids.

## How it works
The system operates by associating a configuration object (often a trait or interface implementation) with each block type. This configuration dictates the vertex layout, the culling mode, and the lighting value for any face generated by that block.

### Inputs and Outputs
*   **Input:** A block ID (e.g., `MyBlock::Glass`) and the face normal ($N$) being evaluated.
*   **Output:** A set of vertices and indices defining the geometry for that face, along with metadata (lighting, transparency flags) passed to the renderer.

### Data Structures
The configuration is typically accessed via a trait or interface. In Rust-like implementations, this involves a struct implementing a trait with methods for shape, culling, and lighting [S1, unofficial].

**Shape Enum/Struct:**
Defines the geometric primitive.
*   `WholeBlock`: Standard 6-face cube.
*   `Cross(CrossInfo)`: Partial geometry (e.g., chains, rails).
    *   `face`: `AlignedFace` (e.g., `PosZ`).
    *   `stretch`: Float value for elongation.
*   `Ramp`: Sloped geometry (see Subtopics).

**CullMode Enum:**
Determines how the face is treated relative to neighbors.
*   `Empty`: Block is air; no geometry generated.
*   `Opaque`: Standard culling. Face is culled if the neighbor is solid (occupied).
*   `TransparentMerged(T)`: Face is culled if the neighbor is transparent **and** has the same `TransparentGroup` value $T$. This merges internal faces between identical transparent blocks (e.g., two glass blocks) into a single surface, reducing draw calls.
*   `TransparentUnmerged`: Face is never culled based on neighbor transparency; always generates geometry if visible from outside the chunk or if the neighbor is empty. Used for blocks like leaves or ladders that need to show their internal structure or distinct edges.

**Lighting Value:**
A float or integer value associated with the block/face, used for ambient occlusion or direct lighting calculations.

### Numbered Steps
1.  **Lookup Configuration:** For a voxel at position $P$ with block ID $B$, retrieve the configuration object $C_B$.
2.  **Determine Cull Mode:** Call $C_B$.cull_mode() to get the culling strategy.
3.  **Evaluate Neighbor:**
    *   Calculate neighbor position $P_{neighbor} = P + N$.
    *   If $P_{neighbor}$ is out of bounds, the face is visible.
    *   If $P_{neighbor}$ is empty (Air), the face is visible.
    *   If $P_{neighbor}$ is occupied by block $B_{neighbor}$:
        *   Retrieve $C_{neighbor}$.
        *   If $C_B$.cull_mode() is `Opaque`: Cull if $B_{neighbor}$ is not Air.
        *   If $C_B$.cull_mode() is `TransparentMerged(T)`: Cull if $B_{neighbor}$ is transparent AND $C_{neighbor}$.transparent_group() == $T$.
        *   If $C_B$.cull_mode() is `TransparentUnmerged`: Do not cull based on neighbor transparency (only cull if neighbor is solid opaque, depending on specific implementation, or always generate).
4.  **Generate Geometry:**
    *   Call $C_B$.shape(face=$N$) to get the vertex layout.
    *   If the shape is `Ramp`, generate slope quads and side triangles (see Subtopics).
    *   If the shape is `Fluid`, check for fluid ID matching with neighbors to stitch surfaces (see Subtopics).
5.  **Assign Lighting:** Retrieve lighting value $L = C_B$.light(face=$N$).
6.  **Add to Mesh:** Add vertices and indices to the chunk's vertex buffer, tagging them with $L$ and block ID $B$.

### Formulas
*   **Neighbor Position:** $P_{neighbor} = P + N$
*   **Transparent Merge Condition:**
    $$ \text{Cull} \iff \text{IsTransparent}(B_{neighbor}) \land \text{Group}(B) == \text{Group}(B_{neighbor}) $$
*   **Lighting Interpolation (Vertex AO):**
    $$ L_{vertex} = \sum_{i=0}^{3} w_i L_{corner_i} $$
    Where $w_i$ are barycentric weights and $L_{corner_i}$ are the lighting values of the four corners of the face.

### Parameters
*   **TransparentGroup (T):** A unique identifier for transparent blocks that should merge. For example, all glass blocks might have $T=1$, all water blocks $T=2$.
*   **Fluid ID:** A `u8` identifier for fluid types. Adjacent fluid blocks join surfaces only if their IDs match [S1, unofficial].

### Edge Cases and Pitfalls
*   **Fluid Shape Implementation:** Setting a flag like `FLUID_ENABLED` to true without implementing the corresponding fluid shape logic causes a debug assertion failure rather than silently drawing fluids as cubes [S1, unofficial].
*   **Thread Safety:** In engines like Unity3D, geometry calculation can occur on a background thread, but the final mesh object creation must be moved to the main thread [S3, unofficial].
*   **Degenerate Slopes:** Ramp shapes require careful handling of UV coordinates and vertex sharing to avoid artifacts at the slope edges [S2, unofficial].

### Pseudocode

```python
def generate_block_face(block_id, position, face_normal):
    """
    Generates geometry for a single face of a voxel block.
    """
    config = get_block_config(block_id)
    
    # 1. Determine Cull Mode
    cull_mode = config.cull_mode()
    
    # 2. Check Neighbor
    neighbor_pos = position + face_normal
    neighbor_id = get_block_at(neighbor_pos)
    
    if neighbor_id is None: # Out of bounds
        is_visible = True
    elif neighbor_id == "Air":
        is_visible = True
    else:
        neighbor_config = get_block_config(neighbor_id)
        
        if cull_mode == "Opaque":
            is_visible = (neighbor_id == "Air")
        elif cull_mode == "TransparentMerged":
            # Merge if both are transparent and have same group
            is_visible = (neighbor_id == "Air") or \
                         (not neighbor_config.is_transparent() or \
                          neighbor_config.transparent_group() != config.transparent_group())
        elif cull_mode == "TransparentUnmerged":
            # Never merge with transparent neighbors
            is_visible = (neighbor_id == "Air")
        else:
            is_visible = True # Fallback
            
    if not is_visible:
        return [] # Culled

    # 3. Generate Geometry based on Shape
    shape = config.shape(face=face_normal)
    vertices = []
    indices = []
    
    if shape.type == "WholeBlock":
        vertices, indices = generate_cube_face(face_normal)
    elif shape.type == "Ramp":
        vertices, indices = generate_ramp_face(face_normal, shape.tints)
    elif shape.type == "Fluid":
        # Fluid stitching logic handled here or in a specialized builder
        vertices, indices = generate_fluid_face(face_normal, config.fluid_id)
    elif shape.type == "Cross":
        vertices, indices = generate_cross_face(face_normal, shape.info)
        
    # 4. Apply Lighting
    lighting = config.light(face=face_normal)
    
    # 5. Return Mesh Data
    return {
        "vertices": vertices,
        "indices": indices,
        "lighting": lighting,
        "block_id": block_id
    }

def generate_ramp_face(face_normal, tints):
    """
    Generates ramp geometry for Left, Right, Top, Front faces.
    """
    if face_normal in ["Back", "Bottom"]:
        return generate_cube_face(face_normal) # Use back/bottom cube shapes
        
    # Slope vertices (6 vertices)
    slope_verts = [
        (0,1,0, UV[0]), (0,0,1, UV[1]), (1,1,0, UV[2]),
        (1,1,0, UV[3]), (0,0,1, UV[4]), (1,0,1, UV[5])
    ]
    
    # Left triangle (3 vertices)
    left_verts = [
        (0,0,1, UV[0]), (0,1,0, UV[1]), (0,0,0, UV[2])
    ]
    
    # Right triangle (3 vertices)
    right_verts = [
        (1,0,0, UV[0]), (1,1,0, UV[1]), (1,0,1, UV[2])
    ]
    
    # Assign tints
    # Top/Front -> tints[0], Left -> tints[1], Right -> tints[2]
    # Fallback if tint is Vector3.One
    
    return slope_verts + left_verts + right_verts, [indices_for_slope, indices_for_left, indices_for_right]
```

## Subtopics

### [Three-Valued Opacity Classification for Meshing](4414-three-valued-opacity-classification-for-meshing.md)
A classification system for block IDs into three mutually exclusive layers: 'opaque', 'water', and 'transparentSolid'. It solves the insufficiency of a single boolean 'transparent' flag by distinguishing between fluids (water) requiring bespoke shaders (ripple, refraction) and see-through solids (glass/leaves) requiring alpha blending. Unlike a boolean transparent flag which collapses water and glass/leaves into one category, this three-valued model allows water to use a bespoke shader while glass/leaves use the ordinary block atlas with alpha blending.

### [VoxelBlockyTypeLibrary with Attributes](12820-voxelblockytypelibrary-with-attributes.md)
`VoxelBlockyTypeLibrary` is a model management system for blocky voxel terrains that organizes meshes by logical "block types" with configurable state attributes, rather than storing individual model references directly. It solves the problem of managing complex block behaviors (e.g., orientation, powered state, connections) by automatically generating unique numerical IDs for every combination of attribute values, similar to Minecraft's block state system. It differs from the standard `VoxelBlockyLibrary` by decoupling model identity from manual ID assignment, using a combinatorial attribute system instead.

### Ramp Shape Geometry
A shape representing a sloped block face, composed of a slope quad (2 triangles) and two side triangles (left and right) [S2, unofficial]. Instance creation iterates visible faces; if the face is Left, Right, Top, or Front, `drawSlope` is set to true and tints are assigned (`tints[0]` for Top/Front, `tints[1]` for Left, `tints[2]` for Right). If a specific tint is `Vector3.One`, it falls back to another face's tint. Instances are added for the slope, left triangle, and right triangle using respective shape IDs and tints. For Back or Bottom faces, the standard `cubeBackFaceShapeID` or `cubeBottomFaceShapeID` is used [S2, unofficial]. The slope vertices are: (0,1,0) UV[0], (0,0,1) UV[1], (1,1,0) UV[2], (1,1,0) UV[3], (0,0,1) UV[4], (1,0,1) UV[5]. Left triangle vertices: (0,0,1) UV[0], (0,1,0) UV[1], (0,0,0) UV[2]. Right triangle vertices: (1,0,0) UV[0], (1,1,0) UV[1], (1,0,1) UV[2] [S2, unofficial].

### Fluid Surface Stitching
A mesh generation technique where fluid columns share a surface height field with neighbors, stitching surfaces when fluid IDs match [S1, unofficial]. Two adjacent fluid blocks join their surfaces only when their `FluidInfo::id` (u8) values are equal [S1, unofficial].

### Geometry Builder Pattern
A design pattern using an interface (`IGeometryBuilder`) to control the type of geometry created for each non-empty voxel, allowing different geometry types (cubes, ramps, X-shapes) to be generated via polymorphism without large switch statements [S3, unofficial]. The interface contains a single function `BuildGeometry()`, which is called once for each non-empty block during mesh creation [S3, unofficial]. It passes a reference to the chunk object, which uses this reference to add vertices and indices to the chunk's linked list [S3, unofficial]. After `BuildGeometry()` is called on every block for the chunk, the vertex and index data is placed into the engine's Mesh object on the main thread [S3, unofficial]. A key pitfall is that while vertex/index calculation is done on a background thread, the final Mesh object creation must be moved to the main thread to comply with engine threading rules [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(V)$ where $V$ is the number of voxels, as each voxel is processed once to determine its faces. The complexity of face generation depends on the shape (e.g., ramp is slightly more expensive than a cube).
*   **Memory Complexity:** $O(F)$ where $F$ is the number of generated faces. Transparent merging reduces $F$ significantly for large volumes of identical transparent blocks.
*   **Strengths:** Supports complex block types (fluids, slopes, partial blocks) without modifying the core meshing loop. Transparent merging reduces draw calls for glass/water.
*   **Limitations:** Requires careful implementation of shape generators to avoid artifacts. Threading constraints in some engines (like Unity) require careful management of mesh creation steps.
*   **When to Use:** When rendering heterogeneous voxel worlds with diverse block types (Minecraft-like) rather than uniform terrain.
*   **When Not to Use:** For simple, uniform voxel terrain where all blocks are identical cubes; the overhead of per-block configuration is unnecessary.

## Background
The concept of per-block configuration for meshing originated in voxel games like Minecraft, where different block types (glass, water, leaves) require different rendering behaviors. The specific trait-based implementation described in [S1, unofficial] and the geometry builder pattern in [S3, unofficial] are derived from modern voxel engine implementations aiming to balance flexibility and performance. The ramp shape geometry [S2, unofficial] is a common extension for terrain deformation.
