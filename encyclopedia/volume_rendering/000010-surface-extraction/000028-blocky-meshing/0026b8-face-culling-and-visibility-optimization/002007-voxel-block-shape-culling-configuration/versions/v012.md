# Voxel Block Shape & Culling Configuration

Also called: Block trait interface, Shape enum system

## Overview
Voxel Block Shape & Culling Configuration is a trait-based system that defines the geometry, transparency culling behavior, and lighting properties for individual block types in a voxel mesh generator [S1, unofficial]. It solves the problem of rigid, single-shape meshing by allowing different block types (e.g., glass, fluids, slopes) to specify their own mesh primitives and visibility rules [S1, unofficial]. Unlike generic face culling which applies uniform rules to all voxels, this method delegates shape and culling logic to the block type itself, enabling complex geometries and specialized rendering passes (e.g., fluid shaders) without modifying the core meshing algorithm [S1, unofficial][S3, unofficial].

## How it works
The system operates by associating a configuration object (trait) with each block type. This configuration determines the `Shape` (geometry), `CullMode` (visibility logic), and `Light` (lighting value) for that block.

### Inputs and Outputs
*   **Input:** A block type identifier (e.g., `MyBlock::Glass`) and the face normal being evaluated.
*   **Output:** A `Shape` enum instance defining vertices/indices, a `CullMode` enum instance defining culling logic, and a `u8` lighting value.

### Data Structures

**Block Trait Interface**
Each block type implements a trait (or interface) providing three methods:
1.  `shape(face: Face) -> Shape`: Returns the geometry for the given face.
2.  `cull_mode() -> CullMode`: Returns the culling strategy for the block type.
3.  `light(face: Face) -> u8`: Returns the lighting value for the given face.

**Shape Enum**
Represents the geometry of a block face. Variants include:
*   `WholeBlock`: Standard 6-face cube.
*   `Cross(CrossInfo)`: A cross-shaped geometry (e.g., for chains) defined by an aligned face and stretch value.
*   `Ramp`: A sloped geometry (see Subtopics).
*   `Fluid`: A surface-only geometry (see Subtopics).

**CullMode Enum**
Defines how faces are culled based on neighbor occupancy and transparency.
*   `Empty`: Block is air; no faces generated.
*   `Opaque`: Standard culling; shared faces with opaque neighbors are removed.
*   `TransparentMerged(T)`: Shared faces between two transparent blocks are culled if their `TransparentGroup` values match.
*   `TransparentUnmerged`: Shared faces are never culled between transparent blocks (always rendered).

**Vertex Layout**
Vertices generated by these shapes contain the following fields [S1, unofficial]:
*   `pos`: `Vec4<f32>` (Position)
*   `uv`: `Vec2<f32>` (Texture coordinates)
*   `normal`: `Vec3<f32>` (Surface normal)
*   `ao`: `f32` (Ambient Occlusion, 0.0=occluded, 1.0=lit)
*   `smooth_light`: `f32` (Smooth lighting value)
*   `block`: `MyBlock` (Block type identifier for render pass filtering)
*   `atlas_offset`: `f32` (Pre-computed atlas tile offset)
*   `two_sided`: `bool` (Whether the quad is two-sided)

### Numbered Steps

1.  **Initialize Mesh Builder:** Create a container for vertices and indices.
2.  **Iterate Voxels:** For each voxel in the chunk:
    a.  Retrieve the block type $B$.
    b.  Retrieve the configuration trait $T$ for $B$.
    c.  Call $T.cull\_mode()$ to get $C$.
    d.  If $C$ is `Empty`, skip to next voxel.
    e.  For each of the 6 faces $F$ of the voxel:
        i.  Check neighbor occupancy. If neighbor is solid and $C$ is `Opaque`, cull face $F$ [S1, unofficial].
        ii. If $C$ is `TransparentMerged(T)`, check if neighbor is transparent with matching group $T$. If so, cull face $F$.
        iii. If face $F$ is visible, call $T.shape(F)$ to get geometry $G$.
        iv. Call $T.light(F)$ to get lighting value $L$.
        v. Generate vertices/indices for $G$ using $L$ and other attributes.
3.  **Finalize:** Transfer vertex/index data to GPU buffers.

### Formulas

**Culling Condition for TransparentMerged**
A face between voxel $A$ and voxel $B$ is culled if:
$$ C_A = \text{TransparentMerged}(T_A) \land C_B = \text{TransparentMerged}(T_B) \land T_A = T_B $$
Where $T$ is the transparent group identifier [S1, unofficial].

**Frustum Culling for Blocks (Optional Optimization)**
For block-level culling, a block bounding box $[min, max]$ is inside the view frustum if it satisfies all 6 plane inequalities:
$$ \forall i \in \{0..5\}, \quad \mathbf{n}_i \cdot \mathbf{p} + d_i \ge 0 \quad \forall \mathbf{p} \in \{min, max\} $$
Where $\mathbf{n}_i, d_i$ are the normal and distance of the $i$-th frustum plane [S2, unofficial].

### Parameters
*   `FLUID_ENABLED`: Boolean flag. If `true`, fluid shapes are enabled. If `false` but fluid blocks exist, debug assertions may fail [S1, unofficial].
*   `TransparentGroup`: Identifier for merging transparent faces.

### Edge Cases and Pitfalls
*   **Fluid Shape Missing:** Setting `FLUID_ENABLED` to `true` without implementing the fluid shape geometry causes a debug assertion failure rather than silently rendering fluids as cubes [S1, unofficial].
*   **Threading Constraints:** In Unity3D environments, vertex/index calculation can occur on a background thread, but the final `Mesh` object creation must be performed on the main thread [S3, unofficial].
*   **Tint Fallback:** For ramp shapes, if a specific tint is `Vector3.One`, the system falls back to another face's tint [S2, unofficial].

### Pseudocode

```python
def generate_chunk_mesh(chunk: Chunk) -> Mesh:
    vertices = []
    indices = []
    
    for voxel_pos in chunk.voxels:
        block_type = chunk.get_block(voxel_pos)
        config = get_block_config(block_type)
        
        cull_mode = config.cull_mode()
        if cull_mode == CullMode.Empty:
            continue
            
        for face in [Face.NEG_X, Face.POS_X, Face.NEG_Y, Face.POS_Y, Face.NEG_Z, Face.POS_Z]:
            neighbor_pos = voxel_pos + face.normal
            neighbor_block = chunk.get_block(neighbor_pos)
            neighbor_config = get_block_config(neighbor_block)
            
            # Basic Opaque Culling
            if cull_mode == CullMode.Opaque and neighbor_config.cull_mode() == CullMode.Opaque:
                continue
                
            # Transparent Merged Culling
            if cull_mode == CullMode.TransparentMerged and neighbor_config.cull_mode() == CullMode.TransparentMerged:
                if cull_mode.group == neighbor_config.cull_mode.group:
                    continue
                    
            # Generate Geometry
            shape = config.shape(face)
            light_val = config.light(face)
            
            # Add vertices/indices for shape
            add_shape_to_mesh(vertices, indices, shape, voxel_pos, face, light_val, block_type)
            
    return Mesh(vertices, indices)
```

## Subtopics

### [Three-Valued Opacity Classification for Meshing](4414-three-valued-opacity-classification-for-meshing.md)
A classification system for block IDs into three mutually exclusive layers: 'opaque', 'water', and 'transparentSolid'. It solves the insufficiency of a single boolean 'transparent' flag by distinguishing between fluids (water) requiring bespoke shaders and see-through solids (glass/leaves) requiring alpha blending. Unlike a boolean transparent flag which collapses water and glass/leaves into one category, this three-valued model allows water to use a bespoke shader (ripple, refraction) while glass/leaves use the ordinary block atlas with alpha blending.

### Ramp Shape Geometry
A shape representing a sloped block face, composed of a slope quad (2 triangles) and two side triangles (left and right) [S2, unofficial]. Instance creation iterates visible faces; if the face is Left, Right, Top, or Front, `drawSlope` is set to true and tints are assigned (`tints[0]` for Top/Front, `tints[1]` for Left, `tints[2]` for Right). If a specific tint is `Vector3.One`, it falls back to another face's tint [S2, unofficial]. Slope vertices are defined as: (0,1,0) UV[0], (0,0,1) UV[1], (1,1,0) UV[2], (1,1,0) UV[3], (0,0,1) UV[4], (1,0,1) UV[5]. Left triangle vertices: (0,0,1) UV[0], (0,1,0) UV[1], (0,0,0) UV[2]. Right triangle vertices: (1,0,0) UV[0], (1,1,0) UV[1], (1,0,1) UV[2] [S2, unofficial].

### Fluid Surface Stitching
A mesh generation technique where fluid columns share a surface height field with neighbors, stitching surfaces when fluid IDs match [S1, unofficial]. Two adjacent fluid blocks join their surfaces only when their `FluidInfo::id` (u8) values are equal [S1, unofficial].

### Geometry Builder Pattern
A design pattern using an interface to control the type of geometry created for each non-empty voxel, allowing different geometry types (cubes, ramps, X-shapes) to be generated via polymorphism without large switch statements [S3, unofficial]. The interface `IGeometryBuilder` contains a single function `BuildGeometry()`. During mesh creation, `BuildGeometry()` is called once for each non-empty block, passing a reference to the chunk object. The builder adds vertices and indices to the chunk's linked list. After all blocks are processed, the data is placed into a Unity3D Mesh object on the main thread [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of voxels, as each voxel is processed once with constant-time trait lookups.
*   **Memory Complexity:** $O(N)$ for vertex/index storage, dependent on the number of visible faces.
*   **Strengths:** Highly flexible; supports complex geometries (ramps, fluids) and specialized rendering passes without core engine changes. Efficient culling reduces draw calls.
*   **Limitations:** Requires careful implementation of shape geometries to avoid assertion failures (e.g., fluids). Threading constraints in some engines (Unity3D) require careful management of mesh finalization [S3, unofficial].
*   **When to Use:** When voxel worlds require diverse block geometries (not just cubes) or specialized rendering effects (fluids, transparency merging).
*   **When Not to Use:** For simple voxel engines where all blocks are identical cubes and transparency is not a concern.

## Background
The trait-based configuration system originated in the `finnbear/voxmesh` project, providing a flexible way to define block geometry and culling [S1, unofficial]. The Geometry Builder pattern was introduced in the thesis "Procedural Generation of Voxel Worlds with Castles" to support complex shapes like Minecraft's stairs and slabs without large switch statements [S3, unofficial]. Ramp shapes and fluid stitching were implemented in the `rarefushion/Cubic-Grid_Voxel_Renderer` to handle sloped terrain and water surfaces [S2, unofficial].
