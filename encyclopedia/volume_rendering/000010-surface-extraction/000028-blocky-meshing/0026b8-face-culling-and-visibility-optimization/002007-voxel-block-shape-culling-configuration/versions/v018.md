# Voxel Block Shape & Culling Configuration

Also called: Block trait interface, Shape enum system

## Overview
Voxel Block Shape & Culling Configuration is a trait-based system that defines block geometry, transparency culling rules, and lighting properties per block type [S1, unofficial]. It solves the problem of rigid, single-shape voxel meshes by allowing distinct geometric representations (e.g., ramps, fluids, thin structures) and specialized face-culling behaviors (e.g., merging transparent faces) to be declared alongside the voxel data [S1, unofficial]. It differs from sibling methods like [Face Coverage Mask Culling](3397-face-coverage-mask-culling.md) by decoupling the *definition* of a block's visual and culling properties from the mesh generation loop, enabling polymorphic geometry generation [S3, unofficial].

## How it works
**Inputs:** A voxel grid (or chunk) containing block identifiers; a configuration registry mapping block IDs to their shape, cull mode, and lighting parameters.
**Outputs:** A list of vertices and indices for the mesh, where each vertex carries per-vertex attributes (position, UV, normal, AO, smooth light, block ID, atlas offset, two-sided flag) [S1, unofficial].

**Data Structures:**
1.  **Block Trait/Registry:** A mapping from Block ID to a configuration struct containing:
    *   `Shape`: Enum or struct defining geometry (e.g., `WholeBlock`, `Cross`, `Ramp`).
    *   `CullMode`: Enum defining culling behavior (e.g., `Empty`, `Opaque`, `TransparentMerged`, `TransparentUnmerged`).
    *   `Light`: Lighting value(s) for the block or specific faces.
2.  **Vertex:** A struct containing:
    *   `pos`: `Vec4<f32>` (position).
    *   `uv`: `Vec2<f32>` (texture coordinates).
    *   `normal`: `Vec3<f32>` (surface normal).
    *   `ao`: `f32` (ambient occlusion, 0.0=occluded, 1.0=lit).
    *   `smooth_light`: `f32` (smooth lighting value).
    *   `block`: Block ID (for render pass filtering).
    *   `atlas_offset`: `f32` (pre-computed atlas tile offset).
    *   `two_sided`: `bool` (flag for two-sided quads).
    [S1, unofficial]
3.  **Geometry Builder Interface:** An interface `IGeometryBuilder` with a single method `BuildGeometry(chunk_ref)` [S3, unofficial].

**Steps:**
1.  **Configuration Lookup:** For each non-empty voxel at position $P$ with block ID $B$, retrieve its configuration from the registry.
2.  **Shape Determination:** Determine the `Shape` of block $B$.
    *   If $B$ is a standard cube, use `WholeBlock`.
    *   If $B$ is a thin structure (e.g., chain, rail), use `Cross` or similar, specifying the `AlignedFace` and `stretch` [S1, unofficial].
    *   If $B$ is a fluid, use `Fluid` shape logic.
    *   If $B$ is a ramp, use `Ramp` shape logic.
3.  **Culling Decision:** Determine the `CullMode` for block $B$.
    *   `Empty`: No mesh generated.
    *   `Opaque`: Standard culling; faces are visible if the neighbor is air.
    *   `TransparentMerged(T)`: Faces between two transparent blocks are culled if their `TransparentGroup` values are equal [S1, unofficial].
    *   `TransparentUnmerged`: Faces are never merged with neighbors, even if both are transparent.
4.  **Geometry Generation:**
    *   Call `BuildGeometry()` on the appropriate `IGeometryBuilder` instance for block $B$, passing a reference to the chunk [S3, unofficial].
    *   The builder iterates through the 6 cardinal directions (Up, Down, Left, Right, Front, Back).
    *   For each direction, check if the face is exposed based on the `CullMode` and neighbor status.
    *   If exposed, generate vertices and indices for the specific shape (e.g., cube face, ramp slope, fluid surface).
    *   Assign vertex attributes:
        *   `pos`: Derived from shape geometry.
        *   `uv`: Derived from texture atlas.
        *   `normal`: Derived from face orientation.
        *   `ao`, `smooth_light`: Derived from block lighting configuration and neighbor occlusion [S1, unofficial].
        *   `block`: Set to $B$.
    *   Add vertices and indices to the chunk's linked list [S3, unofficial].
5.  **Mesh Assembly:** After processing all voxels in the chunk, transfer the linked list data to a GPU mesh object on the main thread [S3, unofficial].

**Formulas:**
*   **Culling for TransparentMerged:**
    $$ \text{Visible}(A, B) = \neg (\text{IsTransparent}(A) \land \text{IsTransparent}(B) \land \text{Group}(A) == \text{Group}(B)) $$
    Where $\text{Group}(A)$ is the `TransparentGroup` value for block $A$ [S1, unofficial].
*   **Lighting for Cactus (Example):**
    $$ L_{face} = \begin{cases} 11.0 & \text{if } face = \text{PosY} \\ 12.0 & \text{if } face = \text{NegY} \\ 10.0 & \text{otherwise} \end{cases} $$
    [S1, unofficial]

**Parameters:**
*   `FLUID_ENABLED`: Boolean flag. If true, fluid geometry is generated. If false, fluids are treated as air or cubes depending on implementation [S1, unofficial].
*   `TransparentGroup`: Integer or enum value for transparent blocks. Default is often 0 or 1 [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Fluid Shape Missing:** Setting `FLUID_ENABLED` to true without implementing the fluid shape logic causes a debug assertion failure rather than silently drawing fluids as cubes [S1, unofficial].
*   **Threading:** Unity3D mesh creation functions must be called on the main thread. Vertex/index calculation can be done on a background thread, but the final mesh assembly must be moved to the main thread [S3, unofficial].
*   **Tint Fallback:** For ramp shapes, if a specific tint is `Vector3.One`, fallback to another face's tint [S2, unofficial].

**Pseudocode:**
```python
def generate_chunk_mesh(chunk):
    """
    Generates the mesh for a chunk using block traits and geometry builders.
    """
    vertices = []
    indices = []
    
    # Iterate through all voxels in the chunk
    for x, y, z in chunk.voxels:
        block_id = chunk.get_block(x, y, z)
        
        # Skip empty blocks
        if block_id == BlockID.AIR:
            continue
            
        # Get block configuration
        config = block_registry.get_config(block_id)
        
        # Get geometry builder for this block type
        builder = get_geometry_builder(config.shape)
        
        # Call builder to generate geometry for this block
        # The builder will add vertices/indices to the chunk's lists
        builder.build_geometry(chunk, x, y, z, config, vertices, indices)
        
    # After all blocks processed, create final mesh object
    # This must be done on the main thread in Unity3D
    mesh = create_mesh_from_lists(vertices, indices)
    return mesh

def build_geometry_cube(chunk, x, y, z, config, vertices, indices):
    """
    Standard cube geometry builder.
    """
    for face in [UP, DOWN, LEFT, RIGHT, FRONT, BACK]:
        neighbor = chunk.get_block_at(x, y, z, face)
        
        # Determine culling
        if is_culled(config.cull_mode, config, neighbor):
            continue
            
        # Generate 4 vertices for the face
        face_vertices = get_face_vertices(face, x, y, z)
        face_indices = get_face_indices()
        
        # Assign attributes
        for v in face_vertices:
            v.normal = get_face_normal(face)
            v.uv = get_face_uv(face)
            v.ao = calculate_ao(v, chunk, x, y, z)
            v.smooth_light = config.light.get(face)
            v.block = config.id
            vertices.append(v)
            
        indices.extend(face_indices)

def is_culled(cull_mode, config, neighbor):
    """
    Determines if a face should be culled based on cull mode.
    """
    if cull_mode == CullMode.EMPTY:
        return True
    elif cull_mode == CullMode.OPAQUE:
        return neighbor != BlockID.AIR
    elif cull_mode == CullMode.TRANSPARENT_MERGED:
        if neighbor == BlockID.AIR:
            return False
        neighbor_config = block_registry.get_config(neighbor)
        if neighbor_config.is_transparent and config.is_transparent:
            if config.transparent_group == neighbor_config.transparent_group:
                return True
        return False
    elif cull_mode == CullMode.TRANSPARENT_UNMERGED:
        return neighbor != BlockID.AIR
    return False
```

## Subtopics

### [Three-Valued Opacity Classification for Meshing](4414-three-valued-opacity-classification-for-meshing.md)
A classification system for block IDs into three mutually exclusive layers ('opaque', 'water', 'transparentSolid') to determine rendering material and buffer assignment. It solves the insufficiency of a single boolean 'transparent' flag by distinguishing between fluids (water) requiring bespoke shaders and see-through solids (glass/leaves) requiring alpha blending. Unlike a boolean transparent flag which collapses water and glass/leaves into one category, this three-valued model allows water to use a bespoke shader (ripple, refraction) while glass/leaves use the ordinary block atlas with alpha blending.

### Ramp Shape Geometry
A shape representing a sloped block face, composed of a slope quad (2 triangles) and two side triangles (left and right) [S2, unofficial]. Instance creation involves iterating visible faces; if the face is Left, Right, Top, or Front, `drawSlope` is set to true and tint is assigned based on face type (`tints[0]` for Top/Front, `tints[1]` for Left, `tints[2]` for Right). If a specific tint is `Vector3.One`, it falls back to another face's tint. Instances are added for slope, left triangle, and right triangle using respective shape IDs and tints. For Back or Bottom faces, instances are added using `cubeBackFaceShapeID` or `cubeBottomFaceShapeID` [S2, unofficial]. Slope vertices are: (0,1,0) UV[0], (0,0,1) UV[1], (1,1,0) UV[2], (1,1,0) UV[3], (0,0,1) UV[4], (1,0,1) UV[5]. Left triangle vertices: (0,0,1) UV[0], (0,1,0) UV[1], (0,0,0) UV[2]. Right triangle vertices: (1,0,0) UV[0], (1,1,0) UV[1], (1,0,1) UV[2] [S2, unofficial].

### Fluid Surface Stitching
A mesh generation technique where fluid columns share a surface height field with neighbors, stitching surfaces when fluid IDs match [S1, unofficial]. Two adjacent fluid blocks join their surfaces only when their `FluidInfo::id` (u8) values match [S1, unofficial].

### Geometry Builder Pattern
A design pattern using an interface to control the type of geometry created for each non-empty voxel, allowing different geometry types (cubes, ramps, X-shapes) to be generated via polymorphism without large switch statements [S3, unofficial]. During mesh creation, `BuildGeometry()` is called once for each non-empty block, passing a reference to the chunk object. Inside `BuildGeometry()`, vertices and indices are added to the chunk's linked list. After all blocks are processed, the data is placed into a Unity3D Mesh object on the main thread [S3, unofficial]. The interface `IGeometryBuilder` contains a single function `BuildGeometry()` [S3, unofficial]. Pitfall: Unity3D functions must be called on the main thread; vertex/index calculation can be done on a background thread, but final mesh creation must be on the main thread [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of voxels in the chunk, as each voxel is processed once [S3, unofficial].
*   **Memory Complexity:** $O(V + I)$ where $V$ is the number of vertices and $I$ is the number of indices generated [S3, unofficial].
*   **Performance:** Depends on the number of exposed faces and the complexity of the shapes. Simple cubes are fast; ramps and fluids require more complex vertex generation [S2, unofficial].
*   **Strengths:** Flexible geometry support; decoupled configuration; efficient culling for transparent blocks [S1, unofficial].
*   **Limitations:** Requires careful handling of threading in engines like Unity3D [S3, unofficial]; potential for assertion failures if shapes are not fully implemented [S1, unofficial].
*   **When to use:** When voxel worlds require diverse block shapes (ramps, fluids, thin structures) and different rendering behaviors (transparency merging) [S1, unofficial].
*   **When not to use:** For simple, uniform voxel worlds where all blocks are cubes and have the same rendering properties [S3, unofficial].

## Background
Originated in implementations like `finnbear/voxmesh` and `rarefushion/Cubic-Grid_Voxel_Renderer` as a way to handle complex voxel geometries and rendering states [S1, unofficial][S2, unofficial]. The Geometry Builder pattern was formalized in academic work on procedural voxel generation, such as the "VoxBox" project, to support diverse block types without code bloat [S3, unofficial]. It is widely used in voxel game engines and terrain rendering systems that require more than simple cube meshes [S1, unofficial][S3, unofficial].
