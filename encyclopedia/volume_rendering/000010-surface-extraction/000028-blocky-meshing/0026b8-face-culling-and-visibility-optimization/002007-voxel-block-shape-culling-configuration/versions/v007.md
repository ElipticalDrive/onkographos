# Voxel Block Shape & Culling Configuration

Also called: Block trait interface, Shape enum system

## Overview
This method defines the geometric and rendering properties of individual voxel types within a blocky meshing pipeline. It solves the problem of mapping abstract block IDs to specific 3D geometry, transparency behaviors, and lighting values, enabling correct face culling and material assignment. It differs from sibling methods like [Boolean Voxel Meshing](971-boolean-voxel-meshing.md) by supporting complex, non-cube shapes and multi-layer transparency classification, and from [Task Shader Cell Classification](1535-task-shader-cell-classification.md) by operating as a configuration trait rather than a classification algorithm.

## How it works
### Inputs and Outputs
- **Input**: A block identifier (e.g., `MyBlock` enum) and a face orientation (e.g., `AlignedFace`).
- **Output**: A `Shape` enum value defining geometry, a `CullMode` enum defining transparency behavior, and a `light` value for illumination.

### Data Structures
The configuration is typically implemented via a trait or interface that maps block types to properties.

**Shape Enum**
Defines the geometry of a block face.
- `WholeBlock`: Standard 1x1x1 cube.
- `Cross(CrossInfo)`: A cross-shaped geometry (e.g., for chains).
  - `face`: The aligned face direction (`PosZ`, etc.).
  - `stretch`: Stretch factor (e.g., `0`).
- `Ramp`: Sloped geometry (see Subtopics).

**CullMode Enum**
Defines how faces are culled based on transparency.
- `Empty`: No geometry generated.
- `Opaque`: Standard opaque culling.
- `TransparentMerged(T)`: Culls shared faces between two transparent blocks if their `TransparentGroup` values are equal. Does not replace `PartialEq` for greedy meshing.
- `TransparentUnmerged`: Transparent blocks do not merge faces with neighbors, even if identical.

**Vertex Layout**
Vertices generated by the shape configuration include:
- `pos`: `Vec4<f32>` position.
- `uv`: `Vec2<f32>` texture coordinates.
- `normal`: `Vec3<f32>` surface normal.
- `ao`: `f32` Ambient Occlusion (0.0 = fully occluded, 1.0 = fully lit).
- `smooth_light`: `f32` Smooth lighting value (0.0..1.0).
- `block`: Block identifier for render pass filtering.
- `atlas_offset`: `f32` Pre-computed atlas tile offset.
- `two_sided`: `bool` Whether the vertex belongs to a two-sided quad.

**Interpolated Vertex-to-Fragment Data (`VsOut`)**
- `uv`: `Vec2<f32>`
- `normal`: `Vec3<f32>`
- `atlas_u_offset`: `f32`
- `ao`: `f32`
- `smooth_light`: `f32`

### Steps
1. **Block Identification**: Determine the block type for the voxel at the current coordinate.
2. **Shape Resolution**: Query the block's shape configuration.
   - If `MyBlock::Air`, return `CullMode::Empty`.
   - If `MyBlock::Cobblestone`, `Clay`, `CobbleSlab`, `Debug`, or `Lamp`, return `CullMode::Opaque`.
   - If `MyBlock::Glass`, return `CullMode::TransparentMerged(())`.
   - If `MyBlock::Cactus`, `SugarCane`, `Cobweb`, `Shrub`, `Ladder`, `Rail`, `ChainY`, `ChainX`, `ChainZ`, or `Leaves`, return `CullMode::TransparentUnmerged`.
3. **Geometry Generation**:
   - For `WholeBlock`, generate standard cube faces.
   - For `Cross`, generate the cross geometry defined in `CrossInfo`.
   - For `Ramp`, generate slope quads and side triangles (see Subtopics).
4. **Lighting Assignment**: Assign a lighting value based on block type and face orientation.
   - `Air`: 0.0
   - `Cobblestone`, `Clay`, etc.: 1.0
   - `Glass`: 2.0
   - `Leaves`: 3.0
   - `SugarCane`: 4.0
   - `Cobweb`: 5.0
   - `Shrub`: 6.0
   - `Ladder`: 7.0
   - `Rail`: 8.0
   - `Debug`: 9.0
   - `Cactus`: 10.0 (default), 11.0 (PosY), 12.0 (NegY)
   - `ChainY/X/Z`: 13.0
   - `Lamp`: 14.0

### Pseudocode
```python
def get_block_config(block: MyBlock, face: AlignedFace) -> BlockConfig:
    """
    Returns the shape, cull mode, and lighting for a given block and face.
    """
    # Shape Resolution
    if block == MyBlock.Air:
        shape = Shape.Empty
        cull_mode = CullMode.Empty
    elif block in [MyBlock.Cobblestone, MyBlock.Clay, MyBlock.CobbleSlab, MyBlock.Debug, MyBlock.Lamp]:
        shape = Shape.WholeBlock
        cull_mode = CullMode.Opaque
    elif block == MyBlock.Glass:
        shape = Shape.WholeBlock
        cull_mode = CullMode.TransparentMerged(())
    elif block in [MyBlock.Cactus, MyBlock.SugarCane, MyBlock.Cobweb, MyBlock.Shrub, 
                   MyBlock.Ladder, MyBlock.Rail, MyBlock.ChainY, MyBlock.ChainX, 
                   MyBlock.ChainZ, MyBlock.Leaves]:
        shape = Shape.WholeBlock # Or specific shape like Cross for chains
        cull_mode = CullMode.TransparentUnmerged
    else:
        shape = Shape.WholeBlock
        cull_mode = CullMode.Opaque

    # Special Shape Handling (e.g., Chains)
    if block in [MyBlock.ChainY, MyBlock.ChainX, MyBlock.ChainZ]:
        axis = get_axis(block) # Y, X, or Z
        shape = Shape.Cross(CrossInfo(face=face, stretch=0))

    # Lighting Assignment
    light = 0.0
    if block == MyBlock.Air:
        light = 0.0
    elif block == MyBlock.Glass:
        light = 2.0
    elif block == MyBlock.Leaves:
        light = 3.0
    elif block == MyBlock.SugarCane:
        light = 4.0
    elif block == MyBlock.Cobweb:
        light = 5.0
    elif block == MyBlock.Shrub:
        light = 6.0
    elif block == MyBlock.Ladder:
        light = 7.0
    elif block == MyBlock.Rail:
        light = 8.0
    elif block == MyBlock.Debug:
        light = 9.0
    elif block == MyBlock.Cactus:
        if face == AlignedFace.PosY:
            light = 11.0
        elif face == AlignedFace.NegY:
            light = 12.0
        else:
            light = 10.0
    elif block in [MyBlock.ChainY, MyBlock.ChainX, MyBlock.ChainZ]:
        light = 13.0
    elif block == MyBlock.Lamp:
        light = 14.0
    else:
        light = 1.0 # Default for Opaque blocks like Cobblestone

    return BlockConfig(shape=shape, cull_mode=cull_mode, light=light)
```

### Parameters
- `FLUID_ENABLED`: Boolean flag. If set to `true` without implementing fluid shape, causes debug assertion failure rather than silently drawing fluids as cubes [S1, unofficial].

### Edge Cases and Pitfalls
- **Fluid Assertion Failure**: Setting `FLUID_ENABLED` to `true` without implementing the corresponding fluid shape logic results in a debug assertion failure [S1, unofficial].
- **Transparent Merging**: `CullMode::TransparentMerged(T)` culls shared faces between two transparent blocks only when their `TransparentGroup` values are equal. It does not replace `PartialEq` for greedy meshing, meaning greedy meshing may still treat them as distinct if equality is not properly defined [S1, unofficial].

## Subtopics

### [Three-Valued Opacity Classification for Meshing](4414-three-valued-opacity-classification-for-meshing.md)
A classification system for block IDs into three mutually exclusive layers ('opaque', 'water', 'transparentSolid') to determine rendering material and buffer assignment. It solves the insufficiency of a single boolean 'transparent' flag by distinguishing between fluids (water) requiring bespoke shaders and see-through solids (glass/leaves) requiring alpha blending. Unlike a boolean transparent flag which collapses water and glass/leaves into one category, this three-valued model allows water to use a bespoke shader (ripple, refraction) while glass/leaves use the ordinary block atlas with alpha blending.

### Ramp Shape Geometry
A shape representing a sloped block face, composed of a slope quad (2 triangles) and two side triangles (left and right) [S2, unofficial].
- **Instance Creation**: Iterate visible faces. If face is Left, Right, Top, or Front, set `drawSlope = true` and assign tint to `tints[0]` (Top/Front), `tints[1]` (Left), or `tints[2]` (Right). If a specific tint is `Vector3.One`, fallback to another face's tint. Add instances for slope, left triangle, and right triangle using respective shape IDs and tints. If face is Back or Bottom, add instance using `cubeBackFaceShapeID` or `cubeBottomFaceShapeID` [S2, unofficial].
- **Layout**:
  - Slope vertices (6 vertices): (0,1,0) with UV[0], (0,0,1) with UV[1], (1,1,0) with UV[2], (1,1,0) with UV[3], (0,0,1) with UV[4], (1,0,1) with UV[5] [S2, unofficial].
  - Left triangle vertices (3 vertices): (0,0,1) with UV[0], (0,1,0) with UV[1], (0,0,0) with UV[2] [S2, unofficial].
  - Right triangle vertices (3 vertices): (1,0,0) with UV[0], (1,1,0) with UV[1], (1,0,1) with UV[2] [S2, unofficial].

### Fluid Surface Stitching
A mesh generation technique where fluid columns share a surface height field with neighbors, stitching surfaces when fluid IDs match [S1, unofficial].
- **Parameter**: `FluidInfo::id: u8` - Two adjacent fluid blocks join their surfaces only when their ids match [S1, unofficial].

### Geometry Builder Pattern
A design pattern using an interface to control the type of geometry created for each non-empty voxel, allowing different geometry types (cubes, ramps, X-shapes) to be generated via polymorphism without large switch statements [S3, unofficial].
- **Steps**:
  1. During mesh creation, call `BuildGeometry()` once for each non-empty block [S3, unofficial].
  2. Pass a reference to the chunk object to `BuildGeometry()` [S3, unofficial].
  3. Inside `BuildGeometry()`, use the chunk reference to add vertices and indices to the chunk's linked list [S3, unofficial].
  4. After `BuildGeometry()` has been called on every block for the chunk, place the vertex and index data into a Unity3D Mesh object on the main thread [S3, unofficial].
- **Layout**: Interface `IGeometryBuilder` contains a single function: `BuildGeometry()` [S3, unofficial].
- **Pitfall**: Unity3D functions must be called on the main thread. While vertex/index calculation is done on a background thread, the final Mesh object creation must be moved to the main thread [S3, unofficial].

## Operating characteristics
- **Time Complexity**: O(N) where N is the number of voxels, as each voxel's configuration is queried once.
- **Memory Complexity**: O(1) per block type for configuration data; O(V) for generated vertices where V is the number of visible faces.
- **Strengths**: Flexible support for complex shapes (ramps, chains) and nuanced transparency handling (fluids vs. glass).
- **Limitations**: Requires careful implementation of shape builders to avoid assertion failures (e.g., fluids). Threading constraints in engines like Unity3D require main-thread mesh assembly.
- **When to Use**: When blocky meshing requires more than simple cubes and nuanced transparency (e.g., water vs. glass).
- **When Not to Use**: For simple voxel worlds where all blocks are opaque cubes, or when performance constraints prevent per-block configuration lookups.

## Background
Originating from implementations like `finnbear/voxmesh` [S1, unofficial] and academic projects like "Procedural Generation of Voxel Worlds with Castles" [S3, unofficial], this method evolved to support complex voxel games (e.g., Minecraft-like) where block geometry and transparency vary significantly. It addresses the limitations of simple boolean transparency flags by introducing trait-based configuration and multi-layer opacity classification.
