# Voxel Block Shape & Culling Configuration

Also called: Block trait interface, Shape enum system

## Overview
This method defines the geometric and rendering properties of individual voxel types within a blocky meshing pipeline. It solves the problem of heterogeneous block rendering by mapping each block ID to a specific shape geometry, a transparency culling mode, and a lighting value [S1, unofficial]. It sets itself apart from sibling methods like [Boolean Voxel Meshing](971-boolean-voxel-meshing.md) by supporting complex, non-cubic geometries (e.g., ramps, fluids) and fine-grained culling strategies (e.g., merging transparent groups) rather than a simple opaque/transparent binary [S1, unofficial][S3, unofficial].

## How it works
The configuration is typically implemented as a trait or interface system where each block type returns specific metadata used during mesh generation.

### Inputs and Outputs
*   **Input:** Block ID (e.g., `MyBlock::Glass`, `MyBlock::Water`).
*   **Output:** A configuration struct or interface implementation containing:
    *   `Shape`: The geometric primitive(s) to generate.
    *   `CullMode`: The face culling rule.
    *   `Light`: The lighting value for shading.

### Data Structures

#### Shape Enum
Defines the geometry for a block. Common variants include:
*   `WholeBlock`: A standard 6-face cube.
*   `Cross`: A specific shape variant (e.g., for chains) defined by an `AlignedFace` and `stretch` value [S1, unofficial].
*   `Ramp`: A sloped block composed of a slope quad and side triangles [S2, unofficial].
*   `Fluid`: A surface-only geometry [S3, unofficial].

#### CullMode Enum
Determines how faces are culled based on neighbor transparency.
*   `Empty`: No faces generated (e.g., Air) [S1, unofficial].
*   `Opaque`: Faces are never culled against neighbors; always rendered [S1, unofficial].
*   `TransparentUnmerged`: Faces are rendered if the neighbor is not the same block type. Shared faces between two transparent blocks are **not** culled [S1, unofficial].
*   `TransparentMerged(T)`: Faces are culled if the neighbor is transparent AND has an equal `TransparentGroup` value `T`. This allows merging of identical transparent surfaces (e.g., water) while keeping distinct transparent types (e.g., glass) separate [S1, unofficial].

### Steps for Mesh Generation

1.  **Iterate Voxel Chunk:** For each non-empty voxel in the chunk.
2.  **Retrieve Configuration:** Call the block's trait methods to get `Shape`, `CullMode`, and `Light` [S1, unofficial].
3.  **Check Culling:** For each of the 6 faces:
    *   If `CullMode` is `Empty`, skip.
    *   If `CullMode` is `Opaque`, generate face.
    *   If `CullMode` is `TransparentUnmerged`, generate face if neighbor is not identical block type.
    *   If `CullMode` is `TransparentMerged(T)`, generate face if neighbor is not transparent OR neighbor's `TransparentGroup` != `T` [S1, unofficial].
4.  **Build Geometry:** Call `BuildGeometry()` on the appropriate `IGeometryBuilder` interface implementation [S3, unofficial].
    *   The builder adds vertices and indices to the chunk's linked list.
    *   For `Ramp` shapes, iterate visible faces. If face is Left, Right, Top, or Front, set `drawSlope = true` and assign tints [S2, unofficial].
    *   For `Fluid` shapes, only generate top faces or stitch surfaces with neighbors if `FluidInfo::id` matches [S1, unofficial][S3, unofficial].
5.  **Finalize Mesh:** After all blocks are processed, transfer the vertex/index linked list data to the GPU mesh object on the main thread [S3, unofficial].

### Pseudocode

> **Unverified code.** The code below did not pass a test run against a reference implementation, or no test fits it, so it may contain errors.

```python
def generate_chunk_mesh(chunk):
    vertices = []
    indices = []
    
    for block_pos in chunk.non_empty_blocks():
        block_type = chunk.get_block(block_pos)
        
        # 1. Retrieve configuration
        shape = block_type.get_shape()
        cull_mode = block_type.get_cull_mode()
        light_val = block_type.get_light()
        
        # 2. Iterate faces
        for face in [Front, Back, Left, Right, Top, Bottom]:
            neighbor_pos = block_pos + face.normal
            neighbor_type = chunk.get_block(neighbor_pos)
            
            # 3. Culling Logic
            if cull_mode == CullMode.Empty:
                continue
            elif cull_mode == CullMode.Opaque:
                should_render = True
            elif cull_mode == CullMode.TransparentUnmerged:
                should_render = (neighbor_type != block_type)
            elif cull_mode == CullMode.TransparentMerged:
                # T is the transparent group ID
                if neighbor_type.is_transparent() and neighbor_type.transparent_group == block_type.transparent_group:
                    should_render = False
                else:
                    should_render = True
            else:
                should_render = False # Default fallback
            
            if should_render:
                # 4. Build Geometry
                builder = get_geometry_builder(shape)
                builder.build_geometry(
                    block_pos=block_pos,
                    face=face,
                    block_type=block_type,
                    light_val=light_val,
                    vertices=vertices,
                    indices=indices
                )
                
    # 5. Finalize
    return create_mesh_from_linked_list(vertices, indices)
```

### Parameters and Typical Values
*   **TransparentGroup (T):** An integer or enum ID assigned to transparent blocks. Water blocks typically share one ID; Glass blocks another [S1, unofficial].
*   **FluidInfo::id:** A `u8` value. Adjacent fluid blocks join surfaces only if IDs match [S1, unofficial].
*   **Light Values:** Floats from 0.0 to 14.0. Air is 0.0; Opaque blocks are 1.0; Transparent blocks vary (Glass 2.0, Leaves 3.0) [S1, unofficial].

### Edge Cases and Pitfalls
*   **Fluid Shape Missing:** Setting `FLUID_ENABLED` to true without implementing the fluid shape builder causes a debug assertion failure, not silent cube rendering [S1, unofficial].
*   **Threading Constraints:** In Unity3D environments, vertex/index calculation can occur on a background thread, but the final `Mesh` object creation must occur on the main thread [S3, unofficial].
*   **Ramp Tint Fallback:** If a specific tint for a ramp face is `Vector3.One`, it must fallback to another face's tint to avoid visual artifacts [S2, unofficial].

## Subtopics

### [Three-Valued Opacity Classification for Meshing](4414-three-valued-opacity-classification-for-meshing.md)
A classification system that divides block IDs into three mutually exclusive layers: 'opaque', 'water', and 'transparentSolid'. It distinguishes between fluids (water), which require bespoke shaders (refraction/ripple), and see-through solids (glass/leaves), which use alpha blending with the standard block atlas. This solves the insufficiency of a single boolean 'transparent' flag which would collapse water and glass into one category.

### Ramp Shape Geometry
A shape representing a sloped block face, composed of a slope quad (2 triangles) and two side triangles (left and right) [S2, unofficial]. It requires specific vertex layouts: Slope (6 vertices), Left Triangle (3 vertices), and Right Triangle (3 vertices) with defined UV mappings [S2, unofficial]. Instance creation iterates visible faces (Left, Right, Top, Front) to assign slopes and tints, while Back/Bottom faces use standard cube IDs [S2, unofficial].

### Fluid Surface Stitching
A mesh generation technique where fluid columns share a surface height field with neighbors [S1, unofficial]. Surfaces are stitched when adjacent fluid blocks have matching `FluidInfo::id` values [S1, unofficial]. Only top faces are typically created for water blocks, with indices stored separately [S3, unofficial].

### Geometry Builder Pattern
A design pattern using an `IGeometryBuilder` interface to control geometry creation for non-empty voxels via polymorphism [S3, unofficial]. The interface contains a single `BuildGeometry()` function called once per block [S3, unofficial]. It allows support for diverse geometries (cubes, ramps, X-shapes) without large switch statements [S3, unofficial]. Implementations include `BoxBuilder`, `WaterBuilder`, and `MicroBlockBuilder` [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of voxels, as each voxel is processed once to determine face visibility and geometry [S3, unofficial].
*   **Memory Complexity:** Proportional to the number of visible faces. The use of `TransparentMerged` culling reduces memory usage for large homogeneous transparent areas (like water) by merging shared faces [S1, unofficial].
*   **Strengths:** Supports complex, non-cubic shapes (ramps, fluids) and fine-grained rendering control (distinct shaders for water vs. glass) [S1, unofficial][S3, unofficial].
*   **Limitations:** Requires careful implementation of shape builders; missing implementations cause crashes [S1, unofficial]. Threading constraints in some engines (Unity3D) require careful main-thread synchronization for mesh finalization [S3, unofficial].

## Background
This configuration system originated in voxel engine implementations aiming to replicate Minecraft-like features with more complex geometry than simple cubes [S3, unofficial]. It evolved from basic boolean transparency checks to trait-based interfaces to support heterogeneous block types and advanced culling strategies [S1, unofficial][S3, unofficial]. It is commonly used in voxel engines requiring fluid simulation, sloped terrain, and varied material rendering [S1, unofficial][S2, unofficial][S3, unofficial].
