# Dynamic Block Mesh Management

Also called: Dynamic Index Buffer Updating

## Overview
Dynamic Block Mesh Management is a technique for maintaining a dynamic list of block indices organized by spatial coordinates, allowing for the efficient addition and removal of individual block faces without rebuilding the entire mesh [S1, unofficial]. It solves the problem of high computational cost associated with regenerating voxel meshes upon every block placement or removal by updating only the affected local geometry [S1, unofficial]. It sets itself apart from [Static Mesh Caching](1138-static-mesh-caching.md) by actively modifying the index buffer in real-time to reflect state changes, rather than relying on pre-computed static data [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Block coordinates $(x, y, z)$, a boolean flag `add` indicating insertion or removal, and vertex indices for the face geometry.
*   **Output:** Updated vertex index arrays and spatial position arrays reflecting the current state of the voxel chunk.

**Data Structures:**
The method relies on three primary data structures:
1.  `blocksX`, `blocksY`, `blocksZ`: Arrays storing block positions along each axis. These are used for spatial indexing.
2.  `blocksData`: A dictionary (hash map) mapping string keys formatted as `'x,y,z'` to arrays of vertex indices. Each entry in the array represents a face (6 indices).
3.  `vertexSlots`: A stack used to manage vertex slot reuse, optimizing memory usage by recycling unused vertex indices [S1, unofficial].

**Numbered Steps:**

1.  **Initialize Spatial Indexing:**
    When adding a block, check if the block's coordinates $(x, y, z)$ already exist in the spatial position arrays. If not, insert them in sorted order to maintain spatial locality.
    *   For the X-axis: Iterate through `blocksX` to find the correct insertion point for $x$.
    *   For the Y-axis: Iterate through `blocksY` to find the correct insertion point for $y$.
    *   For the Z-axis: Iterate through `blocksZ` to find the correct insertion point for $z$.
    *   [G] Ensure arrays are sorted to allow binary search or efficient linear scan insertion.

2.  **Access or Create Block Data:**
    Construct the key `pos = "x,y,z"`.
    *   If `add` is true:
        *   Check if `pos` exists in `blocksData`.
        *   If not, initialize `blocksData[pos] = []` (an empty list of indices).
        *   Call the spatial update function to ensure coordinates are in `blocksPos` (derived from `blocksX/Y/Z`).
    *   If `add` is false:
        *   Retrieve `indices = blocksData[pos]`. If undefined, the block does not exist; handle as error or no-op.

3.  **Update Indices:**
    *   **Add Face:**
        *   Generate the 6 vertex indices for the square face: $[a, b, c, c, d, a]$.
        *   Append these indices to `blocksData[pos]`.
        *   Increment the global `indicesLength` by 6.
    *   **Remove Face:**
        *   Find the specific 6 indices in `blocksData[pos]` that correspond to the face being removed.
        *   Remove these 6 indices from the array.
        *   Decrement `indicesLength` by 6.

4.  **Cleanup Empty Blocks:**
    *   After removal, check if `blocksData[pos]` is empty.
    *   If empty, remove the entry from `blocksData`.
    *   Remove the block's coordinates from the spatial position arrays (`blocksX`, `blocksY`, `blocksZ`).
    *   [G] If the spatial arrays become empty, clear the entire structure.

5.  **Vertex Slot Management:**
    *   When adding new vertices (if vertex positions are also managed dynamically), pop the last used vertex index from `vertexSlots` to reuse the slot, ensuring compact memory usage [S1, unofficial].

**Pseudocode:**

```python
class DynamicBlockMesh:
    def __init__(self):
        # Spatial position arrays
        self.blocksX = []
        self.blocksY = []
        self.blocksZ = []
        # Dictionary mapping 'x,y,z' to list of face indices
        self.blocksData = {}
        # Global counter for total indices
        self.indicesLength = 0
        # Stack for vertex slot reuse
        self.vertexSlots = []

    def _insert_sorted(self, arr, value):
        """Insert value into sorted array arr."""
        # Linear scan for insertion point
        i = 0
        while i < len(arr) and arr[i] < value:
            i += 1
        arr.insert(i, value)

    def _remove_from_sorted(self, arr, value):
        """Remove first occurrence of value from sorted array arr."""
        try:
            arr.remove(value)
        except ValueError:
            pass

    def update_blocks(self, x, y, z, add, face_indices):
        """
        Add or remove a block face.
        :param x, y, z: Block coordinates
        :param add: Boolean, True to add, False to remove
        :param face_indices: List of 6 vertex indices for the face
        """
        pos_key = f"{x},{y},{z}"

        if add:
            # Ensure spatial coordinates are tracked
            if x not in self.blocksX:
                self._insert_sorted(self.blocksX, x)
            if y not in self.blocksY:
                self._insert_sorted(self.blocksY, y)
            if z not in self.blocksZ:
                self._insert_sorted(self.blocksZ, z)

            # Initialize block data if new
            if pos_key not in self.blocksData:
                self.blocksData[pos_key] = []

            # Append face indices
            self.blocksData[pos_key].extend(face_indices)
            self.indicesLength += 6

        else:
            if pos_key not in self.blocksData:
                return  # Block does not exist

            indices_list = self.blocksData[pos_key]
            
            # Remove the specific face indices
            # Note: In a real implementation, one must identify which 6 indices
            # correspond to the face being removed. Here we assume face_indices
            # are provided to be removed.
            for idx in face_indices:
                if idx in indices_list:
                    indices_list.remove(idx)
            
            self.indicesLength -= 6

            # Cleanup if block is empty
            if not indices_list:
                del self.blocksData[pos_key]
                self._remove_from_sorted(self.blocksX, x)
                self._remove_from_sorted(self.blocksY, y)
                self._remove_from_sorted(self.blocksZ, z)

    def get_vertex_slot(self):
        """Pop a vertex slot from the stack for reuse."""
        if self.vertexSlots:
            return self.vertexSlots.pop()
        return None  # [G] If stack empty, allocate new vertex
```

**Parameters and Typical Values:**
*   `face_indices`: Always 6 integers per face (two triangles).
*   `pos_key`: String format `"x,y,z"`.

**Edge Cases and Pitfalls:**
*   **Precision:** Coordinate keys must be exact. Floating-point coordinates should be quantized or rounded to integer grid positions before key generation to avoid hash mismatches [S1, unofficial].
*   **Degenerate Input:** Removing a face from a non-existent block should be handled gracefully (no-op) to prevent crashes [S1, unofficial].
*   **Memory Leaks:** If `blocksData` entries are not removed when empty, memory usage will grow indefinitely with repeated add/remove cycles [S1, unofficial].

## Subtopics

### Dynamic Index Buffer Updating
A technique for handling deformable models by classifying triangles into groups based on surface normals and updating an index buffer in AGP memory dynamically to avoid traversing the whole model for each slab [S2, unofficial]. It sets itself apart by focusing on deformable geometry and GPU memory transfer optimization rather than static voxel block management. Choose this when rendering deformable models where triangle classification needs to be updated in real-time. It involves preprocessing static models once to classify primitives into three groups based on surface normals. For deformable models, the dynamic index buffer in AGP memory is updated. The groups are divided into smaller sets (buckets) that sort triangles intersecting specific slabs. During rasterization, two clipping planes are set along slab borders, and multiple render targets are used to rasterize multiple slabs simultaneously [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ average case for add/remove operations if hash map lookup is $O(1)$. Spatial array insertion/removal is $O(N)$ where $N$ is the number of unique coordinates, but typically small per chunk.
*   **Memory Complexity:** Proportional to the number of visible faces. The use of `vertexSlots` stack helps minimize vertex buffer size.
*   **Measured Performance:** The performance penalty for dynamic index buffer updating is low, with the model traversed approximately only once in the rasterization stage [S2, unofficial].
*   **Strengths:** Efficient incremental updates; no need to regenerate the entire mesh; optimized memory usage via vertex slot reuse.
*   **Limitations:** Requires careful management of spatial indices; performance may degrade if the number of unique block coordinates becomes very large (slow spatial array scans).
*   **When to Use:** Real-time voxel-based games or simulations where blocks are frequently added or removed.
*   **When Not to Use:** Static scenes where pre-computed meshes are sufficient; highly deformable models requiring complex normal-based classification (use Dynamic Index Buffer Updating variant instead).

## Background
Dynamic Block Mesh Management originates from implementations in voxel-based game engines, specifically noted in the `exolands` repository [S1, unofficial]. It is designed to support dynamic world editing in voxel environments. The related technique of Dynamic Index Buffer Updating was introduced in research on real-time voxelization for complex models, leveraging AGP memory for fast data transfer [S2, unofficial].
