# Chunk-Based Parallel Voxel Culling & Rendering

Also called: Concurrent Chunk Culling, Parallel Chunk Rendering

## Overview
This method accelerates blocky voxel mesh rendering by distributing face culling and instance collection across multiple CPU threads organized by spatial chunks [G]. It solves the single-threaded mesh generation bottleneck by allowing independent chunks to be processed concurrently [G]. It differs from [Remesh Budget](3119-remesh-budget.md) by focusing on parallelism and spatial partitioning rather than dynamic cost-based remeshing thresholds [G].

## How it works
**Inputs and Outputs:**
- Input: A list of chunk positions requiring update [G].
- Output: A dictionary mapping chunk positions to arrays of visible instances, passed to the GPU [S1, unofficial].

**Data Structures:**
- `chunksToRender`: A dictionary mapping chunk positions (`Vector3`) to arrays of `ShapeInstance` objects [S1, unofficial].
- `ShapeInstance`: Contains face visibility flags (`faceBack`, `faceFront`, `faceTop`, `faceBottom`, `faceLeft`, `faceRight`), tint colors for each face (`Vector3`), and a reference to the `IShape` geometry [S1, unofficial].
- `renderDataByBlock`: A static array indexed by block ID, storing render data for each block type [S1, unofficial].

**Steps:**
1. Collect visible instances per chunk into a dictionary `chunksToRender` keyed by chunk position [S1, unofficial].
2. Execute culling tasks concurrently and wait for completion [S1, unofficial].
3. Iterate over completed chunks and pass their instance arrays to the shader for rendering [S1, unofficial].

**Pseudocode:**
```python
def process_chunks(chunk_positions):
    chunks_to_render = {}
    tasks = []
    for pos in chunk_positions:
        tasks.append(lambda p=pos: perform_chunk_culling(p))
    # [G] Concurrent execution and synchronization matching Task.WhenAll
    results = [t() for t in tasks]
    for pos, instances in zip(chunk_positions, results):
        chunks_to_render[pos] = instances
    for pos, blocks in chunks_to_render.items():
```

## Operating characteristics
- Time complexity: Not given in the sources. [G]
- Memory complexity: Not given in the sources. [G]
- Strengths: High throughput on multi-core CPUs; scalable with chunk count [G].
- Limitations: Synchronization overhead; potential load imbalance if chunks vary significantly in visible face count [G].
- When to use: Large voxel worlds with frequent updates or high visibility counts [G].
- When not to use: Small worlds or single-core environments where overhead outweighs benefits [G].
