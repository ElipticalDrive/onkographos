# Chunk-Based Parallel Voxel Culling & Rendering

Also called: Concurrent Chunk Culling, Parallel Chunk Rendering

## Overview
This method accelerates the rendering of blocky voxel meshes by distributing the computationally expensive face culling and instance collection tasks across multiple CPU threads, organized by spatial chunks. It solves the bottleneck of single-threaded mesh generation in large voxel worlds by allowing independent chunks to be processed concurrently. It differs from [Remesh Budget](3119-remesh-budget.md) by focusing on parallelism and spatial partitioning rather than dynamic cost-based remeshing thresholds.

## How it works
The method operates in two main phases: parallel culling and sequential rendering.

**Inputs and Outputs:**
- Input: A world data structure containing voxel blocks, organized into chunks.
- Output: A list of renderable instances grouped by chunk, passed to the GPU.

**Data Structures:**
- `chunksToRender`: A dictionary mapping chunk positions (`Vector3`) to arrays of `ShapeInstance` objects.
- `ShapeInstance`: Contains face visibility flags (`faceBack`, `faceFront`, `faceTop`, `faceBottom`, `faceLeft`, `faceRight`), tint colors for each face (`Vector3`), and a reference to the `IShape` geometry.
- `renderDataByBlock`: A static array indexed by block ID, storing render data for each block type.

**Steps:**
1. **Initialize Task List**: Create a list of tasks, one for each chunk that requires updating.
2. **Execute Culling Tasks**: Run all culling tasks concurrently. Each task processes its assigned chunk, determining visible faces based on adjacency to empty space or chunk boundaries, and populates a local collection of `ShapeInstance` objects.
3. **Wait for Completion**: Synchronize all threads to ensure all chunks are processed.
4. **Aggregate Results**: Iterate over the completed chunks and populate the `chunksToRender` dictionary with the resulting instance arrays.
5. **Render**: Iterate through `chunksToRender` and pass each chunk's position and instance array to the shader for rendering.

**Pseudocode:**
```python
# Assuming a list of chunks to process
tasks = []
chunks_to_render = {}

for chunk_pos in chunks_to_process:
    # Define a culling task for this chunk
    def culling_task(pos):
        # [G] Implementation of chunk-specific culling logic
        # 1. Iterate over voxels in the chunk
        # 2. Check neighbors for empty space or chunk boundaries
        # 3. Create ShapeInstance objects for visible faces
        # 4. Store results in a local list
        instances = perform_chunk_culling(pos)
        return instances

    # Add task to list
    tasks.append(culling_task(chunk_pos))

# Execute all tasks concurrently
# [G] Using a thread pool or task scheduler
results = execute_parallel_tasks(tasks)

# Aggregate results
for chunk_pos, instances in results:
    chunks_to_render[chunk_pos] = instances

# Render phase
for chunk_pos, instances in chunks_to_render.items():
    shader.render_chunk(chunk_pos, instances)
```

**Parameters:**
- Number of threads: Determined by hardware capabilities.
- Chunk size: Defined by [Chunked World Management](1405-chunked-world-management.md).

**Edge Cases:**
- Empty chunks: Should be skipped or handled efficiently to avoid overhead.
- Chunk boundaries: Face culling must correctly identify faces on chunk edges to ensure seamless rendering.

## Operating characteristics
- **Time Complexity**: $O(N)$ where $N$ is the number of chunks, assuming constant work per chunk. Parallelism reduces wall-clock time by a factor proportional to the number of cores.
- **Memory Complexity**: $O(M)$ where $M$ is the total number of visible instances across all chunks.
- **Strengths**: High throughput on multi-core CPUs; scalable with chunk count.
- **Limitations**: Synchronization overhead; potential load imbalance if chunks vary significantly in visible face count.
- **When to use**: Large voxel worlds with frequent updates or high visibility counts.
- **When not to use**: Small worlds or single-core environments where overhead outweighs benefits.

## Background
Originated in community-driven voxel rendering projects, this method leverages standard parallel programming patterns to address performance bottlenecks in real-time voxel engines. It builds on [Chunked World Management](1405-chunked-world-management.md) by adding concurrency to the chunk processing pipeline.
