# Remesh Budget

Also called: RemeshQueue

## Overview
Remesh Budget is a rendering optimization for chunked voxel worlds that limits the computational cost of mesh regeneration per frame by processing only the most visually significant dirty chunks. It solves the problem of frame-time spikes caused by rebuilding geometry for distant or less important chunks by enforcing a strict time budget, ensuring that mesh updates are prioritized based on camera proximity. It differs from sibling methods like [Chunk-Based Parallel Voxel Culling & Rendering](3994-chunk-based-parallel-voxel-culling-rendering.md) by focusing on temporal budgeting and spatial prioritization of rebuilds rather than parallel culling strategies.

## How it works
**Inputs and Outputs:**
- Input: A list of "dirty" chunks (chunks that have changed geometry and require mesh regeneration).
- Input: The current camera position.
- Input: The remaining frame time budget allocated for remeshing.
- Output: A set of chunks whose meshes have been regenerated and uploaded to the GPU.
- Output: The remaining frame time budget.

**Data Structures:**
- `RemeshQueue`: A priority queue storing dirty chunks. The priority is determined by the distance from the camera to the chunk's center. Closer chunks have higher priority.
- `Chunk`: Represents a sub-world section. Contains a `dirty` flag and geometric data.

**Steps:**
1. **Identify Dirty Chunks:** Collect all chunks marked as dirty. A chunk becomes dirty when a block is placed, removed, or modified within it.
2. **Sort by Proximity:** Insert all dirty chunks into the `RemeshQueue`, ordered by distance to the camera. The nearest chunk is at the front.
3. **Initialize Budget:** Set the time budget for remeshing to a fixed value, typically 3 ms per frame [S1].
4. **Process Queue:**
   - While the `RemeshQueue` is not empty and the time spent on remeshing is less than the budget:
     - Dequeue the nearest chunk.
     - Generate the mesh for this chunk. The mesh consists of panels for exposed faces, strips for exposed edges, triangles for exposed corners, and caps where four blocks meet along an edge [S1].
     - Upload the mesh data to the GPU.
     - Mark the chunk as clean (not dirty).
     - Record the time taken for this operation.
   - **Constraint:** At least one chunk must be meshed per frame, even if the budget is exhausted immediately after the first chunk [S1].
5. **Update State:** The remaining budget is discarded for the next frame; the budget resets to the full 3 ms for the next frame's processing [S1].

**Parameters:**
- `Frame Budget`: 3 ms per frame [S1]. This is a fixed value in the reference implementation.

**Edge Cases and Pitfalls:**
- **Budget Exhaustion:** If the budget is exhausted after processing one chunk, the remaining dirty chunks are left for subsequent frames. This ensures smooth frame rates but may cause visual pop-in for distant chunks if the camera moves rapidly.
- **No Dirty Chunks:** If there are no dirty chunks, no remeshing occurs, and the full budget is unused.
- **Precision:** Time measurement should use high-resolution timers to accurately track the 3 ms budget.

**Pseudocode:**
```python
def remesh_budget(dirty_chunks, camera_position, frame_time_budget_ms=3.0):
    """
    Remesh chunks within a time budget, prioritizing proximity to the camera.
    
    Args:
        dirty_chunks: List of Chunk objects that need remeshing.
        camera_position: Vector3 representing the camera's position.
        frame_time_budget_ms: Time budget in milliseconds for remeshing.
        
    Returns:
        List of Chunk objects that were successfully remeshed.
    """
    if not dirty_chunks:
        return []

    # Step 2: Sort by proximity to camera
    # Calculate distance for each chunk and sort
    chunks_with_distance = []
    for chunk in dirty_chunks:
        dist = distance(chunk.center, camera_position)
        chunks_with_distance.append((dist, chunk))
    
    # Sort ascending by distance (nearest first)
    chunks_with_distance.sort(key=lambda x: x[0])
    
    remeshed_chunks = []
    time_spent_ms = 0.0
    
    # Step 4: Process Queue
    # Constraint: Always mesh at least one chunk
    processed_at_least_one = False
    
    for dist, chunk in chunks_with_distance:
        # Check budget before processing
        if processed_at_least_one and time_spent_ms >= frame_time_budget_ms:
            break
            
        # Generate mesh for the chunk
        start_time = get_high_resolution_time_ms()
        mesh = generate_chunk_mesh(chunk)
        upload_mesh_to_gpu(mesh)
        end_time = get_high_resolution_time_ms()
        
        time_spent_ms += (end_time - start_time)
        
        # Mark chunk as clean
        chunk.dirty = False
        
        remeshed_chunks.append(chunk)
        processed_at_least_one = True
        
    return remeshed_chunks

def distance(pos1, pos2):
    """Calculate Euclidean distance between two points."""
    dx = pos1.x - pos2.x
    dy = pos1.y - pos2.y
    dz = pos1.z - pos2.z
    return (dx*dx + dy*dy + dz*dz) ** 0.5

def get_high_resolution_time_ms():
    """Return current time in milliseconds."""
    import time
    return time.time() * 1000
```

## Subtopics

### [Chunk Mesh Rebuild Queue](3911-chunk-mesh-rebuild-queue.md)
A queue-based system to batch and process chunk mesh rebuilds asynchronously or on tick. It ensures that modified chunks are regenerated into visible geometry without redundant processing, serving as the execution engine for the Remesh Budget optimization.

## Operating characteristics
- **Time Complexity:** O(N log N) for sorting dirty chunks by distance, where N is the number of dirty chunks. The remeshing step is O(M), where M is the number of chunks processed within the budget.
- **Memory Complexity:** O(N) to store the dirty chunks and the priority queue.
- **Measured Performance:** In the "Outpost" scene, which consists of 4 chunks and 10k triangles, the method ensures that remeshing stays within the 3 ms budget. The scene results in 37 draws and 200k triangles on Low quality, 114 draws and 879k triangles on Balanced, and 153 draws and 1.87M triangles on Ultra quality [S1].
- **Strengths:** Guarantees frame rate stability by limiting remeshing time. Prioritizes visual fidelity for chunks near the camera.
- **Limitations:** Distant chunks may remain unremeshed for multiple frames if the camera moves frequently, potentially causing visual artifacts. The fixed 3 ms budget may be too short for complex scenes on slower hardware.
- **When to Use:** Ideal for real-time voxel games where frame rate consistency is critical and the world is divided into chunks.
- **When Not to Use:** Not suitable for offline rendering or scenarios where all chunks must be updated immediately regardless of frame time.

## Background
Remesh Budget was introduced in the "Claude Survivor Builder" project by Austin Bryan Price. It is part of Phase 2c of the project's development, focusing on optimizing the rendering of beveled chunk meshes with tiered tiles and ambient occlusion [S1]. The method is implemented in the `remesh-queue.ts` file within the project's source code.
