# Chunk Mesh Rebuild Queue

Also called: ProcessRebuildQueue, QueueRebuild

## Overview
A queue-based system to batch and process chunk mesh rebuilds asynchronously or on tick [S1, unofficial]. It ensures that modified chunks are regenerated into visible geometry without redundant processing, serving as the execution engine for the [Remesh Budget](3119-remesh-budget.md) optimization.

## How it works
**Inputs and Outputs:**
*   **Input:** A set of modified blocks per chunk (stored in `Sub->GetModifiedBlocks()`), the current world state (`WorldMesh`), and the player position for collision culling.
*   **Output:** Updated chunk meshes in `WorldMesh` and potentially enabled collision for nearby chunks.

**Data Structures:**
*   `RebuildQueue`: A dynamic array or stack storing `ChunkIndex` values (integer pairs/tuples) pending mesh regeneration.
*   `RebuildSet`: A hash set or boolean map storing `ChunkIndex` values currently in the queue to prevent duplicates.
*   `ActiveChunks`: A set of chunk indices currently loaded and visible in the world.
*   `ChunkCache`: A storage mechanism retrieving raw voxel data for a given `ChunkIndex`.

**Steps:**
1.  **Enqueue Modification:** When a block change occurs, if the `ChunkIndex` is not in `RebuildSet`, add it to both `RebuildSet` and `RebuildQueue` [S1, unofficial].
2.  **Process Loop:**
    a. If `RebuildQueue` is empty or `WorldMesh` is null, terminate the process [S1, unofficial].
    b. Pop the last element from `RebuildQueue`: `ChunkIndex = RebuildQueue.Last()`, then `RebuildQueue.Pop()` [S1, unofficial].
    c. Remove `ChunkIndex` from `RebuildSet` [S1, unofficial].
    d. If `ChunkIndex` is not in `ActiveChunks`, return to step 2a [S1, unofficial].
    e. Retrieve chunk data from `ChunkCache`. If not found, return to step 2a [S1, unofficial].
    f. Prepare mesh: `Mesh = AWorldMeshActor::PrepareChunkMesh(*Data)` [S1, unofficial].
    g. Update the chunk mesh: `WorldMesh->UpdateChunk(ChunkIndex, Mesh)` [S1, unofficial].
    h. Check if the chunk is near the player (within 1 chunk in X and Y). If so, enable collision for the chunk [S1, unofficial].

**Pseudocode:**
```python
def ProcessRebuildQueue(WorldMesh, RebuildQueue, RebuildSet, ActiveChunks, ChunkCache, PlayerPosition):
    if not RebuildQueue or not WorldMesh:
        return

    while RebuildQueue:
        # Pop last element
        ChunkIndex = RebuildQueue[-1]
        RebuildQueue.pop()
        RebuildSet.remove(ChunkIndex)

        # Check if chunk is active
        if ChunkIndex not in ActiveChunks:
            continue

        # Retrieve data
        Data = ChunkCache.get(ChunkIndex)
        if not Data:
            continue

        # Prepare and update mesh
        Mesh = PrepareChunkMesh(Data)
        WorldMesh.UpdateChunk(ChunkIndex, Mesh)

        # Collision culling check
        if IsNearPlayer(ChunkIndex, PlayerPosition, threshold=1):
            WorldMesh.EnableCollision(ChunkIndex)

def EnqueueChunk(ChunkIndex, RebuildQueue, RebuildSet):
    if ChunkIndex not in RebuildSet:
        RebuildSet.add(ChunkIndex)
        RebuildQueue.append(ChunkIndex)
```

**Parameters:**
*   `threshold`: Distance for collision enablement. Typically 1 chunk in X and Y axes [S1, unofficial].

**Edge Cases:**
*   **Duplicate Requests:** The `RebuildSet` prevents adding the same chunk to the queue multiple times, ensuring each chunk is processed only once per batch [S1, unofficial].
*   **Missing Data:** If `ChunkCache` fails to return data for a queued chunk, the chunk is skipped to avoid crashes or null references [S1, unofficial].
*   **Inactive Chunks:** Chunks that become inactive (e.g., unloaded) while in the queue are skipped, preventing work on invisible geometry [S1, unofficial].

## Subtopics

## Operating characteristics
*   **Time Complexity:** O(N) where N is the number of chunks in the queue, assuming constant-time queue operations and mesh preparation.
*   **Memory Complexity:** O(M) where M is the number of modified chunks, storing indices in `RebuildQueue` and `RebuildSet`.
*   **Strengths:** Prevents redundant mesh generation; decouples modification events from rendering updates; allows for batched processing.
*   **Limitations:** Processing order is LIFO (last-in, first-out) by default, which may not prioritize camera proximity unless sorted by the parent [Remesh Budget](3119-remesh-budget.md).
*   **When to use:** When block modifications are frequent and need to be batched for performance.
*   **When not to use:** When immediate visual feedback is required for every single block change without batching.

## Background
Originated in the [HawkDev15/VoxelWorld](https://github.com/HawkDev15/VoxelWorld) project [S1, unofficial]. It is part of a larger chunked world management system that includes saving/loading modified blocks and force-loading chunks at player positions.
