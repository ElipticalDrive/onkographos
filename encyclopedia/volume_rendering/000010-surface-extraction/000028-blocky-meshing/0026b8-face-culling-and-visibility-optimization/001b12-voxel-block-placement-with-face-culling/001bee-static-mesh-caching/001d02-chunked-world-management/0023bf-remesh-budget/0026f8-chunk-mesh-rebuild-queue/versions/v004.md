# Chunk Mesh Rebuild Queue

Also called: ProcessRebuildQueue, QueueRebuild

## Overview
A queue-based system to batch and process chunk mesh rebuilds asynchronously or on tick [S1, unofficial]. It solves the problem of redundant mesh generation by ensuring each dirty chunk is processed exactly once per frame or tick cycle, serving as the execution engine for the Remesh Budget [Remesh Budget](3119-remesh-budget.md).

## How it works
**Inputs:**
- `RebuildQueue`: A dynamic array or stack of chunk indices requiring mesh updates.
- `RebuildSet`: A hash set or boolean array tracking which chunk indices are currently in the queue to prevent duplicates.
- `ActiveChunks`: A set of chunk indices currently loaded and visible in the world.
- `ChunkCache`: A data structure mapping chunk indices to their raw voxel block data.
- `WorldMesh`: The rendering component responsible for managing chunk meshes.

**Outputs:**
- Updated meshes for processed chunks in `WorldMesh`.
- Collision state updates for chunks near the player.

**Data Structures:**
- `RebuildQueue`: Stores `ChunkIndex` (typically `FIntPoint` or `int2` representing X, Z coordinates).
- `RebuildSet`: Stores `ChunkIndex` for O(1) lookup.
- `ChunkCache`: Maps `ChunkIndex` to block data (e.g., `TMap<FIntPoint, TMap<FIntVector, EBlockType>>`).

**Steps:**
1. **Enqueue Dirty Chunks:** When a chunk's block data changes, if its `ChunkIndex` is not in `RebuildSet`, add it to both `RebuildSet` and `RebuildQueue` [S1, unofficial].
2. **Process Loop:**
   a. If `RebuildQueue` is empty or `WorldMesh` is null, terminate the process [S1, unofficial].
   b. Pop the last element from `RebuildQueue`: `ChunkIndex = RebuildQueue.Last()`, then `RebuildQueue.Pop()` [S1, unofficial].
   c. Remove `ChunkIndex` from `RebuildSet` [S1, unofficial].
   d. If `ChunkIndex` is not in `ActiveChunks`, return to step 2a (skip processing) [S1, unofficial].
   e. Retrieve chunk data from `ChunkCache`. If not found, return to step 2a [S1, unofficial].
   f. Prepare mesh: `Mesh = AWorldMeshActor::PrepareChunkMesh(*Data)` [S1, unofficial].
   g. Update the chunk mesh: `WorldMesh->UpdateChunk(ChunkIndex, Mesh)` [S1, unofficial].
   h. Check if the chunk is near the player (within 1 chunk in X and Y). If so, enable collision for the chunk [S1, unofficial].

**Pseudocode:**
```python
def ProcessRebuildQueue(RebuildQueue, RebuildSet, ActiveChunks, ChunkCache, WorldMesh, PlayerPosition):
    if not RebuildQueue or not WorldMesh:
        return

    while RebuildQueue:
        # Pop the last element
        ChunkIndex = RebuildQueue[-1]
        RebuildQueue.pop()
        
        # Remove from set
        RebuildSet.remove(ChunkIndex)
        
        # Check if active
        if ChunkIndex not in ActiveChunks:
            continue
            
        # Retrieve data
        Data = ChunkCache.get(ChunkIndex)
        if Data is None:
            continue
            
        # Prepare and update mesh
        Mesh = PrepareChunkMesh(Data)
        WorldMesh.UpdateChunk(ChunkIndex, Mesh)
        
        # Check proximity for collision
        if IsNearPlayer(ChunkIndex, PlayerPosition):
            WorldMesh.EnableCollision(ChunkIndex)

def IsNearPlayer(ChunkIndex, PlayerPosition):
    # Check if within 1 chunk in X and Y
    # Implementation depends on coordinate system specifics [G]
    dx = abs(ChunkIndex.x - PlayerPosition.chunk_x)
    dy = abs(ChunkIndex.y - PlayerPosition.chunk_y)
    return dx <= 1 and dy <= 1

def EnqueueChunk(ChunkIndex, RebuildQueue, RebuildSet):
    if ChunkIndex not in RebuildSet:
        RebuildSet.add(ChunkIndex)
        RebuildQueue.append(ChunkIndex)
```

**Parameters:**
- Processing order: LIFO (Last-In-First-Out) via `Last()` and `Pop()` [S1, unofficial].
- Proximity threshold: 1 chunk in X and Y [S1, unofficial].

**Edge Cases:**
- If `WorldMesh` is null, the process halts immediately [S1, unofficial].
- If chunk data is missing from cache, the chunk is skipped [S1, unofficial].
- Duplicate entries are prevented by `RebuildSet` [S1, unofficial].

## Subtopics

## Operating characteristics
- **Time Complexity:** O(1) per chunk for queue operations. Mesh generation complexity depends on the chunk size and culling algorithm.
- **Memory Complexity:** O(N) where N is the number of dirty chunks.
- **Performance:** Prevents redundant mesh generation by tracking state in `RebuildSet` [S1, unofficial].
- **Strengths:** Simple implementation, prevents duplicate work, integrates collision updates [S1, unofficial].
- **Limitations:** Synchronous processing on the main thread can cause stutter if not offloaded [Asynchronous Chunk Loading](4216-asynchronous-chunk-loading.md). LIFO order may not prioritize camera proximity without additional logic [Remesh Budget](3119-remesh-budget.md).

## Background
Originated in voxel world management systems for real-time applications, specifically implemented in the VoxelWorld project [S1, unofficial]. It addresses the need for efficient incremental mesh updates in dynamic voxel environments.
