# Face Culling

Also called: Exposure Culling, Neighbor Check Culling, Voxel Neighbor Face Culling

## Overview
Face Culling is a mesh generation optimization that reduces the number of vertices sent to the GPU by skipping the rendering of voxel faces that are adjacent to existing neighboring voxels [S1, unofficial]. It solves the problem of naively rendering all 6 faces of every cube, including those hidden by neighbors. It is distinguished from its siblings by its direct, per-voxel neighbor lookup logic applied during mesh creation, rather than post-generation filtering or complex visibility preprocessing.

## How it works
**Inputs and Outputs:**
*   **Input:** A set of occupied voxel positions (typically stored in a hash set or grid) and a list of voxels to process.
*   **Output:** A vertex buffer containing only the exposed faces of the voxels.

**Data Structures:**
The method relies on specific data structures to track voxel state and face properties [S1, unofficial]:
*   `Cube` struct:
    *   `std::vector<Face> faces`: A fixed-size vector of 6 `Face` objects, one for each direction.
    *   `glm::ivec3 cubeCenter`: The 3D integer coordinates of the voxel's center.
    *   `glm::ivec3 gridPos`: The grid position of the voxel.
    *   `int neighbors`: A counter for adjacent occupied voxels (used for optimization or debugging).
*   `Face` struct:
    *   `std::vector<float> vertices`: The vertex data for the face.
    *   `glm::ivec3 normal`: The direction vector of the face (e.g., `(1, 0, 0)` for right).
    *   `bool isSideFace`: Indicates if the face is a vertical side face.
    *   `bool isBottomFace`: Indicates if the face is the bottom face.
    *   `bool renderFlag`: A boolean flag determining if the face should be included in the final mesh.

**Algorithm Steps:**
1.  Iterate through each voxel in the scene.
2.  For each of the six faces of the voxel, determine the position of the adjacent voxel in the direction of the face's normal:
    $$ \text{neighborPos} = \text{cubeCenter} + \text{face.normal} $$
3.  Check if a voxel exists at `neighborPos` in the occupied positions set.
4.  Apply culling logic based on the face type:
    *   **Bottom Faces:** Always culled (`renderFlag = false`), regardless of whether a neighbor exists below. This assumes the ground or bottom layer is not rendered or is handled separately [S1, unofficial].
    *   **Side Faces:** A side face is culled if:
        *   A neighbor exists directly adjacent in the face's direction (`neighborPos` is occupied), OR
        *   A neighbor exists directly above the neighbor position (`neighborPos + (0, 1, 0)` is occupied). This specific logic prevents rendering side faces that are occluded by overhangs or adjacent blocks above the neighbor [S1, unofficial].
5.  If the face is not culled, add its vertices to the vertex buffer.
6.  Optionally, count the number of neighbors for the voxel by checking the six adjacent positions and the six positions directly above them (as per the specific implementation in [S1, unofficial]).

**Pseudocode:**
```python
def generate_mesh(occupied_positions: set[Vec3i], voxels: list[Cube]) -> list[Face]:
    """
    Generates a mesh by culling hidden faces based on neighbor existence.
    
    Args:
        occupied_positions: A set of Vec3i representing the coordinates of all solid voxels.
        voxels: A list of Cube objects, each containing face data and position.
        
    Returns:
        A list of Face objects that are exposed and should be rendered.
    """
    exposed_faces = []
    
    for cube in voxels:
        for face in cube.faces:
            # Calculate the position of the neighbor in the direction of the face normal
            neighbor_pos = cube.cube_center + face.normal
            
            # Check if a neighbor exists at the adjacent position
            neighbor_exists = neighbor_pos in occupied_positions
            
            # Determine render flag based on face type and neighbor presence
            if face.is_bottom_face:
                # Bottom faces are always culled in this implementation
                face.render_flag = False
            else:
                # For side faces, check for direct neighbor OR neighbor above the neighbor
                # This handles occlusion from overhangs or adjacent blocks above
                neighbor_above_pos = neighbor_pos + Vec3i(0, 1, 0)
                neighbor_above_exists = neighbor_above_pos in occupied_positions
                
                if neighbor_exists or neighbor_above_exists:
                    face.render_flag = False
                else:
                    face.render_flag = True
            
            # If the face is not culled, add it to the output
            if face.render_flag:
                exposed_faces.append(face)
                
    return exposed_faces
```

**Parameters and Typical Values:**
*   **Bottom Face Culling:** Always enabled in the cited implementation [S1, unofficial].
*   **Neighbor Check Depth:** Immediate neighbors only (distance 1) [S1, unofficial].
*   **Overhang Check:** Checks one unit above the neighbor position [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Bottom Face Culling:** The implementation always culls bottom faces, which may be incorrect for scenes where the underside of terrain is visible (e.g., caves) [S1, unofficial].
*   **Overhang Logic:** The check for `neighborPos + (0, 1, 0)` culls side faces if there is a block above the neighbor. This is a specific heuristic that may not match all visual requirements (e.g., it might cull a side face that is actually visible if the neighbor above is transparent or if the camera angle allows seeing around the overhang) [S1, unofficial].
*   **Performance:** The original approach of looping through neighbors with random memory access was noted as poor performance [S2, unofficial]. Using a hash set for `occupied_positions` mitigates this, but cache locality may still be an issue for large worlds.

## Subtopics

### Binary Hidden-Face Culling
A technique that uses bitwise operations on a bitmask representation of voxels to determine visible faces in bulk, avoiding per-voxel loops and random memory access [S2, unofficial]. It represents each voxel as a bit (1 for solid, 0 for air) and uses shifts and bitwise AND/OR operations to compute visibility masks for each face direction simultaneously [S2, unofficial]. It is chosen when performance is critical and the voxel data can be efficiently represented as a linear array or bitmask, such as in 1D slices or flattened grids. It is linked to [Face Culling](52-face-culling.md) as an optimization variant.

## Operating characteristics
*   **Time Complexity:** $O(V)$, where $V$ is the number of voxels, assuming $O(1)$ average case lookup in the `occupied_positions` hash set [S1, unofficial].
*   **Memory Complexity:** $O(V)$ for storing the voxel data and the `occupied_positions` set [S1, unofficial].
*   **Measured Performance:** 4096 cubes rendered at ~60 FPS on the author's system [S1, unofficial].
*   **Strengths:** Simple to implement; runs once during mesh creation, resulting in no framerate loss during rendering [S1, unofficial]; significantly reduces vertex count compared to naive rendering.
*   **Limitations:** The specific overhang culling logic may be too aggressive or incorrect for some scenes; bottom face culling is hardcoded [S1, unofficial]; performance depends on the efficiency of the neighbor lookup structure.
*   **When to Use:** When generating static voxel meshes and the visual style allows for hidden faces to be completely removed (including bottoms and side faces occluded by overhangs).
*   **When Not to Use:** When dynamic voxel changes require frequent mesh updates (the culling must be re-run); when the underside of terrain needs to be visible; when the overhang culling logic does not match the desired visual result.

Face Culling in voxel meshing is a standard optimization technique.
