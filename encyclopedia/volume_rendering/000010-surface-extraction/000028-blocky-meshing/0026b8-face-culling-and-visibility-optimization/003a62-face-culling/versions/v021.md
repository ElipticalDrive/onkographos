# Face Culling

Also called: Exposure Culling, Neighbor Check Culling, Voxel Neighbor Face Culling

## Overview
Face Culling is a mesh generation optimization that reduces the number of vertices sent to the GPU by skipping the rendering of voxel faces that are adjacent to existing neighboring voxels [S1, unofficial]. It solves the problem of naively rendering all 6 faces of every cube, including those hidden by neighbors. It differs from its siblings by performing this check during the mesh creation phase rather than at render time or via complex projection masks, relying on immediate neighbor occupancy checks [S1, unofficial].

## How it works
Face Culling determines the visibility of a voxel's faces by inspecting the occupancy status of its six immediate spatial neighbors. The method operates on a per-voxel basis during mesh generation.

### Inputs and Outputs
*   **Input**: The 3D grid position of the current voxel $P$, the occupancy status of the voxel at $P$ (solid/empty), and the occupancy status of the six immediate neighbors.
*   **Output**: A set of visible faces (vertices and indices) to be added to the mesh buffer.

### Data Structures
The implementation relies on tracking occupied positions and face properties.

1.  **Occupied Positions**: A set or hash map storing the grid coordinates of all solid voxels.
    *   Type: `std::unordered_set<glm::ivec3>` or equivalent hash set of integer triplets [S1, unofficial].
2.  **Cube/Vertex Data**:
    *   `Cube` struct contains:
        *   `cubeCenter`: The 3D integer grid position of the voxel [S1, unofficial].
        *   `gridPos`: The 3D integer grid position (often identical to `cubeCenter`) [S1, unofficial].
        *   `neighbors`: An integer counter for adjacent solid voxels [S1, unofficial].
    *   `Face` struct contains:
        *   `vertices`: A list of floating-point coordinates for the face geometry [S1, unofficial].
        *   `normal`: The 3D integer vector indicating the face's outward direction [S1, unofficial].
        *   `isSideFace`: Boolean flag indicating if the face is a vertical side [S1, unofficial].
        *   `isBottomFace`: Boolean flag indicating if the face is the bottom face [S1, unofficial].
        *   `renderFlag`: Boolean flag determining if the face is added to the buffer (`true`) or culled (`false`) [S1, unofficial].

### Algorithm Steps
The culling logic is applied once during mesh creation. For each solid voxel:

1.  Iterate through the six faces of the voxel.
2.  For each face, calculate the position of the neighbor in the direction of the face's normal:
    $$ P_{neighbor} = P + N $$
    where $P$ is the current voxel's position and $N$ is the face's normal vector.
3.  Check if a solid voxel exists at $P_{neighbor}$ in the `occupiedPositions` set.
4.  Determine the `renderFlag` for the face based on the neighbor's existence and the face type:
    *   **Bottom Faces**: Always culled (`renderFlag = false`), regardless of neighbor occupancy [S1, unofficial].
    *   **Side Faces**:
        *   If a neighbor exists directly adjacent at $P_{neighbor}$, the face is internal and culled (`renderFlag = false`) [S1, unofficial].
        *   If no direct neighbor exists, the face is exposed and rendered (`renderFlag = true`) [S1, unofficial].
        *   *Note*: One source implementation also checks for neighbors directly above the neighbor position ($P_{neighbor} + (0,1,0)$) to influence side face culling, though the primary definition relies on direct adjacency [S1, unofficial].
5.  If `renderFlag` is true, add the face's vertices to the mesh buffer.

        (-1, 0, 0),  # Left
        (0, 1, 0),   # Top
        (0, -1, 0),  # Bottom
        (0, 0, 1),   # Front
        (0, 0, -1)   # Back
    ]
    
    for pos in voxel_grid:
        for normal in normals:
            # Calculate neighbor position
            neighbor_pos = (pos[0] + normal[0], 
                            pos[1] + normal[1], 
                            pos[2] + normal[2])
            
            # Determine face type
            is_bottom = (normal == (0, -1, 0))
            
            render_flag = False
            
            if is_bottom:
                # Bottom faces are always culled
                render_flag = False
            else:
                # Check for direct neighbor
                neighbor_exists = neighbor_pos in voxel_grid
                
                if neighbor_exists:
                    # Neighbor exists, face is internal
                    render_flag = False
                else:

                    render_flag = True

                                          neighbor_pos[1] + 1, 
                                          neighbor_pos[2])
                    if above_neighbor_pos in voxel_grid:
                        render_flag = False

### Parameters and Edge Cases
*   **Bottom Face Culling**: A specific pitfall/feature is that bottom faces are always culled (`renderFlag = false`) regardless of whether there is a voxel below [S1, unofficial]. This implies the mesh is either viewed from above, or bottom faces are handled by a separate mechanism or ignored for performance.
*   **Side Face Logic**: Side faces are culled if a neighbor exists directly adjacent OR if a neighbor exists directly above the neighbor position (checking `neighborPos + (0,1,0)`) [S1, unofficial]. This specific condition suggests a variation where side faces might be hidden by overhangs or specific structural configurations, though the primary definition is simple adjacency.
*   **Precision**: The method relies on integer grid coordinates. Floating-point precision issues are not a factor for the culling decision itself, only for the subsequent vertex generation.

## Subtopics

### Binary Hidden-Face Culling
A technique to reduce the number of faces in a voxel mesh by removing those completely hidden (adjacent to another voxel), using bitwise operations on a bitmask representation of voxels to determine visible faces in bulk [S2, unofficial]. It differs from standard Face Culling by operating on linear bitmasks rather than iterating individual voxel neighbors, allowing for bulk calculation of visible faces via shifts and bitwise AND/OR operations. It is chosen when performance is critical and the voxel data can be efficiently represented as a linear array or bitmask, avoiding the random memory access penalties of neighbor lookups [S2, unofficial]. To determine visible left faces, the bitmask is shifted right by 1, inverted, and ANDed with the original mask. For right faces, it is shifted left [S2, unofficial].

## Operating characteristics
*   **Time Complexity**: $O(V)$, where $V$ is the number of solid voxels. Each voxel is processed once, and neighbor checks are $O(1)$ on average using a hash set [S1, unofficial].
*   **Memory Complexity**: $O(V)$ to store the occupied positions set and the resulting mesh vertices.
*   **Measured Performance**: In one implementation, 4096 cubes were rendered at ~60 FPS on the author's system [S1, unofficial].
*   **Strengths**: The culling check runs once during mesh creation, resulting in no framerate loss during rendering [S1, unofficial]. It significantly reduces the number of vertices sent to the GPU.
*   **Limitations**: The naive implementation of checking neighbors can lead to poor performance due to random memory access if not optimized (e.g., using a hash set or spatial partitioning) [S2, unofficial]. The specific pitfall of always culling bottom faces may require additional handling if bottom visibility is required.
*   **When to use**: When generating static or semi-static voxel meshes where the cost of mesh generation is acceptable, but rendering performance is critical.
*   **When not to use**: When dynamic voxel changes require frequent mesh regeneration and the overhead of neighbor checks is too high, or when bottom faces must be visible.

## Background
Face Culling is a standard optimization in voxel terrain generation and meshing. It originates from the need to optimize the rendering of voxel-based worlds, such as those in Minecraft-like games, where naive rendering of all cube faces results in excessive draw calls and vertex counts. The method is widely used in voxel engines to reduce the geometric complexity of the scene. The specific implementation details regarding bottom-face culling and neighbor checks are documented in community devlogs and open-source repositories [S1, S2, unofficial].
