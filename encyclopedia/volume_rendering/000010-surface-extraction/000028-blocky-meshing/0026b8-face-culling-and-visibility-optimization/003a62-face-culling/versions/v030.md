# Face Culling

Also called: Exposure Culling, Face Occlusion Culling, Neighbor Check Culling, Only render block faces that aren't adjacent to another face, Voxel Neighbor Face Culling

## Overview
Face Culling is a mesh generation optimization that prevents the rendering of block faces occluded by adjacent solid voxels, significantly reducing triangle count in homogeneous voxel terrain [S1, S2, unofficial]. It solves the problem of naively rendering all six faces of every cube, including those hidden by neighbors, by skipping the addition of faces adjacent to existing neighboring voxels to the vertex buffer [S2, unofficial]. Unlike [Block Visibility Culling](5334-block-visibility-culling.md) which operates on whole blocks or [Opacity-based Mesh Culling](8759-opacity-based-mesh-culling.md) which considers material properties, Face Culling relies strictly on local geometric adjacency [S1, S2, unofficial].

## How it works
**Inputs:** A set of solid voxel positions (often stored in a hash set or grid) and a chunk or world boundary definition.
**Outputs:** A list of vertices and indices representing only the exposed faces of the voxel mesh.

**Data Structures:**
The implementation may use a `Cube` struct containing:
*   `std::vector<Face> faces`: A fixed-size array (size 6) representing the six potential faces of a voxel [S2, unofficial].
*   `glm::ivec3 cubeCenter`: The 3D integer coordinates of the voxel [S2, unofficial].
*   `glm::ivec3 gridPos`: The position in the global grid [S2, unofficial].
*   `int neighbors`: A counter for adjacent solid voxels [S2, unofficial].

The `Face` struct contains:
*   `std::vector<float> vertices`: The vertex data for the face [S2, unofficial].
*   `glm::ivec3 normal`: The direction vector of the face normal [S2, unofficial].
*   `bool isSideFace`: Boolean flag indicating if the face is a side (non-bottom) face [S2, unofficial].
*   `bool isBottomFace`: Boolean flag indicating if the face is the bottom face [S2, unofficial].
*   `bool renderFlag`: Boolean flag determining if the face is added to the mesh [S2, unofficial].

**Steps:**
1.  **Neighbor Check**: For each solid voxel at position $P$ with a face normal $N$, calculate the neighbor position $P_{neighbor} = P + N$ [S1, S2, unofficial].
2.  **Occupancy Test**: Check if a solid voxel exists at $P_{neighbor}$ [S1, S2, unofficial].
3.  **Culling Decision**:
    *   If the neighbor is solid, the face is internal and culled (not rendered) [S1, S2, unofficial].
    *   If the neighbor is empty (air) or out of bounds, the face is exposed and rendered [S2, unofficial].
4.  **Bottom Face Culling**: In many implementations, the bottom face (normal $-Y$) is always culled regardless of neighbors below, as it is typically occluded by the ground or not visible from standard viewing angles [S2, unofficial].
5.  **Side Face Logic**: Side faces (non-bottom) are culled if a neighbor exists directly adjacent OR if a neighbor exists directly above the neighbor position [S2, unofficial]. This specific logic implies that if a voxel is present at $P + N + (0,1,0)$, the side face at $P+N$ is also considered occluded or hidden from certain angles [S2, unofficial].
6.  **Batching**: Individual cube meshes are often combined into a single "chunk" mesh to optimize GPU draw calls, subject to vertex count limits (e.g., ~65,000 vertices in Unity) [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Chunk Boundary Transitions**: Adjacent cubes across chunk boundaries (e.g., $x=0$ and $x=15$ in a 16-voxel chunk) must be checked. If ignored, the outline of each chunk is drawn, killing performance [S1, unofficial].
*   **Bottom Face Culling**: Bottom faces are always culled (`renderFlag = false`) regardless of neighbors below, as indicated by the logic `else { face.renderFlag = false; }` for `isBottomFace` [S2, unofficial].
*   **Side Face Logic**: Side faces (non-bottom) are culled if a neighbor exists directly adjacent OR if a neighbor exists directly above the neighbor position (checking `neighborPos + glm::ivec3(0, 1, 0)`) [S2, unofficial].
*   **Precision**: The culling check runs once during mesh creation, resulting in no framerate loss during rendering [S2, unofficial].

## Subtopics

### Binary Hidden-Face Culling
A technique to reduce the number of faces in a voxel mesh by removing those completely hidden (adjacent to another voxel), using bitwise operations on a bitmask representation of voxels to determine visible faces in bulk [S3, unofficial]. It represents each voxel as a bit in a bitmask, where 1 indicates a solid voxel and 0 indicates a transparent or air voxel [S3, unofficial]. To determine visible left faces, it shifts the bitmask right by 1 position (representing the neighbor to the left), inverts the result to find air positions, and performs a bitwise AND with the original mask [S3, unofficial]. To determine visible right faces, it shifts the bitmask left by 1 position (representing the neighbor to the right), inverts the result to find air positions, and performs a bitwise AND with the original mask [S3, unofficial]. Use the resulting masks to choose which faces to draw or not draw for the mesh generation [S3, unofficial]. The original approach of checking each of the six faces by looping through neighbors and performing random memory access leads to very poor performance [S3, unofficial].

## Operating characteristics
*   **Time Complexity**: The culling check runs once during mesh creation, resulting in no framerate loss during rendering [S2, unofficial]. However, the naive implementation of checking each of the six faces by looping through neighbors and performing random memory access leads to very poor performance [S3, unofficial].
*   **Memory Complexity**: Depends on the storage of the voxel grid and the resulting mesh. Using indices can save memory [S1, unofficial].
*   **Measured Performance**: With this optimization working correctly, performance allows running more than 14,440 chunks on a fairly old PC (Intel Core i7 2.5 GHz, AMD Radeon HD 6770M 1024 MB) while performing GPU-heavy algorithms like cascaded shadow mapping and water shading [S1, unofficial]. Another measurement shows 4096 cubes rendered at ~60 FPS on the author's system [S2, unofficial].
*   **Scaling**: Without this optimization, the author could only draw ~20 chunks without lagging. With it, performance increases dramatically, drawing only ~1/1000 of the triangles previously drawn [S1, unofficial].
*   **Strengths**: Significantly reduces triangle count in homogeneous voxel terrain [S1, unofficial]. No runtime overhead as culling is done at mesh generation time [S2, unofficial].
*   **Limitations**: Requires careful handling of chunk boundaries to avoid rendering chunk outlines [S1, unofficial]. The specific side-face occlusion logic (checking above neighbors) may not be suitable for all voxel types or game mechanics [S2, unofficial].
*   **When to use**: When rendering large, homogeneous voxel terrains where most faces are internal [S1, unofficial].
*   **When not to use**: When dynamic voxel changes require frequent mesh regeneration and the overhead of culling outweighs the rendering savings, or when all faces (including internal ones) need to be visible for debugging or specific visual effects.

## Background
Face Culling is a standard optimization in voxel rendering, widely used in voxel games and terrain generation systems. It is often implemented alongside other optimizations such as VBO per chunk, frustum culling, and backface culling [S1, unofficial]. The technique is fundamental to achieving real-time performance in large-scale voxel environments.
