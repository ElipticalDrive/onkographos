# Face Culling

Also called: Exposure Culling, Neighbor Check Culling, Voxel Neighbor Face Culling

## Overview
Face Culling is a mesh generation optimization that reduces the number of vertices and triangles sent to the GPU by skipping the rendering of voxel faces that are adjacent to existing neighboring voxels [S1, unofficial]. It solves the problem of naively rendering all 6 faces of every cube, including those hidden by neighbors. It is distinguished from its siblings by performing a direct neighbor lookup for each face during mesh creation, rather than using bitwise bulk operations [S2, unofficial] or complex visibility masks [S3397-face-coverage-mask-culling.md].

## How it works
**Inputs:** A set of occupied voxel positions (typically stored in a hash set or grid) and a list of voxels to process.
**Outputs:** A vertex buffer containing only the visible faces of the voxel mesh.

**Data Structures:**
The method relies on a representation of voxel occupancy. In the primary implementation, this is a boolean grid or a hash set of occupied positions [S1, unofficial].
The `Cube` struct contains:
- `std::vector<Face> faces` (size 6)
- `glm::ivec3 cubeCenter`
- `glm::ivec3 gridPos`
- `int neighbors`

The `Face` struct contains:
- `std::vector<float> vertices`
- `glm::ivec3 normal`
- `bool isSideFace`
- `bool isBottomFace`
- `bool renderFlag`

**Steps:**
1. For each voxel, iterate through its six adjacent positions in the world grid [S1, unofficial].
2. For each face, calculate the position of the neighbor voxel: $P_{neighbor} = P_{current} + \vec{n}$, where $\vec{n}$ is the face's direction vector (e.g., $(1, 0, 0)$ for the +X face) [S1, unofficial].
3. Query the occupancy state of $P_{neighbor}$ [S1, unofficial].
4. Determine the `renderFlag` for the face based on the following logic [S1, unofficial]:
   - If the face is a bottom face (`isBottomFace` is true), set `renderFlag` to false (always culled) [S1, unofficial].
   - If the face is a side face (`isBottomFace` is false):
     - Check if a neighbor exists directly above the neighbor position: $P_{above} = P_{neighbor} + (0, 1, 0)$ [S1, unofficial].
     - If a neighbor exists at $P_{above}$, set `renderFlag` to false [S1, unofficial].
     - Otherwise, set `renderFlag` to true if no neighbor exists at $P_{neighbor}$, and false if a neighbor exists at $P_{neighbor}$ [S1, unofficial].
5. If `renderFlag` is true, add the face's vertices to the vertex buffer [S1, unofficial].

**Pseudocode:**
```python
def generate_mesh(occupied_positions: set, voxels: list) -> list:
    """
    Generates a mesh by culling faces adjacent to other voxels.
    
    Args:
        occupied_positions: A set of glm::ivec3 representing occupied voxel coordinates.
        voxels: A list of Cube objects, each containing faces and grid position.
        
    Returns:
        A list of vertices for the visible faces.
    """
    visible_vertices = []
    
    for cube in voxels:
        for face in cube.faces:
            # Calculate neighbor position based on face normal
            neighbor_pos = cube.cubeCenter + face.normal
            
            # Check if neighbor exists
            neighbor_exists = neighbor_pos in occupied_positions
            
            # Determine render flag
            if face.isBottomFace:
                # Bottom faces are always culled regardless of neighbors below
                render_flag = False
            else:
                # For side faces, check if there is a neighbor directly above the neighbor position
                # This handles cases where a higher voxel overhangs the current face
                above_neighbor_pos = neighbor_pos + glm_ivec3(0, 1, 0)
                above_neighbor_exists = above_neighbor_pos in occupied_positions
                
                if above_neighbor_exists:
                    render_flag = False
                else:
                    # If no overhang, cull if direct neighbor exists
                    render_flag = not neighbor_exists
            
            # If face is visible, add its vertices to the buffer
            if render_flag:
                visible_vertices.extend(face.vertices)
                
    return visible_vertices
```

**Parameters:**
- `occupied_positions`: The data structure holding voxel occupancy. A hash set (`std::unordered_set<glm::ivec3>`) is used for $O(1)$ average lookup time [S1, unofficial].
- `voxels`: The list of voxels to process.

**Edge Cases and Pitfalls:**
- **Bottom Face Culling:** Bottom faces are always culled (`renderFlag = false`) regardless of whether there is a neighbor below [S1, unofficial]. This implies the mesh is designed for a top-down view or that bottom faces are handled separately/not needed for the specific use case [S1, unofficial].
- **Overhang Handling:** Side faces are culled not only if a direct neighbor exists, but also if a neighbor exists directly above the neighbor position [S1, unofficial]. This prevents rendering faces that are occluded by overhanging voxels.
- **Performance:** The culling check runs once during mesh creation, resulting in no framerate loss during rendering [S1, unofficial]. However, the original approach of checking each of the six faces by looping through neighbors and performing random memory access can lead to poor performance if not optimized [S2, unofficial].

## Subtopics

### Binary Hidden-Face Culling
A technique to reduce the number of faces in a voxel mesh by removing those completely hidden (adjacent to another voxel), using bitwise operations on a bitmask representation of voxels to determine visible faces in bulk [S2, unofficial]. It differs from standard Face Culling by processing entire rows or columns of voxels at once using shifts and bitwise AND/OR operations, rather than checking individual voxel neighbors [S2, unofficial]. Choose this method when performance is critical and voxels can be represented as a linear bitmask [S2, unofficial]. Pitfall: The original approach of checking each of the six faces by looping through neighbors and performing random memory access leads to very poor performance [S2, unofficial].

## Operating characteristics
**Time Complexity:** $O(V)$, where $V$ is the number of voxels, assuming $O(1)$ lookup in the occupancy structure [S1, unofficial].
**Memory Complexity:** $O(V)$ for storing the voxel data and the resulting mesh [S1, unofficial].
**Measured Performance:** 4096 cubes rendered at ~60 FPS on the author's system [S1, unofficial].
**Strengths:** Simple to implement; reduces GPU draw calls and vertex count significantly; no runtime overhead during rendering [S1, unofficial].
**Limitations:** Requires a full mesh rebuild when the voxel world changes; bottom faces are always culled in the primary implementation [S1, unofficial].
**When to use:** Static or infrequently changing voxel worlds where mesh generation cost is acceptable [S1, unofficial].
**When not to use:** Highly dynamic worlds requiring frequent mesh updates, or when bottom faces are required [S1, unofficial].

## Background
Face Culling is a standard optimization in voxel terrain generation, first popularized by games like Minecraft. The specific implementation described here, including the `Cube` struct and `renderCheck` logic, originates from the open-source project `cadenmbond/Voxel-Terrain-Generation` [S1, unofficial]. The Binary Hidden-Face Culling variant was developed by Yunasawa for the project `YNL - Vozel` [S2, unofficial].
