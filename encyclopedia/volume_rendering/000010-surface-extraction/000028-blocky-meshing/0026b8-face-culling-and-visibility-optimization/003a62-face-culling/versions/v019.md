# Face Culling

Also called: Exposure Culling, Neighbor Check Culling, Voxel Neighbor Face Culling

## Overview
Face Culling is a mesh generation optimization that reduces the number of vertices sent to the GPU by skipping the rendering of voxel faces that are adjacent to existing neighboring voxels [S1, unofficial]. It solves the problem of naively rendering all 6 faces of every cube, including those hidden by neighbors. It sets itself apart from its siblings by performing this check during the mesh creation phase rather than relying on hardware depth testing or complex visibility pre-processing, resulting in no framerate loss during rendering [S1, unofficial].

## How it works
**Inputs:** A set of occupied voxel positions (typically stored in a hash set or grid) and a list of voxels to process.
**Outputs:** A vertex buffer containing only the exposed faces of the voxels.

**Data Structures:**
The method relies on checking neighbor existence. A common implementation uses a `Cube` struct and a `Face` struct [S1, unofficial]:
*   `Cube`:
    *   `faces`: `std::vector<Face>` of size 6, representing the 6 potential faces.
    *   `cubeCenter`: `glm::ivec3`, the world grid position of the voxel.
    *   `gridPos`: `glm::ivec3`, the local grid position.
    *   `neighbors`: `int`, count of specific neighbors (used for optimization in some variants).
*   `Face`:
    *   `vertices`: `std::vector<float>`, the vertex data for the face.
    *   `normal`: `glm::ivec3`, the direction the face points.
    *   `isSideFace`: `bool`, true if the face is not the bottom.
    *   `isBottomFace`: `bool`, true if the face is the bottom.
    *   `renderFlag`: `bool`, determines if the face is added to the mesh.

**Steps:**
1.  Iterate through each voxel in the world grid.
2.  For each voxel, iterate through its 6 potential faces.
3.  For each face, calculate the position of the neighbor in that direction:
    $$ P_{neighbor} = P_{current} + N_{face} $$
    Where $P_{current}$ is the voxel's center position and $N_{face}$ is the normal vector of the face (e.g., $(0, 1, 0)$ for Up).
4.  Check if a voxel exists at $P_{neighbor}$ in the occupied positions set.
5.  Apply culling logic based on face type:
    *   **Bottom Faces:** Always set `renderFlag` to `false` (culled), regardless of neighbors below [S1, unofficial].
    *   **Side Faces:**
        *   If a neighbor exists at $P_{neighbor}$, set `renderFlag` to `false` [S1, unofficial].
        *   If no neighbor exists at $P_{neighbor}$, check if a neighbor exists directly above the neighbor position ($P_{neighbor} + (0, 1, 0)$). If such a neighbor exists, set `renderFlag` to `false`. Otherwise, set `renderFlag` to `true` [S1, unofficial].
6.  Add faces with `renderFlag` set to `true` to the vertex buffer.

**Pseudocode:**
```python
def generate_mesh(occupied_positions: set[Vector3i], voxels: list[Cube]) -> list[Face]:
    """
    Generates a mesh by culling hidden faces.
    :param occupied_positions: Set of all occupied voxel coordinates.
    :param voxels: List of Cube objects to process.
    :return: List of Face objects to render.
    """
    mesh_faces = []
    
    # Define directions for side faces (Up, Down, Left, Right, Front, Back)
    # Note: The specific logic in [S1, unofficial] treats Bottom separately.
    # We assume standard axes: Y is Up.
    directions = [
        Vector3i(0, 1, 0),  # Up
        Vector3i(0, -1, 0), # Down (Bottom)
        Vector3i(-1, 0, 0), # Left
        Vector3i(1, 0, 0),  # Right
        Vector3i(0, 0, -1), # Front
        Vector3i(0, 0, 1)   # Back
    ]
    
    for cube in voxels:
        for face in cube.faces:
            # Calculate neighbor position
            neighbor_pos = cube.cubeCenter + face.normal
            
            # Check if neighbor exists
            neighbor_exists = neighbor_pos in occupied_positions
            
            # Apply culling rules
            if face.isBottomFace:
                # Bottom faces are always culled [S1, unofficial]
                face.renderFlag = False
            else:
                # Side faces
                if neighbor_exists:
                    # Neighbor directly adjacent -> cull
                    face.renderFlag = False
                else:
                    # No direct neighbor. Check if neighbor above the neighbor exists.
                    # This handles cases where a voxel is exposed but "under" an overhang?
                    # According to [S1, unofficial]: "Side faces ... are culled if a neighbor exists 
                    # directly adjacent OR if a neighbor exists directly above the neighbor position"
                    above_neighbor_pos = neighbor_pos + Vector3i(0, 1, 0)
                    above_neighbor_exists = above_neighbor_pos in occupied_positions
                    
                    if above_neighbor_exists:
                        face.renderFlag = False
                    else:
                        face.renderFlag = True
            
            if face.renderFlag:
                mesh_faces.append(face)
                
    return mesh_faces
```

**Parameters:**
*   `occupied_positions`: Typically a `std::unordered_set<glm::ivec3>` or similar hash set for $O(1)$ lookup [S1, unofficial].
*   `voxels`: The list of active voxel chunks or individual cubes.

**Edge Cases and Pitfalls:**
*   **Bottom Face Culling:** The implementation in [S1, unofficial] explicitly culls all bottom faces (`isBottomFace` logic). This may be intentional for terrain generation (where the bottom is hidden by the ground) but must be noted as a deviation from general voxel culling [S1, unofficial].
*   **Overhang Logic:** The check for `neighborPos + (0, 1, 0)` for side faces suggests a specific handling for overhangs or specific lighting/visibility requirements not standard in all voxel engines. Standard face culling only checks for the direct neighbor [S1, unofficial].
*   **Performance:** The original approach of looping through neighbors with random memory access leads to poor performance. Using a hash set or contiguous grid array is recommended [S2, unofficial].

## Subtopics

### Binary Hidden-Face Culling
A technique to reduce the number of faces in a voxel mesh by removing those completely hidden (adjacent to another voxel), using bitwise operations on a bitmask representation of voxels to determine visible faces in bulk [S2, unofficial]. It sets itself apart by processing entire rows or slices of voxels at once using bitwise shifts, avoiding per-voxel loops and random memory access [S2, unofficial]. Choose this when working with 1D slices or linearized memory layouts where bitwise parallelism can be exploited. It is a variant of Face Culling optimized for performance [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(V)$ where $V$ is the number of voxels, assuming $O(1)$ neighbor lookup. The bitwise variant reduces constant factors significantly by processing bits in parallel [S2, unofficial].
*   **Memory Complexity:** $O(V)$ to store the voxel data and the resulting mesh. The bitmask approach requires $O(V)$ bits for the mask [S2, unofficial].
*   **Measured Performance:** 4096 cubes rendered at ~60 FPS on the author's system [S1, unofficial].
*   **Strengths:** No framerate loss during rendering as culling happens at mesh creation time [S1, unofficial]. Simple to implement [S1, unofficial].
*   **Limitations:** The specific pitfall of bottom-face culling in [S1, unofficial] may not be suitable for all applications (e.g., floating islands). The bitwise approach is limited to 1D slices or requires complex 3D bit manipulation [S2, unofficial].
*   **When to use:** When static meshes are generated and the number of hidden faces is high.
*   **When not to use:** When the voxel world changes frequently and mesh regeneration is expensive, or when bottom faces need to be visible.

## Background
Face Culling is a standard optimization in voxel rendering. The specific implementation details regarding bottom-face culling and overhang checks were documented in a GitHub repository by cadenmbond [S1, unofficial]. The binary hidden-face culling variant was described in a devlog by Yunasawa for the project "YNL - Vozel" [S2, unofficial].
