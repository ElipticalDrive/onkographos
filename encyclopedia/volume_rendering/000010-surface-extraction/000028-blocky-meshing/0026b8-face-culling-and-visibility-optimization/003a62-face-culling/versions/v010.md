# Face Culling

Also called: Exposure Culling, Neighbor Check Culling, Voxel Neighbor Face Culling

## Overview
Face Culling is a mesh generation optimization that reduces the number of vertices sent to the GPU by skipping the rendering of voxel faces that are adjacent to existing neighboring voxels [S1, unofficial]. It solves the problem of naively rendering all 6 faces of every cube, including those hidden by neighbors. It sets itself apart from its siblings by relying on direct local topology checks (neighbor existence) rather than coverage masks, backface culling, or global visibility preprocessing.

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D grid of voxel occupancy data (solid/empty) and a list of voxel positions.
*   **Output:** A vertex buffer containing only the exposed faces of solid voxels.

**Data Structures:**
The method relies on checking the occupancy state of immediate neighbors. A common implementation uses a hash set or grid lookup for $O(1)$ neighbor checks [S1, unofficial].

*   `occupiedPositions`: A set or grid mapping `glm::ivec3` (or equivalent integer coordinate) to boolean occupancy.
*   `Cube` struct (per voxel):
    *   `cubeCenter`: `glm::ivec3` - The integer coordinates of the voxel's center or minimum corner.
    *   `gridPos`: `glm::ivec3` - The grid position.
    *   `neighbors`: `int` - Count of specific neighbors (implementation dependent).
    *   `faces`: `std::vector<Face>` (size 6) - One entry per face direction.
*   `Face` struct:
    *   `vertices`: `std::vector<float>` - The geometric vertices for this face.
    *   `normal`: `glm::ivec3` - The outward normal direction (e.g., `(1,0,0)` for right).
    *   `isSideFace`: `bool` - True if not the bottom face.
    *   `isBottomFace`: `bool` - True if this is the bottom face.
    *   `renderFlag`: `bool` - Whether to include this face in the final mesh.

**Steps:**
1.  Iterate through every voxel in the world grid.
2.  For each voxel, initialize its `faces` array with the 6 potential face geometries.
3.  For each face in the `faces` array:
    a. Calculate the position of the adjacent voxel in the direction of the face's normal:
       $$ P_{neighbor} = P_{current} + N_{face} $$
       where $P_{current}$ is the voxel's position and $N_{face}$ is the face normal.
    b. Check if a solid voxel exists at $P_{neighbor}$ in the `occupiedPositions` data structure.
    c. Apply culling logic based on face type:
       i. If the face is the **bottom face** ($isBottomFace == true$):
          Set `renderFlag = false`. The bottom face is always culled [S1, unofficial].
       ii. If the face is a **side face** ($isBottomFace == false$):
          Check if a neighbor exists directly adjacent ($P_{neighbor}$) OR if a neighbor exists directly above the neighbor position ($P_{neighbor} + (0,1,0)$).
          If either condition is true, set `renderFlag = false`.
          Otherwise, set `renderFlag = true` [S1, unofficial].
4.  Collect all faces where `renderFlag` is true into the vertex buffer.

**Pseudocode:**
```python
def generate_mesh(voxel_grid, occupied_positions):
    """
    voxel_grid: List of voxel objects, each having a 'pos' (vec3) and 'faces' (list of 6 Face objects)
    occupied_positions: Set of vec3 positions representing solid voxels
    """
    mesh_vertices = []

    for voxel in voxel_grid:
        for face in voxel.faces:
            # Calculate neighbor position
            neighbor_pos = voxel.pos + face.normal
            
            # Check direct neighbor existence
            neighbor_exists = neighbor_pos in occupied_positions
            
            # Apply culling rules
            if face.is_bottom_face:
                # Bottom faces are always culled
                face.render_flag = False
            else:
                # Side faces: check direct neighbor AND neighbor above
                neighbor_above_pos = neighbor_pos + vec3(0, 1, 0)
                neighbor_above_exists = neighbor_above_pos in occupied_positions
                
                if neighbor_exists or neighbor_above_exists:
                    face.render_flag = False
                else:
                    face.render_flag = True
            
            # If face is visible, add to mesh
            if face.render_flag:
                mesh_vertices.extend(face.vertices)
                
    return mesh_vertices
```

**Parameters:**
*   **Neighbor Check Radius:** 1 voxel (immediate neighbors only) [S1, unofficial].
*   **Bottom Face Culling:** Always enabled in the cited implementation [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Bottom Face Culling:** The cited implementation always culls bottom faces (`renderFlag = false`), regardless of whether there is a voxel below. This may be intentional for terrain (hiding the underside) but is a specific design choice, not a universal rule for all voxel engines [S1, unofficial].
*   **Overhang Culling Logic:** The side-face culling logic checks for a neighbor *above* the neighbor position (`neighborPos + (0,1,0)`). This implies that if a voxel is adjacent to the current voxel, but there is also a voxel directly above that adjacent voxel, the shared face is culled. This effectively culls faces that are "shadowed" by overhangs in the adjacent column. Implementers must verify if this matches their desired visual result, as standard face culling usually only checks the immediate neighbor [S1, unofficial].
*   **Performance:** The original naive approach of looping through neighbors with random memory access leads to poor performance. Using a hash set or direct grid indexing is recommended [S2, unofficial].

## Subtopics

### Binary Hidden-Face Culling
A technique to reduce the number of faces in a voxel mesh by removing those completely hidden (adjacent to another voxel), using bitwise operations on a bitmask representation of voxels to determine visible faces in bulk [S2, unofficial]. It sets itself apart by processing entire rows or columns of voxels in parallel using bitwise shifts, avoiding per-voxel loops and random memory access. Choose this when working with 1D slices or linearized bitmasks of voxel data for maximum throughput. It is a variant of Face Culling optimized for bulk processing [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(V)$ where $V$ is the number of voxels, assuming $O(1)$ neighbor lookup (hash set or direct grid access). The cited implementation performs a constant number of checks per face (6 faces per voxel) [S1, unofficial].
*   **Memory Complexity:** $O(V)$ to store the voxel grid and the resulting mesh. The bitmask variant reduces memory overhead for the culling logic itself but requires a contiguous bitmask representation [S2, unofficial].
*   **Measured Performance:** 4096 cubes rendered at ~60 FPS on the author's system [S1, unofficial].
*   **Strengths:** Simple to implement; runs once during mesh creation with no framerate loss during rendering; significantly reduces vertex count for dense terrain [S1, unofficial].
*   **Limitations:** The specific culling logic (culling bottom faces and checking above-neighbors) may not suit all use cases (e.g., floating islands, underground caves). The naive implementation suffers from cache misses if neighbor lookups are not optimized [S2, unofficial].
*   **When to use:** Static or semi-static voxel terrain where mesh generation is not per-frame.
*   **When not to use:** Highly dynamic scenes requiring per-frame mesh updates where the overhead of rebuilding the mesh outweighs the rendering savings, or when bottom faces must be visible.

## Background
Face Culling is a fundamental optimization in voxel-based game development and 3D modeling. It was popularized by games like *Minecraft* and various voxel editors to manage the high vertex count inherent in voxel representations. The specific implementation details cited here originate from community devlogs and open-source projects [S1, S2, unofficial]. The binary variant was developed to address performance bottlenecks in the naive neighbor-checking approach [S2, unofficial].
