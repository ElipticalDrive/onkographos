# ChunkMesh Vertex Packing and Management

Also called: Block Face Culling, Cube Face Mesh Generation

## Overview
ChunkMesh Vertex Packing and Management is a dynamic mesh generation and update technique for blocky voxel terrain that combines face culling with compact vertex storage and incremental buffer updates. It solves the problem of high memory overhead and frequent GPU buffer uploads in voxel rendering by packing vertex attributes into 32-bit integers and reusing vertex slots when faces are removed. It differs from static meshing by supporting incremental add/remove operations, and from simple face culling by managing the vertex buffer lifecycle (allocation, compaction via free-lists, and dynamic upload) [S1, unofficial].

## How it works
**Inputs:** Voxel world state (block types, chunk positions), camera position (for alpha sorting in translucent variants), and block change events (add/remove at specific coordinates).
**Outputs:** GPU vertex buffers (`vertex0`, `vertex1`, `indices`) containing only visible faces.

**Data Structures:**
The method maintains three JavaScript arrays (host-side) that are uploaded to GPU buffers:
1.  `vertex0`: `Uint32Array` of packed vertex positions.
2.  `vertex1`: `Uint32Array` of packed vertex attributes (texture, texcoords, lighting).
3.  `indices`: `Uint32Array` of triangle indices.
4.  `vertexSlots`: Stack of available vertex indices for reuse (free-list).

**Packed Layout:**
Each vertex is represented by two 32-bit unsigned integers.

*   `vertex0` (Position):
    *   Bits 0-9: X coordinate (10 bits, range 0-1023).
    *   Bits 10-19: Y coordinate (10 bits, range 0-1023).
    *   Bits 20-29: Z coordinate (10 bits, range 0-1023).
    *   Bits 30-31: Unused.
*   `vertex1` (Attributes):
    *   Bits 0-9: Texture layer index (10 bits).
    *   Bits 10-14: Texture coordinate U (5 bits, range 0-31).
    *   Bits 15-19: Texture coordinate V (5 bits, range 0-31).
    *   Bits 20-21: Lighting/shading value (2 bits, range 0-3).
    *   Bits 22-31: Unused.

**Parameters:**
*   Block size ($n$): 16 units.
*   Direction mapping: 0=+X, 1=-X, 2=+Y, 3=-Y, 4=+Z, 5=-Z.

**Algorithm Steps:**

1.  **Initialization:**
    *   Initialize `vertex0`, `vertex1`, `indices` as empty arrays.
    *   Initialize `vertexSlots` as empty stack.
    *   Set `update = false`.

2.  **Adding a Face (`addCubeFace`):**
    *   Input: Block position $(x, y, z)$, direction $dir$, texture key.
    *   Calculate vertex positions using `cubeFacePosition(x, y, z, dir)`. This returns 12 floats (4 vertices $\times$ 3 coords).
    *   Calculate texture coordinates using `cubeFaceTexcoord(dir)`. This returns 8 floats (4 vertices $\times$ 2 coords).
    *   Determine lighting value $dLight$ using array `[1, 1, 3, 0, 2, 2][dir]`.
    *   Get a vertex index:
        *   If `vertexSlots` is not empty, pop `idx` from `vertexSlots`.
        *   Else, `idx = vertex0.length`.
    *   For each of the 4 vertices ($k=0$ to $3$):
        *   Extract position $(px, py, pz)$ from `cubeFacePosition` at offset $3k$.
        *   Extract texcoords $(tu, tv)$ from `cubeFaceTexcoord` at offset $2k$.
        *   Pack `vertex0`: `vertex0.push( px | (py << 10) | (pz << 20) )`.
        *   Pack `vertex1`: `vertex1.push( textureLayer | (tu << 10) | (tv << 15) | (dLight << 20) )`.
        *   Store `idx + k` in a local list.
    *   Push indices to `indices`: `[idx, idx+1, idx+2, idx+2, idx+3, idx]` (two triangles).
    *   Set `update = true`.

3.  **Removing a Face (`removeFace`):**
    *   Input: Face position (array of 12 floats representing the 4 vertices).
    *   Find the starting index in `vertex0` using `findFace(facePosition)`.
        *   Iterate `i` from 0 to `vertex0.length` with step 4.
        *   Skip if `vertex0[i]` is NaN.
        *   Reconstruct packed `vertex0` for each of the 4 vertices of the target face and compare against `vertex0[i...i+3]`.
        *   If match, return `i`. Else return -1.
    *   If not found, return.
    *   Mark vertices as invalid: Set `vertex0[i...i+3]` and `vertex1[i...i+3]` to `NaN`.
    *   Remove indices: Find the starting index in `indices` corresponding to vertex index `i` (using `findIndex` which scans for `i` in `indices` with step 6). Remove 6 elements from `indices` starting at that offset.
    *   Push `i` to `vertexSlots` for reuse.
    *   Set `update = true`.

4.  **Updating Block Interaction (`updateBlock`):**
    *   Input: Block position $(x, y, z)$, action `add` (true for add, false for remove), block data.
    *   Iterate $dir$ from 0 to 5.
    *   Calculate neighbor position $P_{neighbor} = P + N_{dir}$.
    *   Get neighbor block data and info.
    *   Determine face interaction using `faceInteraction(blockData0, blockData1, add, dir, blockInfo0, blockInfo1)`.
        *   Logic:
            *   If `add` is true:
                *   Add face if neighbor is invisible/translucent/transparent AND block types differ.
                *   Remove face if neighbor is NOT invisible AND current block is NOT translucent/transparent OR block types are identical.
            *   If `add` is false:
                *   Reverse the logic (Remove face if neighbor is invisible/translucent/transparent AND types differ; Add face if neighbor is NOT invisible AND current is NOT translucent/transparent OR types identical).
    *   If `addFace` is true:
        *   If adding block: Call `addCubeFace` on current chunk.
        *   If removing block: Call `addCubeFace` on neighbor chunk (load neighbor mesh if needed). Direction for neighbor is $dir + (dir \% 2 === 0 ? 1 : -1)$.
    *   If `removeFace` is true:
        *   If adding block: Call `removeFace` on neighbor chunk.
        *   If removing block: Call `removeFace` on current chunk.

5.  **Buffer Upload (`updateBuffers`):**
    *   If `update` is true:
        *   Bind VAO.
        *   Upload `vertex0` to `vertex0Buffer` using `gl.DYNAMIC_DRAW`.
        *   Upload `vertex1` to `vertex1Buffer` using `gl.DYNAMIC_DRAW`.
        *   Upload `indices` to `indexBuffer` using `gl.DYNAMIC_DRAW`.
        *   Set `update = false`.

**Pseudocode:**

```python
def add_vertex(vertex0, vertex1, vertexSlots, x, y, z, textureLayer, texcoordX, texcoordY, dLight):
    # Pack position
    packed_pos = x | (y << 10) | (z << 20)
    # Pack attributes
    packed_attr = textureLayer | (texcoordX << 10) | (texcoordY << 15) | (dLight << 20)
    
    # Get index
    if vertexSlots:
        idx = vertexSlots.pop()
    else:
        idx = len(vertex0)
        
    vertex0.append(packed_pos)
    vertex1.append(packed_attr)
    return idx

def add_cube_face(vertex0, vertex1, indices, vertexSlots, x, y, z, dir, textureLayer):
    n = 16
    # Calculate positions and texcoords based on dir
    # This is a simplified representation; actual implementation uses switch/case
    positions = get_cube_face_positions(x, y, z, dir, n)
    texcoords = get_cube_face_texcoords(dir)
    dLight = [1, 1, 3, 0, 2, 2][dir]
    
    # Add 4 vertices
    v_indices = []
    for k in range(4):
        px, py, pz = positions[3*k], positions[3*k+1], positions[3*k+2]
        tu, tv = texcoords[2*k], texcoords[2*k+1]
        # Normalize texcoords to 0-31 range for packing if needed, or use raw
        # Assuming texcoords are already scaled or need scaling
        tu_packed = int(tu * 31) # Example scaling
        tv_packed = int(tv * 31)
        
        idx = add_vertex(vertex0, vertex1, vertexSlots, px, py, pz, textureLayer, tu_packed, tv_packed, dLight)
        v_indices.append(idx)
        
    # Add indices (two triangles)
    indices.extend([v_indices[0], v_indices[1], v_indices[2], v_indices[2], v_indices[3], v_indices[0]])
    
def remove_face(vertex0, vertex1, indices, vertexSlots, face_positions):
    start_idx = find_face(vertex0, face_positions)
    if start_idx == -1:
        return
        
    # Mark as NaN
    for k in range(4):
        vertex0[start_idx + k] = float('nan')
        vertex1[start_idx + k] = float('nan')
        
    # Remove indices
    idx_start = find_index_in_indices(indices, start_idx)
    if idx_start != -1:
        del indices[idx_start : idx_start + 6]
        
    # Push to free list
    vertexSlots.append(start_idx)

def find_face(vertex0, face_positions):
    for i in range(0, len(vertex0), 4):
        if vertex0[i] != vertex0[i]: # Check for NaN
            continue
        # Reconstruct packed positions for comparison
        p0 = face_positions[0] | (face_positions[1] << 10) | (face_positions[2] << 20)
        p1 = face_positions[3] | (face_positions[4] << 10) | (face_positions[5] << 20)
        p2 = face_positions[6] | (face_positions[7] << 10) | (face_positions[8] << 20)
        p3 = face_positions[9] | (face_positions[10] << 10) | (face_positions[11] << 20)
        
        if vertex0[i] == p0 and vertex0[i+1] == p1 and vertex0[i+2] == p2 and vertex0[i+3] == p3:
            return i
    return -1

def find_index_in_indices(indices, vertex_idx):
    for i in range(0, len(indices), 6):
        if indices[i] == vertex_idx:
            return i
    return -1
```

**Edge Cases and Pitfalls:**
*   **Neighbor Chunk Loading:** When removing a block, the neighbor chunk's mesh must be loaded if it doesn't exist before adding the exposed face to it [S1, unofficial].
*   **Precision:** Coordinates are limited to 10 bits (0-1023). This implies a chunk size of $1024 \times 1024 \times 1024$ units or smaller, or requires chunk-relative coordinates. The block size is 16, so a chunk can hold $64 \times 64 \times 64$ blocks.
*   **NaN Handling:** Using `NaN` to mark deleted vertices requires careful handling in shaders and comparisons. `isNaN` checks are necessary during face search.

## Subtopics

### [Voxel Face Meshing with Packed Attributes](4153-voxel-face-meshing-with-packed-attributes.md)
A mesh generation technique for voxel terrain where vertex data (position, type, direction) is packed into a single float attribute to reduce buffer overhead, unpacked in the vertex shader, and used to generate quad faces for visible voxel surfaces.

### [Mesh Reindexing and Vertex Compaction](4160-mesh-reindexing-and-vertex-compaction.md)
This method reduces the memory footprint of a chunk-based mesh by removing unreferenced vertices and renumbering the remaining ones to form a dense, contiguous array. It solves the problem of sparse vertex buffers that arise during incremental blocky meshing, where vertices are allocated per voxel face but many are culled or unused. Unlike [Voxel Face Meshing with Packed Attributes](4153-voxel-face-meshing-with-packed-attributes.md), which focuses on storage layout, this method actively compacts the data. It differs from [Chunk Mesh Data Structure & Buffer Update](4182-chunk-mesh-data-structure-buffer-update.md) by performing the logical remapping rather than just updating buffer pointers.

### [Chunk Mesh Data Structure & Buffer Update](4182-chunk-mesh-data-structure-buffer-update.md)
This method manages the creation, population, and recycling of GPU vertex buffers for meshed chunk geometry by utilizing a single large Shader Storage Buffer (SSBO) known as the "MegaSSBO". It solves the problem of dynamic memory allocation overhead and fragmentation in voxel terrain rendering by implementing a free-list allocator within the SSBO to handle the variable face counts of individual chunks. It differs from per-chunk buffer allocation by centralizing memory management, and from static buffer approaches by supporting incremental updates and defragmentation.

### [Alpha/Translucent Block Rendering](4860-alpha-translucent-block-rendering.md)
Alpha/Translucent Block Rendering is a fragment-shader-based technique for rendering semi-transparent voxel blocks (such as water or glass) within a chunked voxel world. It solves the problem of visualizing translucent geometry without requiring complex ray-marching or volumetric accumulation per pixel, relying instead on standard rasterization with pre-computed vertex attributes. It differs from opaque block meshing by applying per-fragment shading and fog based on world-space depth, and from volumetric raycasting by operating on discrete mesh faces rather than continuous density fields.

## Operating characteristics
*   **Time Complexity:** Face addition/removal is $O(1)$ for buffer push/pop, but face removal requires $O(V)$ search for `findFace` and $O(I)$ search for `findIndex` where $V$ is number of vertices and $I$ is number of indices. In practice, with free-list reuse, vertex count is bounded by chunk size.
*   **Memory Complexity:** $O(F)$ where $F$ is number of visible faces. Each face uses 4 vertices (8 uints) and 6 indices (6 uints). Packing reduces vertex storage to 8 bytes per vertex (2 uints).
*   **Performance:** Dynamic draw hints allow efficient GPU updates. Reusing vertex slots avoids reallocation overhead.
*   **Strengths:** Low memory footprint due to packing; efficient incremental updates; simple implementation.
*   **Limitations:** Search-based removal is slow for large meshes; 10-bit coordinate limit restricts chunk size or requires relative coordinates; no support for complex geometry beyond quads.

## Background
Originating from the Exolands project (kvxy/exolands), this method is an unofficial implementation of chunk-based voxel meshing. It combines face culling with dynamic vertex management to handle real-time voxel terrain updates. The approach is common in voxel games like Minecraft for managing large, dynamic worlds.
