# ChunkMesh Vertex Packing and Management

Also called: Block Face Culling, Cube Face Mesh Generation

## Overview
ChunkMesh Vertex Packing and Management is a dynamic mesh generation and update technique for voxel terrain that minimizes memory bandwidth and buffer upload overhead by packing vertex attributes into dense 32-bit integer formats [S1, unofficial]. It solves the problem of sparse, high-latency vertex buffer updates in incremental blocky meshing by using a reusable vertex index pool and bitwise-packed data structures, allowing efficient addition and removal of individual voxel faces without reallocating GPU memory [S1, unofficial]. It differs from standard meshing by storing position, texture, and lighting data in two `uint32` values per vertex rather than separate floating-point arrays, and from static meshing by supporting runtime face culling and dynamic buffer updates via a `DYNAMIC_DRAW` hint [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Voxel world state (block types, chunk positions), camera position (for alpha sorting in variants), and block modification events (add/remove).
*   **Output:** Updated GPU vertex buffers (`vertex0Buffer`, `vertex1Buffer`) and index buffer (`indexBuffer`) representing the visible faces of a chunk.

**Data Structures:**
The core data structure consists of three JavaScript arrays (mapped to GPU buffers):
1.  `vertex0`: `Uint32Array` storing packed position data.
2.  `vertex1`: `Uint32Array` storing packed texture and lighting data.
3.  `indices`: `Uint32Array` storing triangle indices.
4.  `vertexSlots`: Array acting as a free-list stack for reusable vertex indices.

**Bit Packing Layout:**
Each vertex is represented by two 32-bit unsigned integers. The layout is defined as follows [S1, unofficial]:

*   **`vertex0` (Position):**
    *   Bits 0–9: X coordinate (10 bits, range 0–1023).
    *   Bits 10–19: Y coordinate (10 bits, range 0–1023).
    *   Bits 20–29: Z coordinate (10 bits, range 0–1023).
    *   Bits 30–31: Unused.
    *   *Note:* The block size `n` is 16. Coordinates are scaled by `n` before packing.

*   **`vertex1` (Attributes):**
    *   Bits 0–9: Texture layer (10 bits).
    *   Bits 10–14: Texture coordinate X (5 bits, range 0–31).
    *   Bits 15–19: Texture coordinate Y (5 bits, range 0–31).
    *   Bits 20–21: Shading/Lighting value (2 bits, range 0–3).
    *   Bits 22–31: Unused.

**Numbered Steps:**

1.  **Face Visibility Determination:**
    For a block modification at $(x, y, z)$, iterate over the 6 neighbor directions $i \in \{0, \dots, 5\}$.
    *   Calculate neighbor coordinates $(tx, ty, tz)$.
    *   Retrieve neighbor block data and info.
    *   Determine if a face needs to be added or removed based on `faceInteraction` logic (see below).
    *   If adding a face to the current chunk, call `addCubeFace`. If adding to a neighbor chunk, load the neighbor's mesh if necessary and call `addCubeFace` on it.
    *   If removing a face, call `removeFace`.

2.  **Face Interaction Logic:**
    The decision to add or remove a face between `blockData0` (current) and `blockData1` (neighbor) depends on the operation (`add` = true for block addition, false for block removal) and block properties (invisible, translucent, transparent, type) [S1, unofficial]:
    *   **Adding a block (`add=true`):**
        *   Add face if: Neighbor is invisible/translucent/transparent AND block types differ.
        *   Remove face (from neighbor) if: Neighbor is NOT invisible AND (Current is NOT translucent/transparent OR block types are identical).
    *   **Removing a block (`add=false`):**
        *   Remove face (from current) if: Neighbor is invisible/translucent/transparent AND block types differ.
        *   Add face (to neighbor) if: Neighbor is NOT invisible AND (Current is NOT translucent/transparent OR block types are identical).
    *   *Note:* If the current block is invisible, no faces are added or removed.

3.  **Vertex Index Management:**
    *   When adding a vertex, check `vertexSlots`. If non-empty, pop the top index `idx` for reuse. Otherwise, push a new index to the end of `vertex0` and `vertex1`.
    *   Set `this.update = true` to trigger buffer refresh.

4.  **Adding a Cube Face:**
    *   Call `cubeFacePosition(x, y, z, dir)` to get 12 floats (4 vertices $\times$ 3 coords).
    *   Call `cubeFaceTexcoord(orientation)` to get 8 floats (4 vertices $\times$ 2 texcoords).
    *   Determine lighting `dLight` using the array `[1, 1, 3, 0, 2, 2][dir]`.
    *   Call `addVertex` for each of the 4 vertices (a, b, c, d), passing the reused/new index.
    *   Push indices `(a, b, c, c, d, a)` to the `indices` array.

5.  **Removing a Face:**
    *   Call `findFace(facePosition)` to locate the starting index of the 4 vertices in `vertex0`.
    *   If found, set `vertex0` and `vertex1` values at indices `i, i+1, i+2, i+3` to `NaN`.
    *   Remove the 6 corresponding indices from the `indices` array using `splice`.
    *   Push the starting vertex index `i` to `vertexSlots` for reuse.
    *   Set `this.update = true`.

6.  **Buffer Update:**
    *   If `this.update` is true, bind the VAO and upload `vertex0`, `vertex1`, and `indices` to GPU buffers using `gl.DYNAMIC_DRAW`.
    *   Reset `this.update = false`.

**Pseudocode:**

```python
# Constants
BLOCK_SIZE = 16
LIGHTING_VALUES = [1, 1, 3, 0, 2, 2]
DIRECTION_MAP = {
    0: [1, 0, 0],   # +X
    1: [-1, 0, 0],  # -X
    2: [0, 1, 0],   # +Y
    3: [0, -1, 0],  # -Y
    4: [0, 0, 1],   # +Z
    5: [0, 0, -1]   # -Z
}

class ChunkMesh:
    def __init__(self):
        self.vertex0 = []  # Uint32Array
        self.vertex1 = []  # Uint32Array
        self.indices = []  # Uint32Array
        self.vertexSlots = []  # Stack for reusable indices
        self.update = False

    def pack_vertex0(self, x, y, z):
        # x, y, z are integers in [0, 1023]
        return (x & 0x3FF) | ((y & 0x3FF) << 10) | ((z & 0x3FF) << 20)

    def pack_vertex1(self, texture_layer, texcoord_x, texcoord_y, d_light):
        # texcoord_x, texcoord_y in [0, 31]
        # d_light in [0, 3]
        return (texture_layer & 0x3FF) | \
               ((texcoord_x & 0x1F) << 10) | \
               ((texcoord_y & 0x1F) << 15) | \
               ((d_light & 0x3) << 20)

    def cube_face_position(self, x, y, z, dir):
        # x, y, z are block coordinates (integers)
        # Returns list of 12 floats: [x0,y0,z0, x1,y1,z1, x2,y2,z2, x3,y3,z3]
        bx = x * BLOCK_SIZE
        by = y * BLOCK_SIZE
        bz = z * BLOCK_SIZE
        n = BLOCK_SIZE
        
        if dir == 0: # +X
            return [bx+n, by, bz, bx+n, by+n, bz, bx+n, by+n, bz+n, bx+n, by, bz+n]
        elif dir == 1: # -X
            return [bx, by, bz, bx, by, bz+n, bx, by+n, bz+n, bx, by+n, bz]
        elif dir == 2: # +Y
            return [bx, by+n, bz, bx, by+n, bz+n, bx+n, by+n, bz+n, bx+n, by+n, bz]
        elif dir == 3: # -Y
            return [bx+n, by, bz+n, bx, by, bz+n, bx, by, bz, bx+n, by, bz]
        elif dir == 4: # +Z
            return [bx, by, bz+n, bx+n, by, bz+n, bx+n, by+n, bz+n, bx, by+n, bz+n]
        elif dir == 5: # -Z
            return [bx, by, bz, bx, by+n, bz, bx+n, by+n, bz, bx+n, by, bz]

    def cube_face_texcoord(self, orientation):
        # orientation derived from dir: [2, 3, 0, 0, 3, 2][dir]
        # Returns list of 8 floats: [u0,v0, u1,v1, u2,v2, u3,v3]
        # Mapping based on source:
        # 0: [0,0, 0,16, 16,16, 16,0]
        # 1: [16,0, 0,0, 0,16, 16,16]
        # 2: [0,0, 0,16, 16,16, 16,0] (Same as 0 in source snippet, assuming standard UV)
        # 3: [16,0, 0,0, 0,16, 16,16] (Same as 1)
        # 4: [0,0, 0,16, 16,16, 16,0]
        # 5: [16,0, 0,0, 0,16, 16,16]
        # Note: Source snippet cuts off, but implies standard quad UVs.
        # Using generic mapping for implementation completeness:
        if orientation == 0: return [0, 0, 0, 16, 16, 16, 16, 0]
        elif orientation == 1: return [16, 0, 0, 0, 0, 16, 16, 16]
        elif orientation == 2: return [0, 0, 0, 16, 16, 16, 16, 0]
        elif orientation == 3: return [16, 0, 0, 0, 0, 16, 16, 16]
        elif orientation == 4: return [0, 0, 0, 16, 16, 16, 16, 0]
        elif orientation == 5: return [16, 0, 0, 0, 0, 16, 16, 16]
        return [0, 0, 0, 16, 16, 16, 16, 0]

    def add_vertex(self, pos, texture, texcoord, d_light, vertex_index):
        # pos: [x, y, z]
        # texture: int
        # texcoord: [u, v]
        # d_light: int
        v0 = self.pack_vertex0(int(pos[0]), int(pos[1]), int(pos[2]))
        # Scale texcoords to 0-31 range (source uses *0.0625f in shader, so 1/16)
        # 16 * 0.0625 = 1.0. So texcoord 16 maps to 1.0.
        # To pack, we need integer representation. 
        # Source: float texcoordX = float((vertex1 & 31744u) >> 10u) * 0.0625f;
        # So if we want 0.0, pack 0. If we want 1.0, pack 16.
        tx = int(texcoord[0] / 0.0625) & 0x1F
        ty = int(texcoord[1] / 0.0625) & 0x1F
        
        v1 = self.pack_vertex1(texture, tx, ty, d_light)
        
        if vertex_index >= 0:
            self.vertex0[vertex_index] = v0
            self.vertex1[vertex_index] = v1
        else:
            self.vertex0.append(v0)
            self.vertex1.append(v1)
            vertex_index = len(self.vertex0) - 1
            
        self.update = True
        return vertex_index

    def add_cube_face(self, x, y, z, dir, texture):
        pos = self.cube_face_position(x, y, z, dir)
        texcoord = self.cube_face_texcoord([2, 3, 0, 0, 3, 2][dir])
        d_light = LIGHTING_VALUES[dir]
        
        # Get reusable index
        if self.vertexSlots:
            vertex_index = self.vertexSlots.pop()
        else:
            vertex_index = -1
            
        a = self.add_vertex(pos[0:3], texture, [texcoord[0], texcoord[1]], d_light, vertex_index)
        b = self.add_vertex(pos[3:6], texture, [texcoord[2], texcoord[3]], d_light, vertex_index + 1)
        c = self.add_vertex(pos[6:9], texture, [texcoord[4], texcoord[5]], d_light, vertex_index + 2)
        d = self.add_vertex(pos[9:12], texture, [texcoord[6], texcoord[7]], d_light, vertex_index + 3)
        
        self.indices.extend([a, b, c, c, d, a])
        self.update = True

    def find_face(self, face_position):
        # face_position: [x0,y0,z0, x1,y1,z1, x2,y2,z2, x3,y3,z3]
        # Reconstruct packed vertex0s
        p0 = self.pack_vertex0(int(face_position[0]), int(face_position[1]), int(face_position[2]))
        p1 = self.pack_vertex0(int(face_position[3]), int(face_position[4]), int(face_position[5]))
        p2 = self.pack_vertex0(int(face_position[6]), int(face_position[7]), int(face_position[8]))
        p3 = self.pack_vertex0(int(face_position[9]), int(face_position[10]), int(face_position[11]))
        
        for i in range(0, len(self.vertex0), 4):
            if self.vertex0[i] != self.vertex0[i]: # Check for NaN if using float, but here uint
                # In JS, NaN !== NaN. In Python, we might use a flag or specific value.
                # Assuming source uses NaN to mark deleted.
                # Python equivalent: check if value is a specific "deleted" marker or handle NaN separately.
                # For this pseudocode, we assume vertex0[i] is valid uint.
                # If source uses NaN, we must handle it.
                pass 
            
            if (self.vertex0[i] == p0 and 
                self.vertex0[i+1] == p1 and 
                self.vertex0[i+2] == p2 and 
                self.vertex0[i+3] == p3):
                return i
        return -1

    def remove_face(self, face_position):
        vertex_index = self.find_face(face_position)
        if vertex_index == -1:
            return
        
        # Mark as deleted (using NaN equivalent or specific marker)
        # In Python, we can't put NaN in Uint32. We'll use a specific "deleted" flag or just clear.
        # Source sets to NaN. We'll assume a helper or specific value.
        # For strict Python, we might use a separate boolean array or a sentinel value like 0xFFFFFFFF if not used.
        # However, to match source logic:
        self.vertex0[vertex_index] = float('nan') # Placeholder for NaN behavior
        self.vertex0[vertex_index+1] = float('nan')
        self.vertex0[vertex_index+2] = float('nan')
        self.vertex0[vertex_index+3] = float('nan')
        
        # Remove indices
        # Find start of indices for this face
        idx_start = -1
        for k in range(0, len(self.indices), 6):
            if self.indices[k] == vertex_index:
                idx_start = k
                break
        
        if idx_start != -1:
            del self.indices[idx_start:idx_start+6]
            
        self.vertexSlots.append(vertex_index)
        self.update = True

    def update_block(self, x, y, z, add, block_data):
        # Iterate 6 directions
        for i in range(6):
            # Calculate neighbor coords
            dx, dy, dz = DIRECTION_MAP[i]
            tx, ty, tz = x + dx, y + dy, z + dz
            
            # Get neighbor data (pseudo-code)
            neighbor_data = get_block_data(tx, ty, tz)
            if neighbor_data is None:
                continue
                
            neighbor_info = get_block_info(neighbor_data.type)
            current_info = get_block_info(block_data.type)
            
            add_face, remove_face = face_interaction(block_data, neighbor_data, add, i, current_info, neighbor_info)
            
            if add_face:
                if add:
                    self.add_cube_face(x, y, z, i, get_texture_key(current_info.texture[i]))
                else:
                    # Add to neighbor
                    neighbor_mesh = load_or_get_mesh(neighbor_info.shader, neighbor_data.chunk_pos)
                    if neighbor_mesh is None:
                        neighbor_mesh = load_chunk_mesh(neighbor_info.shader, neighbor_data.chunk_pos)
                    # Invert direction for neighbor
                    neighbor_dir = i + (1 if i % 2 == 0 else -1)
                    neighbor_mesh.add_cube_face(neighbor_data.x, neighbor_data.y, neighbor_data.z, neighbor_dir, get_texture_key(neighbor_info.texture[neighbor_dir]))
                    
            if remove_face:
                if add:
                    # Remove from neighbor
                    neighbor_mesh = load_or_get_mesh(neighbor_info.shader, neighbor_data.chunk_pos)
                    if neighbor_mesh:
                        neighbor_dir = i + (1 if i % 2 == 0 else -1)
                        neighbor_mesh.remove_face(neighbor_mesh.cube_face_position(neighbor_data.x, neighbor_data.y, neighbor_data.z, neighbor_dir))
                else:
                    # Remove from current
                    self.remove_face(self.cube_face_position(x, y, z, i))
                    
        if self.update:
            self.upload_buffers()

    def upload_buffers(self):
        # Bind VAO and upload to GPU
```

**Edge Cases and Pitfalls:**
*   **Neighbor Chunk Loading:** When adding a face to a neighbor chunk, the neighbor's mesh must be loaded if it does not already exist [S1, unofficial].
*   **Direction Inversion:** When updating a neighbor chunk, the direction index must be inverted: `i + (1 if i % 2 == 0 else -1)` to map the outward normal of the current block to the inward normal of the neighbor [S1, unofficial].
*   **NaN Handling:** The `findFace` function skips entries where `vertex0` is `NaN`. This requires careful handling in languages that do not support NaN in integer arrays [S1, unofficial].
*   **Precision:** Coordinates are limited to 10 bits (0–1023). With a block size of 16, the maximum chunk dimension is $1023 \times 16 = 16368$ units. This limits the size of a single chunk mesh [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Face addition/removal is $O(1)$ for index lookup if using a hash map, but the source implementation uses $O(V)$ linear search in `findFace` where $V$ is the number of vertices in the chunk [S1, unofficial]. Buffer upload is $O(V + I)$ where $I$ is the number of indices.
*   **Memory Complexity:** Each vertex uses 8 bytes (two `uint32`). Indices use 4 bytes each. The `vertexSlots` stack adds minimal overhead. This is significantly more compact than standard float-based vertex buffers (typically 32+ bytes per vertex).
*   **Performance:** The use of `DYNAMIC_DRAW` and packed integers reduces GPU memory bandwidth usage during updates. The linear search in `findFace` can become a bottleneck for large chunks with many faces [S1, unofficial].
*   **Strengths:** Low memory footprint, efficient reuse of vertex slots, simple implementation.
*   **Limitations:** Linear search for face removal, limited coordinate range (10 bits), requires careful handling of NaN in integer arrays.

## Background
The method originates from the Exolands voxel engine, an open-source project by kvxy [S1, unofficial]. It was developed to address the performance issues of naive voxel meshing, where individual cube models or large sparse buffers caused high draw calls and memory overhead. The technique is part of a broader family of blocky meshing optimizations that prioritize dynamic updates and compact data storage [S1, unofficial].
