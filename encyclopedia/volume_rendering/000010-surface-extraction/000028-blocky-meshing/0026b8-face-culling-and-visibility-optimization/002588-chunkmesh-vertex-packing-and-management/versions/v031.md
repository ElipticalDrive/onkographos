# ChunkMesh Vertex Packing and Management

Also called: Block Face Culling, Cube Face Mesh Generation

## Overview
ChunkMesh Vertex Packing and Management is a dynamic mesh generation and buffer management technique for blocky voxel terrain, designed to minimize GPU memory bandwidth and draw call overhead by packing vertex attributes into compact integer formats and managing vertex lifecycles via a free-list allocator [S1, unofficial]. It solves the problem of sparse, fragmented vertex buffers in incremental voxel meshing by reusing vertex slots and compacting data before upload [S1, unofficial]. Unlike static meshing methods, it supports real-time addition and removal of blocks with immediate neighbor face updates, ensuring consistency across chunk boundaries [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Voxel world state (block types, positions), camera position (for alpha sorting), and chunk boundaries.
*   **Output:** GPU vertex buffers (`vertex0`, `vertex1`) and index buffer (`indices`) representing visible voxel faces.

**Data Structures:**
Vertex data is packed into two 32-bit unsigned integers (`uint`) per vertex to reduce buffer size and improve cache efficiency [S1, unofficial].

*   **`vertex0` (Position):**
    *   Bits 0–9: X coordinate (10 bits, range 0–1023).
    *   Bits 10–19: Y coordinate (10 bits, range 0–1023).
    *   Bits 20–29: Z coordinate (10 bits, range 0–1023).
    *   Bits 30–31: Unused.
*   **`vertex1` (Attributes):**
    *   Bits 0–9: Texture layer index (10 bits).
    *   Bits 10–14: Texture coordinate X (5 bits, range 0–31).
    *   Bits 15–19: Texture coordinate Y (5 bits, range 0–31).
    *   Bits 20–21: Shading/Lighting value (2 bits, range 0–3).
    *   Bits 22–31: Unused.

The mesh maintains three arrays: `vertex0`, `vertex1`, and `indices` (element indices). A free-list `vertexSlots` stores indices of removed vertices for reuse [S1, unofficial].

**Numbered Steps:**

1.  **Face Generation:** For each visible voxel face, calculate the 4 vertex positions using `cubeFacePosition(x, y, z, dir)` where block size $n=16$ [S1, unofficial]. Directions 0–5 map to positive/negative X, Y, Z axes respectively [S1, unofficial].
2.  **Attribute Packing:**
    *   Compute texture coordinates using `cubeFaceTexcoord(orientation)`, mapping direction `dir` to orientation via `[2, 3, 0, 0, 3, 2][dir]` [S1, unofficial].
    *   Determine lighting value `dLight` using `[1, 1, 3, 0, 2, 2][dir]` [S1, unofficial].
    *   Pack position: `vertex0 = x | (y << 10) | (z << 20)` [S1, unofficial].
    *   Pack attributes: `vertex1 = textureLayer | (texcoordX << 10) | (texcoordY << 15) | (dLight << 20)` [S1, unofficial].
3.  **Vertex Allocation:**
    *   If `vertexSlots` is not empty, pop an index `idx` for reuse [S1, unofficial].
    *   Otherwise, push new values to `vertex0` and `vertex1` arrays, assigning indices `idx` to `idx+3` for the 4 vertices of the quad [S1, unofficial].
    *   Store packed `vertex0` and `vertex1` at the assigned indices [S1, unofficial].
4.  **Index Recording:** Push the 6 indices forming two triangles (`a, b, c, c, d, a`) to the `indices` array [S1, unofficial].
5.  **Face Removal:**
    *   Search for the face in `vertex0` using `findFace(facePosition)`, which reconstructs packed positions and compares them, skipping `NaN` entries [S1, unofficial].
    *   If found at index `i`, set `vertex0[i...i+3]` and `vertex1[i...i+3]` to `NaN` to mark them as free [S1, unofficial].
    *   Remove the 6 corresponding indices from the `indices` array using `splice` [S1, unofficial].
    *   Push `i` to `vertexSlots` for reuse [S1, unofficial].
6.  **Buffer Update:** Set `this.update = true`. When true, upload `vertex0`, `vertex1`, and `indices` to GPU buffers (`gl.DYNAMIC_DRAW`) [S1, unofficial].

**Pseudocode:**

```python
def add_cube_face(x, y, z, dir, texture_layer):
    # 1. Calculate positions
    n = 16
    positions = cube_face_position(x * n, y * n, z * n, dir) # Returns 12 floats (4 vertices)
    
    # 2. Calculate attributes
    orientation = [2, 3, 0, 0, 3, 2][dir]
    texcoords = cube_face_texcoord(orientation) # Returns 8 floats (4 u,v pairs)
    d_light = [1, 1, 3, 0, 2, 2][dir]
    
    # 3. Allocate vertex indices
    if vertex_slots is not empty:
        base_idx = vertex_slots.pop()
    else:
        base_idx = len(vertex0)
        
    # 4. Pack and store vertices
    for k in range(4):
        px, py, pz = positions[k*3], positions[k*3+1], positions[k*3+2]
        tx, ty = texcoords[k*2], texcoords[k*2+1]
        
        # Normalize texcoords to 0-31 range for 5-bit storage
        tx_idx = int(tx * 2) # Assuming texcoords are 0-16, scale to 0-31? 
                             # Source uses 0-16 range mapped to 5 bits. 
                             # Note: Source code shows texcoordX << 10, implying 5 bits.
                             # The source texcoord generation returns 0-16. 
                             # We assume the shader handles the scaling or the packing assumes 0-31.
                             # Based on source: float texcoordX = float((vertex1 & 31744u) >> 10u) * 0.0625f;
                             # 0.0625 is 1/16. So 5 bits (0-31) * 1/16 = 0-1.9375. 
                             # The source texcoords are 0-16. 16/16 = 1.0. 
                             # So we pack the raw 0-16 value into 5 bits? 
                             # 16 fits in 5 bits (0-31).
        
        v0 = int(px) | (int(py) << 10) | (int(pz) << 20)
        v1 = int(texture_layer) | (int(tx) << 10) | (int(ty) << 15) | (int(d_light) << 20)
        
        vertex0[base_idx + k] = v0
        vertex1[base_idx + k] = v1
        
    # 5. Add indices
    indices.append(base_idx)
    indices.append(base_idx + 1)
    indices.append(base_idx + 2)
    indices.append(base_idx + 2)
    indices.append(base_idx + 3)
    indices.append(base_idx)
    
    update = True

def remove_face(face_positions):
    # face_positions is a list of 12 floats (4 vertices)
    start_idx = find_face(face_positions)
    if start_idx == -1:
        return
        
    # Mark vertices as NaN
    for k in range(4):
        vertex0[start_idx + k] = float('nan')
        vertex1[start_idx + k] = float('nan')
        
    # Remove indices
    # Find the start of the 6 indices in the indices array
    # The source uses a linear search for the index start
    idx_start = find_index_in_indices(start_idx)
    if idx_start != -1:
        del indices[idx_start : idx_start + 6]
        
    # Recycle vertex slot
    vertex_slots.append(start_idx)
    update = True

def find_face(face_positions):
    # Reconstruct packed vertex0 for each of the 4 vertices
    packed_verts = []
    for k in range(4):
        px, py, pz = face_positions[k*3], face_positions[k*3+1], face_positions[k*3+2]
        packed_verts.append(int(px) | (int(py) << 10) | (int(pz) << 20))
        
    # Search vertex0 array in steps of 4
    for i in range(0, len(vertex0), 4):
        if isnan(vertex0[i]):
            continue
        if (vertex0[i] == packed_verts[0] and
            vertex0[i+1] == packed_verts[1] and
            vertex0[i+2] == packed_verts[2] and
            vertex0[i+3] == packed_verts[3]):
            return i
    return -1

def find_index_in_indices(start_vertex_idx):
    # Linear search for the start of the 6 indices corresponding to start_vertex_idx
    for i in range(0, len(indices), 6):
        if indices[i] == start_vertex_idx:
            return i
    return -1
```

**Parameters:**
*   Block size $n=16$ [S1, unofficial].
*   Vertex coordinate precision: 10 bits (range 0–1023) [S1, unofficial].
*   Texture coordinate precision: 5 bits (range 0–31) [S1, unofficial].
*   Lighting precision: 2 bits (range 0–3) [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Neighbor Chunk Loading:** When removing a block, if the neighbor chunk's mesh does not exist, it must be loaded before adding the exposed face to it [S1, unofficial].
*   **NaN Handling:** Removed vertices are marked with `NaN` in `vertex0` to skip them during face search, but `vertex1` is also set to `NaN` to maintain consistency [S1, unofficial].
*   **Index Consistency:** The `indices` array is not sorted, requiring linear search for removal [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Face addition/removal is $O(1)$ for allocation and $O(V)$ for face search (where $V$ is the number of vertices in the chunk) due to linear scan [S1, unofficial]. Buffer upload is $O(N)$ where $N$ is the number of vertices/indices [S1, unofficial].
*   **Memory Complexity:** Vertex data is reduced by 50% compared to standard float32 positions (using 2 uints vs 3 floats) [S1, unofficial].
*   **Performance:** Suitable for dynamic voxel worlds with frequent block changes [S1, unofficial].
*   **Strengths:** Low memory footprint, fast incremental updates, efficient vertex reuse [S1, unofficial].
*   **Limitations:** Linear search for face removal can be slow for large chunks; limited coordinate range (1024 units) [S1, unofficial].

## Background
The method originates from the Exolands project, a voxel-based game engine, where it was implemented to handle dynamic terrain generation and modification [S1, unofficial]. It addresses the specific needs of blocky meshing where faces are generated per-voxel and must be culled and managed in real-time [S1, unofficial].
