# ChunkMesh Vertex Packing and Management

Also called: Block Face Culling, Cube Face Mesh Generation

## Overview
ChunkMesh Vertex Packing and Management is a dynamic mesh generation and update technique for voxel terrain that combines face culling with compact vertex storage and efficient buffer synchronization. It solves the problem of high memory overhead and frequent GPU buffer updates in voxel engines by packing vertex attributes into 32-bit integers and reusing vertex slots to minimize the number of vertices uploaded to the GPU. It differs from static meshing by supporting incremental block addition/removal with neighbor-aware face updates, and from simple vertex buffering by using a free-list allocator (`vertexSlots`) to compact the vertex array without full reallocation.

## How it works
The method manages a chunk's geometry by maintaining arrays of packed vertex data and indices, updating them dynamically as blocks are added or removed. It relies on bitwise packing to store position, texture, and lighting data in minimal space, and uses a search-and-replace strategy for face removal to keep the vertex array dense.

### Inputs and Outputs
*   **Input**: Voxel world state (block types, chunk boundaries), camera position (for alpha sorting in translucent variants), and block modification events (add/remove at $x, y, z$).
*   **Output**: Updated GPU vertex buffers (`vertex0`, `vertex1`) and index buffer (`indices`) representing the visible surface of the chunk.

### Data Structures
The core data structures are three parallel arrays, converted to `Uint32Array` for GPU upload:

1.  **`vertex0`**: Stores position data packed into a 32-bit unsigned integer per vertex.
    *   **Layout**:
        *   Bits 0–9: X coordinate (10 bits).
        *   Bits 10–19: Y coordinate (10 bits).
        *   Bits 20–29: Z coordinate (10 bits).
        *   Bits 30–31: Unused.
    *   **Range**: Supports coordinates in the range $[0, 1023]$ per chunk axis. For a block size of $n=16$, this covers a chunk of $16 \times 16 \times 16$ blocks (256 units), which fits within 10 bits ($2^{10} = 1024$).

2.  **`vertex1`**: Stores texture and lighting data packed into a 32-bit unsigned integer per vertex.
    *   **Layout**:
        *   Bits 0–9: Texture layer index (10 bits).
        *   Bits 10–14: Texture coordinate U (5 bits).
        *   Bits 15–19: Texture coordinate V (5 bits).
        *   Bits 20–21: Lighting/shading value (2 bits).
        *   Bits 22–31: Unused.
    *   **Range**: Texture coordinates are normalized to $[0, 1]$ by multiplying the 5-bit integer by $0.0625$ ($1/32$). Lighting values are scaled by $0.2$ and offset by $0.4$ in the shader.

3.  **`indices`**: Stores triangle indices (unsigned integers) forming triangles from the vertex arrays. Each face consists of 6 indices (2 triangles).

4.  **`vertexSlots`**: A stack (array) storing available vertex indices for reuse. When a face is removed, its starting vertex index is pushed here. When a face is added, an index is popped from here if available; otherwise, new vertices are appended.

5.  **`update`**: A boolean flag. Set to `true` when the mesh changes, triggering a buffer upload to the GPU.

### Numbered Steps

#### 1. Face Visibility Determination
For each block modification, determine which faces need to be added or removed by checking the 6 cardinal neighbors.
*   Let $B_0$ be the current block and $B_1$ be the neighbor in direction $dir \in \{0, \dots, 5\}$.
*   Directions map to normals: 0: +X, 1: -X, 2: +Y, 3: -Y, 4: +Z, 5: -Z.
*   Use `faceInteraction(B_0, B_1, add, dir)` to decide:
    *   If adding a block ($add=true$):
        *   Add face if neighbor is invisible/translucent/transparent AND block types differ.
        *   Remove face (from neighbor) if neighbor is NOT invisible AND current block is NOT translucent/transparent OR block types are identical.
    *   If removing a block ($add=false$):
        *   Reverse the logic.

#### 2. Adding a Cube Face
When a face is determined to be visible:
1.  **Calculate Positions**: Call `cubeFacePosition(x, y, z, dir)` to get 12 floats (4 vertices $\times$ 3 coords). The block size $n=16$.
    *   Example for Dir 0 (+X): Vertices at $(x+16, y, z), (x+16, y+16, z), (x+16, y+16, z+16), (x+16, y, z+16)$.
2.  **Calculate Texture Coordinates**: Call `cubeFaceTexcoord(orientation)` where `orientation` maps from `dir` via `[2, 3, 0, 0, 3, 2][dir]`. Returns 8 floats (4 vertices $\times$ 2 coords).
3.  **Determine Lighting**: Get `dLight` from `[1, 1, 3, 0, 2, 2][dir]`.
4.  **Allocate Vertices**:
    *   Pop `vertexIndex` from `vertexSlots`. If empty, set `vertexIndex` to `vertex0.length`.
5.  **Pack and Store Vertices**: For each of the 4 vertices ($a, b, c, d$):
    *   Pack position: `v0 = x | (y << 10) | (z << 20)`
    *   Pack attributes: `v1 = textureLayer | (texcoordX << 10) | (texcoordY << 15) | (dLight << 20)`
    *   If `vertexIndex` was from `vertexSlots`, overwrite `vertex0[vertexIndex+i]` and `vertex1[vertexIndex+i]`. Else, `push` to `vertex0` and `vertex1`.
6.  **Store Indices**: Push 6 indices to `indices`: `a, b, c, c, d, a` (where $a,b,c,d$ are the assigned vertex indices).
7.  **Mark Update**: Set `this.update = true`.

#### 3. Removing a Cube Face
When a face is determined to be occluded or invalid:
1.  **Find Face**: Call `findFace(facePosition)` where `facePosition` is the array of 12 floats from `cubeFacePosition`.
    *   Iterate `vertex0` in steps of 4.
    *   Skip if `vertex0[i]` is `NaN`.
    *   Reconstruct packed positions for the 4 vertices of the target face and compare against `vertex0[i...i+3]`.
    *   Return the starting index `i` or -1.
2.  **Mark Vertices as Invalid**: If found, set `vertex0[i...i+3]` and `vertex1[i...i+3]` to `NaN`.
3.  **Remove Indices**: Find the index of the first vertex index in `indices` using `findIndex(i)`. Splice out the 6 corresponding indices.
4.  **Recycle Vertex Slot**: Push `i` to `vertexSlots`.
5.  **Mark Update**: Set `this.update = true`.

#### 4. Buffer Update
When `this.update` is true:
1.  Bind VAO.
2.  Upload `vertex0` to `vertex0Buffer` using `gl.bufferData(..., new Uint32Array(this.vertex0), gl.DYNAMIC_DRAW)`.
3.  Upload `vertex1` to `vertex1Buffer` using `gl.bufferData(..., new Uint32Array(this.vertex1), gl.DYNAMIC_DRAW)`.
4.  Upload `indices` to `indexBuffer` using `gl.bufferData(..., new Uint32Array(this.indices), gl.DYNAMIC_DRAW)`.
5.  Reset `this.update = false`.

### Pseudocode

```python
# Constants
BLOCK_SIZE = 16
DIR_LIGHTS = [1, 1, 3, 0, 2, 2]
DIR_TEXCOORDS = [2, 3, 0, 0, 3, 2]

class ChunkMesh:
    def __init__(self):
        self.vertex0 = []  # List of uint32
        self.vertex1 = []  # List of uint32
        self.indices = []  # List of uint32
        self.vertexSlots = []  # Stack of available vertex indices
        self.update = False

    def add_block(self, x, y, z, block_data):
        self.update_block(x, y, z, add=True, block_data=block_data)

    def remove_block(self, x, y, z, prev_block_data):
        self.update_block(x, y, z, add=False, block_data=prev_block_data)

    def update_block(self, x, y, z, add, block_data):
        # Check 6 neighbors
        for dir in range(6):
            tx, ty, tz = get_neighbor_coords(x, y, z, dir)
            neighbor_data = get_block_data(tx, ty, tz)
            if neighbor_data is None: continue
            
            add_face, remove_face = face_interaction(
                block_data, neighbor_data, add, dir
            )
            
            if add_face:
                if add:
                    self.add_cube_face(x, y, z, dir, get_texture(block_data, dir))
                else:
                    # Neighbor chunk needs to be loaded if not present
                    load_chunk_mesh(neighbor_data.chunk_pos)
                    neighbor_dir = dir + (1 if dir % 2 == 0 else -1)
                    self.add_cube_face(
                        tx, ty, tz, neighbor_dir, 
                        get_texture(neighbor_data, neighbor_dir)
                    )
            
            if remove_face:
                if add:
                    # Remove from neighbor
                    load_chunk_mesh(neighbor_data.chunk_pos)
                    neighbor_dir = dir + (1 if dir % 2 == 0 else -1)
                    self.remove_face(
                        get_cube_face_position(tx, ty, tz, neighbor_dir)
                    )
                else:
                    # Remove from current chunk
                    self.remove_face(get_cube_face_position(x, y, z, dir))
        
        if self.update:
            self.upload_buffers()

    def add_cube_face(self, x, y, z, dir, texture_layer):
        positions = get_cube_face_position(x, y, z, dir)
        texcoords = get_cube_face_texcoord(DIR_TEXCOORDS[dir])
        d_light = DIR_LIGHTS[dir]
        
        # Get reusable vertex index
        if self.vertexSlots:
            vertex_index = self.vertexSlots.pop()
        else:
            vertex_index = len(self.vertex0)
            
        # Add 4 vertices
        verts = []
        for i in range(4):
            vx, vy, vz = positions[i*3], positions[i*3+1], positions[i*3+2]
            tu, tv = texcoords[i*2], texcoords[i*2+1]
            
            # Pack vertex0
            v0 = vx | (vy << 10) | (vz << 20)
            # Pack vertex1
            # Normalize texcoords to 0-31 range for 5-bit storage
            tu_int = int(tu * 32) & 31
            tv_int = int(tv * 32) & 31
            v1 = texture_layer | (tu_int << 10) | (tv_int << 15) | (d_light << 20)
            
            if vertex_index + i < len(self.vertex0):
                self.vertex0[vertex_index + i] = v0
                self.vertex1[vertex_index + i] = v1
            else:
                self.vertex0.append(v0)
                self.vertex1.append(v1)
            verts.append(vertex_index + i)
            
        # Add indices
        self.indices.extend([verts[0], verts[1], verts[2], verts[2], verts[3], verts[0]])
        self.update = True

    def remove_face(self, face_position):
        vertex_index = self.find_face(face_position)
        if vertex_index == -1: return
        
        # Mark vertices as invalid
        for i in range(4):
            self.vertex0[vertex_index + i] = float('nan')
            self.vertex1[vertex_index + i] = float('nan')
            
        # Remove indices
        idx = self.find_index(vertex_index)
        if idx != -1:
            del self.indices[idx:idx+6]
            
        # Recycle slot
        self.vertexSlots.append(vertex_index)
        self.update = True

    def find_face(self, face_position):
        for i in range(0, len(self.vertex0), 4):
            if self.vertex0[i] != self.vertex0[i]: continue # Skip NaN
            
            # Reconstruct packed positions for comparison
            v0_check = face_position[0] | (face_position[1] << 10) | (face_position[2] << 20)
            v1_check = face_position[3] | (face_position[4] << 10) | (face_position[5] << 20)
            v2_check = face_position[6] | (face_position[7] << 10) | (face_position[8] << 20)
            v3_check = face_position[9] | (face_position[10] << 10) | (face_position[11] << 20)
            
            if (self.vertex0[i] == v0_check and
                self.vertex0[i+1] == v1_check and
                self.vertex0[i+2] == v2_check and
                self.vertex0[i+3] == v3_check):
                return i
        return -1

    def find_index(self, vertex_index):
        for i in range(0, len(self.indices), 6):
            if self.indices[i] == vertex_index:
                return i
        return -1

    def upload_buffers(self):
        # Pseudocode for GPU upload
        bind_vao()
        bind_buffer(ARRAY_BUFFER, vertex0_buffer)
        buffer_data(ARRAY_BUFFER, Uint32Array(self.vertex0), DYNAMIC_DRAW)
        bind_buffer(ARRAY_BUFFER, vertex1_buffer)
        buffer_data(ARRAY_BUFFER, Uint32Array(self.vertex1), DYNAMIC_DRAW)
        bind_buffer(ELEMENT_ARRAY_BUFFER, index_buffer)
        buffer_data(ELEMENT_ARRAY_BUFFER, Uint32Array(self.indices), DYNAMIC_DRAW)
        self.update = False
```

### Formulas and Parameters
*   **Vertex Packing**:
    $$ V_0 = x + (y \ll 10) + (z \ll 20) $$
    $$ V_1 = T + (U \ll 10) + (V \ll 15) + (L \ll 20) $$
    Where $x,y,z \in [0, 1023]$, $T \in [0, 1023]$, $U,V \in [0, 31]$, $L \in [0, 3]$.
*   **Shader Unpacking**:
    $$ x = V_0 \ \& \ 1023 $$
    $$ y = (V_0 \gg 10) \ \& \ 1023 $$
    $$ z = V_0 \gg 20 $$
    $$ T = V_1 \ \& \ 1023 $$
    $$ U = ((V_1 \gg 10) \ \& \ 31) \times 0.0625 $$
    $$ V = ((V_1 \gg 15) \ \& \ 31) \times 0.0625 $$
    $$ \text{Shade} = ((V_1 \gg 20) \ \& \ 3) \times 0.2 + 0.4 $$
*   **Direction Mapping**:
    *   0: +X, 1: -X, 2: +Y, 3: -Y, 4: +Z, 5: -Z.
    *   Neighbor Direction: $dir_{neighbor} = dir + (1 \text{ if } dir \% 2 == 0 \text{ else } -1)$.

### Edge Cases and Pitfalls
*   **Neighbor Chunk Loading**: When removing a block, the neighbor chunk's mesh must be loaded before adding the exposed face to it, otherwise the face addition will fail [S1, unofficial].
*   **NaN Handling**: Removed vertices are marked with `NaN` in `vertex0`. The `find_face` function must skip these entries to avoid false matches [S1, unofficial].
*   **Index Search**: The `indices` array is not sorted, so binary search cannot be used to find the start of a face's indices. A linear scan is required [S1, unofficial].
*   **Precision**: Coordinates are limited to 10 bits. Chunks larger than $1024$ units in any dimension will overflow. The block size $n=16$ is hardcoded in position generation [S1, unofficial].

## Operating characteristics
*   **Time Complexity**:
    *   Face Addition/Removal: $O(1)$ amortized for vertex allocation (due to slot reuse), but $O(V)$ for `find_face` where $V$ is the number of vertices in the chunk.
    *   Buffer Upload: $O(V + I)$ where $V$ is vertex count and $I$ is index count.
*   **Memory Complexity**: $O(V)$ for vertex arrays and $O(I)$ for index arrays. The packing reduces memory footprint by 50-75% compared to standard float32 vertex buffers.
*   **Performance**: Efficient for dynamic voxel worlds with frequent block changes. The slot reuse avoids memory fragmentation and frequent reallocations.
*   **Strengths**: Low memory usage, fast incremental updates, simple implementation.
*   **Limitations**: Linear search for face removal is slow for large chunks. Coordinate precision is limited to 10 bits per axis. Not suitable for very large continuous terrains without chunking.

## Background
This method originates from the Exolands voxel engine project, an open-source implementation of a Minecraft-like voxel world in JavaScript/HTML5. It was designed to provide efficient dynamic meshing for web-based voxel games, balancing performance and code simplicity. The technique is widely used in browser-based voxel engines where JavaScript performance and memory constraints are significant factors.
