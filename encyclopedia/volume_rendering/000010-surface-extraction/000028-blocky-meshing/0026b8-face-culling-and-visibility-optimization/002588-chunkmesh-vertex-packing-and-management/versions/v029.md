# ChunkMesh Vertex Packing and Management

Also called: Block Face Culling, Cube Face Mesh Generation

## Overview
ChunkMesh Vertex Packing and Management is a dynamic mesh generation and buffer management technique for voxel terrain, designed to minimize GPU memory overhead and draw calls by packing vertex attributes into compact integer formats and reusing vertex slots during incremental updates [S1, unofficial]. It solves the problem of sparse, high-latency vertex buffer updates in blocky meshing by maintaining a free-list of unused vertex indices and uploading data via `DYNAMIC_DRAW` hints [S1, unofficial]. Unlike static meshing approaches, it supports real-time addition and removal of blocks by logically remapping indices and notifying adjacent chunks of visibility changes [S1, unofficial].

## How it works
**Inputs:** Voxel world state (block types, chunks), camera position (for alpha sorting), and block modification events (add/remove).
**Outputs:** GPU vertex buffers (`vertex0`, `vertex1`) and index buffer (`indices`) representing the visible surface of the chunk.

**Data Structures:**
The mesh data is stored in three JavaScript arrays, which are converted to `Uint32Array` for GPU upload:
1.  `vertex0`: Array of 32-bit unsigned integers. Each vertex uses one `uint`.
    *   Bits 0-9: X coordinate (10 bits).
    *   Bits 10-19: Y coordinate (10 bits).
    *   Bits 20-29: Z coordinate (10 bits).
    *   Bits 30-31: Unused.
2.  `vertex1`: Array of 32-bit unsigned integers. Each vertex uses one `uint`.
    *   Bits 0-9: Texture layer index (10 bits).
    *   Bits 10-14: Texture coordinate U (5 bits).
    *   Bits 15-19: Texture coordinate V (5 bits).
    *   Bits 20-21: Lighting/shading value (2 bits).
    *   Bits 22-31: Unused.
3.  `indices`: Array of 32-bit unsigned integers. Stores triangle indices. Each face (quad) consumes 6 indices (2 triangles).
4.  `vertexSlots`: A stack (array) storing available vertex indices for reuse.

**Parameters:**
*   Block size ($n$): 16 units.
*   Direction mapping: 0=+X, 1=-X, 2=+Y, 3=-Y, 4=+Z, 5=-Z.
*   Texcoord scaling: $0.0625$ ($1/16$).
*   Lighting scaling: $0.2$ multiplier, $0.4$ offset.

**Algorithm Steps:**

1.  **Vertex Packing:**
    When adding a vertex at $(x, y, z)$ with texture layer $t$, texcoords $(u, v)$, and lighting $l$:
    *   Pack position: $V_0 = x \mid (y \ll 10) \mid (z \ll 20)$.
    *   Pack attributes: $V_1 = t \mid (u \ll 10) \mid (v \ll 15) \mid (l \ll 20)$.
    *   If a reusable index exists in `vertexSlots`, pop it; otherwise, push new values to `vertex0` and `vertex1` and use the new length as the index.

2.  **Face Generation:**
    For a voxel at block coordinates $(bx, by, bz)$ and direction $dir$:
    *   Calculate world positions for 4 vertices using `cubeFacePosition(bx, by, bz, dir)`. The function scales block coordinates by $n=16$ and returns 12 floats (4 vertices $\times$ 3 coords).
    *   Determine texture orientation using `cubeFaceTexcoord(dir)`. The mapping is $[2, 3, 0, 0, 3, 2][dir]$.
    *   Determine lighting value using $[1, 1, 3, 0, 2, 2][dir]$.
    *   Call `addVertex` for each of the 4 vertices.
    *   Push indices $(a, b, c, c, d, a)$ to the `indices` array.

3.  **Face Removal and Reuse:**
    To remove a face at a specific position:
    *   Search `vertex0` in steps of 4 using `findFace`. Compare packed positions of the 4 vertices of the target face against stored `vertex0` values.
    *   If found at index $i$:
        *   Set `vertex0[i...i+3]` and `vertex1[i...i+3]` to `NaN` (marking them as invalid).
        *   Remove the 6 corresponding indices from the `indices` array using `splice`.
        *   Push $i$ to `vertexSlots` for future reuse.
    *   Set `this.update = true` to trigger buffer refresh.

4.  **Neighbor Interaction:**
    When a block is added or removed at $(x, y, z)$:
    *   Iterate through 6 directions $i \in [0, 5]$.
    *   Calculate neighbor coordinates $(tx, ty, tz)$.
    *   Determine visibility using `faceInteraction`:
        *   If adding a face: Add if neighbor is invisible/translucent/transparent AND block types differ. Remove if neighbor is solid AND (current block is solid OR block types are identical).
        *   If removing a face: Reverse the logic.
    *   If a face needs to be added to the neighbor, call `addCubeFace` on the neighbor's chunk mesh. The direction for the neighbor is $i + (i \% 2 === 0 ? 1 : -1)$ to flip the normal.
    *   **Pitfall:** If the neighbor chunk mesh does not exist, it must be loaded before adding the exposed face [S1, unofficial].

5.  **Buffer Update:**
    If `this.update` is true:
    *   Bind VAO.
    *   Upload `vertex0`, `vertex1`, and `indices` to GPU buffers using `gl.bufferData` with `gl.DYNAMIC_DRAW`.
    *   Reset `this.update = false`.

**Pseudocode:**

```python
def pack_vertex0(x, y, z):
    return x | (y << 10) | (z << 20)

def pack_vertex1(texture, tex_u, tex_v, light):
    return texture | (tex_u << 10) | (tex_v << 15) | (light << 20)

def add_vertex(x, y, z, texture, tex_u, tex_v, light, reuse_index=-1):
    v0 = pack_vertex0(x, y, z)
    v1 = pack_vertex1(texture, tex_u, tex_v, light)
    
    if reuse_index >= 0:
        vertex0[reuse_index] = v0
        vertex1[reuse_index] = v1
        return reuse_index
    else:
        vertex0.append(v0)
        vertex1.append(v1)
        return len(vertex0) - 1

def add_cube_face(bx, by, bz, dir, texture):
    positions = cube_face_position(bx, by, bz, dir)
    texcoords = cube_face_texcoord(dir)
    light = lighting_values[dir]
    
    # positions is 12 floats: [x0,y0,z0, x1,y1,z1, x2,y2,z2, x3,y3,z3]
    # texcoords is 8 floats: [u0,v0, u1,v1, u2,v2, u3,v3]
    
    idx0 = add_vertex(positions[0], positions[1], positions[2], texture, texcoords[0], texcoords[1], light)
    idx1 = add_vertex(positions[3], positions[4], positions[5], texture, texcoords[2], texcoords[3], light, idx0 + 1)
    idx2 = add_vertex(positions[6], positions[7], positions[8], texture, texcoords[4], texcoords[5], light, idx0 + 2)
    idx3 = add_vertex(positions[9], positions[10], positions[11], texture, texcoords[6], texcoords[7], light, idx0 + 3)
    
    indices.extend([idx0, idx1, idx2, idx2, idx3, idx0])

def remove_face(face_positions):
    # face_positions is 12 floats
    start_idx = find_face(face_positions)
    if start_idx == -1:
        return
    
    # Mark as invalid
    for k in range(4):
        vertex0[start_idx + k] = float('nan')
        vertex1[start_idx + k] = float('nan')
        
    # Remove indices
    # Assuming indices are stored sequentially per face start
    idx_start = find_index_in_indices(start_idx)
    if idx_start != -1:
        del indices[idx_start : idx_start + 6]
        
    # Reuse slot
    vertex_slots.append(start_idx)
    update_flag = True

def find_face(face_positions):
    packed_face = [
        pack_vertex0(face_positions[0], face_positions[1], face_positions[2]),
        pack_vertex0(face_positions[3], face_positions[4], face_positions[5]),
        pack_vertex0(face_positions[6], face_positions[7], face_positions[8]),
        pack_vertex0(face_positions[9], face_positions[10], face_positions[11])
    ]
    
    for i in range(0, len(vertex0), 4):
        if isnan(vertex0[i]):
            continue
        if (vertex0[i] == packed_face[0] and
            vertex0[i+1] == packed_face[1] and
            vertex0[i+2] == packed_face[2] and
            vertex0[i+3] == packed_face[3]):
            return i
    return -1

def update_buffers():
    if not update_flag:
        return
    gl.bind_buffer(gl.ARRAY_BUFFER, vertex0_buffer)
    gl.buffer_data(gl.ARRAY_BUFFER, Uint32Array(vertex0), gl.DYNAMIC_DRAW)
    gl.bind_buffer(gl.ARRAY_BUFFER, vertex1_buffer)
    gl.buffer_data(gl.ARRAY_BUFFER, Uint32Array(vertex1), gl.DYNAMIC_DRAW)
    gl.bind_buffer(gl.ELEMENT_ARRAY_BUFFER, index_buffer)
    gl.buffer_data(gl.ELEMENT_ARRAY_BUFFER, Uint32Array(indices), gl.DYNAMIC_DRAW)
    update_flag = False
```

## Operating characteristics
**Time Complexity:**
*   Vertex/Index addition: $O(1)$ amortized due to free-list reuse.
*   Face removal: $O(V)$ where $V$ is the number of vertices, due to linear search in `findFace` [S1, unofficial].
*   Buffer upload: $O(N)$ where $N$ is the number of vertices/indices.

**Memory Complexity:**
*   Uses 8 bytes per vertex (two 32-bit integers) plus 4 bytes per index [S1, unofficial].
*   Significantly reduces buffer overhead compared to storing separate floating-point arrays for position, UV, and color.

**Performance:**
*   Measured on WebGL implementations using `DYNAMIC_DRAW` hints [S1, unofficial].
*   Scaling is efficient for incremental updates but degrades if `findFace` searches become frequent without compaction.

**Strengths:**
*   Low memory footprint per vertex.
*   Fast incremental updates via index reuse.
*   Simple implementation.

**Limitations:**
*   Linear search for face removal is slow for large meshes.
*   Fixed precision (10-bit coordinates) limits world size or block resolution.
*   Not given in the sources: Exact frame rates or vertex counts for specific hardware.

## Background
Originating from the Exolands project (kvxy/exolands), this method was developed for real-time voxel terrain rendering in web browsers using WebGL [S1, unofficial]. It addresses the specific constraints of client-side rendering where memory bandwidth and draw call overhead are critical bottlenecks. The technique combines face culling with efficient data packing to maintain high frame rates during dynamic world modification.
