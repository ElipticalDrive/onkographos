# ChunkMesh Vertex Packing and Management

Also called: Block Face Culling, Cube Face Mesh Generation

## Overview
ChunkMesh Vertex Packing and Management is a dynamic mesh generation and update technique for voxel terrain that packs vertex attributes into 32-bit integers to minimize GPU memory bandwidth and buffer size, while maintaining a mutable index buffer to support real-time block addition and removal [S1, unofficial]. It differs from static meshing methods by using a "delete-by-marking" strategy (setting vertex data to NaN) and a free-list of reusable vertex indices, allowing $O(1)$ face removal without full mesh reconstruction [S1, unofficial]. It builds on [Face Culling and Visibility Optimization](3861-face-culling-and-visibility-optimization.md) by handling the geometric instantiation and buffer management of the culled faces.

## How it works
**Inputs:** Block world coordinates $(x, y, z)$, block type, block visibility flags (invisible, translucent, transparent), and chunk boundaries.
**Outputs:** GPU vertex buffers (`vertex0`, `vertex1`) and an element index buffer (`indices`).

**Data Structures:**
*   `vertex0`: `Uint32Array` storing packed position data.
*   `vertex1`: `Uint32Array` storing packed texture, texcoord, and lighting data.
*   `indices`: `Uint32Array` storing triangle indices (6 indices per quad face).
*   `vertexSlots`: Stack of available vertex indices for reuse.
*   `update`: Boolean flag triggering buffer upload.

**Packed Layout:**
Each vertex uses two 32-bit unsigned integers.
*   `vertex0` (Position):
    *   Bits 0–9: X coordinate (10 bits).
    *   Bits 10–19: Y coordinate (10 bits).
    *   Bits 20–29: Z coordinate (10 bits).
    *   Bits 30–31: Unused.
*   `vertex1` (Attributes):
    *   Bits 0–9: Texture layer (10 bits).
    *   Bits 10–14: Texture coordinate X (5 bits).
    *   Bits 15–19: Texture coordinate Y (5 bits).
    *   Bits 20–21: Shading/Lighting value (2 bits).
    *   Bits 22–31: Unused.

**Constants:**
*   Block size $n = 16$.
*   Direction mapping: 0=+X, 1=-X, 2=+Y, 3=-Y, 4=+Z, 5=-Z.
*   Lighting values array: $[1, 1, 3, 0, 2, 2]$ indexed by direction.
*   Texcoord orientation mapping: $[2, 3, 0, 0, 3, 2]$ indexed by direction.

**Algorithm Steps:**

1.  **Face Generation:**
    For a block at $(x, y, z)$ and direction $dir$, calculate the 4 vertices of the exposed face.
    The position for each vertex $v_k$ ($k=0..3$) is derived from `cubeFacePosition(x, y, z, dir)`, which returns 12 floats (3 floats $\times$ 4 vertices).
    Example for $dir=0$ (+X):
    $v_0 = (x+1, y, z)$
    $v_1 = (x+1, y+1, z)$
    $v_2 = (x+1, y+1, z+1)$
    $v_3 = (x+1, y, z+1)$
    (Coordinates are scaled by $n=16$).

2.  **Attribute Packing:**
    For each vertex, pack coordinates into `vertex0`:
    $$ v0 = x_{int} \mid (y_{int} \ll 10) \mid (z_{int} \ll 20) $$
    Pack attributes into `vertex1`:
    $$ v1 = texLayer \mid (texX \ll 10) \mid (texY \ll 15) \mid (light \ll 20) $$
    Where $texX, texY$ are 5-bit integers derived from `cubeFaceTexcoord(dir)`, and $light$ is from the lighting array.

3.  **Vertex Addition:**
    *   Check `vertexSlots`. If not empty, pop an index $idx$. If empty, $idx = \text{current length of vertex0}$.
    *   Call `addVertex` for all 4 vertices of the face.
    *   If $idx$ was reused, update `vertex0[idx+k]` and `vertex1[idx+k]` for $k=0..3$.
    *   If new, push to `vertex0` and `vertex1`.
    *   Push indices $(idx, idx+1, idx+2, idx+2, idx+3, idx)$ to `indices`.
    *   Set `update = true`.

4.  **Face Removal:**
    *   Call `findFace(facePosition)` to locate the starting index $idx$ of the face in `vertex0`.
    *   `findFace` iterates `vertex0` in steps of 4. It skips entries where `vertex0[i]` is NaN. It reconstructs the packed `vertex0` for the 4 target vertices and compares them against stored values.
    *   If found ($idx \neq -1$):
        *   Set `vertex0[idx...idx+3]` and `vertex1[idx...idx+3]` to `NaN`.
        *   Remove the 6 corresponding indices from `indices` using `splice`.
        *   Push $idx$ to `vertexSlots`.
        *   Set `update = true`.

5.  **Block Update Logic:**
    When a block is added or removed at $(x, y, z)$:
    *   Iterate 6 directions $i=0..5$.
    *   Calculate neighbor coordinates $(tx, ty, tz)$.
    *   Determine neighbor block data and info.
    *   Call `faceInteraction(blockData0, blockData1, add, dir, blockInfo0, blockInfo1)`.
        *   `add=true` (Block Added):
            *   Add face if neighbor is invisible/translucent/transparent AND block types differ.
            *   Remove face if neighbor is NOT invisible AND (current block is NOT translucent/transparent OR block types are identical).
        *   `add=false` (Block Removed):
            *   Reverse logic: Remove face if neighbor is invisible/translucent/transparent AND types differ.
            *   Add face if neighbor is NOT invisible AND (current block is NOT translucent/transparent OR types are identical).
    *   If `addFace` is true:
        *   If adding block: Add face to current chunk.
        *   If removing block: Add face to neighbor chunk (load neighbor mesh if needed). Use direction $i + (i \% 2 === 0 ? 1 : -1)$ for the neighbor's face normal.
    *   If `removeFace` is true:
        *   If adding block: Remove face from neighbor chunk.
        *   If removing block: Remove face from current chunk.

**Pseudocode:**

```python
def add_vertex(vertex0, vertex1, vertex_slots, indices, x, y, z, texture_layer, texcoord_x, texcoord_y, light, vertex_index_hint=-1):
    # Determine index
    if vertex_slots:
        idx = vertex_slots.pop()
    else:
        idx = len(vertex0)

    # Pack vertex0
    v0 = x | (y << 10) | (z << 20)
    # Pack vertex1
    v1 = texture_layer | (texcoord_x << 10) | (texcoord_y << 15) | (light << 20)

    # Update or push
    if idx < len(vertex0):
        vertex0[idx] = v0
        vertex1[idx] = v1
    else:
        vertex0.append(v0)
        vertex1.append(v1)

    return idx

def add_cube_face(vertex0, vertex1, vertex_slots, indices, x, y, z, dir, texture_layer):
    # Get positions (12 floats)
    positions = cube_face_position(x, y, z, dir)
    # Get texcoords (4 floats: u0,v0, u1,v1, u2,v2, u3,v3)
    texcoords = cube_face_texcoord(dir)
    # Get light value
    light = LIGHTING_VALUES[dir]

    # Add 4 vertices
    a = add_vertex(vertex0, vertex1, vertex_slots, indices, positions[0], positions[1], positions[2], texture_layer, texcoords[0], texcoords[1], light)
    b = add_vertex(vertex0, vertex1, vertex_slots, indices, positions[3], positions[4], positions[5], texture_layer, texcoords[2], texcoords[3], light)
    c = add_vertex(vertex0, vertex1, vertex_slots, indices, positions[6], positions[7], positions[8], texture_layer, texcoords[4], texcoords[5], light)
    d = add_vertex(vertex0, vertex1, vertex_slots, indices, positions[9], positions[10], positions[11], texture_layer, texcoords[6], texcoords[7], light)

    # Add indices
    indices.extend([a, b, c, c, d, a])

def remove_face(vertex0, vertex1, vertex_slots, indices, face_position):
    # face_position is 12 floats (4 vertices)
    idx = find_face(vertex0, face_position)
    if idx == -1:
        return

    # Mark as deleted
    vertex0[idx] = float('nan')
    vertex0[idx+1] = float('nan')
    vertex0[idx+2] = float('nan')
    vertex0[idx+3] = float('nan')
    
    vertex1[idx] = float('nan')
    vertex1[idx+1] = float('nan')
    vertex1[idx+2] = float('nan')
    vertex1[idx+3] = float('nan')

    # Remove indices
    # Find start of this face in indices array
    idx_start = find_index_in_indices(indices, idx)
    if idx_start != -1:
        del indices[idx_start : idx_start+6]

    # Recycle vertex index
    vertex_slots.append(idx)

def find_face(vertex0, face_position):
    # face_position is 12 floats
    # Reconstruct packed v0 for each of the 4 vertices
    targets = []
    for k in range(4):
        x = face_position[k*3]
        y = face_position[k*3+1]
        z = face_position[k*3+2]
        targets.append(x | (y << 10) | (z << 20))

    # Search vertex0 in steps of 4
    for i in range(0, len(vertex0), 4):
        if math.isnan(vertex0[i]):
            continue
        if (vertex0[i] == targets[0] and 
            vertex0[i+1] == targets[1] and 
            vertex0[i+2] == targets[2] and 
            vertex0[i+3] == targets[3]):
            return i
    return -1

def find_index_in_indices(indices, vertex_idx):
    # Find the first index in indices array that matches vertex_idx
    # Assumes indices are stored in groups of 6
    for i in range(0, len(indices), 6):
        if indices[i] == vertex_idx:
            return i
    return -1

def cube_face_position(x, y, z, dir):
    n = 16
    x *= n
    y *= n
    z *= n
    if dir == 0: # +X
        return [x+n, y, z, x+n, y+n, z, x+n, y+n, z+n, x+n, y, z+n]
    elif dir == 1: # -X
        return [x, y, z, x, y, z+n, x, y+n, z+n, x, y+n, z]
    elif dir == 2: # +Y
        return [x, y+n, z, x, y+n, z+n, x+n, y+n, z+n, x+n, y+n, z]
    elif dir == 3: # -Y
        return [x+n, y, z+n, x, y, z+n, x, y, z, x+n, y, z]
    elif dir == 4: # +Z
        return [x, y, z+n, x+n, y, z+n, x+n, y+n, z+n, x, y+n, z+n]
    elif dir == 5: # -Z
        return [x, y, z, x, y+n, z, x+n, y+n, z, x+n, y, z]

    # Returns 8 floats: u0,v0, u1,v1, u2,v2, u3,v3
    # Mapping from source: [2, 3, 0, 0, 3, 2]

    # Note: Source code snippet cuts off, but logic implies orientation-based UVs
```

## Operating characteristics
*   **Time Complexity:** Face addition is $O(1)$. Face removal is $O(V)$ where $V$ is the number of vertices, due to `findFace` linear scan. Buffer upload is $O(N)$ where $N$ is the number of vertices/indices.
*   **Memory Complexity:** $O(F)$ where $F$ is the number of visible faces. Each face uses 4 vertices (8 uints) and 6 indices (6 uints). Total $\approx 14 \times 4$ bytes per face = 56 bytes/face.
*   **Performance:** Efficient for dynamic scenes with frequent block changes. The linear search in `findFace` is a bottleneck for large meshes with many removals. [S1, unofficial].
*   **Strengths:** Low memory footprint due to packing. Simple implementation. Supports dynamic updates without full rebuild.
*   **Limitations:** Linear search for face removal. Fragmented index buffer due to splicing. Precision limits on coordinate range (10 bits = 1024 units, scaled by 16 = 16384 world units). [S1, unofficial].

## Background
Originating from the Exolands voxel engine project, this method was developed to handle real-time voxel terrain editing in JavaScript/WebGL. It addresses the need for efficient dynamic mesh updates in browser-based environments where memory and CPU cycles are constrained. The technique is documented in the Exolands GitHub repository. [S1, unofficial].
