# ChunkMesh Vertex Packing and Management

Also called: Block Face Culling, Cube Face Mesh Generation

## Overview
ChunkMesh Vertex Packing and Management is a method for generating and maintaining dynamic surface meshes in voxel environments by packing vertex attributes into compact 32-bit integers and managing buffer updates via a free-list allocator. It solves the problem of high memory overhead and frequent GPU buffer uploads in blocky terrain rendering by minimizing vertex data size and enabling incremental, per-face updates without reallocating memory [S1, unofficial]. It differs from static meshing by supporting runtime addition and removal of blocks, and from simple face culling by integrating the geometric generation, attribute packing, and buffer management into a single cohesive system [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** Voxel world state (block types, positions, chunk boundaries), camera position (for translucent sorting), and block modification events (add/remove).
- **Output:** GPU vertex buffers (`vertex0`, `vertex1`) and index buffer (`indices`) representing the visible surface of the chunk.

**Data Structures:**
Each vertex is represented by two 32-bit unsigned integers (`uint`), packed as follows [S1, unofficial]:

- **`vertex0` (Position):**
  - Bits 0–9: X coordinate (10 bits, range 0–1023).
  - Bits 10–19: Y coordinate (10 bits, range 0–1023).
  - Bits 20–29: Z coordinate (10 bits, range 0–1023).
  - Bits 30–31: Unused.
- **`vertex1` (Attributes):**
  - Bits 0–9: Texture layer index (10 bits).
  - Bits 10–14: Texture coordinate X (5 bits, range 0–31).
  - Bits 15–19: Texture coordinate Y (5 bits, range 0–31).
  - Bits 20–21: Lighting/shading value (2 bits, range 0–3).
  - Bits 22–31: Unused.

The mesh maintains three arrays:
- `vertex0`: Array of `uint` for position data.
- `vertex1`: Array of `uint` for attribute data.
- `indices`: Array of `uint` for triangle indices (6 indices per quad).
- `vertexSlots`: Stack of available vertex indices for reuse (free-list).

**Numbered Steps:**

1. **Initialization:**
   - Initialize `vertex0`, `vertex1`, `indices`, and `vertexSlots` as empty arrays.
   - Set `this.update = false`.

2. **Face Generation (`addCubeFace`):**
   - Given block position $(x, y, z)$, direction $dir \in \{0, \dots, 5\}$, and texture key:
     - Calculate vertex positions using `cubeFacePosition(x, y, z, dir)`. The block size $n=16$. Directions map to: 0: +X, 1: -X, 2: +Y, 3: -Y, 4: +Z, 5: -Z [S1, unofficial].
     - Calculate texture coordinates using `cubeFaceTexcoord(orientation)`. Orientation mapping from direction $dir$ is `[2, 3, 0, 0, 3, 2][dir]` [S1, unofficial].
     - Determine lighting value $dLight$ using `[1, 1, 3, 0, 2, 2][dir]` [S1, unofficial].
     - Pop a reusable vertex index from `vertexSlots`. If empty, start a new index (e.g., `current_max + 4`) [S1, unofficial].
     - Call `addVertex` for 4 vertices (a, b, c, d) with their packed `vertex0` and `vertex1` values.
     - Push indices `(a, b, c, c, d, a)` to `indices` [S1, unofficial].
     - Set `this.update = true` [S1, unofficial].

3. **Vertex Addition (`addVertex`):**
   - If `vertexIndex >= 0` (reused):
     - Update `vertex0[vertexIndex]` with packed position: `x | (y << 10) | (z << 20)` [S1, unofficial].
     - Update `vertex1[vertexIndex]` with packed attributes: `textureLayer | (texcoordX << 10) | (texcoordY << 15) | (dLight << 20)` [S1, unofficial].
   - Else (new vertex):
     - Push packed `vertex0` and `vertex1` to `vertex0` and `vertex1` arrays.
     - Return the new index.

4. **Face Removal (`removeFace`):**
   - Given `facePosition` (array of 12 floats representing 4 vertices):
     - Call `findFace(facePosition)` to locate the starting index in `vertex0` [S1, unofficial].
     - If found:
       - Set `vertex0` and `vertex1` at indices `i, i+1, i+2, i+3` to `NaN` [S1, unofficial].
       - Remove 6 corresponding indices from `indices` using `splice` [S1, unofficial].
       - Push starting vertex index `i` to `vertexSlots` for reuse [S1, unofficial].
       - Set `this.update = true` [S1, unofficial].

5. **Face Search (`findFace`):**
   - Iterate through `vertex0` in steps of 4.
   - Skip entries where `vertex0[i]` is `NaN` [S1, unofficial].
   - Reconstruct packed `vertex0` for each of the 4 vertices of the target face and compare against stored values [S1, unofficial].
   - Return starting index or -1.

6. **Block Update Logic (`updateBlock`):**
   - For each of the 6 directions $i$:
     - Calculate neighbor coordinates $(tx, ty, tz)$ [S1, unofficial].
     - Get neighbor block data and info.
     - Call `faceInteraction(blockData0, blockData1, add, dir, blockInfo0, blockInfo1)` [S1, unofficial].
     - If `addFace` is true:
       - If adding block: add face to current chunk.
       - If removing block: add face to neighbor chunk (load neighbor mesh if needed) [S1, unofficial].
     - If `removeFace` is true:
       - If adding block: remove face from neighbor chunk.
       - If removing block: remove face from current chunk [S1, unofficial].
     - Neighbor direction index: $i + (i \% 2 === 0 ? 1 : -1)$ [S1, unofficial].

7. **Buffer Update (`updateBuffers`):**
   - If `this.update` is true:
     - Bind VAO.
     - Upload `vertex0`, `vertex1`, and `indices` to GPU buffers using `gl.DYNAMIC_DRAW` [S1, unofficial].
     - Reset `this.update = false`.

**Pseudocode:**

```python
def add_cube_face(x, y, z, dir, texture):
    # Directions: 0:+X, 1:-X, 2:+Y, 3:-Y, 4:+Z, 5:-Z
    n = 16
    positions = cube_face_position(x * n, y * n, z * n, dir)
    texcoords = cube_face_texcoord([2, 3, 0, 0, 3, 2][dir])
    d_light = [1, 1, 3, 0, 2, 2][dir]
    
    # Get reusable index or new index
    if vertex_slots:
        vertex_index = vertex_slots.pop()
    else:
        vertex_index = len(vertex0)
        
    # Add 4 vertices
    a = add_vertex(positions[0], positions[1], positions[2], texture, texcoords[0], texcoords[1], d_light, vertex_index)
    b = add_vertex(positions[3], positions[4], positions[5], texture, texcoords[2], texcoords[3], d_light, vertex_index + 1)
    c = add_vertex(positions[6], positions[7], positions[8], texture, texcoords[4], texcoords[5], d_light, vertex_index + 2)
    d = add_vertex(positions[9], positions[10], positions[11], texture, texcoords[6], texcoords[7], d_light, vertex_index + 3)
    
    indices.extend([a, b, c, c, d, a])
    this.update = True

def add_vertex(x, y, z, texture, tex_x, tex_y, d_light, vertex_index):
    # Pack vertex0
    v0 = x | (y << 10) | (z << 20)
    # Pack vertex1
    v1 = texture | (tex_x << 10) | (tex_y << 15) | (d_light << 20)
    
    if vertex_index < len(vertex0):
        vertex0[vertex_index] = v0
        vertex1[vertex_index] = v1
    else:
        vertex0.append(v0)
        vertex1.append(v1)
        
    return vertex_index

def remove_face(face_position):
    # face_position is list of 12 floats
    vertex_index = find_face(face_position)
    if vertex_index == -1:
        return
        
    # Mark as NaN
    for i in range(4):
        vertex0[vertex_index + i] = float('nan')
        vertex1[vertex_index + i] = float('nan')
        
    # Remove indices
    idx_start = find_index(vertex_index)
    if idx_start != -1:
        del indices[idx_start:idx_start+6]
        
    # Push to free list
    vertex_slots.append(vertex_index)
    this.update = True

def find_face(face_position):
    # Reconstruct packed positions for comparison
    packed_positions = [
        face_position[0] | (face_position[1] << 10) | (face_position[2] << 20),
        face_position[3] | (face_position[4] << 10) | (face_position[5] << 20),
        face_position[6] | (face_position[7] << 10) | (face_position[8] << 20),
        face_position[9] | (face_position[10] << 10) | (face_position[11] << 20)
    ]
    
    for i in range(0, len(vertex0), 4):
        if isnan(vertex0[i]):
            continue
        if vertex0[i:i+4] == packed_positions:
            return i
    return -1

def face_interaction(block_data0, block_data1, add, dir, block_info0, block_info1):
    add_face = False
    remove_face = False
    
    if add:
        if block_info0.is_invisible:
            return False, False
        if (block_info1.is_invisible or block_info1.is_translucent or block_info1.is_transparent) and block_data0.type != block_data1.type:
            add_face = True
        if (not block_info1.is_invisible and not block_info0.is_translucent and not block_info0.is_transparent) or (block_data0.type == block_data1.type):
            remove_face = True
    else:
        if (block_info1.is_invisible or block_info1.is_translucent or block_info1.is_transparent) and block_data0.type != block_data1.type:
            remove_face = True
        if (not block_info1.is_invisible and not block_info0.is_translucent and not block_info0.is_transparent) or (block_data0.type == block_data1.type):
            add_face = True
            
    return add_face, remove_face
```

**Parameters:**
- Block size $n=16$ [S1, unofficial].
- Coordinate precision: 10 bits per axis (supports 1024 units per chunk) [S1, unofficial].
- Texture coordinate precision: 5 bits (32 levels) [S1, unofficial].
- Lighting levels: 4 (2 bits) [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Neighbor Chunk Loading:** When removing a block, the neighbor chunk's mesh must be loaded if it doesn't exist before adding the exposed face to it [S1, unofficial].
- **NaN Handling:** `find_face` must skip `NaN` entries to avoid false positives [S1, unofficial].
- **Index Reuse:** The free-list (`vertexSlots`) ensures that removed vertices are reused, preventing unbounded growth of vertex arrays [S1, unofficial].

## Subtopics

### [Voxel Face Meshing with Packed Attributes](4153-voxel-face-meshing-with-packed-attributes.md)
A mesh generation technique for voxel terrain where vertex data (position, type, direction) is packed into a single float attribute to reduce buffer overhead, unpacked in the vertex shader, and used to generate quad faces for visible voxel surfaces.

### [Mesh Reindexing and Vertex Compaction](4160-mesh-reindexing-and-vertex-compaction.md)
This method reduces the memory footprint of a chunk-based mesh by removing unreferenced vertices and renumbering the remaining ones to form a dense, contiguous array. It solves the problem of sparse vertex buffers that arise during incremental blocky meshing, where vertices are allocated per voxel face but many are culled or unused. Unlike [Voxel Face Meshing with Packed Attributes](4153-voxel-face-meshing-with-packed-attributes.md), which focuses on storage layout, this method actively compacts the data. It differs from [Chunk Mesh Data Structure & Buffer Update](4182-chunk-mesh-data-structure-buffer-update.md) by performing the logical remapping rather than just updating buffer pointers.

### [Chunk Mesh Data Structure & Buffer Update](4182-chunk-mesh-data-structure-buffer-update.md)
This method manages the creation, population, and recycling of GPU vertex buffers for meshed chunk geometry by utilizing a single large Shader Storage Buffer (SSBO) known as the "MegaSSBO". It solves the problem of dynamic memory allocation overhead and fragmentation in voxel terrain rendering by implementing a free-list allocator within the SSBO to handle the variable face counts of individual chunks. It differs from per-chunk buffer allocation by centralizing memory management, and from static buffer approaches by supporting incremental updates and defragmentation.

### [Alpha/Translucent Block Rendering](4860-alpha-translucent-block-rendering.md)
Alpha/Translucent Block Rendering is a fragment-shader-based technique for rendering semi-transparent voxel blocks (such as water or glass) within a chunked voxel world. It solves the problem of visualizing translucent geometry without requiring complex ray-marching or volumetric accumulation per pixel, relying instead on standard rasterization with pre-computed vertex attributes. It differs from opaque block meshing by applying per-fragment shading and fog based on world-space depth, and from volumetric raycasting by operating on discrete mesh faces rather than continuous density fields.

## Operating characteristics
- **Time Complexity:** Face generation is $O(1)$ per face. Buffer upload is $O(V + I)$ where $V$ is the number of vertices and $I$ is the number of indices. Finding a face for removal is $O(V)$ in the worst case due to linear search [S1, unofficial].
- **Memory Complexity:** $O(V)$ for vertex data, where each vertex uses 8 bytes (two 32-bit integers) [S1, unofficial].
- **Measured Performance:** Not given in the sources.
- **Scaling:** Scales well with chunk size due to fixed-size vertex packing. Performance degrades if many faces are removed and added frequently due to linear search for face removal [S1, unofficial].
- **Strengths:** Low memory footprint, fast buffer updates, efficient reuse of vertex slots.
- **Limitations:** Linear search for face removal can be slow for large meshes. Fixed coordinate precision limits chunk size to 1024 units per axis [S1, unofficial].
- **When to Use:** Ideal for dynamic voxel worlds with frequent block modifications.
- **When Not to Use:** Not suitable for very large chunks where linear face search becomes a bottleneck, or for scenes requiring higher coordinate precision than 10 bits [S1, unofficial].
