# Voxel Face Meshing with Packed Attributes

Also called: Packed Voxel Face Meshing, Voxel Meshing with Packed Vertex Attributes

## Overview
A mesh generation technique for voxel terrain where vertex data (position, type, direction) is packed into a single float attribute to reduce buffer overhead, unpacked in the vertex shader, and used to generate quad faces for visible voxel surfaces [S1, unofficial]. It builds on [ChunkMesh Vertex Packing and Management](3566-chunkmesh-vertex-packing-and-management.md) by defining the specific bit-layout and shader logic required to reconstruct geometry from the packed data.

## How it works
**Inputs and Outputs:**
*   **Input:** A chunk of voxel data, a packed buffer containing one float per vertex, and uniform variables for chunk/world transformation.
*   **Output:** A `BufferGeometry` with attributes `position` (vec3), `packedData` (float), `vertexID` (float), and an index buffer for triangles.

**Data Structures:**
The `packed_buffer` stores vertex attributes in a single 32-bit float (or equivalent IEEE 754 representation). The bit layout is:
*   **Bits 20-23 (4 bits):** X coordinate of the vertex within the voxel face (0-15).
*   **Bits 16-19 (4 bits):** Y coordinate of the vertex within the voxel face (0-15).
*   **Bits 12-15 (4 bits):** Z coordinate of the vertex within the voxel face (0-15).
*   **Bits 4-11 (8 bits):** Voxel type (0-255).
*   **Bits 0-2 (3 bits):** Face direction (0-7).

**Parameters:**
*   `u_voxel_size`: float, size of a single voxel in world units [S1, unofficial].
*   `u_chunk_size`: float, number of voxels per chunk dimension [S1, unofficial].
*   `u_chunk_indices`: vec3, integer coordinates of the chunk in the world grid [S1, unofficial].
*   `u_time`: float, elapsed time for water animation [S1, unofficial].

**Steps:**
1.  **Unpack Data:** In the vertex shader, extract the components from the packed float.
    $$x = \lfloor \text{mod}(packed / 2^{20}, 16) \rfloor$$
    $$y = \lfloor \text{mod}(packed / 2^{16}, 16) \rfloor$$
    $$z = \lfloor \text{mod}(packed / 2^{12}, 16) \rfloor$$
    $$type = \lfloor \text{mod}(packed / 2^{4}, 256) \rfloor$$
    $$direction = \text{mod}(packed, 8)$$
2.  **Calculate Local Offset:** Determine the vertex offset relative to the voxel center based on the face direction and vertex ID. The half-size is $u\_voxel\_size \times 0.5$. Directions are: 0=TOP, 1=BOTTOM, 2=RIGHT, 3=LEFT, 4=FRONT, 5=BACK [S1, unofficial].
3.  **Compute World Position:**
    $$chunk\_offset = u\_chunk\_indices \times (u\_chunk\_size \times u\_voxel\_size)$$
    $$local\_offset = voxelPosition \times u\_voxel\_size$$
    $$vertexOffset = getFaceVertexPosition(direction, vertexID)$$
    $$final\_position = chunk\_offset + local\_offset + vertexOffset$$
4.  **Apply Effects:** If `voxelType` is 5.0 (water) and `position.y > 0.0`, apply a ripple effect:
    $$position.y += \sin(worldPos.x \times 2.0 + u\_time \times 1.5) \times 0.05 + \cos(worldPos.z \times 2.0 + u\_time \times 2.0) \times 0.06$$ [S1, unofficial].

**Edge Cases and Pitfalls:**
*   The water ripple effect only applies to top faces (`position.y > 0.0`) to avoid distorting submerged or side faces [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Reduces buffer overhead by packing multiple attributes into a single float per vertex [S1, unofficial].
*   **Strengths:** Efficient memory usage for vertex data; simple unpacking logic in the shader.
*   **Limitations:** Limited precision for coordinates (4 bits per axis); limited voxel types (8 bits); limited directions (3 bits).
*   **When to use:** Suitable for voxel terrain where memory bandwidth is a bottleneck and voxel types/directions are limited.
*   **When not to use:** When high-precision coordinates or a large number of voxel types/directions are required.
