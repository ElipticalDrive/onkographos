# Chunk Mesh Data Structure & Buffer Update

Also called: ChunkMesh Update Loop, Dynamic Chunk Mesh Buffer Management, Mega Buffer, MegaSSBO Memory Management, SSBO Allocator, Voxel Buffer Management

## Overview
This method manages the creation, population, and recycling of GPU vertex buffers for meshed chunk geometry using a single large Shader Storage Buffer (SSBO) [S1, S3, unofficial]. It solves the problem of dynamic memory allocation for variable-sized voxel meshes by implementing a free-list allocator within a pre-allocated global buffer, avoiding the overhead of frequent GPU buffer reallocations [S3, unofficial]. It differs from static buffer approaches by supporting incremental updates where only modified chunks are remeshed and their data uploaded to specific offsets within the mega buffer [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Temporary mesh data (`tempMeshData`) containing `VoxelVertex` structs generated during the meshing pass [S1, unofficial]. Block change events triggering `addBlock` or `removeBlock` [S2, unofficial].
*   **Output:** Updated GPU SSBO containing packed vertex/index data for all active chunks [S3, unofficial].

**Data Structures:**
1.  **MegaSSBO:** A single GPU buffer of type `GL_SHADER_STORAGE_BUFFER` with usage hint `GL_DYNAMIC_DRAW` [S3, unofficial].
    *   **Capacity:** `MAX_FACES` elements of type `uint32_t` [S3, unofficial]. The exact value is implementation-dependent but cited as 20,000,000 in one source [S3, unofficial].
    *   **Layout:** Contiguous memory storing vertex/index data for all chunks.
2.  **FreeBlock:** Represents a contiguous free region in the MegaSSBO.
    *   `offset`: `uint32_t`, the starting index in `uint32_t` elements [S3, unofficial].
    *   `size`: `uint32_t`, the number of `uint32_t` elements available [S3, unofficial].
3.  **m_FreeList:** A `std::list<FreeBlock>` (or `std::vector` in some implementations) maintaining all free blocks sorted by ascending `offset` [S3, unofficial].
4.  **Chunk Mesh Object:** Contains properties `x, y, z, pos` (chunk coordinates), `indicesLength` (or `indices` array), `vao` (Vertex Array Object), and an `update` flag [S2, unofficial]. It also stores the `offset` and `faceCount` allocated in the MegaSSBO [S3, unofficial].

**Algorithm Steps:**

1.  **Initialization:**
    *   Create the GL buffer with `glBufferData(GL_SHADER_STORAGE_BUFFER, MAX_FACES * sizeof(uint32_t), nullptr, GL_DYNAMIC_DRAW)` [S3, unofficial].
    *   Initialize `m_FreeList` with a single block: `{offset: 0, size: MAX_FACES}` [S3, unofficial].

2.  **Allocation (First Fit):**
    *   When a chunk is meshed, determine the required `faceCount` (number of `uint32_t` elements needed) [S3, unofficial].
    *   Iterate through `m_FreeList`.
    *   If `it->size >= faceCount`:
        *   Return `it->offset` as the allocation [S3, unofficial].
        *   If `it->size == faceCount`, erase the element from the list [S3, unofficial].
        *   If `it->size > faceCount`, update `it->offset += faceCount` and `it->size -= faceCount` [S3, unofficial].
    *   If no block fits, return `UINT32_MAX` (allocation failure) [S3, unofficial].

3.  **Deallocation (Free):**
    *   When a chunk is removed or updated, call `Free(offset, faceCount)` [S3, unofficial].
    *   Insert a new block `{offset, faceCount}` into `m_FreeList` at the sorted position to maintain ascending offset order [S3, unofficial].
    *   Call `Merge()` to combine adjacent blocks [S3, unofficial].

4.  **Merge Adjacent Blocks:**
    *   Iterate through `m_FreeList`.
    *   If `it->offset + it->size == next->offset` (where `next` is the subsequent element):
        *   Merge by adding `next->size` to `it->size` [S3, unofficial].
        *   Erase `next` from the list [S3, unofficial].
        *   Continue checking from `it` to catch cascading merges (e.g., if the merged block now touches the previous block) [S3, unofficial].

5.  **Data Upload:**
    *   Bind the SSBO [S3, unofficial].
    *   Calculate byte offsets: `byte_offset = offset * sizeof(uint32_t)` and `byte_size = faceCount * sizeof(uint32_t)` [S3, unofficial].
    *   Use `glBufferSubData` to upload the `tempMeshData` to the allocated offset [S3, unofficial].

6.  **Buffer Compaction (Handling Fragmentation):**
    *   If allocation fails (`UINT32_MAX`), fragmentation has occurred [S3, unofficial].
    *   Perform compaction by shifting data to close gaps. This involves using `glCopyBufferSubData` between `GL_COPY_READ_BUFFER` and `GL_COPY_WRITE_BUFFER` (both bound to the same SSBO ID) to shift data by `faceCount * sizeof(uint32_t)` bytes [S3, unofficial].
    *   Update the `m_FreeList` and chunk offsets accordingly after compaction [S3, unofficial].

7.  **Update Loop:**
    *   On block change, `setBlock` calls `removeBlock` or `addBlock` on the relevant chunk mesh [S2, unofficial].
    *   During the draw loop, if `chunkMesh.update` is true, call `chunkMesh.updateBuffers()` before drawing [S2, unofficial].
    *   Recycle temporary mesh visitor and vertex storage pools after buffer upload to prevent memory leaks [S1, unofficial].

class MegaSSBO:
    MAX_FACES = 20_000_000  # Example value [S3, unofficial]
    
    def __init__(self):
        # Initialize GL buffer [S3, unofficial]
        self.buffer_id = create_gl_buffer(GL_SHADER_STORAGE_BUFFER, 
                                          self.MAX_FACES * 4, 
                                          None, 
                                          GL_DYNAMIC_DRAW)
        # Initialize free list with one large block [S3, unofficial]
        self.free_list = [FreeBlock(offset=0, size=self.MAX_FACES)]

    def allocate(self, face_count):
        """First-fit allocation from free list [S3, unofficial]"""
        for i, block in enumerate(self.free_list):
            if block.size >= face_count:
                if block.size == face_count:
                    # Exact fit, remove block
                    self.free_list.pop(i)
                else:
                    # Split block
                    block.offset += face_count
                    block.size -= face_count
                return block.offset - face_count  # Return start offset
        return UINT32_MAX  # Allocation failure [S3, unofficial]

    def free(self, offset, face_count):
        """Free a block and merge adjacent ones [S3, unofficial]"""
        new_block = FreeBlock(offset=offset, size=face_count)
        # Insert into sorted position
        self.free_list.append(new_block)
        self.free_list.sort(key=lambda b: b.offset)
        self.merge()

    def merge(self):
        """Merge adjacent free blocks to reduce fragmentation [S3, unofficial]"""
        i = 0
        while i < len(self.free_list) - 1:
            current = self.free_list[i]
            next_block = self.free_list[i+1]
            if current.offset + current.size == next_block.offset:
                # Merge
                current.size += next_block.size
                self.free_list.pop(i+1)
                # Do not increment i to check for further merges
            else:
                i += 1

    def upload(self, data, face_count, offset):
        """Upload mesh data to the allocated offset [S3, unofficial]"""

        byte_size = face_count * 4
        bind_ssbo(self.buffer_id)

## Operating characteristics
*   **Time Complexity:** Allocation is $O(N)$ where $N$ is the number of free blocks, due to linear scan of the free list [S3, unofficial]. Merge is also $O(N)$ [S3, unofficial]. Upload is $O(F)$ where $F$ is the face count [S3, unofficial].
*   **Memory Complexity:** The MegaSSBO consumes a fixed amount of GPU memory: `MAX_FACES * sizeof(uint32_t)` [S3, unofficial]. For `MAX_FACES = 20,000,000`, this is 80 MB [S3, unofficial].
*   **Performance:** The free-list allocator avoids GPU buffer reallocation overhead, which is costly [S3, unofficial]. However, fragmentation can lead to allocation failures, requiring compaction [S3, unofficial].
*   **Strengths:** Efficient memory reuse, supports dynamic chunk updates, single buffer simplifies binding [S3, unofficial].
*   **Limitations:** Fragmentation can occur, requiring periodic compaction [S3, unofficial]. First-fit allocation can be slow if the free list is large [S3, unofficial].
*   **When to use:** Suitable for dynamic voxel worlds with frequent block changes [S1, S2, unofficial].
*   **When not to use:** If the world is static, a simpler static buffer allocation may be more efficient [S3, unofficial].

## Background
The Chunk Mesh Data Structure & Buffer Update method originates from implementations in voxel engine projects such as `adrienlabayle/VoxelEngine` [S3, unofficial], `vercidium-patreon/meshing` [S1, unofficial], and `kvxy/exolands` [S2, unofficial]. It is commonly used in real-time voxel rendering engines to manage the dynamic geometry of chunk-based terrain [S1, S2, S3, unofficial]. The approach of using a "MegaSSBO" with a free-list allocator is a technique to handle the variable size of meshed chunks efficiently on the GPU [S3, unofficial].
