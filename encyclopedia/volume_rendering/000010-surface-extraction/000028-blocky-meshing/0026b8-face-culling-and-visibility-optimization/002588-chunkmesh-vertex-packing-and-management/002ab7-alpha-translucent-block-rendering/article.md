# Alpha/Translucent Block Rendering

Also called: Translucent Block Shader

## Overview
Alpha/Translucent Block Rendering is a fragment-shader-based technique for rendering semi-transparent voxel blocks (such as water or glass) within a chunked voxel world. It solves the problem of visualizing translucent geometry without requiring complex ray-marching or volumetric accumulation per pixel, relying instead on standard rasterization with pre-computed vertex attributes. It differs from opaque block meshing by applying per-fragment shading and fog based on world-space depth, and from volumetric raycasting by operating on discrete mesh faces rather than continuous density fields.

## How it works
The method operates on a mesh generated by the parent [ChunkMesh Vertex Packing and Management](3566-chunkmesh-vertex-packing-and-management.md) system. It requires no additional CPU-side data structures beyond those provided by the parent, as all necessary attributes are packed into the vertex buffer.

### Inputs and Outputs
*   **Input**: A vertex buffer containing packed attributes for translucent block faces, a `sampler2DArray` for block textures, and uniform variables for chunk position, fog, and lighting.
*   **Output**: A color buffer with translucent blocks rendered with correct shading and distance-based fog.

### Data Structures
The vertex layout is defined by the parent article. For this method, the following fields are critical:
*   `vertex0`: Contains world-space coordinates.
    *   `x`: Bits 0-9 (10 bits).
    *   `y`: Bits 10-19 (10 bits).
    *   `z`: Bits 20-29 (10 bits).
*   `vertex1`: Contains texture and shading data.
    *   `textureLayer`: Bits 0-7 (8 bits).
    *   `texcoordX`: Bits 8-15 (8 bits).
    *   `texcoordY`: Bits 16-23 (8 bits).
    *   `shadingBits`: Bits 20-29 (10 bits).

### Uniforms
*   `chunkPosition`: `vec3` defining the chunk's world offset [S1, unofficial].
*   `fogFar`: `float` defining the far distance for fog fade [S1, unofficial].
*   `fogColor`: `vec4` defining the fog color [S1, unofficial].

### Algorithm Steps

#### Vertex Shader
1.  **Extract Local Coordinates**: Extract `x`, `y`, `z` from `vertex0` using bitmasks.
    *   `x = vertex0 & 1023u`
    *   `y = (vertex0 >> 10) & 1023u`
    *   `z = (vertex0 >> 20) & 1023u` [S1, unofficial]
2.  **Compute World Position**: Add `chunkPosition` to the local coordinates.
    *   `worldPos = vec3(x, y, z) + chunkPosition`
3.  **Compute Clip Position**: Transform `worldPos` by the projection and view matrices to compute `gl_Position` [S1, unofficial].
4.  **Extract Texture Data**: Extract `textureLayer`, `texcoordX`, and `texcoordY` from `vertex1` [S1, unofficial].
5.  **Scale Texture Coordinates**: Scale UVs by `0.0625f` (1/16) to map from the 0-15 block texture atlas range to 0-1 [S1, unofficial].
    *   `uv = vec2(texcoordX, texcoordY) * 0.0625f`
6.  **Compute Shading Factor**: Extract `shadingBits` from `vertex1` (shifted by 20). Scale by `0.2` and offset by `0.4` to map to a [0.4, 2.4] range.
    *   `shadeData = (shadingBits * 0.2) + 0.4` [S1, unofficial]
7.  **Compute View Position**: Calculate the position of the vertex in view space for fog calculation.
    *   `viewPosition = viewMatrix * vec4(worldPos, 1.0)` [S1, unofficial]

#### Fragment Shader
1.  **Sample Texture**: Sample the `sampler2DArray` using `uv` and `textureLayer`.
    *   `color = texture(textureSampler, vec3(uv, textureLayer))`
2.  **Apply Shading**: Multiply the sampled RGB color by `shadeData`.
    *   `color.rgb *= shadeData` [S1, unofficial]
3.  **Apply Fog**: Calculate distance from the camera using `length(viewPosition)`. Mix the color with `fogColor` using `smoothstep`.
    *   `fogFactor = smoothstep(0.0f, fogFar, length(viewPosition))`
    *   `finalColor = mix(color, fogColor, fogFactor)` [S1, unofficial]
4.  **Output**: Write `finalColor` to the framebuffer.

### Edge Cases and Pitfalls
*   **Precision**: The 10-bit coordinate system limits chunk size to 1024 blocks. If chunks exceed this, world position calculation will overflow [S1, unofficial].
*   **Transparency Sorting**: Standard rasterization does not handle depth sorting for translucent surfaces. This method assumes the parent meshing system (ChunkMesh) handles draw order (e.g., back-to-front) or that the translucent blocks are opaque enough to not require strict alpha blending [G].
*   **UV Scaling**: The hardcoded `0.0625f` multiplier assumes a 16x16 texture atlas. If the atlas size changes, this value must be adjusted [S1, unofficial].

## Subtopics

### Greedy Meshing for Translucent Blocks
This variant applies greedy meshing principles specifically to translucent blocks to reduce draw calls. Instead of rendering individual faces, it merges adjacent translucent faces of the same block type into larger quads. The rendering step differs: for each merged face, the shader renders a flat color using raw UVs without an atlas lookup, optimizing texture sampling [S2, unofficial]. The face UVs are retrieved via `quad.uvs(face, false)`, and the block color is obtained via `block_textures.to_color(&chunk_block_id, block_face)`, defaulting to `[0.0, 0.0, 0.0, 1.0]` if the lookup fails [S2, unofficial]. This reduces fragment shader overhead at the cost of increased CPU-side mesh generation complexity.

## Operating characteristics
*   **Time Complexity**: O(N) where N is the number of visible translucent block faces. The vertex shader is lightweight, and the fragment shader involves one texture lookup and basic arithmetic.
*   **Memory Complexity**: O(1) additional memory per vertex compared to opaque meshing, as shading data is packed into existing vertex attributes.
*   **Performance**: Highly efficient on modern GPUs due to low per-fragment computational cost. Performance scales linearly with the number of visible translucent faces.
*   **Strengths**: Simple implementation, low memory overhead, compatible with standard OpenGL/Vulkan pipelines.
*   **Limitations**: Does not support true volumetric transparency (e.g., light scattering through water). Requires careful handling of draw order for correct alpha blending.

## Background
This method is derived from practical implementations in voxel game engines, specifically the Exolands project [S1, unofficial] and Infinigen [S2, unofficial]. It represents a common optimization in chunk-based voxel renderers where translucent blocks (water, glass) are treated as standard geometry with specialized shading rather than volumetric data.
