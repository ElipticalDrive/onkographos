# Extraction of Surface Points (Sobierajski)
Also called: Sobierajski's method, Visible boundary voxel extraction

## Overview
Extraction of Surface Points (Sobierajski) is a fast display method for the direct rendering of boundary surfaces by extracting only visible boundary voxels from volume data [S1, unofficial]. It solves the problem of efficiently generating a surface representation for volume rendering by filtering out occluded geometry before the rendering stage. Unlike sibling methods that rely on block-level culling or mesh topology optimization [Face Culling and Visibility Optimization](3861-face-culling-and-visibility-optimization.md), this method operates on individual voxel boundaries and uses orthographic projection visibility to prune the voxel list, making it suitable for real-time previewing and interactive manipulation [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volume grid of density/opacity values; a set of viewing directions (typically the six orthographic axes).
*   **Output:** A list of visible boundary voxels, each containing coordinates, normal vectors, and density values.

**Data Structures:**
*   **Volume Grid:** A 3D array $V[x][y][z]$ storing scalar density values.
*   **Voxel List:** A dynamic list of structures. Each element contains:
    *   `coords`: $(x, y, z)$ integer indices of the voxel center.
    *   `normal`: $(n_x, n_y, n_z)$ unit normal vector of the visible face.
    *   `density`: Scalar value from $V[x][y][z]$.

**Algorithm Steps:**

1.  **Visibility Determination:**
    For each of the $N$ viewing directions $\vec{v}_i$ (typically $N=6$ for orthographic views along $\pm x, \pm y, \pm z$):
    a.  Project the volume onto a 2D slice perpendicular to $\vec{v}_i$.
    b.  Perform a 2D boundary tracing algorithm on the slice to identify boundary voxels. A voxel is a boundary voxel if it is occupied and has at least one adjacent neighbor that is empty (air/void) in the direction of the viewing ray or perpendicular to it, depending on the specific trace definition.
    c.  Mark these voxels as potentially visible.

2.  **Deduplication:**
    Merge the lists of potentially visible voxels from all viewing directions. Remove duplicate entries for the same voxel index $(x, y, z)$. Store the normal vector corresponding to the face that was visible during extraction.

3.  **Backface Culling (Voxel Culling):**
    For each voxel in the deduplicated list with normal $\vec{n}$ and for the current viewing direction $\vec{v}$:
    a.  Compute the dot product $d = \vec{n} \cdot \vec{v}$.
    b.  If $d > 0$, the voxel is a back face relative to the viewer. Discard it from the rendering list [S1, unofficial].
    c.  If $d \le 0$, keep the voxel.

4.  **Projection and Rasterization:**
    a.  Project each remaining voxel onto the image plane.
    b.  To avoid holes caused by adjacent voxels mapping to non-adjacent pixels, project each voxel onto multiple pixels based on the viewing direction and voxel size [S1, unofficial].
    c.  Shade the projected points using lighting conditions (e.g., Phong shading) based on the stored normal and density [S1, unofficial].

5.  **Cutting Plane Integration (Optional):**
    If cutting planes are defined, voxels intersected by the plane are rendered by projecting their original density values onto the image plane, overlaid with the shaded surface points [S1, unofficial].

**Parameters and Edge Cases:**
*   **Viewing Directions:** Six orthographic views are sufficient for an approximate set of visible voxels. Increasing the number of directions improves approximation but increases computation [S1, unofficial].
*   **Holes:** Adjacent voxels may map to non-adjacent pixels. Mitigation involves projecting each voxel onto several pixels [S1, unofficial].
*   **Precision:** Standard floating-point dot product comparisons are used. Degenerate cases (normal perpendicular to view) result in $d=0$, which is rendered.

## Subtopics

### Saito's Fast Previewing Algorithm
A variant that extracts only a subset of boundary voxels according to a uniform distribution to increase rendering speed [S1, unofficial]. Instead of full boundary extraction, it converts extracted surface samples into geometrical primitives (like crosslines perpendicular to the surface normal) and projects them onto the image plane [S1, unofficial]. This is chosen when interactive preview speed is prioritized over geometric completeness.

## Operating characteristics
*   **Time Complexity:** Dominated by the 2D boundary tracing on $N$ slices and the backface culling. Tracing is linear with respect to the number of voxels in the slices. Backface culling is linear with respect to the number of boundary voxels.
*   **Memory Complexity:** Linear with respect to the number of boundary voxels in the volume. The voxel list stores attributes for each visible voxel.
*   **Strengths:** Fast extraction of visible geometry; simple implementation; supports cutting planes natively; suitable for real-time previewing [S1, unofficial].
*   **Limitations:** May produce holes if voxel projection is not handled carefully; relies on orthographic views which may miss some visible surfaces in complex concave shapes; less efficient for static scenes compared to mesh-based culling [S1, unofficial].
*   **When to use:** Interactive medical imaging systems requiring fast preview and cutting plane operations [S1, unofficial].
*   **When not to use:** High-fidelity offline rendering where mesh topology is preferred; scenes with extreme concavity where 6 orthographic views are insufficient.

## Background
Proposed by Sobierajski [116], this method is a fast display technique for direct rendering of boundary surfaces [S1, unofficial]. It is cited in the context of medical imaging systems where flexible manipulation of extracted voxels, such as simultaneous rendering of shaded isosurfaces and arbitrary cross-sectional slices, is important [S1, unofficial]. The method is part of a broader class of hybrid acceleration methods that bridge image-order and object-order rendering [S1, unofficial].
