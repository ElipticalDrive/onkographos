# Extraction of Surface Points (Sobierajski)
Also called: Visible boundary voxel extraction

## Overview
Extraction of Surface Points is a fast display method for the direct rendering of boundary surfaces by extracting only visible boundary voxels from volume data [S1, unofficial]. It solves the problem of high computational cost in volume rendering by avoiding the processing of occluded or internal voxels. It sets itself apart from sibling methods like [Face Culling and Visibility Optimization](3861-face-culling-and-visibility-optimization.md) by operating on a list of extracted 3D points (voxels) rather than generating polygonal meshes or chunks, and by using a multi-view orthographic projection strategy to determine visibility [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Volume data (scalar field), a set of viewing directions (typically six orthographic views), and lighting parameters.
*   **Output:** A list of surface points with attributes (coordinates, normal vectors) passed to a rendering engine, which projects them onto the image plane.

**Data Structures:**
*   **Boundary Voxel List:** A list of objects, each containing:
    *   `coordinates`: 3D integer or float position of the voxel.
    *   `normal_vector`: 3D vector representing the surface normal at that voxel.
    *   `density`: Original density value (used for cutting planes).
*   **Visibility Mask:** Implicitly derived from the 2D boundary tracing results.

**Steps:**

1.  **Visibility Determination:**
    Determine the visibility of boundary voxels using a set of viewing directions. For efficiency, six orthographic views (along the $\pm X, \pm Y, \pm Z$ axes) are often sufficient to approximate the set of all potentially visible boundary voxels [S1, unofficial]. Better approximation can be achieved by increasing the number of directions [S1, unofficial].

2.  **2D Boundary Tracing:**
    Perform visibility calculations using a 2D boundary tracing algorithm on slices perpendicular to each coordinate axis [S1, unofficial]. This identifies which boundary voxels are exposed to the viewing direction.

3.  **List Generation and Deduplication:**
    Generate a list of boundary voxels identified as visible. Remove duplicate elements from this list to ensure each voxel is processed once [S1, unofficial]. Store necessary attributes for rendering, such as coordinates and normal vectors, for each voxel in the list [S1, unofficial].

4.  **Back-Face Culling:**
    Reduce the voxel list size by performing voxel culling similar to back-face culling in polygon rendering [S1, unofficial]. For a specific viewing direction, calculate the dot product between the surface normal $\mathbf{n}$ and the viewing direction $\mathbf{v}$.
    $$ \text{dot} = \mathbf{n} \cdot \mathbf{v} $$
    If $\text{dot} > 0$, the voxel belongs to a back face and is not rendered [S1, unofficial].

5.  **Projection and Hole Avoidance:**
    Pass the set of surface points to the rendering engine. Since adjacent voxels may map to non-adjacent pixels, holes can appear in the image. To avoid this, project each voxel onto several pixels depending on the viewing direction [S1, unofficial]. This ensures image coverage without recursive subdivision.

6.  **Shading and Cutting Planes:**
    Shade the projected boundary surface points according to lighting conditions [S1, unofficial]. If cutting planes are used, render voxels intersected by the cutting planes by projecting their original density values onto the image plane [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Holes:** Adjacent voxels may map to non-adjacent pixels, causing holes. Mitigated by projecting each voxel onto several pixels [S1, unofficial].

## Subtopics

### [Trimmed Voxel Lists](11309-trimmed-voxel-lists.md)
Trimmed Voxel Lists is a surface extraction algorithm that represents an iso-surface using 3D points as geometric primitives, projecting exactly one point per visible surface cell to ensure image coverage without recursive subdivision. It differs from Dividing Cubes by avoiding subdivision; instead, it allows a single projected point to span up to three pixels on the image plane to guarantee coverage.

### Saito's Fast Previewing Algorithm
Saito's Fast Previewing Algorithm is a previewing method based on extracting a subset of boundary voxels according to a uniform distribution to increase rendering speed [S1, unofficial]. It extracts a subset of boundary voxels, converts them to geometrical primitives like crosslines perpendicular to the surface normal, and projects these primitives onto the image plane [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Depends on the number of boundary voxels and the number of viewing directions. 2D boundary tracing is efficient for determining visibility [S1, unofficial].
*   **Memory Complexity:** Proportional to the number of boundary voxels stored in the list [S1, unofficial].
*   **Strengths:** Fast rendering speed due to reduced number of projected primitives; simple implementation; supports cutting planes easily [S1, unofficial].
*   **Limitations:** Potential for holes in the image if not projected onto multiple pixels; approximation of visibility with limited viewing directions [S1, unofficial].
*   **When to Use:** Fast previewing, medical imaging systems where cutting operations are important [S1, unofficial].
*   **When Not to Use:** When high-quality polygonal mesh is required, or when real-time performance is not critical and higher fidelity is needed.

## Background
The method was proposed by Sobierajski [116] as a fast display method for direct rendering of boundary surfaces [S1, unofficial]. It is cited in the context of medical imaging systems where flexible manipulation of extracted voxels, such as cutting operations, is important [S1, unofficial].
