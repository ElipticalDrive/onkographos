# Extraction of Surface Points (Sobierajski)
Also called: Visible boundary voxel extraction

## Overview
Extraction of Surface Points is a fast display method for the direct rendering of boundary surfaces by extracting only visible boundary voxels from volume data [S1, unofficial]. It solves the problem of rendering complex 3D surfaces efficiently by avoiding the processing of occluded or internal geometry. Unlike sibling methods that generate full blocky meshes or use complex culling masks, this method projects discrete surface points directly to the image plane, using viewing direction checks to prune the voxel list before rendering [S1, unofficial].

## How it works
**Inputs:**
*   Volume data $V$ (3D grid of density/opacity values).
*   Set of viewing directions $\mathcal{D}$ (typically six orthographic directions: $\pm x, \pm y, \pm z$) [S1, unofficial].
*   Lighting parameters for shading [S1, unofficial].

**Outputs:**
*   A list of visible boundary voxels, each containing coordinates and normal vectors [S1, unofficial].
*   Rendered image with shaded surface points and optional cutting plane slices [S1, unofficial].

**Data Structures:**
*   **Boundary Voxel List:** A dynamic list storing tuples $(x, y, z, n_x, n_y, n_z)$, where $(x,y,z)$ are voxel indices and $(n_x, n_y, n_z)$ is the surface normal. Duplicates are removed [S1, unofficial].

**Steps:**
1.  **Visibility Determination:** For each viewing direction $d \in \mathcal{D}$, determine which boundary voxels are potentially visible. This is done using a 2D boundary tracing algorithm on slices perpendicular to each coordinate axis [S1, unofficial].
2.  **Extraction:** Extract the boundary voxels identified as visible. Remove duplicate entries from the list to ensure each voxel is processed once [S1, unofficial].
3.  **Back-face Culling:** For each voxel in the list, calculate the dot product between its surface normal $\mathbf{n}$ and the current viewing direction $\mathbf{v}$. If $\mathbf{n} \cdot \mathbf{v} > 0$, the voxel is a back face and is removed from the list [S1, unofficial].
4.  **Projection:** Project each remaining voxel onto the image plane. To prevent holes in the rendered image caused by non-adjacent voxels mapping to non-adjacent pixels, each voxel is projected onto multiple pixels depending on the viewing direction [S1, unofficial].
5.  **Shading:** Shade the projected boundary surface points according to lighting conditions [S1, unofficial].
6.  **Cutting Planes (Optional):** If cutting planes are defined, render voxels intersected by these planes by projecting their original density values onto the image plane, composited with the shaded surface points [S1, unofficial].

**Pseudocode:**
```python
def extract_surface_points(volume, viewing_directions, lighting):
    visible_voxels = []
    
    # Step 1 & 2: Visibility determination and extraction
    for direction in viewing_directions:
        # Perform 2D boundary tracing on slices perpendicular to direction
        # to find potentially visible boundary voxels
        candidates = trace_boundary(volume, direction)
        visible_voxels.extend(candidates)
    
    # Remove duplicates
    visible_voxels = remove_duplicates(visible_voxels)
    
    # Step 3: Back-face culling
    filtered_voxels = []
    for voxel in visible_voxels:
        normal = compute_normal(volume, voxel.position)
        # If dot product is positive, it's a back face
        if dot(normal, direction) <= 0:
            filtered_voxels.append(voxel)
    
    # Step 4: Projection
    image = create_image()
    for voxel in filtered_voxels:
        # Project voxel to multiple pixels to avoid holes
        pixels = project_to_pixels(voxel.position, direction)
        for pixel in pixels:
            image[pixel] = shade(voxel, lighting)
            
    # Step 6: Cutting planes
    if cutting_planes_defined:
        for plane in cutting_planes:
            intersecting_voxels = get_intersecting_voxels(volume, plane)
            for voxel in intersecting_voxels:
                pixel = project_density(voxel, plane)
                image[pixel] = voxel.density
                
    return image
```

**Edge Cases and Pitfalls:**
*   **Holes:** Adjacent voxels may map to non-adjacent pixels, creating holes. Mitigated by projecting each voxel onto several pixels [S1, unofficial].
*   **Precision:** The dot product check for back-face culling must handle floating-point precision issues near the horizon (where $\mathbf{n} \cdot \mathbf{v} \approx 0$) [S1, unofficial].
*   **Viewing Directions:** Using only six orthographic views provides an approximate set of visible voxels. Increasing the number of directions improves accuracy but increases computation [S1, unofficial].

## Subtopics

### [Trimmed Voxel Lists](11309-trimmed-voxel-lists.md)
Trimmed Voxel Lists is a surface extraction algorithm that represents an iso-surface using 3D points as geometric primitives, projecting exactly one point per visible surface cell to ensure image coverage without recursive subdivision. It differs from Dividing Cubes by avoiding subdivision; instead, it allows a single projected point to span up to three pixels on the image plane to guarantee coverage.

### Saito's Fast Previewing Algorithm
Saito's Fast Previewing Algorithm is a previewing method based on extracting a subset of boundary voxels according to a uniform distribution to increase rendering speed [S1, unofficial]. It extracts a subset of boundary voxels, converts them to geometrical primitives like crosslines perpendicular to the surface normal, and projects these primitives onto the image plane [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Depends on the number of boundary voxels and the number of viewing directions. The 2D boundary tracing is efficient for orthographic views [S1, unofficial].
*   **Memory Complexity:** Proportional to the number of visible boundary voxels, as only a list of points is stored [S1, unofficial].
*   **Strengths:** Fast rendering speed due to reduced voxel list size via culling; simple implementation; supports cutting planes [S1, unofficial].
*   **Limitations:** Approximate visibility with limited viewing directions; potential for holes if projection is not handled carefully; less geometric detail than mesh-based methods [S1, unofficial].
*   **When to Use:** Real-time previewing or applications where speed is prioritized over geometric precision [S1, unofficial].
*   **When Not to Use:** Applications requiring high-fidelity surface geometry or complex lighting interactions [S1, unofficial].

## Background
The method was proposed by Sobierajski [116] as a fast display method for direct rendering of boundary surfaces [S1, unofficial]. It is cited in the context of medical imaging systems, where cutting operations and simultaneous rendering of shaded isosurfaces and cross-sectional slices are important [S1, unofficial]. The approach is related to Saito's fast previewing algorithm [117], which also extracts boundary voxels but uses a uniform distribution subset for speed [S1, unofficial].
