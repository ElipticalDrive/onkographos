# Extraction of Surface Points (Sobierajski)

Also called: Sobierajski's method, Visible boundary voxel extraction

## Overview
Sobierajski's method is a fast display technique for the direct rendering of boundary surfaces by extracting only visible boundary voxels from volume data [S1, unofficial]. It solves the problem of high computational cost in volume rendering by reducing the primitive count to only those voxels potentially visible from a predefined set of viewing directions [S1, unofficial]. It sets itself apart from sibling methods like [Face Culling and Visibility Optimization](3861-face-culling-and-visibility-optimization.md) by operating on a per-voxel basis using orthographic visibility tests rather than per-face geometric culling, and from [Saito's Fast Previewing Algorithm](#saitos-fast-previewing-algorithm) by extracting the full set of visible boundary voxels rather than a sparse subset.

## How it works
**Inputs:**
*   Volume data grid $V$ of dimensions $D_x \times D_y \times D_z$.
*   A set of viewing directions $\mathcal{D} = \{\vec{d}_1, \dots, \vec{d}_k\}$. Typically, the six orthographic directions $\{\pm \hat{x}, \pm \hat{y}, \pm \hat{z}\}$ are used [S1, unofficial].
*   A threshold for boundary detection (implicit in the boundary tracing step).

**Outputs:**
*   A list of unique boundary voxels, each storing coordinates $(x, y, z)$ and normal vector $\vec{n}$ [S1, unofficial].

**Data Structures:**
*   `BoundaryVoxel`: A struct containing:
    *   `pos`: integer tuple $(x, y, z)$ representing the voxel index.
    *   `normal`: float tuple $(n_x, n_y, n_z)$ representing the outward surface normal.
*   `VisibleSet`: A set or hash map used to store unique `BoundaryVoxel` entries to remove duplicates [S1, unofficial].

**Steps:**

1.  **Visibility Determination via Orthographic Views:**
    For each viewing direction $\vec{d} \in \mathcal{D}$, determine which boundary voxels are visible.
    *   If $\mathcal{D}$ consists of the six orthographic views, visibility is calculated efficiently using a 2D boundary tracing algorithm on slices perpendicular to each coordinate axis [S1, unofficial].
    *   For a general direction $\vec{d}$, project the volume onto a 2D plane perpendicular to $\vec{d}$. Identify boundary voxels that are not occluded by other solid voxels along the ray defined by $\vec{d}$ [S1, unofficial].

2.  **Boundary Voxel Extraction:**
    *   Iterate through the volume data to identify boundary voxels. A voxel is a boundary voxel if it is solid (e.g., density above threshold) and has at least one adjacent empty neighbor [S1, unofficial].
    *   For each identified boundary voxel, compute its outward normal $\vec{n}$.
    *   Add the voxel to `VisibleSet` if it is determined to be visible in any direction in $\mathcal{D}$ [S1, unofficial].

3.  **Duplicate Removal:**
    *   The `VisibleSet` inherently handles duplicate removal, ensuring each boundary voxel is stored only once in the final list [S1, unofficial].

4.  **Voxel Culling (Backface Culling):**
    *   For the current rendering view direction $\vec{v}$, reduce the voxel list size by culling back faces [S1, unofficial].
    *   For each voxel in the list with normal $\vec{n}$, calculate the dot product:
        $$ \text{dot} = \vec{n} \cdot \vec{v} $$
    *   If $\text{dot} > 0$, the voxel is a back face and is not rendered [S1, unofficial].
    *   Note: The viewing direction $\vec{v}$ in the dot product formula points from the camera to the object (consistent with the parent article's definition). If $\vec{v}$ points from the object to the camera, the condition would be $\text{dot} < 0$ [S1, unofficial].

5.  **Projection and Hole Avoidance:**
    *   Project each remaining voxel onto the image plane [S1, unofficial].
    *   To avoid holes caused by adjacent voxels mapping to non-adjacent pixels, project each voxel onto several pixels depending on the viewing direction [S1, unofficial]. This can be achieved by expanding the projected footprint of the voxel based on the perspective or orthographic projection parameters.

6.  **Rendering:**
    *   Pass the set of surface points to the rendering engine [S1, unofficial].
    *   Shade the projected boundary surface points according to lighting conditions [S1, unofficial].
    *   If cutting planes are used, render voxels intersected by the cutting plane by projecting their original density values onto the image plane [S1, unofficial].

*   **Viewing Directions:** Typically six orthographic views ($\pm \hat{x}, \pm \hat{y}, \pm \hat{z}$) are sufficient for an approximate set of all potentially visible boundary voxels [S1, unofficial]. **Edge Cases and Pitfalls:**
*   **Holes:** Adjacent voxels may map to non-adjacent pixels, causing holes in the image. This is mitigated by projecting each voxel onto several pixels [S1, unofficial].
*   **Precision:** The dot product calculation for backface culling must handle floating-point precision carefully to avoid culling front faces due to numerical error [G].

## Subtopics

### Saito's Fast Previewing Algorithm
A previewing algorithm based on extracting a subset of boundary voxels according to a uniform distribution to increase rendering speed [S1, unofficial]. It differs from Sobierajski's method by extracting only a subset of boundary voxels rather than all visible ones [S1, unofficial]. The extracted surface samples are converted to geometrical primitives like crosslines perpendicular to the surface normal and projected onto the image plane [S1, unofficial]. It is chosen when rendering speed is prioritized over visual completeness, such as in interactive previewing [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The visibility calculation using six orthographic views and 2D boundary tracing is efficient, but the exact complexity depends on the implementation of the 2D boundary tracing algorithm [S1, unofficial]. The voxel culling step is linear with respect to the number of boundary voxels [S1, unofficial].
*   **Memory Complexity:** Linear with respect to the number of boundary voxels, as it stores a list of unique boundary voxels [S1, unofficial].
*   **Strengths:** Fast rendering speed due to reduced primitive count; simple implementation of cutting planes [S1, unofficial].
*   **Limitations:** May produce holes if not projected onto multiple pixels; visibility approximation may be incomplete with only six orthographic views [S1, unofficial].
*   **When to use:** When fast display of boundary surfaces is required, and approximate visibility is acceptable [S1, unofficial].
*   **When not to use:** When high visual fidelity without holes is required, or when complex lighting/shading is needed beyond simple shading [S1, unofficial].

## Background
Sobierajski proposed this fast display method for direct rendering of boundary surfaces [S1, unofficial]. It is cited in the context of medical imaging systems, where flexible manipulation of extracted voxels, such as cutting operations, is important [S1, unofficial]. The method is compared with Saito's fast previewing algorithm and shear-warp factorization in the context of hybrid acceleration methods [S1, unofficial].
