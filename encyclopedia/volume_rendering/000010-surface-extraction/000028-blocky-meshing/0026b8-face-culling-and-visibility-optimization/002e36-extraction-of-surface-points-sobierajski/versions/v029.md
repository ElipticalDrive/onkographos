# Extraction of Surface Points (Sobierajski)
Also called: Visible boundary voxel extraction

## Overview
Extraction of Surface Points is a fast display method for the direct rendering of boundary surfaces by extracting only visible boundary voxels from volume data [S1, unofficial]. It solves the problem of rendering overhead by generating a minimal set of geometric primitives (surface points) that cover the visible surface, rather than rendering the entire volume or a dense mesh. It sets itself apart from sibling methods like [Voxel Block Placement with Face Culling](923-voxel-block-placement-with-face-culling.md) by operating on individual voxels as points projected to screen space, and from [Face Culling](8735-face-culling.md) by relying on multi-view visibility determination rather than purely local neighbor checks.

## How it works
**Inputs:** Volume data (scalar field), viewing directions (typically six orthographic views), lighting parameters.
**Outputs:** A list of visible boundary voxels with attributes (coordinates, normal vectors) passed to a rendering engine.

**Data Structures:**
*   **Voxel List:** A dynamic list storing tuples for each visible boundary voxel. Each tuple contains:
    *   `position`: 3D integer coordinates $(x, y, z)$ of the voxel.
    *   `normal`: 3D vector $(n_x, n_y, n_z)$ representing the surface normal at that voxel.
    *   `density`: Scalar value (optional, for cutting plane rendering).

**Steps:**

1.  **Visibility Determination:**
    Determine the set of potentially visible boundary voxels using a set of viewing directions. For efficiency, six orthographic views (along $\pm x, \pm y, \pm z$) are often sufficient [S1, unofficial].
    *   For each viewing direction, perform a 2D boundary tracing algorithm on slices perpendicular to the coordinate axis corresponding to that view.
    *   Identify voxels that form the boundary between occupied and empty space in that projection.

2.  **Deduplication:**
    Merge the lists of boundary voxels from all viewing directions. Remove duplicate elements from the combined list to ensure each visible voxel is represented only once [S1, unofficial].

3.  **Attribute Assignment:**
    For each unique voxel in the list, compute and store necessary attributes for rendering:
    *   **Coordinates:** The center or corner of the voxel.
    *   **Normal Vector:** Compute the surface normal. For a voxel at $P$ with neighbor $P_{neighbor}$, the normal $N$ is typically $P_{neighbor} - P$ normalized, or derived from the gradient of the scalar field if available.

4.  **Backface Culling:**
    Reduce the voxel list size by filtering out voxels facing away from the camera. For a specific viewing direction (camera view vector $V$):
    *   Calculate the dot product of the surface normal $N$ and the viewing direction $V$.
    *   If $N \cdot V > 0$, the voxel is a back face and is not rendered [S1, unofficial].
    *   *Note:* This step is performed per-view during the rendering pass or pre-filtered if the view is fixed.

5.  **Projection and Coverage:**
    Pass the set of surface points to the rendering engine.
    *   Project each voxel onto the image plane.
    *   To avoid holes caused by adjacent voxels mapping to non-adjacent pixels, project each voxel onto several pixels depending on the viewing direction [S1, unofficial]. This ensures image coverage without recursive subdivision.

6.  **Rendering and Shading:**
    *   Shade the projected boundary surface points according to lighting conditions (e.g., Phong shading).
    *   If cutting planes are used, render voxels intersected by the cutting plane by projecting their original density values onto the image plane [S1, unofficial].

**Pseudocode:**

```python
def extract_visible_boundary_voxels(volume_data, viewing_directions):
    """
    Extracts visible boundary voxels using multi-view visibility.
    
    Args:
        volume_data: 3D array of scalar values.
        viewing_directions: List of 3D vectors representing camera views.
        
    Returns:
        visible_voxels: List of dicts with 'pos', 'normal', 'density'.
    """
    all_boundary_voxels = set()
    
    # Step 1 & 2: Visibility Determination and Deduplication
    for view_dir in viewing_directions:
        # Determine axis perpendicular to view for 2D slicing
        # Simplified: assume orthographic views along axes for this example
        axis = get_axis_from_view(view_dir)
        
        # Perform 2D boundary tracing on slices perpendicular to axis
        # This identifies voxels on the boundary of the object in this projection
        boundary_in_view = trace_2d_boundaries(volume_data, axis)
        
        # Add to global set (deduplication happens automatically in set)
        for voxel in boundary_in_view:
            all_boundary_voxels.add(voxel)
            
    # Step 3: Attribute Assignment
    visible_voxels = []
    for voxel_pos in all_boundary_voxels:
        normal = compute_normal(volume_data, voxel_pos)
        density = volume_data[voxel_pos]
        visible_voxels.append({
            'pos': voxel_pos,
            'normal': normal,
            'density': density
        })
        
    return visible_voxels

def render_visible_voxels(visible_voxels, camera_view_dir, image_plane):
    """
    Renders the extracted voxels with backface culling and projection.
    """
    for voxel in visible_voxels:
        # Step 4: Backface Culling
        # If dot product of normal and view direction is positive, it's a back face
        if dot(voxel['normal'], camera_view_dir) > 0:
            continue
            
        # Step 5: Projection
        # Project voxel to multiple pixels to avoid holes
        projected_pixels = project_onto_pixels(voxel['pos'], camera_view_dir, image_plane)
        
        # Step 6: Shading
        for pixel in projected_pixels:
            color = shade(voxel['normal'], camera_view_dir, voxel['density'])
            write_to_image(pixel, color)
```

**Parameters:**
*   **Viewing Directions:** Typically 6 orthographic views ($\pm x, \pm y, \pm z$). Increasing the number of directions improves approximation of visible surfaces [S1, unofficial].
*   **Projection Radius:** Number of pixels per voxel to prevent holes. Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Holes:** Adjacent voxels may map to non-adjacent pixels, creating gaps. Mitigated by projecting each voxel onto several pixels [S1, unofficial].
*   **Precision:** Dot product calculation for backface culling should handle floating-point inaccuracies near the threshold of 0.
*   **Degenerate Input:** Empty volume data results in an empty voxel list.

## Subtopics

### [Trimmed Voxel Lists](11309-trimmed-voxel-lists.md)
Trimmed Voxel Lists is a surface extraction algorithm that represents an iso-surface using 3D points as geometric primitives, projecting exactly one point per visible surface cell to ensure image coverage without recursive subdivision. It differs from Dividing Cubes by avoiding subdivision; instead, it allows a single projected point to span up to three pixels on the image plane to guarantee coverage.

### Saito's Fast Previewing Algorithm
A previewing algorithm based on extracting a subset of boundary voxels according to a uniform distribution to increase rendering speed [S1, unofficial]. It extracts a subset of boundary voxels, converts them to geometrical primitives like crosslines perpendicular to the surface normal, and projects them onto the image plane [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Depends on the number of viewing directions and the cost of 2D boundary tracing. Generally faster than full volume rendering as it reduces the number of primitives.
*   **Memory Complexity:** Proportional to the number of visible boundary voxels. Significantly less than storing the full volume or a dense mesh.
*   **Strengths:** Fast rendering speed due to reduced primitive count; simple implementation; supports cutting planes easily [S1, unofficial].
*   **Limitations:** May produce holes if projection is not handled carefully; visibility approximation may be incomplete with only 6 views; not suitable for highly transparent volumes without additional techniques.
*   **When to Use:** Medical imaging systems requiring fast previewing or interactive manipulation of isosurfaces [S1, unofficial].
*   **When Not to Use:** When high-quality, hole-free rendering is required without post-processing; when the volume is highly transparent.

## Background
The method was proposed by Sobierajski [116] as a fast display method for direct rendering of boundary surfaces [S1, unofficial]. It is cited in the context of medical imaging systems where cutting operations are important, allowing simultaneous rendering of shaded isosurfaces and arbitrary cross-sectional slices [S1, unofficial]. The approach is part of a broader family of hybrid acceleration methods in volume rendering.
