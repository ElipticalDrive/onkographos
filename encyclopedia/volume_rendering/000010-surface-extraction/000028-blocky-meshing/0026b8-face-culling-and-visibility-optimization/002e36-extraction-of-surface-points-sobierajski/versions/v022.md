# Extraction of Surface Points (Sobierajski)
Also called: Sobierajski's method, Visible boundary voxel extraction

## Overview
A fast display method for direct rendering of boundary surfaces by extracting only visible boundary voxels from volume data [S1, unofficial]. It sets itself apart from sibling methods like [Face Culling and Visibility Optimization](3861-face-culling-and-visibility-optimization.md) by operating in object space to generate a pre-filtered list of surface points rather than generating geometry per-voxel during rasterization, and from [Face Coverage Mask Culling](3397-face-coverage-mask-culling.md) by relying on orthographic visibility projections rather than coverage masks to determine which voxels are rendered [S1, unofficial].

## How it works
**Inputs:** Volume data grid; set of viewing directions (typically six orthographic views along coordinate axes) [S1, unofficial].
**Outputs:** A list of unique boundary voxels with attributes (coordinates, normal vectors) [S1, unofficial].

**Data Structures:**
*   `VoxelList`: A dynamic array or linked list storing extracted boundary voxels.
*   `VoxelAttributes`: Struct containing `position` (3D integer coordinates), `normal` (3D float vector), and `density` (float) [S1, unofficial].
*   `VisitedSet`: A hash set or boolean grid to track processed voxels for duplicate removal [G].

**Steps:**
1.  **Visibility Determination:** For each of the $N$ viewing directions (e.g., $\pm X, \pm Y, \pm Z$), perform a 2D boundary tracing algorithm on slices perpendicular to the viewing axis [S1, unofficial]. A voxel is marked as potentially visible if it lies on the boundary of the occupied region in that projection [S1, unofficial].
2.  **Extraction and Deduplication:** Collect all voxels marked as visible in any direction. Remove duplicates from the `VoxelList` [S1, unofficial].
3.  **Attribute Assignment:** For each unique voxel in the list, compute and store the surface normal vector and coordinates [S1, unofficial].
4.  **Backface Culling (Voxel Culling):** For a specific rendering view, filter the `VoxelList`. If the dot product of the voxel's surface normal $\mathbf{n}$ and the viewing direction $\mathbf{v}$ is positive, the voxel is a back face and is excluded from rendering [S1, unofficial]:
    $$ \mathbf{n} \cdot \mathbf{v} > 0 \implies \text{Cull} $$
5.  **Projection:** Project each remaining voxel onto the image plane. To avoid holes caused by adjacent voxels mapping to non-adjacent pixels, project each voxel onto multiple pixels depending on the viewing direction and voxel size [S1, unofficial].
6.  **Rendering:** Shade the projected points using lighting conditions. If cutting planes are used, render voxels intersected by the plane by projecting their original density values [S1, unofficial].

**Pseudocode:**
```python
def extract_visible_boundary_voxels(volume, viewing_directions):
    """
    Extracts visible boundary voxels using 2D boundary tracing on orthographic slices.
    volume: 3D array of density values.
    viewing_directions: List of 3D vectors (e.g., [1,0,0], [-1,0,0], ...).
    Returns: List of VoxelAttributes.
    """
    visible_voxels = set()
    
    # Step 1 & 2: Visibility Determination and Extraction
    for direction in viewing_directions:
        # Perform 2D boundary tracing on slices perpendicular to direction
        # This identifies voxels on the silhouette of the volume from this view
        slice_voxels = trace_boundary_in_direction(volume, direction)
        visible_voxels.update(slice_voxels)
        
    # Step 3: Attribute Assignment
    voxel_list = []
    for voxel_pos in visible_voxels:
        normal = compute_surface_normal(volume, voxel_pos)
        voxel_list.append({
            'position': voxel_pos,
            'normal': normal,
            'density': volume[voxel_pos]
        })
        
    return voxel_list

def render_with_sobierajski(voxel_list, view_direction, image_plane):
    """
    Renders the extracted voxel list with backface culling and projection.
    """
    # Step 4: Backface Culling
    renderable_voxels = []
    for voxel in voxel_list:
        # If dot product is positive, it's a back face
        if dot(voxel['normal'], view_direction) > 0:
            continue
        renderable_voxels.append(voxel)
        
    # Step 5 & 6: Projection and Shading
    for voxel in renderable_voxels:
        # Project voxel to multiple pixels to avoid holes
        pixels = project_onto_pixels(voxel['position'], voxel['normal'], view_direction)
        for pixel in pixels:
            shade_pixel(pixel, voxel['density'], lighting_model)
```

**Parameters:**
*   `viewing_directions`: Typically six orthographic views ($\pm X, \pm Y, \pm Z$) [S1, unofficial]. Increasing the number of directions improves approximation of visible surfaces [S1, unofficial].

**Edge Cases:**
*   **Holes:** Adjacent voxels may map to non-adjacent pixels, creating holes. Mitigated by projecting each voxel onto several pixels [S1, unofficial].
*   **Duplicate Voxels:** A voxel visible from multiple directions is added multiple times during extraction. Deduplication is required [S1, unofficial].

## Subtopics

### Saito's Fast Previewing Algorithm
A previewing algorithm based on extracting a subset of boundary voxels according to a uniform distribution to increase rendering speed [S1, unofficial]. It differs from the main method by not extracting all visible voxels, but rather a sparse subset [S1, unofficial]. The extracted samples are converted to geometrical primitives (e.g., crosslines perpendicular to the surface normal) and projected onto the image plane [S1, unofficial].

### Trimmed Voxel Lists
A surface rendering algorithm that uses 3D points as geometric primitives by projecting exactly one point per visible surface cell to ensure image coverage without subdivision [S2, unofficial]. It differs from Dividing Cubes by avoiding recursive subdivision; instead, it projects a single point per cell that can span up to three pixels to guarantee coverage [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Dominated by the 2D boundary tracing on $N$ views. Tracing is linear with respect to the number of voxels in the slices [S1, unofficial].
*   **Memory Complexity:** Proportional to the number of visible boundary voxels, which is typically much smaller than the total volume [S1, unofficial].
*   **Strengths:** Fast rendering speed due to reduced number of projected primitives; supports flexible manipulation of extracted voxels (e.g., cutting planes) [S1, unofficial].
*   **Limitations:** Approximate visibility (unless infinite views are used); potential for holes if projection step is insufficient; geometric primitives only approximate the surface [S2, unofficial].
*   **When to use:** Fast previewing or direct rendering where speed is prioritized over perfect geometric accuracy [S1, unofficial].

## Background
Proposed by Sobierajski [116] as a fast display method for direct rendering of boundary surfaces [S1, unofficial]. It is cited in surveys of medical volume rendering techniques [S1, unofficial]. Saito's variant [117] is also discussed in the same context [S1, unofficial]. The Trimmed Voxel Lists method is discussed in Kaufman's Volume Visualization principles [S2, unofficial].
