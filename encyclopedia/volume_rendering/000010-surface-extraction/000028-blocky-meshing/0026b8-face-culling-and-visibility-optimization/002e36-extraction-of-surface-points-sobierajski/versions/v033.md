# Extraction of Surface Points (Sobierajski)

Also called: Visible boundary voxel extraction

## Overview
Extraction of Surface Points is a direct volume rendering method that accelerates surface visualization by extracting only the visible boundary voxels from the volume data, rather than generating a full mesh or ray-casting the entire volume [S1, unofficial]. It solves the problem of high computational cost in surface rendering by reducing the number of primitives sent to the rasterizer. It differs from [Face Culling](8735-face-culling.md) by operating on individual voxels and projecting them as points rather than generating polygonal faces, and from [Voxel Block Placement with Face Culling](923-voxel-block-placement-with-face-culling.md) by using a multi-view visibility check to determine which voxels are potentially visible before projection.

## How it works
The method extracts a list of boundary voxels that are visible from a set of predefined viewing directions, projects them onto the image plane, and renders them as shaded points.

**Inputs:**
*   Volume data $V$ (density/opacity values).
*   Set of viewing directions $D = \{d_1, d_2, ..., d_n\}$. Typically, the six orthographic views are used [S1, unofficial].

**Outputs:**
*   A list of surface points $P$, where each point contains coordinates $(x, y, z)$ and normal vector $\mathbf{n}$.

**Data Structures:**
*   **Visibility Mask:** A 3D boolean array or bitfield indicating if a voxel is visible from any direction in $D$.
*   **Surface Point List:** A dynamic list of structures containing:
    *   `coord`: 3D integer voxel coordinates.
    *   `normal`: 3D float normal vector.
    *   `density`: Original density value (for cutting planes).

**Steps:**

1.  **Visibility Determination:**
    For each viewing direction $d_i \in D$:
    *   Project the volume onto a 2D slice perpendicular to $d_i$.
    *   Perform a 2D boundary tracing algorithm on the slice to identify boundary voxels visible from $d_i$ [S1, unofficial].
    *   Mark these voxels as visible in the global visibility mask.
    *   *Note:* Using six orthographic views provides an approximate set of all potentially visible boundary voxels [S1, unofficial].

2.  **Extraction and Deduplication:**
    *   Iterate through all voxels marked as visible.
    *   Extract attributes: coordinates and normal vectors.
    *   Remove duplicate entries (voxels visible from multiple directions) to form the final list $P$ [S1, unofficial].

3.  **Back-Face Culling (Voxel Culling):**
    For each point $p \in P$ with normal $\mathbf{n}_p$ and current view direction $\mathbf{v}$:
    *   Calculate the dot product: $dot = \mathbf{n}_p \cdot \mathbf{v}$.
    *   If $dot > 0$, the voxel is a back face. Remove $p$ from the list to be rendered [S1, unofficial].
    *   *Note:* This reduces the voxel list size, directly improving rendering speed [S1, unofficial].

4.  **Projection and Anti-Holing:**
    *   Project each remaining voxel onto the image plane.
    *   To avoid holes caused by adjacent voxels mapping to non-adjacent pixels, project each voxel onto multiple pixels depending on the viewing direction [S1, unofficial]. The exact projection footprint is not specified in the sources but is determined by the viewing angle and voxel size [S1, unofficial].

5.  **Rendering:**
    *   Shade the projected boundary surface points according to lighting conditions [S1, unofficial].
    *   If cutting planes are used, render voxels intersected by the plane by projecting their original density values onto the image plane [S1, unofficial].

**Pseudocode:**

```python
def extract_surface_points(volume, viewing_directions):
    """
    Extracts visible boundary voxels and prepares them for rendering.
    
    Args:
        volume: 3D array of density values.
        viewing_directions: List of 3D vectors representing camera/view directions.
        
    Returns:
        surface_points: List of dicts with 'coord', 'normal', 'density'.
    """
    visible_mask = create_3d_bool_array(volume.shape, False)
    
    # Step 1: Determine visibility using 2D boundary tracing on slices
    for direction in viewing_directions:
        # Project volume onto 2D slice perpendicular to direction
        # Perform 2D boundary tracing to find visible boundary voxels
        visible_voxels = trace_2d_boundary(volume, direction)
        
        # Mark voxels as visible
        for voxel in visible_voxels:
            visible_mask[voxel] = True

    # Step 2: Extract and deduplicate
    surface_points = []
    seen_coords = set()
    
    for voxel in get_all_voxels(volume):
        if visible_mask[voxel]:
            if voxel not in seen_coords:
                seen_coords.add(voxel)
                normal = compute_normal(volume, voxel)
                surface_points.append({
                    'coord': voxel,
                    'normal': normal,
                    'density': volume[voxel]
                })

    return surface_points

def render_surface_points(surface_points, view_direction):
    """
    Renders the extracted points with back-face culling and projection.
    """
    rendered_pixels = []
    
    for point in surface_points:
        # Step 3: Back-face culling
        dot_product = dot(point['normal'], view_direction)
        
        if dot_product > 0:
            # Back face, skip rendering
            continue
            
        # Step 4: Projection
        # Project voxel onto multiple pixels to avoid holes
        # The exact projection pattern depends on viewing direction
        projected_pixels = project_onto_image(point['coord'], view_direction)
        
        for pixel in projected_pixels:
            # Step 5: Shading
            color = shade(point['density'], point['normal'], view_direction)
            rendered_pixels.append((pixel, color))
            
    return rendered_pixels
```

**Parameters:**
*   **Viewing Directions:** Typically 6 orthographic views [S1, unofficial]. Increasing the number of directions improves the approximation of the visible surface set [S1, unofficial].
*   **Projection Footprint:** Not explicitly defined, but must cover multiple pixels to prevent holes [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Holes:** Adjacent voxels may map to non-adjacent pixels, creating holes in the image. Mitigated by projecting each voxel onto several pixels [S1, unofficial].
*   **Precision:** The dot product calculation for back-face culling must handle floating-point precision carefully to avoid culling front-facing voxels due to numerical error [G].
*   **Boundary Conditions:** The 2D boundary tracing algorithm must correctly handle the edges of the volume slices [S1, unofficial].

## Subtopics

### [Trimmed Voxel Lists](11309-trimmed-voxel-lists.md)
Trimmed Voxel Lists is a surface extraction algorithm that represents an iso-surface using 3D points as geometric primitives, projecting exactly one point per visible surface cell to ensure image coverage without recursive subdivision. It differs from Dividing Cubes by avoiding subdivision; instead, it allows a single projected point to span up to three pixels on the image plane to guarantee coverage.

### Saito's Fast Previewing Algorithm
A previewing algorithm based on extracting a subset of boundary voxels according to a uniform distribution to increase rendering speed [S1, unofficial]. It extracts a subset of boundary voxels, converts them to geometrical primitives like crosslines perpendicular to the surface normal, and projects them onto the image plane [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Dominated by the 2D boundary tracing on $N$ views. For $V$ voxels and $D$ views, complexity is roughly $O(D \cdot V)$ for visibility determination, plus $O(P)$ for projection, where $P$ is the number of visible voxels [S1, unofficial].
*   **Memory Complexity:** $O(V)$ for the visibility mask and $O(P)$ for the surface point list [S1, unofficial].
*   **Strengths:** Fast previewing; reduces the number of primitives sent to the rasterizer; supports cutting planes easily [S1, unofficial].
*   **Limitations:** Approximate visibility (depends on number of views); potential for holes if projection footprint is not large enough; not suitable for high-quality final rendering without further processing [S1, unofficial].
*   **When to use:** Fast previewing, medical imaging systems where cutting operations are important [S1, unofficial].
*   **When not to use:** High-quality final rendering requiring smooth surfaces; scenes with complex occlusion not covered by the viewing directions.

## Background
The method was proposed by Sobierajski [116] as a fast display method for direct rendering of boundary surfaces [S1, unofficial]. It is cited in the context of medical imaging systems where flexible manipulation of extracted voxels is important, such as simultaneous rendering of shaded isosurfaces and arbitrary cross-sectional slices [S1, unofficial].
