# Voxel Backface Culling and Internal Face Masking

Also called: Internal Face Masking, Voxel Backface Culling

## Overview
Voxel Backface Culling and Internal Face Masking is a technique to reject invisible faces in voxel rendering by determining front/back orientation in projection space and masking faces shared between neighboring voxels [S1, unofficial]. It sets itself apart from sibling methods by performing visibility checks directly within the geometry shader pipeline using a packed 32-bit integer attribute, allowing for immediate rejection of internal faces and back-facing quads without requiring pre-computed mesh topology or complex chunk boundary handling [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A voxel chunk (typically $32^3$ voxels) processed by a geometry shader. Each voxel is represented by a position and a 32-bit integer code (`vs_out_VoxelCode[0]`) containing visibility masks and position data [S1, unofficial].
*   **Output:** A stream of triangle strips (quads) for visible front and back faces of the voxel [S1, unofficial].

**Data Structures**
The core data structure is a 32-bit integer encoding invisible masking and position [S1, unofficial]:
*   **Bits 0-5:** Mask for each of the 6 sides of the voxel (1 bit per side).
*   **Bits 6-30:** Position information (3 * 8 bits for x, y, z coordinates).
*   **Bits 31-32:** Unused (2 bits) [S1, unofficial].

This layout allows addressing $256^3$ positions, necessitating a chunked approach for larger models [S1, unofficial].

**Parameters**
*   **Chunk Size:** $32^3$ voxels per chunk [S1, unofficial].
*   **Projection Matrix:** The standard perspective projection matrix $mProjection$ is required to compute the inverse diagonal [S1, unofficial].

**Steps**
1.  **Frustum Culling:** Calculate the world-space bounding box of the voxel. Transform corners to clip space. If the voxel is outside the viewing volume (defined by $|vPos.z| > w$ or $|vPos.x| > w$ or $|vPos.y| > w$, where $w$ is the maximum length of the voxel corners plus the position w-component), discard the voxel [S1, unofficial].
2.  **Transform View Direction:** Transform the view direction from projection space to view space using the inverse diagonal of the projection matrix:
    $$ v_{view} = v_{proj} * (1/mProjection[0][0], 1/mProjection[1][1], 1/mProjection[2][2]) $$
    [S1, unofficial]
3.  **Determine Face Orientation:** Calculate the dot product of the sum of two specific voxel corners (transformed by the inverse projection diagonal) and the view direction:
    $$ \text{dot}((c\_vCorner000.xyz + c\_vCorner110.xyz) * c\_vInverseProjection.xyz, vViewDirection) $$
    [S1, unofficial]
4.  **Process Front Face:** If the dot product is greater than 0, the front face is potentially visible. Check if the voxel code bit `0x10` is set in `vs_out_VoxelCode[0]`. If set, emit the front face vertices ($c\_vCorner000, c\_vCorner100, c\_vCorner010, c\_vCorner110$) and compute lighting with normal $(0,0,-1)$ transformed by the world-view matrix [S1, unofficial].
5.  **Process Back Face:** If the dot product is not greater than 0, the back face is potentially visible. Check if the voxel code bit `0x20` is set in `vs_out_VoxelCode[0]`. If set, emit the back face vertices ($c\_vCorner011, c\_vCorner111, c\_vCorner001, c\_vCorner101$) and compute lighting with normal $(0,0,1)$ transformed by the world-view matrix [S1, unofficial].

**Pseudocode**
```python
def process_voxel(vPos, c_vCorner000, c_vCorner110, vs_out_VoxelCode, c_mWorldView, c_vInverseProjection, vViewDirection):
    # Step 1: Frustum Culling
    # Calculate w as max length of corners + vPos.w
    corner_lengths = [
        length(c_vCorner000),
        length(c_vCorner001),
        length(c_vCorner010),
        length(c_vCorner110)
    ]
    max_corner_length = max(corner_lengths)
    w = vPos.w + max_corner_length
    
    # Check if outside viewing volume
    if abs(vPos.z) > w or abs(vPos.x) > w or abs(vPos.y) > w:
        return

    # Step 2 & 3: Determine Face Orientation
    # Transform corners by inverse projection diagonal
    transformed_corners = (c_vCorner000.xyz + c_vCorner110.xyz) * c_vInverseProjection.xyz
    dot_product = dot(transformed_corners, vViewDirection)

    # Step 4: Process Front Face
    if dot_product > 0:
        # Check internal face mask bit 0x10
        if (vs_out_VoxelCode[0] & 0x10) != 0:
            # Emit front face vertices
            emit_vertex(c_vCorner000 + vPos)
            emit_vertex(c_vCorner100 + vPos)
            emit_vertex(c_vCorner010 + vPos)
            emit_vertex(c_vCorner110 + vPos)
            end_primitive()
            # Compute lighting with normal (0,0,-1) transformed by world-view
            vNormal = normalize((vec4(0, 0, -1, 0) * c_mWorldView).xyz)
            gs_color = lightning(vNormal, vViewDirection, shininess, specular, color, emissive)

    # Step 5: Process Back Face
    else:
        # Check internal face mask bit 0x20
        if (vs_out_VoxelCode[0] & 0x20) != 0:
            # Emit back face vertices
            emit_vertex(c_vCorner011 + vPos)
            emit_vertex(c_vCorner111 + vPos)
            emit_vertex(c_vCorner001 + vPos)
            emit_vertex(c_vCorner101 + vPos)
            end_primitive()
            # Compute lighting with normal (0,0,1) transformed by world-view
            vNormal = normalize((vec4(0, 0, 1, 0) * c_mWorldView).xyz)
            gs_color = lightning(vNormal, vViewDirection, shininess, specular, color, emissive)
```

**Edge Cases and Pitfalls**
*   **Internal Faces:** Shared faces between two neighboring voxels are never visible. The masking bits (`0x10` and `0x20`) are used to reject these invisible internal faces [S1, unofficial].
*   **Projection Space Limitations:** Backface culling cannot be done directly in projection space; it requires transformation to view space using the inverse projection diagonal [S1, unofficial].

## Operating characteristics
*   **Performance:** On a Geforce 640M LE, this method draws 32,368 voxels per millisecond [S1, unofficial].
*   **Complexity:** The method is efficient for static scenes as it avoids complex mesh generation. However, geometry shaders can be slow if the amount of data increases significantly [S1, unofficial].
*   **Memory:** The 32-bit integer encoding allows compact storage of position and visibility, but limits position resolution to $256^3$ without chunking [S1, unofficial].
*   **Strengths:** Simple implementation, immediate rejection of internal faces, and efficient memory management via chunking [S1, unofficial].
*   **Limitations:** Geometry shader performance bottleneck for very large datasets; limited position resolution without chunking [S1, unofficial].
