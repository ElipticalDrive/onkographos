# Voxel Backface Culling and Internal Face Masking

Also called: Internal Face Masking, Voxel Backface Culling

## Overview
Voxel Backface Culling and Internal Face Masking is a geometry shader-based optimization that rejects invisible faces in voxel rendering by determining front/back orientation in projection space and masking faces shared between neighboring voxels [S1, unofficial]. It sets itself apart from sibling methods like [Face Coverage Mask Culling](3397-face-coverage-mask-culling.md) by performing visibility checks per-voxel within the geometry shader using projection-space dot products, rather than pre-computing chunk-level masks or using ray-casting for visibility [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A voxel defined by its 8 corner positions in world space (`c_vCorner000` to `c_vCorner111`), a position offset (`vPos`), a view direction (`vViewDirection`), a world-view matrix (`c_mWorldView`), and a 32-bit voxel code (`vs_out_VoxelCode[0]`) encoding visibility masks and position.
*   **Output:** Vertices emitted for visible front or back faces, with color computed via a lighting function.

**Data Structures:**
The voxel code is a 32-bit integer encoding invisible masking and position [S1, unofficial]:
*   Bits 0-5: 6-bit mask for each side (specifically bits 4 (`0x10`) and 5 (`0x20`) are used for front/back face visibility in this implementation).
*   Bits 6-31: 3*8 bits for the position (allowing addressing of $256^3$ positions).
*   Bits 32-33: 2 unused bits.

**Steps:**
1.  **View Frustum Culling:** Calculate the maximum length of the voxel corners. If the voxel position `vPos` exceeds the frustum bounds defined by `w`, return early [S1, unofficial].
    $$ w = \max(\max(\|c_{vCorner000}\|, \|c_{vCorner001}\|), \max(\|c_{vCorner010}\|, \|c_{vCorner011}\|)) $$
    $$ \text{if } |vPos.z| > w \lor |vPos.x| > w \lor |vPos.y| > w \text{ then return} $$
2.  **Projection Space Transformation:** Transform the direction in projection space to view space using the inverse diagonal of the projection matrix [S1, unofficial]:
    $$ v_{view} = v_{proj} * (1/mProjection[0][0], 1/mProjection[1][1], 1/mProjection[2][2]) $$
    *Note: In the source implementation, `c_vInverseProjection` is used directly in the dot product.*
3.  **Backface Determination:** Calculate the dot product of the sum of two diagonal voxel corners transformed by the inverse projection diagonal and the view direction [S1, unofficial]:
    $$ D = \text{dot}((c_{vCorner000}.xyz + c_{vCorner110}.xyz) * c_{vInverseProjection}.xyz, vViewDirection) $$
4.  **Face Emission:**
    *   If $D > 0$, the front face is potentially visible. Check if bit `0x10` is set in `vs_out_VoxelCode[0]`. If set, emit vertices for the front face (`c_vCorner000`, `c_vCorner100`, `c_vCorner010`, `c_vCorner110`) with normal `(0,0,-1)` transformed by the world-view matrix [S1, unofficial].
    *   If $D \le 0$, the back face is potentially visible. Check if bit `0x20` is set in `vs_out_VoxelCode[0]`. If set, emit vertices for the back face (`c_vCorner011`, `c_vCorner111`, `c_vCorner001`, `c_vCorner101`) with normal `(0,0,1)` transformed by the world-view matrix [S1, unofficial].
5.  **Lighting:** Compute color using the lighting function with the transformed normal, view direction, and material properties [S1, unofficial].

**Pseudocode:**
```python
def process_voxel(c_vCorner000, c_vCorner001, c_vCorner010, c_vCorner011, 
                  c_vCorner100, c_vCorner101, c_vCorner110, c_vCorner111, 
                  vPos, vViewDirection, c_mWorldView, c_vInverseProjection, 
                  vs_out_VoxelCode, shininess, specular, color, emissive):
    # Step 1: Frustum Culling
    max_len = max(length(c_vCorner000), length(c_vCorner001), length(c_vCorner010), length(c_vCorner011))
    w = vPos.w + max_len
    if abs(vPos.z) > w or abs(vPos.x) > w or abs(vPos.y) > w:
        return

    # Step 2 & 3: Backface Determination
    # Sum of diagonal corners transformed by inverse projection diagonal
    corner_sum = (c_vCorner000.xyz + c_vCorner110.xyz) * c_vInverseProjection.xyz
    dot_product = dot(corner_sum, vViewDirection)

    if dot_product > 0:
        # Front Face
        # Check mask bit 0x10
        if (vs_out_VoxelCode[0] & 0x10) != 0:
            # Normal (0,0,-1) transformed by world-view matrix
            vNormal = normalize((vec4(0, 0, -1, 0) * c_mWorldView).xyz)
            gs_color = lighting(vNormal, vViewDirection, shininess, specular, color, emissive)
            
            emit_vertex(c_vCorner000 + vPos, gs_color)
            emit_vertex(c_vCorner100 + vPos, gs_color)
            emit_vertex(c_vCorner010 + vPos, gs_color)
            emit_vertex(c_vCorner110 + vPos, gs_color)
            end_primitive()
    else:
        # Back Face
        # Check mask bit 0x20
        if (vs_out_VoxelCode[0] & 0x20) != 0:
            # Normal (0,0,1) transformed by world-view matrix
            vNormal = normalize((vec4(0, 0, 1, 0) * c_mWorldView).xyz)
            gs_color = lighting(vNormal, vViewDirection, shininess, specular, color, emissive)
            
            emit_vertex(c_vCorner011 + vPos, gs_color)
            emit_vertex(c_vCorner111 + vPos, gs_color)
            emit_vertex(c_vCorner001 + vPos, gs_color)
            emit_vertex(c_vCorner101 + vPos, gs_color)
            end_primitive()
```

**Parameters:**
*   **Chunk Size:** $32^3$ voxels per chunk [S1, unofficial]. This size is chosen for efficient memory management, LOD, and large-scale culling algorithms [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Shared Faces:** Shared faces between two neighboring voxels are never visible. The masking bits (`0x10` and `0x20`) are used to reject these invisible internal faces [S1, unofficial].
*   **Projection Space Limitations:** Direct backface culling in projection space is complex; the method relies on transforming the direction to view space using the inverse projection diagonal [S1, unofficial].

## Operating characteristics
*   **Performance:** Draws 32,368 voxels per millisecond on a Geforce 640M LE [S1, unofficial].
*   **Complexity:** The method operates per-voxel in the geometry shader. The cost is dominated by the geometry shader execution and the bitwise operations for masking.
*   **Strengths:** Efficient rejection of internal faces and backfaces without pre-computing complex chunk-level visibility data. The 32-bit encoding allows compact storage of position and visibility state.
*   **Limitations:** Geometry shaders can be slow if the amount of data increases significantly. The method is specific to the projection matrix structure used (inverse diagonal multiplication).
*   **When to use:** Suitable for real-time voxel rendering where geometry shader overhead is acceptable and chunk sizes are manageable ($32^3$).

## Background
This technique was developed by Johannes Jendersie and published on his developer blog [S1, unofficial]. It was part of a series of posts on voxel rendering optimizations, including beam drawing and grid rendering. The approach builds on the general principle of neighbor occupancy checks shared by the [Face Culling and Visibility Optimization](3861-face-culling-and-visibility-optimization.md) family [S1, unofficial].
