# Voxel Backface Culling and Internal Face Masking

Also called: Internal Face Masking, Voxel Backface Culling

## Overview
Voxel Backface Culling and Internal Face Masking is a visibility optimization technique for blocky voxel meshing that rejects invisible faces by determining front/back orientation in projection space and masking faces shared between neighboring voxels [S1, unofficial]. It sets itself apart from sibling methods like [Face Coverage Mask Culling](3397-face-coverage-mask-culling.md) by performing visibility checks directly within the geometry shader using projection-space transformations and bitmask flags, rather than pre-computing coverage masks or relying solely on neighbor occupancy checks during mesh generation [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A voxel position in world space, a 32-bit integer encoding the voxel's position and face visibility masks, the current view direction, the world-view matrix, and the projection matrix.
*   **Output:** Geometry (triangles) for visible front and back faces of the voxel.

**Data Structures:**
The method uses a single 32-bit integer (`vs_out_VoxelCode[0]`) to encode both position and visibility state [S1, unofficial]. The layout is:
*   Bits 0-5 (6 bits): Mask for each of the 6 sides of the voxel cube.
*   Bits 6-30 (3 * 8 bits): Position coordinates (allowing addressing of a $256^3$ volume).
*   Bits 31-32 (2 bits): Unused.

**Parameters:**
*   **Chunk Size:** $32^3$ voxels per chunk. This size is chosen for efficient memory management, LOD support, and large-scale culling algorithms [S1, unofficial].
*   **Projection Matrix:** The diagonal elements $mProjection[0][0]$, $mProjection[1][1]$, and $mProjection[2][2]$ are used to transform projection space directions to view space.

**Steps:**
1.  **Bounding Box Check:** Calculate the maximum length of the voxel's eight corners. If the voxel position's absolute coordinates exceed this length in any axis, the voxel is outside the viewing volume and is discarded [S1, unofficial].
2.  **Transform Projection Direction:** Transform the view direction from projection space to view space using the inverse diagonal of the projection matrix:
    $$ v_{view} = v_{proj} * (1/mProjection[0][0], 1/mProjection[1][1], 1/mProjection[2][2]) $$
    [S1, unofficial]
3.  **Determine Face Orientation:** Calculate the dot product of the sum of two specific voxel corners (transformed by the inverse projection diagonal) and the view direction:
    $$ \text{dot}((c\_vCorner000.xyz + c\_vCorner110.xyz) * c\_vInverseProjection.xyz, vViewDirection) $$
    [S1, unofficial]
4.  **Process Front Face:** If the dot product is greater than 0, the front face is potentially visible. Check if the voxel code bit `0x10` is set in `vs_out_VoxelCode[0]`. If set, emit the front face vertices ($c\_vCorner000, c\_vCorner100, c\_vCorner010, c\_vCorner110$) and compute lighting with normal $(0,0,-1)$ transformed by the world-view matrix [S1, unofficial].
5.  **Process Back Face:** If the dot product is not greater than 0, the back face is potentially visible. Check if the voxel code bit `0x20` is set in `vs_out_VoxelCode[0]`. If set, emit the back face vertices ($c\_vCorner011, c\_vCorner111, c\_vCorner001, c\_vCorner101$) and compute lighting with normal $(0,0,1)$ transformed by the world-view matrix [S1, unofficial].

**Pseudocode:**
```python
def process_voxel_voxel_backface_culling(
    voxel_pos: vec4,          # World position of voxel
    voxel_code: uint32,       # 32-bit mask and position
    view_direction: vec3,     # View direction in projection space
    projection_matrix: mat4,  # Projection matrix
    world_view_matrix: mat4,  # World-view matrix
    corners: list[vec3]       # 8 corners of the voxel in local space
):
    # 1. Bounding Box Check
    max_corner_len = max(
        length(corners[0]), length(corners[1]),
        length(corners[2]), length(corners[3]),
        length(corners[4]), length(corners[5]),
        length(corners[6]), length(corners[7])
    )
    if (abs(voxel_pos.z) > max_corner_len or
        abs(voxel_pos.x) > max_corner_len or
        abs(voxel_pos.y) > max_corner_len):
        return  # Outside viewing volume

    # 2. Transform Projection Direction to View Space
    inv_proj_diag = vec3(
        1.0 / projection_matrix[0][0],
        1.0 / projection_matrix[1][1],
        1.0 / projection_matrix[2][2]
    )
    view_dir_view_space = view_direction * inv_proj_diag

    # 3. Determine Face Orientation
    # c_vCorner000 and c_vCorner110 are specific corners (e.g., min-min-min and max-max-min)
    # The sum is transformed by the inverse projection diagonal
    corner_sum = (corners[0] + corners[7]) * inv_proj_diag
    dot_product = dot(corner_sum, view_dir_view_space)

    # 4. Process Front Face
    if dot_product > 0:
        # Check bit 0x10 (bit 4)
        if (voxel_code & 0x10) != 0:
            # Emit front face vertices
            # Vertices: c_vCorner000, c_vCorner100, c_vCorner010, c_vCorner110
            # Assuming corners are indexed appropriately
            v0 = corners[0] + voxel_pos
            v1 = corners[1] + voxel_pos
            v2 = corners[2] + voxel_pos
            v3 = corners[3] + voxel_pos
            
            # Compute normal
            normal_local = vec3(0, 0, -1)
            normal_world = normalize((vec4(normal_local, 0) * world_view_matrix).xyz)
            
            # Emit geometry (simplified)
            emit_triangle(v0, v1, v2)
            emit_triangle(v0, v2, v3)
            # Lighting computation would happen here

    # 5. Process Back Face
    else:
        # Check bit 0x20 (bit 5)
        if (voxel_code & 0x20) != 0:
            # Emit back face vertices
            # Vertices: c_vCorner011, c_vCorner111, c_vCorner001, c_vCorner101
            v0 = corners[4] + voxel_pos
            v1 = corners[5] + voxel_pos
            v2 = corners[6] + voxel_pos
            v3 = corners[7] + voxel_pos
            
            # Compute normal
            normal_local = vec3(0, 0, 1)
            normal_world = normalize((vec4(normal_local, 0) * world_view_matrix).xyz)
            
            # Emit geometry (simplified)
            emit_triangle(v0, v1, v2)
            emit_triangle(v0, v2, v3)
            # Lighting computation would happen here
```

**Edge Cases and Pitfalls:**
*   **Shared Faces:** Shared faces between two neighboring voxels are never visible. The masking bits (`0x10` and `0x20`) are used to reject these invisible internal faces [S1, unofficial].
*   **Projection Space Limitations:** Backface culling cannot be done directly in projection space without the transformation trick using the inverse projection diagonal [S1, unofficial].
*   **Chunking:** For volumes larger than $256^3$, a chunked approach is necessary because the 32-bit integer only encodes positions within a $256^3$ range [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The culling check is performed once during mesh creation (geometry shader execution), resulting in no framerate loss during rendering [S1, unofficial].
*   **Memory Complexity:** Uses a single 32-bit integer per voxel for encoding position and visibility, minimizing memory overhead [S1, unofficial].
*   **Measured Performance:** Draws 32,368 voxels per millisecond on a Geforce 640M LE [S1, unofficial].
*   **Strengths:** Efficient rejection of internal and back-facing faces; minimal memory overhead; no runtime overhead for culling checks.
*   **Limitations:** Requires geometry shader support; projection space transformation trick is specific to certain projection matrix structures; chunking adds complexity for very large volumes.
*   **When to Use:** Suitable for real-time voxel rendering where geometry shader support is available and internal face visibility is a major performance bottleneck.
*   **When Not to Use:** Not suitable for hardware without geometry shader support or for volumes requiring dynamic visibility changes that cannot be pre-computed into the voxel code.

## Background
This technique was developed by Johannes Jendersie and documented on his graphic developer blog [S1, unofficial]. It was implemented in a voxel rendering engine to optimize performance by reducing the number of triangles drawn. The method addresses the complexity of drawing proper beams and grids in voxel environments, where simple line rendering is insufficient for visual quality [S1, unofficial]. The approach was tested on a Geforce 640M LE GPU [S1, unofficial].
