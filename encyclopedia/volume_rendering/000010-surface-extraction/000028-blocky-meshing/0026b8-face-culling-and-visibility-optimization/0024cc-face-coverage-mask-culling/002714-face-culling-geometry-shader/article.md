# Face-Culling Geometry Shader

Also called: Bitmask Face Generation, Cube Face Culling

## Overview
A geometry shader technique that generates cube faces from point primitives based on a bitmask, culling hidden faces to reduce overdraw and vertex processing [S1, unofficial]. It builds on [Face Coverage Mask Culling](3397-face-coverage-mask-culling.md) by using the bitmask to determine face visibility at the primitive generation stage [G].

## How it works
**Inputs and Outputs:**
*   **Input:** A single point primitive per voxel. Attributes are `vertexColour` (vec4) and `faceBitmaskA` (uint) [S1, unofficial]. The geometry shader receives these as arrays (`vertexColour[]`, `faceBitmaskB[]`), where `faceBitmaskB` is a direct copy of `faceBitmaskA` [S1, unofficial].
*   **Output:** A stream of triangle strips. The shader declares `layout (triangle_strip, max_vertices = 48) out`, allowing up to 48 vertices per input point [S1, unofficial].

**Data Structures:**
*   `faceBitmaskA`/`faceBitmaskB`: A 32-bit unsigned integer where specific bits correspond to face visibility [S1, unofficial]:
    *   Bit 0 (`0x01`): Front face (z = +0.5) [S1, unofficial].
    *   Bit 1 (`0x02`): Back face (z = -0.5) [S1, unofficial].
    *   Bit 2 (`0x04`): Left face (x = -0.5) [S1, unofficial].
    *   Bit 3 (`0x08`): Right face (x = +0.5) [S1, unofficial].
    *   Bit 4 (`0x10`): Top face (y = +0.5) [S1, unofficial].
    *   Bit 5 (`0x20`): Bottom face (y = -0.5) [S1, unofficial].
*   `vertexColour`: The color attribute passed from the vertex shader [S1, unofficial].

**Parameters:**
*   `projection`: A uniform 4×4 matrix applied to vertex positions [S1, unofficial].

**Steps:**
1.  The vertex shader passes the voxel position, color, and bitmask to the geometry shader [S1, unofficial].
2.  The geometry shader receives the point primitive and checks each bit of `faceBitmaskB` against the corresponding face constant [S1, unofficial].
3.  For each set bit, the shader emits two triangle strips forming a square face centered on the voxel's local coordinate system [S1, unofficial].
4.  Vertices are generated by offsetting the input point position by ±0.5 in the relevant axes [S1, unofficial].
5.  The projection matrix is applied to each vertex position before emission [S1, unofficial].
6.  The vertex color is set to the input color for each emitted vertex [S1, unofficial].

**Formulas:**
*   $P_{out} = M_{proj} \times (P_{in} + \Delta)$, where $P_{in}$ is the input point position, $M_{proj}$ is the projection matrix, and $\Delta$ is the face offset vector $(\pm 0.5, \pm 0.5, \pm 0.5)$ [S1, unofficial].

```python
def generate_cube_faces(position, color, mask, projection):
    """
    Generates visible cube faces from a point primitive using a bitmask.
    position: tuple (x, y, z)
    color: tuple (r, g, b, a)
    mask: int (bitmask)
    projection: 4x4 matrix (list of 4 lists, each with 4 floats)
    Returns: list of vertex tuples (projected_pos, color)
    """
    vertices = []
    # Face constants and their corresponding vertex offsets relative to position
    # Each face emits two triangle strips (6 vertices total per face)
    faces = {
        0x01: [ # Front (z=+0.5)
            (-0.5, -0.5, 0.5), (0.5, -0.5, 0.5), (0.5, 0.5, 0.5),
            (0.5, 0.5, 0.5), (-0.5, 0.5, 0.5), (-0.5, -0.5, 0.5)
        ],
        0x02: [ # Back (z=-0.5)
            (-0.5, -0.5, -0.5), (-0.5, 0.5, -0.5), (0.5, 0.5, -0.5),
            (0.5, 0.5, -0.5), (0.5, -0.5, -0.5), (-0.5, -0.5, -0.5)
        ],
        0x04: [ # Left (x=-0.5)
            (-0.5, -0.5, -0.5), (-0.5, -0.5, 0.5), (-0.5, 0.5, 0.5),
            (-0.5, 0.5, 0.5), (-0.5, 0.5, -0.5), (-0.5, -0.5, -0.5)
        ],
        0x08: [ # Right (x=+0.5)
            (0.5, -0.5, -0.5), (0.5, 0.5, -0.5), (0.5, 0.5, 0.5),
            (0.5, 0.5, 0.5), (0.5, -0.5, 0.5), (0.5, -0.5, -0.5)
        ],
        0x10: [ # Top (y=+0.5)
            (-0.5, 0.5, -0.5), (-0.5, 0.5, 0.5), (0.5, 0.5, 0.5),
            (0.5, 0.5, 0.5), (0.5, 0.5, -0.5), (-0.5, 0.5, -0.5)
        ],
        0x20: [ # Bottom (y=-0.5)
            (-0.5, -0.5, -0.5), (-0.5, -0.5, 0.5), (0.5, -0.5, 0.5),
            (0.5, -0.5, 0.5), (0.5, -0.5, -0.5), (-0.5, -0.5, -0.5)
        ]
    }
    
    for bit_mask, offsets in faces.items():
        if mask & bit_mask:
            for dx, dy, dz in offsets:
                local_pos = (position[0] + dx, position[1] + dy, position[2] + dz, 1.0)
                projected_pos = apply_projection(local_pos, projection)
                vertices.append((projected_pos, color))
    return vertices

def apply_projection(pos, proj_matrix):
    # Standard matrix-vector multiplication for projection
    x, y, z, w = pos
    return (
        proj_matrix[0][0]*x + proj_matrix[1][0]*y + proj_matrix[2][0]*z + proj_matrix[3][0]*w,
        proj_matrix[0][1]*x + proj_matrix[1][1]*y + proj_matrix[2][1]*z + proj_matrix[3][1]*w,
        proj_matrix[0][2]*x + proj_matrix[1][2]*y + proj_matrix[2][2]*z + proj_matrix[3][2]*w,
        proj_matrix[0][3]*x + proj_matrix[1][3]*y + proj_matrix[2][3]*z + proj_matrix[3][3]*w
    )
```

## Operating characteristics
*   **Time Complexity:** O(1) per voxel, proportional to the number of visible faces [S1, unofficial].
*   **Memory Complexity:** O(1) per voxel for the bitmask and color [S1, unofficial].
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Not given in the sources.
*   **Strengths:** Simple implementation, leverages GPU hardware for culling, reduces bandwidth and rasterization cost [S1, unofficial].
*   **Limitations:** Requires a geometry shader capable of handling the output; the bitmask must be pre-computed [S1, unofficial].
*   **When to use:** When reducing overdraw and vertex processing is prioritized and the bitmask is available [S1, unofficial].
*   **When not to use:** When hardware lacks geometry shader support or bitmask generation is too costly [S1, unofficial].
