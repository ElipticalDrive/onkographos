# Face-Culling Geometry Shader

Also called: Bitmask Face Generation, Cube Face Culling

## Overview
A geometry shader technique that generates cube faces from point primitives based on a bitmask, culling hidden faces to reduce overdraw and vertex processing [S1, unofficial]. It solves the problem of rendering voxel surfaces by emitting only the visible faces of a voxel, leveraging the GPU's geometry shader stage to expand point data into full cube geometry on-demand. It builds on [Face Coverage Mask Culling](3397-face-coverage-mask-culling.md) by using the bitmask to determine face visibility at the primitive generation stage.

## How it works
**Inputs and Outputs:**
*   **Input:** A single point primitive per voxel. Attributes include `vertexColour` (vec4) and `faceBitmaskA` (uint). The `faceBitmaskA` encodes which of the six faces are visible.
*   **Output:** A stream of triangle strips. The shader declares `layout (triangle_strip, max_vertices = 48) out`, allowing up to 48 vertices per input point (6 faces × 2 triangles per face × 4 vertices per triangle, though strips share vertices).

**Data Structures:**
*   `faceBitmaskA`: A 32-bit unsigned integer where specific bits correspond to face visibility.
    *   Bit 0 (`0x01u`): Front face (z = +0.5)
    *   Bit 1 (`0x02u`): Back face (z = -0.5)
    *   Bit 2 (`0x04u`): Left face (x = -0.5)
    *   Bit 3 (`0x08u`): Right face (x = +0.5)
    *   Bit 4 (`0x10u`): Top face (y = +0.5)
    *   Bit 5 (`0x20u`): Bottom face (y = -0.5)
*   `vertexColour`: The color attribute passed from the vertex shader.

**Parameters:**
*   `projection`: A uniform 4x4 matrix applied to vertex positions.
*   Face constants: `front=0x01u`, `back=0x02u`, `left=0x04u`, `right=0x08u`, `top=0x10u`, `bottom=0x20u`.

**Steps:**
1.  The vertex shader passes the voxel position, color, and bitmask to the geometry shader.
2.  The geometry shader receives the point primitive. It checks each bit of the `faceBitmaskB` (copied from `faceBitmaskA`) against the corresponding face constant.
3.  For each set bit, the shader emits two triangle strips forming a square face centered on the voxel's local coordinate system.
4.  Vertices are generated by offsetting the input point position by ±0.5 in the relevant axes.
5.  The projection matrix is applied to each vertex position before emission.
6.  The vertex color is set to the input color for each emitted vertex.

**Pseudocode:**
> **Unverified code.** The code below did not pass a test run against a reference implementation, or no test fits it, so it may contain errors.

```python
# Geometry Shader Logic
# Input: point primitive with gl_in[0].gl_Position (vec4), vertexColour[0] (vec4), faceBitmaskB[0] (uint)
# Uniform: projection (mat4)
# Output: triangle_strip, max_vertices = 48

def emit_face(position, offset_x, offset_y, offset_z, color):
    """
    Emits a vertex for a specific face.
    position: vec4, the input voxel position
    offset_x, offset_y, offset_z: float, the offset from center (-0.5 or 0.5)
    color: vec4, the vertex color
    """
    # Calculate local vertex position
    local_pos = position + vec4(offset_x, offset_y, offset_z, 0.0)
    # Apply projection
    gl_Position = projection * local_pos
    vertColour = color
    EmitVertex()

def emit_triangle_strip(position, color, offsets):
    """
    Emits two triangle strips for a face.
    offsets: list of 6 vec4 offsets defining the 6 vertices of the two strips.
             The strips share vertices to form a quad.
             Strip 1: v0, v1, v2
             Strip 2: v2, v3, v4 (v2 is shared)
             Wait, standard quad is 2 triangles. 
             Strip 1: v0, v1, v2
             Strip 2: v2, v3, v4? No, a quad is 4 vertices.
             Two strips for a quad:
             Strip 1: v0, v1, v2
             Strip 2: v2, v3, v0? No.
             Let's look at the source code.
             Front face:
             v0: (-0.5, -0.5, 0.5)
             v1: (0.5, -0.5, 0.5)
             v2: (0.5, 0.5, 0.5)
             EndPrimitive
             v2: (0.5, 0.5, 0.5)
             v3: (-0.5, 0.5, 0.5)
             v4: (-0.5, -0.5, 0.5)
             EndPrimitive
             This forms two triangles: (v0,v1,v2) and (v2,v3,v4).
             Note: v4 is same as v0.
    """
    emit_face(position, offsets[0].x, offsets[0].y, offsets[0].z, color)
    emit_face(position, offsets[1].x, offsets[1].y, offsets[1].z, color)
    emit_face(position, offsets[2].x, offsets[2].y, offsets[2].z, color)
    EndPrimitive()
    
    emit_face(position, offsets[2].x, offsets[2].y, offsets[2].z, color)
    emit_face(position, offsets[3].x, offsets[3].y, offsets[3].z, color)
    emit_face(position, offsets[4].x, offsets[4].y, offsets[4].z, color)
    EndPrimitive()

def main():
    pos = gl_in[0].gl_Position
    color = vertexColour[0]
    mask = faceBitmaskB[0]
    
    # Front Face (z = +0.5)
    if (mask & 0x01u) != 0u:
        emit_triangle_strip(pos, color, [
            vec4(-0.5, -0.5, 0.5, 0.0),
            vec4(0.5, -0.5, 0.5, 0.0),
            vec4(0.5, 0.5, 0.5, 0.0),
            vec4(-0.5, 0.5, 0.5, 0.0),
            vec4(-0.5, -0.5, 0.5, 0.0) # Repeats first vertex for strip continuity
        ])

    # Back Face (z = -0.5)
    if (mask & 0x02u) != 0u:
        emit_triangle_strip(pos, color, [
            vec4(-0.5, -0.5, -0.5, 0.0),
            vec4(-0.5, 0.5, -0.5, 0.0),
            vec4(0.5, 0.5, -0.5, 0.0),
            vec4(0.5, -0.5, -0.5, 0.0),
            vec4(-0.5, -0.5, -0.5, 0.0)
        ])

    # Left Face (x = -0.5)
    if (mask & 0x04u) != 0u:
        emit_triangle_strip(pos, color, [
            vec4(-0.5, -0.5, -0.5, 0.0),
            vec4(-0.5, -0.5, 0.5, 0.0),
            vec4(-0.5, 0.5, 0.5, 0.0),
            vec4(-0.5, 0.5, -0.5, 0.0),
            vec4(-0.5, -0.5, -0.5, 0.0)
        ])

    # Right Face (x = +0.5)
    if (mask & 0x08u) != 0u:
        emit_triangle_strip(pos, color, [
            vec4(0.5, -0.5, -0.5, 0.0),
            vec4(0.5, 0.5, -0.5, 0.0),
            vec4(0.5, 0.5, 0.5, 0.0),
            vec4(0.5, -0.5, 0.5, 0.0),
            vec4(0.5, -0.5, -0.5, 0.0)
        ])

    # Top Face (y = +0.5)
    if (mask & 0x10u) != 0u:
        emit_triangle_strip(pos, color, [
            vec4(-0.5, 0.5, -0.5, 0.0),
            vec4(-0.5, 0.5, 0.5, 0.0),
            vec4(0.5, 0.5, 0.5, 0.0),
            vec4(0.5, 0.5, -0.5, 0.0),
            vec4(-0.5, 0.5, -0.5, 0.0)
        ])

    # Bottom Face (y = -0.5)
    if (mask & 0x20u) != 0u:
        emit_triangle_strip(pos, color, [
            vec4(-0.5, -0.5, -0.5, 0.0),
            vec4(-0.5, -0.5, 0.5, 0.0),
            vec4(0.5, -0.5, 0.5, 0.0),
            vec4(0.5, -0.5, -0.5, 0.0),
            vec4(-0.5, -0.5, -0.5, 0.0)
        ])
```

**Edge Cases and Pitfalls:**
*   **Bitmask Accuracy:** The bitmask must be correctly computed in the preceding stage. If a face is occluded but the bit is set, unnecessary geometry is generated. If a face is visible but the bit is unset, it will be missing.
*   **Projection Order:** The projection matrix must be applied to the final vertex position (after local offset) to ensure correct depth buffering and clipping.
*   **Vertex Shader Dependency:** The vertex shader must pass the `faceBitmaskA` and `vertexColour` correctly. The geometry shader expects these as arrays (`vertexColour[]`, `faceBitmaskB[]`) because it is a geometry shader.

## Operating characteristics
*   **Time Complexity:** O(1) per voxel, proportional to the number of visible faces. Each visible face requires emitting 6 vertices (2 triangle strips).
*   **Memory Complexity:** O(1) per voxel for the bitmask and color. The output buffer size depends on the number of visible faces.
*   **Performance:** Reduces overdraw and vertex processing by only generating visible faces. The use of `triangle_strip` reduces the vertex count per face compared to `triangle_list` (6 vertices per face vs 12 if not using strips, but here it's 6 vertices per face due to strip sharing and the specific strip structure).
*   **Strengths:** Simple implementation, leverages GPU hardware for culling, reduces bandwidth and rasterization cost.
*   **Limitations:** Requires a geometry shader capable of handling the output. The bitmask must be pre-computed. Not suitable for non-cube shapes without modification.

## Background
This method is derived from voxel game rendering techniques, specifically those used in the `voxel-game` repository by Vizaxo [S1, unofficial]. It represents a practical application of bitmask-based face culling within the geometry shader pipeline, optimizing the rendering of voxel-based environments.
