# Face Coverage Mask Culling

Also called: Bitmask Culling, Culling Limitations, Partial Shape Culling

## Overview
Face Coverage Mask Culling is a method for optimizing blocky mesh generation by determining face visibility based on partial geometric coverage rather than binary solidity. It solves the problem where standard neighbor-based culling fails for partial shapes (such as stairs, slabs, or leaves), which have mixed visible and hidden areas on a single face boundary. Unlike sibling methods that treat faces as fully solid or fully empty, this method uses precomputed bitmasks to represent the occupancy of a face's sub-regions, allowing for more accurate culling of occluded geometry while maintaining high performance through bitwise operations [S2, unofficial]. It is distinct from [Mask Projection Culling](6836-mask-projection-culling.md) because it operates in local block space using precomputed static masks rather than runtime camera projections, and from [Opacity-based Mesh Culling](8759-opacity-based-mesh-culling.md) because it handles geometric coverage independently of material transparency, though it can be combined with it [S2, unofficial].

## How it works
The method determines whether a face on a voxel block should be rendered by comparing the geometric coverage of the current block's face against the opposite face of its neighbor. If the neighbor completely covers the visible regions of the current face, the face is culled.

### Inputs and Outputs
*   **Inputs**:
    *   Current block state: shape ID, rotation, and position.
    *   Neighbor block state: shape ID, rotation, and position (if present).
    *   Precomputed occlusion data: A lookup table mapping `(shape_id, rotation, face)` to a `FaceMask`.
*   **Outputs**:
    *   A boolean indicating if the face is fully occluded.
    *   If not fully occluded, the face geometry is generated (either the full face or a subdivided subset, depending on implementation choice).

### Data Structures
The core data structure is a bitmask representing the occupancy of a face.

**FaceMask**
A 16-bit unsigned integer representing a 4x4 grid of cells on a face boundary. Each bit corresponds to one cell in the grid.
*   `u16`: The underlying integer value.
*   `FULL`: A constant `FaceMask` with value `0xffff` (all 16 bits set), representing a fully opaque/solid face.
*   `EMPTY`: A constant `FaceMask` with value `0x0000` (all 16 bits unset), representing a fully empty/air face.

**Occlusion Lookup Table**
A multi-dimensional array or hash map storing the precomputed masks for every shape in the engine's vocabulary.
*   Structure: `occlusion[shape_id][rotation][face]`
*   `shape_id`: Identifier for the block shape (e.g., cube, stair, slab).
*   `rotation`: The orientation of the shape (e.g., 0-7 for Minecraft-style rotations).
*   `face`: The face normal direction (e.g., +X, -X, +Y, -Y, +Z, -Z).
*   Value: `FaceMask`.

### Steps
1.  **Retrieve Masks**: For the current block face and its neighbor's opposite face, retrieve the corresponding `FaceMask` from the precomputed occlusion lookup table.
    *   `current_mask = shape.occlusion[rotation][face]`
    *   `neighbor_mask = neighbor_shape.occlusion[neighbor_rotation][opposite(face)]`
2.  **Calculate Visibility**: Determine if the current face is fully occluded by the neighbor. A face is fully occluded if the neighbor's mask covers all bits that are set in the current mask.
    *   Formula: `visible_region = current_mask & !neighbor_mask`
    *   Condition: If `visible_region == 0`, the face is fully occluded.
3.  **Cull or Render**:
    *   If fully occluded, discard the face geometry.
    *   If not fully occluded, generate the face geometry. The implementer must choose between:
        *   Rendering the entire face geometry (accepting overdraw for hidden parts).
        *   Subdividing the geometry to only render the uncovered regions (reducing geometry but increasing mesher complexity).

### Pseudocode
```python
# Data structures
struct FaceMask:
    bits: u16

const FULL: FaceMask = FaceMask(0xFFFF)
const EMPTY: FaceMask = FaceMask(0x0000)

# Precomputed lookup table
# occlusion[shape_id][rotation][face] -> FaceMask
# face is an enum: POS_X, NEG_X, POS_Y, NEG_Y, POS_Z, NEG_Z
# opposite(face) returns the face with the inverted normal
occlusion_table: dict[int, dict[int, dict[Face, FaceMask]]]

def get_face_mask(shape_id: int, rotation: int, face: Face) -> FaceMask:
    return occlusion_table[shape_id][rotation][face]

def opposite(face: Face) -> Face:
    # Returns the face with the opposite normal
    # e.g., POS_X -> NEG_X, POS_Y -> NEG_Y, etc.
    pass

def is_fully_occluded(current_mask: FaceMask, neighbor_mask: FaceMask) -> bool:
    # A face is fully occluded if the neighbor covers all visible bits of the current face
    # visible = current & !neighbor
    # if visible == 0, then fully occluded
    return (current_mask.bits & ~neighbor_mask.bits) == 0

def cull_face(current_block: Block, neighbor_block: Block, face: Face) -> bool:
    """
    Returns True if the face should be culled, False if it should be rendered.
    """
    # 1. Retrieve masks
    current_mask = get_face_mask(current_block.shape_id, current_block.rotation, face)
    
    # Handle missing neighbor: treat as empty space (no occlusion)
    if neighbor_block is None:
        return False
    
    neighbor_face = opposite(face)
    neighbor_mask = get_face_mask(neighbor_block.shape_id, neighbor_block.rotation, neighbor_face)
    
    # 2. Check occlusion
    if is_fully_occluded(current_mask, neighbor_mask):
        return True
    
    # 3. Not fully occluded
    return False
```

### Parameters
*   **Grid Resolution**: The bitmask resolution (e.g., 4x4) depends on the complexity of the shapes in the engine. A 4x4 grid (16 bits) is sufficient for common shapes like stairs and slabs but may be insufficient for highly detailed custom models [S2, unofficial].
*   **OcclusionMode**: For transparent materials, an additional parameter `OcclusionMode` (opaque, cutout, translucent, never-occluding) may be stored alongside the `FaceMask` to separate geometric coverage from material occlusion behavior [S2, unofficial].

### Edge Cases and Pitfalls
*   **Partial Occlusion**: If a face is only partially occluded, the method does not automatically subdivide the geometry. The engine must either render the full face (causing overdraw) or implement complex geometry subdivision [S1][S2, unofficial].
*   **Transparency Artifacts**: Because culling is based on geometric coverage rather than material transparency, transparent blocks (e.g., glass) may incorrectly cull faces that should be visible, or leave hidden geometry visible. This is a fundamental limitation of the bitmask approach when combined with transparency [S1].
*   **Missing Neighbors**: If a neighbor chunk is not loaded, the engine must define a policy (e.g., treat as air, delay meshing, or use an unknown state) to avoid incorrect culling decisions [S2, unofficial].
*   **Internal Geometry**: Only geometry on the voxel cell boundary planes should be tested against neighbors. Internal triangles within a complex block should not participate in neighbor-based culling [S2, unofficial].

## Subtopics

### [Face-Culling Geometry Shader](3928-face-culling-geometry-shader.md)
A geometry shader technique that generates cube faces from point primitives based on a bitmask, culling hidden faces to reduce overdraw and vertex processing. It builds on Face Coverage Mask Culling by using the bitmask to determine face visibility at the primitive generation stage. This shifts the culling logic from the CPU meshing phase to the GPU geometry shader, allowing for dynamic face generation based on the precomputed masks.

### [Per-face Column-based Face Culling with Opacity Masks](4821-per-face-column-based-face-culling-with-opacity-masks.md)
A face culling technique that uses per-face column arrays and opaque column arrays to determine visibility based on solid and transparent block transitions. It extends Face Coverage Mask Culling by distinguishing between opaque and transparent surface contributions on partial shapes. This allows for full per-face control over opacity, addressing the transparency limitations of the basic bitmask approach by integrating material occlusion behavior into the culling decision.

### [Boundary Geometry Classification](5435-boundary-geometry-classification.md)
Boundary Geometry Classification is a method used in blocky meshing to distinguish geometry located on the voxel cell boundary planes from geometry located in the interior of a complex block. It solves the problem where neighbor-based face culling must be restricted to external surfaces to avoid incorrectly culling internal geometry. It provides the geometric predicate to determine which faces are eligible for neighbor occlusion tests, ensuring that only boundary faces are processed by the Face Coverage Mask Culling algorithm.

## Operating characteristics
*   **Time Complexity**: $O(1)$ per face, assuming constant-time lookup in the precomputed occlusion table and constant-time bitwise operations. The cost is dominated by the number of voxel faces, not the complexity of the shapes.
*   **Memory Complexity**: $O(N \times R \times F)$, where $N$ is the number of unique shapes, $R$ is the number of rotations, and $F$ is the number of faces (6). The masks are small (16-32 bits), so memory overhead is minimal.
*   **Measured Performance**: The method is extremely fast because it replaces complex geometric intersection tests with simple bitwise AND and NOT operations. Precomputing masks for all rotations eliminates runtime rotation calculations [S1].
*   **Strengths**:
    *   High performance due to bitwise operations and precomputed data.
    *   Accurate culling for partial shapes (stairs, slabs) compared to binary solid/empty flags.
    *   Simple implementation logic.
*   **Limitations**:
    *   Does not handle partial face culling automatically; requires either overdraw or complex geometry subdivision.
    *   Transparency handling is problematic; geometric coverage does not always align with material opacity.
    *   Requires precomputing masks for all shape rotations, which increases build time but reduces runtime cost.
*   **When to Use**: Ideal for voxel engines with a limited set of block shapes (e.g., Minecraft-like) where performance is critical and transparency is either absent or handled separately.
*   **When Not to Use**: Not suitable for engines requiring high-fidelity partial face culling without overdraw, or for scenes with complex, dynamic transparency where geometric coverage does not match material occlusion.

## Background
Face Coverage Mask Culling originated in the development of voxel-based games and terrain engines, particularly those inspired by Minecraft. The limitations of simple neighbor culling (where sides are either fully culled or not) became apparent with the introduction of partial shapes like stairs and slabs. The method was formalized in documentation for voxel tools and community blogs discussing blocky meshing optimizations. It represents a pragmatic compromise between the accuracy of CSG (Constructive Solid Geometry) and the performance of simple boolean culling, leveraging the discrete nature of voxel grids to precompute visibility data [S1][S2, unofficial].
