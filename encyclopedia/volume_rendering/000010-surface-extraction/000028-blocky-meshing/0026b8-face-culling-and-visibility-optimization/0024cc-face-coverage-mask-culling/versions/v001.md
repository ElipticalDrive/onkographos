# Face Coverage Mask Culling

Also called: Bitmask Culling, Partial Shape Culling

## Overview
Face Coverage Mask Culling solves the visibility problem for partial voxel shapes (such as stairs, slabs, or slopes) where a simple boolean "solid/empty" flag is insufficient because a single face may contain both visible geometry and empty space [S1, unofficial]. It represents face coverage as a bit mask, allowing the mesher to determine if a neighbor completely occludes the visible portions of a current block's face, thereby removing hidden geometry that a binary approach would either incorrectly keep or incorrectly remove [S1, unofficial]. It distinguishes itself from siblings like [Voxel Block Placement with Face Culling](923-voxel-block-placement-with-face-culling.md) by operating on fine-grained coverage bits rather than coarse block-level flags, and from [Block Visibility Culling](5334-block-visibility-culling.md) by optimizing individual face geometry rather than entire blocks.

## How it works
**Inputs and Outputs:**
*   **Input:** The current block's shape and rotation, the neighbor block's shape and rotation, and the face index being processed.
*   **Output:** A boolean indicating if the face should be culled (removed from the mesh), or the visible coverage mask if partial visibility requires geometry generation.

**Data Structures:**
*   `FaceMask`: A struct wrapping a `u16` (unsigned 16-bit integer). It represents a 4x4 grid of cells on a face boundary. Each bit corresponds to one cell in the grid [S1, unofficial].
    *   `FULL`: A constant `FaceMask` with value `0xffff` (all 16 bits set), representing a fully opaque face [S1, unofficial].
    *   `EMPTY`: A constant `FaceMask` with value `0x0000` (all 16 bits unset), representing a fully empty face [S1, unofficial].
*   `shape.occlusion`: A lookup table mapping `rotation` and `face` indices to a `FaceMask`. This precomputed table describes which parts of each boundary face are covered by geometry for a given shape orientation [S1, unofficial].
*   `FaceOcclusion` (Optional, for transparency): A struct containing `coverage: FaceMask` and `mode: OcclusionMode`. `OcclusionMode` is an enum expressing behavior such as opaque, cutout, translucent, or never-occluding [S1, unofficial].

**Steps:**
1.  **Retrieve Masks:** Access the occlusion mask for the current block's face and the neighbor's opposite face.
    *   `current_mask = shape.occlusion[rotation][face]`
    *   `neighbor_mask = neighbor_shape.occlusion[neighbor_rotation][opposite(face)]`
    *   Note: `opposite(face)` returns the face index on the neighbor that shares the boundary with the current face [S1, unofficial].
2.  **Check Occlusion:** Determine if the current face is fully occluded by the neighbor.
    *   Calculate `visible_bits = current_mask.0 & !neighbor_mask.0`.
    *   If `visible_bits == 0`, the face is fully occluded and can be removed [S1, unofficial].
    *   Conceptually: `visible = current coverage - neighbor coverage`. If visible is empty, the face is removed [S1, unofficial].
3.  **Handle Partial Visibility:** If `visible_bits != 0`, the face is partially visible. The implementer must choose between:
    *   Keeping the original face geometry (accepting overdraw from hidden parts).
    *   Generating or subdividing geometry to only expose the uncovered region (reducing geometry but increasing mesher complexity) [S1, unofficial].
4.  **Boundary Classification (Optional):** Ensure culling only applies to geometry on the voxel cell boundary planes. Classify a polygon as a boundary polygon by checking if all its vertices lie on the same cell boundary plane within a small tolerance `eps` [S1, unofficial].
5.  **Transparency Handling (Optional):** If materials have transparency, combine geometric coverage with material occlusion behavior. Do not bake all concepts into one solid flag [S1, unofficial].

**Pseudocode:**
```python
# Data structures
struct FaceMask(u16):
    pass

const FULL: FaceMask = FaceMask(0xffff)
const EMPTY: FaceMask = FaceMask(0x0000)

struct FaceOcclusion:
    coverage: FaceMask
    mode: OcclusionMode # opaque, cutout, translucent, never-occluding

# Helper to check if vertices lie on a boundary plane
fn lies_on_boundary(vertices: list[Vec3], axis: usize, plane: f32, eps: f32) -> bool:
    for v in vertices:
        if abs(v[axis] - plane) > eps:
            return false
    return true

# Main culling logic
fn cull_face(shape: Shape, rotation: Rotation, face: FaceIndex, 
             neighbor: Shape, neighbor_rotation: Rotation, neighbor_face: FaceIndex) -> bool:
    # 1. Retrieve masks
    current_mask = shape.occlusion[rotation][face]
    neighbor_mask = neighbor.occlusion[neighbor_rotation][neighbor_face]
    
    # 2. Check occlusion
    # visible = current coverage - neighbor coverage
    # If visible is empty, the face is removed
    visible_bits = current_mask.0 & ~neighbor_mask.0
    
    if visible_bits == 0:
        return true # Fully occluded, cull face
    
    # 3. Handle partial visibility
    # If only part remains, choose between keeping original geometry or subdividing
    # For this implementation, we assume keeping original geometry (overdraw)
    # or returning the visible mask for further processing
    return false # Not fully occluded

# Boundary classification helper
fn is_boundary_polygon(vertices: list[Vec3], axis: usize, plane: f32, eps: f32) -> bool:
    return lies_on_boundary(vertices, axis, plane, eps)
```

**Parameters:**
*   `FULL`: `0xffff` [S1, unofficial].
*   `EMPTY`: `0x0000` [S1, unofficial].
*   `eps`: A small tolerance value for boundary classification [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Partial Visibility:** If only part of the face remains visible, the implementer must choose between keeping the original face geometry (accepting overdraw) or generating/subdividing geometry to only expose the uncovered region (reducing geometry but increasing mesher complexity) [S1, unofficial].
*   **Chunk Borders:** Faces on the edge of a chunk still have a normal voxel neighbor. The only difference is where that neighbor is retrieved from. If a neighbor chunk is not available, the engine must define a policy (e.g., treat as air, delay meshing, or use an unknown state) [S1, unofficial].
*   **Transparency:** Geometry coverage and render opacity are related but not identical. Two adjacent glass blocks may geometrically cover each other, but whether their shared face should be removed depends on material/rendering semantics. Do not bake all three concepts (coverage, material occlusion, block/material compatibility) into one vague solid flag [S1, unofficial].

## Subtopics

### [Face-Culling Geometry Shader](3928-face-culling-geometry-shader.md)
A geometry shader technique that generates cube faces from point primitives based on a bitmask, culling hidden faces to reduce overdraw and vertex processing [3928-face-culling-geometry-shader.md]. It sets itself apart by performing culling in the GPU pipeline rather than during CPU-side mesh generation, and is chosen when minimizing vertex processing overhead is critical.

### [Per-face Column-based Face Culling with Opacity Masks](4821-per-face-column-based-face-culling-with-opacity-masks.md)
A face culling technique that uses per-face column arrays and opaque column arrays to determine visibility based on solid and transparent block transitions, allowing full per-face control over opacity [4821-per-face-column-based-face-culling-with-opacity-masks.md]. It differs by supporting granular opacity control per column rather than binary face masks, and is chosen when complex transparency effects are required.

### Boundary Geometry Classification
A method to ensure neighbor-based culling only applies to geometry on the voxel cell boundary planes, allowing internal geometry of complex blocks to remain untouched [S1, unofficial]. It classifies a polygon as a boundary polygon by checking if all its vertices lie on the same cell boundary plane within a small tolerance `eps` [S1, unofficial].

### Transparent Material Culling
A method to handle culling for transparent or cutout materials by separating geometric coverage from material occlusion behavior [S1, unofficial]. It uses a `FaceOcclusion` struct containing `coverage: FaceMask` and `mode: OcclusionMode` to express behavior such as opaque, cutout, translucent, or never-occluding [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The core culling operation is O(1) per face, involving a single bitwise AND and NOT operation [S1, unofficial]. Precomputing masks for every allowed orientation makes the hot meshing loop perform only table lookups and bit operations [S1, unofficial].
*   **Memory Complexity:** O(1) per face for the mask storage. The `occlusion` table size depends on the number of shapes and orientations, but is typically small [S1, unofficial].
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Scales well with the number of faces due to the cheap bitwise operations. However, a more sophisticated culling scheme can save mesh geometry while simultaneously making mesh generation slower if geometry subdivision is used [S1, unofficial].
*   **Strengths:** Handles partial shapes correctly, reduces overdraw for fully occluded faces, integrates well with precomputed masks.
*   **Limitations:** Partial visibility requires either overdraw or complex geometry generation. Transparency handling adds complexity.
*   **When to use:** When rendering voxel worlds with partial shapes (stairs, slabs) where binary culling is insufficient.
*   **When not to use:** When simplicity is paramount and overdraw is acceptable, or when transparency requires more complex per-pixel handling.

## Background
Face Coverage Mask Culling was introduced in the context of optimizing voxel meshing for partial shapes. It addresses the limitation of boolean solid flags by using bitmasks to represent face coverage [S1, unofficial]. The method is described in an unofficial blog post by ogyrecdev [S1, unofficial].
