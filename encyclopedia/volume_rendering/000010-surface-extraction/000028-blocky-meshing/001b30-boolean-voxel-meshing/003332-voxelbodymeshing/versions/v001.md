# VoxelBodyMeshing

Also called: Voxel Body Mesh Building

## Overview
VoxelBodyMeshing is a blocky surface extraction method that converts a boolean voxel occupancy grid into a triangular mesh by processing sub-chunks of a `VoxelBody`. It builds on [Boolean Voxel Meshing](971-boolean-voxel-meshing.md) by handling the meshing of individual chunks in a multi-threaded worker loop, supporting both hard-edged (face-merging) and smooth (Marching Cubes) modes. It is distinct from sibling methods by its specific integration with the `VoxelEngine` architecture, using a thread-local `MeshGrid` and `MeshBuilder` to output `ChunkMeshData` parts that are transformed into body-local coordinates to allow shared model matrices.

## How it works
**Inputs and outputs:**
- **Input:** A `VoxelBody` instance providing voxel data via `body.Get(x, y, z)`, `body.Refinements` (tuples of index and field), and `body.ColorOrigin`. A chunk origin `(originX, originY, originZ)` and a chunk `size` (typically `VoxelBody.ChunkSize`). A boolean `smooth` flag.
- **Output:** An array of `ChunkMeshData` objects, one per generated chunk, containing vertices and indices. Vertices are in body voxel coordinates (local to the body, not the world).

**Data structures:**
- `MeshGrid`: A 2D grid representation of the chunk. Created with dimensions `size` x `size` and depth 1. It uses a byte array `blocks` of size `MeshGrid.LengthFor(size, size)`.
- `MeshBuilder`: A helper object passed to the mesher.
- `ChunkMeshData`: The resulting mesh data for a chunk.
- `Entry`: Contains `Parts` (array of nullable `GpuMesh` arrays, one per chunk index), `Pending` (a `Task` returning an array of tuples `(int Chunk, ChunkMeshData[] Data)`), and `PendingSmooth` (bool indicating terrain mode).

**Numbered steps:**
1. **Initialize Grid:** If the thread-static byte array `_grid` is null, initialize it with size `MeshGrid.LengthFor(size, size)`. Create a `MeshGrid` instance using the `blocks` array, dimensions `size` x `size`, and depth 1. [S1, unofficial]
2. **Populate Grid:** Iterate `x`, `y`, `z` from `-1` to `size` (inclusive). For each coordinate, set `blocks[grid.Index(x, y, z)]` to the voxel value from `body.Get(originX + x, originY + y, originZ + z)` cast to `byte`. This covers the sub-chunk and a one-voxel rim for boundary detection. [S1, unofficial]
3. **Initialize Refinements:** If the static thread-local dictionary `_refinements` is null, initialize and clear it. Iterate over `body.Refinements` tuples `(index, field)`. Convert the index to local coordinates `(x, y, z)` by subtracting the origin. If within bounds `[-1, size]`, store the field in `refinements` keyed by `grid.Index(x, y, z)`. [S1, unofficial]
4. **Retrieve Colors:** Get `colorX`, `colorY`, `colorZ` from `body.ColorOrigin`. [S1, unofficial]
5. **Build Mesh:** Call either `SmoothChunkMesher.Build` or `ChunkMesher.Build` depending on the `smooth` flag. Pass the `builder`, `grid`, `refinements`, `colorX`, `colorY`, `colorZ`, and `size`. If not smooth, pass `directionalShade: false`. [S1, unofficial]
6. **Transform Vertices:** For all vertices in all returned `ChunkMeshData` parts, add `originX`, `originY`, and `originZ` to their respective X, Y, and Z components. [S1, unofficial]

**Pseudocode:**
```python
# Thread-local storage
_grid: Optional[byte_array] = None
_refinements: Optional[dict] = None

def VoxelBodyMeshing(body: VoxelBody, originX: int, originY: int, originZ: int, size: int, smooth: bool) -> List[ChunkMeshData]:
    # Step 1: Initialize Grid
    global _grid
    if _grid is None:
        _grid = byte_array(size * size) # MeshGrid.LengthFor(size, size)
    
    blocks = _grid
    grid = MeshGrid(blocks, size, size, depth=1)
    
    # Step 2: Populate Grid
    for x in range(-1, size + 1):
        for y in range(-1, size + 1):
            for z in range(-1, size + 1):
                voxel_val = body.Get(originX + x, originY + y, originZ + z)
                blocks[grid.Index(x, y, z)] = byte(voxel_val)
                
    # Step 3: Initialize Refinements
    global _refinements
    if _refinements is None:
        _refinements = dict()
        _refinements.clear()
        
    for index, field in body.Refinements:
        local_x = index.x - originX
        local_y = index.y - originY
        local_z = index.z - originZ
        if -1 <= local_x <= size and -1 <= local_y <= size and -1 <= local_z <= size:
            _refinements[grid.Index(local_x, local_y, local_z)] = field
            
    # Step 4: Retrieve Colors
    colorX, colorY, colorZ = body.ColorOrigin
    
    # Step 5: Build Mesh
    builder = MeshBuilder()
    if smooth:
        # SmoothChunkMesher.Build uses Marching Cubes
        mesh_data_list = SmoothChunkMesher.Build(builder, grid, _refinements, colorX, colorY, colorZ, size)
    else:
        # ChunkMesher.Build uses hard-edged face merging
        mesh_data_list = ChunkMesher.Build(builder, grid, _refinements, colorX, colorY, colorZ, size, directionalShade=False)
        
    # Step 6: Transform Vertices
    for mesh_data in mesh_data_list:
        for vertex in mesh_data.vertices:
            vertex.x += originX
            vertex.y += originY
            vertex.z += originZ
            
    return mesh_data_list
```

**Parameters:**
- `size`: The dimension of the sub-chunk. Typically `VoxelBody.ChunkSize`. [S1, unofficial]
- `smooth`: Boolean flag. If true, uses smooth mode (Marching Cubes); if false, uses hard-edged mode (face merging). [S1, unofficial]

**Edge cases and pitfalls:**
- **Vertex Coordinates:** Vertices are output in body voxel coordinates. This allows every sub-chunk of a body to be drawn with the same model matrix, avoiding per-chunk transformation overhead. [S1, unofficial]
- **Shading:** No directional shade is baked into the mesh colors. On a sphere, baked 'top is bright' shading would conflict with dynamic sunlight computed by the shader. World shading is applied via shader using the world normal if `VoxelBody.WorldShade` is true. [S1, unofficial]
- **Face Merging:** Hard-edged mode merges equal faces into rectangles to reduce vertex count. Without merging, a planet hundreds of voxels across would have millions of vertices. [S1, unofficial]

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of voxels in the chunk and its rim. The rim iteration is $O(size^3)$ for a 3D chunk, but the grid is 2D with depth 1, so the grid population is $O(size^2)$. The refinement iteration depends on the number of refinements. The meshing step is $O(size^2)$ for hard-edged and $O(size^3)$ for Marching Cubes.
- **Memory Complexity:** $O(size^2)$ for the grid and refinements. The output mesh size depends on the surface area.
- **Strengths:** Efficient for large bodies due to chunking and shared model matrices. Hard-edged mode significantly reduces vertex count.
- **Limitations:** Hard-edged mode may not be suitable for smooth surfaces. Smooth mode uses Marching Cubes, which is more computationally expensive.
- **When to use:** When rendering large voxel bodies where performance is critical and the visual style allows for blocky or smooth surfaces.
- **When not to use:** When per-vertex shading is required without shader support, or when the surface requires high-frequency detail not captured by the chunk size.

## Background
VoxelBodyMeshing is part of the `VoxelEngine` architecture, specifically in the `VoxelEngine.Core` namespace. It is used in the `VoxelTerraformer` project. The method is designed to work with the `GameHost` and `Game` classes, which manage the window, loop, and menus. The meshing is performed in a worker thread loop, iterating over dirty chunks.
