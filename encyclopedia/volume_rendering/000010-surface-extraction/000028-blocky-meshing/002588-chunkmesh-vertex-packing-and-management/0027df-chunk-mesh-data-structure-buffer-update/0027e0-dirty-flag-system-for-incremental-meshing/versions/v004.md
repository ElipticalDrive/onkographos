# Dirty Flag System for Incremental Meshing

Also called: Chunked Incremental Re-meshing, Dirty Chunk System, Display List/VBO Update Strategy, Lazy Rebuild

## Overview
The Dirty Flag System is an optimization technique for blocky meshing that avoids redundant surface extraction by tracking which chunks of a voxel world have changed geometry since the last mesh pass [S1, S3, unofficial]. Instead of rebuilding vertex buffers for every chunk every frame or upon every view change, the system marks only chunks containing modified density values as "dirty" and rebuilds them incrementally [S2, S3, unofficial]. This sets it apart from naive approaches that rebuild all geometry or those that trigger rebuilds based on camera movement, which negates the performance benefits of static geometry caching [S2, unofficial].

## How it works
The method manages a grid of chunks, where each chunk maintains a state indicating whether its mesh needs regeneration. The core logic involves marking chunks as dirty when voxel data changes and processing only those dirty chunks during the meshing phase.

### Inputs and Outputs
- **Input**: A voxel world represented as a 3D grid of density values. A list or set of modified voxel coordinates (or ranges).
- **Output**: Updated GPU vertex buffers (or display lists) for only the dirty chunks.

### Data Structures
1.  **Chunk Grid**: A 3D array or map of `Chunk` objects. Each `Chunk` contains:
    -   `dirty`: A boolean flag indicating if the chunk's geometry has changed since the last mesh pass [S1, unofficial].
    -   `meshData`: Temporary storage for vertex and index data during generation [S1, unofficial].
    -   `vertexBuffer`: The GPU resource holding the final mesh geometry [S1, unofficial].
2.  **Dirty Chunks Set**: A collection (e.g., `HashSet` or `List`) storing the indices of chunks that require rebuilding [S3, unofficial].

### Numbered Steps

1.  **Initialization**:
    -   Allocate the chunk grid. Ensure map dimensions are divisible by the chunk size [S1, unofficial].
    -   Initialize all chunk `dirty` flags to `true` (or rebuild all initially) [G].

2.  **Marking Dirty Chunks (On Voxel Modification)**:
    -   When a voxel at global coordinates $(x, y, z)$ is modified, determine the affected chunk indices.
    -   Because a voxel at index $x$ affects the cell to its left ($x-1$), the minimum chunk index must account for this boundary effect [S3, unofficial].
    -   Calculate the range of affected chunk indices:
        $$ c_{minX} = \lfloor (x_{min} - 1) / \text{chunkSize} \rfloor $$
        $$ c_{maxX} = \lfloor x_{max} / \text{chunkSize} \rfloor $$
        (Similarly for $Y$ and $Z$) [S3, unofficial].
    -   Iterate through all chunk indices $(c_x, c_y, c_z)$ from $(c_{minX}, c_{minY}, c_{minZ})$ to $(c_{maxX}, c_{maxY}, c_{maxZ})$.
    -   For each chunk, set `chunk.dirty = true` and add it to the `dirtyChunks` set [S3, unofficial].
    -   *Note*: If a block on a chunk's outer boundary is modified, neighbor chunks must also be flagged to prevent visual seams [S4, unofficial].

3.  **Meshing Phase (Pre-Meshing)**:
    -   Iterate through each chunk in the `dirtyChunks` set.
    -   For each dirty chunk:
        -   Assert that `chunk.dirty` is true [S1, unofficial].
        -   Call `UnsetDirty()` to clear the flag, preventing double-processing if the chunk is modified again before meshing completes [S1, unofficial].
        -   Perform Marching Cubes (or similar) surface extraction on the chunk's voxel data.
        -   Store the resulting vertices and indices in `chunk.meshData` [S1, unofficial].

4.  **Buffer Update (Post-Meshing)**:
    -   After meshing a chunk, check if `chunk.meshData.Length > 0` [S1, unofficial].
    -   If data exists:
        -   Create a new `VoxelVertexBuffer` or update an existing one.
        -   Copy the mesh data to the GPU using `BufferData()` [S1, unofficial].
    -   Recycle temporary mesh visitor and vertex storage using allocators (e.g., `MeshVisiterAllocator.Recycle`, `TempStorageAllocator<VoxelVertex>.Recycle`) to manage memory efficiently [S1, unofficial].
    -   Remove the chunk from the `dirtyChunks` set [S3, unofficial].

5.  **Cleanup**:
    -   After processing all dirty chunks, the `dirtyChunks` set should be empty [S3, unofficial].

### Pseudocode

```python
# Data Structures
class Chunk:
    dirty: bool
    meshData: List[VoxelVertex]
    vertexBuffer: GPUBuffer

class World:
    chunks: Array[Chunk]
    dirtyChunks: Set[int] # Indices of dirty chunks
    chunkSize: int

def mark_chunk_dirty(world: World, voxel_min: Vector3i, voxel_max: Vector3i):
    """
    Marks chunks containing modified voxels as dirty.
    Accounts for boundary effects where a voxel affects adjacent cells.
    """
    # Calculate affected chunk ranges
    # A voxel at x affects x-1, so min chunk is (minX - 1) / chunkSize
    c_min_x = (voxel_min.x - 1) // world.chunkSize
    c_max_x = voxel_max.x // world.chunkSize
    c_min_y = (voxel_min.y - 1) // world.chunkSize
    c_max_y = voxel_max.y // world.chunkSize
    c_min_z = (voxel_min.z - 1) // world.chunkSize
    c_max_z = voxel_max.z // world.chunkSize

    # Clamp to world bounds [G]
    c_min_x = max(0, c_min_x)
    c_max_x = min(world.ChunkAmountX - 1, c_max_x)
    c_min_y = max(0, c_min_y)
    c_max_y = min(world.ChunkAmountY - 1, c_max_y)
    c_min_z = max(0, c_min_z)
    c_max_z = min(world.ChunkAmountZ - 1, c_max_z)

    for cx in range(c_min_x, c_max_x + 1):
        for cy in range(c_min_y, c_max_y + 1):
            for cz in range(c_min_z, c_max_z + 1):
                chunk = world.chunks[cx, cy, cz]
                if not chunk.dirty:
                    chunk.dirty = True
                    world.dirtyChunks.add((cx, cy, cz))

def process_dirty_chunks(world: World):
    """
    Rebuilds geometry for all dirty chunks and updates GPU buffers.
    """
    # Iterate over a copy of the set if chunks can be added during processing [G]
    dirty_list = list(world.dirtyChunks)
    world.dirtyChunks.clear()

    for (cx, cy, cz) in dirty_list:
        chunk = world.chunks[cx, cy, cz]
        
        # Assert and clear dirty flag
        assert chunk.dirty
        chunk.dirty = False
        
        # Generate mesh
        # PreMeshing() logic: assert dirty, unset dirty
        chunk.meshData = generate_mesh(chunk.voxelData)
        
        # PostMeshing() logic
        if len(chunk.meshData) > 0:
            # Create or update vertex buffer
            chunk.vertexBuffer = create_gpu_buffer(chunk.meshData)
        
        # Recycle temporary memory
        recycle_mesh_visitor()
        recycle_temp_storage(chunk.meshData)

def late_update(world: World):
    """
    Called once per frame to process all pending dirty chunks.
    """
    if len(world.dirtyChunks) > 0:
        process_dirty_chunks(world)
```

### Parameters
-   **Chunk Size**: Typically 16x16x16 or 32x32x32 voxels [S1, S2, unofficial].
-   **Dirty Flag**: Boolean per chunk [S1, unofficial].

### Edge Cases and Pitfalls
-   **View Change Rebuilds**: Modifying display lists or vertex buffers whenever the view changes negates the benefit of caching static geometry [S2, unofficial].
-   **Boundary Effects**: Failing to account for the fact that a voxel at index $x$ affects the cell to its left ($x-1$) will result in missing geometry at chunk boundaries [S3, unofficial].
-   **Visual Flicker**: If a chunk is flagged as unmeshed and the old geometry is discarded immediately, the user sees a blank flicker while the CPU rebuilds the model [S4, unofficial].

## Subtopics

### Double-Buffered Remeshing
A technique to update chunk geometry without visual flicker by keeping the old geometry visible while the new mesh is constructed in the background, then swapping them [S4, unofficial]. When a block is edited, the chunk is flagged as unmeshed, but the existing geometry continues to be rendered [S4, unofficial]. A meshing worker constructs the updated model silently [S4, unofficial]. Once ready, the old and new geometry are swapped in a single frame [S4, unofficial]. If a block on a chunk's outer boundary is modified, neighbor chunks are also flagged, and adjacent chunk edits are overlaid onto halo margins to prevent visual seams [S4, unofficial].

## Operating characteristics
-   **Time Complexity**: $O(N_{dirty})$ per frame, where $N_{dirty}$ is the number of modified chunks. This is significantly faster than $O(N_{total})$ for large worlds with sparse changes.
-   **Memory Complexity**: $O(N_{total})$ for storing chunk data and buffers, plus $O(N_{dirty})$ for temporary meshing storage.
-   **Performance**: Reduces CPU load by avoiding redundant Marching Cubes calculations. The bottleneck shifts to the GPU buffer updates and the meshing of dirty chunks.
-   **Strengths**: Efficient for dynamic worlds with frequent small changes.
-   **Limitations**: Requires careful management of dirty flags and boundary conditions. Double-buffering adds complexity and memory overhead for storing two versions of geometry.

## Background
The Dirty Flag System is a standard optimization in voxel-based games and terrain rendering. It was popularized by games like Minecraft, which rebuilds display lists or vertex buffers only when a block is modified in a given chunk [S2, unofficial]. The technique is widely used in chunk-based meshing systems to balance update frequency with rendering performance.
