# Chunk Mesh Rendering Setup

Also called: Chunk Mesh Rendering

## Overview
Chunk Mesh Rendering Setup manages the GPU-side presentation of pre-computed voxel geometry. It groups meshed blocks into chunks, storing each chunk in a single Vertex Buffer Object (VBO) [S2, unofficial]. The method handles frustum culling at the chunk level and sets up the necessary model matrix uniforms before issuing draw calls [S1, unofficial]. It differs from sibling methods by focusing on the final submission of geometry to the graphics API rather than the mesh generation or data structure management [S1, S2, unofficial].

## How it works
**Inputs:**
- A list of active chunks, each containing a populated VBO [S2, unofficial].
- Camera position and view/projection matrices for frustum culling [S1, unofficial].
- Chunk voxel data (`chunk_voxels`) and world voxel data (`world_voxels`) for context, though the mesh is pre-built [S1, unofficial].

**Outputs:**
- Rendered scene with visible chunks [S1, unofficial].

**Data Structures:**
- **Chunk:** Contains a VBO ID and bounding box for culling.
- **VBO Format:** The vertex data layout is described as `'1u4'`, indicating a packed structure of 1 unsigned byte and 4 unsigned bytes (or similar) per vertex. The total buffer size is calculated by summing the integer parts of the format specifiers [S1, unofficial].

**Steps:**
1. **Build Mesh:** For each chunk, call `build_chunk_mesh` using `chunk_voxels` and `world_voxels` to generate the vertex data [S1, unofficial].
2. **Create VBO:** Upload the generated vertex data to a single VBO per chunk [S2, unofficial].
3. **Cull:** Determine if the chunk is within the camera's frustum [S1, unofficial].
4. **Render:** If the chunk is not empty and passes frustum culling:
   a. Set the model matrix uniform [S1, unofficial].
   b. Issue the draw call.

**Pitfalls:**
- Using `glDrawArrays` instead of indexed drawing (`glDrawElements`) wastes memory and potentially bandwidth, as it does not share vertices between adjacent faces [S2, unofficial].

**Pseudocode:**
```python
def render_chunk_meshes(camera, chunks):
    # 1. Frustum Culling
    visible_chunks = []
    for chunk in chunks:
        if chunk.is_empty:
            continue
        if camera.frustum_intersects(chunk.bounding_box):
            visible_chunks.append(chunk)
    
    # 2. Render Visible Chunks
    for chunk in visible_chunks:
        # Set model matrix uniform for this chunk's position
        set_uniform_matrix4f("model_matrix", chunk.model_matrix)
        
        # Bind the chunk's VBO
        bind_vbo(chunk.vbo_id)
        
        # Draw using indexed drawing to save memory
        # Note: Source [S2, unofficial] warns against glDrawArrays; indices are required
        draw_elements(mode=TRIANGLES, count=chunk.index_count, type=UNSIGNED_INT)
```

## Operating characteristics
- **Time Complexity:** Rendering time scales with the number of visible chunks.
- **Memory:** One VBO per chunk. Using indexed drawing reduces vertex storage compared to non-indexed [S2, unofficial].
- **Performance:**
  - 64 chunks: ~500 FPS [S2, unofficial].
  - 125 chunks: ~300 FPS [S2, unofficial].
  - 1000 chunks: ~45-49 FPS [S2, unofficial].
  - 4096 chunks: ~12 FPS [S2, unofficial].
- **Strengths:** Simple implementation; efficient for static or semi-static worlds when combined with culling [S2, unofficial].
- **Limitations:** Performance degrades significantly with high chunk counts due to draw call overhead and bandwidth [S2, unofficial].
- **When to use:** Small to medium-sized voxel worlds where draw call overhead is manageable.
- **When not to use:** Very large worlds requiring thousands of simultaneous chunks without further optimization (e.g., instancing).
