# VBO with Face Grouping and Texture Atlas

Also called: ChunkMesh Texture-Atlas VBO Management, Face Grouping, Texture Atlas Grouping

## Overview
This method optimizes voxel rendering by grouping faces into Vertex Buffer Objects (VBOs) based on texture and face orientation, minimizing state changes and buffer rebuilds. It differs from per-chunk VBO approaches by pooling faces across chunks into shared buffers, and from naive meshing by explicitly separating face normals into shader uniforms rather than vertex attributes. It builds on [Chunk Mesh Data Structure & Buffer Update](4182-chunk-mesh-data-structure-buffer-update.md) by defining how that data is packed into GPU buffers.

## How it works
**Inputs:** A list of visible chunks, each containing polygonized faces (vertices, indices, texture IDs, face normals).
**Outputs:** A set of VBOs (one per texture/orientation group) and draw calls.

**Data Structures:**
1.  **Face Pool:** A contiguous array of face descriptors. Each descriptor contains:
    *   `texture_id`: Integer index into the texture atlas.
    *   `face_type`: Enum (NORTH, SOUTH, EAST, WEST, TOP, BOTTOM).
    *   `vertex_indices`: Array of 4 vertex indices (for a quad).
    *   *Note:* The exact vertex layout (positions, UVs) is stored in a separate Vertex Buffer, indexed by these indices.
2.  **VBO:** A GPU buffer containing interleaved or separated vertex data (positions, UVs). The Face Pool indices reference this buffer.

**Steps:**
1.  **Frustum Culling:** Test chunk centers against a frustum expanded by half a block. Discard chunks entirely outside this volume. [S1, unofficial]
2.  **Polygonization & Interior Culling:** For each visible chunk, generate faces. Cull interior faces (faces adjacent to another solid block within the same chunk or neighboring chunks). [S1, unofficial]
3.  **Face Grouping:**
    *   Iterate through all generated faces.
    *   Group faces by `texture_id`. Faces with the same texture are candidates for the same VBO. [S1, unofficial]
    *   Within each texture group, sort or partition faces by `face_type` (NORTH, SOUTH, etc.). This ensures indices for the same face type are adjacent in the element array. [S1, unofficial]
    *   Pack faces into VBOs. Multiple chunks share a single VBO until it is "full" (similar to `malloc` behavior). [S1, unofficial]
4.  **Normal Handling:** Do not store face normals in the VBO. Instead, compute the normalized, projected normal for each face type (NORTH, SOUTH, etc.) and upload it as a shader uniform. [S1, unofficial]
5.  **Rendering:**
    *   For each texture group VBO:
        *   Set the texture atlas uniform.
        *   For each face type (NORTH, SOUTH, EAST, WEST, TOP, BOTTOM):
            *   Set the corresponding normal uniform.
            *   Call `glDrawRangeElements` (or equivalent) using the subset of indices for that face type within the VBO. [S1, unofficial]
6.  **Lifecycle Management:**
    *   Create VBOs when chunks become visible.
    *   Destroy VBOs when chunks have been invisible for a long time. [S1, unofficial]
    *   Re-polygonize and update VBOs only when a chunk is edited. [S1, unofficial]

**Pseudocode:**
```python
def render_voxel_world(chunks, texture_atlas):
    # 1. Frustum Culling
    visible_chunks = []
    for chunk in chunks:
        if is_chunk_in_frustum(chunk.center, expanded_frustum):
            visible_chunks.append(chunk)
    
    # 2. Face Grouping
    # Structure: texture_id -> face_type -> list of (vertex_indices)
    face_groups = {} 
    
    for chunk in visible_chunks:
        # Only polygonize if edited or visible
        if not chunk.is_polygonized:
            chunk.faces = polygonize_chunk(chunk)
            chunk.is_polygonized = True
        
        # Interior culling happens during polygonization
        for face in chunk.faces:
            tex_id = face.texture_id
            face_type = face.type # NORTH, SOUTH, etc.
            
            if tex_id not in face_groups:
                face_groups[tex_id] = {}
            if face_type not in face_groups[tex_id]:
                face_groups[tex_id][face_type] = []
            
            face_groups[tex_id][face_type].append(face.vertex_indices)

    # 3. Build VBOs and Draw
    for tex_id, type_groups in face_groups.items():
        bind_texture_atlas(tex_id)
        
        # Combine all face types for this texture into one VBO if possible,
        # or manage separate VBOs per type. The source suggests sharing VBOs
        # across chunks for the same texture.
        vbo = get_or_create_vbo_for_texture(tex_id)
        
        for face_type in [NORTH, SOUTH, EAST, WEST, TOP, BOTTOM]:
            if face_type in type_groups:
                indices = type_groups[face_type]
                if not indices:
                    continue
                
                # Upload indices to VBO if not already present
                # Note: In a real implementation, this requires managing
                # the VBO's index buffer capacity.
                vbo.append_indices(indices)
                
                # Set normal uniform for this face type
                normal = get_normal_uniform(face_type)
                set_shader_uniform("normal", normal)
                
                # Draw range elements for this specific face type subset
                # Assumes vbo tracks offset/count for each face type
                vbo.draw_range_elements(face_type)
```

**Parameters:**
*   **Frustum Expansion:** Half a block size. [S1, unofficial]
*   **VBO Capacity:** Determined by available GPU memory; faces are packed until full. [S1, unofficial]

**Edge Cases:**
*   **Dynamic Destruction:** If blocks are destroyed dynamically, the large VBO may need rebuilding. A secondary buffer for recently modified blocks can mitigate this. [S2, unofficial]
*   **Precision:** Normals are pre-computed and normalized. Ensure floating-point precision is sufficient for normal projection. [S1, unofficial]

## Subtopics

### Single-Buffer Transparent Block Batching
A variant for transparent geometry (e.g., water) where all visible transparent blocks are grouped into a single large VBO and rendered in one draw call after opaque blocks. This replaces per-chunk VAO/VBO setups for transparency. It requires walking the octree to identify visible transparent blocks and appending their indices to the single buffer. A pitfall is dynamic block destruction, which may require a second smaller buffer for recently modified blocks to avoid rebuilding the entire large buffer every frame. [S2, unofficial]

### Texture/Material Grouping for State Minimization
A general optimization strategy where objects sharing the same shader parameters and textures are grouped together. The steps are: identify objects with shared parameters/textures, bind the shared values, and draw all such objects. This minimizes state changes and is applicable to voxel scenes with multiple materials. [S3, unofficial]

## Operating characteristics
*   **Time Complexity:** $O(N)$ for face generation and grouping, where $N$ is the number of visible faces. Draw calls are proportional to the number of texture/orientation groups, not individual chunks or faces.
*   **Memory Complexity:** $O(N)$ for VBO storage. Memory is reused across frames, reducing allocation overhead.
*   **Performance:** Significantly reduces draw call overhead and state changes. The biggest speedup comes from culling interior faces and avoiding per-frame VBO rebuilds. [S1, unofficial]
*   **Strengths:** Efficient for static or semi-static voxel worlds. Minimizes CPU-GPU bandwidth for buffer updates.
*   **Limitations:** Less efficient for highly dynamic worlds where faces change frequently, as VBOs may need frequent updates. [S1, unofficial]
*   **When to Use:** Voxel games with large, mostly static worlds. [S1, unofficial]
*   **When Not to Use:** Highly dynamic scenes with frequent block changes, unless combined with incremental update strategies. [S1, unofficial]

## Background
This method is inspired by rendering techniques used in voxel games like Minecraft. It addresses the "death by a thousand cuts" problem of excessive function calls and state changes. The approach of grouping faces by texture and orientation, and using uniforms for normals, was described in community discussions on game development forums. [S1, S2, S3, unofficial]
