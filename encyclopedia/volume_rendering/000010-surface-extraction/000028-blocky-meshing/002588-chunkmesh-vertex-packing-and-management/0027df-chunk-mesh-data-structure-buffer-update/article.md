# Chunk Mesh Data Structure & Buffer Update

Also called: ChunkMesh Update Loop, Dynamic Chunk Mesh Buffer Management, Mega Buffer, MegaSSBO Memory Management, SSBO Allocator, Voxel Buffer Management

## Overview
This method manages the creation, population, and recycling of GPU vertex buffers for meshed chunk geometry, specifically addressing the dynamic allocation of face data in large, contiguous memory regions [S1, S3, unofficial]. It solves the problem of efficiently mapping variable-sized mesh outputs from blocky surface extraction into a fixed-capacity GPU buffer without frequent reallocation [S3, unofficial]. It sets itself apart from sibling methods by focusing on the low-level memory allocator (free-list) and buffer upload mechanics rather than the mesh generation algorithm itself [S1, S3, unofficial] or the final rendering submission [S2, S4, unofficial].

## How it works
The method operates on a "Mega Buffer" architecture, where a single large Shader Storage Buffer (SSBO) or Vulkan Storage Buffer holds the vertex/index data for all active chunks [S3, S4, unofficial]. A free-list allocator manages the offsets within this buffer, allowing chunks to be allocated, freed, and compacted dynamically [S3, unofficial].

### Inputs and Outputs
*   **Input:** Meshed vertex data (e.g., `tempMeshData` containing `VoxelVertex` structs) generated by the meshing pass [S1, unofficial]. Face counts per chunk [S3, unofficial].
*   **Output:** A populated GPU buffer (SSBO/VBO) containing interleaved chunk mesh data, ready for rendering [S1, S3, unofficial].

### Data Structures

**1. Mega Buffer (SSBO/Vulkan Buffer)**
A single large buffer allocated on the GPU.
*   **Type:** `GL_SHADER_STORAGE_BUFFER` (OpenGL) or `VK_BUFFER_USAGE_STORAGE_BUFFER_BIT` (Vulkan) [S3, S4, unofficial].
*   **Capacity:** Defined by `MAX_FACES` (OpenGL) or `MaxQuads` (Vulkan). In the reference implementation, `MAX_FACES = 20,000,000` elements of `uint32_t` [S3, unofficial].
*   **Usage:** `GL_DYNAMIC_DRAW` (OpenGL) or equivalent dynamic usage flag [S3, S4, unofficial].

**2. Free List Allocator**
Manages free space within the Mega Buffer to handle variable face counts per chunk [S3, unofficial].
*   **Structure `FreeBlock`:**
    *   `offset`: `uint32_t` (Start index in terms of face count/elements) [S3, unofficial].
    *   `size`: `uint32_t` (Capacity in terms of face count/elements) [S3, unofficial].
*   **Container:** `std::list<FreeBlock>` or `std::vector<FreeBlock>` maintaining contiguous free regions in ascending offset order [S3, unofficial].

**3. Chunk Metadata**
Each chunk tracks its allocation status [S2, S3, unofficial].
*   **Fields:**
    *   `offset`: `uint32_t` (The allocated offset in the Mega Buffer) [S3, unofficial].
    *   `faceCount`: `uint32_t` (Number of faces/vertices currently stored) [S3, unofficial].
    *   `update`: `bool` (Flag indicating if the buffer needs refresh) [S2, unofficial].
    *   `x, y, z`: `int` (Chunk coordinates) [S2, unofficial].
    *   `vao`: `GLuint` (OpenGL Vertex Array Object handle, if using VBO approach) [S2, unofficial].

### Initialization
1.  **Create Buffer:** Allocate the Mega Buffer with size `MAX_FACES * sizeof(uint32_t)` (OpenGL) or `MaxQuads * QuadSize` (Vulkan) [S3, S4, unofficial].
2.  **Initialize Free List:** Create `m_FreeList` with a single block: `{offset: 0, size: MAX_FACES}` [S3, unofficial].
3.  **Load Chunks:** Initialize `chunkMeshes` map/dictionary per shader and chunk position [S2, unofficial].

### Allocation (First Fit)
When a chunk is meshed and has data (`tempMeshData.Length > 0`):
1.  Calculate `faceCount` from the meshed data [S3, unofficial].
2.  Iterate through `m_FreeList`.
3.  If `it->size >= faceCount`:
    *   If `it->size == faceCount`: Erase the element from the list. Return `it->offset` [S3, unofficial].
    *   If `it->size > faceCount`: Update `it->offset += faceCount` and `it->size -= faceCount`. Return the original `it->offset` [S3, unofficial].
4.  If no block fits, return `UINT32_MAX` (allocation failure) [S3, unofficial].
5.  Store the returned `offset` and `faceCount` in the chunk's metadata [S3, unofficial].

### Deallocation and Compaction
When a chunk is removed or invalidated:
1.  Insert a new `FreeBlock` `{offset, faceCount}` into `m_FreeList` at the sorted position to maintain ascending offset order [S3, unofficial].
2.  Call `Merge()` to combine adjacent free blocks [S3, unofficial].
    *   Iterate `m_FreeList`.
    *   If `it->offset + it->size == next->offset`:
        *   Merge: `it->size += next->size`.
        *   Erase `next`.
        *   Continue checking from `it` to catch cascading merges [S3, unofficial].

### Data Upload
1.  **Bind Buffer:** Bind the SSBO/VBO to the appropriate binding point [S3, S4, unofficial].
2.  **Calculate Byte Offsets:** `byteOffset = offset * sizeof(uint32_t)` [S3, unofficial].
3.  **Upload Data:**
    *   **OpenGL:** Use `glBufferSubData(GL_SHADER_STORAGE_BUFFER, byteOffset, faceCount * sizeof(uint32_t), data)` [S3, unofficial].
    *   **Vulkan:** Use `vkUpdateBuffer` or map memory and copy [S4, unofficial].
4.  **Move Data (Compaction):** If fragmentation requires shifting data (e.g., to fill a gap), use `glCopyBufferSubData` between `GL_COPY_READ_BUFFER` and `GL_COPY_WRITE_BUFFER` (both bound to the same SSBO ID) to shift data by `faceCount * sizeof(uint32_t)` bytes [S3, unofficial].

### Pseudocode

> **Unverified code.** The code below did not pass a test run against a reference implementation, or no test fits it, so it may contain errors.

```python
# Data Structures
class FreeBlock:
    offset: uint32
    size: uint32

class ChunkMesh:
    offset: uint32
    faceCount: uint32
    update: bool
    x: int
    y: int
    z: int
    vao: GLuint # Optional, if using VBO approach

class MegaSSBO:
    MAX_FACES: uint32 = 20_000_000
    m_RendererID: GLuint
    m_FreeList: list[FreeBlock]
    
    def __init__(self):
        # Initialize GL buffer with MAX_FACES * sizeof(uint32_t)
        self.m_RendererID = glCreateBuffer()
        glBufferData(GL_SHADER_STORAGE_BUFFER, self.MAX_FACES * 4, None, GL_DYNAMIC_DRAW)
        # Initialize free list with one block
        self.m_FreeList = [FreeBlock(offset=0, size=self.MAX_FACES)]

    def allocate(self, faceCount: uint32) -> uint32:
        # First Fit Allocation
        for i, block in enumerate(self.m_FreeList):
            if block.size >= faceCount:
                if block.size == faceCount:
                    self.m_FreeList.pop(i)
                    return block.offset
                else:
                    block.offset += faceCount
                    block.size -= faceCount
                    return block.offset - faceCount
        return UINT32_MAX # Allocation failure

    def free(self, offset: uint32, faceCount: uint32):
        # Insert new block at sorted position
        new_block = FreeBlock(offset=offset, size=faceCount)
        # Insert into m_FreeList maintaining order
        self.m_FreeList.append(new_block)
        self.m_FreeList.sort(key=lambda b: b.offset)
        self.merge()

    def merge(self):
        # Merge adjacent blocks
        i = 0
        while i < len(self.m_FreeList) - 1:
            current = self.m_FreeList[i]
            next_block = self.m_FreeList[i+1]
            if current.offset + current.size == next_block.offset:
                current.size += next_block.size
                self.m_FreeList.pop(i+1)
                # Do not increment i to check for cascading merges
            else:
                i += 1

    def upload(self, data: bytes, faceCount: uint32, offset: uint32):
        # Bind SSBO
        glBindBuffer(GL_SHADER_STORAGE_BUFFER, self.m_RendererID)
        # Upload using glBufferSubData
        byte_offset = offset * 4
        byte_size = faceCount * 4
        glBufferSubData(GL_SHADER_STORAGE_BUFFER, byte_offset, byte_size, data)

    def move(self, srcOffset: uint32, dstOffset: uint32, faceCount: uint32):
        # Shift data using glCopyBufferSubData
        glBindBuffer(GL_COPY_READ_BUFFER, self.m_RendererID)
        glBindBuffer(GL_COPY_WRITE_BUFFER, self.m_RendererID)
        src_byte = srcOffset * 4
        dst_byte = dstOffset * 4
        size_byte = faceCount * 4
        glCopyBufferSubData(GL_COPY_READ_BUFFER, GL_COPY_WRITE_BUFFER, src_byte, dst_byte, size_byte)

# Main Update Loop
def update_chunk_mesh(chunk: ChunkMesh, tempMeshData: list[VoxelVertex], megaSSBO: MegaSSBO):
    if chunk.update:
        if len(tempMeshData) > 0:
            faceCount = len(tempMeshData)
            # Allocate new offset
            newOffset = megaSSBO.allocate(faceCount)
            
            if newOffset != UINT32_MAX:
                chunk.offset = newOffset
                chunk.faceCount = faceCount
                # Upload data
                megaSSBO.upload(tempMeshData, faceCount, newOffset)
            else:
                # Handle fragmentation/failure, potentially trigger compaction
                pass
        else:
            # Free previous allocation
            if chunk.faceCount > 0:
                megaSSBO.free(chunk.offset, chunk.faceCount)
                chunk.faceCount = 0
                chunk.offset = 0
        
        chunk.update = False
        
        # Recycle temporary buffers
        recycle_temp_mesh_visitor(tempMeshData)
```

### Parameters and Typical Values
*   `MAX_FACES`: Total capacity of the MegaSSBO in `uint32_t` elements. Example value: `20,000,000` [S3, unofficial].
*   `ChunkSize`: Typically `16` or `32` blocks per chunk dimension [S1, unofficial].
*   `VoxelVertex`: Vertex structure type. Fields are not detailed in the source excerpts but typically include position, normal, and UV coordinates [S1, S3, unofficial].

### Edge Cases and Pitfalls
*   **Fragmentation:** Free blocks may become non-adjacent, leading to allocation failure (`UINT32_MAX`) even if total free space is sufficient [S3, unofficial]. Mitigated by the `Merge()` step after every `Free()` call [S3, unofficial].
*   **Precision/Boundaries:** Map size must be divisible by `ChunkSize` to ensure consistent chunk indexing [S1, unofficial].
*   **Memory Leaks:** Temporary mesh visitor and vertex storage pools must be recycled after buffer upload [S1, unofficial].

## Subtopics

### [Dirty Flag System for Incremental Meshing](4192-dirty-flag-system-for-incremental-meshing.md)
The Dirty Flag System is an optimization technique for blocky meshing that avoids redundant surface extraction by tracking which chunks of a voxel world have changed geometry since the last mesh pass. Instead of rebuilding vertex buffers for every chunk every frame or upon every view change, the system marks only chunks containing modified density values as "dirty" and rebuilds them incrementally. This sets it apart from naive approaches that rebuild all geometry or those that trigger rebuilds based on camera movement, which negates the performance benefits of static geometry caching.

### [Chunk Mesh Rendering Setup](4833-chunk-mesh-rendering-setup.md)
Chunk Mesh Rendering Setup manages the GPU-side presentation of pre-computed voxel geometry. It groups meshed blocks into chunks, storing each chunk in a single Vertex Buffer Object (VBO). The method handles frustum culling at the chunk level and sets up the necessary model matrix uniforms before issuing draw calls. It differs from sibling methods by focusing on the final submission of geometry to the graphics API rather than the mesh generation or data structure management.

### [OpenMP Parallel Meshing with Thread-Local Buffers](5768-openmp-parallel-meshing-with-thread-local-buffers.md)
This method distributes mesh generation across 4 OpenMP threads using thread-local buffer slots to avoid synchronization overhead during parallel chunk processing. It builds on [Chunk Mesh Data Structure & Buffer Update](4182-chunk-mesh-data-structure-buffer-update.md) by managing per-thread scratch memory for geometry, work indices, and SVL masks without global locks.

### Chunk Mesh Manager Initialization
The `ChunkMeshManager` initializes a storage buffer for chunk quads with size `MaxQuads * QuadSize` and usage `VK_BUFFER_USAGE_STORAGE_BUFFER_BIT` [S4, unofficial]. A GPU-only storage buffer is created for chunk uniform data, with size `MaxDrawCmds * sizeof(ChunkUniformData)` [S4, unofficial]. Cleanup involves waiting for all transfer fences to complete and returning them to the renderer [S4, unofficial].

### VBO with Face Grouping and Texture Atlas
Grouping faces to render together in Vertex Buffer Objects (VBOs) to avoid rebuilding buffers every frame and minimizing texture changes [S5, unofficial]. Faces in each chunk have spans in an element-array VBO; many faces from chunks share the same VBO until it is 'full' (like malloc); faces with the same texture are put in the same VBO where possible [S5, unofficial]. Vertex indices for north, south, etc. faces are adjacent rather than mixed in the VBO [S5, unofficial]. Draw using `glDrawRangeElements` for specific face types (e.g., north faces) with normals already projected and normalized in a uniform, then draw south faces, etc., so normals are not in the VBO [S5, unofficial]. Cull interior faces when polygonizing each chunk [S5, unofficial]. Manage texture-atlas and sort faces by texture, putting faces with the same texture in the same VBO as those from other chunks to avoid too many texture changes [S5, unofficial]. Only polygonize chunks that have ever been visible; discard chunks that haven't been visible for a long time; re-polygonize chunks that are edited [S5, unofficial].

## Operating characteristics
*   **Time Complexity:** Allocation is $O(N)$ where $N$ is the number of free blocks in the free list. Merge is $O(N)$ per deallocation. Upload is $O(F)$ where $F$ is the face count.
*   **Memory Complexity:** $O(MAX\_FACES)$ for the Mega Buffer. $O(C)$ for the free list where $C$ is the number of chunks.
*   **Performance:** Reduces GPU memory allocation overhead significantly compared to per-chunk buffer creation [S5, unofficial]. The free-list approach allows dynamic resizing of chunks without reallocation [S3, unofficial].
*   **Strengths:** Efficient memory reuse, supports variable chunk sizes, reduces driver overhead from frequent buffer creation/destruction [S3, S5, unofficial].
*   **Limitations:** Fragmentation can lead to allocation failures if not managed with compaction [S3, unofficial]. The free-list iteration can become slow if the number of free blocks is very large [S3, unofficial].
*   **When to use:** Large voxel worlds with dynamic changes where chunks are frequently added/removed or modified [S1, S3, unofficial].
*   **When not to use:** Static worlds with no changes, or worlds where chunk sizes are uniform and fixed (simpler contiguous allocation may suffice) [S5, unofficial].

## Background
The method originates from implementations of voxel engines and Minecraft-like renderers, where efficient management of large, dynamic geometry is critical [S1, S2, S3, S5, unofficial]. The "MegaSSBO" approach is detailed in the VoxelEngine project [S3, unofficial], while the VBO grouping and texture atlas strategies are discussed in community forums for optimizing Minecraft-style games [S5, unofficial]. Vulkan implementations adapt this for modern graphics APIs [S4, unofficial].
