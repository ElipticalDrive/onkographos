# Chunk Mesh Data Structure & Buffer Update

Also called: ChunkMesh Update Loop, Dynamic Chunk Mesh Buffer Management, Mega Buffer, MegaSSBO Memory Management, SSBO Allocator, Voxel Buffer Management

## Overview
This method manages the creation, population, and recycling of GPU vertex buffers for meshed chunk geometry, specifically addressing the dynamic allocation of face data within a large, shared storage buffer [S1, S3, unofficial]. It solves the problem of efficiently mapping variable-sized mesh outputs from blocky surface extraction (like [Face Culling](4152-face-culling.md)) into a fixed-capacity GPU resource without frequent reallocation [S3, unofficial]. It sets itself apart from naive per-chunk buffer allocation by using a free-list allocator within a single "Mega" buffer, allowing for compact, contiguous storage of chunk meshes and supporting incremental updates via dirty flags [S3, S1, unofficial].

## How it works
The method operates on a global Shader Storage Buffer (SSBO) or Vulkan Storage Buffer that acts as a heap for all chunk mesh data. It manages this heap using a free-list allocator to handle dynamic allocation and deallocation of face counts [S3, unofficial].

### Inputs and Outputs
*   **Input:** Meshed vertex data (typically `VoxelVertex` structs) generated by the meshing pass, stored in a temporary buffer (`tempMeshData`) [S1, unofficial]. The number of faces (`faceCount`) generated for a specific chunk [S3, unofficial].
*   **Output:** A contiguous region in the global SSBO containing the vertex data for the chunk, identified by an offset and face count stored in the chunk's metadata [S3, unofficial].

### Data Structures

**MegaSSBO / Global Buffer**
A single large buffer allocated on the GPU.
*   **Capacity:** `MAX_FACES` (uint32_t elements). In the reference implementation, `MAX_FACES = 20,000,000` [S3, unofficial].
*   **Usage:** `GL_DYNAMIC_DRAW` (OpenGL) or `VK_BUFFER_USAGE_STORAGE_BUFFER_BIT` (Vulkan) [S3, S4, unofficial].

**FreeBlock**
Represents a contiguous free region in the MegaSSBO.
*   `offset`: `uint32_t`. The starting index (in faces) of the free block within the MegaSSBO.
*   `size`: `uint32_t`. The number of face slots available in this block.
*   **Container:** `m_FreeList` is a sorted list (e.g., `std::list<FreeBlock>` or `std::vector<FreeBlock>`) maintaining all free blocks in ascending order of `offset` [S3, unofficial].

**Chunk Mesh Metadata**
Stored per chunk (often in a CPU-side structure or a separate uniform buffer).
*   `offset`: `uint32_t`. The face-index offset in the MegaSSBO where this chunk's data resides.
*   `faceCount`: `uint32_t`. The number of faces in this chunk.
*   `update`: `bool`. Flag indicating if the buffer needs refresh [S2, unofficial].

### Initialization
1.  Create the global SSBO with size `MAX_FACES * sizeof(uint32_t)` (assuming 32-bit indices/vertices) [S3, unofficial].
2.  Initialize `m_FreeList` with a single block: `{offset: 0, size: MAX_FACES}` [S3, unofficial].

### Allocation
When a chunk is meshed and `tempMeshData.Length > 0`, the system must allocate space in the MegaSSBO [S1, unofficial].

1.  Determine `faceCount` from the generated mesh data [S3, unofficial].
2.  Iterate through `m_FreeList` (First Fit strategy):
    *   If `it->size >= faceCount`:
        *   The block fits.
        *   If `it->size == faceCount`: Remove `it` from the list (exact fit) [S3, unofficial].
        *   If `it->size > faceCount`: Update `it->offset += faceCount` and `it->size -= faceCount` (split block) [S3, unofficial].
        *   Return `it->offset` as the allocated offset [S3, unofficial].
    *   If `it->size < faceCount`: Continue to next block.
3.  If no block fits, return `UINT32_MAX` (allocation failure) [S3, unofficial].

### Deallocation
When a chunk is removed or invalidated:

1.  Retrieve the chunk's `offset` and `faceCount` [S3, unofficial].
2.  Insert a new `FreeBlock {offset, faceCount}` into `m_FreeList` at the correct sorted position to maintain ascending `offset` order [S3, unofficial].
3.  Call `Merge()` to combine adjacent free blocks [S3, unofficial].

**Merge Adjacent Blocks**
1.  Iterate through `m_FreeList`.
2.  If `it->offset + it->size == next->offset` (where `next` is the subsequent element):
    *   Merge: `it->size += next->size`.
    *   Erase `next` from the list.
    *   Continue checking from `it` to handle cascading merges (e.g., if the new merged block is also adjacent to the one after `next`) [S3, unofficial].

### Data Upload
1.  Bind the MegaSSBO [S3, unofficial].
2.  Calculate byte offset: `byte_offset = offset * sizeof(uint32_t)` [S3, unofficial].
3.  Calculate byte size: `byte_size = faceCount * sizeof(uint32_t)` [S3, unofficial].
4.  Upload data from `tempMeshData` to the SSBO using `glBufferSubData` (OpenGL) or `vkUpdateBuffer`/`vkCmdCopyBuffer` (Vulkan) [S1, S3, unofficial].
5.  Update the chunk's metadata with the allocated `offset` and `faceCount` [S3, unofficial].
6.  Recycle temporary mesh visitor and vertex storage pools to prevent memory leaks [S1, unofficial].

### Buffer Compaction (Handling Fragmentation)
Fragmentation can cause `UINT32_MAX` allocation failures even if total free space is sufficient, because free blocks are non-contiguous [S3, unofficial].
*   **Trigger:** When allocation fails or periodically.
*   **Action:** Shift existing data in the SSBO to consolidate free space.
*   **Method:** Use `glCopyBufferSubData` (OpenGL) or `vkCmdCopyBuffer` (Vulkan) to move data blocks.
    *   Example: Shift data by `faceCount * sizeof(uint32_t)` bytes using `GL_COPY_READ_BUFFER` and `GL_COPY_WRITE_BUFFER` bound to the same SSBO ID [S3, unofficial].
    *   Update the `offset` in the chunk metadata for all moved chunks.
    *   Rebuild `m_FreeList` to reflect the new contiguous free space [S3, unofficial].

class FreeBlock:
    offset: int
    size: int

class ChunkMesh:
    offset: int
    faceCount: int
    update: bool
    vertices: list[VoxelVertex] # Temporary storage

class MegaSSBO:
    MAX_FACES: int = 20_000_000
    m_FreeList: list[FreeBlock]
    buffer_id: int

    def __init__(self):
        # Initialize with one large free block
        self.m_FreeList = [FreeBlock(offset=0, size=self.MAX_FACES)]
        # Create GPU buffer of size MAX_FACES * sizeof(uint32_t)
        self.create_gpu_buffer()

    def allocate(self, faceCount: int) -> int:
        """
        Allocates a block of faceCount faces.
        Returns offset in faces, or UINT32_MAX on failure.
        """
        for i, block in enumerate(self.m_FreeList):
            if block.size >= faceCount:
                if block.size == faceCount:
                    # Exact fit: remove block
                    self.m_FreeList.pop(i)
                else:
                    # Split block
                    block.offset += faceCount
                    block.size -= faceCount
                return block.offset - faceCount # Return original offset
        return UINT32_MAX

    def free(self, offset: int, faceCount: int):
        """
        Frees a previously allocated block.
        """
        new_block = FreeBlock(offset=offset, size=faceCount)
        
        # Insert into sorted list
        inserted = False
        for i, block in enumerate(self.m_FreeList):
            if new_block.offset < block.offset:
                self.m_FreeList.insert(i, new_block)
                inserted = True
                break
        if not inserted:
            self.m_FreeList.append(new_block)
            
        self.merge()

    def merge(self):
        """
        Merges adjacent free blocks to reduce fragmentation.
        """
        i = 0
        while i < len(self.m_FreeList) - 1:
            current = self.m_FreeList[i]
            next_block = self.m_FreeList[i+1]
            
            if current.offset + current.size == next_block.offset:
                # Merge next into current
                current.size += next_block.size
                self.m_FreeList.pop(i+1)
                # Do not increment i, check if current merges with the new next
            else:
                i += 1

    def upload(self, data: list[VoxelVertex], faceCount: int, offset: int):
        """
        Uploads mesh data to the SSBO at the given offset.
        """
        byte_offset = offset * sizeof(uint32_t)
        byte_size = faceCount * sizeof(uint32_t)
        # glBufferSubData or equivalent
        self.bind_buffer()
        self.write_subdata(byte_offset, byte_size, data)

### Parameters
*   `MAX_FACES`: Total capacity of the MegaSSBO in face units. Value is implementation-dependent; 20,000,000 is a reference value [S3, unofficial].
*   `VoxelVertex`: The vertex structure type. Fields are not detailed in the sources but typically include position, normal, and texture coordinates [S1, unofficial].
*   `tempMeshData`: Temporary storage buffer holding `VoxelVertex` structs generated during the meshing pass [S1, unofficial].

### Edge Cases and Pitfalls
*   **Fragmentation:** Free blocks may become non-adjacent, leading to allocation failures (`UINT32_MAX`) despite sufficient total free space [S3, unofficial]. Mitigated by the `Merge()` step after every `Free()` call and periodic compaction [S3, unofficial].
*   **Precision:** Offsets are in units of `uint32_t` (faces). Byte offsets must be calculated as `offset * sizeof(uint32_t)` [S3, unofficial].
*   **Boundary Conditions:** If `faceCount` is 0, the chunk should be freed or marked as empty to avoid allocating zero-size blocks which can complicate the free list [S3, unofficial].

## Subtopics

### [Dirty Flag System for Incremental Meshing](4192-dirty-flag-system-for-incremental-meshing.md)
The Dirty Flag System is an optimization technique for blocky meshing that avoids redundant surface extraction by tracking which chunks of a voxel world have changed geometry since the last mesh pass. Instead of rebuilding vertex buffers for every chunk every frame or upon every view change, the system marks only chunks containing modified density values as "dirty" and rebuilds them incrementally. This sets it apart from naive approaches that rebuild all geometry or those that trigger rebuilds based on camera movement, which negates the performance benefits of static geometry caching.

### [Chunk Mesh Rendering Setup](4833-chunk-mesh-rendering-setup.md)
Chunk Mesh Rendering Setup manages the GPU-side presentation of pre-computed voxel geometry. It groups meshed blocks into chunks, storing each chunk in a single Vertex Buffer Object (VBO). The method handles frustum culling at the chunk level and sets up the necessary model matrix uniforms before issuing draw calls. It differs from sibling methods by focusing on the final submission of geometry to the graphics API rather than the mesh generation or data structure management.

### [OpenMP Parallel Meshing with Thread-Local Buffers](5768-openmp-parallel-meshing-with-thread-local-buffers.md)
This method distributes mesh generation across 4 OpenMP threads using thread-local buffer slots to avoid synchronization overhead during parallel chunk processing. It builds on [Chunk Mesh Data Structure & Buffer Update](4182-chunk-mesh-data-structure-buffer-update.md) by managing per-thread scratch memory for geometry, work indices, and SVL masks without global locks.

### Chunk Mesh Manager Initialization
The `ChunkMeshManager` initializes a storage buffer for chunk quads with size `MaxQuads * QuadSize` and usage `VK_BUFFER_USAGE_STORAGE_BUFFER_BIT` [S4, unofficial]. A GPU-only storage buffer is created for chunk uniform data, with size `MaxDrawCmds * sizeof(ChunkUniformData)` [S4, unofficial]. Cleanup involves waiting for all transfer fences to complete and returning them to the renderer [S4, unofficial].

### VBO with Face Grouping and Texture Atlas
Grouping faces to render together in Vertex Buffer Objects (VBOs) to avoid rebuilding buffers every frame and minimizing texture changes [S5, unofficial]. Create/destroy VBOs for what is visible to keep memory consumption down; only take the hit as the VBO was created rather than every frame [S5, unofficial]. Faces in each chunk have spans in an element-array VBO; many faces from chunks share the same VBO until it is 'full' (like malloc); faces with the same texture are put in the same VBO where possible [S5, unofficial]. Vertex indices for north, south, etc. faces are adjacent rather than mixed in the VBO [S5, unofficial]. Draw using `glDrawRangeElements` for specific face types (e.g., north faces) with normals already projected and normalized in a uniform, then draw south faces, etc., so normals are not in the VBO [S5, unofficial]. Cull interior faces when polygonizing each chunk [S5, unofficial]. Manage texture-atlas and sort faces by texture, putting faces with the same texture in the same VBO as those from other chunks to avoid too many texture changes [S5, unofficial]. Only polygonize chunks that have ever been visible; discard chunks that haven't been visible for a long time; re-polygonize chunks that are edited [S5, unofficial].

## Operating characteristics
*   **Time Complexity:** Allocation is $O(N)$ where $N$ is the number of free blocks in the free list. In practice, with efficient merging, $N$ is small. Deallocation is $O(N)$ for insertion and $O(M)$ for merging, where $M$ is the number of adjacent blocks. Upload is $O(F)$ where $F$ is the number of faces.
*   **Memory Complexity:** $O(MAX\_FACES)$ for the SSBO. The free list overhead is minimal.
*   **Performance:** Reduces GPU memory allocation overhead compared to per-chunk buffers [S3, unofficial]. Compaction is expensive and should be done sparingly [S3, unofficial].
*   **Strengths:** Efficient memory usage, supports dynamic chunk sizes, reduces driver overhead from many small buffer allocations [S3, unofficial].
*   **Limitations:** Fragmentation can lead to allocation failures if not managed [S3, unofficial]. Compaction requires data movement [S3, unofficial].
*   **When to use:** When chunk mesh sizes vary significantly and memory efficiency is critical [S3, unofficial].
*   **When not to use:** When chunks are static and sizes are predictable, per-chunk buffers may be simpler [S3, unofficial].

## Background
The method originates from implementations of voxel engines, particularly those inspired by Minecraft-like rendering [S1, S2, S3, unofficial]. The "MegaSSBO" approach is detailed in [adrienlabayle/VoxelEngine](https://github.com/adrienlabayle/VoxelEngine) [S3, unofficial]. The concept of grouping faces and managing VBOs for voxel rendering is discussed in early game development forums [S5, unofficial]. Vulkan implementations use similar storage buffer management [S4, unofficial].
