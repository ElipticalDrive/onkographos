# ChunkMesh Vertex Packing and Management

Also called: Block Face Culling, Cube Face Mesh Generation

## Overview
ChunkMesh Vertex Packing and Management is a dynamic mesh generation and buffer management technique for blocky voxel terrain, optimizing memory usage and draw calls by packing vertex attributes into compact integer formats and managing face visibility via block-type comparison [S1, unofficial]. It differs from static meshing methods by supporting incremental updates (add/remove blocks) that trigger immediate neighbor face adjustments, and from pure culling methods by actively managing the vertex buffer lifecycle through index reuse and compaction [S1, unofficial].

## How it works
**Inputs:**
- Block world data (type, chunk position, visibility flags: `isInvisible`, `isTranslucent`, `isTransparent`).
- Camera position and rotation (for alpha block sorting).
- Chunk dimensions (block size $n=16$).

**Outputs:**
- GPU vertex buffers (`vertex0`, `vertex1`) and index buffer (`indices`).

**Data Structures:**
- `vertex0`: `Uint32Array` storing packed position.
- `vertex1`: `Uint32Array` storing packed texture, texcoord, and lighting.
- `indices`: `Uint32Array` storing triangle indices.
- `vertexSlots`: Stack of reusable vertex indices (for compaction).
- `update`: Boolean flag triggering buffer upload.

**Packed Layout (32-bit unsigned integers):**
- `vertex0`:
  - Bits 0-9: X coordinate (10 bits).
  - Bits 10-19: Y coordinate (10 bits).
  - Bits 20-29: Z coordinate (10 bits).
  - Bits 30-31: Unused.
- `vertex1`:
  - Bits 0-9: Texture layer (10 bits).
  - Bits 10-14: Texcoord X (5 bits).
  - Bits 15-19: Texcoord Y (5 bits).
  - Bits 20-21: Shading/Lighting value (2 bits).
  - Bits 22-31: Unused.

**Steps:**

1. **Face Generation:**
   For a block at $(x, y, z)$ and direction $dir \in [0, 5]$ (positive x, negative x, positive y, negative y, positive z, negative z):
   - Calculate vertex positions using `cubeFacePosition(x, y, z, dir)` with block size $n=16$.
   - Calculate texture coordinates using `cubeFaceTexcoord(orientation)`, where `orientation` maps from `dir` via `[2, 3, 0, 0, 3, 2][dir]`.
   - Determine lighting value `dLight` using `[1, 1, 3, 0, 2, 2][dir]`.

2. **Vertex Addition:**
   - If a reusable index exists in `vertexSlots`, pop it; otherwise, use the current length of `vertex0`.
   - Pack position: `v0 = x | (y << 10) | (z << 20)`.
   - Pack attributes: `v1 = textureLayer | (texcoordX << 10) | (texcoordY << 15) | (dLight << 20)`.
   - Push `v0` and `v1` to `vertex0` and `vertex1` arrays.
   - Push triangle indices `(a, b, c, c, d, a)` to `indices`.
   - Set `update = true`.

3. **Face Removal:**
   - Search for the face in `vertex0` using `findFace(facePosition)`, which reconstructs packed positions and compares them, skipping `NaN` entries.
   - If found at index `i`:
     - Set `vertex0[i...i+3]` and `vertex1[i...i+3]` to `NaN`.
     - Remove the corresponding 6 indices from `indices` using `splice`.
     - Push `i` to `vertexSlots` for reuse.
     - Set `update = true`.

4. **Visibility Logic (Face Interaction):**
   For adjacent blocks `blockData0` (current) and `blockData1` (neighbor) in direction `dir`:
   - **Adding Face:** Add if neighbor is invisible/translucent/transparent AND block types differ.
   - **Removing Face:** Remove if neighbor is NOT invisible AND current block is NOT translucent/transparent OR block types are identical.
   - When updating neighbors, the neighbor's face direction is `dir + (dir % 2 === 0 ? 1 : -1)`.

5. **Buffer Update:**
   - If `update` is true, upload `vertex0`, `vertex1`, and `indices` to GPU buffers using `gl.DYNAMIC_DRAW`.
   - Reset `update` to false.

**Pseudocode:**

```python
def pack_vertex0(x, y, z):
    return x | (y << 10) | (z << 20)

def pack_vertex1(texture_layer, texcoord_x, texcoord_y, d_light):
    return texture_layer | (texcoord_x << 10) | (texcoord_y << 15) | (d_light << 20)

def unpack_vertex0(v0):
    x = v0 & 0x3FF
    y = (v0 >> 10) & 0x3FF
    z = v0 >> 20
    return x, y, z

def unpack_vertex1(v1):
    texture_layer = v1 & 0x3FF
    texcoord_x = ((v1 >> 10) & 0x1F) * 0.0625
    texcoord_y = ((v1 >> 15) & 0x1F) * 0.0625
    d_light = (v1 >> 20) * 0.2 + 0.4
    return texture_layer, texcoord_x, texcoord_y, d_light

def add_vertex(vertex0, vertex1, indices, vertex_slots, x, y, z, texture_layer, texcoord_x, texcoord_y, d_light):
    if vertex_slots:
        idx = vertex_slots.pop()
    else:
        idx = len(vertex0)
    
    v0 = pack_vertex0(x, y, z)
    v1 = pack_vertex1(texture_layer, texcoord_x, texcoord_y, d_light)
    
    vertex0.append(v0)
    vertex1.append(v1)
    return idx

def remove_face(vertex0, vertex1, indices, vertex_slots, face_positions):
    # face_positions is a list of 4 (x,y,z) tuples
    found_idx = -1
    for i in range(0, len(vertex0), 4):
        if math.isnan(vertex0[i]):
            continue
        v0_0 = pack_vertex0(*face_positions[0])
        v0_1 = pack_vertex0(*face_positions[1])
        v0_2 = pack_vertex0(*face_positions[2])
        v0_3 = pack_vertex0(*face_positions[3])
        
        if vertex0[i] == v0_0 and vertex0[i+1] == v0_1 and vertex0[i+2] == v0_2 and vertex0[i+3] == v0_3:
            found_idx = i
            break
            
    if found_idx == -1:
        return
        
    # Mark as removed
    for j in range(4):
        vertex0[found_idx + j] = float('nan')
        vertex1[found_idx + j] = float('nan')
        
    # Remove indices
    # Assuming indices are stored in groups of 6 for each face
    # Find the start of the face indices
    face_idx_start = -1
    for k in range(0, len(indices), 6):
        if indices[k] == found_idx:
            face_idx_start = k
            break
            
    if face_idx_start != -1:
        del indices[face_idx_start:face_idx_start+6]
        
    vertex_slots.append(found_idx)

def update_buffers(gl, vertex0, vertex1, indices, vao, vertex0_buffer, vertex1_buffer, index_buffer):
    gl.bindVertexArray(vao)
    
    gl.bindBuffer(gl.ARRAY_BUFFER, vertex0_buffer)
    gl.bufferData(gl.ARRAY_BUFFER, Uint32Array(vertex0), gl.DYNAMIC_DRAW)
    
    gl.bindBuffer(gl.ARRAY_BUFFER, vertex1_buffer)
    gl.bufferData(gl.ARRAY_BUFFER, Uint32Array(vertex1), gl.DYNAMIC_DRAW)
    
    gl.bindBuffer(gl.ELEMENT_ARRAY_BUFFER, index_buffer)
    gl.bufferData(gl.ELEMENT_ARRAY_BUFFER, Uint32Array(indices), gl.DYNAMIC_DRAW)
```

## Operating characteristics
- **Time Complexity:** Face addition/removal is $O(1)$ for buffer updates but $O(V)$ for face search if not indexed by position [S1, unofficial]. Buffer upload is $O(N)$ where $N$ is the number of vertices/indices.
- **Memory Complexity:** $O(V)$ for vertex data, where each vertex uses 8 bytes (two 32-bit integers) [S1, unofficial].
- **Performance:** Reduces memory bandwidth and VRAM usage by packing attributes. Dynamic updates allow for efficient incremental changes without full mesh regeneration [S1, unofficial].
- **Strengths:** Low memory footprint, supports dynamic terrain changes, efficient GPU buffer updates.
- **Limitations:** Face search can be slow without spatial indexing; precision limits for coordinate range (10 bits per axis).
- **When to Use:** Dynamic voxel worlds with frequent block changes.
- **When Not to Use:** Static worlds where precomputed meshes are more efficient; worlds with very large coordinate ranges exceeding 10-bit precision.

## Background
Originating from the Exolands project, this method was developed to handle dynamic voxel terrain efficiently [S1, unofficial]. It builds on the principles of face culling and blocky meshing, adapting them for real-time updates and compact data storage.
