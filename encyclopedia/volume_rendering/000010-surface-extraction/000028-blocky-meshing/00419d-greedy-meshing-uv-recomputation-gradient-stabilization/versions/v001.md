# Greedy Meshing UV Recomputation & Gradient Stabilization

Also called: Greedy UV tiling, Stable gradient sampling for greedy faces

## Overview
This method is a shader injection technique that recomputes UV coordinates and texture derivatives for faces generated by greedy meshing to ensure correct texture tiling and stable mipmapping across block boundaries [S1, unofficial]. It solves the problem of visual artifacts caused by discontinuous UV coordinates at the edges of merged quads, which lead to unstable mip level selection and visible seams in distant patterned textures [S1, unofficial]. It sets itself apart from vanilla rendering by explicitly computing smooth gradients per face orientation and routing greedy faces to specialized sampling functions, rather than relying on interpolated texture coordinates [S1, unofficial].

## How it works
The method operates as a fragment shader injection that intercepts rendering for greedy-meshed faces. It identifies these faces, reconstructs local UVs based on the block position and face orientation, clamps them to avoid border artifacts, and computes stable derivatives for mipmapping.

**Inputs and Outputs:**
*   **Inputs:**
    *   `v_GreedyFaceId`: Varying integer identifying the face type.
    *   `v_TexCoord`: Original interpolated texture coordinates (smooth).
    *   `v_BlockPos`: Varying block position (smooth).
    *   `sampler`: The texture sampler object.
    *   `u_TexelSize`: Uniform texture texel size (optional, for sampling).
*   **Outputs:**
    *   `_gm_TexCoord`: Corrected UV coordinates for sampling.
    *   `_gm_du`, `_gm_dv`: Stable screen-space derivatives.

**Data Structures:**
The method relies on specific ID ranges to identify greedy faces and map them to sprite sizes:
*   IDs 234–239: 64px sprites, face indices 0–5.
*   IDs 240–245: 32px sprites, face indices 0–5.
*   All other greedy IDs: 16px sprites, face indices 0–5.

**Numbered Steps:**

1.  **Identify Greedy Face:** Check if the current fragment belongs to a greedy-meshed face by verifying if `v_GreedyFaceId` falls within the range [234, 251] [S1, unofficial].
2.  **Determine Sprite Parameters:** Map the face ID to a sprite pixel size (`spritePixels`) and local face index (0–5) based on the ranges defined above [S1, unofficial].
3.  **Compute Sprite Space:** Calculate the sprite's texture space size and origin:
    $$ \text{spriteSize} = \frac{\text{spritePixels}}{\text{textureSize}(sampler, 0)} $$
    $$ \text{spriteOrigin} = v\_TexCoord - \text{spriteSize} \times 0.5 $$
    where `textureSize(sampler, 0)` returns the dimensions of the texture [S1, unofficial].
4.  **Calculate Local UVs:** Compute local UV coordinates based on the face index (0–5) using the fractional block position `v_BlockPos`. Let $f_x = \text{fract}(v\_BlockPos.x)$, $f_y = \text{fract}(v\_BlockPos.y)$, $f_z = \text{fract}(v\_BlockPos.z)$ [S1, unofficial]:
    *   Face 0: $(f_x, 1.0 - f_z)$
    *   Face 1: $(f_x, f_z)$ (Note: Source says `fract(v_BlockPos.xz)`, interpreted as x,z components)
    *   Face 2: $(1.0 - f_x, 1.0 - f_y)$
    *   Face 3: $(f_x, 1.0 - f_y)$
    *   Face 4: $(f_z, 1.0 - f_y)$
    *   Face 5: $(1.0 - f_z, 1.0 - f_y)$
    Let this result be `_gm_local` [S1, unofficial].
5.  **Compute Final UV:** Calculate the UV coordinate using the formula:
    $$ \text{uv} = \text{spriteOrigin} + \text{local} \times \text{spriteSize} $$
    [S1, unofficial]
6.  **Clamp UV:** Clamp the computed UV to the inner sprite region to avoid border sampling artifacts:
    $$ \text{uv} = \text{clamp}(\text{uv}, \text{spriteOrigin} + \text{halfTexel}, \text{spriteOrigin} + \text{spriteSize} - \text{halfTexel}) $$
    where $\text{halfTexel} = 0.5 / \text{textureSize}(sampler, 0)$ [S1, unofficial].
7.  **Compute Stable Derivatives:** Compute stable texture derivatives by taking screen-space gradients of the original smooth `v_TexCoord` or `v_BlockPos` components, scaled by the sprite size, instead of using the discontinuous fractured UVs [S1, unofficial].
8.  **Sample:** Route sampling using the corrected UV and derivatives. If greedy, use `sampleNearest` or `textureGrad` with the computed gradients; otherwise, use standard sampling [S1, unofficial].

**Pseudocode:**
```python
# Inputs: v_GreedyFaceId, v_TexCoord, v_BlockPos, sampler
# Outputs: _gm_TexCoord, _gm_du, _gm_dv

_gm_faceId = int(round(v_GreedyFaceId))
_gm_isGreedy = (234 <= _gm_faceId <= 251)

_gm_TexCoord = v_TexCoord

if _gm_isGreedy:
    # Determine sprite size and face index based on ID
    if 234 <= _gm_faceId <= 239:
        spritePixels = 64
        faceIndex = _gm_faceId - 234
    elif 240 <= _gm_faceId <= 245:
        spritePixels = 32
        faceIndex = _gm_faceId - 240
    else:
        spritePixels = 16
        faceIndex = _gm_faceId - 246 # Assuming other IDs map to 16px, index logic needs adjustment based on exact ID mapping
    
    # Get texture dimensions
    texWidth, texHeight = textureSize(sampler, 0)
    texSize = vec2(texWidth, texHeight)
    
    # Compute sprite size in texture space
    spriteSize = vec2(float(spritePixels) / texSize.x, float(spritePixels) / texSize.y)
    
    # Compute sprite origin
    spriteOrigin = v_TexCoord - spriteSize * 0.5
    
    # Compute fractional block position
    fx = fract(v_BlockPos.x)
    fy = fract(v_BlockPos.y)
    fz = fract(v_BlockPos.z)
    
    # Compute local UV based on face index
    if faceIndex == 0:
        local = vec2(fx, 1.0 - fz)
    elif faceIndex == 1:
        local = vec2(fx, fz) # Interpreting fract(v_BlockPos.xz)
    elif faceIndex == 2:
        local = vec2(1.0 - fx, 1.0 - fy)
    elif faceIndex == 3:
        local = vec2(fx, 1.0 - fy)
    elif faceIndex == 4:
        local = vec2(fz, 1.0 - fy)
    elif faceIndex == 5:
        local = vec2(1.0 - fz, 1.0 - fy)
    else:
        local = vec2(0.0, 0.0) # Fallback
    
    # Compute final UV
    uv = spriteOrigin + local * spriteSize
    
    # Clamp to avoid border artifacts
    halfTexel = 0.5 / texSize
    _gm_TexCoord = clamp(uv, spriteOrigin + halfTexel, spriteOrigin + spriteSize - halfTexel)

# Compute stable derivatives from smooth coordinates
_gm_du = dFdx(v_TexCoord)
_gm_dv = dFdy(v_TexCoord)

# Compute texel screen size for sampling
_gm_texelScreenSize = sqrt(_gm_du * _gm_du + _gm_dv * _gm_dv)

# Sampling logic (conceptual)

#     color = sampleNearest(sampler, _gm_TexCoord, u_TexelSize, _gm_du, _gm_dv, _gm_texelScreenSize)
# else:
#     color = sampleNearest(sampler, _gm_TexCoord, u_TexelSize)
```

**Parameters:**
*   Face ID ranges: 234–251 [S1, unofficial].
*   Sprite sizes: 64px, 32px, 16px [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Discontinuous UVs:** Fractured UVs (`fract(v_BlockPos.*)`) cause discontinuities at block boundaries, leading to unstable mip level selection for distant patterned textures. This is solved by computing derivatives from smooth `v_TexCoord` or `v_BlockPos` directly [S1, unofficial].
*   **Vertex Color Alpha:** Vertex color alpha is repurposed as a face marker in some shader paths. This is solved by routing main's uses through a corrected copy (`_gm_VertexColor`) with alpha forced to 1.0 for greedy faces, preserving cutout discard behavior [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The UV recomputation is performed per fragment, adding a small constant overhead to the fragment shader execution. The derivative computation is also per-fragment.
*   **Memory Complexity:** No additional memory structures are required beyond the existing varying variables and uniforms.
*   **Performance:** The method is implemented in the `GreedyMeshing` mod for Minecraft, targeting Sodium renderer compatibility and VulkanMod debug rendering [S1, unofficial]. It improves visual quality by eliminating mipmapping artifacts without significant performance cost, as the calculations are simple arithmetic operations.
*   **Strengths:** Eliminates visible seams and mipmapping instability on greedy-meshed faces. Compatible with existing greedy meshing pipelines.
*   **Limitations:** Requires specific varying variables (`v_GreedyFaceId`, `v_BlockPos`) to be passed to the shader. Relies on specific ID ranges for face identification.

## Background
This method is part of the `GreedyMeshing` mod (package `hi.sierra.greedy_meshing`) for Minecraft [S1, unofficial]. It addresses issues arising from the vanilla and Sodium stock samplers, which compute derivatives from interpolated texture coordinates, causing instability [S1, unofficial]. The technique is specifically designed for compatibility with the Sodium renderer and VulkanMod debug rendering [S1, unofficial].
