# GPU Face Extraction

Also called: GPU Face Mesher, Persistent Face Mesher

## Overview
GPU Face Extraction is a compute-shader-based algorithm that extracts visible faces from a voxel subchunk and outputs packed quads to a persistent buffer, handling transparency and water occlusion rules [S1, unofficial]. It avoids per-frame meshing by keeping generated descriptors resident until the subchunk becomes dirty again [S1, unofficial]. Unlike [Blocky meshing](31-blocky-meshing.md) which may use CPU-side culling or greedy merging, this method performs the visibility check and quad generation entirely on the GPU using atomic operations for buffer management [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A padded 18³ voxel cache (16³ subchunk + 1-voxel border) containing block IDs [S1, unofficial].
- **Output:** A buffer of `PackedQuad` structures representing exposed faces, and metadata in `SubchunkMeta` storing the total vertex count [S1, unofficial].

**Data Structures:**
1.  **Voxel Buffer:** `u32` array of size $18^3 = 5832$ elements. Index mapping: `voxel_index(x, y, z) = x * 324 + y * 18 + z` [S1, unofficial].
2.  **PackedQuad:** 16-byte struct (4 `u32` fields) [S1, unofficial]:
    -   `origin_and_face` (u32): Packs `ox` (6 bits), `oy` (6 bits), `oz` (6 bits), `face` (6 bits) [S1, unofficial].
        -   $ox = (x-1)*2 + (face==1?2:0)$
        -   $oy = (y-1)*2 + (face==3?2:0)$
        -   $oz = (z-1)*2 + (face==5?2:0)$
        -   Packing: `ox | (oy << 6) | (oz << 12) | (face << 18)` [S1, unofficial].
    -   `size_material_ao` (u32): Packs `AO` (5 bits), `material_index` (8 bits), `tex` (8 bits), `padding` (11 bits) [S1, unofficial].
        -   Packing: `1 | (1 << 5) | (tex(block, face) << 10) | (0xff << 18)` [S1, unofficial].
    -   `color_flags` (u32): Result of `color(face)` [S1, unofficial].
    -   `reserved` (u32): Padding [S1, unofficial].
3.  **SubchunkMeta:** Struct `{ world_origin: vec4<i32>, draw_data: vec4<u32> }`. `draw_data.x` stores `count * 6` (total vertices) [S1, unofficial].
4.  **FaceExtractUniforms:** Struct `{ output_quad_offset: u32, quad_capacity: u32, subchunk_slot: u32, _padding: u32 }` [S1, unofficial].
5.  **Face Counter:** Single `u32` atomic counter [S1, unofficial].

**Steps:**
1.  **Upload Voxel IDs:** Convert the snapshot block cache to IDs via `block_id()`, cast to `u32` slice, and write to `voxel_buffer` at offset 0 [S1, unofficial].
2.  **Reset Face Counter:** Write `0u32` to `face_counter` buffer at offset 0 [S1, unofficial].
3.  **Set Uniforms:** Populate `FaceExtractUniforms` with `allocation.quad_offset`, `allocation.quad_capacity`, `allocation.subchunk_slot`, and 0 padding. Write to uniforms buffer [S1, unofficial].
4.  **Create Bind Group:** Bind `voxel_buffer` to slot 0, `quad_buffer` to 1, `subchunk_meta_buffer` to 2, `face_counter` to 3, `uniforms` to 4 [S1, unofficial].
5.  **Dispatch `extract_faces`:** Launch compute shader with 64 workgroups (64x1x1 threads). Each thread processes one voxel in the 16x16x16 subchunk (4096 voxels total) [S1, unofficial].
    -   For each voxel, iterate faces 0-5.
    -   Check visibility against neighbor.
    -   If visible, atomically increment `face_counter`.
    -   If `atomicAdd` returns value `< quad_capacity`, write `PackedQuad` to `quad_buffer` at `output_quad_offset + result` [S1, unofficial].
6.  **Dispatch `finalize_faces`:** Launch compute shader with 1 workgroup (1x1x1 thread). Read the atomic face counter and update `subchunk_meta_buffer.draw_data.x` with `count * 6` [S1, unofficial].

**Pseudocode:**
```python
# Compute Shader: extract_faces
# Thread ID (0..4095) maps to voxel (x, y, z) in 16x16x16 grid
thread_id = get_thread_id()
x = thread_id % 16
y = (thread_id // 16) % 16
z = thread_id // 256

# Load voxel ID from padded buffer
voxel_id = voxel_buffer[voxel_index(x + 1, y + 1, z + 1)]

# Skip empty voxels
if voxel_id == 0:
    return

# Iterate 6 faces
for face in 0..5:
    # Determine neighbor coordinates based on face normal
    # Face 0: -X, Face 1: +X, Face 2: -Y, Face 3: +Y, Face 4: -Z, Face 5: +Z
    nx = x + (face == 1 ? 1 : (face == 0 ? -1 : 0))
    ny = y + (face == 3 ? 1 : (face == 2 ? -1 : 0))
    nz = z + (face == 5 ? 1 : (face == 4 ? -1 : 0))
    
    # Check neighbor visibility rules
    neighbor_id = voxel_buffer[voxel_index(nx + 1, ny + 1, nz + 1)]
    
    if not should_render_face_against(voxel_id, neighbor_id, face):
        continue
        
    # Calculate quad position
    ox = (x - 1) * 2 + (face == 1 ? 2 : 0)
    oy = (y - 1) * 2 + (face == 3 ? 2 : 0)
    oz = (z - 1) * 2 + (face == 5 ? 2 : 0)
    
    # Pack quad data
    origin_and_face = ox | (oy << 6) | (oz << 12) | (face << 18)
    size_material_ao = 1 | (1 << 5) | (tex(voxel_id, face) << 10) | (0xff << 18)
    color_flags = color(face)
    
    # Atomic buffer management
    index = atomic_add(face_counter, 1)
    
    # Guard against buffer overflow
    if index < quad_capacity:
        quad_buffer[output_quad_offset + index] = PackedQuad(origin_and_face, size_material_ao, color_flags, 0)

# Compute Shader: finalize_faces
count = load(face_counter)
subchunk_meta.draw_data.x = count * 6
```

**Parameters:**
-   `PADDED_SIDE`: 18 [S1, unofficial].
-   `PADDED_VOXEL_COUNT`: 5832 [S1, unofficial].
-   `quad_capacity`: Configurable via uniforms [S1, unofficial].

**Edge Cases and Pitfalls:**
-   **Buffer Overflow:** If `atomicAdd` returns a value $\ge$ `quad_capacity`, the quad is not emitted [S1, unofficial].
-   **Water Occlusion:** Water blocks (`block==5`) are never visible if the neighbor is not water [S1, unofficial].
-   **Leaf Occlusion:** Leaves (`block==7`) are only visible if the neighbor is also leaves [S1, unofficial].
-   **Unsupported Blocks:** Only supports full terrain cubes. Water, DeadBush, and WoodStairs are excluded and retain CPU meshing [S1, unofficial].

## Subtopics

### [Validator Reference Face Reconstruction](3794-validator-reference-face-reconstruction.md)
A validation method that reconstructs expected faces from a `MeshData` structure to verify correctness. It iterates face 0-5, decodes packed quad data (`q`) into components (`a, b, c, w, h, material`), and maps them to axis/positive coordinates via `add_rect` to build a sorted reference list of faces.

### Face Orientation Consistency
A post-processing step that flips faces so that orientation among touching faces is consistent across connected components. It uses BFS/DFS to identify components, checks shared vertices, and flips faces if the normal sum X component is negative for the component's farthest face [S3, unofficial].

### Chunk Face Extraction
Extracts the 6 boundary faces of a chunk into `ChunkFace` structures. It iterates over all 6 directions, calculates block positions on the face, and maps block IDs to visibility types, storing them in a flat array `[VoxelBlock; CHUNK_FACE_VOLUME]` [S4, unofficial].

## Operating characteristics
-   **Time Complexity:** $O(N)$ where $N$ is the number of voxels in the subchunk (4096 for 16³). Each voxel is processed by one thread [S1, unofficial].
-   **Memory Complexity:** $O(F)$ where $F$ is the number of visible faces. The output buffer size is determined by `quad_capacity` [S1, unofficial].
-   **Performance:** Real-time mesh generation on GPU using wgpu and WGSL shaders [S1, unofficial].
-   **Strengths:** Avoids CPU-GPU synchronization for mesh generation; persistent buffers reduce overhead for unchanged subchunks [S1, unofficial].
-   **Limitations:** Does not support all block types (e.g., Water, Stairs) requiring CPU fallback [S1, unofficial]. Buffer overflow requires careful capacity management [S1, unofficial].

## Background
GPU Face Extraction is used in the Minerust project for real-time voxel mesh generation on GPU using wgpu and WGSL shaders [S1, unofficial]. It is part of the blocky meshing family, building on [Blocky meshing](31-blocky-meshing.md) principles of face culling and greedy meshing [S1, unofficial].
