# Voxel Backface Culling and Internal Face Masking

Also called: Internal Face Masking, Voxel Backface Culling

## Overview
This method optimizes voxel mesh generation by rejecting invisible faces in projection space and masking faces shared between neighboring voxels. It distinguishes itself from sibling methods like [Greedy Meshing](1776-greedy-meshing.md) by performing visibility culling per-voxel during geometry generation rather than post-processing a full mesh, and from [Blocky meshing](31-blocky-meshing.md) by explicitly handling front/back orientation relative to the camera to avoid rendering internal surfaces.

## How it works
The method operates within a geometry shader or similar stage, processing voxels defined by their corner positions and a compact encoding of their visibility state.

### Inputs and Outputs
*   **Input**: A voxel defined by its 8 corner positions ($c_{vCorner000}$ to $c_{vCorner111}$), a view direction vector ($v_{ViewDirection}$), a projection matrix ($mProjection$), and a 32-bit voxel code integer ($vs\_out\_VoxelCode[0]$).
*   **Output**: Vertex streams for the front or back face of the voxel, if visible.

### Data Structures
The voxel code is a 32-bit integer encoding invisible masking and position:
*   **Bits 0-5**: Mask for each of the 6 sides (1 bit per side).
*   **Bits 6-31**: Position coordinates (3 * 8 bits for x, y, z).
*   **Bits 32-33**: Unused.
This layout allows addressing $256^3$ positions [S1, unofficial].

### Steps
1.  **Projection Space Transformation**: Transform the direction in projection space to view space using the inverse diagonal of the projection matrix:
    $$ v_{view} = v_{proj} * (1/mProjection[0][0], 1/mProjection[1][1], 1/mProjection[2][2]) $$
    [S1, unofficial]

2.  **Front/Back Decision**: Calculate the dot product of the sum of two voxel corners (transformed by the inverse projection diagonal) and the view direction:
    $$ \text{dot}((c_{vCorner000}.xyz + c_{vCorner110}.xyz) * c_{vInverseProjection}.xyz, v_{ViewDirection}) $$
    [S1, unofficial]

3.  **Face Selection and Masking**:
    *   If the dot product is greater than 0, process the **front face**. Check if the voxel code bit `0x10` is set in $vs\_out\_VoxelCode[0]$. If set, emit the front face vertices ($c_{vCorner000}, c_{vCorner100}, c_{vCorner010}, c_{vCorner110}$) and compute lighting with normal $(0,0,-1)$ transformed by the world-view matrix.
    *   Otherwise, process the **back face**. Check if the voxel code bit `0x20` is set in $vs\_out\_VoxelCode[0]$. If set, emit the back face vertices ($c_{vCorner011}, c_{vCorner111}, c_{vCorner001}, c_{vCorner101}$) and compute lighting with normal $(0,0,1)$ transformed by the world-view matrix.
    [S1, unofficial]

### Pseudocode
```python
def process_voxel(c_vCorner000, c_vCorner110, vs_out_VoxelCode, vViewDirection, mProjection, c_mWorldView):
    # Step 1: Transform projection direction to view space
    # Assuming c_vInverseProjection is precomputed as (1/mProjection[0][0], 1/mProjection[1][1], 1/mProjection[2][2])
    c_vInverseProjection = vec3(1.0 / mProjection[0][0], 1.0 / mProjection[1][1], 1.0 / mProjection[2][2])
    
    # Step 2: Calculate dot product for front/back decision
    sum_corners = c_vCorner000.xyz + c_vCorner110.xyz
    dot_product = dot(sum_corners * c_vInverseProjection.xyz, vViewDirection)
    
    if dot_product > 0:
        # Front face logic
        # Check if bit 0x10 is set
        if (vs_out_VoxelCode[0] & 0x10) != 0:
            # Emit front face vertices
            emit_vertex(c_vCorner000)
            emit_vertex(c_vCorner100)
            emit_vertex(c_vCorner010)
            emit_vertex(c_vCorner110)
            # Compute lighting with normal (0,0,-1) transformed by world-view matrix
            vNormal = normalize((vec4(0, 0, -1, 0) * c_mWorldView).xyz)
            gs_color = compute_lighting(vNormal, vViewDirection)
    else:
        # Back face logic
        # Check if bit 0x20 is set
        if (vs_out_VoxelCode[0] & 0x20) != 0:
            # Emit back face vertices
            emit_vertex(c_vCorner011)
            emit_vertex(c_vCorner111)
            emit_vertex(c_vCorner001)
            emit_vertex(c_vCorner101)
            # Compute lighting with normal (0,0,1) transformed by world-view matrix
            vNormal = normalize((vec4(0, 0, 1, 0) * c_mWorldView).xyz)
            gs_color = compute_lighting(vNormal, vViewDirection)
```

### Parameters
*   **Chunk Size**: 32^3 voxels per chunk. This size is used for efficient memory management, LOD, and large-scale culling algorithms [S1, unofficial].

### Edge Cases and Pitfalls
*   **Shared Faces**: Shared faces between two neighboring voxels are never visible. The masking bits (0x10 and 0x20) are used to reject these invisible internal faces [S1, unofficial].
*   **Projection Space Limitations**: Direct backface culling in projection space is not straightforward; the method relies on transforming the direction to view space [S1, unofficial].

## Operating characteristics
*   **Performance**: On a Geforce 640M LE, the method draws 32,368 voxels per millisecond [S1, unofficial].
*   **Complexity**: The method adds computational overhead per voxel due to the dot product calculation and bit masking, but reduces the total number of primitives emitted by culling internal and back-facing faces.
*   **Scaling**: The chunked approach (32^3 voxels) allows for efficient memory management and large-scale culling, making it suitable for large models [S1, unofficial].
*   **Strengths**: Effective reduction of primitive count by rejecting internal and back-facing faces.
*   **Limitations**: Geometry shaders can be slow if the amount of data increases significantly [S1, unofficial].

## Background
The method was described by Johannes Jendersie in a blog post on his developer blog. It was developed as part of a voxel rendering system, aiming to optimize performance by reducing the number of rendered primitives. The approach was tested on a Geforce 640M LE graphics card [S1, unofficial].
