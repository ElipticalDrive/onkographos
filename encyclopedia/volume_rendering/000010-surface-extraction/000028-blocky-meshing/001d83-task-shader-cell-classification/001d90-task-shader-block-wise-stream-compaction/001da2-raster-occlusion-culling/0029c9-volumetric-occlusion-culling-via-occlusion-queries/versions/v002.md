# Volumetric Occlusion Culling via Occlusion Queries

Also called: Ray-based occlusion culling, Visibility detection using occlusion queries

## Overview
A visibility detection method that determines if a voxel block is visible (not fully occluded by closer voxels) by rasterizing its bounding box and checking for fragment depth test passes [S1, unofficial]. It differs from standard binary occlusion culling by incorporating accumulated opacity into the depth test, ensuring that blocks behind fully opaque foreground volumes are correctly culled [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A voxel block to test, defined by its axis-aligned bounding box; the current ray-marched depth buffer containing the depth at which maximum opacity was reached for each pixel; camera projection and view matrices [S1, unofficial].
*   **Output:** A boolean visibility flag for the block, or a fragment count used for priority-based loading [S1, unofficial].

**Data Structures**
*   **Depth Buffer:** A 2D render target storing floating-point depth values [S1, unofficial]. Each pixel $(u, v)$ stores $D_{opacity}$, the depth along the view ray where accumulated opacity reached a threshold (typically 1.0), or 1.0 (maximum depth) if the ray did not reach full opacity [S1, unofficial].
*   **Bounding Box Geometry:** A triangulated mesh representing the axis-aligned bounding box of the voxel block [S1, unofficial].

**Steps**
1.  **Prepare Depth Buffer:** During the ray marching pass, for each ray, write the depth $D_{opacity}$ at which the ray reaches total opacity to the framebuffer [S1, unofficial]. If the ray does not reach total opacity within the volume, write the maximum depth value (e.g., 1.0 in normalized device coordinates or the far plane distance) [S1, unofficial].
2.  **Initialize Occlusion Query:** Begin an asynchronous GPU occlusion query [S1, unofficial].
3.  **Rasterize Bounding Box:** Rasterize the triangulated bounding box of the voxel block without performing actual ray tracing [S1, unofficial].
4.  **Depth Test:** For each fragment generated by the bounding box, compare its depth against the prepared depth buffer [S1, unofficial].
5.  **Interrogate Result:** Check if the occlusion query is complete [S1, unofficial]. If the test has not finished, the CPU thread synchronizes and waits for the GPU to finish the rasterization and query execution [S1, unofficial].
6.  **Determine Visibility:** Retrieve the number of fragments that passed the depth test [S1, unofficial]. If the count meets or exceeds the configured fragment threshold, the block is considered visible and scheduled for loading [S1, unofficial].

**Formulas**
Let $D_{opacity}$ be the depth value stored in the framebuffer for a given pixel, representing the depth at which the ray reached total opacity. Let $D_{voxel}$ be the depth of the fragment generated by the voxel block's bounding box at that pixel.

The visibility condition for a specific ray/pixel is:
$$ D_{voxel} < D_{opacity} $$

If $D_{voxel} \ge D_{opacity}$, the voxel is occluded by foreground matter that has already reached full opacity [S1, unofficial]. If $D_{voxel} < D_{opacity}$, the voxel is visible [S1, unofficial].

For the entire block, the block is visible if:
$$ \text{fragment\_count} \ge \text{FragmentThreshold} $$

**Parameters**
*   **Fragment Threshold:** The minimum number of fragments required to trigger block loading [S1, unofficial]. This value can be adjusted based on system load to prioritize the most visible blocks [S1, unofficial].

**Pitfalls and Edge Cases**
*   **Projection Alignment:** Requires perfect alignment between the OpenGL projection/viewpoint and the ray tracing projection/viewpoint to ensure correct visibility detection [S1, unofficial].
*   **Asynchronicity and Scheduling:** Occlusion queries are executed asynchronously by the GPU, allowing the CPU to continue immediately after initialization [S1, unofficial]. The visibility test must be anticipated before tracing, but too much anticipation ignores unrendered foreground matter that might occlude the block [S1, unofficial]. Scheduling must overlap query times with loading times of already detected visible blocks to hide latency [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources. The rasterization cost is proportional to the surface area of the bounding box in screen space [S1, unofficial].
*   **Memory Complexity:** Not given in the sources. Requires a depth buffer compatible with the ray marching pass [S1, unofficial].
*   **Strengths:** Efficiently culls blocks behind fully opaque volumes using standard GPU hardware occlusion queries [S1, unofficial].
*   **Limitations:** Sensitive to projection mismatches. Requires careful scheduling to handle asynchronous query results and avoid stalling the CPU [S1, unofficial].

## Background
This method is described in the context of interactive exploration of extended and detailed procedural volumes [S1, unofficial]. It adapts standard hardware occlusion queries to the specific requirements of volumetric rendering, where visibility depends on accumulated opacity rather than simple geometric occlusion [S1, unofficial].
