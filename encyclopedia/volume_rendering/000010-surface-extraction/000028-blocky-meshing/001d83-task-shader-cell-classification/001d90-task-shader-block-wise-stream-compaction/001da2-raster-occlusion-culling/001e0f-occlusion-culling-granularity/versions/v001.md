# Occlusion Culling Granularity

Also called: Block-Based Occlusion Culling Granularity

## Overview
This method defines the spatial resolution at which visibility is determined during the raster occlusion culling phase of volume rendering. It solves the problem of aligning the culling proxy geometry with the underlying data structures to ensure fair performance comparisons against ray-marching baselines. It is distinguished from generic occlusion culling by its strict adherence to the leaf-level granularity of the reference octree, ensuring that the culling unit matches the semantic blocks of the volume data.

## How it works
The method configures the raster occlusion culling pass to operate on specific spatial regions. The core logic involves mapping the culling block size to the extraction block size to determine the necessary shader workgroup launches.

**Inputs and Outputs:**
*   **Input:** The potentially visible regions identified by the previous stream compaction stage.
*   **Output:** A list of occupied subvolumes (blocks) that pass the occlusion test.

**Data Structures:**
*   **Culling Block:** A 3D region of cells defined by the granularity parameter.
*   **Extraction Block:** The unit of geometry extraction, defined by the extraction stage parameters.

**Parameters:**
*   **Culling Granularity:** The size of the region used for occlusion testing.
    *   *Value:* $8 \times 8 \times 8$ cells [S2, unofficial].
*   **Extraction Block Size:** The size of the block processed by the extraction stage.
    *   *Value:* $8 \times 8 \times 4$ cells [S2, unofficial].
*   **Workgroups per Region:** The number of task shader workgroups launched for each potentially visible region.
    *   *Value:* 2 [S2, unofficial].

**Steps:**
1.  **Determine Culling Region Size:** Set the occlusion culling granularity to match the leaf-level of the ray-marching reference octree. This ensures a fair comparison between the rasterization-based approach and the reference [S2, unofficial].
    *   *Formula:* $W_{cull} = 8, H_{cull} = 8, D_{cull} = 8$ cells.
2.  **Identify Extraction Block Size:** Retrieve the block size used by the geometry extraction stage.
    *   *Formula:* $W_{ext} = 8, H_{ext} = 8, D_{ext} = 4$ cells.
3.  **Calculate Workgroup Launch Count:** Determine how many task shader workgroups are required to cover the culling region. Since the extraction stage operates on blocks of $8 \times 8 \times 4$ cells, and the culling region is $8 \times 8 \times 8$ cells, the depth dimension requires two extraction blocks to cover the full culling depth.
    *   *Calculation:* $\frac{D_{cull}}{D_{ext}} = \frac{8}{4} = 2$.
4.  **Launch Task Shaders:** For each potentially visible region, launch exactly two task shader workgroups [S1][S2, unofficial]. These workgroups process the geometry corresponding to the two $8 \times 8 \times 4$ extraction blocks that compose the single $8 \times 8 \times 8$ culling block.

**Pseudocode:**
```python
def configure_occlusion_culling_granularity():
    # Define culling granularity to match ray-marching reference leaf level
    culling_block_size = (8, 8, 8)  # cells
    
    # Define extraction stage block size
    extraction_block_size = (8, 8, 4)  # cells
    
    # Calculate number of extraction blocks needed to cover culling block
    # Assuming alignment along the depth (Z) axis as per source description
    num_extraction_blocks = culling_block_size[2] // extraction_block_size[2]
    
    # Verify calculation matches source specification
    assert num_extraction_blocks == 2, "Expected 2 workgroups per region"
    
    return num_extraction_blocks

def launch_culling_workgroups(region):
    """
    Launches the necessary task shader workgroups for a single potentially visible region.
    """
    num_workgroups = configure_occlusion_culling_granularity()
    
    # Launch two task shader workgroups for the region
    # Each workgroup handles one 8x8x4 extraction block
    for i in range(num_workgroups):
        launch_task_shader_workgroup(region, block_index=i)
```

**Edge Cases and Pitfalls:**
*   **Misalignment:** If the extraction block size does not divide evenly into the culling block size, the workgroup launch count calculation will fail or require padding. The sources specify exact integer division ($8/4=2$), implying strict alignment [S2, unofficial].
*   **Comparison Fairness:** Deviating from the $8 \times 8 \times 8$ granularity breaks the fair comparison with the ray-marching reference, as the culling efficiency would no longer be directly comparable to the reference's leaf-level traversal [S2, unofficial].

## Subtopics

### Block-Based Occlusion Culling Granularity
This variant explicitly defines the configuration where culling granularity aligns with the leaf-level of the ray-marching reference octree. It is chosen when a fair performance comparison between the rasterization-based approach and the ray-marching reference is required [S2, unofficial]. The key characteristic is the use of $8 \times 8 \times 8$ cell regions for culling, necessitating the launch of two task shader workgroups per region to cover the $8 \times 8 \times 4$ extraction blocks [S2, unofficial].

## Operating characteristics
*   **Complexity:** The complexity is determined by the number of potentially visible regions and the fixed cost of launching two workgroups per region. The culling block size ($8 \times 8 \times 8$) is constant.
*   **Performance:** This granularity allows for a direct comparison with the ray-marching reference, which operates on the same leaf-level granularity [S2, unofficial]. The efficiency of the culling pass is tied to the efficiency of the forward mesh renderer for an optimized mesh, which serves as the baseline for "infinitely fast indirect isosurface extraction" comparisons [S1][S2, unofficial].
*   **Limitations:** The granularity is fixed to the reference octree's leaf level. It may not be optimal for all scene structures if the reference octree is not the most efficient representation for the specific hardware or data distribution.

## Background
This method originates from the research on "Efficient Direct Isosurface Rasterization of Scalar Volumes" [S1][S2, unofficial]. It was developed to provide a fair benchmark for the proposed rasterization-based approach by aligning its occlusion culling parameters with a ray-marching reference implementation. The specific granularity of $8 \times 8 \times 8$ cells was chosen to match the leaf-level of the octree used in the ray-marching reference [S2, unofficial].
