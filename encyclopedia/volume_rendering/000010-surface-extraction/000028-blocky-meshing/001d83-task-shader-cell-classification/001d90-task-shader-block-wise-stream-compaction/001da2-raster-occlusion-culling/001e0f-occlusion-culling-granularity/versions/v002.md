# Occlusion Culling Granularity

Also called: Block-Based Occlusion Culling Granularity

## Overview
This method configures the spatial resolution for raster occlusion culling to match the leaf-level granularity of a reference ray-marching octree [S2, unofficial]. It ensures that the culling proxy geometry aligns with the underlying extraction data structures for direct performance comparison [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Potentially visible regions identified by the previous stream compaction stage [S2, unofficial].
*   **Output:** A dense list of occupied subvolumes that pass the occlusion test [S2, unofficial].

**Data Structures:**
*   **Culling Block:** A 3D region of cells used for occlusion testing, sized $8 \times 8 \times 8$ cells [S2, unofficial].
*   **Extraction Block:** The unit of geometry extraction processed by the task shader, sized $8 \times 8 \times 4$ cells [S2, unofficial].

**Parameters:**
*   **Culling Granularity:** The size of the region used for occlusion testing, set to $8 \times 8 \times 8$ cells [S2, unofficial].
*   **Extraction Block Size:** The size of the block processed by the extraction stage, set to $8 \times 8 \times 4$ cells [S2, unofficial].
*   **Workgroups per Region:** The number of task shader workgroups launched for each potentially visible region, set to 2 [S2, unofficial].

**Steps:**
1.  **Determine Culling Region Size:** Set the occlusion culling granularity to match the leaf-level of the ray-marching reference octree, specifically regions comprised of $8 \times 8 \times 8$ cells [S2, unofficial].
2.  **Identify Extraction Block Size:** Retrieve the block size used by the geometry extraction stage, which operates on $8 \times 8 \times 4$ cells [S2, unofficial].
3.  **Calculate Workgroup Launch Count:** Determine how many task shader workgroups are required to cover the culling region along the depth axis: $\lceil D_{\text{cull}} / D_{\text{ext}} \rceil = \lceil 8 / 4 \rceil = 2$ [S2, unofficial].
4.  **Launch Task Shaders:** For each potentially visible region, launch exactly two task shader workgroups to process the geometry corresponding to the two $8 \times 8 \times 4$ extraction blocks that compose the single $8 \times 8 \times 8$ culling block [S1][S2, unofficial].

**Pseudocode:**
```python
def configure_occlusion_culling_granularity():
    culling_block_size = (8, 8, 8)  # cells
    extraction_block_size = (8, 8, 4)  # cells
    num_workgroups = (culling_block_size[2] + extraction_block_size[2] - 1) // extraction_block_size[2]
    return num_workgroups

def dispatch_compute(group_count_x, group_count_y, group_count_z):
    # Standard GPU compute dispatch operation
    pass  # [G] Hardware dispatch call

def dispatch_culling_workgroups(region):
    num_workgroups = configure_occlusion_culling_granularity()
    for block_idx in range(num_workgroups):
        # Launch task shader workgroup for extraction block index
        # Each workgroup processes one 8x8x4 cell block
        # within the 8x8x8 culling region
        dispatch_compute(1, 1, 1)
```

**Edge Cases and Pitfalls:**
*   **Comparison Fairness:** Deviating from the $8 \times 8 \times 8$ granularity breaks the fair comparison with the ray-marching reference, as the culling efficiency would no longer be directly comparable to the reference's leaf-level traversal [S2, unofficial].

## Subtopics

### Block-Based Occlusion Culling Granularity
This variant explicitly defines the configuration where culling granularity aligns with the leaf-level of the ray-marching reference octree [S2, unofficial]. It is chosen when a fair performance comparison between the rasterization-based approach and the ray-marching reference is required [S2, unofficial]. The key characteristic is the use of $8 \times 8 \times 8$ cell regions for culling, necessitating the launch of two task shader workgroups per region to cover the $8 \times 8 \times 4$ extraction blocks [S2, unofficial].

## Operating characteristics
*   **Complexity:** The complexity is determined by the number of potentially visible regions and the fixed cost of launching two workgroups per region [S2, unofficial].
*   **Performance:** This granularity allows for a direct comparison with the ray-marching reference, which operates on the same leaf-level granularity [S2, unofficial].
*   **Limitations:** The granularity is fixed to the reference octree's leaf level [S2, unofficial].

## Background
This method originates from research on efficient direct isosurface rasterization of scalar volumes [S1][S2, unofficial]. It was developed to provide a fair benchmark for the proposed rasterization-based approach by aligning its occlusion culling parameters with a ray-marching reference implementation [S2, unofficial]. The specific granularity of $8 \times 8 \times 8$ cells was chosen to match the leaf-level of the octree used in the ray-marching reference [S2, unofficial].
