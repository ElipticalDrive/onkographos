# GPU-driven Visibility Culling

Also called: Indirect draw culling, Per-subchunk culling

## Overview
GPU-driven visibility culling is a culling technique that uses per-subchunk metadata (AABBs, terrain/water draw ranges) to test visibility on the GPU and emit indirect draw commands only for visible subchunks [S1, unofficial]. It reduces the number of task shader workgroups launched by avoiding geometry extraction for blocks not visible in the display [S1, unofficial]. It builds on [Task Shader Block-wise Stream Compaction](1540-task-shader-block-wise-stream-compaction.md) by utilizing the metadata prepared there to drive the compute dispatch and indirect execution [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A buffer containing per-subchunk metadata, specifically Axis-Aligned Bounding Boxes (AABBs) and draw ranges for terrain and water elements [S1, unofficial].
*   **Output:** A buffer of indirect draw commands corresponding only to subchunks that pass the visibility test [S1, unofficial].

**Data Structures:**
*   **Subchunk Metadata Buffer:** Contains AABBs (typically 6 floats: min/max x, y, z) and draw range information [G].
*   **Indirect Draw Command Buffer:** Stores the arguments for indirect draw calls [G]. Each entry typically contains: `vertex_count` (uint32), `instance_count` (uint32), `first_vertex` (uint32), `first_instance` (uint32) [G].

**Steps:**
1.  **Visibility Test:** Test the AABB of each subchunk against the view frustum or camera position [S1, unofficial].
2.  **Emit Commands:** Emit indirect draw commands only for subchunks that pass the visibility test [S1, unofficial].
3.  **Dispatch:** Execute the draw calls using the indirect command buffer [G].

**Parameters:**
*   **MULTI_DRAW_INDIRECT_COUNT:** A GPU feature that allows the GPU to control how many indirect draw commands are executed, enabling dynamic draw counts [S1, unofficial].

**Pseudocode:**
```python
def cull_subchunks(subchunk_data, frustum_planes, camera_pos, output_commands, command_count):
    """
    Compute shader equivalent: filters subchunks based on frustum/camera visibility
    and writes indirect draw commands to the output buffer.
    command_count is a mutable list acting as a shared counter across threads [G].
    """
    for i in range(len(subchunk_data)):
        aabb_min = subchunk_data[i].aabb_min
        aabb_max = subchunk_data[i].aabb_max
        draw_offset = subchunk_data[i].draw_offset
        draw_count = subchunk_data[i].draw_count

        if is_aabb_visible(aabb_min, aabb_max, frustum_planes, camera_pos):
            cmd_idx = command_count[0]
            command_count[0] += 1
            output_commands[cmd_idx] = {
                'vertex_count': draw_count,
                'instance_count': 1,
                'first_vertex': draw_offset,
                'first_instance': 0
            }

def is_aabb_visible(aabb_min, aabb_max, frustum_planes, camera_pos):
    """
    Checks if an AABB is inside the view frustum or in front of the camera.
    Uses standard half-space tests for frustum planes and a simple depth check [G].
    """
    # Check against each frustum plane (left, right, bottom, top, far)
    for plane in frustum_planes:
        # Plane equation: Ax + By + Cz + D <= 0 for inside
        # Quick rejection: if both min and max corners are outside (positive), AABB is outside
        val_min = plane.a * aabb_min[0] + plane.b * aabb_min[1] + plane.c * aabb_min[2] + plane.d
        val_max = plane.a * aabb_max[0] + plane.b * aabb_max[1] + plane.c * aabb_max[2] + plane.d
        if val_min > 0 and val_max > 0:
            return False

    # Check if AABB is behind the camera (near plane or camera position check) [G]
    if aabb_max[2] < camera_pos[2]:
        return False

    return True
```

**Edge Cases and Pitfalls:**
*   **Precision:** Ensure AABB coordinates are in the same coordinate space as the view frustum [G].
*   **Boundary Conditions:** Handle subchunks exactly on the frustum boundary correctly to avoid flickering or missing geometry [G].
*   **Degenerate Input:** Handle subchunks with zero volume or invalid AABBs gracefully [G].

## Subtopics

### [GPU-Based Chunk Culling via Indirect Commands](8769-gpu-based-chunk-culling-via-indirect-commands.md)
A rendering optimization that uses a compute shader to filter visible chunks and generates indirect draw arguments on the GPU, reducing CPU-GPU synchronization overhead. It differs from CPU-side culling by offloading the visibility test and command buffer population to the GPU, allowing the CPU to remain free for scene management and chunk loading. It builds on [GPU-driven Visibility Culling](3640-gpu-driven-visibility-culling.md) by utilizing the metadata prepared there to drive the compute dispatch and indirect execution.
