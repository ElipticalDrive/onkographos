# PVS Compactification and Temporal Coherence Pass
Also called: PVS Compactification, PVS Compactification and Output Pass, PVS Data Construction, Temporal PVS Generation

## Overview
This compute shader pass compactifies the raw visibility indices generated by the preceding raster occlusion culling stage and constructs two distinct Potentially Visible Set (PVS) datasets: $PVS_{curr}$ and $PVS_{curr-prev}$ [S1, S2]. It solves the problem of efficiently preparing visibility data for temporal coherence by identifying blocks visible in the current frame and those newly visible since the last frame, enabling the selection of optimal occluders for subsequent rendering passes [S1, S2].

## How it works
**Inputs and Outputs:**
*   **Input:** A visibility buffer containing raw block indices written by the fragment shader stage of the raster occlusion culling pass. Each fragment passing the early depth test and representative fragment test writes its block's implicit ID into a preallocated slot [S1, S2].
*   **Outputs:**
    *   $PVS_{curr}$: A compacted list of block indices visible in the current frame, used in the next frame for temporal coherence-based occluder selection [S1, S2].
    *   $PVS_{curr-prev}$: A list of blocks that became visible since the last frame, used to determine new visibility events [S1, S2].

**Data Structures:**
The sources do not specify the exact memory layout (e.g., struct of arrays vs. array of structs) or bit-packing details for the PVS datasets [S1, S2]. The visibility buffer is described as having "preallocated slots" [S1, S2].

**Steps:**
1.  **Bit Compactification:** Execute a bit compactification kernel on the raw indices in the visibility buffer to produce the current frame's potentially visible set, denoted as $PVS_{curr}$ [S1, S2].
2.  **Temporal Data Construction:** Execute a single compute shader pass to generate both $PVS_{curr}$ and $PVS_{curr-prev}$ [S1, S2]. This pass compares the current visibility state with the previous frame's data to identify newly visible blocks [S1, S2].

**Pseudocode:**
```python
# PVS Compactification and Temporal Coherence Pass
# Input: visibility_buffer (array of block IDs, sparse)
# Input: prev_pvs (array of block IDs from previous frame)
# Output: pvs_curr (compact array of current visible blocks)
# Output: pvs_curr_prev (compact array of newly visible blocks)

def pvs_compactification_and_temporal_coherence_pass(visibility_buffer, prev_pvs):
    # Step 1: Bit Compactification
    # Compact the sparse visibility buffer into a dense list of current visible blocks
    # The exact bit-packing and compactification algorithm is not given in the sources.
    pvs_curr = [block_id for block_id in visibility_buffer if block_id is not None]
    
    # Step 2: Temporal Coherence Data Construction
    # Identify blocks in pvs_curr that were not in prev_pvs
    pvs_curr_prev = [block_id for block_id in pvs_curr if block_id not in set(prev_pvs)]
        
    return pvs_curr, pvs_curr_prev
```

**Parameters:**
*   **Shader Type:** Compute shaders are used instead of mesh shaders [S1, S2].
*   **Block Size:** Larger block sizes can be launched for this pass compared to mesh shaders, allowing better utilization of streaming multiprocessors [S1, S2].

**Edge Cases and Pitfalls:**
*   **Multi-view Rendering:** When using multi-view rendering features to rasterize proxy geometry per-eye in a joint pass, one quad must be generated per eye [S1].
*   **Occlusion Geometry:** If a block lies between the viewer's eyes along any of the three cardinal axes, more than 3 sides of the block may need to be rendered to ensure correct occlusion culling [S1].

## Operating characteristics
*   **Time Complexity:** Not given in the sources [S1, S2].
*   **Memory Complexity:** Not given in the sources [S1, S2].
*   **Performance:** The use of compute shaders allows for larger block sizes and better utilization of streaming multiprocessors compared to mesh shaders [S1, S2].
*   **Strengths:** Combines compactification and temporal data construction into a single pass, reducing kernel launch overhead [S1, S2].
*   **Limitations:** Requires careful handling in stereo/multi-view rendering scenarios due to potential multi-sided visibility requirements [S1].

## Background
This method is part of the "Lightweight Raster Occlusion Culling" technique for efficient direct isosurface rasterization of scalar volumes [S1, S2]. It builds on the reference implementation of Kubisch [Kub14] but improves upon it by generating both $PVS_{curr}$ and $PVS_{curr-prev}$ in a single compute shader pass, whereas the reference implementation likely used separate passes [S1, S2]. The technique is implemented in both mono and stereo modes [S1, S2].
