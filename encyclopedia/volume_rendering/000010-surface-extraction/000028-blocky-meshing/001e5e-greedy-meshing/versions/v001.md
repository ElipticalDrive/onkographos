# Greedy Meshing

Also called: C++ version of greedy meshing, GreedMesh, Greedy Mesher, Greedy Quad Merging, Greedy Quad Meshing, Greedy Voxel Meshing, Voxel Quad Merging

## Overview
Greedy meshing is a surface extraction algorithm that reduces the number of rendered primitives in voxel worlds by merging adjacent coplanar faces of identical material into larger quads [S1, S2, S4, S5, S6, S7, S8, S9, S10, S11, S13, unofficial][S14][S15, S16, S17, S18, S19, S20, unofficial][S21][S22, S23, S25, unofficial]. It solves the problem of high vertex and triangle counts in naive per-face voxel rendering by minimizing draw calls and memory bandwidth usage [S1, S2, S4, S10, S11, S13, unofficial][S14][S15, S16, S17, S18, S19, S20, unofficial][S21][S22, S23, S25, unofficial]. Unlike [Blocky meshing](31-blocky-meshing.md) which only culls hidden faces, greedy meshing actively expands visible faces into maximal rectangles [S1, S2, S4, S5, S6, S7, S8, S9, S10, S11, S13, unofficial][S14][S15, S16, S17, S18, S19, S20, unofficial][S21][S22, S23, S25, unofficial]. It differs from [Marching Cubes](52-marching-cubes.md) by preserving the blocky aesthetic while reducing triangle count by 1.88–2.60× and geometry size by 39.5–54.5× compared to Marching Cubes on typical terrain [S3, unofficial].

## How it works
**Inputs:** A 3D voxel grid (chunk) where each voxel has an ID (material type) and potentially other attributes (e.g., ambient occlusion, color). A visibility checker to determine if a face is exposed (neighbor is air or different material) [S1, S2, S4, S5, S6, S7, S8, S9, S10, S11, S13, unofficial][S14][S15, S16, S17, S18, S19, S20, unofficial][S21][S22, S23, S25, unofficial].
**Outputs:** A list of quads, each defined by an origin $(x, y, z)$, dimensions $(w, h)$, face orientation (normal), and material ID [S1, S2, S4, S5, S6, S7, S8, S9, S10, S11, S13, unofficial][S14][S15, S16, S17, S18, S19, S20, unofficial][S21][S22, S23, S25, unofficial].

**Data Structures:**
*   **Voxel Grid:** Flattened 1D array or 3D array. Index mapping: $Index(x, y, z) = x + y \cdot D_x + z \cdot D_x \cdot D_y$ [S15, S23, unofficial].
*   **Mask:** A 2D boolean or integer array representing the current slice. For opaque merging, it stores the voxel ID if the face is visible, or 0 if not [S4, S9, S10, S11, S22, S25, unofficial]. For AO-aware merging, it may pack block ID and AO value into a single integer (e.g., bits 0-7 for ID, 8-9 for AO) [S25, unofficial].
*   **Processed/Visited Mask:** A boolean or bitmask array tracking which voxels have been covered by a generated quad to prevent double-counting [S10, S18, S23, S25, unofficial].

**Steps:**
1.  **Initialization:** Create an empty list of quads. Initialize a `processed` mask to all false/zero [S10, S18, S23, S25, unofficial].
2.  **Axis Sweep:** Iterate over the 3 principal axes (X, Y, Z). For each axis, treat it as the "normal" direction $n$. The other two axes are $u$ and $v$ [S4, S15, S25, unofficial].
3.  **Slice Loop:** Iterate through each slice along the normal axis $n$ from $0$ to $D_n - 1$ [S4, S15, S25, unofficial].
4.  **Face Detection (Mask Generation):** For the current slice at $n$, build a 2D mask for the $u-v$ plane. A cell $(u, v)$ is marked as "visible" if the voxel at $(u, v, n)$ is solid AND the neighbor in the normal direction is not solid (or is out of bounds) [S4, S10, S11, S15, S22, S25, unofficial].
    *   *Note:* If processing back-faces, check the neighbor in the negative normal direction [S15, unofficial].
    *   *Note:* If using a `mergeKey` function, the mask stores the key value instead of just boolean visibility [S9, unofficial].
5.  **Greedy Expansion:** Iterate through the 2D mask in lexicographic order (e.g., row by row, left to right) [S4, S11, S22, unofficial].
    *   If the current cell $(u, v)$ is marked visible and not yet processed:
        *   **Expand Width ($w$):** Increment $w$ starting at 1 while $u+w < D_u$, the cell $(u+w, v)$ is visible, and the material ID matches the start cell's ID [S4, S11, S18, S22, S25, unofficial].
        *   **Expand Height ($h$):** Increment $h$ starting at 1 while $v+h < D_v$. For each potential $h$, check if *all* cells in the rectangle $[u, u+w) \times [v, v+h)$ are visible and have the matching material ID [S4, S11, S19, S22, S25, unofficial].
        *   **Generate Quad:** Add a quad with origin $(u, v, n)$, dimensions $(w, h)$, normal $n$, and material ID to the output list [S4, S11, S19, S22, S25, unofficial].
        *   **Mark Processed:** Mark all cells in the rectangle $[u, u+w) \times [v, v+h)$ as processed in the `processed` mask [S10, S18, S23, S25, unofficial].
        *   **Advance:** Move $u$ forward by $w$ [S4, S11, S22, unofficial].
6.  **Repeat:** Repeat steps 3-5 for all 6 face directions (positive and negative for each axis) if bidirectional meshing is required [S10, S15, S23, unofficial].

**Pseudocode:**
```python
def greedy_mesh(voxels, dims, is_solid, get_material, merge_key=None):
    """
    voxels: 3D array or accessor function
    dims: (Dx, Dy, Dz)
    is_solid: function(x, y, z) -> bool
    get_material: function(x, y, z) -> int
    merge_key: function(material, x, y, z) -> int (optional, default is material)
    """
    quads = []
    processed = [[False] * dims[1] for _ in range(dims[2])] # Simplified for 2D slice
    
    # Axes: 0=X, 1=Y, 2=Z
    for norm in range(3):
        tan = (norm + 1) % 3
        biTan = (norm + 2) % 3
        
        # Iterate slices along the normal axis
        for slice_idx in range(dims[norm]):
            # Build 2D mask for this slice
            # Mask stores merge_key if visible, else 0
            mask = [[0] * dims[tan] for _ in range(dims[biTan])]
            
            for v in range(dims[biTan]):
                for u in range(dims[tan]):
                    # Construct coordinates
                    coords = [0, 0, 0]
                    coords[norm] = slice_idx
                    coords[tan] = u
                    coords[biTan] = v
                    
                    # Check visibility: current is solid, neighbor in +normal is not
                    # Note: This handles one direction. For full meshing, repeat for -normal
                    if is_solid(*coords):
                        neighbor_coords = list(coords)
                        neighbor_coords[norm] += 1
                        if not is_solid(*neighbor_coords):
                            mat = get_material(*coords)
                            key = merge_key(mat, *coords) if merge_key else mat
                            mask[v][u] = key
                    # Handle back-face visibility if needed by checking neighbor_coords[norm] -= 1

            # Greedy expansion on the 2D mask
            for v in range(dims[biTan]):
                for u in range(dims[tan]):
                    if mask[v][u] == 0:
                        continue
                    
                    current_key = mask[v][u]
                    w = 1
                    # Expand width
                    while u + w < dims[tan] and mask[v][u + w] == current_key:
                        w += 1
                    
                    h = 1
                    # Expand height
                    while v + h < dims[biTan]:
                        # Check if entire row segment of width w matches
                        match = True
                        for dx in range(w):
                            if mask[v + h][u + dx] != current_key:
                                match = False
                                break
                        if not match:
                            break
                        h += 1
                    
                    # Generate Quad
                    origin = [0, 0, 0]
                    origin[norm] = slice_idx
                    origin[tan] = u
                    origin[biTan] = v
                    
                    extent = [0, 0]
                    extent[0] = w # tan dimension
                    extent[1] = h # biTan dimension
                    
                    quads.append({
                        'origin': origin,
                        'extent': extent,
                        'normal': norm,
                        'material': current_key
                    })
                    
                    # Mark as processed (set mask to 0)
                    for dy in range(h):
                        for dx in range(w):
                            mask[v + dy][u + dx] = 0
                            
                    # Advance u
                    u += w - 1 # Loop will increment by 1, so we compensate
                    
    return quads
```

**Parameters:**
*   `VOXEL_SIZE`: Scaling factor for world coordinates [S3, S6, S19, unofficial].
*   `CHUNK_DIM`: Spatial dimension of the chunk (e.g., 16, 32) [S17, S23, unofficial].
*   `mergeKey`: Function to determine merge compatibility. Default is material ID [S9, unofficial].
*   `policy`: Boundary policy ("air" or "solid") determining if outer surface is emitted [S9, S25, unofficial].

**Edge Cases and Pitfalls:**
*   **Transparency:** Transparent faces are typically kept unit-sized (not merged) to preserve correct sorting and per-cell attributes [S25, unofficial].
*   **Ambient Occlusion (AO):** Merging faces with different AO values can cause shading artifacts. Solutions include restricted merging (only merge if AO is identical) or texture atlas baking [S30, unofficial].
*   **Chunk Boundaries:** Neighbor chunks must be processed or padded to ensure correct visibility checks at chunk edges [S13, S23, unofficial].
*   **Precision:** Using integer coordinates for origins and extents avoids floating-point errors in vertex generation [S10, S20, unofficial].

## Subtopics

### [Voxel Mesh Generation (Run-based Greedy Meshing)](3127-voxel-mesh-generation-run-based-greedy-meshing.md)
A CPU-based mesh generation algorithm for voxel worlds that combines adjacent faces into runs along the X and Y axes to reduce triangle count, while optimizing for generation speed over minimal triangle count.

### [Chunked Voxel Mesh Generation with Face Culling and Quad Expansion](3133-chunked-voxel-mesh-generation-with-face-culling-and-quad-exp.md)
Chunked Voxel Mesh Generation with Face Culling and Quad Expansion is a surface extraction algorithm that processes a 3D voxel chunk to generate an optimized triangle mesh by merging adjacent coplanar faces of identical voxel types into larger quads. It solves the problem of high vertex and triangle counts in naive voxel rendering by reducing draw calls and memory bandwidth usage. Unlike [Voxel Mesh Generation (Run-based Greedy Meshing)](3127-voxel-mesh-generation-run-based-greedy-meshing.md) which may process runs linearly, this method explicitly handles chunk boundaries and neighbor dependencies to enable maximal rectangle merging across chunk edges, trading increased preparation time for significant triangle count reduction. It differs from [Binary Greedy Meshing with Packed Quads](3312-binary-greedy-meshing-with-packed-quads.md) by using explicit boolean visitation arrays and separate quad expansion logic rather than binary packing for the expansion phase.

### [Binary Greedy Meshing with Packed Quads](3312-binary-greedy-meshing-with-packed-quads.md)
Binary Greedy Meshing (BGM) generates maximal axis-aligned quads from a binary voxel slice by greedily expanding horizontally from the first solid block found in each vertical run, using bitwise operations to minimize clock cycles. It treats the Signed Distance Field (SDF) or voxel grid as solid/empty, culls hidden faces, and merges co-planar visible faces into maximal rectangles drawn via instanced rendering from an 8-byte packed record. Unlike [Marching Cubes](52-marching-cubes.md) which produces smooth isosurfaces, BGM preserves the blocky aesthetic while reducing triangle count by 1.88–2.60× and geometry size by 39.5–54.5× compared to Marching Cubes on typical terrain. It builds on [Greedy Meshing](1776-greedy-meshing.md) by replacing per-voxel iteration with row-wise bitwise logic.

### [Greedy Meshing for Voxel Faces](3367-greedy-meshing-for-voxel-faces.md)
A technique to reduce the number of triangles in voxel rendering by merging adjacent coplanar voxel faces into larger quads. It differs from standard greedy meshing by comparing voxel faces (which may have varying attributes like type, transparency, or lighting) rather than just voxel existence.

### [3D Greedy Meshing](3519-3d-greedy-meshing.md)
Extends 2D greedy meshing to three dimensions by extracting 2D slices from the 3D voxel grid along each axis and processing them with the 2D algorithm.
*   #### SBUG Mesh Entry Point
    *   **Definition:** An entry point implementation for greedy meshing in a specific engine context.
    *   **Steps:** Define `MAX_FACE_QUADS` as `(size_t)CS * CS * CS`. Initialize `outputs[6]` and `begins[6]` arrays. For each face 0-5, if `md.vertices[face].size()` is less than `MAX_FACE_QUADS`, resize it to `MAX_FACE_QUADS`. Set `begins[face]` and `outputs[face]` to `md.vertices[face].data()`. Call `mesh_face_columns_all_x_slices(voxels, opaque_mask, md, outputs)` to perform the greedy meshing. Reset `md.vertex_count` to 0. For each face 0-5, calculate `md.face_vertex_counts[face]` as `(size_t)(outputs[face] - begins[face])` and add it to `md.vertex_count`. Return `md.vertex_count`.
*   #### 4D Greedy Meshing
    *   **Definition:** Greedy meshing is applied to the 4D voxel world to merge coplanar faces. Although neighboring cells present polygons at different angles in slice space, the preimage of a convex set under a linear map (`to_4d`) is convex. Therefore, a box of cells presents one convex polygon at any angle, allowing greedy meshing to work if it sweeps in lattice space (4D) rather than slice space (3D).
    *   **Pitfall:** Re-merging in a third dimension recovers only about 1% of quads at any cut, contrary to earlier design notes claiming no further merging was possible. The turned hyperplane meets more cells, each bringing its own edges, limiting further merging.
    *   **Performance:** Greedy meshing reduction ratios compared to naive per-face meshing for different cut configurations: Flat cut: 1.41x (before merging 2.47x); ZW only: 1.96x (before 3.45x); Both planes: 3.05x (before 4.97x); Hard tilt: 3.58x (before 4.98x). Overall performance: Greedy meshing produces 5.3x fewer triangles than naive per-face meshing (CI gated at 4.5x minimum).
*   #### Integrating AO with Greedy Meshing
    *   **Definition:** Strategies to handle the conflict between ambient occlusion variation across individual block boundaries and the merging of coplanar, adjacent voxel faces into larger single quads in greedy meshing.
    *   **Steps:**
        1.  **Restricted Merging:** Only merge adjacent faces if both their block types and their calculated per-vertex AO values are identical. This preserves accurate vertex-based shading at the cost of a slightly higher polygon count.
        2.  **Texture Atlas Baking:** Instead of baking AO into vertex colors, generate or slice a small, low-resolution texture atlas containing pre-computed AO gradients, applying UVs from the merged quad across the continuous surface.
        3.  **Fragment-Shader Reconstruction:** Pass unmerged face bounds as custom vertex attributes or instanced data, allowing the fragment shader to mathematically calculate edge proximity and distance-to-corner shading analytically.
*   #### VBO Indexing Optimization
    *   **Steps:** After greedy meshing, VBO indexing is applied to reduce vertex count from 6 vertices per face to 4 vertices per face.
    *   **Comparison:** This optimization further reduces the quad count by 1/3 compared to the greedy meshing output alone.

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of voxels in the chunk, as each voxel is visited a constant number of times (once per axis/slice) [S1, S2, S4, S5, S6, S7, S8, S9, S10, S11, S13, unofficial][S14][S15, S16, S17, S18, S19, S20, unofficial][S21][S22, S23, S25, unofficial].
*   **Memory Complexity:** $O(N)$ for the voxel grid and $O(D_u \cdot D_v)$ for the 2D mask per slice [S4, S10, S11, S22, S25, unofficial].
*   **Measured Performance:** On a 5x1x5 chunk scene, greedy meshing reduced the number of quads drawn by an average of 60% compared to naive face culling, with further VBO indexing reducing it by another 1/3 [S1, unofficial].
*   **Scaling:** Performance scales linearly with chunk size. Larger chunks reduce the number of draw calls but increase memory usage and meshing time per chunk [S2, S10, unofficial].
*   **Strengths:** Significantly reduces draw calls and vertex count (10-20x reduction compared to naive per-face rendering) [S11, S13, unofficial][S14][S15, S16, S17, S18, S19, S20, unofficial][S21][S22, S23, S25, unofficial]. Simple to implement on CPU [S1, S2, S4, S5, S6, S7, S8, S9, S10, S11, S13, unofficial][S14][S15, S16, S17, S18, S19, S20, unofficial][S21][S22, S23, S25, unofficial].
*   **Limitations:** Not optimal for highly complex or organic shapes where [Marching Cubes](52-marching-cubes.md) might be preferred. Merging can obscure fine details if not careful with material boundaries [S30, unofficial].
*   **When to Use:** Blocky voxel worlds (e.g., Minecraft-like) where performance is critical and aesthetic allows for large quads [S1, S2, S4, S5, S6, S7, S8, S9, S10, S11, S13, unofficial][S14][S15, S16, S17, S18, S19, S20, unofficial][S21][S22, S23, S25, unofficial].
*   **When Not to Use:** Smooth terrain, complex organic shapes, or when per-vertex attributes (like AO) vary significantly across adjacent faces and cannot be merged [S30, unofficial].

## Background
Greedy meshing was popularized by Mikola Lysenko in a 2012 article on 0fps.net [S2, S4, unofficial][S21]. It is a technique used to optimize the rendering of voxel-based graphics by merging adjacent voxels (or 'blocks') into larger cuboids, thereby reducing the complexity of the mesh [S16, S17, unofficial]. The algorithm is described as very good, somewhat simple, and very fast to generate if done right [S18, unofficial]. It has been implemented in various engines and languages, including C++, JavaScript, Rust, and Python [S1, S4, S5, S6, S7, S8, S9, S10, S11, S12, S13, unofficial][S14][S15, S16, S17, S18, S19, S20, unofficial][S21][S22, S23, S24, S25, S26, S27, S28, unofficial].
