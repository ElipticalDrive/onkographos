# Streaming Binary Greedy Meshing

Also called: SBUG streaming step, Streaming Binary Greedy Meshing (SBUG) Core Loop

## Overview
Streaming Binary Greedy Meshing (SBGM) is a performance-oriented variant of [Binary Greedy Meshing with Packed Quads](3312-binary-greedy-meshing-with-packed-quads.md) that combines face visibility generation and greedy merging into a single streaming traversal. Unlike the parent method, which builds six full-chunk face masks (180 KiB) that exceed L1 cache capacity, SBGM maintains only two rolling face data slices (11 KiB total), significantly improving cache locality and throughput [S1, unofficial].

## How it works
**Inputs and Outputs:**
- `voxels`: `uint8_t*` pointer to the voxel data, ordered in ZXY layout, padded to $64^3$ (62 interior voxels + 1-voxel halo) [S1, unofficial].
- `opaque`: `uint64_t*` pointer to precomputed column opacity masks, size $CS_P \times CS_P$ [S1, unofficial].
- `md`: `MeshData&` structure containing output buffers and counters [S1, unofficial].
- `outputs`: Array of 6 `uint64_t*` pointers, one for each face direction (0: X+, 1: X-, 2: Z+, 3: Z-, 4: Y+, 5: Y-), tracking write positions in `md.vertices` [S1, unofficial].

**Data Structures:**
- `FaceSlice`: Stores face visibility bits and merge spans for a single x-slice.
  ```cpp
  struct FaceSlice {
      uint64_t x_neg[CS_P]; // X- face bits
      uint64_t x_pos[CS_P]; // X+ face bits
      uint64_t z_neg[CS_P]; // Z- face bits
      uint64_t z_pos[CS_P]; // Z+ face bits
      uint64_t y_neg[CS_P]; // Y- face bits
      uint64_t y_pos[CS_P]; // Y+ face bits
      uint8_t y_neg_span[CS_P2]; // Y- merge spans
      uint8_t y_pos_span[CS_P2]; // Y+ merge spans
  };
  ```
- `MeshData`: Contains merge state arrays and vertex buffers. Key offsets relative to `forward_merged`:
  - `MERGED_POS_FORWARD`: Offset for X+ forward merge state.
  - `MERGED_Y_RIGHT`: Offset for Y- right merge state.
  - `MERGED_Y_POS_RIGHT`: Offset for Y+ right merge state.
  - `MERGED_Z_FORWARD`: Offset for Z- forward merge state.
  - `MERGED_Z_POS_FORWARD`: Offset for Z+ forward merge state.
  - `vertices`: `vector<uint64_t>` storing packed quads [S1, unofficial].

**Parameters:**
- `CS`: 62 (Chunk Size) [S1, unofficial].
- `CS_P`: 64 (Padded Chunk Size, $CS + 2$) [S1, unofficial].
- `CS_P2`: 4096 ($CS_P \times CS_P$) [S1, unofficial].
- `P_MASK`: `~(1ull << 63 | 1ull)`, mask excluding top and bottom bits of a 64-bit integer [S1, unofficial].

**Algorithm Steps:**
1. **Initialization:** Allocate two `FaceSlice` buffers (`current`, `next`). Build face data for x-slices 1 and 2 using `build_face_slice`. Initialize `outputs` pointers to the start of `md.vertices` for each face direction [S1, unofficial].
2. **Streaming Loop:** Iterate `x` from 1 to `CS` (interior slices):
   - For each `z` from 1 to `CS`:
     - Calculate column pointer `col = voxels + x * CS_P2 + z * CS_P` and `span_base = z * CS_P` [S1, unofficial].
     - **Process X Faces:**
       - If `current->x_neg[z]` is non-zero, call `mesh_x_bits` with `col`, sign `-1`, `x`, `z`, `current->x_neg[z]`, `current->x_neg[z+1]`, `forward_merged` offset, and `outputs[1]` [S1, unofficial].
       - If `current->x_pos[z]` is non-zero, call `mesh_x_bits` with `col`, sign `+1`, `x`, `z`, `current->x_pos[z]`, `current->x_pos[z+1]`, `pos_forward_merged` offset, and `outputs[0]` [S1, unofficial].
     - **Process Y Faces:**
       - If `current->y_neg[z]` is non-zero, call `mesh_y_end_bits_x_major` with `col`, sign `-1`, `x`, `z`, `current->y_neg[z]`, `right->y_neg[z]`, `current->y_neg_span + span_base`, `right->y_neg_span + span_base`, `y_right_merged` offset, and `outputs[5]` [S1, unofficial].
       - If `current->y_pos[z]` is non-zero, call `mesh_y_end_bits_x_major` with `col`, sign `+1`, `x`, `z`, `current->y_pos[z]`, `right->y_pos[z]`, `current->y_pos_span + span_base`, `right->y_pos_span + span_base`, `y_pos_right_merged` offset, and `outputs[4]` [S1, unofficial].
     - **Process Z Faces:**
       - If `current->z_neg[z]` is non-zero, call `mesh_z_bits` with `col`, sign `-1`, `z`, `x`, `current->z_neg[z]`, `right->z_neg[z]`, `z_forward_merged` offset, and `outputs[3]` [S1, unofficial].
       - If `current->z_pos[z]` is non-zero, call `mesh_z_bits` with `col`, sign `+1`, `z`, `x`, `current->z_pos[z]`, `right->z_pos[z]`, `z_pos_forward_merged` offset, and `outputs[2]` [S1, unofficial].
   - **Swap and Build:** Swap `current` and `next` pointers. If `x + 2 <= CS`, call `build_face_slice` to populate the new `next` slice with data for x-slice `x + 2` [S1, unofficial].
3. **Finalization:** Update `md.face_vertex_counts` and `md.vertex_count` based on the final positions in `outputs` [S1, unofficial].

**Helper Functions:**
- `build_face_slice`: Uses AVX2 to load column occupancy bits for left, mid, and right x-slices. Computes `x_neg` and `x_pos` by masking with `P_MASK` and neighbor occupancy. Sets `x_neg[CS+1]` and `x_pos[CS+1]` to 0 as sentinels. Calls `build_y_face_slice` [S1, unofficial].
- `build_y_face_slice`: Iterates `z` from 1 to `CS`. Computes `neg_current` and `pos_current` bits. Calls `build_y_face_column` for each `z`. Updates `prev_occ`, `current_occ`, `next_occ`. Handles `z=CS` sentinel by setting `neg_next`/`pos_next` to 0 [S1, unofficial].
- `build_y_face_column`: Processes `neg_bits` and `pos_bits`. For each bit `y`, checks if neighbor has same material. If so, increments forward span and removes bit; else stores forward span to `span_end`, resets forward span to 0, and updates terminal bits [S1, unofficial].
- `mesh_x_bits`: Iterates `bits_here`. Finds lowest set bit `y`. Checks if `bits_next` has same bit and same material. If so, increments `forward_span` and continues. Else computes height, merges forward spans, creates quad via `get_quad`, and removes processed bits [S1, unofficial].
- `mesh_z_bits`: Similar to `mesh_x_bits` but processes Z faces [S1, unofficial].
- `mesh_y_end_bits_x_major`: Iterates `bits_here`. Finds bit `y`. Checks if `bits_right` has same bit, `forward_span` equals `span_right[y]`, and same material. If so, increments `right_span`. Else computes start coordinates and length/width from spans, creates quad via `get_quad`, resets `right_span`, and removes processed bits [S1, unofficial].
- `get_quad`: Encodes quad as `(type << 32) | (h << 24) | (w << 18) | (z << 12) | (y << 6) | x` [S1, unofficial].

**Pseudocode:**
```python
def mesh_face_columns_all_x_slices(voxels, opaque, md, outputs):
    CS = 62
    CS_P = 64
    CS_P2 = 4096
    P_MASK = ~(1 << 63 | 1)
    
    slices = [FaceSlice(), FaceSlice()]
    zero_slice = FaceSlice()
    current = slices[0]
    next_slice = slices[1]
    
    build_face_slice(voxels, opaque, 1, current)
    build_face_slice(voxels, opaque, 2, next_slice)
    
    for x in range(1, CS + 1):
        right = next_slice if x < CS else zero_slice
        
        for z in range(1, CS + 1):
            col = voxels + x * CS_P2 + z * CS_P
            span_base = z * CS_P
            
            if current.x_neg[z]:
                outputs[1] = mesh_x_bits(col, -1, x, z, current.x_neg[z], current.x_neg[z+1], md.forward_merged, outputs[1])
            
            if current.x_pos[z]:
                outputs[0] = mesh_x_bits(col, 1, x, z, current.x_pos[z], current.x_pos[z+1], md.pos_forward_merged, outputs[0])
            
            if current.y_neg[z]:
                outputs[5] = mesh_y_end_bits_x_major(col, -1, x, z, current.y_neg[z], right.y_neg[z], current.y_neg_span + span_base, right.y_neg_span + span_base, md.y_right_merged, outputs[5])
            
            if current.y_pos[z]:
                outputs[4] = mesh_y_end_bits_x_major(col, 1, x, z, current.y_pos[z], right.y_pos[z], current.y_pos_span + span_base, right.y_pos_span + span_base, md.y_pos_right_merged, outputs[4])
            
            if current.z_neg[z]:
                outputs[3] = mesh_z_bits(col, -1, z, x, current.z_neg[z], right.z_neg[z], md.z_forward_merged, outputs[3])
            
            if current.z_pos[z]:
                outputs[2] = mesh_z_bits(col, 1, z, x, current.z_pos[z], right.z_pos[z], md.z_pos_forward_merged, outputs[2])
        
        current, next_slice = next_slice, current
        if x + 2 <= CS:
            build_face_slice(voxels, opaque, x + 2, next_slice)
    
    for face in range(6):
        md.face_vertex_counts[face] = outputs[face] - md.vertices.begin()
        md.vertex_count += md.face_vertex_counts[face]
```

## Operating characteristics
- **Time Complexity:** $O(V)$ where $V$ is the number of voxels, but with significantly reduced constant factors due to cache efficiency.
- **Memory Complexity:** $O(CS_P^2)$ for the two rolling slices, compared to $O(CS_P^3)$ for full chunk masks in BGM [S1, unofficial].
- **Performance:** On a Ryzen 5 5600x, SBGM achieves 37.52 us/chunk median throughput (26,650 chunks/s) compared to BGM's 100.27 us/chunk, a 2.67x speedup on a 64x64 grid at 8 iterations [S1, unofficial].
- **Strengths:** Excellent cache locality, reduced memory bandwidth usage, high throughput.
- **Limitations:** Requires AVX2/BMI/BMI2 support. Quad counts may differ from BGM due to different merge order, though coverage is functionally equivalent [S1, unofficial].
- **When to use:** When meshing performance is critical and hardware supports AVX2.
- **When not to use:** When exact quad count matching with BGM is required, or on hardware without AVX2 support.

## Background
SBGM was introduced as an experimental implementation to demonstrate the algorithm's performance benefits over traditional BGM. It addresses the cache miss bottleneck of BGM by streaming face data generation and meshing together [S1, unofficial].
