# Chunk Loading and Mesh Generation
## Overview
This method manages the lifecycle of voxel chunk geometry by loading chunk data, generating its mesh, and caching GPU resources for rendering [S1, unofficial]. It solves the problem of efficiently updating visible geometry when chunks are first accessed or when their content changes, ensuring only non-empty chunks are rendered [S1, unofficial]. It builds on [Greedy Meshing / Face Culling](8783-greedy-meshing-face-culling.md) for triangle generation [S1, unofficial].
## How it works
**Inputs and Outputs:** Input is a 64-bit chunk key, world data, atlas properties, and world material [S1, unofficial]. Output is a `Model` containing a `GPUMesh`, stored in a `chunk_models` map keyed by the chunk key [S1, unofficial].
**Data Structures:**
*   **Chunk Key:** A 64-bit integer representing chunk coordinates, extracted via bit shifts [S1, unofficial].
*   **ChunkMesher:** An object instantiated with a $3 \times 3 \times 3$ neighborhood of chunk keys and atlas properties, responsible for generating raw mesh data [S1, unofficial].
*   **GPUMesh:** A GPU buffer containing the generated vertex and index data [S1, unofficial].
*   **Model:** A wrapper object combining the `GPUMesh` and world material [S1, unofficial].
*   **chunk_models:** A map storing the mesh, model, transform, and bounds for each loaded chunk [S1, unofficial].
**Numbered Steps for Initial Load:**
1. Extract chunk coordinates $(cx, cy, cz)$ from the 64-bit key using bit shifts [S1, unofficial].
2. Build a $3 \times 3 \times 3$ neighborhood of chunk keys centered at $(cx, cy, cz)$ [S1, unofficial].
3. Instantiate a `ChunkMesher` with the neighborhood and atlas properties [S1, unofficial].
4. Generate mesh data (vertices and indices) for the target chunk [S1, unofficial].
5. If the mesh has no vertices, remove the chunk from the render map and return [S1, unofficial].
6. Create a `GPUMesh` from the generated data [S1, unofficial].
7. Create a `Model` from the mesh and the world material [S1, unofficial].
8. Compute the chunk's world transform by translating by chunk size multiples [S1, unofficial].
9. Store the mesh, model, transform, and bounds in the `chunk_models` map [S1, unofficial].
**Formulas:**
*   Transform: $T = \text{translate}(cx \cdot S, cy \cdot S, cz \cdot S)$, where $S$ is the chunk size in world units [S1, unofficial].
*   Bounds: $B = \text{compute\_bounds}(T, \text{mesh\_data})$ [S1, unofficial].
**Parameters:**
*   $S$ (chunk size): Typically 16 blocks per axis [G].
**Edge Cases and Pitfalls:**
*   **Empty Chunks:** Chunks with no solid blocks must be explicitly removed from the render map to avoid rendering empty geometry or wasting memory [S1, unofficial].
*   **Boundary Conditions:** The $3 \times 3 \times 3$ neighborhood must handle chunks that do not exist by treating them as empty or air blocks [S1, unofficial].
*   **Precision:** Chunk coordinates are integers, but world transforms use floats; ensure consistent precision when computing bounds and transforms [G].
**Pseudocode for Initial Load:**
```python
class Vec3:
    def __init__(self, x, y, z): self.x, self.y, self.z = x, y, z
    def __mul__(self, s): return Vec3(self.x*s, self.y*s, self.z*s)

def extract_chunk_coords(key):
    cx = (key >> 32) & 0xFFFFFFFF
    cy = (key >> 16) & 0xFFFF
    cz = key & 0xFFFF
    return cx, cy, cz

def get_chunk_key(cx, cy, cz):
    return (cx << 32) | (cy << 16) | cz

class ChunkMesher:
    def __init__(self, neighborhood, atlas_props):
        self.neighborhood = neighborhood
        self.atlas_props = atlas_props
    def generate(self):
        # Delegates to greedy meshing algorithm [S1, unofficial]
        return {'vertices': [], 'indices': [], 'vertex_count': 0}

class GPUMesh:
    def __init__(self, vertices, indices): self.vertices, self.indices = vertices, indices

class Model:
    def __init__(self, gpu_mesh, material): self.gpu_mesh, self.material = gpu_mesh, material

def translate(v): return v
def compute_bounds(transform, mesh_data): return {'min': Vec3(0,0,0), 'max': Vec3(0,0,0)}

chunk_models = {}

def load_chunk(chunk_key, world_data, atlas_props, material, chunk_size=16):
    cx, cy, cz = extract_chunk_coords(chunk_key)
    neighborhood = []
    for dx in range(-1, 2):
        for dy in range(-1, 2):
            for dz in range(-1, 2):
                neighborhood.append(get_chunk_key(cx + dx, cy + dy, cz + dz))
    mesher = ChunkMesher(neighborhood, atlas_props)
    mesh_data = mesher.generate()
    if mesh_data['vertex_count'] == 0:
        chunk_models.pop(chunk_key, None)
        return None
    gpu_mesh = GPUMesh(mesh_data['vertices'], mesh_data['indices'])
    model = Model(gpu_mesh, material)
    transform = translate(Vec3(cx * chunk_size, cy * chunk_size, cz * chunk_size))
    bounds = compute_bounds(transform, mesh_data)
    chunk_models[chunk_key] = {'mesh': gpu_mesh, 'model': model, 'transform': transform, 'bounds': bounds}
    return model
```
## Subtopics

### Remeshing Affected Chunks
This variant handles updates when a single block changes [S1, unofficial]. It identifies all chunks that need regeneration because the modified block is either inside them or adjacent to them [S1, unofficial].
*   **Steps:**
    1. Compute the chunk coordinates $(cx, cy, cz)$ containing the modified block [S1, unofficial].
    2. Compute local coordinates $(lx, ly, lz)$ within the chunk using bitwise AND with $(S-1)$ [S1, unofficial].
    3. Determine the minimum and maximum offset for each axis based on chunk boundaries [S1, unofficial].
    4. Loop over the determined offsets and generate unique chunk keys [S1, unofficial].
    5. Reload each affected chunk using the unique keys [S1, unofficial].
**Pseudocode for Remeshing:**
```python
def remesh_affected_chunks(modified_block_pos, world_data, atlas_props, material, chunk_size=16):
    cx = modified_block_pos.x // chunk_size
    cy = modified_block_pos.y // chunk_size
    cz = modified_block_pos.z // chunk_size
    lx = modified_block_pos.x & (chunk_size - 1)
    ly = modified_block_pos.y & (chunk_size - 1)
    lz = modified_block_pos.z & (chunk_size - 1)
    offsets = []
    for local in [lx, ly, lz]:
        if local == 0:
            offsets.append((-1, 0))
        elif local == chunk_size - 1:
            offsets.append((0, 1))
        else:
            offsets.append((0, 0))
    affected_keys = set()
    for (min_dx, max_dx), (min_dy, max_dy), (min_dz, max_dz) in zip(offsets, offsets, offsets):
        for dx in range(min_dx, max_dx + 1):
            for dy in range(min_dy, max_dy + 1):
                for dz in range(min_dz, max_dz + 1):
                    affected_keys.add(get_chunk_key(cx + dx, cy + dy, cz + dz))
    for key in affected_keys:
        load_chunk(key, world_data, atlas_props, material, chunk_size)
```

## Operating characteristics
*   **Time Complexity:** Initial load is $O(N)$ where $N$ is the number of blocks in the chunk and its neighborhood, due to mesh generation [S1, unofficial]. Remeshing is $O(M)$ where $M$ is the number of blocks in the affected chunks (typically up to 9 chunks) [S1, unofficial].
*   **Memory Complexity:** Proportional to the number of loaded chunks, as each chunk stores a `GPUMesh` and `Model` [S1, unofficial].
*   **Strengths:** Efficiently handles dynamic worlds by only regenerating necessary chunks and caching results [S1, unofficial].
*   **Limitations:** Requires careful management of the `chunk_models` map and may cause frame drops if large numbers of chunks load simultaneously [G].
*   **When to Use:** When rendering dynamic voxel worlds where blocks are frequently modified [S1, unofficial].
*   **When Not to Use:** For static worlds where a single mesh for the entire world is feasible [G].
