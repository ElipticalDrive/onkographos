# Visible Block Face Meshing

Also called: Chunk-based Voxel Meshing with Neighbor Awareness, Voxel Face Culling (Greedy Meshing-lite / Immediate Mode Culling), Voxel Face Visibility Culling

## Overview
Visible Block Face Meshing is a surface extraction technique that generates a static triangle mesh for a voxel chunk by iterating through occupied voxel positions and emitting geometry only for faces that are adjacent to empty space or transparent blocks [S1, S2, S3, unofficial]. It differs from its parent method, [Voxel Chunk Mesh Generation (Face Culling)](4888-voxel-chunk-mesh-generation-face-culling.md), by explicitly handling cross-chunk boundary visibility checks to ensure global consistency, and it differs from [Greedy Meshing](52-greedy-meshing.md) by not merging adjacent coplanar faces into larger quads [S1, S2, unofficial]. This approach reduces vertex count and draw calls compared to naive voxel rendering by excluding internal faces [S2, unofficial].

## How it works
### Inputs and Outputs
**Inputs:**
*   `chunk`: A 3D array of voxel data representing the current chunk [S1, unofficial].
*   `neighbor_faces`: A map or structure providing visibility data for the six faces of the chunk (adjacent chunks) [S1, unofficial].
*   `block_textures`: Appearance data for the blocks [S1, unofficial].
*   `visibility_checker`: An interface or function to query block solidity/visibility in the global world [S1, unofficial].

**Outputs:**
*   `Mesh`: A triangle mesh containing vertices and indices for all visible block faces [S1, unofficial].

### Data Structures
**Voxel Vertex Layout:**
Each voxel is a cube with side length `Voxel::EDGE_LENGTH` [S2, unofficial]. The 8 vertices are defined in a local coordinate system where the voxel spans `[0, EDGE_LENGTH]` in X, Y, and Z. The indices are fixed as follows [S2, unofficial]:
*   0: `(0, 0, 0)`
*   1: `(0, E, 0)`
*   2: `(E, E, 0)`
*   3: `(E, 0, 0)`
*   4: `(0, 0, E)`
*   5: `(0, E, E)`
*   6: `(E, E, E)`
*   7: `(E, 0, E)`
Where $E = \text{Voxel::EDGE_LENGTH}$. Indices 0-3 form the front face ($Z=0$), and 4-7 form the back face ($Z=E$) [S2, unofficial].

**Block/Chunk Structure:**
*   **Block:** Contains a boolean `active` flag and a boolean array `visibleFaces[6]` indexed by `BlockFace` enum: `XPos=0`, `XNeg=1`, `YPos=2`, `YNeg=3`, `ZPos=4`, `ZNeg=5` [S3, unofficial].
*   **Chunk:** Stores blocks as a 3D pointer array `Block ***blocks` allocated as `new Block **[CHUNK_SIZE]` where each element is `new Block *[CHUNK_SIZE]` containing `new Block[CHUNK_SIZE]` [S3, unofficial].
*   **Parameters:**
    *   `CHUNK_SIZE`: Dimension of a chunk in blocks, set to 4 [S3, unofficial].
    *   `BLOCK_SIZE`: Physical size of a block, set to 10 [S3, unofficial].
    *   `NUMBER_OF_VOXELS_PER_DIMENSION`: Number of voxels along one axis in a chunk [S2, unofficial].
    *   `NUMBER_OF_VOXELS`: Total voxels in a chunk, calculated as `NUMBER_OF_VOXELS_PER_DIMENSION^3` [S2, unofficial].

### Algorithm Steps
1.  **Prepare Padded Chunk:**
    Query adjacent chunks to ensure boundary visibility checks have valid neighbor data [S1, S3, unofficial]. This step populates a padded representation or uses a global visibility checker to resolve out-of-bounds neighbor queries [S1, unofficial].

2.  **Iterate Voxels:**
    Iterate over each voxel in the chunk using a 1D index `i` from $0$ to `NUMBER_OF_VOXELS - 1` [S2, unofficial]. Convert `i` to 3D coordinates $(x, y, z)$ using:
    $$
    \begin{aligned}
    x &= i \pmod{\text{NUMBER\_OF\_VOXELS\_PER\_DIMENSION}} \\
    y &= (i / \text{NUMBER\_OF\_VOXELS\_PER\_DIMENSION}) \pmod{\text{NUMBER\_OF\_VOXELS\_PER\_DIMENSION}} \\
    z &= i / (\text{NUMBER\_OF\_VOXELS\_PER\_DIMENSION}^2)
    \end{aligned}
    $$
    [S2, unofficial]

3.  **Check Visibility:**
    For each active voxel at $(x, y, z)$, check the six neighbors: $(x+1, y, z)$, $(x-1, y, z)$, $(x, y+1, z)$, $(x, y-1, z)$, $(x, y, z+1)$, $(x, y, z-1)$ [S3, unofficial].
    A neighbor blocks a face if:
    *   The neighbor coordinate is within the current chunk bounds ($0 \le \text{coord} < \text{CHUNK\_SIZE}$) AND the neighbor block is active [S2, S3, unofficial].
    *   The neighbor coordinate is outside the current chunk bounds, AND the corresponding block in the adjacent global chunk is active [S3, unofficial].
    
    Global chunk coordinates for out-of-bounds neighbors are calculated as [S3, unofficial]:
    $$
    \begin{aligned}
    x_{\text{Chunk}} &= \lfloor x_{\text{global}} / (\text{CHUNK\_SIZE} \times \text{BLOCK\_SIZE}) \rfloor \\
    y_{\text{Chunk}} &= \lfloor y_{\text{global}} / (\text{CHUNK\_SIZE} \times \text{BLOCK\_SIZE}) \rfloor \\
    z_{\text{Chunk}} &= \lfloor z_{\text{global}} / (\text{CHUNK\_SIZE} \times \text{BLOCK\_SIZE}) \rfloor
    \end{aligned}
    $$
    [S3, unofficial]

4.  **Emit Geometry:**
    If a face is visible (not blocked by an active neighbor), emit 2 triangles (6 vertices) using the predefined vertex indices for that face, offset by `shared_index_buffer_offset = i * 8` [S2, unofficial]. Add one color entry to `color_data` [S2, unofficial].
    
    *   **Front Face (Negative Z, $z-1$):** Indices `{0, 1, 2, 0, 2, 3}` [S2, unofficial].
    *   **Back Face (Positive Z, $z+1$):** Indices `{4, 6, 5, 4, 7, 6}` [S2, unofficial].
    *   **Left Face (Negative X, $x-1$):** Indices `{4, 5, 1, 4, 1, 0}` [S2, unofficial].
    *   **Right Face (Positive X, $x+1$):** Indices `{3, 2, 6, 3, 6, 7}` [S2, unofficial].
    *   **Top Face (Positive Y, $y+1$):** Indices `{1, 5, 6, 1, 6, 2}` [S2, unofficial].
    *   **Bottom Face (Negative Y, $y-1$):** Indices `{4, 0, 3, 4, 3, 7}` [S2, unofficial].

### Pseudocode
```python
def mesh_chunk_visible_block_faces(chunk, neighbor_faces, visibility_checker, block_textures):
    """
    chunk: 3D list/array of Block objects indexed [x][y][z]
    neighbor_faces: dict mapping Direction to ChunkFace data
    visibility_checker: callable(gx_chunk, gy_chunk, gz_chunk, lx, ly, lz) -> bool
    block_textures: dict mapping BlockID to color
    """
    CHUNK_SIZE = len(chunk)
    BLOCK_SIZE = 10
    EDGE_LENGTH = 1.0
    vertices = []
    indices = []
    colors = []
    vertex_offset = 0

    # Iterate in cache-friendly order: y, then z, then x [S4, unofficial]
    for y in range(CHUNK_SIZE):
        for z in range(CHUNK_SIZE):
            for x in range(CHUNK_SIZE):
                block = chunk[x][y][z]
                if not block.active:
                    continue

                base_x = x * EDGE_LENGTH
                base_y = y * EDGE_LENGTH
                base_z = z * EDGE_LENGTH

                # Local vertex offsets for a unit cube [0,1]^3 scaled by EDGE_LENGTH [S2, unofficial]
                local_verts = [
                    (0, 0, 0), (0, 1, 0), (1, 1, 0), (1, 0, 0),
                    (0, 0, 1), (0, 1, 1), (1, 1, 1), (1, 0, 1)
                ]

                # Check 6 neighbors [S2, S3, unofficial]
                directions = [
                    ("front", (0, 0, -1), [0, 1, 2, 0, 2, 3]),
                    ("back", (0, 0, 1), [4, 6, 5, 4, 7, 6]),
                    ("left", (-1, 0, 0), [4, 5, 1, 4, 1, 0]),
                    ("right", (1, 0, 0), [3, 2, 6, 3, 6, 7]),
                    ("top", (0, 1, 0), [1, 5, 6, 1, 6, 2]),
                    ("bottom", (0, -1, 0), [4, 0, 3, 4, 3, 7])
                ]

                for name, (dx, dy, dz), face_indices in directions:
                    nx, ny, nz = x + dx, y + dy, z + dz
                    is_blocked = False

                    if 0 <= nx < CHUNK_SIZE and 0 <= ny < CHUNK_SIZE and 0 <= nz < CHUNK_SIZE:
                        # Neighbor within current chunk
                        if chunk[nx][ny][nz].active:
                            is_blocked = True
                    else:
                        # Neighbor outside chunk: query global world [S3, unofficial]
                        gx = (x * CHUNK_SIZE + nx) * BLOCK_SIZE
                        gy = (y * CHUNK_SIZE + ny) * BLOCK_SIZE
                        gz = (z * CHUNK_SIZE + nz) * BLOCK_SIZE

                        # Global chunk indices [S3, unofficial]
                        gx_chunk = gx // (CHUNK_SIZE * BLOCK_SIZE)
                        gy_chunk = gy // (CHUNK_SIZE * BLOCK_SIZE)
                        gz_chunk = gz // (CHUNK_SIZE * BLOCK_SIZE)

                        # Local coordinates within the neighbor chunk
                        lx = nx % CHUNK_SIZE
                        ly = ny % CHUNK_SIZE
                        lz = nz % CHUNK_SIZE

                        # Handle negative modulo correctly for global coords
                        if gx < 0: gx_chunk -= 1; lx = CHUNK_SIZE + (gx % CHUNK_SIZE)
                        if gy < 0: gy_chunk -= 1; ly = CHUNK_SIZE + (gy % CHUNK_SIZE)
                        if gz < 0: gz_chunk -= 1; lz = CHUNK_SIZE + (gz % CHUNK_SIZE)

                        # Query visibility checker [S1, S3, unofficial]
                        if visibility_checker(gx_chunk, gy_chunk, gz_chunk, lx, ly, lz):
                            is_blocked = True

                    if not is_blocked:
                        # Emit 2 triangles (6 vertices) [S2, unofficial]
                        color = block_textures.get(block.id, (1.0, 1.0, 1.0))
                        for idx in face_indices:
                            lx_v, ly_v, lz_v = local_verts[idx]
                            vertices.append((base_x + lx_v * EDGE_LENGTH,
                                             base_y + ly_v * EDGE_LENGTH,
                                             base_z + lz_v * EDGE_LENGTH))
                            indices.append(vertex_offset + idx)
                            colors.append(color)
                        vertex_offset += 6

    return vertices, indices, colors
```

### Edge Cases and Pitfalls
*   **Boundary Checks:** Accessing neighbor voxels requires strict boundary checks to avoid out-of-bounds array access [S2, unofficial].
*   **Cross-Chunk Consistency:** Faces on chunk boundaries must be checked against adjacent chunks to prevent gaps or double-rendering [S1, S3, unofficial].
*   **Neighbor Block ID Safety:** If a neighbor block ID is $\ge 256$, treat it as visible to prevent out-of-bounds access on lookup tables [S4, unofficial].
*   **Precision:** Floating-point precision issues may arise when calculating world offsets for vertices and chunk positions, especially with large coordinate values [S2, S3, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of voxels in the chunk [G]. Each voxel is processed once, and up to 6 faces are checked.
*   **Memory Complexity:** $O(F)$ where $F$ is the number of visible faces [G]. Each visible face generates 6 vertices and 6 indices.
*   **Performance:** Benchmarks show that `mesh_chunk_visible_block_faces` is significantly faster than `mesh_chunk_greedy_quads` for sparse chunks (e.g., 30% fill probability) because it avoids the complexity of quad merging [S1, unofficial].
*   **Strengths:** Simple implementation, low memory overhead for sparse chunks, no need for complex quad merging logic.
*   **Limitations:** Higher vertex count and draw calls compared to Greedy Meshing for dense chunks, as adjacent coplanar faces are not merged [S1, S2, unofficial].
*   **When to Use:** Suitable for sparse voxel worlds, dynamic environments where mesh regeneration is frequent, or when implementation simplicity is prioritized over optimal vertex count [S1, S2, unofficial].
*   **When Not to Use:** Less optimal for extremely dense worlds where vertex count optimization is critical, as adjacent coplanar faces are not merged [S1, S2, unofficial].

## Background
The technique is implemented in modern voxel engines such as Infinigen and Voxel1993, which use padded chunks and cross-chunk visibility checks [S1, S3, unofficial]. It is widely used in game development for generating static geometry for voxel chunks [S2, unofficial].
