# Binary Greedy Voxel Meshing with Ambient Occlusion

Also called: AO Meshing, Ambient Occlusion Vertex Calculation, Binary Greedy Voxel Meshing

## Overview
Binary Greedy Voxel Meshing with Ambient Occlusion is a surface extraction method that generates a blocky mesh from voxel data while calculating per-vertex ambient occlusion (AO) values based on the solidity of surrounding voxels [S1, unofficial]. Unlike sibling methods that treat all non-air blocks as opaque and output uniform `ao=0`, this method preserves per-vertex AO values derived from the surrounding voxel neighborhood [S1, unofficial].

## How it works
**Inputs:** A voxel chunk with solid/air classification and access to neighboring chunks for boundary sampling [S1, unofficial].
**Outputs:** A list of vertices, each containing position, AO value (0–3), face normal, and block type [S1, unofficial].

**Data Structures:**
*   `ambient_corners`: An array of 8 booleans representing the solidity of the 8 voxels surrounding a face corner in 3D space [S1, unofficial].
*   `Quad`: A geometric primitive defined by direction, position, color, and four corner coordinates [S1, unofficial].
*   `Vertex`: Packed into a `u32` containing position (`IVec3`), AO (`u32`), normal (`u32`), and block type (`u32`) [S1, unofficial].

**Algorithm Steps:**
1.  Iterate through all voxels in the chunk. For a $32^3$ chunk, indices range from $0$ to $32 \times 32 \times 32 - 1$ [S1, unofficial].
2.  For each voxel at position $(x, y, z)$, determine if it is solid [S1, unofficial].
3.  Check adjacent neighbors to identify exposed faces. If the current voxel is solid and an adjacent neighbor in a specific direction is not solid (air), a face is exposed [S1, unofficial].
4.  Call `push_face_ao` for the exposed face, passing the chunk references, mesh buffer, face direction, voxel position, color, and block type [S1, unofficial].
5.  Inside `push_face_ao`:
    a.  Retrieve the 8 surrounding corner voxels for the face direction using `ambient_corner_voxels` [S1, unofficial].
    b.  Initialize a `Quad` from the direction, position, and color [S1, unofficial].
    c.  Iterate over the four corners of the quad. For each corner index $i$ (0 to 3):
        i.  Calculate the index into the `ambient_corners` array: `index = i * 2` [S1, unofficial].
        ii. Identify three relevant neighbor states: `side_1` at `ambient_corners[index]`, `side_2` at `ambient_corners[(index + 2) % 8]`, and `side_corner` at `ambient_corners[(index + 1) % 8]` [S1, unofficial].
        iii. Calculate the raw AO count: `ao_count = side_1 + side_2 + side_corner` [S1, unofficial].
        iv. Apply clamping logic: If both `side_1` and `side_2` are solid (value 1), the corner is fully occluded regardless of `side_corner`. Set `ao_count = 3` [S1, unofficial].
        v.  Push a vertex to the mesh with the calculated `ao_count` as an attribute [S1, unofficial].

**Pseudocode:**
```python
class IVec3:
    def __init__(self, x, y, z):
        self.x, self.y, self.z = x, y, z
    @staticmethod
    def from_array(arr):
        return IVec3(arr[0], arr[1], arr[2])

class Direction:
    def get_normal(self):
        return 0  # Normal index for the face direction [G]

class Quad:
    def __init__(self, corners):
        self.corners = corners
    @staticmethod
    def from_direction(dir, vpos, color):
        # Generates 4 corner positions for the exposed face [G]
        return [IVec3(0,0,0), IVec3(1,0,0), IVec3(1,1,0), IVec3(0,1,0)]

def ambient_corner_voxels(chunks_refs, dir, vpos):
    # Returns 8 integers (0 or 1) for the solidity of surrounding voxels.
    # In practice, this function samples neighbors and handles chunk boundaries [S1, unofficial].
    return [1, 0, 1, 0, 1, 0, 1, 0]

def make_vertex_u32(position, ao, normal, block_type):
    # Packs vertex attributes into a 32-bit integer [G]
    return (position.x << 24) | (ao << 20) | (normal << 16) | block_type

def push_face_ao(chunks_refs, mesh, dir, vpos, color, block_type):
    ambient_corners = ambient_corner_voxels(chunks_refs, dir, vpos)
    quad = Quad.from_direction(dir, vpos, color)
    for i, corner in enumerate(quad.corners):
        index = i * 2
        side_1 = ambient_corners[index]
        side_2 = ambient_corners[(index + 2) % 8]
        side_corner = ambient_corners[(index + 1) % 8]
        ao_count = side_1 + side_2 + side_corner
        if side_1 == 1 and side_2 == 1:
            ao_count = 3
        mesh.vertices.append(make_vertex_u32(corner, ao_count, dir.get_normal(), block_type))
```

**Parameters:**
*   `ao_count`: Ambient occlusion value for the vertex, ranging from 0 (fully open) to 3 (fully occluded) [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Boundary Sampling:** When processing voxels at the edge of a chunk, `ambient_corner_voxels` must sample from neighboring chunks to avoid incorrect AO values [S1, unofficial].
*   **Anisotropy:** The diagonal split of the quad affects AO interpolation. If diagonal vertex pairs have different AO sums, the shading gradient may appear inconsistent. Anisotropy correction (flipping the diagonal) is required if $(AO_{00} + AO_{11}) \neq (AO_{10} + AO_{01})$ [S2, unofficial].
*   **Precision:** AO values are discrete integers (0–3). The evidence maps these tiers to brightness factors (1.0, 0.7, 0.5, and 0.2) and bakes them directly into vertex data [S2, unofficial].

## Subtopics

### [Multi-Block Binary Meshing with AO](4534-multi-block-binary-meshing-with-ao.md)
Multi-Block Binary Meshing with AO generates mesh vertices for a specific face direction within a voxel chunk by iterating over all block types and axes, packing ambient occlusion (AO) values into a vertex index (`p_index`). It builds on [Binary Greedy Voxel Meshing with Ambient Occlusion](4465-binary-greedy-voxel-meshing-with-ambient-occlusion.md) [G]. Unlike its sibling [Binary Greedy Voxel Meshing without Ambient Occlusion](4536-binary-greedy-voxel-meshing-without-ambient-occlusion.md), which treats all non-air blocks as opaque and outputs vertices with `ao=0`, this method preserves per-vertex AO values derived from surrounding voxel solidity.

### [Greedy Quad Vertex Generation with AO and Anisotropy](4535-greedy-quad-vertex-generation-with-ao-and-anisotropy.md)
Converts a greedy mesh quad into four vertex indices while applying ambient occlusion (AO) blending and correcting for interpolation anisotropy. It solves the problem where vertex-based AO values create visible seams or inconsistent shading gradients across a quad face due to the arbitrary direction of the splitting diagonal. It differs from its parent [Binary Greedy Voxel Meshing with Ambient Occlusion](4465-binary-greedy-voxel-meshing-with-ambient-occlusion.md) by actively rotating the vertex order to ensure the diagonal connects vertices with higher combined occlusion, thereby smoothing the gradient.

### Neighbor-Block Sampling (The 4-State Vertex Model)
A runtime technique that evaluates the solid state of neighboring voxels directly surrounding each vertex of an exposed face to calculate ambient occlusion (AO) values for baking into vertex data [S2, unofficial]. When generating a quad for a voxel face, each of the four vertices touches three neighboring voxel positions in the plane perpendicular to the face: two edge-adjacent neighbors (sharing an edge with the face) and one corner-diagonal neighbor (sharing only a corner with the face) [S2, unofficial]. The AO value is calculated using a lookup table or simple summation: if both edge-adjacent blocks are solid, the corner block is fully occluded regardless of its state, yielding maximum occlusion (value of 3) [S2, unofficial]. If neither edge block is solid, the corner block determines whether the value is 0 (open air) or 1 (corner blocked) [S2, unofficial]. If only one edge block is solid, the value scales proportionally (value of 1 or 2 depending on the corner) [S2, unofficial]. This yields four discrete shading tiers (0 to 3), which are mapped to brightness factors (such as 1.0, 0.7, 0.5, and 0.2) and baked directly into vertex data [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of voxels in the chunk. Each voxel is processed once, and AO calculation involves constant-time neighbor lookups [S1, unofficial].
*   **Memory Complexity:** $O(V)$ where $V$ is the number of vertices. Each exposed face generates 4 vertices with AO attributes [S1, unofficial].
*   **Performance:** Measured performance depends on chunk size and neighbor sampling overhead. Boundary sampling can be a bottleneck if not optimized, as it may require accessing multiple chunks [S1, unofficial].
*   **Strengths:** Provides visually improved shading for blocky meshes without requiring complex lighting calculations. Adaptations are required for greedy meshing pipelines [S2, unofficial].
*   **Limitations:** AO values are static and baked into vertices, meaning they do not update dynamically with camera position or lighting changes. Anisotropy artifacts can occur if not corrected [S2, unofficial].

*   **When Not to Use:** Not given in the sources.
