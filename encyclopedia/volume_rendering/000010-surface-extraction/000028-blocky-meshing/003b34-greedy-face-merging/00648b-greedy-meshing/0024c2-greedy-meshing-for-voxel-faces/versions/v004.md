# Greedy Meshing for Voxel Faces

Also called: Greedy Meshing for Voxels, Greedy Meshing with Face Attributes, Greedy meshing for complex voxel data, Quad merging, Voxel face greedy meshing, Voxel face merging

## Overview
Greedy Meshing for Voxel Faces reduces triangle count in voxel rendering by merging adjacent coplanar voxel faces into larger rectangular quads based on multiple attributes (type, transparency, lighting) rather than just voxel existence [S1, S3, unofficial]. Unlike standard greedy meshing which merges voxels based on type alone, this method compares voxel faces using a custom equality check, allowing for face culling and attribute-based merging [S1, S3, unofficial]. It differs from [Greedy Meshing](3519-greedy-meshing.md) by operating on face-level attributes rather than block-level presence, and from [Voxel Mesh Generation (Run-based Greedy Meshing)](3127-voxel-mesh-generation-run-based-greedy-meshing.md) by supporting complex per-face comparisons [S1, S3, unofficial].

## How it works
**Inputs:** A 3D voxel grid `voxels[CHUNK_WIDTH][CHUNK_HEIGHT][CHUNK_WIDTH]` where each cell contains a `VoxelFace` object.
**Outputs:** A set of quads representing the visible surface.

**Data Structures:**
*   `VoxelFace`: Contains fields `transparent` (boolean), `type` (int), `side` (int). The `equals` method returns true if `face.transparent == this.transparent && face.type == this.type` [S1, S3, unofficial].
*   `mask`: A 1D array of size `CHUNK_WIDTH * CHUNK_HEIGHT` storing `VoxelFace` references or null [S1, S3, unofficial].
*   `x[3]`: Current position array [S1, S3, unofficial].
*   `q[3]`: Direction vector for neighbor check [S1, S3, unofficial].
*   `du[3]`, `dv[3]`: Delta vectors for quad dimensions [S1, S3, unofficial].

**Parameters:**
*   `VOXEL_SIZE`: Size of a single voxel in world units. Default: 1 [S1, S3, unofficial].
*   `CHUNK_WIDTH`, `CHUNK_HEIGHT`: Dimensions of the voxel chunk. Example: 3 [S3, unofficial].

**Steps:**
1.  Initialize working arrays: `x[3]`, `q[3]`, `du[3]`, `dv[3]` to 0. Create `mask` array of size `CHUNK_WIDTH * CHUNK_HEIGHT` [S1, S3, unofficial].
2.  Loop over 6 face directions using a boolean toggle loop: `for (boolean backFace = true, b = false; b != backFace; backFace = backFace && b, b = !b)` [S1, S3, unofficial]. This iterates twice: once for back faces, once for front faces [S3, unofficial].
3.  Inside the direction loop, iterate `d` from 0 to 2 (3 dimensions) [S1, S3, unofficial].
    *   Calculate perpendicular axes `u = (d + 1) % 3` and `v = (d + 2) % 3` [S1, S3, unofficial].
    *   Reset `x` to 0 [S1, S3, unofficial].
    *   Set `q[d] = 1` (direction vector for neighbor check), others 0 [S1, S3, unofficial].
    *   Determine `side` (face normal) based on `d` and `backFace`:
        *   If `d == 0`: `side = backFace ? WEST : EAST`
        *   If `d == 1`: `side = backFace ? BOTTOM : TOP`
        *   If `d == 2`: `side = backFace ? SOUTH : NORTH` [S1, S3, unofficial].
4.  Sweep through the depth dimension `d` from `x[d] = -1` up to `CHUNK_WIDTH` [S1, S3, unofficial].
    *   Compute the mask for the current slice:
        *   Reset `n = 0` [S1, S3, unofficial].
        *   Loop `x[v]` from 0 to `CHUNK_HEIGHT - 1` and `x[u]` from 0 to `CHUNK_WIDTH - 1` [S1, S3, unofficial].
        *   Get `voxelFace` at `(x[0], x[1], x[2])` if `x[d] >= 0`, else null [S1, S3, unofficial].
        *   Get `voxelFace1` at `(x[0] + q[0], x[1] + q[1], x[2] + q[2])` if `x[d] < CHUNK_WIDTH - 1`, else null [S1, S3, unofficial].
        *   If both faces exist and are equal (`voxelFace.equals(voxelFace1)`), set `mask[n] = null` [S1, S3, unofficial].
        *   Otherwise, set `mask[n] = backFace ? voxelFace1 : voxelFace` [S1, S3, unofficial].
        *   Increment `n` [S1, S3, unofficial].
    *   Increment `x[d]` [S1, S3, unofficial].
5.  Generate mesh from mask:
    *   Reset `n = 0` [S1, S3, unofficial].
    *   Loop `j` from 0 to `CHUNK_HEIGHT - 1` and `i` from 0 to `CHUNK_WIDTH - 1` [S1, S3, unofficial].
    *   If `mask[n]` is not null:
        *   Calculate width `w`: Start `w = 1`. While `i + w < CHUNK_WIDTH` and `mask[n + w]` is not null and `mask[n + w].equals(mask[n])`, increment `w` [S1, S3, unofficial].
        *   Calculate height `h`: Start `h = 1`. Loop while `j + h < CHUNK_HEIGHT`. Inside, loop `k` from 0 to `w - 1`. Check if `mask[n + k + h * CHUNK_WIDTH]` is null or not equal to `mask[n]`. If so, set `done = true` and break. If `done` is true, break the height loop [S1, S3, unofficial].
        *   If `mask[n].transparent` is false, create quad:
            *   Set `x[u] = i`, `x[v] = j` [S1, S3, unofficial].
            *   Set `du[u] = w`, `dv[v] = h`, others 0 [S1, S3, unofficial].
            *   Call `quad()` with vertices: `(x[0], x[1], x[2])`, `(x[0] + du[0], x[1] + du[1], x[2] + du[2])`, `(x[0] + du[0] + dv[0], x[1] + du[1] + dv[1], x[2] + du[2] + dv[2])`, `(x[0] + dv[0], x[1] + dv[1], x[2] + dv[2])`, width `w`, height `h`, face `mask[n]`, and `backFace` flag [S1, S3, unofficial].
        *   Zero out the processed mask region: Loop `l` from 0 to `h - 1`, loop `k` from 0 to `w - 1`, set `mask[n + k + l * CHUNK_WIDTH] = null` [S1, S3, unofficial].
        *   Increment `i` by `w` and `n` by `w * h` (implied by traversal logic) [S1, S3, unofficial].

**Pitfalls:**
*   Transparent faces must be skipped during meshing to avoid rendering culled geometry [S1, S3, unofficial].
*   A face whose four corners have different lighting values must not be merged with neighbors to preserve correct ambient occlusion shading [S2, unofficial].

## Subtopics

### [Greedy Meshing with Block Type Masking](14703-greedy-meshing-with-block-type-masking.md)
Extends this method by ensuring that adjacent voxel faces are merged into a single quad only if they share the same block type (e.g., material, texture) and orientation. Unlike standard greedy meshing, which merges all coplanar faces regardless of material, this method preserves visual distinctions between different block types (e.g., keeping grass and dirt transitions separate) while still maximizing quad size within homogeneous regions.

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:** On a flat chunk of ground, the number of quads is reduced from 2,048 to 2 [S2, S3, unofficial].
*   **Strengths:** Significantly reduces draw calls for large flat surfaces while preserving per-corner lighting details [S2, unofficial]. Allows for complex material merging based on multiple attributes [S1, S3, unofficial].
*   **Limitations:** Transparent faces must be handled separately to avoid rendering issues [S1, S3, unofficial]. Unevenly lit faces cannot be merged, potentially limiting optimization in complex lighting scenarios [S2, unofficial].
*   **When to use:** When voxel rendering requires optimization of large flat surfaces with complex material or lighting attributes.
*   **When not to use:** When transparent blocks are prevalent and require separate handling, or when lighting varies significantly across adjacent faces [S2, unofficial].

## Background
Originated from Mikola Lysenko's JavaScript implementation described in a blog post [S1, S3, unofficial]. Ported to Java by Robert O'Leary for use in the jMonkeyEngine, with modifications to compare voxel faces rather than voxels themselves and to provide for comparison based on multiple attributes simultaneously [S1, S3, unofficial]. Implemented in the 'mira' voxel engine in the file `src/voxel/mesher.rs` as part of Phase 3 [S2, unofficial].
