# Greedy Meshing

Also called: 3D Greedy Meshing, Greedy Meshing for Opaque Blocks, Greedy Meshing for Voxel Terrain, Greedy Surface Extraction, GreedyMesh

## Overview
Greedy Meshing is a surface extraction algorithm that converts discrete 3D voxel data into optimized triangle meshes by merging adjacent coplanar faces of identical voxel types into larger quads [S1, S2, S4, S6, unofficial]. It solves the problem of excessive vertex and draw call counts in voxel worlds by reducing primitive density while preserving sharp, axis-aligned surfaces suitable for architectural geometry [S6, unofficial]. It differs from standard face culling (which only removes hidden faces) by actively merging contiguous blocks into maximal axis-aligned rectangles, and it differs from Marching Cubes by maintaining discrete voxel boundaries rather than smoothing surfaces [S2, S6, unofficial].

## How it works
Greedy Meshing builds on [Greedy face merging](8935-greedy-face-merging.md). The algorithm processes the voxel volume along each of the three principal axes ($n \in \{0, 1, 2\}$ corresponding to X, Y, Z). For each normal $n$, the algorithm defines the tangent $t = (n + 1) \pmod 3$ and bitangent $b = (n + 2) \pmod 3$.

### Inputs and Outputs
- **Input**: A voxel volume accessible via a function `volume(x, y, z)` returning a material ID (or integer type), and dimensions `dims = (Dx, Dy, Dz)`.
- **Output**: A list of quads, where each quad is defined by an origin $(x, y, z)$, a normal $n$, and dimensions $(w, h)$.

### Data Structures
- **Mask**: A 1D array of size $D_t \times D_b$ (where $D_t, D_b$ are the dimensions of the tangent and bitangent axes). Each cell stores the `mergeKey` of the voxel if it is visible and unprocessed, or $0$ if it is hidden or already processed.
- **Merge Key**: A value derived from the voxel's material ID and potentially other attributes (e.g., lighting, UV offset). Two faces merge only if their merge keys are identical. By default, the merge key is the material ID itself [S15, unofficial].

### Steps
1. **Initialize**: Create an empty list `quads`.
2. **Sweep Axes**: Iterate over the three normal axes $n \in \{0, 1, 2\}$.
3. **Sweep Slices**: For each normal $n$, iterate through each slice index $s$ from $0$ to $D_n - 1$.
4. **Build Visibility Mask**: For each cell $(t, b)$ in the slice $s$:
   - Determine the voxel coordinates: $V = \text{volume}(coords)$, where $coords[n]=s, coords[t]=t, coords[b]=b$.
   - Check visibility: A face is exposed if the voxel $V(s, t, b)$ differs from its neighbor in the normal direction $V(s \pm 1, t, b)$, or if the neighbor is out of bounds and the boundary policy dictates an exposed surface.
   - If exposed, set `mask[b * D_t + t] = merge_key(V, s, t, b)`. Otherwise, set `mask[b * D_t + t] = 0`.
5. **Greedy Expansion**: Scan the 2D mask in lexicographic order (row $b$ from $0$ to $D_b-1$, column $t$ from $0$ to $D_t-1$) to find maximal rectangles.
   - Find the first unprocessed non-zero cell $(t_0, b_0)$ with key $K$.
   - **Expand Width**: Increment width $w$ starting at $1$ while $t_0 + w < D_t$ and `mask[b_0 * D_t + (t_0 + w)] == K`.
   - **Expand Height**: Increment height $h$ starting at $1$ while $b_0 + h < D_b$. For each potential $h$, check if all cells in the rectangle $[t_0, t_0 + w) \times [b_0, b_0 + h)$ have key $K$. If any cell does not match, stop expanding height.
   - **Emit Quad**: Add a quad with origin $(t_0, b_0, s)$, normal $n$, width $w$, and height $h$ to `quads`.
   - **Mark Processed**: Set all cells in the rectangle $[t_0, t_0 + w) \times [b_0, b_0 + h)$ in the mask to $0$ to prevent double-counting.

### Pseudocode
```python
def greedy_meshing(volume, dims, boundary_policy="air", merge_key=None):
    """
    volume: function (x, y, z) -> material_id
    dims: tuple (Dx, Dy, Dz)
    boundary_policy: "air" (default) or "solid"
    merge_key: function (material_id, x, y, z) -> int. Default: identity.
    """
    if merge_key is None:
        merge_key = lambda m, x, y, z: m

    quads = []
    # Iterate over the 3 normal axes: 0=X, 1=Y, 2=Z
    for n in range(3):
        t = (n + 1) % 3  # Tangent axis
        b = (n + 2) % 3  # Bitangent axis
        dim_t, dim_b, dim_n = dims[t], dims[b], dims[n]
        
        # Mask stores the merge key if visible and unprocessed, else 0
        mask = [0] * (dim_t * dim_b)
        
        # Iterate through each slice along the normal axis
        for s in range(dim_n):
            # 1. Build Visibility Mask for slice s
            for y in range(dim_b):
                for x in range(dim_t):
                    coords = [0, 0, 0]
                    coords[n] = s
                    coords[t] = x
                    coords[b] = y
                    voxel_val = volume(*coords)
                    
                    exposed = False
                    # Check both neighbors along the normal axis
                    for dir in [-1, 1]:
                        nb_s = s + dir
                        if 0 <= nb_s < dim_n:
                            nb_coords = coords.copy()
                            nb_coords[n] = nb_s
                            nb_val = volume(*nb_coords)
                            if voxel_val != nb_val:
                                exposed = True
                                break
                        else:
                            # Out of bounds neighbor
                            if boundary_policy == "air":
                                exposed = True  # Air neighbor implies exposed face
                                break
                            else:  # solid
                                exposed = False  # Solid neighbor implies internal
                                break
                    
                    if exposed:
                        mask[y * dim_t + x] = merge_key(voxel_val, *coords)
                    else:
                        mask[y * dim_t + x] = 0

            # 2. Greedy Expansion on the 2D Mask
            for y in range(dim_b):
                for x in range(dim_t):
                    idx = y * dim_t + x
                    key = mask[idx]
                    
                    if key == 0:
                        continue
                    
                    # Start of a new quad
                    w = 1
                    # Expand width
                    while x + w < dim_t and mask[y * dim_t + (x + w)] == key:
                        w += 1
                    
                    h = 1
                    # Expand height
                    while y + h < dim_b:
                        row_match = True
                        for k in range(w):
                            if mask[(y + h) * dim_t + (x + k)] != key:
                                row_match = False
                                break
                        if not row_match:
                            break
                        h += 1
                    
                    # Emit Quad
                    origin = [0, 0, 0]
                    origin[n] = s
                    origin[t] = x
                    origin[b] = y
                    quads.append({
                        'origin': origin,
                        'normal': n,
                        'width': w,
                        'height': h
                    })
                    
                    # Mark cells as processed (set to 0)
                    for dy in range(h):
                        for dx in range(w):
                            mask[(y + dy) * dim_t + (x + dx)] = 0
                            
    return quads
```

### Parameters and Typical Values
- **Chunk Size**: Typically $16 \times 16 \times 16$ or $32 \times 32 \times 32$ blocks [S7, S36, unofficial].
- **Boundary Policy**: "air" is standard for open worlds; "solid" may be used for closed volumes [S15, unofficial].
- **Merge Key**: Defaults to material ID. Can include ambient occlusion, UV offsets, or transparency flags [S30, S40, unofficial].

### Edge Cases and Pitfalls
- **Precision**: Integer coordinates are sufficient for block positions. Floating point errors are not a concern for the meshing logic itself, but vertex generation must handle coordinate scaling correctly [S6, unofficial].
- **Boundaries**: Out-of-bounds neighbors must be handled explicitly. Treating them as "air" ensures the outer surface is rendered; treating them as "solid" hides the outer surface [S15, unofficial].
- **Degenerate Input**: Empty volumes produce no quads. Volumes with no exposed faces (e.g., fully solid) produce no quads.

## Subtopics

### [Chunked Voxel Mesh Generation with Face Culling and Quad Expansion](3133-chunked-voxel-mesh-generation-with-face-culling-and-quad-exp.md)
Chunked Voxel Mesh Generation with Face Culling and Quad Expansion is a CPU-based algorithm that converts discrete 3D voxel data into optimized triangle meshes by merging adjacent coplanar faces of identical voxel types into larger quads. It solves the problem of excessive vertex and draw call counts in voxel worlds by reducing primitive density while preserving sharp, axis-aligned surfaces suitable for architectural geometry. It differs from standard face culling (which only removes hidden faces) by actively merging contiguous blocks into maximal axis-aligned rectangles, and it differs from Marching Cubes by maintaining discrete voxel boundaries rather than smoothing surfaces. This method builds on [Greedy Meshing](3519-greedy-meshing.md) by processing data in fixed-size chunks and handling inter-chunk visibility.

### [Greedy Meshing for Voxel Faces](3367-greedy-meshing-for-voxel-faces.md)
Greedy Meshing for Voxel Faces is a mesh simplification technique that reduces the number of triangles and draw calls in voxel rendering by merging adjacent coplanar voxel faces into larger rectangular quads. Unlike standard greedy meshing, which merges voxels based solely on existence or a single block type, this method compares voxel faces based on multiple attributes (such as material type, transparency, and lighting) to determine mergeability. It builds on [Greedy Meshing](3519-greedy-meshing.md) by extending the 2D slice processing to handle face-level attributes, ensuring that only faces with identical attributes are merged.

### [Integrating AO with Greedy Meshing](5550-integrating-ao-with-greedy-meshing.md)
Integrating Ambient Occlusion (AO) with Greedy Meshing resolves the conflict between merging coplanar voxel faces into large quads and the natural variation of occlusion values across individual block boundaries. Unlike standard greedy meshing which prioritizes minimal polygon count, this method enforces strict visual continuity of lighting by ensuring that the interpolated shading on a merged quad accurately represents the occlusion of every unit face it replaces. It achieves this through specific merge rules, compact data packing, or shader-based reconstruction strategies.

### [Greedy Meshing (Back Face)](16006-greedy-meshing-back-face.md)
Greedy Meshing (Back Face) is a specialized surface extraction method that generates quads for the back-facing surfaces (negative Z direction) of a voxel chunk. It extends the 2D greedy meshing algorithm to three dimensions by extracting 2D slices from the 3D voxel grid along the Z-axis and processing them to merge adjacent blocks of the same type into larger rectangles. It is distinct from general greedy meshing [3519-greedy-meshing.md] because it operates exclusively on the back-facing boundary, requiring specific handling of neighbor chunks to determine visibility at the chunk's rear edge.

### SBUG Mesh Entry Point
- **Definition**: A specific implementation entry point for greedy meshing that manages output buffers for 6 face directions [S44, unofficial].
- **Steps**:
  1. Define `MAX_FACE_QUADS` as $(CS \times CS \times CS)$ [S44, unofficial].
  2. Initialize `outputs[6]` and `begins[6]` arrays. For each face 0-5, if `md.vertices[face].size()` is less than `MAX_FACE_QUADS`, resize it to `MAX_FACE_QUADS`. Set `begins[face]` and `outputs[face]` to `md.vertices[face].data()` [S44, unofficial].
  3. Call `mesh_face_columns_all_x_slices(voxels, opaque_mask, md, outputs)` to perform the greedy meshing [S44, unofficial].
  4. Reset `md.vertex_count` to 0. For each face 0-5, calculate `md.face_vertex_counts[face]` as `(size_t)(outputs[face] - begins[face])` and add it to `md.vertex_count` [S44, unofficial].
  5. Return `md.vertex_count` [S44, unofficial].

### 4D Greedy Meshing
- **Definition**: Greedy meshing is applied to the 4D voxel world to merge coplanar faces. Although neighboring cells present polygons at different angles in slice space, the preimage of a convex set under a linear map (`to_4d`) is convex. Therefore, a box of cells presents one convex polygon at any angle, allowing greedy meshing to work if it sweeps in lattice space (4D) rather than slice space (3D) [S45, unofficial].
- **Pitfall**: Re-merging in a third dimension recovers only about 1% of quads at any cut, contrary to earlier design notes claiming no further merging was possible. The turned hyperplane meets more cells, each bringing its own edges, limiting further merging [S45, unofficial].
- **Performance**: Greedy meshing reduction ratios compared to naive per-face meshing for different cut configurations: Flat cut: 1.41x (before merging 2.47x); ZW only: 1.96x (before 3.45x); Both planes: 3.05x (before 4.97x); Hard tilt: 3.58x (before 4.98x). Overall performance: Greedy meshing produces 5.3x fewer triangles than naive per-face meshing (CI gated at 4.5x minimum) [S45, unofficial].

### VBO Indexing Optimization
- **Steps**: After greedy meshing, VBO indexing is applied to reduce vertex count from 6 vertices per face to 4 vertices per face [S4, unofficial].
- **Comparison**: This optimization further reduces the quad count by 1/3 compared to the greedy meshing output alone [S4, unofficial].

### Padded Chunk Volume Meshing
- **Definition**: Meshes a $32^3$ chunk using a $34^3$ padded volume that includes its 26 immediate neighbours to ensure seamless borders and AO [S46, unofficial].
- **Steps**:
  1. Gather the 26 neighbouring chunks' voxel data to form a $34^3$ padded volume [S46, unofficial].
  2. Mesh the padded volume so that borders and per-vertex AO are seamless in all three axes [S46, unofficial].

## Operating characteristics
- **Time Complexity**: $O(V)$, where $V$ is the number of voxels in the chunk. Each voxel is visited a constant number of times (once per axis, once per slice, and once during mask expansion).
- **Memory Complexity**: $O(D_t \times D_b)$ for the mask, which is $O(D^2)$ for a chunk of size $D$. This is significantly smaller than storing a full mesh.
- **Measured Performance**: On a 16x16x16 chunk, greedy meshing can reduce vertex count by 10-20x compared to naive per-face rendering [S17, unofficial]. In a scene of 5x1x5 chunks, it can achieve ~140 FPS on average with VSYNC deactivated [S4, unofficial].
- **Scaling**: Performance scales linearly with chunk size. Larger chunks allow for more merging but increase memory usage for the mask and mesh buffer.
- **Strengths**: Simple to implement, deterministic, produces minimal quads for blocky geometry, low memory overhead.
- **Limitations**: Only merges axis-aligned faces. Does not handle transparency well without additional logic (transparent faces are often kept unit-sized) [S40, unofficial]. Does not smooth surfaces.
- **When to Use**: Ideal for voxel games, terrain rendering, and any application with discrete, blocky geometry where draw call reduction is critical.
- **When Not to Use**: Not suitable for smooth, organic geometry (use Marching Cubes) or for highly transparent scenes where sorting and per-face attributes are required.

## Background
Greedy Meshing was popularized by Mikola Lysenko in his 2012 article "Meshing in a Minecraft Game" [S5, unofficial][S32]. It is a refinement of earlier face culling techniques, offering a significant reduction in primitive count by merging adjacent coplanar faces. The algorithm has become a standard technique in voxel engine development, used in engines like Minecraft, Noa, and various custom voxel engines [S5, S8, S16, unofficial]. It is often implemented in CPU-side meshing pipelines to generate static or semi-static geometry for GPU rendering [S4, S18, unofficial].
