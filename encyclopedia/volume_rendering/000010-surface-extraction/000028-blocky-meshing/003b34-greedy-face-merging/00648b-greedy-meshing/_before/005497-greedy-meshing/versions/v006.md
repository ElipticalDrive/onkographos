# Greedy Meshing

Also called: 3D Greedy Meshing, GreedMesh, Greedy Mesher, Greedy Quad Merging, Greedy Quad Meshing, Greedy Voxel Meshing, GreedyMesh

## Overview
Greedy Meshing is a surface extraction algorithm that converts a voxel volume into a manifold triangle mesh by merging adjacent coplanar faces of identical material into larger rectangular quads [S1, S2, S3, S4, S5, S7, S8, S9, S10, S11, S12, S13, S14, S15, S16, S17, S18, S19, S20, unofficial][S21][S22, S23, S24, S25, S26, S27, S28, S29, S30, unofficial][S31][S32, S33, S34, S35, S36, unofficial][S37][S38, S39, S40, S41, unofficial]. It solves the problem of excessive vertex counts and draw calls in naive voxel rendering (one quad per exposed face) by reducing geometry by 1.88×–2.60× in triangle count and up to 54.5× in memory compared to methods like Marching Cubes, while maintaining a blocky aesthetic [S3, S16, S32, unofficial]. It sets itself apart from its parent [Greedy face merging](8935-greedy-face-merging.md) by explicitly defining the 3D sweep and expansion logic for voxel chunks, and from siblings like [Binary Greedy Meshing with Packed Quads](3312-binary-greedy-meshing-with-packed-quads.md) by supporting multiple voxel types and attributes rather than just binary occupancy [S3, S4, S15, S33, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A voxel volume accessed via a function `volume(x, y, z)` returning a material ID (integer), dimensions `dims = (D_x, D_y, D_z)`, a `boundary_policy` ("air" or "solid") [S1, S14, S15, unofficial], and an optional `merge_key` function `(material, x, y, z) -> int` to determine merge compatibility (default: identity) [S1, S14, unofficial].
*   **Output:** A list of quads, where each quad is defined by an origin `(x, y, z)`, a normal `n \in \{0, 1, 2\}` (X, Y, Z), and dimensions `(w, h)` [S1, S7, S14, unofficial].

**Data Structures:**
*   **Mask:** A 2D array of size `D_t \times D_b` (where `t` and `b` are the tangent and bitangent axes for the current normal `n`). It stores the `merge_key` of the voxel if the face is exposed and unprocessed, or `0` otherwise [S1, S7, S14, unofficial].
*   **Coordinates:** A 3-element array `coords` mapping indices to axes `[x, y, z]` [S1, S7, unofficial].

**Steps:**
1.  **Iterate Normals:** Loop over the three principal axes `n \in \{0, 1, 2\}` [S1, S7, unofficial].
2.  **Define Axes:** For each `n`, calculate tangent `t = (n + 1) \pmod 3` and bitangent `b = (n + 2) \pmod 3` [S1, S7, unofficial].
3.  **Sweep Slices:** Iterate through each slice index `s` from `0` to `D_n - 1` along the normal axis [S1, S7, unofficial].
4.  **Build Visibility Mask:** For each cell `(x, y)` in the 2D slice (where `x` corresponds to `t` and `y` to `b`):
    *   Construct coordinates `coords` with `coords[n] = s`, `coords[t] = x`, `coords[b] = y` [S1, S7, unofficial].
    *   Check visibility: The face is exposed if the voxel `V = volume(*coords)` differs from its neighbor in the normal direction. The neighbor is at `s \pm 1` [S1, S7, unofficial].
    *   If the neighbor is out of bounds, apply `boundary_policy`: "air" treats it as exposed (different from solid), "solid" treats it as internal (same as solid) [G] [S1, S14, unofficial].
    *   If exposed, set `mask[y * D_t + x] = merge_key(V, *coords)`. Otherwise, set to `0` [S1, S7, S14, unofficial].
5.  **Greedy Expansion:** Scan the mask in lexicographic order (row `y` from `0` to `D_b-1`, column `x` from `0` to `D_t-1`) [S1, S7, unofficial]:
    *   If `mask[y * D_t + x] == 0`, continue [S1, S7, unofficial].
    *   Let `key = mask[y * D_t + x]` [S1, S7, unofficial].
    *   **Expand Width:** Initialize `w = 1`. While `x + w < D_t` and `mask[y * D_t + (x + w)] == key`, increment `w` [S1, S7, unofficial].
    *   **Expand Height:** Initialize `h = 1`. While `y + h < D_b`:
        *   Check if the entire row segment `[x, x + w)` at height `y + h` matches `key`. That is, for all `k \in [0, w)`, `mask[(y + h) * D_t + (x + k)] == key` [S1, S7, unofficial].
        *   If the row matches, increment `h`. Otherwise, break [S1, S7, unofficial].
    *   **Emit Quad:** Create a quad with origin `(x, y, s)`, normal `n`, width `w`, and height `h` [S1, S7, unofficial].
    *   **Mark Processed:** Set `mask[(y + dy) * D_t + (x + dx)] = 0` for all `dy \in [0, h)` and `dx \in [0, w)` to prevent double-counting [S1, S7, unofficial].

**Pseudocode:**
```python
def greedy_meshing(volume, dims, boundary_policy="air", merge_key=None):
    """
    volume: function (x, y, z) -> material_id
    dims: tuple (Dx, Dy, Dz)
    boundary_policy: "air" (default) or "solid"
    merge_key: function (material_id, x, y, z) -> int. Default: identity.
    """
    if merge_key is None:
        merge_key = lambda m, x, y, z: m

    quads = []
    # Iterate over the 3 normal axes: 0=X, 1=Y, 2=Z
    for n in range(3):
        t = (n + 1) % 3  # Tangent axis
        b = (n + 2) % 3  # Bitangent axis
        dim_t, dim_b, dim_n = dims[t], dims[b], dims[n]
        
        # Mask stores the merge key if visible and unprocessed, else 0
        mask = [0] * (dim_t * dim_b)
        
        # Iterate through each slice along the normal axis
        for s in range(dim_n):
            # 1. Build Visibility Mask for slice s
            for y in range(dim_b):
                for x in range(dim_t):
                    coords = [0, 0, 0]
                    coords[n] = s
                    coords[t] = x
                    coords[b] = y
                    voxel_val = volume(*coords)
                    
                    exposed = False
                    # Check both neighbors along the normal axis
                    for dir in [-1, 1]:
                        nb_s = s + dir
                        if 0 <= nb_s < dim_n:
                            nb_coords = coords.copy()
                            nb_coords[n] = nb_s
                            nb_val = volume(*nb_coords)
                            if voxel_val != nb_val:
                                exposed = True
                                break
                        else:
                            # Out of bounds neighbor
                            if boundary_policy == "air":
                                exposed = True  # Air neighbor implies exposed face
                                break
                            else:  # solid
                                exposed = False  # Solid neighbor implies internal
                                break
                    
                    if exposed:
                        mask[y * dim_t + x] = merge_key(voxel_val, *coords)
                    else:
                        mask[y * dim_t + x] = 0

            # 2. Greedy Expansion on the 2D Mask
            for y in range(dim_b):
                for x in range(dim_t):
                    idx = y * dim_t + x
                    key = mask[idx]
                    
                    if key == 0:
                        continue
                    
                    # Start of a new quad
                    w = 1
                    # Expand width
                    while x + w < dim_t and mask[y * dim_t + (x + w)] == key:
                        w += 1
                    
                    h = 1
                    # Expand height
                    while y + h < dim_b:
                        row_match = True
                        for k in range(w):
                            if mask[(y + h) * dim_t + (x + k)] != key:
                                row_match = False
                                break
                        if not row_match:
                            break
                        h += 1
                    
                    # Emit Quad
                    origin = [0, 0, 0]
                    origin[n] = s
                    origin[t] = x
                    origin[b] = y
                    quads.append({
                        'origin': origin,
                        'normal': n,
                        'width': w,
                        'height': h
                    })
                    
                    # Mark cells as processed (set to 0)
                    for dy in range(h):
                        for dx in range(w):
                            mask[(y + dy) * dim_t + (x + dx)] = 0
                            
    return quads
```

**Parameters and Edge Cases:**
*   **Merge Key:** By default, voxels merge only if they have the exact same material ID [S1, S14, unofficial]. Variants may include ambient occlusion, UV mapping, or transparency in the key [S29, S38, unofficial].
*   **Boundary Policy:** Determines if the outer surface of the chunk is rendered. "Air" (default) renders faces at the chunk boundary; "Solid" treats the outside as solid, hiding boundary faces [S1, S14, unofficial].
*   **Precision:** The algorithm is integer-based and deterministic [S15, unofficial].
*   **Degenerate Input:** Empty volumes produce no quads. Fully solid volumes with "solid" boundary policy produce no quads.

## Subtopics

### [Voxel Mesh Generation (Run-based Greedy Meshing)](3127-voxel-mesh-generation-run-based-greedy-meshing.md)
A CPU-based algorithm optimizing for generation speed over minimal triangle count using a linear scan and `done` mask, suitable for real-time chunk regeneration.

### [Chunked Voxel Mesh Generation with Face Culling and Quad Expansion](3133-chunked-voxel-mesh-generation-with-face-culling-and-quad-exp.md)
Handles neighbor chunk references for cross-chunk visibility and uses packed integer formats for vertex attributes.

### [Binary Greedy Meshing with Packed Quads](3312-binary-greedy-meshing-with-packed-quads.md)
Operates on packed binary planes using bitwise operations for significant performance gains on binary occupancy data.

### [Greedy Meshing for Voxel Faces](3367-greedy-meshing-for-voxel-faces.md)
Merges based on per-face attributes (lighting, transparency) rather than just block type.

### [Integrating AO with Greedy Meshing](5550-integrating-ao-with-greedy-meshing.md)
Enforces visual continuity of lighting by ensuring merged quads accurately represent occlusion values.

### [Greedy Meshing with Vertex Pooling](6808-greedy-meshing-with-vertex-pooling.md)
Combines meshing with memory management for vertex buffers, batching quads into shared pools to reduce driver overhead.

### [Greedy Meshing / Face Culling](8783-greedy-meshing-face-culling.md)
Generates static meshes by culling internal faces but does not merge adjacent coplanar faces into larger quads.

### SBUG Mesh Entry Point
An implementation detail where the meshing process is triggered via `mesh_face_columns_all_x_slices`, initializing output buffers for 6 face directions and resetting vertex counts [S42, unofficial].

### 4D Greedy Meshing
Extends the algorithm to 4D voxel worlds by sweeping in lattice space (4D) rather than slice space (3D), leveraging the convexity of preimages under linear maps. It achieves a 5.3x reduction in triangles compared to naive per-face meshing, though re-merging in a third dimension recovers only ~1% of quads [S43, unofficial].

### VBO Indexing Optimization
A post-processing step applied after greedy meshing that reduces vertex count from 6 to 4 per face by sharing vertices, further reducing quad count by 1/3 [S4, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(V)$ where $V$ is the number of voxels, as each voxel is visited a constant number of times (once per axis slice) [S1, S7, S15, unofficial].
*   **Memory Complexity:** $O(D_t \times D_b)$ for the mask per slice, plus $O(Q)$ for the output quads, where $Q$ is the number of merged quads [S1, S7, unofficial].
*   **Performance:** Reduces vertex count 10-20x compared to naive per-face rendering [S16, S32, unofficial]. In a 5x1x5 chunk scene, it can achieve ~140 FPS with VSYNC off [S4, unofficial].
*   **Strengths:** Simple to implement, deterministic, fast generation, significant reduction in draw calls [S1, S4, S15, S27, unofficial].
*   **Limitations:** Not globally optimal (greedy choice may prevent larger merges later); sensitive to sweep order (Z→Y→X is often optimal for architecture) [S25, S33, unofficial]; does not handle transparency well without keeping unit-sized quads [S38, unofficial].
*   **When to Use:** Static or semi-static voxel terrain where mesh generation cost is acceptable and draw call reduction is critical [S1, S4, S15, unofficial].
*   **When Not to Use:** Highly dynamic scenes requiring frequent mesh regeneration where generation speed is paramount (consider [Voxel Mesh Generation (Run-based Greedy Meshing)](3127-voxel-mesh-generation-run-based-greedy-meshing.md)) or when smooth surfaces are required (consider [Marching Cubes](link)) [S27, S35, unofficial].

## Background
Greedy Meshing was popularized by Mikola Lysenko in his 2012 article "Meshing in a Minecraft Game" [S5, unofficial][S31]. It is a refinement of face culling, which only removes internal faces, by additionally merging adjacent coplanar faces into larger primitives [S1, S5, unofficial][S31]. The algorithm is widely used in voxel engines like Minecraft clones and procedural terrain generators to optimize rendering performance [S1, S4, S5, S15, S27, unofficial].
