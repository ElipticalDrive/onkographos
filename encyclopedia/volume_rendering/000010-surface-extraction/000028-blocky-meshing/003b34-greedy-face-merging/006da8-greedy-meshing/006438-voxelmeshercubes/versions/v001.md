# VoxelMesherCubes


## Overview
VoxelMesherCubes generates a mesh representing cubic voxels directly from color values stored in a `VoxelBuffer.CHANNEL_COLOR` channel [S1]. Unlike its parent [Greedy Meshing](18808-greedy-meshing.md), which optimizes for triangle count via quad merging, VoxelMesherCubes focuses on faithful geometric representation of individual cubes, though it optionally supports greedy merging [S1]. It differs from [Voxel Meshing via Column Flushing](21370-voxel-meshing-via-column-flushing.md) by generating individual cube faces rather than merged column segments, making it suitable for standard vertex color rendering without custom shader logic for color mapping [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A `VoxelBuffer` containing color data in `CHANNEL_COLOR`. An optional `Image` for `generate_mesh_from_image`.
*   **Output:** A `Mesh` resource where colors are stored in the `COLOR` vertex attribute [S1].

**Data Structures:**
*   **VoxelBuffer:** Stores voxel colors. The interpretation depends on `color_mode` [S1].
*   **VoxelColorPalette:** Used in `COLOR_MESHER_PALETTE` mode to map voxel indices to colors [S1].

**Parameters:**
*   `color_mode` (enum `ColorMode`): Determines color interpretation. Default: `COLOR_RAW` (0) [S1].
*   `greedy_meshing_enabled` (bool): Enables greedy meshing to merge contiguous faces of the same color. Default: `true` [S1].
*   `opaque_material` (Material): Material for opaque parts.
*   `transparent_material` (Material): Material for transparent parts (alpha < max).
*   `palette` (VoxelColorPalette): Required for `COLOR_MESHER_PALETTE` [S1].

**Color Mode Interpretations:**
1.  **COLOR_RAW (0):** Voxel values are interpreted directly as colors [S1].
    *   **8-bit voxels:** Interpreted as `rrggbbaa` (2 bits per component). The range per component is converted from $0..3$ to $0..255$ [S1].
    *   **16-bit voxels:** Interpreted as `rrrrgggg bbbbaaaa` (4 bits per component). The range per component is converted from $0..15$ to $0..255$ [S1].
    *   **32-bit voxels:** Interpreted as `rrrrrrrr gggggggg bbbbbbbb aaaaaaaa` (8 bits per component). Each component is in $0..255$ [S1].
2.  **COLOR_MESHER_PALETTE (1):** Voxel values are indices into the `palette` property [S1].
3.  **COLOR_SHADER_PALETTE (2):** Voxel values are written directly to the `COLOR` vertex attribute's red component, with green and blue set to zero. The value is normalized to $0..1$ in the shader. The alpha component is set to the transparency of the corresponding color in the palette. A `ShaderMaterial` is required; `StandardMaterial` will not work [S1].

**Algorithm Steps:**
1.  Read voxel colors from `VoxelBuffer.CHANNEL_COLOR` [S1].
2.  Apply `color_mode` to determine the final vertex color for each voxel face [S1].
    *   If `COLOR_RAW`, decode bits according to voxel bit-depth [S1].
    *   If `COLOR_MESHER_PALETTE`, lookup color from `palette` using voxel value as index [S1].
    *   If `COLOR_SHADER_PALETTE`, set `COLOR.r = voxel_value / 255.0`, `COLOR.g = 0`, `COLOR.b = 0`, and `COLOR.a = palette[voxel_value].a` [S1].
3.  Generate mesh geometry for cubic voxels [S1].
4.  If `greedy_meshing_enabled` is true, merge contiguous faces with identical colors to reduce polygon count [S1].
5.  Assign `opaque_material` or `transparent_material` based on the alpha value of the generated colors [S1].

**Pseudocode:**
```python
def generate_mesh(voxel_buffer, color_mode, greedy_meshing_enabled, palette, opaque_material, transparent_material):
    vertices = []
    indices = []
    colors = []
    
    # Iterate over all voxels in the buffer
    for voxel in voxel_buffer:
        raw_value = voxel.value
        final_color = decode_color(raw_value, color_mode, palette)
        
        # Determine material based on alpha
        if final_color.a == 255:
            material = opaque_material
        else:
            material = transparent_material
            
        # Generate cube geometry for this voxel
        # Note: Specific vertex generation logic for cubes is assumed from VoxelMesher base
        cube_vertices, cube_indices, cube_colors = generate_cube_geometry(voxel.position, final_color)
        
        vertices.extend(cube_vertices)
        indices.extend(offset_indices(cube_indices, len(vertices)))
        colors.extend(cube_colors)
        
    # Apply greedy meshing if enabled
    if greedy_meshing_enabled:
        vertices, indices, colors = greedy_merge_faces(vertices, indices, colors)
        
    return create_mesh(vertices, indices, colors, material)

def decode_color(raw_value, color_mode, palette):
    if color_mode == COLOR_RAW:
        if voxel_bit_depth == 8:
            # 2 bits per component, range 0..3 to 0..255
            r = ((raw_value >> 6) & 0x3) * 85
            g = ((raw_value >> 4) & 0x3) * 85
            b = ((raw_value >> 2) & 0x3) * 85
            a = (raw_value & 0x3) * 85
            return Color(r, g, b, a)
        elif voxel_bit_depth == 16:
            # 4 bits per component, range 0..15 to 0..255
            r = ((raw_value >> 12) & 0xF) * 17
            g = ((raw_value >> 8) & 0xF) * 17
            b = ((raw_value >> 4) & 0xF) * 17
            a = (raw_value & 0xF) * 17
            return Color(r, g, b, a)
        elif voxel_bit_depth == 32:
            r = (raw_value >> 24) & 0xFF
            g = (raw_value >> 16) & 0xFF
            b = (raw_value >> 8) & 0xFF
            a = raw_value & 0xFF
            return Color(r, g, b, a)
    elif color_mode == COLOR_MESHER_PALETTE:
        return palette[raw_value]
    elif color_mode == COLOR_SHADER_PALETTE:
        # Red component stores value, normalized. Alpha from palette.
        r = raw_value / 255.0
        a = palette[raw_value].a
        return Color(r, 0.0, 0.0, a)
```

## Subtopics

### [Voxel Meshing via Column Flushing](21370-voxel-meshing-via-column-flushing.md)
A GPU-accelerated method that sweeps along one axis to merge contiguous filled voxels into quads. Choose this when vertex/index count reduction is critical and custom shaders are acceptable. It avoids complex neighbor lookups by using column flushing.

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Performance:** Not given in the sources.
*   **Strengths:** Simple integration with standard vertex color rendering; supports multiple color encoding formats (8, 16, 32-bit); optional greedy meshing for optimization [S1].
*   **Limitations:** `COLOR_SHADER_PALETTE` requires custom shaders; `StandardMaterial` is incompatible with `COLOR_SHADER_PALETTE` [S1].
*   **When to use:** When a direct cubic voxel representation is needed with vertex colors, or when greedy meshing is desired but the column-flushing approach is not suitable.
*   **When not to use:** When high-performance GPU-based column merging is required, or when standard materials must be used with shader-palette colors.

## Background
VoxelMesherCubes is part of the Voxel Tools suite, a set of tools for voxel-based game development and rendering [S1]. It inherits from `VoxelMesher` and provides a straightforward way to convert voxel color data into 3D meshes [S1].
