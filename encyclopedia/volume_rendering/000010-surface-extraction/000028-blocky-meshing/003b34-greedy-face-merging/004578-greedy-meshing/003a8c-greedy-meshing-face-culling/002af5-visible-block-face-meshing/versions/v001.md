# Visible Block Face Meshing

Also called: Voxel Face Culling, Voxel Face Visibility Culling, Greedy Meshing-lite, Immediate Mode Culling

## Overview
Visible Block Face Meshing is a surface extraction technique that generates a static triangle mesh for a voxel chunk by iterating through occupied voxel positions and emitting geometry only for faces that are adjacent to empty space or transparent blocks [S1, S2, S3, unofficial]. It differs from its parent method, [Voxel Chunk Mesh Generation (Face Culling)](4888-voxel-chunk-mesh-generation-face-culling.md), by explicitly handling cross-chunk boundary visibility checks to ensure global consistency, and it differs from [Greedy Meshing](52-greedy-meshing.md) by not merging adjacent coplanar faces into larger quads [S1, S2, unofficial]. This approach reduces vertex count and draw calls compared to naive voxel rendering by excluding internal faces, while maintaining a simpler implementation than greedy approaches [S2, unofficial].

## How it works
### Inputs and Outputs
**Inputs:**
*   `chunk`: A 3D array of voxel data representing the current chunk.
*   `neighbor_faces`: A map or structure providing visibility data for the six faces of the chunk (adjacent chunks) [S1, unofficial].
*   `block_textures`: Appearance data for the blocks [S1, unofficial].
*   `visibility_checker`: An interface or function to query block solidity/visibility [S1, unofficial].

**Outputs:**
*   `Mesh`: A triangle mesh containing vertices and indices for all visible block faces [S1, unofficial].

### Data Structures
**Voxel Vertex Layout:**
Each voxel is a cube with side length `Voxel::EDGE_LENGTH`. The 8 vertices are defined in a local coordinate system where the voxel spans `[0, EDGE_LENGTH]` in X, Y, and Z. The indices are fixed as follows [S2, unofficial]:
*   0: `(0, 0, 0)`
*   1: `(0, E, 0)`
*   2: `(E, E, 0)`
*   3: `(E, 0, 0)`
*   4: `(0, 0, E)`
*   5: `(0, E, E)`
*   6: `(E, E, E)`
*   7: `(E, 0, E)`
Where $E = \text{Voxel::EDGE_LENGTH}$. Indices 0-3 form the front face ($Z=0$), and 4-7 form the back face ($Z=E$) [S2, unofficial].

**Block/Chunk Structure:**
*   **Block:** Contains a boolean `active` flag and a boolean array `visibleFaces[6]` indexed by `BlockFace` enum: `XPos=0`, `XNeg=1`, `YPos=2`, `YNeg=3`, `ZPos=4`, `ZNeg=5` [S3, unofficial].
*   **Chunk:** Stores blocks as a 3D pointer array `Block ***blocks` allocated as `new Block **[CHUNK_SIZE]` where each element is `new Block *[CHUNK_SIZE]` containing `new Block[CHUNK_SIZE]` [S3, unofficial].
*   **Parameters:**
    *   `CHUNK_SIZE`: Dimension of a chunk in blocks, typically 4 [S3, unofficial].
    *   `BLOCK_SIZE`: Physical size of a block, typically 10 [S3, unofficial].
    *   `NUMBER_OF_VOXELS_PER_DIMENSION`: Number of voxels along one axis in a chunk [S2, unofficial].
    *   `NUMBER_OF_VOXELS`: Total voxels in a chunk, calculated as `NUMBER_OF_VOXELS_PER_DIMENSION^3` [S2, unofficial].

### Algorithm Steps
1.  **Prepare Padded Chunk:**
    Call `prepare_padded_chunk(chunk, neighbor_faces, visibility_checker)` to ensure boundary visibility checks have valid neighbor data. This step queries adjacent chunks to determine if faces on the chunk boundary are occluded by blocks in neighboring chunks [S1, S3, unofficial].

2.  **Iterate Voxels:**
    Iterate over each voxel in the chunk using a 1D index `i` from $0$ to `NUMBER_OF_VOXELS - 1` [S2, unofficial].
    Convert `i` to 3D coordinates $(x, y, z)$ using:
    $$
    \begin{aligned}
    x &= i \pmod{\text{NUMBER\_OF\_VOXELS\_PER\_DIMENSION}} \\
    y &= (i / \text{NUMBER\_OF\_VOXELS\_PER\_DIMENSION}) \pmod{\text{NUMBER\_OF\_VOXELS\_PER\_DIMENSION}} \\
    z &= i / (\text{NUMBER\_OF\_VOXELS\_PER\_DIMENSION}^2)
    \end{aligned}
    $$
    [S2, unofficial]

3.  **Check Visibility:**
    For each active voxel at $(x, y, z)$, check the six neighbors: $(x+1, y, z)$, $(x-1, y, z)$, $(x, y+1, z)$, $(x, y-1, z)$, $(x, y, z+1)$, $(x, y, z-1)$ [S3, unofficial].
    A neighbor blocks a face if:
    *   The neighbor coordinate is within the current chunk bounds ($0 \le \text{coord} < \text{CHUNK\_SIZE}$) AND the neighbor block is active [S2, S3, unofficial].
    *   The neighbor coordinate is outside the current chunk bounds, AND the corresponding block in the adjacent global chunk is active [S3, unofficial].
    
    Global chunk coordinates for out-of-bounds neighbors are calculated as [S3, unofficial]:
    $$
    \begin{aligned}
    x_{\text{Chunk}} &= \lfloor x / (\text{CHUNK\_SIZE} \times \text{BLOCK\_SIZE}) \rfloor \\
    y_{\text{Chunk}} &= \lfloor y / (\text{CHUNK\_SIZE} \times \text{BLOCK\_SIZE}) \rfloor \\
    z_{\text{Chunk}} &= \lfloor z / (\text{CHUNK\_SIZE} \times \text{BLOCK\_SIZE}) \rfloor
    \end{aligned}
    $$
    [S3, unofficial]

4.  **Emit Geometry:**
    If a face is visible (not blocked by an active neighbor), emit 2 triangles (6 vertices) using the predefined vertex indices for that face, offset by `shared_index_buffer_offset = i * 8`. Add one color entry to `color_data` [S2, unofficial].
    
    *   **Front Face (Negative Z, $z-1$):** Indices `{0, 1, 2, 0, 2, 3}` [S2, unofficial].
    *   **Back Face (Positive Z, $z+1$):** Indices `{4, 6, 5, 4, 7, 6}` [S2, unofficial].
    *   **Left Face (Negative X, $x-1$):** Indices `{4, 5, 1, 4, 1, 0}` [S2, unofficial].
    *   **Right Face (Positive X, $x+1$):** Indices `{3, 2, 6, 3, 6, 7}` [S2, unofficial].
    *   **Top Face (Positive Y, $y+1$):** Indices `{1, 5, 6, 1, 6, 2}` [S2, unofficial].
    *   **Bottom Face (Negative Y, $y-1$):** Indices `{4, 0, 3, 4, 3, 7}` [S2, unofficial].

### Pseudocode
```python
def mesh_chunk_visible_block_faces(chunk, neighbor_faces, visibility_checker, block_textures):
    # Step 1: Prepare padded chunk data for boundary checks
    samples = prepare_padded_chunk(chunk, neighbor_faces, visibility_checker)
    
    vertices = []
    indices = []
    colors = []
    
    chunk_size = samples.chunk_size
    edge_length = samples.edge_length
    shared_index_buffer_offset = 0
    
    # Step 2: Iterate over each voxel
    for i in range(chunk_size ** 3):
        # Convert 1D index to 3D coordinates
        x = i % chunk_size
        y = (i // chunk_size) % chunk_size
        z = i // (chunk_size ** 2)
        
        # Check if voxel is active
        if not samples.is_active(x, y, z):
            continue
            
        # Step 3 & 4: Check 6 neighbors and emit faces
        # Define neighbor directions and corresponding vertex indices for the face
        # Order: Front(Z-), Back(Z+), Left(X-), Right(X+), Top(Y+), Bottom(Y-)
        faces = [
            {"dir": (0, 0, -1), "verts": [0, 1, 2, 0, 2, 3]},
            {"dir": (0, 0, 1), "verts": [4, 6, 5, 4, 7, 6]},
            {"dir": (-1, 0, 0), "verts": [4, 5, 1, 4, 1, 0]},
            {"dir": (1, 0, 0), "verts": [3, 2, 6, 3, 6, 7]},
            {"dir": (0, 1, 0), "verts": [1, 5, 6, 1, 6, 2]},
            {"dir": (0, -1, 0), "verts": [4, 0, 3, 4, 3, 7]}
        ]
        
        for face in faces:
            dx, dy, dz = face["dir"]
            nx, ny, nz = x + dx, y + dy, z + dz
            
            # Check if neighbor blocks this face
            is_blocked = False
            
            if 0 <= nx < chunk_size and 0 <= ny < chunk_size and 0 <= nz < chunk_size:
                # Neighbor is within current chunk
                if samples.is_active(nx, ny, nz):
                    is_blocked = True
            else:
                # Neighbor is outside current chunk, check global world
                # Calculate global chunk coordinates
                block_size = samples.block_size
                chunk_dim = samples.chunk_size * block_size
                
                # Global voxel coordinates
                gx = x * block_size + dx * block_size
                gy = y * block_size + dy * block_size
                gz = z * block_size + dz * block_size
                
                # Global chunk indices
                gx_chunk = gx // chunk_dim
                gy_chunk = gy // chunk_dim
                gz_chunk = gz // chunk_dim
                
                # Query global world for block solidity
                if visibility_checker.is_block_solid(gx_chunk, gy_chunk, gz_chunk, nx, ny, nz):
                    is_blocked = True
            
            if not is_blocked:
                # Emit 2 triangles (6 vertices)
                # Calculate vertex positions
                base_x = x * edge_length
                base_y = y * edge_length
                base_z = z * edge_length
                
                # Local vertex offsets for a unit cube [0,1]^3 scaled by edge_length
                # 0:(0,0,0), 1:(0,E,0), 2:(E,E,0), 3:(E,0,0), 4:(0,0,E), 5:(0,E,E), 6:(E,E,E), 7:(E,0,E)
                local_verts = [
                    (0, 0, 0), (0, 1, 0), (1, 1, 0), (1, 0, 0),
                    (0, 0, 1), (0, 1, 1), (1, 1, 1), (1, 0, 1)
                ]
                
                for idx in face["verts"]:
                    lx, ly, lz = local_verts[idx]
                    vx = base_x + lx * edge_length
                    vy = base_y + ly * edge_length
                    vz = base_z + lz * edge_length
                    vertices.append((vx, vy, vz))
                    indices.append(shared_index_buffer_offset + idx)
                    colors.append(block_textures.get_color(x, y, z))
                
                shared_index_buffer_offset += 8
                
    return create_mesh(vertices, indices, colors)
```

### Edge Cases and Pitfalls
*   **Boundary Checks:** Accessing neighbor voxels requires strict boundary checks to avoid out-of-bounds array access. For example, checking `index_3d.z != 0` before accessing `z-1` is required [S2, unofficial].
*   **Cross-Chunk Consistency:** Faces on chunk boundaries must be checked against adjacent chunks to prevent gaps or double-rendering. This is handled by the `visibility_checker` and `neighbor_faces` inputs [S1, S3, unofficial].
*   **Precision:** Floating-point precision issues may arise when calculating world offsets for vertices and chunk positions, especially with large coordinate values [S2, S3, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of voxels in the chunk. Each voxel is processed once, and up to 6 faces are checked.
*   **Memory Complexity:** $O(F)$ where $F$ is the number of visible faces. Each visible face generates 6 vertices and 6 indices.
*   **Performance:** Benchmarks show that `mesh_chunk_visible_block_faces` is significantly faster than `mesh_chunk_greedy_quads` for sparse chunks (e.g., 30% fill probability) because it avoids the complexity of quad merging [S1, unofficial].
*   **Strengths:** Simple implementation, low memory overhead for sparse chunks, no need for complex quad merging logic.
*   **Limitations:** Higher vertex count and draw calls compared to Greedy Meshing for dense chunks, as adjacent coplanar faces are not merged [S1, S2, unofficial].
*   **When to Use:** Suitable for sparse voxel worlds, dynamic environments where mesh regeneration is frequent, or when implementation simplicity is prioritized over optimal vertex count [S1, S2, unofficial].
*   **When Not to Use:** Not suitable for dense voxel worlds where vertex count optimization is critical, or when draw call reduction is a primary concern [S1, S2, unofficial].

## Background
Visible Block Face Meshing is a fundamental technique in voxel rendering, originating from early voxel engines like Wolfenstein 3D-style raycasting and later adapted for 3D voxel games like Minecraft [S3, unofficial]. The specific implementation details described here, including the use of padded chunks and cross-chunk visibility checks, are derived from modern voxel engine implementations such as Infinigen and Voxel1993 [S1, S3, unofficial]. The technique is widely used in game development for generating static geometry for voxel chunks [S2, unofficial].
