# VoxelBlockyModelMesh

Also called: Mesh model
## Overview
VoxelBlockyModelMesh is a surface extraction method that generates voxel geometry from a user-defined custom mesh resource rather than a primitive cube. It solves the problem of creating non-cubic, complex voxel shapes (such as trees, rocks, or furniture) while retaining the performance benefits of blocky meshing, including face culling and greedy merging. It differs from sibling methods like [Voxel Block Placement with Face Culling](923-voxel-block-placement-with-face-culling.md) by decoupling the visual geometry from the logical voxel unit, allowing arbitrary mesh shapes to be tiled into a voxel grid.

## How it works
### Inputs and Outputs
**Inputs:**
1.  **Source Mesh:** A 3D mesh resource (typically OBJ format) imported into the engine.
    *   Must be indexed (e.g., via `SurfaceTool.index`).
    *   Must consist of triangles.
    *   Must be confined within a bounding box from $(0,0,0)$ to $(1,1,1)$.
    *   The mesh origin must be at its lower corner $(0,0,0)$.
    *   Vertices should preferably lie within the $0..1$ range in all directions.
    *   Supports up to 2 surfaces (materials); surfaces beyond the second are ignored [S2].
2.  **Configuration Parameters:**
    *   `mesh_ortho_rotation_index`: Integer specifying orthogonal rotation (GridMap convention) [S2].
    *   `side_cutout_enabled`: Boolean flag for occlusion culling [S2].
    *   `side_vertex_tolerance`: Float margin for side classification (default $0.001$) [S2].

**Outputs:**
*   A set of mesh instances placed in the voxel grid, with faces culled based on neighbor occlusion and merged where possible.

### Data Structures
The method relies on the engine's native mesh resource structure. The source mesh is stored as a collection of indexed triangle surfaces. Each surface contains vertex positions, normals, and UV coordinates. The UV coordinates must be assigned within the 3D modeler, as the engine does not generate them procedurally for custom meshes [S1].

### Steps
1.  **Preparation:** The source mesh is prepared in a 3D editor (e.g., Blender) such that it is confined in a bounding box from $(0,0,0)$ to $(1,1,1)$ and uses classic UV-mapping [S2].
2.  **Import:** The mesh is exported in OBJ format and imported into the engine as a Mesh resource [S1].
3.  **Assignment:** The Mesh resource is assigned to the `VoxelBlockyModelMesh` configuration.
4.  **Rotation:** If `mesh_ortho_rotation_index` is non-zero, the mesh is rotated according to the GridMap tile convention before baking [S2].
5.  **Placement:** The mesh is instantiated at each voxel position in the grid.
6.  **Side Classification:** For each voxel, triangles are classified as belonging to one of the 6 sides of the unit cube. A triangle is considered to be on a specific side if its vertices are within `side_vertex_tolerance` of that side's plane [S2].
7.  **Culling:**
    *   **Neighbor Culling:** If `side_cutout_enabled` is true, the mesher checks neighboring voxels. If a neighbor partially covers a side of the current voxel, the occluded geometry on that side is cut away [S2].
    *   **Constraint:** Side cutout only functions if the shape of both interacting sides is a rectangle [S2].
    *   **Transparency:** Face culling uses the model's overall transparency properties. If a model is defined as non-transparent, its sides will be culled even if the middle is transparent [S1].
8.  **Assembly:** The remaining visible geometry is assembled into the final mesh.

### Parameters
*   `mesh`: The source Mesh object. Must not be empty. Must be indexed. Must consist of triangles. Only triangles within the 0..1 area are considered; specifically, only those on the sides of the cubic area are used for neighbor side culling [S2].
*   `mesh_ortho_rotation_index`: Integer specifying the orthogonal rotation applied to the mesh during baking. Values follow the GridMap tile convention [S2].
*   `side_cutout_enabled`: Boolean flag. When true, occluded geometry on a voxel side is cut away if a neighbor voxel partially covers it. This optimization only functions if the shape of both interacting sides is a rectangle [S2].
*   `side_vertex_tolerance`: Float margin (default 0.001). Triangles located within this distance from one of the 6 sides of the voxel are considered to be on that side for the purpose of culling decisions against neighbor sides [S2].

### Edge Cases and Pitfalls
*   **Coordinate Systems:** Godot is Y-up, while Blender is Z-up. Ensure exported meshes do not go into negative coordinates when imported [S1].
*   **Performance:** Faces lying on the sides of the 1x1x1 unit cube are the only faces that can be culled. They must line up perfectly; otherwise, dramatic slowdowns occur due to unculled geometry [S1].
*   **Complexity:** Keep models low-poly. Performance decreases quickly if complex models appear frequently [S1].
*   **Transparency:** A second material can be used for meshes with both transparent and opaque parts (two surfaces). However, face culling uses model properties regardless. If a model is defined as non-transparent, its sides will be culled even if the middle is transparent [S1].
*   **Physics Export:** If using mesh-based physics and exporting with 'Export as dedicated server', ensure meshes in VoxelBlockyModelMesh are not stripped, as mesh data is required at runtime to generate colliders [S1].
*   **Side Cutout Overhead:** Enabling `side_cutout_enabled` can result in a higher triangle count compared to when it is disabled [S2].
*   **Material Limits:** If the mesh has more than 2 surfaces (materials), all surfaces after the second are ignored during generation [S2].

## Operating characteristics
*   **Time Complexity:** Not given in the sources. However, performance is heavily dependent on mesh complexity and the number of occurrences. Complex models appearing frequently cause dramatic slowdowns if geometry is not perfectly aligned for culling [S1].
*   **Memory Complexity:** Not given in the sources.
*   **Strengths:** Versatile workflow allowing assignment of a mesh resource instead of cube geometry. Allows creation of complex shapes using standard 3D editor meshes with UV-mapping [S1, S2].
*   **Limitations:** Requires manual UV assignment in a 3D modeler. Performance degrades with high-poly meshes. Side cutout optimization has constraints (rectangular sides only) and can increase triangle count.
*   **When to use:** When voxel shapes need to be non-cubic and complex (e.g., trees, furniture).
*   **When not to use:** When simple cubic voxels are sufficient, or when high-poly meshes are required and performance is critical.

## Background
VoxelBlockyModelMesh is part of the Voxel Tools suite for the Godot Engine. It was developed to provide a more versatile workflow for voxel terrain and object creation, moving beyond simple cube-based geometry. The method leverages Godot's mesh resource system and integrates with the existing blocky meshing infrastructure, including face culling and greedy merging.
