# Cuberille Method

Also called: Cuberille Model, Herman-Liu method, Meagher's method, Octree Cuberille

## Overview
The Cuberille Method renders a 3D volume by treating the segmented object as a collection of discrete, axis-aligned cubes (voxels) and projecting their exposed faces to the image plane [S1, unofficial]. It solves the problem of visualizing binary segmented structures by approximating the true surface with a "hollow polygonal shell" of parallelepipeds [S1, unofficial]. It differs from smooth isosurface methods like [Marching Cubes](30-isosurface-extraction.md) by avoiding interpolation and maintaining the exact discrete grid alignment, which simplifies culling but introduces aliasing artifacts [S1, unofficial].

## How it works
**Inputs and Outputs**:
- Input: A 3D binary array $V$ where $V(x,y,z) = 1$ if the voxel is part of the object (solid) and $0$ if empty. This array is typically generated by thresholding or connectivity-based segmentation [S1, S2, unofficial].
- Output: A rendered image of the object's surface, or a mesh of exposed faces.

**Data Structures**:
1.  **Binary Volume Array**: A 3D grid of bits or bytes. The sources note that this array is often "presorted" in memory, allowing for efficient traversal [S2, unofficial].
2.  **Octree (Optional)**: To handle sparse data, the binary array can be stored in an octree structure. An octree node represents a $2 \times 2 \times 2$ block of voxels. If all voxels in a block are identical (all 0 or all 1), the node becomes a leaf. This reduces memory usage and traversal time for sparse volumes [S2, unofficial].

**Steps**:
1.  **Segmentation**: Threshold the raw volume data to create the binary array $V$. Connectivity algorithms (e.g., Lorenson et al.) or boundary detection (e.g., Udupa) may be used to isolate the object of interest [S1, unofficial].
2.  **Face Identification**: Identify all faces of solid voxels ($V(x,y,z)=1$) that are adjacent to empty space ($V(x',y',z')=0$). Internal faces between two solid voxels are culled [S1, unofficial].
3.  **Traversal and Rendering**:
    -   **Z-Buffer Approach**: Render each of the six faces of every solid voxel into a z-buffer. Since only three faces are visible from any viewpoint, this is an optimization over rendering all six [S1, unofficial].
    -   **Painter's Algorithm**: If the volume array is sorted (e.g., by z-coordinate), traverse the voxels back-to-front. Render the faces of solid voxels in this order, overwriting previous pixels. This avoids the need for a z-buffer [S2, unofficial].
4.  **Shading**: Apply shading to the faces. Due to the discrete nature, standard polyhedral shading causes aliasing (banding) [S1, unofficial].

**Formulas**:
-   **Visibility**: A face at position $p$ with normal $n$ is visible if the voxel at $p+n$ is empty.
-   **Octree Compression**: An octree node is a leaf if $\forall v \in \text{block}, V(v) = c$ where $c \in \{0,1\}$ [S2, unofficial].

**Parameters**:
-   **Threshold**: The scalar value separating object from background. Not given in the sources.
-   **Filtering**: Low-pass filtering may be applied to the final image to reduce banding, at the cost of resolution [S1, unofficial].

**Pitfalls**:
-   **Aliasing/Banding**: The discrete steps of the voxel grid create stair-step artifacts. Naive shading exacerbates this [S1, unofficial].
-   **Information Loss**: The binary decision (solid/empty) discards partial volume information, leading to artifacts in the rendered shell [S1, unofficial].
-   **Normal Estimation**: Estimating a smooth surface normal from discrete voxel faces is difficult. Context normal shading or gradient-based normals from neighboring elements are required for realistic results [S1, unofficial].

**Pseudocode**:
```python
def render_cuberille(volume, use_octree=False, use_painters=True):
    """
    volume: 3D array of 0s and 1s.
    use_octree: If True, traverse an octree representation.
    use_painters: If True, use back-to-front painter's algorithm.
                  If False, use z-buffer.
    """
    if use_octree:
        tree = build_octree(volume)
        voxels = extract_voxels_from_octree(tree)
    else:
        voxels = extract_voxels_from_array(volume)

    # Sort voxels back-to-front if using Painter's algorithm
    if use_painters:
        voxels.sort(key=lambda v: v.center.z, reverse=True)

    for voxel in voxels:
        if voxel.is_empty:
            continue
        
        # Get exposed faces
        faces = get_exposed_faces(voxel, volume)
        
        for face in faces:
            if use_painters:
                # Draw face directly to screen buffer
                draw_face_to_screen(face)
            else:
                # Draw face to z-buffer
                draw_face_to_zbuffer(face)

def get_exposed_faces(voxel, volume):
    """
    Returns the list of exposed faces for a solid voxel.
    A face is exposed if the neighbor in the normal direction is empty.
    """
    faces = []
    x, y, z = voxel.position
    # Check all 6 neighbors
    neighbors = [
        (x+1, y, z, 'x+'), (x-1, y, z, 'x-'),
        (x, y+1, z, 'y+'), (x, y-1, z, 'y-'),
        (x, y, z+1, 'z+'), (x, y, z-1, 'z-')
    ]
    
    for nx, ny, nz, normal in neighbors:
        # Boundary check
        if not is_inside_volume(nx, ny, nz):
            # Edge of volume is considered exposed
            faces.append(Face(voxel.position, normal))
        elif volume[nx, ny, nz] == 0:
            # Neighbor is empty, face is exposed
            faces.append(Face(voxel.position, normal))
            
    return faces
```

## Subtopics

### Slab Extrusion (Staircase Representation)
A variant where 2D slices are thresholded and extruded in the axial direction by the slice-to-slice distance. The resulting slabs are stacked to form a staircase-like representation [S1, unofficial]. It is simpler than the full 3D cuberille but suffers from similar discretization artifacts.

## Operating characteristics
-   **Time Complexity**: $O(N)$ where $N$ is the number of voxels, assuming constant-time face culling. With an octree, complexity depends on the sparsity and tree depth [S2, unofficial].
-   **Memory Complexity**: $O(N)$ for the binary array. Octree storage is $O(S)$ where $S$ is the number of surface voxels, significantly less for sparse data [S2, unofficial].
-   **Performance**: Fast for dense, binary data. Octree traversal adds overhead but speeds up rendering of sparse volumes [S2, unofficial].
-   **Strengths**: Simple implementation; exact alignment with grid; efficient culling of internal faces [S1, unofficial].
-   **Limitations**: Aliasing/banding artifacts; loss of sub-voxel detail; difficult shading [S1, unofficial].
-   **When to use**: Binary segmented data where speed is critical and smoothness is not required.
-   **When not to use**: When smooth surfaces or partial volume information is needed.

## Background
The cuberille model was first defined by Herman et al. [S1, unofficial]. Herman and Liu (1979) proposed the method of thresholding data into a binary array and rendering it as opaque cubes [S2, unofficial]. Meagher (1984) later proposed storing the binary array as an octree to improve traversal speed for sparse data [S2, unofficial]. The method is widely used in medical volume rendering for segmenting organs and structures [S1, unofficial].
