# VoxelMesherBlocky
Also called: Blocky mesher, Minecraft-like mesher

## Overview
VoxelMesherBlocky is a surface extraction method for blocky, voxel-based terrains that generates meshes by combining small geometric primitives corresponding to specific model IDs into larger chunks. It solves the problem of rendering high-density voxel data by culling faces that occlude each other, thereby reducing draw calls and vertex count. Unlike its sibling [Greedy face merging](8935-greedy-face-merging.md), it does not perform greedy meshing to merge adjacent coplanar faces into larger rectangles, resulting in a mesh structure similar to that used in Minecraft.

## How it works
**Inputs:**
1.  Voxel data stored in a `VoxelBuffer` using `CHANNEL_TYPE`.
2.  A `VoxelBlockyLibraryBase` resource containing a list of models (e.g., grass, dirt, wood, leaves, water, stairs, door parts). The index in this list corresponds to the model ID.

**Outputs:**
A chunked mesh where each chunk contains combined small meshes for the active model IDs within that chunk.

**Data Structures:**
*   `VoxelBuffer`: Stores the voxel data. The specific channel type used is `VoxelBuffer.CHANNEL_TYPE`.
*   `VoxelBlockyLibraryBase`: A resource holding the list of models.
*   `VoxelBlockyLibrary`: A specific implementation of the library, which is a simple list of models where the list index serves as the model ID.

**Steps:**
1.  **Library Initialization**: Create or load a `VoxelBlockyLibraryBase`. This library must contain all models intended for use in the voxel mesh. Models can be added programmatically or loaded from a file. [S1]
2.  **Voxel Data Assignment**: Ensure the voxel data is stored in the `VoxelBuffer` using the `CHANNEL_TYPE`. [S1]
3.  **Chunk Processing**: Iterate through the voxel data in chunks.
4.  **Model Identification**: For each voxel or group of voxels, identify the active model ID based on the data in the `VoxelBuffer`.
5.  **Small Mesh Generation**: Generate small meshes corresponding to the identified model IDs. These are the base geometric primitives for each model type. [S1]
6.  **Face Culling**: Cull faces that occlude each other. This step removes internal faces between adjacent solid voxels of the same or compatible types to reduce geometry. [S1]
7.  **Combining into Chunks**: Combine the culled small meshes corresponding to the same model IDs into larger chunks. This reduces the number of draw calls. [S1]
8.  **Mesh Assembly**: Assemble the chunks into the final mesh output.

**Parameters:**
*   `VoxelBlockyLibraryBase`: The library of models. Typical models include grass, dirt, wood, leaves, water, shrubs, stairs, and door parts. [S1]
*   `VoxelBuffer.CHANNEL_TYPE`: The specific channel type used for storing voxel data. [S1]

**Edge Cases and Pitfalls:**
*   **Model ID Mismatch**: Ensure the model ID in the voxel data matches the index in the `VoxelBlockyLibrary`. [S1]
*   **Occlusion Culling**: Incorrect culling may remove visible faces or leave unnecessary internal faces. The method culls faces occluding each other but does not merge them. [S1]
*   **Chunk Size**: The size of the chunks affects memory usage and draw call optimization. Not given in the sources.

    """
    Generates a blocky mesh from voxel data using a library of models.
    
    Args:
        voxel_buffer (VoxelBuffer): The voxel data buffer.
        voxel_library (VoxelBlockyLibraryBase): The library of models.
        
    Returns:
        list: A list of chunks, where each chunk is a combined mesh.
    """
    chunks = []
    
    # Iterate through chunks of voxel data
    for chunk in voxel_buffer.get_chunks():
        chunk_meshes = []
        
        # Iterate through models in the library
        for model_id, model in enumerate(voxel_library.models):
            # Extract voxels for this model ID
            voxels = chunk.get_voxels_with_id(model_id)
            
            if not voxels:
                continue
                
            # Generate small mesh for this model
            small_mesh = model.generate_mesh(voxels)
            
            # Cull occluding faces
            culled_mesh = cull_faces(small_mesh)
            
            # Add to chunk meshes
            chunk_meshes.append(culled_mesh)
        
        # Combine small meshes into a single chunk mesh
        combined_chunk = combine_meshes(chunk_meshes)
        chunks.append(combined_chunk)
        
    return chunks

### Voxel Mesher Bake Process
The Voxel Mesher Bake Process is a minor variant of VoxelMesherBlocky. It involves baking the voxel data and models into a final mesh. **Strengths and Limitations:**
*   **Strengths**: Reduces draw calls by combining meshes into chunks. Culls occluding faces to reduce geometry. Similar to Minecraft, which is a well-understood and efficient approach for blocky terrains. [S1]
*   **Limitations**: Does not perform greedy meshing, which may result in a higher vertex count compared to methods that merge adjacent coplanar faces. [S1]

**When to Use:**
Use VoxelMesherBlocky for blocky, voxel-based terrains where a Minecraft-like appearance is desired. It is suitable when greedy meshing is not required or when the simplicity of the algorithm is preferred. [S1]

**When Not to Use:**
Do not use VoxelMesherBlocky if greedy meshing is required to reduce vertex count further. It is also not suitable for non-blocky terrains. [S1]

## Background
VoxelMesherBlocky is part of the Voxel Tools documentation. It is designed for creating blocky terrains, similar to those found in Minecraft. The method uses a library of models to define the appearance of different voxel types. [S1]
