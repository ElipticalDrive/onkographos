# VoxelMesherBlocky
Also called: Blocky mesher, Minecraft-like mesher
## Overview
VoxelMesherBlocky is a surface extraction method for blocky, voxel-based terrains that combines small meshes corresponding to model IDs into chunks [S1]. It culls occluding faces to reduce draw calls but does not perform greedy meshing, a technique similar to that used in Minecraft [S1].
## How it works
**Inputs and Outputs:**
- Input: Voxel data stored in `VoxelBuffer.CHANNEL_TYPE` [S1].
- Input: A `VoxelBlockyLibraryBase` resource containing a list of models (e.g., grass, dirt, wood, leaves, water, shrubs, stairs, door parts) where the list index corresponds to the model ID [S1].
- Output: A chunked mesh with occluding faces culled [S1].

**Data Structures:**
- `VoxelBlockyLibraryBase`: A resource holding a list of models; the index serves as the unique model ID [S1].
- `VoxelBuffer`: Stores voxel data using the `CHANNEL_TYPE` channel [S1].

**Steps:**
1. **Library Initialization**: Create or load a `VoxelBlockyLibraryBase` resource containing the geometric definitions for all block types [S1].
2. **Voxel Data Access**: Read voxel data from the `VoxelBuffer` using the `CHANNEL_TYPE` channel [S1].
3. **Model Identification**: For each voxel, identify the corresponding model ID based on the buffer data; the library index matches this ID [S1].
4. **Mesh Combination**: Combine small meshes corresponding to these model IDs into chunks by assembling the geometric primitives defined in the library [S1].
5. **Face Culling**: Cull faces that occlude each other within the chunks; adjacent identical faces are not merged into larger quads [S1].

**Parameters:**
- Library: `VoxelBlockyLibraryBase` instance [S1].
- Data Channel: `VoxelBuffer.CHANNEL_TYPE` [S1].

**Edge Cases and Pitfalls:**
- The method does not perform greedy meshing, resulting in higher vertex counts compared to methods that merge adjacent faces [S1].
- Bottom (−Y) faces of blocky blocks and coarse mesh quads wind clockwise when viewed from outside, causing back-face culling (CCW front) to hide them [S2, unofficial]. Fix: reverse the vertex order of the −Y face in `FaceDirection::vertices_and_normal` and the −Y quads in the coarse mesh generator, keeping each vertex's ambient occlusion (AO) value attached to its vertex during reordering [S2, unofficial].
- Pitfall: The winding fix makes undersides visible where they were previously hidden by culling; requires manual verification by looking up at overhangs or structures from below [S2, unofficial].

**Pseudocode:**
```python
class Model:
    def __init__(self, faces):
        self.faces = faces

class Library:
    def __init__(self):
        self.models = []
    def add(self, model):
        self.models.append(model)
    def get(self, index):
        return self.models[index]

class VoxelBuffer:
    CHANNEL_TYPE = "voxel_data"
    def __init__(self, data):
        self.data = data
    def get_channel(self, name):
        return self.data if name == self.CHANNEL_TYPE else None
    def get_chunks(self):
        # Standard grid chunking
        return []

def generate_blocky_mesh(voxel_buffer, library):
    data = voxel_buffer.get_channel(VoxelBuffer.CHANNEL_TYPE)
    chunks = []
    for chunk_voxels in voxel_buffer.get_chunks():
        chunk_faces = []
        for voxel in chunk_voxels:
            model_id = data.get_model_id(voxel.position)
            if model_id is not None:
                model = library.get(model_id)
                chunk_faces.extend(model.faces)
        # Cull occluding faces within the chunk (algorithm not specified in sources)
        visible_faces = chunk_faces
        chunks.append(visible_faces)
    return chunks
```
