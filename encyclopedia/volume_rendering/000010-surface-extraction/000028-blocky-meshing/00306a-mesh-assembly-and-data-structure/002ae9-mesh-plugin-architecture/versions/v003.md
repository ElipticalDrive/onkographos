# Mesh Plugin Architecture
Also called: IMeshingJob
## Overview
The Mesh Plugin Architecture provides an interface for pluggable meshing algorithms, allowing for extensibility within the meshing pipeline [S1, unofficial]. It decouples the specific geometric generation logic (e.g., Greedy Meshing vs. Marching Cubes) from the chunk management system, enabling the selection of appropriate algorithms based on voxel type (blocky vs. smooth) [S1, unofficial].
## How it works
### Inputs and Outputs
*   **Input**: Voxel data (solid or smooth density) and chunk coordinates.
*   **Output**: Mesh primitives (vertices, indices) aggregated into `MeshInfo` structures.

### Data Structures
The architecture relies on the following structures defined in the source implementations:

1.  **`IMeshingJob`**: An interface defining the contract for meshing algorithms. It must support Burst compilation and zero garbage collection (GC) for performance [S1, unofficial].
2.  **`MeshInfo`**: Contains an optional opaque mesh and a vector of translucent meshes [S2, unofficial].
3.  **`MeshStatus`**: An enum tracking the state of a chunk's mesh generation:
    *   `Meshing`: Generation in progress.
    *   `Meshed(Arc<MeshInfo>)`: Generation complete, holding the result.
    *   `Empty`: No mesh data.
4.  **Resource Store**: A hash map mapping `(ChunkPosition, ZoomLevel)` to `MeshStatus` [S2, unofficial].

### Algorithm Selection
The `ChunkManager` handles smart mesher selection based on the voxel data type [S1, unofficial]:
*   **Blocky Voxels**: Uses `GreedyMeshingJob` for face culling.
*   **Smooth Terrain**: Uses `MarchingCubesJob` for smooth geometry.

### Implementation Steps
1.  **Voxel Registration**: The user registers voxel data (solid or smooth) via `ChunkManager.SetVoxel` [S1, unofficial].
2.  **Job Scheduling**: `ChunkManager` uses a spatial hash to schedule jobs automatically [S1, unofficial].
3.  **Execution**: The selected job (e.g., `GreedyMeshingJob` or `MarchingCubesJob`) executes, generating geometry [S1, unofficial].
4.  **Status Update**: The result is stored in the resource store under the corresponding `ChunkPosition` and `ZoomLevel` [S2, unofficial].

### Pseudocode
```python
# Interface definition
class IMeshingJob:
    def execute(self, chunk_data: VoxelChunk) -> MeshInfo:
        """Generates mesh info from voxel chunk."""
        pass

# Concrete implementations
class GreedyMeshingJob(IMeshingJob):
    def execute(self, chunk_data: VoxelChunk) -> MeshInfo:
        # Face culling for blocky voxels
        # Burst-compiled, zero GC
        return MeshInfo(opaque_mesh=generate_opaque(), translucent=[])

class MarchingCubesJob(IMeshingJob):
    def execute(self, chunk_data: VoxelChunk) -> MeshInfo:
        # Simplified MC prototype for smooth terrain
        # Burst-compiled, zero GC
        return MeshInfo(opaque_mesh=generate_mc(), translucent=[])

# Manager logic
class ChunkManager:
    def __init__(self):
        self.mesh_store = HashMap<(ChunkPosition, ZoomLevel), MeshStatus>()
        self.job_map = {
            "blocky": GreedyMeshingJob(),
            "smooth": MarchingCubesJob()
        }

    def process_chunk(self, pos: ChunkPosition, voxel_type: str):
        job = self.job_map[voxel_type]
        # Update status to Meshing
        self.mesh_store[pos] = MeshStatus.Meshing
        # Execute job
        mesh_info = job.execute(self.get_chunk_data(pos))
        # Update status to Meshed
        self.mesh_store[pos] = MeshStatus.Meshed(Arc(mesh_info))
```
## Operating characteristics
*   **Performance**: Jobs are Burst-compiled and designed for zero GC allocation, ensuring high performance in real-time applications [S1, unofficial].
*   **Memory**: Half-precision density storage can save 50% memory (68KB vs 128KB per 32³ chunk) [S1, unofficial].
*   **Extensibility**: New algorithms can be added by implementing the `IMeshingJob` interface [S1, unofficial].
## Background
This architecture originates from the StraightFour voxel engine project, which introduced support for generic, terrain, and smooth voxel meshing [S1, unofficial]. It is also referenced in the Infinigen project, which utilizes similar plugin-based structures for world generation and block type definitions [S2, unofficial].
