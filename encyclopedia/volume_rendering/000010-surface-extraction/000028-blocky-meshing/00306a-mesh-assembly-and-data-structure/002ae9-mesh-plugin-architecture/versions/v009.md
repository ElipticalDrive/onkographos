# Mesh Plugin Architecture
Also called: IMeshingJob

## Overview
The Mesh Plugin Architecture provides an interface for pluggable meshing algorithms, allowing for extensibility within the meshing pipeline [S1, unofficial]. It decouples the meshing process from the assembly process, enabling different algorithms (e.g., greedy meshing vs. marching cubes) to produce standardized mesh data structures [4921-mesh-plugin-architecture.md, unofficial]. This builds on [Mesh Assembly and Data Structure](6268-mesh-assembly-and-data-structure.md) by defining the contract for geometry generation before it enters the buffer organization phase.

## How it works
The architecture relies on a polymorphic interface (`IMeshingJob`) that abstracts the specific meshing algorithm. The system manages the lifecycle of mesh generation through a status tracking mechanism and a manager that handles scheduling.

**Inputs and Outputs:**
*   **Input:** Voxel data (blocky or smooth density fields) and chunk coordinates.
*   **Output:** `MeshInfo` structures containing opaque and translucent mesh data, stored in contiguous arrays as per the parent's principles.

**Data Structures:**
The system tracks the state of mesh generation for each chunk using a hash map.
*   **Mesh Resource Store:** A hash map mapping `(ChunkPosition, ZoomLevel)` to `MeshStatus`.
*   **MeshStatus:** An enum with three variants:
    *   `Meshing`: The mesh is currently being generated.
    *   `Meshed(Arc<MeshInfo>)`: The mesh is complete and ready for use.
    *   `Empty`: The chunk contains no relevant data.
*   **MeshInfo:** Contains an optional opaque mesh and a vector of translucent meshes.

**Numbered Steps:**
1.  **Registration:** The `ChunkManager` registers chunks and assigns them an initial `MeshStatus` of `Empty` or `Meshing` based on voxel presence.
2.  **Selection:** The `ChunkManager` performs smart mesher selection, choosing between blocky (Greedy) or smooth (Marching Cubes) algorithms based on the voxel type [S1, unofficial].
3.  **Execution:** The selected job (implementing `IMeshingJob`) executes. Jobs are typically burst-compiled for performance and designed for zero garbage collection [S1, unofficial].
4.  **Completion:** Upon completion, the `MeshStatus` for the `(ChunkPosition, ZoomLevel)` key is updated to `Meshed(Arc<MeshInfo>)`.
5.  **Assembly:** The assembly phase consumes the `MeshInfo` from the store, applying material mapping and layer separation as defined in the parent article.

**Pseudocode:**
```python
# Interface definition
class IMeshingJob:
    def execute(self, chunk_data: VoxelChunk) -> MeshInfo:
        """Generates mesh data from voxel chunk."""
        pass

# Status Enum
class MeshStatus:
    MESHING = 0
    MESHED = 1
    EMPTY = 2

# Manager Logic
class ChunkManager:
    def __init__(self):
        self.mesh_store = HashMap<(ChunkPosition, ZoomLevel), MeshStatus>()
        self.jobs = {
            "blocky": GreedyMeshingJob(),
            "smooth": MarchingCubesJob()
        }

    def set_voxel(self, pos: int3, data: VoxelData):
        """Updates voxel data and triggers meshing if necessary."""
        # Update underlying voxel storage
        self.voxel_storage.set(pos, data)
        
        # Determine chunk and zoom level
        chunk_pos = self.get_chunk_position(pos)
        zoom_level = self.get_zoom_level(data)
        
        # Update status to Meshing if not already
        key = (chunk_pos, zoom_level)
        if self.mesh_store.get(key) != MeshStatus.MESHING:
            self.mesh_store[key] = MeshStatus.MESHING
            self.schedule_job(key, data)

    def schedule_job(self, key: (ChunkPosition, ZoomLevel), data: VoxelData):
        """Selects and runs the appropriate meshing job."""
        # Smart mesher selection based on data type
        if data.is_smooth():
            job = self.jobs["smooth"]
        else:
            job = self.jobs["blocky"]
            
        # Execute job (conceptually asynchronous in real implementation)
        mesh_info = job.execute(self.voxel_storage.get_chunk(key[0]))
        
        # Update status to Meshed
        self.mesh_store[key] = MeshStatus.MESHED(mesh_info)

# Example Jobs
class GreedyMeshingJob(IMeshingJob):
    def execute(self, chunk: VoxelChunk) -> MeshInfo:
        # Face culling for blocky voxels
        # Burst-compiled, zero GC
        return generate_greedy_mesh(chunk)

class MarchingCubesJob(IMeshingJob):
    def execute(self, chunk: VoxelChunk) -> MeshInfo:
        # Simplified MC prototype for smooth terrain
        # Full lookup tables noted for future implementation
        return generate_marching_cubes_mesh(chunk)
```

**Parameters and Edge Cases:**
*   **Precision:** Half-precision density fields can save 50% memory (e.g., 68KB vs 128KB per 32³ chunk) [S1, unofficial].
*   **Degenerate Input:** If a chunk is empty, the status remains `Empty`, and no job is scheduled.
*   **Missing Materials:** If a specific material is missing, a fallback material is used to prevent null dereferences [4100-chunk-mesh-assembly.md, unofficial].

## Operating characteristics
*   **Time Complexity:** Depends on the specific algorithm (Greedy Meshing is generally faster for blocky voxels; Marching Cubes is more expensive for smooth terrain).
*   **Memory Complexity:** Reduced by using half-precision density where applicable [S1, unofficial].
*   **Performance:** Jobs are designed to be burst-compiled and zero-GC to minimize overhead [S1, unofficial].
*   **Strengths:** Extensibility allows easy addition of new meshing algorithms; decoupling simplifies testing and maintenance.
*   **Limitations:** Requires careful management of the `MeshStatus` state to avoid race conditions in multi-threaded environments.

## Background
The Mesh Plugin Architecture was introduced as part of the foundational voxel engine development in the StraightFour project [S1, unofficial]. It aims to provide a generic, extensible framework for both terrain and smooth voxel support. The concept of pluggable meshing is also reflected in the Infinigen project, which uses a plugin system for world generation and block definitions [S2, unofficial].
