# Block Mesh Alpha Rendering

Also called: ChunkMesh Alpha Rendering, Transparent Face Sorting & Rendering

## Overview
Block Mesh Alpha Rendering is a rendering technique for voxel-based environments that sorts visible chunk meshes back-to-front relative to the camera's primary viewing axis to enable correct alpha blending without requiring full scene depth sorting [S1, unofficial]. It sets itself apart from sibling methods like [Boolean Voxel Meshing](971-boolean-voxel-meshing.md) or [Greedy face merging](8935-greedy-face-merging.md) by operating on pre-generated chunk meshes and relying on a specific spatial traversal order to handle transparency artifacts, rather than modifying the mesh geometry itself [S1, unofficial].

## How it works
**Inputs:** Camera position $(x_c, y_c, z_c)$ in world units; camera view vector $(v_x, v_y, v_z)$ derived from rotation; a collection of chunk meshes, each containing a list of transparent faces indexed in a nested structure `blocksPos[greatestDir][secondary][tertiary][1]` [S1, unofficial].
**Outputs:** A sorted list of chunk indices for rendering, and updated vertex/index buffers for each chunk [S1, unofficial].

### Data Structures
*   **Vertex Packing:** Each vertex is stored as two 32-bit unsigned integers [S1, unofficial].
    *   `vertex0`: Position. Bits 0-9: $x$, Bits 10-19: $y$, Bits 20-31: $z$ [S1, unofficial].
    *   `vertex1`: Texture and shading. Bits 0-9: Texture layer; Bits 10-14: Texture $x$; Bits 15-19: Texture $y$; Bits 20-31: Shade data [S1, unofficial].
*   **Block Position Index (`blocksPos`):** A nested array structure where `blocksPos[greatestDir][secondary][tertiary]` is an array `[coordinate, [index_list]]`. The `index_list` contains the vertex indices for faces at that block position [S1, unofficial].

### Parameters
*   **Chunk Size:** 32x32x32 blocks [S1, unofficial].
*   **Fog Far Distance:** 256 units ($32 \times 8$) [S1, unofficial].
*   **Camera Matrix Scale:** $0.0625$ ($1/16$) to convert world units to chunk units [S1, unofficial].
*   **Alpha Discard Threshold:** Blocks with alpha $< 0.4$ are discarded in the fragment shader [S1, unofficial].

### Algorithm Steps

1.  **Determine Dominant Axis:**
    Calculate the absolute values of the camera's view vector components $|v_x|, |v_y|, |v_z|$. Identify `greatestDir` as the axis (X, Y, or Z) with the maximum absolute value [S1, unofficial].

2.  **Determine Traversal Direction:**
    Calculate `greatestMag` as the signed magnitude of the view vector component along `greatestDir`. If `greatestMag` is negative, reverse the list of blocks along `greatestDir` to ensure traversal starts from the back relative to the camera [S1, unofficial].

3.  **Traverse Blocks (Forward Phase):**
    Iterate through the blocks along `greatestDir`. For each block, iterate through the secondary axis blocks. Use a rectilinear distance check against the camera's position on the other two axes (`otherPos`) [S1, unofficial].
    For each block in the secondary axis, iterate through the tertiary axis blocks. If the block's coordinate is $\ge$ the camera's coordinate on the tertiary axis, break the inner loop and proceed to the reverse iteration of the tertiary axis for that secondary block [S1, unofficial].

4.  **Traverse Blocks (Reverse Phase - Tertiary):**
    After the forward iteration of the tertiary axis, perform a reverse iteration (from end to start) for the same secondary axis block. Add indices for blocks whose coordinate is $<$ the camera's coordinate on the tertiary axis [S1, unofficial].

5.  **Traverse Blocks (Reverse Phase - Secondary):**
    After processing forward iterations for all secondary blocks, perform a reverse iteration of the secondary axis blocks. For each, iterate forward and then backward through the tertiary axis blocks, applying the same coordinate comparison logic against `otherPos` [S1, unofficial].

6.  **Restore Order:**
    If the traversal direction was reversed in Step 2, reverse the `blocksPos` list back to its original order [S1, unofficial].

7.  **Chunk Sorting:**
    When the camera crosses chunk boundaries, calculate `chunkDistances` for all chunks using Manhattan distance:
    $$ \text{chunkDist} = | \text{chunk}.x \times 32 - x_c + 16 | + | \text{chunk}.y \times 32 - y_c + 16 | + | \text{chunk}.z \times 32 - z_c + 16 | $$
    Sort `shaders.alpha.chunkMeshes` in descending order of distance (far to near) [S1, unofficial].

8.  **Update Indices:**
    Call `ChunkMeshAlpha.processCameraData(camera)` to update indices for transparency based on the sorted order [S1, unofficial].

9.  **Render Setup:**
    Set blend function: `gl.blendFuncSeparate(gl.SRC_ALPHA, gl.ONE_MINUS_SRC_ALPHA, gl.ONE, gl.ONE_MINUS_SRC_ALPHA)` [S1, unofficial].

### Edge Cases and Pitfalls
*   **Alpha Threshold:** Transparent blocks with alpha $< 0.4$ are discarded in the fragment shader to prevent rendering artifacts from semi-transparent surfaces that are effectively invisible [S1, unofficial].
*   **Data Structure Assumption:** The index generation algorithm assumes a specific nested array structure for `blocksPos`: `blocksPos[greatestDir][secondary][tertiary][1]` contains the list of indices for each block [S1, unofficial].
*   **Precision:** The vertex packing uses 10-bit integers for position, limiting coordinate precision to $2^{10}=1024$ units per chunk axis. This is sufficient for 32-unit chunks but requires careful handling of world coordinates [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The sorting step is $O(N \log N)$ where $N$ is the number of chunks, based on the Manhattan distance calculation and sorting [S1, unofficial]. The index generation is linear with respect to the number of visible faces in the dominant traversal order.
*   **Memory Complexity:** Depends on the number of transparent faces stored in `blocksPos`. The vertex packing reduces memory usage by storing vertices in two 32-bit integers per vertex [S1, unofficial].
*   **Strengths:** Avoids the high cost of full scene depth sorting for every transparent fragment. Efficiently handles large voxel worlds by sorting at the chunk level [S1, unofficial].
*   **Limitations:** Relies on a specific traversal order which may not be optimal for all camera angles or complex transparent geometries. The alpha discard threshold may cause visual artifacts for very faint transparent blocks [S1, unofficial].
*   **When to use:** Suitable for voxel-based environments with significant transparency (e.g., glass, water) where chunk-based culling is already in place. Not suitable for non-voxel or highly irregular transparent meshes [S1, unofficial].

## Background
Block Mesh Alpha Rendering is implemented in the open-source project Exolands, a voxel-based game engine written in JavaScript [S1, unofficial]. It was developed as part of the optimization suite for handling transparent blocks in a web-based 3D environment, leveraging WebGL2 capabilities [S1, unofficial]. The method is described in the project's source code and documentation as a customized transparent face sorting algorithm [S1, unofficial].
