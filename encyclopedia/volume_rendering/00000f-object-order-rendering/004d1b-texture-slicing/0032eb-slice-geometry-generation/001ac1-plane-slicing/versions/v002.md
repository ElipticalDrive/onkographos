# Plane Slicing

Also called: Multi-Directional Slicing, Multi-axis Slicing, Plane Slicing with Marching Cubes, Slice Plane Rendering

## Overview
Plane Slicing is a direct volume rendering method for unstructured or curvilinear grids that approximates the volume by slicing cells into polygons on evenly spaced planes perpendicular to the X, Y, and Z axes [S1, S2][S3, unofficial]. It differs from ray casting by leveraging spatial coherence through pre-computed planar slices and from standard texture slicing by generating explicit geometry (polygons) for each cell rather than relying solely on hardware texture sampling of a 3D texture [S1, S2][S3, unofficial]. The method selects the set of slices whose axis is closest to the viewing direction and renders them back-to-front using hardware alpha blending [S1, S2][S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar field defined on an unstructured or curvilinear grid (cells with vertex scalar values).
*   **Output:** A 2D image with correct transparency and color mapping.

**Data Structures:**
*   **Slicing Planes:** Three sets of evenly spaced parallel planes, one set perpendicular to each axis (X, Y, Z). The number of planes is typically several hundred per axis [S1, S2][S3, unofficial].
*   **Polygon Arrays:** For each plane in each axis set, an array of polygons (quadrilaterals or triangles) generated from the cells intersected by that plane.
*   **Texture Map:** A 1D texture map storing the transfer function (mapping scalar values to RGBA) [S1, S2][S3, unofficial].

**Steps:**

1.  **Preprocessing (Slicing):**
    *   Generate several hundred evenly spaced slicing planes perpendicular to the X, Y, and Z axes [S1, S2][S3, unofficial].
    *   For each cell in the grid, use a variant of the marching cubes algorithm to slice the cell incrementally into polygons on these three sets of planes [S1, S2][S3, unofficial].
    *   Group the resulting polygons for each slice into an array for efficient rendering [S1, S2][S3, unofficial].
    *   *Note:* This phase is performed once during preprocessing [S1, S2][S3, unofficial].

2.  **Transfer Function Mapping:**
    *   Normalize the scalar values of the polygon vertices to the range [0, 1] [S1, S2][S3, unofficial].
    *   Use these normalized values as 1D texture coordinates to sample the transfer function stored in a 1D texture map [S1, S2][S3, unofficial].
    *   *Optimization:* An alpha dithering technique may be applied to the texture map to expand the range of allowable opacity values for hardware with limited bit depth (e.g., 8 bits per channel), adjusting the per-slice opacity when slice plane spacing changes [S1, S2][S3, unofficial].

3.  **Rendering Selection:**
    *   Determine the viewing direction.
    *   Select the set of slices (X, Y, or Z) whose axis is closest to the viewing direction [S1, S2][S3, unofficial].

4.  **Rendering:**
    *   Render the selected polygons from back to front relative to the viewer [S1, S2][S3, unofficial].
    *   Use hardware-supported opacity blending (alpha blending) to composite the fragments [S1, S2][S3, unofficial].
    *   *Ordering:* Parent objects must be drawn back-to-front to prevent transparent objects from appearing blended in front of obscured objects, especially when different colors are involved [S5, unofficial].

5.  **Progressive Refinement (Optional):**
    *   Initially render with a few slices.
    *   Improve resolution by rendering with more slices as time permits [S1, S2][S3, unofficial].
    *   Users may request a new set of slices perpendicular to any viewing direction [S1, S2][S3, unofficial].

6.  **Anti-aliasing for Small Cells (Optional):**
    *   Cells that fall between slice planes or are too small to be captured by scan conversion may be rendered using anti-aliased ellipsoidal splats [S1, S2][S3, unofficial].
    *   Only cells above a specific volume threshold are sliced; others are splatted [S1, S2][S3, unofficial].

**Parameters:**
*   **Number of Slicing Planes:** Several hundred per axis (e.g., 300) [S1, S2][S3, unofficial].
*   **Volume Threshold:** Cells below this threshold are not sliced but may be rendered as splats [S1, S2][S3, unofficial].

**Edge Cases and Pitfalls:**
*   **Small Cells:** Small cells may be missed between slice planes or during scan conversion. This is addressed by anti-aliased ellipsoidal splats for cells below a threshold [S1, S2][S3, unofficial].
*   **Opacity Precision:** With high slice density, per-slice opacity becomes very low, potentially below hardware precision. Alpha dithering in the texture map mitigates this [S1, S2][S3, unofficial].
*   **Perspective View:** Viewing ray lengths vary between slanted slice planes in perspective views, potentially requiring per-pixel opacity corrections (noted as future work) [S1, S2][S3, unofficial].
*   **Sorting:** Incorrect back-to-front ordering can cause transparent objects to appear in front of obscured objects, especially with different colors [S5, unofficial].

## Subtopics

### [Plane Composing Algorithms](2154-plane-composing-algorithms.md)
Plane Composing Algorithms are a category of direct volume rendering methods that operate by compositing several slices which comprise a volumetric model. They tend to work best when the view-plane is fixed parallel to the model, so that each of the voxels being composed may be accessed on separate planes. This approach differs from ray casting by leveraging spatial coherence through slicing, often enhanced by texture-based rendering techniques.

### View-Oriented Planes Technique
A volume rendering technique using oriented planes that covers the entire data volume with a fixed number of planes [S4, unofficial]. The minimum number of planes required is equal to the number of voxels in the volume diagonal to intercept all possible voxels when the volume is rotated to maximum plane size, calculated as $\sqrt{W^2 + H^2 + D^2}$, where $W, H, D$ are volume dimensions [S4, unofficial]. For example, a volume of $181 \times 217 \times 181$ requires at least 336 planes [S4, unofficial]. This technique suffers from low performance due to insufficient optimizations; the high number of memory accesses makes the gain from alpha testing negligible [S4, unofficial]. Using 400 planes increases image quality but significantly reduces speed due to generated fragments, memory accesses, and blending operations [S4, unofficial].

### Slice Plane Ordering
A rendering rule where parent objects are drawn back-to-front to prevent transparent objects from appearing blended in front of obscured objects [S5, unofficial]. Slice plane ordering is not important when drawing 3D smoke if all smoke has the same color (only opacity varies), but is important when drawing smoke and fire (different colors) or using elaborate lighting algorithms [S5, unofficial].

## Operating characteristics
*   **Time Complexity:** Preprocessing is $O(N \cdot P)$, where $N$ is the number of cells and $P$ is the number of planes per axis, as each cell is sliced against all planes [S1, S2][S3, unofficial]. Rendering is $O(M)$, where $M$ is the number of generated polygons, dominated by rasterization and blending [S1, S2][S3, unofficial].
*   **Memory Complexity:** $O(N \cdot P)$ to store the polygon arrays for all planes [S1, S2][S3, unofficial].
*   **Measured Performance:** The View-Oriented Planes Technique (a variant) with 400 planes on a $181 \times 217 \times 181$ volume significantly reduced speed due to fragments and memory accesses [S4, unofficial].
*   **Strengths:** Leverages hardware rasterization and blending; supports progressive refinement; handles unstructured grids [S1, S2][S3, unofficial].
*   **Limitations:** Preprocessing is expensive; small cells may be missed without splatting; perspective view requires opacity corrections [S1, S2][S3, unofficial].
*   **When to Use:** Interactive visualization of unstructured grids where view direction is known or changes slowly; when hardware blending is available [S1, S2][S3, unofficial].
*   **When Not to Use:** When high-quality perspective rendering with varying ray lengths is critical without post-correction; when memory is constrained due to polygon storage [S1, S2][S3, unofficial].

## Background
Plane Slicing was proposed by Yagel et al. [4] and detailed by Max et al. in the context of volume rendering for curvilinear and unstructured grids [S1, S2][S3, unofficial]. It was developed to address the challenges of rendering unstructured data using graphics hardware, leveraging the efficiency of polygon rasterization and alpha blending [S1, S2][S3, unofficial]. The method has been parallelized for large datasets [S1, S2][S3, unofficial].
