# Transparent Planes

Also called: Plane-based rendering

## Overview
Transparent Planes is an object-order volume rendering strategy that slices a volumetric dataset into a series of parallel planes, applies a transfer function to generate per-vertex color and transparency, and composites these planes from back to front [S1, unofficial]. It differs from ray-casting (image-order) methods by iterating over data rather than pixels, and from splatting by using planar geometry instead of point-based disks [S1, unofficial]. It is most effective when the view plane is parallel to the volume edges, allowing efficient voxel access as planar slices .

## How it works
**Inputs:** Volumetric dataset (voxel grid), transfer function mapping voxel values to color and opacity, number of planes $N$.
**Outputs:** Final 2D image.

**Data Structures:**
*   **Volume:** 3D array of voxel values.
*   **Plane:** 2D texture or buffer containing vertices with attributes $(x, y, z, \text{color}, \text{opacity})$.
*   **Transfer Function:** Mapping $V \rightarrow (R, G, B, \alpha)$.

**Steps:**
1.  **Slice Generation:** Divide the volume along the viewing direction into $N$ parallel planes. The number of planes $N$ is typically between 200 and 1000 [S1, unofficial].
2.  **Transfer Function Application:** For each plane, evaluate the transfer function at each vertex (or voxel sample) on the plane to determine its color $(R, G, B)$ and opacity $\alpha$ [S1, unofficial].
3.  **Plane Composition:** Render the planes from back to front. For each plane, blend its color and opacity into the accumulated result using front-to-back or back-to-front compositing equations.
    *   If composed rear to front, accumulation starts with initial values of zero color and zero opacity .
    *   If composed front to back, standard ray-casting accumulation equations apply .
4.  **Filtering:** Apply filtering during sampling to handle aliasing and interpolation, as a single voxel projects onto multiple pixels or vice versa .

## Subtopics

### View-Perpendicular Slice Volume Rendering
A rendering approach using view-perpendicular slices ordered back-to-front to incorporate transparency into the transfer function [S2, unofficial]. It uses a fragment program to evaluate the transfer function by comparing each voxel value with three thresholds (one for each color channel) [S2, unofficial]. If a value exceeds a threshold, the corresponding color channel is activated; if no threshold is exceeded, the voxel is transparent (not black) [S2, unofficial]. A color ramp provides smooth transitions, making values near thresholds slightly visible and values much greater clearly visible [S2, unofficial]. Maximal intensity projection is evaluated within the fragment program by mapping a specific color channel or the sum of all three to the Z-buffer [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Relative to the volume size and number of planes [S1, S2, unofficial].
*   **Memory Complexity:** Depends on the number of planes and resolution of each slice [S1, unofficial].
*   **Performance:** Displays 15 frames/sec for a $64^3$ data set ($\sim$260,000 basepairs) with 800x800 pixel output [S2, unofficial].
*   **Strengths:** Can be quickly rendered using 2D or 3D textures [S1, unofficial]. Efficient for fixed view planes parallel to volume edges .
*   **Limitations:** Requires complex sampling if view is not parallel to volume axes .

## Background
Originating from object-order volume rendering techniques, Transparent Planes is an alternative to compositing splats or ray-casting [S1, unofficial]. It leverages graphics hardware capabilities for texture-based rendering [S1, unofficial]. It has been applied in specialized domains such as the visualization of multiple alignments of large genomic DNA sequences [S2, unofficial].
