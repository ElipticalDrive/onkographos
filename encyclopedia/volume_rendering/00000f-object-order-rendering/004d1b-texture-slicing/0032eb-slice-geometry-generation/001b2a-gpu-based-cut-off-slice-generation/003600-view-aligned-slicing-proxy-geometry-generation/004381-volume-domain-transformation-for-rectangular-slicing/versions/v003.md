# Volume Domain Transformation for Rectangular Slicing

Also called: AABB rotation and expansion, Transformed domain V'

## Overview
This method is a preprocessing step that transforms the original Axis-Aligned Bounding Box (AABB) volume domain $V$ into a transformed domain $V'$ to ensure all cutting sections are rectangles [S1]. It solves the problem of complex polygon clipping and intersection testing inherent in slicing an AABB with arbitrary planes, which results in N-gons [S1]. By guaranteeing rectangular cross-sections, it simplifies Layered Polygonal Area Light (LTC)-based integration and avoids the need for handling up to 80 different calculation branches for clipped area lights penetrating the plane [S1]. It builds on [View-Aligned Slicing (Proxy Geometry Generation)](7620-view-aligned-slicing-proxy-geometry-generation.md) [S1].

## How it works
**Inputs:**
- Original volume domain $V$, defined as an Axis-Aligned Bounding Box (AABB) [S1].
- View direction or gravity center direction $\omega_c$ [S1].

**Outputs:**
- Transformed volume domain $V'$, where any planar cut perpendicular to $\omega_c$ yields a rectangular intersection [S1].

**Data Structures:**
- The domain is represented by its bounding box extents (min and max corners) [S1].
- The transformation involves a rotation matrix and a scaling factor (expansion) [S1].

**Steps:**
1. **Rotation:** Rotate the original AABB domain $V$ such that one of its sides becomes perpendicular to the straight line defined by the direction $\omega_c$ (direction to the gravity center) [S1].
2. **Expansion:** Enlarge (scale) the rotated domain to obtain $V'$ such that it bounds the original domain $V$ as tightly as possible while ensuring that all cutting sections remain rectangles [S1].

**Formulas:**
Let $R$ be the rotation matrix aligning a side of the AABB with the normal of the cutting plane (perpendicular to $\omega_c$) [S1]. Let $S$ be the scaling factor applied to the rotated domain [S1].
$$ V' = S \cdot (R \cdot V) $$
The scaling $S$ is determined by the requirement that the projection of the original volume onto the cutting plane fits within the rectangular bounds of the transformed domain without introducing non-rectangular intersections [S1].

**Parameters:**
- $\omega_c$: Direction to the gravity center [S1].
- Scaling factor: Determined by the tightest bound requirement [S1].

**Edge Cases and Pitfalls:**
- **Original AABB Slicing:** Slicing an AABB with arbitrary planes results in N-gons [S1]. This requires multiple intersection tests between the cutting plane and edges of the AABB, followed by sorting the intersection points in clockwise/anticlockwise order [S1].
- **LTC Implementation:** For LTC-based rendering, clipped area lights penetrating the plane require handling up to 80 different calculation branches for triangles to hexagons, which is computationally expensive and unsuitable for real-time performance [S1].
- **Roughness:** The method performs sufficiently well for low roughness surfaces, producing results almost identical to path tracing [S1]. On highly rough surfaces, the blurriness is smaller than path tracing, yet the approximation holds [S1].

**Pseudocode:**
```python
def transform_volume_domain(V_min, V_max, omega_c):
    # V is an AABB defined by min and max corners (3D vectors)
    # omega_c is the direction to the gravity center (3D vector)
    
    # Step 1: Rotate V so that one of its axes aligns with omega_c
    # We find the rotation matrix R that maps the Z-axis (0,0,1) to omega_c
    R = align_vector_to_basis(omega_c, [0, 0, 1])
    
    # Transform all 8 corners of the AABB
    corners = get_aabb_corners(V_min, V_max)
    rotated_corners = [apply_rotation(c, R) for c in corners]
    
    # Compute the bounding box of the rotated corners
    V_rot_min = [min(p[i] for p in rotated_corners) for i in range(3)]
    V_rot_max = [max(p[i] for p in rotated_corners) for i in range(3)]
    
    # Step 2: Expand V_rot to V' to bound the original volume tightly
    # The expansion ensures the projection of the original volume fits within V'
    # [G] Exact scaling formula not given in sources; computed here by projecting 
    # original corners onto rotated axes to find the tightest uniform bound.
    extents_rot = [V_rot_max[i] - V_rot_min[i] for i in range(3)]
    
    # The new axes are the columns of R^T (or rows of R)
    axes = [R[:, i] for i in range(3)]
    required_extents = []
    for i in range(3):
        projections = [dot(p, axes[i]) for p in corners]
        required_extents.append(max(projections) - min(projections))
        
    # Scaling factor is the maximum ratio to ensure all dimensions cover the projection
    scale_factors = [required_extents[i] / extents_rot[i] if extents_rot[i] > 1e-6 else 1.0 for i in range(3)]
    scale = max(scale_factors)
    
    # Apply scaling to the rotated AABB center
    center = [(V_rot_min[i] + V_rot_max[i]) / 2 for i in range(3)]
    new_half_extents = [(V_rot_max[i] - V_rot_min[i]) / 2 * scale for i in range(3)]
    V_prime_min = [center[i] - new_half_extents[i] for i in range(3)]
    V_prime_max = [center[i] + new_half_extents[i] for i in range(3)]
    
    return V_prime_min, V_prime_max

def align_vector_to_basis(target, basis):
    # Returns rotation matrix that rotates basis to target
    b = normalize(basis)
    t = normalize(target)
    dot_val = dot(b, t)
    if abs(dot_val - 1.0) < 1e-6:
        return identity_matrix()
    if abs(dot_val + 1.0) < 1e-6:
        # 180 degree rotation around any perpendicular axis
        perp = cross(b, [1.0, 0.0, 0.0])
        if length(perp) < 1e-6:
            perp = cross(b, [0.0, 1.0, 0.0])
        perp = normalize(perp)
        return rotation_matrix_180(perp)
    axis = cross(b, t)
    angle = acos(dot_val)
    return rotation_matrix(axis, angle)

def identity_matrix():
    return [[1,0,0],[0,1,0],[0,0,1]]

def rotation_matrix_180(axis):
    # Rodrigues for 180 degrees: R = I + 2*(axis x)^2
    x, y, z = axis
    return [[2*x*x-1, 2*x*y, 2*x*z],
            [2*x*y, 2*y*y-1, 2*y*z],
            [2*x*z, 2*y*z, 2*z*z-1]]

def rotation_matrix(axis, angle):
    x, y, z = axis
    c = cos(angle)
    s = sin(angle)
    t = 1 - c
    return [[t*x*x+c, t*x*y-s*z, t*x*z+s*y],
            [t*x*y+s*z, t*y*y+c, t*y*z-s*x],
            [t*x*z-s*y, t*y*z+s*x, t*z*z+c]]

def apply_rotation(point, matrix):
    return [dot(point, matrix[i]) for i in range(3)]

def get_aabb_corners(min_pt, max_pt):
    return [[min_pt[0]+dx, min_pt[1]+dy, min_pt[2]+dz]
            for dx in [0, max_pt[0]-min_pt[0]]
            for dy in [0, max_pt[1]-min_pt[1]]
            for dz in [0, max_pt[2]-min_pt[2]]]

def normalize(v):
    l = length(v)
    return [v[i]/l for i in range(3)]

def length(v):
    return sum(x*x for x in v)**0.5

def dot(v1, v2):
    return sum(v1[i]*v2[i] for i in range(3))

def cross(v1, v2):
    return [v1[1]*v2[2]-v1[2]*v2[1],
            v1[2]*v2[0]-v1[0]*v2[2],
            v1[0]*v2[1]-v1[1]*v2[0]]
```

## Subtopics

### [Deformable Slicing Surface](11614-deformable-slicing-surface.md)
Deformable Slicing Surface (DS) is a method for generating slice geometry in hyper-dimensional radiance fields that maps spatial positions to varying ambient coordinates, replacing fixed axis-aligned planes. It solves the problem of fading artifacts and inefficient representation capacity inherent in Axis-Aligned Slicing Plane (AP) methods by allowing different parts of the scene to reference distinct regions of the ambient template space, resulting in sharper details and smoother interpolations between states.

## Operating characteristics
- **Time Complexity:** Avoids the $O(N)$ intersection tests and vertex sorting required for N-gon clipping in the original domain [S1]. Eliminates the need for up to 80 calculation branches in the shader for clipped area lights [S1].
- **Memory Complexity:** Not given in the sources [S1].
- **Measured Performance:** Experiments were conducted on an Intel Core i7-8700K 3.7 GHz CPU and NVIDIA GeForce GTX 1080 GPU with 32 GB RAM [S1]. Volume data was $128 \times 128 \times 128$ 3D textures [S1]. Rendering used $N=128$ LPALs [S1].
- **Strengths:** Simplifies computation and implementation by ensuring all cutting sections are rectangles [S1]. Enables real-time operation by avoiding complex polygon clipping [S1].
- **Limitations:** The transformation may introduce some blurriness on highly rough surfaces, though it is smaller than path tracing [S1].
- **When to use:** When using LTC-based rendering for emissive inhomogeneous volumes and real-time performance is required [S1].
- **When not to use:** Not given in the sources [S1].

## Background
- **Origin:** Proposed in "Real‐time Indirect Illumination of Emissive Inhomogeneous Volumes using Layered Polygonal Area Lights" [S1].
- **History:** The method addresses the computational bottleneck of slicing AABBs with arbitrary planes, which results in N-gons and complex clipping logic for LTC-based area lights [S1].
- **Usage:** Used in real-time indirect illumination rendering of emissive inhomogeneous volumes [S1].
