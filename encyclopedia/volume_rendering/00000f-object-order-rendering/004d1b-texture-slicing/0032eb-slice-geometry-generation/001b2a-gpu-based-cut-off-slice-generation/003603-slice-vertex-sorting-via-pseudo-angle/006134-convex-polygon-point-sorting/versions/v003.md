# Convex Polygon Point Sorting

Also called: Angular Sort around Pivot, Cross-Product Angular Sort

## Overview
This method sorts a set of 3D intersection points that form a convex polygon into a counter-clockwise order around a pivot point, producing a vertex sequence suitable for rendering [S1, unofficial]. It relies on a view-dependent cross-product metric to determine angular order rather than computing a geometric polar angle in a local 2D plane [S1, unofficial]. A variant constructs an origin outside the polygon and uses dot-product comparisons to order vertices into a triangle fan [S2, unofficial].

## How it works
**Inputs:**
- `points`: A list of $N$ 3D points representing the intersection of a slicing plane with a volume boundary [S1, unofficial].
- `p0`: The pivot point, typically the first point in the list [S1, unofficial].
- `up`: The reference vector (view direction or polygon normal) used to define the sorting orientation [S1, unofficial].

**Outputs:**
- `sorted_points`: The input points sorted in counter-clockwise order around `p0` relative to `up` [S1, unofficial].

**Data Structures:**
- Points are stored as 3D floating-point vectors (e.g., `Eigen::Vector3f` in the source implementation) [S1, unofficial].

**Steps:**
1. Select a pivot point $p_0$ from the input list [S1, unofficial].
2. For any two points $a$ and $b$, compute vectors from the pivot: $\text{va} = a - p_0$ and $\text{vb} = b - p_0$ [S1, unofficial].
3. Compute the cross product $\text{cross} = \text{va} \times \text{vb}$ [S1, unofficial].
4. Compute the dot product $\text{score} = \text{up} \cdot \text{cross}$ [S1, unofficial].
5. Compare points using the score: if $\text{up} \cdot (\text{va} \times \text{vb}) \ge 0$, then $a$ precedes $b$ in the sorted order [S1, unofficial].
6. Apply a stable comparison-based sort to the entire list using this comparator [S1, unofficial].

**Formula:**
The comparison between two points $a$ and $b$ is defined as:
$$ \text{up} \cdot ((a - p_0) \times (b - p_0)) \ge 0 $$
Where $p_0$ is the pivot, $\text{up}$ is the reference vector, $\cdot$ denotes the dot product, and $\times$ denotes the cross product [S1, unofficial].

**Pseudocode:**
```python
def sort_convex_polygon(points, p0, up):
    """Sorts points in CCW order around p0 relative to up."""
    def cross(v1, v2):
        return (
            v1[1]*v2[2] - v1[2]*v2[1],
            v1[2]*v2[0] - v1[0]*v2[2],
            v1[0]*v2[1] - v1[1]*v2[0]
        )
    def dot(v1, v2):
        return v1[0]*v2[0] + v1[1]*v2[1] + v1[2]*v2[2]
    def compare(a, b):
        va = (a[0]-p0[0], a[1]-p0[1], a[2]-p0[2])
        vb = (b[0]-p0[0], b[1]-p0[1], b[2]-p0[2])
        cp = cross(va, vb)
        return dot(up, cp) >= 0
    import functools
    return sorted(points, key=functools.cmp_to_key(lambda a, b: -1 if compare(a, b) else (1 if compare(b, a) else 0)))
```

**Edge Cases and Pitfalls:**
- The source implementation does not specify behavior for collinear points, alternative pivot selection strategies, or degenerate inputs [S1, unofficial].
- The `up` vector determines the winding order; flipping it reverses the sort direction [G].
- Precision loss may occur when points are nearly collinear with the pivot, causing unstable sort order [G].

## Subtopics

### Convex Hull Triangulation
This variant, described in [S2, unofficial], orders vertices of a convex, monotone, simple polygon (resulting from plane-hexahedron intersection) into a triangle fan. It differs from the angular sort by explicitly constructing an origin outside the polygon and using dot-product-based angle comparisons [S2, unofficial].
- **Definition:** An algorithm to order vertices of a convex, monotone, simple polygon into a triangle fan [S2, unofficial].
- **Steps:**
    1. Compute the centroid of the proxy polygon as the average of all points [S2, unofficial].
    2. Calculate a new origin outside the polygon: take the vector from the world origin to the centroid, add to it the vector from the centroid to one of the points (doubled in length) [S2, unofficial].
    3. Let $v_0$ be the new origin and $v_1$ be the closest point to $v_0$ [S2, unofficial].
    4. Sort the remaining points $v_i$ ($i=2..n$) by the angle between vector $v_0v_1$ and $v_0v_i$ using the inner product (dot product) [S2, unofficial].
    5. Tesselate the proxy polygon into triangle fans and add vertices to the output array in the sorted order [S2, unofficial].
- **Pitfall:** The polygon must be simple, monotone, and convex for this specific algorithm to work correctly [S2, unofficial].
- **Complexity:** $O(n^2)$ in its re-ordering stage, where the unit operation is a dot-product (three multiplications) [S2, unofficial].

## Operating characteristics
- **Time Complexity:** The angular sort uses a standard comparison-based sort, yielding $O(N \log N)$ [G]. The convex hull triangulation variant requires $O(n^2)$ for its re-ordering stage [S2, unofficial].
- **Memory Complexity:** Not given in the sources.
- **Performance:** The angular sort is efficient for real-time rendering [G]. The convex hull variant is noted as "quite fast" compared to other convex hull algorithms but scales poorly for high vertex counts due to $O(n^2)$ complexity [S2, unofficial].
- **Strengths:** Simple to implement; robust for convex polygons; view-dependent orientation ensures correct winding for rendering [S1, unofficial].
- **Limitations:** Requires convex input; sensitive to the choice of pivot and view direction; the convex hull variant requires the polygon to be simple, monotone, and convex [S1, unofficial][S2, unofficial].

## Background
The angular sort method originates from the SmokeSimulation project, which implements real-time volumetric rendering techniques [S1, unofficial]. The convex hull triangulation algorithm is described in a thesis on real-time volumetric rendering of fire in a production system, which focuses on optimizing slice generation for hexahedral volumes [S2, unofficial].
