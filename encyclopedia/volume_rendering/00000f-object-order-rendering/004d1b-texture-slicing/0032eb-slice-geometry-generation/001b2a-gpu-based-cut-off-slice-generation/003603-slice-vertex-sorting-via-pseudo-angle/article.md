# Slice Vertex Sorting via Pseudo-Angle
Also called: Pseudo-Angle Metric Sorting, Pseudo-Angle Sorting
## Overview
This method sorts the intersection vertices of a volume slice around their centroid in counter-clockwise order using a custom pseudo-angle metric [S1, unofficial]. It ensures that the resulting polygon vertices are ordered correctly for triangulation, which is a prerequisite for rendering the slice geometry generated by [GPU-based Cut-off Slice Generation](948-gpu-based-cut-off-slice-generation.md) [S1, unofficial]. It differs from sibling methods by using a normalized linear projection of the angle rather than trigonometric functions or incremental traversal [G].
## How it works
### Inputs and Outputs
- **Input**: A list of 3D vertices $V = \{v_0, v_1, \dots, v_{n-1}\}$ representing the intersection polygon of a slicing plane with the volume bounding box [S1, unofficial].
- **Output**: A sorted list of vertices $V_{sorted}$ ordered counter-clockwise around the centroid, ready for triangulation [S1, unofficial].

### Data Structures
- **Vertex**: A 3D vector $(x, y, z)$ [G].
- **Centroid**: A 3D vector $C = (C_x, C_y, C_z)$ [G].
- **Pseudo-Angle**: A scalar float value in the range $[-1, 5]$ (excluding specific boundary cases) [S1, unofficial].

### Steps
1. **Compute Centroid**: Calculate the centroid $C$ of the input vertices by averaging their coordinates:
   $$ C = \frac{1}{n} \sum_{i=0}^{n-1} v_i $$ [S1, unofficial].
2. **Compute Pseudo-Angle**: For each vertex $v_i$, compute the delta vector $\Delta = v_i - C$ [S1, unofficial]. Calculate the pseudo-angle $A(\Delta)$ using the following formula [S1, unofficial]:
   $$ A(\Delta) = \begin{cases} -1 & \text{if } \Delta x = 0 \text{ and } \Delta y = 0 \\ 2.0 - \frac{\Delta y}{|\Delta x| + |\Delta y|} & \text{if } \Delta x < 0 \\ 4.0 + \frac{\Delta y}{|\Delta x| + |\Delta y|} & \text{if } \Delta x \ge 0 \end{cases} $$
   where $\Delta x$ and $\Delta y$ are the x and y components of $\Delta$ [S1, unofficial].
3. **Sort Vertices**: Sort the vertices based on their computed pseudo-angle values in ascending order [S1, unofficial].
4. **Triangulation**: If the number of vertices $n > 3$, generate triangles by iterating through the sorted vertices [S1, unofficial]. For each $i$ from $0$ to $n-1$, let $j = (i+1) \pmod n$ [S1, unofficial]. Create a triangle using vertices $v_{sorted}[i]$, $C$, and $v_{sorted}[j]$ [S1, unofficial]. If $n \le 3$, push the vertices in sorted order directly [S1, unofficial].

### Pseudocode
> **Unverified code.** The code below did not pass a test run against a reference implementation, or no test fits it, so it may contain errors.

```python
def compute_centroid(vertices):
    n = len(vertices)
    if n == 0:
        return (0.0, 0.0, 0.0)
    sum_x = sum(v[0] for v in vertices)
    sum_y = sum(v[1] for v in vertices)
    sum_z = sum(v[2] for v in vertices)
    return (sum_x / n, sum_y / n, sum_z / n)

def compute_pseudo_angle(delta):
    dx = delta[0]
    dy = delta[1]
    if dx == 0.0 and dy == 0.0:
        return -1.0
    abs_dx = abs(dx)
    abs_dy = abs(dy)
    ratio = dy / (abs_dx + abs_dy)
    if dx < 0.0:
        return 2.0 - ratio
    else:
        return 4.0 + ratio

def sort_vertices_by_pseudo_angle(vertices):
    centroid = compute_centroid(vertices)
    vertex_angles = []
    for v in vertices:
        delta = (v[0] - centroid[0], v[1] - centroid[1], v[2] - centroid[2])
        angle = compute_pseudo_angle(delta)
        vertex_angles.append((angle, v))
    vertex_angles.sort(key=lambda x: x[0])
    return [v for _, v in vertex_angles]

def generate_triangles(sorted_vertices, centroid):
    triangles = []
    n = len(sorted_vertices)
    if n > 3:
        for i in range(n):
            j = (i + 1) % n
            triangles.append((sorted_vertices[i], centroid, sorted_vertices[j]))
    else:
        triangles = list(sorted_vertices)
    return triangles
```

### Parameters
- No external parameters. The method is deterministic based on the input vertex positions [S1, unofficial].

### Edge Cases and Pitfalls
- **Centroid Coincidence**: If a vertex coincides with the centroid, the delta vector is zero, and the pseudo-angle is defined as $-1$ [S1, unofficial]. This vertex will be sorted to the beginning of the list [S1, unofficial].
- **Precision**: The use of absolute values and division can lead to precision issues if $\Delta x$ and $\Delta y$ are very small but not zero [G]. However, the formula is designed to be robust for typical geometric intersections [G].
- **Degenerate Polygons**: If the intersection results in fewer than 3 vertices, the triangulation step handles it by storing the vertices directly [S1, unofficial].

## Operating characteristics
- **Time Complexity**: $O(n \log n)$ due to sorting, where $n$ is the number of vertices [G]. Computing the centroid and pseudo-angles is $O(n)$ [G].
- **Memory Complexity**: $O(n)$ to store the vertex-angle pairs [G].
- **Strengths**: Avoids expensive trigonometric functions (sin, cos, atan2), making it computationally efficient for GPU implementation [G].
- **Limitations**: The pseudo-angle metric is an approximation and may not perfectly preserve angular order in all degenerate cases, though it is sufficient for convex polygon triangulation [G].
