# Tangible Volume Slicing (Tablet Plane)

Also called: Tablet-based slicing

## Overview
Tangible Volume Slicing (Tablet Plane) is a technique where a physical tablet acts as a tangible planar object that defines a slice plane through a volumetric dataset [S1]. It solves the problem of intuitively navigating and visualizing internal structures by allowing the user to directly manipulate the slice geometry in 3D space using a physical object [S1]. It sets itself apart from standard texture slicing by replacing abstract UI controls with direct physical manipulation of the slice plane's pose, providing immediate haptic and visual feedback through a handheld window [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A volumetric dataset (scalar field), the real-time 6-DoF pose (position and orientation) of the physical tablet relative to the virtual reference object representing the data, and the pose of the handheld viewing window.
*   **Output:** A real-time rendered 2D image of the slice intersecting the volume, displayed within the handheld window.

**Data Structures:**
*   **Tablet Pose:** A 4x4 transformation matrix $T_{tablet}$ or equivalent quaternion/vector pair representing the tablet's position and orientation in the global coordinate system [S1].
*   **Reference Object Pose:** A 4x4 transformation matrix $T_{ref}$ representing the position and orientation of the volumetric dataset in the global coordinate system [S1].
*   **Slice Plane:** Defined by the tablet's local coordinate system, specifically its planar surface normal and origin [S1].

**Steps:**
1.  **Positioning:** Position the physical tablet and the virtual reference object (representing the dataset) relative to each other in 3D space [S1].
2.  **Compute Slice Plane:** Determine the slice plane equation based on the tablet's current tracked pose. The tablet's planar shape directly defines this plane [S1].
3.  **Render Slice:** Intersect the computed slice plane with the volumetric dataset to extract the slice data. Render this slice in real-time through the handheld window [S1].

**Pseudocode:**
```python
def render_tangible_slice(tablet_pose, ref_object_pose, volume_data, window_pose):
    """
    Renders the slice defined by the physical tablet's pose.
    
    Args:
        tablet_pose: 4x4 matrix, pose of the physical tablet in global space.
        ref_object_pose: 4x4 matrix, pose of the volume data in global space.
        volume_data: 3D array, the scalar field values.
        window_pose: 4x4 matrix, pose of the handheld viewing window.
        
    Returns:
        image: 2D array, the rendered slice image.
    """
    # Step 1 & 2: Compute the slice plane from the tablet's pose relative to the data
    # The tablet defines a plane in its local coordinate system (e.g., z=0 plane)
    # Transform this plane into the global coordinate system
    global_tablet_pose = tablet_pose
    
    # Transform the global tablet pose into the reference object's local coordinate system
    # This allows us to define the slice plane in the volume's native grid space
    local_tablet_pose = ref_object_pose.inverse() @ global_tablet_pose
    
    # Extract the slice plane parameters from the local tablet pose
    # Assuming the tablet's front face is the slicing plane (normal along local Z axis)
    slice_normal_local = local_tablet_pose[0:3, 2] # Z-axis of the tablet
    slice_origin_local = local_tablet_pose[0:3, 3] # Position of the tablet
    
    # Step 3: Render the slice
    # Intersect the slice plane with the volume data
    slice_data = extract_slice_from_volume(volume_data, slice_origin_local, slice_normal_local)
    
    # Render the slice data into the handheld window
    image = render_to_window(slice_data, window_pose)
    
    return image
```

**Parameters:**
*   **Tracking Accuracy:** Not given in the sources.
*   **Update Rate:** Real-time [S1].

**Edge Cases and Pitfalls:**
*   **Degenerate Input:** If the tablet is oriented such that its plane is parallel to the volume's primary axes, standard slicing applies, but the tangible metaphor remains valid [S1].
*   **Precision:** Real-time tracking latency may cause a mismatch between the physical tablet's position and the rendered slice [S1].

## Subtopics

### Tangible Volume Slicing (Stylus Blade)
A technique where a virtual 'blade' is attached to the stylus to define a slice plane through the data volume, allowing the user to slice virtual data with a physical tool [S1]. It sets itself apart from the Tablet Plane variant by using a stylus instead of a tablet, offering a more precise, tool-based interaction metaphor [S1]. Choose this when finer control over the slice orientation and position is needed, or when the user prefers a pen-like interaction [S1]. Steps: Attach a virtual blade geometry to the stylus's tracked pose; update the slice in real-time as the stylus moves; render the slice to give the impression of effectively slicing the virtual data with the physical tool [S1].

## Operating characteristics
*   **Time Complexity:** Real-time rendering is required, implying $O(1)$ per frame for the slicing operation relative to the slice resolution, but dependent on the volume rendering engine's performance [S1].
*   **Memory Complexity:** Depends on the volume data size and the slice resolution [S1].
*   **Measured Performance:** Not given in the sources.
*   **Strengths:** Intuitive physical manipulation of the slice plane; direct mapping between user action and visual result [S1].
*   **Limitations:** Requires specialized hardware for tracking the tablet and handheld window; limited by the physical size of the tablet [S1].
*   **When to use:** When intuitive, direct manipulation of slice geometry is prioritized over abstract parameter entry [S1].
*   **When not to use:** When precise, numerical control of the slice plane is required, or when hardware constraints prevent real-time tracking [S1].

## Background
Originated from the work of Issartel et al. in 2014, presented in the paper "A portable interface for tangible exploration of volumetric data" [S1]. The technique was developed to bring new possibilities for creating and manipulating slice planes through the combination of a tablet and tangible objects [S1]. It is used in the context of portable interfaces for tangible exploration of volumetric data [S1].
