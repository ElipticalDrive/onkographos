# 2D Slice Coordinate Mapping

Also called: Slice indexing, Voxel-to-screen projection

## Overview
This method maps 2D screen coordinates $(u, v)$ to 3D voxel indices $(x, y, z)$ for a specific perpendicular slice extracted from a 3D volume array, handling axis-specific memory layouts and vertical flip conventions [S1, unofficial]. It differs from [AxisCut](18858-axiscut.md) by explicitly defining the coordinate transformation logic for rendering, and from [Patient-Aligned MPR Plane Construction](21407-patient-aligned-mpr-plane-construction.md) by assuming fixed anatomical axes (x, y, z) rather than arbitrary patient-aligned planes.

## How it works
**Inputs:**
- `volume`: A 3D numpy array or equivalent data structure with shape `(D, H, W)` corresponding to dimensions `(z, y, x)` in RAS or standard memory layout.
- `axis`: Integer specifying the extraction axis: `0` (sagittal), `1` (coronal), or `2` (axial) [S1, unofficial].
- `u, v`: 2D screen coordinates (pixel indices) within the slice image.

**Outputs:**
- `x, y, z`: Clipped 3D voxel indices into the original volume array [S1, unofficial].

**Data Structures:**
- The volume is assumed to be stored in row-major order where the first index varies slowest. For medical imaging (DICOM/NIfTI), this often corresponds to `(z, y, x)` [S1, unofficial].

**Steps:**
1. Determine the slice geometry based on `axis` [S1, unofficial].
2. Map screen coordinates $(u, v)$ to volume indices $(x, y, z)$ according to the axis [S1, unofficial].
3. Apply vertical flip for axes 0 and 1 to correct for image coordinate system differences (screen y-down vs. anatomical y-up) [S1, unofficial].
4. Clip all resulting indices to the valid range $[0, \text{dimension\_size} - 1]$ [S1, unofficial].

**Formulas and Logic:**
Let $D, H, W$ be the depth, height, and width of the volume respectively [S1, unofficial].

- **Axis 2 (Axial):**
  - Slice is `volume[z, :, :]` [S1, unofficial].
  - Mapping: $x = u$, $y = v$, $z = \text{fixed\_slice\_index}$ [S1, unofficial].
  - No flip applied [S1, unofficial].

- **Axis 1 (Coronal):**
  - Slice is `volume[:, y, :]` flipped vertically [S1, unofficial].
  - Mapping: $x = u$, $z = \text{shape}[0] - 1 - v$, $y = \text{fixed\_slice\_index}$ [S1, unofficial].
  - Note: The vertical flip maps screen $v=0$ to the top of the volume (max $z$) [S1, unofficial].

- **Axis 0 (Sagittal):**
  - Slice is `volume[:, :, x]` flipped vertically [S1, unofficial].
  - Mapping: $y = u$, $z = \text{shape}[0] - 1 - v$, $x = \text{fixed\_slice\_index}$ [S1, unofficial].
  - Note: The vertical flip maps screen $v=0$ to the top of the volume (max $z$) [S1, unofficial].

def map_slice_coordinates(volume, axis, u, v, fixed_index):
    D, H, W = volume.shape
    
    if axis == 2:
        # Axial
        x = u
        y = v
        z = fixed_index
    elif axis == 1:
        # Coronal
        x = u
        z = D - 1 - v
        y = fixed_index
    elif axis == 0:
        # Sagittal
        y = u
        z = D - 1 - v
        x = fixed_index
    else:
        raise ValueError("Axis must be 0, 1, or 2")

    # Clip to bounds
    x = max(0, min(x, W - 1))
    y = max(0, min(y, H - 1))
    z = max(0, min(z, D - 1))
    
    return (x, y, z)

**Edge Cases:**
- Coordinates outside the volume bounds are clipped to the nearest valid index [S1, unofficial].
- Vertical flips are critical for axes 0 and 1 to align screen coordinates with anatomical orientation [S1, unofficial].

## Subtopics

### [GPU Volume Slicing (Advanced/Transform)](21426-gpu-volume-slicing-advanced-transform.md)
This method renders a 2D slice from a 3D volume by applying an arbitrary 4x4 transformation matrix to screen coordinates, followed by scaling and centering, before sampling the volume texture [21426-gpu-volume-slicing-advanced-transform.md]. It differs from basic slice extraction by supporting complex spatial transformations (rotation, translation, non-uniform scaling) directly in the pixel shader, rather than relying on pre-computed slice geometries or fixed-axis alignment [21426-gpu-volume-slicing-advanced-transform.md]. It builds on [2D Slice Coordinate Mapping](21041-2d-slice-coordinate-mapping.md) by generalizing the coordinate mapping to include full affine transformations [21426-gpu-volume-slicing-advanced-transform.md].

### Export 2D Slice
Exports the 3D volume as a 2D image with dimensions $(width, height \times depth)$, effectively slicing or projecting the volume [S2]. This is a utility operation rather than a real-time rendering mapping technique [S2].

## Operating characteristics
- **Time Complexity:** $O(1)$ per pixel for coordinate mapping [S1, unofficial].
- **Memory Complexity:** $O(1)$ auxiliary memory [S1, unofficial].
- **Strengths:** Simple, fast, and deterministic for orthogonal views [S1, unofficial].
- **Limitations:** Only supports fixed-axis orthogonal slices; does not handle oblique or curved planes without pre-computation [S1, unofficial].
- **When to use:** Orthogonal MPR (Multi-Planar Reconstruction) views in medical imaging [S1, unofficial].
- **When not to use:** Oblique slicing, arbitrary plane rendering, or GPU-based arbitrary transform slicing [21426-gpu-volume-slicing-advanced-transform.md].

## Background
This method originates from basic volume visualization techniques where 3D data is accessed via 2D screen coordinates for orthogonal views [S1, unofficial]. It is commonly used in medical imaging viewers for axial, coronal, and sagittal displays [S1, unofficial].
