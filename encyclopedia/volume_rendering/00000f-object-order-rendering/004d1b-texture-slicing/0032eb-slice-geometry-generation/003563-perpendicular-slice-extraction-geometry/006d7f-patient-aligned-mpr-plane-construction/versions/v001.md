# Patient-Aligned MPR Plane Construction

Also called: Classic CT reformatting, MPR (Multiplanar Reformation), Multi-Planar Reconstruction, Multiplanar Reformation, reformatted image, secondary data reconstruction

## Overview
Patient-Aligned MPR Plane Construction generates a geometric plane aligned with standard patient anatomical axes (LPS coordinate system) for multi-planar reformation [S1, unofficial]. It solves the problem of defining the spatial orientation and origin of axial, coronal, or sagittal slices from a volumetric dataset, enabling visualization of structures in non-acquisition planes [S3]. It differs from [Perpendicular Slice Extraction Geometry](7503-perpendicular-slice-extraction-geometry.md) by explicitly enforcing anatomical alignment (LPS axes) rather than arbitrary perpendicularity to a user-defined axis, and from [AxisCut](18858-axiscut.md) by supporting all three standard anatomical planes rather than a single axis-aligned cut [S1, unofficial].

## How it works
**Inputs:**
- `plane_type`: Enum indicating the anatomical plane (`axial`, `coronal`, or `sagittal`) [S1, unofficial].
- `center`: 3D vector representing the center point of the MPR plane in LPS world coordinates [S1, unofficial].
- `width`: Integer, number of pixels along the U axis [S1, unofficial].
- `height`: Integer, number of pixels along the V axis [S1, unofficial].
- `pixelSpacingUMm`: Float, pixel spacing in millimeters along the U axis [S1, unofficial].
- `pixelSpacingVMm`: Float, pixel spacing in millimeters along the V axis [S1, unofficial].

**Outputs:**
- `MPRPlane`: A structure containing:
  - `origin`: 3D vector, the top-left corner of the plane in LPS world coordinates [S1, unofficial].
  - `u_direction`: 3D vector, the unit vector along the U axis [S1, unofficial].
  - `v_direction`: 3D vector, the unit vector along the V axis [S1, unofficial].
  - `spacing`: 2D vector `(pixelSpacingUMm, pixelSpacingVMm)` [S1, unofficial].
  - `dimensions`: 2D vector `(width, height)` [S1, unofficial].

**Data Structures:**
The `MPRPlane` struct fields are standard 3D vectors (x, y, z) and 2D vectors (u, v). No bit-packing is specified; standard floating-point precision is assumed for coordinates [S1, unofficial].

**Steps:**
1. **Determine Anatomical Axes:** Based on `plane_type`, assign the U and V direction vectors in the LPS coordinate system [S1, unofficial]:
   - If `axial`: $u = [1, 0, 0]$, $v = [0, 1, 0]$ [S1, unofficial].
   - If `coronal`: $u = [1, 0, 0]$, $v = [0, 0, 1]$ [S1, unofficial].
   - If `sagittal`: $u = [0, 1, 0]$, $v = [0, 0, 1]$ [S1, unofficial].
   
2. **Calculate Half Extents:** Compute the physical half-width and half-height of the plane in world units (millimeters) [S1, unofficial]:
   $$ halfU = \frac{(width - 1) \times pixelSpacingUMm}{2} $$
   $$ halfV = \frac{(height - 1) \times pixelSpacingVMm}{2} $$
   [S1, unofficial]

3. **Calculate Origin:** Determine the origin (top-left corner) of the plane in LPS world coordinates by subtracting the half-extent vectors from the center point [S1, unofficial]:
   $$ origin = center - (u \times halfU) - (v \times halfV) $$
   [S1, unofficial]

4. **Validate and Return:** Verify that the resulting plane geometry is valid:
   - The direction vectors $u$ and $v$ are orthonormal [S1, unofficial].
   - Spacing values are finite and positive [S1, unofficial].
   - Dimensions are positive integers [S1, unofficial].
   Return the populated `MPRPlane` struct [S1, unofficial].

**Pseudocode:**
```python
def construct_patient_aligned_mpr_plane(plane_type, center, width, height, pixelSpacingUMm, pixelSpacingVMm):
    # Step 1: Determine anatomical axes based on plane type
    if plane_type == "axial":
        u = Vector3(1, 0, 0)
        v = Vector3(0, 1, 0)
    elif plane_type == "coronal":
        u = Vector3(1, 0, 0)
        v = Vector3(0, 0, 1)
    elif plane_type == "sagittal":
        u = Vector3(0, 1, 0)
        v = Vector3(0, 0, 1)
    else:
        raise ValueError("Invalid plane_type")

    # Step 2: Calculate half extents in world units
    halfU = (width - 1) * pixelSpacingUMm / 2.0
    halfV = (height - 1) * pixelSpacingVMm / 2.0

    # Step 3: Calculate origin in LPS world coordinates
    # origin = center - u * halfU - v * halfV
    origin = Vector3(
        x=center.x - u.x * halfU - v.x * halfV,
        y=center.y - u.y * halfU - v.y * halfV,
        z=center.z - u.z * halfU - v.z * halfV
    )

    # Step 4: Validate and return
    # Validation checks:
    # 1. u and v are unit length and orthogonal (guaranteed by definition above)
    # 2. spacing > 0
    # 3. width, height > 0
    if pixelSpacingUMm <= 0 or pixelSpacingVMm <= 0:
        raise ValueError("Pixel spacing must be positive")
    if width <= 0 or height <= 0:
        raise ValueError("Dimensions must be positive")

    return MPRPlane(
        origin=origin,
        u_direction=u,
        v_direction=v,
        spacing=(pixelSpacingUMm, pixelSpacingVMm),
        dimensions=(width, height)
    )
```

**Parameters:**
- **Section Thickness:** For secondary/thin-section volumetric data intended for high-quality MPR, a section thickness of ~1 mm or less is preferred, preferably with an overlapping interval [S3]. A typical secondary reconstruction thickness is 1.25 mm [S3].
- **Reconstruction Interval:** Typically 0.625 mm (50% overlap) for secondary data reconstruction [S3].
- **Primary Axial Review:** Typically 3–5 mm section thickness [S3].

**Edge Cases and Pitfalls:**
- **Precision:** Floating-point arithmetic for origin calculation may introduce minor rounding errors; ensure consistent precision across the rendering pipeline [G].
- **Boundaries:** The origin calculation assumes the center is the geometric center of the pixel grid. If the center is defined differently (e.g., voxel center vs. pixel center), the formula may need adjustment [G].
- **Degenerate Input:** Zero or negative dimensions/spacing will cause validation failure [S1, unofficial].

## Operating characteristics
- **Time Complexity:** O(1) for plane construction, as it involves a fixed number of arithmetic operations [S1, unofficial].
- **Memory Complexity:** O(1), storing only the plane geometry parameters [S1, unofficial].
- **Measured Performance:** Not given in the sources.
- **Scaling:** Independent of volume size; depends only on the requested plane dimensions [S1, unofficial].
- **Strengths:** Simple, fast, and anatomically intuitive for standard clinical views (axial, coronal, sagittal) [S3].
- **Limitations:** Limited to planes aligned with the LPS axes; cannot handle oblique or arbitrary angled planes without additional rotation logic [S1, unofficial].
- **When to use:** When generating standard diagnostic views from CT/CBCT data [S3].
- **When not to use:** When oblique reformation or arbitrary plane orientation is required [S1, unofficial].

## Background
Multiplanar Reformation (MPR) is a postprocessing technique used in computed tomography (CT) and magnetic resonance imaging (MRI) to reformat volumetric data into three orthogonal planes (X, Y, Z) for visualization [S2]. It allows operators to change the spatial position and orientation of planes according to visualization needs [S2]. MPR is commonly used to visualize anatomical structures in coronal or sagittal planes from axial CT data, such as bowel loop distribution or full-spine sagittal images [S3]. The technique was highlighted in the context of multidetector CT (MDCT) for creating nonaxial two-dimensional images from axial reconstruction data [S3].
