# Regular Texcell Slicing with Non-Linear Pre-filtering

Also called: Regular texcells, Slices parallel to ground

## Overview
Regular Texcell Slicing is a vegetation-specific volume rendering method that represents forest coverage using a stack of 2D textures (texcells) extruded vertically from a ground-plane triangle. It solves the problem of efficiently rendering large numbers of trees by avoiding CPU-side polygon generation for slice geometry and bypassing the blurring artifacts associated with isotropic 3D texture MIP-mapping at grazing angles. It sets itself apart from its parent, Vegetation-Specific Slicing, by using ground-parallel slices and non-linear pre-filtering to manage levels of detail, and from its sibling, Fiber Surface Texturing, by using volumetric alpha-blending rather than surface geometry.

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D polygonal representation of forest geometry (trees/leaves).
*   **Output:** A Level of Detail (LOD) pyramid of 2D alpha-premultiplied textures, and a rendering pipeline that slices these textures based on view distance and angle.

**Data Structures:**
The method uses a pyramid of texture sets $S_i$, where $i$ ranges from $0$ (coarsest) to $N$ (finest).
*   **Level $S_N$ (Finest):** Contains $n = 2^N$ slices. Each slice is a 2D texture of size $L \times L$.
*   **Level $S_i$ (Coarser):** Contains $2^i$ slices. Each slice is a 2D texture of size $L \cdot 2^{N-i} \times L \cdot 2^{N-i}$.
*   **Texture Format:** Alpha-premultiplied color. The color component $C \in \{R, G, B\}$ stores $C \times A$. Denoted as $\bar{C}$.
*   **MIP-mapping:** Each 2D texture in every level is MIP-mapped to handle filtering within the slice plane.

**Numbered Steps:**

1.  **Generate Finest Level ($S_N$):**
    Render $n = 2^N$ slices of the original 3D volume geometry using an orthographic camera looking down (parallel to the vertical axis $\vec{z}$).
    *   For each slice location, set the near and far clipping planes at distance $\delta/2$ above and below the slice center, where $\delta$ is the vertical spacing between slices.
    *   Render the geometry into an $L \times L$ texture.
    *   Store these $n$ textures as level $S_N$.

2.  **Generate Coarser Levels ($S_i$ for $i < N$):**
    Construct level $S_i$ from level $S_{i+1}$ by blending pairs of adjacent slices.
    *   For each $j$ from $0$ to $2^i - 1$:
        *   Retrieve slice $S_{i+1}[2j]$ (front) and $S_{i+1}[2j+1]$ (back).
        *   Blend them using the standard alpha-compositing equation for premultiplied colors:
            $$ \bar{C}_{result} = \bar{C}_{front} + (1 - A_{front}) \cdot \bar{C}_{back} $$
        *   The resulting texture becomes $S_i[j]$.
    *   Apply MIP-mapping to each resulting 2D texture in level $S_i$.

3.  **Rendering Setup (Vertex Shader):**
    Define a base triangle on the ground with vertices $P_1, P_2, P_3$. Extrude this vertically to form a prism.
    *   Calculate the opacity multiply factor $\pi_A$ for each vertex to correct for grazing angles:
        $$ \pi_A = sz \cdot \frac{\vec{N} \cdot \vec{z}}{|\vec{N} \cdot \vec{V}|} $$
        Where:
        *   $sz$ is the vertical scaling factor (ratio of mapped forest height to original sample height).
        *   $\vec{N}$ is the terrain normal.
        *   $\vec{z}$ is the vertical vector $(0, 1, 0)$.
        *   $\vec{V}$ is the view direction.
    *   Interpolate $\pi_A$ across the face during rasterization.

4.  **Rendering Execution:**
    *   Determine the number of slices to use based on distance to observer and incidence angle.
    *   Select the appropriate LOD level $S_i$ such that the slice spacing matches the desired sampling rate.
    *   Render the base triangle with the selected texture set.
    *   Modulate the texture color by the interpolated $\pi_A$ factor.
    *   Use hardware anisotropic filtering for best quality if available.

**Parameters:**
*   **$N$:** Logarithm of the number of finest slices. $n = 2^N$.
*   **$L$:** Base texture resolution (e.g., 256, 512).
*   **$\delta$:** Vertical distance between slices in the finest level.
*   **Pattern Count:** At least 8 aperiodic patterns are required for tiling to avoid repetitiveness and handle precomputed shading/shadows without rotation [S1].

**Edge Cases and Pitfalls:**
*   **Grazing Angles:** At grazing angles, the distance between slices along a ray ($\delta_v$) increases, but the same number of slices are traversed. This leads to incorrect total opacity (under-sampling) if not scaled. The opacity adjustment formula $A(dl) \approx \frac{dl}{\delta} A(\delta)$ must be used, clamping values $> 1$ [S1].
*   **3D Texture MIP-mapping:** Standard 3D texture MIP-mapping is isotropic and blurs volume data in the slicing direction at grazing angles. This method avoids 3D textures for regular texcells by using 2D textures and non-linear pre-filtering [S1].
*   **Clipping Planes:** When generating slices, objects outside the clip volume must still cast shadows if shadows are enabled [S1].

**Pseudocode:**

```python
# Constants
N = 8  # Example: 256 finest slices
L = 256 # Base texture size
delta = 0.1 # Vertical spacing in finest level

# Step 1: Generate Finest Level SN
SN = []
for j in range(2**N):
    slice_y = j * delta
    # Set clipping planes at slice_y - delta/2 and slice_y + delta/2
    texture = render_orthographic_slice(geometry, y=slice_y, near=delta/2, far=delta/2)
    SN.append(texture)

# Step 2: Generate Coarser Levels
LOD_Pyramid = [SN]
current_level = SN

for i in range(N - 1, -1, -1):
    next_level = current_level
    current_level = []
    num_slices = 2**i
    for j in range(num_slices):
        front_tex = next_level[2 * j]
        back_tex = next_level[2 * j + 1]
        
        # Blend using alpha compositing for premultiplied colors
        # C_bar_result = C_bar_front + (1 - A_front) * C_bar_back
        blended_tex = blend_premultiplied(front_tex, back_tex)
        
        # MIP-map the resulting 2D texture
        mipmapped_tex = generate_mipmaps(blended_tex)
        current_level.append(mipmapped_tex)
    
    LOD_Pyramid.append(current_level)

# Step 3: Rendering Function
def render_texcell(base_triangle_vertices, view_direction, terrain_normal, vertical_scaling, distance):
    # Determine LOD level based on distance and angle
    # This is a simplified heuristic; real implementation uses specific criteria
    i = calculate_lod_index(distance, view_direction, terrain_normal)
    texture_set = LOD_Pyramid[i]
    num_slices = len(texture_set)
    
    # Calculate opacity factor for vertices
    # pi_A = sz * (N . z) / |N . V|
    # Note: In practice, this is done per-vertex in the shader
    # Here we compute it for the triangle center for illustration
    N_dot_z = dot(terrain_normal, vec3(0, 1, 0))
    N_dot_V = dot(terrain_normal, view_direction)
    
    if abs(N_dot_V) < 1e-6:
        pi_A = 1.0 # Avoid division by zero
    else:
        pi_A = vertical_scaling * (N_dot_z / abs(N_dot_V))
        
    # Clamp opacity factor
    pi_A = min(pi_A, 1.0)
    
    # Render the triangle with the texture set
    # The vertex shader interpolates pi_A and selects texture coordinates
    # from the appropriate slice in texture_set based on depth
    render_triangle_with_volumetric_textures(base_triangle_vertices, texture_set, pi_A)

def blend_premultiplied(tex1, tex2):
    """
    Blends two alpha-premultiplied textures.
    tex1 is front, tex2 is back.
    """
    result = empty_texture(tex1.width, tex1.height)
    for x, y in pixels:
        c1 = tex1.get_color(x, y) # Premultiplied
        a1 = tex1.get_alpha(x, y)
        c2 = tex2.get_color(x, y) # Premultiplied
        
        # Formula: C_bar_front + (1 - A_front) * C_bar_back
        c_result = c1 + (1.0 - a1) * c2
        a_result = a1 + (1.0 - a1) * tex2.get_alpha(x, y) # Standard alpha comp for alpha channel
        
        result.set_color(x, y, c_result)
        result.set_alpha(x, y, a_result)
    return result
```

## Subtopics

### Silhouette Texcell Slicing
A variant for landscape silhouettes (grazing angles) where slices are nearly facing the viewer. It uses a tilted base triangle offset to generate slices on the GPU, avoiding CPU polygon generation. It differs from regular texcells by using 3D textures with adapted MIP-map levels to mitigate isotropic blurring, though 3D texture MIP-mapping has known implementation bugs. The base triangle is tilted to face the camera by calculating offsets $k_i = -\frac{\overline{GP_i} \cdot \overline{V}}{\overline{z} \cdot \overline{V}}$, and slices are generated by offsetting this tilted base. A maximum slant $k_M$ is often applied to prevent infinite slant at extreme grazing angles [S1].

## Operating characteristics
*   **Time Complexity:** Preprocessing is $O(n \cdot L^2)$ for generating the finest level, and $O(n \cdot L^2)$ for generating coarser levels (blending). Rendering is $O(1)$ per triangle, independent of the number of trees, as the complexity is in the texture generation, not the draw call.
*   **Memory Complexity:** $O(n \cdot L^2)$ for the finest level, with geometric series reduction for coarser levels. Total memory is roughly $1.33 \times$ the finest level size.
*   **Performance:** High performance for real-time rendering of thousands of trees. Avoids CPU-GPU transfer bottlenecks by generating slice geometry on the GPU (vertex shader) or using pre-generated 2D textures.
*   **Strengths:** Efficient LOD management via non-linear pre-filtering. No CPU-side polygon generation for slices. Good quality at normal incidence angles.
*   **Limitations:** Parallax error and visibility of slice boundaries at grazing angles. Requires careful opacity adjustment. 3D texture MIP-mapping bugs in hardware may affect the silhouette variant.
*   **When to Use:** Real-time forest rendering where performance is critical and view angles are mostly not grazing.
*   **When Not to Use:** Scenes with extreme grazing angles (use Silhouette Texcell Slicing instead) or when isotropic 3D texture MIP-mapping artifacts are unacceptable without the silhouette variant.

## Background
Originated in the paper "Rendering Forest Scenes in Real-Time" (2004) by Magnenat et al. The method was developed to address the limitations of existing volume rendering techniques for real-time forest visualization, specifically the high cost of polygonal rendering and the quality issues of 3D texture MIP-mapping. It builds on earlier work in volumetric textures [MN98, LPFH01] and alpha-premultiplied color blending [PD84]. The term "texcell" was coined to distinguish from "texel" (texture element) and avoid confusion with texture pixels [S1].
