# Fiber Surface Texturing


## Overview
Fiber Surface Texturing visualizes fiber fields on tetrahedral meshes by mapping fiber path parameters to a 1D texture map [S1]. It renders sparse, directional data by treating the fiber surface as a textured polygon rather than explicit geometry, leveraging texture hardware on a video card [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A tetrahedral mesh containing a Fiber Surface Curve Path (FSCP) defined by edges; a 1D texture map [S1].
*   **Output:** Rasterized image of the fiber surface with appropriate texture mapping [S1].

**Data Structures:**
*   **FSCP Edge:** Defined by vertices $u$ and $v$ [S1].
*   **1D Texture:** A 1D array of color values where black values $(0,0,0)$ indicate a fiber to be drawn and white values $(1,1,1)$ indicate no fiber [S1].

**Steps:**
1.  **Segment Processing:** The algorithm processes each segment of the FSCP separately [S1].
2.  **Vertex Parameterization:** For a segment defined by vertices $u$ and $v$, assign the local parameter $t=0$ to vertex $u$ and $t=1$ to vertex $v$ [S1]. Parameterize all vertices in the triangles forming the fiber surface to the segment's local scale [S1].
3.  **Global Mapping:** Map each vertex's local parameter to a global range $[0,1]$ representing the total length of the fiber path [S1].
4.  **Texture Lookup:** During rasterization, interpolate the global texture coordinates across each triangle [S1].
5.  **Rendering:** Sample the 1D texture at the interpolated coordinate; render black if the value indicates a fiber, otherwise render nothing [S1].

**Pseudocode:**
```python
def render_fiber_surface(triangles, fscp_edges):
    # 1. Compute cumulative edge lengths to normalize to global [0,1]
    cumulative = [0.0]
    for edge in fscp_edges:
        cumulative.append(cumulative[-1] + length(edge.u, edge.v))
    total = cumulative[-1]

    # 2. Assign global texture coordinates to vertices
    vertex_t = {}
    for i, edge in enumerate(fscp_edges):
        vertex_t[edge.u] = cumulative[i] / total
        vertex_t[edge.v] = cumulative[i+1] / total

    # 3. Rasterize triangles with interpolated coordinates
    image = []
    for tri in triangles:
        t0, t1, t2 = vertex_t[tri.v0], vertex_t[tri.v1], vertex_t[tri.v2]
        # Standard triangle rasterization loop
        for y, x in bounding_box_pixels(tri):
            if point_in_triangle((x, y), tri):
                # Barycentric interpolation of texture coordinates
                bary = barycentric_coords((x, y), tri)
                t = t0 * bary[0] + t1 * bary[1] + t2 * bary[2]
                # Sample 1D texture
                idx = clamp(int(t * TEXTURE_WIDTH), 0, TEXTURE_WIDTH - 1)
                color = TEXTURE_MAP[idx]
                if color == BLACK:
                    image.append((x, y, BLACK))
    return image
```

*   **Sharp Bends:** Regions where the original fiber surface algorithm is inaccurate are precisely at sharp bends in the polygon [S1].
*   **Precision:** Mapping vertex parameters to the global range $[0,1]$ requires careful floating-point handling to avoid discontinuities at segment boundaries [G].

## Subtopics

### [KRS Texturing](10157-krs-texturing.md)
A shading technique for Kernel-Reflection Sequences (KRS) that applies procedural or triplanar textures to kernel solids to eliminate observable repetitiveness. It addresses the visual artifact where applying identical coordinates to all kernel instances produces an extremely repetitive pattern that undesirably emphasizes symmetries. It sets itself apart from standard parametric texturing by handling complex or reflective kernels where simple $u,v$ parametrization is not feasible.

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Strengths:** Efficient use of hardware texture mapping; allows for easy visualization of fiber path length and continuity [S1].
*   **Limitations:** Inaccuracies of the underlying algorithm are visible at sharp bends; binary texture mapping limits shading complexity [S1].
*   **When to Use:** When visualizing fiber paths on tetrahedral meshes is required, and the primary interest is in the trajectory and continuity of fibers rather than volumetric density [S1].
*   **When Not to Use:** When high-fidelity volumetric rendering of fiber density is needed, or when the mesh has significant geometric inaccuracies at sharp bends [S1].

## Background
The method uses texture hardware on a video card to render fiber surfaces efficiently [S1]. It builds on assigning texture parameters to vertices based on their position along the FSCP [S1]. The approach simultaneously shows how fibers change across the surface and which regions correspond to domain values, indicating that topological analysis of fibers may provide further insight [S1].
