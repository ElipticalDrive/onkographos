# Slice-based Volume Rendering using Pixel Bender

Also called: Pixel Bender Slice Rendering

## Overview
A real-time volume rendering technique that uses view-aligned slices and a static 3D texture (set of cross sections), implemented via Pixel Bender shaders [S1, unofficial]. It differs from surface rendering methods (e.g., marching cubes) by rendering volume data directly without building an isosurface, allowing for translucent cross-sections [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A static 3D texture representing volume data as a set of 2D cross-sections [S1, unofficial]. The texture is typically packed into a 2D texture array or sprite sheet [S1, unofficial].
- Output: A 2D image where each pixel corresponds to a sample from the volume along the view direction [S1, unofficial].

**Data Structures:**
- **3D Texture:** Stored as a 2D texture with dimensions $W \times H$, where $W = N_z \times N_x$ and $H = N_y$ [S1, unofficial].
  - Example dimensions:
    - High quality: $4096 \times 128$ texture for a $128 \times 128 \times 32$ volume [S1, unofficial].
    - Low quality: $2048 \times 64$ texture [S1, unofficial].
    - Ultra quality: $4096 \times 128$ texture with 50 visible slices [S1, unofficial].
- **Slice Indexing:** The slice index $z$ is derived from the texture coordinate $v$ (vertical) by mapping $v \in [0, 1]$ to $z \in [0, N_z - 1]$ [S1, unofficial].

**Numbered Steps:**
1. **View-Aligned Slice Generation:** Generate view-aligned slices perpendicular to the camera view direction [S1, unofficial].
2. **Pixel-to-World Transformation:** For each pixel on every slice, calculate the point $p$ on the view-aligned slice [S1, unofficial].
3. **Change of Basis:** Determine the position of $p$ in the texture's 3D space using a change of basis transformation [S1, unofficial]. Since eye space equals world space in this implementation, the transformation is:
   $$ p_{\text{texture}} = M_{\text{object\_inverse}} \cdot p_{\text{eye}} $$
   where $M_{\text{object\_inverse}}$ is the inverse of the object's delta transformation matrix [S1, unofficial].
4. **Interpolation:** The transformed point $p_{\text{texture}}$ usually lies between two adjacent texture slices [S1, unofficial]. Sample both adjacent texture slices using constant $x$ and $y$ coordinates and interpolate the color values [S1, unofficial].
5. **Culling:** Cull half of the back slices to improve performance, as they contribute minimally to the final image [S1, unofficial].
6. **Rendering:** Perform these calculations for every pixel on every slice using Pixel Bender shaders [S1, unofficial].

**Parameters:**
- Number of cross sections: 32 (primary example) [S1, unofficial].
- Visible slices: 16 (high/low quality), 50 (ultra quality) [S1, unofficial].

**Pitfalls:**
- Interpolation is not aligned to the view direction, which is technically incorrect but accepted as a performance trade-off [S1, unofficial].
- Pixel Bender in FP10 is slow on conditionals, limiting alpha-testing capabilities [S1, unofficial].

**Pseudocode:**
```python
def render_pixel_bender_slices(volume_texture, object_inverse_matrix, num_visible_slices, slice_width, slice_height):
    # volume_texture: 2D array of shape (num_slices * slice_width, slice_height)
    # object_inverse_matrix: 4x4 matrix
    for slice_idx in range(num_visible_slices):
        # 1. Generate view-aligned slice geometry (assumed precomputed)
        for y in range(slice_height):
            for x in range(slice_width):
                # 2. Point on view-aligned slice in eye/world space
                p_eye = compute_point_on_slice(x, y, slice_idx)
                # 3. Change of basis to texture space
                p_texture = object_inverse_matrix @ p_eye
                # 4. Determine adjacent slices and interpolation factor
                z_float = p_texture.z
                z0 = int(math.floor(z_float))
                z1 = z0 + 1
                t = z_float - z0
                # 5. Map to texture coordinates (slices stacked horizontally)
                tex_x = (z0 * slice_width) + p_texture.x
                tex_y = p_texture.y
                # 6. Sample adjacent slices with constant x,y and interpolate
                c0 = sample_2d_texture(volume_texture, tex_x, tex_y)
                c1 = sample_2d_texture(volume_texture, tex_x + slice_width, tex_y)
                color = lerp(c0, c1, t)
                set_pixel_color(x, y, color)
```

## Operating characteristics
- **Time Complexity:** $O(N_{\text{visible}} \times W \times H)$ per frame, where $N_{\text{visible}}$ is the number of visible slices and $W \times H$ is the slice resolution [S1, unofficial].
- **Memory Complexity:** $O(N_z \times N_x \times N_y)$ for the packed 2D texture [S1, unofficial].
- **Measured Performance:** Real-time on compatible hardware, but scales linearly with visible slice count [S1, unofficial]. Ultra quality (50 slices) is slow [S1, unofficial].
- **Strengths:** Significantly faster than surface rendering methods; allows translucent cross-sections and easy per-slice visibility toggling [S1, unofficial].
- **Limitations:** Interpolation inaccuracy due to non-view-aligned sampling; conditional performance bottlenecks in Pixel Bender FP10 [S1, unofficial].

## Background
Originated by Der Schmale in 2009 as an alternative to sparse voxel octree ray casting using Alchemy [S1, unofficial]. It builds on earlier experiments with object-aligned slices [S1, unofficial].
