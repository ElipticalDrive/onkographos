# Cabral Texture Mapping
Also called: Filtered Back Projection via Texture Mapping, Texture Mapping Backprojection, Trilinear interpolation of texture mapped slices

## Overview
Cabral Texture Mapping is a volume rendering method that implements filtered back projection (FBP) for CT data using 2D texture mapping hardware and an accumulation buffer [S2, unofficial]. It differs from standard ray-casting texture slicing by treating the rendering process as a back-projection of pre-filtered data, allowing for specific shading and transfer function behaviors that standard texture interpolation might mishandle [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar volume dataset (CT data) and a viewing direction.
*   **Output:** A 2D image composited into the frame buffer.

**Data Structures:**
*   **Textures:** 2D textures are generated from the volume slices. The specific texel format is not detailed in the provided sources, but standard 2D texture mapping approaches imply RGBA or luminance formats [S2, unofficial].
*   **Accumulation Buffer:** A dedicated buffer used to accumulate the back-projected contributions [S2, unofficial].

**Steps:**
1.  **Texture Generation:** The volume data is sliced and loaded into 2D textures. The sources note that standard texture mapping can fail to interpolate non-linear transfer functions correctly, implying that shading or transfer function application may need to be handled carefully or re-applied if viewing parameters change [S2, unofficial].
2.  **Trilinear Interpolation:** During rendering, the system tri-linearly interpolates the scalar value from the volume data. This interpolation occurs at the texture coordinates corresponding to the ray intersection with the slice planes [S1, unofficial].
3.  **Back-to-Front Blending:** The texture-mapped slices are blended into the frame buffer (or accumulation buffer) in a back-to-front manner relative to the camera [S1, unofficial]. This compositing step effectively performs the back-projection accumulation.

**Pseudocode:**
```python
# Pseudocode for Cabral Texture Mapping rendering step
# Assumes volume data V, viewing direction view_dir, and texture objects are pre-loaded

def render_cabral_texture_mapping(V, view_dir):
    # 1. Determine slice planes based on view_dir
    # The specific axis selection logic is inherited from the parent family
    # [2D Texture Mapping Approaches](9842-2d-texture-mapping-approaches.md)
    slices = get_slices(V, view_dir)
    
    # 2. Sort slices back-to-front
    slices.sort_by_depth(back_to_front=True)
    
    # 3. Initialize accumulation buffer or frame buffer
    # Note: Cabral et al. specifically used an accumulation buffer [S2, unofficial]
    buffer = initialize_buffer()
    
    for slice in slices:
        # 4. Tri-linearly interpolate scalar value at current ray position
        # This step combines the 2D texture lookup with the 3rd dimension interpolation
        scalar_value = tri_linear_interpolate(V, slice.position, view_dir)
        
        # 5. Apply transfer function/shading
        # Standard texture hardware may not interpolate non-linear transfer functions correctly [S2, unofficial]
        color = apply_transfer_function(scalar_value)
        
        # 6. Blend into buffer back-to-front
        # Standard alpha blending equation from parent family
        alpha = get_alpha(scalar_value)
        buffer = blend_back_to_front(buffer, color, alpha)
        
    return buffer
```

**Parameters:**
*   **Accumulation Buffer:** Required for the specific implementation described by Cabral et al. [S2, unofficial].
*   **Hardware:** Originally implemented on Raster Manager Reality Engine Onyx machines [S2, unofficial].

**Edge Cases:**
*   **Transfer Function Interpolation:** Non-linear transfer functions are not interpolated correctly by standard texture hardware, potentially requiring re-shading or re-loading of data when viewing parameters change [S2, unofficial].

## Operating characteristics
*   **Performance:** The method relies on texture mapping hardware, which was accelerated on specialized systems like the Onyx [S2, unofficial].
*   **Limitations:** The requirement to re-shade and re-load data when viewing parameters change can be a drawback [S2, unofficial].
*   **Quality:** The use of tri-linear interpolation helps with spatial smoothness, but the reliance on 2D textures still inherits the lack of interpolation in the third dimension inherent to the parent family [S1, unofficial][S3, unofficial].

## Background
*   **Origin:** Proposed by Cabral et al. [S2, unofficial].
*   **Implementation:** The method was implemented using texture mapping in combination with an accumulation buffer on four Raster Manager Reality Engine Onyx machines [S2, unofficial].
*   **Context:** It is cited in the context of massive data management and distributed volume visualization, contrasting with other methods like PixelFlow or shear-warp approaches [S2, unofficial].
