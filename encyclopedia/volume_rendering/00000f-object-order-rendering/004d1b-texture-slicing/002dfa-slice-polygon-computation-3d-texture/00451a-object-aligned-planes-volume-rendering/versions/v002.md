# Object Aligned Planes Volume Rendering

Also called: Slice-based Volume Rendering, Texture 2D Volume Rendering

## Overview
Object Aligned Planes Volume Rendering represents a 3D scalar field as a set of 2D textures aligned with the object's axes (X, Y, Z) and renders them by projecting these slices onto the screen based on the camera's viewing direction, using transparency blending to composite the slices [S1, unofficial]. It differs from parent [Slice Polygon Computation (3D Texture)](5680-slice-polygon-computation-3d-texture.md) by avoiding 3D texture lookups and instead using pre-extracted 2D textures for each axis, and from sibling [Polygon-based Volumetric Rendering with Depth Peeling](8389-polygon-based-volumetric-rendering-with-depth-peeling.md) by relying on alpha blending rather than depth peeling for occlusion handling [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A raw binary volume file named `Name_XxYxZ.raw` located in `files/Modelos`, where X, Y, Z are dimensions [S1, unofficial].
- Output: A composited 2D image on the screen.

**Data Structures:**
The volume data is stored in a structure `vol` with the following fields:
- `XDIM`, `YDIM`, `ZDIM`: `int`, the dimensions of the volume along each axis [S1, unofficial].
- `BITS`: `int`, 8 or 16, indicating the bit depth of the voxel data [S1, unofficial].
- `texX`, `texY`, `texZ`: `GLuint*` arrays of size `XDIM`, `YDIM`, and `ZDIM` respectively, storing the 2D textures for slices along each axis [S1, unofficial].
- `distX`, `distY`, `distZ`: `float`, spacing constants calculated as `2.0f / (float)Dimension` for each axis [S1, unofficial].

**Numbered Steps:**

1. **Parse Filename:** Extract X, Y, Z dimensions from the filename `Name_XxYxZ.raw` [S1, unofficial]. Iterate backwards from the end of the string, identifying 'x' separators and the '.' extension to extract substrings for each dimension using `atoi` [S1, unofficial]. If any dimension remains -1 after parsing, return failure (malformed filename) [S1, unofficial].

2. **Load Raw Volume Data:** Read the file size [S1, unofficial]. Calculate `size = XDIM * YDIM * ZDIM` [S1, unofficial]. If file size matches `size`, set `BITS = 8` and load data as `GLubyte` (8-bit) [S1, unofficial]. If file size matches `size * 2`, set `BITS = 16` and load data as `GLushort` (16-bit) [S1, unofficial]. If size matches neither, print 'dimensiones erroneas' and return failure [S1, unofficial].

3. **Create 2D Textures for Z-Slices:** Allocate `texZ` array of size `ZDIM` [S1, unofficial]. For each slice `i` from 0 to `ZDIM-1`: bind `texZ[i]`, set wrap/filter parameters to `GL_CLAMP` / `GL_LINEAR` [S1, unofficial]. Extract the slice plane (constant Z) from the 3D volume array into a 2D buffer (`bit8` or `bit16`) [S1, unofficial]. Upload using `glTexImage2D` with internal format `1`, width `XDIM`, height `YDIM`, format `GL_LUMINANCE`, type `GL_UNSIGNED_BYTE` or `GL_UNSIGNED_SHORT` [S1, unofficial].

4. **Create 2D Textures for X-Slices:** Allocate `texX` array of size `XDIM` [S1, unofficial]. For each slice `i` from 0 to `XDIM-1`: bind `texX[i]` [S1, unofficial]. Extract slice plane (constant X) from volume [S1, unofficial]. Memory indexing: `volumen8[i*XDIM + j*XDIM*YDIM + k]` where `j` iterates Z and `k` iterates Y [S1, unofficial]. Upload with width `YDIM`, height `ZDIM` [S1, unofficial].

5. **Create 2D Textures for Y-Slices:** Allocate `texY` array of size `YDIM` [S1, unofficial]. For each slice `i` from 0 to `YDIM-1`: bind `texY[i]` [S1, unofficial]. Extract slice plane (constant Y) from volume [S1, unofficial]. Memory indexing: `volumen8[i + j*XDIM*YDIM + k*XDIM]` where `j` iterates Z and `k` iterates X [S1, unofficial]. Upload with width `XDIM`, height `ZDIM` [S1, unofficial].

6. **Determine Viewing Direction:** Unproject the center of the viewport `(viewport[2]/2.0f, viewport[3]/2.0f, 0.0f)` using ModelView and Projection matrices to get world coordinates `(wx, wy, wz)` [S1, unofficial]. Calculate absolute values `abswx = |wx|`, `abswy = |wy|`, `abswz = |wz|` [S1, unofficial].

7. **Render Slices:** Enable `GL_BLEND` [S1, unofficial]. If `shader` flag is true, use `glBlendFunc(GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA)`. Else, use `glBlendFunc(GL_SRC_COLOR, GL_ONE_MINUS_SRC_COLOR)` [S1, unofficial].
   - **If `abswz` is maximum:** Render Z-aligned slices [S1, unofficial]. If `wz >= 0` (front): iterate `i` from `ZDIM-1` down to 0 [S1, unofficial]. Set `dist = -1.0f` initially, increment by `distZ` each iteration [S1, unofficial]. Render quad at `z=dist` with texture `texZ[i]` [S1, unofficial]. If `wz < 0` (back): iterate `i` from 0 to `ZDIM-1` [S1, unofficial]. Set `dist = 1.0f` initially, decrement by `distZ` [S1, unofficial]. Call `glFrontFace(GL_CW)` before rendering [S1, unofficial].
   - **If `abswx` is maximum:** Render X-aligned slices [S1, unofficial]. If `wx >= 0` (right): iterate `i` from 0 to `XDIM-1` [S1, unofficial]. Set `dist = -1.0f` initially [S1, unofficial]. Render quad at `x=dist` with texture `texX[i]` [S1, unofficial]. (Logic for other directions and Y-axis follows the same pattern, iterating in appropriate order and adjusting `dist` and `glFrontFace` as needed) [S1, unofficial].
   - **If `abswy` is maximum:** Render Y-aligned slices [S1, unofficial]. Similar logic to X and Z, using `texY` and `distY` [S1, unofficial].

**Pseudocode:**

```python
def render_object_aligned_planes(vol, modelview, projection, viewport):
    # Step 6: Determine viewing direction
    # Unproject viewport center to world coordinates
    clip = [viewport[2]/2.0, viewport[3]/2.0, 0.0, 1.0]
    # Standard inverse projection and modelview multiplication [G]
    wx, wy, wz = multiply_vector_by_matrices(clip, inverse(projection), inverse(modelview))
    abswx = abs(wx)
    abswy = abs(wy)
    abswz = abs(wz)

    # Step 7: Render Slices
    # Enable alpha blending [G]
    blending_enabled = True
    if vol.shader:
        src_factor, dst_factor = GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA
    else:
        src_factor, dst_factor = GL_SRC_COLOR, GL_ONE_MINUS_SRC_COLOR

    if abswz >= abswx and abswz >= abswy:
        if wz >= 0:
            dist = -1.0
            for i in range(vol.ZDIM - 1, -1, -1):
                draw_slice_at_axis(vol.texZ[i], axis='z', pos=dist)
                dist += vol.distZ
        else:
            front_face_winding = 'CW'
            dist = 1.0
            for i in range(vol.ZDIM):
                draw_slice_at_axis(vol.texZ[i], axis='z', pos=dist)
                dist -= vol.distZ
            front_face_winding = 'CCW'
    elif abswx >= abswy:
        if wx >= 0:
            dist = -1.0
            for i in range(vol.XDIM):
                draw_slice_at_axis(vol.texX[i], axis='x', pos=dist)
                dist += vol.distX
        else:
            front_face_winding = 'CW'
            dist = 1.0
            for i in range(vol.XDIM - 1, -1, -1):
                draw_slice_at_axis(vol.texX[i], axis='x', pos=dist)
                dist -= vol.distX
            front_face_winding = 'CCW'
    else:
        if wy >= 0:
            dist = -1.0
            for i in range(vol.YDIM):
                draw_slice_at_axis(vol.texY[i], axis='y', pos=dist)
                dist += vol.distY
        else:
            front_face_winding = 'CW'
            dist = 1.0
            for i in range(vol.YDIM - 1, -1, -1):
                draw_slice_at_axis(vol.texY[i], axis='y', pos=dist)
                dist -= vol.distY
            front_face_winding = 'CCW'
```

## Operating characteristics
- Time complexity: Not given in the sources.
- Memory complexity: Not given in the sources.
- Measured performance: Not given in the sources.
- Scaling: Not given in the sources.
- Strengths: Simple implementation using standard 2D textures; supports transparency function to hide/show slices [S1, unofficial].
- Limitations: Relies on alpha blending which can be order-dependent and may not handle complex occlusions as well as depth peeling; limited to object-aligned planes which may not be optimal for all viewing angles [S1, unofficial].
- When to use: When simplicity and ease of implementation are prioritized, and the volume data is small enough to fit in 2D textures [S1, unofficial].
