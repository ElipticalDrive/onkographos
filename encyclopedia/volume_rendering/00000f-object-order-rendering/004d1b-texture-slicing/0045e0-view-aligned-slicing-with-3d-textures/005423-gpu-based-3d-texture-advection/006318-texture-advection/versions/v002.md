# Texture Advection

Also called: Direct Texture Advection, Moving Textures, Texture Transport

## Overview
Texture advection is a technique for visualizing vector fields by advecting a texture pattern on a continuous mesh of polygons, rather than compositing separate splats [S1, unofficial]. It differs from splatting methods by maintaining a continuous geometric surface that updates its texture coordinates according to the flow field [S1, unofficial].

## How it works
**Inputs:** A vector field $V(x, t)$, a continuous mesh of polygons, and a periodic texture pattern [S1, unofficial].
**Outputs:** A rendered image of the advected texture on the mesh [S1, unofficial].

**Data Structures:**
* **Mesh:** A set of polygons defined by vertices $P_i$ [S1, unofficial].
* **Texture Coordinates:** For each vertex $P$, a coordinate $Q$ representing the source point in the texture space [S1, unofficial].
* **Vector Field:** Discrete samples of velocity $V$ at spatial locations and time steps [S1, unofficial].

**Parameters:**
* **Texture Periodicity:** The texture pattern must be periodic to allow streamlines of arbitrary length to determine valid texture map addresses [S1, unofficial].

**Steps:**

1. **Initialize:** Set initial texture coordinates $Q(P, 0)$ for each vertex $P$ based on its initial position [G].
2. **Update Texture Coordinates (Steady 2D Flow):** For steady flows, keep polygon vertex positions $P$ constant [S1, unofficial]. Update texture coordinates $Q$ incrementally for each frame $t$ [S1, unofficial]. Find $Q(P, t)$ by tracking a streamline through $P$ backwards to find the point at time $0$ which moves to $P$ at time $t$ [S1, unofficial].
3. **Update Texture Coordinates (Time-Varying Flow):** For unsteady flows, use one of two methods [S1, unofficial]:
   * **Method 1 (PDE):** Derive and solve a partial differential equation for $Q(P, t)$ incrementally from frame to frame [S1, unofficial].
   * **Method 2 (Moving Vertices):** Move the mesh vertices themselves along forward particle traces, integrating incrementally from frame to frame [S1, unofficial].
4. **Mesh Management:** Clip polygons as they leave the region to be rendered [S1, unofficial]. Create any necessary new polygons where the flow enters the region [S1, unofficial].
5. **Rendering (3D Extension):** For 3D flows, composite several meshed sheets of semitransparent textured polygons on top of each other [S1, unofficial].

**Formulas:**
* $Q(P, t)$: The point at time $0$ which moves to vertex $P$ at time $t$ [S1, unofficial].
* Steady update: $Q_{t} = Q_{t-1} - V(Q_{t-1}) \cdot \Delta t$ [G].
* Unsteady vertex move: $P_{t} = P_{t-1} + V(P_{t-1}) \cdot \Delta t$ [G].

def texture_advection_steady_2d(mesh, vector_field, dt):
    """
    Advect texture on a static mesh for a steady 2D flow.
    """
    for vertex in mesh.vertices:
        # Evaluate velocity at current texture coordinate
        v = vector_field(vertex.texture_coordinate)
        # Backward integration to find source point Q
        vertex.texture_coordinate -= v * dt
        # Wrap to [0, 1) for periodic texture
        vertex.texture_coordinate %= 1.0

def texture_advection_unsteady_moving_vertices(mesh, vector_field, dt):

        v = vector_field(vertex.position)

**Edge Cases and Pitfalls:**
* **Periodicity:** The texture pattern must be periodic; otherwise, streamlines of arbitrary length will not determine good texture map addresses [S1, unofficial].
* **Mesh Topology:** Care must be taken to clip polygons leaving the region and create new polygons where flow enters [S1, unofficial].
* **Time-Varying Complexity:** Defining the backward point $Q$ for time-varying flows is more difficult because the backwards particle trace may be completely different for each frame [S1, unofficial].

## Operating characteristics
* **Performance:** Real-time animation is achievable for 2D flows by tracking only particles near a contour surface [S1, unofficial].
* **Hardware:** Originally done in software for 2D vector fields on a plane, but has now been extended to curved surfaces and implemented on GPUs [S2, unofficial].
* **3D Extension:** Requires compositing several meshed sheets of semitransparent textured polygons, which may impact performance compared to 2D [S1, unofficial].

## Background
* **Origin:** The method was described in the context of applying texture mapping to volume and flow visualization [S1, unofficial].
* **Development:** Initially implemented in software for 2D vector fields, it has been extended to curved surfaces and GPU implementation [S2, unofficial].
* **Relation to Other Methods:** It is related to Line Integral Convolution (LIC) where a texture is directly advected by the flow [S2, unofficial]. It contrasts with methods that composite separate textured splats for each data point or particle [S1, unofficial].
