# Gradient-Isosurface Texture Packing

Also called: Gradient Packing in Alpha Channel

## Overview
Gradient-Isosurface Texture Packing is a data layout strategy for 3D volume textures that stores surface gradients in the RGB components and the original scalar isovalue in the Alpha component [S1, unofficial]. This allows a single texture to serve as both the data source for shading (via interpolated normals) and the classification source (via the isovalue), eliminating the need for a second texture copy or runtime gradient calculation [S1, unofficial]. It sets itself apart from [AR mapping to 3D texture](884-ar-mapping-to-3d-texture.md) by embedding geometric shading information directly into the texture coordinates, and from [Uniform Grid](920-uniform-grid.md) by enabling hardware-accelerated normal interpolation during ray casting [S2].

## How it works
**Inputs:** A 3D volume dataset with scalar values $V(x,y,z)$ and computed gradient vectors $\nabla V(x,y,z) = (G_x, G_y, G_z)$ [S2].
**Outputs:** A 3D volume texture $T$ with four components per voxel, where RGB stores the gradient and Alpha stores the original scalar/isovalue [S1, unofficial].

**Data Structures:**
The texture stores four components per voxel:
- $R = G_x$ (Gradient X component)
- $G = G_y$ (Gradient Y component)
- $B = G_z$ (Gradient Z component)
- $A = V$ (Original scalar/isovalue)
Sources note that older hardware implementations used four 8-bit values loaded into an RGB-type texture map, while modern approaches use 16-bit floats [S2][S1, unofficial].

**Steps:**
1. **Gradient Computation:** Compute the gradient $\nabla V$ for each voxel [S2]. The central difference scheme calculates the gradient using adjacent samples: $\nabla V(x,y,z) \approx (V(x+1,y,z) - V(x-1,y,z), V(x,y+1,z) - V(x,y-1,z), V(x,y,z+1) - V(x,y,z-1))$ [S2]. Sources cite high-quality Sobel filters for offline computation [S2]. Optional filtering includes averaging neighboring gradients or applying a separable 3D Gaussian kernel to smooth them [S1, unofficial].
2. **Pack Data:** Construct a packed array for each voxel containing the gradient components and the original scalar value [S1, unofficial].
3. **Upload:** Upload the packed array to the GPU as a 3D volume texture [S1, unofficial].

**Pseudocode:**
```python
def pack_gradients(volume_data: list, resolution: int):
    """
    Pack gradients and isovalue into a 3D texture format.
    volume_data: 3D list of scalar values.
    resolution: N x N x N grid size.
    Returns: 3D list of tuples (gx, gy, gz, val).
    """
    packed_volume = [[[None for _ in range(resolution)] for _ in range(resolution)] for _ in range(resolution)]
    
    for z in range(resolution):
        for y in range(resolution):
            for x in range(resolution):
                # Central difference approximation with boundary clamping [G]
                gx = volume_data[min(x+1, resolution-1)][y][z] - volume_data[max(x-1, 0)][y][z]
                gy = volume_data[x][min(y+1, resolution-1)][z] - volume_data[x][max(y-1, 0)][z]
                gz = volume_data[x][y][min(z+1, resolution-1)] - volume_data[x][y][max(z-1, 0)]
                
                # Normalize gradient to unit length [G]
                norm = (gx**2 + gy**2 + gz**2)**0.5
                if norm > 0.0:
                    gx, gy, gz = gx/norm, gy/norm, gz/norm
                
                packed_volume[z][y][x] = (gx, gy, gz, volume_data[x][y][z])
                
    return packed_volume

def sample_packed_texture(packed_volume: list, pos: tuple, resolution: int):
    """
    Sample the packed texture to retrieve normal and isovalue.
    pos: (x, y, z) floating point coordinates.
    """
    # Hardware interpolation handles linear interpolation of RGB (normal) and A (value) [S2]
    x, y, z = pos
    # Trilinear interpolation for software implementation [G]
    def lerp(a, b, t): return a + t * (b - a)
    
    ix, iy, iz = int(x), int(y), int(z)
    fx, fy, fz = x - ix, y - iy, z - iz
    
    def get_v(dx, dy, dz):
        return packed_volume[min(iz+dz, resolution-1)][min(iy+dy, resolution-1)][min(ix+dx, resolution-1)]
        
    r = lerp(lerp(lerp(get_v(0,0,0)[0], get_v(1,0,0)[0], fx), lerp(get_v(0,1,0)[0], get_v(1,1,0)[0], fx), fy),
             lerp(lerp(get_v(0,0,1)[0], get_v(1,0,1)[0], fx), lerp(get_v(0,1,1)[0], get_v(1,1,1)[0], fx), fy), fz)
    g = lerp(lerp(lerp(get_v(0,0,0)[1], get_v(1,0,0)[1], fx), lerp(get_v(0,1,0)[1], get_v(1,1,0)[1], fx), fy),
             lerp(lerp(get_v(0,0,1)[1], get_v(1,0,1)[1], fx), lerp(get_v(0,1,1)[1], get_v(1,1,1)[1], fx), fy), fz)
    b = lerp(lerp(lerp(get_v(0,0,0)[2], get_v(1,0,0)[2], fx), lerp(get_v(0,1,0)[2], get_v(1,1,0)[2], fx), fy),
             lerp(lerp(get_v(0,0,1)[2], get_v(1,0,1)[2], fx), lerp(get_v(0,1,1)[2], get_v(1,1,1)[2], fx), fy), fz)
    a = lerp(lerp(lerp(get_v(0,0,0)[3], get_v(1,0,0)[3], fx), lerp(get_v(0,1,0)[3], get_v(1,1,0)[3], fx), fy),
             lerp(lerp(get_v(0,0,1)[3], get_v(1,0,1)[3], fx), lerp(get_v(0,1,1)[3], get_v(1,1,1)[3], fx), fy), fz)
                 
    return (r, g, b), a
```

**Parameters:**
- **Gradient Filter:** Sobel or Central Difference. Sobel is preferred for offline quality [S2].
- **Texture Format:** Must support 4 components. 8-bit integers were used on older hardware, while 16-bit floats are common for gradient precision [S2][S1, unofficial].

**Edge Cases:**
- **Zero Gradient:** If the gradient magnitude is zero (flat region), normalization fails. [G] Set gradient to $(0,0,0)$ or a default normal.
- **Boundary Conditions:** Central differences require neighbors outside the volume. [G] Clamp coordinates to the nearest boundary voxel.
- **Precision:** Storing normalized gradients in 8-bit integers loses precision. 16-bit floats are recommended for modern implementations [S1, unofficial].

## Subtopics

### Pre-computed Gradient Resampling
A technique where volume gradients are pre-computed and stored in texture memory alongside density data, allowing the texture mapping hardware to interpolate both density and gradients during resampling [S2]. It sets itself apart from Sommer et al.'s method, which computes gradients from a second copy of the volume in main memory (slower for translucent projections), by using hardware interpolation for throughput [S2]. Choose this when dynamic lighting and high-quality shading are required without reloading textures [S2].

## Operating characteristics
- **Time Complexity:** Gradient computation is performed serially offline [S2]. Rendering is $O(1)$ per sample for shading without extra texture fetches for normals [S1, unofficial].
- **Memory Complexity:** Requires 4 components per voxel [S1, unofficial].
- **Performance:** On a 200MHz CPU, computing gradients for a $256^3$ volume takes 12 seconds [S2]. Rendering speed depends on the base ray-casting implementation but benefits from reduced memory bandwidth for shading data [S2].
- **Strengths:** Enables dynamic lighting changes without reloading texture memory [S1, unofficial]. Hardware-accelerated interpolation of normals [S2].
- **Limitations:** Gradients are static; cannot handle dynamic volume changes without recomputation [S2]. Offline computation cost [S2].

## Background
Originated from early 3D texture mapping hardware acceleration research [S2]. Cullip and Neumann described a method utilizing the PixelFlow machine that pre-computed gradient components [S2]. Sommer et al. proposed resampling texture volumes in planes parallel to image pixels [S2]. The specific packing of gradients into RGB and isovalue into Alpha is detailed in unofficial tutorials [S1, unofficial].
