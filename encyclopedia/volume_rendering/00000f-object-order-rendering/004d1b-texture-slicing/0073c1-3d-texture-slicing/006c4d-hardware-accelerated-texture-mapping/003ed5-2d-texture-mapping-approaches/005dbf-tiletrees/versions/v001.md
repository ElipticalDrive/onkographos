# TileTrees


## Overview
TileTrees are a data structure for texture mapping surfaces that stores square texture tiles in the leaves of an octree surrounding the surface [S1]. At rendering time, the surface is projected onto the tiles, and color is retrieved by a 2D texture fetch into a tile map [S1]. This method avoids global planar parameterizations, supports implicit surfaces, and allows adaptive resolution [S1]. Unlike volume approaches that store the surface as a thick layer requiring 8 samples for tri-linear interpolation, TileTrees map 2D tiles, requiring only 4 samples and avoiding the 2x data overhead [S1]. Unlike polycube maps which require manual intervention and fixed resolution, TileTrees do not require manual intervention and support adaptive resolution [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A surface (triangle mesh or implicit) and a user-specified coverage threshold.
*   **Output:** A tile map (a regular 2D texture) and an octree data structure storing tile coordinates.

**Data Structures:**
1.  **Octree:** Stores leaf nodes. Each leaf node contains:
    *   Bounding box of the leaf.
    *   Coordinates of the top-left corner of the allocated tile(s) in the tile map.
    *   Classification: Full-leaf, boundary-leaf, leaf-stack, or n-leaf [S1].
2.  **Tile Map:** A single regular 2D texture containing all allocated tiles packed contiguously [S1].

**Parameters:**
*   **Tile Size ($S$):** $S = 2k + 1$, where $k$ is a positive integer [S1]. This ensures sample alignment across boundaries and between adaptive resolution levels [S1].
*   **Coverage Threshold:** A user-specified threshold used to enforce coverage by subdividing leaves that have insufficient coverage [S1].

**Steps:**

1.  **Build Octree:** Build an octree around the surface to be textured [S1].
2.  **Subdivide for Injectivity:** Subdivide the octree until no more than one fold exists in each leaf in the direction of projection. This ensures the projection is injective [S1].
3.  **Enforce Coverage:** Subdivide leaves further if the surface coverage within the leaf face is below the user-specified threshold [S1].
4.  **Create Leaf Stacks:** Subdivide to create leaf-stacks where necessary to handle complex topology or ensure proper tiling [S1].
5.  **Map Tiles:** Map 2D tiles of texture data onto the faces of the octree leaves. Each leaf can contain up to six tiles (one per face) [S1].
    *   Tiles are mapped such that the centers of the border samples align with the boundaries of the face [S1].
    *   For n-leaves (leaves with $n$ tiles), tiles are stored contiguously in a rectangle of size $n(2k+1) \times (2k+1)$, where $1 \leq n \leq 6$ [S1].
6.  **Pack Tile Map:** Compact all texture tiles into a regular 2D texture called the tile map [S1].
    *   Store coordinates of top-left corners in octree leaves [S1].
    *   Packing algorithm: Place larger tiles first, left-to-right, top-to-bottom. Track the first free column of every texture row for speed [S1].
7.  **Rendering Projection:** During rendering, project each surface point onto one leaf face using a parallel projection determined by the surface normal's major direction [S1].
8.  **Texture Fetch:** Use the resulting texture coordinates to access the corresponding texture tile in the tile map [S1].

**Pseudocode:**

```python
def build_tile_tree(surface, coverage_threshold):
    """
    Builds the TileTree data structure.
    """
    # Step 1: Build initial octree
    octree = Octree()
    octree.insert(surface)
    
    # Step 2 & 3: Subdivide until injective and coverage is met
    # A leaf is valid if it has <= 1 fold in projection direction
    # and surface coverage > coverage_threshold
    while octree.has_invalid_leaves():
        leaf = octree.get_invalid_leaf()
        octree.subdivide(leaf)
        
    # Step 4: Create leaf stacks if needed (implementation detail from [S1])
    octree.create_leaf_stacks()
    
    # Step 5: Determine tile mapping
    # Each leaf maps to 1-6 tiles on its faces
    tiles = []
    for leaf in octree.leaves:
        # Determine face(s) based on surface normal
        faces = get_faces_from_normal(leaf.normal)
        for face in faces:
            tile = create_tile(leaf, face)
            tiles.append(tile)
            
    # Step 6: Pack tiles into tile map
    tile_map_size = estimate_tile_map_size(tiles)
    tile_map = Texture2D(tile_map_size)
    
    # Naive packing: larger tiles first, left-to-right, top-to-bottom
    tiles.sort(key=lambda t: t.size, reverse=True)
    row_free_columns = [0] * tile_map.height
    
    for tile in tiles:
        # Find position
        col = row_free_columns[tile.row]
        pos = (col, tile.row)
        
        # Store top-left corner in leaf
        leaf = tile.leaf
        leaf.tile_map_coords = pos
        
        # Copy tile data to texture
        tile_map.copy(tile.data, pos)
        
        # Update free column tracker
        row_free_columns[tile.row] += tile.width
        
    return octree, tile_map

def render_tile_tree(octree, tile_map, surface_point, surface_normal):
    """
    Renders a single point using the TileTree.
    """
    # Find enclosing leaf
    leaf = octree.find_leaf(surface_point)
    
    # Determine projection face based on normal
    # Major direction of normal determines the face
    face = get_projection_face(surface_normal)
    
    # Parallel projection onto the leaf face
    # Project surface_point onto the plane of the face
    projected_point = project_onto_face(surface_point, face)
    
    # Calculate texture coordinates within the tile
    # The tile is stored in tile_map at leaf.tile_map_coords
    tile_offset = leaf.tile_map_coords
    tile_size = leaf.tile_size # 2k + 1
    
    # Normalize projected point to tile local coordinates
    # Assuming face is unit square relative to leaf
    u, v = get_local_coords(projected_point, face)
    
    # Scale to tile pixel coordinates
    tex_u = tile_offset.x + u * tile_size
    tex_v = tile_offset.y + v * tile_size
    
    # Fetch from tile map with bilinear filtering
    color = tile_map.sample(tex_u, tex_v)
    
    return color
```

**Edge Cases and Pitfalls:**
*   **Non-surjectivity:** The parallel projection is not surjective, meaning some parts of the leaf faces may never be covered by the projected surface, resulting in wasted memory space in the tile map [S1].
*   **Distortion:** Small amounts of distortion are present on steep surfaces due to the parallel projection [S1].
*   **Sample Duplication:** Neighboring tiles encode the same samples along their boundary to ensure seamless rendering [S1].
*   **Foldovers:** If a leaf contains more than one fold in the direction of projection, the projection is no longer injective, leading to incorrect texture mapping [S1].

## Subtopics

### Tile Allocation and Packing
Tile allocation and packing refers to the process of assigning texture tiles to octree leaves and packing them into a single texture (tile-map) to enable seamless rendering and hardware bilinear filtering [S1]. Tiles are mapped such that border sample centers align with face boundaries [S1]. Tiles within n-leaves are stored contiguously in a rectangle of size $n(2k+1) \times (2k+1)$ where $1 \leq n \leq 6$ [S1]. The packing algorithm places larger tiles first, left-to-right, top-to-bottom, tracking the first free column of every texture row for speed [S1]. This approach placed 18,664 tiles in 96 milliseconds on the armadillo model [S1].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** More compact than volume approaches, avoiding the 2x data overhead [S1]. However, non-surjectivity leads to wasted memory space in the tile map [S1].
*   **Measured Performance:** Packing performance: 18,664 tiles placed in 96 milliseconds on the armadillo model [S1].
*   **Scaling:** Not given in the sources.
*   **Strengths:** Avoids global planar parameterizations, supports implicit surfaces, allows adaptive resolution, requires no manual intervention, and provides fast access to data [S1]. It uses only 4 samples for interpolation compared to 8 in volume approaches [S1].
*   **Limitations:** Non-surjectivity leads to wasted memory; small distortion on steep surfaces; requires careful subdivision to avoid foldovers [S1].
*   **When to use:** Interactive painting applications, texturing implicit surfaces, scenarios requiring adaptive resolution without manual parameterization [S1].
*   **When not to use:** When minimal memory waste is critical and surfaces are very steep (due to distortion and non-surjectivity) [S1].

## Background
TileTrees were introduced by Sylvain Lefebvre and Carsten Dachsbacher [S1]. The method was developed to address the space and time overhead of previous volume-based texturing approaches [S1]. Previous methods by Benson and Davis [2002] and DeBry et al. [2002] used octrees but suffered from unused entries and long chains of indirection [S1]. Polycube maps required manual intervention and fixed resolution [S1]. TileTrees build on these ideas by mapping 2D tiles to octree faces, enabling seamless interpolation and adaptive resolution [S1]. It is used in interactive painting applications to create, edit, and render objects without converting between texture representations [S1].
