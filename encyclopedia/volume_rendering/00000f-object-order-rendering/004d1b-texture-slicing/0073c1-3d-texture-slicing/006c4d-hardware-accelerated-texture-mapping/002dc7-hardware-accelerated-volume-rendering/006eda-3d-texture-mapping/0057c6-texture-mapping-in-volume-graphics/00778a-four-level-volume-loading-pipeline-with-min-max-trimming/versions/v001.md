# Four-level Volume-Loading Pipeline with Min-Max Trimming

Also called: Min-Max Array Based Volume Loading, Texture Mapping Hardware Volume Rendering with Preprocessing

## Overview
This method accelerates volume rendering on hardware with limited texture memory by preprocessing large volume datasets to exclude empty voxels before they enter the rendering pipeline [S1]. It differs from standard 3D texture mapping by introducing a classification and trimming stage that reduces the volume of data transferred to texture memory, thereby saving 40% to 60% of rendering time for large datasets [S1]. It builds on [Texture Mapping in Volume Graphics](16044-texture-mapping-in-volume-graphics.md) by adding a specific four-level loading and preprocessing architecture.

## How it works
The method operates on a four-level pipeline: Disk $\rightarrow$ Volume Buffer $\rightarrow$ Texture Buffer $\rightarrow$ Texture Cache [S1].

### Inputs and Outputs
*   **Input:** Axis-aligned volume data stored as an $l \times m \times n$ 3D array on disk, where $l, m, n$ are the lengths in voxels along the X, Y, and Z axes respectively [S1]. A classification threshold defining "empty" vs. "object" voxels [S1].
*   **Output:** A rendered image generated by blending resampled texture blocks [S1].

### Data Structures

**1. Volume Block**
The volume is divided into uniform blocks of size $2^d \times 2^d \times 2^d$ [S1].
*   **Layout:** A 3D array of voxel values.
*   **Boundary Handling:** Blocks share boundary voxel data with neighboring blocks to avoid seams [S1].
*   **Padding:** If the last block along an axis is not fully filled, the remaining part is filled with empty voxels [S1].

**2. Min-Max Arrays**
For each volume block, three 1D arrays are generated, one for each axis (X, Y, Z) [S1].
*   **Size:** Each array has $2^d$ elements [S1].
*   **Content:** The $i$-th element records the minimum and maximum data value of the corresponding data slice along that axis [S1].
*   **Purpose:** Used to determine the bounding box of object voxels within the block [S1].

**3. Block List Node**
A node in the list of processed blocks [S1].
*   **Fields:**
    *   Pointer to the volume block data.
    *   The three min-max arrays (X, Y, Z).
    *   The block's position in world space [S1].

**4. Texture Block**
The result of trimming a volume block [S1].
*   **Layout:** A subset of the original volume block containing only object voxels (and necessary boundary data) [S1].
*   **Storage:** Stored in the Texture Buffer, eventually merged into texture chunks [S1].

**5. Texture Chunk**
A merged collection of texture blocks [S1].
*   **Storage:** Stored in an array and loaded in tiled page mode [S1].

### Parameters
*   **Block Size ($2^d$):** Must be equal along each axis [S1]. It must be at least the size of the smallest texture page to simplify merging and avoid hardware overhead from irregular fragments [S1].
*   **Texture Cache Constraints:**
    *   Page size: $2^n \times 2^m$ for 2D texture or $2^n \times 2^m \times 2^s$ for 3D texture [S1].
    *   Capacity: At most $2^k$ texture pages can be resident in the cache at the same time [S1].
    *   Minimum I/O unit: One texture page [S1].
    *   $n, m, s, k$ are constants determined by the hardware configuration [S1].

### Algorithm Steps

1.  **Calculate Block Grid:**
    Determine the number of blocks along each axis using ceiling functions [S1]:
    $$ N_x = \left\lceil \frac{l-1}{2^d-1} \right\rceil, \quad N_y = \left\lceil \frac{m-1}{2^d-1} \right\rceil, \quad N_z = \left\lceil \frac{n-1}{2^d-1} \right\rceil $$
    Total blocks: $N_x \times N_y \times N_z$ [S1].

2.  **Load Volume Blocks:**
    Load volume blocks from disk into the Volume Buffer block by block [S1]. Fill any incomplete last blocks with empty voxels [S1].

3.  **Generate Min-Max Arrays:**
    For each loaded volume block, create the three min-max arrays (X, Y, Z) by scanning the slices along each axis [S1].

4.  **Build Block List:**
    Create a list where each node contains a pointer to the volume block, its min-max arrays, and its world space position [S1].

5.  **Classify and Trim:**
    For each block in the list, given a classification threshold:
    a.  Traverse the min-max arrays to find bounding intervals $[L_x, R_x]$, $[L_y, R_y]$, and $[L_z, R_z]$ for object voxels [S1].
        *   Voxels are considered empty if their coordinate index is outside the interval for that axis (e.g., $i < L_x$ or $i > R_x$) [S1].
    b.  Calculate the volume of the bounding box defined by these intervals.
    c.  Determine the block type:
        *   **White Block:** If bounding box volume is zero, all voxels are empty. Mark as 'white' and discard [S1].
        *   **Black Block:** If bounding box volume equals the block volume ($2^{3d}$), the block cannot be trimmed. Mark as 'black' and move all data to the Texture Buffer as a texture block [S1].
        *   **Grey Block:** If partial trimming is possible. Mark as 'grey' [S1].
            *   Choose the trimming axis along which the interval length ($R - L + 1$) is shortest [S1].
            *   Trim the block along this axis, removing empty voxels outside the interval [S1].
            *   Move the remaining part (containing object voxels) to the Texture Buffer as a texture block [S1].

6.  **Merge Texture Blocks:**
    Merge texture blocks in the Texture Buffer into bigger texture chunks to reduce I/O overhead [S1]. Store texture data in an array and prepare for tiled page loading [S1].

7.  **Render:**
    a.  Sort texture chunks by view direction (back to front) [S1].
    b.  Load chunks into the Texture Cache [S1].
    c.  Resample texture blocks using polygons clipped by their bounding boxes [S1].
    d.  Blend back to front to generate the image [S1].

import math

def compute_block_dimensions(l, m, n, d):
    """
    Computes the number of blocks along each axis.
    l, m, n: dimensions of the volume data.
    d: exponent for block size 2^d.
    """
    block_size = 2**d
    # Formula from source: ceil((dim - 1) / (block_size - 1))
    nx = math.ceil((l - 1) / (block_size - 1))
    ny = math.ceil((m - 1) / (block_size - 1))
    nz = math.ceil((n - 1) / (block_size - 1))
    return nx, ny, nz

def generate_min_max_arrays(volume_block, axis):
    """
    Generates min-max array for a specific axis of a volume block.
    volume_block: 3D array of shape (2^d, 2^d, 2^d).
    axis: 0 for X, 1 for Y, 2 for Z.
    Returns: List of tuples (min_val, max_val) for each slice along the axis.
    """
    size = 2**d
    min_max_arr = []
    
    # Iterate through slices along the specified axis
    for i in range(size):
        if axis == 0: # X-axis slices
            # Extract slice at index i along X
            # Shape becomes (2^d, 2^d)
            slice_data = volume_block[i, :, :]
        elif axis == 1: # Y-axis slices
            slice_data = volume_block[:, i, :]
        else: # Z-axis slices
            slice_data = volume_block[:, :, i]
        
        min_val = min(slice_data.flatten())
        max_val = max(slice_data.flatten())
        min_max_arr.append((min_val, max_val))
        
    return min_max_arr

def find_bounding_intervals(min_max_arrays, threshold):
    """
    Finds bounding intervals [L, R] for object voxels based on min-max arrays.
    min_max_arrays: List of (min, max) tuples for all slices along an axis.
    threshold: Classification threshold.
    Returns: (L, R) interval. If no object voxels, returns None.
    """
    L = None
    R = None
    
    for i, (min_val, max_val) in enumerate(min_max_arrays):
        # Check if this slice contains any object voxels
        # Assuming object voxels are >= threshold
        if max_val >= threshold:
            if L is None:
                L = i
            R = i
            
    if L is None:
        return None # No object voxels in this axis projection
        
    return (L, R)

def trim_block(volume_block, intervals_x, intervals_y, intervals_z):
    """
    Trims the volume block based on bounding intervals.
    intervals_x, intervals_y, intervals_z: Tuples (L, R) or None.
    Returns: Trimmed volume block (numpy array or similar) or None if empty.
    """
    size = 2**d
    
    # Determine bounds
    if intervals_x is None or intervals_y is None or intervals_z is None:
        return None # Empty block (White)
        
    lx, rx = intervals_x
    ly, ry = intervals_y
    lz, rz = intervals_z
    
    # Extract the bounding box
    # Note: Source implies trimming along the shortest interval axis first,
    # but the final texture block contains the bounding box of object voxels.
    # The source says: "The remaining part that contains object voxels are moved..."
    # and "choose the trimming axis... to be the one along which the interval length is the shortest."
    # This implies a sequential or axis-aligned trimming. 
    # However, the result is a block defined by the bounding box [Lx, Rx] x [Ly, Ry] x [Lz, Rz].
    # We will extract the bounding box directly as it represents the trimmed data.
    
    trimmed = volume_block[lx:rx+1, ly:ry+1, lz:rz+1]
    return trimmed

def classify_block(min_max_arrays_x, min_max_arrays_y, min_max_arrays_z, threshold, block_volume):
    """
    Classifies a block as White, Black, or Grey.
    Returns: 'white', 'black', 'grey', or 'empty' (if white).
    """
    int_x = find_bounding_intervals(min_max_arrays_x, threshold)
    int_y = find_bounding_intervals(min_max_arrays_y, threshold)
    int_z = find_bounding_intervals(min_max_arrays_z, threshold)
    
    # If any interval is None, the block is empty
    if int_x is None or int_y is None or int_z is None:
        return 'white'
        
    lx, rx = int_x
    ly, ry = int_y
    lz, rz = int_z
    
    # Calculate bounding box volume
    # Length of interval is R - L + 1
    bx = rx - lx + 1
    by = ry - ly + 1
    bz = rz - lz + 1
    bbox_volume = bx * by * bz
    
    if bbox_volume == 0:
        return 'white'
    elif bbox_volume == block_volume:
        return 'black'
    else:
        return 'grey'

def process_volume_data(volume_data, threshold, d):
    """
    Main processing pipeline.
    """
    l, m, n = volume_data.shape
    block_size = 2**d
    
    nx, ny, nz = compute_block_dimensions(l, m, n, d)
    
    block_list = []
    texture_buffer = []
    
    # Iterate over all blocks
    for iz in range(nz):
        for iy in range(ny):
            for ix in range(nx):
                # Calculate source and destination indices
                # Blocks overlap by 1 voxel? Source says "shares boundary voxel data".
                # Formula for block count uses (2^d - 1) as stride.
                # This implies overlap of 1 voxel between adjacent blocks.
                stride = block_size - 1
                
                start_x = ix * stride
                start_y = iy * stride
                start_z = iz * stride
                
                end_x = min(start_x + block_size, l)
                end_y = min(start_y + block_size, m)
                end_z = min(start_z + block_size, n)
                
                # Extract block, padding with empty voxels if necessary
                # Assuming empty voxel value is 0 or min possible. 
                # We create a full block_size array and copy data.
                block = np.zeros((block_size, block_size, block_size))
                
                # Determine actual size of data in this block
                dx = end_x - start_x
                dy = end_y - start_y
                dz = end_z - start_z
                
                block[:dx, :dy, :dz] = volume_data[start_x:end_x, start_y:end_y, start_z:end_z]
                
                # Generate Min-Max Arrays
                mm_x = generate_min_max_arrays(block, 0)
                mm_y = generate_min_max_arrays(block, 1)
                mm_z = generate_min_max_arrays(block, 2)
                
                # Classify
                block_type = classify_block(mm_x, mm_y, mm_z, threshold, block_size**3)
                
                if block_type == 'white':
                    continue # Discard
                elif block_type == 'black':
                    # Move all data to texture buffer
                    texture_block = block
                else: # Grey
                    # Trim
                    trimmed = trim_block(block, 
                                         find_bounding_intervals(mm_x, threshold),
                                         find_bounding_intervals(mm_y, threshold),
                                         find_bounding_intervals(mm_z, threshold))
                    if trimmed is None:
                        continue
                    texture_block = trimmed
                
                # Add to texture buffer
                texture_buffer.append(texture_block)
                
                # Add to block list for rendering info
                block_list.append({
                    'pointer': texture_block,
                    'min_max': (mm_x, mm_y, mm_z),
                    'world_pos': (start_x, start_y, start_z) # Approximate
                })
                
    # Merge texture blocks into chunks (Implementation detail not fully specified in source)
    # Source: "Merge texture blocks... into bigger texture chunks... stored in an array and loaded in tiled page mode."
    texture_chunks = merge_texture_blocks(texture_buffer)
    
    return texture_chunks, block_list

### Edge Cases and Pitfalls
*   **Incomplete Blocks:** The last block along any axis may not be fully filled. It must be padded with empty voxels to maintain the $2^d \times 2^d \times 2^d$ structure [S1].
*   **Seams:** Blocks must share boundary voxel data with neighbors to prevent visual artifacts [S1].
*   **Hardware Overhead:** Using irregular block sizes or fragments smaller than the texture page size causes hardware overhead and complicates merging [S1].
*   **Precision:** Min-max arrays store min/max values. If the classification threshold is very close to a slice's min or max, precision issues might incorrectly classify a slice as empty or non-empty [G].

## Operating characteristics
*   **Time Complexity:** Preprocessing involves scanning the volume to generate min-max arrays ($O(l \cdot m \cdot n)$) and classifying blocks. Rendering time is reduced by 40% to 60% compared to conventional methods for large data [S1].
*   **Memory Complexity:** Texture memory usage is proportional to the number of object voxels, not the total volume size, due to trimming [S1].
*   **Performance:** Saves 40% to 60% of rendering time for large volume data [S1].
*   **Strengths:** Efficiently handles large datasets by excluding empty space; supports real-time classification threshold changes [S1].
*   **Limitations:** Requires preprocessing time; limited by texture cache size ($2^k$ pages) [S1].
*   **When to use:** Large volume data with significant empty space; hardware with limited texture memory [S1].
*   **When not to use:** Small volumes where preprocessing overhead outweighs benefits; volumes with no empty space (all black blocks) [S1].
