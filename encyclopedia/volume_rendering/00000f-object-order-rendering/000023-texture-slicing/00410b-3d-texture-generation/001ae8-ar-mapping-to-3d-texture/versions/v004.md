# AR mapping to 3D texture

Also called: Linear mapping to 3D texture, SIV linear texture mapping

## Overview
AR mapping to 3D texture is a technique for volume visualization that places color and opacity data into a 3D texture using a linear coordinate mapping to avoid non-linear formulae [S1, unofficial]. It solves the performance bottleneck of recalculating texture coordinates for every rotation of parallel polygons by defining coordinates once and rotating the geometry legally [S1, unofficial]. It sets itself apart from Wilson's depth integration by using a simpler estimation method that is likely less accurate but remains effective for visualization goals [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A set of parallel polygons representing the volume or isosurface.
- Output: A 3D texture containing color and opacity values, and a display list of rotated polygons.

**Data Structures:**
- **3D Texture:** Stores color (RGB) and opacity (A) values. The layout is determined by the linear mapping of texture coordinates to the polygon set.
- **Display List:** A group of OpenGL commands precomputed and cached for later execution [S1, unofficial].

**Steps:**
1. Define texture coordinates for the parallel polygons using a linear mapping. This mapping places color and opacity into the 3D texture [S1, unofficial].
2. Rotate the polygons legally. Because the texture coordinates are defined once and do not change with rotation, they do not need to be recalculated at each step [S1, unofficial].
3. Place the set of polygons into a display list. This allows the geometry to be redrawn efficiently without re-executing the command definitions [S1, unofficial].

**Formulas:**
- The mapping is linear. If $T$ is the texture coordinate and $P$ is the polygon position, the relationship is $T = f(P)$ where $f$ is a linear function. The specific coefficients are not given in the sources [S1, unofficial].

**Parameters:**
- Not given in the sources.

**Edge Cases and Pitfalls:**
- The estimation method used is likely worse than Wilson's depth integration [S1, unofficial].
- Visualizations remain effective despite the lower accuracy of the estimation method, especially considering the relative unimportance of this specific aspect in the overall goals of SIV (Volume Visualisation Via Variable-Detail Non-Photorealistic Illustration) [S1, unofficial].
- Linear alpha blending is used for compositing, which requires specific handling of transparency [S1, unofficial].

## Subtopics

### Uniform Grid
A variant where the 3D texture is backed by a uniform grid structure. It accepts a (X, Y, Z) float32 tensor to update scalar values [S2, unofficial]. The bounding box is defined by `aabb_min` (default [-1, -1, -1]) and `aabb_max` (default [1, 1, 1]) [S2, unofficial]. The initial scalar value for all points is `default_value` (default float max) [S2, unofficial]. It provides `get_points` which returns a (X, Y, Z, 3) float32 tensor of 3D coordinates, and `get_values` which returns a (X, Y, Z) float32 tensor of scalar values [S2, unofficial].

## Operating characteristics
- **Time Complexity:** Defining texture coordinates is $O(1)$ per polygon set. Rotating polygons is $O(N)$ where $N$ is the number of vertices. Display list execution is fast as commands are precomputed [S1, unofficial].
- **Memory Complexity:** Depends on the size of the 3D texture and the number of polygons.
- **Performance:** Recalculating texture coordinates at each rotation is slow. This method avoids that cost by defining coordinates once [S1, unofficial].
- **Strengths:** Avoids non-linear formulae. Improves performance by using display lists.
- **Limitations:** The estimation method is likely less accurate than Wilson's depth integration [S1, unofficial].
- **When to use:** When visualization effectiveness is prioritized over precise depth integration accuracy, and when frequent rotation of parallel polygons is required.
- **When not to use:** When high-precision depth integration is critical.

## Background
Originated in the context of Volume Visualisation Via Variable-Detail Non-Photorealistic Illustration (SIV) [S1, unofficial]. The method was developed to address the slowness of recalculating texture coordinates for rotated parallel polygons. It builds on the concept of using 3D textures for color and opacity storage [S1, unofficial].
