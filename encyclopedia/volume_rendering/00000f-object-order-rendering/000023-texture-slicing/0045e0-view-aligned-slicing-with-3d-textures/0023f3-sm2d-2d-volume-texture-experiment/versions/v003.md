# Sm2D (2D Volume Texture Experiment)
Also called: 2D Volume Texture Experiment

## Overview
Sm2D is a two-dimensional test application implemented as a 2D ray tracer to investigate the applicability of a texture-based approach for smoke volumes [S1, unofficial]. It simplifies the three-dimensional volume rendering problem into a one-dimensional viewport function where tetrahedra are represented by triangles [S1, unofficial]. It sets itself apart from its siblings by serving as a diagnostic tool to demonstrate the precision limits and rotational artifacts inherent in texture-based approximations compared to explicit geometric calculations [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of triangles $t_k$ representing the smoke volume, a camera-aligned two-dimensional grid $G$ (equivalent to a three-dimensional texture), and a set of viewing rays $r_j$ [S1, unofficial].
*   **Output:** An absorption coefficient $\alpha(r_j)$ for each ray $r_j$, visualized as a one-dimensional function across the viewport edge [S1, unofficial].

**Data Structures:**
*   **Grid $G$:** A two-dimensional array of cells $c_i$ [S1, unofficial]. In the reference implementation, $G$ is a $16 \times 16$ grid [S1, unofficial]. Each cell $c_i$ has a defined area $\text{area}(c_i)$ [S1, unofficial].
*   **Triangles:** A list of $N_t$ triangles $t_k$ [S1, unofficial]. Each triangle $t_k$ has a defined area $\text{area}(t_k)$ [S1, unofficial].
*   **Rays:** A list of $N_r$ rays $r_j$ entering the grid from below at equally spaced points along the viewport edge [S1, unofficial].

**Algorithm Steps:**
1.  **Calculate Triangle Density:** For each triangle $t_k$, compute its base density:
    $$ \sigma(t_k) = \sigma_k = \frac{1}{\text{area}(t_k)} $$
    where $\text{area}(t)$ returns the area of triangle $t$ [S1, unofficial].
2.  **Accumulate Cell Density:** For each cell $c_i$ in grid $G$, compute the accumulated density by summing contributions from all triangles:
    $$ \sigma(c_i) = \sum_{k=0}^{N_t-1} \frac{\text{overlap}(c_i, t_k)}{\text{area}(c_i)} \sigma(t_k) $$
    where $\text{overlap}(x_0, x_1)$ returns the common area (or length) of objects $x_0$ and $x_1$, and $\sigma(x_0)$ returns the density assigned to object $x_0$ [S1, unofficial].
3.  **Compute Ray Absorption:** For each ray $r_j$, sum the cell densities multiplied by the interval length (distance between entry and exit points of $r_j$ in $c_i$):
    $$ \alpha(r_j) = \sum_{i=0}^{N_c-1} \sigma(c_i) \cdot \text{overlap}(r_j, c_i) $$
    where $N_c$ is the number of grid cells [S1, unofficial].
4.  **Output:** Visualize $\alpha(r_j)$ for all $j$ as a graph across the viewport [S1, unofficial].

**Pseudocode:**
```python
def compute_sm2d(triangles, grid_rows, grid_cols, num_rays):
    # Grid covers unit square [0,1]x[0,1]
    cell_area = 1.0 / (grid_rows * grid_cols)
    sigma_grid = [[0.0] * grid_cols for _ in range(grid_rows)]

    # 1. Map triangles to grid
    for t in triangles:
        t_area = triangle_area(t)
        if t_area == 0:
            continue
        t_density = 1.0 / t_area
        for r in range(grid_rows):
            for c in range(grid_cols):
                x0, y0 = c / grid_cols, r / grid_cols
                x1, y1 = (c + 1) / grid_cols, (r + 1) / grid_cols
                overlap_area = triangle_rectangle_overlap(t, x0, y0, x1, y1)
                sigma_grid[r][c] += (overlap_area / cell_area) * t_density

    # 2. Ray tracing
    ray_xs = [i / num_rays for i in range(num_rays)]
    absorption_coeffs = []

    for x_ray in ray_xs:
        alpha = 0.0
        col_idx = int(x_ray * grid_cols)
        if col_idx >= grid_cols:
            col_idx = grid_cols - 1
        for r in range(grid_rows):
            y0 = r / grid_rows
            y1 = (r + 1) / grid_rows
            overlap_len = line_rectangle_overlap(x_ray, 0.0, x_ray, 1.0, col_idx/grid_cols, y0, (col_idx+1)/grid_cols, y1)
            alpha += sigma_grid[r][col_idx] * overlap_len
        absorption_coeffs.append(alpha)
    return absorption_coeffs

def triangle_area(t):
    # [G] Standard formula for triangle area given 3 vertices
    return 0.5 * abs(t.p1.x*(t.p2.y - t.p3.y) + t.p2.x*(t.p3.y - t.p1.y) + t.p3.x*(t.p1.y - t.p2.y))

def triangle_rectangle_overlap(t, x0, y0, x1, y1):
    # [G] Computes area of intersection between triangle t and axis-aligned rectangle [x0,x1]x[y0,y1]
    clip_rect = [(x0, y0), (x1, y0), (x1, y1), (x0, y1)]
    poly = [(t.p1.x, t.p1.y), (t.p2.x, t.p2.y), (t.p3.x, t.p3.y)]
    for edge in clip_rect:
        poly = clip_polygon(poly, edge)
        if not poly:
            return 0.0
    return polygon_area(poly)

def clip_polygon(poly, edge):
    # [G] Standard Sutherland-Hodgman clip step
    output = []
    if not poly:
        return output
    for i in range(len(poly)):
        curr = poly[i]
        prev = poly[i-1]
        if is_inside(curr, edge):
            if not is_inside(prev, edge):
                output.append(intersect(prev, curr, edge))
            output.append(curr)
        elif is_inside(prev, edge):
            output.append(intersect(prev, curr, edge))
    return output

def is_inside(p, edge):
    # [G] Checks if point p is inside the half-plane defined by edge
    return (edge[1][0] - edge[0][0]) * (p[1] - edge[0][1]) - (edge[1][1] - edge[0][1]) * (p[0] - edge[0][0]) >= 0

def intersect(p1, p2, edge):
    # [G] Computes intersection of line p1-p2 with edge line
    dx, dy = p2[0]-p1[0], p2[1]-p1[1]
    if edge[0][0] == edge[1][0]:
        t = (edge[0][0] - p1[0]) / dx
        return (edge[0][0], p1[1] + t*dy)
    else:
        t = (edge[0][1] - p1[1]) / dy
        return (p1[0] + t*dx, edge[0][1])

def polygon_area(poly):
    # [G] Shoelace formula
    return 0.5 * abs(sum(poly[i][0]*poly[i+1][1] - poly[i+1][0]*poly[i][1] for i in range(len(poly)-1)) + poly[-1][0]*poly[0][1] - poly[0][0]*poly[-1][1])

def line_rectangle_overlap(x, y0, x, y1, rx0, ry0, rx1, ry1):
    # [G] Computes length of intersection between vertical line segment and axis-aligned rectangle
    if x < rx0 or x > rx1:
        return 0.0
    clip_y0 = max(y0, ry0)
    clip_y1 = min(y1, ry1)
    return max(0.0, clip_y1 - clip_y0)
```

**Parameters:**
*   Grid Resolution: The example uses a $16 \times 16$ grid [S1, unofficial].
*   Number of Rays: The example uses 64 rays [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Degenerate Triangles:** Triangles with zero area cause division by zero in $\sigma(t_k) = 1/\text{area}(t_k)$ [S1, unofficial].
*   **Rotational Artifacts:** The texture-based approach produces unstable and faulty results during rotation, unlike explicit calculations which remain smooth [S1, unofficial].
*   **Spikes:** Unpleasant spikes across the viewport can occur, especially for degenerated triangles or unfavorable ray angles [S1, unofficial].
*   **Precision:** A texture-based approach will never get close to the precision of an explicit calculation without considerably increasing the number of grid cells [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources [S1, unofficial].

*   **Strengths:** Demonstrates precision limits and rotational artifacts of texture-based approximations [S1, unofficial].
*   **Limitations:** Low precision compared to explicit methods; suffers from spikes and rotational artifacts; requires high resolution for acceptable accuracy [S1, unofficial].
*   **When to use:** As a diagnostic tool to evaluate texture-based volume rendering suitability [S1, unofficial].
*   **When not to use:** When high precision or smooth rotational transitions are required [S1, unofficial].

## Background
Sm2D was introduced in a 2012 thesis by Dirk Sowinski as part of research on real-time smoke volume rendering [S1, unofficial]. It serves as a simplified two-dimensional test case to evaluate the applicability of texture-based approaches for smoke volumes, highlighting the trade-offs between hardware-accelerated texture sampling and explicit geometric ray tracing [S1, unofficial].
