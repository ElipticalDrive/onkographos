# 2D Volume Cross-Section Rendering

Also called: Cross-sectional Rendering, Reslicing, Single Plane Slicing, Single-Slice Rendering, Subsetting, Volume Slice Rendering, Volume Slicing

## Overview
2D Volume Cross-Section Rendering extracts a single two-dimensional slice from a three-dimensional volume dataset by intersecting it with an arbitrarily positioned plane [S1, unofficial][S4, unofficial]. It solves the problem of visualizing internal structures in specific anatomical or geometric orientations (coronal, sagittal, or oblique) without the computational overhead of full volume rendering [S3, unofficial][S4, unofficial]. Builds on [Texture slicing](25-texture-slicing.md), this method renders a single opaque plane, distinguishing it from siblings like [3-Pass Texture Mapping with Compositing](1354-3-pass-texture-mapping-with-compositing.md) which handles depth accumulation [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volume dataset (scalar field), a view matrix defining the slice plane orientation and position, and an output image size [S2, unofficial].
*   **Output:** A 2D image representing the cross-section of the volume [S2, unofficial].

**Data Structures:**
*   **Volume:** A 3D array of scalar values. Access is performed via `get_volume(volume, x, y, z)` which returns the scalar value at integer coordinates [S2, unofficial].
*   **View Matrix:** A 12-element array (or 3x4 matrix) representing the orientation of the slice plane. It contains:
    *   `u_vector`: The horizontal axis of the slice plane (indices 0-2).
    *   `v_vector`: The vertical axis of the slice plane (indices 4-6).
    *   `view_vector`: The normal vector to the slice plane (indices 8-10) [S2, unofficial].
*   **Image Buffer:** A 1D array of RGBA values (unsigned byte, 0-255) with size `image_size * image_size * 4` [S2, unofficial].

**Numbered Steps:**

1.  **Initialization:**
    *   Clear the output image buffer to zeros [S2, unofficial].
    *   Calculate the center of the image: `image_center = image_size / 2` [S2, unofficial].
    *   Calculate the center of the volume: `volume_center = [volume.dim_x / 2, volume.dim_y / 2, volume.dim_z / 2]` [S2, unofficial].
    *   Determine the maximum scalar value in the volume: `volume_maximum` [S2, unofficial].
    *   Set the loop step size: `step = 2` if interactive mode is enabled, else `1` [S2, unofficial].

2.  **Pixel Loop:**
    *   Iterate over image pixels `(i, j)` where `i` ranges from `0` to `image_size` with step `step`, and `j` ranges from `0` to `image_size` with step `step` [S2, unofficial].

3.  **Coordinate Calculation:**
    *   Compute the 3D voxel coordinates corresponding to the current pixel on the slice plane using the formula:
        $$ \text{voxel\_cords} = \mathbf{u\_vector} \cdot (i - \text{image\_center}) + \mathbf{v\_vector} \cdot (j - \text{image\_center}) + \text{volume\_center} $$
        Where $\mathbf{u\_vector}$ and $\mathbf{v\_vector}$ are the first two rows of the view matrix, and $\text{volume\_center}$ is the offset [S2, unofficial].

4.  **Sampling:**
    *   Sample the scalar value at the computed voxel coordinates:
        $$ \text{value} = \text{get\_voxel}(\text{volume}, \text{voxel\_cords}[0], \text{voxel\_cords}[1], \text{voxel\_cords}[2]) $$
        [S2, unofficial]

5.  **Classification and Coloring:**
    *   Normalize the value to the range $[0, 1]$:
        $$ \text{red} = \text{green} = \text{blue} = \frac{\text{value}}{\text{volume\_maximum}} $$
        [S2, unofficial]
    *   Determine alpha based on opacity threshold (all voxels considered completely opaque if value > 0):
        $$ \text{alpha} = \begin{cases} 1.0 & \text{if red} > 0 \\ 0.0 & \text{otherwise} \end{cases} $$
        [S2, unofficial]

6.  **Quantization:**
    *   Scale and clamp the RGBA components to 8-bit unsigned integers:
        $$ \text{component} = \lfloor \text{component} \times 255 \rfloor \quad \text{if } \text{component} < 1.0 \text{ else } 255 $$
        Apply this to red, green, blue, and alpha [S2, unofficial].

7.  **Writing:**
    *   Write the RGBA values to the image buffer at index `(j * image_size + i) * 4` [S2, unofficial].

**Pseudocode:**

```python
def render_cross_section(volume, view_matrix, image_size, interactive_mode):
    # 1. Initialization
    image = [0] * (image_size * image_size * 4)
    image_center = image_size / 2.0
    volume_center = [volume.dim_x / 2.0, volume.dim_y / 2.0, volume.dim_z / 2.0]
    volume_maximum = volume.get_maximum()
    step = 2 if interactive_mode else 1
    
    # Extract vectors from view matrix (12-element array)
    u_vector = view_matrix[0:3]
    v_vector = view_matrix[4:7]
    
    # 2. Pixel Loop
    for i in range(0, image_size, step):
        for j in range(0, image_size, step):
            # 3. Coordinate Calculation
            voxel_cords = [
                u_vector[0] * (i - image_center) + v_vector[0] * (j - image_center) + volume_center[0],
                u_vector[1] * (i - image_center) + v_vector[1] * (j - image_center) + volume_center[1],
                u_vector[2] * (i - image_center) + v_vector[2] * (j - image_center) + volume_center[2]
            ]
            
            # 4. Sampling
            value = get_voxel(volume, voxel_cords[0], voxel_cords[1], voxel_cords[2])
            
            # 5. Classification
            red = value / volume_maximum
            green = red
            blue = red
            alpha = 1.0 if red > 0 else 0.0
            
            # 6. Quantization
            red = int(red * 255) if red < 1.0 else 255
            green = int(green * 255) if green < 1.0 else 255
            blue = int(blue * 255) if blue < 1.0 else 255
            alpha = int(alpha * 255) if alpha < 1.0 else 255
            
            # 7. Writing
            idx = (j * image_size + i) * 4
            image[idx] = red
            image[idx + 1] = green
            image[idx + 2] = blue
            image[idx + 3] = alpha
            
    return image

def get_voxel(volume, x, y, z):
    # Clamp coordinates to volume bounds [G]
    x = max(0, min(x, volume.dim_x - 1))
    y = max(0, min(y, volume.dim_y - 1))
    z = max(0, min(z, volume.dim_z - 1))
    return volume.data[int(z)][int(y)][int(x)]
```

**Parameters:**
*   `view_matrix`: 12-element array defining the plane [S2, unofficial].
*   `interactive_mode`: Boolean flag determining sampling density [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Boundary Conditions:** The method assumes the slice plane intersects the volume. If the plane is outside the volume bounds, coordinates must be clamped to prevent out-of-bounds memory access [G].
*   **Orientation Dependence:** MPR is orientation dependent. When displaying structures like coronary arteries, incorrect plane orientation may introduce false-positive or false-negative stenoses [S5].
*   **Curved MPR:** If the slice follows a curved anatomic plane (e.g., along a vessel), the method becomes operator-dependent, limiting diagnostic accuracy despite automatic centerline algorithms [S5].

## Subtopics

### Multiplanar Reformation (MPR)
A broader category that includes orthogonal (coronal, sagittal, axial) and oblique slices [S5].

### Curved MPR
Extracts slices along a predefined curved path, useful for tubular structures like blood vessels [S5].

### 2D Pattern to 3D Volume Mapping
A method to create twenty cross-sectional images of a 3D object for printing on films, based on 3D position coordinates and bright information [S11]. For a point of the 3D object at $(O_x, O_y, O_z)$, if $Z_n < O_z < Z_{n+1}$, the point is printed at $(O_x, O_y)$ on the film placed at $z = Z_n$ [S11]. Object data is composed of 3D position coordinates and bright information (R, G, B) [S11]. Twenty films are placed at $z = Z_1, \dots, Z_{20}$ [S11]. Quantum yields are Red 0.43, Green 0.85, Blue 0.89 [S11]. Spacer thickness uses 0.5 mm acrylic plates between the twenty films [S11].

## Operating characteristics
*   **Time Complexity:** $O((N/\text{step})^2)$ where $N$ is the image resolution and $\text{step}$ is the sampling interval (typically 1 or 2) [S2, unofficial].
*   **Memory Complexity:** $O(N^2)$ for the output image buffer [S2, unofficial].
*   **Performance:** 4D MPR (3D + time) can be performed in real time using graphics hardware [S5].
*   **Strengths:** Ease of use, high speed, no information loss within the slice, interactive zooming and panning [S3, unofficial][S5].
*   **Limitations:** 2D display technique, orientation dependent, potential for diagnostic errors if plane is not aligned with pathology [S5].
*   **When to use:** Interactive exploration of internal structures, quick inspection of specific planes [S3, unofficial].
*   **When not to use:** When depth information or transparency is required, or when visualizing complex 3D relationships [S1, unofficial].

## Background
The technique originated as a method for stereotactic neurosurgery planning, where users interactively remove sections of data by slicing through it with an arbitrary cut-plane [S1, unofficial]. Early implementations included PIXAR's Cubetool and TAAC's VOXVU2 [S1, unofficial]. It is a form of indirect rendering, distinct from direct volume rendering (DVR) and surface rendering (SR) [S5].
