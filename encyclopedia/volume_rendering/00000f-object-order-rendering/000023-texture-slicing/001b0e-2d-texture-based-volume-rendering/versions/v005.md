# 2D Texture-Based Volume Rendering

Also called: 2D Texture Mapping, 2D Texture Volume Rendering, 2DTM, NodeVolumeTextureRender, VR Basado en Texturas 2D

## Overview
2D Texture-Based Volume Rendering is an object-space technique that renders volumetric data by decomposing it into a set of parallel, object-aligned 2D slices stored in texture maps, which are then projected onto the image plane and composited back-to-front [S1, unofficial][S2, unofficial][S3, unofficial]. It solves the problem of real-time volume visualization on hardware lacking native 3D texture support by substituting trilinear interpolation with hardware-accelerated bilinear interpolation [S3, unofficial][S6, unofficial]. Unlike [3-Pass Texture Mapping with Compositing](1354-3-pass-texture-mapping-with-compositing.md) which may use view-aligned geometry, this method relies on fixed axis-aligned stacks, trading image quality for broad compatibility and speed [S6, unofficial][S12].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar volume dataset $V$ of dimensions $D_x \times D_y \times D_z$. A viewing direction vector $\vec{v}$ derived from the modelview matrix. A transfer function $T(v)$ mapping scalar values to RGBA.
*   **Output:** A 2D image buffer $I$ of size $H \times W \times 3$ (RGB).

**Data Structures:**
The volume is pre-processed into three stacks of 2D textures, one for each major axis (X, Y, Z).
*   **Texture Stack:** A list of 2D textures. For the X-axis stack, there are $D_x$ textures, each of size $D_y \times D_z$.
*   **Texel Format:** RGBA.
    *   **RGB:** Emission coefficient $I_{emit}$ (color).
    *   **A:** Inverse absorption coefficient $(1 - \vartheta_k)$, where $\vartheta_k$ is the absorption at sample point $k$ [S3, unofficial].
*   **Proxy Geometry:** For each slice, a polygon (typically a triangle fan or quad) representing the intersection of the slicing plane with the volume bounding box. Vertices are ordered back-to-front relative to the camera [S5, unofficial].

**Steps:**

1.  **Preprocessing (Offline/Initialization):**
    For each axis $A \in \{X, Y, Z\}$:
    *   Extract 2D slices perpendicular to $A$.
    *   Apply the transfer function $T$ to each voxel value $v$ to compute color $C$ and opacity $\alpha$.
    *   Store $C$ in RGB and $\alpha$ in the Alpha channel of the corresponding 2D texture.
    *   Generate proxy geometry for each slice by clipping the volume bounding box against the slice plane [S5, unofficial].

2.  **View Direction Selection:**
    *   Extract the rotation matrix $R$ from the current ModelView matrix [S3, unofficial].
    *   Transform the initial viewing direction $\vec{v}_{init} = (0, 0, -1)$: $\vec{v}_{world} = R \cdot \vec{v}_{init}$.
    *   Find the component with the maximum absolute value: $n_{max} = \text{argmax}_i |v_{world}[i]|$.
    *   Select the texture stack corresponding to axis $n_{max}$. If $v_{world}[n_{max}] > 0$, render in increasing order; otherwise, decreasing order [S3, unofficial].
    *   *Constraint:* The chosen stack's normal must be within $\pm 45^\circ$ of the viewing direction to avoid edge-on artifacts [S6, unofficial][S8].

3.  **Rendering Loop (Back-to-Front):**
    For each slice $k$ in the selected stack, from farthest to nearest:
    *   **Geometry:** Bind the proxy polygon for slice $k$.
    *   **Texturing:** Bind the 2D texture for slice $k$. The rasterizer performs bilinear interpolation on the texture coordinates [S3, unofficial].
    *   **Compositing:** Blend the fragment color into the frame buffer using alpha blending.
        The radiative transfer equation is discretized as:
        $$ I(s_k) = I(s_{k-1}) \cdot \vartheta_k + I_{emit}(s_k) \cdot (1 - \vartheta_k) $$
        where $I_{emit}(s_k)$ is the color from the texture RGB, and $(1 - \vartheta_k)$ is the texture Alpha [S3, unofficial].
        The hardware blending equation (e.g., `glBlendFunc(GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA)`) implements:
        $$ C_{dest} = C_{src} \cdot A_{src} + C_{dest} \cdot (1 - A_{src}) $$
        Substituting $C_{src} = I_{emit}$ and $A_{src} = (1 - \vartheta_k)$ yields the correct integration [S3, unofficial].

**Pseudocode:**

```python
def render_2d_texture_volume(volume_data, modelview_matrix, image_buffer):
    # 1. Preprocessing: Create 3 stacks of 2D textures
    # Each stack contains 2D textures where RGB=Color, A=Opacity
    stacks = {}
    for axis in ['X', 'Y', 'Z']:
        stacks[axis] = []
        for i in range(volume_data.shape[axis]):
            slice_data = extract_slice(volume_data, axis, i)
            rgba_slice = apply_transfer_function(slice_data)
            stacks[axis].append(create_2d_texture(rgba_slice))

    # 2. Select Stack based on View Direction
    # Extract rotation from ModelView matrix
    R = extract_rotation(modelview_matrix)
    view_dir = R @ np.array([0.0, 0.0, -1.0])
    
    # Find axis with max absolute component
    abs_view = np.abs(view_dir)
    max_axis_idx = np.argmax(abs_view)
    axes = ['X', 'Y', 'Z']
    selected_axis = axes[max_axis_idx]
    
    # Determine direction (increasing or decreasing)
    if view_dir[max_axis_idx] > 0:
        direction = 'increasing'
    else:
        direction = 'decreasing'
        
    selected_stack = stacks[selected_axis]
    if direction == 'decreasing':
        selected_stack = reversed(selected_stack)

    # 3. Render Slices Back-to-Front
    # Initialize image buffer to black
    image_buffer[:] = 0.0
    
    for slice_texture in selected_stack:
        # Generate proxy geometry for this slice
        # Geometry is a polygon clipped to the volume bounding box
        poly = generate_slice_polygon(slice_texture.index, selected_axis)
        
        # Bind texture and geometry
        bind_texture(slice_texture)
        bind_geometry(poly)
        
        # Rasterize and Blend
        # Hardware performs:
        # C_dest = C_src * A_src + C_dest * (1 - A_src)
        # where C_src is RGB from texture, A_src is Alpha from texture
        rasterize_and_blend()

    return image_buffer
```

**Edge Cases and Pitfalls:**
*   **Banding/Artifacts:** Bilinear interpolation ignores the third dimension, causing "staircase" or banding artifacts, especially when zooming [S2, unofficial][S18, unofficial].
*   **Stack Switching:** Abrupt switching between X, Y, and Z stacks causes visible popping artifacts due to different sampling positions [S3, unofficial][S18, unofficial].
*   **Edge-on Slices:** If the view angle is close to $45^\circ$ from the slice normal, slices become edge-on, leading to aliasing and incorrect sampling [S6, unofficial][S12].
*   **Opacity Scaling:** The distance between sampling points along the viewing ray varies with angle. Opacity values may need scaling to maintain consistent density perception [S17].
*   **VTK OIT Conflict:** In VTK 9+, Order-Independent Translucency (OIT) breaks this method by averaging colors. `UseOITOff()` must be enabled [S5, unofficial].
*   **Negative Values:** Logarithmic transfer functions (if used) fail on zero/negative values [S9, unofficial][S10, unofficial].

## Subtopics

### [Novel Sampling Scheme for Slice Based Volume Rendering](953-novel-sampling-scheme-for-slice-based-volume-rendering.md)
A variant that renders multiple object-aligned 2D texture stacks simultaneously, clipped by planes extending from the front-facing edges of the volume's bounding box. It eliminates stack-switching and jagged boundary artifacts by approximating uniform ray-casting sampling more closely than spherical shells, while avoiding their geometry overhead.

### [Interpolation of Arbitrary Slices (Multi-Texture Blending)](2089-interpolation-of-arbitrary-slices-multi-texture-blending.md)
Renders arbitrary (non-axis-aligned) slices by interpolating between two adjacent object-aligned 2D textures using multi-texturing hardware. It decomposes the arbitrary slice into polygon strips spanning only two textures, reducing polygon count by half compared to single-texture approaches, but is limited by memory bandwidth.

### [Multi-Texture Interpolation](2200-multi-texture-interpolation.md)
Eliminates fixed-slice banding artifacts by computing intermediate slices on the fly using GPU combiners to perform real trilinear interpolation. Unlike the Novel Sampling Scheme, it retains standard slice projection but enhances the interpolation step between adjacent slices.

### [Slice-Based Volume Rendering with HSV Transfer Function](4329-slice-based-volume-rendering-with-hsv-transfer-function.md)
Uses an HSV (Hue, Saturation, Value) transfer function mapped via parametric equations rather than a lookup table. It simulates 3D texture access via a 2D texture array (sprite sheet) for slice indexing, allowing intuitive color control and real-time performance on fixed-function hardware.

### SGI Octane2 Volume Rendering Pipeline
A specific hardware pipeline for SGI Octane2 with V-series cards that uses 3D pixel textures via `glDrawPixels` or `glCopyPixels` [S20]. It renders slices, pixel-textures them with a quantized normal volume for shading, and blends them. It requires a scratch/auxiliary buffer because pixel texture does not occur directly per-fragment during rasterization [S20].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot H \cdot W)$, where $N$ is the number of slices and $H \times W$ is the image resolution. Performance depends on image size, not scene complexity [S6, unofficial].
*   **Memory Complexity:** $O(D_x D_y D_z)$ for storing three full texture stacks. This is a significant limitation; for a $181 \times 217 \times 181$ volume, memory usage can exceed 37 MB for main memory creation of textures alone [S3, unofficial][S18, unofficial].
*   **Performance:** Historically much faster than ray casting on older hardware, achieving near-interactive rates (e.g., 1.6 fps on a Pentium-IV with QuadroFX 3400) [S1, unofficial][S7, unofficial]. Modern GPUs have closed the gap with ray casting, but 2D texture mapping remains efficient for simple interactivity [S7, unofficial].
*   **Strengths:** Compatible with older hardware lacking 3D texture support; leverages standard bilinear interpolation hardware; simple implementation [S6, unofficial][S12].
*   **Limitations:** Lower image quality than ray casting or 3D texture methods due to bilinear interpolation artifacts; high memory consumption for three stacks; visible artifacts during rotation (stack switching, edge-on sampling) [S3, unofficial][S6, unofficial][S7, unofficial].
*   **When to Use:** Legacy hardware, simple interactive previews, or when 3D texture support is unavailable.
*   **When Not to Use:** High-quality offline rendering, volumes requiring precise trilinear interpolation, or scenes with frequent large rotations where stack-switching artifacts are unacceptable.

## Background
The method was introduced by Cabral et al. [Cabral94] as one of the first to use texture mapping capabilities for volume rendering [S1, unofficial]. It was further developed by Lacroute and Levoy [7], who proposed using object-aligned slices to substitute trilinear with bilinear interpolation, though their original implementation did not use texturing hardware [S17]. Engel et al. [Engel01] provided an excellent introduction and improved quality with pre-integrated volume rendering [S1, unofficial][S2, unofficial]. The technique was used by companies such as Silicon Graphics in their InfiniteReality system and is supported by many modern graphics hardware devices [S7, unofficial].
