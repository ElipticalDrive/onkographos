# Novel Sampling Scheme for Slice Based Volume Rendering
Also called: Novel method, Our novel method

## Overview
A volume rendering technique that generates proxy geometry using multiple object-aligned 2D texture stacks clipped by planes extending from the front-facing edges of the volume's bounding box in the viewing direction, eliminating stack-switching artifacts and jagged boundary artifacts [S1, unofficial]. Unlike traditional 2D texture-based volume rendering which selects a single stack causing visible color/opacity shifts during rotation, this method renders multiple clipped stacks simultaneously [S1, unofficial]. It approximates the uniform sampling pattern of ray casting more closely than spherical shell approaches while avoiding their large geometry overhead [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Volumetric data stored in three 2D texture stacks (X, Y, Z aligned) [S1, unofficial]. Viewing direction vector $\mathbf{v}$ [S1, unofficial].
*   **Output:** Composite image via back-to-front or front-to-back blending of clipped proxy geometry [S1, unofficial].

**Data Structures:**
*   **Volume Representation:** Three separate 2D texture arrays. Each array represents slices of the volume along one principal axis (X, Y, or Z) [S1, unofficial].
*   **Proxy Geometry:** A set of quadrilateral primitives representing the visible portions of the three stacks. These are generated by clipping the full stacks against specific planes [S1, unofficial].

**Steps:**
1.  **Identify Front-Facing Edges:** Determine the edges of the volume's bounding box that are front-facing relative to the current viewing direction $\mathbf{v}$ [S1, unofficial].
2.  **Generate Clip Planes:** Extend the identified front-facing edges into infinite planes that point in the viewing direction $\mathbf{v}$ [S1, unofficial]. These planes serve to separate the stacks and define the visible region for each stack relative to the viewer [S1, unofficial].
3.  **Clip Stacks:** Clip the three object-aligned stacks (X, Y, Z) adjacent to these edges using the generated planes [S1, unofficial]. The clipping removes geometry that would otherwise cause overlap or incorrect sampling [S1, unofficial].
4.  **Scale Slice Distance:** To approximate uniform sampling along the view ray, scale the distance between slices in each stack. The slice distance $d$ is scaled by the secant of the angle $\theta$ between the viewing direction and the stack normal $\mathbf{n}$ [S1, unofficial].
    *   Formula: $d_{scaled} = d \cdot \sec(\theta)$ [S1, unofficial].
    *   Approximation: Since $\theta$ varies across a slice, the scaling factor is approximated by the secant of the angle between the stack normal and the ray to the slice center [S1, unofficial].
5.  **Render:** Draw the remaining geometry of the three stacks. The stacks do not overlap in depth after clipping, so they can be drawn in any order (front-to-back or back-to-front) [S1, unofficial]. This allows optimization for out-of-core data by drawing resident cache data first [S1, unofficial].
6.  **Texture Sampling:** Because the adjusted spacing may not align with the original discrete texture slices, the shader must interpolate between two 2D textures if hardware supports it, or repeat the same texture for multiple slices on older hardware [S1, unofficial].

def render_novel_sampling(volume_stacks, view_direction, ray_origin, ray_direction, bounding_box, num_slices):
    """
    volume_stacks: dict with keys 'X', 'Y', 'Z', each containing 3D voxel arrays
    view_direction: normalized 3D vector v
    ray_origin, ray_direction: camera ray for current pixel
    bounding_box: (min_x, min_y, min_z, max_x, max_y, max_z)
    num_slices: number of slices per stack
    """
    # 1. Ray-box intersection to find entry and exit distances
    t_min, t_max = ray_box_intersection(ray_origin, ray_direction, bounding_box)
    if t_max < 0 or t_min > t_max:
        return 0.0, 0.0, 0.0, 0.0  # Ray misses volume

    # 2. Compute secant scaling factors for each stack axis
    stack_normals = {'X': (1.0, 0.0, 0.0), 'Y': (0.0, 1.0, 0.0), 'Z': (0.0, 0.0, 1.0)}
    secants = {}
    for axis, normal in stack_normals.items():
        cos_theta = dot(ray_direction, normal)
        # Avoid division by zero if ray is parallel to stack plane
        if abs(cos_theta) < 1e-6:
            secants[axis] = 1.0
        else:
            secants[axis] = 1.0 / abs(cos_theta)

    # 3. Initialize blending accumulators
    r, g, b, a = 0.0, 0.0, 0.0, 0.0
    alpha_threshold = 0.99

    # 4. March along ray and sample each stack with secant-corrected step size
    for axis in ['X', 'Y', 'Z']:
        secant = secants[axis]
        step_size = (t_max - t_min) / num_slices * secant
        t = t_min
        while t < t_max and a < alpha_threshold:
            sample_pos = ray_origin + t * ray_direction
            # Check bounds
            if not is_inside_box(sample_pos, bounding_box):
                t += step_size
                continue
            # Sample texture (standard trilinear interpolation [G])
            color = sample_stack(volume_stacks[axis], sample_pos)
            alpha = color[3]
            # Front-to-back blending
            r = r + color[0] * alpha * (1.0 - a)
            g = g + color[1] * alpha * (1.0 - a)
            b = b + color[2] * alpha * (1.0 - a)
            a = a + alpha * (1.0 - a)
            t += step_size

    return r, g, b, a

def ray_box_intersection(origin, direction, box):
    inv_dir = (1.0 / direction[0], 1.0 / direction[1], 1.0 / direction[2])
    t1 = (box[0] - origin[0]) * inv_dir[0]
    t2 = (box[3] - origin[0]) * inv_dir[0]
    t3 = (box[1] - origin[1]) * inv_dir[1]
    t4 = (box[4] - origin[1]) * inv_dir[1]
    t5 = (box[2] - origin[2]) * inv_dir[2]
    t6 = (box[5] - origin[2]) * inv_dir[2]
    t_min = max(max(min(t1, t2), min(t3, t4)), min(t5, t6))
    t_max = min(min(max(t1, t2), max(t3, t4)), max(t5, t6))
    return t_min, t_max

def is_inside_box(pos, box):
    return box[0] <= pos[0] <= box[3] and box[1] <= pos[1] <= box[4] and box[2] <= pos[2] <= box[5]

**Parameters:**
*   **Secant Scaling Factor:** Approximated by $\sec(\theta)$ where $\theta$ is the angle between the stack normal and the ray to the slice center [S1, unofficial].
*   **Stack Selection:** All three stacks are used, not just the most perpendicular one [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Stack Switching Artifacts:** Traditional methods switch between stacks, causing color/opacity jumps. This method eliminates this by using all stacks simultaneously [S1, unofficial].
*   **Jagged Boundary Artifacts:** View-aligned slicing suffers from jagged edges. This method avoids them by using object-aligned slices clipped by planes [S1, unofficial].
*   **Performance Overhead:** On ultra-mobile hardware (iPod touch 3rd gen, iPhone 3Gs, Intel GMA), performance drops by ~20% compared to single-stack object-aligned rendering due to additional slices drawn from secant correction [S1, unofficial].
*   **Geometry Generation Bottleneck:** Clipping actual stacks on the GPU sends large amounts of unused geometry. Clipping on the CPU becomes a bottleneck [S1, unofficial].

## Subtopics

### Fast Geometry Generation Optimization
An optimization for generating proxy geometry by clipping the bounding box before stack generation and marching along it with secant-corrected step size, performed on the CPU to avoid GPU overhead [S1, unofficial].
*   **Definition:** Instead of generating full stacks and clipping them, the bounding box is clipped first. The stacks are then generated by marching along the clipped bounding box [S1, unofficial].
*   **Steps:**
    1.  Clip the bounding box using the view-direction planes [S1, unofficial].
    2.  March along the clipped bounding box with the secant-corrected step size to generate quadrilateral geometry [S1, unofficial].
*   **Pitfalls:** GPU-based clipping of all three stacks results in significant overhead due to sending large amounts of geometry that are never rendered [S1, unofficial]. CPU-based clipping of the actual stacks becomes a bottleneck [S1, unofficial].
*   **Comparison:** Clipping the bounding box instead of the stacks ensures generated geometry remains quadrilateral because clip planes only clip away parts perpendicular to the stack generation direction [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Not explicitly given, but performance is affected by the number of slices drawn. Secant correction increases the number of slices, leading to a ~20% performance drop on ultra-mobile hardware compared to single-stack methods [S1, unofficial].
*   **Memory Complexity:** Requires storing three 2D texture stacks [S1, unofficial]. No 3D texture memory required, making it suitable for devices lacking 3D texture support [S1, unofficial].
*   **Measured Performance:**
    *   **Ultra-mobile hardware (iPod touch 3rd gen, iPhone 3Gs, Intel GMA):** ~20% slower than object-aligned implementation [S1, unofficial].
    *   **NVIDIA Quadro 5800 (core data):** ~30% faster than view-aligned slicing [S1, unofficial].
    *   **ATI/AMD Radeon 5970 (out-of-core):** ~25% faster than view-aligned slicing [S1, unofficial].
*   **Strengths:** Eliminates stack-switching artifacts; eliminates jagged boundary artifacts; better performance than view-aligned slicing on high-end GPUs; suitable for hardware without 3D texture support [S1, unofficial].
*   **Limitations:** ~20% performance penalty on low-end hardware compared to single-stack methods; geometry generation can be a bottleneck if not optimized [S1, unofficial].
*   **When to Use:** Devices lacking 3D texture support; scenarios requiring high-quality rendering without stack-switching artifacts; high-end GPUs where view-aligned slicing is too slow or artifact-prone [S1, unofficial].

## Background
Originated from the work of Rezk-Salama et al. [RSEB∗00], who extended Cullip and Neumann's [CN94] and Lacroute et al.'s [LL94] ideas to develop 2D object-aligned stack techniques for hardware incapable of 3D texturing [S1, unofficial]. The novel method was presented as an extension to overcome the stack-switching artifacts of these earlier approaches [S1, unofficial]. It was introduced in the paper "A New Sampling Scheme for Slice Based Volume Rendering" [S1, unofficial].
