# Novel Sampling Scheme for Slice Based Volume Rendering
Also called: Novel method, Our novel method

## Overview
A volume rendering technique that generates proxy geometry using multiple object-aligned 2D texture stacks clipped by planes extending from the front-facing edges of the volume's bounding box in the viewing direction, eliminating stack-switching artifacts and jagged boundary artifacts [S1]. Unlike traditional 2D texture-based volume rendering which selects a single stack causing visible color/opacity shifts during rotation, this method renders multiple clipped stacks simultaneously [S1]. It approximates the uniform sampling pattern of ray casting more closely than spherical shell approaches while avoiding their large geometry overhead [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** Volumetric data stored in three 2D texture stacks (X, Y, Z aligned) [S1]. Viewing direction vector $\mathbf{v}$ [S1].
*   **Output:** Composite image via back-to-front or front-to-back blending of clipped proxy geometry [S1].

**Data Structures:**
*   **Volume Representation:** Three separate 2D texture arrays. Each array represents slices of the volume along one principal axis (X, Y, or Z) [S1].
*   **Proxy Geometry:** A set of quadrilateral primitives representing the visible portions of the three stacks. These are generated by clipping the full stacks against specific planes [S1].

**Steps:**
1.  **Identify Front-Facing Edges:** Determine the edges of the volume's bounding box that are front-facing relative to the current viewing direction $\mathbf{v}$ [S1].
2.  **Generate Clip Planes:** Extend the identified front-facing edges into infinite planes that point in the viewing direction $\mathbf{v}$ [S1]. These planes serve to separate the stacks and define the visible region for each stack relative to the viewer [S1].
3.  **Clip Stacks:** Clip the three object-aligned stacks (X, Y, Z) adjacent to these edges using the generated planes [S1]. The clipping removes geometry that would otherwise cause overlap or incorrect sampling [S1].
4.  **Scale Slice Distance:** To approximate uniform sampling along the view ray, scale the distance between slices in each stack. The slice distance $d$ is scaled by the secant of the angle $\theta$ between the viewing direction and the stack normal $\mathbf{n}$ [S1].
    *   Formula: $d_{scaled} = d \cdot \sec(\theta)$ [S1].
    *   Approximation: Since $\theta$ varies across a slice, the scaling factor is approximated by the secant of the angle between the stack normal and the ray to the slice center [S1].
5.  **Render:** Draw the remaining geometry of the three stacks. The stacks do not overlap in depth after clipping, so they can be drawn in any order (front-to-back or back-to-front) [S1]. This allows optimization for out-of-core data by drawing resident cache data first [S1].
6.  **Texture Sampling:** Because the adjusted spacing may not align with the original discrete texture slices, the shader must interpolate between two 2D textures if hardware supports it, or repeat the same texture for multiple slices on older hardware [S1].

**Pseudocode:**
```python
def render_novel_sampling(volume_stacks, view_direction, bounding_box):
    """
    volume_stacks: dict with keys 'X', 'Y', 'Z', each containing 2D texture data
    view_direction: normalized 3D vector v
    bounding_box: min_corner, max_corner of the volume
    """
    
    # 1. Identify front-facing edges of the bounding box
    # Determine which faces of the bounding box are front-facing relative to v
    front_facing_edges = get_front_facing_edges(bounding_box, view_direction)
    
    # 2. Generate clip planes from these edges
    # Each edge defines a plane extending in the view direction
    clip_planes = []
    for edge in front_facing_edges:
        # Plane normal is perpendicular to the edge and the view direction
        # Or simply define plane passing through edge with normal derived from view
        plane = create_plane_from_edge_and_view(edge, view_direction)
        clip_planes.append(plane)
        
    # 3. Clip the three stacks
    # We only need to clip the stacks adjacent to the front-facing edges
    # However, the method implies clipping the relevant stacks to remove overlaps
    clipped_geometries = {}
    
    for axis in ['X', 'Y', 'Z']:
        stack = volume_stacks[axis]
        normal = get_stack_normal(axis)
        
        # Determine if this stack needs clipping based on adjacency to front edges
        # In practice, all three stacks are rendered but clipped to avoid overlap
        # The clipping planes are defined globally or per-stack based on geometry
        clipped_quads = clip_stack_against_planes(stack, clip_planes)
        
        # 4. Scale slice distance
        # Calculate angle between view direction and stack normal
        angle = acos(dot(normal, view_direction))
        secant = 1.0 / cos(angle)
        
        # Apply scaling to the slice positions/spacing
        # Note: This affects the texture coordinate mapping or the number of slices rendered
        scaled_geometries = apply_slice_scaling(clipped_quads, secant)
        
        clipped_geometries[axis] = scaled_geometries
        
    # 5. Render
    # Draw all clipped geometries. Order does not matter for depth as they don't overlap
    for axis in ['X', 'Y', 'Z']:
        render_geometry(clipped_geometries[axis], volume_stacks[axis])
```

**Parameters:**
*   **Secant Scaling Factor:** Approximated by $\sec(\theta)$ where $\theta$ is the angle between the stack normal and the ray to the slice center [S1].
*   **Stack Selection:** All three stacks are used, not just the most perpendicular one [S1].

**Edge Cases and Pitfalls:**
*   **Stack Switching Artifacts:** Traditional methods switch between stacks, causing color/opacity jumps. This method eliminates this by using all stacks simultaneously [S1].
*   **Jagged Boundary Artifacts:** View-aligned slicing suffers from jagged edges. This method avoids them by using object-aligned slices clipped by planes [S1].
*   **Performance Overhead:** On ultra-mobile hardware (iPod touch 3rd gen, iPhone 3Gs, Intel GMA), performance drops by ~20% compared to single-stack object-aligned rendering due to additional slices drawn from secant correction [S1].
*   **Geometry Generation Bottleneck:** Clipping actual stacks on the GPU sends large amounts of unused geometry. Clipping on the CPU becomes a bottleneck [S1].

## Subtopics

### Fast Geometry Generation Optimization
An optimization for generating proxy geometry by clipping the bounding box before stack generation and marching along it with secant-corrected step size, performed on the CPU to avoid GPU overhead [S1].
*   **Definition:** Instead of generating full stacks and clipping them, the bounding box is clipped first. The stacks are then generated by marching along the clipped bounding box [S1].
*   **Steps:**
    1.  Clip the bounding box using the view-direction planes [S1].
    2.  March along the clipped bounding box with the secant-corrected step size to generate quadrilateral geometry [S1].
*   **Pitfalls:** GPU-based clipping of all three stacks results in significant overhead due to sending large amounts of geometry that are never rendered [S1]. CPU-based clipping of the actual stacks becomes a bottleneck [S1].
*   **Comparison:** Clipping the bounding box instead of the stacks ensures generated geometry remains quadrilateral because clip planes only clip away parts perpendicular to the stack generation direction [S1].

## Operating characteristics
*   **Time Complexity:** Not explicitly given, but performance is affected by the number of slices drawn. Secant correction increases the number of slices, leading to a ~20% performance drop on ultra-mobile hardware compared to single-stack methods [S1].
*   **Memory Complexity:** Requires storing three 2D texture stacks [S1]. No 3D texture memory required, making it suitable for devices lacking 3D texture support [S1].
*   **Measured Performance:**
    *   **Ultra-mobile hardware (iPod touch 3rd gen, iPhone 3Gs, Intel GMA):** ~20% slower than object-aligned implementation [S1].
    *   **NVIDIA Quadro 5800 (core data):** ~30% faster than view-aligned slicing [S1].
    *   **ATI/AMD Radeon 5970 (out-of-core):** ~25% faster than view-aligned slicing [S1].
*   **Strengths:** Eliminates stack-switching artifacts; eliminates jagged boundary artifacts; better performance than view-aligned slicing on high-end GPUs; suitable for hardware without 3D texture support [S1].
*   **Limitations:** ~20% performance penalty on low-end hardware compared to single-stack methods; geometry generation can be a bottleneck if not optimized [S1].
*   **When to Use:** Devices lacking 3D texture support; scenarios requiring high-quality rendering without stack-switching artifacts; high-end GPUs where view-aligned slicing is too slow or artifact-prone [S1].
*   **When Not to Use:** Ultra-mobile hardware where the 20% performance drop is unacceptable and single-stack quality is sufficient [S1].

## Background
Originated from the work of Rezk-Salama et al. [RSEB∗00], who extended Cullip and Neumann's [CN94] and Lacroute et al.'s [LL94] ideas to develop 2D object-aligned stack techniques for hardware incapable of 3D texturing [S1]. The novel method was presented as an extension to overcome the stack-switching artifacts of these earlier approaches [S1]. It was introduced in the paper "A New Sampling Scheme for Slice Based Volume Rendering" [S1].
