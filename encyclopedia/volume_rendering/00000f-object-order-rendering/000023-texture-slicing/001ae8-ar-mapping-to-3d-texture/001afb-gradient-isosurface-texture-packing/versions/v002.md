# Gradient-Isosurface Texture Packing


## Overview
Gradient-Isosurface Texture Packing is a data layout strategy that stores pre-computed gradient vectors in the RGB components of a 3D volume texture and the original scalar isovalue in the Alpha component [S1, unofficial]. This single-texture approach provides both transfer function indexing data and surface normals for shading, eliminating the need for a second texture copy or expensive runtime gradient calculation [S1, unofficial]. It differs from [AR mapping to 3D texture](884-ar-mapping-to-3d-texture.md) by embedding shading normals directly into the volume representation, and from [Röttger et al. Rendering](938-r-ttger-et-al-rendering.md) by relying on hardware interpolation of pre-computed gradients rather than software-based ray casting optimizations [S2].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volume dataset of scalar values (density/isovalue) [S1, unofficial][S2].
*   **Output:** A 3D volume texture where each voxel contains a 4-component vector [S1, unofficial][S2].

**Data Structures:**
The texture stores a 4-component vector per voxel [S1, unofficial].
*   **R, G, B:** The three components of the pre-computed gradient vector (normal) [S1, unofficial][S2].
*   **A:** The original scalar isovalue or density at that voxel position [S1, unofficial][S2].

**Steps:**
1.  **Pre-compute Gradients:** Calculate the gradient vector for each voxel in the source volume data using central differences or high-quality Sobel filters computed serially offline [S1, unofficial][S2].
2.  **Pack Data:** Transform the calculated gradient vectors and original scalar values into a 4-component array where the X, Y, and Z gradient components map to the RGB channels, and the original isovalue maps to the Alpha channel [S1, unofficial].
3.  **Upload:** Transfer the packed data to the 3D volume texture on the GPU [S1, unofficial][S2].
4.  **Sampling:** During rendering, sample the 3D texture so the hardware interpolates both the density (Alpha) and the gradient (RGB) simultaneously [S2].
5.  **Shading:** Use the interpolated gradient to compute lighting (e.g., Phong shading) and use the interpolated density to index the transfer function [S1, unofficial].

**Pseudocode:**
```python
import math

class Vector4:
    def __init__(self, x, y, z, w):
        self.x, self.y, self.z, self.w = x, y, z, w

def compute_gradient(volume, x, y, z, width, height, depth):
    """Central differences scheme for gradient estimation [S1, unofficial]."""
    gx = (volume[x + 1, y, z] - volume[x - 1, y, z]) / 2.0
    gy = (volume[x, y + 1, z] - volume[x, y - 1, z]) / 2.0
    gz = (volume[x, y, z + 1] - volume[x, y, z - 1]) / 2.0
    # Clamp to valid range to handle boundaries [G]
    gx = max(-1.0, min(1.0, gx))
    gy = max(-1.0, min(1.0, gy))
    gz = max(-1.0, min(1.0, gz))
    return gx, gy, gz

def apply_phong_shading(gradient, light_dir, view_dir):
    """Standard Phong shading calculation [G]."""
    norm = math.sqrt(gradient.x**2 + gradient.y**2 + gradient.z**2)
    if norm == 0.0:
        return 0.0
    nx, ny, nz = gradient.x / norm, gradient.y / norm, gradient.z / norm
    diffuse = max(0.0, nx * light_dir.x + ny * light_dir.y + nz * light_dir.z)
    return diffuse

def sample_3d_texture(texture, pos):
    """Simulates hardware 3D texture sampling with interpolation [S2]."""
    return texture[pos]

def pack_volume_data(volume_data, width, height, depth):
    """Pre-computes gradients and packs them into a 3D texture format [S1, unofficial]."""
    packed_data = {}
    for z in range(depth):
        for y in range(height):
            for x in range(width):
                gx, gy, gz = compute_gradient(volume_data, x, y, z, width, height, depth)
                packed_data[(z, y, x)] = Vector4(gx, gy, gz, volume_data[x, y, z])
    return packed_data

def render_sample(pos, packed_texture, light_dir, view_dir):
    """Samples the packed 3D texture and computes shading [S1, unofficial][S2]."""
    texel = sample_3d_texture(packed_texture, pos)
    gradient = Vector4(texel.x, texel.y, texel.z, 0.0)
    density = texel.w
    # Normalize gradient after hardware interpolation [G]
    norm = math.sqrt(gradient.x**2 + gradient.y**2 + gradient.z**2)
    if norm > 0.0:
        gradient.x /= norm
        gradient.y /= norm
        gradient.z /= norm
    color = apply_phong_shading(gradient, light_dir, view_dir)
    opacity = density
    return color, opacity
```

**Parameters and Edge Cases:**
*   **Gradient Normalization:** Hardware interpolation does not preserve vector length, so gradients must be normalized before lighting calculations [G].
*   **Boundary Conditions:** Gradient computation at volume boundaries requires handling out-of-bounds accesses, typically by clamping or mirroring [S1, unofficial].
*   **Runtime Cost:** The method avoids 6 extra runtime texture fetches for gradients but requires offline computation [S1, unofficial][S2].

## Subtopics

### Pre-computed Gradient Resampling
A technique where volume gradients are pre-computed and stored in texture memory alongside density data, allowing the texture mapping hardware to interpolate both density and gradients during resampling [S2]. Unlike Sommer et al.'s method which computes gradients from a second copy of the volume in main memory (slower for translucent projections), this method uses hardware interpolation for throughput [S2]. It involves computing high-quality Sobel gradients serially offline, loading the four 8-bit values (three gradient components and raw density) into an RGB type texture map, and interpolating them using 3D texture mapping hardware [S2]. This approach produces accurate shading for arbitrary and dynamically changing directional lights, viewing parameters, and transfer functions [S2].

## Operating characteristics
*   **Time Complexity:** Pre-computation is $O(N)$ where $N$ is the number of voxels, performed offline [S2]. Runtime complexity is dominated by texture sampling and shading, which benefits from hardware interpolation [S2].
*   **Memory Complexity:** Requires storing 4 components per voxel instead of 1 [S1, unofficial]. This avoids the need for a second texture copy [S1, unofficial].
*   **Performance:** Computing gradients for a $256^3$ volume takes 12 seconds on a 200MHz CPU [S2]. The method enables high-quality Phong shading with hardware acceleration [S2].
*   **Strengths:** Eliminates the need for 6 extra runtime texture fetches for gradients [S1, unofficial]. Supports arbitrary lighting and view changes without reloading textures [S2].
*   **Limitations:** Pre-computation is static; gradient computation occurs only once regardless of viewing parameter changes, so dynamic volume updates require re-computation [S2].

## Background
The method originates from early hardware-accelerated volume rendering research [S2]. Cullip and Neumann described a method utilizing the PixelFlow machine that pre-computed gradient components and used texture mapping to interpolate density and gradients [S2]. This was one of the first proposed solutions to implement full Phong lighting functionality in hardware, though it was never fully realized due to hardware constraints requiring 43 processor cards [S2]. Sommer et al. later proposed resampling texture volumes in planes parallel to image pixels and mentioned the potential to interpolate gradients with hardware [S2]. The specific implementation details of packing gradients and isovalue into a single texture are documented in [S1, unofficial].
