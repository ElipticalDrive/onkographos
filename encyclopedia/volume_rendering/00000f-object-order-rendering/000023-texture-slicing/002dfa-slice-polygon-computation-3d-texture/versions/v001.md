# Slice Polygon Computation (3D Texture)

## Overview
Slice Polygon Computation is a method for generating proxy geometry for volume rendering when the scalar data is stored in a 3D texture. It solves the problem of creating a set of polygons that slice through the volume perpendicular to the viewing direction, ensuring that texture coordinates are correctly mapped to the 3D texture space. It is distinguished from 2D texture-based approaches by avoiding data replication and from brute-force oblique slicing by using a coherent, non-clipping generation strategy for oblique cases.

## How it works
**Inputs:**
- A 3D texture object containing the volumetric data.
- The viewing direction (for view-aligned slicing) or volume axes (for object-aligned slicing).
- The volume bounding box.

**Outputs:**
- A set of polygons (proxy geometry) representing the slices.
- Vertex arrays containing 3D positions and corresponding 3D texture coordinates.

**Data Structures:**
- Vertex arrays storing position $(x, y, z)$ and texture coordinates $(u, v, w)$.
- Polygon indices defining the connectivity of the slice vertices.

**Steps:**
1. **Intersect Slicing Planes with Bounding Box:**
   Define a series of parallel slicing planes perpendicular to the viewing direction. Intersect these planes with the edges of the volume bounding box to determine the intersection points.

2. **Sort Vertices:**
   Sort the resulting intersection vertices in a clockwise or counterclockwise direction around their center to form a valid polygon for each slice.

3. **Calculate Texture Coordinates:**
   For each vertex on the polygon, calculate the corresponding 3D texture coordinate $(u, v, w)$. This can be done on the CPU, in a vertex program, or via automatic texture-coordinate generation. The texture coordinates must map the vertex position to the correct location within the 3D texture.

4. **Render:**
   Pass the vertex arrays to the graphics library to render the projection. The polygons are rasterized, and the fragment shader samples the 3D texture using the interpolated texture coordinates.

**Edge Cases and Pitfalls:**
- **Precision Issues:** Numeric imprecision in clipping can introduce artifacts or degrade image quality. The graph-based approach avoids this by generating slices directly without clipping.
- **Degenerate Input:** If the slicing plane does not intersect the volume, no polygon is generated.

## Subtopics

### Graph-Based Oblique Slice Generation
A method to efficiently generate a stack of oblique slices orthogonal to the viewing direction by treating each slice as a 2D 'scanplane' and exploiting scanplane coherence, avoiding polygon clipping. It steps through the volumetric data set in the negative view direction, creating a new scanplane from its direct neighbor. This approach generates slices directly with no need for additional clipping, avoiding precision problems and artifacts from numeric imprecision in clipping. It is more efficient than the brute-force approach, which treats each slice independently and clips a large triangle to the data set.

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of slices and the complexity of the volume bounding box intersection.
- **Memory Complexity:** Linear with respect to the number of slices and vertices per slice.
- **Strengths:** Avoids data replication required by 2D texture approaches; efficient for oblique slicing compared to brute-force methods.
- **Limitations:** Requires careful handling of texture coordinate generation; performance depends on the number of slices and the complexity of the volume geometry.
- **When to Use:** Suitable for real-time volume rendering with 3D textures, especially when oblique slicing is required.
- **When Not to Use:** Not ideal for scenarios where data replication is acceptable and simpler 2D texture mapping suffices.

## Background
Originated from early GPU-based volume rendering techniques, specifically detailed in "GPU Gems" Chapter 39 and research by Okreylos. It leverages the capabilities of 3D texture mapping on GPUs to perform efficient volume rendering by treating the volume as a series of sliced polygons.
