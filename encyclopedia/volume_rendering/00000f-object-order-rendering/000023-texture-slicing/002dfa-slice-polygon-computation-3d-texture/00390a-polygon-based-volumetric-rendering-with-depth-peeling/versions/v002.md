# Polygon-based Volumetric Rendering with Depth Peeling

Also called: 3D Texture with Polygons, Slice-based Volume Rendering

## Overview
This method renders solid 3D bodies from volumetric data by constructing a mesh of textured polygons and applying a 3D texture, using an undocumented rendering option to handle transparency sorting [S1, unofficial]. It mimics volumetric rendering using false coloring and alpha blending on polygons, whereas true volumetric rendering requires a transfer function converting density accumulation to color per pixel [S1, unofficial]. It builds on [Slice Polygon Computation (3D Texture)](5680-slice-polygon-computation-3d-texture.md) and differs from [Object Aligned Planes Volume Rendering](11411-object-aligned-planes-volume-rendering.md) and [3D Texture Slicing with Back-to-Front Blending](12611-3d-texture-slicing-with-back-to-front-blending.md) by relying on explicit 3D polygon geometry and depth peeling for translucent ordering [S1, unofficial].

## How it works
**Inputs:** A stack of 2D volumetric slice images (e.g., 8-bit TIFFs) and rendering parameters [S1, unofficial].
**Outputs:** A rendered 3D visualization of the volume [S1, unofficial].

**Data Structures:**
1. **Volumetric Texture Data (`data`):** A packed 3D array of shape $(N_z, N_y, N_x, 4)$, where $N_z$ is the number of slices, and $N_x, N_y$ are the image dimensions [S1, unofficial]. Each element is an RGBA value in the "RGB" color space, where the fourth channel is opacity derived from binarized intensity [S1, unofficial].
2. **Polygon Mesh:** A list of quadrilateral primitives [S1, unofficial]. Each polygon is defined by 4 vertices in 3D space, with `VertexTextureCoordinates` mapping to the 3D texture [S1, unofficial].

**Parameters:**
* `top`: The z-value for the x-y cutaway plane. Typical value: $0.4$ (normalized 0-1 coordinates) [S1, unofficial].
* `right`: The x-value for the y-z cutaway plane. Typical value: $0.4$ [S1, unofficial].
* `rpad`: Padding for the cutaway decoration. Typical value: $-0.2$ [S1, unofficial].
* `step`: Slice spacing (distance between polygon layers) [S1, unofficial].
* `DepthPeelingLayers`: Limit on rendering translucent polygons. Typical value: $100$ [S1, unofficial].

**Steps:**
1. **Import and Convert:** Import the slice images and convert them into a single packed array [S1, unofficial].
2. **Colorize and Alpha:** For each slice, apply a color function (e.g., "SunsetColors") to generate RGB values, binarize the original intensity to generate an alpha channel, and combine them into an "RGB" color space array [S1, unofficial].
3. **Pack Texture:** Extract image data from the colored slices, reverse data orientation if required, and pack into a single 3D array `data` [S1, unofficial].
4. **Generate Bottom Polygons:** Create polygons for the z-range $[0, \text{top}]$ [S1, unofficial]. For each $z$ from $0$ to $\text{top}$ with step `step`, define vertices $P_1=(0,0,z)$, $P_2=(1,0,z)$, $P_3=(1,1,z)$, $P_4=(0,1,z)$, and assign `VertexTextureCoordinates` identical to the vertex positions [S1, unofficial].
5. **Generate Top Polygons:** Create polygons for the cutaway geometry [S1, unofficial]. For each $x$ from $0$ to $\text{right}$ with step `step`, define vertices $P_1=(x,0,\text{top})$, $P_2=(x,1,\text{top})$, $P_3=(x,1,1)$, $P_4=(x,0,1)$, and assign `VertexTextureCoordinates` identical to the vertex positions [S1, unofficial].
6. **Render:** Draw the polygons with the 3D texture applied [S1, unofficial]. Set global opacity (e.g., $0.4$) and enable depth peeling with a layer limit (e.g., $100$) to ensure correct translucent sorting [S1, unofficial].

**Pseudocode:**
```python
def render_volume_with_depth_peeling(slices, top=0.4, right=0.4, rpad=-0.2, step=0.01, depth_peeling_layers=100):
    # Step 1 & 2: Colorize and Alpha
    colored_slices = []
    for img in slices:
        rgb = apply_color_function(img, "SunsetColors")
        alpha = binarize(img)
        rgba = combine_rgb_alpha(rgb, alpha, space="RGB")
        colored_slices.append(rgba)
    colored_slices.reverse()

    # Step 3: Pack texture data
    data = pack_array([extract_image_data(img, reverse=True) for img in colored_slices])

    # Step 4: Generate Bottom Polygons (z from 0 to top)
    bottom_polygons = []
    z = 0.0
    while z <= top + 1e-9:
        pts = [[0, 0, z], [1, 0, z], [1, 1, z], [0, 1, z]]
        bottom_polygons.append({"vertices": pts, "vertex_texture_coordinates": pts})
        z += step

    # Step 5: Generate Top Polygons (x from 0 to right)
    top_polygons = []
    x = 0.0
    while x <= right + 1e-9:
        pts = [[x, 0, top], [x, 1, top], [x, 1, 1], [x, 0, 1]]
        top_polygons.append({"vertices": pts, "vertex_texture_coordinates": pts})
        x += step

    # Step 6: Render Setup
    cutaway_pts = [
        [right, 0, top], [1 + rpad, 0, top], [1 + rpad, 1, top],
        [right, 1, top], [right, 1, 1], [right, 0, 1]
    ]
    renderer_state = {
        "opacity": 0.4,
        "texture": data,
        "edge_form": None,
        "polygons": bottom_polygons + top_polygons + [{"vertices": cutaway_pts}],
        "plot_range": [[0, 1 + rpad], [0, 1], [0, 1]],
        "lighting": "Neutral",
        "background": [0, 0, 0],
        "rotation_action": "Clip",
        "spherical_region": True,
        "box_style": {"opacity": 0.2, "color": [1, 1, 1]},
        "image_size": [400, 400],
        "base_style": {"rendering_options": {"DepthPeelingLayers": depth_peeling_layers}},
        "box_ratios": [1 + rpad, 1, 0.9]
    }
    return renderer_state

def apply_color_function(image, name):
    # Standard color mapping logic [G]
    return image

def binarize(image):
    # Standard thresholding logic [G]
    return [[1.0 if pixel > 0.5 else 0.0 for pixel in row] for row in image]

def combine_rgb_alpha(rgb, alpha, space):
    # Concatenates RGB and Alpha channels [G]
    return [row_rgb + row_alpha for row_rgb, row_alpha in zip(rgb, alpha)]

def pack_array(list_of_arrays):
    # Converts list of arrays into a single packed 3D array [G]
    return list_of_arrays

def extract_image_data(img, reverse=False):
    # Extracts raw image data, optionally reversing orientation [G]
    return img[::-1] if reverse else img
```

## Operating characteristics
* **Time Complexity:** Not given in the sources.
* **Memory Complexity:** Not given in the sources.
* **Measured Performance:** Performance is limited by the Front End's ability to handle large polygon counts and depth peeling passes [S1, unofficial]. Decreasing `step` or increasing `DepthPeelingLayers` and `ImageSize` can crash the Front End due to memory/resource limits [S1, unofficial].
* **Strengths:** Simple to implement using standard graphics primitives; leverages existing 3D texture hardware acceleration; provides a visual approximation of volumetric rendering without complex ray-casting [S1, unofficial].
* **Limitations:** Not true volumetric rendering (no transfer function-based density accumulation); quality depends heavily on slice spacing (`step`) and depth peeling layers; prone to crashing with high resolution or fine step sizes; limited flexibility compared to dedicated volume rendering engines [S1, unofficial].
* **When to Use:** Quick visualization of volumetric data when true volume rendering is unavailable or too complex; educational purposes to demonstrate texture mapping and transparency [S1, unofficial].
* **When Not to Use:** When accurate density-based visualization is required; when high resolution and fine detail are needed without performance degradation; when working with very large datasets that exceed available memory [S1, unofficial].

## Background
This technique was presented as a solution for rendering solid 3D bodies using volumetric rendering in Mathematica, leveraging its 3D graphics capabilities and undocumented rendering options [S1, unofficial]. It was developed in response to the limited native volumetric rendering support in earlier versions of Mathematica (e.g., version 8), which lacked proper transfer functions and density accumulation [S1, unofficial]. The method mimics volumetric rendering by using false coloring and alpha blending on polygons, serving as a workaround until more advanced features like `CUDAVolumetricRender` became available [S1, unofficial]. It relies on the `DepthPeelingLayers` rendering option, which is undocumented and controls the limit on rendering translucent polygons [S1, unofficial].
