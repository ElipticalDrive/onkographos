# Wall Surface Projection & Texture Mapping

Also called: Axis-aligned Texture Projection, Planar Mapping, renderBlockSurfaces

## Overview
Wall Surface Projection & Texture Mapping renders 3D volumetric data by projecting individual visible block faces onto the 2D screen plane, applying perspective-correct UV mapping, and compositing the resulting pixels directly. Unlike standard texture slicing which composites semi-transparent slices back-to-front, this method treats opaque block surfaces as discrete geometric primitives, shading them per-face and handling clipping against the view frustum [S1, unofficial]. It is distinct from sibling methods like Cabral Texture Mapping by relying on explicit screen-space projection of block faces rather than ray-casting through texture volumes [S1, unofficial][S7257-cabral-texture-mapping.md].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D voxel grid (chunk) where each block has an associated texture ID and visibility flags for its six faces. The current camera position and orientation.
*   **Output:** A 2D screen buffer with pixels colored by the projected texture, modulated by per-face shading.

**Data Structures:**
*   **Block:** Contains `visibleFaces` (boolean flags for XPos, XNeg, YPos, YNeg, ZPos, ZNeg) and `textureMap` (RGB data).
*   **Texture:** Contains `width`, `height`, and `textureMap` (array of RGB values).
*   **Screen Coordinates:** Pixel positions $(x, y)$ on the screen.

**Algorithm Steps:**
1.  **Visibility Culling:** Iterate through all blocks in the chunk. For each block, determine which faces are visible by checking if adjacent blocks are inactive or out of bounds [S1, unofficial].
2.  **Projection and Clipping:** For each visible face, project its 3D corners to 2D screen coordinates. Clip edges that lie behind the player (specifically checking $y < 1$ in the source implementation) to prevent division by zero and invalid geometry [S1, unofficial].
3.  **UV Mapping Calculation:**
    *   Calculate the horizontal step size:
        $$ \text{horizontalStep} = \frac{\text{texture.width} \cdot uvU}{x_{pos2} - x_{pos1}} $$
    *   Clamp $x_{pos1}$ and $x_{pos2}$ to $[0, \text{SCR\_WIDTH}]$. Adjust `horizontalStart` accordingly.
    *   Compute distance in X:
        $$ \text{distX} = \max(1, x_{pos2} - x_{pos1}) $$
    *   For each screen column $x$, compute the top and bottom Y coordinates of the face:
        $$ y_1 = \text{bottomPos1} + \text{distBottom} \cdot \frac{x - \text{originalX1} + 0.5}{\text{distX}} $$
        $$ y_2 = \text{topPos1} + \text{distTop} \cdot \frac{x - \text{originalX1} + 0.5}{\text{distX}} $$
    *   Calculate the vertical step size:
        $$ \text{verticalStep} = \frac{\text{texture.height} \cdot uvV}{y_2 - y_1} $$
    *   Clamp $y_1$ and $y_2$ to $[0, \text{SCR\_HEIGHT}]$. Adjust `verticalStart` accordingly.
4.  **Pixel Rendering:**
    *   Iterate through each row $y$ from $y_1$ to $y_2$.
    *   Compute the texture index $p$ using modulo wrapping to handle texture repetition:
        $$ p = \left( (\text{texture.height} - (\text{verticalStart} \pmod{\text{texture.height}}) - 1) \cdot 3 \cdot \text{texture.width} + (\text{horizontalStart} \pmod{\text{texture.width}}) \cdot 3 \right) $$
    *   Apply per-face shading to the red component (assuming grayscale or single-channel shading for simplicity in the source):
        $$ r = \max(\text{textureMap}[p + 0] - \text{shade}/2, 0) $$
    *   Draw the pixel at $(x, y)$ with color $(r, g, b)$ and depth `distanceToPlayer` [S1, unofficial].
    *   Increment `verticalStart` by `verticalStep` and `horizontalStart` by `horizontalStep` for the next iteration.

**Pitfalls:**
*   **Division by Zero:** If $x_{pos2} - x_{pos1} = 0$, the horizontal step is undefined. The source handles this by forcing $\text{distX} = 1$ [S1, unofficial].
*   **Clipping:** Faces entirely behind the player must be clipped or discarded to avoid rendering artifacts [S1, unofficial].

**Pseudocode:**
```python
def render_wall_surface(block, camera, screen_width, screen_height):
    # 1. Check visibility of faces
    if not is_face_visible(block, Face.XPos):
        return
    
    # 2. Project face corners to screen space
    # Assume get_screen_coords returns (x1, y1, z1), (x2, y2, z2) for the face
    x1, y1, z1 = get_screen_coords(block, Face.XPos, Corner.Min)
    x2, y2, z2 = get_screen_coords(block, Face.XPos, Corner.Max)
    
    # 3. Clip behind player
    clip_behind_player(x1, y1, z1, x2, y2, z2)
    
    # 4. Calculate UV mapping parameters
    # Clamp x positions to screen bounds
    x1 = clamp(x1, 0, screen_width)
    x2 = clamp(x2, 0, screen_width)
    
    dist_x = max(1, x2 - x1)
    horizontal_step = (block.texture.width * uv_u) / dist_x
    
    # Adjust start based on clamping
    horizontal_start = block.texture.width * uv_u * (x1 / dist_x) # Approximation based on source logic
    
    # Calculate y bounds for each x
    # Note: Source uses specific geometric formulas for y1 and y2 based on perspective
    for x in range(int(x1), int(x2)):
        # Compute y1 and y2 for this x column
        y1_col = bottom_pos1 + dist_bottom * (x - original_x1 + 0.5) / dist_x
        y2_col = top_pos1 + dist_top * (x - original_x1 + 0.5) / dist_x
        
        # Clamp y bounds
        y1_col = clamp(y1_col, 0, screen_height)
        y2_col = clamp(y2_col, 0, screen_height)
        
        if y2_col <= y1_col:
            continue
            
        vertical_step = (block.texture.height * uv_v) / (y2_col - y1_col)
        vertical_start = block.texture.height * uv_v * (y1_col / (y2_col - y1_col)) # Approximation
        
        for y in range(int(y1_col), int(y2_col)):
            # Calculate texture index with modulo wrapping
            tex_h = block.texture.height
            tex_w = block.texture.width
            p = ((tex_h - (int(vertical_start) % tex_h) - 1) * 3 * tex_w + 
                 (int(horizontal_start) % tex_w) * 3)
            
            # Apply shading
            r = max(block.texture.texture_map[p + 0] - shade / 2, 0)
            g = block.texture.texture_map[p + 1]
            b = block.texture.texture_map[p + 2]
            
            # Draw pixel
            screen.draw_pixel(x, y, RgbColor(r, g, b), distance_to_player)
            
            vertical_start += vertical_step
            
        horizontal_start += horizontal_step
```

## Operating characteristics
*   **Time Complexity:** Proportional to the number of visible faces and the screen area they cover. Each visible face requires projection, clipping, and pixel iteration.
*   **Memory Complexity:** Low, as it processes faces individually and does not require storing large intermediate buffers for compositing.
*   **Strengths:** Simple implementation for opaque voxel worlds; efficient culling of hidden faces; direct screen-space rendering.
*   **Limitations:** No support for semi-transparency or volume integration; aliasing at oblique angles due to lack of 3D interpolation; performance degrades with high face counts on screen.
*   **When to Use:** Opaque voxel rendering (e.g., Minecraft-style games) where performance is critical and transparency is not required.
*   **When Not to Use:** Medical imaging, scientific visualization, or any application requiring semi-transparent volume rendering.

## Background
This method originates from early 3D engine implementations, specifically those mimicking the style of 1990s first-person shooters with voxel-based environments. The specific implementation details are derived from a 2026 GitHub repository [S1, unofficial]. It represents a geometric approach to volume rendering, contrasting with the optical/compositing approaches of texture slicing.
