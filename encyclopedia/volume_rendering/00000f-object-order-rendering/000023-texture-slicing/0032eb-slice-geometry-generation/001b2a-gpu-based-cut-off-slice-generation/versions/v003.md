# GPU-based Cut-off Slice Generation

Also called: Rezk-Salama method, Vertex Shader Slice Generation, View-Aligned Slicing (Proxy Geometry Generation), Viewport-Aligned Slices Intersection Algorithm

## Overview
GPU-based Cut-off Slice Generation is a method for generating proxy geometry (polygons) that represent the intersection of a volume's bounding box with a series of parallel slicing planes, executed entirely on the GPU via vertex shaders [S1, unofficial][S2, book][S4]. It solves the performance bottleneck of CPU-based slice generation by offloading the calculation of intersection points, polygon sorting, and tessellation to the graphics hardware, enabling interactive frame rates for dynamic volume rendering [S1, unofficial]. It sets itself apart from CPU-based approaches by leveraging the parallelism of vertex shaders to process multiple slices or vertices simultaneously, and from cell-based methods by operating on the global bounding box rather than individual grid cells [S1, unofficial][S2, book].

## How it works
The method generates a sequence of polygons (proxy geometry) that slice through the volumetric data. These polygons are rendered in depth order (back-to-front or front-to-back) to composite the volume using hardware alpha blending [S1, unofficial][S2, book][S3, unofficial].

### Inputs and Outputs
*   **Inputs:**
    *   Volume bounding box defined by 8 vertices in object space.
    *   Modelview matrix (transforming object space to view space).
    *   Viewing direction (normal vector $\vec{n}_p$).
    *   Number of slices and sampling distance (derived from voxel size and sampling rate) [S2, book][S4].
    *   3D texture containing the volume data.
*   **Outputs:**
    *   A stream of triangle primitives (or triangle strips/fans) representing the slice polygons, ready for rasterization.
    *   Texture coordinates for each vertex, mapping to the 3D volume texture.

### Data Structures
*   **Bounding Box Vertices:** An array of 8 3D vectors representing the corners of the volume bounding box in object space.
*   **Edge List:** 12 edges, where each edge $E_{i \rightarrow j}$ connects vertex $V_i$ to $V_j$.
*   **Edge Flags:** For each of the 12 edges, a set of 6 boolean flags, one for each face of the bounding box (Top, Bottom, Left, Right, Front, Back). A flag is set if the edge belongs to that face [S3, unofficial].
*   **Intersection List:** A temporary list of intersection points. The maximum size is 6, as a plane can intersect a convex hexahedron at most 6 times [S2, book][S4].

### Algorithm Steps

1.  **Transform Bounding Box:**
    Transform the 8 vertices of the volume bounding box from object space to view space using the modelview matrix [S2, book][S4].

2.  **Determine Slicing Planes:**
    Find the minimum ($z_{min}$) and maximum ($z_{max}$) z-coordinates of the transformed vertices. Calculate the number of sampling planes and their positions using equidistant spacing from the view origin. The sampling distance is computed from the voxel size and current sampling rate [S2, book][S4].

3.  **Compute Intersections (Vertex Shader):**
    For each slicing plane (defined by normal $\vec{n}_p$ and distance $d$ from origin):
    *   Represent each bounding box edge $E_{i \rightarrow j}$ as a line segment:
        $$ \vec{x} = \vec{V}_i + \lambda \cdot \vec{e}_{i \rightarrow j} $$
        where $\vec{e}_{i \rightarrow j} = \vec{V}_j - \vec{V}_i$ and $\lambda \in [0, 1]$ [S1, unofficial].
    *   Represent the clipping plane in Hessian normal form:
        $$ \vec{n}_p \cdot \vec{x} = d $$
        For view-aligned slicing, $\vec{n}_p$ is the viewing direction [S1, unofficial].
    *   Solve for $\lambda$:
        $$ \lambda = \begin{cases} \frac{d - \vec{n}_p \cdot \vec{V}_i}{\vec{n}_p \cdot \vec{e}_{i \rightarrow j}}, & \vec{n}_p \cdot \vec{e}_{i \rightarrow j} \neq 0 \\ -1.0, & \text{otherwise} \end{cases} $$
        If $\lambda \in [0, 1]$, the intersection is valid. If the denominator is zero, the edge is parallel to the plane (or on it), denoted by $\lambda = -1.0$ [S1, unofficial].
    *   Store valid intersection points in the Intersection List.

4.  **Filter and Merge Intersections:**
    *   Apply a bounding sphere test to discard points outside the bounding sphere (invalid intersections) [S3, unofficial].
    *   Merge double points that coincide with corner vertices [S3, unofficial].
    *   *Note:* The vertex shader must output exactly 6 vertices for every polygon. If fewer than 6 intersections exist, duplicate existing vertices to fill the output buffer [S1, unofficial].

5.  **Sort Vertices:**
    *   Compute the center of the proxy polygon by averaging the valid intersection points [S2, book][S4].
    *   Sort the vertices clockwise or counter-clockwise. Project points onto the x-y plane and compute a "pseudo-angle" to avoid trigonometric functions. The pseudo-angle is derived from the tangent of the angle and the sign of the coordinates (Moret and Shapiro 1991) [S2, book][S4].
    *   *Alternative Sorting (Rezk-Salama):* Traverse edges in a specific order (Red, Yellow, Green, Cyan, Blue, Purple groups) to form a valid polygon. If an edge in the Yellow, Cyan, or Purple group has no intersection, duplicate the intersection from the preceding Red, Green, or Blue edge respectively [S1, unofficial].
    *   *Flag-based Sorting:* Use the edge flags. A sequence is valid if the bitwise OR of the flags of two adjacent points is nonzero (indicating a common face) [S3, unofficial].

6.  **Compute Texture Coordinates:**
    Translate the 3D intersection point coordinates to texture space. For a unit vector $\vec{k}$ (x, y, or z) in texture space:
    $$ PI \cdot \vec{k} = \begin{cases} \frac{V_i \vec{k} - min(B_{\vec{k}})}{max(B_{\vec{k}}) - min(B_{\vec{k}})} & \vec{k} \cdot \vec{e}_{i \rightarrow j} = 0 \\ \lambda & \vec{k} \cdot \vec{e}_{i \rightarrow j} > 0 \\ 1 - \lambda & \vec{k} \cdot \vec{e}_{i \rightarrow j} < 0 \end{cases} $$
    where $B_{\vec{k}}$ is the bounding box length in direction $\vec{k}$ [S1, unofficial].

7.  **Tessellate:**
    Tessellate the sorted polygon vertices into triangles (using a triangle fan or strip from the center) [S2, book][S4]. Transform vertices back to object space if required by the rendering pipeline [S2, book].

8.  **Render:**
    *   Bind the volume as a 3D texture [S1, unofficial].
    *   Render the generated triangles.
    *   In the fragment shader, sample the 3D texture using the vertex coordinates.
    *   Apply a transfer function (mapping scalar value to RGBA) via a 2D texture lookup [S1, unofficial].
    *   Blend the fragments using hardware alpha blending:
        $$ C_{dest} = C_{src} \cdot A_{src} + C_{dest} \cdot (1 - A_{src}) $$
        Slices must be rendered in correct depth order (back-to-front or front-to-back) [S1, unofficial][S3, unofficial].

```python
def generate_slices(bounding_box_vertices, modelview_matrix, viewing_direction, num_slices, sampling_distance):
    """
    Generates proxy geometry for volume slicing on the GPU.
    
    Args:
        bounding_box_vertices: List of 8 (x, y, z) tuples in object space.
        modelview_matrix: 4x4 matrix to transform object to view space.
        viewing_direction: Normal vector (nx, ny, nz) of the slicing planes.
        num_slices: Number of parallel slices to generate.
        sampling_distance: Distance between adjacent slices.
        
    Returns:
        List of triangle indices and vertex attributes (position, texcoords) for each slice.
    """
    # Step 1: Transform bounding box to view space
    view_vertices = [transform(v, modelview_matrix) for v in bounding_box_vertices]
    
    # Step 2: Determine slice positions
    z_coords = [v[2] for v in view_vertices]
    z_min = min(z_coords)
    z_max = max(z_coords)
    
    # Calculate slice origins in view space
    # Assuming slices are perpendicular to viewing direction and spaced by sampling_distance
    # For view-aligned, viewing_direction is typically (0,0,1) in view space
    slice_origins = []
    current_z = z_min
    for i in range(num_slices):
        slice_origins.append((0, 0, current_z)) # View space origin offset
        current_z += sampling_distance
        
    all_triangles = []
    
    for origin in slice_origins:
        # Step 3: Compute intersections
        intersections = []
        edge_flags = [] # Store flags for each intersection point
        
        for edge_idx, (v1, v2) in enumerate(get_edges(view_vertices)):
            e = v2 - v1
            denom = dot(viewing_direction, e)
            
            if abs(denom) > 1e-9:
                # lambda = (d - n . V_i) / (n . e)
                # Plane equation: n . (x - origin) = 0 => n . x = n . origin
                d = dot(viewing_direction, origin)
                lambda_val = (d - dot(viewing_direction, v1)) / denom
                
                if 0.0 <= lambda_val <= 1.0:
                    point = v1 + lambda_val * e
                    intersections.append(point)
                    edge_flags.append(get_edge_flags(edge_idx)) # Get 6-bit flag set
            else:
                # Edge parallel to plane
                pass
                
        # Step 4: Filter and Merge
        # Apply bounding sphere test and merge duplicates
        valid_intersections = []
        valid_flags = []
        for i, pt in enumerate(intersections):
            if is_inside_bounding_sphere(pt) and not is_duplicate(pt, valid_intersections):
                valid_intersections.append(pt)
                valid_flags.append(edge_flags[i])
                
        # Step 5: Sort Vertices
        # Method A: Pseudo-angle sorting (Moret and Shapiro)
        if len(valid_intersections) > 2:
            center = average(valid_intersections)
            sorted_indices = sort_by_pseudo_angle(valid_intersections, center)
            sorted_points = [valid_intersections[i] for i in sorted_indices]
            sorted_flags = [valid_flags[i] for i in sorted_indices]
        else:
            # Degenerate case (line or point)
            sorted_points = valid_intersections
            sorted_flags = valid_flags
            
        # Step 6: Compute Texture Coordinates
        # Note: This requires object space coordinates for accurate texture mapping
        # Re-calculate lambda in object space or transform view points back to object space
        # For simplicity, assuming we have object space intersection points or can transform back
        object_intersections = [transform_back(pt, modelview_matrix) for pt in sorted_points]
        tex_coords = []
        for pt in object_intersections:
            # Compute texture coordinates based on bounding box bounds
            # This is a simplified placeholder; actual implementation uses the formula from [S1, unofficial]
            tc = compute_texture_coordinate(pt, bounding_box_vertices)
            tex_coords.append(tc)
            
        # Step 7: Tessellate
        # Create triangles using a fan from the center
        triangles = []
        if len(sorted_points) >= 3:
            for i in range(1, len(sorted_points) - 1):
                # Triangle: center, sorted_points[i], sorted_points[i+1]
                # Note: Center must be computed in object space for correct rendering
                center_obj = average(object_intersections)
                triangles.append((center_obj, object_intersections[i], object_intersections[i+1]))
                
        all_triangles.extend(triangles)
        
    return all_triangles

def get_edges(vertices):
    """Returns the 12 edges of a cube defined by 8 vertices."""
    # Standard cube connectivity
    return [
        (vertices[0], vertices[1]), (vertices[1], vertices[5]), (vertices[5], vertices[4]), (vertices[4], vertices[0]), # Front face

        (vertices[0], vertices[2]), (vertices[1], vertices[3]), (vertices[5], vertices[7]), (vertices[4], vertices[6])  # Connecting edges
    ]

def sort_by_pseudo_angle(points, center):
    """Sorts points around center using pseudo-angle to avoid trigonometry."""
    def pseudo_angle(p):
        dx = p[0] - center[0]
        dy = p[1] - center[1]
        # Tangent and sign of coordinates
        if dx == 0:
            return 1.0 if dy > 0 else -1.0
        tan_val = dy / dx
        if dx < 0:
            return tan_val + 2.0 # Adjust for quadrant
        return tan_val
    return sorted(range(len(points)), key=lambda i: pseudo_angle(points[i]))

def compute_texture_coordinate(point, bbox_vertices):
    """Computes texture coordinate for a point in object space."""
    # Simplified: Normalize point within bounding box
    min_b = min(v[0] for v in bbox_vertices), min(v[1] for v in bbox_vertices), min(v[2] for v in bbox_vertices)
    max_b = max(v[0] for v in bbox_vertices), max(v[1] for v in bbox_vertices), max(v[2] for v in bbox_vertices)
    
    u = (point[0] - min_b[0]) / (max_b[0] - min_b[0])
    v = (point[1] - min_b[1]) / (max_b[1] - min_b[1])
    w = (point[2] - min_b[2]) / (max_b[2] - min_b[2])
    return (u, v, w)
```

### Parameters and Edge Cases
*   **Parameters:**
    *   `sampling_distance`: Computed from voxel size and current sampling rate [S2, book][S4].
    *   `viewing_direction`: Typically the z-axis in view space [S2, book].
*   **Edge Cases:**
    *   **Parallel Edges:** If $\vec{n}_p \cdot \vec{e}_{i \rightarrow j} = 0$, the edge is parallel to the plane. $\lambda$ is set to -1.0 [S1, unofficial].
    *   **Degenerate Polygons:** If the plane intersects fewer than 3 vertices, no triangle can be formed. The algorithm must handle this by outputting duplicate vertices or skipping the slice [S1, unofficial].
    *   **Vertex Shader Limitations:** Vertex shaders cannot insert or remove vertices. The algorithm must output 6 vertices per polygon, even if the actual intersection has fewer vertices. Duplicates are used to fill the buffer [S1, unofficial].
    *   **Precision:** Floating-point precision issues may cause gaps or overlaps in the slice geometry. Using a bounding sphere test helps filter invalid points [S3, unofficial].

## Subtopics

### [Incremental Intersection and Texture Coordinates](997-incremental-intersection-and-texture-coordinates.md)
A method to compute intersection points and texture coordinates for axis-aligned boxes against parallel slicing planes incrementally, avoiding the bottleneck of recomputing intersections for every sub-volume and plane. It sets itself apart from naive per-plane intersection by leveraging the uniform spacing and parallel nature of slicing planes to update positions via constant deltas, maintaining an `ActiveIntersectionList` to track active edge intersections.

## Operating characteristics
*   **Time Complexity:** The complexity per slice is dominated by the intersection calculation with 12 edges, which is $O(1)$ per slice. The sorting step is $O(1)$ since the number of vertices is bounded by 6. The total time is proportional to the number of slices [S1, unofficial][S2, book].
*   **Memory Complexity:** Requires storage for the bounding box vertices, edge flags, and the output vertex array. The vertex array size is proportional to the number of slices times a constant (6 vertices per slice) [S2, book][S4].
*   **Performance:** GPU-based generation significantly improves performance compared to CPU-based generation, enabling interactive frame rates (response time < 100ms) [S1, unofficial]. The performance scales with the number of slices and the complexity of the transfer function [S1, unofficial].
*   **Strengths:**
    *   Real-time performance due to GPU offloading [S1, unofficial].
    *   Simple implementation using standard graphics pipeline stages [S2, book].
    *   Compatible with hardware alpha blending [S3, unofficial].
*   **Limitations:**
    *   Limited to convex bounding boxes (typically axis-aligned).
    *   Cannot handle complex internal structures or holes within the volume without additional logic [S1, unofficial].
    *   Requires careful handling of duplicate vertices to avoid rendering artifacts [S1, unofficial].
*   **When to Use:** Suitable for real-time volume rendering of convex volumes where interactive performance is critical [S1, unofficial][S2, book].
*   **When Not to Use:** Unsuitable for non-convex volumes or volumes with complex internal structures that require cell-based slicing [S1, unofficial].

## Background
The method was proposed by Rezk-Salama et al. [50] (cited in [S1, unofficial]) to move the calculation of cut-off slices from the CPU to the GPU using vertex shaders. It is also known as View-Aligned Slicing and is described in the NVIDIA GPU Gems book [S2, book][S4]. The technique is widely used in scientific visualization and medical imaging for real-time volume rendering [S1, unofficial]. The sorting algorithm using pseudo-angles is attributed to Moret and Shapiro (1991) [S2, book][S4].
