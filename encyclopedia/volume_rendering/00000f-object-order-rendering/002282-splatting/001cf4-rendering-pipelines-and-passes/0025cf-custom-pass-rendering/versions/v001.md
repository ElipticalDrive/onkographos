# Custom Pass Rendering

Also called: DemoRenderer pipeline, Multi-pass Octree Rendering Pipeline, NanoVolume Custom Pass Rendering, SSVDAG rendering passes

## Overview
Custom Pass Rendering is a multi-pass, object-order rendering pipeline designed for high-performance visualization of large-scale volumetric data (specifically NanoVDB) and implicit surfaces using GPU compute and fragment shaders [S1, S2, unofficial]. It solves the problem of efficiently rendering complex, high-resolution volumetric datasets by decoupling geometry reconstruction, shading, and post-processing effects into distinct render passes [S1, S2, unofficial]. Unlike monolithic ray-marching approaches, it separates the initial ray-casting/trace phase from lighting calculations, allowing for optimized memory access patterns and modular effect integration (SSAO, shadows) [S1, S2, unofficial]. It is distinct from [Plug-and-Play Ray Marching and Rendering](981-plug-and-play-ray-marching-and-rendering.md) by its explicit multi-pass FBO management and from [Volume Rendering Pipeline](1318-volume-rendering-pipeline.md) by its specific use of NanoVDB structures and Unity's HDRenderPipeline integration [S2, unofficial].

## How it works
The pipeline executes a sequence of fullscreen passes, each writing to a specific Framebuffer Object (FBO) attachment. The core logic involves casting rays through the volume, reconstructing hit positions and normals, filtering normals, computing ambient occlusion, and finally shading with materials and shadows.

### Inputs and Outputs
**Inputs:**
*   Camera matrices: View, Projection, and their inverses.
*   Camera position (`_WorldSpaceCameraPos`).
*   Screen resolution (`screenRes`).
*   Volumetric data: NanoVDB structure (accessed via `usamplerBuffer` or `usampler3D` depending on configuration) [S1, S2, unofficial].
*   Optional Material Octree data (encoded in a `GL_TEXTURE_BUFFER`) [S1, unofficial].

**Outputs:**
*   Final color buffer (RGBA32F or similar, depending on the final pass configuration).

### Data Structures and Layout
The pipeline uses a series of Framebuffer Objects (FBOs) to store intermediate results. Each FBO is bound to specific texture attachments with defined formats and filtering modes [S1, unofficial].

**FBO Layout:**
*   **FBO[0] (Primary Rays/Depth):**
    *   Attachment 0: `_glTexDepth` (GL_TEXTURE_2D, GL_RGBA32F, screen resolution, GL_LINEAR filtering) [S1, unofficial].
*   **FBO[1] (Hit Position/Normal):**
    *   Attachment 0: `_glTexHitPos` (GL_TEXTURE_2D, GL_RGB32F, screen resolution, GL_NEAREST filtering) [S1, unofficial].
    *   Attachment 1: `_glTexHitNorm` (GL_TEXTURE_2D, GL_RGB32F, screen resolution, GL_NEAREST filtering) [S1, unofficial].
*   **FBO[2] (Materials, if enabled):**
    *   Attachment 0: `_glTexHitMaterial` (GL_TEXTURE_2D, GL_R8UI, screen resolution, GL_NEAREST filtering) [S1, unofficial].
*   **FBO[3] (Normal Filtering):**
    *   Attachment 0: `_glTexHitNormFiltered` (GL_TEXTURE_2D, GL_RGB32F, screen resolution, GL_NEAREST filtering) [S1, unofficial].
*   **FBO[4] (Shadows):**
    *   Attachment 0: `_glTexShadows` (GL_TEXTURE_2D, GL_R32F, screen resolution, GL_NEAREST filtering) [S1, unofficial].
*   **FBO[5] (AO):**
    *   Attachment 0: `_glTexAO` (GL_TEXTURE_2D, GL_R32F, screen resolution, GL_NEAREST filtering) [S1, unofficial].
*   **FBO[6] (AO Blurred):**
    *   Attachment 0: `_glTexAOBlurred` (GL_TEXTURE_2D, GL_R32F, screen resolution, GL_NEAREST filtering) [S1, unofficial].

**Uniforms and Constants:**
*   `screenRes`: `vec2` (screen width, height) [S1, unofficial].
*   `depth`: `int` (texture index for depth) [S1, unofficial].
*   `projectionFactor`: `float` (calculated from FOV and screen tolerance) [S1, unofficial].
*   `matOctree`: `int` (texture index for material octree) [S1, unofficial].
*   `matOctreehalfSide`, `matOctreeCenter`, `matOctreeLevels`: `float`/`vec3`/`int` (octree metadata) [S1, unofficial].
*   `inputTex`: `int` (source texture index for filtering/SSAO) [S1, unofficial].
*   `hitPosTex`, `hitNormTex`, `hitNormTexFiltered`, `depthTex`, `noiseTex`, `shadowsTex`, `aoTex`, `aoTexBlurred`, `materialTex`: `int` (texture indices) [S1, unofficial].
*   `samples`: `vec3` array (SSAO sample positions) [S1, unofficial].
*   `materials`: `vec3` array (material colors, if `USE_MATERIALS` is defined) [S1, unofficial].

**Parameters:**
*   `_sigma`: 4.0f (Normal filtering/SSAO smoothing parameter) [S1, unofficial].
*   `_bsigma`: 0.4f (Bilateral filtering/SSAO smoothing parameter) [S1, unofficial].
*   `_msize`: 10 (Kernel size for normal filtering, defines `MSIZE` in shader) [S1, unofficial].
*   `_ssaoRadius`: `eo->getHalfSide(eo->getNLevels()) * 100.0f` (SSAO sample radius) [S1, unofficial].
*   `_ssaoNSamples`: 32 (Number of SSAO samples) [S1, unofficial].
*   `_ssaoNoiseTexSide`: 64 (Side length of SSAO noise texture) [S1, unofficial].
*   `_renderMode`: 0 (Render mode selector) [S1, unofficial].
*   `_useDif`: true (Enable diffuse shading) [S1, unofficial].
*   `_filterNormals`: true (Enable normal filtering pass) [S1, unofficial].
*   `_doSSAO`: true (Enable SSAO pass) [S1, unofficial].
*   `_doShadows`: true (Enable shadow pass) [S1, unofficial].
*   `_useMaterials`: false (Enable material lookup pass) [S1, unofficial].

### Numbered Steps

1.  **Initialization:** Create `NUM_PASSES` `RendererMonitor` instances and start them [S1, unofficial]. Setup the shader as a `FullScreenPass` with `#pragma target 5.0` and `#pragma use_dxc` [S2, unofficial]. Include common headers: `CustomPassCommon.hlsl`, `PseudoRandom.hlsl`, `NanoVolumePass.hlsl` [S2, unofficial].

2.  **Pass 1: Pos and Norm Computation:**
    *   Compile and link the pass using vertex shader from `sqr.getDefaultVertexProgram()` and fragment shader from `SHADER_POS_NORM_FILE` [S1, unofficial].
    *   Set uniforms: `screenRes`, `depth` (TEX_NUM_DEPTH), `projectionFactor` [S1, unofficial].
    *   **Fragment Shader Logic:**
        *   Load camera depth at `varyings.positionCS.xy` using `LoadCameraDepth` [S2, unofficial].
        *   Get position inputs using `GetPositionInput` with screen size, depth, inverse view-projection matrix, and view matrix [S2, unofficial].
        *   Calculate normalized view direction using `GetWorldSpaceNormalizeViewDir(posInput.positionWS)` [S2, unofficial].
        *   Call core volume rendering function `NanoVolumePass` with `_WorldSpaceCameraPos` and negated view direction `-viewDirection` [S2, unofficial].
        *   Return resulting color with alpha blending: `float4(color.rgb, color.a)` [S2, unofficial].
        *   *Note:* The GLSL source for `demo_pos_norm_pass.frag.glsl` shows an alternative implementation for ray casting:
            *   Compute screen coordinates: `screenCoords = (gl_FragCoord.xy / screenRes) * 2.0 - 1.0` [S1, unofficial].
            *   Compute camera ray direction `rd` using `projMatInv` and `viewMatInv` [S1, unofficial].
            *   Fetch depth `val.x` from `depthTex` [S1, unofficial].
            *   Compute hit position: `hitPosition = r.o + val.x * r.d` [S1, unofficial].
            *   Compute diffuse factor `dif`: If `useDif`, `dif = max(0.001, 2.0*(val.y*projectionFactor) / val.x)` [S1, unofficial]. Apply smoothing: if `dif > MINK (5.0)`, `dif = mix(dif, 1.0, min(dif-MINK, MAXK-MINK)/(MAXK-MINK))` where `MAXK=20.0` [S1, unofficial].
            *   Compute normal `hitNormal` using `calcNormal(r.d, dif)` [S1, unofficial].
            *   Handle back-face culling: if `dot(n, camDir) > 0`, `n = -n` [S1, unofficial].

3.  **Pass 2: Material Finding (Optional):**
    *   If `_materialOctree` is not NULL, compile and link the pass using `SHADER_MATERIAL_FILE` [S1, unofficial].
    *   Set uniforms: `matOctree` (TEX_NUM_MATOCTREE), `screenRes`, `depth`, `matOctreehalfSide`, `matOctreeCenter`, `matOctreeLevels` [S1, unofficial].
    *   Create a `GL_TEXTURE_BUFFER` backed by a GL buffer containing the material octree's encoded data, bound to `TEX_NUM_MATOCTREE` [S1, unofficial].
    *   *Shader Logic:* The `getMaterial` function in `demo_shading_pass.frag.glsl` traverses the octree to find the material ID for a given position `p` [S1, unofficial].

4.  **Pass 3: Normal Filtering:**
    *   Compile and link the pass using `SHADER_NORMAL_FILTER_FILE` [S1, unofficial].
    *   Define `MSIZE` as `_msize` (default 10) [S1, unofficial].
    *   Set uniform: `inputTex` (TEX_NUM_HITNORM) [S1, unofficial].
    *   Apply bilateral or Gaussian filtering to `_glTexHitNorm` to produce `_glTexHitNormFiltered` [S1, unofficial].

5.  **Pass 4: SSAO (Screen Space Ambient Occlusion):**
    *   Compile and link the pass using `SHADER_SSAO_FILE` [S1, unofficial].
    *   Define `NUM_SAMPLES` as `_ssaoNSamples` (default 32) and `SIDE_NOISE_TEX` as `_ssaoNoiseTexSide` (default 64) [S1, unofficial].
    *   Set uniforms: `hitPosTex` (TEX_NUM_HITPOS), `hitNormTex` (TEX_NUM_HITNORMFILTERED), `depthTex` (TEX_NUM_DEPTH), `noiseTex` (TEX_NUM_AONOISE) [S1, unofficial].
    *   Generate `_ssaoNSamples` 3D samples via `generateSSAOSamples` and upload to `samples` uniform [S1, unofficial].
    *   Generate a noise texture of size `_ssaoNoiseTexSide x _ssaoNoiseTexSide` via `generateNoiseTex` and bind to `TEX_NUM_AONOISE` [S1, unofficial].
    *   *Fragment Shader Logic (`demo_ssao_pass.frag.glsl`):*
        *   Fetch `hitPos`, `hitNorm`, and `hitDepth_cellSize` from textures [S1, unofficial].
        *   Offset hit position: `hitPos += hitNorm * hitDepth_cellSize.y/5.0` [S1, unofficial].
        *   Generate TBN matrix using noise vector `rvec` [S1, unofficial].
        *   Loop `NUM_SAMPLES`:
            *   Transform sample `samp` to world space: `samp = hitPos + (tbn * samples[i]) * radius` [S1, unofficial].
            *   Project to clip space: `offset = projMat * viewMat * vec4(samp, 1.0)` [S1, unofficial].
            *   Normalize to NDC: `offset.xyz /= offset.w`; `offset.xyz = offset.xyz * 0.5 + 0.5` [S1, unofficial].
            *   Fetch sample depth `sampleDepth` from `depthTex` [S1, unofficial].
            *   Calculate range check: `rangeCheck = smoothstep(0.0, 1.0, radius / abs(hitDepth_cellSize.x - sampleDepth))` or binary check [S1, unofficial].
            *   Accumulate occlusion: `occlusion += (sampleDepth < length(camPos - samp) ? 1.0 : 0.0) * rangeCheck` [S1, unofficial].
        *   Output visibility: `outVisibility = (count > 0.0) ? 1.0 - occlusion / count : 1.0` [S1, unofficial].

6.  **Pass 5: Blur:**
    *   Compile and link the pass using `SHADER_BLUR_FILE` [S1, unofficial].
    *   Set uniform: `inputTex` (TEX_NUM_AO) [S1, unofficial].
    *   Apply blur to `_glTexAO` to produce `_glTexAOBlurred` [S1, unofficial].

7.  **Pass 6: Shading:**
    *   Compile and link the pass using `SHADER_SHADING_FILE` [S1, unofficial].
    *   If `_materialOctree` is not NULL, define `USE_MATERIALS` and `NUM_MATERIALS` [S1, unofficial].
    *   Set uniforms: `screenRes`, `hitPosTex` (TEX_NUM_HITPOS), `hitNormTex` (TEX_NUM_HITNORMFILTERED), `shadowsTex` (TEX_NUM_SHADOW), `aoTex` (TEX_NUM_AOBLURRED), `depthTex` (TEX_NUM_DEPTH), `materialTex` (TEX_NUM_MATERIAL) [S1, unofficial].
    *   If materials are used, upload material colors to `materials` uniform [S1, unofficial].
    *   *Fragment Shader Logic (`demo_shading_pass.frag.glsl`):*
        *   Fetch `pos`, `norm`, `shadow`, `ao` from textures [S1, unofficial].
        *   If `pos == vec3(0,0,0)`, return sky color [S1, unofficial].
        *   If `renderMode == 0`:
            *   Determine `diffuseColor`: Default `vec3(0.8, 0.8, 0.8)` [S1, unofficial].
            *   If `useMaterials`, fetch `matID` from `materialTex` and lookup `materials[matID]` [S1, unofficial]. Handle special IDs (255: magenta, else: cyan) [S1, unofficial].
            *   Apply lighting: `color = ...` (diffuse, specular, ambient, shadow, AO) [S1, unofficial].
        *   If `renderMode == 4`, output step count visualization [S1, unofficial].
        *   Else, discard [S1, unofficial].

### Formulas

**Projection Factor:**
$$ \text{projectionFactor} = \frac{\text{inv\_2tan\_half\_fovy}}{\text{screen\_tolerance}} $$
Where:
$$ \text{inv\_2tan\_half\_fovy} = \frac{1.0}{2.0 \times \tan(0.5 \times \text{fovy})} $$
$$ \text{fovy} = 60^\circ = 60 \times \frac{\pi}{180} \text{ radians} $$
$$ \text{screen\_tolerance} = \frac{1.0}{\text{screenRes}[1]} $$
[S1, unofficial]

**Diffuse Factor Smoothing:**
$$ \text{dif} = \max(0.001, \frac{2.0 \times (\text{val.y} \times \text{projectionFactor})}{\text{val.x}}) $$
If $\text{dif} > \text{MINK}$ (5.0):
$$ \text{dif} = \text{mix}(\text{dif}, 1.0, \frac{\min(\text{dif}-\text{MINK}, \text{MAXK}-\text{MINK})}{\text{MAXK}-\text{MINK}}) $$
Where $\text{MAXK} = 20.0$ [S1, unofficial].

**SSAO Visibility:**
$$ \text{outVisibility} = \begin{cases} 1.0 - \frac{\text{occlusion}}{\text{count}} & \text{if count} > 0.0 \\ 1.0 & \text{otherwise} \end{cases} $$
Where $\text{occlusion} = \sum (\text{sampleDepth} < \|\text{camPos} - \text{samp}\| ? 1.0 : 0.0) \times \text{rangeCheck}$ [S1, unofficial].

### Pseudocode

```python
# Custom Pass Rendering Pipeline Implementation

def init_pipeline():
    # Create RendererMonitor instances
    monitors = [RendererMonitor() for _ in range(NUM_PASSES)]
    for m in monitors:
        m.start()
    
    # Setup shader
    shader = FullScreenPass(target=5.0, use_dxc=True)
    shader.include("CustomPassCommon.hlsl")
    shader.include("PseudoRandom.hlsl")
    shader.include("NanoVolumePass.hlsl")
    
    # Setup FBOs
    fbo_depth = create_fbo(attachment=GL_RGBA32F, filter=GL_LINEAR)
    fbo_hit = create_fbo([
        create_attachment(GL_RGB32F, GL_NEAREST, "hitPos"),
        create_attachment(GL_RGB32F, GL_NEAREST, "hitNorm")
    ])
    fbo_material = create_fbo(attachment=GL_R8UI, filter=GL_NEAREST) if use_materials else None
    fbo_norm_filtered = create_fbo(attachment=GL_RGB32F, filter=GL_NEAREST)
    fbo_shadow = create_fbo(attachment=GL_R32F, filter=GL_NEAREST)
    fbo_ao = create_fbo(attachment=GL_R32F, filter=GL_NEAREST)
    fbo_ao_blurred = create_fbo(attachment=GL_R32F, filter=GL_NEAREST)
    
    # Setup textures and buffers
    tex_depth = fbo_depth.color_attachment
    tex_hit_pos = fbo_hit.color_attachments[0]
    tex_hit_norm = fbo_hit.color_attachments[1]
    tex_norm_filtered = fbo_norm_filtered.color_attachment
    tex_shadow = fbo_shadow.color_attachment
    tex_ao = fbo_ao.color_attachment
    tex_ao_blurred = fbo_ao_blurred.color_attachment
    
    if use_materials:
        tex_material = fbo_material.color_attachment
        mat_octree_buffer = create_texture_buffer(material_octree_data)

def pass_pos_norm():
    # Bind FBO[1]
    bind_fbo(fbo_hit)
    
    # Set uniforms
    set_uniform("screenRes", screen_res)
    set_uniform("depth", tex_depth)
    set_uniform("projectionFactor", calculate_projection_factor())
    
    # Execute shader
    execute_shader("SHADER_POS_NORM_FILE")
    
    # Shader logic (simplified):
    # 1. Load depth at current pixel
    # 2. Compute camera ray
    # 3. Trace volume (NanoVolumePass) or compute hit via depth
    # 4. Write hitPos and hitNorm to attachments

def pass_material():
    if not use_materials:
        return
    
    bind_fbo(fbo_material)
    set_uniform("matOctree", mat_octree_buffer)
    set_uniform("screenRes", screen_res)
    set_uniform("depth", tex_depth)
    set_uniform("matOctreehalfSide", mat_octree_half_side)
    set_uniform("matOctreeCenter", mat_octree_center)
    set_uniform("matOctreeLevels", mat_octree_levels)
    
    execute_shader("SHADER_MATERIAL_FILE")

def pass_normal_filter():
    bind_fbo(fbo_norm_filtered)
    set_uniform("inputTex", tex_hit_norm)
    set_uniform("MSIZE", _msize)
    
    execute_shader("SHADER_NORMAL_FILTER_FILE")

def pass_ssao():
    bind_fbo(fbo_ao)
    
    # Generate samples and noise
    samples = generate_ssao_samples(_ssaoNSamples)
    noise_tex = generate_noise_tex(_ssaoNoiseTexSide)
    
    set_uniform("hitPosTex", tex_hit_pos)
    set_uniform("hitNormTex", tex_norm_filtered)
    set_uniform("depthTex", tex_depth)
    set_uniform("noiseTex", noise_tex)
    set_uniform("samples", samples)
    set_uniform("radius", _ssaoRadius)
    set_uniform("NUM_SAMPLES", _ssaoNSamples)
    set_uniform("SIDE_NOISE_TEX", _ssaoNoiseTexSide)
    
    execute_shader("SHADER_SSAO_FILE")

def pass_blur():
    bind_fbo(fbo_ao_blurred)
    set_uniform("inputTex", tex_ao)
    
    execute_shader("SHADER_BLUR_FILE")

def pass_shading():
    bind_fbo(fbo_depth) # Or final output FBO
    
    set_uniform("screenRes", screen_res)
    set_uniform("hitPosTex", tex_hit_pos)
    set_uniform("hitNormTex", tex_norm_filtered)
    set_uniform("shadowsTex", tex_shadow)
    set_uniform("aoTex", tex_ao_blurred)
    set_uniform("depthTex", tex_depth)
    
    if use_materials:
        set_uniform("materialTex", tex_material)
        set_uniform("materials", material_colors)
        define("USE_MATERIALS")
        define("NUM_MATERIALS", len(material_colors))
    
    execute_shader("SHADER_SHADING_FILE")

def calculate_projection_factor():
    fovy_rad = 60.0 * 3.14159 / 180.0
    inv_2tan_half_fovy = 1.0 / (2.0 * tan(0.5 * fovy_rad))
    screen_tolerance = 1.0 / screen_res[1]
    return inv_2tan_half_fovy / screen_tolerance
```

### Edge Cases and Pitfalls
*   **Precision:** Depth values are stored in `GL_RGBA32F` for FBO[0] and `GL_R32F` for others. Ensure sufficient precision for large scenes to avoid z-fighting or incorrect ray intersections [S1, unofficial].
*   **Boundaries:** The SSAO pass discards fragments where `hitPos == vec3(0,0,0)` (background) [S1, unofficial]. Ensure background pixels are handled correctly in subsequent passes.
*   **Degenerate Input:** If `_materialOctree` is NULL, the material pass is skipped, and `USE_MATERIALS` should not be defined to avoid shader compilation errors [S1, unofficial].
*   **Stereo Rendering:** The Unity implementation uses `UNITY_SETUP_STEREO_EYE_INDEX_POST_VERTEX` to handle stereo eyes [S2, unofficial]. Ensure the pipeline is compatible with the target rendering API's stereo support.
*   **Filtering:** Normal filtering uses a kernel size `MSIZE`. Ensure `MSIZE` is odd and appropriate for the resolution to avoid excessive blurring or aliasing [S1, unofficial].

## Subtopics

### NanoVolume Pass
The core volume rendering function that traces rays through the NanoVDB structure. It is responsible for computing the initial hit position and normal. It is distinct from other ray marching methods by its use of the NanoVDB format and optimized traversal [S2, unofficial].

### Material Octree Traversal
A specialized pass that looks up material IDs from a material octree. It is chosen when material-based shading is required. It differs from simple color lookup by using a hierarchical structure for efficient access [S1, unofficial].

### SSAO Pass
Computes screen-space ambient occlusion using a set of pre-generated samples and a noise texture. It is chosen for adding depth cues to flat-looking volumes. It differs from other AO methods by its reliance on screen-space depth and normal information [S1, unofficial].

### Normal Filtering
A bilateral or Gaussian filter applied to the computed normals to reduce noise. It is chosen when the raw normals from ray casting are too jagged. It differs from simple blurring by preserving edges [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The pipeline is $O(N)$ per pixel, where $N$ is the number of passes (typically 6-7). Each pass is a fullscreen pass, so the total time is proportional to the screen resolution multiplied by the number of passes. The ray tracing pass complexity depends on the volume traversal depth, which is generally logarithmic with respect to the volume size for tree-based structures [S1, S2, unofficial].
*   **Memory Complexity:** The pipeline requires memory for 7 FBOs. For a $1920 \times 1080$ screen, this is approximately $7 \times 1920 \times 1080 \times 4$ bytes (for 32F textures) $\approx 64$ MB, plus additional memory for the NanoVDB structure and material octree [S1, unofficial].
*   **Measured Performance:** Performance depends heavily on the hardware and the complexity of the volume. The use of `#pragma target 5.0` and `#pragma use_dxc` suggests optimization for modern GPUs [S2, unofficial]. The SSAO pass with 32 samples per pixel can be a bottleneck [S1, unofficial].
*   **Scaling:** The pipeline scales linearly with screen resolution. The volume traversal complexity scales with the depth of the octree, which is typically shallow for well-structured data [S1, unofficial].
*   **Strengths:** Modular design allows for easy addition/removal of effects (SSAO, shadows). Efficient memory access patterns due to FBO separation. Support for material-based shading.
*   **Limitations:** High memory usage due to multiple FBOs. Latency introduced by multiple passes. Dependency on specific shader features (DXC, GLSL 440) [S1, S2, unofficial].
*   **When to Use:** High-quality visualization of large volumetric datasets where post-processing effects are desired.
*   **When Not to Use:** Real-time applications with strict memory constraints or low-end hardware. Simple volume rendering without complex lighting.

## Background
Custom Pass Rendering originated from the SSVDAG (Sparse Sparse Volume Data Access Graph) project and was adapted for Unity via the NanoVolume Custom Pass Rendering implementation [S1, S2, unofficial]. The SSVDAG project, by ajaspe, focuses on efficient rendering of sparse volumetric data using DAG-based structures [S1, unofficial]. The Unity implementation, by andersblomqvist, integrates NanoVDB (a compressed, GPU-friendly format for OpenVDB data) into Unity's High Definition Render Pipeline (HDRenderPipeline) [S2, unofficial]. The pipeline was developed to address the limitations of traditional ray marching in terms of performance and flexibility, allowing for complex lighting and material effects [S1, S2, unofficial]. It is used in scientific visualization and high-end rendering applications [S1, S2, unofficial].
