# CPU-Based Splat Sorting

Also called: Splat Sort, WebWorker Splat Sort

## Overview
CPU-Based Splat Sorting is a method for ordering 3D Gaussian splats for correct front-to-back alpha blending by performing the sort operation on the CPU, often asynchronously in a background thread [S1, unofficial]. It solves the problem of rendering order dependency in transparent splatting without incurring the high latency and complexity of GPU-based sorting algorithms like bitonic sort [S1, unofficial]. It differs from GPU sorting by offloading the $O(N \log N)$ comparison work to the CPU, allowing the GPU to focus exclusively on rendering, and from depth-based sorting variants by relying on a simple depth projection rather than complex opacity-weighted keys [S2, unofficial].

## How it works
The method computes a depth value for each splat, sorts the splats by this depth, and outputs a permutation index buffer for the GPU to read [S2, unofficial].

**Inputs:**
- `viewProj`: A $4 \times 4$ view-projection matrix [S2, unofficial].
- `positions`: An array of $N$ 3D positions (interleaved $x, y, z$ floats) [S2, unofficial].
- `vertexCount`: The number of splats $N$ [S2, unofficial].

**Outputs:**
- `depthIndex`: A vector of $N$ unsigned integers representing the original indices of the splats, sorted from front (smallest depth) to back (largest depth) [S2, unofficial].

**Data Structures:**
- `SplatSortEntry`: A struct or pair containing:
  - `depth`: A float representing the projected depth [S2, unofficial].
  - `original_index`: A uint32_t representing the index in the original `positions` array [S2, unofficial].

**Steps:**
1.  **Project Depth:** For each splat $i$ from $0$ to $N-1$:
    - Retrieve the 3D position $P_i = (x_i, y_i, z_i)$ from `positions`.
    - Compute the homogeneous clip-space position:
      $$ V = \text{viewProj} \times \begin{bmatrix} x_i \\ y_i \\ z_i \\ 1 \end{bmatrix} $$
    - Extract the depth:
      $$ d_i = \frac{V_z}{V_w} $$
    - Store the pair $(d_i, i)$ in a temporary list [S2, unofficial].

2.  **Sort:** Sort the list of pairs based on $d_i$ in ascending order (smallest $d_i$ first) [S2, unofficial].

3.  **Extract Indices:** Create the output `depthIndex` vector by extracting the `original_index` from each pair in the sorted list [S2, unofficial].

**Pseudocode:**
```python
def cpu_splat_sort(view_proj_matrix, positions, vertex_count):
    """
    Sorts splats by depth on the CPU.
    
    Args:
        view_proj_matrix: 4x4 matrix (list of lists or array)
        positions: List of tuples (x, y, z)
        vertex_count: Integer N
        
    Returns:
        sorted_indices: List of integers
    """
    # Step 1: Compute depth for each splat
    splat_data = []
    for i in range(vertex_count):
        x, y, z = positions[i]
        
        # Homogeneous transformation
        # Assuming row-major matrix multiplication: V = M * P
        # P is column vector [x, y, z, 1]
        wx = view_proj_matrix[0][0]*x + view_proj_matrix[1][0]*y + view_proj_matrix[2][0]*z + view_proj_matrix[3][0]
        wy = view_proj_matrix[0][1]*x + view_proj_matrix[1][1]*y + view_proj_matrix[2][1]*z + view_proj_matrix[3][1]
        wz = view_proj_matrix[0][2]*x + view_proj_matrix[1][2]*y + view_proj_matrix[2][2]*z + view_proj_matrix[3][2]
        ww = view_proj_matrix[0][3]*x + view_proj_matrix[1][3]*y + view_proj_matrix[2][3]*z + view_proj_matrix[3][3]
        
        # Perspective divide
        depth = wz / ww
        
        splat_data.append((depth, i))
        
    # Step 2: Sort by depth (ascending)
    # Using a stable sort is not strictly required but often preferred for consistency
    splat_data.sort(key=lambda item: item[0])
    
    # Step 3: Extract indices
    sorted_indices = [item[1] for item in splat_data]
    
    return sorted_indices
```

**Parameters:**
- Typical implementation runs asynchronously in a WebWorker [S1, unofficial].
- No specific kernel parameters are required as it relies on standard projection [S2, unofficial].

**Edge Cases and Pitfalls:**
- **Rapid Camera Movement:** If the camera jumps between opposite sides of the scene, the Z-order may not update fast enough relative to the render loop, causing momentary transparency artifacts [S1, unofficial].
- **Precision:** Standard float precision is used for depth calculation [S2, unofficial].
- **Performance:** Sorting ~1M splats takes approximately 150ms on a typical CPU [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N \log N)$ for comparison-based sorting (e.g., Quicksort/Mergesort) [S1, unofficial].
- **Measured Performance:** Sorting ~1M splats takes ~150ms, resulting in a sort rate of approximately 4fps, while the main render runs at 60fps [S1, unofficial].
- **Memory Complexity:** $O(N)$ to store the depth-index pairs and the output index buffer [S2, unofficial].
- **Strengths:** Allows the GPU to focus entirely on rendering, avoiding the latency overhead of GPU sorting algorithms like bitonic sort which require many iterations [S1, unofficial].
- **Limitations:** The CPU sort is significantly slower than the GPU render loop (4fps vs 60fps), leading to potential visual artifacts during rapid camera transitions [S1, unofficial].
- **When to use:** When GPU sorting is unavailable, too complex to implement, or when the CPU is underutilized and can handle the asynchronous sort without blocking the render thread [S1, unofficial].

## Background
The method was popularized in the context of web-based 3D Gaussian Splatting implementations, where file size reduction and browser compatibility are critical [S1, unofficial]. It was adopted as a fallback or primary strategy when GPU-based sorting (like bitonic sort) was deemed too heavy or when simpler transparency methods like stochastic transparency or weighted blended order-independent transparency failed to produce satisfactory results [S1, unofficial].
