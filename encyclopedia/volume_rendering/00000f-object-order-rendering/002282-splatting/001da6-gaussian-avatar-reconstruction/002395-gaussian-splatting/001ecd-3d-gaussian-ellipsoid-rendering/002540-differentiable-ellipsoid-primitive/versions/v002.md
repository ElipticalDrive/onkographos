# Differentiable Ellipsoid Primitive

Also called: Sigmoid-based ellipsoidal primitive

## Overview
The Differentiable Ellipsoid Primitive is a geometric representation used in volume rendering that replaces long-tailed Gaussian kernels with constant-density ellipsoidal shapes to reduce spatial overlap and memory usage [S1, unofficial]. It addresses the non-differentiability of hard-boundary ellipsoids by employing a sigmoid-based formulation, allowing for stable gradient-based optimization against 3D intensity fields [S1, unofficial]. Unlike its sibling [Ever Rendering](3814-ever-rendering.md), which relies on ray-based accumulation to implicitly soften boundaries, this method ensures the primitive itself is fully differentiable, making it suitable for direct volumetric training [S1, unofficial].

## How it works
The method defines a primitive using a center intensity, a mean position, and a covariance matrix, modulated by a sharpness parameter [S1, unofficial].

**Inputs and Outputs:**
*   **Inputs:** Primitive parameters $\mu \in \mathbb{R}^3$ (center), $\Sigma \in \mathbb{R}^{3 \times 3}$ (covariance), $I \in \mathbb{R}$ (center intensity), and $k \in \mathbb{R}$ (sharpness). Query point $x \in \mathbb{R}^3$ [S1, unofficial].
*   **Output:** Scalar intensity value $\tilde{P}(x)$ [S1, unofficial].

**Data Structures:**
Each primitive stores:
1.  $\mu$: 3D vector [S1, unofficial].
2.  $\Sigma$: $3 \times 3$ symmetric positive-definite matrix [S1, unofficial].
3.  $I$: Scalar intensity [S1, unofficial].
4.  $k$: Scalar sharpness (typically fixed) [S1, unofficial].

**Formulas:**
Let $d = x - \mu$ be the displacement vector from the center [S1, unofficial]. The unnormalized primitive profile is defined as:
$$ P(x) = I \cdot \sigma(k \cdot (1 - d^T \Sigma^{-1} d)) $$
where $\sigma(z) = \frac{1}{1 + e^{-z}}$ is the sigmoid function [S1, unofficial].

To decouple peak intensity from the sharpness parameter $k$, the primitive is normalized:
$$ \tilde{P}(x) = \frac{P(x)}{P(\mu)} = I \cdot \frac{\sigma(k \cdot (1 - d^T \Sigma^{-1} d))}{\sigma(k)} $$
This normalization ensures that the peak intensity at the center ($d=0$) remains exactly $I$, regardless of $k$ [S1, unofficial].

**Parameters:**
*   $k$: Controls boundary sharpness. A fixed hyperparameter is used in practice for efficiency [S1, unofficial].
*   Typical values: Lower values cause peak intensity reduction in the unnormalized case; higher values increase boundary sharpness [S1, unofficial].

**Steps:**
1.  Compute displacement $d = x - \mu$ [S1, unofficial].
2.  Compute quadratic form $q = d^T \Sigma^{-1} d$ [S1, unofficial].
3.  Compute unnormalized sigmoid value $s = \sigma(k \cdot (1 - q))$ [S1, unofficial].
4.  Compute normalization factor $n = \sigma(k)$ [S1, unofficial].
5.  Return $\tilde{P}(x) = I \cdot (s / n)$ [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Peak Intensity Deviation:** If $k$ is small and the primitive is not normalized, the peak intensity at the center decreases, deviating from the desired unit response [S1, unofficial].
*   **Truncation Artifacts:** When using a fixed cutoff for rendering or voxelization, the spatial support varies with $k$. The cutoff region must be adjusted according to $k$ to avoid truncation artifacts [S1, unofficial].
*   **Non-differentiability of Hard Boundaries:** Using the indicator function form (as in EVER) results in vanishing gradients during optimization [S1, unofficial].

**Pseudocode:**
```python
import math

def sigmoid(z):
    """Standard sigmoid function."""
    return 1.0 / (1.0 + math.exp(-z))

def differentiable_ellipsoid_primitive(x, mu, Sigma_inv, I, k):
    """
    Computes the normalized intensity of a differentiable ellipsoid primitive at point x.
    
    Args:
        x: Query point (3,)
        mu: Primitive center (3,)
        Sigma_inv: Inverse covariance matrix (3x3)
        I: Center intensity (scalar)
        k: Sharpness parameter (scalar)
        
    Returns:
        Normalized intensity value (scalar)
    """
    # 1. Compute displacement
    d = x - mu
    
    # 2. Compute quadratic form d^T Sigma^{-1} d
    q = d @ Sigma_inv @ d
    
    # 3. Compute unnormalized sigmoid argument
    arg = k * (1.0 - q)
    
    # 4. Compute unnormalized value
    s_unnorm = sigmoid(arg)
    
    # 5. Compute normalization factor sigma(k)
    norm_factor = sigmoid(k)
    
    # 6. Return normalized intensity
    return I * (s_unnorm / norm_factor)
```

## Subtopics

### 3D Intensity Field Fitting
A training stage that optimizes ellipsoidal primitive parameters to fit a volumetric intensity field, storing center intensity $I$ and geometric parameters $(\mu, \Sigma)$ [S1, unofficial]. It differs from view-dependent color learning (e.g., 3DGS) by directly modeling the per-voxel scalar value of the original volume [S1, unofficial].
*   **Definition:** Optimizes primitives to predict voxel intensity $\hat{V}(x)$ by summing normalized primitive profiles [S1, unofficial].
*   **Formula:** The predicted voxel intensity is $\hat{V}(x) = \sum_{i \in N} \tilde{P}_i(x) = \sum_{i \in N} I_i \frac{\sigma(k(1 - d_i^\top \Sigma_i^{-1} d_i))}{\sigma(k)}$, where $N$ is the set of primitives contributing at $x$ [S1, unofficial].
*   **Steps:**
    1.  Subsample a ground truth subvolume $V_{gt} \in \mathbb{R}^{s \times s \times s}$ from the GT volume at each iteration [S1, unofficial].
    2.  Align primitive coordinates to the GT volume coordinates [S1, unofficial].
    3.  Voxelize only the overlapping region to obtain the prediction subvolume $\hat{V}$ [S1, unofficial].
    4.  Compute loss $L_{\text{rec}} = \beta L_1 + (1 - \beta) L_{\text{D-SSIM}}$ with $\beta \in [0, 1]$ [S1, unofficial].
*   **When to choose:** Use when training against a known 3D intensity field (e.g., medical volumes, scientific data) rather than multi-view images [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Rendering/voxelization depends on the number of primitives $N$ and the spatial support. The ellipsoidal shape reduces spatial footprint by up to $9\times$ compared to Gaussian $3\sigma$ support, reducing overlap and computational cost [S1, unofficial].
*   **Memory Complexity:** Reduced memory usage due to smaller spatial overlap and constant-density representation [S1, unofficial].
*   **Performance:** Using $k$ as a fixed hyperparameter improves efficiency. Making $k$ learnable per primitive improves quality but adds overhead and reduces speed [S1, unofficial].
*   **Strengths:** Fully differentiable primitive enables stable training against 3D intensity fields; reduced spatial overlap compared to Gaussians [S1, unofficial].
*   **Limitations:** Requires careful adjustment of cutoff regions to avoid truncation artifacts; fixed $k$ may limit adaptability compared to learnable $k$ [S1, unofficial].
*   **When to use:** Scalable learning on volumes exceeding GPU memory; scenarios requiring direct volumetric optimization [S1, unofficial].
*   **When not to use:** When ray-based accumulation is preferred (see [Ever Rendering](3814-ever-rendering.md)); when extreme adaptability of boundary sharpness is required and speed is not a concern [S1, unofficial].

## Background
The method originates from the ESVR (3D Ellipsoid-based Sparse Volume Rendering) framework [S1, unofficial]. It was developed to address the excessive spatial overlap and high memory usage caused by long-tailed Gaussian primitives in volume rendering [S1, unofficial]. The approach is inspired by EVER [29], which uses indicator functions for ellipsoidal boundaries, but adapts it for differentiable volumetric optimization by replacing the hard boundary with a sigmoid function [S1, unofficial].
