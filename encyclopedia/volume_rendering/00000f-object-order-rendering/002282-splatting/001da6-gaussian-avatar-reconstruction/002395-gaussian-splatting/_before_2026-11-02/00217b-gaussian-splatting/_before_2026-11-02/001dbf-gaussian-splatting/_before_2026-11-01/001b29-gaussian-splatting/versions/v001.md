# Gaussian Splatting

Also called: 3D Gaussian Splatting, 3DGS, 3DGS representation, EWA Volume Splatting, Elliptical Weighted Average splatting, Gaussian Splat, Volume Splatting

## Overview
Gaussian Splatting is an object-order direct volume rendering algorithm that represents a scene as a collection of overlapping 3D Gaussian primitives, projecting them onto the image plane and alpha-compositing them to generate the final image [S2, S4]. It serves as a fast, high-quality alternative to Neural Radiance Fields (NeRF) by leveraging volumetric rendering principles to preserve differentiability while employing point-based rasterization for efficient training and rendering [S1, S4]. Unlike traditional opacity-based splatting, 3DGS assigns a single opacity value per primitive, allowing for constant transparency regardless of viewing direction and enabling the optimization of a well-behaved, bounded scalar [S1]. It builds on [EWA Splatting](1069-ewa-splatting.md) but simplifies the formulation by ignoring self-attenuation and approximating perspective projection [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $M$ 3D Gaussians $\{g_i\}_{i=1}^M$, where each $g_i$ is defined by center $\boldsymbol{\mu}_i$, covariance $\boldsymbol{\Sigma}_i$, opacity $\sigma_i$, and color $c_i$; a camera with intrinsics $K$ and extrinsics $W$; and image dimensions.
*   **Output:** A 2D image $I$ of size $H \times W$.

**Data Structures:**
Each Gaussian splat stores the following fields [S3, S4]:
*   `pos`: $\boldsymbol{\mu}_i \in \mathbb{R}^3$, center position in world space.
*   `scale`: $s \in \mathbb{R}^3$, size along each local axis (stored in log space).
*   `rot`: $q \in \mathbb{R}^4$, orientation as a unit quaternion.
*   `color`: $c_i \in \mathbb{R}^3$, RGB color. In the standard format, this is decoded from spherical harmonic (SH) coefficients. Band-0 SH coefficients $f_{dc} \in \mathbb{R}^3$ are converted to RGB using $C_0 = \frac{1}{2\sqrt{\pi}} \approx 0.282$ [S3]:
    $$ \text{color} = \text{clamp}(0.5 + C_0 \cdot f_{dc}, 0, 1) $$
*   `opacity`: $\sigma_i \in \mathbb{R}$, opacity in $[0, 1]$ (stored as a logit).

The 3D covariance matrix $\boldsymbol{\Sigma}_i$ is parameterized via diagonalization $\boldsymbol{\Sigma}_i = V S V^T$, where $S = \text{diag}(e^{s_1}, e^{s_2}, e^{s_3})$ and $V$ is the rotation matrix derived from the quaternion $q$ [S4].

**Rendering Pipeline:**
The rendering process follows these steps [S4]:

1.  **Projection:** For each Gaussian $i$, compute the 2D screen-space covariance matrix $\tilde{\boldsymbol{\Sigma}}_i$. First, transform the 3D covariance to camera coordinates: $\boldsymbol{\Sigma}'_i = W \boldsymbol{\Sigma}_i W^T$. Then, approximate the perspective projection $P_K$ around the Gaussian center $\boldsymbol{\mu}_i$ using its Jacobian $\mathbf{J} \in \mathbb{R}^{2\times3}$ [S4]:
    $$ P_K(\mathbf{x}) \approx P_K(\boldsymbol{\mu}_i) + \mathbf{J}(\mathbf{x} - \boldsymbol{\mu}_i) $$
    The projected 2D covariance is:
    $$ \tilde{\boldsymbol{\Sigma}}_i = \mathbf{J} \boldsymbol{\Sigma}'_i \mathbf{J}^T $$
    The projected mean is $\tilde{\boldsymbol{\mu}}_i = P_K(\boldsymbol{\mu}_i)$.

2.  **Rasterization (Splatting):** For each pixel $p$ in the image, identify the set of $K$ Gaussians whose projected footprints cover $p$. This is typically done using a tile-based rasterization strategy [S4]. For each covering Gaussian, evaluate the 2D Gaussian value at pixel $p$:
    $$ \tilde{G}_i(p) = \exp\left(-\frac{1}{2}(p - \tilde{\boldsymbol{\mu}}_i)^T \tilde{\boldsymbol{\Sigma}}_i^{-1} (p - \tilde{\boldsymbol{\mu}}_i)\right) $$

3.  **Sorting:** Sort the $K$ Gaussians intersecting the view ray for pixel $p$ by distance from their centers to the camera position (back-to-front order) [S4]. Note: This sorting is based on centers, which is an approximation [S1].

4.  **Alpha-Compositing:** Compute the final pixel intensity $I_f$ by alpha-compositing the sorted Gaussians [S4]:
    $$ I_f = \sum_{i=1}^N c_i \tilde{\sigma}_i \tilde{G}_i(p) \prod_{j=1}^{i-1} \left(1 - \tilde{\sigma}_j \tilde{G}_j(p)\right) $$
    where $N$ is the number of sorted Gaussians, $\tilde{\sigma}_i = \sigma_i$, and $\tilde{G}_i(p)$ is the Gaussian value at $p$.

**Training and Optimization:**
The scene parameters $\theta$ (the set of Gaussians) are optimized by minimizing the photometric loss between the rendered image $I_{\theta,i}$ and the input view $I_i$ [S4]:
$$ \mathcal{L}(\theta) = \frac{1}{N} \sum_{i=1}^N \| I_{\theta,i} - I_i \|^2 $$
Gradients are backpropagated to update Gaussian parameters using Adam [S4]. During training, the number of Gaussians is dynamically adjusted: splitting large Gaussians, cloning those that underfit detail, and pruning those with low opacity [S4].

**Pseudocode:**
```python
def render_gaussian_splats(gaussians, camera, image_width, image_height):
    # Initialize output image
    image = zeros((image_height, image_width, 3))
    
    # Precompute camera matrices
    W = camera.extrinsics # 4x4 pose matrix
    K = camera.intrinsics # 3x3 intrinsic matrix
    
    # Project all Gaussians to 2D
    projected_gaussians = []
    for g in gaussians:
        # 1. Compute 3D covariance from scale and rotation
        S = diag(exp(g.scale))
        V = quaternion_to_rotation_matrix(g.rot)
        Sigma_3d = V @ S @ V.T
        
        # 2. Transform to camera space
        Sigma_cam = W[:3, :3] @ Sigma_3d @ W[:3, :3].T
        
        # 3. Compute Jacobian of perspective projection at Gaussian center
        # P_K(x) = K * (R*x + t) / z
        # Jacobian J depends on camera pose and center position
        mu_cam = W[:3, :3] @ g.pos + W[:3, 3]
        z = mu_cam[2]
        J = compute_projection_jacobian(K, mu_cam) # 2x3 matrix
        
        # 4. Project covariance
        Sigma_2d = J @ Sigma_cam @ J.T
        
        # 5. Project center
        mu_2d = K @ mu_cam
        mu_2d = mu_2d[:2] / mu_2d[2] # Normalize by z
        
        # 6. Compute bounding box for rasterization
        # Use 3-sigma extent for bounding box
        sqrt_Sigma_2d = sqrt_eigenvalues(Sigma_2d)
        bbox = compute_bbox(mu_2d, sqrt_Sigma_2d)
        
        projected_gaussians.append({
            'mu_2d': mu_2d,
            'Sigma_2d': Sigma_2d,
            'sigma': g.opacity,
            'color': decode_sh(g.color_coeffs), # Decode SH to RGB
            'bbox': bbox,
            'depth': z
        })
    
    # Rasterize
    for g_proj in projected_gaussians:
        # Clip bbox to image bounds
        x_min, y_min, x_max, y_max = clip_bbox(g_proj['bbox'], image_width, image_height)
        
        for y in range(y_min, y_max):
            for x in range(x_min, x_max):
                p = vec2(x, y)
                # Evaluate 2D Gaussian
                diff = p - g_proj['mu_2d']
                G_val = exp(-0.5 * diff.T @ inverse(g_proj['Sigma_2d']) @ diff)
                
                # Accumulate color with alpha blending
                # Note: Standard 3DGS rasterizers sort by depth and composite
                # This simplified loop assumes no overlap or uses a simple add
                # For correct alpha compositing, a depth-sorted pass is required
                # Here we approximate with simple accumulation for brevity
                # In practice, use a tile-based sorter and compositing kernel
                alpha = g_proj['sigma'] * G_val
                image[y, x] += g_proj['color'] * alpha
                # Note: This simple accumulation does not handle transparency correctly
                # without proper sorting and compositing.
    
    # Correct compositing requires sorting and back-to-front blending
    # See Subtopics for optimized rasterization details
    return image
```
*Note: The pseudocode above is a simplified illustration. Correct implementation requires depth sorting per pixel or tile-based sorting and proper alpha-compositing as described in the steps [S4].*

## Subtopics

### [Ray-marching on 3D Gaussians](1036-ray-marching-on-3d-gaussians.md)
A ray-marching algorithm implemented on 3D Gaussians to study the impact of approximations like spatial overlap and sorting in 3DGS.

### [EWA Splatting](1069-ewa-splatting.md)
A rendering technique that treats each point as a Gaussian reconstruction kernel on the surface, projects it into screen space, and convolves it with a low-pass filter to produce a resampling filter actually rasterized. This implementation uses a simplified kernel: screen-aligned spherical impostors with isotropic linear falloff, rasterized as plain point sprites, trading anisotropic, correctly band-limited footprint for a formulation needing no per-point normals or radii.

### [Self-Attenuation Rendering](1154-self-attenuation-rendering.md)
A rendering approach that correctly accounts for the attenuation of a Gaussian's own extinction along the ray path (self-attenuation), rather than ignoring it or using a first-order Taylor approximation.

### [Row-constant hoisting for Gaussian Splatting Rasterization](1195-row-constant-hoisting-for-gaussian-splatting-rasterization.md)
An optimization for the inner pixel loop of a Gaussian splatting rasterizer that hoists row-constant terms outside the inner (column) loop to minimize arithmetic operations per pixel.

### [2D Gaussian Projection with Covariance Stabilization](1198-2d-gaussian-projection-with-covariance-stabilization.md)
Computes the 2D screen-space covariance matrix and its inverse for a 3D Gaussian splat, ensuring numerical stability by adding a small epsilon to the diagonal to guarantee positive definiteness.

## Operating characteristics
**Time and Memory Complexity:**
*   **Memory:** Complex scenes require approximately 200,000–500,000 Gaussians, resulting in significant memory and storage demands [S4]. Each Gaussian stores position, scale, rotation, SH coefficients, and opacity.
*   **Time:** Rendering is $O(M \cdot A)$, where $M$ is the number of Gaussians and $A$ is the average number of splats per pixel. Training is computationally intensive due to the need for gradient computation through the rasterization process.

**Performance:**
*   3DGS enables real-time rendering capabilities for novel view synthesis [S4].
*   It is significantly faster than NeRFs for rendering, as it avoids the need for volumetric ray marching and MLP evaluation [S4].

**Strengths and Limitations:**
*   **Strengths:** High-quality view synthesis, real-time rendering, differentiable optimization [S1, S4].
*   **Limitations:** High memory footprint [S4]. The emission-absorption model limits performance on highly reflective surfaces and prevents relighting [S4]. Standard 3DGS uses a dilation-based filter which fails to suppress high-frequency artifacts when varying focal length or camera distance [S4]. Approximations in visibility resolution (sorting by centers) can cause popping artifacts [S1]. Self-attenuation is not treated correctly [S1].

**When to Use:**
*   Use for real-time novel view synthesis of static scenes with moderate complexity.
*   Avoid for scenes with highly reflective surfaces or when relighting is required [S4].

## Background
3D Gaussian Splatting (3DGS) was introduced by Kerbl et al. in 2023 [S4]. It builds on EWA Volume Splatting [S1, S4] and other point-based rendering works [S4]. The method was developed to overcome the computational cost of evaluating the volume rendering equation via quadrature, which requires querying points outside Gaussian supports [S4]. It provides a fast, high-quality alternative to NeRF by using a hybrid, primitive-based rendering method [S1].
