# Projection Jacobian Computation

Also called: perspective projection Jacobian

## Overview
Computes the $2 \times 3$ Jacobian matrix of the perspective projection function with respect to 3D coordinates, used for linearizing the projection of 3D Gaussians into screen space [S1, unofficial]. It transforms the 3D covariance structure into 2D screen-space covariance, enabling accurate Gaussian splatting [S1, unofficial]. It is distinguished from sibling methods by its focus on the analytical derivative of the projection transform itself, whereas [Optimal Gaussian Splatting Projection](3311-optimal-gaussian-splatting-projection.md) focuses on the resulting covariance matrix properties and [Adaptive Bounding Box Computation](1206-adaptive-bounding-box-computation.md) focuses on rasterization coverage [S1, unofficial].

## How it works
**Inputs:**
- `means_3D`: Tensor of shape $(N, 3)$ containing 3D Gaussian centers in world space.
- `camera`: Camera object providing view transformation and focal lengths.
- `img_size`: Tuple $(W, H)$ representing image width and height.

**Outputs:**
- `J`: Tensor of shape $(N, 2, 3)$ containing the Jacobian matrix for each Gaussian.

**Data Structures:**
- `means_view_space`: Tensor of shape $(N, 3)$, view-space coordinates $(t_x, t_y, t_z)$.
- `J`: Tensor of shape $(N, 2, 3)$, initialized to zeros.

**Steps:**
1.  **Validate Camera:** Check if the camera is in NDC (Normalized Device Coordinates) mode. If `camera.in_ndc()` is true, raise a `RuntimeError`. The method assumes standard perspective projection parameters [S1, unofficial].
2.  **Extract Parameters:**
    -   Get focal lengths: $f_x, f_y = \text{camera.focal\_length.flatten()}$.
    -   Get image dimensions: $W, H = \text{img\_size}$.
3.  **Transform to View Space:**
    -   Apply view transformation to 3D means: $\text{means\_view\_space} = \text{view\_transform.transform\_points}(\text{means\_3D})$.
    -   Extract components: $t_x = \text{means\_view\_space}[:, 0]$, $t_y = \text{means\_view\_space}[:, 1]$, $t_z = \text{means\_view\_space}[:, 2]$.
    -   Compute squared depth: $t_z^2 = t_z \cdot t_z$.
4.  **Compute FOV Limits:**
    -   Calculate half-tangent of field of view:
        $$ \text{half\_tan\_fov\_x} = 0.5 \cdot \frac{W}{f_x} $$
        $$ \text{half\_tan\_fov\_y} = 0.5 \cdot \frac{H}{f_y} $$
    -   Apply safety margin (typically 1.3) to define clamping limits:
        $$ \text{lim\_x} = 1.3 \cdot \text{half\_tan\_fov\_x} $$
        $$ \text{lim\_y} = 1.3 \cdot \text{half\_tan\_fov\_y} $$
5.  **Clamp Normalized Coordinates:**
    -   To prevent division by zero or extreme values near frustum edges, clamp the normalized coordinates $(t_x/t_z, t_y/t_z)$ before scaling back:
        $$ t_x^{\text{clamp}} = \text{clamp}\left(\frac{t_x}{t_z}, -\text{lim\_x}, \text{lim\_x}\right) \cdot t_z $$
        $$ t_y^{\text{clamp}} = \text{clamp}\left(\frac{t_y}{t_z}, -\text{lim\_y}, \text{lim\_y}\right) \cdot t_z $$
    -   Use $t_x^{\text{clamp}}$ and $t_y^{\text{clamp}}$ for subsequent Jacobian calculations [S1, unofficial].
6.  **Initialize Jacobian:**
    -   Create tensor `J` of shape $(N, 2, 3)$ filled with zeros.
7.  **Fill Jacobian Entries:**
    -   The Jacobian matrix $J$ is defined as:
        $$ J = \begin{bmatrix} \frac{f_x}{t_z} & 0 & -\frac{f_x t_x^{\text{clamp}}}{t_z^2} \\ 0 & \frac{f_y}{t_z} & -\frac{f_y t_y^{\text{clamp}}}{t_z^2} \end{bmatrix} $$
    -   Assign values:
        -   $J[:, 0, 0] = f_x / t_z$
        -   $J[:, 1, 1] = f_y / t_z$
        -   $J[:, 0, 2] = -(f_x \cdot t_x^{\text{clamp}}) / t_z^2$
        -   $J[:, 1, 2] = -(f_y \cdot t_y^{\text{clamp}}) / t_z^2$

**Pseudocode:**
```python
import torch

def compute_projection_jacobian(means_3D, camera, img_size):
    """
    Computes the 2x3 Jacobian matrix for perspective projection of 3D Gaussians.
    
    Args:
        means_3D: Tensor of shape (N, 3), 3D Gaussian centers.
        camera: Camera object with methods transform_points, focal_length, in_ndc.
        img_size: Tuple (W, H), image dimensions.
        
    Returns:
        J: Tensor of shape (N, 2, 3), the Jacobian matrix.
    """
    # Step 1: Validate Camera
    if camera.in_ndc():
        raise RuntimeError("Camera must not be in NDC mode for this Jacobian computation.")
    
    # Step 2: Extract Parameters
    focal_lengths = camera.focal_length.flatten()
    fx, fy = focal_lengths[0], focal_lengths[1]
    W, H = img_size
    
    # Step 3: Transform to View Space
    # Assuming view_transform is accessible via camera or passed separately
    # In many implementations, camera.transform_points handles world-to-view
    means_view_space = camera.transform_points(means_3D)
    
    tx = means_view_space[:, 0]
    ty = means_view_space[:, 1]
    tz = means_view_space[:, 2]
    tz2 = tz * tz
    
    # Step 4: Compute FOV Limits
    half_tan_fov_x = 0.5 * W / fx
    half_tan_fov_y = 0.5 * H / fy
    
    # Safety margin to stabilize computation near frustum edges
    safety_margin = 1.3
    lim_x = safety_margin * half_tan_fov_x
    lim_y = safety_margin * half_tan_fov_y
    
    # Step 5: Clamp Normalized Coordinates
    # Clamp normalized coordinates to prevent extreme values
    # Note: Division by tz is performed before clamping, but tz should be > 0 for valid points
    # If tz <= 0, these points are behind the camera and should be handled by masking elsewhere
    norm_tx = tx / tz
    norm_ty = ty / tz
    
    norm_tx_clamped = torch.clamp(norm_tx, -lim_x, lim_x)
    norm_ty_clamped = torch.clamp(norm_ty, -lim_y, lim_y)
    
    # Scale back to view space coordinates for Jacobian calculation
    tx_clamped = norm_tx_clamped * tz
    ty_clamped = norm_ty_clamped * tz
    
    # Step 6: Initialize Jacobian
    N = means_3D.shape[0]
    J = torch.zeros((N, 2, 3), dtype=means_3D.dtype, device=means_3D.device)
    
    # Step 7: Fill Jacobian Entries
    # J[0, 0] = fx / tz
    # J[0, 1] = 0
    # J[0, 2] = -fx * tx_clamped / tz2
    # J[1, 0] = 0
    # J[1, 1] = fy / tz
    # J[1, 2] = -fy * ty_clamped / tz2
    
    J[:, 0, 0] = fx / tz
    J[:, 1, 1] = fy / tz
    J[:, 0, 2] = -(fx * tx_clamped) / tz2
    J[:, 1, 2] = -(fy * ty_clamped) / tz2
    
    return J
```

**Parameters:**
-   **FOV Safety Margin:** 1.3 multiplier applied to half-tan-FOV limits. This stabilizes Jacobian computation near frustum edges by preventing extreme normalized coordinate values [S1, unofficial].

**Edge Cases and Pitfalls:**
-   **Division by Zero:** If $t_z \le 0$ (points at or behind the camera), division by $t_z$ causes instability. The clamping step mitigates extreme values but does not fix the singularity. Points with $t_z \le 0$ should be masked out before this computation or handled by a depth check [S1, unofficial].
-   **Frustum Edges:** Without clamping, normalized coordinates near the frustum boundary can lead to large Jacobian values, causing numerical instability in covariance transformation [S1, unofficial].

## Subtopics

### Per-Pixel Jacobian Evaluation
A variant where the Jacobian is evaluated at each ray–splat intersection point rather than at the surfel center, yielding a per-pixel MIP kernel that is maximally accurate but computationally expensive [S2, unofficial]. It computes the full $2 \times 2$ Jacobian at every covered pixel, followed by the outer product and matrix inverse [S2, unofficial]. This method incurs a rendering time of 65 ms per frame, which is a ~1.3x overhead relative to the center-precomputed method and a ~55% increase over the unfiltered baseline [S2, unofficial].

## Operating characteristics
-   **Time Complexity:** $O(N)$ for $N$ Gaussians, as it involves per-Gaussian arithmetic operations.
-   **Memory Complexity:** $O(N)$ to store the Jacobian tensor of shape $(N, 2, 3)$.
-   **Performance:** The center-precomputed method is efficient, with minimal overhead. The per-pixel variant is significantly slower (65 ms/frame vs. ~50 ms for center-precomputed, based on [S2, unofficial] relative metrics).
-   **Strengths:** Provides analytical derivatives for accurate covariance transformation; clamping ensures numerical stability near frustum edges.
-   **Limitations:** Assumes valid view-space coordinates ($t_z > 0$); does not handle NDC cameras directly; per-pixel variant is too expensive for real-time rendering.
-   **When to Use:** Standard Gaussian Splatting rendering where analytical Jacobian is required for covariance transformation.
-   **When Not to Use:** When using NDC cameras or when per-pixel accuracy is not critical and performance is paramount.

## Background
Originated in the context of 3D Gaussian Splatting for novel view synthesis and inverse rendering. The method is implemented in various open-source repositories and research papers focusing on efficient rasterization of 3D Gaussians [S1, unofficial][S2, unofficial]. It is a core component of the rendering pipeline, enabling the transformation of 3D Gaussian covariances into 2D screen-space covariances for splatting.
