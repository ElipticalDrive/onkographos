# Render Means

Also called: Mean-only rendering, Point projection rendering

## Overview
Render Means is the simplest possible rendering mode for 3D Gaussian Splatting, where each Gaussian is represented by a single pixel at the location where its 3D mean projects onto the 2D image plane [S1, unofficial]. It demonstrates the basic camera transformation pipeline (world → camera → image) and frustum culling without any rasterization complexity [S1, unofficial]. Unlike its sibling [2D Gaussian Projection with Covariance Stabilization](1198-2d-gaussian-projection-with-covariance-stabilization.md), which computes screen-space covariance matrices for elliptical splatting, Render Means ignores shape and spread, treating Gaussians as point sprites [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** `gs` (GaussianSet), `camera` (Camera), `bg_color` (background color).
*   **Output:** `rendered_image` (UInt8 Tensor of shape `[3, H, W]`) [S1, unofficial].

**Data Structures:**
The input `gs` is a GaussianSet containing `means` (Float32 Tensor, shape `[N, 3]`), `quats` (Float32 Tensor, shape `[N, 4]`), `scales` (Float32 Tensor, shape `[N, 3]`), `opacities` (Float32 Tensor, shape `[N]`), and `sh_coefficients` (Float32 Tensor, shape `[N, S, 3]`) [S1, unofficial].

**Steps:**
1.  **Initialize Image:** Create a tensor `rendered_image` of shape `[3, H, W]` initialized to `bg_color` [S1, unofficial].
2.  **Transform Means:** Project the 3D means to camera space using the camera's world-to-camera transformation: $M_{cam} = T_{world \to cam} \cdot M_{world}$ [S1, unofficial].
3.  **Project to Image:** Project the camera-space means to the 2D image plane coordinates $(u, v)$: $(u, v) = P(M_{cam})$ [S1, unofficial].
4.  **Frustum Culling:** Filter out points that are behind the camera or outside the view frustum [S1, unofficial].
5.  **Iterate and Render:** For each Gaussian $i$:
    *   Check opacity: If $opacity_i < 0.05$, skip the Gaussian [S1, unofficial].
    *   Get integer pixel coordinates: $u_{int} = \lfloor u_i \rfloor$, $v_{int} = \lfloor v_i \rfloor$ [S1, unofficial].
    *   Check bounds: If $0 \le u_{int} < W$ and $0 \le v_{int} < H$:
        *   Compute color $C_i$ from spherical harmonics [S1, unofficial].
        *   Assign color to pixel: $rendered\_image[:, v_{int}, u_{int}] = C_i$ [S1, unofficial].

**Pseudocode:**
```python
def render_means(gs_means, gs_opacities, gs_colors, camera, bg_color, H, W):
    # Initialize rendered image with background color
    rendered_image = [[[bg_color[0], bg_color[1], bg_color[2]] for _ in range(W)] for _ in range(H)]

    # Project means to image plane
    means_cam = camera.transform_points_world_to_cam(gs_means)
    means_image = camera.project_points_cam_to_image_plane(means_cam)

    # Frustum culling: filter out points behind the camera
    valid_indices = [i for i in range(len(gs_means)) if means_cam[i][2] > 0]

    for i in valid_indices:
        # Skip low opacity Gaussians
        if gs_opacities[i] < 0.05:
            continue

        u, v = means_image[i]
        u_int, v_int = int(u), int(v)

        # Check image bounds
        if 0 <= u_int < W and 0 <= v_int < H:
            # Assign color to the single pixel
            rendered_image[v_int][u_int] = gs_colors[i]

    return rendered_image
```

**Parameters:**
*   **Opacity Threshold:** 0.05. Gaussians with opacity below this value are skipped [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** Integer conversion truncates floating-point coordinates, which may cause slight misalignment at high resolutions [G].
*   **Overwriting:** Later Gaussians overwrite earlier ones if they project to the same pixel, as no alpha blending is performed [S1, unofficial].
*   **Boundaries:** Pixels outside $[0, W) \times [0, H)$ are ignored [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$, where $N$ is the number of Gaussians, as each Gaussian is processed once with constant-time projection and assignment [S1, unofficial].
*   **Memory Complexity:** $O(H \cdot W)$ for the output image, with no additional per-Gaussian memory required for covariance matrices or bounding boxes [S1, unofficial].
*   **Strengths:** Extremely fast with minimal computational overhead; ideal for debugging, previewing, or visualizing mean locations [S1, unofficial].
*   **Limitations:** No shape representation, no alpha blending, artifacts from overwriting, and no smooth edges [S1, unofficial].
*   **When to use:** Debugging camera transforms, visualizing point clouds, or when performance is critical and visual fidelity is secondary [S1, unofficial].
*   **When not to use:** Final rendering, scenes with overlapping Gaussians requiring blending, or when shape/spread information is important [S1, unofficial].

## Background
Render Means is a simplified rendering approach used in the context of 3D Gaussian Splatting to demonstrate the basic camera transformation pipeline [S1, unofficial]. It serves as a baseline to understand the core concepts of depth sorting and alpha blending by removing the complexity of covariance projection and elliptical splatting [S1, unofficial].
