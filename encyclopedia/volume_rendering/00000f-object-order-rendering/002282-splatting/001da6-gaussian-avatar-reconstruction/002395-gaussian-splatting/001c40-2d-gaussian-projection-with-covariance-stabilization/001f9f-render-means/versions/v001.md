# Render Means

Also called: Mean-only rendering, Point projection rendering

## Overview
Render Means is the simplest possible rendering mode for 3D Gaussian Splatting, where each Gaussian is represented by a single pixel at the location where its 3D mean projects onto the 2D image plane [S1, unofficial]. It demonstrates the basic camera transformation pipeline (world → camera → image) and frustum culling without any rasterization complexity or alpha blending [S1, unofficial]. Unlike its sibling [2D Gaussian Projection with Covariance Stabilization](1198-2d-gaussian-projection-with-covariance-stabilization.md), which computes screen-space covariance matrices for elliptical splatting, Render Means ignores shape and spread, treating Gaussians as point sprites.

## How it works
**Inputs and Outputs:**
*   **Input:** `gs` (GaussianSet), `camera` (Camera), `bg_color` (background color).
*   **Output:** `rendered_image` (UInt8 Tensor of shape `[3, H, W]`).

**Data Structures:**
The input `gs` is a GaussianSet with the following fields [S1, unofficial]:
*   `means`: Float32 Tensor, shape `[N, 3]` (3D coordinates).
*   `quats`: Float32 Tensor, shape `[N, 4]` (quaternions).
*   `scales`: Float32 Tensor, shape `[N, 3]` (scaling factors).
*   `opacities`: Float32 Tensor, shape `[N]` (scalar opacity values).
*   `sh_coefficients`: Float32 Tensor, shape `[N, S, 3]` (spherical harmonic coefficients).

**Steps:**
1.  **Initialize Image:** Create a tensor `rendered_image` of shape `[3, H, W]` initialized to `bg_color`. In the reference implementation, `bg_color` is `[0, 0, 0]` (black) [S1, unofficial].
2.  **Transform Means:** Project the 3D means to camera space using the camera's world-to-camera transformation: $M_{cam} = T_{world \to cam} \cdot M_{world}$ [S1, unofficial].
3.  **Project to Image:** Project the camera-space means to the 2D image plane coordinates $(u, v)$: $(u, v) = P(M_{cam})$ [S1, unofficial].
4.  **Frustum Culling:** Filter out points that are behind the camera or outside the view frustum [S1, unofficial].
5.  **Iterate and Render:** For each Gaussian $i$:
    *   Check opacity: If $opacity_i < 0.05$, skip the Gaussian [S1, unofficial].
    *   Get integer pixel coordinates: $u_{int} = \lfloor u_i \rfloor$, $v_{int} = \lfloor v_i \rfloor$ [S1, unofficial].
    *   Check bounds: If $0 \le u_{int} < W$ and $0 \le v_{int} < H$:
        *   Compute color $C_i$ from spherical harmonics or base color [S1, unofficial].
        *   Assign color to pixel: $rendered\_image[:, v_{int}, u_{int}] = C_i$ [S1, unofficial].

**Pseudocode:**
```python
def render_means(gs: GaussianSet, camera: Camera, bg_color: Tensor = torch.tensor([0, 0, 0], dtype=torch.uint8)) -> Tensor:
    H, W = camera.height, camera.width
    # Initialize rendered image with background color
    rendered_image = bg_color[:, None, None].expand(3, H, W).clone()
    
    # Project means to image plane
    means_cam = camera.transform_points_world_to_cam(gs.means)
    means_image = camera.project_points_cam_to_image_plane(means_cam)
    
    # Frustum culling
    valid_indices = frustum_culling(gs, camera, means_cam, means_image)
    
    for i in valid_indices:
        # Skip low opacity Gaussians
        if gs.opacities[i] < 0.05:
            continue
            
        u, v = means_image[i]
        u_int, v_int = int(u.item()), int(v.item())
        
        # Check image bounds
        if 0 <= u_int < W and 0 <= v_int < H:
            # Compute color from SH coefficients or base color
            # Note: Exact SH evaluation is not detailed in the minimal snippet, 
            # but 'colors_at_means' implies precomputed or evaluated colors.
            color = colors_at_means[i, :]
            
            # Assign color to the single pixel
            rendered_image[:, v_int, u_int] = color
            
    return rendered_image
```

**Parameters:**
*   **Opacity Threshold:** 0.05. Gaussians with opacity below this value are skipped [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** Integer conversion of floating-point coordinates truncates towards zero. This may cause slight misalignment for high-resolution images.
*   **Overwriting:** Since this is a point projection, later Gaussians overwrite earlier ones if they project to the same pixel. There is no alpha blending or depth sorting involved in the final pixel assignment in the minimal implementation [S1, unofficial].
*   **Boundaries:** Pixels outside the image bounds $[0, W) \times [0, H)$ are ignored [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$, where $N$ is the number of Gaussians. Each Gaussian is processed once with constant-time projection and assignment.
*   **Memory Complexity:** $O(H \cdot W)$ for the output image. No additional per-Gaussian memory is required for covariance matrices or bounding boxes.
*   **Strengths:** Extremely fast; minimal computational overhead; ideal for debugging, previewing, or visualizing mean locations.
*   **Limitations:** No shape representation; no alpha blending; artifacts from overwriting; no smooth edges.
*   **When to use:** Debugging camera transforms, visualizing point clouds, or when performance is critical and visual fidelity is secondary.
*   **When not to use:** Final rendering, scenes with overlapping Gaussians requiring blending, or when shape/spread information is important.

## Background
Render Means is a simplified rendering approach used in the context of 3D Gaussian Splatting to demonstrate the basic camera transformation pipeline [S1, unofficial]. It is part of the `splaty` library, an unofficial implementation of 3D Gaussian Splatting [S1, unofficial]. The method serves as a baseline to understand the core concepts of depth sorting and alpha blending by removing the complexity of covariance projection and elliptical splatting [S1, unofficial].
