# AccuTile

Also called: Accurate Tile Extent Computation

## Overview
AccuTile is an algorithm for identifying the minimum and maximum points (extents) of a 2D ellipse within a given tile row or column during rasterization, used to determine the exact set of tiles intersected by a Gaussian [S1, S2]. It improves upon SnugBox by handling cases where the ellipse intersects tile boundaries more precisely, reducing the number of tiles further than SnugBox [S1, S2]. Unlike baseline 3D-GS which allocates tiles based on a square inscribing a circle, or SnugBox which uses a tight bounding box, AccuTile computes the exact Gaussian-to-tile intersections by iterating over the shorter side of the SnugBox tile extent [S1, S2].

## How it works
AccuTile extends the SnugBox method to identify the exact tiles intersected by the Gaussian [S1]. It takes as input the tight bounding box produced by SnugBox and its rectangular tile extent [S1]. The algorithm iterates over the rows (or columns) of the SnugBox tile extent, processing along the shorter side of the extent [S1, S2]. For each row or column, it identifies the exact tile extent by finding the minimum and maximum points of the ellipse inside it [S2]. All tiles between these minimum and maximum points are marked as intersecting the ellipse [S2]. The algorithm requires only two intersection points per row or column of the SnugBox [S2].

### Inputs and Outputs
**Inputs:**
*   Ellipse $E$: Implicitly defined by the projected 2D covariance parameters [S2].
*   SnugBox Bounding Box $B$: The axis-aligned tight bounding box of the ellipse, with sides denoted by subscripts $t$ (top), $b$ (bottom), $l$ (left), and $r$ (right) [S1, S2].
*   SnugBox Tile Extent Rectangle $R$: The rectangular tile extent of the Gaussian, with sides denoted similarly [S1].
*   Tile size: Implicitly used to convert coordinates to tile indices [S2].

**Outputs:**
*   Tile count $C$: The total number of tiles intersected by the Gaussian [S1].
*   Processed tiles: The range of tiles for each row/column [S1].

### Data Structures
*   **Ellipse $E$**: Implicitly defined by the projected 2D covariance parameters [S2].
*   **Bounding Box $B$**: Defined by four scalar values: $B_t, B_b, B_l, B_r$ representing the top, bottom, left, and right coordinates of the tight bounding box [S1, S2].
*   **Tile Extent Rectangle $R$**: Defined by four scalar values: $R_t, R_b, R_l, R_r$ representing the top, bottom, left, and right tile boundaries [S1].
*   **Intersection Points**: Pairs of $(x, y)$ coordinates representing the intersection of the ellipse with a horizontal or vertical line [S1].

### Steps
1.  **Initialize**: Set tile count $C \leftarrow 0$. Set $linemin \leftarrow R_b$ (the bottom line of the rectangle $R$) [S1].
2.  **Initial Intersection**: If $linemin \ge B_b$ (the bottom line of the rectangle is below or at the bottom of the bounding box), compute the initial intersection points $imin \leftarrow \text{Intersections}(linemin, E)$ using Equation 15 [S1]. If $linemin < B_b$, no initial intersection is computed for the first row [S2].
3.  **Loop**: For each row $r$ in $R$ (processed from bottom to top):
    a.  Set $linemax \leftarrow R_t$ (the top line of the current row $r$) [S1].
    b.  **Upper Intersection**: If $linemax \le B_t$ (the top line of the current row is above or at the top of the bounding box), compute the intersection points $imax \leftarrow \text{Intersections}(linemax, E)$ using Equation 15 [S1]. If $linemax > B_t$, no intersection is computed for this row [S2].
    c.  **Determine Minimum Extent ($emin$)**:
        *   If the bottom-left corner of the bounding box $B_l$ is within row $r$, then $emin \leftarrow B_l$ [S1].
        *   Otherwise, $emin \leftarrow \min(imin, imax)$ [S1].
    d.  **Determine Maximum Extent ($emax$)**:
        *   If the bottom-right corner of the bounding box $B_r$ is within row $r$, then $emax \leftarrow B_r$ [S1].
        *   Otherwise, $emax \leftarrow \max(imin, imax)$ [S1].
    e.  **Convert to Tile Indices**: Convert $emin$ and $emax$ to tile indices $tilemin$ and $tilemax$ [S1].
    f.  **Update Count**: $C \leftarrow C + (tilemax - tilemin)$ [S1].
    g.  **Process Tiles**: Call $\text{Process}(tilemin, tilemax)$ [S1].
    h.  **Update for Next Row**: Set $imin \leftarrow imax$ [S1]. This reuses the upper boundary intersection of the current row as the lower boundary intersection for the next row, as the boundaries are shared [S1].
4.  **Return**: Return $C$ [S1].

### Edge Cases and Pitfalls
The algorithm handles several cases to ensure correctness [S1, S2]:
1.  **Case 1: Ellipse does not intersect tile row boundary**: The entire ellipse lies within the row. The bounding box extrema $x_{min}$ and $x_{max}$ computed by SnugBox are selected as the furthest extents [S1].
2.  **Case 2: Ellipse intersects one boundary but not the other**:
    *   **2.1**: Both $x_{min}$ and $x_{max}$ are in the row. They are assigned as the furthest extent [S1].
    *   **2.2**: Neither $x_{min}$ nor $x_{max}$ is in the row, but $y_{max}$ (or $y_{min}$) is. The ellipse decreases monotonically from $y_{max}$ to the boundary. The row boundary intersections are selected as the furthest extent [S1].
    *   **2.3**: One critical point (e.g., $x_{min}$) and one extremum (e.g., $y_{min}$) are in the row, but the other extremum (e.g., $x_{max}$) is not. The ellipse increases monotonically from $y_{min}$ to the boundary. The ellipse point on the curve that extends to the right of $y_{min}$ and intersects the tile row boundary is selected as the maximum extent [S1].
3.  **Case 3: Ellipse intersects both top and bottom row boundaries**:
    *   If $x_{min}$ or $x_{max}$ is in the row, it is assigned as the min/max extent [S1].
    *   Otherwise, the ellipse monotonically increases from one boundary to the other. The minimum or maximum boundary point is selected [S1].

### Pseudocode
```python
import math

def AccuTile(E, B, R, tile_size):
    """
    Computes the exact tile intersection of a Gaussian.
    
    Args:
        E: Ellipse object with attributes xc, yc, a, b (semi-axes).
        B: SnugBox Bounding Box with attributes t, b, l, r.
        R: SnugBox Tile Extent Rectangle with attributes t, b, l, r and a list of rows.
        tile_size: Width/height of a single tile in world/pixel coordinates.
        
    Returns:
        C: Total number of tiles intersected.
    """
    C = 0
    linemin = R.b
    
    # Initial intersection if the bottom of the tile extent is within or above the bounding box bottom
    if linemin >= B.b:
        _, imin = Intersections(linemin, E)
    else:
        imin = None
        
    # Iterate over each row in the tile extent
    for row in R.rows:
        linemax = row.t
        
        # Compute upper intersection if the top of the row is within or below the bounding box top
        if linemax <= B.t:
            _, imax = Intersections(linemax, E)
        else:
            imax = None
            
        # Determine emin
        if B.l in row:
            emin = B.l
        else:
            if imin is not None and imax is not None:
                emin = min(imin, imax)
            elif imin is not None:
                emin = imin
            else:
                emin = imax
                
        # Determine emax
        if B.r in row:
            emax = B.r
        else:
            if imin is not None and imax is not None:
                emax = max(imin, imax)
            elif imin is not None:
                emax = imin
            else:
                emax = imax
                
        # Convert to tile indices
        tilemin = int(emin / tile_size)
        tilemax = int(emax / tile_size)
        
        # Update count
        C += (tilemax - tilemin)
        
        # Process tiles
        Process(tilemin, tilemax)
        
        # Update imin for next row
        imin = imax

    return C

def Intersections(line_y, E):
    """
    Computes the intersection points of the ellipse E with the horizontal line y = line_y.
    Returns the left and right x-coordinates, or (None, None) if no intersection.
    [G] Standard ellipse intersection calculation based on Eq. 15.
    """
    dy = line_y - E.yc
    if abs(dy) > E.b:
        return None, None
    delta = 1.0 - (dy * dy) / (E.b * E.b)
    if delta < 0:
        return None, None
    dx = E.a * math.sqrt(delta)
    return E.xc - dx, E.xc + dx
```

## Operating characteristics
*   **Time Complexity**: AccuTile counts tiles in time proportional to the shorter side of the tile extent and processes tiles in time proportional to the tile count [S1, S2].
*   **Memory Complexity**: Not given in the sources. [S1]
*   **Measured Performance**:
    *   On the Tanks & Temples dataset, AccuTile achieves a 1.67x FPS increase and 1.12x training time decrease compared to baseline 3D-GS, with PSNR 23.73, SSIM 0.849, LPIPS 0.177 [S1].
    *   On the Deep Blending dataset, AccuTile achieves a 2.32x FPS increase and 1.13x training time decrease compared to baseline 3D-GS, with PSNR 29.12, SSIM 0.885, LPIPS 0.288 [S1].
    *   AccuTile culminates in an average overall speed-up of 1.99× [S1].
*   **Comparison**: AccuTile outperforms the StopThePop Tile-Based Culling method in overall runtime. It avoids the overhead of warp-level load balancing and inclusive sums required by the alternative [S1].
*   **Strengths**: Reduces the number of tiles further than SnugBox, leading to faster downstream functions [S1]. Efficiently computes exact Gaussian-to-tile intersections [S2].
*   **Limitations**: Requires the SnugBox bounding box as input [S1].

## Background
AccuTile was introduced in the "Speedy-Splat" paper by Hanson et al. in 2025 [S1, S2]. It is part of the Speedy-Splat method, which aims to provide fast 3D Gaussian Splatting with sparse pixels and sparse primitives [S2]. AccuTile extends the SnugBox method, which itself improves upon the baseline 3D-GS tile allocation [S1, S2]. The method is used in the context of 3D Gaussian Splatting rendering and training [S1].
