# Tight Ellipse AABB Derivation

Also called: Ellipse AABB Computation, Tight AABB Ellipse Culling, Tight Elliptical Bounding Box, Tight bounding box for ellipse

## Overview
This method computes the tight axis-aligned bounding box (AABB) of a projected 2D Gaussian ellipse in constant time [S1, S2]. It replaces the loose circular bounding box used in original 3D Gaussian Splatting to determine tile intersections, significantly reducing false-positive splat duplications during rasterization [S2].

## How it works
**Inputs:**
- Two 2D basis vectors $\mathbf{a}, \mathbf{b} \in \mathbb{R}^2$ defining the ellipse shape and orientation [S2].
- Opacity $\sigma_i$ of the Gaussian $\mathcal{G}_i$ [S1].
- Threshold value for $\alpha_i(p)$ to define the ellipse boundary [S1].
- Tile size $T$ [S1].
- Image boundaries (width $W$, height $H$) [S1].
- Center coordinates $(c_x, c_y)$ of the projected Gaussian [G].

**Outputs:**
- A rectangular tile extent (min/max tile coordinates) that tightly encloses the ellipse [S1].

**Data Structures:**
- Matrix $D \in \mathbb{R}^{2 \times 2}$: Symmetric matrix derived from basis vectors [S2].
- Matrix $C \in \mathbb{R}^{2 \times 2}$: Inverse of $D$ [S2].
- Bounds: Four scalar values $(x_{min}, x_{max}, y_{min}, y_{max})$ representing the AABB in pixel coordinates, converted to tile indices [S1, S2].

**Steps:**

1.  **Define Ellipse Geometry:**
    The threshold $\alpha_i(p) = \sigma_i g_i(p)$ determines the exact pixel extent of the Gaussian as an ellipse [S1]. The ellipse is defined by the implicit equation $f(x, y) = 0$ derived from the inverse matrix $C$ [S2].

2.  **Construct Matrix D:**
    Convert the basis vectors $\mathbf{a}$ and $\mathbf{b}$ into a symmetric $2 \times 2$ matrix $D$ using outer products [S2]:
    $$ D = \mathbf{a}\mathbf{a}^T + \mathbf{b}\mathbf{b}^T $$

3.  **Compute Inverse Matrix C:**
    Calculate the inverse of $D$ [S2]:
    $$ C = D^{-1} $$
    Let $C = \begin{pmatrix} C_{00} & C_{01} \\ C_{10} & C_{11} \end{pmatrix}$. Since $D$ is symmetric, $C$ is also symmetric, so $C_{01} = C_{10}$ [S2].

4.  **Derive Vertical Extents (x-bounds):**
    Points on the vertical edges of the AABB are points on the ellipse where the gradient $\nabla f$ is horizontal (i.e., $\partial f/\partial y = 0$) [S2]. Solving this condition yields the half-width $x_{half} = \sqrt{D_{00}}$ [S2]. The source notes this simplified formula saves arithmetic instructions compared to Hanson et al. [HTL*25] [S2].

5.  **Derive Horizontal Extents (y-bounds):**
    Apply the same derivation swapping $x$ and $y$ (and indices 0 and 1) to find points where the gradient is vertical ($\partial f/\partial x = 0$) [S2]. This yields the half-height $y_{half} = \sqrt{D_{11}}$ [S2].

6.  **Combine Bounds:**
    The pixel coordinates for the AABB edges are $x_{left} = c_x - x_{half}$, $x_{right} = c_x + x_{half}$, $y_{bottom} = c_y - y_{half}$, $y_{top} = c_y + y_{half}$ [S2].

7.  **Convert to Tile Coordinates:**
    Divide the pixel bounds by the tile size $T$ and round appropriately [S1]:
    $$ tile_{min\_x} = \lfloor x_{left} / T \rfloor, \quad tile_{max\_x} = \lceil x_{right} / T \rceil $$
    $$ tile_{min\_y} = \lfloor y_{bottom} / T \rceil, \quad tile_{max\_y} = \lceil y_{top} / T \rceil $$

8.  **Clip to Image Boundary:**
    Clip the tile coordinates to the image boundaries $[0, W/T] \times [0, H/T]$ [S1].

**Pseudocode:**

```python
import math

def compute_tight_ellipse_aabb(a, b, center_x, center_y, tile_size, image_width, image_height):
    """
    Computes the tight AABB for a 2D Gaussian ellipse defined by basis vectors a and b.
    
    Args:
        a: tuple (ax, ay), 2D basis vector
        b: tuple (bx, by), 2D basis vector
        center_x: float, x-coordinate of the ellipse center in pixels
        center_y: float, y-coordinate of the ellipse center in pixels
        tile_size: float, size of a tile in pixels
        image_width: int, width of the image in pixels
        image_height: int, height of the image in pixels
        
    Returns:
        tuple: (min_tile_x, min_tile_y, max_tile_x, max_tile_y)
    """
    # Step 2: Construct Matrix D = aa^T + bb^T
    D00 = a[0]*a[0] + b[0]*b[0]
    D01 = a[0]*a[1] + b[0]*b[1]
    D11 = a[1]*a[1] + b[1]*b[1]
    
    # Step 3: Compute Inverse Matrix C = D^-1
    det_D = D00 * D11 - D01 * D01
    
    # Guard against degenerate ellipse (zero determinant)
    if abs(det_D) < 1e-9:
        return (0, 0, 0, 0)
        
    C00 = D11 / det_D
    C01 = -D01 / det_D
    C11 = D00 / det_D
    
    # Steps 4 & 5: Derive extents using simplified formula from Appendix A [S2]
    # x_half = sqrt(D00), y_half = sqrt(D11)
    x_half = math.sqrt(D00)
    y_half = math.sqrt(D11)
    
    # Step 6: Combine bounds with center offset
    x_left = center_x - x_half
    x_right = center_x + x_half
    y_bottom = center_y - y_half
    y_top = center_y + y_half
    
    # Step 7: Convert to tile coordinates
    min_tile_x = math.floor(x_left / tile_size)
    max_tile_x = math.ceil(x_right / tile_size)
    min_tile_y = math.floor(y_bottom / tile_size)
    max_tile_y = math.ceil(y_top / tile_size)
    
    # Step 8: Clip to image boundary
    max_tile_x = min(max_tile_x, math.ceil(image_width / tile_size))
    max_tile_y = min(max_tile_y, math.ceil(image_height / tile_size))
    min_tile_x = max(min_tile_x, 0)
    min_tile_y = max(min_tile_y, 0)
    
    return (min_tile_x, min_tile_y, max_tile_x, max_tile_y)
```

**Parameters:**
- Threshold: Determined by opacity $\sigma_i$ and the Gaussian value function $g_i(p)$ [S1].
- Tile size: Not given in the sources.

**Edge Cases and Pitfalls:**
- **Degenerate Input:** If the determinant of $D$ is zero (degenerate ellipse, e.g., line or point), the inverse $C$ is undefined [S2]. A guard must handle this [G].
- **False Negatives:** Using an approximate tile-ellipse intersection test may produce occasional false-negatives [S2]. This is acceptable for editors operating on fully-trained models but would negatively influence convergence in gradient descent-based optimization [S2].
- **Precision:** Floating-point precision errors in matrix inversion can lead to negative values under the square root. Clamping to zero is recommended [G].

## Subtopics

### [AccuTile](3037-accutile.md)
An algorithm for identifying the minimum and maximum points (extents) of an ellipse within a given tile row or column during rasterization, used to determine which pixels to render. It improves upon SnugBox by handling cases where the ellipse intersects tile boundaries more precisely.

## Operating characteristics
- **Time Complexity:** Constant time $O(1)$ per Gaussian splat for AABB computation [S1].
- **Memory Complexity:** Not given in the sources.
- **Performance:** Significantly reduces false-positive tile intersections compared to the bounding circle approach in 3DGS, leading to fewer splat duplications and improved rendering performance [S2].
- **Strengths:** Tighter bounds reduce the number of tiles processed per splat. The simplified formula saves arithmetic instructions compared to earlier methods like Hanson et al. [HTL*25] [S2].
- **Limitations:** Approximate intersection tests (if used in subsequent steps) may cause false-negatives, which are detrimental to optimization but acceptable for rendering [S2].

## Background
The method was introduced as part of the "SnugBox" algorithm in the Speedy-Splat paper [S1]. It addresses the inefficiency of the original 3D Gaussian Splatting method, which duplicates splats for each tile within the ellipse's bounding circle, leading to numerous false-positives [S2]. The derivation in Appendix A of the Splatshop paper provides a simplified formula for the tight AABB, noting that it saves arithmetic instructions compared to concurrent work by Hanson et al. [S2].
