# Adaptive Bounding Box Computation

Also called: Tsplat bounding box

## Overview
Adaptive Bounding Box Computation computes a tight, axis-aligned bounding box (AABB) for a projected 2D Gaussian splat based on an opacity threshold, replacing the wasteful circular or square bounding boxes of original 3D Gaussian Splatting (3DGS) [S1, unofficial][S2]. It solves the problem of excessive tile intersections and duplicated Gaussian processing by ensuring that only Gaussians with sufficient opacity and geometric extent contribute to rendering [S2]. Unlike its sibling [2D Gaussian Projection with Covariance Stabilization](1198-2d-gaussian-projection-with-covariance-stabilization.md), which ensures numerical stability of the covariance matrix, this method uses the stabilized covariance to derive an opacity-aware bounding box that significantly reduces false-positive tile intersections [S2].

## How it works
### Inputs and Outputs
**Inputs:**
- 3D Gaussian splat parameters: mean position $\mathbf{t}$, covariance matrix $\Sigma$, opacity $\alpha_{3D}$, and Spherical Harmonics (SH) coefficients.
- Camera projection matrix $P$ and view matrix $V$.
- Image dimensions: width $W$, height $H$.
- Alpha threshold $\tau$ (epsilon).

**Outputs:**
- Integer bounding box coordinates $(x_0, y_0, x_1, y_1)$ defining the pixel range to rasterize.
- If the splat is invisible or out of bounds, the output is `None`.

### Data Structures
The method operates on projected 2D Gaussian parameters. While the parent article computes the 2D covariance matrix $\Sigma_{2D}$ and its inverse, this method typically uses the conic representation or the diagonal elements of $\Sigma_{2D}$ for bounding box calculation.
- **Conic Representation (Optional but common in optimized implementations):** A vector $\mathbf{c} = [a, b, c]$ representing the quadratic form $\mathbf{d}^T \Sigma_{2D}^{-1} \mathbf{d} = a du^2 + 2b du dv + c dv^2$ [S4, unofficial].
- **Projected Mean:** $(u_{mean}, v_{mean})$ in screen space [S4, unofficial].
- **Depth:** $z$ value for perspective correction [S4, unofficial].

### Steps
1. **Opacity Filter:** If the splat's opacity $\alpha_{3D} \le \tau$, return `None` [S1, unofficial][S2][S4, unofficial].
2. **Projection:** Project the 3D center and covariance matrix into 2D screen space to obtain the 2D ellipse parameters (mean $\mathbf{u}_{mean}$ and covariance $\Sigma_{2D}$) [S1, S3, unofficial].
3. **Compute $k^2$:** Calculate the squared distance threshold based on the opacity ratio:
   $$ k^2 = \min\left(2.0 \cdot \ln\left(\frac{\alpha_{3D}}{\tau}\right), k^2_{max}\right) $$
   If $k^2 \le 0.0$, return `None` [S1, unofficial].
   *Note: $k^2_{max}$ is a constant to prevent excessively large bounding boxes for very high opacity splats. Not given in the sources.*
4. **Compute Half-Widths:** Calculate the half-extents of the bounding box using the diagonal elements of $\Sigma_{2D}$:
   $$ rx_f = \sqrt{k^2 \cdot \Sigma_{2D,00}} $$
   $$ ry_f = \sqrt{k^2 \cdot \Sigma_{2D,11}} $$
   If $rx_f$ or $ry_f$ are not finite or $< 1.0$, return `None` [S1, unofficial].
   *Note: Some implementations use a simplified radius based on depth if conics are not available, but the adaptive box relies on $\Sigma_{2D}$ [S4, S1, unofficial].*
5. **Compute Integer Bounding Box:**
   $$ x_0 = \lfloor u_{mean} - rx_f \rfloor $$
   $$ y_0 = \lfloor v_{mean} - ry_f \rfloor $$
   $$ x_1 = \lceil u_{mean} + rx_f \rceil $$
   $$ y_1 = \lceil v_{mean} + ry_f \rceil $$
   [S1, S4, unofficial]
6. **Clip to Viewport:**
   $$ x_0 = \max(0, x_0), \quad y_0 = \max(0, y_0) $$
   $$ x_1 = \min(W - 1, x_1), \quad y_1 = \min(H - 1, y_1) $$
   If $x_0 > x_1$ or $y_0 > y_1$, return `None` [S1, unofficial].
7. **Depth and Color Precomputation (Optional but common in pipeline):**
   - Calculate depth for sorting [S3, unofficial].
   - Evaluate SH coefficients for the current viewing direction to compute RGB color [S3, unofficial].
   - Pack color and opacity into a 32-bit integer (RGBA8) [S3, unofficial].

### Pseudocode
```python
def compute_adaptive_bounding_box(
    opacity_3d: float,
    cov2d_00: float,
    cov2d_11: float,
    u_mean: float,
    v_mean: float,
    width: int,
    height: int,
    alpha_threshold: float,
    max_k2: float = 100.0  # [G] Typical value to cap box size; not explicitly defined in sources
) -> tuple[int, int, int, int] | None:
    """
    Computes an adaptive AABB for a 2D Gaussian splat.
    
    Args:
        opacity_3d: 3D Gaussian opacity.
        cov2d_00: Diagonal element (0,0) of the 2D screen-space covariance matrix.
        cov2d_11: Diagonal element (1,1) of the 2D screen-space covariance matrix.
        u_mean: Projected mean x-coordinate.
        v_mean: Projected mean y-coordinate.
        width: Image width in pixels.
        height: Image height in pixels.
        alpha_threshold: Minimum opacity threshold tau.
        max_k2: Maximum allowed k^2 value to prevent huge boxes.
        
    Returns:
        Tuple (x0, y0, x1, y1) or None if splat is invisible.
    """
    # Step 1: Opacity Filter
    if opacity_3d <= alpha_threshold:
        return None

    # Step 2 & 3: Compute k^2
    # Formula: alpha = opacity * exp(-0.5 * d^T Sigma^-1 d)
    # We want alpha >= tau => d^T Sigma^-1 d <= 2 * ln(opacity / tau) = k^2
    log_ratio = opacity_3d / alpha_threshold
    if log_ratio <= 1.0:
        return None # ln(1) = 0, k^2 <= 0
        
    k2 = 2.0 * math.log(log_ratio)
    k2 = min(k2, max_k2)
    
    if k2 <= 0.0:
        return None

    # Step 4: Compute Half-Widths
    # Using diagonal elements of the covariance matrix for axis-aligned box
    rx_f = math.sqrt(k2 * cov2d_00)
    ry_f = math.sqrt(k2 * cov2d_11)
    
    if not math.isfinite(rx_f) or rx_f < 1.0:
        return None
    if not math.isfinite(ry_f) or ry_f < 1.0:
        return None

    # Step 5: Compute Integer Bounding Box
    x0 = math.floor(u_mean - rx_f)
    y0 = math.floor(v_mean - ry_f)
    x1 = math.ceil(u_mean + rx_f)
    y1 = math.ceil(v_mean + ry_f)

    # Step 6: Clip to Viewport
    x0 = max(0, x0)
    y0 = max(0, y0)
    x1 = min(width - 1, x1)
    y1 = min(height - 1, y1)

    if x0 > x1 or y0 > y1:
        return None

    return (x0, y0, x1, y1)
```

### Parameters
- **Alpha Threshold ($\tau$):** The minimum opacity for a splat to be considered visible. Typical value: $0.01$ or $0.05$ [S2][S4, unofficial].
- **Max $k^2$:** Capping factor for the logarithmic term. Not given in the sources [G].

### Edge Cases and Pitfalls
- **Precision:** If $rx_f$ or $ry_f$ are very small, they may be clamped to $1.0$ to ensure at least one pixel is processed [S1, unofficial].
- **Tilted Gaussians:** The adaptive bounding box uses the diagonal elements of $\Sigma_{2D}$. This assumes the ellipse is axis-aligned. For highly tilted ellipses, the diagonal approximation may be loose. However, the original 3DGS method used circular boxes, which are even looser [S2]. Some implementations use the conic representation to skip rows/cols where the peak is below threshold, which is more accurate for tilted Gaussians [S1, unofficial].
- **Depth Scaling:** In some simplified implementations, the radius is scaled inversely with depth (`radius_px / depth`) and clamped [S4, unofficial]. This is less accurate than using the projected covariance but faster. The adaptive box method specifically aims to use the covariance for tighter bounds [S1, unofficial][S2].

## Subtopics

### Original 3DGS Bounding Box
Uses a fixed circular bounding box based on a constant number of standard deviations. It is simple but wasteful for low-opacity or elongated Gaussians. [Link to 3DGS article if available, otherwise refer to parent].

### Elliptical Disk Approximation
Renders Gaussians as filled ellipses rather than AABBs. This reduces false positives further but is more expensive to rasterize. The adaptive bounding box is a pre-filter for this or for standard rasterization. [S2].

## Operating characteristics
- **Time Complexity:** $O(1)$ per Gaussian for bounding box computation. The cost is dominated by the projection and logarithmic operations.
- **Memory Complexity:** $O(1)$ auxiliary memory.
- **Performance:** On the Bicycle scene at native resolution with 16x16 tiles, using adaptive bounding boxes reduced duplicated Gaussians from 87,067,709 (original AABBs) to 18,466,556 (non-square adaptive boxes) [S2]. This led to a 3.77x reduction in rendering time and 2.11x reduction in GPU memory usage [S2].
- **Strengths:** Significantly reduces overdraw and tile intersections, especially for low-opacity or elongated Gaussians.
- **Limitations:** Requires accurate 2D covariance projection. If the covariance is not stabilized (e.g., near singular), the box may be incorrect.

## Background
The method was introduced as an improvement over the original 3D Gaussian Splatting rendering pipeline, which used fixed circular bounding boxes. The adaptive bounding box computation was highlighted in the "Fast 3D Gaussian Splatting Rendering via Easily Integrable Improvements" paper [S2] and implemented in unofficial libraries like `tsplat` [S1, unofficial] and `splaty` [S4, unofficial]. It addresses the inefficiency of the original method where large, transparent Gaussians would affect many tiles unnecessarily.
