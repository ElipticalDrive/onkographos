# Tiled 2D Gaussian Splatting Rasterization


## Overview
Tiled 2D Gaussian Splatting Rasterization is a GPU-parallel rendering method for 3D Gaussian Splatting that divides the image into fixed-size tiles to manage memory and processing load, assigning Gaussians to tiles based on their axis-aligned bounding boxes (AABBs) [S1, unofficial]. It solves the performance bottleneck of sorting millions of splats per pixel by grouping work into tiles, enabling real-time rendering and efficient backpropagation [S1, unofficial][S2]. Unlike non-tiled approaches that iterate over all Gaussians per pixel or use screen-space quads without tiling, this method restricts pixel iteration to relevant Gaussians within each tile, significantly reducing redundant computations [S1, unofficial].

## How it works
**Inputs:**
- `gs`: A collection of $N$ 3D Gaussians, each defined by a mean position $\mu \in \mathbb{R}^3$, a $3 \times 3$ covariance matrix $\Sigma \in \mathbb{R}^{3 \times 3}$, an opacity $\alpha \in [0, 1]$, and spherical harmonic coefficients for color.
- `camera`: A pinhole camera model with focal lengths $f_x, f_y$, principal point $(c_x, c_y)$, image dimensions $W \times H$, and extrinsic parameters (rotation $R \in SO(3)$, translation $t \in \mathbb{R}^3$).
- `tile_size`: Integer, default 32.
- `sigma_multiplier`: Float, default 3.0 (or 3.33 in some implementations). Controls the extent of the Gaussian's bounding box.

**Outputs:**
- `color`: A tensor of shape $[3, H, W]$ containing the final RGB image.
- `alpha`: A tensor of shape $[H, W]$ containing the accumulated alpha values.

**Data Structures:**
- `tile_dict`: A mapping from tile index $(u, v)$ to a list of Gaussian indices assigned to that tile.
- `conics`: A tensor of shape $[N, 3]$ storing the inverse 2D covariance matrix elements $a, b, c$ for each Gaussian. Specifically, the inverse covariance matrix $C^{-1} = \begin{bmatrix} a & b \\ b & c \end{bmatrix}$.

**Steps:**

1.  **Initialize Background:**
    Create a background color tensor `bg` of shape $[3, H, W]$ initialized to black (0.0) or white (1.0) depending on the scene, and clone it for later compositing [S1, unofficial].

2.  **Transform and Project:**
    - Transform Gaussian means to camera space: $\mu_{cam} = R \mu_{world} + t$ [S1, unofficial].
    - Project means to the image plane: $u = f_x \frac{x_{cam}}{z_{cam}} + c_x$, $v = f_y \frac{y_{cam}}{z_{cam}} + c_y$ [S1, unofficial].
    - Perform frustum culling. Discard Gaussians with $z_{cam} < near\_plane$ or $z_{cam} > far\_plane$. Optional image bounds culling can be applied [S1, unofficial].

3.  **Compute 2D Covariances and Conics:**
    - Rotate the 3D covariance matrix to camera space: $\Sigma_{cam} = R \Sigma_{world} R^T$ [S1, unofficial].
    - Approximate the 2D covariance matrix $\Sigma_{2D}$ using the Jacobian $J$ of the projection function and the top-left $2 \times 2$ submatrix of the rotation matrix $L$: $\Sigma_{2D} = J L \Sigma_{cam} L^T J^T + \epsilon I$, where $\epsilon$ is a small constant (e.g., 0.3) to prevent singularity [S1, unofficial].
    - Compute the conics (inverse 2D covariance) for each Gaussian: $C^{-1} = \Sigma_{2D}^{-1} = \begin{bmatrix} a & b \\ b & c \end{bmatrix}$ [S1, unofficial].

4.  **Compute Bounding Boxes and Assign to Tiles:**
    - Calculate the AABB for each Gaussian in screen space. The extent is determined by the eigenvalues of $\Sigma_{2D}$ scaled by `sigma_multiplier` (typically 3.0 for 3-sigma) [S1, unofficial].
    - Assign each Gaussian to all tiles that its AABB intersects. Store the mapping in `tile_dict` [S1, unofficial].

5.  **Evaluate Colors:**
    - Evaluate the spherical harmonics for each Gaussian to obtain the view-dependent color $C_{sh}$ based on the view direction [S1, unofficial].

6.  **Initialize Output Buffers:**
    - Initialize `color` tensor of shape $[3, H, W]$ to zeros.
    - Initialize `alpha` tensor of shape $[H, W]$ to zeros [S1, unofficial].

7.  **Rasterize Tiles:**
    Iterate over each tile $(tile\_idx\_u, tile\_idx\_v)$ in `tile_dict`:
    - If the tile has no Gaussians, continue.
    - Extract contiguous tensors for the Gaussians in this tile: `opacities_tile`, `sh_colors_tile`, `means_image_tile`, `conics_tile` [S1, unofficial].
    - Calculate pixel bounds for the tile:
      $u_{start} = tile\_idx\_u \times tile\_size$
      $v_{start} = tile\_idx\_v \times tile\_size$
      $u_{end} = \min(u_{start} + tile\_size, W)$
      $v_{end} = \min(v_{start} + tile\_size, H)$ [S1, unofficial].
    - Iterate over pixels $(u_{pix}, v_{pix})$ within the tile bounds.
    - For each pixel, iterate over the Gaussians in the tile.
    - **Early Termination:** If the accumulated alpha at the pixel `alpha[v_pix, u_pix]` is $\ge 0.99$, skip further Gaussians for this pixel (transmittance culling) [S1, unofficial].
    - **Splat Evaluation:**
      - Retrieve Gaussian properties: opacity $\alpha_g$, color $C_g$, conic elements $a, b, c$, and projected mean $(u_g, v_g)$ [S1, unofficial].
      - Compute squared Mahalanobis distance:
        $$dist\_sq = a \cdot (u_{pix} - u_g)^2 + 2 \cdot b \cdot (u_{pix} - u_g) \cdot (v_{pix} - v_g) + c \cdot (v_{pix} - v_g)^2$$
      - Compute the Gaussian weight (unnormalized alpha contribution):
        $$w = \alpha_g \cdot \exp(-0.5 \cdot dist\_sq)$$
      - Update the pixel buffers using alpha blending:
        $$\alpha_{new} = \alpha_{old} + w$$
        $$color_{new} = color_{old} + C_g \cdot w$$
        (Note: Standard alpha blending usually involves dividing by the new alpha or accumulating transmittance, but the source code implies a direct accumulation of weighted color and alpha, followed by background compositing [S1, unofficial]. The exact blending equation in the source is implicit in the accumulation steps).

8.  **Composite Background:**
    - Add the background color:
      $$color = color + bg \cdot (1 - \alpha)$$
    - Clamp `color` to $[0.0, 1.0]$ and convert to uint8 by multiplying by 255 [S1, unofficial].

```python
def tiled_2d_gaussian_splatting_rasterization(gs, camera, tile_size=32, sigma_multiplier=3.0):
    """
    gs: Object containing means (N,3), covariances (N,3,3), opacities (N,), sh_coeffs (N, K)
    camera: Object with fx, fy, cx, cy, width, height, q_world_to_cam, t_world_to_cam
    """
    N = gs.means.shape[0]
    H, W = camera.height, camera.width
    
    # 1. Transform to Camera Space
    # Rotation matrix from quaternion
    R = quaternion_to_rotation_matrix(camera.q_world_to_cam)
    means_cam = (R @ gs.means.T).T + camera.t_world_to_cam
    
    # 2. Project to Image Plane
    z_cam = means_cam[:, 2]
    # Frustum culling
    valid = (z_cam > camera.near_plane) & (z_cam < camera.far_plane)
    means_cam = means_cam[valid]
    opacities = gs.opacities[valid]
    covariances_cam = []
    for i in range(N):
        if valid[i]:
            cov_cam = R @ gs.covariances[i] @ R.T
            covariances_cam.append(cov_cam)
    covariances_cam = torch.stack(covariances_cam)
    
    u = camera.fx * (means_cam[:, 0] / z_cam) + camera.cx
    v = camera.fy * (means_cam[:, 1] / z_cam) + camera.cy
    
    # 3. Compute 2D Covariances and Conics
    # Jacobian of projection
    J = torch.zeros((N, 2, 3))
    J[:, 0, 0] = camera.fx / z_cam
    J[:, 0, 2] = -camera.fx * means_cam[:, 0] / (z_cam ** 2)
    J[:, 1, 1] = camera.fy / z_cam
    J[:, 1, 2] = -camera.fy * means_cam[:, 1] / (z_cam ** 2)
    
    # Top-left 2x2 of rotation
    L = R[:2, :2]
    
    # 2D Covariance approximation
    # Sigma_2D = J @ L @ Sigma_cam @ L.T @ J.T + eps * I
    eps_2d = 0.3
    Sigma_2D = torch.zeros((N, 2, 2))
    for i in range(N):
        cov_3d = covariances_cam[i]
        cov_2d_part = L @ cov_3d[:2, :2] @ L.T
        cov_2d = J[i] @ cov_2d_part @ J[i].T + eps_2d * torch.eye(2)
        Sigma_2D[i] = cov_2d
        
    # Compute Conics (Inverse Covariance)
    # C_inv = [a, b; b, c]
    det = Sigma_2D[:, 0, 0] * Sigma_2D[:, 1, 1] - Sigma_2D[:, 0, 1] * Sigma_2D[:, 1, 0]
    a = Sigma_2D[:, 1, 1] / det
    b = -Sigma_2D[:, 0, 1] / det
    c = Sigma_2D[:, 0, 0] / det
    conics = torch.stack([a, b, c], dim=1)
    
    # 4. Compute Bounding Boxes and Assign to Tiles
    # Extent based on sigma_multiplier
    # Simplified: use eigenvalues or diagonal approximation. 
    # Source uses compute_axis_aligned_bounding_box with use_simple_radius=True
    # Assuming radius is derived from covariance trace or max eigenvalue scaled by sigma_multiplier
    # For implementation, we approximate the bounding box in pixels.
    # Let's assume we have a function to get bbox (u_min, v_min, u_max, v_max)
    bboxes = compute_bounding_boxes(u, v, Sigma_2D, sigma_multiplier)
    
    tile_dict = {}
    for i in range(N):
        if not valid[i]: continue
        u_min, v_min, u_max, v_max = bboxes[i]
        tile_u_min = max(0, int(u_min // tile_size))
        tile_v_min = max(0, int(v_min // tile_size))
        tile_u_max = min(W // tile_size, int(u_max // tile_size))
        tile_v_max = min(H // tile_size, int(v_max // tile_size))
        
        for tu in range(tile_u_min, tile_u_max + 1):
            for tv in range(tile_v_min, tile_v_max + 1):
                key = (tu, tv)
                if key not in tile_dict:
                    tile_dict[key] = []
                tile_dict[key].append(i)
                
    # 5. Initialize Output
    color = torch.zeros((3, H, W))
    alpha = torch.zeros((H, W))
    bg = torch.zeros((3, H, W)) # Assuming black background
    
    # 6. Rasterize
    for (tu, tv), indices in tile_dict.items():
        if not indices: continue
        
        # Extract tile data
        idx_tensor = torch.tensor(indices)
        opacities_tile = opacities[idx_tensor]
        conics_tile = conics[idx_tensor]
        means_tile = torch.stack([u[idx_tensor], v[idx_tensor]], dim=1)
        
        # Evaluate SH colors (simplified)
        colors_tile = evaluate_sh(gs.sh_coeffs[idx_tensor], means_cam[idx_tensor])
        
        # Pixel bounds
        u_start = tu * tile_size
        v_start = tv * tile_size
        u_end = min(u_start + tile_size, W)
        v_end = min(v_start + tile_size, H)
        
        # Iterate pixels
        for v_pix in range(v_start, v_end):
            for u_pix in range(u_start, u_end):
                if alpha[v_pix, u_pix] >= 0.99:
                    continue
                    
                current_alpha = alpha[v_pix, u_pix]
                current_color = color[:, v_pix, u_pix]
                
                for k in range(len(indices)):
                    alpha_g = opacities_tile[k]
                    a, b, c = conics_tile[k]
                    u_g, v_g = means_tile[k]
                    color_g = colors_tile[k]
                    
                    du = u_pix - u_g
                    dv = v_pix - v_g
                    
                    dist_sq = a * du**2 + 2 * b * du * dv + c * dv**2
                    
                    w = alpha_g * torch.exp(-0.5 * dist_sq)
                    
                    current_alpha += w
                    current_color += color_g * w
                    
                alpha[v_pix, u_pix] = current_alpha
                color[:, v_pix, u_pix] = current_color
                
    # 7. Composite Background
    color = color + bg * (1 - alpha)[None, :, :]
    color = torch.clamp(color, 0.0, 1.0)
    
    return color, alpha
```

## Subtopics

### [Non-Tiled 2D Gaussian Splatting with Transmittance Culling](2067-non-tiled-2d-gaussian-splatting-with-transmittance-culling.md)
A rasterization method that iterates over Gaussians rather than tiles, using AABBs to limit pixel iteration and transmittance-based early ray termination. It produces visually identical results to tiled rasterization in most cases but is significantly faster due to early stopping and better culling.

### [Tile-Based Culling](2819-tile-based-culling.md)
Computes a precise Gaussian-to-Tile mapping to cull irrelevant tiles during 3D Gaussian Splatting rasterization. It improves upon standard conservative bounding box assignment by computing tight, opacity-aware bounding boxes and iteratively verifying tile intersections. It is distinguished from SnugBox by its iterative tile examination process, which results in higher runtime costs for the culling phase compared to AccuTile, though it may show marginal downstream performance gains due to undercounting artifacts.

### [Tile-based Rasteriser](2846-tile-based-rasteriser.md)
The GPU-optimized sorting and compositing component of the 3D Gaussian Splatting pipeline that assigns projected 2D Gaussian splats to image tiles and sorts them by depth using a single global radix sort. It solves the performance bottleneck of per-pixel depth sorting for millions of splats by grouping work into tiles, enabling real-time rendering and efficient backpropagation. Unlike non-tiled approaches that sort per pixel or per tile independently, it uses a unified 64-bit key to bin and sort all (splat, tile) pairs in one pass.

### [Gaussian Splat Projection and Sorting](3369-gaussian-splat-projection-and-sorting.md)
A compute-shader-based stage that projects 3D Gaussians to 2D screen space, performs visibility and frustum culling, computes lighting, and prepares data for tile-based sorting. It serves as the bridge between raw 3D Gaussian data and the tiled rasterization pipeline, ensuring that only visible splats are processed and that they are ordered by tile and depth for efficient rendering. It differs from non-tiled approaches by explicitly preparing tile-boundary data and from tile-based culling by handling the full projection and sorting key generation.

### Opacity-Thresholded Tile Intersection Filtering
Filters out Gaussians whose opacity $\tau$ falls below the alpha-threshold $\epsilon$ immediately during tile intersection, as their AABB is considered empty [S2]. Combining this modification with others decreased rendering time on the Bicycle scene at native resolution by a factor of 3.77 and GPU memory usage by a factor of 2.11 compared to the reference [S2].

### Splat Batching Strategy
Splits the rendering of Gaussians into batches. If `gaussians_per_splat` is -1, all Gaussians are splatted in one call. If positive, they are split into batches. Higher values increase speed but raise GPU memory usage [S3, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N \cdot T)$ where $N$ is the number of Gaussians and $T$ is the average number of tiles a Gaussian intersects. The rasterization step is $O(P \cdot G_{tile})$ where $P$ is the number of pixels and $G_{tile}$ is the average number of Gaussians per tile.
- **Memory Complexity:** $O(N + H \cdot W)$ for storing Gaussian data and output buffers. Tile-based culling can reduce memory pressure by avoiding processing irrelevant Gaussians [S2].
- **Performance:** Tiled rasterization enables real-time rendering of large scenes with millions of Gaussians [S1, unofficial][S2]. Performance gains from precomputation and opacity filtering are greatest at higher resolutions [S2].
- **Strengths:** Efficient memory usage, parallelizable on GPU, supports real-time frame rates [S1, unofficial][S2].
- **Limitations:** Requires careful tuning of tile size and sigma multiplier. Performance can degrade if tiles are too small (overhead) or too large (cache misses) [S2].

## Background
Originated from the 3D Gaussian Splatting paper [S1, unofficial][S2]. The tiled rasterization approach was developed to address the scalability issues of naive splatting methods, allowing for real-time rendering of complex scenes [S1, unofficial][S2]. It is widely used in modern 3D Gaussian Splatting implementations [S1, unofficial][S2].
