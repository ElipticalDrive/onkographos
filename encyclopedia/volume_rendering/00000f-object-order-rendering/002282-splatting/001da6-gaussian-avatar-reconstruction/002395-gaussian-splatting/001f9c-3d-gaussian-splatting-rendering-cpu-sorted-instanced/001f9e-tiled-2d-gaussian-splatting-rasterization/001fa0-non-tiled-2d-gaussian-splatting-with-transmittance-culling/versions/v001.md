# Non-Tiled 2D Gaussian Splatting with Transmittance Culling


## Overview
A CPU-based rasterization method for 3D Gaussian Splatting that iterates over Gaussians rather than tiles, using axis-aligned bounding boxes (AABBs) to limit pixel iteration and transmittance-based early ray termination for performance optimization [S1, unofficial]. It produces visually identical results to tiled rasterization in most cases but is significantly faster due to early stopping and better culling [S1, unofficial].

## How it works
**Inputs:**
- `gs`: List of $N$ Gaussians, each with 3D mean, covariance, opacity, and spherical harmonic (SH) coefficients.
- `camera`: Camera object containing intrinsic parameters ($f_x, f_y, c_x, c_y$), image dimensions ($W, H$), and extrinsic rotation/translation [S1, unofficial].
- `sigma_multiplier`: Scaling factor for the 2D covariance approximation (default 3.33) [S1, unofficial].

**Outputs:**
- `rendered_image`: An $H \times W \times 3$ image tensor in uint8 format.

**Data Structures:**
- Gaussian properties are accessed via index `i`.
- `u_mean, v_mean`: Projected 2D mean coordinates.
- `opacity_gaussian`: Scalar opacity.
- `sh_color`: Color vector derived from SH evaluation.
- `a, b, c`: Elements of the inverse 2D covariance matrix (conics).
- `u_min, v_min, u_max, v_max`: Bounding box coordinates in pixel space.
- `color`, `alpha`: $H \times W$ tensors initialized to zero, accumulating final color and alpha.

**Steps:**
1. **Initialization:** Initialize `color` and `alpha` tensors to zeros [S1, unofficial].
2. **Preprocessing:** Perform background initialization, projection, and sorting identical to `render_splats` [S1, unofficial]:
    - Transform means to camera space.
    - Project to image plane.
    - Frustum cull using `fov_margin_ratio=0.3` [S1, unofficial].
    - Sort Gaussians back-to-front.
    - Rotate covariances to camera space.
    - Approximate 2D covariances using `eps_2d=0.3` and `sigma_multiplier` [S1, unofficial].
    - Compute conics ($a, b, c$).
    - Evaluate SH colors.
    - Compute AABBs for each Gaussian.
3. **Rasterization Loop:** Iterate over each Gaussian index `i` from $0$ to $N-1$ [S1, unofficial]:
    - Retrieve properties: `u_mean, v_mean, opacity_gaussian, sh_color, a, b, c, u_min, v_min, u_max, v_max` [S1, unofficial].
    - **Opacity Cull:** If `opacity_gaussian < 0.01`, skip this Gaussian [S1, unofficial].
    - **Pixel Loop:** Iterate over pixel coordinates `u_pix` from `u_min` to `u_max` and `v_pix` from `v_min` to `v_max` [S1, unofficial]:
        - **Boundary Check:** If `0 <= u_pix < W` and `0 <= v_pix < H`, proceed; otherwise skip [S1, unofficial].
        - **Transmittance Cull:** Read current `alpha_pixel` at `(u_pix, v_pix)`. If `alpha_pixel >= 0.99`, skip this Gaussian for this pixel (early termination) [S1, unofficial].
        - **Distance Calculation:** Compute squared Mahalanobis distance with half-pixel offset [S1, unofficial]:
          $$du = u\_pix + 0.5 - u\_mean$$
          $$dv = v\_pix + 0.5 - v\_mean$$
          $$dist\_sq = a \cdot du^2 + 2 \cdot b \cdot du \cdot dv + c \cdot dv^2$$
        - **Alpha/Color Contribution:** Calculate Gaussian alpha $\alpha_g = \exp(-0.5 \cdot dist\_sq) \cdot opacity\_gaussian$. Update pixel alpha and color using alpha blending:
          $$\alpha_{new} = \alpha_{pixel} + \alpha_g \cdot (1 - \alpha_{pixel})$$
          $$color_{new} = color_{pixel} + sh\_color \cdot \alpha_g \cdot (1 - \alpha_{pixel})$$
          Store `alpha_pixel = alpha_new` and `color_pixel = color_new` [S1, unofficial].
4. **Finalization:** Add background color (if applicable) and clamp/convert `color` tensor to uint8 [S1, unofficial].

**Pseudocode:**
```python
def render_splats_fov_cull_transmittance(gs, camera, sigma_multiplier=3.33):
    # 1. Preprocessing (identical to render_splats)
    # Transform means, project, frustum cull (fov_margin_ratio=0.3), sort back-to-front
    # Rotate covariances, approximate 2D covariances (eps_2d=0.3), compute conics
    # Evaluate SH colors, compute AABBs
    # Note: Specific implementation details for preprocessing are assumed from parent method
    
    W, H = camera.width, camera.height
    color = torch.zeros((H, W, 3))
    alpha = torch.zeros((H, W))
    
    # 2. Iterate over Gaussians
    for i in range(len(gs)):
        # Retrieve properties
        u_mean, v_mean = gs[i].u_mean, gs[i].v_mean
        opacity_gaussian = gs[i].opacity
        sh_color = gs[i].sh_color
        a, b, c = gs[i].conics
        u_min, v_min, u_max, v_max = gs[i].aabb
        
        # Opacity cull
        if opacity_gaussian < 0.01:
            continue
            
        # 3. Iterate over pixels in AABB
        for u_pix in range(u_min, u_max + 1):
            for v_pix in range(v_min, v_max + 1):
                # Boundary check
                if 0 <= u_pix < W and 0 <= v_pix < H:
                    # Transmittance cull
                    if alpha[v_pix, u_pix] >= 0.99:
                        continue
                        
                    # Distance calculation
                    du = u_pix + 0.5 - u_mean
                    dv = v_pix + 0.5 - v_mean
                    dist_sq = a * du**2 + 2 * b * du * dv + c * dv**2
                    
                    # Alpha/Color contribution
                    alpha_g = math.exp(-0.5 * dist_sq) * opacity_gaussian
                    alpha_new = alpha[v_pix, u_pix] + alpha_g * (1 - alpha[v_pix, u_pix])
                    color_new = color[v_pix, u_pix] + sh_color * alpha_g * (1 - alpha[v_pix, u_pix])
                    
                    alpha[v_pix, u_pix] = alpha_new
                    color[v_pix, u_pix] = color_new

    # 4. Finalization
    # Add background and clamp/convert to uint8
    return color.clamp(0, 1).to(torch.uint8)
```

## Operating characteristics
- **Time Complexity:** $O(N \cdot A)$, where $N$ is the number of Gaussians and $A$ is the average number of pixels in their AABBs. Early termination reduces effective $A$ for opaque regions.
- **Memory Complexity:** $O(W \cdot H)$ for the color and alpha buffers. No tile-based memory overhead.
- **Performance:** Significantly faster than tiled rasterization (`render_splats_tiled`) due to early stopping and better culling [S1, unofficial].
- **Strengths:** Simple implementation, lower memory overhead than tiled approaches, effective culling for sparse scenes.
- **Limitations:** Less cache-friendly than tiled approaches for dense scenes; performance degrades if many Gaussians overlap significantly without early termination.
- **When to use:** CPU-based rendering, sparse scenes, or when memory is constrained.
- **When not to use:** High-performance GPU rendering or very dense scenes where tile-based parallelism is superior.

## Background
This method is part of the `splaty` library, an unofficial implementation of 3D Gaussian Splatting [S1, unofficial]. It serves as an alternative to tiled rasterization, offering a simpler, non-parallelized approach suitable for CPU execution or educational purposes.
