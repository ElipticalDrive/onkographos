# 2D Gaussian Splatting Rasterization

Also called: 2D Gaussian Splatting Surfel Rasterization

## Overview
2D Gaussian Splatting Rasterization renders a scene represented by 2D Gaussian surfels by projecting them to screen space and performing ray-surfel intersection per pixel, accumulating color, alpha, and normal maps via front-to-back alpha compositing [S1, unofficial]. It differs from the standard 3D Gaussian Splatting Rasterization [2812-3d-gaussian-splatting-rasterization.md] by treating primitives as planar surfels with 2D covariance structures rather than 3D ellipsoids, which simplifies the intersection geometry but requires specific handling of the surfel plane orientation relative to the view ray [S1, unofficial].

## How it works

### Inputs and Outputs
**Inputs:**
*   `means`: 3D positions of surfels, shape `[N, 3]`.
*   `quats`: Rotation quaternions (w, x, y, z), shape `[N, 4]`.
*   `scales`: Scale factors, shape `[N, 3]`.
*   `opacities`: Per-surfel opacity, shape `[N]`.
*   `colors`: Per-surfel color coefficients. If `sh_degree` is not None, shape `[N, K, 3]` where $K$ is the number of SH coefficients. If `sh_degree` is None, shape `[N, D]` where $D$ is the number of color channels (typically 3).
*   `viewmats`: View matrices, shape `[C, 4, 4]`.
*   `Ks`: Camera intrinsic matrices, shape `[C, 3, 3]`.
*   `width`, `height`: Image dimensions.
*   `near_plane`, `far_plane`: Clipping plane distances.
*   `tile_size`: Integer, default 16. Side length of tiles for rasterization.
*   `sh_degree`: Integer or None. If not None, spherical harmonics are evaluated.

**Outputs:**
*   `render_colors`: Computed color per pixel, shape `[C, H, W, channels]`.
*   `render_alphas`: Computed alpha per pixel, shape `[C, H, W, 1]`.
*   `render_normals`: Computed normal per pixel, shape `[C, H, W, 3]`.

### Data Structures
*   **Surfel Properties**: Stored in contiguous arrays or tensors. `means` (float32, `[N, 3]`), `quats` (float32, `[N, 4]`), `scales` (float32, `[N, 3]`), `opacities` (float32, `[N]`).
*   **Projection Outputs**:
    *   `radii`: Radius of the 2D Gaussian bounding circle per surfel per camera, shape `[C, N]`.
    *   `means2d`: Projected 2D center coordinates, shape `[C, N, 2]`.
    *   `depths`: Z-depth of surfel centers, shape `[C, N]`.
    *   `ray_transforms`: Transformation matrices for ray-surfel intersection, shape `[C, N, 3, 3]` (derived from view and projection).
    *   `normals`: Surface normals in world space, shape `[C, N, 3]`.
*   **Tile Indices**:
    *   `isect_offsets`: Encoded intersection offsets, shape `[C, tile_height, tile_width]`.
    *   `flatten_ids`: Flattened list of surfel IDs sorted by depth within tiles.

### Steps

1.  **Projection**: Project 3D surfels to 2D screen space using `fully_fused_projection_2dgs`. This function takes `means`, `quats`, `scales`, `viewmats`, `Ks`, `width`, `height`, `near_plane`, and `far_plane`. It outputs `radii`, `means2d`, `depths`, `ray_transforms`, and `normals` [S1, unofficial].
2.  **Color Preparation**:
    *   Broadcast `opacities` from `[N]` to `[C, N]` [S1, unofficial].
    *   If `sh_degree` is not None:
        *   Compute view directions: `dirs = means[None, :, :] - campos[:, None, :]`.
        *   Normalize `dirs`.
        *   Broadcast color coefficients to `[C, N, K, 3]`.
        *   Evaluate spherical harmonics: `rgb = spherical_harmonics(sh_degree, dirs, coeffs_broadcast)`.
        *   Clamp color: `rgb = max(rgb + 0.5, 0.0)` [S1, unofficial].
    *   If `sh_degree` is None:
        *   Broadcast colors from `[N, D]` to `[C, N, D]` or use directly if already `[C, N, D]` [S1, unofficial].
3.  **Tile Assignment**:
    *   Compute tile dimensions: `tile_width = ceil(width / tile_size)`, `tile_height = ceil(height / tile_size)`.
    *   Call `isect_tiles(means2d, radii, depths, tile_size, tile_width, tile_height, sort=True)` to determine which tiles each surfel intersects. This returns `tiles_per_gauss`, `isect_ids`, and `flatten_ids` (surfel IDs sorted by depth within each tile) [S1, unofficial].
    *   Encode intersection offsets: `isect_offsets = isect_offset_encode(isect_ids, C, tile_width, tile_height)` [S1, unofficial].
4.  **Rasterization**:
    *   Call `rasterize_to_pixels_2dgs` with `means2d`, `ray_transforms`, `colors_for_raster`, `normals`, `opacities_cn`, `width`, `height`, `tile_size`, `isect_offsets`, `flatten_ids`, and `backgrounds`.
    *   This function iterates through surfels in depth order within each tile. For each surfel and pixel it covers, it performs the intersection and compositing steps below [S1, unofficial].

### Intersection and Compositing Formula

For each surfel `gid` in depth order and each pixel `(pxf, pyf)` it covers:

1.  **Ray-Surfel Intersection Vectors**:
    Let $M_g$ be the ray transform matrix for surfel $g$ (from `ray_transforms`). Let $p_x, p_y$ be the pixel coordinates (normalized or screen space as defined by the projection, typically normalized device coordinates or similar relative to the center). The source specifies:
    $$ h_u = -M_g[0, :3] + M_g[2, :3] \cdot p_x $$
    $$ h_v = -M_g[1, :3] + M_g[2, :3] \cdot p_y $$
    Where $M_g[0, :3]$ is the first row's x,y,z components, etc. [S1, unofficial].

2.  **Cross Product and Degeneracy Guard**:
    $$ tmp = h_u \times h_v $$
    If $|tmp[2]| < 10^{-10}$, skip this intersection (degenerate case where rays/surfels are parallel) [S1, unofficial].

3.  **Intersection Coordinates**:
    $$ u_s = \frac{tmp[0]}{tmp[2]} $$
    $$ v_s = \frac{tmp[1]}{tmp[2]} $$
    These $(u_s, v_s)$ represent the coordinates in the local 2D Gaussian space [S1, unofficial].

4.  **Sigma Calculation**:
    Compute 3D sigma from intersection:
    $$ \sigma_{3d} = u_s^2 + v_s^2 $$
    Compute 2D fallback sigma from distance to center (where $dx, dy$ are the 2D distance components from `means2d` to pixel center, or derived from $u_s, v_s$ depending on implementation specifics, but the source explicitly defines a fallback):
    $$ \sigma_{2d} = 2.0 \cdot (dx^2 + dy^2) $$
    Take the tighter bound:
    $$ \sigma = 0.5 \cdot \min(\sigma_{3d}, \sigma_{2d}) $$
    Note: Negative sigma values are skipped to prevent invalid alpha computation [S1, unofficial].

5.  **Alpha Computation**:
    $$ \alpha = \min(\text{opacity} \cdot e^{-\sigma}, \text{MAX\_ALPHA}) $$
    Where `MAX_ALPHA` is a clamping value (e.g., 0.999 or similar, exact value not specified in source, but clamping is required) [S1, unofficial].

6.  **Front-to-Back Compositing**:
    Accumulate color and alpha for the pixel using standard front-to-back alpha blending:
    $$ C_{out} = C_{prev} \cdot (1 - \alpha) + C_{surf} \cdot \alpha $$
    $$ \alpha_{out} = \alpha_{prev} + (1 - \alpha_{prev}) \cdot \alpha $$
    Where $C_{surf}$ is the surfel color and $\alpha$ is the computed alpha. The process starts with background color and zero alpha [S1, unofficial].

### Parameters
*   `tile_size`: Integer, default 16. Side length of tiles for rasterization [S1, unofficial].
*   `near_plane`: Float, default 0.01. Near clipping plane distance [S1, unofficial].
*   `far_plane`: Float, default 1e10. Far clipping plane distance [S1, unofficial].

### Pitfalls
*   **Degenerate Cross Product**: When `tmp[2]` is near zero, the rays and surfels are parallel, leading to division by zero. This is handled by skipping the intersection if `abs(tmp[2]) < 1e-10` [S1, unofficial].
*   **Negative Sigma**: Negative sigma values result in invalid alpha computation (exponential growth). These are skipped [S1, unofficial].
*   **Precision**: The use of `min(sigma_3d, sigma_2d)` requires careful handling of numerical precision, especially for small sigma values [S1, unofficial].

## Operating characteristics

*   **Time Complexity**: $O(N \cdot T)$ where $N$ is the number of surfels and $T$ is the average number of surfels per tile. The tile-based approach reduces the complexity from $O(N \cdot H \cdot W)$ to $O(N + H \cdot W \cdot \text{avg\_surfels\_per\_tile})$.
*   **Memory Complexity**: $O(N + H \cdot W)$ for storing surfel properties and output buffers.
*   **Performance**: The method is optimized for GPU execution via fused kernels (e.g., Metal in the reference implementation). Performance scales with the number of surfels and image resolution. The tile-based approach ensures cache efficiency.
*   **Strengths**: Efficient rasterization of 2D surfels, support for spherical harmonics, differentiable projection (in the full pipeline).
*   **Limitations**: The reference implementation is non-differentiable (NumPy-based). The differentiable path uses a separate `accumulate` function. The method assumes planar surfels, which may not capture complex 3D geometry as well as 3D Gaussians in some cases.

## Background

The 2D Gaussian Splatting Rasterization method is part of the 2D Gaussian Splatting (2DGS) approach, which represents scenes using 2D Gaussian surfels. This method was introduced as an alternative to 3D Gaussian Splatting to improve rendering efficiency and quality for certain types of scenes. The reference implementation is provided by the `gsplat-mlx` library [S1, unofficial].
