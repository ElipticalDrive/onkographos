# 3D Gaussian Splatting Differentiable Rasterizer

Also called: 2D Gaussian Rasterization, 3DGS rasterization pipeline, Gaussian Rasterization (Python/C++ Autograd Wrapper), diff-gaussian-rasterization wrapper

## Overview
The 3D Gaussian Splatting Differentiable Rasterizer is the core rendering engine that projects 3D Gaussian primitives to 2D screen space and accumulates color per pixel using alpha compositing, enabling gradients to flow back to Gaussian parameters (position, scale, rotation, opacity, color) [S2, unofficial]. It differs from naive point-sampling approaches by explicitly handling the 2D covariance transformation and alpha blending order, and from production CUDA implementations by providing a Python/PyTorch-based reference implementation that prioritizes gradient correctness and pedagogical clarity over raw throughput [S2, unofficial]. It builds on [3D Gaussian Splatting Rasterization](2812-3d-gaussian-splatting-rasterization.md) by implementing the specific differentiable accumulation logic required for gradient-based optimization [S2, unofficial].

## How it works
The method consists of a forward rasterization pass that computes pixel colors and a backward pass that computes gradients with respect to the input Gaussian parameters [S2, unofficial]. The implementation described here is a Python/PyTorch reference that iterates over Gaussians, serving as a baseline before transitioning to CUDA kernels [S2, unofficial].

### Inputs and Outputs
**Inputs:**
*   `means3D`: Tensor of shape $(N, 3)$, 3D camera-space centers of $N$ Gaussians.
*   `opacity`: Tensor of shape $(N, 1)$ or $(N)$, per-Gaussian opacity values.
*   `scales`: Tensor of shape $(N, 3)$, per-Gaussian scaling factors.
*   `rotations`: Tensor of shape $(N, 4)$, per-Gaussian quaternions.
*   `colors_precomp`: Tensor of shape $(N, 3)$, precomputed RGB colors (if SH degree is 0).
*   `shs`: Tensor of shape $(N, K, 3)$, Spherical Harmonics coefficients (if `colors_precomp` is not used).
*   `features`: Tensor of shape $(N, D)$, auxiliary features (e.g., normals).
*   `raster_settings`: Object containing camera and rendering configuration (see Layout below).

**Outputs:**
*   `rendered_image`: Tensor of shape $(H, W, 3)$, the composited RGB image.
*   `rendered_opacity`: Tensor of shape $(H, W, 1)$, the accumulated opacity.
*   `rendered_depth`: Tensor of shape $(H, W, 1)$, the accumulated depth.
*   `rendered_feature`: Tensor of shape $(H, W, D)$, accumulated features.
*   `radii`: Tensor of shape $(N)$, the maximum screen-space radius of each Gaussian (used for culling).
*   `num_rendered`: Count of Gaussians contributing to at least one pixel.

### Forward Pass Steps

1.  **Input Validation**: Ensure exactly one of `shs` or `colors_precomp` is provided [S1, unofficial]. Ensure exactly one of (`scales`, `rotations`) or `cov3D_precomp` is provided [S1, unofficial]. Replace missing tensors with empty tensors of appropriate shape [S1, unofficial]. If `features` is None, initialize as empty tensor matching `means3D` feature dimension [S1, unofficial].
2.  **Projection**: Project 3D camera-space centers `xyz_cam` to 2D pixel coordinates `means2D` using the perspective projection formula [S2, unofficial]:
    $$
    \text{means2D}_x = \frac{\text{xyz\_cam}_x \cdot f}{\text{xyz\_cam}_z} + \text{camera}.cx
    $$
    $$
    \text{means2D}_y = \frac{\text{xyz\_cam}_y \cdot f}{\text{xyz\_cam}_z} + \text{camera}.cy
    $$
    where $f$ is derived from the focal length and image dimensions, and `camera.cx`, `camera.cy` are the principal points [S2, unofficial].
3.  **Sorting**: Sort Gaussians by depth (`xyz_cam[:, 2]`) in descending order (back-to-front) to ensure correct alpha compositing order [S2, unofficial].
4.  **Initialization**: Initialize a canvas of zeros with shape $(H, W, 3)$ and a transmittance buffer $T$ of ones with shape $(H, W, 1)$ [S2, unofficial].
5.  **Rasterization Loop**: Iterate through each Gaussian $i$ in the sorted list [S2, unofficial]:
    a.  **Covariance Inverse**: Compute the inverse of the 2D covariance matrix `cov2d[i]` for the current Gaussian: `inv_cov = torch.inverse(cov2d[i])` [S2, unofficial].
    b.  **Displacement**: For each pixel, compute the displacement vector $d$ from the pixel center to the Gaussian mean [S2, unofficial].
    c.  **Power Calculation**: Calculate the exponent for the 2D Gaussian density [S2, unofficial]:
        $$
        \text{power} = -0.5 \cdot (d_x^2 \cdot \text{inv\_cov}_{0,0} + d_y^2 \cdot \text{inv\_cov}_{1,1} + 2 \cdot d_x \cdot d_y \cdot \text{inv\_cov}_{0,1})
        $$
        where $d = [d_x, d_y]$ is the 2D displacement vector and `inv_cov` is the $2 \times 2$ inverse covariance matrix [S2, unofficial].
    d.  **Alpha Computation**: Compute the per-pixel alpha value by exponentiating the power, multiplying by the Gaussian's opacity, and clamping the result to a maximum of 0.99 [S2, unofficial]:
        $$
        \alpha = \text{clamp}(\exp(\text{power}) \cdot \text{opacities}[i], \max=0.99)
        $$
    e.  **Color Update**: Update the canvas color by adding the Gaussian's color weighted by its alpha and the current transmittance [S2, unofficial]:
        $$
        \text{canvas} = \text{canvas} + \text{colors}[i] \cdot \alpha \cdot T
        $$
    f.  **Transmittance Update**: Update the transmittance buffer by multiplying it by $(1 - \alpha)$ [S2, unofficial]:
        $$
        T = T \cdot (1 - \alpha)
        $$
6.  **Final Composition**: Add the background color weighted by the final transmittance $T$ to the canvas [S2, unofficial].

### Backward Pass Steps
The backward pass computes gradients with respect to input Gaussian parameters [S2, unofficial]. It is implemented via a custom autograd wrapper that restores context tensors and invokes a C++ backward kernel or equivalent PyTorch gradient logic [G].

### Pseudocode
```python
import torch

def gaussian_rasterizer_forward(means3D, opacity, scales, rotations, colors_precomp, shs, features, raster_settings):
    """
    Forward pass of the 3D Gaussian Splatting Differentiable Rasterizer.
    Implements projection, sorting, and alpha compositing loop.
    """
    H, W = raster_settings.image_height, raster_settings.image_width
    bg = raster_settings.bg
    cx, cy = raster_settings.cx, raster_settings.cy
    scale_modifier = raster_settings.scale_modifier
    
    # 1. Projection: Project 3D camera-space centers to 2D pixel coordinates [S2, unofficial]
    # f is derived from focal length and image dimensions [S2, unofficial]
    f = raster_settings.focal_length # [G] assumed available or computed from FOV
    xyz_cam = means3D # Assume already in camera space
    means2D_x = (xyz_cam[:, 0] * f / xyz_cam[:, 2]) + cx
    means2D_y = (xyz_cam[:, 1] * f / xyz_cam[:, 2]) + cy
    means2D = torch.stack([means2D_x, means2D_y], dim=-1) # (N, 2)
    
    # 2. Covariance Computation: Compute 2D covariance matrices [G]
    # cov2d shape: (N, 2, 2)
    # cov2d = compute_2d_covariance(means3D, scales, rotations, raster_settings) # [G]
    cov2d = torch.zeros((means3D.shape[0], 2, 2), device=means3D.device) # Placeholder for implementation
    
    # 3. Color Assembly: Select colors from precomputed or SH coefficients [G]
    if colors_precomp is not None:
        colors = colors_precomp
    else:
        # colors = evaluate_sh(shs, raster_settings.sh_degree) # [G]
        colors = torch.zeros_like(means3D[:, :3]) # Placeholder for implementation
        
    # 4. Sorting: Sort Gaussians by depth (z) in descending order [S2, unofficial]
    depths = xyz_cam[:, 2]
    sorted_indices = torch.argsort(depths, descending=True)
    means2D = means2D[sorted_indices]
    cov2d = cov2d[sorted_indices]
    colors = colors[sorted_indices]
    opacity = opacity[sorted_indices]
    
    # 5. Initialization: Canvas and transmittance buffer [S2, unofficial]
    canvas = torch.zeros((H, W, 3), device=means3D.device)
    T = torch.ones((H, W, 1), device=means3D.device)
    
    N = means2D.shape[0]
    
    # 6. Rasterization Loop: Iterate through sorted Gaussians [S2, unofficial]
    for i in range(N):
        # Covariance Inverse [S2, unofficial]
        inv_cov = torch.inverse(cov2d[i]) # (2, 2)
        
        # Displacement vector d from pixel center to Gaussian mean [S2, unofficial]
        pixel_centers = torch.stack(torch.meshgrid(
            torch.arange(W, device=means3D.device), 
            torch.arange(H, device=means3D.device), 
            indexing='ij'
        ), dim=-1).float()
        d = pixel_centers - means2D[i] # (H, W, 2)
        
        # Power Calculation [S2, unofficial]
        power = -0.5 * (
            d[:, :, 0]**2 * inv_cov[0, 0] + 
            d[:, :, 1]**2 * inv_cov[1, 1] + 
            2 * d[:, :, 0] * d[:, :, 1] * inv_cov[0, 1]
        ) # (H, W)
        
        # Alpha Computation [S2, unofficial]
        alpha = torch.clamp(torch.exp(power).unsqueeze(-1) * opacity[i], max=0.99) # (H, W, 1)
        
        # Color Update [S2, unofficial]
        canvas = canvas + colors[i] * alpha * T
        
        # Transmittance Update [S2, unofficial]
        T = T * (1 - alpha)
        
    # 7. Final Composition: Add background weighted by final transmittance [S2, unofficial]
    rendered_image = canvas + bg * T
    
    return rendered_image, T
```

### Parameters
*   `lambda_dssim`: Weight for SSIM term in loss function. Typical value not specified in text [S1, unofficial].
*   `lambda_opacity`: Weight for opacity mask loss. Enabled when $> 0$ [S1, unofficial].
*   `lambda_normal_render_depth`: Weight for normal consistency loss. Typical value `0.01` [S1, unofficial].

### Edge Cases and Pitfalls
*   **Memory Constraints**: The Python/PyTorch loop implementation is slow and memory-intensive for large $N$ [S2, unofficial]. The roadmap indicates a transition to CUDA kernels for real-time performance [S2, unofficial].
*   **Covariance Singularity**: If the 2D covariance matrix is singular, `torch.inverse` will fail. A small epsilon should be added to the diagonal [G].
*   **Alpha Clamping**: Alpha values are clamped to a maximum of 0.99 to prevent division by zero in transmittance updates and ensure numerical stability [S2, unofficial].
*   **Sorting Order**: Incorrect sorting (e.g., front-to-back) will result in incorrect alpha compositing and visual artifacts [S2, unofficial].
*   **Performance**: Not suitable for real-time rendering or large-scale scenes without CUDA optimization [S2, unofficial].

## Subtopics

### [Analytic-Splatting](3025-analytic-splatting.md)
Analytic-Splatting is a differentiable rasterization method that replaces the point-sampling of 2D Gaussians in 3D Gaussian Splatting (3DGS) with an analytical approximation of the integral of the Gaussian signal over the pixel window area. It solves the aliasing artifacts (blurring or jaggies) caused by treating pixels as isolated points when the camera zooms or resolution changes. Unlike [Mip-Splatting](3415-gaussian-splatting-rendering-pipeline.md) which uses a hybrid low-pass filter that suppresses high-frequency details, Analytic-Splatting preserves high-quality details by calculating the integral analytically using a conditioned logistic function approximation of the Gaussian CDF.

### [LinPrim Gradient Computation](3038-linprim-gradient-computation.md)
LinPrim Gradient Computation computes the gradients of intersection depths $\mathbf{i}$ with respect to the ray-space triangle corners $\mathbf{v}^{\text{ray}}$ to enable differentiable rendering of linear primitives (triangles). It differs from standard 3D Gaussian Splatting (3DGS) by backpropagating gradients through a linear primitive rasterizer (MTIA) rather than a Gaussian splatting kernel, requiring specific handling of ray-space to world-space transformations and quaternion-based rotation updates. It builds on [3D Gaussian Splatting Differentiable Rasterizer](2813-3d-gaussian-splatting-differentiable-rasterizer.md) by replacing the Gaussian alpha-blending gradient flow with opacity calculations based on intersection depths.

### [Gaussian Splat Rasterization (Vertex Shader)](3253-gaussian-splat-rasterization-vertex-shader.md)
This method implements the vertex shader stage of a GPU-based rasterizer for 3D Gaussian Splatting, transforming 3D Gaussian primitives into 2D screen-space ellipses for instanced rendering. It differs from fragment-based or compute-shader approaches by performing all geometric projection, covariance transformation, and ellipse basis computation within the vertex shader, passing only the final vertex positions and attributes to the rasterizer. It builds on [3D Gaussian Splatting Differentiable Rasterizer](2813-3d-gaussian-splatting-differentiable-rasterizer.md) by handling the specific data unpacking and frustum culling required for efficient vertex-driven splatting.

### [Gaussian Splatting Rendering Pipeline](3415-gaussian-splatting-rendering-pipeline.md)
The Gaussian Splatting Rendering Pipeline orchestrates camera setup, spherical harmonic (SH) evaluation, feature assembly, and Gaussian rasterization for a single view. It projects 3D Gaussians to 2D screen space, rasterizes them into tiles, and composites them front-to-back using alpha blending to produce novel views. It sets apart from its siblings by managing the pre-computation of covariances, colors, and lighting models, and assembling auxiliary features before invoking the differentiable rasterizer.

### [Backpropagation with Per-Splat Parallelization](3533-backpropagation-with-per-splat-parallelization.md)
This method is a parallelization scheme for the backward pass of 3D Gaussian Splatting rasterization that maps CUDA threads to 2D splats rather than pixels to eliminate atomic contention on gradient accumulation. It differs from the original 3DGS approach, which maps threads to pixels and suffers from serialized atomic operations when multiple threads contend for the same Gaussian's gradient, by having threads maintain per-splat state and exchange smaller per-pixel states (transmittance $T$ and accumulated color $RGB$) via intra-warp shuffling.

### GaussianRasterizer Initialization and Input Validation
Validates mutually exclusive input tensors for color representation and 3D covariance before invoking the CUDA rasterization backend [S1, unofficial]. It checks if exactly one of `shs` or `colors_precomp` is provided, and if exactly one of the scale/rotation pair or `cov3D_precomp` is provided. If both are None or both are not None, it raises an exception. It replaces any missing `shs`, `colors_precomp`, `scales`, `rotations`, or `cov3D_precomp` tensors with empty tensors of appropriate shape. If `features` is None, it initializes it as an empty tensor matching the feature dimension of `means3D` (slice `[..., :0]`). It then calls the CUDA rasterization routine `rasterize_gaussians` with all prepared tensors and `raster_settings` [S1, unofficial].

### GaussianRasterizationSettings
Holds camera and rendering parameters [S1, unofficial]. `tanfovx`/`tanfovy` are the tangent of half horizontal/vertical field of view, computed as `math.tan(camera.FoVx * 0.5)` and `math.tan(camera.FoVy * 0.5)` [S1, unofficial]. `cx`/`cy` are principal point coordinates in pixels, extracted from `intrinsic[0, 2]` and `intrinsic[1, 2]` [S1, unofficial]. `scale_modifier` is a multiplicative scalar applied to Gaussian scales during rasterization, with a default value of 1.0 in `render_view` [S1, unofficial]. `backward_geometry` is a boolean flag passed to the CUDA backend to enable geometry gradient computation [S1, unofficial]. `computer_pseudo_normal` is a boolean flag (note source typo) to enable pseudo-normal computation in the rasterizer [S1, unofficial]. It is a NamedTuple with fields: `image_height` (int), `image_width` (int), `tanfovx` (float), `tanfovy` (float), `cx` (float), `cy` (float), `bg` (torch.Tensor), `scale_modifier` (float), `viewmatrix` (torch.Tensor), `projmatrix` (torch.Tensor), `sh_degree` (int), `campos` (torch.Tensor), `prefiltered` (bool), `backward_geometry` (bool), `computer_pseudo_normal` (bool), `debug` (bool) [S1, unofficial].

## Operating characteristics
*   **Time Complexity**: The Python/PyTorch reference implementation is $O(N \cdot H \cdot W)$ due to the nested loop over Gaussians and pixels, making it interpreter-bound and slow [S2, unofficial]. Production CUDA implementations reduce this to near-linear time with respect to the number of pixels and Gaussians by using tile-based rasterization and parallel processing [S2, unofficial].
*   **Memory Complexity**: $O(N + H \cdot W)$ for storing Gaussian parameters and intermediate buffers (canvas, transmittance) [S2, unofficial]. The Python loop is memory-intensive for large $N$ [S2, unofficial].
*   **Measured Performance**: The reference implementation is capped by consumer-grade VRAM limits and the interpreter-bound nature of the custom rendering loop, preventing dense point-cloud representation typical of production-level 3DGS [S2, unofficial].
*   **Strengths**: Provides a clear, differentiable reference implementation for understanding the 3DGS pipeline. Easy to debug and modify.
*   **Limitations**: Slow due to Python loops. Not suitable for real-time rendering or large-scale scenes without CUDA optimization [S2, unofficial].
*   **When to Use**: For educational purposes, debugging, or as a baseline for developing optimized CUDA kernels [S2, unofficial].
*   **When Not to Use**: For production applications requiring real-time performance or large-scale scene rendering [S2, unofficial].

## Background
The 3D Gaussian Splatting Differentiable Rasterizer is part of the 3D Gaussian Splatting (3DGS) framework, which was introduced for novel view synthesis of static scenes [S2, unofficial]. The method projects 3D Gaussians to 2D screen space and accumulates color per pixel using alpha compositing, allowing gradients to flow back to Gaussian parameters (position, scale, rotation, opacity, color) [S2, unofficial]. The Python/PyTorch reference implementation serves as a pedagogical deep-dive into the mechanics of radiance fields, moving beyond high-level abstractions to implement the differentiable rendering pipeline and volumetric accumulation from first principles [S2, unofficial]. The roadmap indicates a transition to CUDA kernels for real-time performance and efficient memory management [S2, unofficial].
