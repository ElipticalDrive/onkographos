# Perspective-Correct 3D Gaussian Splatting via Plücker Coordinates

Also called: Inversion-free splat evaluation, Plücker coordinate ray-splat intersection

## Overview
This method computes the value of a 3D Gaussian primitive for a given viewing ray in screen space without performing matrix inversion, utilizing Plücker coordinates to represent the ray and calculate the distance to the Gaussian's center [S1]. It sets itself apart from standard 3D Gaussian Splatting rasterization by providing a closed-form, numerically stable solution for perspective-correct splat evaluation that handles degenerate ellipsoids and avoids the computational cost of matrix inversions [S1].

## How it works
**Inputs and Outputs**
*   **Inputs:** Model-view matrix $M \in \mathbb{R}^{4 \times 4}$, projection matrix $P \in \mathbb{R}^{4 \times 4}$, viewport transform $V \in \mathbb{R}^{4 \times 4}$, per-splat attributes defining the transformation $T'$ from normalized splat space to screen space, pixel screen coordinates $(x_s, y_s)$, and hyperparameter $\tau_\alpha$ [S1].
*   **Outputs:** The squared distance $\rho(x)^2$ from the viewing ray to the Gaussian center in splat space, used to evaluate the Gaussian's alpha value [S1].

**Data Structures**
*   **Homogeneous Plane:** Represented as a vector $p = (a, b, c, d)^\top$ such that a point $x$ lies on the plane if $p^\top x = 0$ [S1].
*   **Dual Plücker Coordinates:** Represented as $\mathcal{L}_s^* = (d : m)$, where $d$ is the ray direction and $m$ is the moment around the origin [S1].

**Steps**
1.  **Compute Screen-Space Transformation:** Calculate the transformation matrix $T' \in \mathbb{R}^{4 \times 4}$ from normalized splat space to screen space using per-splat attributes [S1].
2.  **Compute Bounding Box:** Calculate the tight 3D axis-aligned bounding box $[b_1, t_1] \times [b_2, t_2] \times [b_3, t_3]$ in screen space. Let $T'_i$ be the $i$-th row of $T'$. The bounds are computed as:
    $$ b_i = \min(T'_{i,4} / T'_{i,3}, T'_{i,4} / T'_{i,3}) \quad \text{(Note: Source implies min/max logic based on Weyrich et al. extension, exact formula components are } T'_{i,1}, T'_{i,2}, T'_{i,3}, T'_{i,4} \text{)} $$
    Specifically, using component-wise multiplication $\odot$ and dot product $\langle \cdot, \cdot \rangle$, the bounds are derived from the rows of $T'$ [S1]. An individual cutoff value is computed for each splat based on $\tau_\alpha$ to optimize bounding box size when opacity $< 1$ [S1].
3.  **Define Ray Planes:** Represent the viewing ray through pixel $(x_s, y_s)$ as two perpendicular planes in screen space:
    $$ \pi_x = (1, 0, 0, -x_s)^\top $$
    $$ \pi_y = (0, 1, 0, -y_s)^\top $$
    [S1]
4.  **Transform Planes to Splat Space:** Transform $\pi_x$ and $\pi_y$ into splat space using the inverse-transposed mapping $(VPMT)^{-\top}$ to obtain $\pi_{sx}$ and $\pi_{sy}$. This avoids matrix inversion [S1].
5.  **Compute Dual Plücker Coordinates:** Calculate the dual Plücker coordinates $\mathcal{L}_s^*$ from the intersection of $\pi_{sx}$ and $\pi_{sy}$. Let $\pi_{sx} = (a_1 : a_2 : a_3 : a_0)$ and $\pi_{sy} = (b_1 : b_2 : b_3 : b_0)$. The coordinates are:
    $$ d = a_1 b_2 - a_2 b_1 $$
    $$ m_x = a_0 b_2 - a_2 b_0 $$
    $$ m_y = a_1 b_0 - a_0 b_1 $$
    $$ m_z = a_0 b_3 - a_3 b_0 \quad \text{(Derived from standard Plücker intersection, source defines general form)} $$
    [S1]
6.  **Compute Squared Distance:** Calculate $\rho(x)^2$ directly using the equality distance formula:
    $$ \rho(x)^2 = \frac{|m|^2}{|d|^2} $$
    where $|m|^2 = m_x^2 + m_y^2 + m_z^2$ and $|d|^2 = d_x^2 + d_y^2 + d_z^2$ [S1].

**Pseudocode**
```python
def evaluate_gaussian_plucker(M, P, V, T_prime, x_s, y_s, tau_alpha):
    """
    Evaluates the squared distance from a viewing ray to a Gaussian center
    using Plücker coordinates, avoiding matrix inversion.
    
    Args:
        M: Model-view matrix (4x4)
        P: Projection matrix (4x4)
        V: Viewport transform (4x4)
        T_prime: Transformation from normalized splat space to screen space (4x4)
        x_s: Screen x coordinate
        y_s: Screen y coordinate
        tau_alpha: Minimum alpha threshold for bounding box cutoff
        
    Returns:
        rho_sq: Squared distance from ray to Gaussian center
    """
    # Step 1: Define ray planes in screen space
    # Plane equation: ax + by + cz + d = 0
    # Ray through (x_s, y_s) is intersection of x=x_s and y=y_s planes
    pi_x = [1, 0, 0, -x_s]
    pi_y = [0, 1, 0, -y_s]
    
    # Step 2: Transform planes to splat space
    # Planes transform via inverse-transpose of the point transformation matrix.
    # The transformation from splat space to screen space is T_prime.
    # However, the source specifies transforming by (VPMT)^-1.
    # Assuming T_prime already incorporates the necessary view/projection/viewport transforms
    # relative to the splat's local space as per Eq 3 context, we use T_prime.
    # To avoid inversion, we use the property that plane coefficients transform
    # by the inverse-transpose.
    
    # Compute inverse-transpose of T_prime
    # Since T_prime is 4x4, we compute its inverse and transpose.
    # Note: The source emphasizes avoiding inversion. 
    # In practice, if T_prime is affine, we can compute the inverse efficiently.
    # For the sake of this implementation, we assume a generic inverse function exists
    # or we compute it directly. The source claims "sidestepping inversion" by using
    # the plane representation and Plücker coordinates, but the transformation of
    # planes still requires the inverse-transpose of the spatial transform.
    # The key insight is that we don't invert the full VPMT matrix explicitly in a 
    # complex way, but rather use the pre-computed T_prime's inverse-transpose.
    
    T_prime_inv_T = inverse_transpose(T_prime)
    
    # Transform planes
    pi_sx = transform_plane(pi_x, T_prime_inv_T)
    pi_sy = transform_plane(pi_y, T_prime_inv_T)
    
    # Step 3: Compute Dual Plücker Coordinates
    # pi_sx = (a1, a2, a3, a0)
    # pi_sy = (b1, b2, b3, b0)
    a1, a2, a3, a0 = pi_sx
    b1, b2, b3, b0 = pi_sy
    
    # Direction d
    d_x = a1 * b2 - a2 * b1
    d_y = a3 * b1 - a1 * b3 # Corrected cross product component for 3D line from planes
    d_z = a2 * b3 - a3 * b2
    
    # Moment m
    m_x = a0 * b2 - a2 * b0
    m_y = a1 * b0 - a0 * b1
    m_z = a0 * b3 - a3 * b0
    
    # Step 4: Compute squared distance
    # rho^2 = |m|^2 / |d|^2
    d_sq = d_x**2 + d_y**2 + d_z**2
    m_sq = m_x**2 + m_y**2 + m_z**2
    
    if d_sq == 0:
        # Vanishing denominator indicates ray misses splat or is degenerate
        return float('inf')
        
    rho_sq = m_sq / d_sq
    return rho_sq

def transform_plane(plane, inv_T):
    """Transforms a homogeneous plane by the inverse-transpose of a 4x4 matrix."""
    # Plane p transforms as p' = (T^-1)^T * p
    # inv_T is already (T^-1)^T
    return [
        inv_T[0][0]*plane[0] + inv_T[1][0]*plane[1] + inv_T[2][0]*plane[2] + inv_T[3][0]*plane[3],
        inv_T[0][1]*plane[0] + inv_T[1][1]*plane[1] + inv_T[2][1]*plane[2] + inv_T[3][1]*plane[3],
        inv_T[0][2]*plane[0] + inv_T[1][2]*plane[1] + inv_T[2][2]*plane[2] + inv_T[3][2]*plane[3],
        inv_T[0][3]*plane[0] + inv_T[1][3]*plane[1] + inv_T[2][3]*plane[2] + inv_T[3][3]*plane[3]
    ]

def inverse_transpose(M):
    """Computes the inverse-transpose of a 4x4 matrix."""
    import numpy as np
    M_np = np.array(M)
    inv_M = np.linalg.inv(M_np)
    return inv_M.T.tolist()
```

**Parameters**
*   $\tau_\alpha$: Hyperparameter defining the minimum alpha value of a fragment for it not to be skipped during blending. Used to compute individual cutoff values for smaller bounding boxes when opacity $< 1$ [S1].

**Edge Cases and Pitfalls**
*   **Vanishing Denominator:** A vanishing denominator in the distance formula ($|d|^2 = 0$) indicates that the ray misses the splat or the ray direction is degenerate. This case is easily detected and handled [S1].
*   **Degenerate Ellipsoids:** The method provides a closed-form solution that handles degenerate ellipsoids (where the Gaussian is flattened in one or more dimensions) without requiring special casing or matrix inversion [S1].

## Operating characteristics
*   **Time Complexity:** Reduced setup costs per Gaussian compared to standard methods, but slightly higher costs per pixel due to the Plücker coordinate calculations [S1].
*   **Memory Complexity:** Not given in the sources.
*   **Strengths:** Numerically stable; avoids matrix inversion; handles degenerate Gaussians; fast and trivial to differentiate (additions, multiplications, and one division) [S1].
*   **Limitations:** Slightly higher per-pixel cost compared to approximations, making it less ideal when primitives cover many pixels [S1].
*   **When to Use:** Desirable when graphics primitives cover only a few pixels [S1].

## Background
This method was introduced in "Efficient Perspective-Correct 3D Gaussian Splatting Using Hybrid Transparency" [S1]. It builds on Weyrich et al.'s optimization of Sigg et al.'s bounding box computation [SWBG06] and extends it to non-degenerate 3D Gaussians. It also follows Radl et al. [RSP*24] for opacity-based cutoffs and contrasts with concurrent works like [YSG24, MLMP*24] which use numerically unstable or slower approaches [S1].
