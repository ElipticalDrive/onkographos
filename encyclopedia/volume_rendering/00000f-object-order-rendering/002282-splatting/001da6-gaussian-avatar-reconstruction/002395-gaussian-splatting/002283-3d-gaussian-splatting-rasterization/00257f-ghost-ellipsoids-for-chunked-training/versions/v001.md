# Ghost Ellipsoids for Chunked Training

Also called: Ghost cell techniques adapted for unstructured primitives

## Overview
Ghost Ellipsoids for Chunked Training resolves boundary artifacts in chunked volume training by including ellipsoids from neighboring chunks in the loss computation without updating their parameters, providing boundary context without requiring a global volume or merged model [S1, unofficial]. Unlike chunk-based 3DGS methods that resolve boundary inconsistencies by merging chunks into a global coarse model or through post-training stages, this method requires boundary support during training itself without access to a global volume [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of 3D ellipsoids (primitives) partitioned into spatial chunks. Each chunk has a defined spatial extent and a normalized coordinate space.
*   **Output:** Updated parameters for the current chunk's ellipsoids, with boundary context provided by "ghost" ellipsoids from neighbors.

**Data Structures:**
*   **Chunk:** A spatial subdivision of the volume. Each chunk maintains its own set of ellipsoids.
*   **Ellipsoid Primitive:** Defined by position $\mathbf{p}$, rotation matrix $R$, scale matrix $S$, and covariance $\Sigma = KRS S^T R^T K^T$ (where $K$ is a scaling factor, though the text implies $\Sigma$ is the primary representation). Positions are stored with a per-chunk spatial offset mapping them to the shared world coordinate system [S1, unofficial].
*   **Ghost Region:** A boundary region around each chunk, defined by the chunk boundary offset, used to identify neighboring ellipsoids that influence the current chunk's loss [S1, unofficial].

**Steps:**
1.  **Chunk Partitioning:** Divide the volume into chunks. Each chunk is trained in its own normalized coordinate space scaled to its spatial extent (e.g., $[-0.5, 0.5]^3$ for a volume split into $2 \times 2 \times 2$ chunks) [S1, unofficial].
2.  **Ghost Ellipsoid Identification:** For each chunk, identify boundary ellipsoids from all neighboring chunks (face-, edge-, and vertex-adjacent). This is done by selecting those ellipsoids whose centers fall within the ghost region of the current chunk [S1, unofficial].
3.  **Voxelization and Loss Computation:** Voxelize the ghost ellipsoids together with the current chunk's ellipsoids during the loss computation step [S1, unofficial].
4.  **Gradient Update:** Ensure that ghost ellipsoids receive no gradient updates. Only the parameters of the ellipsoids belonging to the current chunk are updated [S1, unofficial].
5.  **Training Mode Selection:**
    *   **Sequential Mode (Single-GPU):** Chunks are trained one at a time. Ghost ellipsoids are taken from neighbors that have already been completed [S1, unofficial].
    *   **Parallel Mode (Multi-GPU):** All chunks are trained simultaneously. Ghost ellipsoids are periodically synchronized across GPUs [S1, unofficial].

**Pitfalls and Edge Cases:**
*   **Coordinate Space Rescaling:** Training all chunks in a shared $[-1, 1]^3$ space and applying post-hoc rescaling is computationally impractical. It requires computing $\Sigma' = K \Sigma K^T = K R S S^T R^T K^T$ for each primitive, where $K$ is a chunk-dependent anisotropic scale matrix. Since $K$ and $R$ do not generally commute, this cannot be simplified by scaling $S$ alone. Correctly decomposing $\Sigma'$ back into rotation and scale parameters requires a QR decomposition per primitive [S1, unofficial].
*   **Merging:** The per-chunk primitive sets resulting from this method can be merged through simple concatenation without additional alignment, avoiding the need for global model merging [S1, unofficial].

## Operating characteristics
*   **Complexity:** Not given in the sources.
*   **Performance:** Not given in the sources.
*   **Strengths:** Eliminates boundary artifacts without requiring a global volume or merged model. Avoids computationally expensive QR decompositions associated with post-hoc rescaling.
*   **Limitations:** Requires identification of neighboring ellipsoids and synchronization (in parallel mode). Not given in the sources.
*   **When to use:** When training large volumes on limited GPU memory by chunking, and boundary consistency is critical.
*   **When not to use:** When a global model can be afforded or when post-training merging is acceptable.

## Background
The technique is inspired by ghost cell techniques [45], but adapted for unstructured primitives. Classical ghost cells copy boundary values from adjacent regular grid cells, but this method cannot rely on grid adjacency since the primitives are spatially unstructured [S1, unofficial]. The method addresses the incompatibility of standard 3DGS screenspace rasterization with accurate TF mapping in volumetric settings [S1, unofficial].
