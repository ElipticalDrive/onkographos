# Row-constant hoisting for Gaussian Splatting Rasterization

Also called: row-constant optimization, inner-loop hoisting

## Overview
Row-constant hoisting is an optimization for the inner pixel loop of a Gaussian splatting rasterizer that hoists row-constant terms outside the inner (column) loop to minimize arithmetic operations per pixel [S1, unofficial]. It reduces the computational cost of evaluating the 2D Gaussian exponent by precomputing terms dependent only on the row coordinate, allowing the inner loop to perform fewer multiplications and additions per pixel [S1, unofficial]. This method is a specific implementation detail of the rasterization step in [Gaussian Splatting](946-gaussian-splatting.md), distinct from alternative rasterization strategies like [Ray-marching on 3D Gaussians](1036-ray-marching-on-3d-gaussians.md) or [2D Gaussian Projection with Covariance Stabilization](1198-2d-gaussian-projection-with-covariance-stabilization.md).

## How it works
### Inputs and Outputs
- **Input**: A projected Gaussian primitive $p$ with screen-space center $(sx, sy)$, bounding box $[x_0, y_0, x_1, y_1]$, inverse covariance matrix elements $a, b, d$ (where $a = \Sigma^{-1}_{0,0}$, $b = \Sigma^{-1}_{0,1} = \Sigma^{-1}_{1,0}$, $d = \Sigma^{-1}_{1,1}$), opacity $\alpha_p$, and color $C_p$.
- **Input**: A framebuffer `fb` of width $w$, where each cell stores accumulated color and opacity.
- **Input**: Parameters `saturation` (max accumulated opacity) and `alpha_threshold` (min alpha for contribution).
- **Output**: Updated framebuffer cells for pixels covered by the splat.

### Data Structures
- **Framebuffer Cell**: A tuple `(Vec3, f32)` storing the accumulated color (3 floats) and accumulated opacity (1 float) [S1, unofficial].
- **Projected Gaussian**: Contains screen coordinates, bounding box, inverse covariance matrix components, opacity, and color [S1, unofficial].

### Numbered Steps
1. Extract inverse covariance elements $a, b, d$ from the projected Gaussian's inverse covariance matrix [S1, unofficial].
2. Compute coefficients for the quadratic form:
   - $dx_{coeff} = -0.5 \cdot a$
   - $dy_{coeff} = -0.5 \cdot d$
   - $cross_{coeff} = -b$ (derived from $-0.5 \cdot 2 \cdot b$) [S1, unofficial]
3. Initialize `saturation` and `alpha_threshold` from parameters [S1, unofficial].
4. Iterate over each row $py$ from $y_0$ to $y_1$ inclusive:
   a. Compute $dy = py - sy$ [S1, unofficial].
   b. Precompute row-constant terms:
      - $row_{base} = dy_{coeff} \cdot dy^2$
      - $row_{slope} = cross_{coeff} \cdot dy$
      - $row_{offset} = py \cdot w$ (for framebuffer indexing) [S1, unofficial]
   c. Iterate over each column $px$ from $x_0$ to $x_1$ inclusive:
      i. Calculate framebuffer index $idx = row_{offset} + px$ [S1, unofficial].
      ii. Check saturation: if `fb[idx].opacity >= saturation`, skip to next pixel [S1, unofficial].
      iii. Compute $dx = px - sx$ [S1, unofficial].
      iv. Calculate the power term: $power = dx_{coeff} \cdot dx^2 + row_{slope} \cdot dx + row_{base}$ [S1, unofficial].
      v. If $power > 0.0$, skip the pixel (exponential would exceed 1 or be invalid) [S1, unofficial].
      vi. Compute alpha: $\alpha = (\alpha_p \cdot e^{power}).\min(0.999)$ [S1, unofficial].
      vii. If $\alpha < alpha_{threshold}$, skip the pixel [S1, unofficial].
      viii. Compute contribution: $t = 1.0 - fb[idx].opacity$, $contrib = t \cdot \alpha$ [S1, unofficial].
      ix. Update framebuffer: `fb[idx].color += contrib * C_p`, `fb[idx].opacity += contrib` [S1, unofficial].

### Formulas
The Gaussian exponent power is calculated as:
$$power = dx_{coeff} \cdot dx^2 + row_{slope} \cdot dx + row_{base}$$
where:
- $dx_{coeff} = -0.5 \cdot a$
- $row_{slope} = -b \cdot dy$
- $row_{base} = -0.5 \cdot d \cdot dy^2$
- $a, b, d$ are elements of the inverse covariance matrix
- $dx, dy$ are screen-space offsets from the Gaussian center [S1, unofficial]

### Parameters
- **saturation**: The maximum accumulated opacity value in the framebuffer cell. If reached, further splats are skipped [S1, unofficial].
- **alpha_threshold**: The minimum alpha value for a splat to contribute. Splats with alpha below this are skipped [S1, unofficial].

### Edge Cases and Pitfalls
- If the computed power is positive, the exponential term would exceed 1 (or be invalid for the Gaussian model), so the splat is skipped for that pixel [S1, unofficial].
- Alpha is clamped to 0.999 to prevent numerical issues when blending [S1, unofficial].

### Pseudocode
```python
def composite_splat(p: Projected, fb: List[Tuple[Vec3, float]], w: int, params: RenderParams) -> None:
    x0, y0, x1, y1 = p.bbox
    a = p.cov2d_inv[0, 0]  # (0,0)
    b = p.cov2d_inv[0, 1]  # (0,1) = (1,0) since symmetric
    d = p.cov2d_inv[1, 1]  # (1,1)
    
    dx_coeff = -0.5 * a
    dy_coeff = -0.5 * d
    cross_coeff = -b  # -0.5 * 2 * b
    
    saturation = params.saturation
    alpha_threshold = params.alpha_threshold
    opacity = p.opacity
    color = p.color
    sx = p.screen.x
    sy = p.screen.y
    
    for py in range(y0, y1 + 1):
        dy = py - sy
        row_base = dy_coeff * dy * dy
        row_slope = cross_coeff * dy
        row_offset = py * w
        
        for px in range(x0, x1 + 1):
            idx = row_offset + px
            cell = fb[idx]
            
            if cell[1] >= saturation:
                continue
                
            dx = px - sx
            power = dx_coeff * dx * dx + row_slope * dx + row_base
            
            if power > 0.0:
                continue
                
            alpha = min(opacity * fast_exp(power), 0.999)
            
            if alpha < alpha_threshold:
                continue
                
            t = 1.0 - cell[1]
            contrib = t * alpha
            cell[0] += contrib * color
            cell[1] += contrib
```

## Operating characteristics
- **Time Complexity**: Reduces the number of multiplications and additions per pixel in the inner loop by hoisting row-constant terms. The exact reduction depends on the number of operations moved outside the loop.
- **Memory Complexity**: No additional memory required beyond precomputed row constants, which are stored in registers or local variables.
- **Measured Performance**: Not given in the sources.
- **Scaling**: Performance improvement scales with the number of pixels per splat and the number of splats. More efficient for large splats covering many pixels.
- **Strengths**: Reduces arithmetic operations per pixel, leading to faster rasterization. Simple to implement.
- **Limitations**: Only optimizes the inner loop; other parts of the rasterization pipeline may become bottlenecks. Requires careful handling of bounding boxes and edge cases.
- **When to Use**: When rasterizing many large Gaussians and performance is critical.
- **When Not to Use**: For very small splats or when other parts of the pipeline are the bottleneck.

## Background
Row-constant hoisting is an optimization technique applied to Gaussian splatting rasterization. It is described in the context of the "tsplat" project, which aims to run Gaussian splatting in a terminal environment [S1, unofficial].
