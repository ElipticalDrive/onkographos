# Gaussian Avatars

Also called: FLAME Gaussian Splatting, PSAvatar, PSAvatar / Relightable Avatar, Relightable Avatar

## Overview
Gaussian Avatars is a head-driven, riggable avatar reconstruction method that uses the FLAME parametric model to constrain 3D Gaussians to the surface of a bust mesh [S1][S3, unofficial]. It differs from full-body approaches like [Gaussian Avatar](1575-gaussian-avatar-reconstruction.md) by focusing on high-fidelity facial details and enabling relighting through a light rig [S2, unofficial].

## How it works
**Inputs:** Multi-view video of a talking head; initial FLAME mesh fit (e.g., via MICA or DECA) [S2, unofficial].
**Outputs:** A set of Gaussians parameterized by position, covariance, opacity, and spherical harmonics (color), constrained to the FLAME mesh.

**Data Structures:**
1.  **FLAME Mesh:** A triangulated mesh of the bust. Each triangle $T_i$ has vertices $v_1, v_2, v_3$.
2.  **Gaussian Set:** One Gaussian $G_j$ is initialized per triangle $T_j$.
    *   **Position:** Initialized in the local tangent space of the triangle center, then mapped to world space.
    *   **Covariance:** Defined by scale and rotation.
    *   **Color:** Represented by spherical harmonics coefficients.
    *   **Opacity:** Scalar.

**Steps:**
1.  **Initialization:** Fit a FLAME model to the input video frames to obtain a canonical mesh [S2, unofficial]. For each triangle $T_j$ in the mesh, initialize a Gaussian $G_j$. The position is set to the triangle centroid. The orientation is aligned with the triangle normal. The scale is proportional to the triangle area [S2, unofficial].
2.  **Deformation:** For a target pose $\theta$ (head rotation) and expression $\beta$ (facial shape), the FLAME model deforms the mesh vertices $V(\theta, \beta)$. The Gaussian positions are updated by transforming their local offsets using the deformation of the enclosing triangle's vertices. Specifically, if a Gaussian is associated with triangle $T_j$ with vertices $v_1, v_2, v_3$, its position $p$ in the canonical frame is barycentrically interpolated. In the posed frame, the new position $p'$ is computed by applying the same barycentric weights to the deformed vertices $v'_1, v'_2, v'_3$ [S1][S3, unofficial].
3.  **Color Prediction:** The color of each Gaussian is optimized directly as spherical harmonics coefficients. Some variants use a lightweight MLP conditioned on pose and expression to predict color offsets, but the core method optimizes SH coefficients per Gaussian [S1][S3, unofficial].
4.  **Rendering:** The Gaussians are splatted onto the image plane using standard differentiable rasterization [S1][S3, unofficial].
5.  **Optimization:** Minimize the photometric loss between the rendered image and the ground truth video frame. The loss includes L1 and D-SSIM terms. The FLAME parameters (pose, expression) are optimized alongside the Gaussian attributes (opacity, SH coefficients, and potentially small position offsets) [S2, unofficial].

**Pseudocode:**
```python
def gaussian_avatars_render(flame_mesh, gaussians, pose, expression, camera):
    """
    Render a frame using Gaussian Avatars.
    flame_mesh: Triangulated mesh with vertices V.
    gaussians: List of Gaussian objects, each linked to a triangle index.
    pose: Head rotation parameters.
    expression: Facial expression parameters.
    camera: Camera intrinsics and extrinsics.
    """
    # 1. Deform FLAME mesh
    deformed_vertices = flame_mesh.deform(pose, expression)
    
    # 2. Update Gaussian positions based on triangle deformation
    for g in gaussians:
        triangle_idx = g.triangle_index
        v1, v2, v3 = deformed_vertices[triangle_idx]
        # Barycentric interpolation of the canonical position
        # g.barycentric_coords are pre-computed for the canonical mesh
        g.position = (g.barycentric_coords[0] * v1 + 
                      g.barycentric_coords[1] * v2 + 
                      g.barycentric_coords[2] * v3)
        
        # Update orientation to align with deformed triangle normal
        normal = cross(v2 - v1, v3 - v1)
        g.rotation = align_to_normal(normal)
        
    # 3. Rasterize
    image = splat_render(gaussians, camera)
    return image
```

**Parameters:**
*   **Learning Rate:** Standard 3DGS learning rates [S2, unofficial].
*   **Regularization:** Not explicitly detailed in sources, but typically includes opacity pruning [G].

**Edge Cases:**
*   **Degenerate Triangles:** Triangles with zero area in the canonical mesh may cause initialization issues. [G] Filter out or merge such triangles.
*   **Precision:** Barycentric interpolation must be precise to avoid artifacts at triangle boundaries. [G] Use double precision for position updates if necessary.

## Operating characteristics
*   **Time Complexity:** Rendering is linear in the number of Gaussians $N$, same as standard 3DGS. Training time is comparable to other Gaussian avatar methods, depending on the complexity of the deformation network if used [S2, unofficial].
*   **Memory Complexity:** $O(N)$, where $N$ is the number of triangles in the FLAME mesh. Typically $N \approx 10^4-10^5$ for a high-quality bust mesh [S2, unofficial].
*   **Strengths:** High-fidelity facial details; riggable; supports relighting [S2, unofficial].
*   **Limitations:** Limited to head/bust; requires initial FLAME fit [S2, unofficial].
*   **When to use:** When high-quality talking head avatars are needed.
*   **When not to use:** For full-body avatars or non-human subjects.

## Background
Gaussian Avatars was introduced by [S1][S3, unofficial] as a method to reconstruct human avatars using 3DGS. It addresses the challenges of dynamic Gaussians and relighting by constraining Gaussians to a FLAME mesh. It is distinct from Gaussian Head Avatar (GHA) which uses MLPs for deformation, and Gaussian Avatar which uses SMPL for full-body [S1][S3, unofficial].
