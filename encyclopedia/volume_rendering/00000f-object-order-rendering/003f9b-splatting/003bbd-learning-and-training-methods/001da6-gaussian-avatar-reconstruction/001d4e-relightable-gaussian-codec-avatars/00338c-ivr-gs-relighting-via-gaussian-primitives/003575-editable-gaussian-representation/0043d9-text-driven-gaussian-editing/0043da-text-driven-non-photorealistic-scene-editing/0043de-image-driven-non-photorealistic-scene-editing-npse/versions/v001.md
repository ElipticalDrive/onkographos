# Image-Driven Non-Photorealistic Scene Editing (NPSE)

Also called: Image-Driven NPSE, TexGS-VolVis Image-Driven NPSE

## Overview
Image-Driven Non-Photorealistic Scene Editing (NPSE) stylizes volume visualization scenes by transferring the artistic style of a reference image onto a 3D Gaussian representation, ensuring multi-view consistency. It distinguishes itself from sibling methods like [StyleSplat](11108-text-driven-non-photorealistic-scene-editing.md) by embedding texture attributes within Gaussian primitives, allowing each primitive to express multiple colors and reducing elliptical artifacts, while leveraging a combined NNFM and CLIP loss strategy to capture both local and global style patterns.

## How it works
**Inputs:**
*   A set of multi-view input images of the scene.
*   A reference style image.
*   Text prompts (optional, used for classifier-free guidance in the IP2P model).

**Outputs:**
*   A set of textured Gaussian primitives representing the stylized scene.

**Data Structures:**
*   **Gaussian Primitive:** Defined by position, covariance, opacity, base color, and a **texture attribute**. The texture attribute allows the primitive to store multiple color values, enabling complex style expression.
*   **Model Storage:** The model size is dominated by the texture attributes, which constitute over 90% of the total storage [S1].

**Parameters:**
*   **Classifier-free guidance scale:** Set to 1.25 for input multi-view images and 12.5 for text prompts when using the Stable Diffusion model IP2P [S1].
*   **Rendering Resolution:** 800x800 pixels in reported experiments [S1].

**Steps:**
1.  **Initialization:** Initialize Gaussian primitives from the input multi-view images.
2.  **Optimization:** Optimize the Gaussian parameters (position, covariance, opacity, base color, and texture attributes) to match the reference style.
3.  **Loss Calculation:** Compute the total loss using a combination of:
    *   **Neural Style Loss (NNFM):** To preserve detailed style patterns and ensure multi-view consistency.
    *   **CLIP Loss:** To capture global style patterns from the reference image [S1].
    *   *Note:* While other methods may use only VGG-based losses, TexGS-VolVis explicitly combines NNFM and CLIP [S1].
4.  **Rendering:** Render the scene using the optimized textured Gaussian primitives. The texture attribute allows each Gaussian to express multiple colors during rendering, enhancing expressive capacity [S1].

**Edge Cases and Pitfalls:**
*   **Elliptical Artifacts:** Vanilla Gaussian primitives (representing only a single color) can lead to unnatural elliptical distortions, especially at the ends of objects like wood textures [S1]. The texture attribute mitigates this.
*   **Performance:** The additional lighting and texture mapping computations make rendering slightly slower than methods like StyleSplat [S1].
*   **Optimization Time:** Using both VGG and CLIP during optimization makes TexGS-VolVis slightly slower than ARF and StyleSplat in terms of editing time [S1].

## Subtopics

### TexGS-VolVis
The primary implementation of Image-Driven NPSE described in the sources. It uses textured Gaussian primitives and a combined NNFM/CLIP loss. Choose this when high-fidelity, multi-color style transfer with multi-view consistency is required. [TexGS-VolVis](11108-text-driven-non-photorealistic-scene-editing.md)

### StyleSplat
A baseline method using vanilla Gaussian primitives (single color per primitive). It is faster and has a smaller model size but produces less detailed results and suffers from elliptical artifacts. [StyleSplat](11108-text-driven-non-photorealistic-scene-editing.md)

### ARF
A NeRF-based baseline using Plenoxels and NNFM loss. It requires significantly more storage due to its explicit feature grid. [ARF](11108-text-driven-non-photorealistic-scene-editing.md)

### StyleRF-VolVis
A NeRF-based baseline using a palette color network and unrestricted color network with NNFM loss. It has the slowest rendering time among the compared methods. [StyleRF-VolVis](11108-text-driven-non-photorealistic-scene-editing.md)

## Operating characteristics
**Time and Memory Complexity:**
*   **Editing Time:** TexGS-VolVis takes 8.0 minutes for 800x800 resolution, compared to 6.9 minutes for StyleSplat and 5.9 minutes for ARF [S1].
*   **Model Size:** TexGS-VolVis uses 223 MB, significantly larger than StyleSplat (89 MB) due to texture attributes, but smaller than ARF (975 MB) [S1].
*   **Rendering Time:** TexGS-VolVis has a mean/max rendering time of 11.82/13.32 ms, which is faster than StyleRF-VolVis (243.61/348.58 ms) but slightly slower than StyleSplat (6.11/10.27 ms) [S1].
*   **Primitive Count:** TexGS-VolVis uses 129,857 primitives, far fewer than StyleSplat's 357,090, while producing more detail-rich results [S1].

**Strengths and Limitations:**
*   **Strengths:** Produces more detailed and expressive results than baselines. Captures local and global style patterns. Uses fewer primitives. Multi-view consistency is maintained.
*   **Limitations:** Slower optimization due to CLIP loss. Larger model size than StyleSplat. Slightly slower rendering than StyleSplat.

**When to Use:**
*   Use when high-quality, multi-color stylization with multi-view consistency is needed, and storage/compute for optimization is available.
*   Avoid if minimal model size or fastest rendering speed is the primary constraint (use StyleSplat instead).

## Background
TexGS-VolVis was introduced in the paper "TexGS-VolVis: Expressive Scene Editing for Volume Visualization via Textured Gaussian Splatting" [S1]. It builds upon the Gaussian Splatting technique and extends it with texture attributes for non-photorealistic rendering in volume visualization contexts. The method addresses the limitations of single-color Gaussian primitives in capturing complex artistic styles.
