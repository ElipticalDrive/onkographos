# Text-Driven Non-Photorealistic Scene Editing

Also called: Image-driven NPSE, Text-Driven Gaussian Editing (for VolVis), Text-driven NPSE, Texture-Attribute Non-Photorealistic Scene Editing (NPSE)

## Overview
Text-Driven Non-Photorealistic Scene Editing (NPSE) stylizes volume visualization (VolVis) scenes represented by textured Gaussian primitives using text instructions, while Image-Driven NPSE performs the same task using a reference image prompt [S1]. Both variants optimize only the texture attributes of the Gaussian representation to preserve the underlying geometry and lighting, distinguishing them from methods that alter geometry or require iterative multi-view consistency updates [S1]. It sets itself apart from siblings like [StyleSplat](11108-text-driven-non-photorealistic-scene-editing.md) by embedding texture maps within Gaussian primitives to express complex style patterns and reduce elliptical artifacts, leveraging a one-time update strategy for text-driven editing to avoid the blurriness associated with iterative approaches in semi-transparent scenes [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A pre-trained TexGS-VolVis scene (Gaussian primitives with geometry $\mu$, shading $\beta$, and texture attributes), a text prompt (for text-driven) or an image prompt $I_{prmt}$ (for image-driven), and optionally a 2D segmentation mask for region-specific editing [S1].
*   **Outputs:** An optimized TexGS-VolVis scene with modified texture attributes that reflect the stylized appearance [S1].

**Data Structures:**
The method operates on Gaussian primitives enhanced with a texture attribute [S1]. Each primitive stores:
*   Geometry attributes (e.g., mean position $\mu$) [S1].
*   Shading attributes (e.g., $\beta$) [S1].
*   Texture attributes: A texture map (set of texels) associated with the primitive [S1].
*   Opacity: A scalar value controlling transparency [S1].
*   View-independent color $c_{ind}$: Used only if the texture attribute is disabled [S1].

**Numbered Steps:**

1.  **Initialization:**
    *   For **Image-Driven NPSE**: Randomly initialize all Gaussian texture maps [S1]. Define the view-independent color using the texture-sampled color, ignoring palette colors [S1].
    *   For **Text-Driven NPSE**: Initialize the scene opacity at $2\times$ its target value [S1].
    *   Fix all geometry attributes ($\mu$) and shading attributes ($\beta$) to preserve consistent geometry and lighting [S1].

2.  **Prompt Generation (Text-Driven Only):**
    *   Use the IP2P model (based on Stable Diffusion) to generate edited images from unedited multi-view images and the text instruction [S1].
    *   Set classifier-free guidance scale for input multi-view images to 1.25 [S1].
    *   Set classifier-free guidance scale for text prompts to 12.5 [S1].
    *   [G] Ensure the IP2P model is loaded and configured with the specified guidance scales before inference.

3.  **Optimization Loop:**
    *   Select training views. For text-driven NPSE, use only six views (front, back, left, right, top, bottom) to reduce ambiguity [S1]. For image-driven NPSE, use the full set of training views (e.g., 162 uniformly sampled via icosphere sampling) [S1].
    *   Render the scene $R$ from the selected training views using Blinn-Phong shading [S1].
    *   Calculate the loss function based on the editing type:
        *   **Image-Driven:** Use $L_{img}$ (defined below) [S1].
        *   **Text-Driven:** Use an RGB reconstruction loss between the rendered image $R$ and the IP2P-generated edited image [S1].
    *   Update only the texture attributes (or $c_{ind}$ if texture is disabled) via gradient descent [S1].
    *   **Opacity Adjustment (Text-Driven Only):** Gradually reduce the scene's opacity from the initial $2\times$ target value to $0.5\times$ over fixed iteration intervals to prevent occlusion of unedited primitives and reduce blurriness from inconsistent edits [S1].

4.  **Iteration Count:**
    *   For **Image-Driven NPSE**: Optimize for 3,000 iterations [S1].
    *   For **Text-Driven NPSE**: Optimize for 1,500 iterations using the IP2P editing images [S1].

5.  **Region-Specific Editing (Optional):**
    *   If editing specific regions, use a 2D-lift-3D segmentation approach:
        *   Render a view from TexGS-VolVis [S1].
        *   Use a 2D segmentation model (e.g., SAM) with user-specified point prompts to generate a 2D mask [S1].
        *   Lift the 2D mask to 3D by identifying and segmenting the corresponding Gaussian primitives [S1].
        *   Apply the editing optimization only to the primitives in the segmented group [S1].

**Formulas:**

The loss function for image-driven NPSE is:
$$ L_{img} = \lambda_s L_{NNFM}(R, I_{prmt}) + (1 - \lambda_s) \| C(R) - C(I_{prmt}) \|_2 $$

Where:
*   $R$ is the rendered image from TexGS-VolVis [S1].
*   $I_{prmt}$ is the image prompt [S1].
*   $C$ is a pretrained CLIP model [S1].
*   $L_{NNFM}$ is the Neural Network Feature Matching (NNFM) loss using a pretrained VGG-16 network to capture fine stylization details [S1].
*   $\| C(R) - C(I_{prmt}) \|_2$ is the L2 distance between feature vectors extracted by CLIP, encouraging global style consistency [S1].
*   $\lambda_s$ is the hyperparameter balancing fine details and global style [S1].

If the texture attribute is not used, the appearance is edited by updating the view-independent color $c_{ind}$ within each primitive [S1].

**Parameters:**
*   $\lambda_s$: Hyperparameter balancing fine stylization details and global style consistency [S1].
    *   $\lambda_s = 0.0$: Emphasizes global style patterns [S1].
    *   $\lambda_s = 0.5$: Intermediate balance [S1].
    *   $\lambda_s = 0.9$: Emphasizes finer, more localized style details (default) [S1].
    *   $\lambda_s = 1.0$: Maximum emphasis on fine details [S1].
*   Training Image Resolution:
    *   800×800 for image-driven editing (balances quality and fitting time) [S1].
    *   512×512 for text-driven editing (avoids out-of-memory issues with IP2P) [S1].
*   Training Views: 162 uniformly sampled via icosphere sampling is sufficient; increasing beyond this yields marginal gains [S1].
*   Iterations: 3,000 for image-driven; 1,500 for text-driven [S1].

**Edge Cases and Pitfalls:**
*   **Text Prompt Accuracy:** Text-based editing relies heavily on the IP2P model. Inaccurate or vague text prompts lead to erroneous editing results [S1].
*   **Opacity Issues:** High opacity causes occlusion, leaving uncovered primitives unedited. Low opacity leads to blurry stylization due to inconsistent IP2P edits across views. The gradual opacity reduction strategy mitigates this [S1].
*   **Storage:** The texture attribute can occupy significant storage space, especially with high texel counts, resulting in larger model sizes compared to other Gaussian Splatting methods [S1].
*   **Segmentation Efficiency:** The 2D-lift-3D segmentation method requires identifying and segmenting corresponding Gaussian primitives for each 2D mask, which can be inefficient for scenes requiring multiple rounds of segmentation [S1].

**Pseudocode:**

```python
import random
import torch
import torch.nn.functional as F

def text_driven_npse(texgs_volvis, text_prompt, num_iterations=1500):
    # 1. Generate edited images using IP2P model on 6 training views
    training_views = [0, 1, 2, 3, 4, 5] # front, back, left, right, top, bottom
    edited_images = []
    for view_idx in training_views:
        unedited_image = render(texgs_volvis, view_idx)
        # [S1] IP2P model (Stable Diffusion-based) generates edited image
        # Classifier-free guidance scales: 1.25 for image, 12.5 for text
        edited_img = ip2p_generate(unedited_image, text_prompt, 1.25, 12.5)
        edited_images.append(edited_img)

    # 2. Initialize opacity at 2x target value
    target_opacity = texgs_volvis.get_target_opacity()
    current_opacity = 2.0 * target_opacity
    texgs_volvis.set_opacity(current_opacity)

    # 3. Fix geometry and shading attributes
    texgs_volvis.freeze_geometry()
    texgs_volvis.freeze_shading()

    # 4. Optimization loop
    for i in range(num_iterations):
        # Gradually reduce opacity to 0.5x target over fixed iteration intervals
        progress = i / max(num_iterations - 1, 1)
        current_opacity = target_opacity * (2.0 - 1.5 * progress)
        texgs_volvis.set_opacity(current_opacity)

        # Render and compute RGB reconstruction loss
        total_loss = 0.0
        for view_idx, edited_img in zip(training_views, edited_images):
            rendered_img = render(texgs_volvis, view_idx)
            loss = F.mse_loss(rendered_img, edited_img)
            total_loss += loss

        # Update only texture attributes (or c_ind if texture is disabled)
        texgs_volvis.texture_attributes.retain_grad()
        total_loss.backward()
        texgs_volvis.texture_attributes.data -= 0.01 * texgs_volvis.texture_attributes.grad

    return texgs_volvis

def image_driven_npse(texgs_volvis, image_prompt, lambda_s=0.9, num_iterations=3000):
    # 1. Initialize texture maps randomly
    texgs_volvis.initialize_texture_maps_randomly()
    # Define view-independent color using texture-sampled color
    texgs_volvis.set_view_independent_color_from_texture()

    # 2. Fix geometry and shading attributes
    texgs_volvis.freeze_geometry()
    texgs_volvis.freeze_shading()

    # 3. Optimization loop
    for i in range(num_iterations):
        # Select a random training view
        view_idx = random.randint(0, len(texgs_volvis.training_views) - 1)
        rendered_img = render(texgs_volvis, view_idx)

        # Compute L_img loss
        # [S1] NNFM loss using pretrained VGG-16 for fine details
        nnfm_loss = nnfm_loss_function(rendered_img, image_prompt)
        # [S1] CLIP loss for global style consistency
        clip_feat_r = clip_model_encode(rendered_img)
        clip_feat_p = clip_model_encode(image_prompt)
        clip_loss = F.mse_loss(clip_feat_r, clip_feat_p)
        loss = lambda_s * nnfm_loss + (1 - lambda_s) * clip_loss

        # Update texture attributes
        texgs_volvis.texture_attributes.retain_grad()
        loss.backward()
        texgs_volvis.texture_attributes.data -= 0.01 * texgs_volvis.texture_attributes.grad

    return texgs_volvis

def render(texgs_volvis, view_idx):
    # Standard differentiable splatting/volume rendering
    return texgs_volvis.render(view_idx)

def ip2p_generate(image, prompt, scale_img, scale_txt):
    # [S1] Calls pretrained IP2P model with given guidance scales
    # Returns edited image tensor
    return image

def nnfm_loss_function(rendered, prompt):
    # [S1] Computes Neural Network Feature Matching loss using pretrained VGG-16
    # Returns scalar loss
    return F.mse_loss(rendered, prompt)

def clip_model_encode(image):
    # [S1] Extracts feature vector using pretrained CLIP model
    return image
```

## Subtopics

### [Image-Driven Non-Photorealistic Scene Editing (NPSE)](11113-image-driven-non-photorealistic-scene-editing-npse.md)
Stylizes volume visualization scenes by transferring the artistic style of a reference image onto a 3D Gaussian representation, ensuring multi-view consistency. It distinguishes itself from sibling methods like [StyleSplat](11108-text-driven-non-photorealistic-scene-editing.md) by embedding texture attributes within Gaussian primitives, allowing each primitive to express multiple colors and reducing elliptical artifacts, while leveraging a combined NNFM and CLIP loss strategy to capture both local and global style patterns.

## Operating characteristics
*   **Time Complexity:** The method requires iterative optimization [S1]. Image-driven NPSE takes approximately 3,000 iterations, while text-driven NPSE takes 1,500 iterations [S1]. Fitting time is influenced by the number of primitives and training image resolution [S1].
*   **Memory Complexity:** The texture attribute can occupy significant storage space, especially as the number of texels increases, resulting in a larger model size than other Gaussian Splatting methods [S1]. Text-driven editing uses lower resolution (512×512) to avoid out-of-memory issues with the IP2P model [S1].
*   **Strengths:** Real-time rendering, expressive style patterns via texture attributes, geometry-consistent editing without iterative updates for text-driven NPSE, and flexible partial editing via 2D-lift-3D segmentation [S1].
*   **Limitations:** High storage requirements for texture attributes, reliance on IP2P model quality for text-driven editing, and potential inefficiency in 2D-lift-3D segmentation for complex scenes [S1].
*   **When to Use:** When high-quality, expressive non-photorealistic stylization of volume visualization scenes is required, and real-time rendering is needed [S1].
*   **When Not to Use:** When storage space is limited, or when precise text prompts are not available for text-driven editing [S1].

## Background
TexGS-VolVis is the first 2DGS-based framework in VolVis aimed at expressive scene editing [S1]. It builds upon existing NeRF and 3DGS scene editing approaches guided by text instructions [S1]. The method was introduced in the paper "TexGS-VolVis: Expressive Scene Editing for Volume Visualization via Textured Gaussian Splatting" [S1]. It addresses the challenges of applying iterative editing strategies to complex and semi-transparent VolVis scenes, which often result in blurry appearances or geometry-inconsistent edits [S1].
