# UV-based motion parameterization

Also called: Motion parameterization scheme

## Overview
UV-based motion parameterization is a technique for modeling dynamic human deformation by reparameterizing 3D spatial coordinates into 2D surface-level UV coordinates combined with time [S1]. It solves the problem of high-dimensional motion field learning by exploiting the prior that human motion occurs primarily at the surface level, reducing the input dimensionality from 4D space-time to 3D surface-time [S1]. This approach is significantly more memory efficient and converges faster than methods using raw 3D coordinates [S1].

## How it works
The method refines the rigid transformation provided by Linear Blend Skinning (LBS) with a residual deformation network [S1]. It operates on query points in world space, transforming them to canonical space and then parameterizing them for the residual network [S1].

**Inputs and Outputs:**
*   **Inputs:**
    *   Query point in world space $\mathbf{x}$ (or canonical space after inverse LBS).
    *   Pose parameters $\rho$ (used for LBS).
    *   Time $t$.
    *   UV coordinates $(u, v)$ corresponding to the query point on the canonical SMPL mesh [S1].
*   **Outputs:**
    *   Residual deformation $\Delta\Phi(u, v, t)$ [S1].
    *   Final deformed position $\Phi(\mathbf{x}, w, u, v, \rho, t)$ [S1].

**Data Structures:**
*   **UV Coordinates:** 2D vector $(u, v)$ representing the position on the canonical parametric mesh surface [S1].
*   **Time:** Scalar $t$ [S1].
*   **Residual Deformation Network ($MLP_{res}$):** A Multi-Layer Perceptron that takes encoded $(u, v, t)$ as input and outputs the residual offset [S1].
*   **Multiresolution Hash Encoding ($\psi_{res}$):** A hash-based encoding function applied to the input $(u, v, t)$ [S1].

**Steps:**
1.  **Rigid Transformation:** Compute the rigidly transformed point $\Phi_{LBS}(\mathbf{x}, w, \rho)$ using Linear Blend Skinning with pose parameters $\rho$ [S1]. This maps the point from world space to the deformed canonical space [S1].
2.  **Parameterization:** Concatenate the current time $t$ with the UV coordinates $(u, v)$ of the query point to form the input vector $(u, v, t)$ [S1]. This reparameterizes the 4D space-time query into a 3D surface-time domain [S1].
3.  **Encoding:** Apply multiresolution hash encoding $\psi_{res}$ to the concatenated input $(u, v, t)$ [S1].
4.  **Residual Prediction:** Forward the encoded input through the network $MLP_{res}$ to regress the residual deformation $\Delta\Phi$ [S1].
5.  **Final Deformation:** Add the residual deformation to the rigidly transformed point to obtain the final deformed position [S1].

**Formulas:**
The residual deformation is defined as:
$$ \Delta\Phi(u, v, t) = MLP_{res} (\psi_{res} (u, v, t)) $$
where $\Delta\Phi$ is the residual deformation [S1].

The full human motion is defined as:
$$ \Phi(\mathbf{x}, w, u, v, \rho, t) = \Phi_{LBS} (\mathbf{x}, w, \rho) + \Delta\Phi(u, v, t) $$
where $\Phi_{LBS}$ is the LBS transformation, and $\Delta\Phi$ is the residual [S1].

**Pseudocode:**
```python
def uv_motion_parameterization(x_world, pose_params, time_t, uv_coords):
    """
    Computes the final deformed position using UV-based motion parameterization.
    
    Args:
        x_world: 3D point in world space.
        pose_params: Human pose parameters (rho).
        time_t: Current time frame.
        uv_coords: 2D UV coordinates (u, v) on the canonical mesh.
        
    Returns:
        final_position: 3D deformed position.
    """
    # Step 1: Rigid Transformation via LBS
    # Note: Inverse LBS is required to map world space to canonical space
    # before applying the residual. The source cites [43] for inverse LBS derivation.
    x_canonical = inverse_lbs(x_world, pose_params)
    
    # Step 2: Rigidly deform to the target pose in canonical space
    # w represents the skinning weights derived from pose_params
    phi_lbs = lbs_transform(x_canonical, pose_params.weights, pose_params)
    
    # Step 3: Concatenate time with UV coordinates
    # Input vector for the residual network
    input_vector = concatenate([time_t, uv_coords]) # Shape: (3,)
    
    # Step 4: Multiresolution Hash Encoding
    # psi_res is the multiresolution hash encoding function
    encoded_input = multiresolution_hash_encoding(input_vector)
    
    # Step 5: Regress residual deformation
    # MLP_res is the residual deformation network
    delta_phi = mlp_res(encoded_input)
    
    # Step 6: Combine rigid and residual deformation
    final_position = phi_lbs + delta_phi
    
    return final_position
```

**Parameters and Typical Values:**
*   **Network Size:** The source notes that when using positional encoding of $(x, t)$ as a baseline, a larger network is required for $MLP_{res}$, but does not specify the exact layer counts or hidden dimensions for the UV-based variant [S1].
*   **Hash Encoding:** Uses multiresolution hash encoding [48] [S1]. Specific grid resolutions or hash table sizes are not given in the sources.

**Edge Cases and Pitfalls:**
*   **UV Mapping:** The method relies on the query point having a valid UV coordinate on the canonical mesh. Points far from the surface or in non-manifold regions may not have well-defined UVs [S1].
*   **Dimensionality Reduction Assumption:** The method assumes motion is primarily surface-level. If significant volumetric deformation occurs (e.g., internal organ movement), the accuracy may degrade [S1].

## Subtopics

### Residual Deformation Module
The Residual Deformation Module is the specific component that regresses the residual deformation $\Delta\Phi$ using the UV-based motion parameterization [S1]. It takes the concatenated $(u, v, t)$ input, applies multiresolution hash encoding $\psi_{res}$, and passes it through $MLP_{res}$ to output the residual [S1]. This module is crucial for capturing non-rigid effects like muscle jiggles that LBS cannot model [S1]. It is more memory efficient than alternatives using 3D coordinates [S1].

## Operating characteristics
*   **Memory Efficiency:** The $(u, v, t)$ parameterization is significantly more memory efficient than using 4D space-time $(x, t)$ inputs [S1].
*   **Convergence Speed:** The method reduces the dimensionality of the motion field, leading to a boost in convergence rate. It can be optimized at 1/100 of the time of previous methods [S1].
*   **Performance:** On an RTX 3090 GPU, the method can produce photorealistic free-viewpoint videos from a 100-frame monocular video of $512 \times 512$ resolution in minutes [S1].
*   **Comparison with Alternatives:** The $(u, v, t)$ input outperforms other tested variants:
    1.  Positional encoding of $(x, t)$ [S1].
    2.  Hash encoded $x$ + per-frame learnable latent code [S1].
    3.  Hash encoded $x$ + pose parameter [S1].
*   **Limitations:** The method is designed for dynamic humans. It may not directly apply to scenes with complex background entities without extension (e.g., combining with STNeRF) [S1].

## Background
The UV-based motion parameterization scheme was introduced in the paper "Learning Neural Volumetric Representations of Dynamic Humans in Minutes" [S1]. It was inspired by displacement map and bump map techniques from traditional Computer Graphics pipelines [S1]. The key observation was that typical human motion happens at the surface level, allowing the reduction of 4D volumetric motion to the 3D surface-time domain [S1]. This approach was shown to be superior to naive $(x, y, z, t)$ encoding and other latent code-based methods [S1].
