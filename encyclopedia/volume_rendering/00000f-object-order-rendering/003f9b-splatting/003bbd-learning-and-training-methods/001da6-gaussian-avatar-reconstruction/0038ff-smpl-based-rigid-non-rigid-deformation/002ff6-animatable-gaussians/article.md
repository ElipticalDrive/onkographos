# Animatable Gaussians

## Overview
Animatable Gaussians is a method for reconstructing animatable 3D human avatars from multi-view video by binding 3D Gaussians to an SMPL-X parametric model [S1, unofficial]. It solves the problem of generating high-fidelity, pose-dependent geometry by using explicit pose-conditioned offsets rather than implicit deformation fields [S1, unofficial]. It is distinguished from siblings like [3DGS-Avatar](1480-3dgs-avatar.md) by its use of explicit offsets instead of per-Gaussian MLPs, and from [Gaussian Avatar](1479-gaussian-avatar.md) by its reliance on the SMPL-X rig rather than FLAME for full-body representation [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Multi-view video of a human subject; pre-fitted SMPL-X parameters (pose $\theta$, shape $\beta$, translation $t$) for each frame [S1, unofficial].
*   **Outputs:** A set of 3D Gaussians $\{g_i\}$ in canonical space, each with position $\mathbf{p}_i$, covariance $\Sigma_i$, opacity $\alpha_i$, and spherical harmonics coefficients $\mathbf{c}_i$, along with a deformation network $f_{def}$ [S1, unofficial].

**Data Structures:**
*   **Canonical Gaussians:** Stored in a flat array. Each Gaussian $i$ has:
    *   $\mathbf{p}_i \in \mathbb{R}^3$: Canonical position.
    *   $\Sigma_i \in \mathbb{R}^{3 \times 3}$: Covariance matrix (often stored as rotation $\mathbf{R}_i \in \mathbb{R}^{3 \times 3}$ and scale $\mathbf{s}_i \in \mathbb{R}^3$).
    *   $\alpha_i \in [0, 1]$: Opacity.
    *   $\mathbf{c}_i$: Spherical harmonics coefficients (dimension depends on degree $L$, typically $4(L+1)^2$).
*   **Deformation Network:** A small MLP $f_{def}(\mathbf{p}, \theta)$ that outputs a residual offset $\Delta \mathbf{p}$ [S1, unofficial].

**Steps:**
1.  **Initialization:** Initialize Gaussians on the surface of the SMPL-X mesh in the canonical rest pose (pose $\theta=0$) [S1, unofficial].
2.  **Rigid Deformation:** For a target pose $\theta$, compute the rigidly transformed position $\mathbf{p}_{rigid}$ using Linear Blend Skinning (LBS) [S1, unofficial]:
    $$ \mathbf{p}_{rigid} = \text{LBS}(\mathbf{p}, \theta) = \sum_{j=1}^{N_{bones}} w_j(\mathbf{p}) \mathbf{T}_j(\theta) \mathbf{p} $$
    where $w_j$ are skinning weights and $\mathbf{T}_j$ are bone transformation matrices [S1, unofficial].
3.  **Non-Rigid Deformation:** Compute the residual offset $\Delta \mathbf{p}$ using the deformation network conditioned on the canonical position and target pose:
    $$ \Delta \mathbf{p} = f_{def}(\mathbf{p}, \theta) $$
    The final deformed position is:
    $$ \mathbf{p}' = \mathbf{p}_{rigid} + \Delta \mathbf{p} $$
4.  **Covariance Update:** Update the covariance matrix to account for deformation using the Jacobian $J = \frac{\partial \mathbf{p}'}{\partial \mathbf{p}}$ [G]:
    $$ \Sigma' = J \Sigma J^T + \sigma^2 I $$
    where $\sigma^2$ is a small regularization term [G].
5.  **Rendering:** Render the deformed Gaussians using standard differentiable Gaussian splatting [S1, unofficial].
6.  **Training:** Optimize Gaussian parameters and network weights by minimizing photometric loss $\mathcal{L}_{L1}$ and perceptual loss $\mathcal{L}_{MS-SSIM}$ between rendered and target images [S1, unofficial].

**Parameters:**
*   Learning rate: Not given in the sources.
*   Number of Gaussians: Not given in the sources.
*   Deformation network depth/width: Not given in the sources.

**Edge Cases:**
*   **Degenerate Poses:** Extreme poses may cause skinning weights to become unstable or the Jacobian to become singular [G].
*   **Precision:** Floating-point precision in Jacobian computation may affect gradient stability [G].

## Subtopics

### GSMs
GSMs is a variant that generates animatable 3D humans using a model prior (SMPL) and generative adversarial networks [S2]. It builds multi-layer shells from the SMPL template and binds 3D Gaussians on these shells [S2]. Animatable 3D humans are efficiently generated by utilizing the differentiable rendering of 3DGS and the generative adversarial network of StyleGAN2 [S2].

## Operating characteristics
*   **Time Complexity:** Training time depends on the number of Gaussians and the complexity of the deformation network [S1, unofficial].
*   **Memory Complexity:** Memory usage is proportional to the number of Gaussians and the size of the deformation network [S1, unofficial].
*   **Performance:** High-fidelity results are achievable with multi-view video input [S1, unofficial].
*   **Strengths:** Explicit offsets allow for efficient deformation and high-quality results [S1, unofficial].
*   **Limitations:** Requires multi-view video input and pre-fitted SMPL-X parameters [S1, unofficial].
*   **When to use:** When high-fidelity animatable avatars are needed and multi-view video is available [S1, unofficial].
*   **When not to use:** When only monocular video is available or when computational resources are limited [S1, unofficial].

## Background
Animatable Gaussians was introduced as part of the broader effort to create animatable 3D avatars using Gaussian Splatting [S1, unofficial]. It builds on the principles of SMPL-based deformation and differentiable rendering [S1, unofficial]. The method is cited in surveys of 3D Gaussian Splatting variants [S1, unofficial].
