# GoMAvatar

Also called: Gaussian Monocular Avatar

## Overview
GoMAvatar is a monocular video avatar reconstruction method that embeds 3D Gaussians onto a canonical human body mesh driven by the SMPL-X rig [S2, unofficial]. It solves the problem of reconstructing high-fidelity dynamic human avatars from single-camera video by coupling Gaussian parameters with mesh geometry, allowing for realistic novel animation in real time [S1]. Unlike methods that rely on per-Gaussian deformation MLPs, GoMAvatar determines Gaussian positions via barycentric coordinates and normal displacements on the canonical mesh [S1].

## How it works
**Inputs:** Monocular video sequence; SMPL-X mesh parameters (pose, shape, expression) fitted to the video frames.
**Outputs:** A set of 3D Gaussians representing the dynamic human avatar, parameterized by position, covariance, opacity, and spherical harmonics coefficients.

**Data Structures:**
*   **Canonical Mesh:** A static human body mesh (e.g., SMPL-X template) with $N$ vertices and $F$ triangles.
*   **Gaussian Attributes:** For each Gaussian $i$:
    *   Position offset $\mathbf{d}_i$ (3D vector) in canonical space.
    *   Rotation $\mathbf{q}_i$ (quaternion, 4 floats).
    *   Scale $\mathbf{s}_i$ (3D vector).
    *   Opacity $\alpha_i$ (scalar).
    *   Color coefficients $\mathbf{c}_i$ (Spherical Harmonics).

**Steps:**
1.  **Embedding:** Gaussians are initialized on the canonical human body mesh. Each Gaussian is associated with a specific triangle or vertex region of the mesh [S1].
2.  **Position Determination:** The canonical position $\mathbf{p}_{canon}$ of a Gaussian is determined by its barycentric coordinates $(u, v, w)$ within a mesh triangle and a displacement along the vertex normal direction [S1].
    *   Let $\mathbf{v}_1, \mathbf{v}_2, \mathbf{v}_3$ be the vertices of the triangle.
    *   Let $\mathbf{n}$ be the normal at the barycentric point.
    *   $\mathbf{p}_{canon} = u\mathbf{v}_1 + v\mathbf{v}_2 + w\mathbf{v}_3 + \delta \mathbf{n}$, where $\delta$ is the learned displacement magnitude [S1].
3.  **Deformation:** For a target pose and expression, the canonical mesh is deformed to the target space using the SMPL-X rig. The Gaussians are transformed accordingly. The position in the target space $\mathbf{p}_{target}$ is obtained by applying the rigid/non-rigid transformation defined by the SMPL-X model to $\mathbf{p}_{canon}$ [S1].
4.  **Rendering:** The deformed Gaussians are projected and splatted onto the image plane. The rendering loss (e.g., L1, SSIM) is computed against the input video frame.
5.  **Optimization:** The Gaussian parameters (offsets, scales, rotations, colors) and potentially the displacement $\delta$ are optimized to minimize the rendering error while maintaining mesh consistency [S1].

**Pseudocode:**
```python
# Canonical space setup
canonical_mesh = load_smplx_template() # N vertices, F faces
gaussians = initialize_gaussians_on_mesh(canonical_mesh) # Assign barycentric coords (u,v,w) to each Gaussian

def get_canonical_position(gaussian, canonical_mesh):
    """Get canonical 3D position from barycentric coords and normal displacement."""
    triangle = get_triangle(canonical_mesh, gaussian.face_id)
    v1, v2, v3 = triangle.vertices
    n = triangle.normal
    # Barycentric interpolation
    p_surface = gaussian.u * v1 + gaussian.v * v2 + gaussian.w * v3
    # Add normal displacement
    p_canon = p_surface + gaussian.displacement * n
    return p_canon

def deform_to_target(p_canon, smplx_params, canonical_mesh):
    """Deform canonical point to target pose/expression using SMPL-X."""
    # SMPL-X provides a transformation matrix T for each vertex
    # Interpolate T based on barycentric coords of the parent triangle
    T = interpolate_transform(canonical_mesh, smplx_params, gaussian.u, gaussian.v, gaussian.w)
    # Apply affine transformation
    p_target = T @ p_canon
    return p_target

def render_and_optimize(video_frame, smplx_params, gaussians):
    p_canon = get_canonical_position(gaussians, canonical_mesh)
    p_target = deform_to_target(p_canon, smplx_params, canonical_mesh)
    # Transform rotation and scale accordingly
    # Project to 2D and splat
    rendered_image = splat(p_target, gaussians.rotation, gaussians.scale, gaussians.opacity, gaussians.color)
    loss = compute_loss(rendered_image, video_frame)
    optimize(gaussians, loss)
```

**Parameters:**
*   Learning rate for Gaussian attributes: Not given in the sources.
*   SMPL-X fitting accuracy: Critical for initial pose/shape estimation [S2, unofficial].

**Edge Cases:**
*   **Unbalanced Aggregation:** Densification and splitting operations can cause unbalanced aggregation of Gaussians. This may require surface-guided re-initialization strategies to ensure Gaussians fit the input video well [S1].
*   **Boundary Conditions:** Gaussians near mesh boundaries or holes may have undefined normals or barycentric coordinates. Not given in the sources.

## Subtopics

### Gaussian Avatar
The parent method using SMPL as a prior with pose features predicting Gaussian parameters via a feed-forward network. GoMAvatar builds on this by using SMPL-X and mesh embedding [1479-gaussian-avatar.md].

### HUGS
The first SMPL-driven body Gaussian Splatting method, using the SMPL rig [S2, unofficial].

### 3DGS-Avatar
Uses SMPL-X with per-Gaussian deformation MLPs, differing from GoMAvatar's barycentric/normal displacement approach [S2, unofficial].

### AnimatableGaussians
Uses SMPL-X with explicit pose-conditioned offsets, offering an alternative to GoMAvatar's mesh-coupled deformation [S2, unofficial].

### SplattingAvatar
Embeds Gaussians in mesh tangent space, similar to GoMAvatar but with a different local coordinate system definition [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Real-time novel animation is supported [S1]. Training time is not explicitly given, but similar methods (e.g., Human101) achieve high-fidelity creation in ~100 seconds with fixed-perspective cameras [S1].
*   **Memory Complexity:** Proportional to the number of Gaussians embedded on the mesh. The number of Gaussians is determined by the mesh resolution and densification strategies [S1].
*   **Strengths:** Monocular video input; real-time animation; leverages strong SMPL-X priors for realistic human structure [S2, unofficial].
*   **Limitations:** Relies on accurate SMPL-X fitting; potential issues with Gaussian aggregation if densification is not managed [S1].
*   **When to use:** When reconstructing dynamic human avatars from monocular video with a need for real-time animation and realistic body structure.
*   **When not to use:** When multi-view data is available and higher geometric fidelity without mesh priors is required; or when head-only avatars are needed (use FLAME-based methods like GaussianAvatars) [S2, unofficial].

## Background
GoMAvatar was introduced as part of the evolution of Gaussian Splatting for human avatar reconstruction. It is listed among methods using the SMPL-X rig, specifically noted for being a monocular video method coupled with a mesh [S2, unofficial]. It addresses the limitations of earlier SMPL-driven methods by embedding Gaussians directly onto the canonical mesh using barycentric coordinates and normal displacements, providing a structured approach to dynamic human modeling [S1].
