# GoMAvatar


## Overview
GoMAvatar is a monocular video avatar reconstruction method that embeds 3D Gaussians onto a canonical human body mesh driven by the SMPL-X rig [S2, unofficial]. It solves the problem of reconstructing high-fidelity dynamic human avatars from single-camera video by coupling Gaussian parameters with mesh geometry, allowing for realistic novel animation in real time [S1]. Unlike methods that rely on per-Gaussian deformation MLPs, GoMAvatar determines Gaussian positions via barycentric coordinates and normal displacements on the canonical mesh [S1].

## How it works
**Inputs:** Monocular video sequence; SMPL-X mesh parameters (pose, shape, expression) fitted to the video frames [S2, unofficial].
**Outputs:** A set of 3D Gaussians representing the dynamic human avatar [S1].
**Data Structures:** Gaussians are stored with fields for triangle indices, barycentric coordinates, normal direction, and learned displacement magnitude [S1].
**Steps:**
1. Embed Gaussians onto a canonical human body mesh [S1].
2. Determine the position of each Gaussian using its barycentric coordinates within a mesh triangle and a displacement along the vertex normal direction [S1].
3. Deform the canonical mesh to the target pose and expression using the SMPL-X rig, transforming the Gaussians accordingly [S1].
4. Render the deformed Gaussians and optimize parameters to minimize rendering loss against the input video frame [S1].
**Formulas:**
The canonical position $\mathbf{p}_{\text{canon}}$ is computed as:
$$\mathbf{p}_{\text{canon}} = u\mathbf{v}_1 + v\mathbf{v}_2 + w\mathbf{v}_3 + \delta \mathbf{n}$$
where $(u, v, w)$ are the barycentric coordinates, $\mathbf{v}_1, \mathbf{v}_2, \mathbf{v}_3$ are the triangle vertices, $\mathbf{n}$ is the interpolated normal at the barycentric point, and $\delta$ is the learned normal displacement [S1].
**Pseudocode:**
```python
def compute_canonical_position(triangle_vertices, barycentric_coords, normal, displacement):
    v1, v2, v3 = triangle_vertices
    u, v, w = barycentric_coords
    return u * v1 + v * v2 + w * v3 + displacement * normal

def deform_to_target(canonical_position, smplx_transform_matrix):
    return smplx_transform_matrix @ canonical_position

def render_and_optimize(video_frame, smplx_transform_matrix, gaussians):
    # Compute canonical positions from barycentric coords and normal displacement
    p_canon = [compute_canonical_position(g.tri_verts, g.bary, g.normal, g.disp) for g in gaussians]
    # Deform to target pose using SMPL-X transformation
    p_target = [deform_to_target(p, smplx_transform_matrix) for p in p_canon]
    # Project to 2D and splat onto image plane [G]
    rendered_image = rasterize_gaussians(p_target, gaussians.rotation, gaussians.scale, gaussians.opacity, gaussians.color)
    # Compute loss and optimize parameters [G]
    loss = l1_ssim_loss(rendered_image, video_frame)
    gradient_descent_step(gaussians, loss)
```
**Parameters:**
*   Learning rate and densification thresholds follow standard 3D Gaussian Splatting configurations [G].
**Edge Cases:**
*   **Unbalanced Aggregation:** Densification and splitting operations can cause unbalanced aggregation of Gaussians. This may require surface-guided re-initialization strategies to ensure Gaussians fit the input video well [S1].

## Operating characteristics
*   **Time Complexity:** Real-time novel animation is supported [S1].
*   **Memory Complexity:** Proportional to the number of Gaussians embedded on the mesh [G].
*   **Strengths:** Monocular video input; real-time animation; leverages strong SMPL-X priors for realistic human structure [S2, unofficial].
*   **Limitations:** Relies on accurate SMPL-X fitting; potential issues with Gaussian aggregation if densification is not managed [S1].
*   **When to use:** When reconstructing dynamic human avatars from monocular video with a need for real-time animation and realistic body structure [S2, unofficial].

## Background
GoMAvatar is listed among methods using the SMPL-X rig, specifically noted for being a monocular video method coupled with a mesh [S2, unofficial]. It addresses the limitations of earlier SMPL-driven methods by embedding Gaussians directly onto the canonical mesh using barycentric coordinates and normal displacements, providing a structured approach to dynamic human modeling [S1].

## Subtopics

### Gaussian Avatar
Uses SMPL as a prior with pose features predicting Gaussian parameters via a feed-forward network. Sets it apart by using a feed-forward network instead of mesh embedding. Choose when pose features are sufficient and mesh coupling is not required. [1479-gaussian-avatar.md]

### HUGS
The first SMPL-driven body Gaussian Splatting method. Sets it apart by using the SMPL rig instead of SMPL-X. Choose for early SMPL-based body reconstruction. [S2, unofficial]

### 3DGS-Avatar
Uses SMPL-X with per-Gaussian deformation MLPs. Sets it apart by learning deformation per Gaussian rather than using barycentric/normal displacement. Choose when MLP-based deformation is preferred over mesh embedding. [S2, unofficial]

### AnimatableGaussians
Uses SMPL-X with explicit pose-conditioned offsets. Sets it apart by applying explicit offsets rather than mesh-coupled deformation. Choose when explicit pose conditioning is needed. [S2, unofficial]

### SplattingAvatar
Embeds Gaussians in mesh tangent space. Sets it apart by using a local tangent coordinate system instead of canonical barycentric coordinates. Choose when tangent-space embedding is preferred. [S2, unofficial]
