# Gaussian Splatting

Also called: 3D GS, 3D Gaussian Splatting (3DGS), Volumetric and Splatting Rendering

## Overview
Gaussian Splatting (3DGS) is a method for 3D scene representation and novel view synthesis that models a scene as an explicit collection of anisotropic 3D Gaussians, each encoding position, scale, orientation, opacity, and view-dependent color [S1, S4][S10, unofficial]. It solves the computational bottleneck of traditional neural radiance fields (NeRFs) by replacing implicit volume rendering with a differentiable, tile-based rasterization pipeline that projects 3D Gaussians into 2D splats and alpha-composites them [S1, S4][S10, unofficial]. Unlike NeRFs, which require dense ray marching and query empty space, 3DGS avoids costly queries in empty space by only processing primitives that intersect the view frustum, enabling real-time rendering speeds (≥30 fps at 1080p) while maintaining high visual fidelity [S1][S10, unofficial].

## How it works
**Inputs:** A set of posed input images $\{I_i\}$ and their corresponding camera poses (extrinsics $W$ and intrinsics $K$) obtained via Structure-from-Motion (SfM) [S1][S10, unofficial].
**Outputs:** A rendered image $C$ for a given camera pose, and a set of optimized 3D Gaussian parameters $\{g_i\}_{i=1}^M$ representing the scene [S1, S5].

**Data Structures:**
The scene is represented by a collection of $M$ 3D Gaussians. Each Gaussian $g_i$ is defined by the following learnable parameters [S1, S5][S7, unofficial][S23]:
*   **Position:** $\boldsymbol{\mu}_i \in \mathbb{R}^3$ (world coordinates).
*   **Covariance:** $\boldsymbol{\Sigma}_i \in \mathbb{R}^{3 \times 3}$ (positive-definite). To ensure positive definiteness during optimization, $\boldsymbol{\Sigma}_i$ is parameterized by a scaling vector $\mathbf{s}_i \in \mathbb{R}^3$ (stored in log space) and a rotation quaternion $\mathbf{q}_i \in \mathbb{R}^4$ (normalized to unit length) [S5][S7, unofficial][S13]. The covariance is reconstructed as $\boldsymbol{\Sigma}_i = \mathbf{R}_i \mathbf{S}_i \mathbf{S}_i^\top \mathbf{R}_i^\top$, where $\mathbf{R}_i$ is the rotation matrix derived from $\mathbf{q}_i$ and $\mathbf{S}_i = \text{diag}(\mathbf{s}_i)$ [S5, S13].
*   **Opacity:** $\alpha_i \in [0, 1]$ (learnable scalar, often initialized to 0.1) [S5][S24, unofficial].
*   **Color:** Represented by spherical harmonics (SH) coefficients $\mathbf{c}_i$. Typically, band 3 is used, storing 48 coefficients per splat (16 per RGB channel) to model view-dependent appearance [S7, unofficial][S23].

**Algorithm Steps:**

1.  **Initialization:** Initialize the set of $M$ Gaussians using a sparse point cloud obtained from SfM. Set $\boldsymbol{\mu}_i$ to the 3D point coordinates, $\boldsymbol{\Sigma}_i$ based on local geometric information (or random initialization for extra points to fill holes), $\alpha_i$ to a small constant (e.g., 0.1), and $\mathbf{c}_i$ by averaging pixel colors from visible images or initializing randomly [S1][S24, unofficial].

2.  **Optimization Loop (Training):**
    *   **Rendering:** For a training view, render the image using the current Gaussian parameters (see Rendering Pipeline below).
    *   **Loss Computation:** Compare the rendered image $I_{\theta}$ with the ground truth image $I$ using a combined loss function [S5][S18, unofficial]:
        $$ \mathcal{L} = (1 - \lambda) \mathcal{L}_{L1} + \lambda \mathcal{L}_{D-SSIM} $$
        where $\lambda \in [0, 1]$ is a weighting factor (typically 0.2) [S5][S18, unofficial]. $\mathcal{L}_{L1}$ minimizes pixel-wise differences, and $\mathcal{L}_{D-SSIM}$ enforces structural similarity [S5].
    *   **Gradient Descent:** Backpropagate the loss to update $\boldsymbol{\mu}_i, \mathbf{s}_i, \mathbf{q}_i, \alpha_i, \mathbf{c}_i$ using an optimizer like Adam [S1][S18, unofficial].
    *   **Adaptive Density Control:** Every $k$ iterations (e.g., 100), adjust the number of Gaussians [S1][S10, unofficial]:
        *   **Clone:** Duplicate Gaussians in regions with high image error (underfitting).
        *   **Split:** Split large Gaussians that cover too much detail.
        *   **Prune:** Remove Gaussians with persistently low opacity [S1][S10, S18, unofficial].

3.  **Rendering Pipeline (Inference/Training):**
    *   **Frustum Culling:** Identify Gaussians outside the camera's view frustum and exclude them [S5].
    *   **3D-to-2D Projection (Splatting):** Project each 3D Gaussian into the 2D image plane [S13].
        *   Transform the center to camera space: $\boldsymbol{\mu}'_i = W \boldsymbol{\mu}_i$ [S5].
        *   Compute the 2D mean: $\tilde{\boldsymbol{\mu}}_i = \phi_{\mathbf{K}}(\boldsymbol{\mu}'_i)$, where $\phi_{\mathbf{K}}$ is the perspective projection [S1].
        *   Compute the 2D covariance $\tilde{\boldsymbol{\Sigma}}_i$ using a local affine approximation of the projective transformation [S1, S5]:
            $$ \tilde{\boldsymbol{\Sigma}}_i = \mathbf{J} W \boldsymbol{\Sigma}_i W^\top \mathbf{J}^\top $$
            where $\mathbf{J} \in \mathbb{R}^{2 \times 3}$ is the Jacobian of the projection at $\boldsymbol{\mu}'_i$ [S1, S5].
        *   The opacity and color are preserved: $\tilde{\alpha}_i = \alpha_i$ and $\tilde{\mathbf{c}}_i = \mathbf{c}_i$ [S1].
    *   **Tile-Based Sorting:**
        *   Partition the image into non-overlapping tiles (typically $16 \times 16$ pixels) [S5, S13].
        *   Determine which tiles intersect with the 3-sigma bounding box of each projected Gaussian [S16, unofficial].
        *   Replicate the Gaussian for each intersecting tile, assigning a tile ID [S5].
        *   Sort the Gaussians within each tile by depth (distance from camera) using a GPU-optimized radix sort [S5, S13].
    *   **Alpha Compositing:** For each pixel, traverse the sorted list of overlapping 2D Gaussians and accumulate color [S13]:
        $$ C_{\mathbf{x}} = \sum_{i=1}^{N} c_i \alpha'_{i} T_i $$
        where $N$ is the number of sorted Gaussians for pixel $\mathbf{x}$, $c_i$ is the color evaluated from SH coefficients using the viewing direction, $\alpha'_{i}$ is the effective opacity at pixel $\mathbf{x}$, and $T_i$ is the accumulated transmittance [S5, S14]:
        $$ \alpha'_{i} = \alpha_i \exp\left(-\frac{1}{2} (\mathbf{x} - \tilde{\boldsymbol{\mu}}_i)^\top \tilde{\boldsymbol{\Sigma}}_i^{-1} (\mathbf{x} - \tilde{\boldsymbol{\mu}}_i)\right) $$
        $$ T_i = \prod_{j=1}^{i-1} (1 - \alpha'_{j}) $$
        Rendering stops when $T_i$ is sufficiently small or all Gaussians are processed [S24, unofficial].

**Pseudocode:**

```python
import numpy as np

def render_gaussian_splatting(gaussians, camera, image_shape):
    """
    Render a scene represented by 3D Gaussians using tile-based rasterization.
    
    Args:
        gaussians: List of dicts, each containing:
            'mu': (3,) position in world space
            's': (3,) scale (log space)
            'q': (4,) rotation quaternion (normalized)
            'alpha': (1,) opacity
            'sh_coeffs': (48,) spherical harmonic coefficients
        camera: Dict containing 'W' (4x4 view matrix), 'K' (3x3 intrinsic matrix)
        image_shape: Tuple (height, width)
        
    Returns:
        rendered_image: (height, width, 3) RGB image
    """
    H, W = image_shape
    TILE_SIZE = 16
    
    # 1. Frustum Culling (Simplified: assume all are in frustum for brevity)
    # In practice, cull Gaussians outside the camera frustum [S5]
    
    # 2. Project 3D Gaussians to 2D
    projected_gaussians = []
    for g in gaussians:
        # Reconstruct 3D Covariance from scale and rotation [S5, S13]
        R = quaternion_to_rotation_matrix(g['q'])
        S = np.diag(np.exp(g['s'])) # Scale is stored in log space [S7, unofficial]
        Sigma = R @ (S @ S.T) @ R.T
        
        # Transform to camera space [S5]
        mu_cam = camera['W'][:3, :3] @ g['mu'] + camera['W'][:3, 3]
        Sigma_cam = camera['W'][:3, :3] @ Sigma @ camera['W'][:3, :3].T
        
        # Compute Jacobian of projection at mu_cam [S1, S5]
        # J approximates perspective projection K * [I | 0] * [x; 1]
        # J = d(K * [x/z; y/z; 1]) / d[x,y,z]
        z = mu_cam[2]
        if z <= 0: continue # Behind camera
        J = np.zeros((2, 3))
        J[0, 0] = camera['K'][0, 0] / z
        J[0, 2] = -camera['K'][0, 0] * mu_cam[0] / (z**2)
        J[1, 1] = camera['K'][1, 1] / z
        J[1, 2] = -camera['K'][1, 1] * mu_cam[1] / (z**2)
        
        # Project Covariance [S5]
        Sigma_2d = J @ Sigma_cam @ J.T
        
        # Project Mean [S1]
        mu_2d = camera['K'] @ mu_cam
        mu_2d = mu_2d[:2] / mu_2d[2] # Perspective division
        
        # Compute 3-sigma bounding box for tile assignment [S16, unofficial]
        # Eigenvalues of Sigma_2d give variance along principal axes
        eigenvalues = np.linalg.eigvalsh(Sigma_2d)
        std_devs = np.sqrt(eigenvalues)
        bbox_min = mu_2d - 3 * std_devs
        bbox_max = mu_2d + 3 * std_devs
        
        # Determine intersecting tiles
        tile_min_x = max(0, int(bbox_min[0] // TILE_SIZE))
        tile_max_x = min((W + TILE_SIZE - 1) // TILE_SIZE, int(bbox_max[0] // TILE_SIZE) + 1)
        tile_min_y = max(0, int(bbox_min[1] // TILE_SIZE))
        tile_max_y = min((H + TILE_SIZE - 1) // TILE_SIZE, int(bbox_max[1] // TILE_SIZE) + 1)
        
        for ty in range(tile_min_y, tile_max_y):
            for tx in range(tile_min_x, tile_max_x):
                projected_gaussians.append({
                    'mu_2d': mu_2d,
                    'Sigma_2d': Sigma_2d,
                    'alpha': g['alpha'],
                    'sh_coeffs': g['sh_coeffs'],
                    'tile_id': ty * W + tx, # Unique tile ID
                    'depth': mu_cam[2] # Depth for sorting
                })
    
    # 3. Sort by Tile ID and Depth [S5, S13]
    # Sort primarily by tile_id, secondarily by depth
    projected_gaussians.sort(key=lambda x: (x['tile_id'], x['depth']))
    
    # 4. Initialize Output Buffers
    final_image = np.zeros((H, W, 3))
    transmittance_buffer = np.ones((H, W)) # T_i
    
    # 5. Alpha Compositing per Tile [S13]
    # Iterate through sorted list and accumulate for each pixel in the tile
    # Note: In a real implementation, this is done in parallel on GPU.
    # Here we simulate the accumulation logic.
    
    current_tile = -1
    for g in projected_gaussians:
        tile_id = g['tile_id']
        if tile_id != current_tile:
            current_tile = tile_id
            # Reset transmittance for this tile's pixels? 
            # In reality, transmittance is per-pixel. 
            # For this pseudocode, we assume we process pixels within the tile bounds.
            pass
            
        # Get tile coordinates
        ty = tile_id // W
        tx = tile_id % W
        
        # Pixel coordinates within tile
        # We need to iterate over pixels in the tile that are covered by this Gaussian
        # For simplicity, we iterate over the bounding box of the Gaussian within the tile
        # In practice, this is done via a fragment shader or vectorized operations
        
        # Calculate inverse 2D covariance (Conic matrix) for efficient evaluation [S16, unofficial]
        Sigma_2d_inv = np.linalg.inv(g['Sigma_2d'])
        
        # Define pixel range covered by this Gaussian in this tile
        # (Simplified: assume we evaluate at pixel centers)
        # Real implementation uses row-constant hoisting [1195-row-constant-hoisting-for-gaussian-splatting-rasterization.md]
        
        # For each pixel (x, y) in the tile that overlaps with the Gaussian:
        # This loop is conceptual; actual implementation uses vectorized GPU kernels
        for y in range(ty * TILE_SIZE, min((ty + 1) * TILE_SIZE, H)):
            for x in range(tx * TILE_SIZE, min((tx + 1) * TILE_SIZE, W)):
                # Check if pixel is within Gaussian's 3-sigma bounds (optimization)
                # Compute distance vector
                dx = x - g['mu_2d'][0]
                dy = y - g['mu_2d'][1]
                
                # Evaluate 2D Gaussian
                exponent = -0.5 * np.array([dx, dy]) @ Sigma_2d_inv @ np.array([dx, dy])
                if exponent > 0: continue # Value is negligible
                
                gaussian_value = np.exp(exponent)
                
                # Effective opacity at pixel [S5]
                alpha_prime = g['alpha'] * gaussian_value
                
                # Get color from SH coefficients [S7, unofficial]
                # View direction from camera to Gaussian center
                view_dir = g['mu_2d'] # Simplified; should be 3D direction
                color = evaluate_sh(g['sh_coeffs'], view_dir)
                
                # Alpha blending [S5, S14]
                T = transmittance_buffer[y, x]
                contribution = color * alpha_prime * T
                final_image[y, x] += contribution
                transmittance_buffer[y, x] *= (1 - alpha_prime)
                
                # Early out if fully opaque
                if transmittance_buffer[y, x] < 1e-4:
                    break # Optimization: stop processing this pixel for further Gaussians

    return final_image

def evaluate_sh(sh_coeffs, view_dir):
    """
    Evaluate spherical harmonics coefficients for a given view direction.
    Simplified for Band 0 (DC) for brevity.
    """
    # Band 0: Y0_0 = 1/(2*sqrt(pi)) approx 0.282
    C0 = 0.28209479177387814
    # sh_coeffs[0:3] are the DC coefficients for R, G, B
    dc = sh_coeffs[0:3]
    color = np.clip(0.5 + C0 * dc, 0, 1)
    return color

def quaternion_to_rotation_matrix(q):
    """Convert quaternion to 3x3 rotation matrix."""
    # q is [w, x, y, z] or [x, y, z, w]? Standard is often [x, y, z, w] or [w, x, y, z].
    # Assuming [w, x, y, z] for this example.
    w, x, y, z = q
    return np.array([
        [1 - 2*y*y - 2*z*z, 2*x*y - 2*w*z, 2*x*z + 2*w*y],
        [2*x*y + 2*w*z, 1 - 2*x*x - 2*z*z, 2*y*z - 2*w*x],
        [2*x*z - 2*w*y, 2*y*z + 2*w*x, 1 - 2*x*x - 2*y*y]
    ])
```

## Subtopics

### [Unnormalized 3D Gaussian Function](1026-unnormalized-3d-gaussian-function.md)
Defines the Gaussian primitive where the amplitude at the mean equals the opacity, parameterizing the function via its peak value rather than its integral.

### [Row-constant hoisting for Gaussian Splatting Rasterization](1195-row-constant-hoisting-for-gaussian-splatting-rasterization.md)
An optimization that hoists row-constant terms outside the inner pixel loop to minimize arithmetic operations per pixel.

### [2D Gaussian Projection with Covariance Stabilization](1198-2d-gaussian-projection-with-covariance-stabilization.md)
Projects 3D Gaussians to 2D using a fixed image plane and adds epsilon to the covariance diagonal for positive definiteness.

### [Gaussian in the Wild (GS-W)](1386-gaussian-in-the-wild-gs-w.md)
Separates scene appearance into intrinsic material properties and dynamic environmental factors, using adaptive sampling to mitigate transient occlusions.

### [3DGUT](1474-3dgut.md)
Uses an unscented transform to improve the affine approximation of the projection operator, reducing projection errors.

### [Transformer-based Reconstruction](1794-transformer-based-reconstruction.md)
Uses feed-forward neural networks to predict 3DGS parameters directly from 2D images, bypassing iterative optimization.

### [3D Gaussian Ellipsoid Rendering](1869-3d-gaussian-ellipsoid-rendering.md)
Replaces rasterization with ray tracing to compute exact volume density distributions, solving occlusion ambiguity.

### [Stochastic Gaussian Splatting](6599-stochastic-gaussian-splatting.md)
Eliminates sorting bottlenecks by using stochastic sampling and atomic operations to render hundreds of millions of Gaussians.

### [Rendering Implementation](7155-rendering-implementation.md)
Defines the complete pipeline for projecting and compositing 3D Gaussians, encompassing hardware-accelerated and software-based approaches.

### [Contribution-based ordering](8748-contribution-based-ordering.md)
Sorts primitives by visual importance to enable progressive rendering and efficient data streaming.

### [Feed-forward 3D Gaussian Splatting](9932-feed-forward-3d-gaussian-splatting.md)
Predicts Gaussian primitives directly from input images without iterative optimization, solving latency bottlenecks.

### 3D Convex Splatting
A method that replaces Gaussian primitives with smooth convex shapes to offer greater flexibility and more accurate representation of flat surfaces and sharp edges with fewer primitives [S25, unofficial]. It is coupled with an efficient CUDA rasterizer to improve fidelity while reducing memory usage [S25, unofficial].

## Operating characteristics
*   **Time Complexity:** Rendering is dominated by the sorting and rasterization steps. Sorting $N$ Gaussians takes $O(N \log N)$ or $O(N)$ with radix sort [S5, S13]. Rasterization is $O(P \cdot K)$ where $P$ is the number of pixels and $K$ is the average number of overlapping Gaussians per pixel [S5].
*   **Memory Complexity:** Storage is $O(M)$ where $M$ is the number of Gaussians. Each Gaussian stores position (12 bytes), scale (12 bytes), rotation (16 bytes), opacity (4 bytes), and SH coefficients (192 bytes for band 3), totaling approximately 236 bytes per Gaussian [S7, unofficial][S23].
*   **Performance:** Achieves real-time rendering speeds (≥30 fps at 1080p) on consumer hardware [S10, unofficial]. Performance scales with the number of Gaussians and image resolution [S5].
*   **Strengths:** High visual quality, real-time rendering, explicit representation allows for easy editing and compression [S4][S10, unofficial].
*   **Limitations:** High memory usage for large scenes, potential popping artifacts due to center-based sorting, and approximation errors in perspective projection [S2][S16, unofficial].
*   **When to use:** Real-time novel view synthesis, interactive applications, and scenarios requiring high-quality rendering from sparse inputs [S1, S4].
*   **When not to use:** Scenes with extremely high geometric complexity requiring dense sampling, or applications where memory is severely constrained [S4].

## Background
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1][S10, unofficial]. It builds on earlier work in volume splatting, such as Elliptical Weighted Average (EWA) splatting by Zwicker et al. [S2][S3, unofficial], and point-based rendering methods [S2]. The method combines the differentiable optimization benefits of neural radiance fields with the explicit storage and rendering speed of splatting systems [S5][S10, unofficial]. It has since become a dominant technique in 3D scene representation, inspiring numerous variants and applications in robotics, AR/VR, and digital twins [S4, S13].
