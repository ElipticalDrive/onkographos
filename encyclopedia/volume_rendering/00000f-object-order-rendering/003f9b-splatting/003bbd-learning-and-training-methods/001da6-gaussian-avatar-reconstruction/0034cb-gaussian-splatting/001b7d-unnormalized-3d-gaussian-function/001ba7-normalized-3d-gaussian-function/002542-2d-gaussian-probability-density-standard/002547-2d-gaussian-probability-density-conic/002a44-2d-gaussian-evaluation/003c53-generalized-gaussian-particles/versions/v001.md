# Generalized Gaussian Particles

Also called: Generalized Gaussians of degree n

## Overview
Generalized Gaussian Particles replace the standard quadratic exponent in the 2D Gaussian probability density function with a power-law exponent controlled by a degree parameter $n$ [S1]. This modification allows for steeper and narrower density fall-off, enabling denser particle packing and finer control over the trade-off between rendering quality and computational speed compared to standard Gaussians [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** Position $\mathbf{x} \in \mathbb{R}^2$, mean $\boldsymbol{\mu} \in \mathbb{R}^2$, covariance matrix $\boldsymbol{\Sigma} \in \mathbb{R}^{2 \times 2}$, kernel degree $n \in \mathbb{N}$ (typically even integers), and scale factor $\lambda$.
*   **Output:** Kernel response $\rho(\mathbf{x}) \in [0, 1]$.

**Data Structures:**
The covariance matrix $\boldsymbol{\Sigma}$ is typically decomposed into a scaling matrix $\mathbf{S}$ and rotation matrix $\mathbf{R}$ such that $\boldsymbol{\Sigma} = \mathbf{R}\mathbf{S}\mathbf{S}^T\mathbf{R}^T$. The inverse quadratic form $(\mathbf{x} - \boldsymbol{\mu})^T \boldsymbol{\Sigma}^{-1}(\mathbf{x} - \boldsymbol{\mu})$ is computed efficiently using this decomposition or direct inversion depending on implementation constraints.

**Parameters:**
*   $n$: Kernel degree. $n=2$ corresponds to the standard Gaussian. Higher degrees ($n=4, 8, \dots$) produce steeper fall-off [S1]. Note that the "degree 2" generalized Gaussian in 3DGRT [34] corresponds to degree $n=4$ in this formulation [S1].
*   $\lambda$: Scale factor. Defined to ensure the kernel response at a specific distance $r$ matches that of the reference standard Gaussian kernel.
    *   Formula: $\lambda = r^{-n} \ln(1/\rho_r)$, where $\rho_r$ is the standard Gaussian response at distance $r$.
    *   Typical value: $r = 3$ [S1].

**Steps:**
1.  Compute the displacement vector: $\mathbf{d} = \mathbf{x} - \boldsymbol{\mu}$.
2.  Compute the squared Mahalanobis distance (quadratic form): $q = \mathbf{d}^T \boldsymbol{\Sigma}^{-1} \mathbf{d}$.
3.  Apply the power-law exponent: $p = q^{n/2}$.
4.  Scale by $\lambda$: $s = \lambda \cdot p$.
5.  Compute the response: $\rho(\mathbf{x}) = \exp(-s)$.

**Pseudocode:**
```python
def generalized_gaussian_response(x, mu, Sigma_inv, n, r=3.0):
    """
    Computes the response of a generalized Gaussian particle.
    
    Args:
        x: 2D position vector (numpy array or similar).
        mu: 2D mean vector.
        Sigma_inv: 2x2 inverse covariance matrix.
        n: Kernel degree (integer, e.g., 2, 4, 8).
        r: Reference distance for scaling (default 3.0).
        
    Returns:
        rho: Scalar kernel response.
    """
    # 1. Displacement
    d = x - mu
    
    # 2. Quadratic form: d^T * Sigma_inv * d
    # Using matrix multiplication for clarity
    q = np.dot(d, np.dot(Sigma_inv, d))
    
    # 3. Power-law exponent: q^(n/2)
    # Ensure q is non-negative to avoid complex numbers due to precision errors
    q = max(q, 0.0)
    p = q ** (n / 2.0)
    
    # 4. Calculate lambda
    # Reference: Standard Gaussian response at distance r is exp(-r^2 / 2)
    # We want: exp(-lambda * r^n) = exp(-r^2 / 2)
    # => lambda * r^n = r^2 / 2
    # => lambda = r^(2-n) / 2
    # Note: The source defines lambda generally as r^-n * ln(1/rho_r).
    # For standard Gaussian, rho_r = exp(-r^2/2), so ln(1/rho_r) = r^2/2.
    # Thus lambda = (r^2/2) * r^-n = r^(2-n) / 2.
    lambda_val = (r ** (2 - n)) / 2.0
    
    # 5. Scale and Exponentiate
    s = lambda_val * p
    rho = np.exp(-s)
    
    return rho
```

**Edge Cases and Pitfalls:**
*   **Precision:** If $q$ is slightly negative due to floating-point errors, raising it to a fractional power ($n/2$) results in NaN. Clamp $q$ to $\ge 0$ [G].
*   **Degree Selection:** Higher degrees ($n > 2$) result in narrower particles. While this can improve quality by reducing overlap artifacts, it may require more particles to cover the same area, impacting memory and rasterization speed [S1].
*   **3DGRT Compatibility:** When integrating with existing pipelines using 3DGRT's "degree 2" generalized Gaussians, use $n=4$ in this formulation [S1].

## Operating characteristics
**Time and Memory Complexity:**
*   **Time:** The evaluation cost is dominated by the matrix-vector multiplication for the quadratic form and the power/exponentiation operations. The complexity is $O(1)$ per particle per sample point, similar to standard Gaussians, but the steeper fall-off may require different sampling strategies or tile sizes in rasterization [S1].
*   **Memory:** No additional memory overhead compared to standard Gaussians, as the parameters $\boldsymbol{\mu}$ and $\boldsymbol{\Sigma}$ remain the same [S1].

**Measured Performance:**
On the MipNeRF360 dataset (excluding flower and treehill scenes):
*   Degree $n=2$ (Standard): 28.77 PSNR at 207 FPS [S1].
*   Degree $n=4$: 28.46 PSNR at 233 FPS [S1].
*   Degree $n=8$: 27.63 PSNR at 243 FPS [S1].

Higher degrees increase rendering speed (FPS) but slightly decrease reconstruction quality (PSNR) [S1]. This suggests that narrower particles allow for more efficient rasterization (fewer overlaps or smaller tiles) at the cost of some detail fidelity.

**Strengths and Limitations:**
*   **Strengths:** Allows tuning of particle density and fall-off steepness. Higher degrees enable faster rendering speeds [S1].
*   **Limitations:** Higher degrees reduce PSNR. The choice of $n$ requires balancing quality and speed [S1].

**When to Use:**
Use higher degrees ($n=4, 8$) when rendering speed is prioritized over maximum reconstruction quality, or when narrower particle support is beneficial for specific scene characteristics [S1]. Use $n=2$ for standard compatibility and highest quality [S1].

## Background
Generalized Gaussian Particles were introduced in the context of 3DGRT [34], which proposed using particles with different kernel functions, specifically a generalized Gaussian of degree 2. The formulation presented here generalizes this to arbitrary degree $n$ [S1]. The method is used in Gaussian Splatting variants to optimize the trade-off between rendering quality and speed [S1].
