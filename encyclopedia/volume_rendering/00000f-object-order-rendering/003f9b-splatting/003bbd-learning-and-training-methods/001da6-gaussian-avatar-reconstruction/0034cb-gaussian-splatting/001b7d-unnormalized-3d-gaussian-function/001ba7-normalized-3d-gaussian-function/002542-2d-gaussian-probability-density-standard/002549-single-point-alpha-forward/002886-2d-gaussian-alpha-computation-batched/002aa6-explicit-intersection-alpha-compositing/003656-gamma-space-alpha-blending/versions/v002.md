# Gamma-Space Alpha Blending

Also called: Gamma-Space Alpha Blending for 3DGS, Gamma-Space Splat Blending

## Overview
Gamma-Space Alpha Blending performs Gaussian alpha compositing directly in the Gamma color space to match assets trained in Gamma space, avoiding quality loss from post-blend color conversion [S1, unofficial]. It requires the rendering project to be configured in Gamma color space, as converting colors to linear space before blending produces incorrect results and lowers rendering quality [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** 2D Gaussian splats with associated Gamma-space colors ($C$) and opacities ($\alpha$) [G].
*   **Output:** A composited image buffer in Gamma space [G].

**Data Structures:**
*   **Splat Buffer:** Stores position, covariance, opacity, and Gamma-space color per splat [G].
*   **Render Target:** A texture buffer configured to store Gamma-space values without intermediate linear-space conversion during accumulation [G].

**Steps:**
1.  **Project & Rasterize:** Project 3D Gaussians to 2D screen space and rasterize them to the render target [G].
2.  **Blend in Gamma Space:** For each pixel, accumulate splats using standard alpha compositing equations directly on Gamma-space color values:
    $$ C_{out} = C_{in} + C_{splat} \cdot \alpha_{splat} \cdot (1 - \alpha_{in}) $$
    $$ \alpha_{out} = \alpha_{in} + \alpha_{splat} \cdot (1 - \alpha_{in}) $$
    where $C$ is the Gamma-space color vector and $\alpha$ is opacity [G].
3.  **Output:** Display the resulting Gamma-space buffer directly [G].

**Parameters:**
*   **GammaToLinear:** Boolean flag to attempt color space conversion before blending; disabled by default to prevent quality degradation [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Linear Projects:** Projects using a linear color space require retraining 3DGS assets with linear-space images, as blending in linear space produces incorrect results [S1, unofficial].
*   **HDRP Limitations:** High Definition Render Pipeline (HDRP) does not support Gamma mode, making this method incompatible without pipeline changes [S1, unofficial].
*   **GammaToLinear Workaround:** Enabling `GammaToLinear` converts colors to linear space before blending, which leads to incorrect results and lowers rendering quality [S1, unofficial].

**Pseudocode:**
```python
# Initialize buffers
color_buffer = [[[0.0, 0.0, 0.0] for _ in range(width)] for _ in range(height)]
alpha_buffer = [[0.0 for _ in range(width)] for _ in range(height)]

# Source does not provide explicit pixel picking or Gaussian evaluation steps [G]
# Assuming splats are pre-sorted back-to-front per pixel
for y in range(height):
    for x in range(width):
        acc_color = [0.0, 0.0, 0.0]
        acc_alpha = 0.0
        for splat in splats_for_pixel[y][x]:
            if acc_alpha >= 1.0:
                break
            # Evaluate 2D Gaussian alpha at pixel center (source does not specify) [G]
            alpha_splat = 1.0  # Standard Gaussian evaluation omitted per source [G]
            effective_alpha = alpha_splat * splat.opacity
            if effective_alpha <= 0.0:
                continue
            # Gamma-space compositing
            acc_color = [acc_color[i] + splat.color[i] * effective_alpha * (1.0 - acc_alpha) for i in range(3)]
            acc_alpha = acc_alpha + effective_alpha * (1.0 - acc_alpha)
        color_buffer[y][x] = acc_color
        alpha_buffer[y][x] = acc_alpha
```

## Subtopics

### sRGB to Linear Composite
A vertex and pixel shader pair for the sRGB→linear composite pass using a full-screen triangle [S2, unofficial]. The pixel shader reads the intermediate sRGB-blended splat accumulation texture, converts to linear, and outputs for premultiplied alpha blending onto SceneColor [S2, unofficial]. This variant is used when the initial splatting occurs in Gamma space to match training, but the final composition with the rest of the scene requires Linear space [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Strengths:** Preserves visual fidelity of assets trained in Gamma space without requiring retraining [S1, unofficial].
*   **Limitations:** Incompatible with Linear color space projects unless assets are retrained [S1, unofficial]. Incompatible with HDRP [S1, unofficial].
*   **When to use:** When rendering standard 3DGS assets (trained in Gamma) in a Gamma-space supported pipeline (Built-in RP, URP) [S1, unofficial].
*   **When not to use:** In Linear color space projects with existing Gamma-trained assets, or in HDRP [S1, unofficial].

## Background
Originating from the practical constraints of integrating 3D Gaussian Splatting into game engines, this method addresses the mismatch between the official 3DGS implementation (which trains in Gamma space) and modern rendering pipelines (which operate in Linear space) [S1, unofficial]. It was popularized by community implementations such as `gsplat-unity` which highlighted that converting color space before blending degrades quality [S1, unofficial]. The approach relies on the fact that standard 3DGS assets are trained using Gamma-corrected images, making Gamma-space blending the only way to maintain quality without retraining [S1, unofficial].
