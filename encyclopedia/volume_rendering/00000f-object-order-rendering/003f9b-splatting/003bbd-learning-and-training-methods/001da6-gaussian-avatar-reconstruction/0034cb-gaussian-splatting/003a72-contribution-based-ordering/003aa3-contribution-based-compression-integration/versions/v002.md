# Contribution-based compression integration

Also called: Compression Integration, Integration with compression, PRoGS with Vector Quantization, Progressive compression integration

## Overview
This method integrates contribution-based ordering into existing 3D Gaussian Splatting (3DGS) compression pipelines, specifically Niedermayr et al.'s approach, to improve visual quality at the time to First Paint (TFP) by streaming high-contribution primitives first [S1]. It ensures that spatial or Morton ordering typically applied for storage efficiency does not overwrite the semantic importance ordering derived from rendering contribution [S1].

## How it works
**Inputs and Outputs:**
- **Input:** A compressed 3DGS scene file (specifically the method by Niedermayr et al. [S1]), contribution values per Gaussian, and Gaussian IDs [S1].
- **Output:** A chunked compressed file where chunks are ordered by Gaussian contribution, allowing progressive rendering with higher initial quality [S1].

**Data Structures:**
- **Chunk:** A subset of Gaussians stored together. Each chunk must contain its own minimum and maximum values for vector quantization if rendered independently [S1].
- **Gaussian Data:** Per-Gaussian data must be stored with ID mapping; fully aggregated codebooks without ID mapping are insufficient for this method [S1].

**Steps:**
1. **Adapt Renderer:** Modify the rendering engine to return contribution values and corresponding Gaussian IDs for each splat [S1].
2. **Calculate Ordering:** Sort the Gaussians based on their calculated contribution values [S1].
3. **Rewrite Save Functionality:**
   - Group Gaussians into chunks according to the calculated contribution-based order [S1].
   - For each chunk, calculate and store the minimum and maximum values required for vector quantization dequantization [S1].
   - The base compression method (Niedermayr et al.) sorts Gaussians in Morton order before saving to improve compression ratios; this step voids the contribution-based ordering [S1]. In the implementation, this Morton sorting was disabled because it affects only final storage requirements and not the selected splats for progressive rendering [S1]. If Morton sorting is re-enabled, it must be applied to the already sorted indices [S1].
4. **Save Scene:** Write the chunks to disk in the contribution-based order, explicitly skipping Morton sorting to preserve the progressive order [S1].

**Pseudocode:**
```python
def save_compressed_scene(gaussians, contribution_values, chunk_size):
    # Step 1: Pair Gaussians with their contribution values and IDs
    indexed_gaussians = []
    for i, g in enumerate(gaussians):
        indexed_gaussians.append((i, g, contribution_values[i]))
    
    # Step 2: Sort by contribution (descending, assuming higher contribution is better)
    indexed_gaussians.sort(key=lambda x: x[2], reverse=True)
    
    # Step 3: Chunk the sorted list
    chunks = []
    for i in range(0, len(indexed_gaussians), chunk_size):
        chunk_data = indexed_gaussians[i : i + chunk_size]
        
        # Step 4: Calculate min/max for vector quantization for this chunk
        # [G] Standard min/max calculation over all Gaussian attributes (mean, scale, rotation, opacity, SH coefficients)
        chunk_min = [min(attr[j] for attr in chunk_data) for j in range(len(chunk_data[0]))]
        chunk_max = [max(attr[j] for attr in chunk_data) for j in range(len(chunk_data[0]))]
        
        # Step 5: Quantize and store chunk
        # [S1] The exact vector quantization routine from Niedermayr et al. is not provided in the sources.
        # The min and max values must be included in every chunk for dequantization.
        quantized_chunk = chunk_data  # [S1] Quantization routine omitted; min/max stored separately.
        
        chunks.append({
            'min': chunk_min,
            'max': chunk_max,
            'data': quantized_chunk
        })
        
    # Step 6: Write chunks to file in contribution-based order
    # [S1] Morton order sorting is explicitly skipped to preserve contribution order.
    with open('scene.bin', 'wb') as f:
        for chunk in chunks:
            f.write(chunk['min'])
            f.write(chunk['max'])
            f.write(chunk['data'])
```

**Parameters:**
- **Chunk Size:** Not given in the sources.
- **Compression Method:** Specifically tested with Niedermayr et al. [S1].

**Edge Cases and Pitfalls:**
- **Morton Order Conflict:** Applying Morton order sorting after contribution-based sorting destroys the progressive quality benefit [S1].
- **Independent Chunk Rendering:** If chunks are rendered independently, min/max values must be included in every chunk for correct dequantization [S1].
- **Codebook Usage:** This method requires per-Gaussian data storage with ID mapping. It is incompatible with compression schemes that use fully aggregated codebooks without ID mapping [S1].

## Operating characteristics
- **Quality:** Achieves similar quality per percentage of splats compared to the base approach on standard 3DGS [S1].
- **Memory:** In actually required memory, there is a smaller difference compared to non-compressed progressive methods because the shared codebook reduces Gaussian-specific data [S1].
- **Performance:** Improves quality at the time to First Paint (TFP) [S1].
- **Limitations:** Requires modification of the renderer to pass back contribution values and IDs [S1]. Requires per-Gaussian data storage [S1].

## Background
- **Origin:** Proposed in PRoGS (Progressive Rendering of Gaussian Splats) [S1].
- **Development:** The method was validated on the MiPNeRF360, Tanks&Temples, and Deep Blending datasets using the original 3DGS code [S1].
- **Usage:** Used to facilitate progressive streaming of 3DGS, reducing bandwidth requirements while maintaining visual quality during loading [S1].
