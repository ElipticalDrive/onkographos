# View-Dependent Appearance Representations

Also called: Gaussian Appearance Encoding

## Overview
View-Dependent Appearance Representations are methods to model view-dependent appearance within Gaussian splats, addressing the limitation of standard isotropic color storage in 3D Gaussian Splatting [S1, unofficial]. They differ from sibling methods like [Spec-Gaussian](8087-spec-gaussian.md) by providing a modular framework for encoding view-dependent color through various data structures, including fixed basis functions, neural feature vectors, explicit caching structures, and codebook quantization [S1, unofficial].

## Shared principles
All methods in this family associate each 3D Gaussian primitive with additional data beyond position, covariance, opacity, and base color to encode angular variation [S1, unofficial]. The rendering pipeline queries this appearance data during the splatting process to determine the final pixel color based on the viewing direction [S1, unofficial]. The choice of representation involves a trade-off between storage bandwidth, computational cost during decoding, and the complexity of the appearance being modeled [S1, unofficial].

## Subtopics

### Fixed Basis Functions
Uses Spherical Harmonics (SH) for view-dependent color. Also supports Anisotropic Spherical Gaussians (ASG) for specular components and Spherical Gaussians (SG) for balancing quality and speed. Supports PBR parameters and indirect illumination [S1, unofficial].

### Neural Feature Vectors
Each point is associated with a compact Neural Feature Vector decoded using a small MLP [S1, unofficial].

### Triplane
Neural features are cached in explicit data structures. Position is projected onto axis-aligned feature planes, and final feature $f_t$ is obtained by concatenating three trilinear interpolated features [S1, unofficial].

### Hash Grid
Features are interpolated from a multi-resolution grid stored using instant-ngp. Supports unbounded scenes via contraction technique [S1, unofficial].

### Codebook Quantization
A discrete codebook of vector codes is learned during training. Rendering requires only a simple lookup into the codebook using stored indices, exploiting lower bandwidth and computational costs [S1, unofficial].

## Background
Originating from the need to enhance the representation ability of 3D Gaussians beyond simple color, these methods are part of the enhancement step in frameworks like GauStudio [S1, unofficial]. They build on the initialization and optimization of 3D Gaussians, allowing for material and lighting decomposition [S1, unofficial]. The techniques are used in real-time view synthesis systems and scene compression applications [S1, unofficial].
