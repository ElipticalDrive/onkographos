# Text Embedding Generation with Directional Views


## Overview
This method generates semantic text embeddings for 3D Gaussian Splatting scenes by encoding language prompts into latent vectors using a frozen CLIP text encoder [S1, unofficial]. It extends standard text encoding by appending directional view descriptors (e.g., "front", "side", "back") to prompts, creating view-specific embeddings that allow for directional semantic queries or rendering [S1, unofficial]. It differs from general feature blending [3D Gaussian Splatting with Feature Vectors](8060-3d-gaussian-splatting-with-feature-vectors.md) by focusing on the *generation* of the text-side embeddings rather than the spatial accumulation of Gaussian features.

## How it works
**Inputs:**
- A list of text prompts (strings).
- A tokenizer and a frozen CLIP text encoder.
- A set of directional view descriptors (typically `['front', 'side', 'back']`).

**Outputs:**
- A dictionary `self.embeddings` mapping keys to embedding tensors. Keys include `'pos'` (positive prompt), `'neg'` (negative prompt), and directional keys (`'front'`, `'side'`, `'back'`).
- Each tensor has shape `[1, 77, 768]` (batch size 1, sequence length 77, embedding dimension 768) [S1, unofficial].

**Data Structures:**
- `self.embeddings`: A Python dictionary.
- Tensors: PyTorch tensors on the target device (e.g., CUDA).

**Steps:**
1. **Initialize Tokenizer and Encoder:** Load the CLIP text encoder and its corresponding tokenizer. Ensure the encoder is in evaluation mode (frozen) [S1, unofficial].
2. **Encode Base Prompts:**
   - For the positive prompt, tokenize it with padding to the maximum length:
     ```python
     inputs = self.tokenizer(prompt, padding="max_length", max_length=self.tokenizer.model_max_length, return_tensors="pt")
     ```
   - Pass the token IDs through the text encoder:
     ```python
     embeddings = self.text_encoder(inputs.input_ids.to(self.device))[0]
     ```
   - Store the result in `self.embeddings['pos']` [S1, unofficial].
   - Repeat for the negative prompt, storing in `self.embeddings['neg']` [S1, unofficial].
3. **Encode Directional Views:**
   - For each direction `d` in `['front', 'side', 'back']`:
     - Append the string `', {d} view'` to the original prompt.
     - Tokenize and encode the modified prompt using the same process as Step 2.
     - Store the resulting tensor in `self.embeddings[d]` [S1, unofficial].

**Pseudocode:**
```python
import torch

class TextEmbeddingGenerator:
    def __init__(self, tokenizer, text_encoder, device="cuda"):
        self.tokenizer = tokenizer
        self.text_encoder = text_encoder
        self.text_encoder.eval() # Freeze encoder
        self.device = device
        self.embeddings = {}

    def encode(self, prompt, negative_prompt=""):
        """
        Encode positive, negative, and directional view prompts.
        """
        # 1. Encode positive prompt
        self.embeddings['pos'] = self._encode_single(prompt)
        
        # 2. Encode negative prompt if provided
        if negative_prompt:
            self.embeddings['neg'] = self._encode_single(negative_prompt)
            
        # 3. Encode directional views
        directions = ['front', 'side', 'back']
        for d in directions:
            directional_prompt = f"{prompt}, {d} view"
            self.embeddings[d] = self._encode_single(directional_prompt)
            
        return self.embeddings

    def _encode_single(self, prompt):
        """
        Encode a single prompt string into a [1, 77, 768] tensor.
        """
        # Tokenize with padding to max length
        inputs = self.tokenizer(
            prompt, 
            padding="max_length", 
            max_length=self.tokenizer.model_max_length, 
            return_tensors="pt"
        )
        
        # Pass through frozen text encoder
        # [0] extracts the last hidden state
        embeddings = self.text_encoder(
            inputs.input_ids.to(self.device)
        )[0]
        
        return embeddings
```

**Parameters:**
- `max_length`: Typically 77 for CLIP [S1, unofficial].
- `embedding_dim`: 768 for CLIP ViT-L/14 [S1, unofficial].

**Edge Cases:**
- If the prompt exceeds `max_length`, the tokenizer truncates it.
- If the prompt is shorter, it is padded with padding tokens.

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of prompts and directions. Encoding is fast as the encoder is frozen and batch size is 1.
- **Memory Complexity:** Low. Stores a small dictionary of tensors. Shape `[1, 77, 768]` is ~192 KB per embedding [S1, unofficial].
- **Strengths:** Simple to implement; leverages pre-trained CLIP semantics; provides explicit directional semantic control.
- **Limitations:** Relies on the quality of the frozen CLIP encoder; does not adapt embeddings to the specific 3D geometry or appearance of the scene (unlike learned feature vectors).

## Background
Originated in the DreamGaussian project, which integrates 3D Gaussian Splatting with text-to-3D generation capabilities [S1, unofficial]. The method uses CLIP embeddings to guide the optimization of 3D Gaussians, with directional views enabling view-specific semantic consistency.
