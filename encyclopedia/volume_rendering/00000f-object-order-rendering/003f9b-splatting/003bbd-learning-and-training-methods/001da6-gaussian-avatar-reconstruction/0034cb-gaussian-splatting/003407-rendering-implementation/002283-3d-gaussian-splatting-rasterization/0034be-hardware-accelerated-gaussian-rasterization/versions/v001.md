# Hardware-Accelerated Gaussian Rasterization

Also called: GauRast, Hardware-algorithm co-design for Gaussian rasterization

## Overview
Hardware-Accelerated Gaussian Rasterization is a hardware-algorithm co-design that augments standard triangle rasterizers with dedicated units for Gaussian projection and blending, achieving an order of magnitude speedup in the rasterization stage [S1, unofficial]. It solves the bottleneck of processing millions of 3D Gaussians on general-purpose hardware by isolating specific computational phases into fixed-function pipelines [S2]. Unlike software-based differentiable rasterizers [Sibling: 3D Gaussian Splatting Differentiable Rasterizer](2813-3d-gaussian-splatting-differentiable-rasterizer.md) which rely on GPU kernels, this method uses a four-stage hardware pipeline to handle culling, projection, sorting, and blending in parallel [S2].

## How it works
**Inputs:** A set of $N$ 3D Gaussians defined by mean position $\mu$, covariance matrix $\Sigma$, opacity $\alpha$, and spherical harmonic coefficients for color.
**Outputs:** A 2D image buffer with alpha-blended colors.

**Data Structures:**
*   **Gaussian Attributes:** Stored in a global buffer. Each Gaussian includes position, covariance, opacity, and color.
*   **Tile Memory:** Each 16x16 pixel tile is assigned to an independent SRAM bank [S2].
*   **Codebook:** A lookup table used to retrieve precomputed values based on tile indices [S2].
*   **Sorting Buffer:** Holds Gaussian indices sorted by depth per tile [S2].

**Pipeline Stages:**
The architecture consists of four sequential stages [S2]:

1.  **Stage 0: Near-plane Culling (Point-based)**
    *   Eliminates Gaussians that do not intersect the view frustum or are behind the near plane.
    *   Uses an AABB (Axis-Aligned Bounding Box) depth-interval test to reject invisible regions early [S2].
    *   This stage processes the largest number of points and is isolated to optimize resource usage [S2].

2.  **Stage 1: Projection (Point-based)**
    *   Projects 3D Gaussians onto the 2D image plane.
    *   Computes the 2D covariance matrix $\Sigma'$ and mean $\mu'$ using the Jacobian of the perspective projection.
    *   **Zero-Jacobian Skipping:** If the Jacobian determinant is zero (e.g., viewing direction parallel to principal axis), the multiplication is skipped to save cycles [S2].
    *   Implemented using a 6x1 multiplier-accumulator array [S2].

3.  **Stage 2: Sorting (Tile-based)**
    *   Sorts projected Gaussians by depth within each tile.
    *   Uses a four-way sub-sorter parallelism design [S2].
    *   Each sub-sorter processes 256 data elements at a time [S2].
    *   The sorter outputs the current maximum depth value in a linear delay, aligning with the sequential alpha-blending requirement [S2].

4.  **Stage 3: Rasterization (Tile-based)**
    *   Performs alpha-blending for each pixel in the tile.
    *   Processes one Gaussian point at a time, aligned with the sorted output from Stage 2 [S2].
    *   Uses the tile index to look up values in the codebook [S2].

**Pseudocode:**
```python
# Hardware Pipeline Simulation
# Input: list of Gaussians G, Camera C, Image Width W, Image Height H

def hardware_rasterization(G, C, W, H):
    # Stage 0: Near-plane Culling
    visible_gaussians = []
    for g in G:
        if is_in_view_frustum(g, C) and g.depth > C.near_plane:
            visible_gaussians.append(g)
    
    # Stage 1: Projection
    projected_gaussians = []
    for g in visible_gaussians:
        # Compute 2D mean and covariance
        # Skip if Jacobian is zero
        if is_zero_jacobian(g, C):
            continue
        proj = project_gaussian(g, C)
        projected_gaussians.append(proj)
        
    # Stage 2: Sorting (Tile-based)
    # Divide image into 16x16 tiles
    tile_size = 16
    tiles = create_tiles(W, H, tile_size)
    
    sorted_tiles = {}
    for tile in tiles:
        # Assign tile to independent SRAM bank
        # Filter gaussians belonging to this tile
        tile_gaussians = [g for g in projected_gaussians if intersects_tile(g, tile)]
        
        # Sort by depth using four-way sub-sorter
        # Each sub-sorter handles 256 elements
        sorted_gaussians = sort_gaussians_by_depth(tile_gaussians)
        sorted_tiles[tile.id] = sorted_gaussians
        
    # Stage 3: Rasterization (Alpha Blending)
    image = zeros((H, W, 3))
    alpha_buffer = zeros((H, W))
    
    for tile_id, sorted_gs in sorted_tiles.items():
        # Look up codebook values based on tile index
        codebook_values = lookup_codebook(tile_id)
        
        for g in sorted_gs:
            # Rasterize Gaussian onto pixels in tile
            for pixel in tile.pixels:
                if pixel inside_gaussian_splat(g):
                    # Compute alpha contribution
                    alpha_contrib = compute_alpha(g, pixel)
                    # Alpha blend
                    color = g.color
                    old_alpha = alpha_buffer[pixel]
                    new_alpha = old_alpha + alpha_contrib * (1 - old_alpha)
                    image[pixel] = (image[pixel] * old_alpha + color * alpha_contrib * (1 - old_alpha)) / new_alpha
                    alpha_buffer[pixel] = new_alpha
                    
    return image
```

**Parameters:**
*   Tile Size: 16x16 pixels [S2].
*   Sub-sorter Capacity: 256 elements [S2].
*   Multiplier-Accumulator Array: 6x1 [S2].

**Edge Cases:**
*   **Zero Jacobian:** Must be detected and skipped to avoid division by zero or invalid projections [S2].
*   **Depth Precision:** Sorting must handle floating-point depth precision correctly to ensure correct occlusion [S2].

## Operating characteristics
*   **Performance:** Achieves an order of magnitude speedup in the rasterization stage compared to software implementations [S1, unofficial].
*   **Hardware:** Designed as a fixed-function accelerator, likely on FPGA or ASIC [S2].
*   **Memory:** Uses independent SRAM banks per tile to reduce memory contention [S2].
*   **Scalability:** The point-based preprocessing scales with the number of Gaussians $N$, while the tile-based rendering scales with image resolution [S2].
*   **Limitations:** Fixed tile size (16x16) may not be optimal for all resolutions or aspect ratios [S2]. The hardware design is specific to the Gaussian Splatting algorithm and not general-purpose [S2].

## Background
This method was proposed in "A 129 FPS Full HD Real-Time Accelerator for 3D Gaussian Splatting" [S2]. It represents a shift from software-based rasterization to hardware-algorithm co-design, aiming to overcome the limitations of GPU-based rendering for real-time applications [S1, unofficial]. The design draws inspiration from traditional triangle rasterization pipelines but adapts them for the unique properties of 3D Gaussians [S2].
