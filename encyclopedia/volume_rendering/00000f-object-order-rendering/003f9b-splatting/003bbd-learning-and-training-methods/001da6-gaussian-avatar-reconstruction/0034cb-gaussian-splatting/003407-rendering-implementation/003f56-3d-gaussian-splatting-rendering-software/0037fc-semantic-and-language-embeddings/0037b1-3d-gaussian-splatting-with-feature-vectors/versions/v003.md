# 3D Gaussian Splatting with Feature Vectors

Also called: Feature-3DGS, LangSplat, Semantic 3DGS

## Overview
This method extends standard 3D Gaussian Splatting by attaching a high-dimensional feature vector $\mathbf{f}_i$ to each Gaussian primitive, enabling the rendering of semantic, visual, or language-aligned feature maps instead of (or in addition to) color. It solves the problem of integrating 2D vision-language models (e.g., CLIP, LSeg) into a 3D representation by alpha-blending these per-Gaussian features to produce a 2D feature map $\mathbf{F}$, which can then be decoded for segmentation or compared against text embeddings for open-vocabulary queries [S1, unofficial]. It differs from sibling methods like [Text Embedding Generation with Directional Views](8239-text-embedding-generation-with-directional-views.md) by encoding features directly into the Gaussian attributes rather than generating them via directional views, and from [LSeg Feature Encoding](12078-lseg-feature-encoding.md) by using the standard alpha-blending rasterization pipeline for feature accumulation rather than specialized encoding heads.

## How it works
**Inputs:**
*   A set of $N$ 3D Gaussians, each defined by mean $\boldsymbol{\mu}_i$, covariance $\boldsymbol{\Sigma}_i$ (or rotation $\mathbf{R}_i$ and scale $\mathbf{S}_i$), opacity $\alpha_i$, and a feature vector $\mathbf{f}_i \in \mathbb{R}^D$.
*   Camera parameters (view and projection matrices).
*   Image resolution $W \times H$.

**Outputs:**
*   A 2D feature map $\mathbf{F} \in \mathbb{R}^{H \times W \times D}$.

**Data Structures:**
*   **Gaussian Attributes:** Each Gaussian $i$ stores $\mathbf{f}_i$ as a dense vector of size $D$. In implementations like Feature-3DGS, $D$ is typically 512 or 768 (matching CLIP embedding dimensions).
*   **Rasterization Buffer:** A buffer of size $H \times W \times D$ initialized to zero (or appropriate background) to accumulate the blended features.

**Steps:**
1.  **Projection:** Project each Gaussian $i$ to 2D screen space, computing its 2D covariance matrix $\boldsymbol{\Sigma}'_i$ and center $\mathbf{c}_i$.
2.  **Sorting:** For each pixel (or tile), sort the overlapping Gaussians $\mathcal{O}_p$ front-to-back based on their depth $z_i$.
3.  **Feature Blending:** For each pixel $p$, compute the accumulated feature $\mathbf{F}(p)$ using alpha-blending:
    $$
    \mathbf{F}(p) = \sum_{i \in \mathcal{O}_p} \mathbf{f}_i \cdot \alpha_i \cdot \prod_{j=1}^{i-1} (1 - \alpha_j)
    $$
    where $\mathbf{f}_i$ is the feature vector of Gaussian $i$, $\alpha_i$ is its opacity, and the product term represents the transmittance from all preceding Gaussians $j$ in the sorted order [S1, unofficial].
4.  **Decoding/Querying:** The resulting $\mathbf{F}(p)$ is either passed to a segmentation head (e.g., a small MLP or linear layer) to predict class labels, or compared against text embeddings $\mathbf{t}_k$ from a language model (e.g., CLIP) using cosine similarity to enable open-vocabulary queries [S1, unofficial].

**Parameters:**
*   **Feature Dimension $D$:** Not given in the sources. Typical values are 512 or 768 to match CLIP ViT-L/14 embeddings.
*   **Opacity $\alpha_i$:** Optimized during training alongside features, or fixed from a base 3DGS model.

**Edge Cases and Pitfalls:**
*   **Precision:** Accumulating high-dimensional vectors requires sufficient precision. Standard FP16 may be insufficient for large $D$; FP32 is recommended for the feature accumulation buffer [G].
*   **Degenerate Input:** If $\alpha_i \approx 0$, the feature contribution is negligible, but sorting must still be consistent to avoid artifacts.
*   **Boundary Conditions:** The product $\prod_{j=1}^{i-1} (1 - \alpha_j)$ becomes 1 when $i=1$ (first Gaussian).

**Pseudocode:**
```python
def render_feature_map(gaussians, camera, width, height, feature_dim):
    """
    Render a 2D feature map from 3D Gaussians.
    
    Args:
        gaussians: List of Gaussian objects with attributes:
            - mean: (3,)
            - cov2d: (2, 2) projected covariance
            - alpha: scalar opacity
            - feature: (feature_dim,) vector f_i
            - z_depth: scalar depth for sorting
        camera: Camera object with projection and view matrices.
        width, height: Image dimensions.
        feature_dim: Dimension D of feature vectors.
        
    Returns:
        F: (height, width, feature_dim) feature map.
    """
    # Initialize output buffer
    F = np.zeros((height, width, feature_dim), dtype=np.float32)
    
    # Project Gaussians to 2D and collect visible ones
    projected_gaussians = []
    for g in gaussians:
        # Project mean to screen space
        center_2d = project_to_screen(g.mean, camera)
        # Compute 2D covariance (simplified; actual implementation uses Jacobian)
        cov2d = compute_2d_covariance(g.cov3d, camera)
        # Check if Gaussian is within bounds and has non-negligible alpha
        if is_visible(center_2d, cov2d, g.alpha, width, height):
            projected_gaussians.append({
                'center': center_2d,
                'cov2d': cov2d,
                'alpha': g.alpha,
                'feature': g.feature,
                'z_depth': g.z_depth
            })
    
    # Sort Gaussians front-to-back by depth
    projected_gaussians.sort(key=lambda g: g['z_depth'])
    
    # Rasterize
    for g in projected_gaussians:
        # Determine bounding box of Gaussian in pixel space
        bbox = get_bounding_box(g['center'], g['cov2d'])
        # Clip to image bounds
        bbox = clip_to_image(bbox, width, height)
        
        for y in range(bbox.y_min, bbox.y_max):
            for x in range(bbox.x_min, bbox.x_max):
                # Compute 2D Gaussian weight at pixel (x, y)
                # w = exp(-0.5 * (p - c)^T Sigma^-1 (p - c))
                weight = evaluate_2d_gaussian(x, y, g['center'], g['cov2d'])
                
                # Alpha contribution
                alpha_contrib = g['alpha'] * weight
                
                # Skip if negligible
                if alpha_contrib < 1e-6:
                    continue
                
                # Transmittance from previous Gaussians (accumulated in a separate buffer)
                # For simplicity, we assume a transmittance buffer T is maintained
                # T[y, x] stores product_{j=1}^{i-1} (1 - alpha_j)
                transmittance = get_transmittance(T, y, x)
                
                # Blend feature
                # F(p) += f_i * alpha_i * product_{j=1}^{i-1} (1 - alpha_j)
                F[y, x] += g['feature'] * alpha_contrib * transmittance
                
                # Update transmittance for next Gaussian
                new_transmittance = transmittance * (1 - alpha_contrib)
                set_transmittance(T, y, x, new_transmittance)
                
    return F
```

## Subtopics

### Scale-Aware Semantic Feature Gating
A mechanism to modulate rendered semantic features based on scale, using learned or fixed gate vectors derived from sampled scales [S2, unofficial]. It maps the distribution of sampled scales to a Gaussian distribution using `self.q_trans(sampled_scales)`. If `scale_aware_dim <= 0` or `scale_aware_dim >= 32`, gates are computed by passing sampled scales through `self.scale_gate`: `gates = self.scale_gate(sampled_scales.unsqueeze(-1))`. Otherwise, scales are discretized to integers: `int_sampled_scales = ((1 - sampled_scales.squeeze()) * scale_aware_dim).long()`, and pre-computed gates are looked up: `gates = self.fixed_scale_gate[int_sampled_scales].detach()`. The rendered features are repeated for each sampled scale: `feature_with_scale = rendered_features.unsqueeze(0).repeat([sampled_scales.shape[0], 1, 1, 1])`, and multiplied by gate vectors: `feature_with_scale = feature_with_scale * gates.unsqueeze(-1).unsqueeze(-1)` [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot A)$, where $N$ is the number of Gaussians and $A$ is the average number of Gaussians per pixel (or tile). The feature blending adds a factor of $D$ (feature dimension) to the per-pixel computation.
*   **Memory Complexity:** $O(N \cdot D)$ to store feature vectors for all Gaussians, plus $O(H \cdot W \cdot D)$ for the feature map buffer.
*   **Performance:** Rendering speed is comparable to standard 3DGS, as feature blending is a simple vector addition and multiplication. However, larger $D$ increases memory bandwidth usage.
*   **Strengths:** Enables real-time open-vocabulary segmentation and semantic understanding. Leverages the speed of 3DGS rasterization.
*   **Limitations:** Requires training or distillation to obtain meaningful feature vectors $\mathbf{f}_i$. High-dimensional features increase memory usage.
*   **When to use:** When semantic or language-aligned 3D representations are needed for downstream tasks like segmentation or query-based retrieval.
*   **When not to use:** When only photorealistic color rendering is required, as it adds unnecessary complexity and memory overhead.

## Background
The method was pioneered by Feature-3DGS [102] and LangSplat [103], which demonstrated that 2D vision-model features could be distilled into 3D Gaussian representations by adding high-dimensional feature vectors to each Gaussian [S1, unofficial]. Language Embedded 3D Gaussians [104] expanded this to full scene understanding, encoding object-level embeddings for phrase grounding. Subsequent works like SplatTalk [105] and 3D Vision-Language GS [106] further extended these capabilities [S1, unofficial].
