# Normalized Depth Rendering

Also called: Depth Normalized by Opacity, Normalized Depth Map

## Overview
Normalized Depth Rendering computes a depth map by dividing the accumulated depth buffer by the accumulated opacity buffer, correcting for transparency artifacts inherent in standard Gaussian splatting compositing [S1, unofficial]. Unlike its parent method, which forces constant opacity to decouple depth from alpha weighting, this method preserves the original scene's opacity distribution while producing a geometrically accurate depth estimate [S1, unofficial].

## How it works
**Inputs:**
*   `render_depth`: Accumulated depth buffer from the standard Gaussian splatting rasterizer.
*   `render_acc`: Accumulated alpha/opacity buffer from the standard Gaussian splatting rasterizer.
*   `znear`: Near plane distance of the camera frustum.
*   `zfar`: Far plane distance of the camera frustum.

**Outputs:**
*   `normalized_depth`: Depth map corrected for transparency.
*   `rendered_disp_norm`: Displayable disparity map.

**Data Structures:**
*   `render_depth`: 2D array of floats, shape $(H, W)$.
*   `render_acc`: 2D array of floats, shape $(H, W)$.

**Steps:**
1.  **Accumulate Depth and Opacity:** Perform standard front-to-back alpha compositing for all $N$ Gaussians sorted by depth at each pixel $(x, y)$.
    *   Accumulate depth: $D_{x,y} = \sum_{n=1}^N z_n \cdot \alpha_n \cdot T_n$
    *   Accumulate opacity: $A_{x,y} = \sum_{n=1}^N \alpha_n \cdot T_n$
    *   Where $z_n$ is the Z-depth of the $n$-th Gaussian, $\alpha_n$ is its opacity, and $T_n$ is the accumulated transparency from previous Gaussians: $T_n = \prod_{j=1}^{n-1} (1 - \alpha_j)$ [S2, unofficial].
2.  **Normalize Depth:** Divide the accumulated depth by the accumulated opacity to handle transparent regions.
    $$ \text{rendered\_depth\_norm}_{x,y} = \frac{D_{x,y}}{A_{x,y}} $$
    *   **Pitfall:** If $A_{x,y} = 0$ (no Gaussians cover the pixel), the result is undefined. In practice, clamp or mask these pixels to a default value (e.g., `zfar` or `NaN`) [G].
3.  **Convert to Disparity (Optional):** Map the normalized depth to a displayable disparity range $[0, 1]$ using the camera frustum bounds.
    $$ \text{rendered\_disp\_norm}_{x,y} = 1 - \frac{\text{rendered\_depth\_norm}_{x,y} - z_{near}}{z_{far} - z_{near}} $$

**Pseudocode:**
```python
def normalized_depth_rendering(render_depth, render_acc, znear, zfar):
    """
    Computes normalized depth and disparity from accumulated buffers.
    
    Args:
        render_depth (Tensor): Accumulated depth buffer (H, W).
        render_acc (Tensor): Accumulated opacity buffer (H, W).
        znear (float): Near plane distance.
        zfar (float): Far plane distance.
        
    Returns:
        Tensor: Normalized depth map (H, W).
        Tensor: Disparity map (H, W).
    """
    # Handle division by zero for pixels with no coverage
    # Replace 0 opacity with a small epsilon to avoid NaN, then mask later if needed
    epsilon = 1e-6
    safe_acc = torch.clamp(render_acc, min=epsilon)
    
    # Step 2: Normalize depth
    normalized_depth = render_depth / safe_acc
    
    # Step 3: Convert to disparity
    # Formula: 1 - (depth - znear) / (zfar - znear)
    # Clamp depth to [znear, zfar] before disparity calculation to avoid out-of-range values
    clamped_depth = torch.clamp(normalized_depth, min=znear, max=zfar)
    disparity = 1.0 - (clamped_depth - znear) / (zfar - znear)
    
    return normalized_depth, disparity
```

## Subtopics

### Depth Rendering with Variable Opacity
Computes expected depth at a pixel $(x, y)$ by compositing Gaussians sorted by depth, weighting each Gaussian's depth $z_n$ by its opacity $\alpha_n$ and accumulated transparency $T_n$ [S2, unofficial]. It calculates the weighted average of depths: $d_{x,y}^{exp} = \frac{\sum_{n=1}^N z_n \cdot \alpha_n \cdot T_n}{\sum_{n=1}^N \alpha_n \cdot T_n}$ [S2, unofficial]. This is mathematically equivalent to the normalized depth calculation in the main method but explicitly framed as an "expected depth" metric rather than a post-processing normalization step. It is chosen when a probabilistic depth estimate is required rather than a simple geometric correction.

## Operating characteristics
*   **Time Complexity:** $O(N)$ per pixel for the accumulation phase (shared with standard splatting), plus $O(1)$ per pixel for the normalization division.
*   **Memory Complexity:** $O(H \times W)$ for the depth and opacity buffers.
*   **Strengths:** Produces geometrically accurate depth maps in transparent or semi-transparent regions where standard depth accumulation fails (e.g., glass, foliage) [S1, unofficial].
*   **Limitations:** Sensitive to noise in low-opacity regions due to division by small numbers; requires robust handling of zero-opacity pixels [G].
*   **When to use:** When accurate depth estimation is needed for scenes with varying opacity, such as in 3D Gaussian Avatar Reconstruction or detailed scene analysis.
*   **When not to use:** When simple geometric depth is sufficient and opacity is uniform, or when performance constraints prohibit the extra division step.

## Background
Normalized Depth Rendering is a technique used in Gaussian Splatting pipelines to improve depth map quality. It was introduced in the context of Gaussian Field of Time-of-Flight (GFTOF) reconstruction, where accurate depth is critical for aligning with ToF sensor data [S1, unofficial]. The method leverages the existing alpha compositing infrastructure of Gaussian Splatting to derive a transparency-corrected depth value.
