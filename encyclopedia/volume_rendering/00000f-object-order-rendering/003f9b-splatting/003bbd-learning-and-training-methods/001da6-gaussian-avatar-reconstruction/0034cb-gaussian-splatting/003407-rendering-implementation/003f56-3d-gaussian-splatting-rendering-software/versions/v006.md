# 3D Gaussian Splatting Rendering (Software)

Also called: 3D Gaussian Splatting (3DGS) Pipeline, 3D Gaussian Splatting Rendering Pipeline, Standard 3D Gaussian Splatting Rendering, Original 3DGS, Kerbl et al. pipeline

## Overview
3D Gaussian Splatting (3DGS) rendering is a software-based rasterization method that represents a 3D scene as a collection of anisotropic Gaussian ellipsoids, projecting them to screen space and alpha-compositing them to generate photorealistic images [S3, unofficial][S4][S5]. It solves the problem of real-time novel view synthesis by replacing volume ray-marching with a tile-based, differentiable rasterization pipeline that leverages the efficiency of GPU fragment shaders [S3, unofficial][S4]. It sets itself apart from its siblings by using a specific software rasterization approach that computes 2D covariances via a first-order Jacobian approximation and sorts Gaussians by depth prior to rasterization, rather than using CPU-side sorting with instancing [2058-3d-gaussian-splatting-rendering-cpu-sorted-instanced.md] or hardware-accelerated ray tracing [8101-3d-gaussian-ray-tracing.md].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $N$ 3D Gaussian primitives, each defined by mean position $\mu \in \mathbb{R}^3$, scale $s \in \mathbb{R}^3$, rotation $q \in \mathbb{R}^4$ (quaternion), opacity $\alpha \in \mathbb{R}$, and spherical harmonics (SH) coefficients $c_{\ell m}$ for view-dependent color [S1][S3, unofficial]. Camera parameters: view matrix $V$, projection intrinsics ($f_x, f_y, c_x, c_y$), near plane $z_{near}$, far plane $z_{far}$ [S6, unofficial].
*   **Output:** A 2D image buffer containing the accumulated color $C_{final}$ for each pixel [S3, unofficial].

**Data Structures:**
The Gaussian data is typically stored in a Structure of Arrays (SoA) layout for efficient memory access during rasterization [S6, unofficial]:
*   `xyz`: `float32[N, 3]` – World space means.
*   `rot`: `float32[N, 4]` – Quaternions (normalized).
*   `scale`: `float32[N, 3]` – Log-space scales (exponentiated during rendering).
*   `opacity`: `float32[N, 1]` – Log-space opacities (sigmoided during rendering).
*   `sh`: `float32[N, SH_dim]` – SH coefficients (e.g., degree 3 implies 16 coefficients per channel, so $N \times 48$ for RGB) [S3, unofficial][S6, unofficial].

**Numbered Steps:**

1.  **Preprocessing and Activation:**
    *   Normalize rotations: $q_i \leftarrow q_i / \|q_i\|$ [S6, unofficial].
    *   Exponentiate scales: $s_i \leftarrow \exp(s_i)$ to ensure positive definiteness [S3, unofficial][S6, unofficial].
    *   Sigmoid opacities: $\alpha_i \leftarrow \sigma(\alpha_i) = 1 / (1 + e^{-\alpha_i})$ [S3, unofficial][S6, unofficial].
    *   Concatenate SH coefficients if stored separately (e.g., DC and rest) into a single array [S6, unofficial].

2.  **Covariance Construction:**
    *   Construct the rotation matrix $R$ from the quaternion $q$ [S1][S3, unofficial].
    *   Construct the diagonal scaling matrix $S = \text{diag}(s)$ [S3, unofficial].
    *   Compute the 3D covariance matrix: $\Sigma_{3D} = R S S^T R^T$ [S1][S3, unofficial].

3.  **Transformation to Camera Space:**
    *   Transform the mean to camera space: $\mu' = V \mu$ [S3, unofficial].
    *   Transform the covariance to camera space using the upper-left $3 \times 3$ submatrix of $V$ (denoted $V_{1:3, 1:3}$): $\Sigma' = V_{1:3, 1:3} \Sigma_{3D} V_{1:3, 1:3}^T$ [S3, unofficial].

4.  **Projection to Screen Space:**
    *   Compute the Jacobian $J$ of the projective projection at $\mu'$:
        $$ J = \begin{pmatrix} \frac{f_x}{\mu'_z} & 0 & -\frac{f_x \mu'_x}{\mu'_z^2} \\ 0 & \frac{f_y}{\mu'_z} & -\frac{f_y \mu'_y}{\mu'_z^2} \end{pmatrix} $$
        [S2][S3, unofficial]. Note: $J$ contains zero terms which can be optimized by hardware [S5].
    *   Compute the 2D screen-space covariance: $\Sigma_{2D} = J \Sigma' J^T$ [S2][S3, unofficial].
    *   Compute the 2D mean: $\mu_{2D} = \begin{pmatrix} \frac{f_x \mu'_x}{\mu'_z} + c_x \\ \frac{f_y \mu'_y}{\mu'_z} + c_y \end{pmatrix}$ [S3, unofficial].

5.  **Conic Representation:**
    *   Compute the inverse 2D covariance $\Sigma_{2D}^{-1}$ [S2][S3, unofficial].
    *   Store the upper-triangular elements as a conic vector $C = [\Sigma_{2D}^{-1}[0,0], \Sigma_{2D}^{-1}[0,1], \Sigma_{2D}^{-1}[1,1]]$ [S2][S3, unofficial]. This avoids repeated matrix inversions during rasterization [S2].

6.  **Culling and Sorting:**
    *   **Near-plane Culling:** Discard Gaussians where $\mu'_z < z_{near}$ [S5][S6, unofficial].
    *   **Frustum Culling:** Discard Gaussians outside the view frustum (optional but recommended for performance) [S3, unofficial].
    *   **Sorting:** Sort the remaining Gaussians by their camera-space depth $\mu'_z$ in ascending order (front-to-back) [S3, unofficial][S5]. This approximates the correct occlusion order without per-pixel sorting [S3, unofficial].

7.  **Rasterization and Alpha Compositing:**
    *   Divide the image into tiles (e.g., $16 \times 16$ pixels) [S5].
    *   For each pixel, iterate through the depth-sorted Gaussians that overlap the pixel's bounding box.
    *   Calculate the 2D Gaussian value at pixel coordinate $\mathbf{x}$ (relative to $\mu_{2D}$):
        $$ G(\mathbf{x}) = \exp\left(-\frac{1}{2} \mathbf{x}^T \Sigma_{2D}^{-1} \mathbf{x}\right) $$
        [S4][S8].
    *   Calculate the effective opacity: $\alpha_{pixel} = \alpha_i \cdot G(\mathbf{x})$ [S3, unofficial].
    *   Update accumulated color $C_{acc}$ and transmittance $T$:
        $$ C_{acc} \leftarrow C_{acc} + T \cdot \alpha_{pixel} \cdot c_i $$
        $$ T \leftarrow T \cdot (1 - \alpha_{pixel}) $$
        [S3, unofficial].
    *   **Early Termination:** Stop processing Gaussians for a pixel if $T < \tau$ (e.g., a small threshold) [S5].
    *   **Background:** Add background color $C_{bg}$: $C_{final} = C_{acc} + T \cdot C_{bg}$ [S3, unofficial].

**Pseudocode:**

```python
import numpy as np

def render_gaussians(gaussians, camera, image_width, image_height, tile_size=16):
    """
    Render 3D Gaussians using the standard software rasterization pipeline.
    
    Args:
        gaussians: Dict with keys 'xyz', 'rot', 'scale', 'opacity', 'sh' (N, D)
        camera: Dict with keys 'view_matrix', 'fx', 'fy', 'cx', 'cy', 'znear', 'zfar'
        image_width, image_height: int
        tile_size: int
        
    Returns:
        image: (H, W, 3) float32 array
    """
    N = gaussians['xyz'].shape[0]
    H, W = image_height, image_width
    image = np.zeros((H, W, 3), dtype=np.float32)
    
    # 1. Preprocessing
    # Normalize rotations
    rots = gaussians['rot'] / np.linalg.norm(gaussians['rot'], axis=1, keepdims=True)
    # Exponentiate scales
    scales = np.exp(gaussians['scale'])
    # Sigmoid opacities
    opacities = 1.0 / (1.0 + np.exp(-gaussians['opacity']))
    
    # 2. Covariance Construction
    # Construct rotation matrices from quaternions
    R = quaternions_to_matrices(rots) # Helper function, see below
    S = np.zeros((N, 3, 3))
    for i in range(N):
        S[i] = np.diag(scales[i])
    
    # Sigma_3D = R S S^T R^T
    # Optimization: S S^T is diag(s^2)
    S_sq = np.einsum('ij,ik->ijk', S, S) # Or simply np.diag(scales**2) per Gaussian
    # More efficient:
    S_sq = np.zeros((N, 3, 3))
    for i in range(N):
        s2 = scales[i] ** 2
        S_sq[i, 0, 0] = s2[0]
        S_sq[i, 1, 1] = s2[1]
        S_sq[i, 2, 2] = s2[2]
        
    Sigma_3D = np.einsum('nij,njk,nkl->nil', R, S_sq, R.transpose(0, 2, 1))
    
    # 3. Transformation to Camera Space
    V = camera['view_matrix']
    V_3x3 = V[:3, :3]
    
    # Mu' = V * Mu
    Mu_homogeneous = np.hstack([gaussians['xyz'], np.ones((N, 1))])
    Mu_cam = (V @ Mu_homogeneous.T).T[:, :3] # (N, 3)
    
    # Sigma' = V_3x3 * Sigma_3D * V_3x3^T
    Sigma_cam = np.einsum('ij,njk,kl->nil', V_3x3, Sigma_3D, V_3x3.T)
    
    # 4. Projection
    fx = camera['fx']
    fy = camera['fy']
    cx = camera['cx']
    cy = camera['cy']
    znear = camera['znear']
    
    # Culling: Near plane
    valid_mask = Mu_cam[:, 2] >= znear
    Mu_cam = Mu_cam[valid_mask]
    Sigma_cam = Sigma_cam[valid_mask]
    opacities = opacities[valid_mask]
    rots = rots[valid_mask]
    scales = scales[valid_mask]
    R = R[valid_mask]
    S_sq = S_sq[valid_mask]
    Sigma_3D = Sigma_3D[valid_mask]
    Mu_homogeneous = Mu_homogeneous[valid_mask]
    
    N_valid = Mu_cam.shape[0]
    if N_valid == 0:
        return image
        
    # Jacobian J
    # J = [[fx/z, 0, -fx*x/z^2], [0, fy/z, -fy*y/z^2]]
    zx = Mu_cam[:, 2]
    zx_sq = zx ** 2
    J = np.zeros((N_valid, 2, 3))
    J[:, 0, 0] = fx / zx
    J[:, 0, 2] = -fx * Mu_cam[:, 0] / zx_sq
    J[:, 1, 1] = fy / zx
    J[:, 1, 2] = -fy * Mu_cam[:, 1] / zx_sq
    
    # Sigma_2D = J * Sigma_cam * J^T
    Sigma_2D = np.einsum('nij,njk,nlk->nil', J, Sigma_cam, J)
    
    # Mu_2D
    Mu_2D = np.zeros((N_valid, 2))
    Mu_2D[:, 0] = fx * Mu_cam[:, 0] / zx + cx
    Mu_2D[:, 1] = fy * Mu_cam[:, 1] / zx + cy
    
    # 5. Conic Representation
    # Inverse Sigma_2D
    # Sigma_2D is 2x2 symmetric. Inverse of [[a, b], [b, c]] is 1/(ac-b^2) * [[c, -b], [-b, a]]
    a = Sigma_2D[:, 0, 0]
    b = Sigma_2D[:, 0, 1]
    c = Sigma_2D[:, 1, 1]
    det = a * c - b * b
    
    # Guard against singular matrices
    eps = 1e-6
    det = np.maximum(det, eps)
    
    inv_a = c / det
    inv_b = -b / det
    inv_c = a / det
    
    Conics = np.stack([inv_a, inv_b, inv_c], axis=1) # (N, 3)
    
    # 6. Sorting
    # Sort by depth (z)
    sort_indices = np.argsort(Mu_cam[:, 2])
    Mu_2D = Mu_2D[sort_indices]
    Sigma_2D = Sigma_2D[sort_indices]
    Conics = Conics[sort_indices]
    opacities = opacities[sort_indices]
    Mu_cam = Mu_cam[sort_indices]
    
    # 7. Rasterization
    # Tile-based rasterization
    # For simplicity, we iterate over pixels and Gaussians (inefficient but correct for software)
    # In practice, use a tile-based approach: for each tile, find overlapping Gaussians
    
    # Create a list of Gaussians with their bounding boxes
    # Bounding box radius: 3 sigma
    # Approximate radius from conic: sqrt(3 * max(eigenvalues)) or simpler: 3 * sqrt(diag)
    # Using 3 * sqrt(diag) for simplicity
    radii = 3.0 * np.sqrt(np.maximum(Sigma_2D[:, 0, 0], Sigma_2D[:, 1, 1]))
    
    # For each pixel, find overlapping Gaussians
    # This is O(N * H * W) in naive implementation. 
    # A proper software renderer would use a tile-based approach.
    # Here we implement a simplified version for clarity.
    
    # Precompute SH colors for the current view direction? 
    # For this software implementation, we assume constant color c_i for simplicity 
    # or pre-evaluate SH if view direction is fixed. 
    # Let's assume c_i is pre-computed or constant.
    # In real 3DGS, c_i depends on view direction. 
    # We will assume c_i is provided or constant for this software example.
    # Let's assume 'sh' coefficients are used to compute color.
    # For brevity, we assume 'colors' is pre-computed (N, 3)
    # If not, we must evaluate SH.
    
    # Evaluate SH for each Gaussian towards the camera center (approximate)
    # Or just use DC component for simplicity in this software demo
    # SH degree 3: 16 coeffs. DC is first 3.
    # Let's assume 'sh' contains DC and rest.
    # For this software implementation, we use the DC component as color.
    # In full 3DGS, SH is evaluated per pixel based on view direction.
    # We will skip full SH evaluation for this software example to keep it concise,
    # assuming 'colors' is available.
    
    # Let's assume 'colors' is passed or computed.
    # For this example, we use the DC component of SH as color.
    # sh shape: (N, 48) for degree 3 (3 channels * 16 coeffs)
    # DC is first 3 coeffs per channel.
    # Reshape to (N, 3, 16)
    sh_reshaped = gaussians['sh'][valid_mask][sort_indices].reshape(N_valid, 3, 16)
    colors = sh_reshaped[:, :, 0] # DC component only for simplicity
    
    # Tile-based rasterization loop
    for ty in range(0, H, tile_size):
        for tx in range(0, W, tile_size):
            # Find Gaussians overlapping this tile
            # Bounding box of tile
            tile_min_x = tx
            tile_max_x = min(tx + tile_size, W)
            tile_min_y = ty
            tile_max_y = min(ty + tile_size, H)
            
            # Check overlap with Gaussian bounding box
            # Gaussian bbox: [mu_x - r, mu_x + r], [mu_y - r, mu_y + r]
            # This check is expensive in Python. 
            # In C++/CUDA, this is done with SIMD.
            # For this software example, we skip the tile optimization and do per-pixel.
            pass

    # Simplified per-pixel rasterization (for correctness demonstration)
    # This is extremely slow for large images, but correct.
    for y in range(H):
        for x in range(W):
            pixel_pos = np.array([x, y], dtype=np.float32)
            T = 1.0
            C_acc = np.array([0.0, 0.0, 0.0], dtype=np.float32)
            
            for i in range(N_valid):
                # Check if pixel is inside Gaussian bbox
                mu_x, mu_y = Mu_2D[i]
                r = radii[i]
                if abs(x - mu_x) > r or abs(y - mu_y) > r:
                    continue
                
                # Compute alpha
                dx = x - mu_x
                dy = y - mu_y
                x_vec = np.array([dx, dy], dtype=np.float32)
                
                # Alpha = opacity * exp(-0.5 * x^T Sigma^-1 x)
                # Conic is [inv_a, inv_b, inv_c]
                # x^T Sigma^-1 x = inv_a * dx^2 + 2 * inv_b * dx * dy + inv_c * dy^2
                exponent = -0.5 * (Conics[i, 0] * dx**2 + 2 * Conics[i, 1] * dx * dy + Conics[i, 2] * dy**2)
                alpha_pixel = opacities[i] * np.exp(exponent)
                
                if alpha_pixel < 1e-4: # Skip negligible contributions
                    continue
                
                C_acc += T * alpha_pixel * colors[i]
                T *= (1 - alpha_pixel)
                
                if T < 1e-4: # Early termination
                    break
            
            # Add background
            C_acc += T * np.array([0.0, 0.0, 0.0], dtype=np.float32) # Assume black background
            image[y, x] = C_acc
            
    return image

def quaternions_to_matrices(quats):
    """Convert quaternions to rotation matrices."""
    # q = [w, x, y, z]
    # This is a standard conversion.
    # For brevity, we assume a helper function exists.
    # In a real implementation, this would be a vectorized numpy operation.
    N = quats.shape[0]
    R = np.zeros((N, 3, 3))
    w, x, y, z = quats[:, 0], quats[:, 1], quats[:, 2], quats[:, 3]
    
    # Standard conversion formula
    R[:, 0, 0] = 1 - 2*(y*y + z*z)
    R[:, 0, 1] = 2*(x*y - w*z)
    R[:, 0, 2] = 2*(x*z + w*y)
    
    R[:, 1, 0] = 2*(x*y + w*z)
    R[:, 1, 1] = 1 - 2*(x*x + z*z)
    R[:, 1, 2] = 2*(y*z - w*x)
    
    R[:, 2, 0] = 2*(x*z - w*y)
    R[:, 2, 1] = 2*(y*z + w*x)
    R[:, 2, 2] = 1 - 2*(x*x + y*y)
    
    return R
```

### Perspective-Correct 3D Gaussian Splat Evaluation
A differentiable method that avoids matrix inversion during Gaussian evaluation, ensuring numerical stability and eliminating special handling for degenerate splats [S9]. Unlike the affine approximation in standard 3DGS which causes perspective distortion at close distances, this method provides fully perspective-correct rendering within a rasterization pipeline for real-time performance [S9].

### Fisheye Camera Adaptation (Equidistant Projection)
Adapts the rasterization projection for fisheye cameras by modifying the transformation from image space to camera space using the equidistant projection model [S7]. It computes the 2D coordinate vector $\mathbf{x}_{2D}$ using intrinsic parameters $c_x, c_y, f_x, f_y$ and the equidistant formula involving trigonometric functions of the pixel coordinates [S7].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot T)$ where $N$ is the number of Gaussians and $T$ is the number of tiles/pixels, but optimized by culling and early termination. Sorting is $O(N \log N)$ [S3, unofficial].
*   **Memory Complexity:** $O(N)$ for storing Gaussian attributes [S5].
*   **Measured Performance:** Originally targets desktop GPUs, achieving real-time rendering (e.g., 129 FPS for Full HD) [S5]. However, it faces memory and bandwidth limits on mobile/AR-VR edge devices [S5].
*   **Strengths:** Real-time rendering speeds, high-quality novel view synthesis, differentiable optimization [S3, unofficial][S4].
*   **Limitations:** High memory usage for large scenes (millions of Gaussians), perspective distortion artifacts at close distances due to affine approximation [S5][S9].
*   **When to use:** Real-time novel view synthesis on desktop GPUs.
*   **When not to use:** Resource-constrained devices (mobile/AR-VR) without optimization, or when perspective-correct rendering is critical without approximation [S5][S9].

## Background
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S3, unofficial][S4]. It models a 3D scene as a set of unnormalized 3D Gaussian point primitives, each defined by mean, covariance, opacity, and spherical harmonics coefficients [S3, unofficial]. The method uses a tile-based, differentiable software rasterizer for rendering, achieving real-time performance and state-of-the-art rendering quality for novel view synthesis [S3, unofficial][S4]. The optimization process involves adaptive density control, adding and removing Gaussians based on gradient flow [S3, unofficial][S4].
