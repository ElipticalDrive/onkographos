# SparseOIT Rasterizer

Also called: GPU software rasterization of 3D Gaussians with pre-rendering

## Overview
The SparseOIT Rasterizer is a rendering algorithm for 3D Gaussian Splatting that computes a blended image using Order-Independent Transparency (OIT) without sorting Gaussians by depth [S1, unofficial]. It simultaneously produces a final color image and a pre-rendered state using a blend-and-normalize (BAN) function and a blend-and-update (BAU) function [S1, unofficial]. Unlike standard 3DGS rasterization, which requires sorting by distance to camera to correctly accumulate transmittance, this method eliminates the sorting step entirely in favor of a weighted average that approximates the order-dependent result [S1, unofficial]. It builds on [Transparency and Blending Models](9274-transparency-and-blending-models.md).

## How it works
**Inputs:**
*   Image dimensions: width $w$, height $h$.
*   Gaussian attributes: 3D means $\mathbf{M}$, covariances $\mathbf{S}$, colors $\mathbf{C}$, opacities $\mathbf{A}$.
*   View matrix: $\mathbf{V}$.

**Outputs:**
*   Rendered image: $\mathbf{I}$ (final color).
*   Pre-rendered image: $\mathbf{I}_{pre}$ (intermediate state for accumulation).

**Data Structures:**
*   **Tiles ($\mathbf{T}$):** A grid partitioning the image into square tiles. The specific tile size is not given in the sources [G].
*   **Gaussian List ($\mathbf{L}$):** A list of Gaussian data structures, duplicated per tile they overlap. Each entry contains projected mean $\mathbf{M}'$, projected covariance $\mathbf{S}'$, color $\mathbf{c}$, opacity $\alpha$, and a tile key $k$.
*   **Keys ($\mathbf{K}$):** An array of tile IDs corresponding to entries in $\mathbf{L}$.
*   **Ranges ($\mathbf{R}$):** An array mapping each tile ID to the start and end indices in $\mathbf{L}$ for that tile.

**Parameters:**
*   **Weight ($w_i$):** A learnable or fixed weight for the $i$-th Gaussian. The sources do not specify the initial value or update rule for $w_i$ in the rasterization step itself, only its use in the forward and backward passes [S1, unofficial].
*   **Background Color ($\mathbf{c}_0$):** The color of the background.

**Algorithm Steps:**
1.  **Cull:** Remove Gaussians outside the view frustum defined by $\mathbf{V}$ [S1, unofficial].
2.  **Project:** Compute 2D screen-space means $\mathbf{M}'$ and covariances $\mathbf{S}'$ for the remaining Gaussians using $\mathbf{V}$ [S1, unofficial].
3.  **Tile:** Create a tile grid $\mathbf{T}$ for the image dimensions $w, h$ [S1, unofficial].
4.  **Duplicate & Key:** For each Gaussian, determine which tiles it overlaps. Duplicate the Gaussian data for each overlapping tile and assign the corresponding tile ID as a key $k$ [S1, unofficial]. Store these in list $\mathbf{L}$ and keys $\mathbf{K}$.
5.  **Sort:** Sort $\mathbf{L}$ and $\mathbf{K}$ based on the tile keys $k$ [S1, unofficial]. This is the only sorting step; no depth sorting is performed.
6.  **Range:** Identify the start and end indices in $\mathbf{L}$ for each tile, storing them in $\mathbf{R}$ [S1, unofficial].
7.  **Initialize:** Set $\mathbf{I}$ to zero. Initialize $\mathbf{I}_{pre}$ (details of initialization not given, assumed zero or background) [S1, unofficial].
8.  **Rasterize:** Iterate over each tile $t \in \mathbf{T}$:
    9.  Iterate over each pixel $i$ in tile $t$:
    10. Get the range $r$ of Gaussians in $\mathbf{L}$ belonging to tile $t$ [S1, unofficial].
    11. Compute final color $\mathbf{I}[i]$ using the BAN function [S1, unofficial].
    12. Update pre-rendered state $\mathbf{I}_{pre}[i]$ using the BAU function [S1, unofficial].

**Formulas:**
The final color $\mathbf{C}$ (stored in $\mathbf{I}$) is computed as [S1, unofficial]:
$$
\mathbf{C} = T \mathbf{c}_0 + (1-T)F
$$
where $T$ is the accumulated opacity/transmittance factor. The sources do not explicitly define $T$ in the forward pass formula, but in standard OIT, $T$ is often the sum of opacities or a transmittance term. However, the provided formula for $F$ and the gradients suggest $T$ might be a constant or derived from the pre-render state. The sources define $F$ as [S1, unofficial]:
$$
F = \frac{P}{Q}, \quad P = \sum_{i=1}^{N} \mathbf{c}_i \alpha_i w_i, \quad Q = \sum_{i=1}^{N} \alpha_i w_i
$$
Here, the sum is over all Gaussians $i$ contributing to the pixel (within the tile range $r$). $\mathbf{c}_i$ is the color, $\alpha_i$ is the opacity, and $w_i$ is the weight of the $i$-th Gaussian.

**Pseudocode:**
```python
def SparseOITRasterizer(w, h, M, S, C, A, V):
    # 1. Cull Gaussians
    valid_indices = CullGaussian(M, V)
    M_proj = M[valid_indices]
    S_proj = S[valid_indices]
    C_proj = C[valid_indices]
    A_proj = A[valid_indices]

    # 2. Create Tiles
    T = CreateTiles(w, h)

    # 3. Duplicate with Keys
    L = []
    K = []
    for i, (mean, cov, color, alpha) in enumerate(zip(M_proj, S_proj, C_proj, A_proj)):
        # Determine overlapping tiles for this Gaussian
        # Note: Exact overlap test logic is not provided in sources [G]
        overlapping_tiles = GetOverlappingTiles(mean, cov, T)
        for tile_id in overlapping_tiles:
            L.append({
                'M_prime': mean,
                'S_prime': cov,
                'C': color,
                'A': alpha,
                'W': 1.0 # Default weight, assumed 1.0 if not learned [G]
            })
            K.append(tile_id)

    # 4. Sort by Tile ID
    # Sort L and K based on K
    combined = list(zip(K, L))
    combined.sort(key=lambda x: x[0])
    K_sorted, L_sorted = zip(*combined) if combined else ([], [])
    K_sorted = list(K_sorted)
    L_sorted = list(L_sorted)

    # 5. Identify Tile Ranges
    R = {}
    current_tile = None
    start_idx = 0
    for idx, tile_id in enumerate(K_sorted):
        if tile_id != current_tile:
            if current_tile is not None:
                R[current_tile] = (start_idx, idx)
            current_tile = tile_id
            start_idx = idx
    if current_tile is not None:
        R[current_tile] = (start_idx, len(K_sorted))

    # 6. Initialize Images
    I = np.zeros((h, w, 3))
    I_pre = np.zeros((h, w, 3)) # Assumed initialization [G]

    # 7. Rasterize
    for t in T:
        tile_id = t.id
        if tile_id not in R:
            continue
        start, end = R[tile_id]
        tile_gaussians = L_sorted[start:end]

        for pixel in t.pixels:
            # Compute BAN and BAU
            # Note: The exact implementation of BAN and BAU is not provided in the sources [G]
            # Based on the formula, BAN computes the weighted average F
            # and BAU likely accumulates weights/opacities for T
            
            # Extract attributes for this pixel
            # Note: Gaussian contribution to a specific pixel requires 
            # evaluating the 2D Gaussian function at the pixel coordinate.
            # This step is missing from the high-level algorithm [G]
            
            # Placeholder for Gaussian evaluation and accumulation
            P = 0
            Q = 0
            T_factor = 0 # Accumulated opacity/transmittance
            
            for g in tile_gaussians:
                # Evaluate 2D Gaussian at pixel position
                # alpha_pixel = alpha * exp(-0.5 * (x-M')^T S'^-1 (x-M'))
                # This evaluation is standard in 3DGS but not detailed in SparseOIT notes [G]
                # Assuming alpha_i in the formula refers to the projected alpha at the pixel
                alpha_i = EvaluateGaussian(g['M_prime'], g['S_prime'], pixel)
                c_i = g['C']
                w_i = g['W']
                
                P += c_i * alpha_i * w_i
                Q += alpha_i * w_i
                T_factor += alpha_i # Assumption for T, not explicitly defined [G]
            
            if Q > 0:
                F = P / Q
            else:
                F = 0
            
            # Final Color
            # Note: T in the formula C = T*c0 + (1-T)*F is ambiguous. 
            # In standard OIT, T is often sum(alpha). 
            # The sources do not define T's calculation in the forward pass [G]
            # Assuming T is the sum of alphas for demonstration
            if T_factor > 0:
                T_val = 1.0 - np.exp(-T_factor) # Standard alpha compositing assumption [G]
            else:
                T_val = 0
                
            I[pixel] = T_val * c0 + (1 - T_val) * F
            
            # BAU Update
            # Updates I_pre for subsequent blending or accumulation
            # Exact logic not provided [G]
            I_pre[pixel] = P # Example update

    return I, I_pre
```

**Backward Propagation:**
The gradients for optimization are computed as [S1, unofficial]:
$$
\frac{\partial \mathbf{C}}{\partial \mathbf{c}_i} = (1-T)\frac{\alpha_i w_i}{Q}
$$
$$
\frac{\partial \mathbf{C}}{\partial \alpha_i} = \frac{T}{1-\alpha_i}(F-\mathbf{c}_0) + (1-T)\frac{w_i}{Q}(\mathbf{c}_i - F)
$$
$$
\frac{\partial \mathbf{C}}{\partial w_i} = (1-T)\frac{\alpha_i}{Q}(\mathbf{c}_i - F)
$$
The variables of each Gaussian are mutually independent in the backward propagation equation, allowing for parallel computation [S1, unofficial].

## Subtopics

### [Weighted Order-Independent Transparency for 3DGS](7772-weighted-order-independent-transparency-for-3dgs.md)
Weighted Order-Independent Transparency (OIT) for 3D Gaussian Splatting (3DGS) is a rendering technique that computes a blended image without sorting Gaussians by depth, using a learnable weight function to approximate correct transparency blending. It differs from standard 3DGS rasterization, which requires sorting by distance to camera to correctly accumulate transmittance, by eliminating the sorting step entirely in favor of a weighted average that approximates the order-dependent result.

## Operating characteristics
*   **Time Complexity:** The sorting step is reduced to sorting by tile ID, which is significantly faster than full depth sorting. However, the BAN and BAU functions must be computed per pixel for all overlapping Gaussians. The complexity is $O(N \cdot T)$ where $N$ is the number of Gaussians and $T$ is the average number of Gaussians per tile/pixel, but without the $O(N \log N)$ sorting cost.
*   **Memory Complexity:** Requires storing duplicated Gaussian data for each tile they overlap, increasing memory usage compared to non-duplicated approaches.
*   **Strengths:** Eliminates the expensive depth sorting step. Order-independent, avoiding artifacts from incorrect sorting.
*   **Limitations:** The approximation of order-dependent transparency via weighted averages may introduce visual artifacts in complex scenes. The exact definition of $T$ and the BAU function are not fully specified, potentially leading to implementation ambiguity.
*   **When to use:** When sorting overhead is a bottleneck and approximate transparency is acceptable.
*   **When not to use:** When exact order-dependent transparency is required.

## Background
The SparseOIT Rasterizer was introduced in the paper "SparseOIT: Improving Order-Independent Transparency 3DGS via Active Set Method" [S1, unofficial]. It is part of the development of 3D Gaussian Splatting rendering techniques, aiming to improve efficiency and quality by removing the sorting dependency.
