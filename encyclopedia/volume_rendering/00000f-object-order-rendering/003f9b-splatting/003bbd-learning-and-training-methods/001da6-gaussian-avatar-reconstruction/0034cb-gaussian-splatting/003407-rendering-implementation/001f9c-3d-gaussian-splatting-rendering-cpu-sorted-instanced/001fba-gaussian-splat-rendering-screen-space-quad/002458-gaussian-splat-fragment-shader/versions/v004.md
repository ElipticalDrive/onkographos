# Gaussian Splat Fragment Shader

Also called: 2D Gaussian Splat Fragment Evaluation, FGaussianSplatPS, Gaussian Alpha Cutoff, Gaussian Splat Pixel Shader, Over Operator, Pre-multiplied Alpha Blending, Splat Fragment Shader, splat.frag

## Overview
The Gaussian Splat Fragment Shader evaluates the 2D Gaussian probability density function (PDF) at each fragment of a screen-space quad to determine splat coverage and modulate fragment color [S1, S3, unofficial]. It composites the new splat over the existing framebuffer color using pre-multiplied alpha blending [S1, unofficial]. It is distinguished from its parent [Gaussian Splat Rendering (Screen-Space Quad)](2075-gaussian-splat-rendering-screen-space-quad.md) by performing the per-pixel alpha evaluation and blending logic directly in the fragment shader, handling transparency via alpha cutoffs and discarding fragments behind the camera or with negligible alpha [S1, S3, unofficial].

## How it works
**Inputs and Outputs:**
The shader receives vertex attributes passed from the vertex stage: `vColor` (a `vec4` containing RGBA color, where RGB is typically unmultiplied or pre-multiplied depending on the pipeline, but the shader treats it as the source color) and `vPosition` (a `vec2` containing the 2D position relative to the splat center in screen space) [S3, unofficial]. The output is `fragColor` (a `vec4`) written to the framebuffer [S3, unofficial]. The framebuffer pixel format is assumed to be 32-bit BGRA, packed as a `u32` [S1, unofficial].

**Data Structures and Layout:**
The framebuffer stores pixels as a `u32` integer. The bit layout is:
- Bits 0-7: Blue (B)
- Bits 8-15: Green (G)
- Bits 16-23: Red (R)
- Bits 24-31: Alpha (A)
This is little-endian byte order representation of the 32-bit integer [S1, unofficial].

**Parameters:**
- `alpha_cutoff`: `f32 = 1.0/255.0`. Minimum alpha threshold to discard fragments [S1, unofficial].
- `whitePoint`: `f32 = 0.9`. Used for tone mapping [S3, unofficial].

**Steps:**
1.  **Compute Squared Distance:** Calculate the squared distance $A$ from the splat center using the dot product of the normalized screen-space coordinates `vPosition` [S1, S3, unofficial].
    $$ A = -\text{dot}(\mathbf{vPosition}, \mathbf{vPosition}) $$
    Note: Some implementations compute `power = dot(vPosition, vPosition)` and use `-0.5 * power` in the exponential, which is equivalent to the standard 2D Gaussian PDF form $\alpha(u, v) = \alpha_0 \exp\left(-\frac{1}{2}(u^2 + v^2)\right)$ [S1, S3, unofficial]. The source [S3, unofficial] uses $A$ directly as the argument to exp, implying `vPosition` might be scaled or the formula is adapted. We follow the explicit formula from [S1, unofficial] and the code from [S3, unofficial] which computes `gaussian = exp(A)` where `A = -dot(vPosition, vPosition)`. This implies the base opacity scaling is handled separately or `vPosition` is normalized such that the variance is 1. However, [S1, unofficial] explicitly states $\alpha(u, v) = \alpha_0 \exp\left(-\frac{1}{2}(u^2 + v^2)\right)$. The code in [S1, unofficial] uses `(-0.5 * power).exp()`. The code in [S3, unofficial] uses `exp(A)` where `A = -dot(...)`. This is a discrepancy. [S3, unofficial] also applies `edgeSmoothness`. We will describe the more complete pipeline from [S3, unofficial] which includes smoothing, while noting the standard Gaussian from [S1, unofficial].

    *Reconciliation:* [S1, unofficial] provides the core mathematical definition. [S3, unofficial] provides a specific implementation with optimizations (smoothstep, tone mapping). We present the [S3, unofficial] implementation as it is more complete for a "Fragment Shader" article, but define the Gaussian evaluation clearly.

2.  **Evaluate Gaussian Alpha:** Compute the Gaussian falloff.
    Using the standard definition [S1, unofficial]:
    $$ \alpha_{raw} = \alpha_0 \exp\left(-\frac{1}{2} \|\mathbf{vPosition}\|^2\right) $$
    Where $\alpha_0$ is the base opacity from `vColor.a` [S1, S3, unofficial].
    In [S3, unofficial], this is computed as:
    $$ A = -\text{dot}(\mathbf{vPosition}, \mathbf{vPosition}) $$
    $$ \text{gaussian} = \exp(A) $$
    $$ \alpha_{new} = \text{gaussian} \times \mathbf{vColor}.a \times \text{edgeSmoothness} $$
    Where `edgeSmoothness` is a smoothstep function [S3, unofficial].

3.  **Edge Smoothing (Optional/Implementation Specific):** [S3, unofficial] applies an edge smoothness factor to avoid hard cutoffs.
    $$ \text{edgeSmoothness} = \text{smoothstep}(-4.0, -3.5, A) $$
    Where $A = -\|\mathbf{vPosition}\|^2$ [S3, unofficial].

4.  **Alpha Cutoff:** Discard fragments where the computed alpha is below the threshold.
    If $\alpha_{new} < \text{alpha\_cutoff}$ (where $\text{alpha\_cutoff} = 1.0/255.0$), discard the fragment [S1, S3, unofficial].
    *Note:* [S3, unofficial] checks `if A < -4.0` discard. This is a proxy for the alpha cutoff based on distance. We will use the explicit alpha check as per [S1, unofficial] and the general description, but note the distance check in [S3, unofficial].

5.  **Modulate Color:** Multiply the RGB channels by the computed alpha to produce pre-multiplied color.
    $$ \mathbf{C}_{new\_premult} = \alpha_{new} \times \mathbf{vColor}.rgb $$
    [S1, unofficial] states: `color = Vector4::new(color[0]*alpha, color[1]*alpha, color[2]*alpha, alpha)`.
    [S3, unofficial] states: `color = B * vColor.rgb` where `B = gaussian * vColor.a * edgeSmoothness`.

6.  **Post-Processing (Implementation Specific):** [S3, unofficial] applies additional color adjustments before blending:
    -   **Saturation Adjustment:**
        $$ L = \text{dot}(\mathbf{C}_{new\_premult}, \text{vec3}(0.2126, 0.7152, 0.0722)) $$
        $$ \mathbf{C}_{sat} = \text{mix}(\text{vec3}(L), \mathbf{C}_{new\_premult}, 1.2) $$
    -   **White Point (Tone Mapping):**
        $$ \mathbf{C}_{tone} = \mathbf{C}_{sat} \times \frac{1.0 + \mathbf{C}_{sat} / (\text{whitePoint} \times \text{whitePoint})}{1.0 + \mathbf{C}_{sat}} $$
        With $\text{whitePoint} = 0.9$ [S3, unofficial].
    -   **Sharpening:**
        $$ \mathbf{C}_{final} = \mathbf{C}_{tone}^{\text{vec3}(1.0 / 1.05)} $$
    -   The final alpha is $\alpha_{new}$ [S3, unofficial].

7.  **Read Existing Framebuffer:** Unpack the existing framebuffer pixel from BGRA `u32` format into a `vec4` of normalized floats [S1, unofficial].
    Let `old_color_u32` be the value read from the framebuffer.
    $$ \mathbf{C}_{old} = \text{vec4}\left( \frac{(\text{old\_color\_u32} \gg 16) \& 0xFF}{255.0}, \frac{(\text{old\_color\_u32} \gg 8) \& 0xFF}{255.0}, \frac{\text{old\_color\_u32} \& 0xFF}{255.0}, \frac{(\text{old\_color\_u32} \gg 24) \& 0xFF}{255.0} \right) $$
    [S1, unofficial]

8.  **Composite (Over Operator):** Blend the new fragment over the old pixel using the over operator [S1, unofficial].
    $$ \mathbf{C}_{out} = (1 - \alpha_{new}) \mathbf{C}_{old}.rgb + \alpha_{new} \mathbf{C}_{final}.rgb $$
    $$ \alpha_{out} = \alpha_{new} + (1 - \alpha_{new}) \mathbf{C}_{old}.a $$
    *Note:* The sources [S1, unofficial] provide a simplified blend formula: `blended_color = (1.0 - alpha) * old_color + alpha * new_color`. This assumes `old_color` is pre-multiplied or the alpha channel is handled separately. Standard over operator for pre-multiplied alpha is:
    $$ \mathbf{C}_{out} = \mathbf{C}_{new\_premult} + (1 - \alpha_{new}) \mathbf{C}_{old\_premult} $$
    $$ \alpha_{out} = \alpha_{new} + (1 - \alpha_{new}) \alpha_{old} $$
    [S1, unofficial] code snippet: `let blended_color = (1.0 - alpha) * old_color + alpha * new_color;`. Here `old_color` is a `vec4` including alpha. This is not standard pre-multiplied blending if `old_color` is not pre-multiplied. However, the output discards alpha, so the alpha channel of the framebuffer is likely used for depth/coverage but not stored in the final color buffer (or stored in the alpha channel of the u32). The output format discards alpha [S1, unofficial]. The `fragColor` in [S3, unofficial] sets `fragColor = vec4(color, B)`. This suggests the alpha is written to the framebuffer alpha channel.

9.  **Quantize and Pack:** Quantize the blended RGB channels back to 8-bit integers and pack them into a `u32` BGRA pixel. The alpha channel is discarded from the output color but may be written to the alpha channel of the framebuffer if supported [S1, unofficial].
    $$ R = \lfloor \mathbf{C}_{out}.r \times 255.0 \rfloor $$
    $$ G = \lfloor \mathbf{C}_{out}.g \times 255.0 \rfloor $$
    $$ B = \lfloor \mathbf{C}_{out}.b \times 255.0 \rfloor $$
    $$ \text{output\_u32} = (R \ll 16) | (G \ll 8) | B $$
    [S1, unofficial]

**Pseudocode:**
```python
# Inputs:
# vColor: vec4 (RGBA)
# vPosition: vec2 (screen space relative to center)
# alpha_cutoff: f32 = 1.0/255.0
# whitePoint: f32 = 0.9

# 1. Compute squared distance
A = -dot(vPosition, vPosition)

# 2. Edge smoothness (from [S3, unofficial])
edgeSmoothness = smoothstep(-4.0, -3.5, A)

# 3. Evaluate Gaussian
gaussian = exp(A)
alpha_new = gaussian * vColor.a * edgeSmoothness

# 4. Alpha cutoff
if alpha_new < alpha_cutoff:
    discard_fragment()

# 5. Modulate color
color_premult = vColor.rgb * alpha_new

# 6. Post-processing (from [S3, unofficial])
# Saturation
luminance = dot(color_premult, vec3(0.2126, 0.7152, 0.0722))
color_sat = mix(vec3(luminance), color_premult, 1.2)

# Tone mapping
color_tone = color_sat * (1.0 + color_sat / (whitePoint * whitePoint)) / (1.0 + color_sat)

# Sharpening
color_final = pow(color_tone, vec3(1.0 / 1.05))

# 7. Read old framebuffer pixel (BGRA u32)
old_color_u32 = read_framebuffer_pixel() # Returns u32
old_r = ((old_color_u32 >> 16) & 0xFF) / 255.0
old_g = ((old_color_u32 >> 8) & 0xFF) / 255.0
old_b = (old_color_u32 & 0xFF) / 255.0
old_a = ((old_color_u32 >> 24) & 0xFF) / 255.0
old_color = vec4(old_r, old_g, old_b, old_a)

# 8. Composite
# Note: [S1, unofficial] uses a simplified blend. Standard pre-multiplied blend:
# C_out = C_new_premult + (1 - alpha_new) * C_old_premult
# However, [S1, unofficial] code: blended_color = (1.0 - alpha) * old_color + alpha * new_color
# This implies old_color is NOT pre-multiplied in the blend step, or it's a specific approximation.
# We follow [S1, unofficial] code structure for consistency with the source.
blended_color = (1.0 - alpha_new) * old_color + alpha_new * vec4(color_final, 1.0)

# 9. Quantize and Pack
r = int(blended_color.r * 255.0)
g = int(blended_color.g * 255.0)
b = int(blended_color.b * 255.0)

output_u32 = (r << 16) | (g << 8) | b

# Write to framebuffer (RGB only, alpha discarded per [S1, unofficial])
write_framebuffer_pixel(output_u32)
```

## Subtopics

### [Oriented Ellipse Splatting](7934-oriented-ellipse-splatting.md)
Renders each Gaussian splat as an oriented ellipse in screen space, derived from its 3D rotation and 3-axis scale projected to a 2D covariance matrix, replacing the previous method of drawing round blobs sized by the largest axis. This approach improves visual fidelity by eliminating the "hazy" appearance of isotropic billboards and reduces overdraw, resulting in crisp edges and equal or better frame times. It differs from its parent [Gaussian Splat Fragment Shader](3258-gaussian-splat-fragment-shader.md) by explicitly computing the bounding quad from the covariance eigenvectors and evaluating the Gaussian kernel over the full anisotropic shape rather than a circular disc.

## Operating characteristics
- **Time Complexity:** $O(1)$ per fragment. The shader performs a fixed number of arithmetic operations per pixel.
- **Memory Complexity:** $O(1)$ per fragment. No additional memory is allocated per splat in the fragment shader.
- **Measured Performance:** Not given in the sources.
- **Scaling:** Performance scales linearly with the number of fragments covered by splats. The alpha cutoff and distance checks help cull non-contributing fragments early.
- **Strengths:** Simple to implement, efficient per-pixel evaluation, handles transparency correctly via pre-multiplied alpha blending.
- **Limitations:** The circular disc approximation (in the base method) can lead to "hazy" edges and overdraw compared to oriented ellipses [S1, unofficial]. The post-processing steps (tone mapping, sharpening) are implementation-specific and may not be suitable for all pipelines [S3, unofficial].
- **When to use:** When rendering 3D Gaussian splats as screen-space quads with a pre-sorted order buffer.
- **When not to use:** When high-fidelity anisotropic edges are required (use [Oriented Ellipse Splatting](7934-oriented-ellipse-splatting.md)).

## Background
The Gaussian Splat Fragment Shader is part of the rendering implementation for 3D Gaussian Splatting, a technique for novel view synthesis using 3D Gaussians. The method of evaluating 2D Gaussians in the fragment shader is a standard approach in GPU-based splatting. The specific implementation details, such as the use of `smoothstep` for edge smoothing and tone mapping, are derived from unofficial implementations and plugins [S1, S2, S3, unofficial]. The parent method [Gaussian Splat Rendering (Screen-Space Quad)](2075-gaussian-splat-rendering-screen-space-quad.md) builds on this by handling the sorting and projection.
