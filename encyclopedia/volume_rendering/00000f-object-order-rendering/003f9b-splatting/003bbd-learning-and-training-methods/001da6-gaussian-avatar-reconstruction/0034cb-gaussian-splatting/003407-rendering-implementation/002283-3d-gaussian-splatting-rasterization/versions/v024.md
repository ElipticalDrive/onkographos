# 3D Gaussian Splatting Rasterization

Also called: 3D Gaussian Splatting (3DGS), 3DGS Rasterization, Differentiable Gaussian Rasterization, TrimGS, gsplat.rasterization

## Overview
3D Gaussian Splatting Rasterization is a differentiable rendering technique that represents a scene as a set of anisotropic 3D Gaussians and rasterizes them to 2D images by projecting 3D covariances to 2D screen covariances, sorting by depth, and compositing colors based on alpha and transmittance [S3, S4, unofficial]. It solves the problem of real-time, photorealistic rendering of learned radiance fields by replacing triangle rasterization with Gaussian splatting, enabling gradients to flow back to Gaussian parameters (position, scale, rotation, opacity, color) and camera view matrices [S4, S5, unofficial]. It differs from its siblings by providing the core differentiable forward and backward passes for 3D Gaussians, often implemented as CUDA or MLX kernels for performance, whereas alternatives like [Perspective-Correct 3D Gaussian Splatting via Plücker Coordinates](3403-perspective-correct-3d-gaussian-splatting-via-pl-cker-coordi.md) focus on specific projection corrections or [Analytic-Splatting Forward Shading](3459-analytic-splatting-forward-shading.md) on shading models.

## How it works
**Inputs:**
*   $N$ Gaussians defined by mean position $\mu \in \mathbb{R}^3$, quaternion $q \in \mathbb{R}^4$ (for rotation), scale $s \in \mathbb{R}^3$, opacity $\alpha \in \mathbb{R}$, and spherical harmonics (SH) coefficients or direct RGB colors [S1][S2, S4, unofficial].
*   Camera parameters: view matrix $V \in \mathbb{R}^{4 \times 4}$, intrinsic matrix $K \in \mathbb{R}^{3 \times 3}$, image width $W$, height $H$ [S2, S3, unofficial].
*   Parameters: `render_mode` (e.g., "RGB", "D"), `rasterize_mode` ("classic", "antialiased"), `camera_model` ("pinhole", "ortho", "fisheye"), `tile_size` (default 16), `near_plane` (default 0.01), `far_plane` (default $10^{10}$), `sh_degree` (default 3) [S2, S4, unofficial].

**Outputs:**
*   Rendered image $C_{pixel} \in \mathbb{R}^{H \times W \times 3}$ (and optionally depth, normals, or masks) [S2, S3, unofficial].

**Data Structures:**
*   **Gaussian Attributes:** Stored in contiguous arrays or tensors.
    *   `means`: $[N, 3]$ float32.
    *   `quats`: $[N, 4]$ float32 (normalized).
    *   `scales`: $[N, 3]$ float32.
    *   `opacities`: $[N]$ float32.
    *   `colors`: $[N, 3]$ float32 (if `sh_degree` is None) or $[N, K, 3]$ where $K = (sh\_degree+1)^2$ (if SH is used) [S2, S4, unofficial].
*   **Projected Attributes (per camera):**
    *   `means_2D`: $[N, 2]$ float32.
    *   `conics`: $[N, 3]$ float32, storing the upper triangle of the inverse 2D covariance $\Sigma_{2D}^{-1}$ as $[C_{00}, C_{01}, C_{11}]$ [S2, S3, unofficial].
    *   `radii`: $[N, 2]$ int32, bounding box radius in pixels [S2, unofficial].
    *   `depths`: $[N]$ float32, camera-space Z depth [S2, unofficial].

**Steps:**

1.  **Input Validation & Setup:**
    Validate `render_mode`, `rasterize_mode`, and `camera_model`. Initialize background color $C_{bg}$ [S2, unofficial].

2.  **Covariance Construction:**
    Compute the 3D covariance matrix $\Sigma_{3D}$ from quaternions and scales:
    $$ \Sigma_{3D} = R S S^T R^T $$
    where $S = \text{diag}(s_x, s_y, s_z)$ and $R$ is the rotation matrix derived from $q$ [S2, S3, unofficial][S1].

3.  **Projection to 2D:**
    Transform means to camera space: $\mu_c = R_{view} \mu + t_{view}$.
    Compute the 2D covariance using the local affine approximation of the projective transformation:
    $$ \Sigma_{2D} = J \Sigma' J^T $$
    where $J$ is the Jacobian of the projection function and $\Sigma'$ is the transformed 3D covariance [S2, S3, unofficial].
    Compute the conic representation $C = [\Sigma_{2D}^{-1}[0,0], \Sigma_{2D}^{-1}[0,1], \Sigma_{2D}^{-1}[1,1]]$ [S2, S3, unofficial].
    Compute 2D means and radii (bounding box) for tile culling [S2, unofficial].

4.  **Tile Intersection & Sorting:**
    Divide the image into tiles of size `tile_size` $\times$ `tile_size`.
    Identify which Gaussians intersect which tiles using the 2D bounding boxes [S2, unofficial].
    Sort Gaussians by camera-space depth $z$ within each tile to ensure correct front-to-back compositing [S2, S3, S4, unofficial]. *Note: The primary bottleneck is sorting millions of Gaussians, often handled by CUB device radix sort in CUDA implementations* [S4, unofficial].

5.  **Color Evaluation:**
    If `sh_degree` is not None:
    *   Compute view directions $d = \mu_c - \text{campos}$.
    *   Normalize $d$.
    *   Evaluate Spherical Harmonics: $c(d) = \sum_{\ell=0}^{N} \sum_{m=-\ell}^{\ell} \beta_{\ell m} Y_{\ell m}(d)$ [S1][S2, unofficial].
    *   Clamp color: $c = \max(c + 0.5, 0.0)$ [S2, unofficial].
    If `sh_degree` is None, use direct RGB colors [S2, unofficial].

6.  **Alpha & Transmittance Computation:**
    For each pixel $(x,y)$ covered by a Gaussian:
    *   Compute alpha: $\alpha_{pixel} = \alpha_{gaussian} \cdot \exp(-0.5 \cdot \delta^T \Sigma_{2D}^{-1} \delta)$, where $\delta$ is the offset from the 2D mean [S2, S3, unofficial].
    *   If `rasterize_mode` is "antialiased", apply compensation factors to $\alpha_{pixel}$ [S2, unofficial].

7.  **Alpha Compositing:**
    For each pixel, iterate over sorted Gaussians $i=1 \dots N$:
    *   Compute weight: $w_i = \alpha_i \cdot T_i$, where $T_i = \prod_{j=1}^{i-1} (1 - \alpha_j)$ is the transmittance [S2, S3, unofficial].
    *   Accumulate color: $C_{pixel} = \sum w_i C_i + (1 - \sum w_i) C_{bg}$ [S2, S3, unofficial].
    *   Accumulate mask/alpha: $M_{pixel} = \sum w_i$ [S3, unofficial].

8.  **Post-Processing:**
    *   If depth is requested, compute weighted average depth: $D_{pixel} = \frac{\sum w_i z_i}{\sum w_i}$ [S2, S3, unofficial].
    *   Handle memory constraints by splitting Gaussians into mini-batches if `per_splat > 0`, accumulating results and passing `start_transmittance` between batches [S3, unofficial].

**Pseudocode:**

```python
def rasterize_gaussians(means_3d, quats, scales, opacities, colors, viewmats, Ks, width, height, 
                        tile_size=16, near_plane=0.01, far_plane=1e10, sh_degree=None, 
                        rasterize_mode="classic", backgrounds=None):
    """
    Rasterize 3D Gaussians to 2D image.
    Returns: render_colors [C, H, W, D], render_alphas [C, H, W, 1]
    """
    C = viewmats.shape[0] # Number of cameras
    N = means_3d.shape[0] # Number of Gaussians
    
    # 1. Covariance Construction
    # Compute 3D covariance from quats and scales
    cov_3d = quat_scale_to_covar_preci(quats, scales, compute_covar=True, compute_preci=False)
    
    # 2. Projection
    # Linearize projection to 2D screen space
    means_2d, cov_2d, radii, depths, conics = linearized_project(
        means_3d, cov_3d, viewmats, Ks, width, height, near_plane, far_plane
    )
    
    # 3. Tile Intersection
    # Determine which Gaussians hit which tiles
    tiles_per_gauss, isect_ids, flatten_ids = isect_tiles(
        means_2d, radii, depths, tile_size, width, height
    )
    
    # 4. Color Evaluation (if SH)
    if sh_degree is not None:
        dirs = means_3d[None, :, :] - viewmats[:,:3,3][:, None, :]
        dirs = dirs / mx.maximum(mx.linalg.norm(dirs, axis=-1, keepdims=True), 1e-8)
        colors_sh = spherical_harmonics(sh_degree, dirs, colors)
        colors_final = mx.maximum(colors_sh + 0.5, 0.0)
    else:
        colors_final = colors
        
    # 5. Broadcast Opacities
    opacities_cn = mx.broadcast_to(mx.expand_dims(opacities, axis=0), (C, N))
    # Apply antialiased compensation if needed
    # opacities_cn *= compensations
    
    # 6. Rasterize to Pixels
    # This kernel handles sorting, alpha computation, and compositing
    render_colors, render_alphas = rasterize_to_pixels(
        means_2d, conics, colors_final, opacities_cn, 
        width, height, tile_size, isect_ids, flatten_ids, backgrounds
    )
    
    return render_colors, render_alphas
```

### Temporal Marginal Probability Filtering
Pre-rasterization culling step that removes 4D Gaussians with negligible temporal support at the current frame timestamp, stabilizing rendering speed across video length [S6, unofficial]. It computes the marginal probability $p_i(t)$ for each 4D Gaussian $i$ at the current frame's timestamp $t$ and discards Gaussians with negligible $p_i(t)$ before executing standard frustum culling [S6, unofficial]. Unlike methods where Gaussian count scales with video length, this filtering keeps active Gaussians constant, making the approach friendly to long videos in terms of rendering speed [S6, unofficial].

### t-distribution truncation for splatting
A projection truncation technique that replaces the fixed three-sigma rule used in vanilla 3DGS with a $\nu$-dependent critical value interpolation to handle fat-tailed Student's t-distributions [S7]. For t-distributions with thin tails (high $\nu$), it applies the standard three-sigma rule directly. For fat-tailed distributions (low $\nu$), it obtains critical values for different $\nu$ degrees from reference [9] and interpolates between them to compute the appropriate truncation threshold [S7]. Using a fixed three-sigma threshold on fat-tailed t-distributions causes excessive truncation or leakage, which interpolation resolves [S7].

### Gaussian Opacity Fields (GOF)
Uses ray-tracing-style intersection for accurate depth and derives a level-set surface from accumulated opacity [S5, unofficial].

### Progressive Normal Propagation
Uses progressive propagation along normals to fill texture-less regions [S5, unofficial].

### Splat TBO Upload & Layout
Packs per-splat data (center, covariance, DC color/alpha, optional SH) into Texture Buffer Objects (TBOs) for GPU consumption [S8, unofficial]. It iterates over splats, copying `center.xyz` as raw float bits to `d[0..2]`, packing covariance upper-triangle to `d[3..5]` using `packHalf2x16`, and packing DC color/alpha to `d[6]` using `packDCColor` [S8, unofficial]. The base TBO uses 2 `uvec4` texels per splat (32 B): Texel 0 contains `center.xyz` and `packHalf2x16(cov00, cov01)`; Texel 1 contains `packHalf2x16(cov02, cov11)`, `packHalf2x16(cov12, cov22)`, and `packUnorm4x8(DC-baked RGBA)` [S8, unofficial]. SH TBO uses `GL_RGBA16F` format, with layout `[splat0_c1, splat0_c2, …, splat1_c1, splat1_c2, …]` [S8, unofficial]. Memory complexity is 32 B/splat for base TBO + 8 B $\times$ `sh_coeffs_per_splat_` $\times$ `splat_count_` for SH TBO, where `sh_coeffs_per_splat_` = $(active\_sh\_degree\_ + 1)^2 - 1$ [S8, unofficial].

## Operating characteristics
*   **Time Complexity:** Dominated by sorting $N$ Gaussians, typically $O(N \log N)$ or $O(N)$ with radix sort [S4, unofficial]. Rasterization itself is $O(N \cdot A)$ where $A$ is average pixels per Gaussian [S4, unofficial].
*   **Memory Complexity:** $O(N)$ for Gaussian attributes. High VRAM usage: ~4GB to view, ~12GB to train [S4, unofficial]. Large disk size: 1GB+ for a scene [S4, unofficial].
*   **Performance:** Enables real-time rendering (60+ FPS) on modern GPUs [S1][S4, unofficial].
*   **Strengths:** High visual fidelity, real-time performance, differentiable training [S4, unofficial].
*   **Limitations:** High VRAM/disk usage, static scenes (without extensions), sorting bottleneck on non-CUDA hardware [S4, unofficial]. Incompatible with existing rendering pipelines like Vulkan/DirectX without adaptation [S4, unofficial].
*   **When to use:** Real-time rendering of static or dynamic scenes from learned representations.
*   **When not to use:** When strict compatibility with existing triangle-based pipelines is required without adaptation, or when memory is severely constrained [S4, unofficial].

## Background
3D Gaussian Splatting was introduced in "3D Gaussian Splatting for Real-Time Radiance Field Rendering" [S4, unofficial]. It represents a breakthrough in static scene rendering by representing scenes as collections of 3D Gaussian primitives, enabling real-time rendering rates while maintaining high visual fidelity [S1][S4, unofficial]. The method is analogous to triangle rasterization but uses Gaussians instead of triangles [S4, unofficial]. It is typically initialized using Structure from Motion (SfM) methods like COLMAP to estimate a point cloud, which is then converted to Gaussians [S4, unofficial]. Training involves Stochastic Gradient Descent, rasterizing Gaussians, calculating loss against ground truth images, and adjusting parameters with automated densification and pruning [S4, unofficial].
