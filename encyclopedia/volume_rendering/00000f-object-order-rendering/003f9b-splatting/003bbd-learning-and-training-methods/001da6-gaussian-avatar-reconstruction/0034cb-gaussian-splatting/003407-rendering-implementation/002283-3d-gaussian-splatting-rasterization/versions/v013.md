# 3D Gaussian Splatting Rasterization

Also called: 3DGS Rasterization, Differentiable Gaussian Rasterization, TrimGS, gsplat.rasterization

## Overview
3D Gaussian Splatting Rasterization is a differentiable rendering technique that represents a scene as a set of 3D Gaussian primitives and projects them into 2D images via alpha compositing [S2, S3, unofficial]. It solves the problem of real-time, photorealistic rendering of learned radiance fields by replacing triangle rasterization with Gaussian splatting, enabling gradient-based optimization of scene parameters [S2, S3, unofficial]. It differs from its siblings, such as [3D Gaussian Splatting Rendering (CPU-Sorted, Instanced)](2058-3d-gaussian-splatting-rendering-cpu-sorted-instanced.md) and [3D Gaussian Splatting Rendering (Software)](2805-3d-gaussian-splatting-rendering-software.md), by providing the specific GPU-accelerated, differentiable forward and backward passes required for training, whereas the siblings focus on non-differentiable or CPU-based inference [S4, S5, unofficial].

## How it works
**Inputs:**
*   `means_3D`: $[N, 3]$ tensor of 3D Gaussian centers.
*   `quats`: $[N, 4]$ tensor of unit quaternions $(w, x, y, z)$ representing rotation.
*   `scales`: $[N, 3]$ tensor of Gaussian scales.
*   `opacities`: $[N]$ tensor of per-Gaussian opacity values.
*   `colors`: $[N, D]$ tensor of direct RGB colors or spherical harmonic coefficients.
*   `viewmats`: $[C, 4, 4]$ camera-to-world transformation matrices.
*   `Ks`: $[C, 3, 3]$ camera intrinsic matrices.
*   `width`, `height`: Image dimensions in pixels.
*   `tile_size`: Integer, default 16. Side length of tiles for rasterization [S1, unofficial].
*   `near_plane`, `far_plane`: Floats, default 0.01 and $10^{10}$, defining clipping planes [S1, unofficial].
*   `sh_degree`: Integer or None. If not None, enables spherical harmonics color computation; otherwise uses direct color mode [S1, unofficial].
*   `render_mode`: String specifying output channels. Valid values: "RGB", "D", "ED", "RGB+D", "RGB+ED", "d", "Ed", "RGB+d", "RGB+Ed" [S1, unofficial].
*   `rasterize_mode`: String specifying rendering style. Valid values: "classic", "antialiased" [S1, unofficial].
*   `camera_model`: String specifying camera projection. Valid values: "pinhole", "ortho", "fisheye" [S1, unofficial].
*   `backgrounds`: $[C, 3]$ tensor of background colors.

**Outputs:**
*   `render_colors`: $[C, H, W, D]$ tensor of rendered colors.
*   `render_alphas`: $[C, H, W, 1]$ tensor of accumulated alpha values.

**Data Structures:**
*   **Conic Representation**: The inverse 2D covariance $\Sigma_{2D}^{-1}$ is stored as a vector of 3 floats containing the upper triangle elements: $[\Sigma_{2D}^{-1}[0,0], \Sigma_{2D}^{-1}[0,1], \Sigma_{2D}^{-1}[1,1]]$ [S1, unofficial].
*   **Intersection Offsets**: Encoded indices mapping Gaussians to tiles for efficient rasterization [S1, unofficial].

**Steps:**

1.  **Input Validation**: Check `render_mode`, `rasterize_mode`, and `camera_model` against valid sets [S1, unofficial].
2.  **3D Covariance Computation**: Compute the 3D covariance matrix $\Sigma_{3D}$ from `quats` and `scales`. This is typically done via `quat_scale_to_covar_preci` with `compute_covar=True`, `compute_preci=False`, `triu=False`, resulting in shape $[N, 3, 3]$ [S1, S2, unofficial].
3.  **2D Projection**: Project 3D means and covariances to 2D screen space using camera intrinsics/extrinsics and image size. This involves:
    *   Transforming 3D means to camera space.
    *   Computing the Jacobian $J$ of the projective transformation at the camera-space mean [S2, unofficial].
    *   Computing $\Sigma_{2D} = J \Sigma' J^T$ [S2, unofficial].
    *   Computing the conic representation from $\Sigma_{2D}^{-1}$ [S1, S2, unofficial].
    *   Calculating the bounding box radius using the 3-sigma rule: $\text{bboxsize\_cam} = [3.0 \sqrt{\Sigma_{2D}[0,0]}, 3.0 \sqrt{\Sigma_{2D}[1,1]}]$ [S1, S2, unofficial].
    *   Outputs: `radii` $[C, N, 2]$, `means_2D` $[C, N, 2]$, `depths` $[C, N]$, `conics` $[C, N, 3]$ [S1, unofficial].
4.  **Spherical Harmonics Evaluation** (if `sh_degree` is not None):
    *   Compute view directions `dirs` from camera center to `means_3D`.
    *   Normalize `dirs`.
    *   Broadcast color coefficients to $[C, N, K, 3]$.
    *   Evaluate spherical harmonics to get RGB colors $[C, N, 3]$.
    *   Clamp colors with `mx.maximum(rgb + 0.5, 0.0)` [S1, unofficial].
5.  **Opacity and Compensation**:
    *   Broadcast scalar `opacities` $[N]$ to $[C, N]$ [S1, unofficial].
    *   If `rasterize_mode` is "antialiased", multiply opacities by precomputed compensations [S1, unofficial].
6.  **Tile Intersection**:
    *   Compute tile dimensions: `tile_width` = ceil(`width` / `tile_size`), `tile_height` = ceil(`height` / `tile_size`) [S1, unofficial].
    *   Call `isect_tiles` with `means_2D`, `radii`, `depths`, `tile_size`, `tile_width`, `tile_height`, and `sort=True` to get `tiles_per_gauss`, `isect_ids`, and `flatten_ids` [S1, unofficial].
7.  **Offset Encoding**: Encode `isect_ids` using `isect_offset_encode` to get `isect_offsets` $[C, \text{tile\_height}, \text{tile\_width}]$ [S1, unofficial].
8.  **Rasterization**:
    *   Call `rasterize_to_pixels` (or `rasterize_to_pixels_mlx` for differentiable mode) with `means_2D`, `conics`, `colors_for_raster`, `opacities_cn`, `width`, `height`, `tile_size`, `isect_offsets`, `flatten_ids`, and `backgrounds` [S1, unofficial].
    *   For each pixel in each tile:
        *   Iterate over Gaussians intersecting the tile, sorted by depth.
        *   Compute alpha: $\alpha_i = \text{opacity}_i \cdot \exp(-0.5 \cdot (\mathbf{x} - \boldsymbol{\mu})^T \Sigma_{2D}^{-1} (\mathbf{x} - \boldsymbol{\mu}))$ [S1, S2, unofficial].
        *   Compute weight: $w_i = \alpha_i \cdot T_i$, where $T_i = \prod_{j=1}^{i-1} (1 - \alpha_j)$ is the transmittance [S1, S2, unofficial].
        *   Accumulate color: $C_{pixel} += w_i \cdot \text{color}_i$ [S1, S2, unofficial].
        *   Update transmittance: $T_{i+1} = T_i \cdot (1 - \alpha_i)$ [S1, S2, unofficial].
    *   Composite background: $C_{final} = C_{pixel} + (1 - \sum w_i) \cdot \text{background}$ [S1, S2, unofficial].
9.  **Post-Processing**:
    *   If `render_mode` includes depth ("D", "ED", "d", "Ed"):
        *   Compute expected depth by normalizing accumulated depth/hit-distance by alpha: $\text{depth\_channel} = \text{depth\_channel} / \max(\text{render\_alphas}, 10^{-10})$ [S1, unofficial].
        *   Concatenate normalized depth to color channels if `has_color`, or replace `render_colors` if not [S1, unofficial].
    *   Return `render_colors` and `render_alphas` [S1, unofficial].

**Pseudocode:**

```python
def rasterize_3d_gaussians(
    means_3d: mx.array,      # [N, 3]
    quats: mx.array,         # [N, 4]
    scales: mx.array,        # [N, 3]
    opacities: mx.array,     # [N]
    colors: mx.array,        # [N, D] or [N, K, 3] if SH
    viewmats: mx.array,      # [C, 4, 4]
    Ks: mx.array,            # [C, 3, 3]
    width: int,
    height: int,
    tile_size: int = 16,
    sh_degree: int = None,
    render_mode: str = "RGB",
    backgrounds: mx.array = None
) -> tuple:
    """
    Rasterize 3D Gaussians to 2D images.
    Returns (render_colors, render_alphas).
    """
    C = viewmats.shape[0]
    N = means_3d.shape[0]
    
    # 1. Compute 3D Covariance
    cov_3d = quat_scale_to_covar(quats, scales)  # [N, 3, 3]
    
    # 2. Project to 2D
    # Linearized projection using camera intrinsics/extrinsics
    means_2d, cov_2d, depths, radii, conics = linearized_project(
        means_3d, cov_3d, viewmats, Ks, width, height
    )
    # means_2d: [C, N, 2], cov_2d: [C, N, 2, 2], depths: [C, N]
    # radii: [C, N, 2], conics: [C, N, 3]
    
    # 3. Compute Colors (SH or Direct)
    if sh_degree is not None:
        # Compute view directions
        campos = viewmats[:, :3, 3]  # [C, 3]
        dirs = means_3d[None, :, :] - campos[:, None, :]  # [C, N, 3]
        dirs_norm = mx.sqrt(mx.sum(dirs * dirs, axis=-1, keepdims=True))
        dirs = dirs / mx.maximum(dirs_norm, 1e-8)
        # Evaluate SH
        coeffs = colors  # [N, K, 3]
        coeffs_broadcast = mx.broadcast_to(coeffs, (C, N, coeffs.shape[1], 3))
        rgb = spherical_harmonics(sh_degree, dirs, coeffs_broadcast)  # [C, N, 3]
        rgb = mx.maximum(rgb + 0.5, 0.0)
        colors_for_raster = rgb
    else:
        # Direct color
        colors_for_raster = mx.broadcast_to(colors[None, :, :], (C, N, colors.shape[-1]))
        
    # 4. Broadcast Opacities
    opacities_cn = mx.broadcast_to(mx.expand_dims(opacities, axis=0), (C, N))
    
    # 5. Tile Intersection
    tile_width = mx.ceil(width / tile_size).astype(mx.int32)
    tile_height = mx.ceil(height / tile_size).astype(mx.int32)
    
    # isect_tiles returns indices for Gaussians intersecting each tile
    tiles_per_gauss, isect_ids, flatten_ids = isect_tiles(
        means_2d, radii, depths, tile_size, tile_width, tile_height, sort=True
    )
    
    # 6. Encode Offsets
    isect_offsets = isect_offset_encode(isect_ids, C, tile_width, tile_height)
    
    # 7. Rasterize
    # rasterize_to_pixels handles the inner loop: alpha computation, sorting, blending
    render_colors, render_alphas = rasterize_to_pixels(
        means_2d, conics, colors_for_raster, opacities_cn,
        width, height, tile_size, isect_offsets, flatten_ids,
        backgrounds
    )
    
    # 8. Post-Processing (Depth)
    if "D" in render_mode or "d" in render_mode:
        # Compute expected depth
        # Note: rasterize_to_pixels must also return accumulated depth if requested
        # Assuming it returns depth_channel if configured
        depth_channel = render_colors[..., -1] if render_colors.shape[-1] > 3 else None
        if depth_channel is not None:
            expected_depth = depth_channel / mx.maximum(render_alphas, 1e-10)
            # Replace or concatenate as needed based on render_mode
            pass
            
    return render_colors, render_alphas
```

## Subtopics

### [3D Gaussian Splatting Differentiable Rasterizer](2813-3d-gaussian-splatting-differentiable-rasterizer.md)
The core rendering engine that projects 3D Gaussians into 2D and composites colors, enabling gradient-based optimization. It differs from siblings by providing specific differentiable forward and backward passes required for training.

### [Perspective-Correct 3D Gaussian Splatting via Plücker Coordinates](3403-perspective-correct-3d-gaussian-splatting-via-pl-cker-coordi.md)
Computes Gaussian values using Plücker coordinates to represent rays, avoiding matrix inversion. It sets itself apart by providing a closed-form, numerically stable solution for perspective-correct splat evaluation.

### [Analytic-Splatting Forward Shading](3459-analytic-splatting-forward-shading.md)
Analytically integrates the Gaussian PDF over the pixel area to solve aliasing artifacts. It differs from vanilla 3DGS by providing anti-aliased results and from Mip-Splatting by using a different analytical approximation.

### [Speedy-Splat Rendering Pipeline](3543-speedy-splat-rendering-pipeline.md)
Replaces coarse bounding-box tile intersection with precise Gaussian-tile intersection checks and sorting-based depth ordering. It addresses inefficiency by generating a sparse set of Gaussian-tile pairs.

### [Ghost Ellipsoids for Chunked Training](3559-ghost-ellipsoids-for-chunked-training.md)
Resolves boundary artifacts in chunked volume training by including ellipsoids from neighboring chunks in loss computation without updating parameters. It differs from chunk-based methods by requiring boundary support during training itself.

### [Ref-Gaussian Deferred Surfel Rendering with Split-Sum IBL](4464-ref-gaussian-deferred-surfel-rendering-with-split-sum-ibl.md)
A real-time deferred shading method for relighting 3DGS on mobile hardware. It solves dynamic environment lighting by decomposing splats into PBR materials and computing lighting via a deferred pipeline.

### [3D Gaussian Splatting Self-Shadowing (T_light)](4487-3d-gaussian-splatting-self-shadowing-t-light.md)
Calculates self-shadowing transmittance $T_{light}$ for each Gaussian along a directional sun direction. It differs from standard alpha blending by tracking accumulated occlusion from the light source's perspective.

### [Light Space Rasterization for T_light](4489-light-space-rasterization-for-t-light.md)
Computes $T_{light}$ for each 3D Gaussian along a directional sun direction. It differs from voxel-based fallbacks by providing full continuous gradients and zero parameter expansion.

### [2D Gaussian Splatting Rasterization](4815-2d-gaussian-splatting-rasterization.md)
Renders 3D Gaussian surfels as planar disks with explicit normal vectors, enabling normal map accumulation. It differs from 3DGS by using ray-surfel intersection logic.

### [Hardware-Accelerated Gaussian Rasterization](7329-hardware-accelerated-gaussian-rasterization.md)
Augments standard triangle rasterizers with dedicated units for Gaussian projection and blending. It solves the bottleneck of processing millions of Gaussians on general-purpose hardware.

### [AdR-Gaussian](8365-adr-gaussian.md)
Optimizes the rasterization pipeline by moving serial culling operations to a parallel preprocessing stage. It achieves speedups without reducing the total number of Gaussians.

### [3D Half-Gaussian Splatting](9011-3d-half-gaussian-splatting.md)
Replaces the standard isotropic Gaussian with a half-space truncated Gaussian to resolve shape and color discontinuities at object boundaries. It distinguishes itself from 2D-GS by retaining volumetric rendering.

### [QuadBox](9231-quadbox.md)
Uses four axis-aligned bounding boxes (AABBs) to tightly encapsulate projected 2D Gaussians, reducing tile over-approximation. It sets itself apart from standard 3DGS by replacing the conservative single AABB with a geometry-aware QuadBox.

### [Transparency and Blending Models](9274-transparency-and-blending-models.md)
Defines how 3D Gaussian primitives are composited, addressing order-dependent alpha blending. It provides alternatives that correct depth ordering, replace projection with analytic ray-space integration, or eliminate sorting via OIT.

### [Projection Geometry and Coordinate Systems](9313-projection-geometry-and-coordinate-systems.md)
Defines coordinate transformations and projection mappings for 3D Gaussian primitives. It differs from standard perspective projection by supporting alternative camera models and specialized geometries.

### [RoofGS Quadratic Form Expansion and Coefficient Folding](10258-roofgs-quadratic-form-expansion-and-coefficient-folding.md)
Expands the Gaussian quadratic form to separate pixel-dependent terms from Gaussian-dependent terms, reducing instruction overhead. It sets itself apart by pre-computing and folding opacity and scaling factors into quadratic coefficients.

### Temporal Marginal Probability Filtering
Pre-rasterization culling step that removes 4D Gaussians with negligible temporal support at the current frame timestamp, stabilizing rendering speed across video length. It computes the marginal probability $p_i(t)$ for each 4D Gaussian $i$ at the current frame's timestamp $t$ and discards Gaussians with negligible $p_i(t)$ before executing standard frustum culling. Unlike methods where Gaussian count scales with video length, this filtering keeps active Gaussians constant, making the approach friendly to long videos in terms of rendering speed [S5, unofficial].

### t-distribution truncation for splatting
A projection truncation technique that replaces the fixed three-sigma rule used in vanilla 3DGS with a $\nu$-dependent critical value interpolation to handle fat-tailed Student's t-distributions. For t-distributions with thin tails (high $\nu$), it applies the standard three-sigma rule directly. For fat-tailed distributions (low $\nu$), it obtains critical values for different $\nu$ degrees from reference [9] and interpolates between them to compute the appropriate truncation threshold. Using a fixed three-sigma threshold on fat-tailed t-distributions causes excessive truncation or leakage, which interpolation resolves [S6].

### Gaussian Opacity Fields (GOF)
Uses ray-tracing-style intersection for accurate depth and derives a level-set surface from accumulated opacity [S4, unofficial].

### Progressive Normal Propagation
Uses progressive propagation along normals to fill texture-less regions [S4, unofficial].

### Gaussian Surfels
Uses zero-thickness oriented surfels [S4, unofficial].

## Operating characteristics
*   **Time Complexity**: Dominated by sorting millions of Gaussians, which is efficiently handled by CUB device radix sort in CUDA implementations [S3, unofficial]. Tile-based rasterization reduces the number of pixels processed per Gaussian [S1, unofficial].
*   **Memory Complexity**: High VRAM usage, typically 4GB to view and 12GB to train [S3, unofficial]. Large disk size, often 1GB+ for a scene [S3, unofficial].
*   **Performance**: Real-time rendering of photorealistic scenes is achievable [S3, unofficial]. The primary bottleneck is sorting, which is highly optimized in CUDA but may be less efficient in other pipelines [S3, unofficial].
*   **Strengths**: High-quality, photorealistic scenes; fast, real-time rasterization; relatively fast to train [S3, unofficial].
*   **Limitations**: High VRAM and disk usage; incompatible with existing rendering pipelines (Vulkan, DirectX, WebGPU) without adaptation; static representation (for now) [S3, unofficial].
*   **When to Use**: When real-time, high-quality rendering of learned scenes is required, and GPU resources are sufficient.
*   **When Not to Use**: When memory is constrained, or when integration with existing production rendering pipelines is required without significant adaptation [S3, unofficial].

## Background
3D Gaussian Splatting was introduced in the paper "3D Gaussian Splatting for Real-Time Radiance Field Rendering" [S3, unofficial]. It is a rasterization technique that allows real-time rendering of photorealistic scenes learned from small samples of images, analogous to triangle rasterization but using Gaussians instead of triangles [S3, unofficial]. The method was developed to address the limitations of NeRFs, which are slow to render, by providing a differentiable, GPU-accelerated rasterization pipeline [S3, unofficial]. It has since inspired numerous variants and adaptations, including differentiable rasterizers, hardware acceleration, and dynamic scene representations [S4, S5, unofficial][S6].
