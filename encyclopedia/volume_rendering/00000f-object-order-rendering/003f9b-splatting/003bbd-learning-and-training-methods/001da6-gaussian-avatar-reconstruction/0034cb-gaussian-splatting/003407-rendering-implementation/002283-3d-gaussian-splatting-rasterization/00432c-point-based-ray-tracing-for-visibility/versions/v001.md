# Point-Based Ray Tracing for Visibility

Also called: VisibilitySplat Ray Tracing

## Overview
Point-Based Ray Tracing for Visibility serves as a sparse visibility oracle that evaluates transmittance along sampled light directions using a bounding volume hierarchy (BVH) of Gaussian proxies, enabling evaluation from any point in space in any direction [S1]. Unlike the camera-tied rasterizer, it decouples visibility estimation from screen-space projection, allowing it to act as a drop-in companion to standard 3D Gaussian Splatting (3DGS) by reusing the same EWA-splatting formulation for consistent blending without requiring training mismatch [S1].

## How it works
**Inputs and Outputs**
*   **Input:** A set of 3D Gaussians (position, covariance, opacity $\alpha$, color); a ray $r(t) = o + td$; an early-out threshold $T_{stop}$; a minimum response threshold $\epsilon$.
*   **Output:** The accumulated transmittance $T$ along the ray.

**Data Structures**
*   **Gaussian Proxy:** For each Gaussian, a proxy mesh (e.g., a subdivided regular icosahedron) is constructed. The triangles of this proxy are inserted into a BVH for fast ray-triangle traversal [S1].
*   **Proxy Scale:** The proxy is scaled to tightly bound the region where the particle’s response exceeds $\epsilon$. The scale explicitly incorporates the particle’s opacity $\alpha$ to apply "adaptive clamping," ensuring nearly transparent splats receive proportionally tighter bounds to reduce false-positive hits during traversal [S1].

**Algorithm Steps**
1.  **Ray Query:** For a given ray $r(t) = o + td$, query the BVH to gather the batch of intersected Gaussian proxies.
2.  **Virtual Camera Setup:** To reuse the unmodified rasterizer for consistent blending, instantiate a one-pixel virtual camera at the ray origin $o$ with the optical axis aligned to the ray direction $d$ [S1].
3.  **Splatting Evaluation:** Splat exactly the Gaussians reported by the BVH for that ray into the center pixel of this virtual camera using the standard EWA-splatting formulation [S1]. This computes the per-hit attenuation $\Delta a_i$ from the Gaussian’s line integral along the ray segment covered by the proxy [S1].
4.  **Transmittance Update:** Update the accumulated transmittance $T$ using the formula:
    $$ T \leftarrow T \cdot (1 - \Delta a_i) $$
    where $\Delta a_i$ is the attenuation of the $i$-th hit [S1].
5.  **Ordering:** For occlusion-only queries, hits do not need to be depth-sorted because multiplication commutes; they can be processed in arbitrary order while maintaining correctness for $T$ [S1].
6.  **Early Termination:** If $T \le T_{stop}$, terminate the traversal and return $T$ [S1].

**Parameters**
*   **$T_{stop}$:** The early-out threshold for transmittance. It should match the early-out used by the rasterizer to keep consistency between visibility estimated by ray tracing and the screen-space renderer [S1].
*   **$\epsilon$:** A small minimum response threshold used to define the tight bounding region for the proxy [S1].

    Returns:
        float: Accumulated transmittance T.
    """
    T = 1.0
    
    # 1. Query BVH for intersected proxies
    # The BVH contains proxies scaled by opacity (adaptive clamping)
    intersected_proxies = bvh.query(ray_origin, ray_direction)
    
    # 2. Setup virtual camera frame
    # Local camera frame aligned with ray direction
    # This allows reusing the standard EWA-splatting logic
    cam_frame = create_local_camera_frame(ray_origin, ray_direction)
    
    # 3. Process intersections
    # No depth sorting required for transmittance accumulation
    for proxy in intersected_proxies:
        # Find the corresponding Gaussian
        gaussian = proxy.parent_gaussian
        
        # 4. Evaluate attenuation using EWA-splatting via virtual camera
        # Splat the Gaussian into the center pixel of the 1-pixel virtual camera
        # This computes the line integral along the ray segment covered by the proxy
        delta_a = splat_gaussian_to_pixel(gaussian, cam_frame)
        
        # 5. Update transmittance
        T = T * (1.0 - delta_a)
        
        # 6. Early termination
        if T <= t_stop:
            break
            
    return T

## Operating characteristics
*   **Time Complexity:** Depends on BVH traversal depth and the number of intersected proxies per ray. Early termination reduces average cost when transmittance drops below $T_{stop}$.
*   **Memory Complexity:** Requires storing the BVH of Gaussian proxies. The proxy scale incorporates opacity, which may increase memory slightly compared to minimal bounding spheres but reduces false positives.
*   **Strengths:** Decouples visibility from camera projection; allows reuse of pretrained 3DGS point clouds and the existing rasterizer without training mismatch; consistent blending with the screen-space renderer.
*   **Limitations:** Not a full renderer; serves only as a visibility oracle. Requires careful tuning of $T_{stop}$ to match the rasterizer's early-out behavior.
*   **When to use:** When evaluating transmittance along arbitrary light directions for relighting or shadowing in 3DGS scenes.
*   **When not to use:** For primary view synthesis where the tile-based rasterizer is more efficient.

## Background
The method was introduced in "VisibilitySplat: Ray-Traced Occlusion for Relighting with 3D Gaussian Splatting" [S1]. It addresses the limitation of the standard 3DGS rasterizer, which is tied to camera projection and ordered blending per tile, by providing a point-based ray tracer that evaluates Gaussian splatting from any point in space in any direction [S1]. It contrasts with alternative ray-based renderers like 3DGRT (which evaluates at max response and uses a k-buffer) and IRGS (which collapses to 2D disks) by strictly adhering to the EWA-splatting formulation [S1].
