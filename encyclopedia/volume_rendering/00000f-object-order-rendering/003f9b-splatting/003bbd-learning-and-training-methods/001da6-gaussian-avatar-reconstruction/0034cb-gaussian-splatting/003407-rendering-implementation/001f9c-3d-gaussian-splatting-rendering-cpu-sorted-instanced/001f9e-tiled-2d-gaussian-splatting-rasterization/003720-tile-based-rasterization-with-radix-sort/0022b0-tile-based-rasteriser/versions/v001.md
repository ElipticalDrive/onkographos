# Tile-based Rasteriser

Also called: 3DGS GPU Rasterization, Radix Sort Binning, Tile-Based Rasterization, Tile-based Rasterization with Radix Sort, Tile-based Rasterizer, Tile-based sorting rasterizer

## Overview
The Tile-based Rasteriser is the GPU-optimized sorting and compositing component of the 3D Gaussian Splatting pipeline that assigns projected 2D Gaussian splats to image tiles and sorts them by depth using a single global radix sort [S1, S2, unofficial]. It solves the performance bottleneck of per-pixel depth sorting for millions of splats by grouping work into tiles, enabling real-time rendering and efficient backpropagation [S1, S2, unofficial]. Unlike non-tiled approaches that sort per pixel or per tile independently, it uses a unified 64-bit key to bin and sort all (splat, tile) pairs in one pass [S2, unofficial].

## How it works
**Inputs:**
- List of $N$ projected 2D Gaussian splats, each defined by center $(x_i, y_i)$, 2D covariance matrix $\Sigma'_i$, color $c_i$, opacity $\alpha_i$, and depth $Z_c$ [S1, S2, unofficial].
- Image resolution $(W, H)$ and tile dimensions $T_w \times T_h$ (typically $16 \times 16$ pixels) [S1, S2, unofficial].

**Outputs:**
- A sorted list of (splat, tile) pairs, ordered by tile ID and then by depth $Z_c$ within each tile [S1, S2, unofficial].
- The final rendered image and gradients for training [S1, unofficial].

**Data Structures:**
- **Splat List:** Array of $N$ splats. Each splat contains fields: `x`, `y`, `sigma_xx`, `sigma_xy`, `sigma_yy` (for $\Sigma'$), `color`, `opacity`, `Zc` [S1, S2, unofficial].
- **Tile Grid:** Implicit grid of tiles covering the image. Tile ID $t$ for a pixel $(x, y)$ is calculated as $t = \lfloor y / T_h \rfloor \times \lceil W / T_w \rceil + \lfloor x / T_w \rfloor$ [S2, unofficial].
- **Sort Key:** A 64-bit integer key for each (splat, tile) pair. The high bits contain the tile ID, and the low bits contain the depth $Z_c$ [S2, unofficial].
- **Sorted Pairs:** Array of indices or pointers into the Splat List, ordered by the Sort Key [S2, unofficial].

**Steps:**
1. **Tile Assignment:** For each splat $i$, calculate its 2D axis-aligned bounding box (AABB) based on its covariance $\Sigma'_i$ and a cutoff threshold (e.g., $3\sigma$) [S2, unofficial]. Identify all tiles that overlap with this AABB [S2, unofficial].
2. **Pair Generation:** For each overlapping tile $t$, create a (splat, tile) pair. If a splat straddles multiple tiles, it is duplicated into each relevant tile's pair list [S1, S2, unofficial].
3. **Key Packing:** For each (splat, tile) pair, pack the tile ID $t$ into the high bits and the splat's depth $Z_c$ into the low bits of a 64-bit integer key $K$ [S2, unofficial]. The exact bit allocation depends on the maximum tile ID and depth range, but the principle is $K = (t \ll \text{depth\_bits}) | Z_c$ [S2, unofficial].
4. **Global Radix Sort:** Perform a single GPU radix sort on all generated (splat, tile) pairs using the 64-bit keys [S1, S2, unofficial]. This sort simultaneously bins splats by tile ID (making them contiguous) and sorts them by depth within each tile [S2, unofficial].
5. **Tile Processing:** For each tile $t$, a GPU thread block processes the contiguous segment of sorted pairs belonging to that tile [S1, S2, unofficial].
6. **Compositing:** For each pixel in the tile, iterate through the sorted splats for that tile. Perform front-to-back alpha compositing using the splat's color and alpha at the pixel location [S2, unofficial]. The compositing loop is:
   $$
   C_{out} = \sum_{i \in \text{sorted}} c_i \alpha_i T_i, \quad T_{out} = \prod_{i \in \text{sorted}} (1 - \alpha_i)
   $$
   where $T_i = \prod_{j < i} (1 - \alpha_j)$ is the transmittance before splat $i$ [S2, unofficial].
7. **Early Termination:** Stop compositing for a pixel when the accumulated transmittance $T$ drops below a small threshold $\epsilon$ (e.g., $1/255$) [S2, unofficial].
8. **Backpropagation:** Reuse the same sorted list of (splat, tile) pairs to compute gradients for position, shape, opacity, and color during training, avoiding additional sorting [S1, unofficial].

**Pseudocode:**
```python
def tile_based_rasterization(splats, image_width, image_height, tile_width=16, tile_height=16):
    """
    Performs tile-based rasterization for 3D Gaussian Splatting.
    
    Args:
        splats: List of dicts with keys 'x', 'y', 'sigma_xx', 'sigma_xy', 'sigma_yy', 
                'color', 'opacity', 'Zc'.
        image_width: Width of the image in pixels.
        image_height: Height of the image in pixels.
        tile_width: Width of each tile in pixels.
        tile_height: Height of each tile in pixels.
        
    Returns:
        image: Rendered image array of shape (image_height, image_width, 3).
        gradients: Gradients for splat parameters (simplified for this example).
    """
    num_tiles_x = (image_width + tile_width - 1) // tile_width
    num_tiles_y = (image_height + tile_height - 1) // tile_height
    num_tiles = num_tiles_x * num_tiles_y
    
    # Step 1 & 2: Tile Assignment and Pair Generation
    pairs = []  # List of (splat_index, tile_id, depth)
    
    for i, splat in enumerate(splats):
        # Calculate 2D AABB for the splat
        # This involves projecting the Gaussian covariance to 2D and finding the bounding box
        # For simplicity, assume we have a function to get the tile range
        tile_min_x, tile_max_x, tile_min_y, tile_max_y = get_splat_tile_range(splat, tile_width, tile_height)
        
        for ty in range(tile_min_y, tile_max_y + 1):
            for tx in range(tile_min_x, tile_max_x + 1):
                tile_id = ty * num_tiles_x + tx
                pairs.append((i, tile_id, splat['Zc']))
    
    # Step 3 & 4: Key Packing and Global Radix Sort
    # Pack tile_id into high bits and depth into low bits
    # Assuming 32 bits for tile_id and 32 bits for depth (simplified)
    # In practice, bit widths depend on max tile_id and depth range
    keys = []
    for i, tile_id, depth in pairs:
        key = (tile_id << 32) | depth
        keys.append(key)
    
    # Perform radix sort on keys
    # This sorts pairs by tile_id, then by depth within each tile
    sorted_indices = radix_sort(keys)
    
    # Reorder pairs based on sorted indices
    sorted_pairs = [pairs[i] for i in sorted_indices]
    
    # Step 5 & 6: Tile Processing and Compositing
    image = np.zeros((image_height, image_width, 3))
    
    # Group sorted pairs by tile
    tile_groups = {}
    for i, tile_id, depth in sorted_pairs:
        if tile_id not in tile_groups:
            tile_groups[tile_id] = []
        tile_groups[tile_id].append((i, depth))
    
    for tile_id, tile_pairs in tile_groups.items():
        # Determine tile coordinates
        ty = tile_id // num_tiles_x
        tx = tile_id % num_tiles_x
        
        tile_x_start = tx * tile_width
        tile_y_start = ty * tile_height
        tile_x_end = min((tx + 1) * tile_width, image_width)
        tile_y_end = min((ty + 1) * tile_height, image_height)
        
        # Step 7: Compositing with Early Termination
        for y in range(tile_y_start, tile_y_end):
            for x in range(tile_x_start, tile_x_end):
                transmittance = 1.0
                color = np.zeros(3)
                
                for splat_idx, depth in tile_pairs:
                    splat = splats[splat_idx]
                    
                    # Calculate alpha for this pixel
                    alpha = calculate_gaussian_alpha(splat, x, y)
                    
                    if alpha > 0:
                        color += splat['color'] * alpha * transmittance
                        transmittance *= (1 - alpha)
                    
                    if transmittance < 1e-3:  # Early termination threshold
                        break
                
                image[y, x] = color
    
    return image, gradients
```

**Parameters:**
- Tile size: $16 \times 16$ pixels [S1, S2, unofficial].
- Early termination threshold: Not given in the sources.

**Edge Cases and Pitfalls:**
- Sorting per pixel is too slow for millions of splats; tile-based sorting with a single global radix sort is required for real-time performance [S1, unofficial].
- A splat straddling tile boundaries must be duplicated into each relevant tile [S1, S2, unofficial].
- Precision issues in depth sorting may affect compositing order; ensure depth values are packed correctly into the sort key [S2, unofficial].

## Operating characteristics
- **Time Complexity:** One O(n) radix sort over all (splat, tile) pairs, where n is the number of (splat, tile) pairs [S2, unofficial]. This replaces thousands of per-tile sorts [S2, unofficial].
- **Memory Complexity:** O(n) for storing the (splat, tile) pairs and sorted indices [S2, unofficial].
- **Measured Performance:** On the Mip-NeRF360 benchmark, the method reaches 27.21 dB PSNR and 0.214 LPIPS at 134 fps, rendering roughly three orders of magnitude faster than previous quality leaders [S1, unofficial].
- **Scaling:** The method scales well with the number of splats due to the single global sort [S1, S2, unofficial].
- **Strengths:** Real-time performance, efficient use of GPU parallelism, shared sorting for rendering and training [S1, S2, unofficial].
- **Limitations:** Memory overhead for duplicating splats across tiles [S1, S2, unofficial].
- **When to Use:** Real-time rendering and training of 3D Gaussian Splatting [S1, unofficial].
- **When Not to Use:** Scenes with very few splats where the overhead of tile management outweighs the benefits [S2, unofficial].

## Background
The Tile-based Rasteriser was introduced as part of the 3D Gaussian Splatting pipeline by Kerbl et al. in 2023 [S1, unofficial]. It was designed to address the performance bottleneck of sorting millions of splats for real-time rendering and training [S1, unofficial]. The method leverages GPU-optimized radix sorting to achieve efficient per-tile depth ordering [S2, unofficial]. It is used in the 3D Gaussian Splatting rendering pipeline for novel-view synthesis [S1, unofficial].
