# 3D Gaussian Splatting Rasterization

Also called: 3DGS Rasterization, Differentiable Gaussian Rasterization, TrimGS, gsplat.rasterization

## Overview
3D Gaussian Splatting Rasterization is a differentiable rendering technique that represents a scene as a set of 3D Gaussians and rasterizes them to 2D images by projecting 3D covariances to 2D screen covariances, sorting by depth, and compositing colors based on alpha and transmittance [S2, S3, unofficial]. It serves as the core rendering engine for training and inference in 3D Gaussian Splatting, enabling gradient-based optimization of Gaussian parameters (position, covariance, opacity, color) and camera poses [S4, unofficial][S5]. Unlike traditional triangle rasterization, it draws ellipsoids directly, and unlike NeRF, it avoids extensive ray sampling by using a tile-based, front-to-back alpha compositing approach [S3, unofficial]. It differs from its siblings by providing the specific differentiable forward and backward passes required for training; for instance, [Optimal Gaussian Splatting](3293-optimal-gaussian-splatting.md) focuses on sampling efficiency, while [Hybrid Transparency](3294-hybrid-transparency.md) modifies the blending model, and [Perspective-Correct 3D Gaussian Splatting via Plücker Coordinates](3403-perspective-correct-3d-gaussian-splatting-via-pl-cker-coordi.md) alters the projection geometry.

## How it works
**Inputs:**
*   `means_3D`: $[N, 3]$ tensor of 3D Gaussian centers.
*   `quats`: $[N, 4]$ tensor of unit quaternions $(w, x, y, z)$ representing rotation.
*   `scales`: $[N, 3]$ tensor of Gaussian scales (log-scale or linear, depending on activation).
*   `opacities`: $[N]$ tensor of scalar opacity values.
*   `colors`: $[N, D]$ tensor of color coefficients (RGB or Spherical Harmonics coefficients).
*   `viewmats`: $[C, 4, 4]$ camera-to-world transformation matrices for $C$ cameras.
*   `Ks`: $[C, 3, 3]$ camera intrinsic matrices.
*   `width`, `height`: Image dimensions in pixels.
*   `tile_size`: Integer, default 16. Side length of tiles for rasterization [S1, unofficial].
*   `near_plane`, `far_plane`: Floats, default 0.01 and $10^{10}$, defining clipping planes [S1, unofficial].
*   `sh_degree`: Integer or None. If not None, enables spherical harmonics color computation; otherwise uses direct color mode [S1, unofficial].
*   `render_mode`: String specifying output channels. Valid values: "RGB", "D", "ED", "RGB+D", "RGB+ED", "d", "Ed", "RGB+d", "RGB+Ed" [S1, unofficial].
*   `rasterize_mode`: String specifying rendering style. Valid values: "classic", "antialiased" [S1, unofficial].
*   `camera_model`: String specifying camera projection. Valid values: "pinhole", "ortho", "fisheye" [S1, unofficial].

**Outputs:**
*   `render_colors`: $[C, H, W, D]$ tensor of rendered colors.
*   `render_alphas`: $[C, H, W, 1]$ tensor of accumulated alpha values.
*   (Optional) Depth maps and masks depending on `render_mode`.

**Data Structures:**
*   **Conic Representation**: To avoid repeated matrix inversions during rasterization, the inverse 2D covariance $\Sigma_{2D}^{-1}$ is precomputed and stored as a "conic" vector containing the upper triangle elements: $[\Sigma_{2D}^{-1}[0,0], \Sigma_{2D}^{-1}[0,1], \Sigma_{2D}^{-1}[1,1]]$ [S1, unofficial].
*   **Tile Intersection Data**: `isect_offsets` $[C, \text{tile\_height}, \text{tile\_width}]$ and `flatten_ids` mapping Gaussians to tiles.

**Steps:**

1.  **Input Validation**: Check `render_mode`, `rasterize_mode`, and `camera_model` against valid sets [S1, unofficial].
2.  **3D Covariance Computation**: Compute 3D covariance matrices from quaternions and scales. Using `quat_scale_to_covar_preci` with `compute_covar=True`, `compute_preci=False`, `triu=False`, resulting in shape $[N, 3, 3]$ [S1, unofficial]. Let this be $\Sigma_{3D}$ [S2, unofficial].
3.  **Projection to 2D**: Linearize projection of 3D means and 3D covariance to 2D screen space using camera intrinsics/extrinsics and image size [S2, unofficial].
    *   Compute camera-space means: $\mathbf{means}_c = \mathbf{R} \mathbf{means}_3^\top + \mathbf{t}$, where $\mathbf{R}$ and $\mathbf{t}$ are from `viewmats` [S1, unofficial].
    *   Compute 2D covariance $\Sigma_{2D}$ using the Jacobian $J$ of the projection function $\phi(\mathbf{x}') = \mathbf{x}' (\mathbf{x}_0^\top \mathbf{x}')^{-1}$ evaluated at the camera-space mean $\mu'$: $\Sigma_{2D} = J \Sigma' J^T$ [Parent].
    *   Compute conics from $\Sigma_{2D}^{-1}$ [Parent].
    *   Compute bounding box radii using the 3-sigma rule: $\text{bboxsize\_cam} = [3.0 \sqrt{\Sigma_{2D}[0,0]}, 3.0 \sqrt{\Sigma_{2D}[1,1]}]$ [Parent].
    *   Output: `radii` $[C, N, 2]$, `means_2D` $[C, N, 2]$, `depths` $[C, N]$, `conics` $[C, N, 3]$ [S1, unofficial].
4.  **Spherical Harmonics Evaluation (Optional)**: If `sh_degree` is not None:
    *   Compute view directions: $\mathbf{dirs} = \mathbf{means}_3 - \mathbf{campos}$, normalized [S1, unofficial].
    *   Broadcast color coefficients to $[C, N, K, 3]$ and evaluate spherical harmonics to get RGB $[C, N, 3]$ [S1, unofficial].
    *   Clamp colors: $\max(\mathbf{rgb} + 0.5, 0.0)$ [S1, unofficial].
    *   If `sh_degree` is None, broadcast colors $[N, D]$ to $[C, N, D]$ or use directly [S1, unofficial].
5.  **Tile Intersection**:
    *   Compute tile dimensions: $\text{tile\_width} = \lceil \text{width} / \text{tile\_size} \rceil$, $\text{tile\_height} = \lceil \text{height} / \text{tile\_size} \rceil$ [S1, unofficial].
    *   Call `isect_tiles(means_2D, radii, depths, tile_size, tile_width, tile_height, sort=True)` to get `tiles_per_gauss`, `isect_ids`, `flatten_ids` [S1, unofficial].
    *   Encode intersection offsets: `isect_offsets` $[C, \text{tile\_height}, \text{tile\_width}]$ using `isect_offset_encode` [S1, unofficial].
6.  **Opacity and Compensation**:
    *   Broadcast scalar per-Gaussian opacities $[N]$ to per-camera $[C, N]$ [S1, unofficial].
    *   If `rasterize_mode` is "antialiased", compensations are computed and multiplied with opacities [S1, unofficial].
7.  **Alpha Computation**: Compute alpha values for each Gaussian at each pixel based on opacities, 2D means, and 2D covariances [S2, unofficial].
    *   $\alpha_i = \text{opacity}_i \cdot \exp(-0.5 (\mathbf{x} - \mathbf{\mu}_{2D})^\top \Sigma_{2D}^{-1} (\mathbf{x} - \mathbf{\mu}_{2D}))$ [Parent, unofficial].
8.  **Sorting and Filtering**:
    *   Filter Gaussians behind the camera: $\text{mask} = z_{\text{vals}} \ge 0.0$ [S2, unofficial].
    *   Sort remaining Gaussians by depth using a stable sort (e.g., radix sort) [S2, S3, unofficial].
9.  **Rasterization to Pixels**:
    *   For each tile, iterate over intersecting Gaussians in sorted order.
    *   Compute transmittance: $T_i = \prod_{j=1}^{i-1} (1 - \alpha_j)$ [Parent].
    *   Compute weight: $w_i = \alpha_i T_i$ [Parent].
    *   Composite color: $\mathbf{C}_{\text{pixel}} = \sum_i w_i \mathbf{C}_i$ [S2, unofficial].
    *   Composite alpha: $\alpha_{\text{pixel}} = \sum_i w_i$ [S2, unofficial].
    *   Composite depth (if requested): $D_{\text{pixel}} = \sum_i w_i z_i$ [S2, unofficial].
    *   Normalize depth by alpha if expected depth is required: $D_{\text{normalized}} = D_{\text{pixel}} / \max(\alpha_{\text{pixel}}, 10^{-10})$ [S1, unofficial].
10. **Background Compositing**:
    *   Composite background color where mask is zero: $\mathbf{I} = \alpha_{\text{mask}} \mathbf{I}_{\text{comp}} + (1.0 - \alpha_{\text{mask}}) \mathbf{B}_{\text{color}}$ [S2, unofficial].

**Pseudocode:**

```python
def rasterize_gaussians(
    means_3d: Tensor,
    quats: Tensor,
    scales: Tensor,
    opacities: Tensor,
    colors: Tensor,
    viewmats: Tensor,
    Ks: Tensor,
    width: int,
    height: int,
    tile_size: int = 16,
    near_plane: float = 0.01,
    far_plane: float = 1e10,
    sh_degree: int = None,
    render_mode: str = "RGB",
    rasterize_mode: str = "classic",
    camera_model: str = "pinhole"
) -> Tuple[Tensor, Tensor]:
    """
    Rasterize 3D Gaussians to 2D images.
    
    Args:
        means_3d: [N, 3]
        quats: [N, 4]
        scales: [N, 3]
        opacities: [N]
        colors: [N, D] or [N, K, 3] if sh_degree is set
        viewmats: [C, 4, 4]
        Ks: [C, 3, 3]
        width, height: int
        tile_size: int
        near_plane, far_plane: float
        sh_degree: int or None
        render_mode: str
        rasterize_mode: str
        camera_model: str
        
    Returns:
        render_colors: [C, H, W, D]
        render_alphas: [C, H, W, 1]
    """
    C = viewmats.shape[0]
    
    # 1. Input Validation
    assert render_mode in {"RGB", "D", "ED", "RGB+D", "RGB+ED", "d", "Ed", "RGB+d", "RGB+Ed"}
    assert rasterize_mode in {"classic", "antialiased"}
    assert camera_model in {"pinhole", "ortho", "fisheye"}
    
    # 2. Compute 3D Covariance
    cov_3d = quat_scale_to_covar(quats, scales) # [N, 3, 3]
    
    # 3. Project to 2D
    # Compute camera-space means and covariances
    R = viewmats[:, :3, :3] # [C, 3, 3]
    t = viewmats[:, :3, 3]  # [C, 3]
    means_c = einsum("cij,nj->cni", R, means_3d) + t[:, None, :] # [C, N, 3]
    
    # Project covariance using Jacobian J
    # J is derived from camera intrinsics Ks and means_c
    cov_2d = project_covariance(cov_3d, means_c, Ks) # [C, N, 2, 2]
    
    # Compute conics (inverse 2D covariance upper triangle)
    conics = compute_conics(cov_2d) # [C, N, 3]
    
    # Compute 2D means and radii
    means_2d = project_means(means_c, Ks) # [C, N, 2]
    radii = compute_radii(cov_2d) # [C, N, 2]
    
    # Compute depths for sorting
    depths = means_c[:, :, 2] # [C, N]
    
    # 4. Spherical Harmonics (if applicable)
    if sh_degree is not None:
        campos = -einsum("cij,j->ci", R, t) # Camera positions in world space
        dirs = means_3d[None, :, :] - campos[:, None, :] # [C, N, 3]
        dirs_norm = maximum(norm(dirs, axis=-1, keepdims=True), 1e-8)
        dirs = dirs / dirs_norm
        # Broadcast colors and evaluate SH
        coeffs = broadcast_colors(colors, C, N)
        rgb = spherical_harmonics(sh_degree, dirs, coeffs) # [C, N, 3]
        rgb = maximum(rgb + 0.5, 0.0)
        colors_for_raster = rgb
    else:
        colors_for_raster = broadcast_colors(colors, C, N) # [C, N, D]
        
    # 5. Tile Intersection
    tile_width = ceil(width / tile_size)
    tile_height = ceil(height / tile_size)
    tiles_per_gauss, isect_ids, flatten_ids = isect_tiles(
        means_2d, radii, depths, tile_size, tile_width, tile_height, sort=True
    )
    isect_offsets = isect_offset_encode(isect_ids, C, tile_width, tile_height)
    
    # 6. Opacity and Compensation
    opacities_cn = broadcast_to(opacities, (C, N)) # [C, N]
    if rasterize_mode == "antialiased":
        compensations = compute_compensations(cov_2d, Ks)
        opacities_cn = opacities_cn * compensations
        
    # 7. Compute Alphas
    alphas = compute_alphas(opacities_cn, means_2d, cov_2d, width, height) # [C, N, H, W]
    
    # 8. Sorting and Filtering
    # Filter behind camera
    mask = depths >= 0.0
    # Sort by depth
    sorted_indices = argsort(depths * mask, axis=1)
    # Gather sorted tensors
    means_2d_sorted = gather(means_2d, sorted_indices)
    conics_sorted = gather(conics, sorted_indices)
    colors_sorted = gather(colors_for_raster, sorted_indices)
    alphas_sorted = gather(alphas, sorted_indices)
    depths_sorted = gather(depths, sorted_indices)
    
    # 9. Rasterize to Pixels
    # Use fused kernel for tile-based rasterization
    render_colors, render_alphas = rasterize_to_pixels_mlx(
        means_2d_sorted,
        conics_sorted,
        colors_sorted,
        alphas_sorted,
        width,
        height,
        tile_size,
        isect_offsets,
        flatten_ids,
        backgrounds=ones((C, 3)) # Default white background
    )
    
    # 10. Post-processing for Depth/Expected Depth
    if "D" in render_mode or "d" in render_mode:
        # Compute weighted depth sum
        # Note: alphas_sorted is [C, N, H, W], depths_sorted is [C, N]
        # Need to broadcast depths to [C, N, H, W]
        depths_expanded = expand_dims(depths_sorted, axis=(2, 3))
        weights = alphas_sorted
        depth_sum = sum(weights * depths_expanded, axis=1) # [C, H, W]
        alpha_sum = sum(alphas_sorted, axis=1) # [C, H, W]
        
        if "d" in render_mode: # Unnormalized depth
            depth_channel = depth_sum
        else: # Normalized depth (expected depth)
            depth_channel = depth_sum / maximum(alpha_sum, 1e-10)
            
        # Concatenate or replace color channels
        if "RGB" in render_mode:
            render_colors = concatenate([render_colors, expand_dims(depth_channel, axis=-1)], axis=-1)
        else:
            render_colors = expand_dims(depth_channel, axis=-1)
            
    return render_colors, expand_dims(render_alphas, axis=-1)
```

## Subtopics

### [3D Gaussian Splatting Differentiable Rasterizer](2813-3d-gaussian-splatting-differentiable-rasterizer.md)
The 3D Gaussian Splatting Differentiable Rasterizer is the core rendering engine that projects a set of 3D Gaussian primitives into a 2D image plane and accumulates color via alpha compositing, enabling gradient-based optimization of Gaussian parameters (position, covariance, opacity, color) and camera poses. It differs from its siblings by providing the specific differentiable forward and backward passes required for training; for instance, [Optimal Gaussian Splatting](3293-optimal-gaussian-splatting.md) focuses on sampling efficiency, while [Hybrid Transparency](3294-hybrid-transparency.md) modifies the blending model, and [Perspective-Correct 3D Gaussian Splatting via Plücker Coordinates](3403-perspective-correct-3d-gaussian-splatting-via-pl-cker-coordi.md) alters the projection geometry.

### [Optimal Gaussian Splatting](3293-optimal-gaussian-splatting.md)
Optimal Gaussian Splatting is a rendering method that reduces projection error by radially projecting each 3D Gaussian onto a unique tangent plane perpendicular to the line connecting the Gaussian mean to the camera center, rather than projecting all Gaussians onto a single plane $z=1$. Unlike the original 3D Gaussian Splatting rasterization which uses a fixed perspective plane, this method treats the projection as a radial mapping onto a unit sphere, ensuring the projection of the Gaussian mean coincides with the ray direction from the camera center. It differs from NeRF by avoiding extensive ray sampling, instead determining which tangent-plane Gaussians intersect the ray on the unit sphere.

### [Perspective-Correct 3D Gaussian Splatting via Plücker Coordinates](3403-perspective-correct-3d-gaussian-splatting-via-pl-cker-coordi.md)
This method computes the value of a 3D Gaussian primitive for a given viewing ray in screen space without performing matrix inversion, utilizing Plücker coordinates to represent the ray and calculate the distance to the Gaussian's center. It sets itself apart from standard 3D Gaussian Splatting rasterization by providing a closed-form, numerically stable solution for perspective-correct splat evaluation that handles degenerate ellipsoids and avoids the computational cost of matrix inversions.

### [3D Gaussian Splatting Rasterization (Cone-Beam/Scanner Space)](3458-3d-gaussian-splatting-rasterization-cone-beam-scanner-space.md)
This method renders X-ray projections from a 3D Gaussian representation by integrating the 3D Gaussian density along cone-beam ray paths, resulting in a sum of 2D Gaussians rather than the alpha-compositing used in standard visible-light rendering. It solves the problem of simulating X-ray CT projections from learned 3D Gaussian fields by adapting the rasterization pipeline to a pinhole camera model, enabling analytical integration of radiative density. Unlike standard 3D Gaussian Splatting which composites opacities, this method sums projected 2D densities, fundamentally addressing integration bias issues where learning integrated density in 2D leads to inconsistencies in 3D density retrieval.

### [Analytic-Splatting Forward Shading](3459-analytic-splatting-forward-shading.md)
Analytic-Splatting Forward Shading computes the color contribution of 3D Gaussians to a pixel by analytically integrating the Gaussian probability density function over the pixel area, rather than sampling the center. It solves the aliasing artifacts inherent in point-sampling approaches by approximating the pixel area integral using a conditioned logistic function. It sets itself apart from vanilla 3DGS by providing anti-aliased results and from Mip-Splatting by using a different analytical approximation that maintains higher detail fidelity, albeit with a slight computational overhead.

### [Speedy-Splat Rendering Pipeline](3543-speedy-splat-rendering-pipeline.md)
The Speedy-Splat Rendering Pipeline is a GPU-accelerated rasterization method for 3D Gaussian Splatting that replaces coarse bounding-box tile intersection tests with precise Gaussian-tile intersection checks and sorting-based depth ordering. It addresses the inefficiency of standard 3D-GS rasterization, which overestimates Gaussian extents and processes non-intersecting pixels, by generating a sparse set of Gaussian-tile pairs and sorting them for efficient pixel-wise compositing.

### [Ghost Ellipsoids for Chunked Training](3559-ghost-ellipsoids-for-chunked-training.md)
Ghost Ellipsoids for Chunked Training resolves boundary artifacts in chunked volume training by including ellipsoids from neighboring chunks in the loss computation without updating their parameters, providing boundary context without requiring a global volume or merged model. Unlike chunk-based 3DGS methods that resolve boundary inconsistencies by merging chunks into a global coarse model or through post-training stages, this method requires boundary support during training itself without access to a global volume.

### [Ref-Gaussian Deferred Surfel Rendering with Split-Sum IBL](4464-ref-gaussian-deferred-surfel-rendering-with-split-sum-ibl.md)
Ref-Gaussian Deferred Surfel Rendering with Split-Sum IBL is a real-time deferred shading method for relighting 3D Gaussian Splatting (3DGS) models on mobile hardware (specifically iOS/Metal). It solves the problem of dynamic environment lighting in Gaussian splats by decomposing splats into physically-based rendering (PBR) materials (albedo, normal, roughness, reflectance) and computing lighting via a deferred pipeline with split-sum environment map integration. Unlike forward-shading Gaussian splatters that bake lighting into spherical harmonics or use analytic approximations, this method separates the material definition from the lighting environment, allowing the environment map to be swapped or rotated in real-time without retraining or re-rasterizing the splats. It differs from standard PBR deferred renderers by adapting the splat-based rasterization and surfel accumulation to the deferred G-buffer workflow.

### [3D Gaussian Splatting Self-Shadowing (T_light)](4487-3d-gaussian-splatting-self-shadowing-t-light.md)
Calculates the self-shadowing transmittance $T_{light}$ for each Gaussian along a directional sun direction, representing the 'front occlusion transmittance' to model self-shadowing effects in volume rendering. It differs from standard alpha blending by explicitly tracking accumulated occlusion from the light source's perspective rather than the camera's, enabling physically plausible shadows within the Gaussian volume.

### [Light Space Rasterization for T_light](4489-light-space-rasterization-for-t-light.md)
Light Space Rasterization computes $T_{light}$, the front-facing occlusion transmittance for each 3D Gaussian along a directional sun direction. It differs from voxel-based fallbacks by providing full continuous gradients and zero parameter expansion, enabling differentiable relighting without requiring specific training hyperparameters.

### [2D Gaussian Splatting Rasterization](4815-2d-gaussian-splatting-rasterization.md)
2D Gaussian Splatting Rasterization renders a scene represented by 3D Gaussian surfels by projecting them to 2D screen-space ellipses and performing tile-based, front-to-back alpha compositing. It differs from its parent [3D Gaussian Splatting Rasterization](2812-3d-gaussian-splatting-rasterization.md) by treating primitives as planar surfels with explicit normal vectors, enabling the accumulation of normal maps alongside color and depth, and by using a specific ray-surfel intersection logic to determine the contribution of each surfel to a pixel. It serves as a differentiable rendering kernel for 2D Gaussian Splatting, allowing gradients to flow from the rendered image back to the Gaussian parameters.

### [AdR-Gaussian](8365-adr-gaussian.md)
AdR-Gaussian is a rendering acceleration method for 3D Gaussian Splatting that optimizes the rasterization pipeline by moving serial culling operations to a parallel preprocessing stage and balancing computational loads across pixel threads. It achieves significant speedups without reducing the total number of Gaussians, thereby avoiding the quality degradation associated with pruning-based acceleration methods.

### [3D Half-Gaussian Splatting](9011-3d-half-gaussian-splatting.md)
3D Half-Gaussian Splatting (3D-HGS) is a reconstruction kernel for 3D Gaussian Splatting that replaces the standard isotropic Gaussian with a half-space truncated Gaussian to resolve shape and color discontinuities (Gibbs phenomenon) at object boundaries and texture-rich areas. It achieves state-of-the-art rendering quality on standard benchmarks without compromising the real-time performance of the underlying rasterizer, distinguishing itself from 2D-GS by retaining volumetric rendering and from GES by explicitly modifying the kernel function rather than just scaling factors.

### [QuadBox](9231-quadbox.md)
QuadBox is a Gaussian-tile intersection method that uses four axis-aligned bounding boxes (AABBs) to tightly encapsulate projected 2D Gaussians, reducing tile over-approximation and redundant computations in the rasterizer preprocess stage. It sets itself apart from its sibling [3D Gaussian Splatting Rasterization](2812-3d-gaussian-splatting-rasterization.md) by replacing the conservative single AABB with a geometry-aware QuadBox, and from [AdR-Gaussian](8365-adr-gaussian.md) by using four adaptive sub-boxes to better capture anisotropic shapes, thereby suppressing residual redundancy along the minor axis.

### [Transparency and Blending Models](9274-transparency-and-blending-models.md)
Transparency and Blending Models define how 3D Gaussian primitives are composited into a 2D image, addressing the fundamental problem of order-dependent alpha blending in splatting-based rendering. Standard 3D Gaussian Splatting uses approximate per-primitive sorting and 2D projection, which can introduce popping artifacts and inaccuracies in transmittance [2812-3d-gaussian-splatting-rasterization.md]. This family provides alternatives that either correct depth ordering for real-time performance, replace projection with analytic ray-space integration for physical accuracy, or eliminate sorting entirely via Order-Independent Transparency (OIT) [3294-hybrid-transparency.md], [4440-analytic-transmittance-3dgs.md], [7562-sparseoit-rasterizer.md].

## Operating characteristics
**Time Complexity:** The dominant cost is sorting $N$ Gaussians, which is $O(N \log N)$ but optimized to near-linear using radix sort on GPU [S3, unofficial]. Tile-based rasterization reduces the number of pixel-Gaussian intersections to $O(K)$ where $K$ is the number of active splats per pixel, typically small.
**Memory Complexity:** $O(N)$ for storing Gaussian parameters and $O(H \times W)$ for the output image and intermediate buffers. High VRAM usage: 4GB to view, 12GB to train [S3, unofficial].
**Measured Performance:** Real-time rendering (60+ FPS) is achievable on modern GPUs (e.g., RTX 3090/4090) for scenes with millions of Gaussians [S3, unofficial].
**Scaling:** Scales well with resolution due to tile-based processing. Scales with $N$ linearly, but sorting becomes a bottleneck for very large $N$ (millions) [S3, unofficial].
**Strengths:** Real-time performance, differentiability for training, high visual quality [S3, unofficial].
**Limitations:** High VRAM usage, large disk size (1GB+ for a scene) [S3, unofficial], incompatible with existing rendering pipelines (Vulkan, DirectX, WebGPU) without adaptation [S3, unofficial]. The primary bottleneck is sorting millions of gaussians, which is done efficiently in the original implementation using CUB device radix sort, a highly optimized sort only available in CUDA [S3, unofficial].

## Background
3D Gaussian Splatting was introduced in the paper "3D Gaussian Splatting for Real-Time Radiance Field Rendering" by Kerbl et al. in 2023 [S3, unofficial]. It emerged as a method to achieve real-time rendering of photorealistic scenes learned from small samples of images, analogous to triangle rasterization but using Gaussians instead of triangles [S3, unofficial]. The method relies on Structure from Motion (SfM) to initialize the Gaussians, typically using COLMAP [S3, unofficial]. It has since become a standard technique in novel view synthesis and 3D reconstruction, with numerous variants and optimizations developed to address its limitations in geometry, performance, and compatibility [S4, S8, unofficial].
