# Tiled 2D Gaussian Splatting Rasterization

Also called: Gaussian Rasterization (GPU), Speedy-Splat, Standard 3DGS Rasterization, Tile allocation methods, binAndSortGaussians

## Overview
Tiled 2D Gaussian Splatting Rasterization is a highly optimized, GPU-parallel method for rendering 3D Gaussian Splatting scenes in real-time [S1, S2, S3, unofficial]. It partitions the image plane into macro-tiles (typically 16x16 or 32x32 pixels) and assigns CUDA thread blocks to each tile, allowing threads to cooperatively fetch sorted Gaussians and accumulate pixel color via iterative alpha-blending [S1, S3, unofficial]. Unlike parent methods that sort on the CPU, this approach performs device-side sorting and rasterization, enabling differentiable gradient computation for training [S2, unofficial]. It sets itself apart from non-tiled approaches by managing memory and processing load through spatial partitioning, and from screen-space quad methods by explicitly handling tile-boundary data and depth-sorted accumulation [S1, S3, unofficial].

## How it works
**Inputs:**
- 3D Gaussian attributes: means ($\mathbf{x}$), covariances ($\Sigma$), opacities ($\alpha$), spherical harmonics coefficients (for color $\mathbf{c}$).
- Camera parameters: intrinsic matrix ($K$), extrinsic rotation ($R$) and translation ($t$), image dimensions ($W, H$), tile size ($T_x, T_y$).
- Background color tensor $\mathbf{bg}$ of shape $[3, H, W]$.

**Outputs:**
- Output image tensor $\mathbf{C}$ of shape $[3, H, W]$.
- Alpha tensor $\mathbf{A}$ of shape $[H, W]$.
- Intermediate tensors for backward pass: final transmittance $\mathbf{T}$, final indices $\mathbf{Idx}$.

**Data Structures:**
- **Tile Grid:** A 2D grid of tiles covering the image. Tile width $W_{tile} = \lceil W / T_x \rceil$, Tile height $H_{tile} = \lceil H / T_y \rceil$.
- **Gaussian List:** Array of Gaussian structs containing projected 2D mean $(u, v)$, conics $(a, b, c)$, opacity $\alpha$, and color $\mathbf{c}$.
- **Tile Bins:** An array of size $N_{tiles} + 1$ storing the start and end indices of Gaussians assigned to each tile in the sorted Gaussian list.

**Steps:**

1.  **Frustum Culling:** Filter out Gaussians outside the camera's near/far planes and field of view [S1, S3, unofficial].
2.  **Projection:** Transform Gaussian means to camera space and project to the image plane [S3, unofficial]. Compute 2D covariances in screen space using the Jacobian of the projection and the rotated 3D covariance [S3, unofficial].
3.  **Conic Computation:** Compute the inverse of the 2D covariance matrix (conics) to efficiently evaluate the Gaussian density function [S3, unofficial]. Let the conic matrix be $\begin{bmatrix} a & b \\ b & c \end{bmatrix}$.
4.  **Bounding Box & Tile Assignment:** Compute the axis-aligned bounding box (AABB) for each Gaussian's 2D extent. Assign each Gaussian to all tiles that intersect its AABB [S1, S3, unofficial].
    *   *Note:* Variants like SnugBox use tight ellipse bounds, while AccuTile iterates to verify intersection [S1, unofficial].
5.  **Sorting:** Sort the assigned Gaussians by a unique ID combining tile index and depth (view-space Z) using a device-side radix sort [S1, S2, unofficial]. This ensures Gaussians are processed back-to-front within each tile.
6.  **Tile Bin Generation:** Compute cumulative counts of Gaussians per tile to create bin edges, defining the range of Gaussians in the sorted list for each tile [S2, S3, unofficial].
7.  **Rasterization Kernel:**
    *   Launch one CUDA thread block per tile [S1, unofficial].
    *   Each thread block loads the Gaussians assigned to its tile from the sorted list using the bin edges [S3, unofficial].
    *   For each pixel $(u, v)$ in the tile:
        *   Initialize accumulated color $C_{acc} = 0$ and transmittance $T_{acc} = 1.0$ [S3, unofficial].
        *   Iterate through the tile's Gaussians in sorted order:
            *   Calculate squared Mahalanobis distance: $dist\_sq = a \cdot du^2 + 2 \cdot b \cdot du \cdot dv + c \cdot dv^2$, where $du = u - u_{mean}$ and $dv = v - v_{mean}$ [S3, unofficial].
            *   Compute Gaussian contribution: $G = \exp(-0.5 \cdot dist\_sq)$ [S3, unofficial].
            *   Compute pixel opacity: $\alpha_{pix} = \alpha_{gauss} \cdot G$ [S1, unofficial].
            *   Update color: $C_{acc} += \mathbf{c} \cdot \alpha_{pix} \cdot T_{acc}$ [S1, unofficial].
            *   Update transmittance: $T_{acc} *= (1 - \alpha_{pix})$ [S1, unofficial].
            *   **Early Termination:** If $T_{acc}$ drops below a threshold (e.g., 0.01) or $\alpha_{pix}$ is negligible, break the loop for this pixel [S1, S3, unofficial].
        *   Store final $C_{acc}$ and $T_{acc}$ for the pixel [S3, unofficial].
8.  **Background Compositing:** Add the background color weighted by the final transmittance: $\mathbf{C}_{final} = \mathbf{C}_{acc} + \mathbf{bg} \cdot (1 - \mathbf{A})$ [S3, unofficial].
9.  **Backward Pass:** Gradients are computed by reversing the blending chain. For each Gaussian, gradients for color and opacity are accumulated across all affected pixels using atomic operations [S1, unofficial].

**Pseudocode:**

```python
def tiled_rasterization(gaussians, camera, tile_size=32):
    # 1. Frustum Culling
    visible_gaussians = frustum_cull(gaussians, camera)
    
    # 2. Projection
    means_cam = camera.transform_points_world_to_cam(visible_gaussians.means)
    means_img = camera.project_points_cam_to_image_plane(means_cam)
    
    # 3. Covariance Rotation and 2D Approximation
    covs_cam = camera.rotate_covariances_world_to_cam(visible_gaussians.covariances)
    covs_2d = approximate_2d_covariances(covs_cam, means_cam, camera.fx, camera.fy)
    
    # 4. Conics (Inverse Covariance)
    conics = compute_conics(covs_2d) # Returns (a, b, c) for each Gaussian
    
    # 5. Bounding Box and Tile Assignment
    # Compute AABB for each Gaussian based on conics and sigma_multiplier (e.g., 3.0)
    bboxes = compute_axis_aligned_bounding_box(conics, means_img, sigma_multiplier=3.0)
    
    # Assign Gaussians to tiles
    tile_assignments = assign_gaussians_to_tiles(bboxes, means_img, tile_size, camera.width, camera.height)
    
    # 6. Sorting
    # Create unique IDs: (tile_index << 32) | depth_index
    isect_ids = map_gaussian_to_intersects(tile_assignments, means_cam.z)
    isect_ids_sorted, sorted_indices = torch.sort(isect_ids)
    
    # Gather sorted Gaussian properties
    sorted_gaussians = gather_properties(visible_gaussians, sorted_indices)
    
    # 7. Tile Bins
    num_tiles = (camera.width + tile_size - 1) // tile_size * ((camera.height + tile_size - 1) // tile_size)
    tile_bins = get_tile_bin_edges_tensor(isect_ids_sorted, num_tiles)
    
    # 8. Rasterization Kernel (Simulated for clarity)
    output_color = torch.zeros(3, camera.height, camera.width)
    output_alpha = torch.zeros(camera.height, camera.width)
    final_transmittance = torch.ones(camera.height, camera.width)
    
    # In practice, this is a CUDA kernel. Here is the logic per tile:
    for tile_u in range(num_tiles_x):
        for tile_v in range(num_tiles_y):
            tile_idx = tile_v * num_tiles_x + tile_u
            start_idx = tile_bins[tile_idx]
            end_idx = tile_bins[tile_idx + 1]
            
            tile_gaussians = sorted_gaussians[start_idx:end_idx]
            
            u_start = tile_u * tile_size
            v_start = tile_v * tile_size
            u_end = min(u_start + tile_size, camera.width)
            v_end = min(v_start + tile_size, camera.height)
            
            for u_pix in range(u_start, u_end):
                for v_pix in range(v_start, v_end):
                    # Early termination check
                    if final_transmittance[v_pix, u_pix] < 0.01:
                        continue
                        
                    acc_color = 0.0
                    acc_alpha = 0.0
                    current_transmittance = final_transmittance[v_pix, u_pix]
                    
                    for g in tile_gaussians:
                        du = u_pix - g.means_img.x
                        dv = v_pix - g.means_img.y
                        
                        # Mahalanobis distance
                        dist_sq = g.conics.a * du**2 + 2 * g.conics.b * du * dv + g.conics.c * dv**2
                        
                        # Gaussian value
                        g_val = torch.exp(-0.5 * dist_sq)
                        
                        # Pixel opacity
                        alpha_pix = g.opacity * g_val
                        
                        # Alpha blending
                        acc_color += g.color * alpha_pix * current_transmittance
                        current_transmittance *= (1 - alpha_pix)
                        
                        # Accumulate alpha for this pixel (for backward pass or final alpha)
                        acc_alpha += alpha_pix * current_transmittance # Note: standard 3DGS accumulates differently for backward
                        
                    final_transmittance[v_pix, u_pix] = current_transmittance
                    output_color[:, v_pix, u_pix] = acc_color
                    output_alpha[v_pix, u_pix] = 1.0 - current_transmittance # Simplified
                    
    # 9. Background Compositing
    bg = torch.zeros(3, camera.height, camera.width) # Or loaded background
    output_color += bg * (1 - output_alpha).unsqueeze(0)
    
    return output_color, output_alpha, final_transmittance
```

**Parameters:**
- `tile_size`: Default 32x32 pixels [S3, unofficial].
- `sigma_multiplier`: Multiplier for Gaussian extent, typically 3.0 for 3-sigma [S3, unofficial].
- `BLOCK_X`, `BLOCK_Y`: Tile dimensions in pixels, used for tile bound calculation [S2, unofficial].

**Edge Cases and Pitfalls:**
- **Precision:** Floating-point precision in the Mahalanobis distance calculation can affect gradient stability during training [S1, unofficial].
- **Boundaries:** Ensure tile bounds are correctly calculated for images where width/height are not multiples of tile size [S2, unofficial].
- **Degenerate Input:** Gaussians with zero or near-zero covariance can cause numerical instability in conic computation [S3, unofficial].

## Subtopics

### [Non-Tiled 2D Gaussian Splatting with Transmittance Culling](2067-non-tiled-2d-gaussian-splatting-with-transmittance-culling.md)
A rasterization method for 3D Gaussian Splatting that iterates over Gaussians rather than tiles, using axis-aligned bounding boxes to limit pixel iteration and transmittance-based early ray termination for performance optimization. It produces visually identical results to tiled rasterization in most cases but is significantly faster due to early stopping and better culling.

### [Tile-Based Culling](2819-tile-based-culling.md)
Tile-Based Culling computes a precise Gaussian-to-Tile mapping to cull irrelevant tiles during 3D Gaussian Splatting rasterization. It improves upon standard conservative bounding box assignment by computing tight, opacity-aware bounding boxes and iteratively verifying tile intersections. It is distinguished from [SnugBox](3378-snugbox.md) by its iterative tile examination process, which results in higher runtime costs for the culling phase compared to AccuTile, though it may show marginal downstream performance gains due to undercounting artifacts.

### [Gaussian Splat Projection and Sorting](3369-gaussian-splat-projection-and-sorting.md)
This method is a compute-shader stage that projects 3D Gaussians to 2D screen space, performs visibility and frustum culling, computes lighting, and prepares data for tile-based sorting. It bridges raw 3D Gaussian data and the tiled rasterization pipeline by ensuring only visible splats are processed and ordered by tile and depth. It differs from non-tiled approaches by explicitly preparing tile-boundary data and from tile-based culling by handling full projection and sorting key generation.

### [Splat Batching Strategy](4296-splat-batching-strategy.md)
Splat Batching Strategy is a GPU optimization technique for 3D Gaussian Splatting that reduces draw call overhead by packing multiple Gaussian splats into a single instanced rendering command. It addresses the performance bottleneck of issuing individual draw calls for each Gaussian, which is inefficient when rendering scenes with tens or hundreds of thousands of splats. Unlike non-tiled approaches that may process all splats in one massive batch or tile-based methods that split work spatially, batching focuses on temporal efficiency by grouping splats into fixed-size chunks for instanced drawing.

### [Spirula Renderer](6909-spirula-renderer.md)
A GPU-accelerated Gaussian Splatting renderer implemented as a native Vulkan bridge (librosplat_spirula.so) called via ctypes from Python. It handles tile sorting, Gaussian rasterization, and rendering to Vulkan textures.

### [Depth Rendering with Constant Opacity](7462-depth-rendering-with-constant-opacity.md)
A rendering pass designed to produce depth maps by forcing all Gaussians to have uniform opacity, ensuring that the rasterizer's depth accumulation is driven by geometric distance rather than opacity weighting.

### Opacity-Thresholded Tile Intersection Filtering
Filters out Gaussians whose opacity $\tau$ falls below the alpha-threshold $\epsilon$ immediately during tile intersection, as their axis-aligned bounding box is considered empty [S4]. Gaussians with opacity $\tau < \epsilon$ are filtered [S4]. Combining all modifications decreased rendering time on the Bicycle scene at native resolution by a factor of 3.77 and GPU memory usage by a factor of 2.11 compared to the reference [S4].

### Mobile-GS
A memory-centric rendering design for smartphones that loads only the Gaussians visible in the current view frustum from flash storage, uses a quantized integer representation for positions and colors, and performs the blending in a lower-precision shader [S1, unofficial].

### FlashGS
A method focusing on accelerating the forward process by partitioning the screen into finer tiles and scheduling them on a multi-GPU pipeline [S1, unofficial].

### FilterGS
A method that proposes a traversal-free, parallel filtering structure that selects a single scale for each Gaussian via a learned network, avoiding expensive tree traversal at render time [S1, unofficial].

### 4D Gaussian Splatting Motion Evaluation
A technique for rendering time-varying 3D captures (volumetric video) by storing static per-splat attributes and per-splat motion coefficients in extra textures, evaluated in the vertex shader from a time uniform, avoiding per-frame CPU sorting and texture uploads [S5, unofficial].
- Store static per-splat attributes (position, scale, rotation, color) in standard splat buffers [S5, unofficial].
- Store per-splat motion coefficients (linear or polynomial trajectory parameters) and temporal opacity window parameters in extra textures [S5, unofficial].
- Pass the current playback time as a uniform to the vertex shader [S5, unofficial].
- In the vertex shader, evaluate the motion coefficients against the time uniform to compute the current position and opacity for each splat [S5, unofficial].
- Perform sorting only occasionally, as motions are assumed to be small enough to not require per-frame sorting for visual correctness [S5, unofficial].

### Tile-based Depth Sorting
A method to mitigate 'popping' artifacts caused by per-ray depth sorting inconsistencies when viewpoints rotate, by replacing per-ray sorting with tile-based sorting [S6].
- Replaces the per-ray depth sorting mechanism with tile-based sorting to ensure consistent sorting order within a local region [S6].

### AABB Culling for Gaussian Splatting
A culling technique that uses an axis-aligned bounding box of the projected Gaussian ellipse to reduce ineffective rendering expenses, specifically addressing the inability of bounding circles to cull low-opacity pairs in the minor axis direction [S7].
- Set the partial derivatives to 0 to find extrema. Substitute the coordinate relationships into the ellipse function to solve for the maximum coordinate values $x_{max}$ and $y_{max}$ [S7].
- Cull tiles based on the axis-aligned bounding box constructed by $x_{max}$ and $y_{max}$, which correspond to the half-width $w$ and half-height $h$ of the bounding box [S7].

### Load Balancing for Pixel-parallel Splatting
A strategy to address uneven computational load across pixel threads in Gaussian rasterization by reducing the number of Gaussians rendered for heavy-load pixels and increasing it for light-load pixels [S7].
- Parameter: $\lambda_{L1} + \lambda_{ssim}$: Sum of weights for remaining losses. Typical value: 0.55 [S7].

## Operating characteristics
- **Time Complexity:** $O(N \log N)$ for sorting, where $N$ is the number of Gaussians. Rasterization is $O(T \cdot P \cdot G_{avg})$, where $T$ is the number of tiles, $P$ is pixels per tile, and $G_{avg}$ is the average number of Gaussians per tile.
- **Memory Complexity:** $O(N + T)$ for storing Gaussian attributes and tile bins.
- **Performance:** Achieves real-time rendering speeds (e.g., >200 FPS) on modern GPUs [S1, unofficial].
- **Strengths:** High performance, differentiable, scalable to large scenes.
- **Limitations:** Memory usage can be high for very large scenes; sorting overhead can be significant for dynamic scenes.
- **When to use:** Real-time rendering and training of 3D Gaussian Splatting scenes.
- **When not to use:** Resource-constrained environments without GPU acceleration (use Mobile-GS [S1, unofficial] or CPU-sorted variants).

## Background
Originated with the 3D Gaussian Splatting paper [S1, unofficial], which introduced tile-based rasterization to achieve real-time rendering speeds. It has since been optimized in various ways, such as Speedy-Splat [S1, unofficial], Mobile-GS [S1, unofficial], and FlashGS [S1, unofficial]. It is widely used in 3D reconstruction, novel view synthesis, and real-time visualization of 3D scenes.
