# RoofGS Quadratic Form Expansion and Coefficient Folding

Also called: RoofGS coefficient folding, RoofGS exponent expansion

## Overview
RoofGS Quadratic Form Expansion and Coefficient Folding is a rasterization optimization that expands the Gaussian quadratic form to separate pixel-dependent terms from Gaussian-dependent terms, allowing pixel coordinates to be hoisted out of the primitive loop and reducing instruction overhead in the innermost rendering loop [S1, unofficial]. It sets itself apart from standard 3D Gaussian Splatting rasterization by pre-computing and folding opacity and scaling factors into the quadratic coefficients, enabling a streamlined FMA (Fused Multiply-Add) sequence for exponent evaluation [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:**
    *   Pixel coordinates $(x, y)$ for the current thread's target pixel(s).
    *   Gaussian parameters: projected mean $(u, v)$, inverse 2D covariance matrix elements $(a, b, c)$ where $\Sigma'^{-1} = \begin{pmatrix} a & b/2 \\ b/2 & c \end{pmatrix}$, and opacity $o \in (0, 1]$.
*   **Outputs:**
    *   Unclamped opacity contribution $\tilde{\alpha}(x, y)$.
    *   Final clamped opacity $\alpha(x, y)$ (via external blending step).

**Data Structures:**
*   **Folded Coefficients:** A set of 6 pre-computed coefficients $(C_1, \dots, C_6)$ derived from the Gaussian's $(a, b, c, u, v, o)$. These are stored in registers or shared memory for reuse across the primitive loop.
*   **Hoisted Coordinates:** Pixel terms $(x^2, xy, y^2, x, y)$ stored in registers, invariant across the primitive loop for a fixed pixel.

**Step-by-Step Method:**

1.  **Expand the Quadratic Form:**
    The baseline exponent $p(x, y)$ involves offsets $(x-u)$ and $(y-v)$. RoofGS expands the quadratic form $a(x - u)^2 + b(x - u)(y - v) + c(y - v)^2$ to separate variables [S1, unofficial]:
    $$
    a(x - u)^2 + b(x - u)(y - v) + c(y - v)^2 = ax^2 + bxy + cy^2 - (2au + bv)x - (2cv + bu)y + C_0
    $$
    where the constant term $C_0$ is:
    $$
    C_0 = au^2 + buv + cv^2
    $$

2.  **Fold Coefficients:**
    During the shared-memory loading stage, fold the constant factor $-0.5$ and the opacity term $\log o$ into the Gaussian coefficients to form $C_1$ through $C_6$ [S1, unofficial]:
    $$
    \begin{aligned}
    C_1 &= -0.5a \\
    C_2 &= -0.5b \\
    C_3 &= -0.5c \\
    C_4 &= au + 0.5bu \\
    C_5 &= cv + 0.5bu \\
    C_6 &= -0.5C_0 + \log o
    \end{aligned}
    $$
    *Note: The source defines $C_4$ and $C_5$ with specific linear combinations. Specifically, $C_4 = au + 0.5bu$ and $C_5 = cv + 0.5bu$ [S1, unofficial].*

3.  **Hoist Pixel Terms:**
    Since each active thread is assigned to a fixed pixel, compute and store the pixel-dependent terms $x^2, xy, y^2, x, y$ in registers. These remain invariant across all Gaussians processed by that thread [S1, unofficial].

4.  **Evaluate Folded Exponent:**
    For each Gaussian in the primitive list, evaluate the folded exponent $P(x, y)$ using a regular FMA sequence with the pre-folded coefficients [S1, unofficial]:
    $$
    P(x, y) = C_1 x^2 + C_2 xy + C_3 y^2 + C_4 x + C_5 y + C_6
    $$
    This formulation satisfies $P(x, y) = p(x, y) + \log o$, where $p(x, y)$ is the standard quadratic form exponent [S1, unofficial].

5.  **Compute Opacity:**
    Compute the unclamped opacity contribution directly from the folded exponent [S1, unofficial]:
    $$
    \tilde{\alpha}(x, y) = \exp(P(x, y))
    $$
    The final opacity used for alpha blending is clamped:
    $$
    \alpha(x, y) = \min(0.99, \tilde{\alpha}(x, y))
    $$

**Pseudocode:**
```python
def roofgs_coefficient_folding(u, v, a, b, c, o, x, y):
    """
    Computes the opacity contribution for a single Gaussian at pixel (x, y)
    using RoofGS coefficient folding.
    
    Args:
        u, v: Projected 2D Gaussian mean.
        a, b, c: Elements of the inverse 2D covariance matrix Sigma'^-1.
                 Sigma'^-1 = [[a, b/2], [b/2, c]]
        o: Learned Gaussian opacity (0 < o <= 1).
        x, y: Target pixel coordinates.
        
    Returns:
        alpha: Clamped opacity contribution.
    """
    # Step 1: Compute constant term C0
    C0 = a * u**2 + b * u * v + c * v**2
    
    # Step 2: Fold coefficients
    # Note: Source [S1, unofficial] defines C4 and C5 as:
    # C4 = au + 0.5bu
    # C5 = cv + 0.5bu
    C1 = -0.5 * a
    C2 = -0.5 * b
    C3 = -0.5 * c
    C4 = a * u + 0.5 * b * u
    C5 = c * v + 0.5 * b * u
    C6 = -0.5 * C0 + math.log(o)
    
    # Step 3: Hoist pixel terms (invariant for this thread)
    x2 = x * x
    xy = x * y
    y2 = y * y
    
    # Step 4: Evaluate folded exponent P(x, y)
    P = (C1 * x2 + 
         C2 * xy + 
         C3 * y2 + 
         C4 * x + 
         C5 * y + 
         C6)
         
    # Step 5: Compute unclamped and clamped opacity
    alpha_unclamped = math.exp(P)
    alpha = min(0.99, alpha_unclamped)
    
    return alpha
```

**Edge Cases and Pitfalls:**
*   **Opacity $o$:** Must be in $(0, 1]$. If $o=0$, $\log o$ is undefined. In practice, Gaussians with negligible opacity are culled.
*   **Precision:** The folding of $\log o$ into $C_6$ requires careful handling of floating-point precision, especially for very small opacities, to avoid underflow or loss of significance in the exponent [S1, unofficial].
*   **Coordinate Invariance:** The optimization assumes $(x, y)$ are fixed for the thread. If a thread processes multiple pixels (e.g., vertically adjacent pixels $(x, y)$ and $(x, y+1)$), the hoisted terms must be updated or recomputed for the second pixel, though the Gaussian coefficients remain reusable [S1, unofficial].

## Subtopics

### RoofGS Vertical Pixel Pairing
Exploits spatial coherence by assigning each thread to process two vertically adjacent pixels $(x, y)$ and $(x, y+1)$, reusing the same shared-memory attribute load and folded coefficients [S1, unofficial].

### 3D Gaussian Splatting Rasterization
The parent method that RoofGS optimizes. Standard rasterization recomputes offsets $(x-u)$ and $(y-v)$ for every primitive, introducing repeated subtraction and temporary register usage [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Reduces instruction count in the innermost loop by eliminating repeated coordinate subtractions and enabling efficient FMA sequences. The number of arithmetic operations per Gaussian per pixel is reduced.
*   **Memory Complexity:** Requires storage for 6 folded coefficients per Gaussian and 5 hoisted pixel terms per thread. No significant additional memory overhead compared to standard rasterization.
*   **Performance:** Improves instruction scheduling and reduces register pressure by hoisting invariant terms. Measured on hardware supporting efficient FMA operations. Specific performance metrics are not given in the sources.
*   **Strengths:** Reduced instruction overhead, better instruction scheduling, efficient use of registers.
*   **Limitations:** Requires careful handling of opacity folding and precision. Assumes fixed pixel assignment per thread.
*   **When to use:** When rendering 3D Gaussas with high throughput requirements and hardware supports efficient FMA operations.
*   **When not to use:** If pixel coordinates are not invariant within the primitive loop (e.g., dynamic pixel assignment).

## Background
RoofGS (Roofline-Guided End-to-End Acceleration of 3D Gaussian Splatting) was introduced in 2026 [S1, unofficial]. The quadratic form expansion and coefficient folding technique is a core optimization within RoofGS, designed to address the instruction overhead of standard Gaussian rasterization. It builds on the principles of 3D Gaussian Splatting [2812-3d-gaussian-splatting-rasterization.md] but focuses on low-level rendering loop optimization.
