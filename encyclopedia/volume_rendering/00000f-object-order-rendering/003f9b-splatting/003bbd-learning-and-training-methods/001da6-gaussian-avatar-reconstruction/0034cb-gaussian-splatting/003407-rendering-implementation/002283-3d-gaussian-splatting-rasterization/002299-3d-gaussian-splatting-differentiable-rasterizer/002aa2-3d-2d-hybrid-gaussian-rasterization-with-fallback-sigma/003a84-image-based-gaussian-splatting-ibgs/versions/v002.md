# Image-Based Gaussian Splatting (IBGS)

Also called: IBGS: Image-Based Gaussian Splatting

## Overview
Image-Based Gaussian Splatting (IBGS) is a novel view synthesis method that augments standard 3D Gaussian Splatting (3DGS) by predicting a color residual from neighboring training images to capture high-frequency details and view-dependent effects that low-degree spherical harmonics cannot represent [S1]. Unlike methods that attach per-Gaussian texture maps (high storage) or global texture maps (poor complex scene handling), IBGS uses a lightweight neural network to learn the difference between the base 3DGS rendering and the actual pixel colors observed in source views, maintaining the original storage footprint while significantly improving rendering quality [S1].

## How it works
IBGS decomposes the final pixel color into a base color rendered via standard 3DGS volume rendering and a learned residual derived from multi-view features [S1]. The method involves feature extraction from source views, residual prediction via a convolutional decoder, and optional exposure correction [S1].

### Inputs and Outputs
*   **Inputs:**
    *   3D Gaussian primitives (centers $\mu_i$, covariances $\Sigma_i$, opacities $o_i$, spherical harmonics coefficients $h_i$, and normal vectors $n_i$) [S1].
    *   Camera poses and intrinsics for the target view and $M$ neighboring source views [S1].
    *   Source images $C^m_{real}$ for $m \in \{1, \dots, M\}$ [S1].
*   **Outputs:**
    *   Final rendered image $C_{final} \in \mathbb{R}^{H \times W \times 3}$ [S1].

### Data Structures
*   **Gaussian Attributes:** Each Gaussian $i$ stores center $\mu_i \in \mathbb{R}^3$, covariance $\Sigma_i \in \mathbb{R}^{3 \times 3}$, opacity $o_i \in \mathbb{R}$, SH coefficients $h_i$ (degree $l=2$), and normal vector $n_i \in \mathbb{R}^3$ [S1].
*   **Feature Map:** $F \in \mathbb{R}^{H \times W \times 32}$, containing aggregated multi-view features per pixel [S1].
*   **Base Image:** $C \in \mathbb{R}^{H \times W \times 3}$, the result of standard 3DGS rasterization [S1].
*   **Ray Direction Map:** $D \in \mathbb{R}^{H \times W \times 3}$, containing camera ray directions for each pixel [S1].
*   **Residual Map:** $\Delta C \in \mathbb{R}^{H \times W \times 3}$, predicted by the decoder [S1].

### Parameters
*   $l$: Spherical Harmonics degree. Value: 2 [S1].
*   $K$: Number of median intersection points used for feature extraction. Value: 4 [S1].
*   $M$: Number of visible source views used as input. Value: 3 [S1].
*   $S$: Number of candidate source views (closest views) before visibility filtering. Value: 4 [S1].
*   $\tau$: Depth error threshold for visibility check. Value: 0.001 [S1].
*   $\beta$: Weight for L1 vs SSIM in loss. Value: 0.8 [S1].
*   $\gamma$: Weight balancing base image loss vs final image loss. Initial: 1, decreased to 0.5 in last 20,000 iterations [S1].
*   $\lambda_1, \lambda_2$: Loss weights for photometric and normal consistency. Value: 0 for first 7,000 iterations, then 0.3 and 0.03 respectively [S1].
*   Opacity prune threshold: 0.05 [S1].

### Steps

1.  **Base Color Rendering:** Compute the base color $c(p)$ for each pixel $p$ using standard 3DGS volume rendering [S1]:
    $$ c(p) = \sum_{i} w_i c_i $$
    where $w_i = \alpha_i T_i$, $T_i = \prod_{j=1}^{i-1} (1 - \alpha_j)$, $\alpha_i = o_i G_{2D}^i(p)$, and $c_i = \Psi_l(h_i, v_i)$ is the color of Gaussian $i$ evaluated at ray direction $v_i$ using SH degree $l$ [S1].

2.  **Median Intersection Selection:** To filter out floating Gaussians, select $K$ intersection points $\{x_k(p)\}_{k=1}^K$ where the accumulated transmittance $T_i$ is closest to 0.5 [S1].

3.  **Warping to Source Views:** For each selected intersection point $x_k(p)$ and each candidate source view $m$:
    *   Project $x_k(p)$ to the source view image plane using projection function $\pi_m$:
        $$ \text{coord}_{m} = \pi_m(x_k(p)) $$
    *   Bilinearly interpolate the color from the source image $C^m_{real}$:
        $$ c^{warp}_{k,m}(p) = B(\text{coord}_{m}, C^m_{real}) $$
        where $B(\cdot)$ is bilinear interpolation [S1].

4.  **Visibility Filtering:** Select the $M$ visible source views from the $S$ candidates based on depth consistency (threshold $\tau$) [S1].

5.  **Per-Pixel Feature Extraction:** For each visible source view $m \in \{1, \dots, M\}$:
    *   Compute the weighted average warped color:
        $$ c^{warp}_m(p) = \frac{\sum_{k=1}^K w_k c^{warp}_{k,m}(p)}{\sum_{k=1}^K w_k} $$
    *   Compute the appearance feature deviation:
        $$ \Delta c_m(p) = c^{warp}_m(p) - c(p) $$
    *   Define the camera feature $\Delta d_m(p) \in \mathbb{R}^4$ (derived from source view pose/direction) [S1].
    *   Process features through encoder $E$ (two linear layers, 32 output dim, ReLU):
        $$ f_m(p) = E(\Delta c_m(p), \Delta d_m(p)) $$
    *   Apply max-pooling across all $M$ views to get aggregated feature $\bar{f}(p) \in \mathbb{R}^{32}$ [S1].
    *   Assemble feature map $F \in \mathbb{R}^{H \times W \times 32}$ [S1].

6.  **Exposure Correction (Optional):** If applied (e.g., on Tanks and Temples), estimate an affine transformation $A^*$ from the nearest source view and correct the base color:
    $$ c^{expo}(p) = A^* c(p) $$
    If used, replace $c(p)$ with $c^{expo}(p)$ in subsequent steps [S1].

7.  **Residual Prediction:** Feed the base image $C$ (or $C^{expo}$), ray direction map $D$, and feature map $F$ into a nine-layer convolutional decoder $D(\cdot)$ with $3 \times 3$ kernels to predict the residual map $\Delta C$:
    $$ \Delta C = D(C, D, F) $$
    [S1].

8.  **Final Rendering:** Add the residual to the base image:
    $$ C_{final} = C + \Delta C $$
    [S1].

import numpy as np

def project_to_image_plane(intersections, view_pose, view_intrinsics):
    """Project 3D intersection points to 2D image coordinates of a source view."""
    # Transform to camera space: X_c = R * (X_w - t)
    X_c = view_pose.R @ intersections.T + view_pose.t
    # Project: u = K * X_c / Z
    coords = view_intrinsics.K @ X_c
    coords = coords[:2, :] / coords[2, :]
    return coords.T  # Shape: (N, 2)

def bilinear_interpolate(image, coords):
    """Bilinearly sample color from image at given (H, W, 2) coordinates."""
    h, w, _ = image.shape
    u = np.clip(coords[:, 0], 0, w - 1)
    v = np.clip(coords[:, 1], 0, h - 1)
    u0, v0 = np.floor(u).astype(int), np.floor(v).astype(int)
    u1, v1 = u0 + 1, v0 + 1
    w_u, w_v = u - u0, v - v0
    # Interpolate
    val = (1 - w_u) * (1 - w_v) * image[v0, u0] + \
          w_u * (1 - w_v) * image[v0, u1] + \
          (1 - w_u) * w_v * image[v1, u0] + \
          w_u * w_v * image[v1, u1]
    return val  # Shape: (N, 3)

def select_median_indices(transmittance, K):
    """Select K indices per pixel where transmittance is closest to 0.5."""
    # transmittance shape: (H, W, N)
    diff = np.abs(transmittance - 0.5)
    # Get indices of K smallest differences
    indices = np.argpartition(diff, K, axis=-1)[:, :, :K]

class IBGS:
    def __init__(self, K=4, M=3, S=4, tau=0.001, l=2):
        self.K = K
        self.M = M
        self.S = S
        self.tau = tau
        self.l = l
        # Encoder: 2 linear layers, 32 output dim, ReLU
        self.encoder_W1 = np.random.randn(7, 32)
        self.encoder_b1 = np.zeros(32)
        self.encoder_W2 = np.random.randn(32, 32)
        self.encoder_b2 = np.zeros(32)
        # Decoder: 9-layer CNN, 3x3 kernels, input channels: 38, output: 3
        self.decoder_weights = [np.random.randn(32, 38, 3, 3) if i == 0 else np.random.randn(32, 32, 3, 3) for i in range(9)]
        self.decoder_bias = [np.zeros(32) for _ in range(9)]
        self.decoder_out_W = np.random.randn(3, 32, 3, 3)
        self.decoder_out_b = np.zeros(3)

    def encoder_forward(self, x):
        # x: (H, W, 7)
        x = np.tanh(x @ self.encoder_W1 + self.encoder_b1)
        x = np.tanh(x @ self.encoder_W2 + self.encoder_b2)

        x = np.transpose(x, (0, 2, 1))

        x = np.transpose(x, (0, 2, 3, 1))

        warped_colors = []

            colors = bilinear_interpolate(source_views[m].image, coords)

        warped_colors = np.stack(warped_colors, axis=2)  # (H, W, M, K, 3)

                         np.sum(weights[:, median_indices], axis=3).reshape(weights.shape[0], weights.shape[1], 1)

            delta_d = compute_camera_feature(m, ray_dirs)
            f_m = self.encoder_forward(np.concatenate([delta_c, delta_d], axis=-1))
            features.append(f_m)

        input_tensor = np.concatenate([C, D_map, F], axis=-1)
        delta_C = self.decoder_forward(input_tensor)
        
        # 7. Final rendering
        C_final = C + delta_C
        return C_final, C, delta_C

## Operating characteristics
*   **Time Complexity:** Dominated by the standard 3DGS rasterization and the lightweight 9-layer CNN decoder [S1]. The feature extraction involves projecting $K$ points to $M$ views, which is negligible compared to rasterization for typical $K=4, M=3$ [S1].
*   **Memory Complexity:** Storage footprint is identical to standard 3DGS (Gaussians + SH coefficients) [S1]. The neural network weights are small and not stored per-Gaussian [S1].
*   **Performance:** Significantly outperforms prior Gaussian Splatting approaches in rendering quality (PSNR, SSIM) on benchmarks like Tanks and Temples, Deep Blending, and Mip-NeRF360, without increasing storage [S1].
*   **Strengths:** Captures high-frequency details and view-dependent effects (specular highlights, reflections) that low-degree SH ($l \le 3$) misses, without the storage overhead of per-Gaussian textures [S1].
*   **Limitations:** Requires access to neighboring training images for feature extraction [S1]. Performance depends on the quality of multi-view correspondences [S1]. Auto-exposure settings in cameras can cause inconsistent brightness across views, introducing noise into Gaussian optimization if uncorrected [S1].
*   **When to use:** When high-fidelity novel view synthesis is required, especially for scenes with complex lighting or fine textures, and storage is constrained [S1].
*   **When not to use:** If source views are not available or have poor overlap/visibility with the target view [S1].

## Background
IBGS was proposed by Hoang Chuong Nguyen, Wei Mao, Jose M. Alvarez, and Miaomiao Liu from the Australian National University and NVIDIA [S1]. It was published on arXiv in November 2025 [S1]. The method addresses the limitations of 3DGS, which uses low-degree spherical harmonics to model view-dependent color, limiting its ability to capture spatially varying color and effects like specular highlights [S1]. Previous attempts to augment Gaussians with texture maps either struggled with complex scenes (global maps) or introduced high storage overhead (per-Gaussian maps) [S1]. IBGS leverages image-based rendering principles to "borrow" pixels from source views, modeling the residual color to supplement the base 3DGS rendering [S1].
