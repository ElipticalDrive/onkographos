# Ref-Gaussian Deferred Surfel Rendering with Split-Sum IBL

Also called: MetalGaussianSplatRelighting, Ref-Gaussian, Ref-Gaussian on iOS

## Overview
Ref-Gaussian is a physically based rendering (PBR) method for novel view synthesis and relighting of reflective objects using 2D Gaussian primitives [S1, S2, unofficial]. It solves the problem of blurred reflective details and incorrect lighting in standard Gaussian Splatting by decomposing splats into PBR material attributes (albedo, normal, roughness, reflectance) and computing lighting via a deferred shading pipeline with split-sum environment map integration [S2, unofficial]. It differs from sibling methods like 3DGS-DR by using full PBR with spherical harmonics for diffuse fitting rather than simplified shading functions, and by employing deferred rendering to prevent the blurring of reflective details inherent in per-Gaussian shading [S1, unofficial].

## How it works

### Inputs and Outputs
**Inputs:**
*   A `.ply` file containing 2D Gaussian primitives. Each primitive stores geometry (position, covariance/orientation, scale) and trainable material attributes: normal $\mathbf{N}$, roughness $r$, reflectance $R$ (specular strength), and albedo $\mathbf{C}_{diff}$ [S1, S2, unofficial].
*   An HDR environment map (equirectangular or cubemap) representing the lighting [S2, unofficial].
*   Camera parameters (view and projection matrices) [S1, S2, unofficial].

**Outputs:**
*   A final color image $C_{final}$ and depth buffer [S1, S2, unofficial].

### Data Structures
The method relies on two parallel buffers aligned by splat index:
1.  **Splat Buffer:** Contains screen-space positions, projected covariance matrices, opacities, and colors (if used for initialization) [S1, S2, unofficial].
2.  **Material Buffer:** Contains per-splat material attributes: normal vector $\mathbf{N}$, roughness scalar $r$, reflectance scalar $R$, and albedo vector $\mathbf{C}_{diff}$ [S2, unofficial].

**Pre-computed IBL Data:**
*   **Prefiltered Environment Map:** A mipmapped texture where each level corresponds to a specific roughness, storing specular reflections [S2, unofficial].
*   **Irradiance Map:** A pre-filtered environment map for diffuse lighting [S2, unofficial].
*   **BRDF LUT:** A 2D lookup table storing the Fresnel-G term components $fg.x$ and $fg.y$ based on roughness and dot product of normal and view direction [S2, unofficial].

### Training Procedure
Training occurs in two stages [S1, unofficial]:
1.  **Initial Stage (18,000 steps):** Per-Gaussian rendering is used to optimize geometry and initial material attributes.
2.  **Deferred Rendering Stage (40,000 steps):** All color and material attributes are reset, retaining only the geometry of the Gaussians. Training resumes with deferred rendering [S1, unofficial].

**Loss Function:**
The objective function is:
$$ L = L_c + \lambda_n L_n + \lambda_{smooth} L_{smooth} $$
Where:
*   $L_c = (1 - \lambda)L_1 + \lambda L_{D-SSIM}$ is the RGB reconstruction loss, with balancing weight $\lambda = 0.2$ [S1, unofficial].
*   $L_n = 1 - \tilde{\mathbf{N}}^T \mathbf{N}$ is the normal consistency loss, encouraging alignment between the rendered normal $\mathbf{N}$ (obtained via alpha-blending) and the surface normal $\tilde{\mathbf{N}}$ derived from the depth map [S1, unofficial].
*   $L_{smooth} = \|\nabla \mathbf{N}\| \exp(-\|\nabla C_{gt}\|)$ is an edge-aware normal smoothness loss, regularizing normal variation in low-texture regions [S1, unofficial].

**Parameters:**
*   Learning rate for trainable material attributes (metallic, roughness, albedo): 0.005 [S1, unofficial].
*   Learning rate for the environment map: 0.01 [S1, unofficial].
*   $\lambda_n = 0.05$ [S1, unofficial].
*   $\lambda_{smooth} = 1.0$ [S1, unofficial].
*   Initial roughness: 0.1 [S1, unofficial].
*   Initial metallic: Adopted from 3DGS-DR (exact value not specified in sources) [S1, unofficial].
*   Material-aware normal propagation is applied to Gaussians with metallic $\ge 0.02$ and roughness $\le 0.1$ [S1, unofficial].
*   Surface mesh extraction occurs every 3,000 steps [S1, unofficial].

### Rendering Pipeline (Deferred Surfel)
The rendering process uses a deferred shading approach to compute lighting [S2, unofficial]:

1.  **G-Buffer Pass:**
    *   Project 2D Gaussians to screen space.
    *   Sort splats using Morton codes for cache locality [S2, unofficial].
    *   **Crucial Step:** Apply the same sort indices to the Material Buffer to prevent desynchronization [S2, unofficial].
    *   Rasterize splats into a G-Buffer (tile memory), storing position, normal, roughness, reflectance, and albedo [S2, unofficial].

2.  **Shading Pass (Split-Sum IBL):**
    For each pixel, retrieve material attributes from the G-Buffer and compute the final color using the following formulas [S2, unofficial]:

    *   **Base Specular Reflectivity ($F_0$):**
        $$ F_0 = 0.04 \times (1 - R) + \mathbf{C}_{diff} \times R $$
        Where $R$ is the learned reflectance and $\mathbf{C}_{diff}$ is the albedo [S2, unofficial].

    *   **Specular Term:**
        $$ \text{specular} = \text{prefiltered}(\text{reflect}(\mathbf{V}, \mathbf{N}), r) \times (F_0 \cdot fg.x + fg.y) $$
        Where $\mathbf{V}$ is the view direction, $\mathbf{N}$ is the normal, $r$ is roughness, $\text{reflect}(\mathbf{V}, \mathbf{N})$ is the reflection vector, $\text{prefiltered}(\cdot, r)$ samples the prefiltered environment map at the mip level corresponding to roughness, and $fg$ is the result from the BRDF LUT [S2, unofficial].

    *   **Final Color:**
        $$ \text{final} = (1 - R) \times \mathbf{C}_{diff} + \text{specular} $$
        Note: The diffuse component uses the base albedo $\mathbf{C}_{diff}$ directly, without multiplying by the irradiance map [S2, unofficial].

def render_ref_gaussian(splats, camera, env_map):
    """
    Renders a scene using Ref-Gaussian deferred surfel rendering.
    
    Args:
        splats: List of Gaussian primitives with attributes:
                - pos: (3,) position
                - cov: (3,3) covariance matrix
                - N: (3,) normal vector
                - roughness: float
                - reflectance: float
                - albedo: (3,) color vector
        camera: Camera object with view_proj matrix and view direction function
        env_map: Environment map object with methods:
                - prefilter(view_dir, roughness) -> color
                - sample_irradiance(normal) -> color (unused in final formula per S2)
                - brdf_lut(roughness, cos_theta) -> (fg_x, fg_y)
    
    Returns:
        image: (H, W, 3) rendered color buffer
    """
    H, W = camera.resolution
    
    # 1. Project and Sort
    # Project 3D Gaussians to 2D screen space ellipses
    projected_splats = []
    for s in splats:
        # Standard 2DGS projection logic [S1, unofficial]
        # Compute 2D covariance, screen position, and depth
        proj = project_gaussian_2d(s, camera)
        projected_splats.append(proj)
    
    # Sort by Morton code for cache locality
    # Generate Morton codes from screen coordinates
    morton_codes = [compute_morton(p.x, p.y) for p in projected_splats]
    sorted_indices = argsort(morton_codes)
    
    # Apply sort to both geometry and material buffers to prevent desynchronization [S2, unofficial]
    sorted_splats = [projected_splats[i] for i in sorted_indices]
    
    # 2. Rasterize G-Buffer
    # Initialize G-Buffer with depth and material attributes
    gbuffer_depth = np.full((H, W), np.inf)
    gbuffer_normal = np.zeros((H, W, 3))
    gbuffer_roughness = np.zeros((H, W))
    gbuffer_reflectance = np.zeros((H, W))
    gbuffer_albedo = np.zeros((H, W, 3))
    
    for s in sorted_splats:
        if s.depth > gbuffer_depth[s.x, s.y]:
            continue
        
        # Rasterize the 2D Gaussian ellipse
        # For each pixel covered by the ellipse:
        for pixel in s.covered_pixels:
            # Compute alpha based on 2D Gaussian PDF
            alpha = compute_alpha(s, pixel)
            
            # Store material attributes
            gbuffer_normal[pixel.x, pixel.y] = s.N
            gbuffer_roughness[pixel.x, pixel.y] = s.roughness
            gbuffer_reflectance[pixel.x, pixel.y] = s.reflectance
            gbuffer_albedo[pixel.x, pixel.y] = s.albedo
            gbuffer_depth[pixel.x, pixel.y] = s.depth
            
    # 3. Shading Pass (Split-Sum IBL)
    image = np.zeros((H, W, 3))
    
    for y in range(H):
        for x in range(W):
            N = gbuffer_normal[y, x]
            r = gbuffer_roughness[y, x]
            R = gbuffer_reflectance[y, x]
            C_diff = gbuffer_albedo[y, x]
            
            # Skip if no splat covered this pixel
            if np.all(N == 0):
                continue
                
            # Compute view direction for this pixel
            V = camera.get_view_direction(x, y)
            
            # Compute F0
            # F0 = 0.04 * (1 - reflectance) + albedo * reflectance [S2, unofficial]
            F0 = 0.04 * (1 - R) + C_diff * R
            
            # Compute Specular
            # reflect(V, N) computes the reflection vector
            R_dir = reflect(V, N)
            
            # Sample prefiltered environment map based on roughness
            # prefiltered returns the specular color from the environment
            env_specular = env_map.prefilter(R_dir, r)
            
            # Sample BRDF LUT
            # cos_theta is the dot product of N and V (or similar, depending on LUT definition)
            # Assuming standard GGX BRDF LUT inputs: roughness and cos_theta
            cos_theta = np.dot(N, V)
            fg_x, fg_y = env_map.brdf_lut(r, cos_theta)
            
            specular = env_specular * (F0 * fg_x + fg_y)
            
            # Compute Final Color
            # final = (1 - reflectance) * base_color + specular [S2, unofficial]
            # Note: Diffuse is base_color directly, not multiplied by irradiance [S2, unofficial]
            final = (1 - R) * C_diff + specular
            
            image[y, x] = final
            
    return image

### Edge Cases and Pitfalls
*   **Normal Map Noise:** If splats are sorted (e.g., by Morton code) but the material buffer is not sorted in parallel, normals become misaligned with positions, causing rainbow noise [S2, unofficial]. Fix: Apply the same sort indices to the material buffer [S2, unofficial].
*   **Incorrect Diffuse Lighting:** Do not multiply albedo by the irradiance map for diffuse color. Ref-Gaussian uses `base_color` directly for diffuse. Only specular is computed from the environment map [S2, unofficial].
*   **Coordinate System Mismatch:** If scene data is Z-up (e.g., Blender) but the viewer assumes Y-up, objects appear rotated 90 degrees. Fix: Apply a -90° rotation around the X-axis to the camera/view matrix and adjust environment map sampling directions [S2, unofficial].
*   **Stale Binary Execution:** On iOS, if the build fails due to type errors (e.g., `Float16` bitPattern mismatch between arm64 and x86_64 simulator), the device may run an old binary. Always check build success for the target platform before debugging logic [S2, unofficial].
*   **Geometric Collapse:** Smooth surfaces are prone to geometric collapse. Material-aware normal propagation addresses this by propagating normals to adjacent Gaussians with metallic $\ge 0.02$ and roughness $\le 0.1$ [S1, unofficial].
*   **Blurring:** Per-Gaussian rendering causes reflective details to become noticeably more blurred. Deferred rendering is used to mitigate this [S1, unofficial].

## Operating characteristics

**Time and Memory Complexity:**
*   Training time on the Shiny Blender dataset is approximately 0.58 hours [S1, unofficial].
*   Rendering performance is 122 FPS on a single NVIDIA A6000 GPU [S1, unofficial].
*   The deferred rendering pipeline adds complexity to the shading pass but improves visual quality by avoiding per-Gaussian shading blurring [S1, unofficial].

**Measured Performance:**
*   On the Shiny Blender dataset, Ref-Gaussian achieves PSNR 30.33, SSIM 0.958, and LPIPS 0.049 [S1, unofficial].
*   Geometry metrics: MAE 2.15, Normal SSIM 0.954, Normal LPIPS 0.0511 [S1, unofficial].
*   Environment map quality: Envmap LPIPS 0.4431 [S1, unofficial].

**Scaling:**
*   The method uses 2D Gaussian primitives for precise geometric representation, avoiding the conflict of 3D Gaussian volumetric radiance with the thin nature of surfaces [S1, unofficial].
*   Spherical harmonics are used for diffuse lighting fitting, which has better fitting capability than integrated diffuse lighting [S1, unofficial].

**Strengths and Limitations:**
*   **Strengths:** Real-time relighting on mobile devices (iPhone via Metal) [S2, unofficial], high-quality reflective novel view synthesis, accurate geometry reconstruction [S1, unofficial].
*   **Limitations:** Requires deferred rendering pipeline, sensitive to material buffer synchronization [S2, unofficial], coordinate system mismatches can cause visual artifacts [S2, unofficial].

**When to Use:**
*   Use for relighting reflective objects in real-time applications, especially on mobile platforms [S2, unofficial].
*   Use when high-fidelity geometry and material reconstruction are required [S1, unofficial].

**When Not to Use:**
*   Avoid if simple, non-reflective scenes are sufficient, as the complexity of PBR and deferred rendering is unnecessary [S1, unofficial].
*   Avoid if coordinate system consistency cannot be guaranteed [S2, unofficial].

## Background

**Origin:**
Ref-Gaussian was introduced in the paper "Reflective Gaussian Splatting" [S1, unofficial]. It builds upon 2D Gaussian Splatting (2DGS) [S1, unofficial] and incorporates physically based rendering (PBR) techniques.

**History and Development:**
The method was developed to address the limitations of standard Gaussian Splatting in representing reflective surfaces. It uses a two-stage training process and deferred rendering to improve the quality of reflective details [S1, unofficial]. The implementation details for mobile devices (iOS/Metal) have been documented in unofficial sources [S2, unofficial].

**Usage:**
Ref-Gaussian has been evaluated on synthetic datasets (Shiny Blender, Glossy Synthetic) and real-world open scenes (Ref-Real) [S1, unofficial]. It is used for novel view synthesis, geometry reconstruction, and relighting [S1, unofficial].
