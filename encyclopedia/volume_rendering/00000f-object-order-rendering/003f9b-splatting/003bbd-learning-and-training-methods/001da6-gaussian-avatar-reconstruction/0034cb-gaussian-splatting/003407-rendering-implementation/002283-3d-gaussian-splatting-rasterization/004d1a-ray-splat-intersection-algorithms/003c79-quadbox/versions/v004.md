# QuadBox


## Overview
QuadBox is a Gaussian-tile intersection method that uses four axis-aligned bounding boxes (AABBs) to tightly encapsulate projected 2D Gaussians, reducing tile over-approximation and redundant computations in the rasterizer preprocess stage [S1]. It sets itself apart from its siblings by replacing the single conservative AABB (used in standard 3DGS and AdR-Gaussian) with four adaptive sub-boxes that follow the ellipse's major axis and are geometrically stretched to fit the minor axis, combined with a branch-free single-pass traversal algorithm (QPass) [S1].

## How it works
QuadBox operates in two main phases: **QuadBox Construction** (preprocessing) and **QPass** (tile traversal). The method determines which tiles a Gaussian primitive overlaps by approximating its elliptical support region with four axis-aligned boxes.

### Inputs and Outputs
*   **Inputs**:
    *   Gaussian primitive $i$ with 2D center $\mu_i^{2D}$, 2D covariance $\Sigma_i^{2D}$, and opacity $\theta_i$.
    *   Image resolution and tile size (typically $16 \times 16$ pixels) [S1].
    *   Opacity threshold $\alpha_{\min}$ (typically $1/255$) [S1].
*   **Outputs**:
    *   A list of tile coordinates $(t_x, t_y)$ that intersect the Gaussian's support region.

### Data Structures
The core data structure is the **QuadBox**, consisting of four AABBs. Each AABB is defined by its minimum and maximum coordinates in screen space $(x_{min}, y_{min}, x_{max}, y_{max})$. These coordinates are derived algebraically from the inverse covariance matrix $\Lambda = (\Sigma_i^{2D})^{-1}$ [S1].

### Step-by-Step Method

#### Phase 1: Initialization
1.  **Opacity Filtering**: Filter out Gaussians where the splatted opacity $\alpha < \alpha_{\min}$. This ensures numerical stability and reduces computational load [S1].
2.  **Confidence Inequality**: Define the support region of the Gaussian using the confidence inequality [S1]:
    $$ 2 \ln\left(\frac{\theta_i}{\alpha_{\min}}\right) \leq (u - \mu_i^{2D})(\Sigma_i^{2D})^{-1}(u - \mu_i^{2D})^\top $$
    Let $\Lambda = (\Sigma_i^{2D})^{-1} = \begin{bmatrix} a & b \\ b & c \end{bmatrix}$ and define centered coordinates $(x_d, y_d) = u - \mu_i^{2D}$. The region is defined by the ellipse equation [S1]:
    $$ F(x_d, y_d) = ax_d^2 + 2bx_dy_d + cy_d^2 - \gamma \leq 0 $$
    where $\gamma = 2 \ln\left(\frac{\theta_i}{\alpha_{\min}}\right)$ [S1].

#### Phase 2: DualBox Extraction
1.  **Major Axis Alignment**: Instead of using a single AABB that covers the entire bounding box of the ellipse (which includes significant empty space along the minor axis for anisotropic Gaussians), extract a **DualBox** [S1].
2.  **Quadrant Selection**: Retain only the two quadrants of the AdR-AABB that are aligned with the ellipse's major axis. This suppresses empty tile coverage along the minor axis [S1].

#### Phase 3: Adaptive Stretching (QuadBox Construction)
To cover the parts of the ellipse not included in the DualBox, the remaining two quadrants are adaptively stretched [S1].

1.  **Compute Axis Intercepts**: Calculate the intercepts of the ellipse with the local axes by setting $x_d=0$ and $y_d=0$ in the ellipse equation [S1]:
    $$ y_{\text{inter}} = \sqrt{\gamma/c}, \quad x_{\text{inter}} = \sqrt{\gamma/a} $$
2.  **Compute Maximal Extents**: Calculate the maximal support along the axes using the inverse matrix $\Lambda^{-1}$ [S1]:
    $$ y_{\max} = \sqrt{\frac{\gamma a}{ac - b^2}}, \quad x_{\max} = \sqrt{\frac{\gamma c}{ac - b^2}} $$
    *Derivation*: The maximal support in direction $v$ is $\sqrt{\gamma v^\top \Lambda^{-1} v}$. For $v=e_y=(0,1)^\top$ and $v=e_x=(1,0)^\top$, and using $\Lambda^{-1} = \frac{1}{ac - b^2} \begin{bmatrix} c & -b \\ -b & a \end{bmatrix}$, we obtain the above formulas [S1].
3.  **Compute Stretching Factor $f$**: Derive a purely algebraic closed form for the stretching factor to avoid expensive square roots and divisions during runtime [S1]:
    $$ f = \frac{y_{\text{inter}}}{y_{\max}} = \sqrt{1 - \frac{b^2}{ac}} $$
    This factor depends only on the entries of $\Lambda$ and is independent of $\gamma$ and center translation. It satisfies $0 < f \leq 1$ [S1].
4.  **Construct QuadBox**: Apply the stretching factor $f$ to the extents of the sub-boxes in the minor axis directions to tightly fit the ellipse while maintaining axis-alignment [S1].

#### Phase 4: QPass (Tile Traversal)
A naive iteration over the four sub-boxes causes redundant tile checks and warp divergence. QPass aggregates these into a single pass [S1].

1.  **Global Tile Range**: Compute the global tile range covering all four QuadBox sub-boxes using simple integer divisions based on the QuadBox bounds [S1].
2.  **Scanline Aggregation**: For each scanline (row of tiles) within the global range:
    *   Aggregate the active tile interval by performing fast min/max tests over the intersecting sub-boxes [S1].
3.  **Tile Intersection Check**: For each tile in the aggregated range, perform a simple interval test (integer comparison) to determine if the tile is covered. This ensures each tile is visited exactly once [S1].

### Pseudocode

```python
def quadbox_rasterize(gaussian, tile_size=16, alpha_min=1/255):
    """
    Rasterize a single 3D Gaussian primitive using the QuadBox method.
    
    Args:
        gaussian: Object containing center (mu_2d), covariance (Sigma_2D), and opacity (theta).
        tile_size: Size of tiles in pixels (default 16).
        alpha_min: Opacity threshold for filtering (default 1/255).
        
    Returns:
        List of tile coordinates (tx, ty) intersecting the Gaussian.
    """
    # Phase 1: Initialization
    # Calculate splatted opacity at center to check threshold
    # Note: In practice, opacity varies across the tile. 
    # The source uses the global opacity theta_i for the threshold check [S1].
    if gaussian.opacity < alpha_min:
        return []

    # Extract 2D covariance inverse Lambda
    Sigma_2D = gaussian.covariance_2d
    Lambda = inverse_2x2_symmetric(Sigma_2D)
    a, b, c = Lambda[0,0], Lambda[0,1], Lambda[1,1]
    
    # Calculate gamma from confidence inequality
    # 2 * ln(theta / alpha_min)
    gamma = 2.0 * math.log(gaussian.opacity / alpha_min)
    
    # Phase 2 & 3: QuadBox Construction
    # Compute stretching factor f (purely algebraic)
    # f = sqrt(1 - b^2 / (a*c))
    # Guard against division by zero or negative due to numerical error
    denom = a * c
    if denom <= 0:
        return [] # Degenerate covariance
    
    f_sq = 1.0 - (b * b) / denom
    if f_sq < 0:
        f_sq = 0.0
    f = math.sqrt(f_sq)
    
    # Compute maximal extents
    # y_max = sqrt(gamma * a / (a*c - b^2))
    # x_max = sqrt(gamma * c / (a*c - b^2))
    det = a * c - b * b
    if det <= 0:
        return [] # Singular matrix
        
    y_max = math.sqrt(gamma * a / det)
    x_max = math.sqrt(gamma * c / det)
    
    # Determine the four sub-boxes relative to center
    # The DualBox keeps the two quadrants aligned with the major axis.
    # The other two are stretched by f.
    # For simplicity, we define the bounds of the 4 boxes.
    # Let the ellipse be centered at (0,0) in local coords.
    # Quadrants: (+,+), (+,-), (-,+), (-,-)
    # We need to determine which axis is major to apply DualBox logic correctly.
    # However, the source describes a symmetric construction where f adapts the minor axis coverage.
    # A robust implementation computes the bounding box of the ellipse in each quadrant.
    
    # Simplified approach based on source description:
    # The QuadBox consists of 4 AABBs.
    # We compute the bounding box of the ellipse segment in each quadrant.
    # For a quadrant, the bounds are determined by the intercepts and the maximal extent.
    
    # Intercepts
    x_inter = math.sqrt(gamma / a)
    y_inter = math.sqrt(gamma / c)
    
    # The QuadBox bounds are derived from x_max, y_max and f.
    # Specifically, the extent in the minor axis direction is scaled by f.
    # Let's assume standard orientation for derivation, then rotate if needed.
    # But Lambda already encodes rotation. The algebraic form handles this.
    
    # Construct the 4 AABBs in screen space
    # Center
    cx, cy = gaussian.center_2d
    
    # The source implies the boxes are symmetric around the center.
    # We define the half-widths and half-heights for the 4 boxes.
    # Box 1 (Top-Right): x in [0, x_max], y in [0, y_max_stretched]
    # Box 2 (Top-Left): x in [-x_max, 0], y in [0, y_max_stretched]
    # Box 3 (Bottom-Right): x in [0, x_max], y in [-y_max_stretched, 0]
    # Box 4 (Bottom-Left): x in [-x_max, 0], y in [-y_max_stretched, 0]
    
    # Note: The "DualBox" logic selects 2 quadrants fully, and stretches the other 2.
    # The source states: "Retain only the two quadrants... aligned with the major axis".
    # And "QuadBox adds adaptively stretched sub-boxes to cover the minor axis".
    # This implies the 4 boxes are:
    # 2 boxes along major axis (full extent)
    # 2 boxes along minor axis (stretched extent)
    
    # To implement this without explicit eigen-decomposition:
    # The stretching factor f applies to the axis perpendicular to the one being "full".
    # Actually, the formula f = sqrt(1 - b^2/ac) is derived from the ratio of intercept to max extent.
    # This ratio is constant for both axes if we consider the geometry correctly.
    
    # Let's define the 4 boxes based on the global x_max and y_max.
    # The QuadBox is the union of 4 AABBs.
    # Box 1: [cx, cx + x_max], [cy, cy + y_max * f]  (if y is minor)
    # This requires knowing which axis is minor.
    # If a < c, x-axis is major (larger extent). If a > c, y-axis is major.
    
    # Determine major axis
    # Extent along x is proportional to sqrt(c/det), along y to sqrt(a/det)
    # So if c > a, x-extent > y-extent.
    
    if c > a:
        # X is major axis
        # Boxes 1 & 2 (Top/Bottom) cover full X, stretched Y
        # Boxes 3 & 4 (Left/Right) cover stretched X, full Y? 
        # Source says: "Retain only the two quadrants... aligned with major axis"
        # This means the boxes covering the major axis direction are "full".
        # The boxes covering the minor axis direction are "stretched".
        
        # Quadrants aligned with Major Axis (X): Top-Right and Bottom-Right? 
        # No, "aligned with" usually means the box extends along that axis.
        # Let's assume the 4 boxes are:
        # 1. Top-Right: x>0, y>0
        # 2. Top-Left: x<0, y>0
        # 3. Bottom-Right: x>0, y<0
        # 4. Bottom-Left: x<0, y<0
        
        # If X is major, the "major axis" runs horizontally.
        # The DualBox retains the two quadrants aligned with the major axis.
        # This likely means the boxes that are long in X.
        # All 4 boxes are long in X? No.
        
        # Re-reading: "Retain only the two quadrants of the AdR-AABB aligned with the ellipse's major axis."
        # AdR-AABB is the bounding box of the ellipse.
        # Splitting it along the major axis gives 2 halves.
        # Then QuadBox adds stretched sub-boxes for the minor axis parts.
        
        # Implementation detail from source:
        # The final QuadBox is 4 boxes.
        # We can compute the bounding box of the ellipse in each of the 4 quadrants.
        # For quadrant (sx, sy) where sx, sy in {-1, 1}:
        # x range: [0, sx * x_max]
        # y range: [0, sy * y_max_stretched]
        # where y_max_stretched = y_max * f?
        
        # Let's use the derived f.
        # The source says f is the ratio y_inter / y_max.
        # This suggests that for the "minor" direction, the extent is scaled by f.
        
        # Let's define the 4 boxes simply as:
        # Box 1: [cx, cx + x_max], [cy, cy + y_max * f]
        # Box 2: [cx - x_max, cx], [cy, cy + y_max * f]
        # Box 3: [cx, cx + x_max], [cy - y_max * f, cy]
        # Box 4: [cx - x_max, cx], [cy - y_max * f, cy]
        
        # This covers the ellipse tightly in the minor axis direction (Y)
        # and fully in the major axis direction (X).
        # If Y is major, we swap roles.
        
        pass # Logic handled below
    
    # Generalized Box Construction
    # Determine which axis is major
    # Extent_x ~ sqrt(c), Extent_y ~ sqrt(a)
    major_is_x = (c > a)
    
    if major_is_x:
        # X is major. Y is minor.
        # Boxes cover full X extent, stretched Y extent.
        x_half = x_max
        y_half = y_max * f
    else:
        # Y is major. X is minor.
        # Boxes cover full Y extent, stretched X extent.
        x_half = x_max * f
        y_half = y_max
        
    # Define the 4 AABBs
    boxes = [
        (cx, cy + y_half, cx + x_half, cy), # Top-Right
        (cx - x_half, cy + y_half, cx, cy), # Top-Left
        (cx, cy, cx + x_half, cy - y_half), # Bottom-Right
        (cx - x_half, cy, cx, cy - y_half)  # Bottom-Left
    ]
    
    # Phase 4: QPass
    # Compute global tile range
    # Convert box coordinates to tile coordinates
    # Tile tx = floor(x / tile_size)
    
    min_tx = min(floor(b[0] / tile_size) for b in boxes)
    max_tx = max(floor(b[2] / tile_size) for b in boxes)
    min_ty = min(floor(b[3] / tile_size) for b in boxes)
    max_ty = max(floor(b[1] / tile_size) for b in boxes)
    
    tiles = []
    
    # Scanline aggregation
    # For each tile row
    for ty in range(min_ty, max_ty + 1):
        # Aggregate active tile interval for this row
        # Find min and max tx for this ty across all 4 boxes
        row_min_tx = infinity
        row_max_tx = -infinity
        
        for (x1, y1, x2, y2) in boxes:
            # Check if box intersects this tile row
            # Box y range: [y2, y1] (assuming y1 > y2)
            # Tile y range: [ty * tile_size, (ty+1) * tile_size]
            
            # Simple overlap check
            if y2 < (ty + 1) * tile_size and y1 > ty * tile_size:
                # Box intersects this row
                # Compute tile x range for this box in this row
                # Since boxes are axis aligned, the x range is constant for the whole box
                tx1 = floor(x1 / tile_size)
                tx2 = floor(x2 / tile_size)
                
                if tx1 < row_min_tx:
                    row_min_tx = tx1
                if tx2 > row_max_tx:
                    row_max_tx = tx2
        
        # Perform tile intersection check for the aggregated range
        for tx in range(row_min_tx, row_max_tx + 1):
            tiles.append((tx, ty))
            
    return tiles

def inverse_2x2_symmetric(M):
    a, b = M[0,0], M[0,1]
    c = M[1,1]
    det = a * c - b * b
    if det == 0:
        raise ValueError("Singular matrix")
    return [[c/det, -b/det], [-b/det, a/det]]
```

### Parameters
*   **Opacity Threshold ($\alpha_{\min}$)**: Gaussians with splatted opacity below this value are ignored. Typical value: $1/255$ [S1].
*   **Tile Size**: The image plane is partitioned into $16 \times 16$ tiles [S1].

### Edge Cases and Pitfalls
*   **Numerical Stability**: Gaussians with very low opacity can cause instability. Handled by filtering Gaussians with opacity $\alpha < \alpha_{\min}$ [S1].
*   **Computational Overhead**: Excessive use of square roots and division operations inflates computational overhead. Handled by deriving a purely algebraic closed form for $f$ that avoids these operations where possible [S1].
*   **Degenerate Covariance**: If the determinant of $\Lambda$ is zero or negative, the matrix is singular or indefinite. This should be handled by filtering or fallback [G].
*   **Boundary Conditions**: Integer division for tile coordinates must handle negative coordinates correctly (floor division) [G].

## Operating characteristics
*   **Time Complexity**: The preprocessing step (QuadBox construction) is $O(1)$ per Gaussian, involving a constant number of arithmetic operations. The traversal step (QPass) is $O(T)$ where $T$ is the number of tiles covered, but with a very small constant factor due to branch-free aggregation [S1].
*   **Memory Complexity**: $O(1)$ auxiliary memory per Gaussian for storing the 4 box bounds [S1].
*   **Measured Performance**: QuadBox achieves an average over $1.8\times$ speedup compared to standard 3DGS on Mip-NeRF 360, Tanks & Temples, and Deep Blending datasets [S1]. It outperforms AdR-Gaussian's AABB algorithm by $1.85\times$ [S1].
*   **Strengths**: Tighter bounding reduces tile redundancy, leading to fewer overdraw and faster rendering. The branch-free QPass algorithm is cache-friendly and scalable [S1].
*   **Limitations**: The method assumes the Gaussian projection is well-approximated by the 4-box structure. Highly anisotropic or rotated Gaussians might still have some residual over-approximation, though less than single AABB [S1].

## Background
QuadBox was introduced in the paper "QuadBox: Accelerating 3D Gaussian Splatting with Geometry-Aware Boxes" [S1]. It addresses the inefficiency of conservative bounding boxes in 3D Gaussian Splatting rasterization. The method builds on the concept of adaptive bounding boxes (AdR-Gaussian) but improves upon them by using four boxes and a dedicated traversal algorithm [S1].
