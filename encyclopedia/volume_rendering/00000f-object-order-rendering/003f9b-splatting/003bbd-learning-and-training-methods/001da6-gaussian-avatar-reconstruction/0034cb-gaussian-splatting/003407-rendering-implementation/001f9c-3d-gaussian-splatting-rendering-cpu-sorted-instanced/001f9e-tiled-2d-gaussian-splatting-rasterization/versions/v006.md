# Tiled 2D Gaussian Splatting Rasterization

Also called: 3D Gaussian Splatting Rasterization (GPU), 3DGS Rasterization, Gaussian Rasterization (GPU)

## Overview
Tiled 2D Gaussian Splatting Rasterization is a highly optimized, differentiable GPU-based rendering method for 3D Gaussian Splatting scenes. It solves the performance bottleneck of rendering millions of Gaussian primitives by partitioning the image plane into fixed-size macro-tiles and processing them in parallel using CUDA thread blocks [S1, S2, S3, unofficial]. Unlike parent methods that sort on the CPU or render via standard graphics pipeline primitives, this method performs depth sorting and alpha blending entirely on the GPU within shared memory, enabling real-time training and rendering speeds [S1, S2, unofficial]. It differs from non-tiled approaches by avoiding per-pixel sorting overhead and from ray-tracing alternatives by restricting itself to pinhole cameras but achieving higher throughput through tile-based memory coalescing [S5].

## How it works
**Inputs:**
*   List of 3D Gaussians: each defined by mean $\mu \in \mathbb{R}^3$, 3D covariance $\Sigma \in \mathbb{R}^{3 \times 3}$ (or scale/rotation), opacity logit $o \in \mathbb{R}$, and spherical harmonic coefficients for color.
*   Camera parameters: intrinsic matrix (focal lengths $f_x, f_y$, principal point $c_x, c_y$) and extrinsic world-to-camera transformation.
*   Image dimensions: width $W$, height $H$.
*   Tile size: $T \times T$ pixels (default 16x16 or 32x32) [S1, S3, unofficial].
*   Background color tensor $B \in \mathbb{R}^{3 \times H \times W}$ [S3, unofficial].

**Outputs:**
*   Rendered color image $C \in \mathbb{R}^{3 \times H \times W}$.
*   Rendered alpha image $A \in \mathbb{R}^{H \times W}$.
*   Intermediate transmittance values for backward pass [S2, unofficial].

**Data Structures:**
*   **Gaussian Attributes:** Stored in Structure-of-Arrays (SoA) or Array-of-Structures (AoS) on GPU memory. Key fields: `means_image` (2D projected means), `conics` (inverse 2D covariance matrices), `opacities` (sigmoid of logits), `colors` (evaluated SH colors).
*   **Tile Bins:** Arrays defining the start and end indices of Gaussians assigned to each tile in the sorted list.
*   **Sorted Gaussian List:** Gaussians sorted by a composite key (tile index, depth) to ensure front-to-back processing within each tile.

**Steps:**

1.  **Frustum Culling:** Discard Gaussians entirely outside the camera's view frustum (near/far planes and image bounds) [S1, S3, unofficial].
2.  **Projection:** Transform Gaussian means to camera space and project to 2D image plane. Compute the 2D covariance matrix $\Sigma'$ using the Jacobian of the projection and the view transformation [S4, unofficial].
    $$ \Sigma' = J W \Sigma W^T J^T $$
    where $W$ is the view matrix and $J$ is the projection Jacobian [S4, unofficial].
3.  **Conic Computation:** Compute the conic matrix (inverse 2D covariance) for efficient distance evaluation. Let the conic be represented by coefficients $a, b, c$ such that the quadratic form is $a \cdot du^2 + 2b \cdot du \cdot dv + c \cdot dv^2$ [S3, unofficial].
    $$ \text{Conic} = (\Sigma')^{-1} $$
4.  **Bounding Box & Tile Assignment:** Calculate the axis-aligned bounding box (AABB) for each projected Gaussian. The extent is typically determined by a multiple of the standard deviation (e.g., $3\sigma$) or by solving for the extrema of the ellipse equation [S3, unofficial][S7]. Assign each Gaussian to all tiles its AABB intersects [S1, S3, unofficial].
    *   *Note:* Advanced variants use "SnugBox" (tightest AABB) or "AccuTile" (exact ellipse intersection) for tighter culling [S1, unofficial].
5.  **Sorting:** Sort the assigned Gaussians. The primary sort key is the tile index; the secondary key is the view-space depth (back-to-front) [S1, S2, unofficial]. This is typically done using a device-side radix sort on a 64-bit integer key combining tile ID and depth [S2, S9].
6.  **Tile Bin Generation:** Compute cumulative counts to determine the range of sorted Gaussian indices belonging to each tile [S2, unofficial].
7.  **Rasterization Kernel (Per Tile):**
    *   Launch one CUDA thread block per tile.
    *   Threads cooperatively fetch the Gaussians assigned to this tile from global memory into shared memory.
    *   For each pixel $(u, v)$ in the tile:
        *   Initialize accumulated transmittance $T = 1.0$ and color $C_{pix} = 0$.
        *   Iterate through the sorted Gaussians for this tile.
        *   Compute squared Mahalanobis distance $dist\_sq$ from pixel to Gaussian mean:
            $$ dist\_sq = a \cdot du^2 + 2 \cdot b \cdot du \cdot dv + c \cdot dv^2 $$
            where $du = u - u_{mean}$ and $dv = v - v_{mean}$ [S3, unofficial].
        *   Compute opacity contribution:
            $$ \alpha_i = \text{sigm}(o_i) \cdot \exp(-\frac{1}{2} dist\_sq) $$
            [S4, unofficial].
        *   If $\alpha_i < \epsilon$ (threshold), skip.
        *   Update color and transmittance:
            $$ C_{pix} += c_i \cdot \alpha_i \cdot T $$
            $$ T *= (1 - \alpha_i) $$
        *   **Early Termination:** If $T < \tau$ (e.g., 0.01 or 0.99 accumulated opacity), break the inner loop [S1, S3, unofficial].
    *   Write final pixel color $C_{pix} + B_{pix} \cdot T$ and alpha $1 - T$ to output buffers.

**Pseudocode:**

```python
import torch
import math

def tiled_gaussian_rasterization(
    means_3d: torch.Tensor,      # [N, 3]
    cov3d: torch.Tensor,         # [N, 6] (symmetric 3x3 covariance)
    opacities: torch.Tensor,     # [N]
    sh_colors: torch.Tensor,     # [N, K] (SH coefficients)
    camera: Camera,              # Object with intrinsic/extrinsic methods
    img_width: int,
    img_height: int,
    tile_size: int = 16,
    sigma_multiplier: float = 3.0
):
    """
    Simplified pseudocode for Tiled 2D Gaussian Splatting Rasterization.
    Assumes CUDA-like parallel execution model mapped to Python logic for clarity.
    """
    # 1. Preprocessing: Project Gaussians
    # Transform means to camera space
    means_cam = camera.transform_points_world_to_cam(means_3d)
    
    # Project to 2D image plane
    means_img = camera.project_points_cam_to_image_plane(means_cam)
    
    # Rotate and project covariance to 2D
    cov2d = camera.rotate_covariances_world_to_cam(cov3d)
    cov2d_img = camera.project_covariance_to_image(cov2d, means_cam)
    
    # Compute conics (inverse 2D covariance) for fast distance eval
    # cov2d_img is [N, 2, 2]. Invert each 2x2 matrix.
    conics = torch.inverse(cov2d_img) # [N, 2, 2]
    
    # Evaluate SH colors
    colors = eval_spherical_harmonics(sh_colors, camera.sh_degree)
    
    # 2. Bounding Box & Tile Assignment
    # Compute AABB for each Gaussian in screen space
    # Extent is approx sigma_multiplier * sqrt(eigenvalues)
    # Assign Gaussian to tiles it intersects
    tile_assignments = assign_gaussians_to_tiles(
        means_img, conics, img_width, img_height, tile_size, sigma_multiplier
    )
    
    # 3. Sorting
    # Create unique IDs: (tile_idx << 32) | depth_idx
    # Sort by these IDs to get global order of (tile, gaussian)
    isect_ids, gaussian_ids = map_gaussian_to_intersects_tensor(
        means_img, tile_assignments, img_width, img_height
    )
    
    # Sort isect_ids to determine processing order
    isect_ids_sorted, sorted_indices = torch.sort(isect_ids)
    gaussian_ids_sorted = torch.gather(gaussian_ids, 0, sorted_indices)
    
    # Compute tile bins (start/end indices in the sorted list for each tile)
    tile_bins = get_tile_bin_edges_tensor(isect_ids_sorted, img_width, img_height, tile_size)
    
    # 4. Rasterization Kernel Execution
    # Initialize output buffers
    out_img = torch.zeros(3, img_height, img_width, device=means_img.device)
    out_alpha = torch.zeros(img_height, img_width, device=means_img.device)
    
    # Launch kernel (conceptually)
    # For each tile (tu, tv):
    for tu in range(0, img_width, tile_size):
        for tv in range(0, img_height, tile_size):
            u_start, v_start = tu, tv
            u_end = min(u_start + tile_size, img_width)
            v_end = min(v_start + tile_size, img_height)
            
            # Get range of Gaussians for this tile from sorted list
            bin_start, bin_end = tile_bins[tu // tile_size, tv // tile_size]
            tile_gaussian_indices = sorted_indices[bin_start:bin_end]
            
            # Extract tile data
            opacities_tile = opacities[tile_gaussian_indices]
            colors_tile = colors[tile_gaussian_indices]
            means_img_tile = means_img[tile_gaussian_indices]
            conics_tile = conics[tile_gaussian_indices]
            
            # Process pixels in tile
            for u_pix in range(u_start, u_end):
                for v_pix in range(v_start, v_end):
                    # Early termination check
                    current_alpha = out_alpha[v_pix, u_pix]
                    if current_alpha >= 0.99: # Transmittance < 0.01
                        continue
                        
                    accumulated_color = 0.0
                    transmittance = 1.0 - current_alpha
                    
                    # Iterate Gaussians back-to-front
                    for i in range(len(tile_gaussian_indices)):
                        idx = tile_gaussian_indices[i]
                        
                        # Get properties
                        op = opacities[idx]
                        col = colors[idx]
                        conic = conics_tile[i] # a, b, c
                        mean = means_img_tile[i]
                        
                        # Distance
                        du = u_pix - mean[0]
                        dv = v_pix - mean[1]
                        dist_sq = conic[0,0]*du**2 + 2*conic[0,1]*du*dv + conic[1,1]*dv**2
                        
                        # Opacity
                        alpha = torch.sigmoid(op) * torch.exp(-0.5 * dist_sq)
                        
                        if alpha < 1e-4:
                            continue
                            
                        accumulated_color += col * alpha * transmittance
                        transmittance *= (1 - alpha)
                        
                        if transmittance < 0.01:
                            break
                    
                    out_img[:, v_pix, u_pix] = accumulated_color + camera.bg_color[:, v_pix, u_pix] * transmittance
                    out_alpha[v_pix, u_pix] = 1.0 - transmittance

    return out_img, out_alpha
```

**Parameters:**
*   `tile_size`: Default 16x16 or 32x32 pixels [S1, S3, unofficial].
*   `sigma_multiplier`: Extent multiplier for bounding boxes, typically 3.0 (3-sigma) [S3, unofficial].
*   `BLOCK_X`, `BLOCK_Y`: Tile dimensions in pixels [S2, unofficial].

**Edge Cases & Pitfalls:**
*   **Precision:** Floating-point precision in depth sorting can cause z-fighting or incorrect ordering for very close Gaussians [S2, unofficial].
*   **Boundaries:** Gaussians partially outside the image must be handled correctly during AABB calculation to avoid out-of-bounds memory access [S3, unofficial].
*   **Degenerate Input:** Near-zero covariance matrices (singularities) must be regularized (e.g., adding epsilon to diagonal) before inversion [S3, unofficial].
*   **Camera Model:** Restricted to pinhole cameras; does not support complex lens effects or arbitrary light paths [S5].

### Mobile-GS
Memory-centric design for smartphones: loads only frustum-visible Gaussians from flash, uses quantized integer positions/colors, and lower-precision blending shaders [S1, unofficial].

### FlashGS
Accelerates forward rendering by partitioning the screen into finer tiles and scheduling them on a multi-GPU pipeline [S1, unofficial].

### FilterGS
Proposes a traversal-free, parallel filtering structure that selects a single scale per Gaussian via a learned network, avoiding expensive tree traversal [S1, unofficial].

### 4D Gaussian Splatting Motion Evaluation
Renders time-varying captures by storing static attributes and per-splat motion coefficients in textures, evaluated in the vertex shader from a time uniform, avoiding per-frame CPU sorting [S6, unofficial].

### AABB Culling for Gaussian Splatting
Uses axis-aligned bounding boxes of projected ellipses (solved via partial derivatives) to cull tiles, addressing the inability of bounding circles to cull low-opacity pairs in the minor axis direction [S7].

### Load Balancing for Pixel-parallel Splatting
Addresses uneven computational load across pixel threads by reducing Gaussians for heavy-load pixels and increasing for light-load pixels, using a loss weight $\lambda_{L1} + \lambda_{ssim} = 0.55$ [S7].

### Tight Quad Rasterization with Eigenvalue Decomposition
Represents Gaussians as non-axis-aligned quads using 2D eigenvalue decomposition, incorporating alpha into bound rectangle calculation for tighter fits and reduced overdraw [S8].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot T^2)$ in the worst case where $N$ is the number of Gaussians and $T^2$ is the tile size, but effectively $O(K)$ where $K$ is the number of visible splat-pixel intersections due to early termination and culling [S5].
*   **Memory Complexity:** $O(N + W \cdot H)$ for storing Gaussian attributes and output buffers. Shared memory usage per tile is minimal [S1, unofficial].
*   **Performance:** Enables real-time rendering (100+ FPS) and accelerated training on modern GPUs (e.g., RTX 3090/4090) for scenes with millions of Gaussians [S1, unofficial].
*   **Strengths:** High throughput due to shared memory usage and coalesced memory access; differentiable for end-to-end training; simple implementation on CUDA [S1, S2, unofficial].
*   **Limitations:** Restricted to pinhole cameras; linear scaling with Gaussian density for small splats (wasted computation on empty pixels within large tiles); sensitive to tile size selection [S5].
*   **When to Use:** Real-time rendering and training of static or slowly moving 3D Gaussian Splatting scenes on GPU.
*   **When Not to Use:** Scenes requiring complex light transport (reflections, refractions), non-pinhole cameras, or extreme mobile constraints without specialized variants (e.g., Mobile-GS) [S5].

## Background
Originated with the "3D Gaussian Splatting" paper by Kerbl et al. (2023) [S1, unofficial][S5]. The method was developed to address the slow rendering speeds of previous 3D Gaussian representations by leveraging GPU tile-based rasterization techniques common in traditional graphics. It has since become the standard rendering backend for most 3DGS implementations, with numerous optimizations added for mobile, large-scale, and dynamic scenes [S1, S2, S3, unofficial].
