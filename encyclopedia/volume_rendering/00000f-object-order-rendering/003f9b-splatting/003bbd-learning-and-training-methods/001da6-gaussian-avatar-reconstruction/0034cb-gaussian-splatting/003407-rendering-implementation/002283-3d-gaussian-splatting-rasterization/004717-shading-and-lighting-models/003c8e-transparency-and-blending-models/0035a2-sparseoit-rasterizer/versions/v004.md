# SparseOIT Rasterizer

Also called: GPU software rasterization of 3D Gaussians with pre-rendering

## Overview
SparseOIT Rasterizer is a rendering technique for 3D Gaussian Splatting that computes a blended image using Order-Independent Transparency (OIT) without sorting Gaussians by depth [S1, unofficial]. It differs from standard 3DGS rasterization, which requires sorting by distance to camera to correctly accumulate transmittance, by eliminating the sorting step entirely in favor of a weighted average that approximates the order-dependent result [S1, unofficial]. It achieves this by simultaneously computing a final OIT color and a pre-rendered image state using Blend-and-Normalize (BAN) and Blend-and-Update (BAU) functions [S1, unofficial].

## How it works
The method operates on 3D Gaussian primitives defined by mean $\boldsymbol{\mu}$, covariance $\boldsymbol{\Sigma}$ (or scales and orientation), opacity $o$, and color $\mathbf{c}$ [S1, unofficial]. The core challenge is computing the pixel color $C$ and accumulated alpha $\alpha$ given a camera ray. Standard splatting projects 3D Gaussians to 2D ellipses, computes a 2D alpha mask, and blends them in screen space. These models modify the blending or shading stage: some refine the depth metric used for sorting, others integrate the 3D density function directly along the ray, and others use weighted averages to bypass sorting. All assume the Gaussians are sorted or processed in a manner that approximates front-to-back accumulation to ensure correct occlusion.

### Inputs and Outputs
**Inputs:**
*   Image dimensions: width $w$, height $h$.
*   Gaussian attributes: 3D means $M$, covariances $S$, colors $C$, opacities $A$.
*   View matrix $V$.

**Outputs:**
*   Rendered image $I$.
*   Pre-rendered image state $I_{pre}$ (used for accumulation/updates).

### Data Structures
*   **Tiles ($T$):** A grid partitioning the image of size $w \times h$. The specific tile size is not given in the sources [S1, unofficial].
*   **Gaussian List ($L$):** A list of Gaussian data structures duplicated and keyed by tile ID.
*   **Keys ($K$):** Tile IDs assigned to each Gaussian entry in $L$.
*   **Ranges ($R$):** Start and end indices in $L$ for each tile $t$.

### Steps
1.  **Cull:** Remove Gaussians outside the view frustum or too small to contribute [S1, unofficial].
2.  **Project:** Project 3D means $M$ and covariances $S$ to screen space using view $V$, resulting in $M'$ and $S'$ [S1, unofficial].
3.  **Tile:** Create a tile grid $T$ for the image dimensions $w, h$ [S1, unofficial].
4.  **Assign Keys:** Duplicate Gaussian data into list $L$ and assign tile keys $K$ based on which tile each Gaussian's center falls into [S1, unofficial].
5.  **Sort:** Sort the list $L$ only by the tile keys $K$. This groups Gaussians by tile but does *not* sort by depth within the tile [S1, unofficial].
6.  **Identify Ranges:** Compute the range $R_t$ of indices in $L$ corresponding to each tile $t$ [S1, unofficial].
7.  **Initialize:** Initialize the rendered image $I$ to zero [S1, unofficial].
8.  **Loop Tiles:** For each tile $t$ in $T$:
    9.  **Loop Pixels:** For each pixel $i$ in tile $t$:
        10. **Get Range:** Retrieve the range $r$ of Gaussians in $L$ that cover tile $t$ [S1, unofficial].
        11. **BAN:** Compute the final color $I[i]$ using the Blend-and-Normalize function [S1, unofficial].
        12. **BAU:** Update the pre-rendered state $I_{pre}[i]$ using the Blend-and-Update function [S1, unofficial].

### Formulas
The final color $\mathbf{C}$ is computed as [S1, unofficial]:

$$
\mathbf{C} = T \mathbf{c}_0 + (1-T)F
$$

where:
*   $\mathbf{c}_0$ is the background color.
*   $T$ is the accumulated opacity/transmittance factor.
*   $F$ is the weighted average color:
    $$
    F = \frac{P}{Q}
    $$
    $$
    P = \sum_{i=1}^{N} \mathbf{c}_i \alpha_i w_i
    $$
    $$
    Q = \sum_{i=1}^{N} \alpha_i w_i
    $$
*   $\mathbf{c}_i$ is the color of the $i$-th Gaussian.
*   $\alpha_i$ is the opacity of the $i$-th Gaussian.
*   $w_i$ is the weight of the $i$-th Gaussian.

The gradients for backpropagation are [S1, unofficial]:

$$
\frac{\partial \mathbf{C}}{\partial \mathbf{c}_i} = (1-T)\frac{\alpha_i w_i}{Q}
$$

$$
\frac{\partial \mathbf{C}}{\partial \alpha_i} = \frac{T}{1-\alpha_i}(F-\mathbf{c}_0) + (1-T)\frac{w_i}{Q}(\mathbf{c}_i - F)
$$

$$
\frac{\partial \mathbf{C}}{\partial w_i} = (1-T)\frac{\alpha_i}{Q}(\mathbf{c}_i - F)
$$

### Parameters
*   **BAN (Blend and Normalize):** Function that computes the final OIT color [S1, unofficial].
*   **BAU (Blend and Update):** Function that updates the pre-rendered image state for subsequent blending or accumulation [S1, unofficial].
*   **Update Interval:** In most cases, the update interval is not specified, but for scenes like train, room, and bonsai, it is set to 600 to ensure correct execution [S1, unofficial].

### Edge Cases and Pitfalls
*   **Gradient Independence:** The variables of each Gaussian are mutually independent in the backward propagation equation, allowing for parallel computation [S1, unofficial].
*   **Update Interval:** For specific scenes (train, room, bonsai), the update interval must be set to 600 to ensure correct execution, exceeding twice the number of training views [S1, unofficial].

## Subtopics

### [Weighted Order-Independent Transparency for 3DGS](7772-weighted-order-independent-transparency-for-3dgs.md)
Weighted Order-Independent Transparency (OIT) for 3D Gaussian Splatting (3DGS) is a rendering technique that computes a blended image without sorting Gaussians by depth, using a learnable weight function to approximate correct transparency blending. It differs from standard 3DGS rasterization, which requires sorting by distance to camera to correctly accumulate transmittance, by eliminating the sorting step entirely in favor of a weighted average that approximates the order-dependent result.

## Operating characteristics
*   **Time Complexity:** The sorting step is reduced to sorting by tile ID only, which is significantly faster than full depth sorting [S1, unofficial]. The blending process is independent of depth order, allowing for parallel computation of gradients [S1, unofficial].
*   **Memory Complexity:** Requires storing the rendered image $I$ and pre-rendered state $I_{pre}$ [S1, unofficial].
*   **Strengths:** Eliminates the expensive depth sorting step required by standard 3DGS rasterization [S1, unofficial]. Allows for parallel computation of gradients due to mutual independence of Gaussian variables in the backward propagation [S1, unofficial].
*   **Limitations:** The specific tile size and the exact implementation of the BAN and BAU functions are not detailed in the sources [S1, unofficial]. The quality of the OIT approximation depends on the weight function $w_i$, which is not explicitly defined [S1, unofficial].
*   **When to Use:** When order-independent transparency is desired and the computational cost of depth sorting is prohibitive [S1, unofficial].
*   **When Not to Use:** When exact order-dependent transparency is required and the approximation error of OIT is unacceptable [S1, unofficial].

## Background
The SparseOIT Rasterizer was introduced in the paper "SparseOIT: Improving Order-Independent Transparency 3DGS via Active Set Method" [S1, unofficial]. It builds on the principles of 3D Gaussian Splatting and extends them with order-independent transparency techniques. The method is part of the broader family of transparency and blending models for Gaussian Splatting.
