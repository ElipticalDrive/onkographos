# Point-Based Ray Tracing for Visibility

Also called: VisibilitySplat Ray Tracing

## Overview
Point-Based Ray Tracing for Visibility serves as a sparse visibility oracle that evaluates transmittance along sampled light directions using a bounding volume hierarchy (BVH) of Gaussian proxies, enabling evaluation from any point in space in any direction [S1]. Unlike the camera-tied rasterizer, it decouples visibility estimation from screen-space projection, allowing it to act as a drop-in companion to standard 3D Gaussian Splatting (3DGS) by reusing the same EWA-splatting formulation for consistent blending without requiring training mismatch [S1].

## How it works
**Inputs and Outputs**
*   **Input:** A set of 3D Gaussians (position, covariance, opacity $\alpha$, color); a ray $r(t) = o + td$; an early-out threshold $T_{stop}$; a minimum response threshold $\epsilon$ [S1].
*   **Output:** The accumulated transmittance $T$ along the ray [S1].

**Data Structures**
*   **Gaussian Proxy:** For each Gaussian, a proxy mesh (e.g., a subdivided regular icosahedron) is constructed, and its triangles are inserted into a BVH for fast ray-triangle traversal [S1].
*   **Proxy Scale:** The proxy is scaled to tightly bound the region where the particle’s response exceeds $\epsilon$ [S1]. The scale explicitly incorporates the particle’s opacity $\alpha$ to apply "adaptive clamping," ensuring nearly transparent splats receive proportionally tighter bounds to reduce false-positive hits during traversal [S1].

**Algorithm Steps**
1.  **Ray Query:** For a given ray $r(t) = o + td$, query the BVH to gather the batch of intersected Gaussian proxies [S1].
2.  **Virtual Camera Setup:** To reuse the unmodified rasterizer for consistent blending, instantiate a one-pixel virtual camera at the ray origin $o$ with the optical axis aligned to the ray direction $d$ [S1].
3.  **Splatting Evaluation:** Splat exactly the Gaussians reported by the BVH for that ray into the center pixel of this virtual camera using the standard EWA-splatting formulation [S1]. This computes the per-hit attenuation $\Delta a_i$ from the Gaussian’s line integral along the ray segment covered by the proxy [S1].
4.  **Transmittance Update:** Update the accumulated transmittance $T$ using the formula:
    $$ T \leftarrow T \cdot (1 - \Delta a_i) $$
    where $\Delta a_i$ is the attenuation of the $i$-th hit [S1].
5.  **Ordering:** For occlusion-only queries, hits do not need to be depth-sorted because multiplication commutes; they can be processed in arbitrary order while maintaining correctness for $T$ [S1].
6.  **Early Termination:** If $T \le T_{stop}$, terminate the traversal and return $T$ [S1].

**Parameters**
*   **$T_{stop}$:** The early-out threshold for transmittance. It should match the early-out used by the rasterizer to keep consistency between visibility estimated by ray tracing and the screen-space renderer [S1].
*   **$\epsilon$:** A small minimum response threshold used to define the tight bounding region for the proxy [S1].

**Pitfalls**
*   **False Positives:** Without adaptive clamping, transparent Gaussians may generate oversized proxies, increasing traversal cost and false-positive hits [S1].
*   **Threshold Mismatch:** Setting $T_{stop}$ differently from the rasterizer's early-out threshold will cause inconsistency between ray-traced visibility and screen-space rendering [S1].

**Pseudocode**
```python
def evaluate_visibility(ray_origin, ray_direction, gaussians, bvh, t_stop, epsilon):
    """
    Evaluates transmittance along a ray using Gaussian proxies.
    """
    T = 1.0
    # 1. Query BVH for intersected proxies. Proxies are scaled with opacity (adaptive clamping) [S1].
    intersected_proxies = bvh.query(ray_origin, ray_direction)
    
    # 2. Setup virtual camera frame at ray origin with optical axis aligned to ray direction [S1].
    # This local frame allows reusing the standard EWA-splatting formulation [S1].
    
    # 3. Process intersections. Depth sorting is not required for transmittance accumulation [S1].
    for proxy in intersected_proxies:
        gaussian = proxy.parent_gaussian
        
        # 4. Splat the Gaussian into the center pixel of the 1-pixel virtual camera using EWA-splatting [S1].
        # This computes the per-hit attenuation delta_a from the Gaussian's line integral along the ray segment [S1].
        # Note: The exact EWA-splatting projection is implemented in the parent rasterizer article [G].
        delta_a = standard_ewa_splatting(gaussian, ray_origin, ray_direction)  # Standard EWA-splatting step [G]
        
        # 5. Update transmittance: T <- T * (1 - delta_a) [S1].
        T = T * (1.0 - delta_a)
        
        # 6. Early termination when transmittance drops below threshold [S1].
        if T <= t_stop:
            break
            
    return T
```

## Operating characteristics
*   **Time Complexity:** Depends on BVH traversal depth and the number of intersected proxies per ray [S1]. Early termination reduces average cost when transmittance drops below $T_{stop}$ [S1].
*   **Memory Complexity:** Requires storing the BVH of Gaussian proxies [S1]. The proxy scale incorporates opacity, which may increase memory slightly compared to minimal bounding spheres but reduces false positives [S1].
*   **Strengths:** Decouples visibility from camera projection [S1]. Allows reuse of pretrained 3DGS point clouds and the existing rasterizer without training mismatch [S1]. Provides consistent blending with the screen-space renderer [S1].
*   **Limitations:** Not a full renderer; serves only as a visibility oracle [S1]. Requires careful tuning of $T_{stop}$ to match the rasterizer's early-out behavior [S1].
*   **When to use:** When evaluating transmittance along arbitrary light directions for relighting or shadowing in 3DGS scenes [S1].
*   **When not to use:** For primary view synthesis where the tile-based rasterizer is more efficient [S1].

## Background
The method was introduced in "VisibilitySplat: Ray-Traced Occlusion for Relighting with 3D Gaussian Splatting" [S1]. It addresses the limitation of the standard 3DGS rasterizer, which is tied to camera projection and ordered blending per tile, by providing a point-based ray tracer that evaluates Gaussian splatting from any point in space in any direction [S1]. It contrasts with alternative ray-based renderers like 3DGRT (which evaluates at max response and uses a k-buffer) and IRGS (which collapses to 2D disks) by strictly adhering to the EWA-splatting formulation [S1].
