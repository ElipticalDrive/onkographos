# Hybrid Transparency

Also called: Core-Tail Blending, Hybrid Transparency Blending, Hybrid Transparency-based blending, Hybrid transparency for 3DGS, Partial depth-ordering blending

## Overview
Hybrid Transparency is a rendering technique that mitigates popping artifacts in 3D Gaussian Splatting by combining depth-ordered alpha blending for the foremost $K$ fragments (the 'core') with order-independent accumulation for the remaining fragments (the 'tail') [S1, S2]. It solves the inconsistency of splat shapes and transparency across viewpoints caused by approximate sorting in standard splatting, avoiding the performance cost of hierarchical sorting or ray tracing [S2]. Unlike [Analytic Transmittance 3DGS](4440-analytic-transmittance-3dgs.md) which refines the density integration, and [SparseOIT Rasterizer](7562-sparseoit-rasterizer.md) which uses order-independent transparency for all fragments, Hybrid Transparency restricts expensive sorting to a small subset of fragments to maintain real-time performance [S1].

## How it works
**Inputs:** A set of 3D Gaussians defined by mean $\boldsymbol{\mu}$, covariance $\boldsymbol{\Sigma}$ (or scales and orientation), opacity $o$, and color $\mathbf{c}$. Camera parameters.
**Outputs:** Pixel color $C$ and accumulated alpha $\alpha$.

**Data Structures:**
*   **Tile Fragment List:** An unordered list of fragments belonging to a tile. Each fragment stores the projected 2D Gaussian parameters, the pixel-specific depth value $x_{view}$, and the pre-computed color/alpha contribution.
*   **Core Buffer:** A compact 64-bit data structure per thread used to store the top $K$ fragments for a pixel during insertion sort, minimizing register usage and swaps [S2].

**Parameters:**
*   $K$: Number of foremost contributions blended explicitly. Default/Typical value: 16 [S1, S2].
*   $\tau_K$: Minimum alpha threshold for a fragment to be considered for the core. Default value: 0.05 [S1].

**Steps:**

1.  **Splat Staging and Bounding Box Computation:**
    Project 3D Gaussians to screen space. Use plane-fitting to compute exact bounding boxes of each 3D Gaussian in screen space [S2]. Create unordered per-tile fragment lists. Omit global depth ordering at this stage [S2].

2.  **Pixel-Specific Depth Evaluation ($x_{view}$):**
    For each fragment contributing to a pixel, compute the pixel-specific depth value $x_{view}$, defined as the splat's point of maximum contribution along the pixel viewing ray in view space [S1, S2]. This value is computed efficiently using intermediate values from the splat evaluation, avoiding matrix inversion [S1].
    $$ x_{view} = \text{depth of point of max contribution along ray} $$
    [S1]

3.  **Core Identification and Sorting:**
    For each pixel, identify the fragments contributing to it. Sort these fragments based on $x_{view}$. Select the first $K$ fragments as the 'core'. If a fragment's alpha is below $\tau_K$, it may be excluded from the core consideration depending on implementation specifics, but typically the top $K$ by depth are selected [S1].
    *   *Pitfall:* Using only the view-space depth of the mean causes incorrect per-pixel blending order and popping artifacts. $x_{view}$ must be used [S1].
    *   *Pitfall:* Insertion sort for per-pixel core causes significant divergence. Mitigated by reducing tile size to $8 \times 8$ [S1].

4.  **Core Blending:**
    Alpha-blend the $K$ core fragments in their correct depth order per pixel using standard front-to-back alpha blending [S1, S2].
    $$ C_{core} = \sum_{i=1}^{K} c_i \alpha_i \prod_{j=1}^{i-1} (1 - \alpha_j) $$
    $$ \alpha_{core} = 1 - \prod_{i=1}^{K} (1 - \alpha_i) $$
    where $c_i, \alpha_i$ are the color and alpha of the $i$-th core fragment [S1].

5.  **Tail Accumulation:**
    Accumulate the contributions of all remaining fragments (the 'tail', $N-K$ fragments) using an order-independent residual. This is done without sorting [S1].
    $$ C_{tail} = \sum_{j=K+1}^{N} c_j $$
    $$ \alpha_{tail} = \sum_{j=K+1}^{N} \alpha_j $$
    *Note:* The sources describe accumulating RGB and alpha. The final composition combines the core and tail. The exact composition formula provided in [S1] implies:
    $$ C = C_{core} + C_{tail} (1 - \alpha_{core}) $$
    $$ \alpha = \alpha_{core} + \alpha_{tail} (1 - \alpha_{core}) $$
    [S1]
    *Optimization:* Since the partial derivative of the blending function is the same for all splats in the tail, partial derivatives can be pre-computed during the forward pass for efficient backward pass [S1].

6.  **Final Composition:**
    Combine $C_{core}, \alpha_{core}$ and $C_{tail}, \alpha_{tail}$ to produce the final pixel color and alpha [S1].

**Pseudocode:**

```python
def hybrid_transparency_rasterize(gaussians, camera, K=16, tau_K=0.05):
    # 1. Splat Staging
    # Project Gaussians to screen space.
    # Compute exact bounding boxes using plane-fitting.
    # Create unordered per-tile fragment lists.
    tiles = create_tiles(gaussians)
    
    # 2. Per-Pixel Processing
    for tile in tiles:
        # 3. Core Identification
        # For each pixel in tile, gather all contributing fragments.
        # Compute x_view for each fragment (depth of max contribution).
        fragments = gather_pixel_fragments(tile)
        
        # Sort fragments by x_view.
        sorted_fragments = sort_by_depth(fragments)
        
        # Select Core: First K fragments.
        # Filter by alpha threshold if necessary (implementation detail).
        core_fragments = sorted_fragments[:K]
        tail_fragments = sorted_fragments[K:]
        
        # 4. Core Blending
        c_core = vec3(0.0)
        a_core = 0.0
        transmittance = 1.0
        
        # Insertion sort within core if K is small and divergence is managed
        # or use the 64-bit compact structure for sorting [S2]
        for frag in core_fragments:
            c_i = frag.color
            a_i = frag.alpha
            c_core += c_i * a_i * transmittance
            transmittance *= (1.0 - a_i)
            a_core = 1.0 - transmittance
            
        # 5. Tail Accumulation
        c_tail = vec3(0.0)
        a_tail = 0.0
        
        for frag in tail_fragments:
            c_tail += frag.color
            a_tail += frag.alpha
            
        # 6. Final Composition
        # C = C_core + C_tail * (1 - A_core)
        # A = A_core + A_tail * (1 - A_core)
        final_alpha = a_core + a_tail * (1.0 - a_core)
        final_color = c_core + c_tail * (1.0 - a_core)
        
        write_pixel(final_color, final_alpha)
```

## Subtopics

### Multi-layers Alpha Blending Approximation
A sorting strategy that approximates the $\tau_{max}$ order of hit particles along a ray by storing the $k$-farthest hit particles in a buffer and incrementally alpha-blending the closest hits until transmittance vanishes [S3]. It uses $k=16$ as a typical value for the buffer size [S3]. Unlike Hybrid Transparency which stores the $k$-closest particles and blends farthest hits incrementally, MLAB stores the $k$-farthest and blends closest hits. Hybrid Transparency recovers exact $k$-closest particles but requires processing all particles, which is slow without optimizations [S3].

## Operating characteristics
*   **Time Complexity:** Rendering time is reduced because it avoids global depth-sorting overhead for the tail [S1]. It is significantly faster than hierarchical sorting methods like StopThePop [RSP*24] [S1].
*   **Memory Complexity:** Uses a compact 64-bit data structure for core fragments to reduce register usage [S2].
*   **Performance:** On Mip-NeRF360 datasets, it achieves a training speedup of $2.1\times$ and renders $1.6\times$ faster on average compared to standard 3DGS [S1].
*   **Strengths:** Eliminates popping artifacts caused by approximate sorting; maintains real-time performance; perspective-correct splat evaluation [S1, S2].
*   **Limitations:** Cannot use early stopping based on transmittance threshold by default, as all non-core fragments must be accumulated [S1]. Slightly lower PSNR than 3DGS due to absence of screen-space aliasing filter [S1].
*   **When to use:** VR/AR applications or fast-paced scenes where temporal stability and high frame rates are critical [S1, S2].
*   **When not to use:** Scenes with extreme depth complexity where accumulating the tail becomes prohibitively slow without further optimizations (e.g., depth prepass) [S1].

## Background
Hybrid Transparency was originally proposed by Wymann et al. [Wym16] (cited as [MCTB13] in the context of Maule et al.'s formulation) as a rendering paradigm for combining depth-ordered and order-independent transparency [S1]. It was integrated into the 3D Gaussian Splatting framework by Hahlbohm et al. [HFW*25] to solve popping artifacts and provide perspective-correct rendering for VR editing [S1, S2]. The method extends the formulation by Maule et al. to improve behavior within gradient descent-based optimization [S1].
