# Depth Rendering with Constant Opacity

Also called: Depth-Only Rendering Mode

## Overview
Depth Rendering with Constant Opacity is a specialized rendering pass designed to extract clean depth maps from 3D Gaussian Splatting models by forcing uniform opacity across all Gaussians [S1, unofficial]. Unlike standard rendering which weights depth accumulation by per-Gaussian opacity, this method ensures that the rasterizer's depth accumulation is driven strictly by geometric distance, removing shading and opacity variations that can distort depth estimation [S1, unofficial]. It serves as the foundation for depth-only passes in Gaussian Avatar Reconstruction pipelines, enabling accurate depth extraction before further processing like normalization or compositing [S1, unofficial].

## How it works
**Inputs:**
- `pc`: The Gaussian model object containing methods `get_xyz`, `get_scaling`, `get_rotation`, `get_covariance`, and `sh_degree`.
- `viewpoint_camera`: The camera object containing `FoVx`, `FoVy`, and projection/view matrices.
- `image_size`: Tuple `(width, height)` of the output image.
- `value`: Constant opacity multiplier (default 0.95) [S1, unofficial].

**Outputs:**
- Dictionary containing:
  - `render`: The rendered image tensor (all ones, effectively white).
  - `depth`: The accumulated depth buffer.
  - `alpha`: The accumulated alpha buffer.
  - `viewspace_points`: The 3D positions of the Gaussians in view space.
  - `visibility_filter`: Boolean mask of Gaussians with `radii > 0`.
  - `radii`: The radii of visible Gaussians.

**Data Structures:**
- `screenspace_points`: Tensor of shape `(num_gaussians, 2)`, initialized to zeros, with gradient retention enabled [S1, unofficial].
- `opacity`: Tensor of shape `(num_gaussians, 1)`, filled with `value` [S1, unofficial].
- `colors_precomp`: Tensor of shape `(num_gaussians, 3)`, filled with ones [S1, unofficial].
- `scales`, `rotations`, `cov3D_precomp`: Set to `None` or detached tensors to prevent gradient leakage [S1, unofficial].

**Parameters:**
- `value`: Constant opacity value. Default is 0.95 [S1, unofficial].

**Steps:**
1. Initialize `screenspace_points` tensor with zeros, matching the dtype and device of `pc.get_xyz()`, and enable gradient retention:
   ```python
   screenspace_points = torch.zeros_like(pc.get_xyz, dtype=pc.get_xyz.dtype, requires_grad=True, device="cuda") + 0
   try:
       screenspace_points.retain_grad()
   except:
       pass
   ```
   [S1, unofficial]

2. Compute tangent field of view values from the `viewpoint_camera`:
   $$ \text{tanfovx} = \tan\left(\frac{\text{FoVx}}{2}\right) $$
   $$ \text{tanfovy} = \tan\left(\frac{\text{FoVy}}{2}\right) $$
   [S1, unofficial]

3. Configure `GaussianRasterizationSettings` with:
   - Image dimensions: `(width, height)`
   - Tangent FOV: `(tanfovx, tanfovy)`
   - Background color: Typically white `[1, 1, 1]` or black `[0, 0, 0]` depending on dataset settings [S1, unofficial]
   - Scale modifier: As provided by pipeline
   - View and projection matrices: From `viewpoint_camera`
   - SH degree: From `pc.sh_degree`
   - Camera position: From `viewpoint_camera`
   - Prefiltered: `False`
   - Debug flag: As required [S1, unofficial]

4. Set Gaussian attributes:
   - `means3D`: `pc.get_xyz()`
   - `means2D`: `screenspace_points`
   - `opacity`: `torch.ones(pc.get_xyz.shape[0], 1, device=pc.get_xyz.device) * value`
   - `shs`: `None`
   - `colors_precomp`: `torch.ones_like(pc.get_xyz)`
   [S1, unofficial]

5. Within a `torch.no_grad()` context, prepare scales, rotations, and covariance:
   - If `pipe.compute_cov3D_python` is true:
     - `cov3D_precomp = pc.get_covariance(scaling_modifier)`
   - Else:
     - `scales = pc.get_scaling().detach()`
     - `rotations = pc.get_rotation().detach()`
     - `cov3D_precomp = None`
   [S1, unofficial]

6. Call the rasterizer with the configured settings and attributes to obtain `rendered_image`, `radii`, `rendered_depth`, and `rendered_alpha` [S1, unofficial].

7. Return the dictionary with results [S1, unofficial].

**Pseudocode:**
```python
import torch
import math

def render_depth_constant_opacity(pc, viewpoint_camera, image_size, value=0.95):
    # Step 1: Initialize screenspace_points with gradient retention
    screenspace_points = torch.zeros_like(pc.get_xyz, dtype=pc.get_xyz.dtype, requires_grad=True, device="cuda") + 0
    try:
        screenspace_points.retain_grad()
    except:
        pass

    # Step 2: Compute tangent FOV
    tanfovx = math.tan(viewpoint_camera.FoVx * 0.5)
    tanfovy = math.tan(viewpoint_camera.FoVy * 0.5)

    # Step 3: Configure rasterization settings
    # Note: Background color depends on dataset (white for many, black for others)
    bg_color = [1, 1, 1] # Assumed white background based on common usage [S1, unofficial]
    background = torch.tensor(bg_color, dtype=torch.float32, device="cuda")
    
    raster_settings = GaussianRasterizationSettings(
        image_height=image_size[1],
        image_width=image_size[0],
        tanfovx=tanfovx,
        tanfovy=tanfovy,
        bg=background,
        scale_modifier=1.0, # Assuming default scale modifier
        viewmatrix=viewpoint_camera.world_view_transform,
        projmatrix=viewpoint_camera.full_proj_transform,
        sh_degree=pc.sh_degree,
        campos=viewpoint_camera.camera_center,
        prefiltered=False,
        debug=False
    )

    # Step 4: Set attributes
    means3D = pc.get_xyz()
    means2D = screenspace_points
    opacity = torch.ones(means3D.shape[0], 1, device=means3D.device) * value
    shs = None
    colors_precomp = torch.ones_like(means3D)

    # Step 5: Prepare scales, rotations, cov3D
    with torch.no_grad():
        if hasattr(pc, 'compute_cov3D_python') and pc.compute_cov3D_python:
            cov3D_precomp = pc.get_covariance(scaling_modifier=1.0)
            scales = None
            rotations = None
        else:
            cov3D_precomp = None
            scales = pc.get_scaling().detach()
            rotations = pc.get_rotation().detach()

    # Step 6: Rasterize
    rasterizer = GaussianRasterizer(raster_settings=raster_settings)
    rendered_image, radii, rendered_depth, rendered_alpha = rasterizer(
        means3D=means3D,
        means2D=means2D,
        shs=shs,
        colors_precomp=colors_precomp,
        opacities=opacity,
        scales=scales,
        rotations=rotations,
        cov3D_precomp=cov3D_precomp
    )

    # Step 7: Return results
    return {
        "render": rendered_image,
        "depth": rendered_depth,
        "alpha": rendered_alpha,
        "viewspace_points": screenspace_points,
        "visibility_filter": radii > 0,
        "radii": radii
    }
```
[S1, unofficial]

**Edge Cases and Pitfalls:**
- Gradient leakage: Scales and rotations must be detached or set to None to prevent gradients from flowing into depth estimation [S1, unofficial].
- Opacity value: Using a value too close to 1.0 may cause over-saturation in alpha accumulation, while too low may result in sparse depth maps. 0.95 is the empirical default [S1, unofficial].
- Background color: Mismatched background color can affect depth accumulation at edges. Ensure consistency with the dataset's expected background [S1, unofficial].

## Subtopics

### Normalized Depth Rendering
Normalized Depth Rendering extends the constant opacity pass by dividing the accumulated depth buffer by the accumulated alpha buffer to correct for transparency artifacts [S2, unofficial]. It converts the normalized depth to displayable disparity using near and far clipping planes: $ \text{rendered\_disp\_norm} = 1 - \frac{\text{rendered\_depth\_norm} - z_{\text{near}}}{z_{\text{far}} - z_{\text{near}}} $ [S2, unofficial]. This method is chosen when accurate depth estimation in semi-transparent regions is required, as it accounts for the varying opacity contributions that constant opacity rendering ignores [S2, unofficial].

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of Gaussians and pixels, similar to standard Gaussian Splatting rasterization, as it uses the same tiled rasterization pipeline [S1, unofficial].
- **Memory Complexity:** Low, as it only requires storing the depth and alpha buffers, plus the screenspace points tensor [S1, unofficial].
- **Strengths:** Produces clean, consistent depth maps unaffected by per-Gaussian opacity variations, making it suitable for depth-based applications like compositing or depth-aware post-processing [S1, unofficial].
- **Limitations:** Does not account for actual opacity variations, which can lead to inaccurate depth in semi-transparent regions compared to variable opacity methods [S1, unofficial][S2, unofficial].
- **When to use:** When a geometrically accurate depth map is needed for downstream tasks like depth normalization or compositing, and opacity variations are not critical to the depth estimation [S1, unofficial].
- **When not to use:** When accurate depth in semi-transparent regions is required, in which case Depth Rendering with Variable Opacity should be used [S2, unofficial].

## Background
Depth Rendering with Constant Opacity originates from the Gaussian Splatting ecosystem, specifically adapted for depth extraction in 3D Gaussian Avatar Reconstruction pipelines [S1, unofficial]. It was developed to address the need for clean depth maps that are not skewed by the varying opacity of Gaussians, which is common in standard rendering passes [S1, unofficial]. The method is implemented in unofficial repositories such as DNGaussian, which extend the original Gaussian Splatting codebase for specialized rendering tasks [S1, unofficial].
