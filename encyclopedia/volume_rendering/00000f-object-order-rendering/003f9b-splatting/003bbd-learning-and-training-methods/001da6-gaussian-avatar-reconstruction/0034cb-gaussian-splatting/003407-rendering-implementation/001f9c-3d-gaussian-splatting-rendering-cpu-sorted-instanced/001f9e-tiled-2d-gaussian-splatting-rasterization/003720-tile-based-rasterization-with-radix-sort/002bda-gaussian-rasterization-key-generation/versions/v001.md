# Gaussian Rasterization Key Generation

Also called: duplicateWithKeys

## Overview
This method generates the key-value pairs required for the tile-based rasterization of 3D Gaussians. It maps each 3D Gaussian to every tile it overlaps, creating one work item per (Gaussian, tile) pair. The keys pack the tile ID and depth to enable a single global radix sort that simultaneously bins splats by tile and sorts them by depth [S1, unofficial]. It differs from [Tile-based Culling](2819-tile-based-culling.md) by generating explicit overlap entries rather than filtering, and from [Tile-based Depth Sorting](8038-tile-based-depth-sorting.md) by handling the key construction logic explicitly before the sort phase.

## How it works
**Inputs:**
- `points_xy`: Tensor of shape $(N, 2)$, screen-space centers $(x, y)$ [S1, unofficial].
- `radii`: Tensor of shape $(N)$, radius of each Gaussian in pixels [S1, unofficial].
- `depths`: Tensor of shape $(N)$, camera-space depth $Z_c$ for each Gaussian [S1, unofficial].
- `grid`: Tuple $(W_{tiles}, H_{tiles})$, number of tiles in x and y directions [S1, unofficial].
- `tile_size`: Integer, pixels per tile dimension (e.g., 16 or 32) [S1, G, unofficial].

**Outputs:**
- `gaussian_keys_unsorted`: Tensor of shape $(M)$, 64-bit integers, where $M$ is the total number of Gaussian-tile overlaps [S1, unofficial].
- `gaussian_values_unsorted`: Tensor of shape $(M)$, 32-bit integers, storing the original Gaussian index `idx` [S1, unofficial].

**Data Structures:**
- **Key**: 64-bit unsigned integer (`uint64_t`).
  - Bits [63:32]: 1D tile ID, calculated as $y_{tile} \times W_{tiles} + x_{tile}$.
  - Bits [31:0]: Camera coordinate depth $Z_c$, cast to `uint32_t` [S1, unofficial].
- **Value**: 32-bit unsigned integer (`uint32_t`) representing the Gaussian index `idx` [S1, unofficial].

**Steps:**
1. Initialize empty lists `gaussian_keys_unsorted` and `gaussian_values_unsorted`.
2. For each Gaussian index `idx` from $0$ to $N-1$:
   a. If `radii[idx]` $\le 0$, skip to next Gaussian [S1, unofficial].
   b. Calculate the bounding rectangle in tile coordinates:
      $$ x_{min} = \lfloor \frac{x_{idx} - r_{idx}}{tile\_size} \rfloor $$
      $$ x_{max} = \lfloor \frac{x_{idx} + r_{idx}}{tile\_size} \rfloor $$
      $$ y_{min} = \lfloor \frac{y_{idx} - r_{idx}}{tile\_size} \rfloor $$
      $$ y_{max} = \lfloor \frac{y_{idx} + r_{idx}}{tile\_size} \rfloor $$
      Clamp $x_{min}, x_{max}$ to $[0, W_{tiles}-1]$ and $y_{min}, y_{max}$ to $[0, H_{tiles}-1]$ [S1, unofficial].
   c. Iterate over $y_{tile}$ from $y_{min}$ to $y_{max}-1$ and $x_{tile}$ from $x_{min}$ to $x_{max}-1$:
      i. Compute 1D tile ID: $tile\_id = y_{tile} \times W_{tiles} + x_{tile}$.
      ii. Construct key: $key = (tile\_id \ll 32) \mid (\text{uint32\_t})depths[idx]$.
      iii. Append $key$ to `gaussian_keys_unsorted`.
      iv. Append `idx` to `gaussian_values_unsorted` [S1, unofficial].

**Pseudocode:**
```python
def generate_gaussian_keys(points_xy, radii, depths, grid_width, grid_height, tile_size):
    """
    Generates sort keys and values for Gaussian rasterization.
    
    Args:
        points_xy: (N, 2) tensor, screen space centers.
        radii: (N,) tensor, radii in pixels.
        depths: (N,) tensor, camera space depths.
        grid_width: int, number of tiles horizontally.
        grid_height: int, number of tiles vertically.
        tile_size: int, pixels per tile.
        
    Returns:
        keys: (M,) tensor of uint64_t sort keys.
        values: (M,) tensor of uint32_t Gaussian indices.
    """
    N = points_xy.shape[0]
    keys = []
    values = []
    
    for idx in range(N):
        r = radii[idx]
        if r <= 0:
            continue
            
        cx, cy = points_xy[idx]
        depth = depths[idx]
        
        # Calculate bounding rect in tile coordinates
        # Using floor for min, floor for max to cover all touched tiles
        x_min = int((cx - r) // tile_size)
        x_max = int((cx + r) // tile_size)
        y_min = int((cy - r) // tile_size)
        y_max = int((cy + r) // tile_size)
        
        # Clamp to grid bounds
        x_min = max(0, min(x_min, grid_width - 1))
        x_max = max(0, min(x_max, grid_width - 1))
        y_min = max(0, min(y_min, grid_height - 1))
        y_max = max(0, min(y_max, grid_height - 1))
        
        # Iterate over tiles
        for y_tile in range(y_min, y_max + 1):
            for x_tile in range(x_min, x_max + 1):
                tile_id = y_tile * grid_width + x_tile
                
                # Pack key: high 32 bits tile ID, low 32 bits depth
                # Note: Source uses << 32 for tile_id and casts depth to uint32
                key = (tile_id << 32) | (depth & 0xFFFFFFFF)
                
                keys.append(key)
                values.append(idx)
                
    return keys, values
```

**Edge Cases and Pitfalls:**
- **Precision**: Depth must be cast to `uint32_t` consistently. Floating point depth values must be interpreted as unsigned integers for correct sorting order [S1, unofficial].
- **Boundaries**: Tiles outside the image grid must be clamped or ignored to prevent out-of-bounds access [S1, unofficial].
- **Degenerate Input**: Gaussians with radius $\le 0$ are skipped [S1, unofficial].

## Operating characteristics
- **Time Complexity**: $O(N + M)$, where $N$ is the number of Gaussians and $M$ is the number of Gaussian-tile overlaps. The bounding box calculation is $O(1)$ per Gaussian, and iteration is proportional to the number of touched tiles [S1, unofficial].
- **Memory Complexity**: $O(M)$ for storing keys and values. $M$ can be significantly larger than $N$ if Gaussians are large or numerous [S1, unofficial].
- **Strengths**: Enables a single global radix sort for both binning and depth sorting, simplifying the rasterization pipeline [S1, unofficial].
- **Limitations**: Memory usage scales with overlap count. Large Gaussians increase $M$ substantially [S1, unofficial].

## Background
This method is part of the rendering implementation for 3D Gaussian Splatting, specifically within the tiled rasterization framework. It originates from the open-source implementation of Gaussian Splatting rendering on CPU/GPU hybrid architectures [S1, unofficial].
