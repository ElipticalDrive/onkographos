# QuadBox


## Overview
QuadBox is a Gaussian-tile intersection method that uses four axis-aligned bounding boxes (AABBs) to tightly encapsulate projected 2D Gaussians, reducing tile over-approximation and redundant computations in the rasterizer preprocess stage [S1]. It sets itself apart from its siblings by replacing the single conservative AABB (used in standard 3DGS) and the single adaptive AABB (used in AdR-Gaussian) with four adaptive sub-boxes that symmetrically fit the elliptical footprint, thereby suppressing empty tile coverage along the minor axis [S1].

## How it works
**Inputs**: A set of 3D Gaussians, each defined by center $\mu_i$, 3D covariance $\Sigma_i$, opacity $o_i$, and color $c_i$ [S1]. The image plane is partitioned into $16 \times 16$ tiles [S1].
**Outputs**: A list of tile-Gaussian pairs, where each Gaussian is assigned only to the tiles it intersects, ensuring each tile is visited exactly once [S1].

### Data Structures
*   **Gaussian Primitive**: Contains $\mu_i \in \mathbb{R}^3$, $\Sigma_i \in \mathbb{R}^{3 \times 3}$ (or rotation/scale parameters), $o_i \in \mathbb{R}$, $c_i$ [S1].
*   **2D Covariance Inverse ($\Lambda$)**: A $2 \times 2$ symmetric matrix $\Lambda = (\Sigma_i^{2D})^{-1} = \begin{bmatrix} a & b \\ b & c \end{bmatrix}$, derived from the projected 2D covariance $\Sigma_i^{2D}$ [S1].
*   **QuadBox**: Defined by four AABBs. Each AABB is defined by its minimum and maximum coordinates $(x_{min}, y_{min})$ and $(x_{max}, y_{max})$ in screen space [S1].

### Parameters
*   **Opacity Threshold ($\alpha_{\min}$)**: Gaussians with splatted opacity below this value are ignored. Typical value: $1/255$ [S1].
*   **Tile Size**: The image plane is partitioned into $16 \times 16$ tiles [S1].

### Algorithm Steps

#### Phase 1: Initialization
1.  Filter Gaussians with splatted opacity $\alpha < \alpha_{\min}$ to ensure numerical stability [S1].
2.  For each remaining Gaussian, compute the confidence inequality defining the support region:
    $$2 \ln\left(\frac{\theta_i}{\alpha_{\min}}\right) \leq (u - \mu_i^{2D})(\Sigma_i^{2D})^{-1}(u - \mu_i^{2D})^\top$$
    where $\theta_i$ is the opacity, $u$ is the pixel coordinate, $\mu_i^{2D}$ is the 2D Gaussian center, and $\Sigma_i^{2D}$ is the 2D covariance [S1].
3.  Let $\Lambda = (\Sigma_i^{2D})^{-1} = \begin{bmatrix} a & b \\ b & c \end{bmatrix}$ and define centered coordinates $(x_d, y_d) = u - \mu_i^{2D}$. Reformulate the inequality as the ellipse equation:
    $$F(x_d, y_d) = ax_d^2 + 2bx_dy_d + cy_d^2 - \gamma \leq 0$$
    where $\gamma = 2 \ln\left(\frac{\theta_i}{\alpha_{\min}}\right)$ [S1].

#### Phase 2: DualBox Extraction
1.  Compute the axis intercepts of the ellipse:
    $$y_{\text{inter}} = \sqrt{\gamma/c}, \quad x_{\text{inter}} = \sqrt{\gamma/a}$$
    These are derived by setting $x_d=0$ and $y_d=0$ respectively in the ellipse equation [S1].
2.  Compute the maximal support extents along the coordinate axes using the inverse matrix $\Lambda^{-1}$:
    $$\Lambda^{-1} = \frac{1}{ac - b^2} \begin{bmatrix} c & -b \\ -b & a \end{bmatrix}$$
    $$y_{\max} = \sqrt{\frac{\gamma a}{ac - b^2}}, \quad x_{\max} = \sqrt{\frac{\gamma c}{ac - b^2}}$$
    [S1]
3.  Compute the stretching factor $f$:
    $$f = \sqrt{1 - \frac{b^2}{ac}}$$
    This factor depends only on the entries $a, b, c$ of $\Lambda$ and is independent of $\gamma$ and center translation. Note that $0 < f \leq 1$ [S1].
4.  Extract the DualBox by retaining only the two quadrants of the AdR-AABB aligned with the ellipse's major axis. This suppresses empty tile coverage along the minor axis [S1].

#### Phase 3: QuadBox Construction
1.  Construct four adaptive AABBs symmetrically positioned around the Gaussian center.
2.  Stretch the sub-boxes using the factor $f$ to tightly enclose the parts of the ellipse not covered by the DualBox. The stretching ensures the boxes are conservative but tight [S1].

#### Phase 4: QPass Tile Traversal
1.  **Global Range**: Compute the global tile range using simple integer divisions based on the QuadBox bounds [S1].
2.  **Scanline Aggregation**: Scan along the shorter axis. For each scanline, aggregate the active tile interval using fast min/max tests over the intersecting sub-boxes [S1].
3.  **Tile Intersection**: Perform tile intersection checks using simple interval tests (integer comparisons) for each tile in the aggregated range. This ensures each tile is visited exactly once [S1].

    """
    # Phase 1: Initialization
    alpha_min = 1.0 / 255.0

        return []

    # Compute Lambda = (Sigma_2D)^-1
    # Sigma_2D is a 2x2 matrix [[s11, s12], [s21, s22]]
    s11, s12, s21, s22 = gaussian.Sigma_2D
    det = s11 * s22 - s12 * s21
    # Lambda entries a, b, c
    a = s22 / det
    b = -s12 / det
    c = s11 / det
    
    # Gamma threshold
    gamma = 2.0 * math.log(gaussian.opacity / alpha_min)
    
    # Phase 2 & 3: Compute Stretching Factor and Bounds
    # f = sqrt(1 - b^2 / (a*c))
    # Note: a, c > 0 and ac - b^2 > 0 for positive definite Lambda
    f = math.sqrt(1.0 - (b * b) / (a * c))
    
    # Compute maximal extents

    denom = a * c - b * b

### Edge Cases and Pitfalls
*   **Numerical Stability**: Gaussians with very low opacity can cause instability. Handled by filtering Gaussians with opacity $\alpha < \alpha_{\min}$ [S1].
*   **Computational Overhead**: Excessive use of square roots ($\sqrt{}$) and division operations inflates computational overhead. The method derives a purely algebraic closed form for $f$ that avoids these operations where possible [S1].
*   **Warp Divergence**: Naive iteration over sub-boxes causes redundant tile checks and warp divergence. QPass aggregates intervals to avoid this [S1].

## Operating characteristics
*   **Time Complexity**: The preprocessing stage is $O(N)$ where $N$ is the number of Gaussians, as the QuadBox construction is executed once per Gaussian. The tile traversal is $O(T)$ where $T$ is the number of tiles visited, which is significantly reduced compared to standard 3DGS due to tighter bounding boxes [S1].
*   **Memory Complexity**: The method requires storing the 4 AABBs per Gaussian, which is a constant overhead per Gaussian [S1].
*   **Measured Performance**: QuadBox achieves an average over 1.8× speedup compared to 3DGS on Mip-NeRF 360, Tanks & Temples, and Deep Blending datasets [S1]. It outperforms AdR-Gaussian's AABB algorithm by 1.85× [S1].
*   **Strengths**: Reduces tile over-approximation, minimizes redundant computations, and provides a deterministic, cache-friendly scan [S1].
*   **Limitations**: The method is specific to the Gaussian Splatting rasterization pipeline and may not be directly applicable to other volume rendering techniques without adaptation [S1].

## Background
QuadBox was introduced in the paper "QuadBox: Accelerating 3D Gaussian Splatting with Geometry-Aware Boxes" [S1]. It addresses the inefficiency of standard 3DGS rasterization, where conservative bounding boxes cover many tiles that receive no actual splats. The method builds on the concept of adaptive bounding boxes, specifically improving upon AdR-Gaussian by using four sub-boxes instead of one to better fit the anisotropic shape of the Gaussian projection [S1].
