# 3D Gaussian Splatting Rasterization

Also called: 3DGS Rasterization, Differentiable Gaussian Rasterization, TrimGS, gsplat.rasterization

## Overview
3D Gaussian Splatting Rasterization is a differentiable rendering technique that represents a scene as a set of 3D Gaussians and rasterizes them to 2D images by projecting 3D covariances to 2D screen covariances, sorting by depth, and compositing colors based on alpha and transmittance [S2, S3, unofficial]. It serves as the core rendering engine for training and inference in 3D Gaussian Splatting, enabling gradient-based optimization of Gaussian parameters (position, covariance, opacity, color) and camera poses [S4, unofficial][S5]. Unlike traditional triangle rasterization, it uses direct Gaussian projection and alpha blending, offering photorealistic quality at real-time speeds but requiring significant VRAM and specialized sorting hardware [S3, unofficial].

## How it works
**Inputs:**
*   `means_3D`: $[N, 3]$ tensor of 3D Gaussian centers.
*   `quats`: $[N, 4]$ tensor of unit quaternions $(w, x, y, z)$ representing rotation.
*   `scales`: $[N, 3]$ tensor of Gaussian scales.
*   `opacities`: $[N]$ tensor of scalar opacity values.
*   `colors`: $[N, D]$ tensor of color coefficients (RGB or SH coefficients).
*   `viewmats`: $[C, 4, 4]$ camera-to-world transformation matrices for $C$ cameras.
*   `Ks`: $[C, 3, 3]$ camera intrinsic matrices.
*   `width`, `height`: Image dimensions in pixels.
*   `tile_size`: Integer, default 16. Side length of tiles for rasterization [S1, unofficial].
*   `near_plane`, `far_plane`: Floats, default 0.01 and $10^{10}$. Clipping distances [S1, unofficial].
*   `sh_degree`: Integer or None. If not None, enables spherical harmonics color computation [S1, unofficial].
*   `render_mode`: String specifying output channels: "RGB", "D", "ED", "RGB+D", "RGB+ED", "d", "Ed", "RGB+d", "RGB+Ed" [S1, unofficial].
*   `rasterize_mode`: String: "classic" or "antialiased" [S1, unofficial].
*   `camera_model`: String: "pinhole", "ortho", "fisheye" [S1, unofficial].
*   `backgrounds`: $[C, 3]$ tensor of background colors.

**Outputs:**
*   `render_colors`: $[C, H, W, D]$ tensor of rendered colors.
*   `render_alphas`: $[C, H, W, 1]$ tensor of accumulated alpha.
*   `info`: Dictionary containing `radii`, `means2D`, `depths`, `conics`, `compensations` [S1, unofficial].

**Data Structures:**
*   **Conic**: Precomputed inverse 2D covariance stored as a vector $[\Sigma_{2D}^{-1}[0,0], \Sigma_{2D}^{-1}[0,1], \Sigma_{2D}^{-1}[1,1]]$ [S1, unofficial].
*   **Tile Intersection**: `isect_offsets` $[C, tile\_height, tile\_width]$ encoding which Gaussians intersect which tiles [S1, unofficial].
*   **Flattened IDs**: `flatten_ids` mapping tile-local Gaussian indices to global Gaussian indices [S1, unofficial].

**Steps:**

1.  **Input Validation**: Check `render_mode`, `rasterize_mode`, and `camera_model` against valid sets [S1, unofficial].
2.  **Covariance Construction**: Compute the 3D covariance matrix $\Sigma_{3D}$ from `quats` and `scales`. This is typically done via `quat_scale_to_covar_preci` with `compute_covar=True`, `compute_preci=False`, `triu=False`, resulting in shape $[N, 3, 3]$ [S1, S2, unofficial].
3.  **3D to 2D Projection**:
    *   Transform `means_3D` to camera space using `viewmats` [S1, unofficial].
    *   Project `means_3D` and $\Sigma_{3D}$ to 2D screen space using camera intrinsics `Ks` and image size. This uses a local affine approximation of the projective transformation. The Jacobian $J$ of the projection function is evaluated at the camera-space mean $\mu'$ [S2, unofficial].
    *   Compute 2D covariance: $\Sigma_{2D} = J \Sigma' J^T$ [S2, unofficial].
    *   Compute the **Conic** vector from $\Sigma_{2D}^{-1}$ [S1, unofficial].
    *   Compute **Radii** (bounding box size) using the 3-sigma rule: $\text{bboxsize\_cam} = [3.0 \sqrt{\Sigma_{2D}[0,0]}, 3.0 \sqrt{\Sigma_{2D}[1,1]}]$ [S1, unofficial].
    *   Compute **Depths** (camera-space z-distance) [S1, unofficial].
4.  **Tile Intersection**:
    *   Compute tile dimensions: $tile\_width = \lceil width / tile\_size \rceil$, $tile\_height = \lceil height / tile\_size \rceil$ [S1, unofficial].
    *   Identify which Gaussians intersect which tiles using `isect_tiles`. This returns `tiles_per_gauss`, `isect_ids`, and `flatten_ids` [S1, unofficial].
    *   Encode intersection offsets: `isect_offsets = isect_offset_encode(isect_ids, C, tile_width, tile_height)` [S1, unofficial].
5.  **Color Computation (Spherical Harmonics)**:
    *   If `sh_degree` is not None:
        *   Compute view directions: $\text{dirs} = \text{means}[None, :, :] - \text{campos}[:, None, :]$ [S1, unofficial].
        *   Normalize directions: $\text{dirs} = \text{dirs} / \max(\|\text{dirs}\|, 10^{-8})$ [S1, unofficial].
        *   Broadcast color coefficients to $[C, N, K, 3]$ [S1, unofficial].
        *   Evaluate Spherical Harmonics: $\text{rgb} = \text{spherical\_harmonics}(sh\_degree, \text{dirs}, \text{coeffs})$ [S1, unofficial].
        *   Clamp: $\text{rgb} = \max(\text{rgb} + 0.5, 0.0)$ [S1, unofficial].
    *   If `sh_degree` is None, broadcast `colors` to $[C, N, D]$ [S1, unofficial].
6.  **Opacity and Compensation**:
    *   Broadcast scalar `opacities` $[N]$ to $[C, N]$ [S1, unofficial].
    *   If `rasterize_mode` is "antialiased", multiply opacities by precomputed `compensations` [S1, unofficial].
7.  **Depth Sorting and Culling**:
    *   Filter Gaussians behind the camera: $\text{mask} = \text{depths} \ge 0.0$ [S2, unofficial].
    *   Sort remaining Gaussians by depth (front-to-back) using a radix sort (e.g., CUB) [S2, S3, unofficial].
8.  **Rasterization (Pixel Compositing)**:
    *   For each pixel in each tile:
        *   Retrieve the list of intersecting Gaussians from `isect_offsets` and `flatten_ids` [S1, unofficial].
        *   Iterate through Gaussians front-to-back.
        *   Compute 2D Gaussian value $G_{2D}$ at the pixel using the Conic [S2, unofficial].
        *   Compute Alpha: $\alpha_i = \text{opacity}_i \times G_{2D}$ [S2, unofficial].
        *   Compute Transmittance: $T_i = \prod_{j=1}^{i-1} (1 - \alpha_j)$ [S2, unofficial].
        *   Compute Weight: $w_i = \alpha_i T_i$ [S2, unofficial].
        *   Accumulate Color: $C_{pixel} += w_i \times \text{color}_i$ [S2, unofficial].
        *   Accumulate Alpha: $A_{pixel} += w_i$ [S2, unofficial].
    *   Composite Background: $\text{image} = A_{pixel} \times C_{pixel} + (1.0 - A_{pixel}) \times \text{background}$ [S2, unofficial].
9.  **Post-Processing**:
    *   If `render_mode` includes depth ("D", "ED", etc.):
        *   Compute weighted depth: $\text{depth} = \sum (\text{depth}_i \times w_i)$ [S2, unofficial].
        *   Normalize by alpha: $\text{depth\_channel} = \text{depth} / \max(A_{pixel}, 10^{-10})$ [S1, unofficial].
        *   Concatenate to color channels if `has_color` [S1, unofficial].

**Pseudocode:**

```python
def rasterize_gaussians(
    means_3d, quats, scales, opacities, colors,
    viewmats, Ks, width, height,
    tile_size=16, near_plane=0.01, far_plane=1e10,
    sh_degree=None, render_mode="RGB", rasterize_mode="classic",
    camera_model="pinhole", backgrounds=None
):
    # 1. Covariance Construction
    # cov_3D shape: [N, 3, 3]
    cov_3d = quat_scale_to_covar(quats, scales)
    
    # 2. 3D to 2D Projection
    # Project means and covariances to 2D screen space
    # means_2d shape: [C, N, 2]
    # cov_2d shape: [C, N, 2, 2]
    # depths shape: [C, N]
    # radii shape: [C, N, 2]
    means_2d, cov_2d, depths, radii, conics, compensations = linearized_project(
        means_3d, cov_3d, viewmats, Ks, width, height, 
        near_plane, far_plane, rasterize_mode == "antialiased"
    )
    
    # 3. Tile Intersection
    tile_width = ceil(width / tile_size)
    tile_height = ceil(height / tile_size)
    isect_offsets, flatten_ids = isect_tiles(
        means_2d, radii, depths, tile_size, tile_width, tile_height
    )
    
    # 4. Color Computation
    if sh_degree is not None:
        # Compute view directions
        campos = viewmats[:, :3, 3] # [C, 3]
        dirs = means_3d[None, :, :] - campos[:, None, :] # [C, N, 3]
        dirs_norm = mx.maximum(linalg.norm(dirs, axis=-1, keepdims=True), 1e-8)
        dirs = dirs / dirs_norm
        # Broadcast SH coefficients
        coeffs = broadcast_to(colors, (len(viewmats), len(colors), sh_degree + 1, 3))
        # Evaluate SH
        rgb = spherical_harmonics(sh_degree, dirs, coeffs)
        rgb = mx.maximum(rgb + 0.5, 0.0)
    else:
        rgb = broadcast_to(colors, (len(viewmats), len(colors), colors.shape[-1]))
        
    # 5. Opacity and Compensation
    opacities_cn = mx.broadcast_to(mx.expand_dims(opacities, 0), (len(viewmats), len(opacities)))
    if rasterize_mode == "antialiased" and compensations is not None:
        opacities_cn = opacities_cn * compensations
        
    # 6. Prepare Colors for Rasterization
    # Concatenate depth if required by render_mode
    dist_channel = None
    if "D" in render_mode:
        dist_channel = depths
    elif "d" in render_mode:
        # Hit distance in camera space
        R = viewmats[:, :3, :3]
        t = viewmats[:, :3, 3]
        means_c = einsum("cij,nj->cni", R, means_3d) + t[:, None, :]
        dist_channel = sqrt(sum(means_c * means_c, axis=-1))
        
    if dist_channel is not None:
        colors_for_raster = concatenate([rgb, dist_channel[..., None]], axis=-1)
    else:
        colors_for_raster = rgb
        
    # 7. Rasterize
    # This step involves tile-based iteration and front-to-back blending
    render_colors, render_alphas = rasterize_to_pixels(
        means_2d, conics, colors_for_raster, opacities_cn,
        width, height, tile_size, isect_offsets, flatten_ids,
        backgrounds if backgrounds is not None else mx.ones((len(viewmats), 3))
    )
    
    # 8. Post-Processing for Depth
    if "D" in render_mode or "d" in render_mode:
        # Normalize accumulated depth by alpha
        depth_channel = render_colors[..., -1] / mx.maximum(render_alphas[..., 0], 1e-10)
        # Replace or concatenate back depending on render_mode
        if "RGB" in render_mode:
            # Replace the last channel if it was depth, or append if not
            # Implementation detail depends on exact render_mode string parsing
            pass
        else:
            render_colors = depth_channel[..., None]
            
    return render_colors, render_alphas
```

## Subtopics

### [3D Gaussian Splatting Differentiable Rasterizer](2813-3d-gaussian-splatting-differentiable-rasterizer.md)
The core rendering engine that projects 3D Gaussians to 2D and composites colors, enabling gradient-based optimization. It differs from siblings by providing specific differentiable forward and backward passes required for training.

### [Optimal Gaussian Splatting](3293-optimal-gaussian-splatting.md)
Reduces projection error by radially projecting each 3D Gaussian onto a unique tangent plane perpendicular to the line connecting the Gaussian mean to the camera center, rather than projecting all Gaussians onto a single plane $z=1$.

### [Hybrid Transparency](3294-hybrid-transparency.md)
Combines depth-ordered alpha blending for the first $K$ fragments with order-independent accumulation for the remaining fragments to mitigate popping artifacts while maintaining real-time performance.

### [Perspective-Correct 3D Gaussian Splatting via Plücker Coordinates](3403-perspective-correct-3d-gaussian-splatting-via-pl-cker-coordi.md)
Computes the value of a 3D Gaussian primitive for a given viewing ray in screen space without performing matrix inversion, utilizing Plücker coordinates to represent the ray and calculate the distance to the Gaussian's center.

### [3D Gaussian Splatting Rasterization (Cone-Beam/Scanner Space)](3458-3d-gaussian-splatting-rasterization-cone-beam-scanner-space.md)
Renders X-ray projections from a 3D Gaussian representation by integrating the 3D Gaussian density along cone-beam ray paths, resulting in a sum of 2D Gaussians rather than alpha-compositing.

### [Analytic-Splatting Forward Shading](3459-analytic-splatting-forward-shading.md)
Computes the color contribution of 3D Gaussians to a pixel by analytically integrating the Gaussian probability density function over the pixel area, rather than sampling the center.

### [Speedy-Splat Rendering Pipeline](3543-speedy-splat-rendering-pipeline.md)
Replaces coarse bounding-box tile intersection tests with precise Gaussian-tile intersection checks and sorting-based depth ordering to address inefficiency in standard 3D-GS rasterization.

### [Ghost Ellipsoids for Chunked Training](3559-ghost-ellipsoids-for-chunked-training.md)
Resolves boundary artifacts in chunked volume training by including ellipsoids from neighboring chunks in the loss computation without updating their parameters.

### [Analytic Transmittance 3DGS](4440-analytic-transmittance-3dgs.md)
Replaces the approximate alpha computation of standard 3DGS with an analytic integration of the volume rendering equation along the camera ray, avoiding the linearization of exponential transmittance.

### [Ref-Gaussian Deferred Surfel Rendering with Split-Sum IBL](4464-ref-gaussian-deferred-surfel-rendering-with-split-sum-ibl.md)
A real-time deferred shading method for relighting 3DGS models on mobile hardware, decomposing splats into PBR materials and computing lighting via a deferred pipeline.

### [3D Gaussian Splatting Self-Shadowing (T_light)](4487-3d-gaussian-splatting-self-shadowing-t-light.md)
Calculates the self-shadowing transmittance $T_{light}$ for each Gaussian along a directional sun direction, representing the 'front occlusion transmittance'.

### [Light Space Rasterization for T_light](4489-light-space-rasterization-for-t-light.md)
Computes $T_{light}$, the front-facing occlusion transmittance for each 3D Gaussian along a directional sun direction, providing full continuous gradients and zero parameter expansion.

### [2D Gaussian Splatting Rasterization](4815-2d-gaussian-splatting-rasterization.md)
Renders scene primitives as 2D Gaussian surfels by performing explicit ray-surfel intersection tests per pixel, rather than projecting 3D ellipsoids to screen space.

### [SparseOIT Rasterizer](7562-sparseoit-rasterizer.md)
Computes a blended image using Order-Independent Transparency (OIT) without sorting Gaussians by depth, eliminating the sorting step entirely in favor of a weighted average.

### [AdR-Gaussian](8365-adr-gaussian.md)
Optimizes the rasterization pipeline by moving serial culling operations to a parallel preprocessing stage and balancing computational loads across pixel threads.

### [3D Half-Gaussian Splatting](9011-3d-half-gaussian-splatting.md)
Replaces the standard isotropic Gaussian with a half-space truncated Gaussian to resolve shape and color discontinuities (Gibbs phenomenon) at object boundaries.

### [3D Gaussian Unscented Transform (3DGUT)](9154-3d-gaussian-unscented-transform-3dgut.md)
Replaces the standard Elliptical Weighted Average (EWA) splatting formulation with the Unscented Transform (UT) to solve approximation errors and Jacobian derivation complexity in non-linear camera models.

### Panorama Camera Adaptation
Adapts the rasterization projection for panoramic images by mapping pixel coordinates to the unit sphere using the formula $\mathbf{x}_{2D} = \varphi_p \left( \begin{bmatrix} \sin \left( \frac{\pi(-W+2u)}{W} \right) \cos \left( \frac{\pi(-\frac{H}{2}+v)}{H} \right) \\ \sin \left( \frac{\pi(-\frac{H}{2}+v)}{H} \right) \\ \cos \left( \frac{\pi(-\frac{H}{2}+v)}{H} \right) \cos \left( \frac{\pi(-W+2u)}{W} \right) \end{bmatrix} \right)$ where $H$ and $W$ are image height and width [S5].

### Temporal Marginal Probability Filtering
Pre-rasterization culling step that removes 4D Gaussians with negligible temporal support at the current frame timestamp, stabilizing rendering speed across video length by keeping active Gaussians constant [S6, unofficial].

### t-distribution truncation for splatting
Replaces the fixed three-sigma rule with a $\nu$-dependent critical value interpolation to handle fat-tailed Student's t-distributions, preventing excessive truncation or leakage [S7].

### Gaussian Opacity Fields (GOF)
Uses ray-tracing-style intersection for accurate depth and derives a level-set surface from accumulated opacity [S4, unofficial].

### Progressive Normal Propagation
Uses progressive propagation along normals to fill texture-less regions [S4, unofficial].

### Gaussian Surfels
Uses zero-thickness oriented surfels [S4, unofficial].

### Hardware-Accelerated Gaussian Rasterization
A hardware-algorithm co-design that augments standard triangle rasterizers with dedicated units for Gaussian projection and blending, achieving an order of magnitude speedup [S8, unofficial].

## Operating characteristics
*   **Time Complexity**: Dominated by the sorting step, which is $O(N \log N)$ for $N$ Gaussians. The original implementation uses CUB device radix sort, which is highly optimized but CUDA-specific [S3, unofficial]. Tile-based rasterization reduces the number of pixels processed per Gaussian, making the effective complexity closer to $O(P)$ where $P$ is the number of pixels covered by Gaussians.
*   **Memory Complexity**: High VRAM usage. Requires 4GB to view and 12GB to train for typical scenes [S3, unofficial]. Large disk size, often 1GB+ for a scene [S3, unofficial]. Memory is consumed by storing Gaussian parameters, intermediate projection data, and tile intersection structures.
*   **Performance**: Real-time rendering speeds are achievable on modern GPUs (e.g., RTX 3090/4090) for scenes with millions of Gaussians at 1080p resolution [S3, unofficial].
*   **Strengths**: Photorealistic quality, real-time rendering, differentiable for training.
*   **Limitations**: High VRAM usage, large storage requirements, dependency on CUDA for optimal sorting performance, incompatibility with some existing rendering pipelines (WebGL, Unity) without adaptation [S3, unofficial].
*   **When to use**: Real-time rendering of learned 3D scenes, training of Gaussian representations.
*   **When not to use**: Environments with strict memory constraints, non-CUDA hardware without optimized ports, or when compatibility with standard triangle-based pipelines is required without significant adaptation [S3, unofficial].

## Background
3D Gaussian Splatting was introduced in the paper "3D Gaussian Splatting for Real-Time Radiance Field Rendering" [S3, unofficial]. It is a rasterization technique analogous to triangle rasterization but uses Gaussians instead of triangles [S3, unofficial]. The method allows real-time rendering of photorealistic scenes learned from small samples of images [S3, unofficial]. The primary bottleneck identified is the sorting of millions of Gaussians, which is efficiently handled by CUB device radix sort in the original CUDA implementation [S3, unofficial]. The technique has spawned numerous variants and adaptations, including differentiable rasterizers, hardware acceleration, and support for various camera models [S4, S8, unofficial].
