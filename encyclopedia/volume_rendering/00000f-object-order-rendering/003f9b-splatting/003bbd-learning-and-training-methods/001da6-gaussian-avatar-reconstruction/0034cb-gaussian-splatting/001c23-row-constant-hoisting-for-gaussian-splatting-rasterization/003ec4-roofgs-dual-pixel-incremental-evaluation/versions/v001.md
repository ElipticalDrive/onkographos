# RoofGS Dual-Pixel Incremental Evaluation

Also called: RoofGS dual-pixel formulation, RoofGS vertical coherence optimization

## Overview
An optimization that exploits spatial coherence between vertically adjacent pixels by assigning each thread to process two pixels, $(x, y)$ and $(x, y+1)$, allowing reuse of shared-memory attribute loads and incremental exponent calculation [S1, unofficial]. It sets itself apart from standard single-pixel rasterization by halving shared-memory traffic and replacing the second pixel's full exponent evaluation with a lightweight incremental update [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** The folded exponent $P(x, y)$ for the first pixel $(x, y)$, the Gaussian coefficients $C_2, C_3, C_5$, and the pixel coordinates $x, y$.
*   **Output:** The folded exponent $P(x, y+1)$ for the second pixel $(x, y+1)$.

**Data Structures:**
*   **Registers:** Store the current pixel coordinates $x, y$ and the Gaussian coefficients $C_2, C_3, C_5$ [S1, unofficial].
*   **Shared Memory:** Stores Gaussian attributes (e.g., position, covariance, SH coefficients) loaded once per tile [S1, unofficial].

**Numbered Steps:**
1.  **Thread Assignment:** Assign each thread to process two vertically adjacent pixels: $(x, y)$ and $(x, y+1)$. Both pixels traverse the same Gaussian sequence within a tile [S1, unofficial].
2.  **Attribute Load Reuse:** Load Gaussian attributes from shared memory once. This single load serves both vertically adjacent pixels, halving per-pixel shared-memory traffic [S1, unofficial].
3.  **First Pixel Exponent:** Compute the exponent $P(x, y)$ for the first pixel using the regular FMA path (as defined in the parent article's Eq. 16) [S1, unofficial].
4.  **Incremental Update:** Compute the exponent $P(x, y+1)$ for the second pixel using the incremental formula derived from $P(x, y)$ [S1, unofficial].

**Formulas:**
Let $P(x, y)$ be the folded exponent for pixel $(x, y)$. The exponent for the adjacent pixel $(x, y+1)$ is calculated as:

$$
P(x, y + 1) = P(x, y) + C_2x + C_3(2y + 1) + C_5
$$

Where:
*   $C_2, C_3, C_5$ are pre-folded Gaussian coefficients [S1, unofficial].
*   $x, y$ are the coordinates of the first pixel [S1, unofficial].

**Pseudocode:**
```python
def roofgs_dual_pixel_eval(P_xy, C2, C3, C5, x, y):
    """
    Computes the exponent for the second pixel (x, y+1) given the first pixel's exponent.
    
    Args:
        P_xy (float): The folded exponent P(x, y) for the first pixel.
        C2 (float): Coefficient C2.
        C3 (float): Coefficient C3.
        C5 (float): Coefficient C5.
        x (int): X-coordinate of the first pixel.
        y (int): Y-coordinate of the first pixel.
        
    Returns:
        float: The folded exponent P(x, y+1) for the second pixel.
    """
    # Incremental update formula: P(x, y+1) = P(x, y) + C2*x + C3*(2*y + 1) + C5
    P_xy1 = P_xy + C2 * x + C3 * (2 * y + 1) + C5
    return P_xy1
```

**Parameters:**
*   **Tile Size:** Not given in the sources.
*   **Resolution:** Evaluated at 4K resolution [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Boundary Conditions:** If $y$ is the last row of the tile, the second pixel $(x, y+1)$ may be out of bounds. The implementation must check if the second pixel is within the valid image/tile range before performing the incremental update or blending [G].
*   **Precision:** The incremental update involves additions of potentially different magnitudes. Care should be taken to maintain numerical stability, though the sources do not specify specific precision requirements [G].

## Subtopics

### Dual-pixel evaluation
A rasterization optimization that evaluates two adjacent pixels to improve instruction-level parallelism [S1, unofficial]. It is chosen when vertical coherence can be exploited to reduce memory bandwidth and arithmetic operations. It is a core component of the RoofGS method.

## Operating characteristics
*   **Time Complexity:** Reduces arithmetic operations per pixel by avoiding re-evaluation of the full dot product for the second pixel [S1, unofficial].
*   **Memory Complexity:** Halves per-pixel shared-memory traffic by reusing attribute loads for vertically adjacent pixels [S1, unofficial].
*   **Measured Performance:** At 4K resolution on an NVIDIA RTX 4090 GPU, RoofGS increases average rendering throughput [S1, unofficial].
*   **Strengths:** Reduces redundant arithmetic instructions and on-chip memory accesses in the innermost blending loop. Improves instruction scheduling and instruction-level parallelism (ILP) within the rasterization core [S1, unofficial].
*   **Limitations:** Requires vertical coherence between pixels. May not benefit scenes with high vertical discontinuity or specific memory access patterns that do not align with the dual-pixel assignment [G].
*   **When to Use:** When rendering 3D Gaussian Splatting scenes on GPUs where shared-memory bandwidth and arithmetic throughput are bottlenecks [S1, unofficial].
*   **When Not to Use:** When the overhead of managing dual-pixel threads outweighs the benefits, or on hardware with very high shared-memory bandwidth relative to arithmetic throughput [G].
