# Row-constant hoisting for Gaussian Splatting Rasterization

Also called: row-constant optimization, inner-loop hoisting

## Overview
Row-constant hoisting is an optimization for the inner pixel loop of a Gaussian splatting rasterizer that hoists row-constant terms outside the inner (column) loop to minimize arithmetic operations per pixel [S1, unofficial]. It reduces the computational cost of evaluating the 2D Gaussian exponent by precomputing terms dependent only on the row coordinate, allowing the inner loop to perform fewer multiplications and additions per column [S1, unofficial]. This method is a specific implementation detail within the broader [Gaussian Splatting](946-gaussian-splatting.md) rendering pipeline, distinct from higher-level optimizations like [Contribution-based ordering](8748-contribution-based-ordering.md) or [RoofGS Dual-Pixel Incremental Evaluation](9827-roofgs-dual-pixel-incremental-evaluation.md).

## How it works
**Inputs and Outputs:**
- **Input:** A projected 2D Gaussian primitive $p$ with screen-space center $(s_x, s_y)$, inverse covariance matrix elements $a, b, d$ (where $a = \Sigma^{-1}_{00}, b = \Sigma^{-1}_{01} = \Sigma^{-1}_{10}, d = \Sigma^{-1}_{11}$), opacity $\alpha_p$, and color $\mathbf{c}_p$. The bounding box of the splat $[x_0, y_0, x_1, y_1]$ is precomputed.
- **Input:** A framebuffer `fb` of width $w$, where each cell stores an accumulated color $\mathbf{C}$ and accumulated opacity $\alpha_{acc}$.
- **Input:** Parameters `saturation` (max accumulated opacity) and `alpha_threshold` (min alpha for contribution).
- **Output:** Updated framebuffer cells within the splat's bounding box.

**Data Structures:**
- **Framebuffer Cell:** A tuple $(\mathbf{Vec3}, f32)$ storing accumulated color and opacity [S1, unofficial].
- **Projected Gaussian:** Contains screen position, bounding box, inverse covariance components, opacity, and color [S1, unofficial].

**Steps:**
1. Extract inverse covariance elements $a, b, d$ from the projected Gaussian's inverse covariance matrix [S1, unofficial].
2. Compute coefficients for the quadratic form of the Gaussian exponent:
   - $dx_{coeff} = -0.5 \cdot a$
   - $dy_{coeff} = -0.5 \cdot d$
   - $cross_{coeff} = -b$ (derived from $-0.5 \cdot 2b$) [S1, unofficial]
3. Initialize loop bounds $y$ from $y_0$ to $y_1$ inclusive [S1, unofficial].
4. For each row $p_y$ in the outer loop:
   - Compute $dy = p_y - s_y$ [S1, unofficial].
   - Precompute row-constant terms:
     - $row_{base} = dy_{coeff} \cdot dy^2$
     - $row_{slope} = cross_{coeff} \cdot dy$
     - $row_{offset} = p_y \cdot w$ (for framebuffer indexing) [S1, unofficial]
5. For each column $p_x$ in the inner loop (from $x_0$ to $x_1$):
   - Calculate framebuffer index $idx = row_{offset} + p_x$ [S1, unofficial].
   - Check saturation: if $fb[idx].\alpha_{acc} \ge saturation$, skip to next pixel [S1, unofficial].
   - Compute $dx = p_x - s_x$ [S1, unofficial].
   - Calculate the Gaussian exponent power using hoisted coefficients:
     $$power = dx_{coeff} \cdot dx^2 + row_{slope} \cdot dx + row_{base}$$ [S1, unofficial]
   - If $power > 0.0$, skip the pixel (exponential would exceed valid range) [S1, unofficial].
   - Compute alpha: $\alpha = (\alpha_p \cdot e^{power}).\min(0.999)$ [S1, unofficial].
   - If $\alpha < alpha_{threshold}$, skip the pixel [S1, unofficial].
   - Compute contribution: $t = 1.0 - fb[idx].\alpha_{acc}$, $contrib = t \cdot \alpha$ [S1, unofficial].
   - Update framebuffer:
     - $fb[idx].\mathbf{C} \leftarrow fb[idx].\mathbf{C} + contrib \cdot \mathbf{c}_p$
     - $fb[idx].\alpha_{acc} \leftarrow fb[idx].\alpha_{acc} + contrib$ [S1, unofficial]

**Pseudocode:**
```python
def composite_splat(p: Projected, fb: List[Tuple[Vec3, float]], w: int, params: RenderParams):
    """
    Composite a single 2D Gaussian splat into the framebuffer using row-constant hoisting.
    
    Args:
        p: Projected Gaussian with attributes:
            bbox: [x0, y0, x1, y1] (integers)
            cov2d_inv: Inverse covariance matrix elements
                x_axis.x: a (Sigma^-1_00)
                x_axis.y: b (Sigma^-1_01)
                y_axis.y: d (Sigma^-1_11)
            screen: (sx, sy) (floats)
            opacity: alpha_p (float)
            color: c_p (Vec3)
        fb: Framebuffer list of (color: Vec3, alpha: float) tuples
        w: Framebuffer width
        params: Render parameters including saturation and alpha_threshold
    """
    # Extract bounding box
    x0, y0, x1, y1 = p.bbox
    
    # Extract inverse covariance elements
    a = p.cov2d_inv.x_axis.x
    b = p.cov2d_inv.x_axis.y
    d = p.cov2d_inv.y_axis.y
    
    # Precompute coefficients for the quadratic form
    dx_coeff = -0.5 * a
    dy_coeff = -0.5 * d
    cross_coeff = -b  # Equivalent to -0.5 * 2 * b
    
    # Extract parameters
    saturation = params.saturation
    alpha_threshold = params.alpha_threshold
    opacity = p.opacity
    color = p.color
    sx = p.screen.x
    sy = p.screen.y
    
    # Outer loop over rows
    for py in range(y0, y1 + 1):
        # Compute row-constant terms
        dy = py - sy
        row_base = dy_coeff * dy * dy
        row_slope = cross_coeff * dy
        row_offset = py * w
        
        # Inner loop over columns
        for px in range(x0, x1 + 1):
            idx = row_offset + px
            cell = fb[idx]
            
            # Check saturation
            if cell[1] >= saturation:
                continue
            
            # Compute column offset
            dx = px - sx
            
            # Calculate power using hoisted row constants
            power = dx_coeff * dx * dx + row_slope * dx + row_base
            
            # Skip if power is positive (exponential > 1)
            if power > 0.0:
                continue
            
            # Compute alpha with clamping
            alpha = min(opacity * fast_exp(power), 0.999)
            
            # Skip if alpha is below threshold
            if alpha < alpha_threshold:
                continue
            
            # Compute contribution
            t = 1.0 - cell[1]
            contrib = t * alpha
            
            # Update framebuffer
            fb[idx] = (
                cell[0] + contrib * color,
                cell[1] + contrib
            )
```

**Parameters:**
- `saturation`: Maximum accumulated opacity value in the framebuffer cell. If reached, further splats are skipped [S1, unofficial].
- `alpha_threshold`: Minimum alpha value for a splat to contribute. Splats with alpha below this are skipped [S1, unofficial].

**Edge Cases and Pitfalls:**
- If the computed `power` is positive, the exponential term would exceed 1 (or be invalid for the Gaussian model), so the splat is skipped [S1, unofficial].
- Alpha is clamped to 0.999 to prevent numerical issues when blending [S1, unofficial].

## Subtopics

### [RoofGS Dual-Pixel Incremental Evaluation](9827-roofgs-dual-pixel-incremental-evaluation.md)
An optimization that exploits spatial coherence between vertically adjacent pixels by assigning each thread to process two pixels, $(x, y)$ and $(x, y+1)$, allowing reuse of shared-memory attribute loads and incremental exponent calculation.

## Operating characteristics
**Time and Memory Complexity:**
- The optimization reduces the number of arithmetic operations per pixel in the inner loop by hoisting row-constant calculations. Specifically, it moves the computation of $dy_{coeff} \cdot dy^2$ and $cross_{coeff} \cdot dy$ outside the inner loop [S1, unofficial].
- Memory complexity is unchanged, as it operates on the same framebuffer structure [S1, unofficial].

**Measured Performance:**
- Not given in the sources.

**Scaling:**
- The benefit scales with the number of pixels per splat, as more pixels mean more savings from hoisting row-constant terms [S1, unofficial].

**Strengths and Limitations:**
- **Strengths:** Reduces computational overhead per pixel by minimizing multiplications and additions in the inner loop [S1, unofficial].
- **Limitations:** Requires precomputing row-constant terms for each row, adding a small overhead to the outer loop [S1, unofficial].

**When to Use:**
- Use when optimizing the inner loop of Gaussian splatting rasterization for performance [S1, unofficial].

**When Not to Use:**
- Not applicable as a standalone method; it is an optimization within a larger rasterization pipeline [S1, unofficial].
