# Feed-forward 3D Gaussian Splatting

Also called: Feed-forward Reconstruction Model

## Overview
Feed-forward 3D Gaussian Splatting predicts a complete set of 3D Gaussian primitives directly from a small number of input RGB images without iterative optimization. It solves the problem of slow novel view synthesis by replacing the training phase of standard [Gaussian Splatting](946-gaussian-splatting.md) with a single forward pass through a neural network. It differs from iterative methods by being instantaneous but potentially less accurate, and from other reconstruction models by explicitly outputting Gaussian parameters rather than implicit fields or mesh vertices.

## How it works
**Inputs:** $N$ RGB images of resolution $H \times W$, along with known camera intrinsics and extrinsics.
**Outputs:** A set of $K$ 3D Gaussian primitives, where each primitive $k$ is defined by position $\boldsymbol{\mu}_k \in \mathbb{R}^3$, opacity $\alpha_k \in \mathbb{R}$, rotation $\mathbf{r}_k \in \mathbb{R}^4$ (quaternion), scale $\mathbf{s}_k \in \mathbb{R}^3$, and spherical harmonic coefficients $\mathbf{c}_k \in \mathbb{R}^S$ for view-dependent color. Additionally, a feature vector $\mathbf{F}_k$ is produced for each primitive.

**Data Structures:**
1.  **Patch Features:** A sequence of tokens $\{\mathbf{X}\}$ with shape $[N \times \frac{HW}{p^2}, C]$, where $p$ is the patch size and $C$ is the channel dimension.
2.  **Latent Features:** A sequence of tokens $\{\mathbf{Z}\}$ with the same shape as $\{\mathbf{X}\}$, output by the Transformer.
3.  **Gaussian Primitives:** A list of $K$ primitives, where $K = N \times \frac{HW}{p^2}$. Each primitive contains the geometric parameters and color coefficients.

**Steps:**
1.  **Feature Extraction:** For each of the $N$ input images, extract per-pixel features by concatenating the RGB values with Plücker ray embeddings [S1].
2.  **Patch Encoding:** Group the per-pixel features into non-overlapping $p \times p$ image patches. Encode each patch using a shallow Convolutional Neural Network (CNN) to produce patch features of channel dimension $C$ [S1].
3.  **Tokenization:** Flatten the patch features from all $N$ views into a single sequence of tokens $\{\mathbf{X}\}$, resulting in $N \times \frac{HW}{p^2}$ tokens [S1].
4.  **Transformer Processing:** Process the token sequence $\{\mathbf{X}\}$ using a multi-view Transformer to jointly model geometric structure and appearance across views. This produces latent features $\{\mathbf{Z}\}$:
    $$ \{\mathbf{Z}\} = \text{Transformer}_{MV}(\{\mathbf{X}\}) \quad [S1] $$
5.  **Primitive Generation:** Apply a linear projection to each latent token in $\{\mathbf{Z}\}$ to produce the initial set of Gaussian primitives $\{\mathbf{G}_k\}$ and associated feature vectors $\{\mathbf{F}_k\}$:
    $$ \{\mathbf{G}_k, \mathbf{F}_k\} = \text{Linear}(\{\mathbf{Z}\}) \quad [S1] $$
    Here, $\mathbf{G}_k$ represents the parameters of the $k$-th 3D Gaussian primitive aligned with the $k$-th image patch.

**Rendering Formula:**
The primitives generated by this method can be rendered using standard Gaussian Splatting rasterization. The rendered color at pixel $\mathbf{p}$ is computed via front-to-back alpha compositing [S1]:
$$ C(\mathbf{p}) = \sum_{i=1}^K \mathbf{c}_i \alpha_i \mathcal{G}_i^{\text{2D}}(\mathbf{p}) \prod_{j=1}^{i-1} (1 - \alpha_j \mathcal{G}_j^{\text{2D}}(\mathbf{p})) $$
where $\mathcal{G}_i^{\text{2D}}(\mathbf{p})$ is the 2D projection of the $i$-th 3D Gaussian at pixel $\mathbf{p}$, $\mathbf{c}_i$ is the color, $\alpha_i$ is the opacity, and $K$ is the total number of splats [S1].

**Parameters:**
*   $N$: Number of input views.
*   $H, W$: Image height and width.
*   $p$: Patch size for grouping features.
*   $C$: Channel dimension of patch features.
*   $S$: Number of spherical harmonic coefficients for view-dependent color.

**Edge Cases and Pitfalls:**
*   **Precision:** The linear projection maps continuous latent features to discrete geometric parameters (position, scale, rotation). Care must be taken to ensure the output ranges are valid (e.g., quaternions must be normalized, scales must be positive). [G]
*   **Boundaries:** The method assumes known camera intrinsics and extrinsics. Errors in these inputs will propagate directly to the predicted Gaussian positions.
*   **Degenerate Input:** If $N$ is too small or the views are insufficiently diverse, the Transformer may fail to disambiguate depth, leading to poor reconstruction.

## Operating characteristics
*   **Time Complexity:** $O(N \cdot \frac{HW}{p^2} \cdot L \cdot d^2)$ for the Transformer, where $L$ is the number of layers and $d$ is the hidden dimension. The linear projection is $O(K \cdot d)$. Overall, it is significantly faster than iterative optimization, which is $O(\text{iterations} \cdot M)$.
*   **Memory Complexity:** $O(N \cdot \frac{HW}{p^2} \cdot C)$ for input features and $O(K \cdot d)$ for latent features. The output requires $O(K)$ memory for the primitives.
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Scales linearly with the number of input views $N$ and the number of patches.
*   **Strengths:** Instantaneous novel view synthesis; no training required per scene; history-aware inference for streaming scenarios.
*   **Limitations:** Potentially lower accuracy than iterative methods; dependent on the quality of the pre-trained Transformer; may struggle with complex view-dependent effects if not adequately captured by the spherical harmonics.
*   **When to use:** Real-time applications, streaming scenarios, or when rapid reconstruction from sparse views is needed.
*   **When not to use:** When maximum photorealistic fidelity is required and offline optimization is acceptable.

## Background
Feed-forward 3D Gaussian Splatting was introduced to enable efficient, history-aware novel view synthesis for streaming scenarios without requiring additional temporal data [S1]. It builds on the 3D Gaussian Splatting (3DGS) representation, which models a scene as a set of anisotropic 3D Gaussian primitives [S1]. The feed-forward model adopts the multi-view Transformer architecture from GS-LRM [S1]. It allows for the prediction of 3D Gaussian primitives in a feed-forward manner from sparse-view images, overcoming the computational cost of iterative optimization [S1].
