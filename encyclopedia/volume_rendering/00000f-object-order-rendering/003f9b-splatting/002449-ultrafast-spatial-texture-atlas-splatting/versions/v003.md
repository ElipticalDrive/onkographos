# Ultrafast Spatial Texture-Atlas Splatting

Also called: Texture-Atlas Splatting

## Overview
Ultrafast Spatial Texture-Atlas Splatting is a learned sparse scene representation that eliminates runtime neural network inference by baking view-independent appearance into a hardware-accelerated 2D texture atlas [S1, unofficial]. It replaces the volumetric ellipsoids of 3D Gaussian Splatting with oriented 2D Beta kernels and decomposes appearance into low-frequency per-surfel view-dependent color and high-frequency baked residuals [S1, unofficial]. This approach achieves 7–9× faster rendering than standard 3DGS by reducing overdraw through flat kernel regularization and replacing expensive ray-surfel intersection shaders with an exact rational reformulation [S1, unofficial].

## How it works
### Inputs and Outputs
**Inputs:**
*   A set of $N$ oriented 2D surfels, each defined by position $\mu_i$, rotation $q_i$, 2D scale $s_i$, opacity $o_i$, and shape parameter $b_i$ [S1, unofficial].
*   Training images and camera poses [S1, unofficial].
*   A multi-resolution hash grid $E_\theta$ and an MLP decoder $f_\theta$ (used during training only) [S1, unofficial].

**Outputs:**
*   A rendered image frame.
*   A compressed RGB texture atlas (55–320 MB for typical scenes) containing the baked residuals [S1, unofficial].

### Data Structures
1.  **Surfel List:** An array of $N$ surfels. Each surfel stores:
    *   $\mu_i \in \mathbb{R}^3$: World-space position [S1, unofficial].
    *   $q_i \in \mathbb{R}^4$: Unit quaternion for orientation [S1, unofficial].
    *   $s_i \in \mathbb{R}^2$: 2D scale factors [S1, unofficial].
    *   $o_i \in \mathbb{R}$: Opacity [S1, unofficial].
    *   $b_i \in \mathbb{R}$: Shape parameter for the Beta kernel [S1, unofficial].
    *   $f_{SV} \in \mathbb{R}^3$: Per-surfel view-dependent color vector [S1, unofficial].
    *   $b_{SV} \in \mathbb{R}$: Fixed offset (value 0.5) [S1, unofficial].
    *   Texture coordinates: Mapping from local surfel space to the texture atlas [S1, unofficial].
2.  **Texture Atlas:** A 2D RGB texture. Each surfel $i$ is assigned a rectangular region in the atlas. The texels store the baked residual color $\rho(\mathbf{x})$. The atlas is allocated once after sparsification [S1, unofficial].

### Numbered Steps
#### 1. Scene Representation and Kernel Definition
The scene is represented as a sparse set of oriented 2D Beta kernels [S1, unofficial]. Unlike standard Gaussians, these kernels use a Deformable Beta function to control the falloff profile [S1, unofficial].

The kernel $\mathcal{B}$ is defined as:
$$ \mathcal{B}(x;b) = (1-x)^{\beta(b)} $$
where:
*   $x \in [0,1]$ is the squared radial distance from the kernel center, normalized to 1 at the edge of the support [S1, unofficial].
*   $b \in \mathbb{R}$ is the learnable shape parameter [S1, unofficial].
*   $\beta(b) = 5\sigma(b)$, where $\sigma$ is the sigmoid function [S1, unofficial].

Small $b$ values produce flat, hard-edged disks that fit sharp geometry with fewer primitives and less overdraw [S1, unofficial]. Large $b$ values produce soft, Gaussian-like surfels [S1, unofficial]. The parameter $b$ is restricted so kernels lie between a flat disk and a soft Gaussian [S1, unofficial].

#### 2. Appearance Decomposition
Appearance is decomposed into a per-surfel view-dependent term and a global view-independent residual [S1, unofficial].

*   **Per-surfel term ($f_{SV}$):** A vector representing low-frequency, view-dependent color. It is constant across the surfel surface [S1, unofficial].
*   **Residual term ($\rho$):** A high-frequency, view-independent texture detail. It is learned using a spatial multi-resolution hash grid $E_\theta$ and an MLP decoder $f_\theta$ during training [S1, unofficial].

The fragment color $\mathbf{c}(\mathbf{x}, \mathbf{d})$ at position $\mathbf{x}$ and viewing direction $\mathbf{d}$ is computed as:
$$ \mathbf{c}(\mathbf{x}, \mathbf{d}) = \text{ReLU}\left(\text{ReLU}(f_{SV}(\mathbf{d}) + b_{SV}) + f_\theta(\mathbf{E}_\theta(\mathbf{x}))\right) $$
where $b_{SV} = 0.5$ is a fixed offset providing a neutral gray baseline [S1, unofficial].

The residual is signed (positive and negative), allowing it to add to or subtract from the base color. This provides more representational power than positive-only residuals, enabling a single surfel to reproduce complex color variations (53–55 dB PSNR vs. 14–20 dB for positive-only) [S1, unofficial].

#### 3. Training
Training proceeds jointly, involving:
1.  **Hash Grid Querying:** During training, the hash grid $E_\theta$ is queried at every fragment along the surfel's surface. This allows the grid to absorb fine spatial texture, while $f_{SV}$ absorbs low-frequency view-dependent appearance [S1, unofficial].
2.  **Sparsity and Regularization:** The field is trained jointly with the multi-view error criterion of FastGS to limit densification [S1, unofficial]. A falloff prior using Beta kernels progressively regularizes kernels toward flat, hard-edged profiles. This stops redundant overlaps between soft Gaussian tails and dampens positional gradients, reducing primitive count and overdraw [S1, unofficial].
3.  **Baking:** The output of the hash-grid sampling is baked into a compressed RGB texture atlas. Each surfel is assigned a rectangle in the atlas [S1, unofficial].
4.  **Finetuning:** The atlas texels are finetuned directly against the training images to overcome hash collisions that occurred during training [S1, unofficial].

#### 4. Rendering
Rendering eliminates the neural network inference and uses hardware-accelerated texture fetching [S1, unofficial].

1.  **Rasterization:** Surfels are projected to screen space [S1, unofficial].
2.  **Intersection Test:** An exact rational reformulation of the ray-surfel intersection is used instead of the standard shader. This reduces the computational cost of the intersection test, which becomes a bottleneck at high frame rates [S1, unofficial].
3.  **Color Fetch:** For each fragment covered by a surfel, the texture atlas is sampled to retrieve the residual color. The per-surfel $f_{SV}(\mathbf{d})$ is computed (or looked up if precomputed) and combined with the baked residual.
4.  **Compositing:** Front-to-back alpha compositing is performed using the effective alpha $\alpha_i(\mathbf{x}) = o_i \mathcal{B}(x;b_i)$ and the computed color [S1, unofficial].

import math

def sigmoid(x):
    return 1.0 / (1.0 + math.exp(-x))

def beta_kernel(x, b):
    beta_b = 5.0 * sigmoid(b)
    x_clamped = max(0.0, min(1.0, x))
    return (1.0 - x_clamped) ** beta_b

def render_frame(surfels, texture_atlas, camera):
    projected_surfels = []
    for surfel in surfels:
        pos_cam = camera.view_matrix @ surfel.position
        cov_2d = compute_screen_covariance(surfel, camera) # Standard 2DGS projection [G]
        width, height = compute_bbox(cov_2d) # 3-sigma rule [G]
        projected_surfels.append({
            'center': pos_cam.xy, 'cov_inv': inverse(cov_2d),
            'bbox': {'min': pos_cam.xy - [width, height], 'max': pos_cam.xy + [width, height]},
            'depth': pos_cam.z, 'f_sv': surfel.f_sv, 'b_sv': surfel.b_sv,
            'b': surfel.b, 'opacity': surfel.opacity, 'tex_coords': surfel.tex_coords
        })
    projected_surfels.sort(key=lambda s: s['depth'])
    
    image = create_zero_image(camera.resolution)
    transmittance = create_zero_image(camera.resolution)
    
    for surfel in projected_surfels:
        pixels = get_pixels_in_bbox(surfel['bbox'])
        for pixel in pixels:
            diff = pixel - surfel['center']
            x = diff @ surfel['cov_inv'] @ diff
            if x >= 1.0: continue
            kernel_alpha = beta_kernel(x, surfel['b'])
            alpha = surfel['opacity'] * kernel_alpha
            if alpha < 1e-4: continue
            residual_color = texture_atlas.sample(surfel['tex_coords'], pixel)
            f_sv = surfel['f_sv']
            base_color = f_sv + surfel['b_sv']
            base_color = max(0.0, base_color)
            final_color = base_color + residual_color
            final_color = max(0.0, final_color)
            current_transmittance = transmittance[pixel]
            contribution = final_color * alpha * current_transmittance
            image[pixel] += contribution
            transmittance[pixel] *= (1.0 - alpha)
            if transmittance[pixel] < 1e-4: break
    return image

### Parameters and Typical Values
*   **Texture Atlas Size:** 55–320 MB for typical scenes [S1, unofficial].
*   **Fixed Offset $b_{SV}$:** 0.5 [S1, unofficial].
*   **Shape Parameter $b$:** Restricted to lie between a flat disk and a soft Gaussian. Small $b$ yields flat disks; large $b$ yields soft Gaussians [S1, unofficial].
*   **Hash Grid:** Multi-resolution hash grid $E_\theta$ and MLP decoder $f_\theta$ used during training [S1, unofficial].

### Edge Cases and Pitfalls
*   **Hash Collisions:** Hash collisions during training can cause artifacts. These are mitigated by finetuning the atlas texels directly against training images [S1, unofficial].
*   **Overdraw:** Soft Gaussian tails cause redundant overlaps. The Beta kernel regularization with small $b$ reduces overdraw by creating flat, hard-edged disks [S1, unofficial].
*   **Sparsity Limits:** Pipelines using per-primitive textures start from a converged dense model with densification frozen, capping attainable sparsity. This method allocates the atlas once after sparsification, allowing higher sparsity [S1, unofficial].
*   **Positive-Only Residuals:** Using positive-only residuals limits representational power. Signed residuals are required for high-fidelity detail (53–55 dB PSNR vs. 14–20 dB) [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Rendering is dominated by texture fetches and alpha compositing. The exact rational reformulation of the ray-surfel intersection reduces shader complexity [S1, unofficial].
*   **Memory Complexity:** The texture atlas requires 55–320 MB for typical scenes, which is larger than memory-optimized 3DGS scene representations [S1, unofficial].
*   **Measured Performance:** Renders roughly 7–9× faster than 3DGS on common benchmarks. 5.4–6.9× faster than 3DGS with standard 2DGS ray-surfel shader. 1.2–1.8× faster than FastGS and Speedy-Splat at better perceptual quality. 14.5× faster than Beta-Splatti [S1, unofficial].
*   **Scaling:** Performance scales well with hardware texture mapping. The method runs without issues on low-to-mid-range GPUs [S1, unofficial].
*   **Strengths:** High rendering speed, reduced overdraw, elimination of runtime neural inference, high fidelity with signed residuals [S1, unofficial].
*   **Limitations:** Larger memory footprint than optimized 3DGS, requires baking step, less flexible than neural representations for dynamic changes [S1, unofficial].
*   **When to Use:** When high frame rates are critical and the scene is static or changes infrequently. Suitable for applications on low-to-mid-range GPUs [S1, unofficial].
*   **When Not to Use:** When dynamic scene updates are frequent, or memory is extremely constrained [S1, unofficial].

## Background
Ultrafast Spatial Texture-Atlas Splatting was introduced by An Petkov and Klaus Engel at Siemens Healthineers [S1, unofficial]. It builds on 2D Gaussian Splatting (2DGS) by Huang et al. (2024) and uses Deformable Beta kernels from Liu et al. (2025) [S1, unofficial]. The method addresses the rendering overhead of neural radiance representations in Gaussian Splatting by baking the neural component into a texture atlas [S1, unofficial].
