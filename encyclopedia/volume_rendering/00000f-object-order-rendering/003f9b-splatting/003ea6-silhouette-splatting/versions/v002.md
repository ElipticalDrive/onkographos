# Silhouette Splatting
## Overview
Silhouette Splatting is a volume rendering technique that projects irregular grid cells by triangulating their convex hulls and rendering them as geometric primitives [S2, unofficial]. Unlike standard splatting which treats data as point samples, this method operates on the cells between sample points [S2, unofficial]. It was developed for rendering irregular grids but was ultimately abandoned due to visual artifacts and lack of performance gain over simpler methods [S1][S2, unofficial].
## How it works
**Inputs:** Irregular grid cells defined by their 3D vertices and associated scalar values at those vertices [S2, unofficial].
**Outputs:** A 2D rendered image [G].

**Data Structures:**
*   **Cell:** A collection of $N$ vertices $\mathbf{v}_i$ in 3D space with associated scalar values $s_i$ [S2, unofficial].
*   **Convex Hull:** The subset of cell vertices that form the outer boundary polygon when projected onto the view plane [S2, unofficial].
*   **Centroid:** The geometric center of the cell, calculated as the arithmetic mean of its vertices [S2, unofficial].

**Steps:**
1.  **Identify Convex Hull:** Determine which vertices of the current cell lie on the convex hull relative to the current view direction [S2, unofficial].
2.  **Form Polygon:** Connect the convex hull vertices to form a closed polygon [S2, unofficial].
3.  **Compute Centroid:** Calculate the centroid $\mathbf{c}$ of the cell [S2, unofficial].
    $$ \mathbf{c} = \frac{1}{N} \sum_{i=1}^{N} \mathbf{v}_i $$
4.  **Estimate Properties:** Determine the depth $z_c$ and the estimated scalar value $V_c$ (e.g., average of vertex values) for the centroid [S2, unofficial].
5.  **Triangulate:** Create a set of triangles by connecting the centroid $\mathbf{c}$ to each edge of the convex hull polygon [S1][S2, unofficial].
6.  **Project and Render:** Transform the vertices of these triangles into screen space and rasterize them [S2, unofficial].

**Pseudocode:**
```python
def silhouette_splatting(cell_vertices, cell_values, view_direction, projection_matrix):
    # 1. Project vertices to 2D plane perpendicular to view direction
    projected_2d = [v - (v @ view_direction) * view_direction for v in cell_vertices]
    # 2. Compute convex hull of projected points [G]
    hull_indices = convex_hull_2d(projected_2d)
    hull_vertices = [cell_vertices[i] for i in hull_indices]
    # 3. Compute centroid
    centroid = sum(cell_vertices) / len(cell_vertices)
    # 4. Estimate depth and value at centroid
    depth = centroid @ view_direction
    value = sum(cell_values) / len(cell_values)
    # 5. Triangulate by connecting centroid to hull edges
    triangles = []
    for i in range(len(hull_vertices)):
        v1 = hull_vertices[i]
        v2 = hull_vertices[(i + 1) % len(hull_vertices)]
        triangles.append((centroid, v1, v2))
    # 6. Rasterize triangles to screen
    for tri in triangles:
        rasterize_triangle(tri, depth, value, projection_matrix)
```

**Edge Cases and Pitfalls:**
*   **Blotchiness:** Images produced are very blotchy from oblique angles on irregular grids [S1][S2, unofficial].
*   **Performance:** The method was not significantly faster than simpler projection methods like Cell Face Projection with Depth [S2, unofficial].
*   **Overlap:** Unlike standard splatting, where overlapping splats can reduce blotchiness, this method's rigid triangulation does not easily allow for overlapping primitives without significant additional calculation (e.g., moving the convex hull away from the centroid) [S2, unofficial].
## Operating characteristics
*   **Time Complexity:** Dominated by convex hull computation and triangulation per cell [G]. The method was not significantly faster than cell face projection [S2, unofficial].
*   **Memory Complexity:** Low, as it processes cells individually without complex data structures [G].
*   **Visual Quality:** Poor on irregular grids, especially at oblique angles, resulting in blotchy images [S1][S2, unofficial].
*   **Strengths:** Simple to implement; conceptually similar to standard splatting but applied to cells [S2, unofficial].
*   **Limitations:** Visual artifacts; no substantial performance benefit over alternatives; abandoned in favor of other methods [S2, unofficial].
*   **When to use:** Not recommended. The method was abandoned due to poor results [S2, unofficial].
## Background
Silhouette Splatting was proposed in the context of rapid exploration of irregular grids using direct volume rendering [S1][S2, unofficial]. It was mentioned primarily to document that the approach was tried and found unsuccessful, saving others from repeating the effort [S2, unofficial]. It is distinct from standard splatting (e.g., [Splatting](23-splatting.md)) because it operates on cells rather than sample points [S2, unofficial].
