# Hardware Accelerated Texture Atlases

Also called: Indirect Texture Sampling for Splatting, Texture Atlas Splatting

## Overview
This method organizes per-primitive texture data into large 2D atlas textures to leverage GPU hardware filtering and caching, thereby avoiding multiple texture bindings and software-based sampling overhead [S1]. It sets itself apart from software-based interpolation by utilizing dedicated texture units for bilinear filtering, which is significantly faster than manual interpolation from global memory arrays [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** $P$ splats (primitives), $C$ total attribute channels, fixed primitive texture resolution $T$ (typically a power of 2), and GPU maximum atlas dimensions [S1].
*   **Outputs:** One or more 2D atlas textures containing packed primitive textures, and an indirection buffer mapping primitive IDs to atlas chart coordinates [S1].

**Data Structures:**
1.  **Atlas Texture(s):** Large 2D textures. If $C > 4$, split attributes across multiple atlases (e.g., one for albedo/roughness, another for tangent normals/metallic) to respect CUDA texture object channel limits [S1].
2.  **Indirection Buffer:** A buffer storing the top-left corner coordinates $(chart\_idx\_x, chart\_idx\_y)$ for each primitive's texture within the atlas [S1].

**Steps:**

1.  **Determine Atlas Geometry:**
    Calculate the maximum number of $T \times T$ textures that fit along the width and height of the atlas based on GPU capabilities [S1]. Let $N_{chartsx}$ and $N_{chartsy}$ be the total number of charts along the width and height, respectively [S1].

2.  **Pack Textures:**
    Organize the $P \times C \times T \times T$ texel data into one or more atlases [S1]. Each primitive's texture occupies a $T \times T$ block [S1]. The top-left corner of primitive $k$'s texture is stored in the indirection buffer at index $k$ [S1].

3.  **Sampling (Per Primitive $k$ at pixel $(x,y)$):**
    a. Map local coordinates $(u, v)$ to normalized texture coordinates $(s, t) \in [0, 1] \times [0, 1]$ [S1].
    b. Retrieve $(chart\_idx\_x, chart\_idx\_y)$ from the indirection buffer for primitive $k$ [S1].
    c. Compute atlas coordinates $(s_{atlas}, t_{atlas})$ using the formula:
       $$s_{atlas} = \frac{chart\_idx\_x \cdot T + s \cdot T}{N_{chartsx} \cdot T}$$
       $$t_{atlas} = \frac{chart\_idx\_y \cdot T + t \cdot T}{N_{chartsy} \cdot T}$$
       [S1]
    d. Sample the atlas using hardware-accelerated bilinear filtering:
       $$a_k(x, y) = \text{BilinearFilter}(atlas, s_{atlas}, t_{atlas})$$
       [S1]

**Pseudocode:**

```python
def build_atlas(primitives, T, max_atlas_width, max_atlas_height):
    """
    primitives: list of P objects, each having a T x T x 4 texture data array.
    T: resolution of each primitive's texture (power of 2).
    max_atlas_width, max_atlas_height: GPU limits in texels.
    Returns: list of atlas textures, global indirection buffer
    """
    charts_per_row = max_atlas_width // T
    charts_per_col = max_atlas_height // T
    total_charts_per_atlas = charts_per_row * charts_per_col
    num_atlases = (len(primitives) + total_charts_per_atlas - 1) // total_charts_per_atlas
    
    atlases = []
    indirection_buffer = []
    
    for a in range(num_atlases):
        atlas_w = charts_per_row * T
        atlas_h = charts_per_col * T
        # Initialize atlas as 4-channel 2D array: atlas[channel][y][x]
        atlas = [[[0.0] * atlas_w for _ in range(atlas_h)] for _ in range(4)]
        
        start = a * total_charts_per_atlas
        end = min(start + total_charts_per_atlas, len(primitives))
        
        for k in range(start, end):
            chart_x = (k - start) % charts_per_row
            chart_y = (k - start) // charts_per_row
            indirection_buffer.append((chart_x, chart_y))
            
            for u in range(T):
                for v in range(T):
                    ax = chart_x * T + u
                    ay = chart_y * T + v
                    for c in range(4):
                        atlas[c][ay][ax] = primitives[k].texture[v][u][c]
        
        atlases.append(atlas)
        
    return atlases, indirection_buffer

def sample_atlas(atlas, indirection_buffer, k, s, t, T, Nchartsx, Nchartsy, atlas_w, atlas_h):
    """
    Sample the texture for primitive k at normalized coordinates (s, t).
    """
    chart_x, chart_y = indirection_buffer[k]
    
    # Compute atlas coordinates
    s_atlas = (chart_x * T + s * T) / (Nchartsx * T)
    t_atlas = (chart_y * T + t * T) / (Nchartsy * T)
    
    # Bilinear interpolation (standard graphics step)
    u0 = int(s_atlas * (atlas_w - 1))
    v0 = int(t_atlas * (atlas_h - 1))
    u1 = min(u0 + 1, atlas_w - 1)
    v1 = min(v0 + 1, atlas_h - 1)
    su = s_atlas * (atlas_w - 1) - u0
    sv = t_atlas * (atlas_h - 1) - v0
    
    res = [0.0] * 4
    for c in range(4):
        c00 = atlas[c][v0][u0]
        c10 = atlas[c][v0][u1]
        c01 = atlas[c][v1][u0]
        c11 = atlas[c][v1][u1]
        res[c] = (c00 * (1 - su) + c10 * su) * (1 - sv) + (c01 * (1 - su) + c11 * su) * sv
    return res
```

**Parameters:**
*   $T$: Fixed resolution of each primitive's small texture, typically in powers of 2 [S1].
*   $N_{chartsx}, N_{chartsy}$: Total number of charts along the width and height of the atlas [S1].

**Edge Cases and Pitfalls:**
*   CUDA texture objects support up to 4 channels [S1]. If total attribute channels $C$ exceed 4, attributes must be split across multiple atlases to avoid data loss or incorrect sampling (e.g., one atlas for albedo/roughness, another for normals/metallic) [S1].

## Subtopics

### Hardware Accelerated Texture Sampling
This variant refers specifically to the sampling phase where hardware bilinear filtering is used via CUDA’s `tex2D()` intrinsic, as opposed to software interpolation [S1]. It relies on the indirection buffer to map primitive IDs to atlas chart coordinates and computes normalized atlas coordinates $(s_{atlas}, t_{atlas})$ for sampling [S1]. It is chosen when performance is critical and the GPU supports efficient texture filtering [S1].

## Operating characteristics
*   **Time Complexity:** Sampling is $O(1)$ per primitive per pixel due to hardware filtering, significantly faster than software-based interpolation [S1].
*   **Memory Complexity:** Requires storing $P \times C \times T \times T$ texels in atlas textures plus the indirection buffer [S1].
*   **Performance:** Leverages dedicated texture caching and filtering hardware, speeding up attribute fetching compared to manual interpolation from global memory arrays [S1]. Avoids multiple texture bindings, reducing API overhead [S1].
*   **Strengths:** High performance on non-specular scenes; can reach performance levels of vanilla 3DGS on NeRF Synthetic dataset [S1].
*   **Limitations:** Limited by GPU maximum atlas dimensions and channel support (4 channels per texture object) [S1].
