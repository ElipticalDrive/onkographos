# Splat Texture Layout & Mapping

Also called: Splat Data Texture Mapping

## Overview
Splat Texture Layout & Mapping defines the mechanism for storing and accessing splat primitive data within GPU-accessible 3D textures, enabling efficient hardware-accelerated rasterization of volumetric primitives. It sets itself apart from software-based interpolation by organizing per-primitive data into structured texture records that leverage GPU hardware filtering and caching, thereby avoiding multiple texture bindings and manual sampling overhead [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A set of splat primitives (defined by position, density, and kernel parameters) and a target texture capacity.
- **Output:** Two 3D textures backed by `Uint32Array` buffers, containing the mapped splat data ready for GPU sampling.

**Data Structures:**
Each splat primitive corresponds to two 16-byte texture records within the 3D textures. The layout is organized to support efficient coordinate calculation and paging for large splat counts [S1, unofficial][S2, unofficial].

**Parameters:**
- `SPLAT_TEX_WIDTH_BITS`: A constant defining the width of the texture in bits (value not given in sources).
- `inputCapacity`: The number of splats provided by the input data.
- `maxSplats`: The maximum capacity supported by the texture, calculated as `getTextureSize(inputCapacity).maxSplats` [S1, unofficial].

**Steps:**
1. **Capacity Calculation:** Determine `maxSplats` using `getTextureSize(inputCapacity).maxSplats` [S1, unofficial].
2. **Allocation:** If `inputCapacity` differs from `maxSplats`, allocate new `Uint32Array` buffers of size `maxSplats * 4` and copy the original data [S1, unofficial].
3. **Layer Bit Calculation:** Calculate the number of bits required for the layer index based on texture width and height:
   $$ \text{layerBits} = \text{SPLAT\_TEX\_WIDTH\_BITS} + \lceil \log_2(\text{height}) \rceil $$
   [S1, unofficial]
4. **Mask Generation:** Create a source layer mask to isolate relevant bits:
   $$ \text{sourceLayerMask} = 2^{\text{layerBits}} - 1 $$
   [S1, unofficial]
5. **Coordinate Mapping:** For each splat index, calculate the 3D texture coordinate (`ivec3`) using the layer bits and mask to handle paging or tiling for large splat counts [S2, unofficial].

**Pseudocode:**
```python
def map_splat_texture(splat_data, input_capacity, splat_tex_width_bits, height):
    # Step 1: Calculate max capacity
    max_splats = get_texture_size(input_capacity).max_splats
    
    # Step 2: Allocate and copy if necessary
    if input_capacity != max_splats:
        # Allocate new Uint32Arrays of size max_splats * 4
        # Copy original data
        texture_buffer = allocate_uint32_array(max_splats * 4)
        copy_data(splat_data, texture_buffer)
    else:
        texture_buffer = splat_data
        
    # Step 3: Calculate layer bits
    layer_bits = splat_tex_width_bits + math.ceil(math.log2(height))
    
    # Step 4: Generate mask
    source_layer_mask = (2 ** layer_bits) - 1
    
    # Step 5: Map coordinates for each splat
    mapped_records = []
    for i in range(max_splats):
        # Calculate 3D texture coordinate (ivec3)
        # This handles paging/tiling for large splat counts
        coord = calculate_splat_tex_coord(i, layer_bits, source_layer_mask)
        mapped_records.append(coord)
        
    return texture_buffer, mapped_records

def calculate_splat_tex_coord(splat_index, layer_bits, source_layer_mask):

    x = splat_index & 0xFF
```

**Edge Cases and Pitfalls:**
- **Precision:** Ensure `Uint32Array` bounds are respected to avoid overflow when `max_splats` is large [S1, unofficial].
- **Boundaries:** Handle cases where `input_capacity` exceeds `max_splats` by truncating or erroring, as the allocation is fixed to `max_splats` [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Not given in the sources.
- **Memory Complexity:** Proportional to `max_splats * 4` for the `Uint32Array` buffer [S1, unofficial].
- **Measured Performance:** Not given in the sources.
- **Scaling:** Scales with the number of splats up to `max_splats`, limited by texture dimensions and GPU memory [S1, unofficial].
- **Strengths:** Leverages GPU hardware filtering for fast sampling; avoids software interpolation overhead [S1, unofficial].
- **Limitations:** Requires fixed-size texture allocation; paging logic may add complexity for very large scenes [S1, unofficial][S2, unofficial].
- **When to use:** When real-time rendering of large splat sets is required and GPU hardware filtering is beneficial [S1, unofficial].
- **When not:** When splat counts are small and software interpolation is sufficient, or when dynamic texture resizing is needed without reallocation [S1, unofficial].

## Background
The method is part of the Gaussian Splatting ecosystem, specifically implemented in libraries like `gaussian-splat-lite` and `spark` for efficient WebGL/WebGPU rendering [S1, unofficial][S2, unofficial]. It addresses the need for efficient data layout in real-time volumetric rendering of 3D Gaussian splats.
