# Splat Data Structure (ISplatSource)
Also called: ISplatSource

## Overview
The Splat Data Structure (ISplatSource) is an abstract interface designed for the asynchronous loading of splat data, returning a `LoadResult` object [S1, unofficial]. It solves the problem of blocking the main thread during the parsing of large 3D Gaussian Splat captures by decoupling I/O operations from rendering [S1, unofficial]. It is distinguished from synchronous loading methods by its non-blocking callback-based architecture [S1, unofficial].

## How it works
**Inputs and Outputs:**
The method takes no direct input parameters other than the callback mechanism. It outputs a `LoadResult` struct containing the loaded splat data, spherical harmonic degree, and error status.

**Data Structures:**
The core output is the `LoadResult` struct, defined as follows [S1, unofficial]:
*   `splats`: A `std::vector<SplatGPU>` containing the loaded splat primitives.
*   `sh_degree`: An `int` indicating the active spherical harmonic degree.
*   `error`: A `std::string` which is non-empty if the load operation failed.
*   `ok()`: A method returning `true` if `error` is empty.

The `SplatGPU` structure (implied by usage in [S1, unofficial]) contains position, covariance, color, and spherical harmonic coefficients. The SH coefficients are stored in a packed format where non-DC coefficients are stored as `RGBA16F` texels in a Texture Buffer Object (TBO), excluding the DC term [S1, unofficial].

**Steps:**
1.  Instantiate the `ISplatSource` implementation.
2.  Call `start(Callback cb)`, passing a callback function of type `std::function<void(LoadResult)>` [S1, unofficial].
3.  The implementation performs asynchronous file parsing and memory allocation.
4.  Upon completion, the callback is invoked with a `LoadResult` instance.
5.  The caller checks `result.ok()`. If false, `result.error` contains the failure reason. If true, `result.splats` contains the valid data.

**Pseudocode:**
```python
# Definition of the callback type
# Callback = function(LoadResult) -> None

# Definition of LoadResult
class LoadResult:
    splats: List[SplatGPU]
    sh_degree: int
    error: str

    def ok(self) -> bool:
        return len(self.error) == 0

# Implementation of the loading process
def start_load(callback: Callback):
    # 1. Initialize asynchronous loader
    loader = ISplatSourceImpl()
    
    # 2. Define the completion handler
    def on_complete(result: LoadResult):
        # 3. Invoke the user-provided callback
        callback(result)

    # 4. Start the background loading task
    # The loader parses the file (e.g., .spz or .ply) and populates result.splats
    loader.start(on_complete)

# Usage example
def on_load_finished(result: LoadResult):
    if result.ok():
        splat_count = len(result.splats)
        sh_deg = result.sh_degree
        # Proceed with rendering setup
        pass
    else:
        print(f"Load failed: {result.error}")

start_load(on_load_finished)
```

**Parameters:**
*   `sh_degree`: Determines the number of SH coefficients. The number of non-DC coefficients per splat is calculated as $(active\_sh\_degree + 1)^2 - 1$ [S1, unofficial].
*   `sh_coeffs_per_splat`: Calculated as $(active\_sh\_degree + 1)^2 - 1$ [S1, unofficial].

**Edge Cases:**
*   **File Corruption:** If the file is invalid, `result.error` will be populated, and `result.ok()` will return false [S1, unofficial].
*   **Memory Exhaustion:** Large splat clouds may fail to allocate `std::vector<SplatGPU>`, resulting in an error [S1, unofficial].

## Subtopics

### [Splat Cloud Loading](13758-splat-cloud-loading.md)
An asynchronous file parsing method that loads a `SplatCloud` data structure from `.spz` or `.ply` files off the main thread. It solves the problem of blocking the UI during the loading of large 3D Gaussian Splat captures by returning `null` while parsing is in progress. It is distinguished from synchronous parsing methods by its non-blocking nature and its support for multiple compression formats (gzip and ZSTD) within a single pure-Kotlin implementation.

## Operating characteristics
*   **Time Complexity:** The loading time is proportional to the file size and the complexity of the compression format (gzip or ZSTD) [S2, unofficial]. The asynchronous nature ensures the main thread remains responsive.
*   **Memory Complexity:** Linear with respect to the number of splats, storing positions, covariances, colors, and SH coefficients [S1, unofficial].
*   **Strengths:** Non-blocking I/O prevents UI freezes; supports multiple compression formats [S2, unofficial].
*   **Limitations:** Requires careful management of the callback lifecycle to avoid dangling references; memory usage can be high for very large scenes [S1, unofficial].

## Background
The `ISplatSource` interface was introduced in the `splat-ros/RVizSplat` project to facilitate real-time visualization of 3D Gaussian Splatting data in ROS environments [S1, unofficial]. It addresses the performance bottlenecks associated with synchronous loading of large-scale splat captures.
