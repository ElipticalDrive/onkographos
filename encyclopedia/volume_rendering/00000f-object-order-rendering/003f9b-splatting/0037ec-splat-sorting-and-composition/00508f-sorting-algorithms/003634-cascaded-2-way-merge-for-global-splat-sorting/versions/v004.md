# Cascaded 2-way Merge for Global Splat Sorting

Also called: Global Splat Merge, Cascaded Binary Merge Tree for Splat Sorting

## Overview
Cascaded 2-way Merge is a GPU-based algorithm that merges pre-sorted splat lists from multiple independent renderers into a single globally depth-sorted order buffer using a cascaded binary merge tree [S1, unofficial]. It solves the problem of incorrect depth ordering and excessive overdraw when rendering multiple active Gaussian Splat scenes in a unified viewport [S1, unofficial]. Unlike per-renderer rendering, where each renderer handles its own depth sorting and draw calls independently, this method delegates sorting execution to a global sorter and rendering to a global renderer, triggered when camera movement exceeds thresholds or refresh rate dictates [S1, unofficial]. It sets itself apart from CPU-based sorting by leveraging GPU subgroups/waves for parallel merging, and from Bitonic Sort by using a deterministic, fixed-depth merge tree that assumes inputs are already sorted [S1, unofficial].

## How it works
The method assumes $K$ active renderers, each providing a list of splats sorted by depth. The goal is to produce a single list of $N = \sum_{k=0}^{K-1} \text{cnt}_k$ splats sorted by depth.

**Inputs and Outputs:**
- **Inputs:** $K$ renderers. Renderer $k$ has `RemainingCount` ($\text{cnt}_k$) splats. Each splat has an order index and a depth value.
- **Outputs:** `m_globalOrderBuffer` containing the final sorted global order indices.

**Data Structures:**
The algorithm uses four scratch buffers and one global output buffer, all of size `m_totalSplatCount` (the sum of maximum possible splats across all renderers):
1. `m_packScratchOrders`: `GraphicsBuffer` of type `uint`, name 'Gsplat.PackScratchOrders'.
2. `m_packScratchDepths`: `GraphicsBuffer` of type `float`, name 'Gsplat.PackScratchDepths'.
3. `m_mergeScratchOrders`: `GraphicsBuffer` of type `uint`, name 'Gsplat.MergeScratchOrders'.
4. `m_mergeScratchDepths`: `GraphicsBuffer` of type `float`, name 'Gsplat.MergeScratchDepths'.
5. `m_globalOrderBuffer`: `GraphicsBuffer` holding the final sorted global order, bound via `k_globalOrderBuffer` property.

**Parameters:**
- `k_rendererIdx`: Index of the current renderer being packed.
- `k_srcCount`: Number of splats in the current renderer's range.
- `k_dstOffset`: Offset in the destination scratch buffer for the current renderer's packed data.
- `k_offsetA`: Offset of Source A (merged result) in the destination buffer.
- `k_offsetB`: Offset of Source B (current renderer) in the destination buffer.
- `k_countA`: Number of elements in Source A.
- `k_countB`: Number of elements in Source B.

**Algorithm Steps:**

1. **Packing Phase:**
   - For each renderer $k$ from $0$ to $K-1$:
     - If $\text{cnt}_k == 0$, skip renderer $k$.
     - Dispatch `m_kernelPackOrders` with parameters:
       - `k_rendererIdx = k`
       - `k_srcCount = cnt_k`
       - `k_dstOffset = off_k` (where $off_k$ is the cumulative offset of previous renderers' counts).
     - This kernel reads raw orders/depths from `res.OrderBuffer`/`res.InputKeys` and writes to `m_packScratchOrders`/`m_packScratchDepths` at offset $off_k$.

2. **Initialization:**
   - Set `mergedCount = cnt_0` (count of the first renderer).
   - Set `mergedOffset = 0`.
   - Set `mergedInPack = true` (indicating the current merged result resides in `m_packScratch` buffers).

3. **Cascaded Merge Loop:**
   - Iterate $k$ from $1$ to $K-1$:
     - Calculate `total = mergedCount + cnt_k`.
     - **Select Source A (Current Merged Result):**
       - If `mergedInPack` is true:
         - `srcAOrders = m_packScratchOrders`
         - `srcADepths = m_packScratchDepths`
       - Else:
         - `srcAOrders = m_mergeScratchOrders`
         - `srcADepths = m_mergeScratchDepths`
     - **Select Source B (Renderer $k$'s Data):**
       - `srcBOrders = m_packScratchOrders` (at offset $off_k$)
       - `srcBDepths = m_packScratchDepths` (at offset $off_k$)
     - **Select Destination:**
       - If $k == K-1$ (Final Pass):
         - `dstOrders = m_globalOrderBuffer`
         - `dstDepths = null`
       - Else:
         - If `mergedInPack` is true:
           - `dstOrders = m_mergeScratchOrders`
           - `dstDepths = m_mergeScratchDepths`
         - Else:
           - `dstOrders = m_packScratchOrders`
           - `dstDepths = m_packScratchDepths`
     - **Dispatch Merge Kernel:**
       - If `isFinal` ($k == K-1$):
         - Kernel: `m_kernelMergeTwo`
         - Parameters: `k_offsetA = mergedOffset`, `k_offsetB = off_k`, `k_countA = mergedCount`, `k_countB = cnt_k`, `k_outputOffset = 0`.
         - Bind: `srcAOrders`, `srcBOrders`, `dstOrders`.
       - Else:
         - Kernel: `m_kernelMergeTwoWithDepth`
         - Parameters: `k_offsetA = mergedOffset`, `k_offsetB = off_k`, `k_countA = mergedCount`, `k_countB = cnt_k`, `k_outputOffset = 0`.
         - Bind: `srcAOrders`, `srcADepths`, `srcBOrders`, `srcBDepths`, `dstOrders`, `dstDepths`.
       - Dispatch thread count: $\lceil \text{total} / 256 \rceil$.
     - **Update State:**
       - `mergedCount = total`
       - `mergedOffset = 0`
       - `mergedInPack = !mergedInPack` (toggle buffer ownership)

4. **Finalization:**
   - Set `m_totalRemainingCount = mergedCount`.

**Pseudocode:**

```python
def cascaded_2_way_merge(active_gsplats, m_total_splat_count, m_global_order_buffer):
    K = len(active_gsplats)
    
    # Pitfall: Early exit if insufficient renderers or no output buffer
    if K < 2 or m_global_order_buffer is None:
        return

    # Data structures (assumed pre-allocated)
    pack_orders = GraphicsBuffer(uint, m_total_splat_count, "Gsplat.PackScratchOrders")
    pack_depths = GraphicsBuffer(float, m_total_splat_count, "Gsplat.PackScratchDepths")
    merge_orders = GraphicsBuffer(uint, m_total_splat_count, "Gsplat.MergeScratchOrders")
    merge_depths = GraphicsBuffer(float, m_total_splat_count, "Gsplat.MergeScratchDepths")

    # Step 1: Pack each renderer's sorted orders and depths into scratch buffers
    offset = 0
    for k in range(K):
        cnt_k = active_gsplats[k].RemainingCount
        if cnt_k == 0:
            continue
        
        # Dispatch kernel to pack data
        # Reads from active_gsplats[k].OrderBuffer / InputKeys
        # Writes to pack_orders / pack_depths at offset
        dispatch_kernel_pack_orders(
            renderer_idx=k,
            src_count=cnt_k,
            dst_offset=offset,
            src_orders=active_gsplats[k].OrderBuffer,
            src_depths=active_gsplats[k].InputKeys,
            dst_orders=pack_orders,
            dst_depths=pack_depths
        )
        offset += cnt_k

    # Step 2: Initialize merged state
    merged_count = active_gsplats[0].RemainingCount
    merged_offset = 0
    merged_in_pack = True  # Current merged result is in pack buffers

    # Step 3: Iterate and merge
    for k in range(1, K):
        cnt_k = active_gsplats[k].RemainingCount
        if cnt_k == 0:
            continue
            
        total = merged_count + cnt_k
        is_final = (k == K - 1)
        
        # Select Source A (Current Merged Result)
        if merged_in_pack:
            src_a_orders = pack_orders
            src_a_depths = pack_depths
        else:
            src_a_orders = merge_orders
            src_a_depths = merge_depths
            
        # Select Source B (Renderer k's Data)
        # Note: Source B is always in pack buffers at offset off_k
        # We need to track off_k. In the loop, off_k is the offset where renderer k's data was packed.
        # Assuming we can retrieve this or it's implicitly handled by the kernel binding logic.
        # For implementation clarity, we assume src_b_orders/depths point to pack buffers at the correct offset.
        src_b_orders = pack_orders
        src_b_depths = pack_depths
        
        # Select Destination
        if is_final:
            dst_orders = m_global_order_buffer
            dst_depths = None
        else:
            if merged_in_pack:
                dst_orders = merge_orders
                dst_depths = merge_depths
            else:
                dst_orders = pack_orders
                dst_depths = pack_depths
        
        # Dispatch Merge Kernel
        k_offset_a = merged_offset
        k_offset_b = 0 # Offset within Source B's local range (always 0 for the renderer's own buffer)
        k_count_a = merged_count
        k_count_b = cnt_k
        k_output_offset = 0
        
        thread_count = (total + 255) // 256
        
        if is_final:
            dispatch_kernel_merge_two(
                offset_a=k_offset_a,
                offset_b=k_offset_b,
                count_a=k_count_a,
                count_b=k_count_b,
                output_offset=k_output_offset,
                src_a_orders=src_a_orders,
                src_b_orders=src_b_orders,
                dst_orders=dst_orders
            )
        else:
            dispatch_kernel_merge_two_with_depth(
                offset_a=k_offset_a,
                offset_b=k_offset_b,
                count_a=k_count_a,
                count_b=k_count_b,
                output_offset=k_output_offset,
                src_a_orders=src_a_orders,
                src_a_depths=src_a_depths,
                src_b_orders=src_b_orders,
                src_b_depths=src_b_depths,
                dst_orders=dst_orders,
                dst_depths=dst_depths
            )
            
        # Update State
        merged_count = total
        merged_offset = 0
        merged_in_pack = not merged_in_pack

    # Step 4: Finalization
    m_total_remaining_count = merged_count
```

**Edge Cases and Pitfalls:**
- If $K < 2$ or `m_globalOrderBuffer` is null, the merge process returns immediately without performing any merges [S1, unofficial].
- If a renderer's count is 0, it is skipped during the packing phase [S1, unofficial].
- The algorithm requires GPU subgroups/wave operations, which are only available in D3D12, Metal, or Vulkan graphics APIs [S1, unofficial]. WebGPU supports subgroups but Unity has not implemented it for this feature [S1, unofficial].
- Global sort is all-or-nothing: presence of any uncompressed renderer forces fallback to per-renderer sorting [S1, unofficial].

## Subtopics

### [Global Splat Merge and Rendering](7691-global-splat-merge-and-rendering.md)
Global Splat Merge and Rendering is a technique that merges multiple independent Gaussian Splat renderers into a single global draw call by packing their splat data, spherical harmonic (SH) coefficients, and depth/order information into shared global buffers, then performing a cascaded merge of depth-sorted orders. It merges two or more active Gaussian splat renderers into a single globally depth-sorted draw call to reduce overdraw and improve sorting accuracy across scenes. Unlike per-renderer rendering, where each renderer handles its own depth sorting and draw calls independently, this method delegates sorting execution to a global sorter and rendering to a global renderer, triggered when camera movement exceeds thresholds or refresh rate dictates.

### Global Depth Sorting for 3DGS
Global Depth Sorting for 3DGS sorts Gaussians across multiple renderers globally using GPU subgroups/waves to maintain correct depth ordering in a unified scene [S1, unofficial]. It is activated by the `EnableGlobalSort` boolean setting, which requires all active renderers to use compressed assets [S1, unofficial]. A key pitfall is that global sort is all-or-nothing: the presence of any uncompressed renderer forces a fallback to per-renderer sorting [S1, unofficial].

## Operating characteristics
- **Time Complexity:** The merging process is $O(N \log K)$, where $N$ is the total number of splats and $K$ is the number of active renderers. Each merge step is linear in the number of elements being merged, and there are $K-1$ merge steps.
- **Memory Complexity:** $O(N)$ for the scratch buffers (`m_packScratchOrders`, `m_packScratchDepths`, `m_mergeScratchOrders`, `m_mergeScratchDepths`) and the global order buffer.
- **Measured Performance:** Performance depends on the GPU's subgroup/wave support. Requires D3D12, Metal, or Vulkan [S1, unofficial].
- **Scaling:** Scales linearly with the number of splats and logarithmically with the number of renderers.
- **Strengths:** Reduces overdraw, improves sorting accuracy across scenes, enables unified rendering of multiple scenes.
- **Limitations:** Requires compressed assets for all renderers, limited to specific graphics APIs, all-or-nothing activation.
- **When to use:** When rendering multiple Gaussian Splat scenes in a single viewport with overlapping depth ranges.
- **When not to use:** When renderers use uncompressed assets, or when the target platform does not support GPU subgroups (e.g., older APIs, WebGPU in Unity).

## Background
The method originates from the `wuyize25/gsplat-unity` project, an unofficial implementation of Gaussian Splatting for Unity [S1, unofficial]. It builds on the `b0nes164/GPUSorting` library for GPU-based sorting primitives [S1, unofficial]. The technique was developed to address the limitations of per-renderer sorting in multi-scene environments, providing a more efficient and accurate way to composite multiple Gaussian Splat scenes.
