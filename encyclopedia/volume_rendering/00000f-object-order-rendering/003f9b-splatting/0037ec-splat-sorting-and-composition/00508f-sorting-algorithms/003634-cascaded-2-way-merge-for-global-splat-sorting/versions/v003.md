# Cascaded 2-way Merge for Global Splat Sorting

Also called: Cascaded Binary Merge, Global Splat Merge

## Overview
This method merges depth-sorted splat lists from multiple independent Gaussian Splat renderers into a single globally depth-sorted order buffer using a cascaded binary merge tree [S1, unofficial]. It solves the problem of incorrect depth ordering and excessive overdraw when multiple renderers operate in the same scene by delegating sorting execution to a global sorter and rendering to a global renderer [S1, unofficial]. Unlike per-renderer rendering, where each renderer handles its own depth sorting and draw calls independently, this approach triggers a global merge when camera movement exceeds thresholds or refresh rate dictates [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A list of $K$ active renderers. Each renderer $k$ provides a sorted list of splat orders and depths.
*   **Outputs:** A single global order buffer (`m_globalOrderBuffer`) containing the merged, depth-sorted indices.

**Data Structures:**
The algorithm uses four scratch buffers and one global output buffer, all allocated with size `m_totalSplatCount` (the sum of splat counts from all active renderers).

1.  `m_packScratchOrders`: `GraphicsBuffer` of type `uint`, name `'Gsplat.PackScratchOrders'`.
2.  `m_packScratchDepths`: `GraphicsBuffer` of type `float`, name `'Gsplat.PackScratchDepths'`.
3.  `m_mergeScratchOrders`: `GraphicsBuffer` of type `uint`, name `'Gsplat.MergeScratchOrders'`.
4.  `m_mergeScratchDepths`: `GraphicsBuffer` of type `float`, name `'Gsplat.MergeScratchDepths'`.
5.  `m_globalOrderBuffer`: `GraphicsBuffer` holding the final sorted global order.

**Parameters:**
*   `k_rendererIdx`: Index of the current renderer being packed.
*   `k_srcCount`: Number of splats in the current renderer's range.
*   `k_dstOffset`: Offset in the destination scratch buffer for the current renderer's packed data.
*   `k_offsetA`: Offset of Source A (merged result) in the destination buffer.
*   `k_offsetB`: Offset of Source B (current renderer) in the destination buffer.
*   `k_countA`: Number of elements in Source A.
*   `k_countB`: Number of elements in Source B.

**Algorithm Steps:**

1.  **Validation:** If the number of active renderers $K < 2$ or `m_globalOrderBuffer` is null, return immediately [S1, unofficial].
2.  **Pack Phase:** For each renderer $k$ from $0$ to $K-1$:
    *   Let `cnt` be the remaining splat count for renderer $k$.
    *   If `cnt` is 0, skip this renderer [S1, unofficial].
    *   Let `off` be the cumulative offset of previous renderers' counts.
    *   Dispatch kernel `m_kernelPackOrders` with parameters `k_rendererIdx=k`, `k_srcCount=cnt`, `k_dstOffset=off`.
    *   This kernel copies raw orders and depths from the renderer's `res.OrderBuffer` and `res.InputKeys` into `m_packScratchOrders` and `m_packScratchDepths` at offset `off` [S1, unofficial].
3.  **Initialize Merge State:**
    *   `mergedCount` = `activeGsplats[0].RemainingCount`
    *   `mergedOffset` = 0
    *   `mergedInPack` = `true` (indicates the current merged result resides in `m_packScratch` buffers)
4.  **Cascaded Merge Loop:** Iterate $k$ from $1$ to $K-1$:
    *   Let `cntK` be `activeGsplats[k].RemainingCount`.
    *   Calculate `total` = `mergedCount` + `cntK`.
    *   **Select Source A (Current Merged Result):**
        *   If `mergedInPack` is `true`, Source A orders/depths are in `m_packScratchOrders`/`m_packScratchDepths`.
        *   Otherwise, Source A orders/depths are in `m_mergeScratchOrders`/`m_mergeScratchDepths`.
    *   **Select Source B (Renderer $k$'s Data):**
        *   Source B orders/depths are in `m_packScratchOrders` and `m_packScratchDepths` at offset `offK` (where `offK` is the cumulative offset for renderer $k$) [S1, unofficial].
    *   **Select Destination:**
        *   If $k == K-1$ (final pass), Destination Orders is `m_globalOrderBuffer`, and Destination Depths is `null`.
        *   Otherwise, Destination is the buffer *not* currently holding the merged result (swaps between `m_mergeScratch` and `m_packScratch`).
    *   **Dispatch Merge Kernel:**
        *   If `isFinal` ($k == K-1$), use kernel `m_kernelMergeTwo`.
        *   Otherwise, use kernel `m_kernelMergeTwoWithDepth`.
        *   Set kernel parameters: `k_offsetA=mergedOffset`, `k_offsetB=offK`, `k_countA=mergedCount`, `k_countB=cntK`, `k_outputOffset=0`.
        *   Bind Source A, Source B, Destination Orders, and Destination Depths (if not final).
        *   Dispatch with thread count `DivRoundUp(total, 256)` [S1, unofficial].
    *   **Update State:**
        *   `mergedCount` = `total`
        *   `mergedOffset` = 0
        *   `mergedInPack` = `true` if Destination was `m_packScratch`, else `false` [S1, unofficial].
5.  **Finalize:** Set `m_totalRemainingCount` = `mergedCount` [S1, unofficial].

**Pseudocode:**

```python
def cascaded_2_way_merge(active_renderers, buffers):
    """
    active_renderers: List of renderer objects, each having RemainingCount and InputKeys/OrderBuffer.
    buffers: Dictionary containing m_packScratchOrders, m_packScratchDepths, 
             m_mergeScratchOrders, m_mergeScratchDepths, m_globalOrderBuffer.
    """
    K = len(active_renderers)
    
    # Pitfall: Early exit if insufficient renderers or no global buffer
    if K < 2 or buffers['m_globalOrderBuffer'] is None:
        return

    # Step 1: Pack Phase
    cumulative_offset = 0
    for k in range(K):
        cnt = active_renderers[k].RemainingCount
        if cnt == 0:
            continue
        
        # Dispatch packing kernel
        # m_kernelPackOrders(k_rendererIdx=k, k_srcCount=cnt, k_dstOffset=cumulative_offset)
        # Implementation detail: Copies from renderer k's buffers to scratch buffers at offset
        pack_kernel_dispatch(
            src_orders=active_renderers[k].OrderBuffer,
            src_depths=active_renderers[k].InputKeys,
            dst_orders=buffers['m_packScratchOrders'],
            dst_depths=buffers['m_packScratchDepths'],
            offset=cumulative_offset,
            count=cnt
        )
        cumulative_offset += cnt

    # Step 2: Initialize Merge State
    merged_count = active_renderers[0].RemainingCount
    merged_offset = 0
    merged_in_pack = True  # Result is currently in m_packScratch

    # Step 3: Cascaded Merge Loop
    for k in range(1, K):
        cnt_k = active_renderers[k].Remaining_count
        total = merged_count + cnt_k
        
        # Determine offsets for Source B (Renderer k's packed data)
        # Note: In the source, offK is calculated based on cumulative counts. 
        # For simplicity in this pseudocode, we assume we know the offset for renderer k's packed data.
        # In the actual implementation, this offset is pre-calculated during the pack phase or derived.
        # Here we assume a helper to get the offset for renderer k's packed data in m_packScratch.
        offset_b = get_packed_offset_for_renderer(k, active_renderers)

        # Select Source A
        if merged_in_pack:
            src_a_orders = buffers['m_packScratchOrders']
            src_a_depths = buffers['m_packScratchDepths']
        else:
            src_a_orders = buffers['m_mergeScratchOrders']
            src_a_depths = buffers['m_mergeScratchDepths']

        # Select Source B (always from pack scratch at offset_b)
        src_b_orders = buffers['m_packScratchOrders']
        src_b_depths = buffers['m_packScratchDepths']

        # Select Destination
        is_final = (k == K - 1)
        if is_final:
            dst_orders = buffers['m_globalOrderBuffer']
            dst_depths = None
        else:
            # Swap buffers: if merged_in_pack is true, dst is merge scratch, else pack scratch
            if merged_in_pack:
                dst_orders = buffers['m_mergeScratchOrders']
                dst_depths = buffers['m_mergeScratchDepths']
            else:
                dst_orders = buffers['m_packScratchOrders']
                dst_depths = buffers['m_packScratchDepths']

        # Dispatch Merge Kernel
        if is_final:
            # Final pass: no depth output
            merge_kernel_two(
                src_a_orders=src_a_orders,
                src_a_depths=src_a_depths,
                src_b_orders=src_b_orders,
                src_b_depths=src_b_depths,
                dst_orders=dst_orders,
                k_offset_a=merged_offset,
                k_offset_b=offset_b,
                k_count_a=merged_count,
                k_count_b=cnt_k,
                k_output_offset=0
            )
        else:
            # Intermediate pass: output depths
            merge_kernel_two_with_depth(
                src_a_orders=src_a_orders,
                src_a_depths=src_a_depths,
                src_b_orders=src_b_orders,
                src_b_depths=src_b_depths,
                dst_orders=dst_orders,
                dst_depths=dst_depths,
                k_offset_a=merged_offset,
                k_offset_b=offset_b,
                k_count_a=merged_count,
                k_count_b=cnt_k,
                k_output_offset=0
            )

        # Update State
        merged_count = total
        merged_offset = 0
        # If destination was pack scratch, merged result is in pack scratch
        if dst_orders is buffers['m_packScratchOrders']:
            merged_in_pack = True
        else:
            merged_in_pack = False

    # Step 4: Finalize
    buffers['m_totalRemainingCount'] = merged_count
```

## Subtopics

### [Global Splat Merge and Rendering](7691-global-splat-merge-and-rendering.md)
Global Splat Merge and Rendering is a technique that merges multiple independent Gaussian Splat renderers into a single global draw call by packing their splat data, spherical harmonic (SH) coefficients, and depth/order information into shared global buffers, then performing a cascaded merge of depth-sorted orders. It merges two or more active Gaussian splat renderers into a single globally depth-sorted draw call to reduce overdraw and improve sorting accuracy across scenes. Unlike per-renderer rendering, where each renderer handles its own depth sorting and draw calls independently, this method delegates sorting execution to a global sorter and rendering to a global renderer, triggered when camera movement exceeds thresholds or refresh rate dictates.

### Global Depth Sorting for 3DGS
Global Depth Sorting for 3DGS sorts Gaussians across multiple renderers globally using GPU subgroups/waves to maintain correct depth ordering in a unified scene [S1, unofficial]. It is activated by the `EnableGlobalSort` boolean setting, which requires all active renderers to use compressed assets [S1, unofficial]. A key pitfall is that global sort is all-or-nothing: the presence of any uncompressed renderer forces a fallback to per-renderer sorting [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The merge process is $O(N \log K)$, where $N$ is the total number of splats and $K$ is the number of active renderers. Each merge step is linear in the number of elements being merged, and there are $\log K$ levels in the cascaded tree.
*   **Memory Complexity:** Requires $O(N)$ additional memory for scratch buffers (`m_packScratch` and `m_mergeScratch`), where $N$ is the total splat count.
*   **Hardware Requirements:** Requires GPU support for wave/subgroup operations, available in D3D12, Metal, or Vulkan. WebGPU supports subgroups but Unity has not implemented it. Other graphics APIs are not supported [S1, unofficial].
*   **Strengths:** Reduces overdraw and improves sorting accuracy across multiple scenes/renderers. Compatible with MSAA and XR (Multi-pass in BiRP/URP, Single Pass Instanced in URP) [S1, unofficial].
*   **Limitations:** Requires all active renderers to use compressed assets for global depth sorting. Fallback to per-renderer sorting occurs if any uncompressed renderer is present. Platform-specific setup is required (e.g., Vulkan/D3D12 on Windows, specific Android settings) [S1, unofficial].

## Background
This method is part of the `gsplat-unity` package by Yize Wu, which implements Gaussian Splatting in Unity. It builds upon the `b0nes164/GPUSorting` library for GPU-based sorting operations [S1, unofficial]. The technique addresses the limitations of per-renderer sorting in multi-scene or multi-camera setups by providing a global sorting mechanism.
