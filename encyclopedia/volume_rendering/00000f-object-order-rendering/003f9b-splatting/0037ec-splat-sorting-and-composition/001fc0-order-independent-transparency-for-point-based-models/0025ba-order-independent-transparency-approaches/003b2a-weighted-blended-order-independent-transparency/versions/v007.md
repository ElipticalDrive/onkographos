# Weighted Blended Order-Independent Transparency

Also called: OIT based implementation, WBOIT (Weighted Blended Order-Independent Transparency), WBOT Transparency Mode, Weighted Blended OIT

## Overview
Weighted Blended Order-Independent Transparency (WBOIT) is a transparency rendering technique that bypasses explicit depth sorting to achieve order-independent blending, primarily intended for resource-constrained CPUs and weaker GPUs (e.g., integrated graphics) [S1, unofficial]. It solves the problem of incorrect alpha blending in standard fixed-function pipelines by encoding depth information into blending weights, allowing the GPU to accumulate translucent layers in a single pass without depth-based sorting [S2]. Unlike siblings such as [Improved Order Independent Transparency for Opaque Kernels](4562-improved-order-independent-transparency-for-opaque-kernels.md) or [Hardware-Z Cull Depth Peeling](13947-hardware-z-cull-depth-peeling.md), WBOIT does not require multiple rendering passes or complex depth peeling logic, but instead relies on heuristic weight assignment to approximate occlusion [S2].

## How it works
WBOIT modifies the standard volume rendering equation by introducing weights that estimate the occlusion for each depth as a function of the transparency of the rest of the objects considered [S2]. The algorithm operates by enabling a specific compositor viewport and configuring weight parameters, rather than performing geometric sorting [S1, unofficial].

### Inputs and Outputs
*   **Inputs:** A stream of splats or translucent primitives, each defined by position, color, opacity, and potentially higher-order coefficients (e.g., spherical harmonics).
*   **Outputs:** A final composited image where translucent layers are blended in an order-independent manner, approximating the correct depth-sorted accumulation.

### Data Structures
The method relies on standard GPU fragment shader state and specific compositor viewport configurations. In implementations such as the `gsplat_rviz_plugin`, the input data is often structured in a `SplatGPU` format for efficient transfer to the GPU [S1, unofficial].

**SplatGPU Layout (304 bytes, aligned to 4 bytes):**
*   `center[3]` (12 bytes): Float3, splat center coordinates $(x, y, z)$.
*   `alpha` (4 bytes): Float, opacity.
*   `covA[3]` (12 bytes): Float3, upper-triangle covariance components $\{v_{11}, v_{12}, v_{13}\}$.
*   `_pad0` (4 bytes): Padding.
*   `covB[3]` (12 bytes): Float3, remaining covariance components $\{v_{22}, v_{23}, v_{33}\}$.
*   `_pad1` (4 bytes): Padding.
*   `sh[16][4]` (256 bytes): Float16x4, Spherical Harmonics coefficients. `sh[i][0..2]` stores RGB, `sh[i][3]` is 0.

*Note: The exact layout above is specific to the cited implementation [S1, unofficial]. General WBOIT implementations may use simpler primitive structures.*

### Parameters
The quality and behavior of WBOIT are controlled by three primary parameters, which often require expert adjustment for each specific scene [S2]:
1.  **WBOIT Weight Scale:** Controls the scaling factor for the depth-based weights. Set via `setWboitWeightScale` [S1, unofficial].
2.  **WBOIT Weight Exponent:** Controls the exponent applied to the depth weight, influencing how sharply distant fragments are attenuated. Set via `setWboitWeightExponent` [S1, unofficial].
3.  **WBOIT Alpha Discard Threshold:** Fragments with opacity below this threshold are discarded to reduce noise and computational load. Set via `setWboitAlphaDiscard` [S1, unofficial].

### Steps
1.  **Initialization:** When WBOIT is enabled (e.g., `transparency_mode_property` is 1), ensure the compositor is defined and active [S1, unofficial].
    *   Call `ensureDefined()`.
    *   Enable the compositor viewport: `enable(vp)`.
    *   Set `compositor_viewport_ = vp`.
    *   Set `wboit_compositor_active_ = true`.
2.  **Configuration:** Apply the weight scale, weight exponent, and alpha discard threshold using the respective setter functions [S1, unofficial].
3.  **Rendering:** Render the scene. The fragment shader uses the configured weights to blend fragments. The weight $w_i$ for a fragment $i$ is typically a function of its depth $z_i$ relative to the camera and the scene's depth range, designed to approximate the transmittance term $\prod (1-\alpha_j)$ [S2].
    *   *Note: The exact mathematical formula for the weight $w_i$ is not provided in the sources, but it is described as estimating occlusion as a function of the transparency of the rest of the objects [S2].*
4.  **Disabling:** If WBOIT is disabled, call `disable(compositor_viewport_)` and set `wboit_compositor_active_ = false` [S1, unofficial].

### Pseudocode
```python
# Pseudocode for enabling WBOIT in a compositor-based renderer
# Based on [S1, unofficial]

def enable_wboit(compositor_viewport, weight_scale, weight_exponent, alpha_discard_threshold):
    """
    Enables Weighted Blended Order-Independent Transparency.
    """
    # Ensure the compositor is defined
    ensure_defined()
    
    # Enable the specific viewport for compositing
    enable(compositor_viewport)
    
    # Store the active viewport
    compositor_viewport_ = compositor_viewport
    
    # Mark WBOIT as active
    wboit_compositor_active_ = true
    
    # Set the weight parameters
    set_wboit_weight_scale(weight_scale)
    set_wboit_weight_exponent(weight_exponent)
    set_wboit_alpha_discard(alpha_discard_threshold)

def disable_wboit(compositor_viewport):
    """
    Disables WBOIT.
    """
    if wboit_compositor_active_:
        disable(compositor_viewport)
        wboit_compositor_active_ = false

# Fragment Shader Logic (Conceptual)
# The sources do not provide the exact GLSL/HLSL code for the weight calculation.
# However, the weight w is used to blend the fragment color C and alpha a.
# Standard alpha blending:
# C_out = C_in * (1 - a) + C_frag * a
# WBOIT modifies this by using a weight w to scale the contribution or alpha.
# A common WBOIT formulation (not explicitly detailed in sources) is:
# w = exp(-scale * (z - z_near) / (z_far - z_near)) ^ exponent
# alpha_eff = alpha * w
# Then blend using alpha_eff.
```

### Edge Cases and Pitfalls
*   **Cluster Quality Degradation:** Rendering quality decreases significantly in cases with close clusters of several transparent elements of different colors [S2].
*   **Expert Tuning Required:** The assignment of weights (scale and exponent) requires expert adjustment for each scene to achieve quality sorting [S2].
*   **Not Suitable for High-Precision Medical Data:** Due to the variability in results and lack of precise depth sorting, WBOIT is considered unsuitable for medical image visualization where accuracy in any depth range is essential [S2].

## Subtopics

### Per-Pixel Linked Lists for Order Independent Transparency
An Order Independent Transparency (OIT) technique that operates at the fragment level to analyze and sort all object depths linked to each pixel, avoiding layer-based grouping and ensuring precise blending suitable for volumetric data fusion [S2]. It requires two rendering passes per frame, regardless of scene complexity, to achieve real-time performance while maintaining accurate depth sorting [S2]. Unlike WBOIT, which performs sorting in a single pass but suffers from quality degradation in clusters of transparent elements and requires expert weight adjustment, Per-Pixel Linked Lists provide accurate sorting without scene-specific weight tuning [S2]. Unlike Depth Peeling, which requires separate passes for each depth layer, and Dual Depth Peeling, which may store elements at different depths within the same layer, Per-Pixel Linked Lists provide precise per-fragment depth sorting without layer-based grouping [S2].

## Operating characteristics
*   **Time Complexity:** Single pass rendering, making it computationally efficient compared to multi-pass methods like Depth Peeling [S2].
*   **Memory Complexity:** Low memory overhead as it does not require storing linked lists or multiple depth buffers [S2].
*   **Performance:** Suitable for resource-constrained CPUs and weaker GPUs (e.g., integrated graphics) [S1, unofficial].
*   **Strengths:** Simple implementation, low computational cost, no need for depth-based sorting [S2].
*   **Limitations:** Rendering quality varies greatly depending on the scene type; poor performance with close clusters of transparent elements of different colors; requires expert tuning of weights for each scene [S2].
*   **When to Use:** Resource-constrained environments where approximate transparency is acceptable and scene complexity is low or uniform.
*   **When Not to Use:** High-precision applications (e.g., medical visualization) where accurate depth sorting is critical, or scenes with complex clusters of transparent objects [S2].

## Background
WBOIT was introduced as a weight-based sorting OIT technique to reduce the computational cost of rendering by performing sorting in a single pass without depth-based sorting [S2]. It is cited in the context of order-independent transparency approaches for point-based models [S2]. The method is implemented in the `gsplat_rviz_plugin` for ROS-based visualization, where it is activated via the 'Advanced' options of the RViz plugin [S1, unofficial].
