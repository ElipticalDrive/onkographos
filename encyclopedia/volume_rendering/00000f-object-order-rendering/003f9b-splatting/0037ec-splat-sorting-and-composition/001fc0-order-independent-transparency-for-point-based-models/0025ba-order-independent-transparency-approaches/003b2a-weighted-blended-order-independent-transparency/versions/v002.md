# Weighted Blended Order-Independent Transparency

Also called: Weighted Blended OIT

## Overview
Weighted Blended Order-Independent Transparency (WBOIT) is a weight-based sorting technique that approximates correct alpha compositing by performing blending in a single rendering pass, thereby avoiding the computational cost of explicit depth sorting [S1]. It distinguishes itself from sibling methods like Per-Pixel Linked Lists by trading precise depth accuracy for significantly reduced hardware overhead, making it suitable for scenes where exact occlusion is less critical than performance [S1].

## How it works
WBOIT modifies the standard alpha blending equation to incorporate a weight that estimates the occlusion contribution of fragments based on their transparency, allowing the hardware's fixed-function blending unit to approximate a sorted accumulation [S1].

**Inputs and Outputs:**
*   **Input:** A stream of translucent fragments with color $(C)$ and opacity $(\alpha)$, and a user-defined weight parameter $(w)$.
*   **Output:** A final color buffer approximating the correct order-independent blend.

**Data Structures:**
*   Standard Frame Buffer (Color and Depth).
*   No additional accumulation buffers or linked lists are required [S1].

**Parameters:**
*   **Weight ($w$):** A scalar value used to scale the contribution of each fragment. The sources note that this value is not fixed; it requires expert adjustment for each specific scene based on the distribution of elements to achieve quality sorting [S1]. Typical values are not provided in the sources.

**Algorithm Steps:**
1.  **Fragment Processing:** For each fragment $i$ with color $C_i$ and opacity $\alpha_i$, calculate a weight $w_i$. The sources do not provide a specific formula for $w_i$, only that it is derived from the translucency equation to estimate occlusion [S1].
2.  **Blending:** Use the standard hardware blending operation (e.g., `GL_BLEND` in OpenGL) with a custom blend function. The fragment's contribution is weighted by $w_i$. The exact blend equation is not explicitly defined in the sources, but it operates by running through the scene to estimate occlusion for each depth as a function of the transparency of the rest of the objects [S1].
3.  **Accumulation:** The hardware accumulates the weighted fragments into the color buffer in a single pass [S1].

**Edge Cases and Pitfalls:**
*   **Color Clusters:** Rendering quality decreases significantly in cases with close clusters of several transparent elements of different colors [S1].
*   **Weight Tuning:** The assignment of weights requires expert adjustment for each scene according to the distribution of elements if quality sorting is to be achieved [S1].
*   **Medical Data Integrity:** Due to the potential for inaccurate depth sorting, this method is considered unsuitable for medical image visualization where preserving the integrity of underlying data is essential [S1].

## Subtopics

### Per-Pixel Linked Lists for Order Independent Transparency
An Order Independent Transparency (OIT) technique that operates at the fragment level to analyze and sort all object depths linked to each pixel, avoiding layer-based grouping and ensuring precise blending suitable for volumetric data fusion [S1]. Unlike Weighted Blended Order-Independent Transparency, which performs sorting in a single pass but suffers from quality degradation in clusters of transparent elements and requires expert weight adjustment, Per-Pixel Linked Lists provide accurate sorting without scene-specific weight tuning [S1]. However, it requires two rendering passes per frame, regardless of scene complexity, to achieve real-time performance [S1].

## Operating characteristics
*   **Time Complexity:** Single pass rendering, making it computationally less intensive than sorting-based methods [S1].
*   **Memory Complexity:** Low; it does not require additional memory for linked lists or depth peeling buffers [S1].
*   **Performance:** The algorithm is not computationally or memory-intensive [S1].
*   **Strengths:** High performance due to single-pass execution; no need for depth-based sorting [S1].
*   **Limitations:** Rendering quality varies greatly depending on the scene type; poor accuracy in clusters of different-colored transparent elements; requires manual weight tuning per scene [S1].
*   **When to use:** When performance is critical and exact depth sorting is not required.
*   **When not to use:** For medical image visualization or any application requiring high accuracy in depth range and color blend integrity [S1].
