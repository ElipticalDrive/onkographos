# Order Independent Transparency Approaches

Also called: Transparency Handling

## Overview
Order Independent Transparency (OIT) approaches solve the problem of correctly compositing translucent fragments without requiring explicit depth sorting, which is computationally expensive for large fragment counts [S1, unofficial]. Unlike standard alpha blending, which assumes a fixed draw order and produces incorrect results on arbitrary overlaps, OIT methods approximate the correct accumulation in a single or multi-pass pipeline [S1, unofficial]. This family encompasses techniques that either approximate commutative blending via weights or separate the closest fragment's contribution to reduce artifacts in dense splatting, as detailed in its child methods [Improved Order Independent Transparency for Opaque Kernels](4562-improved-order-independent-transparency-for-opaque-kernels.md) and [Weighted Blended Order-Independent Transparency](8931-weighted-blended-order-independent-transparency.md).

## Shared principles
All methods in this family address the fundamental issue that alpha compositing is not commutative; a stack of translucent objects renders differently depending on the draw order [S1, unofficial]. Standard hardware blending cannot handle arbitrary fragment overlaps correctly without sorting [S1, unofficial]. The shared goal is to avoid the high cost of CPU-side sorting (e.g., ~150ms for 1M splats) or complex GPU-side sorting algorithms like Bitonic Sort, which may be too slow or buggy on certain hardware [S1, unofficial]. Approaches typically modify the rendering pipeline to either approximate order-independent accumulation using weights or heuristics, or to isolate the closest fragment's contribution before blending the remainder [S1, unofficial]. Common data structures include standard frame buffers (color and depth) and, for weight-based variants, an additional render buffer to store occlusion weights [S1, unofficial].

## Subtopics

### [Improved Order Independent Transparency for Opaque Kernels](4562-improved-order-independent-transparency-for-opaque-kernels.md)
A multi-pass variant that improves rendering of opaque kernels by explicitly incorporating the closest sample's contribution and using a weighted average for the rest. It solves transparency artifacts and aliasing in dense models while maintaining performance close to geometry instancing.

### [Weighted Blended Order-Independent Transparency](8931-weighted-blended-order-independent-transparency.md)
A weight-based technique that reduces computational cost by performing blending in a single pass without explicit depth sorting. It uses weights in the translucency equation to estimate occlusion, achieving single-pass performance at the expense of accuracy in complex scenes with clustered translucent elements.

## Background
The problem of rendering translucent objects is described as "somewhat unsolved" in real-time computer graphics due to the non-commutative nature of compositing [S1, unofficial]. Early or simple solutions included:
* **Speculative Transparency:** Simulating translucency by randomly discarding pixels based on opacity, resulting in a noisy, dithered look [S1, unofficial].
* **Painter's Algorithm:** Pre-sorting all objects before rendering, which is expensive on the CPU for large datasets [S1, unofficial].
* **Depth Peeling:** A multi-pass technique that renders the top translucent layer, peels it off, and repeats, but is expected to be slow and difficult to implement efficiently [S1, unofficial].

The specific OIT variants discussed here emerged as alternatives to these methods, particularly in the context of Gaussian Splatting and point-based rendering, where GPU-side sorting was deemed too slow or buggy on certain platforms (e.g., WebGL 2.0 on Safari with M1 chips) [S1, unofficial]. Weighted Blended OIT was noted as not working well in experiments with high-opacity splats, leading the author to settle on running the sorting process on the CPU in a webworker instead [S1, unofficial].
