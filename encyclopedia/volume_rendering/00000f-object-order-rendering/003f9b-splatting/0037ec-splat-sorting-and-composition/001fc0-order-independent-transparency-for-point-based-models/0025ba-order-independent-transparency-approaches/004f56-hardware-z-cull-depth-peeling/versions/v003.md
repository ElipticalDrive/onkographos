# Hardware-Z Cull Depth Peeling

Also called: Modified depth peeling with z-buffer culling, OIT approach with hardware depth test

## Overview
Hardware-Z Cull Depth Peeling is an Order-Independent Transparency (OIT) technique for rendering semi-transparent layers on animated surfaces, specifically designed to overcome the performance bottlenecks of standard depth peeling [S1]. It solves the problem of expensive fragment shader invocations and high wave divergence caused by software-based culling and conditional shading in traditional peeling methods [S1]. By utilizing the hardware z-buffer for culling instead of shader-based discard operations, it reduces unnecessary GPU work and ensures that lighting computations are performed only for visible pixels [S1].

## How it works
The method modifies standard depth peeling by rendering transparent layers sequentially, one per pass, until the last layer is reached or a user-defined maximum number of layers is exceeded [S1]. Each rendering pass consists of four distinct steps that separate depth finding, depth buffer management, shading, and final culling updates [S1].

### Inputs and Outputs
*   **Inputs:**
    *   Previous layer's depth buffer (read-only).
    *   Encoded surface geometry (implicit surface or shell geometry) [S1].
    *   Accumulated opacity from previous passes [S1].
    *   User-defined parameters: `max_layers` (typical value: 4) and `opacity_threshold` (typical value: 0.95) [S1].
*   **Outputs:**
    *   Updated hardware z-buffer.
    *   Accumulated color buffer with the new layer blended in.

### Data Structures
*   **Z-Buffer:** Standard hardware depth buffer. Values are compared using standard depth functions. A special value `z_max` (far culling plane) is used to represent culled or invisible regions [S1].
*   **Color Buffer:** Accumulates the final color using hardware alpha blending [S1].
*   **Layer Depth Texture:** A temporary texture used in Step 1 to store the nearest depth found for the current layer before it is converted to the hardware z-buffer [S1].

### Parameters
*   `max_layers`: The maximum number of transparency layers to render. Empirical results suggest 3-4 passes are sufficient for many cases [S1].
*   `opacity_threshold`: The accumulated opacity threshold. If the accumulated opacity exceeds this value (e.g., 0.95), subsequent layers are treated as invisible and culled [S1].

### Steps
Each pass processes one new transparency layer and blends it with previously rendered layers [S1].

1.  **Layer Depth Finding:**
    *   Set the previous layer's depth as the z-buffer in read-only mode [S1].
    *   Render the geometry for the current layer.
    *   For each fragment, search for intersection with the encoded surface to determine if the fragment should be discarded [S1]. Without this check, transparent parts would occupy each layer, requiring more passes for a correct image [S1].
    *   Write the nearest depth as output color using a 'min' blending function [S1]. This step finds the depth of the new layer without performing shading [S1].

2.  **Depth Conversion #1:**
    *   Perform a full-screen pass to convert the found depth from the texture into the hardware z-buffer [S1]. Due to hardware restrictions, the depth cannot be copied directly from a texture to the z-buffer; the shader must modify the fragment depth [S1].
    *   Compare the new layer's depth with the previous scene's depth [S1].
    *   If the layer's depth is greater than the previous scene's depth, cull the fragment and write the far culling plane value (`z_max`) into the z-buffer [S1]. This ensures all layers behind the current visible surface are also culled [S1].

3.  **Layer Shading:**
    *   Perform shading for the new layer [S1].
    *   Set the z-function to 'equal' to ensure lighting computations are performed only for visible pixels without overdraw [S1]. This separation of depth finding and shading minimizes lighting calculations and avoids wave divergence caused by conditional discards in the same draw call [S1].
    *   Use hardware alpha-blending to blend the new layer with previously rendered layers [S1].

4.  **Depth Conversion #2:**
    *   Perform a full-screen pass similar to Step 2 [S1].
    *   Check if the accumulated opaqueness is greater than the `opacity_threshold` (e.g., 0.95) [S1].
    *   If the accumulated opacity exceeds the threshold, write `z_max` into the z-buffer [S1]. This treats all subsequent layers as invisible in this region and culls them, preventing unnecessary rendering of deep, occluded layers [S1].

### Pseudocode
```python
# Global parameters
MAX_LAYERS = 4
OPACITY_THRESHOLD = 0.95
Z_MAX = 1.0  # Far culling plane value

# State
accumulated_opacity = 0.0
z_buffer = initialize_z_buffer()
color_buffer = initialize_color_buffer()

for layer_index in range(MAX_LAYERS):
    # Step 1: Layer Depth Finding
    # Set previous layer depth as read-only z-buffer
    set_z_buffer_read_only(z_buffer)
    
    # Render geometry for current layer
    # Fragment shader for depth finding:
    #   if (intersect_encoded_surface()):
    #       output_depth = min(current_depth, layer_depth)
    #   else:
    #       discard_fragment()
    layer_depth_texture = render_layer_depth_pass()
    
    # Step 2: Depth Conversion #1
    # Full-screen pass to update z-buffer
    for each pixel in screen:
        found_depth = layer_depth_texture[pixel]
        previous_scene_depth = z_buffer[pixel]
        
        if found_depth > previous_scene_depth:
            # Layer is behind previous scene, cull it
            z_buffer[pixel] = Z_MAX
        else:
            # Layer is visible, update z-buffer with found depth
            z_buffer[pixel] = found_depth
            
    # Step 3: Layer Shading
    # Set z-function to 'equal' for precise visibility check
    set_z_function(EQUAL)
    
    # Render geometry for current layer with shading
    # Fragment shader for shading:
    #   color = compute_lighting(geometry, normal, view_dir)
    #   alpha = compute_opacity(geometry)
    #   blend color and alpha into color_buffer using hardware alpha blending
    render_layer_shading_pass()
    
    # Update accumulated opacity
    # Note: The exact method to update accumulated opacity from the color buffer
    # is not specified in the source, but it is required for Step 4.
    # [G] Assuming standard alpha blending, accumulated opacity can be tracked
    # or re-read from a separate accumulation buffer.
    accumulated_opacity = update_accumulated_opacity(color_buffer)
    
    # Step 4: Depth Conversion #2
    # Full-screen pass to check opacity threshold
    for each pixel in screen:
        if accumulated_opacity[pixel] > OPACITY_THRESHOLD:
            # Subsequent layers are invisible, cull them
            z_buffer[pixel] = Z_MAX
        # Else, z_buffer remains as updated in Step 2
```

### Edge Cases and Pitfalls
*   **Wave Divergence:** Standard depth peeling performs lighting conditionally in the same draw call as depth finding, causing high wave divergence due to shader discard operations [S1]. This method avoids this by separating depth finding (Step 1) from shading (Step 3) [S1].
*   **Surface Intersection Check:** In Step 1, it is necessary to search for intersection with the encoded surface to determine whether the fragment should be discarded or not [S1]. Without this, transparent parts would occupy each layer, requiring more passes for a correct image [S1].
*   **Performance Scaling:** The method is faster on smaller resolutions due to better cache utilization [S1]. With increasing texture size, performance of basic methods reduces significantly due to lower cache hit rates, but this method maintains speed and outperforms basic methods on larger sizes [S1].
*   **Visual Artifacts:** Some color altering can be noticed on parts where the surface is nearly perpendicular to the view projection plane, as many prisms meet in the view direction and the OIT approach doesn't handle all layers [S1]. This is mitigated by using a sufficient number of layers (e.g., 4) [S1].

## Operating characteristics
*   **Time Complexity:** The method requires a fixed number of passes per frame, equal to the number of transparent layers rendered (up to `max_layers`) [S1]. Each pass consists of 4 steps, including two full-screen passes for depth conversion [S1]. The cost of the full-screen passes is constant, while the geometry rendering cost decreases with each pass as more pixels are culled [S1]. Empirical results show that 3-4 passes are enough in many cases, and after the second pass, there are almost no changes in the resulting image [S1].
*   **Memory Complexity:** Requires storage for the z-buffer, color buffer, and a temporary texture for layer depth [S1].
*   **Measured Performance:** Tests were conducted on an NVIDIA GeForce RTX 2080 GPU at resolutions of 800x800 and 2560x1600 [S1]. The method outperforms basic shell mapping without texture LODs on larger resolutions [S1].
*   **Strengths:** Reduces fragment shader invocations and wave divergence by using hardware z-buffer for culling [S1]. Avoids re-rendering all geometry every pass for parts already rendered [S1].
*   **Limitations:** Requires a user-defined maximum number of layers, which may lead to visual artifacts if too few layers are used [S1]. The full-screen depth conversion passes add a constant cost [S1].
*   **When to use:** Suitable for real-time rendering of small-scale volumetric structures on animated surfaces where order-independent transparency is required and performance is critical [S1].
*   **When not to use:** Not appropriate for scenes requiring accurate transmittance approximation or linked list construction, as the first K semi-transparent layers need to be found for a stable and good quality result [S1].

## Background
The method was introduced in the paper "Real-time Rendering of Small-scale Volumetric Structure on Animated Surfaces" [S1]. It addresses the limitations of standard depth peeling, which suffers from expensive shader-based culling and high wave divergence [S1]. The technique is part of the broader field of Order-Independent Transparency (OIT) for point-based models and shell mapping [S1].
