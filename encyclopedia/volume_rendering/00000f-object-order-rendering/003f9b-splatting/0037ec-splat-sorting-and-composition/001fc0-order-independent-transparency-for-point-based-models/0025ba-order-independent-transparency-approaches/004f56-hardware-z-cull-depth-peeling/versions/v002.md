# Hardware-Z Cull Depth Peeling

Also called: Modified depth peeling with z-buffer culling, OIT approach with hardware depth test

## Overview
Hardware-Z Cull Depth Peeling is an Order-Independent Transparency (OIT) technique designed to render semi-transparent layers on animated volumetric surfaces by modifying standard depth peeling to utilize the hardware z-buffer for culling [S1]. It solves the problem of expensive fragment shader invocations and high wave divergence inherent in standard depth peeling, where culling and lighting are performed conditionally within the same draw call [S1]. Unlike its siblings, which may rely on linked lists, transmittance approximation, or stochastic methods, this approach explicitly isolates the first $K$ semi-transparent layers to ensure stable visual quality, using hardware depth tests to avoid unnecessary GPU work [S1].

## How it works
The method renders transparent layers sequentially until the last layer is reached or a user-defined maximum number of layers is exceeded [S1]. Each rendering pass consists of four distinct steps, utilizing the hardware z-buffer to cull fragments that are behind previously rendered layers or fully occluded by accumulated opacity [S1].

### Inputs and Outputs
*   **Inputs:**
    *   Encoded surface texture defining the volumetric shell [S1].
    *   Previous layer's depth buffer (read-only) [S1].
    *   Accumulated color and opacity from previous passes [S1].
    *   Parameters: Maximum layers ($N_{max}$), Opacity threshold ($T_{op}$) [S1].
*   **Outputs:**
    *   Updated frame buffer with blended layer color [S1].
    *   Updated hardware z-buffer [S1].

### Data Structures
*   **Z-Buffer:** Hardware depth buffer storing depth values.
*   **Color Buffer:** Accumulates the final blended color.
*   **Opacity Accumulator:** Implicitly tracked via alpha blending or explicitly if required by the specific implementation of the "accumulated opaqueness" check [S1]. The source describes checking accumulated opaqueness in Step 4, implying an access to the current accumulated alpha value [S1].

### Parameters
*   **Maximum Layers ($N_{max}$):** User-defined limit on passes. Typical value: 4 [S1].
*   **Opacity Threshold ($T_{op}$):** Threshold for accumulated opacity. If exceeded, subsequent layers are culled. Typical value: 0.95 [S1].
*   **Far Culling Plane ($z_{max}$):** A depth value representing the far plane, used to mark culled fragments [S1].

### Steps
Each pass $i$ (from 1 to $N_{max}$) executes the following sequence:

1.  **Layer Depth Finding:**
    *   Set the z-buffer to read-only mode, initialized with the depth of the previous layer (or 0 for the first pass) [S1].
    *   Render the geometry (or shell) with a fragment shader that computes the intersection depth with the encoded surface [S1].
    *   **Crucial Check:** The shader must verify if the fragment intersects the encoded surface. If no intersection exists, the fragment is discarded [S1]. Without this check, transparent parts would incorrectly occupy layers, requiring more passes [S1].
    *   Write the nearest intersection depth to the output color buffer using a 'min' blending function [S1]. This effectively finds the depth of the current layer at each pixel [S1].

2.  **Depth Conversion #1:**
    *   Perform a full-screen pass (or a pass covering the relevant geometry) to update the hardware z-buffer [S1].
    *   Read the depth found in Step 1.
    *   Compare the new layer's depth ($d_{new}$) with the previous scene's depth ($d_{prev}$) stored in the z-buffer [S1].
    *   If $d_{new} > d_{prev}$, the fragment is behind the previous layer. Cull it by writing $z_{max}$ to the z-buffer [S1].
    *   Otherwise, write $d_{new}$ to the z-buffer [S1]. This step converts the color-buffer depth into the hardware z-buffer format [S1].

3.  **Layer Shading:**
    *   Render the geometry again for the current layer [S1].
    *   Set the z-function to 'equal' [S1]. This ensures lighting computations are performed *only* for pixels where the current layer's depth matches the depth established in Step 2, eliminating overdraw [S1].
    *   Perform standard lighting calculations for the fragment [S1].
    *   Use hardware alpha-blending to blend the newly shaded color and opacity with the previously rendered layers in the color buffer [S1].

4.  **Depth Conversion #2:**
    *   Perform another full-screen pass similar to Step 2 [S1].
    *   Check the accumulated opaqueness (alpha) of the current pixel in the color buffer [S1].
    *   If accumulated opacity $> T_{op}$ (e.g., 0.95), write $z_{max}$ to the z-buffer [S1]. This culls all subsequent layers for this pixel as they are treated as invisible [S1].
    *   Otherwise, ensure the z-buffer reflects the current layer's depth to allow subsequent passes to proceed correctly [S1].

### Pseudocode

```python
# Constants
Z_MAX = 1.0  # Far culling plane value
OPACITY_THRESHOLD = 0.95
MAX_LAYERS = 4

# State
current_z_buffer = initialize_z_buffer() # Depth of previous layer, or 0 for first pass
accumulated_color = vec4(0.0)
accumulated_alpha = 0.0

for layer_index in range(1, MAX_LAYERS + 1):
    
    # Step 1: Layer Depth Finding
    # Render geometry to find intersection depth. 
    # Output is written to a temporary color buffer (layer_depth_color) using MIN blend.
    # Shader logic:
    #   if intersects_encoded_surface():
    #       write intersection_depth to layer_depth_color
    #   else:
    #       discard
    
    layer_depth_color = render_geometry_with_min_blend(current_z_buffer, mode='read_only')
    
    # Step 2: Depth Conversion #1
    # Update hardware z-buffer based on layer_depth_color
    # Full-screen pass or geometry pass to update Z-buffer
    for each pixel p:
        d_new = layer_depth_color[p].r # Depth found in Step 1
        d_prev = current_z_buffer[p]   # Depth from previous scene/layer
        
        if d_new > d_prev:
            # Fragment is behind previous layer, cull it
            current_z_buffer[p] = Z_MAX
        else:
            # Fragment is the new nearest layer, update z-buffer
            current_z_buffer[p] = d_new
            
    # Step 3: Layer Shading
    # Render geometry again with Z-test = EQUAL
    # This ensures shading only happens for visible pixels of the current layer
    shaded_color, shaded_alpha = render_geometry_with_shading(z_test='equal')
    
    # Blend with accumulated result
    # Standard Source Over blending
    new_alpha = shaded_alpha + accumulated_alpha * (1.0 - shaded_alpha)
    if new_alpha > 0.0:
        blended_color = (shaded_color * shaded_alpha + accumulated_color * accumulated_alpha * (1.0 - shaded_alpha)) / new_alpha
    else:
        blended_color = vec4(0.0)
        
    accumulated_color = blended_color
    accumulated_alpha = new_alpha
    
    # Step 4: Depth Conversion #2
    # Check accumulated opacity and update Z-buffer for future culling
    for each pixel p:
        if accumulated_alpha[p] > OPACITY_THRESHOLD:
            # Accumulated opacity is high enough, treat subsequent layers as invisible
            current_z_buffer[p] = Z_MAX
        else:
            # Keep the depth from Step 2 (already written) or re-verify
            # Note: Step 2 already wrote d_new. If we didn't cull in Step 2, 
            # we keep d_new unless opacity threshold triggers culling.
            pass # Z-buffer already holds d_new from Step 2
            
    # Prepare for next iteration
    # current_z_buffer is now updated for the next pass's Step 1
```

### Edge Cases and Pitfalls
*   **Wave Divergence:** Standard depth peeling suffers from high wave divergence because lighting and depth finding are combined, leading to shader discards. This method separates them, minimizing divergence [S1].
*   **Surface Intersection Check:** In Step 1, it is mandatory to check for intersection with the encoded surface. Failure to do so results in transparent parts occupying every layer, significantly increasing the number of required passes [S1].
*   **Performance Scaling:** Empirical results indicate that 3-4 passes are sufficient in many cases. After the second pass, there are almost no changes in the resulting image, and rendering time reduces with each subsequent pass [S1].
*   **Hardware Restrictions:** The method cannot simply copy a texture into the hardware z-buffer; it requires a shader pass to convert the depth, due to hardware restrictions [S1].

## Operating characteristics
*   **Time Complexity:** The method performs $N$ passes, where $N$ is the number of layers (typically 3-4) [S1]. Each pass involves rendering geometry and full-screen depth conversion passes. The cost per pass decreases as more layers are culled [S1].
*   **Memory Complexity:** Requires storage for the z-buffer, color buffer, and potentially temporary buffers for depth conversion [S1].
*   **Measured Performance:** Tested on an NVIDIA GeForce RTX 2080 GPU at resolutions 800x800 and 2560x1600 [S1]. The method outperforms basic shell mapping on larger texture sizes due to better cache utilization and reduced overdraw [S1].
*   **Strengths:** Utilizes hardware depth test for culling, avoiding expensive shader-based discard operations. Reduces wave divergence by separating depth finding from shading.
*   **Limitations:** Requires a user-defined maximum number of layers. May exhibit color altering on parts where the surface is nearly perpendicular to the view projection plane due to not handling all layers [S1].
*   **When to Use:** Suitable for real-time rendering of small-scale volumetric structures on animated surfaces where the first $K$ semi-transparent layers are critical for visual quality [S1].
*   **When Not to Use:** Not appropriate for cases requiring linked list construction, transmittance approximation, or stochastic transparency, as these do not guarantee the stable quality of the first $K$ layers [S1].

## Background
The method was introduced in the paper "Real-time Rendering of Small-scale Volumetric Structure on Animated Surfaces" [S1]. It addresses the limitations of standard depth peeling, which performs culling within shaders using discard operations dependent on texture reads, making each pass expensive and requiring re-rendering of all geometry [S1]. The technique is a modification of depth peeling, leveraging hardware z-buffer capabilities to optimize performance for animated volumetric shells [S1].
