# Hardware-Z Cull Depth Peeling

Also called: Modified depth peeling with z-buffer culling, OIT approach with hardware depth test

## Overview
Hardware-Z Cull Depth Peeling is an order-independent transparency (OIT) technique designed for rendering semi-transparent layers on animated surfaces, such as volumetric textures encoded in shell geometry [S1]. It solves the problem of expensive fragment shader discard operations and high wave divergence inherent in standard depth peeling by utilizing the hardware z-buffer for culling [S1]. Unlike standard depth peeling, which re-renders all geometry and performs conditional shading within the same draw call, this method separates depth finding from shading and uses hardware depth tests to skip invisible pixels, significantly reducing GPU work [S1]. It is specifically chosen when the first $K$ semi-transparent layers must be found for stable quality, making linked-list or stochastic OIT methods inappropriate [S1].

## How it works
The method renders transparent layers sequentially, one per pass, up to a user-defined maximum number of layers. Each pass consists of four distinct steps. The algorithm assumes a pre-existing depth buffer representing the opaque background or previously rendered opaque geometry.

### Inputs and Outputs
*   **Inputs:**
    *   Current accumulated color buffer (initially empty or containing opaque background).
    *   Current accumulated opacity buffer (initially 0).
    *   Current hardware z-buffer (initially containing the depth of the opaque background).
    *   Geometry of the current transparent layer (e.g., prisms or tetrahedrons from a volumetric shell).
    *   Surface intersection data (encoded in a texture or computed on-the-fly) to determine if a fragment belongs to the current layer.
*   **Outputs:**
    *   Updated color buffer with the new layer composited.
    *   Updated opacity buffer.
    *   Updated hardware z-buffer reflecting the depth of the newly rendered layer and culling planes.

### Data Structures
*   **Color Buffer:** Standard RGBA framebuffer.
*   **Opacity Buffer:** Standard single-channel (R8 or similar) framebuffer to track accumulated opacity.
*   **Z-Buffer:** Hardware depth buffer.
*   **Layer Geometry:** Defined by the shell mapping or volumetric representation. The specific geometry construction (e.g., shell mapping) is handled by the parent method [Parent](3611-order-independent-transparency-approaches.md).

### Parameters
*   **Maximum Layers ($N_{max}$):** User-defined limit on the number of transparency passes. Typical value: 4 [S1].
*   **Opacity Threshold ($T_{op}$):** Threshold for accumulated opacity. If accumulated opacity exceeds this, subsequent layers are culled. Typical value: 0.95 [S1].
*   **Far Culling Plane ($z_{max}$):** A depth value representing the far plane, used to mark culled fragments.

### Steps
Each pass $i$ (from 1 to $N_{max}$) performs the following:

1.  **Layer Depth Finding:**
    *   Set the hardware z-buffer to read-only mode, initialized with the depth of the previous layer (or background for the first pass).
    *   Render the current layer's geometry.
    *   In the fragment shader, check for intersection with the encoded surface. If no intersection, discard the fragment [S1].
    *   If an intersection exists, compute the depth $d_i$ of the fragment.
    *   Write $d_i$ to the color buffer using a 'min' blending function. This effectively finds the nearest depth of the current layer at each pixel [S1].

2.  **Depth Conversion #1:**
    *   Perform a full-screen pass (quad rendering) using the color buffer from Step 1 as input.
    *   For each pixel, read the found depth $d_i$.
    *   Compare $d_i$ with the current hardware z-buffer value $z_{prev}$ (which contains the depth of the previous layer/background).
    *   If $d_i > z_{prev}$, the current layer is behind the previous layer. Write $z_{max}$ to the z-buffer to cull this fragment and all subsequent layers behind it.
    *   If $d_i \le z_{prev}$, write $d_i$ to the z-buffer. This updates the hardware z-buffer with the new layer's depth [S1].

3.  **Layer Shading:**
    *   Render the current layer's geometry again.
    *   Set the z-function to 'equal'. This ensures that lighting computations are performed only for pixels where the depth matches the newly written z-buffer (i.e., visible pixels) [S1].
    *   Compute the color $C_i$ and opacity $\alpha_i$ of the fragment.
    *   Use hardware alpha-blending to composite the new fragment into the color buffer. The blending equation uses the standard 'over' operator, but since the z-buffer ensures only the closest visible fragment is shaded, the order is implicitly correct for this layer [S1].
    *   Update the opacity buffer by adding $\alpha_i$ to the accumulated opacity.

4.  **Depth Conversion #2:**
    *   Perform another full-screen pass.
    *   Read the accumulated opacity from the opacity buffer.
    *   If accumulated opacity $> T_{op}$, write $z_{max}$ to the z-buffer. This culls all subsequent layers for this pixel, as the surface is effectively opaque [S1].
    *   Otherwise, preserve the current z-buffer value.

### Edge Cases and Pitfalls
*   **Wave Divergence:** Standard depth peeling suffers from high wave divergence because lighting and depth finding are combined, leading to shader discards. This method avoids this by separating depth finding (Step 1) from shading (Step 3) [S1].
*   **Surface Intersection Check:** In Step 1, it is critical to check for intersection with the encoded surface. Without this, transparent parts would occupy each layer, requiring more passes for a correct image [S1].
*   **Performance Scaling:** Empirical results show that 3-4 passes are often sufficient. After the second pass, there are almost no changes in the resulting image [S1].
*   **Resolution Impact:** Performance is better at smaller resolutions due to cache utilization. At larger resolutions, cache hit rates decrease, but the method still outperforms basic shell mapping without LODs [S1].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot P)$, where $N$ is the number of passes (layers) and $P$ is the number of pixels. Each pass involves rendering the geometry once for depth finding, a full-screen pass for depth conversion, rendering the geometry again for shading, and another full-screen pass for opacity culling. Thus, 4 draw calls per layer.
*   **Memory Complexity:** $O(P)$ for the color buffer, opacity buffer, and z-buffer. The geometry storage is independent of the OIT method.
*   **Measured Performance:** Tested on an NVIDIA GeForce RTX 2080 GPU at resolutions 800x800 and 2560x1600. The method is faster than basic shell mapping at larger resolutions due to reduced overdraw [S1].
*   **Strengths:**
    *   Reduces fragment shader invocations by using hardware z-buffer culling.
    *   Minimizes wave divergence by separating depth finding and shading.
    *   Provides stable quality for the first $K$ layers.
*   **Limitations:**
    *   Requires multiple passes (4 per layer).
    *   May suffer from color altering if the number of layers is insufficient (e.g., darkening where many prisms meet) [S1].
    *   Not suitable for scenes requiring infinite transparency layers.
*   **When to Use:** When rendering semi-transparent layers on animated surfaces where the first few layers are critical for visual quality, and hardware performance is a concern.
*   **When Not to Use:** When infinite transparency layers are required, or when the scene is too simple to warrant the overhead of multiple passes.

## Background
The method was introduced in the paper "Real-time Rendering of Small-scale Volumetric Structure on Animated Surfaces" [S1]. It addresses the limitations of standard depth peeling, which was introduced in [15] and has advanced variants [19, 20]. The key innovation is the use of hardware z-buffer for culling instead of shader-based discard operations, which were identified as a major bottleneck in previous approaches [S1]. The method is particularly relevant for volumetric textures on animated surfaces, where sorting tetrahedrons is too expensive [S1].
