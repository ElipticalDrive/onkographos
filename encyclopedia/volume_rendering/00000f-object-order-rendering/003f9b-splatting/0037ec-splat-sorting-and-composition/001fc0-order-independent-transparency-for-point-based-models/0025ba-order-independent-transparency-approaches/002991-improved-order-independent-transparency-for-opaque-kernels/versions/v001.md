# Improved Order Independent Transparency for Opaque Kernels


## Overview
This method is an Order Independent Transparency (OIT) variant designed to improve the rendering of opaque kernels by incorporating the contribution of the closest sample into the transparency accumulation [S1, unofficial]. It reduces transparency artifacts compared to standard OIT while maintaining performance close to geometry instancing [S1, unofficial]. It sets itself apart from standard OIT by re-introducing depth information via the closest sample to handle opaque regions, and from geometry instancing by avoiding z-fighting aliasing and supporting semi-transparency [S1, unofficial].

## How it works
**Inputs and Outputs**
- **Input**: A set of kernel clusters $\mathcal{C}_i$ for $i \in [0, N-1]$, where each cluster contains sample points $\mathbf{p}_j$. For each ray, the closest kernel sample $\mathbf{p}_f$ and its transparency $\alpha_f$ are identified. The color contributions $L_{\mathcal{C}_i}$ and transparencies $T(\mathbf{p}_j)$ for all samples are computed.
- **Output**: The final color $L$ for the pixel.

**Data Structures**
- **Kernel Clusters**: A list of $N$ clusters. Each cluster $\mathcal{C}_i$ contains a list of sample points $\mathbf{p}_j$.
- **Sample Data**: Each sample point $\mathbf{p}_j$ has an associated transparency $T(\mathbf{p}_j)$ and contributes to a color sum $L_{\mathcal{C}_i}$ for its cluster.
- **Closest Sample**: The sample $\mathbf{p}_f$ with the minimum depth along the ray, with transparency $\alpha_f$.

**Steps**
1. Identify the closest kernel sample $\mathbf{p}_f$ and its transparency $\alpha_f$ using a depth test [S1, unofficial].
2. Calculate the direct contribution of the closest kernel: $\tilde{K}(\mathbf{d}, \mathbf{p}_f) \alpha_f$, where $\tilde{K}(\mathbf{d}, \mathbf{p}_f)$ is the kernel value at $\mathbf{p}_f$ with direction $\mathbf{d}$ [S1, unofficial].
3. Compute the weighted average color of all other kernels by summing the color contributions $L_{\mathcal{C}_i}$ for all clusters and dividing by the sum of transparencies $T(\mathbf{p}_j)$ for all samples in all clusters [S1, unofficial].
4. Multiply this average by the remaining opacity $(1 - \alpha_f)$ [S1, unofficial].
5. Sum the direct contribution from step 2 and the weighted average contribution from step 4 to get the final color $L$ [S1, unofficial].

**Formula**
$$L \approx \tilde{K}(\mathbf{d}, \mathbf{p}_f) \alpha_f + \left( \frac{\sum_{i=0}^{N-1} L_{\mathcal{C}_i}}{\sum_{i=0}^{N-1} \sum_{\mathbf{p}_j \in \mathcal{C}_i^*} T(\mathbf{p}_j)} \right) (1 - \alpha_f)$$

Where:
- $L$ is the final color.
- $\tilde{K}(\mathbf{d}, \mathbf{p}_f)$ is the kernel value at the closest sample point $\mathbf{p}_f$ with direction $\mathbf{d}$.
- $\alpha_f$ is the transparency of the closest kernel.
- $N$ is the number of kernel clusters or slices.
- $L_{\mathcal{C}_i}$ is the color contribution from cluster $i$.
- $T(\mathbf{p}_j)$ is the transparency at sample point $\mathbf{p}_j$ in cluster $\mathcal{C}_i^*$.

**Parameters**
- $N$: The number of kernel clusters or slices. In experiments, 32 samples per ray per evaluated kernel were used [S1, unofficial].

**Pseudocode**
```python
def compute_color(closest_sample, clusters):
    """
    Compute the final color using Improved OIT for Opaque Kernels.
    
    Args:
        closest_sample: Object with attributes 'kernel_value' (K), 'transparency' (alpha_f), 'direction' (d).
        clusters: List of cluster objects. Each cluster has 'color_sum' (L_C_i) and 'transparency_sum' (sum of T(p_j)).
        
    Returns:
        float: The final color L.
    """
    # Step 1: Get closest sample data (already provided as input)
    alpha_f = closest_sample.transparency
    K_f = closest_sample.kernel_value
    d = closest_sample.direction
    
    # Step 2: Direct contribution of the closest kernel
    # K(d, p_f) is assumed to be pre-computed and stored in closest_sample.kernel_value
    direct_contribution = K_f * alpha_f
    
    # Step 3: Compute weighted average color of all other kernels
    total_color_sum = 0.0
    total_transparency_sum = 0.0
    
    for cluster in clusters:
        total_color_sum += cluster.color_sum
        total_transparency_sum += cluster.transparency_sum
        
    # Avoid division by zero if no other kernels contribute
    if total_transparency_sum == 0:
        average_color = 0.0
    else:
        average_color = total_color_sum / total_transparency_sum
        
    # Step 4: Multiply average by remaining opacity
    remaining_opacity_contribution = average_color * (1 - alpha_f)
    
    # Step 5: Sum contributions
    final_color = direct_contribution + remaining_opacity_contribution
    
    return final_color
```

**Edge Cases and Pitfalls**
- **Division by Zero**: If the sum of transparencies for all other kernels is zero, the average color is undefined. The pseudocode handles this by setting the average color to 0.0 [G].
- **Opaque Kernels**: The method shows significant improvements for opaque kernels compared to standard OIT [S1, unofficial].
- **Highly Transparent Kernels**: Results are almost identical to standard OIT for highly transparent kernels [S1, unofficial].

## Subtopics

## Operating characteristics
- **Time Complexity**: Not given in the sources.
- **Memory Complexity**: Not given in the sources.
- **Measured Performance**: On a GeForce 980, with 1920×1080 resolution, the method runs at roughly half the framerate of geometry instancing or basic OIT [S1, unofficial]. Geometry instancing offers 60fps for 800k kernels and 3fps for 10M kernels [S1, unofficial]. The improved OIT method runs at approximately 2 fps for 400k impulses [S1, unofficial].
- **Strengths**: Avoids aliasing artifacts (z-fighting) and handles semi-transparency, which geometry instancing cannot [S1, unofficial]. Re-introduces depth information to avoid transparency artifacts in close-up views, which basic OIT suffers from [S1, unofficial].
- **Limitations**: Performance is roughly half that of geometry instancing [S1, unofficial].
- **When to Use**: When rendering opaque kernels where aliasing artifacts from geometry instancing are unacceptable, and semi-transparency is required, but full depth-sorted EWA splatting is too slow [S1, unofficial].
- **When Not to Use**: When maximum performance is required and aliasing artifacts are tolerable (use geometry instancing) or when kernels are highly transparent (standard OIT is sufficient) [S1, unofficial].

## Background
The method was introduced in the paper "Volumetric Spot Noise for Procedural 3D Shell Texture Synthesis" [S1, unofficial]. It was developed to address the limitations of standard OIT and geometry instancing in rendering procedural shell textures composed of opaque kernels. The authors demonstrated the method using an OpenGL 4.3 framework on a GeForce 980 GPU [S1, unofficial].
