# Improved Order Independent Transparency for Opaque Kernels


## Overview
This method improves the rendering of opaque kernels by incorporating the contribution of the closest sample into the transparency accumulation, reducing transparency artifacts compared to standard Order Independent Transparency (OIT) while maintaining performance close to geometry instancing [S1, unofficial]. It addresses the limitation of standard OIT, which fails to distinguish neighboring kernels in close-up views, by re-introducing depth information via the closest sample [S1, unofficial]. It builds on [Order Independent Transparency Approaches](3611-order-independent-transparency-approaches.md).

## How it works
The method combines a direct contribution from the closest kernel with a weighted average of all other kernels.

**Inputs and Outputs:**
- Input: A set of kernel clusters $\mathcal{C}_i$ for $i=0 \dots N-1$. Each cluster contains sample points $\mathbf{p}_j$.
- Input: The direction $\mathbf{d}$ for the kernel evaluation.
- Output: The final color $L$ for the pixel.

**Data Structures:**
- $\mathbf{p}_f$: The position of the closest kernel sample, determined via a depth test.
- $\alpha_f$: The transparency (opacity) of the closest kernel sample $\mathbf{p}_f$.
- $L_{\mathcal{C}_i}$: The color contribution from cluster $i$.
- $T(\mathbf{p}_j)$: The transparency at sample point $\mathbf{p}_j$ in cluster $\mathcal{C}_i^*$.
- $\tilde{K}(\mathbf{d}, \mathbf{p}_f)$: The kernel value at the closest sample point $\mathbf{p}_f$ with direction $\mathbf{d}$.

**Steps:**
1. Identify the closest kernel sample $\mathbf{p}_f$ and its transparency $\alpha_f$ using a depth test [S1, unofficial].
2. Calculate the direct contribution of the closest kernel: $\tilde{K}(\mathbf{d}, \mathbf{p}_f) \alpha_f$ [S1, unofficial].
3. Compute the weighted average color of all other kernels by summing their color contributions $\sum_{i=0}^{N-1} L_{\mathcal{C}_i}$ and dividing by the sum of their transparencies $\sum_{i=0}^{N-1} \sum_{\mathbf{p}_j \in \mathcal{C}_i^*} T(\mathbf{p}_j)$ [S1, unofficial].
4. Multiply this average by the remaining opacity $(1 - \alpha_f)$ [S1, unofficial].
5. Sum the direct contribution and the weighted average contribution to get the final color $L$ [S1, unofficial].

**Formula:**
$$ L \approx \tilde{K}(\mathbf{d}, \mathbf{p}_f) \alpha_f + \left( \frac{\sum_{i=0}^{N-1} L_{\mathcal{C}_i}}{\sum_{i=0}^{N-1} \sum_{\mathbf{p}_j \in \mathcal{C}_i^*} T(\mathbf{p}_j)} \right) (1 - \alpha_f) \quad (1) $$

Where:
- $L$ is the final color.
- $\tilde{K}(\mathbf{d}, \mathbf{p}_f)$ is the kernel value at the closest sample point $\mathbf{p}_f$ with direction $\mathbf{d}$.
- $\alpha_f$ is the transparency of the closest kernel.
- $N$ is the number of kernel clusters/slices.
- $L_{\mathcal{C}_i}$ is the color contribution from cluster $i$.
- $T(\mathbf{p}_j)$ is the transparency at sample point $\mathbf{p}_j$ in cluster $\mathcal{C}_i^*$.

**Parameters:**
- $N$: The number of kernel clusters or slices used in the summation. In experiments, 32 samples per ray per evaluated kernel are used [S1, unofficial].

**Pseudocode:**
```python
def compute_color(closest_kernel_value, closest_transparency, cluster_colors, cluster_transparencies):
    """
    Computes the final color using Improved OIT for Opaque Kernels.
    
    Args:
        closest_kernel_value (float): K(d, p_f), the kernel value at the closest sample.
        closest_transparency (float): alpha_f, the transparency of the closest kernel.
        cluster_colors (list of float): List of color contributions L_C_i for each cluster.
        cluster_transparencies (list of float): List of total transparencies sum(T(p_j)) for each cluster.
        
    Returns:
        float: The final color L.
    """
    # Step 1: Direct contribution of the closest kernel
    direct_contribution = closest_kernel_value * closest_transparency
    
    # Step 2: Sum of color contributions from all other kernels
    sum_colors = sum(cluster_colors)
    
    # Step 3: Sum of transparencies from all other kernels
    sum_transparencies = sum(cluster_transparencies)
    
    # Step 4: Weighted average color of other kernels
    # Avoid division by zero if no other kernels contribute
    if sum_transparencies == 0:
        weighted_average_color = 0.0
    else:
        weighted_average_color = sum_colors / sum_transparencies
        
    # Step 5: Multiply by remaining opacity
    remaining_opacity_contribution = weighted_average_color * (1.0 - closest_transparency)
    
    # Step 6: Sum contributions
    final_color = direct_contribution + remaining_opacity_contribution
    
    return final_color
```

**Edge Cases and Pitfalls:**
- If the sum of transparencies of other kernels is zero, the weighted average is undefined. The pseudocode handles this by setting the average to 0.0 [G].
- Standard OIT is not precise enough to distinguish pairs of neighboring kernels, leading to artifacts. This method mitigates that by using the closest sample [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Not explicitly given, but performance is close to geometry instancing [S1, unofficial].
- **Memory Complexity:** Not given in the sources.
- **Measured Performance:** On a GeForce 980 with a 1920×1080 rendering window, interactive examples using flat Gaussian kernels run between 5 and 60+ fps, depending on kernel density and viewpoint [S1, unofficial]. For a lichen pattern with ≈400k impulses, it runs at ≈1.5 frames per second [S1, unofficial].
- **Scaling:** Performance is strongly related to the density and complexity of the kernels [S1, unofficial].
- **Strengths:** Avoids aliasing artifacts (z-fighting) and handles semi-transparency, unlike geometry instancing [S1, unofficial]. Avoids transparency artifacts in close-up views compared to basic OIT [S1, unofficial].
- **Limitations:** Runs at roughly half the framerate of geometry instancing (e.g., 3 fps for 10M kernels vs 60 fps for 800k kernels for instancing) [S1, unofficial].
- **When to use:** When rendering opaque kernels where standard OIT shows transparency artifacts in close-up views, and geometry instancing causes z-fighting or cannot handle semi-transparency [S1, unofficial].
- **When not to use:** When maximum performance is required and semi-transparency is not needed, geometry instancing is faster [S1, unofficial].

## Background
This method was introduced in the context of Volumetric Spot Noise for Procedural 3D Shell Texture Synthesis [S1, unofficial]. It was developed to address the limitations of traditional EWA Splatting (which requires depth-sorting and has severe performance/storage overhead) and basic OIT (which lacks precision for neighboring kernels) [S1, unofficial]. The work was published in the Journal of Computer Graphics Techniques (JCGT) in December 2013 [S1, unofficial].
