# Plug-and-Play Ray Marching and Rendering

Also called: Differentiable Volumetric Rendering Pipeline, nerfacc pipeline

## Overview
Plug-and-Play Ray Marching and Rendering is a modular pipeline interface that decouples the acceleration logic of ray marching and volumetric compositing from the specific radiance field representation [S1, unofficial]. It allows efficient, differentiable volumetric rendering to be integrated into any user-defined neural radiance field by implementing two query functions [S1, unofficial]. Unlike specialized implementations such as Instant-NGP which rely on custom CUDA kernels, this method provides a Python API built on PyTorch, prioritizing ease of extension for dynamic and unbounded scenes over raw kernel-level optimization [S1, unofficial].

## How it works
The method operates by abstracting the ray marching and rendering loop into two user-defined functions that interface with a core acceleration engine. The engine handles sample selection, empty space pruning, and differentiable accumulation.

### Inputs and Outputs
*   **Inputs**: Ray origins $\mathbf{r}_o$ (tensor of shape $[N_{rays}, 3]$), ray directions $\mathbf{r}_d$ (tensor of shape $[N_{rays}, 3]$), and a user-defined radiance field model.
*   **Outputs**: Rendered color $\mathbf{C}(\mathbf{r})$ (shape $[N_{rays}, 3]$), opacity $\alpha$ (shape $[N_{rays}, 1]$), and depth $D$ (shape $[N_{rays}, 1]$).

### Data Structures
The pipeline relies on PyTorch tensors. The core intermediate data structures generated by the ray marching step are:
1.  `packed_info`: A tensor containing metadata about the valid samples (e.g., ray indices, sample indices) required for efficient indexing during rendering.
2.  `t_starts`: A tensor of shape $[N_{samples}, 1]$ containing the start distance of each sample interval along the ray.
3.  `t_ends`: A tensor of shape $[N_{samples}, 1]$ containing the end distance of each sample interval along the ray.

### Parameters
*   `near_plane`: The starting distance for ray marching. Typical value: $0.2$ [S1, unofficial].
*   `far_plane`: The ending distance for ray marching. Typical value: $1.0$ [S1, unofficial].
*   `early_stop_eps`: Threshold for early stopping based on transmittance. Typical value: $10^{-4}$ [S1, unofficial].
*   `alpha_thre`: Threshold for skipping samples with low opacity. Typical value: $10^{-2}$ [S1, unofficial].

### Formulas
The volumetric rendering equation used for accumulation is:
$$
\mathbf{C}(\mathbf{r}) = \sum_{i=1}^N T_i \alpha_i \mathbf{c}_i
$$
where:
*   $\mathbf{c}_i$ is the color of the $i$-th sample.
*   $\alpha_i = 1 - \exp(-\sigma_i \delta_i)$ is the opacity of the $i$-th sample.
*   $\sigma_i$ is the volume density (sigma) of the $i$-th sample.
*   $\delta_i = t_{ends,i} - t_{starts,i}$ is the distance between sample boundaries.
*   $T_i = \exp\left(-\sum_{j=1}^{i-1} \sigma_j \delta_j\right)$ is the accumulated transmittance up to the $i$-th sample [S1, unofficial].

def sigma_fn(t_starts: Tensor, t_ends: Tensor, ray_indices: Tensor) -> Tensor:

    # Query density from the radiance field
    sigmas = radiance_field.query_density(positions)
    return sigmas # Shape (n_samples, 1)

# 4. Define the RGB and density query function
def rgb_sigma_fn(t_starts: Tensor, t_ends: Tensor, ray_indices: Tensor) -> Tuple[Tensor, Tensor]:
    """
    Query RGB colors and density values from the radiance field.
    :param t_starts: Start of sample intervals, shape (n_samples, 1)
    :param t_ends: End of sample intervals, shape (n_samples, 1)
    :param ray_indices: Indices of rays for each samples, shape (n_samples,)
    :return: RGB colors (n_samples, 3) and densities (n_samples, 1)
    """
    t_origins = rays_o[ray_indices]
    t_dirs = rays_d[ray_indices]
    
    # Compute sample positions
    positions = t_origins + t_dirs * (t_starts + t_ends) / 2.0
    
    # Query RGB and density from the radiance field
    # The radiance field typically takes position and view direction
    rgbs, sigmas = radiance_field(positions, condition=t_dirs)
    return rgbs, sigmas

packed_info, t_starts, t_ends = nerfacc.ray_marching(

    rays_d=rays_d,
    sigma_fn=sigma_fn,
    near_plane=0.2,
    far_plane=1.0,

# 6. Differentiable Volumetric Rendering

### Edge Cases and Pitfalls
*   **Empty/Occluded Regions**: The pipeline includes logic to skip samples in empty or occluded regions based on `early_stop_eps` and `alpha_thre`. If these thresholds are set too aggressively, valid details in low-density regions may be lost; if too lenient, performance gains from pruning are reduced [S1, unofficial].
*   **Gradient Flow**: The entire pipeline is differentiable. Users must ensure their `radiance_field` implementation supports gradient computation through `query_density` and the RGB query to enable backpropagation [S1, unofficial].
*   **Tensor Shapes**: The `sigma_fn` and `rgb_sigma_fn` must return tensors with the exact shapes specified (e.g., `sigmas` as `(n_samples, 1)`). Mismatched shapes will cause runtime errors in the accumulation step [S1, unofficial].

## Subtopics

### Dynamic Scene Support
*   **What it is**: The ability to render scenes where the radiance field changes over time (e.g., animated characters, moving objects).
*   **Differentiation**: Unlike static NeRF implementations that cache grid structures for fixed scenes, this pipeline supports time-dependent radiance fields by allowing the query functions to accept time as an additional condition.
*   **When to choose**: Use when rendering animated 3D content or video sequences where the geometry or appearance evolves.
*   **Link**: [Dynamic Neural Radiance Fields](dynamic-nerf.md)

### Unbounded Scene Rendering
*   **What it is**: Rendering scenes that extend to infinity, without a predefined bounding box.
*   **Differentiation**: Standard splatting methods often require a fixed bounding volume. This pipeline handles unbounded scenes by using ray marching with configurable `near_plane` and `far_plane` and pruning logic that adapts to the scene's depth distribution.
*   **When to choose**: Use for outdoor scenes, large-scale environments, or any scenario where the camera can move freely without hitting a hard boundary.
*   **Link**: [Unbounded NeRF Rendering](unbounded-nerf.md)

## Operating characteristics
*   **Time Complexity**: The complexity is dominated by the number of valid samples after pruning. The ray marching step is $O(N_{samples})$ where $N_{samples}$ is the number of samples per ray, but effective complexity is reduced by skipping empty space. The rendering step is also linear in the number of valid samples [S1, unofficial].
*   **Memory Complexity**: Memory usage is proportional to the number of valid samples and the size of the radiance field model. The `packed_info` structure adds minimal overhead [S1, unofficial].
*   **Measured Performance**: On a single NVIDIA TITAN RTX GPU, training a vanilla 8-layer MLP NeRF takes approximately 1 hour, compared to 1-2 days in the original paper. Instant-NGP models can be trained to equal quality in 4.5 minutes using the Python API, compared to the official CUDA implementation [S1, unofficial].
*   **Strengths**: High ease of use due to Python/PyTorch API; flexible integration with various radiance field architectures; supports dynamic and unbounded scenes out of the box.
*   **Limitations**: May be slower than highly optimized, scene-specific CUDA kernels (like Instant-NGP's native implementation) due to Python overhead and general tensor operations. Not given in the sources.
*   **When to use**: When rapid prototyping, extending existing NeRF methods, or supporting dynamic/unbounded scenes is prioritized over maximum raw rendering speed.
*   **When not**: When deploying to resource-constrained hardware requiring minimal latency and maximum throughput, where custom CUDA kernels are preferred.

## Background
The Plug-and-Play Ray Marching and Rendering pipeline was introduced in the NerfAcc toolbox, a general acceleration library for Neural Radiance Fields (NeRFs) [S1, unofficial]. It builds upon techniques from Instant-NGP but extends them to support dynamic and unbounded scenes [S1, unofficial]. The library was released as a preprint in 2022, aiming to provide a user-friendly Python API that accelerates most NeRF methods without requiring low-level CUDA programming [S1, unofficial].
