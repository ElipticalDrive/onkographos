# Plug-and-Play Ray Marching and Rendering

Also called: Differentiable Volumetric Rendering Pipeline, nerfacc pipeline

## Overview
Plug-and-Play Ray Marching and Rendering is a modular pipeline interface that decouples the efficient ray marching and differentiable volumetric rendering logic from the specific radiance field representation [S1, unofficial]. It allows users to plug any user-defined radiance field (e.g., MLPs, hash grids) into a standardized acceleration engine by implementing two query functions [S1, unofficial]. Unlike Instant-NGP, which relies on specialized, monolithic CUDA implementations, this method provides a Python API built on PyTorch, facilitating easier extension to dynamic scenes, unbounded environments, and custom radiance field architectures [S1, unofficial].

## How it works
The method operates by separating the sampling strategy and accumulation logic from the scene representation. The user defines how the radiance field is queried, while the library handles the optimization of sample placement (skipping empty/occluded regions) and the differentiable accumulation of color and opacity.

### Inputs and Outputs
*   **Inputs:**
    *   `rays_o`: Tensor of ray origins, shape $(N_{rays}, 3)$.
    *   `rays_d`: Tensor of normalized ray directions, shape $(N_{rays}, 3)$.
    *   `radiance_field`: A user-defined neural network or data structure capable of querying density and color.
    *   `near_plane`: Float, starting distance for ray marching (Typical: 0.2) [S1, unofficial].
    *   `far_plane`: Float, ending distance for ray marching (Typical: 1.0) [S1, unofficial].
*   **Outputs:**
    *   `color`: Tensor of rendered RGB colors, shape $(N_{rays}, 3)$.
    *   `opacity`: Tensor of accumulated opacity, shape $(N_{rays}, 1)$.
    *   `depth`: Tensor of accumulated depth, shape $(N_{rays}, 1)$.
    *   `packed_info`: Internal metadata describing the valid samples for the rendering step.
    *   `t_starts`, `t_ends`: Tensors defining the start and end distances of valid sample intervals along each ray.

### Data Structures
The core data structures are PyTorch tensors. The `nerfacc` library manages memory packing to optimize GPU utilization by skipping empty space.
*   `t_starts`, `t_ends`: 1D tensors of shape $(N_{samples},)$, where $N_{samples}$ is the total number of valid samples across all rays.
*   `ray_indices`: 1D tensor of shape $(N_{samples},)$, mapping each sample to its corresponding ray index in `rays_o` and `rays_d`.
*   `packed_info`: A structure (often a tuple or object) containing the mapping between rays and samples, used by the rendering function to correctly scatter results back to per-ray outputs.

### Steps
1.  **Define Density Query Function (`sigma_fn`):**
    Implement a function that takes `t_starts`, `t_ends`, and `ray_indices` and returns the density ($\sigma$) values.
    *   Compute sample positions: $\mathbf{p}_i = \mathbf{o}_{r_i} + \mathbf{d}_{r_i} \cdot \frac{t_{start, i} + t_{end, i}}{2}$.
    *   Query the radiance field for density at $\mathbf{p}_i$.
    *   Return $\sigma$ values.

2.  **Define RGB and Density Query Function (`rgb_sigma_fn`):**
    Implement a function that takes `t_starts`, `t_ends`, and `ray_indices` and returns both RGB color ($\mathbf{c}$) and density ($\sigma$).
    *   Compute sample positions similarly to Step 1.
    *   Query the radiance field for color and density.
    *   Return $\mathbf{c}$ and $\sigma$ values.

3.  **Efficient Ray Marching:**
    Call the ray marching routine with the defined `sigma_fn`. This step identifies valid sample intervals along each ray, skipping regions where the density is negligible or transmittance is too low.
    *   Parameters: `near_plane`, `far_plane`, `early_stop_eps` (Typical: $10^{-4}$), `alpha_thre` (Typical: $10^{-2}$) [S1, unofficial].
    *   Returns: `packed_info`, `t_starts`, `t_ends`.

4.  **Differentiable Volumetric Rendering:**
    Call the rendering routine with `rgb_sigma_fn`, `packed_info`, `t_starts`, and `t_ends`. This accumulates the color, opacity, and depth using the volumetric rendering equation.

### Formulas
The volumetric rendering equation used for accumulation is [S1, unofficial]:

$$ C(\mathbf{r}) = \sum_{i=1}^N T_i \alpha_i \mathbf{c}_i $$

Where:
*   $N$ is the number of samples along the ray.
*   $\mathbf{c}_i$ is the color of the $i$-th sample.
*   $\alpha_i$ is the opacity of the $i$-th sample, defined as:
    $$ \alpha_i = 1 - \exp(-\sigma_i \delta_i) $$
*   $\sigma_i$ is the density of the $i$-th sample.
*   $\delta_i$ is the distance between the $i$-th and $(i-1)$-th sample (or start/end points).
*   $T_i$ is the transmittance up to the $i$-th sample, defined as:
    $$ T_i = \exp\left(-\sum_{j=1}^{i-1} \sigma_j \delta_j\right) $$

### Pseudocode
The following Python-like pseudocode implements the pipeline using the `nerfacc` library conventions described in the sources [S1, unofficial].

```python
import torch
from torch import Tensor
import nerfacc

# Assume these are defined externally:
# radiance_field: User-defined neural network or data structure
# rays_o: Tensor of shape (n_rays, 3)
# rays_d: Tensor of shape (n_rays, 3)
# optimizer: PyTorch optimizer

def sigma_fn(t_starts: Tensor, t_ends: Tensor, ray_indices: Tensor) -> Tensor:
    """
    Query density values from a user-defined radiance field.
    :param t_starts: Start of the sample interval along the ray.
    :param t_ends: End of the sample interval along the ray.
    :param ray_indices: Ray indices that each sample belongs to.
    :returns: The post-activation density values.
    """
    # Gather ray origins and directions for the specific samples
    t_origins = rays_o[ray_indices]  # (n_samples, 3)
    t_dirs = rays_d[ray_indices]     # (n_samples, 3)
    
    # Compute sample positions at the midpoint of the interval
    positions = t_origins + t_dirs * (t_starts + t_ends) / 2.0
    
    # Query density from the radiance field
    sigmas = radiance_field.query_density(positions)
    return sigmas  # (n_samples, 1)

def rgb_sigma_fn(t_starts: Tensor, t_ends: Tensor, ray_indices: Tensor):
    """
    Query rgb and density values from a user-defined radiance field.
    :param t_starts: Start of the sample interval along the ray.
    :param t_ends: End of the sample interval along the ray.
    :param ray_indices: Ray indices that each sample belongs to.
    :returns: The post-activation rgb and density values.
    """
    t_origins = rays_o[ray_indices]  # (n_samples, 3)
    t_dirs = rays_d[ray_indices]     # (n_samples, 3)
    
    # Compute sample positions at the midpoint of the interval
    positions = t_origins + t_dirs * (t_starts + t_ends) / 2.0
    
    # Query color and density from the radiance field
    rgbs, sigmas = radiance_field(positions, condition=t_dirs)
    return rgbs, sigmas  # (n_samples, 3), (n_samples, 1)

# 1. Efficient Raymarching: Skip empty and occluded space
packed_info, t_starts, t_ends = nerfacc.ray_marching(
    rays_o, 
    rays_d, 
    sigma_fn=sigma_fn, 
    near_plane=0.2, 
    far_plane=1.0, 
    early_stop_eps=1e-4, 
    alpha_thre=1e-2
)

# 2. Differentiable Volumetric Rendering
color, opacity, depth = nerfacc.rendering(
    rgb_sigma_fn, 
    packed_info, 
    t_starts, 
    t_ends
)

# 3. Optimization step (example)
# optimizer.zero_grad()
# loss = F.mse_loss(color, color_gt)
# loss.backward()
# optimizer.step()
```

### Edge Cases and Pitfalls
*   **Empty/Occluded Regions:** The ray marching step explicitly skips samples with low opacity $\alpha_i$ or low transmittance $T_i$ to optimize GPU utilization [S1, unofficial]. If `early_stop_eps` or `alpha_thre` are set too aggressively, valid but faint details may be lost.
*   **Position Calculation:** The sample positions are calculated at the midpoint of the interval $(t_{start} + t_{end}) / 2$. This assumes linear interpolation within the interval.
*   **Radiance Field Interface:** The user must ensure their `radiance_field` accepts the `positions` tensor and optionally a `condition` (e.g., view direction) as specified in the pseudocode [S1, unofficial].

## Operating characteristics
*   **Performance:** The method accelerates training significantly. For example, an 8-layer MLP NeRF can be trained to better quality (+0.5 PSNR) in 1 hour compared to 1-2 days in the original paper [S1, unofficial]. Instant-NGP models can be trained to equal quality in 4.5 minutes in Python, comparable to the official pure CUDA implementation [S1, unofficial].
*   **Hardware:** Experiments were conducted on a single NVIDIA TITAN RTX GPU [S1, unofficial].
*   **Scalability:** By skipping empty and occluded regions, the method reduces the number of samples processed, improving efficiency for scenes with large empty spaces [S1, unofficial].
*   **Strengths:** Python API with PyTorch makes it easy to extend to other applications and dynamic scenes [S1, unofficial]. It is a universal acceleration tool for various NeRFs [S1, unofficial].
*   **Limitations:** Relies on PyTorch overhead compared to pure CUDA implementations, though the performance gap is minimal for many use cases [S1, unofficial].

## Background
The method is part of the NerfAcc toolbox, which focuses on efficient volumetric rendering of radiance fields [S1, unofficial]. It builds on the techniques proposed in Instant-NGP [S1, unofficial] and extends them to support dynamic scenes and unbounded scenes [S1, unofficial]. The toolbox provides a user-friendly Python API written with PyTorch, ready for plug-and-play acceleration of most NeRFs [S1, unofficial].
