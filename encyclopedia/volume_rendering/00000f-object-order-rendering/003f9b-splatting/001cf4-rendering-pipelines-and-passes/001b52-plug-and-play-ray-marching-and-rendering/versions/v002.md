# Plug-and-Play Ray Marching and Rendering

Also called: Differentiable Volumetric Rendering Pipeline, nerfacc pipeline

## Overview
This method provides a modular interface for efficient ray marching and differentiable volumetric rendering, allowing users to plug any custom radiance field into a standardized acceleration pipeline [S1, unofficial]. It builds on [Rendering Pipelines and Passes](1411-rendering-pipelines-and-passes.md) and distinguishes itself from specialized implementations like Instant-NGP by offering a Python API built on PyTorch, which facilitates easier extension to dynamic and unbounded scenes while maintaining high performance [S1, unofficial].

## How it works
The pipeline separates the radiance field query logic from the rendering accumulation logic [S1, unofficial]. The user defines two functions that map sample intervals to field values, while the library handles the optimization of sample placement and the differentiable accumulation of color and opacity [S1, unofficial].

### Inputs and Outputs
*   **Inputs**:
    *   `rays_o`: Ray origins, shape `(n_rays, 3)` [S1, unofficial].
    *   `rays_d`: Ray directions, shape `(n_rays, 3)` [S1, unofficial].
    *   `radiance_field`: A user-defined model capable of querying density and optionally RGB color at 3D positions [S1, unofficial].
*   **Outputs**:
    *   `color`: Rendered RGB colors, shape `(n_rays, 3)` [S1, unofficial].
    *   `opacity`: Accumulated opacity, shape `(n_rays, 1)` [S1, unofficial].
    *   `depth`: Accumulated depth, shape `(n_rays, 1)` [S1, unofficial].

### Data Structures
The core data structures are PyTorch tensors [S1, unofficial]. The `nerfacc` library manages internal packed information (`packed_info`) to optimize memory access during ray marching, but the user interacts primarily with the sample interval tensors `t_starts` and `t_ends` [S1, unofficial].
*   `t_starts`: Start distances of sample intervals along the ray, shape `(n_samples,)` [S1, unofficial].
*   `t_ends`: End distances of sample intervals along the ray, shape `(n_samples,)` [S1, unofficial].
*   `ray_indices`: Indices mapping each sample to its corresponding ray, shape `(n_samples,)` [S1, unofficial].

### Steps
1.  **Define Density Query Function**: Implement `sigma_fn(t_starts, t_ends, ray_indices)` to return density values $\sigma$ [S1, unofficial].
2.  **Define RGB and Density Query Function**: Implement `rgb_sigma_fn(t_starts, t_ends, ray_indices)` to return RGB colors $\mathbf{c}$ and density values $\sigma$ [S1, unofficial].
3.  **Ray Marching**: Call the ray marching routine to determine valid sample intervals, skipping empty or occluded regions [S1, unofficial].
4.  **Rendering**: Call the rendering routine to accumulate color, opacity, and depth using the determined samples [S1, unofficial].
5.  **Optimization**: Compute loss against ground truth and backpropagate through the differentiable rendering pipeline [S1, unofficial].

### Formulas
The volumetric rendering equation accumulates color contributions from samples along a ray $\mathbf{r}$ [S1, unofficial]:
$$C(\mathbf{r}) = \sum_{i=1}^N T_i \alpha_i \mathbf{c}_i$$
Where:
*   $N$ is the number of samples along the ray [G].
*   $\mathbf{c}_i$ is the color of the $i$-th sample [G].
*   $\alpha_i$ is the opacity of the $i$-th sample, defined as $\alpha_i = 1 - \exp(-\sigma_i \delta_i)$ [S1, unofficial].
*   $\sigma_i$ is the density of the $i$-th sample [G].
*   $\delta_i$ is the distance between the start and end of the $i$-th sample interval ($\delta_i = t_{ends,i} - t_{starts,i}$) [G].
*   $T_i$ is the transmittance up to the $i$-th sample, defined as $T_i = \exp\left(-\sum_{j=1}^{i-1} \sigma_j \delta_j\right)$ [S1, unofficial].

### Parameters
*   `near_plane`: The starting distance for ray marching. Typical value: 0.2 [S1, unofficial].
*   `far_plane`: The ending distance for ray marching. Typical value: 1.0 [S1, unofficial].
*   `early_stop_eps`: Threshold for early stopping during ray marching. Typical value: $1 \times 10^{-4}$ [S1, unofficial].
*   `alpha_thre`: Threshold for skipping samples with low opacity. Typical value: $1 \times 10^{-2}$ [S1, unofficial].

### Pseudocode
The following Python-like pseudocode implements the pipeline using PyTorch and the `nerfacc` library interface described in the sources [S1, unofficial].

```python
import torch
from torch import Tensor
from typing import Tuple
import nerfacc

def plug_and_play_rendering(
    rays_o: Tensor,
    rays_d: Tensor,
    radiance_field,
    near_plane: float = 0.2,
    far_plane: float = 1.0,
    early_stop_eps: float = 1e-4,
    alpha_thre: float = 1e-2
) -> Tuple[Tensor, Tensor, Tensor]:
    """
    Executes the plug-and-play ray marching and differentiable rendering pipeline.
    """
    # 1. Define Density Query Function
    def sigma_fn(t_starts: Tensor, t_ends: Tensor, ray_indices: Tensor) -> Tensor:
        t_origins = rays_o[ray_indices]
        t_dirs = rays_d[ray_indices]
        positions = t_origins + t_dirs * (t_starts + t_ends) / 2.0
        return radiance_field.query_density(positions)

    # 2. Define RGB and Density Query Function
    def rgb_sigma_fn(t_starts: Tensor, t_ends: Tensor, ray_indices: Tensor) -> Tuple[Tensor, Tensor]:
        t_origins = rays_o[ray_indices]
        t_dirs = rays_d[ray_indices]
        positions = t_origins + t_dirs * (t_starts + t_ends) / 2.0
        return radiance_field(positions, condition=t_dirs)

    # 3. Ray Marching: Skip empty and occluded space
    packed_info, t_starts, t_ends = nerfacc.ray_marching(
        rays_o, rays_d, sigma_fn=sigma_fn,
        near_plane=near_plane, far_plane=far_plane,
        early_stop_eps=early_stop_eps, alpha_thre=alpha_thre
    )

    # 4. Differentiable Volumetric Rendering
    color, opacity, depth = nerfacc.rendering(
        rgb_sigma_fn, packed_info, t_starts, t_ends
    )
    
    return color, opacity, depth
```

### Edge Cases and Pitfalls
*   **Empty/Occluded Regions**: The pipeline includes logic to skip samples in empty or occluded regions (where $\alpha_i$ or $T_i$ is low) to optimize GPU utilization [S1, unofficial].
*   **Dynamic Scenes**: The Python API is designed to support dynamic and unbounded scenes, unlike some static-only CUDA implementations [S1, unofficial].
*   **Precision**: The use of PyTorch ensures differentiability for gradient-based optimization [S1, unofficial].

## Operating characteristics
*   **Performance**: The Python API achieves performance comparable to specialized CUDA implementations. For example, training an Instant-NGP NeRF takes 4.5 minutes in Python using this pipeline, compared to the official pure CUDA implementation [S1, unofficial].
*   **Hardware**: Experiments were conducted on a single NVIDIA TITAN RTX GPU [S1, unofficial].
*   **Strengths**: Ease of use, extensibility to dynamic/unbounded scenes, and compatibility with existing PyTorch workflows [S1, unofficial].
*   **Limitations**: Potential overhead compared to highly optimized pure CUDA kernels for static scenes, though the source claims comparable speed for Instant-NGP [S1, unofficial].

## Background
The method originates from the NerfAcc toolbox, which focuses on efficient volumetric rendering of radiance fields [S1, unofficial]. It builds on techniques from Instant-NGP but extends them to support dynamic and unbounded scenes [S1, unofficial]. The toolbox provides a user-friendly Python API written with PyTorch, aiming to accelerate most NeRF methods without requiring custom CUDA code [S1, unofficial].
