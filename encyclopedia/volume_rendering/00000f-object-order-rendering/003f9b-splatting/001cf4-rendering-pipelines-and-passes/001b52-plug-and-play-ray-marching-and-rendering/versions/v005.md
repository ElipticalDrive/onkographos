# Plug-and-Play Ray Marching and Rendering

Also called: Differentiable Volumetric Rendering Pipeline, nerfacc pipeline

## Overview
This method provides a modular interface for efficient ray marching and differentiable volumetric rendering, allowing users to plug any user-defined radiance field into a standardized acceleration pipeline [S1, unofficial]. It distinguishes itself from specialized implementations like Instant-NGP by offering a Python API built on PyTorch, which facilitates easier extension to dynamic and unbounded scenes while maintaining high performance [S1, unofficial].

## How it works
The method separates the radiance field query logic from the rendering loop [S1, unofficial]. The user defines two callback functions that the pipeline calls to sample the scene, while the pipeline handles the optimization of sample selection (skipping empty/occluded regions) and the accumulation of color and opacity [S1, unofficial].

### Inputs and Outputs
*   **Inputs**:
    *   `rays_o`: Tensor of ray origins, shape `(n_rays, 3)` [S1, unofficial].
    *   `rays_d`: Tensor of normalized ray directions, shape `(n_rays, 3)` [S1, unofficial].
    *   `radiance_field`: A user-defined model (e.g., MLP, grid) capable of querying density and RGB at 3D positions [S1, unofficial].
*   **Outputs**:
    *   `color`: Rendered RGB image, shape `(n_rays, 3)` [S1, unofficial].
    *   `opacity`: Accumulated opacity, shape `(n_rays, 1)` [S1, unofficial].
    *   `depth`: Accumulated depth, shape `(n_rays, 1)` [S1, unofficial].

### Data Structures
The pipeline manages sample intervals along rays [S1, unofficial].
*   `t_starts`: Tensor of start distances for each sample interval [S1, unofficial].
*   `t_ends`: Tensor of end distances for each sample interval [S1, unofficial].
*   `ray_indices`: Tensor mapping each sample interval to its parent ray index [S1, unofficial].
*   `packed_info`: Internal structure returned by `ray_marching` containing metadata for valid samples to skip empty or occluded regions [S1, unofficial].

### Formulas
The volumetric rendering equation accumulates color contributions [S1, unofficial]:
$$
C(\mathbf{r}) = \sum_{i=1}^N T_i \alpha_i \mathbf{c}_i
$$
where:
*   $\mathbf{c}_i$ is the RGB color at sample $i$ [S1, unofficial].
*   $\alpha_i$ is the opacity of sample $i$, defined as $\alpha_i = (1 - \exp(\sigma_i \delta_i))$ [S1, unofficial].
*   $\sigma_i$ is the volume density at sample $i$ [S1, unofficial].
*   $\delta_i$ is the distance between sample $i$ and $i+1$ (or end of ray) [S1, unofficial].
*   $T_i$ is the transmittance up to sample $i$, defined as $T_i = \exp\left(-\sum_{j=1}^{i-1} \sigma_j \delta_j\right)$ [S1, unofficial].

### Parameters
*   `near_plane`: Starting distance for ray marching. Typical value: 0.2 [S1, unofficial].
*   `far_plane`: Ending distance for ray marching. Typical value: 1.0 [S1, unofficial].
*   `early_stop_eps`: Threshold for early stopping based on transmittance. Typical value: $1e-4$ [S1, unofficial].
*   `alpha_thre`: Threshold for skipping samples with low opacity. Typical value: $1e-2$ [S1, unofficial].

### Pseudocode
The following Python-like pseudocode implements the pipeline using PyTorch conventions [S1, unofficial]. It assumes `radiance_field` is a user-defined module and implements the marching and accumulation logic directly to ensure self-containment [G].

```python
import torch
from torch import Tensor
from typing import Tuple

def run_pipeline(rays_o: Tensor, rays_d: Tensor, radiance_field, 
                 near_plane: float = 0.2, far_plane: float = 1.0, 
                 step: float = 0.5, early_stop_eps: float = 1e-4, 
                 alpha_thre: float = 1e-2):
    """
    Execute the plug-and-play ray marching and rendering pipeline.
    
    Args:
        rays_o: Ray origins (n_rays, 3)
        rays_d: Ray directions (n_rays, 3)
        radiance_field: User-defined radiance field model
        near_plane: Start distance for marching
        far_plane: End distance for marching
        step: Fixed step size for sampling
        early_stop_eps: Transmittance threshold for early stopping
        alpha_thre: Opacity threshold for pruning
    """
    n_rays = rays_o.shape[0]
    color = torch.zeros(n_rays, 3, device=rays_o.device)
    opacity = torch.zeros(n_rays, 1, device=rays_o.device)
    depth = torch.zeros(n_rays, 1, device=rays_o.device)
    
    # Pre-allocate transmittance and active mask
    T = torch.ones(n_rays, 1, device=rays_o.device)
    active = torch.ones(n_rays, dtype=torch.bool, device=rays_o.device)
    
    t = near_plane
    while t <= far_plane:
        # 1. Compute sample positions
        positions = rays_o[active] + rays_d[active] * t  # (n_active, 3)
        
        # 2. Query radiance field (sigma_fn equivalent)
        sigmas = radiance_field.query_density(positions)  # (n_active, 1)
        
        # 3. Query RGB and density (rgb_sigma_fn equivalent)
        rgbs, sigmas = radiance_field(positions, condition=rays_d[active])  # (n_active, 3), (n_active, 1)
        
        # 4. Compute opacity and update transmittance
        delta = torch.full_like(sigmas, step)
        alpha = 1.0 - torch.exp(sigmas * delta)  # Per evidence formula
        T[active] = T[active] * torch.exp(-sigmas * delta)
        
        # 5. Accumulate color, opacity, and depth
        contrib = T[active] * alpha  # (n_active, 1)
        color[active] += contrib * rgbs
        opacity[active] += contrib
        depth[active] += contrib * t
        
        # 6. Prune: skip samples with low opacity or low transmittance
        active = active & (alpha >= alpha_thre) & (T[active] >= early_stop_eps)
        
        if not active.any():
            break
            
        t += step
        
    return color, opacity, depth
```

### Edge Cases and Pitfalls
*   **Precision**: The transmittance calculation involves exponentials of negative sums [S1, unofficial].
*   **Boundaries**: The `near_plane` and `far_plane` parameters define the marching bounds [S1, unofficial].
*   **Empty Regions**: The pipeline automatically skips samples with low opacity ($\alpha_i < \text{alpha\_thre}$) or low transmittance ($T_i < \text{early\_stop\_eps}$) [S1, unofficial].

## Subtopics

### Differentiable Volumetric Rendering
*   **What it is**: The core accumulation step that computes the final pixel color, opacity, and depth by integrating samples along rays using the volumetric rendering equation.
*   **What sets it apart**: It is differentiable with respect to the radiance field parameters, enabling gradient-based optimization for training neural radiance fields.
*   **When to choose it**: When training a NeRF or similar implicit representation where gradients need to flow from the image loss to the scene representation.
*   **Link**: [Differentiable Volumetric Rendering](1318-volume-rendering-pipeline.md)

### Efficient Ray Marching
*   **What it is**: The process of selecting which sample intervals along each ray are relevant for rendering, specifically by skipping empty or occluded regions.
*   **What sets it apart**: It uses density queries to dynamically prune the search space, significantly reducing the number of samples processed compared to uniform sampling.
*   **When to choose it**: When rendering scenes with large empty spaces or when computational efficiency is a priority.
*   **Link**: [Efficient Ray Marching](1318-volume-rendering-pipeline.md)

## Operating characteristics
*   **Time Complexity**: Depends on the number of valid samples after pruning [S1, unofficial].
*   **Memory Complexity**: Proportional to the number of valid samples [S1, unofficial].
*   **Measured Performance**: On a single NVIDIA TITAN RTX GPU, training an 8-layer MLP NeRF to better quality (+0.5 PSNR) takes approximately 1 hour, compared to 1-2 days in the original paper [S1, unofficial]. Instant-NGP NeRF training takes 4.5 minutes in Python, comparable to the official CUDA implementation [S1, unofficial].
*   **Strengths**: High performance, easy to integrate with existing PyTorch models, supports dynamic and unbounded scenes [S1, unofficial].
*   **Limitations**: Requires the user to implement the radiance field query logic [S1, unofficial].
*   **When to use it**: When accelerating existing NeRF methods or developing new radiance field representations that need efficient rendering and differentiability [S1, unofficial].

## Background
The method originates from the NerfAcc toolbox, which focuses on efficient volumetric rendering of radiance fields [S1, unofficial]. It builds on techniques from Instant-NGP but extends them to support dynamic and unbounded scenes [S1, unofficial]. The toolbox provides a user-friendly Python API written with PyTorch, designed to accelerate most NeRF methods [S1, unofficial].
