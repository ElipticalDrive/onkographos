# Point Cloud Rendering

Also called: Point Splatting, Point-based Rendering

## Overview
Point Cloud Rendering projects a set of 3D points into screen space and aggregates their contributions to determine the final pixel color [S1, unofficial]. It differs from mesh rendering by operating on unstructured discrete samples rather than continuous surfaces, and from voxel rendering by avoiding the memory overhead of a dense 3D grid [S1, unofficial]. The method is primarily distinguished by its differentiability, allowing gradients to flow from the rendered image back to the 3D point positions and attributes [S1, unofficial].

## How it works
**Inputs:** A set of 3D points $P_{xyz}^{(i)} = (x_i, y_i, z_i)$ with associated attributes (e.g., color $C_i$), and camera parameters (projection matrix $M$, view matrix $V$).
**Outputs:** A 2D image $I(u, v)$ with color values for each pixel.

**Data Structures:**
*   **Point Cloud:** An array of structures, each containing:
    *   `position`: `vec3` $(x, y, z)$
    *   `color`: `vec3` $(r, g, b)$
    *   `size`: `float` (influence radius, optional)

**Steps:**

1.  **Calculate Screen Space Coordinates:**
    For each point $P_{xyz}^{(i)}$, compute its screen space coordinates $p_{uv}^{(i)} = (u_i, v_i)$. This is achieved via matrix multiplication using the camera's projection and view matrices [S1, unofficial].
    $$
    \begin{bmatrix} u_i \\ v_i \\ w_i \end{bmatrix} = M \cdot V \cdot \begin{bmatrix} x_i \\ y_i \\ z_i \\ 1 \end{bmatrix}
    $$
    $$
    u_i = \frac{u_i}{w_i}, \quad v_i = \frac{v_i}{w_i}
    $$
    This step is differentiable with respect to the point positions [S1, unofficial].

2.  **Compute Influence:**
    Calculate the spatial influence $I_i$ of each point on a target pixel. Assuming a size of one pixel leads to sparse images [S1, unofficial]. Common methods include:
    *   **Truncated Gaussian Blur:** $I_i$ is determined by a Gaussian kernel centered at $p_{uv}^{(i)}$ [S1, unofficial].
    *   **Distance-based:** $I_i$ is a function of the Euclidean distance between the pixel center and $p_{uv}^{(i)}$ [S1, unofficial].
    *   **Trade-off:** Large influence sizes prevent derivatives from becoming zero for distant points but reduce rendering quality [S1, unofficial].

3.  **Aggregate Pixel Color:**
    Determine the final color $C_{pixel}$ for each pixel based on $I_i$ and depth $z_i$. Several aggregation strategies exist:
    *   **Weighted Sum:** $C_{pixel} = \sum I_i \cdot C_i$. This does not account for occlusion [S1, unofficial].
    *   **Closest Point (Z-Buffer):** Select the single point $i$ with the smallest $z_i$ among those influencing the pixel. This prevents optimization of occluded points [S1, unofficial].
    *   **K-Nearest Neighbors:** Select the $K$ nearest 3D points to the camera and weigh them by $I_i$ [S1, unofficial].
    *   **Distance-Weighted Sum:** Weigh all points by both spatial influence $I_i$ and distance from the camera [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Sparsity:** Assuming point influence size is one pixel results in very sparse images [S1, unofficial].
*   **Occlusion:** Simple weighted sum approaches do not account for occlusion [S1, unofficial].
*   **Convergence Trade-off:** Large influence sizes aid optimization convergence by preventing zero derivatives for distant points but degrade rendering quality [S1, unofficial].
*   **Depth Density:** When converting depth images to point clouds, point density decreases inversely proportional to distance [S1, unofficial].

## Subtopics

### Voxel-based Point Rendering
Generates 3D voxels from the point cloud and renders them using voxel-based methods [S1, unofficial]. Chosen when voxel-based acceleration structures are preferred over direct splatting. See [Voxel Rendering](52-voxel-rendering.md).

### Depth Image Rendering
Treats depth images as a special case of point cloud rendering by converting depth to points and projecting to a virtual view [S1, unofficial]. Used in self-supervised monocular depth estimation. See [Depth Rendering](52-depth-rendering.md).

## Operating characteristics
*   **Time Complexity:** $O(N \cdot K)$ where $N$ is the number of points and $K$ is the number of pixels influenced by each point (or $K$ nearest neighbors).
*   **Memory Complexity:** $O(N)$ for storing points, plus $O(W \cdot H)$ for the image buffer.
*   **Strengths:** Differentiable with respect to point positions and attributes, enabling optimization in neural networks [S1, unofficial]. Simple implementation.
*   **Limitations:** Sparse images if influence is small. Occlusion handling is non-trivial with simple blending. Quality-convergence trade-off with influence size [S1, unofficial].
*   **When to use:** Differentiable rendering tasks, neural implicit representations, and scenarios with reduced 3D supervision [S1, unofficial].
*   **When not to use:** When high-fidelity occlusion is required without complex aggregation logic, or when dense surface representation is needed.

## Background
Point cloud rendering has become a natural choice for data representation in differentiable rendering and scene understanding with reduced 3D supervision [S1, unofficial]. It is used in various practical 3D problems [S1, unofficial]. The method is foundational for neural implicit representations and self-supervised learning of monocular depth estimation [S1, unofficial].
