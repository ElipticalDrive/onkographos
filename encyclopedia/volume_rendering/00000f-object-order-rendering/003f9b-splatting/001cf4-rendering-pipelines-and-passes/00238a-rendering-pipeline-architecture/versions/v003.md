# Rendering Pipeline Architecture


## Overview
Rendering Pipeline Architecture defines the structural organization of rendering stages, decomposing the image generation process into sequential, independent phases such as data traversal, interpolation, shading, and compositing [S1, S3, unofficial]. It solves the problem of managing complex visual effects and geometric projections by isolating their computational requirements into distinct passes, allowing for optimized memory access patterns and flexible appearance control [S3, unofficial]. It differs from monolithic rendering approaches by explicitly separating geometric projection (e.g., depth testing, splatting) from visual appearance (e.g., shading, classification), enabling techniques like deferred shading or multi-pass accumulation [S3, unofficial].

## Shared principles
The rendering pipeline family operates on the principle of stage separation, where each stage performs a specific transformation on the data or image state. Common mechanisms include:

1.  **Stage Decomposition:** The rendering process is divided into logical stages such as Data Traversal, Interpolation, Gradient Computation, Classification, Shading, and Compositing [S1, S3, unofficial]. This allows for independent optimization of visual appearance (shading/classification) and geometric projection (compositing) [S3, unofficial].
2.  **Intermediate Storage:** Pipelines utilize intermediate framebuffers or data structures (e.g., fragment lists, G-buffers) to store per-pixel or per-voxel attributes (color, normal, depth, opacity) between stages [S1, S2, unofficial]. For example, [Custom Pass Rendering](3629-custom-pass-rendering.md) uses multiple FBOs to store hit positions, normals, and material IDs [S1, unofficial].
3.  **Sequential Execution:** Stages are executed in a defined order. For instance, [Fragment List-Based Rendering](3488-fragment-list-based-rendering-pipeline.md) follows a Clear, Construction, Insertion, and Evaluation sequence [S1, unofficial].
4.  **Accumulation and Blending:** Final image generation involves accumulating contributions from multiple samples or primitives, often using alpha blending or weighted summation [S1, S3, unofficial].

## Subtopics

### [Splat Attributes Pass](1066-splat-attributes-pass.md)
Computes visible surface contributions by combining depth testing with attribute accumulation into a G-Buffer, decoupling composition from accumulation.

### [Single-Pass Splat Rendering Pipeline](1254-single-pass-splat-rendering-pipeline.md)
Combines splat and mesh rendering in one pass using object-space attribute interpolation on grid patches, avoiding multi-pass artifacts.

### [Three-Pass GPU Point Rendering Pipeline](2837-three-pass-gpu-point-rendering-pipeline.md)
Decomposes splatting into depth, accumulation, and normalization stages to handle occlusion and weighted blending correctly.

## Background
The concept of pipeline architecture in graphics rendering originated with the separation of fixed-function hardware stages in early 3D accelerators, evolving into programmable shader pipelines. In volume rendering, this architecture was adapted to handle the high memory bandwidth requirements of ray marching and splatting by breaking down the process into manageable passes [S1, S3, unofficial]. It is widely used in real-time volume visualization, point cloud rendering, and deferred shading techniques [S1, S3, unofficial].
