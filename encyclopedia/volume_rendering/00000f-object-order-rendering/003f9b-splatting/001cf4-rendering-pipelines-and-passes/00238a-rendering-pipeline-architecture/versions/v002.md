# Rendering Pipeline Architecture

Also called: Splatting Pipeline Architecture, Point-Based Rendering Pipeline

## Overview
This family defines the architectural decomposition of rendering point-sampled geometry (splats) into sequential processing stages. It solves the problem of correctly blending overlapping, semi-transparent primitives with proper occlusion handling, which is difficult to achieve in a single pass due to the non-linear nature of depth sorting and alpha blending [S1, unofficial]. It differs from [Plug-and-Play Ray Marching and Rendering](981-plug-and-play-ray-marching-and-rendering.md) by using rasterization-based accumulation rather than ray casting, and from [Volume Rendering Pipeline](1318-volume-rendering-pipeline.md) by operating on discrete point primitives rather than continuous voxel grids.

## Shared principles
The family shares the fundamental mechanism of decomposing the rendering of point-based geometry into distinct, sequential stages that can be optimized for specific tasks such as depth testing, attribute accumulation, or normalization. All methods utilize a fragment shader or equivalent processing unit to compute per-pixel contributions based on the geometric relationship between the splat center and the fragment position.

Key shared mathematical concepts include:
1.  **Splat Projection:** Mapping 3D point attributes (position, radius, color) to 2D screen space.
2.  **Weight Calculation:** Determining the contribution of each fragment based on radial distance from the splat center and/or depth proximity to the visible surface.
3.  **Accumulation:** Summing weighted attributes (color, normal) into framebuffers.
4.  **Occlusion Handling:** Using depth buffers to discard fragments behind opaque geometry.

The specific implementation of these principles varies: some pipelines decouple attribute computation from final color writing (deferred), while others combine them in a single pass. Some rely on hardware depth testing, while others perform explicit depth comparisons in the fragment shader.

## Subtopics

### [Splat Attributes Pass](1066-splat-attributes-pass.md)
Computes visible surface contributions by combining geometric depth testing with attribute accumulation into a G-Buffer. It differs from the [Single-Pass Splat Rendering Pipeline](1254-single-pass-splat-rendering-pipeline.md) by decoupling final color composition from attribute accumulation, and from the [Three-Pass GPU Point Rendering Pipeline](2837-three-pass-gpu-point-rendering-pipeline.md) by explicitly performing per-fragment depth comparisons against a pre-written depth buffer to determine visibility before accumulating attributes.

### [Single-Pass Splat Rendering Pipeline](1254-single-pass-splat-rendering-pipeline.md)
Combines splat and mesh rendering components to enable high-quality shader effects in a single pass, avoiding multi-pass blending artifacts. It differs from the [Three-Pass GPU Point Rendering Pipeline](2837-three-pass-gpu-point-rendering-pipeline.md) by replacing screen-space blending with object-space attribute interpolation on regular grid patches, allowing for complex lighting in one pass.

### [Three-Pass GPU Point Rendering Pipeline](2837-three-pass-gpu-point-rendering-pipeline.md)
A hardware-accelerated method decomposing splatting into distinct depth, accumulation, and normalization stages. It differs from the Single-Pass Splat Rendering Pipeline by explicitly separating the depth test from the color accumulation to ensure correct occlusion, and from the Splat Attributes Pass by performing the final weighted sum and normalization in dedicated framebuffer operations rather than deferred attribute computation.

## Background
The concept of splatting was introduced by Levoy and Hanrahan in 1990 [G]. The specific pipeline architectures described here, particularly those involving G-Buffer accumulation and multi-pass normalization, are derived from modern real-time point cloud rendering techniques [S1, unofficial].
