# Selective Exact Repair

## Overview
Selective Exact Repair is a post-binning sorting step in the TileGS rasterization pipeline that restores exact baseline depth order for specific segments of the tile-bin-major pair stream to ensure correct rasterization, while leaving other segments in their tile-local bin order [S1]. It solves the problem of depth ambiguity introduced by atomic scatter operations during bin construction, which produce entries in arbitrary order within a bin [S1]. Unlike full sorting, which is prohibitively expensive for large bins, this method selectively repairs only segments that are likely to cause visible artifacts or performance bottlenecks, balancing correctness and speed [S1].

## How it works
**Inputs and Outputs:**
- Input: The pair stream $P$ and its sidecars (flat-id, geometry) after Tile-Local Bin Construction, along with bin offset arrays `binOffsets[t, b]` for tile $t$ and bin $b$ [S1].
- Output: A repaired pair stream where selected segments are sorted by the original baseline key $s(e)$, with sidecars aligned [S1].

**Data Structures:**
- `binOffsets[t, b]`: Array of integers storing the start index of bin $b$ in tile $t$. Size: $(T \times (K+1))$, where $T$ is number of tiles and $K$ is number of bins per tile [S1].
- `P`: Array of pairs (depth key, index) [S1].
- `sidecars`: Arrays aligned with `P` (e.g., `flat_id`, `geometry`) [S1].
- `R`: List of segments to repair, each tuple $(t, b, \text{begin}, \text{end})$ [S1].
- `used`: Integer counter for total entries in $R$ [S1].
- `B_rep`: Maximum number of entries allowed in $R$ (Not given in the sources) [G].

**Parameters:**
- $K$: Number of bins per tile (Default: 64) [S1].
- $l$: Length of a segment ($\text{end} - \text{begin}$) [S1].
- $l_{\text{tile}}$: Total length of all bins in a tile ($\text{binOffsets}[t, K] - \text{binOffsets}[t, 0]$) [S1].
- Thresholds (from Table 4 in [S1]):
  - No-repair threshold: $l \le 1$ [S1].
  - Local exact-repair maximum: 512 entries [S1].
  - Always-keep long segment cutoff: $l \ge 320$ [S1].
  - Global-tail bucket: $l > 512$ [S1].
  - Tile-share cutoff: $l / l_{\text{tile}} \ge 45\%$ [S1].
  - Local-256 share cutoff: $129 \le l \le 256$ AND $l / l_{\text{tile}} \ge 10\%$ [S1].
  - Early bin repair: $b < 2$ AND $l \ge 16$ [S1].

**Steps:**
1. Initialize $R = \emptyset$ and $\text{used} = 0$ [S1].
2. Iterate over logical segment IDs $q = t \times K + b$ in tile-bin order [S1].
3. For each segment $(t, b)$:
   a. Get $\text{begin} = \text{binOffsets}[t, b]$ and $\text{end} = \text{binOffsets}[t, b+1]$ [S1].
   b. Calculate length $l = \text{end} - \text{begin}$ [S1].
   c. Calculate $l_{\text{tile}} = \text{binOffsets}[t, K] - \text{binOffsets}[t, 0]$ [S1].
   d. Set $\text{keep} = \text{false}$ [S1].
   e. If $129 \le l \le 256$ AND $l / l_{\text{tile}} \ge 0.10$, set $\text{keep} = \text{true}$ [S1].
   f. If $b < 2$ AND $l \ge 16$, set $\text{keep} = \text{true}$ [S1].
   g. If $\text{keep}$ is true AND $\text{used} + l \le B_{\text{rep}}$, add $(t, b, \text{begin}, \text{end})$ to $R$ and update $\text{used} = \text{used} + l$ [S1].
4. For all segments $(t, b, \text{begin}, \text{end})$ in $R$:
   a. Sort $P[\text{begin}:\text{end})$ by original baseline key $s(e)$ [S1].
   b. Keep flat-id and geometry sidecars aligned with the sorted pair order [S1].
5. Return repaired pair stream and aligned sidecars [S1].

**Pseudocode:**
```python
def selective_exact_repair(P, sidecars, binOffsets, K, B_rep):
    R = []
    used = 0
    T = len(binOffsets)
    
    for t in range(T):
        for b in range(K):
            begin = binOffsets[t][b]
            end = binOffsets[t][b + 1]
            l = end - begin
            
            if l <= 1:
                continue
                
            l_tile = binOffsets[t][K] - binOffsets[t][0]
            keep = False
            
            if 129 <= l <= 256 and l / l_tile >= 0.10:
                keep = True
                
            if b < 2 and l >= 16:
                keep = True
                
            if keep and used + l <= B_rep:
                R.append((t, b, begin, end))
                used += l
                
    for (t, b, begin, end) in R:
        segment_keys = [P[i][0] for i in range(begin, end)]
        segment_indices = list(range(begin, end))
        
        sorted_pairs = sorted(zip(segment_keys, segment_indices), key=lambda x: x[0])
        
        for new_pos, (key, old_pos) in enumerate(sorted_pairs):
            actual_pos = begin + new_pos
            P[actual_pos] = P[old_pos]
            for sc in sidecars:
                sc[actual_pos] = sc[old_pos]
                
    return P, sidecars
```

**Edge Cases and Pitfalls:**
- Precision: The depth key $s(e)$ must be the same near-depth-shifted key used during range estimation to ensure consistency [S1].
- Boundaries: $B_{\text{rep}}$ limits the total repair cost. If not given, it must be defined by the implementation [G].
- Degenerate Input: Segments with $l \le 1$ are skipped, avoiding unnecessary sorting overhead [S1].

## Operating characteristics
- Time Complexity: Sorting is performed only on selected segments. The cost is $O(\sum_{s \in R} l_s \log l_s)$, where $l_s$ is the length of segment $s$ [G].
- Memory Complexity: $O(N)$ for the pair stream and sidecars, plus $O(|R|)$ for the repair list [G].
- Measured Performance: The selective policy uses fixed global thresholds, not tuned per scene [S1]. The default path (No-GW, K=64) is recommended [S1].
- Strengths: Avoids full sorting cost while ensuring correctness for critical segments [S1].
- Limitations: May still have artifacts in un-repaired segments if they are large and unordered [S1].
