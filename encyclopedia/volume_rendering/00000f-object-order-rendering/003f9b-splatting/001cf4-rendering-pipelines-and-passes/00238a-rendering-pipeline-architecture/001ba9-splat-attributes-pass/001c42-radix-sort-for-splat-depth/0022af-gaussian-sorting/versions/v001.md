# Gaussian Sorting


## Overview
Gaussian Sorting is the process of ordering 3D Gaussian primitives by their depth in camera space to enable correct front-to-back alpha compositing during splatting [S1, unofficial]. It transforms the spatial positions of Gaussians into the view frustum and sorts them based on their z-coordinate [S1, unofficial]. Unlike general-purpose sorting, this method is tightly coupled with the rasterization pipeline, often serving as a prerequisite for tile-based sorting [S2, unofficial]. It differs from [Fast Splat Sorting](2953-fast-splat-sorting.md) by focusing on the initial global depth sort rather than optimized tile-local reordering.

## How it works
**Inputs:**
- Array of $N$ Gaussians, each defined by position $\mathbf{p} = (x, y, z)$, covariance $\Sigma$, opacity $\alpha$, and color $C$.
- View matrix $V$ (4x4) transforming world space to camera space.

**Outputs:**
- An index array `indices` of length $N$, such that $z_{indices[0]} \le z_{indices[1]} \le \dots \le z_{indices[N-1]}$ in camera space.

**Data Structures:**
- `Gaussian`: struct containing `position` (vec3), `covariance` (mat3), `opacity` (f32), `color` (vec3).
- `IndexArray`: array of integers `[0, 1, ..., N-1]`.

**Steps:**
1. **Transform Positions:** For each Gaussian $i$, compute its camera-space position $\mathbf{p}'_i = V \cdot \begin{bmatrix} \mathbf{p}_i \\ 1 \end{bmatrix}$. Extract the z-component $z'_i = \mathbf{p}'_i.z$.
2. **Initialize Indices:** Create an index array `idx` where `idx[i] = i` for all $i \in [0, N-1]$.
3. **Sort Indices:** Sort `idx` based on the values $z'_{idx[i]}$ in ascending order (front-to-back).

**Pseudocode:**
```python
def gaussian_sort(gaussians: List[Gaussian], view_matrix: Matrix4x4) -> List[int]:
    """
    Sorts Gaussians by depth in camera space.
    :param gaussians: List of Gaussian primitives.
    :param view_matrix: 4x4 view matrix.
    :return: List of indices sorted by camera-space z-depth.
    """
    n = len(gaussians)
    indices = list(range(n))
    
    # Precompute camera-space z-depths
    depths = []
    for i in range(n):
        pos = gaussians[i].position
        # Homogeneous coordinate transformation
        # Assuming view_matrix is row-major or column-major consistent with math library
        # p_cam = view_matrix * [x, y, z, 1]
        p_cam = view_matrix.transform_point(pos) 
        depths.append(p_cam.z)
        
    # Sort indices based on precomputed depths
    # Stable sort is preferred to maintain original order for equal depths
    indices.sort(key=lambda i: depths[i])
    
    return indices
```

**Parameters:**
- Sorting algorithm: Typically a stable sort (e.g., Radix Sort, Merge Sort) is used for performance on GPU [S2, unofficial].
- Depth metric: Euclidean distance or z-depth in camera space. Z-depth is standard for rasterization [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Precision:** Floating-point precision errors in depth comparison can cause z-fighting or incorrect blending if Gaussians are very close. [G] Use epsilon comparison or stable sorting to handle ties.
- **Back-face Gaussians:** Gaussians behind the camera ($z' \le 0$) should be excluded or handled carefully to avoid rendering artifacts. [G] Filter out Gaussians with $z' \le 0$ before sorting.
- **Large N:** For very large scenes, global sorting may be expensive. [S2, unofficial] Temporal coherence heuristics can reduce re-sorting costs.

## Subtopics

### Temporal Coherence Heuristic for Gaussian Sorting
A method that introduces a temporal coherence heuristic into the tile sorting, avoiding re-sorting of Gaussians whose depth order has not changed between frames [S2, unofficial]. It leverages the fact that Gaussian positions change minimally between consecutive frames in video sequences, allowing the rasterizer to skip sorting for stable Gaussians, thereby reducing computational overhead [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N \log N)$ for comparison-based sorts; $O(N)$ for radix sort if bit-pattern sorting is applicable (as in [Radix Sort for Splat Depth](1207-radix-sort-for-splat-depth.md)).
- **Memory Complexity:** $O(N)$ for storing indices and depth values.
- **Performance:** Global sorting is a bottleneck for large scenes. [S2, unofficial] Temporal coherence can significantly reduce the number of sorts required per frame.
- **Strengths:** Simple to implement; ensures correct front-to-back rendering.
- **Limitations:** Global sort is expensive for millions of Gaussians. [S2, unofficial] Does not account for tile occupancy or occlusion culling.

## Background
Gaussian Sorting is a fundamental step in 3D Gaussian Splatting rasterization, introduced alongside the original 3D Gaussian Splatting paper [S1, unofficial]. It ensures that alpha blending occurs in the correct depth order. The method has been extended with temporal coherence heuristics to improve performance in dynamic scenes [S2, unofficial].
