# Gaussian Splat Sorting

Also called: Clip-space w depth sorting, Tile-based sorting using clip-space w

## Overview
Gaussian Splat Sorting sorts projected 3D Gaussian splats front-to-back within screen-space tiles to enable correct alpha blending [S1, unofficial]. It differs from its parent [Radix Sort for Splat Depth](1207-radix-sort-for-splat-depth.md) by operating on a per-tile basis using a combined tile-ID and depth key, and from [Gaussian Sorting](2845-gaussian-sorting.md) by relying on a simple monotonic depth proxy rather than complex geometric comparisons.

## How it works
**Inputs:**
- `clip_pos`: Clip-space position of the splat center (vec4).
- `tile_id`: The screen-space tile identifier for the splat (uint).
- `id`: The unique splat identifier (uint).

**Outputs:**
- `sort_keys`: Array of 32-bit sort keys.
- `sort_values`: Array of splat IDs corresponding to the keys.

**Data Structures:**
- `sort_keys`: `uint` array. Each element is a 32-bit integer where the upper 16 bits are `tile_id` and the lower 16 bits are the quantized depth.
- `sort_values`: `uint` array. Stores the original splat `id`.

**Steps:**
1. **Calculate View Depth:** Extract the clip-space $w$ component. Since reverse-Z projection is used, $w$ increases with distance. Clamp to zero to handle near-plane clipping artifacts.
   $$ d_{view} = \max(0.0, \text{clip\_pos}.w) $$
2. **Normalize Depth:** Map the view depth to the range $[0, 1]$ using a rational function that preserves monotonicity and handles large depth values without overflow.
   $$ d_{01} = \frac{d_{view}}{1.0 + d_{view}} $$
3. **Quantize Depth:** Convert the normalized depth to a 16-bit unsigned integer.
   $$ d_{16} = \text{uint}(d_{01} \times 65535.0) \ \& \ 0\text{xFFFF} $$
4. **Create Sort Key:** Combine the tile ID and quantized depth into a single 32-bit key. The tile ID occupies the upper 16 bits, and the depth occupies the lower 16 bits. This ensures that sorting by the key first groups splats by tile, then by depth within each tile.
   $$ \text{key} = (\text{tile\_id} \ll 16) \ | \ d_{16} $$
5. **Store Keys and Values:** Write the key and the splat ID to the respective sort buffers at the current offset.
   $$ \text{sort\_keys}[\text{offset}] = \text{key} $$
   $$ \text{sort\_values}[\text{offset}] = \text{id} $$

**Parameters:**
- Depth quantization bits: 16.
- Depth normalization constant: 1.0 (added to denominator).

**Edge Cases and Pitfalls:**
- **Reverse-Z:** The method assumes reverse-Z projection where $w$ is monotonic with distance. If forward-Z is used, the depth comparison must be inverted or the projection matrix adjusted.
- **Near Plane:** Clamping $d_{view}$ to 0 prevents negative depths from causing incorrect sorting or underflow during quantization.
- **Precision:** The rational normalization $d_{view} / (1.0 + d_{view})$ provides better precision for distant splats compared to linear normalization, but 16-bit quantization may still cause z-fighting artifacts for very distant, overlapping splats.

**Pseudocode:**
```python
def gaussian_splat_sort(clip_pos_w: float, tile_id: uint, splat_id: uint) -> tuple[uint, uint]:
    # Step 1: Calculate view depth
    view_depth = max(0.0, clip_pos_w)
    
    # Step 2: Normalize depth to 0-1 range
    depth01 = view_depth / (1.0 + view_depth)
    
    # Step 3: Quantize depth to 16-bit integer
    depth16 = uint(depth01 * 65535.0) & 0xFFFF
    
    # Step 4: Create sort key by combining tile ID and depth
    key = (tile_id << 16) | depth16
    
    # Step 5: Return key and value
    return key, splat_id
```

## Subtopics

## Operating characteristics
- **Time Complexity:** $O(N)$ for key generation, where $N$ is the number of splats. Sorting is handled by the parent radix sort method.
- **Memory Complexity:** $O(N)$ for storing keys and values.
- **Strengths:** Simple, hardware-friendly key generation. The combined tile-depth key allows for efficient tile-based sorting without complex data structures.
- **Limitations:** 16-bit depth quantization may lead to sorting inaccuracies for distant splats. Relies on reverse-Z projection.

## Background
This method is derived from implementations in real-time 3D Gaussian Splatting renderers, specifically those targeting mobile or constrained hardware where efficient tile-based sorting is critical [S1, unofficial]. It leverages the properties of clip-space $w$ as a monotonic distance proxy in reverse-Z projection systems.
