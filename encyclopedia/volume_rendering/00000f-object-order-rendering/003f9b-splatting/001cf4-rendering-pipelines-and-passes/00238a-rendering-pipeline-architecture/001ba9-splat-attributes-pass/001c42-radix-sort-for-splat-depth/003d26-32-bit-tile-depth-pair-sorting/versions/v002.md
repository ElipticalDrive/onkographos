# 32-bit Tile-Depth Pair Sorting

Also called: 32-bit Key Sorting, Resolution-adaptive quantized depth sorting key, VkSplat 32-bit Key Sorting

## Overview
This method compresses the conventional 64-bit depth sorting key into 32 bits to reduce sorting traffic and the number of radix passes required for splat sorting [S1, unofficial]. It differs from popular CUDA implementations that use 64-bit keys by mapping depth to a specific range where only the lower 23 mantissa bits vary, allowing tile IDs to occupy the minimum necessary higher bits [S2, unofficial]. This optimization is particularly beneficial for Vulkan sorting implementations, which are often slower than CUDA's built-in sorting, while maintaining quality metrics comparable to 64-bit approaches [S2, unofficial].

## How it works
**Inputs and Outputs**
- **Input**: Projected splat depth $z$ (positive real value), tile ID (integer) [S2, unofficial].
- **Output**: A 32-bit unsigned integer sorting key [S1, unofficial].

**Data Structures**
The sorting key is a 32-bit unsigned integer (`u32`) packed with two fields:
1.  **Tile ID**: Occupies the most significant bits (MSBs) [S2, unofficial]. The number of bits is resolution-adaptive [S1, unofficial].
2.  **Quantized Depth**: Occupies the remaining least significant bits (LSBs) [S2, unofficial]. This field uses at least 18 bits for standard resolutions (e.g., 1080p with 16x16 tiles) [S2, unofficial].

**Steps**
1.  **Map Depth**: Transform the positive real depth value $z$ into a new value $z'$ using the mapping function:
    $$ z' = \frac{2z+1}{z+1} $$
    This maps $z \in (0, \infty)$ to $z' \in (1, 2)$ [S2, unofficial].
2.  **Interpret as Float**: Treat $z'$ as a standard IEEE 754 single-precision (FP32) floating-point number [G]. Because $z' \in (1, 2)$, the exponent bits are constant, and the ordering of $z'$ is preserved in the bit pattern of the mantissa [S2, unofficial].
3.  **Ensure Mantissa Distinctness**: Verify that the mapping ensures distinct depth values result in differences only in the lower 23 mantissa bits of the FP32 representation [S2, unofficial].
4.  **Pack Key**:
    - Extract the bit pattern of the FP32 value $z'$ [G].
    - Determine the number of bits required for the tile ID based on image resolution and tile size [S2, unofficial]. For images up to 1080p with a 16x16 tile size, this is at most 14 bits [S2, unofficial].
    - Place the tile ID in the highest bits of the 32-bit integer [S2, unofficial].
    - Place the higher bits of the floating-point mantissa (from the mapped depth) in the lower bits of the 32-bit integer [S2, unofficial].
    - The resulting 32-bit integer serves as the sorting key [S2, unofficial].

**Pseudocode**
```python
def pack_tile_depth_key(tile_id: int, depth: float, img_width: int, img_height: int, tile_width: int, tile_height: int) -> int:
    """
    Packs tile ID and quantized depth into a 32-bit sorting key.
    
    Args:
        tile_id: The integer ID of the tile containing the splat.
        depth: The positive real depth value of the splat.
        tile_width: Width of a tile in pixels.
        tile_height: Height of a tile in pixels.
        img_width: Total image width in pixels.
        img_height: Total image height in pixels.
        
    Returns:
        A 32-bit unsigned integer sorting key.
    """
    # Step 1: Map depth to range (1, 2)
    z_prime = (2.0 * depth + 1.0) / (depth + 1.0)
    
    # Step 2: Extract FP32 bit pattern (little-endian assumed for GPU sorting)
    import struct
    fp32_bits = struct.unpack('<I', struct.pack('<f', z_prime))[0]
    
    # Step 3: Determine bit allocation
    num_tiles_x = (img_width + tile_width - 1) // tile_width
    num_tiles_y = (img_height + tile_height - 1) // tile_height
    total_tiles = num_tiles_x * num_tiles_y
    tile_id_bits = total_tiles.bit_length() if total_tiles > 1 else 0
    
    # Step 4: Pack key
    # Extract mantissa (lower 23 bits of FP32 for range [1, 2))
    mantissa = fp32_bits & 0x7FFFFF
    depth_bits = 32 - tile_id_bits
    # Clamp depth_bits to available mantissa bits (23), ensuring at least 18 as per typical usage
    depth_bits = max(18, min(depth_bits, 23))
    # Shift mantissa to keep the most significant depth_bits
    quantized_depth = mantissa >> (23 - depth_bits)
    
    # Tile ID in MSBs, quantized depth in LSBs
    return (tile_id << depth_bits) | quantized_depth
```

**Parameters**
- **Key Size**: 32 bits [S1, unofficial].
- **Tile Size**: 16x16 pixels is a common configuration [S2, unofficial].
- **Resolution**: Tested up to 1080p [S2, unofficial].

**Edge Cases and Pitfalls**
- **Precision Loss**: Compressing to 32 bits reduces depth precision compared to 64-bit keys, though no difference in quality metrics was observed for resolutions up to 1080p [S2, unofficial].
- **Endianness**: The bit packing assumes a specific endianness for the float-to-int conversion; the implementation must match the hardware's endianness [G].
- **Depth Range**: The mapping function assumes positive real depths; negative or zero depths are not defined by the formula [S2, unofficial].

## Operating characteristics
- **Time Complexity**: Reduces the number of radix passes compared to 64-bit sorting [S1, unofficial].
- **Memory Complexity**: Reduces intermediate data movement in the front end by halving the key size [S1, unofficial].
- **Performance**: On an NVIDIA RTX 4090 GPU, RoofGS achieves 10× end-to-end acceleration [S1, unofficial].
- **Strengths**: Optimizes for Vulkan sorting performance, which is often slower than CUDA [S2, unofficial]. Reduces sorting traffic [S1, unofficial].
- **Limitations**: Reduced depth precision compared to 64-bit keys, though quality impact is negligible for typical resolutions [S2, unofficial].

## Background
This method was introduced in RoofGS [S1, unofficial] and VkSplat [S2, unofficial] as part of efforts to accelerate 3D Gaussian Splatting (3DGS) rendering and training. It addresses the bottleneck of sorting projected splats by depth, which is a critical step in object-order splatting pipelines [S2, unofficial]. The technique is specifically designed to mitigate the performance gap between Vulkan and CUDA sorting implementations [S2, unofficial].
