# Splat Attributes Pass

Also called: Blending Pass, G-Buffer Pass

## Overview
The Splat Attributes Pass is a fragment-processing stage in hardware-accelerated surface splatting that reconstructs continuous and cardinal attributes from overlapping splats into a reconstruction buffer (G-Buffer) [S1, unofficial]. It solves the problem of correctly accumulating per-splat attributes (such as color and normal) in the presence of transparency and depth occlusion, distinguishing itself from sibling passes by handling two distinct attribute types: continuous attributes are accumulated via weighted blending, while cardinal attributes are resolved via maximum-weight comparison [13190-attribute-accumulation-and-blending.md]. It operates in conjunction with a ternary depth test to manage z-pass, z-fail, and z-blend conditions [13190-attribute-accumulation-and-blending.md].

## How it works
The pass processes each fragment generated by the rasterization of a splat primitive. It calculates a combined weight based on radial distance from the splat center and depth proximity to the visible surface, then accumulates weighted attributes into the G-Buffer.

### Inputs and Outputs
**Inputs:**
*   `i.radius`: The radius of the splat in world space (or screen space, depending on implementation; source uses world-space conversion logic [S1, unofficial]).
*   `i.color`: The base color of the splat.
*   `gl_FragCoord`: The window-space coordinates of the fragment.
*   `g_depth`: The depth buffer texture containing the current surface depth.
*   `viewport_size`: The dimensions of the rendering viewport.

**Outputs (G-Buffer Textures):**
*   `g_normal` (vec4, location 0): Stores the accumulated weighted normal vector in the RGB channels. The alpha channel is unused or reserved [S1, unofficial].
*   `g_color` (vec4, location 1): Stores the accumulated weighted color in the RGB channels and the accumulated weight in the Alpha channel [S1, unofficial].

### Data Structures
*   **G-Buffer:** A set of render targets (textures) bound to fragment shader output locations.
    *   `g_normal`: `vec4` format.
    *   `g_color`: `vec4` format.

### Steps
1.  **Discard Outside Radius:** Calculate the squared distance from the fragment to the center of the point in screen space. Discard the fragment if it lies outside the splat's circular boundary.
    *   `from_center_pt_spc = gl_PointCoord - vec2(0.5, 0.5)`
    *   `mag_sq = dot(from_center_pt_spc, from_center_pt_spc)`
    *   If `mag_sq > 0.25`, discard.
2.  **Convert to World Space Offset:** Transform the screen-space offset to a world-space offset using the splat's radius.
    *   `from_center_wld_spc = from_center_pt_spc * 2 * i.radius`
3.  **Calculate Depth Offset:** Compute the depth offset from the center of the sphere to its surface at the current fragment's 2D position.
    *   `depth_offset = sqrt(i.radius * i.radius - dot(from_center_wld_spc, from_center_wld_spc))`
4.  **Calculate Fragment Depth:** Determine the fragment's depth in view space by subtracting the surface depth offset from the linear depth of the splat center.
    *   `depth = linearDepth(gl_FragCoord.z) - depth_offset`
5.  **Sample Surface Depth:** Read the current depth value from the depth buffer at the fragment's screen coordinates.
    *   `tex_coords = gl_FragCoord.xy / viewport_size`
    *   `surface_depth = linearDepth(texture(g_depth, tex_coords).x)`
6.  **Occlusion Test:** Discard the fragment if the splat surface is behind the already-rendered geometry.
    *   If `depth > surface_depth`, discard.
7.  **Calculate Radial Weight ($w_1$):** Compute the falloff based on the distance from the splat center.
    *   `w1 = 1 - (sqrt(mag_sq) / 0.5)`
8.  **Calculate Depth-Proximity Weight ($w_2$):** Compute a weight based on how close the splat surface is to the visible surface. This ensures splats behind the surface contribute less, and splats intersecting the surface contribute proportionally to their intersection depth.
    *   `w2 = (surface_depth - depth) / epsilon`
    *   Where `epsilon` is a small constant, typically `0.25` [S1, unofficial].
9.  **Combine Weights:**
    *   `weight = w1 * w2`
10. **Compute Normal:** Calculate the view-space normal at the fragment's position on the splat sphere.
    *   `normal = normalize(vec3(from_center_wld_spc, depth_offset))`
11. **Accumulate Attributes:** Add the weighted attributes to the G-Buffer. This is an additive accumulation step.
    *   `g_normal.xyz += weight * normal`
    *   `g_color.rgb += weight * i.color`
    *   `g_color.a += weight`

### Pseudocode
```python
# Fragment Shader Logic for Splat Attributes Pass
# Inputs: i.radius (float), i.color (vec3), gl_FragCoord (vec2), g_depth (sampler2D), viewport_size (vec2)
# Outputs: g_normal (vec4), g_color (vec4)
# Constants: epsilon = 0.25

def splat_attributes_pass():
    # 1. Discard Outside Radius
    from_center_pt_spc = gl_PointCoord - vec2(0.5, 0.5)
    mag_sq = dot(from_center_pt_spc, from_center_pt_spc)
    if mag_sq > 0.25:
        discard_fragment()

    # 2. Convert to World Space Offset
    from_center_wld_spc = from_center_pt_spc * 2.0 * i.radius

    # 3. Calculate Depth Offset
    depth_offset = sqrt(i.radius * i.radius - dot(from_center_wld_spc, from_center_wld_spc))

    # 4. Calculate Fragment Depth
    # Note: linearDepth converts normalized device coordinate z to view-space depth
    depth = linearDepth(gl_FragCoord.z) - depth_offset

    # 5. Sample Surface Depth
    tex_coords = gl_FragCoord.xy / viewport_size
    surface_depth = linearDepth(texture(g_depth, tex_coords).x)

    # 6. Occlusion Test
    if depth > surface_depth:
        discard_fragment()

    # 7. Calculate Radial Weight
    w1 = 1.0 - (sqrt(mag_sq) / 0.5)

    # 8. Calculate Depth-Proximity Weight
    w2 = (surface_depth - depth) / epsilon

    # 9. Combine Weights
    weight = w1 * w2

    # 10. Compute Normal
    normal = normalize(vec3(from_center_wld_spc, depth_offset))

    # 11. Accumulate Attributes
    # Using atomicAdd or standard blending depending on G-Buffer format support
    # Assuming standard additive blending for G-Buffer reconstruction
    g_normal.xyz += weight * normal
    g_color.rgb += weight * i.color
    g_color.a += weight
```

### Parameters
*   `epsilon`: A small constant used in the depth-proximity falloff calculation to prevent division by zero and control the sensitivity of the depth test. Typical value: `0.25` [S1, unofficial].

### Edge Cases and Pitfalls
*   **Precision:** The calculation of `depth_offset` involves a square root of a difference of squares. If the fragment is very close to the edge of the splat (`mag_sq` close to `0.25`), floating-point precision errors may result in negative values under the square root. Guard against this by clamping the argument to `sqrt` to be non-negative.
*   **Depth Buffer Format:** The correctness of the occlusion test depends on the depth buffer containing accurate linear view-space depths. If the depth buffer uses normalized device coordinates (NDC) or logarithmic depth, `linearDepth` must be implemented correctly to convert these values.
*   **Alpha Accumulation:** The alpha channel of `g_color` accumulates the sum of weights. This value represents the total "opacity" or coverage of the splats at that pixel. It must be used correctly in subsequent compositing passes to avoid over-brightening or incorrect transparency.

## Subtopics

### Front-to-Back Blending Setup
This configuration sets up the blending state for the accumulation pass. It clears the color buffer to `RGBA(0,0,0,0)` to ensure zero initial alpha. Depth testing is disabled to allow all fragments to be processed regardless of depth order (depth sorting is handled by the logic within the pass or pre-passes). Blending is enabled with separate factors: RGB uses `GL_ONE_MINUS_DST_ALPHA` / `GL_ONE`, and Alpha uses `GL_ONE_MINUS_DST_ALPHA` / `GL_ONE`. The blend equation is `GL_FUNC_ADD` for both RGB and Alpha [S2, unofficial]. This setup ensures that the accumulated color is correctly modulated by the existing alpha in the buffer, which is critical for transparent splat accumulation.

### sRGB to Linear Composite Pass
A full-screen triangle pass that reads an intermediate sRGB-blended splat accumulation texture, converts it to linear space, and outputs for premultiplied alpha blending onto the Scene Color. This pass is necessary because the G-Buffer accumulation (Splat Attributes Pass) typically occurs in linear space, but the final display requires sRGB. The shader parameters include `IntermediateTexture` (Texture2D) and `IntermediateSampler` (SamplerState) [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of fragments generated by the splats. Each fragment performs a constant number of arithmetic operations and texture lookups.
*   **Memory Complexity:** $O(W \times H)$ for the G-Buffer textures, where $W$ and $H$ are the viewport dimensions.
*   **Performance:** The pass is highly parallelizable and runs efficiently on modern GPUs. However, the depth buffer read (`texture(g_depth, ...)`) can cause cache thrashing if the depth buffer is not well-utilized or if the access pattern is random.
*   **Strengths:** Correctly handles occlusion and transparency for spherical splats. Provides continuous attribute reconstruction (normals, colors) suitable for downstream lighting calculations.
*   **Limitations:** The additive accumulation of weights in the alpha channel can lead to values greater than 1.0, which must be handled in subsequent compositing stages. The depth-proximity weight calculation assumes a spherical splat shape; non-spherical splats (e.g., 2D Gaussians) may require different weight calculations.
*   **When to Use:** Use when rendering volumetric data or point clouds with spherical splats where correct occlusion and attribute interpolation are required.
*   **When Not to Use:** Avoid if the splats are strictly opaque and depth-sorted, as a simpler depth-buffered render pass would suffice. Also avoid if the splats are highly non-spherical and the spherical depth offset calculation introduces significant artifacts.

## Background
The Splat Attributes Pass is part of the broader family of object-order volume rendering techniques, specifically those leveraging GPU rasterization pipelines for real-time performance [S1, S2, S3, unofficial]. It builds on the principles of splatting, where volumetric data is decomposed into primitives (splats) that are transformed and rasterized [S1, S3, S4, unofficial]. The specific implementation details, such as the depth-proximity weight and G-Buffer layout, are derived from modern implementations of Gaussian Splatting and point cloud rendering systems [S1, S2, S3, unofficial]. The method addresses the limitations of simple alpha blending by incorporating depth-aware weighting to handle translucent surfaces more accurately.
