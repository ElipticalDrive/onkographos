# Volume Rendering Pipeline

Also called: CRIO Process, Classification, Reflection, Illumination, Opacity, Rendering Stages, Shading and Classification Pipeline, VolumeRenderer forward method

## Overview
The Volume Rendering Pipeline is a conceptual and implementation structure for direct volume rendering that decomposes the image formation process into sequential stages: data traversal, interpolation, gradient computation, classification, shading, and compositing [S1, unofficial]. Unlike splatting methods that fit geometric primitives to the data [S2, S4, unofficial], this pipeline treats each sample point as a semi-transparent cloud that absorbs and emits light, shading samples directly using local gradients as surface normals before projecting them onto the image plane [S2, unofficial]. It is distinct from the Fragment List-Based Rendering Pipeline and Deferred Rendering Pipeline by its explicit separation of optical property assignment (classification) from lighting calculations (shading) prior to the final accumulation step [S1, S2, unofficial].

## How it works
The pipeline processes volumetric data to produce a 2D image. The standard implementation consists of six stages [S1, unofficial].

**Inputs and Outputs**
*   **Input:** A 3D scalar field (voxel database) with values $f_0(\mathbf{x}_i)$ at voxel locations $\mathbf{x}_i = (x_i, y_j, z_k)$ [S3, unofficial]. Camera parameters defining the view.
*   **Output:** A 2D image where each pixel $(u,v)$ has a final color $C_\lambda(u,v)$ and opacity $a(u,v)$ [S3, unofficial].

**Data Structures**
1.  **Voxel Database:** A 3D array storing scalar values.
2.  **Prepared Values Array ($f_1$):** An array of the same dimensions as the input, storing processed scalar values after data preparation [S3, unofficial].
3.  **Color Array ($c_\lambda$):** A 3D array storing RGB colors for each voxel, derived from the shading model [S3, unofficial].
4.  **Opacity Array ($\alpha$):** A 3D array storing opacity values for each voxel, derived from the classification procedure [S3, unofficial].
5.  **Ray Sample Arrays:** Temporary vectors storing interpolated colors $c_\lambda(\tilde{\mathbf{x}}_i)$ and opacities $\alpha(\tilde{\mathbf{x}}_i)$ for $K$ sample locations along a ray [S3, unofficial].

**Numbered Steps**

1.  **Data Traversal and Preparation:**
    The pipeline begins by traversing the 3D scalar field. Depending on the data topology, this may involve correcting for non-orthogonal sampling grids, patient motion, or contrast enhancement [S3, unofficial]. The output is an array of prepared values $f_1(\mathbf{x}_i)$ [S3, unofficial]. [S1, unofficial] notes that traversal depends on the underlying organization of the scalar field and that samples along a light ray form the basis for discretization.

2.  **Shading (Color Calculation):**
    The prepared values $f_1(\mathbf{x}_i)$ are input into a shading model to yield an array of voxel colors $c_\lambda(\mathbf{x}_i)$, where $\lambda \in \{r, g, b\}$ [S3, unofficial]. [S2, unofficial] specifies that surface shading calculations are performed at every voxel using local gradient vectors as surface normals.

3.  **Classification (Opacity Calculation):**
    In a separate step, the prepared values $f_1(\mathbf{x}_i)$ are input into a classification procedure to yield an array of voxel opacities $\alpha(\mathbf{x}_i)$ [S3, unofficial]. [S4, unofficial] describes this as the "CRIO" process (Classification, Reflection, Illumination, Opacity), where discrete values for primary properties (emitted color, reflected color, opacity) are determined based on sample features like density or gradient magnitude. [S2, unofficial] emphasizes that independence between shading and classification ensures undistorted visualization of 3-D shape.

4.  **Gradient Computation:**
    The gradient of the scalar field is computed at sample positions to provide visual cues for directional lighting or Phong shading [S1, unofficial]. This is typically approximated using central differences [S1, unofficial].

5.  **Ray Casting and Resampling:**
    Rays are cast from the observer's eyepoint. For each ray, a vector of sample colors and opacities is computed by resampling the voxel database at $K$ evenly spaced locations $\tilde{\mathbf{x}}_i$ along the ray [S3, unofficial]. The values are obtained by tri-linearly interpolating from the colors and opacities in the eight voxels closest to each sample location $\tilde{\mathbf{x}}_i$ [S3, unofficial].
    *   Parameter $K$: Number of evenly spaced sample locations along a viewing ray [S2, unofficial].

6.  **Compositing:**
    A fully opaque background of color $c_{bkg,\lambda}$ is draped behind the dataset [S3, unofficial]. The resampled colors and opacities are merged with each other and with the background in back-to-front order [S3, unofficial]. The compositing uses the transparency formula:
    $$ C_{out,\lambda}(\tilde{\mathbf{u}}_i) = C_{in,\lambda}(\tilde{\mathbf{u}}_i)(1 - \alpha(\tilde{\mathbf{x}}_i)) + c_\lambda(\tilde{\mathbf{x}}_i)\alpha(\tilde{\mathbf{x}}_i) $$
    where $C_{in}$ is the color of the ray as it enters the sample location and $C_{out}$ is the color as it leaves [S3, unofficial]. This is solved recursively from back to front to yield the final pixel color $C_\lambda(\tilde{\mathbf{u}}_i)$ and opacity $a(\tilde{\mathbf{u}}_i)$ [S3, unofficial].

**Edge Cases and Pitfalls**
*   **Precision:** Tri-linear interpolation assumes linear variation between voxels, which may blur sharp boundaries if the transfer function is non-linear [S1, unofficial].
*   **Boundaries:** The pipeline assumes a fully opaque background behind the dataset; if the volume does not fill the view frustum, artifacts may appear at the edges [S3, unofficial].
*   **Degenerate Input:** Non-orthogonal sampling grids require specific correction during data preparation to avoid geometric distortion [S3, unofficial].

## Subtopics

### [Post-classification Shading Pipeline](7545-post-classification-shading-pipeline.md)
A variant where shading follows immediately after classification. It handles partial voluming differently and is susceptible to blurring at high resolutions compared to pre-classification methods.

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of pixels and the number of samples per ray ($O(W \cdot H \cdot K)$), where $W, H$ are image dimensions and $K$ is the number of samples [S3, unofficial].
*   **Memory Complexity:** Requires storage for the voxel data, plus auxiliary arrays for colors and opacities, typically $O(N)$ where $N$ is the number of voxels [S3, unofficial].
*   **Performance:** The separation of shading and classification allows for independent optimization [S2, unofficial]. However, the need to cast rays and resample data for every pixel can be computationally expensive without hardware acceleration [S2, unofficial].
*   **Strengths:** Independence of shading and classification ensures undistorted visualization of 3-D shape [S2, unofficial]. Non-binary classification operators prevent loss of small or poorly defined features [S2, unofficial].
*   **Limitations:** Susceptible to blurring at high image resolutions in post-classification variants [S1, unofficial]. Requires careful handling of non-orthogonal grids [S3, unofficial].

## Background
The volume rendering pipeline was first reported in June 1987 and presented at the SPIE Medical Imaging II conference in January 1988 [S3, unofficial]. It was developed to display surfaces from sampled scalar functions of three spatial dimensions without fitting geometric primitives [S2, unofficial]. The concept of treating samples as reflective, light-emitting, semi-transparent clouds (CRIO) was further formalized in the context of feed-forward algorithms [S4, unofficial]. The pipeline structure described in [S1, unofficial] generalizes these stages into a common implementation framework.
