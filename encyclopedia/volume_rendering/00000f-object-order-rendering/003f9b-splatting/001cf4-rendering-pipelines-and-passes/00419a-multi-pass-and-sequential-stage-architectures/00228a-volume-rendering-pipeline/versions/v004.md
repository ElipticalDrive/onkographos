# Volume Rendering Pipeline

Also called: CRIO Process, Classification, Reflection, Illumination, Opacity, Rendering Stages, Shading and Classification Pipeline, VolumeRenderer forward method

## Overview
The Volume Rendering Pipeline is a conceptual and implementation structure that decomposes the rendering of 3D scalar fields into distinct, sequential stages to discretize the continuous volume rendering integral [S1, unofficial]. It solves the problem of mapping volumetric data to a 2D image by treating each sample point as a semi-transparent, light-emitting, and reflective cloud [S4, unofficial]. Unlike methods that fit geometric primitives to the data, this pipeline directly shades samples and projects them onto the picture plane, using local gradient vectors as surface normals for shading and separate classification operators for opacity [S2, unofficial]. It sets itself apart from sibling pipelines by explicitly decoupling attribute computation (shading/classification) from the final geometric projection and accumulation (compositing), allowing for independent optimization of visual appearance and depth handling [S3, unofficial].

## How it works
The pipeline processes data through a sequence of stages. While implementations vary, the canonical structure consists of six stages: Data Traversal, Interpolation, Gradient Computation, Classification, Shading/Illumination, and Compositing [S1, unofficial].

### Inputs and Outputs
*   **Input:** A 3D scalar field (voxel database) with acquired values $f_0(x_i)$ at voxel locations $x_i = (x_i, y_j, z_k)$ [S3, unofficial].
*   **Output:** A 2D image where each pixel $(u, v)$ has a final color $C_\lambda(u, v)$ and opacity $\alpha(u, v)$ [S3, unofficial].

### Data Structures
*   **Voxel Database:** A 3D array storing scalar values.
*   **Prepared Values Array ($f_1$):** An array of the same dimensions as the input, storing processed scalar values after data preparation [S3, unofficial].
*   **Color Array ($c_\lambda$):** A 3D array storing RGB colors for each voxel, derived from the shading model [S3, unofficial].
*   **Opacity Array ($\alpha$):** A 3D array storing opacity values for each voxel, derived from the classification procedure [S3, unofficial].
*   **Ray Bundle:** A collection of rays defined by origin and direction, typically one per pixel [S5, unofficial].

### Numbered Steps

1.  **Data Preparation/Traversal:**
    The pipeline begins by traversing the 3D scalar field. This step may include corrections for non-orthogonal sampling grids, patient motion, contrast enhancement, or interpolation of additional samples [S3, unofficial]. The output is an array of prepared values $f_1(x_i)$ [S3, unofficial]. In object-order or splatting contexts, this involves determining the spatial footprint of samples [S4, unofficial].

2.  **Shading (Color Computation):**
    The prepared values $f_1(x_i)$ are input into a shading model to yield an array of voxel colors $c_\lambda(x_i)$, where $\lambda \in \{r, g, b\}$ [S3, unofficial]. This step calculates the emitted and reflected color components.

3.  **Classification (Opacity Computation):**
    In a separate step, the prepared values $f_1(x_i)$ are input into a classification procedure to yield an array of voxel opacities $\alpha(x_i)$ [S3, unofficial]. Classification maps scalar properties to optical properties (emitted color, reflected color, opacity) based on features like density or gradient magnitude [S4, unofficial]. This independence ensures undistorted visualization of 3D shape [S2, unofficial].

4.  **Gradient Computation:**
    The gradient of the scalar field is computed at sample positions to add visual cues, enabling directional lighting or Phong shading [S1, unofficial]. This is typically approximated by central differences [S1, unofficial]. The gradient vector serves as the surface normal for shading calculations [S2, unofficial].

5.  **Ray Casting and Resampling:**
    Rays are cast from the observer eyepoint into the color and opacity arrays [S3, unofficial]. For each ray, a vector of sample colors $c_\lambda(\tilde{x}_i)$ and opacities $\alpha(\tilde{x}_i)$ is computed by resampling the voxel database at $K$ evenly spaced locations $\tilde{x}_i$ along the ray [S3, unofficial]. The values are obtained by tri-linearly interpolating from the colors and opacities in the eight voxels closest to each sample location $\tilde{x}_i$ [S3, unofficial].

6.  **Compositing:**
    A fully opaque background of color $c_{bkg, \lambda}$ is draped behind the dataset [S3, unofficial]. The resampled colors and opacities are merged with each other and with the background in back-to-front order to yield a single color $C_\lambda(\tilde{u}_i)$ for the ray/pixel [S3, unofficial].

### Formulas

**Transparency Formula (Compositing):**
The color $C_{out, \lambda}(\tilde{u}_i)$ of the ray as it leaves a sample location is related to the color $C_{in, \lambda}(\tilde{u}_i)$ as it enters, the sample color $c_\lambda(\tilde{x}_i)$, and the sample opacity $\alpha(\tilde{x}_i)$ by:

$$
C_{out, \lambda}(\tilde{u}_i) = C_{in, \lambda}(\tilde{u}_i)(1 - \alpha(\tilde{x}_i)) + c_\lambda(\tilde{x}_i)\alpha(\tilde{x}_i)
$$

Where:
*   $C_{in, \lambda}$: Incoming ray color (initially the background color $c_{bkg, \lambda}$).
*   $c_\lambda(\tilde{x}_i)$: Sample color at location $\tilde{x}_i$.
*   $\alpha(\tilde{x}_i)$: Sample opacity at location $\tilde{x}_i$.

**Final Pixel Color:**
Solving the recursive transparency formula for the pixel color $C_\lambda(\tilde{u}_i)$ involves accumulating contributions from all $K$ samples along the ray from back to front [S3, unofficial].

### Parameters
*   **$K$:** Number of evenly spaced sample locations along a viewing ray [S3, unofficial].
*   **Primary Properties:** Emitted color, reflected color, and opacity [S4, unofficial].

### Pseudocode

```python
def volume_rendering_pipeline(voxel_data, camera, image_width, image_height, num_samples_per_ray):
    """
    Implements the canonical Volume Rendering Pipeline.
    
    Args:
        voxel_data: 3D array of scalar values f0(xi).
        camera: Camera object with projection and view matrices.
        image_width: Width of the output image.
        image_height: Height of the output image.
        num_samples_per_ray: K, number of samples per ray.
        
    Returns:
        final_color: 2D array of RGB colors.
        final_opacity: 2D array of opacity values.
    """
    
    # Stage 1: Data Preparation / Traversal
    # Corrects for grid issues, motion, etc.
    prepared_values = prepare_data(voxel_data)
    
    # Stage 2: Shading (Color Computation)
    # Computes voxel colors based on shading model
    voxel_colors = compute_shading(prepared_values)
    
    # Stage 3: Classification (Opacity Computation)
    # Computes voxel opacities based on classification procedure
    voxel_opacities = compute_classification(prepared_values)
    
    # Stage 4: Gradient Computation (for shading)
    # Computes gradients for lighting calculations
    gradients = compute_gradients(prepared_values)
    
    # Stage 5 & 6: Ray Casting, Resampling, and Compositing
    final_color = np.zeros((image_height, image_width, 3))
    final_opacity = np.zeros((image_height, image_width))
    
    for y in range(image_height):
        for x in range(image_width):
            # Cast ray from eyepoint through pixel (x, y)
            ray = camera.get_ray(x, y)
            
            # Initialize compositing state
            # Background is fully opaque
            current_color = np.array([1.0, 1.0, 1.0]) # Example background color
            current_opacity = 1.0
            
            # Resample along ray
            for k in range(num_samples_per_ray):
                # Compute sample location along ray
                sample_pos = ray.origin + ray.direction * (k * ray.step_size)
                
                # Tri-linear interpolation from voxel database
                # Interpolate from colors and opacities in 8 closest voxels
                sample_color = tri_linear_interpolate(voxel_colors, sample_pos)
                sample_opacity = tri_linear_interpolate(voxel_opacities, sample_pos)
                
                # Apply transparency formula
                # Cout = Cin * (1 - alpha) + c * alpha
                contribution = sample_color * sample_opacity
                current_color = current_color * (1 - sample_opacity) + contribution
                current_opacity = current_opacity * (1 - sample_opacity)
                
                # Early ray termination optimization [G]
                if current_opacity < 0.001:
                    break
            
            final_color[y, x] = current_color
            final_opacity[y, x] = 1.0 - current_opacity # Total opacity is 1 - transmittance
            
    return final_color, final_opacity

def compute_shading(prepared_values):
    """
    Computes voxel colors using shading model and gradients.
    """
    gradients = compute_gradients(prepared_values)
    colors = np.zeros_like(prepared_values)
    # [G] Shading model (e.g., Phong) uses gradients as normals
    for i in range(prepared_values.shape[0]):
        for j in range(prepared_values.shape[1]):

def compute_gradients(prepared_values):
    """
    Computes gradients using central differences.
    """
    gradients = np.zeros_like(prepared_values)
    # [G] Central difference approximation
    gradients[1:-1, 1:-1, 1:-1] = (
        prepared_values[2:, 1:-1, 1:-1] - prepared_values[:-2, 1:-1, 1:-1] +
        prepared_values[1:-1, 2:, 1:-1] - prepared_values[1:-1, :-2, 1:-1] +
        prepared_values[1:-1, 1:-1, 2:] - prepared_values[1:-1, 1:-1, :-2]
    ) / 2.0
    return gradients

def tri_linear_interpolate(data, pos):
    """
    Tri-linearly interpolates value at pos from 3D data array.
    """
    # [G] Standard tri-linear interpolation implementation
    # Extract fractional coordinates
    x, y, z = pos
    ix, iy, iz = int(x), int(y), int(z)
    fx, fy, fz = x - ix, y - iy, z - iz
    
    # Get 8 surrounding voxels

    v100 = data[ix+1, iy, iz]
    v010 = data[ix, iy+1, iz]
    v110 = data[ix+1, iy+1, iz]
    v001 = data[ix, iy, iz+1]

    c1 = lerp(c01, c11, fy)
```

### Edge Cases and Pitfalls
*   **Precision:** Tri-linear interpolation and compositing are sensitive to floating-point precision, especially with large dynamic ranges in opacity [S3, unofficial].
*   **Boundaries:** Interpolation at the edges of the voxel grid requires handling out-of-bounds accesses, typically by clamping or mirroring [S3, unofficial].
*   **Degenerate Input:** Non-orthogonal sampling grids or missing data require specific correction steps during data preparation [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot K)$, where $N$ is the number of pixels and $K$ is the number of samples per ray [S3, unofficial].
*   **Memory Complexity:** $O(V)$, where $V$ is the number of voxels, for storing the voxel database and intermediate arrays [S3, unofficial].
*   **Measured Performance:** Performance depends heavily on the hardware and resolution. GPU implementations can achieve real-time rates for moderate resolutions [S5, unofficial].
*   **Scaling:** Scales well with parallelization on GPUs [S4, unofficial].
*   **Strengths:** Flexibility in shading and classification; independence of shading and classification allows for undistorted visualization [S2, unofficial].
*   **Limitations:** Computationally expensive for high-resolution volumes or large $K$; requires careful handling of occlusion and depth [S3, unofficial].
*   **When to Use:** Suitable for high-quality offline rendering or real-time applications with moderate resolution requirements [S1, unofficial].
*   **When Not to Use:** Not suitable for very large volumes with strict real-time constraints without optimization [S1, unofficial].

## Background
The Volume Rendering Pipeline was introduced by Williams et al. in 1988, presenting a method for rendering surfaces from volume data without fitting geometric primitives [S2, unofficial][S3, unofficial]. The pipeline was presented at the SPIE Medical Imaging II conference in January 1988 [S3, unofficial]. It has since become a foundational concept in volume rendering, influencing various implementations and optimizations [S1, unofficial]. The term "CRIO Process" (Classification, Reflection, Illumination, Opacity) was coined by Westover in 1991 to describe the feed-forward nature of the algorithm [S4, unofficial].
