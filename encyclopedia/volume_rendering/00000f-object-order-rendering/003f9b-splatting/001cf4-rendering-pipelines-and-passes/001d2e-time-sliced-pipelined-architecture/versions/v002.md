# Time-Sliced Pipelined Architecture

Also called: Multi-core time-sliced pipeline, Time-slicing

## Overview
A hardware architecture for volume rendering where functional blocks are time-sliced to allow simultaneous processing of multiple tasks, enabling real-time rendering and continuous hardware-software communication [S1, unofficial]. It differs from standard linear pipelines by overlapping execution stages across independent sub-cores, allowing a single physical component to serve multiple logical stages or tasks [S1, unofficial].

## How it works
The architecture decomposes the rendering pipeline into independent, reusable functional blocks (sub-cores) that are configured or replicated based on processing requirements [S1, unofficial].

**Inputs and Outputs:** Input consists of incoming voxel data and transformation parameters; output is the final pixel values [S1, unofficial].

**Data Structures:** Context RAM stores intermediate results (e.g., dot products) for several clock cycles to be accessed by other components [S1, unofficial]. Normal mode registers and a context address snooping mechanism provide a common interface for component communication [S1, unofficial].

**Functional Blocks:** The pipeline is divided into the classifier, gradient calculator, shearing-warping block (shearer-composer), shader (shading processor), and composer [S1, unofficial].

**Steps:**
1. Decompose the rendering pipeline into the functional blocks listed above [S1, unofficial].
2. Implement each block as an independent reusable component or sub-core composed of basic units like multipliers, adders, or inner product processors [S1, unofficial].
3. Configure or replicate the embedded sub-core based on the required processing type to execute a specific operation [S1, unofficial].
4. Use time-slicing to overlap execution stages, allowing simultaneous processing of several tasks [S1, unofficial].
5. Route communication through the common interface (Context RAM, normal mode registers, and context address snooping), where computed values like dot products are stored in RAM cells and retrieved by other components in subsequent cycles [S1, unofficial].

**Pitfalls:** Not given in the sources.

## Subtopics

### Vg500 Parallel Pipeline Architecture
The vg500 chip architecture uses four parallel rendering pipelines to achieve real-time rendering rates by processing adjacent voxel or sample values in the x-direction [S2, unofficial]. Each pipeline is connected to its neighbor by shift registers in each major unit, providing values to neighbors in the same cycle [S2, unofficial]. The shift registers of the rightmost pipeline recirculate values needed in the next cycle and send them to the leftmost pipeline [S2, unofficial]. The chip runs at a 133 MHz clock frequency, with each pipeline accepting a new voxel every cycle [S2, unofficial]. An off-chip Voxel Memory supplies data to all pipelines, and they write pixel values to an off-chip Pixel Memory [S2, unofficial].

## Operating characteristics
- **Time Complexity:** The architecture enables real-time rendering by overlapping tasks [S1, unofficial]. For the vg500 variant, four pipelines operating at 133 MHz process approximately 532 million voxels per second, sufficient for rendering a $256^3$ dataset at 30 frames per second [S2, unofficial].
- **Memory Complexity:** Requires Context RAM for intermediate storage and off-chip Voxel/Pixel Memory [S1, unofficial][S2, unofficial]. The vg500 chip includes 2 Mbits of on-chip SRAM [S2, unofficial].
- **Strengths:** Component reusability simplifies layout; time-slicing allows simultaneous processing of multiple tasks; continuous hardware-software communication supports interactive user interfaces [S1, unofficial].
- **Limitations:** Complexity in managing context switching and inter-pipeline communication (e.g., shift register recirculation) [S1, unofficial][S2, unofficial].

## Background
The time-sliced pipelined architecture was developed as part of the Shear-warp factorization volume rendering visualization system (VRS) [S1, unofficial]. It was designed to provide real-time rendering capabilities by leveraging component reusability and multi-core structures [S1, unofficial]. The vg500 chip, an ASIC implementation of this architecture, was developed for the VolumePro real-time ray-casting system [S2, unofficial].
