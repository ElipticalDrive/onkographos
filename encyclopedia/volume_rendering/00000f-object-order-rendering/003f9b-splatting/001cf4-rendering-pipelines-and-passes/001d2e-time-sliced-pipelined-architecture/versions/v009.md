# Time-Sliced Pipelined Architecture

Also called: Multi-core time-sliced pipeline, Time-slicing

## Overview
The Time-Sliced Pipelined Architecture is a hardware design methodology for volume rendering systems that achieves real-time performance by overlapping the execution of distinct pipeline stages through time-slicing [S1, unofficial]. It solves the bottleneck of sequential processing in traditional volume rendering pipelines by allowing multiple tasks to be processed simultaneously on shared or replicated functional blocks [S1, unofficial]. Unlike general-purpose DSP-based solutions that require multiple chips for similar volumes, this architecture integrates the rendering pipeline into a unified multi-core structure, enabling continuous hardware-software communication and interactive frame rates [S1, unofficial].

## How it works
The architecture decomposes the volume rendering pipeline into independent functional blocks that are configured or replicated as sub-cores based on processing requirements [S1, unofficial].

**Inputs and Outputs:**
*   **Input:** Volumetric data (voxels), transformation matrices (Model-View-Projection), and rendering parameters (opacity, shading models).
*   **Output:** Final rendered image frame.

**Data Structures:**
*   **Context Memory:** A shared RAM structure used for inter-component communication. It stores intermediate results (e.g., dot products) for several clock cycles so they can be accessed by other components [S1, unofficial].
*   **Normal Mode Registers:** Provide a common interface for components to access context memory [S1, unofficial].
*   **Context Address Snooping Mechanism:** Allows components to monitor and access stored information in the context memory [S1, unofficial].
*   **Sub-cores:** Basic functional blocks (multipliers, adders, inner product processors) that are physically considered as sub-cores. They are configured or replicated to execute specific operations [S1, unofficial].

**Numbered Steps:**
1.  **Pipeline Decomposition:** Divide the rendering pipeline into functional blocks: classifier, gradient calculator, shearing-warping block, shader, and composer [S1, unofficial].
2.  **Component Implementation:** Implement these blocks as independent, reusable components/sub-cores. The gradient calculator, shearer-composer, shading processor, and matrix multiplication processor are composed from basic functional blocks like multipliers, adders, or inner product processors [S1, unofficial].
3.  **Configuration/Replication:** Based on the type of processing required by the calling module, the embedded sub-core is configured or replicated to execute a specific operation [S1, unofficial].
4.  **Time-Sliced Execution:** Use time-slicing to overlap execution stages. This allows the simultaneous processing of several tasks, such as calculating a dot product for a voxel in the classifier and using that same value in the shader and composer within the same time frame [S1, unofficial].
5.  **Inter-Component Communication:** Components communicate via the common interface provided by context RAM, normal mode registers, and the context address snooping mechanism. Calculated values (e.g., dot products) are stored in corresponding RAM cells to be called up by another component [S1, unofficial].

## Subtopics

### [Vg500 Parallel Pipeline Architecture](2072-vg500-parallel-pipeline-architecture.md)
The Vg500 Parallel Pipeline Architecture is a highly parallel, template-based ray-casting hardware accelerator implemented as the vg500 ASIC for the VolumePro system. It solves the real-time rendering bottleneck by distributing the processing of adjacent voxel samples across four identical pipelines operating in parallel. Unlike general-purpose DSP-based solutions like VIRIM, which require multiple chips and lower frame rates for similar volumes, the Vg500 integrates the entire rendering pipeline into a single ASIC, enabling real-time frame rates for large datasets. It builds on the Time-Sliced Pipelined Architecture by utilizing fixed-function hardware units for interpolation, shading, and compositing.

## Background
The Time-Sliced Pipelined Architecture was developed as part of the Shear-warp factorization volume rendering visualization system (SWE) [S1, unofficial]. It was designed to provide real-time rendering capabilities by implementing a multi-core structure compliant with the rendering pipeline [S1, unofficial]. The architecture emphasizes component reusability and hierarchical design to simplify layout and improve efficiency [S1, unofficial]. It is used in systems like the VolumePro, where the Vg500 ASIC implements a similar pipelined approach [S1, unofficial].
