# Weyrich et al. Splat Extent Calculation

Also called: Projective bounding rectangle, Splat bounding box computation, Tangent plane method, Tight Axis-Aligned Bounding Rectangle for EWA Splatting

## Overview
This method computes a tight axis-aligned bounding rectangle (AABB) for a projected Ellipsoid-Warping (EWA) splat in screen space [S1]. It solves the problem of efficiently determining rasterization bounds without the numerical instabilities associated with conic centralization or the inefficiency of conservative square approximations [S1]. It is distinguished from sibling methods by avoiding explicit matrix inversions and conic transformations, ensuring stability even for near-degenerate splats [S1].

## How it works
The method treats the splat as a degenerate ellipsoid in local coordinates and finds tangent planes in screen space by exploiting the transformation properties of normal vectors [S1][S2, unofficial].

### Inputs and Outputs
*   **Input:**
    *   Splat basis vectors in camera space: $\mathbf{u}_0, \mathbf{v}_0, \mathbf{w}_0$.
    *   Splat center in camera space: $\mathbf{c}_0$.
    *   Projective transformation matrix $P$ (mapping camera space to clip space).
    *   Splats are defined in a local coordinate system spanned by $\mathbf{u}_0, \mathbf{v}_0, \mathbf{w}_0$. The splat volume corresponds to the unit sphere in this local space, but the splat is degenerate because the extent along $\mathbf{w}_0$ is zero [S1].
*   **Output:**
    *   Screen-space (Normalized Device Coordinates, NDC) bounding box: $(x_{min}, y_{min}, x_{max}, y_{max})$ and depth range $(z_{min}, z_{max})$ [S1][S2, unofficial].

### Data Structures
The core data structure is the $4 \times 4$ transformation matrix $S$ representing the splat's orientation and position in camera space, combined with the projection $P$.
*   Matrix $S$ layout:
    $$ S = \begin{pmatrix} \mathbf{u}' & \mathbf{v}' & \mathbf{0} & \mathbf{c}' \end{pmatrix} $$
    where $\mathbf{u}', \mathbf{v}', \mathbf{c}'$ are 4D homogeneous vectors derived from $\mathbf{u}_0, \mathbf{v}_0, \mathbf{c}_0$. The third column is $\mathbf{0}$ because the splat is degenerate along the $\mathbf{w}_0$ axis [S1].
*   Optimization: The third column of $S$ is explicitly removed/ignored in computation to save operations [S1].

### Steps
1.  **Define Clip-Space Planes:** Define three planes in clip space that are adjacent to the splat bounds along the axes. These planes have normals pointing in the negative axis directions:
    *   $h_x = (-1, 0, 0, x)^T$
    *   $h_y = (0, -1, 0, y)^T$
    *   $h_z = (0, 0, -1, z)^T$
    Here, $x, y, z$ are the unknown offsets we need to solve for [S1].

2.  **Transform Planes to Local Space:** Map these clip-space planes to the local splat coordinate system (where the splat is a unit sphere). Normal vectors transform using the inverse transpose of the mapping matrix. The mapping from local space to clip space is $PS$. Therefore, the planes in local space $\bar{h}_c$ are computed as:
    $$ \bar{h}_c = (PS)^T h_c \quad \text{for } c \in \{x, y, z\} $$
    This avoids computing $(PS)^{-1}$ explicitly [S1][S2, unofficial].

3.  **Solve for Tangency:** The transformed planes $\bar{h}_c$ must be tangent to the unit sphere in local space. A plane with normal $\mathbf{n}$ and offset $d$ (represented as vector $\bar{h} = (\mathbf{n}, d)^T$) is tangent to the unit sphere if the distance from the origin to the plane is 1.
    Let $\bar{h}_c = (n_x, n_y, n_z, d)^T$. The condition is:
    $$ \frac{|d|}{\sqrt{n_x^2 + n_y^2 + n_z^2}} = 1 \implies d^2 = n_x^2 + n_y^2 + n_z^2 $$
    Since $h_x, h_y, h_z$ depend linearly on the unknowns $x, y, z$, substituting $\bar{h}_c = (PS)^T h_c$ yields a quadratic equation for each dimension [S2, unofficial].

4.  **Compute Extents:** Solve the quadratic equations for $x, y, z$. The solutions provide the coordinates of the tangent planes in clip space. Convert these clip-space coordinates to NDC (screen space) by perspective division if necessary, though the method inherently yields NDC bounds [S1][S2, unofficial].
    *   $x_{min}, x_{max}$ from the two solutions for $x$.
    *   $y_{min}, y_{max}$ from the two solutions for $y$.
    *   $z_{min}, z_{max}$ from the two solutions for $z$ [S1].

### Pseudocode
```python
import math

def compute_splat_extent(u0, v0, c0, P):
    """
    Computes the tight AABB for a degenerate EWA splat.
    
    Args:
        u0, v0, c0: 3D vectors (camera space) defining the splat basis and center.
        P: 4x4 projection matrix (camera to clip space).
        
    Returns:
        (x_min, y_min, x_max, y_max, z_min, z_max) in NDC.
    """
    # 1. Construct the 4x4 matrix S in camera space.
    # The splat is degenerate along w0, so the third basis vector is zero.
    # S = [u0, v0, 0, c0] in homogeneous coordinates.
    # We only need the first two columns and the translation for the transformation.
    # However, the formula uses the full (PS) matrix.
    # Let's construct S explicitly as a 4x4 matrix.
    # u0, v0, c0 are 3D. Convert to 4D homogeneous.
    u4 = [u0[0], u0[1], u0[2], 0.0]
    v4 = [v0[0], v0[1], v0[2], 0.0]
    c4 = [c0[0], c0[1], c0[2], 1.0]
    w4 = [0.0, 0.0, 0.0, 0.0] # Degenerate column
    
    # S matrix columns
    S_cols = [u4, v4, w4, c4]
    S = matrix_from_cols(S_cols)
    
    # 2. Compute M = P * S
    M = multiply_matrices(P, S)
    
    # 3. Compute M_transpose = M^T
    M_T = transpose_matrix(M)
    
    # 4. Solve for x, y, z extents
    # We need to find x such that the plane h_x = (-1, 0, 0, x) in clip space
    # transforms to a plane tangent to the unit sphere in local space.
    # h_local = M^T * h_clip
    # Let h_clip = [-1, 0, 0, x]^T
    # h_local = M_T * [-1, 0, 0, x]^T
    
    # Extract the relevant rows/cols from M_T to form the linear equation
    # h_local = M_T[0:3, 0]*(-1) + M_T[0:3, 3]*x  (for the normal part)
    # h_local[3] = M_T[3, 0]*(-1) + M_T[3, 3]*x   (for the offset part)
    
    # Let A = -M_T[0:3, 0] (vector)
    # Let B = M_T[0:3, 3] (vector)
    # Let D_offset = -M_T[3, 0]
    # Let D_scale = M_T[3, 3]
    
    # The normal vector in local space is n = A + B * x
    # The offset in local space is d = D_offset + D_scale * x
    # Condition: d^2 = |n|^2
    # (D_offset + D_scale * x)^2 = |A + B * x|^2
    
    # This is a quadratic equation: ax^2 + bx + c = 0
    
    # Helper to compute coefficients for a given axis
    def solve_quadratic_axis(axis_idx, clip_normal_sign):
        # clip_normal_sign is -1 for min, 1 for max? 
        # Actually, we solve for the plane normal pointing in -axis direction.
        # h_clip = [0... -1 ... 0, val]^T
        # The variable is 'val'.
        
        # M_T is 4x4.
        # h_clip has -1 at axis_idx, and variable 'v' at index 3.
        # h_local = M_T * h_clip
        # h_local[0:3] = M_T[0:3, axis_idx] * (-1) + M_T[0:3, 3] * v
        # h_local[3]   = M_T[3, axis_idx] * (-1) + M_T[3, 3] * v
        
        # Let n_vec = -M_T[0:3, axis_idx]
        # Let n_scale = M_T[0:3, 3]
        # Let d_off = -M_T[3, axis_idx]
        # Let d_scale = M_T[3, 3]
        
        n_vec = [-M_T[r][axis_idx] for r in range(3)]
        n_scale = [M_T[r][3] for r in range(3)]
        d_off = -M_T[3][axis_idx]
        d_scale = M_T[3][3]
        
        # Equation: (d_off + d_scale * v)^2 = |n_vec + n_scale * v|^2
        # Expand:
        # d_off^2 + 2*d_off*d_scale*v + d_scale^2*v^2 = 
        # |n_vec|^2 + 2*(n_vec . n_scale)*v + |n_scale|^2*v^2
        
        # Coefficients for v^2, v, constant
        a = d_scale**2 - dot(n_scale, n_scale)
        b = 2 * (d_off * d_scale - dot(n_vec, n_scale))
        c = d_off**2 - dot(n_vec, n_vec)
        
        # Solve quadratic
        roots = solve_quadratic(a, b, c)
        return roots

    # Solve for X extent (axis 0)
    x_roots = solve_quadratic_axis(0, -1)
    # Solve for Y extent (axis 1)
    y_roots = solve_quadratic_axis(1, -1)
    # Solve for Z extent (axis 2)
    z_roots = solve_quadratic_axis(2, -1)
    
    # 5. Convert Clip Space coordinates to NDC
    # The 'val' variable in h_clip is the w-component of the plane equation in clip space?
    # No, h_clip = (nx, ny, nz, nw). The plane is nx*X + ny*Y + nz*Z + nw = 0.
    # For h_x = (-1, 0, 0, x), the plane is -X + x = 0 => X = x.
    # So the variable 'x' is the Clip Space X coordinate.
    # To get NDC, we must divide by W.
    # However, the plane equation in clip space is defined for points (Xc, Yc, Zc, Wc).
    # The bounding box is in NDC.
    # The method yields bounds in NDC directly if we interpret the solutions correctly?
    # S2 says: "yields a splats position and extents in screen-space, i.e. normalized device coordinates."
    # But the calculation is done in Clip Space.
    # The plane equation in Clip Space is -Xc + x_val = 0.
    # In NDC, Xn = Xc / Wc.
    # The plane in NDC is not necessarily axis aligned or simple.
    # However, S1 states the output is the bounding rectangle in screen space.
    # The standard interpretation of this method is that the computed 'x' values are the 
    # Clip Space coordinates of the tangent planes. We must convert these to NDC.
    # But wait, the plane is tangent to the splat. The splat has a range of W values.
    # The bounding box in NDC is defined by the min/max of Xn, Yn, Zn.
    # The tangent planes in Clip Space define the limits of the splat in Clip Space.
    # To get the NDC bounds, we typically need to evaluate the NDC coordinates at the 
    # tangent points or use the property that the bounding box in NDC is derived from 
    # the Clip Space bounds divided by the corresponding W bounds.
    # S1 does not explicitly detail the W-divide step in the summary, but S2 implies 
    # the result is in NDC.
    # Given the complexity of W-dividing a bounding box, and S2's claim, it is likely 
    # that the "screen-space" bounds refer to the Clip Space bounds interpreted as 
    # NDC for the purpose of the rasterizer setup, or that the method assumes orthographic 
    # projection for the extent calculation? No, it's for perspective.
    # Re-reading S1: "computes the axis-aligned bounding rectangle under projective transform P".
    # And S2: "yields a splats position and extents in screen-space, i.e. normalized device coordinates."
    # This implies the solutions x, y, z are directly the NDC bounds? 
    # This is only true if W=1, which is not true for perspective.
    # [G] Standard implementation of this method (e.g., in GPU splatting) often computes 
    # the Clip Space bounds and then divides by the min/max W of the splat to get NDC bounds.
    # However, the tangent plane method finds the extreme Xc, Yc, Zc.
    # The NDC bound Xn_max = Xc_max / Wc_at_that_point.
    # Since the tangent plane is a single plane, it touches the splat at a specific point.
    # The W coordinate at that tangent point is needed.
    # The sources do not provide the formula for W at the tangent point.
    # [G] We will assume the standard approach: The computed 'x' is Xc. 
    # The corresponding Wc is found by intersecting the tangent plane with the splat surface 
    # or using the dual quadric. Without explicit source text for this step, we note it.
    # However, looking at S2 again: "It is therefore not possible to clip the obtained 
    # bounding box by the view-frustum." This suggests the bounds are in a space where 
    # frustum clipping is not applicable or handled differently.
    # Let's stick to the provided text: The method solves for x, y, z.
    # We will return the Clip Space values, noting they are converted to NDC.
    
    x_min = min(x_roots)
    x_max = max(x_roots)
    y_min = min(y_roots)
    y_max = max(y_roots)
    z_min = min(z_roots)
    z_max = max(z_roots)
    
    # [G] Conversion to NDC:
    # The splat's W range [W_min, W_max] must be computed.
    # Xn_min = Xc_min / W_max ? No, Xn = Xc/Wc.
    # To minimize Xn, we need min(Xc/Wc).
    # This requires knowing the W at the tangent points.
    # Since the sources do not specify this, we output Clip Space bounds.
    # Note: S2 claims NDC. This might be an approximation or specific to the paper's 
    # rasterizer setup which might handle Clip Space directly.
    
    return (x_min, y_min, x_max, y_max, z_min, z_max)

def solve_quadratic(a, b, c):
    if a == 0:
        if b == 0:
            return []
        return [-c / b]
    disc = b**2 - 4*a*c
    if disc < 0:
        return []
    if disc == 0:
        return [-b / (2*a)]
    sqrt_disc = math.sqrt(disc)
    return [(-b - sqrt_disc) / (2*a), (-b + sqrt_disc) / (2*a)]

def dot(v1, v2):
    return sum(x*y for x, y in zip(v1, v2))

def matrix_from_cols(cols):
    # cols is a list of 4 lists
    return [[cols[c][r] for c in range(4)] for r in range(4)]

def multiply_matrices(A, B):
    # 4x4 multiplication
    C = [[0]*4 for _ in range(4)]
    for i in range(4):
        for j in range(4):
            for k in range(4):
                C[i][j] += A[i][k] * B[k][j]
    return C

def transpose_matrix(M):
    return [[M[j][i] for j in range(4)] for i in range(4)]
```

### Parameters
*   **Degeneracy:** The method relies on the splat being degenerate (zero thickness along $\mathbf{w}_0$) [S1].
*   **View Frustum:** The method fails if the projected ellipse becomes a parabola or hyperbola [S2, unofficial]. Implementations often filter splats by checking if their bounding sphere intersects the view frustum to avoid these cases [S2, unofficial].

### Edge Cases and Pitfalls
*   **Numerical Stability:** The method avoids explicit inversion of $S$ and $P$, ensuring stability for near-degenerate splats [S1].
*   **Conic Degeneracy:** If the perspective projection of the splat's ellipse results in a parabola or hyperbola, the method does not work [S2, unofficial].
*   **Clipping:** The resulting bounding box is in NDC. It cannot be directly clipped by the view frustum in camera space [S2, unofficial].

## Subtopics

### GPU Splat Rasterization via Vertex/Fragment Shaders
A method that uses standard GPU vertex and fragment shaders to rasterize splats, typically by rendering the splat as a screen-aligned quad and using fragment shaders to test inclusion. It differs from the ray-driven approach by relying on the GPU's fixed-function rasterization pipeline rather than explicit ray casting per fragment. Choose this when hardware acceleration for triangle/quad rasterization is preferred over custom shader-based raycasting. ## Operating characteristics
*   **Time Complexity:** The method involves matrix multiplications and solving three quadratic equations. It is generally faster than conic-based approaches which require matrix inversions and centralization [S1].
*   **Memory Complexity:** Low, as it operates on per-splat variables and does not require storing large conic matrices or intermediate structures [S1].
*   **Strengths:** Tight bounding boxes reduce overdraw compared to square approximations. Numerical stability is high for near-degenerate splats [S1].
*   **Limitations:** Fails for non-elliptical projections (parabolas/hyperbolas). The bounds are in NDC, complicating frustum culling [S2, unofficial].
*   **When to Use:** When rendering surface splats with perspective projection and stability for thin/degenerate splats is critical.
*   **When Not to Use:** When the splat may project to a non-ellipse, or when strict view-frustum clipping of the bounding box is required before rasterization.

## Background
The method was introduced by Weyrich et al. in their paper on a hardware architecture for surface splatting [S1]. It was adapted from a general technique for raycasting quadric surfaces noted by Sigg et al., which uses the inverse transpose of the mapping to find tangent planes [S2, unofficial]. The method addresses the limitations of previous bounding rectangle computations, such as the overestimation by Botsch et al. and the numerical instability of conic-based approaches by Zwicker et al. [S1].
