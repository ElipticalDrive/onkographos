# Voxel Point Sprite Rendering

Also called: Draw Points Pass, GL_POINTS voxel rendering, OpenGL Voxel Splatting, Point-based Voxel Rendering, Rendering with Point Sprites and Kernel Footprints, Voxel Splatting, Voxel shader

## Overview
Voxel Point Sprite Rendering is a technique that stores voxels as points (splatting) in a buffer and renders them using a geometry shader or point sprites, allowing for mipmapped voxel data to be drawn as points with a specific scale [S4, unofficial]. It visualizes voxels as points with size and color based on solidity [S2, unofficial]. The method reduces vertex traffic by using the `glPoint` primitive with the Point Sprites extension to create automatic quads, reducing vertex traffic from four to one [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A voxel grid defined by dimensions $width \times height \times depth$ (default 200x50x200 in [S3, unofficial] or 4x4x4 cubes in [S4, unofficial]). Each voxel contains position and color/albedo data [S3, unofficial].
*   **Output:** A rendered image where voxels are drawn as point sprites, with size and LOD determined by camera distance [S4, unofficial].

**Data Structures:**
Two distinct packing layouts are cited in the sources:
1.  **Layout A (Source [S3, unofficial]):** Voxel data is packed into pairs of `uint32_t`.
    *   **Position (`uint32_t`):** Bits 0-10 (11 bits): $x$; Bits 11-20 (10 bits): $y$; Bits 21-31 (11 bits): $z$.
    *   **Albedo (`uint32_t`):** Bits 0-4 (5 bits): $R$; Bits 5-10 (6 bits): $G$; Bits 11-15 (5 bits): $B$.
    *   Stored in a flat `uint32_t` array of size `no_of_vertices * 2` [S3, unofficial].
2.  **Layout B (Source [S4, unofficial]):** Used within `CUBE256::MipMap::voxels` (`std::vector<uint>`).
    *   Single `uint32_t` per voxel: $x$ (8 bits) | $(y \ll 8)$ (8 bits) | $(z \ll 16)$ (8 bits) | $(color \ll 24)$ (8 bits) [S4, unofficial].
    *   The VBO layout for the geometry shader consists of four 4-component attributes (`vertex0` to `vertex3`), each reading 4 unsigned bytes (`GL_UNSIGNED_BYTE`) with normalization (`GL_TRUE`) from a stride of 16 bytes. `vertex0` reads bytes 0-3, `vertex1` reads bytes 4-7, `vertex2` reads bytes 8-11, `vertex3` reads bytes 12-15 [S4, unofficial].

**Parameters:**
*   `voxelSize`: Physical size of a single voxel in world units (e.g., 0.05) [S3, unofficial].
*   `halfScreenSize`: Half of the viewport dimensions, used to scale projected AABB to screen space [S3, unofficial].
*   `cubes_x, cubes_y, cubes_z`: Grid dimensions for the voxel space (default 4, 4, 4) [S4, unofficial].
*   `scale`: Rendering scale of splats, calculated as $0.1f \times (1 \ll \text{mipmap})$ [S4, unofficial].
*   `_Color`: Color for non-solid voxels. Default (1, 0, 0, 1) (red) [S2, unofficial].
*   `_CollisionColor`: Color for solid voxels. Default (0, 1, 0, 1) (green) [S2, unofficial].

**Steps:**
1.  **Initialize Voxel Grid:**
    *   Resize the cubes vector to `cubes_x * cubes_y * cubes_z` (default 64 cubes) [S4, unofficial].
    *   For each voxel index $i$, compute packed position and albedo using bitwise shifts and random color generation [S3, unofficial].
2.  **Set Voxel Position and Mipmap:**
    *   Shift $x, y, z$ by mipmap level: $x \ll= \text{mipmap}$ [S4, unofficial].
    *   Calculate cube ID: $\text{cubeID} = (x \gg 8) + (y \gg 8) \times \text{cubes\_x} + (z \gg 8) \times \text{cubes\_x} \times \text{cubes\_y}$ [S4, unofficial].
    *   Store local voxel $(x \& 255, y \& 255, z \& 255)$ in the corresponding cube's mipmap [S4, unofficial].
    *   Boundary check: If $x, y,$ or $z$ exceed 255, discard the voxel [S4, unofficial].
3.  **Calculate Mipmap Level:**
    *   Determine mipmap based on camera distance:
        $$ \text{mipmap} = \sqrt{\sqrt{(\text{screen.pos} + (\text{pos} + \text{vec3f}(0.5, 0.5, 0.5) + \text{add}) \times 16).\text{length()}}} - 1 $$
    *   Clamp mipmap to $\ge 0$ [S4, unofficial].
4.  **Generate VBOs:**
    *   For each mipmap with voxels, create a `GL_ARRAY_BUFFER`, bind it, and upload voxel data with `GL_STATIC_DRAW_ARB` [S4, unofficial].
    *   Bind to a VAO using `glVertexAttribIPointer(0, 2, GL_INT, 2 * sizeof(uint32_t), 0)` for Layout A [S3, unofficial].
5.  **Vertex Shader Processing:**
    *   Unpack voxel coordinates from the packed position `uint32_t` using bitmasks:
        $$ u_x = \text{data.x} \& \text{uint}(2047) $$
        $$ u_y = (\text{data.x} \& \text{uint}(2095104)) \gg \text{uint}(11) $$
        $$ u_z = (\text{data.x} \& (\text{uint}(2047) \ll \text{uint}(21))) \gg \text{uint}(21) $$
    *   Convert to world space by multiplying by 0.1 [S3, unofficial].
    *   Transform position to clip space: $\text{o.position} = \text{UnityWorldToClipPos}(\text{float4}(\text{pos.xyz}, 1.0))$ [S2, unofficial].
6.  **Stochastic Culling:**
    *   Apply stochastic culling for distant/small voxels to maintain performance [S3, unofficial].
    *   Calculate projected area: $\text{stochasticCoverage} = \text{point\_size} \times \text{point\_size}$ [S3, unofficial].
    *   If $\text{stochasticCoverage} < 0.8$, discard vertex with probability proportional to size:
        ```glsl
        if ((stochasticCoverage < 0.8) && ((gl_VertexID & 0xffff) > stochasticCoverage * (0xffff / 0.8))) {
            position = vec4(-1, -1, -1, -1);
            point_size = 0.0;
        }
        ```
    *   Discard voxels behind the camera ($\text{position.z} \le 0.0$) by setting `position = vec4(-1,-1,-1,-1)` and `point_size = 0.0` [S3, unofficial].
7.  **Sphere Radius and Quadric Projection:**
    *   Approximate sphere radius: $\text{sphereRadius} = \text{voxelSize} \times 1.732051$ (where $1.732051 \approx \sqrt{3}$) [S3, unofficial].
    *   Calculate quadric projection coefficients:
        $$ \text{eqCoefs} = \frac{\text{vec4}(\text{dot}(\text{matD}[0], \text{matT}[2]), \text{dot}(\text{matD}[1], \text{matT}[2]), \text{dot}(\text{matD}[0], \text{matT}[0]), \text{dot}(\text{matD}[1], \text{matT}[1]))}{\text{dot}(\text{matD}[2], \text{matT}[2])} $$
        where $\text{matT}$ and $\text{matD}$ are derived from the model-view-projection matrix scaled by $\text{sphereRadius}$ [S3, unofficial].
8.  **Draw:**
    *   Enable `GL_PROGRAM_POINT_SIZE` [S3, unofficial].
    *   Draw with `glDrawArrays(GL_POINTS, 0, no_of_vertices)` [S3, unofficial].
    *   For Layout B: Bind shader, set projection matrix uniform, enable 4 vertex attributes pointing to VBO with stride 16, set `block_pos` and `scale` uniforms, draw `GL_POINTS` with count `voxels.size()/4`, then disable attributes and unbind buffer [S4, unofficial].
    *   For Point Sprites, compute correct texture coordinates in a vertex shader to index into the sub-texture containing the corresponding footprint, as texture coordinates are otherwise computed automatically [S1, unofficial].
    *   Instead of storing one footprint and modulating it with a slab coefficient, this method computes all different kernel footprints for different slabs and stores them in one 2D texture [S1, unofficial].

**Pseudocode:**

def voxel_point_sprite_rendering(voxel_grid, camera_pos, screen_size):
    # Parameters
    voxel_size = 0.05
    half_screen_size = screen_size * 0.5
    cubes_x, cubes_y, cubes_z = 4, 4, 4
    
    # Step 1 & 2: Initialize Grid and Set Voxel Position
    cubes = [None] * (cubes_x * cubes_y * cubes_z)
    for mipmap_level in range(8):
        for cube_id in range(len(cubes)):
            cubes[cube_id] = {"mipmaps": [None] * 8}
            cubes[cube_id]["mipmaps"][mipmap_level] = []
            
            for voxel in voxel_grid:
                x, y, z = voxel.position
                x_shifted = x << mipmap_level
                y_shifted = y << mipmap_level
                z_shifted = z << mipmap_level
                
                # Boundary check
                if x_shifted > 255 or y_shifted > 255 or z_shifted > 255:
                    continue
                    
                # Store local voxel
                local_x = x_shifted & 255
                local_y = y_shifted & 255
                local_z = z_shifted & 255
                cubes[cube_id]["mipmaps"][mipmap_level].append((local_x, local_y, local_z, voxel.color))

    # Step 3: Calculate Mipmap Level for each voxel based on camera distance
    def calculate_mipmap(screen_pos, voxel_pos_world, add_offset):
        length_sq = (screen_pos + (voxel_pos_world + (0.5, 0.5, 0.5) + add_offset) * 16)
        length_sq = length_sq[0]**2 + length_sq[1]**2 + length_sq[2]**2
        mipmap = math.sqrt(math.sqrt(length_sq)) - 1
        return max(0, int(mipmap))

    # Step 4: Generate VBOs
    vbo_list = []
    for cube in cubes:
        for mipmap_level in range(len(cube["mipmaps"])):
            voxels = cube["mipmaps"][mipmap_level]
            if not voxels:
                continue
                
            # Create VBO
            vbo = []
            
            # Upload data (Layout B: 4 attributes of 4 bytes each, stride 16)
            data = []
            for i in range(0, len(voxels), 4):
                for j in range(4):
                    if i + j < len(voxels):
                        vx, vy, vz, vc = voxels[i+j]
                        data.extend([vx, vy, vz, vc])
                    else:
                        data.extend([0, 0, 0, 0])
                        
            vbo = data
            vbo_list.append((vbo, len(voxels)//4, mipmap_level))

    # Step 5 & 6: Vertex Shader Logic (Conceptual)
    def vertex_shader(packed_data):
        data_x = packed_data[0]
        u_x = data_x & 2047
        u_y = (data_x & 2095104) >> 11
        u_z = (data_x & (2047 << 21)) >> 21
        
        world_pos = (u_x * 0.1, u_y * 0.1, u_z * 0.1)
        
        if world_pos[2] <= 0.0:
            return (-1, -1, -1, -1), 0.0
            
        return world_pos, point_size

    # Step 7: Sphere Radius and Quadric Projection
    def calculate_quadric_coefs(model_view_proj, sphere_radius):
        matT = [[c * sphere_radius for c in row] for row in model_view_proj]
        matD = derive_matD_from_matT(matT)
        
        eq_coefs = [
            dot(matD[0], matT[2]),
            dot(matD[1], matT[2]),
            dot(matD[0], matT[0]),
            dot(matD[1], matT[1])
        ] / dot(matD[2], matT[2])
        return eq_coefs

## Subtopics

### [Hybrid Voxel Rendering (Mesh/Splatting)](5766-hybrid-voxel-rendering-mesh-splatting.md)
Hybrid Voxel Rendering is a strategy that combines OpenGL splatting for distant voxels with mesh rendering for nearby voxels to reduce vertex count while maintaining visual quality. It addresses the performance bottleneck of slow fragment shaders in pure splatting methods when rendering voxels close to the camera, a problem inherent to its parent method, [Splatting and Point-based Rendering](4975-splatting-and-point-based-rendering.md).

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of voxels, $O(N)$, where $N$ is the number of active voxels [G]. Stochastic culling reduces the effective $N$ for distant voxels [S3, unofficial].
*   **Memory Complexity:** Linear with respect to the voxel grid size [G]. Packing data into `uint32_t` arrays minimizes memory footprint [S3, unofficial].
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Scales well with voxel count due to point sprite efficiency. Mipmapping allows distant voxels to be rendered with lower resolution, reducing fragment shader load [S4, unofficial].
*   **Strengths:** Efficient rendering of large voxel datasets; hardware-accelerated point sprites; stochastic culling improves performance for distant objects [S3, unofficial].
*   **Limitations:** Potential artifacts from point sprite blending; requires geometry shader support; precision issues with large coordinate values if not packed carefully [S4, unofficial].
*   **When to use:** Real-time rendering of large voxel datasets where performance is critical and visual quality can be approximated by splats [S4, unofficial].
*   **When not to use:** When precise geometric boundaries are required, or when hardware does not support geometry shaders or point sprites [S4, unofficial].

## Background
Voxel Point Sprite Rendering is an implementation technique found in open-source voxel rendering experiments, specifically associated with the "OpenGL-Voxel-Splatting" project by sp4cerat [S4, unofficial] and the "voxel-renderer" by clayjohn [S3, unofficial]. These projects demonstrate the use of OpenGL point sprites and geometry shaders for efficient voxel visualization [S4, unofficial].
