# Sparse Voxel Octree Rendering via Square Splats

Also called: SVO Renderer, Square Splat Rendering

## Overview
Sparse Voxel Octree Rendering via Square Splats is a method that visualizes sparse voxel octrees (SVOs) by converting leaf voxels into square splats (billboards) using a geometry shader within a programmable graphics pipeline [S1, unofficial]. It solves the problem of efficiently rendering large, sparse 3D datasets by avoiding the overhead of traditional mesh generation for every voxel. Unlike [Ray-Box Intersection via Quad Rasterization](2253-ray-box-intersection-via-quad-rasterization.md) which uses ray tracing logic for visibility, or [Voxel Point Sprite Rendering](4307-voxel-point-sprite-rendering.md) which uses isotropic point sprites, this method generates explicit square quads aligned with the view plane, allowing for precise face culling and standard rasterization [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A sparse voxel octree structure (typically generated by tools like `ooc_svo_builder` [S1, unofficial]). The rendering pipeline receives leaf voxels as point primitives containing position, color, and normal data.
*   **Output:** Rasterized square splats on the screen.

**Data Structures:**
The input data for each voxel consists of:
*   `voxelPosition`: `vec3` (world or view space coordinates).
*   `voxelColor`: `vec3` (RGB color).
*   `voxelNormal`: `vec3` (surface normal).

**Steps:**
1.  **Vertex Shader Processing:**
    For each leaf voxel, the vertex shader receives the position, color, and normal. It transforms the position into view space using the Model-View (MV) matrix. The normal is also transformed into view space (using the upper-left 3x3 of the MV matrix, treating it as a vector, not a point). The transformed position is passed to the geometry shader.
    $$
    P_{view} = MV \times P_{world}
    $$
    $$
    N_{view} = MV_{3x3} \times N_{world}
    $$

2.  **Geometry Shader: Frustum Culling:**
    The geometry shader receives the voxel as a point. It first performs a conservative frustum cull in clip space.
    *   Transform the voxel center to clip space: $P_{clip} = P \times P_{view}$.
    *   Perform perspective division to get normalized device coordinates (NDC): $P_{ndc} = P_{clip} / P_{clip.w}$.
    *   Calculate the clip-space offset for the splat size. The source code calculates a `voxelHalfEdgeLengthClipSpace` by comparing the center to a right-edge midpoint in clip space.
    *   Define a culling border: $B = 1 + \text{voxelHalfEdgeLengthClipSpace}$.
    *   If $P_{ndc}.x < -B$ or $P_{ndc}.x > B$ or $P_{ndc}.y < -B$ or $P_{ndc}.y > B$, discard the primitive.

3.  **Geometry Shader: Back-Face Culling:**
    Check if the voxel's front face is visible.
    *   Calculate the view direction vector from the camera to the voxel in view space: $V_{dir} = -P_{view}.xyz$ (assuming camera at origin in view space).
    *   Calculate the dot product between the view direction and the transformed normal: $D = V_{dir} \cdot N_{view}$.
    *   If $D < 0$, the face is oriented away from the camera; discard the primitive.

4.  **Geometry Shader: Splat Generation:**
    Generate a triangle strip of 4 vertices representing the square splat.
    *   Determine the `voxelOffset` in view space. The source code implies the splat size is derived from the voxel's extent in clip space, projected back to view space. Specifically, it uses `voxelOffset` which appears to be the side length of the voxel in view space coordinates.
    *   Calculate the four corners of the square in view space, centered on $P_{view}.xy$:
        *   Bottom-Left: $C_{BL} = P_{view}.xy + (-0.5, -0.5) \times \text{voxelOffset}$
        *   Bottom-Right: $C_{BR} = P_{view}.xy + (0.5, -0.5) \times \text{voxelOffset}$
        *   Top-Left: $C_{TL} = P_{view}.xy + (-0.5, 0.5) \times \text{voxelOffset}$
        *   Top-Right: $C_{TR} = P_{view}.xy + (0.5, 0.5) \times \text{voxelOffset}$
    *   For each corner, construct the clip-space position: $P_{corner\_clip} = P \times (C_{corner}.x, C_{corner}.y, P_{view}.z, 1.0)$. Note: The Z-coordinate remains the voxel's depth.
    *   Emit the vertices in order: BL, BR, TL, TR. This forms two triangles (BL-BR-TR and BL-TR-TL) or a strip depending on the primitive type.
    *   Pass color and normal to the fragment shader.

**Pseudocode:**

```python
# Vertex Shader
def vertex_shader(voxel_position_world, voxel_normal_world, mv_matrix):
    # Transform position to view space
    voxel_position_view = mv_matrix * vec4(voxel_position_world, 1.0)
    # Transform normal to view space (treat as vector)
    voxel_normal_view = mv_matrix[0:3, 0:3] * voxel_normal_world
    return voxel_position_view.xyz, voxel_normal_view

# Geometry Shader
def geometry_shader(voxel_position_view, voxel_normal_view, mv_matrix, projection_matrix):
    # 1. Frustum Culling in Clip Space
    voxel_position_clip = projection_matrix * vec4(voxel_position_view, 1.0)
    voxel_position_ndc = voxel_position_clip.xyz / voxel_position_clip.w
    
    # Calculate half-edge length in clip space for culling border
    # Approximation: distance from center to right edge midpoint in clip space
    # Note: Source uses a specific calculation involving 'voxelRightEdgeMidPointClipSpace'
    # Simplified logic based on source:
    voxel_half_edge_clip = distance(voxel_position_clip, voxel_right_edge_midpoint_clip)
    culling_border = 1.0 + voxel_half_edge_clip
    
    if (abs(voxel_position_ndc.x) > culling_border or 
        abs(voxel_position_ndc.y) > culling_border):
        return # Discard

    # 2. Back-Face Culling
    # View direction is from camera (origin in view space) to voxel
    view_direction = -voxel_position_view.xyz
    dot_product = dot(view_direction, voxel_normal_view)
    
    if dot_product < 0:
        return # Discard

    # 3. Generate Square Splat
    # Determine voxel offset (side length) in view space.
    # Source implies this is derived from the voxel's size.
    # For unit voxels in view space, this might be constant or scaled.
    # Assuming 'voxel_offset' is the side length in view space units.
    voxel_offset = get_voxel_side_length_view_space() 
    
    corners_view = [
        voxel_position_view.xy + vec2(-0.5, -0.5) * voxel_offset,
        voxel_position_view.xy + vec2(0.5, -0.5) * voxel_offset,
        voxel_position_view.xy + vec2(-0.5, 0.5) * voxel_offset,
        voxel_position_view.xy + vec2(0.5, 0.5) * voxel_offset
    ]
    
    vertices = []
    for corner_xy in corners_view:
        # Construct 4D position in view space (Z is preserved)
        pos_view_4d = vec4(corner_xy, voxel_position_view.z, 1.0)
        # Transform to clip space
        pos_clip = projection_matrix * pos_view_4d
        vertices.append(pos_clip)
        
    # Emit triangle strip: 0-1-2-3
    emit_vertex(vertices[0])
    emit_vertex(vertices[1])
    emit_vertex(vertices[2])
    emit_vertex(vertices[3])
    end_primitive()
```

**Parameters:**
*   `cullInvisibleFaces`: Boolean flag to enable back-face culling. Default: True.
*   `voxelOffset`: The side length of the voxel in view space. Not explicitly defined as a uniform in the snippet, but derived from the voxel's geometry.

**Edge Cases:**
*   **Precision:** Clip-space calculations can suffer from precision issues at extreme distances. The culling border is calculated dynamically to account for the splat's size in clip space.
*   **Degenerate Input:** If a voxel is exactly on the frustum boundary, the culling logic may discard it. The border is set to $1 + \text{half\_edge}$, providing a small margin.

## Subtopics

### [Voxel Splatting to Pixel Footprints](3613-voxel-splatting-to-pixel-footprints.md)
A rasterization technique where each voxel in a cluster is processed by a single invocation, projecting its footprint box to the pixel centers it covers, replacing the previous method of walking every pixel of a brick's rectangle through its cells. It solves the inefficiency of processing pixels that no voxel footprint covers, particularly at shallow voxel levels where footprints are small fractions of cell sizes.

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of leaf voxels $N_{leaves}$. Each leaf is processed in constant time by the geometry shader.
*   **Memory Complexity:** Low. Only leaf voxel data needs to be stored in vertex buffers. The octree structure itself is stored in memory but not directly rendered.
*   **Performance:** Efficient for sparse datasets where the number of visible leaves is small compared to the total volume. Performance degrades if the scene is dense and nearly all leaves are visible, as the geometry shader overhead becomes significant.
*   **Strengths:** Simple implementation using standard OpenGL geometry shaders. Effective culling reduces overdraw.
*   **Limitations:** Geometry shader overhead can be high on some hardware. Not suitable for very dense volumes without additional optimization (like the child method). Transparency handling requires sorting or alpha blending, which is not detailed in the source.

## Background
The method was implemented as part of a sparse voxel octree renderer using OpenGL and C++ [S1, unofficial]. It relies on SVOs generated by the `ooc_svo_builder` tool by Forceflow [S1, unofficial]. The approach leverages the programmable graphics pipeline to handle the conversion from volumetric data to geometric primitives on the GPU.
