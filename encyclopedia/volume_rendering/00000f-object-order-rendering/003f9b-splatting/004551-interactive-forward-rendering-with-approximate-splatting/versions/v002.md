# Interactive Forward Rendering with Approximate Splatting

Also called: Fast Rendering, OpenGL Approximation

## Overview
This method provides an efficient, hardware-accelerated approximation of point reprojection for high-quality free-viewpoint rendering, enabling interactive frame rates by replacing full soft rasterization with a global depth layering system [S1]. It differs from sibling methods like [Slice-by-Slice (Sheet Buffer) Splatting](2110-slice-by-slice-sheet-buffer-splatting.md) by using a fixed number of global depth layers rather than processing slices sequentially, and from [Screen Quad Rendering](2435-screen-quad-rendering.md) by explicitly managing opacity accumulation via logarithmic blending in screen space [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of input views (images and camera poses), a multi-view stereo (MVS) mesh, and a pre-trained neural network for image synthesis [S1].
*   **Outputs:** A synthesized novel view image [S1].

**Data Structures:**
*   **Depth Layers:** A stack of $k_d$ texture buffers representing global depth intervals [S1]. Each layer stores accumulated opacity and depth information [S1].
*   **MVS Mesh Depth Map:** A low-resolution depth map used to determine the relevant depth interval for the scene [S1].

**Parameters:**
*   $k_d$: Number of global depth layers. Typical value: 10 [S1].
*   Resolution: Target output resolution (e.g., 900x600) [S1].

**Steps:**
1.  **Camera Selection:** Choose a subset of input views relevant to the novel view [S1].
2.  **Depth Interval Determination:** Rasterize the MVS mesh depth at a low resolution (1/16 of target) and construct a min-max mipmap to determine the relevant depth range [S1].
3.  **Splatting into Depth Layers:** Project points from all selected input views into the $k_d$ global depth layers in parallel [S1].
    *   Opacity accumulation uses hardware-accelerated additive blending of $\log(1 - \alpha)$ to achieve multiplicative opacity accumulation [S1].
    *   Formula for opacity accumulation: If $\alpha$ is the splat opacity, the stored value $V$ is updated as $V_{\text{new}} = V_{\text{old}} + \log(1 - \alpha)$ [S1]. The final accumulated opacity is $1 - \exp(V_{\text{total}})$ [S1].
4.  **Compositing:** Composite the depth layers back-to-front in parallel over all re-projected pixels of all input images [S1].
5.  **Probabilistic Depth Test:** Apply a probabilistic depth test considering at most $k_d$ alpha-weighted depth samples to refine visibility [S1].
6.  **Neural Synthesis:** Run the neural network to synthesize the final image using the accumulated depth and color information [S1].

**Pseudocode:**
```python
def interactive_forward_rendering(input_views, mvs_mesh, neural_net, k_d=10, target_res=(900, 600)):
    # 1. Camera Selection: Choose relevant input views [S1]
    selected_views = input_views  # Selection algorithm not specified in sources [G]

    # 2. Determine Depth Interval: Rasterize MVS mesh at 1/16 resolution, build min-max mipmap [S1]
    low_res = (target_res[0] // 16, target_res[1] // 16)
    low_res_depth = rasterize_mesh_to_depth(mvs_mesh, low_res)  # Standard GPU rasterization [G]
    depth_min, depth_max = compute_min_max_mipmap(low_res_depth)  # Standard mipmap reduction [G]

    # 3. Initialize Depth Layers: Stack of k_d texture buffers for log(1-alpha) accumulation [S1]
    depth_layers = [create_texture_buffer(target_res, init=0.0) for _ in range(k_d)]

    # 4. Splat Points into Depth Layers: Project all pixels of selected views in parallel [S1]
    for view in selected_views:
        for point in extract_points_from_view(view):  # Standard point extraction [G]
            screen_pos, depth = project_point_to_screen(point, view.camera)  # Standard MVP transform [G]
            layer_idx = map_depth_to_layer(depth, depth_min, depth_max, k_d)  # Standard quantization [G]
            alpha = compute_splat_opacity(point)  # Standard kernel evaluation [G]
            log_val = math.log(1.0 - alpha)
            depth_layers[layer_idx].additive_blend(screen_pos, log_val)  # Hardware-accelerated additive blending [S1]

    # 5. Composite Depth Layers Back-to-Front in parallel [S1]
    accumulated_log_alpha = sum(layer.texture for layer in depth_layers)  # Sum across layers [G]
    final_alpha = 1.0 - math.exp(accumulated_log_alpha)  # Inverse of log accumulation [S1]

    # 6. Probabilistic Depth Test: Consider at most k_d alpha-weighted depth samples [S1]
    refined_depth = apply_probabilistic_depth_test(depth_layers, k_d)  # Standard test logic [G]

    # 7. Neural Synthesis: Run neural network to synthesize image [S1]
    final_image = neural_net(refined_depth, final_alpha, selected_views)

    return final_image
```

**Edge Cases and Pitfalls:**
*   **Memory Consumption:** High memory usage due to batching all input views and depth layers. For 900x600 resolution, 10 layers, and 9 views, depth layers take ~4 GB [S1].
*   **Compression:** Memory can be reduced through standard texture compression methods [S1].

## Operating characteristics
*   **Time Complexity:** The method is designed for interactive performance. An unoptimized implementation runs at 4.5 fps [S1].
*   **Breakdown:** Camera selection: 87 ms, point splatting: 36 ms, depth test: 38 ms, network evaluation: 59 ms [S1].
*   **Memory Complexity:** High. Depth layers consume ~4 GB for 900x600 resolution, 10 layers, 9 views. PyTorch reports 4.5 GB total memory usage for this configuration [S1].
*   **Strengths:** Enables interactive viewing with marginal quality degradation compared to full soft rasterization [S1].
*   **Limitations:** High memory consumption; requires pre-trained neural network [S1].
*   **When to use:** When interactive frame rates are required for free-viewpoint rendering and sufficient GPU memory is available [S1].
*   **When not to use:** When memory is constrained or offline rendering quality is prioritized over speed [S1].

## Background
This method was introduced by Kopanas et al. in "Point-Based Neural Rendering with Per-View Optimization" [S1]. It is part of a differentiable multi-view pipeline used for applications such as image-based rendering (IBR), multi-view harmonization, and multi-view style transfer [S1]. The implementation was done in PyTorch with custom OpenGL-based approximations for the forward pass [S1].
