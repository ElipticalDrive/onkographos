# Multi Resolution Alpha Blending

Also called: Per-pixel sorting and blending, Fragment list accumulation

## Overview
Multi Resolution Alpha Blending is a rendering technique that resolves visibility and color for splatted primitives by collecting fragments into per-pixel lists, sorting them by depth, and combining them via front-to-back alpha compositing. It solves the problem of correct occlusion and transparency in dense, multi-resolution point-based rendering where global sorting is computationally prohibitive. It differs from [Hierarchical Splatting](1168-hierarchical-splatting.md) and [Octree-based Splatting](8067-octree-based-splatting.md) by deferring the final visibility determination to a per-pixel sorting step rather than relying solely on hierarchical node selection or global depth buffers, which allows for efficient handling of high fragment counts with small list sizes [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of splatted primitives (points/Gaussians) projected onto the image plane, each with position $(x, y)$, depth $z$, opacity $\alpha$, and color $c$.
*   **Output:** A final color image $C_\Lambda$.

**Data Structures:**
*   **Per-pixel fragment lists:** $\Lambda_{l_i, x_i, y_i}$, where $l_i$ is the resolution level, and $(x_i, y_i)$ are pixel coordinates.
*   **List Capacity:** Each list is clamped to a maximum size of $K=16$ elements [S1].

**Algorithm Steps:**
1.  **Fragment Collection:** For each primitive, determine the pixels it covers. Append the primitive's attributes (depth $z$, opacity $\alpha$, color $c$, and level index $i$) to the corresponding per-pixel list $\Lambda_{l_i, x_i, y_i}$ [S1].
2.  **Coarse Layer Inclusion:** To handle occlusion errors in scenes with large density deviations, include points from coarser resolution layers in the blending process. This ensures that background structures are not incorrectly occluded by foreground noise [S1].
3.  **GPU-Friendly Sorting:** Sort each list $\Lambda$ by depth (front-to-back). Since lists are small ($K \le 16$), use warp-local sorting (32 threads) and shuffle-based bitonic sorts. The algorithm iteratively replaces the last 16 elements of the list with new unsorted fragments until all fragments are processed [S1].
4.  **Alpha Blending:** Perform front-to-back alpha blending in the same pass as sorting, as elements reside in registers. Compute the final color $C_\Lambda$ for each pixel using the sorted fragments [S1].

**Formulas:**
The final color $C_\Lambda$ is computed as [S1]:
$$C_\Lambda = \sum_{m=1}^{|\Lambda|} T_m \cdot \alpha_m \cdot c_m$$

The transmittance $T_m$ for the $m$-th fragment is [S1]:
$$T_m = \prod_{i=1}^{m-1} (1 - \alpha_i)$$

Where:
*   $|\Lambda|$ is the number of fragments in the list (up to 16).
*   $\alpha_m$ is the opacity of fragment $m$.
*   $c_m$ is the color of fragment $m$.
*   $T_m$ is the transmittance (probability of light passing through all preceding fragments).

**Parameters:**
*   **Max List Size:** 16 elements [S1].
*   **Minimum Contribution Weight:** $\epsilon = 0.25$. To prevent weights from disappearing for points at finer levels, their contribution is clamped to at least this value [S1].

**Pitfalls:**
*   **Occlusion Errors:** In scenes with large deviations in point density, the neural network component (if used) may fail to correctly evaluate occlusion in edge cases. This is mitigated by explicitly including coarser layer points in the blending step [S1].
*   **Precision:** Sorting and blending occur in the same pass to keep elements in registers, requiring careful management of floating-point precision during accumulation [S1].

**Pseudocode:**
```python
def multi_resolution_alpha_blending(primitives, image_width, image_height):
    # Initialize per-pixel lists
    # Each list stores tuples: (depth_z, opacity_alpha, color_c, level_index)
    pixel_lists = [[[] for _ in range(image_width)] for _ in range(image_height)]

    # Step 1: Collect fragments
    for prim in primitives:
        x, y = prim.projected_position
        z = prim.depth
        alpha = prim.opacity
        c = prim.color
        level = prim.level

        # Add to pixel list
        pixel_lists[y][x].append((z, alpha, c, level))

    # Step 2: Sort and Blend
    final_image = np.zeros((image_height, image_width, 3))

    for y in range(image_height):
        for x in range(image_width):
            frag_list = pixel_lists[y][x]
            
            # Clamp list size to 16
            if len(frag_list) > 16:
                # Sort by depth (ascending, front-to-back)
                # Use GPU-friendly warp-local bitonic sort logic here
                frag_list.sort(key=lambda item: item[0])
                frag_list = frag_list[:16]
            else:
                # Sort small lists
                frag_list.sort(key=lambda item: item[0])

            # Step 3: Front-to-back Alpha Blending
            transmittance = 1.0
            accumulated_color = np.zeros(3)
            
            for z, alpha, c, level in frag_list:
                # Ensure minimum contribution weight if necessary
                # [G] Implementation detail: clamp alpha or weight if required by specific variant
                # Based on [S1], min weight epsilon=0.25 applies to level contributions
                
                # Alpha blending formula
                contribution = transmittance * alpha * c
                accumulated_color += contribution
                transmittance *= (1.0 - alpha)
                
                # Early exit if fully opaque
                if transmittance < 1e-6:
                    break
            
            final_image[y, x] = accumulated_color

    return final_image
```

## Subtopics

### Neural Reconstruction Network
A compact neural network that consolidates a feature image pyramid of $n$ layers into a single full-resolution image, resembling a U-Net decoder. It incorporates a single gated convolution [YLY* 19] in each layer with a self-bypass connection and a feature size of 32. It requires a significantly smaller and more efficient network than hole-filling networks because the renderer fills gaps autonomously and generates smooth output [S1].

## Operating characteristics
*   **Time Complexity:** Dominated by the per-pixel sorting step. Using warp-local sorting on lists of size 16 makes this highly efficient on GPU architectures, faster than global sorting for high fragment counts [S1].
*   **Memory Complexity:** $O(N)$ where $N$ is the number of pixels, plus overhead for fragment lists. The list size is capped at 16, bounding memory usage per pixel [S1].
*   **Performance:** The approach is optimized for real-time rendering. The sorting and blending pass is combined to minimize memory bandwidth usage by keeping elements in registers [S1].
*   **Strengths:** Handles dense point clouds efficiently; avoids global sorting bottlenecks; correct alpha compositing for transparency.
*   **Limitations:** May require auxiliary neural networks for hole-filling in sparse regions; occlusion handling depends on including coarser layers [S1].

## Background
Multi Resolution Alpha Blending is a core component of the TRIPS (Trilinear Point Splatting for Real-Time Radiance Field Rendering) method. It was introduced to address the inefficiencies of global sorting in point-based radiance field rendering, leveraging the fact that per-pixel fragment counts are naturally small and bounded [S1].
