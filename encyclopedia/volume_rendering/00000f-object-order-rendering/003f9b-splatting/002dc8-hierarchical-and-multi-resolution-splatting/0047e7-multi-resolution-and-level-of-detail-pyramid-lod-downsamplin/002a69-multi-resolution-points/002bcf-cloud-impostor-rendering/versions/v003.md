# Cloud Impostor Rendering

Also called: Dynamic impostors, Dynamically Generated Impostors, Impostors for clouds

## Overview
Cloud Impostor Rendering is a technique to accelerate cloud rendering by replacing geometric particle models with 2D texture impostors, exploiting the lack of high-frequency edges in clouds to tolerate lower resolution textures and frequent updates [S1, unofficial]. It solves the performance bottleneck of particle-based cloud rendering by approximating multiple forward scattering in a preprocess and first-order anisotropic scattering at runtime, using dynamically generated 2D impostors to accelerate rendering [S2, unofficial]. It sets itself apart from its sibling [Real-Time Cloud Rendering](5270-real-time-cloud-rendering.md) by explicitly separating the illumination calculation into a precomputed multiple forward scattering term and a runtime anisotropic single scattering term, rather than relying solely on isotropic approximations or simple texture mapping [S1, unofficial].

## How it works
**Inputs:**
*   Cloud particle system (position, size, color, opacity).
*   Viewpoint position and viewing direction.
*   Object bounding volumes (for clouds containing objects).
*   Screen resolution ($resolution_{screen}$).

**Outputs:**
*   Textured impostor polygons (quads) rendered to the frame buffer.

**Data Structures:**
*   **Impostor Texture:** A 2D image generated by rendering the cloud particles from the current viewpoint.
*   **Impostor Geometry:** A screen-space rectangle (quad) sized to fill the screen (for internal clouds) or fitted to the object's bounding volume projection (for distant clouds).
*   **Error Metrics:**
    *   Translation error angle ($\alpha_{trans}$): The angle between the current viewing direction and the direction used to generate the impostor texture.
    *   Required texture resolution: Calculated based on object size and distance.

**Parameters:**
*   **Translation error tolerance:** ~0.15 degrees for imperceptible popping [S1, unofficial]. Up to 1 degree for added performance [S1, unofficial].
*   **Resolution reduction factor:** 4 in each dimension for clouds containing the viewpoint [S1, unofficial].

**Steps:**

1.  **Determine Cloud Category:** Check if the viewpoint is inside the cloud's bounding volume.
    *   If **distant**: Proceed to Step 2.
    *   If **internal (containing viewpoint)**: Proceed to Step 3.

2.  **Generate Distant Impostor:**
    1.  Position a view frustum at the current viewpoint.
    2.  Fit the frustum tightly to the cloud's bounding volume.
    3.  Render the cloud particles into an image using this frustum.
    4.  Use this image to texture an impostor polygon.
    5.  Display the impostor as a polygon oriented toward the viewer.

3.  **Generate Internal Impostor:**
    1.  Use the same view frustum used to display the whole scene (not tightly fitted to the cloud).
    2.  Render the cloud particles into an image.
    3.  Reduce the texture resolution by a factor of 4 in each dimension compared to the screen resolution [S1, unofficial].
    4.  Use this lower-resolution image to texture an impostor polygon.
    5.  Display the impostor as a screen-space rectangle sized to fill the screen [S1, unofficial].

4.  **Update Decision:**
    1.  Compute the translation error angle $\alpha_{trans}$ between the current viewing direction and the direction used for the last impostor generation.
    2.  Compute the required texture resolution using the formula:
        $$resolution_{texture} = resolution_{screen} \cdot \frac{object\_size}{dist}$$
        where $resolution_{screen}$ is the screen resolution, $object\_size$ is the object size, and $dist$ is the distance to the object [S1, unofficial].
    3.  If $\alpha_{trans} >$ tolerance OR current resolution < required resolution, regenerate the impostor from the current viewpoint [S1, unofficial].

**Pseudocode:**

```python
def update_cloud_impostor(cloud, viewpoint, screen_res, last_impostor):
    """
    Updates the impostor for a cloud based on viewpoint movement.
    
    Args:
        cloud: Object containing particle data and bounding volume.
        viewpoint: Current camera position and direction.
        screen_res: Tuple (width, height) of the screen resolution.
        last_impostor: Previous impostor state (texture, generation_view_dir, resolution).
        
    Returns:
        New impostor texture and geometry state.
    """
    # Step 1: Determine if viewpoint is inside the cloud
    is_internal = is_viewpoint_inside_bounding_volume(viewpoint.pos, cloud.bounding_volume)
    
    # Step 2: Calculate error metrics
    # Compute translation error angle alpha_trans
    alpha_trans = angle_between_vectors(last_impostor.gen_view_dir, viewpoint.dir)
    
    # Compute required resolution
    # object_size is the diameter or max extent of the cloud's bounding volume
    object_size = cloud.bounding_volume.diameter()
    dist = distance(viewpoint.pos, cloud.bounding_volume.center)
    
    # Avoid division by zero
    if dist < 1e-6:
        dist = 1e-6
        
    required_res = screen_res * (object_size / dist)
    
    # Step 3: Check if regeneration is needed
    # Tolerance is 0.15 degrees for imperceptible popping [S1, unofficial]
    tolerance = 0.15 
    needs_update = (alpha_trans > tolerance) or (last_impostor.resolution < required_res)
    
    if not needs_update:
        return last_impostor.texture, last_impostor.geometry
    
    # Step 4: Regenerate Impostor
    if is_internal:
        # Internal cloud: Use scene frustum, reduce resolution by factor of 4 [S1, unofficial]
        frustum = get_scene_frustum()
        render_res = (screen_res[0] // 4, screen_res[1] // 4)
        texture = render_cloud_to_texture(cloud, frustum, render_res)
        # Display as screen-space rectangle filling the screen [S1, unofficial]
        geometry = create_screen_filling_quad()
    else:
        # Distant cloud: Use tightly fitted frustum [S1, unofficial]
        frustum = create_tightly_fitted_frustum(viewpoint.pos, cloud.bounding_volume)
        render_res = screen_res # Full resolution for distant objects usually
        texture = render_cloud_to_texture(cloud, frustum, render_res)
        # Display as polygon oriented toward viewer
        geometry = create_oriented_quad(cloud.bounding_volume, viewpoint.pos)
        
    return texture, geometry

def render_cloud_to_texture(cloud, frustum, resolution):
    """
    Renders cloud particles into a texture using the given frustum.
    This involves sorting particles and rasterizing them as billboards.
    """
    # Sort particles back-to-front relative to frustum viewpoint
    sorted_particles = sort_particles_back_to_front(cloud.particles, frustum.viewpoint)
    
    # Allocate texture buffer
    texture_buffer = allocate_texture_buffer(resolution)
    
    # Render particles into buffer
    for particle in sorted_particles:
        # Project particle center to screen space
        screen_pos = project_to_screen(particle.center, frustum)
        
        # Determine billboard size based on particle size and distance
        billboard_size = calculate_billboard_size(particle, frustum)
        
        # Rasterize billboard into texture buffer
        rasterize_billboard(texture_buffer, screen_pos, billboard_size, particle.color, particle.opacity)
        
    return texture_buffer
```

## Subtopics

### [Real-Time Cloud Rendering](5270-real-time-cloud-rendering.md)
Real-Time Cloud Rendering is a two-pass algorithm for the realistic, real-time rendering of static, constant-shape clouds suitable for flight simulation and games. It solves the performance bottleneck of particle-based cloud rendering by approximating multiple forward scattering in a preprocess and first-order anisotropic scattering at runtime, using dynamically generated 2D impostors to accelerate rendering. It sets itself apart from its sibling [Cloud Impostor Rendering](5125-cloud-impostor-rendering.md) by explicitly separating the illumination calculation into a precomputed multiple forward scattering term and a runtime anisotropic single scattering term, rather than relying solely on isotropic approximations or simple texture mapping.

### Impostor Splitting
Impostor Splitting is a technique to render objects passing through clouds realistically by splitting a single cloud impostor into multiple layers to avoid the artifact of objects appearing to pass through 2D images [S1, unofficial]. It detects when objects pass within the bounding volume of a cloud and splits the cloud impostor into N+1 layers, where N is the number of objects within the cloud [S1, unofficial]. Layer 1 is behind the first object, Layer 2 is in front of the first object and behind the second, etc. [S1, unofficial]. The set of alternating impostor layers and objects is rendered from back to front, with depth testing enabled for objects and disabled for impostors [S1, unofficial]. Unlike direct particle rendering, impostor splitting avoids artifacts caused by billboards intersecting object geometry [S1, unofficial].

### Incremental Impostor Orientation Update
Incremental Impostor Orientation Update is a technique to reduce sawtooth-like rotational artifacts caused by the mismatch between real-time impostor geometry reorientation (60Hz) and delayed texture updates [S2, unofficial]. It minimizes the rotation of the quad in the image plane by calculating a correctional rotation between the normal's direction in the previous frame and the new viewing direction, instead of calculating a rotation matrix between the initial quad normal and the current viewing direction [S2, unofficial]. The rotational axis for this incremental update is fixed in the image plane [S2, unofficial]. Since the incremental update is always taken between the correct new position and the previous result, errors do not accumulate [S2, unofficial]. A pitfall is that quick rotational changes cause artifacts because impostor textures update only every few frames while geometry updates at ~60Hz [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** The cost is dominated by the regeneration of impostor textures, which involves rendering the cloud particles. For distant clouds, this is amortized over multiple frames due to frame-to-frame coherence [S1, unofficial]. For internal clouds, updates may be required every frame, but the resolution is reduced by a factor of 4 in each dimension, lowering the cost [S1, unofficial].
*   **Memory Complexity:** Requires storage for the impostor textures. The resolution is determined by the screen resolution and object size/distance [S1, unofficial].
*   **Measured Performance:** On an NVIDIA GeForce 256 (PC, 800 MHz Pentium III, 256MB RAM), the system renders scenes with up to hundreds of thousands of particles at >50 fps, and >1.2 million particles at 10-12 fps with slow viewpoint movement [S1, unofficial].
*   **Strengths:** Exploits the lack of high-frequency edges in clouds to tolerate lower resolution textures and frequent updates [S1, unofficial]. Can be used for clouds no matter where they are in relation to the viewer [S1, unofficial].
*   **Limitations:** Requires frequent updates for internal clouds or fast-moving viewpoints [S1, unofficial]. Artifacts can occur if the translation error tolerance is too high or if rotational changes are too quick [S2, unofficial].
*   **When to use:** Suitable for flight simulators and games where clouds are a major visual component and performance is critical [S1, unofficial].
*   **When not to use:** Not suitable for scenes with sharp-edged objects where impostor artifacts would be noticeable [S1, unofficial].

## Background
Cloud Impostor Rendering was introduced in the paper "Real-Time Cloud Rendering" [S1, unofficial]. It builds on the concept of dynamically generated impostors [S1, unofficial]. The technique was implemented using OpenGL and DirectX 8 APIs and tested on PC systems and SGI Onyx2 with InfiniteReality2 graphics [S1, unofficial].
