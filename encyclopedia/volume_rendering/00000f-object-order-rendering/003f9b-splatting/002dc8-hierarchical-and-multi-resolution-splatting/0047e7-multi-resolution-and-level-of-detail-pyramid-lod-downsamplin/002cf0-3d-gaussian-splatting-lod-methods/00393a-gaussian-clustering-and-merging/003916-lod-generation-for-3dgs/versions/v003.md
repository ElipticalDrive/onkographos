# LOD Generation for 3DGS

Also called: 3DGS LOD Generation, Gaussian Clustering for LOD

## Overview
This method reduces the computational load of 3D Gaussian Splatting (3DGS) by merging Gaussians into clusters based on attribute similarity, thereby minimizing the number of Gaussians copied, stored, sorted, and rendered [S1]. It differs from virtual texturing approaches where mip levels consist of uniform-sized pages; instead, this method reduces the Gaussian count with each LOD level, allowing multiple virtual pages to map to a single physical page [S1]. It builds on [Gaussian clustering and merging](8436-gaussian-clustering-and-merging.md) by specifying the clustering algorithm (k-means), the specific merging arithmetic, and the dynamic memory-driven threshold management.

## How it works
**Inputs:** A set of 3D Gaussians assigned to a specific page (or spatial partition). Each Gaussian $g_i$ is defined by position $\mathbf{p}_i$, rotation $\mathbf{q}_i$ (quaternion), scale $\mathbf{s}_i$ (vector), opacity $\alpha_i$, and spherical harmonics coefficients $\mathbf{c}_i$.
**Outputs:** A reduced set of representative Gaussians for a lower LOD level, and a page table mapping virtual pages to physical LOD levels.

**Data Structures:**
*   **Gaussian:** Struct containing fields for position (3 floats), rotation (4 floats), scale (3 floats), opacity (1 float), and SH coefficients (variable, typically 48 floats for degree 3).
*   **Page Table:** Array of entries. Each entry contains:
    *   `page_id`: Identifier for the virtual page.
    *   `lod_level`: Integer index of the current LOD level (0 = highest detail).
    *   `last_use`: Timestamp or frame counter for eviction policies.
    *   `physical_data`: Pointer or handle to the merged Gaussian data in GPU memory.

**Algorithm Steps:**

1.  **Clustering:**
    For each page, identify clusters of Gaussians using the k-means algorithm. The points to cluster are the Gaussian attributes mapped into a multidimensional space.
    *   *Attribute Weighting:* Prioritize position attributes during distance calculation to prevent dispersed clusters. Scale attributes, rotation, and color/SH coefficients are included but weighted lower [S1].
    *   *Constraint:* Only Gaussians residing on the same page can be merged into a single cluster [S1].

2.  **Merging:**
    Replace each cluster with a single representative Gaussian.
    *   **Translation, Rotation, Opacity, SH:** Compute the arithmetic mean of the cluster members [S1].
        $$ \mathbf{p}_{new} = \frac{1}{N} \sum_{i=1}^{N} \mathbf{p}_i $$
        $$ \mathbf{q}_{new} = \text{Normalize}\left(\frac{1}{N} \sum_{i=1}^{N} \mathbf{q}_i\right) $$
        $$ \alpha_{new} = \frac{1}{N} \sum_{i=1}^{N} \alpha_i $$
        $$ \mathbf{c}_{new} = \frac{1}{N} \sum_{i=1}^{N} \mathbf{c}_i $$
    *   **Scale:** Do not average scales directly, as this results in a Gaussian that is too small [S1]. Instead, scale up the merged Gaussian by a fixed factor $k$ to fill gaps. This factor is derived from average pixel coverage metrics observed during training [S1].
        $$ \mathbf{s}_{new} = k \cdot \mathbf{s}_{base} $$
        Where $\mathbf{s}_{base}$ is a representative scale (e.g., mean or median of the cluster) and $k > 1$ is the fixed adjustment factor [S1].

3.  **LOD Assignment:**
    Mark page table entries with their current LOD level. The LOD level determines the granularity of the Gaussian data stored for that page [S1].

4.  **Dynamic Threshold Adjustment:**
    Select the appropriate LOD level during rendering based on camera distance and memory constraints [S1].
    *   **Thresholds:** Maintain distance thresholds that define the boundaries between LOD levels.
    *   **Memory Adaptation:**
        *   If GPU memory usage exceeds a limit, move thresholds away from the camera (increasing LOD index, reducing detail) [S1].
        *   If memory is available, move thresholds closer to the camera (decreasing LOD index, increasing detail) [S1].
    *   **Step Size Control:** Dynamically adjust the step size for threshold changes based on previous moves to prevent rapid flipping (popping/flickering) between levels [S1].

**Pseudocode:**

```python
def merge_gaussians(cluster_gaussians, scale_factor):
    """
    Merges a list of Gaussians into one representative Gaussian.
    cluster_gaussians: List of Gaussian objects.
    scale_factor: Fixed multiplier for scale adjustment.
    """
    n = len(cluster_gaussians)
    if n == 0:
        return None

    # Arithmetic mean for position, opacity, and SH
    pos_sum = vec3(0, 0, 0)
    alpha_sum = 0.0
    sh_sum = vec4(0, 0, 0, 0) # Assuming 4 coeffs for simplicity, actual size varies
    
    # Quaternion averaging (simplified normalization)
    quat_sum = vec4(0, 0, 0, 0)
    
    # Scale base (using mean scale magnitude as base for adjustment)
    scale_sum = vec3(0, 0, 0)

    for g in cluster_gaussians:
        pos_sum += g.position
        alpha_sum += g.opacity
        sh_sum += g.sh_coeffs
        quat_sum += g.rotation
        scale_sum += g.scale

    new_gaussian = Gaussian()
    new_gaussian.position = pos_sum / n
    new_gaussian.opacity = alpha_sum / n
    new_gaussian.sh_coeffs = sh_sum / n
    
    # Normalize averaged quaternion
    new_gaussian.rotation = normalize(quat_sum)
    
    # Scale adjustment: apply fixed factor to fill gaps
    # Note: Source specifies scaling up by a fixed factor derived from training.
    # We use the mean scale of the cluster as the base for this adjustment.
    mean_scale = scale_sum / n
    new_gaussian.scale = mean_scale * scale_factor
    
    return new_gaussian

def update_lod_thresholds(current_memory_usage, memory_limit, current_thresholds, prev_move_direction):
    """
    Dynamically adjusts LOD thresholds based on memory pressure.
    """
    # Determine if we need to reduce detail (move thresholds away) or increase (move closer)
    if current_memory_usage > memory_limit:
        direction = 1 # Increase LOD index (reduce detail)
    else:
        direction = -1 # Decrease LOD index (increase detail)
        
    # Dynamic step size based on previous moves to prevent oscillation
    # If previous move was in same direction, increase step size slightly for faster adaptation
    # If opposite, decrease step size to prevent overshooting
    step_size = base_step_size
    if direction == prev_move_direction:
        step_size *= 1.2
    else:
        step_size *= 0.8
        
    # Apply step to thresholds
    new_thresholds = []
    for t in current_thresholds:
        new_t = t + (direction * step_size)
        # Clamp thresholds to valid range
        new_thresholds.append(clamp(new_t, min_dist, max_dist))
        
    return new_thresholds, direction
```

## Operating characteristics
*   **Time Complexity:** Clustering using k-means is generally $O(N \cdot I \cdot D)$, where $N$ is the number of Gaussians per page, $I$ is the number of iterations, and $D$ is the dimensionality of the attribute space [S1]. Merging is linear $O(N)$ per cluster.
*   **Memory Complexity:** Reduces GPU memory usage by storing fewer, larger Gaussians at distance [S1].
*   **Performance:** Enables real-time rendering (60+ FPS) by reducing the number of Gaussians sorted and splatted [S1].
*   **Strengths:** Minimizes distant appearance impact without altering scene creation; allows multiple virtual pages per physical page [S1].
*   **Limitations:** Requires careful tuning of the scale adjustment factor and LOD thresholds to avoid artifacts [S1].
*   **When to use:** When VRAM is limited or when rendering large scenes at high frame rates where full-resolution Gaussian sorting is prohibitive [S1].
*   **When not to use:** When maximum visual fidelity at all distances is required and memory is abundant.

## Background
This method originates from the work on virtual memory for 3D Gaussian Splatting [S1]. It adapts concepts from virtual texturing, where mip levels are uniform-sized pages, to the non-uniform nature of Gaussian splatting [S1]. The approach addresses the high memory and computational costs of rendering millions of Gaussians by hierarchically reducing detail based on screen-space importance and memory availability [S1].
