# Virtual Memory for 3D Gaussian Splatting

Also called: Page-based Rendering, Virtual Texturing for 3DGS, Vmem

## Overview
Virtual Memory for 3D Gaussian Splatting (Vmem) enables the rendering of large-scale 3D Gaussian Splatting (3DGS) scenes that exceed available GPU memory by applying virtual texturing concepts [S1]. It groups Gaussians into fixed-size pages, uses a proxy mesh for visibility culling, and streams only visible pages into a limited GPU buffer [S1]. Unlike standard 3DGS which loads all Gaussians or relies on simple distance culling, Vmem separates virtual and physical address spaces, allowing dynamic LOD selection and just-in-time memory allocation to maintain stable frame rates in memory-constrained environments [S1].

## How it works

### Inputs and Outputs
**Inputs:**
*   A trained 3DGS scene containing Gaussians with position, covariance, opacity, and spherical harmonics coefficients [S1].
*   Camera position and orientation [S1].
*   Configuration parameters including Page Size ($N_{page}$), Staging Buffer Size, Rendering Buffer Size, and Adaptive LOD memory targets [S1].

**Outputs:**
*   Rendered image frame [S1].
*   Updated GPU memory state containing resident pages [S1].

### Data Structures

**Scene File (Preprocessed):**
*   **Proxy Mesh:** A coarse mesh approximating the scene geometry, used for visibility determination [S1].
*   **Page IDs:** An array mapping each Gaussian to a page index [S1].
*   **Page Links:** Adjacency list where each page ID maps to a list of overlapping page IDs [S1].
*   **LOD Levels:** Precomputed Gaussian sets for each page at different levels of detail [S1].
*   *Size:* Typically < 20 MiB [S1].

**Page Structure:**
*   Each page contains a fixed number of Gaussians ($N_{page}$) [S1].
*   **LOD Levels:** For each page, multiple LOD levels exist [S1]. Level 0 contains the original Gaussians [S1]. Level $L$ contains $\frac{1}{2^L}$ of the Gaussians of Level 0, generated by merging or clustering Gaussians within the page [S1].
*   *Note:* The source notes that LOD creation may have flaws regarding incorrect scale and lack of level blending [S1].

**GPU Buffers:**
*   **Staging Buffer:** A temporary buffer for copying data from CPU to GPU [S1]. Size is typically ~18.4 MiB (e.g., 40 pages of 2048 Gaussians) [S1].
*   **Rendering Buffer:** A resident GPU buffer holding visible pages [S1]. Size is configurable, e.g., 500 pages for the Berlin scene which uses 489 pages [S1].
*   **Page Table:** Maps virtual page IDs to physical locations in the Rendering Buffer [S1]. Supports sparse residency or reserved resources via APIs like Vulkan or Direct3D 12 [S1].

### Algorithm Steps

1.  **Preprocessing (Offline):**
    1.  **Mesh Extraction:** Generate a proxy mesh from the 3DGS scene using techniques like marching cubes or Gaussian Opacity Fields, tailored to the scene [S1].
    2.  **Page Assignment:** Group Gaussians into pages based on spatial position and assign a unique Page ID to each Gaussian [S1].
    3.  **Page Linking:** Identify overlapping pages and link them if their spatial extents overlap [S1]. This ensures that pages occluded by the proxy mesh but visible via Gaussian spread are included [S1].
        *   *Pitfall:* Unchecked overlaps can negate occlusion culling [S1]. A threshold should be used to ignore small overlaps [S1].
    4.  **LOD Generation:** For each page, generate lower LOD levels by merging Gaussians so that Level $L$ has half the count of Level $L-1$ [S1].
    5.  **File Creation:** Store the proxy mesh, page IDs, links, and LOD data in a single file [S1].

2.  **Runtime (Per Frame):**
    1.  **Visibility Determination:**
        *   Render the proxy mesh to a visibility buffer to identify which pages are potentially visible [S1].
        *   Expand the list of visible pages by including all linked pages that overlap with directly visible pages [S1].
    2.  **LOD Selection:**
        *   Calculate the distance from the camera to each visible page [S1].
        *   Determine the required LOD level for each page based on distance and current memory usage [S1].
        *   **Adaptive LOD:** Dynamically adjust the distance thresholds for LOD transitions to keep physical memory usage between 50% and 80% [S1].
        *   *Constraint:* A single physical page in the rendering buffer can store up to 2, 4, or 8 logical pages at higher LOD levels (Level 1, 2, 3) to save space [S1].
    3.  **Memory Management (Streaming):**
        *   Compare the set of required pages with selected LOD levels against the currently resident pages in the Rendering Buffer [S1].
        *   Identify pages to evict if the buffer is full and pages to load [S1].
        *   Copy non-resident pages from the staging buffer to the Rendering Buffer [S1].
        *   Update the Page Table to map virtual IDs to physical buffer locations [S1].
    4.  **Rendering:**
        *   Sort the resident Gaussians by depth (back-to-front) [S1].
        *   Rasterize the Gaussians to the screen [S1].

### Pseudocode

```python
def render_frame(camera, scene_file, config):
    # 1. Visibility Determination
    # Render proxy mesh to get visible tile/page IDs
    visible_page_ids = render_proxy_mesh_visibility(scene_file.proxy_mesh, camera)
    
    # Expand to include linked pages
    all_required_page_ids = set(visible_page_ids)
    for pid in visible_page_ids:
        if pid in scene_file.page_links:
            all_required_page_ids.update(scene_file.page_links[pid])
            
    # 2. LOD Selection and Memory Budgeting
    # Calculate distance to each page center
    page_distances = {}
    for pid in all_required_page_ids:
        page_distances[pid] = euclidean_distance(camera.position, get_page_center(scene_file, pid))
    
    # Determine LOD level for each page
    # Adaptive LOD adjusts thresholds to keep memory usage in [50%, 80%]
    required_pages = []
    for pid in all_required_page_ids:
        dist = page_distances[pid]
        # Select LOD level L such that memory fits budget
        # Higher L means fewer Gaussians (halved per level)
        lod_level = select_lod_level(dist, config.adaptive_lod_thresholds, config.memory_budget)
        required_pages.append((pid, lod_level))
        
    # 3. Memory Management
    # Identify resident pages in GPU buffer
    resident_pages = get_resident_pages(config.rendering_buffer)
    
    # Determine pages to load and evict
    pages_to_load = []
    pages_to_evict = []
    
    current_memory_usage = calculate_memory_usage(resident_pages, config.rendering_buffer_capacity)
    
    for pid, lod in required_pages:
        if (pid, lod) not in resident_pages:
            pages_to_load.append((pid, lod))
            
    # If buffer is full, evict least recently used or lowest priority pages
    if len(resident_pages) + len(pages_to_load) > config.rendering_buffer_capacity:
        pages_to_evict = select_pages_to_evict(resident_pages, pages_to_load, config.rendering_buffer_capacity)
        
    # Execute streaming
    for pid, lod in pages_to_evict:
        evict_page_from_gpu(config.rendering_buffer, pid, lod)
        
    for pid, lod in pages_to_load:
        # Copy from staging buffer or disk
        copy_page_to_gpu(config.staging_buffer, config.rendering_buffer, pid, lod)
        
    # Update page table
    update_page_table(config.page_table, resident_pages, pages_to_load, pages_to_evict)
    
    # 4. Rendering
    # Gather all resident Gaussians for the current frame
    resident_gaussians = get_gaussians_from_buffer(config.rendering_buffer)
    
    # Sort by depth
    sorted_gaussians = sort_gaussians_by_depth(resident_gaussians, camera)
    
    # Rasterize
    image = rasterize_gaussians(sorted_gaussians, camera, config.resolution)
    
    return image

def select_lod_level(distance, thresholds, memory_budget):
    """
    Selects LOD level based on distance and memory constraints.
    Level 0: Original Gaussians.
    Level L: 1/2^L Gaussians.
    """
    # Base selection from distance
    lod = 0
    for i, threshold in enumerate(thresholds):
        if distance > threshold:
            lod = i + 1
            
    # Adaptive adjustment: if memory is high, increase LOD (reduce Gaussians)
    # This is a simplified representation of the adaptive mechanism described
    # The source notes that thresholds are dynamically modified to keep memory in 50-80% range.
    if memory_budget > 0.8:
        lod = min(lod + 1, max_lod_level)
    elif memory_budget < 0.5:
        lod = max(lod - 1, 0)
        
    return lod

def render_proxy_mesh_visibility(mesh, camera):
    # Renders proxy mesh to a visibility buffer and returns visible page IDs
    return [pid for pid in mesh.visible_pages]

def get_page_center(scene_file, pid):
    # Returns the centroid of Gaussians in the specified page
    return scene_file.page_centroids[pid]

def get_resident_pages(buffer):
    # Returns set of (page_id, lod_level) tuples currently in GPU memory
    return set(buffer.resident_pages)

def calculate_memory_usage(resident_pages, capacity):
    # Calculates ratio of used pages to total capacity
    return len(resident_pages) / capacity

def select_pages_to_evict(resident, to_load, capacity):
    # Evicts pages to make room for to_load, prioritizing higher LOD or least recently used
    needed = len(to_load) - (capacity - len(resident))
    evict_candidates = sorted(resident, key=lambda x: x[1], reverse=True) # Evict highest LOD first
    return evict_candidates[:needed]

def evict_page_from_gpu(buffer, pid, lod):
    # Unmaps virtual page from physical buffer
    buffer.unmap(pid, lod)

def copy_page_to_gpu(staging, target, pid, lod):
    # Copies page data from staging to target buffer
    target.map(pid, lod, staging.data[pid][lod])

def update_page_table(table, resident, load, evict):
    # Updates virtual-to-physical mapping
    for pid, lod in load:
        table[pid] = lod
    for pid, lod in evict:
        del table[pid]

def get_gaussians_from_buffer(buffer):
    # Retrieves all Gaussian data from resident pages
    return buffer.gather_all()

def sort_gaussians_by_depth(gaussians, camera):
    # Sorts back-to-front based on camera projection
    return sorted(gaussians, key=lambda g: g.depth_from(camera))

def rasterize_gaussians(sorted_gaussians, camera, resolution):
    # Standard 3DGS splatting rasterization
    return rasterize(sorted_gaussians, camera, resolution)
```

### Parameters and Typical Values
*   **Page Size ($N_{page}$):** 2048 Gaussians [S1]. Smaller sizes increase page table overhead; larger sizes reduce cache locality and increase false visibility [S1].
*   **Staging Buffer Size:** ~18.4 MiB (e.g., 40 pages of 2048 Gaussians) [S1].
*   **Rendering Buffer Size:** Configurable to hold visible pages, e.g., 500 pages for the Berlin scene which uses 489 pages [S1].
*   **Camera FoV:** 90° (used in evaluation paths) [S1].
*   **Adaptive LOD Memory Target:** 50% to 80% [S1].
*   **LOD Page Capacity:** A single physical page can store up to 2, 4, or 8 logical pages at higher LOD levels [S1].

### Edge Cases and Pitfalls
*   **Page Overlap:** If page overlaps are not guarded during preprocessing, occlusion culling may be negated, increasing memory overhead [S1].
*   **LOD Artifacts:** Merging Gaussians for higher LOD levels creates artifacts, especially near the camera [S1]. Reducing page overlaps and adjusting Gaussian scales can decrease these [S1].
*   **Buffer Too Small:** If the rendering buffer is too small, holes and popping artifacts occur [S1].
*   **Page Linking Trade-off:** Page links increase memory usage and can degrade image quality by forcing poorer LOD selection [S1]. Omitting links causes rendering artifacts [S1]. Mitigation: use careful page assignments and set a threshold to ignore small overlaps [S1].
*   **LOD System Flaws:** The source notes incorrect scale during LOD creation and a lack of level blending during rendering [S1].

## Operating characteristics

### Time and Memory Complexity
*   **Preprocessing:** Highly parallel [S1]. For the 'Residence' scene, preprocessing takes >1 hour, with 85% spent on LOD generation [S1]. For other scenes, page assignment, linking, and LOD each take ~0.5s per page [S1].
*   **Page Table Update:** 0.9ms (Page Size 2048), 0.5ms (4096), 0.3ms (8192) [S1].
*   **Depth Sort:** 2.0ms (2048), 3.0ms (4096), 6.7ms (8192) [S1].
*   **Render Time:** 8.0ms (2048), 9.7ms (4096), 10.6ms (8192) [S1].
*   **Memory Usage:** Drastically reduced compared to baseline [S1]. In 'Alameda', memory never exceeds 50% [S1]. In 'Residence', memory is quickly saturated without LOD but reduces drastically with LOD [S1].

### Measured Performance
*   **Hardware:** Tested on NVIDIA GTX 1070 (Desktop) and Apple M1 SoC (Mobile) [S1].
*   **Quality:** With Page Links and LOD: PSNR 47.19, SSIM 0.99 [S1]. Baseline (No Virtual Memory): PSNR 42.89, SSIM 0.99 [S1].
*   **Mobile Performance:** iPad M1 experiences a fourfold increase in Gaussian sorting time compared to desktop due to slower integrated GPU memory access [S1]. However, Vmem reduces the number of Gaussians sorted, justifying the overhead [S1].

### Strengths and Limitations
*   **Strengths:** Enables rendering of scenes exceeding GPU memory [S1]. Improves frame times by reducing the number of Gaussians processed [S1]. Good cache locality due to page grouping [S1].
*   **Limitations:** LOD artifacts near the camera [S1]. Page linking increases memory overhead [S1]. Streaming overhead on mobile devices [S1]. LOD system lacks level blending [S1].

### When to Use
*   Large-scale 3DGS scenes (e.g., city streets, large open scenes) where GPU memory is insufficient to hold all Gaussians [S1].
*   Scenarios with significant occlusions (e.g., 'Alameda') where visibility culling is effective [S1].

### When Not to Use
*   Small scenes with negligible occlusions (e.g., single object novel view synthesis), as the overhead of page management may not be justified [S1].
*   Scenes where high-fidelity LOD blending is critical and the current LOD flaws (scale, blending) are unacceptable [S1].

## Background

### Origin and History
Virtual Memory for 3D Gaussian Splatting is based on the concept of Virtual Texturing, originally applied to GPU textures by Barrett [30] and analyzed by Mayer [31] [S1]. The method adapts these concepts to 3DGS by using a proxy mesh for visibility and grouping Gaussians into pages [S1]. The specific implementation described in the source was tested on large-scale scenes like ArtSci, Residence, Alameda, and Berlin [S1].

### Usage
The method is used in large-scale 3DGS rendering to handle scenes exceeding GPU memory [S1]. It was tested on desktop and mobile hardware across various scene types [S1]. The implementation avoids compression to test the virtual memory methods in isolation [S1].
