# Budgeted-GS

Also called: Factoring LOD

## Overview
Budgeted-GS is a post-hoc method that converts any trained 3D Gaussian Splatting (3DGS) model into a multi-resolution hierarchy of moment-matched aggregates, enabling real-time rendering of city-scale scenes on consumer GPUs by selecting the level of detail that fits the target device's memory [S1, unofficial]. It solves the problem of excessive memory consumption in large-scale 3DGS by introducing a "capacity floor" derived from optimal transport, which determines the minimum number of primitives required for a given error budget, allowing the same model to serve GPUs with widely different memory capacities [S1, unofficial]. Unlike standard 3DGS which optimizes a fixed set of primitives, Budgeted-GS separates the representation into a hierarchy where a single quality parameter selects the appropriate level of detail per view, ensuring that redundant primitives are merged or dropped based on a pixel-footprint scheduler [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A trained 3DGS model consisting of a flat set of raw planks (Gaussian primitives) defined by their spatial cells, opacity weights, and value models [S1, unofficial].
*   **Output:** A rendered image stream emitted to any standard splatting rasterizer, where the stream consists of selected primitives from the factoring tree based on the current view and memory budget [S1, unofficial].

**Data Structures:**
The core data structure is the **Factoring Tree**, an octree of scale bands [S1, unofficial].
*   **Nodes:** Each node in the tree corresponds to a leaf in the spatial octree and a specific scale band.
*   **Content:** Nodes contain "moment-matched equivalent planks." These are aggregates of raw planks that preserve the first and second moments (mean and covariance) of the original primitives within that spatial and scale region [S1, unofficial].
*   **Layout:** The tree is structured as `leaf × scale-band`. Raw planks are stored at the finest scale bands, while coarser bands store aggregated planks [S1, unofficial].

**Steps:**
1.  **Construction:** Convert the trained model (flat set of raw planks) into the factoring tree. This involves a construction pass that groups raw planks into scale bands and computes moment-matched equivalent planks for each node [S1, unofficial]. This pass takes a few seconds [S1, unofficial].
2.  **Scheduling:** For each view, determine the level of detail using a one-parameter pixel-footprint scheduler [S1, unofficial].
3.  **Selection:** Select raw, fine, or aggregate content based on the threshold $t$. If the pixel footprint of a primitive is smaller than $t$, use aggregated content; otherwise, use raw or fine content [S1, unofficial].
4.  **Rendering:** Emit the selected stream of primitives to a standard splatting rasterizer [S1, unofficial].

**Formulas:**
The selection threshold $t$ is calculated as:
$$ t = c \cdot \frac{d}{f} $$
Where:
*   $t$: The pixel-footprint threshold [S1, unofficial].
*   $c$: A constant parameter [S1, unofficial].
*   $d$: Distance from the camera to the primitive [S1, unofficial].
*   $f$: Focal length of the camera [S1, unofficial].

The capacity floor, which dictates the minimum number of primitives $N^*$ per tile $j$, is given by:
$$ N^*_j \propto \frac{K_j s_j}{d_j} $$
Where:
*   $K_j$: A constant related to the tile [S1, unofficial].
*   $s_j$: Scale of the primitives in tile $j$ [S1, unofficial].
*   $d_j$: Distance to tile $j$ [S1, unofficial].

**Parameters:**
*   $c$: Constant in the pixel-footprint threshold formula. Typical value not given in the sources.
*   $t$: Threshold for LOD selection.

**Edge Cases and Pitfalls:**
*   **Precision:** The method relies on moment-matching, which may introduce approximation errors when aggregating primitives. The sources mention "bounded volumetric loss" but do not specify the error bounds [S1, unofficial].
*   **Boundaries:** The octree structure handles spatial boundaries, but the scale bands must be carefully defined to ensure smooth transitions between LOD levels.
*   **Degenerate Input:** The method assumes a trained 3DGS model. If the initial model is poorly trained or has insufficient primitives, the factoring tree may not provide significant compression or quality benefits.

**Pseudocode:**
```python
def budgeted_gs_render(camera, scene_model, constant_c):
    """
    Renders a scene using the Budgeted-GS factoring tree.
    
    Args:
        camera: Object containing focal_length (f) and position.
        scene_model: The Factoring Tree (octree of scale bands).
        constant_c: The constant c for the pixel-footprint threshold.
        
    Returns:
        Rendered image.
    """
    # Initialize rasterizer
    rasterizer = SplattingRasterizer()
    
    # Get camera distance to scene center or relevant bounding box
    # Note: Distance d is typically per-primitive or per-tile. 
    # For simplicity, we assume d is computed per primitive in the selection step.
    
    selected_primitives = []
    
    # Traverse the factoring tree
    for node in scene_model.traverse():
        # Calculate distance d from camera to node's center
        d = distance(camera.position, node.center)
        
        # Calculate threshold t
        t = constant_c * (d / camera.focal_length)
        
        # Determine LOD level based on primitive footprint
        # Footprint is approximated by the primitive's size in pixels
        # If primitive size < t, use aggregated (coarser) version
        # Else, use raw/fine version
        
        if node.is_aggregate():
            # Check if aggregation is sufficient
            # This depends on the specific implementation of moment-matched planks
            # For this pseudocode, we assume the node provides both raw and aggregate data
            if node.primitive_footprint < t:
                selected_primitives.extend(node.aggregate_planks)
            else:
                selected_primitives.extend(node.raw_planks)
        else:
            # Leaf nodes or fine nodes
            selected_primitives.extend(node.raw_planks)
            
    # Render the selected primitives
    image = rasterizer.render(selected_primitives)
    return image
```
*Note: The pseudocode above is a high-level representation. The actual implementation requires traversing the octree and computing the pixel footprint of each primitive, which involves projecting the Gaussian covariance to screen space. The "moment-matched equivalent planks" are pre-computed during the construction phase.*

## Subtopics

### Differentiated Quality Modeling via Gaussian Masking
A quality modeling approach that classifies 3DGS videos into four tiers of models with varying qualities using a binary Gaussian mask based on significance distribution, considering both opacity and ellipsoid size to filter out less significant primitives [S2]. It identifies and filters out Gaussian primitives with lower transparency and smaller ellipsoid sizes, as they have minimal impact on rendering quality [S2]. Three distinct masking thresholds are established to classify the 3DGS videos within each Group of Frames (GoF) into four tiers of models with varying qualities [S2]. Thresholds are determined by referencing previously obtained saliency distribution maps and adjusting thresholds based on saliency weights within different tiles; for high-saliency regions, as many Gaussian primitives as possible are retained, while for less visually significant regions, thresholds are increased to exclude unnecessary primitives [S2]. All tiles of different quality levels are encoded to facilitate subsequent delivery from server to client [S2].

## Operating characteristics
*   **Time Complexity:** The construction pass takes a few seconds [S1, unofficial]. Rendering time depends on the number of selected primitives, which is dynamically adjusted by the scheduler.
*   **Memory Complexity:** The method reduces memory usage by aggregating primitives, allowing city-scale scenes to fit on consumer GPUs [S1, unofficial]. The exact memory savings depend on the scene and the chosen quality parameter.
*   **Measured Performance:** Validated on 13 public scenes under a preregistered protocol, demonstrating real-time rendering of city-scale scenes [S1, unofficial].
*   **Scaling:** The method scales to large scenes by using a multi-resolution hierarchy. The capacity floor provides a theoretical limit on the number of primitives needed.
*   **Strengths:** Enables real-time rendering of large-scale scenes on consumer hardware; flexible quality adjustment via a single parameter; avoids wasted optimization effort in training.
*   **Limitations:** Requires a post-hoc construction pass; relies on the accuracy of the moment-matching approximation; performance depends on the scene's complexity and the chosen quality parameter.
*   **When to use:** When rendering large-scale, city-scale scenes on hardware with limited memory.
*   **When not to use:** For small-scale scenes where standard 3DGS fits in memory; when training time is a critical constraint and budget-centered training is not used.

## Background
Budgeted-GS was introduced in the paper "Budgeted-GS: Real-Time Large-Scale Gaussian Splatting via Factoring LOD" [S1, unofficial]. It is grounded in a measurable capacity floor derived from optimal transport in phase space, which answers how many primitives a scene actually needs and how many can safely be given up [S1, unofficial]. The method builds on the principles of 3D Gaussian Splatting [Parent](7342-hierarchical-3d-gaussian-representations.md) but extends it to handle large-scale scenes by introducing a multi-resolution hierarchy and a budget-centered training approach.
