# Cluster Culling (Nanite-style)

Also called: FClusterCullingCS, FClusterCullingResetCS

## Overview
Cluster Culling (Nanite-style) is a hierarchical frustum culling and Level-of-Detail (LOD) selection mechanism for 3D Gaussian Splatting, designed to efficiently manage large sets of clustered splats by discarding invisible or low-priority clusters [S1, unofficial]. It distinguishes itself from sibling methods by implementing a compute-shader-based spatial clustering system that outputs visibility bitmaps and indirect draw arguments, enabling batched rendering of only relevant cluster subsets [S1, unofficial].

## How it works
The method operates in two primary compute shader stages: a reset stage to initialize buffers and a culling stage to determine visibility and LOD.

**Inputs and Outputs:**
*   **Input:** A structured buffer of Gaussian clusters (`ClusterBuffer`), view frustum planes, camera matrices, and culling parameters.
*   **Output:** Visible cluster indices, visibility bitmaps, indirect draw arguments, and LOD-specific cluster lists.

**Data Structures:**
The core input is `FGaussianGPUCluster`. While the exact field layout of `FGaussianGPUCluster` is not explicitly detailed in the provided notes, it is inferred to contain the spatial bounds (e.g., bounding sphere) and LOD metadata required for culling, derived from the parent merging process [S1, unofficial].

The culling system uses the following buffers:
*   `RWStructuredBuffer<uint> VisibleClusterCountBuffer`: Stores the total count of visible clusters.
*   `RWStructuredBuffer<uint> IndirectDrawArgsBuffer`: Stores indirect draw call parameters.
*   `RWStructuredBuffer<uint> ClusterVisibilityBitmap`: Bitmask indicating cluster visibility.
*   `RWStructuredBuffer<uint> SelectedClusterBuffer`: List of visible cluster indices.
*   `RWStructuredBuffer<uint> LODClusterBuffer`: List of clusters for specific LOD levels.
*   `RWStructuredBuffer<uint> LODClusterCountBuffer`: Count of clusters per LOD level.
*   `RWStructuredBuffer<uint> LODClusterSelectedBitmap`: Bitmask for LOD-specific visibility.
*   `RWStructuredBuffer<uint> LODSplatTotalBuffer`: Total splat count per LOD.
*   `RWStructuredBuffer<uint> LODSplatOutputCountBuffer`: Output splat count per LOD.

**Parameters:**
*   `FrustumPlanes`: Array of 6 plane vectors defining the view frustum [S1, unofficial].
*   `ErrorThreshold`: Threshold for screen-space error calculation for LOD selection [S1, unofficial].
*   `LODBias`: Bias applied to LOD selection [S1, unofficial].
*   `MaxDrawDistance`: Maximum distance for cluster visibility [S1, unofficial].
*   `DebugForceLODLevel`: Debug parameter to force a specific LOD level (-1 = auto, 0 = leaf, 1+ = specific level) [S1, unofficial].
*   `THREADGROUP_SIZE`: Compilation define set to 64 for `FClusterCullingCS` [S1, unofficial].
*   `LocalToWorld`, `WorldToClip`: Transformation matrices [S1, unofficial].
*   `CameraPosition`: Camera location [S1, unofficial].
*   `ScreenHeight`: Screen height in pixels [S1, unofficial].
*   `ClusterCount`, `LeafClusterCount`: Counts of clusters [S1, unofficial].
*   `UseLODRendering`: Flag to enable LOD rendering [S1, unofficial].

**Steps:**

1.  **Reset Stage (`FClusterCullingResetCS`):**
    *   Initialize `VisibleClusterCountBuffer` to 0.
    *   Initialize `IndirectDrawArgsBuffer` to 0.
    *   Initialize `ClusterVisibilityBitmap` to 0.
    *   Initialize `SelectedClusterBuffer` to 0.
    *   Initialize `LODClusterBuffer` to 0.
    *   Initialize `LODClusterCountBuffer` to 0.
    *   Initialize `LODClusterSelectedBitmap` to 0.
    *   Initialize `LODSplatTotalBuffer` to 0.
    *   Initialize `LODSplatOutputCountBuffer` to 0.
    *   This prepares the buffers for the subsequent culling pass [S1, unofficial].

2.  **Culling Stage (`FClusterCullingCS`):**
    *   For each cluster `i` in `ClusterBuffer`:
        *   **Frustum Culling:** Test the cluster's bounding sphere against the 6 frustum planes defined in `FrustumPlanes`. If the sphere is completely outside any plane, the cluster is marked as invisible.
        *   **Distance Culling:** Calculate the distance from `CameraPosition` to the cluster center. If the distance exceeds `MaxDrawDistance`, mark as invisible.
        *   **LOD Selection:** If visible, calculate the screen-space error. This involves projecting the cluster's spatial extent to screen space and comparing it against `ErrorThreshold`. Apply `LODBias` to the calculated error. Select the appropriate LOD level based on this error. If `DebugForceLODLevel` is not -1, force the specified LOD.
        *   **Output:**
            *   Set the corresponding bit in `ClusterVisibilityBitmap` to 1 if visible.
            *   Append cluster index `i` to `SelectedClusterBuffer`.
            *   If LOD rendering is enabled (`UseLODRendering`), append cluster index `i` to `LODClusterBuffer` for the selected LOD level and increment `LODClusterCountBuffer` for that LOD.
            *   Update `LODSplatTotalBuffer` and `LODSplatOutputCountBuffer` based on the number of splats in the cluster and the selected LOD.
    *   Write the final count of visible clusters to `VisibleClusterCountBuffer`.
    *   Write the indirect draw arguments to `IndirectDrawArgsBuffer` based on the visible clusters and selected LODs [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** Screen-space error calculation must handle very small or very large clusters without overflow or underflow [G].
*   **Boundaries:** Clusters exactly on the frustum plane boundary should be handled consistently (e.g., included) to avoid flickering [G].
*   **Degenerate Input:** Clusters with zero radius or splat count should be handled gracefully [G].
*   **LOD Thresholds:** The specific thresholds for LOD selection (`LOD_THRESHOLDS`) are not provided in the notes and must be determined empirically or from the parent clustering method's configuration [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ for culling $N$ clusters, as each cluster is processed independently in the compute shader [S1, unofficial].
*   **Memory Complexity:** $O(N)$ for storing cluster data and output buffers [S1, unofficial].
*   **Performance:** Efficient for large scenes with many clusters, as it reduces the number of draw calls and splats processed per frame [S1, unofficial].
*   **Strengths:** Reduces rendering overhead by culling invisible clusters and selecting appropriate LODs [S1, unofficial].
*   **Limitations:** Requires compute shader support and careful tuning of LOD thresholds and error metrics [S1, unofficial].
*   **When to Use:** Large-scale 3D Gaussian Splatting scenes with significant depth variation and visibility changes [S1, unofficial].
*   **When Not to Use:** Small scenes or real-time applications with strict latency constraints where culling overhead might outweigh benefits [G].

## Background
Cluster Culling (Nanite-style) is implemented in the OpenSplat4D project, an unofficial native 4D variant of 3D Gaussian Splatting [S1, unofficial]. It draws inspiration from Nanite-style spatial clustering for efficient LOD and frustum culling [S1, unofficial]. The method is part of a broader effort to support higher-order Spacetime Gaussians and point-cloud asset editing [S1, unofficial].
