# Cluster Culling (Nanite-style)

Also called: FClusterCullingCS, FClusterCullingResetCS

## Overview
Cluster Culling is a hierarchical spatial culling and Level-of-Detail (LOD) selection system for Gaussian splats, implementing Nanite-style spatial clustering to optimize rendering throughput [S1, unofficial]. It solves the problem of efficiently determining which clusters of Gaussians are visible within the view frustum and selecting the appropriate resolution (LOD) for each, thereby reducing the number of draw calls and splats processed [S1, unofficial]. It sets itself apart from sibling merging methods by focusing on the *selection* and *culling* phase of the rendering pipeline rather than the geometric approximation of merged clusters, operating on pre-computed cluster hierarchies to filter visible geometry before rasterization [S1, unofficial].

## How it works
The method operates in two distinct compute shader passes: a reset pass to initialize buffers and a culling pass to determine visibility and LOD.

### Inputs and Outputs
**Inputs:**
*   `ClusterBuffer`: A structured buffer containing `FGaussianGPUCluster` objects. Each cluster represents a node in the hierarchy.
*   `LocalToWorld`: $4 \times 4$ transformation matrix mapping cluster local coordinates to world space.
*   `WorldToClip`: $4 \times 4$ projection matrix mapping world coordinates to clip space.
*   `FrustumPlanes`: An array of 6 `FVector4f` vectors, where each vector represents the plane equation $(A, B, C, D)$ of the view frustum planes (Near, Far, Left, Right, Top, Bottom) in world space.
*   `CameraPosition`: The position of the camera in world space.
*   `ScreenHeight`: The height of the viewport in pixels.
*   `ErrorThreshold`: Scalar threshold for screen-space error calculation.
*   `LODBias`: Scalar bias applied to LOD selection.
*   `MaxDrawDistance`: Maximum distance from the camera for cluster visibility.
*   `LeafClusterCount`: The number of leaf clusters in the hierarchy.
*   `ClusterCount`: The total number of clusters.
*   `UseLODRendering`: Boolean flag indicating if LOD rendering is active.
*   `DebugForceLODLevel`: Integer debug parameter (-1 for auto, 0 for leaf, 1+ for specific level).

**Outputs (UAVs):**
*   `VisibleClusterCountBuffer`: Counter for visible clusters.
*   `IndirectDrawArgsBuffer`: Arguments for indirect draw calls.
*   `ClusterVisibilityBitmap`: Bitmask indicating cluster visibility.
*   `SelectedClusterBuffer`: List of indices of selected visible clusters.
*   `LODClusterBuffer`: List of indices of clusters selected for specific LOD levels.
*   `LODClusterCountBuffer`: Counter for LOD-selected clusters.
*   `LODClusterSelectedBitmap`: Bitmask for LOD-selected clusters.
*   `LODSplatTotalBuffer`: Total count of splats in selected LOD clusters.
*   `LODSplatOutputCountBuffer`: Output count of splats.

### Data Structures
The core data structure is `FGaussianGPUCluster`. While the exact field layout is not fully detailed in the provided notes, it must contain at least:
*   Bounding sphere information (center $\mathbf{c}$, radius $r$) for frustum and distance culling.
*   Hierarchy level information (to distinguish leaf vs. non-leaf clusters).
*   Reference to child clusters or splats (for LOD traversal).

### Parameters
*   `THREADGROUP_SIZE`: Set to 64 for `FClusterCullingCS` [S1, unofficial].
*   `FrustumPlanes`: 6 plane vectors [S1, unofficial].
*   `ErrorThreshold`: Threshold for screen-space error [S1, unofficial].
*   `LODBias`: Bias for LOD selection [S1, unofficial].
*   `MaxDrawDistance`: Max visibility distance [S1, unofficial].
*   `DebugForceLODLevel`: Debug override [S1, unofficial].

### Steps

1.  **Reset Phase (`FClusterCullingResetCS`)**:
    *   Initialize `VisibleClusterCountBuffer` to 0.
    *   Initialize `IndirectDrawArgsBuffer` to 0.
    *   Initialize `ClusterVisibilityBitmap` to 0.
    *   Initialize `SelectedClusterBuffer` to 0.
    *   Initialize `LODClusterBuffer` to 0.
    *   Initialize `LODClusterCountBuffer` to 0.
    *   Initialize `LODClusterSelectedBitmap` to 0.
    *   Initialize `LODSplatTotalBuffer` to 0.
    *   Initialize `LODSplatOutputCountBuffer` to 0.

2.  **Culling Phase (`FClusterCullingCS`)**:
    *   Each thread processes one cluster index $i$.
    *   **Frustum Culling**: Test the cluster's bounding sphere against the 6 frustum planes. A sphere with center $\mathbf{c}$ and radius $r$ is inside plane $(A, B, C, D)$ if $A c_x + B c_y + C c_z + D \ge r$. The cluster is visible if it intersects or is inside all 6 planes.
    *   **Distance Culling**: Calculate distance $d$ from `CameraPosition` to cluster center $\mathbf{c}$. If $d > MaxDrawDistance$, mark as invisible.
    *   **LOD Selection**: If visible, calculate screen-space error. The error is typically proportional to the cluster's world-space radius projected to screen space. If `UseLODRendering` is true:
        *   Determine the appropriate LOD level based on `ErrorThreshold`, `LODBias`, and `ScreenHeight`.
        *   If `DebugForceLODLevel` is not -1, force this level.
        *   If the cluster is a leaf or meets the LOD criteria, add its index to `SelectedClusterBuffer` and update `VisibleClusterCountBuffer`.
        *   If it is a non-leaf cluster selected for a higher LOD, add to `LODClusterBuffer` and update `LODClusterCountBuffer`.
    *   **Bitmap Update**: Set the corresponding bit in `ClusterVisibilityBitmap` if the cluster is visible.

### Pseudocode

```python
# FClusterCullingResetCS
def reset_buffers():
    # Initialize all output buffers to zero
    VisibleClusterCountBuffer[0] = 0
    IndirectDrawArgsBuffer[0] = 0
    ClusterVisibilityBitmap[:] = 0
    SelectedClusterBuffer[:] = 0
    LODClusterBuffer[:] = 0
    LODClusterCountBuffer[0] = 0
    LODClusterSelectedBitmap[:] = 0
    LODSplatTotalBuffer[0] = 0
    LODSplatOutputCountBuffer[0] = 0

# FClusterCullingCS
def cull_clusters(cluster_index):
    cluster = ClusterBuffer[cluster_index]
    
    # 1. Frustum Culling
    visible = True
    for plane in FrustumPlanes:
        # Plane equation: Ax + By + Cz + D >= 0
        # Sphere test: distance from center to plane >= radius
        dist_to_plane = plane.x * cluster.center.x + \
                        plane.y * cluster.center.y + \
                        plane.z * cluster.center.z + \
                        plane.w
        if dist_to_plane < -cluster.radius:
            visible = False
            break
            
    if not visible:
        return

    # 2. Distance Culling
    dx = cluster.center.x - CameraPosition.x
    dy = cluster.center.y - CameraPosition.y
    dz = cluster.center.z - CameraPosition.z
    distance_squared = dx*dx + dy*dy + dz*dz
    
    if distance_squared > MaxDrawDistance * MaxDrawDistance:
        return

    # 3. LOD Selection
    lod_level = 0
    if UseLODRendering:
        # Calculate screen-space error
        # Project cluster radius to screen space
        # This is a simplified approximation; actual implementation may vary
        world_radius = cluster.radius
        # Project center to clip space to get depth
        clip_pos = WorldToClip * float4(cluster.center, 1.0)
        if clip_pos.w > 0:
            ndc_radius = world_radius / clip_pos.w * ScreenHeight * 0.5
            # Determine LOD based on error threshold and bias
            # Higher LOD index means lower resolution
            lod_level = int(log2(nd_radius / ErrorThreshold) + LODBias)
        else:
            lod_level = 0 # Default to leaf if projection fails
            
        if DebugForceLODLevel != -1:
            lod_level = DebugForceLODLevel
            
        # Clamp LOD level
        lod_level = max(0, min(lod_level, cluster.max_lod_level))
        
        # If it's a non-leaf cluster and we selected a higher LOD, 
        # we might cull its children and use this cluster as a proxy
        if lod_level > 0 and not cluster.is_leaf:
            # Add to LOD cluster buffer
            idx = atomic_add(LODClusterCountBuffer[0], 1)
            LODClusterBuffer[idx] = cluster_index
            LODClusterSelectedBitmap[cluster_index // 32] |= (1 << (cluster_index % 32))
            # Add splat count from this cluster
            atomic_add(LODSplatTotalBuffer[0], cluster.splat_count)
        else:
            # It's a leaf or lowest LOD, add to visible cluster buffer
            idx = atomic_add(VisibleClusterCountBuffer[0], 1)
            SelectedClusterBuffer[idx] = cluster_index
            ClusterVisibilityBitmap[cluster_index // 32] |= (1 << (cluster_index % 32))
    else:
        # No LOD, just cull
        idx = atomic_add(VisibleClusterCountBuffer[0], 1)
        SelectedClusterBuffer[idx] = cluster_index
        ClusterVisibilityBitmap[cluster_index // 32] |= (1 << (cluster_index % 32))
```

### Edge Cases and Pitfalls
*   **Precision**: Frustum plane tests are sensitive to floating-point precision. Use robust sphere-plane intersection tests [S1, unofficial].
*   **Boundaries**: Clusters exactly on the frustum boundary may be inconsistently culled due to precision errors. [G] A small epsilon should be added to the radius during frustum culling to ensure consistent inclusion.
*   **Degenerate Input**: Clusters with zero radius or invalid bounding spheres should be handled gracefully, typically by treating them as points or culling them if they are outside the frustum.
*   **LOD Bias**: Incorrect `LODBias` values can lead to excessive detail (performance hit) or excessive coarseness (visual artifacts). [S1, unofficial]

## Operating characteristics
*   **Time Complexity**: $O(M)$ for $M$ clusters, as each cluster is processed in constant time by a single thread in the compute shader.
*   **Memory Complexity**: $O(M)$ for storing visibility bitmaps and buffer indices.
*   **Performance**: Highly efficient on modern GPUs due to parallel processing in compute shaders. The use of indirect draw calls reduces CPU-GPU synchronization overhead.
*   **Strengths**: Reduces rendering overhead by culling invisible clusters and selecting appropriate LODs. Integrates well with hierarchical clustering structures.
*   **Limitations**: Requires pre-computed cluster hierarchies. LOD selection is heuristic and may not always produce optimal visual quality.
*   **When to use**: When rendering large scenes with many Gaussian splats and hierarchical clustering is employed.
*   **When not to use**: For small scenes where the overhead of culling outweighs the benefits, or when non-hierarchical rendering is used.

## Background
Cluster Culling (Nanite-style) is inspired by Nanite, Unreal Engine's virtualized geometry system, which uses hierarchical clustering and culling to render massive amounts of geometry efficiently [S1, unofficial]. It has been adapted for 3D Gaussian Splatting to handle the large number of splats generated by modern Gaussian splatting techniques. The implementation is part of the OpenSplat4D project, which provides tools for 4D Gaussian splatting [S1, unofficial].
