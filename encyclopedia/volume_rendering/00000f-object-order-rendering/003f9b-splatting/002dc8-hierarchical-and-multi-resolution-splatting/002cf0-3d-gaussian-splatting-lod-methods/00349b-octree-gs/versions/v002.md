# Octree-GS

Also called: Octree-GS: Towards Consistent Real-time Rendering with LOD-Structured 3D Gaussians

## Overview
Octree-GS is a Level-of-Detail (LOD) structured approach for 3D Gaussian Splatting that dynamically selects appropriate levels from a set of multi-scale Gaussian primitives organized in an octree, ensuring consistent rendering performance by adapting to viewing distance and scene complexity [S3]. It builds on Scaffold-GS by introducing an explicit octree structure with an accumulative LOD strategy, where rendering at LOD $K$ rasterizes all Gaussian primitives from LOD 0 to $K$ [S3]. Unlike concurrent works where each LOD level independently represents the entire scene, Octree-GS decouples multi-scale primitives into varying LOD levels, enabling finer primitives to capture details while coarse primitives represent low-frequency information, reducing redundancy and pruning unnecessary primitives via a view-frequency strategy [S3].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Sparse Structure-from-Motion (SfM) points, training images with camera poses and intrinsics, base voxel size $\delta$ for LOD 0, and hyperparameters ($r_d, \tau_g, \beta, \epsilon, \tau_v, T, \omega$).
*   **Outputs:** An octree-structured set of anchors, each associated with Gaussian primitives (explicit or neural), optimized for novel view synthesis.

**Data Structures:**
*   **Octree:** A sparse octree with $K$ layers (LOD levels). LOD 0 is the coarsest level.
*   **Anchor:** Each node in the octree is an anchor. An anchor $j$ at level $L_j$ has:
    *   Position: Center of a voxel in the grid for level $L_j$.
    *   Voxel Size: $V_{L_j} = \delta / 2^{L_j}$.
    *   LOD Bias: $\Delta_{L_j}$, a learnable scalar accounting for local complexity.
    *   Gaussians: A set of $k$ Gaussian primitives associated with the anchor.

**Number of Levels:**
The number of octree layers $K$ is determined by the range of distances between camera centers and SfM points:
$$ K = \lfloor \log_2(\hat{d}_{max} / \hat{d}_{min}) \rceil + 1 $$
where $\hat{d}_{max}$ is the $r_d$-th largest distance, $\hat{d}_{min}$ is the $r_d$-th smallest distance, and $\lfloor \cdot \rceil$ denotes the round operator [S3]. The hyperparameter $r_d$ is typically 0.999 to discard outliers [S3].

**Training Steps:**

1.  **Anchor Initialization:**
    *   Compute distances $d_{ij}$ between each camera center $i$ and SfM point $j$.
    *   Determine $\hat{d}_{max}$ and $\hat{d}_{min}$ as the $r_d$-th largest and smallest distances ($r_d=0.999$) [S3].
    *   Calculate $K$ using the formula above.
    *   Construct octree grids with $K$ layers. Voxel size for layer $L$ is $V_L = \delta / 2^L$ [S3].
    *   Initialize anchors at voxel centers.

2.  **Progressive Training:**
    *   Run training for 10k iterations with weight $\omega = 1.5$ [S3].
    *   Extend densification by an additional 10k iterations [S3].
    *   Total iterations: 40k (densification ends at 20k) for small-scale scenes; 100k (densification ends at 50k) for large-scale scenes [S3].

3.  **Anchor Growing (Densification):**
    *   Every $T$ iterations ($T=100$), calculate the average accumulated gradient $\nabla_g$ of spawned Gaussian primitives [S3].
    *   If $\nabla_g > \tau_g$ ($\tau_g=0.0002$), the primitive is significant.
    *   If located in an empty voxel, convert to a new anchor.
    *   **Next-Level Growth:** Assign LOD level based on gradient thresholds. Threshold for level $L$ is $\tau_{gL} = \tau_g \cdot 2^{\beta L}$ ($\beta=0.2$) [S3].
        *   If $\nabla_g > \tau_{g(L+1)}$, promote to level $L+1$.
        *   If $\tau_{gL} < \nabla_g < \tau_{g(L+1)}$, remain at level $L$ [S3].
    *   **LOD Bias Adjustment:** Calculate anchor gradient $\nabla_v$ (average gradient of spawned primitives for that anchor). If $\nabla_v > \tau_{gL} \cdot 0.25$, increase $\Delta_{L_j}$ by $\epsilon$ ($\epsilon=0.01$) [S3].

4.  **Anchor Pruning:**
    *   Compute average opacity of Gaussians generated over $T$ iterations. Remove anchors with low average opacity [S3].
    *   Compute **view-frequency**: probability that anchors are selected in training view frustums.
    *   Remove anchors with view-frequency below visibility threshold $\tau_v$ ($\tau_v=0.7$ for small-scale, $0.01$ for large-scale, $0.2$ for multi-scale) [S3].

## Operating characteristics
*   **Time Complexity:** Rendering is real-time. On the MatrixCity dataset (2k resolution), Octree-GS achieves 57.08 FPS (Our-3D-GS) and 40.91 FPS (Our-Scaffold-GS) across three trajectories, outperforming all baselines which fail to meet real-time performance [S3]. It is up to 10x faster than state-of-the-art methods in large-scale scenes [S3].
*   **Memory Complexity:** Reduces storage overhead by pruning redundant Gaussians. On MatrixCity, it uses 3.59M Gaussians compared to 20.8M for Hierarchical-GS and 13.0M for Scaffold-GS [S3].
*   **Training Time:** Faster than Hierarchical-GS (35 minutes vs 38-69 minutes on Mip-NeRF360) due to single-stage LOD construction and fewer primitives [S3].
*   **Strengths:** Consistent rendering speed irrespective of trajectory changes; handles large-scale and multi-resolution scenes effectively; avoids stroboscopic effects and manual threshold adjustments [S3].
*   **Limitations:** Requires careful tuning of visibility threshold $\tau_v$ for different scene scales [S3].

## Background
Octree-GS was introduced in "Octree-GS: Towards Consistent Real-time Rendering with LOD-Structured 3D Gaussians" [S3]. It addresses the inefficiency of vanilla 3D-GS and Scaffold-GS in zoomed-out views where all primitives are rendered regardless of projected size [S3]. It is the first approach to deal with LOD in Gaussian representation using an explicit octree structure [S3].
