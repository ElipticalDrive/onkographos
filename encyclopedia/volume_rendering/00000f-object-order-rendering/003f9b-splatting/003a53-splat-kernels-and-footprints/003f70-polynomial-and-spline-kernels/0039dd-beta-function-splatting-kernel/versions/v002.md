# Beta Function Splatting Kernel

Also called: Beta distribution splatting, Beta footprint

## Overview
The Beta Function Splatting Kernel is a 2D footprint function used in object-order volume rendering that replaces the standard Normal (Gaussian) distribution with a Beta function to control the shape of the splat [S1, unofficial]. It solves the problem of tuning visual parameters such as opacity, zoom, and shading by allowing independent control over the openness, height, and width of the kernel curve [S1, unofficial]. It sets itself apart from its siblings, such as [Quadratic Spline Splatting](8112-quadratic-spline-splatting.md) and [Raised Cosine Splatting](9916-raised-cosine-splatting.md), by offering smaller footprints for equivalent visual quality, which can result in significantly faster execution times [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Screen coordinates relative to the splat center $(x, y)$, shape parameters $a$ and $b$, scaling factor $k_{scale}$, and voxel density $\rho$.
*   **Outputs:** The weight $W(x,y)$ contributed by the splat to the pixel.

**Data Structures:**
The kernel is defined by a set of parameters:
*   $a, b$: Shape parameters (floats).
*   $k_{scale}$: Scaling factor (float).
*   $x, y$: Normalized coordinates in the range $[0, 1]$ relative to the footprint's local domain.

**Formulas:**
The core Beta function is defined as:
$$ \text{Beta}(x, a, b) = k_{scale} \cdot x^a \cdot (1 - x)^b $$
where $x \in [0, 1]$ [S1, unofficial].

In the context of 2D splatting, the footprint $F(x,y)$ is typically constructed by combining independent 1D Beta profiles along the x and y axes, or by using a radial distance $r$ mapped to $[0,1]$. The source describes using a "kernel base distribution" and scaling factors to generate sections [S1, unofficial]. For a symmetric curve where $a=b$, the function is symmetric around $x=0.5$.

**Parameters:**
*   $a, b$: Control the curve shape. Identical values produce symmetric curves. Lower values produce more 'opened' (wider/flatter) curves [S1, unofficial].
*   $k_{scale}$: Adjusts the range/height of the curve [S1, unofficial].
*   Typical values: Not given in the sources.

**Steps:**
1.  Map the screen-space distance from the splat center to a normalized coordinate $u \in [0, 1]$. This often involves defining a support radius $R$ such that $u = \frac{\sqrt{(x-x_c)^2 + (y-y_c)^2}}{R}$ [G].
2.  Evaluate the Beta function using the mapped coordinate $u$ and parameters $a, b, k_{scale}$:
    $$ W = k_{scale} \cdot u^a \cdot (1 - u)^b $$
3.  Modulate the weight by the voxel density $\rho$:
    $$ P(x,y) = W \cdot \rho $$
4.  Accumulate $P(x,y)$ into the pixel buffer using alpha blending [S1, unofficial].

**Pitfalls:**
*   **Holes:** Holes may appear when voxel opacity decreases, requiring changes in footprint size to maintain continuity between neighbor voxels. This is especially noticeable at feature boundaries in tagged volumes [S1, unofficial].
*   **Precision:** The term $x^a$ can suffer from precision issues if $x$ is very close to 0 and $a$ is large.

**Pseudocode:**
```python
def beta_kernel(u, a, b, k_scale):
    """
    Evaluate the Beta function kernel.
    u: normalized distance in [0, 1]
    a, b: shape parameters
    k_scale: scaling factor
    """
    # Guard against log(0) or 0^0 issues
    if u <= 0.0:
        if a > 0:
            return 0.0
        else:
            # If a=0, limit is 1, but practically handled by k_scale
            return k_scale
    if u >= 1.0:
        if b > 0:
            return 0.0
        else:
            return k_scale
            
    return k_scale * (u ** a) * ((1.0 - u) ** b)

def splat_pixel(screen_x, screen_y, center_x, center_y, radius, a, b, k_scale, density):
    """
    Calculate contribution of a splat to a pixel.
    """
    # Calculate normalized distance
    dist = sqrt((screen_x - center_x)**2 + (screen_y - center_y)**2)
    u = dist / radius
    
    # Clamp u to [0, 1]
    u = max(0.0, min(1.0, u))
    
    weight = beta_kernel(u, a, b, k_scale)
    return weight * density
```

## Subtopics

### [Deformable Beta Splatting](9228-deformable-beta-splatting.md)
An explicit radiance field rendering method that replaces the standard Gaussian kernel with an adaptive, bounded Beta function kernel. It allows the kernel's profile to deform during training via a single learnable parameter, enabling better modeling of sharp boundaries and high-frequency details.

### [Universal Beta Splatting (UBS)](10589-universal-beta-splatting-ubs.md)
An N-dimensional splatting kernel that replaces the Gaussian distribution with a Beta function to enable independent per-dimension shape control, addressing limitations of methods like 6DGS and 7DGS.

## Operating characteristics
*   **Performance:** Beta footprints are smaller than Normal distribution footprints while providing equivalent visual quality. In tested examples, this resulted in execution being twice as fast [S1, unofficial].
*   **Memory:** Not given in the sources.
*   **Strengths:** Smaller footprints reduce the number of pixels touched per splat, improving rasterization speed. The parameters $a$ and $b$ allow easy tuning of openness and width [S1, unofficial].
*   **Limitations:** Holes may appear at feature boundaries if opacity varies significantly, requiring careful tuning of footprint size relative to opacity [S1, unofficial].

## Background
The Beta Function Splatting Kernel was proposed in the context of rendering classified datasets using a feature graph representation [S1, unofficial]. The method was introduced to improve rendering performance by using smaller footprints that are easier to tune under visual changes such as zooming and opacity adjustments [S1, unofficial].
