# EWA Splatting

Also called: EWA Volume Splatting, Elliptical Weighted Average (EWA) Splatting, Elliptical Weighted Average Volume Splatting, Zwicker EWA Volume Splatting, Zwicker EWA splatting

## Overview
EWA Volume Splatting is a high-quality direct volume rendering technique that eliminates aliasing artifacts by replacing the standard footprint function with a band-limited resampling filter [S1, unofficial][S2][S8, unofficial]. It solves the problem of incorrect visibility determination and high-frequency sampling errors inherent in basic splatting, where reconstruction kernels are assumed non-overlapping [S1, S8, unofficial]. It sets itself apart from its parent [Splat Kernels and Footprints](8724-splat-kernels-and-footprints.md) by combining an elliptical Gaussian reconstruction kernel with a Gaussian low-pass filter to produce an aliasing-free footprint, and from alternatives like [Phong Splatting](2802-phong-splatting.md) by prioritizing correct antialiasing over per-pixel surface shading [S2][S15, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Volume data represented as a set of particles (voxels or samples), each with a position, color/emission coefficient, and extinction coefficient. A viewing transformation matrix $\mathbf{W}$ and camera parameters (center of projection, image plane).
*   **Output:** A 2D image where each pixel color is the accumulated contribution of splats composited back-to-front.

**Data Structures:**
*   **Particle:** Contains position $\mathbf{p}$, color $c_\lambda$, extinction $g$, and a 3x3 variance matrix $\mathbf{V}$ defining the 3D elliptical Gaussian kernel shape.
*   **Resampling Filter ($\rho_k$):** A 2D Gaussian footprint defined by a mean $\mathbf{x}_k$ (projected center) and a 2x2 covariance matrix $\mathbf{M}_k^{-1}$ (derived from $\hat{\mathbf{V}}_k + \mathbf{V}_h$).
*   **1D Lookup Table:** Stores values of $e^{-r}$ to accelerate Gaussian evaluation during rasterization [S8, unofficial].

**Steps:**

1.  **Interpret Volume Data:** Treat volume data as a set of absorbing and emitting particles [S6, unofficial][S11].
2.  **Transform to Camera Space:** Map object-space coordinates to camera space using the viewing transformation. Camera space origin is at the center of projection; the image plane is at $u_2 = 1$ [S6, unofficial][S11].
    $$ \mathbf{u}_k = \mathbf{W} \mathbf{p}_k + \mathbf{t} $$
    (Note: $\mathbf{W}$ is the rotational part of the viewing transformation [S6, unofficial][S11]).
3.  **Compute Jacobian:** Calculate the Jacobian matrix $\mathbf{J}_{\mathbf{u}_k}$ of the perspective projection at point $\mathbf{u}_k$ [S6, unofficial][S11].
    $$ \mathbf{J}_{\mathbf{u}_k} = \begin{pmatrix} \frac{1}{u_{k_2}} & 0 & -\frac{u_{k_0}}{u_{k_2}^2} \\ 0 & \frac{1}{u_{k_2}} & -\frac{u_{k_1}}{u_{k_2}^2} \\ \frac{u_{k_0}}{\|\mathbf{u}_k\|} & \frac{u_{k_1}}{\|\mathbf{u}_k\|} & \frac{u_{k_2}}{\|\mathbf{u}_k\|} \end{pmatrix} $$
    where $\|\mathbf{u}_k\| = \sqrt{u_{k_0}^2 + u_{k_1}^2 + u_{k_2}^2}$ [S6, unofficial][S11].
4.  **Transform Variance Matrix:** Transform the 3D Gaussian kernel's variance matrix $\mathbf{V}_k$ from object space to image space [S6, unofficial][S11].
    $$ \mathbf{V}_k^{\text{img}} = \mathbf{J}_{\mathbf{u}_k} \mathbf{W} \mathbf{V}_k \mathbf{W}^T \mathbf{J}_{\mathbf{u}_k}^T $$
5.  **Derive 2D Covariance:** Obtain the 2x2 variance matrix $\hat{\mathbf{V}}_k$ by skipping the third row and column of $\mathbf{V}_k^{\text{img}}$ [S6, unofficial][S11][S15, unofficial].
    *   *Note:* A matrix with a hat symbol denotes the result of skipping its third row and column [S6, unofficial][S11].
6.  **Setup Resampling Filter:** Compute the inverse covariance matrix $\mathbf{M}_k$ for the 2D footprint by adding the low-pass filter variance $\mathbf{V}_h$ (usually the 2x2 identity matrix) to $\hat{\mathbf{V}}_k$ [S6, unofficial][S11].
    $$ \mathbf{M}_k = (\hat{\mathbf{V}}_k + \mathbf{V}_h)^{-1} $$
7.  **Project Center:** Project the voxel center $\mathbf{u}_k$ to screen coordinates $\hat{\mathbf{x}}_k = (x_{k_0}, x_{k_1})^T$ via perspective division [S6, unofficial][S11].
8.  **Rasterize Footprint:** Rasterize the 2D Gaussian footprint $\rho_k(\mathbf{x})$ onto the image plane. The footprint function is:
    $$ \rho_k(\mathbf{x}) = \frac{1}{2\pi |\mathbf{J}_{\mathbf{u}_k}^{-1}| |\mathbf{W}^{-1}| |\hat{\mathbf{V}}_k + \mathbf{V}_h|^{\frac{1}{2}}} e^{-\frac{1}{2} (\mathbf{x} - \mathbf{x}_k)^T \mathbf{M}_k (\mathbf{x} - \mathbf{x}_k)} $$
    Rasterization can be performed using forward differencing with a 1D lookup table for the exponential term [S8, unofficial].
9.  **Composite:** Accumulate splat contributions back-to-front to compute the final image [S6, unofficial][S11].

**Pseudocode:**

```python
import math

def ewa_volume_splatting(volume_particles, W, projection_matrix, image_width, image_height):
    """
    Renders volume data using EWA Volume Splatting.
    
    Args:
        volume_particles: List of dicts with keys:
            'p': (x, y, z) object space position
            'V': 3x3 list of lists (variance matrix in object space)
            'c': (r, g, b) color
            'g': extinction coefficient
        W: 3x3 list of lists (rotational part of viewing transformation)
        projection_matrix: 4x4 OpenGL-style projection matrix
        image_width: int
        image_height: int
        
    Returns:
        2D list of (r, g, b) colors
    """
    # Initialize image buffers
    # We need to accumulate color and weight for proper blending
    # Standard splatting assumes non-overlapping or uses back-to-front alpha blending.
    # EWA typically uses a sheet-buffer or back-to-front accumulation.
    # For simplicity, we assume back-to-front sorting and alpha blending.
    
    # 1. Transform particles to camera space and compute splat parameters
    splats = []
    
    for k, particle in enumerate(volume_particles):
        p_obj = particle['p']
        V_obj = particle['V']
        c = particle['c']
        g = particle['g']
        
        # Transform position to camera space
        # Assuming W is just rotation, we need translation too. 
        # For this simplified model, we assume W includes translation or p is already relative.
        # Standard: u = W * p + t. Here we use W as the full 3x3 rotation and assume 
        # the camera center is handled by the projection logic or p is relative.
        # Let's assume W is the 3x3 rotation part and we need the full view matrix.
        # To keep it self-contained, we assume 'W' passed is the 3x3 rotation.
        # We need the full view transform. Let's assume a standard camera at origin looking down -Z?
        # No, the formula uses u_k. Let's assume we have a function to get camera coords.
        
        # Simplified: Assume p is already in camera space or W handles it.
        # The source defines u_k as camera space coords.
        # Let's assume we have a helper to get u_k from p and W.
        u_k = transform_to_camera(p_obj, W) # Placeholder for full view transform
        
        u0, u1, u2 = u_k
        
        # 2. Compute Jacobian J_u_k
        norm_u = math.sqrt(u0**2 + u1**2 + u2**2)
        if norm_u == 0:
            continue # Avoid division by zero
            
        J = [
            [1.0/u2, 0, -u0/(u2**2)],
            [0, 1.0/u2, -u1/(u2**2)],
            [u0/norm_u, u1/norm_u, u2/norm_u]
        ]
        
        # 3. Transform Variance Matrix V_k
        # V_img = J * W * V_obj * W^T * J^T
        # Note: Source uses W for rotation. If W is just rotation, we need the full transform.
        # Assuming W passed is the rotation part.
        # Matrix multiplication helper
        V_img = mat_mul(mat_mul(mat_mul(J, W), V_obj), mat_transpose(W))
        V_img = mat_mul(V_img, mat_transpose(J))
        
        # 4. Get 2x2 submatrix V_hat_k
        V_hat_k = [
            [V_img[0][0], V_img[0][1]],
            [V_img[1][0], V_img[1][1]]
        ]
        
        # 5. Setup Resampling Filter M_k
        # V_h is usually identity matrix
        V_h = [[1.0, 0.0], [0.0, 1.0]]
        
        V_total = [
            [V_hat_k[0][0] + V_h[0][0], V_hat_k[0][1] + V_h[0][1]],
            [V_hat_k[1][0] + V_h[1][0], V_hat_k[1][1] + V_h[1][1]]
        ]
        
        M_k = mat_inverse(V_total)
        
        # 6. Project Center to Screen
        # Perspective division
        x_k = (u0 / u2, u1 / u2)
        
        # 7. Compute Normalization Factor
        # Det(J^-1) * Det(W^-1) * Det(V_total)^0.5
        # Note: Source formula uses |J^-1| |W^-1|. 
        # |J^-1| = 1/|J|.
        det_J = det(J)
        det_W = det(W)
        det_V_total = det(V_total)
        
        if det_V_total <= 0:
            continue # Invalid covariance
            
        norm_factor = 1.0 / (2.0 * math.pi * abs(det_J) * abs(det_W) * math.sqrt(det_V_total))
        
        splats.append({
            'x_k': x_k,
            'M_k': M_k,
            'norm_factor': norm_factor,
            'c': c,
            'g': g,
            'u2': u2 # For sorting
        })
        
    # 8. Sort splats back-to-front (by camera space depth u2)
    # Note: In camera space, u2 is depth. Larger u2 is further away if looking down -Z?
    # Standard OpenGL: Camera looks down -Z. u2 < 0 is in front.
    # Source says "origin u=0 is at center of projection... image plane u2=1".
    # This implies looking down +Z. So larger u2 is further.
    # Back-to-front means rendering furthest first.
    splats.sort(key=lambda s: s['u2'], reverse=True)
    
    # 9. Rasterize and Composite
    image = [[(0.0, 0.0, 0.0, 0.0) for _ in range(image_width)] for _ in range(image_height)]
    
    for splat in splats:
        x_k = splat['x_k']
        M_k = splat['M_k']
        norm_factor = splat['norm_factor']
        c = splat['c']
        g = splat['g']
        
        # Determine bounding box of the ellipse
        # Eigenvalues of M_k give inverse squared semi-axes.
        # For simplicity, use a fixed radius based on cutoff r (1-3)
        # The support is (x - x_k)^T M_k (x - x_k) <= r^2
        # Approximate bounding box
        # This is complex to compute exactly without eigen decomposition.
        # We iterate over a reasonable bounding box around x_k.
        
        # Get eigenvalues of M_k to find axes
        # M_k is 2x2 symmetric
        a, b = M_k[0][0], M_k[0][1]
        c_m = M_k[1][1]
        
        # Trace and Det
        tr = a + c_m
        dt = a*c_m - b*b
        
        # Eigenvalues
        sqrt_disc = math.sqrt(tr*tr - 4*dt)
        lam1 = (tr + sqrt_disc) / 2.0
        lam2 = (tr - sqrt_disc) / 2.0
        
        # Max radius in screen space
        # r_max = sqrt(r_cutoff^2 / min(lam1, lam2))
        min_lam = min(lam1, lam2)
        if min_lam <= 0:
            continue
            
        r_cutoff = 3.0 # Typical value
        radius = math.sqrt(r_cutoff / min_lam)
        
        x_min = int(max(0, math.floor(x_k[0] - radius)))
        x_max = int(min(image_width - 1, math.ceil(x_k[0] + radius)))
        y_min = int(max(0, math.floor(x_k[1] - radius)))
        y_max = int(min(image_height - 1, math.ceil(x_k[1] + radius)))
        
        for y in range(y_min, y_max + 1):
            for x in range(x_min, x_max + 1):
                # Evaluate Gaussian
                dx = x - x_k[0]
                dy = y - x_k[1]
                
                # Quadratic form
                val = dx * (M_k[0][0] * dx + M_k[0][1] * dy) + dy * (M_k[1][0] * dx + M_k[1][1] * dy)
                
                if val > r_cutoff**2:
                    continue
                    
                # Exponential
                # Use lookup table or math.exp
                exp_val = math.exp(-0.5 * val)
                
                footprint = norm_factor * exp_val
                
                # Alpha blending
                # I_new = I_old * (1 - alpha) + C * alpha
                # Here footprint acts as the alpha contribution (scaled by g and c)
                # Source: I_lambda(x) = sum c_k g_k q_k(x) prod (1 - g_j q_j(x))
                # Simplified: accumulate color and weight
                
                # Current pixel
                curr_r, curr_g, curr_b, curr_a = image[y][x]
                
                # Contribution
                contrib_r = c[0] * g * footprint
                contrib_g = c[1] * g * footprint
                contrib_b = c[2] * g * footprint
                
                # Update
                # Using simple alpha blending for demonstration
                # In true EWA, the footprint IS the alpha/weight
                new_a = curr_a + g * footprint
                if new_a > 1.0:
                    new_a = 1.0
                    
                # Weighted average color
                if new_a > 0:
                    new_r = (curr_r * curr_a + contrib_r) / new_a
                    new_g = (curr_g * curr_a + contrib_g) / new_a
                    new_b = (curr_b * curr_a + contrib_b) / new_a
                else:
                    new_r, new_g, new_b = 0, 0, 0
                    
                image[y][x] = (new_r, new_g, new_b, new_a)
                
    return image

def transform_to_camera(p, W):
    # Simplified: Assume W is 3x3 rotation and translation is 0 for this example
    # In reality, need full 4x4 view matrix
    return (
        W[0][0]*p[0] + W[0][1]*p[1] + W[0][2]*p[2],
        W[1][0]*p[0] + W[1][1]*p[1] + W[1][2]*p[2],
        W[2][0]*p[0] + W[2][1]*p[1] + W[2][2]*p[2]
    )

def mat_mul(A, B):
    return [[sum(A[i][k]*B[k][j] for k in range(3)) for j in range(3)] for i in range(3)]

def mat_transpose(A):
    return [[A[j][i] for j in range(len(A))] for i in range(len(A[0]))]

def mat_inverse(M):
    # Inverse of 2x2 matrix
    a, b = M[0][0], M[0][1]
    c, d = M[1][0], M[1][1]
    det = a*d - b*c
    if det == 0:
        return None
    return [[d/det, -b/det], [-c/det, a/det]]

def det(M):
    if len(M) == 2:
        return M[0][0]*M[1][1] - M[0][1]*M[1][0]
    # 3x3
    a,b,c = M[0]
    d,e,f = M[1]
    g,h,i = M[2]
    return a*(e*i - f*h) - b*(d*i - f*g) + c*(d*h - e*g)
```

**Parameters:**
*   **Cutoff radius $r$:** The Gaussian kernel is truncated where $(\mathbf{t} - \mathbf{p})^T \mathbf{V}^{-1} (\mathbf{t} - \mathbf{p}) \leq r^2$. Typical value: $1 \leq r \leq 3$ [S6, unofficial][S11].
*   **Low-pass filter variance $\mathbf{V}_h$:** Usually chosen to be the 2x2 identity matrix [S6, unofficial][S11].
*   **Reconstruction Kernel:** 3D Elliptical Gaussian [S9, S15, unofficial].

**Edge Cases and Pitfalls:**
*   **Aliasing:** Occurs if reconstruction kernels are assumed non-overlapping but must overlap to avoid artifacts [S1, S8, unofficial].
*   **Numerical Stability:** The centralized conics approach can be numerically unstable when the projection approaches a line [S12, unofficial].
*   **Non-symmetric Kernels:** If 3D kernels are not radially symmetric (e.g., sheared, anisotropic), additional care is required to ensure contributions sum to one [S9, unofficial].
*   **Soft Edges:** Ignoring variations in the attenuation factor means edge aliasing cannot be prevented [S8, unofficial].

## Subtopics

### [Deferred Surface Splatting](1072-deferred-surface-splatting.md)
Deferred Surface Splatting is a rendering technique that converts unstructured point clouds into continuous, shaded surfaces by projecting points as splats into a deferred rendering pipeline. It solves sparse dot cloud aliasing and transparency artifacts by assigning each point sample an extent drawn as a small oriented primitive (a splat) carrying a radially decreasing reconstruction kernel. It differs from its parent [EWA Splatting](1069-ewa-splatting.md) by using screen-aligned spherical impostors with isotropic linear falloff rather than anisotropic, correctly band-limited EWA footprints, trading accurate filtering for a formulation that requires no per-point normals or radii. It differs from siblings like [Phong Splatting](2802-phong-splatting.md) by deferring the lighting calculation to a final screen-space pass, allowing multiple light sources to be applied efficiently without re-projecting geometry [G].

### [Opacity-Thin-Side (OTS)](1155-opacity-thin-side-ots.md)
Opacity-Thin-Side (OTS) is a parameterization scheme for EWA-based splatting that ensures robust gradient-descent optimization by dynamically scaling the learned weight $\theta$ such that the projected amplitude $a'$ equals $\theta$ when viewing the Gaussian along its thinnest side (shortest axis). It differs from standard EWA splatting, which preserves the integral of extinction (mass), and 3D Gaussian Splatting (3DGS), which preserves the 2D projected amplitude regardless of view, by preserving the 3D unbounded integral (view-independent mass) while ensuring the 2D projection behaves as an ordinary integral relative to the thinnest view.

### [OTS (EWA-Based Splatting)](1181-ots-ewa-based-splatting.md)
OTS (Opacity-Thin-Side) is a splatting method using unnormalized Gaussians that preserves the 2D amplitude $a'$ (called 'opacity') across projections, unlike EWA Splatting which preserves the weight $w$. It differs from standard EWA Splatting by requiring a Jacobian determinant correction to preserve the integral of the extinction coefficient under perspective projection.

### [GPU-Accelerated Volume Splatting With Elliptical RBFs](1186-gpu-accelerated-volume-splatting-with-elliptical-rbfs.md)
This method renders scattered volumetric data represented as 3D ellipsoidal Radial Basis Functions (RBFs) using a post-shaded, kernel-centric approach. It extends high-quality image-aligned sheet-buffer splatting to irregular grids by slicing kernels into parallel, image-aligned density planes, rasterizing them as 2D footprints, and compositing them. Unlike fragment-centric methods that evaluate Gaussian functions per pixel, this technique leverages hard-wired GPU polygonal rasterization, achieving two orders of magnitude higher frame rates. It differs from its parent [EWA Splatting](1069-ewa-splatting.md) by supporting general ellipsoidal kernels and using a flat spatial decomposition with active cell lists rather than screen-aligned spherical impostors.

### [Ellipsoidal Kernel Splatting with Warped Slicing](1290-ellipsoidal-kernel-splatting-with-warped-slicing.md)
Ellipsoidal Kernel Splatting with Warped Slicing is a volume rendering technique that represents point samples as 3D ellipsoids and rasterizes them by slicing the ellipsoid into 2D polygons. It solves the problem of efficiently computing the intersection of general ellipsoids with screen-aligned slicing planes on GPU hardware, where direct analytical slicing requires expensive square roots and conditional statements. The method warps the slicing planes from screen space into the coordinate system of a unit sphere, allowing the use of hard-wired GPU texture mapping and blending on radially symmetric kernel slices. It differs from its parent [EWA Splatting](1069-ewa-splatting.md) by explicitly slicing the kernel into discrete polygons for incremental rasterization rather than rasterizing the entire projected footprint, and it avoids the pre-integrated slab approach of earlier image-aligned splatting by using point-sampled slices.

### [Perspective Correct Splat Rasterization with EWA Approximation](2095-perspective-correct-splat-rasterization-with-ewa-approximati.md)
This method is an improved splat rendering pipeline that combines a perspectively correct fast splat rasterization procedure with an approximation of the Elliptical Weighted Average (EWA) filter. It solves the problem of aliasing artifacts and visual holes in point-sampled geometry rendering, particularly when the model is viewed from flat angles or shifted from the viewing axis. Unlike its siblings, it uses an affine approximation to the projective mapping to ensure perspective-correct splat shapes without requiring per-point normals or complex anisotropic footprint calculations, trading exact band-limited footprints for a formulation that avoids holes and Moiré patterns. It builds on [EWA Splatting](1069-ewa-splatting.md) by replacing the standard EWA covariance computation with a faster, perspective-correct affine approximation.

### [Adaptive EWA Volume Splatting](2137-adaptive-ewa-volume-splatting.md)
Adaptive EWA Volume Splatting is a rendering technique that simplifies the computationally expensive Elliptical Weighted Average (EWA) resampling filter by classifying volume particles into three cases based on their distance from the viewpoint. It solves the problem of high computational cost in full EWA splatting while maintaining aliasing-free quality. Unlike full EWA splatting, which always computes the combined covariance of the reconstruction and low-pass filters, this method uses only the reconstruction filter for close particles (magnification) and only the low-pass filter for far particles (minification), resorting to full EWA only in the transition zone.

### [EWA Approximation with Tangent Vector Adjustment](2143-ewa-approximation-with-tangent-vector-adjustment.md)
A high-quality filtering technique for point-based rendering that approximates the EWA resampling filter by dynamically adjusting the tangent vectors of isotropic splats during setup to prevent aliasing during minification, without requiring expensive per-fragment convolution. It sets itself apart from the original EWA framework by using projective mapping and tangent adjustment rather than affine mapping and Gaussians for both reconstruction and low-pass filters, and from Botsch et al. [BHZK05] by avoiding per-fragment filter evaluation, thus eliminating the fragment shader bottleneck.

### [Phong Splatting](2802-phong-splatting.md)
Phong Splatting is a surface splatting technique that assigns a linearly varying normal field to each elliptical splat, enabling per-pixel Phong shading without surface connectivity. It solves the piecewise constant shading artifacts of standard point-based rendering by providing smooth, Phong-like shading quality on modern GPUs. Unlike its sibling [EWA Splatting](1069-ewa-splatting.md), which uses a simplified isotropic kernel, Phong Splatting uses elliptical splats with projectively correct per-pixel parameterization, trading the simplicity of isotropic filtering for superior visual quality and exact depth values.

### [EWA Splatting Renderer (Mesh-Free)](4665-ewa-splatting-renderer-mesh-free.md)
A mesh-free rendering pipeline that projects raw point clouds directly to 2D camera views using EWA projection and Z-buffer occlusion, producing RGB images, label maps, and 2D-to-3D index maps without mesh reconstruction. It differs from its parent [EWA Splatting](1069-ewa-splatting.md) by using simplified screen-aligned spherical impostors with isotropic linear falloff, trading anisotropic, correctly band-limited footprints for a formulation that requires no per-point normals or radii.

## Operating characteristics
*   **Time Complexity:** The computation of the EWA footprint is expensive due to matrix inversions and determinant calculations for each particle [S6, unofficial][S11]. Adaptive EWA splatting reduces this cost by simplifying the filter for distant particles [S6, unofficial][S11].
*   **Memory Complexity:** Requires storage for the 1D lookup table and the splat parameters (position, covariance, color, extinction) [S8, unofficial].
*   **Measured Performance:** Rendering time was approximately 11 seconds per frame on an 866 MHz Pentium-III processor for the UNC CT scan, engine, and foot datasets [S1, S8, S10, unofficial].
*   **Strengths:** Provides high-quality antialiasing without excessive blurring, handles arbitrary elliptical kernels, and supports perspective projection efficiently [S2][S8, S15, unofficial].
*   **Limitations:** Computationally expensive compared to basic splatting; assumes self-occlusion is ignored and emission coefficient is constant in the support of each footprint [S8, unofficial].
*   **When to Use:** When high-quality, aliasing-free volume rendering is required, especially for non-spherical kernels or perspective views [S2][S8, unofficial].
*   **When Not to Use:** When real-time performance is critical and basic splatting quality is sufficient, or when hardware acceleration for EWA is not available [S6, unofficial].

## Background
EWA Volume Splatting was introduced by Matthias Zwicker, Hanspeter Pfister, Jeroen van Baar, and Markus Gross in 2001 [S8, unofficial]. It is named after Heckbert's EWA filter for texture mapping due to the similarity in derivation [S7, abstract only, unofficial][S8, unofficial]. The method addresses the limitations of Westover's original splatting framework, which did not deal with sampling rate changes due to perspective projections, leading to aliasing artifacts [S8, unofficial]. It has been used in various volume rendering applications, including medical imaging (CT scans) and scientific visualization [S8, S10, unofficial].
