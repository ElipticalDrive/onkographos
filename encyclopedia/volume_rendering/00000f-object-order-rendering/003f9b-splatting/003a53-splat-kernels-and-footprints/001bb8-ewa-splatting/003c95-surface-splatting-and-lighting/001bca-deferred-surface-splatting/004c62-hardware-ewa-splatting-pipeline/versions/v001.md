# Hardware EWA Splatting Pipeline

Also called: Hardware-assisted EWA splatting, Splat rasterization unit

## Overview
The Hardware EWA Splatting Pipeline is a specialized GPU architecture designed to render Elliptical Weighted Average (EWA) splats in a single pass, addressing the inefficiencies of multi-pass software implementations on standard graphics hardware [S1]. It solves the problem of accurate attribute accumulation and normalization for point-based surfaces by introducing a frame buffer-sized surface reconstruction buffer and a ternary depth test, allowing splats to be processed with maximum reuse of existing GPU units [S1]. Unlike standard triangle rasterization, which processes discrete primitives, this pipeline defers shading until after splat contributions are accumulated, enabling any fragment shading program to be used on the reconstructed surface [S1].

## How it works
The pipeline operates by routing splats through a dedicated surface reconstruction buffer before they proceed to fragment shading and final frame buffer blending [S1]. This architecture compensates for standard GPUs lacking dedicated splat rasterizers, specific blending modes for normalization, and ternary depth tests [S1].

### Inputs and Outputs
*   **Input:** A stream of EWA splats defined by center $c$, normal $n$, and tangent vectors $u, v$ in object space, along with vertex attributes $a$.
*   **Output:** A shaded image in the final frame buffer, with depth and attributes correctly accumulated and normalized.

### Data Structures
**Surface Reconstruction Buffer:**
A frame buffer-sized buffer that stores intermediate splat contributions. It requires double buffering for efficient operation and fast clears [S1]. The buffer holds depth, color, and other attributes before they are normalized and fed back into the traditional graphics pipeline [S1].

**Splat Representation:**
Each splat is defined by:
*   $c$: Center in object space.
*   $n$: Normal in object space.
*   $u, v$: Tangent vectors in object space.
*   $a$: Vertex attributes (e.g., color, opacity).

### Numbered Steps

1.  **Splat Transformation and Lighting (Vertex Shader Stage):**
    For each splat, transform the center and tangents to screen space and compute lighting.
    *   Transform center to camera space: $c_0 = PM c$ [S1].
    *   Project center to screen space: $c'_0 = M c$ [S1]. *Note: The source lists $c_0$ and $c'_0$ with different transformations ($PM$ vs $M$), implying distinct intermediate states or a typo in the source notation, but both are used for subsequent steps.*
    *   Transform tangents: $u_0 = M u$, $v_0 = M v$ [S1].
    *   Compute unnormalized normal: $\tilde{n}_0 = u_0 \times v_0$ [S1].
    *   Backface culling: If $\langle c'_0, \tilde{n}_0 \rangle > 0$, the splat is backfacing and is killed [S1].
    *   Normalize normal: $n_0 = \tilde{n}_0 / \|\tilde{n}_0\|$ [S1].
    *   Compute lighting: $a_s = \text{lighting}(a, c'_0, n_0)$ [S1].

2.  **Rasterization Setup (Fixed Function/Custom Unit):**
    Compute the bounding rectangle and projection parameters for the EWA splat.
    *   Construct transformation matrix $T$ from clip space to canonical splat: $T = \begin{pmatrix} u' & v' & c' \\ 0 & 0 & 1 \end{pmatrix} P^T$ in $\mathbb{R}^{3 \times 4}$ [S1].
    *   Compute denominator $d$: $d = \langle \langle 1, 1, -1 \rangle, (T_4 \cdot T_4) \rangle$ [S1].
    *   Compute vector $f$: $f = \frac{1}{d} \langle 1, 1, -1 \rangle$ [S1].
    *   Compute center of projected splat $\pi_i$: $\pi_i = \langle f, (T_i \cdot T_4) \rangle$ [S1].
    *   Compute half extents $h_i$: $h_i = \sqrt{\pi_i^2 - \langle f, (T_i \cdot T_i) \rangle}$ [S1].

3.  **Splat Rasterization and Accumulation:**
    *   Since standard GPUs lack a dedicated rasterizer for splat bounding rectangles, the bounding box is traversed, and pixels overlapping the splat are identified [S1].
    *   For each pixel covered by the splat, compute the EWA weight and accumulate attributes into the **Surface Reconstruction Buffer**.
    *   This stage requires a **ternary depth test** (pass, fail, accumulate) to handle depth values exactly like other attributes, which standard GPUs lack [S1].
    *   Attribute accumulation imposes a heavy burden on frame buffer caches due to kernel overlap; a novel **reordering stage** is proposed to improve caching efficiency over typical frame buffer caches [S1].

4.  **Deferred Shading and Resolve:**
    *   Once all splats have been accumulated in the Surface Reconstruction Buffer, the pipeline feeds back "readily reconstructed fragments" into the traditional graphics pipeline [S1].
    *   This implements deferred shading for splats, allowing any fragment shading program to be used [S1].
    *   The accumulated attributes are normalized and blended into the final frame buffer using extended blending functionality [S1].

### Edge Cases and Pitfalls
*   **Backface Culling:** Splats must be checked for backfacing using $\langle c'_0, \tilde{n}_0 \rangle > 0$ to avoid rendering invisible surfaces [S1].
*   **Cache Performance:** Attribute accumulation imposes a heavy burden on frame buffer caches due to splat kernel overlap. Current caches may not be optimal, necessitating the novel reordering stage [S1].
*   **Hardware Limitations:** Standard GPUs lack the necessary blending modes for accurate accumulation and normalization in a single pass, and lack a normalizing depth test hardware unit supporting ternary depth tests [S1].

## Operating characteristics
*   **Time Complexity:** Single-pass rendering of EWA splats, assuming hardware support for ternary depth tests and extended blending [S1].
*   **Memory Complexity:** Requires a frame buffer-sized surface reconstruction buffer with double buffering [S1].
*   **Performance:** The architecture aims to make maximum reuse of existing GPU units, avoiding the inefficiency of multi-pass software implementations [S1].
*   **Strengths:** Enables deferred shading for splats, allowing any fragment shading program to be used; single-pass rendering; improved caching efficiency via reordering [S1].
*   **Limitations:** Requires custom hardware units (rasterizer, ternary depth test, extended blending) not present in standard GPUs; heavy memory bandwidth requirements if caches are not efficient [S1].
*   **When to use:** When high-performance, single-pass EWA splatting is required and hardware support for the specific extensions is available or emulated via FPGA/ASIC [S1].
*   **When not to use:** On standard GPUs without the required hardware extensions, as it would require inefficient multi-pass software emulation [S1].

## Background
The Hardware EWA Splatting Pipeline was introduced to address the performance issues of implementing EWA splatting on modern programmable GPUs, which resulted in relatively inefficient multi-pass algorithms [S1]. It builds on the concept of deferred shading [Deering et al. 1988; Botsch et al. 2005] and integrates with existing triangle rendering functionality [S1]. The design was detailed in a paper describing a hardware architecture for surface splatting, including implementations on FPGA, ASIC, and Mesa [S1].
