# Phong Splatting

Also called: Per-pixel lighting splatting, Phong Splat Generation, Splatting with linear normal fields, Surface Splats

## Overview
Phong Splatting is a surface rendering technique that assigns a linearly varying normal field to each elliptical splat, enabling per-pixel Phong shading without surface connectivity [S1]. It solves the piecewise constant shading artifacts of standard point-based rendering by approximating the surface curvature within each splat, achieving visual quality comparable to triangle mesh Phong shading with significantly fewer primitives [S1].

## How it works
### Inputs and Outputs
**Input:** A dense set of surface sample points $P = \{p_i\}$, where each $p_i$ has position $\mathbf{p}_i$ and normal $\mathbf{n}_i$.
**Output:** A set of optimized elliptical surface splats $S_j$, where each splat $S_j$ is defined by:
*   Center position $\mathbf{c}_j$ (3 floats).
*   Scaled orthogonal tangent vectors $\mathbf{u}_j, \mathbf{v}_j$ (6 floats).
*   Linear normal field parameters: center normal representation $(\bar{x}, \bar{y})$ and gradients $\alpha, \beta$ (4 floats).
*   Clip line parameters $(a, b, c)$ if the splat is clipped (3 floats, optional) [S1].

Total: 17 floating-point values per splat (or 14 if unclipped) [S1].

### Data Structures
Each splat $S_j$ stores:
1.  `center`: $\mathbf{c}_j \in \mathbb{R}^3$
2.  `tangent_u`: $\mathbf{u}_j \in \mathbb{R}^3$
3.  `tangent_v`: $\mathbf{v}_j \in \mathbb{R}^3$
4.  `normal_bar_x`: $\bar{x}$
5.  `normal_bar_y`: $\bar{y}$
6.  `normal_grad_x`: $\alpha$
7.  `normal_grad_y`: $\beta$
8.  `clip_a`: $a$ (0 if not clipped)
9.  `clip_b`: $b$ (0 if not clipped)
10. `clip_c`: $c$ (0 if not clipped)

### Splat Generation (Preprocessing)
1.  **Splat Optimization:** Generate an initial set of elliptical splats approximating $P$ within error tolerance $\epsilon$ using local principal curvature estimation and global relaxation [S1]. Align $\mathbf{u}_j, \mathbf{v}_j$ with principal curvature directions [S1].
2.  **Coverage Assignment:** For each splat $S_j$, identify the subset $P_j \subseteq P$ of input samples contained in the elliptical cylinder generated by offsetting the splat in the normal direction by $\epsilon$ and $-\epsilon$ [S1].
3.  **Normal Field Fitting:**
    *   Represent each input normal $\mathbf{n}_i \in P_j$ in the local frame spanned by $\mathbf{u}_j, \mathbf{v}_j, \mathbf{u}_j \times \mathbf{v}_j$.
    *   Set the third coordinate (along the normal) to 1. The normal is represented as a point $(x_i, y_i)$ on an offset tangent plane [S1].
    *   Solve for the center normal $(\bar{x}, \bar{y})$ and gradients $\alpha, \beta$ using least squares. The $x$ and $y$ components are uncoupled, resulting in two $2 \times 2$ linear systems [S1]:
        $$
        \begin{pmatrix} |P_j| & \sum u_i \\ \sum u_i & \sum u_i^2 \end{pmatrix} \begin{pmatrix} \bar{x} \\ \alpha \end{pmatrix} = \begin{pmatrix} \sum x_i \\ \sum x_i u_i \end{pmatrix}
        $$
        $$
        \begin{pmatrix} |P_j| & \sum v_i \\ \sum v_i & \sum v_i^2 \end{pmatrix} \begin{pmatrix} \bar{y} \\ \beta \end{pmatrix} = \begin{pmatrix} \sum y_i \\ \sum y_i v_i \end{pmatrix}
        $$
    *   If $|P_j| < 2$ (underdetermined), compute the least-norm solution using the pseudo-inverse [S1].

### Rendering Pipeline
The rendering is performed on modern GPUs using vertex and fragment shaders.

1.  **Vertex Processing:**
    *   Transform splat center $\mathbf{c}_j$ to window coordinates.
    *   Transform tangents $\mathbf{u}_j, \mathbf{v}_j$ and center normal to eye-space [S1].
    *   Compute the image-space square size $size$ to rasterize:
        $$
        size = 2r \frac{n}{z_{eye}} \frac{h_{vp}}{t-b}
        $$
        where $r$ is the larger ellipse radius, $z_{eye}$ is the depth of $\mathbf{c}_j$, $n$ is the near plane distance, $t, b$ are far/near frustum parameters, and $h_{vp}$ is viewport height [S1].
    *   Precompute the scaled normal $\mathbf{n} \cdot (\mathbf{c}^T \mathbf{n})^{-1}$ for ray intersection [S1].
    *   Set OpenGL point size to $size$.

2.  **Fragment Processing (Per Pixel):**
    *   **Ray Intersection:** For the current window pixel $(x, y)$, compute the point $\mathbf{q}_n$ on the near plane by inverting the viewport transformation [S1]:
        $$
        \mathbf{q}_n = \begin{pmatrix} x \frac{w_h}{w_{vp}} - \frac{w_h}{2} \\ y \frac{h_n}{h_{vp}} - \frac{h_n}{2} \\ -n \end{pmatrix}
        $$
        where $w_{vp}, h_{vp}$ are viewport width/height and $w_h, h_n$ are near plane width/height [S1].
    *   Intersect the ray from the eye through $\mathbf{q}_n$ with the splat's supporting plane to find $\mathbf{q}$ in eye-space [S1]:
        $$
        \mathbf{q} = \mathbf{q}_n \frac{\mathbf{c}^T \mathbf{n}}{\mathbf{q}_n^T \mathbf{n}}
        $$
    *   **Inside Test:** Compute local parameters $u, v$ [S1]:
        $$
        u = \mathbf{u}_j^T(\mathbf{q} - \mathbf{c}_j), \quad v = \mathbf{v}_j^T(\mathbf{q} - \mathbf{c}_j)
        $$
        If $u^2 + v^2 > 1$, discard the fragment [S1].
    *   **Clipping Test:** If the splat has clip parameters $(a, b, c)$, discard if $au + bv + c < 0$ [S1].
    *   **Normal Computation:** Compute the interpolated normal vector $\mathbf{n}_{frag}$ using the linear field [S1]:
        $$
        \mathbf{n}_{frag} = \begin{pmatrix} \bar{x} + \alpha u + \beta v \\ \bar{y} + \dots \end{pmatrix} \text{ (in local frame)}
        $$
        Transform $\mathbf{n}_{frag}$ back to eye-space and normalize [S1].
    *   **Lighting:** Compute color using per-pixel Phong lighting. Use a cube map to store precomputed lighting terms (diffuse/specular intensities) as a function of normal vectors. For achromatic lights, store diffuse and specular in a luminance-alpha cube map [S1].
    *   **Depth:** Compute exact fragment depth $z_{frag}$ from $\mathbf{q}$ for robust blending [S1].

3.  **Blending and Normalization:**
    *   **Pass 1 (Visibility Splatting):** Render splats with radially decreasing weights. Accumulate weighted color and depth using alpha blending [S1].
    *   **Pass 2 (Normalization):** Render a viewport-sized quad textured with the accumulated results. Perform per-pixel division by the sum of weights in a pixel shader [S1].

# Preprocessing: Normal Field Fitting
def fit_normal_field(P_j, u_j, v_j):
    """
    P_j: list of (x_i, y_i, u_i, v_i)
    Returns: (bar_x, bar_y, alpha, beta)
    """
    n = len(P_j)
    sum_u = sum(p[2] for p in P_j)
    sum_v = sum(p[3] for p in P_j)
    sum_u2 = sum(p[2]**2 for p in P_j)
    sum_v2 = sum(p[3]**2 for p in P_j)
    sum_x = sum(p[0] for p in P_j)
    sum_y = sum(p[1] for p in P_j)
    sum_xu = sum(p[0]*p[2] for p in P_j)
    sum_yv = sum(p[1]*p[3] for p in P_j)
    
    # Solve for x component: [[n, sum_u], [sum_u, sum_u2]] * [bar_x, alpha] = [sum_x, sum_xu]
    det_x = n * sum_u2 - sum_u**2
    if abs(det_x) < 1e-9:
        bar_x, alpha = 0.0, 0.0 # Pseudo-inverse fallback for underdetermined
    else:
        bar_x = (sum_x * sum_u2 - sum_xu * sum_u) / det_x
        alpha = (n * sum_xu - sum_x * sum_u) / det_x
        
    # Solve for y component: [[n, sum_v], [sum_v, sum_v2]] * [bar_y, beta] = [sum_y, sum_yv]
    det_y = n * sum_v2 - sum_v**2
    if abs(det_y) < 1e-9:
        bar_y, beta = 0.0, 0.0
    else:
        bar_y = (sum_y * sum_v2 - sum_yv * sum_v) / det_y
        beta = (n * sum_yv - sum_y * sum_v) / det_y
        
    return bar_x, bar_y, alpha, beta

# Rendering: Fragment Shader Logic
def render_phong_splat(splat, window_pixel, eye_pos, near_plane_dist, frustum_params, viewport):
    """
    splat: {center, u, v, bar_x, bar_y, alpha, beta, clip_a, clip_b, clip_c}
    window_pixel: (x, y)
    Returns: (color, depth) or None if discarded
    """
    # 1. Invert Viewport to get point on near plane
    x, y = window_pixel
    w_vp, h_vp = viewport.width, viewport.height
    w_h, h_n = near_plane_dist.width, near_plane_dist.height # Dimensions of near plane
    n = near_plane_dist.dist
    
    q_n = vec3(
        x * (w_h / w_vp) - (w_h / 2),
        y * (h_n / h_vp) - (h_n / 2),
        -n
    )
    
    # 2. Intersect ray with splat plane
    # Plane defined by center c and normal n (eye-space)
    c = splat.center
    n_vec = splat.normal # Eye-space normal
    
    # Precomputed scaled normal: n_vec / (c dot n_vec)
    # q = q_n * (c dot n) / (q_n dot n)
    denom = dot(q_n, n_vec)
    if abs(denom) < 1e-9:
        return None # Parallel to plane
        
    scale = dot(c, n_vec) / denom
    q = q_n * scale
    
    # 3. Compute local parameters u, v
    # u = u_j^T (q - c)
    # v = v_j^T (q - c)
    diff = q - c
    u = dot(splat.u, diff)
    v = dot(splat.v, diff)
    
    # 4. Inside test
    if u*u + v*v > 1.0:
        return None
        
    # 5. Clipping test
    if splat.clip_a != 0 or splat.clip_b != 0 or splat.clip_c != 0:
        if splat.clip_a * u + splat.clip_b * v + splat.clip_c < 0:
            return None
            
    # 6. Compute interpolated normal
    # Local normal vector (x, y) on offset plane
    local_n_x = splat.bar_x + splat.alpha * u + splat.beta * v # Note: beta applies to v, but formula in source uses beta for y-gradient
    # Correction: Source Eq 2 implies:
    # x_comp = bar_x + alpha * u + beta * v ?? 
    # Source text: "x component ... alpha", "y component ... beta"
    # Eq 2: [x_bar, y_bar] + [u_i, v_i] * [alpha, beta]^T ??
    # Actually Eq 2 is: [x_bar, y_bar] + [u_i alpha + v_i beta] is NOT correct.
    # Source Eq 2: [x_bar, y_bar] + [u_i, v_i] * [alpha, beta] -> This implies x depends on u*alpha and y on v*beta?
    # Let's re-read carefully: "x and y components are uncoupled".
    # Eq 3 solves for bar_x, alpha. Eq 4 solves for bar_y, beta.
    # So x_local = bar_x + alpha * u
    # y_local = bar_y + beta * v
    local_n_x = splat.bar_x + splat.alpha * u
    local_n_y = splat.bar_y + splat.beta * v
    
    # Construct local normal vector (x, y, 1) in tangent frame
    local_normal = vec3(local_n_x, local_n_y, 1.0)
    
    # Transform to eye-space
    # Frame is u, v, n_vec
    eye_normal = splat.u * local_normal.x + splat.v * local_normal.y + splat.normal * local_normal.z
    eye_normal = normalize(eye_normal)
    
    # 7. Lighting
    # Use cube map lookup for precomputed lighting terms based on eye_normal
    color = lookup_lighting_cube_map(eye_normal) * splat.color
    
    # 8. Depth
    depth = q.z # Eye-space depth
    
    return (color, depth)

### Parameters and Typical Values
*   **Error Tolerance $\epsilon$:** Determines the thickness of the elliptical cylinder for coverage. Not given in the sources.
*   **Cube Map Resolution:** Not given in the sources.
*   **Rendering Passes:** 2 passes (Visibility Splatting + Normalization) [S1].

### Edge Cases and Pitfalls
*   **Underdetermined Systems:** If a splat covers fewer than 2 samples, the linear systems for normal fitting are underdetermined. Compute the least-norm solution using the pseudo-inverse [S1].
*   **Affine Approximation:** Using an affine approximation to projective mapping enables EWA splatting but sacrifices projective correctness. This method avoids affine approximation, providing exact parameters for shape, normal, and clipping, but disables EWA. Using the object-space reconstruction filter alone is sufficient in practice [S1].
*   **Clipping Order:** Render non-clipped splats first, then splats with one or two clipping lines to minimize shader switching overhead [S1].
*   **Backface Culling:** A conservative backface test can be performed in the vertex program based on the transformed normal field [S1].

## Operating characteristics
*   **Time Complexity:** Rendering is $O(N)$ where $N$ is the number of splats, with constant-time per-pixel operations (6 instructions in fragment shader) [S1].
*   **Memory Complexity:** 17 floats per splat. However, Phong splats require an order of magnitude fewer primitives than flat shading for comparable quality, reducing overall memory consumption [S1].
*   **Performance:** Achieves up to 4 million Phong shaded, filtered, and blended splats per second on modern GPUs [S1].
*   **Quality:** Visual quality comparable to Phong shading in triangle mesh rendering with 3k splats, whereas flat shading requires 170k splats and flat shading with Gaussian blending requires 33k splats [S1].
*   **Strengths:** Projectively correct, exact per-pixel depth for robust blending, superior shading quality without connectivity [S1].
*   **Limitations:** Cannot use EWA splatting (combined object/image space filtering) due to lack of affine approximation [S1].

## Background
Phong Splatting was introduced by [S1] (Specht et al., 2004) as an advancement over previous point-based rendering methods like QSplat and Surfels. It builds on the concept of varying normal fields proposed by [KV01] but adapts it for dense range-scanned point clouds where connectivity is absent. The method addresses the limitations of constant normal vectors in standard splatting, which result in flat or Gouraud-like shading artifacts. It is predominantly used for rendering point clouds from range scanners and surfaces extracted from volumes [S2, unofficial].
