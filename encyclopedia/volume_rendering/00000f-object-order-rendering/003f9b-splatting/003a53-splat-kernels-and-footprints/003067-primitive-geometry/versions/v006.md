# Primitive Geometry
## Overview
Primitive Geometry is the foundational family of splatting methods that decompose volumetric data into explicit geometric or parametric primitives (such as voxels, tetrahedra, or line segments) which are transformed and rasterized in screen space [S1, S3, S4]. It differs from ray-casting by computing contributions per primitive rather than per pixel, leveraging hardware-accelerated rasterization for real-time performance [S3].

## Shared principles
The splatting family shares the fundamental mechanism of treating volumetric data as a set of geometric or parametric primitives that are transformed and rasterized [S1, S3, S4].
1. **Primitive Representation:** The volume is decomposed into primitives. These may be explicit geometric shapes (cubes, cells, splats) or implicit functions sampled via texture hardware [S1, S6, S10]. Each primitive $k$ is defined by its position $\mathbf{p}_k$, density/extinction coefficient $g_k$ or $\rho_k$, and a reconstruction kernel $h$ (typically a Gaussian) [S1, S6, S10].
2. **Transformation:** Primitives are transformed from volume space to screen space using the Model-View-Projection (MVP) matrix or specific factorizations (e.g., shear-warp) [S2, S3, S4]. For perspective projections, the kernel shape may be distorted (e.g., EWA splatting) to account for foreshortening [S6, S10].
3. **Rasterization:** The transformed primitives are projected onto the 2D image plane. This step leverages hardware-accelerated scan-conversion, depth testing, and blending [S1, S2, S3, S4]. The contribution of a voxel $D$ to a screen point $(x,y)$ is determined by the footprint function $F(x,y)$, which is the integral of the 3D kernel along the view direction [S2, S6, S10]:
$$ F(x,y) = \int h(x-x_D, y-y_D, z) \, dz $$
The intensity written to the pixel is modulated by the voxel density:
$$ P(x,y) = \text{weight}(x,y) \cdot \rho(D) $$
where $\text{weight}(x,y) = F(x-x_D, y-y_D)$ [S10].
4. **Compositing:** Contributions are accumulated to form the final image. This is typically done using alpha blending in back-to-front or front-to-back order to handle transparency correctly [S1, S2, S3, S7]. Splatting compositing is performed along sheets (all pixels at once for a set of voxels), whereas ray-casting composites along rays (one sample at a time) [S10].
5. **Hardware Acceleration:** Most methods in this family rely on GPU rasterization pipelines for performance, enabling real-time interactivity [S1, S2, S3].

## Subtopics

### [Circle Splat Rendering](2981-circle-splat-rendering.md)
Projects volumetric primitives as 2D quads in screen space, explicitly constructing quad geometry with size derived from voxel grid scale and splat parameter for consistent coverage and efficient frustum culling. Choose when consistent coverage and hardware culling are prioritized over exact kernel shapes.

### [Line Capsule Primitive](3131-line-capsule-primitive.md)
Renders line-based volumetric data as rotationally symmetric capsules in screen space, solving visual continuity at joints via deficit-rule composition. Choose for streamlines or fiber tracts where gaps or double brightness at corners must be avoided.

### [Tetrahedral Splatting](3181-tetrahedral-splatting.md)
Renders unstructured tetrahedral meshes by approximating each tetrahedron with a single spherical or ellipsoidal splat, operating directly on unstructured geometric primitives. Choose for real-time visualization of large unstructured meshes where topological preservation is not strictly required.

### [Voxel Splat Rendering](3730-voxel-splat-rendering.md)
Projects 3D voxels onto the 2D image plane as geometric primitives (quads/circles) for interactive visualization, distinct from ray-casting by computing contributions per voxel. Choose for regular grid data where interactive parameter tuning and subset selection are needed.

### [Decomposition](7254-decomposition.md)
Converts volumetric data into explicit geometric primitives (spheres/slices) placed and colored by transfer functions, suitable for geometric processing like segmentation. Choose when the volume needs to be converted into discrete geometric assets for downstream processing.

### [Triangle Mesh Splatting](8109-triangle-mesh-splatting.md)
Approximates continuous splat kernels with triangle meshes to leverage standard GPU rasterization for rapid scan-conversion of kernel footprints. Choose when polygonal approximation of kernels is preferred over analytical footprint evaluation.

### [Resonant Brane Splatting](9845-resonant-brane-splatting.md)
Replaces standard 2D Gaussian splats with "Branes" that emit spatially varying colors using Gaussian-Hermite modes, enabling super-resolution without dense overlapping splats. Choose for arbitrary-scale super-resolution tasks requiring local contrast and sharp edges.
