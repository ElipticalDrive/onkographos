# Decomposition
Also called: Primitive Decomposition, Geometric Primitive Decomposition

## Overview
Decomposition is an image-order volume rendering technique that converts a volumetric data set into a collection of explicit geometric primitives, such as spheres or slices, which are then placed, scaled, and colored based on a transfer function mapping [S1, unofficial][S2, unofficial]. It distinguishes itself from ray-casting and standard splatting by explicitly treating the volume as a set of discrete geometric objects rather than a continuous scalar field or a set of splatted footprints, making it particularly suitable for applications requiring further geometric processing like segmentation [S1, unofficial][S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar volume dataset $V$ and a transfer function $T$ that maps scalar values to color and opacity.
*   **Output:** A 2D image generated by rasterizing the decomposed primitives.

**Data Structures:**
The volume is decomposed into a list of primitives $\mathcal{P} = \{p_1, p_2, \dots, p_N\}$. Each primitive $p_i$ is defined by:
*   **Geometry:** A parametric shape (e.g., sphere center $\mathbf{c}_i$ and radius $r_i$, or slice plane equation and extent).
*   **Attributes:** A scalar value $v_i$ sampled from the volume, which determines the primitive's color $\mathbf{C}_i = T(v_i)$ and opacity $\alpha_i = T_{\alpha}(v_i)$.

**Steps:**
1.  **Decomposition:** Iterate through the volume data. For each voxel or region of interest, generate a corresponding geometric primitive.
    *   *Sphere Decomposition:* Each voxel or cluster of voxels is represented by a sphere. The sphere's position is the voxel center, and its radius may be fixed or scaled by the local density/value.
    *   *Slice Decomposition:* The volume is sliced into 2D planes. Each slice is treated as a textured quad or height map.
2.  **Transformation:** Transform the primitives from volume space to screen space using the Model-View-Projection (MVP) matrix. For spheres, this involves transforming the center and scaling the radius according to the projection matrix's perspective division. For slices, this involves transforming the plane equation or vertices.
3.  **Coloring and Scaling:** Apply the transfer function to the scalar value associated with each primitive to determine its visual properties (color and opacity). Scale the primitives if the method uses value-dependent sizing (e.g., larger spheres for higher density).
4.  **Rasterization:** Render the primitives using standard graphics pipeline rasterization.
    *   For spheres, this typically involves depth testing and blending.
    *   For slices, this involves rendering textured quads or height maps, often with pseudo-coloring [S2, unofficial].
5.  **Compositing:** Accumulate the contributions of overlapping primitives. Since primitives are explicit, standard alpha blending or depth-based occlusion handling is used. Back-to-front sorting may be required for correct transparency if the primitives are not depth-sorted by the hardware.

**Parameters:**
*   **Primitive Type:** Sphere or Slice. Not given in the sources.
*   **Transfer Function:** Maps scalar values to color/opacity. Not given in the sources.
*   **Radius Scaling:** Factor for sphere radius based on scalar value. Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Occlusion:** Explicit primitives may suffer from incorrect occlusion if depth sorting is not handled correctly, especially for transparent spheres.
*   **Discretization Artifacts:** The choice of primitive size and spacing can lead to visible gaps or overlaps, affecting the visual continuity of the volume.
*   **Performance:** The number of primitives can be very large, leading to high draw call overhead if not instanced or batched.

## Subtopics

### [Curve-Skeleton Decomposition](8486-curve-skeleton-decomposition.md)
Curve-Skeleton Decomposition is a proxy geometry technique that represents a volumetric object as a 1D line-like structure (skeleton or centerline) to enable bend, move, re-pose, and sweep transformations. It solves the problem of interactive manipulation of volumetric data by decomposing the volume into bounding cuboids along the skeleton, allowing independent transformation and rendering of segments. Unlike direct volume deformation, this method separates the geometric abstraction from the rendering, enabling fast, minimum-geometric-processing manipulation.

## Operating characteristics
*   **Time Complexity:** Depends on the number of primitives $N$ and the complexity of the rasterization. Typically $O(N)$ for decomposition and $O(N \log N)$ or $O(N)$ with sorting for compositing.
*   **Memory Complexity:** $O(N)$ to store the primitives.
*   **Strengths:** Allows for standard geometric processing (segmentation, manipulation) on the primitives; leverages hardware rasterization for speed; suitable for real-time interaction if the number of primitives is managed.
*   **Limitations:** May not capture fine details as well as ray-casting; occlusion handling for transparent primitives can be complex; performance degrades with very high resolution data if not optimized.
*   **When to Use:** When the volume needs to be treated as a set of geometric objects for further processing or manipulation; when real-time interaction is required and the data can be approximated by primitives.
*   **When Not to Use:** When high-fidelity continuous volume visualization is required; when the data has complex internal structures that are not well-represented by simple primitives.

## Background
Decomposition methods were identified as one of the five main image-order volume rendering techniques in early surveys of interactive volume rendering [S1, unofficial][S2, unofficial]. The approach leverages the explicit nature of geometric primitives to bridge the gap between volume data and traditional computer graphics pipelines.
