# Circle Splat Rendering


## Overview
Circle Splat Rendering is a volume rendering technique where voxels are projected as 2D quads (splats) in screen space to approximate spherical primitives [S1, unofficial]. It solves the problem of efficiently rendering large voxel datasets by bypassing ray-marching in favor of object-order rasterization, using a fixed offset to determine quad size based on a splat size parameter and grid scale [S1, unofficial]. It differs from Voxel Splat Rendering by explicitly calculating a clip-space bounding box for frustum culling based on the projected half-edge length, ensuring that only splats intersecting the view frustum are processed [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A stream of voxel points, each containing position, color, and normal data.
*   **Uniforms:** Model-View matrix ($MV$), Projection matrix ($P$), entity scale ($scale$), grid length ($gridLength$), splat size parameter ($splatSize$), and a boolean flag for back-face culling ($cullInvisibleFaces$).
*   **Output:** A triangle strip representing a quad for each voxel, rasterized with interpolated color and normal.

**Data Structures**
The input data structure per vertex (point primitive) contains:
*   `position`: `vec3` (voxel center in world or local space, transformed by model matrix before geometry shader).
*   `color`: `vec4` (RGBA color).
*   `normal`: `vec3` (surface normal).

**Algorithm Steps**
1.  **Transform to View Space:** Multiply the input voxel position by the Model-View matrix ($MV$) to obtain `voxelPosViewSpace`.
2.  **Transform to Clip Space:** Multiply `voxelPosViewSpace` by the Projection matrix ($P$) to get `voxelPosClipSpace`. Perform perspective division by dividing by $w$ to normalize clip coordinates.
3.  **Calculate Voxel Offset:** Compute the physical offset in view space using the formula:
    $$voxelOffset = splatSize \times \frac{scale}{gridLength} \times \sqrt{2}$$
    where $\sqrt{2} \approx 1.414213$ [S1, unofficial].
4.  **Calculate Clip-Space Half-Edge:**
    *   Compute the clip-space position of the right edge midpoint of the quad in view space:
        $$voxelRightEdgeMidPointClipSpace = P \times \begin{bmatrix} voxelPosViewSpace.x + 0.5 \times voxelOffset \\ voxelPosViewSpace.y \\ voxelPosViewSpace.z \\ voxelPosViewSpace.w \end{bmatrix}$$
    *   Perform perspective division on this midpoint.
    *   Calculate the Euclidean distance in clip space between the normalized voxel center and this midpoint:
        $$voxelHalfEdgeLengthClipSpace = distance(voxelPosClipSpace, voxelRightEdgeMidPointClipSpace)$$
5.  **Frustum Culling:** Define a culling border:
    $$voxelFrustumCullingBorder = 1 + voxelHalfEdgeLengthClipSpace$$
    Discard the primitive if the normalized clip-space coordinates ($x$ or $y$) of the voxel center fall outside $[-voxelFrustumCullingBorder, voxelFrustumCullingBorder]$ [S1, unofficial].
6.  **Back-Face Culling:** If $cullInvisibleFaces$ is true:
    *   Transform the voxel normal to view space: $normalViewSpace = MV \times [normal, 0]^T$.
    *   Calculate the dot product between the view vector (from voxel to camera, approximated as $-voxelPosViewSpace$) and the normal.
    *   Discard if $dot(-voxelPosViewSpace.xyz, normalViewSpace.xyz) < 0$ [S1, unofficial].
7.  **Emit Vertices:** Emit four vertices forming a triangle strip (bottom-left, bottom-right, top-left, top-right) in view space, offset by $\pm 0.5 \times voxelOffset$, transformed by $P$, and assigned texture coordinates $(0,0), (1,0), (0,1), (1,1)$ [S1, unofficial].

**Pseudocode**
```python
# Geometry Shader Logic for Circle Splat Rendering
# Input: Single point per voxel
# Uniforms: MV, P, scale, gridLength, splatSize, cullInvisibleFaces

def process_voxel(voxel_pos_world, voxel_color, voxel_normal):
    # 1. Transform to View Space
    voxel_pos_view = MV * vec4(voxel_pos_world, 1.0)
    
    # 2. Transform to Clip Space and Normalize
    voxel_pos_clip = P * voxel_pos_view
    voxel_pos_clip /= voxel_pos_clip.w
    
    # 3. Calculate Voxel Offset
    # sqrt(2) approx 1.414213
    voxel_offset = splatSize * (scale / gridLength) * 1.414213
    
    # 4. Calculate Clip-Space Half-Edge Length
    # Right edge midpoint in view space: x + 0.5*offset, y, z, w
    right_edge_view = vec4(
        voxel_pos_view.x + 0.5 * voxel_offset,
        voxel_pos_view.y,
        voxel_pos_view.z,
        voxel_pos_view.w
    )
    right_edge_clip = P * right_edge_view
    right_edge_clip /= right_edge_clip.w
    
    half_edge_length = distance(voxel_pos_clip.xy, right_edge_clip.xy)
    frustum_border = 1.0 + half_edge_length
    
    # 5. Frustum Culling
    if (voxel_pos_clip.x < -frustum_border or voxel_pos_clip.x > frustum_border or
        voxel_pos_clip.y < -frustum_border or voxel_pos_clip.y > frustum_border):
        return # Discard primitive

    # 6. Back-Face Culling
    if cull_invisible_faces:
        normal_view = MV * vec4(voxel_normal, 0.0)
        # View vector is from voxel to camera (origin in view space)
        view_vector = -voxel_pos_view.xyz
        if dot(view_vector, normal_view.xyz) < 0:
            return # Discard primitive

    # 7. Emit Quad Vertices (Triangle Strip)
    # Offsets: (-0.5, -0.5), (0.5, -0.5), (-0.5, 0.5), (0.5, 0.5)
    offsets = [
        vec2(-0.5, -0.5),
        vec2(0.5, -0.5),
        vec2(-0.5, 0.5),
        vec2(0.5, 0.5)
    ]
    tex_coords = [
        vec2(0, 0),
        vec2(1, 0),
        vec2(0, 1),
        vec2(1, 1)
    ]
    
    for i in range(4):
        offset = offsets[i]
        tex_coord = tex_coords[i]
        
        # Vertex position in view space
        vert_view = vec4(
            voxel_pos_view.x + offset.x * voxel_offset,
            voxel_pos_view.y + offset.y * voxel_offset,
            voxel_pos_view.z,
            voxel_pos_view.w
        )
        
        # Transform to clip space
        vert_clip = P * vert_view
        
        # Emit vertex
        emit_vertex(vert_clip, voxel_color, normal_view)
        
    end_primitive()
```

**Parameters**
*   $splatSize$: Uniform float controlling the base size of the splat.
*   $scale$: Entity scale factor.
*   $gridLength$: Grid length factor.
*   $cullInvisibleFaces$: Boolean flag for back-face culling.

**Edge Cases and Pitfalls**
*   **Precision:** Perspective division must be performed on both the center and the edge midpoint before calculating the distance to ensure accurate clip-space bounding [S1, unofficial].
*   **Degenerate Input:** If $gridLength$ is zero, the offset calculation will fail; this must be guarded against [G].
*   **Boundary:** The frustum culling border includes the half-edge length to prevent splats from being culled if they partially intersect the view frustum [S1, unofficial].

## Subtopics

### Square Splat
A variant where the projection is strictly axis-aligned without the diagonal offset calculation, often used for simpler voxel representations. [Square Splat](square-splat.md)

### Voxel Splat Rendering
Uses voxel-based primitives for volume rendering, differing in how the splat size is derived and how density is accumulated. [Voxel Splat Rendering](3730-voxel-splat-rendering.md)

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of voxels, as each voxel is processed independently in the geometry shader.
*   **Memory Complexity:** $O(N)$ for storing voxel data.
*   **Performance:** Efficient for large datasets due to early frustum culling in clip space, reducing rasterization load. Performance scales with the number of visible voxels and the complexity of the back-face culling check.
*   **Strengths:** Simple implementation, hardware-accelerated rasterization, effective culling.
*   **Limitations:** Order-dependent blending requires sorting or alpha blending; does not handle internal volume density as naturally as ray-marching methods.
*   **When to Use:** Real-time visualization of large voxel datasets where approximate spherical representation is acceptable.
*   **When Not to Use:** When accurate internal volume density or complex lighting interactions within the volume are required.

## Background
Circle Splat Rendering, also known as square_splat, originates from the SVO Renderer project by mmalesadev [S1, unofficial]. It is used in the context of Sparse Voxel Octree (SVO) rendering to visualize voxel data efficiently using GPU geometry shaders.
