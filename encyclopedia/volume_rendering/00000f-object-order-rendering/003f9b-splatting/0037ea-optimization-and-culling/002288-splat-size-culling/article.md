# Splat Size Culling

Also called: Culling Small Splats

## Overview
Splat Size Culling is a staging optimization in object-order volume rendering that discards splats smaller than a defined threshold to reduce computational workload and improve real-time frame rates [S1]. It trades off visual quality for performance by ignoring splats whose contribution to the final image is deemed negligible, distinguishing itself from sibling methods like [Early Splat Termination](811-early-splat-termination.md) which operate during the rasterization phase rather than the data staging phase.

## How it works
**Inputs and Outputs:**
*   **Input:** A set of splats (e.g., 3D Gaussian splats) defined by position, covariance, opacity, and color.
*   **Output:** A filtered subset of splats ready for rasterization.

**Data Structures:**
The splat data structure typically includes fields for center position $\mathbf{c}$, covariance matrix $\mathbf{C}$ (or rotation/scale), opacity $\alpha$, and color coefficients. The specific layout depends on the underlying representation (e.g., 3DGS), but the culling logic relies on the geometric extent derived from the covariance.

**Method:**
1.  **Threshold Definition:** Define a minimum radius or area threshold $T$. This threshold represents the minimum projected size a splat must have to be considered visually significant.
2.  **Extent Estimation:** For each splat, estimate its projected extent on the screen. This is typically derived from the covariance matrix $\mathbf{C}$ and the view projection. A common approximation uses the eigenvalues of the projected covariance to determine the bounding box or radius.
3.  **Comparison:** Compare the estimated projected size (e.g., radius $r$ or area $A$) against the threshold $T$.
    *   If $r < T$ (or $A < T$), discard the splat.
    *   Otherwise, keep the splat for staging.
4.  **Staging:** Pass only the kept splats to the rendering pipeline.

**Parameters:**
*   **Threshold ($T$):** Not given in the sources. The value is chosen based on the desired balance between quality and performance. Users can disable culling entirely to capture high-quality screenshots [S1].

**Edge Cases and Pitfalls:**
*   **Small Splat Scenes:** This approach fails for scenes composed entirely of small splats, such as models constructed via Mesh2Splat, as all splats may be discarded or the visual quality degrades significantly [S1].
*   **Quality Trade-off:** Disabling culling is necessary for high-quality offline rendering or screenshots [S1].

## Subtopics

## Operating characteristics
*   **Performance:** On the GardenF scene, culling reduces staged splats from 5.79M to 1.25M and fragments from 8.16M to 1.99M, decreasing render time from 9.7 ms to 2.1 ms [S1].
*   **Scaling:** The method is effective for scenes with a mixture of widely varying splat sizes, such as those generated by 3DGS, where many small splats can be safely discarded even at greater distances [S1].
*   **Limitations:** It is not suitable for scenes consisting solely of small splats (e.g., Mesh2Splat models) [S1].
*   **Quality:** Visual quality is reduced when culling is enabled, but can be restored by disabling the optimization [S1].

## Background
Splat Size Culling is described in the context of "Splatshop," an efficient editing tool for large Gaussian Splat models [S1]. The method leverages the observation that reconstruction applications prioritize quality, whereas interactive editing and rendering can afford to reduce quality to maintain real-time frame rates [S1].
