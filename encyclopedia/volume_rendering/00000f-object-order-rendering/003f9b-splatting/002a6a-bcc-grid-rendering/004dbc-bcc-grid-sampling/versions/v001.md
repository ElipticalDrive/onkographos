# BCC Grid Sampling

Also called: BCC Lattice Sampling, Body Centered Cartesian

## Overview
BCC Grid Sampling uses a Body-Centered Cartesian (BCC) lattice to store volume data, requiring fewer sample points than a standard Cubic Cartesian (CC) grid while maintaining lossless compression for spherically bandlimited signals [S1, unofficial]. It is distinct from CC sampling by its higher packing efficiency for isotropic signals and is best suited for point-based object-order methods that employ spherical filters, whereas CC grids are more common in general-purpose rendering [S1, unofficial].

## How it works
**Inputs:** A continuous volumetric signal $f(\mathbf{x})$ that is spherically bandlimited.
**Outputs:** A discrete set of sample values stored on a BCC lattice.

**Data Structures:**
The BCC lattice is defined as the dual of the Face-Centered Cartesian (FCC) lattice [S1, unofficial]. It consists of two interleaved CC grids. If the base CC grid has a sampling interval of $\Delta$, the BCC grid samples are located at integer coordinates $(x, y, z)$ such that $x+y+z$ is even (forming one CC sublattice) and at half-integer coordinates $(x+0.5, y+0.5, z+0.5)$ where $x+y+z$ is even (forming the second CC sublattice) [S1, unofficial]. This structure implies that the BCC grid requires $\frac{\pi}{2\sqrt{2}} \approx 0.71$ (or 71%) of the samples of a usual cubic Cartesian (CC) grid for the same spatial coverage [S1, unofficial].

**Numbered Steps:**
1.  **Define Lattice Geometry:** Determine the generator matrix or coordinate condition for the BCC lattice. The BCC lattice $\Lambda_{BCC}$ can be viewed as the set of points $\mathbf{x} \in \mathbb{R}^3$ such that $\mathbf{x}$ belongs to the dual of the FCC lattice. In practice, this is often implemented by storing two interleaved CC grids or by using a specific stride/access pattern [S1, unofficial].
2.  **Sample the Signal:** Evaluate the continuous volume signal $f(\mathbf{x})$ at each lattice point $\mathbf{x}_i \in \Lambda_{BCC}$.
3.  **Store Samples:** Store the resulting values in memory. Due to the 71% sample reduction, memory usage is significantly lower than CC sampling for the same resolution [S1, unofficial].
4.  **Reconstruct (Rendering):** During rendering, reconstruct the continuous signal from the discrete BCC samples using a reconstruction filter.
    *   **Critical Constraint:** The reconstruction filter must be spherically (radially) symmetric to preserve the spherical shape of the BCC grid-sampled volume’s frequency spectrum [S1, unofficial].
    *   **Pitfall:** Using trilinear filters for reconstruction leads to aliasing because the trilinear filter's frequency response is not radially symmetric, causing it to include higher spectra that were not present in the original bandlimited signal [S1, unofficial].

**Pseudocode:**
```python
def sample_bcc_volume(volume_function, grid_size, spacing):
    """
    Samples a continuous volume function onto a BCC lattice.
    
    Args:
        volume_function: Callable f(x, y, z) returning the density/value.
        grid_size: Tuple (nx, ny, nz) defining the bounding box dimensions.
        spacing: Float delta, the base CC grid spacing.
        
    Returns:
        A list of tuples (x, y, z, value) representing the BCC samples.
    """
    samples = []
    # BCC lattice points are those where (x + y + z) is even in a CC grid
    # with spacing 'spacing'. We iterate over integer indices and scale.
    
    for x_idx in range(grid_size[0]):
        for y_idx in range(grid_size[1]):
            for z_idx in range(grid_size[2]):
                # Check parity condition for BCC lattice subset 1
                if (x_idx + y_idx + z_idx) % 2 == 0:
                    x = x_idx * spacing
                    y = y_idx * spacing
                    z = z_idx * spacing
                    value = volume_function(x, y, z)
                    samples.append((x, y, z, value))
                    
                # Subset 2: Half-integer offsets
                # These correspond to the "body center" of the CC cells
                # where the sum of the integer parts is even.
                # Note: The source [S1, unofficial] describes BCC as two interleaved CC grids.
                # The second grid is offset by (0.5, 0.5, 0.5) relative to the first.
                # We must ensure we cover the entire volume.
                # A simpler implementation often used is iterating all integers
                # and checking the parity, then adding the offset points if within bounds.
                
    # Add the second interleaved CC grid (offset by 0.5, 0.5, 0.5)
    # This grid contains points where the underlying integer coordinates sum to even.
    for x_idx in range(grid_size[0] - 1): # Adjust bounds for offset
        for y_idx in range(grid_size[1] - 1):
            for z_idx in range(grid_size[2] - 1):
                if (x_idx + y_idx + z_idx) % 2 == 0:
                    x = (x_idx + 0.5) * spacing
                    y = (y_idx + 0.5) * spacing
                    z = (z_idx + 0.5) * spacing
                    # Check if within volume bounds
                    if is_within_volume(x, y, z, grid_size, spacing):
                        value = volume_function(x, y, z)
                        samples.append((x, y, z, value))
                        
    return samples

def reconstruct_bcc_point(x, y, z, samples, filter_func):
    """
    Reconstructs value at (x,y,z) using spherical filter.
    """
    # Find nearest BCC neighbors
    neighbors = find_bcc_neighbors(x, y, z, samples)
    value = 0.0
    for (nx, ny, nz, nv) in neighbors:
        dist = sqrt((x-nx)**2 + (y-ny)**2 + (z-nz)**2)
        # Must use radially symmetric filter (e.g., spherical box, sinc, or Gaussian)
        # Trilinear is INVALID for BCC [S1, unofficial]
        weight = filter_func(dist)
        value += nv * weight
    return value
```

**Parameters:**
*   **Filter Type:** Must be radially symmetric (e.g., spherical box spline, isotropic Gaussian). Trilinear filters are explicitly discouraged [S1, unofficial].
*   **Spacing:** The base CC grid spacing $\Delta$. The effective sampling density is $\frac{\pi}{2\sqrt{2}} \approx 0.71$ times that of CC [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Aliasing:** Reconstructing a BCC grid with trilinear filters causes aliasing because the trilinear filter's frequency response is not radially symmetric [S1, unofficial].
*   **Boundary Conditions:** The two interleaved CC grids may have different boundary behaviors; care must be taken to ensure the second grid (offset by 0.5) does not sample outside the defined volume bounds [S1, unofficial].
*   **Non-Spherical Signals:** If the signal is not spherically bandlimited, the optimality of BCC may not hold, and FCC might be preferred [S2].

## Subtopics

### FCC Lattice Sampling
FCC Lattice Sampling uses a Face-Centered Cartesian lattice, defined as a subset of the Cartesian lattice where $x+y+z$ is even, or via the generator matrix $G = \begin{bmatrix} 0 & 1 & 1 \\ 1 & 0 & 1 \\ 1 & 1 & 0 \end{bmatrix}$ [S2]. It offers better sampling efficiency than the Cartesian lattice and is optimal for signals sampled at a depressed rate, whereas BCC is optimal for band-limited and isotropic signals [S2]. It is used in medical datasets, GPU ray casting, and mobile volume rendering [S2].

## Operating characteristics
*   **Memory Efficiency:** BCC grids require approximately 71% of the samples of a CC grid for the same spatial resolution, reducing memory footprint by ~29% [S1, unofficial].
*   **Performance:** In benchmarks on the "Foot" dataset, BCC rendering took 70% of the time of CC rendering, indicating a significant speedup [S1, unofficial].
*   **Strengths:** Reduced memory bandwidth and storage costs for isotropic, spherically bandlimited signals; faster rendering due to fewer samples [S1, unofficial].
*   **Limitations:** Requires spherical reconstruction filters; incompatible with standard trilinear interpolation pipelines without quality loss (aliasing) [S1, unofficial]. Not optimal for signals sampled at a depressed rate (FCC is preferred there) [S2].
*   **When to Use:** Point-based object-order methods (e.g., splatting, ray casting with spherical kernels) where memory bandwidth is a bottleneck and the signal is isotropic [S1, unofficial].
*   **When Not to Use:** When using standard trilinear interpolation or when the signal is not spherically bandlimited [S1, unofficial].

## Background
The BCC lattice is the dual of the FCC lattice [S1, unofficial]. The relationship between BCC and CC sampling densities is derived from the Fourier scaling theorem, where the spacing of samples in the spatial domain is reciprocal to that in the frequency domain [S1, unofficial]. The efficiency of BCC over CC for 3D volumes is a known result in sampling theory, extending to higher dimensions (e.g., 4D BCC uses 50% of 4D CC samples) [S1, unofficial]. The use of BCC in volume rendering was highlighted in comparisons showing nearly identical visual quality to CC but with reduced computation time [S1, unofficial].
