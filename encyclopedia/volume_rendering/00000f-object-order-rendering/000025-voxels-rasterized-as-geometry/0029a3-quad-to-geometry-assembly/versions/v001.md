# Quad-to-Geometry Assembly

Also called: Quad BufferGeometry Conversion, quadsToGeometry

## Overview
Quad-to-Geometry Assembly converts a list of axis-aligned quads (typically generated by greedy meshing or voxel culling) into a flat, GPU-ready vertex buffer and index buffer. It solves the problem of translating abstract quad primitives into the specific memory layouts required by WebGL/OpenGL `BufferGeometry` or `Mesh` objects. It differs from sibling methods like [Instancing with Procedural/Shader Generation](2794-instancing-with-procedural-shader-generation.md) by pre-computing all vertex data on the CPU, whereas instancing pushes the geometry generation into the vertex shader.

## How it works
**Inputs:**
- `quads`: An array of quad objects. Each quad object contains:
  - `axis`: The normal direction of the quad (e.g., 0 for X, 1 for Y, 2 for Z).
  - `dir`: The winding direction or orientation (used for index generation).
  - `slice`: The coordinate along the axis perpendicular to the quad face.
  - `u`, `v`: The start coordinates in the two dimensions parallel to the quad face.
  - `w`, `h`: The width and height of the quad in voxel units.
  - `material`: An integer index identifying the material type.
- `scale`: A global multiplier for position coordinates (default 1.0).

**Outputs:**
- `positions`: A `Float32Array` containing vertex coordinates.
- `normals`: A `Float32Array` containing vertex normals.
- `colors`: A `Float32Array` containing vertex colors (RGB).
- `indices`: A `Uint16Array` or `Uint32Array` containing triangle indices.

**Data Structures:**
The output arrays are flat and interleaved by attribute type, not by vertex.
- `positions`: Size `quads.length * 12` (4 vertices × 3 floats).
- `normals`: Size `quads.length * 12` (4 vertices × 3 floats).
- `colors`: Size `quads.length * 12` (4 vertices × 3 floats).
- `indices`: Size `quads.length * 6` (2 triangles × 3 indices).

**Material Colors:**
The method uses a predefined lookup table `MATERIAL_COLORS` to map material indices to RGB values:
- Index 0: `[0.0, 0.0, 0.0]` (Air/Unused)
- Index 1: `[0.24, 0.72, 0.48]` (1-surface)
- Index 2: `[0.46, 0.33, 0.23]` (2-dirt)
- Index 3: `[0.44, 0.47, 0.55]` (3-stone)
- Index 4: `[0.13, 0.83, 0.93]` (4-crystal)

**Algorithm Steps:**
1. Calculate the total number of vertices: `vertexCount = quads.length * 4`.
2. Determine the index type. If `vertexCount > 65535`, allocate `indices` as `Uint32Array`; otherwise, allocate as `Uint16Array`.
3. Initialize `positions`, `normals`, and `colors` as `Float32Array` of size `quads.length * 12`.
4. Initialize `indices` as the determined type of size `quads.length * 6`.
5. Iterate through each quad in `quads` with an index `i`:
   a. Calculate the base position `p` of the quad's first vertex. The exact formula depends on the coordinate system, but generally involves `slice`, `u`, `v`, and `axis`. For a standard axis-aligned grid, if `axis` is 0 (X-normal), the position might be derived from `(slice, u, v)`. The source notes imply `p` is computed using `q.axis`, `q.slice`, `q.u`, `q.v` [S1, unofficial].
   b. Compute direction vectors `du` and `dv` based on `q.w`, `q.h`, and the orientation of the axis. These represent the steps along the quad's surface.
   c. Define the four vertices of the quad relative to `p`:
      - `v0 = p`
      - `v1 = p + du`
      - `v2 = p + du + dv`
      - `v3 = p + dv`
   d. Scale these positions by `scale` and write them to the `positions` array at offsets `i*12` to `(i+1)*12 - 3`.
   e. Set the normal for all four vertices. The normal is an axis-aligned unit vector determined by `q.axis` and `q.dir`. For example, if `axis` is 0, the normal is `(±1, 0, 0)`. Write these to the `normals` array.
   f. Determine the color by looking up `q.material` in `MATERIAL_COLORS`. If the index is out of bounds, default to index 3 (stone). Write this RGB triplet to all four vertices in the `colors` array.
   g. Generate the 6 indices for the two triangles forming the quad. The order depends on `q.dir` to ensure correct winding (culling). The source references a helper `quadTriangleIndices(q.dir)` [S1, unofficial]. Write these indices to the `indices` array, offset by `i*6`.

**Pseudocode:**

```python
def quad_to_geometry(quads, scale=1.0):
    num_quads = len(quads)
    num_vertices = num_quads * 4
    num_indices = num_quads * 6

    # Initialize arrays
    positions = [0.0] * (num_quads * 12)
    normals = [0.0] * (num_quads * 12)
    colors = [0.0] * (num_quads * 12)
    
    # Determine index type to avoid overflow
    if num_vertices > 65535:
        indices = [0] * num_indices # Uint32
    else:
        indices = [0] * num_indices # Uint16

    # Material color lookup table
    material_colors = [
        [0.0, 0.0, 0.0],      # 0: Air
        [0.24, 0.72, 0.48],   # 1: Surface
        [0.46, 0.33, 0.23],   # 2: Dirt
        [0.44, 0.47, 0.55],   # 3: Stone (default)
        [0.13, 0.83, 0.93]    # 4: Crystal
    ]

    for i, q in enumerate(quads):
        # Base vertex index for this quad
        v_base = i * 4
        # Array offsets (3 floats per vertex)
        p_base = i * 12
        n_base = i * 12
        c_base = i * 12
        idx_base = i * 6

        # 1. Compute base position p
        # Note: Exact formula for p depends on axis mapping. 
        # Assuming standard axis-aligned logic where axis 0=X, 1=Y, 2=Z.
        # p is constructed from slice, u, v based on q.axis.
        # This is a placeholder for the specific coordinate transformation logic [S1, unofficial].
        p = compute_base_position(q.axis, q.slice, q.u, q.v)

        # 2. Compute direction vectors du and dv
        # du and dv are scaled by w and h and oriented based on axis
        du = compute_direction_vector(q.axis, q.w, q.dir, "u")
        dv = compute_direction_vector(q.axis, q.h, q.dir, "v")

        # 3. Compute 4 vertices
        v0 = p
        v1 = add_vectors(p, du)
        v2 = add_vectors(add_vectors(p, du), dv)
        v3 = add_vectors(p, dv)

        # 4. Write positions (scaled)
        write_vector(positions, p_base, multiply_scalar(v0, scale))
        write_vector(positions, p_base + 3, multiply_scalar(v1, scale))
        write_vector(positions, p_base + 6, multiply_scalar(v2, scale))
        write_vector(positions, p_base + 9, multiply_scalar(v3, scale))

        # 5. Write normals
        normal = get_axis_normal(q.axis, q.dir)
        write_vector(normals, n_base, normal)
        write_vector(normals, n_base + 3, normal)
        write_vector(normals, n_base + 6, normal)
        write_vector(normals, n_base + 9, normal)

        # 6. Write colors
        mat_idx = q.material
        if mat_idx < 0 or mat_idx >= len(material_colors):
            mat_idx = 3 # Default to stone
        color = material_colors[mat_idx]
        write_vector(colors, c_base, color)
        write_vector(colors, c_base + 3, color)
        write_vector(colors, c_base + 6, color)
        write_vector(colors, c_base + 9, color)

        # 7. Write indices
        tri_indices = get_quad_triangles(q.dir)
        indices[idx_base] = v_base + tri_indices[0]
        indices[idx_base + 1] = v_base + tri_indices[1]
        indices[idx_base + 2] = v_base + tri_indices[2]
        indices[idx_base + 3] = v_base + tri_indices[3]
        indices[idx_base + 4] = v_base + tri_indices[4]
        indices[idx_base + 5] = v_base + tri_indices[5]

    return positions, normals, colors, indices

def compute_base_position(axis, slice, u, v):
    # Placeholder for specific axis-to-coordinate mapping [S1, unofficial]
    # Example for axis 0 (X-normal): position is (slice, u, v)
    if axis == 0:
        return [slice, u, v]
    elif axis == 1:
        return [u, slice, v]
    elif axis == 2:
        return [u, v, slice]
    return [0, 0, 0]

def get_axis_normal(axis, dir):
    # Returns unit vector for the axis, possibly negated by dir
    normal = [0, 0, 0]
    normal[axis] = 1.0 if dir == 0 else -1.0
    return normal

def get_quad_triangles(dir):
    # Returns indices for two triangles forming a quad, winding order depends on dir
    # Standard quad: 0, 1, 2, 3. Triangles: (0,1,2), (0,2,3) or similar.
    # Source mentions quadTriangleIndices(q.dir) [S1, unofficial]
    return [0, 1, 2, 0, 2, 3]

def write_vector(arr, offset, vec):
    arr[offset] = vec[0]
    arr[offset+1] = vec[1]
    arr[offset+2] = vec[2]

def add_vectors(v1, v2):
    return [v1[0]+v2[0], v1[1]+v2[1], v1[2]+v2[2]]

def multiply_scalar(v, s):
    return [v[0]*s, v[1]*s, v[2]*s]
```

**Edge Cases and Pitfalls:**
- **Index Overflow:** If the total number of vertices exceeds 65,535, using a `Uint16Array` for indices will cause silent wrapping, resulting in visual artifacts (giant triangle spikes). The method must check `vertexCount > 65535` and switch to `Uint32Array` [S1, unofficial].
- **Material Index Bounds:** If a quad's material index is outside the range of `MATERIAL_COLORS`, it should default to index 3 (stone) to prevent out-of-bounds errors [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N)$, where $N$ is the number of quads. The algorithm iterates through the quad list once [S1, unofficial].
- **Memory Complexity:** $O(N)$. It allocates four arrays proportional to the number of quads: positions, normals, colors, and indices [S1, unofficial].
- **Strengths:** Simple, deterministic, and produces a single draw call (if combined with other geometry) or a few draw calls. It is efficient for static geometry.
- **Limitations:** High memory usage for large scenes due to flat arrays. The index overflow pitfall requires careful handling. It does not support dynamic updates efficiently without rebuilding the arrays.

## Background
This method is associated with TypeScript implementations of voxel greedy meshing, specifically found in the `m2-md/voxel-greedy-meshing-typescript` repository. It is an unofficial implementation [S1, unofficial].
