# Chunk-Based Voxel Rendering

Also called: Chunk Vertex Buffer Update, Chunk-based Voxel Engine, Chunked Instancing, Chunked Voxel Rendering, Voxel Chunks

## Overview
Chunk-Based Voxel Rendering is a method that subdivides a voxel world into fixed-size spatial units (chunks), generating a single mesh and vertex buffer per chunk to optimize rendering performance [S1, S2, S3, unofficial]. It solves the problem of excessive CPU overhead and rendering lag associated with processing individual voxels by allowing the graphics pipeline to handle visibility via standard rasterization, rather than per-voxel culling [S2, unofficial]. It differs from [Binary Volume Rendering](1015-binary-volume-rendering-opacity-thresholding.md) by explicitly constructing geometric primitives (meshes) rather than relying on scalar field thresholding, and from [Instancing with Procedural/Shader Generation](2794-instancing-with-procedural-shader-generation.md) by pre-computing and storing static vertex buffers for chunks rather than generating geometry procedurally per draw call [S1, S2, unofficial].

## How it works
**Inputs:**
- A voxel world data structure containing block states [S1, unofficial].
- Camera position and viewing frustum parameters [G].
- Chunk dimension parameter $c_{dim}$ (typically 32) [S3, unofficial].

**Outputs:**
- A set of draw calls, one per visible chunk [S1, unofficial].
- Updated vertex buffers for chunks containing modified voxels [S1, unofficial].

**Data Structures:**
The world is managed using a map where the key identifies the chunk's spatial coordinates and the value is a pointer to the chunk object [S3, unofficial].

1. **Chunk Structure:**
   Each chunk contains:
   - A 1D array of voxel data: `voxels: list[int]` of size $c_{dim}^3$ [S3, unofficial].
   - A vertex buffer object (VBO) handle (e.g., `GLuint vbo`) [S3, unofficial].
   - A draw count (number of indices) (e.g., `GLuint drawCount`) [S3, unofficial].

2. **World Map Layout:**
   The world uses a map structure: `std::map<std::string, Chunk*>` [S3, unofficial].
   - Key: A string formatted as `"x|y|z"` representing the chunk coordinates [S3, unofficial].
   - Value: A pointer to the `Chunk` object [S3, unofficial].

**Algorithm Steps:**

1. **Chunk Division:**
   Divide the voxel world into non-overlapping chunks of size $c_{dim} \times c_{dim} \times c_{dim}$ [S1, S3, unofficial].

2. **Mesh Generation (Chunk Update):**
   When a voxel changes (added, removed, or modified):
   a. Identify the chunk containing the changed voxel by computing `chunk_x = voxel_x // c_dim`, `chunk_y = voxel_y // c_dim`, `chunk_z = voxel_z // c_dim` [G].
   b. Rebuild the mesh for **only** that specific chunk [S2, unofficial].
   c. To rebuild the mesh:
      i. Iterate through all voxels in the chunk.
      ii. Apply culling algorithms to identify visible faces (e.g., faces adjacent to empty space) [S1, unofficial].
      iii. Generate vertices and indices for these visible faces [S2, unofficial].
      iv. Upload the new vertex data to the chunk's VBO [G].
      v. Update the `drawCount` based on the number of generated primitives [S3, unofficial].

3. **Visibility Culling:**
   a. Check each chunk's bounding box against the camera's viewing frustum or draw distance bounds [S2, unofficial].
   b. Discard chunks outside the view volume [S2, unofficial].
   c. For chunks within the view but far from the camera, optionally generate buffers with reduced polygon counts (Level of Detail) [S2, unofficial].
   d. Unload chunks beyond the draw distance to support infinite worlds [S2, unofficial].

4. **Rendering:**
   a. For each visible chunk:
      i. Bind the chunk's VBO.
      ii. Issue a single draw call using the chunk's `drawCount` [S1, S3, unofficial].

**Pseudocode:**

```python
class Chunk:
    c_dim = 32  # Fixed dimension, typically 32 [S3, unofficial]
    voxels: list[int]  # 1D array of size c_dim^3 [S3, unofficial]
    vbo: object
    draw_count: int

class World:
    chunks: dict[str, Chunk]  # Key format "x|y|z" [S3, unofficial]

    @staticmethod
    def get_chunk_coords(voxel_x: int, voxel_y: int, voxel_z: int) -> tuple[int, int, int]:
        return (voxel_x // Chunk.c_dim, voxel_y // Chunk.c_dim, voxel_z // Chunk.c_dim)

    @staticmethod
    def update_chunk_mesh(chunk: Chunk) -> None:
        """Rebuilds the vertex buffer for a specific chunk."""
        indices: list[int] = []
        c_dim = chunk.c_dim
        voxels = chunk.voxels
        
        # Face directions: (dx, dy, dz, i0, i1, i2, i3) for quad indices
        faces = [
            (1, 0, 0, 0, 1, 3, 2), (-1, 0, 0, 0, 2, 3, 1),
            (0, 1, 0, 0, 1, 3, 2), (0, -1, 0, 0, 2, 3, 1),
            (0, 0, 1, 0, 1, 3, 2), (0, 0, -1, 0, 2, 3, 1)
        ]
        
        for x in range(c_dim):
            for y in range(c_dim):
                for z in range(c_dim):
                    if voxels[x * c_dim * c_dim + y * c_dim + z] == 0:
                        continue
                    base = len(indices)
                    for dx, dy, dz, i0, i1, i2, i3 in faces:
                        nx, ny, nz = x + dx, y + dy, z + dz
                        is_empty = False
                        if 0 <= nx < c_dim and 0 <= ny < c_dim and 0 <= nz < c_dim:
                            if voxels[nx * c_dim * c_dim + ny * c_dim + nz] == 0:
                                is_empty = True
                        else:
                            is_empty = True
                        
                        if is_empty:
                            indices.extend([base + i0, base + i1, base + i2, base + i0, base + i2, base + i3])
                            base += 4
        
        # Upload indices to GPU VBO [G]
        chunk.vbo = indices  
        chunk.draw_count = len(indices)

    def on_voxel_change(self, voxel_x: int, voxel_y: int, voxel_z: int, new_state: int) -> None:
        """Called when a voxel is modified."""
        cx, cy, cz = World.get_chunk_coords(voxel_x, voxel_y, voxel_z)
        key = f"{cx}|{cy}|{cz}"
        
        if key in self.chunks:
            chunk = self.chunks[key]
            lx, ly, lz = voxel_x % Chunk.c_dim, voxel_y % Chunk.c_dim, voxel_z % Chunk.c_dim
            chunk.voxels[lx * Chunk.c_dim * Chunk.c_dim + ly * Chunk.c_dim + lz] = new_state
            World.update_chunk_mesh(chunk)

    def render(self, camera) -> None:
        """Render visible chunks."""
        for key, chunk in self.chunks.items():
            # Check chunk bounding box against camera frustum [S2, unofficial]
            if chunk.is_in_frustum(camera):
                # Issue draw call for the chunk [S1, unofficial]
                pass
```

**Parameters:**
- **Chunk Dimension ($c_{dim}$):** The size of the chunk in voxels along one axis. A typical value is 32 [S3, unofficial].
  - *Trade-off:* Larger chunks reduce the number of draw calls but increase the cost of buffer rebuilds when a block changes. Smaller chunks reduce rebuild costs but increase driver overhead due to more chunks and draw calls [S1, S2, unofficial].

**Edge Cases and Pitfalls:**
- **Visibility Checks:** Do not perform per-voxel visibility checks from the camera's perspective every frame. Instead, rely on the graphics card to discard faces not visible after the mesh is built. Visibility logic should only determine which faces are included in the mesh (e.g., buried vs. exposed) [S2, unofficial].
- **Chunk Size Selection:** Choosing inappropriate chunk sizes leads to performance degradation. Too large: costly updates. Too small: high driver overhead [S1, unofficial].

## Subtopics

### [Chunk Draw Call Preparation](22207-chunk-draw-call-preparation.md)
Focuses on the immediate preparation of draw state by iterating through a chunk's 3D block array to generate draw commands, filtering out invisible blocks. It differs from Chunk-Based Voxel Rendering by focusing on the immediate preparation of draw state rather than the long-term management of vertex buffers and chunk updates.

## Operating characteristics
- **Time Complexity:**
  - *Update:* $O(c_{dim}^3)$ per chunk update, where $c_{dim}$ is the chunk dimension. Only affected chunks are updated [S1, S2, unofficial].
  - *Render:* $O(N_{visible})$, where $N_{visible}$ is the number of visible chunks. One draw call per visible chunk [S1, unofficial].
- **Memory Complexity:**
  - $O(N_{chunks} \times c_{dim}^3)$ for voxel data storage [G].
  - $O(N_{visible} \times V_{mesh})$ for vertex buffers, where $V_{mesh}$ is the size of the mesh for a chunk [G].
- **Measured Performance:**
  - Reduces CPU-side visibility logic overhead significantly compared to per-voxel drawing [S2, unofficial].
  - Enables infinite worlds by allowing chunks to be unloaded beyond draw distance [S2, unofficial].
- **Strengths:**
  - Minimizes CPU overhead by batching geometry into chunks [S1, unofficial].
  - Allows efficient partial updates (only changed chunks are rebuilt) [S2, unofficial].
  - Leverages GPU rasterization for visibility culling [S2, unofficial].
- **Limitations:**
  - Driver overhead increases with the number of chunks [S1, unofficial].
  - Rebuilding vertex buffers can still be costly if chunks are too large [S1, unofficial].
- **When to Use:**
  - Suitable for voxel engines requiring dynamic world modification (e.g., Minecraft-like games) where performance is critical [S1, S3, unofficial].
- **When Not to Use:**
  - Not suitable for static, high-resolution scalar field volume rendering where ray-marching or ray-casting is more appropriate [G].

## Background
Chunk-based rendering originated as a solution to rendering lag in voxel engines, particularly in the context of games like Minecraft [S1, S3, unofficial]. The approach allows for efficient management of large, dynamic voxel environments by balancing the cost of mesh generation against the cost of draw calls [S2, unofficial].
