# SVO LOD Management

Also called: Graphics Component SVO LOD Management

## Overview
SVO LOD Management is a method for managing the Level of Detail (LOD) of Sparse Voxel Octrees (SVOs) by switching between pre-generated geometric representations (Vertex Buffer Objects) at different octree depths. It solves the problem of balancing rendering performance and visual fidelity for complex, pre-voxelized assets by allowing the renderer to dynamically select the appropriate octree resolution. It differs from dynamic voxelization methods by relying on pre-computed, static geometry buffers for each LOD level, rather than generating voxels per frame [S1, unofficial].

## How it works
The method manages a set of pre-generated OpenGL resources (VAOs and VBOs) corresponding to different depths of the SVO. The renderer switches between these resources based on a requested LOD index.

**Inputs and Outputs:**
- **Input:** A target Level of Detail (LOD) index (integer), typically derived from camera distance or performance metrics.
- **Output:** The active OpenGL Vertex Array Object (VAO) and Vertex Buffer Object (VBO) corresponding to the specified LOD, along with updated metadata (bounding sphere, voxel count).

**Data Structures:**
The core data structure is a component (e.g., `GraphicsComponentSVO`) that maintains:
- `maxSvoDepth_`: The maximum supported octree depth (uint8_t).
- `currentSvoLodIdx_`: The index of the currently active LOD (uint8_t), where $0$ corresponds to the finest detail (depth $maxSvoDepth_$) and $maxSvoDepth_-1$ corresponds to the coarsest (depth $1$).
- `octreeFiles_`: An array or list of `OctreeFile` objects, one for each LOD level. Each `OctreeFile` contains header data (grid length) and raw voxel data.
- `VAOs_` and `VBOs_`: Arrays of OpenGL handles, one pair per LOD level.
- `boundingSphereRadius_`: A float representing the radius of the asset's bounding sphere.
- `visible_`: A boolean flag.

**Initialization (Constructor):**
1. Initialize `boundingSphereRadius_` to $0.0f$ and `visible_` to `true` [S1, unofficial].
2. Retrieve the maximum SVO depth supported by the rendering system, stored in `maxSvoDepth_` [S1, unofficial].
3. Set `currentSvoLodIdx_` to `maxSvoDepth_ - 1` (initially selecting the coarsest LOD) [S1, unofficial].
4. For each depth $d$ from $1$ to `maxSvoDepth_`:
    a. Create an `OctreeFile` for depth $d$ [S1, unofficial].
    b. Generate a VAO and VBO [S1, unofficial].
    c. Bind the VAO and VBO [S1, unofficial].
    d. Load the octree data for depth $d$ into the VBO with usage hint `GL_STATIC_DRAW` [S1, unofficial].
    e. Set up three vertex attribute arrays using offsets from `OctreeFile::Data`:
        - Position: 3 floats
        - Color: 3 floats
        - Normal: 3 floats
    [S1, unofficial]

**Bounding Sphere Calculation:**
1. Iterate through the voxel data of the maximum depth octree (`octreeFiles_[maxSvoDepth_]`), starting from index $1$ (skipping the root voxel at index $0$) [S1, unofficial].
2. Skip nodes where position coordinates $x, y, z$ are all equal to $-0.5f$ [S1, unofficial].
3. Track the minimum ($minX, minY, minZ$) and maximum ($maxX, maxY, maxZ$) coordinates encountered [S1, unofficial].
4. Compute the bounding sphere radius as the length of the vector from the maximum corner $(maxX, maxY, maxZ)$ to the midpoint of the bounding box defined by min and max coordinates [S1, unofficial].
   $$
   R_{bound} = \left\| (maxX, maxY, maxZ) - \left( \frac{minX + maxX}{2}, \frac{minY + maxY}{2}, \frac{minZ + maxZ}{2} \right) \right\|
   $$
   [S1, unofficial]

**LOD Management:**
- **Set LOD:** When `setLod(lod)` is called:
    1. Update `currentSvoLodIdx_` to `lod - 1` [S1, unofficial].
    2. Trigger a recalculation of the total voxel number in the rendering system [S1, unofficial].
- **Decrease LOD:** When `decreaseLevelOfDetail()` is called:
    1. If `currentSvoLodIdx_` is $0$, set LOD to `maxSvoDepth_` (wrap to finest) [S1, unofficial].
    2. Otherwise, decrease `currentSvoLodIdx_` by $1$ [S1, unofficial].
- **Increase LOD:** When `increaseLevelOfDetail()` is called:
    1. If `currentSvoLodIdx_` is `maxSvoDepth_ - 1`, set LOD to $1$ (wrap to coarsest) [S1, unofficial].
    2. Otherwise, increase `currentSvoLodIdx_` by $1$ [S1, unofficial].

**Retrieval:**
- The active VAO is retrieved via `getVAO()`, which returns `VAOs_[currentSvoLodIdx_]` [S1, unofficial].
- The current LOD index is retrieved via `getLevelOfDetail()`, which returns `currentSvoLodIdx_ + 1` [S1, unofficial].

**Pseudocode:**
```python
class SVOGraphicsComponent:
    def __init__(self, max_svo_depth):
        self.max_svo_depth_ = max_svo_depth
        self.current_svo_lod_idx_ = max_svo_depth - 1
        self.bounding_sphere_radius_ = 0.0
        self.visible_ = True
        self.octree_files_ = []
        self.vaos_ = []
        self.vbos_ = []
        
        # Initialization of resources
        for d in range(1, max_svo_depth + 1):
            octree_file = create_octree_file(d)
            self.octree_files_.append(octree_file)
            
            vao = generate_vao()
            vbo = generate_vbo()
            bind_vao(vao)
            bind_vbo(vbo)
            
            # Load data into VBO
            data = octree_file.get_data()
            upload_to_vbo(vbo, data, usage=GL_STATIC_DRAW)
            
            # Setup vertex attributes
            setup_vertex_attribute(vao, offset=0, count=3, type=FLOAT) # Position
            setup_vertex_attribute(vao, offset=12, count=3, type=FLOAT) # Color
            setup_vertex_attribute(vao, offset=24, count=3, type=FLOAT) # Normal
            
            self.vaos_.append(vao)
            self.vbos_.append(vbo)
            
        # Calculate bounding sphere
        self.calculate_bounding_sphere()

    def calculate_bounding_sphere(self):
        min_x, min_y, min_z = float('inf'), float('inf'), float('inf')
        max_x, max_y, max_z = float('-inf'), float('-inf'), float('-inf')
        
        # Iterate max depth data, skip root (index 0)
        data = self.octree_files_[self.max_svo_depth_ - 1].get_data()
        for i in range(1, len(data)):
            node = data[i]
            if node.x == -0.5 and node.y == -0.5 and node.z == -0.5:
                continue
            min_x = min(min_x, node.x)
            min_y = min(min_y, node.y)
            min_z = min(min_z, node.z)
            max_x = max(max_x, node.x)
            max_y = max(max_y, node.y)
            max_z = max(max_z, node.z)
            
        mid_x = (min_x + max_x) / 2.0
        mid_y = (min_y + max_y) / 2.0
        mid_z = (min_z + max_z) / 2.0
        
        self.bounding_sphere_radius_ = length(vec3(max_x, max_y, max_z) - vec3(mid_x, mid_y, mid_z))

    def set_lod(self, lod):
        self.current_svo_lod_idx_ = lod - 1
        recalculate_total_voxel_count()

    def decrease_level_of_detail(self):
        if self.current_svo_lod_idx_ == 0:
            self.current_svo_lod_idx_ = self.max_svo_depth_ - 1
        else:
            self.current_svo_lod_idx_ -= 1

    def increase_level_of_detail(self):
        if self.current_svo_lod_idx_ == self.max_svo_depth_ - 1:
            self.current_svo_lod_idx_ = 0
        else:
            self.current_svo_lod_idx_ += 1

    def get_vao(self):
        return self.vaos_[self.current_svo_lod_idx_]

    def get_level_of_detail(self):
        return self.current_svo_lod_idx_ + 1
```

## Subtopics

### [Sparse Voxel Octree (SVO) LOD Pipeline](6811-sparse-voxel-octree-svo-lod-pipeline.md)
A unified production pipeline that converts complex, animated assets into a consistent SVO representation. It addresses the challenge of efficiently populating, animating, and ray-tracing dynamic scenes by replacing direct geometry processing with a pre-voxelized, LOD-managed cache. Unlike standard real-time SVO ray-tracing which often requires dynamic voxelization per frame, this pipeline separates asset preparation from rendering, using stored surface data and procedural blend shapes to animate static SVOs, thereby reducing memory footprint and voxelization time.

## Operating characteristics
- **Time Complexity:** Switching LOD is $O(1)$ as it involves updating an index and triggering a metadata recalculation. Rendering time depends on the number of voxels in the active LOD buffer.
- **Memory Complexity:** $O(N \times D)$, where $N$ is the number of voxels at the finest level and $D$ is the max depth. Each LOD level requires a separate VBO, leading to significant memory overhead if many LOD levels are stored simultaneously [S1, unofficial].
- **Strengths:** Fast LOD switching; no runtime voxelization cost; simple integration with existing OpenGL pipelines.
- **Limitations:** High memory usage due to storing multiple LOD buffers; static geometry limits dynamic deformation unless blend shapes are used; requires pre-processing of assets [S1, unofficial].
- **When to use:** Pre-processed, static or semi-static assets where LOD switching is needed and memory is not a critical constraint.
- **When not to use:** Highly dynamic scenes requiring per-frame voxelization; memory-constrained environments.

## Background
The method originates from the `svo_renderer` project by mmalesadev, which implements a Sparse Voxel Octree renderer using OpenGL. It is part of a broader effort to streamline lighting and rendering workflows for complex assets by pre-voxelizing them into LOD-managed caches [S1, unofficial].
