# Pixel Shader Fragment Clipping

Also called: PS Fragment Clipping, Pixel Shader Clipping Method

## Overview
Pixel Shader Fragment Clipping is a single-pass GPU method for multi-channel surface voxelization where the geometry shader rasterizes triangles into all intersecting volume slices without clipping, and the pixel shader discards fragments that fall outside the slice boundaries [S1, unofficial]. It avoids the computational overhead of geometry shader clipping by relying on fragment rejection in the pixel shader, achieving performance comparable to geometry slicing while being slightly more efficient for small triangle counts [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Triangle vertices $v_1, v_2, v_3$ in Eye Coordinate Space (ECS); volume slice thickness $t$; volume minimum z-coordinate $z_{min\_vol}$ in ECS [S1, unofficial].
*   **Output:** Rasterized fragments contributing to the appropriate volume layer, with multi-channel data computed in the pixel shader [S1, unofficial].

**Data Structures:**
*   **Geometry Shader Output:** A stream of vertices forming triangle strips. The number of emitted vertices is $3 \times n$, where $n$ is the number of slices the triangle spans [S1, unofficial].
*   **Inter-shader Communication:** Flat-shaded varying variables `zMin` and `zMax` passed from the geometry shader to the pixel shader, representing slice boundaries in Normalized Device Coordinates (NDC) [S1, unofficial].

**Steps:**
1.  **Geometry Shader Processing:**
    *   For each directional voxelization, pass each triangle through the geometry shader [S1, unofficial].
    *   Check if the triangle is aligned with the current sweeping direction (Z-axis). If not aligned, discard the primitive [S1, unofficial].
    *   Compute the slice indices $s_{min}$ and $s_{max}$ that the triangle intersects:
        $$ s_{min} = \left\lfloor \min_i \frac{z(v_i) - z_{min\_vol}}{t} \right\rfloor $$
        $$ s_{max} = \left\lfloor \max_i \frac{z(v_i) - z_{min\_vol}}{t} \right\rfloor $$
        where $z(v_i)$ is the z-coordinate of vertex $v_i$ in ECS [S1, unofficial].
    *   Iterate through each slice $s$ from $s_{min}$ to $s_{max}$:
        *   Determine the depth range $[z_{min}, z_{max}]$ of the triangle within slice $s$ in NDC [S1, unofficial].
        *   Emit vertices to rasterize the triangle into slice $s$. The specific geometric clipping logic is omitted as the method relies on the pixel shader for boundary enforcement [S1, unofficial].
        *   Pass the computed NDC boundaries `zMin` and `zMax` to the pixel shader for the emitted vertices [S1, unofficial].

2.  **Pixel Shader Processing:**
    *   Receive `zMin` and `zMax` from the geometry shader [S1, unofficial].
    *   For each fragment, check its depth $z_{frag}$ against the boundaries:
        $$ \text{if } z_{frag} < z_{Min} \text{ or } z_{frag} > z_{Max} \text{ then discard} $$
    *   If the fragment is within bounds, compute the required multi-channel data and write to the volume buffer [S1, unofficial].

**Pseudocode:**

```python
def perspective_divide(v):
    # Standard perspective division to convert ECS to NDC [G]
    return (v.x / v.w, v.y / v.w, v.z / v.w)

def is_aligned_with_z(v1, v2, v3):
    # Standard orientation check for Z-axis alignment [G]
    return abs(v1.z - v2.z) < 1e-6 and abs(v2.z - v3.z) < 1e-6

def geometry_shader(v1, v2, v3, slice_thickness, z_vol_min):
    # Check alignment with sweeping direction (Z-axis) [S1, unofficial]
    if not is_aligned_with_z(v1, v2, v3):
        return
    
    z_coords = [v1.z, v2.z, v3.z]
    # Compute slice indices in ECS
    s_min = floor(min(z_coords) - z_vol_min) / slice_thickness
    s_max = floor(max(z_coords) - z_vol_min) / slice_thickness
    
    # Transform vertices to NDC for rasterization [G]
    v1_ndc = perspective_divide(v1)
    v2_ndc = perspective_divide(v2)
    v3_ndc = perspective_divide(v3)
    
    for s in range(int(s_min), int(s_max) + 1):
        # Compute NDC depth bounds for this slice
        z_min_ecs = z_vol_min + s * slice_thickness
        z_max_ecs = z_vol_min + (s + 1) * slice_thickness
        z_min_ndc = perspective_divide_z(z_min_ecs)
        z_max_ndc = perspective_divide_z(z_max_ecs)
        
        # Emit the full triangle vertices for this slice
        # Flat varyings zMin and zMax are attached to each vertex
        emit_vertex(v1_ndc, z_min_ndc, z_max_ndc)
        emit_vertex(v2_ndc, z_min_ndc, z_max_ndc)
        emit_vertex(v3_ndc, z_min_ndc, z_max_ndc)

def pixel_shader(z_min, z_max, fragment_depth):
    # Discard fragments outside the slice boundaries
    if fragment_depth < z_min or fragment_depth > z_max:
        return None # discard
    
    # Compute multi-channel data (e.g., occupancy, normal, color)
    # The pixel shader is virtually empty, computing just the data required by the application [S1, unofficial]
    occupancy = compute_occupancy(fragment_depth)
    normal = compute_normal(fragment_depth)
    color = compute_color(fragment_depth)
    
    return occupancy, normal, color

def emit_vertex(v, z_min, z_max):
    # Standard graphics pipeline vertex emission [G]
    pass

def compute_occupancy(depth):
    # Application-specific occupancy calculation [S1, unofficial]
    return 1.0

def compute_normal(depth):
    # Application-specific normal calculation [S1, unofficial]
    return (0.0, 0.0, 1.0)

def compute_color(depth):
    # Application-specific color calculation [S1, unofficial]
    return (1.0, 1.0, 1.0)

def perspective_divide_z(z_ecs):
    # Extract z-component after perspective division [G]
    return z_ecs / 1.0 # Simplified for NDC depth extraction
```

**Parameters:**
*   **Output Vertex Count:** The geometry shader must be configured to output $3 \times n$ vertices, where $n$ is the number of slices spanned by the triangle [S1, unofficial].
*   **Slice Thickness:** Determined by the target voxel grid resolution [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Output Vertex Limit:** If the geometry shader's output vertex limit is too low (e.g., requesting only 3 vertices), holes appear in the voxelization because the triangle cannot be fully rasterized across all intersecting slices [S1, unofficial]. A higher output vertex count is required to remedy this [S1, unofficial].
*   **Partial Slicing:** If the output vertex limit is small, triangles may be partially sliced, resulting in empty voxels [S1, unofficial]. However, this is less common in volume sweep planes of maximum projection due to selective processing [S1, unofficial].
*   **Precision:** The method relies on accurate computation of slice boundaries in NDC. Precision errors in depth comparison may lead to incorrect fragment discarding [G].

## Operating characteristics
**Time and Memory Complexity:**
*   The method is single-pass, making it efficient for real-time applications [S1, unofficial].
*   Performance scales with the number of triangles and the number of slices each triangle spans [S1, unofficial].

**Measured Performance:**
*   Tested on an Intel Core i7 860 @ 2.80GHz, 8 GB RAM, nVIDIA GeForce GTX 285 GPU (1 GB memory) [S1, unofficial].
*   For the Bunny model (69,451 triangles) at a $256^3$ grid size:
    *   12 vertices out: 5.12 ms [S1, unofficial].
    *   15 vertices out: 5.48 ms [S1, unofficial].
*   The method achieves slightly better results than geometry slicing for small triangle counts, but performance is equivalent for larger models (e.g., Dragon model) [S1, unofficial].

**Strengths and Limitations:**
*   **Strengths:** Avoids geometry shader clipping overhead; simple implementation; suitable for sparse or incomplete volume representations [S1, unofficial].
*   **Limitations:** Quality depends on the number of volume slices each triangle spans; requires sufficient geometry shader output vertex capacity [S1, unofficial].

**When to Use:**
*   Suitable for effects like diffuse global illumination (e.g., virtual point light injection) where a sparse or incomplete volume representation is acceptable due to the low-frequency nature of secondary diffuse light transport [S1, unofficial].
