# Geometry Shader Triangle Slicing (Z-Pass)

Also called: GS Triangle Slicing, GS Voxelization, Triangle Slicing Method, Triangle Slicing Voxelization

## Overview
Geometry Shader Triangle Slicing is a single-pass GPU method for multi-channel surface voxelization that explicitly clips input triangles against volume slice boundaries within the geometry shader, emitting only the valid geometric fragments for rasterization into the appropriate volume layer [S1, unofficial]. Unlike sibling methods such as [Pixel Shader Fragment Clipping](1685-pixel-shader-fragment-clipping.md) which rasterize the full triangle and discard invalid fragments later, this approach generates precise triangle strips per slice in the geometry stage, avoiding the computational overhead of fragment rejection and making it particularly suitable for architectures with limited bandwidth or where pixel shader cores are heavily utilized [S1, unofficial].

## How it works
The method converts 3D triangle geometry into a layered volume representation by slicing triangles along the Z-axis (Eye Coordinate Space) and assigning the resulting strips to specific texture array layers [S1, unofficial].

### Inputs and Outputs
*   **Input Vertices:** Three vertices $v_1, v_2, v_3$, each containing position $(x, y, z)$ in Eye Coordinate Space (ECS) [S1, unofficial].
*   **Data Parameters:**
    *   $z_{slice}$: The thickness of the volume slice in volume sweep ECS [S1, unofficial].
    *   $z_{min}$: The minimum Z-depth of the volume in volume sweep ECS [S1, unofficial].
*   **Output Primitives:** Triangle strips rasterized to specific layers via the built-in variable `gl_Layer` [S1, unofficial].
*   **Layer Assignment:** The output layer index is set using `gl_Layer` to direct rasterization to the corresponding slice of the volume texture array [S1, unofficial].

### Data Structures and Layout
*   **Input Vertices:** Three vertices $v_1, v_2, v_3$, each containing position $(x, y, z)$ in ECS [S1, unofficial].
*   **Output Primitives:** Triangle strips. For a triangle spanning $n$ slices, the geometry shader emits $3 + 4n$ vertices [S1, unofficial]. The method detects triangle emittance and does not produce degenerate quads [S1, unofficial].
*   **Layer Assignment:** The output layer index is set using `gl_Layer` to direct rasterization to the corresponding slice of the volume texture array [S1, unofficial].

### Algorithm Steps
The algorithm processes each triangle independently [G]. It assumes the triangle is aligned with the Z-axis; if not, it is ignored [S1, unofficial].

1.  **Alignment Check:** If the triangle is not aligned with the Z-axis, return immediately [S1, unofficial].
2.  **Sorting:** Sort the triangle vertices $v_1, v_2, v_3$ such that their Z-depths are non-decreasing ($z_1 \le z_2 \le z_3$) [S1, unofficial].
3.  **Initialization:**
    *   Calculate the minimum slice index: $s_{min} = \lfloor (z_1 - z_{min}) / z_{slice} \rfloor$ [S1, unofficial].
    *   Calculate the maximum slice index: $s_{max} = \lfloor (z_3 - z_{min}) / z_{slice} \rfloor$ [S1, unofficial].
    *   Set `layer` to $s_{min}$ [S1, unofficial].
    *   Set `slice` depth to the start of the current slice in ECS: $z_{slice\_start} = z_{min} + s_{min} \times z_{slice}$ [S1, unofficial].
    *   Initialize boundary vertices for the previous slice: $v_{1L} = v_{1R} = v_1$ and $v_{2L} = v_{2R} = v_2$ (conceptually, though actual logic handles the first slice specifically) [S1, unofficial].
4.  **First Slice Handling (Case A):**
    *   If $z_3 \ge z_{slice\_start}$, emit the original triangle $(v_1, v_2, v_3)$ to `layer` and return [S1, unofficial].
5.  **First Slice Intersection (Case B):**
    *   If $z_2 \ge z_{slice\_start}$:
        *   If $z_1 \ge z_{slice\_start}$, set $v_{1L} = v_{1R} = v_1$ [S1, unofficial].
        *   Else, set $v_{1L} = v_2$ and $v_{1R} = v_1$ [S1, unofficial].
        *   Calculate intersection points $v_{2L}, v_{2R}$ by intersecting edges $(v_1, v_2)$ and $(v_1, v_3)$ with the current slice plane $z_{slice\_start}$ [S1, unofficial].
        *   Emit the quad strip $(v_{1R}, v_{1L}, v_{2L}, v_{2R})$ to `layer` [S1, unofficial].
6.  **Iterative Slicing Loop:**
    *   Increment `slice` by $z_{slice}$ and increment `layer` [S1, unofficial].
    *   Update $v_{1L} = v_{2L}$ and $v_{1R} = v_{2R}$ from the previous iteration's right-side intersections [S1, unofficial].
    *   Determine the next case based on vertex depths relative to the new `slice` depth:
        *   **Case B (Continuation):** If $z_2 \ge z_{slice\_start}$:
            *   Calculate $v_{2L}, v_{2R}$ by intersecting edges with the current slice [S1, unofficial].
            *   Proceed to next iteration (emit logic handled in subsequent steps or implicit in strip continuity) [S1, unofficial].
        *   **Case C (Triangle ends in this slice, $v_2$ crossed):** If $z_3 < z_{slice\_start}$ and $z_2$ was previously $\ge$ slice:
            *   Set $v_{2L} = v_2$ and $v_{2R} = v_3$ [S1, unofficial].
        *   **Case D (Triangle ends in this slice, $v_2$ did not cross):** If $z_3 < z_{slice\_start}$ and $z_2$ was previously $<$ slice:
            *   Set $v_{2L} = v_{2R} = v_3$ [S1, unofficial].
        *   **Case E (Triangle continues, $v_2$ crossed previously):** If $z_3 \ge z_{slice\_start}$ and $z_2$ was previously $<$ slice:
            *   Calculate $v_{2L}, v_{2R}$ by intersecting edges with the current slice [S1, unofficial].
        *   **Case F (Triangle continues, $v_2$ did not cross previously):** If $z_3 \ge z_{slice\_start}$ and $z_2$ was previously $\ge$ slice:
            *   Calculate $v_{2L}, v_{2R}$ by intersecting edges with $v_2$ depth (effectively keeping the previous intersection or recalculating based on geometry) [S1, unofficial].
        *   **Emit:** Emit the quad strip $(v_{1R}, v_{1L}, v_{2L}, v_{2R})$ to `layer` [S1, unofficial].
        *   Update $v_{1L} = v_{2L}$ and $v_{1R} = v_{2R}$ [S1, unofficial].
        *   Calculate new $v_{2L}, v_{2R}$ by intersecting edges with the current slice [S1, unofficial].
        *   Emit the quad strip $(v_{1R}, v_{1L}, v_{2L}, v_{2R})$ to `layer` [S1, unofficial].
    *   Repeat until $z_3 < z_{slice\_start}$ [S1, unofficial].

### Pseudocode
```python
def geometry_shader_triangle_slicing(v1, v2, v3, z_slice_thickness, z_vol_min):
    # Input: v1, v2, v3 are vec3 in Eye Coordinate Space
    # Output: Primitives emitted to gl_Layer

    # 1. Alignment Check
    # [S1, unofficial] states: if triangle not aligned with Z-axis, return.
    # Implementation note: Typically checks if the triangle normal is perpendicular to Z 
    # or if the triangle is degenerate in XY. We assume a hard filter here.
    if not is_aligned_with_z(v1, v2, v3):
        return

    # 2. Sort vertices by Z depth
    verts = sorted([v1, v2, v3], key=lambda v: v.z)
    v1, v2, v3 = verts

    # 3. Initialization
    # [S1, unofficial] layer <- minimum slice index for the first vertex
    layer = int((v1.z - z_vol_min) / z_slice_thickness)
    # [S1, unofficial] slice <- current slice depth in ECS
    slice_z = z_vol_min + layer * z_slice_thickness

    # Helper to intersect edges (v1,v2) and (v1,v3) with plane z = z_plane
    # [S1, unofficial] "Intersect Edges (slice)" implies intersecting edges connected to v1
    def intersect_edges(v1, v2, v3, z_plane):
        if abs(v2.z - v1.z) < 1e-6:
            p1 = v1
        else:
            t = (z_plane - v1.z) / (v2.z - v1.z)
            p1 = v1 + t * (v2 - v1)
        if abs(v3.z - v1.z) < 1e-6:
            p2 = v1
        else:
            t = (z_plane - v1.z) / (v3.z - v1.z)
            p2 = v1 + t * (v3 - v1)
        return p1, p2

    # Helper to emit a quad strip
    # [G] Standard GLSL geometry shader emission mapped to Python for clarity
    def emit_strip(p1, p2, p3, p4, lyr):
        pass  # Emits triangle strip (p1, p2, p3, p4) to gl_Layer = lyr

    # Helper to emit a triangle
    # [G] Standard GLSL geometry shader emission mapped to Python for clarity
    def emit_triangle(v1, v2, v3, lyr):
        pass  # Emits triangle (v1, v2, v3) to gl_Layer = lyr

    # 4. First slice
    # [S1, unofficial] if v3 depth is >= slice then CASE A
    if v3.z >= slice_z:
        emit_triangle(v1, v2, v3, layer)
        return

    v2L, v2R = None, None
    v2_above_prev = False

    # [S1, unofficial] if v2 depth is >= slice then
    if v2.z >= slice_z:
        if v1.z >= slice_z:
            v1L = v1R = v1
        else:
            v1L = v2
            v1R = v1
        v2L, v2R = intersect_edges(v1, v2, v3, slice_z)
        emit_strip(v1R, v1L, v2L, v2R, layer)
        v2_above_prev = True
    else:
        v2_above_prev = False

    # 5. Iterative loop
    # [S1, unofficial] repeat ... until v3 depth < slice
    while v3.z >= slice_z:
        slice_z += z_slice_thickness
        layer += 1
        v1L = v2L
        v1R = v2R

        if v2.z >= slice_z:
            # CASE B
            v2L, v2R = intersect_edges(v1, v2, v3, slice_z)
            v2_above_prev = True
        elif v3.z < slice_z:
            # Triangle ends in this slice
            if v2_above_prev:
                # CASE C
                v2L = v2
                v2R = v3
            else:
                # CASE D
                v2L = v2R = v3
            emit_strip(v1R, v1L, v2L, v2R, layer)
            break
        elif not v2_above_prev:
            # CASE E
            v2L, v2R = intersect_edges(v1, v2, v3, slice_z)
            v2_above_prev = True
        else:
            # CASE F
            # [S1, unofficial] Intersect Edges (v2 depth)
            v2L, v2R = intersect_edges(v1, v2, v3, v2.z)
            v2_above_prev = True

        emit_strip(v1R, v1L, v2L, v2R, layer)
        v1L = v2L
        v1R = v2R
        v2L, v2R = intersect_edges(v1, v2, v3, slice_z)

def is_aligned_with_z(v1, v2, v3):
    # [G] Placeholder for alignment check. Typically verifies triangle normal is perpendicular to Z axis.
    return True
```

### Parameters
*   **z slice thickness:** The thickness of the volume slice in volume sweep ECS. Typical values depend on the target resolution (e.g., $1/256$ of the view volume depth for a $256^3$ grid) [S1, unofficial].
*   **Geometry Shader Output Vertex Count:** $3 + 4n$, where $n$ is the number of slices the triangle spans [S1, unofficial].

### Edge Cases and Pitfalls
*   **Z-Axis Alignment:** Triangles not aligned with the Z-axis are ignored in this specific Z-Pass implementation [S1, unofficial]. This is a significant limitation for general-purpose voxelization unless multiple passes are used for different axes.
*   **Degenerate Quads:** The method detects triangle emittance and does not produce degenerate quads, optimizing rasterization [S1, unofficial].
*   **Precision:** Intersections must be calculated carefully to avoid gaps or overlaps between slices. Floating-point precision issues at slice boundaries can lead to artifacts [G].

## Subtopics

### [Pixel Shader Fragment Clipping](1685-pixel-shader-fragment-clipping.md)
A single-pass GPU method where the geometry shader rasterizes triangles into all intersecting volume slices without clipping, and the pixel shader discards fragments that fall outside the slice boundaries. It avoids the computational overhead of geometry shader clipping by relying on fragment rejection in the pixel shader, achieving performance comparable to geometry slicing while being slightly more efficient for small triangle counts.

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of triangles and the number of slices each triangle intersects. The complexity is $O(N \cdot n)$, where $N$ is the number of triangles and $n$ is the average number of slices spanned per triangle [G].
*   **Memory Complexity:** The output vertex count is $3 + 4n$ per triangle, which is higher than the pixel shader clipping method's $3n$ vertices [S1, unofficial]. This increased vertex output can be a bottleneck on GPUs with limited geometry shader output bandwidth [S1, unofficial].
*   **Measured Performance:** On an Intel Core i7 860 @ 2.80GHz, 8 GB RAM, nVIDIA GeForce GTX 285 GPU (1 GB memory), voxelizing the Bunny model (69,451 triangles) into a $256^3$ grid took 6.43 ms (15 vertices out) and 6.98 ms (19 vertices out) [S1, unofficial].
*   **Strengths:**
    *   Produces exactly the fragments rasterized in the final volume slices, avoiding the overhead of generating and discarding invalid fragments [S1, unofficial].
    *   Preferred on non-unified architectures if pixel shader cores are intensively used [S1, unofficial].
    *   Preferred on architectures with small bandwidth to avoid fragment rejection overhead [S1, unofficial].
*   **Limitations:**
    *   Requires explicit clipping logic in the geometry shader, which can be complex to implement correctly for all triangle configurations (Cases A-F) [S1, unofficial].
    *   Limited to Z-aligned triangles in the basic implementation [S1, unofficial].
    *   Higher vertex output count compared to pixel shader clipping can saturate geometry shader output limits on some hardware [S1, unofficial].

## Background
The method was introduced by Athanasios Gaitatzes, Pavlos Mavridis, and Georgios Papaioannou in the paper "Two Simple Single-pass GPU methods for Multi-channel Surface Voxelization of Dynamic Scenes" [S1, unofficial]. It is part of a family of real-time surface voxelization algorithms designed for deferred rendering and global illumination effects, leveraging OpenGL layered rendering extensions (`gl_Layer`) to write to volume texture arrays in a single pass [S1, unofficial].
