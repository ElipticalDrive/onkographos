# Geometry Shader Triangle Slicing (Z-Pass)

Also called: GS Triangle Slicing, Triangle Slicing Method

## Overview
Geometry Shader Triangle Slicing is a single-pass GPU method for multi-channel surface voxelization that explicitly clips input triangles against volume slice boundaries within the geometry shader, emitting only the valid fragments for rasterization into the appropriate volume layer [S1, unofficial]. It differs from its sibling [Pixel Shader Fragment Clipping](1685-pixel-shader-fragment-clipping.md) by performing clipping in the geometry shader rather than the pixel shader, which avoids fragment rejection overhead on architectures with limited bandwidth or non-unified cores [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Triangle vertices $v_1, v_2, v_3$ in Eye Coordinate Space (ECS) [S1, unofficial].
*   **Data Parameters:** $z_{slice}$ (thickness of the volume slice in volume sweep ECS), $z_{volume\_min}$ (minimum Z depth of the volume in volume sweep ECS) [S1, unofficial].
*   **Output:** Triangle strips rasterized to specific volume texture layers via the built-in variable `gl_Layer` [S1, unofficial].

**Data Structures:**
The geometry shader processes a single triangle input primitive [S1, unofficial]. It generates output vertices for triangle strips [S1, unofficial]. The number of vertices emitted is $3 + 4n$, where $n$ is the number of slices the triangle spans [S1, unofficial]. The method detects triangle emittance and does not produce degenerate quads [S1, unofficial].

**Algorithm Steps:**
The method assumes the triangle is aligned with the Z-axis; if not, it returns immediately [S1, unofficial].

1.  **Sort Vertices:** Sort $v_1, v_2, v_3$ according to their Z-depth in ECS such that $z(v_1) \le z(v_2) \le z(v_3)$ [S1, unofficial].
2.  **Calculate Bounds:** Compute the minimum and maximum slice indices ($s_{min}, s_{max}$) that the triangle intersects [S1, unofficial]:
    $$ s_{min} = \left\lfloor \frac{\min(z(v_1, v_2, v_3) - z_{volume\_min})}{z_{slice}} \right\rfloor $$
    $$ s_{max} = \left\lfloor \frac{\max(z(v_1, v_2, v_3) - z_{volume\_min})}{z_{slice}} \right\rfloor $$
    Integer truncation is used for slice indexing [S1, unofficial].
3.  **Initialize:** Set `layer` to $s_{min}$ [S1, unofficial]. Set `slice` depth to the start of the current slice in ECS [S1, unofficial].
4.  **Case A (Full Containment):** If $z(v_3) \ge slice$ at the initial check, emit the original triangle $(v_1, v_2, v_3)$ to `layer` and return [S1, unofficial].
5.  **Iterate Slices:** Loop while $z(v_3) \ge slice$ [S1, unofficial]:
    *   **Determine Left/Right Intersections:**
        *   If $z(v_2) \ge slice$:
            *   If $z(v_1) \ge slice$: Set $v_{1L} = v_{1R} = v_1$ [S1, unofficial].
            *   Else: Set $v_{1L} = v_2, v_{1R} = v_1$ [S1, unofficial].
            *   Calculate $v_{2L}, v_{2R}$ by intersecting edges with the current slice plane [S1, unofficial].
        *   **Loop Update:** Increment `slice` by $z_{slice}$ and increment `layer` [S1, unofficial].
        *   **Update State:** Set $v_{1L} = v_{2L}, v_{1R} = v_{2R}$ (from previous iteration's right-side intersections) [S1, unofficial].
        *   **Case B:** If $z(v_2) \ge slice$: calculate $v_{2L}, v_{2R}$ by intersecting edges with the current slice plane [S1, unofficial].
        *   **Case C/D (Triangle ends in this slice):** If $z(v_3) < slice$:
            *   If $z(v_2)$ was $\ge slice$ (in previous step): Set $v_{2L} = v_2, v_{2R} = v_3$ (Case C) [S1, unofficial].
            *   Else: Set $v_{2L} = v_{2R} = v_3$ (Case D) [S1, unofficial].
            *   Emit the quad strip $(v_{1R}, v_{1L}, v_{2L}, v_{2R})$ to `layer` [S1, unofficial].
        *   **Case E/F (Triangle continues but vertex status changes):** Else if $z(v_2)$ was $< slice$:
            *   If $z(v_2)$ was $< slice$ (meaning $v_2$ is below current slice): Calculate $v_{2L}, v_{2R}$ by intersecting edges with slice (Case E) [S1, unofficial].
            *   Else (meaning $v_2$ is exactly at slice depth or handled by Case F logic): Calculate $v_{2L}, v_{2R}$ by intersecting edges with $v_2$ depth (Case F) [S1, unofficial].
            *   Emit the quad strip $(v_{1R}, v_{1L}, v_{2L}, v_{2R})$ to `layer` [S1, unofficial].
            *   Update $v_{1L} = v_{2L}, v_{1R} = v_{2R}$ [S1, unofficial].
            *   Calculate new $v_{2L}, v_{2R}$ by intersecting edges with current slice [S1, unofficial].
            *   Emit the quad strip $(v_{1R}, v_{1L}, v_{2L}, v_{2R})$ to `layer` [S1, unofficial].
    *   Repeat until $z(v_3) < slice$ [S1, unofficial].

**Pseudocode:**
The following pseudocode implements Algorithm 1 from [S1, unofficial]. It is self-contained and defines all helper operations.

```python
def GeometryShaderTriangleSlicing(v1, v2, v3, z_slice_thickness, z_volume_min):
    # 1. Check alignment with Z-axis
    if not is_aligned_with_z(v1, v2, v3):
        return

    # 2. Sort vertices by Z depth
    verts = sorted([v1, v2, v3], key=lambda v: v.z)
    v1, v2, v3 = verts[0], verts[1], verts[2]

    # 3. Calculate slice bounds
    z_min_tri = min(v1.z, v2.z, v3.z)
    z_max_tri = max(v1.z, v2.z, v3.z)
    s_min = int((z_min_tri - z_volume_min) / z_slice_thickness)
    s_max = int((z_max_tri - z_volume_min) / z_slice_thickness)

    # 4. Initialize loop variables
    layer = s_min
    current_slice_z = z_volume_min + layer * z_slice_thickness
    
    # Track intersection points from previous slice
    v1L = None
    v1R = None
    v2L = None
    v2R = None
    v2_was_above = False

    # Case A: Triangle fits entirely within the first slice
    if v3.z >= current_slice_z:
        emit_triangle_strip([v1, v2, v3], layer)
        return

    # 5. Iterate through slices
    while v3.z >= current_slice_z:
        if v2.z >= current_slice_z:
            # v2 is above or at slice plane
            if v1.z >= current_slice_z:
                v1L = v1
                v1R = v1
            else:
                v1L = v2
                v1R = v1
            v2L, v2R = intersect_edges(v1, v2, v3, current_slice_z)
            emit_triangle_strip([v1R, v1L, v2L, v2R], layer)
            v1L = v2L
            v1R = v2R
            v2_was_above = True
        else:
            # v2 is below slice plane
            if v2_was_above:
                # Case E
                v2L, v2R = intersect_edges(v1, v2, v3, current_slice_z)
            else:
                # Case F
                v2L, v2R = intersect_edges(v1, v2, v3, v2.z)
            emit_triangle_strip([v1R, v1L, v2L, v2R], layer)
            v1L = v2L
            v1R = v2R
            v2L, v2R = intersect_edges(v1, v2, v3, current_slice_z)
            emit_triangle_strip([v1R, v1L, v2L, v2R], layer)
            v2_was_above = False

        # Increment slice
        current_slice_z += z_slice_thickness
        layer += 1

    # Handle final slice where v3.z < current_slice_z
    if v3.z < current_slice_z:
        if v2_was_above:
            # Case C
            v2L = v2
            v2R = v3
        else:
            # Case D
            v2L = v2R = v3
        emit_triangle_strip([v1R, v1L, v2L, v2R], layer)

# Helper: Intersect triangle edges with a Z-plane
def intersect_edges(va, vb, vc, z_plane):
    pts = []
    if (va.z - z_plane) * (vb.z - z_plane) <= 0:
        pts.append(intersect_point(va, vb, z_plane))
    if (vb.z - z_plane) * (vc.z - z_plane) <= 0:
        pts.append(intersect_point(vb, vc, z_plane))
    if (vc.z - z_plane) * (va.z - z_plane) <= 0:
        pts.append(intersect_point(vc, va, z_plane))
    return pts[0], pts[1]

# Helper: Linear interpolation to find point on segment at z_plane
def intersect_point(va, vb, z_plane):
    t = (z_plane - va.z) / (vb.z - va.z)
    return va + t * (vb - va)

# Helper: Check if triangle is aligned with Z-axis
def is_aligned_with_z(v1, v2, v3):
    # Triangle is aligned if it has extent in Z (non-degenerate in sweep direction)
    return not (v1.z == v2.z == v3.z)
```

**Parameters:**
*   $z_{slice}$: Thickness of the volume slice in volume sweep ECS [S1, unofficial].
*   $z_{min}$: Minimum Z depth of the volume in volume sweep ECS [S1, unofficial].

**Edge Cases and Pitfalls:**
*   Triangles not aligned with the Z-axis are ignored (returned) in this specific Z-Pass implementation [S1, unofficial].
*   The method detects triangle emittance and does not produce degenerate quads [S1, unofficial].
*   On GPU architectures with small bandwidth, the alternative Pixel Shader Clipping method produces many fragments that are rejected in the pixel shader, which is an issue [S1, unofficial]. The Geometry Shader Slicing method is favored here because it produces exactly the fragments rasterized in the final volume slices [S1, unofficial].

## Subtopics

### [Pixel Shader Fragment Clipping](1685-pixel-shader-fragment-clipping.md)
A single-pass GPU method for multi-channel surface voxelization where the geometry shader rasterizes triangles into all intersecting volume slices without clipping, and the pixel shader discards fragments that fall outside the slice boundaries. It avoids the computational overhead of geometry shader clipping by relying on fragment rejection in the pixel shader, achieving performance comparable to geometry slicing while being slightly more efficient for small triangle counts.

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of triangles and the number of slices each triangle intersects [S1, unofficial]. The number of vertices emitted is $3 + 4n$, where $n$ is the number of slices [S1, unofficial].
*   **Memory Complexity:** Depends on the volume grid size and the number of multi-channel render targets (MRTs) [S1, unofficial]. The method uses layered rendering to write directly to volume texture layers [S1, unofficial].
*   **Performance:** Tested on an Intel Core i7 860 @ 2.80GHz, 8 GB RAM, nVIDIA GeForce GTX 285 GPU (1 GB memory) [S1, unofficial]. For the Bunny model (69,451 triangles) at a $256^3$ grid size, Geometry Slicing took 6.43 ms (15 vertices out) and 6.98 ms (19 vertices out) [S1, unofficial].
*   **Strengths:** Produces exactly the fragments rasterized in the final volume slices, avoiding fragment rejection overhead [S1, unofficial]. Preferred on non-unified architectures if pixel shader cores are intensively used, and on architectures with small bandwidth [S1, unofficial].
*   **Limitations:** Requires geometry shader support [S1, unofficial]. Triangles not aligned with the Z-axis are ignored [S1, unofficial]. Performance varies with the number of output vertices allowed by the GPU [S1, unofficial].

## Background
The method was introduced by Athanasios Gaitatzes, Pavlos Mavridis, and Georgios Papaioannou in the paper "Two Simple Single-pass GPU methods for Multi-channel Surface Voxelization of Dynamic Scenes" [S1, unofficial]. It is part of a suite of real-time surface voxelization algorithms designed for deferred rendering and global illumination effects, utilizing OpenGL layered rendering extensions to write to arbitrary volume texture layers [S1, unofficial].
