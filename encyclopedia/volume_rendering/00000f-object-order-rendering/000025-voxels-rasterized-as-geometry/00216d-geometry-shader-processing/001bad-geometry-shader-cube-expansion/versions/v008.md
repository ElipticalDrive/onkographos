# Geometry Shader Cube Expansion

Also called: GS Voxels, GS-based voxelizer, Geometry Shader (Voxels), Geometry Shader quads generated each frame from voxels, Point-to-Cube voxelization

## Overview
Geometry Shader Cube Expansion is a technique that converts mesh surfaces or pre-computed voxel data into geometric primitives by expanding input points into full cube shells within the geometry shader [S1, S2, S3, unofficial]. It solves the problem of rendering voxel-based volumes or shell-voxelized meshes with minimal CPU-side geometry preparation by generating the 6 faces of a cube on the GPU from a single point primitive [S1, S2, S3, unofficial]. Unlike [Geometry Shader (Quads)](4369-geometry-shader-quads.md), which may break voxels down to individual faces or use display lists, this method generates up to 6 quads per voxel point, offering a balance between memory efficiency and render speed [S2, S3, unofficial]. It builds on [Geometry Shader Processing](2524-geometry-shader-processing.md) by utilizing the shader's ability to emit multiple primitives from a single input [G].

## How it works
The method operates in two primary modes depending on the input source: mesh-based voxelization (centroid expansion) and pre-computed voxel data (flag-based expansion) [S1, S2, S3, unofficial]. Both modes rely on the geometry shader to reconstruct 3D geometry from 1D point inputs [S1, S2, S3, unofficial].

### Inputs and Outputs
*   **Input (Mesh Mode):** A stream of triangles (`GL_TRIANGLES`) processed by the geometry shader [S1, unofficial].
*   **Input (Voxel Mode):** A stream of points (`GL_POINTS`) where each point contains the voxel center position, color, and a bitmask of enabled faces [S2, S3, unofficial].
*   **Output:** A stream of triangle strips (`GL_TRIANGLE_STRIP`) with `max_vertices` set to 24 for mesh mode or 12 for voxel mode [S1, S2, S3, unofficial].

### Data Structures
**Voxel Mode Input Structure (CPU-side buffer layout):**
Each voxel is represented by a single point with the following layout [S2, S3, unofficial]:
```python
struct PointVertex:
    position: vec3          # Center of the voxel (12 bytes)
    packedColor: uint32     # Color information (4 bytes)
    enabledFaces: uint8     # Bitmask for face visibility (1 byte)
# Total: 25 bytes per voxel
```
The `enabledFaces` bitmask assigns bits to axes as follows [S2, S3, unofficial]:
*   Bit 0 (0x01): +X face
*   Bit 1 (0x02): -X face
*   Bit 2 (0x04): +Y face
*   Bit 3 (0x08): -Y face
*   Bit 4 (0x10): +Z face
*   Bit 5 (0x20): -Z face

### Pseudocode
The following Python-like pseudocode implements the voxel mode expansion, which is the core algorithm detailed in the sources [S2, S3, unofficial]:
```python
def GeometryShaderCubeExpansion(point_stream, mvp_matrix, voxSize):
    # Extract axis extents from MVP matrix columns scaled by half voxel size
    dx = mvp_matrix[0] * voxSize / 2.0
    dy = mvp_matrix[1] * voxSize / 2.0
    dz = mvp_matrix[2] * voxSize / 2.0
    output_primitives = []

    for point in point_stream:
        center = point.position
        enabled = point.enabledFaces

        # Check +X face (bit 0x01)
        if (enabled & 0x01) and not IsCulled(dx):
            output_primitives.append(AddQuad(center + dx, dy, dz))
        # Check -X face (bit 0x02)
        if (enabled & 0x02) and not IsCulled(-dx):
            output_primitives.append(AddQuad(center - dx, dz, dy))
        # Check +Y face (bit 0x04)
        if (enabled & 0x04) and not IsCulled(dy):
            output_primitives.append(AddQuad(center + dy, dz, dx))
        # Check -Y face (bit 0x08)
        if (enabled & 0x08) and not IsCulled(-dy):
            output_primitives.append(AddQuad(center - dy, dx, dz))
        # Check +Z face (bit 0x10)
        if (enabled & 0x10) and not IsCulled(dz):
            output_primitives.append(AddQuad(center + dz, dx, dy))
        # Check -Z face (bit 0x20)
        if (enabled & 0x20) and not IsCulled(-dz):
            output_primitives.append(AddQuad(center - dz, dy, dx))

    return output_primitives

def AddQuad(center, axis1, axis2):
    # Emits a triangle strip for the quad defined by center and two orthogonal extent vectors
    vertices = [
        center + (axis2 - axis1),
        center + (-axis2 - axis1),
        center + (axis2 + axis1),
        center + (-axis2 + axis1)
    ]
    return TriangleStrip(vertices)

def IsCulled(normal):
    # Returns true if the face normal's Z component in view space is positive
    return normal.z > 0
```
For mesh mode, the geometry shader computes the centroid directly from the three input triangle vertices using `center = (gl_in[0].gl_Position.xyz + gl_in[1].gl_Position.xyz + gl_in[2].gl_Position.xyz) / 3.0` [S1, unofficial]. It then treats this centroid as the cube center and generates all 6 faces unconditionally, computing per-vertex normals, view-space eye vectors, and light directions for shading [S1, unofficial].

### Parameters
*   `voxSize` / `voxel_size`: The side length of the generated cube, passed as a uniform float [S1, S2, S3, unofficial].
*   `mvp_matrix`: The combined Model-View-Projection matrix used for transforming vertices and extracting axis extents [S1, S2, S3, unofficial].
*   `gColor`: An array of colors where `gColor[0]` is typically assigned to emitted vertices [S2, S3, unofficial].

### Edge Cases and Pitfalls
*   **Precision Artifacts:** Centering cubes on triangle centroids approximates the mesh surface, leading to aliasing and holes, especially with large voxel sizes relative to mesh features [S1, unofficial].
*   **Interior Filling:** The method performs shell voxelization only and does not fill the interior of the mesh, making it unsuitable for deep voxelization [S1, unofficial].
*   **Vertex Output Limits:** Emitting up to 12 vertices per primitive in voxel mode may be less efficient on some GPU architectures compared to limiting output to 4 vertices per primitive [S3, unofficial].
*   **Culling Logic:** The `IsCulled` function relies on the normal's Z component in view space, which assumes a specific view direction and coordinate system [S2, S3, unofficial].

## Operating characteristics
*   **Memory Usage:** The method requires 25 bytes per voxel, significantly lower than previous techniques requiring 96–576 bytes [S2, S3, unofficial].
*   **Performance:** Render time is close to display lists, which are the fastest but have high setup costs and immutability [S2, S3, unofficial].
*   **Scalability:** Performance scales with the number of voxels and visible faces, with culling reducing emitted vertices for sparse volumes [S2, S3, unofficial].
*   **Strengths:** Low memory usage, dynamic GPU-side geometry generation, and simple implementation [S2, S3, unofficial].
*   **Limitations:** Lower geometric accuracy for mesh voxelization compared to ray-casting or rasterization-based voxelizers due to centroid approximation [S1, unofficial]. High vertex output count can impact GPU throughput if not optimized [S3, unofficial].

## Background
The technique was developed as part of exploring simple voxel rendering methods for voxel art and shell-based volume representation [S1, unofficial]. It was implemented in GeeXLab demos around 2016, comparing it against header-only C voxelizer libraries and display list techniques [S1, unofficial]. The memory-efficient point-based approach with bitmask flags was further detailed in "Quads All the Way Down: Simple Voxel Rendering" by Caleb Leak, which benchmarked it against other geometry shader and display list techniques on a GTX 980 Ti [S2, S3, unofficial].
