# Velocity Visualization via Geometry Shader Extrusion
Also called: Grid Velocity Lines, Velocity Vector Lines

## Overview
This method visualizes a 3D velocity field by rendering short line segments whose length and direction correspond to the velocity vector in each grid cell [S1, unofficial]. It differs from volume rendering techniques by converting scalar/vector field data into explicit geometric primitives (lines) rather than splatting or ray-marching, providing a sparse, vector-based representation of flow [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A Vertex Buffer Object (VBO) containing one point per grid cell in world space; a 3D texture volume (`sampler3D`) storing the velocity vectors; Model-View-Projection (MVP) matrix.
- **Output:** A set of line primitives rendered with red color and alpha gradients.

**Data Structures:**
- **VBO:** Contains `vec4 Position` for each grid cell.
- **Volume Texture:** 3D texture where each texel stores a `vec3` velocity vector. Coordinates are normalized to $[0, 1]$.

**Numbered Steps:**
1.  **Vertex Shader:** Compute the clip-space position using the MVP matrix. Pass the original world-space position to the geometry shader.
2.  **Geometry Shader Input:** Receive the point primitive. Retrieve the world-space position.
3.  **Velocity Sampling:** Sample the velocity vector from the 3D volume texture. The texture coordinates are derived from the world-space position, typically normalized to $[0, 1]$ or $[-1, 1]$ depending on the coordinate system. The source code uses `0.5 * (vPosition[0].xyz + 1.0)`, implying the input positions are in $[-1, 1]$ range.
4.  **Line Extrusion:**
    -   Emit the first vertex at the original position with alpha $0$.
    -   Compute the second vertex position by adding the sampled velocity vector to the original position.
    -   Transform the second vertex to clip space using the MVP matrix.
    -   Emit the second vertex with alpha $1$.
5.  **Fragment Shader:** Output a red color scaled by the interpolated alpha and a uniform brightness factor.

**Formulas:**
-   **Clip Space Position:** $P_{clip} = M_{vp} \times P_{world}$
-   **Texture Coordinate:** $C_{tex} = 0.5 \times (P_{world} + 1.0)$ (assuming $P_{world} \in [-1, 1]$)
-   **Velocity Vector:** $V = \text{texture}(Volume, C_{tex}).xyz$
-   **Second Vertex Position:** $P_{end} = P_{world} + V$
-   **Fragment Color:** $C_{frag} = B \times (A, 0, 0, 1)$, where $B$ is brightness and $A$ is interpolated alpha.

**Parameters:**
-   **Brightness:** Uniform float controlling intensity, typically $0.5$ [S1, unofficial].

**Pseudocode:**
```python
# Vertex Shader
def vertex_shader(Position: vec4, ModelviewProjection: mat4) -> (vec4 clip_pos, vec4 world_pos):
    clip_pos = ModelviewProjection * Position
    world_pos = Position
    return clip_pos, world_pos

# Geometry Shader
def geometry_shader(world_pos: vec4, ModelviewProjection: mat4, Volume: sampler3D) -> list[Vertex]:
    # Sample velocity from 3D texture
    # Assuming world_pos.xyz is in [-1, 1] range
    coord = 0.5 * (world_pos.xyz + 1.0)
    velocity = texture(Volume, coord).xyz
    
    vertices = []
    
    # First vertex: original position, alpha 0
    v1_clip = ModelviewProjection * world_pos
    v1_alpha = 0.0
    vertices.append(Vertex(clip_pos=v1_clip, alpha=v1_alpha))
    
    # Second vertex: offset by velocity, alpha 1
    end_pos = world_pos + vec4(velocity, 0.0)
    v2_clip = ModelviewProjection * end_pos
    v2_alpha = 1.0
    vertices.append(Vertex(clip_pos=v2_clip, alpha=v2_alpha))
    
    return vertices

# Fragment Shader
def fragment_shader(alpha: float, Brightness: float) -> vec4:
    color = vec4(alpha, 0.0, 0.0, 1.0)
    return Brightness * color
```

**Edge Cases and Pitfalls:**
-   **Coordinate System:** The source code assumes input positions are in $[-1, 1]$ range for texture sampling. If positions are in a different range, the texture coordinate calculation must be adjusted [S1, unofficial].
-   **Blending:** The technique relies on alpha blending. The source mentions using `GL_MAX` blending rather than `GL_FUNC_ADD` for certain effects, but the default blending equation is `GL_FUNC_ADD` [S1, unofficial].
-   **Velocity Magnitude:** The length of the line is directly proportional to the velocity vector's magnitude. Large velocities may cause lines to extend far outside the voxel, potentially causing visual clutter or occlusion issues.

## Operating characteristics
-   **Time Complexity:** $O(N)$ where $N$ is the number of grid cells. Each cell generates a constant number of vertices (2) and fragments.
-   **Memory Complexity:** $O(N)$ for the VBO and $O(V)$ for the volume texture, where $V$ is the volume resolution.
-   **Strengths:** Simple implementation; efficient on GPU; provides clear vector direction and magnitude visualization.
-   **Limitations:** Sparse representation; may not show flow continuity as well as streamlines; sensitive to velocity magnitude scaling.

## Background
This technique was described by Philip Rideout in a blog post titled "Volumetric Splatting at The Little Grasshopper" in November 2010 [S1, unofficial]. It is part of the "Pez" ecosystem, which includes demo code for various rendering techniques.
