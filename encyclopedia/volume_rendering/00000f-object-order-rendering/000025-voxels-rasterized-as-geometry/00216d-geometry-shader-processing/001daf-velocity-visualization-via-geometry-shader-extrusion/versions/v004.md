# Velocity Visualization via Geometry Shader Extrusion
Also called: Grid Velocity Lines, Velocity Vector Lines

## Overview
This method visualizes a 3D velocity field by rendering short line segments whose length and direction correspond to the velocity vector in each grid cell [S1, unofficial]. It differs from volume rendering techniques by converting field data into explicit geometric primitives (lines) rather than splatting or ray-marching, providing a sparse, vector-based representation of flow [S1, unofficial]. It builds on [Geometry Shader Processing](2524-geometry-shader-processing.md).

## How it works
**Inputs and Outputs:**
- **Input:** A Vertex Buffer Object (VBO) containing one point per grid cell [S1, unofficial]. A 3D texture volume (`sampler3D`) storing velocity vectors [S1, unofficial]. The Model-View-Projection (MVP) matrix [S1, unofficial].
- **Output:** A set of line primitives rendered with red color and alpha gradients [S1, unofficial].

**Data Structures:**
- **VBO:** Contains `vec4 Position` for each grid cell [S1, unofficial].
- **Volume Texture:** 3D texture where each texel stores a `vec3` velocity vector [S1, unofficial].

**Numbered Steps:**
1. Populate a VBO with a single point per grid cell [S1, unofficial].
2. In the vertex shader, compute the clip-space position using the MVP matrix and pass the original world-space position to the geometry shader [S1, unofficial].
3. In the geometry shader, retrieve the input vertex position and sample the velocity vector from the 3D texture volume at the normalized coordinate [S1, unofficial].
4. Emit the first vertex of the line strip at the original position with an alpha value of 0 [S1, unofficial].
5. Emit the second vertex of the line strip at the position offset by the velocity vector, with an alpha value of 1 [S1, unofficial].
6. Finalize the primitive in the geometry shader [S1, unofficial].
7. In the fragment shader, output a red color scaled by the interpolated alpha and a uniform brightness factor [S1, unofficial].

**Formulas:**
- **Clip Space Position:** $P_{clip} = M_{vp} \times P_{world}$ [S1, unofficial].
- **Texture Coordinate:** $C_{tex} = 0.5 \times (P_{world} + 1.0)$, assuming input positions are in the $[-1, 1]$ range [S1, unofficial].
- **Velocity Vector:** $V = \text{texture}(Volume, C_{tex}).xyz$ [S1, unofficial].
- **Second Vertex Position:** $P_{end} = P_{world} + V$ [S1, unofficial].
- **Fragment Color:** $C_{frag} = B \times (A, 0, 0, 1)$, where $B$ is brightness and $A$ is interpolated alpha [S1, unofficial].

**Parameters:**
- **Brightness:** A uniform float controlling the intensity of the output color, typically set to 0.5 [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Coordinate System:** The source code assumes input positions are in the $[-1, 1]$ range for texture sampling [S1, unofficial].
- **Blending:** The technique relies on alpha blending; the source notes that `GL_MAX` blending may be preferred over `GL_FUNC_ADD` for certain effects, though the default is `GL_FUNC_ADD` [S1, unofficial].
- **Velocity Magnitude:** The length of the line is directly proportional to the velocity vector's magnitude [S1, unofficial].

**Pseudocode:**
```python
# Vertex Shader
def vertex_shader(position, modelview_projection):
    clip_pos = modelview_projection @ position
    world_pos = position
    return clip_pos, world_pos

# Geometry Shader
def geometry_shader(world_pos, modelview_projection, volume_texture):
    # Sample velocity from 3D texture
    coord = 0.5 * (world_pos[:3] + 1.0)
    velocity = volume_texture.sample(coord)[:3]

    vertices = []

    # First vertex: original position, alpha 0
    v1_clip = modelview_projection @ world_pos
    vertices.append((v1_clip, 0.0))

    # Second vertex: offset by velocity, alpha 1
    end_pos = world_pos + [velocity[0], velocity[1], velocity[2], 0.0]
    v2_clip = modelview_projection @ end_pos
    vertices.append((v2_clip, 1.0))

    return vertices

# Fragment Shader
def fragment_shader(alpha, brightness):
    return [brightness * alpha, 0.0, 0.0, brightness]
```
Matrix multiplication (`@`) and texture sampling are standard operations [G].

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of grid cells, as each cell generates a constant number of vertices and fragments [G].
- **Memory Complexity:** $O(N)$ for the VBO and $O(V)$ for the volume texture, where $V$ is the volume resolution [G].
- **Strengths:** Simple implementation; efficient on GPU; provides clear vector direction and magnitude visualization [S1, unofficial].
- **Limitations:** Sparse representation; may not show flow continuity as well as streamlines; sensitive to velocity magnitude scaling [S1, unofficial].

## Background
This technique was described by Philip Rideout in a blog post titled "Volumetric Splatting at The Little Grasshopper" in November 2010 [S1, unofficial]. It is part of the "Pez" ecosystem, which includes demo code for various rendering techniques [S1, unofficial].
