# Adaptive Beam Generation

Also called: Hierarchical Projected Grid

## Overview
Adaptive Beam Generation is a method for generating caustic beams by rasterizing specular surfaces from the light's perspective into a G-buffer, projecting a planar grid onto these surfaces, and adaptively refining the resulting grid triangles based on geometric discontinuities, beam energy, and camera parameters [S1]. It differs from standard caustic mapping by projecting a regular grid onto the G-buffer parameterization instead of emitting photons, and relies on a geometry shader with stream-out feedback for adaptive subdivision [S1].

## How it works
**Inputs and Outputs**
*   **Input:** Specular geometry, light source parameters, camera position, and a coarse regular planar grid.
*   **Output:** A set of refined caustic beam base triangles ready for extrusion and rasterization [S1].

**Data Structures**
*   **G-buffer:** An off-screen geometry buffer storing per-pixel data for the specular surfaces as seen from the light source [S1]. Fields include:
    *   Position (3D)
    *   Normal (3D)
    *   Material properties (transparency, index of refraction) [S1].

**Steps**
1.  **Rasterize Specular Surfaces:** Render the specular surfaces from the light source's viewpoint into the G-buffer. This creates a 2D parameterization over the directly lit surfaces [S1].
2.  **Project Planar Grid:** Take a coarse, regular planar grid. For each vertex, sample the corresponding location in the G-buffer and move the vertex to the sampled 3D position on the surface [S1].
3.  **Form Base Triangles:** Treat each cell of the initial regular grid as two triangles to form caustic beams with triangular bases. Omit invalid triangles crossing the silhouettes of specular objects or lying outside [S1].
4.  **Adaptive Refinement:** Iteratively refine the beam triangles using a geometry shader. The decision to split, keep, or discard a triangle is based on three heuristics:
    *   **Geometric Discontinuities:** Compare the sampled surface parameters (normal and depth) at the location where the beam edges start. Split the triangles if they differ significantly [S1].
    *   **Beam Energy:** Assess the beams' energy and contribution. Divergent beams are typically unproblematic unless their energy is very high. Convergent beams focus light and are refined with higher priority. For non-isotropic light sources, lighting discontinuities can also be accounted for here [S1].
    *   **Camera Proximity:** Estimate the beam's importance to the camera. Find the closest point to the camera on the beam's central ray (average of the three beam edges) and base the decision on the distance of this point to the camera [S1].
5.  **Repeat:** Repeat the refinement step for a fixed number of iterations [S1].

**Formulas**
*   Central ray direction: $\vec{d} = \frac{\vec{e}_0 + \vec{e}_1 + \vec{e}_2}{3}$, where $\vec{e}_0, \vec{e}_1, \vec{e}_2$ are the three beam edge vectors [S1].
*   Closest point on ray to camera: $\vec{p} = \vec{o} + t\vec{d}$, where $\vec{o}$ is the ray origin, $\vec{d}$ is the normalized central ray direction, and $t = (\vec{c} - \vec{o}) \cdot \vec{d}$ with $\vec{c}$ being the camera position [S1].

**Parameters**
*   **Refinement Steps:** 3 to 4 steps are sufficient for most cases [S1].

**Edge Cases and Pitfalls**
*   **Boundary Mismatch:** Projected grid boundaries typically do not match the silhouettes (discontinuities) of the surfaces. This is suppressed using adaptive subdivision, at the expense of generating more beams [S1].
*   **Precision:** Comparing normal and depth values for discontinuity detection requires thresholding to avoid over-subdivision in smooth areas or under-subdivision in sharp areas [G].

    projected_vertices = {}
    for vertex in coarse_grid.vertices:
        uv = vertex.uv
        g_data = sample_gbuffer(uv)
        if g_data is not None:
            projected_vertices[vertex.id] = g_data.position
        else:
            projected_vertices[vertex.id] = None

    # Step 3: Form base triangles. Each cell becomes two triangles.
    initial_triangles = []
    for cell in coarse_grid.cells:
        v_ids = cell.vertex_ids
        p0 = projected_vertices[v_ids[0]]
        p1 = projected_vertices[v_ids[1]]
        p2 = projected_vertices[v_ids[2]]
        p3 = projected_vertices[v_ids[3]]

        # Omit invalid triangles crossing silhouettes or lying outside
        if p0 is not None and p1 is not None and p2 is not None:
            initial_triangles.append([p0, p1, p2])
        if p0 is not None and p2 is not None and p3 is not None:
            initial_triangles.append([p0, p2, p3])

    # Step 4 & 5: Adaptive refinement loop
    current_triangles = initial_triangles
    for step in range(3, 5): # 3 to 4 steps sufficient
        next_triangles = []
        for tri in current_triangles:
            should_split = False

            # Heuristic 1: Geometric discontinuities
            if check_discontinuity(tri):
                should_split = True

            # Heuristic 2: Beam energy
            # Sources do not provide exact convergence formula; typically assessed from light direction and surface normals [G]
            if is_convergent_beam(tri):
                should_split = True

            # Heuristic 3: Camera proximity
            if check_camera_proximity(tri, camera_position):
                should_split = True

            if should_split:
                # Split triangle into smaller ones
                sub_tris = split_triangle(tri)
                next_triangles.extend(sub_tris)
            else:
                next_triangles.append(tri)
        current_triangles = next_triangles

    return current_triangles

def check_camera_proximity(tri, camera_pos):
    # Find closest point to camera on beam's central ray (average of three beam edges)
    e0 = tri[1].pos - tri[0].pos
    e1 = tri[2].pos - tri[1].pos
    e2 = tri[0].pos - tri[2].pos

    return [[tri[0], m0, m2], [m0, tri[1], m1], [m2, m1, tri[2]], [m0, m1, m2]]

## Operating characteristics
*   **Time Complexity:** Not given in the sources. Each refinement step increases the number of triangles, limited by the 3-4 step constraint [S1].
*   **Memory Complexity:** Not given in the sources. Proportional to the number of generated beam primitives. The G-buffer size is determined by the light's view frustum resolution [S1].
*   **Strengths:** Decouples geometric complexity from the actual caustic generation process; adapts to light emission characteristics and camera position; handles complex specular surfaces efficiently [S1].
*   **Limitations:** Generates more beams than necessary in some cases due to boundary mismatch suppression; requires G-buffer rasterization from the light's perspective [S1].
*   **When to use:** Real-time volume caustics with dynamic specular surfaces and camera movement [S1].
*   **When not to use:** Not given in the sources.

## Background
Adaptive Beam Generation, also known as Hierarchical Projected Grid, was introduced in the paper "Real-time volume caustics with adaptive beam tracing" [S1]. It builds upon standard caustic mapping by replacing photon emission with a projected grid approach that uses a G-buffer for surface parameterization [S1].
