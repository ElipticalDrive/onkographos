# Proxy Mesh Rendering for Page Visibility

Also called: Visibility Buffer Reduction

## Overview
Proxy Mesh Rendering for Page Visibility determines which virtual memory pages are visible in a scene by rendering a simplified proxy mesh to a visibility buffer and reducing that buffer to a list of active page IDs [S1]. The method encodes depth information to support Level of Detail (LOD) selection and uses a compute shader reduction step to minimize memory bandwidth [S1].

## How it works
**Inputs and Outputs**
* **Input:** A proxy mesh representing the geometry of the scene, where each face is associated with a specific virtual memory page ID [S1].
* **Output:** A CPU-accessible array of page IDs. Entries are zero for invisible pages and contain integer depth values for visible pages [S1].

**Data Structures**
* **Visibility Buffer:** A single-channel, 32-bit unsigned integer image rendered at low resolution to enhance performance [S1].
* **Page ID Buffer:** A buffer passed to the fragment shader containing the page ID for each face, indexed by the face index [S1].

**Steps**
1. **Vertex Shader Execution:** The vertex shader receives vertex positions and applies model and camera transformations [S1].
2. **Fragment Shader Execution:** For each rasterized fragment, the fragment shader retrieves the page ID corresponding to the input face index [S1]. Background and unassigned faces output a zero page ID, which is ignored in later steps [S1].
3. **Visibility Buffer Reduction:** A compute shader processes the visibility buffer to generate a list of required page IDs [S1]. It updates each pixel's list entry in parallel, encoding depth as integers that decrease with greater depth [S1]. The `atomicMax()` function ensures only the closest depth value is written to the buffer [S1]. The shader iterates through linked pages per pixel to set buffer entries, connecting nearby pages to mitigate the effects of low resolution [S1].
4. **Data Transfer:** The buffer is transferred to CPU memory [S1]. The resulting array contains zeroes for unneeded pages and depth values for needed pages [S1].

**Pseudocode**

```python
# Constants
WORKGROUP_SIZE = 256  # Workgroup size for shared memory optimization [G]

# Vertex Shader
def vertex_shader(position, model_matrix, camera_matrix):
    # Apply model and camera transformations [S1]
    return camera_matrix @ (model_matrix @ position)

# Fragment Shader
def fragment_shader(face_index, page_id_buffer):
    # Retrieve page ID for the current face [S1]
    page_id = page_id_buffer[face_index]
    # Background and unassigned faces result in zero page [S1]
    # Sources do not specify how to detect background or unassigned faces [G]
    if page_id is None:
        return 0
    return page_id

# Compute Shader (Reduction)
def compute_shader_thread(pixel_idx, visibility_buffer, linked_pages, depth_values):
    # Shared memory optimization suggested to avoid atomic contention [S1]
    shared_depth = [0] * WORKGROUP_SIZE

    # Encode depth as integers that decrease with greater depth [S1]
    new_depth = depth_values[pixel_idx]

    # Use atomicMax to ensure only the closest (maximum integer) depth is kept [S1]
    visibility_buffer[pixel_idx] = atomic_max(visibility_buffer[pixel_idx], new_depth)

    # Iterate through linked pages per pixel to set buffer entries [S1]
    for linked_page in linked_pages[pixel_idx]:
        visibility_buffer[linked_page] = atomic_max(visibility_buffer[linked_page], new_depth)

def atomic_max(current, new):
    # Simulates hardware atomicMax operation [G]
    return new if new > current else current

# CPU Side
def transfer_to_cpu(visibility_buffer):
    # Transfer buffer to CPU memory [S1]
    return list(visibility_buffer)
```

**Parameters**
* **Resolution:** The visibility buffer is rendered at low resolution to enhance performance, as atomic operations are avoided in favor of shared memory in workgroups [S1].

**Edge Cases and Pitfalls**
* **Race Conditions:** Finding the minimum depth for LOD communication can lead to race conditions [S1]. `atomicMax()` is employed but has an adverse performance impact on concurrent thread updates [S1].
* **Primitive ID Performance:** Using `gl_PrimitiveID` has a negative performance impact [S1]. The implementation uses the leading vertex to determine triangle primitive IDs instead [S1].
* **Distant Page Misses:** Low resolution can cause distant pages to be missed in virtual texturing [S1]. However, overlapping Gaussians cause nearby pages to remain memory-bound, making the trade-off acceptable [S1].

## Operating characteristics
* **Performance:** Rendering at low resolution improves performance by reducing the number of atomic operations required [S1]. However, atomic operations themselves have an adverse performance impact on concurrent thread updates [S1].
* **Memory:** The method reduces memory bandwidth usage by transferring a reduced list of page IDs rather than full visibility data [S1].
* **Accuracy:** Low resolution may cause distant pages to be missed [S1]. This is mitigated by page linking, which connects nearby pages [S1].
* **When to use:** Suitable for virtual texturing systems where nearby pages are memory-bound due to overlapping geometry (e.g., 3D Gaussian Splatting) [S1].
* **When not to use:** Not suitable when precise visibility of distant, non-overlapping pages is critical, as low resolution may miss them [S1].

## Background
The method is described in the context of virtual memory for 3D Gaussian Splatting [S1]. It builds on techniques discussed by Hable regarding primitive ID performance and Mayer regarding small visibility buffers for virtual texturing [S1]. The implementation is part of a Vulkan-based system described by Haberl [S1].
