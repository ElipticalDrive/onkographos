# 3-axis rasterization voxelization

Also called: 6-separating voxelization of 2D input, CNS*11 method, FBP09 method

## Overview
This method produces a 6-separating voxelization of 3D input geometry by rasterizing primitives along three axis-aligned projection directions in three separate passes [S1, unofficial]. It is distinct from 26-separating methods (such as full-volume coverage) by generating a sparser voxel set that is sufficient for applications using 6-connected ray marching [S1, unofficial]. It is equivalent to using a "crosshairs" intersection target and is notably robust for curved primitives, requiring only point-depth evaluations [S1, unofficial].

## How it works
**Inputs:** A set of 3D input primitives (typically triangles or curved patches) and a 3D voxel grid resolution.
**Outputs:** A set of occupied voxel indices $S_d$ representing the surface.

**Data Structures:**
*   **Voxel Grid:** A 3D array or hash map storing boolean occupancy or voxel IDs.
*   **2D Rasterization Buffer:** A 2D buffer (image) used during each pass to store depth values or primitive IDs. The dimensions correspond to the resolution of the voxel grid projected onto the 2D plane.

**Steps:**
1.  **Initialize:** Clear the 3D voxel occupancy grid.
2.  **Loop over Axes:** For each of the three principal axes $d \in \{x, y, z\}$:
    a.  **Project:** Project all input primitives onto the 2D plane perpendicular to axis $d$.
    b.  **Rasterize:** Rasterize the projected primitives into a 2D buffer. For each pixel $(u, v)$ covered by a primitive, compute the depth $z_{prim}$ of the primitive at the pixel center.
        *   *Note:* For curved primitives, this requires evaluating the surface function at the 2D pixel coordinates to find the corresponding 3D depth along the projection axis [S1, unofficial].
    c.  **Map to Voxel:** For each pixel $(u, v)$ with a valid depth $z_{prim}$:
        i.  Determine the voxel column index $(i, j)$ corresponding to pixel $(u, v)$.
        ii. Calculate the voxel center depth $z_{vox}$ for the voxel in column $(i, j)$ that is closest to $z_{prim}$.
        iii. Mark the voxel at $(i, j, k)$ as occupied, where $k$ is the voxel index along axis $d$ corresponding to $z_{vox}$.
3.  **Aggregate:** The union of voxels marked in all three passes constitutes the final voxel set $S_d$.

**Pseudocode:**
```python
def voxelize_3_axis(primitives, grid_resolution):
    # Initialize 3D occupancy grid
    # grid[x][y][z] = False
    grid = create_3d_grid(grid_resolution)
    
    axes = ['x', 'y', 'z']
    
    for axis in axes:
        # Determine the 2D plane axes (e.g., if axis is 'x', plane is 'yz')
        plane_axes = [a for a in axes if a != axis]
        
        # Create 2D buffer for depth storage
        # Initialize with infinity
        depth_buffer = create_2d_buffer(grid_resolution[plane_axes[0]], 
                                        grid_resolution[plane_axes[1]])
        
        # Rasterize primitives onto the 2D plane
        for prim in primitives:
            # Project primitive onto 2D plane
            projected_prim = project(prim, axis)
            
            # Rasterize to fill depth_buffer
            # For each pixel (u, v) covered by projected_prim:
            #   Compute depth of prim at pixel center along 'axis'
            #   Update depth_buffer[u][v] with min(current, new_depth)
            rasterize_primitive(projected_prim, axis, depth_buffer)
            
        # Map 2D buffer to 3D voxels
        for u in range(grid_resolution[plane_axes[0]]):
            for v in range(grid_resolution[plane_axes[1]]):
                depth_val = depth_buffer[u][v]
                if depth_val is not infinity:
                    # Find the voxel index along the projection axis
                    # closest to depth_val
                    k = round_to_voxel_index(depth_val, axis)
                    
                    # Map 2D pixel coordinates to 3D voxel coordinates
                    i = u # or v, depending on mapping
                    j = v # or u
                    
                    # Mark voxel as occupied
                    grid[i][j][k] = True
                    
    return grid
```

**Parameters:**
*   **Grid Resolution:** Determines the size of the voxel grid. Typical values depend on scene scale and required detail.
*   **Depth Evaluation:** For curved primitives, the method relies on accurate point-depth evaluation at pixel centers [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Curved Primitives:** The method produces 6-separating results even for curved primitives, a property that is difficult to ascertain without topological analysis [S1, unofficial].
*   **Precision:** Depth evaluation at pixel centers must be precise to ensure the correct voxel is selected [S1, unofficial].
*   **Boundaries:** Ensure proper handling of primitives intersecting voxel boundaries to avoid gaps or overlaps that violate 6-separation.

## Subtopics

### 6-separating voxelization
A general category of voxelization methods that ensure 6-connected paths do not penetrate separating surfaces. The 3-axis rasterization method is a specific implementation of this [S1, unofficial].

### Crosshairs Intersection Target
The geometric interpretation of the 3-axis rasterization method, where the intersection target consists of line segments connecting voxel face centers [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot R^2)$, where $N$ is the number of primitives and $R$ is the grid resolution per axis (assuming uniform rasterization cost). Three passes are required.
*   **Memory Complexity:** $O(R^3)$ for the voxel grid, plus $O(R^2)$ for the 2D buffers per pass.
*   **Strengths:** Produces a sparse voxel set compared to 26-separating methods. Simple to implement using standard 2D rasterization hardware. Robust for curved primitives.
*   **Limitations:** Requires three passes over the geometry. May produce gaps if depth evaluation is inaccurate.
*   **When to use:** When 6-connected ray marching is sufficient and sparsity is desired.
*   **When not to use:** When 26-separability is required for complex topological queries.

## Background
The method was analyzed by Laine et al. [S1, unofficial] in the context of topological approaches to voxelization. It is equivalent to GPU-based methods by Forest et al. [FBP09] and Crassin et al. [CNS*11]. The theoretical basis for 6-separation and intersection targets is discussed in Cohen-Or and Kaufman [COK97] and [COK95].
