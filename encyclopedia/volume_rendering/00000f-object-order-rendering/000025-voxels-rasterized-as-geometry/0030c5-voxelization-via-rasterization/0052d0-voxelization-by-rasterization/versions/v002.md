# Voxelization by Rasterization

Also called: Hybrid Ambient Occlusion (HAO), Occupancy grid generation via rasterization, Voxelization by Eisemann and Décoret

## Overview
This method generates a 3D occupancy grid (voxel proxy) by rasterizing scene geometry into a 3D texture using a single-pass orthographic projection [S1]. It solves the problem of capturing geometry outside the view frustum or occluded by front-facing objects for downstream applications like Hybrid Ambient Occlusion (HAO) [S1]. It differs from standard screen-space techniques by operating in object space, allowing it to consider occluders that are not currently visible on the screen [S1].

## How it works
**Inputs:**
- Scene geometry (triangles) within a defined bounding box [S1].
- Orthographic camera parameters defining the voxelization volume (near/far planes) [S1].

**Outputs:**
- A 3D texture representing the occupancy grid [S1].

**Data Structures:**
- **Voxel Grid:** A 3D texture where each slice represents a layer [S1].
- **Cell Representation:** Each pixel in the 3D texture holds one to four 32-bit unsigned integer values [S1]. A voxel cell is described by a single bit indicating the presence of geometry in its associated sub-volume [S1].
- **Bit Packing:** Using up to 8 output buffers simultaneously leads to a maximum 3D resolution ranging from $256^3$ to $1024^3$ according to the pixel format [S1].

**Steps:**
1. **Setup Voxelization Camera:** Define an orthographic camera that encompasses the region of interest (bounding box) [S1].
2. **Disable Pipeline Operations:** Disable texturing, depth testing, and other unnecessary operations to optimize performance [S1].
3. **Rasterize Geometry:** Render the scene geometry from the orthographic camera [S1].
4. **Logical Combination:** Combine newly rasterized fragments with existing data in the framebuffer using a logical OR operator. This ensures that if any part of a triangle covers a voxel cell, that cell is marked as occupied [S1].
5. **Handle Axis-Aligned Artifacts:** To prevent polygons aligned with the viewing direction from having a zero framebuffer footprint (and thus being missed), rotate the voxelizing camera by a random angle prior to voxelization [S1].

**Pseudocode:**
```python
def voxelize_by_rasterization(triangles, bounding_box, resolution, num_buffers):
    # Initialize 3D occupancy grid (Nx, Ny, Nz) with zeros
    grid = [[[0] * num_buffers for _ in range(resolution[1])] for _ in range(resolution[0])]
    
    # Define orthographic projection for the bounding box
    # [G] Standard orthographic projection matrix setup
    proj_matrix = orthographic_projection(bounding_box)
    
    # Rotate projection by a random angle to avoid axis-aligned artifacts
    # [G] Random rotation prevents zero-area projection of axis-aligned polygons
    angle = random.uniform(0, 2 * math.pi)
    rot_matrix = rotation_matrix_z(angle)
    proj_matrix = rot_matrix @ proj_matrix
    
    # Disable depth test and texturing
    # [G] Standard pipeline configuration
    use_depth_test = False
    use_texturing = False
    
    # Clear grid to zero
    for z in range(resolution[2]):
        for y in range(resolution[1]):
            for x in range(resolution[0]):
                grid[x][y][z] = [0] * num_buffers
    
    # Rasterize each triangle
    for tri in triangles:
        if intersects_bounding_box(tri, bounding_box):
            # Project triangle vertices to 2D screen space
            projected = [transform(proj_matrix, v) for v in tri]
            # Rasterize projected triangle onto 2D slices
            for z in range(resolution[2]):
                slice_tri = project_to_slice(projected, z)
                if slice_tri:
                    # Rasterize 2D triangle to pixel coordinates
                    pixels = rasterize_2d_triangle(slice_tri)
                    for (px, py) in pixels:
                        # Combine with existing grid data using logical OR
                        for b in range(num_buffers):
                            grid[px][py][z][b] |= compute_occupancy_bit(tri, px, py, z)
    return grid
```

**Parameters:**
- **Resolution:** Maximum 3D resolution ranges from $256^3$ to $1024^3$ depending on the pixel format and number of output buffers (up to 8) [S1].
- **Bit Depth:** Each voxel cell is described by a single bit [S1].

**Edge Cases and Pitfalls:**
- **Axis-Aligned Artifacts:** Polygons aligned with the viewing direction of the voxelizing camera have a framebuffer footprint of zero and are not stored. Solution: Rotate the voxelizing camera by a random angle prior to voxelization [S1].
- **Precision:** Numerical precision issues may cause axis-aligned polygons to be missed if the camera is not rotated [S1].

## Operating characteristics
- **Time Complexity:** Single-pass rasterization makes it fast, suitable for real-time applications [S1].
- **Memory Complexity:** Depends on resolution and bit packing. Up to 8 buffers allow higher resolution but increase memory usage [S1].
- **Strengths:** Real-time performance, handles dynamic scenes without CPU precomputation, considers geometry outside the view frustum [S1].
- **Limitations:** Axis-aligned artifacts if camera is not rotated, lower fidelity than exact methods due to 3D proxy approximation [S1].
- **When to Use:** Real-time ambient occlusion in dynamic scenes where objects outside the view frustum contribute to occlusion [S1].

## Background
The method was introduced by Eisemann and Décoret in 2006 as part of the Hybrid Ambient Occlusion (HAO) technique [S1]. It was designed to overcome the limitations of screen-space ambient occlusion (SSAO) by incorporating object-space information [S1]. The technique has been used in real-time rendering engines for dynamic scenes [S1].
