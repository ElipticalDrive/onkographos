# Chunked UV Rasterization with Face ID Storage

Also called: UV Space Rasterization for Voxelization

## Overview
This method rasterizes a 3D mesh in 2D UV space to generate voxel data, storing the face ID in the alpha channel of the rasterization buffer to enable per-texel face identification and subsequent 3D position interpolation. It differs from standard rasterization by decoupling the geometric projection from the final voxel grid storage, using a chunked approach to manage memory usage when processing large meshes. It builds on [Voxelization via Rasterization](6352-voxelization-via-rasterization.md).

## How it works
**Inputs:**
- `out_vertices`: Tensor of vertex positions, shape $(N, 3)$.
- `out_faces`: Tensor of face indices, shape $(M, 3)$.
- `out_uvs`: Tensor of UV coordinates, shape $(N, 2)$.
- `texture_size`: Integer resolution of the 2D rasterization buffer (e.g., 1024).
- `chunk_size`: Integer number of faces to process per rasterization call (default 100,000).

**Outputs:**
- `rast`: Rasterization buffer tensor, shape $(1, \text{texture\_size}, \text{texture\_size}, 4)$. The alpha channel stores the accumulated face ID.
- `pos`: Interpolated 3D positions for valid pixels, shape $(\text{texture\_size}, \text{texture\_size}, 3)$.

**Data Structures:**
- `rast`: A 4-channel float32 tensor. Channels 0-2 store interpolated barycentric coordinates or depth (depending on the rasterizer implementation, but typically depth/coverage is implicit in the mask), and channel 3 (alpha) stores the face ID.
- `mask`: Boolean tensor indicating valid pixels where `rast[..., 3] > 0`.

**Steps:**
1. **Prepare UV Coordinates:** Convert UVs to clip space for rasterization. The UVs are scaled to $[-1, 1]$ and padded with $z=0$ and $w=1$.
   $$ \text{uvs\_rast} = \text{cat}([\text{out\_uvs} \times 2 - 1, \mathbf{0}, \mathbf{1}], \text{dim}=-1) $$
   The tensor is unsqueezed to add a batch dimension: shape $(1, N, 3)$.

2. **Initialize Rasterization Buffer:** Create a zero-initialized tensor for the rasterization output.
   $$ \text{rast} = \text{zeros}((1, \text{texture\_size}, \text{texture\_size}, 4), \text{device}=\text{'cuda'}, \text{dtype}=\text{float32}) $$

3. **Chunked Rasterization Loop:** Iterate over faces in chunks of size `chunk_size`.
   For each chunk index $i$ from $0$ to $M$ with step `chunk_size`:
   a. Extract the current chunk of faces: $\text{faces\_chunk} = \text{out\_faces}[i : i+\text{chunk\_size}]$.
   b. Rasterize the chunk:
      $$ (\text{rast\_chunk}, \_) = \text{dr.rasterize}(\text{ctx}, \text{uvs\_rast}, \text{faces\_chunk}, \text{resolution}=[\text{texture\_size}, \text{texture\_size}]) $$
      Note: `dr.rasterize` returns the rasterization buffer and a list of hit face indices.
   c. Compute the mask for the current chunk:
      $$ \text{mask\_chunk} = \text{rast\_chunk}[..., 3:4] > 0 $$
   d. Update the face ID in the alpha channel. The face ID is stored as the global face index $i$.
      $$ \text{rast\_chunk}[..., 3:4] = \text{rast\_chunk}[..., 3:4] + i $$
      *Pitfall:* The original alpha value from the rasterizer (often coverage or depth) is overwritten. The mask must be computed *before* adding the index if the original alpha value is needed for blending or depth testing, or the mask is recomputed from the condition `> 0` after the addition if only validity is required. The source code computes the mask from the raw rasterizer output before adding the index, then merges.
   e. Merge the chunk result into the global `rast` buffer:
      $$ \text{rast} = \text{where}(\text{mask\_chunk}, \text{rast\_chunk}, \text{rast}) $$

4. **Extract Valid Pixels:**
   $$ \text{mask} = \text{rast}[0, ..., 3] > 0 $$

5. **Interpolate 3D Positions:** Use the rasterization buffer and face indices to interpolate vertex positions for the valid pixels.
   $$ \text{pos} = \text{dr.interpolate}(\text{out\_vertices}.\text{unsqueeze}(0), \text{rast}, \text{out\_faces})[0][0] $$
   The `dr.interpolate` function uses the barycentric coordinates (implicitly stored or derived from the rasterizer) and the face indices (stored in `rast[..., 3]`) to fetch the corresponding vertex positions.

**Pseudocode:**
```python
import torch
import diff_rasterizer as dr  # Placeholder for the specific rasterizer library

def chunked_uv_rasterization(out_vertices, out_faces, out_uvs, texture_size, chunk_size=100000):
    """
    Rasterize mesh in UV space with face ID storage.
    
    Args:
        out_vertices: (N, 3) tensor of vertex positions.
        out_faces: (M, 3) tensor of face indices.
        out_uvs: (N, 2) tensor of UV coordinates.
        texture_size: int, resolution of the 2D buffer.
        chunk_size: int, number of faces per rasterization call.
        
    Returns:
        rast: (1, texture_size, texture_size, 4) tensor with face IDs in alpha.
        pos: (texture_size, texture_size, 3) tensor of interpolated 3D positions.
    """
    # 1. Prepare UV coordinates
    # Scale UVs to [-1, 1], add z=0, w=1
    uvs_clip = out_uvs * 2 - 1
    uvs_rast = torch.cat([uvs_clip, torch.zeros_like(out_uvs[:, :1]), torch.ones_like(out_uvs[:, :1])], dim=-1)
    uvs_rast = uvs_rast.unsqueeze(0)  # Shape: (1, N, 3)
    
    # 2. Initialize rasterization buffer
    rast = torch.zeros((1, texture_size, texture_size, 4), device=out_vertices.device, dtype=torch.float32)
    
    # 3. Loop over faces in chunks
    num_faces = out_faces.shape[0]
    for i in range(0, num_faces, chunk_size):
        end_idx = min(i + chunk_size, num_faces)
        faces_chunk = out_faces[i:end_idx]
        
        # Rasterize chunk
        # dr.rasterize returns (rast_buffer, hit_faces)
        # hit_faces are the indices into the chunk's face list
        rast_chunk, hit_faces = dr.rasterize(None, uvs_rast, faces_chunk, resolution=[texture_size, texture_size])
        
        # Compute mask from the raw rasterizer output (before modifying alpha)
        # The rasterizer typically sets alpha > 0 for covered pixels
        mask_chunk = rast_chunk[..., 3:4] > 0
        
        # Update alpha channel with global face index
        # Note: This overwrites the original alpha. If depth/coverage is needed,
        # it must be preserved or recomputed. Here we assume face ID is the primary storage.
        rast_chunk[..., 3:4] += i
        
        # Merge into global buffer
        rast = torch.where(mask_chunk, rast_chunk, rast)
        
    # 4. Extract valid pixel mask
    mask = rast[0, ..., 3] > 0
    
    # 5. Interpolate 3D positions
    # dr.interpolate uses the rast buffer (containing barycentrics and face IDs)
    # to look up vertex positions.
    pos = dr.interpolate(out_vertices.unsqueeze(0), rast, out_faces)[0][0]
    
    return rast, pos
```

## Subtopics

### Face Token Layout
A compact encoding for face identity within a voxel chunk. It uses a `uint64_t` to store: bits 0-5 for u coordinate (6 bits), bits 6-11 for v coordinate (6 bits), bits 12-17 for depth (6 bits), bits 18-20 for axis (3 bits), bit 21 for positive direction flag (1 bit), and bits 22-31 for material (10 bits). This layout allows efficient storage and retrieval of face properties in memory-constrained environments [S2, unofficial].

### Face Specification for Padded Coordinates
A structure used to define the orientation and boundary of a face within a padded voxel chunk. It contains `fixed_axis` (the axis perpendicular to the face), `fixed_value` (the coordinate value on that axis), `iter_axes` (the two axes spanning the face), and `padded_boundary_index` (the index in the padded buffer). Padded coordinates are calculated as `coords[iter_axes[0]] = u + 1`, `coords[iter_axes[1]] = v + 1`, and `coords[fixed_axis] = padded_boundary_index` [S3, unofficial].

## Operating characteristics
- **Time Complexity:** $O(M \cdot C)$, where $M$ is the number of faces and $C$ is the cost of rasterizing a chunk. The chunking adds overhead but allows processing of large meshes that would otherwise exceed VRAM.
- **Memory Complexity:** $O(\text{texture\_size}^2 \cdot 4)$ for the raster buffer, plus $O(N)$ for vertices and UVs. The chunk size limits the peak memory usage of the rasterization process itself.
- **Strengths:** Enables voxelization of very large meshes by breaking them into manageable chunks. Face ID storage allows for accurate 3D position interpolation and material identification per voxel.
- **Limitations:** Requires a rasterizer that supports custom alpha channel manipulation or post-processing. The chunking process may introduce artifacts at chunk boundaries if not handled carefully (though the merge step mitigates this). Precision issues may arise if face IDs exceed the range representable in the alpha channel (e.g., if alpha is 8-bit, max face ID is 255; here float32 is used, so this is not a limitation).
- **When to use:** When voxelizing large meshes with limited VRAM, or when per-voxel face/material information is required.
- **When not to use:** For small meshes where direct rasterization is feasible, or when face ID information is not needed.

## Background
This method is derived from the `o-voxel-gpu` project, which implements efficient GPU-based voxelization using differentiable rasterization [S1, unofficial]. It addresses the challenge of processing large-scale 3D models for volumetric rendering by managing memory through chunking and preserving geometric information via face ID storage.
