# Axis-Aligned Projection via Face Normal

Also called: Face Normal Axis Selection, Optimal Axis Projection

## Overview
This method is a geometry shader technique used in rasterization-based voxelization to project 3D mesh triangles onto a 2D plane aligned with the axis most perpendicular to the triangle's face normal [S1, unofficial]. By selecting the optimal viewing axis (X, Y, or Z) for each triangle, it minimizes projection overlap and distortion, ensuring that the triangle's area is preserved as much as possible in the chosen projection plane [S1, unofficial]. This approach adapts the projection direction per primitive, which is particularly useful for reducing artifacts in voxel grids where triangles might otherwise be foreshortened or occluded incorrectly [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A triangle strip consisting of vertices, each with a world-space position, a normal vector, and texture UV coordinates [S1, unofficial].
*   **Output:** A geometry stream containing transformed clip-space positions, world-space positions, and texture UVs, ready for rasterization into a voxel texture or buffer [S1, unofficial].

**Data Structures:**
*   **Vertex Input:** Contains `vertex.xyz` (world position), `normal` (world normal), and `uv` (texture coordinates) [S1, unofficial].
*   **Geometry Output:** Contains `positionCS` (clip space position), `positionWS` (world space position), and `uv` (texture coordinates) [S1, unofficial].

**Steps:**
1.  **Calculate Face Normal:** Compute the average of the three input vertex normals and normalize the result to obtain the triangle's face normal [S1, unofficial].
    $$ \mathbf{n}_{face} = \text{normalize}(\mathbf{n}_0 + \mathbf{n}_1 + \mathbf{n}_2) $$
2.  **Determine Optimal Axis:** Calculate the absolute dot product of the face normal with the three world-space axes ($\mathbf{x}=(1,0,0)$, $\mathbf{y}=(0,1,0)$, $\mathbf{z}=(0,0,1)$) [S1, unofficial]. Select the axis with the maximum dot product [S1, unofficial].
    $$ d_x = |\mathbf{n}_{face} \cdot \mathbf{x}|, \quad d_y = |\mathbf{n}_{face} \cdot \mathbf{y}|, \quad d_z = |\mathbf{n}_{face} \cdot \mathbf{z}| $$
    The axis index is determined as follows [S1, unofficial]:
    *   If $d_x$ is maximum, select the X-axis (projection onto the ZY plane).
    *   If $d_y$ is maximum, select the Y-axis (projection onto the XZ plane).
    *   If $d_z$ is maximum, select the Z-axis (projection onto the XY plane).
3.  **Transform to Clip Space:** For each vertex, transform its world-space position to clip space [S1, unofficial].
    $$ \mathbf{p}_{clip} = \text{TransformWorldToHClip}(\mathbf{p}_{world}) $$
4.  **Normalize to NDC:** Divide the clip space position by its w-component to normalize to Normalized Device Coordinates (NDC) [S1, unofficial].
    $$ \mathbf{p}_{ndc} = \frac{\mathbf{p}_{clip}}{w} $$
5.  **Adjust Z Range (Platform Specific):** If the platform uses a 0-1 Z range for clip space (e.g., DirectX), convert the Z coordinate from 0-1 to -1-1 range [S1, unofficial]. This is typically checked using a platform-specific constant like `UNITY_NEAR_CLIP_VALUE` [S1, unofficial].
    $$ \text{if } \text{UNITY\_NEAR\_CLIP\_VALUE} \ge 0: \quad z_{ndc} = z_{ndc} \times 2.0 - 1.0 $$
6.  **Permute Coordinates:** Swap the XYZ coordinates of the NDC position to align the selected projection axis with the depth (Z) axis for rasterization [S1, unofficial].
    *   If X-axis is dominant (Index 0): Swap to ZY. $\mathbf{p}_{permuted} = (z, y, x)$ [S1, unofficial].
    *   If Y-axis is dominant (Index 1): Swap to XZ. $\mathbf{p}_{permuted} = (x, z, y)$ [S1, unofficial].
    *   If Z-axis is dominant (Index 2): No swap. $\mathbf{p}_{permuted} = (x, y, z)$ [S1, unofficial].
7.  **Restore Z Range (Platform Specific):** If the platform uses a 0-1 Z range, convert the Z coordinate back from -1-1 to 0-1 [S1, unofficial].
    $$ \text{if } \text{UNITY\_NEAR\_CLIP\_VALUE} \ge 0: \quad z_{permuted} = z_{permuted} \times 0.5 + 0.5 $$
8.  **De-normalize:** Multiply the permuted position by w to restore the clip space scale [S1, unofficial].
    $$ \mathbf{p}_{final} = \mathbf{p}_{permuted} \times w $$
9.  **Output:** Output the final clip space position, the original world space position, and the texture UV to the geometry stream [S1, unofficial]. Restart the triangle strip [S1, unofficial].

**Pseudocode:**
```python
def dot(v1, v2):
    return v1[0]*v2[0] + v1[1]*v2[1] + v1[2]*v2[2]

def normalize(v):
    length = (v[0]**2 + v[1]**2 + v[2]**2)**0.5
    return (v[0]/length, v[1]/length, v[2]/length)

def abs_vec(v):
    return (abs(v[0]), abs(v[1]), abs(v[2]))

def transform_world_to_hclip(pos, view_proj_matrix):
    w = view_proj_matrix[3][0]*pos[0] + view_proj_matrix[3][1]*pos[1] + view_proj_matrix[3][2]*pos[2] + view_proj_matrix[3][3]
    return (view_proj_matrix[0][0]*pos[0] + view_proj_matrix[0][1]*pos[1] + view_proj_matrix[0][2]*pos[2] + view_proj_matrix[0][3],
            view_proj_matrix[1][0]*pos[0] + view_proj_matrix[1][1]*pos[1] + view_proj_matrix[1][2]*pos[2] + view_proj_matrix[1][3],
            view_proj_matrix[2][0]*pos[0] + view_proj_matrix[2][1]*pos[1] + view_proj_matrix[2][2]*pos[2] + view_proj_matrix[2][3],
            w)

def transform_tex(uv, scale, offset):
    return (uv[0]*scale[0] + offset[0], uv[1]*scale[1] + offset[1])

def process_triangle(input_vertices, view_proj_matrix, uv_scale, uv_offset):
    # Step 1: Calculate Face Normal
    n0 = input_vertices[0].normal
    n1 = input_vertices[1].normal
    n2 = input_vertices[2].normal
    face_normal = normalize((n0[0]+n1[0]+n2[0], n0[1]+n1[1]+n2[1], n0[2]+n1[2]+n2[2]))
    
    # Step 2: Determine Optimal Axis
    axis_x = (1.0, 0.0, 0.0)
    axis_y = (0.0, 1.0, 0.0)
    axis_z = (0.0, 0.0, 1.0)
    
    dot_x = abs_vec(dot(face_normal, axis_x))
    dot_y = abs_vec(dot(face_normal, axis_y))
    dot_z = abs_vec(dot(face_normal, axis_z))
    
    if dot_x >= dot_y and dot_x >= dot_z:
        axis_idx = 0
    elif dot_y >= dot_x and dot_y >= dot_z:
        axis_idx = 1
    else:
        axis_idx = 2
        
    output_stream = []
    UNITY_NEAR_CLIP_VALUE = 0.0 # Platform constant
    
    for i in range(3):
        vertex = input_vertices[i]
        
        # Step 3: Transform to Clip Space
        position_cs = transform_world_to_hclip(vertex.position, view_proj_matrix)
        
        # Step 4: Normalize to NDC
        w = position_cs[3]
        position_ndc = (position_cs[0]/w, position_cs[1]/w, position_cs[2]/w)
        
        # Step 5: Adjust Z Range (Platform Specific)
        if UNITY_NEAR_CLIP_VALUE >= 0:
            position_ndc = (position_ndc[0], position_ndc[1], position_ndc[2]*2.0 - 1.0)
            
        # Step 6: Permute Coordinates
        if axis_idx == 0: # X-axis dominant -> Project onto ZY, Depth is X
            position_permuted = (position_ndc[2], position_ndc[1], position_ndc[0])
        elif axis_idx == 1: # Y-axis dominant -> Project onto XZ, Depth is Y
            position_permuted = (position_ndc[0], position_ndc[2], position_ndc[1])
        else: # Z-axis dominant -> Project onto XY, Depth is Z
            position_permuted = position_ndc
            
        # Step 7: Restore Z Range (Platform Specific)
        if UNITY_NEAR_CLIP_VALUE >= 0:
            position_permuted = (position_permuted[0], position_permuted[1], position_permuted[2]*0.5 + 0.5)
            
        # Step 8: De-normalize
        position_final = (position_permuted[0]*w, position_permuted[1]*w, position_permuted[2]*w)
        
        # Step 9: Output
        output_vertex = {
            'positionCS': position_final,
            'positionWS': vertex.position,
            'uv': transform_tex(vertex.uv, uv_scale, uv_offset)
        }
        output_stream.append(output_vertex)
        
    output_stream.append({'restart_strip': True})
    return output_stream
```

**Parameters:**
*   `UNITY_NEAR_CLIP_VALUE`: A platform-specific constant. If $\ge 0$, the platform uses a 0-1 Z range for clip space (e.g., DirectX), requiring conversion to/from -1-1. If $< 0$, it uses a -1-1 range (e.g., OpenGL/Vulkan) [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Visual Incorrectness:** The geometry shader output is visually incorrect if rendered directly to a standard screen because the coordinate permutation is intended for rasterization into a specific texture layout (voxel grid), not for standard screen projection [S1, unofficial]. The technique relies on the pixel shader running on the permuted data, not on the visual correctness of the geometry shader output [S1, unofficial].
*   **Degenerate Triangles:** Triangles with zero area or collinear vertices may produce undefined normals. The source does not specify handling for this, but standard geometry shader practices should include a check for degenerate triangles to avoid artifacts [G].
*   **Precision:** The normalization and dot product calculations are sensitive to floating-point precision. Ensure that the normal calculation is robust for nearly coplanar or degenerate triangles [G].

## Operating characteristics
*   **Time Complexity:** The method adds a constant amount of computation per triangle in the geometry shader. The complexity is $O(N)$ where $N$ is the number of triangles, as each triangle is processed independently to determine its projection axis [S1, unofficial].
*   **Memory Complexity:** The method requires storing the transformed positions and attributes for the output stream. The memory usage is proportional to the number of vertices in the output stream, which is $3 \times N$ for $N$ triangles [S1, unofficial].
*   **Measured Performance:** Performance depends on the efficiency of the geometry shader and the rasterization stage. Not given in the sources.
*   **Strengths:** Reduces projection distortion and overlap by adapting to the triangle's orientation. Simple to implement within a geometry shader pipeline [S1, unofficial].
*   **Limitations:** Relies on rasterization, which may have limitations in handling complex overlaps or transparency. The visual output is not directly interpretable as a standard 3D view [S1, unofficial].
*   **When to Use:** Suitable for real-time voxelization of meshes where projection quality is important and the target is a voxel grid rather than a standard screen image [S1, unofficial].
*   **When Not to Use:** Not suitable for offline rendering or when a standard 3D view is required directly from the geometry shader output [S1, unofficial].

## Background
This technique is described in a Unity-focused blog post [S1, unofficial]. It is part of a broader effort to perform real-time GPU-based voxelization of 3D models using Unity's Universal Render Pipeline (URP) [S1, unofficial]. The method builds on the concept of triangle projection voxelization, where triangles are rendered into a voxel grid [5432-triangle-projection-voxelization.md]. The specific approach of choosing the projection axis based on the face normal is a heuristic to optimize the rasterization process for voxel coverage [S1, unofficial].
