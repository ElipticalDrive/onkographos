# ClearView Vertex Shader

Also called: HexMeshUnified Vertex

## Overview
The ClearView Vertex Shader is a geometry reconstruction technique that generates voxel face geometry entirely within the vertex shader using `gl_VertexID`, eliminating the need for CPU-side vertex attribute buffers or geometry shaders [S1, unofficial]. It reconstructs 54,000 faces per cell, each consisting of 4 vertices and 2 triangles, by fetching pre-packed face, vertex, and edge data from GPU textures [S1, unofficial]. It is distinguished from sibling methods like [Instancing with Procedural/Shader Generation](2794-instancing-with-procedural-shader-generation.md) by its explicit reliance on texture-based attribute lookups for LOD and line-drawing logic, and from [Geometry Shader Processing](2524-geometry-shader-processing.md) by performing primitive assembly in the vertex stage rather than the geometry stage [G].

## How it works
**Inputs and Outputs:**
*   **Inputs:**
    *   `uFaceTex`: RG32UI texture storing face topology [S1, unofficial].
    *   `uVertexTex`: RGBA32F texture storing vertex positions and scalar attributes [S1, unofficial].
    *   `uEdgeTex`: RG32F texture storing edge line attributes and LOD values [S1, unofficial].
    *   `uModelMatrix`, `uModelViewProjection`: Transformation matrices [G].
    *   `gl_VertexID`: The built-in vertex identifier [S1, unofficial].
    *   `uTexWidth`: Texture width for linear indexing [S1, unofficial].
*   **Outputs:**
    *   `gl_Position`: Clip-space position [S1, unofficial].
    *   `vFragmentPositionWorld`: World-space position for fragment shading [S1, unofficial].
    *   `vVertexPositions[4]`, `vVertexAttributes[4]`, `vLineAttributes[4]`, `vEdgeLodValues[4]`: Attributes passed to the fragment shader [S1, unofficial].

**Data Structures:**
1.  **Face Buffer (`uFaceTex`):** RG32UI texture with width `uTexWidth` and height `ceil(faceCount * 2 / uTexWidth)` [S1, unofficial]. Two texels per face are packed linearly: index `2 * faceId + 0` stores vertex indices (RGBA), where each component is a 32-bit unsigned integer index into `uVertexTex`, and index `2 * faceId + 1` stores edge indices (RGBA), where each component is a 32-bit unsigned integer index into `uEdgeTex` [S1, unofficial].
2.  **Vertex Buffer (`uVertexTex`):** RGBA32F texture with width `uTexWidth` and height `ceil(vertexCount / uTexWidth)` [S1, unofficial]. Each texel stores the vertex position in `xyz` and a scalar attribute in `a` [S1, unofficial].
3.  **Edge Buffer (`uEdgeTex`):** RG32F texture with width `uTexWidth` and height `ceil(edgeCount / uTexWidth)` [S1, unofficial]. Each texel stores a line attribute in `r` and an LOD value in `g` [S1, unofficial].

**Steps:**
1.  **Calculate Face ID:** Determine which face is being processed: $faceId = \lfloor gl\_VertexID / 6 \rfloor$ [S1, unofficial].
2.  **Fetch Face Topology:** Retrieve the two texels corresponding to the face: $texel0 = \text{texelFetch}(uFaceTex, \text{linearToTexel}(faceId \times 2 + 0), 0)$ and $texel1 = \text{texelFetch}(uFaceTex, \text{linearToTexel}(faceId \times 2 + 1), 0)$ [S1, unofficial]. Extract vertex indices $vIdx[0..3]$ from $texel0.rgba$ and edge indices $eIdx[0..3]$ from $texel1.rgba$ [S1, unofficial].
3.  **Fetch Vertex and Edge Data:** For each corner $i \in \{0, 1, 2, 3\}$: fetch vertex data $vData = \text{texelFetch}(uVertexTex, \text{linearToTexel}(vIdx[i]), 0)$, store position $vVertexPositions[i] = vData.xyz$, store attribute $vVertexAttributes[i] = vData.a$, fetch edge data $eData = \text{texelFetch}(uEdgeTex, \text{linearToTexel}(eIdx[i]), 0)$, store line attribute $vLineAttributes[i] = eData.r$, and store LOD value $vEdgeLodValues[i] = eData.g$ [S1, unofficial].
4.  **Determine Current Corner:** Calculate the corner ID for the current vertex based on `gl_VertexID` modulo 6. The mapping for the two triangles per face (indices 0-5) is: Vertex 0 $\rightarrow$ Corner 0, Vertex 1 $\rightarrow$ Corner 3, Vertex 2 $\rightarrow$ Corner 1, Vertex 3 $\rightarrow$ Corner 2, Vertex 4 $\rightarrow$ Corner 1, Vertex 5 $\rightarrow$ Corner 3 [S1, unofficial]. Let $cornerId$ be the result of this mapping.
5.  **Transform Position:** Fetch the world position for the current corner: $thisVertexData = \text{texelFetch}(uVertexTex, \text{linearToTexel}(vIdx[cornerId]), 0)$ [S1, unofficial]. Compute $worldPos = uModelMatrix \times vec4(thisVertexData.xyz, 1.0)$, set $vFragmentPositionWorld = worldPos.xyz$, and set $gl\_Position = uModelViewProjection \times vec4(thisVertexData.xyz, 1.0)$ [S1, unofficial].

**Pseudocode:**
```python
class vec2:
    def __init__(self, x, y): self.x, self.y = x, y
class vec3:
    def __init__(self, x, y, z): self.x, self.y, self.z = x, y, z
class vec4:
    def __init__(self, x, y, z, w): self.x, self.y, self.z, self.w = x, y, z, w

def linearToTexel(index, width):
    return vec2(index % width, index // width)

def texelFetch(tex, coord, lod):
    return tex[coord.y][coord.x]

def main(gl_VertexID, uFaceTex, uVertexTex, uEdgeTex, uModelViewProjection, uTexWidth):
    faceId = gl_VertexID // 6
    
    faceVertices = texelFetch(uFaceTex, linearToTexel(faceId * 2 + 0, uTexWidth), 0)
    faceEdges = texelFetch(uFaceTex, linearToTexel(faceId * 2 + 1, uTexWidth), 0)
    
    vIdx = [faceVertices.r, faceVertices.g, faceVertices.b, faceVertices.a]
    eIdx = [faceEdges.r, faceEdges.g, faceEdges.b, faceEdges.a]
    
    vVertexPositions = [vec3(0.0, 0.0, 0.0)] * 4
    vVertexAttributes = [0.0] * 4
    vLineAttributes = [0.0] * 4
    vEdgeLodValues = [0.0] * 4
    
    for i in range(4):
        vData = texelFetch(uVertexTex, linearToTexel(int(vIdx[i]), uTexWidth), 0)
        vVertexPositions[i] = vec3(vData.x, vData.y, vData.z)
        vVertexAttributes[i] = vData.a
        
        eData = texelFetch(uEdgeTex, linearToTexel(int(eIdx[i]), uTexWidth), 0)
        vLineAttributes[i] = eData.r
        vEdgeLodValues[i] = eData.g
        
    vertexMod = gl_VertexID % 6
    cornerId = [0, 3, 1, 2, 1, 3][vertexMod]
        
    thisVertexData = texelFetch(uVertexTex, linearToTexel(int(vIdx[cornerId]), uTexWidth), 0)
    vFragmentPositionWorld = thisVertexData.xyz
    gl_Position = uModelViewProjection @ vec4(thisVertexData.x, thisVertexData.y, thisVertexData.z, 1.0)
```

**Parameters:**
*   `uTexWidth`: Texture width for linear indexing [S1, unofficial].
*   `uModelMatrix`, `uModelViewProjection`: Standard transformation matrices [G].

**Edge Cases and Pitfalls:**
*   **Precision:** Using `RG32UI` for indices requires careful handling of large voxel counts to avoid index overflow if `uTexWidth` is not sufficient [G].
*   **Boundaries:** The `linearToTexel` function must correctly handle texture boundaries if `faceCount` or `vertexCount` does not align perfectly with `uTexWidth` [G].
*   **Degenerate Input:** If `faceId` exceeds the texture dimensions, `texelFetch` may return undefined values [G]. Implementers should clamp `faceId` or ensure texture sizes are sufficient [G].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per vertex, as it performs a fixed number of texture fetches and arithmetic operations [G].
*   **Memory Complexity:** Depends on the size of the texture buffers (`uFaceTex`, `uVertexTex`, `uEdgeTex`) [G]. The vertex buffer size is proportional to the number of unique vertices [G].
*   **Performance:** Reduces CPU-GPU transfer overhead by avoiding vertex attribute buffers [G]. However, it increases texture bandwidth usage due to multiple fetches per vertex [G].
*   **Strengths:** No need for complex geometry shaders or CPU-side mesh generation [G]. Flexible LOD control via edge attributes [G].
*   **Limitations:** High texture fetch count per vertex [G]. Limited by texture size limits for very large voxel grids [G].
*   **When to use:** When vertex attribute buffers are undesirable or when dynamic LOD based on edge attributes is required [G].
*   **When not to use:** For simple, static voxel rendering where standard instancing or geometry shaders are more efficient [G].

## Background
The ClearView Vertex Shader is part of the ClearView rendering system, specifically designed for high-performance volume visualization with LOD support [G].
