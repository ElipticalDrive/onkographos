# ClearView Vertex Shader

Also called: HexMeshUnified Vertex

## Overview
The ClearView Vertex Shader is a vertex shader technique that reconstructs face geometry and attributes from texture buffers using `gl_VertexID`, thereby avoiding the overhead of vertex attribute buffers. It processes 54,000 per-cell faces, each consisting of 4 vertices and 2 triangles (6 indices) [S1, unofficial]. It sets itself apart from sibling methods like [Naive Voxel Rendering](1103-naive-voxel-rendering.md) by decoupling geometry data from the vertex stream, storing it in dedicated texture buffers for efficient random access during reconstruction.

## How it works
**Inputs and Outputs:**
The method takes a vertex ID (`gl_VertexID`) and three texture buffers as inputs. It outputs world-space positions, fragment positions, and standard OpenGL clip-space positions.

**Data Structures:**
1.  **Face Buffer:** `RG32UI` texture. Width is `uTexWidth`. Height is `ceil(faceCount * 2 / uTexWidth)`. Two texels are packed linearly per face: index `2*faceId + 0` stores vertex indices (RGBA), and `2*faceId + 1` stores edge indices (RGBA) [S1, unofficial].
2.  **Vertex Buffer:** `RGBA32F` texture. Width is `uTexWidth`. Height is `ceil(vertexCount / uTexWidth)`. Each texel stores vertex position (`xyz`) and a scalar attribute (`a`) [S1, unofficial].
3.  **Edge Buffer:** `RG32F` texture. Width is `uTexWidth`. Height is `ceil(edgeCount / uTexWidth)`. Each texel stores a line attribute (`r`) and an LOD value (`g`) [S1, unofficial].

**Steps:**
1.  Calculate `faceId = gl_VertexID / 6`.
2.  Fetch face data:
    *   `faceVertices = texelFetch(uFaceTex, linearToTexel(faceId * 2 + 0), 0)`
    *   `faceEdges = texelFetch(uFaceTex, linearToTexel(faceId * 2 + 1), 0)`
3.  Extract vertex indices `vIdx[0..3]` from `faceVertices.rgba` and edge indices `eIdx[0..3]` from `faceEdges.rgba` [S1, unofficial].
4.  Loop `i` from 0 to 3:
    *   Fetch vertex data: `vData = texelFetch(uVertexTex, linearToTexel(int(vIdx[i])), 0)`.
    *   Set `vVertexPositions[i] = vData.xyz` and `vVertexAttributes[i] = vData.a`.
    *   Fetch edge data: `eData = texelFetch(uEdgeTex, linearToTexel(int(eIdx[i])), 0)`.
    *   Set `vLineAttributes[i] = eData.r` and `vEdgeLodValues[i] = eData.g` [S1, unofficial].
5.  Determine the current corner based on `gl_VertexID`. The mapping for the two triangles per face (vertices `(v0, v3, v1)` and `(v2, v1, v3)`) is:
    *   Vertex ID 0 -> Corner 0
    *   Vertex ID 1 -> Corner 3
    *   Vertex ID 2 -> Corner 1
    *   Vertex ID 3 -> Corner 2
    *   Vertex ID 4 -> Corner 1
    *   Vertex ID 5 -> Corner 3
    Let `cornerId` be the mapped corner index [S1, unofficial].
6.  Fetch the current vertex data: `thisVertexData = texelFetch(uVertexTex, linearToTexel(int(vIdx[cornerId])), 0)`.
7.  Compute world position: `worldPos = uModelMatrix * vec4(thisVertexData.xyz, 1.0)`.
8.  Set `vFragmentPositionWorld = worldPos.xyz` and `gl_Position = uModelViewProjection * vec4(thisVertexData.xyz, 1.0)` [S1, unofficial].

**Pseudocode:**
```python
# Inputs: gl_VertexID, uFaceTex, uVertexTex, uEdgeTex, uModelMatrix, uModelViewProjection
# Constants: uTexWidth

def linearToTexel(index):
    return vec2(index % uTexWidth, index / uTexWidth)

def main():
    faceId = gl_VertexID / 6
    
    # Fetch face data
    faceVertices = texelFetch(uFaceTex, linearToTexel(faceId * 2 + 0), 0)
    faceEdges = texelFetch(uFaceTex, linearToTexel(faceId * 2 + 1), 0)
    
    # Extract indices
    vIdx = [int(faceVertices.r), int(faceVertices.g), int(faceVertices.b), int(faceVertices.a)]
    eIdx = [int(faceEdges.r), int(faceEdges.g), int(faceEdges.b), int(faceEdges.a)]
    
    # Fetch vertex and edge data for all 4 corners
    vVertexPositions = [vec3(0.0)] * 4
    vVertexAttributes = [0.0] * 4
    vLineAttributes = [0.0] * 4
    vEdgeLodValues = [0.0] * 4
    
    for i in range(4):
        vData = texelFetch(uVertexTex, linearToTexel(vIdx[i]), 0)
        vVertexPositions[i] = vData.xyz
        vVertexAttributes[i] = vData.a
        
        eData = texelFetch(uEdgeTex, linearToTexel(eIdx[i]), 0)
        vLineAttributes[i] = eData.r
        vEdgeLodValues[i] = eData.g
        
    # Determine cornerId based on gl_VertexID
    vertexIdInFace = gl_VertexID % 6
    if vertexIdInFace == 0:
        cornerId = 0
    elif vertexIdInFace == 1:
        cornerId = 3
    elif vertexIdInFace == 2:
        cornerId = 1
    elif vertexIdInFace == 3:
        cornerId = 2
    elif vertexIdInFace == 4:
        cornerId = 1
    elif vertexIdInFace == 5:
        cornerId = 3
        
    # Fetch current vertex data
    thisVertexData = texelFetch(uVertexTex, linearToTexel(vIdx[cornerId]), 0)
    
    # Compute positions
    worldPos = uModelMatrix * vec4(thisVertexData.xyz, 1.0)
    vFragmentPositionWorld = worldPos.xyz
    gl_Position = uModelViewProjection * vec4(thisVertexData.xyz, 1.0)
```

**Parameters:**
*   `uTexWidth`: Texture width for buffer layouts. Not given in the sources.
*   `uModelMatrix`, `uModelViewProjection`: Standard transformation matrices. Not given in the sources.

**Edge Cases and Pitfalls:**
*   Precision: The vertex buffer uses `RGBA32F`, ensuring high precision for positions [S1, unofficial].
*   Boundaries: The `linearToTexel` function must handle indices within the texture dimensions. If `faceId` or vertex/edge indices exceed buffer bounds, undefined behavior occurs. Not given in the sources.

## Subtopics

## Operating characteristics
*   **Time Complexity:** O(1) per vertex, assuming constant-time texture fetches.
*   **Memory Complexity:** O(F + V + E) where F is face count, V is vertex count, and E is edge count. The buffers store indices and attributes separately.
*   **Measured Performance:** Not given in the sources.
*   **Strengths:** Avoids vertex attribute buffer overhead; allows efficient random access to geometry data via texture buffers.
*   **Limitations:** Requires texture fetches for every vertex, which may be slower than cached vertex attributes depending on hardware.
*   **When to use:** When vertex attribute buffers are a bottleneck or when geometry data needs to be dynamically updated in textures.
*   **When not to use:** When simple vertex attribute buffers suffice and texture fetch overhead is unacceptable.

## Background
The ClearView Vertex Shader is part of the ClearView rendering system, specifically associated with the ST-2 variant and HexMeshUnified Vertex. It is used in the context of volume rendering, particularly for hexagonal prism voxel rendering and sparse voxel rasterization. The method is documented in the `geresim-spike` repository [S1, unofficial].
