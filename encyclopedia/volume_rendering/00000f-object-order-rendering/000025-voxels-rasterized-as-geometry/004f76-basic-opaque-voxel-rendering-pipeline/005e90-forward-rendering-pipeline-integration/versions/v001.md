# Forward Rendering Pipeline Integration

Also called: Opaque-to-transparent pass insertion

## Overview
Forward Rendering Pipeline Integration is a method for incorporating voxel-based global illumination (VXGI) into a standard forward rendering pipeline by inserting dedicated rendering passes between the opaque and transparent geometry passes [S1]. It solves the problem of integrating volumetric lighting data into existing mesh-based renderers without requiring a full deferred rendering architecture [S1]. Unlike deferred approaches that decouple shading from lighting via a G-buffer, this method maintains the forward execution order, allowing voxel lighting to be computed and blended directly during the forward pass [S1, S2]. It is distinguished by its seamless integration with mesh rendering, enabling developers to mix voxel and mesh representations for different objects within the same scene [S1].

## How it works
The method extends the basic opaque voxel rendering pipeline by modifying the render pass sequence.

**Inputs and Outputs:**
*   **Inputs:** Opaque voxel geometry data (typically organized in chunks or a sparse voxel octree), camera matrices, and standard forward rendering state (lighting parameters, material properties).
*   **Outputs:** A final color buffer containing both mesh and voxel contributions.

**Data Structures:**
*   **Voxel Volume:** Stored as a sparse structure (e.g., chunks) to manage memory efficiently. The specific layout depends on the underlying [Basic Opaque Voxel Rendering Pipeline](13975-basic-opaque-voxel-rendering-pipeline.md) implementation.
*   **Render Passes:** The pipeline is structured as a sequence of passes:
    1.  Opaque Mesh Pass
    2.  **Voxel Lighting Pass(es)** (Inserted here)
    3.  Transparent Mesh Pass

**Steps:**
1.  **Execute Opaque Mesh Pass:** Render all opaque mesh geometry to the color buffer using standard forward shading techniques.
2.  **Insert Voxel Passes:** Execute one or more rendering passes dedicated to processing voxel data. These passes are inserted between the opaque and transparent passes [S1].
3.  **Process Voxel Data:** For each voxel or chunk, perform shading and classification calculations. The algorithm examines only a small surrounding area around the voxel to determine its contribution, allowing for parallel execution [S2].
4.  **Blend Voxel Lighting:** The results from the voxel passes are blended into the existing color buffer. Since this is a forward pipeline, blending must respect the depth buffer state established by the opaque pass.
5.  **Execute Transparent Mesh Pass:** Render transparent mesh geometry, which will now receive lighting contributions from the previously processed voxel data if the lighting model supports it.

**Parameters:**
*   **Streaming Factor:** Controls the trade-off between visual quality and performance by determining how many chunks are loaded into active memory. Typical values range from 1.2 to 2.4 [S1].
*   **Resolution:** The voxel grid resolution (e.g., 8K, 16K, 32K) affects the detail of the lighting [S1].

**Edge Cases and Pitfalls:**
*   **Transparency:** Transparent voxels are not supported by this method. Transparent objects such as rivers or windows must be rendered as substitute meshes to avoid incorrect blending or sorting issues [S1].
*   **Ordering:** Care must be taken to ensure that the voxel lighting pass does not overwrite depth information incorrectly, as it runs after the opaque pass but before the transparent pass.

**Pseudocode:**
```python
def forward_rendering_pipeline_integration(scene, camera):
    # 1. Opaque Mesh Pass
    render_opaque_meshes(scene.meshes, camera)
    
    # 2. Inserted Voxel Passes
    # Determine active chunks based on camera frustum and streaming factor
    active_chunks = get_active_chunks(scene.voxel_volume, camera, streaming_factor=2.0)
    
    # Process voxel lighting
    # This pass examines a small surrounding area for shading/classification [S2]
    for chunk in active_chunks:
        voxel_lighting_data = compute_voxel_shading(chunk, camera)
        blend_voxel_lighting(voxel_lighting_data, camera)
        
    # 3. Transparent Mesh Pass
    # Transparent objects must be substitute meshes, not voxels [S1]
    render_transparent_meshes(scene.transparent_meshes, camera)
```

## Subtopics

### [Deferred VXGI Pipeline](19198-deferred-vxgi-pipeline.md)
The Deferred VXGI Pipeline is a deferred rendering implementation for Unity's Scriptable Render Pipeline (SRP) that integrates voxel-based global illumination (VXGI) lighting passes. It differs from forward rendering approaches by decoupling the geometry shading (G-buffer creation) from the lighting computation, allowing multiple lighting passes (emission, direct, indirect diffuse, indirect specular) to be executed against a pre-computed voxel volume. This method builds on [Forward Rendering Pipeline Integration](17677-forward-rendering-pipeline-integration.md) by shifting the lighting calculation to a deferred stage, which is particularly beneficial for scenes with many dynamic lights or complex indirect illumination requirements.

## Operating characteristics
*   **Time Complexity:** The method offers good render times compared to image-order (backward mapping) techniques. While image-order algorithms have a complexity of $O(N^3)$ where $N^3$ is the volume size, object-order methods like this one are more efficient, though exact complexity depends on the number of active voxels/chunks [S2].
*   **Memory Complexity:** Depends on the sparse voxel structure and the streaming factor. Higher resolutions (e.g., 64K) require significantly more memory and active chunks (e.g., 2217.07 for San Miguel at 64K) [S1].
*   **Performance:** Measured performance shows that increasing resolution increases frame time. For example, in the San Miguel scene, frame time increases from 52.79 ms at 8K to 2217.07 ms at 64K [S1]. Visual quality (SSIM) decreases as resolution or streaming factor decreases (e.g., SSIM drops from 0.924 to 0.694 as streaming factor decreases from 2.4 to 1.2 at 8K resolution) [S1].
*   **Strengths:** Good render time with average to good picture quality; seamless integration with mesh rendering [S1, S2].
*   **Limitations:** Does not support transparent voxels; limited to forward rendering constraints [S1].
*   **When to use:** When integrating voxel lighting into an existing forward rendering pipeline is required, and transparent voxels are not needed.
*   **When not to use:** When complex indirect illumination with many dynamic lights is required (deferred is better) or when transparent voxel effects are necessary.

## Background
The concept of object-order rendering, also known as forward mapping, reverses the direction of image-order techniques by projecting data in a forward direction [S2]. This approach allows for parallel execution because only a small surrounding area around a voxel needs to be examined for shading and classification calculations [S2]. Applications of this method include shear-warp and splatting [S2]. The specific integration into forward rendering pipelines for VXGI is detailed in the Aokana framework [S1].
