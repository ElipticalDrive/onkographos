# Voxel Fragment Shader Rendering


## Overview
Voxel Fragment Shader Rendering is a fragment-shader-based technique that renders voxels as solid cubes by performing ray-AABB (Axis-Aligned Bounding Box) intersection in screen space [S1, unofficial]. It computes surface normals, samples colors, and applies fog within the fragment shader, effectively moving the geometric intersection logic from the CPU or vertex stage into the per-fragment pipeline [S1, unofficial]. This method differs from [Naive Voxel Rendering](1103-naive-voxel-rendering.md) by handling visibility and shading entirely in the fragment shader via ray casting, and from [Sparse Voxel Rasterization](3032-sparse-voxel-rasterization.md) by treating each voxel as a discrete geometric primitive with explicit intersection math rather than relying on sparse data structures for culling.

## How it works
**Inputs and Outputs:**
The method requires vertex attributes for each voxel instance: `vColor` (vec3), `vVert` (vec3, representing the voxel center), and `ndotl` (float, pre-computed dot product of normal and light) [S1, unofficial]. The fragment shader outputs `out_Color` (vec4) [S1, unofficial]. Uniforms include `u_inv_proj_view_rot` (inverse projection-view rotation matrix), `u_far` (far plane distance), `uViewport` (viewport dimensions), `uTex` (texture sampler, noted as declared but commented out in the reference implementation), and `u_lod` (level of detail/size parameter) [S1, unofficial].

**Data Structures:**
The voxel is defined as an AABB centered at `vxl` (derived from `vVert`) with bounds:
$$
minV = vxl - 0.5 \times u\_lod
$$
$$
maxV = vxl + 0.5 \times u\_lod
$$
[S1, unofficial].

**Steps:**
1.  **Ray Direction Calculation:** Compute the world-space ray direction from the fragment's screen coordinates. Normalize screen coordinates to $[0,1]$ using `uViewport`. Convert to clip space with $z=-1$. Transform by `u_inv_proj_view_rot` and normalize the resulting vector [S1, unofficial].
2.  **Ray-AABB Intersection:** Perform ray-AABB intersection against the voxel defined by `minV` and `maxV`. The ray origin is $(0,0,0)$ in the voxel's local space [S1, unofficial].
3.  **Hit Point Calculation:** Calculate the hit point `hit` relative to the voxel center:
    $$
    hit = vxl - ray \times result.x
    $$
    where `result.x` is the intersection distance $t_0$ [S1, unofficial]. This point lies in the range $[-0.5 \times u\_lod, 0.5 \times u\_lod]$ [S1, unofficial].
4.  **Normal Determination:** Determine the surface normal by finding the component of `hit` with the maximum absolute value. The normal is a unit vector along the axis corresponding to this maximum dimension, signed by the sign of the hit coordinate [S1, unofficial].
5.  **Texture Coordinate Calculation:** Calculate UV coordinates based on the determined normal [S1, unofficial]:
    *   If $normal.y \neq 0$: $uv.y = hit.x$, $uv.x = hit.z \times normal.y$.
    *   If $normal.x \neq 0$: $uv.y = hit.y$, $uv.x = hit.z \times normal.x$.
    *   If $normal.z \neq 0$: $uv.y = hit.y$, $uv.x = hit.x \times -normal.z$.
    *   Offset $uv$ by $0.5$ [S1, unofficial].
6.  **Depth Setting:** Set the fragment depth to `result.x / u_far` [S1, unofficial].
7.  **Fog Application:** Calculate fog start as $256.0 / u\_far$. Compute fog factor:
    $$
    fog = \max(gl\_FragDepth - fog\_start, 0.0001)^{0.5}
    $$
    Mix the calculated color with fog color $(0.5, 0.5, 0.7)$ using the fog factor [S1, unofficial].

**Pseudocode:**
```python
# Fragment Shader Logic
# Inputs: gl_FragCoord (screen pos), vColor, vVert, ndotl
# Uniforms: u_inv_proj_view_rot, u_far, uViewport, u_lod

def fragment_shader():
    # 1. Ray Direction Calculation
    # Normalize screen coordinates to [0,1]
    x = gl_FragCoord.x / uViewport.x
    y = gl_FragCoord.y / uViewport.y
    
    # Convert to clip space [-1,1] with z=-1
    clip_pos = vec4(x * 2 - 1, y * 2 - 1, -1, 1)
    
    # Transform by inverse projection-view rotation
    # Note: The source uses u_inv_proj_view_rot directly on clip pos
    transformed = u_inv_proj_view_rot * clip_pos
    
    # Normalize to get ray direction
    ray = normalize(transformed.xyz / transformed.w)
    
    # 2. Ray-AABB Intersection
    # Voxel bounds
    minV = vVert - 0.5 * u_lod
    maxV = vVert + 0.5 * u_lod
    
    # Ray origin is (0,0,0) in local space
    ro = vec3(0, 0, 0)
    rd = ray
    
    # Standard AABB intersection
    invR = 1.0 / rd
    tbot = (minV - ro) * invR
    ttop = (maxV - ro) * invR
    
    tmin = min(ttop, tbot)
    tmax = max(ttop, tbot)
    
    t0 = max(max(tmin.x, tmin.y), tmin.z)
    t1 = min(min(tmax.x, tmax.y), tmax.z)
    
    # Check for hit
    if t0 > t1:
        discard # No intersection
    
    result_x = t0 # Intersection distance
    
    # 3. Hit Point Calculation
    hit = vVert - ray * result_x
    
    # 4. Normal Determination
    abs_hit = abs(hit)
    if abs_hit.x >= abs_hit.y and abs_hit.x >= abs_hit.z:
        normal = vec3(sign(hit.x), 0, 0)
    elif abs_hit.y >= abs_hit.x and abs_hit.y >= abs_hit.z:
        normal = vec3(0, sign(hit.y), 0)
    else:
        normal = vec3(0, 0, sign(hit.z))
        
    # 5. Texture Coordinate Calculation
    uv = vec2(0, 0)
    if normal.y != 0:
        uv.y = hit.x
        uv.x = hit.z * normal.y
    elif normal.x != 0:
        uv.y = hit.y
        uv.x = hit.z * normal.x
    elif normal.z != 0:
        uv.y = hit.y
        uv.x = hit.x * -normal.z
        
    uv = uv + 0.5
    
    # 6. Depth Setting
    gl_FragDepth = result_x / u_far
    
    # 7. Fog Application
    fog_start = 256.0 / u_far
    fog_factor = pow(max(gl_FragDepth - fog_start, 0.0001), 0.5)
    fog_color = vec3(0.5, 0.5, 0.7)
    
    # Base color calculation (simplified from source which comments out texture sampling)
    # Assuming vColor is the base color
    final_color = vColor
    
    # Mix with fog
    out_Color = mix(final_color, fog_color, fog_factor)
```

**Parameters:**
*   `u_inv_proj_view_rot`: Inverse projection-view rotation matrix [S1, unofficial].
*   `u_far`: Far plane distance [S1, unofficial].
*   `uViewport`: Viewport dimensions (width, height) [S1, unofficial].
*   `u_lod`: Level of detail or size parameter defining voxel bounds [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** The ray direction calculation involves division by `transformed.w`. If `w` is near zero, normalization may fail.
*   **Boundaries:** The AABB intersection assumes the ray origin is at the voxel center. If the voxel is not centered at the origin in local space, the intersection math must be adjusted.
*   **Degenerate Input:** If `u_lod` is zero or negative, the AABB bounds collapse or invert, leading to undefined behavior.
*   **Fog Start:** The fog start calculation `256.0 / u_far` is hardcoded. If `u_far` is very large, `fog_start` becomes small, potentially causing fog to appear too early.

## Operating characteristics
**Time and Memory Complexity:**
The complexity per fragment is constant $O(1)$, involving a fixed number of arithmetic operations for ray-AABB intersection and normal calculation. Memory usage is minimal, requiring only the vertex attributes and uniforms. No additional buffers or textures are strictly required for the intersection logic, though `uTex` is declared [S1, unofficial].

**Measured Performance:**
Not given in the sources.

**Scaling:**
Performance scales linearly with the number of visible fragments. Since each voxel is rendered as a full-screen quad (or similar primitive) and the intersection is done in the fragment shader, the cost is independent of the number of voxels in the scene, provided they are culled by the rasterizer's depth test or frustum culling.

**Strengths and Limitations:**
*   **Strengths:** Simple implementation within the fragment shader; no complex geometry generation required; handles transparency/fog easily.
*   **Limitations:** High fragment shader overhead due to per-fragment ray casting; no early-Z culling benefits for the ray intersection itself; limited to solid cubes (no internal structure rendering without additional logic).

**When to Use:**
Suitable for simple voxel visualizations where implementation simplicity is prioritized over performance, or when the number of visible voxels is small.

**When Not to Use:**
Not suitable for large-scale voxel scenes with high fragment counts, where CPU-side culling or GPU-based sparse voxel octrees (like [Sparse Voxel Rasterization](3032-sparse-voxel-rasterization.md)) would be more efficient.

## Background
This method is derived from the `voxplat` project by kosshi-net [S1, unofficial]. It represents a specific implementation of fragment-shader-based voxel rendering, focusing on simplicity and direct integration with the OpenGL pipeline.
