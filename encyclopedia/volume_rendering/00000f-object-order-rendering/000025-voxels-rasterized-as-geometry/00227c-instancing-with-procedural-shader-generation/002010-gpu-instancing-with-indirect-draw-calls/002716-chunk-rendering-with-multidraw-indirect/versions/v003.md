# Chunk Rendering with Multidraw Indirect

Also called: GPU Instanced Voxel Rendering via DrawMeshInstancedIndirect, Indirect Chunk Rendering, Indirect Draw Call Buffer Rendering, Indirect Voxel Rendering, MegaSSBO, MegaSSBO Indirect Rendering with Instance Encoding, Multidraw-Indirect Rendering with DAIC, glMultiDrawElementsIndirect

## Overview
Chunk Rendering with Multidraw Indirect is a technique for rendering voxel worlds that batches chunk geometry using OpenGL's `glMultiDrawElementsIndirect` to reduce draw call overhead [S2, unofficial]. It stores chunk geometry in a large shared Vertex Buffer Object (VBO) or Shader Storage Buffer (SSBO) and uses indirect commands to specify per-chunk offsets and counts [S1, unofficial][S2, unofficial][S3, unofficial]. It is distinguished from its parent [GPU Instancing with Indirect Draw Calls](2205-gpu-instancing-with-indirect-draw-calls.md) by aggregating mesh data from multiple world chunks into a single large buffer and encoding chunk identity into the instance ID or base vertex, rather than relying on per-instance vertex attributes for position [S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A list of visible chunks containing remeshed voxel geometry (quads).
*   **Output:** A single GPU draw call rendering all visible chunks.

**Data Structures:**
1.  **`blocksIbo` (Index Buffer):** Size `maxIndices` elements [S2, unofficial]. Contains pre-generated indices for a single quad mesh `{0, 2, 1, 0, 3, 2}` repeated for each chunk [S2, unofficial]. Total indices: `CHUNK_SIZE * 6 * 6` [S2, unofficial].
2.  **`hugeVbo` (Vertex Buffer):** Capacity `std::pow(GetSettings()->GetRenderDistance(), 3ULL) * CHUNK_SIZE / 2` elements of type `BlockQuad` [S2, unofficial]. Layout: Concatenated vertex data for all active chunks.
3.  **`multidrawCommands` (Indirect Command Buffer):** Array of `DrawElementsIndirectCommand` structures [S2, unofficial]. Fields: `count` (indices to draw), `instanceCount` (1), `firstIndex` (0), `baseVertex` (offset into `hugeVbo`), `baseInstance` (chunk index `i`) [S2, unofficial].
4.  **`multidrawChunkOffsets` (Vertex Buffer):** Array of `glm::vec3` (3 floats) [S2, unofficial]. Content: Chunk location offsets relative to the player [S2, unofficial].
5.  **`ChunkDrawCall` Structure:** Fields: Chunk pointer, number of indices to draw, chunk's shader position offset [S2, unofficial].
6.  **`DAIC` struct:** `uint cnt`, `uint instCnt`, `uint start`, `uint baseVert`, `uint baseInst`, `uint* index` [S1, unofficial].
7.  **`MegaSSBO`:** A single large SSBO containing face data for all visible chunks [S3, unofficial]. Each chunk contributes a contiguous block of faces [S3, unofficial]. Tracked by `m_MegaSSBOOffset` and `m_MegaSSBOFaceCount` [S3, unofficial].

**Numbered Steps:**
1.  **Initialize Index Buffer:** Create `blocksIbo` with `maxIndices` size [S2, unofficial]. Loop `i` from `0` to `maxIndices / 6`. For each `i`, write 6 indices to buffer: `indices[0] + (i * 4)` through `indices[5] + (i * 4)` [S2, unofficial].
2.  **Copy Remeshed Chunks:** Iterate over each chunk in `remeshedChunks` [S2, unofficial]. If `mesh->GetQuadCount() == 0`, skip the chunk [S2, unofficial]. Ensure GL buffers exist. Reserve VBO/IBO capacity at `1.5 * mesh_count` [S2, unofficial]. Copy mesh data to mapped buffers via `memcpy` [S2, unofficial]. Write to `hugeVbo` range via `WriteToRange` [S2, unofficial]. Swap next buffers [S2, unofficial].
3.  **Prepare Multidraw Commands:** Create arrays for `chunkOffsets` and `commands` [S2, unofficial]. Loop `i` from `0` to `chunksToDraw`. For each chunk, create `DrawElementsIndirectCommand`: `count` = indices to draw, `instanceCount` = 1, `firstIndex` = 0, `baseVertex` = `chunkVboRange->GetOffset() * 4`, `baseInstance` = `i` [S2, unofficial]. Add chunk offset to `chunkOffsets` [S2, unofficial].
4.  **Execute Multidraw:** Bind `blockMultidrawShader` [S2, unofficial]. Bind `blocksIbo` and `hugeVbo`. Bind `multidrawChunkOffsets` as vertex buffer at binding point 4 [S2, unofficial]. Bind `multidrawCommands` as indirect buffer [S2, unofficial]. Call `glMultiDrawElementsIndirect(GL_TRIANGLES, GL_UNSIGNED_INT, (const void*)0, chunksToDraw, 0)` [S2, unofficial].

**Alternative Pipeline (MegaSSBO):**
1.  Iterate over all chunks in `m_Chunks`. Skip chunks where `!chunk->IsMeshReady()` [S3, unofficial]. Calculate world position: `wx = chunk->GetXWorldPos() * Chunk::m_XSize`, `wz = chunk->GetZWorldPos() * Chunk::m_ZSize` [S3, unofficial]. Check frustum culling. Skip if no faces [S3, unofficial].
2.  Encode chunk X and Z world positions into a 32-bit `baseInstance` integer [S3, unofficial]. Chunk X occupies lower 16 bits, Chunk Z upper 16 bits [S3, unofficial]. Add 32768 to each position before masking to handle signed integers: `baseInstance = ((uint32_t)(chunk->GetXWorldPos() + 32768) & 0xFFFF) | (((uint32_t)(chunk->GetZWorldPos() + 32768) & 0xFFFF) << 16)` [S3, unofficial].
3.  Add an indirect draw command to `m_DrawIndirectBuffer` with: count = `chunk->GetMegaSSBOFaceCount()`, first = `chunk->GetMegaSSBOOffset()`, baseInstance = `baseInstance` [S3, unofficial].
4.  Upload indirect commands to GPU. If no commands, bind empty indirect buffer and return early [S3, unofficial].
5.  Perform indirect draw call using empty VAO, MegaSSBO, shader, and indirect buffer [S3, unofficial].
6.  **MegaSSBO Compaction:** When chunks are added/removed, iterate chunks, skip if not allocated or empty. If offset differs from sequential `writeOffset`, move data using `glCopyBufferSubData`. Update chunk offset. Increment `writeOffset`. Reset free list [S3, unofficial].

**Formulas:**
*   **Shader Position Offset:** The position offset for a chunk in the shader is calculated as:
    $$ \text{vec3}(\text{chunkLocation} - \text{playerPos}) $$
    Where:
    $$ \text{chunkLocation} = \text{vec3}(\text{chunkPos}.x \times \text{CHUNK\_LENGTH}, \text{chunkPos}.y \times \text{CHUNK\_LENGTH}, \text{chunkPos}.z \times \text{CHUNK\_LENGTH}) $$
    [S2, unofficial]
*   **Chunk Size:** `Chunk::m_XSize = 16`, `Chunk::m_ZSize = 16`, `Chunk::m_YSize = 512` [S3, unofficial].

**Parameters:**
*   **Huge VBO Reserve Capacity:** `std::pow(GetSettings()->GetRenderDistance(), 3ULL) * CHUNK_SIZE / 2` elements of type `BlockQuad` [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **GPU Synchronization:** GPU synchronization is required to guarantee writes to persistently bound VBOs are completed before drawing, but multi-buffering is often used instead due to lock inconsistencies [S1, unofficial].
*   **Signed Chunk Coordinates:** Chunk world positions can be negative. Encoding into `baseInstance` requires unsigned 16-bit integers. Adding 32768 shifts the range [-32768, 32767] to [0, 65535] [S3, unofficial].
*   **Empty Chunks:** Chunks with 0 quads are skipped during buffer copy to avoid wasting buffer space and draw commands [S2, unofficial].

**Pseudocode:**
```python
def render_chunks_multidraw_indirect(chunks, player_pos, chunk_length, huge_vbo_capacity):
    # Step 1: Initialize Index Buffer
    max_indices = huge_vbo_capacity * 6
    blocks_ibo = [0] * max_indices
    indices_base = [0, 2, 1, 0, 3, 2]
    for i in range(max_indices // 6):
        for j in range(6):
            blocks_ibo[i * 6 + j] = indices_base[j] + (i * 4)

    # Step 2: Copy Remeshed Chunks
    huge_vbo = [None] * huge_vbo_capacity
    chunk_offsets = []
    commands = []
    current_vbo_offset = 0
    
    for chunk in chunks:
        if chunk.mesh.get_quad_count() == 0:
            continue
        mesh_data = chunk.mesh.get_vertex_data()
        # Write to huge_vbo range
        for k, vertex in enumerate(mesh_data):
            huge_vbo[current_vbo_offset + k] = vertex
        
        # Step 3: Prepare Multidraw Commands
        base_vertex = current_vbo_offset * 4
        command = {
            'count': chunk.mesh.get_index_count(),
            'instanceCount': 1,
            'firstIndex': 0,
            'baseVertex': base_vertex,
            'baseInstance': len(commands)
        }
        commands.append(command)
        
        chunk_pos = chunk.pos
        chunk_location = [chunk_pos[0] * chunk_length, chunk_pos[1] * chunk_length, chunk_pos[2] * chunk_length]
        offset = [chunk_location[d] - player_pos[d] for d in range(3)]
        chunk_offsets.append(offset)
        
        current_vbo_offset += chunk.mesh.get_vertex_count()

    # Step 4: Execute Multidraw
    # Bind shader, index buffer, vertex buffers, and issue draw call
    # glMultiDrawElementsIndirect(GL_TRIANGLES, GL_UNSIGNED_INT, commands, len(commands), 0)
    return commands, chunk_offsets
```

## Subtopics

### Chunk Draw Call Preparation
A variant step where the `ChunkDrawCall` structure is initialized with the chunk pointer, the number of indices to draw, and the chunk's shader position offset [S2, unofficial]. This structure is used to aggregate data before creating the final indirect commands.

### Indirect Drawing with BaseInstance Encoding
Encodes chunk coordinates into the `baseInstance` parameter of `glDrawArraysInstancedBaseInstance` for indirect drawing [S3, unofficial]. Iterates chunks, checks `IsMeshReady()`, frustum, and `GetMegaSSBOFaceCount() > 0`. Encodes chunkX and chunkZ into `baseInstance` (16 bits each, chunkX offset by 32768 for unsigned handling) [S3, unofficial]. Sets up draw loop with indirect commands [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of visible chunks, as each chunk is processed once to build the command buffer. The draw call itself is $O(1)$ relative to the number of chunks, though the GPU work is proportional to the total number of vertices and indices.
*   **Memory Complexity:** $O(N)$ for the `hugeVbo` and command buffers, where $N$ is the number of chunks. The VBO size is pre-allocated based on render distance [S2, unofficial].
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Scales well with the number of chunks because it reduces the CPU overhead of issuing many draw calls. The bottleneck shifts to the GPU's ability to process the large vertex buffer and the bandwidth of the VBO.
*   **Strengths:** Significantly reduces draw call overhead compared to individual draw calls or instanced drawing with base vertex [S2, unofficial].
*   **Limitations:** Requires a large contiguous VBO, which may be difficult to allocate for very large render distances. The source disables individual draw calls and instanced drawing with `glDrawElementsInstancedBaseVertexBaseInstance` via `#if false`, suggesting this method is preferred for this specific implementation [S2, unofficial].
*   **When to Use:** When rendering a large number of similar geometry chunks (voxels) where draw call overhead is a bottleneck.
*   **When Not to Use:** When the number of chunks is small, or when memory constraints prevent allocating a large VBO.

## Background
This technique is implemented in the `gabkhanfig/Cube` repository, an unofficial project [S2, unofficial]. It uses OpenGL's `glMultiDrawElementsIndirect` to batch chunk rendering. The source code explicitly disables alternative methods like individual draw calls and `glDrawElementsInstancedBaseVertexBaseInstance`, indicating a design choice to favor multidraw indirect for this voxel engine [S2, unofficial].
