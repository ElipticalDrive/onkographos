# Procedural and Rule-Based Spawning
## Overview
Procedural and Rule-Based Spawning populates voxel terrains with large numbers of objects by evaluating spawn rules against terrain geometry rather than manual placement [S1]. It distinguishes itself from static instancing by dynamically generating instance positions and properties through procedural generators tied to the terrain system [S1].
## Shared principles
The family operates by evaluating spawn rules defined in a `VoxelInstanceLibrary` against eligible terrain chunks [G]. The core mechanism involves:
1. **Chunk Eligibility**: The system iterates through loaded voxel chunks and matches them to items based on resolution level [12572-block-lod-instancing.md].
2. **Candidate Generation**: The item's `generator` evaluates conditions (e.g., noise thresholds) at candidate positions within eligible chunks [Parent].
3. **Surface Snapping (Optional)**: If enabled, the system queries the terrain generator for Signed Distance Field (SDF) values at candidate positions and nearby samples, interpolating to find the zero-crossing surface [12566-voxel-instancing-system.md]. This is an interpolation approximation, not exact ray-casting, and may fail if the terrain is edited after generation [12566-voxel-instancing-system.md].
4. **Normal Offset**: The instance position is displaced along the interpolated surface normal by `offset_along_normal` [12566-voxel-instancing-system.md].
5. **Alignment**: Instances are rotated to align with either the local terrain origin (sphere mode) or a fixed world up vector [12566-voxel-instancing-system.md].
6. **Instance Creation**: Instances are created as either `MultiMesh` (high-performance, static) or `Scene` (dynamic, scriptable) types [12566-voxel-instancing-system.md].
7. **Persistence**: If `persistent` is true and a `VoxelStream` is active, the instance's ID and position are saved; edited blocks prevent regeneration for these instances [S1].

```python
def process_terrain_chunks(voxel_instancer, chunks):
    library = voxel_instancer.library
    generator = voxel_instancer.generator
    stream = voxel_instancer.stream
    up_mode = voxel_instancer.up_mode  # 'Sphere mode' or 'World Up'
    
    for chunk in chunks:
        for item in library.items:
            # Step 1: Chunk Eligibility
            if chunk.lod_level != item.lod_index:
                continue
            
            # Step 2: Candidate Generation
            candidates = item.generator.evaluate(chunk)
            
            for candidate in candidates:
                position = candidate.position
                
                # Step 3: Surface Snapping
                if item.snap_to_generator_sdf_enabled:
                    # Requires VoxelGeneratorGraph for arbitrary float queries
                    sdf_val = generator.query_sdf(position)
                    # [Comment: Sources do not give the exact interpolation routine for zero-crossing. Standard approach: sample neighbors, linearly interpolate to find t where sdf(t) = 0.]
                    normal = generator.query_sdf_gradient(position)
                    position = position + normal * item.offset_along_normal
                else:
                    # [Comment: Sources do not give default fallback behavior. Standard approach: use chunk surface or center.]
                    position = position + Vector3(0, item.offset_along_normal, 0)
                
                # Step 5: Alignment
                if up_mode == 'Sphere mode':
                    # [G] Align with local terrain origin
                    rotation = align_to_sphere_normal(position)
                else:
                    # [G] Align with fixed world up vector
                    rotation = align_to_world_up()
                
                # Step 6: Instance Creation
                if isinstance(item, VoxelInstanceLibraryMultiMeshItem):
                    mesh = select_lod_mesh(item, chunk, position)
                    # [G] Add to MultiMesh batch
                    add_multimesh_instance(position, rotation, mesh)
                elif isinstance(item, VoxelInstanceLibrarySceneItem):
                    scene_instance = item.scene.instantiate()
                    scene_instance.position = position
                    scene_instance.rotation = rotation
                    voxel_instancer.add_child(scene_instance)
                
                # Step 7: Persistence
                if item.persistent and stream:
                    stream.save_instance(item.id, position)
```

## Subtopics

### [Voxel Instancing System](12566-voxel-instancing-system.md)
The Voxel Instancing System is a procedural spawning mechanism for voxel terrains, designed primarily for natural elements like grass, rocks, and trees. It solves the problem of efficiently rendering thousands of distinct objects by evaluating spawn rules against terrain chunks and placing instances either as high-performance `MultiMesh` batches or flexible `Scene` nodes [12566-voxel-instancing-system.md]. It distinguishes itself from sibling methods by its tight integration with the voxel terrain's LOD system and its ability to snap instances to procedural surface approximations using SDF interpolation [12566-voxel-instancing-system.md].

### [Block LOD Instancing](12572-block-lod-instancing.md)
Block LOD Instancing is a method for spawning voxel instances based on the resolution level (LOD) of the underlying terrain chunks [12572-block-lod-instancing.md]. It solves the problem of efficiently populating large voxel worlds by assigning instance types to specific distance ranges via chunk resolution [12572-block-lod-instancing.md]. It differs from standard instancing by tying spawn eligibility directly to the terrain's hierarchical LOD structure rather than a fixed global radius, allowing larger items to spawn on distant, low-resolution chunks while smaller items populate high-resolution areas [12572-block-lod-instancing.md].

#### Procedural Object Instancing

### definition
- [S1] Items spawn based on procedural rules via a built-in generator, rather than manual painting. The generator is accessed via the `generator` property of `VoxelInstanceLibraryItem` [S1].

### pitfall
- [S1] Manual editing of instances in the editor is not supported [S1].
- [S1] Custom instance generator API is recent and may change; it is not available to scripts at time of writing [S1].
- [S1] `VoxelInstancer` registers to parent block events to know when to spawn [S1].

## Background
The Voxel Instancing System is part of the Voxel Tools suite for the Godot engine [S1]. It was designed to handle the specific constraints of voxel terrain rendering, where geometry changes dynamically and LODs vary by distance [G]. The persistent instance feature relies on `VoxelStreamSQLite` for data storage [S1].
