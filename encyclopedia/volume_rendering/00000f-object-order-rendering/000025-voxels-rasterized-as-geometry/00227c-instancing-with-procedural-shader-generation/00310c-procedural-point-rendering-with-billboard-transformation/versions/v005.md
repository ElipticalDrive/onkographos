# Procedural Point Rendering with Billboard Transformation

Also called: GPU Instancing Setup, Procedural Instancing Configuration

## Overview
A rendering technique using Unity procedural instancing to render surface points as billboards [S1, unofficial]. It transforms a grid-based point cloud into world space, orients each point to face the camera, and scales them based on a step size [S1, unofficial].

## How it works
**Inputs:**
- `_SurfacePoints`: A structured buffer of `float4` containing point data. The `xyz` components are the point position, and the `w` component is the alpha value [S1, unofficial].
- `_GridToWorld`: A 4x4 matrix used to transform point indices from grid space to world space [S1, unofficial].
- `_ViewDir`: The view direction vector used to orient the billboards towards the camera [S1, unofficial].
- `_Step`: A scalar value used to scale the object's local axes [S1, unofficial].
- `_PointSize`: A scalar subtracted from `BASE_POINTSIZE` to determine the scaling factor [S1, unofficial].
- `BASE_POINTSIZE`: Constant value 4.0 [S1, unofficial].
- `BASE_BRIGHTNESS`: Constant value for brightness scaling [S1, unofficial].
- `_PointBrightness`: Range 0.0 to 0.99, default 0.99 [S1, unofficial].
- `_IsoVals`: A buffer containing per-instance isovalue/color data [S1, unofficial].
- `grid_dim`: The grid dimension used for coordinate mapping [G].

**Outputs:**
- Rendered billboards representing surface points [S1, unofficial].

**Data Structures:**
- `DrawCallArgBuffer`: Structured buffer for indirect draw calls. Fields: `vertexCountPerInstance` (int), `instanceCount` (int), `startVertexLocation` (int), `startInstanceLocation` (int) [S1, unofficial].

**Steps:**
1. **Retrieve Point Data:** In the `ConfigureProcedural` phase, retrieve the point position from `_SurfacePoints` using `unity_InstanceID`. Transform this position to world space using `_GridToWorld`. Extract the alpha value into `_Alpha` [S1, unofficial].
2. **Calculate World Position:** Map the instance ID to a 3D grid coordinate using `oneDToThreeD`. Calculate the world position of the voxel center by shifting the grid coordinate to origin, scaling by `_Step`, and adding a half-step offset. Transform this position using `_GridToWorld` [S1, unofficial].
3. **Set Translation:** Set the translation part of `unity_ObjectToWorld` to the calculated world position `pos` [S1, unofficial].
4. **Set Scale:** Set the scale part of `unity_ObjectToWorld` (diagonal elements `m00`, `m11`, `m22`) to `_Step` divided by `(BASE_POINTSIZE - _PointSize)` [S1, unofficial].
5. **Orient Billboard:** Construct a look-at matrix using the eye position as `pos`, the target as `pos - _ViewDir * 1000`, and up vector `(0, 1, 0)`. Multiply `unity_ObjectToWorld` by this matrix to orient the billboard [S1, unofficial].
6. **Set Color:** Set the instance color based on the isovalue. The color is derived from `_IsoVals[unity_InstanceID]` scaled by `BASE_BRIGHTNESS - _PointBrightness` [S1, unofficial].
7. **Discard Invalid Points:** Points with alpha less than 1.0 are discarded in the `clip_float` function to hide invalid or empty points [S1, unofficial].

**Pseudocode:**
```python
def configure_procedural(instance_id, surface_points, grid_to_world, view_dir, step, point_size, base_pointsize, base_brightness, point_brightness, iso_vals, grid_dim):
    # Step 1: Retrieve Point Data
    point_data = surface_points[instance_id]
    pos_buf = grid_to_world @ [point_data.x, point_data.y, point_data.z, 1.0]
    alpha = point_data.w

    # Step 7: Discard Invalid Points
    if alpha < 1.0:
        return

    # Step 2: Calculate World Position
    grid_coord = one_d_to_three_d(instance_id, grid_dim)
    pos = grid_to_world @ [(grid_coord.x + 0.5) * step, (grid_coord.y + 0.5) * step, (grid_coord.z + 0.5) * step, 1.0]

    # Step 3: Set Translation
    unity_object_to_world = identity_matrix()
    unity_object_to_world[0][3] = pos[0]
    unity_object_to_world[1][3] = pos[1]
    unity_object_to_world[2][3] = pos[2]

    # Step 4: Set Scale
    scale_factor = step / (base_pointsize - point_size)
    unity_object_to_world[0][0] = scale_factor
    unity_object_to_world[1][1] = scale_factor
    unity_object_to_world[2][2] = scale_factor

    # Step 5: Orient Billboard
    eye_pos = pos
    target_pos = [pos[0] - view_dir.x * 1000.0, pos[1] - view_dir.y * 1000.0, pos[2] - view_dir.z * 1000.0]
    up_vec = [0.0, 1.0, 0.0]
    look_at_matrix = look_at(eye_pos, target_pos, up_vec)
    unity_object_to_world = matrix_multiply(unity_object_to_world, look_at_matrix)

    # Step 6: Set Color
    color = iso_vals[instance_id] * (base_brightness - point_brightness)
    return unity_object_to_world, color

def one_d_to_three_d(idx, grid_dim):
    # Standard 1D-to-3D grid coordinate extraction [G]
    return (idx % grid_dim, (idx // grid_dim) % grid_dim, idx // (grid_dim * grid_dim))
```

**Parameters:**
- `_PointBrightness`: Range 0.0 to 0.99, default 0.99 [S1, unofficial].
- `shapeFunction`: Enum, default Sphere [S1, unofficial].
- `surfacePointsFunc`: Enum (QEF, Centroid, Block), default Centroid [S1, unofficial].
- `renderMode`: Enum (Shaded, Wireframe), default Shaded [S1, unofficial].
- `showGrid`, `showVolume`, `showSurface`, `showMesh`: Booleans [S1, unofficial].

**Edge Cases and Pitfalls:**
- Points with alpha less than 1.0 are discarded [S1, unofficial].
- Precision issues may arise if `BASE_POINTSIZE - _PointSize` is close to zero [G].
- Boundary conditions for grid coordinate mapping need careful handling to avoid out-of-bounds access [G].

## Operating characteristics
- **Time Complexity:** O(N) for N points, where each point undergoes constant-time transformations [G].
- **Memory Complexity:** O(N) for storing point data in `_SurfacePoints` [G].
- **Performance:** Efficient for large point clouds due to instancing. Indirect draw calls reduce CPU overhead [S1, unofficial].
- **Strengths:** Simple implementation, flexible point positioning, good for visualizing isosurfaces [G].
- **Limitations:** Limited to point-based representation, no depth sorting for transparent points (requires additional handling) [G].
- **When to Use:** Visualizing surface points, isosurfaces, or particle systems where billboarding is sufficient [G].
- **When Not to Use:** When detailed geometry or complex shading is required [G].
