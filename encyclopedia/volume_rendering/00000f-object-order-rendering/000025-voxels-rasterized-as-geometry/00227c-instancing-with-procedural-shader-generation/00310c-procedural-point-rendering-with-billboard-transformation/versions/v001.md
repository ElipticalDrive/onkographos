# Procedural Point Rendering with Billboard Transformation

Also called: GPU Instancing Setup, Procedural Instancing Configuration

## Overview
A rendering technique that transforms a grid-based point cloud into world space, orienting each point to face the camera (billboarding) and scaling them based on a step size [S1, unofficial]. It differs from standard voxel instancing by dynamically constructing view-dependent rotation matrices in the vertex shader or compute shader to ensure billboards always face the viewer, rather than relying on static orientation or geometry shader expansion [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A structured buffer `_SurfacePoints` containing `float4` elements. The `xyz` components represent the point position in grid space, and the `w` component represents an alpha/visibility flag [S1, unofficial].
*   **Input:** A 4x4 matrix `_GridToWorld` to transform grid coordinates to world space [S1, unofficial].
*   **Input:** A view direction vector `_ViewDir` [S1, unofficial].
*   **Input:** Scalar parameters `_Step` (grid spacing), `_PointSize` (render size), and `BASE_POINTSIZE` (constant 4.0) [S1, unofficial].
*   **Input:** An array `_IsoVals` for color mapping [S1, unofficial].
*   **Output:** Rendered billboards representing the isosurface points.

**Data Structures:**
*   `_SurfacePoints`: `StructuredBuffer<float4>` (or equivalent). Layout: `[x, y, z, alpha]` per instance.
*   `DrawCallArgBuffer`: A compute buffer for indirect draw calls, layout: `[vertexCountPerInstance, instanceCount, startVertexLocation, startInstanceLocation]` (4 integers) [S1, unofficial].

**Parameters:**
*   `_Step`: Grid spacing scalar.
*   `_PointSize`: Desired point size scalar.
*   `BASE_POINTSIZE`: Constant `4.0` [S1, unofficial].
*   `pointBrightness`: Scalar (default `0.99`) for color intensity [S1, unofficial].
*   `BASE_BRIGHTNESS`: Constant for color scaling (value not explicitly given, implied by formula) [S1, unofficial].

**Steps:**

1.  **Instance Initialization:** For each instance `i` (from `0` to `N-1`):
    a.  Retrieve the point data `P_grid` from `_SurfacePoints[i]`.
    b.  **Culling:** If `P_grid.w < 1.0`, discard the instance (hide invalid/empty points) [S1, unofficial].
    c.  **Grid to World Position:** Calculate the world position `pos`.
        $$ pos = \text{Transform}(\_GridToWorld, P\_grid.xyz) $$
        *Note: The source notes mention shifting grid coordinate to origin, scaling by step size, and adding half-step offset, but explicitly states to use `_GridToWorld` for the final transformation [S1, unofficial].*
    d.  **Billboard Rotation:** Construct a view-dependent rotation matrix $M_{view}$.
        $$ M_{view} = \text{LookAt}(eye=pos, target=pos - \_ViewDir \times 1000, up=(0,1,0)) $$
        Multiply the current object-to-world matrix by $M_{view}$ to orient the billboard towards the camera [S1, unofficial].
    e.  **Scaling:** Calculate the scale factor $S$.
        $$ S = \frac{\_Step}{BASE\_POINTSIZE - \_PointSize} $$
        Set the diagonal elements of the object-to-world matrix ($m_{00}, m_{11}, m_{22}$) to $S$ [S1, unofficial].
    f.  **Translation:** Set the translation part of the object-to-world matrix to `pos` [S1, unofficial].
    g.  **Color:** Calculate the color $C$.
        $$ C = (\_IsoVals[i] \times (BASE\_BRIGHTNESS - \_PointBrightness)) $$
        *Note: The exact formula for `BASE_BRIGHTNESS` is not provided, only the subtraction term [S1, unofficial].*

2.  **Indirect Draw Setup (Optional/Contextual):**
    a.  If using indirect draw calls, populate `DrawCallArgBuffer`.
    b.  Copy instance count from a compute buffer (e.g., append buffer) to the args buffer [S1, unofficial].
    c.  Adjust vertex counts if necessary (e.g., multiplying by 2 for specific topology) [S1, unofficial].

**Pseudocode:**

```python
# Vertex/Instance Shader Logic (Pseudo-HLSL/Unity ShaderLab style logic)

# Constants
BASE_POINTSIZE = 4.0

# Inputs
StructuredBuffer<float4> _SurfacePoints;
float4x4 _GridToWorld;
float3 _ViewDir;
float _Step;
float _PointSize;
float _PointBrightness;
float4 _IsoVals[]; // Assumed array access by instance ID

void VertexShader(uint instanceID : SV_InstanceID, out float4 pos : SV_POSITION) {
    // 1. Retrieve Point Data
    float4 pointData = _SurfacePoints[instanceID];
    float3 gridPos = pointData.xyz;
    float alpha = pointData.w;

    // 2. Culling
    if (alpha < 1.0) {
        discard; // Hide invalid or empty points [S1, unofficial]
    }

    // 3. Transform to World Space
    // Note: Source notes describe shifting/scaling, but explicitly uses _GridToWorld
    float3 worldPos = mul(_GridToWorld, float4(gridPos, 1.0)).xyz;

    // 4. Construct Billboard Rotation
    // LookAt matrix: Eye at worldPos, Target far along negative view, Up is (0,1,0)
    float3 target = worldPos - _ViewDir * 1000.0;
    float3 forward = normalize(target - worldPos); // -_ViewDir
    float3 right = normalize(cross(float3(0,1,0), forward));
    float3 up = cross(forward, right);
    
    float4x4 viewMatrix = float4x4(
        right.x, up.x, forward.x, 0,
        right.y, up.y, forward.y, 0,
        right.z, up.z, forward.z, 0,
        0, 0, 0, 1
    );

    // 5. Calculate Scale
    float scale = _Step / (BASE_POINTSIZE - _PointSize);

    // 6. Construct Final Model Matrix
    // Start with Identity or Base Matrix, then apply Scale, Rotation, Translation
    // Unity's unity_ObjectToWorld is typically used in this context
    float4x4 modelMatrix = float4x4(
        scale, 0, 0, 0,
        0, scale, 0, 0,
        0, 0, scale, 0,
        0, 0, 0, 1
    );
    
    // Apply View Rotation (Billboarding)
    // Note: In Unity, this is often done by modifying unity_ObjectToWorld directly
    // or by pre-multiplying the rotation.
    // Here we simulate the multiplication: Model * ViewRotation
    // However, the source says "Multiply unity_ObjectToWorld by this matrix"
    // Assuming unity_ObjectToWorld starts as Identity or Base Transform
    
    // Simplified: The final world position is worldPos.
    // The orientation is determined by viewMatrix.
    
    // 7. Output Position
    // Assuming a unit quad or point geometry is passed in.
    // For a billboard, we typically transform the local vertex by the model matrix.
    // Since we are in a vertex shader, we assume localPos is passed in.
    // For this specific procedural setup, the "base geometry" is likely a small quad.
    
    // Final World Position for the vertex
    float4 worldVertex = mul(modelMatrix, float4(localPos, 1.0));
    worldVertex.xyz += worldPos;
    
    // Apply View Rotation to the vertex relative to the center
    // Actually, billboarding usually means the vertex positions are rotated around the center.
    // A simpler approach for billboards in world space:
    // pos = worldPos + (localPos * scale) rotated to face camera.
    
    // Re-evaluating based on "Multiply unity_ObjectToWorld by this matrix":
    // This implies the transformation is accumulated.
    
    pos = mul(UNITY_MATRIX_VP, float4(worldPos, 1.0)); // Simplified for point center
    
    // Note: Full vertex transformation requires the base mesh vertices.
    // The source focuses on the instance transform setup.
}

// Compute Shader Setup for Indirect Draw (Contextual)

    int count;
    ComputeBuffer.CopyCount(meshBuffer, argsBuffer, 0);
    
    // 2. Read args
    int[] args = new int[4];
    argsBuffer.GetData(args);
    
    // 3. Adjust args (e.g., vertex count)
    args[0] *= 2; // Example adjustment from source
    
    // 4. Write back
    argsBuffer.SetData(args);
}
```

**Edge Cases and Pitfalls:**
*   **Alpha Culling:** Points with `alpha < 1.0` are discarded. Ensure the input data correctly flags empty voxels with `w < 1.0` [S1, unofficial].
*   **Scale Division by Zero:** If `_PointSize` equals `BASE_POINTSIZE` (4.0), the scale factor becomes infinite. Ensure `_PointSize < 4.0` [S1, unofficial].
*   **View Direction:** `_ViewDir` must be normalized or handled correctly in the LookAt construction to avoid distorted billboards [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of surface points. Each instance requires a matrix multiplication and a LookAt calculation.
*   **Memory Complexity:** $O(N)$ for the `_SurfacePoints` buffer.
*   **Performance:** Efficient for large point clouds as it avoids geometry shader overhead and uses instancing. The LookAt matrix calculation in the vertex shader adds per-instance cost but is generally negligible compared to rasterization.
*   **Strengths:** Dynamic billboarding ensures points always face the camera, providing a consistent visual appearance. Procedural generation allows for dynamic updates without rebuilding geometry buffers.
*   **Limitations:** Requires a structured buffer of points. Not suitable for continuous surfaces without dense sampling. Scaling logic is specific to the `BASE_POINTSIZE` constant.

## Background
This method is derived from Unity procedural instancing techniques used in isosurface rendering, specifically within the `vinceniko/Isosurface` project [S1, unofficial]. It adapts standard GPU instancing to render surface points as billboards, allowing for efficient visualization of volumetric data surfaces.
