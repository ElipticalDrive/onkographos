# Procedural Point Rendering with Billboard Transformation

Also called: GPU Instancing Setup, Procedural Instancing Configuration

## Overview
This method renders a sparse set of surface points as billboards using GPU procedural instancing, transforming grid-based point cloud data into world space and orienting each primitive to face the camera [S1, unofficial]. It differs from standard voxel rasterization by decoupling the geometric representation from the dense grid structure, allowing for efficient rendering of isosurface samples or particle-like data without generating full voxel cubes [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A structured buffer `_SurfacePoints` containing point data [S1, unofficial].
*   **Input:** A 4x4 matrix `_GridToWorld` for coordinate transformation [S1, unofficial].
*   **Input:** A view direction vector `_ViewDir` [S1, unofficial].
*   **Input:** Scalar parameters `_Step`, `_PointSize`, `BASE_POINTSIZE` (4.0), and `_PointBrightness` [S1, unofficial].
*   **Input:** An array `_IsoVals` containing isovalue-derived colors [S1, unofficial].
*   **Output:** A stream of billboard primitives submitted to the graphics pipeline via indirect draw calls [S1, unofficial].

**Data Structures:**
*   `_SurfacePoints`: A structured buffer of `float4`. The `xyz` components represent the point position in grid space, and the `w` component represents the alpha value [S1, unofficial].
*   `DrawCallArgBuffer`: A compute buffer used for indirect drawing, containing four integers: `vertexCountPerInstance`, `instanceCount`, `startVertexLocation`, and `startInstanceLocation` [S1, unofficial].

**Parameters:**
*   `BASE_POINTSIZE`: Constant value 4.0 [S1, unofficial].
*   `_Step`: Scalar used to scale the object's local axes [S1, unofficial].
*   `_PointSize`: Scalar subtracted from `BASE_POINTSIZE` to determine the scaling factor [S1, unofficial].
*   `_PointBrightness`: Scalar (range 0.0–0.99) used to modulate color brightness [S1, unofficial].
*   `BASE_BRIGHTNESS`: Implicit constant used in color calculation (value not explicitly defined in sources, assumed to be 1.0 or a standard base) [S1, unofficial].

**Steps:**
1.  **Instance ID Mapping:** The rendering engine provides an `unity_InstanceID` for each instance. This ID maps to a specific point in the `_SurfacePoints` buffer [S1, unofficial].
2.  **World Position Calculation:**
    *   Retrieve the point position `pos_grid` from `_SurfacePoints[unity_InstanceID].xyz` [S1, unofficial].
    *   Transform `pos_grid` to world space: `pos_world = _GridToWorld * float4(pos_grid, 1.0)` [S1, unofficial].
    *   *Note:* The source notes mention shifting grid coordinates to origin and scaling by step size, but the primary implementation uses the `_GridToWorld` matrix for this transformation [S1, unofficial].
3.  **Billboard Orientation:**
    *   Construct a look-at matrix to orient the billboard towards the camera [S1, unofficial].
    *   Eye position: `pos_world` [S1, unofficial].
    *   Target position: `pos_world - _ViewDir * 1000.0` [S1, unofficial].
    *   Up vector: `(0, 1, 0)` [S1, unofficial].
    *   Multiply the current object-to-world matrix by this look-at matrix to set the rotation [S1, unofficial].
4.  **Scaling:**
    *   Calculate the scale factor: `scale = _Step / (BASE_POINTSIZE - _PointSize)` [S1, unofficial].
    *   Set the diagonal elements of the object-to-world matrix (`m00`, `m11`, `m22`) to `scale` [S1, unofficial].
5.  **Color Assignment:**
    *   Retrieve the isovalue color from `_IsoVals[unity_InstanceID]` [S1, unofficial].
    *   Apply brightness modulation: `color = retrieved_color * (BASE_BRIGHTNESS - _PointBrightness)` [S1, unofficial].
6.  **Alpha Culling:**
    *   Retrieve the alpha value from `_SurfacePoints[unity_InstanceID].w` [S1, unofficial].
    *   If alpha < 1.0, discard the point (clip_float) to hide invalid or empty points [S1, unofficial].

**Pseudocode:**
```python
# Vertex/Instance Shader Logic (Simplified for Procedural Instancing)

# Constants
BASE_POINTSIZE = 4.0
BASE_BRIGHTNESS = 1.0 # Assumed based on context

# Inputs
SurfacePoints: StructuredBuffer<float4> # xyz: position, w: alpha
GridToWorld: float4x4
ViewDir: float3
Step: float
PointSize: float
PointBrightness: float
IsoVals: Array<float4> # Colors indexed by instance ID

# Per-Instance Data
InstanceID: uint

def RenderBillboard(InstanceID):
    # 1. Retrieve Point Data
    point_data = SurfacePoints[InstanceID]
    pos_grid = point_data.xyz
    alpha = point_data.w
    
    # 2. Alpha Culling
    if alpha < 1.0:
        return # Discard invalid/empty points

    # 3. World Position
    # Transform grid position to world space
    pos_world = mul(GridToWorld, float4(pos_grid, 1.0))
    
    # 4. Billboard Orientation
    # Construct look-at matrix
    # Eye: pos_world, Target: pos_world - ViewDir * 1000, Up: (0,1,0)
    # Note: In Unity procedural instancing, this is often done by modifying unity_ObjectToWorld
    # Here we simulate the matrix construction
    forward = normalize(-ViewDir)
    right = normalize(cross(float3(0,1,0), forward))
    up = cross(forward, right)
    
    # Construct rotation matrix
    # R = [right.x, right.y, right.z, 0]
    #     [up.x,   up.y,   up.z,   0]
    #     [forward.x, forward.y, forward.z, 0]
    #     [0, 0, 0, 1]
    
    # 5. Scaling
    scale_factor = Step / (BASE_POINTSIZE - PointSize)
    
    # 6. Color
    base_color = IsoVals[InstanceID]
    final_color = base_color * (BASE_BRIGHTNESS - PointBrightness)
    
    # 7. Output
    # The instance matrix (unity_ObjectToWorld) is set to:
    # Translation: pos_world
    # Scale: scale_factor (applied to local axes)
    # Rotation: Look-at matrix constructed above
    
    return final_color
```

**Edge Cases and Pitfalls:**
*   **Invalid Points:** Points with alpha values less than 1.0 must be explicitly discarded to prevent rendering artifacts or empty space [S1, unofficial].
*   **Precision:** The use of a large multiplier (1000.0) in the look-at target calculation may introduce precision issues if the scene coordinates are very large or very small [S1, unofficial].
*   **Scaling Division:** If `PointSize` equals `BASE_POINTSIZE`, the scale factor becomes undefined (division by zero). Ensure `PointSize < BASE_POINTSIZE` [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** O(N) where N is the number of valid surface points. Each point requires a constant amount of work for transformation and orientation [S1, unofficial].
*   **Memory Complexity:** O(N) for the `_SurfacePoints` buffer and `_IsoVals` array [S1, unofficial].
*   **Performance:** Efficient for sparse point clouds. The use of indirect draw calls minimizes CPU-GPU synchronization overhead [S1, unofficial].
*   **Strengths:** Simple implementation, low memory footprint for sparse data, easy integration with existing procedural instancing frameworks [S1, unofficial].
*   **Limitations:** Billboards do not provide true 3D volume information; they are always front-facing. Not suitable for dense volumetric visualization where depth cues are critical [S1, unofficial].
*   **When to Use:** Rendering isosurface samples, particle systems, or sparse point clouds where performance is critical and 3D shape is less important than position and color [S1, unofficial].
*   **When Not to Use:** When true volumetric rendering or accurate depth representation of the surface is required [S1, unofficial].

## Background
This technique is derived from Unity procedural instancing workflows for rendering isosurfaces and surface points [S1, unofficial]. It is commonly used in scientific visualization and real-time rendering of sparse data sets where traditional voxel rendering is too expensive or unnecessary [S1, unofficial].
