# Flowline Extrusion


## Overview
Flowline Extrusion is a technique to extrude a path of positions into a velocity field by looping over positions, computing velocity vectors, and splatting them using instanced rendering [S1, unofficial]. It solves the problem of generating volumetric velocity data from discrete path points by converting vector information into additive splat contributions. It sets itself apart from [3D Gaussian Splatting via Instancing](1586-3d-gaussian-splatting-via-instancing.md) by explicitly encoding the velocity vector as the color of the splat rather than just density, and from [Volumetric Spot Noise Rendering](2360-volumetric-spot-noise-rendering.md) by relying on deterministic path integration rather than stochastic noise functions.

## How it works
**Inputs and Outputs:**
*   **Input:** A list of 3D positions (`PointList`) representing a flow path.
*   **Output:** A 3D texture (`GL_TEXTURE_3D`) storing the accumulated velocity field.

**Data Structures:**
*   **Volume Texture:** A 3D texture with format `GL_RGB16F`, dimensions `width x height x depth`. Data type is `GL_HALF_FLOAT`.
*   **Point List:** A vector of 3D points (`VectorMath::Point3`).

**Parameters:**
*   **Blend Function:** `GL_ONE`, `GL_ONE` (additive blending).
*   **Splat Geometry:** A quad (4 vertices) rendered as `GL_TRIANGLE_STRIP`.
*   **Instance Count:** Determined by the "depth of the splat" [S1, unofficial].

**Steps:**
1.  Initialize a 3D texture with `GL_RGB16F` format and `GL_CLAMP_TO_EDGE` wrapping.
2.  Enable blending: `glEnable(GL_BLEND)`.
3.  Set blend function: `glBlendFunc(GL_ONE, GL_ONE)`.
4.  Iterate through each position `i` in the `PointList`.
5.  Determine the next position `next` in the path. If `i` is the last element, wrap to the beginning.
6.  Compute the velocity vector: $v = \text{next} - i$.
7.  Set the fragment shader uniform `Center` to the current position $(x, y, z, 0)$.
8.  Set the fragment shader uniform `Color` to the computed velocity vector $v$.
9.  Draw the splat using `glDrawArraysInstanced` with `GL_TRIANGLE_STRIP`, 4 vertices, and the instance count.

**Pseudocode:**
```python
def flowline_extrusion(positions, splat_program, texture_handle, instance_count):
    # Initialize texture if not already done
    # glTexImage3D(GL_TEXTURE_3D, 0, GL_RGB16F, width, height, depth, 0, GL_RGB, GL_HALF_FLOAT, 0)
    
    # Enable additive blending
    glEnable(GL_BLEND)
    glBlendFunc(GL_ONE, GL_ONE)
    
    # Bind the volume texture to the shader
    glActiveTexture(GL_TEXTURE0)
    glBindTexture(GL_TEXTURE_3D, texture_handle)
    
    # Use the splat program
    glUseProgram(splat_program)
    
    center_loc = glGetUniformLocation(splat_program, "Center")
    color_loc = glGetUniformLocation(splat_program, "Color")
    
    num_points = len(positions)
    
    for idx in range(num_points):
        current_pos = positions[idx]
        
        # Get next position, wrapping around if at the end
        next_idx = (idx + 1) % num_points
        next_pos = positions[next_idx]
        
        # Compute velocity vector
        velocity = next_pos - current_pos
        
        # Set uniforms
        glUniform4f(center_loc, current_pos.x, current_pos.y, current_pos.z, 0.0)
        glUniform3f(color_loc, velocity.x, velocity.y, velocity.z)
        
        # Draw instanced splats
        # Assuming a quad defined by 4 vertices in a VAO
        glDrawArraysInstanced(GL_TRIANGLE_STRIP, 0, 4, instance_count)
        
    glUseProgram(0)
    glDisable(GL_BLEND)
```

**Edge Cases and Pitfalls:**
*   **Memory Usage:** Using `GL_RGB16F` for velocity fields consumes significant memory [S1, unofficial].
*   **Distance Fields:** For a true distance field, use `GL_MAX` blending and a linear falloff in the fragment shader instead of Gaussian and additive blending [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of positions in the path.
*   **Memory Complexity:** Dominated by the 3D texture size (`width * height * depth * 6` bytes for `RGB16F`).
*   **Strengths:** Simple implementation; directly encodes vector direction and magnitude in the splat color.
*   **Limitations:** High memory usage for high-resolution volumes; additive blending may cause saturation if splats overlap excessively.
*   **When to use:** When generating velocity fields from known paths is required.
*   **When not to use:** When memory is constrained or when a true distance field representation is needed (use `GL_MAX` blending instead).

## Background
Originated in the context of volumetric splatting techniques for visualizing vector fields, as described in "Volumetric Splatting" by Pride [S1, unofficial]. It builds on the concept of rendering 3D Gaussians via instancing but adapts the output to represent velocity vectors.
