# Stream Tube Generation
Also called: Pentagonal Stream Tube Generation

## Overview
Stream tube generation solves the ambiguity of line position and orientation in still images by inflating thin stream lines with volume to create shaded tubes [S1, unofficial]. It differs from standard stream lines by computing face normals and indices for a pentagonal cross-section, which consumes more GPU memory but allows for smooth shading that helps viewers perceive 3D orientation [S1, unofficial].

## How it works
**Inputs:**
- `pos`: Current position along the stream line (float3).
- `v`: Velocity vector at `pos` (float3).
- `radius`: Radius of the tube (float).
- `baseIndex`: Starting index for the current tube's vertices in the output arrays (uint).
- `color`: Color of the tube (float3).

**Outputs:**
- `outVertices`: Array of vertex positions (float3*).
- `outNormals`: Array of vertex normals (float3*).
- `outColors`: Array of vertex colors (float3*).
- `outFaces`: Array of triangle indices (uint3*).

**Data Structures:**
- Each tube segment consists of 5 vertices forming a regular pentagon.
- Each segment generates 10 triangles (faces).
- Vertices are stored in a flat array indexed by `baseIndex`.
- Normals are stored in a flat array indexed by `baseIndex`.
- Colors are stored in a flat array indexed by `baseIndex`.
- Faces are stored in a flat array indexed by `baseFaceId`.

**Steps:**
1. **Compute Local Frame:**
   - Calculate `xAxis` as the normalized perpendicular vector to `v`. The source uses a helper function `findPerpendicular(v)` [S1, unofficial].
   - Calculate `yAxis` as the normalized cross product of `v` and `xAxis`: `yAxis = normalize(cross(v, xAxis))` [S1, unofficial].
   - Note: The tube extrusion occurs in the plane defined by `xAxis` and `yAxis`, perpendicular to the velocity vector `v` [S1, unofficial].

2. **Generate Pentagon Vertices and Normals:**
   - For each of the 5 vertices $i \in \{0, 1, 2, 3, 4\}$, calculate the angle $\theta_i = i \times 72^\circ$.
   - Compute the direction vector $d_i$ in the local frame:
     $$ d_i = \cos(\theta_i) \cdot \text{xAxis} + \sin(\theta_i) \cdot \text{yAxis} $$
   - The source provides pre-computed coefficients for these angles:
     - $i=0$ ($0^\circ$): $d_0 = 1.0 \cdot \text{xAxis} + 0.0 \cdot \text{yAxis}$
     - $i=1$ ($72^\circ$): $d_1 = 0.3090 \cdot \text{xAxis} + 0.9511 \cdot \text{yAxis}$
     - $i=2$ ($144^\circ$): $d_2 = -0.8090 \cdot \text{xAxis} + 0.5878 \cdot \text{yAxis}$
     - $i=3$ ($216^\circ$): $d_3 = -0.8090 \cdot \text{xAxis} - 0.5878 \cdot \text{yAxis}$
     - $i=4$ ($288^\circ$): $d_4 = 0.3090 \cdot \text{xAxis} - 0.9511 \cdot \text{yAxis}$
   - Set the normal for vertex $i$: `outNormals[baseIndex + i] = normalize(d_i)` [S1, unofficial].
   - Set the position for vertex $i$: `outVertices[baseIndex + i] = pos + d_i * radius` [S1, unofficial].
   - Set the color for vertex $i$: `outColors[baseIndex + i] = color` [S1, unofficial].

3. **Generate Triangle Indices:**
   - For each vertex $i \in \{0, 1, 2, 3, 4\}$, define two triangles connecting the current pentagon to the previous pentagon (stored at `baseIndex - 5`).
   - Let $v_{curr} = \text{baseIndex} + i$ and $v_{prev} = \text{baseIndex} - 5 + i$.
   - Let $v_{next\_curr} = \text{baseIndex} + (i + 1) \% 5$ and $v_{next\_prev} = \text{baseIndex} - 5 + (i + 1) \% 5$.
   - Triangle 1: $(v_{curr}, v_{next\_curr}, v_{next\_prev})$
   - Triangle 2: $(v_{curr}, v_{prev}, v_{next\_prev})$
   - Store these indices in `outFaces` starting at `baseFaceId` [S1, unofficial].

**Pseudocode:**
```python
def create_tube_base_vertices(pos, v, radius, base_index, color, out_vertices, out_normals, out_colors):
    # Find a vector perpendicular to v
    x_axis = normalize(find_perpendicular(v))
    y_axis = normalize(cross(v, x_axis))
    
    # Pre-computed coefficients for 0, 72, 144, 216, 288 degrees
    # cos(0)=1, sin(0)=0
    # cos(72)=0.3090, sin(72)=0.9511
    # cos(144)=-0.8090, sin(144)=0.5878
    # cos(216)=-0.8090, sin(216)=-0.5878
    # cos(288)=0.3090, sin(288)=-0.9511
    
    coeffs = [
        (1.0, 0.0),
        (0.3090, 0.9511),
        (-0.8090, 0.5878),
        (-0.8090, -0.5878),
        (0.3090, -0.9511)
    ]
    
    for i in range(5):
        cx, cy = coeffs[i]
        # Direction vector in the local plane
        dir_vec = x_axis * cx + y_axis * cy
        
        # Normalize the direction vector for the normal
        # Note: Since x_axis and y_axis are orthonormal and cx^2 + cy^2 = 1,
        # dir_vec is already normalized. However, the source explicitly normalizes.
        normal = normalize(dir_vec)
        
        out_normals[base_index + i] = normal
        out_vertices[base_index + i] = pos + normal * radius
        out_colors[base_index + i] = color

def create_tube_indices(vertex_base_id, base_face_id, out_faces):
    for i in range(5):
        i_next = (i + 1) % 5
        
        # Current vertex and next vertex in the current pentagon
        v_curr = vertex_base_id + i
        v_next_curr = vertex_base_id + i_next
        
        # Previous vertex and next vertex in the previous pentagon
        v_prev = vertex_base_id - 5 + i
        v_next_prev = vertex_base_id - 5 + i_next
        
        # Triangle 1: v_curr -> v_next_curr -> v_next_prev
        out_faces[base_face_id] = (v_curr, v_next_curr, v_next_prev)
        base_face_id += 1
        
        # Triangle 2: v_curr -> v_prev -> v_next_prev
        out_faces[base_face_id] = (v_curr, v_prev, v_next_prev)
        base_face_id += 1
```

**Parameters:**
- `radius`: Not given in the sources.
- `num_samples`: Not given in the sources.

**Edge Cases and Pitfalls:**
- The adaptive algorithm does not work with stream tubes due to array index management bugs during counting [S1, unofficial].
- Stream tubes consume significantly more GPU memory than stream lines because they require storing vertices, normals, colors, and face indices [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Computation power for integration is the same as for stream lines [S1, unofficial].
- **Memory Complexity:** Higher than stream lines due to the need to store face indices, normals, and more vertices per segment [S1, unofficial].
- **Performance:** On an NVIDIA Quadro K5000, $2^{13}$ stream tubes with $2^{13}$ samples took 240 ms [S1, unofficial].
- **Strengths:** Provides better 3D orientation perception through shading; smooth shading makes the pentagonal cross-section appear smooth [S1, unofficial].
- **Limitations:** Higher memory usage; adaptive algorithms are not supported [S1, unofficial].

## Background
Stream tube generation was implemented as part of a realtime visualization system for 3D vector fields using CUDA [S1, unofficial]. The method was chosen to address the difficulty of perceiving line position and orientation in still images [S1, unofficial].
