# Stream Tube Generation

Also called: Pentagonal Stream Tube Generation, Streamlines with Tube Geometry, Streamtube Line Integration

## Overview
Stream Tube Generation is a technique for visualizing 3D vector fields by integrating seed points into streamlines and extruding them into volumetric tube geometry [S1][S3, unofficial]. It solves the ambiguity of line position and orientation in still images by inflating thin stream lines with volume, allowing for shading and better spatial perception [S2, unofficial]. It sets itself apart from [Flow Volumes](7690-flow-volumes.md) by generating explicit geometric primitives (triangles) rather than volume textures, and from [Fabric Tube Rendering](10641-fabric-tube-rendering.md) by constructing actual 3D mesh geometry rather than relying on image-space post-processing [S1].

## How it works
**Inputs:**
- Volumetric data set $\Omega \subset \mathbb{R}^3$ and associated vector field $V: \Omega \rightarrow \mathbb{R}^3$ [S1].
- Seed points $p$ [S1].
- Integration step size $\varepsilon$ [S1].
- Tube radius $r$ [S1].
- `useRk4`: Boolean flag selecting between Runge-Kutta 4th order (`rk4Integrate`) and Euler integration (`eulerIntegrate`) [S3, unofficial].
- `geometrySampling`: Integer controlling frequency of tube mesh generation (geometry generated every `geometrySampling` steps) [S3, unofficial].
- `magnitudeCtfNormalizeMult`: Normalization factor for vector magnitude texture lookup [S3, unofficial].

**Outputs:**
- `outVertices` (`float3*`): Tube vertices [S3, unofficial].
- `outVertexNormals` (`float3*`): Tube normals [S3, unofficial].
- `outVertexColors` (`float3*`): Tube colors [S3, unofficial].
- `outFaces` (`uint3*`): Tube indices [S3, unofficial].
- `outComputedSteps` (`uint*`): Step count per seed [S3, unofficial].

**Data Structures:**
- The tube cross-section is a regular pentagon with 5 vertices [S2, unofficial].
- Indices are generated per segment connecting two pentagonal slices [S2, unofficial].

**Steps:**

1. **Integration:** Solve the ODE $\frac{\partial x(t)}{\partial t} = V(x(t))$ with $x(0) = p$ to generate a streamline [S1]. Discretize using Euler's method:
   $$x_{i+1} = x_i + \varepsilon V(x_i)$$
   where $\varepsilon$ is a small value appropriate to the data set $\Omega$ to reduce integration error [S1]. If `useRk4` is true, use 4th-order Runge-Kutta instead [S3, unofficial].

2. **Boundary Check:** Initialize `maxWorld` bounds: `maxWorld.x = volumeSize.width / volumeCoordSpaceMult.x`, `maxWorld.y = volumeSize.height / volumeCoordSpaceMult.y`, `maxWorld.z = volumeSize.depth / volumeCoordSpaceMult.z` [S3, unofficial]. If `position.x < 0` or `position.y < 0` or `position.z < 0` or `position.x > maxWorld.x` or `position.y > maxWorld.y` or `position.z > maxWorld.z`, break the loop [S3, unofficial].

3. **Geometry Generation Trigger:** Maintain a counter `geometryStep` initialized to `geometrySampling` [S3, unofficial]. Decrement it each step. If `geometryStep == 0`, reset `geometryStep = geometrySampling` and generate geometry for the current position [S3, unofficial].

4. **Color Lookup:** Sample magnitude color: `color = tex1D(vectorMangitudeCtfTex, (float)(dv.w * magnitudeCtfNormalizeMult))` where `dv.w` is the magnitude component from the integration result [S3, unofficial].

5. **Vertex Generation:** Call `createTubeBaseVertices` with `position`, velocity vector `dv.xyz` (from integration), `radius`, `outputPos`, `color`, and output buffers [S3, unofficial]. This function computes the pentagonal cross-section in the plane defined by the velocity vector [S2, unofficial].

6. **Index Generation:** Call `createTubeIndices` with `outputPos` and `(outputPos - 5 * id - 5) * 2` to generate triangles connecting the current pentagon to the previous one [S3, unofficial].

7. **Loop & Store:** Increment step counter. If `step < maxSteps`, continue integration [S3, unofficial]. Otherwise, store `outComputedSteps[id] = step / geometrySampling` [S3, unofficial].

**Pseudocode:**

```python
class Vec3:
    def __init__(self, x=0.0, y=0.0, z=0.0):
        self.x, self.y, self.z = x, y, z
    def __add__(self, o): return Vec3(self.x+o.x, self.y+o.y, self.z+o.z)
    def __sub__(self, o): return Vec3(self.x-o.x, self.y-o.y, self.z-o.z)
    def __mul__(self, s): return Vec3(self.x*s, self.y*s, self.z*s)
    def length(self): return (self.x**2 + self.y**2 + self.z**2)**0.5
    def normalize(self): l = self.length(); return Vec3(self.x/l, self.y/l, self.z/l) if l > 0 else Vec3()

class Vec4:
    def __init__(self, x=0.0, y=0.0, z=0.0, w=0.0):
        self.x, self.y, self.z, self.w = x, y, z, w

def cross(a, b):
    return Vec3(a.y*b.z - a.z*b.y, a.z*b.x - a.x*b.z, a.x*b.y - a.y*b.x)

def find_perpendicular(v):
    # [G] Standard heuristic to find a vector perpendicular to v
    if abs(v.x) < 0.9:
        return cross(v, Vec3(1, 0, 0)).normalize()
    else:
        return cross(v, Vec3(0, 1, 0)).normalize()

def euler_integrate(position, dt, field_func, coord_mult):
    # [G] Standard Euler step for dx/dt = V(x)
    vel = field_func(position)
    dv = Vec4(vel.x * dt * coord_mult.x, vel.y * dt * coord_mult.y, vel.z * dt * coord_mult.z, vel.length())
    return dv

def rk4_integrate(position, dt, field_func, coord_mult):
    # [G] Standard RK4 step
    k1 = field_func(position)
    k2 = field_func(position + 0.5*dt*k1)
    k3 = field_func(position + 0.5*dt*k2)
    k4 = field_func(position + dt*k3)
    new_pos = position + (dt/6.0) * (k1 + 2*k2 + 2*k3 + k4)
    vel = (k1 + 2*k2 + 2*k3 + k4) / 6.0
    return Vec4(new_pos.x, new_pos.y, new_pos.z, vel.length())

def sample_magnitude_texture(magnitude, normalize_mult, ctf_texture):
    # [G] Linear interpolation or clamped lookup in a 1D magnitude-to-color texture
    t = min(max(magnitude * normalize_mult, 0.0), 1.0)
    return ctf_texture[t] # Returns Vec3

def create_tube_base_vertices(pos, v, radius, base_index, color, out_vertices, out_normals, out_colors):
    x_axis = find_perpendicular(v)
    y_axis = cross(v, x_axis).normalize()
    # Precomputed pentagon directions (cos, sin) for 0, 72, 144, 216, 288 degrees
    pentagon_dirs = [
        (1.0, 0.0), (0.3090, 0.9511), (-0.8090, 0.5878),
        (-0.8090, -0.5878), (0.3090, -0.9511)
    ]
    for i in range(5):
        cos_a, sin_a = pentagon_dirs[i]
        normal = x_axis * cos_a + y_axis * sin_a
        out_normals[base_index + i] = normal
        out_vertices[base_index + i] = pos + normal * radius
        out_colors[base_index + i] = color

def create_tube_indices(vertex_base_id, base_face_id, out_faces):
    for i in range(5):
        i_next = (i + 1) % 5
        out_faces[base_face_id] = (vertex_base_id + i, vertex_base_id + i_next, vertex_base_id - 5 + i_next)
        out_faces[base_face_id + 1] = (vertex_base_id + i, vertex_base_id - 5 + i, vertex_base_id - 5 + i_next)
        base_face_id += 2

def generate_stream_tubes(seed_position, field_func, volume_size, coord_mult, radius, use_rk4, geometry_sampling, mag_normalize_mult, ctf_texture, max_steps, seed_id):
    out_vertices = [None] * (max_steps * 5)
    out_normals = [None] * (max_steps * 5)
    out_colors = [None] * (max_steps * 5)
    out_faces = [None] * (max_steps * 10)
    
    position = seed_position
    step = 1
    geometry_step = geometry_sampling
    output_pos = 0
    
    # Max world bounds [S3, unofficial]
    max_world_x = volume_size.width / coord_mult.x
    max_world_y = volume_size.height / coord_mult.y
    max_world_z = volume_size.depth / coord_mult.z
    
    while step < max_steps:
        # Boundary check [S3, unofficial]
        if (position.x < 0 or position.y < 0 or position.z < 0 or
            position.x > max_world_x or position.y > max_world_y or position.z > max_world_z):
            break
            
        # Integration [S3, unofficial]
        if use_rk4:
            dv = rk4_integrate(position, 1.0, field_func, coord_mult)
        else:
            dv = euler_integrate(position, 1.0, field_func, coord_mult)
            
        position.x += dv.x
        position.y += dv.y
        position.z += dv.z
        
        # Geometry generation trigger [S3, unofficial]
        geometry_step -= 1
        if geometry_step == 0:
            geometry_step = geometry_sampling
            
            # Color lookup [S3, unofficial]
            color = sample_magnitude_texture(dv.w, mag_normalize_mult, ctf_texture)
            
            # Vertex generation [S3, unofficial]
            create_tube_base_vertices(position, Vec3(dv.x, dv.y, dv.z), radius, output_pos, color, out_vertices, out_normals, out_colors)
            
            # Index generation [S3, unofficial]
            if output_pos >= 5:
                create_tube_indices(output_pos, (output_pos - 5 * seed_id - 5) * 2, out_faces)
                
            output_pos += 5
        step += 1
        
    out_computed_steps = step / geometry_sampling
    return out_vertices, out_normals, out_colors, out_faces, out_computed_steps
```

**Edge Cases and Pitfalls:**
- **Frenet Frame Twist:** If using a swept circle along a B-spline curve $\gamma(u)$, the normal of the Frenet frame flips at inflection points, causing severe twists in the surface $\sigma(u, v)$ [S1]. The CUDA implementation avoids this by constructing the tube locally in the plane defined by the velocity vector at each step, rather than using a global Frenet frame [S2, unofficial].
- **Self-Intersections:** To avoid self-intersections in the stream tube, the radius must be smaller than $1/\kappa_{max}$, where $\kappa_{max}$ is the maximum curvature of the curve [S1].
- **Memory Usage:** Stream tubes consume significantly more GPU memory than stream lines due to the computation of indices, normals, and the increased vertex count [S2, unofficial].

## Subtopics

### [Fabric Tube Rendering](10641-fabric-tube-rendering.md)
A post-processing technique that interprets a composited image of a tensor field as streamtubes on the surface without creating actual 3D geometry. It uses binormals derived from eigenvectors and image-plane normals to determine tube position and width, creating a tube-like effect with proper spatial impression. It sets itself apart from [Stream Tube Generation](2707-stream-tube-generation.md) by avoiding explicit geometric construction and integration along the field, instead relying on local image-space analysis to compute shading normals.

### [Edge Enhanced Transparent Streamtubes](16713-edge-enhanced-transparent-streamtubes.md)
Edge Enhanced Transparent Streamtubes is a hardware-accelerated rendering technique that represents fibre tracts as semi-transparent tubes with emphasised silhouettes. It improves the identification of individual fibre tracts and their 3D arrangement by revealing inner structures and softening silhouette edges. Unlike standard polygon transparency which lacks real-world attenuation effects, this method approximates the apparent change in transparency at silhouette edges of real objects, reducing visual cluttering and aliasing effects in densely packed streamlines.

## Operating characteristics
- **Time Complexity:** Integration is $O(N)$ where $N$ is the number of steps per streamline [S3, unofficial]. Geometry generation is proportional to the number of steps divided by `geometrySampling` [S3, unofficial].
- **Memory Complexity:** Significantly higher than stream lines [S2, unofficial]. Requires storage for vertices, normals, colors, and indices for all tubes [S3, unofficial].
- **Performance:** On an NVIDIA Quadro K5000, $2^{13}$ stream tubes with $2^{13}$ samples took 240 ms [S2, unofficial]. This is comparable to stream lines in integration time, but the geometry generation and memory bandwidth for normals/indices add overhead [S2, unofficial].
- **Strengths:** Provides clear 3D orientation and position of flow paths; allows for shading and lighting effects; smooth shading with pentagonal cross-sections is visually sufficient [S2, unofficial].
- **Limitations:** High memory consumption; adaptive algorithms are difficult to implement due to index management bugs [S2, unofficial]; requires careful radius selection to avoid self-intersections [S1].

## Background
Stream Tube Generation was developed as a method to visualize 3D vector fields by solving the ODE $\frac{\partial x(t)}{\partial t} = V(x(t))$ and constructing tube geometry from the resulting streamlines [S1]. The approach was detailed in research on combined volumes and tubular geometry [S1]. Practical CUDA implementations for real-time visualization have been documented in academic blogs and open-source repositories [S2, S3, unofficial].
