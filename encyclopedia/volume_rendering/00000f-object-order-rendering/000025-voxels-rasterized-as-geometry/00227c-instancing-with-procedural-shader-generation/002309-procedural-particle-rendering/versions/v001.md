# Procedural Particle Rendering

Also called: Procedural Particle System, RNG-Seeded Particle Rendering

## Overview
Procedural Particle Rendering generates particle attributes (position, velocity, color, size) on-the-fly using a Random Number Generator (RNG) seeded by particle ID, eliminating the need to store per-particle state in memory buffers [S1, unofficial]. Unlike [Instancing with Procedural/Shader Generation](2794-instancing-with-procedural-shader-generation.md) which relies on static instance buffers, this method computes dynamic physics and appearance entirely within the shader, making it suitable for high-density, short-lived effects like fire or dust where memory bandwidth is a bottleneck [S1, unofficial]. It differs from [Procedural Point Rendering with Billboard Transformation](6422-procedural-point-rendering-with-billboard-transformation.md) by explicitly modeling uniformly accelerated motion for position updates rather than simple billboard scaling [S1, unofficial].

## How it works
**Inputs:**
*   Particle ID ($i$): Unique integer identifier for each particle instance.
*   Time ($t$): Global simulation time or frame delta.
*   RNG State: A deterministic random number generator (e.g., PCG, Xoshiro) initialized with $i$.

**Outputs:**
*   World-space position ($\mathbf{p}$), velocity ($\mathbf{v}$), color ($\mathbf{c}$), and size ($s$) for each particle.

**Data Structures:**
*   No persistent particle buffers. Attributes are computed per-vertex/fragment.
*   Base geometry: Typically a quad or point sprite, transformed by the computed position and size.

**Steps:**
1.  **Initialize RNG:** Seed the RNG with the particle ID $i$. This ensures deterministic behavior for each particle across frames [S1, unofficial].
2.  **Sample Attributes:** Use the RNG to sample uniform distributions for initial position $\mathbf{p}_0$, initial velocity $\mathbf{v}_0$, color $\mathbf{c}$, and size $s$ [S1, unofficial]. These represent the "start" values at birth time $t_0$.
3.  **Interpolate Attributes:** Interpolate between start values ($\mathbf{p}_0, \mathbf{v}_0, \mathbf{c}, s$) and end values ($\mathbf{p}_1, \mathbf{v}_1, \mathbf{c}_1, s_1$) based on the particle's age relative to its lifetime. The end values are also sampled from the RNG at initialization [S1, unofficial].
4.  **Calculate Position:** Solve the equation of uniformly accelerated motion to determine current position $\mathbf{p}(t)$:
    $$ \mathbf{p}(t) = \mathbf{p}_0 + \mathbf{v}_0 \Delta t + \frac{1}{2} \mathbf{a} \Delta t^2 $$
    where $\Delta t$ is the time elapsed since particle birth, and $\mathbf{a}$ is the acceleration vector (e.g., gravity, buoyancy) [S1, unofficial].
5.  **Render Translucent Particles:** For effects like fire, render particles in a separate pass after opaque geometry to prevent Z-buffer artifacts caused by transparency [S1, unofficial].
6.  **Voxelization (if applicable):** During voxelization, add light values for translucent/additive particles instead of averaging them, preserving the additive nature of the effect [S1, unofficial].

**Pseudocode:**
```python
def compute_particle_attributes(particle_id, current_time, rng_seed_func):
    # Step 1: Initialize RNG with particle ID
    rng = rng_seed_func(particle_id)
    
    # Step 2: Sample start and end attributes from uniform distributions
    p0 = rng.sample_vector3()  # Initial position
    v0 = rng.sample_vector3()  # Initial velocity
    c0 = rng.sample_vector3()  # Initial color
    s0 = rng.sample_float()    # Initial size
    
    p1 = rng.sample_vector3()  # End position
    v1 = rng.sample_vector3()  # End velocity
    c1 = rng.sample_vector3()  # End color
    s1 = rng.sample_float()    # End size
    
    lifetime = rng.sample_float()  # Particle lifetime
    birth_time = current_time - lifetime
    
    # Step 3: Interpolate attributes based on age
    age = current_time - birth_time
    t = clamp(age / lifetime, 0.0, 1.0)
    
    p_current = lerp(p0, p1, t)
    v_current = lerp(v0, v1, t)
    c_current = lerp(c0, c1, t)
    s_current = lerp(s0, s1, t)
    
    # Step 4: Calculate position using uniformly accelerated motion
    # Assume constant acceleration 'a' (e.g., gravity)
    a = vector3(0.0, -9.81, 0.0)  # Example: gravity
    dt = age
    p_final = p0 + v0 * dt + 0.5 * a * dt * dt
    
    return p_final, v_current, c_current, s_current
```

**Edge Cases:**
*   **Precision:** Floating-point precision errors in $\Delta t^2$ can cause jitter for very long-lived particles. Use double precision or re-center coordinates if necessary [G].
*   **Boundary Conditions:** Particles may escape the view frustum or simulation bounds. Implement early culling in the vertex shader if possible [G].
*   **Z-Buffer Issues:** Rendering translucent particles before opaque objects causes incorrect depth sorting. Always render opaque geometry first [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per particle, independent of the number of particles. Computation is dominated by RNG calls and basic arithmetic [S1, unofficial].
*   **Memory Complexity:** $O(1)$ persistent memory. No buffers for particle positions, velocities, or lifetimes are stored [S1, unofficial].
*   **Performance:** On a Ryzen 3500U with Vega 8 GPU, the approach showed noticeable speedup due to reduced memory bandwidth usage, though thermal throttling may affect measurements [S1, unofficial].
*   **Strengths:** Extremely low memory footprint; easy to parallelize; no synchronization needed between CPU and GPU for particle state.
*   **Limitations:** Limited to simple physics (uniform acceleration); difficult to implement complex particle interactions (collisions, fluid dynamics); deterministic RNG must be carefully chosen to avoid visible patterns [S1, unofficial].
*   **When to Use:** Fire, smoke, dust, sparks, or any effect with high particle count and simple motion.
*   **When Not to Use:** Effects requiring complex particle interactions, precise collision detection, or long-term state persistence [S1, unofficial].

## Background
This method was described in a personal project report on Voxel Cone Tracing, where the author implemented a simple particle system for fire effects [S1, unofficial]. The approach leverages the computational power of modern GPUs to trade memory bandwidth for arithmetic operations, a common optimization in real-time rendering [S1, unofficial].
