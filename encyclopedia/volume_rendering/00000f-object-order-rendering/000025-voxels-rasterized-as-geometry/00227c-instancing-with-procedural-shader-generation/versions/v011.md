# Instancing with Procedural/Shader Generation

Also called: Instanced Voxel Rendering with Palette Textures, Palette-based Voxel Rendering

## Overview
This method renders a voxel model by instantiating a single unit cube mesh for each occupied voxel, positioning them via per-instance 3D offsets and coloring them via per-instance UV coordinates sampled from a 2D palette texture [S1, unofficial]. It solves the problem of efficiently rendering large voxel worlds by decoupling geometry generation from instance data, allowing the GPU to handle the repetition of the base mesh [S4, unofficial]. It differs from [Voxels rasterized as geometry](27-voxels-rasterized-as-geometry.md) by avoiding the creation of individual vertex buffers for every voxel face, instead relying on hardware instancing to replicate a single proxy geometry [S1, unofficial]. It differs from [Instanced Rendering with Texture Arrays](12569-instanced-rendering-with-texture-arrays.md) by using a 2D palette texture for color lookup rather than a 3D texture array for direct voxel sampling [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A list of occupied voxel coordinates (indices $i, j, k$) and a 2D palette texture containing base colors.
*   **Output:** A rasterized image of the voxel model with lighting.

**Data Structures:**
1.  **Instance Buffer (VBO):** A contiguous array of floats. Each instance contains exactly 5 floats in the following order:
    *   `offsetX` (float): X-coordinate offset.
    *   `offsetY` (float): Y-coordinate offset.
    *   `offsetZ` (float): Z-coordinate offset.
    *   `u` (float): S-coordinate for palette texture sampling.
    *   `v` (float): T-coordinate for palette texture sampling.
    *   Total size: $N_{instances} \times 5 \times 4$ bytes [S1, unofficial].
2.  **Palette Texture:** A 2D texture (e.g., RGBA8) where each texel represents a unique color. Wrap modes must be set to `GL_CLAMP_TO_EDGE` to prevent sampling artifacts at boundaries [S1, unofficial].
3.  **Base Geometry:** A single unit cube mesh (6 faces, 24 vertices for flat shading or 6 vertices for shared shading) [S1, unofficial].

**Numbered Steps:**
1.  **Instance Data Generation:** For each occupied voxel at grid index $(i, j, k)$, calculate the world-space offset. If the voxel grid is unit-sized, the offset is $(i, j, k)$. Assign a unique UV coordinate $(u, v)$ to the voxel, typically derived from a color index or procedural mapping [S1, unofficial].
2.  **Buffer Upload:** Pack the per-instance data into a contiguous float array and upload it to a Vertex Buffer Object (VBO) bound to `GL_ARRAY_BUFFER` with usage hint `GL_STATIC_DRAW` [S1, unofficial].
3.  **Vertex Shader Execution:**
    *   Receive the local vertex position of the base cube.
    *   Retrieve the instance offset using the instance ID.
    *   Combine the local position with the instance offset: $P_{local\_combined} = P_{local} + P_{instance\_offset}$.
    *   Transform the combined position to clip space using the Model-View-Projection (MVP) matrix: $gl\_Position = MVP \times vec4(P_{local\_combined}, 1.0)$ [S1, unofficial].
    *   Pass the instance UV coordinates to the fragment shader [S1, unofficial].
4.  **Fragment Shader Execution:**
    *   Sample the base color from the palette texture using the interpolated UVs: $C_{base} = texture(uPaletteTexture, vUV).rgb$ [S1, unofficial].
    *   Compute lighting using a Phong model:
        *   Ambient: $C_{ambient} = C_{base} \times I_{ambient}$
        *   Diffuse: $C_{diffuse} = C_{base} \times \max(N \cdot L, 0.0) \times I_{diffuse}$
        *   Specular: $C_{specular} = V_{specular} \times I_{specular}$
        *   Total: $C_{final} = C_{ambient} + C_{diffuse} + C_{specular}$ [S1, unofficial].

**Pseudocode:**
```python
# Vertex Shader Logic (GLSL-like)
# Inputs: aLocalPosition (vec3), aInstanceOffset (vec3), aInstanceUV (vec2)
# Uniforms: uMVPMatrix (mat4)

void main() {
    // Combine local vertex position with instance offset
    vec3 localCombined = aLocalPosition + aInstanceOffset;
    
    // Transform to clip space
    gl_Position = uMVPMatrix * vec4(localCombined, 1.0);
}

# Fragment Shader Logic (GLSL-like)
# Inputs: vUV (vec2)
# Uniforms: uPaletteTexture (sampler2D), uAmbientIntensity (float), 
#           uSpecularIntensity (float), uLightPosWorld (vec3), 
#           uCameraPosWorld (vec3), uShininess (float)

void main() {
    // Sample base color from palette
    vec3 baseColor = texture(uPaletteTexture, vUV).rgb;
    
    // Phong Lighting Calculation
    vec3 N = normalize(gl_FrontFacing ? vec3(0.0, 0.0, 1.0) : vec3(0.0, 0.0, -1.0)); 
    // Note: Normal calculation depends on face orientation; simplified here for unit cube faces
    
    vec3 L = normalize(uLightPosWorld - gl_FragCoord.xyz);
    vec3 V = normalize(uCameraPosWorld - gl_FragCoord.xyz);
    vec3 H = normalize(L + V);
    
    float diff = max(dot(N, L), 0.0);
    float spec = pow(max(dot(N, H), 0.0), uShininess);
    
    vec3 ambient = baseColor * uAmbientIntensity;
    vec3 diffuse = baseColor * diff;
    vec3 specular = vec3(1.0) * spec * uSpecularIntensity;
    
    gl_FragColor = vec4(ambient + diffuse + specular, 1.0);
}
```

**Parameters:**
*   `AMBIENT_INTENSITY`: 0.35 [S1, unofficial].
*   `SPECULAR_INTENSITY`: 0.5 [S1, unofficial].
*   `SHININESS`: 32 [S1, unofficial].
*   `LIGHT_POS_WORLD`: (10, 15, 10) [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Coordinate System Mismatch:** If the source model uses a Z-up coordinate system (common in some voxel formats) while OpenGL uses Y-up, the Y and Z offsets must be swapped during instance buffer generation to align the geometry correctly [S1, unofficial].
*   **Palette Texture Artifacts:** Sampling near the edges of the palette texture can cause bleeding from adjacent colors. This is mitigated by setting the texture wrap modes for both S and T axes to `GL_CLAMP_TO_EDGE` [S1, unofficial].

## Subtopics

### [Surface-based Instancing with Noise Modulation](1582-surface-based-instancing-with-noise-modulation.md)
Surface-based Instancing with Noise Modulation generates a dense cloud of instanced points on a parametric surface, where point density and position are modulated by procedural noise functions. It solves the problem of creating smooth, organic volumetric appearances (such as smoke or fire) from discrete surface meshes by distributing millions of sample points across the geometry. It differs from sibling methods like [3D Gaussian Splatting via Instancing](1586-3d-gaussian-splatting-via-instancing.md) by using scalar/vector noise to drive density and displacement rather than learned Gaussian parameters, and from [Procedural Particle Rendering](2926-procedural-particle-rendering.md) by explicitly mapping noise to surface parameter space ($s,t$) rather than world space.

### [3D Gaussian Splatting via Instancing](1586-3d-gaussian-splatting-via-instancing.md)
This method renders sorted 2D Gaussians by submitting instanced quads to the standard hardware vertex/fragment pipeline, avoiding the memory overhead of tile-based rasterization. It solves the problem of efficiently projecting these Gaussians onto the screen by dynamically sizing quads based on opacity cutoffs and evaluating the Gaussian decay function in the fragment shader. It differs from [Volumetric Spot Noise Rendering](2360-volumetric-spot-noise-rendering.md) by relying on deterministic instanced geometry and standard blending rather than stochastic noise functions and hybrid OIT pipelines.

### [GPU Instancing with Indirect Draw Calls](2205-gpu-instancing-with-indirect-draw-calls.md)
GPU Instancing with Indirect Draw Calls is a technique to render a large number of identical meshes (voxels) efficiently by using indirect draw calls. Instead of issuing one draw call per instance, a single draw call is issued that reads instance counts and parameters from a GPU-accessible buffer, allowing the GPU to generate the draw commands itself. It is distinguished from its siblings by decoupling the CPU-side draw call issuance from the GPU-side execution logic, enabling dynamic instance counts and reducing CPU-GPU synchronization overhead compared to standard hardware instancing.

### [Indirect Draw Argument Setting](2418-indirect-draw-argument-setting.md)
Indirect Draw Argument Setting is a rendering optimization technique that uses a persistently mapped Vertex Buffer Object (VBO) as a memory pool for interleaved vertex data, divided into fixed-size buckets. Each occupied bucket is associated with an indirect draw call structure, allowing multiple sub-meshes to be rendered simultaneously via `glMultiDrawElementsIndirect`. This method reduces driver overhead from frequent state changes and draw calls while simplifying memory management for procedural voxel meshing. It sets itself apart from naive per-chunk VAO/VBO systems by merging sub-meshes and from merged VAO/VBO systems by avoiding full buffer resizes and re-uploads when updating sub-regions.

### [Procedural Particle Rendering](2926-procedural-particle-rendering.md)
Procedural Particle Rendering generates particle attributes on-the-fly by seeding a random number generator (RNG) with a particle ID, eliminating the need to store particle data in memory buffers. This approach allows particles to be generated directly inside a simple shader, reducing data management overhead.

### [WebGL 2 Hardware Instancing](3152-webgl-2-hardware-instancing.md)
WebGL 2 Hardware Instancing is a rendering technique that sends a single base primitive (typically a 2x2x2 cube) to the GPU and executes `gl.drawElementsInstanced` to render hundreds of thousands of copies simultaneously. It solves the CPU bottleneck associated with issuing individual draw calls for large numbers of voxels by packing translation, scaling, and color data into flat typed arrays. Unlike surface-based instancing which modulates geometry with noise, this method relies on explicit instance buffers and procedural sampling to dictate vertex positions and colors.

### [Geometry Shader Advanced Instancing for Cubes](4576-geometry-shader-advanced-instancing-for-cubes.md)
A technique using geometry shaders to generate cube meshes from instanced points, optimizing for visibility by emitting at most 12 vertices (3 quads) per cube. It differs from creating full 24-vertex cubes by leveraging the fact that backface culling always removes one of two opposite faces, allowing the shader to emit only the visible subset.

### [Procedural Point Rendering with Billboard Transformation](6422-procedural-point-rendering-with-billboard-transformation.md)
A rendering technique using Unity procedural instancing to render surface points as billboards. It transforms a grid-based point cloud into world space, orients each point to face the camera, and scales them based on a step size.

### [Buffer-Based Instancing (SSBO/Instance Buffers)](6501-buffer-based-instancing-ssbo-instance-buffers.md)
Buffer-Based Instancing is a rendering technique that supplies per-instance data (such as position, rotation, and material IDs) to the vertex shader via large, flexible Shader Storage Buffer Objects (SSBOs) rather than standard vertex attribute buffers or uniform buffers. It solves the problem of efficiently rendering massive numbers of distinct objects (e.g., voxels) by allowing the CPU or a compute shader to write instance records directly into GPU memory, which the vertex shader then accesses dynamically using `gl_InstanceID`. It differs from standard hardware instancing by decoupling instance data from the vertex stream, enabling complex, non-uniform instance layouts and procedural generation of transforms in the vertex stage, avoiding CPU-side mesh generation.

### [Voxel Instancing](9449-voxel-instancing.md)
Voxel Instancing renders a voxel grid by instantiating static mesh proxies at voxel coordinates, using per-voxel color indices to select from a mesh array. It solves the problem of rendering large voxel worlds by allowing easier addition and removal of individual instances compared to chunking, where modifying a block requires regenerating the entire chunk mesh. Unlike polygonal instancing which operates at the polygon level, voxel instancing operates on voxel data, offering a constant memory footprint and fast loading times for the instances.

### [Procedural and Rule-Based Spawning](13402-procedural-and-rule-based-spawning.md)
Procedural and Rule-Based Spawning is a family of techniques for automatically generating and placing large numbers of 3D instances (such as vegetation, rocks, or debris) onto a surface or volume based on algorithmic rules rather than manual placement. It solves the scalability problem of hand-placing assets in large environments by decoupling instance logic from the rendering pipeline, allowing for dynamic, data-driven distribution. It distinguishes itself from sibling methods like [Surface-based Instancing with Noise Modulation](1582-surface-based-instancing-with-noise-modulation.md) by relying on explicit procedural generators and LOD-aware grid constraints rather than purely continuous noise fields, and from [3D Gaussian Splatting via Instancing](1586-3d-gaussian-splatting-via-instancing.md) by using discrete geometric primitives instead of point-sprites.

### Splat quad vertex layout
Sets up a 4-vertex quad with specific coordinates for shader-based scaling of projected 2D Gaussian eigenvectors [S2, unofficial]. Vertex positions are defined as (-2,-2), (2,-2), (2,2), (-2,2) with indices 0,1,2,0,2,3. The vertex buffer uses `VET_FLOAT2` at `VES_POSITION`, and the index buffer uses `IT_16BIT`. The instance buffer contains 1 float per instance (`VET_FLOAT1`, `VES_TEXTURE_COORDINATES[0]`, location 8) [S2, unofficial].

### Uniform Object Distribution via Modulo Instancing
A technique where a modulo function is applied to the scene distance function to repeat a single SDF component with a defined interval, generating a uniform grid of object copies [S3]. A pitfall is that cutting off the previous grid hit by a ray may result in 3D objects associated with the cell and potentially intersected by the ray being removed from the scene [S3]. The original single-pass approach causes visible artifacts from many vantage points despite using Existence operators to reduce visibility [S3].

### Instanced Rendering
A rendering technique where a single vertex object is uploaded once, and transformation matrices are uploaded in a buffer, allowing efficient drawing of many static objects with the same geometry [S4, unofficial]. Steps include assuming all voxels use the same geometry and are mostly static, uploading transformation matrices in a buffer, and uploading the vertex object once [S4, unofficial]. Compared to per-object rendering, instanced rendering avoids repeated matrix multiplications, inverses, uniform uploads, and texture state changes per frame, which are expensive operations [S4, unofficial].

## Operating characteristics
*   **Time Complexity:** Setup time is $O(V)$ to compute offsets and pack data, where $V$ is the number of voxels. Draw time is $O(1)$ draw call with instancing, but fragment shader cost is proportional to the number of visible voxels [S1, unofficial].
*   **Memory Complexity:** $O(V)$ for the instance buffer (5 floats per voxel) and $O(P)$ for the palette texture, where $P$ is the number of unique colors [S1, unofficial].
*   **Strengths:** Reduces CPU-GPU synchronization overhead by minimizing draw calls. Decouples geometry from instance data, allowing for dynamic updates of voxel positions or colors without regenerating mesh buffers [S4, unofficial].
*   **Limitations:** Requires a palette texture, which may limit color depth or require complex UV mapping for procedural colors. Back-face culling is still necessary to optimize performance [S1, unofficial].
*   **When to Use:** Ideal for rendering large, static or semi-static voxel worlds where memory bandwidth and draw call overhead are bottlenecks [S4, unofficial].
*   **When Not to Use:** When voxels require highly unique geometry per instance (not just color/position) or when dynamic per-voxel topology changes are frequent and complex [S2, unofficial].

## Background
This method was implemented in the VoxelRenderer Android application for rendering .vly voxel models using OpenGL ES 3.0 [S1, unofficial]. It builds on the general principles of instanced rendering, which avoids repeated matrix multiplications and uniform uploads per frame [S4, unofficial]. The use of palette textures for coloring is a common optimization in voxel rendering to reduce the size of instance data buffers [S1, unofficial].
