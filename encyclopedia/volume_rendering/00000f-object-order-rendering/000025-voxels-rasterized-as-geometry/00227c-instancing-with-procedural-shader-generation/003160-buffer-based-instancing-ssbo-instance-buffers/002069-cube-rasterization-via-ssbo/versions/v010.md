# Cube Rasterization via SSBO

Also called: GL_DRAW_ELEMENTS instancing, GPU Instancing, Voxel Instance Rendering, glDrawElementsInstanced Voxel Draw

## Overview
This method renders a set of voxels as instances of a base unit cube geometry using a single `glDrawElementsInstanced` draw call, where each instance is transformed by an offset and colored via a palette texture lookup [S1, S2, unofficial]. It rasterizes 3 faces of each cube per voxel to optimize for visibility, using a single large index buffer and a large SSBO containing voxel data [S2, unofficial]. It sets itself apart from point-sprite based voxel renderers by using explicit triangle geometry, which provides exact cube geometry and allows for explicit face culling logic within the vertex shader [S2, unofficial].

## How it works
### Inputs and Outputs
**Inputs:**
*   A list of voxel definitions (position and material/color data).
*   A base unit cube vertex buffer containing position and normal attributes.
*   A static index buffer defining 3 faces of a cube (6 triangles, 18 indices).
*   A camera view-projection matrix and world position.

**Outputs:**
*   Rasterized pixels representing the visible faces of the voxel cloud.

### Data Structures

**1. Base Geometry (VAO)**
The vertex buffer stores per-vertex data for the base cube.
*   **Stride:** `CubeGeometry.FLOATS_PER_VERTEX * 4` bytes.
*   **Layout:**
    *   `[0:3]` `aLocalPosition` (`vec3`, float): Local vertex coordinates.
    *   `[3:6]` `aNormal` (`vec3`, float): Vertex normal.
*   **Divisors:** Instance attributes have a divisor of 1; vertex attributes have a divisor of 0.

**2. Instance Buffer (SSBO)**
A `std430` (GLSL) or `StructuredBuffer` (HLSL) buffer bound at binding point 0. Each instance (voxel) is represented by a `uvec2` (8 bytes total).
*   **`data.x` (Packed Position):**
    *   Bits 0-10: X coordinate (11 bits).
    *   Bits 11-20: Y coordinate (10 bits).
    *   Bits 21-31: Z coordinate (11 bits).
*   **`data.y` (Packed Material):**
    *   Bits 0-15: ALBEDO (16 bits, R5G6B5 format).
    *   Bits 16-19: METAL (4 bits).
    *   Bits 20-23: ROUGH (4 bits).
    *   Bits 24-27: INTENSITY (4 bits).
    *   Bits 28-31: TYPE (4 bits).

**3. Index Buffer (EBO)**
A static buffer containing 18 indices per voxel instance.
*   **Total Indices:** `num_cube_indices = no_of_instances * 3 * 2 * 3` (3 faces, 2 triangles per face, 3 vertices per triangle).
*   **Generation:** The indices are generated at startup by replicating a base 18-index cube face definition with offset adjustments: `indices[i] = cube_indices[cube_local] + cube * num_cube_vertices`, where `num_cube_vertices = 8`.

### Numbered Steps

1.  **Initialization:**
    *   Create and bind the base cube VAO with vertex and normal attributes.
    *   Create and bind the static index buffer containing the 18 indices for 3 cube faces.
    *   Create and bind the SSBO, populating it with packed `uvec2` data for each voxel.
    *   Generate the palette texture from color indices if using the S1 approach (not required for S2's packed albedo).

2.  **Draw Call Setup:**
    *   Bind the VAO, EBO, and SSBO.
    *   Set vertex attribute divisors for instance attributes to 1.
    *   Issue `glDrawElementsInstanced` with:
        *   Primitive type: `GL_TRIANGLES`.
        *   Index count: `num_cube_indices`.
        *   Index type: `GL_UNSIGNED_SHORT` (or appropriate type for the index buffer).
        *   Instance count: Number of valid voxels.

3.  **Vertex Shader Execution (Per Vertex):**
    *   Determine the instance index from `gl_VertexID`:
        $$ \text{instance} = \text{gl\_VertexID} \gg 3 $$
        *(Note: This assumes 8 vertices per instance are addressed, though only 3 faces are drawn via the index buffer. The source uses `gl_VertexID` directly to derive face orientation and instance data.)*
    *   Fetch the instance data `uvec2 data` from the SSBO at `instance`.
    *   Unpack position and albedo using bitmasks.
    *   Compute world position from the packed coordinates.
    *   Determine cube face orientation based on camera position:
        *   Compute local camera position: `local_camera_pos = camera_origin - world_position`.
        *   Determine vertex face index `xyz` from `gl_VertexID` bits:
            $$ x = \text{gl\_VertexID} \ \& \ 1 $$
            $$ y = (\text{gl\_VertexID} \ \& \ 2) \gg 1 $$
            $$ z = (\text{gl\_VertexID} \ \& \ 4) \gg 2 $$
        *   Flip components based on the sign of `local_camera_pos` to ensure correct face culling/orientation:
            ```glsl
            if (local_camera_pos.x > 0.0) xyz.x = 1 - xyz.x;
            if (local_camera_pos.y > 0.0) xyz.y = 1 - xyz.y;
            if (local_camera_pos.z > 0.0) xyz.z = 1 - xyz.z;
            ```
    *   Transform the local cube vertex:
        $$ \text{local\_pos} = \text{uvw} \times 2.0 - 1.0 $$
        $$ \text{world\_pos} = \text{view\_projection\_matrix} \times (\text{local\_pos} \times 0.05 + \text{world\_position}) $$
    *   Set `gl_Position` and output color.

### Formulas

**Position Unpacking (S2):**
*   X: `data.x & 0x7FF` (11 bits)
*   Y: `(data.x >> 11) & 0x3FF` (10 bits)
*   Z: `(data.x >> 21) & 0x7FF` (11 bits)

**Albedo Unpacking (S2):**
*   Red: `(data.y & 0x1F) / 32.0` (5 bits)
*   Green: `((data.y >> 5) & 0x3F) / 64.0` (6 bits)
*   Blue: `((data.y >> 11) & 0x1F) / 32.0` (5 bits)

**Camera Distance (S1):**
*   `distance = cameraDistance / zoomFactor`
*   `eyeZ = modelCenter[2] + distance * 0.4f + distance`

**FPS Calculation (S1):**
*   `fps = fpsFrameCount / (elapsed / 1_000_000_000f)` (elapsed in nanoseconds)

### Parameters

*   **`ROTATION_SENSITIVITY`**: 0.4f (degrees per pixel of drag) [S1, unofficial].
*   **`MIN_ZOOM`**: 0.3f [S1, unofficial].
*   **`MAX_ZOOM`**: 3.0f [S1, unofficial].
*   **`cameraDistance`**: 5f (base camera distance from model center) [S1, unofficial].
*   **`AMBIENT_INTENSITY`**: 0.35f [S1, unofficial].
*   **`SPECULAR_INTENSITY`**: 0.5f [S1, unofficial].
*   **`SHININESS`**: 32f [S1, unofficial].
*   **`LIGHT_POS_WORLD`**: `{10f, 15f, 10f}` [S1, unofficial].
*   **`FPS_UPDATE_INTERVAL_NANOS`**: 500,000,000 nanoseconds (0.5 seconds) [S1, unofficial].

### Edge Cases and Pitfalls

*   **VAO Availability:** VAOs are not universally available via pure GLES 3.0 on Android; explicit VBO/EBO binding may be required every frame, though overhead is negligible due to the single draw call [S1, unofficial].
*   **Zoom Clamping:** The zoom factor must be clamped to `[MIN_ZOOM, MAX_ZOOM]` to prevent extreme scaling artifacts [S1, unofficial].
*   **Rotation Direction:** Rotation direction depends on drag direction across screen halves (right/left), handled naturally by the sign of `dx` [S1, unofficial].
*   **Cache Efficiency:** Dynamic indexing into the SSBO using `gl_InstanceID` (or derived from `gl_VertexID`) prevents the driver from pre-fetching or inlining data, impacting cache efficiency compared to standard instancing [S1, S2, S4, unofficial].

### Pseudocode

```python
# Vertex Shader Logic (GLSL-like)

# Constants
NUM_CUBE_VERTICES = 8
NUM_INDICES_PER_FACE = 3
NUM_FACES = 3
TOTAL_INDICES_PER_INSTANCE = NUM_INDICES_PER_FACE * NUM_FACES # 18

# SSBO Layout
struct VoxelData {
    uvec2 data; // x: position, y: material
};
layout(std430, binding = 0) buffer VoxelBuffer {
    VoxelData voxels[];
};

uniform mat4 view_projection_matrix;
uniform vec3 camera_origin;

in uint gl_VertexID;
out vec3 color;
out vec3 clip_pos;
out vec3 world_pos;

void main() {
    // 1. Determine instance index
    // Note: Source uses gl_VertexID >> 3. This implies 8 vertices per instance
    // are logically addressed, even if only 18 indices are drawn.
    uint instance_id = gl_VertexID >> uint(3);
    
    // 2. Fetch instance data
    VoxelData voxel = voxels[instance_id];
    
    // 3. Unpack position
    uint pos_x = voxel.data.x & 0x7FF;
    uint pos_y = (voxel.data.x >> uint(11)) & 0x3FF;
    uint pos_z = (voxel.data.x >> uint(21)) & 0x7FF;
    vec3 world_position = vec3(float(pos_x), float(pos_y), float(pos_z));
    
    // 4. Unpack albedo (R5G6B5)
    uint u_albedo = voxel.data.y & 0xFFFF;
    uint u_red = (u_albedo & uint(31));
    uint u_green = (u_albedo & uint(2016)) >> uint(5);
    uint u_blue = (u_albedo & uint(63488)) >> uint(11);
    color = vec3(float(u_red) / 32.0, float(u_green) / 64.0, float(u_blue) / 32.0);
    
    // 5. Determine face orientation
    vec3 local_camera_pos = camera_origin - world_position;
    uint xyz_x = gl_VertexID & uint(1);
    uint xyz_y = (gl_VertexID & uint(2)) >> uint(1);
    uint xyz_z = (gl_VertexID & uint(4)) >> uint(2);
    
    if (local_camera_pos.x > 0.0) xyz_x = 1 - xyz_x;
    if (local_camera_pos.y > 0.0) xyz_y = 1 - xyz_y;
    if (local_camera_pos.z > 0.0) xyz_z = 1 - xyz_z;
    
    vec3 uvw = vec3(float(xyz_x), float(xyz_y), float(xyz_z));
    
    // 6. Transform vertex
    // Base cube is unit size, scaled by 0.05
    vec4 position = vec4(uvw * vec3(2.0) - vec3(1.0), 1.0);
    position = view_projection_matrix * vec4(position.xyz * 0.05 + world_position, 1.0);
    
    clip_pos = position.xyz;
    world_pos = world_position;
    gl_Position = position;
}
```

## Subtopics

### Procedural Instancing for Voxel Blocks
Renders voxel blocks as procedural geometry without explicit instance buffers, using shader-based generation. Choose when memory bandwidth for instance buffers is a bottleneck. [Link](1637-procedural-instancing-for-voxel-blocks.md)

### Instanced Voxel Renderer
Uses hardware instancing with point sprites and ray-box intersection in the fragment shader. Choose for simpler geometry setup but potentially lower precision in face culling. [Link](4102-instanced-voxel-renderer.md)

### Hardware Instancing (Instance ID Lookup)
Uses standard `gl_InstanceID` to fetch instance attributes from a separate buffer. Choose for better cache locality if instance data fits in cache. [Link](11005-hardware-instancing-instance-id-lookup.md)

### Per-Instance Attribute Buffering
Stores instance attributes in a separate buffer with explicit strides. Choose when instance data is large and complex. [Link](12563-per-instance-attribute-buffering.md)

## Operating characteristics
*   **Time Complexity:** $O(1)$ draw call overhead plus $O(N)$ vertex processing for $N$ instances [S1, unofficial].
*   **Memory Complexity:** Requires an index buffer of size $18 \times N$ indices and an SSBO of size $8 \times N$ bytes [S2, unofficial].
*   **Performance:** On dedicated graphics cards, `MODE_CUBE` is approximately twice as slow as `MODE_QUAD` (point sprite based). On Intel Integrated graphics, performance is similar [S2, unofficial].
*   **Strengths:** Exact cube geometry, explicit face culling logic, single draw call.
*   **Limitations:** Higher memory bandwidth usage due to index buffer and SSBO. Dynamic SSBO lookup reduces cache efficiency. Slower on dedicated GPUs compared to point-sprite methods.
*   **When to Use:** When exact cube geometry is required and face culling must be handled in the vertex shader. Suitable for integrated graphics where point-sprite performance is comparable.
*   **When Not to Use:** When maximum performance on dedicated GPUs is critical and point-sprite methods are acceptable.

## Background
This method was implemented in Android OpenGL ES 3.0 voxel visualization via the `VoxelRenderer` class [S1, unofficial]. It is also described in a GitHub repository `clayjohn/voxel-renderer` as `MODE_CUBE`, referencing Sebastian Aaltonen's technique for rasterizing 3 cube faces per voxel [S2, unofficial]. The technique relies on a single large index buffer and a large SSBO for voxel data.
