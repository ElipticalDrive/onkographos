# Cube Rasterization via SSBO

Also called: Voxel Instance Rendering, glDrawElementsInstanced Voxel Draw

## Overview
Renders $N$ voxels as instances of a base unit cube geometry using a single draw call, where each instance is transformed by an offset and colored via a palette texture lookup [S1, unofficial]. It rasterizes 3 faces of each cube per voxel to optimize fill rate, using a single large index buffer (18 indices per instance) and a large SSBO containing voxel data (1 `uvec2` per voxel) [S2, unofficial]. Unlike point-sprite or ray-traced voxel methods, it uses explicit triangle geometry for exact cube shapes and deterministic face culling based on camera orientation [S2, unofficial].

## How it works
**Inputs:**
- A list of $N$ voxels, each defined by integer grid coordinates $(x, y, z)$ and material properties (albedo, metalness, roughness, intensity, type) [S1, unofficial][S2, unofficial].
- A palette texture mapping color indices to RGB values [S1, unofficial].
- Camera position and view-projection matrix [S2, unofficial].

**Outputs:**
- Rasterized image of $N$ visible cube faces [S2, unofficial].

**Data Structures:**

1.  **Index Buffer (EBO):**
    -   Size: $N \times 18$ indices.
    -   Content: Defines 3 faces of a cube (6 triangles, 18 indices). Indices are local to the cube vertex buffer (0-7). For instance $i$, indices are offset by $i \times 8$ [S2, unofficial].
    -   Format: `GL_UNSIGNED_SHORT` or `GL_UNSIGNED_INT` [S1, unofficial][S2, unofficial].

2.  **Shader Storage Buffer Object (SSBO):**
    -   Binding: Binding point 0 [S2, unofficial].
    -   Layout: Array of `uvec2`, one per voxel.
    -   `data.x` (packed position):
        -   X: 11 bits
        -   Y: 10 bits
        -   Z: 11 bits
        -   Total: 32 bits [S2, unofficial].
    -   `data.y` (packed material):
        -   ALBEDO: 16 bits (R5G6B5 format)
        -   METAL: 4 bits
        -   ROUGH: 4 bits
        -   INTENSITY: 4 bits
        -   TYPE: 4 bits
        -   Total: 32 bits [S2, unofficial].

3.  **Vertex Buffer (VBO):**
    -   Stride: 24 bytes (6 floats).
    -   Layout:
        -   `[0:3]` `aLocalPosition` (`vec3`, float): Local cube vertex position.
        -   `[3:6]` `aNormal` (`vec3`, float): Local cube normal [S1, unofficial].

**Numbered Steps:**

1.  **Initialization:**
    -   Create and bind a static index buffer containing 18 indices per voxel instance [S2, unofficial].
    -   Populate the SSBO with voxel data, packing position and material properties into `uvec2` arrays [S2, unofficial].
    -   Create a palette texture from color indices [S1, unofficial].

2.  **Draw Call:**
    -   Bind the VAO containing cube vertex/normal attributes and instance offset/UV attributes [S1, unofficial].
    -   Set vertex attribute divisors for instance attributes to 1 [S1, unofficial].
    -   Bind the element buffer [S1, unofficial].
    -   Call `glDrawElementsInstanced` with `GL_TRIANGLES`, index count ($N \times 18$), `GL_UNSIGNED_SHORT` (or `GL_UNSIGNED_INT`), offset 0, and `instanceCount` $N$ [S1, unofficial].

3.  **Vertex Shader Processing:**
    -   Determine instance index from `gl_VertexID`: `instance = gl_VertexID >> 3` [S2, unofficial].
    -   Fetch voxel data from SSBO using `instance` [S2, unofficial].
    -   Unpack position and albedo using bitmasks [S2, unofficial].
    -   Compute world position from unpacked coordinates [S2, unofficial].
    -   Determine cube face orientation based on camera position relative to voxel:
        -   Compute `local_camera_pos = camera_origin - world_position` [S2, unofficial].
        -   Flip `xyz` components based on the sign of `local_camera_pos` to ensure correct face culling/orientation [S2, unofficial].
    -   Transform local cube vertex:
        -   `uvw = vec3(xyz)` where `xyz` is derived from `gl_VertexID` bits [S2, unofficial].
        -   `position = uvw * 2.0 - 1.0` [S2, unofficial].
        -   Scale by 0.05 and add `world_position` [S2, unofficial].
        -   Apply `view_projection_matrix` [S2, unofficial].
    -   Set `gl_Position` and output color [S2, unofficial].

**Parameters:**
-   `num_cube_indices`: Total indices for all instances, calculated as $N \times 3 \times 2 \times 3$ (3 faces, 2 tris/face, 3 verts/tri) [S2, unofficial].
-   `MIN_ZOOM` and `MAX_ZOOM`: Clamping the zoom factor to the range $[0.3f, 3.0f]$ [S1, unofficial].
-   `ROTATION_SENSITIVITY`: 0.4f [S1, unofficial].
-   `AMBIENT_INTENSITY`: 0.35f [S1, unofficial].
-   `SPECULAR_INTENSITY`: 0.5f [S1, unofficial].
-   `SHININESS`: 32f [S1, unofficial].
-   `LIGHT_POS_WORLD`: `{10f, 15f, 10f}` [S1, unofficial].
-   `cameraDistance`: 5f [S1, unofficial].
-   `FPS_UPDATE_INTERVAL_NANOS`: 500,000,000 nanoseconds [S1, unofficial].

**Edge Cases and Pitfalls:**
-   VAOs are not universally available via pure GLES30 on Android; explicit VBO/EBO binding is performed every frame, though overhead is negligible due to the single draw call [S1, unofficial].
-   Zoom factor is clamped to $[MIN\_ZOOM, MAX\_ZOOM]$ to prevent extreme scaling artifacts [S1, unofficial].
-   Rotation direction depends on drag direction across screen halves (right/left), handled naturally by the sign of dx [S1, unofficial].
-   Precision issues may arise from bit-packing large coordinates into 32-bit integers [S2, unofficial].

## Operating characteristics
-   **Time Complexity:** $O(1)$ draw call overhead plus $O(N)$ vertex processing for $N$ instances [S1, unofficial].
-   **Memory Complexity:** $O(N)$ for SSBO and index buffer [S2, unofficial].
-   **Performance:** Slower than `MODE_QUAD` on dedicated graphics cards, but performs similarly on Intel Integrated graphics [S2, unofficial].
-   **Strengths:** Exact cube geometry, explicit face culling logic, single draw call [S2, unofficial].
-   **Limitations:** Higher memory bandwidth usage due to index buffer and instance buffer [S2, unofficial].
-   **When to Use:** When exact cube geometry is required and face culling is important [S2, unofficial].
-   **When Not to Use:** When fill rate is the bottleneck and point sprites or ray-traced methods are viable [S2, unofficial].
