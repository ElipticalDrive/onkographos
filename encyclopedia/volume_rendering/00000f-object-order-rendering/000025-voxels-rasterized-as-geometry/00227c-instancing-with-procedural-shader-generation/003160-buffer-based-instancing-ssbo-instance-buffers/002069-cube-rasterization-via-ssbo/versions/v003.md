# Cube Rasterization via SSBO
Also called: GL_DRAW_ELEMENTS instancing, Instanced voxel rendering, Voxel Instance Rendering

## Overview
Cube Rasterization via SSBO is a voxel rendering technique that explicitly rasterizes the visible geometry of each voxel as a set of triangles, rather than using point sprites or ray-marching [S1, unofficial]. It solves the problem of rendering large voxel fields with correct lighting and shading by generating explicit cube faces in the vertex shader, selected based on the camera's relative position to each voxel [S1, unofficial]. It differs from [Procedural Instancing for Voxel Blocks](1637-procedural-instancing-for-voxel-blocks.md) by using a single large index buffer and SSBO for explicit triangle generation, and from [Instanced Voxel Renderer](4102-instanced-voxel-renderer.md) by its specific face-culling logic and 3-face-per-voxel output [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A dense voxel grid stored in a `GL_SHADER_STORAGE_BUFFER` (SSBO). Camera position and View-Projection matrix.
- **Output:** Rasterized triangles representing the visible faces of occupied voxels.

**Data Structures:**
1.  **SSBO (Instance Data):** Bound at binding point 0. Contains one `uvec2` per voxel.
    -   `data.x`: Packed position.
        -   Bits 0-10: X coordinate (11 bits).
        -   Bits 11-20: Y coordinate (10 bits).
        -   Bits 21-31: Z coordinate (11 bits).
    -   `data.y`: Packed material properties.
        -   Bits 0-15: ALBEDO (16 bits, R5G6B5 format).
        -   Bits 16-19: METAL (4 bits).
        -   Bits 20-23: ROUGH (4 bits).
        -   Bits 24-27: INTENSITY (4 bits).
        -   Bits 28-31: TYPE (4 bits).
2.  **Index Buffer:** A static buffer containing 18 indices per voxel instance, defining 3 faces of a cube (6 triangles, 3 vertices per triangle) [S1, unofficial].

**Numbered Steps:**
1.  **Initialization:** Create and bind a single large index buffer containing 18 indices per voxel instance at startup [S1, unofficial].
2.  **Instance Count:** Determine the total number of instances (`no_of_instances`) based on the voxel grid size [S1, unofficial].
3.  **Draw Call:** Issue a draw call using `GL_DRAW_ELEMENTS` instancing. The total number of indices is `num_cube_indices = no_of_instances * 18` [S1, unofficial].
4.  **Vertex Shader Execution:** For each vertex generated by the index buffer:
    a.  Calculate the instance index from `gl_VertexID`: `instance = gl_VertexID >> 3` [S1, unofficial].
    b.  Unpack voxel position and material data from the SSBO using bitmasks [S1, unofficial].
    c.  Compute the world position of the voxel center from the packed coordinates [S1, unofficial].
    d.  Determine the local camera position: `local_camera_pos = camera_origin - world_position` [S1, unofficial].
    e.  Determine the cube face orientation based on the sign of `local_camera_pos` components to ensure correct face culling [S1, unofficial].
    f.  Transform the local cube vertex coordinates, scale by voxel size (0.05), add world position, and apply the view-projection matrix [S1, unofficial].

**Formulas:**
-   **Instance Index:**
    $$
    I_{instance} = \lfloor \frac{I_{vertex}}{8} \rfloor
    $$
    Where $I_{vertex}$ is `gl_VertexID` and 8 is the number of vertices per cube face set (though only 3 faces are drawn, the indexing logic maps to 8 vertices per instance in the source logic) [S1, unofficial].
-   **World Position Unpacking:**
    $$
    P_{world} = \text{unpack\_position}(data[I_{instance}].x)
    $$
    Where `unpack_position` extracts the 11/10/11 bit fields and converts them to world coordinates [S1, unofficial].
-   **Face Orientation:**
    $$
    V_{xyz} = \begin{cases} 
    1 - V_{xyz} & \text{if } L_{camera} > 0 \\
    V_{xyz} & \text{otherwise}
    \end{cases}
    $$
    Where $V_{xyz}$ is the vertex component (0 or 1) and $L_{camera}$ is the corresponding component of `local_camera_pos` [S1, unofficial].
-   **Clip Space Position:**
    $$
    P_{clip} = M_{vp} \times (P_{world} + (2 \cdot V_{uvw} - 1) \cdot S_{voxel})
    $$
    Where $M_{vp}$ is the view-projection matrix, $V_{uvw}$ is the unpacked vertex coordinate (0 or 1), and $S_{voxel}$ is 0.05 [S1, unofficial].

**Parameters:**
-   `num_cube_indices`: Total indices for all instances, calculated as `no_of_instances * 3 * 2 * 3` (3 faces, 2 triangles/face, 3 vertices/triangle) [S1, unofficial].
-   Voxel Size: 0.05 (used in vertex shader) [S1, unofficial].

**Edge Cases and Pitfalls:**
-   **Precision:** The packed position uses 11/10/11 bits, limiting spatial resolution. Ensure the voxel grid dimensions fit within these bit limits [S1, unofficial].
-   **Face Culling:** The face selection logic relies on the sign of the camera offset. If the camera is exactly aligned with a voxel face, the logic may produce artifacts. [G] In practice, this is rare and often handled by the rasterizer's depth buffer.
-   **Memory Bandwidth:** This method requires an index buffer and instance buffer, increasing memory bandwidth compared to point-sprite methods [S1, unofficial].

**Pseudocode:**
```python
# Vertex Shader Logic (GLSL-like)

# 1. Get instance index
instance_id = gl_VertexID >> 3

# 2. Unpack voxel data from SSBO
voxel_data = ssbo_voxels[instance_id]
packed_pos = voxel_data.x
packed_mat = voxel_data.y

# Unpack position (X:11, Y:10, Z:11)
x = packed_pos & 0x7FF
y = (packed_pos >> 11) & 0x3FF
z = (packed_pos >> 21) & 0x7FF
world_position = vec3(float(x), float(y), float(z)) * 0.05 # Assuming unit voxel size scaling

# Unpack albedo (R5G6B5)
albedo_raw = packed_mat & 0xFFFF
r = (albedo_raw & 0x1F) / 32.0
g = ((albedo_raw >> 5) & 0x3F) / 64.0
b = ((albedo_raw >> 11) & 0x1F) / 32.0
color = vec3(r, g, b)

# 3. Determine face orientation
local_camera_pos = camera_origin - world_position
vertex_id_in_cube = gl_VertexID & 0x7 # 0-7
xyz = uvec3(vertex_id_in_cube & 0x1, (vertex_id_in_cube & 0x2) >> 1, (vertex_id_in_cube & 0x4) >> 2)

if local_camera_pos.x > 0.0:
    xyz.x = 1 - xyz.x
if local_camera_pos.y > 0.0:
    xyz.y = 1 - xyz.y
if local_camera_pos.z > 0.0:
    xyz.z = 1 - xyz.z

uvw = vec3(xyz)

# 4. Transform and output
local_vertex = uvw * 2.0 - 1.0
position = view_projection_matrix * vec4(local_vertex * 0.05 + world_position, 1.0)
gl_Position = position
```

## Subtopics

### [Procedural Instancing for Voxel Blocks](1637-procedural-instancing-for-voxel-blocks.md)
Generates geometry procedurally per block, reducing index buffer size but increasing vertex shader complexity. Choose when memory bandwidth is a bottleneck.

Uses a different instancing strategy, potentially with different culling or geometry generation. Choose based on specific hardware performance characteristics.

## Operating characteristics
-   **Time Complexity:** $O(N)$ where $N$ is the number of occupied voxels. Each voxel generates a constant number of triangles (18 indices).
-   **Memory Complexity:** $O(N)$ for the SSBO and index buffer. The index buffer size is fixed per instance (18 indices).
-   **Measured Performance:** On Intel Integrated graphics, `MODE_CUBE` performs similarly to `MODE_QUAD`. On dedicated graphics cards, `MODE_QUAD` is approximately twice as fast as `MODE_CUBE` [S1, unofficial].
-   **Strengths:** Provides exact cube geometry, allows for explicit face culling logic, and supports standard rasterization techniques for lighting and shading.
-   **Limitations:** Higher memory bandwidth usage due to explicit triangle generation. Slower on dedicated GPUs compared to quad-based methods.
-   **When to Use:** When explicit geometry is required for advanced shading or when targeting integrated graphics where performance is comparable to other methods.
-   **When Not to Use:** When maximum performance on dedicated GPUs is critical and simple face rendering is sufficient.

## Background
This method was described by Sebastian Aaltonen in a tweet and implemented in the `voxel-renderer` project by Clay John [S1, unofficial]. It represents an approach to voxel rendering that leverages explicit geometry generation within the graphics pipeline, contrasting with ray-marching or point-sprite based techniques.
