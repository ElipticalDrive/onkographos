# Cube Rasterization via SSBO

Also called: Voxel Instance Rendering, glDrawElementsInstanced Voxel Draw

## Overview
This method renders $N$ voxels as instances of a base unit cube geometry using a single `glDrawElementsInstanced` draw call, where each instance is transformed by an offset fetched from a Shader Storage Buffer Object (SSBO) and colored via a palette texture lookup [S1, unofficial]. It rasterizes only the 3 visible faces of each cube per voxel to optimize fill rate, using a single large index buffer (18 indices per instance) and a large SSBO containing voxel data (1 `uvec2` per voxel) [S2, unofficial]. It is distinguished from point-sprite based voxel rendering (e.g., [Procedural Instancing for Voxel Blocks](1637-procedural-instancing-for-voxel-blocks.md)) by using explicit triangle geometry for exact cube shapes and explicit face culling logic, and from hardware instancing (e.g., [Hardware Instancing (Instance ID Lookup)](11005-hardware-instancing-instance-id-lookup.md)) by deriving instance identification from `gl_VertexID` bitmasks rather than relying solely on `gl_InstanceID` for data lookup [S2, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A list of $N$ voxels, each defined by a packed position and material properties.
- **Output:** A rasterized image of $N$ visible cube faces.

**Data Structures:**

1.  **Index Buffer (EBO):** A static buffer containing 18 indices per voxel instance. The indices define 3 faces of a cube (6 triangles, 18 indices). The indices are pre-computed to offset local vertex indices by `cube * num_cube_vertices` where `num_cube_vertices = 8` [S2, unofficial].
    -   Total indices: `num_cube_indices = no_of_instances * 3 * 2 * 3` [S2, unofficial].
2.  **Instance Data Buffer (SSBO):** A `GL_SHADER_STORAGE_BUFFER` bound at binding point 0. Each instance contains a `uvec2 data[]` array [S2, unofficial].
    -   `data.x`: Packs position. Bits layout: X (11 bits), Y (10 bits), Z (11 bits).
    -   `data.y`: Packs material properties. Bits layout: ALBEDO (16 bits, R5G6B5), METAL (4 bits), ROUGH (4 bits), INTENSITY (4 bits), TYPE (4 bits).
3.  **Vertex Buffer (VBO):** Defines the base unit cube geometry.
    -   Stride: `CubeGeometry.FLOATS_PER_VERTEX * 4` bytes.
    -   Layout: `[0:3] aLocalPosition (vec3, float)`, `[3:6] aNormal (vec3, float)` [S1, unofficial].
4.  **Instance Attributes (VAO):**
    -   Stride: 5 floats (20 bytes).
    -   Layout: `[0:3] aInstanceOffset (vec3, float)`, `[3:5] aInstanceUV (vec2, float)`.
    -   Divisor: 1 for instance attributes [S1, unofficial].

**Numbered Steps:**

1.  **Initialization:**
    -   Create and bind a single large index buffer containing 18 indices per voxel instance at startup [S2, unofficial].
    -   Store voxel data in the SSBO using the `uvec2` packing scheme described above [S2, unofficial].
    -   Create the VAO with the cube vertex/normal attributes and instance offset/UV attributes. Set vertex attribute divisors for instance attributes to 1 [S1, unofficial].

2.  **Draw Call:**
    -   Bind the VAO and the element buffer.
    -   Call `glDrawElementsInstanced` with `GL_TRIANGLES`, the total index count (`num_cube_indices`), `GL_UNSIGNED_SHORT`, offset 0, and `instanceCount` ($N$) [S1, unofficial].

3.  **Vertex Shader Processing:**
    -   **Instance Identification:** Determine the instance index from `gl_VertexID`:
        $$ \text{instance} = \text{gl\_VertexID} \gg 3 $$
        [S2, unofficial]
    -   **Data Lookup:** Use the instance index to fetch the `uvec2` data from the SSBO.
    -   **Position Unpacking:** Extract X, Y, Z coordinates from `data.x` using bitmasks (X: 11 bits, Y: 10 bits, Z: 11 bits) [S2, unofficial].
    -   **Material Unpacking:** Extract ALBEDO from `data.y` (R5G6B5 format). Convert to normalized float:
        $$ u\_red = (u\_albedo \ \& \ 0x1F) \gg 0 $$
        $$ u\_green = (u\_albedo \ \& \ 0x7E0) \gg 5 $$
        $$ u\_blue = (u\_albedo \ \& \ 0xF800) \gg 11 $$
        $$ \text{albedo} = \text{vec3}\left(\frac{u\_red}{32.0}, \frac{u\_green}{64.0}, \frac{u\_blue}{32.0}\right) $$
        [S2, unofficial]
    -   **Face Culling/Orientation:** Compute local camera position:
        $$ \text{local\_camera\_pos} = \text{camera\_origin} - \text{world\_position} $$
        Determine cube face orientation based on the sign of `local_camera_pos`. Flip XYZ components of the local vertex index to ensure correct face culling:
        ```glsl
        uvec3 xyz = uvec3(gl_VertexID & 0x1, (gl_VertexID & 0x2) >> 1, (gl_VertexID & 0x4) >> 2);
        if (local_camera_pos.x > 0.0) xyz.x = 1 - xyz.x;
        if (local_camera_pos.y > 0.0) xyz.y = 1 - xyz.y;
        if (local_camera_pos.z > 0.0) xyz.z = 1 - xyz.z;
        ```
        [S2, unofficial]
    -   **Transformation:** Transform the local cube vertex. The base vertex is mapped from `[0,1]` to `[-1,1]` and scaled by 0.05 (voxel size):
        $$ \text{uvw} = \text{vec3}(xyz) $$
        $$ \text{position} = \text{view\_projection\_matrix} \times \text{vec4}(\text{uvw} \times \text{vec3}(2.0) - \text{vec3}(1.0) \times 0.05 + \text{world\_position}, 1.0) $$
        Set `gl_Position` and output color [S2, unofficial].

**Parameters:**
-   `num_cube_indices`: Total indices for all instances, calculated as `no_of_instances * 3 * 2 * 3` [S2, unofficial].
-   `MIN_ZOOM` and `MAX_ZOOM`: Clamping constants for zoom factor, typically `[0.3f, 3.0f]` [S1, unofficial].
-   `ROTATION_SENSITIVITY`: Rotation degrees per pixel of drag, typically `0.4f` [S1, unofficial].
-   Lighting constants: `AMBIENT_INTENSITY` (0.35f), `SPECULAR_INTENSITY` (0.5f), `SHININESS` (32f) [S1, unofficial].
-   `LIGHT_POS_WORLD`: World-space light position, typically `{10f, 15f, 10f}` [S1, unofficial].
-   `cameraDistance`: Base camera distance from model center, typically `5f` [S1, unofficial].

**Edge Cases and Pitfalls:**
-   **VAO Availability:** VAOs are not universally available via pure GLES30 on Android; explicit VBO/EBO binding may be required every frame, though overhead is negligible due to the single draw call [S1, unofficial].
-   **Zoom Artifacts:** Zoom factor must be clamped to `[MIN_ZOOM, MAX_ZOOM]` to prevent extreme scaling artifacts [S1, unofficial].
-   **Rotation Direction:** Rotation direction depends on drag direction across screen halves (right/left), handled naturally by the sign of `dx` [S1, unofficial].
-   **Precision:** Bit-packing positions into `uvec2` limits coordinate precision. Ensure the bit allocation (11/10/11) covers the required world space range [S2, unofficial].

## Operating characteristics
-   **Time Complexity:** $O(1)$ draw call overhead plus $O(N)$ vertex processing for $N$ instances [S1, unofficial].
-   **Memory Complexity:** Requires storage for the index buffer ($18 \times N$ indices) and the SSBO ($2 \times N$ `uvec2`s) [S2, unofficial].
-   **Performance:** On Intel Integrated graphics, MODE_CUBE performs similarly to MODE_QUAD. On dedicated graphics cards, MODE_QUAD is approximately twice as fast as MODE_CUBE [S2, unofficial].
-   **Strengths:** Provides exact cube geometry and explicit face culling logic, reducing overdraw compared to rendering all 6 faces. Single draw call minimizes CPU overhead.
-   **Limitations:** Slower on dedicated GPUs compared to point-sprite methods. Requires careful bit-packing for position data.
-   **When to Use:** When exact cube geometry is required and face culling is beneficial, or on hardware where draw call overhead is significant.
-   **When Not to Use:** When maximum fill-rate performance is critical on dedicated GPUs and approximate cube shapes are acceptable.

## Background
This method was implemented in Android OpenGL ES 3.0 voxel visualization via the `VoxelRenderer` class [S1, unofficial]. The specific face-culling strategy (rasterizing 3 faces per voxel) is attributed to Sebastian Aaltonen [S2, unofficial]. It is part of a broader exploration of high-performance voxel rendering techniques, including comparisons with point-sprite based methods [S2, unofficial].
