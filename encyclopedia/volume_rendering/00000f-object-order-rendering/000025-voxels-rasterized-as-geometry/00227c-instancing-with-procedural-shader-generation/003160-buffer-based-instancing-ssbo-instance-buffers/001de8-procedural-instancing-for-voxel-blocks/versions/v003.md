# Procedural Instancing for Voxel Blocks

Also called: Cubic Grid Voxel Rendering with Instance Buffers, Feature/center instancing, GalensUnified Cubic Grid Renderer, Procedural Instancing, center instancing, voxel object generator

## Overview
Procedural Instancing for Voxel Blocks is a rendering technique that replaces baked mesh geometry with a compact instance record per voxel, resolving position, color, and occlusion in the vertex shader using a shared cube template [S1, S3, unofficial]. It differs from standard instancing by computing transformations, visibility culling, and texture selection procedurally within the shader based on a dense, bit-packed instance buffer, allowing for significant memory reduction and cache efficiency compared to pre-baked geometries [S1, S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A list of occupied voxel coordinates and their properties (texture index, tint, orientation).
*   **Output:** Rasterized fragments representing the visible faces of the voxel blocks.

**Data Structures:**
The method relies on two primary buffers and one uniform structure.

1.  **Instance Buffer (SSBO/StructuredBuffer):** Stores per-voxel data.
    *   *Layout A (Compact, S1):* 6 bytes per occupied voxel.
        *   `grid_index`: Integer (flat grid index).
        *   `face_mask`: 6-bit uint8 (surviving-face mask).
        *   `orbit_byte`: uint8 (orbit/hue data).
    *   *Layout B (Detailed, S3):* 32 bytes per instance (`ShapeInstance` struct, `std430` alignment).
        *   `posX`, `posY`, `posZ`: `float` (4 bytes each, total 12 bytes).
        *   `textureIndex`: `int` (4 bytes).
        *   `shapeRotation`: `uint` (4 bytes). Composed of two `ushort`s:
            *   Lower 16 bits (`& 0xFFFF`): `shape` index.
            *   Upper 16 bits (`>> 16`): `rotation` index (0-23).
        *   `tintR`, `tintG`, `tintB`: `float` (4 bytes each, total 12 bytes).
    *   *Layout C (Unity, S2):* `StructuredBuffer<float4> _Positions`.
        *   Each `float4` contains `x, y, z` (position) and `w` (clip parameter).

2.  **Vertex Buffer (Geometry):**
    *   A shared template of a unit cube.
    *   *Vertices:* 24 vertices (6 faces × 4 vertices).
    *   *Layout (S3):* `ShapeVertex` struct, 32 bytes per vertex.
        *   `position`: `vec3` (12 bytes).
        *   `_pad0`: `float` (4 bytes).
        *   `uv`: `vec2` (8 bytes).
        *   `_pad2`, `_pad1`: `float` (4 bytes each).

3.  **Uniforms (S3):**
    *   `view`: `mat4` (64 bytes).
    *   `projection`: `mat4` (64 bytes).
    *   `chunkPos`: `vec3` (12 bytes).
    *   `verticesPerShape`: `int` (4 bytes).

**Numbered Steps:**

1.  **Instance Generation:**
    *   For each occupied voxel, generate an instance record.
    *   If using Layout A (S1), calculate the 6-bit face mask based on neighbor occlusion.
    *   If using Layout B (S3), determine `shape` and `rotation` indices. `rotation` is calculated as `(int)up * 4 + forward` [S3, unofficial].

2.  **Buffer Upload:**
    *   Upload the instance records to the GPU SSBO/StructuredBuffer.
    *   Upload the shared 24-vertex cube template to the vertex buffer.

3.  **Vertex Shader Execution (Per Instance):**
    *   **Step 1: Index Calculation.**
        *   Calculate the vertex index within the shape's vertex buffer:
            $$ Index = gl\_VertexID + (shapeRotation \ \& \ 0xFFFF) \times verticesPerShape $$
            [S3, unofficial]
        *   Fetch the `ShapeVertex` using this index.
    *   **Step 2: Rotation Matrix Retrieval.**
        *   Retrieve the base rotation matrix from a precomputed array `_87` (or equivalent) using the upper 16 bits of `shapeRotation`:
            $$ RotationIndex = shapeRotation \ >> \ 16u $$
            [S3, unofficial]
        *   This matrix represents one of 24 possible orientations for the cube faces.
    *   **Step 3: Position Transformation.**
        *   Transform the local vertex position:
            $$ LocalPos = ShapeVertices[Index].position - vec3(0.5) $$
            $$ RotatedPos = RotationMatrix \times LocalPos $$
            $$ TranslatedPos = RotatedPos + vec3(0.5) $$
            $$ WorldPos = TranslatedPos + Instance.Position + ChunkPosition $$
            [S3, unofficial]
        *   *Alternative (Unity S2):* Construct a translation matrix `_Matrix` from the position `float4` and multiply the input vertex.
    *   **Step 4: Visibility Culling (Clip Distance).**
        *   Determine if the face is hidden.
        *   If hidden, move the vertex corners outside the clip volume (e.g., set clip distance to -1.0 or push vertices to infinity) [S1, S2, unofficial].
        *   *Note:* This submits whole cubes and discards hidden faces in the vertex shader, rather than not drawing them [S1, unofficial].
    *   **Step 5: Output Varyings.**
        *   Output UV coordinates from the vertex buffer.
        *   Output texture index and tint color from the instance buffer.
    *   **Step 6: Clip Space Conversion.**
        *   Convert `WorldPos` to homogeneous coordinates ($w=1.0$).
        *   Transform by View and Projection matrices:
            $$ ClipPos = Projection \times View \times float4(WorldPos, 1.0) $$
            [S3, unofficial]

4.  **Fragment Shader Execution:**
    *   Sample the texture using the texture index and UVs.
    *   Apply tint color.
    *   Apply clipping if `_Clip` value is set (Unity specific) [S2, unofficial].

5.  **Draw Call:**
    *   Issue a single draw call (e.g., `glDrawArraysInstanced` or `glDrawElementsInstanced`) with an instance count equal to the total number of potential instances [S1, S2, S3, unofficial].

**Pseudocode:**

```python
# Vertex Shader Logic (GLSL-like)

# Uniforms
uniform mat4 view;
uniform mat4 projection;
uniform vec3 chunkPos;
uniform int verticesPerShape;
uniform mat4 rotation_matrices[24]; # Precomputed _87 array

# Buffers
layout(std430) buffer ShapeInstancesBuffer {
    ShapeInstance instances[];
};

layout(std430) buffer ShapeVerticesBuffer {
    ShapeVertex vertices[];
};

struct ShapeInstance {
    float posX, posY, posZ;
    int textureIndex;
    uint shapeRotation; # Lower 16: shape, Upper 16: rotation
    float tintR, tintG, tintB;
};

struct ShapeVertex {
    vec3 position;
    vec2 uv;
    # Padding fields omitted for brevity
};

void main() {
    uint instanceID = gl_InstanceID;
    uint vertexID = gl_VertexID;
    
    # Fetch Instance Data
    ShapeInstance instance = instances[instanceID];
    
    # Step 1: Calculate Vertex Index
    uint shapeIndex = instance.shapeRotation & 0xFFFFu;
    uint rotationIndex = instance.shapeRotation >> 16u;
    uint vertexIndex = vertexID + shapeIndex * verticesPerShape;
    
    # Fetch Vertex Data
    ShapeVertex vert = vertices[vertexIndex];
    
    # Step 2 & 3: Transform Position
    vec3 localPos = vert.position - vec3(0.5);
    vec3 rotatedPos = rotation_matrices[rotationIndex] * vec4(localPos, 1.0).xyz;
    vec3 translatedPos = rotatedPos + vec3(0.5);
    vec3 worldPos = translatedPos + vec3(instance.posX, instance.posY, instance.posZ) + chunkPos;
    
    # Step 4: Visibility Culling
    # If face is hidden (determined by face mask or neighbor check), push outside clip volume
    # Simplified: Assume instance data includes a 'isHidden' flag or we check neighbors
    # Here we assume standard clip space transformation first
    vec4 clipPos = projection * view * vec4(worldPos, 1.0);
    
    # If hidden, move corners outside
    # Example: clipPos.xyz = vec3(1000.0); # Push to infinity
    
    # Step 5: Output Varyings
    gl_Position = clipPos;
    FragUV = vert.uv;
    FragTextureIndex = instance.textureIndex;
    FragTint = vec3(instance.tintR, instance.tintG, instance.tintB);
}
```

## Operating characteristics
*   **Memory Efficiency:** Significantly reduces memory usage compared to baked meshes. At resolution R=64, specimen memory reduced from 42.0 MB to 649 KB (19-65× smaller) [S1, unofficial]. Worker message size reduced from 42.3 MB to 457 KB (92× reduction) [S1, unofficial].
*   **Cache Capacity:** Increased cache capacity at R=64 from 6 specimens to about 394 specimens before exhausting `CACHE_BYTES` [S1, unofficial].
*   **Performance:** Geometry build speed is 1.9–4.6× faster than pre-branch core; whole build speed is 1.3–1.8× faster [S1, unofficial]. Maintains interactive frame rates of approximately 60 FPS at high voxel densities [S2, unofficial].
*   **Vertex Work Overhead:** Submits whole cubes and discards hidden faces in the vertex shader. For zero-gap layouts, this increases vertex work by 2.0× to 3.3× compared to culling faces before submission [S1, unofficial]. This is considered acceptable as it is vertex work only and no fragments are processed for hidden faces [S1, unofficial].
*   **Precision:** GPU f32 arithmetic drift is bounded to under 1e-7 of the unit box, which is less than half a step of an 8-bit channel, ensuring visual correctness [S1, unofficial]. Axis centre table is kept as `Float64Array` on CPU to prevent precision drift [S1, unofficial].

## Background
*   **Origin:** This method is used in the `block-showroom` project by lardratboy, specifically in `src/scene/instancing.js` and `lattice/recipe.js` [S1, unofficial]. It was implemented as part of a switch from baked mesh geometry to procedural instancing to improve memory efficiency and build speed [S1, unofficial].
*   **Development:** The technique was developed to replace derived wire/points/centres geometries and their byte accounting, allowing four render modes to become four indexings of the same instance attributes [S1, unofficial]. It eliminates the need for `THREE` imports in `lattice/recipe.js` [S1, unofficial].
*   **Usage:** Used in voxel rendering applications where memory footprint and build speed are critical, such as in block-based games or voxel editors [S1, S3, unofficial].
