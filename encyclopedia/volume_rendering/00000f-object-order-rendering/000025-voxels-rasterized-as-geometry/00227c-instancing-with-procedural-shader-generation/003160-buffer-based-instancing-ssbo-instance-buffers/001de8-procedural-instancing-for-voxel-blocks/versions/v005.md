# Procedural Instancing for Voxel Blocks

Also called: Cubic Grid Voxel Rendering with Instance Buffers, Procedural Instancing Voxel Rendering, Voxel Block Procedural Instancing

## Overview
Procedural instancing for voxel blocks replaces baked mesh geometry with a compact instance record per voxel, resolving position, color, and occlusion in the vertex shader using a shared cube template [S1, S2, S3, S4, unofficial]. It differs from standard hardware instancing by computing visibility flags and clip distances procedurally in the vertex stage, allowing for custom setup logic such as face culling without CPU-side mesh generation [S1, S3, S4, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A structured buffer (SSBO/StructuredBuffer) containing per-voxel instance data (position, solidity/visibility, texture index, rotation). A shared vertex buffer containing a base geometry (typically a 24-vertex unit cube or a set of shape vertices).
*   **Output:** Rasterized voxels. Non-solid voxels are clipped. Hidden faces of solid voxels are pushed outside the clip volume.

**Data Structures:**
The instance data layout varies by implementation but generally follows these patterns:

1.  **Compact Record (6 bytes):** Used in high-performance scenarios [S1, unofficial].
    *   Flat grid index (integer, size not specified, likely 32-bit).
    *   Six-bit surviving-face mask (`uint8`).
    *   Orbit byte (`uint8`).
    *   *Note:* This layout is significantly smaller than the 32-byte or 64-byte structures used in other variants.
2.  **Standard Struct (32 bytes):** Used in Unity and OpenGL implementations [S3, S4, S5, unofficial].
    *   **C# / GLSL `std430` layout [S5, unofficial]:**
        *   `posX`, `posY`, `posZ`: `float` (4 bytes each, offset 0, 4, 8).
        *   `textureIndex`: `int` (4 bytes, offset 12).
        *   `shapeRotation`: `uint` (4 bytes, offset 16). Packed: lower 16 bits = shape index, upper 16 bits = rotation index.
        *   `tintR`, `tintG`, `tintB`: `float` (4 bytes each, offset 20, 24, 28).
    *   **Unity `StructuredBuffer<Voxel>` [S4, unofficial]:**
        *   `position`: `float3`.
        *   `isSolid`: `float`.
    *   **Unity `StructuredBuffer<float4>` [S3, unofficial]:**
        *   `x, y, z`: Position components.
        *   `w`: Clip parameter.

**Numbered Steps:**

1.  **Instance Buffer Population:** The application builds an instance record for each occupied voxel. This replaces the generation of baked mesh geometry [S1, unofficial]. The record contains position, visibility, and rendering attributes [S5, unofficial].
2.  **Draw Call:** A single instanced draw call (e.g., `glDrawArraysInstanced`, `glDrawElementsInstanced`, or Unity's procedural instancing pragma) is issued with the instance count equal to the number of valid voxels [S1, S2, S4, unofficial].
3.  **Vertex Shader - Instance Fetch:** The vertex shader uses the instance ID (`gl_InstanceID`, `SV_InstanceID`, or `unity_InstanceID`) to fetch the instance record from the SSBO [S1, S2, S3, S4, S5, unofficial].
4.  **Vertex Shader - Transformation:**
    *   Calculate the local vertex position. If using a shared shape buffer, the vertex index is offset by the shape ID: `vertexIndex = gl_VertexID + (shapeRotation & 0xFFFF) * verticesPerShape` [S5, unofficial].
    *   Apply rotation if applicable. In some implementations, a precomputed rotation matrix is selected from a lookup table based on the upper 16 bits of `shapeRotation` [S5, unofficial].
    *   Translate the vertex to the voxel's world position. The transformation matrix is typically constructed as an identity matrix with translation components set to the instance's position [S2, S3, S4, unofficial].
    *   Add any chunk or world offset if the voxels are part of a larger chunked system [S5, unofficial].
5.  **Vertex Shader - Culling/Occlusion:**
    *   **Solidity Check:** Determine if the voxel is solid. In Unity implementations, this is often done by setting a clip value: `_Clip = -1.0 + isSolid`. If `isSolid` is 1.0, `_Clip` is 0.0; if 0.0, `_Clip` is -1.0 [S2, S4, unofficial].
    *   **Face Culling:** For solid voxels, hidden faces are culled by moving their vertices outside the clip volume (e.g., setting their position to a large negative value or using `clip()` with a negative threshold) rather than omitting them from the draw call [S1, S2, S4, unofficial]. This ensures correct rendering during translucent fade-ins [S1, unofficial].
6.  **Vertex Shader - Output:** Transform the final position to clip space and output UV coordinates and texture indices [S5, unofficial].
7.  **Fragment Shader:** Apply clipping based on the `_Clip` value. Fragments are discarded if `_Clip < 0` (non-solid voxels) [S2, S3, S4, unofficial]. Apply texture sampling and tinting [S5, unofficial].

**Pseudocode (GLSL-style):**

```glsl
// Uniforms
uniform mat4 view;
uniform mat4 projection;
uniform vec3 chunkPos;
uniform int verticesPerShape;

// SSBOs
layout(std430) buffer ShapeInstances {
    ShapeInstance instances[];
};
struct ShapeInstance {
    float posX, posY, posZ;
    int textureIndex;
    uint shapeRotation; // Lower 16: shape, Upper 16: rotation
    float tintR, tintG, tintB;
};

layout(std430) buffer ShapeVertices {
    ShapeVertex vertices[];
};
struct ShapeVertex {
    vec3 position;
    vec2 uv;
    // Padding fields omitted for brevity
};

// Vertex Shader
void main() {
    uint instanceID = gl_InstanceID;
    uint vertexID = gl_VertexID;
    
    // 1. Fetch instance data
    ShapeInstance instance = instances[instanceID];
    
    // 2. Determine shape and rotation
    uint shapeIndex = instance.shapeRotation & 0xFFFFu;
    uint rotationIndex = instance.shapeRotation >> 16u;
    
    // 3. Fetch vertex
    uint vertexOffset = shapeIndex * verticesPerShape;
    ShapeVertex vert = vertices[vertexID + vertexOffset];
    
    // 4. Transform position
    vec3 localPos = vert.position;
    
    // Apply rotation (simplified: assume rotation matrix lookup or identity for basic cubes)
    // In full implementation, rotate localPos by rotation matrix from lookup table
    
    // Center and translate
    vec3 worldPos = localPos - vec3(0.5) + vec3(instance.posX, instance.posY, instance.posZ) + chunkPos;
    
    // 5. Culling logic (example: clip non-solid)
    // In this model, solidity is often handled by the instance count or a separate clip value
    // If using the 6-byte mask, face culling moves vertices outside clip volume
    
    gl_Position = projection * view * vec4(worldPos, 1.0);
    
    // 6. Output varyings
    // Pass texture index and tint to fragment shader
}
```

**Parameters:**
*   `verticesPerShape`: Uniform integer specifying the number of vertices per shape instance [S5, unofficial].
*   `_Color`: Albedo color property, often applied in the fragment shader [S2, S4, unofficial].
*   `UNITY_PROCEDURAL_INSTANCING_ENABLED`: Preprocessor define enabling procedural instancing in Unity [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Vertex Work Increase:** Because whole cubes are submitted and hidden faces are culled in the shader, vertex work increases by 2.0× to 3.3× for zero-gap layouts (e.g., a 4×4×4 block with a 0 in the center) compared to a mesh that only generates visible faces [S1, unofficial]. This is acceptable as it is vertex-only work and avoids the cost of per-frame buffer rebuilds or multiple draw calls [S1, unofficial].
*   **Precision Drift:** GPU `f32` arithmetic drift is bounded to under $10^{-7}$ of the unit box, which is less than half a step of an 8-bit channel, ensuring visual correctness [S1, unofficial].
*   **Matrix Multiplication Order:** Row-major vs. column-major matrix multiplication must be handled correctly, especially when using uniforms that may be stored in row-major order [S5, unofficial].

## Operating characteristics
*   **Time Complexity:** Geometry build speed is 1.9–4.6× faster than pre-branch core methods [S1, unofficial]. Whole build speed is 1.3–1.8× faster [S1, unofficial].
*   **Memory Complexity:** Memory usage is significantly reduced. At resolution R=64, specimen memory drops from 42.0 MB to 649 KB (19–65× smaller) [S1, unofficial]. Worker message size reduces from 42.3 MB to 457 KB (92× reduction) [S1, unofficial].
*   **Cache Efficiency:** Cache capacity increases from 6 specimens to about 394 specimens before exhausting `CACHE_BYTES` at R=64 [S1, unofficial].
*   **Performance:** Maintains interactive frame rates of approximately 60 FPS at high voxel densities [S3, unofficial].
*   **Strengths:** Low memory footprint, fast build times, single draw call, flexible visibility logic.
*   **Limitations:** Increased vertex throughput for dense, gap-free volumes due to full cube submission.

## Background
This method is used in projects such as the block-showroom by lardratboy [S1, unofficial], and is implemented in Unity via procedural instancing shaders [S2, S3, S4, unofficial] and OpenGL via SSBOs [S5, unofficial]. It evolved from baked mesh approaches to reduce memory overhead and improve build times [S1, unofficial].
