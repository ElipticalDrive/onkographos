# Instanced Voxel Renderer

Also called: Chunk-based Instanced Voxel Rendering, Cubic-Grid Voxel Renderer, Indirect Rendering via SSBO, SSBO-based Instanced Rendering (Pipeline A)

## Overview
The Instanced Voxel Renderer is a GPU-driven technique that packs shape instances into large Shader Storage Buffer Objects (SSBOs), groups them into spatial chunks, and renders them via instanced drawing with per-chunk frustum culling [S1, S2, unofficial]. It differs from procedural instancing by pre-computing and storing packed geometric data in buffers, allowing for complex, non-uniform shapes and texture atlasing, while avoiding the vertex buffer overhead of naive cube rasterization by using indirect draw calls [S1, S2, unofficial].

## How it works
### Inputs and Outputs
**Inputs:**
- A set of block definitions (shapes) with associated textures and properties [S1, unofficial].
- A world grid composed of chunks, where each chunk contains a local array of block IDs [S1, S2, unofficial].
- Camera matrices (View, Projection) and frustum planes [S1, unofficial].

**Outputs:**
- Rasterized pixels on the screen representing the voxel world [S1, S2, unofficial].

### Data Structures

**1. ShapeInstance (SSBO Binding Point 3)**
Stores per-shape metadata. Fields include texture index, tint color, shape ID, and rotation [S1, unofficial]. The memory size is fixed per shape type, calculated via `ShapeInstance.MemorySize` [S1, unofficial].

**2. PackedVertex (uint32)**
A compact representation of a vertex stored in the SSBO. Layout:
- Bits 0-4 (5 bits): X coordinate (relative to block) [S2, unofficial].
- Bits 5-9 (5 bits): Z coordinate (relative to block) [S2, unofficial].
- Bits 10-20 (11 bits): Y coordinate (relative to block) [S2, unofficial].
- Bits 21-23 (3 bits): Face ID [S2, unofficial].
- Bits 24-29 (6 bits): Texture Index [S2, unofficial].

**3. DrawIndirectBuffer Command**
Stores rendering commands for indirect drawing [S2, unofficial]:
- `count`: Number of vertices to draw (`faceCount * 6`) [S2, unofficial].
- `instanceCount`: Always 1 [S2, unofficial].
- `first`: Offset in the SSBO (in vertices) (`offset * 6`) [S2, unofficial].
- `baseInstance`: Chunk index [S2, unofficial].

**4. MegaSSBO (Free List Management)**
Manages memory allocation within the large SSBO using a free list [S2, unofficial].
- `FreeList`: List of `{offset, size}` pairs representing unused regions [S2, unofficial].
- `Allocate(faceCount)`: First-fit algorithm to find a contiguous block of sufficient size [S2, unofficial].
- `Release(offset, faceCount)`: Returns memory to the free list and merges adjacent free blocks [S2, unofficial].

### Steps

1. **Initialize Texture Array**:
   - Determine `maxX` and `maxY` from all input textures [S1, unofficial].
   - Create a `Texture2DArray` with dimensions `maxX`, `maxY`, and `numTextures` [S1, unofficial].
   - Set min/mag filters to `Nearest` and wrap to `Repeat` [S1, unofficial].
   - Upload each texture `i` using `GL.TexSubImage3D` at z-offset `i` [S1, unofficial].

2. **Condense Shapes**:
   - Find `verticesPerShape` = maximum vertex count across all input shapes [S1, unofficial].
   - Allocate a flat array `condensedShapes` of size `numShapes * verticesPerShape` [S1, unofficial].
   - For each shape `s` and vertex `v`:
     - If `v < shape[s].Vertices.Length`, copy `shape[s].Vertices[v]` [S1, unofficial].
     - Else, assign a default `Vertex()` (padding) [S1, unofficial].
   - Upload `condensedShapes` to SSBO at binding point 3 [S1, unofficial].

3. **Register Chunks (SSBO Allocation)**:
   - For each chunk, calculate `size = shapes.Length * ShapeInstance.MemorySize` [S1, unofficial].
   - Check if `vramBufferRegionSize` (total SSBO size) is valid:
     - Must be `>= chunkVolumeSize` [S1, unofficial].
     - Must be `<= MaxShaderStorageBlockSize` [S1, unofficial].
     - If not a multiple of `chunkVolumeSize`, waste `vramBufferRegionSize % chunkVolumeSize` bytes [S1, unofficial].
   - Allocate space in the MegaSSBO using `Allocate(size)` [S2, unofficial].
   - Write shape instances to the SSBO at the allocated offset [S1, unofficial].
   - Store `ChunkRenderingData` with `RegionInstanceIndex = offset / ShapeInstance.MemorySize` [S1, unofficial].
   - Advance the free list pointer [S1, unofficial].

4. **Render Pass**:
   - Compute View and Projection matrices [S1, unofficial].
   - Extract frustum planes from the View matrix [S1, unofficial].
   - For each chunk:
     - Bind the SSBO [S1, unofficial].
     - Calculate `offsetPos = chunk.Position - cam.Position` [S1, unofficial].
     - Cull if `!MatrixPlanes.IsBoxInFrustum(planes, offsetPos, offsetPos + Vector3.One * chunkLength)` [S1, unofficial].
     - Set `chunkPos` uniform [S1, unofficial].
     - Call `GL.DrawArraysInstancedBaseInstance(Triangles, 0, verticesPerShape, chunk.Shapes.Length, chunk.RegionInstanceIndex)` [S1, unofficial].

### Vertex Shader Logic
- Unpack face data from the SSBO using `gl_VertexID` to determine face and corner index [S2, unofficial].
- Decode chunk position from `gl_BaseInstance`:
  - `chunkX = (base & 0xFFFF) - 32768` [S2, unofficial].
  - `chunkZ = ((base >> 16) & 0xFFFF) - 32768` [S2, unofficial].
- Compute world position: `chunkWorldPos + blockPos + corner`, where `blockPos` is `(bx, by, bz)` and `corner` is from `faceCorners[faceId][cornerIndex]` [S2, unofficial].
- Apply face-specific lighting from `faceLights` array [S2, unofficial].

### Parameters
- `chunkLength`: Width/height/depth of a single chunk in blocks. Typical value: 33 [S1, unofficial].
- `vramBufferRegionSize`: VRAM batch size in bytes for SSBO regions. Must be `>= chunkVolumeSize` and `<= MaxShaderStorageBlockSize` [S1, unofficial].
- `faceLights`: Lighting coefficients per face. +X=0.6, -X=0.6, +Y=1.0, -Y=0.3, +Z=0.8, -Z=0.8 [S2, unofficial].
- `u_AtlasTileSize`: Uniform `(1.0/atlasWidth, 1.0/atlasHeight)` [S2, unofficial].

### Edge Cases and Pitfalls
- **VRAM Limits**: `vramBufferRegionSize` must not exceed `MaxShaderStorageBlockSize` [S1, unofficial].
- **Memory Waste**: If `vramBufferRegionSize` is not a multiple of `chunkVolumeSize`, unused bytes are wasted [S1, unofficial].
- **Boundary Access**: When accessing adjacent chunks for culling, handle boundary conditions by returning air (0) if the neighbor chunk does not exist [S2, unofficial].

## Operating characteristics
- **Time Complexity**: O(N) for chunk registration, where N is the number of chunks. Rendering is O(M) where M is the number of visible chunks.
- **Memory Complexity**: O(V) for the SSBO, where V is the total number of voxels in the batched chunks.
- **Strengths**: Efficient culling at the chunk level reduces overdraw. Indirect rendering allows dynamic updates without CPU-side buffer rebuilds.
- **Limitations**: Fixed chunk size may lead to memory waste if not aligned. Complex shapes require pre-condensation.

## Background
The technique is implemented in open-source voxel engines such as `Cubic-Grid_Voxel_Renderer` [S1, unofficial] and `VoxelEngine` [S2, unofficial]. It leverages modern OpenGL features like SSBOs and indirect drawing to achieve high performance in voxel-based applications.
