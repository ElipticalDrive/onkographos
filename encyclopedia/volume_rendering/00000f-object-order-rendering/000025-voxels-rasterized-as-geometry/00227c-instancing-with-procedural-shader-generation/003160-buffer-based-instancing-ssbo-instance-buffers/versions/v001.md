# Buffer-Based Instancing (SSBO/Instance Buffers)

Also called: SSBO Instancing, Structured Buffer Instancing, Instance Buffer Rendering

## Overview
Buffer-Based Instancing is a GPU-driven rendering technique for voxel and procedural geometry that decouples instance data from the draw call by storing per-voxel attributes (position, material, orientation) in a Shader Storage Buffer Object (SSBO) or structured buffer. It solves the problem of efficiently rendering large-scale voxel fields by allowing the vertex shader to procedurally generate geometry from a shared base primitive (typically a cube) using data fetched from the buffer, rather than relying on pre-baked mesh topology or complex surface extraction. It differs from [Surface-based Instancing with Noise Modulation](1582-surface-based-instancing-with-noise-modulation.md) by operating on the full cubic grid occupancy rather than extracted surfaces, and from [Instancing with Procedural/Shader Generation](2794-instancing-with-procedural-shader-generation.md) by explicitly leveraging GPU-accessible storage buffers for dynamic instance records rather than purely uniform-based or hardcoded procedural generation.

## Shared principles
The mechanism relies on three components: a shared base geometry buffer, an instance data buffer, and an instanced draw call.

1.  **Base Geometry**: A static vertex buffer containing the vertices of a single primitive, typically a unit cube centered at the origin or $(0,0,0)$ to $(1,1,1)$. To support flat shading (unique normals per face), the cube is often defined with 24 vertices (4 vertices per face $\times$ 6 faces) rather than 8. An index buffer may define the triangles for the visible faces (e.g., 3 faces $\times$ 2 triangles $\times$ 3 vertices = 18 indices) or all 6 faces (36 indices).
2.  **Instance Data Buffer**: A GPU-accessible buffer (e.g., `StructuredBuffer` in HLSL, `std430` buffer in GLSL, or `ComputeBuffer` in Unity) stores per-instance attributes. Common attributes include:
    *   **Position**: 3D coordinates $(x, y, z)$.
    *   **Occupancy/Visibility**: A scalar flag (e.g., $w$-component of a `float4`) indicating if the voxel is solid or empty.
    *   **Material/Color**: Albedo, tint, or texture atlas index.
    *   **Orientation/Shape**: Rotation matrices or indices into a precomputed rotation table.
    *   **Scale**: Uniform or non-uniform scaling factors.
3.  **Instanced Draw Call**: A single draw command (e.g., `glDrawArraysInstanced`, `DrawInstanced`, or `DrawMeshInstancedIndirect`) is issued. The number of instances corresponds to the number of elements in the instance data buffer.
4.  **Shader Processing**:
    *   **Vertex Shader**: Retrieves per-instance data using `gl_InstanceID` (or equivalent). It transforms the base geometry vertices into world space using the instance's position, rotation, and scale. It may also perform early culling (e.g., discarding empty voxels) or face culling (determining visible faces based on camera position).
    *   **Fragment Shader**: Samples textures or computes colors based on the interpolated attributes passed from the vertex shader.

## Subtopics

### [Procedural Instancing for Voxel Blocks](1637-procedural-instancing-for-voxel-blocks.md)
Procedural instancing for voxel blocks replaces baked mesh geometry with a compact instance record per voxel, resolving position, color, and occlusion in the vertex shader using a shared cube template. It differs from surface-based instancing by operating on the full cubic grid occupancy rather than extracted surfaces, and from 3D Gaussian splatting by using hard-edged geometric primitives rather than soft volumetric blobs.

### [Cube Rasterization via SSBO](2267-cube-rasterization-via-ssbo.md)
Cube Rasterization via SSBO is a voxel rendering technique that explicitly rasterizes the visible faces of each voxel as triangle geometry rather than using point sprites or ray-marching. It solves the problem of rendering large voxel fields with exact geometric boundaries and explicit face culling by packing voxel data into a Shader Storage Buffer Object (SSBO) and using a single large index buffer to draw 3 faces per voxel instance. It differs from [Surface-based Instancing with Noise Modulation](1582-surface-based-instancing-with-noise-modulation.md) by using explicit triangle primitives instead of implicit surface definitions, and from [Instancing with Procedural/Shader Generation](2794-instancing-with-procedural-shader-generation.md) by relying on a pre-computed index buffer for face selection rather than procedural generation in the vertex shader.

### [Instanced Voxel Renderer](4102-instanced-voxel-renderer.md)
A GPU-driven voxel rendering technique that packs shape instances into large Shader Storage Buffer Objects (SSBOs), groups them into spatial chunks, and renders them via instanced drawing with per-chunk frustum culling.
