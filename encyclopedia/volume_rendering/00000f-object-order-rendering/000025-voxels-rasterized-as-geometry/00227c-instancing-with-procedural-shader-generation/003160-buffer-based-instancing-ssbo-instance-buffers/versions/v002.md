# Buffer-Based Instancing (SSBO/Instance Buffers)

Also called: GPU-driven Voxel Instancing, SSBO Instancing, Structured Buffer Instancing

## Overview
Buffer-Based Instancing is a volume rendering technique that renders voxel worlds by storing per-voxel attributes (position, material, orientation) in a GPU-accessible Shader Storage Buffer Object (SSBO) or Structured Buffer, and rendering them via a single instanced draw call using a shared base geometry primitive [S1, S2, S3, unofficial]. It solves the performance bottleneck of generating and uploading individual mesh geometry for millions of voxels by moving attribute resolution and transformation into the vertex shader. It is distinguished from [Surface-based Instancing with Noise Modulation](1582-surface-based-instancing-with-noise-modulation.md) by its explicit geometric rasterization of voxels rather than procedural surface approximation, and from [3D Gaussian Splatting via Instancing](1586-3d-gaussian-splatting-via-instancing.md) by its use of hard-edged cubic primitives rather than soft volumetric splats.

## Shared principles
The mechanism relies on three components: a shared base geometry buffer, an instance data buffer, and an instanced draw call.

1.  **Base Geometry**: A static vertex buffer containing the vertices of a single primitive, typically a unit cube centered at the origin or $(0,0,0)$ to $(1,1,1)$. To support flat shading (unique normals per face), the cube is often defined with 24 vertices (4 vertices per face $\times$ 6 faces) rather than 8. An index buffer may define the triangles for the visible faces (e.g., 3 faces $\times$ 2 triangles $\times$ 3 vertices = 18 indices) or all 6 faces (36 indices).
2.  **Instance Data Buffer**: A GPU-accessible buffer (e.g., `StructuredBuffer` in HLSL, `std430` buffer in GLSL, or `ComputeBuffer` in Unity) stores per-instance attributes. Common attributes include:
    *   **Position**: 3D coordinates $(x, y, z)$.
    *   **Occupancy/Visibility**: A scalar flag (e.g., $w$-component of a `float4`) indicating if the voxel is solid or empty.
    *   **Material/Color**: Albedo, tint, or texture atlas index.
    *   **Orientation/Shape**: Rotation matrices or indices into a precomputed rotation table.
    *   **Scale**: Uniform or non-uniform scaling factors.
3.  **Instanced Draw Call**: A single draw command (e.g., `glDrawArraysInstanced`, `DrawInstanced`, or `DrawMeshInstancedIndirect`) is issued. The number of instances corresponds to the number of elements in the instance data buffer.
4.  **Shader Processing**:
    *   **Vertex Shader**: Retrieves per-instance data using `gl_InstanceID` (or equivalent). It transforms the base geometry vertices into world space using the instance's position, rotation, and scale. It may also perform early culling (e.g., discarding empty voxels) or face culling (determining visible faces based on camera position).
    *   **Fragment Shader**: Samples textures or computes colors based on the interpolated attributes passed from the vertex shader.

## Subtopics

### [Procedural Instancing for Voxel Blocks](1637-procedural-instancing-for-voxel-blocks.md)
Replaces baked mesh geometry with a compact instance record per voxel, resolving position, color, and occlusion in the vertex shader using a shared cube template. It separates block data into an instance buffer and geometry data into a vertex buffer, applying transformations in the vertex shader. It uses procedural instancing to render voxel blocks as individual instances where position and clip distance are determined by a structured buffer. It builds on Buffer-Based Instancing by replacing per-voxel mesh generation with a single shared primitive and GPU-driven attribute resolution.

### [Cube Rasterization via SSBO](2267-cube-rasterization-via-ssbo.md)
Explicitly rasterizes the visible geometry of voxels as triangles using a single large index buffer and an SSBO to drive instanced drawing. It is distinguished by its reliance on explicit triangle buffers and specific face-culling logic based on camera position relative to each voxel, rather than submitting all 6 faces and relying on depth testing or clip distances.

### [Instanced Voxel Renderer](4102-instanced-voxel-renderer.md)
Packs shape instances into large SSBOs, groups them into spatial chunks, and renders them via instanced drawing with per-chunk frustum culling. It differs by relying on explicit, pre-allocated instance buffers and chunk-based spatial partitioning rather than purely procedural generation during the draw call, introducing a hierarchical chunking structure to manage VRAM allocation and culling efficiency.

## Background
The technique leverages the evolution of GPU compute and shader storage capabilities, specifically the introduction of Shader Storage Buffer Objects (SSBOs) in OpenGL 4.3 and equivalent structures in DirectX 11/12. It emerged as a solution to the memory bandwidth and draw call overhead limitations of traditional mesh-based voxel rendering, allowing for the rendering of millions of voxels with minimal CPU-GPU synchronization. It is widely used in voxel-based games and real-time visualization tools where dynamic world modification is required.
