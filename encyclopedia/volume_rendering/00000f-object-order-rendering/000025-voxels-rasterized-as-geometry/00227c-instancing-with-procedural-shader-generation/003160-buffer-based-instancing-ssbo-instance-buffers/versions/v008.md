# Buffer-Based Instancing (SSBO/Instance Buffers)

Also called: SSBO Instancing, Shader Storage Buffer Instancing, Indirect Instance Lookup

## Overview
Buffer-Based Instancing is a rendering technique where instance-specific data (transformations, materials, visibility flags) is stored in a Shader Storage Buffer Object (SSBO) or equivalent GPU-accessible buffer, and retrieved by the vertex shader using an instance identifier. It solves the problem of managing large numbers of distinct objects or voxels where per-instance data exceeds the capacity of standard vertex attributes or where data must be computed/modified dynamically on the GPU. It differs from standard hardware instancing, which passes instance data via a second vertex buffer with fixed strides, by allowing arbitrary, shader-driven data access and complex packing schemes [S1, unofficial].

## Shared principles
The core mechanism relies on three components:
1.  **Instance Identifier:** A unique integer identifying the instance. This is typically `gl_InstanceID` (or `SV_InstanceID` in Direct3D), but can also be derived from `gl_VertexID` via bitmasks when using custom index buffers [S2, unofficial].
2.  **Instance Data Buffer:** A buffer object (SSBO in OpenGL, `StructuredBuffer` in HLSL) bound to a shader binding point. It contains per-instance records. The layout is defined by the shader (e.g., `std430` or `std140` in GLSL) and can be tightly packed (e.g., bit-fields in `uvec2`) or loosely structured [S2, S3, unofficial].
3.  **Lookup Logic:** In the vertex shader, the instance identifier is used as an index to fetch the corresponding record from the buffer. This record provides the data needed to transform the base geometry or determine its properties [S1, S2, unofficial].

Mathematically, for an instance $i$ and vertex $v$, the world position $P_{world}$ is computed as:
$$ P_{world} = T_i \times P_{local} + O_i $$
where $T_i$ and $O_i$ are fetched from the instance buffer for instance $i$, derived from the instance ID [S3, unofficial].

## Subtopics

### [Procedural Instancing for Voxel Blocks](1637-procedural-instancing-for-voxel-blocks.md)
Procedural Instancing for Voxel Blocks replaces baked mesh geometry with a compact instance record per voxel, resolving position, color, and occlusion in the vertex shader using a shared cube template. It differs from standard instancing by computing transformations, visibility culling, and texture selection procedurally within the shader based on a dense, bit-packed instance buffer, allowing for significant memory reduction and cache efficiency compared to pre-baked geometries.

### [Cube Rasterization via SSBO](2267-cube-rasterization-via-ssbo.md)
This method renders $N$ voxels as instances of a base unit cube geometry using a single `glDrawElementsInstanced` draw call, where each instance is transformed by an offset fetched from a Shader Storage Buffer Object (SSBO) and colored via a palette texture lookup. It rasterizes only the 3 visible faces of each cube per voxel to optimize fill rate, using a single large index buffer (18 indices per instance) and a large SSBO containing voxel data (1 `uvec2` per voxel). It is distinguished from point-sprite based voxel rendering by using explicit triangle geometry for exact cube shapes and explicit face culling logic, and from hardware instancing by deriving instance identification from `gl_VertexID` bitmasks rather than relying solely on `gl_InstanceID` for data lookup.

### [Instanced Voxel Renderer](4102-instanced-voxel-renderer.md)
The Instanced Voxel Renderer is a GPU-driven technique that packs voxel shape instances into large Shader Storage Buffer Objects (SSBOs), groups them into spatial chunks, and renders them via instanced drawing with per-chunk frustum culling. It builds on Buffer-Based Instancing by introducing chunk-based spatial partitioning and indirect draw calls to minimize CPU-GPU synchronization overhead. Unlike Procedural Instancing for Voxel Blocks which generates geometry procedurally per-vertex, or Cube Rasterization via SSBO which may use simpler flat indexing, this method explicitly manages VRAM regions for chunks and uses a free-list allocator within the SSBO to handle variable face counts per chunk.

### [Hardware Instancing (Instance ID Lookup)](11005-hardware-instancing-instance-id-lookup.md)
Hardware Instancing with Instance ID Lookup is a rendering technique that draws multiple instances of a base geometry using a single draw call, where instance-specific data (such as transformation matrices or material properties) is retrieved from a buffer within the vertex shader using a system-provided instance identifier. It differs from standard hardware instancing, which passes instance data directly via a second vertex buffer, by relying on an indirect lookup mechanism that trades off driver optimization potential for flexible, shader-driven data access.

### Render to Vertex Buffer (R2VB) with PBO
#### definition
A technique using Vertex Buffer Objects (VBO) and the Render to Vertex Buffer (R2VB) extension, combined with Pixel Buffer Object (PBO) to load 2D texture values into VBOs, keeping data flow entirely on the GPU [S1, unofficial].
#### usage
Used in Buckets Texture construction and for the rendering stage [S1, unofficial].

## Background
Buffer-based instancing leverages the Shader Storage Buffer Object (SSBO) introduced in OpenGL 4.4 and equivalent structures in other APIs (e.g., `StructuredBuffer` in Direct3D 11). It allows shaders to read and write to large buffers with minimal overhead, making it suitable for GPU-driven rendering pipelines where instance data is generated or modified on the GPU. The technique is widely used in voxel rendering, particle systems, and procedural geometry generation where the number of instances is large and their properties are complex or dynamic [S1, S2, S3, unofficial].
