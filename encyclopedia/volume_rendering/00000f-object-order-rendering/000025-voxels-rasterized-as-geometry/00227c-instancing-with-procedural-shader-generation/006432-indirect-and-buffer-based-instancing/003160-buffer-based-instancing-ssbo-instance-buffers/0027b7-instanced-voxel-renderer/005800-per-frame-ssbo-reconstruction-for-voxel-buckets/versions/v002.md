# Per-Frame SSBO Reconstruction for Voxel Buckets

Also called: New SSBO per bucket per frame, VXL-041

## Overview
Per-Frame SSBO Reconstruction is a GPU-driven voxel rendering architecture that abandons incremental instance management in favor of completely discarding and recreating Shader Storage Buffer Objects (SSBOs) every frame for each non-empty render bucket [S1]. It differs from its parent, the [Instanced Voxel Renderer](4102-instanced-voxel-renderer.md), by rejecting persistent buffers, double buffering, swap-and-pop optimizations, and partial uploads, opting instead for a full reconstruction model where instance data is rebuilt from scratch each frame [S1]. This approach simplifies synchronization and state management at the cost of higher memory bandwidth and allocation overhead [S1].

## How it works
The method operates within the `VoxelRenderingSystem` and relies on the `RenderSnapshot` architecture [S1]. It processes active scene components to generate immutable GPU buffers for each frame [S1].

### Inputs and Outputs
*   **Input:** A `Registry` containing active `Model` and `Assembly` components, each with local transforms, parent references, and mesh/material bindings [S1].
*   **Output:** A `RenderSnapshot` containing `DrawVoxelBucketCommand` objects, each bound to a newly created, immutable `ShaderStorageBuffer::Handle` [S1].

### Data Structures
The core data structures are defined in the `spk::Voxel` namespace [S1]:

1.  **`GPUInstance`**: A struct containing the dynamic data for a single voxel instance [S1]. Fields include world transform matrix, palette or material mapping, and shader instance fields [S1]. The exact byte layout follows compiler packing rules and is aligned for SSBO binding [S1].
2.  **`BucketKey`**: A struct used to group instances that can be drawn together [S1]. Fields include mesh identity, render pass identifier, and compatible GPU bindings [S1].
3.  **`DrawVoxelBucketCommand`**: A render command inheriting from `spk::RenderCommand` [S1]. It stores immutable mesh and material bindings, a `ShaderStorageBuffer::Handle` specific to the current snapshot, and the number of instances [S1].

### Steps
The reconstruction process occurs in `VoxelRenderingSystem::_buildRenderSnapshot(builder)` [S1]:

1.  **Collection:** Collect all active `Model` and `Assembly` components from the `Registry` [S1].
2.  **Transform Calculation:** Recalculate the world transform for every collected component [S1]. The world matrix is computed as `worldEntityMatrix * parentPartMatrices * local` [S1].
3.  **Bucketing:** Group the calculated occurrences into compact vectors (buckets) based on `BucketKey` [S1]. Instances sharing the same mesh identity, render pass, and compatible GPU bindings are grouped together [S1].
4.  **SSBO Creation:** For each non-empty bucket: create a new `spk::ShaderStorageBuffer` object, resize it to the instance count, write the full dynamic data array using a span-like view, and call `validate()` to signal modification [S1].
5.  **Command Construction:** Capture the immutable `ShaderStorageBuffer::Handle` from the SSBO [S1]. Emplace a `DrawVoxelBucketCommand` into the `RenderSnapshot` builder, passing the mesh/material bindings, the handle, and the instance count [S1].
6.  **Execution:** During rendering, `DrawVoxelBucketCommand::execute(RenderContext&)` activates the SSBO handle [S1]. The `RenderContext` triggers GPU resource synchronization (uploading the entire buffer content) and performs the instanced draw call [S1].

### Pseudocode
The following Python-like pseudocode represents the core logic of `_buildRenderSnapshot` [S1]. All helper classes and operations are defined within the block to ensure self-containment [G].

```python
def build_render_snapshot(registry, builder):
    # 1. Collect active components
    active_components = registry.get_active_models_and_assemblies()
    
    # Dictionary mapping BucketKey to list of GPUInstance
    buckets = {}
    
    for component in active_components:
        # 2. Recalculate world transform: worldEntityMatrix * parentPartMatrices * local
        world_transform = component.world_entity_matrix @ component.parent_part_matrices @ component.local_matrix
        
        # Create GPUInstance data
        gpu_instance = {
            'world_transform': world_transform,
            'palette': component.palette_mapping,
            'shader_fields': component.shader_instance_data
        }
        
        # 3. Group into buckets by BucketKey
        key = (component.mesh_identity, component.render_pass, component.gpu_bindings)
        if key not in buckets:
            buckets[key] = []
        buckets[key].append(gpu_instance)
    
    # 4 & 5. Create SSBOs and Commands
    for key, instances in buckets.items():
        if not instances:
            continue
            
        mesh_id, render_pass, bindings = key
        
        # Create new SSBO
        ssbo = ShaderStorageBuffer(binding_point=bindings, element_size=64)
        
        # Resize to instance count and write full dynamic data
        ssbo.resize(len(instances))
        ssbo.set_dynamic_data(instances)
        
        # Signal modification
        ssbo.validate()
        
        # Capture immutable handle
        handle = ssbo.handle()
        
        # Add command to snapshot
        builder.render_pass(render_pass).emplace(
            DrawVoxelBucketCommand(
                mesh_bindings=mesh_id,
                material_bindings=bindings,
                ssbo_handle=handle,
                instance_count=len(instances)
            )
        )

class ShaderStorageBuffer:
    def __init__(self, binding_point, element_size):
        self.binding_point = binding_point
        self.element_size = element_size
        self.data = []
        self._handle = None
    def resize(self, count):
        self.data = [None] * count
    def set_dynamic_data(self, data):
        self.data = list(data)
    def validate(self):
        self._handle = f"SSBO_{id(self)}"
    def handle(self):
        return self._handle

class DrawVoxelBucketCommand:
    def __init__(self, mesh_bindings, material_bindings, ssbo_handle, instance_count):
        self.mesh_bindings = mesh_bindings
        self.material_bindings = material_bindings
        self.ssbo_handle = ssbo_handle
        self.instance_count = instance_count
```

### Parameters and Edge Cases
*   **BucketKey:** Must accurately reflect all GPU state differences (mesh, pass, bindings) to ensure correct grouping [S1].
*   **Instance Removal:** Handled by omitting the instance from the next frame's bucket [S1]. No holes or sentinels are left; buckets are always compact [S1].
*   **Immutability:** SSBO handles must be immutable after publication to the snapshot [S1]. Modifying the SSBO after creating the handle is forbidden [S1].
*   **Lifecycle:** Each `RenderSnapshot` must retain its SSBO handles and immutable resources until execution completes [S1]. A new snapshot cannot alter an old SSBO [S1].
*   **Double Buffering:** Explicit double buffering of SSBOs is not implemented [S1]. New SSBOs are created per snapshot instead of swapping [S1].

## Operating characteristics
*   **Time Complexity:** Scales linearly with the number of active instances per frame, requiring full component collection, transform calculation, grouping, and buffer allocation/upload [S1].
*   **Memory Complexity:** $O(N)$ for the SSBO storage per frame, where $N$ is the number of active instances [S1].
*   **Performance:** Incurs the cost of full GPU object creation and complete data upload every frame, regardless of whether instances changed [S1]. This is a deliberate trade-off for simplicity [S1].
*   **Strengths:** Simplified synchronization (no dirty ranges, no partial uploads), no need for complex double-buffering logic, and robust handling of dynamic scene changes [S1].
*   **Limitations:** High bandwidth usage and allocation overhead for static or slowly changing scenes [S1].
*   **When to Use:** Scenes with high instance turnover or when implementation simplicity is prioritized over bandwidth efficiency [S1].
*   **When Not to Use:** Not given in the sources.

## Background
This architecture represents a shift away from previous rendering systems that used incremental updates, persistent SSBOs, and swap-and-pop optimizations [S1]. The design was validated as VXL-041 [S1].
