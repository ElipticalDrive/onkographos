# GPU Instancing with Layered Offset for Volume Clouds

Also called: DrawMeshInstanced Cloud Rendering, Multi-layer Offset Clouds

## Overview
This method renders volumetric cloud appearance by using GPU instancing to draw multiple vertically offset layers of a base mesh, where each layer uses distinct noise sampling parameters to simulate depth and thickness [S1, unofficial]. It differs from ray-marching or parallax mapping by relying on discrete geometric layers with per-instance shader property variations to create a 3D noise-based volume effect [S1, unofficial].

## How it works
**Inputs:**
- Base mesh (typically a plane or low-poly geometry representing a cloud slice).
- Material with shader supporting 3D Perlin noise sampling and instanced properties.
- Parameters: `layers` (count), `thickness` (total vertical extent), `clipThresPower` (exponent for alpha clipping), `noiseTiling` (noise scale).

**Outputs:**
- Rendered cloud volume with perceived depth and volumetric texture.

**Data Structures:**
- **Instance Matrices:** Array of $N$ transformation matrices (where $N = \text{layers}$), typically set to the local-to-world matrix of the cloud object for all instances.
- **MaterialPropertyBlock (MPB) Arrays:** Three float arrays of size $N$, passed to the shader via `SetFloatArray`:
  1. `_PosOffset_Array`: Vertical offset for each layer.
  2. `_ClipThres_Array`: Alpha clip threshold for each layer.
  3. `_NoiseTiling_Array`: Noise tiling scale for each layer.

**Steps:**
1. **Initialize Arrays:** Create three arrays of size `layers`.
2. **Calculate Layer Parameters:** For each layer index $i$ from $0$ to `layers` - 1:
   a. Calculate normalized offset:
      $$ \text{offset} = \frac{i}{\text{layers}} $$
   b. Calculate vertical position offset:
      $$ \text{PosOffset}[i] = \text{offset} \times \text{thickness} $$
   c. Calculate clip threshold:
      $$ \text{ClipThres}[i] = \text{offset}^{\text{clipThresPower}} $$
   d. Set noise tiling (constant across layers in this implementation):
      $$ \text{NoiseTiling}[i] = \text{noiseTiling} $$
3. **Assign to MPB:** Set the arrays into the MaterialPropertyBlock using keys `"_PosOffset"`, `"_ClipThres"`, and `"_NoiseTiling"`.
4. **Prepare Matrices:** Create an array of `layers` transformation matrices, all set to the object's local-to-world matrix.
5. **Draw Instanced Mesh:** Call the instanced draw function (e.g., `Graphics.DrawMeshInstanced`) with:
   - Base mesh
   - Material
   - Matrices array
   - Instance count (`layers`)
   - MaterialPropertyBlock
   - Shadow settings: `ShadowCastingMode` set to `Off` (or custom pass handling), `receiveShadows` set to component setting.

**Pseudocode:**
```python
def render_cloud_layers(base_mesh, material, transform, layers, thickness, clipThresPower, noiseTiling):
    # Initialize arrays
    pos_offsets = [0.0] * layers
    clip_thres = [0.0] * layers
    noise_tiling = [0.0] * layers
    
    # Calculate parameters for each layer
    for i in range(layers):
        offset = i / layers
        pos_offsets[i] = offset * thickness
        clip_thres[i] = offset ** clipThresPower
        noise_tiling[i] = noiseTiling
        
    # Create MaterialPropertyBlock and set arrays
    mpb = MaterialPropertyBlock()
    mpb.SetFloatArray("_PosOffset", pos_offsets)
    mpb.SetFloatArray("_ClipThres", clip_thres)
    mpb.SetFloatArray("_NoiseTiling", noise_tiling)
    
    # Prepare instance matrices (all same transform)
    matrices = [transform.localToWorldMatrix] * layers
    
    # Draw instanced mesh
    Graphics.DrawMeshInstanced(
        mesh=base_mesh,
        material=material,
        matrices=matrices,
        count=layers,
        propertyBlock=mpb,
        shadowCastingMode=ShadowCastingMode.Off,
        receiveShadows=True
    )
```

**Edge Cases and Pitfalls:**
- **Shadow Casting:** If vertex offset is applied in the main pass, the default ShadowCaster pass may not apply the same offset, causing incorrect shadows [S1, unofficial]. Solution: Write a custom ShadowCaster pass that replicates the vertex offset logic [S1, unofficial].
- **iOS Shadow Aliasing:** Traditional shadow mapping on iOS may exhibit aliasing due to lack of shadow cascades [S1, unofficial].
- **Shader Requirements:** The shader must use 3D Perlin noise sampled against vertex coordinates (not 2D UVs) to achieve volumetric depth [S1, unofficial].
- **Shadow Receiving:** For PC (SS Shadow Mapping), ensure "Queue" <= 2500, have a ShadowCaster pass, enable receive shadows, and use shadow receiving macros in the shader [S1, unofficial]. For iOS, similar conditions apply but with traditional shadow mapping constraints [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(L)$ where $L$ is the number of layers, as each layer requires a draw call or is handled within a single instanced draw call with $L$ instances.
- **Memory Complexity:** $O(L)$ for storing instance matrices and MPB arrays.
- **Performance:** Efficient for moderate layer counts (default 20, range 1-50) as it leverages GPU instancing. Performance degrades if layer count is very high due to increased draw overhead or fragment shader load.
- **Strengths:** Simple implementation, good volumetric appearance with 3D noise, easy parameter tuning.
- **Limitations:** Discrete layers may show artifacts if not blended properly; shadow casting requires custom passes; iOS shadow quality may be poor.
- **When to Use:** Real-time cloud rendering where performance is critical and high-fidelity volumetric ray-marching is not feasible.
- **When Not to Use:** When high-quality shadows with cascades are required, or when continuous volumetric effects are needed without layering artifacts.

## Background
This technique is based on GPU instancing and procedural noise rendering, as described in unofficial sources [S1, unofficial]. It builds on the principles of hardware instancing via draw calls [16221-hardware-instancing-via-draw-calls.md], extending them with layered offset and per-instance shader properties to simulate volume clouds. The approach references 3D Perlin noise for texture generation [S1, unofficial] and draws inspiration from community implementations [S1, unofficial].
