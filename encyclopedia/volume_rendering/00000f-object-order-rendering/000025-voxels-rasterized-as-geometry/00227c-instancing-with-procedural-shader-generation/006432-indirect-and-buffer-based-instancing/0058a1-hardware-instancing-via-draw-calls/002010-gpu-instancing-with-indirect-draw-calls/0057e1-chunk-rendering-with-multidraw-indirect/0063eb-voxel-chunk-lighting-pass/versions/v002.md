# Voxel Chunk Lighting Pass

Also called: Indirect Voxel Rendering, Voxel Engine Lighting

## Overview
A rasterization pass that renders voxel chunks as textured quads with lighting, using indirect draw calls and texture buffer objects (TBOs) to supply materials and light data to the shader [S1, unofficial]. It builds on [Chunk Rendering with Multidraw Indirect](3933-chunk-rendering-with-multidraw-indirect.md) by adding the lighting computation and post-processing pipeline required to produce the final image from the geometry generated by the parent method [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Indirect draw command buffer (from parent), material definitions, chunk metadata, light sources (point, directional, spot), and camera matrices [S1, unofficial].
*   **Outputs:** A lighting framebuffer with two color attachments (base color and bloom/highlight) and a depth buffer [S1, unofficial].

**Data Structures:**
The method relies on Texture Buffer Objects (TBOs) bound to `GL_TEXTURE_BUFFER` with `GL_RGBA32F` format [S1, unofficial]. The layouts are [S1, unofficial]:

1.  **Material** (per material ID):
    *   `vec3 ambient`
    *   `vec3 diffuse`
    *   `vec3 specular`
    *   `vec3 emission`
    *   `float shininess`
    *   `int type`
2.  **ChunkInfo** (per chunk):
    *   `vec3 position`
    *   `float normal` (Note: Source asserts size equals one `vec4`, implying padding or specific alignment [S1, unofficial]).
3.  **PointLight**:
    *   `vec3 position`
    *   `float constant`
    *   `float linear`
    *   `float quadratic`
    *   `vec3 ambient`
    *   `vec3 diffuse`
    *   `vec3 specular`
    *   `float padding_1`
4.  **DirLight**:
    *   `vec3 direction`
    *   `vec3 ambient`
    *   `vec3 diffuse`
    *   `vec3 specular`
5.  **SpotLight**:
    *   `vec3 position`
    *   `vec3 direction`
    *   `float cutOff`
    *   `float outerCutOff`
    *   `float constant`
    *   `float linear`
    *   `float quadratic`
    *   `vec3 ambient`
    *   `vec3 diffuse`
    *   `vec3 specular`

**Steps:**
The execution sequence is [S1, unofficial]:
1.  **Setup TBOs:** Create TBOs for materials, chunk info, point lights, directional lights, and spot lights. Bind each to `GL_TEXTURE_BUFFER` using `GL_RGBA32F` format [S1, unofficial].
2.  **Setup FBOs:** Create a lighting Framebuffer Object (FBO) with two color attachments (0 and 1) and a depth buffer. Create two ping-pong FBOs for subsequent post-processing [S1, unofficial].
3.  **Bind Lighting FBO:** Bind the lighting FBO and clear the color and depth buffers [S1, unofficial].
4.  **Upload Geometry:** Upload quad vertex data to the vertex buffer using `GL_STATIC_DRAW` [S1, unofficial].
5.  **Set Uniforms:** Set shader uniforms for Model-View-Projection (MVP), NormalMatrix, and `BloomThreshold` [S1, unofficial].
6.  **Upload Data:** Upload the materials array to the material TBO, light arrays to their respective TBOs, and chunk info to the chunk info TBO [S1, unofficial].
7.  **Bind Depth:** Bind the depth renderbuffer to the lighting FBO's depth attachment [S1, unofficial].
8.  **Set Draw Buffers:** Configure the FBO to write to `GL_COLOR_ATTACHMENT0` and `GL_COLOR_ATTACHMENT1` [S1, unofficial].
9.  **Upload Indirect Data:** Upload the indirect draw command data to the indirect buffer bound to `GL_DRAW_INDIRECT_BUFFER` [S1, unofficial].
10. **Execute Draw:** Call `glMultiDrawArraysIndirect` with `GL_TRIANGLES` to render all chunks [S1, unofficial].

**Pseudocode:**
```python
# Standard OpenGL stubs for self-contained pseudocode
def glCreateBuffer(data, format=None, usage=None): return data
def glCreateFramebuffer(num_color_attachments, has_depth): return 1
def glBindFramebuffer(target, fbo): pass
def glClear(mask): pass
def glBindBuffer(target, buf): pass
def glUniformMatrix4fv(name, val): pass
def glUniformMatrix3fv(name, val): pass
def glUniform1f(name, val): pass
def glActiveTexture(unit): pass
def glBindTexture(target, tex): pass
def glFramebufferTexture2D(target, attachment, textarget, texture, level): pass
def glDrawBuffers(buffers): pass
def glMultiDrawArraysIndirect(mode, offset, count, stride): pass

def execute_voxel_chunk_lighting_pass(indirect_commands, materials, chunks, point_lights, dir_lights, spot_lights, mvp, normal_matrix, bloom_threshold, quads_vertex_data, depth_renderbuffer):
    # 1. Setup TBOs
    material_tbo = glCreateBuffer(materials, format='GL_RGBA32F')
    chunk_tbo = glCreateBuffer(chunks, format='GL_RGBA32F')
    point_tbo = glCreateBuffer(point_lights, format='GL_RGBA32F')
    dir_tbo = glCreateBuffer(dir_lights, format='GL_RGBA32F')
    spot_tbo = glCreateBuffer(spot_lights, format='GL_RGBA32F')

    # 2. Setup FBOs
    lighting_fbo = glCreateFramebuffer(num_color_attachments=2, has_depth=True)
    pingpong_fbo_1 = glCreateFramebuffer(num_color_attachments=1, has_depth=False)
    pingpong_fbo_2 = glCreateFramebuffer(num_color_attachments=1, has_depth=False)

    # 3. Bind Lighting FBO
    glBindFramebuffer(GL_FRAMEBUFFER, lighting_fbo)
    glClear(GL_COLOR_BUFFER_BIT | GL_DEPTH_BUFFER_BIT)

    # 4. Upload Geometry
    vbo = glCreateBuffer(quads_vertex_data, usage='GL_STATIC_DRAW')
    glBindBuffer(GL_ARRAY_BUFFER, vbo)

    # 5. Set Uniforms
    glUniformMatrix4fv('MVP', mvp)
    glUniformMatrix3fv('NormalMatrix', normal_matrix)
    glUniform1f('BloomThreshold', bloom_threshold)

    # 6. Upload Data to TBOs
    glActiveTexture(GL_TEXTURE0); glBindTexture(GL_TEXTURE_BUFFER, material_tbo)
    glActiveTexture(GL_TEXTURE1); glBindTexture(GL_TEXTURE_BUFFER, chunk_tbo)
    glActiveTexture(GL_TEXTURE2); glBindTexture(GL_TEXTURE_BUFFER, point_tbo)
    glActiveTexture(GL_TEXTURE3); glBindTexture(GL_TEXTURE_BUFFER, dir_tbo)
    glActiveTexture(GL_TEXTURE4); glBindTexture(GL_TEXTURE_BUFFER, spot_tbo)

    # 7. Bind Depth
    glBindFramebuffer(GL_FRAMEBUFFER, lighting_fbo)
    glFramebufferTexture2D(GL_FRAMEBUFFER, GL_DEPTH_ATTACHMENT, GL_TEXTURE_2D, depth_renderbuffer, 0)

    # 8. Set Draw Buffers
    glDrawBuffers([GL_COLOR_ATTACHMENT0, GL_COLOR_ATTACHMENT1])

    # 9. Upload Indirect Data
    indirect_buffer = glCreateBuffer(indirect_commands, usage='GL_DYNAMIC_DRAW')
    glBindBuffer(GL_DRAW_INDIRECT_BUFFER, indirect_buffer)

    # 10. Execute Draw
    glMultiDrawArraysIndirect(GL_TRIANGLES, offset=0, count=len(indirect_commands), stride=0)
```

**Parameters:**
*   `bloomThreshold`: Threshold for separating bright colors in the lighting pass. Range: 0.0f to 5.0f [S1, unofficial].
*   `gamma`: Gamma correction value. Range: 0.0f to 10.0f [S1, unofficial].
*   `exposure`: Exposure value for tone mapping. Range: 0.0f to 10.0f [S1, unofficial].
*   `bloomBlurPasses`: Number of bloom blur passes. Minimum: 0 [S1, unofficial].
*   `bloomOffset`: Offset for bloom sampling. Range: 0.0f to 10.0f [S1, unofficial].
*   `break_radius`: Radius for block breaking interaction. Range: 1.0f to 100.0f [S1, unofficial].
*   `break_range`: Range for block breaking interaction. Range: 1.0f to 500.0f [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Resource Leaks:** TBOs are created but not explicitly deleted in the destructor, potentially causing resource leaks [S1, unofficial].
*   **Depth Binding:** The depth buffer attachment is commented as potentially missing actual binding, though it is regenerated on resize [S1, unofficial].
*   **Stride:** The indirect draw call uses a stride of 0 [S1, unofficial]. In standard OpenGL, `glMultiDrawArraysIndirect` requires a non-zero stride if the indirect commands are not tightly packed or if the driver does not assume tight packing [G]. Implementers should verify if the specific implementation relies on a tightly packed `DrawElementsIndirect` struct or if this is a source-specific quirk [G].

## Operating characteristics
*   **Time Complexity:** O(N) for uploading quad data and indirect data per frame, where N is the number of chunks or draw commands. O(1) for TBO setup [S1, unofficial].
*   **Memory Complexity:** Proportional to the number of materials, lights, and chunks stored in TBOs [S1, unofficial].
*   **Strengths:** Reduces draw call overhead by batching chunks via indirect drawing. Centralizes lighting data in TBOs for efficient shader access [S1, unofficial].
*   **Limitations:** Potential resource leaks if not managed carefully. Depth attachment binding issues may cause rendering artifacts [S1, unofficial].
*   **When to use:** Suitable for voxel engines requiring efficient rendering of large numbers of chunks with dynamic lighting [S1, unofficial].
*   **When not to use:** Not suitable for scenes with very few chunks where the overhead of TBO setup outweighs the benefits, or for hardware that does not support `GL_TEXTURE_BUFFER` [S1, unofficial].

It utilizes OpenGL features such as Texture Buffer Objects and Indirect Drawing to optimize the rendering pipeline for voxel-based worlds [S1, unofficial].
