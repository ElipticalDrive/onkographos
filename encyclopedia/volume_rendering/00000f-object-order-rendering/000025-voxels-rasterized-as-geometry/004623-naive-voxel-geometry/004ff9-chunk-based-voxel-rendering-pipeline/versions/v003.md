# Chunk-based Voxel Rendering Pipeline

Also called: Baking geometry into VBOs, Batched Voxel Rendering Pipeline, Chunk VBOs

## Overview
The Chunk-based Voxel Rendering Pipeline aggregates individual voxel cubes into larger static mesh batches (chunks) and uploads them to GPU Vertex Buffer Objects (VBOs) to overcome the high overhead of instancing small, per-cube geometry [S1, unofficial]. It separates visibility processing (handled by an octree or spatial structure) from the rendering loop, which simply traverses a list of active chunk VBOs [S1, unofficial]. This approach eliminates hidden faces and reduces draw calls, making it suitable for high-throughput rendering where GPU fill rate and generation bottlenecks are critical [S1, unofficial].

## How it works
The method converts voxel data into geometric primitives, aggregates them into chunks, transforms them to world space, projects and clips them, sorts by depth, applies visual effects, and rasterizes using polygon drawing [S3, unofficial].

### Inputs and Outputs
*   **Input:** A voxel grid (e.g., `map_data` or `Grid`) containing block IDs or solid/empty flags [S3, unofficial].
*   **Output:** Rasterized pixels on the screen via the graphics pipeline [S3, unofficial].

### Data Structures

**Chunk Structure**
A chunk aggregates geometry for a specific region of the voxel space [S2, unofficial].
*   `side`: The physical size of a single voxel unit (`GLfloat`) [S2, unofficial].
*   `chunkpos`: The world-space position of the chunk origin (`glm::vec3`) [S2, unofficial].
*   `filled`: A 3D boolean array indicating voxel presence. In one implementation, this is a fixed-size array `filled[512][512][512]` [S2, unofficial].
*   `rendervert`: A flat list of vertex coordinates (`std::vector<GLfloat>` or `numpy` array) [S2, unofficial].
*   `indices`: A flat list of vertex indices (`std::vector<GLuint>` or `numpy` array) [S2, unofficial].
*   `count`: The number of cubes (blocks) in the chunk [S2, unofficial].

**Face Buffer Layout (Intermediate Representation)**
When aggregating geometry from visible sections, faces are stored in a buffer with specific column layouts [S3, unofficial]:
*   `V_COLS` (indices 0–11): 12 vertex coordinates (4 vertices × 3 coordinates) [S3, unofficial].
*   `C_COLS` (indices 12–14): Center coordinates (X, Y, Z) [S3, unofficial].
*   `RGB_COLS` (indices 15–17): RGB color values [S3, unofficial].
*   Indices 19 and 20: Chunk offsets `WX` and `WY` respectively [S3, unofficial].

**Vertex Layout**
The vertex layout pushed to the graphics pipeline includes 4 floats per vertex [S2, unofficial].

### Parameters
*   **Chunk Dimensions:** Typically $16 \times 16 \times 16$ voxels, resulting in 4096 cubes per chunk [S1, unofficial].
*   **Render Distance:** A limit used for horizon clipping. The squared distance limit is calculated as $(\text{render\_dist} + 0.5)^2$ [S3, unofficial].

### Steps

1.  **Chunk Instantiation and Grid Filling**
    Instantiate a chunk object with voxel dimension, position, and display flag [S2, unofficial]. Fill the chunk's internal grid from the global voxel data using triple nested loops over the chunk's local dimensions [S3, unofficial].

2.  **Geometry Aggregation (Baking)**
    Generate the surface mesh for the chunk by iterating over active voxels [S2, unofficial].
    *   For each solid voxel, determine visible faces by culling internal faces [S2, unofficial].
    *   Concatenate raw stacked faces from all visible sections into a single array [S3, unofficial].
    *   If no arrays are generated, return [S3, unofficial].
    *   This step may be performed asynchronously or in parallel (e.g., using `std::async` for slabs) to separate geometry generation from the render loop [S2, unofficial].

3.  **Transform to World Space**
    Transform the aggregated vertices to world space [S3, unofficial]:
    *   Copy vertex columns (`V_COLS`) to a temporary vertex array `verts` [S3, unofficial].
    *   Add chunk offset `WX` (from `faces[:, 19]`) to vertex columns 0, 3, 6, 9 (`verts[:, 0::3]`) [S3, unofficial].
    *   Add chunk offset `WY` (from `faces[:, 20]`) to vertex columns 1, 4, 7, 10 (`verts[:, 1::3]`) [S3, unofficial].

4.  **Projection**
    Project vertices to screen space [S3, unofficial]:
    *   Call `project_vertices(verts, cam_f32, *view_params)` to get projected points (`pts`), unused values, and a projection mask (`proj_mask`) [S3, unofficial].
    *   If no points pass projection (`not np.any(proj_mask)`), return [S3, unofficial].

5.  **Horizon Clipping**
    Filter faces based on distance from the camera [S3, unofficial]:
    *   Calculate world-space centers:
        $$wx = \text{faces}[:, 12] + \text{faces}[:, 19]$$
        $$wy = \text{faces}[:, 13] + \text{faces}[:, 20]$$
        $$wz = \text{faces}[:, 14]$$
    *   Calculate squared distance to camera position $(cam\_pos[0], cam\_pos[1], cam\_pos[2])$:
        $$dx = wx - cam\_pos[0]$$
        $$dy = wy - cam\_pos[1]$$
        $$dz = wz - cam\_pos[2]$$
        $$dist\_sq = dx^2 + dy^2 + dz^2$$
    *   Define limit: $limit\_sq = (\text{render\_dist} + 0.5)^2$ [S3, unofficial].
    *   Create mask: $\text{Mask} = dist\_sq \le limit\_sq$ [S3, unofficial].
    *   Return filtered `pts`, `faces`, `dist_sq`, and `wz` [S3, unofficial].

6.  **Sorting (Painter's Algorithm)**
    Sort faces by distance from far to near [S3, unofficial]:
    *   Compute indices: $\text{idx} = \text{np.argsort}(dist\_sq)[::-1]$ [S3, unofficial].
    *   Return sorted `pts[idx]`, `faces[idx]`, `dist_sq[idx]`, `wz[idx]` [S3, unofficial].

7.  **Visual Effects**
    Apply shading and fog [S3, unofficial]:
    *   Call `apply_visual_effects` with parameters:
        *   `colors`: `s_faces[:, RGB_COLS]`
        *   `z_centers`: `s_wz`
        *   `euclidean_dist`: $\sqrt{s\_dist}$
        *   `render_dist`, `fog_density`, `use_h_shading`, `height_shading_factor`, `height_fog_density`, `height_fog_max_z`, `height_fog_fade` [S3, unofficial].

8.  **Rasterization**
    Draw the polygons [S3, unofficial]:
    *   For each face $i$, draw the polygon using the projected points and colors: `pygame.draw.polygon(surface, colors[i], pts[i])` [S3, unofficial].
    *   In a full OpenGL pipeline, this involves creating VBOs/IBOs and calling `glDrawElements(GL_TRIANGLES, cntblocks, GL_UNSIGNED_INT, nullptr)` [S2, unofficial].

### Pseudocode

```python
import numpy as np
import math

def project_vertices(verts, focal_length, view_params):
    """Standard perspective projection. Returns projected points, unused buffer, and visibility mask."""
    pts = np.zeros_like(verts)
    mask = np.ones(verts.shape[0], dtype=bool)
    for i in range(verts.shape[0]):
        z = verts[i, 2]
        if z <= 0.0:
            mask[i] = False
            continue
        scale = focal_length / z
        pts[i, 0] = verts[i, 0] * scale + view_params[0]
        pts[i, 1] = verts[i, 1] * scale + view_params[1]
        pts[i, 2] = z
    return pts, None, mask

def apply_visual_effects(colors, z_centers, euclidean_dist, render_dist, fog_density, use_h_shading, height_shading_factor, height_fog_density, height_fog_max_z, height_fog_fade):
    """Applies distance fog and height-based shading."""
    final_colors = colors.copy()
    for i in range(len(colors)):
        fog_factor = 1.0 - math.exp(-euclidean_dist[i] * fog_density)
        final_colors[i] = (final_colors[i] * (1.0 - fog_factor)) + np.array([0.5, 0.5, 0.5]) * fog_factor
        if use_h_shading:
            h_factor = max(0.0, 1.0 - (z_centers[i] / height_fog_max_z)) * height_fog_fade
            final_colors[i] *= (1.0 - height_fog_density * h_factor)
    return final_colors

def render_chunk_pipeline(chunk, camera, view_params, render_dist):
    """
    Renders a single chunk using the chunk-based pipeline.
    """
    # 1. Aggregate Geometry (Baking)
    faces = chunk.generate_surface_mesh()
    if faces is None or len(faces) == 0:
        return

    # 2. Transform to World Space
    # faces layout: V_COLS(0-11), C_COLS(12-14), RGB_COLS(15-17), WX(19), WY(20)
    verts = faces[:, 0:12].copy()
    wx_offset = faces[:, 19]
    wy_offset = faces[:, 20]
    
    # Add chunk offsets to vertex columns
    verts[:, 0::3] += wx_offset[:, np.newaxis]
    verts[:, 1::3] += wy_offset[:, np.newaxis]
    
    # 3. Project Vertices
    pts, unused, proj_mask = project_vertices(verts, camera.focal_length_32, view_params)
    
    if not np.any(proj_mask):
        return

    # 4. Horizon Clipping
    wx_centers = faces[:, 12] + wx_offset
    wy_centers = faces[:, 13] + wy_offset
    wz_centers = faces[:, 14]
    
    dx = wx_centers - camera.pos[0]
    dy = wy_centers - camera.pos[1]
    dz = wz_centers - camera.pos[2]
    dist_sq = dx**2 + dy**2 + dz**2
    
    limit_sq = (render_dist + 0.5)**2
    mask = dist_sq <= limit_sq
    
    s_pts = pts[mask]
    s_faces = faces[mask]
    s_dist_sq = dist_sq[mask]
    s_wz = wz_centers[mask]
    
    if len(s_pts) == 0:
        return

    # 5. Sort Far to Near
    idx = np.argsort(s_dist_sq)[::-1]
    s_pts = s_pts[idx]
    s_faces = s_faces[idx]
    s_dist_sq = s_dist_sq[idx]
    s_wz = s_wz[idx]

    # 6. Apply Visual Effects
    colors = s_faces[:, 15:18]
    euclidean_dist = np.sqrt(s_dist_sq)
    
    final_colors = apply_visual_effects(
        colors=colors,
        z_centers=s_wz,
        euclidean_dist=euclidean_dist,
        render_dist=render_dist,
        fog_density=0.01,
        use_h_shading=True,
        height_shading_factor=0.5,
        height_fog_density=0.005,
        height_fog_max_z=100.0,
        height_fog_fade=1.0
    )

    # 7. Rasterize
    for i in range(len(s_pts)):
        draw_polygon(surface, final_colors[i], s_pts[i])
```

### Edge Cases and Pitfalls
*   **GPU Overhead:** Instancing entire cubes individually causes huge GPU overhead relative to the small triangle count (12 triangles per cube), which worsens as GPU speed increases [S1, unofficial]. Baking into chunks eliminates this [S1, unofficial].
*   **Small Batches:** Small batches are inefficient [S1, unofficial].
*   **Visibility vs. Rendering:** Do not use an octree structure for the rendering loop itself. Use it exclusively for processing visibility (determining which chunks to add/remove from the active list) or collisions [S1, unofficial].
*   **VR Frustum:** For VR, create a frustum box that encompasses both eyes to perform a single visibility check instead of two [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Chunk generation time depends on processor speed and content density. On a quad-core i7 2.2GHz with GTX 560M, the system generates >10 chunks per second [S1, unofficial]. On a BeagleBoard (single-core ARM Cortex-A8 at 720MHz), it manages about 10 chunks per second [S1, unofficial].
*   **Memory Complexity:** Memory usage scales with the number of active chunks and the fixed chunk size of $16 \times 16 \times 16$ voxels per chunk [S1, unofficial].
*   **Strengths:** Eliminates hidden faces, reduces draw calls, separates geometry generation from rendering (allowing asynchronous loading), and mitigates GPU overhead associated with small batches [S1, unofficial].
*   **Limitations:** Requires pre-baking or asynchronous generation of chunk geometry, which adds complexity to the loading pipeline. The render loop relies on a simple list traversal, which may not be optimal for extremely sparse or highly dynamic scenes without spatial indexing [S1, unofficial].
*   **When to Use:** High-throughput voxel rendering where fill rate and generation bottlenecks are critical, and the scene has static or semi-static geometry that can be batched into chunks [S1, unofficial].
*   **When Not to Use:** Scenes requiring frequent, fine-grained dynamic updates to individual voxels, or where memory bandwidth is severely constrained by large VBO uploads [S1, unofficial].

## Background
The method was discussed in the context of overcoming fill rate and generation bottlenecks in voxel engines [S1, unofficial]. It was proposed as an alternative to naive voxel rendering (instancing individual cubes) to improve performance on both high-end GPUs and low-power embedded devices like the BeagleBoard [S1, unofficial]. The approach separates the spatial data structure (octree) used for visibility culling from the rendering pipeline, which uses a simple list of active chunks [S1, unofficial].
