# Naive Voxel Rendering

Also called: Cuboid-based Volume Rendering, Rasterization without LODs, Voxel Cuboid Rendering, VoxelShader::render

## Overview
Naive Voxel Rendering is an object-order volume rendering technique that represents every occupied voxel in a dense grid as a full geometric cube and submits these primitives to the graphics pipeline for rasterization [S1, S3, S4, unofficial]. It visualizes scalar field data by converting it directly into mesh geometry, differing from image-order ray-casting methods by projecting geometry into screen space rather than sampling rays through the volume [G]. Unlike optimized variants such as [Sparse Voxel Rasterization](3032-sparse-voxel-rasterization.md) or [SVO LOD Management](2990-svo-lod-management.md), this method generates primitives for all voxels without Level of Detail (LOD) reduction or greedy meshing, resulting in massive vertex counts for large scenes [S1, S4, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A dense 3D grid of voxel data (scalar values, colors, or active flags) defined by bounds $P_{min}$, $P_{max}$, and dimensions $N_{dim}$ [S4, S5, unofficial].
- **Output:** A rasterized 2D image on the screen, determined by the depth buffer (z-buffer) for opaque voxels or a back-to-front painter's algorithm for transparency [S2, S3, unofficial].

**Data Structures:**
The core data structure is a list of occupied voxel coordinates, typically stored in a `HashSet<IVec3>` or a flat array [S3, S4, unofficial]. For implementations requiring per-voxel attributes (color, normal), a flat array or interleaved buffer is used [G].
- **Vertex Buffer Layout:** Vertices are stored in a `std::vector<GLfloat>` in interleaved triangle-strip-like order for 6 faces [S4, unofficial]. Each face has 6 vertices (2 triangles) [S4, unofficial]. The order for the 'front' face (Z+) is: $(-,-,+)$, $(-,+,+)$, $(+,+,+)$, $(-,-,+)$, $(+,-,+)$, $(+,+,+)$ [S4, unofficial].
- **Normal Buffer:** Normals are stored in a separate `std::vector<GLfloat>` with 108 entries (3 floats per vertex × 6 vertices per face × 6 faces) [S4, unofficial].
- **Color Buffer:** Colors are associated with triangles [S4, unofficial]. For 6 faces × 2 triangles, there are 12 color entries (3 floats each: R, G, B), assuming flat shading per triangle [S4, unofficial].

**Coordinate Transformation:**
Voxel indices $(i, j, k)$ are transformed into world space [G]. For a dense grid with bounds $P_{min}$ and $P_{max}$ and dimension $N_{dim}$, the world position $P_{world}$ of a voxel center is calculated as [S4, unofficial]:
$$
P_{world} = P_{min} + \frac{I_{voxel}}{N_{dim}} \times (P_{max} - P_{min})
$$
For unit voxels ($V_{size}=1.0$), this simplifies to $P_{world} = I_{voxel} \times V_{size}$ [S2, S4, unofficial]. The vertex positions for a cube centered at $P_{world}$ are offset by $\pm VoxelHalfSize$ (typically 0.5) [S4, unofficial].

**Numbered Steps:**
1. **Initialization:** Load voxel data into a CPU-side structure (e.g., `HashSet` or array) [S3, S4, unofficial]. If using GPU-accelerated updates, pull volume texture data from GPU to CPU [S5, unofficial].
2. **Iteration:** Iterate through all voxel coordinates $(x, y, z)$ in the grid [S3, S4, unofficial].
3. **Frustum Culling:** Check if the voxel's world position exceeds the camera's frustum border (e.g., Y coordinate check); if so, skip rendering [S2, unofficial].
4. **Back-face Culling:** If `cullInvisibleFaces` is enabled, calculate the view-space normal [S2, unofficial]. Compute the dot product between the view-space normal and the vector from the voxel to the camera (view-space origin) [S2, unofficial]. If the result is $< 0$, the face is back-facing and is discarded [S2, unofficial].
5. **Geometry Generation:** For each active voxel, generate 36 vertices representing 6 faces [S4, unofficial]. Calculate vertex positions in local space relative to the voxel center, transform to world space using grid coordinates and voxel size [S4, unofficial], transform to view space using the Model-View (MV) matrix [S2, unofficial], then to clip space using the Projection (P) matrix [S2, unofficial]. Emit vertices with texture coordinates [S2, unofficial].
6. **Rasterization:** Submit the generated primitives to the graphics pipeline [G]. The depth buffer resolves visibility for opaque voxels [S2, S3, unofficial].
7. **Update:** If dynamic, re-upload updated voxel positions and data to GPU buffers [S5, unofficial].

**Pseudocode:**
```python
def render_naive_voxels(voxels: list, mv_matrix: list, p_matrix: list, frustum: object, cull_invisible_faces: bool = True) -> tuple:
    """
    Renders a list of voxels as individual cubes.
    voxels: List of dicts with keys: x, y, z (grid coords), color (tuple of 3 floats), active (bool)
    mv_matrix: 4x4 Model-View matrix (list of lists)
    p_matrix: 4x4 Projection matrix (list of lists)
    frustum: Object with method contains(position) -> bool
    Returns: (vertices: list of vec3, colors: list of vec3)
    """
    voxel_size = 1.0
    half_size = 0.5
    vertices = []
    colors = []

    for voxel in voxels:
        if not voxel.get('active', True):
            continue

        # 1. Frustum Culling
        world_pos = [voxel['x'] * voxel_size, voxel['y'] * voxel_size, voxel['z'] * voxel_size]
        if not frustum.contains(world_pos):
            continue

        # 2. Transform center to view space
        view_center = mat_vec_mul(mv_matrix, [world_pos[0], world_pos[1], world_pos[2], 1.0])

        # 3. Generate Cube Geometry (6 faces, 6 vertices each in triangle-strip order)
        # Face normals and corner offsets (local space)
        faces = [
            ([0, 0, 1], [[-half_size, -half_size, half_size], [half_size, -half_size, half_size], [half_size, half_size, half_size], [-half_size, half_size, half_size]]), # Front
            ([0, 0, -1], [[half_size, -half_size, -half_size], [-half_size, -half_size, -half_size], [-half_size, half_size, -half_size], [half_size, half_size, -half_size]]), # Back
            ([0, 1, 0], [[-half_size, half_size, -half_size], [half_size, half_size, -half_size], [half_size, half_size, half_size], [-half_size, half_size, half_size]]), # Top
            ([0, -1, 0], [[-half_size, -half_size, half_size], [half_size, -half_size, half_size], [half_size, -half_size, -half_size], [-half_size, -half_size, -half_size]]), # Bottom
            ([1, 0, 0], [[half_size, -half_size, half_size], [half_size, -half_size, -half_size], [half_size, half_size, -half_size], [half_size, half_size, half_size]]), # Right
            ([-1, 0, 0], [[-half_size, -half_size, -half_size], [-half_size, -half_size, half_size], [-half_size, half_size, half_size], [-half_size, half_size, -half_size]])  # Left
        ]

        for face_normal_local, corners in faces:
            # Back-face culling
            if cull_invisible_faces:
                view_normal = normalize(mat_vec_mul(mv_matrix, [face_normal_local[0], face_normal_local[1], face_normal_local[2], 0.0]))
                view_vector = normalize([-view_center[0], -view_center[1], -view_center[2]])
                if dot(view_normal, view_vector) < 0:
                    continue

            # Triangle-strip order: v0, v1, v2, v0, v3, v2
            strip_indices = [0, 1, 2, 0, 3, 2]
            for idx in strip_indices:
                local_v = corners[idx]
                # Transform local vertex to world, then to view, then to clip
                world_v = [world_pos[0] + local_v[0], world_pos[1] + local_v[1], world_pos[2] + local_v[2]]
                view_v = mat_vec_mul(mv_matrix, [world_v[0], world_v[1], world_v[2], 1.0])
                clip_v = mat_vec_mul(p_matrix, view_v)
                # Store clip coordinates (hardware performs perspective divide)
                vertices.append([clip_v[0], clip_v[1], clip_v[2]])
                colors.append(voxel['color'])

    return vertices, colors

# Helper math functions (standard vector operations)
def mat_vec_mul(M, v):
    return [sum(M[i][j] * v[j] for j in range(4)) for i in range(4)]

def dot(a, b):
    return sum(x * y for x, y in zip(a, b))

def normalize(v):
    mag = dot(v, v) ** 0.5
    return [x / mag for x in v]
```

**Parameters:**
- **VoxelSize:** Physical size of a voxel in world units. Default: 1.0f [S4, unofficial].
- **VoxelHalfSize:** Half of VoxelSize. Default: 0.5f [S4, unofficial].
- **CullInvisibleFaces:** Boolean flag to enable back-face culling. Default: True [S2, unofficial].

**Edge Cases and Pitfalls:**
- **Performance:** Performance degrades quadratically or worse with scene size because every voxel generates 36 vertices [S3, unofficial]. Increasing platform size from 32x32 to 64x64 increases vertex count by 16x [S3, unofficial].
- **No Adjacency Culling:** The engine does not cull faces hidden by adjacent voxels [S4, unofficial]. Every voxel generates full geometry regardless of neighbors, leading to high vertex buffer overhead [S4, unofficial].
- **Precision:** Using integer grid indices (`IVec3`) ensures alignment but requires careful conversion to floating-point world coordinates [S3, unofficial].
- **Memory Limits:** Extremely slow and memory intensive; can crash the kernel or cause swapping issues with large datasets [S6, unofficial].

## Subtopics

### [Per-voxel Projection (Object-order)](1816-per-voxel-projection-object-order.md)
Optimized for Maximum Intensity Projection (MIP) by sorting voxels by value and overwriting pixels, avoiding depth buffer complexity. Choose when visualizing density/maximums rather than surface geometry.

## Operating characteristics
- **Time Complexity:** $O(V)$, where $V$ is the number of voxels [S3, S4, unofficial]. Each voxel requires linear-time geometry generation and submission relative to the grid size [S3, S4, unofficial].
- **Memory Complexity:** $O(V)$ for vertex buffers [S4, unofficial]. Each voxel consumes 36 vertices × 3 floats × 4 bytes = 432 bytes for positions alone, plus normals and colors [S4, unofficial].
- **Measured Performance:** On a 32x32x1 platform, naive rendering is feasible [S3, unofficial]. On larger scales (e.g., 1k³ resolution), it generates nearly a million quads, causing significant CPU-GPU bandwidth bottlenecks due to frequent buffer uploads [S1, S3, unofficial].
- **Strengths:** Simple implementation; no complex spatial data structures required; works well for small, dense scenes or debugging [S4, unofficial].
- **Limitations:** Extremely inefficient for large scenes; no LOD; no occlusion culling between adjacent voxels; high draw call overhead if not instanced [S1, S3, S4, unofficial].
- **When to Use:** Small voxel art scenes, educational purposes, or as a baseline for comparison [S4, unofficial].
- **When Not to Use:** Large-scale volumetric visualization, real-time applications with high voxel counts, or sparse datasets [S1, S3, S4, unofficial].

## Background
Naive Voxel Rendering originated as a foundational technique in early voxel engines, where simplicity of implementation took precedence over performance [S3, S4, unofficial]. It is exemplified in tutorials such as "Make yourself a Voxel Engine THIS weekend" [S3, unofficial] and the "Simple Voxel Engine" by James Randall [S4, unofficial]. The method is commonly used in educational contexts and simple visualization tools like the `bwImageHeightMap` and `perlinLandscape` examples [S4, unofficial].
