# Per-voxel Projection (Object-order)

Also called: Forward rendering, Histogram-based sorting, Object Space Approach, Object order voxel projection with value-sorted array, Object-order voxel projection, Voxel projection with value sorting, Voxel space projection

## Overview
Per-voxel projection is an object-order volume rendering technique that iterates through volume data, projecting each voxel directly onto the image plane to accumulate pixel values [S1, S3][S4, unofficial]. It solves the problem of efficiently computing Maximum Intensity Projections (MIP) by avoiding expensive read-compare-write GPU cycles, instead relying on a value-sorted traversal order where later projections overwrite earlier ones [S1, S3]. Unlike its sibling [Naive Voxel Rendering](1103-naive-voxel-rendering.md), which rasterizes individual cubes, this method treats voxels as point samples projected to single pixels, and unlike [Front-to-Back Object-Order Projection](11222-front-to-back-object-order-projection.md), it does not require a Z-buffer or depth buffer for visibility resolution, instead using value magnitude to determine occlusion [S1, S3].

## How it works
**Inputs:** A 3D volume dataset $V$ of size $N_x \times N_y \times N_z$, a viewing transformation matrix $M$, and an image plane resolution $W \times H$ [G].
**Outputs:** A 2D image buffer $I$ of size $W \times H$ [S1, S3].

**Data Structures:**
1. **Value-Sorted Array ($P$):** An array of voxel positions (indices or coordinates) containing only "interesting" voxels [S1, S3]. A voxel is considered interesting if its value $v > 0$, as zero voxels are excluded because they never contribute to the maximum [S1, S3].
2. **Cumulative Histogram Array ($H_{cum}$):** An auxiliary array storing cumulative counts of voxels up to specific value thresholds, used to facilitate histogram-based sorting [S1, S3].
3. **Image Buffer ($I$):** A 2D array where $I[u, v]$ stores the accumulated value for pixel $(u, v)$ [S1, S3].

**Steps:**
1. **Filter and Sort:** Iterate through the volume $V$ and identify all voxels with $v > 0$ [S1, S3]. Store their positions in a temporary list [S3]. Sort this list based on their corresponding voxel values in ascending order (low to high) [S1, S3]. The sources mention storing cumulative histogram values, implying a histogram-based sorting algorithm is used to achieve this order efficiently [S1, S3].
2. **Project and Accumulate:** Initialize the image buffer $I$ to the background value [S1]. Iterate through the sorted positions in $P$ from the first element (lowest value) to the last (highest value) [S1, S3]. For each voxel position $p_i$ in $P$: compute the 2D image coordinates $(u, v)$ by applying the viewing transformation $M$ to the 3D position of $p_i$ and projecting onto the image plane [S3][S4, unofficial]. Retrieve the voxel value $v_i$ associated with $p_i$ [S3]. Update the image buffer at $(u, v)$ with $I[u, v] \leftarrow v_i$ [S1, S3]. Since the voxels are processed in ascending order of value, the current voxel's value $v_i$ is guaranteed to be greater than or equal to any previously written value at $(u, v)$ (if any), so a simple overwrite operation correctly implements the Maximum Intensity Projection [S1, S3].
3. **Handle Undersampling (Edge Case):** For non-axial views, holes may form due to undersampling [S1]. A continuous function must be reconstructed using morphological sampling, followed by a morphological closing of the projection images [S1].

**Pseudocode:**
```python
def per_voxel_projection_mip(volume, view_matrix, image_width, image_height):
    # Initialize image buffer to background value
    image = [[0 for _ in range(image_width)] for _ in range(image_height)]
    
    # Step 1: Filter interesting voxels (value > 0)
    interesting_voxels = []
    for z in range(volume.depth):
        for y in range(volume.height):
            for x in range(volume.width):
                value = volume.get(x, y, z)
                if value > 0:
                    interesting_voxels.append((x, y, z, value))
    
    # Step 2: Sort voxels by value in ascending order
    interesting_voxels.sort(key=lambda voxel: voxel[3])
    
    # Step 3: Project and accumulate
    for (x, y, z, value) in interesting_voxels:
        # Standard perspective projection [G]
        wx = view_matrix[0]*x + view_matrix[1]*y + view_matrix[2]*z + view_matrix[3]
        wy = view_matrix[4]*x + view_matrix[5]*y + view_matrix[6]*z + view_matrix[7]
        wz = view_matrix[8]*x + view_matrix[9]*y + view_matrix[10]*z + view_matrix[11]
        w  = view_matrix[12]*x + view_matrix[13]*y + view_matrix[14]*z + view_matrix[15]
        
        if w == 0: continue
        nx, ny = wx / w, wy / w
        u = int((nx + 1) * image_width / 2)
        v = int((1 - ny) * image_height / 2)
        
        if 0 <= u < image_width and 0 <= v < image_height:
            # Overwrite with current value (ascending sort guarantees max)
            image[v][u] = value
            
    return image
```

**Parameters:**
*   **Threshold for "Interesting" Voxels:** 0. Voxels with value $\le 0$ are excluded [S1].
*   **Sorting Order:** Ascending (low to high) [S1, S3].

**Pitfalls:**
*   **Arbitrary Order:** If voxels are projected in arbitrary order, the final image is incorrect because the last projected voxel overwrites previous ones, regardless of depth or value [S4, unofficial].
*   **Undersampling Holes:** Non-axial views may exhibit holes due to sparse sampling of the volume by the projection rays [S1].

## Operating characteristics
*   **Time Complexity:** Dominated by the sorting step, $O(N \log N)$ or $O(N)$ with histogram-based sorting, where $N$ is the number of non-zero voxels [S1, S3]. The projection step is $O(N)$ [S3].
*   **Memory Complexity:** $O(N)$ for storing the value-sorted array and cumulative histogram [S1, S3].
*   **Performance:** Substantial reduction in processed voxels (often >95%) by excluding zero voxels [S1]. Allows compression-domain rendering as MIP can be computed directly on the value-sorted array without full 3D reconstruction [S1].
*   **Strengths:** Efficient for MIP; avoids Z-buffer contention; suitable for sparse volumes [S1, S3].
*   **Limitations:** Primarily suited for MIP or simple overwriting compositing; requires sorting overhead [S1, S3].
*   **When to Use:** When computing Maximum Intensity Projections on sparse volumetric data where performance is critical and transparency is not required [S1, S3].

## Background
The method was introduced as an object-order voxel-projection technique [MKG00] to avoid processing empty space in volume rendering [S3]. It was notably applied in the context of morphological pyramids for multiresolution MIP rendering, where it allowed for efficient progressive refinement by storing data in value-sorted arrays [S1]. The approach is part of the broader object-space rendering paradigm, which projects contributions from the volume to the image plane, contrasting with image-space ray tracing [S2, unofficial][S4, unofficial].
