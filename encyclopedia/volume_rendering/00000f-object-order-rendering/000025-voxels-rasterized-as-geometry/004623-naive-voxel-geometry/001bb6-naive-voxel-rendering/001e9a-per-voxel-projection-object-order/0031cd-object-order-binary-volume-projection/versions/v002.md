# Object-order Binary Volume Projection

Also called: Back-to-Front Algorithm, Back-to-Front Object-Order Projection, Object space rendering, Object-order voxel projection with value-sorted array, Voxel space projection

## Overview
Object-order Binary Volume Projection is an early forward-mapping technique for rendering binary volumes, where voxels with a value of one are projected onto the image plane in back-to-front order to ensure correct occlusion without a Z-buffer [S1, S2, unofficial]. It differs from its sibling [Per-voxel Projection (Object-order)](1816-per-voxel-projection-object-order.md) by strictly restricting the input to binary data and relying on traversal order rather than a depth buffer to resolve visibility [S2, unofficial]. Unlike later object-order methods like splatting, it does not reconstruct continuous density functions or handle gray-scale values [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D binary volume grid $V$ of dimensions $D_x \times D_y \times D_z$, where $V(x,y,z) \in \{0, 1\}$ [S2, unofficial]. A projection function $P(x,y,z) \to (u,v,d)$ mapping voxel coordinates to image pixel $(u,v)$ and distance $d$ from the image plane [G].
*   **Output:** An image buffer $I$ and a depth buffer $D$, both of size $W \times H$ [S1, S2, unofficial].

**Data Structures:**
*   **Volume Grid:** A 3D array indexed by $(x, y, z)$ storing binary values [S2, unofficial].
*   **Image Buffer:** A 2D array indexed by pixel coordinates $(u, v)$ storing the projected voxel value [S1, S2, unofficial].
*   **Depth Buffer:** A 2D array indexed by pixel coordinates $(u, v)$ storing the distance of the projected voxel from the image plane [S1, unofficial].

**Parameters:**
*   **Traversal Order:** Determined by the relative orientation of the data axes to the image plane; each axis is traversed in increasing or decreasing order to satisfy the back-to-front requirement [S1, S2, unofficial].
*   **Clipping Planes:** Optional axis-parallel clipping planes that restrict traversal to a smaller rectangular region within the full data set [S1, S2, unofficial].

**Steps:**
1.  **Initialize Buffers:** Clear the image buffer $I$ and depth buffer $D$ to background values [G].
2.  **Determine Traversal Order:** Analyze the camera orientation to determine if each axis ($x, y, z$) should be traversed in increasing or decreasing order [S2, unofficial].
3.  **Traverse and Project:** Iterate through the volume using three nested loops. For each voxel $(x, y, z)$:
    *   If $V(x,y,z) == 0$, skip [S2, unofficial].
    *   If clipping planes are active, check if the voxel is within the valid range; if not, skip [S1, S2, unofficial].
    *   Project the voxel center to the image plane to obtain pixel coordinates $(u, v)$ and distance $d$ [G].
    *   If $(u, v)$ is within the image bounds, overwrite $I(u,v)$ with the voxel value (1) and $D(u,v)$ with $d$ [S1, unofficial].
4.  **Post-processing (Optional):** The generated depth image $D$ can be passed to a simple 2D discrete shader for further processing [S1, unofficial].

**Pseudocode:**
```python
def object_order_binary_projection(volume, image, depth, width, height, project_voxel, clip_bounds):
    """
    volume: 3D array [Dx, Dy, Dz] with values 0 or 1
    image, depth: 2D arrays [width, height]
    project_voxel: callable(x, y, z) -> (u, v, dist)
    clip_bounds: tuple of (min_x, max_x, min_y, max_y, min_z, max_z) or None
    """
    Dx, Dy, Dz = len(volume), len(volume[0]), len(volume[0][0])
    
    # Initialize buffers to background values
    for u in range(width):
        for v in range(height):
            image[u][v] = 0
            depth[u][v] = float('inf')
            
    # Determine traversal directions based on camera orientation [S2, unofficial]
    # dir_x, dir_y, dir_z are +1 or -1
    dir_x, dir_y, dir_z = 1, 1, -1
    
    # Define loop ranges for each axis
    x_range = range(0, Dx, dir_x) if dir_x == 1 else range(Dx - 1, -1, -1)
    y_range = range(0, Dy, dir_y) if dir_y == 1 else range(Dy - 1, -1, -1)
    z_range = range(0, Dz, dir_z) if dir_z == 1 else range(Dz - 1, -1, -1)
    
    for z in z_range:
        for y in y_range:
            for x in x_range:
                if volume[x][y][z] == 0:
                    continue
                if clip_bounds is not None:
                    cx, cy, cz = clip_bounds
                    if not (cx[0] <= x < cx[1] and cy[0] <= y < cy[1] and cz[0] <= z < cz[1]):
                        continue
                u, v, dist = project_voxel(x, y, z)
                if 0 <= u < width and 0 <= v < height:
                    image[u][v] = 1
                    depth[u][v] = dist
```

**Edge Cases and Pitfalls:**
*   **Arbitrary Order:** If voxels are projected in arbitrary order, the last projected voxel overwrites earlier ones, causing incorrect occlusion where closer voxels might be hidden by farther ones [S2, unofficial].
*   **Precision:** Floating-point precision in projection calculations may cause gaps or overlaps in the image, especially at high resolutions or oblique angles [G].
*   **Clipping:** Clipping planes parallel to the image plane are implemented by modifying loop bounds; incorrect bounds can lead to artifacts or missing data [S1, S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$, where $N$ is the number of voxels in the volume, as each voxel is processed once [S1, S2, unofficial].
*   **Memory Requirements:** Requires storage for the volume grid and two $W \times H$ buffers for the image and depth planes [S1, S2, unofficial].
*   **Performance:** Efficient for binary volumes due to simple traversal and projection; performance degrades if the volume is sparse and the traversal overhead is high relative to the number of projected voxels [G].
*   **Strengths:** Simple implementation; no Z-buffer required; easy to generate depth images; supports axis-parallel clipping via loop bounds [S1, S2, unofficial].
*   **Limitations:** Restricted to binary volumes; does not handle gray-scale or continuous density functions [S1, unofficial].
*   **When to Use:** When rendering binary volumes (e.g., segmented medical data) and simplicity is prioritized over visual fidelity or flexibility [S1, S2, unofficial].
*   **When Not to Use:** For gray-scale volumes or continuous rendering [S1, unofficial].

## Background
Object-order Binary Volume Projection was one of the first object-order methods for volume rendering, developed in the early days of the field [S1, unofficial]. It was designed to render binary volumes, such as those derived from medical imaging, by projecting voxels in back-to-front order [S1, S2, unofficial]. The method is described in foundational texts on volume visualization, including Kaufman's "Volume Visualization: Principles and Advances" [S2, unofficial] and various dissertations on interactive volume rendering [S1, unofficial]. It serves as a precursor to more sophisticated object-order techniques like splatting [S1, unofficial].
