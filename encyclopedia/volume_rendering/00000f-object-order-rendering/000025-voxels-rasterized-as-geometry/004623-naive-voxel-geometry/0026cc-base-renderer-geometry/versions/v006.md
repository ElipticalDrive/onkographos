# Base Renderer Geometry
Also called: Cube Indices Layout, DrawVoxel, Square Face Indices Layout, Square Line Indices Layout, VoxelPass

## Overview
Base Renderer Geometry is a method for rendering voxel data by converting scalar field values into explicit geometric primitives (squares or cubes) and submitting them to the graphics pipeline via immediate-mode or batched draw calls. It solves the problem of visualizing volumetric data by treating each voxel as a discrete geometric object rather than a volume element for ray marching. It differs from [Naive Voxel Rendering](1103-naive-voxel-rendering.md) by explicitly constructing vertex and index buffers for faces or edges, and from [Cube Geometry for Volume Rendering](10885-cube-geometry-for-volume-rendering.md) by often utilizing simpler primitive topologies (such as single squares per axis) or immediate-mode APIs depending on the implementation context.

## How it works
**Inputs and Outputs:**
The method takes voxel data (positions, colors, transparency states) and rendering parameters (orientation, scale, transformation) as input. It outputs a sequence of draw calls to the graphics API, rendering either wireframe edges, square faces, or full cubes.

**Data Structures:**
The implementation relies on specific index layouts and vertex buffers.

1.  **Index Layouts:**
    *   **Cube Indices (`CUBE_INDICES`):** An integer array of 24 elements defining the edges of a cube. The layout is: `[0, 1, 1, 2, 2, 3, 3, 0, 4, 5, 5, 6, 6, 7, 7, 4, 0, 4, 1, 5, 2, 6, 3, 7]` [S1, unofficial].
    *   **Square Line Indices (`SQUARE_LINE_INDICES`):** An integer array of 8 elements defining a square perimeter. The layout is: `[0, 1, 1, 2, 2, 3, 3, 0]` [S1, unofficial].
    *   **Square Face Indices (`SQUARE_FACE_INDICES`):** An integer array of 6 elements defining two triangles for a square face. The layout is: `[0, 1, 2, 0, 2, 3]` [S1, unofficial].

2.  **Vertex Data:**
    *   **Vertices:** A list of `Vector4` (or `Vector3`) storing the base positions of the voxels [S1, unofficial].
    *   **Colors:** A list of `Color` storing vertex colors [S1, unofficial].
    *   **Base Vertex Format:** Comprises `Position`, `Normal`, `Tangent`, and `Surface` attributes. The `Surface` attribute packs texture coordinates and ambient occlusion into a single 3-component float array (RGB 32-bit float) [S2, unofficial].
    *   **Skinned Vertex Format:** Extends the base format with `JointCombined` [S2, unofficial].

3.  **Batching Structure (`DrawVoxel`):**
    A structure holding the rendering state:
    *   `pipeline_basic`: Graphics pipeline for opaque/standard rendering.
    *   `pipeline_skinned`: Graphics pipeline for skinned rendering.
    *   `static_batches`: A two-level batch structure mapping `MaterialId` to a list of vertex arguments (e.g., `SmallVec<[VertexArgs; 4]>`).
    *   `skinned_batches`: Similar to static batches but for skinned vertex arguments.
    *   `models`: A dynamic vertex buffer for static geometry.
    *   `skinned_models`: A dynamic vertex buffer for skinned geometry.
    *   `transparency`: Boolean flag controlling alpha filtering [S2, unofficial].

**Parameters:**
*   `LocalToWorld`: A `Matrix4x4` transformation matrix from local to world space. Default: Identity [S1, unofficial].
*   `Orientation`: An enum `DRAW_ORIENTATION` with values `XY` or `XZ`. Default: `XY` [S1, unofficial].
*   `Size`: The side length of the voxel. If `ScaleOnZoom` is enabled and the camera is orthographic, the size is scaled by `camera.orthographicSize / 10.0f` [S1, unofficial].
*   `transparency`: Boolean determining if the pass handles transparent voxels. Controls alpha filtering and blend state [S2, unofficial].
*   `skinning`: Boolean enabling the construction and use of a secondary pipeline with skinning support [S2, unofficial].
*   `DefaultColor`: Default color for voxels. Default: White [S1, unofficial].
*   `CullMode`: Rendering cull mode. Default: Off [S1, unofficial].

**Pipeline Construction:**
1.  Create a layout from descriptor set layouts.
2.  Build a basic pipeline with:
    *   Back-face culling enabled.
    *   Depth test function set to `Less`.
    *   Depth write enabled if the voxel is not transparent (`!transparent`).
    *   Optional premultiplied alpha blending [S2, unofficial].
3.  If `skinning` is enabled, build a child pipeline with a different vertex descriptor and skinned vertex shader [S2, unofficial].

**Rendering Steps:**
1.  **Preparation:**
    *   Fetch `VoxelMesh`, `Atlas`, `Handle<VoxelMesh>`, `Transform`, `JointTransforms`, and `Tint` from the world [S2, unofficial].
    *   Filter meshes by transparency match. Meshes are only processed if their alpha state matches the pass configuration to prevent incorrect blending or culling [S2, unofficial].
    *   Group meshes by material ID.
    *   Insert grouped data into `static_batches` or `skinned_batches` [S2, unofficial].
    *   Write batch data to `models` and `skinned_models` dynamic vertex buffers [S2, unofficial].

2.  **Drawing:**
    *   Bind the basic graphics pipeline, environment descriptor set, and iterate over `static_batches` [S2, unofficial].
    *   For each material, bind the material descriptor set.
    *   Iterate over mesh batches, calling `mesh.bind_and_draw` with instance ranges [S2, unofficial].

**Pseudocode (Immediate Mode Variant based on [S1, unofficial]):**
```python
def draw_voxels(vertices, colors, local_to_world, orientation, size, camera):
    """
    Renders voxels using immediate mode OpenGL-style calls.
    """
    if size <= 0:
        return

    # Handle orthographic scaling
    if camera.is_orthographic and camera.scale_on_zoom:
        effective_size = size * (camera.orthographic_size / 10.0)
    else:
        effective_size = size

    half = effective_size * 0.5

    # Set up matrix stack
    gl_push_matrix()
    gl_load_identity()
    
    # Model-View-Projection setup
    # Note: In modern OpenGL, this would be handled by shaders and uniforms.
    # Here we assume immediate mode state setting.
    model_view = camera.world_to_camera_matrix * local_to_world
    gl_modelview = model_view
    gl_load_projection_matrix(camera.projection_matrix)

    # Set material pass
    material.set_pass(0)

    gl_begin(gl_quads)

    for i in range(len(vertices)):
        x, y, z = vertices[i].x, vertices[i].y, vertices[i].z
        color = colors[i]
        
        gl_color(color)

        if orientation == DRAW_ORIENTATION.XY:
            # Draw square in XY plane at Z
            gl_vertex3(x + half, y + half, z)
            gl_vertex3(x + half, y - half, z)
            gl_vertex3(x - half, y - half, z)
            gl_vertex3(x - half, y + half, z)
            
        elif orientation == DRAW_ORIENTATION.XZ:
            # Draw square in XZ plane at Y
            gl_vertex3(x + half, y, z + half)
            gl_vertex3(x + half, y, z - half)
            gl_vertex3(x - half, y, z - half)
            gl_vertex3(x - half, y, z + half)

    gl_end()
    gl_pop_matrix()
```

**Pseudocode (Batched Variant based on [S2, unofficial]):**
```python
def render_voxel_batch(draw_voxel_state, world):
    """
    Renders voxel batches using a modern pipeline with descriptors.
    """
    # 1. Preparation
    static_batches = {}
    skinned_batches = {}
    
    for entity in world.entities:
        if not entity.has(VoxelMesh) or not entity.has(Transform):
            continue
            
        voxel_mesh = entity.get(VoxelMesh)
        transform = entity.get(Transform)
        atlas = voxel_mesh.atlas
        
        # Filter by transparency
        if voxel_mesh.alpha_state != draw_voxel_state.transparency:
            continue
            
        material_id = voxel_mesh.material_id
        if material_id not in static_batches:
            static_batches[material_id] = []
            
        # Add vertex arguments to batch
        static_batches[material_id].append(VertexArgs(
            transform=transform.matrix,
            atlas_handle=atlas,
            tint=entity.get(Tint, default=WHITE)
        ))
        
    # 2. Upload to Dynamic Vertex Buffers
    for material_id, args in static_batches.items():
        draw_voxel_state.models.upload(args)
        
    # 3. Drawing Loop
    draw_voxel_state.pipeline_basic.bind()
    draw_voxel_state.env_descriptor_set.bind()
    
    for material_id, args in static_batches.items():
        material_descriptor = draw_voxel_state.materials.get(material_id)
        material_descriptor.bind()
        
        # Issue draw call with instance ranges
        draw_voxel_state.models.bind_and_draw(
            pipeline=draw_voxel_state.pipeline_basic,
            instance_count=len(args)
        )
```

## Subtopics

### [OpenGL Client State Array Rendering](11008-opengl-client-state-array-rendering.md)
Renders pre-generated voxel mesh data using OpenGL client state arrays for vertices, normals, and colors, supporting both indexed and non-indexed drawing. It differs from modern core-profile rendering by relying on per-draw-call state enablement and pointer specification rather than encapsulated Vertex Array Objects (VAOs).

### [Dynamic VBO with Octree Rendering](13670-dynamic-vbo-with-octree-rendering.md)
A rendering approach for voxel terrain using an octree data structure where a single dynamic Vertex Buffer Object (VBO) is rebuilt every frame to contain geometry for visible octree nodes, combined with an index buffer. Unlike fixed-chunk approaches, this method rebuilds the VBO every frame based on visibility, allowing for dynamic LOD and culling. It builds on [Base Renderer Geometry](3902-base-renderer-geometry.md) by replacing static geometry uploads with a per-frame visibility-driven reconstruction.

## Operating characteristics
**Time and Memory Complexity:**
The complexity is linear with respect to the number of visible voxels $N$. Memory usage is proportional to the number of vertices and indices generated, which is $O(N)$ for the vertex buffer and $O(N)$ for the index buffer (if indexed). Immediate mode implementations have higher CPU overhead per draw call due to state changes and API calls, while batched implementations reduce this overhead by grouping draw calls.

**Measured Performance:**
Performance depends heavily on the graphics API and batching strategy. Immediate mode (e.g., legacy OpenGL `GL_QUADS`) is slow for large voxel counts due to the high number of draw calls and state changes. Batched rendering with dynamic VBOs improves performance by reducing API overhead. The use of index buffers (like `CUBE_INDICES`) reduces vertex data size compared to non-indexed quads.

**Strengths and Limitations:**
*   **Strengths:** Simple to implement; explicit geometry allows for easy integration with standard rasterization pipelines; supports various primitive types (lines, quads, cubes).
*   **Limitations:** High vertex count for large scenes; transparency handling requires careful sorting or blending state management; immediate mode is obsolete and inefficient on modern hardware.

**When to Use:**
Use for small-scale voxel visualization, debugging, or when integrating with legacy graphics APIs. Avoid for large-scale real-time applications where [Chunk-based Voxel Rendering Pipeline](14105-chunk-based-voxel-rendering-pipeline.md) or ray marching methods are more efficient.

## Background
The method originates from early voxel rendering techniques that treated voxels as geometric primitives. The specific index layouts and batching structures described in [S1, unofficial] and [S2, unofficial] are derived from open-source implementations in the context of voxel terrain and volume visualization. The immediate mode approach ([S1, unofficial]) reflects legacy OpenGL practices, while the batched descriptor-based approach ([S2, unofficial]) reflects modern Vulkan/DirectX-inspired architectures adapted for voxel data.
