# OpenGL Client State Array Rendering

Also called: OpenGL Rendering with Client State Arrays, RenderQuadArrays, RenderQuadGeometry, RenderTriangleArrays

## Overview
This method renders pre-generated voxel mesh data by configuring OpenGL's legacy client state arrays for vertices, normals, and colors, supporting both indexed and non-indexed drawing [S1, unofficial]. It sets itself apart from its siblings by explicitly managing the matrix stack and binding client-side buffers directly during draw calls, rather than relying on pre-uploaded Vertex Buffer Objects (VBOs) or procedural geometry generation in shaders [S1, unofficial].

## How it works
**Inputs and Outputs**
- **Input**: Host-side memory buffers containing vertex positions (3 floats), normals (3 floats), colors (4 floats), and optional indices (unsigned integers) [S1, unofficial].
- **Output**: Rasterized triangles or quads on the screen.

**Data Structures**
The vertex data layout consists of:
- **Position**: 3 floats (x, y, z) [S1, unofficial].
- **Normal**: 3 floats [S1, unofficial].
- **Color**: 4 floats (RGBA) [S1, unofficial].
- **Indices**: Unsigned integers (for indexed drawing) [S1, unofficial].

**Steps**
The rendering process configures the OpenGL matrix stack, binds the vertex buffer, enables and points to the client state arrays, issues the draw command, and restores state [S1, unofficial]. The following pseudocode implements the `RenderTriangleArrays` variant:

```python
def render_triangle_arrays(geometry_position, chunk_size, vertex_buffer, normal_buffer, color_buffer, vertex_count):
    # 1. Push current matrix to preserve state
    matrix_stack.append(current_matrix)
    # 2. Translate by geometryPosition * CHUNK_SIZE
    translation = translate_matrix(geometry_position * chunk_size)
    current_matrix = matrix_multiply(current_matrix, translation)
    # 3. Bind vertex buffer
    active_buffer = vertex_buffer
    # 4. Enable and set vertex array (3 floats, stride 0, offset 0)
    enabled_states.add(GL_VERTEX_ARRAY)
    vertex_array_config = (3, GL_FLOAT, 0, 0)
    # 5. Enable and set normal array (3 floats, stride 0, offset 0)
    enabled_states.add(GL_NORMAL_ARRAY)
    normal_array_config = (GL_FLOAT, 0, 0)
    # 6. Enable and set color array (4 floats, stride 0, offset 0)
    enabled_states.add(GL_COLOR_ARRAY)
    color_array_config = (4, GL_FLOAT, 0, 0)
    # 7. Draw triangles
    draw_arrays(GL_TRIANGLES, 0, vertex_count)
    # 8. Disable states
    enabled_states.discard(GL_COLOR_ARRAY)
    enabled_states.discard(GL_NORMAL_ARRAY)
    enabled_states.discard(GL_VERTEX_ARRAY)
    # 9. Pop matrix
    current_matrix = matrix_stack.pop()
```

**Variants**
1. **RenderQuadArrays**: Identical to `RenderTriangleArrays` but calls `draw_arrays(GL_QUADS, 0, vertex_count)` instead of `GL_TRIANGLES` [S1, unofficial].
2. **RenderQuadGeometry**: Sets the provoking vertex convention to `GL_FIRST_VERTEX_CONVENTION`, binds an element array buffer, and calls `draw_elements(GL_QUADS, ...)` with indices [S1, unofficial].

**Parameters**
- `BUFFER_OFFSET(0)`: A macro used to specify the buffer offset, assumed to be 0 [S1, unofficial].
- `stride`: Set to 0 for all array pointers as specified in the source [S1, unofficial].

## Subtopics

### [OpenGL Mesh Setup (VAO/VBO/EBO)](11322-opengl-mesh-setup-vao-vbo-ebo.md)
This method initializes OpenGL vertex arrays and buffers for a static mesh, uploading vertex positions, normals, and texture coordinates to GPU memory for rendering via indexed triangle lists. It sets apart from its siblings by explicitly managing the lifecycle of Vertex Array Objects (VAO), Vertex Buffer Objects (VBO), and Element Buffer Objects (EBO) to decouple host-side data structures from GPU-side storage, supporting both indexed and non-indexed drawing through a unified buffer upload pipeline. It builds on [OpenGL Client State Array Rendering](11008-opengl-client-state-array-rendering.md) by providing the concrete buffer management and attribute configuration required for those arrays.

### [Immediate Mode to Array Mode Optimization](17332-immediate-mode-to-array-mode-optimization.md)
Immediate Mode to Array Mode Optimization is a technique to optimize rendering performance by replacing the immediate mode API (`glBegin`/`glEnd` with per-vertex calls) with array-based drawing commands (`glDrawArrays`/`glDrawElements`), reducing driver overhead and state changes. It further improves performance by storing vertex data in GPU memory (Buffer Object) rather than client memory, reducing transfer overhead. This method builds on [OpenGL Client State Array Rendering](11008-opengl-client-state-array-rendering.md) by introducing the Vertex Buffer Object (VBO) extension.
