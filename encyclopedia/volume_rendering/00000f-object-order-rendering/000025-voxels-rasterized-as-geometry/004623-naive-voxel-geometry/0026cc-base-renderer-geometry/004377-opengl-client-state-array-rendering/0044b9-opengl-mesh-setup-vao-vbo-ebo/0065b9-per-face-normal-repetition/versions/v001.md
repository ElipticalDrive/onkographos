# Per-face Normal Repetition

Also called: Cube normal duplication, Flat shading normals, Per-face normal repetition for cube vertices

## Overview
Per-face normal repetition is a vertex buffer layout technique for voxel geometry where each face of a cube is assigned a single outward-facing normal vector, repeated for all four vertices of that face to achieve flat shading and correct per-face lighting [S1, unofficial]. It differs from smooth shading, which averages normals across shared vertices to create curved surfaces; this method preserves sharp edges and correct face orientation for voxel geometry [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A single cube mesh defined by 24 vertex positions (4 vertices per face × 6 faces) and 6 unique axis-aligned normal vectors.
*   **Output:** A vertex buffer containing 24 vertices and 24 normals, ready for OpenGL rasterization.

**Data Structures**
The vertex data consists of two interleaved or separate arrays, both of size 24 elements. Each element is a 3-component float vector.

1.  **Vertex Positions:** 24 vertices × 3 floats ($x, y, z$). The positions define the 8 corners of the cube, with each corner duplicated for the adjacent faces it belongs to, resulting in 24 unique position entries.
2.  **Vertex Normals:** 24 normals × 3 floats. The normals are ordered by face. For each of the 6 faces, the same normal vector is repeated 4 times in sequence.

**Normal Vector Definitions**
The 6 unique normal vectors correspond to the 6 faces of an axis-aligned cube:
*   Front: $(0, 0, -1)$
*   Back: $(0, 0, 1)$
*   Right: $(1, 0, 0)$
*   Left: $(-1, 0, 0)$
*   Bottom: $(0, -1, 0)$
*   Top: $(0, 1, 0)$

**Numbered Steps**
1.  Define the 24 vertex positions for the 6 faces of the cube. Each face has 4 vertices.
2.  Define the 6 unique normal vectors listed above.
3.  Construct the normal array by duplicating each of the 6 normal vectors exactly 4 times in sequence. The order of faces in the normal array must match the order of faces in the position array.
4.  Store the duplicated normals in a buffer (e.g., `FloatBuffer`) aligned with the vertex positions.
5.  Bind the normal data to the graphics pipeline (e.g., via `glVertexAttribPointer`).

**Pseudocode**
The following Python-like pseudocode demonstrates the construction of the normal array. It assumes `positions` is a list of 24 vertices, grouped by face.

```python
def generate_per_face_normals(positions):
    """
    Generates per-face normals for a cube mesh.
    
    Args:
        positions: A list of 24 vertices (each a tuple of 3 floats).
                   The list is assumed to be ordered by face:
                   positions[0:4] are the 4 vertices of face 0,
                   positions[4:8] are the 4 vertices of face 1, etc.
    
    Returns:
        A list of 24 normals (each a tuple of 3 floats).
    """
    # Define the 6 unique normals for the 6 faces of an axis-aligned cube
    # Order must match the order of faces in the positions list
    unique_normals = [
        (0.0, 0.0, -1.0),  # Face 0
        (0.0, 0.0, 1.0),   # Face 1
        (1.0, 0.0, 0.0),   # Face 2
        (-1.0, 0.0, 0.0),  # Face 3
        (0.0, -1.0, 0.0),  # Face 4
        (0.0, 1.0, 0.0)    # Face 5
    ]
    
    normals = []
    
    # Iterate over each face (6 faces total)
    for face_index in range(6):
        normal = unique_normals[face_index]
        # Repeat the normal for each of the 4 vertices of the face
        for _ in range(4):
            normals.append(normal)
            
    return normals
```

**Parameters**
*   **Cube Size:** Not specified in sources, but typically defined by `BLOCK_SIZE` in voxel engines [S1, unofficial].
*   **Normal Precision:** Float32 is standard [S1, unofficial].

**Edge Cases and Pitfalls**
*   **Mismatched Counts:** If the number of normal vectors does not match the number of vertex positions, the lighting pipeline will interpolate normals across faces, causing blocks to appear lit as if isolated from their neighbors [S1, unofficial].
*   **Incorrect Assignment:** Placing the normal data insertion call (e.g., `vertexNormalData.put()`) inside a loop instead of a single array initialization can cause incorrect normal assignment and break flat shading [S1, unofficial].
*   **Face Order Mismatch:** The order of normals in the array must correspond exactly to the order of vertices in the position array. If the face order in positions differs from the assumed order in the normal generation logic, lighting will be incorrect [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ for a single cube, as the number of vertices and normals is fixed.
*   **Memory Complexity:** $O(1)$ for a single cube. Each cube requires 24 normals × 3 floats × 4 bytes = 288 bytes for normals, plus 288 bytes for positions (assuming float32).
*   **Measured Performance:** Not given in the sources.
*   **Strengths:** Simple to implement; produces correct flat shading for voxel geometry; preserves sharp edges.
*   **Limitations:** Only suitable for axis-aligned cubes; does not support smooth shading or curved surfaces.
*   **When to Use:** Voxel engines, Minecraft-like block renderers, and fixed-function or basic shader lighting pipelines [S1, unofficial].
*   **When Not to Use:** When smooth shading or curved surfaces are required [S1, unofficial].

## Background
This technique is commonly used in voxel engines and Minecraft-like block renderers [S1, unofficial]. It was discussed in a Stack Overflow question in June 2014 regarding adding normals to a voxel engine's 16x16 cube chunks [S1, unofficial].
