# Bounding Box Drawing

Also called: debug box, Selection Box, edge highlight, AABB Wireframe Rendering, Wireframe Outline Rendering, Wireframe Bounding Box Visualization

## Overview
Bounding Box Drawing renders the wireframe outline of an Axis-Aligned Bounding Box (AABB) to provide visual context for voxel data, such as highlighting a selected voxel or defining the volume's spatial extent [S1, S3, S4, unofficial]. It differs from [Axis-Aligned Bounding Box Geometry](1317-axis-aligned-bounding-box-geometry.md) by explicitly using line primitives (edges) rather than filled geometry, and serves as a debug/visualization aid rather than contributing to the final volumetric appearance [S1, S3, S4, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** AABB bounds (min/max coordinates or center/size), camera view/projection matrices, and a color specification.
*   **Outputs:** A wireframe rendering of 12 edges on the screen.

**Data Structures:**
*   **Vertex Data:** A list of 24 vertices (3 floats per vertex: $x, y, z$) defining the 12 edges of a unit cube or scaled box. The vertices are ordered to form 12 line segments (6 for the bottom face, 6 for the top face, and 4 vertical connectors, though often implemented as 2 loops of 4 and 4 verticals, totaling 24 unique vertex positions if not duplicated, or 48 if duplicated for `GL_LINES` without index buffers). In the vertex-shader-only approach, no vertex buffer is used; vertices are generated per-fragment or per-vertex in the shader [S3, unofficial]. In the VBO approach, 24 vertices are uploaded to a VBO [S4, unofficial].
*   **Transformation Matrix:** A $4 \times 4$ matrix combining translation to the target position, scaling (for outline thickness/offset), and rotation (if non-axis-aligned, though typically AABB implies axis-aligned) [S4, unofficial][S5].

**Steps:**
1.  **Setup Rendering State:**
    *   Push current OpenGL attributes [S1, unofficial].
    *   Disable lighting to ensure uniform color [S1, S4, unofficial].
    *   Set line width (e.g., 1.5 to 3.0) [S1, S4, unofficial].
    *   Enable line smooth and blending (e.g., `GL_SRC_ALPHA`, `GL_ONE_MINUS_SRC_ALPHA`) for anti-aliased edges [S1, unofficial].
    *   Enable depth testing to allow voxels to occlude the box if desired, or disable it to ensure the box is always visible [S3, S4, unofficial]. Note: [S3, unofficial] uses depth testing to hide edges behind voxels, while [S4, unofficial] implies standard depth testing for occlusion.
2.  **Define Geometry:**
    *   Calculate the 8 corners of the AABB based on min/max bounds or center/size.
    *   Define the 12 edges connecting these corners.
    *   *Optional Offset:* Scale the box slightly larger (e.g., by 0.002 or 0.005 units) to prevent z-fighting with voxel faces [S3, S4, unofficial].
3.  **Apply Transformation:**
    *   Translate the box to the target voxel position [S4, unofficial].
    *   Apply the offset scaling [S4, unofficial].
    *   *Vertex Shader Approach:* Generate vertices directly in the vertex shader using the transformed bounds [S3, unofficial].
    *   *VBO Approach:* Upload the 24 vertices to a VBO and bind the VAO [S2, S4, unofficial].
4.  **Render:**
    *   Draw the 12 edges using `GL_LINES` (24 vertices) or `GL_LINE_LOOP` (8 vertices per face, 2 loops) [S1, S4, unofficial].
    *   *Depth Offset:* If using depth testing, apply a small depth bias or move lines nearer to the camera in the shader to prevent occlusion by voxel faces [S3, unofficial].
5.  **Cleanup:**
    *   Disable line smooth and blend [S1, unofficial].
    *   Re-enable lighting [S1, unofficial].
    *   Pop attributes [S1, unofficial].

**Formulas:**
*   **Transformation Matrix ($P$):**
    $$ P = T(pos) \cdot S(scale) \cdot T(-center) $$
    Where $T$ is translation, $S$ is scaling, $pos$ is the target center, and $center$ is the local box center (usually origin) [S4, unofficial].
*   **Lattice Integration (R):**
    $$ P = \begin{pmatrix} \text{scale} & \text{shift} \\ 0 & 1 \end{pmatrix} $$
    $$ rot.mat_{new} = rot.mat_{old} \times P $$
    $$ tr = \begin{pmatrix} x & y & z & 1 \end{pmatrix} \times pmat $$
    $$ x_{out} = tr_x / tr_w, \quad y_{out} = tr_y / tr_w, \quad z_{out} = tr_z / tr_w $$
    [S5]

**Parameters:**
*   **Line Width:** 1.5 to 3.0 pixels [S1, S4, unofficial].
*   **Scale Offset:** 0.002 to 0.005 units larger than the voxel [S3, S4, unofficial].
*   **Color:** White (1,1,1,1) or Black (0,0,0,1) [S1, S3, unofficial].

**Edge Cases and Pitfalls:**
*   **Z-Fighting/Occlusion:** Without a depth offset or depth bias, voxel faces may occlude the wireframe edges [S3, unofficial].
*   **Precision:** Floating-point precision issues may cause gaps in the wireframe if vertices are not perfectly aligned [S3, unofficial].
*   **Degenerate Input:** Empty volumes or zero-sized boxes should be handled gracefully (e.g., skip drawing) [S4, unofficial].

**Pseudocode:**
```python
def draw_bounding_box(min_pos, max_pos, view_matrix, projection_matrix, color=(1.0, 1.0, 1.0, 1.0)):
    """
    Draws a wireframe bounding box for the given AABB.
    """
    # 1. Setup State
    gl_push_attrib(GL_CURRENT_BIT | GL_ENABLE_BIT)
    gl_disable(GL_LIGHTING)
    gl_color4f(*color)
    gl_line_width(1.5)
    gl_enable(GL_LINE_SMOOTH)
    gl_hint(GL_LINE_SMOOTH_HINT, GL_NICEST)
    gl_enable(GL_BLEND)
    gl_blend_func(GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA)
    gl_enable(GL_DEPTH_TEST) # Or disable if box must always be on top

    # 2. Define Vertices (24 vertices for 12 lines)
    # Corners of the box
    corners = [
        (min_pos.x, min_pos.y, min_pos.z), (max_pos.x, min_pos.y, min_pos.z),
        (max_pos.x, max_pos.y, min_pos.z), (min_pos.x, max_pos.y, min_pos.z),
        (min_pos.x, min_pos.y, max_pos.z), (max_pos.x, min_pos.y, max_pos.z),
        (max_pos.x, max_pos.y, max_pos.z), (min_pos.x, max_pos.y, max_pos.z)
    ]
    
    # Edges: 12 lines, each defined by 2 vertices
    edges = [
        (0, 1), (1, 2), (2, 3), (3, 0), # Bottom face
        (4, 5), (5, 6), (6, 7), (7, 4), # Top face
        (0, 4), (1, 5), (2, 6), (3, 7)  # Verticals
    ]
    
    # 3. Draw
    gl_begin(GL_LINES)
    for v1_idx, v2_idx in edges:
        gl_vertex3f(*corners[v1_idx])
        gl_vertex3f(*corners[v2_idx])
    gl_end()

    # 4. Cleanup
    gl_disable(GL_LINE_SMOOTH)
    gl_disable(GL_BLEND)
    gl_enable(GL_LIGHTING)
    gl_pop_attrib()
```

## Subtopics

### Wireframe Integration with Lattice/Persp
Integrates bounding box drawing with R's `lattice` and `persp` plotting systems. It requires computing shifting and scaling matrices based on the lattice's coordinate transformations and incorporating them into the transformation matrix applied to the contour. The `drawScene` function is called with `add=TRUE` to draw in the graphics viewport. For `persp`, the bounding box is reconstructed using a `trans3dz` function that includes z-values of transformed coordinates, and the front-most corner is identified to redraw damaged parts of the box. This method handles the specific coordinate system and projection of R's 3D plotting tools [S5].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per frame, as it draws a fixed number of primitives (12 lines) regardless of volume size [S1, S3, S4, unofficial].
*   **Memory Complexity:** $O(1)$ for vertex data (24 vertices) [S4, unofficial].
*   **Performance:** Extremely fast; negligible impact on frame rate [S3, unofficial].
*   **Strengths:** Simple to implement, low overhead, effective for debugging and selection feedback [S1, S3, S4, unofficial].
*   **Limitations:** Only shows bounds, not internal structure; can be occluded by voxels if not handled correctly [S3, unofficial].
*   **When to Use:** Debugging voxel positions, highlighting selected voxels, visualizing volume extents [S1, S3, S4, unofficial].
*   **When Not to Use:** When detailed internal structure visualization is required; use ray marching or ray casting instead [S1, unofficial].

## Background
Bounding box drawing is a standard technique in computer graphics for visualization and debugging. It has been used in various voxel engines and raycasting renderers to provide spatial context for voxel data [S1, S3, S4, unofficial]. The method is often implemented using OpenGL's line primitives and has been adapted for integration with higher-level plotting libraries like R's `lattice` [S5].
