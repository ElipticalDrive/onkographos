# Bounding Box Drawing

Also called: debug box, Selection Box, edge highlight, AABB Wireframe Rendering, Wireframe Outline Rendering, Wireframe Bounding Box Visualization

## Overview
Bounding Box Drawing renders the wireframe outline of an Axis-Aligned Bounding Box (AABB) to provide visual context for volume data or to highlight a specific selected voxel [S1, S2, S4, unofficial]. It solves the problem of spatial orientation and selection feedback in voxel-based environments by drawing the 12 edges of the box as line primitives [S3, unofficial]. It differs from [Axis-Aligned Bounding Box Geometry](1317-axis-aligned-bounding-box-geometry.md) by focusing on the rendering of the wireframe edges for debug/selection purposes rather than generating geometry for collision or physics [S1, S2, S4, unofficial].

## How it works
The method renders a wireframe box using OpenGL line primitives, either by defining vertices directly in immediate mode or by generating them in a vertex shader [S1, S3, S4, unofficial]. The box is typically centered at a target position (e.g., the center of a selected voxel) and scaled slightly larger than the voxel unit to ensure visibility [S3, S4, unofficial].

### Inputs and Outputs
*   **Inputs**:
    *   Volume dimensions (`dim_x`, `dim_y`, `dim_z`) or voxel center position (`pos`) [S1, S4, unofficial].
    *   Camera view and projection matrices (`view_projection`, `view_rotation`, `view_translation`, `far_plane`) [S2, unofficial].
    *   Color (`u_color`) and line width parameters [S1, S2, S4, unofficial].
*   **Outputs**:
    *   Rendered wireframe lines on the screen [S1, S3, S4, unofficial].

### Data Structures
*   **Vertex Data**:
    *   For immediate mode or static VBO: An array of 24 vertices (72 floats) defining the 12 edges of a unit cube [S2, S4, unofficial].
    *   The 24 vertices correspond to 12 lines (2 vertices per line).
    *   Coordinates are typically defined relative to the box center, e.g., $\pm 0.5$ for a unit cube, or scaled by volume dimensions [S1, S4, unofficial].
    *   Layout: `float verticesBox[72]` containing $(x, y, z)$ for each of the 24 vertices [S4, unofficial].
*   **Shader Uniforms**:
    *   `u_color`: vec4 [S2, unofficial].
    *   `u_projection`: mat4 [S2, unofficial].
    *   `u_view_rotation`: mat3 or mat4 [S2, unofficial].
    *   `u_far`: float [S2, unofficial].
    *   `u_view_translation`: vec3 [S2, unofficial].
    *   `u_model`: mat4 (for translation and scaling) [S4, unofficial].

### Steps
1.  **Setup Rendering State**:
    *   Push current attributes [S1, unofficial].
    *   Disable lighting (`glDisable(GL_LIGHTING)`) [S1, unofficial].
    *   Set color to white or specified highlight color (`glColor4d(1.0, 1.0, 1.0, 1.0)` or `u_color`) [S1, S2, unofficial].
    *   Set line width (e.g., 1.5 or 3.0) [S1, S4, unofficial].
    *   Enable line smooth and blend (`glEnable(GL_LINE_SMOOTH)`, `glEnable(GL_BLEND)`) [S1, unofficial].
    *   Enable depth testing (`glEnable(GL_DEPTH_TEST)`) [S2, S3, unofficial].
2.  **Compute Transformation**:
    *   Translate the model matrix to the target position `pos` (e.g., voxel center) [S4, unofficial].
    *   Scale the box slightly larger than the voxel unit (e.g., scale by 1.002 or add an offset of 0.005 voxels) [S3, S4, unofficial].
    *   Apply a depth offset in the vertex shader to move lines slightly nearer to the camera to prevent z-fighting with voxel faces [S3, unofficial].
3.  **Generate/Upload Vertices**:
    *   *Immediate Mode*: Define 6 line loops (12 edges) using vertices at $\pm dim_x/2, \pm dim_y/2, \pm dim_z/2$ [S1, unofficial].
    *   *VBO/Shader*: Upload the 24-vertex array to a VBO (`aabb_vbo`) with `GL_STATIC_DRAW` [S2, unofficial].
    *   *Vertex Shader*: Generate vertices dynamically based on the transformed model matrix [S3, unofficial].
4.  **Draw**:
    *   Bind the shader program (`aabb_shader`) and Vertex Array Object (`aabb_vao`) [S2, unofficial].
    *   Draw the lines using `glDrawArrays(GL_LINES, 0, 24)` or `glBegin(GL_LINE_LOOP)` [S1, S2, S4, unofficial].
5.  **Cleanup**:
    *   Disable line smooth and blend [S1, unofficial].
    *   Re-enable lighting [S1, unofficial].
    *   Pop attributes [S1, unofficial].
    *   Reset geometry buffer length if applicable [S2, unofficial].

### Pseudocode
```python
def draw_bounding_box(volume, camera, color=(1.0, 1.0, 1.0, 1.0)):
    # 1. Setup State
    gl_push_attrib(GL_CURRENT_BIT)
    gl_disable(GL_LIGHTING)
    gl_color4d(*color)
    gl_line_width(1.5)
    gl_enable(GL_LINE_SMOOTH)
    gl_hint(GL_LINE_SMOOTH_HINT, GL_NICEST)
    gl_enable(GL_BLEND)
    gl_blend_func(GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA)
    gl_enable(GL_DEPTH_TEST)

    # 2. Draw Box (Immediate Mode Example)
    # Define half-dimensions
    hx = volume.dim_x / 2.0
    hy = volume.dim_y / 2.0
    hz = volume.dim_z / 2.0

    # Bottom face (z = -hz)
    gl_begin(GL_LINE_LOOP)
    gl_vertex3d(-hx, -hy, -hz)
    gl_vertex3d(-hx,  hy, -hz)
    gl_vertex3d( hx,  hy, -hz)
    gl_vertex3d( hx, -hy, -hz)
    gl_end()

    # Top face (z = +hz)
    gl_begin(GL_LINE_LOOP)
    gl_vertex3d(-hx, -hy, hz)
    gl_vertex3d(-hx,  hy, hz)
    gl_vertex3d( hx,  hy, hz)
    gl_vertex3d( hx, -hy, hz)
    gl_end()

    # Vertical edges
    gl_begin(GL_LINES)
    gl_vertex3d(-hx, -hy, -hz)
    gl_vertex3d(-hx, -hy,  hz)
    gl_vertex3d(-hx,  hy, -hz)
    gl_vertex3d(-hx,  hy,  hz)
    gl_vertex3d( hx,  hy, -hz)
    gl_vertex3d( hx,  hy,  hz)
    gl_vertex3d( hx, -hy, -hz)
    gl_vertex3d( hx, -hy,  hz)
    gl_end()

    # 3. Cleanup
    gl_disable(GL_LINE_SMOOTH)
    gl_disable(GL_BLEND)
    gl_enable(GL_LIGHTING)
    gl_pop_attrib()
```

### Parameters
*   **Line Width**: 1.5 to 3.0 pixels [S1, S4, unofficial].
*   **Scale Offset**: 0.005 voxels larger than the voxel unit, or a scale factor of 1.002 [S3, S4, unofficial].
*   **Color**: White (1,1,1,1) or custom selection color [S1, S2, S4, unofficial].

### Edge Cases and Pitfalls
*   **Z-Fighting**: Without a depth offset in the shader, voxel faces may occlude parts of the selection lines [S3, unofficial].
*   **Precision**: Ray origins exactly on voxel boundaries with negative directions require careful handling to avoid starting inside the wrong voxel [S3, unofficial].
*   **Degenerate Input**: Ensure volume dimensions are non-zero to avoid division by zero in half-dimension calculations [S1, unofficial].

## Subtopics

### Wireframe Integration with Lattice/Persp
This variant integrates bounding box wireframes into R's `lattice` and `persp` plotting environments [S5]. It requires custom panel functions to compute shifting and scaling matrices based on lattice's coordinate transformations [S5]. The transformation matrix $P$ is constructed as:
$$P = \begin{pmatrix} \text{scale} & \text{shift} \\ 0 & 1 \end{pmatrix}$$
where scale and shift are derived from lattice's scaled coordinates [S5]. The rotation matrix is updated as $rot.mat_{new} = rot.mat_{old} \times P$ [S5]. For `persp` integration, the bounding box is reconstructed using a `trans3dz` function that includes z-values of transformed coordinates:
$$tr = \begin{pmatrix} x & y & z & 1 \end{pmatrix} \times pmat$$
$$x_{out} = tr_x / tr_w, \quad y_{out} = tr_y / tr_w, \quad z_{out} = tr_z / tr_w$$
The front-most corner is identified to redraw the damaged bounding box [S5].

## Operating characteristics
*   **Time Complexity**: $O(1)$ per frame, as the number of vertices and lines is fixed (24 vertices, 12 lines) [S1, S3, S4, unofficial].
*   **Memory Complexity**: $O(1)$, requiring only a small static buffer for 24 vertices [S2, S4, unofficial].
*   **Performance**: Extremely fast; suitable for real-time debug overlays in voxel engines [S3, S4, unofficial].
*   **Strengths**: Simple to implement, low overhead, provides clear spatial context [S1, S3, S4, unofficial].
*   **Limitations**: Only shows the outer boundary; does not convey internal structure [S1, S3, S4, unofficial].
*   **When to Use**: Debugging, selection highlighting, spatial orientation [S1, S3, S4, unofficial].
*   **When Not to Use**: When internal volume structure needs to be visualized (use ray marching or slicing instead) [S1, S3, S4, unofficial].

## Background
Bounding box drawing is a standard technique in computer graphics for debugging and visualization [S1, S2, S4, unofficial]. It is commonly used in voxel engines to highlight selected blocks or to visualize the extent of volume data [S1, S3, S4, unofficial]. The method has been implemented in various contexts, from OpenGL immediate mode to modern shader-based pipelines [S1, S2, S3, S4, unofficial].
