# Wireframe Block Highlighter

Also called: Voxel Block Wireframe Outline

## Overview
The Wireframe Block Highlighter draws a wireframe outline around a target voxel block using 12 LineRenderer components [S1, unofficial]. It solves the problem of identifying specific block coordinates in a dense voxel grid by drawing a wireframe box slightly larger than the block itself [G]. It differs from face-based highlighting methods by enclosing the entire volume of the block rather than marking a specific surface normal, making it suitable for general selection or debugging where the block's position is the primary concern rather than its orientation [G].

## How it works
**Inputs:**
- Target block position $(x, y, z)$ in voxel space [S1, unofficial].
- Outline padding parameter $p$ [S1, unofficial].
- Line width parameter $w$ [S1, unofficial].
- Outline color $C$ [S1, unofficial].

**Outputs:**
- 12 line segments defining the cube edges [S1, unofficial].

**Data Structures:**
- **Edges Array**: A static array of 12 pairs of corner indices [S1, unofficial]. Each pair defines a line segment between two vertices of the unit cube [G]. The indices correspond to the 8 corners of the cube, indexed 0–7 [G].
  - Layout: `[{0,1}, {1,2}, {2,3}, {3,0}, {4,5}, {5,6}, {6,7}, {7,4}, {0,4}, {1,5}, {2,6}, {3,7}]` [S1, unofficial].
  - Corner mapping (standard unit cube):
    - 0: $(0,0,0)$
    - 1: $(1,0,0)$
    - 2: $(1,1,0)$
    - 3: $(0,1,0)$
    - 4: $(0,0,1)$
    - 5: $(1,0,1)$
    - 6: $(1,1,1)$
    - 7: $(0,1,1)$

**Parameters:**
- Line width $w = 0.025$ [S1, unofficial].
- Outline padding $p = 0.01$ [S1, unofficial].
- Outline color $C = \text{Color.black}$ [S1, unofficial].

**Steps:**
1. **Calculate Block Bounds**:
   - Define the block's local bounds in voxel space:
     $$ \text{min}_{local} = (x, y, z) $$
     $$ \text{max}_{local} = (x+1, y+1, z+1) $$
   - Apply padding to create the wireframe bounds:
     $$ \text{min}_{wire} = \text{min}_{local} - (p, p, p) $$
     $$ \text{max}_{wire} = \text{max}_{local} + (p, p, p) $$
2. **Compute Corner Vertices**:
   - Generate the 8 vertices of the padded cube using $\text{min}_{wire}$ and $\text{max}_{wire}$ [S1, unofficial]. Let $V_i$ be the vertex corresponding to corner index $i$ [G].
   - Example for $V_0$:
     $$ V_0 = (\text{min}_{wire}.x, \text{min}_{wire}.y, \text{min}_{wire}.z) $$
   - Example for $V_6$:
     $$ V_6 = (\text{max}_{wire}.x, \text{max}_{wire}.y, \text{max}_{wire}.z) $$
3. **Generate Line Segments**:
   - Iterate through the 12 edge pairs in the Edges array [S1, unofficial].
   - For each pair $\{i, j\}$, create a line segment from vertex $V_i$ to vertex $V_j$ [S1, unofficial].
   - Render these segments using a line renderer with width $w$ and color $C$ [S1, unofficial].

**Pseudocode:**
```python
def render_wireframe_highlight(block_pos, padding, line_width, color):
    # 1. Calculate padded bounds
    min_wire = (block_pos[0] - padding, block_pos[1] - padding, block_pos[2] - padding)
    max_wire = (block_pos[0] + 1.0 + padding, block_pos[1] + 1.0 + padding, block_pos[2] + 1.0 + padding)
    
    # 2. Define the 8 corners of the padded cube
    # Indices: 0:(0,0,0), 1:(1,0,0), 2:(1,1,0), 3:(0,1,0), 
    #          4:(0,0,1), 5:(1,0,1), 6:(1,1,1), 7:(0,1,1)
    corners = [
        (min_wire[0], min_wire[1], min_wire[2]), # 0
        (max_wire[0], min_wire[1], min_wire[2]), # 1
        (max_wire[0], max_wire[1], min_wire[2]), # 2
        (min_wire[0], max_wire[1], min_wire[2]), # 3
        (min_wire[0], min_wire[1], max_wire[2]), # 4
        (max_wire[0], min_wire[1], max_wire[2]), # 5
        (max_wire[0], max_wire[1], max_wire[2]), # 6
        (min_wire[0], max_wire[1], max_wire[2])  # 7
    ]
    
    # 3. Define the 12 edges as pairs of corner indices
    edges = [
        (0, 1), (1, 2), (2, 3), (3, 0), # Bottom face
        (4, 5), (5, 6), (6, 7), (7, 4), # Top face
        (0, 4), (1, 5), (2, 6), (3, 7)  # Vertical edges
    ]
    
    # 4. Render lines
    lines = []
    for start_idx, end_idx in edges:
        start_point = corners[start_idx]
        end_point = corners[end_idx]
        lines.append((start_point, end_point, line_width, color))
    return lines
```

## Subtopics

### Voxel Face Highlight Placement
This variant highlights a specific face of the voxel block rather than the entire block outline [G]. It is chosen when the user needs to identify the surface normal or the specific side of a block being targeted, rather than just the block's location [G]. It differs from the Wireframe Block Highlighter by adjusting the highlight position based on the face normal to avoid z-fighting and by rotating the highlight mesh to align with the face [S2, unofficial].
- **Steps**:
  1. Convert global voxel coordinates to local coordinates using the world's coordinate system [S2, unofficial].
  2. Calculate the distance $d$ from the camera to the highlight position [S2, unofficial].
  3. Iterate over the 3 axes (x, y, z). For each axis $i$:
     - If the normal component $n_i$ is 0, add 0.5 to the position to center the highlight on the face: $pos_i += 0.5$ [S2, unofficial].
     - If $n_i \neq 0$, add an offset based on the normal direction:
       $$ pos_i += \begin{cases} 1 + \text{slop} & \text{if } n_i > 0 \\ -\text{slop} & \text{if } n_i < 0 \end{cases} $$
       where $\text{slop} = 0.001 + 0.001 \times d$ [S2, unofficial].
  4. Apply the calculated position to the highlight mesh [S2, unofficial].
  5. Set rotation based on the normal axes:
     - If $n_y \neq 0$, set $rotation.x = \pi/2$ [S2, unofficial].
     - If $n_x \neq 0$, set $rotation.y = \pi/2$ [S2, unofficial] [G: Assumes axis-aligned faces; other orientations may require quaternion rotation].
- **Parameters**:
  - `slop`: Z-fighting avoidance offset, calculated as $0.001 + 0.001 \times \text{distance}$ [S2, unofficial].
- **Pitfalls**:
  - Z-fighting is avoided by the distance-dependent `slop` offset [S2, unofficial].
  - The rotation logic assumes axis-aligned faces; it sets X or Y rotation to 90 degrees based on normal components [S2, unofficial].

## Background
The Wireframe Block Highlighter is a common technique in voxel-based game development and debugging tools [G]. It draws a wireframe outline around a target voxel block using 12 LineRenderer components [S1, unofficial]. The method is often paired with raycasting to determine the target block and then rendered as a debug overlay [G].
