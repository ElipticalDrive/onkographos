# Axis-Aligned Bounding Box Geometry

Also called: AABB Geometry, RenderClippedBoundingBox, Volume Extent Bounding Box

## Overview
This method generates and uploads geometry for a volume's spatial extent to the graphics pipeline, optionally including texture coordinates [S1, S2, unofficial]. It serves as a debug primitive to delineate the volume boundaries [S2, unofficial]. It builds on the [Debug and Visualization](4974-debug-and-visualization.md) principles by converting volume extent data into geometric primitives submitted to the graphics pipeline [G].

## How it works
**Inputs and Outputs:**
*   **Inputs:**
    *   `currentBlock`: `size_t` index of the current rendering block [S1, unofficial].
    *   `numberOfBlocks`: `size_t` total number of blocks to process [S1, unofficial].
    *   `tcoordFlag`: Boolean/int flag indicating whether to render texture coordinates [S1, unofficial].
    *   `renWin`: Pointer to the render window context (e.g., `vtkRenderWindow`) [S1, unofficial].
    *   `minB`, `maxB`: The minimum and maximum corners of the bounding box [S2, unofficial].
    *   `img_size`: Optional image dimensions used for texture coordinate normalization [S3, unofficial].
*   **Outputs:**
    *   Vertex array and buffer objects configured for drawing [S2, unofficial].

**Data Structures:**
*   **Vertices Array:** A static array of 36 floats (12 triangles × 3 vertices × 3 components) defining the 6 faces of the box [S2, unofficial].

**Steps:**
1.  **Validation:** Check if `currentBlock` is within the valid range $[0, \text{numberOfBlocks})$. Return false to abort rendering if out of bounds [S1, unofficial].
2.  **Geometry Generation:** Define the 8 corners of the axis-aligned bounding box from `minB` and `maxB`. Order the vertices as: $(x_0,y_0,z_1), (x_1,y_0,z_1), (x_1,y_1,z_1), (x_0,y_1,z_1), (x_0,y_0,z_0), (x_1,y_0,z_0), (x_1,y_1,z_0), (x_0,y_1,z_0)$ where $x_0=\text{minB}.x$, $y_0=\text{minB}.y$, $z_0=\text{minB}.z$, $x_1=\text{maxB}.x$, $y_1=\text{maxB}.y$, $z_1=\text{maxB}.z$ [S3, unofficial].
3.  **Texture Coordinates (Optional):** If `tcoordFlag` is true and `img_size` is provided, compute deltas $dx = 0.5 / \text{img\_size}.x$, $dy = 0.5 / \text{img\_size}.y$, $dz = 0.5 / \text{img\_size}.z$. Compute normalized coordinates $x_0 = \text{min\_corner}.x / \text{img\_size}.x + dx$, $x_1 = \text{max\_corner}.x / \text{img\_size}.x - dx$, $y_0 = \text{min\_corner}.y / \text{img\_size}.y + dy$, $y_1 = \text{max\_corner}.y / \text{img\_size}.y - dy$, $z_0 = \text{min\_corner}.z / \text{img\_size}.z + dz$, $z_1 = \text{max\_corner}.z / \text{img\_size}.z - dz$. Assign these coordinates to the corresponding vertices [S3, unofficial].
4.  **Buffer Upload:** Create VAO and VBO, bind them, upload vertex data with `GL_STATIC_DRAW`, set vertex attribute pointer for 3 floats per vertex, and enable the attribute array [S2, unofficial].

**Pseudocode:**
```python
def render_aabb_geometry(current_block, number_of_blocks, tcoord_flag, min_b, max_b, img_size=None):
    # Step 1: Validation
    if current_block < 0 or current_block >= number_of_blocks:
        return False

    # Step 2: Geometry Generation
    x0, y0, z0 = min_b.x, min_b.y, min_b.z
    x1, y1, z1 = max_b.x, max_b.y, max_b.z
    # Vertex order per [S3, unofficial]
    vertices = [
        (x0, y0, z1), (x1, y0, z1), (x1, y1, z1), (x0, y1, z1),
        (x0, y0, z0), (x1, y0, z0), (x1, y1, z0), (x0, y1, z0)
    ]
    flat_vertices = [v for corner in vertices for v in corner]

    # Step 3: Texture Coordinates (Optional)
    tex_coords = None
    if tcoord_flag and img_size is not None:
        if img_size.x == 0 or img_size.y == 0 or img_size.z == 0:
            raise ValueError("Invalid image size")
        dx = 0.5 / img_size.x
        dy = 0.5 / img_size.y
        dz = 0.5 / img_size.z
        x0_t = min_b.x / img_size.x + dx
        x1_t = max_b.x / img_size.x - dx
        y0_t = min_b.y / img_size.y + dy
        y1_t = max_b.y / img_size.y - dy
        z0_t = min_b.z / img_size.z + dz
        z1_t = max_b.z / img_size.z - dz
        tex_coords = [
            (x0_t, y0_t, z1_t), (x1_t, y0_t, z1_t), (x1_t, y1_t, z1_t), (x0_t, y1_t, z1_t),
            (x0_t, y0_t, z0_t), (x1_t, y0_t, z0_t), (x1_t, y1_t, z0_t), (x0_t, y1_t, z0_t)
        ]
        flat_tex = [v for corner in tex_coords for v in corner]

    # Step 4: Buffer Upload & Setup (Standard graphics API operations)
    vao = allocate_vertex_array()
    vbo = allocate_buffer()
    bind_vertex_array(vao)
    bind_buffer(GL_ARRAY_BUFFER, vbo)
    copy_to_buffer(vbo, flat_vertices, GL_STATIC_DRAW)
    set_vertex_attribute(0, 3, GL_FLOAT, GL_FALSE, 3 * 4, None)
    enable_vertex_attribute(0)

    if tex_coords is not None:
        tex_vbo = allocate_buffer()
        bind_buffer(GL_ARRAY_BUFFER, tex_vbo)
        copy_to_buffer(tex_vbo, flat_tex, GL_STATIC_DRAW)
        set_vertex_attribute(1, 3, GL_FLOAT, GL_FALSE, 3 * 4, None)
        enable_vertex_attribute(1)

    bind_vertex_array(0)
    return True
```

**Parameters:**
*   `minB`: Default $(-1.0, -1.0, -0.42578125)$ [S2, unofficial].
*   `maxB`: Default $(1.0, 1.0, 0.42578125)$ [S2, unofficial].
*   `tcoordFlag`: Controls inclusion of texture coordinates [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Invalid Image Size:** If `img_size` components are zero, texture coordinate generation fails [S3, unofficial].

## Subtopics

### AABB Geometry Update
Updates the vertex positions of the volume box based on a new Axis-Aligned Bounding Box (AABB) [S3, unofficial]. It extracts the min and max corners of the new box, assigns them to the vertex positions in the order: $(x_0,y_0,z_1), (x_1,y_0,z_1), (x_1,y_1,z_1), (x_0,y_1,z_1), (x_0,y_0,z_0), (x_1,y_0,z_0), (x_1,y_1,z_0), (x_0,y_1,z_0)$, copies the vertices to the coordinate buffer (`mVertCoord`), and marks the geometry bounds as dirty to trigger a redraw [S3, unofficial]. This variant is chosen when the volume extent changes dynamically and needs to be reflected in the debug visualization without recreating the entire VAO/VBO [S3, unofficial].

## Background
The method originates from implementations in VTK-based volume ray casting and custom ray tracing engines [S1, S2, S3, unofficial]. It is used in debug and visualization tools to provide a visual cue for the volume's spatial boundaries [S1, S2, unofficial]. The specific vertex ordering and texture coordinate generation logic are documented in visualization library source code [S3, unofficial].
