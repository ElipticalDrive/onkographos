# Perspective Projection Rendering

Also called: Perspective Projection Rendering 2, Perspective Shear-Warp

## Overview
Perspective Projection Rendering is a volume rendering method that extends the shear-warp factorization to support perspective viewing transformations [S2, S12]. It solves the problem of rendering 3D scalar fields with perspective projection by decomposing the view matrix into shear, permutation, and warp components, applying perspective-specific scaling to volume slices during the shear phase [S2]. It sets itself apart from parallel projection variants by uniformly scaling each slice based on its depth to account for foreshortening, which requires more complex resampling than the parallel case [S1, unofficial][S2].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volume dataset $V$, a perspective viewing transformation matrix $M_{view}$, and a transfer function for classification.
*   **Output:** A 2D image $I$.

**Data Structures:**
*   **Run-Length Encoded (RLE) Volume:** To optimize coherence, the volume is pre-computed into RLE format. Each copy contains four bytes per non-transparent voxel and one byte per run [S2]. Three copies are typically pre-computed, one for each principal axis, to avoid re-encoding when the view direction changes [S3, S12].
*   **Intermediate Image:** A 2D buffer storing the composited result before the final warp.

**Method Steps:**

1.  **Permutation (Axis Selection):** Determine the principal viewing axis by finding the coordinate axis (X, Y, or Z) most aligned with the view direction vector $v_o$ [S12]. Construct a permutation matrix $P$ to align this axis with the Z-axis of the intermediate coordinate system [S2, S12].
2.  **Shear and Resampling (Perspective):** Transform each slice $z_0$ of the voxel data from object space to sheared object space [S2]. Unlike parallel projection, this step involves both translation and uniform scaling [S2]:
    *   Translate the slice by $(z_0 s'_x, z_0 s'_y)$.
    *   Scale the slice uniformly by a factor of $1/(1 + z_0 s'_w)$ [S2].
    *   Here, $s'_x, s'_y, s'_w$ are elements of the perspective shear matrix $S_{\text{persp}}$ derived from $M_{view}$ [S2].
    *   **Scaling Factors:** Choose scaling factors such that the closest slice has unit scaling (factor of 1); all other slices will have a scaling factor $< 1$, ensuring no slice is enlarged [S1, unofficial].
    *   **Resampling:** Use a box reconstruction filter and a box low-pass filter during resampling [S1, unofficial]. Because slices are scaled differently, more than two voxel scanlines may need to be traversed simultaneously to contribute to a single intermediate image scanline, and voxel scanlines may not be traversed at the same rate as image scanlines [S1, unofficial].
3.  **Composite:** Composite the resampled slices in front-to-back order into the intermediate image using the Porter-Duff "over" operator [S2, S12]:
    $$ C_{new} = C_{slice} \cdot \alpha_{slice} + C_{accum} \cdot (1 - \alpha_{slice}) $$
    $$ \alpha_{new} = \alpha_{slice} + \alpha_{accum} \cdot (1 - \alpha_{slice}) $$
    Early ray termination is supported by skipping further slices for pixels where accumulated opacity exceeds a threshold (e.g., 0.95) [S2, S11, abstract only, unofficial].
4.  **Warp:** Transform the intermediate image to the final image space using the 2D warp matrix $M_{\text{warp}}$ [S2]:
    $$ M_{\text{warp}} = S^{-1} \cdot P^{-1} \cdot M_{\text{view}} $$
    Resample the intermediate image using bilinear interpolation to produce the final image [S2, S12].

**Pseudocode:**

```python
def perspective_shear_warp_render(volume, M_view, image_width, image_height):
    # 1. Permutation
    view_dir = get_view_direction(M_view)
    P, principal_axis = determine_permutation_matrix(view_dir)
    
    # 2. Shear and Resampling
    # Extract perspective shear parameters from M_view
    # S_persp = [[1, 0, 0, 0],
    #            [0, 1, 1, 0],
    #            [s'x, s'y, 1, s'w],
    #            [0, 0, 0, 1]]
    s_prime_x, s_prime_y, s_prime_w = extract_perspective_shear_params(M_view)
    
    intermediate_image = zeros((image_height, image_width, 4)) # RGBA
    
    # Iterate slices along the principal axis (Z in sheared space)
    # Note: The number of slices and their z0 coordinates depend on the volume bounds and P
    for z0 in volume_slices(principal_axis):
        # Calculate scaling factor for this slice
        # Ensure closest slice has unit scaling; others < 1
        scale_factor = 1.0 / (1.0 + z0 * s_prime_w)
        
        # Translate offset
        tx = z0 * s_prime_x
        ty = z0 * s_prime_y
        
        # Resample slice with translation and scaling
        # Use box reconstruction and box low-pass filters
        # More than 2 voxel scanlines may contribute to one image scanline
        slice_image = resample_slice(volume, z0, tx, ty, scale_factor, 
                                     filter_type="box")
        
        # Composite into intermediate image
        # Front-to-back order is maintained by the slice iteration
        composite_front_to_back(intermediate_image, slice_image)
        
        # Early ray termination check could be applied here per pixel
        if early_ray_termination(intermediate_image, threshold=0.95):
            break
            
    # 3. Warp
    # M_warp = S^-1 * P^-1 * M_view
    M_warp = compute_warp_matrix(M_view, P)
    final_image = warp_image(intermediate_image, M_warp, interpolation="bilinear")
    
    return final_image
```

## Subtopics

### Perspective Projection Algorithm
A specific implementation of perspective projection rendering that utilizes run-length encoded volume data [S2]. It transforms each slice $z_0$ by translating it by $(z_0 s'_x, z_0 s'_y)$ and scaling it uniformly by $1/(1 + z_0 s'_w)$ [S2]. The RLE structure stores four bytes per non-transparent voxel and one byte per run [S2]. It is chosen when perspective viewing is required and memory allows for three RLE copies [S2]. Unlike the fast-classification algorithm, it does not suffer from performance degradation when the major viewing axis changes, provided the three RLE copies fit in memory [S2].

## Operating characteristics
*   **Time Complexity:** Rendering time is generally higher than parallel projection due to the additional scaling and resampling complexity [S1, unofficial][S2].
*   **Measured Performance:** On an SGI Indigo R4000, the algorithm renders the 128x128x109 'brainsmall' dataset in an average of 1.0 seconds and the 128x128x113 'headsmall' dataset in 1.1 seconds [S2]. Color renderings take 1.3x longer than grayscale renderings [S2].
*   **Memory Complexity:** Requires storing three run-length encoded copies of the volume, one for each principal axis [S3, S12]. For a 256x256x226 voxel dataset, these three copies total approximately 9.8 Mbytes [S2].
*   **Strengths:** Supports true perspective viewing; performance is stable regardless of the major viewing axis change, provided memory constraints are met [S2].
*   **Limitations:** Requires more complex resampling than parallel projection (more than 2 voxel scanlines may contribute to one image scanline) [S1, unofficial]; effectiveness of coherence optimizations varies with viewpoint [S2]; intermediate image size increases as rotation angle approaches 45 degrees [S2].

## Background
The method was introduced by Levoy and Whitted in their 1990 paper "Fast Volume Rendering Using a Shear-warp Factorization of The Viewing Transformation" [S2]. It extends the original shear-warp factorization, which was designed for parallel projections, to handle perspective transformations by introducing a perspective shear matrix [S2]. The approach was implemented on SGI Indigo workstations and demonstrated real-time capabilities for medical imaging datasets [S2].
