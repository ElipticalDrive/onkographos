# Perspective Projection Rendering

Also called: Perspective Projection Rendering 2, Perspective Shear-Warp

## Overview
Perspective Projection Rendering extends the Shear-warp algorithm to support perspective viewing transformations by scaling each volume slice in addition to shearing it [S2][S1, unofficial]. It solves the problem of rendering 3D volumes with perspective projection, which introduces foreshortening that standard parallel projection shear-warp methods cannot handle [S2]. Unlike the [Parallel Projection Rendering](5556-parallel-projection-rendering.md) variant, it accounts for depth-dependent scaling, ensuring that farther slices are rendered smaller to match perspective geometry [S1, unofficial].

## How it works
The method factorizes the general viewing transformation matrix $M_{view}$ into a permutation matrix $P$, a perspective shear matrix $S_{persp}$, and a 2D warp matrix $M_{warp2D}$ [S2]:
$$ M_{view} = M_{warp2D} \cdot S_{persp} \cdot P $$
The process consists of four phases: Permutation, Shear/Resampling, Composite, and Warp [S2, S12, unofficial].

**Inputs and Outputs:**
*   **Input:** 3D volume data $V(x,y,z)$, viewing transformation matrix $M_{view}$, transfer function (mapping density to color/opacity), and image dimensions $(W, H)$.
*   **Output:** 2D image buffer $I(u,v)$ with color and opacity values.

**Data Structures:**
*   **Volume Data:** Stored as a 3D array or 3D texture. For optimization, three Run-Length Encoded (RLE) structures are pre-computed, one for each principal axis (X, Y, Z) [S3, S12, unofficial]. Each RLE entry contains a start index, length, and pre-classified opacity/density [S17, unofficial]. Each copy contains four bytes per non-transparent voxel and one byte per run [S2].
*   **Intermediate Image:** A 2D buffer of size $(W, H)$ storing accumulated color and opacity. To support early ray termination, opaque pixels store an offset (pointer) to the next non-opaque pixel in the scanline [S2][S11, abstract only, unofficial].

**Numbered Steps:**

1.  **Permutation (Axis Selection):** Determine the principal viewing axis by finding the coordinate axis (X, Y, or Z) most aligned with the view direction vector $v_o$ [S12, unofficial]. Construct the permutation matrix $P$ to align this axis with the Z-axis of the intermediate coordinate system [S2, S12, unofficial].
    *   If $v_o$ is closest to Z, $P = I$ (identity).
    *   If $v_o$ is closest to X, swap X and Z axes.
    *   If $v_o$ is closest to Y, swap Y and Z axes.
    *   *Pitfall:* If the angle is near 45 degrees to any axis, artifacts increase; the choice is arbitrary but affects artifact direction [S9, unofficial][S15, book].

2.  **Shear and Resampling:** Transform the volume slices (perpendicular to the principal axis) into an intermediate 2D image space [S2, S12, unofficial].
    *   Calculate shear coefficients $s'_x, s'_y, s'_w$ from the view direction $v_o = [v_{o,x}, v_{o,y}, v_{o,z}]^T$ in the permuted space. The perspective shear matrix is defined as [S2]:
        $$ S_{\text{persp}} = \begin{pmatrix} 1 & 0 & 0 & 0 \\ 0 & 1 & 1 & 0 \\ s'_x & s'_y & 1 & s'_w \\ 0 & 0 & 0 & 1 \end{pmatrix} $$
    *   For each slice at depth $z_0$, transform it from object space to sheared object space by translating it by $(z_0 s'_x, z_0 s'_y)$ and then scaling it uniformly by $1/(1 + z_0 s'_w)$ [S2].
    *   Resample each volume slice using bilinear interpolation into the intermediate image. The shear ensures that sampling rays are perpendicular to the slices, allowing fixed interpolation weights computed once per frame [S3, S9, unofficial].
    *   *Optimization:* Use RLE to skip transparent voxel runs. Use the intermediate image's opaque-pixel offsets to skip occluded pixels [S2][S11, abstract only, unofficial].
    *   *Pitfall:* Because each voxel is scaled as well as translated, more than 2 voxel scanlines may need to be traversed simultaneously to contribute to the intermediate image scanline, and voxel scanlines may not be traversed at the same rate as image scanlines [S1, unofficial]. Choose scaling factors so the closest slice has unit scaling; all other slices will have $< 1$ scaling, so no slice is enlarged [S1, unofficial]. Use a box reconstruction filter and a box low-pass filter [S1, unofficial].

3.  **Composite:** Composite the sheared slices in front-to-back order into the intermediate image using the Porter-Duff "over" operator [S2, S12, unofficial].
    *   For each pixel $(u,v)$ in the intermediate image, accumulate color $C$ and opacity $\alpha$:
        $$ C_{new} = C_{slice} \cdot \alpha_{slice} + C_{accum} \cdot (1 - \alpha_{slice}) $$
        $$ \alpha_{new} = \alpha_{slice} + \alpha_{accum} \cdot (1 - \alpha_{slice}) $$
    *   *Early Ray Termination:* If $\alpha_{accum}$ exceeds a user-defined threshold (e.g., 0.95), stop processing further slices for that pixel [S2][S11, abstract only, unofficial].

4.  **Warp:** Transform the intermediate image to the final image space using the 2D warp matrix $M_{warp2D}$ [S2, S12, unofficial].
    *   Compute $M_{warp2D}$ as:
        $$ M_{warp2D} = S_{persp}^{-1} \cdot P^{-1} \cdot M_{view} $$
        (Note: Some sources define $M_{warp2D} = M_{view} \cdot M_{shear}^{-1}$ assuming $P$ is handled in the permutation step [S7, S21, unofficial]. The source [S2] explicitly defines it as $S^{-1} \cdot P^{-1} \cdot M_{view}$).
    *   Resample the intermediate image using bilinear interpolation to produce the final image [S2, S12, unofficial]. This step corrects the distortion introduced by the shear and applies the correct perspective projection [S22, unofficial].

## Subtopics

### Perspective Projection Algorithm
A variant of the shear-warp algorithm that supports perspective viewing transformations by scaling each slice in addition to shearing it [S2]. It utilizes run-length encoded volume data [S2]. Unlike the fast-classification algorithm, it does not suffer from performance degradation when the major viewing axis changes, provided three run-length encoded copies fit in memory [S2]. On an SGI Indigo R4000, it renders the 128x128x109 'brainsmall' dataset in an average of 1.0 seconds and the 128x128x113 'headsmall' dataset in 1.1 seconds [S2]. Color renderings take 1.3x longer than grayscale renderings for perspective projections [S2].

## Operating characteristics
*   **Time Complexity:** The rendering time is generally higher than parallel projection due to the additional scaling operations and the potential for more voxel scanlines to contribute to a single image scanline [S1, unofficial].
*   **Memory Complexity:** Requires storing three RLE copies of the volume data, one for each principal axis. For a 256x256x226 voxel dataset, these total approximately 9.8 Mbytes [S2].
*   **Performance:** On an SGI Indigo R4000, perspective projection rendering is slower than parallel projection (e.g., 1.0s vs 0.4s for 'brainsmall') [S2]. The time required to warp the intermediate image into the final image is typically 10-20% of the total rendering time [S2].
*   **Strengths:** Supports perspective viewing without significant performance jumps when the viewing axis changes [S2].
*   **Limitations:** More complex resampling due to scaling; requires careful filter selection (box reconstruction and low-pass) to avoid artifacts [S1, unofficial].

## Background
The method was introduced by Levoy and Hanrahan in their 1990 paper "Fast Volume Rendering Using a Shear-warp Factorization of The Viewing Transformation" [S2]. It extends the original shear-warp factorization to handle perspective projections by adding a scaling component to the shear transformation [S2].
