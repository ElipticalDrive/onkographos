# Parallel Perspective Shear-Warp Rendering

Also called: Parallel Perspective Shear-Warp Rendering with MPI, Parallelized Perspective Shear-Warp Algorithm, Perspective Shear-Warp Parallelization, Remote Volume Rendering

## Overview
Parallel Perspective Shear-Warp Rendering is a distributed volume rendering technique that parallelizes the compositing step of the perspective shear-warp algorithm across multiple nodes using Message Passing Interface (MPI) [S1]. It solves the problem of rendering high-resolution perspective volumes on distributed memory clusters by offloading the computationally expensive 2D warping step to the graphics hardware of a remote display machine [S1]. Unlike parallel projection methods that distribute volume data, this method requires every node to hold a full copy of the volume, partitioning the intermediate image scanlines instead [S1]. It is distinct from hardware-based texture mapping approaches by avoiding OpenGL extension dependencies and texture memory limits, making it suitable for clusters without dedicated graphics cards [S1].

## How it works
The method extends the standard perspective shear-warp algorithm [Shear-Warp Algorithm](4304-shear-warp-algorithm.md) by distributing the compositing phase across an MPI cluster [S1]. The system consists of a local display machine (running a rendering plug-in) and a remote parallel computer (running the MPI renderer) [S1].

### Inputs and Outputs
*   **Inputs:** View matrix, opacity/color transfer functions, interpolation mode, image quality parameters, and volume data (transferred once at startup) [S1].
*   **Outputs:** Final 2D image displayed on the local machine [S1].

### Data Structures
*   **Volume Data:** Stored on each node as three separate Run-Length Encoded (RLE) datasets, one sorted along each principal axis (x, y, z) [S1]. This axis-sorted structure prevents volume data distribution on distributed memory machines, requiring every node to hold a full copy of the volume [S1].
*   **Intermediate Image:** A 2D RGBA image. Edge lengths are constrained to powers of two to satisfy 2D texturing hardware requirements for the warp step [S1]. Typical size is $1024 \times 1024$ pixels (4 MB) for large datasets [S1].
*   **Memory Management:** The intermediate image data is stored only once in memory per node; a pointer to it is passed among functions to avoid unnecessary copying [S1]. Memory is not reallocated if the image size remains the same or shrinks; reallocation occurs only if the new image is larger than the allocated space [S1].

### Algorithm Steps
The rendering loop operates as follows [S1]:

1.  **Initialization:**
    *   The display machine establishes a bidirectional TCP socket connection to the remote renderer [S1].
    *   The volume data is transferred from disk/memory to the remote cluster [S1].
    *   Each node generates and stores the three RLE-encoded versions of the volume [S1].

2.  **Per-Frame Rendering (Root Node):**
    *   Receive the view matrix from the local rendering plug-in [S1].
    *   Compute the partitioning of the intermediate image into equally sized scanline sections for the available MPI processes [S1].
    *   Pass the section partition parameters (start/end scanlines) to all other nodes [S1].
    *   Render its own assigned scanline section of the intermediate image via compositing in sheared object space [S1].
    *   Receive the rendered intermediate image sections from all other nodes using `MPI_Recv()` with the correct destination memory address to avoid copying [S1].
    *   RLE encode the assembled intermediate image. Two encoding strategies are implemented: encoding the entire image or encoding only the rectangular window actually touched by compositing. The window encoding is typically faster [S1].
    *   Transfer the RLE-encoded intermediate image and the respective warp matrix to the local rendering plug-in [S1].

3.  **Per-Frame Rendering (Other Nodes):**
    *   Receive section parameters from the root node [S1].
    *   Render the assigned scanline section of the intermediate image via compositing in sheared object space [S1].
    *   Transfer the rendered section to the root node [S1].

4.  **Final Display (Local Plug-in):**
    *   Decode the RLE-encoded intermediate image [S1].
    *   Apply the 2D warp transformation using the received warp matrix, utilizing 2D texturing hardware if available [S1].
    *   Draw the final image to the screen [S1].

### Formulas
*   **View Matrix Factorization:** The viewing matrix $M$ is factorized into a 3D shear/scale matrix $M_{shear}$ and a 2D warp matrix $M_{warp}$ [S2].
*   **Front-to-Back Compositing:** For each pixel $(x, y)$, the accumulated color $C$ and opacity $\alpha$ are updated as:
    $$C_{new} = C_{old} + c \cdot \alpha \cdot (1 - \alpha_{old})$$
    $$\alpha_{new} = \alpha_{old} + \alpha \cdot (1 - \alpha_{old})$$
    where $c$ and $\alpha$ are the color and opacity of the current voxel sample [G].
*   **Perspective Scaling:** In perspective projection, slices scale down as they recede, requiring more than one pixel per voxel for front slices to retain detail, unlike parallel projection which maps voxels 1:1 [S1].

### Pseudocode
The following pseudocode represents the control flow on the remote MPI cluster. It is self-contained and valid Python.

```python
# Remote Renderer Initialization
def remote_renderer_init(volume_data, num_nodes, display_host, port):
    # Transfer volume data to all nodes
    # Generate 3 RLE-encoded volumes (one per axis) for each node
    rle_volumes = generate_rle_volumes(volume_data)
    return rle_volumes

# Root Node Logic
def root_node_render_loop(rle_volumes, view_matrix, image_dims, num_nodes):
    # 1. Partition intermediate image into scanline sections
    partitions = compute_scanline_partitions(image_dims.height, num_nodes)
    # 2. Distribute partitions to other nodes
    for node_id in range(1, num_nodes):
        MPI_Send(partitions[node_id], dest=node_id)
    # 3. Root renders its own section
    root_section = partitions[0]
    root_image = composite_sheared_volume(rle_volumes, view_matrix, root_section, image_dims)
    # 4. Receive sections from other nodes
    for node_id in range(1, num_nodes):
        recv_buf = allocate_buffer(partitions[node_id].size)
        MPI_Recv(recv_buf, source=node_id, dest_addr=recv_buf)
        assemble_intermediate_image(root_image, recv_buf, partitions[node_id])
    # 5. Encode and transfer
    encoded_image, warp_matrix = rle_encode_window(root_image, view_matrix)
    send_to_display(encoded_image, warp_matrix)

# Other Nodes Logic
def other_node_render_loop(rle_volumes, view_matrix, image_dims):
    partition = MPI_Recv_receive_partition()
    section_image = composite_sheared_volume(rle_volumes, view_matrix, partition, image_dims)
    MPI_Send(section_image, dest=0)

# Core Compositing Step (Shear-Warp)
def composite_sheared_volume(rle_volumes, view_matrix, partition, image_dims):
    # Factorize view matrix into shear and warp components [Parent]
    M_shear, M_warp = factorize_view_matrix(view_matrix)
    # Initialize intermediate image buffer for the partition
    image = zeros(partition.size)
    # For perspective projection, slices scale down as they go back.
    for slice_idx in range(rle_volumes.depth):
        sheared_slice = shear_slice(rle_volumes[slice_idx], M_shear)
        for y in range(partition.start_y, partition.end_y):
            for x in range(image_dims.width):
                val, alpha = resample_and_classify(sheared_slice, x, y)
                # Front-to-back compositing
                accumulate(image, x, y, val, alpha)
    return image

# Helper Definitions
def generate_rle_volumes(volume_data):
    # Returns list of 3 RLE-encoded arrays sorted along x, y, z axes
    return [rle_encode(axis) for axis in volume_data.axes]

def compute_scanline_partitions(height, num_nodes):
    # Divides height into equally sized scanline sections.
    # Root node gets fewer lines if height % num_nodes != 0.
    base_size = height // num_nodes
    remainder = height % num_nodes
    partitions = []
    start = 0
    for i in range(num_nodes):
        size = base_size + (1 if i < remainder else 0)
        # Root (i=0) gets fewer lines if remainder < num_nodes
        if i == 0 and remainder < num_nodes:
            size = base_size - 1
        partitions.append({'start_y': start, 'end_y': start + size, 'size': size})
        start += size
    return partitions

def factorize_view_matrix(view_matrix):
    # Returns shear/scale matrix M_shear and 2D warp matrix M_warp
    # Implementation follows the parent shear-warp algorithm [Parent]
    return M_shear, M_warp

def shear_slice(rle_data, M_shear):
    # Applies 3D shear transformation to the RLE-encoded slice
    return apply_transformation(rle_data, M_shear)

def resample_and_classify(sheared_slice, x, y):
    # Samples voxel color c and opacity alpha at (x, y)
    return sample_voxel(sheared_slice, x, y)

def accumulate(image, x, y, val, alpha):
    # Updates front-to-back compositing: C += c * alpha * (1 - alpha_old)
    old_alpha = image[y, x].alpha
    image[y, x].color += val * alpha * (1.0 - old_alpha)
    image[y, x].alpha += alpha * (1.0 - old_alpha)

def rle_encode_window(image, view_matrix):
    # Encodes only the rectangular window actually touched in compositing
    window = get_touched_window(image)
    encoded = run_length_encode(window)
    return encoded, view_matrix.warp_matrix

def send_to_display(encoded_image, warp_matrix):
    # Sends RLE data and warp matrix to local plug-in via TCP socket
    socket.send(encoded_image)
    socket.send(warp_matrix)

def MPI_Send(data, dest):
    # Standard MPI send operation
    pass

def MPI_Recv_receive_partition():
    # Receives partition parameters from root
    return receive_data()

def MPI_Recv(buf, source, dest_addr):
    # Standard MPI receive into pre-allocated buffer
    pass

def allocate_buffer(size):
    return [None] * size

def assemble_intermediate_image(global_image, local_buf, partition):
    # Places local_buf into global_image at partition coordinates
    for i in range(partition.size):
        global_image[partition.start_y + i] = local_buf[i]
```

### Parameters and Typical Values
*   **Intermediate Image Size:** Powers of two (e.g., $1024 \times 1024$ for large datasets, $512 \times 512$ for small) [S1].
*   **Color Space:** 24-bit RGB [S1].
*   **Opacity Transfer Function:** Linear ramp from zero to full opacity [S1].
*   **Network:** Bidirectional TCP socket [S1].
*   **Remote Renderer Parameters:** Port number and display host address [S1].

### Edge Cases and Pitfalls
*   **Memory Constraints:** Because the shear-warp algorithm requires three axis-sorted volume datasets, volume data cannot be distributed across nodes; every node must hold a full copy of the volume [S1]. If memory is constrained on a large cluster, nodes can be split into three groups (one per axis), allowing three times the maximum volume size but limiting rendering to one-third of the nodes simultaneously [S1].
*   **Perspective Cost:** Perspective compositing is significantly more expensive than parallel projection; a single intermediate image pixel may require accumulating voxels from an entire voxel slice at the back of the volume, unlike parallel projection which maps voxels 1:1 [S1].
*   **Load Balancing:** Compositing time can vary based on view direction and opacity distribution; on SGI Onyx2, the load balancing factor was 2.08, meaning perfect load balancing would improve speed by this factor [S1]. The optimal process count may not be the maximum available (e.g., 14 processes was fastest on a 16-processor Onyx2) [S1].
*   **Network Bottlenecks:** On fast processors (e.g., PC Cluster), image transfer and idle time can dominate rendering time, whereas on slower processors (e.g., SUN Fire), compositing dominates [S1].

## Operating characteristics
*   **Time Complexity:** The compositing step dominates the total rendering time on most architectures [S1]. The warp step is offloaded to hardware and is nearly independent of output image size [S1].
*   **Memory Complexity:** High. Each node must store three full RLE-encoded copies of the volume dataset [S1].
*   **Measured Performance:** 
    *   **SUN Fire (6 processes):** 3.5 images/sec. Compositing dominates. Encoding: 0.91s, Transfer: 0.89s [S1].
    *   **SGI Onyx2 (14 processes):** 2.7 images/sec. Compositing dominates. Transfer: <0.2s (1 Gbit/s Ethernet), Encoding: 2.67s [S1].
    *   **PC Cluster (16 processes):** 8.4 images/sec. Transfer and idle time dominate due to fast CPUs. Encoding: 0.27s [S1].
    *   **Decoding/Drawing:** Constant ~2.6s decode and ~1.4s draw time on the display machine across tests [S1].
*   **Scaling:** Performance scales with the number of processors for compositing, but is limited by load balancing inefficiencies and network bandwidth for data transfer [S1].
*   **Strengths:** Works on clusters without graphics hardware; avoids OpenGL extension dependencies; suitable for remote rendering in virtual environments; warp is hardware-accelerated [S1].
*   **Limitations:** High memory usage per node; perspective compositing is expensive; network bandwidth can be a bottleneck for large images; load balancing is imperfect [S1].
*   **When to use:** Remote rendering on distributed clusters where graphics hardware is unavailable or insufficient, and perspective projection is required [S1].
*   **When not to use:** When single-processor performance is critical (hardware texture mapping is faster on single cores); when volume data is too large to fit in memory on each node [S1].

## Background
Parallel Perspective Shear-Warp Rendering was developed by Schulze and Lang in 2002 [S1]. It is based on their prior work on perspective shear-warp rendering [S1] and extends Lacroute's parallel projection parallelization method [S1]. The method was designed to support remote rendering for virtual environments requiring perspective projection, high frame rates, stereo projection, and multiple display screens [S1]. It was implemented using the Virvo volume renderer framework with a plug-in mechanism [S1].
