# Shear-Warp Algorithm

Also called: Lacroute and Levoy algorithm, Lacroute-Levoy algorithm, Shear-Warp Factorization, Shear-warp factorization of the viewing transformation

## Overview
The Shear-Warp Algorithm is a fast, software-based volume rendering technique that reduces the number of resampling passes from three to two by factorizing the viewing transformation matrix into a 3D shear and a 2D warp [S1, S12, unofficial]. It solves the problem of efficient rendering from arbitrary viewing angles by transforming the volume data into a "sheared object space" where viewing rays are parallel to a coordinate axis, allowing for efficient slice-by-slice compositing [S12, unofficial]. Unlike general ray-casting methods that perform trilinear interpolation per pixel, Shear-Warp substitutes this with fixed bilinear interpolation weights computed once per frame, exploiting spatial coherence and memory alignment [S3, S9, unofficial]. It is distinct from GPU-based ray marching by relying on CPU-driven affine transformations and intermediate image buffers, though it shares the slice-based processing logic with [Affine-Transformations Method](2038-affine-transformations-method.md).

## How it works
**Inputs and Outputs:**
*   **Input:** 3D volume data $V(x,y,z)$, viewing transformation matrix $M_{view}$, transfer function (mapping density to color/opacity), and image dimensions $(W, H)$.
*   **Output:** 2D image buffer $I(u,v)$ with color and opacity values.

**Data Structures:**
*   **Volume Data:** Stored as a 3D array or 3D texture. For optimization, three Run-Length Encoded (RLE) structures are pre-computed, one for each principal axis (X, Y, Z) [S3, S12, unofficial]. Each RLE entry contains a start index, length, and pre-classified opacity/density [S17, unofficial].
*   **Intermediate Image:** A 2D buffer of size $(W, H)$ storing accumulated color and opacity. To support early ray termination, opaque pixels store an offset (pointer) to the next non-opaque pixel in the scanline [S2, unofficial][S11, unofficial].

**Numbered Steps:**

1.  **Permutation (Axis Selection):** Determine the principal viewing axis by finding the coordinate axis (X, Y, or Z) most aligned with the view direction vector $v_o$ [S12, unofficial]. Construct the permutation matrix $P$ to align this axis with the Z-axis of the intermediate coordinate system [S2, S12, unofficial].
    *   If $v_o$ is closest to Z, $P = I$ (identity).
    *   If $v_o$ is closest to X, swap X and Z axes.
    *   If $v_o$ is closest to Y, swap Y and Z axes.
    *   *Pitfall:* If the angle is near 45 degrees to any axis, artifacts increase; the choice is arbitrary but affects artifact direction [S9, unofficial][S15, book].

2.  **Shear and Resampling:** Transform the volume slices (perpendicular to the principal axis) into an intermediate 2D image space [S2, S12, unofficial].
    *   Calculate shear coefficients $s_x, s_y$ from the view direction $v_o = [v_{o,x}, v_{o,y}, v_{o,z}]^T$ in the permuted space:
        $$ s_x = -\frac{v_{o,x}}{v_{o,z}}, \quad s_y = -\frac{v_{o,y}}{v_{o,z}} $$
    *   For parallel projection, the shear matrix is:
        $$ S = \begin{pmatrix} 1 & 0 & s_x & 0 \\ 0 & 1 & s_y & 0 \\ 0 & 0 & 1 & 0 \\ 0 & 0 & 0 & 1 \end{pmatrix} $$
    *   For perspective projection, an additional scaling factor is applied to each slice to account for foreshortening, and the shear matrix includes a perspective component $s'_w$ [S2, unofficial][S15, book]:
        $$ S_{persp} = \begin{pmatrix} 1 & 0 & s'_x & 0 \\ 0 & 1 & s'_y & 0 \\ 0 & 0 & 1 & 0 \\ 0 & 0 & s'_w & 1 \end{pmatrix} $$
    *   Resample each volume slice using bilinear interpolation into the intermediate image. The shear ensures that sampling rays are perpendicular to the slices, allowing fixed interpolation weights computed once per frame [S3, S9, unofficial].
    *   *Optimization:* Use RLE to skip transparent voxel runs. Use the intermediate image's opaque-pixel offsets to skip occluded pixels [S2, unofficial][S11, unofficial].

3.  **Composite:** Composite the sheared slices in front-to-back order into the intermediate image using the Porter-Duff "over" operator [S2, S12, unofficial].
    *   For each pixel $(u,v)$ in the intermediate image, accumulate color $C$ and opacity $\alpha$:
        $$ C_{new} = C_{slice} \cdot \alpha_{slice} + C_{accum} \cdot (1 - \alpha_{slice}) $$
        $$ \alpha_{new} = \alpha_{slice} + \alpha_{accum} \cdot (1 - \alpha_{slice}) $$
    *   *Early Ray Termination:* If $\alpha_{accum}$ exceeds a user-defined threshold (e.g., 0.95), stop processing further slices for that pixel [S2, unofficial][S11, unofficial].

4.  **Warp:** Transform the intermediate image to the final image space using the 2D warp matrix $M_{warp2D}$ [S2, S12, unofficial].
    *   Compute $M_{warp2D}$ as:
        $$ M_{warp2D} = M_{view} \cdot S^{-1} \cdot P^{-1} $$
        (Note: Some sources define $M_{warp2D} = M_{view} \cdot M_{shear}^{-1}$ assuming $P$ is handled in the permutation step [S7, S21, unofficial]).
    *   Resample the intermediate image using bilinear interpolation to produce the final image [S2, S12, unofficial]. This step corrects the distortion introduced by the shear and applies the correct perspective/parallel projection [S22, unofficial].

**Pseudocode:**

```python
def shear_warp_render(volume, M_view, transfer_function, width, height):
    # 1. Permutation
    # Determine principal axis (z, x, or y) based on view direction
    view_dir = get_view_direction(M_view)
    principal_axis = argmax(abs(view_dir)) # 0:x, 1:y, 2:z
    
    # Construct permutation matrix P to align principal axis with Z
    P = get_permutation_matrix(principal_axis)
    
    # 2. Shear
    # Calculate shear coefficients
    # Transform view direction to permuted space if necessary, 
    # but typically derived from M_view components directly
    # vo = [m12*m23 - m22*m13, m21*m13 - m11*m23, m11*m22 - m21*m12]
    vo = compute_view_direction_from_matrix(M_view)
    
    sx = -vo[0] / vo[2]
    sy = -vo[1] / vo[2]
    
    # For perspective, additional scaling factors are needed per slice
    # S_par for parallel projection
    S = [
        [1, 0, sx, 0],
        [0, 1, sy, 0],
        [0, 0, 1, 0],
        [0, 0, 0, 1]
    ]
    
    # Pre-compute RLE structures for the volume along the principal axis
    # This requires three copies of RLE data for X, Y, Z directions
    rle_data = build_rle(volume, transfer_function, principal_axis)
    
    # Initialize intermediate image with opaque pixel offsets
    intermediate_image = init_intermediate_image(width, height)
    
    # 3. Composite
    # Iterate through slices in front-to-back order
    for slice_idx in range(num_slices):
        # Get slice data from RLE or volume
        slice_data = get_slice_data(rle_data, slice_idx)
        
        # Resample slice into intermediate image using bilinear interpolation
        # The shear transforms the slice coordinates
        resample_slice_to_intermediate(slice_data, S, intermediate_image, slice_idx)
        
        # Early ray termination check can be integrated here
        if check_early_termination(intermediate_image):
            break
            
    # 4. Warp
    # Compute warp matrix
    S_inv = invert_matrix(S)
    P_inv = invert_matrix(P)
    M_warp2D = multiply_matrices(M_view, S_inv, P_inv)
    
    # Warp intermediate image to final screen
    final_image = warp_image(intermediate_image, M_warp2D, width, height)
    
    return final_image
```

## Subtopics

### [Parallel Perspective Shear-Warp Rendering](802-parallel-perspective-shear-warp-rendering.md)
Parallel Perspective Shear-Warp Rendering is a distributed volume rendering technique that parallelizes the compositing step of the perspective shear-warp algorithm across multiple nodes using Message Passing Interface (MPI). It solves the problem of rendering high-resolution perspective volumes on distributed memory clusters by offloading the computationally expensive 2D warping step to the graphics hardware of a remote display machine. Unlike parallel projection methods that distribute volume data, this method requires every node to hold a full copy of the volume, partitioning the intermediate image scanlines instead. It is distinct from hardware-based texture mapping approaches by avoiding OpenGL extension dependencies and texture memory limits, making it suitable for clusters without dedicated graphics cards.

### [CPU-based Shear-Warp](1161-cpu-based-shear-warp.md)
CPU-based Shear-Warp is a volume rendering method that implements the Shear-Warp algorithm on a central processing unit, utilizing Run-Length Encoding (RLE) to accelerate traversal by skipping empty voxels. It distinguishes itself from the original Shear-Warp proposal by relying on 1D RLE compression along principal axes rather than 3D data structures like octrees, and from GPU-based variants by its sequential, CPU-bound execution model.

### [Permutation Proof for Projection and Warp](1702-permutation-proof-for-projection-and-warp.md)
A mathematical proof demonstrating that the projection matrix $P$ and warp matrix $W$ in the perspective shear-warp algorithm can be permuted, allowing the viewing transformation to be computed as $W \cdot P \cdot S$ instead of the standard $P \cdot W \cdot S$. This property is a basic premise for the perspective projection shear-warp algorithm, enabling specific optimization paths in the compositing step. It sets the method apart from general matrix factorizations by proving that the specific structure of the shear-warp decomposition allows the projection to precede the warp without altering the final image coordinates, provided the warp matrix satisfies specific zero-element constraints.

### [Spatially Partitioned Shear-Warp Method](3481-spatially-partitioned-shear-warp-method.md)
The Spatially Partitioned Shear-Warp Method is a parallel volume rendering technique that partitions a 3D volume dataset into axis-aligned sub-volumes, renders each independently into intermediate baseplanes using the shear-warp factorization, composites these baseplanes using a binary tree to resolve occlusion, and finally warps the result to the image plane. It distinguishes itself from its sibling, the Distributed Data Volume Rendering via Shear-Warp Factorisation, by explicitly defining a hierarchical rendering tree with configurable branching factors and specific optimizations for network transfer (window-encoding, RLE) and memory storage (multi-order copies) to handle large datasets on distributed clusters. Unlike standard shear-warp which processes the whole volume, this method allows view-independent partitioning, meaning the volume is partitioned once in object coordinates and can be rendered from any viewing direction without repartitioning.

### [Shear-warp Factorization for Combined Surface/Volume Rendering](7392-shear-warp-factorization-for-combined-surface-volume-renderi.md)
This method enables real-time visualization in surgical simulators by combining volume-rendered 3D medical images (organs) with surface-rendered medical instruments (e.g., needles) using shear-warp factorization, Z-buffer depth comparison, early ray termination, and instrument-region masking to reduce computation. It sets itself apart from pure volume rendering by leveraging the speed of surface rendering for simple, frequently moving objects (instruments) while retaining the segmentation-free realism of volume rendering for complex, fuzzy data (organs), using a shared intermediate sheared space to efficiently composite the two.

### [GPU-based Shear-Warp](7425-gpu-based-shear-warp.md)
GPU-based Shear-Warp is a hardware-accelerated implementation of the Shear-Warp algorithm. It solves the problem of efficient real-time volume rendering by decomposing the viewing transformation into a 3D shear, a projection, and a 2D warp, utilizing vertex and fragment shaders to perform these operations in parallel. Unlike traditional CPU-based implementations, this method leverages graphics hardware to achieve interactive frame rates, though it is generally slower than GPU-based Ray Marching for equivalent image quality.

### [Optimization Technique](7922-optimization-technique.md)
Optimization techniques in the Shear-Warp family accelerate volume rendering by reducing computational complexity, skipping empty regions, or adapting resolution to maintain frame rates. They set themselves apart from the base [Shear-Warp Algorithm](4304-shear-warp-algorithm.md) by introducing specific hardware-aware or algorithmic shortcuts (such as binary masks or dynamic scaling) rather than just decomposing the view transformation.

### Texture-Based Warp
A warp implementation that uses 2D texturing hardware to transform the intermediate image to the final screen, leveraging the OpenGL model/view and projection matrices [S25, unofficial].
*   **Step:** Set the OpenGL model/view matrix to the warp matrix. Set the OpenGL projection matrix to the identity matrix. Draw the intermediate image as a textured quad. The hardware performs the non-affine perspective warp and bilinear interpolation automatically [S25, unofficial].
*   **Parameter:** Warp Matrix: The general perspective projection warp matrix Wper, which is non-affine [S25, unofficial].
*   **Layout:** Wper Matrix Layout: A 3x3 matrix with elements a00, a01, a02, a10, a11, a12, a20, a21, a22 [S25, unofficial].
*   **Pitfall:** Image Size Constraints: Texturing hardware requires image sizes to be powers of two, causing jumps in rendering time at edge lengths of 512 and 1024 pixels [S25, unofficial].
*   **Comparison:** Compared to software warp, texture-based warp is faster for large images and accounts for less than 2% of total rendering time on SGI Onyx2, but has higher overhead for small images [S25, unofficial].

### Software Warp
A warp implementation that computes the final 2D image using a pure software algorithm and pastes it to the viewport [S25, unofficial].
*   **Formula:** Parallel Warp Operations: Multiplying Wpar by vector $(x, y, 1)^T$ requires 4 multiplications and 4 additions (8 FLOPs). $W_{par} = [[a00, a01, a02], [a10, a11, a12], [0, 0, 1]]$. Perspective Warp Operations: Multiplying Wper by vector $(x, y, 1)^T$ requires 6 multiplications, 6 additions, and 2 divisions (14 FLOPs) [S25, unofficial].
*   **Pitfall:** Object Ordering: Software warp does not allow automatic object ordering; the programmer must choose to draw the volume before or after polygons, which is incorrect for intersecting polygons [S25, unofficial].
*   **Comparison:** Software warp is faster than texture-based warp for small images due to texturing hardware overhead, but slower for large images [S25, unofficial].

### GPU-Accelerated On-the-Fly Deskewing
An open-source software package that transforms the display of Oblique Plane Microscopy (OPM) imaging data in real time to produce a live extended depth of field projection, correcting the distorted coordinate frame [S19, abstract only, unofficial].
*   **Step:** Utilize GPU acceleration and multiprocessing. Transform the display of OPM imaging data in real time. Produce a live extended depth of field projection [S19, abstract only, unofficial].
*   **Parameter:** Processing rate: several Hz [S19, abstract only, unofficial].

### Resampling from Sheared Space
*   **Step:** Determine the first non-transparent cell using the Depth routine on the sheared mask. Calculate accurate sample location inside the cell using exact translation values at depth z. Map sample location to original object space by subtracting trans_x[i] and trans_y[i] from x and y coordinates. Use bilinear interpolation for the four corner voxels of the cell to calculate density. If opacity is not one, trace further. Use binary volume to skip empty regions: copy z-row integer to temp variable, set processed non-zero bits to zero, and call Depth again for next non-transparent cell [S8, unofficial].

## Operating characteristics
The Shear-Warp algorithm is highly optimized for software-based rendering, achieving frame rates in the sub-second range for moderately sized datasets (e.g., 256^3 voxels) on single-processor workstations like the SGI Indigo R4000 [S1, S6, unofficial]. It is generally faster than ray casting and splatting by an order of magnitude for these resolutions [S6, unofficial]. However, it incurs higher memory overhead due to the requirement of three RLE structures for the volume data [S3, unofficial]. Image quality can suffer from stair-casing artifacts near 45-degree viewing angles and blurring during zoom-ins, as the resampling of the warp matrix is not adaptive [S1, unofficial]. Perspective rendering is slower than parallel projection due to the need for individual slice scaling and many-to-one voxel-to-pixel mappings [S2, unofficial].

## Background
The Shear-Warp algorithm was proposed by Lacroute and Levoy in 1994 [S1, S3, unofficial]. It was designed to be the world's fastest purely software-based volume rendering algorithm at the time, combining the advantages of image-order and object-order methods [S2, S6, unofficial]. It has been used in various hardware implementations, such as the VolumePro system, and remains a foundational technique for understanding affine-based volume rendering [S1, S6, unofficial].
