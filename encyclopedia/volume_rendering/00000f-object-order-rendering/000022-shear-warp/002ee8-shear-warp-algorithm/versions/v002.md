# Shear-Warp Algorithm

Also called: Lacroute-Levoy algorithm, Lacroute and Levoy algorithm, Shear-Warp Factorization

## Overview
The Shear-Warp Algorithm is a fast, software-based volume rendering technique that reduces the number of resampling passes from three to two by factorizing the viewing transformation matrix into a 3D shear and a 2D warp [S1, S6, S24, unofficial]. It solves the problem of efficient rendering from arbitrary viewing angles by transforming the volume into a sheared object space where viewing rays are parallel to a coordinate axis, enabling efficient slice-by-slice compositing [S1, S3, S12, unofficial]. Unlike standard ray casting which performs trilinear interpolation for every pixel, Shear-Warp substitutes this with bilinear interpolation on aligned slices, exploiting memory alignment and spatial coherence [S3, S9, unofficial]. It is distinct from its siblings, such as [VolumePro Ray-Casting with Slice-by-Slice Processing](1865-volumepro-ray-casting-with-slice-by-slice-processing.md) which uses custom hardware, and [Affine-Transformations Method](2038-affine-transformations-method.md) which applies full affine transforms per slice, by relying on a specific matrix factorization that decouples the shear (object-space alignment) from the warp (image-space correction) [S2, S12, unofficial].

## How it works
The algorithm factorizes the viewing transformation matrix $M_{view}$ into three components: a permutation $P$, a shear $S$, and a 2D warp $M_{warp2D}$ [S3, S12, S21, unofficial]:
$$ M_{view} = M_{warp2D} \cdot S \cdot P $$
The process consists of three main phases:

### Inputs and Outputs
*   **Inputs:**
    *   Volume data $V$ of dimensions $D_x \times D_y \times D_z$.
    *   Viewing transformation matrix $M_{view}$ (4x4).
    *   Transfer function mapping density to color/opacity.
    *   Image dimensions $W \times H$.
*   **Outputs:**
    *   Final 2D image $I_{final}$ of size $W \times H$.

### Data Structures
1.  **Volume Data:** Stored as a 3D array or 3D texture [S7, S21, unofficial].
2.  **Run-Length Encoded (RLE) Voxel Scanlines:** To optimize traversal, the volume is pre-processed into RLE structures for each of the three principal axes (X, Y, Z) [S3, S12, S17, unofficial]. Each RLE entry contains:
    *   `shade_index`: Pre-computed from voxel gradient and transfer function [S17, unofficial].
    *   `density`: Voxel density value [S17, unofficial].
    *   `is_opaque`: Boolean or thresholded opacity flag [S17, unofficial].
    *   *Note:* Three separate RLE stacks are required, one for each principal viewing direction, incurring higher memory overhead [S3, S9, unofficial].
3.  **Intermediate Image:** A 2D buffer $I_{int}$ of size $W \times H$ (or adapted size) [S24, unofficial].
    *   **Opaque Pixel Optimization:** Each opaque pixel stores an offset (pointer) to the next non-opaque pixel in the same scanline [S2, S11, S12, unofficial]. This allows skipping occluded voxels efficiently, analogous to early-ray termination.

### Steps

1.  **Permutation and Shear:**
    *   **Permutation ($P$):** Determine the principal viewing axis (the axis most nearly orthogonal to the viewing direction) to minimize shear [S4, S9, S12, unofficial]. Let the view direction in object space be $v_o$. If $v_o$ is mostly parallel to the +Z axis ($v_{o,z} > v_{o,x}$ and $v_{o,z} > v_{o,y}$), the Z-axis is the principal axis, and $P$ is the identity or a simple axis swap if another axis is dominant [S7, S21, unofficial].
    *   **Shear Matrix ($S$):** Compute the shear matrix to align viewing rays with the principal axis (typically Z) [S2, S12, unofficial].
        *   For **Parallel Projection**:
            $$ S_{par} = \begin{pmatrix} 1 & 0 & s_x & 0 \\ 0 & 1 & s_y & 0 \\ 0 & 0 & 1 & 0 \\ 0 & 0 & 0 & 1 \end{pmatrix} $$
            where $s_x = -\frac{v_{o,x}}{v_{o,z}}$ and $s_y = -\frac{v_{o,y}}{v_{o,z}}$ [S2, S7, S21, unofficial].
        *   For **Perspective Projection**:
            $$ S_{persp} = \begin{pmatrix} 1 & 0 & s'_x & 0 \\ 0 & 1 & s'_y & 0 \\ 0 & 0 & 1 & 0 \\ 0 & 0 & s'_w & 1 \end{pmatrix} $$
            where $s'_x, s'_y$ are derived similarly, and $s'_w$ accounts for perspective scaling [S2, S24, unofficial].
    *   **Resampling:** Transform volume data to sheared object space by translating and resampling each slice according to $S$ [S2, S11, unofficial].
        *   Use **bilinear interpolation** for resampling [S2, S6, S12, unofficial].
        *   For parallel projection, a unity scale factor is used, resulting in a 1-to-1 mapping between voxel scanlines and intermediate image pixels [S2, S11, unofficial].
        *   For perspective projection, each slice is scaled individually to account for diverging rays [S2, S11, unofficial].

2.  **Composite:**
    *   Traverse the volume slice-by-slice in the sheared space [S2, S5, unofficial].
    *   Use the RLE structures to skip transparent voxel runs [S2, S17, unofficial].
    *   Composite samples into the intermediate image $I_{int}$ using front-to-back alpha blending (Porter-Duff over operator) [S2, S8, S12, unofficial]:
        $$ I_{int}[y, x] = I_{int}[y, x] + C \cdot \alpha \cdot (1 - A_{int}[y, x]) $$
        $$ A_{int}[y, x] = A_{int}[y, x] + \alpha \cdot (1 - A_{int}[y, x]) $$
        where $C$ is color and $\alpha$ is opacity [S2, unofficial].
    *   **Optimization:** Use the opaque pixel offsets in $I_{int}$ to skip pixels that are already opaque (early-ray termination equivalent) [S2, S11, S19, unofficial].

3.  **Warp:**
    *   Transform the intermediate image $I_{int}$ to the final image space using the 2D warp matrix $M_{warp2D}$ [S2, S12, S21, unofficial].
    *   $$ M_{warp2D} = M_{view} \cdot S^{-1} \cdot P^{-1} $$ [S3, S12, S21, unofficial].
    *   This is a 2D resampling step that corrects the distortion introduced by the shear [S2, S5, unofficial].
    *   **Implementation:** Can be done via software computation or hardware texture mapping [S24, unofficial].

### Pseudocode

```python
def shear_warp_render(volume, M_view, transfer_function, image_width, image_height):
    # 1. Permutation
    # Determine principal axis based on view direction v_o derived from M_view
    v_o = get_view_direction(M_view)
    principal_axis = determine_principal_axis(v_o) # Returns 'x', 'y', or 'z'
    P = get_permutation_matrix(principal_axis)
    
    # 2. Shear
    # Calculate shear coefficients
    if principal_axis == 'z':
        sx = -v_o.x / v_o.z
        sy = -v_o.y / v_o.z
    elif principal_axis == 'y':
        sx = -v_o.x / v_o.y
        sy = -v_o.z / v_o.y
    else: # principal_axis == 'x'
        sx = -v_o.y / v_o.x
        sy = -v_o.z / v_o.x
        
    S = create_shear_matrix(sx, sy)
    
    # Pre-compute RLE structures for the volume if not already done
    # Requires 3 stacks for X, Y, Z directions
    rle_structures = precompute_rle(volume, transfer_function)
    current_rle = rle_structures[principal_axis]
    
    # Initialize intermediate image
    I_int = zeros(image_width, image_height)
    A_int = zeros(image_width, image_height)
    opaque_offsets = zeros(image_width, image_height) # Stores offset to next non-opaque pixel
    
    # 3. Composite
    # Iterate through slices in sheared space
    for slice_idx in range(volume_depth):
        # Get slice data from RLE or volume
        slice_data = get_slice_data(current_rle, slice_idx)
        
        # Resample slice into intermediate image coordinates
        # Using bilinear interpolation
        resampled_slice = resample_slice(slice_data, S, slice_idx)
        
        # Composite into I_int
        for y in range(image_height):
            for x in range(image_width):
                # Check if pixel is already opaque (optimization)
                if A_int[y, x] >= 1.0:
                    # Skip to next non-opaque pixel if stored
                    next_x = opaque_offsets[y, x]
                    if next_x is not None:
                        x = next_x - 1 # Loop increment will add 1
                        continue
                    else:
                        continue # End of scanline
                
                # Get sample color and opacity
                color, alpha = resampled_slice[y, x]
                
                # Front-to-back compositing
                if alpha > 0:
                    I_int[y, x] = I_int[y, x] + color * alpha * (1 - A_int[y, x])
                    A_int[y, x] = A_int[y, x] + alpha * (1 - A_int[y, x])
                    
                    # Update opaque offset if pixel becomes opaque
                    if A_int[y, x] >= 1.0:
                        opaque_offsets[y, x] = find_next_non_opaque_pixel(x, y, I_int)

    # 4. Warp
    # Calculate warp matrix
    M_warp2D = M_view * inverse(S) * inverse(P)
    
    # Apply 2D warp to I_int
    I_final = warp_image(I_int, M_warp2D, image_width, image_height)
    
    return I_final
```

### Parameters
*   **Interpolation:** Bilinear interpolation is standard for resampling [S2, S6, S12, unofficial].
*   **Opacity Threshold:** A user-defined threshold to classify voxels as transparent or opaque for RLE encoding [S2, S19, unofficial].
*   **Intermediate Image Size:** Can be adapted at runtime to control frame rate [S24, unofficial].
*   **Shading:** Lookup tables are often used for shading and opacity correction [S6, S12, unofficial].

### Edge Cases and Pitfalls
*   **45-Degree Artifacts:** Stair-casing artifacts appear when the viewing angle approaches 45 degrees relative to the volume axes [S1, S4, unofficial][S15, book]. This can be mitigated by virtually inserting intermediate slices between adjacent volume slices [S1, S22, unofficial].
*   **Perspective Performance:** Perspective projections are slower than parallel ones because rays diverge, requiring scaling and resulting in a many-to-one mapping from voxels to pixels [S2, S11, unofficial].
*   **Image Quality:** The algorithm may produce blurry images on zoom and reduced quality compared to ray casting due to the fixed sampling rate and bilinear interpolation [S6, S10, unofficial][S14].
*   **Memory Overhead:** Storing three RLE stacks for all principal directions increases memory usage significantly [S3, S9, unofficial].

### Texture-Based Warp
A warp implementation that uses 2D texturing hardware to transform the intermediate image to the final screen, leveraging the OpenGL model/view and projection matrices [S24, unofficial].
*   **Step:** Set the OpenGL model/view matrix to the warp matrix $W_{per}$, set the projection matrix to identity, and draw the intermediate image as a textured quad [S24, unofficial].
*   **Parameter:** The warp matrix $W_{per}$ is a non-affine 3x3 matrix [S24, unofficial].
*   **Pitfall:** Texturing hardware requires image sizes to be powers of two, causing jumps in rendering time at edge lengths of 512 and 1024 pixels [S24, unofficial].
*   **Comparison:** Faster than software warp for large images, accounting for <2% of total time on SGI Onyx2, but has higher overhead for small images [S24, unofficial].

### Software Warp
A warp implementation that computes the final 2D image using a pure software algorithm and pastes it to the viewport [S24, unofficial].
*   **Formula:** Parallel warp requires 8 FLOPs (4 mult, 4 add); Perspective warp requires 14 FLOPs (6 mult, 6 add, 2 div) [S24, unofficial].
*   **Pitfall:** Does not allow automatic object ordering; the programmer must manually handle draw order for intersecting polygons [S24, unofficial].
*   **Comparison:** Faster than texture-based warp for small images due to hardware overhead, but slower for large images [S24, unofficial].

### Intermediate Image Size Adaptation
A technique to maintain constant frame rates by dynamically adjusting the resolution of the intermediate image [S24, unofficial].
*   **Step:** Modify the scaling matrix $M_{scale}$ to change intermediate image size. Use footprint-based interpolation for downsizing and bilinear for upsizing [S24, unofficial].
*   **Parameter:** Target frame rate is typically 5-10 fps [S24, unofficial].

### GPU-Accelerated On-the-Fly Deskewing
An open-source software package that transforms Oblique Plane Microscopy (OPM) data in real time using GPU acceleration [S18, abstract only, unofficial].
*   **Step:** Utilize GPU and multiprocessing to produce a live extended depth of field projection [S18, abstract only, unofficial].
*   **Parameter:** Processing rate is several Hz [S18, abstract only, unofficial].

### Resampling from Sheared Space
Details on efficient resampling within volume slices [S8, unofficial].
*   **Step:** Determine the first non-transparent cell using a Depth routine on the sheared mask. Calculate accurate sample location using exact translation values. Map to original object space by subtracting translation offsets. Use bilinear interpolation for the four corner voxels. If opacity is not one, trace further. Use a binary volume to skip empty regions by processing non-zero bits [S8, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of voxels, but optimized by RLE skipping transparent voxels and opaque pixels [S2, S17, unofficial].
*   **Memory Complexity:** $O(V)$ for volume storage plus $O(V)$ for three RLE stacks [S3, S9, unofficial].
*   **Performance:** Historically one of the fastest software-based volume rendering algorithms, achieving sub-second frame rates for moderate datasets (e.g., 256^3 voxels in ~1 second on SGI Indigo) [S6, S24, unofficial].
*   **Strengths:** High speed due to cache-friendly scanline traversal and fixed interpolation weights; efficient early-ray termination via opaque pixel offsets [S2, S11, unofficial].
*   **Limitations:** Reduced image quality compared to ray casting (blurring, stair-casing artifacts); high memory overhead for RLE stacks; perspective rendering is slower [S1, S6, S11, unofficial].
*   **When to use:** When interactive frame rates are required on CPU-only systems and image quality is secondary to speed [S6, unofficial].
*   **When not to use:** When high-quality shading, perspective accuracy, or minimal memory footprint is critical [S6, S9, unofficial].

## Background
The Shear-Warp algorithm was proposed by Lacroute and Levoy in 1994 [S1, S3, S6, unofficial]. It was designed as a fast software implementation for volume rendering, reducing resampling passes from three to two [S1, unofficial]. The algorithm combines the advantages of image-order (ray casting) and object-order (splatting) methods by exploiting spatial coherence [S2, unofficial][S14]. It has been widely used in early software-based volume renderers and influenced hardware implementations like VolumePro [S6, unofficial][S15, book]. The method assumes the view direction is mostly parallel to one of the principal axes to define shear slopes [S7, S21, unofficial].
