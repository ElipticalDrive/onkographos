# Shear-Warp Algorithm

Also called: GPU Shear-Warp, GPU-Based Shear-Warp, Lacroute-Levoy algorithm, Perspective Shear-Warp Algorithm, Shear-Warp Factorization, Shear-Warp on GPU

## Overview
The Shear-Warp Algorithm is a fast, purely software-based volume rendering technique that reduces the computational complexity of 3D ray casting by factorizing the viewing transformation into a 3D shear and a 2D warp [S1, unofficial][S5, unofficial]. It solves the problem of efficient memory access and interpolation for arbitrary viewing angles by transforming the volume into a "sheared object space" where viewing rays are parallel to a coordinate axis, allowing slice-by-slice compositing [S2, unofficial][S10, unofficial]. Unlike ray casting which performs trilinear interpolation per pixel, Shear-Warp substitutes this with bilinear interpolation within slices and a final 2D resampling, making it significantly faster than object-order ray casting and image-order splatting for moderate-sized datasets [S5, unofficial]. It is distinct from hardware-accelerated texture mapping methods by relying on software scanline traversal and RLE optimization, though it can be accelerated by GPU texturing for the final warp step [S21, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volume dataset $V$ (scalar field), a viewing transformation matrix $M_{view}$, and output image dimensions $W \times H$.
*   **Output:** A 2D rendered image $I$.

**Data Structures:**
*   **Volume Data:** Stored as a 3D array. For optimization, three Run-Length Encoded (RLE) structures may be precomputed, one for each principal axis (X, Y, Z). Each RLE entry contains `shade_index`, `density`, and `is_transparent` flags [S15, unofficial].
*   **Intermediate Image:** A 2D buffer of size $W \times H$ storing accumulated color and opacity. Opaque pixels may store an offset to the next non-opaque pixel to skip occluded regions [S9, unofficial].

**Step 1: Factorization and Permutation**
1.  Determine the principal viewing axis by finding the object-space axis with the largest dot product with the viewing direction [S5, unofficial].
2.  Construct the permutation matrix $P$ to align the principal axis with the standard Z-axis. For example, if the principal axis is $x_0$, $P$ maps standard coordinates $(i, j, k)$ to object coordinates $(y_0, z_0, x_0)$ [S5, unofficial].
3.  Compute the modified view matrix $M'_{view} = M_{view} \cdot P^T$ [S5, unofficial].
4.  Calculate shear coefficients $S_i$ and $S_j$ for parallel projection:
    $$ S_i = \frac{M'_{12}M'_{23} - M'_{13}M'_{22}}{M'_{11}M'_{22} - M'_{21}M'_{12}}, \quad S_j = \frac{M'_{21}M'_{13} - M'_{11}M'_{23}}{M'_{11}M'_{22} - M'_{21}M'_{12}} $$
    [S5, unofficial]
5.  Calculate translation coefficients $T_i$ and $T_j$ based on the signs of $S_i, S_j$ and the maximum voxel slice index $K_{max}$:
    *   If $S_i > 0, S_j > 0$: $T_i = -S_i K_{max}, T_j = -S_j K_{max}$
    *   If $S_i > 0, S_j < 0$: $T_i = -S_i K_{max}, T_j = -S_j K_{max}$
    *   If $S_i < 0, S_j > 0$: $T_i = -S_i K_{max}, T_j = -S_j K_{max}$
    *   If $S_i < 0, S_j < 0$: $T_i = -S_i K_{max}, T_j = -S_j K_{max}$
    [S5, unofficial]
6.  Construct the 3D shear matrix $M_{shear}$:
    $$ M_{shear} = \begin{pmatrix} 1 & 0 & S_i & 0 \\ 0 & 1 & S_j & 0 \\ 0 & 0 & 1 & 0 \\ 0 & 0 & 0 & 1 \end{pmatrix} $$
    [S5, unofficial][S6, unofficial]
7.  Construct the 2D warp matrix $M_{warp2D}$:
    $$ M_{warp2D} = \begin{pmatrix} M'_{x1} & M'_{x2} & M'_{x3} \\ M'_{y1} & M'_{y2} & M'_{y3} \\ 0 & 0 & 1 \end{pmatrix} $$
    where $M'_{x1} = M'_{14} - T_i M'_{11} - T_j M'_{12}$ and $M'_{y1} = M'_{24} - T_i M'_{21} - T_j M'_{22}$ [S5, unofficial].
    *Note: For perspective projection, an additional scaling step is required for each slice, and the factorization includes a shift matrix $T_{shift}$ defined by the eye location [S5, unofficial].*

**Step 2: Shear and Composite**
1.  Initialize the intermediate image $I_{int}$ and alpha accumulator $A_{int}$ to zero.
2.  Iterate through each slice $k$ of the volume (from front to back in sheared space).
3.  Resample the slice into the intermediate image coordinates using the shear transformation. For parallel projection, the scale factor is 1.0, ensuring a 1-to-1 mapping between voxel scanlines and intermediate image pixels [S9, unofficial][S10, unofficial]. For perspective projection, scale each slice individually to account for foreshortening [S5, unofficial].
4.  Use bilinear interpolation to sample the volume data [S2, unofficial][S5, unofficial].
5.  Classify the sampled value using the transfer function to obtain opacity $\alpha$ and color $C$ [S2, unofficial].
6.  Composite into the intermediate image using front-to-back blending:
    $$ I_{int}[y, x] = I_{int}[y, x] + C \cdot \alpha \cdot (1 - A_{int}[y, x]) $$
    $$ A_{int}[y, x] = A_{int}[y, x] + \alpha \cdot (1 - A_{int}[y, x]) $$
    [S2, unofficial][S8, unofficial]
7.  **Optimization (RLE):** If RLE is enabled, traverse the volume and intermediate image scanlines in tandem. Skip transparent voxel runs and opaque pixel runs using the precomputed RLE structures [S2, unofficial][S15, unofficial].

**Step 3: Warp**
1.  Transform the intermediate image $I_{int}$ to the final image space $I$ using the warp matrix $M_{warp2D}$ [S2, unofficial][S9, unofficial].
2.  This is a 2D resampling step. It can be performed in software or using 2D texturing hardware [S21, unofficial].
3.  If using software, compute source coordinates $(src_x, src_y)$ for each destination pixel $(x, y)$ using $M_{warp2D}$ and interpolate from $I_{int}$ [S2, unofficial].
4.  If using hardware (Texture-Based Warp), set the OpenGL model/view matrix to $M_{warp2D}$ and draw the intermediate image as a textured quad [S21, unofficial].

**Pseudocode:**
```python
def shear_warp_render(volume, view_matrix, image_width, image_height):
    # 1. Factorization
    # Determine principal axis and permutation matrix P
    P = compute_permutation_matrix(view_matrix, volume)
    M_prime_view = view_matrix * transpose(P)
    
    # Compute shear coefficients for parallel projection
    denom = M_prime_view[0][0] * M_prime_view[1][1] - M_prime_view[1][0] * M_prime_view[0][1]
    S_i = (M_prime_view[0][1] * M_prime_view[1][2] - M_prime_view[0][2] * M_prime_view[1][1]) / denom
    S_j = (M_prime_view[1][0] * M_prime_view[0][2] - M_prime_view[0][0] * M_prime_view[1][2]) / denom
    
    # Compute translation coefficients
    K_max = volume.depth
    if S_i > 0: T_i = -S_i * K_max
    else: T_i = -S_i * K_max # Simplified: always negative shift relative to max
    if S_j > 0: T_j = -S_j * K_max
    else: T_j = -S_j * K_max
    
    # Construct Shear Matrix
    M_shear = [[1, 0, S_i, 0],
               [0, 1, S_j, 0],
               [0, 0, 1, 0],
               [0, 0, 0, 1]]
               
    # Construct Warp Matrix components
    M_warp_x1 = M_prime_view[0][3] - T_i * M_prime_view[0][0] - T_j * M_prime_view[0][1]
    M_warp_y1 = M_prime_view[1][3] - T_i * M_prime_view[1][0] - T_j * M_prime_view[1][1]
    # Note: Full M_warp2D requires more elements from M_prime_view, 
    # but for 2D warp of intermediate image, we primarily need the mapping logic.
    # In practice, M_warp2D is derived as M_view * P * S^-1 (for parallel)
    M_warp2D = compute_warp_matrix(M_prime_view, P, M_shear)

    # 2. Shear and Composite
    intermediate_image = zeros((image_height, image_width, 3))
    alpha_accum = zeros((image_height, image_width))
    
    # Precompute RLE if enabled
    if use_rle:
        rle_list = build_rle(volume, view_matrix) # Returns RLE for principal axis
        
    for slice_idx in range(volume.depth):
        # Resample slice into intermediate space
        # For parallel projection, scale is 1.0
        # For perspective, scale = 1.0 / (1 + slice_idx * perspective_factor)
        
        for y in range(image_height):
            for x in range(image_width):
                # Map intermediate pixel to sheared volume coordinates
                # This is the inverse of the shear transform applied to the slice
                # In sheared space, rays are perpendicular to slices.
                # We sample the slice at the corresponding (u, v) in the slice plane.
                
                # Simplified: Assume we have a function to get the resampled value
                # from the slice at the correct sheared coordinates.
                val = resample_slice(volume, slice_idx, x, y, M_shear)
                
                # Classify
                alpha, color = classify(val)
                
                # Front-to-back compositing
                if alpha_accum[y, x] < 1.0:
                    intermediate_image[y, x] += color * alpha * (1.0 - alpha_accum[y, x])
                    alpha_accum[y, x] += alpha * (1.0 - alpha_accum[y, x])
                    
                # Optimization: Skip opaque pixels if RLE is used
                if use_rle and alpha_accum[y, x] >= 1.0:
                    # Skip to next non-opaque pixel using RLE offset
                    pass 

    # 3. Warp
    final_image = zeros((image_height, image_width, 3))
    for y in range(image_height):
        for x in range(image_width):
            # Apply 2D warp to find source in intermediate image
            src_x, src_y = warp_coords(M_warp2D, x, y)
            final_image[y, x] = interpolate_2d(intermediate_image, src_x, src_y)
            
    return final_image
```

## Subtopics

### [Parallel Perspective Shear-Warp Rendering](802-parallel-perspective-shear-warp-rendering.md)
A distributed volume rendering technique that parallelizes the compositing step of the perspective shear-warp algorithm across multiple nodes using MPI. It solves the problem of rendering high-resolution perspective volumes on distributed memory clusters by offloading the computationally expensive 2D warping step to the graphics hardware of a remote display machine. Unlike parallel projection methods that distribute volume data, this method requires every node to hold a full copy of the volume, partitioning the intermediate image scanlines instead. It is distinct from hardware-based texture mapping approaches by avoiding OpenGL extension dependencies and texture memory limits, making it suitable for clusters without dedicated graphics cards.

### [CPU-based Shear-Warp](1161-cpu-based-shear-warp.md)
CPU-based Shear-Warp is a CPU implementation of the Shear-Warp algorithm that accelerates volume rendering by using Run-Length Encoding (RLE) and Hounsfield scale classification to skip empty voxels. It differs from its siblings by relying on 1D run-lists per axis rather than 3D spatial structures like octrees.

### [Permutation Proof for Projection and Warp](1702-permutation-proof-for-projection-and-warp.md)
A mathematical proof demonstrating that the projection matrix $P$ and warp matrix $W$ in the perspective shear-warp algorithm can be permuted, allowing the viewing transformation to be computed as $W \cdot P \cdot S$ instead of the standard $P \cdot W \cdot S$. This property is a basic premise for the perspective projection shear-warp algorithm, enabling specific optimization paths in the compositing step. It sets the method apart from general matrix factorizations by proving that the specific structure of the shear-warp decomposition allows the projection to precede the warp without altering the final image coordinates, provided the warp matrix satisfies specific zero-element constraints.

### [Warped Isosurface Extraction (WISE)](1906-warped-isosurface-extraction-wise.md)
Warped Isosurface Extraction (WISE) is a method to accelerate visibility tests in volume rendering by using shear-warp factorization to replace expensive perspective projections with cheaper orthographic-like projections on a warped plane. It sets itself apart from standard perspective projection by eliminating the nonlinearity of the view transformation for visibility culling, allowing precomputed per-slice coefficients for grid points and reducing the computational cost of vertex projection significantly.

### [Spatially Partitioned Shear-Warp Method](3481-spatially-partitioned-shear-warp-method.md)
A parallel volume rendering method that partitions the volume into subvolumes, generates local base plane images (sheared images) for each subvolume in parallel, composites these images using a binary tree (compositing tree) to handle occlusion/priority, and finally applies warping to correct distortion.

### Texture-Based Warp
A warp implementation that uses 2D texturing hardware to transform the intermediate image to the final screen, leveraging the OpenGL model/view and projection matrices [S21, unofficial]. It sets the OpenGL model/view matrix to the warp matrix and the projection matrix to the identity, then draws the intermediate image as a textured quad [S21, unofficial]. The warp matrix $W_{per}$ is non-affine for perspective views [S21, unofficial]. A pitfall is that texturing hardware requires image sizes to be powers of two, causing jumps in rendering time at edge lengths of 512 and 1024 pixels [S21, unofficial]. Compared to software warp, it is faster for large images but has higher overhead for small images [S21, unofficial].

### Software Warp
A warp implementation that computes the final 2D image using a pure software algorithm and pastes it to the viewport [S21, unofficial]. Parallel warp operations require 8 FLOPs, while perspective warp operations require 14 FLOPs [S21, unofficial]. A pitfall is that it does not allow automatic object ordering, requiring the programmer to manually handle depth sorting for intersecting polygons [S21, unofficial]. It is faster than texture-based warp for small images but slower for large ones [S21, unofficial].

### Intermediate Image Size Adaptation
A technique to maintain constant frame rates by dynamically adjusting the resolution of the intermediate image rendered during the compositing step [S21, unofficial]. It modifies the scaling matrix parameters to change the intermediate image size, using footprint-based interpolation for downsizing and bilinear interpolation for enlarging [S21, unofficial]. The target frame rate is typically 5-10 fps [S21, unofficial].

### Fast volume rotation using binary shear-warp factorization
A fast volume rotation technique that skips precisely empty regions along rays to be evaluated without trading image quality for speed or requiring specialized hardware [S21, unofficial]. It generates a binary volume mask indicating transparent cells, rotates the mask by an incremental binary shear transformation using bitwise boolean operations, and accelerates ray casting using the transformed mask and a lookup-table technique for finding the first non-transparent cell [S21, unofficial].

### GPU-Accelerated On-the-Fly Deskewing
An open-source software package that transforms the display of Oblique Plane Microscopy (OPM) imaging data in real time to produce a live extended depth of field projection, correcting the distorted coordinate frame [S16, abstract only, unofficial]. It utilizes GPU acceleration and multiprocessing to achieve processing rates of several Hz [S16, abstract only, unofficial].

### Hybrid Shear-Warp and Polygon Rendering
A method to achieve correct concurrent display of volumes and polygons by rendering opaque polygons first and using an inversely warped Z buffer to limit the viewing rays during the shear-warp compositing step [S21, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
*   **Time:** The algorithm is generally $O(N)$ with respect to the number of voxels, but the constant factor is significantly lower than ray casting due to the reduction of 3D interpolation to 2D bilinear interpolation and the use of RLE to skip empty space [S5, unofficial]. Performance scales well with resolution, but perspective projection is slower than parallel projection due to the need for per-slice scaling and non-uniform sampling [S9, unofficial].
*   **Memory:** Requires storage for the volume data and three RLE structures if optimization is enabled, leading to higher memory overhead compared to methods without RLE [S2, unofficial]. The intermediate image requires $O(W \times H)$ memory [S9, unofficial].

**Measured Performance:**
*   On an SGI Indigo R4000, the original implementation rendered a $256^3$ volume in 1 second for orthographic projection and 3 seconds for perspective projection [S1, unofficial][S5, unofficial].
*   On an SGI Octane, frame rates were in the sub-second range (e.g., 0.09s for Fuel dataset) [S5, unofficial].
*   Modern hardware implementations (e.g., VolumePro) can achieve real-time rates, but software implementations on standard CPUs are limited by the lack of hardware acceleration for the shear/composite steps [S1, unofficial][S12].

**Strengths and Limitations:**
*   **Strengths:** Fast software implementation; exploits spatial coherence; supports early ray termination via RLE; simple to implement on CPUs [S1, unofficial][S5, unofficial].
*   **Limitations:** Image quality is lower than ray casting due to bilinear interpolation and fixed sampling rate; artifacts (stair-casing, blurring) appear near 45-degree viewing angles and during zoom [S1, unofficial][S3, unofficial][S5, unofficial]; perspective rendering is more complex and slower; requires three copies of the volume for interactive rotation if RLE is used [S7, unofficial].

**When to Use:**
*   Use for fast, interactive software-based volume rendering on CPUs where hardware acceleration is not available or for the compositing step in hybrid pipelines [S5, unofficial].
*   Use when the viewing direction is primarily aligned with one of the principal axes [S2, unofficial].

**When Not to Use:**
*   Do not use when high image quality is required, especially for perspective views or near 45-degree angles [S1, unofficial][S3, unofficial].
*   Do not use if memory is constrained and RLE optimization is necessary [S2, unofficial].

## Background
The Shear-Warp algorithm was proposed by Lacroute and Levoy in 1994 [S2, unofficial][S5, unofficial]. It was designed as a fast software implementation for volume rendering, aiming to reduce the number of resampling passes from three to two by factorizing the projection matrix [S1, unofficial]. The algorithm was described as the "world's fastest purely software-based volume rendering algorithm" at the time of its publication [S5, unofficial]. It has been used in various hardware implementations, such as VolumePro, and remains a foundational technique for understanding the trade-offs between speed and quality in volume rendering [S1, unofficial][S5, unofficial].
