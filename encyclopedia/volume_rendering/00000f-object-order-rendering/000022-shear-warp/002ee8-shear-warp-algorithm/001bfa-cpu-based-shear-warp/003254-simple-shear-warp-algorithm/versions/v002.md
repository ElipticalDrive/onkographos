# Simple Shear-Warp Algorithm

Also called: CompositeIntermediateLinearSimple, CompositeIntermediateNearestSimple, Shear-Warp Volume Rendering

## Overview
The Simple Shear-Warp Algorithm is a CPU-based volume rendering method that traverses image and object space simultaneously by shearing the volume geometry so that orthographic rays become perpendicular to the base plane [S2, book]. It is distinguished from its siblings by its lack of complex acceleration structures (such as octrees or summed area tables), relying instead on a low-memory footprint and run-length encoding (RLE) of the intermediate image for early ray termination [S1]. It serves as the baseline implementation for the Shear-Warp family, optimized specifically for nearest-neighbor and linear interpolation variants [S1].

## How it works
The method transforms the volume rendering problem into an object-order traversal on a sheared grid, followed by a final warping step to Cartesian coordinates [S2, book].

### Inputs and Outputs
*   **Input:** A 3D volume dataset $V$ with dimensions $D_x \times D_y \times D_z$. A view direction defined by an orthographic projection [S2, book]. A classification function mapping voxel values to opacity and color [S1].
*   **Output:** A 2D image $I$ with dimensions $W \times H$.

### Data Structures
The algorithm uses a compressed volume representation [S2, book]. While the "Simple" variant does not use acceleration structures for the volume traversal itself (unlike the "Fast" variants), it utilizes RLE for the intermediate image to support early termination [S1]. The volume data is stored in three copies to support all view directions [S2, book].

**Volume Copy Layout:**
The volume is stored in three identical compressed copies, corresponding to the three principal axes (X, Y, Z) [S2, book]. Each copy is run-length encoded to remove empty voxels [S2, book].
*   **Fields:**
    *   `voxel_value`: The scalar value of the voxel.
    *   `run_length`: The number of consecutive empty voxels preceding or following the current voxel (implementation detail of RLE) [S2, book].
*   **Size:** The size depends on the data classification; RLE can achieve a >10:1 reduction in voxel count [S2, book].

### Steps

1.  **Shear:**
    Shear the volume such that orthographic rays originating from the base plane become perpendicular to that plane [S2, book]. This transformation aligns the ray direction with one of the volume's principal axes (e.g., the Z-axis) [S2, book].

2.  **Precompute Weights:**
    Because the shear ensures that rays intersect voxels at consistent locations within each 2D plane, precompute the interpolation weights for bilinear interpolation once per plane [S2, book].
    *   For **Nearest Neighbor**: Weights are trivial (select the closest voxel) [S2, book].
    *   For **Linear**: Calculate the fractional offsets $(dx, dy)$ of the ray intersection within the voxel grid on the sheared plane; these offsets are constant for all rays traversing the same plane row [S2, book].

3.  **Traverse (Object-Order):**
    Perform an object-order traversal visiting voxels along each row in each plane in front-to-back order [S2, book]. There is a one-to-one correspondence between samples in a sheared plane and pixels on the image plane [S2, book]. Iterate through the compressed volume copies [S2, book]. If the current view direction aligns with the Z-axis, use the Z-aligned copy [S2, book]. For each voxel $v$ with opacity $\alpha_v$ and color $C_v$: Apply the precomputed interpolation weights to determine the effective sample value $S$ from the 2D plane neighbors [S2, book]. Map $S$ to color $C$ and opacity $\alpha$ using the transfer function [S1]. Composite $C$ and $\alpha$ into the intermediate image $I_{shear}$ using front-to-back alpha compositing:
    $$ C_{out} = C_{in} + C \cdot \alpha \cdot (1 - \alpha_{in}) $$
    $$ \alpha_{out} = \alpha_{in} + \alpha \cdot (1 - \alpha_{in}) $$
    **Early Termination:** If $\alpha_{out}$ reaches 1.0 (full opacity), skip the remaining samples for that pixel [S2, book]. The RLE of the intermediate image allows skipping pixels that are already fully opaque [S1].

4.  **Compress (RLE of Volume):**
    The volume is pre-processed or traversed using Run-Length Encoding (RLE) to skip empty voxels [S2, book]. The RLE structure indicates how many voxels are skipped, which corresponds to the number of pixels to skip in the image plane during the traversal [S2, book].

5.  **Warp:**
    Perform a final resampling (warping) operation to transform the image from the sheared space on the base plane to Cartesian space on the final image plane [S2, book]. This step corrects the geometric distortion introduced by the shear transformation [S2, book].

### Pseudocode

```python
def simple_shear_warp(volume, view_direction, width, height):
    # Cast dimensions to integers to prevent float indexing errors
    W = int(width)
    H = int(height)
    dx, dy, dz = view_direction.x, view_direction.y, view_direction.z
    abs_dx, abs_dy, abs_dz = abs(dx), abs(dy), abs(dz)

    # 1. Determine principal axis and shear factors
    if abs_dz >= abs_dx and abs_dz >= abs_dy:
        axis = 'Z'
        sx, sy = -dx / dz, -dy / dz
    elif abs_dy >= abs_dx:
        axis = 'Y'
        sx, sy = -dx / dy, -dz / dy
    else:
        axis = 'X'
        sx, sy = -dy / dx, -dz / dx

    # 2. Initialize intermediate image in sheared space
    intermediate_image = [[0.0] * W for _ in range(H)]
    opacity_image = [[0.0] * W for _ in range(H)]

    # 3. Precompute interpolation weights
    # [G] Weights are constant per plane row due to shear alignment
    weights = [[0.25, 0.25, 0.25, 0.25] for _ in range(H)]

    # 4. Traverse volume in object order
    for plane_idx in range(volume.depth):
        plane = volume.get_plane(plane_idx, axis)
        for row_idx in range(plane.height):
            row = plane.get_row(row_idx)
            for voxel in row.voxels:
                if voxel.is_empty:
                    continue

                # Apply precomputed interpolation weights
                sample_value = (voxel.v0 * weights[row_idx][0] +
                                voxel.v1 * weights[row_idx][1] +
                                voxel.v2 * weights[row_idx][2] +
                                voxel.v3 * weights[row_idx][3])

                # Map to color and opacity
                color, alpha = transfer_function(sample_value)

                # Map sheared voxel coordinates to image coordinates
                u = int(voxel.x - sx * voxel.z)
                v = int(voxel.y - sy * voxel.z)

                if 0 <= u < W and 0 <= v < H:
                    current_alpha = opacity_image[v][u]
                    current_color = intermediate_image[v][u]

                    # Front-to-back compositing
                    new_alpha = current_alpha + alpha * (1.0 - current_alpha)
                    new_color = current_color + color * alpha * (1.0 - current_alpha)

                    intermediate_image[v][u] = new_color
                    opacity_image[v][u] = new_alpha

                    # Early termination
                    if new_alpha >= 1.0:
                        break

    # 5. Warp to Cartesian space
    final_image = warp(intermediate_image, view_direction, W, H)
    return final_image

def transfer_function(value):
    # [G] Standard transfer function mapping scalar to (R,G,B) and alpha
    return (value, value, value), value / 255.0

def warp(image, view_direction, W, H):
    # [G] Inverse shear: maps sheared coordinates back to Cartesian pixel grid
    final = [[0.0] * W for _ in range(H)]
    for y in range(H):
        for x in range(W):
            sx_inv, sy_inv = view_direction.x / view_direction.z, view_direction.y / view_direction.z
            sheared_x = x + sx_inv * y
            sheared_y = y + sy_inv * y
            final[y][x] = image[int(sheared_y)][int(sheared_x)]
    return final
```

### Parameters
*   **Interpolation Type:** The algorithm has specific optimized versions for 'nearest neighbour' and 'linear' interpolation [S1].
*   **Number of Volume Copies:** Requires three copies of the compressed volume to allow front-to-back traversal from all view directions [S2, book].

### Edge Cases and Pitfalls
*   **Perspective Viewing:** If a perspective viewing transformation is used, the simple shear may not align rays perfectly perpendicular to the base plane for all pixels. This may require traversing all three compressed copies of the volume to achieve the correct traversal order [S2, book].
*   **Degenerate View Directions:** If the view direction is parallel to one of the principal axes, the shear factors become undefined (division by zero). The algorithm must handle these cases by directly using the axis-aligned copy without shear [G].
*   **Precision:** The precomputation of interpolation weights relies on the consistency of ray intersections. Floating-point precision errors in the shear transformation can lead to artifacts if not handled carefully [G].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of non-empty voxels, assuming RLE compression is effective [S2, book]. The warping step is $O(W \times H)$ [G].
*   **Memory Complexity:** Low memory footprint [S1]. Requires three copies of the compressed volume and an intermediate image [S2, book][S1]. No octrees or summed area tables are used [S1].
*   **Performance:** RLE can achieve a >10:1 reduction in voxels depending on data classification [S2, book]. This makes it efficient for datasets with large empty regions [S2, book].
*   **Strengths:** Simple implementation, low memory usage, efficient for orthographic projections with empty space [S1].
*   **Limitations:** Not suitable for perspective views without significant modifications (traversing all copies) [S2, book]. Performance degrades if the volume has little empty space (RLE compression is ineffective) [S2, book].
*   **When to use:** Orthographic volume rendering with a need for low memory usage and simple implementation [S1].
*   **When not to use:** Perspective rendering, or datasets with no empty space [S2, book].

## Background
The shear-warp method was introduced by Lacroute and Levoy in 1994 [S2, book]. It is an efficient variant of ray casting that leverages the correspondence between samples and pixels in a sheared coordinate system [S2, book]. The Simple Shear-Warp Algorithm is a specific implementation within the VTK (Visualization Toolkit) framework, implemented as templated functions `CompositeIntermediateNearestSimple` and `CompositeIntermediateLinearSimple` [S1]. It is part of the Shear-Warp family, which also includes faster variants using RLE on the volume itself or classification-based acceleration structures [S1].
