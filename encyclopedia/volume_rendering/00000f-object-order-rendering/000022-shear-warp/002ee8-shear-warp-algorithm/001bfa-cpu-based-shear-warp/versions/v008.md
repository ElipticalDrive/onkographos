# CPU-based Shear-Warp

Also called: CPU Shear-Warp

## Overview
CPU-based Shear-Warp is a volume rendering method that implements the Shear-Warp algorithm on a central processing unit, utilizing Run-Length Encoding (RLE) to skip empty voxels and accelerate rendering [S1, unofficial][S2, unofficial][S3, unofficial]. It solves the performance bottleneck of standard Shear-Warp by avoiding complex 3D acceleration structures like octrees, relying instead on the spatial coherence of medical volume data [S1, unofficial][S2, unofficial][S3, unofficial]. Unlike its GPU-based sibling [GPU-based Shear-Warp](7425-gpu-based-shear-warp.md), it is significantly slower and limited to lower sampling rates, but serves as a baseline for comparison [S2, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A 3D volume dataset (e.g., DICOM medical images), a viewing direction defined by a vector $\mathbf{v}_0$, and a transfer function [S1, unofficial][S2, unofficial][S3, unofficial].
*   **Output:** A 2D rendered image [S2, unofficial].

**Data Structures**
The method constructs three separate data structures, one for each principal coordinate axis (X, Y, Z) corresponding to the three principal view directions [S1, unofficial][S2, unofficial][S3, unofficial]. Each data structure consists of a set of lists of runs [S1, unofficial][S2, unofficial][S3, unofficial].
*   **Run:** A contiguous sequence of voxels along a scan line [S1, unofficial][S2, unofficial][S3, unofficial].
*   **Run Types:**
    1.  **Completely Transparent:** Corresponds to empty voxels or voxels with zero opacity [S1, unofficial][S2, unofficial][S3, unofficial].
    2.  **Not Completely Transparent:** Voxels with non-zero opacity [S1, unofficial][S2, unofficial][S3, unofficial].
*   **Layout:** Each list in the set corresponds to one scan line of one slice [S1, unofficial][S2, unofficial][S3, unofficial].

**Algorithm Steps**

1.  **Preprocessing: Classification and Compression**
    For each coordinate axis (X, Y, Z):
    1.  Iterate through each slice and each scan line within that slice [S1, unofficial][S2, unofficial][S3, unofficial].
    2.  Classify each voxel in the scan line using the Hounsfield scale and a linear transfer function with lower and upper bounds to determine opacity [S1, unofficial][S2, unofficial][S3, unofficial].
        The opacity $\alpha$ is calculated using a linear interpolation between the bounds, clamping to $0$ below the lower bound and $1$ above the upper bound [G].
    3.  Compress the scan line into a list of runs based on the calculated opacity [S1, unofficial][S2, unofficial][S3, unofficial]. Voxels with $\alpha = 0$ form "completely transparent" runs, while voxels with $\alpha > 0$ form "not completely transparent" runs [S1, unofficial][S2, unofficial][S3, unofficial]. Consecutive voxels of the same type are merged into a single run [S1, unofficial][S2, unofficial][S3, unofficial].

2.  **Rendering: Shear, Warp, and Accumulate**
    For each principal view direction (corresponding to the three axes):
    1.  **Shear:** Apply a shear transformation to the volume data to align the viewing rays with the principal axis. The shear factors $s_x$ and $s_y$ are derived from the viewing direction vector $\mathbf{v}_0 = (v_{0x}, v_{0y}, v_{0z})$ [S1, unofficial][S2, unofficial]:
        $$
        s_x = -\frac{v_{0x}}{v_{0z}}
        $$
        $$
        s_y = -\frac{v_{0y}}{v_{0z}}
        $$
        [G: This assumes the viewing direction is normalized or the ratio holds for the projection geometry. The negative sign is explicitly stated in the sources.]
    2.  **Warp:** Project the sheared volume onto the 2D image plane [S2, unofficial].
    3.  **Accumulate:** Traverse the precomputed RLE data structures slice by slice and line by line [S1, unofficial][S2, unofficial][S3, unofficial]. For each pixel in the image, accumulate the color and opacity contributions from the voxels along the ray [S2, unofficial]. The algorithm skips "completely transparent" runs entirely to skip empty voxels, which drastically speeds up rendering [S1, unofficial][S2, unofficial][S3, unofficial]. A Phong shading model is used for direct lighting during the accumulation step [S2, unofficial].

**Pseudocode**

```python
def cpu_shear_warp(volume_data, view_direction, image_width, image_height, h_min, h_max):
    """
    volume_data: 3D array (X, Y, Z) of Hounsfield units
    view_direction: tuple (vx, vy, vz)
    image_width, image_height: int
    h_min, h_max: float, bounds for linear transfer function
    """
    vx, vy, vz = view_direction
    
    # 1. Preprocessing: Build RLE structures for each axis
    # The sources specify 3 data structures, one for each coordinate axis.
    # Each structure maps a slice/line coordinate to a list of runs.
    rle_structures = {}
    for axis in ['X', 'Y', 'Z']:
        rle_structures[axis] = build_rle(volume_data, axis, h_min, h_max)
        
    # 2. Rendering
    # Calculate shear factors
    if vz == 0:
        raise ValueError("View direction cannot be perpendicular to the projection plane (vz=0)")
        
    sx = -vx / vz
    sy = -vy / vz
    
    # Initialize image buffer
    image = [[(0.0, 0.0, 0.0, 0.0) for _ in range(image_width)] for _ in range(image_height)]
    
    # Traverse slices and lines
    # Assuming the primary view direction aligns with the Z-axis after shear.
    # We iterate over the image pixels, which map to (x, y) in the sheared space.
    for y in range(image_height):
        for x in range(image_width):
            # Map image pixel to volume coordinates in the sheared space.
            # In Shear-Warp, the warp step transforms image coordinates to volume coordinates.
            # For a standard setup, the ray passes through volume at (x, y, z).
            # We retrieve the precomputed runs for this (x, y) line along Z.
            runs = rle_structures['Z'].get((x, y), [])
            
            accumulated_alpha = 0.0
            accumulated_color = (0.0, 0.0, 0.0)
            
            for run in runs:
                if run.is_transparent:
                    continue # Skip empty voxels
                
                # Process the run
                # A run covers a range of z (depth)
                for z in range(run.start, run.end + 1):
                    # Get voxel value
                    h_val = volume_data[x, y, z]
                    
                    # Transfer function
                    if h_val < h_min:
                        alpha = 0.0
                    elif h_val > h_max:
                        alpha = 1.0
                    else:
                        alpha = (h_val - h_min) / (h_max - h_min)
                        
                    # Color mapping and Phong lighting are not specified in the sources [G]
                    color = (0.0, 0.0, 0.0) 
                    
                    # Blending
                    weight = alpha * (1.0 - accumulated_alpha)
                    accumulated_color = (
                        accumulated_color[0] + color[0] * weight,
                        accumulated_color[1] + color[1] * weight,
                        accumulated_color[2] + color[2] * weight
                    )
                    accumulated_alpha += weight
                    
                    # Early termination if fully opaque
                    if accumulated_alpha >= 1.0:
                        break
                        
            image[y][x] = (accumulated_color[0], accumulated_color[1], accumulated_color[2], accumulated_alpha)
            
    return image

def build_rle(volume_data, axis, h_min, h_max):
    """
    Builds RLE structures for a specific axis.
    Returns a dictionary mapping slice/line indices to lists of runs.
    """
    rle = {}
    shape = volume_data.shape
    
    if axis == 'Z':
        for x in range(shape[0]):
            for y in range(shape[1]):
                line = volume_data[x, y, :]
                runs = compress_line(line, h_min, h_max)
                rle[(x, y)] = runs
    elif axis == 'Y':
        for x in range(shape[0]):
            for z in range(shape[2]):
                line = volume_data[x, :, z]
                runs = compress_line(line, h_min, h_max)
                rle[(x, z)] = runs
    elif axis == 'X':
        for y in range(shape[1]):
            for z in range(shape[2]):
                line = volume_data[:, y, z]
                runs = compress_line(line, h_min, h_max)
                rle[(y, z)] = runs
    return rle

def compress_line(line, h_min, h_max):
    """
    Compresses a 1D line of Hounsfield values into runs.
    """
    runs = []
    if not line:
        return runs
        
    current_type = is_transparent(line[0], h_min, h_max)
    current_start = 0
    
    for i in range(1, len(line)):
        is_trans = is_transparent(line[i], h_min, h_max)
        if is_trans != current_type:
            runs.append(Run(current_type, current_start, i - 1))
            current_type = is_trans
            current_start = i
            
    runs.append(Run(current_type, current_start, len(line) - 1))
    return runs

def is_transparent(h_val, h_min, h_max):
    """Returns True if opacity is 0."""
    if h_val < h_min:
        return True
    return False

class Run:
    def __init__(self, is_transparent, start, end):
        self.is_transparent = is_transparent
        self.start = start
        self.end = end
```

## Subtopics

### [Simple Shear-Warp Algorithm](6736-simple-shear-warp-algorithm.md)
The Simple Shear-Warp Algorithm is a CPU-based volume rendering method that traverses image and object space simultaneously by shearing the volume geometry so that orthographic rays become perpendicular to the base plane. It is distinguished from its siblings by its lack of complex acceleration structures (such as octrees or summed area tables), relying instead on a low-memory footprint and run-length encoding (RLE) of the intermediate image for early ray termination. It serves as the baseline implementation for the Shear-Warp family, optimized specifically for nearest-neighbor and linear interpolation variants.

### [Fast Shear-Warp with Runlength Encoding](6737-fast-shear-warp-with-runlength-encoding.md)
Fast Shear-Warp with Runlength Encoding is a scanline-based volume rendering algorithm optimized for parallel projections that uses run-length encoding (RLE) of voxel scanlines and intermediate image pixels to skip transparent voxels and occluded pixels, assuming a fixed opacity transfer function. It achieves sub-second rendering times for moderately-sized datasets, with quality rivaling raycasting and splatting at unity magnification. Unlike the Simple Shear-Warp Algorithm, which traverses every voxel, this method leverages object coherence (transparent voxel runs) and image coherence (occluded pixel runs) to significantly reduce the number of shading and compositing operations.

## Operating characteristics
*   **Time Complexity:** The preprocessing step is $O(N)$ where $N$ is the number of voxels, as each voxel is visited once to build the RLE structures [S1, unofficial][S2, unofficial][S3, unofficial]. The rendering step is proportional to the number of non-transparent voxels along the rays, which is significantly less than $N$ due to the skipping of transparent runs [S1, unofficial][S2, unofficial][S3, unofficial].
*   **Memory Complexity:** The RLE structures require memory proportional to the number of runs [S1, unofficial][S2, unofficial][S3, unofficial]. In the worst case (checkerboard pattern), this is $O(N)$, but for typical medical volumes with large empty spaces, it is much smaller [G]. The sources do not specify the exact memory overhead of the RLE lists [S1, unofficial][S2, unofficial][S3, unofficial].
*   **Measured Performance:** On a 3.8GHz Pentium 4 with 2GB RAM, rendering times for the Skull model (320x320x46) were 22s, 43s, 64s, 86s, and 107s for sampling rates $s=1$ to $5$ respectively [S2, unofficial]. For the Knee model (512x512x73), times were 110s, 155s, 226s, 300s, and 370s for $s=1$ to $5$ [S2, unofficial].
*   **Scaling:** Performance degrades linearly with increasing sampling rate [S2, unofficial]. The method is limited to a maximum sampling rate of 5 due to speed constraints [S2, unofficial].
*   **Strengths:** Low memory footprint compared to octree-based methods; efficient skipping of empty voxels; simple implementation on CPU [S1, unofficial][S2, unofficial][S3, unofficial].
*   **Limitations:** Significantly slower than GPU-based methods; limited to low sampling rates for interactive frame rates; requires preprocessing time to build RLE structures [S2, unofficial].
*   **When to use:** When GPU hardware is unavailable or when a CPU-based baseline is needed for comparison [S2, unofficial].
*   **When not to use:** When high frame rates or high sampling rates are required [S2, unofficial].

## Background
The CPU-based Shear-Warp algorithm was implemented as part of a study comparing CPU and GPU volume rendering techniques [S1, unofficial][S2, unofficial][S3, unofficial]. The implementation specifically avoids the octree structures suggested in the original paper, opting for RLE compression instead [S1, unofficial][S2, unofficial][S3, unofficial]. The method uses the Hounsfield scale for classifying voxels, which is standard in medical imaging [S1, unofficial][S2, unofficial][S3, unofficial].
