# CPU-based Shear-Warp

Also called: CPU Shear-Warp

## Overview
CPU-based Shear-Warp is a high-performance volume rendering method that achieves sub-second rendering times for moderately-sized datasets by skipping transparent voxels using runlength-encoded (RLE) data structures [S1, S2, unofficial]. It rivals the image quality of raycasting and splatting at unity magnification but is distinguished by its reliance on pre-classified opacity runs and a fixed view-dependent sampling interval that precludes adaptive supersampling [S1, unofficial].

## How it works
The method implements the Shear-Warp algorithm on a CPU, utilizing RLE compression and run-lists to skip empty voxels [S1, S2, unofficial]. Unlike the original Shear-Warp paper which suggested 3D data structures like octrees, this implementation relies solely on 1D run-lists for each principal axis [S1, S2, unofficial].

### Inputs and Outputs
*   **Input:** A 3D volume dataset (e.g., medical imagery using the Hounsfield scale) [S1, S2, unofficial].
*   **Output:** A 2D rendered image [S1, S2, unofficial].

### Data Structures
The algorithm constructs three separate data structures, one for each coordinate axis ($x, y, z$) corresponding to the three principal view directions [S1, S2, unofficial].

Each data structure consists of a set of lists of runs. Each list corresponds to one scan line of one slice [S1, S2, unofficial].
*   **Run Definition:** A run is a contiguous sequence of voxels along a scan line.
*   **Run Types:**
    1.  **Completely Transparent:** Represents empty voxels. These are skipped during rendering [S1, S2, unofficial].
    2.  **Not Completely Transparent:** Represents voxels with non-zero opacity. These are processed [S1, S2, unofficial].

### Pre-processing Steps
Before rendering, the volume data is compressed into the RLE structures:

1.  **Classification:** Voxels are classified using the Hounsfield scale (a quantitative scale for describing radiodensity) and a transfer function [S1, S2, unofficial].
    *   The transfer function is defined as a linear curve with a lower bound ($T_{min}$) and an upper bound ($T_{max}$) [S1, S2, unofficial].
    *   Input values $v$ are converted to opacities $\alpha$ as follows:
        $$
        \alpha = \begin{cases} 
        0 & \text{if } v < T_{min} \\
        \frac{v - T_{min}}{T_{max} - T_{min}} & \text{if } T_{min} \le v \le T_{max} \\
        1 & \text{if } v > T_{max}
        \end{cases}
        $$
        [S1, S2, unofficial]
2.  **Compression:** For each coordinate axis and for each slice, each scan line of voxels is compressed into a list of runs based on the computed opacities [S1, S2, unofficial].

### Rendering Steps
The rendering process traverses the pre-computed data structures:

1.  **Iteration:** Iterate through the data structures slice by slice and line by line [S1, S2, unofficial].
2.  **Skip Transparent Runs:** For each scan line, iterate through the list of runs. If a run is marked as "completely transparent," ignore it entirely (skip the empty voxels) [S1, S2, unofficial].
3.  **Composite Opaque Runs:** For runs marked as "not completely transparent," perform the standard Shear-Warp compositing steps (Shear, Project, Warp) for the voxels within those runs [S1, S2, unofficial].
    *   *Note:* The specific shear, projection, and warp matrices are derived from the viewing transformation, as detailed in the parent article [Shear-Warp Algorithm](4304-shear-warp-algorithm.md).

### Pseudocode

```python
def cpu_shear_warp_render(volume_data, transfer_min, transfer_max, view_matrix):
    """
    Renders volume data using CPU-based Shear-Warp with RLE acceleration.
    
    Args:
        volume_data: 3D array of voxel values (e.g., Hounsfield units).
        transfer_min: Lower bound of the transfer function.
        transfer_max: Upper bound of the transfer function.
        view_matrix: 4x4 view transformation matrix.
        
    Returns:
        2D image array.
    """
    # 1. Pre-processing: Build RLE structures for all 3 axes
    # Each structure is a list of lists of runs.
    # runs[axis][slice_idx][line_idx] = list of (start_voxel_idx, length, is_transparent)
    rle_structures = build_rle_structures(volume_data, transfer_min, transfer_max)
    
    # 2. Initialize output image
    image = zeros(image_width, image_height)
    
    # 3. Rendering: Iterate through each axis (principal view direction)
    for axis in [0, 1, 2]: # x, y, z
        structure = rle_structures[axis]
        
        # Iterate through slices along the axis
        for slice_idx in range(num_slices):
            slice_runs = structure[slice_idx]
            
            # Iterate through scan lines in the slice
            for line_idx in range(num_lines):
                runs = slice_runs[line_idx]
                
                # Iterate through runs in the scan line
                for run in runs:
                    start_voxel, length, is_transparent = run
                    
                    # Skip completely transparent runs
                    if is_transparent:
                        continue
                    
                    # Process the opaque run
                    # Apply Shear-Warp compositing for voxels from start_voxel to start_voxel + length
                    # This involves transforming voxel coordinates, projecting to 2D, 
                    # and compositing into the image buffer.
                    # The specific compositing logic is defined in the parent Shear-Warp Algorithm article.
                    shear_warp_composite(image, volume_data, run, axis, view_matrix)
                    
    return image

def build_rle_structures(volume_data, t_min, t_max):
    """
    Compresses volume data into RLE structures for all 3 axes.
    """
    rle = {}
    for axis in [0, 1, 2]:
        rle[axis] = []
        # Determine slice and line dimensions based on axis
        # For each slice along the axis:
        for slice_idx in range(num_slices):
            slice_runs = []
            # For each scan line in the slice:
            for line_idx in range(num_lines):
                # Extract voxels along the scan line
                voxels = get_scan_line_voxels(volume_data, axis, slice_idx, line_idx)
                
                # Classify and compress into runs
                runs = []
                current_run_start = 0
                current_run_transparent = True
                
                for i, v in enumerate(voxels):
                    # Compute opacity
                    if v < t_min:
                        alpha = 0
                    elif v > t_max:
                        alpha = 1
                    else:
                        alpha = (v - t_min) / (t_max - t_min)
                        
                    is_transparent = (alpha == 0)
                    
                    if is_transparent == current_run_transparent:
                        # Continue current run
                        pass
                    else:
                        # End current run, start new one
                        if i > current_run_start:
                            runs.append((current_run_start, i - current_run_start, current_run_transparent))
                        current_run_start = i
                        current_run_transparent = is_transparent
                
                # Append final run
                if len(voxels) > current_run_start:
                    runs.append((current_run_start, len(voxels) - current_run_start, current_run_transparent))
                    
                slice_runs.append(runs)
            rle[axis].append(slice_runs)
    return rle
```

### Parameters
*   **Transfer Function Bounds ($T_{min}, T_{max}$):** Define the linear opacity mapping. Typical values depend on the dataset (e.g., for CT data, $T_{min}$ and $T_{max}$ might be set to isolate specific tissue densities) [S1, S2, unofficial].
*   **View Matrix:** Defines the camera position and orientation [S1, S2, unofficial].

### Edge Cases and Pitfalls
*   **Classification Changes:** If the transfer function parameters ($T_{min}, T_{max}$) change, the RLE structures must be recomputed, as the transparency of voxels changes [S3].
*   **No Adaptive Sampling:** The method uses a fixed view-dependent sampling interval, which precludes adaptive supersampling [S1, unofficial].
*   **No 3D Acceleration:** The algorithm does not use 3D data structures like octrees, which may limit performance on very sparse or complex datasets compared to methods that do [S1, S2, unofficial].

### Simple Shear-Warp Algorithm
The Simple Shear-Warp Algorithm is a shear-warp volume rendering method that does not use acceleration data structures (except for the runlength-encoded intermediate image for early ray termination), resulting in a low memory footprint [S3]. It has specific optimized versions for 'nearest neighbour' and 'linear' interpolation, implemented as templated functions named `CompositeIntermediateNearestSimple` and `CompositeIntermediateLinearSimple` [S3].

## Operating characteristics
*   **Performance:** Achieves sub-second rendering times for moderately-sized datasets [S1, unofficial].
*   **Memory Footprint:** Low memory footprint compared to methods using 3D acceleration structures like octrees [S3].
*   **Strengths:** High performance on CPU; skips empty voxels effectively using RLE; simple implementation without complex 3D data structures [S1, S2, unofficial].
*   **Limitations:** Requires recomputation of RLE structures if classification changes; fixed sampling interval prevents adaptive supersampling; does not use 3D acceleration structures like octrees [S1, S2, unofficial][S3].
*   **When to Use:** Interactive rendering of moderately-sized datasets on CPU where memory is constrained and classification is static [S1, S2, unofficial][S3].
*   **When Not to Use:** When adaptive supersampling is required, or when the dataset is very sparse and benefits from 3D acceleration structures like octrees [S1, S2, unofficial][S3].

## Background
The Shear-Warp algorithm was originally designed for interactive rendering of volume data on the CPU [S2, unofficial]. It facilitates interpolation by decomposing the viewing transformation into a 3D shear, a projection, and a 2D warp [Parent]. The CPU-based implementation with RLE acceleration was developed to speed up rendering by skipping empty voxels, as described in [S1, S2, unofficial]. The Simple Shear-Warp variant is part of the VTK volume mapper API implementation [S3].
