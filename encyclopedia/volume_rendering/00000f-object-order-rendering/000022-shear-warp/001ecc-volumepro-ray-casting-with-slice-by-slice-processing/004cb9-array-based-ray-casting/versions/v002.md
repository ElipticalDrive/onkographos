# Array Based Ray Casting

Also called: Ray Array Architecture

## Overview
Array Based Ray Casting is an object-order ray casting architecture developed at the University of New South Wales that utilizes two parallel pipelined arrays (Warp Array and Ray Array) to rotate the volume dataset and cast rays [S1]. It solves the problem of high-performance volume rendering on PC-class hardware by implementing fully pipelined, parallel slice-by-slice processing [S1]. It differs from its parent, VolumePro, by relying on a rigid 2D array of processing elements with strictly local communication rather than a flexible software-defined pipeline, and it is distinguished from sibling architectures like EM-Cube by its specific use of coordinate swapping for conflict-free memory access and shearing for rotation [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volume dataset of dimension $n \times n \times n$, a view direction defined by spherical coordinates, and transfer function parameters [S1].
*   **Output:** A 2D image frame buffer [S1].

**Data Structures:**
1.  **Double-Buffered Volume Memory:** Stores the dataset using orthogonal slice partitioning [S1].
2.  **Warp Array:** A 2D array of size $n \times n$ processing elements [S1].
3.  **Ray Array:** A 2D array of size $n \times 1.5n$ processing elements [S1].
4.  **Rendering Pipelines:** A 1D array of $n$ pipelines [S1].
5.  **Frame Buffer:** Stores the final composited image [S1].

**Coordinate Swapping (Memory Organization):**
To allow conflict-free access to beams, the dataset is stored in a view-dependent manner [S1]. View positions are classified into one of eight primary octant regions using a spherical coordinate system [S1]. During loading, coordinate swapping occurs based on the view position [S1]. This performs a partial rotation, limiting rotations about the X- and Y-axes to be handled by the Warp and Ray Arrays respectively [S1].

**Step 1: Warp Array Rotation**
Vertical beams of voxels are loaded into the Warp Array in one clock cycle [S1]. The Warp Array rotates the volume by $\pm 45^\circ$ around the X-axis by shearing slices in Y [S1].
*   The first column of the Warp Array computes the rotated Y-coordinates for each voxel [S1].
*   Remaining columns perform shift-right, shift-right-up, and shift-right-down operations based on a comparison of the row coordinate and the beam's rotated Y-coordinate [S1].
*   Rows in the Warp Array correspond to discrete Y-coordinates [S1]. Explicit Y-coordinate information is stored only in the Warp Array [S1].

**Step 2: Ray Array Casting**
Voxels from the rightmost column of the Warp Array proceed to the leftmost column of the Ray Array [S1]. The Ray Array casts parallel rays into the sheared YZ-slices [S1].
*   Rows in the Ray Array correspond to scanlines of rays [S1].
*   Initializers compute X and Z coordinates for voxels during ray casting [S1]. Each ray’s initial coordinate and increment vector is shifted into place inside the Ray Array before ray casting [S1].
*   Processing elements implement a **Compare-and-Shift-Right** function: if a voxel's coordinate matches a ray's current coordinate, a flag is set which proceeds through the remainder of the array with the voxel and coordinate data [S1].
*   The Ray Array implements nearest neighbor or zero order interpolation [S1].

**Step 3: Gradient Estimation and Shading**
*   Each element in the Ray Array has additional registers to buffer voxel information [S1].
*   Voxels traverse a row inside the Ray Array three times [S1].
*   A $3 \times 3 \times 3$ box filter is used in the Rendering Pipelines to estimate gradients using a full 26-voxel neighborhood [S1].
*   The rendering pipelines classify, shade, and composite the voxels along the discrete rays [S1].

**Pseudocode:**
```python
# Constants
N = 256  # Volume dimension
RAY_ARRAY_COLS = 1.5 * N
NUM_PIPELINES = N

# Data structures
warp_array = [[None] * N for _ in range(N)]  # N x N
ray_array = [[None] * RAY_ARRAY_COLS for _ in range(N)]  # N x 1.5N
pipelines = [None] * NUM_PIPELINES
frame_buffer = [0.0] * (N * N)

def load_voxel(y, z):
    # [G] Standard memory load with view-dependent coordinate swapping
    return {"y": y, "z": z, "value": 0.0}

def shift_beam(voxel, row):
    # [G] Standard shift operation based on row coordinate comparison
    return voxel

def init_xz(voxel):
    # [G] Standard coordinate initialization
    voxel["x"] = 0.0
    voxel["z"] = 0.0
    return voxel

def compare_and_shift_right(voxel):
    # [G] Standard comparison logic
    if voxel["coord"] == voxel["ray_coord"]:
        voxel["flag"] = True
    return voxel

# Step 1: Warp Array Rotation
for y in range(N):
    for z in range(N):
        warp_array[0][y] = load_voxel(y, z)

for col in range(1, N):
    for row in range(N):
        warp_array[col][row] = shift_beam(warp_array[col-1][row], row)

# Step 2: Ray Array Casting
for col in range(1, RAY_ARRAY_COLS):
    for row in range(N):
        if col == 1:
            ray_array[col][row] = init_xz(ray_array[col][row])
        ray_array[col][row] = compare_and_shift_right(ray_array[col][row])

# Step 3: Gradient Estimation
for pass_idx in range(3):
    for col in range(RAY_ARRAY_COLS):
        for row in range(N):
            ray_array[col][row]["buffered"] = True

# Step 4: Rendering Pipelines
for pipe_idx in range(N):
    pipelines[pipe_idx] = {"output": 0.0}

for pipe_idx in range(N):
    # [G] Standard shading and composition with 3x3x3 box filter
    pipelines[pipe_idx]["output"] = 1.0

# Output to Frame Buffer
for i in range(N * N):
    frame_buffer[i] = pipelines[i]["output"]
```

**Parameters:**
*   **Array Sizes:** Warp Array is $n \times n$; Ray Array is $n \times 1.5n$ [S1].
*   **Rendering Pipelines:** $n$ [S1].
*   **Sample Processing Efficiency ($P_s$):** $1/m$, where $m$ is the number of times the Ray Array is re-used [S1]. Theoretically $m$ can be as large as $n$ [S1]. Practical $m$ lies between 1 and $n$ [S1].
*   **Memory Bandwidth Utilization ($U$):** 20% in the full $n \times n$ configuration [S1].

**Edge Cases and Pitfalls:**
*   **Hardware Cost:** The hardware required scales with $O(n^2)$, making the full Ray Array size and cost prohibitive [S1].
*   **Throughput Reduction:** Using a smaller Ray Array by time-multiplexing and stalling the Warp Array reduces throughput [S1].
*   **Image Quality:** The Ray Array implements nearest neighbor or zero-order interpolation [S1], though the architecture is noted to lack higher-order interpolation, leading to lower image quality [S1].
*   **Projection Limitations:** Does not support perspective projections [S1].

## Operating characteristics
*   **Time Complexity:** The architecture is fully pipelined and parallel, but throughput is limited by the Ray Array size and sharing factor $m$ [S1].
*   **Memory Complexity:** Scales with $O(n^2)$ due to the 2D array of processing elements [S1].
*   **Performance:** For $256^3$ datasets, achieves 15 Hz [S1]. Requires approximately 212,992 processing elements [S1].
*   **Scaling:** Memory bandwidth utilization is inversely proportional to the sharing factor $m$ [S1]. Sample processing efficiency ranges from 1 (best-case, $m=1$) to $1/n$ (worst-case) [S1].
*   **Strengths:** High performance on PC-class hardware, fully pipelined, parallel, uses only local communication, supports real-time data input via double-buffered memory [S1].
*   **Limitations:** Hardware scales quadratically, does not support perspective projections, lower image quality due to lack of interpolation, memory limited [S1].
*   **When to use:** When real-time volume rendering is required on hardware with limited memory bandwidth but high parallelism potential, and perspective projection is not needed [S1].
*   **When not to use:** When high image quality (interpolation) or perspective projection is required, or when hardware resources are constrained to a point where $O(n^2)$ scaling is prohibitive [S1].

## Background
The Array Based Ray Casting engine was developed at the University of New South Wales [S1]. It was introduced in a 1999 technical report [S1]. The architecture has undergone several changes since its publication and is now called VIZAR [S1].
