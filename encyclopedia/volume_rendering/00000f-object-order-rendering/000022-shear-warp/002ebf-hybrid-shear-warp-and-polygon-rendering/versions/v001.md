# Hybrid Shear-Warp and Polygon Rendering

Also called: Shear-Warp Rendering Modes

## Overview
This method extends the Shear-Warp Algorithm to support the concurrent display of volume data and opaque polygonal geometry. It solves the problem of correct depth ordering between volumetric samples and surface primitives by rendering polygons first and using an inversely warped Z-buffer to clip volume rendering rays. It is distinguished from sibling methods by its explicit integration of standard rasterization primitives with the shear-warp compositing pipeline.

## How it works
**Inputs and Outputs:**
- Input: Volume dataset (scalar field), polygonal geometry (opaque), viewing transformation, clipping planes.
- Output: Composite image with correct depth occlusion between polygons and volume.

**Data Structures:**
- Z-buffer: Standard depth buffer, transformed into the shear-warp coordinate space.
- Volume Acceleration: Min-max octree and Summed Area Table (SAT) for fast classification [S2].

**Steps:**
1. **Polygon Rendering:** Render all opaque polygons into the Z-buffer using standard rasterization [S1, unofficial].
2. **Z-Buffer Warping:** Transform the Z-buffer contents from view space into the shear-warp coordinate space. This creates an "inversely warped Z-buffer" that represents the depth of opaque geometry as seen by the shear-warp rays [S1, unofficial].
3. **Volume Compositing:** Perform the shear-warp compositing (shear, project, warp) for the volume data.
4. **Ray Clipping:** During compositing, use the inversely warped Z-buffer to limit the viewing rays. If a ray's depth exceeds the value in the warped Z-buffer, the ray is terminated or the sample is discarded, ensuring polygons occlude the volume correctly [S1, unofficial].

**Parameters:**
- `clippingMode`: Enum or string, values `'transparent'` or `'mip'`. Controls how clipping planes interact with the volume [S2].
- `intermixIntersectingGeometry`: Boolean. Enables or disables the intersection logic between geometry and volume [S2].

**Pseudocode:**
```python
def hybrid_shear_warp_render(volume, polygons, view_matrix, clip_planes):
    # 1. Render opaque polygons
    # Standard rasterization into Z-buffer
    z_buffer = rasterize_polygons(polygons, view_matrix)
    
    # 2. Warp Z-buffer to shear-warp space
    # Transform depth values to match the shear-warp projection
    warped_z_buffer = warp_z_buffer(z_buffer, view_matrix)
    
    # 3. Shear-Warp Volume Rendering with Clipping
    # Initialize output image
    image = zeros(screen_width, screen_height)
    
    # For each pixel in the warped screen space
    for y, x in screen_pixels:
        # Get depth limit from warped Z-buffer
        z_limit = warped_z_buffer[y, x]
        
        # Perform shear-warp compositing along the ray
        # Ray is defined by the inverse warp of (x, y)
        ray = get_ray_from_warp(x, y)
        
        # Traverse volume along ray
        sample = traverse_volume(ray, volume, z_limit)
        
        # Apply compositing mode (Alpha, MIP, Isosurface)
        # Based on clippingMode and intermixIntersectingGeometry
        color = composite_sample(sample, clip_planes)
        
        image[y, x] = color
        
    return image
```

**Edge Cases:**
- Precision errors in Z-buffer warping may cause z-fighting or incorrect occlusion [G].
- Degenerate polygons or empty volume regions require standard handling [G].

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of voxels traversed and pixels rendered. Clipping adds minimal overhead [S2].
- **Memory Complexity:** Requires storage for the Z-buffer and volume acceleration structures (octree, SAT) [S2].
- **Strengths:** Correct occlusion of volume by polygons; interactive performance with optimized acceleration structures [S2].
- **Limitations:** Limited to opaque polygons for correct depth ordering; transparent polygons require different handling [S1, unofficial].

## Background
The concept of integrating shear-warp with polygon rendering was proposed to achieve correct concurrent display [S1, unofficial]. The implementation details, including VTK integration and acceleration structures, are described in the Shear Warp project [S2].
