# Parallel Projection Rendering

Also called: Parallel Projection Rendering 1

## Overview
Parallel Projection Rendering is an object-order volume rendering algorithm optimized for parallel projections, utilizing the shear-warp factorization to exploit spatial coherence [S2]. It solves the performance bottleneck of traditional volume rendering by replacing expensive trilinear interpolation with efficient run-length encoded traversal, assuming a static opacity transfer function [S2]. Unlike its sibling [Perspective Shear-Warp](6047-perspective-shear-warp.md) which handles perspective distortions, this method leverages the property that voxel slices scale uniformly, allowing a one-to-one mapping between sheared voxels and intermediate image pixels [S2].

## How it works
**Inputs and Outputs:**
- **Input:** A 3D volume dataset $V$ with scalar values and a static opacity transfer function $f(v)$ [S2]. The viewing transformation is decomposed into shear, parallel projection, and warp steps [S2].
- **Output:** A 2D rendered image [S2].

**Data Structures:**
The algorithm relies on run-length encoding (RLE) for both the volume and the intermediate image to skip transparent or occluded regions [S2].

1.  **Volume RLE:** The sheared, resampled volume is stored as run-length encoded voxel scanlines [S1, unofficial]. Each scanline consists of two types of runs:
    -   **Transparent runs:** Voxels where opacity $f(v)$ is below a user-specified threshold [S1, unofficial].
    -   **Non-transparent runs:** Voxels where opacity $f(v)$ meets or exceeds the threshold [S1, unofficial].
    -   **Layout:** Each non-transparent voxel consumes 4 bytes (value + opacity), and each run header consumes 1 byte [S2].

2.  **Intermediate Image RLE:** The intermediate image (before the final 2D warp) stores offsets for opaque pixels [S2].
    -   **Layout:** For each opaque pixel (based on the same user threshold), the structure stores a pointer or offset to the next non-opaque pixel in the scanline [S1, unofficial][S2]. This allows the compositing step to skip occluded voxels efficiently [S2].

**Algorithm Steps:**

1.  **Shear and Resample:** Apply the shear transformation to the volume [S2]. For parallel projections, Property 3 of the shear-warp factorization states that every voxel slice has the same scale factor, which can be chosen arbitrarily [S2]. A unity scale factor is chosen so that there is a one-to-one mapping between voxels in a voxel scanline and pixels in the corresponding intermediate image scanline [S2]. This eliminates the need for per-pixel interpolation weights during compositing; all voxels in a slice are scaled by the same factor [S1, unofficial].

2.  **Initialize Data Structures:** Convert the sheared volume into RLE format [S2]. Identify transparent vs. non-transparent runs using the opacity threshold [S2]. Initialize the intermediate image RLE structure [S2].

3.  **Synchronous Traversal:** Traverse the volume and the intermediate image in synchrony, processing one slice at a time [S2]. For each slice and each volume scanline:
    -   Walk through the volume scanline and the corresponding intermediate image scanline simultaneously [S1, unofficial].
    -   Use the volume RLE to skip runs of transparent voxels [S1, unofficial].
    -   Use the intermediate image RLE to skip runs of occluded (already opaque) pixels [S1, unofficial].

4.  **Compositing:** For the remaining unskipped voxel runs:
    -   Since the scale factor is unity, map voxels directly to intermediate image pixels [S2].
    -   Compute the opacity and color for each voxel using the static transfer function [S2].
    -   Composite the voxel values into the intermediate image using front-to-back accumulation, updating the opacity of the intermediate image pixels [S2].

5.  **Warp:** Apply the 2D warp transformation to the intermediate image to produce the final rendered image [S2].

**Pseudocode:**

```python
def parallel_projection_render(volume, opacity_threshold, image_width, image_height):
    # Step 1: Shear and Resample
    # Apply shear transformation S to align voxel scanlines with pixel scanlines.
    # For parallel projection, choose unity scale factor for 1:1 voxel-to-pixel mapping.
    sheared_volume = [slice_data for slice_data in volume] # [G] Shear/resample step

    # Step 2: Initialize Data Structures
    # Build Volume RLE: list of runs per slice, each run is (start, length, is_transparent)
    volume_rle = []
    for slice_data in sheared_volume:
        runs = []
        i = 0
        while i < len(slice_data):
            val = slice_data[i]
            is_trans = opacity_function(val) < opacity_threshold
            length = 1
            while i + length < len(slice_data) and opacity_function(slice_data[i + length]) < opacity_threshold == is_trans:
                length += 1
            runs.append((i, length, is_trans))
            i += length
        volume_rle.append(runs)

    # Initialize Intermediate Image RLE
    # opaque_next[i] stores index of next non-opaque pixel after i
    opaque_next = list(range(1, image_width + 1))
    opaque_next[image_width] = image_width
    image_opacity = [0.0] * image_width
    image_color = [[0.0, 0.0, 0.0] for _ in range(image_width)]

    # Step 3 & 4: Synchronous Traversal and Compositing
    for slice_idx in range(len(volume_rle)):
        scanline_runs = volume_rle[slice_idx]
        vol_ptr = 0
        img_ptr = 0

        while vol_ptr < len(scanline_runs) and img_ptr < image_width:
            run = scanline_runs[vol_ptr]

            # Skip transparent volume runs
            if run[2]:
                vol_ptr += 1
                img_ptr += run[1]
                continue

            # Skip occluded image pixels using RLE offset
            if image_opacity[img_ptr] >= opacity_threshold:
                next_img = opaque_next[img_ptr]
                vol_ptr += (next_img - img_ptr)
                img_ptr = next_img
                continue

            # Process unskipped voxel run (1:1 mapping)
            run_len = run[1]
            for i in range(run_len):
                v_val = sheared_volume[slice_idx][vol_ptr + i]
                alpha = opacity_function(v_val)
                rgb = color_function(v_val)

                # Front-to-back compositing
                curr_a = image_opacity[img_ptr + i]
                new_a = alpha + curr_a * (1.0 - alpha)
                new_c = [rgb[j] * alpha + image_color[img_ptr + i][j] * curr_a * (1.0 - alpha) for j in range(3)]

                image_opacity[img_ptr + i] = new_a
                image_color[img_ptr + i] = new_c

                # Update image RLE if pixel becomes opaque
                if curr_a < opacity_threshold and new_a >= opacity_threshold:
                    next_non_opaque = img_ptr + i + 1
                    while next_non_opaque < image_width and image_opacity[next_non_opaque] >= opacity_threshold:
                        next_non_opaque = opaque_next[next_non_opaque]
                    opaque_next[img_ptr + i] = next_non_opaque

            vol_ptr += run_len
            img_ptr += run_len

    # Step 5: Warp
    final_image = apply_2d_warp(image_color, image_opacity, image_width, image_height) # [G] Applies M_warp2D
    return final_image

def opacity_function(v): return min(1.0, v / 255.0) # [G] Standard normalization
def color_function(v): return [v/255.0, v/255.0, v/255.0] # [G] Grayscale mapping
def apply_2d_warp(color, alpha, w, h): return color # [G] Applies 2D affine warp
```

**Parameters:**
-   **Opacity Threshold:** A user-specified value to distinguish transparent from non-transparent voxels [S1, unofficial].
-   **Scale Factor:** Chosen as 1.0 for parallel projections to enable 1:1 voxel-to-pixel mapping [S2].

**Edge Cases and Pitfalls:**
-   **Memory Constraints:** The algorithm requires storing three run-length encoded copies of the volume in memory for optimal performance [S2].
-   **Viewing Angle:** Rendering time increases as the rotation angle approaches 45 degrees because the intermediate image size increases, requiring more compositing operations [S2].
-   **Static Transfer Function:** The algorithm assumes the opacity transfer function does not change between renderings [S2].

## Operating characteristics
-   **Time Complexity:** The algorithm traverses the volume and image in synchrony, skipping transparent and occluded regions [S2].
-   **Memory Complexity:** Requires $O(N)$ memory for the volume RLE and image RLE, where $N$ is the number of voxels [S2]. Specifically, each copy of the volume RLE uses 4 bytes per non-transparent voxel and 1 byte per run [S2].
-   **Performance:** On an SGI Indigo R4000 workstation, the algorithm renders a $128 \times 128 \times 109$ voxel dataset ('brainsmall') in an average of 0.4 seconds and a $128 \times 128 \times 113$ voxel dataset ('headsmall') in 0.4 seconds [S2]. A $256^3$ voxel dataset renders in 1 second [S2]. This is at least five times faster than previous algorithms on comparable hardware [S2].
-   **Scaling:** Performance is stable regardless of the major viewing axis, provided the three RLE copies fit in memory [S2]. Color renderings take roughly twice as long as grayscale renderings [S2].
-   **Strengths:** High speed for parallel projections, minimal loss of image quality compared to subsampling methods, and no performance degradation when changing the major viewing axis [S2].
-   **Limitations:** Requires a static opacity transfer function, and memory usage can be high for large datasets if three RLE copies cannot fit in RAM [S2].

## Background
The Parallel Projection Rendering algorithm was introduced by Lacroute and Levoy in their 1995 technical report "Fast Volume Rendering Using a Shear-warp Factorization of The Viewing Transformation" [S2]. It is based on the shear-warp factorization, which decomposes the viewing transformation into a 3D shear, a projection, and a 2D warp [S2]. The method was designed to address the performance limitations of earlier volume rendering algorithms, which required multiple resampling steps and did not exploit spatial coherence as effectively [S2]. The algorithm is part of a family of shear-warp based rendering methods, including variants for perspective projections and fast classification [S2].
