# Parallel Projection Rendering

Also called: Parallel Projection Rendering 1

## Overview
Parallel Projection Rendering is an object-order volume rendering algorithm optimized for parallel projections, utilizing the shear-warp factorization to exploit spatial coherence [S2]. It solves the performance bottleneck of traditional volume rendering by replacing expensive trilinear interpolation with efficient run-length encoded traversal, assuming a static opacity transfer function [S2]. Unlike its sibling [Parallel Perspective Shear-Warp Rendering](802-parallel-perspective-shear-warp-rendering.md) which handles perspective distortions, this method leverages the property that voxel slices scale uniformly, allowing a one-to-one mapping between sheared voxels and intermediate image pixels [S2].

## How it works
**Inputs and Outputs:**
- **Input:** A 3D volume dataset $V$ with scalar values and a static opacity transfer function $f(v)$. The viewing transformation is decomposed into shear, parallel projection, and warp steps.
- **Output:** A 2D rendered image.

**Data Structures:**
The algorithm relies on run-length encoding (RLE) for both the volume and the intermediate image to skip transparent or occluded regions [S2].

1.  **Volume RLE:** The sheared, resampled volume is stored as run-length encoded voxel scanlines. Each scanline consists of two types of runs:
    -   **Transparent runs:** Voxels where opacity $f(v)$ is below a user-specified threshold.
    -   **Non-transparent runs:** Voxels where opacity $f(v)$ meets or exceeds the threshold.
    -   **Layout:** Each non-transparent voxel consumes 4 bytes (value + opacity), and each run header consumes 1 byte [S2].

2.  **Intermediate Image RLE:** The intermediate image (before the final 2D warp) stores offsets for opaque pixels.
    -   **Layout:** For each opaque pixel (based on the same user threshold), the structure stores a pointer or offset to the next non-opaque pixel in the scanline [S1, unofficial][S2]. This allows the compositing step to skip occluded voxels efficiently [S2].

**Algorithm Steps:**

1.  **Shear and Resample:** Apply the shear transformation to the volume. For parallel projections, Property 3 of the shear-warp factorization states that every voxel slice has the same scale factor, which can be chosen arbitrarily [S2]. A unity scale factor is chosen so that there is a one-to-one mapping between voxels in a voxel scanline and pixels in the corresponding intermediate image scanline [S2]. This eliminates the need for per-pixel interpolation weights during compositing; all voxels in a slice are scaled by the same factor [S1, unofficial].

2.  **Initialize Data Structures:** Convert the sheared volume into RLE format. Identify transparent vs. non-transparent runs using the opacity threshold [S2]. Initialize the intermediate image RLE structure [S2].

3.  **Synchronous Traversal:** Traverse the volume and the intermediate image in synchrony, processing one slice at a time [S2]. For each slice and each volume scanline:
    -   Walk through the volume scanline and the corresponding intermediate image scanline simultaneously [S1, unofficial].
    -   Use the volume RLE to skip runs of transparent voxels [S1, unofficial].
    -   Use the intermediate image RLE to skip runs of occluded (already opaque) pixels [S1, unofficial].

4.  **Compositing:** For the remaining unskipped voxel runs:
    -   Since the scale factor is unity, map voxels directly to intermediate image pixels [S2].
    -   Compute the opacity and color for each voxel using the static transfer function [S2].
    -   Composite the voxel values into the intermediate image using front-to-back or back-to-front accumulation, updating the opacity of the intermediate image pixels [S2].

5.  **Warp:** Apply the 2D warp transformation to the intermediate image to produce the final rendered image [S2].

**Pseudocode:**

```python
def parallel_projection_render(volume, opacity_threshold, image_width, image_height):
    # Step 1: Shear and Resample
    # The shear transformation aligns voxel scanlines with pixel scanlines.
    # For parallel projection, we choose a unity scale factor.
    sheared_volume = shear_volume(volume)
    
    # Step 2: Build Volume RLE
    # Each run is (start_index, length, type) where type is 'transparent' or 'opaque'
    volume_rle = build_volume_rle(sheared_volume, opacity_threshold)
    
    # Step 3: Initialize Intermediate Image RLE
    # Each opaque pixel stores an offset/pointer to the next non-opaque pixel
    # Initialize all pixels as transparent (empty)
    intermediate_image_rle = initialize_image_rle(image_width, image_height)
    intermediate_image_data = create_empty_image(image_width, image_height)
    
    # Step 4: Synchronous Traversal and Compositing
    for slice_index in range(volume.depth):
        volume_scanline = volume_rle.get_scanline(slice_index)
        image_scanline = intermediate_image_rle.get_scanline(slice_index)
        
        vol_idx = 0
        img_idx = 0
        
        while vol_idx < len(volume_scanline) and img_idx < image_width:
            vol_run = volume_scanline[vol_idx]
            
            # Skip transparent volume runs
            if vol_run.type == 'transparent':
                vol_idx += 1
                img_idx += vol_run.length
                continue
            
            # Check if the current image position is already opaque (occluded)
            # The image RLE allows us to jump to the next non-opaque pixel
            if intermediate_image_data[img_idx] is opaque:
                # Jump to the next non-opaque pixel using the stored offset
                next_img_idx = intermediate_image_rle.get_next_non_opaque(img_idx)
                # Advance volume index to match the new image index
                # Since scale is 1:1, vol_idx advances by the difference in indices
                vol_idx += (next_img_idx - img_idx)
                img_idx = next_img_idx
                continue
            
            # Process the unskipped voxel run
            # Map voxels directly to pixels (1:1 mapping due to unity scale)
            run_length = vol_run.length
            for i in range(run_length):
                voxel_value = sheared_volume[slice_index][vol_idx + i]
                opacity = opacity_function(voxel_value)
                color = color_function(voxel_value)
                
                # Composite into intermediate image
                # Front-to-back accumulation example
                current_img_opacity = intermediate_image_data[img_idx + i].opacity
                new_opacity = opacity + current_img_opacity * (1 - opacity)
                new_color = color * opacity + intermediate_image_data[img_idx + i].color * current_img_opacity * (1 - opacity)
                
                intermediate_image_data[img_idx + i] = (new_color, new_opacity)
                
                # Update RLE if pixel became opaque
                if not intermediate_image_data[img_idx + i].was_opaque and new_opacity > opacity_threshold:
                    intermediate_image_rle.mark_opaque(img_idx + i)
            
            vol_idx += run_length
            img_idx += run_length
            
    # Step 5: Warp
    final_image = warp_2d(intermediate_image_data)
    return final_image
```

**Parameters:**
-   **Opacity Threshold:** A user-specified value to distinguish transparent from non-transparent voxels. Typical values depend on the data range, but the algorithm requires a binary classification for RLE construction [S2].
-   **Scale Factor:** Chosen as 1.0 for parallel projections to enable 1:1 voxel-to-pixel mapping [S2].

**Edge Cases and Pitfalls:**
-   **Memory Constraints:** The algorithm requires storing three run-length encoded copies of the volume in memory for optimal performance. If memory is insufficient, performance degrades [S2].
-   **Viewing Angle:** Rendering time increases as the rotation angle approaches 45 degrees because the intermediate image size increases, requiring more compositing operations [S2].
-   **Static Transfer Function:** The algorithm assumes the opacity transfer function does not change between renderings. Changing it requires rebuilding the RLE structures [S2].

## Subtopics

### [Parallel Perspective Shear-Warp Rendering](802-parallel-perspective-shear-warp-rendering.md)
Extends the shear-warp factorization to perspective projections, requiring two resampling steps and handling varying scale factors per slice. Choose when perspective views are needed.

### [CPU-based Shear-Warp](1161-cpu-based-shear-warp.md)
A generalization of the shear-warp approach for CPU execution, potentially lacking the specific RLE optimizations of the parallel projection variant. Choose for CPU-only environments.

### [GPU-based Shear-Warp](7425-gpu-based-shear-warp.md)
Adapts the shear-warp algorithm for GPU architectures, leveraging parallelism for compositing. Choose for high-performance rendering on modern GPUs.

### [Fast Classification Algorithm](3481-spatially-partitioned-shear-warp-method.md)
An extension that supports unclassified volumes (scalar fields with no precomputed opacity) using a rain-max octree. Choose when the opacity transfer function changes frequently.

## Operating characteristics
-   **Time Complexity:** The algorithm traverses the volume and image in synchrony, skipping transparent and occluded regions. The complexity is proportional to the number of non-transparent voxels and opaque pixels, rather than the total volume size [S2].
-   **Memory Complexity:** Requires $O(N)$ memory for the volume RLE and image RLE, where $N$ is the number of voxels. Specifically, each copy of the volume RLE uses 4 bytes per non-transparent voxel and 1 byte per run [S2].
-   **Performance:** On an SGI Indigo R4000 workstation, the algorithm renders a $128 \times 128 \times 109$ voxel dataset ('brainsmall') in an average of 0.4 seconds and a $128 \times 128 \times 113$ voxel dataset ('headsmall') in 0.4 seconds [S2]. A $256^3$ voxel dataset renders in 1 second [S2]. This is at least five times faster than previous algorithms on comparable hardware [S2].
-   **Scaling:** Performance is stable regardless of the major viewing axis, provided the three RLE copies fit in memory [S2]. Color renderings take roughly twice as long as grayscale renderings [S2].
-   **Strengths:** High speed for parallel projections, minimal loss of image quality compared to subsampling methods, and no performance degradation when changing the major viewing axis [S2].
-   **Limitations:** Requires a static opacity transfer function, and memory usage can be high for large datasets if three RLE copies cannot fit in RAM [S2].

## Background
The Parallel Projection Rendering algorithm was introduced by Lacroute and Levoy in their 1995 technical report "Fast Volume Rendering Using a Shear-warp Factorization of The Viewing Transformation" [S2]. It is based on the shear-warp factorization, which decomposes the viewing transformation into a 3D shear, a projection, and a 2D warp [S2]. The method was designed to address the performance limitations of earlier volume rendering algorithms, which required multiple resampling steps and did not exploit spatial coherence as effectively [S2]. The algorithm is part of a family of shear-warp based rendering methods, including variants for perspective projections and fast classification [S2].
