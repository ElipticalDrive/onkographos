# GPU-based Shear-Warp

Also called: GPU Shear-Warp, Shear-Warp on the GPU

## Overview
GPU-based Shear-Warp is a real-time volume rendering technique that implements the Shear-Warp algorithm on graphics hardware using vertex and fragment shaders [S1, unofficial]. It solves the problem of rendering volumetric data efficiently by leveraging the parallel processing capabilities of the GPU to perform the shear and warp transformations [S1, unofficial]. Unlike CPU-based implementations or single-pass ray marching, this method explicitly decomposes the viewing transformation into shear and warp phases, utilizing hardware alpha-blending for compositing [S1, unofficial]. It is distinguished from [Shear-Warp Algorithm](4304-shear-warp-algorithm.md) by its specific use of 3D textures and shader-based shading models (e.g., Phong) to enhance volumetric appearance, and from [VolumePro Ray-Casting with Slice-by-Slice Processing](1865-volumepro-ray-casting-with-slice-by-slice-processing.md) by its reliance on slice-based quadrilateral rendering rather than pure ray casting [S1, unofficial].

## How it works
The method operates in two main rendering passes, preceded by a preprocessing step. It requires volume data containing opacity values and assumes a parallel or perspective projection defined by a view matrix.

### Inputs and Outputs
*   **Inputs:**
    *   Volume data: A 3D grid of voxels, each containing an opacity value $op(x,y,z)$ and optionally a normal vector.
    *   View parameters: Model-view matrix $M_{GLModelView}$ and projection matrix $M_{GLProjection}$ [S1, unofficial].
    *   Sampling rate $s$: An integer determining the number of interpolated slices between input slices [S1, unofficial].
*   **Outputs:**
    *   Final 2D image rendered to the screen buffer.

### Data Structures
1.  **3D Texture:** Stores opacity and normal data.
    *   Layout: 3D texture object in GPU memory.
    *   Fields: Opacity value $op$ and normal vector $\mathbf{n}$ for each voxel coordinate $(x,y,z)$ [S1, unofficial].
2.  **Slice Quadrilaterals:** Geometric primitives representing volume slices.
    *   Layout: A set of $n$ quadrilaterals, where $n$ is the number of slices (potentially increased by interpolation) [S1, unofficial].
    *   Vertex Attributes: Texture coordinates where one component encodes the slice index $d = \text{sliceNumber} / \text{sliceCount}$ [S1, unofficial].

### Steps

**1. Preprocessing**
1.  Load opacity values from storage [S1, unofficial].
2.  Estimate normals for each voxel using a simple gradient approach based on neighboring opacity values [S1, unofficial]:
    $$ \mathbf{n}(x, y, z) = \frac{1}{2} \begin{pmatrix} op(x+1, y, z) - op(x-1, y, z) \\ op(x, y+1, z) - op(x, y-1, z) \\ op(x, y, z+1) - op(x, y, z-1) \end{pmatrix} $$
    [S1, unofficial]
3.  Store opacity and normals in a 3D texture on the GPU [S1, unofficial].

**2. Pass 1: Shearing and Shading**
1.  Construct the view matrix $M_{view} = M_{GLModelView} \times M_{GLProjection}$ [S1, unofficial].
2.  Derive the 3D shear matrix $M_{shear3D}$ from $M_{view}$ according to the Shear-Warp factorization [S1, unofficial].
3.  Send $M_{shear3D}$ to the GPU Vertex Shader [S1, unofficial].
4.  For each slice quadrilateral:
    *   **Vertex Shader:** Apply $M_{shear3D}$ to the vertices of the quadrilateral representing the slice [S1, unofficial].
    *   **Fragment Shader:**
        *   Fetch opacity $op$ and normal $\mathbf{n}$ from the 3D texture for the current fragment [S1, unofficial].
        *   Compute shading using the Phong lighting model [S1, unofficial]:
            $$ L_o(p, \omega_o) = k_a + \frac{k_d}{\pi} L_i(p, \omega_i) (\omega_i \cdot \mathbf{n}) + k_s (R(\omega_i, \mathbf{n}) \cdot \omega_o)^n $$
            Where:
            *   $L_o$: Outgoing radiance.
            *   $k_a, k_d, k_s$: Ambient, diffuse, and specular coefficients.
            *   $L_i$: Incident light intensity.
            *   $\omega_i, \omega_o$: Incoming and outgoing directions.
            *   $R(\omega_i, \mathbf{n})$: Reflection direction.
            *   $n$: Shininess exponent [S1, unofficial].
        *   Output the shaded color and opacity to the frame buffer.
    *   **Compositing:** Slices are composited back-to-front using hardware alpha-blending [S1, unofficial]. This produces a distorted intermediate image [S1, unofficial].

**3. Pass 2: Warping**
1.  Create a textured quadrilateral representing the intermediate image from Pass 1 [S1, unofficial].
2.  Apply the warping matrix $M_{warp}$ to this quadrilateral in the Vertex Shader [S1, unofficial].
3.  The Fragment Shader maps the intermediate image texture onto the warped quadrilateral to yield the final undistorted image [S1, unofficial].

### Parameters
*   **Sampling Rate ($s$):** The number of additional slices virtually inserted between successive input slices using linear interpolation [S1, unofficial].
    *   Typical values: $s=1$ (no interpolation), $s=5$ (improved quality), $s=10$ or higher [S1, unofficial].
    *   Note: Higher $s$ improves visual quality by reducing slice visibility but decreases frame rate linearly [S1, unofficial].

### Edge Cases and Pitfalls
*   **Normal Estimation Precision:** The simple gradient method for normal estimation may lack precision compared to more complex methods, potentially affecting shading accuracy [S1, unofficial].
*   **Slice Visibility:** With low sampling rates ($s=1$), individual slices may be clearly visible, degrading image quality [S1, unofficial].
*   **Performance Scaling:** Frame rate drops linearly as the number of slices (input + interpolated) increases [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of slices and fragments. Frame rate decreases linearly with increased sampling rate (number of slices) [S1, unofficial].
*   **Memory Complexity:** Proportional to the volume size for the 3D texture storage [S1, unofficial].
*   **Measured Performance:**
    *   Skull Model (320×320×46 voxels): 95 fps at $s=1$ with Phong shading [S1, unofficial].
    *   Knee Model (512×512×73 voxels): 134 fps at $s=1$ with Phong shading [S1, unofficial].
    *   At $s=10$, Skull Model performance drops to 15 fps [S1, unofficial].
*   **Strengths:** Real-time rendering capability; enhanced volumetric appearance via Phong shading; efficient use of GPU hardware for compositing [S1, unofficial].
*   **Limitations:** Slower than GPU-based Ray Marching for equivalent quality (e.g., Shear-Warp at $s=10$ is 10 fps vs. Ray Marching at 400 steps is 48 fps) [S1, unofficial]. Slice artifacts may appear at low sampling rates [S1, unofficial].
*   **When to use:** When real-time performance is required and the volume has a relatively small number of slices (e.g., medical imaging datasets with <100 slices) [S1, unofficial].
*   **When not to use:** When higher image quality is needed without significant performance loss, or when the volume has a large number of slices, as Ray Marching may be faster and higher quality [S1, unofficial].

## Background
The GPU-based Shear-Warp method was presented as one of the first implementations of the Shear-Warp algorithm on graphics hardware [S1, unofficial]. It leverages the programmability of vertex and fragment shaders to accelerate the rendering process [S1, unofficial]. The approach was applied to medical imagery, specifically skull and knee models, demonstrating the feasibility of real-time volume rendering with shading enhancements [S1, unofficial]. The method builds on the foundational Shear-Warp algorithm [4304-shear-warp-algorithm.md] but adapts it to the fixed-function and programmable pipeline of GPUs available at the time of publication [S1, unofficial].
