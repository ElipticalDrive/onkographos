# Shear-warp

Also called: Shear-warp factorization, Shear-wrap

## Overview
The Shear-warp family solves the problem of efficient memory access and interpolation for volume rendering at arbitrary viewing angles by factorizing the viewing transformation into a 3D shear and a 2D warp [S1, S2, S6, unofficial]. It sets itself apart from standard ray-casting by transforming the volume into a sheared object space where viewing rays are perpendicular to volume slices, allowing the use of fixed bilinear interpolation and scanline-based optimizations [S3, S9, unofficial]. Unlike pure feed-forward methods, it bridges the gap by aligning samples with pixels before compositing, leveraging the efficiency of warping while maintaining the visibility handling of feed-backward approaches [S1, unofficial].

## Shared principles
The Shear-warp family relies on the factorization of the general viewing transformation matrix $M_{view}$ into three components: a permutation matrix $P$, a shear matrix $S$, and a 2D warp matrix $M_{warp2D}$ [S2, S12, unofficial]:
$$ M_{view} = M_{warp2D} \cdot S \cdot P $$
The process consists of three phases: Permutation/Shear, Composite, and Warp [S2, unofficial][S5, book].

1.  **Permutation:** The volume data is permuted so that the principal viewing axis (the axis most aligned with the view direction) aligns with a coordinate axis (typically Z) [S2, S12, unofficial]. This minimizes the shear required and allows the use of pre-computed acceleration structures (like Run-Length Encoded data) for that specific axis [S3, S9, unofficial].
2.  **Shear and Resampling:** The volume slices (perpendicular to the principal axis) are sheared and resampled into an intermediate 2D image space [S2, S12, unofficial]. The shear coefficients $s_x, s_y$ are derived from the view direction $v_o = [v_{o,x}, v_{o,y}, v_{o,z}]^T$ in the permuted space:
    $$ s_x = -\frac{v_{o,x}}{v_{o,z}}, \quad s_y = -\frac{v_{o,y}}{v_{o,z}} $$
    For parallel projection, the shear matrix is:
    $$ S = \begin{pmatrix} 1 & 0 & s_x & 0 \\ 0 & 1 & s_y & 0 \\ 0 & 0 & 1 & 0 \\ 0 & 0 & 0 & 1 \end{pmatrix} $$
    This transformation ensures that viewing rays are perpendicular to the volume slices, allowing for efficient, fixed-weight interpolation (typically bilinear) within each slice [S3, S9, unofficial].
3.  **Composite:** The sheared slices are composited in front-to-back order into the intermediate image [S2, S12, unofficial]. This step projects the volume into a 2D intermediate image in sheared object space. Optimizations such as Run-Length Encoding (RLE) are used to skip transparent voxel runs and opaque pixel runs (early ray termination) [S2, S11, unofficial].
4.  **Warp:** The intermediate image is transformed to the final image space using the 2D warp matrix $M_{warp2D}$ [S2, S12, unofficial]. This corrects the distortion introduced by the shear. The warp matrix is computed as:
    $$ M_{warp2D} = M_{view} \cdot S^{-1} \cdot P^{-1} $$
    (Note: Some sources define $M_{warp2D} = M_{view} \cdot M_{shear}^{-1}$ assuming $P$ is handled in the permutation step [S7, S21, unofficial]). This is a 2D resampling step, typically using bilinear interpolation [S2, S12, unofficial].

## Subtopics

### [VolumePro Ray-Casting with Slice-by-Slice Processing](1865-volumepro-ray-casting-with-slice-by-slice-processing.md)
VolumePro is a specialized hardware architecture that implements object-space ray-casting with parallel slice-by-slice processing to achieve real-time frame rates on PC-class computers. It differs from texture-mapping approaches by supporting gradient estimation and per-sample Phong illumination in real-time, and from pre-processing approaches by allowing immediate visual feedback during parameter changes without lengthy recomputation. It builds on the Shear-warp method [24-shear-warp.md] by casting rays from the base plane (the volume face most parallel to the viewing plane) into the dataset, projecting the resulting base plane image onto the final image plane via a 3D transformation and 2D warping.

### [Affine-Transformations Method](2038-affine-transformations-method.md)
The Affine-Transformations Method is a hybrid volume rendering technique that uses affine transformations to warp volume slices or the entire volume into the image plane so that data samples become pixel-aligned, after which the transformed data is composited to calculate visibility. It is distinct from pure feed-backward (ray-casting) methods, which cast rays into the data set, and pure feed-forward (element-tossing) methods, which map data elements directly to the image plane. By aligning samples with pixels before compositing, it bridges the gap between these two extremes, leveraging the efficiency of feed-forward warping while maintaining the visibility handling of feed-backward approaches.

### [Shear-Warp Algorithm](4304-shear-warp-algorithm.md)
The Shear-Warp Algorithm is a fast, software-based volume rendering technique that reduces the computational complexity of arbitrary viewing angles by factorizing the viewing transformation into a 3D shear and a 2D warp. It solves the problem of efficient memory access and interpolation for oblique views by transforming the volume into a sheared object space where viewing rays are perpendicular to the volume slices, allowing the use of fixed bilinear interpolation and scanline-based optimizations. Unlike standard ray-casting which performs trilinear interpolation per pixel, Shear-Warp substitutes this with two 2D resampling steps (shear and warp), making it significantly faster for pure software implementations, though it trades off some image quality due to the fixed sampling grid.

### [Hybrid Shear-Warp and Polygon Rendering](5876-hybrid-shear-warp-and-polygon-rendering.md)
This method extends the Shear-warp algorithm to correctly intermix polygonal geometry with volume rendering in a single pass. It solves the problem of visual artifacts when opaque polygons intersect or occlude volumetric data by rendering the geometry first and using an inversely warped Z-buffer to clip the volume compositing rays. It is distinct from pure volume methods by its explicit handling of discrete surface primitives alongside the voxel data.

### [Perspective Shear-Warp](6047-perspective-shear-warp.md)
Perspective Shear-Warp extends the Shear-warp algorithm to handle perspective projection, where viewing rays diverge from a focal point. It solves the problem of rendering volumetric data with perspective distortion by incorporating slice scaling into the shear phase, ensuring that the resampling footprint adapts to the increasing distance from the camera. Unlike parallel Shear-warp, which assumes uniform ray spacing, this method accounts for the non-linear sampling density inherent in perspective views.

### Back-to-front polygon rendering with display lists
Renders parallel polygons from back to front to satisfy linear alpha blending requirements for compositing [S7, unofficial]. Define six display lists (two directions along each of three axes). Determine the largest absolute component of the view vector (x, y, or z) and its sign. Execute the corresponding display list [S7, unofficial]. Polygons are never viewed edge-on, limiting oblique viewing angles [S7, unofficial].

### Coordinate System Conventions
A set of six distinct coordinate systems used to track transformations in the shear-warp algorithm, each identified by a unique single character [S9, unofficial]. Transition matrices between coordinate systems are named using the source and destination identifiers, e.g., $M_{ow}$ for object-to-world, and $M_{wo}$ for world-to-object [S9, unofficial]. Coordinate systems: 'o' (object space, actual volume data coordinates), 's' (standard object space, after permutation), 'd' (deformed space, 3D coordinates after shear), 'i' (intermediate image space, 2D coordinates within intermediate image), 'w' (world coordinate space), 'v' (viewport space, 2D output window coordinates) [S9, unofficial].

### Parallel Shear-Warp on Shared Memory
A parallel volume rendering algorithm for shared-memory multiprocessors that minimizes computation, synchronization, and data communication time [S9, unofficial]. Base the parallel algorithm on the shear-warp serial volume rendering algorithm to minimize computation time [S9, unofficial]. Minimize synchronization time by using dynamic load balancing and a task partition that minimizes synchronization events [S9, unofficial]. Implement for shared-memory multiprocessors to leverage hardware support for low-latency fine-grain communication and hardware caching to hide latency [S9, unofficial]. Cache locality requirements impose a limit on parallelism; shared-memory machines with hundreds of processors are only useful for rendering very large data sets [S9, unofficial].

### Parallel Projection Rendering
Store sheared, resampled volume as run-length encoded voxel scanlines with two kinds of runs: transparent and non-transparent, defined by a user-specified threshold [S4, unofficial]. For each slice and for each volume scanline, walk through volume scanline and intermediate image, using voxel run-length encoding to skip transparent voxels and image encoding to skip occluded voxels [S4, unofficial]. Process unskipped voxel runs efficiently, noting that all voxels in a slice are scaled by the same factors, so resampling uses the same weights [S4, unofficial]. Intermediate image scanline stores run information: each opaque pixel (based on user threshold) has a pointer to the next non-opaque pixel in the scanline [S4, unofficial].

### Parallel Projection Rendering 3
Use bilinear interpolation and backward projection convolution [S4, unofficial]. Traverse 2 voxel scanlines simultaneously to produce one intermediate image scanline, which lies between the two voxel scanlines [S4, unofficial]. Use a lookup table for shading [S4, unofficial]. Use a lookup table to correct voxel opacity for view angle, accounting for apparent slice thickness dependence on angle [S4, unofficial]. After compositing, warp the 2D intermediate image to the final image using a general purpose affine image warper with bilinear filter [S4, unofficial]. Run length encoded data structure created on the fly, but is nearly view-independent. Create 3 encodings, one for each principal view direction [S4, unofficial]. Transparent voxels are not stored, so the size is usually tractable [S4, unofficial].

### Perspective Projection Rendering
Scale and translate each voxel during resampling, requiring more than 2 voxel scanlines to be traversed simultaneously to contribute to the intermediate image scanline [S4, unofficial]. Voxel scanlines may not be traversed at the same rate as image scanlines [S4, unofficial]. Use a box reconstruction filter and a box low-pass filter [S4, unofficial]. Scaling factors: Choose factors so the closest slice has unit scaling; all other slices will have < 1 scaling, so no slice is enlarged [S4, unofficial].

## Background
The Shear-warp algorithm was designed by Lacroute et al. [48] and recognized as the fastest software render algorithm at the time [S2, unofficial]. It was implemented in VolumePro hardware, which was specialized for this algorithm [S2, unofficial]. The basic idea is to factorize the projection matrix into a 3D shear and 2D warp [S1, unofficial]. Using the shearing, the data set is transformed into sheared object space where all viewing rays are parallel to one coordinate axis and the volume is considered as a stack of 2D slices [S1, unofficial].
