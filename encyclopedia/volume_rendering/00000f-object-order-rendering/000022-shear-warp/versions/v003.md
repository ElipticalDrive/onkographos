# Shear-warp
Also called: Shear-warp factorization
## Overview
The Shear-warp family solves the problem of efficient volume rendering for arbitrary viewing angles by factorizing the 3D viewing transformation into a 3D shear and a 2D warp [S2, S3, S5, unofficial]. Unlike pure object-order ray casting, which suffers from irregular memory access and interpolation costs, or pure image-order splatting, which lacks early ray termination, Shear-warp transforms the volume into a "sheared object space" where viewing rays are parallel to a coordinate axis [S2, S5, unofficial]. This allows for efficient slice-by-slice compositing with regular memory access, followed by a final 2D resampling to correct the distortion [S2, S5, unofficial]. It is distinct from [Texture slicing](25-texture-slicing.md) by explicitly separating the geometric shear from the hardware-accelerated warp, and from [Cell projection](26-cell-projection.md) by using a continuous resampling approach rather than discrete cell projection [S2, S5, unofficial].
## Shared principles
The Shear-warp family relies on the factorization of the viewing transformation matrix $M_{view}$ into three components: a permutation $P$, a shear $S$, and a 2D warp $M_{warp2D}$ [S3, S5, unofficial]:
$$ M_{view} = M_{warp2D} \cdot S \cdot P $$
The process consists of three main phases:

1.  **Permutation and Shear:** The volume is permuted so that the principal viewing axis aligns with a coordinate axis (typically Z) [S3, S5, unofficial]. A 3D shear matrix $M_{shear}$ is applied to transform the volume into sheared object space [S2, S5, unofficial]. In this space, the viewing rays are perpendicular to the volume slices (parallel to the Z-axis) [S1, S5, unofficial].
    *   For parallel projection, the shear coefficients $S_i, S_j$ are derived from the view direction vector $v_o$ [S5, unofficial]:
        $$ S_i = -\frac{v_{o,x}}{v_{o,z}}, \quad S_j = -\frac{v_{o,y}}{v_{o,z}} $$
    *   The shear matrix is:
        $$ M_{shear} = \begin{pmatrix} 1 & 0 & S_i & 0 \\ 0 & 1 & S_j & 0 \\ 0 & 0 & 1 & 0 \\ 0 & 0 & 0 & 1 \end{pmatrix} $$
    *   For perspective projection, the shear step also includes a scaling factor for each slice to account for diverging rays [S2, S5, unofficial].

2.  **Shear and Composite:** The volume is traversed slice-by-slice in the sheared space [S2, S5, unofficial].
    *   **Resampling:** Each slice is resampled into an intermediate 2D image using bilinear interpolation [S2, S5, unofficial]. For parallel projection, there is a 1-to-1 mapping between voxel scanlines and intermediate image pixels [S2, unofficial]. For perspective projection, slices are scaled, and adaptive area sampling is used [S2, S3, unofficial].
    *   **Compositing:** Samples are composited into the intermediate image using front-to-back alpha blending [S2, S5, unofficial]:
        $$ I_{int}[y, x] = I_{int}[y, x] + C \cdot \alpha \cdot (1 - A_{int}[y, x]) $$
        $$ A_{int}[y, x] = A_{int}[y, x] + \alpha \cdot (1 - A_{int}[y, x]) $$
    *   **Optimization:** Run-Length Encoding (RLE) is often used to skip transparent voxel runs and opaque pixel runs in the intermediate image [S2, S3, unofficial].

3.  **Warp:** The intermediate image is transformed to the final image space using the 2D warp matrix $M_{warp2D}$ [S2, S5, unofficial]. This is a 2D resampling step that corrects the distortion introduced by the shear [S2, S5, unofficial].
    $$ M_{warp2D} = M_{view} \cdot M_{shear}^{-1} \cdot P^{-1} $$
    [S3, S5, unofficial]

## Subtopics

### [VolumePro Ray-Casting with Slice-by-Slice Processing](1865-volumepro-ray-casting-with-slice-by-slice-processing.md)
A specialized hardware implementation of Shear-warp that uses parallel slice-by-slice processing to achieve real-time frame rates. It differs from software implementations by supporting gradient estimation and per-sample Phong illumination in real-time, and from pre-processing approaches by allowing immediate visual feedback. It builds on the Shear-warp method by casting rays from the base plane into the dataset and projecting the result via a 3D transformation and 2D warping.

### [Affine-Transformations Method](2038-affine-transformations-method.md)
A hybrid technique that uses affine transformations to warp volume slices or the entire volume into the image plane so that data samples become pixel-aligned before compositing. It bridges the gap between feed-backward (ray-casting) and feed-forward (element-tossing) methods by leveraging the efficiency of warping while maintaining visibility handling.

### [Shear-Warp Algorithm](4304-shear-warp-algorithm.md)
The foundational fast, software-based technique that reduces 3D ray casting complexity by factorizing the view into a 3D shear and a 2D warp. It solves memory access issues by transforming the volume so rays are axis-aligned, allowing slice-by-slice compositing with bilinear interpolation. It is distinct from hardware-accelerated texture mapping by relying on software scanline traversal and RLE optimization, though it can use GPU texturing for the final warp.

### [Perspective Shear-Warp](6047-perspective-shear-warp.md)
An extension of the Shear-warp algorithm that handles perspective viewing transformations by scaling voxels during the shear step to account for diverging rays. This ensures geometric correctness for perspective cameras, unlike the sibling [Shear-Warp Algorithm](4304-shear-warp-algorithm.md) which assumes parallel projection.

### Back-to-front polygon rendering with display lists
Renders parallel polygons from back to front to satisfy linear alpha blending requirements [S6, unofficial]. It defines six display lists (two directions along each of three axes) and executes the one corresponding to the largest absolute component of the view vector [S6, unofficial]. A pitfall is that polygons are never viewed edge-on, limiting oblique viewing angles [S6, unofficial].

### Shear-Warp Factorization Rendered Examples Pipeline
A pipeline including a gradient processor, matrix multiplication processor, shader, and classifier [S7, unofficial]. It applies a rotation matrix, classification transfer functions (e.g., making soft tissues transparent), and a Phong fast lighting model to shade the image [S7, unofficial].

### Coordinate System Conventions
A set of six distinct coordinate systems used to track transformations: 'o' (object space), 's' (standard object space after permutation), 'd' (deformed space after shear), 'i' (intermediate image space), 'w' (world space), and 'v' (viewport space) [S8, unofficial]. Transition matrices are named by source and destination identifiers (e.g., $M_{ow}$) [S8, unofficial].

### Parallel Shear-Warp on Shared Memory
A parallel algorithm for shared-memory multiprocessors that minimizes computation, synchronization, and data communication [S8, unofficial]. It uses dynamic load balancing and task partitioning to minimize synchronization events, leveraging hardware caching to hide latency [S8, unofficial]. A pitfall is that cache locality limits parallelism, making hundreds of processors useful only for very large datasets [S8, unofficial].

### Parallel Projection Rendering
Stores sheared, resampled volume as run-length encoded voxel scanlines with transparent and non-transparent runs [S3, unofficial]. It walks through volume and intermediate image scanlines in tandem, using RLE to skip transparent voxels and occluded pixels [S3, unofficial]. The intermediate image scanline stores pointers to the next non-opaque pixel to skip occluded regions [S3, unofficial].

### Parallel Projection Rendering 3
Uses bilinear interpolation and backward projection convolution, traversing two voxel scanlines simultaneously to produce one intermediate image scanline [S3, unofficial]. It uses lookup tables for shading and opacity correction for view angle [S3, unofficial]. The RLE structure is created on the fly but is nearly view-independent, with three encodings for each principal view direction [S3, unofficial].

### Perspective Projection Rendering
Scales and translates each voxel during resampling, requiring more than two voxel scanlines to be traversed simultaneously [S3, unofficial]. Voxel scanlines may not be traversed at the same rate as image scanlines [S3, unofficial]. It uses a box reconstruction filter and a box low-pass filter, with scaling factors chosen so the closest slice has unit scaling [S3, unofficial].

### Gaussian Volumetric Representation for Shear-Warp Visualization
A Gaussian-based volumetric representation proposed to address the high computational cost of large datasets while preserving anatomical fidelity and maintaining high rendering speeds in Shear-Warp visualization [S9, abstract only, unofficial].

## Background
The Shear-warp algorithm was designed by Lacroute and Levoy [48] and recognized as the fastest software rendering algorithm at the time [S1, unofficial]. It was implemented in the VolumePro hardware architecture, a specialized single-chip hardware compatible with consumer PCs for real-time volume rendering [S1, unofficial]. The first GPU-based implementation was presented by Gautron and Bouatouch, claiming to be the first on the GPU, providing real-time frame rates and outperforming CPU-based implementations [S5, unofficial]. The method is widely used in medical imaging and scientific visualization where real-time interaction is required [S1, S5, unofficial].
