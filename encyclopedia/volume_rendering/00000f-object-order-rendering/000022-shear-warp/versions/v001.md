# Shear-warp

Also called: Shear-warp factorization

## Overview
Shear-warp is a hybrid volume rendering algorithm that exhibits characteristics of both image-order and object-order methods [S2, S3]. It solves the problem of efficient rendering at arbitrary viewing angles by avoiding the computational expense of rendering volumes at arbitrary rotations directly [S2]. The method renders the volume onto an image plane parallel to one of the volume faces, then warps or distorts this intermediate image to generate the desired final image [S2, S3]. Unlike its siblings, such as [Splatting](23-splatting.md) or [Texture slicing](25-texture-slicing.md), shear-warp allows for early ray termination via skipping opaque pixels, a capability that object-order algorithms lacked at the time of its introduction [S2].

## Shared principles
The core mechanism of the shear-warp family relies on the factorization of the viewing transformation matrix $M_{view}$ into a 3D shearing matrix $M_{shear3D}$ and a 2D warping matrix $M_{warp2D}$ [S3]:

$$ M_{view} = M_{warp2D} \cdot M_{shear3D} $$

The algorithm proceeds in three distinct steps [S2, S3]:

1.  **Shear:** The volume data is transformed into a "sheared object space" by translating (and for perspective, scaling) each volume slice according to the viewing direction [S2]. This shearing aligns the viewing rays perpendicular to the volume slices [S1]. The result is a distorted intermediate image where voxel scanlines are parallel to pixel scanlines [S2].
2.  **Composite:** The resampled slices are composited together in front-to-back order to project the volume into a 2D intermediate image in sheared object space [S2]. This step typically uses bilinear interpolation within the traversed volume slices [S1, S2].
3.  **Warp:** The intermediate image is transformed to the final image space by warping it [S2, S3]. This second resampling step compensates for the distortion introduced in the first step [S3].

**Viewing Direction Assumption:** The algorithm assumes the view direction is generally aligned with the z-axis [S2]. If the view is along the x or y axes (or negative x/y), the voxel coordinates must be reordered by transposing the coordinate axes [S2]. To avoid re-ordering voxels when the view direction changes, three encoded Run-Length Encoding (RLE) volumes are required, one for each main viewing axis [S2].

**Interpolation:** The basic algorithm uses bilinear interpolation, which can lead to unsatisfactory image quality [S1]. Hardware implementations, such as VolumePro, use trilinear interpolation for better quality [S1].

**Optimization (RLE):** A key optimization is the use of Run-Length Encoding (RLE) on classified volume data to compute runs of transparent and opaque voxels [S2]. RLE stores a sequence as count-value pairs (e.g., '44444999933222555788' becomes '54 49 23 32 35 17 28') [S2]. This allows the renderer to skip through scanlines quickly, processing only "interesting" voxels [S2]. Scanline traversal processes voxel and pixel scanlines in tandem due to their 1-to-1 correspondence [S2].

**Perspective Projection:** For perspective transformations, voxels must be scaled as well as translated [S2]. Resampling is no longer uniform; two or more voxel scanlines may project onto a single image scanline [S2].

**Fast Classification (Alternative to RLE):** To support interactive modification of the opacity transfer function, a Min-Max Octree can be used [S2]. This recursive data structure stores extrema of parameter values (opacities) in nodes [S2]. The classification algorithm finds extrema ($d_{min}, d_{max}, \nabla d_{min}, \nabla d_{max}$) for a block, determines if the region is transparent, and discards it if so, or subdivides recursively [S2].

**Shading:** The basic pipeline is pre-shaded (interpolating already-shaded samples) [S2]. An enhancement involves interpolating densities inside each voxel scanline during resampling, performing classification and shading, and then compositing results into the intermediate image, converting to a post-shaded pipeline [S2].

## Subtopics

### [Parallel Perspective Shear-Warp Rendering](802-parallel-perspective-shear-warp-rendering.md)
A distributed volume rendering technique using Message Passing Interface (MPI) to parallelize the compositing step of the perspective shear-warp algorithm across multiple nodes (shared memory or cluster), where a display machine coordinates the rendering and a remote renderer performs the heavy computation.

### Back-to-front polygon rendering with display lists
Renders parallel polygons from back to front to satisfy linear alpha blending requirements for compositing [S4]. It defines six display lists (two directions along each of three axes) [S4]. The largest absolute component of the view vector (x, y, or z) and its sign determine which display list to execute [S4]. A pitfall is that polygons are never viewed edge-on, limiting oblique viewing angles [S4].

## Background
The shear-warp algorithm was designed by Lacroute et al. [S1, S3]. It was recognized as the fastest software rendering algorithm at the time of its introduction [S1]. The method was implemented in VolumePro hardware, which was specialized for this algorithm and used trilinear interpolation for better image quality [S1]. Performance on a Silicon Graphics machine with 16 processors achieved 10fps for a $256^3$ voxels medical data set and over 30fps for a $128^3$ voxels data set [S1].

The algorithm generates several frames per second in software [S2]. However, the true sampling rate in z varies between [1.0, 1.72] due to shearing [S2]. This variation often violates the Nyquist theorem, leading to staircasing artifacts for diagonal views (e.g., at 45°) [S2]. Blurring also occurs for magnified views because the volume is pre-shaded [S2]. If the opacity transfer function changes, the RLE volume must be re-encoded, making the basic RLE-based approach unsuitable for interactive iso-surface modification [S2].
