# Rotation by Shearing

Also called: Discrete rotation by shearing, Shear-based rotation

## Overview
Rotation by shearing is a technique for rotating a point cloud or voxel grid by decomposing the rotation into a sequence of shear operations. It is described as an 'area-preserving discrete rotation' in 2D that does not introduce holes, but in 3D it requires chaining multiple shears. It sets itself apart from direct matrix multiplication by avoiding floating-point matrix inversion overhead and potentially allowing for a single sequential pass over an array, though it introduces specific rounding error artifacts.

## How it works
**Inputs and Outputs:**
- Input: A source point cloud (hash map or sparse array) mapping voxel coordinates to values (e.g., color), Euler angles for rotation ($\theta_x, \theta_y, \theta_z$), and a local position translation vector.
- Output: An aligned point cloud (hash map or sparse array) with rotated coordinates.

**Data Structures:**
- `sourceCloud`: Dictionary/Map where key is `Vector3Int` (voxel position) and value is `Color` or scalar.
- `alignedCloud`: Dictionary/Map with the same structure, storing the result.
- `eulers`: A vector containing three floating-point angles in radians or degrees.

**Shear Operations:**
The method uses two types of shear functions, `ShearA` and `ShearB`. While the exact mathematical definition of these shears is not provided in the source code comments, they are applied sequentially to approximate rotation. The parameters for these shears are derived from the Euler angles.

**Numbered Steps:**
1. Initialize `alignedCloud` as empty.
2. Iterate through each `point` in `sourceCloud`. Let `point.Key` be the original voxel position and `point.Value` be its data.
3. Initialize a temporary vector `transed` with `point.Key`.
4. Apply Z-axis rotation approximation using three shears:
   - `transed = ShearA(transed, zero, z, x, y, eulers.z)`
   - `transed = ShearB(transed, zero, z, y, x, eulers.z)`
   - `transed = ShearA(transed, zero, z, x, y, eulers.z)`
5. Apply X-axis rotation approximation using three shears:
   - `transed = ShearA(transed, zero, x, y, z, eulers.x)`
   - `transed = ShearB(transed, zero, x, z, y, eulers.x)`
   - `transed = ShearA(transed, zero, x, y, z, eulers.x)`
6. Apply Y-axis rotation approximation using three shears:
   - `transed = ShearA(transed, zero, y, z, x, eulers.y)`
   - `transed = ShearB(transed, zero, y, x, z, eulers.y)`
   - `transed = ShearA(transed, zero, y, z, x, eulers.y)`
7. Add local position translation: `transed += localPos`.
8. Round the final coordinate to the nearest voxel: `rounded = VoxelUtil.RoundVector3(transed)`.
9. Assign the point's value to the aligned cloud: `alignedCloud[rounded] = point.Value`.

**Edge Cases and Pitfalls:**
- Chaining three axis-aligned rotations introduces rounding errors at each step. These errors accumulate, leading to noticeable artifacts in the output [S1, unofficial].
- The quality of the output is sensitive to the rotation order. Setting a unique rotation order for each object may improve quality [S1, unofficial].
- The quality of the output using the shearing approach is approximately 80% compared to other methods [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of points in the source cloud, $O(N)$, where $N$ is the number of non-empty voxels. Each point undergoes a fixed number of shear operations (9 shears total).
- **Memory Complexity:** $O(N)$ for storing the output cloud.
- **Performance:** It may be more efficient than the forward-backward method because it allows eliminating hash table overhead and using a single sequential pass over an array/list, but performance was not tested [S1, unofficial].
- **Strengths:** Straightforward implementation; potentially lower overhead than matrix inversion; area-preserving in 2D.
- **Limitations:** Accumulated rounding errors; sensitivity to rotation order; lower visual quality (~80%) compared to other methods [S1, unofficial].
