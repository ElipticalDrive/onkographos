# Parallel Projection Rendering

Also called: Parallel Projection Rendering 1

## Overview
Parallel Projection Rendering is an object-order volume rendering algorithm optimized for parallel viewing transformations, utilizing the Shear-Warp factorization to align voxel scanlines with pixel scanlines [S2]. It solves the performance bottleneck of traditional ray-casting by exploiting spatial coherence in both the volume data and the intermediate image through run-length encoding (RLE), allowing it to skip transparent voxels and occluded pixels efficiently [S2]. Unlike general shear-warp variants, it assumes a static opacity transfer function and leverages the specific geometric property that all voxel slices share a uniform scale factor, enabling a one-to-one mapping between voxels and intermediate-image pixels [S2].

## How it works
The algorithm operates in three main phases: preprocessing (RLE construction), compositing (synchronous traversal), and warping [S2]. It assumes a parallel projection where the viewing direction is fixed relative to the volume axes such that the shear-warp factorization results in a unity scale factor for all slices [S2].

### Inputs and Outputs
*   **Input:** A 3D scalar volume $V$ of dimensions $W \times H \times D$. An opacity transfer function $f(v)$ that maps scalar values to opacity. A user-specified opacity threshold $\tau$ defining the boundary between transparent and non-transparent voxels [S2].
*   **Output:** A final 2D rendered image [S2].

### Data Structures
The algorithm relies on two primary RLE structures to exploit spatial coherence [S2]:

1.  **Volume RLE:** The sheared and resampled volume is stored as run-length encoded voxel scanlines [S1, unofficial]. Each scanline consists of two types of runs:
    *   **Transparent runs:** Voxels where $f(v) < \tau$ [S1, unofficial].
    *   **Non-transparent runs:** Voxels where $f(v) \ge \tau$ [S1, unofficial].
    *   **Layout:** Each non-transparent voxel consumes 4 bytes (typically for the scalar value or pre-computed color/opacity). Each run header consumes 1 byte (encoding the run length or type) [S2].

2.  **Intermediate Image RLE:** The intermediate image (created after shearing and projection) stores run information to skip occluded pixels [S2].
    *   **Layout:** For each opaque pixel in the intermediate image scanline, a pointer or offset is stored to the next non-opaque pixel in that scanline [S1, unofficial]. This allows the algorithm to skip over regions of the image that are already fully occluded by previously processed voxels [S2].

### Steps

1.  **Preprocessing (RLE Construction):**
    *   Construct the RLE representation of the volume. This involves traversing the volume, applying the opacity threshold $\tau$, and encoding consecutive transparent or non-transparent voxels into runs [S2].
    *   Note: This step is performed once per viewpoint change. If the opacity transfer function changes, this structure must be rebuilt [S2].

2.  **Shear and Project (Resampling):**
    *   Apply the shear transformation to the volume.
    *   Project the sheared volume onto the intermediate image plane.
    *   **Key Property:** For parallel projections, Property 3 of the shear-warp factorization states that every voxel slice has the same scale factor, which can be chosen arbitrarily [S2]. The algorithm chooses a **unity scale factor** ($s=1$) [S2].
    *   This choice ensures a one-to-one mapping between voxels in a voxel scanline and pixels in the corresponding intermediate-image scanline [S2]. Consequently, resampling weights are identical for all voxels within a slice, simplifying the compositing step [S1, unofficial].

3.  **Compositing (Synchronous Traversal):**
    *   Traverse the volume and the intermediate image in synchrony, processing slice by slice [S2].
    *   For each volume scanline and its corresponding intermediate image scanline:
        1.  Initialize the compositing state (e.g., current accumulated opacity and color) [G].
        2.  Iterate through the volume RLE runs.
        3.  **Skip Transparent Runs:** If the current volume run is transparent, skip it entirely [S1, unofficial].
        4.  **Process Non-Transparent Runs:** For a non-transparent run:
            *   Check the intermediate image RLE to see if the corresponding pixel range is already occluded (fully opaque). If so, skip the compositing work for this run [S1, unofficial].
            *   If not fully occluded, perform the compositing. Since the scale factor is 1, each voxel maps directly to one pixel. The voxel's contribution is blended into the intermediate image pixel using standard alpha compositing [G].
            *   Update the intermediate image RLE if the pixel becomes opaque, potentially shortening future runs [S2].

4.  **Warp:**
    *   Apply the 2D warp transformation to the intermediate image to produce the final view [S2]. This step typically accounts for 10-20% of the total rendering time [S2].

### Pseudocode

```python
def parallel_projection_render(volume, opacity_func, threshold, width, height):
    """
    Renders a volume using the Parallel Projection Shear-Warp algorithm.
    Assumes unity scale factor and parallel projection.
    """
    # 1. Preprocessing: Build Volume RLE
    volume_rle = build_volume_rle(volume, opacity_func, threshold)
    
    # 2. Initialize Intermediate Image RLE
    # Each entry stores the index of the next opaque pixel, or -1 if none
    image_rle = [[-1] * width for _ in range(height)]
    
    # 3. Shear and Project (Resampling)
    # Since scale factor is 1, we can map voxels directly to pixels
    # The shear transformation aligns voxel scanlines with pixel scanlines
    sheared_volume = shear_volume(volume)
    
    # 4. Compositing
    intermediate_image = [[(0.0, 0.0, 0.0)] * width for _ in range(height)]
    
    for slice_idx in range(volume.depth):
        for scanline_idx in range(volume.height):
            vol_runs = volume_rle[slice_idx][scanline_idx]
            acc_color = (0.0, 0.0, 0.0)
            acc_opacity = 0.0
            current_pixel = 0
            
            for run_type, run_length, run_data in vol_runs:
                if run_type == 0: # Transparent run
                    current_pixel += run_length
                    continue
                
                # Non-transparent run
                start_pixel = current_pixel
                end_pixel = current_pixel + run_length
                
                # Check occlusion using image RLE
                is_occluded = check_image_occlusion(image_rle[scanline_idx], start_pixel, end_pixel)
                
                if not is_occluded:
                    for i in range(run_length):
                        pixel_idx = start_pixel + i
                        voxel_val = run_data[i] if isinstance(run_data, list) else run_data
                        
                        opacity = opacity_func(voxel_val)
                        color = compute_color(voxel_val)
                        
                        acc_color = tuple(c + col * opacity * (1.0 - acc_opacity) for c, col in zip(acc_color, color))
                        acc_opacity = acc_opacity + opacity * (1.0 - acc_opacity)
                        
                        if acc_opacity >= 1.0:
                            update_image_rle(image_rle[scanline_idx], pixel_idx)
                    
                    current_pixel = end_pixel
            
            for p in range(width):
                intermediate_image[scanline_idx][p] = acc_color
                
    # 5. Warp
    final_image = warp_image(intermediate_image)
    return final_image

def build_volume_rle(volume, opacity_func, threshold):
    rle = []
    for slice in volume:
        slice_rle = []
        for scanline in slice:
            runs = []
            current_run_type = None
            current_run_length = 0
            current_run_data = []
            for voxel in scanline:
                val = voxel.value
                op = opacity_func(val)
                is_transparent = op < threshold
                run_type = 0 if is_transparent else 1
                if run_type == current_run_type:
                    current_run_length += 1
                    current_run_data.append(val)
                else:
                    if current_run_type is not None:
                        runs.append((current_run_type, current_run_length, current_run_data))
                    current_run_type = run_type
                    current_run_length = 1
                    current_run_data = [val]
            if current_run_type is not None:
                runs.append((current_run_type, current_run_length, current_run_data))
            slice_rle.append(runs)
        rle.append(slice_rle)
    return rle

def check_image_occlusion(img_rle, start_pixel, end_pixel):
    for p in range(start_pixel, end_pixel):
        next_opaque = img_rle[p]
        if next_opaque != -1 and next_opaque < end_pixel:
            return True
    return False

def update_image_rle(img_rle, pixel_idx):
    for p in range(pixel_idx, len(img_rle)):
        if img_rle[p] == -1 or img_rle[p] > p:
            img_rle[p] = pixel_idx
        else:
            break

def shear_volume(volume):
    return volume # Simplified for pseudocode

def compute_color(voxel_val):
    return (voxel_val, voxel_val, voxel_val) # Simplified for pseudocode

def warp_image(intermediate_image):
    return intermediate_image # Simplified for pseudocode
```

### Parameters and Typical Values
*   **Opacity Threshold ($\tau$):** User-specified. Determines the cutoff for transparent vs. non-transparent runs [S1, unofficial].
*   **Scale Factor:** Fixed at 1.0 for parallel projections [S2].

### Edge Cases and Pitfalls
*   **Memory Usage:** The algorithm requires storing three run-length encoded copies of the volume in memory for efficient traversal [S2]. For a $256 \times 256 \times 226$ dataset, this totals 9.8 Mbytes [S2]. If the volume is too large to fit three copies in memory, performance will degrade or the algorithm cannot be used [S2].
*   **Viewpoint Changes:** The RLE structures must be rebuilt if the viewpoint changes significantly, as the shear transformation changes [S2]. However, unlike some other algorithms, there is no sudden jump in rendering time when the major viewing axis changes, provided the memory constraint is met [S2].
*   **Opacity Transfer Function Changes:** The algorithm assumes a static opacity transfer function. If the transfer function changes, the volume RLE must be rebuilt, which incurs a preprocessing cost [S2].

## Operating characteristics
*   **Time Complexity:** The compositing step is linear with respect to the number of non-transparent voxels and pixels, but significantly faster in practice due to skipping transparent and occluded regions [S2].
*   **Memory Complexity:** Requires $O(N)$ memory for the volume RLE, where $N$ is the number of voxels. Specifically, 4 bytes per non-transparent voxel and 1 byte per run [S2]. The algorithm requires three copies of the volume RLE in memory for optimal performance [S2].
*   **Measured Performance:**
    *   On an SGI Indigo R4000, the algorithm renders a $128 \times 128 \times 109$ 'brainsmall' dataset in an average of 0.4 seconds [S2].
    *   On an SGI Indigo R4000, the algorithm renders a $128 \times 128 \times 113$ 'headsmall' dataset in an average of 0.4 seconds [S2].
    *   On an SGI Indigo workstation, the algorithm renders a $256^3$ voxel medical dataset in one second [S2].
    *   This is at least five times faster than previous algorithms on comparable hardware [S2].
    *   Color renderings take roughly twice as long as grayscale renderings [S2].
*   **Strengths:**
    *   High performance for parallel projections with spatial coherence [S2].
    *   No performance degradation when the major viewing axis changes, provided memory constraints are met [S2].
    *   Minimal loss of image quality compared to subsampling methods [S2].
*   **Limitations:**
    *   Requires static opacity transfer function [S2].
    *   Requires sufficient memory to store three copies of the volume RLE [S2].
    *   Optimized for parallel projections; perspective projections require a different variant (Parallel Perspective Shear-Warp Rendering) [S2].

## Background
The Parallel Projection Rendering algorithm was introduced by Lacroute and Levoy as part of their work on fast volume rendering using shear-warp factorization [S2]. It was published in 1995 as a technical report from Stanford University [S2]. The algorithm was designed to address the high computational cost of volume rendering by exploiting the geometric properties of the shear-warp factorization and the spatial coherence of medical volume data [S2]. It is a foundational method in the Shear-Warp family of algorithms [S2].
