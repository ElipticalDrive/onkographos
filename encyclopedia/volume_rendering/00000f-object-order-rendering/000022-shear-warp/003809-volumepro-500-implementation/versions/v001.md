# VolumePro 500 Implementation

Also called: Cube-4 Architecture Volume Rendering, VolumePro 500

## Overview
The VolumePro 500 is a hardware-accelerated volume rendering system based on the Cube-4 architecture that implements the Shear-warp factorization [S1, unofficial]. It distinguishes itself from software implementations by using specialized 3D skewing memory address arithmetic to efficiently access axis-aligned voxel slices, enabling fixed-rate Phong shading and on-the-fly gradient estimation [S1, unofficial]. Unlike general-purpose ray-casting, it processes data at a constant throughput independent of classification complexity, relying on brute-force sampling with tri-linear interpolation to prevent undersampling artifacts [S1, unofficial].

## How it works
The method decomposes the viewing transformation into permutation, shear, and warp phases [S1, unofficial], leveraging the Cube-4 architecture's memory interface.

**Inputs and Outputs:**
*   **Input:** 3D volume data (typically $256^3$ or smaller), viewing parameters (position, direction, projection type), lighting parameters, and classification/shading lookup tables.
*   **Output:** 2D color image with alpha channel.

**Data Structures:**
*   **Volume Data:** Stored in a single copy in memory. Access is managed via 3D skewing address arithmetic, which maps 3D coordinates to memory addresses such that axis-aligned slices are contiguous [S1, unofficial].
*   **Classification Lookup Table (LUT):** $4096 \times 36$ bits. Maps input scalar values to 24-bit color and 12-bit alpha [S1, unofficial].
*   **Reflectance Maps:** Pre-computed tables storing diffuse and specular illumination sums for all light sources, indexed by surface normal and eye vector [S1, unofficial].

**Steps:**

1.  **Permutation and Shear:**
    The volume is permuted so the principal viewing axis aligns with a coordinate axis (typically Z). The volume slices perpendicular to this axis are sheared to align viewing rays with the slice normal [S1, unofficial]. The shear coefficients $s_x, s_y$ are derived from the view direction $v_o = [v_{o,x}, v_{o,y}, v_{o,z}]^T$ in the permuted space:
    $$ s_x = -\frac{v_{o,x}}{v_{o,z}}, \quad s_y = -\frac{v_{o,y}}{v_{o,z}} $$
    The hardware uses 3D skewing to read these sheared slices efficiently from the single volume copy [S1, unofficial].

2.  **Resampling and Interpolation:**
    Viewing rays start at sub-pixel locations to allow over-sampling and prevent popping artifacts during base plane switches [S1, unofficial]. Tri-linear interpolation is used between volume slices to prevent undersampling [S1, unofficial]. On-chip slice buffers maintain axis-aligned processing order for maximum memory coherence [S1, unofficial].

3.  **Gradient Estimation and Correction:**
    Hardware performs on-the-fly central-difference gradient estimation at each voxel [S1, unofficial]. Gradients are tri-linearly interpolated to resampling locations. The gradient magnitude is mapped via a LUT to a user-specified piece-wise linear function to highlight specific values or attenuate modulation effects [S1, unofficial]. The LUT also automatically corrects gradient magnitudes for anisotropic volumes [S1, unofficial].

4.  **Classification:**
    Post-classification is applied using the $4096 \times 36$ bit LUT, outputting 24-bit color and 12-bit alpha values [S1, unofficial]. The high alpha precision (12-bit) is necessary for accurate rendering of low-opacity volumes [S1, unofficial]. Opacity correction for uniform sample spacing is applied in software per frame [S1, unofficial]. The LUTs are dynamically loaded using hardware double buffering [S1, unofficial].

5.  **Shading:**
    Phong shading is implemented at each sample point at a rate of one illuminated sample per clock cycle [S1, unofficial]. Diffuse and specular illumination are looked up in pre-computed reflectance maps [S1, unofficial]. Reflectance maps are reloaded when object/light positions change or to correct the eye vector for anisotropic volumes [S1, unofficial].

6.  **Composite and Warp:**
    Samples are composited onto the viewing plane along axis-aligned viewing rays [S1, unofficial]. The intermediate image is warped to the final image space using the 2D warp matrix [S1, unofficial].

7.  **Large Volume Handling:**
    For volumes larger than the hardware's native capacity, the driver software partitions the volume into smaller blocks. Each block is rendered independently, and the resulting images are automatically combined [S1, unofficial].

**Pseudocode:**
```python
def volume_pro_500_render(volume, view_params, light_params, classification_lut, reflectance_maps):
    # 1. Permutation and Shear Setup
    # Determine principal axis and compute shear coefficients
    v_o = view_params.direction
    s_x = -v_o.x / v_o.z
    s_y = -v_o.y / v_o.z
    
    # Initialize 3D skewing address arithmetic for efficient slice access
    skewer = init_3d_skewing(volume, s_x, s_y)
    
    # 2. Ray Casting Loop
    for y in range(image_height):
        for x in range(image_width):
            # Start ray at sub-pixel location for over-sampling
            ray_origin = get_subpixel_origin(x, y, view_params)
            ray_direction = get_ray_direction(x, y, view_params)
            
            color = (0.0, 0.0, 0.0)
            alpha = 0.0
            
            # Traverse volume along axis-aligned rays (after shear)
            while ray_inside_volume(ray_origin, ray_direction):
                # Get voxel value using 3D skewing
                voxel_val = skewer.read(ray_origin)
                
                # Gradient estimation (hardware accelerated)
                grad = compute_central_difference_gradient(voxel_val, skewer)
                grad_mag = magnitude(grad)
                
                # Gradient correction for anisotropy and mapping
                grad_mag_corrected = classification_lut.correct_gradient(grad_mag)
                
                # Classification
                rgba = classification_lut.lookup(voxel_val)
                c = rgba[:3]
                a = rgba[3]
                
                # Shading (Phong)
                # Lookup reflectance based on normal (from grad) and eye vector
                reflectance = reflectance_maps.lookup(grad, ray_direction)
                shaded_c = c * reflectance
                
                # Composite (Front-to-Back)
                # Apply opacity correction in software
                a_corrected = a * opacity_correction_factor
                color = color + shaded_c * a_corrected * (1.0 - alpha)
                alpha = alpha + a_corrected * (1.0 - alpha)
                
                if alpha > 0.99: # Early termination threshold
                    break
                
                ray_origin += ray_direction * step_size
            
            # 3. Warp to final image space
            final_pixel = warp_2d(x, y, color, alpha, view_params)
            set_pixel(final_pixel)
```

## Operating characteristics
*   **Performance:** Renders $256^3$ volumes at 30 frames per second [S1, unofficial].
*   **Complexity:** Performance is independent of classification or data complexity due to brute-force processing at a fixed hardware rate (one sample per clock cycle) [S1, unofficial].
*   **Memory:** Uses a single copy of volume data with 3D skewing to minimize memory bandwidth [S1, unofficial].
*   **Limitations:** Native support is limited to volumes of $256^3$ or smaller; larger volumes require software partitioning and compositing [S1, unofficial].
*   **Strengths:** High throughput, consistent frame rates, hardware-accelerated shading and gradient estimation [S1, unofficial].

## Background
The VolumePro 500 system [Pfister et al. 1999] is based on the Cube-4 architecture developed at SUNY Stony Brook [Pfister and Kaufman 1996]. Mitsubishi Electric licensed the technology, improved it [Osborne et al. 1997], and began production shipments in 1999 [Pfister et al. 1999]. It was one of the first commercial hardware-accelerated volume rendering systems, leveraging the Shear-warp factorization [S1, unofficial].
