# 3D Forward FFT via FFTW
Also called: 3D FFT (FFTW), FFTW 3D DFT

## Overview
This method computes the 3D discrete Fourier transform (DFT) of a real-valued volume by treating the input as a complex array with zero imaginary components [S1, unofficial]. It differs from GPU-based 2D FFT [841-gpu-based-2d-fft.md] by operating on the full 3D domain using the CPU-bound FFTW library rather than GPU kernels, and from GPU-based FFT Convolution [4274-gpu-based-fft-convolution.md] by performing a direct transform rather than a convolution in the frequency domain.

## How it works
**Inputs:** A real-valued 3D volume of dimensions $W \times H \times D$ (where $W = \text{mVolWidth}$, $H = \text{mVolHeight}$, $D = \text{mVolDepth}$).
**Outputs:** A complex-valued 3D array of size $W \times H \times D$ containing the spectral data, stored in-place.

**Data Structures:**
*   **Complex Array:** A single-precision complex array allocated using `fftwf_malloc`. The layout is a contiguous block of memory where each element consists of two floats: the real component at index 0 and the imaginary component at index 1. The total number of elements is $N = W \times H \times D$.

**Steps:**
1.  **Allocation:** Allocate the complex array of size $N$ using `fftwf_malloc` to ensure memory alignment required by FFTW [S1, unofficial].
2.  **Initialization:** Pack the volume data into the real component (index 0) of the complex array. Explicitly set the imaginary component (index 1) to $0.0$ for all $N$ elements [S1, unofficial].
3.  **Plan Creation:** Create an in-place forward FFT plan using the `FFTW_ESTIMATE` strategy with dimensions $W, H, D$ [S1, unofficial]. The `FFTW_ESTIMATE` flag skips extensive benchmarking to quickly select a heuristic algorithm [S2, unofficial].
4.  **Execution:** Execute the plan. This overwrites the input array with the spectral data [S1, unofficial].

**Parameters:**
*   `FFTW_ESTIMATE`: Flag passed to plan creation to skip extensive benchmarking and use a fast, heuristic plan [S1, S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Memory Alignment:** `fftwf_malloc` must be used instead of standard `malloc` to ensure the memory is aligned for SIMD instructions, which is a requirement for FFTW performance and correctness [S1, unofficial].
*   **In-place Operation:** The method overwrites the input data. If the original volume is needed, it must be copied before execution [S1, unofficial].
*   **Real-to-Complex:** Although the input is real, the method treats it as a complex array with zero imaginary parts. This is distinct from specialized real-to-complex transforms but functionally equivalent for the forward pass if the imaginary part is zeroed [S1, unofficial].

## Operating characteristics
**Time Complexity:** $O(N \log N)$ where $N = W \times H \times D$, typical for FFT algorithms. The `FFTW_ESTIMATE` strategy minimizes planning time but may not yield the optimal execution kernel compared to `FFTW_MEASURE` or `FFTW_PATIENT` [S1, S2, unofficial].
**Memory Complexity:** $O(N)$ for the complex array. Since it is in-place, no additional large buffers are required for the transform itself [S1, unofficial].
**Performance:** Performance depends on the hardware's CPU cache hierarchy and SIMD capabilities. FFTW is optimized for specific architectures. The `ESTIMATE` strategy is faster to plan but may be slower to execute than a measured plan [S2, unofficial].
**Strengths:** Simple implementation using a well-optimized library; handles arbitrary dimensions [S1, unofficial].
**Limitations:** CPU-bound; does not leverage GPU parallelism like sibling methods [841-gpu-based-2d-fft.md, 4274-gpu-based-fft-convolution.md].

## Background
This method is derived from the cuFVR project, which implements a CUDA-based volume rendering framework but utilizes FFTW for the 3D FFT step on the CPU side before transferring data or using it in subsequent GPU steps [S1, unofficial]. The approach is standard for CPU-based spectral analysis in scientific visualization.
