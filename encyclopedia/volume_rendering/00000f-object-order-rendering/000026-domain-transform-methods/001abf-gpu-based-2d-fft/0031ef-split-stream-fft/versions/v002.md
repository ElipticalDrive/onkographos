# Split-Stream-FFT

## Overview
Split-Stream-FFT is a GPU-optimized implementation of the Fast Fourier Transform designed to map the recursive structure of the FFT to the stream architecture of graphics hardware [S1, unofficial]. It solves the problem of efficiently computing the Discrete Fourier Transform (DFT) for volume rendering and other DSP applications by leveraging the parallel processing capabilities of commodity GPUs [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   Input: A sequence of $N$ complex samples $f(n)$, where $0 \le n < N$ and $N$ is a power of 2 [S1, unofficial].
*   Output: The frequency domain representation $F(k)$, where $0 \le k < N$, initially in bit-reversed order [S1, unofficial].

**Data Structures:**
*   The algorithm operates on a 1D array of complex numbers [S1, unofficial].
*   No explicit tree structures are used; the recursion is implicit in the stage-based processing [G].
*   Memory layout: A contiguous array of size $N$ for input and output [S1, unofficial].

**Algorithm Steps:**
1.  **Initialization:** Load the input signal $f(n)$ into the GPU memory [G].
2.  **Recursive Decomposition (DIF):** Perform $\log_2 N$ stages of butterfly operations [S1, unofficial]. In each stage, the data is divided into smaller DFTs [S1, unofficial]. The division occurs in the frequency domain [S1, unofficial].
    *   The standard DFT definition includes a constant factor $1/N$ [S1, unofficial]. This factor is discarded during the recursive steps to maintain a strict recursive structure without scaling at every level [S1, unofficial].
    *   The decomposition for a sequence of size $N$ splits the input into even-indexed and odd-indexed frequency components based on the following relations for $0 \le n < N/2$:
        $$ e(n) = f(n) + f(n + N/2) $$
        $$ o(n) = (f(n) - f(n + N/2)) e^{-2\pi i n / N} $$
    *   The resulting frequency values are computed as:
        $$ F(k) = F_e(k) + W_N^k F_o(k) \quad \text{for even } k $$
        $$ F(k) = F_e(k) - W_N^k F_o(k) \quad \text{for odd } k $$
        where $F_e$ and $F_o$ are the DFTs of the even and odd indexed input samples respectively, and $W_N^k = e^{-2\pi i k / N}$ is the twiddle factor [S1, unofficial].
3.  **Post-Processing:** After all $\log_2 N$ stages are complete, the resulting frequency distribution is in the wrong order (bit-reversed) [S1, unofficial]. A bit-reversal (or tangling) operation is performed to re-sort the values into natural order [S1, unofficial].
4.  **Scaling:** Multiply the final result by the constant factor $1/N$ to correct for the scaling discarded in step 2 [S1, unofficial].

**Pseudocode:**
```python
import math

def split_stream_fft(f, N):
    """
    Computes the FFT of input array f of size N using DIF approach.
    Returns F in bit-reversed order, then applies bit-reversal and scaling.
    """
    # f is a list of complex numbers of length N
    # N must be a power of 2
    
    num_stages = int(math.log2(N))
    
    # Stage-based DIF butterfly operations
    for stage in range(num_stages):
        block_size = 2 ** (stage + 1)
        half_block = block_size // 2
        
        for i in range(0, N, block_size):
            for j in range(half_block):
                idx_even = i + j
                idx_odd = i + j + half_block
                
                # Twiddle factor W_{block_size}^j
                twiddle = complex(math.cos(-2 * math.pi * j / block_size), 
                                  math.sin(-2 * math.pi * j / block_size))
                
                val_even = f[idx_even]
                val_odd = f[idx_odd]
                
                # Butterfly operation
                t = val_odd * twiddle
                f[idx_even] = val_even + t
                f[idx_odd] = val_even - t

    # Bit-reversal permutation
    num_bits = int(math.log2(N))
    result = [0] * N
    for i in range(N):
        rev = 0
        temp = i
        for _ in range(num_bits):
            rev = (rev << 1) | (temp & 1)
            temp >>= 1
        result[rev] = f[i]
    
    # Post-multiply by 1/N
    for i in range(N):
        result[i] = result[i] / N
        
    return result
```

**Parameters:**
*   $N$: Input size, must be a power of 2 [S1, unofficial]. Typical values depend on the volume resolution (e.g., $128^3$, $256^3$) [G].
*   Reconstruction Filter: The source mentions using a Lanczos windowed-sinc function for resampling in the frequency domain, but this is part of the broader FVR pipeline, not the FFT itself [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** Floating-point precision errors can accumulate during the recursive stages [G].
*   **Boundaries:** The algorithm assumes $N$ is a power of 2 [S1, unofficial]. Non-power-of-2 sizes require padding or a different algorithm [G].
*   **Ordering:** The output is in bit-reversed order. Failure to perform the bit-reversal step results in incorrect frequency ordering [S1, unofficial].
*   **Scaling:** Forgetting to multiply by $1/N$ at the end results in an amplitude error [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \log N)$ for $N$ input values [S1, unofficial].
*   **Memory Complexity:** $O(N)$ for storing the input and output arrays [G].
*   **Performance:** The method is designed for superior speed performance on commodity graphics hardware compared to naive implementations [S1, unofficial].
*   **Strengths:** Efficient mapping to GPU stream architecture; high performance for DSP and volume rendering applications [S1, unofficial].
*   **Limitations:** Requires $N$ to be a power of 2; output is in bit-reversed order; subject to under-/oversampling and aliasing issues inherent to the DFT [S1, unofficial].
*   **When to use:** When high-performance FFT computation is needed on a GPU for volume rendering or general DSP [G].
*   **When not to use:** When the input size is not a power of 2 and padding is undesirable; when natural order output is required without post-processing [G].

## Background
Split-Stream-FFT was introduced in the context of Fourier Volume Rendering (FVR) on the GPU [S1, unofficial]. The paper "Fourier volume rendering on the GPU using a split-stream-FFT" describes this novel implementation designed to take advantage of commodity graphics hardware features [S1, unofficial]. It was developed to address the limitations of previous FVR approaches and to provide an efficient FFT implementation for volume visualization, which is seen as the inverse problem of tomographic reconstruction [S1, unofficial]. The method uses the Decimation-in-Frequency (DIF) approach and incorporates a Lanczos windowed-sinc function for reconstruction filtering [S1, unofficial].
