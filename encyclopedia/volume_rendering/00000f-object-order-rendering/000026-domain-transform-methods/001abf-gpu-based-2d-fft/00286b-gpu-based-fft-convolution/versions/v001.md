# GPU-based FFT Convolution

Also called: CUDA FFT Convolution, FFT-based Convolution

## Overview
GPU-based FFT Convolution is a method to calculate the matrix-vector product $Hx$ (convolution) efficiently by leveraging CUDA's FFT library to reduce computational cost [S1, unofficial]. It solves the problem of expensive spatial convolution for large kernels by transforming inputs to the frequency domain, multiplying transforms, and inverse transforming [S2, unofficial]. It sets itself apart from spatial methods by becoming computationally economical when kernel size increases, and from sibling methods like Split-Stream-FFT by relying on the general CUDA FFT library for the transform operations [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: Spatial image data $g$ and filter kernel $h$.
- Output: Convolved result $\lambda Hx$ written to global memory.

**Data Structures:**
- FFT Plans: Objects created and initialized for both forward and inverse FFT operations [S1, unofficial].
- Padded Filter: The filter $h$ is zero-padded to match the image dimensions [S1, unofficial].

**Steps:**
1. **Plan Initialization:** Create and initialize plans for both forward and inverse FFT [S1, unofficial].
2. **Padding:** Pad the filter with zeros to match the image size [S1, unofficial].
3. **Forward Transform:** Apply forward FFT to the input data and the padded filter [S1, unofficial].
4. **Point-wise Multiplication:** Perform point-wise multiplication of the FFT of input data and the FFT of padded filter data [S1, unofficial].
5. **Inverse Transform:** Apply inverse FFT on the result of the multiplication to obtain $\lambda Hx$ [S1, unofficial].
6. **Finalization:** Write the result into global memory and eliminate the FFT plan [S1, unofficial].

**Formula:**
The method relies on the 2-D Convolution Theorem [S2, unofficial]:
$$g_{x,y} * h_{x,y} = \sum_{a=0}^{N-1} \sum_{b=0}^{N-1} h_{a,b} \cdot g_{x-a,y-b} \Leftrightarrow G_{u,v} H_{u,v}$$
where $*$ is spatial convolution, $G$ and $H$ are frequency transforms, and $N$ is the dimension size assumed in the convolution sum limits (0 to $N-1$) [S2, unofficial].

**Pseudocode:**
```python
def gpu_fft_convolution(image, kernel):
    # 1. Create and initialize plans for both forward and inverse FFT
    forward_plan = create_fft_plan(image.shape)
    inverse_plan = create_ifft_plan(image.shape)

    # 2. Pad the filter with zeros to match the image size
    padded_kernel = zero_pad(kernel, image.shape)

    # 3. Apply forward FFT to the input data and the padded filter
    fft_image = forward_plan.execute(image)
    fft_kernel = forward_plan.execute(padded_kernel)

    # 4. Perform point-wise multiplication of the FFT of input data and the FFT of padded filter data
    product = fft_image * fft_kernel

    # 5. Apply inverse FFT on the result of the multiplication to obtain lambda Hx
    result = inverse_plan.execute(product)

    # 6. Write the result into global memory and eliminate the FFT plan
    write_to_global_memory(result)
    destroy_plan(forward_plan)
    destroy_plan(inverse_plan)

    return result
```

**Parameters:**
- $N$: The dimension size assumed in the convolution sum limits (0 to $N-1$) [S2, unofficial].

**Edge Cases and Pitfalls:**
- Kernel size vs. Image size: The kernel is usually smaller than the image, requiring padding [S1, unofficial].
- Performance: The method is computationally economical for large kernels where the speed of frequency domain convolution balances the cost of the inverse transform [S2, unofficial].

## Subtopics

### Frequency Domain Convolution
Frequency Domain Convolution is the general technique of performing spatial convolution by transforming inputs to the frequency domain, multiplying transforms, and inverse transforming [S2, unofficial]. It is chosen when the kernel size is large enough that spatial convolution becomes computationally expensive, as the frequency domain approach balances the cost of the inverse transform with the speed of multiplication [S2, unofficial]. It is defined by the 2-D Convolution Theorem $g_{x,y} * h_{x,y} \Leftrightarrow G_{u,v} H_{u,v}$ [S2, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
The method reduces computational cost compared to direct spatial convolution, especially for large kernels [S1, unofficial]. The time complexity is dominated by the FFT operations, which are generally $O(N \log N)$, making it more efficient than the $O(N^2)$ or higher complexity of direct spatial convolution for large kernels [S2, unofficial]. Memory usage includes storage for the image, padded kernel, and intermediate FFT buffers.

**Measured Performance:**
Specific performance metrics are not given in the sources. However, it is noted that convolution is often the most expensive operation in volume rendering solvers, and this method is used to mitigate that cost [S1, unofficial].

**Strengths and Limitations:**
- Strengths: Significant reduction in computational cost for convolution operations [S1, unofficial]. Economical for large kernels [S2, unofficial].
- Limitations: Requires padding the filter to match image size [S1, unofficial]. The inverse transform time must be balanced by the speed of frequency domain multiplication [S2, unofficial].

**When to Use:**
Use when convolution is the bottleneck and the kernel size is large enough to justify the overhead of FFT [S1, unofficial][S2, unofficial].

## Background
**Origin:**
The method is described in "GPU-based Compressive Volume Rendering" by V Podlozhnyuk et al., which utilizes CUDA's FFT library developed by V Podlozhnyuk [S1, unofficial]. The underlying principle of frequency domain convolution is detailed in "Fourier volume rendering" [S2, unofficial].

**History and Development:**
The approach leverages the CUDA FFT library to optimize the convolution step in volume rendering solvers, addressing the high computational cost of this operation [S1, unofficial].

**Where it is Used:**
It is used in GPU-based compressive volume rendering to accelerate the convolution step within the solver [S1, unofficial].
