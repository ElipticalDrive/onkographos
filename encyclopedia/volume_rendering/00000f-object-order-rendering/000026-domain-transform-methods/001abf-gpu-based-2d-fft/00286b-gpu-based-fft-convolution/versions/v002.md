# GPU-based FFT Convolution
Also called: CUDA FFT Convolution, FFT-based Convolution

## Overview
GPU-based FFT Convolution is a method to calculate the matrix-vector product $Hx$ (convolution) efficiently using CUDA's FFT library to reduce computational cost [S1, unofficial]. It is computationally economical for large kernels where the cost of the Fast Fourier Transform (FFT) is outweighed by the reduction in arithmetic operations compared to direct spatial convolution [S2, unofficial]. It builds on [GPU-based 2D FFT](841-gpu-based-2d-fft.md).

## How it works
**Inputs and Outputs:**
- Input: Image data (spatial domain), Filter/Kernel data (spatial domain).
- Output: Result of convolution $\lambda Hx$ in global memory.

**Data Structures:**
- The input data and filter are treated as 1D arrays where each thread index corresponds to the address of that particular data [S1, unofficial].
- The filter is padded with zeros to match the image size [S1, unofficial].

**Steps:**
1. **Plan Creation:** Create and initialize plans for both forward and inverse FFT using the CUDA FFT library [S1, unofficial].
2. **Padding:** Pad the filter with zeros to match the image size [S1, unofficial].
3. **Forward FFT:** Apply forward FFT to the input data and the padded filter [S1, unofficial].
4. **Point-wise Multiplication:** Perform point-wise multiplication of the FFT of input data and the FFT of padded filter data [S1, unofficial].
5. **Inverse FFT:** Apply inverse FFT on the result of the multiplication to obtain $\lambda Hx$ [S1, unofficial].
6. **Memory Management:** Write the result into global memory and eliminate the FFT plan [S1, unofficial].

**Pseudocode:**
```python
# Assume input_image and filter_kernel are available in device memory
# Assume image_size is known

# 1. Create plans
forward_plan = cufft_plan_1d(image_size, cufft_type, 1)
inverse_plan = cufft_plan_1d(image_size, cufft_type, 1)

# 2. Pad filter
padded_filter = zero_pad(filter_kernel, image_size)

# 3. Forward FFT
fft_input = cufft_execute(forward_plan, input_image)
fft_filter = cufft_execute(forward_plan, padded_filter)

# 4. Point-wise multiplication
# Element-wise multiplication of two complex arrays
fft_result = fft_input * fft_filter

# 5. Inverse FFT
conv_result = cufft_execute(inverse_plan, fft_result)

# 6. Write result and cleanup
write_to_global_memory(conv_result)
cufft_destroy(forward_plan)
cufft_destroy(inverse_plan)
```

**Parameters:**
- Iteration count: Many iterations may take longer time while producing better result. A fixed small number of iterations can deteriorate the quality of the reconstruction [S1, unofficial].

**Edge Cases and Pitfalls:**
- Precision: Not given in the sources.
- Boundaries: Padding is required to handle boundary conditions via zero-padding [S1, unofficial].

## Subtopics

### [Frequency Domain Convolution](6341-frequency-domain-convolution.md)
Frequency Domain Convolution computes the spatial convolution of an image or volume slice by transforming the input and kernel into the frequency domain, performing element-wise multiplication, and inverse-transforming the result. It is computationally economical for large kernels where the cost of the Fast Fourier Transform (FFT) is outweighed by the reduction in arithmetic operations compared to direct spatial convolution.

## Operating characteristics
**Time and Memory Complexity:**
- The method reduces computational cost compared to direct spatial convolution [S1, unofficial].
- Memory usage includes storage for input, padded filter, and FFT plans [S1, unofficial].

**Measured Performance:**
- Performance depends on the number of iterations; more iterations improve quality but increase time [S1, unofficial].

**Strengths and Limitations:**
- Strength: Efficient for large kernels [S2, unofficial].
- Limitation: Padding overhead and FFT plan management [S1, unofficial].

**When to Use:**
- Use when convolution is the most expensive operation and kernel size is large [S1, unofficial].
