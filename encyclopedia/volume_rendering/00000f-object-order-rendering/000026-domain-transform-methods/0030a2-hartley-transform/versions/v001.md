# Hartley Transform
Also called: Real Fourier Transform

## Overview
The Hartley Transform is a real-valued integral transform used in volume rendering as an alternative to the complex Fourier Transform for processing real-valued scalar volumes. It solves the problem of avoiding complex number arithmetic during the global transformation stage of domain-transform methods, thereby reducing memory usage and computational overhead for data that is inherently real [S1, S895]. Unlike the Fourier Transform, which produces complex conjugate symmetric outputs for real inputs, the Hartley Transform produces a purely real output, allowing for more efficient storage and processing in the frequency domain [S1, unofficial].

## How it works
The Hartley Transform method follows the standard three-stage pipeline of domain-transform volume rendering, replacing the Fourier kernel with the Hartley kernel ($cas$).

**Inputs and Outputs:**
*   **Input:** A 3D real-valued scalar volume $f(x, y, z)$.
*   **Output:** A 2D real-valued projection image $P(u, v)$ corresponding to a viewing direction.

**Data Structures:**
*   **Volume:** Array of real numbers (e.g., `float` or `double`). No complex components are stored.
*   **Frequency Domain:** Array of real numbers representing the Hartley coefficients.

**Mathematical Foundation:**
The forward Hartley transform of a real function $h(t)$ is defined as [S1, unofficial]:
$$H(f) = \int_{-\infty}^{\infty} h(t) \cdot cas(ft) \, dt$$
where $cas(x) = \cos(x) + \sin(x)$ [S1, unofficial].

The inverse Hartley transform is defined as [S1, unofficial]:
$$h(t) = \int_{-\infty}^{\infty} H(f) \cdot cas(ft) \, df$$

The transform is self-reciprocal, meaning the forward and inverse formulas are identical except for the sign of the integration variable (or normalization factor in the discrete case) [S1, unofficial].

**Conversion to/from Fourier Transform:**
The Hartley Transform $H(f)$ can be converted to the Fourier Transform $S(f)$ using the even and odd parts of $H(f)$ [S1, unofficial]:
$$E(f) = \frac{H(f) + H(-f)}{2} = \int_{-\infty}^{\infty} h(t) \cos(ft) \, dt$$
$$O(f) = \frac{H(f) - H(-f)}{2} = \int_{-\infty}^{\infty} h(t) \sin(ft) \, dt$$
$$S(f) = E(f) + iO(f)$$

Conversely, given the Fourier Transform $S(f)$, the Hartley Transform is [S1, unofficial]:
$$H(f) = \text{Re}[S(f)] + \text{Im}[S(f)]$$

For the inverse direction, if $h(t) = e(t) + o(t)$ where $e(t)$ and $o(t)$ are the even and odd parts of $h(t)$, the inverse Fourier transform $s(t)$ is [S1, unofficial]:
$$s(t) = e(t) - io(t)$$
And given $s(t)$, the inverse Hartley transform is [S1, unofficial]:
$$h(t) = \text{Re}[s(t)] - \text{Im}[s(t)]$$

**Algorithm Steps:**
1.  **Global Transformation:** Compute the 3D Hartley Transform of the volume $f(x, y, z)$ to obtain $F(\omega_1, \omega_2, \omega_3)$. This is typically done using the Discrete Hartley Transform (DHT) [S1, S895].
2.  **Slice Extraction:** Extract a 2D slice from $F(\omega_1, \omega_2, \omega_3)$ passing through the origin and perpendicular to the viewing direction vector $V$. This step relies on the Hartley Projection-Slice Theorem [S1, unofficial]:
    $$P_\theta(\hat{U}_1) = H(\hat{U}_1 \cos \theta, \hat{U}_1 \sin \theta)$$
    where $P_\theta$ is the Hartley transform of the projection at angle $\theta$, and $H$ is the 2D Hartley transform of the object [S1, unofficial].
3.  **Inverse Transformation:** Compute the 2D Inverse Hartley Transform of the extracted slice to generate the final 2D projection image [S1, S824].

**Pseudocode:**
```python
def hartley_transform_1d(signal):
    """
    Computes the 1D Discrete Hartley Transform (DHT) for a real-valued signal.
    Based on the definition: H_n = sum(h_k * cas(2*pi*n*k/N))
    """
    N = len(signal)
    H = [0.0] * N
    for n in range(N):
        sum_val = 0.0
        for k in range(N):
            # cas(x) = cos(x) + sin(x)
            angle = 2.0 * 3.141592653589793 * n * k / N
            cas_val = math.cos(angle) + math.sin(angle)
            sum_val += signal[k] * cas_val
        H[n] = sum_val
    return H

def inverse_hartley_transform_1d(H):
    """
    Computes the 1D Inverse Discrete Hartley Transform (IDHT).
    Based on the definition: h_k = (1/N) * sum(H_n * cas(2*pi*n*k/N))
    """
    N = len(H)
    signal = [0.0] * N
    for k in range(N):
        sum_val = 0.0
        for n in range(N):
            angle = 2.0 * 3.141592653589793 * n * k / N
            cas_val = math.cos(angle) + math.sin(angle)
            sum_val += H[n] * cas_val
        signal[k] = sum_val / N
    return signal

def hartley_volume_rendering(volume, view_direction):
    """
    Performs volume rendering using the Hartley Transform.
    volume: 3D array of real numbers.
    view_direction: 3D vector (x, y, z) defining the projection axis.
    """
    # Step 1: Global 3D Hartley Transform
    # Note: In practice, this is often implemented via FFT for speed,
    # then converted to Hartley domain, or using a specialized 3D DHT.
    # Here we assume a direct 3D DHT implementation exists.
    F_hartley = hartley_transform_3d(volume)
    
    # Step 2: Slice Extraction
    # Extract the 2D slice from F_hartley perpendicular to view_direction.
    # This requires mapping the 3D frequency coordinates to the 2D slice plane.
    # The slice passes through the origin (0,0,0) in frequency space.
    slice_2d = extract_slice_hartley(F_hartley, view_direction)
    
    # Step 3: Inverse 2D Hartley Transform
    # Convert the 2D frequency slice back to spatial domain.
    projection = inverse_hartley_transform_2d(slice_2d)
    
    return projection
```

**Edge Cases and Pitfalls:**
*   **Precision:** The Hartley Transform uses real arithmetic, which can be more numerically stable than complex FFT for certain applications, but standard floating-point precision issues still apply [S1, unofficial].
*   **Boundary Conditions:** Like FFT, the DHT assumes periodic boundary conditions. Discontinuities at the volume boundaries can cause spectral leakage [S1, unofficial].
*   **Conversion Errors:** When converting between Hartley and Fourier domains, care must be taken with the even/odd decomposition to avoid sign errors [S1, unofficial].

## Subtopics

### [Discrete Hartley Transform](6335-discrete-hartley-transform.md)
The discrete version of the Hartley transform, defined for a sequence of $N$ real values, producing $N$ real values. It is the practical implementation used in digital volume rendering. The forward DHT is defined as $H_n = \sum_{k=0}^{N-1} h_k \cdot cas(2\pi nk/N)$ and the inverse as $h_k = \frac{1}{N} \sum_{n=0}^{N-1} H_n \cdot cas(2\pi nk/N)$. It is chosen when memory efficiency and real-valued arithmetic are prioritized over the speed of optimized complex FFT libraries. See [Discrete Hartley Transform](6335-discrete-hartley-transform.md).

## Operating characteristics
*   **Time Complexity:** The preprocessing 3D transform has a complexity of $O(N^3 \log N)$ if implemented via FFT-based conversion, or $O(N^3)$ for a direct DHT (though less common due to speed). Per-view, slice extraction is $O(N^2)$ and the 2D inverse transform is $O(N^2 \log N)$ [S1, S3].
*   **Memory Complexity:** The Hartley Transform stores only real numbers, requiring half the memory of the complex-valued Fourier Transform for the same resolution [S895]. This is a significant advantage for large volumes.
*   **Strengths:** Real-valued arithmetic simplifies implementation and reduces memory footprint. It avoids the need for complex number handling in the frequency domain [S1, unofficial].
*   **Limitations:** Direct DHT implementations are generally slower than optimized FFT libraries. The method is linear and does not support non-linear transfer functions or shading without hybrid techniques [S1, S3]. It lacks interactivity for parameters other than viewing direction [S1, unofficial].
*   **When to use:** When memory is constrained and the volume data is real-valued, and when the overhead of complex arithmetic is undesirable.
*   **When not to use:** When maximum rendering speed is critical and optimized FFT libraries are available, or when non-linear volume rendering effects are required.

## Background
The Hartley Transform was introduced by R.V.L. Hartley in 1942 as a real-valued alternative to the Fourier Transform [S1, unofficial]. In the context of volume rendering, it has been explored as a method to reduce the memory overhead associated with complex frequency domain representations [S895]. The Hartley Projection-Slice Theorem, which extends the Fourier Projection-Slice Theorem to the Hartley domain, provides the mathematical basis for using this transform in tomographic reconstruction and volume rendering [S1, unofficial].
