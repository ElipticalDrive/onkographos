# Domain-transform methods

Also called: Fourier-space techniques, frequency-domain volume rendering, alternative domain methods

## Overview
Domain-transform methods are object-order volume rendering techniques that generate projection images by transforming volumetric data from the spatial domain into an alternative domain (typically the frequency domain) [S1, unofficial][S2]. Instead of integrating along rays in space, these methods compute a global transform of the volume, extract a slice corresponding to the desired view, and inverse-transform that slice to produce the final image [S1, unofficial][S2]. This approach decouples rendering performance from dataset resolution, achieving a per-view computational complexity of $O(N^2)$ after a one-time $O(N^3 \log N)$ preprocessing step [S1, unofficial]. Unlike [Ray Casting](52-ray-casting.md) or [Digital Compositing](53-digital-compositing.md), domain-transform methods produce order-independent linear projections (attenuation-only) and do not support interactive modification of display parameters such as lighting or transparency, limiting interactivity to viewing direction changes [S1, unofficial].

## Shared principles
All domain-transform methods in this family share a common three-stage pipeline:

1.  **Global Transformation:** The entire 3D scalar volume $f(x, y, z)$ is transformed into an alternative domain representation $F(\omega_1, \omega_2, \omega_3)$ using a linear integral transform. The most common transform is the Fourier Transform, but variants use the Hartley Transform or Discrete Cosine Transform (DCT) to handle real-valued data more efficiently [S1, S2, S3, S4, S895, S5396].
2.  **Slice Extraction:** A 2D slice is extracted from the 3D transformed volume. For frequency-domain methods, this slice corresponds to a plane passing through the origin of the frequency volume and perpendicular to the viewing direction vector $V$ [S1, S3, S824]. This step exploits the Fourier Projection-Slice Theorem, which states that the 1D Fourier transform of a projection is a slice through the origin of the 3D Fourier transform of the object [S3, S824].
3.  **Inverse Transformation:** The extracted 2D slice is transformed back into the spatial domain using the inverse of the original transform (e.g., 2D Inverse FFT or Inverse Hartley Transform) to generate the final 2D projection image [S1, S3, S824].

**Mathematical Foundation:**
The core mathematical principle for Fourier-based methods is the Projection-Slice Theorem. If $P_V(u, v)$ is the projection of the volume $f(x, y, z)$ along direction $V$, and $F(\omega_1, \omega_2, \omega_3)$ is the 3D Fourier transform of $f$, then the 2D Fourier transform of $P_V$ is equal to the slice of $F$ through the origin perpendicular to $V$ [S3, S824].

**Complexity:**
*   **Preprocessing:** One-time 3D transform. Complexity is $O(N^3 \log N)$ for FFT-based methods [S1, S3].
*   **Per-View:** Slice extraction ($O(N^2)$ or $O(W^3 N^2)$ with interpolation) and 2D inverse transform ($O(N^2 \log N)$) [S1, S3, S824].

**Limitations:**
*   **Lack of Interactivity:** Parameters other than viewing direction cannot be modified interactively because the transform is global and linear [S1, unofficial].
*   **Linearity:** Standard Fourier methods produce linear projections (X-ray-like) and do not inherently support non-linear transfer functions, shading, or transparency compositing without additional approximations or hybrid techniques [S1, S3, S824].
*   **Memory:** Frequency domain representations require complex numbers (for FFT) or high-precision floating point, increasing memory usage compared to spatial domain storage [S3, S895, S952].

## Subtopics

### [Fourier Projection-Slice Volume Rendering](824-fourier-projection-slice-volume-rendering.md)
The canonical implementation using the 3D FFT and Projection-Slice Theorem. It generates attenuation-only projections. It is chosen when high-quality, order-independent linear projections are needed for large datasets where interactive parameter tweaking is not required.

### [Frequency Domain Volume Rendering](952-frequency-domain-volume-rendering.md)
A general pipeline description often implemented on GPU using 3D textures and ping-pong buffers. It emphasizes the separation of CPU-based preprocessing (3D FFT) and GPU-based rendering (slicing and 2D IFFT). It sets itself apart by detailing the hardware acceleration aspects and interpolation schemes (NN, TL, TC, Windowed Sinc) for slice extraction.

### [GPU-based 2D FFT](841-gpu-based-2d-fft.md)
A specific implementation technique for the 2D FFT component, using fragment shaders, ping-pong buffers, and lookup textures for bit-reversal and butterfly operations. It is chosen when implementing the inverse transform stage on GPU hardware to leverage parallelism.

### [Hartley Transform for Memory Reduction](895-hartley-transform-for-memory-reduction.md)
Uses the Hartley Transform instead of FFT to map real-valued data to real-valued spectra. It is chosen to reduce memory requirements by half (no complex numbers) and avoid Hermitian symmetry handling issues during slice extraction. It sets itself apart from FFT by eliminating complex arithmetic.

### [DCT-based Volume Rendering](5396-dct-based-volume-rendering.md)
Uses the Discrete Cosine Transform as the basis for domain transformation. It maps real inputs to real outputs, similar to Hartley, but uses cosine basis functions. It is chosen for applications where cosine bases are more appropriate or for specific compression-related rendering tasks.

### [Fourier Transform](2288-fourier-transform.md)
The foundational mathematical tool. It decomposes signals into frequencies. In volume rendering, it enables the convolution theorem and frequency-domain operations. It differs from siblings by being the global transform itself, not a rendering method per se, but a prerequisite for Fourier-based domain methods.

### [Hartley Transform](6324-hartley-transform.md)
The real-valued integral transform kernel. It produces real results from real inputs. It is the mathematical alternative to the complex Fourier transform used in [Hartley Transform for Memory Reduction](895-hartley-transform-for-memory-reduction.md).

### [Domain Repetition](1218-domain-repetition.md)
A technique for creating infinite periodic scenes by wrapping raymarching coordinates using modulo arithmetic. It is included in this family because it operates via coordinate transformation in the domain space, though it differs from frequency-domain methods by operating in the spatial domain during raymarching rather than transforming the volume data globally. It sets itself apart by enabling infinite tiling without geometry expansion.

### [Translation-invariant Fluorescence Rendering via Fourier Convolution](5085-translation-invariant-fluorescence-rendering-via-fourier-con.md)
A specialized model for fluorescence microscopy where the image is a convolution of fluorophore density with a Point Spread Function (PSF). It uses Fourier space for efficient convolution. It sets itself apart by modeling a specific physical imaging process (diffraction-limited PSF) rather than simple attenuation projection.

## Background
Domain-transform methods were introduced to address the high computational cost of spatial domain ray-casting ($O(N^3)$ per view) for large volumetric datasets [S1, S3]. The foundational concept relies on the Fourier Projection-Slice Theorem, which allows the computation of projections via frequency domain slicing [S3, S824]. Early work by Malzbender (1993) and others demonstrated the feasibility of frequency-domain volume rendering [S2, S13]. The approach was further developed to leverage GPU hardware, with implementations using 3D textures and ping-pong buffering for real-time interactive viewing direction changes [S1, S2, S952]. Variants like the Hartley Transform were proposed to mitigate memory and complexity issues associated with complex arithmetic in FFT [S1, S3, S895].
