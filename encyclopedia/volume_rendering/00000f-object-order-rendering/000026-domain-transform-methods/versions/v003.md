# Domain-transform methods

Also called: Fourier-space techniques, frequency-domain volume rendering, spectral volume rendering

## Overview
Domain-transform methods render volumetric data by converting it from the spatial domain into an alternative domain (typically the frequency domain, but also compression or wavelet domains) where a 2D projection slice is extracted and then transformed back to the spatial domain to form the image [S1, unofficial][S2]. This approach solves the high computational cost of spatial-domain ray-casting by decoupling rendering performance from dataset resolution, achieving a per-view complexity of $O(N^2)$ after a one-time $O(N^3 \log N)$ preprocessing step [S1, 952-frequency-domain-volume-rendering.md, unofficial]. Unlike [Ray Casting](52-ray-casting.md) or [Digital Compositing](53-digital-compositing.md), domain-transform methods inherently produce order-independent linear projections (attenuation-only images) and do not support interactive modification of display parameters such as lighting, transfer functions, or transparency [S1, 824-fourier-projection-slice-volume-rendering.md, 5396-dct-based-volume-rendering.md, unofficial].

## Shared principles
All domain-transform methods follow a three-stage pipeline: Global Transformation, Slice Extraction, and Inverse Transformation [S1, 824-fourier-projection-slice-volume-rendering.md, 895-hartley-transform-for-memory-reduction.md, 5396-dct-based-volume-rendering.md, unofficial].

1.  **Global Transformation:** The input 3D scalar volume $f(x, y, z)$ is transformed into the alternative domain to produce a 3D spectrum or coefficient array $F(\omega_1, \omega_2, \omega_3)$ [S1, unofficial][S2]. This step is performed once as a preprocessing stage [S1, 5396-dct-based-volume-rendering.md, unofficial].
    *   For frequency-domain methods, this is typically a 3D Discrete Fourier Transform (DFT) or Discrete Hartley Transform (DHT) [S1, 6324-hartley-transform.md, unofficial].
    *   The transform assumes periodic boundary conditions; therefore, zero-padding or vignetting correction is often applied to mitigate aliasing and boundary artifacts [S3, 841-gpu-based-2d-fft.md, 952-frequency-domain-volume-rendering.md].
    *   The origin of the spatial data is often shifted to the center of the volume (via `fftshift` or multiplication by $(-1)^{x+y+z}$) to center the zero-frequency component in the spectrum [S12, 2288-fourier-transform.md, 952-frequency-domain-volume-rendering.md].

2.  **Slice Extraction:** For a given viewing direction vector $V$, a 2D plane passing through the origin of the frequency domain and perpendicular to $V$ is defined [S3, 824-fourier-projection-slice-volume-rendering.md, 6324-hartley-transform.md]. The 3D spectrum is resampled onto this 2D plane to obtain a 2D slice $I(u, v)$ [S1, unofficial][S2].
    *   Since the slicing plane rarely coincides with the integer lattice of the discrete spectrum, interpolation is required [S3, 824-fourier-projection-slice-volume-rendering.md, 6324-hartley-transform.md].
    *   Common interpolation schemes include Nearest Neighbor, Trilinear, Tri-cubic, and Windowed Sinc [S2, 952-frequency-domain-volume-rendering.md].
    *   The resolution of the output image must meet the Nyquist criterion to avoid aliasing artifacts during this resampling step [S2, 952-frequency-domain-volume-rendering.md, 5396-dct-based-volume-rendering.md].

3.  **Inverse Transformation:** The extracted 2D slice is transformed back into the spatial domain using the corresponding 2D Inverse Transform (e.g., Inverse DFT, Inverse Hartley Transform, or Inverse DCT) to generate the final 2D projection image [S1, 6324-hartley-transform.md, unofficial][S2].
    *   For Inverse DFT, the result is scaled by $N^{-1}$ [S1, 952-frequency-domain-volume-rendering.md, unofficial].
    *   For Inverse Hartley Transform, the operation is identical to the forward transform scaled by $N^{-1}$ [G].

## Subtopics

### [Fourier Projection-Slice Volume Rendering](824-fourier-projection-slice-volume-rendering.md)
Uses the standard complex-valued 3D DFT and 2D IDFT. It is the foundational method for frequency-domain rendering, producing order-independent linear projections. Choose this when standard spectral analysis is required and memory is not the primary constraint.

### [GPU-based 2D FFT](841-gpu-based-2d-fft.md)
A specific implementation technique for the FFT stages, mapping the butterfly algorithm to GPU fragment shaders using ping-pong buffers and lookup textures. Choose this when implementing domain-transform methods on hardware with limited memory bandwidth or when optimizing the speed of the transform stages.

### [Hartley Transform for Memory Reduction](895-hartley-transform-for-memory-reduction.md)
Replaces the complex Fourier Transform with the real-valued Hartley Transform, reducing the memory footprint of the 3D spectrum by half (or more with 16-bit precision) compared to double-precision complex storage. Choose this when memory bandwidth or capacity is a bottleneck.

### [Frequency Domain Volume Rendering](952-frequency-domain-volume-rendering.md)
Describes the general pipeline separating CPU-based preprocessing (3D FFT) from GPU-based rendering (slicing and 2D IFFT). Choose this for a clear separation of concerns in a hybrid CPU/GPU architecture.

### [Domain Repetition](1218-domain-repetition.md)
A technique for creating infinite, periodic repetitions of an object in space by wrapping query coordinates using modulo arithmetic. Choose this for rendering periodic structures or infinite grids without increasing dataset size.

### [Fourier Transform](2288-fourier-transform.md)
The theoretical basis relying on the global spectral representation. It differs from siblings by emphasizing the mathematical definition of the DFT/IDFT and the projection-slice theorem. Choose this for understanding the underlying mathematics of spectral extraction.

### [Translation-invariant Fluorescence Rendering via Fourier Convolution](5085-translation-invariant-fluorescence-rendering-via-fourier-con.md)
Models image formation as a convolution with a Point Spread Function (PSF) in Fourier space. Unlike standard methods, it supports differentiable rendering for optimizing optical parameters and geometry. Choose this for scientific microscopy simulation and inverse problems.

### [DCT-based Volume Rendering](5396-dct-based-volume-rendering.md)
Uses the Discrete Cosine Transform (DCT) for real-valued frequency representation. Unlike Fourier and Hartley methods, it requires on-demand decompression of data blocks and does not support direct rendering from the compression domain. Choose this when working with DCT-compressed data sources.

### [Hartley Transform](6324-hartley-transform.md)
The real-valued integral transform alternative to the complex Fourier Transform. It eliminates complex arithmetic overhead while maintaining the projection-slice foundation. Choose this for simpler implementation on hardware lacking native complex number support.

## Background
Domain-transform methods, also known as Fourier-space techniques, were introduced to address the computational complexity of spatial-domain volume rendering [S1, unofficial][S2]. Early work by Malzbender [1993] and others demonstrated that projecting a volume could be achieved by extracting a slice from its 3D Fourier transform, leveraging the Projection-Slice Theorem [S1, 824-fourier-projection-slice-volume-rendering.md, unofficial]. This approach reduced the per-view complexity from $O(N^3)$ to $O(N^2)$, making interactive visualization of large datasets feasible on early graphics hardware [S1, 952-frequency-domain-volume-rendering.md, unofficial]. The family has since expanded to include variants using the Hartley Transform for memory efficiency [S1, 895-hartley-transform-for-memory-reduction.md, unofficial], the DCT for compression compatibility [S1, 5396-dct-based-volume-rendering.md, unofficial], and GPU-optimized FFT implementations [S1, 841-gpu-based-2d-fft.md, unofficial]. More recently, the framework has been extended to differentiable rendering for fluorescence microscopy [S1, 5085-translation-invariant-fluorescence-rendering-via-fourier-con.md].
