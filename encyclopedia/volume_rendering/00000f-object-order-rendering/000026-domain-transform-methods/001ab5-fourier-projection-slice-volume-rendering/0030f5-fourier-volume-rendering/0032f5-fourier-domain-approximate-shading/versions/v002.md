# Fourier Domain Approximate Shading

Also called: Fourier domain shading, Frequency domain shading

## Overview
Fourier Domain Approximate Shading approximates diffuse shading in the Fourier domain by expressing shading terms (linear, quadratic, cubic) as convolutions of the volume's Fourier transform $F$ and frequency vectors [S1]. It solves the problem of applying spatial lighting models to volume data rendered via Fourier Volume Rendering without requiring repeated 3D Fourier transforms of the shaded volume for constant light sources [S1]. Unlike [Spherical Harmonics](6052-spherical-harmonics.md), which supports efficient relighting, this method is efficient only for constant light sources because changing the light direction requires recomputing expensive full-volume convolutions [S1].

## How it works
**Inputs:**
*   $f$: The input volume data (scalar field) [S1].
*   $L = (l_1, l_2, l_3)$: The light vector, which must remain constant during the rendering pass [S1].
*   $N$: The grid dimensions for the 3D FFT [S1].

**Outputs:**
*   Rendered image slices derived from the inverse Fourier transform of the shaded frequency domain representation [S1].

**Data Structures:**
*   $F$: The 3D Fourier transform of $f$, stored as a complex array of size $N_x \times N_y \times N_z$ [S1].
*   $\Omega = (\omega_x, \omega_y, \omega_z)$: The frequency vector grid, where each element corresponds to the spatial frequency coordinates in the Fourier domain [S1].
*   $\nabla f$: The gradient magnitude volume, computed in the spatial domain [S1].

**Step-by-Step Method:**

1.  **Precompute Gradient Magnitude:**
    Compute the gradient magnitude volume $|\nabla f|$ in the spatial domain [S1]. This is used for normalization if required by the specific shading model [S1].
    $$ |\nabla f| = \sqrt{f_x^2 + f_y^2 + f_z^2} $$
    [G] The gradient components $f_x, f_y, f_z$ are typically computed using finite differences or Sobel filters in the spatial domain before transformation.

2.  **Fourier Transform:**
    Compute the 3D Fourier Transform of the original volume $f$ to obtain $F$ [S1].
    $$ F = \mathcal{F}\{f\} $$
    [G] Standard FFT libraries are used here. The result $F$ is complex-valued.

3.  **Compute Shading Term in Frequency Domain:**
    Depending on the desired shading order (Linear, Quadratic, or Cubic), compute the Fourier transform of the shading term [S1]. The core identity used to convert spatial products of derivatives into frequency domain convolutions is [S1]:
    $$ f_a f_b = \frac{1}{2}(f_a^2 + f_b^2 - f_{ab}^2) $$
    This identity allows the conversion of cross-terms like $f_x f_y$ into convolutions of squared derivatives [S1].

    **Linear Shading:**
    The linear term $\nabla f \cdot L$ is computed directly in the frequency domain without convolution [S1]:
    $$ \mathcal{T}\{ \nabla f \cdot L \} = (i\Omega \cdot L)F $$
    where $i$ is the imaginary unit, $\Omega \cdot L = \omega_x l_1 + \omega_y l_2 + \omega_z l_3$, and $F$ is the Fourier transform of $f$ [S1].

    **Quadratic Shading:**
    The quadratic term $(\nabla f \cdot L)^2$ is computed using convolutions [S1]:
    $$ \mathcal{T}\{ (\nabla f \cdot L)^2 \} = \frac{1}{2} (i\Omega \cdot L)(F \otimes F) - (F \otimes ((i\Omega \cdot L)F)) $$
    where $\otimes$ denotes 3D convolution [S1].

    **Cubic Shading:**
    The cubic term $(\nabla f \cdot L)^3$ is computed using higher-order convolutions [S1]:
    $$ \mathcal{T}\{ (\nabla f \cdot L)^3 \} = \frac{1}{6} (i\Omega \cdot L)(F \otimes F \otimes F) - \frac{1}{2} (F \otimes ((i\Omega \cdot L)(F \otimes F))) + \frac{1}{2} (F \otimes F \otimes ((i\Omega \cdot L)F)) $$

4.  **Normalization (Optional):**
    If using the normalization factor $1/|\nabla f|$ as suggested by Totsuka and Levoy, this term is precomputed in the spatial domain and can be handled via multiplication or division in the spatial domain before or after the shading calculation, depending on the specific implementation of the hemispherical reflection model [S1].

5.  **Rendering:**
    Two volumes (the original data set and its gradient magnitude volume) are sliced in the frequency domain instead of one, then inverse transformed to obtain the spatial domain image for each slice [S1].

**Pseudocode:**

```python
import numpy as np

def convolve_3d(A, B):
    """Computes 3D convolution in the frequency domain.
    Convolution in frequency domain is equivalent to pointwise multiplication 
    of the inverse Fourier transforms in the spatial domain."""
    a = np.fft.ifftn(A)
    b = np.fft.ifftn(B)
    g = a * b
    return np.fft.fftn(g)

def fourier_domain_approximate_shading(f, L, order='linear'):
    """
    Compute approximate diffuse shading in the Fourier domain.
    
    Args:
        f: Input volume data (numpy array, shape Nx, Ny, Nz)
        L: Light vector (tuple or array of 3 floats)
        order: Shading order ('linear', 'quadratic', 'cubic')
        
    Returns:
        shaded_F: Shaded volume in frequency domain (complex array)
        grad_mag: Gradient magnitude volume in spatial domain
    """
    # 1. Compute Gradient Magnitude in Spatial Domain
    fx = np.gradient(f, axis=0)
    fy = np.gradient(f, axis=1)
    fz = np.gradient(f, axis=2)
    grad_mag = np.sqrt(fx**2 + fy**2 + fz**2)
    
    # 2. Fourier Transform of the volume
    F = np.fft.fftn(f)
    
    # 3. Create Frequency Grid Omega
    Nx, Ny, Nz = f.shape
    kx = np.fft.fftfreq(Nx) * Nx * 2 * np.pi
    ky = np.fft.fftfreq(Ny) * Ny * 2 * np.pi
    kz = np.fft.fftfreq(Nz) * Nz * 2 * np.pi
    KX, KY, KZ = np.meshgrid(kx, ky, kz, indexing='ij')
    
    l1, l2, l3 = L
    i_omega_dot_L = 1j * (KX * l1 + KY * l2 + KZ * l3)
    
    # 4. Compute Shading Term based on Order
    if order == 'linear':
        shaded_F = i_omega_dot_L * F
    elif order == 'quadratic':
        conv_FF = convolve_3d(F, F)
        term1 = 0.5 * i_omega_dot_L * conv_FF
        term2 = i_omega_dot_L * F
        conv_F_term2 = convolve_3d(F, term2)
        shaded_F = term1 - conv_F_term2
    elif order == 'cubic':
        conv_FF = convolve_3d(F, F)
        conv_FFF = convolve_3d(conv_FF, F)
        part1 = (1/6) * i_omega_dot_L * conv_FFF
        
        A = i_omega_dot_L * conv_FF
        part2 = (1/2) * convolve_3d(F, A)
        
        B = i_omega_dot_L * F
        part3 = (1/2) * convolve_3d(conv_FF, B)
        
        shaded_F = part1 - part2 + part3
    else:
        raise ValueError("Order must be linear, quadratic, or cubic")
        
    return shaded_F, grad_mag
```

**Parameters:**
*   **Shading Order:** Linear, Quadratic, or Cubic [S1]. Cubic provides a better approximation of the diffuse shading term $\max(N \cdot L, 0)$ but is more expensive [S1].
*   **Light Vector $L$:** Must be constant for the entire rendering pass to avoid recomputation [S1].
*   **Normalization:** The factor $1/|\nabla f|$ can be precomputed [S1].

**Edge Cases and Pitfalls:**
*   **Dynamic Lighting:** If the light direction $L$ changes, the convolution terms in the quadratic and cubic equations must be fully recomputed because they depend on $L$ within the frequency domain operations [S1]. This prevents real-time relighting [S1].
*   **Computational Cost:** The equations require convolution with a full volume, which is computationally expensive [S1].
*   **Erroneous Energy:** Linear shading can produce significantly higher erroneous energy and excess intensity on surfaces facing away from the light compared to Gamma Corrected Hemispherical Shading (GCHS) [S1]. GCHS approximates $\max(N \cdot L, 0)$ with $(1 + N \cdot L)$, reducing these artifacts [S1].

## Operating characteristics
*   **Time Complexity:** The method requires 3D convolutions in the frequency domain, which are computationally expensive [S1].
*   **Memory Complexity:** Requires storage for the original volume $F$, the gradient magnitude, and intermediate convolution results [S1].
*   **Measured Performance:**
    *   **128^3 Synthetic Sphere:** Original FVR achieves 116 fps without depth cueing and 79 fps with depth cueing [S1]. Linear/cubic illumination achieves 98 fps without depth cueing and 64 fps with depth cueing [S1].
    *   **256^3 UNC Brain:** Original FVR achieves 27 fps without depth cueing and 17 fps with depth cueing [S1]. Linear/cubic illumination achieves 21 fps without depth cueing and 14 fps with depth cueing [S1].
    *   **Hardware:** Experiments were conducted on a Pentium 4 2.2GHz processor with 1.5GB main memory [S1].
*   **Strengths:** Efficient for constant light sources where convolution terms are precomputed; allows observer position changes without data transformation [S1].
*   **Limitations:** Not suitable for dynamic lighting due to the need to recompute convolutions; linear shading introduces excess intensity on back-facing surfaces [S1].
*   **When to Use:** When rendering with a static light source and higher-order shading (quadratic/cubic) is desired for better visual quality than simple FVR, and real-time relighting is not required [S1].
*   **When Not to Use:** When the light direction changes frequently (use [Spherical Harmonics](6052-spherical-harmonics.md) instead); when linear shading artifacts are unacceptable (use GCHS or SH) [S1].

## Background
*   **Origin:** The method was introduced in the paper "Shading For Fourier Volume Rendering" [S1].
*   **History:** It builds upon the Fourier Projection-Slice Theorem used in [Fourier Volume Rendering](6050-fourier-volume-rendering.md) [S1]. It attempts to integrate shading models (like Totsuka and Levoy's) into the Fourier domain to avoid spatial domain shading costs [S1].
*   **Usage:** Used in volume rendering applications where diffuse shading is desired and the light source is static [S1]. It serves as an alternative to [Spherical Harmonics](6052-spherical-harmonics.md) for static lighting scenarios [S1].
