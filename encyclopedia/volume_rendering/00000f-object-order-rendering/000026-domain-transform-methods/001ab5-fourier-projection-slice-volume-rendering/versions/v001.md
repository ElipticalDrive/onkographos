# Fourier Projection-Slice Volume Rendering

Also called: Attenuation-only rendering via Fourier projection-slice theorem, Fourier Volume Rendering, Fourier projection rendering, Frequency Domain Volume Rendering

## Overview
Fourier Projection-Slice Volume Rendering is a method for generating attenuation-only images (X-ray-like projections) by exploiting the Fourier projection-slice theorem to compute projections in $O(N^2 \log N)$ time per view, avoiding the $O(N^3)$ cost of digital compositing [S1, S2, S4, S5, unofficial]. Unlike conventional volume rendering or ray-casting, this method does not exhibit occlusion or hidden surface removal; it computes an order-independent linear projection where voxels on a viewing ray contribute equally regardless of distance [S3, S4, unofficial]. It is distinguished from its sibling [Domain-transform methods](28-domain-transform-methods.md) by its specific reliance on frequency-domain slicing to achieve computational efficiency for parallel projections [S1, S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A scalar volume $f(\mathbf{x})$ sampled on a 3D integer lattice of size $N \times N \times N$ [S1, S3, unofficial].
*   **Output:** A 2D projection image $I$ for a given viewing direction [S1, S2, unofficial].

**Data Structures:**
*   **3D Spectrum:** An array of $N^3$ complex coefficients (or real coefficients if using Hartley transform). Requires 32-bit floating point precision for accuracy, increasing memory by a factor of 4 compared to 8-bit input volume [S1, unofficial]. If using standard complex FFT, it requires 16 bytes per voxel (pair of 64-bit doubles) [S2, S4, S5, unofficial].
*   **2D Slice:** An array of $N^2$ coefficients extracted from the 3D spectrum [S1, unofficial].

**Parameters:**
*   $N$: Side length of the cubical volume. Assumed to be an integer power of two for FFT efficiency [S1, unofficial].
*   $V$: Normalized viewing direction vector. Defines the orientation of the slice in frequency space. Note: $V$ points away from the eye [S1, unofficial].
*   $W$: Nonzero width of the interpolating filter used during slice extraction. Typical value: 4 (4^3 tap filter) [S1, unofficial].
*   $k_2$: Factor by which volume width is increased via zero-padding. Typical value: $k_2 = 4/3$ (16% margin) [S1, unofficial].
*   $M$: Resolution of the projection slice ($M \times M$). Must be high enough to prevent aliasing [S3, unofficial].

**Steps:**

1.  **Preprocessing (Frequency Domain Transformation):**
    Compute the 3D discrete Fourier transform (DFT) of the scalar volume $f(\mathbf{x})$. For real volumes, a Discrete Hartley Transform (DHT) may be substituted to halve memory and time [S1, S3, unofficial].
    *   *Vignetting Correction:* To cope with vignetting (attenuation of the periphery due to non-ideal filter response), premultiply the volume data $f(\mathbf{x})$ by the reciprocal of the filter response $P_m(\mathbf{x}) = 1/H(\mathbf{x})$ before the forward transformation [S2, S4, S5, unofficial]. Here $H(\mathbf{s})$ is the interpolation filter in frequency space, and $h(\mathbf{x})$ is its spatial response. Specifically, $P_m(\mathbf{x}) = 1/h(\mathbf{x})$ or $1/h(1/\mathbf{x})$ depending on notation [S2, S4, S5, unofficial].
    *   *Zero Padding:* Surround the data with a margin of zeros to avoid ghosting artifacts. A typical margin is 16% ($k_2=4/3$) [S1, unofficial].

2.  **Slice Extraction (Per View):**
    For each view defined by direction $V$:
    *   Define an extraction plane passing through the origin of the frequency domain and perpendicular to $V$ [S1, S2, unofficial].
    *   Interpolate the discrete spectrum $F(\mathbf{s})$ along this plane using a filter $H(\mathbf{s})$. Since the plane does not typically pass through integer lattice points, interpolation from nearby samples is required [S1, S2, S4, unofficial].
    *   Resample the interpolated spectrum to obtain a 2D spectrum [S2, S4, S5, unofficial].

3.  **Inverse Transform:**
    Compute the inverse 2D Fourier transform (or inverse FHT) of the extracted 2D slice to generate the final projection image $I$ [S1, S2, S4, S5, unofficial].

**Formulas:**
The Fourier projection-slice theorem states that the 2D image obtained by taking line integrals of the volume along rays perpendicular to the image plane is a Fourier transform pair with the 2D spectrum obtained by extracting a slice from the Fourier transform of the volume along a plane which includes the origin and is parallel to the image plane [S4, unofficial].

Mathematically, the projection operator $\Pi_V$ is defined as [S1, unofficial]:
$$ I = \Pi_V(f) = \mathcal{F}_2^{-1} \{ \mathcal{F}_3 \{ f \} \delta_V \} $$
where $\mathcal{F}_3$ is the 3D Fourier transform, $\mathcal{F}_2^{-1}$ is the 2D inverse Fourier transform, and $\delta_V$ restricts the spectrum to a plane passing through the origin and perpendicular to viewing direction $V$ [S1, unofficial].

**Pseudocode:**

```python
def fourier_projection_slice_rendering(volume, viewing_direction):
    """
    volume: 3D numpy array of shape (N, N, N), real-valued scalar data.
    viewing_direction: 3D numpy array, normalized vector V pointing away from eye.
    Returns: 2D numpy array of shape (N, N), the projection image.
    """
    N = volume.shape[0]
    
    # 1. Preprocessing: Zero Padding and Vignetting Correction
    # Add 16% margin of zeros (k2 = 4/3)
    margin = int(N * (4/3 - 1) / 2)
    padded_volume = np.zeros((N + 2*margin, N + 2*margin, N + 2*margin))
    padded_volume[margin:-margin, margin:-margin, margin:-margin] = volume
    
    # Vignetting correction: Premultiply by reciprocal of filter response
    # Note: In practice, H(s) is the interpolation filter. 
    # h(x) is its spatial response. P_m(x) = 1/h(x).
    # For simplicity, assuming an ideal lowpass or known filter h(x) is applied.
    # [G] If h(x) is not provided, this step is skipped, leading to vignetting.
    # Here we assume a placeholder function get_filter_response(x) returns h(x).
    # To avoid division by zero, add epsilon.
    x_coords = np.arange(-margin, N + margin)
    y_coords = np.arange(-margin, N + margin)
    z_coords = np.arange(-margin, N + margin)
    X, Y, Z = np.meshgrid(x_coords, y_coords, z_coords, indexing='ij')
    # Example: Assuming a simple Gaussian or box filter response h(x) for demonstration
    # Real implementation requires the specific filter used in interpolation.
    h_response = get_filter_response(X, Y, Z) 
    h_response = np.maximum(h_response, 1e-8) # Guard against division by zero
    corrected_volume = padded_volume / h_response
    
    # 2. Forward 3D FFT
    # Use complex FFT. For real data, FHT could be used to save memory/time.
    spectrum = np.fft.fftn(corrected_volume)
    
    # 3. Slice Extraction
    # Define the plane perpendicular to viewing_direction V passing through origin.
    # The origin in the spectrum corresponds to index (N/2, N/2, N/2) in FFT output
    # if using standard fftn (zero frequency at start). 
    # np.fft.fftn puts zero freq at index 0. 
    # We need to handle coordinate systems carefully.
    # Let's assume spectrum is centered for logic, then shift back.
    
    # Create coordinate grid for the frequency domain
    # Shift spectrum so zero freq is at center for easier plane definition
    spectrum_shifted = np.fft.fftshift(spectrum)
    
    # Define grid coordinates centered at 0
    size = spectrum_shifted.shape[0]
    half_size = size // 2
    fx = np.arange(-half_size, half_size)
    fy = np.arange(-half_size, half_size)
    fz = np.arange(-half_size, half_size)
    FX, FY, FZ = np.meshgrid(fx, fy, fz, indexing='ij')
    
    # Interpolation filter H(s)
    # [G] Assuming a tricubic spline or similar high-quality filter.
    # For implementation, we interpolate values from the 3D grid onto the 2D plane.
    
    # Define the 2D plane coordinates
    # We need two basis vectors u, v perpendicular to V and each other.
    V = viewing_direction
    # Find arbitrary vector not parallel to V
    if abs(V[0]) < 0.9:
        arbitrary = np.array([1, 0, 0])
    else:
        arbitrary = np.array([0, 1, 0])
    u = np.cross(V, arbitrary)
    u = u / np.linalg.norm(u)
    v = np.cross(V, u)
    v = v / np.linalg.norm(v)
    
    # Generate 2D grid points on the plane
    # Resolution M x M. Let M = N for full resolution.
    M = N
    u_vals = np.linspace(-half_size, half_size, M)
    v_vals = np.linspace(-half_size, half_size, M)
    U_grid, V_grid = np.meshgrid(u_vals, v_vals, indexing='ij')
    
    # Convert 2D plane coordinates to 3D frequency coordinates
    # Point on plane: P = s_u * u + s_v * v
    # We need to map these to indices in FX, FY, FZ
    # Since FX, FY, FZ are in frequency bins, and u, v are unit vectors in bin space?
    # Actually, u and v are directions. The coordinates in the grid are integers.
    # We need to interpolate F(s) at points s = alpha*u + beta*v.
    
    # Reshape for interpolation
    # Points to interpolate: (M*M, 3)
    points = np.zeros((M*M, 3))
    for i in range(M):
        for j in range(M):
            points[i*M + j] = U_grid[i,j]*u + V_grid[i,j]*v
            
    # Interpolate spectrum_shifted at these points
    # Using scipy.interpolate.RegularGridInterpolator or similar
    # [G] Standard library interpolation. Assuming 'spectrum_shifted' is on a regular grid.
    # The grid coordinates are FX, FY, FZ.
    from scipy.interpolate import RegularGridInterpolator
    interp_func = RegularGridInterpolator(
        (fx, fy, fz), spectrum_shifted, method='cubic', bounds_error=False, fill_value=0
    )
    interpolated_slice_values = interp_func(points)
    
    # Reshape to 2D slice
    slice_2d = interpolated_slice_values.reshape(M, M)
    
    # 4. Inverse 2D FFT
    # The slice is in frequency domain. Inverse FFT to get spatial projection.
    projection = np.fft.ifft2(slice_2d)
    
    # Return real part (imaginary part should be near zero for real input)
    return np.real(projection)

def get_filter_response(X, Y, Z):
    """
    Placeholder for the spatial response of the interpolation filter H(s).
    In practice, this is the inverse Fourier transform of the interpolation kernel.
    For a tricubic spline, this is a specific function.
    """
    # Example: Simple box filter response for demonstration
    # Real implementation must match the interpolation filter used in step 3.
    return np.ones_like(X)
```

## Subtopics

### Implementation Details for Fourier Volume Rendering
This variant focuses on practical optimizations for the base algorithm. It involves edge enhancing and nonlinearly windowing the input data before adding a 16% margin of zeros to avoid ghosting [S1, unofficial]. Slices are extracted using a tricubic interpolating spline [S1, unofficial]. A key optimization is replacing the FFT with a Fast Hartley Transform (FHT), which halves per-view rendering time and memory requirements for real-valued data [S1, unofficial]. Further speedups can be achieved by optimizing the filter and trimming zero padding [S1, unofficial]. This implementation was tested on a 36 MHz Silicon Graphics 4D/320 VGX [S1, unofficial].

## Operating characteristics
**Time Complexity:**
*   **Preprocessing:** $O(N^3 \log N)$ operations to compute the 3D spectrum [S1, S3, unofficial].
*   **Per-View Rendering:** $O(N^2 \log N)$ operations for the inverse transform, plus $O(W^3 N^2)$ for slice extraction where $W$ is the filter width [S1, unofficial]. The overall cost is dominated by the 2D inverse FFT, $O(n^2 \log n)$ [S4, unofficial].
*   **Interpolation Cost:** High interpolation cost is a bottleneck. Interpolation is $O(n^2)$ with large constant factors, often taking more time than the FFT for practical data sizes (128^3 or 256^3) [S2, S4, unofficial].

**Memory Complexity:**
*   Requires 16 bytes per voxel (pair of 64-bit doubles) for complex arithmetic, compared to 1 byte in spatial domain algorithms [S2, S4, S5, unofficial].
*   Zero padding increases memory by a factor of $k_2^3$ [S1, unofficial].

**Performance:**
*   For $N=256$, digital compositing requires 16M operations, while FVR requires 512K operations (speedup >10x) theoretically [S1, unofficial].
*   In practice, interpolation overhead reduces this gain. GPU acceleration can achieve highly interactive framerates (factor of 17 speedup reported) [S3, unofficial].

**Strengths and Limitations:**
*   **Strengths:** Fast generation of X-ray-like projections; suitable for MR angiography and attenuation-only renderings where speed is prioritized [S1, S3, unofficial].
*   **Limitations:** No occlusion or depth cues (unless added via shading models); vignetting artifacts; ghosting artifacts from interpolation; high memory usage; only supports parallel projection [S1, S2, S3, S4, unofficial].

## Background
The method is based on the Fourier projection-slice theorem, which states that the inverse transform of a slice extracted from the frequency domain representation of a volume yields a projection of the volume in a direction perpendicular to the slice [S1, unofficial]. It was independently proposed for image synthesis by Dunne and Malzbender [S1, unofficial]. Marc Levoy published the foundational paper "Volume Rendering using the Fourier Projection-Slice Theorem" in 1992 [S1, unofficial]. Takashi Totsuka and Marc Levoy extended this in 1993 with "Frequency Domain Volume Rendering," introducing shading models in the frequency domain [S2, S4, unofficial]. Later, Viola et al. accelerated the method using GPU-based pipelines [S3, unofficial].
