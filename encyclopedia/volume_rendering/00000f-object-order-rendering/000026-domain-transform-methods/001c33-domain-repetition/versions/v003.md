# Domain Repetition
Also called: Modular repetition, Tiling via modulo

## Overview
Domain Repetition is a technique for creating infinite, periodic repetitions of an object in space by wrapping query coordinates using modulo arithmetic [S1, S2, unofficial]. It allows rendering an infinite grid of primitives "for free" by modifying the position before querying the base distance field [S4, unofficial]. Unlike [Space Repetition](1677-space-repetition.md), which repeats objects in a rectangular (Cartesian) cell structure, Domain Repetition is the foundational method often applied to specific planes (such as the xz-plane) or combined with other domain distortions [S1, S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D point $p = (p_x, p_y, p_z)$ in world space, and a repetition size (tile size) $T = (T_x, T_z)$ for the dimensions to be repeated.
*   **Output:** A transformed point $p'$ that maps the infinite space into a periodic tile, which is then passed to a base Signed Distance Field (SDF) function.

**Data Structures:**
No complex data structures are required. The method operates on scalar values and vectors.

**Steps:**
1.  **Modulo Wrapping:** Apply the modulo operation to the coordinates intended for repetition (typically $x$ and $z$). The formula is:
    $$p'_x = \text{mod}(p_x, T_x)$$
    $$p'_z = \text{mod}(p_z, T_z)$$
    [S1, S2, unofficial]
2.  **Centering:** Shift the result by $-0.5 \times T$ to center the repeated domain around the origin. This ensures the object is centered within each tile rather than aligned to the corner.
    $$p'_x = p'_x - 0.5 \times T_x$$
    $$p'_z = p'_z - 0.5 \times T_z$$
    [S1, S2, unofficial]
3.  **Evaluation:** Evaluate the base distance field function (e.g., `cube`) on the transformed point $p'$. The $y$ coordinate remains unchanged unless specific 2D tiling is desired.
    $$d = \text{base\_sdf}(p'_x, p_y, p'_z)$$
    [S1, S2, unofficial]

**Pseudocode:**
```python
def domain_repetition(p: vec3, tile_size: vec2) -> vec3:
    """
    Applies domain repetition to the x and z coordinates of point p.
    tile_size: (gx, gz) defining the period in x and z.
    """
    # Apply modulo to x and z
    p_x_mod = mod(p.x, tile_size.x)
    p_z_mod = mod(p.z, tile_size.z)
    
    # Center the result by subtracting half the tile size
    p_x_centered = p_x_mod - 0.5 * tile_size.x
    p_z_centered = p_z_mod - 0.5 * tile_size.z
    
    # Return the transformed point (y is unchanged)
    return vec3(p_x_centered, p.y, p_z_centered)

def repeated_cubes(p: vec3, tile_size: vec2) -> float:
    """
    Example: Repeated cubes in the xz-plane.
    """
    p_transformed = domain_repetition(p, tile_size)
    return cube(p_transformed)
```

**Parameters:**
*   `tile_size`: The dimensions of the repeating unit. Typical values depend on the scene scale.
*   `mod`: The modulo operator. In GLSL, `mod(a, b)` returns $a - b \times \lfloor a/b \rfloor$.

**Edge Cases and Pitfalls:**
*   **Artifacts:** Distorting the distance field can cause "nasty artifacts" during raymarching, such as incorrect normals or missed collisions. A suggested mitigation is to step shorter in the raymarching function than the distance field returns [S1, unofficial].
*   **Boundary Continuity:** The modulo operation creates discontinuities at the tile boundaries if the base SDF is not periodic or symmetric. Centering helps visually but does not guarantee $C^0$ continuity of the distance value itself across the boundary unless the base object is symmetric and centered.

## Subtopics

### [Space Repetition](1677-space-repetition.md)
Extends this concept to create infinite, periodic repetitions of an SDF in 3D space by wrapping query coordinates using modulo arithmetic. It tiles space with a rectangular (Cartesian) cell structure.

### [Polar Modulo](3358-polar-modulo.md)
Applies modulo arithmetic to the angular coordinate rather than Cartesian coordinates, enabling radial symmetry and concentric tiling.

## Operating characteristics
*   **Complexity:** $O(1)$ per raymarch step. The transformation is a constant-time arithmetic operation.
*   **Memory:** $O(1)$. No additional memory is required beyond the base SDF.
*   **Strengths:** Extremely efficient for creating infinite environments or tiled patterns without increasing memory usage or draw calls.
*   **Limitations:** Can introduce visual artifacts if the base SDF is not carefully designed for periodicity. The method assumes the base object fits within the tile size.

## Background
Domain Repetition is a technique popularized in the context of raymarching Signed Distance Fields (SDFs) for real-time graphics. It was described in blog posts and tutorials focusing on advanced SDF techniques, such as those by Inigo Quilez and community contributors [S1, S2, unofficial]. It is often used in conjunction with other domain distortions like twisting or scaling to create complex procedural scenes.
