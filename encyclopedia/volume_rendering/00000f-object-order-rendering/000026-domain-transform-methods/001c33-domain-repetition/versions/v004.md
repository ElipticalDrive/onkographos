# Domain Repetition

Also called: Modular repetition, Tiling via modulo

## Overview
Domain Repetition is a technique for creating infinite, periodic repetitions of an object in space by wrapping query coordinates using modulo arithmetic [S1, S3, S4, unofficial]. It allows rendering an infinite grid of primitives "for free" by modifying the position before querying the base signed distance field (SDF) [S4, unofficial]. Unlike [Polar Modulo](3358-polar-modulo.md), which repeats objects in a polar/cylindrical arrangement, Space Repetition tiles space with a rectangular (Cartesian) cell structure [S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D point $p = (p_x, p_y, p_z)$ in world space, and repetition grid dimensions $g_x, g_z$ for the x and z axes. The y-axis is typically left unmodified to allow vertical stacking or single-layer tiling.
*   **Output:** A transformed point $p'$ suitable for querying a base SDF, and the resulting distance value.

**Data Structures:**
*   No persistent data structures are required. The method operates on scalar values and vectors.

**Steps:**
1.  **Modulo Wrapping:** Apply the modulo operation to the x and z coordinates of the point $p$ using the grid dimensions $g_x$ and $g_z$. This maps the infinite space into a periodic interval $[0, g_x)$ and $[0, g_z)$.
2.  **Centering:** Shift the result by $-0.5 \times g$ to center the repeated domain around the origin. This ensures that the base primitive (e.g., a sphere or cube centered at the origin) is repeated symmetrically around each grid cell center.
3.  **Evaluation:** Evaluate the base distance field function (e.g., `cube`, `sphere`) on the transformed point $p'$.

**Formulas:**
The transformation for the x and z coordinates is defined as [S1, S2, unofficial]:
$$
p'_x = \text{mod}(p_x, g_x) - \frac{g_x}{2}
$$
$$
p'_z = \text{mod}(p_z, g_z) - \frac{g_z}{2}
$$
The y coordinate remains unchanged:
$$
p'_y = p_y
$$

**Parameters:**
*   $g_x, g_z$: The width and depth of the repeating cell. Typical values depend on the scene scale (e.g., 1.0 for unit cubes).

**Edge Cases and Pitfalls:**
*   **Artifacts:** Distorting the distance field can cause "nasty artifacts" during raymarching, such as incorrect normals or lighting discontinuities at tile boundaries [S1, unofficial].
*   **Mitigation:** A suggested solution is to step shorter in the raymarching function than the distance field returns to avoid overshooting across tile boundaries [S1, unofficial].
*   **Boundary Conditions:** The modulo operation assumes periodic boundary conditions. If the base SDF is not periodic or symmetric, visible seams may appear.

**Pseudocode:**
```python
def domain_repetition(p: Vector3, gx: float, gz: float) -> Vector3:
    """
    Transforms point p by repeating it in the xz-plane with grid sizes gx and gz.
    """
    # Apply modulo and center the result
    # Note: GLSL mod(a, b) returns a - b * floor(a/b)
    p_x = mod(p.x, gx) - gx * 0.5
    p_z = mod(p.z, gz) - gz * 0.5
    p_y = p.y
    
    return Vector3(p_x, p_y, p_z)

def repeated_cubes(p: Vector3) -> float:
    """
    Example: Repeated cubes in the xz-plane with grid size 1.0.
    """
    transformed_p = domain_repetition(p, 1.0, 1.0)
    return cube(transformed_p)
```

## Subtopics

### [Space Repetition](1677-space-repetition.md)
Space Repetition is a domain-transform technique that creates infinite, periodic repetitions of a signed distance field (SDF) in 3D space by wrapping query coordinates using modulo arithmetic. It allows rendering an infinite grid of primitives "for free" by modifying the position before querying the base SDF. Unlike [Polar Modulo](3358-polar-modulo.md), which repeats objects in a polar/cylindrical arrangement, Space Repetition tiles space with a rectangular (Cartesian) cell structure.

### [Polar Modulo](3358-polar-modulo.md)
Polar Modulo repeats a 2D pattern around the origin by a fixed angle determined by the number of repetitions. It builds on [Domain Repetition](1218-domain-repetition.md) by applying modulo arithmetic to the angular coordinate rather than Cartesian coordinates, enabling radial symmetry. Unlike [Space Repetition](1677-space-repetition.md) which tiles in linear space, Polar Modulo creates concentric or angular sectors.

## Operating characteristics
*   **Time Complexity:** $O(1)$ per raymarch step. The modulo and arithmetic operations are constant time.
*   **Memory Complexity:** $O(1)$. No additional memory is required beyond the base SDF evaluation.
*   **Strengths:** Extremely efficient for creating infinite environments or tiled patterns without increasing geometric complexity.
*   **Limitations:** Can introduce visual artifacts at tile boundaries if not handled carefully (e.g., via smaller raymarch steps) [S1, unofficial]. The distance field is no longer globally smooth, which may affect gradient-based operations like normals if not computed carefully.
*   **When to use:** When rendering infinite grids, tiled floors, or periodic structures.
*   **When not to use:** When global smoothness or non-periodic boundaries are required.

## Background
Domain Repetition is a technique popularized in the context of raymarching signed distance fields (SDFs) for real-time graphics. It was described in early blog posts and tutorials on procedural geometry generation [S1, S2, unofficial]. The method leverages the mathematical property of the modulo operator to map infinite space onto a finite repeating domain.
