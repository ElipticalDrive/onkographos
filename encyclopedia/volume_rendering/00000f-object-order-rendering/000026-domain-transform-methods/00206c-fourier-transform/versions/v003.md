# Fourier Transform
Also called: Discrete Fourier Transform

## Overview
The Fourier Transform method renders a 3D volume by converting the spatial data into the frequency domain, extracting a 2D slice corresponding to the viewing direction, and transforming it back to the spatial domain to produce a projection image [S1, S2, 824-fourier-projection-slice-volume-rendering.md, unofficial]. It differs from its siblings by relying on the global spectral representation of the volume, which enables efficient convolution-based operations but inherently produces order-independent linear projections without support for transparency or interactive lighting [S3, 824-fourier-projection-slice-volume-rendering.md].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar volume $f(x, y, z)$ of dimensions $N_x \times N_y \times N_z$.
*   **Output:** A 2D projection image $I(u, v)$ corresponding to a specific viewing direction.

**Data Structures:**
*   **Volume:** A 3D array of floating-point values representing voxel densities.
*   **Spectrum:** A 3D complex-valued array $F(\omega_1, \omega_2, \omega_3)$ resulting from the 3D Discrete Fourier Transform (DFT).
*   **Slice:** A 2D complex-valued array extracted from the spectrum.

**Parameters:**
*   $N$: Number of samples per dimension. Assumed to be even for standard frequency point derivation [S2, unofficial].
*   $\Delta$: Sampling interval (spatial distance between consecutive samples) [S2, unofficial].
*   $f_c$: Nyquist critical frequency, defined as $1/(2\Delta)$ [S2, unofficial].

**Steps:**

1.  **Global Transformation:** Compute the 3D DFT of the input volume $f(x, y, z)$ to obtain the 3D spectrum $F(\omega_1, \omega_2, \omega_3)$. The DFT is defined as:
    $$H_n = \sum_{k=0}^{N-1} h_k e^{2\pi i k n/N}$$
    where $h_k$ are the input samples and $H_n$ are the frequency coefficients [S2, unofficial]. For a 3D volume, this is applied separably across all three dimensions. The frequency points are mapped as $f_n = \frac{n}{N\Delta}$ for $n = -\frac{N}{2}, \dots, \frac{N}{2}$ [S2, unofficial].

2.  **Centering (Optional but Recommended):** To center the zero-frequency component at the origin of the spectrum, multiply the spatial domain data by $(-1)^{x+y+z}$ before computing the 3D DFT [S2, unofficial]. This avoids discontinuity artifacts at the boundaries of the standard DFT output range.

3.  **Slice Extraction:** For a given viewing direction vector $V$, define a 2D plane passing through the origin of the frequency volume and perpendicular to $V$. Extract the values of the spectrum $F$ on this plane. Since the plane rarely coincides with the integer lattice of the discrete spectrum, interpolation (resampling) is required to estimate the complex values at the non-integer coordinates [S3, 824-fourier-projection-slice-volume-rendering.md].

4.  **Inverse Transformation:** Compute the 2D Inverse Discrete Fourier Transform (IDFT) of the extracted slice to generate the final 2D projection image. The IDFT is defined as:
    $$h_k = \frac{1}{N} \sum_{n=0}^{N-1} H_n e^{-2\pi i k n/N}$$
    [S2, unofficial].

**Pseudocode:**

```python
import numpy as np

def fourier_transform_render(volume, view_direction, resolution):
    """
    Renders a 2D projection of a 3D volume using the Fourier Transform method.
    
    Args:
        volume: 3D numpy array of shape (Nx, Ny, Nz) representing the scalar field.
        view_direction: 3D numpy array (vx, vy, vz) representing the camera viewing vector.
        resolution: Tuple (width, height) for the output image.
        
    Returns:
        2D numpy array of shape (width, height) representing the projection.
    """
    # Step 1: Global Transformation
    # Apply centering shift: multiply by (-1)^(x+y+z)
    Nx, Ny, Nz = volume.shape
    x = np.arange(Nx).reshape(-1, 1, 1)
    y = np.arange(Ny).reshape(1, -1, 1)
    z = np.arange(Nz).reshape(1, 1, -1)
    
    centered_volume = volume * ((-1) ** (x + y + z))
    
    # Compute 3D DFT using FFT
    spectrum = np.fft.fftn(centered_volume)
    
    # Step 2: Slice Extraction
    # Define the 2D plane in frequency space perpendicular to view_direction
    # The plane passes through the origin (0,0,0) in frequency coordinates.
    # We need to map the output image coordinates (u, v) to frequency coordinates (fx, fy, fz).
    
    # Create coordinate grids for the output image
    u = np.linspace(-0.5, 0.5, resolution[0]) * Nx
    v = np.linspace(-0.5, 0.5, resolution[1]) * Ny
    U, V = np.meshgrid(u, v, indexing='ij')
    
    # Determine two orthogonal basis vectors for the plane
    # Let view_direction be normalized
    v_dir = view_direction / np.linalg.norm(view_direction)
    
    # Find a vector not parallel to v_dir to compute the first basis vector
    if abs(v_dir[0]) < 0.9:
        ref = np.array([1, 0, 0])
    else:
        ref = np.array([0, 1, 0])
        
    basis1 = np.cross(v_dir, ref)
    basis1 = basis1 / np.linalg.norm(basis1)
    basis2 = np.cross(v_dir, basis1)
    basis2 = basis2 / np.linalg.norm(basis2)
    
    # Map image coordinates (u, v) to 3D frequency coordinates
    # fx, fy, fz are linear combinations of u and v along the basis vectors
    fx = U * basis1[0] + V * basis2[0]
    fy = U * basis1[1] + V * basis2[1]
    fz = U * basis1[2] + V * basis2[2]
    
    # Interpolate the spectrum at these coordinates
    # Note: np.fft.fftfreq returns frequencies in cycles per unit. 
    # The indices in the spectrum array correspond to integer indices.
    # We need to interpolate in the index space of the spectrum array.
    
    # Shift spectrum so that zero frequency is at (0,0,0) for easier interpolation logic
    # fftshift moves the zero-frequency component to the center
    spectrum_shifted = np.fft.fftshift(spectrum)
    
    # The coordinates fx, fy, fz are in "cycles" relative to the volume size.
    # In the shifted spectrum array, the center is at (Nx/2, Ny/2, Nz/2).
    # The indices in the shifted array correspond to frequency bins.
    # We need to map fx, fy, fz to indices in the shifted array.
    # Index = Frequency * N + N/2 (approximate mapping for interpolation)
    
    idx_x = fx * Nx + Nx / 2
    idx_y = fy * Ny + Ny / 2
    idx_z = fz * Nz + Nz / 2
    
    # Perform 3D interpolation on the shifted spectrum
    # Using scipy.ndimage.map_coordinates for simplicity in pseudocode
    from scipy.ndimage import map_coordinates
    
    # Coordinates must be in the order [axis0, axis1, axis2]
    # map_coordinates expects coordinates in the same order as the array dimensions
    coords = np.array([idx_z, idx_y, idx_x]) # Note: fftn output order is (0,1,2) -> (x,y,z) usually, but let's assume standard (z,y,x) for map_coordinates if volume is (z,y,x)
    # Correction: volume is (Nx, Ny, Nz). fftn output is (Nx, Ny, Nz).
    # fftshift shifts all axes.
    # map_coordinates expects coordinates for each axis.
    
    # Re-evaluating coordinate mapping for standard numpy array (Nx, Ny, Nz)
    # fx corresponds to axis 0, fy to axis 1, fz to axis 2.
    coords = np.array([idx_x, idx_y, idx_z])
    
    # Extract complex values
    slice_complex = map_coordinates(spectrum_shifted, coords, order=1, mode='constant', cval=0+0j)
    
    # Step 3: Inverse Transformation
    # Compute 2D IDFT of the extracted slice
    # The slice is now a 2D array of complex numbers
    projection = np.fft.ifft2(slice_complex)
    
    # Return the real part of the projection (imaginary part should be near zero for real input)
    return np.real(projection)
```

**Edge Cases and Pitfalls:**
*   **Aliasing:** If the volume is not zero-padded, the periodicity assumption of the FFT can cause ghosting artifacts [S3, 841-gpu-based-2d-fft.md].
*   **Nyquist Criterion:** The resolution of the output image must meet the Nyquist criterion to avoid aliasing during slice extraction [S2, 952-frequency-domain-volume-rendering.md, unofficial].
*   **Hermitian Symmetry:** The DFT of a real function is Hermitian ($H_{N-n}^* = H_n$). This redundancy can be exploited for memory savings but must be handled correctly during interpolation [S2, unofficial].

## Subtopics

### Windowed Fourier Transform
Unlike the standard Fourier transform which covers the whole spatial domain and is not spatially localized, the windowed Fourier transform uses a translated window to cover the whole signal, allowing localization of irregularities [S1, unofficial]. It is chosen when spatial localization of frequency information is required, at the cost of increased computational complexity and reduced frequency resolution.

### Centered DFT
A method to compute the DFT of a real signal such that the frequency spectrum is centered (zero frequency at the center), avoiding the discontinuity at the boundaries of the standard DFT output range [S2, unofficial]. It is implemented by multiplying each element $h_k$ by $(-1)^k$ (1D) or $(-1)^{x+y}$ (2D) before computing the DFT [S2, unofficial]. It is chosen when visualizing or processing the spectrum requires the zero-frequency component to be at the origin.

## Operating characteristics
**Time and Memory Complexity:**
*   **Preprocessing:** The global transformation step typically costs $O(N^3 \log N)$ using Fast Fourier Transform algorithms, where $N$ is the volume dimension [S3, 2288-fourier-transform.md].
*   **Per-View Rendering:** The cost is dominated by the 2D slice extraction and inverse transform, resulting in $O(N^2)$ complexity per view [S1, 952-frequency-domain-volume-rendering.md, unofficial].
*   **Memory:** The 3D spectrum requires $O(N^3)$ memory. For real-valued inputs, Hermitian symmetry allows storing only $N^3/2$ complex numbers [S2, unofficial].

**Measured Performance:**
Performance depends heavily on the efficiency of the FFT implementation and the interpolation method used for slice extraction. GPU-based implementations can significantly accelerate the FFT and interpolation steps [841-gpu-based-2d-fft.md].

**Strengths and Limitations:**
*   **Strengths:** Efficient global transformation; suitable for convolution-based operations; order-independent rendering.
*   **Limitations:** No support for transparency or alpha blending; fixed parameters (no interactive transfer functions or lighting); prone to aliasing and ghosting artifacts if not properly padded or sampled [S3, 824-fourier-projection-slice-volume-rendering.md, S1, 5396-dct-based-volume-rendering.md, unofficial].

**When to Use:**
Use when rendering static, linear projections of large volumes where performance is critical and transparency/lighting are not required.

**When Not to Use:**
Do not use when interactive exploration, transparency, or complex shading models are needed.

## Background
The Fourier Transform is a classical theory for multiresolution decomposition [S1, unofficial]. It provides a measure of high-frequency information but is not spatially localized, making it difficult to find the position of irregularities [S1, unofficial]. In volume rendering, it was adapted to exploit the Convolution Theorem, which states that the Fourier transform of the convolution of two functions is equal to the product of their individual Fourier transforms [S2, unofficial]. This allows for efficient computation of projections and other volume operations in the frequency domain.
