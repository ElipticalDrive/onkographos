# Anisotropic Noise

Also called: Goldberg et al. noise, Oriented Band Filtering, Oriented subband noise

## Overview
Anisotropic noise is a procedural noise function designed to support high-quality anisotropic filtering, addressing the trade-off between aliasing artifacts and detail loss inherent in isotropic noise methods [S1]. It partitions the frequency domain into oriented subbands using steerable filters, allowing the noise content to adapt to non-uniform perspective distortions and parametric surface distortions by adjusting subband weights during rendering [S1].

## How it works
**Inputs:**
- Pre-computed oriented noise subband textures.
- Surface position and derivative information (Jacobian) to determine local anisotropic filter characteristics.

**Outputs:**
- A scalar noise value for a given 3D or 2D location.

**Data Structures:**
- **Subband Textures:** Each oriented subband is stored in a 32-bit RGBA image. Four orientations are packed into the R, G, B, and A channels of a single texture [S1].
- **Scale:** Subbands are precomputed at a single scale. Other scales are generated on-the-fly by scaling the texture coordinates [S1].

**Algorithm:**

1.  **Preprocessing (Offline):**
    1.  Partition the frequency domain using steerable filters [SF95, PS00] to create oriented subbands that are tightly localized in scale and orientation [S1].
    2.  Synthesize noise tiles for each subband. The construction ensures the filters implement an invertible transform, allowing exact signal recovery [S1].
    3.  Pack each oriented subband image into one channel of a 32-bit RGBA image. This yields four orientations per texture [S1].
    4.  Typically, use four or eight bands (one or two textures) to balance storage, speed, and quality [S1].

2.  **Runtime (Per-Pixel/Per-Point):**
    1.  Determine the local anisotropic filter requirements based on the surface geometry (e.g., parametric distortion or perspective projection) [S1].
    2.  Compute the appropriate weighted combination of the oriented subbands at the current location. The weights are adapted with respect to the anisotropic filter to approximate the desired frequency spectrum on the surface [S1].
    3.  Sample the pre-computed subband textures at the scaled coordinates.
    4.  Compute the final noise value as the weighted sum of the sampled subband values [S1].

**Pseudocode:**

```python
def evaluate_anisotropic_noise(x, y, weights):
    """
    Evaluates anisotropic noise at (x, y) using pre-computed subband textures.
    
    Args:
        x, y: Coordinates in the texture space (scaled for desired frequency).
        weights: A list of 4 floating-point weights [w_r, w_g, w_b, w_a] 
                 corresponding to the four oriented subbands packed in RGBA.
                 These weights are derived from the local anisotropic filter 
                 characteristics.
    
    Returns:
        float: The final noise value.
    """
    # Sample the four oriented subbands from the packed RGBA texture
    # Note: In a real implementation, texture sampling handles interpolation.
    # Here we assume a function `sample_texture(u, v)` that returns RGBA.
    rgba = sample_texture(x, y)
    
    r = rgba.r
    g = rgba.g
    b = rgba.b
    a = rgba.a
    
    # Compute weighted sum
    noise_value = (r * weights[0] + 
                   g * weights[1] + 
                   b * weights[2] + 
                   a * weights[3])
    
    return noise_value
```

**Parameters:**
- **Number of Bands:** Typically 4 or 8 bands (1 or 2 textures) [S1].
- **Scale:** Precomputed at a single scale; other scales are handled by texture coordinate scaling [S1].

**Edge Cases and Pitfalls:**
- **Precision:** The method relies on linear interpolation of filters to avoid artifacts when blending subbands [S1].
- **Boundaries:** The invertible transform property ensures exact recovery, but practical implementation must handle texture wrapping correctly [S1].
- **Degenerate Input:** If the surface has no anisotropy (isotropic), the weights should be uniform or adjusted to match isotropic filtering requirements [S1].

## Operating characteristics
- **Time Complexity:** Runtime is efficient, involving a weighted sum of a few texture samples (typically 4-8) per pixel [S1].
- **Memory Complexity:** Storage is proportional to the number of subbands. Four or eight bands (1-2 RGBA textures) provide a good trade-off [S1].
- **Performance:** High-quality anisotropic filtering with minimal aliasing on tilted surfaces [S1].
- **Strengths:** Adapts to non-uniform perspective distortions and parametric surface distortions [S1].
- **Limitations:** Requires pre-computation of oriented subbands [S1].

## Background
Anisotropic noise was introduced by Goldberg et al. in 2008 [GZD08] [S1]. It builds on the concept of wavelet noise [CD05] but extends it to support anisotropic filtering, which existing isotropic noise functions could not handle without compromising between aliasing and blurring [S1]. The method uses steerable filters [SF95, PS00] to partition the frequency domain into oriented subbands [S1].
