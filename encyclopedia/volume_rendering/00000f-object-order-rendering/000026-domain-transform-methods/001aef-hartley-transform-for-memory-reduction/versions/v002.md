# Hartley Transform for Memory Reduction

Also called: Hartley Transform for Frequency Domain Volume Rendering, Hartley Transform for Real-Valued Spectra, Hartley-based Volume Rendering, Real-valued Fourier Transform, Real-valued frequency domain rendering

## Overview
The Hartley Transform for Memory Reduction is a technique for frequency-domain volume rendering that replaces the standard Fourier Transform with the Hartley Transform to map real-valued spatial data directly to real-valued spectral data [S1, S2, S4, unofficial]. This eliminates the need for complex number arithmetic, thereby reducing memory requirements by half compared to storing complex Fourier spectra [S1, S2, S4, unofficial]. Unlike standard Fourier methods which require complex storage or complicate slice extraction by dropping half the spectrum due to Hermitian symmetry, the Hartley Transform provides a symmetric, real-valued spectrum that simplifies the slice extraction process [S1, S3, unofficial]. It builds on [Domain-transform methods](28-domain-transform-methods.md) by providing the specific mathematical and storage optimizations that enable efficient frequency-domain rendering.

## How it works
The method operates within the three-stage pipeline of domain-transform methods: Global Transformation, Slice Extraction, and Inverse Transformation [S1, S3, S824]. The core innovation lies in the choice of transform and data representation to minimize memory footprint without significant loss of visual fidelity.

### Inputs and Outputs
*   **Input:** A 3D scalar volume $f(x, y, z)$ of size $N \times N \times N$.
*   **Output:** A 2D projection image $P(u, v)$ for a given viewing direction.
*   **Intermediate:** A 3D real-valued frequency spectrum $F_H(\omega_1, \omega_2, \omega_3)$.

### Data Structures
The frequency spectrum is stored as a 3D array of real numbers. To optimize memory, a custom 16-bit floating-point format is used [S1, S4, unofficial].
*   **Standard Format:** 64-bit double precision is considered safe for a $256^3$ volume due to the wide dynamic range of spectra [S1, unofficial]. However, this occupies 8 times more memory than the original spatial volume (assuming 1-byte voxels) [S1, unofficial].
*   **Optimized Format:** A 16-bit floating-point format is defined and used to represent the spectrum [S1, unofficial]. This reduces the memory cost factor to 2 relative to the original spatial volume [S1, unofficial].
*   **Comparison:** A standard double-precision complex Fourier transform would require 16 times more memory than the spatial domain algorithm [S4, unofficial]. The Hartley transform with 16-bit storage reduces this requirement significantly [S1, S4, unofficial].

### Mathematical Definition
The Hartley Transform $H\{f\}(s)$ of a real function $f(x)$ is defined as [S2, S3, S4, unofficial]:

$$
F_H(s) = \int_{-\infty}^{+\infty} f(x) \text{cas}(2\pi s x) \, dx
$$

where the kernel $\text{cas}(\theta)$ is defined as [S2, S3, S4, unofficial]:

$$
\text{cas}(\theta) = \cos(\theta) + \sin(\theta)
$$

For the 3D volume $f(x, y, z)$, the 3D Hartley Transform is applied. Since the kernel is real, the transform maps the real function $f(x, y, z)$ to a real spectrum $F_H(\omega_1, \omega_2, \omega_3)$ [S1, S2, S4, unofficial].

### Algorithm Steps

1.  **Preprocessing (Global Transformation):**
    Apply the 3D Hartley Transform to the input volume $f(x, y, z)$ to obtain the frequency spectrum $F_H(\omega_1, \omega_2, \omega_3)$.
    *   *Note:* The sources mention "premultiplying the volume before transforming" as a consideration for precision [S1, unofficial], but do not specify the exact operation. [G] Typically, this may involve windowing or scaling to manage dynamic range, but the specific operation is not defined in the provided text.

2.  **Slice Extraction:**
    For a given viewing direction vector $V$, extract a 2D slice from the 3D frequency spectrum $F_H$. This slice corresponds to a plane passing through the origin of the frequency volume and perpendicular to $V$ [S1, S3, S824].
    *   Interpolation and resampling are performed on the frequency spectrum corresponding to the current view plane [S1, unofficial].
    *   Adaptive filtering is used to reduce the cost of interpolation [S1, unofficial]. The scheme reduces the cost of interpolation to about 15% of the non-adaptive case [S1, unofficial].
    *   The relative error between adaptive filtering and the non-adaptive case is always below 40dB, a level at which image differences are not visible [S1, unofficial].

3.  **Inverse Transformation:**
    Apply the 2D Inverse Hartley Transform to the extracted slice data to return to the spatial domain, generating the final 2D projection image [S1, S3, unofficial].
    *   Format conversion to and from the 16-bit floating-point format and the machine's native format is performed [S1, unofficial].

### Pseudocode

```python
def hartley_transform_volume_rendering(volume_3d, view_direction):
    """
    Renders a 3D volume using the Hartley Transform for memory reduction.
    
    Args:
        volume_3d: 3D array of shape (N, N, N) representing the spatial domain volume.
        view_direction: 3D vector (vx, vy, vz) representing the viewing direction.
        
    Returns:
        2D array representing the rendered projection image.
    """
    N = volume_3d.shape[0]
    
    # Step 1: Global Transformation
    # Apply 3D Hartley Transform to convert spatial volume to real-valued frequency spectrum.
    # The result is stored in 16-bit floating point format to reduce memory usage.
    # Note: The specific implementation of the 3D Hartley Transform (e.g., separable 1D transforms)
    # is assumed to be available. The sources do not provide the FFT-like algorithm details for FHT.
    frequency_spectrum_3d = compute_3d_hartley_transform(volume_3d)
    
    # Step 2: Slice Extraction
    # Extract a 2D slice from the 3D frequency spectrum corresponding to the view direction.
    # This slice is a plane through the origin perpendicular to view_direction.
    # Interpolation and resampling are required.
    # Adaptive filtering is applied to reduce interpolation cost.
    frequency_slice_2d = extract_slice_adaptive(frequency_spectrum_3d, view_direction)
    
    # Step 3: Inverse Transformation
    # Apply 2D Inverse Hartley Transform to the slice to get the projection image.
    projection_image = compute_2d_inverse_hartley_transform(frequency_slice_2d)
    
    return projection_image

def compute_3d_hartley_transform(volume):
    """
    Computes the 3D Hartley Transform of a real-valued volume.
    Returns a real-valued 3D spectrum.
    """
    # The Hartley Transform is separable.
    # H{f}(u, v, w) = H_x{ H_y{ H_z{ f(x, y, z) } } }
    # Apply 1D Hartley Transform along each axis.
    
    # Apply along Z axis
    temp = apply_1d_hartley_along_axis(volume, axis=2)
    # Apply along Y axis
    temp = apply_1d_hartley_along_axis(temp, axis=1)
    # Apply along X axis
    spectrum = apply_1d_hartley_along_axis(temp, axis=0)
    
    return spectrum

def apply_1d_hartley_along_axis(data, axis):
    """
    Applies the 1D Hartley Transform along a specified axis.
    """
    # The 1D Hartley Transform kernel is cas(2*pi*u*x) = cos(2*pi*u*x) + sin(2*pi*u*x)
    # For discrete data of size N, the transform is:
    # H[u] = sum_{x=0}^{N-1} f[x] * cas(2*pi*u*x/N)
    # This can be computed efficiently using a Fast Hartley Transform (FHT) algorithm.
    # The sources do not provide the FHT algorithm details.
    # [G] A standard FHT algorithm (e.g., based on butterfly operations) would be used here.
    # For the purpose of this article, we assume a function `fast_hartley_transform` exists.
    return fast_hartley_transform(data, axis=axis)

def extract_slice_adaptive(spectrum_3d, view_direction):
    """
    Extracts a 2D slice from the 3D frequency spectrum using adaptive filtering.
    """
    # Determine the 2D plane in the frequency domain perpendicular to view_direction.
    # Interpolate the 3D spectrum onto this 2D plane.
    # Adaptive filtering selects smaller filters for regions where the signal is smooth,
    # reducing computational cost.
    # The relative error is kept below 40dB.
    slice_2d = interpolate_3d_to_2d(spectrum_3d, view_direction, adaptive=True)
    return slice_2d

def compute_2d_inverse_hartley_transform(slice_2d):
    """
    Computes the 2D Inverse Hartley Transform.
    The inverse Hartley Transform is similar to the forward transform,
    with a normalization factor of 1/N^2.
    """
    # Apply 2D Inverse Hartley Transform
    # H^{-1}{F}(x, y) = (1/N^2) * sum_{u=0}^{N-1} sum_{v=0}^{N-1} F(u, v) * cas(2*pi*(u*x + v*y)/N)
    image = fast_hartley_transform(slice_2d, axis=0, inverse=True)
    image = fast_hartley_transform(image, axis=1, inverse=True)
    # Normalize
    N = image.shape[0]
    image = image / (N * N)
    return image
```

### Parameters and Typical Values
*   **Precision:** 16-bit floating-point format is used for the spectrum [S1, unofficial]. This reduces memory cost by a factor of 2 compared to the original volume size (if 1-byte voxels) and 8 times less than 64-bit double precision [S1, unofficial].
*   **Error Bounds:**
    *   Round-off error from 16-bit floating-point format results in a relative difference below 50dB compared to 64-bit double precision images [S1, unofficial].
    *   Adaptive filtering relative error is below 40dB [S1, unofficial].
*   **Volume Size:** Examples include $128^3$ (human head CT) and $256^3$ (Utah teapot, turbine blade) [S1, unofficial].

### Edge Cases and Pitfalls
*   **Hermitian Symmetry:** Standard Fourier transforms of real signals exhibit Hermitian symmetry, allowing storage of only half the spectrum. However, dropping half the spectrum complicates slice extraction [S1, S3, unofficial]. The Hartley Transform avoids this complexity by mapping real functions to real spectra directly [S1, S3, unofficial].
*   **Dynamic Range:** Spectra have a wide dynamic range, necessitating floating-point representation [S1, unofficial]. Using insufficient precision (e.g., 8-bit) may lead to visible artifacts, though 16-bit was found to be sufficient with <50dB error [S1, unofficial].
*   **Interpolation Cost:** Slice extraction requires interpolation. Non-adaptive interpolation is expensive. Adaptive filtering is recommended to reduce cost to ~15% of non-adaptive cases [S1, unofficial].

## Operating characteristics
*   **Time Complexity:**
    *   **Preprocessing:** One-time 3D Hartley Transform. Complexity is $O(N^3 \log N)$, similar to FFT-based methods [S1, S3, unofficial].
    *   **Per-View:** Slice extraction ($O(N^2)$ or $O(W^3 N^2)$ with interpolation) and 2D inverse Hartley Transform ($O(N^2 \log N)$) [S1, S3, S824].
    *   **Comparison:** The frequency domain method grows at $O(N^2 \log N)$ for projection, and $O(N^2)$ for shading/depth cueing, which is much slower growth than the spatial domain method's $O(N^3)$ [S1, unofficial].
*   **Memory Complexity:**
    *   The Hartley Transform produces real-valued spectra, reducing memory requirements by half compared to complex Fourier spectra [S1, S2, S4, unofficial].
    *   Using 16-bit floating-point format further reduces memory usage, making it comparable to or only slightly larger than the spatial domain storage [S1, unofficial].
*   **Measured Performance:**
    *   Rendering times were measured on an IRIS Crimson with a 50MHz R4000 processor [S1, unofficial].
    *   For a $128^3$ volume, frequency domain rendering took 0.54 seconds, while spatial domain took 1.77 seconds [S1, unofficial].
    *   For a $256^3$ volume, frequency domain rendering took 2.03 seconds, while spatial domain took 24.29 seconds [S1, unofficial].
    *   Adaptive filtering reduced interpolation cost to about 15% of the non-adaptive case [S1, unofficial].
*   **Strengths:**
    *   Significant memory reduction compared to Fourier-based methods [S1, S2, S4, unofficial].
    *   Faster rendering for large volumes compared to spatial domain methods [S1, unofficial].
    *   Simplified slice extraction compared to Fourier methods with Hermitian symmetry handling [S1, S3, unofficial].
*   **Limitations:**
    *   Lack of interactivity: Parameters other than viewing direction cannot be modified interactively because the transform is global and linear [S1, unofficial].
    *   Linearity: Standard methods produce linear projections and do not inherently support non-linear transfer functions, shading, or transparency compositing without additional approximations or hybrid techniques [S1, S3, S824].
    *   Requires adaptive filtering to manage interpolation cost effectively [S1, unofficial].

## Background
The Hartley Transform for Memory Reduction was introduced by Takashi Totsuka and Marc Levoy in their 1993 paper "Frequency Domain Volume Rendering" [S1, S2, S3, S4, unofficial]. The work was presented at SIGGRAPH 1993 [S1, unofficial]. The method was used to render human head CT data, the Utah teapot, and a turbine blade volume with shading and depth cueing [S1, unofficial]. The data for the human head was courtesy of North Carolina Memorial Hospital [S1, unofficial]. The technique addresses the memory explosion problem associated with frequency-domain volume rendering by leveraging the real-valued nature of the Hartley Transform and compact floating-point representations [S1, S4, unofficial].
