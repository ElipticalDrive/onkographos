# Hartley Transform for Memory Reduction

Also called: Hartley Transform for Frequency Domain Volume Rendering, Hartley Transform for Real-Valued Spectra, Hartley-based Volume Rendering, Real-valued Fourier Transform, Real-valued frequency domain rendering

## Overview
The Hartley Transform for Memory Reduction is a frequency-domain volume rendering technique that replaces the standard Fourier transform with the Hartley transform to map real-valued spatial data directly to real-valued frequency spectra [S1, S2, S4, unofficial]. This substitution eliminates the need for complex number arithmetic, thereby reducing the memory footprint of the 3D spectrum by half compared to a standard double-precision complex Fourier transform [S1, S2, S4, unofficial]. It sets itself apart from standard Fourier-based methods by avoiding the complexity of handling Hermitian symmetry during slice extraction, which is required when storing only half the spectrum of a real signal [S1, S3, unofficial]. It builds on [Domain-transform methods](28-domain-transform-methods.md) by providing the specific spectral representation and memory optimization strategies for the global transformation and slice extraction stages.

## How it works
The method follows the three-stage pipeline of [Domain-transform methods](28-domain-transform-methods.md): Global Transformation, Slice Extraction, and Inverse Transformation [S1, S3, 824-fourier-projection-slice-volume-rendering.md, unofficial].

### Inputs and Outputs
*   **Input:** A 3D scalar volume $f(x, y, z)$ of dimensions $N_x \times N_y \times N_z$, typically zero-padded to a power-of-two size for efficient Fast Hartley Transform (FHT) computation.
*   **Output:** A 2D projection image $I(u, v)$ corresponding to a specific viewing direction.

### Data Structures
*   **Spatial Volume:** Stored in native format (e.g., 8-bit or 16-bit integer/float).
*   **Frequency Spectrum:** Stored as a 3D array of real-valued numbers. The sources specify the use of a **16-bit floating-point format** for the spectrum to minimize memory cost [S1, S4, unofficial].
    *   **Bit Layout (16-bit float):** Not explicitly defined in the sources, but standard IEEE 754 half-precision (binary16) is implied by the context of "shorter number representation" and "16-bit floating point format" [S1, S4, unofficial]. It consists of 1 sign bit, 5 exponent bits, and 10 mantissa bits.
    *   **Memory Reduction:** A 64-bit double-precision complex spectrum requires 16 bytes per voxel. The Hartley transform produces a real spectrum, requiring 8 bytes per voxel (double precision) or 2 bytes per voxel (16-bit float). The 16-bit format reduces memory usage by a factor of 16 compared to double-precision complex Fourier transform [S1, S4, unofficial].

### Formulas
The continuous Hartley transform is defined as [S1, S2, S3, S4, unofficial]:

$$
F_H(s) = \int_{-\infty}^{+\infty} f(x) \text{cas}(2\pi s x) \, dx
$$

where the kernel function $\text{cas}(\theta)$ is:

$$
\text{cas}(\theta) = \cos(\theta) + \sin(\theta)
$$

For the discrete 3D case, the transform is applied along each dimension. The inverse Hartley transform is identical to the forward transform for real-valued functions, scaled by the number of elements [G].

### Parameters
*   **Precision:** 16-bit floating-point format is used for the spectrum [S1, S4, unofficial].
*   **Volume Size:** Examples use $128^3$ and $256^3$ volumes [S1, unofficial].
*   **Padding:** Zero-padding is applied to the spatial volume to avoid aliasing artifacts caused by the periodicity assumption of the transform [S1, 841-gpu-based-2d-fft.md, unofficial].

### Steps

1.  **Preprocessing (Global Transformation):**
    *   Apply zero-padding to the input volume $f(x, y, z)$ to the nearest power-of-two dimensions.
    *   Compute the 3D Hartley Transform of the padded volume to obtain the real-valued frequency spectrum $F_H(\omega_1, \omega_2, \omega_3)$.
    *   Store the spectrum in 16-bit floating-point format.

2.  **Slice Extraction:**
    *   For a given viewing direction vector $V$, define a 2D plane passing through the origin of the frequency domain and perpendicular to $V$.
    *   Sample the 3D spectrum $F_H$ along this plane. Since the plane rarely aligns with the integer lattice of the discrete spectrum, interpolation (resampling) is required [S1, S3, 824-fourier-projection-slice-volume-rendering.md, unofficial].
    *   **Adaptive Filtering:** The sources mention an adaptive filtering scheme for interpolation that reduces computational cost to ~15% of the non-adaptive case while maintaining image quality (relative error < 40dB) [S1, unofficial].

3.  **Inverse Transformation:**
    *   Apply the 2D Inverse Hartley Transform to the extracted slice to generate the 2D projection image in the spatial domain [S1, S3, unofficial].
    *   Convert the result from 16-bit float to the display format.

### Edge Cases and Pitfalls
*   **Precision Loss:** Using 16-bit floating-point format introduces round-off errors. The sources report that the relative difference between 16-bit and 64-bit double-precision images is below 50dB, which is visually imperceptible [S1, unofficial].
*   **Hermitian Symmetry Complexity:** While the Fourier transform of a real signal is Hermitian symmetric (allowing storage of only half the spectrum), extracting a slice from this half-spectrum is complex because the symmetry plane does not necessarily align with the arbitrary viewing direction. The Hartley transform avoids this by producing a real spectrum, simplifying slice extraction [S1, S3, unofficial].
*   **Aliasing:** Zero-padding is required to prevent aliasing artifacts due to the periodicity of the discrete transform [S1, 841-gpu-based-2d-fft.md, unofficial].

## Operating characteristics
*   **Time Complexity:**
    *   **Preprocessing:** $O(N^3 \log N)$ for the 3D Hartley Transform, where $N$ is the volume dimension [S3, 2288-fourier-transform.md, unofficial].
    *   **Per-View Rendering:** $O(N^2)$ for slice extraction and 2D inverse transform [S1, 952-frequency-domain-volume-rendering.md, unofficial].
    *   **Comparison:** Grows much slower than spatial domain rendering, which grows at $O(N^3)$ [S1, unofficial].
*   **Memory Complexity:**
    *   **Standard FFT:** Double-precision complex spectrum requires 16 bytes per voxel (16x the memory of a 1-byte spatial volume) [S1, S4, unofficial].
    *   **Hartley Transform:** Real-valued spectrum. With 16-bit float, it requires 2 bytes per voxel, reducing memory cost by a factor of 16 compared to double-precision complex FFT and a factor of 2 compared to 64-bit real spectrum [S1, S4, unofficial].
*   **Measured Performance:**
    *   On an IRIS Crimson with a 50MHz R4000 processor, rendering a $128^3$ volume took 0.54 seconds for frequency domain vs. 1.77 seconds for spatial domain [S1, unofficial].
    *   For a $256^3$ volume, 3.15 seconds vs. 24.38 seconds [S1, unofficial].
*   **Strengths:**
    *   Significant memory reduction.
    *   Faster rendering for large volumes due to lower complexity growth.
    *   Simplified slice extraction compared to half-spectrum Fourier methods.
*   **Limitations:**
    *   Still subject to the limitations of domain-transform methods: no transparency/alpha blending, fixed transfer functions, and potential aliasing if not padded [S3, 824-fourier-projection-slice-volume-rendering.md, unofficial].
    *   Requires adaptive filtering for efficient interpolation, adding implementation complexity [S1, unofficial].

## Background
The Hartley Transform for Memory Reduction was introduced by Takashi Totsuka and Marc Levoy in their 1993 paper "Frequency Domain Volume Rendering" [S1, S2, S4, unofficial]. The paper presented at SIGGRAPH 1993 demonstrated the use of the Hartley transform to control the explosion in memory cost associated with frequency-domain volume rendering. The method was applied to render human head (CT data), Utah teapot, and turbine blade volumes, demonstrating shading and depth cueing capabilities [S1, unofficial]. The Hartley transform itself is a direct relative of the Fourier transform, defined by Ralph Hartley in 1942 [S1, S2, S4, unofficial].
