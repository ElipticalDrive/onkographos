# Ray-Driven Splatting

Also called: Hybrid Splatting/Ray Casting, Muller Yagel hybrid, Muller and Yagel hybrid, Ray-driven volume splatting

## Overview
Ray-driven splatting is a hybrid volume rendering technique that combines the precomputation of splatting with the pixel-accurate accumulation of ray casting [S1, S2, unofficial]. It solves the problem of efficient perspective projection in splatting, where traditional methods struggle with the complexity of mapping 3D footprints to screen space [S2, unofficial]. Unlike [EWA Splatting](1069-ewa-splatting.md), which approximates footprints via elliptical weighting, ray-driven splatting spawns rays to intersect splats suspended in object space, enabling acceleration structures like early ray termination and bounding volumes [S1, S2, unofficial].

## How it works
**Inputs:**
- Volumetric dataset $V$ with voxel positions $\mathbf{p}_k$, density/extinction coefficients $\rho_k$, and reconstruction kernels $h$ [S1, S2, unofficial].
- Camera parameters (view and projection matrices) [S2, unofficial].

**Outputs:**
- Final image $I(x,y)$ [S1, S2, unofficial].

**Data Structures:**
- **Splat List:** A collection of splats, one per voxel, suspended in object space. Each splat $k$ is defined by its position $\mathbf{p}_k$, density $\rho_k$, and kernel shape $h$ [S2, unofficial].
- **Acceleration Structure:** Optional spatial acceleration structure (e.g., bounding volume hierarchy) to optimize ray-splat intersection [S1, unofficial].

**Steps:**
1. **Precompute Splat Contributions:** For each voxel $k$, compute the contribution of its kernel $h$ in object space. This step is analogous to standard splatting but retains the splat in 3D space rather than rasterizing it immediately [S1, unofficial].
2. **Spawn Rays:** For each pixel $(x,y)$ in the image plane, spawn a ray $\mathbf{r}$ into the scene [S2, unofficial].
3. **Intersect Splats:** Traverse the ray through the scene and intersect it with the suspended splats [S2, unofficial]. This involves solving for the intersection of the ray with the kernel function $h$ of each splat [S2, unofficial].
4. **Accumulate:** Accumulate the contributions of intersected splats along the ray, similar to ray casting compositing [S1, unofficial]. The contribution of a splat $k$ to the pixel is determined by the value of the kernel at the intersection point, modulated by the voxel density $\rho_k$ [S1, S2, unofficial].
5. **Optimize:** Use acceleration techniques such as space leaping, adaptive screen sampling, or early ray termination to skip empty regions or terminate rays when opacity is sufficient [S1, S2, unofficial].

**Formulas:**
The contribution of a splat $k$ to a pixel is given by:
$$ C_k = \rho_k \cdot h(\mathbf{r}(t) - \mathbf{p}_k) $$
where $\mathbf{r}(t)$ is the point on the ray intersecting the splat, and $t$ is the intersection parameter [S1, S2, unofficial].

**Parameters:**
- Kernel width: Not given in the sources.
- Ray step size: Not given in the sources.

**Edge Cases and Pitfalls:**
- **Perspective Distortion:** Traditional splatting methods suffer from incorrect footprint mapping under perspective projection. Ray-driven splatting handles this naturally by intersecting rays in 3D space [S2, unofficial].
- **Performance:** Early implementations were slow (e.g., 30 seconds for a 260x260 viewport on an SGI Indigo with 200 MHz) due to the computational cost of ray-splat intersection [S1, unofficial].

**Pseudocode:**
```python
def ray_driven_splatting(volume, camera, image_width, image_height):
    # Initialize image buffer
    image = zeros((image_height, image_width, 3))
    
    # Precompute splats in object space
    splats = []
    for voxel in volume:
        splat = {
            'position': voxel.position,
            'density': voxel.density,
            'kernel': voxel.kernel
        }
        splats.append(splat)
    
    # Optional: Build acceleration structure for splats
    accel_struct = build_acceleration_structure(splats)
    
    # Spawn rays for each pixel
    for y in range(image_height):
        for x in range(image_width):
            ray = camera.spawn_ray(x, y)
            color = vec3(0.0)
            alpha = 0.0
            
            # Intersect ray with splats
            intersections = intersect_ray_with_splats(ray, splats, accel_struct)
            
            # Sort intersections by distance (front-to-back)
            intersections.sort(key=lambda i: i.distance)
            
            # Accumulate contributions
            for intersection in intersections:
                splat = intersection.splat
                t = intersection.distance
                point = ray.origin + t * ray.direction
                
                # Evaluate kernel at intersection point
                kernel_value = splat.kernel.evaluate(point - splat.position)
                
                # Modulate by density
                contribution = splat.density * kernel_value
                
                # Composite (front-to-back)
                color = color * (1.0 - contribution) + contribution * splat.color
                alpha += contribution * (1.0 - alpha)
                
                # Early ray termination if alpha is sufficient
                if alpha > 0.99:
                    break
            
            image[y, x] = color
            
    return image
```

## Operating characteristics
- **Time Complexity:** Depends on the number of splats and the efficiency of the ray-splat intersection. Early implementations were slow, but acceleration structures can improve performance [S1, S2, unofficial].
- **Memory Complexity:** Linear in the number of voxels, as each voxel generates a splat [S1, S2, unofficial].
- **Performance:** Offers competitive or superior performance for parallel projection, and superior performance for perspective projection compared to traditional splatting [S2, unofficial].
- **Strengths:** Inherently insensitive to the complexity of the perspective viewing transform; supports acceleration methods like early ray termination and bounding volumes [S2, unofficial].
- **Limitations:** Early implementations were computationally expensive [S1, unofficial].

## Background
Ray-driven splatting was introduced by Müller and Yagel as a hybrid method to address the limitations of traditional splatting under perspective projection [S1, S2, unofficial]. It merges the technique of splatting with principles of raycasting, allowing for the use of ray tracing optimization techniques [S1, S2, unofficial].
