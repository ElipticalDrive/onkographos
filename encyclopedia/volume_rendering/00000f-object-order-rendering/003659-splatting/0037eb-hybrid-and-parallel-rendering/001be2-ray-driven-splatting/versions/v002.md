# Ray-Driven Splatting

Also called: Hybrid Splatting/Ray Casting, Muller Yagel hybrid, Muller and Yagel hybrid, Ray-driven volume splatting

## Overview
Ray-driven splatting is a hybrid volume rendering technique that combines the precomputation of voxel contributions via splatting with the pixel accumulation logic of ray casting [S1, unofficial]. It solves the performance bottlenecks of traditional voxel-driven splatting, particularly the inefficiency and complexity of handling perspective projections [S2, unofficial]. Unlike standard splatting, which projects footprints directly to the screen, this method suspends splats in object space and intersects them with rays spawned per pixel, enabling the use of ray-tracing optimizations like early ray termination and spatial acceleration structures [S1, unofficial][S2, unofficial].

## How it works
**Inputs:** Volumetric dataset (scalar values), camera parameters (view and projection matrices), and rendering resolution.
**Outputs:** Final color and opacity image.

**Data Structures:**
1.  **Voxel Grid:** Regular 3D grid of scalar values.
2.  **Splat Representation:** Each voxel $i$ at position $\mathbf{D}_i$ with density $\rho_i$ is associated with a 3D reconstruction kernel (footprint) $h_V$. In object space, this is a volume or a defined spatial extent [S1, unofficial].
3.  **Acceleration Structure:** (Optional) Spatial acceleration structure (e.g., BVH, grid) to optimize ray-splat intersection [S1, unofficial].

**Steps:**
1.  **Precompute Splat Extents:** For each voxel $i$ in the volume, define its contribution as a spatial extent (footprint) in object space. This extent represents the region where the voxel's kernel has non-negligible value [S1, unofficial].
2.  **Spawn Rays:** For each pixel $(u, v)$ in the image plane, spawn a ray $\mathbf{r}(t) = \mathbf{o} + t\mathbf{d}$ into the volume, where $\mathbf{o}$ is the eye position and $\mathbf{d}$ is the direction vector derived from the camera projection [S2, unofficial].
3.  **Ray-Splat Intersection:** Traverse the ray through the volume. Identify all splats (voxels) whose object-space footprints intersect the ray [S2, unofficial]. This is the core "ray-driven" step, replacing the screen-space accumulation of traditional splatting [S1, unofficial].
4.  **Accumulate Contributions:** For each intersected splat $i$, calculate the contribution to the pixel. The contribution is determined by the value of the reconstruction kernel $h_V$ at the intersection point relative to the voxel center, modulated by the voxel density $\rho_i$ [S1, unofficial].
    $$ C_{pixel} = \sum_{i \in \text{intersected}} h_V(\mathbf{r}(t_i) - \mathbf{D}_i) \cdot \rho_i $$
    where $t_i$ is the intersection parameter for splat $i$ [S1, unofficial].
5.  **Composite:** Accumulate the contributions along the ray, typically using front-to-back alpha compositing to handle transparency correctly [S1, unofficial][S2, unofficial].

**Parameters:**
*   **Kernel Radius:** The spatial extent of the splat. A diameter of 1.6 times the grid spacing is sufficient to avoid aliasing while preventing excessive blurring [S7, book].
*   **Acceleration Structure:** Choice of structure (e.g., uniform grid, BVH) affects traversal speed [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Perspective Distortion:** Traditional splatting struggles with perspective projection because footprint shapes and sizes vary significantly with depth. Ray-driven splatting is inherently insensitive to this complexity [S2, unofficial].
*   **Intersection Accuracy:** The method requires accurate determination of ray-splat intersections to avoid artifacts. Incorrect visibility determination can cause aliasing if kernels are assumed non-overlapping when they are not [S1, unofficial].
*   **Performance:** While superior for perspective views, performance depends heavily on the efficiency of the ray-splat intersection test and the acceleration structure used [S2, unofficial].

**Pseudocode:**
```python
def ray_driven_splatting(volume, camera, resolution):
    # Initialize output image
    image = zeros(resolution)
    
    # Precompute splat extents for all voxels (Splat Representation)
    # Each voxel i has position D_i, density rho_i, and kernel h_V
    splats = []
    for each voxel i in volume:
        splat = {
            'position': D_i,
            'density': rho_i,
            'kernel': h_V,
            'extent': compute_extent(h_V) # Spatial extent of the footprint
        }
        splats.append(splat)
    
    # Build acceleration structure for splats (Optional but recommended)
    accel_struct = build_acceleration_structure(splats)
    
    # Spawn rays and accumulate
    for y in range(resolution.height):
        for x in range(resolution.width):
            # Generate ray for pixel (x, y)
            ray_origin, ray_direction = camera.generate_ray(x, y)
            
            # Find intersected splats using acceleration structure
            intersected_splats = accel_struct.intersect(ray_origin, ray_direction)
            
            # Sort splats by distance from ray origin (front-to-back)
            intersected_splats.sort(key=lambda s: distance(ray_origin, s['position']))
            
            accumulated_color = 0.0
            accumulated_alpha = 0.0
            
            for splat in intersected_splats:
                # Calculate intersection point t
                t = intersect_ray_splat(ray_origin, ray_direction, splat['extent'])
                if t is None:
                    continue
                
                intersection_point = ray_origin + t * ray_direction
                
                # Evaluate kernel at intersection point relative to voxel center
                # h_V is the volumetric reconstruction kernel
                kernel_value = splat['kernel'](intersection_point - splat['position'])
                
                # Contribution modulated by density
                contribution = kernel_value * splat['density']
                
                # Alpha compositing
                alpha = contribution
                color = contribution # Assuming scalar volume mapped to color
                
                # Front-to-back compositing
                new_alpha = accumulated_alpha + alpha * (1.0 - accumulated_alpha)
                new_color = (accumulated_color + color * (1.0 - accumulated_alpha)) / new_alpha if new_alpha > 0 else 0.0
                
                accumulated_alpha = new_alpha
                accumulated_color = new_color
                
                # Early ray termination (Optimization)
                if accumulated_alpha > 0.99:
                    break
            
            image[y, x] = accumulated_color

    return image
```

## Operating characteristics
**Time Complexity:** Depends on the number of voxels, the number of pixels, and the efficiency of the ray-splat intersection test. With an acceleration structure, traversal is faster than brute-force intersection.
**Memory Complexity:** $O(N)$ for storing splat data, where $N$ is the number of voxels.
**Performance:** Reported performance of 30 seconds for the MRbrain dataset with a $260^2$ viewport on an SGI Indigo with 200 MHz [S1, unofficial]. Offers competitive or superior performance for parallel projection and superior performance for perspective projection compared to traditional splatting [S2, unofficial].
**Strengths:** Inherently insensitive to perspective viewing transform complexity; supports ray-tracing optimizations (early ray termination, spatial acceleration structures) [S1, unofficial][S2, unofficial].
**Limitations:** Requires efficient ray-splat intersection logic; potentially higher computational cost per pixel than optimized screen-space splatting for simple orthographic views if acceleration structures are not used effectively.

## Background
Ray-driven splatting was introduced as a hybrid approach to address the limitations of traditional voxel-driven splatting, particularly regarding perspective projection efficiency [S1, unofficial][S2, unofficial]. It merges the technique of splatting with principles of raycasting, allowing splats to be suspended in object space and intersected by rays [S2, unofficial]. This approach enables the use of optimization techniques common in ray tracing, such as space leaping and adaptive screen sampling [S1, unofficial].
