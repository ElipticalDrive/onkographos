# CityGaussian / VastGaussian / DoGaussian

Also called: City-Gaussian, CityGaussian V2, DoGaussian, VastGaussian

## Overview
CityGaussian, VastGaussian, and DoGaussian are block-based partitioning methods that enable the training and rendering of city-scale scenes by dividing large environments into overlapping spatial tiles, training independent 3D Gaussian Splatting (3DGS) models per tile, and merging them at render time [S1, S2, unofficial]. They solve the memory and convergence limitations of monolithic 3DGS training on scenes spanning square kilometers [S2, unofficial]. Unlike anchor-based hierarchical methods like Octree-GS or Scaffold-GS that build a single unified structure, these methods decouple training into independent blocks, allowing for distributed training and explicit handling of lighting variations across large areas [S1, S2, unofficial].

## How it works
**Inputs:** A large-scale scene captured by multi-view images (e.g., aerial or street-level); scene bounding box; block size (tile dimensions); overlap ratio.
**Outputs:** A set of per-block 3DGS models (positions, covariances, colors, opacities) and a metadata structure defining block boundaries and overlap regions.

**Data Structures:**
1.  **Block Grid:** A 2D or 3D grid partitioning the scene bounding box into square tiles. Each tile $T_i$ has a defined spatial extent (bbox) and an overlap region with neighbors.
2.  **Per-Block Model:** Standard 3DGS primitives for each block.
    *   Position: $\mathbf{p} \in \mathbb{R}^3$
    *   Scale/Rotation: $\mathbf{s} \in \mathbb{R}^3, \mathbf{q} \in \mathbb{R}^4$ (quaternion)
    *   Opacity: $\alpha \in [0, 1]$
    *   Spherical Harmonics (SH): Coefficients $\mathbf{c}_{l,m}$ for view-dependent color.

**Steps:**
1.  **Partitioning:** Divide the scene bounding box into non-overlapping or slightly overlapping tiles [S1, unofficial]. VastGaussian uses spatially-disjoint regions, while CityGaussian uses overlapping blocks to handle seams [S2, unofficial].
2.  **Independent Training:** Train a separate 3DGS model for each tile using only the images that overlap with that tile's region [S1, unofficial].
    *   *VastGaussian:* Handles varying lighting by decoupling appearance handling per block, often training with local lighting assumptions or normalizing appearance statistics [S2, unofficial].
    *   *CityGaussian:* Uses depth regularization and visibility-aware training to ensure geometric consistency within the block [S2, unofficial].
3.  **Merging:** At render time, collect all Gaussians from all blocks.
    *   *Overlap Handling:* In regions where blocks overlap, Gaussians from multiple blocks exist. A blending or selection strategy is applied. VastGaussian uses "feathered overlap" to blend contributions [S2, unofficial]. CityGaussian relies on the hierarchical LoD structure to select the appropriate level of detail, implicitly handling overlaps by prioritizing closer or higher-resolution blocks [S2, unofficial].
4.  **Hierarchical LoD (CityGaussian V2):** To support streaming and large-scale rendering, CityGaussian V2 builds a LoD pyramid.
    *   Clusters of Gaussians within each block are merged into coarser representations.
    *   A tree structure is formed where nodes summarize radiance and opacity of children [S2, unofficial].
    *   Rendering selects the appropriate LoD based on view distance, streaming only necessary blocks [S2, unofficial].

**Parameters:**
*   Block Size: Typically determined by GPU memory limits and scene scale. Not given in the sources.
*   Overlap Width: Sufficient to cover aliasing artifacts at tile boundaries. Not given in the sources.
*   LoD Levels: Number of pyramid levels. Not given in the sources.

**Pseudocode:**
```python
def train_city_gaussian(scene_images, bounding_box, block_size, overlap):
    # 1. Partition scene into blocks
    blocks = partition_grid(bounding_box, block_size, overlap)
    
    models = {}
    for block_id, block in blocks.items():
        # 2. Identify images overlapping this block
        relevant_images = get_overlapping_images(scene_images, block.bbox)
        
        # 3. Train independent 3DGS model for this block
        # VastGaussian: decoupled appearance handling
        # CityGaussian: depth regularization
        model = train_3dgs(relevant_images, block.bbox, 
                           method="depth_regularized") # Specifics vary by variant
        models[block_id] = model
        
    return models

def render_city_gaussian(models, camera, lod_level):
    # 4. Collect Gaussians from relevant blocks
    # Determine which blocks are visible and at which LoD
    visible_blocks = get_visible_blocks(models, camera, lod_level)
    
    all_gaussians = []
    for block_id in visible_blocks:
        block_gaussians = models[block_id].get_gaussians()
        # 5. Merge with overlap handling
        # VastGaussian: feathered blend
        # CityGaussian: hierarchical selection
        all_gaussians.extend(block_gaussians)
        
    # 6. Rasterize
    return rasterize(all_gaussians, camera)
```

## Subtopics

### CityGS-X
A method that extends block-based partitioning with a geometry-aware architecture that refines block boundaries according to building footprints, achieving highly accurate urban reconstruction [S1, unofficial]. It targets large-scale urban scenes by combining semantic segmentation to allocate Gaussians only on building facades and road surfaces [S1, unofficial].

### Proxy-GS
A method that uses a coarse proxy mesh to guide Gaussian placement, significantly reducing the number of Gaussians required for background regions [S1, unofficial].

## Operating characteristics
*   **Memory:** Scales linearly with the number of blocks, allowing training on hardware with limited memory by processing blocks independently [S1, unofficial]. Total memory is the sum of per-block models.
*   **Training Time:** Parallelizable across blocks/nodes. DoGaussian specifically enables distributed training across multiple nodes [S2, unofficial].
*   **Rendering:** Standard 3DGS rasterization complexity, but requires managing multiple block sources. Overlap handling adds minor computational overhead [S2, unofficial].
*   **Strengths:** Enables city-scale training (square kilometers) which is impossible with monolithic 3DGS. Handles lighting variations better than global models [S2, unofficial].
*   **Limitations:** Potential seams or artifacts at block boundaries if overlap blending is not handled well. Requires careful management of block dependencies [S1, unofficial].

## Background
Originating from the need to scale 3D Gaussian Splatting to urban environments, VastGaussian was presented at CVPR 2024, proposing the partition-and-merge strategy with decoupled appearance handling [S2, unofficial]. CityGaussian (and V2) introduced hierarchical LoD and depth regularization for city-scale scenes [S2, unofficial]. DoGaussian focused on the distributed training aspect [S2, unofficial]. These methods build on the foundational 3DGS work [S1, unofficial].
