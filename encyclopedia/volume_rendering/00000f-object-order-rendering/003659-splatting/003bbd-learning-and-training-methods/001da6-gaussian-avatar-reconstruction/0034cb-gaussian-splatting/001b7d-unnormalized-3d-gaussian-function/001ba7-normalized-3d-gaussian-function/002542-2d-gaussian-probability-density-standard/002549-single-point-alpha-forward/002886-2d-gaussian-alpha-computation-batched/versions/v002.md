# 2D Gaussian Alpha Computation (Batched)

Also called: Alpha Computation, Batched Gaussian Alpha Forward

## Overview
This method computes the alpha values for all $N$ 2D Gaussians across all $W \times H$ pixels in a single batched operation, serving as the core rasterization step in Gaussian Splatting [S1, unofficial]. It builds on [Single Point Alpha Forward](3478-single-point-alpha-forward.md) by vectorizing the evaluation over the entire image grid, enabling efficient GPU execution [G]. It differs from [Explicit Intersection Alpha Compositing](4814-explicit-intersection-alpha-compositing.md) by computing raw alpha contributions for all pixel-gaussian pairs rather than identifying explicit intersection pairs for compositing [S1, unofficial].

## How it works
**Inputs:**
- `means_2D`: Tensor of shape $(N, 2)$, the 2D means of the Gaussians in screen space [S1, unofficial].
- `cov_2D`: Tensor of shape $(N, 2, 2)$, the 2D covariance matrices for each Gaussian [S1, unofficial].
- `opacities`: Tensor of shape $(N,)$, the opacity values for each Gaussian [S1, unofficial].
- $W, H$: Integer width and height of the image [S1, unofficial].

**Outputs:**
- `alphas`: Tensor of shape $(N, H, W)$, the alpha values for each Gaussian at each pixel [S1, unofficial].

**Data Structures:**
- `points_2D`: Tensor of shape $(W \cdot H, 2)$, containing the coordinates of every pixel center [S1, unofficial].
- `power`: Tensor of shape $(N, W \cdot H)$, containing the negative half-squared Mahalanobis distance for each Gaussian-pixel pair [S1, unofficial].
- `exp_power`: Tensor of shape $(N, W \cdot H)$, containing the exponential of the power term [S1, unofficial].

**Steps:**
1. **Generate Pixel Grid:** Create a meshgrid of pixel coordinates $(x, y)$ for $x \in [0, W-1]$ and $y \in [0, H-1]$. Stack these coordinates and flatten them into a tensor `points_2D` of shape $(W \cdot H, 2)$ [S1, unofficial].
2. **Broadcast Dimensions:** Expand `points_2D` to shape $(1, W \cdot H, 2)$ and `means_2D` to shape $(N, 1, 2)$ to enable broadcasting during evaluation [S1, unofficial].
3. **Evaluate 2D Gaussian:** Compute the power term for all pairs. The power is defined as $-\frac{1}{2} (\mathbf{x} - \boldsymbol{\mu})^T \Sigma^{-1} (\mathbf{x} - \boldsymbol{\mu})$, where $\mathbf{x}$ is the pixel coordinate, $\boldsymbol{\mu}$ is the mean, and $\Sigma$ is the covariance [G]. This results in a tensor `power` of shape $(N, W \cdot H)$ [S1, unofficial].
4. **Compute Exponential:** Calculate $\exp(\text{power})$. To prevent numerical overflow when power is positive (which should not occur for valid Gaussians but may due to precision), clamp positive power values to 0 before exponentiation: $\text{exp\_power} = \exp(\max(0, \text{power}))$ [S1, unofficial].
5. **Apply Opacity:** Multiply the exponential term by the opacity of each Gaussian: $\alpha_{i,j} = \text{opacity}_i \cdot \text{exp\_power}_{i,j}$. This results in a tensor of shape $(N, W \cdot H)$ [S1, unofficial].
6. **Reshape:** Reshape the alpha tensor to $(N, H, W)$ to match the image layout [S1, unofficial].
7. **Clamp for Stability:** Clamp all alpha values to a maximum of 0.99 to prevent division by zero or numerical instability during subsequent compositing steps: $\alpha_{i,j} = \min(\alpha_{i,j}, 0.99)$ [S1, unofficial].
8. **Threshold Small Values:** Zero out alpha values smaller than $1/255.0$ to reduce memory bandwidth and computation for negligible contributions: $\alpha_{i,j} = \alpha_{i,j}$ if $\alpha_{i,j} \ge 1/255.0$, else $0.0$ [S1, unofficial].

**Pseudocode:**
```python
def compute_batched_alphas(means_2D, cov_2D, opacities, W, H):
    # Step 1: Generate pixel grid
    xs = [float(i) for i in range(W)]
    ys = [float(i) for i in range(H)]
    grid_x = [[x for _ in range(H)] for x in xs]
    grid_y = [[y for _ in range(W)] for y in ys]
    points_2D = [[grid_x[r][c], grid_y[r][c]] for r in range(H) for c in range(W)]
    
    # Step 2: Broadcast dimensions
    # points_2D_exp: shape (1, W*H, 2)
    # means_2D_exp: shape (N, 1, 2)
    points_2D_exp = [[[p] for p in points_2D]]
    means_2D_exp = [[[m] for m in means_2D]]
    
    # Step 3: Evaluate 2D Gaussian power
    N = len(means_2D)
    num_pixels = W * H
    power = [[0.0] * num_pixels for _ in range(N)]
    for i in range(N):
        cov_inv = inverse_2x2(cov_2D[i])
        for j in range(num_pixels):
            diff = [points_2D_exp[0][j][k] - means_2D_exp[i][0][k] for k in range(2)]
            left_prod = matmul_vector_2x2(diff, cov_inv)
            dot = sum(left_prod[k] * diff[k] for k in range(2))
            power[i][j] = -0.5 * dot
            
    # Step 4: Compute exponential with overflow guard
    exp_power = [[exp(power[i][j]) if power[i][j] <= 0.0 else 0.0 for j in range(num_pixels)] for i in range(N)]
    
    # Step 5: Apply opacity
    alphas_flat = [[opacities[i] * exp_power[i][j] for j in range(num_pixels)] for i in range(N)]
    
    # Step 6: Reshape
    alphas = [[[alphas_flat[i][r * W + c] for c in range(W)] for r in range(H)] for i in range(N)]
    
    # Step 7: Clamp for stability
    alphas = [[min(alphas[i][r][c], 0.99) for c in range(W)] for r in range(H)] for i in range(N)]
    
    # Step 8: Threshold small values
    alphas = [[[0.0 if alphas[i][r][c] < 1.0 / 255.0 else alphas[i][r][c]] for c in range(W)] for r in range(H)] for i in range(N)]
    
    return alphas

# Standard helper operations (defined for self-containment)
def inverse_2x2(M):
    det = M[0][0]*M[1][1] - M[0][1]*M[1][0]
    return [[M[1][1]/det, -M[0][1]/det], [-M[1][0]/det, M[0][0]/det]]

def matmul_vector_2x2(v, M):
    return [M[0][0]*v[0] + M[0][1]*v[1], M[1][0]*v[0] + M[1][1]*v[1]]
```

**Parameters:**
- Clamping threshold: 0.99 [S1, unofficial].
- Zeroing threshold: $1/255.0$ [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Numerical Overflow:** If the power term is positive due to precision errors, $\exp(\text{power})$ can overflow. The source explicitly clamps positive power to 0 before exponentiation [S1, unofficial].
- **Covariance Inversion:** The method assumes `cov_2D` is invertible. Degenerate covariances (e.g., zero determinant) will cause inversion failures. This is typically handled in earlier steps by ensuring valid covariance matrices [G].
- **Memory Usage:** The intermediate tensor `power` has shape $(N, W \cdot H)$, which can be large for high-resolution images and many Gaussians. This is the primary memory bottleneck of this batched approach [G].

## Subtopics

## Operating characteristics
- **Time Complexity:** $O(N \cdot W \cdot H)$, as every Gaussian is evaluated at every pixel. The matrix operations (inverse, multiplication) are constant time per Gaussian-pixel pair but dominate the constant factor [G].
- **Memory Complexity:** $O(N \cdot W \cdot H)$ for the intermediate `power` and `alphas` tensors. This is significantly higher than sparse approaches [G].
- **Performance:** Highly parallelizable on GPUs due to the batched nature. Performance scales linearly with the number of Gaussians and pixels [G].
- **Strengths:** Simple implementation, high throughput on modern GPUs, easy to integrate with automatic differentiation frameworks [G].
- **Limitations:** High memory consumption for large scenes or high resolutions. Does not exploit spatial coherence or sparsity [G].
- **When to use:** When the number of Gaussians and image resolution are moderate, and simplicity of implementation is prioritized. Not suitable for very large-scale scenes without further optimization (e.g., tiling, sparse representations) [G].
