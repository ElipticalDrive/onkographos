# Opacity-Sensitive Elliptical Bounding Box

Also called: Elliptical Bounding Box, Non-square Bounding Box

## Overview
A method to compute 2D Gaussian projections as elliptical disks rather than axis-aligned bounding boxes (AABBs) to reduce false-positive tile intersections in Gaussian Splatting rendering [S1]. It integrates opacity thresholds to prune empty or negligible splats [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** 2D Gaussian splat defined by mean $\mu$, covariance matrix $\Sigma$, and opacity $\tau$ [S1, S2]. Tile grid dimensions (e.g., $16 \times 16$) [S1].
*   **Output:** A set of tile indices intersecting the splat, minimized by excluding tiles where the splat's opacity is below a threshold $\epsilon$ or where the bounding box is empty [S1].

**Data Structures:**
*   **Covariance Matrix:** $\Sigma = \begin{bmatrix} \Sigma_{xx} & \Sigma_{xy} \\ \Sigma_{yx} & \Sigma_{yy} \end{bmatrix}$ [S2].
*   **Eigen Decomposition:** $\Sigma = R \Lambda R^T$, where $R$ is the rotation matrix of eigenvectors and $\Lambda$ is the diagonal matrix of eigenvalues $\lambda_1, \lambda_2$ [S2].
*   **Basis Vectors:** The 2D basis vectors $\mathbf{a}$ and $\mathbf{b}$ correspond to the semi-axes of the ellipse, derived from the eigenvalues [S2].

**Steps:**
1.  **Opacity Check:** If the splat opacity $\tau < \epsilon$, discard the splat immediately; the bounding box is considered empty [S1].
2.  **Compute Elliptical Extent:** Calculate the semi-axes lengths of the 2D Gaussian from the eigenvalues of $\Sigma$ [S2].
3.  **Determine Non-Square Bounding Box:** Compute the tightest AABB that encloses the rotated ellipse using the basis vectors $\mathbf{a}$ and $\mathbf{b}$ [S2].
4.  **Tile Intersection:** Identify all tiles whose AABB intersects with the computed non-square bounding box [S1].
5.  **Filtering:** Exclude tiles where the intersection is negligible, primarily relying on the opacity threshold to prune empty splats [S1].

**Pseudocode:**
```python
import math

def compute_tight_aabb(mean, covariance, opacity, epsilon):
    # Step 1: Opacity Check
    if opacity < epsilon:
        return None  # Empty bounding box, no tiles

    # Step 2 & 3: Compute Tight AABB from Covariance
    # Eigen decomposition of 2x2 covariance matrix Sigma
    sxx, sxy, syy = covariance[0, 0], covariance[0, 1], covariance[1, 1]
    trace = sxx + syy
    det = sxx * syy - sxy * sxy
    sqrt_term = math.sqrt(max(0.0, (trace / 2.0) ** 2 - det))
    l1 = trace / 2.0 + sqrt_term
    l2 = trace / 2.0 - sqrt_term

    # Semi-axes lengths from eigenvalues
    a = math.sqrt(max(0.0, l1))
    b = math.sqrt(max(0.0, l2))

    # Rotation angle from eigenvector corresponding to l1
    # Standard 2D eigenvector for l1 is [sxy, l1 - sxx]
    if abs(l1 - sxx) > 1e-6:
        theta = math.atan2(l1 - sxx, sxy)
    else:
        theta = math.pi / 2.0

    # Tight AABB extents for a rotated ellipse [G]
    width = 2.0 * (abs(a * math.cos(theta)) + abs(b * math.sin(theta)))
    height = 2.0 * (abs(a * math.sin(theta)) + abs(b * math.cos(theta)))

    # Calculate bounding box corners in screen space
    min_x = mean[0] - width / 2.0
    max_x = mean[0] + width / 2.0
    min_y = mean[1] - height / 2.0
    max_y = mean[1] + height / 2.0

    return (min_x, min_y, max_x, max_y)

def intersect_tiles(mean, covariance, opacity, epsilon, tile_width, tile_height, image_width, image_height):
    bbox = compute_tight_aabb(mean, covariance, opacity, epsilon)
    if bbox is None:
        return []

    min_x, min_y, max_x, max_y = bbox

    # Determine tile range
    min_tile_x = max(0, math.floor(min_x / tile_width))
    max_tile_x = min(math.floor((image_width - 1) / tile_width), math.floor(max_x / tile_width))
    min_tile_y = max(0, math.floor(min_y / tile_height))
    max_tile_y = min(math.floor((image_height - 1) / tile_height), math.floor(max_y / tile_height))

    tiles = []
    for ty in range(min_tile_y, max_tile_y + 1):
        for tx in range(min_tile_x, max_tile_x + 1):
            tiles.append((tx, ty))

    return tiles
```

**Parameters:**
*   $\epsilon$: Opacity threshold. Typical value: Not given in the sources. [S1]
*   Tile Size: e.g., $16 \times 16$ pixels. [S1]

**Edge Cases and Pitfalls:**
*   **Precision:** Inaccuracies in approximate circle-ellipse intersection tests occur near the sharp ends of the ellipse, but visual impact is minimal due to low remaining opacity [S2].
*   **Degenerate Input:** If the covariance matrix is singular (zero eigenvalue), the ellipse collapses to a line or point. The bounding box becomes degenerate. [G] Handle by checking the determinant of $\Sigma$ before decomposition and clamping eigenvalues to a small positive value.

## Subtopics

### Staged-fragment Reduction
A reduction technique for per-touched-tile duplicated splats using tighter AABBs and an approximate tile-ellipse intersection test [S2]. It reduces the number of tiles per splat by checking only tiles whose bounding-circle intersects with the splat, using approximate circle-ellipse intersection tests [S2]. Inaccuracies in the test mostly occur near the side of a splat's sharp end, where potential impact on the rendered image is minimal due to low remaining opacity [S2]. Developed concurrently with Speedy-Splat [S2].

## Operating characteristics
**Time and Memory Complexity:**
*   Reduces the number of duplicated Gaussians significantly. On the Bicycle scene at native resolution with $16 \times 16$ tiles, original AABBs resulted in 87,067,709 duplicated Gaussians [S1]. Using opacity-sensitive ellipses with square boxes reduced this to 55,648,264 [S1]. Allowing non-square bounding boxes further reduced duplicated Gaussians to 18,466,556 [S1].
*   Decreases render time and GPU memory usage by factors of 3.77 and 2.11 respectively on the Bicycle scene [S1].

**Measured Performance:**
*   At higher resolutions, the reduction in duplicated Gaussians leads to more consistent render times, especially for large, mostly transparent 3D Gaussians that previously affected a significant number of tiles [S1].
*   Using $16 \times 32$ tiles increases average render time to 9.77 ms, illustrating why tile size is only increased at higher resolutions [S1].

**Strengths and Limitations:**
*   **Strengths:** Massive reduction in false-positive tile intersections; consistent render times; lower memory usage [S1].
*   **Limitations:** Exact pixel-perfect intersections would result in only 10,976,269 duplicated Gaussians, but are computationally too expensive. The elliptical/non-square approach provides a trade-off [S1].

**When to Use:**
*   Use when rendering large scenes with many transparent or large Gaussians where false-positive tile intersections dominate overhead [S1].
*   Use when memory bandwidth is a bottleneck due to duplicate splat processing [S1].

**When Not to Use:**
*   Not necessary for very small scenes or when the overhead of computing the elliptical bounding box outweighs the benefits. [G]
*   If exact pixel-perfect rendering is required and computational resources allow for expensive intersection tests. [S1]

## Background
Originated from improvements to 3D Gaussian Splatting rendering [S1]. The method was introduced to address the inefficiency of the original 3DGS method, which used circular bounding boxes leading to square AABBs and excessive duplicate splat processing [S1]. The specific formulation of the tight AABB around the ellipse was also concurrently published by Hanson et al. [S2].
