# Gaussian Splatting

Also called: 3D Gaussian Splatting, 3DGS, 3DGS representation, EWA Volume Splatting, Elliptical Weighted Average splatting, Gaussian Splat, Volume Splatting, 3D Gaussian Splatting Rasterization, 3D Gaussian Splat Representation & Band-0 SH Decoding

## Overview
Gaussian Splatting is an object-order direct volume rendering algorithm that represents a scene as a collection of overlapping 3D Gaussian primitives, projecting them onto the image plane and alpha-compositing them to generate the final image [S2][S4, unofficial]. It serves as a fast, high-quality alternative to Neural Radiance Fields (NeRF) by leveraging volumetric rendering principles to preserve differentiability while employing point-based rasterization for efficient training and rendering [S1][S4, unofficial]. Unlike traditional opacity-based splatting, 3DGS assigns a single opacity value per primitive, allowing for constant transparency regardless of viewing direction and enabling the optimization of a well-behaved, bounded scalar [S1]. It builds on [EWA Splatting](1069-ewa-splatting.md) but simplifies the formulation by ignoring self-attenuation and approximating perspective projection [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $M$ 3D Gaussians $\{g_i\}_{i=1}^M$, where each $g_i$ is defined by center $\boldsymbol{\mu}_i$, covariance $\boldsymbol{\Sigma}_i$, opacity $\sigma_i$, and color $c_i$; a camera with intrinsics $K$ and extrinsics $W$; and image dimensions $H \times W$ [S4, S8, unofficial].
*   **Output:** A 2D image $I$ of size $H \times W$ [S4, unofficial].

**Data Structures:**
Each Gaussian splat stores the following fields [S3, S4, unofficial]:
*   `pos`: $\boldsymbol{\mu}_i \in \mathbb{R}^3$, center position in world space.
*   `scale`: $s \in \mathbb{R}^3$, size along each local axis (stored in log space).
*   `rot`: $q \in \mathbb{R}^4$, orientation as a unit quaternion.
*   `color`: $c_i \in \mathbb{R}^3$, RGB color. In the standard format, this is decoded from spherical harmonic (SH) coefficients [S3, unofficial]. Band-0 SH coefficients $f_{dc} \in \mathbb{R}^3$ are converted to RGB using $C_0 = \frac{1}{2\sqrt{\pi}} \approx 0.282$ [S3, unofficial]:
    $$ \text{color} = \text{clamp}(0.5 + C_0 \cdot f_{dc}, 0, 1) $$
*   `opacity`: $\sigma_i \in \mathbb{R}$, opacity in $[0, 1]$ (stored as a logit).

The 3D covariance matrix $\boldsymbol{\Sigma}_i$ is parameterized via diagonalization $\boldsymbol{\Sigma}_i = V S V^T$, where $S = \text{diag}(e^{s_1}, e^{s_2}, e^{s_3})$ and $V$ is the rotation matrix derived from the quaternion $q$ [S5][S8, unofficial].

**Rendering Pipeline:**
The rendering process follows these steps [S1][S8, unofficial]:

1.  **Projection:** For each Gaussian $i$, compute the 2D screen-space covariance matrix $\tilde{\boldsymbol{\Sigma}}_i$. First, transform the 3D covariance to camera coordinates: $\boldsymbol{\Sigma}'_i = W \boldsymbol{\Sigma}_i W^T$ [S8, unofficial]. Then, approximate the perspective projection $P_K$ around the Gaussian center $\boldsymbol{\mu}_i$ using its Jacobian $\mathbf{J} \in \mathbb{R}^{2\times3}$ [S8, unofficial]:
    $$ P_K(\mathbf{x}) \approx P_K(\boldsymbol{\mu}_i) + \mathbf{J}(\mathbf{x} - \boldsymbol{\mu}_i) $$
    The projected 2D covariance is:
    $$ \tilde{\boldsymbol{\Sigma}}_i = \mathbf{J} \boldsymbol{\Sigma}'_i \mathbf{J}^T $$
    The projected mean is $\tilde{\boldsymbol{\mu}}_i = P_K(\boldsymbol{\mu}_i)$ [S8, unofficial].

2.  **Rasterization (Splatting):** For each pixel $p$ in the image, identify the set of $K$ Gaussians whose projected footprints cover $p$. This is typically done using a tile-based rasterization strategy [S1][S8, unofficial]. For each covering Gaussian, evaluate the 2D Gaussian value at pixel $p$:
    $$ \tilde{G}_i(p) = \exp\left(-\frac{1}{2}(p - \tilde{\boldsymbol{\mu}}_i)^T \tilde{\boldsymbol{\Sigma}}_i^{-1} (p - \tilde{\boldsymbol{\mu}}_i)\right) $$

3.  **Sorting:** Sort the $K$ Gaussians intersecting the view ray for pixel $p$ by distance from their centers to the camera position (back-to-front order) [S8, unofficial]. Note: This sorting is based on centers, which is an approximation [S2].

4.  **Alpha-Compositing:** Compute the final pixel intensity $I_f$ by alpha-compositing the sorted Gaussians [S1][S8, unofficial]:
    $$ I_f = \sum_{i=1}^N c_i \tilde{\sigma}_i \tilde{G}_i(p) \prod_{j=1}^{i-1} \left(1 - \tilde{\sigma}_j \tilde{G}_j(p)\right) $$
    where $N$ is the number of sorted Gaussians, $\tilde{\sigma}_i = \sigma_i$, and $\tilde{G}_i(p)$ is the Gaussian value at $p$ [S8, unofficial].

**Training and Optimization:**
The scene parameters $\theta$ (the set of Gaussians) are optimized by minimizing the photometric loss between the rendered image $I_{\theta,i}$ and the input view $I_i$ [S8, unofficial]:
$$ \mathcal{L}(\theta) = \frac{1}{N} \sum_{i=1}^N \| I_{\theta,i} - I_i \|^2 $$
Gradients are backpropagated to update Gaussian parameters using Adam [S8, unofficial]. During training, the number of Gaussians is dynamically adjusted: splitting large Gaussians, cloning those that underfit detail, and pruning those with low opacity [S8, unofficial].

**Pseudocode:**
```python
def render_gaussian_splats(gaussians, camera, image_width, image_height):
    import math
    # Initialize output buffers
    color_buffer = [[0.0, 0.0, 0.0] for _ in range(image_height)]
    alpha_buffer = [[0.0] * image_width for _ in range(image_height)]
    
    # Precompute camera matrices
    R_cam = camera.extrinsics[:3, :3]
    t_cam = camera.extrinsics[:3, 3]
    K = camera.intrinsics[:3, :3]
    
    projected = []
    for g in gaussians:
        # 1. Build 3D covariance from scale and rotation
        S = [[math.exp(g.scale[0]), 0, 0], [0, math.exp(g.scale[1]), 0], [0, 0, math.exp(g.scale[2])]]
        V = quaternion_to_rotation_matrix(g.rot)
        Sigma_3d = mat_mul(mat_mul(V, S), transpose(V))
        
        # 2. Transform to camera space
        Sigma_cam = mat_mul(mat_mul(R_cam, Sigma_3d), transpose(R_cam))
        
        # 3. Project center to camera space
        mu_cam = vec3_add(mat_mul(R_cam, g.pos), t_cam)
        z = mu_cam[2]
        if z <= 0.0: continue # Behind camera
        
        # 4. Compute Jacobian of perspective projection
        K23 = [K[0][:3], K[1][:3]]
        J = [[K23[r][c] / z for c in range(3)] for r in range(2)]
        for r in range(2):
            J[r][2] -= (K23[r][0]*mu_cam[0] + K23[r][1]*mu_cam[1] + K23[r][2]*mu_cam[2]) / (z * z)
            
        # 5. Project covariance and stabilize
        Sigma_2d = mat_mul(mat_mul(J, Sigma_cam), transpose(J))
        Sigma_2d[0][0] += 0.3
        Sigma_2d[1][1] += 0.3
        
        # 6. Project center to screen
        mu_2d_hom = mat_mul(K, [mu_cam[0], mu_cam[1], mu_cam[2], 1.0])
        mu_2d = [mu_2d_hom[0] / mu_2d_hom[2], mu_2d_hom[1] / mu_2d_hom[2]]
        
        # 7. Compute bounding box (3-sigma extent)
        extent_x = 3.0 * math.sqrt(Sigma_2d[0][0])
        extent_y = 3.0 * math.sqrt(Sigma_2d[1][1])
        x_min, x_max = int(mu_2d[0] - extent_x), int(mu_2d[0] + extent_x)
        y_min, y_max = int(mu_2d[1] - extent_y), int(mu_2d[1] + extent_y)
        x_min, y_min = max(0, x_min), max(0, y_min)
        x_max, y_max = min(image_width, x_max), min(image_height, y_max)
        
        projected.append({
            'mu_2d': mu_2d, 'Sigma_2d': Sigma_2d, 'sigma': g.opacity,
            'color': decode_sh_band0(g.color_coeffs),
            'x_min': x_min, 'y_min': y_min, 'x_max': x_max, 'y_max': y_max,
            'depth': z
        })
    
    # Sort back-to-front
    projected.sort(key=lambda g: g['depth'], reverse=True)
    
    # Rasterize with alpha compositing
    for g_proj in projected:
        for y in range(g_proj['y_min'], g_proj['y_max']):
            for x in range(g_proj['x_min'], g_proj['x_max']):
                diff = [x - g_proj['mu_2d'][0], y - g_proj['mu_2d'][1]]
                inv_Sigma = inverse_2x2(g_proj['Sigma_2d'])
                quad = diff[0]*(inv_Sigma[0][0]*diff[0] + inv_Sigma[0][1]*diff[1]) + \
                       diff[1]*(inv_Sigma[1][0]*diff[0] + inv_Sigma[1][1]*diff[1])
                G_val = math.exp(-0.5 * quad)
                
                alpha = g_proj['sigma'] * G_val
                T = alpha_buffer[y][x][0]
                if alpha > 1e-4 and T < 0.99:
                    color = g_proj['color']
                    color_buffer[y][x] = [
                        color_buffer[y][x][0] * T + color[0] * alpha,
                        color_buffer[y][x][1] * T + color[1] * alpha,
                        color_buffer[y][x][2] * T + color[2] * alpha
                    ]
                    alpha_buffer[y][x][0] = T * (1.0 - alpha)
                if alpha_buffer[y][x][0] < 1e-4:
                    break
    return color_buffer

# Helper functions
def quaternion_to_rotation_matrix(q):
    x, y, z, w = q
    return [
        [1 - 2*(y*y + z*z), 2*(x*y - z*w), 2*(x*z + y*w)],
        [2*(x*y + z*w), 1 - 2*(x*x + z*z), 2*(y*z - x*w)],
        [2*(x*z - y*w), 2*(y*z + x*w), 1 - 2*(x*x + y*y)]
    ]

def decode_sh_band0(f_dc):
    SH_C0 = 0.28209479177387814
    return [max(0.0, min(1.0, 0.5 + SH_C0 * c)) for c in f_dc]

def inverse_2x2(M):
    det = M[0][0]*M[1][1] - M[0][1]*M[1][0]
    return [[M[1][1]/det, -M[0][1]/det], [-M[1][0]/det, M[0][0]/det]]

def mat_mul(A, B):
    return [[sum(A[i][k]*B[k][j] for k in range(len(B))) for j in range(len(B[0]))] for i in range(len(A))]

def transpose(M):
    return [[M[j][i] for j in range(len(M))] for i in range(len(M[0]))]

def vec3_add(a, b): return [a[0]+b[0], a[1]+b[1], a[2]+b[2]]
```

## Subtopics

### [Ray-marching on 3D Gaussians](1036-ray-marching-on-3d-gaussians.md)
A ray-marching algorithm implemented on 3D Gaussians to study the impact of approximations like spatial overlap and sorting in 3DGS.

### [EWA Splatting](1069-ewa-splatting.md)
A rendering technique that treats each point as a Gaussian reconstruction kernel on the surface, projects it into screen space, and convolves it with a low-pass filter to produce a resampling filter actually rasterized. This implementation uses a simplified kernel: screen-aligned spherical impostors with isotropic linear falloff, rasterized as plain point sprites, trading anisotropic, correctly band-limited footprint for a formulation needing no per-point normals or radii.

### [Self-Attenuation Rendering](1154-self-attenuation-rendering.md)
A rendering approach that correctly accounts for the attenuation of a Gaussian's own extinction along the ray path (self-attenuation), rather than ignoring it or using a first-order Taylor approximation.

### [Row-constant hoisting for Gaussian Splatting Rasterization](1195-row-constant-hoisting-for-gaussian-splatting-rasterization.md)
An optimization for the inner pixel loop of a Gaussian splatting rasterizer that hoists row-constant terms outside the inner (column) loop to minimize arithmetic operations per pixel.

### [2D Gaussian Projection with Covariance Stabilization](1198-2d-gaussian-projection-with-covariance-stabilization.md)
Computes the 2D screen-space covariance matrix and its inverse for a 3D Gaussian splat, ensuring numerical stability by adding a small epsilon to the diagonal to guarantee positive definiteness.

### Gaussian in the Wild (GS-W)
A method that separates intrinsic and dynamic appearance attributes per Gaussian point to mitigate transient occlusions and photometric variations. It employs an adaptive sampling strategy, leverages 2D visibility maps, uses depth regularization, and aligns pixel appearance features from image triplanes directly to 3D Gaussians [S8, unofficial].

### WildGaussians
A method for 'in-the-wild' settings that integrates robust DINO features and a lightweight appearance modeling module within the 3DGS framework. It handles unconstrained photo collections [S8, unofficial].

### 4D Gaussian Splatting
A method for modeling dynamic Gaussians for time-varying content. It develops a spatiotemporal structure encoder to capture deformations of both positions and colors over time [S8, unofficial].

### MIP-Splatting
An extension that introduces 2D and 3D Gaussian filters to improve robustness to aliasing caused by resolution changes [S1].

### 3DGUT
A method that employs an unscented transform for more precise Gaussian projection onto the image plane, improving the affine approximation of the projection operator [S8, unofficial].

### SWAG
A method that extends 3DGS by conditioning Gaussians on learned appearance embeddings and training unsupervised transient Gaussians to ignore occluders [S8, unofficial].

### Flash3D
A method that uses a feed-forward network (FFN) for monocular reconstruction, generating 3DGS scenes by estimating depth from a single view [S8, unofficial].

### GS-LRM
A method that tokenizes two to four images and their camera parameters, concatenates them, and passes them through a transformer block whose output tokens are decoded into Gaussian parameters [S8, unofficial].

### PixelSplat
A method that incorporates an epipolar transformer to generalize features between two views, paired with a probabilistic prediction of Gaussians aligned along camera-to-pixel rays [S8, unofficial].

### CoR-GS
A method that improves sparse-view reconstruction by defining two independent reconstructions and comparing them to discard inaccurate Gaussians [S8, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
*   **Memory:** Complex scenes require approximately 200,000–500,000 Gaussians, resulting in significant memory and storage demands [S1]. Each Gaussian stores position, scale, rotation, SH coefficients, and opacity [S3, S4, unofficial].
*   **Time:** Rendering is $O(M \cdot A)$, where $M$ is the number of Gaussians and $A$ is the average number of splats per pixel [G]. Training uses gradient descent to update Gaussian parameters, but the rasterization pipeline itself is highly optimized for real-time performance [S1][S8, unofficial].

**Performance:**
*   3DGS enables real-time rendering capabilities for novel view synthesis [S1][S8, unofficial].
*   It is significantly faster than NeRFs for rendering, as it avoids the need for volumetric ray marching and MLP evaluation [S1][S8, unofficial].

**Strengths and Limitations:**
*   **Strengths:** High-quality view synthesis, real-time rendering, differentiable optimization [S1][S8, unofficial].
*   **Limitations:** High memory footprint [S1]. The emission-absorption model limits performance on highly reflective surfaces and prevents relighting [S1]. Standard 3DGS uses a dilation-based filter which fails to suppress high-frequency artifacts when varying focal length or camera distance [S1]. Approximations in visibility resolution (sorting by centers) can cause popping artifacts [S2]. Self-attenuation is not treated correctly [S2].

**When to Use:**
*   Use for real-time novel view synthesis of static scenes with moderate complexity [S1][S8, unofficial].
*   Avoid for scenes with highly reflective surfaces or when relighting is required [S1].

## Background
3D Gaussian Splatting (3DGS) was introduced by Kerbl et al. in 2023 [S1][S8, unofficial]. It builds on EWA Volume Splatting [S1][S8, unofficial] and other point-based rendering works [S8, unofficial]. The method was developed to overcome the computational cost of evaluating the volume rendering equation via quadrature, which requires querying points outside Gaussian supports [S8, unofficial]. It provides a fast, high-quality alternative to NeRF by using a hybrid, primitive-based rendering method [S1].
