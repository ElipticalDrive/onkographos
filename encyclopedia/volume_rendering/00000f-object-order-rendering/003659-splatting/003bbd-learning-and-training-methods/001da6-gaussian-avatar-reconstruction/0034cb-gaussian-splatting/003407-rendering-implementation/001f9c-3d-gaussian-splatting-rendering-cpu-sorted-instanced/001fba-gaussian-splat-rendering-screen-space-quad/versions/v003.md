# Gaussian Splat Rendering (Screen-Space Quad)

Also called: RenderGaussianSplats, Splat Rendering

## Overview
This method renders 3D Gaussian Splatting scenes by projecting 3D Gaussian distributions into 2D screen-space quads, utilizing a pre-sorted order buffer and view-space projection data to handle transparency via alpha blending [S2, unofficial]. It is identical in geometry generation to Circle Splat [S1, unofficial]. Unlike its parent [3D Gaussian Splatting Rendering (CPU-Sorted, Instanced)](2058-3d-gaussian-splatting-rendering-cpu-sorted-instanced.md), which relies on instanced drawing with standard alpha blending, this method explicitly constructs screen-space quads in the vertex shader to allow for precise per-pixel Gaussian falloff evaluation and selection highlighting in the fragment shader [S2, unofficial].

## How it works
**Inputs:**
*   A pre-sorted order buffer (`_OrderBuffer`) mapping instance IDs to splat indices [S2, unofficial].
*   View-space projection data (`_SplatViewData`) containing axis vectors (`axis1`, `axis2`), center clip position, and compressed color for each splat [S2, unofficial].
*   Optional selection bits (`_SplatSelectedBits`) for debugging [S2, unofficial].
*   Uniforms: Model-View matrix (`MV`), Projection matrix (`P`), Screen resolution (`_ScreenParams.xy`), Splat size (`splatSize`), Scale, Grid length, and Frustum culling border parameters [S1, unofficial][S2, unofficial].

**Outputs:**
*   Framebuffer with composited splat colors and alpha [S2, unofficial].

**Data Structures:**
*   `SplatViewData`: Contains `axis1` (vec2), `axis2` (vec2), `centerClipPos` (vec4), and `color` (compressed half-floats) [S2, unofficial].
*   `_OrderBuffer`: Array of integers mapping draw call instance IDs to splat indices [S2, unofficial].

**Steps:**

1.  **Vertex Shader: Index Mapping and Visibility Check**
    *   Map the hardware instance ID to the splat index using the order buffer: `instID = _OrderBuffer[instanceID]` [S2, unofficial].
    *   Load the corresponding `SplatViewData` for `instID` [S2, unofficial].
    *   Check if the splat center is behind the camera (`centerClipPos.w <= 0`). If true, output a NaN vertex (`asfloat(0x7fc00000)`) to discard the primitive [S2, unofficial].

2.  **Vertex Shader: Quad Construction**
    *   Decompress the color from `view.color` (half-floats) into `o.col.rgba` using `f16tof32` [S2, unofficial].
    *   Determine the quad corner index `idx` (0-3) based on the primitive ID within the triangle strip.
    *   Calculate the normalized quad position in clip space: `quadPos = float2(idx & 1, (idx >> 1) & 1) * 2.0 - 1.0` [S2, unofficial].
    *   Scale the quad position: `quadPos *= 2.0` [S2, unofficial].
    *   Calculate the screen-space delta using the view-space axes and screen resolution: `deltaScreenPos = (quadPos.x * view.axis1 + quadPos.y * view.axis2) * 2.0 / _ScreenParams.xy` [S2, unofficial].
    *   Apply the delta to the vertex position in clip space, scaled by the clip-space w: `o.vertex.xy += deltaScreenPos * centerClipPos.w` [S2, unofficial].

3.  **Vertex Shader: Selection Highlight (Optional)**
    *   If `_SplatBitsValid` is true, calculate the word and bit index: `wordIdx = instID / 32`, `bitIdx = instID & 31` [S2, unofficial].
    *   Load the selection word and check the bit: `selVal = _SplatSelectedBits.Load(wordIdx * 4)` [S2, unofficial].
    *   If `(selVal & (1 << bitIdx))` is true, set `o.col.a = -1` to mark the splat as selected [S2, unofficial].

4.  **Fragment Shader: Gaussian Evaluation**
    *   Calculate the Gaussian falloff power using the fragment's local position `i.pos` (relative to quad center): `power = -dot(i.pos, i.pos)` [S2, unofficial].
    *   Compute alpha: `alpha = exp(power)` [S2, unofficial].
    *   **Selection Logic:**
        *   If not selected (`i.col.a >= 0`): Saturate alpha: `alpha = saturate(alpha * i.col.a)` [S2, unofficial].
        *   If selected (`i.col.a < 0`):
            *   If `alpha > 7.0/255.0`: Set `alpha = 1` and `i.col.rgb = selectedColor` (magenta) if `alpha < 10.0/255.0`; otherwise, set `alpha = saturate(alpha + 0.3)` and tint `i.col.rgb = lerp(i.col.rgb, selectedColor, 0.5)` [S2, unofficial].
    *   **Discard:** Discard the fragment if `alpha < 1.0/255.0` [S2, unofficial].
    *   **Output:** Return `res = half4(i.col.rgb * alpha, alpha)` [S2, unofficial].

**Pseudocode:**

```python
# Vertex Shader
def vertex_shader(instance_id, primitive_id):
    # 1. Map instance ID to splat index
    splat_index = OrderBuffer[instance_id]
    
    # 2. Load view data
    view = SplatViewData[splat_index]
    
    # 3. Check visibility (behind camera)
    if view.centerClipPos.w <= 0:
        return NaN_VERTEX
    
    # 4. Decompress color
    color_rgba = f16tof32(view.color)
    
    # 5. Calculate quad corner
    idx = primitive_id % 4
    quad_pos = float2((idx & 1), ((idx >> 1) & 1)) * 2.0 - 1.0
    quad_pos *= 2.0
    
    # 6. Calculate screen delta
    delta_screen = (quad_pos.x * view.axis1 + quad_pos.y * view.axis2) * 2.0 / ScreenParams.xy
    
    # 7. Apply delta to clip space position
    final_vertex = view.centerClipPos
    final_vertex.xy += delta_screen * view.centerClipPos.w
    
    # 8. Selection highlight
    if SplatBitsValid:
        word_idx = splat_index // 32
        bit_idx = splat_index & 31
        sel_val = SplatSelectedBits.Load(word_idx * 4)
        if (sel_val & (1 << bit_idx)):
            color_rgba.a = -1.0
            
    return VertexOutput(vertex=final_vertex, color=color_rgba)

# Fragment Shader
def fragment_shader(input_color, local_pos):
    # 1. Calculate Gaussian falloff
    power = -dot(local_pos, local_pos)
    alpha = exp(power)
    
    # 2. Handle selection
    if input_color.a >= 0:
        # Not selected
        alpha = saturate(alpha * input_color.a)
    else:
        # Selected
        if alpha > 7.0 / 255.0:
            if alpha < 10.0 / 255.0:
                alpha = 1.0
                rgb = SelectedColor # Magenta
            else:
                alpha = saturate(alpha + 0.3)
                rgb = lerp(input_color.rgb, SelectedColor, 0.5)
        else:
            rgb = input_color.rgb
            
    # 3. Discard low alpha
    if alpha < 1.0 / 255.0:
        discard()
        
    # 4. Output
    return half4(rgb * alpha, alpha)
```

**Parameters:**
*   `_ScreenParams.xy`: Screen resolution in pixels, used to normalize the screen-space delta of the quad [S2, unofficial].
*   `splatSize`, `scale`, `gridLength`: Used in alternative geometry generation methods (e.g., Circle Splat) to calculate voxel offset [S1, unofficial].

**Edge Cases and Pitfalls:**
*   Splats behind the camera (`clip-space w <= 0`) must be discarded to prevent rendering artifacts. This is handled by outputting a NaN vertex in the vertex shader [S2, unofficial].
*   Precision issues in half-float decompression may affect color accuracy; `f16tof32` should be used for conversion [S2, unofficial].

## Subtopics

### [WebGL Gaussian Splatting](2084-webgl-gaussian-splatting.md)
WebGL Gaussian Splatting is a real-time rendering technique for 3D Gaussian Splatting (3DGS) scenes in web browsers, typically implemented using WebGL 1.0 and libraries like Three.js. It solves the problem of displaying large-scale, photorealistic radiance field reconstructions on standard client hardware without requiring neural network inference or heavy server-side processing. Unlike parent method [Gaussian Splat Rendering (Screen-Space Quad)](2075-gaussian-splat-rendering-screen-space-quad.md), which relies on a pre-sorted order buffer and view-space projection data, this method performs depth sorting in a JavaScript Web Worker and projects 3D Gaussians into screen-space quads using custom vertex and fragment shaders. It sets itself apart from sibling [Gaussian Splat Fragment Shader](3258-gaussian-splat-fragment-shader.md) by providing the complete pipeline, including data parsing, instance matrix construction, and CPU-side sorting, rather than just the shading logic.

### [Gaussian Splat Fragment Shader](3258-gaussian-splat-fragment-shader.md)
The Gaussian Splat Fragment Shader evaluates the 2D Gaussian alpha value at each fragment to determine splat coverage and modulates the fragment color accordingly. It composites the new splat over the existing framebuffer color using pre-multiplied alpha blending. It is distinguished from its parent method by handling the per-pixel transparency logic, alpha cutoffs, and framebuffer packing directly in the fragment stage, rather than relying on CPU-side sorting or generic quad rasterization [G].

### [Gaussian Splat Shader Property Configuration](3596-gaussian-splat-shader-property-configuration.md)
Configures the material property block (or uniform buffer) with splat count, spherical harmonic (SH) degree, brightness, scale, antialiasing, transform matrix, and optional skinning/volume lighting data for the GPU render pass. It ensures that the fragment shader receives valid sampled resources even when advanced features like rigging are disabled, preventing compilation or runtime errors.

### Debug Splat Point Rendering
Renders small quads at the center of each splat for debugging, optionally displaying the splat index as color [S2, unofficial]. The vertex shader loads splat data, transforms the center to world and then clip space, and applies a small offset in screen space based on `_SplatSize` and `_ScreenParams.xy` [S2, unofficial]. If `_DisplayIndex` is true, the splat index is encoded into the RGB color channels (`r = frac(index / count * 100)`, `g = frac(index / count * 10)`, `b = index / count`) [S2, unofficial]. Inputs include `float _SplatSize`, `bool _DisplayIndex`, and `int _SplatCount` [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Dominated by the vertex shader per-splat processing and fragment shader evaluation. Sorting is performed on the CPU (inherited from parent method).
*   **Memory Complexity:** Requires storage for the order buffer, view data, and selection bits.
*   **Strengths:** Precise control over per-pixel Gaussian falloff and selection highlighting. Efficient use of standard alpha blending.
*   **Limitations:** Relies on CPU-side sorting. Performance may degrade with very high splat counts due to vertex/fragment shader overhead.
*   **When to use:** When precise visual feedback (e.g., selection outlines) and exact Gaussian falloff are required.
*   **When not to use:** When extreme performance is needed and selection/debugging features are not required; consider instanced rendering or tiled rasterization.

## Background
This method is used for Gaussian Splat visualization, projecting voxels as 2D quads [S1, unofficial]. It is implemented in Unity-based Gaussian Splatting tools [S2, unofficial].
