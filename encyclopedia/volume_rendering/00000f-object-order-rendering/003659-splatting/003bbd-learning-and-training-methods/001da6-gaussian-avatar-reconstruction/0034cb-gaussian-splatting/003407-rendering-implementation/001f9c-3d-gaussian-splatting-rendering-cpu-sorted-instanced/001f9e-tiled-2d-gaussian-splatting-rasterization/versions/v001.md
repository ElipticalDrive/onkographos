# Tiled 2D Gaussian Splatting Rasterization

Also called: tile-based rasterizer

## Overview
A GPU-parallel rasterization method for 3D Gaussian Splatting that divides the image into tiles to manage memory and processing load, assigning Gaussians to tiles based on their axis-aligned bounding boxes (AABBs) [S1, unofficial]. It sets itself apart from non-tiled approaches by replacing per-pixel iteration with tile-based work distribution, enabling a single global radix sort to order splats for both rendering and backpropagation [S3, unofficial]. This method is distinct from [Gaussian Splat Projection and Sorting](3369-gaussian-splat-projection-and-sorting.md) by handling the actual rasterization loop and from [Tile-Based Culling](2819-tile-based-culling.md) by using standard AABB assignment rather than iterative opacity-aware culling [S1, unofficial].

## How it works
**Inputs:**
- `gs`: A set of $N$ 3D Gaussians, each defined by mean position $\mu \in \mathbb{R}^3$, covariance matrix $\Sigma \in \mathbb{R}^{3 \times 3}$, opacity $\alpha \in [0, 1]$, and spherical harmonic coefficients for color.
- `camera`: Pinhole camera model with intrinsic parameters $(f_x, f_y, c_x, c_y)$, extrinsic rotation $R \in SO(3)$ and translation $t \in \mathbb{R}^3$, image dimensions $W \times H$, and near/far planes.
- `tile_size`: Integer, default 32.
- `sigma_multiplier`: Float, typically 3.0, controlling the extent of the Gaussian bounding box.

**Outputs:**
- `color`: Tensor of shape $[3, H, W]$ with values in $[0, 1]$.
- `alpha`: Tensor of shape $[H, W]$ with values in $[0, 1]$.

**Data Structures:**
- `tile_dict`: A mapping from tile index $(u, v)$ to a list of Gaussian indices contained in that tile.
- `conics`: Precomputed inverse 2D covariance matrices for each Gaussian, stored as $[N, 3]$ tensors $(a, b, c)$.
- `means_image`: Projected 2D means for each Gaussian, stored as $[N, 2]$ tensors $(u, v)$.

**Steps:**

1. **Initialization:**
   Initialize background color tensor `bg` of shape $[3, H, W]$ with black values (0.0) and clone it. Initialize output color tensor `color` of shape $[3, H, W]$ and alpha tensor `alpha` of shape $[H, W]$ to zeros.

2. **Transformation and Projection:**
   Transform Gaussian means to camera space: $\mu_{cam} = R \mu + t$.
   Project to image plane: $u = f_x \frac{x_{cam}}{z_{cam}} + c_x$, $v = f_y \frac{y_{cam}}{z_{cam}} + c_y$.
   Perform frustum culling: discard Gaussians with $z_{cam} < near\_plane$ or $z_{cam} > far\_plane$. Apply a field-of-view margin if specified.

3. **Covariance Approximation:**
   Rotate 3D covariances to camera space: $\Sigma_{cam} = R \Sigma R^T$.
   Approximate 2D covariances using the Jacobian of the perspective projection. Let $J$ be the Jacobian of the projection function with respect to the 3D point. The 2D covariance is $\Sigma_{2D} = J \Sigma_{cam} J^T$. Add a small epsilon ($\epsilon_{2d} \approx 0.3$) to the diagonal to ensure numerical stability.

4. **Conic Computation:**
   Compute the conics (inverse 2D covariance matrices) for each Gaussian:
   $$
   C = \Sigma_{2D}^{-1} = \begin{bmatrix} a & b \\ b & c \end{bmatrix}
   $$
   Store $a, b, c$ for each Gaussian.

5. **Bounding Box and Tile Assignment:**
   Compute the axis-aligned bounding box (AABB) for each Gaussian in screen space. The extent is determined by the eigenvalues of $\Sigma_{2D}$ scaled by `sigma_multiplier` (typically 3.0 for 3-sigma).
   Assign each Gaussian to all tiles its AABB overlaps. Store these assignments in `tile_dict`.

6. **Sorting:**
   Create a list of work items, each containing a Gaussian index and its tile index.
   Perform a single GPU radix sort over combined keys: primary key is tile index, secondary key is camera-space depth of the Gaussian mean. This orders splats front-to-back within each tile. [S3, unofficial]

7. **Rasterization Loop:**
   Iterate over each tile $(tile\_idx\_u, tile\_idx\_v)$ in `tile_dict`.
   - If the tile has no Gaussians, continue.
   - Extract contiguous tensors for the tile: `opacities_tile`, `sh_colors_tile`, `means_image_tile`, `conics_tile`.
   - Calculate pixel bounds:
     $$
     u_{start} = tile\_idx\_u \times tile\_size, \quad v_{start} = tile\_idx\_v \times tile\_size
     $$
     $$
     u_{end} = \min(u_{start} + tile\_size, W), \quad v_{end} = \min(v_{start} + tile\_size, H)
     $$
   - Iterate over pixels $u_{pix}$ from $u_{start}$ to $u_{end}$ and $v_{pix}$ from $v_{start}$ to $v_{end}$.
   - For each pixel, iterate over the sorted Gaussians in the tile.
     - **Early Termination:** If `alpha[v_pix, u_pix] >= 0.99`, skip remaining Gaussians for this pixel.
     - **Color Evaluation:** Evaluate spherical harmonics color $C_{SH}$ using the view direction.
     - **Distance Calculation:** Compute squared Mahalanobis distance:
       $$
       dist\_sq = a \cdot du^2 + 2 \cdot b \cdot du \cdot dv + c \cdot dv^2
       $$
       where $du = u_{pix} - u_{mean}$ and $dv = v_{pix} - v_{mean}$.
     - **Alpha and Color Contribution:**
       $$
       \alpha_g = \alpha_{gaussian} \cdot \exp(-0.5 \cdot dist\_sq)
       $$
       $$
       color\_contrib = C_{SH} \cdot \alpha_g
       $$
       Update pixel color and alpha using front-to-back blending:
       $$
       color[v_{pix}, u_{pix}] += color\_contrib \cdot (1 - alpha[v_{pix}, u_{pix}])
       $$
       $$
       alpha[v_{pix}, u_{pix}] += \alpha_g \cdot (1 - alpha[v_{pix}, u_{pix}])
       $$

8. **Background Compositing:**
   After processing all tiles, add the background:
   $$
   color += bg \cdot (1 - alpha)[None, :, :]
   $$

9. **Clamping and Conversion:**
   Clamp `color` to $[0.0, 1.0]$. Convert to uint8 by multiplying by 255.

**Pseudocode:**

```python
def render_splats_tiled(gs, camera, tile_size=32, sigma_multiplier=3.0):
    H, W = camera.height, camera.width
    bg = torch.zeros(3, H, W, device=gs.device)
    color = torch.zeros(3, H, W, device=gs.device)
    alpha = torch.zeros(H, W, device=gs.device)

    # 1. Transform and Project
    means_cam = camera.transform_points_world_to_cam(gs.means)
    means_img = camera.project_points_cam_to_image_plane(means_cam)
    
    # 2. Frustum Culling
    # Filter by near/far planes and image bounds
    valid_mask = (means_cam[:, 2] > camera.near_plane) & \
                 (means_cam[:, 2] < camera.far_plane) & \
                 (means_img[:, 0] >= -0.3) & \
                 (means_img[:, 0] <= W + 0.3) & \
                 (means_img[:, 1] >= -0.3) & \
                 (means_img[:, 1] <= H + 0.3)
    
    gs_filtered = gs[valid_mask]
    means_img_filtered = means_img[valid_mask]
    means_cam_filtered = means_cam[valid_mask]

    # 3. Covariance and Conics
    covs_cam = camera.rotate_covariances_world_to_cam(gs.covariances)
    covs_2d = approximate_2d_covariances(covs_cam, means_cam_filtered, camera)
    conics = compute_conics(covs_2d) # Returns [N, 3] (a, b, c)

    # 4. Bounding Boxes and Tile Assignment
    bboxes = compute_axis_aligned_bounding_box(means_img_filtered, covs_2d, sigma_multiplier)
    tile_dict = assign_gaussians_to_tiles(bboxes, means_img_filtered, tile_size, W, H)

    # 5. Sorting
    # Create work items: (tile_idx, depth, gaussian_idx)
    work_items = []
    for tile_idx, g_indices in tile_dict.items():
        for g_idx in g_indices:
            depth = means_cam_filtered[g_idx, 2]
            work_items.append((tile_idx, depth, g_idx))
    
    # Sort by tile_idx then depth
    work_items.sort(key=lambda x: (x[0], x[1]))

    # 6. Rasterization
    for tile_idx, depth, g_idx in work_items:
        tile_u, tile_v = divmod(tile_idx, int(W / tile_size))
        
        u_start = tile_u * tile_size
        v_start = tile_v * tile_size
        u_end = min(u_start + tile_size, W)
        v_end = min(v_start + tile_size, H)
        
        # Extract tile data
        # Note: In a real GPU implementation, this is done via gather/scatter or texture fetches
        # Here we simulate the extraction for clarity
        tile_g_indices = [g for t, d, g in work_items if divmod(t, int(W / tile_size))[0] == tile_u and divmod(t, int(W / tile_size))[1] == tile_v]
        
        # Re-sort tile-specific items to ensure front-to-back within tile
        tile_g_indices.sort(key=lambda g: means_cam_filtered[g, 2])

        for u_pix in range(u_start, u_end):
            for v_pix in range(v_start, v_end):
                if alpha[v_pix, u_pix] >= 0.99:
                    continue
                
                for g_idx in tile_g_indices:
                    # Retrieve properties
                    opacity = gs_filtered.opacities[g_idx]
                    sh_color = eval_spherical_harmonics_color(gs_filtered.sh_coeffs[g_idx], view_dir)
                    a, b, c = conics[g_idx]
                    u_mean, v_mean = means_img_filtered[g_idx]
                    
                    du = u_pix - u_mean
                    dv = v_pix - v_mean
                    
                    dist_sq = a * du**2 + 2 * b * du * dv + c * dv**2
                    alpha_g = opacity * torch.exp(-0.5 * dist_sq)
                    
                    color[:, v_pix, u_pix] += sh_color * alpha_g * (1 - alpha[v_pix, u_pix])
                    alpha[v_pix, u_pix] += alpha_g * (1 - alpha[v_pix, u_pix])
                    
                    if alpha[v_pix, u_pix] >= 0.99:
                        break

    # 7. Background
    color += bg * (1 - alpha)[None, :, :]
    
    # 8. Clamp and Convert
    color = torch.clamp(color, 0.0, 1.0)
    return color, alpha
```

## Subtopics

### [Non-Tiled 2D Gaussian Splatting with Transmittance Culling](2067-non-tiled-2d-gaussian-splatting-with-transmittance-culling.md)
A CPU-based rasterization method that iterates over Gaussians rather than tiles, using AABBs to limit pixel iteration and transmittance-based early ray termination. It produces visually identical results to tiled rasterization in most cases but is significantly faster due to early stopping and better culling. Choose this when CPU resources are available and tile overhead is undesirable. Link: [Non-Tiled 2D Gaussian Splatting with Transmittance Culling](2067-non-tiled-2d-gaussian-splatting-with-transmittance-culling.md).

### [Tile-Based Culling](2819-tile-based-culling.md)
A method for computing a precise mapping between 3D Gaussians and image tiles, designed to cull irrelevant tiles during rasterization. It improves upon standard conservative bounding box assignment by computing tight, opacity-aware bounding boxes and iteratively verifying tile intersections. It is distinguished from [SnugBox](3378-snugbox.md) by its iterative tile examination process, which results in higher runtime costs for the culling phase compared to AccuTile, though it may show marginal downstream performance gains due to undercounting artifacts. Choose this when minimizing the number of processed splats is critical and culling overhead is acceptable. Link: [Tile-Based Culling](2819-tile-based-culling.md).

### [Gaussian Splat Projection and Sorting](3369-gaussian-splat-projection-and-sorting.md)
A compute-shader-based stage that projects 3D Gaussians to 2D screen space, performs visibility and frustum culling, computes lighting, and prepares data for tile-based sorting. It serves as the bridge between raw 3D Gaussian data and the tiled rasterization pipeline, ensuring that only visible splats are processed and that they are ordered by tile and depth for efficient rendering. It differs from non-tiled approaches by explicitly preparing tile-boundary data and from tile-based culling by handling the full projection and sorting key generation. Choose this as the preprocessing step for tiled rasterization. Link: [Gaussian Splat Projection and Sorting](3369-gaussian-splat-projection-and-sorting.md).

### Opacity-Thresholded Tile Intersection Filtering
A variant that filters out Gaussians whose opacity $\tau$ falls below an alpha-threshold $\epsilon$ immediately during tile intersection, as their AABB is considered empty [S2]. The alpha-threshold $\epsilon$ is a parameter. Combining this modification with others decreased rendering time on the Bicycle scene at native resolution by a factor of 3.77 and GPU memory usage by a factor of 2.11 compared to the reference [S2].

### Tile-based Rasteriser
A rendering component that sorts primitives once per frame to serve both forward rendering and backpropagation [S3, unofficial]. It divides the image into 16x16-pixel tiles, assigns each Gaussian to every tile its projected 2D splat touches, and performs a single GPU radix sort over combined tile-and-depth keys to order all items at once, resulting in front-to-back order within each tile [S3, unofficial]. Every tile is processed by one GPU thread block that walks the sorted list and applies blending, stopping early once a pixel is effectively opaque [S3, unofficial]. Sorting per pixel is too slow for millions of splats; tile-based sorting with a single global radix sort is required for real-time performance [S3, unofficial]. One sort per frame is shared by both rendering and training [S3, unofficial]. The backward pass reuses the same sorted lists for training, allowing gradients to flow to position, shape, opacity, and color without additional sorting [S3, unofficial].

### Splat Batching Strategy
A strategy where splats are processed in batches. The parameter `gaussians_per_splat` controls this: if -1, splats all Gaussians in one call; if positive, splits into batches. Higher values increase speed but raise GPU memory usage [S4, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N \log N)$ for sorting $N$ Gaussians, plus $O(T \cdot P \cdot K)$ for rasterization, where $T$ is the number of tiles, $P$ is pixels per tile, and $K$ is average splats per tile. The single global radix sort is the dominant cost for large $N$ [S3, unofficial].
- **Memory Complexity:** $O(N + T \cdot P)$ for storing work items and tile data. Batching can reduce peak memory usage at the cost of increased kernel launch overhead [S4, unofficial].
- **Measured Performance:** On the Mip-NeRF360 benchmark, the method reaches 27.21 dB PSNR and 0.214 LPIPS at 134 fps, surpassing previous quality leaders in perceptual similarity while rendering roughly three orders of magnitude faster than NeRF-based methods [S3, unofficial].
- **Scaling:** Performance gains from precomputation (like opacity-thresholded filtering) are greatest at higher rendering resolutions [S2]. Increasing tile size (e.g., to 16x32) can increase render time on low-resolution scenes like Bicycle to 9.77 ms, indicating optimal tile size depends on resolution [S2].
- **Strengths:** Real-time performance on consumer hardware, support for training via shared sorting, efficient memory usage via tiling.
- **Limitations:** Sorting overhead for very large scenes, potential artifacts from early termination thresholds.
- **When to use:** Real-time rendering and training of 3D Gaussian Splatting scenes.
- **When not to use:** Offline rendering where extreme quality is prioritized over speed and sorting overhead is negligible, or on hardware without efficient radix sort support.

## Background
Originated in the 3D Gaussian Splatting paper (Kerbl et al., 2023), the tiled rasterization method was introduced to enable real-time rendering and training of millions of Gaussians [S3, unofficial]. It builds on the EWA splatting technique and spherical harmonic color representation. The method has been refined through various optimizations, including opacity-thresholded culling and batching strategies [S1, unofficial][S2][S4, unofficial]. It is widely used in Gaussian Avatar Reconstruction and novel-view synthesis applications.
