# iVR-GS Relighting via Gaussian Primitives

Also called: iVR-GS

## Overview
iVR-GS is a relighting method for volumetric visualization (VolVis) scenes that leverages composable and editable 3D Gaussian primitives to enable flexible exploration without access to the underlying volume data [S1]. It distinguishes itself from naive image-space techniques, such as linear interpolation (LERP) of rendered images, by explicitly modeling scene geometry to produce faithful relighting results [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A pre-trained iVR-GS scene representation consisting of 3D Gaussian primitives. The primitives are parameterized with geometry attributes (position, covariance, opacity) and shading attributes (color, specular properties) [S1].
*   **Output:** A sequence of rendered images corresponding to different light source polar angles.

**Data Structures:**
The scene is represented by a set of Gaussian primitives. Each primitive $i$ contains:
*   Position $\mathbf{p}_i$
*   Covariance matrix $\Sigma_i$ (defining shape and orientation)
*   Opacity $\alpha_i$
*   Color/Shading parameters (diffuse and specular components compatible with the Blinn-Phong model) [S1].

**Method Steps:**
1.  **Light Source Alignment:** Fix the azimuthal angle of the light source to be identical to the camera's azimuthal angle. This simplifies the lighting trajectory to a single degree of freedom [S1].
2.  **Polar Angle Adjustment:** Define the light source polar angle $\theta$ to vary from $-90^\circ$ (bottom) to $90^\circ$ (top) [S1].
3.  **Trajectory Sampling:** Uniformly sample 180 images along this light source trajectory [S1].
4.  **Rendering:** For each sampled polar angle, render the scene using the Gaussian primitives. The lighting effect is modeled using the Blinn-Phong model [S1].

**Formulas:**
The lighting model used is the Blinn-Phong model [S1]. The specific mathematical formulation for the Blinn-Phong shading applied to the Gaussian primitives is not detailed in the provided sources, but the model is explicitly cited as the mechanism for modeling lighting effects [S1].

**Parameters:**
*   Number of sampled images: 180 [S1].
*   Polar angle range: $-90^\circ$ to $90^\circ$ [S1].

**Edge Cases and Pitfalls:**
*   **Lighting Model Mismatch:** iVR-GS relies on the Blinn-Phong model. It may encounter challenges when handling VolVis scenes that employ a different lighting model, potentially requiring a redesign of the lighting representation [S1].
*   **Geometry Dependency:** Unlike image-space interpolation, iVR-GS requires accurate geometry modeling. Straightforward image-space operations (like LERP) fail to produce faithful results because they do not account for geometry [S1].

**Pseudocode:**
```python
def relight_ivrgs(scene_gaussians, camera_azimuth, num_samples=180):
    """
    Relights a scene represented by iVR-GS Gaussian primitives.
    
    Args:
        scene_gaussians: List of Gaussian primitives with position, covariance, opacity, and shading.
        camera_azimuth: The azimuthal angle of the camera (fixed for light source).
        num_samples: Number of images to generate along the polar trajectory.
        
    Returns:
        List of rendered images.
    """
    images = []
    # Polar angle ranges from -90 to 90 degrees
    polar_angles = linspace(-90, 90, num_samples)
    
    for theta in polar_angles:
        # Set light source direction based on fixed azimuth and current polar angle
        # Note: Exact vector conversion from spherical to Cartesian depends on coordinate system
        light_direction = spherical_to_cartesian(azimuth=camera_azimuth, polar=theta)
        
        # Render scene using Blinn-Phong model
        # This involves projecting Gaussians to screen space and shading them
        image = render_gaussians(scene_gaussians, light_direction=light_direction)
        images.append(image)
        
    return images
```

## Subtopics

### [Editable Gaussian Representation](7495-editable-gaussian-representation.md)
A Gaussian primitive parameterized with geometry attributes and shading attributes to allow explicit editing of color, opacity, and lighting.

## Operating characteristics
*   **Time and Memory Complexity:** Not given in the sources.
*   **Measured Performance:** iVR-GS produces higher-quality reconstruction results compared to Plenoxels, CCNeRF, and base 3DGS [S1]. It supports real-time scene editing [S1].
*   **Strengths and Limitations:**
    *   **Strengths:** Supports flexible exploration without access to volume data; higher quality than NeRF-based methods for basic scenes; supports real-time editing [S1].
    *   **Limitations:** Relies on the Blinn-Phong model, which may not fit all VolVis scenes; incurs extra training costs if dynamic updates are required, potentially needing remote workstations [S1].
*   **When to use:** When flexible exploration and relighting of VolVis scenes are needed without volume data access, and the scene lighting can be approximated by Blinn-Phong [S1].
*   **When not to use:** When the scene uses a complex lighting model incompatible with Blinn-Phong, or when computational resources for training are limited and dynamic updates are frequent [S1].

## Background
iVR-GS (Inverse Volume Rendering for Explorable Visualization via Editable 3D Gaussian Splatting) is an NVS (Novel View Synthesis) framework designed for VolVis scenes [S1]. It was presented in a paper published in 2025 [S1]. The method overcomes existing NVS limitations by leveraging numerous composable and editable Gaussian primitives [S1].
