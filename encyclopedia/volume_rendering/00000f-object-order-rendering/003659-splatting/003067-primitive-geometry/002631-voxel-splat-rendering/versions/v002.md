# Voxel Splat Rendering

Also called: Interactive Splat Rendering with Alpha/Gamma Control, Interactive value selection rendering

## Overview
Voxel Splat Rendering is an object-order volume rendering technique that projects 3D voxels onto the 2D image plane as geometric primitives (splats), typically quads or circles, which are then rasterized and blended [S2, S3, unofficial]. It solves the problem of interactive visualization of large volumetric datasets by leveraging hardware-accelerated rasterization pipelines, allowing for real-time interaction such as slice-based value selection and parameter tuning [S2, unofficial]. Unlike ray-casting methods that compute contributions per pixel, this method computes contributions per voxel, making it distinct from siblings like Circle Splat Rendering which may use different primitive shapes or kernel approximations [S2, S3, unofficial].

## How it works
**Inputs:** A 3D volumetric dataset (voxels with position, color, and optionally normal/density attributes); a camera view (eye position, projection matrix); and rendering parameters (point size, alpha, gamma).
**Outputs:** A 2D color image.

**Data Structures:**
*   **Voxel:** Contains position $(x, y, z)$, color $(r, g, b)$, and optionally a normal vector $\mathbf{n}$. In out-of-core implementations, voxels are stored with relative positions to reduce disk I/O [S2, unofficial].
*   **Normal Storage:** Normals can be quantized to one of 240 pre-defined directions distributed nearly uniformly over a sphere (derived from a dodecahedron triangulation), stored in 1 byte [S2, unofficial].
*   **Bounding Box:** A pre-defined region used to filter voxels during interactive selection to reduce decoding overhead [S2, unofficial].

**Steps:**

1.  **Front-to-Back Traversal:** Traverse the 3D dataset in front-to-back order relative to the current camera view [S3, unofficial]. This ensures correct alpha blending accumulation.
2.  **Voxel Selection (Optional):** If interactive value selection is active, retrieve and decode only voxels corresponding to selected colors within a pre-defined bounding box [S2, unofficial]. This handles cases where different tissues share similar colors by limiting the rendered subset [S2, unofficial].
3.  **Projection and Splat Generation:** For each voxel $k$:
    *   Project the voxel center to screen space.
    *   Determine the screen-space footprint. The contribution is highest at the center and drops off away from it [S3, unofficial].
    *   Render the voxel as a square or circular splat (quad or point) using GL commands/extensions [S2, unofficial]. The diameter can be fixed or distance-dependent [S2, unofficial].
4.  **Weighting (For Multi-View/Texture Mapping):** If weighting contributions based on camera visibility (e.g., for image-based modeling), compute weights for each camera $i$ [S1]:
    *   Let $\mathbf{V}_{toEye}$ be the unit vector from the voxel center to the eye point.
    *   Let $\mathbf{N}$ be the unit normal to the surface at the voxel center.
    *   Let $\mathbf{V}_{toCamera}[i]$ be the unit vector from the voxel center to camera $i$'s position.
    *   Calculate view weight: $w_V = \max(0, \mathbf{V}_{toEye} \cdot \mathbf{V}_{toCamera}[i])^4$.
    *   Calculate normal weight: $w_N = \max(0, \mathbf{N} \cdot \mathbf{V}_{toCamera}[i])^4$.
    *   Total weight: $w[i] = w_V \cdot w_N$.
    *   Normalize weights by dividing by the sum of all weights [S1].
5.  **Rasterization and Blending:**
    *   If alpha-blending is enabled, blend the splat's color into the frame buffer using the computed weights and alpha/gamma parameters [S2, unofficial].
    *   If alpha-blending is disabled, use the stored normals to shade the points, creating an illusion of a shaded surface if point density is high [S2, unofficial].
    *   Apply gamma correction to reduce the contribution of points from tissues with differing color value densities [S2, unofficial].

**Pseudocode:**

```python
def render_voxel_splats(voxels, camera, params):
    # Sort voxels back-to-front relative to camera
    sorted_voxels = sort_by_depth(voxels, camera.eye_position)
    
    # Initialize frame buffer
    frame_buffer = zeros(camera.resolution)
    
    for voxel in sorted_voxels:
        # 1. Project voxel to screen space
        screen_pos = project(voxel.position, camera.mvp_matrix)
        
        # 2. Determine splat footprint (quad/circle)
        # Size can be fixed or distance-dependent
        splat_size = params.point_size * (1.0 + params.distance_factor * distance(voxel.position, camera.eye_position))
        
        # 3. Compute weight if multi-view weighting is active
        weight = 1.0
        if params.use_weighting:
            v_to_eye = normalize(camera.eye_position - voxel.position)
            v_to_cam = normalize(camera.camera_positions - voxel.position) # Vector for specific camera
            n = voxel.normal
            
            dot_v = max(0.0, dot(v_to_eye, v_to_cam))
            dot_n = max(0.0, dot(n, v_to_cam))
            
            # Power exponent 4 reduces artifacts in transitions
            w_v = pow(dot_v, 4)
            w_n = pow(dot_n, 4)
            weight = w_v * w_n
            
        # 4. Apply Alpha and Gamma
        alpha = params.alpha * weight
        color = apply_gamma(voxel.color, params.gamma)
        
        # 5. Rasterize Splat
        # Render as quad or point using hardware rasterization
        # Blend into frame buffer
        blend_pixel(screen_pos, color, alpha, frame_buffer)
        
    return frame_buffer
```

**Edge Cases and Pitfalls:**
*   **Close-range views:** Voxel splats may appear as rectangular blocks covering many pixels, causing pixelation artifacts due to the finite resolution of RGB images [S1].
*   **Single-pixel quads:** GPU rasterization is not optimized for single-pixel quads, though performance remains acceptable [S1].
*   **Aliasing:** Minor aliasing artifacts similar to non-anti-aliased triangle models may occur [S1].
*   **Color Ambiguity:** Different tissues may share similar colors, requiring bounding box filtering or alpha/gamma tuning to isolate features [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of voxels $N$, $O(N)$, assuming constant-time projection and rasterization [S3, unofficial].
*   **Memory Complexity:** Depends on the dataset size and whether out-of-core techniques are used. Out-of-core approaches reduce memory footprint by loading only selected voxelsets [S2, unofficial].
*   **Performance:** Enables real-time interactivity due to hardware acceleration [S2, unofficial]. Performance is acceptable even for giga-voxel resolutions at HD resolution, though single-pixel quads are not optimized by GPUs [S1].
*   **Strengths:** Simple implementation, efficient for large datasets via out-of-core loading, supports interactive value selection and parameter tuning [S2, unofficial].
*   **Limitations:** Artifacts at close range (blockiness, pixelation), aliasing, and potential over-rendering if color selection is not precise [S1][S2, unofficial].

## Background
Voxel Splat Rendering was first published in [20] (cited in [S3, unofficial]). It is an object-space front-to-back volume rendering method [S3, unofficial]. The technique has been extended to support interactive visualization of very large datasets using out-of-core point-based approaches, allowing for real-time decoding and rendering [S2, unofficial]. It is also applied in image-based modeling contexts, such as sparse voxelization for novel view synthesis [S1].
