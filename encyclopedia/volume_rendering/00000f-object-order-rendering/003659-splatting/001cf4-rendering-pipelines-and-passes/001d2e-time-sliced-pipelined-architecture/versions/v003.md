# Time-Sliced Pipelined Architecture

Also called: Multi-core time-sliced pipeline, Time-slicing

## Overview
A hardware architecture for volume rendering where functional blocks are time-sliced to allow simultaneous processing of multiple tasks, enabling real-time rendering and continuous hardware-software communication [S1, unofficial]. It sets itself apart from standard sequential pipelines by overlapping execution stages through time-slicing and component reusability, allowing independent sub-cores to execute specific operations concurrently [S1, unofficial].

## How it works
The architecture decomposes the rendering pipeline into independent, reusable functional blocks (sub-cores) that are configured or replicated based on processing requirements. Time-slicing allows these blocks to overlap execution, processing several tasks simultaneously [S1, unofficial].

**Inputs and Outputs:**
*   **Input:** Voxel data, configuration parameters, context data.
*   **Output:** Rendered pixel values.

**Data Structures:**
*   **Context RAM:** Stores intermediate results (e.g., dot products) for reuse across components.
*   **Normal Mode Registers:** Provide common interface communication between components [S1, unofficial].
*   **Context Address Snooping Mechanism:** Allows stored information in Context RAM to be accessible by other components [S1, unofficial].

**Steps:**
1.  **Decomposition:** Divide the rendering pipeline into functional blocks: classifier, gradient calculator, shearing-warping block, shader, and composer [S1, unofficial].
2.  **Component Implementation:** Implement blocks as independent reusable components/sub-cores. Basic functional blocks (multipliers, adders, inner product processors) form a hardware "library" [S1, unofficial].
3.  **Configuration/Replication:** Based on the type of processing required by the calling module, the embedded sub-core is configured or replicated to execute a specific operation [S1, unofficial].
4.  **Time-Sliced Execution:** Use time-slicing to overlap execution stages, allowing simultaneous processing of several tasks [S1, unofficial].
5.  **Data Sharing:** Compute values once (e.g., dot product of incoming voxel) and store them in RAM cells to be called up by another component in subsequent clock cycles [S1, unofficial].
6.  **Communication:** Components communicate via a common interface provided by Context RAM, normal mode registers, and context address snooping [S1, unofficial].

## Subtopics

### Vg500 Parallel Pipeline Architecture
An ASIC implementation using four parallel rendering pipelines to achieve real-time rendering rates by processing adjacent voxel values in the x-direction [S2, unofficial]. It sets itself apart by using shift registers to pass values between neighboring pipelines in the same cycle, rather than recirculating them within a single pipeline [S2, unofficial]. Choose this when high-throughput, fixed-function real-time rendering of large voxel datasets is required [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Each pipeline operates at 133 MHz and can accept a new voxel every cycle [S2, unofficial]. Four pipelines provide approximately 532 million voxels per second, sufficient for 256^3 voxels at 30 fps [S2, unofficial].
*   **Memory Complexity:** The vg500 chip contains 2 Mbits of on-chip SRAM and interfaces with off-chip Voxel Memory (up to 128 MB using 16 SDRAMs) and off-chip Pixel Memory [S2, unofficial].
*   **Measured Performance:** The vg500 chip, fabricated in 0.35 technology with ~3.2 million transistors, runs at 133 MHz [S2, unofficial].
*   **Scaling:** Scaling is achieved by adding parallel pipelines (e.g., four pipelines for 256^3 at 30 fps) [S2, unofficial].
*   **Strengths:** Real-time rendering capability, component reusability, simplified layout due to hierarchical design [S1, unofficial][S2, unofficial].
*   **Limitations:** Fixed-function ASIC design limits flexibility compared to programmable shaders [S2, unofficial].
*   **When to use:** Real-time volume rendering on dedicated hardware [S2, unofficial].
*   **When not:** When flexibility or dynamic pipeline configuration is required [S1, unofficial].

## Background
The concept originates from the design of the Shear-warp factorization volume rendering visualization system (SWE system), which uses a time-slicing approach and multi-core structure to provide real-time rendering [S1, unofficial]. The Vg500 chip architecture, part of the VolumePro system, is an application-specific integrated circuit (ASIC) that implements this parallel pipeline approach [S2, unofficial].
