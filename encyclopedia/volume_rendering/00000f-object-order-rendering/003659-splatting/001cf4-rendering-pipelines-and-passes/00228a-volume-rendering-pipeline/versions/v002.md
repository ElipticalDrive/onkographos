# Volume Rendering Pipeline

Also called: CRIO Process, Classification, Reflection, Illumination, Opacity, Rendering Stages, Shading and Classification Pipeline, VolumeRenderer forward method

## Overview
The volume rendering pipeline is a standard implementation structure for direct volume rendering that processes scalar field data into a 2D image through a sequence of six distinct stages: data traversal, interpolation, gradient computation, classification, shading, and compositing [S1, unofficial]. Unlike methods that fit geometric primitives to the data, this pipeline forms images by directly shading each sample and projecting it onto the picture plane, treating volume samples as semi-transparent clouds that act as both absorbers and emitters [S2, unofficial][S4, unofficial]. It is distinguished from sibling pipelines like [Plug-and-Play Ray Marching and Rendering](981-plug-and-play-ray-marching-and-rendering.md) by its explicit separation of shading (color calculation) and classification (opacity calculation) into independent steps, ensuring undistorted visualization of 3-D shape [S2, unofficial].

## How it works
The pipeline operates on a 3D scalar field and produces a 2D image [S3, unofficial]. The core data structures are arrays of scalar values, prepared values, voxel colors, and voxel opacities [S3, unofficial].

**Inputs:**
*   Acquired scalar values $f_0(x_i)$ at voxel locations $x_i = (x_i, y_j, z_k)$ [S3, unofficial].
*   Ray bundle defined by observer eyepoint and image pixel coordinates [S2, unofficial][S3, unofficial].
*   Number of sample locations $K$ along each ray [S2, unofficial][S3, unofficial].

**Outputs:**
*   Final pixel color $C_\lambda(u,v)$ and opacity $\alpha(u,v)$ for each pixel $(u,v)$ [S2, unofficial][S3, unofficial].

**Data Structures:**
1.  **Acquired Values:** Array $f_0$ of scalar densities/intensities at grid points [S3, unofficial].
2.  **Prepared Values:** Array $f_1$ after data preparation (corrections, enhancements) [S3, unofficial].
3.  **Voxel Colors:** Array $c_\lambda(x_i)$ where $\lambda \in \{r, g, b\}$, computed from $f_1$ via shading [S3, unofficial].
4.  **Voxel Opacities:** Array $\alpha(x_i)$, computed from $f_1$ via classification [S3, unofficial].
5.  **Sample Colors/Opacities:** Vectors $c_\lambda(\tilde{x}_i)$ and $\alpha(\tilde{x}_i)$ for $K$ sample points along a ray [S3, unofficial].

**Steps:**

1.  **Data Traversal:** Traverse the 3D scalar field organization to identify samples along light rays. This discretizes the continuous volume rendering integral [S1, unofficial].
2.  **Data Preparation:** Apply corrections (e.g., for non-orthogonal grids, patient motion) and enhancements to $f_0(x_i)$ to produce prepared values $f_1(x_i)$ [S3, unofficial].
3.  **Interpolation:** Interpolate values from the scalar field at sampling positions that differ from grid points. This is often done during ray casting via tri-linear interpolation from the eight closest voxels [S1, unofficial][S3, unofficial].
4.  **Gradient Computation:** Compute the gradient of the scalar field at sample positions to add visual cues for directional lighting or Phong shading [S1, unofficial].
5.  **Shading:** Input $f_1(x_i)$ into a shading model to yield voxel colors $c_\lambda(x_i)$ [S3, unofficial].
6.  **Classification:** Input $f_1(x_i)$ into a classification procedure to yield voxel opacities $\alpha(x_i)$. This maps scalar properties to optical properties like emitted color, reflected color, and opacity [S3, unofficial][S4, unofficial].
7.  **Ray Casting and Resampling:** Cast rays from the observer eyepoint. For each ray, compute sample colors and opacities by resampling the voxel databases at $K$ evenly spaced locations $\tilde{x}_i = (x_0 + j \frac{d}{K})$ along the ray and tri-linearly interpolating from the eight closest voxels [S2, unofficial][S3, unofficial].
8.  **Compositing:** Composite colors and opacities back-to-front along viewing rays. A fully opaque background of color $c_{bkg,\lambda}$ is draped behind the dataset. The transparency formula is applied iteratively [S2, unofficial][S3, unofficial].

**Formulas:**

The compositing step uses the transparency formula for each sample $i$ along the ray:
$$ C_{out, \lambda}(\tilde{u}_i) = C_{in, \lambda}(\tilde{u}_i)(1 - \alpha(\tilde{x}_i)) + c_\lambda(\tilde{x}_i)\alpha(\tilde{x}_i) $$
Where:
*   $C_{out, \lambda}(\tilde{u}_i)$ is the color of the ray as it leaves sample location $\tilde{x}_i$ [S3, unofficial].
*   $C_{in, \lambda}(\tilde{u}_i)$ is the color of the ray as it enters sample location $\tilde{x}_i$ [S3, unofficial].
*   $c_\lambda(\tilde{x}_i)$ is the color of the sample at $\tilde{x}_i$ [S3, unofficial].
*   $\alpha(\tilde{x}_i)$ is the opacity of the sample at $\tilde{x}_i$ [S3, unofficial].
*   $\lambda \in \{r, g, b\}$ [S3, unofficial].

The final pixel color $C_\lambda(u,v)$ is the result of this iterative compositing starting from the background [S3, unofficial].

**Pseudocode:**

```python
def volume_rendering_pipeline(acquired_values, voxel_grid, ray_bundle, K, step_size):
    """
    Implements the standard volume rendering pipeline.
    
    Args:
        acquired_values: 3D array of scalar values f0(xi).
        voxel_grid: Structure defining voxel locations and spacing.
        ray_bundle: Collection of rays, each with origin and direction.
        K: Number of evenly spaced sample locations along each ray.
        step_size: Distance between consecutive samples along the ray.
        
    Returns:
        image_colors: 2D array of final pixel colors.
        image_opacities: 2D array of final pixel opacities.
    """
    
    # Step 2: Data Preparation
    # Apply corrections (non-orthogonal grids, motion, contrast) to acquired_values [S3, unofficial]
    prepared_values = [row[:] for row in acquired_values]
    
    # Step 5: Shading
    # Compute voxel colors from prepared values [S3, unofficial]
    voxel_colors = compute_shading(prepared_values)
    
    # Step 6: Classification
    # Compute voxel opacities from prepared values [S3, unofficial]
    voxel_opacities = compute_classification(prepared_values)
    
    # Initialize output images
    image_colors = [[0.0, 0.0, 0.0] for _ in range(len(ray_bundle))]
    image_opacities = [0.0 for _ in range(len(ray_bundle))]
    
    # Background setup: fully opaque background of color cbkg,lambda [S3, unofficial]
    background_color = [1.0, 1.0, 1.0]
    background_opacity = 1.0
    
    # Step 7 & 8: Ray Casting, Resampling, and Compositing
    for ray in ray_bundle:
        # Generate K evenly spaced sample locations along the ray
        sample_locations = generate_sample_locations(ray.origin, ray.direction, K, step_size)
        
        # Initialize ray color and transmittance from background
        ray_color = background_color[:]
        ray_opacity = background_opacity
        
        # Composite back-to-front
        for i in range(K - 1, -1, -1):
            x_tilde = sample_locations[i]
            
            # Tri-linear interpolation from voxel databases
            c_sample = tri_linear_interpolate(voxel_colors, x_tilde, voxel_grid)
            alpha_sample = tri_linear_interpolate(voxel_opacities, x_tilde, voxel_grid)
            
            # Apply transparency formula
            ray_color = [ray_color[c] * (1 - alpha_sample) + c_sample[c] * alpha_sample for c in range(3)]
            ray_opacity = ray_opacity * (1 - alpha_sample) + alpha_sample
            
        # Store result for the pixel corresponding to this ray
        pixel_idx = ray.pixel_index
        image_colors[pixel_idx] = ray_color
        image_opacities[pixel_idx] = ray_opacity

    return image_colors, image_opacities

def generate_sample_locations(origin, direction, K, step_size):
    locations = []
    for j in range(K):
        t = j * step_size
        locations.append([origin[0] + direction[0]*t, origin[1] + direction[1]*t, origin[2] + direction[2]*t])
    return locations

def tri_linear_interpolate(data_grid, point, voxel_grid):
    # Standard tri-linear interpolation from the 8 closest voxels [G]
    ix, iy, iz = point[0] / voxel_grid.spacing, point[1] / voxel_grid.spacing, point[2] / voxel_grid.spacing
    x0, y0, z0 = int(ix), int(iy), int(iz)
    fx, fy, fz = ix - x0, iy - y0, iz - z0
    # Handle boundaries by clamping
    x0, x1 = max(0, min(x0, voxel_grid.width-1)), max(0, min(x0+1, voxel_grid.width-1))
    y0, y1 = max(0, min(y0, voxel_grid.height-1)), max(0, min(y0+1, voxel_grid.height-1))
    z0, z1 = max(0, min(z0, voxel_grid.depth-1)), max(0, min(z0+1, voxel_grid.depth-1))
    v000 = data_grid[x0][y0][z0]
    v100 = data_grid[x1][y0][z0]
    v010 = data_grid[x0][y1][z0]
    v110 = data_grid[x1][y1][z0]
    v001 = data_grid[x0][y0][z1]
    v101 = data_grid[x1][y0][z1]
    v011 = data_grid[x0][y1][z1]
    v111 = data_grid[x1][y1][z1]
    c00 = v000 * (1-fx) + v100 * fx
    c10 = v010 * (1-fx) + v110 * fx
    c01 = v001 * (1-fx) + v101 * fx
    c11 = v011 * (1-fx) + v111 * fx
    c0 = c00 * (1-fy) + c10 * fy
    c1 = c01 * (1-fy) + c11 * fy
    return c0 * (1-fz) + c1 * fz

def compute_shading(prepared_values):
    # Apply shading model to yield voxel colors [S3, unofficial]
    return [row[:] for row in prepared_values]

def compute_classification(prepared_values):
    # Apply transfer function to yield voxel opacities [S3, unofficial]
    return [row[:] for row in prepared_values]
```

**Edge Cases and Pitfalls:**
*   **Precision:** Tri-linear interpolation and compositing are sensitive to floating-point precision, especially with many samples [S2, unofficial][S3, unofficial].
*   **Boundaries:** Handling rays that do not intersect the volume or intersect only partially requires careful boundary checks during traversal [S1, unofficial].
*   **Degenerate Input:** Non-orthogonal sampling grids require specific corrections during data preparation to avoid artifacts [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot K)$, where $N$ is the number of pixels (rays) and $K$ is the number of samples per ray [S2, unofficial][S3, unofficial].
*   **Memory Complexity:** $O(V)$ for storing the volume data, where $V$ is the number of voxels, plus $O(K)$ per ray for temporary storage [S2, unofficial][S3, unofficial].
*   **Strengths:** Direct visualization without geometric fitting; separation of shading and classification allows flexible material definition; handles semi-transparent data well [S2, unofficial][S3, unofficial].
*   **Limitations:** Computationally expensive for high-resolution volumes due to $K$ samples per ray; interpolation artifacts if $K$ is too low; sensitive to transfer function design [S2, unofficial][S3, unofficial].
*   **When to Use:** When accurate representation of internal structures and transparency is required, and computational resources allow for per-pixel ray casting [S2, unofficial][S3, unofficial].
*   **When Not to Use:** When real-time performance on very large volumes is critical without hardware acceleration; when geometric primitives are sufficient [S2, unofficial][S3, unofficial].

## Background
The volume rendering pipeline was formalized in the late 1980s. A key early description was presented by Levoy at the SPIE Medical Imaging II conference in January 1988 [S3, unofficial]. The pipeline structure, distinguishing six stages (data traversal, interpolation, gradient computation, classification, shading, and compositing), is commonly referenced in literature such as Engel [S1, unofficial]. The term "CRIO" (Classification, Reflection, Illumination, Opacity) was used in parallel feed-forward algorithms to describe the conceptual treatment of samples as reflective, light-emitting clouds [S4, unofficial]. The pipeline assumes each sample acts as both an absorber and an emitter [S5, unofficial].
