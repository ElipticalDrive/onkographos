# Plug-and-Play Ray Marching and Rendering

Also called: Differentiable Volumetric Rendering Pipeline, nerfacc pipeline

## Overview
A modular rendering interface that decouples the ray marching and volumetric accumulation logic from the specific radiance field representation, allowing efficient differentiable rendering to be "plugged in" to any user-defined neural field [S1, unofficial]. Unlike specialized implementations such as Instant-NGP which rely on custom CUDA kernels, this method provides a Python API (typically via PyTorch) that accelerates training for static, dynamic, and unbounded scenes while maintaining compatibility with standard deep learning workflows [S1, unofficial].

## How it works
The method operates by defining two callback functions that interface with a generic ray marching engine. The engine handles the discretization of rays, empty space pruning, and the final differentiable accumulation.

**Inputs:**
- `rays_o`: Tensor of ray origins, shape $(N_{rays}, 3)$.
- `rays_d`: Tensor of normalized ray directions, shape $(N_{rays}, 3)$.
- `radiance_field`: A user-defined neural network or data structure capable of querying density ($\sigma$) and color ($\mathbf{c}$) at 3D positions.

**Outputs:**
- `color`: Rendered RGB image, shape $(N_{rays}, 3)$.
- `opacity`: Accumulated opacity per ray, shape $(N_{rays}, 1)$.
- `depth`: Accumulated depth per ray, shape $(N_{rays}, 1)$.

**Data Structures and Parameters:**
- `t_starts`, `t_ends`: 1D Tensors containing the start and end distances of valid sample intervals along rays.
- `ray_indices`: 1D Tensor mapping each sample to its parent ray index.
- `near_plane`: Starting distance for ray marching. Typical value: $0.2$ [S1, unofficial].
- `far_plane`: Ending distance for ray marching. Typical value: $1.0$ [S1, unofficial].
- `early_stop_eps`: Threshold for early stopping based on transmittance. Typical value: $10^{-4}$ [S1, unofficial].
- `alpha_thre`: Threshold for skipping samples with low opacity contribution. Typical value: $10^{-2}$ [S1, unofficial].

**Volumetric Rendering Equation:**
The final color $\mathbf{C}(\mathbf{r})$ for a ray $\mathbf{r}$ is computed as [S1, unofficial]:

$$
\mathbf{C}(\mathbf{r}) = \sum_{i=1}^N T_i \alpha_i \mathbf{c}_i
$$

where:
- $N$ is the number of valid samples.
- $\mathbf{c}_i$ is the color at sample $i$.
- $\alpha_i = 1 - \exp(-\sigma_i \delta_i)$ is the opacity of sample $i$.
- $\sigma_i$ is the density at sample $i$.
- $\delta_i$ is the distance between sample $i$ and $i+1$ (or end of interval).
- $T_i = \exp\left(-\sum_{j=1}^{i-1} \sigma_j \delta_j\right)$ is the transmittance up to sample $i$.

**Algorithm Steps:**

1.  **Define Density Query Function (`sigma_fn`):**
    Create a function that accepts `t_starts`, `t_ends`, and `ray_indices`.
    - Compute sample positions: $\mathbf{p}_i = \mathbf{o}_{r_i} + \mathbf{d}_{r_i} \cdot \frac{t_{start, i} + t_{end, i}}{2}$.
    - Query the radiance field for density $\sigma_i$ at $\mathbf{p}_i$.
    - Return $\sigma$ as a tensor of shape $(N_{samples}, 1)$.

2.  **Define RGB-Density Query Function (`rgb_sigma_fn`):**
    Create a function with the same inputs as `sigma_fn`.
    - Compute sample positions $\mathbf{p}_i$ as above.
    - Query the radiance field for color $\mathbf{c}_i$ and density $\sigma_i$.
    - Return $\mathbf{c}$ (shape $(N_{samples}, 3)$) and $\sigma$ (shape $(N_{samples}, 1)$).

3.  **Execute Ray Marching:**
    Call the ray marching routine with `rays_o`, `rays_d`, `sigma_fn`, and plane parameters.
    - The routine iterates along rays, using `sigma_fn` to identify empty or occluded regions.
    - It prunes samples where transmittance is below `early_stop_eps` or opacity contribution is below `alpha_thre`.
    - Returns `packed_info` (metadata for efficient memory access), `t_starts`, and `t_ends` for the remaining valid samples.

4.  **Execute Differentiable Rendering:**
    Call the rendering routine with `rgb_sigma_fn`, `packed_info`, `t_starts`, and `t_ends`.
    - The routine queries colors and densities for the valid samples.
    - It computes $\alpha_i$ and $T_i$ for each sample.
    - It accumulates the color, opacity, and depth according to the rendering equation.
    - Returns the final per-ray color, opacity, and depth tensors.

**Pseudocode:**

```python
import torch
from torch import Tensor
import nerfacc

# Assume radiance_field is a defined neural network module
# Assume rays_o and rays_d are defined tensors of shape (N_rays, 3)

def sigma_fn(t_starts: Tensor, t_ends: Tensor, ray_indices: Tensor) -> Tensor:
    """
    Query density values from a user-defined radiance field.
    """
    # Gather ray origins and directions for the specific samples
    t_origins = rays_o[ray_indices]  # Shape: (n_samples, 3)
    t_dirs = rays_d[ray_indices]     # Shape: (n_samples, 3)
    
    # Compute midpoints of the sample intervals
    positions = t_origins + t_dirs * (t_starts + t_ends) / 2.0
    
    # Query density from the radiance field
    # radiance_field.query_density should return shape (n_samples, 1)
    sigmas = radiance_field.query_density(positions)
    
    return sigmas

def rgb_sigma_fn(t_starts: Tensor, t_ends: Tensor, ray_indices: Tensor):
    """
    Query RGB and density values from the radiance field.
    """
    t_origins = rays_o[ray_indices]
    t_dirs = rays_d[ray_indices]
    
    positions = t_origins + t_dirs * (t_starts + t_ends) / 2.0
    
    # Query color and density
    # radiance_field should return (n_samples, 3) for color and (n_samples, 1) for density
    rgbs, sigmas = radiance_field(positions, condition=t_dirs)
    
    return rgbs, sigmas

# Step 1: Efficient Ray Marching with pruning
packed_info, t_starts, t_ends = nerfacc.ray_marching(
    rays_o=rays_o,
    rays_d=rays_d,
    sigma_fn=sigma_fn,
    near_plane=0.2,
    far_plane=1.0,
    early_stop_eps=1e-4,
    alpha_thre=1e-2
)

# Step 2: Differentiable Volumetric Rendering
color, opacity, depth = nerfacc.rendering(
    rgb_sigma_fn=rgb_sigma_fn,
    packed_info=packed_info,
    t_starts=t_starts,
    t_ends=t_ends
)

# Step 3: Optimization (Example)
# loss = F.mse_loss(color, color_gt)
# loss.backward()
# optimizer.step()
```

**Edge Cases and Pitfalls:**
- **Precision:** The transmittance calculation involves exponentials of negative sums. Ensure densities are non-negative to avoid numerical instability in $T_i$ [S1, unofficial].
- **Boundaries:** The `near_plane` and `far_plane` must encompass the scene geometry. If the scene is unbounded, `far_plane` may need to be large or handled via specific unbounded scene techniques supported by the radiance field [S1, unofficial].
- **Empty Space:** The pruning logic relies on `sigma_fn`. If the radiance field returns noisy or non-zero densities in empty space, pruning efficiency drops, increasing compute time [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Depends on the number of valid samples after pruning. The Python API introduces overhead compared to pure CUDA, but the pruning significantly reduces the number of neural network queries [S1, unofficial].
- **Memory Complexity:** Linear with respect to the number of valid samples. The `packed_info` structure allows for efficient memory layout on the GPU [S1, unofficial].
- **Performance:** On a single NVIDIA TITAN RTX, an 8-layer MLP NeRF can be trained to high quality in ~1 hour, compared to 1-2 days in original implementations. Instant-NGP quality can be matched in ~4.5 minutes in Python [S1, unofficial].
- **Strengths:** High flexibility; works with any radiance field (MLP, hash grids, etc.); supports dynamic and unbounded scenes; easy to integrate into existing PyTorch pipelines [S1, unofficial].
- **Limitations:** Python API overhead may be slower than highly optimized custom CUDA kernels for static, simple scenes; requires careful tuning of `near_plane` and `far_plane` for optimal pruning [S1, unofficial].

## Background
The method originates from the NerfAcc toolbox, introduced to provide a general acceleration framework for Neural Radiance Fields (NeRFs) [S1, unofficial]. It builds upon techniques from Instant-NGP but extends them to support dynamic and unbounded scenes while offering a user-friendly Python API [S1, unofficial]. It addresses the bottleneck of training NeRFs by efficiently skipping empty and occluded regions during ray marching [S1, unofficial].
