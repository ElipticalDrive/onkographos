# GPU Implementation Pipeline
Also called: Single-pass GPU Raycasting, Volumetric Raycasting

## Overview
A GPU-accelerated rendering technique that traces rays from the camera through each pixel into a 3D volume to compute color and opacity, implemented in a single pass using fragment shaders [S2, unofficial]. It solves the problem of visualizing volumetric data directly on the GPU without generating intermediate polygonal meshes [S4]. It differs from isosurface extraction (e.g., [Marching Cubes](53-marching-cubes.md)) by preserving internal volume information [S1], and from splatting ([Splatting](10-splatting.md)) by avoiding sorting and blending overheads for dense volumes, though it is computationally heavier per pixel than texture-based splatting [G].

## How it works
The method consists of two distinct implementation patterns found in the sources: a standard single-pass raycasting approach for direct visualization [S2, unofficial], and a multi-pass light propagation approach for global illumination [S1].

### Inputs and Outputs
**Inputs:**
*   **Volume Data:** A 3D texture (e.g., `volume` in texture unit 0) containing scalar density/intensity values [S2, unofficial].
*   **Jitter Data:** A 2D texture (e.g., `jitter` in texture unit 1) containing pre-generated random values for anti-aliasing [S2, unofficial].
*   **Camera Parameters:** View matrix, Model-View-Projection (MVP) matrix, aspect ratio, focal length, viewport size, ray origin, and bounding box coordinates (top/bottom) [S2, unofficial].
*   **Rendering Parameters:** Step length, threshold, gamma, background color, material color, and light position [S2, unofficial].

**Outputs:**
*   **Final Image:** A color buffer with alpha blending and gamma correction [S2, unofficial].
*   **Light Volumes (Optional):** Intermediate Frame Buffer Objects (FBOs) attached to 3D texture slices storing local opacity ($\alpha_{lp}$), global opacity ($\alpha_g$), and final intensity ($I_{final}$) for light propagation [S1].

### Data Structures
*   **Ray:** Defined by origin ($\vec{o}$) and direction ($\vec{d}$) [S2, unofficial].
*   **AABB (Axis-Aligned Bounding Box):** Defined by `top` and `bottom` vectors representing the volume bounds [S2, unofficial].
*   **3D Texture:** Stores volume data. In multi-resolution implementations, this may be reduced (e.g., $256 \times 256 \times 128$ for a $512^3$ dataset) using flat blocking [S1].

### Numbered Steps

#### Pattern A: Single-Pass Raycasting [S2, unofficial]
1.  **Initialize OpenGL State:** Create the volume data structure and generate noise if required [S2, unofficial].
2.  **Compute Matrices:**
    *   Calculate the View Matrix by translating along the Z-axis: $\text{translate}(0, 0, -4.0 \cdot \exp(\text{distExp} / 600.0))$ [S2, unofficial].
    *   Calculate the MVP Matrix using perspective projection with field of view (FOV), aspect ratio ($\text{scaled\_width}/\text{scaled\_height}$), near plane (0.1), and far plane (100.0) [S2, unofficial].
3.  **Compute Ray Origin:** Invert the View Matrix and transform the world origin $(0,0,0)$ to get the ray origin in world space [S2, unofficial].
4.  **Bind Shaders and Uniforms:** Bind the vertex and fragment shaders. Set uniforms: `ViewMatrix`, `ModelViewProjectionMatrix`, `NormalMatrix`, `aspect_ratio`, `focal_length`, `viewport_size`, `ray_origin`, `top`, `bottom`, `background_colour`, `light_position`, `material_colour`, `step_length`, `threshold`, `gamma`, `volume` (unit 0), and `jitter` (unit 1) [S2, unofficial].
5.  **Clear Buffer:** Clear the color buffer with the background color [S2, unofficial].
6.  **Execute Raycasting Shader:** For each pixel (fragment):
    *   Compute ray direction from fragment coordinates [S2, unofficial].
    *   Perform ray-box intersection to find entry ($t_0$) and exit ($t_1$) distances [S2, unofficial].
    *   Calculate ray start/stop in texture coordinates and step vector [S2, unofficial].
    *   Apply random jitter to the start position [S2, unofficial].
    *   **Marching Loop:** While ray length remains and color is not saturated:
        *   Sample volume intensity [S2, unofficial].
        *   Apply color transfer function (e.g., exponential mapping to alpha) [S2, unofficial].
        *   Composite using front-to-back alpha blending [S2, unofficial].
        *   Advance position and reduce remaining length [S2, unofficial].
    *   Blend result with background using gamma correction [S2, unofficial].
7.  **Select Mode:** Execute specific shader logic for Isosurface, Alpha blending, or Maximum Intensity Projection (MIP) [S2, unofficial].

#### Pattern B: Global Light Propagation [S1]
1.  **Light Update Order:** Compute light source direction first (for shadows), then incrementally add scattering directions by subdividing a tetrahedron/icosahedron/octahedron [S1].
2.  **Render Light Volumes:** Execute three shader programs to update light computations, rendering one slice at a time to an FBO attached to a 3D texture slice [S1]:
    *   Compute $\alpha_{lp}$ (local piecewise opacity) [S1].
    *   Compute $\alpha_g$ (global opacity) [S1].
    *   Compute $I_{final}$ (final intensity including scattering) [S1].
3.  **Incremental Refinement:** Blend new $I_{final}$ results with previously stored intensities ($I_{stored}$) using the formula:
    $$I_{blended} = \frac{1}{J} \sum_{j=1}^{J} I_{final}^{(j)}$$
    where $J$ is the number of rays discretizing the scattering sphere [S1].
4.  **Final Ray Casting:** Execute a final shader program to compute $I_{eye}$ using the stored light volumes [S1].
5.  **Empty Block Handling:** If a sample point in global opacity calculation falls in an empty block, advance the ray to the next non-empty block to prevent occlusion artifacts [S1].

### Formulas
*   **Ray Direction:**
    $$\vec{d}_{xy} = 2.0 \frac{\vec{c}_{xy}}{\vec{v}_{size}} - 1.0$$
    $$\vec{d}_x \cdot \text{aspect\_ratio} = \vec{d}_x$$
    $$\vec{d}_z = -\text{focal\_length}$$
    $$\vec{d} = \text{normalize}((\vec{d}, 0) \cdot \text{ViewMatrix})$$ [S2, unofficial]
*   **Ray-Box Intersection:**
    $$\vec{d}_{inv} = 1.0 / \vec{d}$$
    $$\vec{t}_{top} = \vec{d}_{inv} \cdot (\text{box.top} - \vec{o})$$
    $$\vec{t}_{bottom} = \vec{d}_{inv} \cdot (\text{box.bottom} - \vec{o})$$
    $$\vec{t}_{min} = \min(\vec{t}_{top}, \vec{t}_{bottom})$$
    $$t_0 = \max(0.0, \max(\vec{t}_{min}.x, \vec{t}_{min}.y))$$
    $$\vec{t}_{max} = \max(\vec{t}_{top}, \vec{t}_{bottom})$$
    $$t_1 = \min(\vec{t}_{max}.x, \vec{t}_{max}.y)$$ [S2, unofficial]
*   **Color Transfer (Simple):**
    $$\alpha = \frac{\exp(\text{intensity}) - 1.0}{\exp(1.0) - 1.0}$$ [S2, unofficial]
*   **Alpha Blending:**
    $$\vec{C}_{out} = \alpha_c \vec{C}_c + (1 - \alpha_c) \alpha_{out} \vec{C}_{out}$$
    $$\alpha_{out} = \alpha_c + (1 - \alpha_c) \alpha_{out}$$ [S2, unofficial]

### Parameters and Typical Values
*   **Hardware:** Nvidia GeForce 8800 Ultra with 768 MB graphics texture memory [S1].
*   **Volume Size:** $512^3$ medical dataset [S1].
*   **Data Reduction:** 8.9:1 reduction (stored as $256 \times 256 \times 128$) [S1].
*   **Piecewise Segment Length:** 8 voxels (optimal for performance/quality balance) [S1].
*   **Performance:** Global light integration (A) takes 284-552 ms. First order scattering incremental refinements (B) take 62-233 ms. High frame rates (15-22 fps) reached after light update [S1].

### Edge Cases and Pitfalls
*   **Empty Blocks:** In multi-resolution structures, rays originating in empty blocks may cover neighboring non-empty blocks, losing occlusion. Solution: Advance ray to next non-empty block [S1].
*   **Interpolation Artifacts:** Flat blocking multi-resolution data management can cause interpolation problems at block boundaries [S1].
*   **Scattering Radius:** Large scattering sphere radius ($\Omega$) makes shadows less distinct [S1].
*   **Bias:** $I_{bias}$ adjusts minimum light level; improper values cause dark/bright artifacts [S1].

### Pseudocode
```python
# Pattern A: Single-Pass Raycasting [S2, unofficial]

def compute_ray_direction(frag_coord, viewport_size, aspect_ratio, view_matrix, focal_length):
    # Compute direction in clip space
    d_xy = 2.0 * frag_coord.xy / viewport_size - 1.0
    d_xy.x *= aspect_ratio
    d_z = -focal_length
    d_clip = vec4(d_xy, d_z, 0.0)
    # Transform to world space
    d_world = (view_matrix * d_clip).xyz
    return normalize(d_world)

def ray_box_intersection(ray_origin, ray_direction, box_top, box_bottom):
    direction_inv = 1.0 / ray_direction
    t_top = direction_inv * (box_top - ray_origin)
    t_bottom = direction_inv * (box_bottom - ray_origin)
    t_min = min(t_top, t_bottom)
    t_max = max(t_top, t_bottom)
    
    t0 = max(max(t_min.x, t_min.y), 0.0)
    t1 = min(t_max.x, t_max.y)
    return t0, t1

def color_transfer(intensity):
    # Simple exponential transfer function [S2, unofficial]
    alpha = (exp(intensity) - 1.0) / (exp(1.0) - 1.0)
    high = vec3(1.0)
    low = vec3(0.0)
    color = intensity * high + (1.0 - intensity) * low
    return vec4(color, alpha)

def main_raycasting(view_matrix, mvp_matrix, volume_texture, jitter_texture, 
                    ray_origin, box_top, box_bottom, viewport_size, 
                    aspect_ratio, focal_length, step_length, background_color, gamma):
    
    # 1. Compute Ray Direction [S2, unofficial]
    ray_dir = compute_ray_direction(gl_FragCoord, viewport_size, aspect_ratio, view_matrix, focal_length)
    
    # 2. Ray-Box Intersection [S2, unofficial]
    t0, t1 = ray_box_intersection(ray_origin, ray_dir, box_top, box_bottom)
    
    # 3. Setup Ray Parameters [S2, unofficial]
    ray_start = (ray_origin + ray_dir * t0 - box_bottom) / (box_top - box_bottom)
    ray_stop = (ray_origin + ray_dir * t1 - box_bottom) / (box_top - box_bottom)
    ray_vec = ray_stop - ray_start
    ray_length = length(ray_vec)
    step_vec = step_length * ray_vec / ray_length
    
    # 4. Jitter [S2, unofficial]
    jitter_val = texture(jitter_texture, gl_FragCoord.xy / viewport_size).r
    ray_start += step_vec * jitter_val
    
    # 5. Marching Loop [S2, unofficial]
    color = vec4(0.0)
    position = ray_start
    
    while ray_length > 0 and color.a < 1.0:
        intensity = texture(volume_texture, position).r
        c = color_transfer(intensity)
        
        # Alpha blending
        color.rgb = c.a * c.rgb + (1 - c.a) * color.a * color.rgb
        color.a = c.a + (1 - c.a) * color.a
        
        ray_length -= step_length
        position += step_vec
        
    # 6. Background Blend and Gamma [S2, unofficial]
    final_color = color.a * color.rgb + (1 - color.a) * pow(background_color, vec3(gamma)).rgb
    final_color = pow(final_color, vec3(1.0 / gamma))
    
    return final_color
```

## Subtopics

### [Volume Rendering with 3D Textures and Ray Marching](2584-volume-rendering-with-3d-textures-and-ray-marching.md)
This method performs object-order volume rendering by ray marching through a 3D texture stored in GPU memory, applying a transfer function to map scalar values to color and opacity, and compositing the result front-to-back. It solves the problem of visualizing volumetric data (such as medical DICOM series or synthetic density fields) directly on the GPU without generating intermediate polygonal meshes. It differs from isosurface extraction (e.g., [Marching Cubes](53-marching-cubes.md)) by preserving internal volume information, and from splatting ([Splatting](10-splatting.md)) by avoiding sorting and blending overheads for dense volumes, though it is computationally heavier per pixel than texture-based splatting [G].

### [NVIDIA GeForce3 Volume Rendering Pipeline](5630-nvidia-geforce3-volume-rendering-pipeline.md)
The NVIDIA GeForce3 Volume Rendering Pipeline is a hardware-accelerated method for interactive volume rendering that utilizes per-fragment dependent texture reads and 4-way multi-texturing to eliminate the need for intermediate scratch buffers. It distinguishes itself from prior software-based or scratch-buffer-dependent approaches (such as the SGI Octane2 method) by performing texture lookups dynamically based on computed fragment attributes, thereby avoiding expensive memory copy operations. This approach trades the flexibility of arbitrary 3D transfer functions for performance gains, constraining the transfer function to a separable product of 2D and 1D components due to hardware limitations on dependent texture dimensions.

## Operating characteristics
*   **Time Complexity:** Dependent on volume size, step length, and scattering sphere discretization. For a $512^3$ volume with 8.9:1 reduction, global light integration takes 284-552 ms, and incremental refinements take 62-233 ms [S1].
*   **Memory Complexity:** Requires storage for the volume texture and intermediate light volumes (FBOs). Multi-resolution structures can reduce storage significantly (e.g., $256 \times 256 \times 128$ for $512^3$) [S1].
*   **Performance:** High frame rates (15-22 fps) achieved after light update on Nvidia GeForce 8800 Ultra [S1].
*   **Strengths:** Single-pass efficiency for direct visualization [S2, unofficial]; preserves internal volume information [S1]; hardware acceleration via fragment shaders [S2, unofficial].
*   **Limitations:** Computationally heavier per pixel than splatting [G]; artifacts from empty blocks in multi-resolution structures [S1]; interpolation issues at block boundaries [S1].
*   **When to Use:** Direct visualization of dense volumetric data without mesh generation [S4]; interactive applications requiring global illumination updates [S1].
*   **When Not to Use:** When extreme performance is required for very large volumes without multi-resolution reduction [S1]; when isosurface extraction is preferred [S1].

## Background
The method originates from GPU-accelerated volumetric raycasting techniques implemented in GLSL and C++ [S2, unofficial]. It builds on the principles of stage separation and sequential execution defined in [Rendering Pipelines and Passes](1411-rendering-pipelines-and-passes.md). The single-pass approach was popularized by implementations such as the one by Martino Pilia [S2, unofficial]. The global light propagation variant was introduced to handle complex illumination effects in direct volume rendering [S1].
