# Real-Time Rendering Pipeline with Virtual Memory

Also called: Virtual Memory Gaussian Streaming Pipeline

## Overview
This method implements a real-time rendering pipeline for 3D Gaussian Splatting that streams Gaussian data to GPU memory on demand using a virtual memory system [S1]. It solves the memory capacity bottleneck of large scenes by mapping logical page IDs to physical GPU memory pages, replacing unused pages based on a least-recently-used (LRU) policy [S1]. Unlike software-based tile-sorting approaches (e.g., Kerbl et al.), this method performs global distance sorting of Gaussians in a GLSL compute shader before splatting them via the hardware rasterizer [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A scene of 3D Gaussians, each assigned to a logical page ID; camera position and orientation; a proxy mesh representing the spatial distribution of these pages.
*   **Output:** A final 2D image with alpha-blended Gaussians.

**Data Structures:**
1.  **Page Table:** A single array structure (selected over hierarchical for memory locality) [S1]. Each entry contains:
    *   `page_id`: The logical page identifier.
    *   `physical_page_index`: The index of the physical memory page currently holding this data.
    *   `valid`: Boolean indicating if the entry maps to valid data.
    *   `LOD`: The detail level of the data in the physical page.
    *   `last_use_frame`: The frame index in which this page was last accessed.
    *   `required`: Boolean flag set during the update phase to indicate necessity for the current frame.
2.  **Gaussian Buffer:** A storage buffer containing the actual Gaussian properties (translation, rotation, scale, opacity, spherical harmonics) for all active physical pages [S1].
3.  **Index Buffer:** A buffer of indices, one per Gaussian, used to sort and retrieve Gaussian properties [S1].
4.  **Staging Buffer:** A temporary CPU/GPU accessible buffer used to transfer new page data before copying to the Gaussian Buffer [S1].

**Numbered Steps:**

1.  **Proxy Rendering:** Render a proxy mesh where each face is marked with a `page_id`. This generates a list of visible page IDs required for the current frame [S1].
2.  **Page Table Update:**
    a. Traverse the page table entries. Mark entries as `required` if their `page_id` is in the visible list.
    b. Identify `free` physical pages (those with `valid=false` or whose `page_id` is not in the required list). Store these free pages along with their `last_use_frame` [S1].
    c. Remove pages from the required list that are already present in the page table at the correct LOD. The remaining required list contains only pages missing from GPU memory [S1].
3.  **Data Streaming:**
    a. If there is space in the Gaussian Buffer, copy the data for the remaining required pages into the Staging Buffer.
    b. Select free physical pages from the list generated in Step 2b based on the Least-Recently-Used (LRU) order (lowest `last_use_frame`) [S1].
    c. Copy the Staging Buffer contents into the Gaussian Buffer at the selected physical page indices.
    d. Update the Page Table entries for these pages to mark them `valid`, set their `physical_page_index`, and update `last_use_frame` to the current frame [S1].
    e. Write the list of currently valid physical pages to a buffer accessible by the GPU renderer [S1].
4.  **Index Generation:** A compute shader converts the list of valid physical pages into a list of sortable indices. It calculates the distance of each Gaussian from the camera [S1].
5.  **Global Sorting:** A compute shader performs a radix sort on the index buffer based on the calculated camera distances. This ensures Gaussians are sorted back-to-front for correct alpha blending [S1].
6.  **Rendering:**
    a. Dispatch a vertex shader for every Gaussian in the sorted index buffer. The vertex shader retrieves Gaussian properties from the Gaussian Storage Buffer using the sorted index [S1].
    b. **Geometry Construction:**
        *   *Preferred:* If geometry shaders are available, use them to construct rectangular quads from the point primitives [S1].
        *   *Fallback:* If geometry shaders are unavailable, render point primitives as squares. Note: This fallback leads to a significant increase in fragment shader invocations and discards due to the square shape covering non-Gaussian areas [S1].
    c. **Fragment Shader:** Discard pixels outside the splatted Gaussian shape (ellipse) [S1].
    d. **Alpha Blending:** Combine the quads via alpha blending to create the final image [S1].

**Edge Cases and Pitfalls:**
*   **Fallback Rendering:** Using point primitives instead of geometry shader quads results in square fragments. This causes a significant increase in fragment shader invocations and subsequent discards, reducing performance [S1].
*   **Memory Locality:** A hierarchical page table was considered but rejected in favor of a single array to improve memory locality [S1].

## Operating characteristics
*   **Time Complexity:** Sorting is performed using a radix sort on the index buffer, which is generally $O(N)$ for $N$ Gaussians [S1]. Page table updates are linear with respect to the number of pages in the table [S1].
*   **Memory Complexity:** Memory usage is bounded by the number of physical pages loaded into GPU memory, determined by available VRAM and the LRU eviction policy [S1].
*   **Performance:** The method is designed for real-time performance, targeting frame times below 16 ms [S1]. It avoids the overhead of sparse residency indirection textures by using an index buffer [S1].
*   **Strengths:** Global sorting ensures correct alpha blending; virtual memory allows rendering scenes larger than VRAM; single-array page table improves locality.
*   **Limitations:** Requires geometry shaders for optimal performance (fallback is inefficient); global sorting can be costly for extremely large numbers of Gaussians compared to tile-based approaches [S1].

## Background
This method originates from research on applying virtual memory concepts to 3D Gaussian Splatting [S1]. It contrasts with the original 3DGS implementation by Kerbl et al., which uses a CUDA-based software renderer with tile-based sorting [S1]. The approach adapts virtual texturing techniques (Barrett [30]) to the specific data structure of Gaussian splats, using a proxy mesh to determine visible pages [S1].
