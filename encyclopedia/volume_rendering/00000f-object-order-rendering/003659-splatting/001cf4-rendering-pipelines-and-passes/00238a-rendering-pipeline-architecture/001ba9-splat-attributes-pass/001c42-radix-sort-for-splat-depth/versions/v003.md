# Radix Sort for Splat Depth

Also called: 16-bit Radix Sort for Splatting, Depth Sorting via Radix Sort, Tsplat depth sort

## Overview
This method sorts projected splats by depth to establish the correct front-to-back rendering order required for alpha blending in object-order splatting [S1, unofficial]. It leverages the property that positive 32-bit floating-point bit patterns preserve numerical ordering when reinterpreted as unsigned 32-bit integers, allowing the use of a 2-pass 16-bit radix sort on the depth values [S1, unofficial]. This approach is chosen over comparison-based sorts because it achieves $O(n)$ time complexity with small constants and is consistently faster for typical splat counts (~100k–200k elements) [S1, unofficial]. It builds on the [Splat Attributes Pass](1066-splat-attributes-pass.md) and differs from the [Splat Depth Pass](1078-splat-depth-pass.md) by operating directly on projected depth bit patterns rather than recomputing or storing depth separately.

## How it works
### Inputs and Outputs
- **Input**: An array of `n` projected splats. Each splat contains a `depth` field (f32) representing its distance from the camera [S1, unofficial].
- **Output**: The same array of splats, reordered such that splats with smaller depth values appear first (front-to-back) [S1, unofficial].
- **Auxiliary Data**: Two histogram arrays `counts_lo` and `counts_hi` of size 65,536 each (u32), an `offsets` array of size 65,536 (u32), and an auxiliary buffer `aux` of size `n` to hold splats during the sort [S1, unofficial].

### Data Structures
- `counts_lo`: Histogram for the lower 16 bits of the depth bit pattern [S1, unofficial].
- `counts_hi`: Histogram for the upper 16 bits of the depth bit pattern [S1, unofficial].
- `offsets`: Prefix sum (scan) of the histogram counts, determining the starting index for each bucket [S1, unofficial].
- `projected`: The input/output array of splats [S1, unofficial].
- `aux`: Temporary storage for splats during the scatter phase [S1, unofficial].

### Algorithm Steps
1. **Edge Case**: If $n \le 1$, return immediately as the array is already sorted [S1, unofficial].
2. **Histogram Initialization & Population**: Initialize `counts_lo` and `counts_hi` to zero [S1, unofficial]. Iterate through each splat $i$ from $0$ to $n-1$: let $k$ be the bit pattern of `projected[i].depth` interpreted as a `u32` [S1, unofficial]. Increment `counts_lo[k & 0xFFFF]` and `counts_hi[k >> 16]` [S1, unofficial].
3. **Pass 1 (Low 16 bits)**: Compute the prefix sum of `counts_lo` into `offsets` [S1, unofficial]. Scatter splats from `projected` to `aux` based on the low 16 bits of their depth [S1, unofficial].
4. **Pass 2 (High 16 bits)**: Compute the prefix sum of `counts_hi` into `offsets` [S1, unofficial]. Scatter splats from `aux` to `projected` based on the high 16 bits of their depth [S1, unofficial].

### Pseudocode
```python
def sort_splats_by_depth(projected: list[Splat], aux: list[Splat], counts_lo: list[int], counts_hi: list[int], offsets: list[int]):
    n = len(projected)
    if n <= 1:
        return

    # Initialize histograms
    for i in range(65536):
        counts_lo[i] = 0
        counts_hi[i] = 0

    # Populate histograms
    for i in range(n):
        k = projected[i].depth.to_bits()  # Reinterpret f32 as u32
        counts_lo[k & 0xFFFF] += 1
        counts_hi[k >> 16] += 1

    # Pass 1: Sort by low 16 bits
    # Compute prefix sums of counts_lo into offsets
    current_sum = 0
    for i in range(65536):
        temp = counts_lo[i]
        offsets[i] = current_sum
        current_sum += temp

    # Scatter based on low bits
    for i in range(n):
        k = projected[i].depth.to_bits()
        idx = offsets[k & 0xFFFF]
        aux[idx] = projected[i]
        offsets[k & 0xFFFF] += 1

    # Pass 2: Sort by high 16 bits
    # Compute prefix sums of counts_hi into offsets
    current_sum = 0
    for i in range(65536):
        temp = counts_hi[i]
        offsets[i] = current_sum
        current_sum += temp

    # Scatter based on high bits
    for i in range(n):
        k = aux[i].depth.to_bits()
        idx = offsets[k >> 16]
        projected[idx] = aux[i]
        offsets[k >> 16] += 1
```

### Parameters
- **Parallel Sort Threshold**: If the number of splats is less than 50,000 or no thread pool is available, use a sequential radix sort [S1, unofficial]. Otherwise, use `par_sort_unstable_by_key` on the depth bits [S1, unofficial].

### Edge Cases and Pitfalls
- **Negative Depths**: The method relies on positive float bit patterns preserving order [S1, unofficial]. Ensure depths are positive (e.g., by using view space z or clip space w) before converting to bits [S1, unofficial].
- **Boundaries**: The histogram size is fixed at 65,536 (16 bits) [S1, unofficial]. Ensure the bit masking and shifting operations correctly isolate the lower and upper 16 bits of the 32-bit integer [S1, unofficial].

## Subtopics

### Gaussian Sorting
Sorts Gaussians by their depth (z-coordinate) in camera space for front-to-back rendering [S2, unofficial]. It transforms all Gaussian positions to camera space using the view matrix and then sorts the indices based on the z-component (index 2) of the camera-space positions [S2, unofficial].

### [Fast Splat Sorting](2953-fast-splat-sorting.md)
Fast Splat Sorting is an optimization for the rendering pipeline of 3D Gaussian Splatting that replaces the original combined 48-bit radix sort with two sequential, narrower sorts: a 32-bit depth sort followed by a 16-bit tileID sort. It solves the performance bottleneck of sorting all splat fragments by their combined tile identifier and depth, which requires processing 48-bit keys for every fragment generated. By separating the visibility check (depth) from the spatial grouping (tileID), it reduces the computational cost of the sorting phase, leveraging the fact that the number of visible splats is typically smaller than the total number of fragments, and that radix sort runtime scales linearly with key width.

### Gaussian Splat Sorting
Sorts Gaussian splats front-to-back within tiles for correct alpha blending, using clip-space $w$ as a monotonic distance proxy to handle reverse-z projection [S3, unofficial]. The steps are:
1. Calculate view depth: `float view_depth = max(0.0, clip_pos.w);` [S3, unofficial].
2. Normalize depth to 0-1 range: `float depth01 = view_depth / (1.0 + view_depth);` [S3, unofficial].
3. Quantize depth to 16-bit integer: `uint depth = uint(depth01 * 65535.0) & 0xFFFF;` [S3, unofficial].
4. Create sort key by combining tile ID and depth: `uint key = (tile_id << 16) | depth;` [S3, unofficial].
5. Store key and splat ID in sort buffers for the current tile iteration: `sort_keys[sort_buffer_offset] = key; sort_values[sort_buffer_offset] = id;` [S3, unofficial].

## Operating characteristics
- **Time Complexity**: $O(n)$ for the radix sort, where $n$ is the number of splats [S1, unofficial].
- **Memory Complexity**: $O(n)$ for the auxiliary buffer `aux` and $O(1)$ for the histogram arrays (fixed size 65,536) [S1, unofficial].
- **Performance**: Consistently 2 times faster than comparison-based sorts for ~100k–200k elements [S1, unofficial].
- **Strengths**: Linear time complexity, efficient for large numbers of splats, leverages GPU-friendly parallel operations [S1, unofficial].
- **Limitations**: Requires positive depth values for correct bit-pattern ordering [S1, unofficial].

## Background
This method is used in Gaussian Splatting rendering pipelines to ensure correct alpha blending by sorting splats by depth [S1, unofficial].
