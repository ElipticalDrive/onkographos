# Gaussian Sorting


## Overview
Gaussian Sorting is the process of ordering 3D Gaussian primitives by their depth in camera space to enable correct front-to-back alpha blending during rasterization [S1, unofficial]. It sets itself apart from general-purpose sorting by specifically targeting the z-coordinate of transformed Gaussian centers, serving as the critical data preparation step for the subsequent tile-based splatting pipeline.

## How it works
**Inputs:**
- A list of $N$ Gaussians, each defined by a position vector $\mathbf{p} \in \mathbb{R}^3$ in world space.
- A view matrix $\mathbf{V}$ (typically $4 \times 4$) representing the camera transformation.

**Outputs:**
- A sorted array of indices or Gaussian references, ordered from smallest to largest camera-space depth ($z$).

**Data Structures:**
- `Gaussian`: Struct containing at least `pos: Vec3` (world space).
- `Indices`: Array of integers $[0, \dots, N-1]$.

**Steps:**
1. **Transform to Camera Space:** For each Gaussian $i$ with world position $\mathbf{p}_i$, compute the camera-space position $\mathbf{p}'_i$.
   $$ \mathbf{p}'_i = \mathbf{V} \cdot \begin{bmatrix} \mathbf{p}_i \\ 1 \end{bmatrix} $$
   Let $z_i$ be the $z$-component (index 2) of $\mathbf{p}'_i$. Note: In standard OpenGL/DirectX conventions, $z$ increases into the screen or decreases; the sort order must match the depth buffer clear state and blending logic. Typically, smaller $z$ is "front" in right-handed systems with negative view direction, or larger $z$ is front in left-handed. The source specifies sorting by the z-component for front-to-back rendering [S1, unofficial].

2. **Sort Indices:** Create an index array $I = [0, 1, \dots, N-1]$. Sort $I$ such that for any adjacent indices $j, j+1$:
   $$ z_{I[j]} \le z_{I[j+1]} $$
   If depths are equal, a stable sort or secondary key (e.g., original index) is required to maintain deterministic behavior [S1, unofficial].

**Pseudocode:**
```python
def gaussian_sort(gaussians, view_matrix):
    """
    Sorts Gaussians by camera-space depth.
    
    Args:
        gaussians: List of objects with attribute 'pos' (Vec3 in world space).
        view_matrix: 4x4 matrix (Vec4xVec4) for camera transformation.
        
    Returns:
        List of indices sorted by camera-space Z depth (front-to-back).
    """
    n = len(gaussians)
    indices = list(range(n))
    
    # Precompute camera-space Z for all Gaussians
    # Assuming view_matrix transforms world to camera space.
    # p' = V * [x, y, z, 1]
    # z_cam is the third component (index 2) of the resulting vector.
    z_values = []
    for i in range(n):
        p_world = gaussians[i].pos
        # Homogeneous coordinate transformation
        # w is typically 1.0 for positions
        p_cam = view_matrix.transform_point(p_world) 
        z_values.append(p_cam.z)
        
    # Sort indices based on z_values
    # Stable sort ensures deterministic order for equal depths
    indices.sort(key=lambda i: z_values[i])
    
    return indices
```

**Parameters:**
- View Matrix: Standard camera view matrix.
- Sort Stability: Must be stable to handle degenerate cases where multiple Gaussians share the same depth [S1, unofficial].

**Edge Cases:**
- **Equal Depth:** If $z_i = z_j$, the relative order is undefined by depth alone. A secondary sort key (e.g., original index) ensures a total ordering [S1, unofficial].
- **Precision:** Floating-point precision in the view transformation may cause jitter in sorting order for very close Gaussians. Using higher precision (e.g., `f64`) for intermediate calculations may be beneficial [G].

## Subtopics

### [Temporal Coherence Heuristic for Gaussian Sorting](7339-temporal-coherence-heuristic-for-gaussian-sorting.md)
A method that introduces a temporal coherence heuristic into the tile sorting phase of 3D Gaussian Splatting rasterization, avoiding the computational cost of re-sorting Gaussians whose depth order has not changed between consecutive frames. It sets itself apart from standard per-frame sorting by leveraging the high degree of similarity between adjacent video frames to skip redundant sorting operations.

### Front-to-Back Rendering for Alpha Blending
An ordering technique that sorts draw calls front-to-back based on the dot product of the vector between chunk positions and the camera position, reducing z-buffer burden and increasing speed for alpha blending [S2, unofficial]. It sets itself apart by operating on chunk-level draw calls rather than individual splats, using a geometric heuristic relative to the camera position.

**Steps:**
1. Define a comparison function for two draw calls $a$ and $b$ with positions $\mathbf{a.pos}$ and $\mathbf{b.pos}$, and camera position $\mathbf{cam::pos}$.
2. Compute the dot product $d = \text{dot}(\mathbf{b.pos} - \mathbf{a.pos}, \mathbf{cam::pos})$.
3. If $d < 0$, return `true` (a comes before b).
4. If $d > 0$, return `false` (b comes before a).
5. If $d = 0$, return `true` if $a.baseVert < b.baseVert$, else `false` (imposes a weak ordering) [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N \log N)$ for the sorting step, where $N$ is the number of Gaussians.
- **Memory Complexity:** $O(N)$ to store the indices and transformed depths.
- **Performance:** Sorting is a significant bottleneck in 3D Gaussian Splatting rasterization. Optimizations like temporal coherence can reduce this cost in video sequences [S1, unofficial].
- **Strengths:** Simple to implement; ensures correct alpha blending.
- **Limitations:** Requires full sort every frame unless temporal coherence is applied; sensitive to camera movement speed.

## Background
Gaussian Sorting is a fundamental step in the rasterization pipeline for 3D Gaussian Splatting, introduced alongside the 3D Gaussian Splatting technique itself. It enables the efficient tile-based rendering approach by ensuring that splats are processed in depth order, which is critical for correct alpha blending without requiring a depth buffer for every pixel [S1, unofficial].
