# Splat Attributes Pass

Also called: Blending Pass, G-Buffer Pass

## Overview
The Splat Attributes Pass is a fragment-shader-driven stage in object-order volume rendering that computes per-fragment visibility and accumulates weighted geometric and photometric attributes into a G-buffer. It solves the problem of correctly occluding the back faces of spherical splats while simultaneously preparing data for subsequent shading or compositing stages. It differs from the [Single-Pass Splat Rendering Pipeline](1254-single-pass-splat-rendering-pipeline.md) by separating visibility determination and attribute accumulation into a distinct pass that writes to intermediate textures, and from the [Three-Pass GPU Point Rendering Pipeline](2837-three-pass-gpu-point-rendering-pipeline.md) by explicitly calculating depth offsets to handle spherical geometry rather than treating splats as simple billboards.

## How it works
**Inputs and Outputs:**
*   **Input:** A stream of splat primitives, each defined by a center position, radius, color, and linear depth in view space. The current depth buffer (`g_depth`) is read to determine occlusion.
*   **Output:** Two G-buffer textures: `g_normal` (vec4, location 0) storing weighted normals, and `g_color` (vec4, location 1) storing weighted RGB color in RGB channels and accumulated weight in the Alpha channel.

**Data Structures:**
*   `g_depth`: Depth texture sampled at `tex_coords = gl_FragCoord.xy / viewport_size`.
*   `g_normal`: `vec4` texture. `xyz` stores the accumulated weighted normal vector.
*   `g_color`: `vec4` texture. `rgb` stores the accumulated weighted color; `a` stores the accumulated scalar weight.

**Parameters:**
*   `epsilon`: A small constant for depth-proximity falloff. Typical value: `0.25` [S1, unofficial].

**Steps:**
1.  **Fragment Position:** Calculate the distance of the current fragment from the center of the splat in screen space:
    $$ \text{from\_center\_pt\_spc} = \text{gl\_PointCoord} - \text{vec2}(0.5, 0.5) $$
2.  **Circular Mask:** Calculate the squared magnitude:
    $$ \text{mag\_sq} = \text{dot}(\text{from\_center\_pt\_spc}, \text{from\_center\_pt\_spc}) $$
    Discard the fragment if $\text{mag\_sq} > 0.25$ (outside the unit circle).
3.  **World-Space Offset:** Convert the screen-space offset to a world-space offset using the splat's radius:
    $$ \text{from\_center\_wld\_spc} = \text{from\_center\_pt\_spc} \times 2 \times i.\text{radius} $$
4.  **Depth Offset:** Calculate the depth offset from the sphere surface to the fragment plane:
    $$ \text{depth\_offset} = \sqrt{i.\text{radius}^2 - \text{dot}(\text{from\_center\_wld\_spc}, \text{from\_center\_wld\_spc})} $$
5.  **Fragment Depth:** Calculate the fragment depth in view space by subtracting the depth offset from the linear depth of the splat center:
    $$ \text{depth} = \text{linearDepth}(\text{gl\_FragCoord.z}) - \text{depth\_offset} $$
6.  **Occlusion Test:** Sample the depth buffer to get the surface depth at the current fragment coordinates:
    $$ \text{tex\_coords} = \text{gl\_FragCoord.xy} / \text{viewport\_size} $$
    $$ \text{surface\_depth} = \text{linearDepth}(\text{texture}(g\_depth, \text{tex\_coords}).x) $$
    Discard the fragment if $\text{depth} > \text{surface\_depth}$ (splat is behind existing geometry).
7.  **Weight Calculation:**
    *   Radial falloff weight:
        $$ w_1 = 1 - \frac{\sqrt{\text{mag\_sq}}}{0.5} $$
    *   Depth-proximity falloff weight:
        $$ w_2 = \frac{\text{surface\_depth} - \text{depth}}{\epsilon} $$
    *   Combined weight:
        $$ \text{weight} = w_1 \times w_2 $$
8.  **Normal Computation:** Calculate the view-space normal from the geometry:
    $$ \text{normal} = \text{normalize}(\text{vec3}(\text{from\_center\_wld\_spc}, \text{depth\_offset})) $$
9.  **Accumulation:**
    *   Accumulate weighted normal into `g_normal.xyz`:
        $$ g\_normal.xyz = \text{weight} \times \text{normal} $$
    *   Accumulate weighted color into `g_color.rgb`:
        $$ \text{color} = \text{weight} \times i.\text{color} $$
        $$ g\_color.rgb = \text{color} $$
    *   Accumulate weight into `g_color.a`:
        $$ g\_color.a = \text{weight} $$

**Pseudocode:**
```python
def splat_attributes_pass(splat, viewport_size, epsilon=0.25):
    # 1. Fragment position relative to center
    from_center_pt_spc = gl_PointCoord - vec2(0.5, 0.5)
    
    # 2. Circular mask
    mag_sq = dot(from_center_pt_spc, from_center_pt_spc)
    if mag_sq > 0.25:
        discard()
        
    # 3. World-space offset
    from_center_wld_spc = from_center_pt_spc * 2.0 * splat.radius
    
    # 4. Depth offset
    depth_offset = sqrt(splat.radius * splat.radius - dot(from_center_wld_spc, from_center_wld_spc))
    
    # 5. Fragment depth
    linear_center_depth = linearDepth(gl_FragCoord.z)
    depth = linear_center_depth - depth_offset
    
    # 6. Occlusion test
    tex_coords = gl_FragCoord.xy / viewport_size
    surface_depth = linearDepth(texture(g_depth, tex_coords).x)
    
    if depth > surface_depth:
        discard()
        
    # 7. Weight calculation
    w1 = 1.0 - (sqrt(mag_sq) / 0.5)
    w2 = (surface_depth - depth) / epsilon
    weight = w1 * w2
    
    # 8. Normal computation
    normal = normalize(vec3(from_center_wld_spc, depth_offset))
    
    # 9. Accumulation
    # Note: In a real implementation, these would be atomic adds or 
    # read-modify-write operations on the G-buffer textures.
    g_normal.xyz += weight * normal
    g_color.rgb += weight * splat.color
    g_color.a += weight
```

## Subtopics

### Front-to-Back Blending Setup
This variant configures the rendering state for the compositing phase that follows the attribute accumulation. It clears the color buffer with RGBA(0,0,0,0) to ensure zero initial alpha and disables depth testing. It enables blending with separate blend factors: RGB uses `GL_ONE_MINUS_DST_ALPHA` / `GL_ONE`, and Alpha uses `GL_ONE_MINUS_DST_ALPHA` / `GL_ONE`. The blend equation is set to `GL_FUNC_ADD` for both RGB and Alpha. It draws instanced quads using `GL_TRIANGLE_FAN` with 4 vertices per instance, passing `splatCount` instances. Vertex attributes include 'position' (2 floats) and 'index' (1 unsigned int, instanced with divisor 1). Uniforms passed to the shader include projection (mat4), view (mat4), focal (vec2: fx, fy), viewport (vec2: width, height), and `u_texture` (sampler2D at unit 0) [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot F)$, where $N$ is the number of splats and $F$ is the number of fragments covered by the splats. The depth test and texture sampling add constant overhead per fragment.
*   **Memory Complexity:** $O(W \cdot H)$ for the G-buffer textures (`g_normal`, `g_color`, `g_depth`), where $W$ and $H$ are the viewport dimensions.
*   **Strengths:** Correctly handles spherical geometry occlusion via depth offset calculation. Separates visibility logic from shading, allowing for flexible downstream processing.
*   **Limitations:** Requires multiple texture reads/writes (depth buffer, G-buffers). The depth-proximity falloff ($w_2$) can introduce artifacts if $\epsilon$ is not tuned correctly relative to scene depth ranges.
*   **When to use:** When accurate spherical splat rendering is required and subsequent passes need access to normals or accumulated weights.
*   **When not to use:** For simple billboard rendering where depth offsets are unnecessary, or when memory bandwidth is a critical bottleneck and a single-pass approach is preferred.

## Background
The Splat Attributes Pass originates from object-order volume rendering techniques that use point-sampled primitives to represent volumetric data. It is implemented in the [PointCloudRendering](https://github.com/arminkz/PointCloudRendering) project [S1, unofficial] and adapted in [gsplat-opengl](https://github.com/liaozhangsheng/gsplat-opengl) for Gaussian splatting applications [S2, unofficial]. The method builds on the principle of stage separation, where geometric projection and compositing are handled independently to allow for optimized intermediate storage [S1, S3, unofficial].
