# Rendering Pipeline Architecture


## Overview
Rendering Pipeline Architecture defines the structural organization of rendering stages for object-order splatting, coordinating data flow between geometry processing, attribute accumulation, and final compositing. It solves the problem of efficiently projecting 3D point-based representations onto a 2D image while managing depth occlusion, attribute blending, and memory bandwidth. It differs from [Plug-and-Play Ray Marching and Rendering](981-plug-and-play-ray-marching-and-rendering.md) by relying on rasterization primitives rather than ray casting, and from [Volume Rendering Pipeline](1318-volume-rendering-pipeline.md) by operating on discrete point sprites rather than volumetric voxels.

## Shared principles
The family shares the fundamental mechanism of decomposing the rendering of point-based geometry into distinct, sequential stages that can be optimized for specific tasks such as depth testing, attribute accumulation, or normalization. All methods utilize a fragment shader or equivalent processing unit to compute per-pixel contributions based on the geometric relationship between the splat center and the fragment position.

Key shared mathematical concepts include:
1.  **Splat Projection:** Mapping 3D point attributes (position, radius, color) to 2D screen space.
2.  **Weight Calculation:** Determining the contribution of each fragment based on radial distance from the splat center and/or depth proximity to the visible surface.
3.  **Accumulation:** Summing weighted attributes (color, normal) into framebuffers.
4.  **Occlusion Handling:** Using depth buffers to discard fragments behind opaque geometry.

The specific implementation of these principles varies: some pipelines decouple attribute computation from final color writing (deferred), while others combine them in a single pass. Some rely on hardware depth testing, while others perform explicit depth comparisons in the fragment shader.

## Subtopics

### [Splat Attributes Pass](1066-splat-attributes-pass.md)
A fragment-shader-based step that computes visibility-weighted attributes and writes them to a G-Buffer. It differs by decoupling attribute accumulation from the final color buffer write, allowing for deferred shading. Choose this when complex lighting or multi-pass compositing is required.

### [Single-Pass Splat Rendering Pipeline](1254-single-pass-splat-rendering-pipeline.md)
Combines splat and mesh rendering in a single pass using planar patches and height fields. It differs by replacing screen-space blending with object-space attribute interpolation on regular grid patches. Choose this for high-quality shader effects (reflection, refraction) with dense point sets.

### [Three-Pass GPU Point Rendering Pipeline](2837-three-pass-gpu-point-rendering-pipeline.md)
Decomposes rendering into depth offset, accumulation, and normalization passes. It differs by explicitly separating these stages to handle projective distortions and varying splat sizes. Choose this for perspective-accurate point cloud rendering on modern GPUs.

## Background
The concept of splatting was introduced by Williams [S1] in 1978 as a method for rendering 3D objects using point sprites. The evolution of rendering pipelines for point-based geometry has been driven by the need to handle large datasets efficiently on GPUs. Early methods relied on simple screen-space blending, while modern approaches incorporate deferred shading, patch-based representations, and multi-pass normalization to improve visual quality and performance. The specific architectures described in the subtopics represent optimizations for different use cases, such as real-time rendering, high-fidelity effects, and accurate perspective projection.
