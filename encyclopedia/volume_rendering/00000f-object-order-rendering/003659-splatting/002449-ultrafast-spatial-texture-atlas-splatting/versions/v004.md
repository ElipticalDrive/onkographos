# Ultrafast Spatial Texture-Atlas Splatting

Also called: Texture-Atlas Splatting

## Overview
Ultrafast Spatial Texture-Atlas Splatting is a learned sparse scene representation that eliminates runtime neural network inference by baking view-independent high-frequency texture into a hardware-accelerated 2D texture atlas [S1, unofficial]. It represents the scene as a sparse set of oriented 2D Beta kernels, separating low-frequency view-dependent appearance (stored per-surfel) from high-frequency spatial texture (stored in the atlas) [S1, unofficial]. Unlike sibling methods that rely on per-primitive textures or runtime hash-grid queries, this method allocates a single global atlas after sparsification, enabling significantly faster rendering speeds (7–9× faster than 3DGS) while maintaining high perceptual quality [S1, unofficial].

## How it works
**Inputs:** A set of optimized 2D surfels (position $\mu_i$, rotation $q_i$, scale $s_i$, opacity $o_i$, and view-dependent color parameters) and a trained multi-resolution hash grid with an MLP decoder.
**Outputs:** A rendered image and a compressed 2D texture atlas (55–320 MB for typical scenes) [S1, unofficial].

**Data Structures:**
1.  **Surfel Attributes:** For each surfel $i$, store:
    *   $\mu_i \in \mathbb{R}^3$: Position.
    *   $q_i \in \mathbb{R}^4$: Rotation (quaternion).
    *   $s_i \in \mathbb{R}^2$: 2D scale.
    *   $o_i \in \mathbb{R}$: Opacity.
    *   $f_{SV}(\mathbf{d})$: View-dependent color function parameters (e.g., spherical harmonics coefficients or MLP weights).
    *   $b_{SV} = 0.5$: Fixed offset for neutral gray baseline [S1, unofficial].
2.  **Texture Atlas:** A 2D RGB texture where each surfel maps to a rectangular region. The atlas stores signed residuals (positive and negative color offsets) to allow subtraction from the base color, providing higher representational power than positive-only textures [S1, unofficial].

**Steps:**

1.  **Scene Representation (Training Phase):**
    Represent the scene as a sparse set of oriented 2D Beta kernels. Regularize the kernels to reduce overdraw by using a falloff prior that encourages flat, hard-edged profiles [S1, unofficial].

2.  **Appearance Decomposition:**
    Decompose appearance into:
    *   **Per-surfel view-dependent color:** $f_{SV}(\mathbf{d})$, which varies with viewing direction $\mathbf{d}$ but is constant across the surfel surface.
    *   **View-independent residual:** $\rho(\mathbf{x}) = f_\theta(\mathbf{E}_\theta(\mathbf{x}))$, where $\mathbf{E}_\theta$ is a multi-resolution hash grid and $f_\theta$ is an MLP decoder. This residual captures high-frequency spatial texture [S1, unofficial].

3.  **Kernel Definition:**
    Use the Deformable Beta kernel $\mathcal{B}(x;b)$ instead of a Gaussian. The kernel is defined as:
    $$ \mathcal{B}(x;b) = (1-x)^{\beta(b)} $$
    where:
    *   $x \in [0,1]$ is the squared radial distance from the kernel center, normalized to 1 at the edge of the support.
    *   $b \in \mathbb{R}$ is a shape parameter.
    *   $\beta(b) = 5\sigma(b)$, where $\sigma$ is the sigmoid function.
    *   Small $b$ values produce flat, hard-edged disks; large $b$ values produce soft, Gaussian-like surfels. The method restricts $b$ to keep kernels between these extremes [S1, unofficial].

4.  **Fragment Color Computation:**
    For a fragment at position $\mathbf{x}$ with viewing direction $\mathbf{d}$, compute the color $\mathbf{c}(\mathbf{x}, \mathbf{d})$ as:
    $$ \mathbf{c}(\mathbf{x}, \mathbf{d}) = \text{ReLU}\left(\text{ReLU}(f_{SV}(\mathbf{d}) + b_{SV}) + f_\theta(\mathbf{E}_\theta(\mathbf{x}))\right) $$
    where $b_{SV} = 0.5$ is a fixed offset [S1, unofficial].

5.  **Hash Grid Sampling and Baking:**
    *   During training, query the hash grid $\mathbf{E}_\theta$ at every fragment along the surface of each primitive to absorb fine spatial texture [S1, unofficial].
    *   After training, sample the hash-grid output across the surface of each primitive.
    *   Bake these samples into a compressed RGB texture atlas. Each surfel corresponds to a rectangle in the atlas [S1, unofficial].

6.  **Atlas Finetuning:**
    Finetune the atlas texels directly against the training images to overcome hash collisions that occurred during training [S1, unofficial].

7.  **Rendering (Inference Phase):**
    *   **Sorting:** Sort surfels front-to-back based on depth [S1, unofficial].
    *   **Projection:** Project each surfel onto the image plane. Use an exact rational reformulation of the ray-surfel intersection test for efficiency [S1, unofficial].
    *   **Texture Fetch:** For each pixel covered by a surfel, perform a hardware-accelerated texture fetch from the atlas to retrieve the residual color.
    *   **Compositing:** Composite the surfels using alpha blending. The effective alpha is $\alpha_i(\mathbf{x}) = o_i \mathcal{B}(x;b)$, and the color is retrieved from the atlas and combined with the per-surfel view-dependent color [S1, unofficial].

**Pseudocode:**

```python
import math

def sigmoid(x):
    return 1.0 / (1.0 + math.exp(-x))

def beta_kernel(x, b):
    """
    Compute the Deformable Beta kernel value.
    x: squared radial distance normalized to [0, 1]
    b: shape parameter
    """
    beta_b = 5.0 * sigmoid(b)
    # Clamp x to [0, 1] to avoid numerical issues
    x = max(0.0, min(1.0, x))
    return (1.0 - x) ** beta_b

def compute_fragment_color(f_sv_params, d, atlas_texel, b_sv=0.5):
    """
    Compute the final color for a fragment.
    f_sv_params: parameters for view-dependent color function
    d: viewing direction vector
    atlas_texel: RGB vector from texture atlas (residual)
    b_sv: fixed offset (0.5)
    """
    # Compute view-dependent color (simplified as a linear combination for pseudocode)
    # In practice, f_sv(d) might involve spherical harmonics or an MLP
    f_sv = compute_view_dependent_color(f_sv_params, d)
    
    # Apply ReLU activations as per the formula
    # ReLU(f_sv(d) + b_sv)
    base_color = max(0.0, f_sv + b_sv)
    
    # Add residual from atlas
    # ReLU(base_color + atlas_texel)
    # Note: The formula uses ReLU(ReLU(...) + residual). 
    # Assuming element-wise operations for RGB.
    final_color = max(0.0, base_color + atlas_texel)
    
    return final_color

def render_scene(surfels, camera, atlas_texture):
    """
    Render the scene using Ultrafast Spatial Texture-Atlas Splatting.
    """
    # 1. Sort surfels front-to-back
    sorted_surfels = sort_surfels_by_depth(surfels, camera)
    
    # 2. Initialize image buffer
    image = zeros(image_width, image_height, 3)
    alpha_accum = zeros(image_width, image_height)
    
    # 3. Iterate over sorted surfels
    for surfel in sorted_surfels:
        # Project surfel to screen space
        screen_coords = project_surfel_to_screen(surfel, camera)
        
        # Determine bounding box of the splat
        bbox = get_splat_bounding_box(screen_coords)
        
        # 4. Iterate over pixels in bounding box
        for y, x in bbox:
            if not is_pixel_in_splat(x, y, screen_coords):
                continue
            
            # Compute squared radial distance normalized to support edge
            x_norm = compute_normalized_radial_distance(x, y, screen_coords)
            
            # Compute kernel weight
            # b is the shape parameter for this surfel
            weight = beta_kernel(x_norm, surfel.b)
            
            # Effective alpha
            alpha = surfel.opacity * weight
            
            # Skip if alpha is negligible
            if alpha < 1e-6:
                continue
            
            # Fetch residual from atlas
            # Map screen coordinates to atlas UVs
            uv = map_screen_to_atlas_uv(x, y, screen_coords)
            residual = atlas_texture.sample(uv)
            
            # Compute view-dependent color
            # d is the viewing direction for this pixel
            d = compute_view_direction(x, y, camera)
            base_color = compute_fragment_color(surfel.f_sv_params, d, residual)
            
            # Alpha blending (front-to-back)
            # C_out = C_in * (1 - alpha) + C_new * alpha
            # A_out = A_in + alpha * (1 - A_in)
            
            current_alpha = alpha_accum[y, x]
            if current_alpha >= 1.0:
                continue
                
            # Blend
            new_alpha = alpha * (1.0 - current_alpha)
            blended_color = image[y, x] * (1.0 - new_alpha) + base_color * new_alpha
            
            image[y, x] = blended_color
            alpha_accum[y, x] += new_alpha

    return image
```

**Parameters:**
*   **Texture Atlas Size:** 55–320 MB for typical scenes [S1, unofficial].
*   **Fixed Offset $b_{SV}$:** 0.5 [S1, unofficial].
*   **Shape Parameter $b$:** Restricted to lie between flat disk and soft Gaussian profiles [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Hash Collisions:** During training, hash collisions can occur. These are mitigated by finetuning the atlas texels directly against training images [S1, unofficial].
*   **Overdraw:** Soft Gaussian tails cause redundant overlaps. The use of flat Beta kernels reduces overdraw and primitive count [S1, unofficial].
*   **Positive-Only Residuals:** Using only positive additive textures limits representational power (14–20 dB PSNR vs. 53–55 dB for signed residuals) [S1, unofficial].

## Subtopics

### EWA Splatting
Uses elliptical weighted average filtering for smooth projection. Chosen when smoothness is prioritized over sharp edges. [EWA Splatting](1069-ewa-splatting.md)

### Ray-Driven Splatting
Traces rays to determine splat contributions. Chosen for accuracy in complex scenes but is slower. [Ray-Driven Splatting](1156-ray-driven-splatting.md)

### Slice-by-Slice (Sheet Buffer) Splatting
Renders volume slices as textured quads. Chosen for efficient hardware rasterization of regular grids. [Slice-by-Slice (Sheet Buffer) Splatting](2110-slice-by-slice-sheet-buffer-splatting.md)

### Gaussian Avatar Reconstruction
Uses 3D Gaussians for human avatars. Chosen for dynamic human rendering. [Gaussian Avatar Reconstruction](1575-gaussian-avatar-reconstruction.md)

## Operating characteristics
*   **Time Complexity:** Rendering is dominated by sorting and blending. The exact rational reformulation of the ray-surfel intersection reduces shader overhead.
*   **Memory Complexity:** Requires a texture atlas of 55–320 MB for typical scenes, which is larger than memory-optimized 3DGS representations but fits on low-to-mid-range GPUs [S1, unofficial].
*   **Performance:** Renders 7.1–9.1× faster than 3DGS and 1.2–1.8× faster than FastGS and Speedy-Splat on common benchmarks [S1, unofficial].
*   **Strengths:** High rendering speed, reduced overdraw via flat kernels, high perceptual quality (53–55 dB PSNR with signed residuals).
*   **Limitations:** Larger memory footprint than some compressed 3DGS variants; requires training phase to bake the atlas.
*   **When to Use:** When high frame rates are required and hardware texture mapping is available.
*   **When Not to Use:** When memory is extremely constrained and lower frame rates are acceptable.

## Background
Ultrafast Spatial Texture-Atlas Splatting was introduced by Petkov and Klaus from Siemens Healthineers in 2026 [S1, unofficial]. It builds on 2D Gaussian Splatting (2DGS) by Huang et al. (2024) and incorporates the Deformable Beta kernel from Liu et al. (2025) [S1, unofficial]. The method addresses the rendering overhead of neural radiance representations in Gaussian Splatting by baking the neural component into a texture atlas [S1, unofficial].
