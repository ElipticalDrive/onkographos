# Ultrafast Spatial Texture-Atlas Splatting

Also called: Texture-Atlas Splatting

## Overview
Ultrafast Spatial Texture-Atlas Splatting is a learned sparse scene representation that eliminates runtime neural network inference by baking view-independent high-frequency texture into a hardware-accelerated 2D texture atlas [S1, unofficial]. It represents the scene as a sparse set of oriented 2D Beta kernels, separating low-frequency view-dependent appearance (stored per-surfel) from high-frequency spatial texture (stored in the atlas) [S1, unofficial]. This approach achieves 7–9× faster rendering than 3D Gaussian Splatting (3DGS) on common benchmarks by reducing overdraw via flat Beta kernels and replacing expensive ray-surfel intersection shaders with an exact rational reformulation [S1, unofficial].

## How it works
**Inputs:** A set of optimized 2D surfels (position $\boldsymbol{\mu}_i$, rotation $\mathbf{q}_i$, scale $\mathbf{s}_i$, opacity $o_i$, and view-dependent color parameters) and a trained multi-resolution hash grid $E_\theta$ with MLP decoder $f_\theta$.
**Outputs:** A compressed RGB texture atlas (55–320 MB for typical scenes) and the surfel attributes. The final rendered image.

**Data Structures:**
1.  **Surfel Attributes:** For each surfel $i$:
    *   $\boldsymbol{\mu}_i \in \mathbb{R}^3$: Position.
    *   $\mathbf{q}_i \in \mathbb{R}^4$: Rotation (quaternion).
    *   $\mathbf{s}_i \in \mathbb{R}^2$: 2D scale.
    *   $o_i \in \mathbb{R}$: Opacity.
    *   $f_{SV}(\mathbf{d})$: View-dependent color function parameters (stored per-surfel).
2.  **Texture Atlas:** A 2D RGB texture where each surfel $i$ maps to a rectangular region. The texels store the signed residual color $\rho(\mathbf{x}) = f_\theta(E_\theta(\mathbf{x}))$. The atlas is allocated once after sparsification [S1, unofficial].

**Numbered Steps:**

1.  **Primitive Representation:** Represent the scene as a sparse set of oriented 2D surfels. Each surfel $i$ is defined by its position, rotation, scale, and opacity [S1, unofficial].
2.  **Kernel Selection:** Use the Deformable Beta kernel $\mathcal{B}(x;b)$ instead of a Gaussian. The kernel shape is controlled by a parameter $b \in \mathbb{R}$:
    $$ \mathcal{B}(x;b) = (1-x)^{\beta(b)} $$
    where $x \in [0,1]$ is the squared radial distance from the kernel center normalized to 1 at the edge of the support, and $\beta(b) = 5\sigma(b)$ with $\sigma$ being the sigmoid function [S1, unofficial]. Small $b$ values produce flat, hard-edged disks to reduce overdraw; large $b$ values produce soft, Gaussian-like profiles. The parameter $b$ is restricted to lie between a flat disk and a soft Gaussian [S1, unofficial].
3.  **Appearance Decomposition:** Decompose the fragment color $\mathbf{c}(\mathbf{x}, \mathbf{d})$ into a per-surfel view-dependent term and a view-independent residual:
    $$ \mathbf{c}(\mathbf{x}, \mathbf{d}) = \text{ReLU}\left(\text{ReLU}(f_{SV}(\mathbf{d}) + b_{SV}) + f_\theta(\mathbf{E}_\theta(\mathbf{x}))\right) $$
    where $b_{SV} = 0.5$ is a fixed offset providing a neutral gray baseline, $f_{SV}$ is the per-surfel view-dependent color, and $f_\theta(\mathbf{E}_\theta(\mathbf{x}))$ is the residual from the hash grid $E_\theta$ and MLP decoder $f_\theta$ [S1, unofficial].
4.  **Training:**
    *   Query the hash grid at every fragment along the surfel's surface during training to absorb fine spatial texture [S1, unofficial].
    *   Per-surfel attributes remain constant across the surfel to absorb low-frequency view-dependent appearance [S1, unofficial].
    *   Use signed texture residuals (positive and negative color offsets) to provide representational power, allowing a single surfel to reproduce color variation that positive-only textures cannot [S1, unofficial].
    *   Train jointly with the multi-view error criterion of FastGS to limit densification [S1, unofficial].
    *   Introduce a falloff prior using Beta kernels to regularize kernels toward flat, hard-edged profiles, dampening positional gradients and reducing primitive count [S1, unofficial].
5.  **Baking:**
    *   Sample the hash-grid across the surface of each primitive during training [S1, unofficial].
    *   Bake the output of the hash-grid sampling into a compressed RGB texture atlas [S1, unofficial].
    *   Finetune the atlas texels directly against the training images to overcome hash collisions from training [S1, unofficial].
6.  **Rendering:**
    *   Perform fast, per-fragment texture fetches from the atlas [S1, unofficial].
    *   Evaluate the ray-surfel intersection using an exact rational reformulation of the intersection test [S1, unofficial].
    *   Composite the surfels in front-to-back order using alpha blending [S1, unofficial].

**Pseudocode:**

```python
import math

def sigmoid(x):
    return 1.0 / (1.0 + math.exp(-x))

def beta_kernel(x, b):
    """
    Compute the Deformable Beta kernel value.
    x: squared radial distance normalized to [0, 1]
    b: shape parameter
    """
    beta = 5.0 * sigmoid(b)
    # Clamp x to [0, 1] to avoid domain errors
    x = max(0.0, min(1.0, x))
    return (1.0 - x) ** beta

def compute_fragment_color(surfel, hash_grid, texels, view_direction, fragment_uv):
    """
    Compute the color of a fragment covered by a surfel.
    surfel: object containing f_sv_params, opacity, etc.
    hash_grid: multi-resolution hash grid structure
    texels: the baked texture atlas
    view_direction: d
    fragment_uv: UV coordinates within the surfel's texture region
    """
    # 1. View-dependent color (low frequency)
    # f_sv is a function of view_direction d, stored in surfel attributes
    f_sv = surfel.compute_view_dependent_color(view_direction)
    
    # 2. Base color with neutral gray baseline
    b_sv = 0.5
    base_color = max(0.0, f_sv + b_sv) # ReLU(base)
    
    # 3. View-independent residual (high frequency)
    # Option A: Use hash grid (during training or if not baked)
    # hash_query = hash_grid.query(fragment_world_position)
    # residual = mlp_decoder(hash_query)
    
    # Option B: Use baked texture atlas (during inference)
    # Sample texels at fragment_uv
    residual = texels.sample(fragment_uv)
    
    # 4. Combine
    # ReLU(base + residual)
    final_color = max(0.0, base_color + residual)
    
    return final_color

def render_scene(surfels, camera, texture_atlas):
    """
    Render the scene using the texture atlas and rational intersection.
    """
    image = empty_image()
    
    # Sort surfels front-to-back based on camera
    sorted_surfels = sort_surfels_front_to_back(surfels, camera)
    
    for surfel in sorted_surfels:
        # Transform surfel to screen space
        screen_bounds = transform_to_screen(surfel, camera)
        
        # Iterate over pixels in screen bounds
        for y, x in screen_bounds:
            # Check if pixel is covered by surfel
            # Use exact rational reformulation of ray-surfel intersection
            if is_covered(x, y, surfel, camera):
                # Compute UV coordinates within the surfel's texture region
                uv = compute_uv(x, y, surfel, camera)
                
                # Fetch color from texture atlas
                color = texture_atlas.sample(uv)
                
                # Compute effective alpha
                # alpha = opacity * kernel_value
                # Kernel value depends on distance from center
                dist_sq = compute_normalized_squared_distance(x, y, surfel)
                kernel_val = beta_kernel(dist_sq, surfel.b_param)
                alpha = surfel.opacity * kernel_val
                
                # Alpha composite
                image[x, y] = composite(image[x, y], color, alpha)
                
    return image
```

**Parameters:**
*   $b_{SV} = 0.5$: Fixed offset inside the inner ReLU activation [S1, unofficial].
*   Texture atlas size: 55–320 MB for typical scenes [S1, unofficial].
*   $\beta(b) = 5\sigma(b)$: Shape parameter scaling [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Hash Collisions:** Hash collisions from training can degrade quality. Finetuning the atlas texels directly against training images mitigates this [S1, unofficial].
*   **Overdraw:** Soft Gaussian tails cause redundant overlaps. Using flat Beta kernels (small $b$) reduces overdraw and primitive count [S1, unofficial].
*   **Sparsity:** Pipelines using per-primitive textures start from a converged dense model with densification frozen, capping sparsity. This method allocates the atlas once after sparsification, allowing higher sparsity [S1, unofficial].

## Subtopics

### Deformable Beta Kernels
A kernel family defined by $\mathcal{B}(x;b) = (1-x)^{\beta(b)}$ that interpolates between flat disks and soft Gaussals via the parameter $b$. Chosen to reduce overdraw compared to standard Gaussians. [Link](1792-splat-extent-and-projection.md)

### Texture Atlas Baking
The process of converting view-independent neural queries (hash grid + MLP) into a static 2D texture map. Enables hardware-accelerated sampling without runtime neural inference. [Link](1411-rendering-pipelines-and-passes.md)

### Rational Ray-Surfel Intersection
An exact mathematical reformulation of the intersection test between a ray and a planar surfel, optimized for GPU shader performance. [Link](1792-splat-extent-and-projection.md)

## Operating characteristics
*   **Time Complexity:** Rendering is dominated by texture fetches and simple arithmetic, avoiding neural network evaluations. The rational intersection test is computationally cheaper than standard ray-surfel shaders.
*   **Memory Complexity:** Requires a texture atlas of 55–320 MB for typical scenes, which is larger than memory-optimized 3DGS representations but fits on low-to-mid-range GPUs [S1, unofficial].
*   **Performance:** Renders 7.1–9.1× faster than 3DGS and 1.2–1.8× faster than FastGS and Speedy-Splat on common benchmarks [S1, unofficial].
*   **Strengths:** High rendering speed due to elimination of runtime neural inference; reduced overdraw via flat kernels; high sparsity.
*   **Limitations:** Larger memory footprint than some compressed 3DGS variants; requires training to bake the atlas; signed residuals require careful handling of negative values in texture formats.
*   **When to Use:** Real-time rendering of high-fidelity scenes where GPU compute is limited by neural network inference overhead.
*   **When Not to Use:** When memory is extremely constrained and smaller scene representations are prioritized over rendering speed.

## Background
Ultrafast Spatial Texture-Atlas Splatting was introduced by Petkov and Klaus from Siemens Healthineers in 2026 [S1, unofficial]. It builds on 2D Gaussian Splatting (2DGS) and FastGS, aiming to solve the rendering overhead caused by runtime neural network evaluations in neural radiance representations. The method leverages the observation that view-independent high-frequency texture can be baked into a texture atlas, while view-dependent low-frequency appearance remains per-surfel.
