# InstantSplat

Also called: MASt3R/VGGT-guided 3DGS, Pose-free 3D Gaussian Splatting

## Overview
InstantSplat is a pose-free, sparse-view 3D Gaussian Splatting method that reconstructs scenes from uncalibrated image collections in seconds by leveraging MASt3R or VGGT geometry priors [S1, unofficial]. Unlike standard differentiable rendering which requires known camera poses, InstantSplat bypasses explicit pose estimation by using these priors to initialize the 3D structure, allowing for rapid optimization [S1, unofficial]. It distinguishes itself from feed-forward methods like pixelSplat by relying on geometry priors for initialization rather than direct image-to-Gaussian regression, and from joint pose optimization by fixing poses via priors rather than learning them [S1, unofficial][6464-pixelsplat.md].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of uncalibrated images $\{I_i\}$ (intrinsics and extrinsics unknown).
*   **Output:** A set of 3D Gaussian primitives $\{G_i\}$ defined by mean $\mu_i$, covariance $\Sigma_i$, opacity $\alpha_i$, and spherical harmonics coefficients $c_{i,lm}$ [6136-instantsplat.md][6464-pixelsplat.md].

**Data Structures:**
The method initializes a sparse set of 3D points using a geometry prior network (MASt3R or VGGT). These points are converted into Gaussian primitives. The exact layout of the Gaussian primitive is standard for 3DGS:
*   $\mu_i \in \mathbb{R}^3$: Mean position.
*   $\Sigma_i \in \mathbb{R}^{3 \times 3}$: Covariance matrix (often parameterized as rotation $R_i$ and scale $S_i$).
*   $\alpha_i \in [0, 1]$: Opacity.
*   $c_{i,lm}$: Spherical Harmonics coefficients for view-dependent color.

**Steps:**
1.  **Geometry Prior Extraction:** Run MASt3R or VGGT on the input image pairs or collection to obtain dense or sparse 3D point clouds and relative poses [S1, unofficial].
2.  **Initialization:** Initialize the 3D Gaussian set $\{G_i\}$ using the points from the prior. The poses are fixed to those estimated by the prior [S1, unofficial].
3.  **Differentiable Rendering:** Render the images from the fixed poses using the current Gaussian set [6136-instantsplat.md][6464-pixelsplat.md].
4.  **Optimization:** Minimize the photometric reconstruction error. The loss function combines L1 loss and perceptual metrics:
    $$ \mathcal{L} = \mathcal{L}_{L1} + \lambda \mathcal{L}_{MS-SSIM} $$
    or
    $$ \mathcal{L} = \mathcal{L}_{MSE} + \lambda \mathcal{L}_{LPIPS} $$
    [6136-instantsplat.md][6464-pixelsplat.md].
5.  **Update:** Update Gaussian parameters ($\mu, \Sigma, \alpha, c$) via gradient descent. Poses remain fixed [S1, unofficial].

**Parameters:**
*   $\lambda$: Weight for the perceptual loss term. Typical values are not specified in the sources.
*   Learning rate: Not specified in the sources.

**Edge Cases and Pitfalls:**
*   **Prior Accuracy:** The quality of the reconstruction is heavily dependent on the accuracy of the MASt3R/VGGT priors. Poor priors may lead to incorrect initialization [S1, unofficial].
*   **Sparse Views:** While designed for sparse views, extremely sparse inputs (e.g., 2 views) may still suffer from ambiguity if the prior is weak [S1, unofficial].

## Subtopics

### MoSca
A prior-aided monocular dynamic Gaussian Splatting method using CoTracker, VGG-T, DUSt3R, or metric-depth priors [S1, unofficial]. It extends InstantSplat's pose-free concept to dynamic scenes by incorporating temporal priors [S1, unofficial].

### Shape-of-Motion
A prior-aided monocular dynamic Gaussian Splatting method using CoTracker, VGG-T, DUSt3R, or metric-depth priors [S1, unofficial]. It focuses on capturing the motion structure of dynamic scenes using similar priors as MoSca [S1, unofficial].

### Feature-3DGS
A method storing per-Gaussian language features (CLIP, LSeg) for open-vocabulary 3D segmentation [S1, unofficial]. It adds semantic capabilities to the Gaussian representation, allowing for language-based queries [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Trains in seconds, significantly faster than standard 3DGS which requires iterative pose optimization [S1, unofficial].
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:** Matches pose-aware baselines and surpasses prior pose-free methods in zero-shot evaluations at real-time rendering latency [S1, unofficial].
*   **Strengths:** Fast training, no need for camera pose estimation, works with sparse views.
*   **Limitations:** Dependent on the quality of the geometry prior, may struggle with highly dynamic scenes without temporal priors.
*   **When to use:** When camera poses are unknown and rapid reconstruction is needed.
*   **When not to use:** When high precision is required and priors are unreliable, or for dynamic scenes without temporal extensions.

## Background
InstantSplat was introduced as a solution for sparse-view and few-shot 3D Gaussian Splatting, addressing the need for pose-free reconstruction [S1, unofficial]. It builds on the principles of differentiable rendering and 3D Gaussian Splatting, integrating modern geometry priors like MASt3R and VGGT to enable fast, accurate reconstructions from uncalibrated images [S1, unofficial].
