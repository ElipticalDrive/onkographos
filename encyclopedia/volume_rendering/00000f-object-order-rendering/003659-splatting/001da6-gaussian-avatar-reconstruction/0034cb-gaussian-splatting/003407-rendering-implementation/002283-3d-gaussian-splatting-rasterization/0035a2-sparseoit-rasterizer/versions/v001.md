# SparseOIT Rasterizer

Also called: GPU software rasterization of 3D Gaussians with pre-rendering

## Overview
The SparseOIT Rasterizer is a method for rendering 3D Gaussian Splatting scenes that computes a weighted blended order-independent transparency (OIT) image and a pre-rendered image simultaneously [S1, unofficial]. It solves the depth-sorting bottleneck of standard alpha-blending by decoupling the blending process from the depth order of the Gaussians, relying instead on a tile-based sorting strategy [S1, unofficial]. Unlike standard differentiable rasterizers that require strict depth sorting per pixel, this method uses a blend-and-normalize (BAN) function for final color and a blend-and-update (BAU) function for state accumulation, allowing for parallel computation of independent Gaussian variables during backward propagation [S1, unofficial].

## How it works
**Inputs:**
*   Image dimensions: width $w$, height $h$.
*   Gaussian attributes: 3D means $M$, covariances $S$, colors $C$, opacities $A$.
*   View matrix: $V$.

**Outputs:**
*   Rendered image $I$.
*   Pre-rendered image state $I_{pre}$.

**Data Structures:**
*   $M'$: Screen-space projected means.
*   $S'$: Screen-space projected covariances.
*   $T$: Tile grid structure for image dimensions $w, h$.
*   $L$: List of Gaussian data entries, duplicated and assigned tile keys.
*   $K$: List of tile keys corresponding to entries in $L$.
*   $R$: Ranges identifying the subset of Gaussians belonging to each tile.

**Parameters:**
*   **BAN (Blend and Normalize):** Computes the final OIT color for a pixel.
*   **BAU (Blend and Update):** Updates the pre-rendered image state for subsequent blending or accumulation.
*   **Update Interval:** In most cases, the active set update interval is standard; for scenes like *train*, *room*, and *bonsai*, it is set to 600 to exceed twice the number of training views [S1, unofficial].

**Formulas:**
The final color $\mathbf{C}$ is computed as:
$$
\mathbf{C} = T \mathbf{c}_0 + (1-T)F
$$
where:
*   $T$ is the accumulated opacity/transmittance factor.
*   $\mathbf{c}_0$ is the background color.
*   $F = \frac{P}{Q}$ is the weighted average color.
*   $P = \sum_{i=1}^{N} \mathbf{c}_i \alpha_i w_i$.
*   $Q = \sum_{i=1}^{N} \alpha_i w_i$.
*   $\mathbf{c}_i$ is the color of the $i$-th Gaussian.
*   $\alpha_i$ is the opacity of the $i$-th Gaussian.
*   $w_i$ is the weight of the $i$-th Gaussian.

**Backward Propagation Gradients:**
The gradients for optimization are derived as follows [S1, unofficial]:
$$
\frac{\partial \mathbf{C}}{\partial \mathbf{c}_i} = (1-T)\frac{\alpha_i w_i}{Q}
$$
$$
\frac{\partial \mathbf{C}}{\partial \alpha_i} = \frac{T}{1-\alpha_i}(F-\mathbf{c}_0) + (1-T)\frac{w_i}{Q}(\mathbf{c}_i - F)
$$
$$
\frac{\partial \mathbf{C}}{\partial w_i} = (1-T)\frac{\alpha_i}{Q}(\mathbf{c}_i - F)
$$
From these equations, it is observed that the variables of each Gaussian are mutually independent, allowing for parallel computation [S1, unofficial].

**Algorithm Steps:**
1.  **CullGaussian(p, V):** Cull Gaussians based on position $p$ and view $V$.
2.  **ScreenspaceGaussians(M, S, V):** Project 3D means $M$ and covariances $S$ to screen space, resulting in $M'$ and $S'$.
3.  **CreateTiles(w, h):** Create a tile grid $T$ for the image dimensions $w$ and $h$.
4.  **DuplicateWithKeys(M', T):** Duplicate Gaussian data into list $L$ and assign tile keys $K$ based on which tile each Gaussian falls into.
5.  **SortByKeys(K, L):** Sort the entries in $L$ only by their tile ID in $K$. This step does not sort by depth.
6.  **IdentifyTileRanges(T, K):** Identify the start and end ranges $R$ of Gaussians for each tile $t$.
7.  **Initialize:** Set the rendered image $I$ to 0.
8.  **Loop over all tiles $t$ in $T$:**
    9.  **Loop over all pixels $i$ in tile $t$:**
        10. **GetTileRange(R, t):** Retrieve the range $r$ of Gaussians associated with tile $t$.
        11. **BAN(i, L, r, K, M', S', C, A, I_pre[i]):** Compute the final color $I[i]$ using the BAN function.
        12. **BAU(i, L, r, K, M', S', C, A, I_pre[i]):** Update the pre-rendered state $I_{pre}[i]$ using the BAU function.
13. **Return:** The rendered image $I$.

**Pseudocode:**
```python
def SparseOITRasterize(w, h, M, S, C, A, V):
    # 1. Cull Gaussians
    # Implementation detail: Filter Gaussians outside view frustum
    valid_indices = CullGaussian(M, V)
    M_culled = M[valid_indices]
    S_culled = S[valid_indices]
    C_culled = C[valid_indices]
    A_culled = A[valid_indices]

    # 2. Project to Screen Space
    M_prime, S_prime = ScreenspaceGaussians(M_culled, S_culled, V)

    # 3. Create Tiles
    T = CreateTiles(w, h)

    # 4. Duplicate with Keys
    # Assign each Gaussian to a tile based on its screen position
    L = []
    K = []
    for idx in range(len(M_prime)):
        tile_id = GetTileId(M_prime[idx], T)
        L.append({
            'idx': idx,
            'M_prime': M_prime[idx],
            'S_prime': S_prime[idx],
            'C': C_culled[idx],
            'A': A_culled[idx]
        })
        K.append(tile_id)

    # 5. Sort by Tile ID only
    # Stable sort or partition to group by tile
    combined = list(zip(K, L))
    combined.sort(key=lambda x: x[0])
    K_sorted, L_sorted = zip(*combined) if combined else ([], [])
    K_sorted = list(K_sorted)
    L_sorted = list(L_sorted)

    # 6. Identify Tile Ranges
    R = IdentifyTileRanges(T, K_sorted)

    # 7. Initialize Images
    I = zeros((h, w, 3))
    I_pre = zeros((h, w, 3)) # Or appropriate state structure for BAU

    # 8-12. Process Tiles and Pixels
    for t in T:
        r = R[t] # Range indices in L_sorted
        for y in range(t.y_start, t.y_end):
            for x in range(t.x_start, t.x_end):
                pixel_idx = (y, x)
                
                # 11. BAN: Compute final color
                I[y, x] = BAN(pixel_idx, L_sorted, r, K_sorted, M_prime, S_prime, C_culled, A_culled, I_pre[pixel_idx])
                
                # 12. BAU: Update pre-rendered state
                I_pre[pixel_idx] = BAU(pixel_idx, L_sorted, r, K_sorted, M_prime, S_prime, C_culled, A_culled, I_pre[pixel_idx])

    return I
```

**Edge Cases and Pitfalls:**
*   **Depth Independence:** The blending process is independent of the depth order of the Gaussians. This is a key distinction from standard OIT but requires careful handling of the BAU function to ensure correct accumulation [S1, unofficial].
*   **Parallel Backward Propagation:** The mutual independence of Gaussian variables in the backward propagation equations allows for efficient parallel computation, but implementations must ensure no race conditions occur if shared state is used in BAN/BAU [S1, unofficial].
*   **Update Interval:** For specific scenes (*train*, *room*, *bonsai*), the update interval must be set to 600 to ensure correct algorithm execution, exceeding twice the number of training views [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Dominated by the sorting step, which is $O(N \log N)$ or $O(N)$ depending on the sorting algorithm used for tile IDs, where $N$ is the number of Gaussians. The blending step is linear with respect to the number of Gaussians per pixel.
*   **Memory Complexity:** Requires storage for duplicated Gaussian data $L$ and keys $K$, proportional to $N$. Tile ranges $R$ require $O(\text{num\_tiles})$ space.
*   **Strengths:** Order-independent transparency without complex depth sorting per pixel; parallelizable backward pass; suitable for GPU software rasterization.
*   **Limitations:** Requires careful implementation of BAN and BAU functions to maintain correctness without depth sorting; potentially higher memory usage due to data duplication and key assignment.
*   **When to use:** When order-independent transparency is required for 3D Gaussian Splatting and depth sorting is a bottleneck or undesirable.
*   **When not to use:** When strict depth ordering is physically required and cannot be approximated by the OIT method, or when memory bandwidth is severely constrained.

## Background
The SparseOIT Rasterizer was introduced in the paper "SparseOIT: Improving Order-Independent Transparency 3DGS via Active Set Method" [S1, unofficial]. It builds upon the 3D Gaussian Splatting framework and aims to improve rendering quality by addressing transparency artifacts through an active set method and pre-rendering techniques. The method is part of the broader effort to optimize and enhance the rendering pipeline of 3D Gaussian Splatting.
