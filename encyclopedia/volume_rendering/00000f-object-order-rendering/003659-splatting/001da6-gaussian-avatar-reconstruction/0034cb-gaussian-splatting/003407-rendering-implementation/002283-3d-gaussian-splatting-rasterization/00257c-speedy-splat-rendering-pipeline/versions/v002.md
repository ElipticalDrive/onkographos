# Speedy-Splat Rendering Pipeline

Also called: Speedy-Splat

## Overview
The Speedy-Splat Rendering Pipeline is a GPU-accelerated rasterization method for 3D Gaussian Splatting that replaces coarse bounding-box tile intersection tests with precise Gaussian-tile intersection checks and sorting-based depth ordering [S1]. It addresses the inefficiency of standard 3D-GS rasterization, which overestimates Gaussian extents and processes non-intersecting pixels, by generating a sparse set of Gaussian-tile pairs and sorting them for efficient pixel-wise compositing [S1].

## How it works
**Inputs:**
*   List of 3D Gaussians $G_i$ with opacity $\sigma_i$, color $c_i$, projected 2D mean $\mu_{i_{2D}}$, and inverse 2D covariance $\Sigma_{i_{2D}}^{-1}$ [S1].
*   Camera parameters and image resolution are standard prerequisites for projection [G].

**Outputs:**
*   Final image color buffer $C(p)$ for each pixel $p$ [S1].

**Data Structures:**
*   **Key Array:** Stores pairs of `(tile_index, gaussian_depth)` for each intersecting Gaussian-tile pair [S1].
*   **Value Array:** Stores the Gaussian index $i$ corresponding to each key [S1].

**Steps:**
1.  **InclusiveSum:** A CUDA primitive computes the prefix sum over all Gaussian-tile counts to allocate the key and value arrays for the Gaussian-to-tile mapping [S1].
2.  **DuplicateWithKeys:** A Gaussian-parallel kernel recomputes Gaussian-tile intersections to generate a key for each intersecting tile, consisting of the tile index and Gaussian depth [S1].
3.  **RadixSort:** A CUDA primitive sorts the key array, ordering Gaussian indices by tile and then depth [S1].
4.  **IdentifyTileRanges:** A kernel parallelized across the key array post-processes keys before pixel rendering [S1].
5.  **Render Kernel:** The render kernel is parallelized across pixels [S1]. For each pixel $p$, all Gaussians within its corresponding tile are loaded and processed in depth order as determined by RadixSort [S1].

**Formulas:**
The alpha value for Gaussian $G_i$ at pixel $p$ is:
$$ \alpha_i(p) = \sigma_i g_i(p) \quad (5) $$
where $\sigma_i$ is the opacity of $G_i$ and $g_i(p)$ is the value of the projected 2D Gaussian at pixel $p$ [S1].

The projected 2D Gaussian value is:
$$ g_i = e^q, \quad q = -\frac{1}{2}(p - \mu_{i_{2D}})\Sigma_{i_{2D}}^{-1}(p - \mu_{i_{2D}})^T \quad (6) $$
where $p$ is the pixel coordinate, $\mu_{i_{2D}}$ is the 2D mean of the projected Gaussian, and $\Sigma_{i_{2D}}^{-1}$ is the inverse of the projected 2D covariance matrix [S1].

The pixel color is computed via front-to-back alpha compositing:
$$ C(p) = \sum_{i \in \mathcal{N}} c_i \alpha_i(p) \prod_{j=1}^{i-1} (1 - \alpha_j(p)) \quad (7) $$
where $c_i$ is the color of Gaussian $i$, $\mathcal{N}$ is the set of Gaussians in the tile, and Gaussians are processed in depth order [S1].

**Edge Cases and Pitfalls:**
*   **Alpha Threshold:** The source specifies a condition $\alpha_i > 255$ for inclusion in compositing, while the formula defines $\alpha_i \in [0,1]$ [S1]. This implies a fixed-point or scaled integer representation in the source implementation [S1]. Implementers should verify the alpha scaling convention or treat the threshold as a source-specific artifact [G].
*   **Precision:** The computation of $q$ involves matrix inversion and dot products, which may suffer from precision loss for highly anisotropic or degenerate Gaussians [G].
*   **Degenerate Input:** If a Gaussian has a singular covariance matrix, the inverse $\Sigma_{i_{2D}}^{-1}$ is undefined [G]. A small regularization term should be added to the diagonal of the covariance matrix before inversion [G].

## Operating characteristics
*   **Time Complexity:** The dominant operations are the tile intersection computation, the radix sort, and the pixel-wise rendering [S1]. The radix sort requires $O(N \log N)$ time where $N$ is the number of Gaussian-tile pairs [S1]. The rendering step requires $O(P \cdot K)$ time where $P$ is the number of pixels and $K$ is the average number of Gaussians per tile [S1].
*   **Memory Complexity:** The Key and Value arrays require $O(N)$ memory [S1].
*   **Performance:** Speedy-Splat is designed to be faster than standard 3D-GS rasterization by reducing the number of Gaussians processed per pixel through precise intersection testing and efficient sorting [S1].
*   **Strengths:** Reduces overestimation of Gaussian extents, leading to fewer unnecessary computations [S1]. Efficient sorting allows for fast depth-ordered compositing [S1].
*   **Limitations:** The precise tile intersection computation may be more expensive per Gaussian than the coarse bounding box test [S1]. The alpha threshold condition requires careful handling of fixed-point representations [S1].

## Background
Speedy-Splat was introduced in the paper "Speedy-Splat: Fast 3D Gaussian Splatting with Sparse Pixels and Sparse Primitives" [S1]. The method is motivated by the observation that standard 3D-GS rasterization overestimates Gaussian extents and that 3D-GS models are heavily overparameterized [S1]. The method aims to address these inefficiencies by using precise tile intersections and sparse processing [S1].
