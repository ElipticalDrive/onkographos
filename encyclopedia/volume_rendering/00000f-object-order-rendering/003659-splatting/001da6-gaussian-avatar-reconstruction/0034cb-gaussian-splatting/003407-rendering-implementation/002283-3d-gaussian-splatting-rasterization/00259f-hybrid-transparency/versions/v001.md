# Hybrid Transparency

Also called: Core-Tail Blending, Hybrid Transparency Blending, Hybrid Transparency-based blending, Hybrid transparency for 3DGS, Partial depth-ordering blending

## Overview
Hybrid Transparency is a blending formulation that combines depth-ordered alpha blending for the first $K$ fragments (the 'core') with order-independent accumulation for the remaining fragments (the 'tail') to mitigate popping artifacts while maintaining real-time performance [S1, S2]. It solves the inconsistency of splat shapes and popping artifacts across viewpoints in VR and motion by avoiding the performance cost of hierarchical sorting or ray tracing [S2]. Unlike standard 3D Gaussian Splatting which uses approximate per-primitive sorting, Hybrid Transparency guarantees correct depth ordering for the front-most contributions and uses fast, unsorted blending for the rest [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of 3D Gaussians defined by mean $\mu$, opacity $o$, orientation vectors $t_u, t_v, t_w$, and scales $s_u, s_v, s_w$ [S1].
*   **Output:** A final pixel color $C_{final}$ and alpha $\alpha_{final}$.

**Data Structures:**
*   **Core Fragments:** Each thread uses a compact 64-bit data structure to store core fragments during blending. This structure is optimized to reduce register usage and swaps during insertion sort [S2].
*   **Tail Accumulators:** Per-pixel accumulators for RGB color and alpha for the tail contributions [S1].

**Parameters:**
*   $K$: The number of fragments to include in the depth-ordered core. The default and optimal value is 16 [S1, S2].
*   $\tau_K$: Minimum alpha of a fragment to be considered for the core. Default value is 0.05 [S1].

**Steps:**

1.  **Splat Staging and Tiling:**
    *   Compute exact bounding boxes of each 3D Gaussian in screen space using plane-fitting [S2].
    *   Create unordered per-tile fragment lists. Depth ordering is omitted at this stage as it is resolved during blending [S2].
    *   Apply load balancing during tile fragment creation to handle imbalanced workloads [S2].

2.  **Per-Pixel Depth Evaluation:**
    *   For each splat contributing to a pixel, compute the pixel-specific depth value $x_{view}$ (the z-value in view space) at the point of maximum contribution along the pixel ray [S1].
    *   $x_{view}$ is computed efficiently using intermediate values from the splat evaluation [S1]. This ensures perspective-accurate depth ordering, avoiding the popping artifacts caused by using only the view-space depth of the mean [S1].

3.  **Core Identification and Sorting:**
    *   Identify the initial $K$ splats contributing to each pixel color based on $x_{view}$ [S1].
    *   Only splats with alpha $\alpha \ge \tau_K$ are considered for the core [S1].
    *   Sort these core fragments correctly by depth per pixel [S1].
    *   *Pitfall:* Insertion sort for per-pixel core causes significant divergence. Mitigated by reducing tile size to $8 \times 8$ [S1].

4.  **Core Blending:**
    *   Alpha-blend the first $K$ fragments (the core) in their correct depth order per pixel using standard $\alpha$-blending [S1].
    *   Let $C_{core}$ and $\alpha_{core}$ be the resulting color and alpha from this step [S1].

5.  **Tail Accumulation:**
    *   Accumulate the contributions of all remaining fragments (the tail, $N-K$ splats) using an order-independent residual [S1].
    *   Compute the tail transmittance $T_{tail}$ and tail color $C_{tail}$ [S1].
    *   The computation of $T_{tail}$ is more accurate than the average-based formulation of Maule et al. [MCTB13] [S1].
    *   *Optimization:* As the partial derivative of the blending function is the same for all splats in the tail, partial derivatives can be pre-computed during the forward pass for efficient backward pass [S1].

6.  **Final Composition:**
    *   Compute the final color using the core blend and tail accumulation [S1]:
        $$ C_{final} = C_{core} + C_{tail} \cdot (1 - \alpha_{core}) $$
        $$ \alpha_{final} = \alpha_{core} + \alpha_{tail} \cdot (1 - \alpha_{core}) $$
    *   Where $C_{tail}$ and $\alpha_{tail}$ are derived from the accumulated tail contributions [S1].

**Pseudocode:**

```python
# Constants
K = 16
TAU_K = 0.05
TILE_SIZE = 8

# Data structures
# CoreBuffer: 64-bit structure storing up to K fragments per pixel
# TailAccum: Per-pixel accumulators for color and alpha

def hybrid_transparency_rasterize(gaussians, camera):
    # 1. Splat Staging
    # Compute screen-space bounding boxes using plane-fitting
    splats = []
    for g in gaussians:
        bbox = compute_exact_screen_bbox(g, camera)
        splats.append({'g': g, 'bbox': bbox})
    
    # 2. Tiling
    # Create unordered per-tile fragment lists
    tiles = create_tiles(splats, TILE_SIZE)
    
    # 3. Blending Kernel (executed per tile)
    for tile in tiles:
        # Initialize tail accumulators for this tile's pixels
        tail_color = zeros(tile.width, tile.height, 3)
        tail_alpha = zeros(tile.width, tile.height)
        
        # Process each fragment in the tile
        for frag in tile.fragments:
            g = frag.g
            # Compute pixel-specific depth at point of max contribution
            x_view = compute_x_view(g, camera)
            
            # Determine which pixels this splat covers
            covered_pixels = get_covered_pixels(g, camera)
            
            for p in covered_pixels:
                # Compute alpha at pixel p
                alpha_p = compute_alpha_at_pixel(g, p, camera)
                
                # Check if eligible for core
                if alpha_p >= TAU_K:
                    # Add to core buffer for pixel p
                    add_to_core_buffer(p, x_view, alpha_p, g.color)
                else:
                    # Accumulate to tail
                    tail_color[p] += g.color * alpha_p * (1 - get_current_transmittance(p))
                    tail_alpha[p] += alpha_p * (1 - get_current_transmittance(p))
        
        # 4. Finalize Core and Composite
        for p in tile.pixels:
            core_buffer = get_core_buffer(p)
            
            # Sort core fragments by x_view
            sort(core_buffer, key=lambda f: f.x_view)
            
            # Blend core
            c_core = 0
            a_core = 0
            for i, frag in enumerate(core_buffer):
                if i >= K:
                    break
                # Standard alpha blending
                c_core = c_core * (1 - frag.alpha) + frag.color * frag.alpha
                a_core = a_core * (1 - frag.alpha) + frag.alpha
                if a_core >= 1.0:
                    break
            
            # Composite with tail
            transmittance_core = 1.0 - a_core
            c_final = c_core + tail_color[p] * transmittance_core
            a_final = a_core + tail_alpha[p] * transmittance_core
            
            set_pixel_color(p, c_final)
            set_pixel_alpha(p, a_final)
```

**Edge Cases and Pitfalls:**
*   **Incorrect Depth Ordering:** Using only the view-space depth of the mean causes popping artifacts. Must use correct per-pixel depth ordering ($x_{view}$) for the core [S1].
*   **Blending without Sorting:** $K=0$ is invalid as it causes foreground transparency issues [S1].
*   **Training Failure:** Omitting tail computation during training causes catastrophic failure, though it causes only a small drop in image quality during inference [S1].
*   **Divergence:** Insertion sort for per-pixel core causes significant divergence. Mitigated by reducing tile size to $8 \times 8$ [S1].

## Operating characteristics
*   **Time Complexity:** Rendering time is reduced because it avoids global depth-sorting overhead for the tail [S1]. It is significantly faster than StopThePop [RSP*24] which uses hierarchical sorting for all splats [S1].
*   **Memory Complexity:** Uses a compact 64-bit data structure for core fragments to reduce register usage [S2].
*   **Measured Performance:** On Mip-NeRF360 datasets, achieves a training speedup of 2.1× and renders 1.6× faster on average compared to 3DGS [S1]. For example, on the "Bicycle" scene, total time is 3.317s vs 8.015s for 3DGS [S1].
*   **Strengths:** Eliminates popping artifacts, provides temporally stable rendering, improves viewing experience in VR, and maintains high performance by skipping global presorting [S1, S2].
*   **Limitations:** Cannot use early stopping based on transmittance threshold by default. Achieves slightly lower PSNR than 3DGS, possibly due to the absence of a screen-space aliasing filter [S1]. Performance may degrade in scenes with very large depth complexity without additional optimizations like depth prepass [S1].
*   **When to use:** VR/AR applications, fast-paced games, or any scenario requiring high frame rates and temporal stability where popping artifacts are noticeable [S1, S2].
*   **When not to use:** Scenes requiring maximum possible PSNR where slight quality loss is unacceptable, or scenes with extreme depth complexity where unsorted tail accumulation becomes a bottleneck [S1].

## Background
Hybrid Transparency was originally proposed by Wymberley et al. [Wym16] and later extended by Maule et al. [MCTB13] for gradient descent-based optimization [S1]. It was integrated into the 3D Gaussian Splatting framework by Hahlbohm et al. [HFW*25] to solve popping artifacts caused by approximate sorting in 3DGS [S1, S2]. This approach avoids the need for sophisticated sorting implementations like those in StopThePop [RSP*24], improving performance while maintaining correct depth ordering for the core fragments [S1].
