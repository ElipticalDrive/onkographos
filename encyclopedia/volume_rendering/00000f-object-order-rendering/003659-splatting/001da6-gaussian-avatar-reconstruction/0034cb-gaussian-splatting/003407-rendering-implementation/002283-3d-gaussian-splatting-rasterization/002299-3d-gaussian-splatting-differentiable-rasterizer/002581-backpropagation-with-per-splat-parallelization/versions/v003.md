# Backpropagation with Per-Splat Parallelization

Also called: Per-splat backward, Splat-parallel backprop

## Overview
This method is a parallelization scheme for the 3D Gaussian Splatting backward pass that maps GPU threads to 2D splats instead of pixels to avoid atomic contention on gradient accumulation [S1]. It differs from its parent, the [3D Gaussian Splatting Differentiable Rasterizer](2813-3d-gaussian-splatting-differentiable-rasterizer.md), by changing the thread-to-workload mapping from pixel-centric (which causes serialized atomic updates) to splat-centric (which enables collaborative state exchange) [S1]. It is distinct from [Analytic-Splatting](3025-analytic-splatting.md) by retaining the standard alpha compositing gradient logic but optimizing its execution parallelism, and from [LinPrim Gradient Computation](3038-linprim-gradient-computation.md) by operating on the full Gaussian primitives rather than linearized primitives [S1].

## How it works
**Inputs:**
- Forward pass output: Depth-sorted list of splats per tile, and a stored autodiff context containing per-pixel states sampled every $N$ splats [S1].
- Gradients of the loss with respect to the final pixel colors ($\frac{\partial L}{\partial C_{pixel}}$) [S1].

**Outputs:**
- Gradients with respect to Gaussian parameters (position, scale, rotation, opacity, spherical harmonics coefficients) for all splats [S1].

**Data Structures:**
- **Autodiff Context:** Stores per-pixel state $(T_j, C_j)$ for every pixel $j$ in the tile at specific splat indices $k \in \{0, N, 2N, \dots\}$ [S1].
- **Per-Splat State:** Each thread maintains the current transmittance $T$ and accumulated color $C$ for all pixels $j$ in the tile [S1].
- **Bucket Size:** Splats are divided into buckets of size $B=32$, each scheduled to a CUDA warp [S1].

**Parameters:**
- $N$: Sampling interval for storing states in the forward pass. The source uses a bucket size of 32, implying $N=32$ [S1].
- $W$: Warp size (typically 32 for CUDA) [S1].

**Algorithm:**

1. **Forward Pass (Preparation):**
   - For each tile, iterate through depth-sorted splats.
   - Compute per-pixel transmittance $T_j$ and accumulated color $C_j$ using alpha compositing.
   - Store the state $(T_j, C_j)$ for every pixel $j$ in the tile at splat indices $k = 0, N, 2N, \dots$ into the autodiff context [S1].
   - Track the last contributing splat index for each tile to enable skipping in the backward pass [S1].

2. **Backward Pass Initialization:**
   - Divide the depth-sorted splats in the tile into buckets of size $B=32$ [S1].
   - Assign each bucket to a CUDA warp. Within a warp, each thread $i$ (where $0 \le i < B$) is responsible for splat $s_i$ [S1].
   - Each thread retrieves the stored starting states $(T_j^{(0)}, C_j^{(0)})$ for all pixels $j$ from the autodiff context [S1].

3. **State Reconstruction (Inter-Bucket):**
   - For each bucket $b$ (representing splats $s_{b \cdot B}$ to $s_{(b+1) \cdot B - 1}$):
     - If $b > 0$, threads must reconstruct the pixel states at the start of this bucket from the end of the previous bucket.
     - Thread $i$ holds the state after processing splat $s_{(b-1) \cdot B + i - 1}$ (or the stored state if $i=0$).
     - Threads use intra-warp shuffling to exchange pixel states $(T_j, C_j)$ so that all threads in the warp have the correct starting state for the current bucket [S1].

4. **Gradient Computation (Intra-Bucket):**
   - For each splat $s$ in the current bucket, processed by thread $i$:
     - Let $(T_j^{in}, C_j^{in})$ be the pixel state received from the previous splat (or the stored state for the first splat in the bucket).
     - Compute the contribution of splat $s$ to pixel $j$:
       $$ \alpha_s = \text{opacity}_s \cdot \exp\left(-\frac{1}{2} \mathbf{d}_j^T \mathbf{\Sigma}_s^{-1} \mathbf{d}_j\right) $$
       $$ T_j^{out} = T_j^{in} \cdot (1 - \alpha_s) $$
       $$ C_j^{out} = C_j^{in} + \alpha_s \cdot \text{color}_s \cdot T_j^{in} $$
     - Compute the gradient for splat $s$ with respect to the loss $L$. The gradient flows from $\frac{\partial L}{\partial C_j}$ through $C_j^{out}$ and $T_j^{out}$ [S1].
     - Specifically, the gradient with respect to the splat's color and opacity is derived from the chain rule applied to the compositing equations [S1].
     - Accumulate these gradients into the splat's parameter gradients. Since each thread handles a unique splat, no atomic operations are needed for gradient accumulation [S1].

5. **State Exchange (Intra-Warp):**
   - After processing splat $s_i$, thread $i$ updates its local pixel states $(T_j, C_j)$ to $(T_j^{out}, C_j^{out})$ [S1].
   - Thread $i+1$ (in the same warp) receives the updated states from thread $i$ via intra-warp shuffling to use as input for its splat $s_{i+1}$ [S1].
   - This continues for all splats in the bucket [S1].

6. **Optimization: Skip Redundant Splats:**
   - Use the "last contributor" index tracked in the forward pass.
   - If the current splat index exceeds the last contributing splat for any pixel in the tile, skip gradient computation for that pixel (transmittance is effectively 0) [S1].

7. **Optimization: Tighter Culling:**
   - Apply tighter culling as proposed by Radl et al. [2024] to minimize redundant splats in both forward and backward passes [S1].

## Subtopics

### [CUDA Backward Pass Optimization](5429-cuda-backward-pass-optimization.md)
Applies low-level GPU kernel optimizations to reduce memory access overhead and improve cache utilization. It differs by focusing on hardware-level efficiency rather than algorithmic parallelization structure, providing consistent speedups without altering rendering results.

## Operating characteristics
- **Time Complexity:** The method reduces the time complexity of gradient accumulation from $O(S \cdot P \cdot A)$ (where $S$ is splats, $P$ is pixels, $A$ is atomic contention) to $O(S \cdot P)$ with lower constant factors due to collaborative sharing [S1].
- **Memory Complexity:** Requires storing per-pixel states every $N$ splats in the autodiff context, increasing memory usage by $O(P \cdot S/N)$ compared to storing only final states [S1].
- **Measured Performance:** The method significantly reduces backward pass duration compared to the original 3DGS and DISTWAR [S1].
- **Strengths:** Eliminates atomic contention, enabling full parallelism across splats [S1].
- **Limitations:** Requires careful state management and intra-warp communication [S1].

## Background
The original 3DGS backward pass maps threads to pixels, causing serialized atomic operations when multiple threads contend for the same Gaussian's gradient [S1]. This method was proposed to address this bottleneck by parallelizing over splats instead [S1]. It builds on the standard alpha compositing gradient logic but changes the execution model [S1].
