# 3D Gaussian Splatting Rasterization

Also called: 3DGS Rasterization, Differentiable Gaussian Rasterization, TrimGS, gsplat.rasterization

## Overview
3D Gaussian Splatting Rasterization is a differentiable rendering technique that represents a scene as a set of 3D Gaussians and rasterizes them to 2D images by projecting 3D covariances to 2D screen covariances, sorting by depth, and compositing colors based on alpha and transmittance [S2, unofficial]. It is analogous to triangle rasterization but uses Gaussians instead of triangles, enabling real-time rendering of photorealistic scenes learned from small samples of images [S3, unofficial]. It differs from its siblings by providing the core differentiable kernel that bridges the 3D scene representation and the 2D image plane, whereas methods like [Optimal Gaussian Splatting](3293-optimal-gaussian-splatting.md) focus on training efficiency and [Hybrid Transparency](3294-hybrid-transparency.md) on specific blending artifacts [S2, unofficial].

## How it works
**Inputs:**
*   `means_3D`: $[N, 3]$ tensor of 3D Gaussian means (positions).
*   `quats`: $[N, 4]$ tensor of quaternions (rotation, normalized).
*   `scales`: $[N, 3]$ tensor of scales (log-space or linear, depending on implementation; typically log-space in training [S2, unofficial]).
*   `opacities`: $[N]$ tensor of scalar opacities.
*   `colors`: $[N, D]$ tensor of colors (RGB or SH coefficients).
*   `viewmats`: $[C, 4, 4]$ camera-to-world matrices for $C$ cameras.
*   `Ks`: $[C, 3, 3]$ camera intrinsic matrices.
*   `width`, `height`: Image dimensions.
*   `tile_size`: Integer, default 16 [S1, unofficial].
*   `near_plane`, `far_plane`: Floats, default 0.01, 1e10 [S1, unofficial].
*   `render_mode`: String, e.g., "RGB", "D", "ED", "RGB+D", "RGB+ED", "d", "Ed", "RGB+d", "RGB+Ed" [S1, unofficial].
*   `rasterize_mode`: String, "classic" or "antialiased" [S1, unofficial].
*   `camera_model`: String, "pinhole", "ortho", or "fisheye" [S1, unofficial].
*   `sh_degree`: Integer or None. If not None, enables spherical harmonics color computation [S1, unofficial].

**Outputs:**
*   `render_colors`: $[C, H, W, D]$ tensor of rendered colors.
*   `render_alphas`: $[C, H, W, 1]$ tensor of accumulated alpha.
*   `info`: Optional metadata (radii, depths, etc.).

**Data Structures:**
*   **Conic**: Precomputed inverse 2D covariance stored as a vector of 3 floats: $[\Sigma_{2D}^{-1}[0,0], \Sigma_{2D}^{-1}[0,1], \Sigma_{2D}^{-1}[1,1]]$ [S1, unofficial].
*   **Tile Intersection**: `isect_offsets` $[C, tile\_height, tile\_width]$ encoding which Gaussians intersect which tiles, and `flatten_ids` mapping tile-local indices to global Gaussian indices [S1, unofficial].

**Steps:**

1.  **Input Validation**: Check `render_mode`, `rasterize_mode`, and `camera_model` against valid sets [S1, unofficial].
2.  **3D Covariance Computation**: Compute the 3D covariance matrix $\Sigma_{3D}$ from `quats` and `scales`. This is typically done via `quat_scale_to_covar_preci` with `compute_covar=True`, `compute_preci=False`, `triu=False`, resulting in shape $[N, 3, 3]$ [S1, unofficial].
3.  **Projection to 2D**:
    *   Transform 3D means to camera space: $\mu' = R \mu + t$ [S1, unofficial].
    *   Transform 3D covariance to camera space: $\Sigma' = R \Sigma_{3D} R^T$ [S2, unofficial].
    *   Project to 2D screen space using the Jacobian $J$ of the projective transformation $\phi(\mathbf{x}') = \mathbf{x}' (\mathbf{x}_0^\top \mathbf{x}')^{-1}$ evaluated at $\mu'$: $\Sigma_{2D} = J \Sigma' J^T$ [S2, unofficial].
    *   Compute 2D means `means_2D` and `radii` (bounding box size) using the 3-sigma rule: $\text{bboxsize\_cam} = [3.0 \sqrt{\Sigma_{2D}[0,0]}, 3.0 \sqrt{\Sigma_{2D}[1,1]}]$ [S1, unofficial].
    *   Compute the **Conic** representation: $\Sigma_{2D}^{-1}$ upper triangle [S1, unofficial].
    *   If `rasterize_mode` is "antialiased", compute compensation factors [S1, unofficial].
    *   Output: `radii` $[C, N, 2]$, `means_2D` $[C, N, 2]$, `depths` $[C, N]$, `conics` $[C, N, 3]$, `compensations` $[C, N]$ [S1, unofficial].
4.  **Tile Intersection**:
    *   Compute tile dimensions: $tile\_width = \lceil width / tile\_size \rceil$, $tile\_height = \lceil height / tile\_size \rceil$ [S1, unofficial].
    *   Call `isect_tiles(means_2D, radii, depths, tile_size, tile_width, tile_height, sort=True)` to get `tiles_per_gauss`, `isect_ids`, `flatten_ids` [S1, unofficial].
    *   Encode intersection offsets: `isect_offsets` $[C, tile\_height, tile\_width]$ using `isect_offset_encode` [S1, unofficial].
5.  **Color Computation (Spherical Harmonics)**:
    *   If `sh_degree` is not None:
        *   Compute view directions: $\text{dirs} = \mu - \text{campos}$, normalized [S1, unofficial].
        *   Broadcast color coefficients to $[C, N, K, 3]$ where $K$ is SH basis count [S1, unofficial].
        *   Evaluate SH: $\text{rgb} = \text{spherical\_harmonics}(sh\_degree, \text{dirs}, \text{coeffs})$ [S1, unofficial].
        *   Clamp: $\text{rgb} = \max(\text{rgb} + 0.5, 0.0)$ [S1, unofficial].
    *   If `sh_degree` is None, use direct colors [S1, unofficial].
6.  **Depth/Hit Distance (Optional)**:
    *   If hit distance is needed, compute camera-space means and $d = \|\mu'\|$ [S1, unofficial].
7.  **Alpha and Transmittance Preparation**:
    *   Broadcast opacities from $[N]$ to $[C, N]$ [S1, unofficial].
    *   If `compensations` are not None, multiply opacities by them [S1, unofficial].
    *   Filter Gaussians behind the camera ($z < 0$) and sort remaining by depth [S2, unofficial].
    *   Handle memory constraints by splitting Gaussians into mini-batches if `per_splat > 0` [S2, unofficial].
8.  **Rasterization to Pixels**:
    *   For each tile, iterate over intersecting Gaussians.
    *   For each pixel in the tile, for each Gaussian in front-to-back order:
        *   Evaluate 2D Gaussian value $G_{2D}$ at pixel center using `means_2D` and `conics` [S2, unofficial].
        *   Compute alpha: $\alpha_i = \text{opacity}_i \times G_{2D}$ [S2, unofficial].
        *   Compute transmittance: $T_i = \prod_{j=1}^{i-1} (1 - \alpha_j)$ [S2, unofficial].
        *   Compute weight: $w_i = \alpha_i T_i$ [S2, unofficial].
        *   Accumulate color: $\text{color} += w_i \times \text{color}_i$ [S2, unofficial].
        *   Accumulate alpha: $\text{alpha} += w_i$ [S2, unofficial].
    *   Composite background: $\text{image} = \text{mask} \times \text{image} + (1.0 - \text{mask}) \times \text{bg\_colour}$ [S2, unofficial].
9.  **Post-Processing**:
    *   If expected depth is required, normalize accumulated depth by alpha: $\text{depth\_channel} = \text{depth\_channel} / \max(\text{render\_alphas}, 1e-10)$ [S1, unofficial].
    *   Concatenate/replace channels based on `render_mode` [S1, unofficial].

```python
def rasterize_gaussians(
    means_3d: mx.array,       # [N, 3]
    quats: mx.array,          # [N, 4]
    scales: mx.array,         # [N, 3]
    opacities: mx.array,      # [N]
    colors: mx.array,         # [N, D] or [N, K, 3] if SH
    viewmats: mx.array,       # [C, 4, 4]
    Ks: mx.array,             # [C, 3, 3]
    width: int,
    height: int,
    tile_size: int = 16,
    sh_degree: int = None,
    backgrounds: mx.array = None,
    render_mode: str = "RGB"
) -> tuple:
    """
    Rasterize 3D Gaussians to 2D images.
    Returns (render_colors, render_alphas, info)
    """
    C = viewmats.shape[0]
    N = means_3d.shape[0]
    
    # 1. Compute 3D Covariance
    # cov_3d shape: [N, 3, 3]
    cov_3d = compute_cov_3d(quats, scales) 
    
    # 2. Project to 2D
    # means_2d: [C, N, 2], cov_2d: [C, N, 2, 2], depths: [C, N]
    # conics: [C, N, 3] (upper triangle of inv(cov_2d))
    # radii: [C, N, 2] (bounding box)
    means_2d, cov_2d, depths, conics, radii = linearized_project(
        means_3d, cov_3d, viewmats, Ks, width, height
    )
    
    # 3. Tile Intersection
    tile_width = (width + tile_size - 1) // tile_size
    tile_height = (height + tile_size - 1) // tile_size
    
    # isect_ids: [C, N], flatten_ids: [C, N]
    isect_ids, flatten_ids = isect_tiles(
        means_2d, radii, depths, tile_size, tile_width, tile_height
    )
    
    # Encode offsets for efficient lookup
    isect_offsets = isect_offset_encode(isect_ids, C, tile_width, tile_height)
    
    # 4. Color Computation
    if sh_degree is not None:
        # Compute view directions
        campos = viewmats[:, :3, 3] # [C, 3]
        dirs = means_3d[None, :, :] - campos[:, None, :] # [C, N, 3]
        dirs_norm = mx.maximum(mx.linalg.norm(dirs, axis=-1, keepdims=True), 1e-8)
        dirs = dirs / dirs_norm
        # Evaluate SH

        colors = mx.maximum(colors + 0.5, 0.0)

    # 5. Opacity and Alpha

    opacities_cn = mx.broadcast_to(mx.expand_dims(opacities, axis=0), (C, N))

def compute_cov_3d(quats: mx.array, scales: mx.array) -> mx.array:
    """Compute 3D covariance from quaternion and scale."""
    # R is rotation matrix from quaternion
    R = quat_to_rot_matrix(quats) # [N, 3, 3]
    S = mx.diag_embed(scales)     # [N, 3, 3]
    # Sigma = R S S^T R^T
    return R @ (S @ S.T) @ R.T

def linearized_project(means_3d, cov_3d, viewmats, Ks, width, height):
    """Project 3D Gaussians to 2D screen space."""
    # Transform to camera space
    R_cam = viewmats[:, :3, :3] # [C, 3, 3]
    t_cam = viewmats[:, :3, 3]  # [C, 3]
    
    means_cam = (R_cam @ means_3d[None, :, :].transpose(0, 2, 1)).transpose(0, 2, 1) + t_cam[:, None, :] # [C, N, 3]
    cov_cam = R_cam[:, None, :, :] @ cov_3d[None, :, :, :] @ R_cam[:, None, :, :].transpose(0, 1, 3, 2) # [C, N, 3, 3]
    
    # Project to 2D
    # Jacobian J of projection
    # x_proj = x / z, y_proj = y / z
    # J = [[1/z, 0, -x/z^2], [0, 1/z, -y/z^2]]
    z = means_cam[:, :, 2:3] # [C, N, 1]
    x = means_cam[:, :, 0:1]
    y = means_cam[:, :, 1:2]
    
    J = mx.zeros((means_cam.shape[0], means_cam.shape[1], 2, 3))
    J[:, :, 0, 0] = 1.0 / z
    J[:, :, 0, 2] = -x / (z * z)
    J[:, :, 1, 1] = 1.0 / z
    J[:, :, 1, 2] = -y / (z * z)
    
    # Sigma_2D = J Sigma_cam J^T
    cov_2d_full = J @ cov_cam @ J.transpose(0, 1, 3, 2) # [C, N, 2, 2]
    
    # Extract upper triangle for conic
    conic = mx.stack([
        cov_2d_full[:, :, 0, 0],
        cov_2d_full[:, :, 0, 1],
        cov_2d_full[:, :, 1, 1]
    ], axis=-1) # [C, N, 3]
    
    # Inverse conic (actually we store the inverse covariance elements directly in some implementations, 
    # but the note says conic contains upper triangle of inverse. 
    # Standard 3DGS stores the inverse of the 2x2 covariance. 
    # Let's assume conic is the inverse covariance upper triangle as per note [S1, unofficial])
    # Note: The note says "conic vector containing the upper triangle elements: [inv[0,0], inv[0,1], inv[1,1]]"
    # So we need to invert the 2x2 matrix.
    inv_cov_2d = invert_2x2(cov_2d_full) # [C, N, 2, 2]
    conic = mx.stack([
        inv_cov_2d[:, :, 0, 0],
        inv_cov_2d[:, :, 0, 1],
        inv_cov_2d[:, :, 1, 1]
    ], axis=-1)
    
    # Means 2D
    means_2d = (Ks[:, None, :, :] @ means_cam[:, :, :, None]).squeeze(-1) # [C, N, 3]
    means_2d = means_2d[:, :, :2] / means_2d[:, :, 2:3] # [C, N, 2]
    
    # Radii (3-sigma)
    radii = 3.0 * mx.sqrt(mx.diag(cov_2d_full)) # Approximation, need proper sqrt of diagonal
    # Correct radii calculation from cov_2d_full diagonal
    radii = 3.0 * mx.sqrt(cov_2d_full[:, :, 0, 0:1]) # [C, N, 1]
    radii_y = 3.0 * mx.sqrt(cov_2d_full[:, :, 1, 1:2]) # [C, N, 1]
    radii = mx.concatenate([radii, radii_y], axis=-1)
    
    return means_2d, cov_2d_full, means_cam[:, :, 2], conic, radii

def invert_2x2(m):
    """Invert a batch of 2x2 matrices."""
    a = m[:, :, 0, 0]
    b = m[:, :, 0, 1]
    c = m[:, :, 1, 0]
    d = m[:, :, 1, 1]
    det = a * d - b * c
    inv_det = 1.0 / det
    return mx.stack([
        d * inv_det, -b * inv_det,
        -c * inv_det, a * inv_det
    ], axis=-1).reshape(m.shape)
```

## Subtopics

### [3D Gaussian Splatting Differentiable Rasterizer](2813-3d-gaussian-splatting-differentiable-rasterizer.md)
The 3D Gaussian Splatting Differentiable Rasterizer projects 3D Gaussian primitives into 2D screen space and accumulates color per pixel using alpha compositing, enabling gradients to flow back to Gaussian parameters (position, scale, rotation, opacity, color). It differs from its siblings by providing the core differentiable kernel that bridges the 3D scene representation and the 2D image plane, whereas methods like [Optimal Gaussian Splatting](3293-optimal-gaussian-splatting.md) focus on training efficiency and [Hybrid Transparency](3294-hybrid-transparency.md) on specific blending artifacts.

### [Optimal Gaussian Splatting](3293-optimal-gaussian-splatting.md)
Optimal Gaussian Splatting is a rendering method that reduces projection error by radially projecting each 3D Gaussian onto a unique tangent plane perpendicular to the line connecting the Gaussian mean to the camera center, rather than projecting all Gaussians onto a single plane $z=1$. Unlike the original 3D Gaussian Splatting rasterization which uses a fixed perspective plane, this method treats the projection as a radial mapping onto a unit sphere, ensuring the projection of the Gaussian mean coincides with the ray direction from the camera center. It differs from NeRF by avoiding extensive ray sampling, instead determining which tangent-plane Gaussians intersect the ray on the unit sphere.

### [Hybrid Transparency](3294-hybrid-transparency.md)
Hybrid Transparency is a blending formulation that combines depth-ordered alpha blending for the first $K$ fragments (the 'core') with order-independent accumulation for the remaining fragments (the 'tail') to mitigate popping artifacts while maintaining real-time performance. It solves the inconsistency of splat shapes and popping artifacts across viewpoints in VR and motion by avoiding the performance cost of hierarchical sorting or ray tracing. Unlike standard 3D Gaussian Splatting which uses approximate per-primitive sorting, Hybrid Transparency guarantees correct depth ordering for the front-most contributions and uses fast, unsorted blending for the rest.

### [Perspective-Correct 3D Gaussian Splatting via Plücker Coordinates](3403-perspective-correct-3d-gaussian-splatting-via-pl-cker-coordi.md)
This method computes the value of a 3D Gaussian primitive for a given viewing ray in screen space without performing matrix inversion, utilizing Plücker coordinates to represent the ray and calculate the distance to the Gaussian's center. It sets itself apart from standard 3D Gaussian Splatting rasterization by providing a closed-form, numerically stable solution for perspective-correct splat evaluation that handles degenerate ellipsoids and avoids the computational cost of matrix inversions.

### [3D Gaussian Splatting Rasterization (Cone-Beam/Scanner Space)](3458-3d-gaussian-splatting-rasterization-cone-beam-scanner-space.md)
This method renders X-ray projections from a 3D Gaussian representation by integrating the 3D Gaussian density along cone-beam ray paths, resulting in a sum of 2D Gaussians rather than the alpha-compositing used in standard visible-light rendering. It solves the problem of simulating X-ray CT projections from learned 3D Gaussian fields by adapting the rasterization pipeline to a pinhole camera model, enabling analytical integration of radiative density. Unlike standard 3D Gaussian Splatting which composites opacities, this method sums projected 2D densities, fundamentally addressing integration bias issues where learning integrated density in 2D leads to inconsistencies in 3D density retrieval.

### [Analytic-Splatting Forward Shading](3459-analytic-splatting-forward-shading.md)
Analytic-Splatting Forward Shading computes the color contribution of 3D Gaussians to a pixel by analytically integrating the Gaussian probability density function over the pixel area, rather than sampling the center. It solves the aliasing artifacts inherent in point-sampling approaches by approximating the pixel area integral using a conditioned logistic function. It sets itself apart from vanilla 3DGS by providing anti-aliased results and from Mip-Splatting by using a different analytical approximation that maintains higher detail fidelity, albeit with a slight computational overhead.

### [Speedy-Splat Rendering Pipeline](3543-speedy-splat-rendering-pipeline.md)
The Speedy-Splat Rendering Pipeline is a GPU-accelerated rasterization method for 3D Gaussian Splatting that replaces coarse bounding-box tile intersection tests with precise Gaussian-tile intersection checks and sorting-based depth ordering. It addresses the inefficiency of standard 3D-GS rasterization, which overestimates Gaussian extents and processes non-intersecting pixels, by generating a sparse set of Gaussian-tile pairs and sorting them for efficient pixel-wise compositing.

### [Ghost Ellipsoids for Chunked Training](3559-ghost-ellipsoids-for-chunked-training.md)
Ghost Ellipsoids for Chunked Training resolves boundary artifacts in chunked volume training by including ellipsoids from neighboring chunks in the loss computation without updating their parameters, providing boundary context without requiring a global volume or merged model. Unlike chunk-based 3DGS methods that resolve boundary inconsistencies by merging chunks into a global coarse model or through post-training stages, this method requires boundary support during training itself without access to a global volume.

### [Analytic Transmittance 3DGS](4440-analytic-transmittance-3dgs.md)
Analytic Transmittance 3DGS is a rasterization-based rendering method that replaces the approximate alpha computation of standard 3D Gaussian Splatting (3DGS) with an analytic integration of the volume rendering equation along the camera ray. It computes physically accurate transmittance and alpha values without projecting 3D Gaussians to 2D splats, thereby avoiding the linearization of the exponential transmittance and the assumption of non-self-occlusion inherent in splatting. Unlike its sibling [3D Gaussian Splatting Differentiable Rasterizer](2813-3d-gaussian-splatting-differentiable-rasterizer.md) which relies on 2D Gaussian projection, this method integrates 3D Gaussians directly in ray-space to better represent opaque surfaces and improve view synthesis quality.

### [Ref-Gaussian Deferred Surfel Rendering with Split-Sum IBL](4464-ref-gaussian-deferred-surfel-rendering-with-split-sum-ibl.md)
Ref-Gaussian Deferred Surfel Rendering with Split-Sum IBL is a real-time deferred shading method for relighting 3D Gaussian Splatting (3DGS) models on mobile hardware (specifically iOS/Metal). It solves the problem of dynamic environment lighting in Gaussian splats by decomposing splats into physically-based rendering (PBR) materials (albedo, normal, roughness, reflectance) and computing lighting via a deferred pipeline with split-sum environment map integration. Unlike forward-shading Gaussian splatters that bake lighting into spherical harmonics or use analytic approximations, this method separates the material definition from the lighting environment, allowing the environment map to be swapped or rotated in real-time without retraining or re-rasterizing the splats. It differs from standard PBR deferred renderers by adapting the splat-based rasterization and surfel accumulation to the deferred G-buffer workflow.

### [3D Gaussian Splatting Self-Shadowing (T_light)](4487-3d-gaussian-splatting-self-shadowing-t-light.md)
Calculates the self-shadowing transmittance $T_{light}$ for each Gaussian along a directional sun direction, representing the 'front occlusion transmittance' to model self-shadowing effects in volume rendering. It differs from standard alpha blending by explicitly tracking accumulated occlusion from the light source's perspective rather than the camera's, enabling physically plausible shadows within the Gaussian volume.

### [Light Space Rasterization for T_light](4489-light-space-rasterization-for-t-light.md)
Light Space Rasterization computes $T_{light}$, the front-facing occlusion transmittance for each 3D Gaussian along a directional sun direction. It differs from voxel-based fallbacks by providing full continuous gradients and zero parameter expansion, enabling differentiable relighting without requiring specific training hyperparameters.

### [2D Gaussian Splatting Rasterization](4815-2d-gaussian-splatting-rasterization.md)
2D Gaussian Splatting Rasterization renders a scene represented by 2D Gaussian surfels by projecting them to screen space and performing ray-surfel intersection per pixel, accumulating colour, alpha, and normal maps via front-to-back alpha compositing. It differs from the standard 3D Gaussian Splatting Rasterization [2812-3d-gaussian-splatting-rasterization.md] by treating primitives as planar surfels with 2D covariance structures rather than 3D ellipsoids, which simplifies the intersection geometry but requires specific handling of the surfel plane orientation relative to the view ray.

### [SparseOIT Rasterizer](7562-sparseoit-rasterizer.md)
The SparseOIT Rasterizer is a method for rendering 3D Gaussian Splatting scenes that computes a weighted blended order-independent transparency (OIT) image and a pre-rendered image simultaneously. It solves the depth-sorting bottleneck of standard alpha-blending by decoupling the blending process from the depth order of the Gaussians, relying instead on a tile-based sorting strategy. Unlike standard differentiable rasterizers that require strict depth sorting per pixel, this method uses a blend-and-normalize (BAN) function for final color and a blend-and-update (BAU) function for state accumulation, allowing for parallel computation of independent Gaussian variables during backward propagation.

### Panorama Camera Adaptation
A method to adapt the rasterization projection for panoramic images by mapping pixel coordinates to the unit sphere [S5]. For a pixel $(u, v)$ on the image, cast a ray and compute the 2D coordinate vector $\mathbf{x}_{2D}$ using the panoramic projection formula involving image height $H$ and width $W$ [S5]. The formula is:
$$ \mathbf{x}_{2D} = \varphi_p \left( \begin{bmatrix} \sin \left( \frac{\pi(-W+2u)}{W} \right) \cos \left( \frac{\pi(-\frac{H}{2}+v)}{H} \right) \\ \sin \left( \frac{\pi(-\frac{H}{2}+v)}{H} \right) \\ \cos \left( \frac{\pi(-\frac{H}{2}+v)}{H} \right) \cos \left( \frac{\pi(-W+2u)}{W} \right) \end{bmatrix} \right) $$
where $H$ is the height of the image and $W$ is the width of the image [S5].

### Temporal Marginal Probability Filtering
Pre-rasterization culling step that removes 4D Gaussians with negligible temporal support at the current frame timestamp, stabilizing rendering speed across video length [S6, unofficial]. Compute the marginal probability $p_i(t)$ for each 4D Gaussian $i$ at the current frame's timestamp $t$ [S6, unofficial]. Discard Gaussians with negligible $p_i(t)$ before executing standard frustum culling [S6, unofficial]. Unlike methods where Gaussian count scales with video length, this filtering keeps active Gaussians constant, making the approach friendly to long videos in terms of rendering speed [S6, unofficial].

### t-distribution truncation for splatting
A projection truncation technique that replaces the fixed three-sigma rule used in vanilla 3DGS with a $\nu$-dependent critical value interpolation to handle fat-tailed Student's t-distributions [S7]. For t-distributions with thin tails (high $\nu$), apply the standard three-sigma rule directly. For fat-tailed distributions (low $\nu$), obtain critical values for different $\nu$ degrees from reference [9] and interpolate between them to compute the appropriate truncation threshold [S7]. Using a fixed three-sigma threshold on fat-tailed t-distributions causes excessive truncation or leakage. Interpolation across $\nu$ degrees resolves this [S7].

### Gaussian Opacity Fields (GOF)
Uses ray-tracing-style intersection for accurate depth. Derives a level-set surface from accumulated opacity [S4, unofficial].

### Progressive Normal Propagation
Uses progressive propagation along normals to fill texture-less regions [S4, unofficial].

### Gaussian Surfels
Uses zero-thickness oriented surfels [S4, unofficial].

### NeuSG
Combines NeuS-style SDF with a GS rasterizer [S4, unofficial].

### Hardware-Accelerated Gaussian Rasterization
A hardware-algorithm co-design that augments standard triangle rasterizers with dedicated units for Gaussian projection and blending, achieving an order of magnitude speedup in the rasterization stage [S8, unofficial].

## Operating characteristics
**Time Complexity:** Dominated by sorting $N$ Gaussians, which is $O(N \log N)$ or $O(N)$ with radix sort [S3, unofficial]. Rasterization is $O(P \cdot K)$ where $P$ is pixels and $K$ is average Gaussians per pixel [S3, unofficial].
**Memory Complexity:** $O(N)$ for Gaussian parameters and $O(P)$ for output buffers [S3, unofficial]. High VRAM usage: 4GB to view, 12GB to train [S3, unofficial]. Large disk size: 1GB+ for a scene [S3, unofficial].
**Measured Performance:** Real-time rendering (60+ FPS) on modern GPUs for scenes with millions of Gaussians [S3, unofficial].
**Scaling:** Scales linearly with number of Gaussians and pixels [S3, unofficial].
**Strengths:** Real-time performance, high visual quality, differentiable [S3, unofficial].
**Limitations:** High VRAM usage, large disk size, sorting bottleneck on non-CUDA hardware [S3, unofficial].
**When to use:** Real-time rendering of learned radiance fields [S3, unofficial].
**When not to use:** When hardware acceleration (CUDA) is unavailable and performance is critical, or when strict compatibility with existing triangle-based pipelines is required without adaptation [S3, unofficial].

## Background
3D Gaussian Splatting was introduced in the paper "3D Gaussian Splatting for Real-Time Radiance Field Rendering" [S3, unofficial]. It allows real-time rendering of photorealistic scenes learned from small samples of images [S3, unofficial]. The method uses Structure from Motion (SfM) to estimate a point cloud, converts points to Gaussians, and trains them using Stochastic Gradient Descent [S3, unofficial]. The primary bottleneck is sorting millions of Gaussians, which is done efficiently in the original implementation using CUB device radix sort, a highly optimized sort only available in CUDA [S3, unofficial].
