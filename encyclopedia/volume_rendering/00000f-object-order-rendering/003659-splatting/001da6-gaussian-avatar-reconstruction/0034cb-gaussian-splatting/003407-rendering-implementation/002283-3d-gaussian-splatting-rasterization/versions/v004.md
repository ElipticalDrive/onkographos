# 3D Gaussian Splatting Rasterization

Also called: 3DGS Rasterization, Differentiable Gaussian Rasterization, TrimGS, gsplat.rasterization

## Overview
3D Gaussian Splatting Rasterization is a differentiable rendering technique that represents a scene as a set of 3D Gaussians and rasterizes them to 2D images by projecting 3D covariances to 2D screen covariances, sorting by depth, and compositing colors based on alpha and transmittance [S2, S3, unofficial]. It solves the problem of real-time, photorealistic rendering of learned scenes by providing a fast, GPU-accelerated pipeline analogous to triangle rasterization but using Gaussians instead of triangles [S3, unofficial]. It differs from its siblings by providing the core differentiable kernel that bridges the 3D scene representation and the 2D image plane, whereas methods like [Optimal Gaussian Splatting](3293-optimal-gaussian-splatting.md) focus on training efficiency and [Hybrid Transparency](3294-hybrid-transparency.md) on specific blending artifacts [S2, unofficial].

## How it works
**Inputs:**
*   `means_3D`: Array of shape $[N, 3]$ containing the 3D positions of $N$ Gaussians.
*   `quats`: Array of shape $[N, 4]$ containing unit quaternions $(w, x, y, z)$ representing rotation.
*   `scales`: Array of shape $[N, 3]$ containing the scaling factors for each axis.
*   `opacities`: Array of shape $[N]$ containing scalar opacity values.
*   `colors`: Array of shape $[N, D]$ (or $[N, 3]$) containing direct RGB colors, or spherical harmonic coefficients if `sh_degree` is set.
*   `viewmats`: Array of shape $[C, 4, 4]$ containing camera-to-world transformation matrices for $C$ cameras.
*   `Ks`: Array of shape $[C, 3, 3]$ containing camera intrinsic matrices.
*   `width`, `height`: Integer image dimensions.
*   `tile_size`: Integer, default 16. Side length of tiles for rasterization [S1, unofficial].
*   `near_plane`, `far_plane`: Floats, defaults 0.01 and $10^{10}$, defining clipping planes [S1, unofficial].
*   `render_mode`: String specifying output channels: "RGB", "D", "ED", "RGB+D", "RGB+ED", "d", "Ed", "RGB+d", "RGB+Ed" [S1, unofficial].
*   `rasterize_mode`: String, "classic" or "antialiased" [S1, unofficial].
*   `camera_model`: String, "pinhole", "ortho", or "fisheye" [S1, unofficial].
*   `sh_degree`: Integer or None. If not None, enables spherical harmonics color computation [S1, unofficial].
*   `backgrounds`: Array of shape $[C, 3]$ for background color where alpha is zero [S1, unofficial].

**Outputs:**
*   `render_colors`: Array of shape $[C, H, W, D]$ (where $D=3$ or $4$ depending on mode).
*   `render_alphas`: Array of shape $[C, H, W, 1]$ containing accumulated alpha.

**Data Structures:**
*   **Covariance Matrix ($\Sigma_{3D}$):** Computed from `quats` and `scales`. The rotation matrix $R$ is derived from the quaternion. The covariance is $\Sigma_{3D} = R S S^T R^T$, where $S$ is a diagonal matrix of scales [S2, unofficial].
*   **2D Projection:** The 3D mean $\mu_{3D}$ and covariance $\Sigma_{3D}$ are linearized to 2D screen space using camera intrinsics/extrinsics and image size, resulting in `means_2D` $[N, 2]$ and `cov_2D` $[N, 2, 2]$ [S2, unofficial].
*   **Conics:** The inverse of the 2D covariance matrix is stored in a compact form `conics` $[N, 3]$ for efficient evaluation [S1, unofficial].
*   **Tile Intersection:** Gaussians are mapped to tiles. `isect_offsets` $[C, H_{tile}, W_{tile}]$ and `flatten_ids` encode which Gaussians intersect which tiles [S1, unofficial].

**Steps:**

1.  **Input Validation:** Check `render_mode`, `rasterize_mode`, and `camera_model` against valid sets [S1, unofficial].
2.  **Covariance Computation:** Compute 3D covariance matrices from quaternions and scales. Using `quat_scale_to_covar_preci` with `compute_covar=True`, `compute_preci=False`, `triu=False`, resulting in shape $[N, 3, 3]$ [S1, unofficial].
3.  **Projection:** Project Gaussians to 2D screen space using `fully_fused_projection`. Inputs: `means`, `covars`, `viewmats`, `Ks`, `width`, `height`, `eps2d`, `near_plane`, `far_plane`, `calc_compensations` (True if `rasterize_mode` is "antialiased"), and `camera_model`. Outputs: `radii` $[C, N, 2]$, `means2d` $[C, N, 2]$, `depths` $[C, N]$, `conics` $[C, N, 3]$, and `compensations` [S1, unofficial].
4.  **Opacity and Color Preparation:**
    *   Broadcast scalar per-Gaussian opacities $[N]$ to per-camera $[C, N]$ using `mx.broadcast_to(mx.expand_dims(opacities, axis=0), (C, N))` [S1, unofficial].
    *   If `compensations` are not None, multiply opacities by compensations [S1, unofficial].
    *   If `sh_degree` is not None:
        *   Compute view directions: `dirs = means[None, :, :] - campos[:, None, :]` [S1, unofficial].
        *   Normalize `dirs` by dividing by `mx.maximum(dirs_norm, 1e-8)` [S1, unofficial].
        *   Broadcast color coefficients to $[C, N, K, 3]$ [S1, unofficial].
        *   Evaluate `spherical_harmonics(sh_degree, dirs, coeffs_broadcast)` to get `rgb` $[C, N, 3]$ [S1, unofficial].
        *   Clamp with `mx.maximum(rgb + 0.5, 0.0)` [S1, unofficial].
    *   If `sh_degree` is None, broadcast colors $[N, D]$ to $[C, N, D]$ or use colors $[C, N, D]$ directly as `colors_for_raster` [S1, unofficial].
5.  **Tile Intersection:**
    *   Compute tile dimensions: `tile_width = ceil(width / tile_size)`, `tile_height = ceil(height / tile_size)` [S1, unofficial].
    *   Call `isect_tiles(means2d, radii, depths, tile_size, tile_width, tile_height, sort=True)` to get `tiles_per_gauss`, `isect_ids`, `flatten_ids` [S1, unofficial].
    *   Encode intersection offsets using `isect_offset_encode(isect_ids, C, tile_width, tile_height)` to get `isect_offsets` $[C, tile_height, tile_width]$ [S1, unofficial].
6.  **Rasterization (Pixel Compositing):**
    *   Call `rasterize_to_pixels_mlx` (if differentiable) or `rasterize_to_pixels`, passing `means2d`, `conics`, `colors_for_raster`, `opacities_cn`, `width`, `height`, `tile_size`, `isect_offsets`, `flatten_ids`, and `backgrounds` [S1, unofficial].
    *   Inside the kernel, for each pixel:
        *   Iterate over Gaussians in the tile that cover the pixel.
        *   Compute alpha: $\alpha = \text{opacity} \cdot \exp(-0.5 \cdot \mathbf{d}^T \Sigma^{-1} \mathbf{d})$, where $\mathbf{d}$ is the distance from pixel center to Gaussian mean in 2D [S2, unofficial].
        *   Compute transmittance: $T_i = \prod_{j=1}^{i-1} (1 - \alpha_j)$ [S2, unofficial].
        *   Compute weight: $w_i = \alpha_i \cdot T_i$ [S2, unofficial].
        *   Accumulate color: $C_{pixel} = \sum w_i C_i$ [S2, unofficial].
        *   Accumulate alpha: $\alpha_{pixel} = \sum w_i$ [S2, unofficial].
7.  **Post-Processing:**
    *   If `render_mode` includes depth:
        *   If `has_depth`, use `depths`; if `has_hit_dist`, compute `hit_dists = mx.sqrt(mx.sum(means_c * means_c, axis=-1))` where `means_c` is camera-space mean [S1, unofficial].
        *   Normalize accumulated depth by alpha: `depth_channel = depth_channel / mx.maximum(render_alphas, 1e-10)` [S1, unofficial].
        *   Concatenate normalized depth back to color channels if `has_color`, or replace `render_colors` if not [S1, unofficial].
    *   Composite background color where mask is zero: `image = mask * image + (1.0 - mask) * bg_colour_` [S2, unofficial].

        1 - 2*(y*y + z*z), 2*(x*y - w*z), 2*(x*z + w*y),
        2*(x*y + w*z), 1 - 2*(x*x + z*z), 2*(y*z - w*x),
        2*(x*z - w*y), 2*(y*z + w*x), 1 - 2*(x*x + y*y)
    ], axis=-1).reshape(N, 3, 3)
    
    S = mx.diag_embed(scales) # Shape [N, 3, 3]
    cov_3d = R @ S @ S.T @ R.T # Shape [N, 3, 3]
    
    # 2. Project to 2D
    # Simplified linearized projection for pinhole camera
    # Get camera rotation and translation
    R_cam = viewmats[:, :3, :3] # [C, 3, 3]
    t_cam = viewmats[:, :3, 3] # [C, 3]
    
    # Transform means to camera space
    means_cam = (R_cam @ means_3d.T).T + t_cam[:, None, :] # [C, N, 3]
    
    # Perspective divide
    z_cam = means_cam[:, :, 2:3] # [C, N, 1]
    x_cam = means_cam[:, :, 0:1]
    y_cam = means_cam[:, :, 1:2]
    
    fx = Ks[:, 0, 0] # [C]
    fy = Ks[:, 1, 1]
    cx = Ks[:, 0, 2]
    cy = Ks[:, 1, 2]
    
    # Projected 2D means
    means_2d_x = (x_cam / z_cam) * fx[:, None, None] + cx[:, None, None]
    means_2d_y = (y_cam / z_cam) * fy[:, None, None] + cy[:, None, None]
    means_2d = mx.concatenate([means_2d_x, means_2d_y], axis=-1) # [C, N, 2]
    
    # Project Covariance (Jacobian approximation)
    # J = [fx/z, 0, -fx*x/z^2; 0, fy/z, -fy*y/z^2]
    # This is a simplified approximation; full derivation involves 3x3 to 2x2 projection

        dirs_norm = mx.sqrt(mx.sum(dirs**2, axis=-1, keepdims=True))

    J = [fx/z, 0, -fx*x/z^2; 0, fy/z, -fy*y/z^2]

    cov_2d = J @ cov_3d[0:3, 0:3] @ J.T
    """
    x = means_cam[:, :, 0:1]
    y = means_cam[:, :, 1:2]
    z = z_cam
    
    fx_inv_z = fx[:, None, None] / z
    fy_inv_z = fy[:, None, None] / z
    
    # Jacobian J [C, N, 2, 3]
    J = mx.zeros((means_cam.shape[0], means_cam.shape[1], 2, 3))
    J = J.at[:, :, 0, 0].set(fx_inv_z)
    J = J.at[:, :, 1, 1].set(fy_inv_z)
    J = J.at[:, :, 0, 2].set(-fx_inv_z * x / z)
    J = J.at[:, :, 1, 2].set(-fy_inv_z * y / z)

    return cov_2d

def compute_conics(cov_2d):
    """
    Compute inverse covariance and store as [x, z, y] for [[x, z], [z, y]]
    """
    # Invert 2x2 matrices
    # det = a*d - b*c
    # inv = [[d, -b], [-c, a]] / det
    a = cov_2d[:, :, 0, 0]
    b = cov_2d[:, :, 0, 1]
    c = cov_2d[:, :, 1, 0]
    d = cov_2d[:, :, 1, 1]
    
    det = a * d - b * c
    # Add epsilon for stability
    det = mx.maximum(det, 1e-6)
    
    inv_a = d / det
    inv_b = -b / det
    inv_c = -c / det
    inv_d = a / det
    
    # Store as [x, z, y] where x=inv_a, z=inv_b (assuming symmetric), y=inv_d
    # Note: inv_b should equal inv_c for symmetric matrices
    conics = mx.stack([inv_a, inv_b, inv_d], axis=-1)
    return conics

## Subtopics

### [3D Gaussian Splatting Differentiable Rasterizer](2813-3d-gaussian-splatting-differentiable-rasterizer.md)
The 3D Gaussian Splatting Differentiable Rasterizer projects 3D Gaussian primitives into 2D screen space and accumulates color per pixel using alpha compositing, enabling gradients to flow back to Gaussian parameters (position, scale, rotation, opacity, color). It differs from its siblings by providing the core differentiable kernel that bridges the 3D scene representation and the 2D image plane, whereas methods like [Optimal Gaussian Splatting](3293-optimal-gaussian-splatting.md) focus on training efficiency and [Hybrid Transparency](3294-hybrid-transparency.md) on specific blending artifacts.

### [Optimal Gaussian Splatting](3293-optimal-gaussian-splatting.md)
Optimal Gaussian Splatting is a rendering method that reduces projection error by radially projecting each 3D Gaussian onto a unique tangent plane perpendicular to the line connecting the Gaussian mean to the camera center, rather than projecting all Gaussians onto a single plane $z=1$. Unlike the original 3D Gaussian Splatting rasterization which uses a fixed perspective plane, this method treats the projection as a radial mapping onto a unit sphere, ensuring the projection of the Gaussian mean coincides with the ray direction from the camera center. It differs from NeRF by avoiding extensive ray sampling, instead determining which tangent-plane Gaussians intersect the ray on the unit sphere.

### [Hybrid Transparency](3294-hybrid-transparency.md)
Hybrid Transparency is a blending formulation that combines depth-ordered alpha blending for the first $K$ fragments (the 'core') with order-independent accumulation for the remaining fragments (the 'tail') to mitigate popping artifacts while maintaining real-time performance. It solves the inconsistency of splat shapes and popping artifacts across viewpoints in VR and motion by avoiding the performance cost of hierarchical sorting or ray tracing. Unlike standard 3D Gaussian Splatting which uses approximate per-primitive sorting, Hybrid Transparency guarantees correct depth ordering for the front-most contributions and uses fast, unsorted blending for the rest.

### [Perspective-Correct 3D Gaussian Splatting via Plücker Coordinates](3403-perspective-correct-3d-gaussian-splatting-via-pl-cker-coordi.md)
This method computes the value of a 3D Gaussian primitive for a given viewing ray in screen space without performing matrix inversion, utilizing Plücker coordinates to represent the ray and calculate the distance to the Gaussian's center. It sets itself apart from standard 3D Gaussian Splatting rasterization by providing a closed-form, numerically stable solution for perspective-correct splat evaluation that handles degenerate ellipsoids and avoids the computational cost of matrix inversions.

### [3D Gaussian Splatting Rasterization (Cone-Beam/Scanner Space)](3458-3d-gaussian-splatting-rasterization-cone-beam-scanner-space.md)
This method renders X-ray projections from a 3D Gaussian representation by integrating the 3D Gaussian density along cone-beam ray paths, resulting in a sum of 2D Gaussians rather than the alpha-compositing used in standard visible-light rendering. It solves the problem of simulating X-ray CT projections from learned 3D Gaussian fields by adapting the rasterization pipeline to a pinhole camera model, enabling analytical integration of radiative density. Unlike standard 3D Gaussian Splatting which composites opacities, this method sums projected 2D densities, fundamentally addressing integration bias issues where learning integrated density in 2D leads to inconsistencies in 3D density retrieval.

### [Analytic-Splatting Forward Shading](3459-analytic-splatting-forward-shading.md)
Analytic-Splatting Forward Shading computes the color contribution of 3D Gaussians to a pixel by analytically integrating the Gaussian probability density function over the pixel area, rather than sampling the center. It solves the aliasing artifacts inherent in point-sampling approaches by approximating the pixel area integral using a conditioned logistic function. It sets itself apart from vanilla 3DGS by providing anti-aliased results and from Mip-Splatting by using a different analytical approximation that maintains higher detail fidelity, albeit with a slight computational overhead.

### [Speedy-Splat Rendering Pipeline](3543-speedy-splat-rendering-pipeline.md)
The Speedy-Splat Rendering Pipeline is a GPU-accelerated rasterization method for 3D Gaussian Splatting that optimizes the rendering loop by replacing coarse bounding-box tile intersection tests with precise Gaussian-tile intersection checks and sorting-based depth ordering. It addresses the inefficiency of standard 3-GS rasterization, which overestimates Gaussian extents and processes non-intersecting pixels, by generating a sparse set of Gaussian-tile pairs and sorting them for efficient pixel-wise compositing.

### [Ghost Ellipsoids for Chunked Training](3559-ghost-ellipsoids-for-chunked-training.md)
Ghost Ellipsoids for Chunked Training resolves boundary artifacts in chunked volume training by including ellipsoids from neighboring chunks in the loss computation without updating their parameters, providing boundary context without requiring a global volume or merged model. Unlike chunk-based 3DGS methods that resolve boundary inconsistencies by merging chunks into a global coarse model or through post-training stages, this method requires boundary support during training itself without access to a global volume.

### [Analytic Transmittance 3DGS](4440-analytic-transmittance-3dgs.md)
Analytic Transmittance 3DGS is a rasterization-based rendering method that replaces the approximate alpha computation of standard 3D Gaussian Splatting (3DGS) with an analytic integration of the volume rendering equation along the camera ray. It computes physically accurate transmittance and alpha values without projecting 3D Gaussians to 2D splats, thereby avoiding the linearization of the exponential transmittance and the assumption of non-self-occlusion inherent in splatting. Unlike its sibling [3D Gaussian Splatting Differentiable Rasterizer](2813-3d-gaussian-splatting-differentiable-rasterizer.md) which relies on 2D Gaussian projection, this method integrates 3D Gaussians directly in ray-space to better represent opaque surfaces and improve view synthesis quality.

### [Ref-Gaussian Deferred Surfel Rendering with Split-Sum IBL](4464-ref-gaussian-deferred-surfel-rendering-with-split-sum-ibl.md)
Ref-Gaussian Deferred Surfel Rendering with Split-Sum IBL is a real-time deferred shading method for relighting 3D Gaussian Splatting (3DGS) models on mobile hardware (specifically iOS/Metal). It solves the problem of dynamic environment lighting in Gaussian splats by decomposing splats into physically-based rendering (PBR) materials (albedo, normal, roughness, reflectance) and computing lighting via a deferred pipeline with split-sum environment map integration. Unlike forward-shading Gaussian splatters that bake lighting into spherical harmonics or use analytic approximations, this method separates the material definition from the lighting environment, allowing the environment map to be swapped or rotated in real-time without retraining or re-rasterizing the splats. It differs from standard PBR deferred renderers by adapting the splat-based rasterization and surfel accumulation to the deferred G-buffer workflow.

### [3D Gaussian Splatting Self-Shadowing (T_light)](4487-3d-gaussian-splatting-self-shadowing-t-light.md)
Calculates the self-shadowing transmittance $T_{light}$ for each Gaussian along the sun direction. It represents the 'front occlusion transmittance' to model self-shadowing effects in volume rendering.

### [Light Space Rasterization for T_light](4489-light-space-rasterization-for-t-light.md)
Light Space Rasterization computes $T_{light}$, the front-facing occlusion transmittance for each 3D Gaussian along a directional sun direction, enabling physically plausible self-shadowing in volume cloud rendering. It differs from voxel-based fallbacks by providing full continuous gradients and zero parameter expansion, allowing for differentiable relighting without requiring specific training hyperparameters.

### [2D Gaussian Splatting Rasterization](4815-2d-gaussian-splatting-rasterization.md)
2D Gaussian Splatting Rasterization renders a scene represented by 2D Gaussian surfels by projecting them to screen space and performing ray-surfel intersection per pixel, accumulating colour, alpha, and normal maps via front-to-back alpha compositing. It differs from the standard 3D Gaussian Splatting Rasterization [2812-3d-gaussian-splatting-rasterization.md] by treating primitives as planar surfels with 2D covariance structures rather than 3D ellipsoids, which simplifies the intersection geometry but requires specific handling of the surfel plane orientation relative to the view ray.

### [SparseOIT Rasterizer](7562-sparseoit-rasterizer.md)
The SparseOIT Rasterizer is a method for rendering 3D Gaussian Splatting scenes that computes a weighted blended order-independent transparency (OIT) image and a pre-rendered image simultaneously. It solves the depth-sorting bottleneck of standard alpha-blending by decoupling the blending process from the depth order of the Gaussians, relying instead on a tile-based sorting strategy. Unlike standard differentiable rasterizers that require strict depth sorting per pixel, this method uses a blend-and-normalize (BAN) function for final color and a blend-and-update (BAU) function for state accumulation, allowing for parallel computation of independent Gaussian variables during backward propagation.

### Panorama Camera Adaptation
A method to adapt the rasterization projection for panoramic images by mapping pixel coordinates to the unit sphere [S5]. For a pixel $(u, v)$ on the image, cast a ray and compute the 2D coordinate vector $\mathbf{x}_{2D}$ using the panoramic projection formula involving image height $H$ and width $W$ [S5]. The formula is $\mathbf{x}_{2D} = \varphi_p \left( \begin{bmatrix} \sin \left( \frac{\pi(-W+2u)}{W} \right) \cos \left( \frac{\pi(-\frac{H}{2}+v)}{H} \right) \\ \sin \left( \frac{\pi(-\frac{H}{2}+v)}{H} \right) \\ \cos \left( \frac{\pi(-\frac{H}{2}+v)}{H} \right) \cos \left( \frac{\pi(-W+2u)}{W} \right) \end{bmatrix} \right)$ [S5].

### Temporal Marginal Probability Filtering
Pre-rasterization culling step that removes 4D Gaussians with negligible temporal support at the current frame timestamp, stabilizing rendering speed across video length [S6, unofficial]. Compute the marginal probability $p_i(t)$ for each 4D Gaussian $i$ at the current frame's timestamp $t$ [S6, unofficial]. Discard Gaussians with negligible $p_i(t)$ before executing standard frustum culling [S6, unofficial]. Unlike methods where Gaussian count scales with video length, this filtering keeps active Gaussians constant, making the approach friendly to long videos in terms of rendering speed [S6, unofficial].

### t-distribution truncation for splatting
A projection truncation technique that replaces the fixed three-sigma rule used in vanilla 3DGS with a $\nu$-dependent critical value interpolation to handle fat-tailed Student's t-distributions [S7]. For t-distributions with thin tails (high $\nu$), apply the standard three-sigma rule directly. For fat-tailed distributions (low $\nu$), obtain critical values for different $\nu$ degrees from reference [9] and interpolate between them to compute the appropriate truncation threshold [S7]. Using a fixed three-sigma threshold on fat-tailed t-distributions causes excessive truncation or leakage. Interpolation across $\nu$ degrees resolves this [S7].

### Gaussian Opacity Fields (GOF)
Uses ray-tracing-style intersection for accurate depth. Derives a level-set surface from accumulated opacity [S4, unofficial].

### Progressive Normal Propagation
Uses progressive propagation along normals to fill texture-less regions [S4, unofficial].

### Gaussian Surfels
Uses zero-thickness oriented surfels [S4, unofficial].

### NeuSG
Combines NeuS-style SDF with a GS rasterizer [S4, unofficial].

### Hardware-Accelerated Gaussian Rasterization
A hardware-algorithm co-design that augments standard triangle rasterizers with dedicated units for Gaussian projection and blending, achieving an order of magnitude speedup in the rasterization stage [S8, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
The primary bottleneck is sorting millions of Gaussians, which is done efficiently in the original implementation using CUB device radix sort, a highly optimized sort only available in CUDA [S3, unofficial]. The memory complexity is high: 4GB VRAM to view and 12GB to train [S3, unofficial]. The disk size is large, 1GB+ for a scene [S3, unofficial].

**Measured Performance:**
Performance is real-time for typical scenes on modern GPUs [S3, unofficial].

**Scaling:**
The algorithm can run faster if more Gaussians are splatted per function call, but at the cost of higher GPU memory consumption [S2, unofficial]. Handling memory constraints by splitting Gaussians into mini-batches if `per_splat > 0` is recommended [S2, unofficial].

**Strengths and Limitations:**
Strengths include high-quality, photorealistic scenes and fast, real-time rasterization [S3, unofficial]. Limitations include high VRAM usage, large disk size, incompatibility with existing rendering pipelines (Vulkan, DirectX, WebGPU) without adaptation, and static scenes (for now) [S3, unofficial]. The primary bottleneck is sorting, which is CUDA-specific [S3, unofficial].

**When to Use:**
Use for real-time rendering of photorealistic scenes learned from small samples of images [S3, unofficial].

**When Not to Use:**
Avoid if compatibility with existing rendering pipelines is required without significant adaptation, or if VRAM is severely constrained [S3, unofficial].

## Background
**Origin:**
3D Gaussian Splatting was introduced in "3D Gaussian Splatting for Real-Time Radiance Field Rendering" [S3, unofficial]. It is a rasterization technique described in this paper that allows real-time rendering of photorealistic scenes learned from small samples of images [S3, unofficial].

**History and Development:**
The technique uses Structure from Motion (SfM) to estimate a point cloud, converts points to Gaussians, and trains them using Stochastic Gradient Descent with differentiable rasterization [S3, unofficial]. Automated densification and pruning are applied during training [S3, unofficial].

**Where it is used:**
It is used for real-time rendering of 3D scenes, with adaptations for remote viewers, WebGPU, WebGL, and Unity [S3, unofficial].
