# Gaussian Splat Fragment Shader

Also called: 2D Gaussian Splat Fragment Evaluation, Alpha Blending, Gaussian Alpha Cutoff, Over Operator, Pre-multiplied Alpha Blending, Splat Fragment Shader, splat.frag

## Overview
The Gaussian Splat Fragment Shader evaluates the 2D Gaussian alpha value at each fragment to determine splat coverage and modulates the fragment color accordingly [S1, unofficial]. It composites the new splat over the existing framebuffer color using pre-multiplied alpha blending [S1, unofficial]. It is distinguished from its parent method by handling the per-pixel transparency logic, alpha cutoffs, and framebuffer packing directly in the fragment stage, rather than relying on CPU-side sorting or generic quad rasterization [G].

## How it works
**Inputs:**
*   `vColor` (`vec4`): RGBA color of the splat [S2, unofficial].
*   `vPosition` (`vec2`): Screen-space coordinates relative to the splat center [S2, unofficial].
*   `framebuffer_pixel` (`u32`): Current framebuffer pixel value in BGRA format [S1, unofficial].

**Outputs:**
*   `fragColor` (`vec4`): The final pre-multiplied color and alpha to be written to the framebuffer [S2, unofficial].

**Data Structures:**
*   **Framebuffer Pixel:** A 32-bit unsigned integer (`u32`) packed in BGRA format (little-endian byte order) [S1, unofficial].
    *   Bits 0-7: Blue (B)
    *   Bits 8-15: Green (G)
    *   Bits 16-23: Red (R)
    *   Bits 24-31: Alpha (A)
    *   Note: The output of this shader discards the alpha channel in the final packed integer, storing only RGB [S1, unofficial].

**Parameters:**
*   `alpha_cutoff` (`f32`): `1.0/255.0`. Minimum alpha threshold to discard fragments [S1, unofficial].
*   `whitePoint` (`f32`): `0.9`. Used in tone mapping [S2, unofficial].
*   `saturation_scale` (`f32`): `1.2`. Multiplier for saturation adjustment [S2, unofficial].
*   `sharpen_gamma` (`f32`): `1.0/1.05`. Exponent for sharpening [S2, unofficial].

**Steps:**
1.  **Compute Squared Distance:** Calculate the squared Euclidean distance from the splat center using the dot product of the normalized screen-space position vector `vPosition` [S2, unofficial].
    $$ A = -\text{dot}(\mathbf{vPosition}, \mathbf{vPosition}) $$
2.  **Evaluate Gaussian:** Compute the Gaussian weight using the exponential of the squared distance [S2, unofficial].
    $$ \text{gaussian} = \exp(A) $$
    *Note: This corresponds to the 2D Gaussian PDF $\alpha(u, v) = \alpha_0 \exp\left(-\frac{1}{2}(u^2 + v^2)\right)$ where the factor of $1/2$ is absorbed into the scaling of `vPosition` or handled by the specific implementation's coordinate normalization [S1, unofficial].*
3.  **Edge Smoothing:** Compute a smoothstep factor to soften the cutoff boundary [S2, unofficial].
    $$ \text{edgeSmoothness} = \text{smoothstep}(-4.0, -3.5, A) $$
4.  **Compute Pre-multiplied Color:** Modulate the RGB channels by the Gaussian weight, base opacity, and edge smoothness [S2, unofficial].
    $$ B_{\alpha} = \text{gaussian} \times \mathbf{vColor}.a \times \text{edgeSmoothness} $$
    $$ \mathbf{color}_{new} = B_{\alpha} \times \mathbf{vColor}.rgb $$
5.  **Tone Mapping and Sharpening:** Apply post-processing to the new color before blending [S2, unofficial].
    *   **Saturation:** Compute luminance $L = \text{dot}(\mathbf{color}_{new}, [0.2126, 0.7152, 0.0722])$ and mix: $\mathbf{color}_{new} = \text{mix}([L, L, L], \mathbf{color}_{new}, 1.2)$ [S2, unofficial].
    *   **White Point/Tone Mapping:** $\mathbf{color}_{new} = \mathbf{color}_{new} \times \frac{1.0 + \mathbf{color}_{new} / (\text{whitePoint}^2)}{1.0 + \mathbf{color}_{new}}$ with $\text{whitePoint} = 0.9$ [S2, unofficial].
    *   **Sharpening:** $\mathbf{color}_{new} = \mathbf{color}_{new}^{[1.0/1.05, 1.0/1.05, 1.0/1.05]}$ [S2, unofficial].
6.  **Alpha Cutoff:** If $A < -4.0$, discard the fragment [S2, unofficial]. Alternatively, if the computed alpha $B_{\alpha} < \text{alpha\_cutoff}$, the fragment may be discarded or treated as fully transparent [S1, unofficial].
7.  **Fetch Existing Framebuffer:** Read the current pixel from the framebuffer as a `u32` [S1, unofficial].
8.  **Unpack Existing Color:** Convert the `u32` BGRA value into a `vec4` of normalized floats [S1, unofficial].
    *   $R_{old} = ((\text{pixel} \gg 16) \ \& \ 0xFF) / 255.0$ [S1, unofficial]
    *   $G_{old} = ((\text{pixel} \gg 8) \ \& \ 0xFF) / 255.0$ [S1, unofficial]
    *   $B_{old} = (\text{pixel} \ \& \ 0xFF) / 255.0$ [S1, unofficial]
    *   $A_{old} = ((\text{pixel} \gg 24) \ \& \ 0xFF) / 255.0$ [S1, unofficial]
    *   $\mathbf{color}_{old} = [R_{old}, G_{old}, B_{old}, A_{old}]$ [S1, unofficial]
9.  **Composite:** Apply the over operator using pre-multiplied alpha blending [S1, unofficial].
    $$ \mathbf{color}_{out} = (1.0 - B_{\alpha}) \times \mathbf{color}_{old} + B_{\alpha} \times [\mathbf{color}_{new}, 1.0] $$
    *Note: The source code implements this as `let blended_color = (1.0 - alpha) * old_color + alpha * new_color;`, treating both vectors as pre-multiplied [S1, unofficial].*
10. **Pack Output:** Quantize the resulting RGB channels to 8-bit integers and pack them into a `u32` BGRA format. The alpha channel is discarded in the final integer value [S1, unofficial].
    *   $R = \text{clamp}(\mathbf{RGB}_{out}.r \times 255.0, 0, 255)$ [S1, unofficial]
    *   $G = \text{clamp}(\mathbf{RGB}_{out}.g \times 255.0, 0, 255)$ [S1, unofficial]
    *   $B = \text{clamp}(\mathbf{RGB}_{out}.b \times 255.0, 0, 255)$ [S1, unofficial]
    *   $\text{output\_pixel} = (R \ll 16) | (G \ll 8) | B$ [S1, unofficial]

**Pseudocode:**
```python
# Inputs: vColor (vec4), vPosition (vec2), framebuffer_pixel_u32 (u32)
# Outputs: fragColor (vec4)

def gaussian_splat_fragment_shader(vColor, vPosition, framebuffer_pixel_u32):
    # 1. Compute squared distance (negative)
    A = -dot(vPosition, vPosition)
    
    # 2. Evaluate Gaussian
    gaussian = exp(A)
    
    # 3. Edge smoothing
    edgeSmoothness = smoothstep(-4.0, -3.5, A)
    
    # 4. Compute pre-multiplied color components
    B_alpha = gaussian * vColor.a * edgeSmoothness
    
    # 5. Apply tone mapping and sharpening
    color_new_rgb = B_alpha * vColor.rgb
    
    # Saturation adjustment
    luminance = dot(color_new_rgb, vec3(0.2126, 0.7152, 0.0722))
    color_new_rgb = mix(vec3(luminance), color_new_rgb, 1.2)
    
    # White point / Tone mapping
    whitePoint = 0.9
    color_new_rgb = color_new_rgb * (1.0 + color_new_rgb / (whitePoint * whitePoint)) / (1.0 + color_new_rgb)
    
    # Sharpening
    color_new_rgb = pow(color_new_rgb, vec3(1.0 / 1.05))
    
    # 6. Alpha cutoff
    if A < -4.0:
        return vec4(0.0, 0.0, 0.0, 0.0)
        
    # 7. Fetch and unpack existing framebuffer pixel (BGRA u32)
    old_r = ((framebuffer_pixel_u32 >> 16) & 0xFF) / 255.0
    old_g = ((framebuffer_pixel_u32 >> 8) & 0xFF) / 255.0
    old_b = (framebuffer_pixel_u32 & 0xFF) / 255.0
    old_a = ((framebuffer_pixel_u32 >> 24) & 0xFF) / 255.0
    
    old_color = vec4(old_r, old_g, old_b, old_a)
    
    # 8. Composite using over operator (pre-multiplied)
    blended_color = (1.0 - B_alpha) * old_color + B_alpha * vec4(color_new_rgb, 1.0)
    
    # 9. Pack Output: Quantize RGB to 8-bit integers and pack into u32 BGRA
    R = int(clamp(blended_color.r * 255.0, 0.0, 255.0))
    G = int(clamp(blended_color.g * 255.0, 0.0, 255.0))
    B_val = int(clamp(blended_color.b * 255.0, 0.0, 255.0))
    output_pixel = (R << 16) | (G << 8) | B_val
    
    # Return pre-multiplied color for fragment shader output
    return vec4(blended_color.rgb, B_alpha)
```

## Operating characteristics
*   **Time Complexity:** $O(1)$ per fragment [G]. The computation involves a few arithmetic operations, an exponential, and a texture fetch [G].
*   **Memory Complexity:** $O(1)$ per fragment [G]. No additional memory is required beyond the framebuffer [G].
*   **Performance:** Highly efficient on modern GPUs due to the simplicity of the fragment shader [G]. The use of `smoothstep` and early discards helps cull transparent fragments [G].
*   **Strengths:** Simple to implement, low overhead, handles transparency correctly via pre-multiplied alpha [G].
*   **Limitations:** The alpha cutoff and edge smoothing parameters are hardcoded or require tuning [S2, unofficial]. The tone mapping and sharpening steps are implementation-specific and may not be present in all versions [S2, unofficial]. The framebuffer format (BGRA) must be supported by the hardware [S1, unofficial].

## Background
The rendering pipeline involves projecting 3D Gaussians to 2D, sorting them, and rasterizing them as screen-space quads [S1, S2, unofficial]. The fragment shader is a critical component of this rasterization step, handling the per-pixel evaluation of the Gaussian function and the blending with the existing scene [S1, S2, unofficial]. The specific implementation details, such as the use of `smoothstep` for edge smoothing and the specific tone mapping parameters, are found in community implementations like `thomasantony/splat` and `liaozhangsheng/gsplat-opengl` [S1, S2, unofficial].
