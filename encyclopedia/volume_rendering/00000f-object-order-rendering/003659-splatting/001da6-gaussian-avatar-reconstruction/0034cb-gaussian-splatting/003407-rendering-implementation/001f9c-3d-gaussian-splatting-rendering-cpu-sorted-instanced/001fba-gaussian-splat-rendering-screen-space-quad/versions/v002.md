# Gaussian Splat Rendering (Screen-Space Quad)

Also called: RenderGaussianSplats, Splat Rendering

## Overview
This method renders 3D Gaussian Splatting scenes by projecting 3D Gaussian distributions into 2D screen-space quads, utilizing a pre-sorted order buffer and view-space projection data to handle transparency via alpha blending [S2, unofficial]. Unlike its parent [3D Gaussian Splatting Rendering (CPU-Sorted, Instanced)](2058-3d-gaussian-splatting-rendering-cpu-sorted-instanced.md), which uses instanced drawing with standard alpha blending, this method explicitly constructs screen-space quads in the vertex shader to allow for precise frustum culling and selection highlighting, and it differs from the sibling [Tiled 2D Gaussian Splatting Rasterization](2061-tiled-2d-gaussian-splatting-rasterization.md) by not using tiled memory optimizations or screen-space depth sorting [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A pre-sorted order buffer (`_OrderBuffer`) mapping instance IDs to splat indices, and view-space projection data (`_SplatViewData`) containing camera-space positions, axes, and colors for each splat [S2, unofficial].
*   **Output:** A framebuffer with composited colors and alpha values, where splats are drawn as screen-space quads [S2, unofficial].

**Data Structures:**
*   `_OrderBuffer`: An array of integers where the index corresponds to the draw call instance ID, and the value is the index into the splat data buffer [S2, unofficial].
*   `_SplatViewData`: A structure containing pre-computed view-space data for each splat [S2, unofficial]. Fields include `centerClipPos` (clip-space position for depth and behind-camera checks), `axis1` and `axis2` (2D vectors for projected Gaussian axes), `color` (packed color and opacity, often stored as half-floats), and `pos` (normalized screen-space position for falloff calculation) [S2, unofficial].

**Numbered Steps:**

1.  **Vertex Shader: Instance Mapping and Validation**
    *   Map instance ID to splat index: `instID = _OrderBuffer[instanceID]` [S2, unofficial].
    *   Load view data: `view = _SplatViewData[instID]` [S2, unofficial].
    *   Check if behind camera: `if view.centerClipPos.w <= 0` [S2, unofficial].
    *   If behind, output a NaN vertex to discard the primitive [S2, unofficial].

2.  **Vertex Shader: Quad Position Calculation**
    *   Decompress color from `view.color` (half-floats) into `o.col.rgba` [S2, unofficial].
    *   Calculate quad position in clip space: `quadPos = float2(instanceID & 1, (instanceID >> 1) & 1) * 2.0 - 1.0` [S2, unofficial].
    *   Scale quad position: `quadPos *= 2.0` [S2, unofficial].
    *   Calculate screen delta: `deltaScreenPos = (quadPos.x * view.axis1 + quadPos.y * view.axis2) * 2.0 / _ScreenParams.xy` [S2, unofficial].
    *   Apply delta: `o.vertex.xy += deltaScreenPos * view.centerClipPos.w` [S2, unofficial].

3.  **Vertex Shader: Selection Highlighting (Optional)**
    *   If `_SplatBitsValid` is true, calculate `wordIdx = instID // 32` and `bitIdx = instID & 31` [S2, unofficial].
    *   Load selection word: `selVal = _SplatSelectedBits.Load(wordIdx * 4)` [S2, unofficial].
    *   If bit set, set `o.col.a = -1` to mark as selected [S2, unofficial].

4.  **Fragment Shader: Gaussian Evaluation and Compositing**
    *   Calculate falloff: `power = -dot(i.pos, i.pos)` [S2, unofficial].
    *   Compute alpha: `alpha = exp(power)` [S2, unofficial].
    *   If not selected (`i.col.a >= 0`), saturate alpha: `alpha = saturate(alpha * i.col.a)` [S2, unofficial].
    *   If selected (`i.col.a < 0`), apply magenta outline: if `alpha > 7.0/255.0`, set `alpha = 1` and `i.col.rgb = selectedColor` if `alpha < 10.0/255.0`; otherwise `alpha = saturate(alpha + 0.3)` and tint `i.col.rgb = lerp(i.col.rgb, selectedColor, 0.5)` [S2, unofficial].
    *   Discard if `alpha < 1.0/255.0` [S2, unofficial].
    *   Output final color: `res = half4(i.col.rgb * alpha, alpha)` [S2, unofficial].

**Formulas:**
*   **Screen Delta Calculation:**
    $$ \text{deltaScreenPos} = \frac{(\text{quadPos}_x \cdot \text{axis1} + \text{quadPos}_y \cdot \text{axis2}) \cdot 2}{\text{ScreenResolution}} $$
    Where `quadPos` is the normalized quad corner (-1 to 1), `axis1` and `axis2` are the projected Gaussian axes in screen space, and `ScreenResolution` is the pixel dimensions [S2, unofficial].

*   **Gaussian Alpha:**
    $$ \alpha = e^{-\|\mathbf{p}\|^2} $$
    Where $\mathbf{p}$ is the normalized screen-space position relative to the splat center [S2, unofficial].

**Parameters:**
*   `_ScreenParams.xy`: Screen resolution in pixels [S2, unofficial].
*   `selectedColor`: Magenta color vector for highlighting selected splats [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Behind Camera:** Splats with clip-space $w \le 0$ must be discarded to prevent rendering artifacts, handled by outputting a NaN vertex [S2, unofficial].
*   **Precision:** Half-float decompression must be handled correctly to avoid color banding or incorrect alpha values [S2, unofficial].
*   **Selection Logic:** The selection bit logic relies on a 32-bit word array, so instance IDs must be correctly mapped to word and bit indices [S2, unofficial].

**Pseudocode:**

```python
import math

class Vec2:
    def __init__(self, x, y): self.x, self.y = x, y
class Vec3:
    def __init__(self, r, g, b): self.r, self.g, self.b = r, g, b
class Vec4:
    def __init__(self, x, y, z, w): self.x, self.y, self.z, self.w = x, y, z, w

def dot(v1, v2): return v1.x * v2.x + v1.y * v2.y + v1.z * v2.z
def saturate(v): return max(0.0, min(1.0, v))
def lerp(a, b, t): return a + (b - a) * t
def decompress_half_float(half_val): return half_val  # Conceptual decompression
DISCARD_PRIMITIVE = object()
DISCARD_FRAGMENT = object()
SELECTED_COLOR = Vec3(1.0, 0.0, 1.0)  # Magenta

def vertex_shader(instance_id, order_buffer, splat_view_data, screen_params, splat_bits_valid, splat_selected_bits):
    inst_id = order_buffer[instance_id]
    view = splat_view_data[inst_id]
    if view.center_clip_pos.w <= 0:
        return DISCARD_PRIMITIVE
    o_col = decompress_half_float(view.color)
    quad_x = instance_id & 1
    quad_y = (instance_id >> 1) & 1
    quad_pos = Vec2(quad_x, quad_y) * 2.0 - 1.0
    quad_pos = Vec2(quad_pos.x * 2.0, quad_pos.y * 2.0)
    delta = Vec2((quad_pos.x * view.axis1.x + quad_pos.y * view.axis2.x) * 2.0 / screen_params.x,
                 (quad_pos.x * view.axis1.y + quad_pos.y * view.axis2.y) * 2.0 / screen_params.y)
    o_vertex = Vec2(view.center_clip_pos.x + delta.x * view.center_clip_pos.w,
                    view.center_clip_pos.y + delta.y * view.center_clip_pos.w)
    if splat_bits_valid:
        word_idx = inst_id // 32
        bit_idx = inst_id & 31
        sel_val = splat_selected_bits.Load(word_idx * 4)
        if (sel_val & (1 << bit_idx)):
            o_col.a = -1.0
    return {'vertex': o_vertex, 'color': o_col, 'pos': view.pos}

def fragment_shader(input_data):
    power = -dot(input_data['pos'], input_data['pos'])
    alpha = math.exp(power)
    if input_data['color'].a >= 0:
        alpha = saturate(alpha * input_data['color'].a)
    else:
        if alpha > 7.0 / 255.0:
            if alpha < 10.0 / 255.0:
                alpha = 1.0
                rgb = SELECTED_COLOR
            else:
                alpha = saturate(alpha + 0.3)
                rgb = lerp(input_data['color'].rgb, SELECTED_COLOR, 0.5)
        else:
            rgb = input_data['color'].rgb
    if alpha < 1.0 / 255.0:
        raise DISCARD_FRAGMENT
    return Vec4(rgb.r * alpha, rgb.g * alpha, rgb.b * alpha, alpha)
```

## Subtopics

### [WebGL Gaussian Splatting](2084-webgl-gaussian-splatting.md)
WebGL Gaussian Splatting is a real-time rendering technique for 3D Gaussian Splatting (3DGS) scenes in web browsers, typically implemented using WebGL 1.0 and libraries like Three.js. It solves the problem of displaying large-scale, photorealistic radiance field reconstructions on standard client hardware without requiring neural network inference or heavy server-side processing. Unlike parent method [Gaussian Splat Rendering (Screen-Space Quad)](2075-gaussian-splat-rendering-screen-space-quad.md), which relies on a pre-sorted order buffer and view-space projection data, this method performs depth sorting in a JavaScript Web Worker and projects 3D Gaussians into screen-space quads using custom vertex and fragment shaders. It sets itself apart from sibling [Gaussian Splat Fragment Shader](3258-gaussian-splat-fragment-shader.md) by providing the complete pipeline, including data parsing, instance matrix construction, and CPU-side sorting, rather than just the shading logic.

### [Gaussian Splat Fragment Shader](3258-gaussian-splat-fragment-shader.md)
The Gaussian Splat Fragment Shader evaluates the 2D Gaussian alpha value at each fragment to determine splat coverage and modulates the fragment color accordingly. It composites the new splat over the existing framebuffer color using pre-multiplied alpha blending. It is distinguished from its parent method by handling the per-pixel transparency logic, alpha cutoffs, and framebuffer packing directly in the fragment stage, rather than relying on CPU-side sorting or generic quad rasterization [G].

### Debug Splat Point Rendering
Debug Splat Point Rendering renders small quads at the center of each splat for debugging, optionally displaying the splat index as color [S2, unofficial]. The vertex shader loads splat data, transforms the center to world and clip space, and applies a small offset in screen space based on `_SplatSize` and `_ScreenParams.xy` [S2, unofficial]. If `_DisplayIndex` is true, the splat index is encoded into the RGB color channels for visualization [S2, unofficial].

### Gaussian Splat Shader Property Configuration
Gaussian Splat Shader Property Configuration configures the material property block with splat count, SH degree, brightness, scale, antialiasing, transform matrix, and optional skinning/volume lighting data for the GPU render pass [S3, unofficial]. Key parameters include `shDegree` (capped by the asset's `SHBands` property), `brightness` (default 1.0f), and `scaleFactor` (default 1.0f) [S3, unofficial]. A pitfall is that portable shader variants require valid sampled resources even when skinning is disabled; binding null or uninitialized buffers causes shader compilation/runtime errors [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of splats, as each splat is processed once in the vertex shader and potentially once in the fragment shader [S2, unofficial].
*   **Memory Complexity:** $O(N)$ for storing the order buffer and view-space projection data [S2, unofficial].
*   **Measured Performance:** Performance is highly dependent on the number of splats and the efficiency of the pre-sorted order buffer [S2, unofficial].
*   **Scaling:** Scales linearly with the number of splats [S2, unofficial].
*   **Strengths:** Simple implementation, efficient use of standard rasterization pipelines, effective frustum culling, and support for selection highlighting [S2, unofficial].
*   **Limitations:** Requires CPU-side sorting, which can be a bottleneck for very large scenes [S2, unofficial].
*   **When to Use:** Ideal for real-time visualization of 3DGS scenes in desktop and mobile applications where simplicity and compatibility are prioritized [S2, unofficial].
*   **When Not to Use:** Not suitable for scenes requiring dynamic, per-frame sorting or complex lighting effects that cannot be captured by the simple Gaussian falloff model [S2, unofficial].

## Background
The method originates from the broader field of 3D Gaussian Splatting, introduced by Kerbl et al. in 2023 [S1, S2, unofficial]. The specific implementation of screen-space quad rendering with pre-sorted order buffers was popularized by open-source projects such as UnityGaussianSplatting [S2, unofficial] and svo_renderer [S1, unofficial]. It is widely used in web-based viewers (e.g., WebGL Gaussian Splatting) and desktop applications (e.g., UnitySplats) for real-time visualization of photorealistic 3D reconstructions [S1, S3, unofficial].
