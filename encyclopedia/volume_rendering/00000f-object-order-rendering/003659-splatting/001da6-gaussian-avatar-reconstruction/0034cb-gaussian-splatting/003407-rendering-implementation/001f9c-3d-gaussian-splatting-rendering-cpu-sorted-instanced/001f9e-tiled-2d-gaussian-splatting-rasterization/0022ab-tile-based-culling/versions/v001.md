# Tile-Based Culling

Also called: StopThePop Tile-Based Culling

## Overview
Tile-Based Culling is a method for computing a precise mapping between 3D Gaussians and image tiles in 3D Gaussian Splatting, designed to cull irrelevant tiles during rasterization [S1]. It improves upon the standard conservative bounding box assignment by computing tight, opacity-aware bounding boxes and iteratively verifying tile intersections [S1]. It is distinguished from [SnugBox](3378-snugbox.md) by its iterative tile examination process, which results in higher runtime costs for the culling phase compared to AccuTile, though it may show marginal downstream performance gains due to undercounting artifacts [S1].

## How it works
**Inputs:** 3D Gaussian parameters (position, covariance, opacity, color); image resolution; tile dimensions (typically 32x32 pixels, inherited from [Tiled 2D Gaussian Splatting Rasterization](2061-tiled-2d-gaussian-splatting-rasterization.md)).
**Outputs:** A list of tile IDs for each Gaussian that require processing.

**Data Structures:**
*   `Gaussian`: Structure containing 3D position $\mathbf{p}$, 3x3 covariance matrix $\mathbf{\Sigma}$, opacity $\alpha$, and color.
*   `Tile`: Identified by integer coordinates $(t_x, t_y)$.
*   `Bounding Box`: Axis-aligned bounding box (AABB) in screen space, defined by min/max coordinates $(x_{min}, y_{min})$ and $(x_{max}, y_{max})$.

**Parameters:**
*   **Padded Alpha Threshold:** A value required to accurately compute bounding boxes and prevent undercounting of Gaussian-to-Tile mappings. The specific value is not provided in the source ablation study [S1]. In the cited implementation, this parameter was omitted, leading to loose bounding boxes and undercounting [S1].

**Steps:**
1.  **Compute Tight Bounding Box:** For each Gaussian, compute a tight, opacity-aware axis-aligned bounding box in screen space. This involves projecting the Gaussian's elliptical extent into 2D and determining the bounds based on opacity [S1].
    *   *Note:* The source indicates that using thresholds in the original code prevents all bounding boxes from being tight [S1].
2.  **Iterative Tile Examination:** For each Gaussian, identify all tiles that intersect with the computed bounding box. Iteratively examine each candidate tile to determine if it should be included in the final mapping [S1].
3.  **Warp-Level Load Balancing:** Accelerate the tile examination process using warp-level load balancing techniques to handle the iterative checks efficiently on the GPU [S1].

**Edge Cases and Pitfalls:**
*   **Undercounting:** Without a padded alpha threshold, the method undercounts Gaussian-to-Tile mappings [S1]. This artificially improves downstream performance (Radix Sort, Identify Tile Ranges, Render) by reducing the number of elements to process, but leads to incorrect rendering if not corrected [S1].
*   **Loose Bounding Boxes:** The use of thresholds in the original code causes not all bounding boxes to be tight, reducing the effectiveness of the culling [S1].

## Subtopics

## Operating characteristics
*   **Time Complexity:** The method involves an iterative examination of candidate tiles for each Gaussian. This results in higher runtime cost for the culling phase (Preprocess and Duplicate with Keys) compared to AccuTile, which does not iterate over all candidate tiles [S1].
*   **Measured Performance:** In ablation studies on the Preprocess and Duplicate with Keys stages, Tile-Based Culling is significantly slower than AccuTile [S1]. However, it slightly outperforms AccuTile in downstream functions (Radix Sort, Identify Tile Ranges, Render) due to undercounting artifacts [S1]. When padded alpha thresholds are introduced to fix undercounting, the downstream advantage disappears, and the culling cost increases further [S1].
*   **Strengths:** Provides a more precise Gaussian-to-Tile mapping than standard conservative bounding box methods [S1].
*   **Limitations:** High computational cost in the culling phase due to iterative tile examination [S1]. Prone to undercounting if parameters are not correctly tuned [S1].
*   **When to use:** When a balance between precision and standard rasterization pipelines is needed, and the overhead of iterative culling is acceptable. Not recommended when maximum culling efficiency is required (use [AccuTile](3378-snugbox.md) instead).

## Background
Tile-Based Culling was introduced in the "StopThePop" paper [S1]. It was designed to improve the efficiency of 3D Gaussian Splatting rasterization by reducing the number of pixels processed per Gaussian through precise tile culling [S1]. The method was ablated against the AccuTile algorithm in the "Speedy-Splat" paper to highlight the trade-offs between iterative culling and sparse primitive processing [S1].
