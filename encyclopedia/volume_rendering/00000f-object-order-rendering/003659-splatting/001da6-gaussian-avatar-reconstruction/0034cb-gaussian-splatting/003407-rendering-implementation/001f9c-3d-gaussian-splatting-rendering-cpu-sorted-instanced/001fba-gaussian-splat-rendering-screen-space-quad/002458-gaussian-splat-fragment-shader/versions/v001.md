# Gaussian Splat Fragment Shader

Also called: 2D Gaussian Splat Fragment Evaluation, Alpha Blending, Gaussian Alpha Cutoff, Over Operator, Pre-multiplied Alpha Blending, Splat Fragment Shader, splat.frag

## Overview
The Gaussian Splat Fragment Shader evaluates the 2D Gaussian probability density function (PDF) at each fragment to determine splat coverage and modulates the fragment color accordingly [S1, S2, unofficial]. It composites the new splat over the existing framebuffer color using pre-multiplied alpha blending [S1, S2, unofficial]. It is distinguished from its parent method by handling the per-pixel transparency logic, alpha cutoffs, and framebuffer packing directly in the fragment stage, rather than relying on CPU-side sorting or generic quad rasterization [Parent].

## How it works
**Inputs:**
*   `vColor` (`vec4`): RGBA color of the splat. The RGB channels are typically unnormalized or linear, and `a` is the base opacity $\alpha_0$ [S2, unofficial].
*   `vPosition` (`vec2`): Screen-space coordinates relative to the splat center [S2, unofficial].

**Outputs:**
*   `fragColor` (`vec4`): The final pre-multiplied color and alpha to be written to the framebuffer [S2, unofficial].

**Data Structures:**
*   **Framebuffer Pixel:** A 32-bit unsigned integer (`u32`) packed in BGRA format (little-endian byte order) [S1, unofficial].
    *   Bits 0-7: Blue (B)
    *   Bits 8-15: Green (G)
    *   Bits 16-23: Red (R)
    *   Bits 24-31: Alpha (A)
    *   Note: The output of this shader discards the alpha channel in the final packed integer, storing only RGB [S1, unofficial].

**Parameters:**
*   `alpha_cutoff` (`f32`): `1.0/255.0`. Minimum alpha threshold to discard fragments [S1, unofficial].
*   `whitePoint` (`f32`): `0.9`. Used in tone mapping [S2, unofficial].
*   `saturation_scale` (`f32`): `1.2`. Multiplier for saturation adjustment [S2, unofficial].
*   `sharpen_gamma` (`f32`): `1.0/1.05`. Exponent for sharpening [S2, unofficial].

**Steps:**
1.  **Compute Squared Distance:** Calculate the squared Euclidean distance from the splat center using the dot product of the normalized screen-space position vector `vPosition` [S1, S2, unofficial].
    $$ A = -\text{dot}(\mathbf{vPosition}, \mathbf{vPosition}) $$
2.  **Evaluate Gaussian Alpha:** Compute the Gaussian weight using the exponential of the squared distance [S2, unofficial].
    $$ \text{gaussian} = \exp(A) $$
    *Note: This corresponds to the 2D Gaussian PDF $\alpha(u, v) = \alpha_0 \exp\left(-\frac{1}{2}(u^2 + v^2)\right)$ where the factor of $1/2$ is absorbed into the scaling of `vPosition` or handled by the specific implementation's coordinate normalization [S1, unofficial].*
3.  **Edge Smoothing:** Compute a smoothstep factor to soften the cutoff boundary [S2, unofficial].
    $$ \text{edgeSmoothness} = \text{smoothstep}(-4.0, -3.5, A) $$
4.  **Compute Pre-multiplied Color:** Modulate the RGB channels by the Gaussian weight, base opacity, and edge smoothness [S2, unofficial].
    $$ B = \text{gaussian} \times \mathbf{vColor}.a \times \text{edgeSmoothness} $$
    $$ \mathbf{color}_{new} = B \times \mathbf{vColor}.rgb $$
5.  **Tone Mapping and Sharpening (Optional/Implementation Specific):** Some implementations apply post-processing to the new color before blending [S2, unofficial].
    *   **Saturation:** Compute luminance $L = \text{dot}(\mathbf{color}_{new}, [0.2126, 0.7152, 0.0722])$ and mix: $\mathbf{color}_{new} = \text{mix}([L, L, L], \mathbf{color}_{new}, 1.2)$.
    *   **White Point/Tone Mapping:** $\mathbf{color}_{new} = \mathbf{color}_{new} \times \frac{1.0 + \mathbf{color}_{new} / (\text{whitePoint}^2)}{1.0 + \mathbf{color}_{new}}$ with $\text{whitePoint} = 0.9$.
    *   **Sharpening:** $\mathbf{color}_{new} = \mathbf{color}_{new}^{[1.0/1.05, 1.0/1.05, 1.0/1.05]}$.
6.  **Alpha Cutoff:** If $A < -4.0$, discard the fragment [S2, unofficial]. Alternatively, if the computed alpha $B < \text{alpha\_cutoff}$, the fragment may be discarded or treated as fully transparent [S1, unofficial].
7.  **Fetch Existing Framebuffer:** Read the current pixel from the framebuffer as a `u32` [S1, unofficial].
8.  **Unpack Existing Color:** Convert the `u32` BGRA value into a `vec4` of normalized floats [S1, unofficial].
    *   $R_{old} = ((\text{pixel} \gg 16) \ \& \ 0xFF) / 255.0$
    *   $G_{old} = ((\text{pixel} \gg 8) \ \& \ 0xFF) / 255.0$
    *   $B_{old} = (\text{pixel} \ \& \ 0xFF) / 255.0$
    *   $A_{old} = (\text{pixel} \gg 24) \ \& \ 0xFF) / 255.0$
    *   $\mathbf{color}_{old} = [R_{old}, G_{old}, B_{old}, A_{old}]$
9.  **Composite:** Apply the over operator using pre-multiplied alpha blending [S1, S2, unofficial].
    $$ \mathbf{color}_{out} = (1.0 - B) \times \mathbf{color}_{old} + B \times [\mathbf{color}_{new}, 1.0] $$
    *Note: The alpha of the new fragment is $B$. The RGB of the new fragment is $\mathbf{color}_{new}$. The existing framebuffer alpha $A_{old}$ is typically ignored in the final output packing but used in the blend if the existing color is not pre-multiplied. However, standard pre-multiplied blending assumes the stored RGB is already multiplied by $A_{old}$. If the framebuffer stores straight alpha, the formula differs. The source code suggests standard linear blending of the RGB components weighted by alpha [S1, unofficial].*
    Correct pre-multiplied blend for output RGB:
    $$ \mathbf{RGB}_{out} = (1.0 - B) \times \mathbf{RGB}_{old} + \mathbf{RGB}_{new} $$
    $$ \alpha_{out} = B + A_{old} \times (1.0 - B) $$
    *However, the source [S1, unofficial] code snippet shows:*
    `let blended_color = (1.0 - alpha) * old_color + alpha * new_color;`
    This implies `old_color` and `new_color` are treated as pre-multiplied vectors.
10. **Pack Output:** Quantize the resulting RGB channels to 8-bit integers and pack them into a `u32` BGRA format. The alpha channel is discarded in the final integer value [S1, unofficial].
    *   $R = \text{clamp}(\mathbf{RGB}_{out}.r \times 255.0, 0, 255)$
    *   $G = \text{clamp}(\mathbf{RGB}_{out}.g \times 255.0, 0, 255)$
    *   $B = \text{clamp}(\mathbf{RGB}_{out}.b \times 255.0, 0, 255)$
    *   $\text{output\_pixel} = (R \ll 16) | (G \ll 8) | B$

**Pseudocode:**
```python
# Inputs: vColor (vec4), vPosition (vec2)
# Outputs: fragColor (vec4) - though final framebuffer write is u32 BGRA

def gaussian_splat_fragment_shader(vColor, vPosition, framebuffer_pixel_u32):
    # 1. Compute squared distance (negative)
    A = -dot(vPosition, vPosition)
    
    # 2. Evaluate Gaussian
    gaussian = exp(A)
    
    # 3. Edge smoothing
    edgeSmoothness = smoothstep(-4.0, -3.5, A)
    
    # 4. Compute pre-multiplied color components
    B = gaussian * vColor.a * edgeSmoothness
    
    # 5. Apply tone mapping and sharpening (if implemented in shader)
    color_new_rgb = B * vColor.rgb
    
    # Saturation adjustment
    luminance = dot(color_new_rgb, vec3(0.2126, 0.7152, 0.0722))
    color_new_rgb = mix(vec3(luminance), color_new_rgb, 1.2)
    
    # White point / Tone mapping
    whitePoint = 0.9
    color_new_rgb = color_new_rgb * (1.0 + color_new_rgb / (whitePoint * whitePoint)) / (1.0 + color_new_rgb)
    
    # Sharpening
    color_new_rgb = pow(color_new_rgb, vec3(1.0 / 1.05))
    
    # 6. Alpha cutoff
    if A < -4.0:
        discard_fragment()
        
    # 7. Fetch and unpack existing framebuffer pixel (BGRA u32)
    old_r = ((framebuffer_pixel_u32 >> 16) & 0xFF) / 255.0
    old_g = ((framebuffer_pixel_u32 >> 8) & 0xFF) / 255.0
    old_b = (framebuffer_pixel_u32 & 0xFF) / 255.0
    old_a = ((framebuffer_pixel_u32 >> 24) & 0xFF) / 255.0
    
    old_color = vec4(old_r, old_g, old_b, old_a)
    
    # 8. Composite using over operator (pre-multiplied)
    # Note: old_color.rgb is assumed to be pre-multiplied by old_a in the framebuffer
    # new_color.rgb is pre-multiplied by B
    blended_rgb = (1.0 - B) * old_color.rgb + color_new_rgb
    
    # 9. Return pre-multiplied color for fragment shader output
    # The alpha B is used for blending, but the final framebuffer write discards alpha
    return vec4(blended_rgb, B)
```

## Operating characteristics
*   **Time Complexity:** $O(1)$ per fragment. The computation involves a few arithmetic operations, an exponential, and a texture fetch (if reading the framebuffer directly, though typically this is done via a render-to-texture or direct framebuffer access).
*   **Memory Complexity:** $O(1)$ per fragment. No additional memory is required beyond the framebuffer.
*   **Performance:** Highly efficient on modern GPUs due to the simplicity of the fragment shader. The use of `smoothstep` and early discards helps cull transparent fragments.
*   **Strengths:** Simple to implement, low overhead, handles transparency correctly via pre-multiplied alpha.
*   **Limitations:** The alpha cutoff and edge smoothing parameters are hardcoded or require tuning. The tone mapping and sharpening steps are implementation-specific and may not be present in all versions [S2, unofficial]. The framebuffer format (BGRA) must be supported by the hardware.

## Background
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1, S2, unofficial]. The rendering pipeline typically involves projecting 3D Gaussians to 2D, sorting them, and then rasterizing them as screen-space quads. The fragment shader is a critical component of this rasterization step, handling the per-pixel evaluation of the Gaussian function and the blending with the existing scene. The specific implementation details, such as the use of `smoothstep` for edge smoothing and the specific tone mapping parameters, are found in community implementations like `thomasantony/splat` and `liaozhangsheng/gsplat-opengl` [S1, S2, unofficial].
