# EWA Splatting

Also called: EWA Volume Splatting, Elliptical Weighted Average (EWA) Splatting, Elliptical Weighted Average Volume Splatting, Zwicker EWA Volume Splatting, Zwicker EWA splatting

## Overview
EWA Splatting is a high-quality volume rendering technique that eliminates aliasing artifacts in splat-based rendering by replacing the standard footprint function with a band-limited resampling filter [S1, unofficial][S2][S8, S10, unofficial]. It solves the problem of visual artifacts caused by incorrect visibility determination and sampling rate mismatches in perspective projections, which occur because standard splatting assumes non-overlapping kernels [S1, S8, S15, unofficial]. Unlike basic splatting or methods that use uniform scaling, EWA Splatting handles arbitrary elliptical kernels without excessive blurring by combining an elliptical Gaussian reconstruction kernel with a Gaussian low-pass filter [S2][S5, S8, S15, unofficial]. It builds on [Splatting](23-splatting.md) by introducing a mathematically derived 2D footprint that accounts for perspective distortion and Nyquist frequency limits.

## How it works
**Inputs and Outputs:**
*   **Input:** Volume data represented as a set of particles (voxels), each defined by a position $\mathbf{p}_k$, a scalar density/extinction coefficient $g_k$, and a 3D elliptical Gaussian reconstruction kernel with variance matrix $\mathbf{V}_k$ [S6, S8, unofficial][S11].
*   **Output:** A 2D image where each pixel color is the result of compositing the projected splats [S6, S8, unofficial][S11].

**Data Structures:**
*   **Particle $k$:**
    *   $\mathbf{p}_k$: 3D position in object space.
    *   $g_k$: Extinction coefficient (density).
    *   $\mathbf{V}_k$: $3 \times 3$ symmetric positive-definite variance matrix defining the shape and orientation of the 3D Gaussian kernel in object space [S6, S8, unofficial][S11].
    *   $\mathbf{c}_{\lambda k}$: Emission coefficient (color) at wavelength $\lambda$, assumed constant within the kernel support [S8, unofficial].
*   **Resampling Filter $\rho_k$:**
    *   Defined in screen space coordinates $\hat{\mathbf{x}} = (x_0, x_1)^T$.
    *   A 2D Gaussian function parameterized by a mean $\mathbf{x}_k$ (projected center) and a $2 \times 2$ covariance matrix derived from the transformed 3D kernel and the low-pass filter [S6, S8, unofficial][S11].

**Numbered Steps:**

1.  **Interpret Volume Data:** Treat the volume as a set of absorbing and emitting particles [S6, unofficial][S11].
2.  **Transform to Camera Space:** Apply the viewing transformation to map object coordinates to camera coordinates $\mathbf{u}_k = (u_{k_0}, u_{k_1}, u_{k_2})^T$. The camera origin is at the center of projection, and the image plane is at $u_2 = 1$ [S6, S8, unofficial][S11].
3.  **Compute Jacobian:** Calculate the Jacobian matrix $\mathbf{J}_{\mathbf{u}_k}$ of the perspective projection at point $\mathbf{u}_k$. This matrix linearly approximates the nonlinear perspective transformation [S6, S8, unofficial][S11]:
    $$ \mathbf{J}_{\mathbf{u}_k} = \begin{pmatrix} \frac{1}{u_{k_2}} & 0 & -\frac{u_{k_0}}{u_{k_2}^2} \\ 0 & \frac{1}{u_{k_2}} & -\frac{u_{k_1}}{u_{k_2}^2} \\ \frac{u_{k_0}}{\|\mathbf{u}_k\|} & \frac{u_{k_1}}{\|\mathbf{u}_k\|} & \frac{u_{k_2}}{\|\mathbf{u}_k\|} \end{pmatrix} $$
    where $\|\mathbf{u}_k\|$ is the Euclidean norm of $\mathbf{u}_k$ [S6, S8, unofficial][S11].
4.  **Transform Kernel to Image Space:** Transform the 3D variance matrix $\mathbf{V}_k$ from object space to image space using the rotational part of the viewing transformation $\mathbf{W}$ and the Jacobian $\mathbf{J}_{\mathbf{u}_k}$:
    $$ \mathbf{V}_k^{\text{img}} = \mathbf{J}_{\mathbf{u}_k} \mathbf{W} \mathbf{V}_k \mathbf{W}^T \mathbf{J}_{\mathbf{u}_k}^T $$
    [S6, S8, unofficial][S11].
5.  **Derive 2D Variance:** Obtain the $2 \times 2$ variance matrix $\hat{\mathbf{V}}_k$ by skipping the third row and column of $\mathbf{V}_k^{\text{img}}$ [S6, S8, unofficial][S11].
6.  **Setup Resampling Filter:** Combine the transformed kernel variance with the low-pass filter variance $\mathbf{V}_h$ (typically the $2 \times 2$ identity matrix) to compute the inverse covariance matrix $\mathbf{M}_k$ for the 2D footprint:
    $$ \mathbf{M}_k = (\hat{\mathbf{V}}_k + \mathbf{V}_h)^{-1} $$
    [S6, S8, unofficial][S11].
7.  **Project Center:** Project the camera-space center $\mathbf{u}_k$ to screen coordinates $\hat{\mathbf{x}}_k$ by performing perspective division on the first two components (assuming image plane at $u_2=1$, $\hat{\mathbf{x}}_k = (u_{k_0}/u_{k_2}, u_{k_1}/u_{k_2})^T$) [S6, S8, unofficial][S11].
8.  **Rasterize Footprint:** Rasterize the 2D Gaussian footprint $\rho_k(\hat{\mathbf{x}})$ over the screen. The footprint function is:
    $$ \rho_k(\hat{\mathbf{x}}) = \frac{1}{2\pi |\mathbf{J}_{\mathbf{u}_k}^{-1}| |\mathbf{W}^{-1}| |\hat{\mathbf{V}}_k + \mathbf{V}_h|^{\frac{1}{2}}} e^{-\frac{1}{2} (\hat{\mathbf{x}} - \hat{\mathbf{x}}_k)^T \mathbf{M}_k (\hat{\mathbf{x}} - \hat{\mathbf{x}}_k)} $$
    [S6, S8, unofficial][S11].
    *Note: The normalization factor includes determinants of the Jacobian and viewing rotation to preserve energy [S6, S8, unofficial][S11].*
9.  **Composite:** Accumulate the contributions of all splats back-to-front to compute the final image intensity [S6, S8, unofficial][S11].

**Pseudocode:**

```python
import math
import numpy as np

def ewa_splatting(volume_particles, view_matrix, projection_matrix, image_width, image_height):
    """
    Renders volume particles using EWA Splatting.
    
    Args:
        volume_particles: List of dicts with keys 'p' (3D pos), 'g' (density), 
                          'V' (3x3 variance matrix), 'c' (color).
        view_matrix: 4x4 Model-View matrix.
        projection_matrix: 4x4 Projection matrix.
        image_width, image_height: Output image dimensions.
        
    Returns:
        image: 2D array of color values.
    """
    image = np.zeros((image_height, image_width, 3))
    
    # Extract rotational part W (3x3) from view matrix
    # Assuming standard OpenGL column-major or similar, adjust indexing as needed
    W = view_matrix[:3, :3]
    
    # Precompute inverse determinants for normalization if constant, 
    # but here we compute per-particle as per formula requirements.
    
    for particle in volume_particles:
        p_obj = np.array(particle['p'])
        g = particle['g']
        V_obj = np.array(particle['V'])
        c = np.array(particle['c'])
        
        # 1. Transform to Camera Space
        # Homogeneous coordinate
        p_obj_h = np.append(p_obj, 1.0)
        p_cam_h = view_matrix @ p_obj_h
        u = p_cam_h[:3] # u = (u0, u1, u2)
        
        # Check if behind camera
        if u[2] <= 0:
            continue
            
        # 2. Compute Jacobian J_u
        u_norm = np.linalg.norm(u)
        u2 = u[2]
        J = np.array([
            [1.0/u2, 0, -u[0]/(u2**2)],
            [0, 1.0/u2, -u[1]/(u2**2)],
            [u[0]/u_norm, u[1]/u_norm, u[2]/u_norm]
        ])
        
        # 3. Transform Variance Matrix to Image Space
        # V_img = J * W * V_obj * W^T * J^T
        V_img = J @ (W @ (V_obj @ W.T)) @ J.T
        
        # 4. Extract 2x2 Variance Matrix V_hat
        # Skip third row and column
        V_hat = V_img[:2, :2]
        
        # 5. Setup Low-Pass Filter Variance V_h (Identity)
        V_h = np.eye(2)
        
        # 6. Compute M_k = (V_hat + V_h)^-1
        V_sum = V_hat + V_h
        try:
            M_k = np.linalg.inv(V_sum)
        except np.linalg.LinAlgError:
            continue # Singular matrix
            
        # 7. Project Center to Screen
        # Assuming standard perspective division for screen coords relative to center
        # Note: The formula uses image space coordinates x. 
        # In the derivation, x is often normalized or mapped to the image plane u2=1.
        # For rasterization, we map to pixel coordinates.
        # Let's assume the formula's x is in the same scale as the image plane u2=1.
        # To map to pixels, we need viewport transform. 
        # For simplicity, assuming normalized device coordinates or direct mapping 
        # as per the analytic derivation context. 
        # Standard implementation maps u to screen pixels.
        
        # Perspective division
        x_screen = u[:2] / u[2]
        
        # Map to pixel coordinates (assuming center of projection maps to center of image)
        # This step depends on specific viewport setup. 
        # The formula assumes x is in the coordinate system of the image plane.
        # We will rasterize based on the extent in this coordinate system.
        
        # 8. Compute Normalization Factor
        # Det(J^-1) = 1/Det(J)
        det_J = np.linalg.det(J)
        det_W_inv = 1.0 / np.linalg.det(W) # Assuming W is rotation, det is 1, but keeping for generality
        det_V_sum = np.linalg.det(V_sum)
        
        norm_factor = 1.0 / (2.0 * math.pi * abs(det_J) * abs(det_W_inv) * math.sqrt(det_V_sum))
        
        # 9. Rasterize Footprint
        # Determine bounding box of the ellipse in screen space
        # The ellipse is defined by (x - x_screen)^T M_k (x - x_screen) <= r^2
        # Truncate at r=3 (typical cutoff)
        cutoff = 3.0
        
        # Get eigenvalues/vectors to find extent
        eigenvalues, eigenvectors = np.linalg.eigh(M_k)
        # Major axis length squared is cutoff^2 / min_eigenvalue
        # Minor axis length squared is cutoff^2 / max_eigenvalue
        if eigenvalues[0] <= 0 or eigenvalues[1] <= 0:
            continue
            
        radius_major = math.sqrt(cutoff / eigenvalues[0])
        radius_minor = math.sqrt(cutoff / eigenvalues[1])
        
        # Approximate bounding box in screen space
        # Convert screen space coords to pixel coords roughly
        # This is a simplification; real implementation uses viewport transform
        # Assuming 1 unit in screen space = 1 pixel for this pseudocode structure
        # or that x_screen is already in pixel coordinates relative to center.
        
        min_x = int(math.floor(x_screen[0] - radius_major))
        max_x = int(math.ceil(x_screen[0] + radius_major))
        min_y = int(math.floor(x_screen[1] - radius_minor))
        max_y = int(math.ceil(x_screen[1] + radius_minor))
        
        # Clip to image bounds
        min_x = max(0, min_x)
        max_x = min(image_width, max_x)
        min_y = max(0, min_y)
        max_y = min(image_height, max_y)
        
        for y in range(min_y, max_y):
            for x in range(min_x, max_x):
                # Vector from center
                delta = np.array([x - x_screen[0], y - x_screen[1]])
                
                # Evaluate Gaussian
                exponent = -0.5 * delta @ M_k @ delta
                
                if exponent > cutoff**2:
                    continue
                    
                weight = norm_factor * math.exp(exponent)
                
                # Accumulate
                # Note: True EWA compositing requires back-to-front sorting and alpha blending
                # This pseudocode assumes additive accumulation for simplicity of structure,
                # or that the caller handles the compositing order.
                # For correct volume rendering:
                # alpha = 1 - exp(-g * weight)
                # color = c * alpha
                # However, the formula rho_k is the footprint function q_k convolved with h.
                # The intensity contribution is c * g * rho_k.
                
                # Simple additive accumulation for demonstration of footprint application
                image[y, x] += c * g * weight
                
    return image
```

**Parameters:**
*   **Cutoff radius $r$:** The Gaussian kernel is truncated where $(\mathbf{t} - \mathbf{p})^T \mathbf{V}^{-1} (\mathbf{t} - \mathbf{p}) \leq r^2$. Typical values are $1 \leq r \leq 3$ [S6, unofficial][S11].
*   **Low-pass filter variance $\mathbf{V}_h$:** Usually chosen as the $2 \times 2$ identity matrix [S6, unofficial][S11].
*   **Assumptions:**
    *   Reconstruction kernels have local support and do not overlap along a ray [S8, unofficial].
    *   Emission coefficient is constant in the support of each footprint function [S8, unofficial].
    *   Attenuation factor is approximately constant in the support of each footprint function [S8, unofficial].
    *   Self-occlusion is ignored [S8, unofficial].

**Edge Cases and Pitfalls:**
*   **Aliasing:** Occurs if reconstruction kernels are assumed non-overlapping but must overlap to avoid artifacts [S1, S8, S15, unofficial].
*   **Numerical Stability:** The centralized conics approach can be numerically unstable when the projection approaches a line because the condition number of the inverse 2D-to-2D projective mapping increases rapidly [S12, unofficial].
*   **Non-symmetric Kernels:** If 3D reconstruction kernels are not radially symmetric (e.g., sheared, anisotropic), additional care is required to ensure contributions sum up correctly [S9, unofficial].
*   **Notation:** A matrix with a hat symbol ($\hat{\mathbf{V}}$) denotes the result of skipping its third row and column [S6, unofficial][S11].

## Subtopics

### [Deferred Surface Splatting](1072-deferred-surface-splatting.md)
Deferred Surface Splatting is a rendering technique that converts unstructured point clouds into continuous, shaded surfaces by projecting points as splats into a deferred rendering pipeline. It solves sparse dot cloud aliasing and transparency artifacts by assigning each point sample an extent drawn as a small oriented primitive (a splat) carrying a radially decreasing reconstruction kernel. It differs from its parent [EWA Splatting](1069-ewa-splatting.md) by using screen-aligned spherical impostors with isotropic linear falloff rather than anisotropic, correctly band-limited EWA footprints, trading accurate filtering for a formulation that requires no per-point normals or radii. It differs from siblings like [Phong Splatting](2802-phong-splatting.md) by deferring the lighting calculation to a final screen-space pass, allowing multiple light sources to be applied efficiently without re-projecting geometry [G].

### [Opacity-Thin-Side (OTS)](1155-opacity-thin-side-ots.md)
Opacity-Thin-Side (OTS) is a parameterization scheme for EWA-based splatting that ensures robust gradient-descent optimization by dynamically scaling the learned weight $\theta$ such that the projected amplitude $a'$ equals $\theta$ when viewing the Gaussian along its thinnest side (shortest axis). It differs from standard EWA splatting, which preserves the integral of extinction (mass), and 3D Gaussian Splatting (3DGS), which preserves the 2D projected amplitude regardless of view, by preserving the 3D unbounded integral (view-independent mass) while ensuring the 2D projection behaves as an ordinary integral relative to the thinnest view.

### [OTS (EWA-Based Splatting)](1181-ots-ewa-based-splatting.md)
OTS (Opacity-Thin-Side) is a splatting method using unnormalized Gaussians that preserves the 2D amplitude $a'$ (called 'opacity') across projections, unlike EWA Splatting which preserves the weight $w$. It differs from standard EWA Splatting by requiring a Jacobian determinant correction to preserve the integral of the extinction coefficient under perspective projection.

### [GPU-Accelerated Volume Splatting With Elliptical RBFs](1186-gpu-accelerated-volume-splatting-with-elliptical-rbfs.md)
This method renders scattered volumetric data represented as 3D ellipsoidal Radial Basis Functions (RBFs) using a post-shaded, kernel-centric approach. It extends high-quality image-aligned sheet-buffer splatting to irregular grids by slicing kernels into parallel, image-aligned density planes, rasterizing them as 2D footprints, and compositing them. Unlike fragment-centric methods that evaluate Gaussian functions per pixel, this technique leverages hard-wired GPU polygonal rasterization, achieving two orders of magnitude higher frame rates. It differs from its parent [EWA Splatting](1069-ewa-splatting.md) by supporting general ellipsoidal kernels and using a flat spatial decomposition with active cell lists rather than screen-aligned spherical impostors.

### [Ellipsoidal Kernel Splatting with Warped Slicing](1290-ellipsoidal-kernel-splatting-with-warped-slicing.md)
Ellipsoidal Kernel Splatting with Warped Slicing is a volume rendering technique that represents point samples as 3D ellipsoids and rasterizes them by slicing the ellipsoid into 2D polygons. It solves the problem of efficiently computing the intersection of general ellipsoids with screen-aligned slicing planes on GPU hardware, where direct analytical slicing requires expensive square roots and conditional statements. The method warps the slicing planes from screen space into the coordinate system of a unit sphere, allowing the use of hard-wired GPU texture mapping and blending on radially symmetric kernel slices. It differs from its parent [EWA Splatting](1069-ewa-splatting.md) by explicitly slicing the kernel into discrete polygons for incremental rasterization rather than rasterizing the entire projected footprint, and it avoids the pre-integrated slab approach of earlier image-aligned splatting by using point-sampled slices.

### [Perspective Correct Splat Rasterization with EWA Approximation](2095-perspective-correct-splat-rasterization-with-ewa-approximati.md)
This method is an improved splat rendering pipeline that combines a perspectively correct fast splat rasterization procedure with an approximation of the Elliptical Weighted Average (EWA) filter. It solves the problem of aliasing artifacts and visual holes in point-sampled geometry rendering, particularly when the model is viewed from flat angles or shifted from the viewing axis. Unlike its siblings, it uses an affine approximation to the projective mapping to ensure perspective-correct splat shapes without requiring per-point normals or complex anisotropic footprint calculations, trading exact band-limited footprints for a formulation that avoids holes and Moiré patterns. It builds on [EWA Splatting](1069-ewa-splatting.md) by replacing the standard EWA covariance computation with a faster, perspective-correct affine approximation.

### [Adaptive EWA Volume Splatting](2137-adaptive-ewa-volume-splatting.md)
Adaptive EWA Volume Splatting is a rendering technique that simplifies the computationally expensive Elliptical Weighted Average (EWA) resampling filter by classifying volume particles into three cases based on their distance from the viewpoint. It solves the problem of high computational cost in full EWA splatting while maintaining aliasing-free quality. Unlike full EWA splatting, which always computes the combined covariance of the reconstruction and low-pass filters, this method uses only the reconstruction filter for close particles (magnification) and only the low-pass filter for far particles (minification), resorting to full EWA only in the transition zone.

### [EWA Approximation with Tangent Vector Adjustment](2143-ewa-approximation-with-tangent-vector-adjustment.md)
A high-quality filtering technique for point-based rendering that approximates the EWA resampling filter by dynamically adjusting the tangent vectors of isotropic splats during setup to prevent aliasing during minification, without requiring expensive per-fragment convolution. It sets itself apart from the original EWA framework by using projective mapping and tangent adjustment rather than affine mapping and Gaussians for both reconstruction and low-pass filters, and from Botsch et al. [BHZK05] by avoiding per-fragment filter evaluation, thus eliminating the fragment shader bottleneck.

### [Phong Splatting](2802-phong-splatting.md)
Phong Splatting is a surface splatting technique that assigns a linearly varying normal field to each elliptical splat, enabling per-pixel Phong shading without surface connectivity. It solves the piecewise constant shading artifacts of standard point-based rendering by providing smooth, Phong-like shading quality on modern GPUs. Unlike its sibling [EWA Splatting](1069-ewa-splatting.md), which uses a simplified isotropic kernel, Phong Splatting uses elliptical splats with projectively correct per-pixel parameterization, trading the simplicity of isotropic filtering for superior visual quality and exact depth values.

### [EWA Splatting Renderer (Mesh-Free)](4665-ewa-splatting-renderer-mesh-free.md)
A mesh-free rendering pipeline that projects raw point clouds directly to 2D camera views using EWA projection and Z-buffer occlusion, producing RGB images, label maps, and 2D-to-3D index maps without mesh reconstruction. It differs from its parent [EWA Splatting](1069-ewa-splatting.md) by using simplified screen-aligned spherical impostors with isotropic linear falloff, trading anisotropic, correctly band-limited footprints for a formulation that requires no per-point normals or radii.

### [EWA Splatting with kNN Covariance Estimation](4690-ewa-splatting-with-knn-covariance-estimation.md)
A rendering method that uses per-point 3D covariance estimated from k-nearest neighbours to project an elliptical weighted average (EWA) shape onto the 2D image plane for denser coverage than simple disk splatting. It works directly on raw point clouds without mesh reconstruction, addressing the need for high-quality, dense point-cloud rendering in multi-view pipelines.

## Operating characteristics
*   **Time Complexity:** The computation of the EWA footprint is expensive due to the matrix inversions and determinant calculations required for each particle [S6, unofficial][S11]. Adaptive EWA splatting reduces this cost by simplifying the filter for distant particles [S6, unofficial][S11].
*   **Memory Complexity:** Requires storage for the variance matrices and footprint tables. The use of a 1D footprint table for rasterization via forward differencing helps reduce memory bandwidth [S7, abstract only, unofficial][S8, unofficial].
*   **Measured Performance:** Original implementations on an 866 MHz Pentium-III took approximately 11 seconds per frame for datasets like the UNC CT scan of a human head or an engine [S1, S8, S10, unofficial]. Hardware-accelerated versions achieve interactive frame rates [S6, S9, unofficial].
*   **Strengths:** Provides high-quality antialiasing without excessive blurring, handles arbitrary elliptical kernels, and supports perspective projection efficiently [S2][S5, S8, S15, unofficial].
*   **Limitations:** Computationally intensive compared to basic splatting; assumes non-overlapping kernels which can lead to visibility artifacts if not handled correctly [S1, S8, S15, unofficial].
*   **When to Use:** When high-quality, alias-free volume rendering is required, especially with non-spherical kernels or perspective projections.
*   **When Not to Use:** When real-time performance is critical and basic splatting quality is sufficient, or when hardware acceleration for EWA filters is not available.

## Background
EWA Splatting was introduced by Matthias Zwicker, Hanspeter Pfister, Jeroen van Baar, and Markus Gross in 2001 [S8, unofficial]. It is named after Heckbert's Elliptical Weighted Average (EWA) filter for texture mapping due to the similarity in derivation [S2][S7, abstract only, unofficial][S8, S10, unofficial]. The method was developed to address the aliasing artifacts inherent in earlier splatting techniques, particularly those arising from perspective projections and non-spherical kernels [S2][S8, S15, unofficial]. It has been widely used in high-quality volume rendering and point-based surface rendering [S2][S7, abstract only, unofficial][S8, unofficial].
