# CPU Fallback Sort Path

Also called: CPU-only cutout path, Portable CPU-sort path

## Overview
The CPU Fallback Sort Path provides a CPU-side sorting and rendering fallback for Gaussian splatting when GPU compute sorting is disabled or unavailable [S1, unofficial]. It differs from GPU-based approaches by utilizing a shader-readable structured buffer instead of append/unordered access view (UAV) buffers, allowing the CPU to manage the sorting pipeline while the GPU focuses on rendering [S1, unofficial]. This method is chosen when GPU compute capabilities are insufficient or when avoiding the overhead of GPU sorting algorithms like bitonic sort is necessary [S1, unofficial].

## How it works
**Inputs:**
- `GsplatSorter.Instance.CpuFallbackEnabled`: A boolean flag determining the active path.
- Splat data (centroids, colors, opacities, scales) to be sorted.

**Outputs:**
- `OrderBuffer`: A `GraphicsBuffer` containing the sorted order of splats, readable by shaders.
- `OrderSizeBuffer`: (Optional) An indirect argument buffer storing the number of sorted splats.
- `BoundsBuffer`: (Optional) A structured buffer storing bounding box information.

**Data Structures:**
1.  **`OrderBuffer`**:
    -   Type: `GraphicsBuffer.Target.Structured` (if CPU fallback enabled) or `GraphicsBuffer.Target.Append` (if disabled).
    -   Content: Indices or identifiers of splats in sorted order.
2.  **`OrderSizeBuffer`**:
    -   Type: `GraphicsBuffer.Target.IndirectArguments`.
    -   Size: 1 element.
    -   Content: The count of splats to be rendered/sorted.
3.  **`BoundsBuffer`**:
    -   Type: `GraphicsBuffer.Target.Structured`.
    -   Size: 6 elements (likely representing min/max coordinates for bounding volumes).
    -   Content: Bounding box data for the splats.

**Steps:**
1.  Check the value of `GsplatSorter.Instance.CpuFallbackEnabled`.
2.  If `CpuFallbackEnabled` is `true`:
    a.  Create `OrderBuffer` as `GraphicsBuffer.Target.Structured`.
    b.  Proceed with CPU-side sorting logic (details delegated to specific sorting algorithms like Radix Sort).
3.  If `CpuFallbackEnabled` is `false`:
    a.  Create `OrderBuffer` as `GraphicsBuffer.Target.Append`.
    b.  Allocate `OrderSizeBuffer` as `GraphicsBuffer.Target.IndirectArguments` with size 1.
    c.  Allocate `BoundsBuffer` as `GraphicsBuffer.Target.Structured` with size 6.
    d.  Proceed with the non-fallback (likely GPU-based) sorting path.

**Pseudocode:**
```python
def setup_sort_buffer(cpu_fallback_enabled):
    """
    Sets up the graphics buffers for splat sorting based on the fallback flag.
    """
    # Step 1: Check flag
    is_fallback = cpu_fallback_enabled

    # Step 2 & 3: Create OrderBuffer based on flag
    if is_fallback:
        # CPU fallback enabled: use Structured buffer for shader readability
        order_buffer = create_graphics_buffer(target=GraphicsBuffer.Target.Structured)
    else:
        # CPU fallback disabled: use Append buffer
        order_buffer = create_graphics_buffer(target=GraphicsBuffer.Target.Append)
        
        # Step 4: Allocate additional buffers for non-fallback path
        order_size_buffer = create_graphics_buffer(
            target=GraphicsBuffer.Target.IndirectArguments, 
            size=1
        )
        bounds_buffer = create_graphics_buffer(
            target=GraphicsBuffer.Target.Structured, 
            size=6
        )

    return order_buffer, order_size_buffer, bounds_buffer
```

**Parameters:**
-   `CpuFallbackEnabled`: Boolean flag. `True` activates the CPU fallback path using structured buffers; `False` uses append buffers and allocates size/bounds buffers [S1, unofficial].

-   **Precision:** Not given in the sources.
-   **Boundaries:** The size of `BoundsBuffer` is fixed at 6 elements [S1, unofficial].

## Subtopics

### [CPU Radix Sort for Face Centroids](6216-cpu-radix-sort-for-face-centroids.md)
This method provides a CPU-side fallback for sorting face centroids in volume splatting when GPU compute sorting is unavailable, building on [CPU Fallback Sort Path](5586-cpu-fallback-sort-path.md). It achieves linear time complexity by converting IEEE 754 floating-point numbers to signed integers and performing a Least Significant Digit (LSD) radix sort using counting sort on 8-bit blocks. It is chosen over general-purpose sorts (quicksort, heapsort) or re-sorting-optimized algorithms (mergesort) because viewing direction changes significantly alter centroid ordering, making the overhead of adaptive sorts inefficient compared to the raw speed of radix sort.

## Operating characteristics

-   **Strengths:** Avoids GPU sorting overhead; allows GPU to focus on rendering; portable to systems without GPU compute support [S1, unofficial].
-   **Limitations:** Relies on CPU performance for sorting; may become a bottleneck for large numbers of splats if the CPU is slow [S1, unofficial].
-   **When to use:** When GPU compute sorting is unavailable or disabled; when CPU resources are sufficient for the sorting load [S1, unofficial].
-   **When not to use:** When high performance is required for large-scale splatting and GPU compute is available [S1, unofficial].

## Background
The CPU Fallback Sort Path is part of the UnitySplats project by arloopa, which implements Gaussian Splatting in Unity [S1, unofficial]. It was developed to provide a robust fallback mechanism for environments where GPU compute shaders might not be available or efficient [S1, unofficial].
