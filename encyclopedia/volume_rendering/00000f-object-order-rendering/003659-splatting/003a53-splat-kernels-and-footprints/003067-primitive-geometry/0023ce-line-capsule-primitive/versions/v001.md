# Line Capsule Primitive
Also called: Geometry Primitives and Mesh Shading, Mesh Lighting and Materials

## Overview
The Line Capsule Primitive is a screen-space rendering primitive used in object-order splatting to represent line segments as rotationally symmetric profiles of the 2D point-to-segment distance [S1, unofficial]. It serves as the primary geometric representation for lines in systems that also support points, Gaussian splats, and meshes, offering a visual quality comparable to exact volumetric primitives (closed-form convolution of a segment with a 3D Gaussian) at a significantly lower computational cost [S1, unofficial]. It is distinguished from sibling primitives by its specific handling of joint composition via a deficit rule and its conditional substitution with screen-space quads based on an effective segment load threshold [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A line segment defined by two endpoints in 3D space, projected into screen space.
*   **Output:** A set of fragments contributing to the accumulation buffer, with color and opacity determined by the capsule profile and shading model.

**Data Structures:**
*   **Line Segment:** Defined by two 3D vertices.
*   **Capsule Profile:** A 2D function representing the rotationally symmetric intensity falloff based on the perpendicular distance from the screen-space segment center.
*   **Joint State:** Metadata required to apply the deficit rule at segment endpoints to prevent double-brightness or gaps [S1, unofficial].

**Numbered Steps:**
1.  **Projection:** Transform the 3D line segment endpoints into screen space coordinates $(x_1, y_1)$ and $(x_2, y_2)$ [S1, unofficial].
2.  **Primitive Selection:** Calculate the effective segment load for the current line node. The effective segment load is defined as the authored segment count scaled by the on-screen width of the widest segment at the opening framing [S1, unofficial].
    *   If the effective segment load is less than 2,000,000, select the **Capsule** primitive [S1, unofficial].
    *   If the effective segment load is greater than or equal to 2,000,000, select the **Screen-Space Quad** primitive [S1, unofficial].
    *   *Note:* This policy can be pinned to a specific primitive if required [S1, unofficial].
3.  **Capsule Rendering (if selected):**
    *   For each pixel within the bounding box of the projected segment, calculate the perpendicular distance $d$ from the pixel center to the line segment in screen space [S1, unofficial].
    *   Evaluate the rotationally symmetric profile function $P(d)$ based on $d$ [S1, unofficial].
    *   **Joint Composition:** At segment endpoints (joints), apply a deficit rule to the profile contribution. This ensures that corners do not double their own brightness (overlapping contributions) nor open gaps (missing contributions) [S1, unofficial].
4.  **Quad Rendering (if selected):** Render the line segment as a standard screen-space quadrilateral texture-mapped with opacity [S1, unofficial].
5.  **Shading:**
    *   If the geometry is a mesh, apply shading using a light-free headlight anchored to the view direction [S1, unofficial].
    *   Base color is derived from exactly one source: per-vertex colors, a colormap over per-vertex scalars, or an image texture (optionally GPU-compressed as KTX2/Basis) [S1, unofficial].
    *   If the mesh uses a physically based material (`material="physical"`), compute lighting using roughness, metalness, clearcoat, iridescence, and sheen parameters [S1, unofficial].
    *   If the mesh uses the transmission family (glass), compute refraction using index of refraction, thickness, attenuation, and dispersion, refracting background/meshes/points behind it while keeping data in front crisp [S1, unofficial].
    *   Meshes lit by scene environment use a neutral room (default), equirectangular HDR image, or cube map captured from a probe inside the scene [S1, unofficial].
6.  **Compositing:** Composite the resulting fragments into the accumulation buffer using alpha blending, respecting the front-to-back or back-to-front order as dictated by the parent splatting method [S1, unofficial].

**Formulas:**
*   **Effective Segment Load:**
    $$ L_{eff} = N_{seg} \times W_{max} $$
    Where $N_{seg}$ is the authored segment count and $W_{max}$ is the on-screen width of the widest segment at the opening framing [S1, unofficial].
*   **Primitive Selection Threshold:**
    $$ \text{Use Quad if } L_{eff} \ge 2,000,000 \text{ else Use Capsule} $$
    [S1, unofficial].
*   **Capsule Profile:**
    The intensity is a function of the 2D point-to-segment distance $d$ in screen space, denoted as $P(d)$ [S1, unofficial]. The exact analytic form of $P(d)$ is not specified in the sources, but it is rotationally symmetric [S1, unofficial].

**Parameters:**
*   **Effective Segment Load Threshold:** 2,000,000 [S1, unofficial].
*   **Shading Model:** Light-free headlight anchored to view (default for meshes) [S1, unofficial].
*   **Material Types:** Standard (base color only), Physical (roughness, metalness, clearcoat, iridescence, sheen), Transmission (IOR, thickness, attenuation, dispersion) [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Missing Attributes:** Refuse to render if texture coordinates are missing for image textures, or if dimension names are missing for vertex normals [S1, unofficial].
*   **Volumetric Blending:** Meshes refuse volumetric blending because triangles have zero thickness, providing no path length for absorption [S1, unofficial].
*   **Additive Ladder:** Refuse additive ladder over arbitrary face order because a prefix of such an order is a surface with holes, not a coarser surface [S1, unofficial]. Only spatially coherent reveal ordering yields a presentable prefix [S1, unofficial].
*   **Picking:** Picking resolves to the vertex, not the face [S1, unofficial].
*   **Scene Bounds:** Meshes contribute no size padding to scene bounds [S1, unofficial].

## Subtopics

### Screen-Space Quad
A cheaper alternative to the capsule used when the effective segment load exceeds 2 million. It renders the line as a standard textured quadrilateral [S1, unofficial].

### Mesh Shading
The only shaded geometry type in the system, lit by a light-free headlight. It supports PBR and transmission materials but refuses volumetric blending [S1, unofficial].

### Exact Volumetric Primitive
A closed-form convolution of a segment with a 3D Gaussian. It is visually comparable to the capsule but costs 2.7–5x more than the screen-space quad per frame [S1, unofficial].

## Operating characteristics
*   **Performance:** The capsule primitive is preferred over the exact volumetric primitive because it matched or beat it in blinded visual comparisons (including near-axial cases) while costing significantly less [S1, unofficial].
*   **Comparison:** The performance difference between the capsule and the screen-space quad is 1.04–1.11x on Apple GPUs and approximately 1.5x on thin lines on discrete NVIDIA GPUs [S1, unofficial].
*   **Memory:** Meshes are loaded whole, not through a spatial index, and contribute no size padding to scene bounds [S1, unofficial].
*   **Strengths:** High visual fidelity for lines compared to exact volumetric methods at lower cost; efficient handling of large segment counts via quad substitution; robust shading model for meshes.
*   **Limitations:** Meshes cannot be used for volumetric blending due to zero thickness; additive rendering over arbitrary face order is not supported [S1, unofficial].

## Background
The Line Capsule Primitive is part of the "Geometry primitives and mesh shading" system described in the Luxar viewer for Gaussian splatting microscopy and scalable interactive web visualization of multidimensional scientific data [S1, unofficial]. It was developed to provide efficient and visually accurate line rendering in web-based 3D visualization environments, balancing performance and quality for large-scale scientific data [S1, unofficial].
