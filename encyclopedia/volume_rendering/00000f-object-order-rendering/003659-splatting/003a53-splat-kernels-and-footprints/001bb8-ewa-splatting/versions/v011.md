# EWA Splatting

Also called: EWA Volume Splatting, Elliptical Weighted Average (EWA) Splatting, Elliptical Weighted Average Volume Splatting, Zwicker EWA Volume Splatting, Zwicker EWA splatting

## Overview
EWA Splatting is a high-quality volume rendering technique that eliminates aliasing artifacts in splat-based rendering by replacing the standard footprint function with a band-limited resampling filter [S1, unofficial][S2][S8, S10, S15, unofficial]. It solves the problem of incorrect visibility determination and high-frequency sampling artifacts that occur when reconstruction kernels are assumed to be non-overlapping and sorted strictly back-to-front [S1, S8, unofficial]. Unlike basic splatting, which uses isotropic or simple elliptical footprints, EWA Splatting derives an analytic 2D Gaussian footprint in screen space by combining a 3D elliptical Gaussian reconstruction kernel with a 2D Gaussian low-pass filter, ensuring correct anti-aliasing under perspective projection [S2][S6, S8, S15, unofficial].

## How it works
**Inputs:** Volume data represented as a set of particles (voxels or points), each defined by a position $\mathbf{p}_k$, an extinction/density coefficient $g_k$, an emission color $c_{\lambda k}$, and a 3D elliptical Gaussian reconstruction kernel with variance matrix $\mathbf{V}_k$ in object space. Camera parameters (viewing transformation $\mathbf{W}$, projection matrix).

**Outputs:** A 2D image where each pixel contains the accumulated color and opacity.

**Data Structures:**
*   **Particle:** Struct containing position $\mathbf{p}_k$, variance matrix $\mathbf{V}_k$ (3x3 symmetric), color $c_{\lambda k}$, and extinction $g_k$.
*   **Resampling Filter Parameters:** For each particle, a 2x2 covariance matrix $\mathbf{M}_k^{-1}$ (or its inverse $\mathbf{M}_k$), a 2D mean $\mathbf{x}_k$, and a normalization scalar.
*   **Footprint Table:** A 1D lookup table storing values of the Gaussian exponential function $e^{-r^2/2}$ or similar, used for efficient rasterization [S8, S12, unofficial].

**Steps:**

1.  **Interpretation:** Treat volume data as a set of absorbing and emitting particles [S6, S8, unofficial].
2.  **Transformation to Camera Space:** Transform the particle position $\mathbf{p}_k$ and the variance matrix $\mathbf{V}_k$ from object space to camera space using the viewing transformation. The rotational part of the viewing transformation is denoted by $\mathbf{W}$. The camera space position is $\mathbf{u}_k = (u_{k_0}, u_{k_1}, u_{k_2})^T$, where the origin is the center of projection and the image plane is $u_2 = 1$ [S6, S8, unofficial][S11].
    $$ \mathbf{V}_{k, \text{cam}} = \mathbf{W} \mathbf{V}_k \mathbf{W}^T $$
3.  **Jacobian Calculation:** Compute the Jacobian matrix $\mathbf{J}_{\mathbf{u}_k}$ of the perspective projection at $\mathbf{u}_k$. This matrix linearly approximates the non-linear perspective transformation [S6, S8, unofficial][S11]:
    $$ \mathbf{J}_{\mathbf{u}_k} = \begin{pmatrix} \frac{1}{u_{k_2}} & 0 & -\frac{u_{k_0}}{u_{k_2}^2} \\ 0 & \frac{1}{u_{k_2}} & -\frac{u_{k_1}}{u_{k_2}^2} \\ \frac{u_{k_0}}{\|\mathbf{u}_k\|} & \frac{u_{k_1}}{\|\mathbf{u}_k\|} & \frac{u_{k_2}}{\|\mathbf{u}_k\|} \end{pmatrix} $$
    where $\|\mathbf{u}_k\| = \sqrt{u_{k_0}^2 + u_{k_1}^2 + u_{k_2}^2}$ [S6, S8, unofficial][S11].
4.  **Variance Transformation:** Transform the camera-space variance matrix to image space (ray space) using the Jacobian. Let $\mathbf{V}_k$ denote the full 3x3 variance matrix in image space:
    $$ \mathbf{V}_k = \mathbf{J}_{\mathbf{u}_k} \mathbf{V}_{k, \text{cam}} \mathbf{J}_{\mathbf{u}_k}^T = \mathbf{J}_{\mathbf{u}_k} \mathbf{W} \mathbf{V}_k \mathbf{W}^T \mathbf{J}_{\mathbf{u}_k}^T $$
    Extract the 2x2 submatrix $\hat{\mathbf{V}}_k$ by skipping the third row and column of $\mathbf{V}_k$ [S6, S8, unofficial][S11].
5.  **Resampling Filter Setup:** Define the 2D low-pass filter variance matrix $\mathbf{V}_h$, typically the 2x2 identity matrix $\mathbf{I}$ [S6, unofficial][S11]. Compute the combined covariance matrix for the resampling filter:
    $$ \mathbf{M}_k = (\hat{\mathbf{V}}_k + \mathbf{V}_h)^{-1} $$
    The resampling filter $\rho_k(\mathbf{x})$ is a 2D Gaussian centered at the projected screen position $\mathbf{x}_k$:
    $$ \rho_k(\mathbf{x}) = \frac{1}{2\pi |\mathbf{J}_{\mathbf{u}_k}^{-1}| |\mathbf{W}^{-1}| |\hat{\mathbf{V}}_k + \mathbf{V}_h|^{\frac{1}{2}}} e^{-\frac{1}{2} (\mathbf{x} - \mathbf{x}_k)^T \mathbf{M}_k (\mathbf{x} - \mathbf{x}_k)} $$
    Note: The normalization factor includes determinants of the Jacobian and viewing transformation inverses to preserve energy [S6, S8, unofficial][S11].
6.  **Rasterization:** Rasterize the elliptical footprint $\rho_k(\mathbf{x})$ onto the screen. This is often done by deforming a texture-mapped quadrilateral or using forward differencing with a 1D footprint table [S8, S9, unofficial]. The footprint is truncated at a cutoff radius $r$ (typically $1 \le r \le 3$) [S6, unofficial][S11].
7.  **Compositing:** Accumulate the contributions of all splats into the image buffer. Standard EWA Splatting assumes self-occlusion is ignored or approximated, and composites back-to-front using alpha blending [S8, S15, unofficial]. The intensity for a ray is approximated as:
    $$ I_\lambda(\hat{\mathbf{x}}) \approx \sum_k c_{\lambda k} o_k g_k \rho_k(\hat{\mathbf{x}}) $$
    where $o_k$ is an attenuation factor assumed constant over the footprint [S8, unofficial].

**Pseudocode:**

```python
import numpy as np

def ewa_splatting(particles, camera_matrix, projection_matrix, image_width, image_height):
    """
    Renders volume data using EWA Splatting.
    particles: List of dicts with keys 'pos' (3,), 'V' (3x3), 'color' (3,), 'extinction' (float)
    camera_matrix: 4x4 MVP matrix (or separate view/projection)
    image_width, image_height: int
    """
    image = np.zeros((image_height, image_width, 4)) # RGBA
    
    # Sort particles back-to-front based on camera space Z
    # Note: True EWA handles overlap better, but standard compositing requires order
    # For simplicity, we assume sorting by view-space depth
    particles_sorted = sort_particles_back_to_front(particles, camera_matrix)
    
    for p in particles_sorted:
        # 1. Transform to camera space
        # Assuming camera_matrix includes the view transform
        pos_cam = transform_point(p['pos'], camera_matrix)
        u_k = pos_cam[:3] # (u0, u1, u2)
        
        # 2. Compute Jacobian J
        u2 = u_k[2]
        norm_u = np.linalg.norm(u_k)
        J = np.array([
            [1/u2, 0, -u_k[0]/(u2**2)],
            [0, 1/u2, -u_k[1]/(u2**2)],
            [u_k[0]/norm_u, u_k[1]/norm_u, u_k[2]/norm_u]
        ])
        
        # 3. Transform Variance Matrix
        # W is the rotational part of the view transform (top-left 3x3 of camera_matrix)
        W = camera_matrix[:3, :3]
        V_cam = W @ p['V'] @ W.T
        V_img = J @ V_cam @ J.T
        
        # 4. Extract 2x2 submatrix V_hat
        V_hat = V_img[:2, :2]
        
        # 5. Setup Resampling Filter
        V_h = np.eye(2) # Identity low-pass filter
        M_k_inv = V_hat + V_h
        M_k = np.linalg.inv(M_k_inv)
        
        # 6. Project Center to Screen
        # Perspective division
        x_screen = (u_k[0] / u2, u_k[1] / u2)
        
        # 7. Rasterize Footprint
        # Determine bounding box of the ellipse
        # Eigen decomposition to find extent
        eigenvalues, eigenvectors = np.linalg.eigh(M_k_inv)
        # Cutoff radius r (e.g., 3)
        r = 3.0
        # Extent along principal axes
        extent_x = r * np.sqrt(eigenvalues[0])
        extent_y = r * np.sqrt(eigenvalues[1])
        
        min_x = int(max(0, x_screen[0] - extent_x))
        max_x = int(min(image_width, x_screen[0] + extent_x))
        min_y = int(max(0, x_screen[1] - extent_y))
        max_y = int(min(image_height, x_screen[1] + extent_y))
        
        # Normalization factor
        # |J^-1| |W^-1| |V_hat + V_h|^0.5
        # Note: |J^-1| is 1/|J|. |W^-1| is 1/|W|. Since W is rotation, |W|=1.
        # |J| = 1/u2^2 * norm_u? Let's use the determinant of J.
        det_J = np.linalg.det(J)
        norm_factor = 1.0 / (abs(det_J) * np.sqrt(np.linalg.det(M_k_inv)))
        
        for y in range(min_y, max_y):
            for x in range(min_x, max_x):
                # Vector from center
                dx = x - x_screen[0]
                dy = y - x_screen[1]
                vec = np.array([dx, dy])
                
                # Exponent term
                exponent = -0.5 * vec @ M_k @ vec
                
                if exponent > 0: # Outside cutoff
                    continue
                
                # Evaluate Gaussian
                weight = norm_factor * np.exp(exponent)
                
                # Accumulate
                # Assuming simple alpha blending or additive accumulation for density
                # Standard EWA uses pre-integrated footprints, so direct addition of weighted color/extinction
                # is an approximation if self-occlusion is ignored.
                alpha_contribution = weight * p['extinction']
                
                # Simple additive accumulation for demonstration
                # In practice, use alpha blending: C_out = C_in * (1-a) + C_splat * a
                # Here we assume the footprint rho_k already incorporates the extinction g_k in some formulations,
                # or we multiply here. Based on S8: I approx sum c * o * g * rho.
                
                color = p['color'] * weight * p['extinction']
                
                # Update image (simplified additive for density/color, ignoring alpha complexity for brevity)
                # A full implementation requires proper alpha compositing pass
                image[y, x, :3] += color
                image[y, x, 3] += weight # Accumulate alpha/weight

    return image

def sort_particles_back_to_front(particles, camera_matrix):
    # Transform positions to camera space and sort by Z (u2)
    # Higher u2 is further away in standard OpenGL camera space (looking down -Z) or lower?
    # Assuming standard view: camera at origin, looking down -Z. 
    # But EWA notes say u2=1 is image plane, origin at COP. 
    # Usually, back-to-front means sorting by distance from COP.
    transformed = []
    for p in particles:
        pos_cam = transform_point(p['pos'], camera_matrix)
        transformed.append((pos_cam[2], p)) # u2
    # Sort descending if u2 increases with depth, or ascending. 
    # Standard back-to-front: furthest first.
    transformed.sort(key=lambda x: x[0], reverse=True)
    return [item[1] for item in transformed]

def transform_point(pos, matrix):
    p = np.append(pos, 1.0)
    return matrix @ p
```

**Parameters:**
*   **Cutoff radius $r$:** Truncation radius for the Gaussian kernel. Typical value $1 \le r \le 3$ [S6, unofficial][S11].
*   **Low-pass filter variance $\mathbf{V}_h$:** Typically the 2x2 identity matrix [S6, unofficial][S11].
*   **Reconstruction Kernel:** 3D Elliptical Gaussian [S8, S9, unofficial].

**Edge Cases and Pitfalls:**
*   **Numerical Stability:** The central conics approach can be numerically unstable when the projection approaches a line, as the condition number of the inverse 2D-to-2D projective mapping increases rapidly [S12, unofficial].
*   **Overlap Assumption:** Basic splatting assumes non-overlapping kernels for visibility, which causes artifacts. EWA reduces but does not fully eliminate artifacts if self-occlusion is ignored in compositing [S1, S8, unofficial].
*   **Non-Spherical Kernels:** If 3D kernels are not radially symmetric (e.g., irregular grids), additional care is needed to ensure contributions sum correctly [S9, unofficial].
*   **Perspective Distortion:** The affine approximation of the Jacobian may introduce errors for very large fields of view or extreme angles [S6, unofficial][S11].

## Subtopics

### [Deferred Surface Splatting](1072-deferred-surface-splatting.md)
Deferred Surface Splatting converts unstructured point clouds into continuous surfaces by projecting points as splats into a deferred rendering pipeline. It differs from standard EWA Splatting by using screen-aligned spherical impostors with isotropic linear falloff rather than anisotropic, correctly band-limited EWA footprints, trading accurate filtering for a formulation that requires no per-point normals or radii. It differs from siblings like [Phong Splatting](2802-phong-splatting.md) by deferring lighting to a final screen-space pass [G].

### [Opacity-Thin-Side (OTS)](1155-opacity-thin-side-ots.md)
Opacity-Thin-Side (OTS) is a parameterization scheme for EWA-based splatting that ensures robust gradient-descent optimization by dynamically scaling the learned weight $\theta$ such that the projected amplitude $a'$ equals $\theta$ when viewing the Gaussian along its thinnest side (shortest axis). It differs from standard EWA Splatting, which preserves the integral of extinction (mass), and 3D Gaussian Splatting (3DGS), which preserves the 2D projected amplitude regardless of view, by preserving the 3D unbounded integral (view-independent mass) while ensuring the 2D projection behaves as an ordinary integral relative to the thinnest view.

### [OTS (EWA-Based Splatting)](1181-ots-ewa-based-splatting.md)
OTS (Opacity-Thin-Side) is a splatting method using unnormalized Gaussians that preserves the 2D amplitude $a'$ (called 'opacity') across projections, unlike EWA Splatting which preserves the weight $w$. It differs from standard EWA Splatting by requiring a Jacobian determinant correction to preserve the integral of the extinction coefficient under perspective projection.

### [GPU-Accelerated Volume Splatting With Elliptical RBFs](1186-gpu-accelerated-volume-splatting-with-elliptical-rbfs.md)
This method renders scattered volumetric data represented as 3D ellipsoidal Radial Basis Functions (RBFs) using a post-shaded, kernel-centric approach. It extends high-quality image-aligned sheet-buffer splatting to irregular grids by slicing kernels into parallel, image-aligned density planes, rasterizing them as 2D footprints, and compositing them. Unlike fragment-centric methods that evaluate Gaussian functions per pixel, this technique leverages hard-wired GPU polygonal rasterization, achieving two orders of magnitude higher frame rates. It differs from its parent [EWA Splatting](1069-ewa-splatting.md) by supporting general ellipsoidal kernels and using a flat spatial decomposition with active cell lists rather than screen-aligned spherical impostors.

### [Ellipsoidal Kernel Splatting with Warped Slicing](1290-ellipsoidal-kernel-splatting-with-warped-slicing.md)
Ellipsoidal Kernel Splatting with Warped Slicing is a volume rendering technique that represents point samples as 3D ellipsoids and rasterizes them by slicing the ellipsoid into 2D polygons. It solves the problem of efficiently computing the intersection of general ellipsoids with screen-aligned slicing planes on GPU hardware, where direct analytical slicing requires expensive square roots and conditional statements. The method warps the slicing planes from screen space into the coordinate system of a unit sphere, allowing the use of hard-wired GPU texture mapping and blending on radially symmetric kernel slices. It differs from its parent [EWA Splatting](1069-ewa-splatting.md) by explicitly slicing the kernel into discrete polygons for incremental rasterization rather than rasterizing the entire projected footprint, and it avoids the pre-integrated slab approach of earlier image-aligned splatting by using point-sampled slices.

### [Perspective Correct Splat Rasterization with EWA Approximation](2095-perspective-correct-splat-rasterization-with-ewa-approximati.md)
This method is an improved splat rendering pipeline that combines a perspectively correct fast splat rasterization procedure with an approximation of the Elliptical Weighted Average (EWA) filter. It solves the problem of aliasing artifacts and visual holes in point-sampled geometry rendering, particularly when the model is viewed from flat angles or shifted from the viewing axis. Unlike its siblings, it uses an affine approximation to the projective mapping to ensure perspective-correct splat shapes without requiring per-point normals or complex anisotropic footprint calculations, trading exact band-limited footprints for a formulation that avoids holes and Moiré patterns. It builds on [EWA Splatting](1069-ewa-splatting.md) by replacing the standard EWA covariance computation with a faster, perspective-correct affine approximation.

### [Adaptive EWA Volume Splatting](2137-adaptive-ewa-volume-splatting.md)
Adaptive EWA Volume Splatting is a rendering technique that simplifies the computationally expensive Elliptical Weighted Average (EWA) resampling filter by classifying volume particles into three cases based on their distance from the viewpoint. It solves the problem of high computational cost in full EWA splatting while maintaining aliasing-free quality. Unlike full EWA splatting, which always computes the combined covariance of the reconstruction and low-pass filters, this method uses only the reconstruction filter for close particles (magnification) and only the low-pass filter for far particles (minification), resorting to full EWA only in the transition zone.

### [EWA Approximation with Tangent Vector Adjustment](2143-ewa-approximation-with-tangent-vector-adjustment.md)
A high-quality filtering technique for point-based rendering that approximates the EWA resampling filter by dynamically adjusting the tangent vectors of isotropic splats during setup to prevent aliasing during minification, without requiring expensive per-fragment convolution. It sets itself apart from the original EWA framework by using projective mapping and tangent adjustment rather than affine mapping and Gaussians for both reconstruction and low-pass filters, and from Botsch et al. [BHZK05] by avoiding per-fragment filter evaluation, thus eliminating the fragment shader bottleneck.

### [Phong Splatting](2802-phong-splatting.md)
Phong Splatting is a surface splatting technique that assigns a linearly varying normal field to each elliptical splat, enabling per-pixel Phong shading without surface connectivity. It solves the piecewise constant shading artifacts of standard point-based rendering by providing smooth, Phong-like shading quality on modern GPUs. Unlike its sibling [EWA Splatting](1069-ewa-splatting.md), which uses a simplified isotropic kernel, Phong Splatting uses elliptical splats with projectively correct per-pixel parameterization, trading the simplicity of isotropic filtering for superior visual quality and exact depth values.

### [EWA Splatting Renderer (Mesh-Free)](4665-ewa-splatting-renderer-mesh-free.md)
A mesh-free rendering pipeline that projects raw point clouds directly to 2D camera views using EWA projection and Z-buffer occlusion, producing RGB images, label maps, and 2D-to-3D index maps without mesh reconstruction. It differs from its parent [EWA Splatting](1069-ewa-splatting.md) by using simplified screen-aligned spherical impostors with isotropic linear falloff, trading anisotropic, correctly band-limited footprints for a formulation that requires no per-point normals or radii.

### [EWA Splatting with kNN Covariance Estimation](4690-ewa-splatting-with-knn-covariance-estimation.md)
A rendering method that uses per-point 3D covariance estimated from k-nearest neighbours to project an elliptical weighted average (EWA) shape onto the 2D image plane for denser coverage than simple disk splatting. It builds on [EWA Splatting](1069-ewa-splatting.md) by replacing the simplified spherical impostor with an anisotropic footprint derived from local point cloud geometry, trading the need for explicit surface normals for a statistical estimate of local orientation.

### Order Independent EWA Volume Splatting
A novel order independent EWA volume splatting method that unifies the advantages of previous OI techniques and provides an efficient high-speed approximation by exploiting the analytical expression of elliptical Gaussian kernels used for the noise [S16, unofficial]. It computes a fast view-dependent approximation of accumulated densities along viewing directions using a per-pixel projective volume rendering approach and projects the spatially bound kernel functions directly (splat them) thanks to their analytic representation [S16, unofficial]. Unlike ray marching which requires hundreds of evaluations per pixel and is computationally demanding for procedural noise, this method provides interactive visualization [S16, unofficial]. Unlike EWA volume splatting which requires time-consuming back-to-front ordering and introduces rasterization overhead due to overlapping ellipses, this OI method gets rid of ordering to trade realism for speed [S16, unofficial].

### EWA Surface Splatting
A method where EWA volume splats reduce to surface splats suitable for high-quality iso-surface rendering by flattening the 3D Gaussian kernel along the volume gradient [S9, unofficial]. For each point in object-space, it deforms quadrilaterals texture-mapped with a Gaussian texture to result in the correct screen-space EWA splat after projection [S9, unofficial].

## Operating characteristics
**Time Complexity:** $O(N)$ where $N$ is the number of particles, assuming constant-time footprint evaluation and rasterization. However, the constant factor is high due to the computation of the Jacobian, matrix inversion, and elliptical footprint rasterization [S1, S8, unofficial].
**Memory Complexity:** $O(N)$ to store particle data and filter parameters.
**Measured Performance:** On an 866 MHz Pentium-III, rendering times were approximately 11 seconds for the Skull dataset and 6-11 seconds for other datasets (zebra, engine, foot) [S1, S8, S10, unofficial]. Hardware acceleration significantly improves this, but interactive rates were difficult to achieve initially due to computational complexity [S6, unofficial].
**Scaling:** Performance scales linearly with the number of particles but is sensitive to the number of fragments generated by large elliptical footprints. Adaptive EWA splatting improves performance for distant particles by simplifying the filter [S6, unofficial].
**Strengths:** High image quality, aliasing-free rendering, handles arbitrary elliptical kernels, supports perspective projection correctly [S2][S8, S15, unofficial].
**Limitations:** Computationally expensive compared to basic splatting, requires sorting for correct compositing (unless using OI variants), numerical instability in extreme projections [S1, S8, S12, unofficial].
**When to use:** When high-quality, alias-free volume rendering is required and performance allows for the computational cost of EWA filtering.
**When not to use:** For real-time applications with very large datasets where basic splatting or ray marching is preferred, or when hardware does not support efficient elliptical rasterization.

## Background
EWA Splatting was introduced by Matthias Zwicker, Hanspeter Pfister, Jeroen van Baar, and Markus Gross in 2001 [S8, S10, unofficial]. It is named after Heckbert's Elliptical Weighted Average (EWA) filter for texture mapping due to the similarity in derivation [S2][S7, abstract only, unofficial][S8, unofficial]. The method was developed to address the aliasing artifacts inherent in traditional splatting methods, which assumed non-overlapping reconstruction kernels [S1, S8, unofficial]. It has been widely used in high-quality volume rendering and point-based surface rendering [S2][S7, abstract only, unofficial].
