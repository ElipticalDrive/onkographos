# Adaptive EWA Volume Splatting

Also called: Adaptive EWA Filtering, Adaptive EWA Splatting, Chen adaptive splatting, Distance-dependent Adaptive EWA Volume Splatting

## Overview
Adaptive EWA Volume Splatting is a rendering technique that simplifies the computationally expensive Elliptical Weighted Average (EWA) resampling filter by classifying volume particles into three cases based on their distance from the viewpoint [S2, unofficial][S3]. It solves the problem of high computational cost in full EWA splatting while maintaining aliasing-free quality [S2, unofficial][S3]. Unlike full EWA splatting, which always computes the combined covariance of the reconstruction and low-pass filters, this method uses only the reconstruction filter for close particles (magnification) and only the low-pass filter for far particles (minification), resorting to full EWA only in the transition zone [S2, unofficial][S3].

## How it works
**Inputs:**
- Volume dataset (regular or rectilinear) [S2, unofficial][S3].
- Camera parameters (view angle $fov$, projection matrix) [S2, unofficial][S3].
- Reconstruction kernel cutoff radius $r_k$ and low-pass filter cutoff radius $r_h$ [S2, unofficial][S3].

**Outputs:**
- Rendered image with antialiasing [S2, unofficial][S3].

**Data Structures:**
- **Packed Vertex Representation (32 bits):** Used to store proxy geometry efficiently in GPU memory [S3].
  - $t_x$: Volume texture coordinate X. Packed as $m_x \times 256 + i_x$. $m_x$ uses 7 bits, $i_x$ uses 8 bits [S3].
  - $t_y$: Volume texture coordinate Y. Packed similarly ($m_y$ 7 bits, $i_y$ 8 bits) [S3].
  - $f_x, f_y$: Gaussian texture coordinates. Each uses 1 bit (values 0 or 1) [S3].
  - Total: $7+8+7+8+1+1 = 32$ bits [S3].
- **Lookup Table:** Stored in constant registers, accessed via an address register in the vertex shader to decompress $m_x, m_y, f_x, f_y$ [S3].

**Parameters:**
- $c_{min}$: Lower bound parameter for distance-dependent criteria. Typical value: $0.3$ [S2, unofficial][S3].
- $c_{max}$: Upper bound parameter for distance-dependent criteria. Typical value: $2.0 \times (1.0 + 2.0 \times \tan(fov/2)^2)$ [S2, unofficial][S3].

**Method Steps:**

1.  **Patch Grouping:** Group quads (voxels) of each slice into uniform rectangular patches [S2, unofficial][S3].
2.  **Corner Computation:** For each patch, compute the camera space coordinate $u_{k2}$ (depth) of each of the four corner voxels on-the-fly [S2, unofficial][S3].
3.  **Classification:** Evaluate the criteria from Equation 7 for the four vertices of the patch [S2, unofficial][S3]:
    -   **Magnification (Close):** If all four vertices satisfy $u_{k2} < \frac{r_k}{r_h} \times c_{min}$, use the reconstruction filter [S2, unofficial][S3].
    -   **Minification (Far):** If all four vertices satisfy $u_{k2} > \frac{r_k}{r_h} \times c_{max}$, use the low-pass filter [S2, unofficial][S3].
    -   **Transition:** Otherwise, use the full EWA resampling filter [S2, unofficial][S3].
4.  **Filter Selection:** Apply the appropriate vertex shader corresponding to the selected filter case [S2, unofficial][S3].
    -   The filter function $H_k(\mathbf{x})$ is defined as:
        $$
        H_k(\mathbf{x}) = \begin{cases} 
        \mathbf{x}^T \cdot \hat{\mathbf{V}}_k^{-1} \cdot \mathbf{x}, & \text{if } u_{k2} < \frac{r_k}{r_h} \times c_{min} \\
        \mathbf{x}^T \cdot \mathbf{V}_h^{-1} \cdot \mathbf{x}, & \text{if } u_{k2} > \frac{r_k}{r_h} \times c_{max} \\
        \mathbf{x}^T \cdot (\hat{\mathbf{V}}_k + \mathbf{V}_h)^{-1} \cdot \mathbf{x}, & \text{otherwise}
        \end{cases}
        $$
        where $\mathbf{x}$ is the screen-space offset vector [S2, unofficial][S3].
    -   $\hat{\mathbf{V}}_k$ is the 2x2 variance matrix of the reconstruction filter, obtained by skipping the third row and column of the full 3x3 covariance matrix $\mathbf{V}_k$ [S2, unofficial][S3].
    -   $\mathbf{V}_h$ is the 2x2 variance matrix of the Gaussian low-pass filter, usually the identity matrix [S2, unofficial][S3].
5.  **Rasterization:** Rasterize the proxy quads using the selected vertex shader to deform the unit Gaussian texture according to the footprint function [S2, unofficial][S3].

**Pseudocode:**

```python
def classify_patch(patch_corners_camera_space, r_k, r_h, c_min, c_max):
    """
    Determines the filter type for a patch based on the depth of its four corners.
    patch_corners_camera_space: list of 4 tuples (u_k0, u_k1, u_k2)
    Returns: 'MAGNIFICATION', 'MINIFICATION', or 'FULL_EWA'
    """
    all_magnification = True
    all_minification = True
    threshold_min = (r_k / r_h) * c_min
    threshold_max = (r_k / r_h) * c_max
    
    for u_k0, u_k1, u_k2 in patch_corners_camera_space:
        if u_k2 >= threshold_min:
            all_magnification = False
        if u_k2 <= threshold_max:
            all_minification = False
        if not all_magnification and not all_minification:
            return 'FULL_EWA'
            
    if all_magnification:
        return 'MAGNIFICATION'
    elif all_minification:
        return 'MINIFICATION'
    else:
        return 'FULL_EWA'

def compute_filter_matrix(filter_type, V_hat_k, V_h):
    """
    Computes the inverse covariance matrix used in the filter exponent.
    """
    if filter_type == 'MAGNIFICATION':
        return V_hat_k
    elif filter_type == 'MINIFICATION':
        return V_h
    else:
        return V_hat_k + V_h
```

**Edge Cases and Pitfalls:**
- **Transition Zone:** In the transition between magnification and minification, neither approximation avoids aliasing artifacts without the full EWA computation [S2, unofficial][S3].
- **Memory Limits:** A naive implementation of proxy geometry for a $256^3$ volume requires 2240M bytes of memory, exceeding the 256M limit of commodity graphics hardware at the time of publication [S3]. Compression is necessary [S3].
- **Precision:** The classification relies on conservative bounds derived from the maximum value of $(u_{k0}^2 + u_{k1}^2 + u_{k2}^2)/u_{k2}^2$, which is $(1.0 + 2.0 \times \tan(fov/2)^2)$ [S2, unofficial][S3].

## Operating characteristics
- **Time Complexity:** Reduces computation cost compared to full EWA splatting by using simpler filters (low-pass or reconstruction) in extreme cases, but adds classification overhead [S2, unofficial].
- **Measured Performance:**
    - On a $512 \times 512 \times 3$ checkerboard dataset: 6.88 fps vs 4.83 fps for full EWA [S2, unofficial].
    - Engine dataset ($256 \times 256 \times 110$): 3.25 fps vs 2.90 fps (12% improvement) [S2, unofficial][S3].
    - Bonsai dataset ($256 \times 256 \times 128$): 7.53 fps vs 6.90 fps (9% improvement) [S2, unofficial][S3].
    - Lobster dataset ($301 \times 324 \times 56$): 10.60 fps vs 8.75 fps (21% improvement) [S2, unofficial][S3].
    - UNC Head dataset ($208 \times 256 \times 225$): 3.00 fps vs 2.70 fps (11% improvement) [S2, unofficial][S3].
- **Strengths:** Achieves high image quality comparable to full EWA while reducing computational cost by 10% to 20% [S2, unofficial][S3]. Corrects aliasing artifacts and holes that occur with improper filters (reconstruction or low-pass only) [S2, unofficial][S3].
- **Limitations:** Adds classification overhead. The improvement is modest (10-20%) [S2, unofficial][S3].
- **When to use:** When interactive frame rates are required for large volume datasets and full EWA is too slow, but quality must be maintained [S2, unofficial][S3].
- **When not to use:** When the scene is uniformly very close or very far, as the overhead of classification may not be justified if one filter could be used globally without quality loss (though full EWA is safer for mixed depths) [S2, unofficial][S3].

## Background
Adaptive EWA Volume Splatting was introduced by Wei Chen et al. in 2004 [S2, unofficial][S3]. It builds on the EWA Splatting method [1069-ewa-splatting.md] by observing that the EWA resampling filter computation is expensive and can be simplified adaptively based on depth [S1, S2, unofficial][S3]. The method was implemented on GPU to gain additional performance for interactive frame rates [S1, S2, unofficial][S3].
