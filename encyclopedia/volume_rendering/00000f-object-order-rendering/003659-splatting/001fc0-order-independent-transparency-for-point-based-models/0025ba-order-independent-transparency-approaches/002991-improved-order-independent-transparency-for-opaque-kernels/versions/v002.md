# Improved Order Independent Transparency for Opaque Kernels


## Overview
This method improves the rendering of opaque or semi-transparent kernels by incorporating the contribution of the closest sample into the transparency accumulation, thereby reducing transparency artifacts compared to standard Order Independent Transparency (OIT) [S1, unofficial]. It addresses the limitation of standard OIT, which fails to distinguish neighboring kernels in close-up views, by re-introducing depth information via the closest sample while maintaining performance close to geometry instancing [S1, unofficial]. It builds on [Order Independent Transparency Approaches](3611-order-independent-transparency-approaches.md).

## How it works
The method computes the final color $L$ for a pixel by combining the direct contribution of the closest kernel sample with a weighted average of all other kernel samples.

**Inputs and Outputs:**
- **Input:** A set of kernel clusters $\mathcal{C}_i$ for $i \in [0, N-1]$, where each cluster contains sample points $\mathbf{p}_j$. For each pixel, the closest sample point $\mathbf{p}_f$ and its transparency $\alpha_f$ are identified.
- **Output:** The final color $L$.

**Data Structures:**
- **Kernel Clusters:** $\mathcal{C}_i$ represents a group of sample points.
- **Sample Points:** $\mathbf{p}_j$ are individual points within a cluster.
- **Transparency:** $T(\mathbf{p}_j)$ is the transparency value at sample point $\mathbf{p}_j$.
- **Color Contribution:** $L_{\mathcal{C}_i}$ is the color contribution from cluster $i$.
- **Closest Sample:** $\mathbf{p}_f$ is the sample point with the smallest depth (closest to the camera) among all samples contributing to the pixel.
- **Kernel Value:** $\tilde{K}(\mathbf{d}, \mathbf{p}_f)$ is the kernel value at the closest sample point $\mathbf{p}_f$ with direction $\mathbf{d}$.

**Steps:**
1. Identify the closest kernel sample $\mathbf{p}_f$ and its transparency $\alpha_f$. This can be trivially determined using a depth test in the rendering pipeline [S1, unofficial].
2. Calculate the direct contribution of the closest kernel: $\tilde{K}(\mathbf{d}, \mathbf{p}_f) \alpha_f$.
3. Compute the weighted average color of all other kernels by summing the color contributions $L_{\mathcal{C}_i}$ and dividing by the sum of their transparencies $T(\mathbf{p}_j)$.
4. Multiply this average by the remaining opacity $(1 - \alpha_f)$.
5. Sum the direct contribution and the weighted average contribution to get the final color $L$.

**Formula:**
$$L \approx \tilde{K}(\mathbf{d}, \mathbf{p}_f) \alpha_f + \left( \frac{\sum_{i=0}^{N-1} L_{\mathcal{C}_i}}{\sum_{i=0}^{N-1} \sum_{\mathbf{p}_j \in \mathcal{C}_i^*} T(\mathbf{p}_j)} \right) (1 - \alpha_f) \quad (1)$$

Where:
- $L$ is the final color.
- $\tilde{K}(\mathbf{d}, \mathbf{p}_f)$ is the kernel value at the closest sample point $\mathbf{p}_f$ with direction $\mathbf{d}$.
- $\alpha_f$ is the transparency of the closest kernel.
- $N$ is the number of kernel clusters/slices.
- $L_{\mathcal{C}_i}$ is the color contribution from cluster $i$.
- $T(\mathbf{p}_j)$ is the transparency at sample point $\mathbf{p}_j$ in cluster $\mathcal{C}_i^*$.

**Parameters:**
- $N$: The number of kernel clusters or slices used in the summation. In experiments, 32 samples per ray per evaluated kernel were used [S1, unofficial].

**Pseudocode:**
```python
def compute_color_closest_sample(clusters, closest_sample, direction):
    """
    Computes the final color L using the Improved OIT method for opaque kernels.
    
    Args:
        clusters (list of list of Sample): List of kernel clusters, each containing Sample objects.
        closest_sample (Sample): The sample point p_f with the smallest depth.
        direction (Vector): The view direction d.
        
    Returns:
        Color: The final color L.
    """
    # Step 1: Get closest sample properties
    p_f = closest_sample
    alpha_f = p_f.transparency
    kernel_value = evaluate_kernel(p_f, direction)  # \tilde{K}(d, p_f)
    
    # Step 2: Direct contribution of the closest kernel
    direct_contribution = kernel_value * alpha_f
    
    # Step 3: Compute weighted average color of all other kernels
    total_color_sum = 0.0
    total_transparency_sum = 0.0
    
    for cluster in clusters:
        for sample in cluster:
            # Exclude the closest sample from the average calculation if it is part of the clusters
            # Note: The formula sums over all clusters, but the closest sample's contribution
            # is handled separately. The denominator sums transparencies of all samples.
            # The numerator sums color contributions of all samples.
            # However, the formula implies L_C_i is the color contribution from cluster i.
            # We assume L_C_i is pre-computed or can be derived from samples in the cluster.
            # For simplicity, we sum individual sample contributions.
            total_color_sum += sample.color_contribution
            total_transparency_sum += sample.transparency
            
    # Avoid division by zero
    if total_transparency_sum == 0:
        average_color = Color(0, 0, 0)
    else:
        average_color = total_color_sum / total_transparency_sum
        
    # Step 4: Multiply average by remaining opacity
    remaining_opacity_contribution = average_color * (1 - alpha_f)
    
    # Step 5: Sum contributions
    final_color = direct_contribution + remaining_opacity_contribution
    
    return final_color
```

**Edge Cases and Pitfalls:**
- **Division by Zero:** If the sum of transparencies is zero, the average color is undefined. A guard clause should return a default color or handle this case appropriately [G].
- **Closest Sample Identification:** The closest sample must be correctly identified using a depth test. Errors in depth testing can lead to incorrect results [S1, unofficial].
- **Opaque Kernels:** The method shows significant improvements for opaque kernels but is almost identical to standard OIT for highly transparent kernels [S1, unofficial].

## Operating characteristics
- **Time Complexity:** The method involves summing over all kernel clusters and samples, which is $O(N \cdot M)$ where $N$ is the number of clusters and $M$ is the average number of samples per cluster. However, the closest sample is identified in $O(1)$ if pre-computed or during the depth pass.
- **Memory Complexity:** Requires storing kernel clusters and sample properties. Memory usage is proportional to the number of kernels and samples.
- **Measured Performance:** On a GeForce 980 with a 1920×1080 rendering window, the method runs at approximately 2 fps for 400k impulses with a lichen pattern [S1, unofficial]. Geometry instancing offers 60 fps for 800k kernels and 3 fps for 10M kernels, while the improved OIT method runs at roughly half the framerate of the previous methods (instancing or basic OIT) [S1, unofficial].
- **Strengths:** Avoids aliasing artifacts (z-fighting) and handles semi-transparency, which geometry instancing cannot [S1, unofficial]. It also avoids transparency artifacts in close-up views compared to basic OIT [S1, unofficial].
- **Limitations:** Performance is lower than geometry instancing [S1, unofficial].
- **When to Use:** Use when rendering opaque or semi-transparent kernels where aliasing artifacts from geometry instancing are unacceptable, and transparency artifacts from basic OIT are noticeable.
- **When Not to Use:** Use geometry instancing if performance is critical and aliasing artifacts can be tolerated or mitigated by other means.

## Background
The method was introduced in the context of volumetric spot noise for procedural 3D shell texture synthesis [S1, unofficial]. It addresses the limitations of traditional EWA Splatting, which is not tractable due to depth-sorting overhead, and basic OIT, which lacks precision for neighboring kernels [S1, unofficial]. The approach combines geometry instancing for the closest sample with OIT EWA splatting for the rest, effectively balancing performance and visual quality [S1, unofficial].
