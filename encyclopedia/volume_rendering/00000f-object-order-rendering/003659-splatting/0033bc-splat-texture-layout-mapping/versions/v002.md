# Splat Texture Layout & Mapping

Also called: Splat Data Texture Mapping

## Overview
Splat Texture Layout & Mapping organizes per-primitive splat data into 3D texture structures to enable efficient GPU-based rendering of Gaussian splats. It solves the problem of mapping arbitrary numbers of splats into a fixed-size hardware texture format by calculating specific texture coordinates and managing memory alignment. It sets itself apart from proxy geometry methods by keeping data in texture memory for hardware filtering, and from sparse volume textures by using a dense, pre-allocated 3D texture layout for the splat attributes themselves.

## How it works
**Inputs:** A list of splats with attributes (position, covariance, color, opacity) and an input capacity (number of splats).
**Outputs:** Two 3D textures (backed by `Uint32Array` buffers) containing the mapped splat data, and the calculated texture coordinates for sampling.

**Data Structures:**
1.  **Splat Buffer:** A flat array of `Uint32` values. Each splat occupies 4 `Uint32` slots (16 bytes).
2.  **3D Textures:** Two 3D textures. Each splat corresponds to two 16-byte texture records within these textures. The textures are backed by `Uint32Array` objects.

**Algorithm:**

1.  **Calculate Capacity:** Determine the maximum splat capacity supported by the texture dimensions using `getTextureSize(inputCapacity).maxSplats`.
2.  **Allocate Memory:** If `inputCapacity` differs from `maxSplats`, allocate new `Uint32Array` buffers of size `maxSplats * 4`. Copy the original splat data into these new buffers.
3.  **Calculate Layer Bits:** Determine the number of bits required for the texture layer index based on the splat height and width.
    *   Formula: `layerBits = SPLAT_TEX_WIDTH_BITS + Math.ceil(Math.log2(height))`
    *   Where `SPLAT_TEX_WIDTH_BITS` is a constant defining the width of the splat texture in bits, and `height` is the height of the splat in texels.
4.  **Create Mask:** Generate a source layer mask to isolate the relevant bits for layer indexing.
    *   Formula: `sourceLayerMask = 2 ** layerBits - 1`
5.  **Map to Textures:** Distribute the splat data into the two 3D textures. Each splat's 16-byte record is split or mapped across the two textures according to the implementation's specific packing scheme.
6.  **Calculate Coordinates:** For each splat index, compute the 3D texture coordinate (`ivec3`) required to sample its data. This function handles paging or tiling for large splat counts to ensure coordinates remain within the allocated texture bounds [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Capacity Mismatch:** If `inputCapacity` does not match `maxSplats`, memory must be reallocated and data copied. Failure to do so results in out-of-bounds access or wasted memory [S1, unofficial].
*   **Precision:** Use of `Math.ceil(Math.log2(height))` requires careful handling of non-power-of-two heights to ensure `layerBits` is sufficient [S1, unofficial].
*   **Large Splat Counts:** For very large scenes, the coordinate calculation must handle paging or tiling to avoid exceeding texture dimensions [S2, unofficial].

## Subtopics

### [Hardware Accelerated Texture Atlases](8597-hardware-accelerated-texture-atlases.md)
This method organizes per-primitive texture data into large 2D atlas textures to leverage GPU hardware filtering and caching, thereby avoiding multiple texture bindings and software-based sampling overhead. It sets itself apart from software-based interpolation by utilizing dedicated texture units for bilinear filtering, which is significantly faster than manual interpolation from global memory arrays.

## Operating characteristics
**Time Complexity:** O(N) for allocation and mapping, where N is the number of splats. Coordinate calculation is O(1) per splat.
**Memory Complexity:** O(N) for the `Uint32Array` buffers and 3D textures. The size is determined by `maxSplats * 4 * sizeof(uint32)`.
**Performance:** Hardware filtering provides significant speedup over software interpolation [S1, unofficial].
**Scaling:** Scales with the number of splats, limited by texture size constraints.
**Strengths:** Efficient GPU sampling, reduced driver overhead from texture binding.
**Limitations:** Fixed texture size limits the maximum number of splats without complex paging [S2, unofficial].

## Background
This method is part of the Gaussian Splatting rendering pipeline, specifically for efficient data transfer and sampling on the GPU. It is implemented in libraries such as `gaussian-splat-lite` [S1, unofficial].
