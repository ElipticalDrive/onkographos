# Texture Splatting

Also called: Textured Splat Rendering, Texture Splatting for Scalar Fields, Wang's Texture Splatting on Particles

## Overview
Texture Splatting is a volume rendering technique that represents volumetric data or point clouds as a set of texture-mapped primitives (typically quads or squares) rasterized onto the screen. It solves the problem of rendering high-frequency detail and complex scalar/vector fields efficiently by offloading the reconstruction kernel evaluation to the fragment shader via texture lookups, rather than computing per-fragment kernel values analytically. It sets itself apart from standard Gaussian Splatting by using texture maps to store color, normal, or other per-fragment properties, allowing for higher fidelity with fewer primitives and avoiding the artifacts associated with polygonal mesh approximations of Gaussian kernels.

## Shared principles
The Texture Splatting family shares the fundamental mechanism of treating volumetric data as a set of geometric or parametric primitives that are transformed and rasterized [G].

1.  **Primitive Representation:** The volume is decomposed into primitives [G]. Each primitive $k$ is defined by its position $\mathbf{p}_k$, density/extinction coefficient $g_k$ or $\rho_k$, and a reconstruction kernel $h$ (typically a Gaussian) [S1].
2.  **Transformation:** Primitives are transformed from volume space to screen space using the Model-View-Projection (MVP) matrix or specific factorizations (e.g., shear-warp) [S2, unofficial][S3]. For perspective projections, the kernel shape may be distorted (e.g., EWA splatting) to account for foreshortening .
3.  **Rasterization:** The transformed primitives are projected onto the 2D image plane [G]. The contribution of a voxel $D$ to a screen point $(x,y)$ is determined by the footprint function $F(x,y)$, which is the integral of the 3D kernel along the view direction [S2, unofficial]:
    $$ F(x,y) = \int h(x-x_D, y-y_D, z) \, dz $$
    The intensity written to the pixel is modulated by the voxel density:
    $$ P(x,y) = \text{weight}(x,y) \cdot \rho(D) $$
4.  **Compositing:** Contributions are accumulated to form the final image [G]. This is typically done using alpha blending in back-to-front or front-to-back order to handle transparency correctly [S1][S2, unofficial][S3]. Splatting compositing is performed along sheets (all pixels at once for a set of voxels), whereas ray-casting composites along rays (one sample at a time) .
5.  **Hardware Acceleration:** Most methods in this family rely on GPU rasterization pipelines for performance, enabling real-time interactivity [S1][S2, unofficial][S3].

## Subtopics

### Textured Splat Rendering
Textured Splat Rendering is a method for rendering massive point clouds where each point is drawn as an oriented quad, and per-fragment properties (color, normals) are retrieved from texture maps rather than being constant across the primitive. It sets itself apart from flat splats by recovering high-frequency detail with fewer, larger samples, avoiding the precision loss of encoding geometry in textures. It is chosen when high-fidelity surface detail is required from sparse point cloud data. See [Textured Splat Rendering](1343-textured-splat-rendering.md).

### Texture Splatting for Scalar Fields
Texture Splatting for Scalar Fields uses texture-mapped squares to represent scalar fields, utilizing an ideal reconstruction kernel to improve image quality over polygonal approximations. It sets itself apart from Gaussian splats by being faster for small splats (one square vs. a triangle strip) and avoiding the rapid cutoff artifacts of polygonal meshes. It is chosen for visualizing scalar fields where small splat coverage is dominant. See [Texture Splatting for Scalar Fields](1344-texture-splatting-for-scalar-fields.md).

### Wang's Texture Splatting on Particles
Wang's Texture Splatting on Particles extends texture splatting to model various cloud types with artistic control. It sets itself apart by applying different textures to particles depending on the target cloud type. It is chosen for artistic cloud rendering. See [Wang's Texture Splatting on Particles](1345-wangs-texture-splatting-on-particles.md).

## Background
Texture Splatting originated as a technique to render large datasets efficiently by leveraging texture hardware. Early work by Westin et al. introduced texture splats for 3D vector and scalar field visualization, demonstrating the use of ideal reconstruction kernels to avoid polygonal artifacts [S2, unofficial]. Later, Comino et al. proposed view-dependent hierarchical rendering of massive point clouds using textured splats, storing geometry in regular coordinates and color in texture maps to reduce memory footprint and allow for high-frequency detail recovery [S1]. Wang extended these concepts to cloud modeling, allowing for artistic control over different cloud types by texturing particles differently [S3]. The technique has been widely adopted in scientific visualization and real-time rendering for its balance of performance and visual quality.
