# Particle Advection and Rendering
Also called: GPU-computed particle advection, Particle-based vector field visualization

## Overview
Particle Advection and Rendering visualizes movement in time-dependent vector fields by emitting discrete particles from user-defined probe volumes and advecting them through the data [S1, unofficial]. It differs from static streamline rendering by explicitly handling temporal evolution, replacing dead particles with new ones to maintain a consistent visual representation of unsteady flows [S1, unofficial].

## How it works
**Inputs:** A time-dependent vector field $\mathbf{V}(\mathbf{x}, t)$, probe volume definitions (position, size), and user-controllable parameters: particle size, color, lifetime, and emission amount [S1, unofficial].
**Outputs:** A rendered image showing flow movement via point primitives or lit billboards [S1, unofficial].

**Data Structures:**
*   **Particle:** A structure containing current position $\mathbf{p}$, velocity $\mathbf{v}$, age $a$, and maximum lifetime $L$.
*   **Probe Volume:** A spatial region (e.g., box or sphere) from which particles are emitted.

**Steps:**
1.  **Emission:** For each frame, emit new particles from probe volumes. The number of particles is controlled by the "amount" parameter [S1, unofficial]. Initial positions are sampled within the probe volume. Initial velocities are typically set to the vector field value at the emission point or zero, depending on implementation [G].
2.  **Advection:** For each active particle, update its position based on the vector field. Let $\mathbf{p}_i(t)$ be the position of particle $i$ at time $t$. The new position is calculated by integrating the velocity field:
    $$ \mathbf{p}_i(t + \Delta t) = \mathbf{p}_i(t) + \mathbf{V}(\mathbf{p}_i(t), t) \cdot \Delta t $$
    where $\Delta t$ is the time step [S1, unofficial]. This integration occurs during the particle's lifetime [S1, unofficial].
3.  **Lifecycle Management:** Increment the particle's age $a$. If $a > L$ (lifetime), the particle is removed and replaced by a new one emitted from a probe volume [S1, unofficial]. This prevents error accumulation from long-term integration [S1, unofficial].
4.  **Rendering:** Two methods are implemented [S1, unofficial]:
    *   **Point Primitives:** Render particles as simple points at their calculated positions $\mathbf{p}_i$ [S1, unofficial].
    *   **Billboards:** Use a geometry shader to create quads around $\mathbf{p}_i$. To perform lighting calculations, a sphere is calculated based on camera distance and position, and used to compute lighting on the billboard [S1, unofficial].

**Pseudocode:**
```python
def render_particle_advection(vector_field, probe_volumes, params):
    # params: {particle_size, color, lifetime, amount}
    active_particles = []
    
    # 1. Emission
    for probe in probe_volumes:
        for _ in range(params['amount']):
            # Sample position within probe volume
            p = sample_position(probe)
            # Initialize particle [G]
            particle = {
                'pos': p,
                'vel': vector_field(p, 0), # Initial velocity [G]
                'age': 0,
                'lifetime': params['lifetime']
            }
            active_particles.append(particle)
            
    # 2. Advection and Update
    next_particles = []
    for particle in active_particles:
        # Advect based on vector field
        # p(t+dt) = p(t) + V(p(t), t) * dt
        particle['pos'] = particle['pos'] + particle['vel'] * dt
        particle['age'] += dt
        
        # 3. Lifecycle Management
        if particle['age'] < particle['lifetime']:
            next_particles.append(particle)
        else:
            # Replace with new particle from probe volume [S1, unofficial]
            # In a real loop, this would be handled by the emission step 
            # or a separate respawn logic. Here we assume emission 
            # happens per frame for new particles, and dead ones are discarded.
            pass
            
    # 4. Rendering
    for particle in next_particles:
        if params['render_mode'] == 'points':
            render_point(particle['pos'], params['particle_size'], params['color'])
        elif params['render_mode'] == 'billboards':
            # Use geometry shader to create quads [S1, unofficial]
            # Calculate sphere based on camera distance/position for lighting [S1, unofficial]
            render_billboard(particle['pos'], params['particle_size'], params['color'])
```

## Operating characteristics
*   **Performance:** GPU-computed advection allows for real-time interaction [S1, unofficial]. Rendering as point primitives is computationally cheaper than billboards with lighting [S1, unofficial].
*   **Limitations:** Visual quality depends on particle density and lifetime parameters [S1, unofficial]. Long-term integration without lifecycle management leads to error accumulation [S1, unofficial].
*   **Use Cases:** Interactive visualization of time-dependent flow data [S1, unofficial].
