# Interval Set Splatting

Also called: Fast Volume Rendering of Data Slices, SoListSplat

## Overview
Interval Set Splatting is a method for the interactive visualization of "thin" interval sets within volumetric data by maintaining a sorted list of data values and their coordinates [S1]. It solves the problem of efficiently rendering specific value ranges by using binary search to isolate relevant voxels and splatting them with constant color and opacity [S1]. It differs from general volume splatting by pre-filtering data into a sorted structure to enable rapid, selective rendering of narrow value bands, and from pure iso-surface extraction by rendering a thickness (interval) rather than a single surface [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volumetric dataset, a user-defined selection range ($[RangeMin, RangeMax]$), a target contour value ($C$), a thickness parameter ($\Delta$), and viewing parameters (projection matrix, rotation) [S1].
*   **Output:** A 2D image where voxels with values in $[C-\Delta, C+\Delta]$ are rendered as semi-transparent splats [S1].

**Data Structures:**
The core data structure is a sorted list encapsulated in a class (e.g., `SoListSplat`) [S1].
*   **List Layout:** An array of four-component vectors ($\mathbf{v}$) [S1].
*   **Components 0-2:** 3D coordinates $(x, y, z)$ [S1].
*   **Component 3:** The scalar data value $d$ [S1].
*   **Sorting:** The list is sorted by the scalar data value (Component 3) [S1].
*   **Metadata:** The class stores bounding box members `bboxMin` and `bboxMax` [S1].

**Parameters:**
*   $RangeMin, RangeMax$: Define the initial filter for data inclusion. Changing these requires rebuilding the list [S1].
*   $C$ (Contour Value): The center of the interval to render (e.g., 37.0) [S1].
*   $\Delta$ (Delta): Half-thickness of the interval. The rendered range is $[C-\Delta, C+\Delta]$ (e.g., 35.0 to 41.0) [S1].
*   $SplatSize$: A user parameter scaling the size of the splats [S1].
*   $Color, Opacity$: Constant values applied to all splats in the interval [S1].

**Algorithm Steps:**
1.  **List Construction (Offline/Update):** Traverse the entire volumetric dataset once [S1]. Select only voxels where $RangeMin \leq d \leq RangeMax$ [S1]. Store selected voxels as 4-component vectors $(x, y, z, d)$ [S1]. Sort the array by $d$ [S1].
2.  **Rendering Loop (Per Frame):** Inquire the current viewing transformation and determine a rotation matrix to orient the volume with projection space [S1]. Initialize the rendering pipeline for global settings, blending functions, and texture splats [S1]. Perform a binary search on the sorted list to find the indices of entries with values $C-\Delta$ and $C+\Delta$ [S1]. Traverse the subset of entries within the found range [S1]. Transform the voxel position $(x, y, z)$ using the rotation matrix [S1]. Project to screen space [G]. Render a primitive. Use a texture-mapped square containing the reconstruction function of Crawfis and Max in the alpha channel for higher accuracy [S1]. Alternatively, use a semi-transparent point primitive for large datasets where splats project to few pixels [S1]. Points do not require orientation transformations parallel to the screen and can be cached [S1]. Apply the constant $Color$ and $Opacity$, scaled by $SplatSize$ [S1].

**Edge Cases and Pitfalls:**
*   **Performance:** For large datasets, rendering a moderate number of texture splats can take greater than 0.5 seconds, disrupting smooth rotation [S1]. Use point splats for interactive rates in such cases [S1].
*   **Mesh Topology:** Reconstruction properties of splatting on regular grids break down for curvilinear and unstructured meshes [S1]. Results require careful examination [S1].
*   **List Rebuild:** Changing $RangeMin$ or $RangeMax$ requires traversing the data and rebuilding the sorted list, which is an expensive operation [S1].

## Operating characteristics
*   **Time Complexity:** List construction requires a single traversal and sorting of the filtered data [S1]. The exact asymptotic complexity is Not given in the sources. Rendering iterates over $K$ voxels in the interval $[C-\Delta, C+\Delta]$ [S1]. Binary search takes logarithmic time relative to the list size [S1].
*   **Memory Complexity:** $O(N)$ to store the sorted list of selected voxels [S1].
*   **Performance:** Point splats offer substantial speed-up over texture splats, enabling interactive exploration of large datasets (e.g., 1 million points) [S1]. Texture splats are slower but more accurate [S1].
*   **Strengths:** Fast selection of specific value ranges; interactive animation possible with point splats; simple implementation [S1].
*   **Limitations:** Not suitable for unstructured/curvilinear meshes without modification; texture splatting can be slow for large $K$; rebuilding the list is costly [S1].

## Background
The method was introduced in "Real-time slicing of data space" [S1]. It combines hardware-assisted splatting techniques with ideas from Shen and Johnson and Ihm and Lee to create a simple algorithm for representing "thin" interval sets [S1]. It was implemented as a C++ class extending Open Inventor graphics classes, specifically as `SoListSplat` [S1].
