# Auto Tile Refinement Calculation

Also called: Auto Tile Refinement, Tile Refinement Calculation

## Overview
Auto Tile Refinement Calculation determines the number of root tiles required to distribute splats evenly across a tiling hierarchy, preventing over-refinement by ensuring a minimum density of splats per leaf node [S1, unofficial]. It sets itself apart from sibling methods by focusing on the initial root-level partitioning count rather than the recursive subdivision logic or error metrics used in [Hierarchical and Multi-Resolution Splatting](5618-hierarchical-and-multi-resolution-splatting.md) or [Octree-based Hierarchy](12129-octree-based-hierarchy.md).

## How it works
**Inputs:**
- $N$: Total number of splats in the scene.
- $L$: Leaf limit parameter (maximum splats allowed per leaf node before further subdivision is considered).
- $r$: Sampling rate per level (geometric reduction factor).
- $\text{maxDepth}$: Maximum allowed depth of the tiling hierarchy.

**Outputs:**
- $T$: The calculated number of root tiles (tile refinement count).

**Data Structures:**
No complex data structures are required; the method uses scalar arithmetic.

**Parameters:**
- `AUTO_TILE_REFINEMENT_LEAF_LIMIT_MULTIPLIER`: Multiplier applied to $L$. Default value is 5 [S1, unofficial].
- `AUTO_TILE_REFINEMENT_MIN_SPLATS_PER_ROOT_TILE`: Absolute minimum number of splats required per root tile. Default value is 5000 [S1, unofficial].

**Steps:**
1.  Calculate the effective maximum depth $D$:
    $$ D = \max(0, \lfloor \text{maxDepth} \rfloor) $$
2.  Calculate the depth factor $F$:
    - If $D \le 0$ or $r$ is not finite, $F = 1$.
    - Otherwise, $F = (1/r)^D$.
3.  Calculate the target splat capacity per root tile $S$:
    $$ S = \max(L \times 5, 5000) $$
    *Note: The constants 5 and 5000 correspond to the default parameter values [S1, unofficial].*
4.  Calculate the denominator:
    $$ \text{denominator} = S \times F $$
5.  Determine $T$:
    - If $D \le 0$, or $N$ is not finite, or denominator is not finite, or denominator $\le 0.0$, or $N \le \text{denominator}$, return $T = 1$.
    - Otherwise, compute:
      $$ T = \max\left(1, \left\lceil \frac{N}{\text{denominator}} \right\rceil \right) $$
    - Return $T$.

**Pseudocode:**
```python
def calculate_tile_refinement(N, L, r, max_depth):
    # Step 1: Effective depth
    D = max(0, int(max_depth))
    
    # Step 2: Depth factor
    if D <= 0 or not is_finite(r):
        F = 1.0
    else:
        F = (1.0 / r) ** D
        
    # Step 3: Target capacity S
    # Using default constants as per source [S1, unofficial]
    S = max(L * 5, 5000)
    
    # Step 4: Denominator
    denominator = S * F
    
    # Step 5: Final calculation
    if D <= 0 or not is_finite(N) or not is_finite(denominator) or denominator <= 0.0 or N <= denominator:
        return 1
    
    # Ceiling division: ceil(N / denominator)
    # Using integer arithmetic: (N + denominator - 1) // denominator
    T = (N + int(denominator) - 1) // int(denominator)
    return max(1, T)

def is_finite(val):
    return val == val and val != float('inf') and val != float('-inf')
```

**Edge Cases and Pitfalls:**
- **Non-finite inputs:** If $N$ or $r$ are NaN or Infinity, the method defaults to returning 1 tile to prevent invalid hierarchy generation [S1, unofficial].
- **Zero or Negative Denominator:** If the denominator is zero or negative, the method returns 1 tile [S1, unofficial].
- **Small N:** If the splat count $N$ is less than or equal to the denominator, a single root tile is sufficient, so $T=1$ [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$. The calculation involves a fixed number of arithmetic operations and comparisons.
- **Memory Complexity:** $O(1)$. No additional memory is allocated.
- **Strengths:** Prevents excessive root-level subdivision, ensuring that each root tile contains a sufficient density of splats to justify the overhead of tile management.
- **Limitations:** It is a heuristic based on global counts and does not account for spatial distribution or clustering of splats.
- **When to use:** When initializing a 3D Tiles hierarchy for Gaussian splats or point clouds where uniform distribution is assumed or desired.
- **When not to use:** When the scene has highly non-uniform density that requires spatial-aware partitioning rather than count-based partitioning.

## Background
The method originates from the `3DGS-PLY-3DTiles-Converter` project, an unofficial tool for converting Gaussian Splatting PLY files into 3D Tiles format [S1, unofficial]. It was designed to address the problem of over-refinement in the tiling hierarchy, ensuring that the generated tileset is efficient for web-based rendering.
