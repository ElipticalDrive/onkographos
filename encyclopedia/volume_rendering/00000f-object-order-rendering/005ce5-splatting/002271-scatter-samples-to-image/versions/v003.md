# Scatter Samples to Image

Also called: Sample Scattering to Image, ScatterSamplesToImage

## Overview
Scatter Samples to Image is a post-processing step that scatters computed sample values from arbitrary screen-space positions into a regular image grid [S1, unofficial]. It maps non-uniformly distributed samples to a standard raster image for visualization [G]. Unlike [Splatting](23-splatting.md), which uses geometric kernels to blur and accumulate contributions, this method performs a direct assignment of values to pixel coordinates without filtering [S1, unofficial].

## How it works
**Inputs and Outputs:**
* `sample_positions`: A tensor of shape $2 \times N$, where $N$ is the number of samples [S1, unofficial].
* `samples`: A tensor of shape $C \times N$, where $C$ is the number of channels [S1, unofficial].
* `image_out`: A tensor of shape $C \times H \times W$ [S1, unofficial].
* `sample_mask_out`: A tensor of shape $1 \times H \times W$, containing `1` where samples were taken and `0` elsewhere [S1, unofficial].
* `default_values`: A vector of doubles providing default values for the 8 channels, used in the PyTorch interface `ScatterSamplesToImage` [S1, unofficial].

**Data Structures:**
* `sample_positions`: $2 \times N$ tensor [S1, unofficial].
* `samples`: $C \times N$ tensor [S1, unofficial].
* `image_out`: $C \times H \times W$ tensor [S1, unofficial].
* `sample_mask_out`: $1 \times H \times W$ tensor [S1, unofficial].

**Steps:**
1. Initialize `image_out` and `sample_mask_out` [S1, unofficial].
2. Initialize `sample_mask_out` to all zeros [S1, unofficial].
3. For each sample index $k$ from $0$ to $N-1$:
   a. Retrieve position $(x_k, y_k)$ from `sample_positions`[:, k] [S1, unofficial].
   b. Retrieve values $v_{k,1}, \dots, v_{k,C}$ from `samples`[:, k] [S1, unofficial].
   c. Convert $(x_k, y_k)$ to integer pixel coordinates $(i, j)$ by flooring or rounding [G].
   d. Check if $(i, j)$ is within the image boundaries $[0, W-1] \times [0, H-1]$ [S1, unofficial]. If outside, ignore this sample [S1, unofficial].
   e. For each channel $c$ from $0$ to $C-1$: write $v_{k,c}$ to `image_out`[c, j, i] [S1, unofficial].
   f. Set `sample_mask_out`[0, j, i] = 1 [S1, unofficial].

**Pseudocode:**
```python
import math

def scatter_samples_to_image(sample_positions, samples, image_shape, default_values=None):
    C, N = samples.shape
    H, W = image_shape
    # Initialize output tensors
    image_out = [[[0.0] * W for _ in range(H)] for _ in range(C)]
    sample_mask_out = [[[0.0] * W for _ in range(H)] for _ in range(1)]
    # Apply default values if provided; otherwise pixels receiving no samples remain untouched
    if default_values is not None:
        for c in range(C):
            for r in range(H):
                for col in range(W):
                    image_out[c][r][col] = default_values[c]
    # Scatter samples
    for k in range(N):
        x = sample_positions[0][k]
        y = sample_positions[1][k]
        col = math.floor(x)
        row = math.floor(y)
        # Check boundaries
        if 0 <= col < W and 0 <= row < H:
            for c in range(C):
                image_out[c][row][col] = samples[c][k]
            sample_mask_out[0][row][col] = 1.0
    return image_out, sample_mask_out
```

**Parameters:**
* `default_values`: A vector of doubles providing default values for the 8 channels, used in the PyTorch interface `ScatterSamplesToImage` [S1, unofficial].

**Edge Cases and Pitfalls:**
* Samples located outside the image boundaries are ignored [S1, unofficial].
* Pixels in the output image that receive no samples are left untouched (no default value overwriting) [S1, unofficial].
* Multiple samples may map to the same pixel; the last sample processed overwrites previous values [G].

## Subtopics

### 2D Trace Heatmap Rendering
A variant that uses scatter-like logic to render a 2D heatmap from trace data [S2, unofficial]. It initializes a canvas of width `traceCount * 2` and height `sampleCount` [S2, unofficial]. It computes min and max values across the 2D array `samples[traceCount][sampleCount]`, calculating range as `max - min` (defaulting to 1 if 0 to avoid division by zero) [S2, unofficial]. For each pixel $(i, j)$, it calculates normalized value $v = (samples[i][j] - min) / range$, computes color intensity $color = \lfloor v \times 255 \rfloor$, and sets RGBA to $(color, color, color, 255)$ [S2, unofficial].

## Operating characteristics
* **Time Complexity:** $O(N)$, where $N$ is the number of samples, as each sample is processed once [G].
* **Memory Complexity:** $O(C \times H \times W)$ for the output image and mask [G].
* **Measured Performance:** Not given in the sources. [G]
* **Scaling:** Not given in the sources. [G]
* **Strengths:** Extremely fast for direct mapping; no kernel evaluation or sorting required [G].
* **Limitations:** No anti-aliasing or smoothing; artifacts appear if samples are sparse or misaligned with pixels [G].
* **When to use:** When samples are already on a grid or when a raw, unfiltered representation is desired [G].
* **When not to use:** When smooth visualization or blending is required; use [Splatting](23-splatting.md) instead [G].
