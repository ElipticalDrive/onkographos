# Splat Cloud Loading

Also called: Runtime Gaussian Splat Loading, SPZ Download & Processing Pipeline, SPZ/PLY Parsing, WorldLabsWorldManager Load Pipeline

## Overview
Splat Cloud Loading is an asynchronous method for loading 3D Gaussian Splat (3DGS) data from compressed files (`.spz` or `.ply`) off the main thread, returning `null` while the operation is in progress [S2, unofficial][S3, unofficial]. It solves the problem of blocking the UI thread during large asset ingestion by handling network I/O, decompression, and binary parsing in the background [S2, unofficial][S3, unofficial]. It is distinguished from sibling methods by its specific support for Niantic's `.spz` format versions 2–4 and its integration with the `SplatNode` composable, which automatically handles camera-relative sorting for the scene view [S2, unofficial][S3, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** `fileLocation` (String) specifying the source of the splat data. Supported formats include asset paths (e.g., `"splats/scan.spz"`), absolute file paths, and URIs (`file://`, `content://`, `http(s)://`) [S2, unofficial][S3, unofficial].
*   **Output:** `SplatCloud?` (Nullable `SplatCloud` object). Returns `null` while loading or if the file cannot be read. Returns a non-empty `SplatCloud` instance upon successful completion [S2, unofficial][S3, unofficial].

**Data Structures**
*   **SplatCloud:** The in-memory representation of the loaded splats. It contains a `count` property indicating the total number of splats and must be non-empty upon successful load [S2, unofficial].

**Steps**
1.  **State Check:** Check if the world is already loaded or currently loading. If loaded, return the existing renderer immediately. If currently loading, log a warning and return `null` [S1, unofficial].
2.  **Resource Cleanup:** Unload all previously loaded worlds except the default placeholder to free memory slots before starting the new load [S1, unofficial].
3.  **URL Resolution:** If loading from a remote source, resolve the download URL by mapping a preferred resolution enum to a string key (`"full_res"`, `"500k"`, or `"100k"`) and calling `GetUrl(key)` or falling back to `GetBestResolutionUrl()` [S1, unofficial].
4.  **Asynchronous Download:** Download the file as binary bytes asynchronously, reporting progress at intervals of `0.05f` [S1, unofficial].
5.  **Background Processing:** Process the raw bytes on a background thread using `RuntimeSplatProcessing.ProcessSPZBytes`, passing format parameters derived from the selected quality preset [S1, unofficial].
6.  **Parsing:** Parse the binary data using pure Kotlin parsers (`SplatParser.fromSpz`, `SplatParser.fromPly`, or `SplatParser.parse` for auto-detection) which support `.spz` versions 2 and 3 (gzip compressed) and version 4 (ZSTD streams, the current Niantic format) [S2, unofficial][S3, unofficial].
7.  **Scene Integration:** Spawn a new `GameObject` named `World_{display_name}`, set its parent to `worldParent`, and apply a `-180°` rotation around the X axis [S1, unofficial].
8.  **Renderer Attachment:** Attach a `GaussianSplatRenderer` component, assign required shaders, and load the processed runtime data into the renderer [S1, unofficial].

**Pseudocode**
```python
def load_splat_cloud(file_location: str) -> SplatCloud | None:
    # Step 1: State check
    if world_is_loaded():
        return get_existing_renderer()
    if world_is_loading():
        log_warning("World is currently loading")
        return None

    # Step 2: Resource cleanup
    unload_all_worlds_except_default()

    # Step 3 & 4: URL resolution and async download
    if is_remote_uri(file_location):
        url = resolve_download_url(map_resolution_to_key(file_location))
        bytes_data = download_async(url, progress_step=0.05)
    else:
        bytes_data = read_file_bytes(file_location)

    # Step 5 & 6: Background processing and parsing
    # SplatParser handles .spz (v2, v3, v4) and .ply
    cloud = process_and_parse_bytes(bytes_data)

    # Step 7 & 8: Scene integration
    spawn_game_object(name=f"World_{display_name}", parent=world_parent)
    apply_rotation(axis="X", degrees=-180)
    attach_renderer(component="GaussianSplatRenderer")
    assign_shaders()
    load_data_into_renderer(cloud)

    return cloud
```

**Parameters**
*   `fileLocation`: String. The source path or URI. Typical values: `"splats/raccoon_family.spz"` (asset), `"file:///path/to/cloud.ply"` [S2, unofficial][S3, unofficial].

**Edge Cases and Pitfalls**
*   **Null Return:** The function returns `null` during the loading phase. The consumer must handle this, typically by checking for null before passing to `SplatNode` [S3, unofficial].
*   **Format Support:** Only `.spz` (v2, v3, v4) and `.ply` are supported. Other formats will fail during parsing [S3, unofficial].
*   **Concurrency:** The parsing is implemented in pure Kotlin to ensure compatibility across all target platforms (Android, iOS, Desktop, Web) [S3, unofficial].

## Subtopics

### SplatNode
Renders a `SplatCloud` as oriented ellipses with premultiplied-alpha blending [S2, unofficial]. It sets itself apart by automatically sorting splats back-to-front relative to the scene camera when `cameraPositionProvider` is null, eliminating popping during orbit [S2, unofficial][S3, unofficial]. Choose it for standard scene rendering where camera-relative depth sorting is required. See [Splat Data Structure (ISplatSource)](10289-splat-data-structure-isplatsource.md).

### SplatParser
Parses raw binary bytes into a `SplatCloud` structure [S2, unofficial]. It distinguishes itself by auto-detecting `.spz` versus `.ply` formats and natively supporting `.spz` versions 2, 3, and 4 (ZSTD) using pure Kotlin across all target platforms [S2, unofficial][S3, unofficial]. Choose it when loading compressed splat assets without platform-specific native libraries. See [Splat Data Structure (ISplatSource)](10289-splat-data-structure-isplatsource.md).

## Operating characteristics
*   **Time Complexity:** Dominated by I/O and decompression. Parsing scales linearly with the number of splats, as indicated by the `count` property and sequential byte processing [S2, unofficial]. The method is asynchronous, so it does not block the main thread [S3, unofficial].
*   **Memory Complexity:** Proportional to the size of the uncompressed splat cloud. The method unloads previous worlds to free memory slots before loading new ones [S1, unofficial].
*   **Performance:** Parsing is performed in pure Kotlin, ensuring cross-platform consistency on every target [S3, unofficial]. Not given in the sources whether it is slower than native C++ implementations.
*   **Strengths:** Non-blocking UI execution, support for modern compressed formats (SPZ v4), automatic camera sorting in `SplatNode` [S2, unofficial][S3, unofficial].
*   **Limitations:** Returns `null` during load, requiring null-checks in the UI. Only supports `.spz` (v2, v3, v4) and `.ply` formats [S2, unofficial][S3, unofficial].

## Background
This method is part of the SceneView library ecosystem, specifically introduced in commits related to sorting splats for the scene camera by default and adding the `rememberSplatCloud` composable [S2, unofficial][S3, unofficial]. It integrates with the WorldLabs Unity plugin ecosystem concepts (referenced in [S1, unofficial]) but is implemented in Kotlin for the SceneView Android/JVM targets [S1, unofficial][S2, unofficial][S3, unofficial].
