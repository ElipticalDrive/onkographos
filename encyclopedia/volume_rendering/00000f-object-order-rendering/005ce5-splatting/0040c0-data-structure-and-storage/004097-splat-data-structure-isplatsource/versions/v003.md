# Splat Data Structure (ISplatSource)

Also called: ISplatSource

## Overview
The Splat Data Structure (ISplatSource) is an abstract interface designed for the asynchronous loading of 3D Gaussian Splat data, returning a structured `LoadResult` upon completion [S1, unofficial]. It solves the problem of blocking the main execution thread during the parsing of large splat captures by decoupling data ingestion from rendering [S1, unofficial]. It is distinguished from synchronous loading methods by its non-blocking callback mechanism and its specific handling of spherical harmonic (SH) coefficient packing for GPU consumption [S1, unofficial].

## How it works
**Inputs and Outputs:**
The interface accepts a callback function `Callback` of type `std::function<void(LoadResult)>` [S1, unofficial]. The output is a `LoadResult` struct containing the loaded splat data, SH degree, and error status [S1, unofficial].

**Data Structures:**
The `LoadResult` struct layout is defined as follows [S1, unofficial]:
*   `splats`: `std::vector<SplatGPU>` — The container for the loaded splat primitives.
*   `sh_degree`: `int` — The degree of spherical harmonics used for color representation.
*   `error`: `std::string` — Non-empty string if loading failed; empty on success.
*   `ok()`: A method returning `true` if `error` is empty.

The `SplatGPU` structure implies a GPU-ready layout. Based on the implementation details in the source, the spherical harmonic coefficients are packed into a Texture Buffer Object (TBO) using `GL_RGBA16F` [S1, unofficial].
*   **SH Packing Layout:** For a given active SH degree, the number of non-DC coefficients per splat is calculated as:
    $$ \text{sh\_coeffs\_per\_splat} = (\text{active\_sh\_degree} + 1)^2 - 1 $$
    These coefficients exclude the DC term (index 0) [S1, unofficial].
*   **Memory Layout:** The coefficients are stored in a flat array where each coefficient occupies one `RGBA16F` texel (8 bytes). The layout is interleaved by splat: `[splat0_c1, splat0_c2, ..., splat1_c1, splat1_c2, ...]` [S1, unofficial].
*   **Coefficient Packing:** Each non-DC coefficient (3 floats) is packed into a single `RGBA16F` texel as `(R, G, B, 0)`, where the RGB components are the coefficient values converted to half-precision floats (`floatToHalf`) [S1, unofficial].

**Numbered Steps:**
1.  Initialize the `ISplatSource` instance.
2.  Call `start(Callback cb)`, passing a callback function that accepts a `LoadResult` [S1, unofficial].
3.  The implementation parses the source file (e.g., `.spz` or `.ply`) asynchronously [S1, unofficial].
4.  Upon completion, the callback is invoked with a `LoadResult` containing the `splats` vector and `sh_degree` [S1, unofficial].
5.  The caller checks `result.ok()` to verify success; if false, `result.error` contains the failure reason [S1, unofficial].

**Parameters and Edge Cases:**
*   **SH Degree:** The `sh_degree` determines the number of coefficients. If `sh_degree` is 0, no non-DC coefficients are loaded, and `sh_coeffs_per_splat` is 0 [S1, unofficial].
*   **Precision:** Coefficients are stored as half-precision floats (`uint16_t` via `floatToHalf`) to optimize memory bandwidth for the `GL_RGBA16F` TBO [S1, unofficial].
*   **Error Handling:** The `error` field is the sole indicator of failure; a successful load always results in an empty string [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Asynchronous loading time depends on I/O speed and file size (`.spz`/`.ply` parsing). The `start` call is $O(1)$ [S1, unofficial].
*   **Memory Complexity:** $O(N \cdot C)$, where $N$ is the number of splats and $C$ is the number of SH coefficients per splat. The SH data is packed tightly into `RGBA16F` texels [S1, unofficial].
*   **Strengths:** Non-blocking UI/main thread; efficient GPU memory layout for SH coefficients [S1, unofficial].
*   **Limitations:** Requires a callback-based architecture; error handling is string-based [S1, unofficial].
*   **When to use:** Real-time applications requiring smooth frame rates during asset loading [S1, unofficial].

## Background
The `ISplatSource` interface originates from the `splat-ros/RVizSplat` project, an unofficial implementation for integrating 3D Gaussian Splatting into ROS-based visualization tools [S1, unofficial]. It was developed to address the performance bottlenecks of synchronous splat loading in interactive 3D environments.
