# Splat Data Structure (ISplatSource)
Also called: ISplatSource

## Overview
The Splat Data Structure (ISplatSource) is an abstract interface for loading splat data asynchronously, returning a `LoadResult` upon completion [S1, unofficial]. It decouples data ingestion from the rendering pipeline to prevent main-thread blocking [S1, unofficial]. It provides the foundational contract that sibling methods implement: `Splat Cloud Loading` handles specific file formats, while the `LOD Download Manager` manages prioritized network fetching [G].

## How it works
**Inputs and Outputs:**
The interface requires no direct input parameters for initialization but requires a callback function to handle the asynchronous result [S1, unofficial]. The output is delivered via the callback as a `LoadResult` struct containing the loaded splat primitives, spherical harmonic degree, and error status [S1, unofficial].

**Data Structures:**
The `LoadResult` struct contains four fields: `splats` (`std::vector<SplatGPU>`), `sh_degree` (`int`), `error` (`std::string`, non-empty on failure), and `ok()` (returns `true` if `error` is empty) [S1, unofficial]. The `SplatGPU` structure holds geometric and photometric data for each primitive [S1, unofficial]. Its spherical harmonic coefficients (`sh`) are indexed such that `sh[0]` is the DC component, while `sh[1]` onward are non-DC coefficients [S1, unofficial]. Non-DC coefficients are packed into GPU textures as `RGBA16F` texels in the layout `[splat0_c1, splat0_c2, …, splat1_c1, splat1_c2, …]`, where each coefficient occupies `(R, G, B, 0)` and the total count per splat is `(active_sh_degree + 1)^2 - 1` [S1, unofficial].

**Steps:**
1. Instantiate the concrete `ISplatSource` implementation.
2. Call `start(Callback cb)`, passing a function of type `std::function<void(LoadResult)>` [S1, unofficial].
3. The implementation performs background I/O and parsing [S1, unofficial].
4. Upon completion, the callback is invoked with a `LoadResult` object [S1, unofficial].
5. The caller evaluates `result.ok()`. If `false`, `result.error` contains the failure reason [S1, unofficial]. If `true`, `result.splats` contains the loaded data [S1, unofficial].

- `Callback`: A function or lambda accepting a `LoadResult` instance [S1, unofficial].

**Edge Cases:**
- Network failures or file corruption populate `error` with a descriptive string [G].
- The `splats` vector may be empty if the source contains no primitives [G].
- Precision limits in `RGBA16F` packing may affect high-dynamic-range SH coefficients [G].

## Subtopics

### [Splat Cloud Loading](13758-splat-cloud-loading.md)
An asynchronous method for loading 3D Gaussian Splat data from compressed files (`.spz` or `.ply`) off the main thread. It is distinguished by its support for Niantic's `.spz` format and integration with `SplatNode` for camera-relative sorting.

### [LOD Download Manager](14938-lod-download-manager.md)
A component that manages asynchronous, prioritized downloading of 3D Gaussian splat data organized in a Level of Detail hierarchy. It differs by dynamically adapting to predicted bandwidth and viewport position.

## Operating characteristics
**Time and Memory Complexity:**
Not given in the sources. Complexity depends on the concrete implementation, file size, network speed, and decompression algorithm [G].

**Measured Performance:**
Not given in the sources.

**Strengths and Limitations:**
- **Strengths:** Prevents main-thread blocking during large asset ingestion [G]. Provides a unified contract for diverse loading backends [G].
- **Limitations:** The abstract interface does not define the loading mechanism; performance and feature parity depend entirely on the concrete implementation [G].

**When to Use:**
Use when loading large splat datasets that would otherwise block the main thread [G]. Choose a specific implementation based on the data format and source (local file vs. network) [G].

## Background
The interface was defined in [S1, unofficial] to support asynchronous data ingestion in a ROS-based visualization context [S1, unofficial]. It belongs to the splatting family, which treats volumetric data as geometric or parametric primitives [G].
