# Layered Splat Scheduling (Case I)

Also called: Layered splats with segmented objects scheduling, Problem 1

## Overview
Layered Splat Scheduling (Case I) is a scheduling method for delivering layered 3D Gaussian splats where objects are segmented, allowing the scheduler to select both specific objects and their quality layers [S1]. It solves the problem of maximizing total visual utility under variable bandwidth constraints by formulating the selection as a precedence-constrained generalized assignment problem [S1]. Unlike Case II, which lacks object segmentation and offers only coarse-grained layer control, Case I provides fine-grained control over which objects and layers to download, enabling selective rendering of specific scene components [S1].

## How it works
The method determines which splats to download in each time slot to maximize utility while respecting bandwidth limits and layer precedence constraints.

**Inputs and Outputs:**
*   **Inputs:**
    *   $J$: Set of objects.
    *   $L_j$: Set of layers for object $j$.
    *   $\Delta U_{jl}[t]$: Utility gain of downloading layer $l$ of object $j$ at time $t$.
    *   $\Delta c_{jl}$: Cost (size) of downloading layer $l$ of object $j$.
    *   $B[t]$: Available predicted bandwidth at time $t$.
    *   $T$: Set of time slots.
*   **Outputs:**
    *   Binary decision variables $x_{jl}[t]$ indicating if layer $l$ of object $j$ is downloaded at time $t$.

**Data Structures:**
*   $x_{jl}[t]$: Binary variable, 1 if layer $l$ of object $j$ is downloaded in time slot $t$, 0 otherwise.
*   $y_{jl}[t]$: Helper variable, 1 if layer $l$ of object $j$ has been downloaded before time slot $t$, 0 otherwise.

**Formulas:**
The problem is defined as maximizing total utility subject to bandwidth, uniqueness, and precedence constraints [S1]:

$$
\max_{x,y} \sum_{t} \sum_{j} \sum_{l} \Delta U_{jl}[t] y_{jl}[t]
$$

Subject to:
1.  **Bandwidth Constraint:** The total size of downloaded splats in time slot $t$ must not exceed available bandwidth $B[t]$ [S1]:
    $$
    \sum_{j} \sum_{l} \Delta c_{jl} x_{jl}[t] \le B[t] \quad \forall t
    $$
2.  **Uniqueness Constraint:** Each layer of each object can be downloaded only once over the entire duration [S1]:
    $$
    \sum_{t} x_{jl}[t] \le 1 \quad \forall j, l
    $$
3.  **Precedence Constraint:** Layer $l$ can only be downloaded if the preceding layer $l-1$ has been downloaded in a previous time slot [S1]:
    $$
    x_{jl}[t] \le \sum_{t' < t} x_{jl}[t'] \quad \forall j, l, t
    $$

4.  **Binary Constraints:**
    $$
    x_{jl}[t], y_{jl}[t] \in \{0, 1\} \quad \forall j, t

**Algorithm:**
The full problem is NP-Hard [S1]. However, for a single time slot, it reduces to a Multiple Choice Knapsack Problem (MCKP) [S1].

1.  **Solve for a single time slot:** Reduce Problem 1 to an MCKP [S1].
2.  **Dynamic Programming:** Solve the MCKP using dynamic programming in pseudo-polynomial time [S1].
3.  **Iterate:** Repeat for each time slot $t$ using predicted bandwidth $B[t]$ [S1].

**Pseudocode:**
```python
def solve_single_slot(objects, layers, utilities, costs, bandwidth):
    """
    Solves the scheduling problem for a single time slot using DP.
    objects: list of object IDs
    layers: dict mapping object_id -> list of layer IDs
    utilities: dict mapping (obj_id, layer_id) -> utility value
    costs: dict mapping (obj_id, layer_id) -> cost size
    bandwidth: int, available bandwidth for this slot
    
    Returns: set of (obj_id, layer_id) to download
    """
    # This is a Multiple Choice Knapsack Problem variant.
    # Each object-layer combination is an item.
    # However, precedence constraints (layer l requires l-1) 
    # must be handled. In a single slot, if l-1 was not downloaded 
    # in previous slots, l cannot be downloaded.
    # Assuming y_jl[t] is 0 if l-1 not downloaded previously,
    # then x_jl[t] must be 0.
    
    # Filter out items that violate precedence based on previous state
    valid_items = []
    for obj in objects:
        for layer in layers[obj]:
            # Check if previous layer is available/downloaded
            if layer == 0 or is_layer_downloaded(obj, layer - 1):
                valid_items.append({
                    'obj': obj,
                    'layer': layer,
                    'value': utilities[(obj, layer)],
                    'weight': costs[(obj, layer)]
                })
    
    # Solve MCKP using DP
    # dp[w] = max utility with weight w
    dp = [0] * (bandwidth + 1)
    # To reconstruct solution, store choices
    choice = [[None] * (bandwidth + 1) for _ in range(len(valid_items))]
    
    for i, item in enumerate(valid_items):
        for w in range(bandwidth, item['weight'] - 1, -1):
            if dp[w - item['weight']] + item['value'] > dp[w]:
                dp[w] = dp[w - item['weight']] + item['value']
                choice[i][w] = item
            else:
                choice[i][w] = choice[i-1][w] if i > 0 else None
                
    # Reconstruct solution
    selected = []
    w = bandwidth
    for i in range(len(valid_items) - 1, -1, -1):
        if choice[i][w] == valid_items[i]:
            selected.append((valid_items[i]['obj'], valid_items[i]['layer']))
            w -= valid_items[i]['weight']
            
    return selected
```

**Edge Cases and Pitfalls:**
*   **NP-Hardness:** The general problem is NP-Hard, so exact solutions for multiple time slots with complex dependencies are intractable [S1].
*   **Prediction Errors:** Bandwidth and viewport predictions are imperfect, which affects the optimality of the single-slot greedy approach [S1].
*   **Partial Downloads:** Layers can be partially downloaded across time slots, but within a single slot, precedence must be respected relative to previous slots [S1].

## Subtopics

### L3GS with Object Segmentation
A configuration where the scheduler has flexibility to choose both objects and layers, resulting in a larger selection space compared to non-segmented layered splats (Case II) [S1]. The scheduler can selectively render specific objects by excluding others, such as excluding a truck to render only the background or rendering only the truck splats [S1]. Rendering only the truck splats takes 25.9% of the total splats [S1]. This approach enables more efficient rendering based on user preferences, such as prioritizing foreground objects [S1].

## Operating characteristics
*   **Complexity:** The general problem is NP-Hard [S1]. The single-time-slot reduction is solvable in pseudo-polynomial time via dynamic programming [S1].
*   **Performance:** Incorporating object-level decisions enhances performance compared to non-segmented layered splats (Case II) [S1].
*   **Strengths:** Fine-grained control over scene content; allows selective rendering of specific objects [S1].
*   **Limitations:** Relies on accurate bandwidth and viewport predictions, which are difficult to obtain far into the future [S1].

## Background
The method is part of the L3GS (Layered 3D Gaussian Splats) system, introduced by Yi-Zhen Tsai, Xuechen Zhang, Zheng Li, and Jiasi Chen in 2025 [S1]. It addresses the challenge of delivering 3D Gaussian splats over variable network conditions by leveraging semantic segmentation of 3D scenes into objects and layers [S1].
