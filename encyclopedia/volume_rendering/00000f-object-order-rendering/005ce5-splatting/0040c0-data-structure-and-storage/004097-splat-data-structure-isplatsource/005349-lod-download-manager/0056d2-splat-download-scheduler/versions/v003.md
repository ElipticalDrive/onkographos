# Splat Download Scheduler


## Overview
The Splat Download Scheduler determines which 3D Gaussian splats to download and in what order to maximize total visual utility while respecting variable network bandwidth constraints [S1]. It solves the problem of selecting splats from layered or separate representations, with or without object segmentation, by formulating the selection as an optimization problem [S1]. Unlike static LOD selection, it dynamically adapts to predicted bandwidth and viewport position to prioritize splats that contribute most to the current user view [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Predicted bandwidth $B[t]$ for each time slot $t$; splat data including layer ID $l$, optional object ID $j$, cost $c_{jl}$, and pre-computed utility $U_{jl}[t]$; viewport position and orientation at time $t$ [S1].
*   **Outputs:** Binary decision variables $x_{jl}[t]$ indicating whether to download object $j$ at layer $l$ at time $t$ [S1].

**Data Structures:**
*   **Splat List:** A collection of splats, each containing:
    *   `id`: Unique identifier.
    *   `object_id`: Integer ID of the object (optional, if scene is segmented).
    *   `layer_id`: Integer ID of the quality layer (0 is base).
    *   `cost`: Size in bytes.
    *   `utility`: Pre-computed scalar value.
    *   `opacity`: Static opacity property.
    *   `center_3d`: 3D coordinates of the splat center.
*   **Bandwidth Predictor:** Provides $B[t]$ for the next time slot [S1].

**Numbered Steps:**
1.  Divide time into slots of duration $T$ indexed by $t$ [S1].
2.  Predict bandwidth $B[t]$ for each slot [S1].
3.  Pre-compute splat utilities offline using viewport position and orientation [S1].
4.  Calculate total object utility $U_{jl}[t]$ and marginal utility $\Delta U_{jl}[t]$ for layered cases [S1].
5.  Select splats to download by solving the appropriate optimization problem based on representation type and segmentation [S1].
6.  Enforce dependency constraints: enhancement layers only download if base/lower layers were previously downloaded [S1].

**Formulas:**
*   $U_{ijl}[t] = closeness_{ijl}[t] \times overlap_{ijl}[t] \times opacity_{ijl}$ [S1]
*   $U_{jl}[t] = \sum_{i \in \text{splats}(j,l)} U_{ijl}[t]$ [S1]
*   $\Delta U_{jl}[t] = U_{jl}[t] - U_{j,l-1}[t]$ [S1]

Where:
*   $closeness_{ijl}[t]$: 3D Euclidean distance between the splat center and the viewport center [S1].
*   $overlap_{ijl}[t]$: 2D area of the splat projected onto the 2D viewport [S1].
*   $opacity_{ijl}$: Static opacity property stored in the splat data structure [S1].
*   $U_{jl}[t]$: Total utility of object $j$ at layer $l$ [S1].
*   $\Delta U_{jl}[t]$: Marginal utility of layer $l$ [S1].

**Parameters:**
*   $B[t]$: Predicted bandwidth in time slot $t$ [S1].
*   $c_{jl}$: Cost of object $j$ at layer $l$ (or version $l$ for separate representations) [S1].
*   $U_{jl}[t]$: Utility of object $j$ from layer $l$ at time $t$ [S1].
*   $T$: Duration of time slot [S1].

**Edge Cases and Pitfalls:**
*   Precision issues may arise in distance and overlap calculations [S1].
*   Boundary condition: layer $l=0$ (base layer) has no predecessor, so precedence checks must handle $l-1$ gracefully [S1].
*   NP-hard complexity requires approximation algorithms (knapsack or progressive loading) rather than exact solvers [S1].

**Pseudocode:**
```python
import math

def compute_splat_utilities(splats, viewport):
    """Pre-compute utilities for all splats based on current viewport [S1]."""
    for splat in splats:
        # closeness: 3D Euclidean distance between splat center and viewport center [S1]
        dist = math.sqrt(sum((splat.center_3d[k] - viewport.center_3d[k])**2 for k in range(3)))
        # [G] Exact 3D-to-2D projection area calculation is not given in the sources.
        overlap = 0.0
        # Utility formula (1) [S1]
        splat.utility = dist * overlap * splat.opacity
    return splats

def schedule_splats(splats, bandwidth_predictor, viewport, time_slot, downloaded_layers):
    """
    Determines which splats to download for the current time slot [S1].
    Args:
        splats: List of splat objects with attributes: id, object_id, layer_id, cost, opacity, center_3d, utility.
        bandwidth_predictor: Callable returning predicted bandwidth B[t].
        viewport: Object with attribute center_3d.
        time_slot: Current time index t.
        downloaded_layers: Dict mapping object_id to set of downloaded layer_ids.
    Returns:
        List of splat IDs to download, updated downloaded_layers.
    """
    B_t = bandwidth_predictor(time_slot)
    selected_ids = []
    bandwidth_used = 0
    # Pre-compute utilities if not already done
    splats = compute_splat_utilities(splats, viewport)

    # Group splats by object and layer
    groups = {}
    for splat in splats:
        obj_id = splat.object_id if splat.object_id else "scene"
        groups.setdefault(obj_id, {}).setdefault(splat.layer_id, []).append(splat)

    # Process each object's layers
    for obj_id, layers in groups.items():
        for layer_id in sorted(layers.keys()):
            layer_splats = layers[layer_id]
            # Precedence constraint: layer l requires l-1 downloaded previously [S1]
            if layer_id == 0 or (layer_id - 1) in downloaded_layers.get(obj_id, set()):
                # Sort by utility-to-cost ratio for greedy knapsack selection [S1]
                layer_splats.sort(key=lambda s: s.utility / s.cost, reverse=True)
                for splat in layer_splats:
                    if bandwidth_used + splat.cost <= B_t:
                        selected_ids.append(splat.id)
                        bandwidth_used += splat.cost
                        downloaded_layers.setdefault(obj_id, set()).add(layer_id)
                    else:
                        break
            # If precedence not met, skip layer
    return selected_ids, downloaded_layers
```

## Subtopics

### [Layered Splat Scheduling (Case I)](15804-layered-splat-scheduling-case-i.md)
Layered Splat Scheduling (Case I) is a scheduling method for delivering layered 3D Gaussian splats where objects are segmented, allowing the scheduler to select both specific objects and their quality layers. It solves the problem of maximizing total visual utility under variable bandwidth constraints by formulating the selection as a precedence-constrained generalized assignment problem. Unlike Case II, which lacks object segmentation and offers only coarse-grained layer control, Case I provides fine-grained control over which objects and layers to download, enabling selective rendering of specific scene components. Choose it when fine-grained object and layer selection is required for segmented scenes with layered representations.

### Splat Utility Function
A numerical utility value assigned to each splat to determine its importance for download prioritization by the scheduler, based on its contribution to the current user viewport [S1]. It is pre-computed offline [S1]. The utility of a splat $i$ in object $j$ at layer $l$ at time $t$ is $U_{ijl}[t] = closeness_{ijl}[t] \times overlap_{ijl}[t] \times opacity_{ijl}$, where $closeness$ is the 3D Euclidean distance between the splat center and viewport center, $overlap$ is the 2D projected area on the viewport, and $opacity$ is a static property [S1]. The total object utility is the sum of its splat utilities, and the marginal utility for layered representations is $\Delta U_{jl}[t] = U_{jl}[t] - U_{j,l-1}[t]$ [S1]. It differs from Global Significance Score (GSG) because GSG is viewport-independent and used for training layered splats, whereas this utility function is viewport-dependent to optimize the visual quality of the user's current viewport [S1].

### Separate Splat Scheduling (Case II)
A scheduling problem for separate (non-layered) splats with segmented objects, where subsequent versions replace prior ones, formulated as an NP-Hard problem [S1]. It is solved by loading versions in sequence (0 to $L$), similar to progressive JPEG [S1]. It differs from Case I by using $\max_{l} U_{jl}[t]$ in the objective (replacing versions) instead of summation, and lacking precedence constraints [S1].

## Operating characteristics
*   **Complexity:** The underlying optimization problems (Case I and II) are NP-hard [S1]. Case I is solved via knapsack approximation, and Case II via progressive loading [S1].
*   **Performance:** The scheduler adapts to variable bandwidth $B[t]$ [S1].
*   **Strengths:** Maximizes visual utility for the current viewport; handles multiple representation types (layered/separate) and scene structures (segmented/non-segmented) [S1].
*   **Limitations:** Requires pre-computation of utilities; NP-hard nature requires approximation [S1].
*   **When to use:** When network bandwidth is variable and visual quality of specific objects/viewport regions is critical [S1].

## Background
The Splat Download Scheduler was introduced in the L3GS (Layered 3D Gaussian Splats for Efficient 3D Scene Delivery) paper, presented at ACM MOBICOM ’25 in November 2025 [S1]. It addresses the challenge of efficiently delivering 3D Gaussian splats over networks with limited and variable bandwidth [S1].
