# Hardware Accelerated Texture Atlases

Also called: Indirect Texture Sampling for Splatting, Texture Atlas Splatting

## Overview
Hardware Accelerated Texture Atlases organize per-primitive texture data into large 2D atlas textures to leverage GPU hardware filtering and caching, thereby avoiding multiple texture bindings and software-based sampling overhead [S1]. This method builds on [Splat Texture Layout & Mapping](7089-splat-texture-layout-mapping.md) by consolidating individual primitive textures into a unified structure that enables efficient, filtered attribute fetching during rendering [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** $P$ splats, each associated with a small fixed-resolution texture of size $T \times T$ texels; $C$ total attribute channels across all splats; GPU maximum texture dimensions [S1].
*   **Outputs:** One or more large 2D atlas textures; an indirection buffer mapping primitive IDs to atlas coordinates [S1].

**Data Structures:**
1.  **Atlas Texture(s):** Large 2D textures containing packed $T \times T$ charts [S1]. The layout is determined by GPU capabilities [S1]. If the total channels $C$ exceed the maximum supported by a single CUDA texture object (typically 4), multiple atlases are created [S1]. For example, one atlas may store Albedo (RGB) and Roughness (A), while another stores Tangent Normals (RGB) and Metallic (A) [S1].
2.  **Indirection Buffer:** A buffer storing the top-left corner coordinates $(chart\_idx\_x, chart\_idx\_y)$ for each primitive's texture chart within the atlas [S1]. This maps primitive IDs to their specific location in the atlas grid [S1].

**Parameters:**
*   $T$: Fixed resolution of each primitive's small texture, typically a power of 2 [S1].
*   $N_{chartsx}, N_{chartsy}$: Total number of charts along the width and height of the atlas, respectively [S1].

**Algorithm Steps:**

1.  **Determine Atlas Dimensions:** Calculate the maximum atlas dimensions supported by the GPU [S1]. Determine how many $T \times T$ textures fit along each dimension ($N_{chartsx}, N_{chartsy}$) [S1].
2.  **Calculate Atlas Count:** Compute the total number of textures per atlas based on channel constraints (e.g., max 4 channels per CUDA texture object) [S1]. Determine the total number of atlases needed to store all $P \times C$ textures [S1].
3.  **Construct Atlases:** Pack the $P \times C \times T \times T$ texel data into the atlas textures [S1]. Assign each primitive's texture to a specific chart position within the atlas [S1].
4.  **Build Indirection Buffer:** For each primitive $k$, store the top-left chart coordinates $(chart\_idx\_x_k, chart\_idx\_y_k)$ in the indirection buffer [S1].

**Rendering (Hardware Accelerated Texture Sampling):**
For a given primitive $k$ and local coordinates $(u, v)$:

1.  **Normalize Coordinates:** Map local coordinates to normalized texture coordinates $(s, t) \in [0, 1] \times [0, 1]$ [S1].
2.  **Retrieve Chart Coordinates:** Look up $(chart\_idx\_x, chart\_idx\_y)$ for primitive $k$ from the indirection buffer [S1].
3.  **Compute Atlas Coordinates:** Calculate the normalized coordinates within the atlas texture using the following formulas [S1]:
    $$
    s_{atlas} = \frac{chart\_idx\_x \cdot T + s \cdot T}{N_{chartsx} \cdot T}
    $$
    $$
    t_{atlas} = \frac{chart\_idx\_y \cdot T + t \cdot T}{N_{chartsy} \cdot T}
    $$
4.  **Sample:** Perform hardware-accelerated bilinear filtering using the CUDA `tex2D()` intrinsic [S1]:
    $$
    a_k(x, y) = \text{BilinearFilter}(atlas, s_{atlas}, t_{atlas})
    $$ [S1]

**Pseudocode:**

```python
import math

def bilinear_filter(tex_array, s, t):
    """Standard bilinear interpolation for a 2D texture array."""
    h, w = tex_array.shape
    s0 = int(math.floor(s * (w - 1)))
    s1 = min(s0 + 1, w - 1)
    t0 = int(math.floor(t * (h - 1)))
    t1 = min(t0 + 1, h - 1)
    ws = s * (w - 1) - s0
    wt = t * (h - 1) - t0
    return (tex_array[t0, s0] * (1 - ws) * (1 - wt) +
            tex_array[t0, s1] * ws * (1 - wt) +
            tex_array[t1, s0] * (1 - ws) * wt +
            tex_array[t1, s1] * ws * wt)

def construct_atlas(primitives, T, max_atlas_width, max_atlas_height, max_channels_per_atlas):
    charts_per_atlas_x = max_atlas_width // T
    charts_per_atlas_y = max_atlas_height // T
    charts_per_atlas = charts_per_atlas_x * charts_per_atlas_y

    C = primitives[0].channels
    textures_per_primitive = math.ceil(C / max_channels_per_atlas)
    total_textures = len(primitives) * textures_per_primitive
    num_atlases = math.ceil(total_textures / charts_per_atlas)

    atlases = [None] * num_atlases
    indirection_buffer = []
    current_atlas_idx = 0
    current_chart_idx = 0

    for p_idx, primitive in enumerate(primitives):
        atlas_idx = current_atlas_idx
        chart_idx = current_chart_idx
        chart_x = chart_idx % charts_per_atlas_x
        chart_y = chart_idx // charts_per_atlas_x

        indirection_buffer.append({
            'primitive_id': p_idx,
            'atlas_idx': atlas_idx,
            'chart_idx_x': chart_x,
            'chart_idx_y': chart_y
        })

        if atlases[atlas_idx] is None:
            atlases[atlas_idx] = [[0.0] * max_atlas_width for _ in range(max_atlas_height)]
        # Pack T x T x C data into atlas at (chart_x * T, chart_y * T) [G]
        
        current_chart_idx += 1
        if current_chart_idx >= charts_per_atlas:
            current_chart_idx = 0
            current_atlas_idx += 1

    return atlases, indirection_buffer

def sample_texture(primitive_idx, u, v, atlases, indirection_buffer, T, N_charts_x, N_charts_y):
    s = u
    t = v
    info = indirection_buffer[primitive_idx]
    chart_x = info['chart_idx_x']
    chart_y = info['chart_idx_y']
    atlas_idx = info['atlas_idx']

    # Formula from source: (chart_idx * T + s * T) / (N_charts * T)
    s_atlas = (chart_x + s) / N_charts_x
    t_atlas = (chart_y + t) / N_charts_y

    atlas = atlases[atlas_idx]
    color = bilinear_filter(atlas, s_atlas, t_atlas)
    return color
```

## Subtopics

### Hardware Accelerated Texture Sampling
A rendering technique where texture sampling is performed using GPU hardware filtering (e.g., CUDA `tex2D()`) rather than software interpolation [S1]. It maps primitive local coordinates to normalized atlas coordinates and retrieves values via bilinear filtering, leveraging dedicated texture caching for significant performance gains over manual global memory access [S1].

### Multi-Texturing for Splat Atlases
A process applied after shape/location refinement to generate a single texture atlas per splat by blending color information from multiple cameras [S2]. Unlike Yang et al. [2006] which uses view-dependent dynamic texture selection, or Sibbing et al. [2013] which uses a single texture per splat with three-pass rendering, this method blends multiple images into one atlas per splat to reduce inaccuracies from misalignments or irregular lighting [S2]. It works for splats even when they partially occlude each other, producing seamless transitions across surfaces [S2].

## Operating characteristics
*   **Performance:** Significantly faster than software-based sampling approaches due to the use of dedicated texture caching and filtering hardware [S1]. Improves performance by avoiding multiple texture bindings during rendering, reducing API overhead [S1].
*   **Memory:** Requires large 2D atlas textures [S1]. The number of atlases depends on GPU texture object channel limits (typically 4) and total attribute channels [S1].
*   **Limitations:** CUDA texture objects typically support up to 4 channels; exceeding this requires splitting attributes across multiple atlases, which increases complexity [S1].
*   **Use Cases:** Suitable for non-specular scenes where high-quality material and normal texture splatting is required, capable of reaching performance levels comparable to vanilla 3DGS on NeRF Synthetic datasets [S1].

## Background
The technique is detailed in "TextureSplat: Per-Primitive Texture Mapping for Reflective Gaussian Splatting" [S1]. It builds upon the concept of Ewa splatting [Gross 2002] [S1]. The multi-texturing aspect is derived from work on textured splat-based point clouds for handheld devices [S2], which itself references Pagés et al. [2015] for the blending approach [S2].
