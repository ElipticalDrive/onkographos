# Threshold Slicing and Anti-Aliasing

Also called: Threshold-based Hybrid Slicing

## Overview
Threshold Slicing and Anti-Aliasing is a hybrid volume rendering technique for curvilinear and unstructured grids that partitions cells based on a scalar value threshold to balance geometric precision and rendering performance [S1]. It solves the problem of aliasing and geometric inaccuracy in large datasets by rendering high-value cells as exact projected polygons while rendering low-value cells as anti-aliased ellipsoidal splats [S1]. It differs from pure polygonal slicing by handling inter-slice gaps and low-density regions via splatting, and from pure splatting by providing exact boundaries for significant features [S1].

## How it works
**Inputs:**
- Unstructured or curvilinear grid data.
- Scalar field values associated with cells.
- A user-defined volume threshold $T$.
- Camera parameters (view direction, projection type).

**Outputs:**
- A 2D image with anti-aliased boundaries for high-value structures and smooth, aliased-free representation of low-value regions.

**Data Structures:**
- **Cell List:** Each cell contains its geometric vertices, connectivity, and scalar value.
- **Render Queue:** Divided into two subsets: `PolygonCells` (value $\ge T$) and `SplatCells` (value $< T$).

**Steps:**
1. **Threshold Classification:** Iterate through all cells in the dataset. For each cell $C_i$ with scalar value $v_i$:
   - If $v_i \ge T$, add $C_i$ to `PolygonCells`.
   - If $v_i < T$, add $C_i$ to `SplatCells`.
2. **Polygonal Rendering (High Threshold):**
   - For each cell in `PolygonCells`, compute the convex hull of its projected vertices on the image plane [S1].
   - Determine front-facing and back-facing faces based on the view direction [S1].
   - For orthogonal projection, calculate the length $l$ of the viewing ray segment within the cell using the intersection of the ray with the front and back faces [S1].
   - Render these polygons using standard rasterization, applying opacity and color based on the scalar value.
3. **Splatting Rendering (Low Threshold):**
   - For each cell in `SplatCells`, compute an ellipsoidal kernel that approximates the cell's influence on the image plane [S1].
   - The ellipsoid parameters (center, axes, orientation) are derived from the cell's geometry and the viewing direction to ensure anti-aliasing [S1].
   - Render these ellipsoids as splats, accumulating color and opacity into the frame buffer. This handles cells that lie between slice planes or pixel samples, preventing gaps [S1].
4. **Compositing:**
   - Combine the results from polygonal rendering and splatting. Since polygons are rendered first (or with higher priority), they occlude splats where they overlap, ensuring sharp boundaries for high-value structures [S1].

**Parameters:**
- **Threshold $T$:** Determines the boundary between precise polygonal rendering and approximate splatting. Typical values depend on the data range and desired visual fidelity. Not given in the sources.

**Edge Cases and Pitfalls:**
- **Precision:** Floating-point errors in polygon projection may cause gaps or overlaps at the boundary between polygonal and splatted regions [G].
- **Degenerate Input:** Cells with zero volume or collapsed geometry should be skipped or handled as splats to avoid division by zero in polygon calculations [G].
- **Boundary Artifacts:** The transition between polygonal and splatted regions may exhibit visual discontinuities if opacity functions are not carefully matched [G].

## Operating characteristics
- **Time Complexity:** Depends on the distribution of cells relative to threshold $T$. Polygonal rendering is $O(N_p \cdot F)$ where $N_p$ is the number of polygonal cells and $F$ is the number of faces. Splatting is $O(N_s \cdot K)$ where $N_s$ is the number of splatted cells and $K$ is the kernel size.
- **Memory Complexity:** $O(N)$ to store cell data and render queues.
- **Measured Performance:** Interactive visualization on large datasets is supported, especially when parallelized [S1]. Performance scales with the ratio of high-value to low-value cells.
- **Strengths:** Provides sharp boundaries for significant features while maintaining anti-aliasing for less significant regions. Efficient for large datasets.
- **Limitations:** Visual discontinuities at the threshold boundary if not carefully tuned. Requires careful selection of threshold $T$.
- **When to Use:** When visualizing large unstructured/curvilinear grids where both precise boundaries and smooth anti-aliasing are required.
- **When Not to Use:** When uniform precision is required across all values, or when the threshold classification introduces unacceptable visual artifacts.

## Background
Originated in the context of volume rendering for curvilinear and unstructured grids, proposed by Silva et al. in 2003 [S1]. It builds on earlier work by Yagel et al. for polygonal slicing [S1] and Zwicker et al. for anti-aliased ellipsoidal splatting [S1]. The method was developed to address the limitations of pure polygonal or pure splatting approaches for large, complex datasets.
