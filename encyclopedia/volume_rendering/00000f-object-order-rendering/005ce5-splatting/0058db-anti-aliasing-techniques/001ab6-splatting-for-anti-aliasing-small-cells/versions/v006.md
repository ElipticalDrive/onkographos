# Splatting for Anti-aliasing Small Cells

Also called: Anti-Aliased Ellipsoidal Splats, Anti-Aliasing for Small Cells via Splatting, Anti-aliased Splatting for Small Cells, Gaussian Splatting for Small Cells, Gaussian ellipsoid splatting, Small cell anti-aliasing, Splatting Anti-Aliasing

## Overview
This method prevents the loss of geometric detail in adaptive mesh volume rendering by replacing small, easily missed polyhedral cells with anti-aliased ellipsoidal splats [S1][S3, unofficial]. While standard slicing renders large cells as polygons, this technique detects cells that are too small to be reliably sampled by pixel centers or slice planes and renders them as Gaussian ellipsoids [S2]. It sets itself apart from sibling methods like [Threshold Slicing and Anti-Aliasing](1447-threshold-slicing-and-anti-aliasing.md) by explicitly using ellipsoidal splats convolved with a Gaussian presampling filter to handle the anti-aliasing, rather than relying solely on polygon rasterization or post-processing blurs [S1][S3, unofficial].

## How it works
The method integrates with a slicing-based volume renderer. It operates on unstructured or curvilinear grids where cells vary significantly in size [S1].

### Inputs and Outputs
*   **Input:** A set of polyhedral cells from an adaptive mesh, a transfer function mapping cell properties (volume, density) to RGBA, a slicing direction, and a volume threshold $V_{thresh}$ [S1][S3, unofficial].
*   **Output:** A rendered image where large cells are rendered as polygons and small cells are rendered as anti-aliased splats, composited correctly without overlapping opaque regions [S3, unofficial].

### Data Structures
1.  **Cell List:** Contains cell geometry (vertices), volume $V_c$, and center of gravity $\mathbf{c}_g$ [S1][S3, unofficial].
2.  **Small Cell List:** Cells where $V_c < V_{thresh}$ [S2].
3.  **Texture Map:** A 2D texture array storing pre-computed splat rectangles for consecutive slices to optimize rendering [S1][S3, unofficial].
4.  **Stencil Buffer:** A depth buffer variant recording which screen pixels are covered by large cell polygons [S3, unofficial].

### Parameters
*   $V_{thresh}$: The volume threshold distinguishing "small" from "large" cells. Not given in the sources.
*   Gaussian Filter Width: Determines the size of the anti-aliasing blur. Not given in the sources.

### Steps

1.  **Classification:** For each cell in the mesh, calculate its volume $V_c$. If $V_c < V_{thresh}$, classify it as a small cell; otherwise, classify it as a large cell [S1][S3, unofficial].
2.  **Ellipsoid Fitting:** For each small cell, fit a Gaussian ellipsoid that approximates the cell's shape [S1][S3, unofficial].
    *   *Note:* In curvilinear grids with a slowly varying Jacobian derivative matrix for the mapping from computational to physical coordinates, these splats sum to near unity at any point, ensuring smooth interpolation of the scalar field [S1][S3, unofficial].
3.  **Assignment:** Assign each small cell to the closest slice plane perpendicular to the current viewing direction [S1][S3, unofficial].
4.  **Preprocessing (Splat Generation):**
    a.  Sort the small cells assigned to each slice plane by the depth of their centers of gravity, from back to front [S1][S3, unofficial].
    b.  Project each small cell's ellipsoid onto the image plane to determine its footprint [S3, unofficial].
    c.  Convolve the footprint projection of each splat with a Gaussian presampling filter in the image plane to create an enlarged 2D splat for anti-aliasing [S1][S3, unofficial].
    d.  Determine the rectangular bounding box that encloses the elliptical footprint of the enlarged splat [S1][S3, unofficial].
    e.  Calculate the RGBA color for the splat based on the transfer function, the cell volume, and the enlarged footprint size [S1][S3, unofficial].
    f.  Render the enlarged splat into a temporary image buffer in back-to-front order [S1][S3, unofficial].
    g.  Read back the temporary image to determine the global rectangle enclosing all non-zero values for the current set of slices [S1][S3, unofficial].
    h.  Create texture maps per slicing direction. Each map contains as many of the textured rectangles (from consecutive slices) as would fit within the texture memory limits [S1][S3, unofficial].
5.  **Interactive Rendering:**
    a.  Load the texture maps for the current slicing direction into texture objects [S1][S3, unofficial].
    b.  Render the polygons for the large cells in the current slice. Record the presence of these polygons in a stencil buffer [S3, unofficial].
    c.  Bind the appropriate texture map containing the small cell splats for the current slice [S1][S3, unofficial].
    d.  Position the rectangle representing the splats on the slice plane [S3, unofficial].
    e.  Composite the splats using texture mapping. Apply a stencil test that restricts the splat's effect to regions where large cell polygons are absent [S3, unofficial]. This prevents the enlarged splats from overwriting the full opacity already accounted for by the large cell polygons [S3, unofficial].

    large_cells = []

        if cell.volume < volume_threshold:
            small_cells.append(cell)
        else:
            large_cells.append(cell)
            
    # 2. Preprocessing for Small Cells
    # Group small cells by their closest slice plane
    slice_groups = group_cells_by_slice(small_cells, slice_direction)
    
    # Pre-compute splat textures
    splat_textures = []
    for slice_id, group in slice_groups.items():
        # Sort by depth (back to front)
        group.sort(key=lambda c: depth_of_center(c, slice_direction))
        
        # Create a temporary buffer for this slice's splats
        temp_image = create_empty_image()
        
        for cell in group:
            # Fit Gaussian ellipsoid approximating cell shape
            ellipsoid = fit_gaussian_ellipsoid(cell)
            
            # Project footprint to image plane
            footprint = project_ellipsoid_footprint(ellipsoid, slice_direction)
            
            # Convolve with Gaussian presampling filter for anti-aliasing
            enlarged_footprint = convolve_gaussian(footprint)
            
            # Determine bounding rectangle
            rect = get_bounding_rectangle(enlarged_footprint)
            
            # Calculate color from transfer function, volume, and footprint size
            color = transfer_function(cell.volume, cell.density, enlarged_footprint.size)
            
            # Render splat to temp image (back-to-front handled by sort)
            render_splat_to_image(temp_image, rect, color, enlarged_footprint)
            
        # Determine global bounding box of non-zero values in temp_image
        global_rect = get_global_non_zero_rect(temp_image)
        
        # Create texture map entry
        splat_textures.append({
            'slice_id': slice_id,
            'texture': create_texture_from_image(temp_image, global_rect),
            'rect': global_rect
        })
        
    # 3. Interactive Rendering
    for slice_id, large_slice_cells in enumerate(large_cells_by_slice(large_cells, slice_direction)):
        # Render large cells and record in stencil buffer
        render_large_cells(large_slice_cells, stencil_buffer=stencil_buffer)
        
        # Find corresponding splat texture for this slice

        if splat_data is not None:

            render_rectangle(splat_data['rect'])
            set_stencil_test(condition=STENCIL_TEST_ALWAYS_PASS) # Reset for next pass

### Edge Cases and Pitfalls
*   **Precision:** The subpixel location of the center of gravity is used to analytically compute splat weights. Loss of precision here may affect the accuracy of the compositing opacity [S1].
*   **Boundaries:** The stencil test must correctly handle the boundaries between large cell polygons and splat regions. If the stencil test is not restricted to regions where polygons are absent, splats may incorrectly overlap opaque regions, causing visual artifacts [S3, unofficial].
*   **Degenerate Input:** If a cell has zero volume, it should be ignored or handled as a degenerate case. Not given in the sources.

## Operating characteristics
*   **Time Complexity:** Preprocessing involves sorting and projecting all small cells, which is $O(N \log N)$ for sorting and $O(N)$ for projection, where $N$ is the number of small cells. Interactive rendering is efficient as splats are pre-computed into texture maps.
*   **Memory Complexity:** Requires storing texture maps for all slices. The size depends on the number of slices and the size of the bounding rectangles. Not given in the sources.
*   **Strengths:** Prevents loss of detail in adaptive meshes; handles small cells that would otherwise be missed; efficient interactive rendering via texture mapping.
*   **Limitations:** Requires preprocessing; complex to implement due to the need for ellipsoid fitting and stencil buffer management; relies on hardware texture mapping capabilities.
*   **When to use:** When rendering adaptive meshes with significant variation in cell size, and small cells contain important geometric details.
*   **When not to use:** When cells are uniformly large, or when pre-processing time is prohibitive.

## Background
This method was developed for volume rendering on curvilinear and unstructured grids, specifically to address the issue of small cells in adaptive meshes being missed during slice-based rendering [S1][S3, unofficial]. It builds on the work of Williams et al. [8] regarding spine splats and Zwicker et al. [5] regarding Gaussian presampling filters [S1][S3, unofficial]. The technique was presented in the context of interactive visualization of large datasets, requiring parallelization for performance [S1][S3, unofficial].
