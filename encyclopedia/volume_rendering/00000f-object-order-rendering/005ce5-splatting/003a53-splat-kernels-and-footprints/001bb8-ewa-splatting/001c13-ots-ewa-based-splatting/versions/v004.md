# OTS (EWA-Based Splatting)
Also called: EWA-Based Splatting
## Overview
OTS (EWA-Based Splatting) is a volumetric rendering method that adapts the standard EWA splatting framework to support accurate volumetric integration by correcting the primitive weight for perspective projection effects [S1]. It solves the problem of incorrect opacity accumulation in standard EWA splatting, where the projected 2D Gaussian's integral is distorted by perspective division, leading to visual inaccuracies in depth-dependent attenuation [S1]. It sets itself apart from standard EWA Splatting by explicitly multiplying the splat weight by the determinant of the projection Jacobian, and from 3DGS by retaining the exact volumetric integration model rather than approximating it with affine assumptions [S1].
## How it works
**Inputs and Outputs:**
- Input: A set of 3D Gaussian primitives, each defined by position $\mathbf{p}$, covariance $\Sigma$, color $\mathbf{c}$, and base weight $a$.
- Output: A 2D image with accumulated color and opacity.

**Data Structures:**
- Primitive: Contains $\mathbf{p} \in \mathbb{R}^3$, $\Sigma \in \mathbb{R}^{3 \times 3}$ (symmetric positive definite), $\mathbf{c} \in \mathbb{R}^3$, and scalar $a$.
- Screen-space Primitive: Contains projected center $\mathbf{p}'$, projected covariance $\Sigma'$, and corrected weight $a'$.

**Steps:**
1. **Projection and Covariance Transformation:**
   For each primitive, compute the screen-space center $\mathbf{p}'$ and the projected 2D covariance matrix $\Sigma'$ using the standard EWA projection pipeline [S1]. This involves projecting the 3D covariance into screen space, accounting for the view and projection matrices.

2. **Jacobian Determinant Calculation:**
   Compute the determinant of the Jacobian of the perspective projection, denoted as $J$. This value represents the scaling factor of the area element due to perspective division [S1].

3. **Weight Correction:**
   Calculate the corrected weight $a'$ by multiplying the original weight $a$ by the Jacobian determinant $J$:
   $$ a' = a \cdot \det(J) $$
   This step preserves the integral of the extinction coefficient under perspective projection, correcting the distortion introduced by $\Sigma'$ [S1].

4. **Rendering Kernel Execution:**
   For each pixel covered by a primitive's footprint:
   a. Evaluate the 2D Gaussian function $f_i(\mathbf{x})$ at the pixel's screen-space coordinates $\mathbf{x}$ using $\Sigma'$ and $\mathbf{p}'$.
   b. **Clamp** the value of $f_i(\mathbf{x})$ to a maximum of 1.0. This is required for correctness in the OTS model because the perspective-corrected 2D Gaussians can produce values greater than 1, which would violate the physical interpretation of the extinction coefficient in the volumetric integration [S1].
   c. Accumulate the color and opacity using the corrected weight $a'$ and the clamped $f_i(\mathbf{x})$.

**Pseudocode:**
```python
def render_ots_primitives(primitives, camera_matrix, projection_matrix):
    """
    Renders primitives using OTS (EWA-Based Splatting) with perspective correction.
    """
    image = zeros_like(output_shape)
    
    # Sort primitives back-to-front for correct alpha blending
    sorted_primitives = sort_by_depth(primitives, camera_matrix)
    
    for prim in sorted_primitives:
        # 1. Project primitive to screen space
        p_prime, sigma_prime = project_ewa(prim.p, prim.sigma, camera_matrix, projection_matrix)
        
        # 2. Compute Jacobian determinant for perspective correction
        # The Jacobian determinant accounts for the change in area due to perspective division
        jacobian_det = compute_jacobian_determinant(prim.p, camera_matrix, projection_matrix)
        
        # 3. Correct the weight
        a_prime = prim.a * jacobian_det
        
        # 4. Rasterize the primitive
        footprint = get_footprint(sigma_prime)
        for x in footprint:
            # Evaluate 2D Gaussian
            f_x = evaluate_2d_gaussian(x, p_prime, sigma_prime)
            
            # Clamp f_x to 1.0 for correctness in OTS model
            f_x = min(f_x, 1.0)
            
            # Accumulate color and opacity
            # Assuming standard volumetric integration: C = C * (1 - alpha) + c * alpha
            # where alpha is derived from a' and f_x
            alpha = compute_alpha(a_prime, f_x)
            color = prim.c
            image[x] = image[x] * (1 - alpha) + color * alpha
            
    return image
```

**Parameters:**
- Clamping threshold: 1.0 [S1].

**Edge Cases and Pitfalls:**
- **Values > 1:** Without clamping, $f_i(\mathbf{x})$ can exceed 1, leading to incorrect opacity values in the volumetric integration [S1].
- **Perspective Distortion:** Ignoring the Jacobian determinant leads to incorrect weight scaling, especially for primitives far from the camera or at oblique angles [S1].
- **Numerical Stability:** The clamp was originally present in 3DGS for numerical stability but is now required for correctness in the OTS model [S1].
## Subtopics

### [Self-Attenuation Rendering](1154-self-attenuation-rendering.md)
Uses exact exponential extinction $1-e^{-f(\mathbf{p})}$ instead of Taylor approximation, requiring front-to-back traversal.

### [3D Gaussian Splatting (3DGS) Approximation](1397-3d-gaussian-splatting-3dgs-approximation.md)
Uses affine projection and first-order Taylor expansion for attenuation, ignoring perspective distortion in the integration model.

## Operating characteristics
- **Time Complexity:** Dominated by rasterization of splats. The Jacobian calculation adds a constant overhead per primitive.
- **Memory Complexity:** Linear in the number of primitives.
- **Strengths:** Correctly handles perspective distortion in volumetric integration, leading to more accurate opacity accumulation.
- **Limitations:** Requires computation of the Jacobian determinant. The clamping step is a heuristic that may affect visual quality if not carefully tuned.
- **When to use:** When accurate volumetric rendering under perspective projection is required, and the scene contains primitives at varying depths or oblique angles.
- **When not to use:** For orthographic projections where perspective distortion is negligible, or when real-time performance is critical and the approximation error is acceptable.
## Background
OTS (EWA-Based Splatting) is described in the context of comparing different splatting methods for 3D Gaussian Splatting [S1]. It builds on the EWA splatting framework [ZPVBG02] and is discussed as a baseline for evaluating the impact of accurate volumetric rendering in 3DGS [S1].
