# Anisotropic SPH Kernel

Also called: Anisotropic SPH

## Overview
The Anisotropic SPH Kernel extends the standard Smoothed Particle Hydrodynamics (SPH) formulation by replacing the spherical support domain with an ellipsoidal one, defined by an anisotropy matrix $H$ [S1]. This method is specifically designed for rendering fluid surfaces, where isotropic kernels often produce artifacts, whereas the simulation itself typically retains an isotropic formulation [S1]. It differs from the parent [SPH Kernel Implementation](16549-sph-kernel-implementation.md) by introducing directional dependence in the kernel footprint to better capture surface geometry.

## How it works
**Inputs and Outputs:**
*   **Inputs:** Particle positions $x_i, x_j$, particle properties (mass $m_j$, density $\rho_j$, rest volume $V_i$), anisotropy matrices $H_i, H_j$, and the cubic spline kernel parameters.
*   **Outputs:** Kernel value $\hat{W}$, density contribution, or surface normal information depending on the rendering pass.

**Data Structures:**
*   **Anisotropy Matrix ($H$):** A $3 \times 3$ matrix for each particle. In the isotropic case, $H = h \mathbf{I}$ (where $\mathbf{I}$ is the identity matrix) [S1]. For anisotropic cases, $H$ defines the ellipsoidal extent such that $h_x \neq h_y \neq h_z$ [S1].
*   **Particle Data:** Contains position $x$, mass $m$, density $\rho$, and rest volume $V$.

**Formulas:**
1.  **Relative Position:** $x_{ij} = x_i - x_j$ [S1].
2.  **Normalized Distance ($q$):** For isotropic kernels, $q = \|x_{ij}\| / h$ [S1]. For anisotropic kernels, the argument to the base kernel is the transformed distance $\|H \cdot x_{ij}\|$ [S1].
3.  **Base Kernel ($\hat{W}$):** The rendering kernel uses a simplified cubic form:
    $$ \hat{W}(q) = (1 - q^2)^3_+ $$
    where $(\cdot)_+ = \max(\cdot, 0)$ [S1].
4.  **Normalization Constant ($C_3$):**
    $$ C_3 = \frac{64}{64\pi} $$
    (Note: The source text states $C_3 = \frac{64}{64\pi}$, which simplifies to $1/\pi$, though standard SPH normalization for 3D cubic splines is often cited differently; we adhere strictly to the source text [S1]).
5.  **Anisotropic Kernel Evaluation:**
    The kernel value for particle $j$ at position $x_i$ is:
    $$ W_{ij} = C_d \frac{1}{|H|} \hat{W}(\|H \cdot x_{ij}\|) $$
    where $|H|$ is the determinant of $H$ and $C_d$ is the dimensionality normalization factor [S1].
6.  **Symmetric Formulation:**
    When particles $i$ and $j$ have different anisotropy matrices (e.g., due to spatial adaptivity or different particle definitions), the symmetric kernel is:
    $$ \hat{W}(\|H \cdot x_{ij}\|) = \frac{1}{2} \left( \hat{W}(\|H_i \cdot x_{ij}\|) + \hat{W}(\|H_j \cdot x_{ij}\|) \right) $$
    [S1].

**Parameters:**
*   **$N_h$:** Target number of neighbors. For the cubic spline kernel, $N_h = 50$ [S1].
*   **Support Radius ($h$):** In isotropic simulation, $h_i = \sqrt[3]{3 N_h V_i}$, where $V_i$ is the rest volume (e.g., $V_i = \frac{4}{3}\pi r^3$ for a particle of radius $r$) [S1].

def calculate_isotropic_support_radius(rest_volume, Nh):
    """
    Calculates the isotropic support radius h.
    """
    # h = cube_root(3 * Nh * Vi)
    return (3.0 * Nh * rest_volume) ** (1.0/3.0)

**Edge Cases and Pitfalls:**
*   **Neighborhood Queries:** The ellipsoidal support domain ($h_x \neq h_y \neq h_z$) requires non-cubic cells in spatial data structures, complicating neighbor search compared to isotropic spherical domains [S1].
*   **Symmetric Determinant:** The source provides a symmetric formula for the kernel shape $\hat{W}$ but does not explicitly define how to handle the determinant $|H|$ or normalization $C_d$ when $H_i \neq H_j$ in the symmetric case [S1]. Implementers must decide whether to average determinants or use one particle's determinant.
*   **Precision:** The term $(1 - q^2)$ can become negative due to floating-point errors when $q \approx 1$. The $(\cdot)_+$ operator must be applied to prevent invalid kernel values [S1].

## Subtopics

### Isotropic SPH
Standard SPH where the support radius $h$ is isotropic (equal in all directions), resulting in a spherical support domain [S1]. It is used for the simulation phase, whereas the anisotropic variant is reserved for rendering [S1]. The support radius is determined by $h_i = \sqrt[3]{3 N_h V_i}$, with $N_h = 50$ for the cubic spline kernel [S1]. It suffers from surface artifacts in rendering compared to the anisotropic version [S1].

## Operating characteristics
*   **Complexity:** Neighbor search complexity increases from $O(n \cdot c)$ with cubic cells (isotropic) to non-cubic cells (anisotropic), potentially increasing overhead for spatial queries [S1].
*   **Performance:** The anisotropic formulation is computationally more expensive per particle due to matrix-vector multiplications ($H \cdot x_{ij}$) and determinant calculations [S1].
*   **Strengths:** Eliminates surface artifacts in fluid rendering by adapting the kernel shape to the local fluid surface orientation [S1].
*   **Limitations:** Requires more complex spatial data structures to handle ellipsoidal search domains [S1]. Not used for the simulation dynamics in the cited work, limiting its use to post-processing/rendering [S1].

## Background
The anisotropic SPH formulation was introduced by Ohtsuka and Vlachos [OVSM98] to handle fluid surfaces [S1]. The symmetric formulation for different particle anisotropies is attributed to [HK89] [S1]. The specific rendering kernel $\hat{W}(q) = (1 - q^2)^3_+$ is cited from [YT13] [S1]. The method is implemented in the context of multi-level memory structures for simulating and rendering SPH [S1].
