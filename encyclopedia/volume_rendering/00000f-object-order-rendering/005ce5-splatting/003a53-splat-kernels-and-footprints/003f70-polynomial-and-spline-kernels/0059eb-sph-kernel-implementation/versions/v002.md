# SPH Kernel Implementation

Also called: SPH Kernels

## Overview
The SPH Kernel Implementation provides a polymorphic interface for evaluating Smoothed Particle Hydrodynamics (SPH) kernels on CPU and GPU architectures [S1, unofficial]. It is distinguished from general splatting methods by its focus on particle-based simulation data, providing closed-form 3D expressions for both kernel values and spatial derivatives [S1, unofficial]. It builds on the shared principles of compact support and radial symmetry defined in [Polynomial and Spline Kernels](9995-polynomial-and-spline-kernels.md).

## How it works
**Inputs and Outputs:**
*   **Input:** Particle position $\mathbf{x}_i$, smoothing length $h$, particle mass $m$, and a kernel type identifier [S1, unofficial].
*   **Output:** Kernel value $W(\mathbf{x})$ and its spatial derivative $\nabla W(\mathbf{x})$ at a query point, typically a voxel center [S1, unofficial].

**Data Structures:**
The module uses a polymorphic interface class structure where concrete implementations store kernel parameters and evaluation methods [S1, unofficial]. A kd-tree is employed to calculate particle radii and perform neighbor searches for density estimation [S1, unofficial].

**Supported Kernels:**
The implementation supports the following families, each with closed-form 3D expressions for value and derivative [S1, unofficial]:
1. Cubic B-spline
2. Quintic B-spline
3. Wendland C2
4. Wendland C4
5. Wendland C6
6. Wendland C8

**Algorithm Steps:**
1. Compute the Euclidean distance $r = \|\mathbf{x} - \mathbf{x}_i\|$ between the query point and particle center [S1, unofficial].
2. Normalize the distance to $q = r / h$ [S1, unofficial].
3. Check compact support: if $q > 1$, return zero value and gradient [S1, unofficial].
4. Evaluate the closed-form polynomial for $W(q)$ and its derivative $dW/dq$ based on the selected kernel type [S1, unofficial].
5. Compute the gradient $\nabla W = (dW/dq \cdot 1/h) \cdot \mathbf{u}$, where $\mathbf{u}$ is the unit vector from the particle to the query point [S1, unofficial].
6. Apply density bias correction using the particle mass and smoothing length if computing volumetric density [S1, unofficial].

**Formulas:**
The sources confirm that closed-form 3D expressions exist for all supported kernels, but exact polynomial coefficients are not provided in the documentation [S1, unofficial]. The evaluation relies on the normalized radial distance $q = \|\mathbf{x} - \mathbf{x}_i\| / h$ and the compact support condition $q \leq 1$ [S1, unofficial].

**Parameters:**
*   **Smoothing Length ($h$):** Controls the support radius of the kernel [S1, unofficial].
*   **Particle Mass ($m$):** Used for density bias correction during voxelization [S1, unofficial].
*   **Kernel Type:** Enumerated selector for the B-spline or Wendland variant [S1, unofficial].

**Pseudocode:**
```python
import math

class SPHKernel:
    """Polymorphic base interface for SPH kernel evaluation."""
    def evaluate(self, query_pos, particle_pos, smoothing_length):
        raise NotImplementedError

class CubicBSplineKernel(SPHKernel):
    """Concrete implementation for the cubic B-spline kernel."""
    def evaluate(self, query_pos, particle_pos, smoothing_length):
        # 1. Distance calculation
        diff = [query_pos[i] - particle_pos[i] for i in range(3)]
        r = math.sqrt(sum(d*d for d in diff))
        q = r / smoothing_length
        
        # 2. Compact support check
        if q > 1.0:
            return 0.0, [0.0, 0.0, 0.0]
        
        # 3. Closed-form value and derivative (standard 1D radial form)
        val = (1.0 - q**2)**3
        dW_dq = -6.0 * q * (1.0 - q**2)**2
        
        # 4. Gradient computation
        if r > 1e-9:
            grad = [dW_dq / smoothing_length * (diff[i] / r) for i in range(3)]
        else:
            grad = [0.0, 0.0, 0.0]
            
        return val, grad

# Note: Quintic B-spline and Wendland C2/C4/C6/C8 follow identical 
# structural logic with different polynomial coefficients [G].
```

## Subtopics

### [Anisotropic SPH Kernel](18763-anisotropic-sph-kernel.md)
An extension that replaces the spherical support domain with an ellipsoidal one defined by an anisotropy matrix, designed to reduce artifacts in fluid surface rendering [18763-anisotropic-sph-kernel.md]. It differs from the isotropic parent by introducing directional dependence in the footprint to better capture surface geometry [18763-anisotropic-sph-kernel.md]. Choose this variant when rendering fluid interfaces where isotropic kernels produce visible smoothing artifacts. The provided sources do not detail its algorithmic implementation.

## Operating characteristics
*   **Time Complexity:** $O(1)$ per kernel evaluation; neighbor search via kd-tree typically requires $O(\log N)$ [S1, unofficial].
*   **Memory Complexity:** Low, as kernels are stateless functions; the kd-tree requires $O(N)$ auxiliary space [S1, unofficial].
*   **Strengths:** Closed-form derivatives enable efficient gradient-based operations for density calculation and voxelization [S1, unofficial]. Support for multiple kernel families allows tuning for different simulation characteristics [S1, unofficial].
*   **Limitations:** Voxelization requires extending the base algorithm to 3D grids [S1, unofficial]. Exact polynomial coefficients for all supported kernels are not documented [S1, unofficial].
*   **When to use:** Visualizing particle-based astrophysical or fluid simulations where accurate density estimation and smooth voxelization are required [S1, unofficial].

## Background
The method originates from a C++ module defined in [Bös25] that provides a polymorphic interface for SPH kernels [S1, unofficial]. The voxelization pipeline extends the algorithm described in [Pri07] to support 3D voxels [S1, unofficial]. It is used in astrophysical simulation visualization pipelines to bridge particle data with volume rendering formats [S1, unofficial].
