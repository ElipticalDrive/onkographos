# Voxel Splat Rendering

Also called: Interactive Splat Rendering with Alpha/Gamma Control, Interactive value selection rendering, Splatting (Object Order), Voxel splatting

## Overview
Voxel Splat Rendering is an object-order volume rendering technique where each voxel is projected onto the screen as a 2D footprint (splat) and composited into the image buffer [S3, unofficial][S4, unofficial]. It solves the problem of rendering large volumetric datasets interactively by replacing per-pixel ray traversal with per-voxel projection, allowing for efficient culling of irrelevant voxels and parallelization [S3, unofficial]. Unlike [Circle Splat Rendering](2981-circle-splat-rendering.md) which uses circular footprints, Voxel Splat Rendering typically projects axis-aligned bounding rectangles or squares, often optimized for GPU rasterization of quads [S1]. It differs from [Image-Space Sheet-Buffered Splatting Pipeline](8961-image-space-sheet-buffered-splatting-pipeline.md) by typically processing voxels in object space (often front-to-back) rather than pre-sorting them into image-space slabs on the GPU [S3, unofficial][S5, unofficial].

## How it works
**Inputs:**
*   Volumetric dataset $V$ (array of voxels with position, color, opacity, and optionally normal) [S2, unofficial][S5, unofficial].
*   Camera parameters: Model-View-Projection (MVP) matrix or separate Model-View (MV) and Projection (P) matrices [G].
*   Rendering parameters: Point size, alpha value, gamma value, and anti-aliasing settings [S2, unofficial].

**Outputs:**
*   2D Image buffer (Color and Depth/Alpha) [G].

**Data Structures:**
*   **Voxel:** Contains 3D position $(x,y,z)$, color $(R,G,B)$, opacity $\alpha$, and optionally a surface normal $\mathbf{n}$ [S2, unofficial][S5, unofficial].
*   **Splat Footprint:** A 2D region in screen space [S4, unofficial]. For axis-aligned splats, this is defined by an axis-aligned bounding rectangle (AABB) in screen coordinates [S1]. For Gaussian splats, it is a radially symmetric kernel [S3, unofficial].
*   **Image Buffer:** Accumulates color and opacity [G].

**Steps:**

1.  **Voxel Transformation:**
    For each voxel in the volume, transform its center position $\mathbf{p}_{obj}$ from object space to screen space $\mathbf{p}_{screen}$ using the camera's view and projection matrices [S3, unofficial][S4, unofficial].
    $$ \mathbf{p}_{screen} = M_{view} \cdot M_{proj} \cdot \mathbf{p}_{obj} $$
    If the voxel is behind the camera or outside the view frustum, cull it [S3, unofficial].

2.  **Footprint Calculation:**
    Determine the screen-space extent of the voxel [S1][S4, unofficial].
    *   **Axis-Aligned (Rectangular):** Compute the axis-aligned bounding rectangle of the projected voxel cube [S1].
    *   **Gaussian (Radial):** Define a radius $r$ based on the voxel size and distance to camera, or use a fixed footprint size for parallel projection [S3, unofficial][S5, unofficial].

3.  **Shading and Weighting (Optional but common):**
    Calculate a weight for the voxel to modulate its contribution [S1][S2, unofficial].
    *   **Normal-based Culling/Weighting:** If normals are available, compute a weight based on the angle between the view vector and the normal to simulate surface shading or cull back-facing voxels [S2, unofficial][S3, unofficial].
    *   **Multi-View Weighting (e.g., for NeRF/Image-based modeling):** If rendering from a novel view using multiple source cameras, compute weights for each source camera $i$ [S1]:
        1.  Calculate $\text{dotV} = \text{dot}(\mathbf{V}_{toEye}, \mathbf{V}_{toCamera[i]})$ [S1].
        2.  Calculate $\text{dotN} = \text{dot}(\mathbf{n}, \mathbf{V}_{toCamera[i]})$ [S1].
        3.  $\text{weightV} = \text{dotV} > 0.0 ? \text{pow}(\text{dotV}, 4) : 0.0$ [S1].
        4.  $\text{weightN} = \text{dotN} > 0.0 ? \text{pow}(\text{dotN}, 4) : 0.0$ [S1].
        5.  $\text{weight}[i] = \text{weightV} \times \text{weightN}$ [S1].
        6.  Normalize weights by dividing by the sum of all weights [S1].

4.  **Rasterization (Splatting):**
    Render the footprint onto the image buffer [S1][S3, unofficial].
    *   **Rectangular Splat:** Render the AABB as a pair of triangles (quad) [S1].
    *   **Gaussian Splat:** Rasterize a precomputed footprint lookup table (LUT) that stores the analytically integrated kernel function along a traversing ray [S3, unofficial]. This spreads the voxel's energy across multiple pixels to counter holes caused by discrete processing [S4, unofficial].

5.  **Compositing:**
    Accumulate the splat's color and opacity into the image buffer [S5, unofficial].
    *   **Front-to-Back:** Traverse voxels from near to far [S5, unofficial][S6, unofficial]. For each splat, update the buffer using alpha blending [S4, unofficial][S5, unofficial]:
        $$ C_{out} = C_{in} \cdot (1 - \alpha_{splat}) + C_{splat} \cdot \alpha_{splat} $$
        $$ \alpha_{out} = \alpha_{in} \cdot (1 - \alpha_{splat}) + \alpha_{splat} $$
    *   **Back-to-Front:** Also possible, though front-to-back is standard for early termination in raycasting, splatting often processes all visible voxels [S4, unofficial].

6.  **Post-Processing:**
    Apply gamma correction and alpha blending adjustments to reduce contributions from tissues with differing color densities [S2, unofficial].

**Pseudocode:**

```python
import math

def voxel_splat_rendering(volume, view_proj_matrix, image_width, image_height, clear_color=(0.0, 0.0, 0.0)):
    # Initialize image buffer with clear color and zero alpha
    image_buffer = [(clear_color, 0.0) for _ in range(image_width * image_height)]
    
    # Sort voxels front-to-back based on depth in camera space
    sorted_voxels = sort_voxels_by_depth(volume, view_proj_matrix)
    
    for voxel in sorted_voxels:
        # 1. Transform voxel center to screen space
        p_screen = transform_to_screen(voxel.position, view_proj_matrix)
        
        # 2. Cull if behind camera or outside frustum
        if not is_in_frustum(p_screen, image_width, image_height):
            continue
            
        # 3. Calculate footprint (AABB for rectangular splats)
        footprint = calculate_aabb_footprint(voxel, view_proj_matrix, image_width, image_height)
        if footprint is None:
            continue
            
        # 4. Calculate shading weight (optional, e.g., normal-based)
        # Multi-view weighting logic omitted; see Step 3 for source-specific formula [S1].
        weight = 1.0
        if voxel.has_normal:
            view_dir = normalize(voxel.eye_pos - voxel.position)
            weight = max(0.0, dot(view_dir, voxel.normal)) ** 4
            
        # 5. Rasterize footprint and composite
        render_quad(footprint, voxel.color, voxel.opacity * weight, image_buffer, image_width)
        
    return image_buffer

def clear_image_buffer(buffer, clear_color):
    for i in range(len(buffer)):
        buffer[i] = (clear_color, 0.0)

def sort_voxels_by_depth(voxels, view_proj_matrix):
    for v in voxels:
        p = transform_to_screen(v.position, view_proj_matrix)
        v.screen_z = p.z if p else float('inf')
    return sorted(voxels, key=lambda v: v.screen_z, reverse=True)

def transform_to_screen(position, view_proj_matrix):
    # Standard MVP transformation: multiply position by matrix, divide by w
    p_homogeneous = view_proj_matrix @ position
    if p_homogeneous.w <= 0.0:
        return None
    return (p_homogeneous.x / p_homogeneous.w, p_homogeneous.y / p_homogeneous.w, p_homogeneous.z / p_homogeneous.w)

def is_in_frustum(p_screen, width, height):
    if p_screen is None:
        return False
    u, v, z = p_screen
    if z < 0.0 or z > 1.0:
        return False
    if u < 0.0 or u > width or v < 0.0 or v > height:
        return False
    return True

def calculate_aabb_footprint(voxel, view_proj_matrix, width, height):
    # Project 8 corners of the voxel cube to screen space
    corners = get_voxel_corners(voxel.position, voxel.size)
    screen_corners = [transform_to_screen(c, view_proj_matrix) for c in corners]
    screen_corners = [c for c in screen_corners if c is not None]
    if not screen_corners:
        return None
    min_u = min(c[0] for c in screen_corners)
    max_u = max(c[0] for c in screen_corners)
    min_v = min(c[1] for c in screen_corners)
    max_v = max(c[1] for c in screen_corners)
    return (min_u, min_v, max_u, max_v)

def get_voxel_corners(position, size):
    x, y, z = position
    s = size / 2.0
    return [
        (x-s, y-s, z-s), (x+s, y-s, z-s), (x-s, y+s, z-s), (x+s, y+s, z-s),
        (x-s, y-s, z+s), (x+s, y-s, z+s), (x-s, y+s, z+s), (x+s, y+s, z+s)
    ]

def render_quad(footprint, color, opacity, buffer, width):
    min_u, min_v, max_u, max_v = footprint
    for y in range(int(min_v), int(max_v) + 1):
        for x in range(int(min_u), int(max_u) + 1):
            idx = y * width + x
            if 0 <= idx < len(buffer):
                buffer[idx] = blend(buffer[idx], color, opacity)

def blend(current_pixel, new_color, new_opacity):
    c_in, a_in = current_pixel
    c_out = [c_in[i] * (1.0 - new_opacity) + new_color[i] * new_opacity for i in range(3)]
    a_out = a_in * (1.0 - new_opacity) + new_opacity
    return (tuple(c_out), a_out)

def normalize(v):
    mag = math.sqrt(sum(c*c for c in v))
    return tuple(c/mag for c in v) if mag > 0 else (0.0, 0.0, 0.0)

def dot(v1, v2):
    return sum(a*b for a, b in zip(v1, v2))
```

**Parameters:**
*   **Point-size/Radius:** Determines the size of the splat [S2, unofficial].
*   **Alpha-value:** Global or per-voxel opacity [S2, unofficial].
*   **Gamma-value:** Gamma correction exponent to adjust brightness/contrast [S2, unofficial].
*   **Power Exponent:** In normal-based weighting, a power of 4 is commonly used to smooth transitions [S1].

**Edge Cases and Pitfalls:**
*   **Holes:** Discrete processing can produce holes on the periphery or during extreme perspective projection. Countered by distributing energy across multiple pixels via a footprint table [S4, unofficial][S5, unofficial].
*   **Aliasing:** Minor aliasing artifacts similar to non-anti-aliased triangle models. Close-range views show rectangular block artifacts and pixelation from finite RGB image resolution [S1].
*   **Blurring:** Tends to blur edges of objects and reduce image contrast [S3, unofficial].
*   **Performance:** Requires extensive filtering, making it time-consuming for large datasets if not optimized [S3, unofficial]. GPU rasterization is not always optimized for single-pixel quads, but performance is often acceptable [S1].

## Subtopics

### [Image-Space Sheet-Buffered Splatting Pipeline](8961-image-space-sheet-buffered-splatting-pipeline.md)
A GPU-accelerated variant that processes voxels in slabs parallel to the image plane, avoiding CPU-GPU bottlenecks by constructing buckets and sorting on the GPU. It accelerates rendering by 2-2.5x compared to CPU-based bucketing.

### [Orthographic Voxel Sprite Rendering](16665-orthographic-voxel-sprite-rendering.md)
Uses parallel rays to project voxels onto a 2D sprite plane, solving per-eye pixel shimmer in VR by rendering a single static image identical for both eyes. It uses a single fragment pass with a chunky virtual-pixel grid.

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:** Achieves 1.1 Hz on a single 150MHz R4400 processor for a $256 \times 256 \times 225$ volume with 65 seconds of pre-processing time [S3, unofficial].
*   **Strengths:** Interactive frame rates for large datasets; efficient culling of irrelevant voxels; suitable for parallelization based on object space subdivision [S3, unofficial].
*   **Limitations:** Blurs edges; prone to aliasing and holes if footprint is not properly distributed; brightness variations in animation if not using image-aligned splatting [S3, unofficial].
*   **When to use:** Interactive visualization of large volumetric datasets where speed is prioritized over photorealistic edge sharpness [S2, unofficial][S3, unofficial].
*   **When not to use:** When extreme perspective distortion causes severe aliasing or holes that footprints cannot resolve [S4, unofficial][S5, unofficial].

## Background
Voxel Splat Rendering was first published by Westover [S3, unofficial][S6, unofficial]. It was introduced as an alternative to ray casting, representing the volume as an array of overlapping basis functions (commonly Gaussian kernels) scaled by voxel values [S3, unofficial]. The method was designed to provide interactive frame rates by projecting voxels to the screen and compositing them, rather than casting rays per pixel [S3, unofficial]. Subsequent improvements included image-aligned splatting by Mueller to reduce brightness variations in animation [S3, unofficial], and normal-based culling by Sobierajski et al. to reduce processing load [S3, unofficial]. It is widely used in medical visualization and interactive volume exploration [S2, unofficial][S3, unofficial].
