# Voxel Splat Rendering

Also called: Interactive Splat Rendering with Alpha/Gamma Control, Interactive value selection rendering, Splatting (Object Order), Voxel splatting

## Overview
Voxel Splat Rendering is an object-order volume rendering technique where each voxel is projected onto the screen as a 2D footprint (splat) and composited into the image buffer [S3, unofficial][S4, unofficial]. It solves the problem of rendering large volumetric datasets interactively by replacing per-pixel ray traversal with per-voxel projection, allowing for efficient culling of irrelevant voxels and parallelization [S3, unofficial]. Unlike [Circle Splat Rendering](2981-circle-splat-rendering.md) which uses circular footprints, or [Tetrahedral Splatting](3181-tetrahedral-splatting.md) which preserves volume continuity, Voxel Splat Rendering typically uses square or circular splats derived from the voxel's axis-aligned bounding box or a Gaussian kernel, often resulting in blocky artifacts at close range but offering high performance for distant views [S1][S3, unofficial].

## How it works
**Inputs:**
*   Volumetric dataset $V$ (array of voxels with position, color, opacity, and optionally normal).
*   Camera parameters (Model-View-Projection matrix $MVP$).
*   Rendering parameters: point-size, alpha-value, gamma-value, anti-aliasing [S2, unofficial].

**Outputs:**
*   2D Image buffer (color and opacity).

**Data Structures:**
*   **Voxel:** Contains position $(x,y,z)$, color $(R,G,B)$, opacity $\alpha$, and optionally a normal vector $N$. Normals can be quantized to 240 pre-defined directions stored in 1 byte [S2, unofficial].
*   **Footprint Table:** A 2D lookup table storing the analytically integrated kernel function along a traversing ray, used to spread energy across multiple pixels [S3, unofficial].

**Steps:**

1.  **Voxel Selection and Culling:**
    *   Traverse the volume. Optionally, cull voxels based on normal orientation (back-face culling) to reduce processing by up to half [S3, unofficial].
    *   For interactive selection, retrieve and decode only voxelsets corresponding to selected colors within a bounding box [S2, unofficial].

2.  **Projection to Screen Space:**
    *   For each voxel, transform its center from object space to screen space using the MVP matrix [S3, unofficial].
    *   Calculate the axis-aligned bounding rectangle of the projected voxel in screen space [S1].
    *   *Note:* In parallel projection, the footprint size is constant. In perspective projection, it varies [S4, unofficial].

3.  **Weighting (Optional, for Multi-View/IBR):**
    *   If rendering for novel views from a capture rig, compute a weight $w[i]$ for each camera $i$ to blend contributions [S1]:
        $$
        \begin{aligned}
        dotV &= \text{dot}(VtoEye, VtoCamera[i]) \\
        dotN &= \text{dot}(Normal, VtoCamera[i]) \\
        weightV &= \begin{cases} dotV^4 & \text{if } dotV > 0.0 \\ 0.0 & \text{otherwise} \end{cases} \\
        weightN &= \begin{cases} dotN^4 & \text{if } dotN > 0.0 \\ 0.0 & \text{otherwise} \end{cases} \\
        w[i] &= weightV \times weightN
        \end{aligned}
        $$
        Normalize weights by dividing by $\sum w[i]$. The power exponent is typically 4 [S1].

4.  **Footprint Generation (Splatting):**
    *   Represent the voxel as a basis function (e.g., Gaussian kernel) scaled by voxel value [S3, unofficial].
    *   Generate a 2D footprint by rasterizing a precomputed lookup table. Each entry stores the integrated kernel value [S3, unofficial].
    *   Alternatively, render the bounding rectangle as a quad (pair of triangles) and texture-map the splat, weighting the contribution based on distance from the center [S1].

5.  **Compositing:**
    *   **Front-to-Back:** Traverse voxels from near to far. For each splat, alpha-blend its color and opacity into the image buffer [S4, unofficial][S5, unofficial].
    *   **Image-Aligned (Mueller):** Process voxels within slabs parallel to the image plane. Clip kernels to the slab, sum into a sheet buffer, and composite the sheet with the previous one [S3, unofficial]. This avoids brightness variations seen in slice-based summation [S3, unofficial].
    *   Apply alpha-blending and gamma-correction to reduce contributions from tissues with differing density [S2, unofficial].

**Pseudocode:**

```python
def voxel_splat_rendering(volume, camera, image_buffer):
    # Initialize image buffer with zero color and zero opacity
    for pixel in image_buffer:
        pixel.color = (0, 0, 0)
        pixel.opacity = 0.0

    # Sort voxels back-to-front or front-to-back depending on compositing strategy
    # For standard alpha blending, front-to-back is standard
    sorted_voxels = sort_voxels_by_depth(volume, camera)

    for voxel in sorted_voxels:
        # 1. Project voxel to screen space
        screen_rect = project_to_screen(voxel.position, camera.mvp)
        
        # 2. Cull if outside view frustum
        if not intersects_view_frustum(screen_rect, camera):
            continue

        # 3. Calculate contribution (Splat)
        # Using a simple Gaussian-like falloff or footprint table lookup
        # For each pixel (x,y) in screen_rect:
        for pixel in screen_rect.pixels:
            # Distance from voxel center to pixel center
            dist = distance(voxel.position.projected, pixel.position)
            
            # Kernel weight (e.g., Gaussian)
            # sigma is related to point-size parameter [S2, unofficial]
            weight = exp(-dist**2 / (2 * sigma**2))
            
            # Apply normal-based culling if enabled [S3, unofficial]
            if use_normal_culling and dot(voxel.normal, camera.view_direction) < 0:
                weight = 0.0

            # 4. Alpha Blend
            # Source color and opacity
            src_color = voxel.color * weight
            src_opacity = voxel.opacity * weight
            
            # Destination color and opacity
            dst_color = pixel.color
            dst_opacity = pixel.opacity
            
            # Standard front-to-back alpha blending
            new_opacity = dst_opacity + src_opacity * (1.0 - dst_opacity)
            if new_opacity > 0.0:
                new_color = (dst_color * dst_opacity + src_color * (1.0 - dst_opacity)) / new_opacity
            else:
                new_color = src_color
            
            pixel.color = new_color
            pixel.opacity = new_opacity

    return image_buffer
```

## Subtopics

### [Image-Space Sheet-Buffered Splatting Pipeline](8961-image-space-sheet-buffered-splatting-pipeline.md)
A GPU-accelerated variant that processes voxels in slabs parallel to the image plane, performing bucket construction and depth sorting on the GPU to avoid CPU-GPU bottlenecks. It accelerates rendering by 2-2.5x compared to CPU-based bucketing.

### [Orthographic Voxel Sprite Rendering](16665-orthographic-voxel-sprite-rendering.md)
Projects voxels using parallel rays to create a flat billboard appearance, solving per-eye pixel shimmer in VR by rendering a single static image identical for both eyes. It uses a single fragment pass with a chunky virtual-pixel grid.

## Operating characteristics
*   **Time Complexity:** $O(N \cdot A)$, where $N$ is the number of voxels and $A$ is the average area (in pixels) covered by a splat [S3, unofficial].
*   **Memory Complexity:** $O(N)$ for voxel storage, plus $O(W \cdot H)$ for the image buffer and footprint tables [S3, unofficial].
*   **Performance:** Achieves interactive frame rates (e.g., 1.1 Hz on a 150MHz R4400 for a $256^3$ volume with pre-processing) [S3, unofficial]. GPU implementations are significantly faster, though rasterization of single-pixel quads may not be fully optimized [S1].
*   **Strengths:** Efficient culling of irrelevant voxels; suitable for parallelization via object-space subdivision; allows interactive parameter tuning (alpha, gamma, point-size) [S2, unofficial][S3, unofficial].
*   **Limitations:** Tends to blur object edges and reduce contrast [S3, unofficial]. Discrete processing causes holes on periphery or under extreme perspective projection [S4, unofficial]. Close-range views show rectangular block artifacts and pixelation [S1]. Requires extensive filtering, making it time-consuming for high-quality results [S3, unofficial].
*   **When to use:** Interactive visualization of large datasets where performance is critical and slight blurring is acceptable.
*   **When not to use:** High-fidelity medical imaging requiring sharp edges, or close-up views where voxel structure is visible.

## Background
Voxel Splatting was first introduced by Westover [S3, unofficial][S5, unofficial]. It was proposed as an alternative to ray casting to improve performance by projecting basis functions (typically Gaussian kernels) to the screen and rasterizing precomputed footprints [S3, unofficial]. The method was later refined by Mueller to address brightness variations in animation through image-aligned splatting using slabs [S3, unofficial]. It is widely used in interactive volume visualization systems, particularly for large datasets where out-of-core rendering is necessary [S2, unofficial].
