# Voxel Splat Rendering

Also called: Interactive Splat Rendering with Alpha/Gamma Control, Interactive value selection rendering, Splatting (Object Order), Voxel splatting

## Overview
Voxel splat rendering is an object-order volume rendering technique where each voxel is projected onto the 2D image plane and blurred into a 2D footprint to spread its energy across multiple pixels, thereby avoiding the aliasing artifacts inherent in discrete point sampling [S3, unofficial][S4, unofficial]. It differs from ray casting by processing data in object space rather than image space, and from simple point projection by using a filtering function (typically a Gaussian kernel) to ensure continuous coverage of the image plane [S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volumetric dataset (array of voxels), each containing scalar or vector values (e.g., density, color, normal). Camera parameters (view and projection matrices).
*   **Output:** A 2D image buffer (color and/or opacity).

**Data Structures:**
*   **Voxel:** Contains position $(x, y, z)$, value $v$, and optionally a normal vector $\mathbf{n}$ [S2, unofficial][S5, unofficial].
*   **Footprint Table:** A precomputed lookup table storing the analytically integrated kernel function values for a traversing ray, used to efficiently rasterize the splat footprint [S3, unofficial].

**Steps:**
1.  **Voxel Selection:** Identify voxels relevant to the current view. Culling techniques, such as normal-based culling (discarding voxels with normals pointing away from the observer), can reduce the number of processed voxels by up to half [S3, unofficial].
2.  **Transformation:** Transform each voxel's position from object space to screen space using the Model-View-Projection (MVP) matrix [S3, unofficial][S4, unofficial].
3.  **Footprint Generation:**
    *   For each voxel, determine its 2D footprint $F(x,y)$ on the image plane.
    *   The footprint is generated by applying a filtering function (e.g., Gaussian) to the voxel's contribution, proportional to its distance from the projection plane [S4, unofficial].
    *   Alternatively, use a precomputed footprint lookup table where each entry stores the integrated kernel value [S3, unofficial].
    *   In parallel projection, the footprint size is constant for all voxels [S4, unofficial].
4.  **Weighting (Optional):** Compute view-dependent and normal-dependent weights to modulate the splat's contribution. For a voxel with center-to-eye vector $\mathbf{V}_{toEye}$, surface normal $\mathbf{N}$, and camera direction $\mathbf{V}_{toCamera}$:
    $$ \text{dotV} = \mathbf{V}_{toEye} \cdot \mathbf{V}_{toCamera} $$
    $$ \text{dotN} = \mathbf{N} \cdot \mathbf{V}_{toCamera} $$
    $$ w_V = \begin{cases} \text{dotV}^4 & \text{if } \text{dotV} > 0.0 \\ 0.0 & \text{otherwise} \end{cases} $$
    $$ w_N = \begin{cases} \text{dotN}^4 & \text{if } \text{dotN} > 0.0 \\ 0.0 & \text{otherwise} \end{cases} $$
    $$ w = w_V \cdot w_N $$
    Normalize weights by dividing by the sum of all weights [S1].
5.  **Compositing:**
    *   **Front-to-Back or Back-to-Front:** Traverse the volume in depth order [S4, unofficial][S5, unofficial].
    *   **Alpha Blending:** Composite the splatted voxel contribution into the image buffer using alpha blending [S4, unofficial].
    *   **Sheet-Buffered (Mueller):** Process voxel kernels within slabs of width $\Delta s$ aligned parallel to the image plane. Clip kernels to the slab, sum into a sheet buffer, and composite the sheet with the previous one [S3, unofficial]. The integrated values for color $C$, opacity $\alpha$, and function $f$ are:
        $$ C_\lambda(s_i) = \frac{\int_{i\Delta s}^{(i+1)\Delta s} C_\lambda(s) ds}{\Delta s}, \quad \alpha(s_i) = \frac{\int_{i\Delta s}^{(i+1)\Delta s} \alpha(s) ds}{\Delta s}, \quad f(s_i) = \frac{\int_{i\Delta s}^{(i+1)\Delta s} f(s) ds}{\Delta s} $$
        [S3, unofficial].

**Pseudocode:**
```python
def voxel_splat_render(volume, camera, image_buffer):
    # 1. Select and transform voxels
    splats = []
    for voxel in volume:
        # Transform voxel center to screen space
        screen_pos = camera.mvp_matrix * voxel.position
        
        # Culling: discard if behind camera or normal points away (optional)
        if screen_pos.z < 0:
            continue
        if camera.normal_culling and dot(voxel.normal, camera.view_direction) < 0:
            continue
            
        # 2. Generate Footprint
        # Determine bounding rectangle of the splat in screen space
        footprint_rect = get_footprint_bounds(screen_pos, voxel.value, camera.projection)
        
        # 3. Compute Weight (if applicable)
        weight = 1.0
        if camera.use_weighting:
            dotV = dot(camera.eye_vector, camera.camera_vector)
            dotN = dot(voxel.normal, camera.camera_vector)
            wV = pow(dotV, 4) if dotV > 0.0 else 0.0
            wN = pow(dotN, 4) if dotN > 0.0 else 0.0
            weight = wV * wN
            
        splats.append({
            'screen_pos': screen_pos,
            'footprint_rect': footprint_rect,
            'weight': weight,
            'value': voxel.value
        })
        
    # 4. Sort splats (Front-to-Back or Back-to-Front)
    # Note: Sorting is required for correct alpha blending
    splats.sort(key=lambda s: s['screen_pos'].z, reverse=True)
    
    # 5. Composite
    for splat in splats:
        rect = splat['footprint_rect']
        for pixel in rect:
            # Sample footprint value from lookup table or kernel function
            # based on distance from splat center
            footprint_val = sample_footprint(splat['screen_pos'], pixel)
            
            # Calculate contribution
            contribution = splat['value'] * splat['weight'] * footprint_val
            
            # Alpha blend into image buffer
            alpha = contribution # Assuming value maps to opacity
            image_buffer[pixel] = blend(image_buffer[pixel], contribution)
            
    return image_buffer
```

**Parameters:**
*   **Point-size / Diameter:** Fixed or distance-dependent diameter of the splat [S2, unofficial].
*   **Alpha-value:** Controls opacity blending [S2, unofficial].
*   **Gamma-value:** Gamma correction applied to reduce contribution of points from tissues with differing color densities [S2, unofficial].
*   **Power Exponent:** In weighting calculations, a power of 4 is typical to reduce artifacts in transitions [S1].

**Edge Cases and Pitfalls:**
*   **Holes:** Discrete processing can produce holes on the periphery or during extreme perspective projection. This is countered by distributing energy across multiple pixels via a footprint table [S4, unofficial].
*   **Blurring:** The method tends to blur object edges and reduce image contrast [S3, unofficial].
*   **Aliasing:** Minor aliasing artifacts similar to non-anti-aliased triangle models may occur [S1].
*   **Performance:** Requires extensive filtering, making it time-consuming for large datasets [S3, unofficial].
*   **Close-range Views:** Voxel splats may appear as rectangular blocks, showing pixelation artifacts from finite RGB image resolution [S1].

## Subtopics

### [Image-Space Sheet-Buffered Splatting Pipeline](8961-image-space-sheet-buffered-splatting-pipeline.md)
A GPU-accelerated variant that processes voxels in slabs parallel to the image plane, performing bucket construction and depth sorting on the GPU to avoid CPU-GPU bottlenecks. It accelerates rendering by a factor of 2 to 2.5 compared to CPU-based bucketing.

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of voxels projected, but heavily dependent on the number of pixels covered by splats. Each splat can cover hundreds of pixels [S3, unofficial].
*   **Memory Complexity:** Requires storage for the volume data and potentially a footprint lookup table.
*   **Performance:** Achieves 1.1 Hz on a single 150MHz R4400 processor for a $256 \times 256 \times 225$ volume with 65 seconds of pre-processing [S3, unofficial]. GPU implementations are significantly faster but may suffer from rasterization inefficiencies for single-pixel quads [S1].
*   **Strengths:** Interactive frame rates for moderate datasets; only relevant voxels need to be projected; suitable for parallelization based on object space subdivision [S3, unofficial].
*   **Limitations:** Blurs edges; prone to brightness variations in animation (unless sheet-buffered); discrete processing artifacts; high computational cost for extensive filtering [S3, unofficial].
*   **When to use:** Interactive visualization where speed is prioritized over sharp edge fidelity; datasets where voxels are sparse or can be culled effectively [S3, unofficial].
*   **When not to use:** High-fidelity medical imaging requiring sharp boundaries; extreme close-up views where pixelation is visible [S1].

## Background
Voxel splat rendering was first published by Westover [S5, unofficial]. It was introduced as an alternative to ray casting to achieve interactive frame rates by projecting overlapping basis functions (commonly Gaussian kernels) scaled by voxel values onto the screen [S3, unofficial]. The method was later refined by Mueller to address brightness variations in animation through image-aligned splatting (sheet-buffered approach) [S3, unofficial]. It is widely used in interactive volume visualization systems [S2, unofficial].
