# Voxel Splat Rendering

Also called: Interactive Splat Rendering with Alpha/Gamma Control, Interactive value selection rendering, Splatting (Object Order), Voxel splatting

## Overview
Voxel Splat Rendering is an object-order volume rendering technique where each voxel is projected onto the 2D image plane and blurred into a footprint to spread its energy across multiple pixels, thereby preventing aliasing artifacts inherent in discrete sampling [S3, unofficial][S4, unofficial]. It differs from ray casting by processing data in object space and from image-space sheet-buffered splatting by typically relying on CPU-driven bucketing or simpler GPU rasterization of screen-space bounding rectangles rather than complex depth-sorted sheet buffers [S1][S3, unofficial].

## How it works
**Inputs:** 3D voxel grid (values, colors, optional normals), camera parameters (view/projection matrices), rendering parameters (point size, alpha, gamma).
**Outputs:** 2D color and opacity image buffer.

**Data Structures:**
*   **Voxel:** Position $(x,y,z)$, value/color $C$, opacity $\alpha$, optional normal $N$.
*   **Footprint Table:** Precomputed 2D lookup table storing analytically integrated kernel values along a traversing ray, used to determine the weight of each pixel within the splat's footprint [S3, unofficial].
*   **Image Buffer:** Accumulates color and opacity via alpha blending.

**Steps:**
1.  **Voxel Selection & Culling:** Identify voxels relevant to the current view. Optional normal-based culling removes voxels with normals pointing away from the observer to reduce processing load [S3, unofficial].
2.  **Transformation:** Transform each voxel's center from object space to screen space using the Model-View-Projection (MVP) matrix [S3, unofficial].
3.  **Footprint Generation:** Determine the 2D footprint $F(x,y)$ for the voxel. For parallel projection, the footprint size is constant; for perspective, it varies with depth. The footprint represents the spatial extent of the blurred voxel contribution [S4, unofficial].
4.  **Weight Calculation (Optional/Advanced):** In multi-camera or novel view synthesis contexts, compute weights based on view direction and surface normal to blend contributions from multiple sources [S1].
    *   Let $V_{toEye}$ be the unit vector from voxel center to eye.
    *   Let $N$ be the unit normal at voxel center.
    *   Let $V_{toCamera}[i]$ be the unit vector from voxel center to camera $i$.
    *   $dotV = \text{dot}(V_{toEye}, V_{toCamera}[i])$
    *   $dotN = \text{dot}(N, V_{toCamera}[i])$
    *   $weightV = dotV > 0.0 ? \text{pow}(dotV, 4) : 0.0$
    *   $weightN = dotN > 0.0 ? \text{pow}(dotN, 4) : 0.0$
    *   $weight[i] = weightV \times weightN$
    *   Normalize weights by dividing by the sum of all weights [S1].
5.  **Rasterization (Splatting):** Rasterize the footprint onto the image plane. Each pixel within the footprint receives a contribution weighted by the footprint table value and the voxel's intrinsic properties (color, opacity) [S3, unofficial].
6.  **Compositing:** Accumulate the splatted contributions into the image buffer. This is typically done front-to-back or back-to-front using alpha blending [S4, unofficial].
    *   Standard Alpha Blending: $C_{out} = C_{src} \alpha_{src} + C_{dst} (1 - \alpha_{src})$, $\alpha_{out} = \alpha_{src} + \alpha_{dst} (1 - \alpha_{src})$.
    *   Interactive adjustments may apply gamma correction to reduce contributions from tissues with differing color densities [S2, unofficial].

**Pseudocode:**
```python
def voxel_splat_render(voxels, camera, image_buffer, footprint_table):
    # 1. Transform and Project
    for voxel in voxels:
        # Transform voxel center to screen space
        screen_pos = camera.mvp_matrix * voxel.position
        
        # Check if voxel is in front of camera and within view frustum
        if screen_pos.z <= 0 or not in_frustum(screen_pos):
            continue
            
        # 2. Determine Footprint
        # Footprint radius/size depends on projection type and depth
        footprint_radius = get_footprint_radius(screen_pos, camera.projection_type)
        
        # 3. Rasterize Splat
        # Iterate over pixels covered by the footprint
        for pixel in pixels_in_rectangle(screen_pos, footprint_radius):
            # Get weight from precomputed footprint table
            # Table stores analytically integrated kernel values
            weight = footprint_table.get_weight(pixel.relative_to_center(screen_pos), footprint_radius)
            
            if weight == 0:
                continue
                
            # 4. Calculate Contribution
            # Optional: Apply view-dependent weighting (e.g., for multi-view synthesis)
            contrib_color = voxel.color * weight
            contrib_alpha = voxel.opacity * weight
            
            # 5. Composite into Image Buffer
            # Front-to-back or back-to-front accumulation
            # Using standard alpha blending
            dst_color = image_buffer[pixel].color
            dst_alpha = image_buffer[pixel].alpha
            
            # Blend source into destination
            new_alpha = contrib_alpha + dst_alpha * (1 - contrib_alpha)
            if new_alpha > 0:
                new_color = (contrib_color * contrib_alpha + dst_color * dst_alpha * (1 - contrib_alpha)) / new_alpha
            else:
                new_color = dst_color
                
            image_buffer[pixel].color = new_color
            image_buffer[pixel].alpha = new_alpha
```

**Parameters:**
*   **Point-size:** Diameter of the splat, can be fixed or distance-dependent [S2, unofficial].
*   **Alpha-value:** Opacity scaling factor [S2, unofficial].
*   **Gamma-value:** Gamma correction applied to reduce contribution of low-density points [S2, unofficial].
*   **Power Exponent:** Used in view-dependent weighting (default 4) to smooth transitions [S1].

**Edge Cases:**
*   **Holes:** Discrete processing can produce holes on periphery or under extreme perspective projection. Countered by distributing energy across multiple pixels via the footprint table [S4, unofficial].
*   **Aliasing:** Minor aliasing artifacts similar to non-anti-aliased triangle models may occur [S1].
*   **Close-range View:** Voxels may appear as rectangular blocks; pixelation artifacts arise from finite RGB image resolution [S1].
*   **Blurring:** The method tends to blur object edges and reduce image contrast [S3, unofficial].

## Subtopics

### [Image-Space Sheet-Buffered Splatting Pipeline](8961-image-space-sheet-buffered-splatting-pipeline.md)
A GPU-accelerated variant that processes voxels in slabs parallel to the image plane, using sheet buffers to avoid CPU-GPU bottlenecks and achieving 2-2.5x speedup over CPU-based bucketing.

### [Orthographic Voxel Sprite Rendering](16665-orthographic-voxel-sprite-rendering.md)
Projects voxels using parallel rays to create a static billboard appearance, solving per-eye pixel shimmer in VR by ensuring identical ray marching for both eyes.

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of voxels projected onto the screen. However, each splat can cover hundreds of pixels, making the pixel-processing cost significant [S3, unofficial].
*   **Memory Complexity:** Requires storage for the voxel data and the footprint lookup table. The footprint table size depends on the maximum splat radius [S3, unofficial].
*   **Performance:** Achieves interactive frame rates (e.g., 1.1 Hz on a 150MHz R4400 for a 256^3 volume) with pre-processing [S3, unofficial]. GPU implementations are acceptable for single-pixel quads but not fully optimized for them [S1].
*   **Strengths:** Only relevant voxels are projected, reducing data processing and storage needs. Suitable for parallelization based on object-space subdivision. Allows interactive value selection and fine-tuning of alpha/gamma [S2, unofficial][S3, unofficial].
*   **Limitations:** Tends to blur edges and reduce contrast. Prone to brightness variations in animation if not using image-aligned slabs [S3, unofficial]. Discrete processing can cause holes without proper footprinting [S4, unofficial].

## Background
Voxel Splat Rendering was introduced by Westover [S3, unofficial][S5, unofficial]. It represents the volume as an array of overlapping basis functions (commonly Gaussian kernels) scaled by voxel values [S3, unofficial]. The method was first published in [20] (cited as [S5, unofficial]). It addresses the aliasing issues of point-based projection by spreading energy across multiple pixels [S3, unofficial].
