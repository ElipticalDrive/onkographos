# Voxel Splat Rendering

Also called: Interactive Splat Rendering with Alpha/Gamma Control, Interactive value selection rendering, Splatting (Object Order), Voxel splatting

## Overview
Voxel Splat Rendering is an object-order volume rendering technique that projects individual voxels from 3D space onto the 2D image plane as geometric primitives (splats), which are then rasterized and accumulated using alpha blending [S3, unofficial][S4, unofficial]. It solves the problem of real-time interactive visualization of volumetric data by leveraging hardware-accelerated rasterization pipelines, allowing users to interactively select voxel subsets and tune rendering parameters like alpha and gamma [S2, unofficial]. Unlike ray-casting methods that compute contributions per pixel, splatting computes contributions per voxel, distributing energy across multiple pixels via a footprint function to mitigate aliasing and holes [S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volumetric dataset $V$ where each voxel $k$ has position $\mathbf{p}_k$, density/extinction coefficient $\rho_k$ (or color/intensity), and optionally a surface normal $\mathbf{n}_k$ [G]. A camera model defined by the Model-View-Projection (MVP) matrix [G].
*   **Output:** A 2D image buffer containing the accumulated color and opacity values [G].

**Data Structures:**
*   **Voxel List:** An array of structures containing:
    *   `position`: 3D coordinates $(x, y, z)$ [G].
    *   `density`: Scalar value $\rho$ [G].
    *   `color`: RGB or RGBA value [G].
    *   `normal`: 3D unit vector $\mathbf{n}$ (optional, used for shading/weighting) [S2, unofficial][S1].
*   **Image Buffer:** 2D array of color and opacity values $(C_x, C_y, \alpha_x, \alpha_y)$ [G].

**Steps:**

1.  **Traversal and Selection:**
    Traverse the volume dataset. Optionally, filter voxels based on user-defined criteria (e.g., value selection via slice clicking, bounding box constraints) to create a subset of active voxels for rendering [S2, unofficial].

2.  **Projection:**
    For each active voxel $k$, transform its position $\mathbf{p}_k$ from volume space to screen space using the MVP matrix. Determine the 2D screen coordinates $(x_k, y_k)$ of the voxel center [S3, unofficial][S4, unofficial].

3.  **Footprint Calculation:**
    Determine the area covered by the splat (footprint) on the screen. For parallel projection, the footprint is constant for all voxels [S3, unofficial]. For perspective projection, the footprint may vary based on depth [G]. The contribution of a voxel to a screen point $(x,y)$ is determined by the footprint function $F(x,y)$, which is the analytically integrated kernel function along a traversing ray [S3, unofficial]:
    $$ F(x,y) = \int h(x-x_k, y-y_k, z) \, dz $$
    where $h$ is a reconstruction kernel, commonly Gaussian [S3, unofficial]. The weight applied to the voxel's contribution at screen location $(x,y)$ is:
    $$ w(x,y) = F(x-x_k, y-y_k) $$
    To counter holes produced by discrete processing, energy is distributed across multiple pixels using a footprint table [S3, unofficial].

4.  **Weighting (Optional):**
    If normals are available, compute a weighting factor to modulate the splat's intensity based on view and surface orientation [S1]. For each camera $i$ (or view direction):
    *   Calculate $\text{dotV} = \mathbf{V}_{\text{toEye}} \cdot \mathbf{V}_{\text{toCamera}[i]}$, where $\mathbf{V}_{\text{toEye}}$ is the unit vector from the voxel center to the eye point, and $\mathbf{V}_{\text{toCamera}[i]}$ is the unit vector from the voxel center to the camera position [S1].
    *   Calculate $\text{dotN} = \mathbf{n} \cdot \mathbf{V}_{\text{toCamera}[i]}$, where $\mathbf{n}$ is the unit normal to the surface at the voxel center [S1].
    *   Compute view-dependent weight: $w_V = \max(0, \text{dotV})^4$ [S1].
    *   Compute normal-dependent weight: $w_N = \max(0, \text{dotN})^4$ [S1].
    *   Compute combined weight: $w_{\text{combined}} = w_V \cdot w_N$ [S1].
    *   Normalize weights by dividing by the sum of all weights [S1].

5.  **Rasterization (Splatting):**
    Render the voxel as a primitive (e.g., a square or circular quad) centered at $(x_k, y_k)$ with a size corresponding to the footprint [S2, unofficial]. The primitive is rasterized into the image buffer. The contribution $P(x,y)$ written to the pixel is modulated by the voxel density and the footprint weight:
    $$ P(x,y) = w(x,y) \cdot \rho_k $$
    If alpha blending is disabled, the splat may be rendered as a point or square to provide a surface-oriented view, potentially using normals for shading [S2, unofficial].

6.  **Compositing:**
    Accumulate the splatted contributions into the image buffer. This is typically done using alpha blending in front-to-back or back-to-front order to handle transparency correctly [S4, unofficial]. The standard alpha blending equation for a new fragment with color $C_f$ and opacity $\alpha_f$ over an existing buffer color $C_b$ and opacity $\alpha_b$ is:
    $$ C_{out} = C_f \alpha_f + C_b \alpha_b (1 - \alpha_f) $$
    $$ \alpha_{out} = \alpha_f + \alpha_b (1 - \alpha_f) $$
    Gamma correction may be applied to reduce the contribution of points from tissues with differing color value densities [S2, unofficial].

**Pseudocode:**

```python
import math

def voxel_splat_rendering(voxels, mvp_matrix, image_width, image_height, camera_eye_pos):
    """
    Renders a volume using voxel splatting.
    
    Args:
        voxels: List of voxel objects with attributes:
            - position: (x, y, z)
            - density: float
            - color: (r, g, b)
            - normal: (nx, ny, nz) [optional]
        mvp_matrix: 4x4 Model-View-Projection matrix
        image_width: int
        image_height: int
        camera_eye_pos: (x, y, z) camera position
        
    Returns:
        image_buffer: 2D list of shape (image_height, image_width) with RGBA tuples
    """
    # Initialize image buffer with zeros (color and alpha)
    image_buffer = [[(0.0, 0.0, 0.0, 0.0) for _ in range(image_width)] for _ in range(image_height)]
    
    for voxel in voxels:
        # 1. Project voxel center to screen space
        # Homogeneous coordinates
        pos_hom = (voxel.position[0], voxel.position[1], voxel.position[2], 1.0)
        clip_coords = multiply_matrix_vector(mvp_matrix, pos_hom)
        
        # Perspective division
        if clip_coords[3] == 0.0:
            continue
            
        ndc_coords = (clip_coords[0] / clip_coords[3], 
                      clip_coords[1] / clip_coords[3], 
                      clip_coords[2] / clip_coords[3])
        
        # Convert NDC [-1, 1] to screen coordinates [0, width/height]
        sx = (ndc_coords[0] + 1.0) * 0.5 * image_width
        sy = (1.0 - ndc_coords[1]) * 0.5 * image_height
        
        # 2. Determine footprint size
        # For parallel projection, footprint is constant.
        # For perspective, it scales with depth.
        footprint_radius = calculate_footprint_radius(voxel.position, camera_eye_pos)
        
        # 3. Calculate weight if normals are available
        weight = 1.0
        if voxel.normal is not None:
            v_to_eye = normalize(subtract(camera_eye_pos, voxel.position))
            v_to_cam = normalize(subtract(camera_eye_pos, voxel.position))
            dot_v = dot(v_to_eye, v_to_cam)
            dot_n = dot(voxel.normal, v_to_cam)
            
            w_v = max(0.0, dot_v) ** 4
            w_n = max(0.0, dot_n) ** 4
            weight = w_v * w_n
            
        # 4. Rasterize the splat
        min_x = max(0, int(sx - footprint_radius))
        max_x = min(image_width, int(sx + footprint_radius))
        min_y = max(0, int(sy - footprint_radius))
        max_y = min(image_height, int(sy + footprint_radius))
        
        for y in range(min_y, max_y):
            for x in range(min_x, max_x):
                dx = x - sx
                dy = y - sy
                dist_sq = dx*dx + dy*dy
                
                # Evaluate footprint function (Gaussian kernel) [G]
                sigma = footprint_radius / 2.0
                footprint_val = math.exp(-dist_sq / (2.0 * sigma * sigma)) if sigma > 0 else 0.0
                
                # Modulate by voxel density and weight
                contribution_color = (voxel.color[0] * footprint_val * weight * voxel.density,
                                      voxel.color[1] * footprint_val * weight * voxel.density,
                                      voxel.color[2] * footprint_val * weight * voxel.density)
                contribution_alpha = footprint_val * weight * voxel.density
                
                # 5. Composite into buffer
                buf_color = image_buffer[y][x][:3]
                buf_alpha = image_buffer[y][x][3]
                
                new_alpha = contribution_alpha + buf_alpha * (1.0 - contribution_alpha)
                if new_alpha > 0.0:
                    new_color = (contribution_color[0] * contribution_alpha + buf_color[0] * buf_alpha * (1.0 - contribution_alpha)) / new_alpha, \
                                (contribution_color[1] * contribution_alpha + buf_color[1] * buf_alpha * (1.0 - contribution_alpha)) / new_alpha, \
                                (contribution_color[2] * contribution_alpha + buf_color[2] * buf_alpha * (1.0 - contribution_alpha)) / new_alpha
                else:
                    new_color = buf_color
                    
                image_buffer[y][x] = (new_color[0], new_color[1], new_color[2], new_alpha)
                
    return image_buffer

def multiply_matrix_vector(matrix, vector):
    # Standard 4x4 matrix-vector multiplication
    return (
        matrix[0][0]*vector[0] + matrix[0][1]*vector[1] + matrix[0][2]*vector[2] + matrix[0][3]*vector[3],
        matrix[1][0]*vector[0] + matrix[1][1]*vector[1] + matrix[1][2]*vector[2] + matrix[1][3]*vector[3],
        matrix[2][0]*vector[0] + matrix[2][1]*vector[1] + matrix[2][2]*vector[2] + matrix[2][3]*vector[3],
        matrix[3][0]*vector[0] + matrix[3][1]*vector[1] + matrix[3][2]*vector[2] + matrix[3][3]*vector[3]
    )

def subtract(v1, v2):
    return (v1[0]-v2[0], v1[1]-v2[1], v1[2]-v2[2])

def normalize(v):
    length = math.sqrt(v[0]**2 + v[1]**2 + v[2]**2)
    if length == 0: return (0,0,0)
    return (v[0]/length, v[1]/length, v[2]/length)

def dot(v1, v2):
    return v1[0]*v2[0] + v1[1]*v2[1] + v1[2]*v2[2]
```

**Parameters:**
*   **Point-size / Footprint Radius:** Determines the spread of the splat. Can be fixed or distance-dependent [S2, unofficial].
*   **Alpha-value:** Controls the opacity of individual voxels [S2, unofficial].
*   **Gamma-value:** Applied to reduce contribution of points from tissues with differing densities [S2, unofficial].
*   **Power Exponent:** Used in weighting calculations (default 4) [S1].

**Edge Cases and Pitfalls:**
*   **Holes:** Discrete processing can produce holes on the periphery or during extreme perspective projection. This is countered by distributing energy across multiple pixels via a footprint table [S3, unofficial].
*   **Aliasing:** Minor aliasing artifacts similar to non-anti-aliased triangle models may occur. GPU rasterization is not optimized for single-pixel quads, but performance is acceptable [S1].
*   **Close-range Views:** At close range, voxel splats may appear as rectangular blocks covering many pixels, leading to pixelation artifacts induced by the finite resolution of RGB images [S1].
*   **Brightness Variations:** Summing voxel kernels within volume slices most parallel to the image plane is prone to severe brightness variations in animated viewing [S3, unofficial].

## Subtopics

### [Image-Space Sheet-Buffered Splatting Pipeline](8961-image-space-sheet-buffered-splatting-pipeline.md)
A GPU-based variant that processes voxels in slabs parallel to the image plane, performing bucket construction, transformation, and depth sorting entirely on the GPU to avoid CPU-GPU memory transfer bottlenecks. Unlike CPU-based buckets containing all intersecting voxels, GPU buckets contain depth-sorted voxels whose centers fall inside a specific slab, allowing each voxel to belong to exactly one bucket while still being splatted for all intersecting slabs. Accelerates rendering by 2 to 2.5 times compared to CPU-based implementations.

## Operating characteristics
*   **Time Complexity:** $O(N \cdot A)$, where $N$ is the number of voxels and $A$ is the average area (in pixels) covered by a splat. The complexity depends on the footprint size and the density of voxels [S3, unofficial].
*   **Memory Complexity:** $O(W \cdot H)$ for the image buffer, plus $O(N)$ for the voxel data [G].
*   **Performance:** Enables real-time interactivity due to hardware-accelerated rasterization [S1][S2, unofficial][S3, unofficial]. Performance is acceptable even for single-pixel quads, though not optimal [S1].
*   **Strengths:** Simple and efficient method for displaying contours and volume-oriented views. Allows interactive selection of voxelsets and fine-tuning of parameters [S2, unofficial].
*   **Limitations:** Discrete processing can cause holes and aliasing. Close-range views suffer from pixelation and block artifacts [S1][S3, unofficial]. Tends to blur the edges of objects and reduce image contrast [S3, unofficial]. Requires extensive filtering, making it time-consuming [S3, unofficial].
*   **When to use:** Real-time interactive visualization of volumetric datasets, especially when user interaction (selection, parameter tuning) is required [S2, unofficial].
*   **When not to use:** Not given in the sources.

## Background
Voxel Splatting was first published in [20] (referenced in [S4, unofficial]). It is an object-space front-to-back algorithm where voxels are projected onto the screen as contributions that are highest at the center and drop off away from it [S4, unofficial]. The method is part of the broader splatting family, which treats volumetric data as a set of geometric primitives [S1][S3, unofficial][S4, unofficial]. It has been used in various applications for interactive visualization of volumetric data, including medical imaging and scientific visualization [S2, unofficial].
