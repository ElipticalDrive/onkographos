# Voxel Splat Rendering

Also called: Interactive Splat Rendering with Alpha/Gamma Control, Interactive value selection rendering, Splatting (Object Order), Voxel splatting

## Overview
Voxel Splat Rendering is an object-order volume rendering technique where each voxel is transformed into screen space and projected as a 2D footprint (splat) that contributes to the final image via alpha blending [S3, unofficial][S4, unofficial]. Unlike ray casting, which traverses rays per pixel, splatting traverses voxels per object, distributing each voxel's energy across multiple pixels to mitigate aliasing and holes caused by discrete sampling [S3, unofficial][S4, unofficial]. It sets itself apart from sibling methods like Circle Splat Rendering by typically utilizing square or axis-aligned bounding box projections for efficient rasterization, and from Tetrahedral Splatting by operating on grid-aligned volumetric primitives rather than unstructured tetrahedra [S2, unofficial][S3, unofficial].

## How it works
**Inputs:** 3D volume dataset (voxel positions, values, normals), camera parameters (view and projection matrices), rendering parameters (point size, alpha, gamma).
**Outputs:** 2D color and opacity image buffer.

**Data Structures:**
*   **Voxel:** Contains position $(x,y,z)$, value (color/density), and optionally a normal vector $\mathbf{n}$. Normals may be quantized to one of 240 pre-defined directions stored in 1 byte [S2, unofficial].
*   **Footprint Table:** A 2D lookup table storing the analytically integrated kernel function along a traversing ray. Entries correspond to screen-space offsets from the voxel center [S3, unofficial].
*   **Image Buffer:** Accumulates color and opacity via alpha blending.

**Steps:**
1.  **Traversal:** Traverse the 3D dataset, typically front-to-back relative to the camera [S5, unofficial][S4, unofficial].
2.  **Culling (Optional):** Cull voxels whose surface normals point away from the observer to reduce processing load [S3, unofficial].
3.  **Transformation:** Transform each voxel's center from object space to screen space using the Model-View-Projection (MVP) matrix [S3, unofficial][S4, unofficial].
4.  **Bounding Box Calculation:** Compute the axis-aligned bounding rectangle of the projected voxel in screen space [S1].
5.  **Weighting (Optional):** Calculate view-dependent and normal-dependent weights to modulate contribution, reducing artifacts in transitions between textures [S1]:
    $$ \text{weight}_V = \begin{cases} \text{dot}(\mathbf{V}_{\text{toEye}}, \mathbf{V}_{\text{toCamera}[i]})^4 & \text{if } \text{dot} > 0 \\ 0 & \text{otherwise} \end{cases} $$
    $$ \text{weight}_N = \begin{cases} \text{dot}(\mathbf{n}, \mathbf{V}_{\text{toCamera}[i]})^4 & \text{if } \text{dot} > 0 \\ 0 & \text{otherwise} \end{cases} $$
    $$ w[i] = \text{weight}_V \times \text{weight}_N $$
    Normalize weights by dividing by the sum of all weights [S1].
6.  **Splatting (Rasterization):** Render the projected voxel as a quad (pair of triangles) covering the bounding rectangle. Use the Footprint Table to determine the contribution of each pixel within the rectangle. The footprint spreads the voxel's energy across multiple pixels, countering holes produced by discrete processing [S4, unofficial].
7.  **Compositing:** Alpha blend the splatted contribution into the image buffer. This can be done front-to-back or back-to-front [S4, unofficial].
    *   *Surface-oriented view:* Disable alpha blending; use normals to shade points [S2, unofficial].
    *   *Volume-oriented view:* Enable alpha blending and gamma correction to reduce contributions from tissues with differing densities [S2, unofficial].

**Pseudocode:**
```python
def voxel_splat_rendering(volume, camera, image_buffer):
    # Initialize image buffer with zero color and zero opacity
    image_buffer.clear()
    
    # Traverse voxels front-to-back
    for voxel in volume.front_to_back_traversal():
        # Transform voxel center to screen space
        screen_pos = camera.mvp_matrix * voxel.position
        
        # Cull if normal points away (optional optimization)
        if voxel.has_normal:
            view_dir = normalize(camera.eye_position - voxel.position)
            if dot(voxel.normal, view_dir) < 0:
                continue
                
        # Calculate bounding box in screen space
        bbox = get_axis_aligned_bounding_box(screen_pos, voxel.size)
        
        # Determine footprint weights for pixels in bbox
        # Using a precomputed footprint table F(x,y)
        for pixel in bbox.pixels:
            offset = pixel.position - screen_pos
            footprint_weight = footprint_table.lookup(offset)
            
            # Modulate by voxel value and optional view/normal weights
            contribution = voxel.value * footprint_weight
            
            # Alpha blend into image buffer
            image_buffer.alpha_blend(pixel.position, contribution)
```

**Parameters:**
*   **Point-size:** Diameter of the splat, can be fixed or distance-dependent [S2, unofficial].
*   **Alpha-value:** Controls opacity blending [S2, unofficial].
*   **Gamma-value:** Adjusts contrast for tissues with differing color value densities [S2, unofficial].
*   **Power exponent:** Used in weighting calculations (typically 4) to reduce transition artifacts [S1].

**Edge Cases and Pitfalls:**
*   **Holes:** Discrete processing produces holes on the periphery or during extreme perspective projection. Mitigated by distributing energy across multiple pixels via the footprint table [S4, unofficial].
*   **Blurring:** Tends to blur object edges and reduce image contrast [S3, unofficial].
*   **Aliasing:** Minor aliasing artifacts similar to non-anti-aliased triangle models; close-range views show rectangular block artifacts and pixelation from finite RGB image resolution [S1].
*   **Performance:** Requires extensive filtering and is time-consuming for large datasets if not optimized [S3, unofficial].

## Subtopics

### [Image-Space Sheet-Buffered Splatting Pipeline](8961-image-space-sheet-buffered-splatting-pipeline.md)
A GPU-accelerated variant that processes voxels in slabs parallel to the image plane, performing bucket construction and depth sorting on the GPU to avoid CPU-GPU bottlenecks, offering 2-2.5x speedup over CPU-based bucketing.

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of voxels $N$ and the number of pixels covered by each splat $P$. Total complexity $O(N \cdot P)$.
*   **Memory Complexity:** $O(N)$ for voxel storage plus $O(W \cdot H)$ for the image buffer and footprint table, where $W, H$ are image dimensions.
*   **Performance:** Achieves interactive frame rates (e.g., 1.1 Hz on a 150MHz R4400 for a $256^3$ volume with pre-processing) [S3, unofficial]. GPU implementations are significantly faster, though rasterization of single-pixel quads is not always optimized [S1].
*   **Strengths:** Interactive value selection; efficient culling of irrelevant voxels; suitable for parallelization based on object space subdivision [S3, unofficial].
*   **Limitations:** Blurs edges; prone to brightness variations in animation (unless image-aligned splatting is used); discrete processing artifacts at extreme perspectives [S3, unofficial][S4, unofficial].
*   **When to use:** Interactive visualization, large datasets where pre-processing is acceptable, and when surface-oriented or volume-oriented views with interactive parameter tuning are required [S2, unofficial].
*   **When not to use:** When high-fidelity edge preservation is critical, or when extreme perspective projection causes significant discretization artifacts that cannot be mitigated by footprint size [S3, unofficial][S4, unofficial].

## Background
Voxel Splatting was first published by Westover [S5, unofficial]. It represents the volume as an array of overlapping basis functions (commonly Gaussian kernels) scaled by voxel values, projecting them to the screen [S3, unofficial]. The method was introduced to address the aliasing and sampling issues of ray casting while providing interactive performance. Variations include Mueller's image-aligned splatting, which processes voxel kernels within slabs aligned parallel to the image plane to eliminate brightness variations in animation [S3, unofficial].
