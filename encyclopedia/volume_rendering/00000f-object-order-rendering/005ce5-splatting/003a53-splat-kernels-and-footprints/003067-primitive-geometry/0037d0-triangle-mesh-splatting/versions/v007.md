# Triangle Mesh Splatting

Also called: Laur and Hanrahan splatting

## Overview
Triangle Mesh Splatting is a volume rendering technique that approximates continuous splat kernels with discrete triangle meshes to leverage standard graphics hardware for rapid scan conversion [S1, unofficial]. Unlike analytic footprint methods or circular splats, it relies on the rasterization pipeline to handle the projection and compositing of the splat's 2D footprint, trading geometric precision for rendering speed.

## How it works
**Inputs and Outputs:**
*   **Input:** A set of splat primitives, each defined by a 3D position, orientation, scale, and opacity/value.
*   **Output:** A 2D image buffer with accumulated color and depth.

**Data Structures:**
Each splat is represented as a triangle mesh. The specific topology (e.g., a quad decomposed into two triangles) approximates the shape of the splat kernel's footprint. The mesh vertices are stored in object space.

**Steps:**
1.  **Mesh Approximation:** Each splat primitive is approximated by a triangle mesh. The mesh geometry is designed to match the spatial extent and falloff of the underlying splat kernel [S1, unofficial].
2.  **Transformation:** The mesh vertices are transformed from object space to clip space using the Model-View-Projection (MVP) matrix.
3.  **Rasterization:** The transformed triangles are scan-converted by the graphics hardware. This step effectively computes the 2D footprint $F(x,y)$ on the screen, handling overlap and depth testing [S1, unofficial].
4.  **Compositing:** During rasterization, fragment shaders accumulate the splat's value and opacity into the frame buffer, typically using front-to-back or back-to-front alpha blending depending on the desired compositing order.

**Pseudocode:**
```python
# Pseudocode for rendering a single splat using triangle mesh approximation
def render_triangle_mesh_splat(splat, mvp_matrix, framebuffer):
    # 1. Approximate the splat kernel with a triangle mesh
    # The mesh vertices are defined in object space to match the kernel's shape
    mesh = approximate_splat_with_mesh(splat)
    
    # 2. Transform vertices to clip space
    clip_vertices = []
    for vertex in mesh.vertices:
        # Homogeneous transformation
        clip_pos = mvp_matrix @ vec4(vertex, 1.0)
        clip_vertices.append(clip_pos)
    
    # 3. Rasterize the mesh
    # Graphics hardware handles scan conversion and depth testing
    # Fragment shader computes the contribution of each pixel covered by the triangle
    for triangle in mesh.triangles:
        v0, v1, v2 = clip_vertices[triangle[0]], clip_vertices[triangle[1]], clip_vertices[triangle[2]]
        
        # Interpolate attributes (position, opacity, color) across the triangle
        # This effectively evaluates the footprint F(x,y)
        rasterize_triangle(v0, v1, v2, splat.opacity, splat.color, framebuffer)
```

**Parameters:**
*   **Mesh Resolution:** The number of triangles used to approximate the splat. Higher resolution yields better fidelity but increases rasterization cost [S1, unofficial].
*   **MVP Matrix:** The standard view-projection matrix.

**Edge Cases:**
*   **Degenerate Triangles:** If the splat scale is zero or near-zero, the mesh may degenerate, causing rasterization artifacts or division by zero in perspective correction.
*   **Back-Facing Culling:** Standard graphics pipelines cull back-facing triangles. For splatting, this may need to be disabled if the splat kernel is non-directional and requires full coverage.

## Subtopics

### [Differentiable Triangle Splatting](8761-differentiable-triangle-splatting.md)
Differentiable Triangle Splatting is a real-time differentiable renderer that represents a scene as a soup of unstructured, disconnected 3D triangles and optimizes them via end-to-end gradients by rendering each triangle as a differentiable splat in screen space. It merges the adaptability of Gaussian splatting with the efficiency of triangle primitives, surpassing 3D Gaussian Splatting (3DGS), 2D Gaussian Splatting (2DGS), and 3D Convex Splatting (3DCS) in visual fidelity, training speed, and rendering throughput.

## Operating characteristics
*   **Time Complexity:** Dominated by rasterization cost, which is proportional to the number of triangles in the mesh and the area of the footprint on the screen.
*   **Memory Complexity:** Linear in the number of splats, with additional memory for the mesh data structures.
*   **Strengths:** Leverages highly optimized GPU rasterization hardware, enabling real-time performance for large numbers of splats.
*   **Limitations:** Approximation error depends on mesh resolution. Less precise than analytic methods for complex kernel shapes.
*   **When to Use:** When real-time performance is critical and the splat kernels can be well-approximated by triangles.
*   **When Not to Use:** When high geometric fidelity of the kernel shape is required, or when the number of splats is small enough that analytic evaluation is faster.

## Background
Triangle Mesh Splatting was introduced by Laur and Hanrahan as a method to accelerate splatting by approximating view-dependent footprints with triangle meshes, allowing the use of standard graphics hardware for scan conversion [S1, unofficial]. It is part of the broader family of splatting techniques that map 3D data to 2D screen space for efficient rendering.
