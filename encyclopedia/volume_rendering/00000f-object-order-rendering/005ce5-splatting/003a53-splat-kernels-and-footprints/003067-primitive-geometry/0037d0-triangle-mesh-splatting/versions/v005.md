# Triangle Mesh Splatting

Also called: Laur and Hanrahan splatting

## Overview
Triangle Mesh Splatting is a volume rendering technique that approximates volumetric splats with triangle meshes to leverage graphics hardware for rapid scan conversion of footprints [S1, unofficial]. It distinguishes itself from sibling methods like Circle Splat Rendering by replacing analytical footprint computation with rasterization-based approximation, trading exact analytical integration for significant rendering speed improvements via standard GPU pipelines [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of volumetric primitives (voxels or splats) defined in object space, each with a position, orientation, and density $\rho$.
*   **Output:** A 2D screen image with accumulated color and opacity.

**Data Structures:**
*   **Primitive Representation:** Each splat is represented as a triangle mesh. The specific topology (e.g., a single triangle, a quad decomposed into two triangles) is not detailed in the sources [S1, unofficial].
*   **Transformation:** The Model-View-Projection (MVP) matrix transforms object-space coordinates to screen space.

**Steps:**
1.  **Transformation:** Transform the vertices of the triangle mesh representing each splat from object space to screen space using the MVP matrix [S1, unofficial].
2.  **Rasterization:** Use graphics hardware (GPU) to scan convert the transformed triangle mesh onto the screen buffer [S1, unofficial].
3.  **Footprint Approximation:** The rasterized triangle serves as an approximation of the splat's footprint. The hardware handles the coverage calculation, effectively integrating the kernel over the screen area [S1, unofficial].
4.  **Accumulation:** Modulate the rasterized footprint by the primitive's density $\rho_k$ and accumulate contributions to the pixel using alpha blending, consistent with the parent method's principles.

**Formulas:**
The contribution $P(x,y)$ to a pixel at screen location $(x,y)$ is determined by the footprint weight $w(x,y)$ derived from the rasterized triangle and the density $\rho_k$:
$$ P(x,y) = w(x,y) \cdot \rho_k $$
Where $w(x,y)$ is the result of the hardware scan conversion of the triangle mesh [S1, unofficial].

**Parameters:**
*   **Triangle Mesh Resolution:** Not given in the sources.
*   **Rasterization Settings:** Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Precision:** Hardware rasterization may introduce discretization errors compared to analytical integration [S1, unofficial].
*   **Boundaries:** The approximation quality depends on the triangle's alignment with the pixel grid [S1, unofficial].

## Subtopics

### [Differentiable Triangle Splatting](8761-differentiable-triangle-splatting.md)
A real-time differentiable renderer that represents scenes as unstructured 3D triangles, optimizing them via end-to-end gradients. It uses a single smoothness parameter $\sigma$ for all triangles, ensuring consistent spatial influence regardless of depth, and surpasses 3D Gaussian Splatting in fidelity and speed.

## Operating characteristics
*   **Time Complexity:** Faster than analytical footprint computation due to hardware acceleration [S1, unofficial].
*   **Memory Complexity:** Depends on the triangle mesh representation of each splat [S1, unofficial].
*   **Strengths:** Rapid scan conversion using graphics hardware; improved rendering speed [S1, unofficial].
*   **Limitations:** Approximate footprint; potential loss of analytical precision [S1, unofficial].
*   **When to Use:** When rendering speed is critical and hardware rasterization is available [S1, unofficial].
*   **When Not to Use:** When exact analytical integration of the footprint is required [S1, unofficial].

## Background
Originated by Laur and Hanrahan, who proposed approximating splats with triangle meshes to utilize graphics hardware for quick scan conversion [S1, unofficial]. This approach was part of a broader effort to accelerate volume rendering by leveraging existing graphics pipelines, alongside other methods like texture mapping hardware [S1, unofficial].
