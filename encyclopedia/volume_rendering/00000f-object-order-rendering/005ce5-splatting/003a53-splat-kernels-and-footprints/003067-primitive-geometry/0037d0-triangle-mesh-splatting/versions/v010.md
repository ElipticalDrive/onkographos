# Triangle Mesh Splatting
Also called: Laur and Hanrahan splatting
## Overview
Triangle Mesh Splatting is an object-order rendering technique that approximates volumetric splats with triangle meshes to leverage graphics hardware for rapid scan conversion [S1, unofficial].
## How it works
**Inputs and Outputs:**
- Input: A set of splats, each defined by a center position, orientation, shape parameters (e.g., covariance matrix), color, and opacity [G].
- Output: A 2D image buffer with accumulated color and opacity [G].

**Data Structures:**
- Splat Representation: Center position $\mathbf{p}$, orientation, covariance matrix $\Sigma$, color $C$, opacity $\alpha$ [G].
- Triangle Mesh: List of vertices and indices defining triangles that approximate the splat's screen-space footprint [G].

**Steps:**
1. **Transformation:** Transform the splat center from object space to screen space using the Model-View-Projection (MVP) matrix [G].
2. **Footprint Approximation:** Approximate the splat's footprint (e.g., an ellipse) with a triangle mesh [S1, unofficial].
3. **Rasterization:** Rasterize the triangle mesh to determine covered pixels (fragments) [G].
4. **Fragment Processing:** Evaluate the splat kernel function at each fragment's screen-space coordinates to compute weight [G].
5. **Compositing:** Accumulate the fragment's color and opacity into the image buffer using alpha compositing, ordered by depth [G].

**Formulas:**
- Screen-space position: $\mathbf{p}_{screen} = P \cdot V \cdot M \cdot \mathbf{p}_{object}$ [G]
- Splat kernel value: $K(\mathbf{u}) = \exp(-\frac{1}{2} \mathbf{u}^T \Sigma^{-1} \mathbf{u})$, where $\mathbf{u}$ is the vector from the splat center to the fragment, and $\Sigma$ is the covariance matrix [G]
- Color contribution: $C_{frag} = C_{splat} \cdot K(\mathbf{u}) \cdot \alpha_{splat}$ [G]

**Parameters:**
- Triangle mesh resolution: The number of triangles used to approximate the footprint [G].
- Splat kernel width: Controls the spread of the splat [G].

**Edge Cases and Pitfalls:**
- Precision: Floating-point precision issues may arise when transforming coordinates, especially for large scenes [G].
- Boundaries: Ensure that the triangle mesh fully covers the splat's footprint to avoid artifacts [G].
- Degenerate Input: Handle splats with zero size or invalid orientations [G].

**Pseudocode:**
```python
def triangle_mesh_splatting(splats, image_width, image_height, mvp_matrix):
    image = [[[0.0, 0.0, 0.0] for _ in range(image_width)] for _ in range(image_height)]
    alpha_buffer = [[0.0] * image_width for _ in range(image_height)]

    def compute_bounding_box(tri, w, h):
        xs = [max(0, min(w - 1, int(v[0]))) for v in tri]
        ys = [max(0, min(h - 1, int(v[1]))) for v in tri]
        return min(xs), min(ys), max(xs), max(ys)

    def point_in_triangle(px, py, tri):
        x1, y1 = tri[0]
        x2, y2 = tri[1]
        x3, y3 = tri[2]
        denom = (y2 - y3) * (x1 - x3) + (x3 - x2) * (y1 - y3)
        if denom == 0: return False
        u = ((y2 - y3) * (px - x3) + (x3 - x2) * (py - y3)) / denom
        v = ((y3 - y1) * (px - x3) + (x1 - x3) * (py - y3)) / denom
        return 0 <= u <= 1 and 0 <= v <= 1 and u + v <= 1

    for splat in splats:
        p_obj = [splat.center[0], splat.center[1], splat.center[2], 1.0]
        p_screen = mat_mul(mvp_matrix, p_obj)
        if p_screen[3] <= 0: continue
        p_screen[0] /= p_screen[3]
        p_screen[1] /= p_screen[3]

        # Sources do not specify mesh generation; standard polygonization of the footprint is used [G].
        triangles = []

        for tri in triangles:
            bbox = compute_bounding_box(tri, image_width, image_height)
            for y in range(bbox[1], bbox[3] + 1):
                for x in range(bbox[0], bbox[2] + 1):
                    if point_in_triangle(x, y, tri):
                        u = [x - p_screen[0], y - p_screen[1]]
                        cov_inv = inverse(splat.covariance)
                        k = exp(-0.5 * dot(u, mat_mul(cov_inv, u)))
                        if k > 0.01:
                            c_frag = [c * k for c in splat.color]
                            a_frag = splat.opacity * k
                            old_alpha = alpha_buffer[y][x]
                            new_alpha = a_frag * (1.0 - old_alpha)
                            alpha_buffer[y][x] = old_alpha + new_alpha
                            for i in range(3):
                                image[y][x][i] = image[y][x][i] * old_alpha + c_frag[i] * new_alpha
```
## Subtopics

### [Differentiable Triangle Splatting](8761-differentiable-triangle-splatting.md)
Differentiable Triangle Splatting is a real-time differentiable renderer that represents a scene as a soup of unstructured, disconnected 3D triangles and optimizes them via end-to-end gradients by rendering each triangle as a differentiable splat in screen space. It merges the adaptability of Gaussian splatting with the efficiency of triangle primitives, surpassing 3D Gaussian Splatting (3DGS), 2D Gaussian Splatting (2DGS), and 3D Convex Splatting (3DCS) in visual fidelity, training speed, and rendering throughput.

## Operating characteristics
- **Time Complexity:** Depends on the number of splats and the resolution of the triangle mesh approximation [G].
- **Memory Complexity:** Proportional to the number of splats and the size of the triangle meshes [G].
- **Performance:** Fast rendering due to hardware acceleration. Performance scales well with the number of splats [G].
- **Strengths:** Efficient use of graphics hardware, flexible footprint shapes [G].
- **Limitations:** Approximation errors from triangle mesh representation, potential artifacts at low mesh resolutions [G].
- **When to Use:** When real-time rendering of complex splat shapes is required and hardware acceleration is available [G].
- **When Not to Use:** When high precision is required and approximation errors are unacceptable [G].
## Background
Triangle Mesh Splatting was introduced by Laur and Hanrahan as a method to improve rendering speed by approximating splats with triangle meshes and using graphics hardware for scan conversion [S1, unofficial].
