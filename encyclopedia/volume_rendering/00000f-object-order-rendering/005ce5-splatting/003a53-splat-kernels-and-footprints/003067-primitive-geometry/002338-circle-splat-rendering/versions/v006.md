# Circle Splat Rendering

## Overview
Circle Splat Rendering projects 3D voxels into 2D screen-space quads (splats) to accelerate volume visualization by leveraging the GPU's rasterization pipeline [S1, unofficial]. It differs from [Voxel Splat Rendering](3730-voxel-splat-rendering.md) by explicitly computing a fixed offset based on grid scale and splat size to determine quad dimensions, and from [Tetrahedral Splatting](3181-tetrahedral-splatting.md) by using axis-aligned quads rather than perspective-correct tetrahedra [S1, unofficial].

## How it works
**Inputs:**
- Voxel position in object space (via `gl_Position` in vertex shader).
- Voxel color and normal.
- Uniforms: Model-View matrix ($MV$), Projection matrix ($P$), entity scale ($scale$), grid length ($gridLength$), splat size parameter ($splatSize$), and boolean flag $cullInvisibleFaces$.

**Outputs:**
- A triangle strip of four vertices representing a screen-space quad.
- Interpolated color and normal for the fragment shader.

**Data Structures:**
- The geometry shader receives a single point per voxel (`layout(points) in`).
- It emits a `triangle_strip` with `max_vertices = 4`.
- Vertex attributes passed to the fragment shader: `color` (vec4), `normal` (vec3).

**Steps:**
1. **Transform to View Space:** Compute the voxel position in view space:
   $$ P_{view} = MV \times P_{obj} $$
   where $P_{obj}$ is the input vertex position.

2. **Transform to Clip Space:** Project the view-space position:
   $$ P_{clip} = P \times P_{view} $$
   Normalize to normalized device coordinates (NDC):
   $$ P_{ndc} = P_{clip} / P_{clip}.w $$

3. **Calculate Voxel Offset:** Determine the physical size of the splat in view space. The offset is derived from the diagonal of a unit square scaled by the grid parameters:
   $$ offset = splatSize \times \frac{scale}{gridLength} \times \sqrt{2} $$
   where $\sqrt{2} \approx 1.414213$ [S1, unofficial].

4. **Compute Clip-Space Half-Edge:** To determine the spatial extent in clip space for culling, calculate the position of the right edge midpoint in view space, project it, and normalize:
   $$ P_{right\_mid\_view} = (P_{view}.xy + (0.5, 0) \times offset, P_{view}.zw) $$
   $$ P_{right\_mid\_clip} = P \times P_{right\_mid\_view} $$
   $$ P_{right\_mid\_ndc} = P_{right\_mid\_clip} / P_{right\_mid\_clip}.w $$
   The half-edge length in clip space is the Euclidean distance between the center and this midpoint in NDC:
   $$ half\_edge = \text{distance}(P_{ndc}, P_{right\_mid\_ndc}) $$

5. **Frustum Culling:** Define a culling border that accounts for the splat's extent:
   $$ border = 1 + half\_edge $$
   Discard the primitive if the center $P_{ndc}.x$ or $P_{ndc}.y$ falls outside $[-border, border]$ [S1, unofficial].

6. **Back-Face Culling (Optional):** If $cullInvisibleFaces$ is true, compute the view-space normal:
   $$ N_{view} = MV \times (N_{obj}, 0) $$
   Discard if the dot product of the vector from the camera (origin in view space) to the voxel and the normal is negative:
   $$ \text{if } \text{dot}(-P_{view}.xyz, N_{view}.xyz) < 0 \text{, discard} $$
   [S1, unofficial].

7. **Emit Vertices:** Emit four vertices for a triangle strip. The vertices are defined in view space by offsetting the center by $\pm 0.5 \times offset$ in X and Y, then projected to clip space:
   - Bottom-Left: $P_{view}.xy + (-0.5, -0.5) \times offset$
   - Bottom-Right: $P_{view}.xy + (0.5, -0.5) \times offset$
   - Top-Left: $P_{view}.xy + (-0.5, 0.5) \times offset$
   - Top-Right: $P_{view}.xy + (0.5, 0.5) \times offset$
   
   Each vertex is transformed by $P$ for `gl_Position`, and texture coordinates $(0,0), (1,0), (0,1), (1,1)$ are assigned respectively [S1, unofficial].

**Pseudocode:**
```python
def process_voxel(voxel_pos_obj, voxel_color, voxel_normal, MV, P, scale, grid_length, splat_size, cull_invisible_faces):
    # 1. Transform to View Space
    voxel_pos_view = MV * voxel_pos_obj
    
    # 2. Transform to Clip Space and NDC
    voxel_pos_clip = P * voxel_pos_view
    voxel_pos_ndc = voxel_pos_clip / voxel_pos_clip.w
    
    # 3. Calculate Voxel Offset
    offset = splat_size * (scale / grid_length) * 1.414213
    
    # 4. Compute Clip-Space Half-Edge for Culling
    # Right edge midpoint in view space
    right_mid_view_x = voxel_pos_view.x + 0.5 * offset
    right_mid_view_y = voxel_pos_view.y
    right_mid_view_z = voxel_pos_view.z
    right_mid_view_w = voxel_pos_view.w
    
    right_mid_clip = P * vec4(right_mid_view_x, right_mid_view_y, right_mid_view_z, right_mid_view_w)
    right_mid_ndc = right_mid_clip / right_mid_clip.w
    
    half_edge = distance(voxel_pos_ndc.xy, right_mid_ndc.xy)
    border = 1.0 + half_edge
    
    # 5. Frustum Culling
    if (voxel_pos_ndc.x < -border or voxel_pos_ndc.x > border or
        voxel_pos_ndc.y < -border or voxel_pos_ndc.y > border):
        return None # Discard

    # 6. Back-Face Culling
    if cull_invisible_faces:
        # Transform normal (w=0 for direction vectors)
        normal_view = MV * vec4(voxel_normal, 0.0)
        # Vector from camera (0,0,0 in view) to voxel
        view_dir = -voxel_pos_view.xyz
        if dot(view_dir, normal_view.xyz) < 0:
            return None # Discard

    # 7. Emit Vertices
    vertices = []
    offsets = [(-0.5, -0.5), (0.5, -0.5), (-0.5, 0.5), (0.5, 0.5)]
    tex_coords = [(0, 0), (1, 0), (0, 1), (1, 1)]
    
    for i in range(4):
        dx, dy = offsets[i]
        # Calculate view space position of the corner
        corner_view_x = voxel_pos_view.x + dx * offset
        corner_view_y = voxel_pos_view.y + dy * offset
        corner_view_z = voxel_pos_view.z
        corner_view_w = voxel_pos_view.w
        
        # Project to clip space
        corner_clip = P * vec4(corner_view_x, corner_view_y, corner_view_z, corner_view_w)
        
        vertices.append({
            'position': corner_clip,
            'tex_coord': tex_coords[i],
            'color': voxel_color,
            'normal': voxel_normal
        })
        
    return vertices
```

## Operating characteristics
- **Time Complexity:** $O(1)$ per voxel for geometry generation, assuming constant matrix multiplications.
- **Memory Complexity:** Minimal; only uniform buffers and vertex attributes are required.
- **Performance:** Highly efficient on GPUs due to fixed-function rasterization of quads. Performance scales linearly with voxel count.
- **Strengths:** Simple implementation; leverages hardware rasterization; effective for dense volumes.
- **Limitations:** Quads are axis-aligned in view space, which can cause aliasing or gaps if not properly blended; does not handle perspective distortion of the voxel shape as accurately as tetrahedral splatting.
- **When to use:** Real-time visualization of large voxel datasets where performance is critical and slight geometric approximation is acceptable.
- **When not to use:** When precise perspective-correct volume representation is required (use [Tetrahedral Splatting](3181-tetrahedral-splatting.md) instead).

## Background
Circle Splat Rendering, also known as square_splat, is implemented in the SVO Renderer project by mmalesadev [S1, unofficial]. It is part of a broader family of splatting techniques used in volume rendering to map 3D data to 2D screen space. The method relies on standard OpenGL geometry shaders to expand point primitives into quads.
