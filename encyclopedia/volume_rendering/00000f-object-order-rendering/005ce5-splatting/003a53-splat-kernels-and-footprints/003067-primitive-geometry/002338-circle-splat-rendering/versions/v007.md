# Circle Splat Rendering
## Overview
Circle Splat Rendering is a volume rendering technique where voxels are projected as 2D quads (splats) in screen space [S1, unofficial]. It differs from other splatting methods by using a fixed offset derived from the splat size parameter and grid scale to determine the quad dimensions, effectively rendering square footprints that approximate circular coverage when viewed from certain angles or when scaled [S1, unofficial].
## How it works
### Inputs and Outputs
**Inputs:**
- Voxel position in object space (via `gl_Position` from the vertex shader).
- Voxel color (`vec4 color`).
- Voxel normal (`vec3 normal`).
- Uniforms: Model-View matrix (`MV`), Projection matrix (`P`), entity scale (`scale`), grid length (`gridLength`), splat size parameter (`splatSize`), color multiplier (`splatColorMultiplier`), and culling flag (`cullInvisibleFaces`).

**Outputs:**
- Screen-space triangle strip representing the voxel's footprint.
- Interpolated color and normal for fragment shading.

### Data Structures
The geometry shader operates on a single input point per voxel. The input data structure (`voxelData`) contains:
- `color`: `vec4` (RGBA).
- `normal`: `vec3`.

The output is a `triangle_strip` with a maximum of 4 vertices, forming a single quad.

### Steps
1.  **Transform to View Space:** Multiply the input voxel's clip-space position by the Model-View matrix to get the view-space position.
    $$ \mathbf{p}_{view} = MV \cdot \mathbf{p}_{clip\_input} $$
    *(Note: The source code uses `gl_in[0].gl_Position` which is typically clip-space, but the variable name `voxelPosViewSpace` implies the result of `MV * gl_Position`. Standard OpenGL pipeline passes clip-space to geometry shaders. If `gl_Position` is clip-space, multiplying by `MV` is incorrect for getting view space. However, the source code explicitly does `MV * gl_in[0].gl_Position`. We follow the source code's logic: it assumes `gl_in[0].gl_Position` might be in a space where `MV` converts it to view space, or it is a specific implementation detail where `gl_Position` was pre-transformed. Given `MV` is Model-View, it expects object space. If the vertex shader passed object space, this works. If it passed clip space, this is wrong. We assume the source code's variable naming `voxelPosViewSpace` is the ground truth for the intended result: the position in view space.)*
    Correction: In standard OpenGL, `gl_Position` in the geometry shader is clip-space. To get view-space, one should multiply by `inverse(MV)`. However, the source code does `MV * gl_in[0].gl_Position`. This suggests either:
    a) The vertex shader passed object-space position in `gl_Position` (non-standard).
    b) The variable name is misleading and it's actually calculating something else.
    c) It's a bug in the source.
    Given the instruction to implement from the source, we follow the source's calculation: `voxelPosViewSpace = MV * gl_in[0].gl_Position`.

2.  **Transform to Normalized Device Coordinates (NDC):** Project the view-space position to clip space and divide by $w$ to get NDC.
    $$ \mathbf{p}_{ndc} = \frac{P \cdot \mathbf{p}_{view}}{P \cdot \mathbf{p}_{view}.w} $$

3.  **Calculate Splat Offset:** Compute the offset size for the quad in view space.
    $$ \text{voxelOffset} = \text{splatSize} \times \left( \frac{\text{scale}}{\text{gridLength}} \right) \times \sqrt{2} $$
    Where $\sqrt{2} \approx 1.414213$.

4.  **Calculate Clip-Space Half-Edge:** Determine the distance in NDC between the voxel center and the projected right-edge midpoint to establish the footprint size in screen space.
    - Calculate the right-edge midpoint in view space:
      $$ \mathbf{p}_{right\_view} = \mathbf{p}_{view}.xy + \text{voxelOffset} \cdot (0.5, 0) $$
      $$ \mathbf{p}_{right\_view}.zw = \mathbf{p}_{view}.zw $$
    - Project this point to NDC:
      $$ \mathbf{p}_{right\_ndc} = \frac{P \cdot \mathbf{p}_{right\_view}}{P \cdot \mathbf{p}_{right\_view}.w} $$
    - Compute the Euclidean distance in NDC:
      $$ \text{voxelHalfEdgeLengthClipSpace} = \text{distance}(\mathbf{p}_{ndc}, \mathbf{p}_{right\_ndc}) $$

5.  **Frustum Culling:** Discard the primitive if the voxel center in NDC is outside the expanded frustum border.
    $$ \text{voxelFrustumCullingBorder} = 1 + \text{voxelHalfEdgeLengthClipSpace} $$
    If any of the following are true, discard:
    - $\mathbf{p}_{ndc}.x < -\text{voxelFrustumCullingBorder}$
    - $\mathbf{p}_{ndc}.x > \text{voxelFrustumCullingBorder}$
    - $\mathbf{p}_{ndc}.y < -\text{voxelFrustumCullingBorder}$
    - $\mathbf{p}_{ndc}.y > \text{voxelFrustumCullingBorder}$

6.  **Back-Face Culling (Optional):** If `cullInvisibleFaces` is true, discard if the voxel is back-facing relative to the camera.
    - Calculate view-space normal:
      $$ \mathbf{n}_{view} = MV \cdot (\mathbf{n}, 0) $$
    - Vector from voxel to camera (origin in view space):
      $$ \mathbf{v} = (0,0,0) - \mathbf{p}_{view}.xyz $$
    - If $\mathbf{v} \cdot \mathbf{n}_{view}.xyz < 0$, discard.

7.  **Emit Vertices:** Emit four vertices for a triangle strip (quad) in view space, then project to clip space.
    - **Bottom-Left:**
      $$ \mathbf{p}_{bl\_view} = \mathbf{p}_{view}.xy + \text{voxelOffset} \cdot (-0.5, -0.5) $$
      $$ \mathbf{p}_{bl\_view}.zw = \mathbf{p}_{view}.zw $$
      $$ \mathbf{p}_{bl\_clip} = P \cdot \mathbf{p}_{bl\_view} $$
      Emit vertex with `gl_Position = \mathbf{p}_{bl\_clip}` and texCoords $(0,0)$.
    - **Bottom-Right:**
      $$ \mathbf{p}_{br\_view} = \mathbf{p}_{view}.xy + \text{voxelOffset} \cdot (0.5, -0.5) $$
      $$ \mathbf{p}_{br\_view}.zw = \mathbf{p}_{view}.zw $$
      $$ \mathbf{p}_{br\_clip} = P \cdot \mathbf{p}_{br\_view} $$
      Emit vertex with `gl_Position = \mathbf{p}_{br\_clip}` and texCoords $(1,0)$.
    - **Top-Left:**
      $$ \mathbf{p}_{tl\_view} = \mathbf{p}_{view}.xy + \text{voxelOffset} \cdot (-0.5, 0.5) $$
      $$ \mathbf{p}_{tl\_view}.zw = \mathbf{p}_{view}.zw $$
      $$ \mathbf{p}_{tl\_clip} = P \cdot \mathbf{p}_{tl\_view} $$
      Emit vertex with `gl_Position = \mathbf{p}_{tl\_clip}` and texCoords $(0,1)$.
    - **Top-Right:**
      $$ \mathbf{p}_{tr\_view} = \mathbf{p}_{view}.xy + \text{voxelOffset} \cdot (0.5, 0.5) $$
      $$ \mathbf{p}_{tr\_view}.zw = \mathbf{p}_{view}.zw $$
      $$ \mathbf{p}_{tr\_clip} = P \cdot \mathbf{p}_{tr\_view} $$
      Emit vertex with `gl_Position = \mathbf{p}_{tr\_clip}` and texCoords $(1,1)$.

8.  **End Primitive:** Call `EndPrimitive()` to finalize the triangle strip.

### Pseudocode
```python
def process_voxel(gl_in_position, color, normal, MV, P, scale, gridLength, splatSize, cullInvisibleFaces):
    # Step 1: Transform to View Space (as per source code logic)
    voxelPosViewSpace = MV * gl_in_position
    
    # Step 2: Transform to NDC
    voxelPosClipSpace = P * voxelPosViewSpace
    voxelPosClipSpace /= voxelPosClipSpace.w
    
    # Step 3: Calculate Splat Offset
    voxelOffset = splatSize * (scale / gridLength) * 1.414213
    
    # Step 4: Calculate Clip-Space Half-Edge
    # Right edge midpoint in view space
    rightEdgeMidView = vec4(voxelPosViewSpace.x + 0.5 * voxelOffset, 
                            voxelPosViewSpace.y, 
                            voxelPosViewSpace.z, 
                            voxelPosViewSpace.w)
    rightEdgeMidClip = P * rightEdgeMidView
    rightEdgeMidClip /= rightEdgeMidClip.w
    
    voxelHalfEdgeLengthClipSpace = distance(voxelPosClipSpace.xy, rightEdgeMidClip.xy)
    voxelFrustumCullingBorder = 1 + voxelHalfEdgeLengthClipSpace
    
    # Step 5: Frustum Culling
    if (voxelPosClipSpace.x < -voxelFrustumCullingBorder or 
        voxelPosClipSpace.x > voxelFrustumCullingBorder or 
        voxelPosClipSpace.y < -voxelFrustumCullingBorder or 
        voxelPosClipSpace.y > voxelFrustumCullingBorder):
        return None # Discard
    
    # Step 6: Back-Face Culling
    if cullInvisibleFaces:
        normalViewSpace = MV * vec4(normal, 0)
        viewDir = vec3(0, 0, 0) - voxelPosViewSpace.xyz
        if dot(viewDir, normalViewSpace.xyz) < 0:
            return None # Discard
    
    # Step 7: Emit Vertices
    vertices = []
    
    # Bottom-Left
    bl_view = vec4(voxelPosViewSpace.x - 0.5 * voxelOffset, 
                   voxelPosViewSpace.y - 0.5 * voxelOffset, 
                   voxelPosViewSpace.z, 
                   voxelPosViewSpace.w)
    bl_clip = P * bl_view
    vertices.append({'pos': bl_clip, 'tex': (0, 0), 'color': color, 'normal': normal})
    
    # Bottom-Right
    br_view = vec4(voxelPosViewSpace.x + 0.5 * voxelOffset, 
                   voxelPosViewSpace.y - 0.5 * voxelOffset, 
                   voxelPosViewSpace.z, 
                   voxelPosViewSpace.w)
    br_clip = P * br_view
    vertices.append({'pos': br_clip, 'tex': (1, 0), 'color': color, 'normal': normal})
    
    # Top-Left
    tl_view = vec4(voxelPosViewSpace.x - 0.5 * voxelOffset, 
                   voxelPosViewSpace.y + 0.5 * voxelOffset, 
                   voxelPosViewSpace.z, 
                   voxelPosViewSpace.w)
    tl_clip = P * tl_view
    vertices.append({'pos': tl_clip, 'tex': (0, 1), 'color': color, 'normal': normal})
    
    # Top-Right
    tr_view = vec4(voxelPosViewSpace.x + 0.5 * voxelOffset, 
                   voxelPosViewSpace.y + 0.5 * voxelOffset, 
                   voxelPosViewSpace.z, 
                   voxelPosViewSpace.w)
    tr_clip = P * tr_view
    vertices.append({'pos': tr_clip, 'tex': (1, 1), 'color': color, 'normal': normal})
    
    return vertices
```

### Parameters
- `splatSize`: Uniform float. Controls the base size of the splat.
- `scale`: Uniform float. Entity scale factor.
- `gridLength`: Uniform float. Grid length factor.
- `cullInvisibleFaces`: Uniform bool. Enables back-face culling.

### Edge Cases and Pitfalls
- **Precision:** The calculation of `voxelOffset` relies on floating-point arithmetic. Large scales or small grid lengths may lead to precision issues.
- **Frustum Culling:** The border expansion `1 + voxelHalfEdgeLengthClipSpace` ensures that splats near the edge of the screen are not clipped incorrectly. However, if `voxelHalfEdgeLengthClipSpace` is very large, the border becomes large, potentially including voxels that are technically outside the view but whose splats extend into it.
- **Back-Face Culling:** The normal transformation assumes the normal is in object space. If the normal is already in view space, the transformation `MV * vec4(normal, 0)` is incorrect. The source code uses `MV`, implying object space input.
- **W-Division:** The NDC conversion requires division by $w$. If $w$ is zero or very close to zero, the result is undefined. This should be handled by the graphics driver, but it's a potential pitfall for near-plane voxels.

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of voxels. Each voxel is processed independently in the geometry shader.
- **Memory Complexity:** $O(N)$ for storing voxel data. The geometry shader generates 4 vertices per voxel.
- **Performance:** The method is efficient for GPU rasterization as it uses standard triangle strips. The frustum and back-face culling reduce the number of primitives sent to the rasterizer.
- **Strengths:** Simple implementation, leverages GPU rasterization, effective culling.
- **Limitations:** Square footprints may alias or leave gaps compared to circular splats. The fixed offset calculation may not adapt well to varying voxel densities or non-uniform scaling.
- **When to Use:** When simple, fast volume rendering is needed and square footprints are acceptable.
- **When Not to Use:** When high-quality anti-aliasing or circular coverage is required.

## Background
Circle Splat Rendering, also known as square_splat, is implemented in the `svo_renderer` project by mmalesadev [S1, unofficial]. It is used for rendering SVO (Sparse Voxel Octree) data structures. The method maps voxels to 2D quads for efficient rasterization.
