# Tetrahedral Splatting

Also called: TetSplat

## Overview
Tetrahedral Splatting (TetSplat) is a point-based, object-order rendering technique designed for the real-time visualization of large, static tetrahedral meshes [S1, unofficial]. It maps each tetrahedron to a single spherical or ellipsoidal splat to approximate the volume integral, utilizing hierarchical data structures for efficient culling [S1, unofficial]. Unlike voxel-based methods that rely on regular grids, TetSplat operates directly on unstructured meshes but requires a preprocessing step that partitions the volume, making it unsuitable for dynamic scenes in its current implementation [S1, unofficial]. It is distinguished from sibling methods like [Voxel Splat Rendering](3730-voxel-splat-rendering.md) by its direct handling of unstructured geometry, though it suffers from visible gaps due to the one-splat-per-tetrahedron representation [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A static, unstructured tetrahedral mesh $T$.
*   **Output:** A 2D image buffer with accumulated color and opacity.

**Data Structures:**
1.  **Partitioned Mesh:** The mesh is divided into two sets:
    *   **Shell:** The non-convex boundary tetrahedra.
    *   **Solid:** The internal tetrahedra fragments [S1, unofficial].
2.  **Hierarchical Culling Structure:** A spatial hierarchy (e.g., BVH or grid) built over the splats to enable back-face and occlusion culling [S1, unofficial].
3.  **Splat Representation:** Each tetrahedron $t_i$ is represented by a single primitive $P_i$.
    *   For spherical splats: Center $c_i$ and radius $r_i$.
    *   For ellipsoidal splats: Center $c_i$, orientation matrix $R_i$, and scale vector $s_i$.
    *   *Note:* The exact mapping from tetrahedron geometry to splat parameters (e.g., centroid vs. circumcenter, radius calculation) is not specified in the sources [G].

**Steps:**
1.  **Preprocessing (Partitioning & Cleaning):**
    *   Identify and remove degenerated tetrahedra (needles, spindles, slivers, caps) using edge collapse [S1, unofficial].
    *   Partition the remaining mesh into Shell and Solid sets [S1, unofficial].
    *   *Note:* This step assumes a static mesh and is performed once [S1, unofficial].
2.  **Splat Generation:**
    *   For each tetrahedron $t_i$, generate a single splat $P_i$ (spherical or ellipsoidal) [S1, unofficial].
    *   Assign intrinsic density/color to the splat based on the tetrahedron's properties.
3.  **Rendering Loop (Per Frame):**
    *   Transform all splats to screen space using the Model-View-Projection (MVP) matrix.
    *   Use the hierarchical structure to cull occluded or back-facing splats [S1, unofficial].
    *   For each visible splat $P_i$:
        *   Compute the 2D footprint $F_i(x,y)$ on the image plane.
        *   Composite $F_i$ into the image buffer using alpha blending or additive accumulation, weighted by the splat's density [S1, unofficial].

**Pseudocode:**
```python
def render_tetsplat(mesh, camera):
    # Preprocessing (One-time)
    # Remove degenerated tets (needles, spindles, slivers, caps) via edge collapse
    cleaned_mesh = remove_degenerate_tets(mesh)
    
    # Partition into Shell and Solid
    shell, solid = partition_volume(cleaned_mesh)
    
    # Generate splats for all tets in cleaned_mesh
    splats = []
    for tet in cleaned_mesh.tetrahedra:
        # Map tet to single splat (spherical or ellipsoidal)
        # Implementation of mapping logic is not specified in sources [G]
        splat = create_splat(tet)
        splats.append(splat)
    
    # Build hierarchical culling structure
    hierarchy = build_hierarchy(splats)
    
    # Rendering
    image = empty_image_buffer()
    
    # Transform and cull
    visible_splats = []
    for splat in splats:
        if is_visible(splat, camera, hierarchy):
            visible_splats.append(splat)
    
    # Sort splats back-to-front for correct alpha blending
    visible_splats.sort(key=lambda s: s.depth_from_camera)
    
    # Composite
    for splat in visible_splats:
        footprint = compute_footprint(splat, camera.projection_matrix)
        color, alpha = splat.get_properties()
        image.composite(footprint, color, alpha)
        
    return image
```

**Parameters:**
*   **Splat Shape:** Spherical or Ellipsoidal. Ellipsoids may reduce gaps for small meshes but increase computational cost [S1, unofficial].
*   **Culling:** Back-face and occlusion culling enabled via hierarchy [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Degenerate Tetrahedra:** The method requires the removal of degenerate tets, which is incompatible with smoke volume rendering where topology must be maintained and tets may naturally approach degenerate states during integration [S1, unofficial].
*   **Visible Gaps:** Representing each tetrahedron with exactly one splat leads to visible gaps and unpleasant artifacts, even with ellipsoidal adaptation [S1, unofficial].
*   **Static Mesh Only:** The preprocessing step assumes a static mesh; dynamic objects are not supported [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Real-time performance is achieved through hierarchical culling, but preprocessing is $O(N)$ where $N$ is the number of tetrahedra [S1, unofficial].
*   **Memory Complexity:** Requires storage for the partitioned mesh, hierarchical structure, and splat data [S1, unofficial].
*   **Strengths:** Real-time capability for large meshes; handles unstructured geometry directly [S1, unofficial].
*   **Limitations:** Visible gaps due to one-splat-per-tetrahedron; incompatible with dynamic meshes; preprocessing removes topological details (degenerate tets) [S1, unofficial].
*   **When to Use:** Static, large-scale tetrahedral meshes where real-time performance is critical and some visual artifacting is acceptable [S1, unofficial].
*   **When Not to Use:** Dynamic scenes, smoke volume rendering requiring topological fidelity, or applications sensitive to visible gaps [S1, unofficial].

## Background
Tetrahedral Splatting was introduced as a point-based technique for real-time rendering of large tetrahedral meshes [S1, unofficial]. It addresses the limitations of voxel-based methods by operating on unstructured data, though it introduces its own artifacts related to splat representation [S1, unofficial]. The method is discussed in the context of smoke volume rendering, where its limitations regarding degenerate tetrahedra are particularly relevant [S1, unofficial].
