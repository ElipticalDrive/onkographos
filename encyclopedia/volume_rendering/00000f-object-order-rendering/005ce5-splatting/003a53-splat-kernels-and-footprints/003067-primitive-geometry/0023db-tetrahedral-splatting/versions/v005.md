# Tetrahedral Splatting

Also called: TetSplat

## Overview
Tetrahedral Splatting (TetSplat) is a point-based technique for the real-time rendering of large, unstructured tetrahedral meshes [S1, unofficial]. It solves the performance bottleneck of ray-casting large volumes by approximating each tetrahedron with a spherical or ellipsoidal splat, leveraging hierarchical data structures for efficient culling [S1, unofficial]. Unlike [Voxel Splat Rendering](3730-voxel-splat-rendering.md) which relies on regular grids, TetSplat handles irregular topologies but suffers from visible gaps between individual splats and requires static meshes due to its preprocessing requirements [S1, unofficial].

## How it works
**Inputs:** A static, unstructured tetrahedral mesh.
**Outputs:** A rasterized image with volumetric density and color accumulation.

**Data Structures:**
1.  **Partitioned Mesh:** The input mesh is divided into two sets:
    *   **Shell:** The non-convex boundary tetrahedra.
    *   **Solid:** The internal fragment tetrahedra [S1, unofficial].
2.  **Splat Representation:** Each tetrahedron is mapped to a single primitive:
    *   **Shell Tetrahedra:** Rendered as standard opaque surface triangles with vertex normals.
    *   **Solid Tetrahedra:** Rendered as spherical or ellipsoidal splats. The shape (sphere vs. ellipsoid) is adapted based on mesh size to minimize gaps, though individual splats remain visible [S1, unofficial].
3.  **Hierarchical Culling Structure:** A spatial hierarchy (e.g., BVH or octree) is built to enable efficient back-face and occlusion culling [S1, unofficial].

**Preprocessing Steps:**
1.  **Degeneracy Removal:** Identify and eliminate degenerated tetrahedra (needles, spindles, slivers, and caps) using edge collapse [S1, unofficial]. This is necessary because degenerate shapes are difficult to represent as valid splats.
2.  **Partitioning:** Separate the remaining mesh into Shell and Solid sets [S1, unofficial].
3.  **Hierarchy Construction:** Build the hierarchical data structure for the Solid set [S1, unofficial].

**Rendering Steps:**
1.  **Culling:** Use the hierarchical structure to cull occluded or back-facing splats [S1, unofficial].
2.  **Projection:** Transform the center and extents of each valid splat from object space to screen space using the Model-View-Projection (MVP) matrix.
3.  **Rasterization:** For each remaining splat, compute its footprint $F(x,y)$ on the screen.
4.  **Accumulation:** Write the contribution to the pixel buffer. For Shell tetrahedra, use standard opaque rasterization. For Solid tetrahedra, apply the splat weight $w(x,y)$ modulated by density $\rho_k$:
    $$ P(x,y) = w(x,y) \cdot \rho_k $$
    Accumulate using alpha blending [S1, unofficial].

**Pitfalls:**
*   **Topology Loss:** The preprocessing step eliminates degenerate tetrahedra. This is incompatible with smoke volume rendering where topology must be maintained, as many tetrahedra approach a degenerate state during integration [S1, unofficial].
*   **Visual Artifacts:** Representing a tetrahedron with exactly one splat leads to visible gaps between primitives, even when adapting the shape to the mesh scale [S1, unofficial].
*   **Static Constraint:** The method assumes a static mesh; dynamic objects are not supported in the current implementation [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Real-time performance is achieved through hierarchical culling, reducing the number of splats processed per frame [S1, unofficial].
*   **Memory Complexity:** Requires storage for the partitioned mesh and the hierarchical culling structure [S1, unofficial].
*   **Strengths:** Handles large, unstructured tetrahedral meshes efficiently; supports real-time frame rates via culling [S1, unofficial].
*   **Limitations:** Requires static meshes; preprocessing removes topological details (degenerate tetrahedra); visible gaps between splats reduce visual quality; not suitable for dynamic simulations like smoke where topology changes [S1, unofficial].
*   **When to use:** Real-time visualization of static, large-scale unstructured tetrahedral volumes where performance is critical and minor visual artifacts are acceptable.
*   **When not to use:** Dynamic volumes (e.g., smoke), scenarios requiring strict topological fidelity, or high-quality rendering where splat gaps are unacceptable.

## Background
Tetrahedral Splatting was introduced as a point-based technique for real-time rendering of large tetrahedral meshes [S1, unofficial]. It addresses the limitations of ray-casting methods for large volumes by approximating geometry with splats and using hierarchical culling [S1, unofficial]. The method is described in the context of smoke volume rendering, where it is contrasted with volume texture and ray-casting approaches [S1, unofficial].
