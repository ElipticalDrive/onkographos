# Decomposition
Also called: Primitive-based decomposition, Geometric decomposition

## Overview
Decomposition is a volume rendering technique that converts a volumetric dataset into a collection of geometric primitives, such as spheres or slices, which are then placed, scaled, and colored based on a transfer function mapping [S1][S2, unofficial]. It differs from ray-casting and splatting methods by explicitly constructing discrete geometric proxies for the data, making it particularly suitable for applications requiring further geometric processing like segmentation or interactive manipulation [S1][S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A volumetric dataset (scalar field) and a transfer function mapping scalar values to geometric properties (position, scale, color).
*   **Output:** A set of geometric primitives (spheres or slices) ready for rasterization or ray-tracing.

**Data Structures:**
The method generates a list of primitives. Each primitive $P_i$ contains:
*   **Type:** Enum indicating 'sphere' or 'slice'.
*   **Position:** 3D vector $(x, y, z)$ derived from the data coordinates.
*   **Scale/Size:** Scalar value or vector determining the primitive's dimensions, mapped from the data value.
*   **Color/Opacity:** RGBA tuple or scalar opacity, mapped from the data value.

**Steps:**
1.  **Sampling/Extraction:** Iterate through the volumetric dataset. For each voxel or data point, determine if it meets criteria for primitive generation (e.g., thresholding or sampling at regular intervals) [S1][S2, unofficial].
2.  **Primitive Creation:** Convert the data point into a geometric primitive.
    *   If **spheres** are chosen: Create a sphere centered at the voxel location. The radius may be constant or scaled based on the data value [S1][S2, unofficial].
    *   If **slices** are chosen: Create a planar surface (e.g., a quad or texture plane) at the voxel location, oriented according to the data gradient or a fixed axis [S1][S2, unofficial].
3.  **Mapping:** Apply the transfer function to determine the visual properties (color, opacity, scale) of each primitive based on the underlying data value [S1][S2, unofficial].
4.  **Rendering:** Render the resulting primitives using standard graphics pipeline techniques. Slices are commonly rendered as pseudo-colored textures or height maps [S2, unofficial].

**Parameters:**
*   **Primitive Type:** Choice between spheres and slices. Slices are often preferred for planar structures or when texture mapping is desired [S2, unofficial].
*   **Sampling Rate:** Determines the density of primitives. Not given in the sources.
*   **Transfer Function:** Defines the mapping from data values to primitive properties. Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Occlusion:** Overlapping primitives can cause visual artifacts if not handled with proper depth buffering or alpha blending.
*   **Performance:** The number of primitives can grow large, impacting rendering performance. Not given in the sources.
*   **Data Representation:** The choice of primitive (sphere vs. slice) affects the fidelity of the representation. Spheres may introduce aliasing at boundaries, while slices may require careful orientation. Not given in the sources.

## Operating characteristics
*   **Time Complexity:** Depends on the number of primitives generated and the rendering cost per primitive. Not given in the sources.
*   **Memory Complexity:** Proportional to the number of primitives. Not given in the sources.
*   **Strengths:** Allows for easy integration with geometric processing pipelines (e.g., segmentation, deformation). Slices can be efficiently rendered using texture mapping [S2, unofficial].
*   **Limitations:** May not capture fine volumetric details as accurately as ray-casting. Performance can degrade with high data resolution. Not given in the sources.
*   **When to use:** When the volume needs to be manipulated geometrically or when specific geometric features (like surfaces) need to be extracted and processed [S1][S2, unofficial].

## Background
Decomposition is one of the five main volume rendering techniques operating in image order, alongside MIP, X-Ray, Iso-surface, and Transparent depth methods [S1][S2, unofficial]. It was categorized in early surveys of interactive volume rendering techniques [S1][S2, unofficial].
