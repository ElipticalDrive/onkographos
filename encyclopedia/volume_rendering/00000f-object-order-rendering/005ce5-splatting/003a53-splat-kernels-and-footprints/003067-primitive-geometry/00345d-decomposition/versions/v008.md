# Decomposition
Also called: Primitive Decomposition, Geometric Decomposition

## Overview
Decomposition is an image-order volume rendering technique that converts a volumetric dataset into a collection of geometric primitives, such as spheres or slices, which are then placed, scaled, and colored based on a data mapping [S1][S2, unofficial]. It differs from ray-casting methods by rasterizing explicit geometry rather than integrating along rays, and from iso-surface methods by representing the entire volume density field rather than a single thresholded level set [S1][S2, unofficial].

## How it works
**Inputs:** A volumetric dataset (scalar field $V$) and a transfer function mapping scalar values to color and opacity.
**Outputs:** A 2D image buffer.

**Data Structures:**
The dataset is decomposed into a list of primitives $\mathcal{P} = \{p_1, p_2, \dots, p_n\}$.
Each primitive $p_i$ contains:
-   **Geometry:** Position $\mathbf{c}_i$ (center), radius $r_i$ (for spheres) or dimensions (for slices).
-   **Attributes:** Color $\mathbf{color}_i$, opacity $\alpha_i$, and scalar value $s_i$ derived from $V$.

**Steps:**
1.  **Decomposition:** Iterate through the volumetric dataset. For each voxel or region, generate a corresponding geometric primitive.
    -   *Spheres:* Each voxel or cluster of voxels becomes a sphere. The radius $r_i$ and position $\mathbf{c}_i$ are determined by the voxel location and potentially the local density or gradient.
    -   *Slices:* The volume is sliced along a specific axis (e.g., axial, coronal, sagittal). Each slice becomes a 2D texture or height map [S2, unofficial].
2.  **Mapping:** Apply the transfer function to determine the visual attributes ($\mathbf{color}_i, \alpha_i$) for each primitive based on its underlying scalar value $s_i$ [S1][S2, unofficial].
3.  **Placement:** Transform the primitives from object space to screen space using the Model-View-Projection (MVP) matrix [Parent].
4.  **Rasterization:** Render the primitives to the image buffer.
    -   Slices are rendered as pseudo-colored textures or height maps [S2, unofficial].
    -   Spheres are rasterized as circles with appropriate shading or opacity blending.
5.  **Compositing:** Accumulate the contributions of all primitives. For transparent primitives, standard front-to-back alpha compositing is used:
    $$ C_{out} = C_{in} + \mathbf{color}_i \cdot \alpha_i \cdot (1 - C_{in}.opacity) $$
    $$ \alpha_{out} = \alpha_{in} + \alpha_i \cdot (1 - \alpha_{in}) $$

**Parameters:**
-   **Primitive Type:** Sphere vs. Slice. Slices are commonly used for further processing like segmentation [S1][S2, unofficial].
-   **Mapping Function:** The specific transfer function defining color/opacity vs. scalar value.

**Edge Cases:**
-   **Occlusion:** Overlapping primitives must be sorted or handled via depth buffering to ensure correct compositing order.
-   **Artifacting:** Spherical primitives may introduce "stair-step" artifacts if the voxel-to-sphere mapping is not carefully tuned.

## Operating characteristics
-   **Time Complexity:** Depends on the number of primitives $N$ and the cost of rasterizing each primitive. Generally faster than ray-casting for large datasets if the number of primitives is reduced via clustering or simplification.
-   **Memory Complexity:** Requires storing the list of primitives, which can be larger than the original voxel grid if each voxel becomes a primitive.
-   **Strengths:** Enables interactive manipulation (bend, move, re-pose) when combined with skeleton-based methods; allows for standard graphics pipeline optimization [S1].
-   **Limitations:** May lose fine detail if decomposition is too aggressive; spherical primitives may not accurately represent complex shapes.

## Background
Decomposition methods were identified as one of the five main image-order volume rendering techniques in early surveys [S1][S2, unofficial]. They are particularly useful when the volume needs to be treated as a collection of distinct geometric objects for further processing or manipulation [S1][S2, unofficial].
