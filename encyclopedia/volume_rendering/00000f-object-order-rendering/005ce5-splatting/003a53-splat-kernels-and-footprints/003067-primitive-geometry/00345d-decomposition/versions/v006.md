# Decomposition
## Overview
Decomposition is an image-order volume rendering technique that converts a volumetric data set into geometric primitives, such as spheres or slices, which are placed in space, scaled, and colored based on a transfer function mapping [S1][S2, unofficial]. It differs from direct voxel-based methods by explicitly constructing intermediate geometric representations, allowing for specialized rendering of slices as pseudo-colored textures or height maps, and facilitating further processing like segmentation [S1][S2, unofficial].
## How it works
**Inputs and Outputs:**
- Input: A volumetric data set $V$ (scalar or vector field) and a transfer function $T$ mapping data values to color and opacity.
- Output: A 2D image composed of projected geometric primitives.

**Data Structures:**
The method generates a list of geometric primitives $P_k$. Each primitive $P_k$ is defined by:
1.  **Geometry:** Type (e.g., sphere center/radius, slice plane equation/extent).
2.  **Attributes:** Color $C_k$ and Opacity $\alpha_k$ derived from $T(V)$.
3.  **Transformation:** Position and scale in world/view space.

**Steps:**
1.  **Decomposition:** Iterate through the data set $V$. For each data element (voxel or region), generate a corresponding geometric primitive $P_k$. Common primitives include spheres (for point-based data) or planar slices (for volume sections) [S1][S2, unofficial].
2.  **Mapping:** Apply the transfer function $T$ to the data values associated with each primitive to determine its color $C_k$ and opacity $\alpha_k$ [S1][S2, unofficial].
3.  **Placement:** Position the primitives in space according to their original data coordinates. Scale the primitives based on the data values or resolution [S1][S2, unofficial].
4.  **Rendering:**
    -   For **spheres**: Project onto the image plane and accumulate using alpha blending [S1][S2, unofficial].
    -   For **slices**: Render as pseudo-colored textures or height maps. This involves rasterizing the slice geometry and applying the mapped colors [S1][S2, unofficial].
5.  **Accumulation:** Composite the rendered primitives into the final image buffer.

**Formulas:**
-   Primitive Color: $C_k = T_c(v_k)$
-   Primitive Opacity: $\alpha_k = T_a(v_k)$
    Where $v_k$ is the data value associated with primitive $P_k$, and $T_c, T_a$ are the color and opacity components of the transfer function.

**Parameters:**
-   Primitive Type: Sphere or Slice. Not given in the sources.
-   Transfer Function: User-defined. Not given in the sources.

**Edge Cases and Pitfalls:**
-   **Occlusion:** Spheres may require depth sorting to ensure correct alpha blending. Not given in the sources.
-   **Slice Orientation:** Slices must be correctly oriented relative to the view vector to avoid degenerate projections. Not given in the sources.
## Subtopics

### [Curve-Skeleton Decomposition](8486-curve-skeleton-decomposition.md)
Represents a volumetric object as a 1D line-like structure (skeleton) to enable interactive manipulation. It decomposes the volume into bounding cuboids along the skeleton for independent transformation and rendering, separating geometric abstraction from rendering.

## Operating characteristics
**Time and Memory Complexity:**
-   Time: Depends on the number of primitives generated and the complexity of the transfer function. Rendering spheres involves projection and blending; rendering slices involves texture mapping. Not given in the sources.
-   Memory: Requires storage for the list of primitives and their attributes. Not given in the sources.

**Measured Performance:**
-   Not given in the sources.

**Scaling:**
-   Not given in the sources.

**Strengths and Limitations:**
-   **Strengths:** Allows for specialized rendering of slices (e.g., as height maps); facilitates further processing like segmentation; flexible primitive selection [S1][S2, unofficial].
-   **Limitations:** Explicit construction of primitives can be memory-intensive for large data sets; requires careful handling of primitive ordering for correct blending [S1][S2, unofficial].

**When to Use:**
-   When specialized rendering of slices (textures, height maps) is required.
-   When further processing (segmentation) of the decomposed geometry is needed [S1][S2, unofficial].

**When Not to Use:**
-   When real-time performance on very large data sets is critical and memory is constrained.
-   When direct voxel-based rendering is sufficient and simpler.
## Background
**Origin:**
-   Decomposition is one of five volume rendering techniques operating in image order, alongside MIP, X-Ray, Iso-surface, and Transparent Depth [S1][S2, unofficial]. It was categorized in early surveys of interactive volume rendering techniques [S1][S2, unofficial].

**History and Development:**
-   The technique is described in foundational surveys of interactive volume rendering [S1][S2, unofficial].

**Where it is Used:**
-   Applications requiring slice-based visualization, pseudo-colored textures, or height map representations of volumetric data [S1][S2, unofficial].
