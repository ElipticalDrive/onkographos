# Decomposition
## Overview
Decomposition is a volume rendering technique that converts a volumetric data set into a collection of geometric primitives, such as spheres or slices, which are then placed, scaled, and colored based on a data-to-primitive mapping [S1][S2, unofficial]. It differs from direct volume rendering (e.g., ray casting) by explicitly discretizing the volume into discrete geometric objects, and from iso-surface rendering by preserving the continuous nature of the data through scaling rather than thresholding [S1][S2, unofficial].
## How it works
**Inputs:** A volumetric data set $V$ (scalar or vector field) and a mapping function $M$ that assigns geometric parameters (position, scale, color) to data values.
**Outputs:** A set of geometric primitives ready for rasterization or ray tracing.

**Data Structures:**
The output is a list of primitives $\mathcal{P} = \{P_1, P_2, \dots, P_N\}$. Each primitive $P_i$ is defined by parameters $\Theta_i$:
-   **Type:** Sphere or Slice.
-   **Position:** $(x_i, y_i, z_i)$ in object space.
-   **Scale:** $s_i$ (radius for spheres, thickness/extent for slices).
-   **Color/Opacity:** $c_i$ derived from $V$ at the sampling location.

**Steps:**
1.  **Sampling:** Iterate through the volumetric data set $V$. For each voxel or data point, determine its contribution to a primitive.
2.  **Primitive Generation:**
    -   *Spheres:* For each data point, generate a sphere centered at the voxel location. The radius $r$ is scaled by the data value $v$ (e.g., $r = k \cdot v$) [S1][S2, unofficial].
    -   *Slices:* For each data point or slab, generate a planar slice. The slice is positioned at the voxel's depth and scaled according to the data value [S1][S2, unofficial].
3.  **Mapping:** Apply the mapping function $M$ to determine the color and opacity of each primitive based on the underlying data value [S1][S2, unofficial].
4.  **Rendering:**
    -   *Spheres:* Rendered as point sprites or implicit surfaces.
    -   *Slices:* Rendered as pseudo-colored textures or height maps [S1][S2, unofficial].
5.  **Compositing:** Combine the primitives using standard alpha blending or ray tracing to produce the final image.

**Parameters:**
-   Scaling factor $k$ for sphere radius: Not given in the sources.
-   Slice thickness: Not given in the sources.

**Edge Cases:**
-   Overlapping primitives may require careful depth sorting or alpha blending to avoid artifacts.
-   High data values may result in excessively large primitives, causing occlusion or performance issues.

## Operating characteristics
**Time Complexity:** $O(N)$ where $N$ is the number of data points/primitives. Rendering complexity depends on the number of primitives and the rendering method (rasterization vs. ray tracing).
**Memory Complexity:** $O(N)$ to store the list of primitives.
**Strengths:** Allows for interactive manipulation of volumetric data by treating it as geometric objects; suitable for segmentation and further processing of slices [S1][S2, unofficial].
**Limitations:** May lose fine detail if the sampling is sparse; performance can degrade with a large number of primitives.
**When to use:** When interactive manipulation or segmentation of volumetric data is required [S1][S2, unofficial].
**When not to use:** When high-fidelity, continuous volume visualization is needed without discretization artifacts.
## Background
Decomposition methods are one of the five main categories of image-order volume rendering techniques, alongside MIP, X-Ray, Iso-surface, and Transparent/Depth methods [S1][S2, unofficial]. The technique was described in early interactive volume rendering surveys [S1][S2, unofficial].
