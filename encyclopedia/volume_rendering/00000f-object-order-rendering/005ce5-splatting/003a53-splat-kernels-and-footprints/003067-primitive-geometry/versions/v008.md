# Primitive Geometry

Also called: Splat Primitives, Geometric Splatting Primitives

## Overview
Primitive Geometry defines the specific 2D or 3D shapes used as volumetric primitives in splat-based volume rendering. It solves the problem of how to approximate continuous volumetric data (voxels, lines, tetrahedra) as discrete geometric entities that can be efficiently rasterized or ray-cast in screen space. It is distinguished from kernel selection methods by focusing on the *shape* and *topology* of the primitive (e.g., sphere vs. capsule vs. tetrahedron) rather than the mathematical function describing its density falloff.

## Shared principles
All primitive geometry methods in this family share the following mechanism:
1.  **Primitive Mapping:** Each data element (voxel, segment, tetrahedron) is mapped to a single geometric primitive $P_k$ defined in object or view space.
2.  **Transformation:** The primitive is transformed to screen space using the Model-View-Projection (MVP) matrix.
3.  **Footprint Generation:** The primitive generates a 2D footprint $F(x,y)$ on the image plane. This footprint represents the spatial extent and density contribution of the primitive.
4.  **Accumulation:** The footprint is composited into the image buffer, typically via alpha blending or additive accumulation, weighted by the primitive's intrinsic density or color.

## Subtopics

### [Circle Splat Rendering](2981-circle-splat-rendering.md)
Circle Splat Rendering projects voxels as 2D quads in screen space to approximate circular footprints. It is distinguished by its explicit generation of screen-space quads with specific culling logic based on clip-space half-edge lengths. Choose this method when efficient rasterization of regular voxel grids is required with strict frustum culling.

### [Line Capsule Primitive](3131-line-capsule-primitive.md)
The Line Capsule Primitive renders line-based volumetric data as rotationally symmetric capsules in screen space. It distinguishes itself by explicitly modeling line segments as capsules with deficit-rule joints to maintain visual continuity without gaps or double brightness. Choose this for rendering line fields or skeleton data where rotational symmetry is critical.

### [Tetrahedral Splatting](3181-tetrahedral-splatting.md)
Tetrahedral Splatting (TetSplat) approximates unstructured tetrahedral meshes with spherical or ellipsoidal splats. It sets itself apart by handling irregular topologies but suffers from visible gaps between individual splats. Choose this for real-time rendering of large, static, unstructured tetrahedral meshes where ray-casting is too slow.

### [Voxel Splat Rendering](3730-voxel-splat-rendering.md)
Voxel Splat Rendering projects each voxel as a 2D footprint (splat) that contributes to the final image via alpha blending. It sets itself apart by typically utilizing square or axis-aligned bounding box projections for efficient rasterization. Choose this for standard regular grid volume rendering to mitigate aliasing and holes.

### [Decomposition](7254-decomposition.md)
Decomposition converts a volumetric dataset into a collection of geometric primitives, such as spheres or slices. It differs from ray-casting and splatting by explicitly constructing discrete geometric proxies. Choose this when further geometric processing, such as segmentation or interactive manipulation, is required.

### [Triangle Mesh Splatting](8109-triangle-mesh-splatting.md)
Triangle Mesh Splatting approximates volumetric splats with triangle meshes to leverage graphics hardware for rapid scan conversion. It distinguishes itself by replacing analytical footprint computation with rasterization-based approximation. Choose this for significant rendering speed improvements via standard GPU pipelines.

### [Resonant Brane Splatting](9845-resonant-brane-splatting.md)
Resonant Brane Splatting (RBS) replaces flat, single-color 2D Gaussians with 'Branes' that emit spatially varying colors using Gaussian-Hermite modes. It differs from standard splatting where color is constant over the footprint. Choose this for arbitrary-scale super-resolution where local contrast and sharp edges must be modeled by a single primitive.

## Background
The concept of splatting was introduced by Levoy  as an object-order rendering technique. The specific geometric primitives (voxels, capsules, tetrahedra) have evolved to address different data structures (regular grids, unstructured meshes, line fields) and hardware constraints (analytical integration vs. rasterization).
