# Primitive Geometry

Also called: Splat Primitives, Geometric Splats

## Overview
Primitive Geometry defines the specific 2D or 3D shapes used to represent volumetric data elements as splats during object-order rendering. It solves the problem of how to map discrete data units (voxels, lines, tetrahedra) to continuous screen-space footprints that can be efficiently rasterized and composited. It differs from kernel definition methods by focusing on the topological and geometric structure of the primitive itself (e.g., quad vs. capsule vs. mesh) rather than the analytic function of its intensity falloff.

## Shared principles
All primitive geometry methods in this family share the following mechanism:
1.  **Data-to-Primitive Mapping:** Each data element (voxel, segment, tetrahedron) is mapped to a single geometric primitive $P$. The primitive is defined by parameters $\Theta$ (position, orientation, scale, shape coefficients).
2.  **Projection:** The primitive is transformed from object space to screen space using the Model-View-Projection (MVP) matrix.
3.  **Footprint Generation:** The 3D primitive projects to a 2D footprint $F(x,y)$ on the image plane. This footprint determines which pixels are affected and with what weight.
4.  **Rasterization/Compositing:** The footprint is rendered into the image buffer. This is typically done via GPU rasterization (for mesh/quad primitives) or explicit pixel evaluation (for analytic primitives like capsules or Branes).
5.  **Culling:** Primitives are culled if they fall outside the view frustum or are occluded/back-facing, often using bounding volumes derived from the primitive's geometry.

## Subtopics

### [Circle Splat Rendering](2981-circle-splat-rendering.md)
Projects 3D voxels into 2D screen-space quads. It differs from other methods by explicitly computing a fixed offset based on grid scale and splat size to determine quad dimensions, using axis-aligned quads rather than perspective-correct shapes. Choose when GPU rasterization of simple quads is preferred for performance.

### [Line Capsule Primitive](3131-line-capsule-primitive.md)
Renders line-based volumetric data as rotationally symmetric capsules in screen space. It distinguishes itself by explicitly modeling line segments as capsules with deficit-rule joints to maintain visual continuity without gaps or double brightness. Choose for line-based data (e.g., smoke filaments, vector fields).

### [Tetrahedral Splatting](3181-tetrahedral-splatting.md)
Maps each tetrahedron of an unstructured mesh to a single spherical or ellipsoidal splat. It differs from voxel-based methods by handling unstructured geometry directly but suffers from visible gaps due to the one-splat-per-tetrahedron representation. Choose for static, unstructured tetrahedral meshes.

### [Voxel Splat Rendering](3730-voxel-splat-rendering.md)
Projects voxels onto the 2D image plane and blurs them into a footprint to prevent aliasing. It differs from ray casting by processing data in object space and from image-space sheet-buffered splatting by relying on CPU-driven bucketing or simpler GPU rasterization. Choose for regular voxel grids requiring anti-aliasing.

### [Decomposition](7254-decomposition.md)
Converts volumetric data into geometric primitives (spheres or slices) placed in space, scaled, and colored by a transfer function. It differs from direct voxel-based methods by explicitly constructing intermediate geometric representations, allowing for specialized rendering of slices. Choose when intermediate geometric processing or segmentation is required.

### [Triangle Mesh Splatting](8109-triangle-mesh-splatting.md)
Approximates continuous splat kernels with a discrete triangle mesh to leverage standard graphics hardware. It distinguishes itself by replacing analytic integration with rasterization-based accumulation, trading geometric precision for speed. Choose for high-performance rendering where mesh approximation is acceptable.

### [Resonant Brane Splatting](9845-resonant-brane-splatting.md)
Replaces flat, single-color 2D Gaussians with 'Branes' that emit spatially varying colors using Gaussian-Hermite modes. It differs from other methods by encoding high-frequency color variations internally within the primitive footprint rather than through shape deformation. Choose for super-resolution or high-frequency texture rendering.

## Background
The concept of splatting originated with Williams (1978) for volume rendering . The specific geometric primitives (quads, capsules, meshes) evolved to leverage GPU rasterization pipelines for real-time performance. Tetrahedral splatting was introduced for unstructured meshes . Resonant Brane Splatting is a recent development in neural rendering for super-resolution .
