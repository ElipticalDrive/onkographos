# Mueller's Splatting Approach

Also called: Mueller splatting

## Overview
Mueller's Splatting Approach is an object-order direct volume rendering technique that treats a gray-scale volume as a 3D discrete density function, where a convolution kernel defines how each sample contributes to points in space [S1, unofficial][S5, unofficial]. It solves the computational cost of 3D convolution by pre-integrating the kernel along the viewing ray to create a 2D footprint table, which is then rasterized onto the screen [S1, unofficial][S3, unofficial]. Unlike basic splatting which sums kernels within volume slices parallel to the viewing direction, Mueller's method aligns the processing slabs parallel to the image plane (image-aligned splatting), eliminating brightness variations and allowing variable interval distances [S7]. It builds on [Splat Extent and Projection](1792-splat-extent-and-projection.md) by using pre-computed 2D footprint lookups and leveraging texture mapping hardware for rasterization [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D discrete density function $f(s)$ where $s=(x_s, y_s, z_s)$ represents voxel centers and values [S1, unofficial][S5, unofficial]. A radially symmetric reconstruction kernel $h$ (e.g., Gaussian, Cone, Sinc, or Bilinear) [S1, unofficial][S7].
*   **Output:** A 2D image composed of accumulated splat contributions [S3, unofficial][S4].

**Data Structures:**
1.  **Footprint Table:** A 2D lookup table storing the analytically integrated kernel function along a traversing ray. The table resolution is much higher than the image plane resolution to ensure smoothness [S1, unofficial][S5, unofficial]. Values outside the table extent are zero [S5, unofficial].
2.  **Sheet Buffer:** A buffer aligned parallel to the image plane that accumulates contributions from voxels within a specific slab [S7].
3.  **Occlusion Map:** A dynamically constructed map used to cull invisible splats [S7].

**Formulas:**
The contribution of a sample $s$ to a point $(x, y, z)$ in space is defined as [S1, unofficial][S5, unofficial]:
$$C(x, y, z) = h(x - x_s, y - y_s, z - z_s) \cdot f(s)$$

The contribution to an image plane pixel $(x, y)$ is computed by integrating along the viewing ray (axis $u$ parallel to the ray) [S1, unofficial][S5, unofficial]:
$$C(x, y) = f(s) \int_{-\infty}^{\infty} h(x - x_s, y - y_s, u) du$$

The **Footprint Function** $F(x, y)$ is defined as the integral part, which is independent of sample density and depends only on the projected location [S1, unofficial][S5, unofficial]:
$$F(x, y) = \int_{-\infty}^{\infty} h(x - x_s, y - y_s, u) du$$

**Parameters:**
*   **Reconstruction Filter:** Choices include Cone, Gaussian, Sinc, or Bilinear functions [S1, unofficial]. Gaussian kernels are commonly used for their anti-aliasing characteristics, though they introduce signal smoothing [S7].
*   **Footprint Table Size:** Small tables produce blocky images; large tables smooth details but require more memory [S1, unofficial].
*   **Sampling Method:** Nearest-neighbor (fast, aliasing) or bilinear interpolation (smoother, slower) when generating the view-transformed footprint table [S1, unofficial].

**Steps:**
1.  **Pre-compute Footprint Table:** Evaluate the integral in Equation 2.22 on a grid with high resolution [S1, unofficial][S5, unofficial]. For orthographic projection, only one footprint table is needed per view [S1, unofficial].
2.  **Depth Sorting:** Traverse the list of object voxels in depth order [S3, unofficial][S4].
3.  **Slab Processing (Image-Aligned):** Group voxels into slabs of width $\Delta s$ aligned parallel to the image plane [S7].
4.  **Transformation:** Transform each relevant voxel center into screen space [S7].
5.  **Occlusion Culling:** Index into the occlusion map to test for visibility [S7].
    *   *Note:* Early splat elimination only culls invisible splats from rasterization; their transformation to screen space must still be performed to determine occlusion [S7].
6.  **Rasterization:** For each visible voxel:
    *   Calculate the screen-space coordinate of the projected grid point [S3, unofficial].
    *   Center the footprint around that point and stretch it according to the image magnification factor [S3, unofficial].
    *   Rasterize the footprint to the screen using the pre-integrated footprint table, multiplying indexed values by the voxel's value [S3, unofficial][S4].
    *   Clip voxel kernels overlapping a slab to the slab and sum into a sheet buffer [S7].
7.  **Composition:** Composite the current sheet with the previous sheet using the Porter-Duff over operator [S1, unofficial][S7].
8.  **Occlusion Map Update:** Perform a convolution operation after each sheet-buffer composite to update the occlusion map, limited to buffer tiles that received splat contributions [S7].

**Pseudocode:**
```python
def mueller_splatting(volume_data, kernel, view_matrix, projection_matrix, image_width, image_height):
    # 1. Pre-compute the generic footprint table
    footprint_table = precompute_footprint_table(kernel)
    
    # 2. Initialize sheet buffer and occlusion map
    sheet_buffer = [[0.0] * image_width for _ in range(image_height)]
    occlusion_map = [[0.0] * image_width for _ in range(image_height)]
    
    # 3. Sort voxels by depth (z-coordinate in view space)
    sorted_voxels = sorted(volume_data, key=lambda v: transform_to_view(v.center, view_matrix).z)
    
    # 4. Process voxels in slabs aligned with the image plane
    slab_width = calculate_slab_width(volume_data, view_matrix)
    current_slab_z = min(v.z_view for v in sorted_voxels)
    
    while current_slab_z <= max(v.z_view for v in sorted_voxels):
        slab_voxels = [v for v in sorted_voxels if current_slab_z <= v.z_view < current_slab_z + slab_width]
        slab_contribution = [[0.0] * image_width for _ in range(image_height)]
        
        for voxel in slab_voxels:
            screen_x, screen_y = transform_to_screen(voxel.center, view_matrix, projection_matrix)
            
            # Check occlusion
            if occlusion_map[screen_y][screen_x] > 0.0:
                continue
                
            footprint_scale = get_magnification_factor(voxel.center, view_matrix)
            footprint_extent = calculate_footprint_extent(footprint_scale)
            
            # Rasterize the footprint
            for dx in range(-footprint_extent, footprint_extent + 1):
                for dy in range(-footprint_extent, footprint_extent + 1):
                    if dx*dx + dy*dy <= footprint_extent*footprint_extent:
                        weight = sample_footprint_table(footprint_table, dx, dy, footprint_scale)
                        contribution = weight * voxel.value
                        slab_contribution[screen_y + dy][screen_x + dx] += contribution
                        
        # Composite slab contribution into the main sheet buffer
        sheet_buffer = composite_porter_duff(slab_contribution, sheet_buffer)
        
        # Update occlusion map based on the new sheet buffer state
        update_occlusion_map(occlusion_map, slab_contribution)
        
        current_slab_z += slab_width

    return sheet_buffer
```

## Subtopics

### [Multi-texture Mapping Splatting](7515-multi-texture-mapping-splatting.md)
Multi-texture Mapping Splatting is a hardware-accelerated volume rendering technique that reduces the computational cost of depth sorting by segmenting the volume data into parallel texture slices along the primary viewing direction. Unlike standard object-order splatting which sorts all voxels globally, this method projects voxels onto local texture planes and blends them using graphics hardware, trading increased memory usage for reduced sorting complexity. It builds on [Mueller's Splatting Approach](5752-mueller-s-splatting-approach.md) by replacing 3D kernel evaluation with pre-computed 2D footprint lookups and leveraging texture mapping hardware for rasterization.

## Operating characteristics
*   **Time Complexity:** Generally faster than ray casting for large datasets due to cache coherency (sequential voxel traversal) [S1, unofficial]. However, it requires depth sorting and multiple passes for sheet composition [S3, unofficial][S7].
*   **Memory Complexity:** Requires storage for the footprint table and sheet buffers. Large footprint tables increase memory usage [S1, unofficial].
*   **Performance:** Supports incremental rendering in back-to-front or front-to-back order [S1, unofficial]. Only processes relevant voxels, reducing data processed and stored compared to ray casting [S7].
*   **Strengths:** Exploits cache coherency [S1, unofficial]. Renders smooth surfaces without staircase artifacts [S1, unofficial]. Replaces point sampling with sample averaging, introducing low-pass filtering that reduces aliasing (especially for isosurfaces and $\Delta s > 1.0$) [S7].
*   **Limitations:** Generated images are blurred due to the spherically symmetric reconstruction kernel [S1, unofficial]. Basic splatting suffers from "color bleeding" artifacts, which Mueller's image-aligned approach mitigates but does not entirely eliminate without further techniques (e.g., FreeVoxels) [S4]. Axis-aligned sheet buffers (in basic splatting) introduce "popping" artifacts; Mueller's image-aligned approach reduces this but requires dynamic occlusion map updates [S4, S7]. Early splat elimination saves rasterization cost but still requires transformation for occlusion testing [S7].
*   **When to Use:** When cache coherency is beneficial, smooth surfaces are desired, and incremental rendering is needed. Suitable for hardware acceleration via texture mapping [S3, unofficial][S4].
*   **When Not to Use:** When sharp object boundaries are required (ray casting with trilinear reconstruction is sharper) [S1, unofficial]. When memory is constrained and large footprint tables are prohibitive [S1, unofficial].

## Background
Mueller's Splatting Approach was introduced by Mueller et al. as an improvement over Westover's original splatting method [S7]. Westover's method summed voxel kernels within volume slices most parallel to the viewing direction, which was prone to severe brightness variations in animated viewing and did not allow variable interval distances [S7]. Mueller's method, termed "image-aligned splatting," aligns the sheet buffers parallel to the image plane, eliminating these drawbacks [S7]. It was further accelerated with GPUs by Mueller et al. [S4]. The method is part of the broader object-order rendering family, which decomposes the volume into basis functions projected to the screen [S3, unofficial].
