# Footprint Evaluation

Also called: Footprint Mapping, Westover 1990, Westover Splatting, Splatting (Westover), Westover's Splatting, Westover's Footprint Evaluation

## Overview
Footprint Evaluation is an object-order direct volume rendering algorithm that projects each voxel from the volume grid onto the 2D image plane as a "splat" (footprint) and accumulates these contributions to form the final image [S1, S3, S4, S5, S7, S8, S10, S12, S13, unofficial]. It solves the problem of efficiently rendering volumetric data by distributing each sample's energy across a region on the screen using a pre-integrated reconstruction kernel, rather than casting rays per pixel [S1, unofficial][S2][S3, S4, S5, S7, S8, S10, S12, S13, unofficial]. It sets itself apart from its siblings and nearest alternatives by using a forward-mapping scheme where the footprint is the integral of the 3D kernel along the view ray, allowing for pre-computation and fast rasterization, whereas [Perspective-Correct Point Splatting Vertex Shader](1082-perspective-correct-point-splatting-vertex-shader.md) and [Centralized Conics Approach](1243-centralized-conics-approach.md) focus on geometric projection accuracy, and [Exact Half-Space Clipping](3395-exact-half-space-clipping.md) focuses on boundary handling [S1, unofficial][S2][S3, S4, S5, S7, S8, S10, S12, S13, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volume grid of voxels with values $f(v_k)$, a viewing direction (orthographic or perspective), a reconstruction kernel $w$, and a compositing order (front-to-back or back-to-front).
*   **Output:** A 2D image where each pixel contains the accumulated color and opacity from all overlapping splats [S1, S3, S4, S5, S7, S8, S10, S12, S13, unofficial].

**Data Structures:**
1.  **Volume Grid:** Array of voxels. Each voxel has a position $(i,j,k)$ and a value $f(v_k)$ (density/color) [S3, S7, unofficial][S14, book].
2.  **Footprint Table:** A 2D lookup table storing the pre-integrated values of the reconstruction kernel. It represents the integration of the 3D spherically symmetric kernel along one axis (typically the view ray) [S1, S4, S5, S7, S10, S11, S12, S13, unofficial][S14, book].
    *   **Layout:** A 2D array of floating-point values. The center of the table corresponds to the projected voxel center. The size of the table determines the support of the footprint [S5, S10, S13, unofficial][S14, book].
    *   **Generic vs. View-Transformed:** For orthographic projection with uniform grid spacing and symmetric kernels, a single generic footprint table is used for all voxels [S1, S10, S13, unofficial]. For perspective projection or non-uniform spacing, a view-transformed table is computed per view (or per voxel) to account for elliptical distortion [S10, S11, S12, S13, unofficial].
3.  **Compositing Buffer:** The final image buffer storing accumulated color and opacity [S3, S7, unofficial].
4.  **Sheet Buffer (Optional):** In the sheet-buffer method, splats are accumulated in intermediate buffers aligned with the volume face most parallel to the image plane before being composited into the final buffer [S2][S3, S7, S8, unofficial].

**Numbered Steps:**

1.  **Preprocessing (Footprint Table Generation):**
    *   Select a 3D reconstruction kernel $w(x,y,z)$, typically a Gaussian [S3, S7, S10, unofficial].
    *   Compute the 2D footprint function $F(x,y)$ by integrating the 3D kernel along the view ray (z-axis):
        $$ F(x,y) = \int_{-\infty}^{\infty} w(x,y,z) \, dz $$
        [S3, S7, S10, S11, S12, unofficial]
    *   Sample $F(x,y)$ on a 2D grid to create the Footprint Table. The resolution of this table should be high enough to avoid aliasing but low enough to fit in memory [S10, S13, unofficial][S14, book].
    *   For perspective projection, compute the orientation and scale of the elliptical footprint for the current view [S7, S10, S11, S12, S13, unofficial].

2.  **Voxel Traversal and Projection:**
    *   Determine the traversal order of voxels. This is typically done by sorting voxels based on their depth along the view ray. Common strategies include:
        *   Back-to-front: Guarantees correct visibility but is slower [S3, S4, S5, S7, unofficial].
        *   Front-to-back: Faster because compositing can stop when pixels are fully opaque [S3, S4, S5, S7, unofficial].
        *   Sheet-based: Group voxels into slabs parallel to the image plane to optimize cache usage and compositing [S2][S3, S7, S8, unofficial].
    *   For each voxel $v_k$ at position $(x_k, y_k, z_k)$ with value $f(v_k)$:
        *   Project the voxel center to the image plane coordinates $(x_s, y_s)$ using the view and projection matrices [S4, S5, S10, unofficial][S14, book].
        *   Determine the screen-space extent of the footprint. For orthographic projection, this is a circle (if the kernel is isotropic). For perspective projection, it is an ellipse [S10, S11, S12, S13, unofficial].
        *   If using a view-transformed table, map the elliptical extent to the generic circular table extent using a transformation $T^{-1}$ [S10, unofficial].

3.  **Rasterization (Splatting):**
    *   Identify all pixels $(x,y)$ that lie within the footprint's extent [S4, S10, unofficial].
    *   For each pixel in the extent:
        *   Calculate the displacement $(dx, dy) = (x - x_s, y - y_s)$ from the projected voxel center [S10, S13, unofficial].
        *   Look up the weight $w(x,y)_s$ from the Footprint Table. If the footprint is elliptical, interpolate from the view-transformed table or map the coordinates to the generic table [S10, S11, S12, S13, unofficial].
        *   Compute the contribution: $C = f(v_k) \times w(x,y)_s$ [S10, S11, S13, unofficial].
        *   Composite this contribution into the Compositing Buffer (and/or Sheet Buffer) using the chosen compositing operator (e.g., front-to-back alpha blending) [S4, S5, S7, S8, unofficial].

4.  **Final Compositing (if using Sheet Buffer):**
    *   If the sheet-buffer method is used, composite the accumulated sheet buffers into the final Compositing Buffer in front-to-back order [S2][S3, S7, S8, unofficial].

**Pseudocode:**

```python
def footprint_evaluation(volume, view_matrix, projection_matrix, kernel_width, footprint_table_size):
    """
    Renders a volume using Footprint Evaluation (Splatting).
    
    Args:
        volume: 3D array of voxel values.
        view_matrix: 4x4 view matrix.
        projection_matrix: 4x4 projection matrix.
        kernel_width: Radius of the reconstruction kernel.
        footprint_table_size: Size of the 2D footprint lookup table.
        
    Returns:
        image: 2D array of pixel colors.
    """
    # 1. Preprocessing: Generate Footprint Table
    # Assume a 3D Gaussian kernel w(x,y,z) = exp(-(x^2+y^2+z^2)/sigma^2)
    # Integrate along z to get 2D footprint F(x,y)
    footprint_table = generate_footprint_table(kernel_width, footprint_table_size)
    
    # Initialize Compositing Buffer (Color and Opacity)
    # Using front-to-back compositing: C_out = C_in + C_splat * (1 - A_in)
    # A_out = A_in + A_splat * (1 - A_in)
    # For simplicity, assume alpha compositing is handled by the hardware or a specific function
    compositing_buffer = initialize_buffer(volume.shape[0], volume.shape[1])
    
    # 2. Determine Traversal Order
    # Sort voxels by depth along the view ray
    voxels = get_voxels(volume)
    sorted_voxels = sort_by_depth(voxels, view_matrix)
    
    # 3. Project and Splat
    for voxel in sorted_voxels:
        # Project voxel center to screen space
        screen_pos = project(voxel.position, view_matrix, projection_matrix)
        x_s, y_s = screen_pos.x, screen_pos.y
        
        # Determine footprint extent in screen space
        # For orthographic, extent is circular. For perspective, it's elliptical.
        # Here we assume a simplified circular extent for the generic table
        extent_radius = get_footprint_radius(voxel, projection_matrix)
        
        # Iterate over pixels in the footprint extent
        for dy in range(-extent_radius, extent_radius + 1):
            for dx in range(-extent_radius, extent_radius + 1):
                x = int(x_s + dx)
                y = int(y_s + dy)
                
                # Check if pixel is within image bounds
                if not is_in_bounds(x, y, compositing_buffer):
                    continue
                
                # Calculate weight from footprint table
                # Normalize dx, dy to table coordinates
                table_x = normalize(dx, extent_radius, footprint_table_size)
                table_y = normalize(dy, extent_radius, footprint_table_size)
                weight = lookup_footprint(footprint_table, table_x, table_y)
                
                # Compute contribution
                contribution = voxel.value * weight
                
                # Composite into buffer
                composite_pixel(compositing_buffer, x, y, contribution)
                
    return compositing_buffer

def generate_footprint_table(kernel_width, table_size):
    """
    Generates a 2D footprint table by integrating a 3D Gaussian kernel along the z-axis.
    """
    table = zeros(table_size, table_size)
    sigma = kernel_width / 2.0 # Approximate sigma for Gaussian
    center = table_size // 2
    
    for i in range(table_size):
        for j in range(table_size):
            x = (i - center) / table_size
            y = (j - center) / table_size
            # Integrate 3D Gaussian along z: integral of exp(-(x^2+y^2+z^2)/sigma^2) dz
            # This results in a 2D Gaussian: exp(-(x^2+y^2)/sigma^2) * sqrt(pi)*sigma
            # For simplicity, we store the normalized 2D Gaussian profile
            value = exp(-(x**2 + y**2) / (2 * sigma**2))
            table[i][j] = value
            
    return table

def composite_pixel(buffer, x, y, contribution):
    """
    Adds the contribution to the pixel in the buffer.
    Assumes simple additive accumulation for density/color.
    For proper alpha compositing, use front-to-back or back-to-front formulas.
    """
    buffer[x][y] += contribution
```

**Edge Cases and Pitfalls:**
*   **Aliasing:** Standard splatting suffers from aliasing when the volume sampling rate is higher than the image sampling rate (e.g., high-resolution volumes or perspective views) [S5, S7, unofficial]. This is caused by the discrete evaluation of the splatting equation [S2]. Solutions include Antialiased Splatting with Footprint Alignment [1288-antialiased-splatting-with-footprint-alignment.md] or EWA filters [S2][S9, unofficial].
*   **Overlapping Splats:** When splats overlap, the compositing order affects the result. Front-to-back compositing is faster but may produce incorrect results if the traversal order is not perfectly sorted [S3, S4, S5, S7, unofficial]. Back-to-front guarantees correctness but is slower [S3, S4, S5, S7, unofficial].
*   **Perspective Projection:** The footprint becomes elliptical, requiring additional computation for orientation and scaling [S7, S10, S11, S12, S13, unofficial].
*   **Sheet Buffer Popping:** In the sheet-buffer method, sudden changes in the orientation of the compositing sheets can cause popping artifacts [S2][S8, unofficial].
*   **Kernel Size:** Large footprints increase blurring; small footprints generate gaps [S3, S7, S13, unofficial]. The footprint size must be tuned for the pixel-to-voxel ratio [S3, S7, unofficial].

## Subtopics

### [Antialiased Splatting with Footprint Alignment](1288-antialiased-splatting-with-footprint-alignment.md)
Antialiased Splatting with Footprint Alignment is a forward-mapping volume rendering technique that prevents sample-rate aliasing in perspective views by dynamically scaling splat sizes and attenuating splat energy for voxels beyond a critical distance. It sets itself apart from standard splatting by varying the kernel size and energy as a function of depth to match the diverging integration grid rays, ensuring the integration grid sampling frequency remains above twice the maximum volume raster frequency.

### [Separable Footprint (SF) Projector](2900-separable-footprint-sf-projector.md)
The Separable Footprint (SF) projector is a forward mapping algorithm for X-ray Computed Tomography (XCT) that calculates line integrals through a voxelized volume by explicitly modeling the finite width of both detector pixels and volume voxels. Unlike Siddon or Joseph methods, which treat voxels and pixels as infinitesimal lines, SF provides higher quantitative accuracy and avoids specific artifacts, at the cost of increased computational complexity.

### [Footprint Function Mechanism](4731-footprint-function-mechanism.md)
The Footprint Function Mechanism implements 3D spherically symmetric splatting kernels in volume rendering by reducing computational dimensionality from 3D to 2D. It projects volumetric data onto a 2D image plane by pre-computing the integration of the 3D kernel along one axis and storing the result as a 2D lookup table. This approach avoids per-pixel 3D kernel evaluations by relying on 2D table lookups and interpolation, as detailed in [Footprint Evaluation](1180-footprint-evaluation.md).

## Operating characteristics
*   **Time Complexity:** $O(k^2 n^3)$, where $n^3$ is the number of voxels and $k$ is the kernel size (footprint radius) [S4, S5, unofficial]. This is faster than ray-casting's $O(k^3 n^3)$ because the convolution is precomputed and each voxel is splatted exactly once [S4, S5, unofficial].
*   **Memory Complexity:** Depends on the footprint table size and the number of voxels. The footprint table is small (2D), but the volume data is large (3D) [S1, S10, S13, unofficial][S14, book].
*   **Measured Performance:** Splatting is inherently faster than ray-casting for moderate screen sizes and specific datasets, but good quality results may require as much CPU time as ray-casting [S3, S7, S8, unofficial][S15]. It is efficient for real-time rendering on older hardware due to its simplicity and parallelizability [S4, S5, S11, unofficial].
*   **Strengths:**
    *   Fast due to pre-integrated kernels and object-order processing [S4, S5, S11, unofficial].
    *   Simple static parallel decomposition [S5, unofficial].
    *   Easy to implement and parallelize [S11, unofficial].
    *   Supports scattered data (e.g., SPH) with sorting [S7, unofficial].
*   **Limitations:**
    *   Poor quality without anti-aliasing techniques (aliasing artifacts) [S5, S7, unofficial].
    *   Blurry images for zoomed views due to Gaussian kernel properties [S3, S7, unofficial].
    *   High fill-rate for zoomed splats [S7, unofficial].
    *   Incorrect compositing when splats overlap, especially with changing traversal orders [S5, S7, unofficial].
    *   Not well-suited for perspective projection without additional transformations [S2][S7, unofficial].
*   **When to Use:** Real-time volume rendering where speed is prioritized over perfect accuracy, or for orthographic projections of moderate-resolution volumes [S4, S5, S11, unofficial].
*   **When Not to Use:** High-quality offline rendering, perspective views with high dynamic range, or when strict anti-aliasing is required without additional techniques [S2][S5, S7, unofficial].

## Background
Footprint Evaluation, also known as Westover Splatting, was first described by L. Westover in 1990 in the paper "Footprint evaluation for volume rendering" [S1, unofficial][S2][S3, S4, S5, S7, S8, S10, unofficial]. It was introduced as a forward mapping algorithm for rendering regular grids on a CPU [S1, unofficial][S2][S8, S10, unofficial]. The method was developed to address the computational cost of ray-casting by pre-computing the integration of the reconstruction kernel [S1, S4, S5, unofficial]. It has since been extended to support perspective projection, anti-aliasing, and hardware acceleration [S2][S5, S7, S8, S9, S10, unofficial].
