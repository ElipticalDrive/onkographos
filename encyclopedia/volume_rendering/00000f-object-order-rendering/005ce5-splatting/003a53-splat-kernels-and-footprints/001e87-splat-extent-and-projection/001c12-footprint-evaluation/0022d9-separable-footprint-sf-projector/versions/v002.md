# Separable Footprint (SF) Projector

Also called: SF method, Separable Footprint (SF) Method

## Overview
The Separable Footprint (SF) projector is a forward mapping algorithm for X-ray Computed Tomography (XCT) that calculates line integrals through a voxelized volume by explicitly modeling the finite width of both detector pixels and volume voxels [S1, unofficial][S2, unofficial]. Unlike Siddon or Joseph methods, which treat voxels and pixels as infinitesimal lines, SF provides higher quantitative accuracy and avoids specific artifacts, at the cost of increased computational complexity [S1, unofficial][S2, unofficial].

## How it works
The SF method computes the projection of a 3D volume onto a 2D detector plane [G]. 

**Inputs and Outputs:**
- **Input:** A 3D volumetric grid $V$ with dimensions $(N_x, N_y, N_z)$ and voxel spacings $(\Delta x, \Delta y, \Delta z)$ [G]. A set of ray paths defined by source and detector positions/orientations [G].
- **Output:** A 2D projection image $P$ representing the line integrals (attenuation) measured by the detector pixels [G].

**Data Structures:**
- The volume is stored as a regular grid [G].
- Detector geometry is defined by pixel dimensions $(\Delta u, \Delta v)$ and the transformation from world space to detector space [G].

**Algorithm Steps:**
1. **Ray Tracing:** For each detector pixel, determine the corresponding ray path through the volume by calculating the intersection of the ray with the volume bounding box [G].
2. **Footprint Calculation:** For each voxel intersected by the ray, calculate the geometric overlap volume between the voxel and the effective detector pixel area projected back into the volume space [G].
3. **Weight Computation:** Compute the weight $w_{ijk}$ for each voxel $(i,j,k)$ based on the geometric overlap [G].
4. **Accumulation:** Accumulate the weighted voxel values into the detector pixel:
   $$ P_{uv} = \sum_{i,j,k} w_{ijk} V_{ijk} $$
   where $V_{ijk}$ is the value of the voxel at $(i,j,k)$ [G].

**Parameters:**
- Voxel sizes $(\Delta x, \Delta y, \Delta z)$: Must be provided for accurate scaling [S2, unofficial].
- Detector pixel sizes $(\Delta u, \Delta v)$: Must be provided for accurate scaling [S2, unofficial].

**Edge Cases and Pitfalls:**
- **Boundaries:** Rays grazing the volume boundary must be handled to avoid missing contributions or double-counting [G].
- **Precision:** Standard floating-point arithmetic is sufficient for typical XCT scales, but ray origins and intersections should be computed in double precision to avoid accumulation errors [G].

**Pseudocode:**
```python
def forward_project(volume, voxel_spacing, detector_geometry):
    dx, dy, dz = voxel_spacing
    projection = [[0.0 for _ in range(detector_geometry.width)] for _ in range(detector_geometry.height)]
    for v in range(detector_geometry.height):
        for u in range(detector_geometry.width):
            ray_origin, ray_direction = detector_geometry.get_ray(u, v)
            t_min, t_max = intersect_box(ray_origin, ray_direction, volume.bounds)
            if t_max <= t_min:
                continue
            start_voxel = voxel_index(ray_origin, voxel_spacing)
            end_voxel = voxel_index(ray_origin + ray_direction * t_max, voxel_spacing)
            step_x = 1 if ray_direction.x >= 0 else -1
            step_y = 1 if ray_direction.y >= 0 else -1
            step_z = 1 if ray_direction.z >= 0 else -1
            t_x = (start_voxel.x + step_x * 0.5 - ray_origin.x) / ray_direction.x if ray_direction.x != 0 else float('inf')
            t_y = (start_voxel.y + step_y * 0.5 - ray_origin.y) / ray_direction.y if ray_direction.y != 0 else float('inf')
            t_z = (start_voxel.z + step_z * 0.5 - ray_origin.z) / ray_direction.z if ray_direction.z != 0 else float('inf')
            i, j, k = start_voxel.x, start_voxel.y, start_voxel.z
            while True:
                voxel_min = [i * dx, j * dy, k * dz]
                voxel_max = [(i + 1) * dx, (j + 1) * dy, (k + 1) * dz]
                overlap_x = max(0.0, min(t_max, voxel_max[0] - ray_origin.x) / ray_direction.x - max(t_min, voxel_min[0] - ray_origin.x) / ray_direction.x) if ray_direction.x != 0 else max(0.0, min(t_max, t_max) - max(t_min, t_min))
                overlap_y = max(0.0, min(t_max, voxel_max[1] - ray_origin.y) / ray_direction.y - max(t_min, voxel_min[1] - ray_origin.y) / ray_direction.y) if ray_direction.y != 0 else max(0.0, min(t_max, t_max) - max(t_min, t_min))
                overlap_z = max(0.0, min(t_max, voxel_max[2] - ray_origin.z) / ray_direction.z - max(t_min, voxel_min[2] - ray_origin.z) / ray_direction.z) if ray_direction.z != 0 else max(0.0, min(t_max, t_max) - max(t_min, t_min))
                weight = (overlap_x * overlap_y * overlap_z) / (dx * dy * dz)
                if weight > 0.0:
                    projection[v][u] += volume[k][j][i] * weight
                if i == end_voxel.x and j == end_voxel.y and k == end_voxel.z:
                    break
                if t_x < t_y and t_x < t_z:
                    i += step_x
                    t_x += step_x * dx / ray_direction.x if ray_direction.x != 0 else float('inf')
                elif t_y < t_z:
                    j += step_y
                    t_y += step_y * dy / ray_direction.y if ray_direction.y != 0 else float('inf')
                else:
                    k += step_z
                    t_z += step_z * dz / ray_direction.z if ray_direction.z != 0 else float('inf')
    return projection

def intersect_box(origin, direction, bounds):
    t_min = -float('inf')
    t_max = float('inf')
    for axis in range(3):
        if direction[axis] == 0:
            if origin[axis] < bounds[axis][0] or origin[axis] > bounds[axis][1]:
                return 0.0, 0.0
        else:
            t1 = (bounds[axis][0] - origin[axis]) / direction[axis]
            t2 = (bounds[axis][1] - origin[axis]) / direction[axis]
            if t1 > t2:
                t1, t2 = t2, t1
            t_min = max(t_min, t1)
            t_max = min(t_max, t2)
    return t_min, t_max

def voxel_index(position, spacing):
    return (int(position[0] / spacing[0]), int(position[1] / spacing[1]), int(position[2] / spacing[2]))
```

## Operating characteristics
- **Accuracy:** Quantitatively accurate; numerical values scale appropriately with changes in voxel and detector sizes [S2, unofficial]. More accurate than Siddon or Joseph methods, which do not model finite widths [S1, unofficial][S2, unofficial].
- **Computational Cost:** More computationally expensive than Siddon or Joseph methods due to the complexity of calculating finite footprints [S1, unofficial][S2, unofficial].
- **Artifacts:** Avoids artifacts produced by Siddon/Joseph methods in cases where finite width effects are significant [S1, unofficial][S2, unofficial].
- **Implementation:** Implemented in CPU (C/C++) and GPU (CUDA) environments [S2, unofficial].

## Background
The SF method was introduced by Long et al. in 2010 as one of the most popular and effective models for calculating XCT line integrals through a voxelized volume [S1, unofficial]. It is part of a class of methods (along with Distance Driven) that explicitly model the finite width of detector pixels and volume voxels, contrasting with earlier methods like Siddon (1985) and Joseph (1982) [S1, unofficial][S2, unofficial]. It is implemented in the LEAP software package for CPU and GPU forward and back projections [S2, unofficial]. Optimization-based reconstruction algorithms that rely on gradient calculations require the adjoint (transpose) of the X-ray Transform, which corresponds to backprojection [S1, unofficial][S2, unofficial].
