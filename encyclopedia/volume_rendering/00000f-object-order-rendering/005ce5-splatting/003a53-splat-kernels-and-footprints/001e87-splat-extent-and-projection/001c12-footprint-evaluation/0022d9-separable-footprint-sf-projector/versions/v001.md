# Separable Footprint (SF) Projector

Also called: SF method, Separable Footprint (SF) Method

## Overview
The Separable Footprint (SF) projector is a forward mapping algorithm for X-ray Computed Tomography (XCT) that calculates line integrals through a voxelized volume by explicitly modeling the finite width of both detector pixels and volume voxels [S1, S2, unofficial]. Unlike Siddon or Joseph methods, which treat voxels and pixels as infinitesimal lines, SF provides higher quantitative accuracy and avoids specific artifacts, at the cost of increased computational complexity [S1, S2, unofficial].

## How it works
The SF method computes the projection of a 3D volume onto a 2D detector plane. It is characterized by its separability, allowing the 3D integration to be decomposed into independent 1D operations along the grid axes, which ensures that numerical values scale appropriately with changes in voxel or detector sizes [S2, unofficial].

**Inputs and Outputs:**
- **Input:** A 3D volumetric grid $V$ with dimensions $(N_x, N_y, N_z)$ and voxel spacings $(\Delta x, \Delta y, \Delta z)$. A set of ray paths defined by source and detector positions/orientations.
- **Output:** A 2D projection image $P$ representing the line integrals (attenuation) measured by the detector pixels.

**Data Structures:**
- The volume is stored as a regular grid.
- Detector geometry is defined by pixel dimensions $(\Delta u, \Delta v)$ and the transformation from world space to detector space.

**Algorithm Steps:**
1. **Ray Tracing:** For each detector pixel, determine the corresponding ray path through the volume. This involves calculating the intersection of the ray with the volume bounding box.
2. **Footprint Calculation:** For each voxel intersected by the ray, calculate the "footprint" or overlap volume between the voxel and the effective detector pixel area projected back into the volume space. The SF method assumes the detector response and voxel shape are separable along the principal axes [S1, S2, unofficial].
3. **Weight Computation:** Compute the weight $w_{ijk}$ for each voxel $(i,j,k)$ based on the geometric overlap. The separability implies that the 3D overlap integral can be computed as the product of 1D integrals along the $x$, $y$, and $z$ axes.
4. **Accumulation:** Accumulate the weighted voxel values into the detector pixel:
   $$ P = \sum_{i,j,k} w_{ijk} V_{ijk} $$
   where $V_{ijk}$ is the value of the voxel at $(i,j,k)$.

**Parameters:**
- Voxel sizes $(\Delta x, \Delta y, \Delta z)$: Must be provided for accurate scaling [S2, unofficial].
- Detector pixel sizes $(\Delta u, \Delta v)$: Must be provided for accurate scaling [S2, unofficial].

**Edge Cases and Pitfalls:**
- **Precision:** The method is quantitatively accurate, but requires careful handling of floating-point precision when calculating small overlaps [S2, unofficial].
- **Boundaries:** Rays grazing the volume boundary must be handled to avoid missing contributions or double-counting [G].

**Pseudocode:**
```python
def forward_project(volume, voxel_spacing, detector_geometry):
    """
    Performs forward projection using the Separable Footprint method.
    
    Args:
        volume: 3D array of voxel values.
        voxel_spacing: Tuple (dx, dy, dz) of voxel dimensions.
        detector_geometry: Object containing source positions, detector positions, 
                           and detector pixel dimensions (du, dv).
    
    Returns:
        projection: 2D array of projected values.
    """
    # Initialize output projection buffer
    projection = zeros(detector_geometry.shape)
    
    # Iterate over each detector pixel
    for u, v in detector_geometry.pixels:
        # Determine ray direction and origin for this pixel
        ray_origin, ray_direction = detector_geometry.get_ray(u, v)
        
        # Calculate intersection with volume bounding box
        t_min, t_max = intersect_box(ray_origin, ray_direction, volume.bounds)
        
        if t_max <= t_min:
            continue
            
        # Calculate the footprint weights for intersected voxels
        # The SF method separates the 3D integration into 1D components
        # along the grid axes.
        weights = compute_separable_footprint_weights(
            ray_origin, ray_direction, t_min, t_max, 
            voxel_spacing, detector_geometry.pixel_size
        )
        
        # Accumulate weighted voxel values
        for voxel_index, weight in weights.items():
            projection[u, v] += volume[voxel_index] * weight
            
    return projection

    """

    # projected into the volume space.
    # The weight for a voxel is the product of the 1D overlaps along each axis.

    # Standard SF uses a box kernel for both voxel and detector.
    
    weights = {}
    
    # Iterate over voxels intersected by the ray
    # This requires efficient traversal (e.g., 3D DDA)
    voxels = traverse_voxels(ray_origin, ray_direction, t_min, t_max, voxel_spacing)
    
    for voxel in voxels:
        # Calculate 1D overlap along x, y, z
        overlap_x = calculate_1d_overlap(ray_origin.x, ray_direction.x, 
                                         voxel.x_min, voxel.x_max, detector_pixel_size.x)
        overlap_y = calculate_1d_overlap(ray_origin.y, ray_direction.y, 
                                         voxel.y_min, voxel.y_max, detector_pixel_size.y)
        overlap_z = calculate_1d_overlap(ray_origin.z, ray_direction.z, 
                                         voxel.z_min, voxel.z_max, detector_pixel_size.z)
        
        # Weight is the product of overlaps normalized by voxel volume
        weight = (overlap_x * overlap_y * overlap_z) / (voxel_spacing.x * voxel_spacing.y * voxel_spacing.z)
        
        weights[voxel.index] = weight
        
    return weights
```

## Operating characteristics
- **Accuracy:** Quantitatively accurate; numerical values scale appropriately with changes in voxel and detector sizes [S2, unofficial]. More accurate than Siddon or Joseph methods, which do not model finite widths [S1, S2, unofficial].
- **Computational Cost:** More computationally expensive than Siddon or Joseph methods due to the complexity of calculating finite footprints [S1, S2, unofficial].
- **Artifacts:** Avoids artifacts produced by Siddon/Joseph methods in cases where finite width effects are significant [S1, S2, unofficial].
- **Implementation:** Implemented in CPU (C/C++) and GPU (CUDA) environments [S2, unofficial].

## Background
The SF method was introduced by Long et al. in 2010 as one of the most popular and effective models for calculating XCT line integrals through a voxelized volume [S1, unofficial]. It is part of a class of methods (along with Distance Driven) that explicitly model the finite width of detector pixels and volume voxels, contrasting with earlier methods like Siddon (1985) and Joseph (1982) [S1, S2, unofficial]. It is used in software packages such as LEAP for both forward and back projections, particularly in optimization-based reconstruction algorithms that require the adjoint (transpose) of the X-ray Transform [S1, S2, unofficial].
