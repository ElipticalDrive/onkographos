# Volume Rendering Pipeline

Also called: CRIO Process, Classification, Reflection, Illumination, Opacity, Rendering Stages, Direct Volume Rendering (DVR) Pipeline, Shading and Classification Pipeline, VolumeRenderer forward method

## Overview
The Volume Rendering Pipeline is a standard implementation structure for direct volume rendering that processes scalar field data through a sequence of stages to produce a 2D image without fitting geometric primitives [S1, unofficial][S2, unofficial][S6]. It solves the problem of visualizing 3D volumetric data by discretizing the continuous volume rendering integral along light rays, mapping scalar values to optical properties, and compositing the results [S1, unofficial][S2, unofficial]. What sets it apart from its siblings, such as the [Fragment List-Based Rendering Pipeline](3488-fragment-list-based-rendering-pipeline.md) or the [Deferred Rendering Pipeline](10584-deferred-rendering-pipeline.md), is its explicit separation of classification (opacity assignment) and shading (color assignment) into distinct, often parallel, steps before ray casting, allowing for independent control of surface appearance and transparency [S2, unofficial][S3, unofficial].

## How it works
The pipeline typically consists of six stages: data traversal, interpolation, gradient computation, classification, shading and illumination, and compositing [S1, unofficial]. The following describes the canonical implementation based on the "Shading and Classification Pipeline" model [S2, unofficial][S3, unofficial].

### Inputs and Outputs
*   **Input:** A 3D scalar field (voxel grid) $f_0(x_i)$ at voxel locations $x_i = (x_i, y_j, z_k)$ [S3, unofficial].
*   **Output:** A 2D image where each pixel $(u, v)$ has a color $C_\lambda(u, v)$ and an opacity $\alpha(u, v)$ [S2, unofficial][S3, unofficial].

### Data Structures
*   **Voxel Database:** Stores prepared scalar values $f_1(x_i)$, colors $c_\lambda(x_i)$, and opacities $\alpha(x_i)$ for each voxel [S2, unofficial][S3, unofficial].
*   **Ray Bundle:** A set of rays defined by origin and direction, typically one per pixel [S5, unofficial].
*   **Sample Points:** $K$ evenly spaced locations $x_j$ along each ray [S2, unofficial][S3, unofficial].

### Numbered Steps

1.  **Data Preparation and Traversal:**
    Acquire raw values $f_0(x_i)$. Perform data preparation such as correction for non-orthogonal sampling grids, patient motion, contrast enhancement, or interpolation of additional samples to produce an array of prepared values $f_1(x_i)$ [S2, unofficial][S3, unofficial].

2.  **Shading (Color Assignment):**
    Input $f_1(x_i)$ into a shading model to yield an array of voxel colors $c_\lambda(x_i)$, where $\lambda \in \{r, g, b\}$ [S2, unofficial][S3, unofficial]. The shading model uses local gradient vectors as surface normals and considers light source and viewpoint positions [S2, unofficial][S6]. Common models include Phong shading [S1, unofficial][S4, unofficial].

3.  **Classification (Opacity Assignment):**
    In a separate step, input $f_1(x_i)$ into a classification procedure (using transfer functions) to yield an array of voxel opacities $\alpha(x_i)$ [S2, unofficial][S3, unofficial]. Unwanted data values are faded out (opacity zero) [S6]. This independence ensures undistorted visualization of 3D shape [S2, unofficial].

4.  **Gradient Computation:**
    Compute the gradient of the scalar field at sample positions to provide visual cues for shading [S1, unofficial]. This is typically approximated by central differences [S1, unofficial].

5.  **Ray Casting and Resampling:**
    Cast rays from the observer eyepoint [S2, unofficial][S3, unofficial][S6]. For each ray, compute a vector of sample colors $c_\lambda(\tilde{x}_i)$ and opacities $\alpha(\tilde{x}_i)$ by resampling the voxel database at $K$ evenly spaced locations $\tilde{x}_i$ along the ray [S2, unofficial][S3, unofficial]. This is done by tri-linearly interpolating from the colors and opacities in the eight voxels closest to each sample location $\tilde{x}_i$ [S2, unofficial][S3, unofficial][S6].

6.  **Compositing:**
    Drape a fully opaque background of color $c_{bkg, \lambda}$ behind the dataset [S3, unofficial]. Composite the resampled colors and opacities with each other and with the background in back-to-front order to yield a single color $C_\lambda(\tilde{u}_i)$ for the ray/pixel [S2, unofficial][S3, unofficial][S6].

### Formulas

**Transparency Formula (Compositing):**
The color $C_{out, \lambda}$ of the ray as it leaves a sample location is related to the color $C_{in, \lambda}$ as it enters, and the sample color $c_\lambda$ and opacity $\alpha$ at that location by [S2, unofficial][S3, unofficial]:

$$
C_{out, \lambda} = C_{in, \lambda}(1 - \alpha) + c_\lambda \alpha
$$

Solving for the final pixel color $C_\lambda(u, v)$ involves iterating this formula from the back to the front [S2, unofficial][S3, unofficial].

**Interpolation:**
Tri-linear interpolation is used to resample values from the eight closest voxels [S2, unofficial][S3, unofficial][S6].

### Parameters
*   **K:** Number of evenly spaced sample locations along a viewing ray [S2, unofficial][S3, unofficial].
*   **Light Source Position:** Adjustable parameter for shading [S6].
*   **View Point Position:** Adjustable parameter for shading [S6].
*   **Transfer Functions:** Define the mapping from scalar values to opacity and color [S6].

### Edge Cases and Pitfalls
*   **Performance Cost:** Shading and interpolation between the eight voxels of a cell are high-cost operations [S6]. These can be switched off to improve performance, potentially degrading visual quality [S6].
*   **Precision:** The file format for input data may expect 16-bit resolution and little-endian byte order [S6].
*   **Clipping:** Standard pipelines apply global rendering parameters, which can obscure important structures if they lie within a clipping area [S7].

def volume_rendering_pipeline(voxel_grid, camera, light_source, transfer_functions, num_samples):
    """
    Implements the standard Shading and Classification Volume Rendering Pipeline.
    
    Args:
        voxel_grid: 3D array of scalar values f0(xi).
        camera: Camera object with position and projection matrix.
        light_source: 3D vector position of the light.
        transfer_functions: Object containing color and opacity mapping functions.
        num_samples: K, number of samples per ray.
        
    Returns:
        image_color: 2D array of RGB colors.
        image_opacity: 2D array of alpha values.
    """
    
    # Step 1: Data Preparation
    # Apply corrections (motion, grid orthogonality, etc.)
    prepared_values = prepare_data(voxel_grid)
    
    # Step 2 & 3: Shading and Classification (Pre-compute per voxel)
    # These can be done in parallel or sequentially as they are independent
    voxel_colors = compute_shading(prepared_values, light_source, camera)
    voxel_opacities = compute_classification(prepared_values, transfer_functions)
    
    # Step 4: Gradient Computation (for shading)
    # Gradients are computed inside compute_shading if needed for Phong shading
    # gradient = compute_gradient(prepared_values)
    
    # Initialize output buffers
    height, width = get_image_dimensions(camera)
    image_color = np.zeros((height, width, 3))
    image_opacity = np.zeros((height, width))
    
    # Background color (fully opaque)
    bg_color = np.array([0.0, 0.0, 0.0]) # Or specific background color
    bg_opacity = 1.0
    
    # Step 5 & 6: Ray Casting and Compositing
    for y in range(height):
        for x in range(width):
            # Get ray for this pixel
            ray_origin, ray_direction = get_ray_from_pixel(camera, x, y)
            
            # Initialize compositing variables
            # Cin is the color entering the volume from the back
            current_color = bg_color
            current_opacity = bg_opacity
            
            # Sample along the ray
            for k in range(num_samples):
                # Calculate sample position along the ray
                # Assuming ray parameter t goes from 0 (near) to 1 (far)
                # We need to map k to t. Typically t = k / (K-1) or similar
                # depending on how the ray is parameterized relative to the volume bounds.
                # For back-to-front, we iterate from far to near.
                t_far = 1.0
                t_near = 0.0
                t = t_far - (k / (num_samples - 1)) * (t_far - t_near)
                
                sample_pos = ray_origin + ray_direction * t
                
                # Check if sample is inside volume bounds
                if not is_inside_volume(sample_pos):
                    continue
                
                # Step 5: Resampling (Tri-linear Interpolation)
                # Get colors and opacities from the 8 closest voxels
                sample_color = tri_linear_interpolate(voxel_colors, sample_pos)
                sample_alpha = tri_linear_interpolate(voxel_opacities, sample_pos)
                
                # Step 6: Compositing (Back-to-Front)
                # Cout = Cin * (1 - alpha) + c * alpha
                # Note: current_color represents Cin for the next step
                # We update current_color to be the output of this step
                
                # Standard front-to-back compositing is more common for accumulation,
                # but the source specifies back-to-front with a background.
                # Back-to-front means we start from the back of the volume and move forward.
                # If t=1 is back and t=0 is front, we iterate k from 0 to K-1 (t from 1 to 0).
                
                # Update color and opacity
                # The source formula: Cout = Cin(1 - alpha) + c * alpha
                # This assumes Cin is the accumulated color from behind the current sample.
                
                new_color = current_color * (1 - sample_alpha) + sample_color * sample_alpha
                new_opacity = current_opacity * (1 - sample_alpha) + sample_alpha
                
                current_color = new_color
                current_opacity = new_opacity
                
                # Optimization: If opacity is 1.0, we can stop early
                if current_opacity >= 1.0:
                    break
            
            image_color[y, x] = current_color
            image_opacity[y, x] = current_opacity
            
    return image_color, image_opacity

## Subtopics

### [Post-classification Shading Pipeline](7545-post-classification-shading-pipeline.md)
The Post-classification Shading Pipeline is a volume rendering model where raw volume values are interpolated by the rays first, and the interpolation result is then mapped to color and opacity via transfer functions. Unlike the Pre-classification Shading Pipeline, which classifies discrete grid samples before interpolation, this approach interpolates raw density values first, allowing fine detail in transfer functions to be readily expressed in the final image. It is distinct from pre-classification primarily in its handling of partial voluming and its susceptibility to false colors rather than blurring.

### Two-stage Rendering Pipeline for Non-Clipped Structures
A pipeline split into two parallel stages to render important pathological structures with different parameters even if they lie in a clipping area, while rendering anatomical structures normally [S7]. Stage 1 renders anatomical structures that are not clipped away using standard volume rendering steps. Stage 2 renders important structures (e.g., vessels, pathological tissue) that are excluded from clipping, using specific rendering parameters (gradient computation, classification, lighting) [S7].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of pixels and the number of samples per ray ($O(W \cdot H \cdot K)$), where $W, H$ are image dimensions and $K$ is the number of samples [S2, unofficial][S3, unofficial].
*   **Memory Complexity:** Linear with respect to the volume size ($O(N)$) to store the voxel grid and pre-computed color/opacity arrays [S2, unofficial][S3, unofficial].
*   **Performance:** Shading and interpolation are computationally expensive [S6]. Performance can be improved by switching off shading or interpolation, but at the cost of visual quality [S6].
*   **Strengths:** Independent control of shading and classification allows for flexible visualization of 3D shape and internal features [S2, unofficial].
*   **Limitations:** Global rendering parameters can obscure important structures in clipped regions [S7]. High computational cost for real-time interaction without optimization [S6].

## Background
The volume rendering pipeline was introduced by Marc Levoy in his 1988 paper "Display of Surfaces from Volume Data" [S2, unofficial][S3, unofficial]. It was presented at the SPIE Medical Imaging II conference in January 1988 [S3, unofficial]. The pipeline is based on the concept of treating volume samples as reflective, light-emitting, semi-transparent clouds (CRIO: Classification, Reflection, Illumination, Opacity) [S4, unofficial]. It has become a standard approach in direct volume rendering, widely used in medical imaging and scientific visualization [S1, unofficial][S6].
