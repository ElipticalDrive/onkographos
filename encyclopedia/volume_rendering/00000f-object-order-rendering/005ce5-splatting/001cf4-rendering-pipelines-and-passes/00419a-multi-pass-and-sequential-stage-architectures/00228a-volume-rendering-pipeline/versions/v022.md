# Volume Rendering Pipeline

Also called: CRIO Process, Classification, Reflection, Illumination, Opacity, Rendering Stages, Direct Volume Rendering (DVR) Pipeline, Shading and Classification Pipeline, VolumeRenderer forward method

## Overview
The Volume Rendering Pipeline is a conceptual and implementation structure for Direct Volume Rendering (DVR) that processes volumetric data through a sequence of stages to produce a 2D image [S1, unofficial][S2, unofficial][S3, unofficial]. It solves the problem of visualizing 3D scalar fields by mapping sample properties to optical attributes (color, opacity) and compositing them along viewing rays [S4, unofficial][S6]. It is distinct from splatting methods, which decompose the volume into geometric primitives for rasterization, by treating each sample as a semi-transparent cloud that is shaded and projected directly without intermediate geometric fitting [S2, unofficial].

## How it works
The pipeline typically consists of six sequential stages: Data Traversal, Interpolation, Gradient Computation, Classification, Shading/Illumination, and Compositing [S1, unofficial].

### Inputs and Outputs
*   **Input:** A 3D scalar field $f_0(\mathbf{x}_i)$ defined at voxel locations $\mathbf{x}_i = (x_i, y_j, z_k)$ [S3, unofficial].
*   **Output:** A 2D image where each pixel $(u,v)$ has a final color $C_\lambda(u,v)$ and opacity $\alpha(u,v)$ [S3, unofficial].

### Data Structures
*   **Voxel Database:** An array of scalar values. In some implementations (e.g., DVR 1.0), this is stored in a simple binary format with width, height, and depth specified first, followed by 16-bit little-endian data values [S6].
*   **Prepared Values Array:** An intermediate array $f_1(\mathbf{x}_i)$ resulting from data preparation steps [S3, unofficial].
*   **Color Array:** An array of RGB colors $c_\lambda(\mathbf{x}_i)$ for each voxel, where $\lambda \in \{r, g, b\}$ [S3, unofficial].
*   **Opacity Array:** An array of scalar opacities $\alpha(\mathbf{x}_i)$ for each voxel [S3, unofficial].
*   **Ray Bundle:** A set of rays defined by origin and direction, often generated from camera parameters [S5, unofficial].

### Numbered Steps

1.  **Data Traversal and Preparation:**
    The pipeline begins by traversing the 3D scalar field [S1, unofficial]. This step may include corrections for non-orthogonal sampling grids, patient motion, contrast enhancement, or interpolation of additional samples [S3, unofficial]. The output is an array of prepared values $f_1(\mathbf{x}_i)$ [S3, unofficial].

2.  **Interpolation:**
    Since sampling positions along a ray usually do not coincide with voxel centers, values must be interpolated [S1, unofficial]. For ray-casting pipelines, this occurs during ray traversal [G]. For pre-classification pipelines, interpolation may occur on the voxel grid itself or during the ray casting phase [S1, unofficial][S3, unofficial].

3.  **Gradient Computation:**
    The gradient of the scalar field $\nabla f$ is computed at sample positions to provide visual cues for shading [S1, unofficial]. This is typically approximated using central differences [S1, unofficial]. The gradient vector serves as a surface normal for lighting calculations [S2, unofficial].

4.  **Classification:**
    A classification procedure maps the prepared values (or interpolated sample values) to optical properties [S2, unofficial]. Transfer functions are applied to assign an opacity $\alpha$ and potentially a color to each sample based on features like density or gradient magnitude [S4, unofficial]. Unwanted data values are faded out (opacity set to zero) [S6].

5.  **Shading and Illumination:**
    A shading model calculates the final color $c_\lambda$ for each sample [S3, unofficial]. This uses the assigned color, the position of the light source, and the view point [S6]. Models range from simple identity functions to directional lighting like Phong shading [S4, unofficial].

6.  **Compositing:**
    Rays are cast from the observer eyepoint through the volume [S3, unofficial]. For each ray, samples are taken at $K$ evenly spaced locations $\tilde{\mathbf{x}}_i$ along the ray [S3, unofficial]. The color and opacity at these locations are determined by resampling the pre-computed color and opacity arrays using trilinear interpolation from the eight closest voxels [S3, unofficial][S6]. These samples are composited back-to-front using the transparency formula to produce the final pixel color [S2, unofficial][S3, unofficial].

### Formulas

**Transparency Formula (Compositing):**
The color $C_{out, \lambda}$ of the ray leaving a sample is related to the color $C_{in, \lambda}$ entering the sample, the sample color $c_\lambda$, and opacity $\alpha$ by:
$$ C_{out, \lambda} = C_{in, \lambda}(1 - \alpha) + c_\lambda \alpha $$
This is applied recursively from back to front [S3, unofficial].

**Ray Sampling:**
Sample locations $\tilde{\mathbf{x}}_i$ along a ray are computed as:
$$ \tilde{\mathbf{x}}_i = \mathbf{x}_0 + i \frac{d}{K} $$
where $\mathbf{x}_0$ is the observer eyepoint, $d$ is the ray length through the volume, and $K$ is the number of evenly spaced sample locations [S3, unofficial].

**Trilinear Interpolation:**
The value $V$ at a sample location is interpolated from the eight surrounding voxels $V_{ijk}$ using weights $w_x, w_y, w_z$ derived from the fractional distance to the voxel corners [S3, unofficial][S6].

### Parameters
*   **K:** Number of evenly spaced sample locations along a viewing ray [S2, unofficial][S3, unofficial].
*   **Light Source Position:** Adjustable parameter for shading [S6].
*   **View Point:** Adjustable parameter for shading and ray origin [S6].
*   **Transfer Function Parameters:** Define the mapping from scalar values to color and opacity [S6].

### Edge Cases and Pitfalls
*   **Performance Cost:** Shading and trilinear interpolation between eight voxels are high-cost operations [S6]. In some implementations, these can be switched off to improve performance, potentially reducing visual quality [S6].
*   **Precision:** The input data format may require specific endianness (e.g., little-endian 16-bit) which must be handled correctly during loading [S6].
*   **Clipping:** Standard pipelines apply clipping globally [S7]. Specialized variants are needed to render important structures differently if they lie within a clipped area [S7].

### Pseudocode

```python
def volume_rendering_pipeline(volume_data, width, height, depth, ray_origin, ray_direction, num_samples, transfer_functions):
    """
    Implements the standard Direct Volume Rendering pipeline.
    
    Args:
        volume_data: 3D list of scalar values indexed as [x][y][z].
        width, height, depth: Dimensions of the volume.
        ray_origin: Tuple (ox, oy, oz) for the observer eyepoint.
        ray_direction: Tuple (dx, dy, dz) for the ray direction.
        num_samples: Integer K, number of samples per ray.
        transfer_functions: List of functions mapping scalar value to (color, opacity).
        
    Returns:
        image: 2D list of RGB colors.
        alpha_image: 2D list of opacities.
    """
    image = [[(0.0, 0.0, 0.0) for _ in range(width)] for _ in range(height)]
    alpha_image = [[0.0 for _ in range(width)] for _ in range(height)]
    
    # Pre-compute voxel colors and opacities (Pre-classification approach)
    voxel_colors = [[[None for _ in range(depth)] for _ in range(height)] for _ in range(width)]
    voxel_opacities = [[[0.0 for _ in range(depth)] for _ in range(height)] for _ in range(width)]
    
    for x in range(width):
        for y in range(height):
            for z in range(depth):
                val = volume_data[x][y][z]
                color, opacity = apply_transfer_function(val, transfer_functions)
                voxel_colors[x][y][z] = color
                voxel_opacities[x][y][z] = opacity

    for v in range(height):
        for u in range(width):
            ray_length = compute_ray_length(ray_origin, ray_direction, width, height, depth)
            step_size = ray_length / num_samples
            
            current_color = (0.0, 0.0, 0.0)
            current_opacity = 1.0
            
            # Traverse ray from back to front
            for k in range(num_samples, 0, -1):
                t = (k - 0.5) * step_size
                sample_pos = (ray_origin[0] + t * ray_direction[0],
                              ray_origin[1] + t * ray_direction[1],
                              ray_origin[2] + t * ray_direction[2])
                
                if not is_inside_volume(sample_pos, width, height, depth):
                    continue
                
                sample_color = trilinear_interpolate(voxel_colors, sample_pos)
                sample_opacity = trilinear_interpolate(voxel_opacities, sample_pos)
                
                current_color = (current_color[0] * (1 - sample_opacity) + sample_color[0] * sample_opacity,
                                 current_color[1] * (1 - sample_opacity) + sample_color[1] * sample_opacity,
                                 current_color[2] * (1 - sample_opacity) + sample_color[2] * sample_opacity)
                current_opacity = current_opacity * (1 - sample_opacity)
                
                if current_opacity >= 1.0:
                    break
            
            image[v][u] = current_color
            alpha_image[v][u] = 1.0 - current_opacity
            
    return image, alpha_image

def apply_transfer_function(value, transfer_functions):
    color = (0.0, 0.0, 0.0)
    opacity = 0.0
    for tf in transfer_functions:
        c, a = tf(value)
        opacity += a * (1 - opacity)
        color = (color[0] * (1 - a) + c[0] * a,
                 color[1] * (1 - a) + c[1] * a,
                 color[2] * (1 - a) + c[2] * a)
    return color, opacity

def is_inside_volume(point, width, height, depth):
    return 0 <= point[0] < width and 0 <= point[1] < height and 0 <= point[2] < depth

def trilinear_interpolate(data_array, point):
    x, y, z = point
    ix, iy, iz = int(x), int(y), int(z)
    fx, fy, fz = x - ix, y - iy, z - iz
    
    ix = max(0, min(ix, len(data_array) - 2))
    iy = max(0, min(iy, len(data_array[0]) - 2))
    iz = max(0, min(iz, len(data_array[0][0]) - 2))
    
    c000 = data_array[ix][iy][iz]
    c100 = data_array[ix+1][iy][iz]
    c010 = data_array[ix][iy+1][iz]
    c110 = data_array[ix+1][iy+1][iz]
    c001 = data_array[ix][iy][iz+1]
    c101 = data_array[ix+1][iy][iz+1]
    c011 = data_array[ix][iy+1][iz+1]
    c111 = data_array[ix+1][iy+1][iz+1]
    
    c00 = c000 * (1 - fx) + c100 * fx
    c01 = c010 * (1 - fx) + c110 * fx
    c10 = c001 * (1 - fx) + c101 * fx
    c11 = c011 * (1 - fx) + c111 * fx
    
    c0 = c00 * (1 - fy) + c01 * fy
    c1 = c10 * (1 - fy) + c11 * fy
    
    result = c0 * (1 - fz) + c1 * fz
    return result
```

## Subtopics

### [Post-classification Shading Pipeline](7545-post-classification-shading-pipeline.md)
The Post-classification Shading Pipeline (also known as Post-DVRI) is a volume rendering model where raw volume density values are interpolated by the ray first, and the resulting interpolated values are then mapped to color and opacity via transfer functions, followed by shading. This approach solves the blurring artifacts inherent in pre-classification methods by ensuring that high-frequency details in transfer functions are resolved after interpolation. It is distinct from the Pre-classification Shading Pipeline, which classifies discrete voxel values before interpolation, resulting in blurry edges and loss of fine detail under magnification.

### Two-stage Rendering Pipeline for Non-Clipped Structures
A pipeline split into two parallel stages to render important pathological structures with different parameters even if they lie in a clipping area, while rendering anatomical structures normally [S7]. Stage 1 renders anatomical structures that are not clipped away using standard volume rendering steps [S7]. Stage 2 renders important structures (e.g., vessels, pathological tissue) that are excluded from clipping, using specific rendering parameters (gradient computation, classification, lighting) [S7].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of pixels and the number of samples per ray ($O(W \cdot H \cdot K)$) [G]. Gradient computation and classification are typically $O(V)$ where $V$ is the volume size, if done pre-pass, or $O(W \cdot H \cdot K)$ if done per-sample [G].
*   **Memory Complexity:** $O(V)$ to store the volume data [G].
*   **Performance:** High computational cost due to shading and interpolation per sample [S6]. Performance can be improved by switching off shading/interpolation or using early ray termination [S6].
*   **Strengths:** High visual quality, ability to handle complex transfer functions, independence of shading and classification allows for undistorted visualization of 3D shape [S2, unofficial].
*   **Limitations:** Blurring in pre-classification methods; high cost of per-voxel shading and interpolation; global clipping limitations in standard pipelines [S2, unofficial][S6][S7].
*   **When to use:** When high-quality visualization of internal structures is required, and interactive frame rates are not the primary constraint, or when hardware acceleration is available [G].
*   **When not to use:** When real-time performance on low-end hardware is critical without optimization, or when the volume data is extremely large and memory bandwidth is a bottleneck [G].

## Background
The volume rendering pipeline was formalized in the late 1980s [S3, unofficial][S2, unofficial]. Key early work includes the presentation of the "Display of Surfaces from Volume Data" technique by Marc Levoy at the SPIE Medical Imaging II conference in January 1988 [S3, unofficial][S2, unofficial]. This work described the pipeline stages of classification, shading, and back-to-front compositing [S3, unofficial]. The term "CRIO" (Classification, Reflection, Illumination, Opacity) was used to describe the conceptual feed-forward process in splatting algorithms [S4, unofficial]. The pipeline structure is widely cited in volume rendering literature, such as Engel's survey [S1, unofficial].
