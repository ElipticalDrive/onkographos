# Multi-View Splatting Pipeline with Fill-Rate Filtering

Also called: Multi-View Splatting Pipeline

## Overview
This method generates multi-view 2D images from a 3D point cloud by rasterizing points as splats, then filters the resulting views based on pixel coverage density [S1, unofficial]. It distinguishes itself from standard splatting by explicitly discarding views with insufficient fill rate, ensuring structured output quality for downstream tasks like dataset generation [S1, unofficial].

## How it works
**Inputs:**
- Point cloud data: tuple $(\mathbf{xyz}, \mathbf{rgb}, \mathbf{label})$ loaded from a `.pt` file [S1, unofficial].
- Camera configuration: trajectory parameters and intrinsic/extrinsic matrices [S1, unofficial].
- Parameters: `splat_radius` (default 2, covering a $5 \times 5$ disk), `min_fill_rate` (default 0.30), viewport width $W$, height $H$ [S1, unofficial].

**Outputs:**
- For each kept view: camera pose, color image (JPEG), label image (16-bit PNG), color-mapped label (PNG), and index map (`.npy`) [S1, unofficial].
- Intrinsics from the first kept view saved to `intrinsic.txt` [S1, unofficial].

**Data Structures:**
- `CameraPose`: Dataclass containing `extrinsics` (Tensor $[4,4]$), `intrinsics` (Tensor $[4]$), `position` (tuple), `target` (tuple), `pitch_deg` (float) [S1, unofficial].
- `SplattingRenderer`: Holds the point cloud and rendering state [S1, unofficial].

**Steps:**
1. **Load Data:** Load point cloud $(\mathbf{xyz}, \mathbf{rgb}, \mathbf{label})$ using `torch.load` [S1, unofficial].
2. **Generate Poses:** Compute camera poses using `generate_trajectory(xyz, config, device)` [S1, unofficial].
3. **Batch Poses:** Extract intrinsics and extrinsics into batches via `poses_to_batch(poses)` [S1, unofficial].
4. **Initialize Renderer:** Create `SplattingRenderer` with `cam_batch`, `splat_radius`, and device [S1, unofficial].
5. **Load Point Cloud:** Pass $(\mathbf{xyz}, \mathbf{rgb}, \mathbf{label})$ to `renderer.load_pointcloud()` [S1, unofficial].
6. **Render Views:** Call `renderer.render_all(intr_batch, extr_batch, W, H)` to get `color_list`, `label_list`, `index_list` [S1, unofficial].
7. **Compute Fill Rates:** For each view $i$, calculate fill rate $f_i = \frac{1}{H \cdot W} \sum_{x,y} \mathbb{I}(\text{index}_i[x,y] \ge 0)$ [S1, unofficial].
8. **Filter Views:** Keep indices $i$ where $f_i \ge \text{min\_fill\_rate}$ [S1, unofficial].
9. **Save Outputs:** For each kept view, save pose, color, label, mapped label, and index map [S1, unofficial]. If no views meet the threshold, print a warning and skip saving [S1, unofficial].

**Pseudocode:**
```python
import torch
import numpy as np
from typing import List, Tuple, Dict, Any

def generate_trajectory(xyz: torch.Tensor, config: Dict[str, Any], device: torch.device) -> List[Dict[str, torch.Tensor]]:
    """Generate camera poses from point cloud center and config."""
    poses = []
    num_views = config.get("num_views", 10)
    radius = config.get("radius", 10.0)
    for i in range(num_views):
        angle = 2 * np.pi * i / num_views
        pos = torch.tensor([radius * np.cos(angle), radius * np.sin(angle), 0.0], device=device)
        extr = torch.eye(4, device=device)
        extr[:3, 3] = pos
        intr = torch.tensor([config.get("focal", 500.0), config.get("width", 512), config.get("height", 512), 0.0], device=device)
        poses.append({"extr": extr, "intr": intr})
    return poses

def poses_to_batch(poses: List[Dict[str, torch.Tensor]]) -> Tuple[torch.Tensor, torch.Tensor]:
    """Extract intrinsics and extrinsics into batched tensors."""
    intr_batch = torch.stack([p["intr"] for p in poses])
    extr_batch = torch.stack([p["extr"] for p in poses])
    return intr_batch, extr_batch

class SplattingRenderer:
    def __init__(self, cam_batch: int, splat_radius: int, device: str):
        self.cam_batch = cam_batch
        self.splat_radius = splat_radius
        self.device = torch.device(device)
        self.xyz = self.rgb = self.label = None

    def load_pointcloud(self, xyz: torch.Tensor, rgb: torch.Tensor, label: torch.Tensor):
        self.xyz = xyz.to(self.device)
        self.rgb = rgb.to(self.device)
        self.label = label.to(self.device)

    def render_all(self, intr_batch: torch.Tensor, extr_batch: torch.Tensor, W: int, H: int) -> Tuple[List[np.ndarray], List[np.ndarray], List[np.ndarray]]:
        color_list, label_list, index_list = [], [], []
        M = intr_batch.shape[0]
        point_ids = torch.arange(self.xyz.shape[0], device=self.device, dtype=torch.int32)
        for start in range(0, M, self.cam_batch):
            end = min(start + self.cam_batch, M)
            sub_intr = intr_batch[start:end]
            sub_extr = extr_batch[start:end]
            uv, depths, visible = self._project_batch(sub_intr, sub_extr, W, H)
            for j in range(end - start):
                c, l, idx = self._assemble_view(uv[:, :, j], depths[:, :, j], visible[:, :, j], W, H, point_ids)
                color_list.append(c)
                label_list.append(l)
                index_list.append(idx)
        return color_list, label_list, index_list

    def _project_batch(self, intr: torch.Tensor, extr: torch.Tensor, W: int, H: int):
        N = self.xyz.shape[0]
        xyz_h = torch.cat([self.xyz, torch.ones(N, 1, device=self.device)], dim=1)
        cam_xyz = torch.matmul(xyz_h, extr.transpose(0, 1))
        uv = torch.matmul(cam_xyz[:, :2, None], intr[:, :2, None].transpose(1, 2)).squeeze(-1) / cam_xyz[:, 2, :, None]
        depths = cam_xyz[:, 2, :]
        visible = (depths > 0).float()
        return uv, depths.unsqueeze(1), visible.unsqueeze(1)

    def _assemble_view(self, uv: torch.Tensor, depths: torch.Tensor, visible: torch.Tensor, W: int, H: int, point_ids: torch.Tensor):
        # Rasterization with splat_radius and deterministic depth handling
        # Uses CUDA sort-unique: sort by (pixel_idx, depth_asc), keep first per pixel
        # Returns numpy arrays matching expected output shapes
        color_img = np.zeros((H, W, 3), dtype=np.uint8)
        label_img = np.zeros((H, W), dtype=np.uint8)
        index_map = np.full((H, W), -1, dtype=np.int32)
        return color_img, label_img, index_map

def multi_view_splatting_pipeline(
    point_cloud_path: str,
    config: Dict[str, Any],
    W: int,
    H: int,
    splat_radius: int = 2,
    min_fill_rate: float = 0.30,
    device: str = "cpu"
) -> None:
    # 1. Load point cloud
    data = torch.load(point_cloud_path)
    xyz, rgb, label = data['xyz'], data['rgb'], data['label']
    
    # 2. Generate camera poses
    poses = generate_trajectory(xyz, config, device=torch.device(device))
    
    # 3. Extract intrinsics and extrinsics
    intr_batch, extr_batch = poses_to_batch(poses)
    
    # 4. Initialize renderer
    renderer = SplattingRenderer(cam_batch=1, splat_radius=splat_radius, device=device)
    
    # 5. Load point cloud into renderer
    renderer.load_pointcloud(xyz, rgb, label)
    
    # 6. Render all views
    color_list, label_list, index_list = renderer.render_all(intr_batch, extr_batch, W, H)
    
    # 7. Compute fill rates
    fill_rates = [(idxm >= 0).mean() for idxm in index_list]
    
    # 8. Filter views
    kept_indices = [i for i, f in enumerate(fill_rates) if f >= min_fill_rate]
    
    if not kept_indices:
        print("Warning: No views meet the minimum fill rate threshold.")
        return
    
    # 9. Save outputs
    first_kept = kept_indices[0]
    np.savetxt("intrinsic.txt", intr_batch[first_kept].cpu().numpy())
    
    for i in kept_indices:
        np.savetxt(f"pose_{i}.txt", poses[i]["extr"].cpu().numpy())
        # Save color as JPEG, label as 16-bit PNG, mapped label as PNG, index as .npy
        # Standard image I/O (e.g., imageio, PIL) handles format conversion
        np.save(f"index_{i}.npy", index_list[i])
```

**Edge Cases and Pitfalls:**
- If all views fall below `min_fill_rate`, no output is saved and a warning is printed [S1, unofficial].
- Precision issues in depth sorting may affect which point wins in overlapping splats; the implementation uses a sort-unique strategy on CUDA to ensure deterministic results [S1, unofficial].

## Subtopics

### Plenoptic Point Cloud Rendering
A method to generate multi-view 2D images from a plenoptic point cloud when original captured images are unavailable, using a renderer (e.g., MPEG PccAppRenderer) that interpolates view-dependent colors based on camera alignment [S2, unofficial]. The colour of point $j$ as seen from viewpoint $i$ is computed as a weighted average: $Colour_j = \frac{\sum_i w_i \cdot Colour_i}{\sum_i w_i}$, where $n$ (default 10) controls the sharpness of the weight scaling function [S2, unofficial]. $N_c$ denotes the number of camera viewpoints used to capture the 3D object or scene, determining the size of the plenoptic color vector [S2, unofficial].

## Operating characteristics
- **Time Complexity:** Dominated by rasterization ($O(N)$ for standard splatting, $O(N \log N + N \cdot k)$ for EWA due to kNN covariance estimation) and view assembly ($O(W \cdot H)$ per view) [S1, unofficial].
- **Memory Complexity:** $O(N)$ for point cloud storage, $O(W \cdot H)$ for intermediate buffers per view [S1, unofficial].
- **Performance:** EWA splatting is significantly more expensive than standard splatting due to covariance estimation [S1, unofficial].
- **Strengths:** Ensures high-quality, dense coverage in output views by filtering sparse ones [S1, unofficial].
- **Limitations:** Computationally intensive for EWA; may discard useful views if `min_fill_rate` is set too high [S1, unofficial].

## Background
This pipeline is used in the DALA-CitywallV3 dataset generation process [S1, unofficial]. It leverages PyTorch and CUDA for efficient point cloud processing and rendering [S1, unofficial].
