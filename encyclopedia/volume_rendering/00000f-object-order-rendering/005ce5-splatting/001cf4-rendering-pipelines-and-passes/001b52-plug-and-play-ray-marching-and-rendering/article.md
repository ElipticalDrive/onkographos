# Plug-and-Play Ray Marching and Rendering

Also called: Differentiable Volumetric Rendering Pipeline, nerfacc pipeline

## Overview
Plug-and-Play Ray Marching and Rendering is a modular pipeline interface that decouples the acceleration logic of ray marching and volumetric compositing from the specific radiance field representation [S1, unofficial]. It allows efficient, differentiable volumetric rendering to be integrated into any user-defined neural radiance field by implementing two query functions [S1, unofficial]. Unlike specialized implementations such as Instant-NGP which rely on custom CUDA kernels, this method provides a Python API built on PyTorch, prioritizing ease of extension for dynamic and unbounded scenes over raw kernel-level optimization [S1, unofficial].

## How it works
### Inputs and Outputs
*   **Inputs**: Ray origins $\mathbf{r}_o$ (tensor of shape $[N_{rays}, 3]$), ray directions $\mathbf{r}_d$ (tensor of shape $[N_{rays}, 3]$), and a user-defined radiance field model [S1, unofficial].
*   **Outputs**: Rendered color $\mathbf{C}(\mathbf{r})$ (shape $[N_{rays}, 3]$), opacity $\alpha$ (shape $[N_{rays}, 1]$), and depth $D$ (shape $[N_{rays}, 1]$) [S1, unofficial].

### Data Structures
The pipeline relies on PyTorch tensors [S1, unofficial]. The core intermediate data structures generated by the ray marching step are:
1.  `packed_info`: A tensor containing metadata about the valid samples (e.g., ray indices, sample indices) required for efficient indexing during rendering [S1, unofficial].
2.  `t_starts`: A tensor of shape $[N_{samples}, 1]$ containing the start distance of each sample interval along the ray [S1, unofficial].
3.  `t_ends`: A tensor of shape $[N_{samples}, 1]$ containing the end distance of each sample interval along the ray [S1, unofficial].

### Numbered Steps
1.  Define `sigma_fn(t_starts, t_ends, ray_indices)` to query density values from the radiance field [S1, unofficial].
2.  Define `rgb_sigma_fn(t_starts, t_ends, ray_indices)` to query both RGB and density values [S1, unofficial].
3.  Call `nerfacc.ray_marching(rays_o, rays_d, sigma_fn, near_plane, far_plane, early_stop_eps, alpha_thre)` to compute `packed_info`, `t_starts`, and `t_ends` for valid samples, skipping empty or occluded regions [S1, unofficial].
4.  Call `nerfacc.rendering(rgb_sigma_fn, packed_info, t_starts, t_ends)` to accumulate color, opacity, and depth [S1, unofficial].
5.  Compute the loss against ground truth and backpropagate through the differentiable pipeline [S1, unofficial].

### Formulas
The volumetric rendering equation used for accumulation is:
$$ \mathbf{C}(\mathbf{r}) = \sum_{i=1}^N T_i \alpha_i \mathbf{c}_i $$
where:
*   $\mathbf{c}_i$ is the color of the $i$-th sample [S1, unofficial].
*   $\alpha_i = 1 - \exp(\sigma_i \delta_i)$ is the opacity of the $i$-th sample [S1, unofficial].
*   $\sigma_i$ is the volume density (sigma) of the $i$-th sample [S1, unofficial].
*   $\delta_i = t_{ends,i} - t_{starts,i}$ is the distance between sample boundaries [S1, unofficial].
*   $T_i = \exp\left(-\sum_{j=1}^{i-1} \sigma_j \delta_j\right)$ is the accumulated transmittance up to the $i$-th sample [S1, unofficial].

### Parameters
*   `near_plane`: The starting distance for ray marching. Typical value: $0.2$ [S1, unofficial].
*   `far_plane`: The ending distance for ray marching. Typical value: $1.0$ [S1, unofficial].
*   `early_stop_eps`: Threshold for early stopping based on transmittance. Typical value: $10^{-4}$ [S1, unofficial].
*   `alpha_thre`: Threshold for skipping samples with low opacity. Typical value: $10^{-2}$ [S1, unofficial].

### Edge Cases and Pitfalls
*   **Empty/Occluded Regions**: The pipeline skips samples in empty or occluded regions based on `early_stop_eps` and `alpha_thre` to optimize GPU utilization [S1, unofficial].
*   **Gradient Flow**: The entire pipeline is differentiable, requiring the user-defined radiance field to support gradient computation through its density and RGB queries [S1, unofficial].
*   **Tensor Shapes**: The `sigma_fn` and `rgb_sigma_fn` must return tensors with the exact shapes specified (e.g., `sigmas` as `(n_samples, 1)` and `rgbs` as `(n_samples, 3)`) to match the accumulation logic [S1, unofficial].

### Pseudocode
The following Python-like pseudocode demonstrates the complete pipeline [S1, unofficial]. It assumes `nerfacc` is the acceleration library and `radiance_field` is the user-defined model.

> **Unverified code.** The code below did not pass a test run against a reference implementation, or no test fits it, so it may contain errors.

```python
import torch
from torch import Tensor
from typing import Tuple
import nerfacc

# User-provided inputs
radiance_field = None  # User-defined neural radiance field model
optimizer = None       # PyTorch optimizer
rays_o: Tensor = None  # Ray origins, shape (n_rays, 3)
rays_d: Tensor = None  # Ray normalized directions, shape (n_rays, 3)
gt_color: Tensor = None # Ground truth color, shape (n_rays, 3)

# 1. Define the density query function
def sigma_fn(t_starts: Tensor, t_ends: Tensor, ray_indices: Tensor) -> Tensor:
    """Query density values from the radiance field."""
    t_origins = rays_o[ray_indices] # Shape (n_samples, 3)
    t_dirs = rays_d[ray_indices]    # Shape (n_samples, 3)
    positions = t_origins + t_dirs * (t_starts + t_ends) / 2.0
    sigmas = radiance_field.query_density(positions)
    return sigmas # Shape (n_samples, 1)

# 2. Define the RGB and density query function
def rgb_sigma_fn(t_starts: Tensor, t_ends: Tensor, ray_indices: Tensor) -> Tuple[Tensor, Tensor]:
    """Query RGB colors and density values from the radiance field."""
    t_origins = rays_o[ray_indices]
    t_dirs = rays_d[ray_indices]
    positions = t_origins + t_dirs * (t_starts + t_ends) / 2.0
    rgbs, sigmas = radiance_field(positions, condition=t_dirs)
    return rgbs, sigmas # Shape (n_samples, 3), (n_samples, 1)

# 3. Efficient Ray Marching
packed_info, t_starts, t_ends = nerfacc.ray_marching(
    rays_o=rays_o,
    rays_d=rays_d,
    sigma_fn=sigma_fn,
    near_plane=0.2,
    far_plane=1.0,
    early_stop_eps=1e-4,
    alpha_thre=1e-2
)

# 4. Differentiable Volumetric Rendering
color, opacity, depth = nerfacc.rendering(
    rgb_sigma_fn=rgb_sigma_fn,
    packed_info=packed_info,
    t_starts=t_starts,
    t_ends=t_ends
)

# 5. Optimization Step
optimizer.zero_grad()
loss = torch.nn.functional.mse_loss(color, gt_color)
loss.backward()
optimizer.step()
```

## Subtopics

### Dynamic Scene Support
*   **What it is**: The ability to render scenes where the radiance field changes over time (e.g., animated characters, moving objects) [S1, unofficial].
*   **What sets it apart**: Unlike static NeRF implementations that cache grid structures for fixed scenes, this pipeline supports time-dependent radiance fields by allowing the query functions to accept time as an additional condition [G].
*   **When to choose**: Use when rendering animated 3D content or video sequences where the geometry or appearance evolves [G].
*   **Link**: [Dynamic Neural Radiance Fields](dynamic-nerf.md)

### Unbounded Scene Rendering
*   **What it is**: Rendering scenes that extend to infinity, without a predefined bounding box [S1, unofficial].
*   **What sets it apart**: Standard splatting methods often require a fixed bounding volume, whereas this pipeline handles unbounded scenes by using ray marching with configurable `near_plane` and `far_plane` and pruning logic that adapts to the scene's depth distribution [G].
*   **When to choose**: Use for outdoor scenes, large-scale environments, or any scenario where the camera can move freely without hitting a hard boundary [G].
*   **Link**: [Unbounded NeRF Rendering](unbounded-nerf.md)

## Operating characteristics
*   **Time Complexity**: Not given in the sources. The pipeline scales linearly with the number of valid samples after pruning [S1, unofficial].
*   **Memory Complexity**: Not given in the sources. Memory usage is proportional to the number of valid samples and the size of the radiance field model [S1, unofficial].
*   **Measured Performance**: On a single NVIDIA TITAN RTX GPU, training a vanilla 8-layer MLP NeRF takes approximately 1 hour, compared to 1-2 days in the original paper [S1, unofficial]. Instant-NGP models can be trained to equal quality in 4.5 minutes using the Python API, compared to the official CUDA implementation [S1, unofficial].
*   **Strengths**: High ease of use due to Python/PyTorch API; flexible integration with various radiance field architectures; supports dynamic and unbounded scenes out of the box [S1, unofficial].
*   **Limitations**: May be slower than highly optimized, scene-specific CUDA kernels (like Instant-NGP's native implementation) due to Python overhead and general tensor operations [S1, unofficial].
*   **When to use**: When rapid prototyping, extending existing NeRF methods, or supporting dynamic/unbounded scenes is prioritized over maximum raw rendering speed [S1, unofficial].
*   **When not**: When deploying to resource-constrained hardware requiring minimal latency and maximum throughput, where custom CUDA kernels are preferred [G].

## Background
The Plug-and-Play Ray Marching and Rendering pipeline was introduced in the NerfAcc toolbox, a general acceleration library for Neural Radiance Fields (NeRFs) [S1, unofficial]. It builds upon techniques from Instant-NGP but extends them to support dynamic and unbounded scenes [S1, unofficial]. The library was released as a preprint in 2022, aiming to provide a user-friendly Python API that accelerates most NeRF methods without requiring low-level CUDA programming [S1, unofficial].
