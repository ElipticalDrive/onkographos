# Ray-Centric and Hardware-Accelerated Rendering
## Overview
Ray-centric rendering computes pixel color by tracing rays from the camera through volumetric data and accumulating density and color along the path, typically executed on the GPU for performance [S1, unofficial][S2]. It differs from splatting by processing samples per-ray rather than per-primitive, avoiding sorting overheads for dense volumes, though it is computationally heavier per pixel [G]. It preserves internal volume information, unlike isosurface extraction methods such as [Marching Cubes](53-marching-cubes.md) [S1, unofficial].

## Shared principles
The family traces rays from the camera through volumetric data to compute pixel color and opacity [S1, unofficial][S2]. Rays are marched through the volume using step-based sampling or acceleration structures, with contributions accumulated along the ray path [S1, unofficial][S2]. GPU hardware acceleration is used for parallel execution [S1, unofficial][S2].

```python
import torch
import math

def batchify_rays(rays_flat, chunk=32768, **kwargs):
    """
    Renders rays in smaller mini-batches to avoid OOM.
    
    Args:
        rays_flat: Tensor of shape (B, 11).
        chunk: Size of mini-batches.
        **kwargs: Arguments passed to render_rays.
        
    Returns:
        Dictionary of output tensors with shape (B, ...).
    """
    all_ret = {}
    num_rays = rays_flat.shape[0]
    
    # Iterate through rays in chunks
    for i in range(0, num_rays, chunk):
        # Extract chunk
        ray_batch = rays_flat[i : i + chunk]
        
        # Render the chunk
        ret = render_rays(ray_batch, **kwargs)
        
        # Accumulate results
        for k in ret:
            if k not in all_ret:
                all_ret[k] = []
            all_ret[k].append(ret[k])
            
    # Concatenate results along the batch dimension (dim 0)
    for k in all_ret:
        all_ret[k] = torch.cat(all_ret[k], dim=0)
        
    return all_ret

def render_rays(ray_batch,
                network_fn,
                network_query_fn,
                N_samples=64,
                retraw=False,
                lindisp=False,
                perturb=0.0,
                N_importance=0,
                network_fine=None,
                white_bkgd=False,
                raw_noise_std=0.0,
                verbose=False,
                pytest=False):
    """
    Renders a single batch of rays.
    
    Args:
        ray_batch: Tensor of shape (N_rays, 11).
        network_fn: Coarse network function.
        network_query_fn: Function to query network with pts and viewdirs.
        N_samples: Number of coarse samples.
        lindisp: Use disparity sampling.
        perturb: Noise for stratified sampling.
        N_importance: Number of fine samples.
        network_fine: Fine network function.
        ... other args ...
        
    Returns:
        Dictionary with keys: rgb_map, disp_map, acc_map, etc.
    """
    N_rays = ray_batch.shape[0]
    
    # Unpack ray parameters
    rays_o = ray_batch[:, 0:3]      # (N_rays, 3)
    rays_d = ray_batch[:, 3:6]      # (N_rays, 3)
    
    # Viewdirs are the last 3 components if present
    viewdirs = ray_batch[:, -3:] if ray_batch.shape[-1] > 8 else None
    
    # Bounds
    bounds = torch.reshape(ray_batch[..., 6:8], [-1, 1, 2])
    near = bounds[..., 0]  # (N_rays, 1)
    far = bounds[..., 1]   # (N_rays, 1)
    
    # Generate t_vals
    t_vals = torch.linspace(0., 1., steps=N_samples, device=ray_batch.device)
    
    # Compute z_vals (sample depths)
    if not lindisp:
        z_vals = near * (1. - t_vals) + far * t_vals
    else:
        z_vals = 1. / (1./near * (1. - t_vals) + 1./far * t_vals)
        
    # Expand z_vals to [N_rays, N_samples]
    z_vals = z_vals.expand([N_rays, N_samples])
    
    # Stratified sampling
    if perturb > 0.:
        mids = .5 * (z_vals[..., 1:] + z_vals[..., :-1])
        upper = torch.cat([mids, z_vals[..., -1:]], -1)
        lower = torch.cat([z_vals[..., :1], mids], -1)
        t_rand = torch.rand(z_vals.shape, device=ray_batch.device)
        
        # Pytest override for deterministic results
        if pytest:
            torch.manual_seed(0)
            t_rand = torch.rand(z_vals.shape, device=ray_batch.device)
            
        z_vals = lower + (upper - lower) * t_rand
        
    # Compute 3D points
    # pts shape: (N_rays, N_samples, 3)
    pts = rays_o[..., None, :] + rays_d[..., None, :] * z_vals[..., :, None]
    
    # Query network
    raw = network_query_fn(pts, viewdirs, network_fn)
    
    # Process raw output to get rgb, weights, etc.
    # Note: raw2outputs is a helper function defined in the NeRF source code
    # that implements the alpha compositing formula.
    rgb_map, disp_map, acc_map, weights, depth_map = raw2outputs(
        raw, z_vals, rays_d, raw_noise_std, white_bkgd, pytest=pytest
    )
    
    # Hierarchical sampling
    if N_importance > 0:
        # Store coarse outputs
        rgb_map_0, disp_map_0, acc_map_0 = rgb_map, disp_map, acc_map
        
        # Calculate midpoints of coarse samples
        z_vals_mid = .5 * (z_vals[..., 1:] + z_vals[..., :-1])
        
        # Sample fine depths based on weights
        # sample_pdf is a helper function for inverse CDF sampling
        z_samples = sample_pdf(z_vals_mid, weights[..., 1:-1], N_importance, 
                               det=(perturb==0.), pytest=pytest)
        
        # Detach to break gradient flow from fine to coarse
        z_samples = z_samples.detach()
        
        # Concatenate and sort
        z_vals, _ = torch.sort(torch.cat([z_vals, z_samples], -1), -1)
        
        # Recompute points
        pts = rays_o[..., None, :] + rays_d[..., None, :] * z_vals[..., :, None]
        
        # Query fine network
        run_fn = network_fn if network_fine is None else network_fine
        raw = network_query_fn(pts, viewdirs, run_fn)
        
        # Process fine output
        rgb_map, disp_map, acc_map, weights, depth_map = raw2outputs(
            raw, z_vals, rays_d, raw_noise_std, white_bkgd, pytest=pytest
        )
        
    ret = {'rgb_map': rgb_map, 'disp_map': disp_map, 'acc_map': acc_map}
    
    if retraw:
        ret['raw'] = raw
        
    if N_importance > 0:
        ret['rgb_map_0'] = rgb_map_0
        ret['disp_map_0'] = disp_map_0
        ret['acc_map_0'] = acc_map_0
        
    return ret

def raw2outputs(raw, z_vals, rays_d, raw_noise_std=0.0, white_bkgd=False, pytest=False):
    """
    Converts raw network output (rgb, sigma) to final image components.
    Implements volume rendering equation. [G]
    """
    # raw shape: (N_rays, N_samples, 4) -> (rgb, sigma)
    rgb = raw[..., :3]
    sigma = raw[..., 3:4]
    
    # Add noise to sigma
    noise = 0.
    if sigma.shape[-1] > 0:
        noise = torch.randn(sigma.shape, device=raw.device) * raw_noise_std
    sigma = sigma + noise
    
    # Compute delta (distance between samples)
    deltas = z_vals[..., 1:] - z_vals[..., :-1]
    # Approximate last delta to avoid boundary issues
    deltas = torch.cat([deltas, torch.ones_like(deltas[..., :1]) * 1e10], dim=-1)
    
    # Compute alpha
    alpha = 1.0 - torch.exp(-torch.relu(sigma) * deltas)
    
    # Transmittance
    T = torch.cumsum(1. - alpha, dim=-1)
    T = torch.cat([torch.ones_like(T[..., :1]), T[..., :-1]], dim=-1)
    
    # Weights
    weights = alpha * T
    
    # Compositing
    rgb_map = torch.sum(weights[..., None] * rgb, dim=-2)
    acc_map = torch.sum(weights, dim=-1)
    depth_map = torch.sum(weights * z_vals, dim=-1) / (acc_map + 1e-10)
    disp_map = 1. / (depth_map + 1e-10)
    
    return rgb_map, disp_map, acc_map, weights, depth_map

def sample_pdf(z_vals_mid, weights, N_importance, det=False, pytest=False):
    """
    Hierarchical sampling: sample N_importance points from the distribution defined by weights. [G]
    """
    # weights shape: (N_rays, N_samples-1)
    # z_vals_mid shape: (N_rays, N_samples-1)
    
    # Get pdf
    pdf = weights / (weights.sum(dim=-1, keepdim=True) + 1e-10)
    cdf = torch.cumsum(pdf, dim=-1)
    cdf = torch.cat([torch.zeros_like(cdf[..., :1]), cdf], dim=-1)
    
    # Uniform samples
    if det:
        u = torch.linspace(0., 1., N_importance, device=weights.device)
        u = u.expand([weights.shape[0], N_importance])
    else:
        u = torch.rand([weights.shape[0], N_importance], device=weights.device)
        
    # Inverse CDF
    indices = torch.searchsorted(cdf, u, right=True)
    indices = torch.clamp(indices, 0, cdf.shape[-1] - 2)
    
    # Linear interpolation within bins
    z0 = z_vals_mid[torch.arange(weights.shape[0]), indices]
    z1 = z_vals_mid[torch.arange(weights.shape[0]), indices + 1]
    c0 = cdf[torch.arange(weights.shape[0]), indices]
    c1 = cdf[torch.arange(weights.shape[0]), indices + 1]
    
    # Avoid division by zero
    denom = c1 - c0
    denom = torch.where(denom < 1e-10, torch.ones_like(denom), denom)
    
    t = (u - c0) / denom
    z_samples = z0 + t * (z1 - z0)
    
    return z_samples
```

## Subtopics

### [Batched Ray Rendering](1547-batched-ray-rendering.md)
Batched Ray Rendering is a memory-management strategy for object-order volume rendering that processes large batches of rays in smaller, fixed-size chunks to prevent Out-Of-Memory (OOM) errors on the GPU. It builds on [Ray-Centric and Hardware-Accelerated Rendering](8936-ray-centric-and-hardware-accelerated-rendering.md) by explicitly managing the batch size relative to available VRAM, and differs from [Chunked Trilinear Volume Rendering](2557-chunked-trilinear-volume-rendering.md) by chunking the *rays* (the query set) rather than the *volume data* (the lookup grid). See [Batched Ray Rendering](1547-batched-ray-rendering.md).

### [GPU Implementation Pipeline](2385-gpu-implementation-pipeline.md)
A GPU-accelerated rendering technique that traces rays from the camera through each pixel into a 3D volume to compute color and opacity, implemented in a single pass using fragment shaders. It solves the problem of visualizing volumetric data directly on the GPU without generating intermediate polygonal meshes. It differs from isosurface extraction (e.g., [Marching Cubes](53-marching-cubes.md)) by preserving internal volume information, and from splatting ([Splatting](10-splatting.md)) by avoiding sorting and blending overheads for dense volumes, though it is computationally heavier per pixel than texture-based splatting [G]. See [GPU Implementation Pipeline](2385-gpu-implementation-pipeline.md).

### OptiX Volume Rendering Pipeline
- [S1, unofficial] A volume rendering method implemented using NVIDIA OptiX. It uses a Ray Generation shader, Miss shaders for radiance and shadow, and Hit/Any-Hit/Intersection shaders for volume traversal and shading.
- [S1, unofficial] Initialize shaders: Set `shader_raygen` to `__raygen__default`. Add miss shaders `__miss__radiance` and `__miss__shadow`.
- [S1, unofficial] Configure volume object group: Set `group.type = VOLUME_STRUCTURED_REGULAR`. Assign hit group shaders: Closest Hit `__closesthit__volume_radiance` and `__closesthit__volume_shadow`, Any Hit `__anyhit__volume_radiance` and `__anyhit__volume_shadow`, and Intersection `__intersection__volume`.
- [S1, unofficial] Shader assignments: Ray Gen: `__raygen__default`. Miss: `__miss__radiance`, `__miss__shadow`. Volume Closest Hit: `__closesthit__volume_radiance`, `__closesthit__volume_shadow`. Volume Any Hit: `__anyhit__volume_radiance`, `__anyhit__volume_shadow`. Volume Intersection: `__intersection__volume`.

### Hybrid Splatting/Tracing Rendering
- [S2] A rendering pipeline that rasterizes primary rays for speed and traces secondary rays for lighting effects (reflections/refractions) within the same 3D representation.
- [S2] Compute all primary ray intersections with the scene.
- [S2] Render these primary rays using rasterization (splatting).
- [S2] Discard Gaussian hits that fall behind a ray's closest intersection.
- [S2] Compute and trace secondary rays using 3DGRT.

## Background
Ray casting and marching are standard techniques for high-quality volume visualization, leveraging the parallel nature of GPU fragment shaders for per-pixel ray marching [G]. The specific GPU implementation pipeline utilizes a slab method for AABB intersection and front-to-back compositing within a single fragment shader pass [S2]. The integration of ray tracing APIs like NVIDIA OptiX [S1, unofficial] allows for more complex traversal and shading models, while recent hybrid approaches [S2] combine the speed of rasterization for primary rays with the accuracy of ray tracing for secondary effects like reflections.
