# Hybrid Splatting/Raycasting with Smooth Transition
Also called: Smooth Transition
## Overview
This method renders volumetric datasets as a collection of overlapping 3D detailed kernels, combining GPU-accelerated splatting for coarse structure with raycasting for local detail [S1, unofficial]. It addresses the trade-off between splatting speed and raycasting accuracy by employing a hierarchical representation where each node stores a 3D texture [S1, unofficial]. Unlike pure splatting, it enhances each footprint with raycasted details along the kernel's extent, and unlike pure raycasting, it batches these operations per fragment [S1, unofficial].
## How it works
**Inputs:** A volumetric dataset organized hierarchically; a selected octree node representing a region; screen coordinates $(x, y)$ for fragments generated from kernel projections [S1, unofficial].
**Outputs:** Final color and opacity values for each pixel [S1, unofficial].

**Data Structures:**
1. **Hierarchical Representation:** An octree where each node represents a coarse region of the dataset [S1, unofficial].
2. **3D Texture:** Attached to each octree node, storing resampled data for rendering that region [S1, unofficial].
3. **Gaussian Kernel ($G_i$):** A truncated radially symmetric Gaussian function associated with each sample point [S1, unofficial].
4. **Bounding Sphere ($B_i$):** The bounding box of the truncated Gaussian kernel, treated as a sphere centered at the original sample point [S1, unofficial].
5. **2D Lookup Table:** Pre-computed via a classical pre-integrated classification scheme, storing color and opacity values [S1, unofficial].

**Parameters:**
* **Resampling Rate:** Defines the density of sample points/kernels and is a key control feature [S1, unofficial].
* **3D Texture Resolution:** Defines the detail level stored in the GPU texture and is a key control feature [S1, unofficial].
* **Segment Length ($l$):** Derived from the 3D texture resolution and the extent of the truncated kernel $G_i$ [S1, unofficial].

**Steps:**
1. **Selection:** At runtime, select a subpart of the hierarchical representation (an octree node) to render [S1, unofficial].
2. **Splatting Projection:** Project the Gaussian kernel $G_i$ associated with the selected node onto the screen to generate footprints $F_i$ [S1, unofficial].
3. **Fragment Processing:** For each fragment $f_{i,x,y}$ at screen coordinates $(x, y)$ within a footprint $F_i$:
   a. **Ray Casting:** Cast a ray through the fragment into the volume [S1, unofficial].
   b. **Intersection:** Determine the intersection of this ray with the bounding sphere $B_i$ of the kernel $G_i$, yielding two points $p_a$ and $p_b$ [S1, unofficial]. In extreme cases, $p_a = p_b$ [S1, unofficial].
   c. **Segment Division:** Divide the segment $p_a p_b$ into $n$ equal sections of length $l$ [S1, unofficial]. The step size is derived from the 3D texture resolution and the kernel extent [S1, unofficial].
   d. **Lookup:** For each segment, perform a lookup into the 2D pre-integrated classification table to obtain a base color and opacity value [S1, unofficial].
   e. **Weighting:** Weight the result of the 2D lookup with the segment length $l$ to handle varying segment sizes [S1, unofficial]. This uses the approximation scheme from Roettger et al. (2000) [S1, unofficial].
   f. **Composition:** Accumulate the weighted color and opacity values from all segments along the ray to enhance the appearance of the fragment [S1, unofficial].
4. **Final Image:** Compose the enhanced footprints to yield the final image [S1, unofficial].

**Pseudocode:**
```python
def render_hybrid_kernel(kernel_node, screen_fragments):
    """Renders a single kernel node using hybrid splatting/raycasting."""
    G = kernel_node.gaussian_kernel
    B = kernel_node.bounding_sphere
    texture_3d = kernel_node.texture_3d
    lookup_table = kernel_node.preintegrated_table
    # Not given in the sources: specific formula for deriving l from resolution/extent
    l = 1.0  # Placeholder value; replace with actual derivation when formula is known
    results = {}
    for fragment in screen_fragments:
        x, y = fragment.coords
        ray_origin, ray_direction = fragment.get_ray()
        # Standard sphere intersection: solve |O + tD - C|^2 = R^2
        oc = ray_origin - B.center
        a = dot(ray_direction, ray_direction)
        b = 2.0 * dot(oc, ray_direction)
        c = dot(oc, oc) - B.radius * B.radius
        discriminant = b * b - 4.0 * a * c
        if discriminant < 0:
            results[fragment] = (0.0, 0.0)
            continue
        t1 = (-b - sqrt(discriminant)) / (2.0 * a)
        t2 = (-b + sqrt(discriminant)) / (2.0 * a)
        p_a = ray_origin + ray_direction * t1
        p_b = ray_origin + ray_direction * t2
        if p_a == p_b:
            results[fragment] = (0.0, 0.0)
            continue
        segment_length = length(p_b - p_a)
        n = max(1, round(segment_length / l))
        step_size = segment_length / n
        accumulated_color = (0.0, 0.0, 0.0)
        accumulated_opacity = 0.0
        for i in range(n):
            t_start = i * step_size
            t_end = (i + 1) * step_size
            p_start = ray_origin + ray_direction * t_start
            p_end = ray_origin + ray_direction * t_end
            # Not given in the sources: exact sampling positions and 2D table indexing
            base_color, base_opacity = lookup_table.query(p_start, p_end)
            # Weight by segment length l as per Roettger et al. (2000)
            weighted_color = base_color * l
            weighted_opacity = base_opacity * l
            # Standard front-to-back compositing [G]
            alpha = 1.0 - accumulated_opacity
            accumulated_color = accumulated_color + weighted_color * alpha
            accumulated_opacity = accumulated_opacity + weighted_opacity * alpha
        results[fragment] = (accumulated_color, accumulated_opacity)
    return results
```

**Edge Cases and Pitfalls:**
* **Varying Segment Lengths:** Standard 2D table lookups assume fixed segment lengths [S1, unofficial]. Since segment lengths vary with kernel size, results must be weighted by length $l$ using the Roettger et al. (2000) approximation scheme [S1, unofficial].
* **Degenerate Intersection:** If the ray is tangent to or outside the bounding sphere, $p_a = p_b$ [S1, unofficial]. This case must be handled explicitly [S1, unofficial].
* **Precision:** The derivation of the sampling step $l$ must be careful to align with the 3D texture resolution to avoid aliasing or blurring [S1, unofficial].
## Operating characteristics
**Time Complexity:** Depends on the number of fragments and the number of segments $n$ per fragment [S1, unofficial]. $n$ is derived from the kernel extent and texture resolution [S1, unofficial].
**Memory Complexity:** Proportional to the size of the hierarchical octree and the 3D textures attached to each node [S1, unofficial].
**Strengths:** Combines the speed of splatting with the detail of raycasting; allows for variable resolution per region via the hierarchical structure [S1, unofficial].
**Limitations:** Requires pre-computation of 3D textures and lookup tables; complexity in managing the hierarchical structure and segment weighting [S1, unofficial].
**When to Use:** When rendering large volumetric datasets where some regions require high detail and others do not, and hardware acceleration for splatting is desired [S1, unofficial].
## Background
The method was introduced in the paper "From Volume Splatting to Raycasting - A Smooth Transition" [S1, unofficial]. It builds on the idea of representing volumetric datasets as overlapping 3D detailed kernels [S1, unofficial]. The hierarchical representation uses an octree, similar to approaches by Laur and Hanrahan [S1, unofficial]. The pre-integrated classification scheme references Engel et al. (2001), and the segment weighting approximation references Roettger et al. (2000) [S1, unofficial].
