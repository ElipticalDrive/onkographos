# Chunked Ray Rendering

Also called: Batched Neural Query, Chunked Ray Processing, Chunked Rendering, Memory-Bounded Ray & Point Chunking, Ray Chunking, Staged Ray Rendering

## Overview
Chunked Ray Rendering is a memory-management strategy for object-order volume rendering that processes rays in fixed-size batches (chunks) rather than all at once [S1, unofficial][S2, unofficial][S4, unofficial][S5, unofficial][S6, unofficial][S8, unofficial]. It solves Out-Of-Memory (OOM) errors that occur when the number of rays in an image exceeds the accelerator's VRAM capacity or when the neural network model is too large for a full-batch forward pass [S3, unofficial][S7, unofficial]. It sets itself apart from its parent, Batched Ray Rendering, by explicitly handling the sharding of these chunks across multiple hosts and devices in distributed settings, ensuring that partial results are correctly concatenated and reshaped into the final image [S2, unofficial].

## How it works
**Inputs and Outputs:**
- **Inputs:** A set of rays defined by origins $\mathbf{o}$ and directions $\mathbf{d}$, typically shaped $(H, W, 3)$ or flattened to $(N, 3)$ where $N = H \times W$ [S2, unofficial][S6, unofficial]. A rendering function `model_fn` that accepts ray bundles and returns per-ray properties (color, depth, etc.) [S2, unofficial][S3, unofficial]. Configuration parameters including `chunk_size` (or `render_chunk_size`) and `device_count` [S2, unofficial][S3, unofficial].
- **Outputs:** Rendered image tensors (e.g., RGB, depth) reshaped to $(H, W, C)$, where $C$ is the number of output channels [S2, unofficial][S3, unofficial].

**Data Structures:**
- **Ray Bundle:** A dictionary or object containing tensors for ray origins, directions, and potentially other attributes (e.g., camera indices, time) [S2, unofficial][S3, unofficial]. Tensors are typically 2D: $(N, D)$ where $N$ is the number of rays and $D$ is the feature dimension (e.g., 3 for origins) [S1, unofficial][S2, unofficial].
- **Chunk List:** A list of ray bundles, each containing a subset of the total rays [S2, unofficial][S5, unofficial].
- **Result Accumulator:** A list of output tensors from each chunk, concatenated along the ray dimension (axis 0) before reshaping [S2, unofficial][S5, unofficial][S9, unofficial].

**Parameters:**
- `chunk_size` (or `render_chunk_size`, `max_ray_batch`): The maximum number of rays processed in a single forward pass. Typical values range from 1024 to 8192, chosen to fit within available VRAM while maximizing throughput [S2, unofficial][S3, unofficial][S5, unofficial][S6, unofficial][S7, unofficial][S8, unofficial].
- `device_count`: The number of parallel devices (GPUs/TPUs) used for rendering [S2, unofficial][S3, unofficial].
- `white_bkgd`: Boolean flag for background compositing (default True) [S5, unofficial][S6, unofficial].
- `perturb`: Boolean flag for sampling perturbation (default False for video rendering to avoid noise) [S5, unofficial][S6, unofficial].
- `default_ret_key`: Optional string ('fine' or 'coarse') to select output key from model_fn [S3, unofficial].

**Steps:**
1. **Initialization:** Flatten ray origins and directions to 2D tensors of shape $(N, 3)$ where $N = H \times W$ [S1, unofficial][S2, unofficial][S6, unofficial]. Initialize empty lists for results [S5, unofficial][S6, unofficial][S8, unofficial].
2. **Chunk Generation:** Determine the number of chunks: $N_{\text{chunks}} = \lceil N / \text{chunk\_size} \rceil$ [S2, unofficial][S9, unofficial]. Generate start indices: $\text{idx0s} = \text{range}(0, N, \text{chunk\_size})$ [S2, unofficial].
3. **Iteration:** For each start index `idx0` in `idx0s`:
    a. **Slice:** Extract the chunk of rays: $\mathbf{o}_{\text{chunk}} = \mathbf{o}[\text{idx0} : \text{idx0} + \text{chunk\_size}]$, $\mathbf{d}_{\text{chunk}} = \mathbf{d}[\text{idx0} : \text{idx0} + \text{chunk\_size}]$ [S2, unofficial][S5, unofficial][S8, unofficial].
    b. **Padding (Distributed):** If rendering across multiple devices, calculate the actual chunk size. If `actual_chunk_size % device_count != 0`, pad the chunk with edge-mode values (e.g., repeating the last ray) to make the number of rays divisible by `device_count` [S2, unofficial][S3, unofficial]. Track the padding amount [S3, unofficial].
    c. **Sharding (Distributed):** Shard the chunk across hosts and devices. Calculate `rays_per_host = chunk_rays.origins.shape[0] // jax.process_count()` [S2, unofficial]. Determine start and stop indices for the current host [S2, unofficial]. Shard the chunk using a framework-specific utility [S2, unofficial].
    d. **Forward Pass:** Call the rendering function: `results_chunk = model_fn(rays_o=chunk_o, rays_d=chunk_d, ...)` [S2, unofficial][S4, unofficial][S5, unofficial][S8, unofficial][S9, unofficial]. If `cuda_ray` is enabled, staging is disabled, and the entire batch is processed at once [S8, unofficial].
    e. **Unsharding (Distributed):** Unreplicate and unshard the results from devices back to the host [S2, unofficial]. Remove the previously added padding from the results to avoid corrupting image dimensions [S2, unofficial][S3, unofficial].
    f. **Accumulate:** Append the results (e.g., `rgb_chunk`, `depth_chunk`) to the result lists [S4, unofficial][S5, unofficial][S8, unofficial][S9, unofficial].
4. **Concatenation:** Concatenate all accumulated results along axis 0: $\mathbf{R}_{\text{total}} = \text{concat}(\mathbf{R}_1, \mathbf{R}_2, \dots)$ [S2, unofficial][S4, unofficial][S5, unofficial][S8, unofficial][S9, unofficial].
5. **Reshaping:** Reshape the concatenated results from $(N, C)$ back to $(H, W, C)$ [S2, unofficial][S3, unofficial].
6. **Visualization Subset (Optional):** If extracting a subset of rays for visualization, generate a deterministic random index set and subset the final rendering [S2, unofficial].

**Edge Cases and Pitfalls:**
- **Padding Removal:** Padding must be tracked and removed during unsharding to avoid corrupting image dimensions [S3, unofficial].
- **CUDA Raymarching:** Staging is disabled when `cuda_ray` is True; the entire ray batch is processed at once, bypassing chunking [S8, unofficial].
- **Non-Square Images:** Flattening $(H, W, 3)$ to $(N, 3)$ requires storing $H$ and $W$ separately to correctly reshape results [S2, unofficial].

**Pseudocode:**
```python
import torch
import numpy as np

def chunked_ray_rendering(rays_o, rays_d, model_fn, chunk_size=4096, device_count=1, 
                          H=None, W=None, device='cuda', white_bkgd=True, perturb=False):
    """
    Render rays in chunks to manage memory and enable distributed sharding.
    
    Args:
        rays_o: Tensor of ray origins, shape (H, W, 3) or (N, 3).
        rays_d: Tensor of ray directions, shape (H, W, 3) or (N, 3).
        model_fn: Function that takes (rays_o, rays_d) and returns rendered properties.
        chunk_size: Number of rays per chunk.
        device_count: Number of devices for sharding.
        H, W: Image dimensions. Required if rays_o is 2D.
        device: Target device string.
        white_bkgd: Background compositing flag.
        perturb: Perturbation flag.
        
    Returns:
        rgb: Rendered RGB image, shape (H, W, 3).
        depth: Rendered depth image, shape (H, W).
    """
    # Extract dimensions and flatten to (N, 3)
    if rays_o.dim() == 3:
        H_in, W_in, _ = rays_o.shape
        rays_o = rays_o.reshape(-1, 3)
        rays_d = rays_d.reshape(-1, 3)
        H, W = H_in, W_in
    else:
        N, _ = rays_o.shape
        if H is None or W is None:
            raise ValueError("H and W must be provided when rays_o is 2D.")
        
    N = rays_o.shape[0]
    rgbs = []
    depths = []
    
    # Generate chunk indices
    idx0s = range(0, N, chunk_size)
    
    for idx0 in idx0s:
        # Slice chunk
        end_idx = min(idx0 + chunk_size, N)
        chunk_o = rays_o[idx0:end_idx].clone()
        chunk_d = rays_d[idx0:end_idx].clone()
        
        actual_chunk_size = chunk_o.shape[0]
        padding = (device_count - (actual_chunk_size % device_count)) % device_count
        
        # Padding for distributed sharding
        if padding > 0:
            last_ray_o = chunk_o[-1:].expand(padding, -1)
            last_ray_d = chunk_d[-1:].expand(padding, -1)
            chunk_o = torch.cat([chunk_o, last_ray_o], dim=0)
            chunk_d = torch.cat([chunk_d, last_ray_d], dim=0)
            
        # Move to device
        chunk_o = chunk_o.to(device)
        chunk_d = chunk_d.to(device)
        
        # Forward pass
        # Note: Sharding/unsharding logic is framework-specific (e.g., JAX pmap, PyTorch DDP) [S2, unofficial]
        with torch.no_grad():
            out = model_fn(chunk_o, chunk_d, white_bkgd=white_bkgd, perturb=perturb)
            
        # Extract results
        rgb_chunk = out['rgb']  # Shape: (actual_chunk_size + padding, 3)
        depth_chunk = out['depth']  # Shape: (actual_chunk_size + padding,)
        
        # Remove padding
        if padding > 0:
            rgb_chunk = rgb_chunk[:-padding]
            depth_chunk = depth_chunk[:-padding]
            
        # Accumulate
        rgbs.append(rgb_chunk.cpu())
        depths.append(depth_chunk.cpu())
        
    # Concatenate and reshape
    if not rgbs:
        return None, None
        
    rgb_cat = torch.cat(rgbs, dim=0)
    depth_cat = torch.cat(depths, dim=0)
    
    rgb_image = rgb_cat.reshape(H, W, 3)
    depth_image = depth_cat.reshape(H, W)
    
    return rgb_image, depth_image
```

## Subtopics

### [Minibatch Splitting](3176-minibatch-splitting.md)
A variant that splits a huge tensor (ray bundle) into a list of minibatches to avoid out-of-memory issues. It uses a simple list comprehension to split the input tensor into chunks of size `chunksize` [G].

## Operating characteristics
- **Time Complexity:** $O(N)$, where $N$ is the total number of rays [G]. The constant factor is slightly higher than non-chunked rendering due to the overhead of loop iterations and tensor concatenations [G].
- **Memory Complexity:** $O(\text{chunk\_size} \times D)$, where $D$ is the memory footprint per ray (including intermediate activations) [G]. This allows rendering images with $N \gg \text{chunk\_size}$ on hardware with limited VRAM [S2, unofficial].
- **Measured Performance:** Typical `chunk_size` values range from 1024 to 8192 rays, with specific implementations using 1024 [S6, unofficial], 4096 [S7, unofficial][S8, unofficial], or 8192 [S2, unofficial]. The optimal value depends on the model size and available VRAM [G]. Larger chunks improve throughput by reducing kernel launch overhead, but risk OOM errors [G].
- **Strengths:** Enables rendering of high-resolution images and large scenes on consumer-grade GPUs. Supports multi-host distributed rendering by sharding chunks across devices [S2, unofficial][S3, unofficial].
- **Limitations:** Slightly slower than full-batch rendering due to overhead. Requires careful tuning of `chunk_size` to balance memory and speed [G]. Padding overhead is minimal but non-zero [S2, unofficial].
- **When to use:** When rendering large images or using large neural networks that exceed VRAM capacity [S1, unofficial][S3, unofficial][S5, unofficial][S8, unofficial]. Essential for distributed rendering setups [S2, unofficial][S3, unofficial].
- **When not to use:** When `cuda_ray` is enabled, as staging is disabled and the entire batch is processed at once [S8, unofficial]. For very small scenes where full-batch rendering fits in memory, chunking adds unnecessary overhead [G].

## Background
Chunked Ray Rendering originated as a practical necessity in the development of Neural Radiance Fields (NeRF) and related neural rendering techniques [S2, unofficial][S3, unofficial]. As NeRF models grew in complexity and image resolutions increased, the memory requirements for processing all rays in an image simultaneously exceeded the capacity of available GPUs [G]. Early implementations in libraries like `nerfies` [S3, unofficial] and `multinerf` [S2, unofficial] introduced chunking to manage memory and enable distributed training and rendering. It is particularly important in distributed settings where rays are sharded across multiple hosts and devices [S2, unofficial].
