# Inverse LBS Motion Field

Also called: Inverse Linear Blend Skinning

## Overview
Inverse LBS Motion Field is a module that transforms a query point from posed space to unposed (canonical) space using inverse Linear Blend Skinning (LBS), serving as the base for residual deformation in neural volumetric representations of dynamic humans [S1]. It differs from forward skinning methods by explicitly computing the inverse of the weighted bone transformation matrices to map points back to a canonical reference frame, which is then used to condition occupancy networks or predict residuals [S1, S2].

## How it works
**Inputs and Outputs:**
- Input: A query point $x$ in posed space, blend weights $w$ (associated with the point), and human pose parameters $\rho$ which define the bone transformations [S1].
- Output: The coordinate $x_{\text{can}}$ in canonical (unposed) space [S1].

**Data Structures:**
- $x$: A 3D vector representing the query point in posed space [G].
- $w$: A vector of blend weights $w_{k,j}$, where $k$ indexes the point and $j$ indexes the bone. The weights sum to 1 for each point [G].
- $G_j$: A $4 \times 4$ transformation matrix for bone $j$, derived from the pose parameters $\rho$ [S1].
- $J$: The total number of bones in the skeleton [S1].

**Formula:**
The transformation is defined as [S1]:

$$
\Phi_{LBS} (x, w, \rho) = \left( \sum_{j=1}^{J} w_{k,j} G_j \right)^{-1} x
$$

Where:
- $\Phi_{LBS}$ is the inverse LBS motion field function [S1].
- $x$ is the query point, treated as a homogeneous coordinate vector for matrix-vector multiplication [G].
- $w_{k,j}$ is the weight of bone $j$ for point $k$ [S1].
- $G_j$ is the transformation matrix of bone $j$ [S1].

**Steps:**
1. Retrieve the pose parameters $\rho$ and compute the bone transformation matrices $G_j$ for all $J$ bones [S1].
2. For a given query point $x$, retrieve its associated blend weights $w_{k,j}$ for all bones $j=1 \dots J$ [S1].
3. Compute the weighted sum of the bone transformation matrices: $M = \sum_{j=1}^{J} w_{k,j} G_j$ [S1].
4. Compute the inverse of the matrix $M$: $M^{-1}$ [S1].
5. Apply the inverse matrix to the query point: $x_{\text{can}} = M^{-1} x$ [S1].

## Subtopics

### Inverse Linear Blend Skinning for Occupancy Networks
This variant, used in methods like LEAP, integrates inverse LBS into occupancy networks [S2]. It sends transformation matrices of all bones into shape, structure, and pose encoders as global features, obtains local features through a projection module for each bone, and uses the transformation matrix of each bone to learn inverse LBS [S2]. The local features of all bones are then weighed using inverse LBS to condition the occupancy network [S2]. A key pitfall is that adopting reverse skinning makes the learning of the canonical space pose dependent on the specific pose, making it difficult to handle unseen poses [S2].

### SNARF
SNARF avoids the direct learning of the reverse skinning function [S2]. Instead, it maps the posed shape into canonical space through reverse skinning but solves for the inverse of the forward skinning according to geometry cycle consistency [S2]. It uses an iterative root-seeking method to handle situations where the solution is not closed when calculating forward skinning inversely [S2].

## Operating characteristics
- **Time Complexity:** The core operation involves matrix multiplication and inversion. For $J$ bones, computing the weighted sum takes $O(J)$ matrix multiplications and additions. Inverting a $4 \times 4$ matrix is $O(1)$ but involves a fixed number of operations. Thus, the complexity per query point is $O(J)$ [G].
- **Memory Complexity:** Requires storing $J$ bone transformation matrices $G_j$ and the blend weights $w$ for each query point [G].
- **Strengths:** Provides a direct, differentiable mapping from posed to canonical space, which is essential for training neural fields on dynamic data [G]. It leverages the well-established LBS framework [G].
- **Limitations:** The method is pose-dependent, which can lead to difficulties with unseen poses if not regularized or handled carefully (as noted in the Occupancy Networks variant) [S2].
- **When to use:** When a direct, explicit inverse mapping is required for neural volumetric representations of humans, and the pose space is well-covered during training [G].
- **When not to use:** When dealing with highly degenerate poses where the skinning matrix might be singular, or when computational resources are extremely limited and iterative methods (like SNARF) are preferred for robustness despite higher per-step cost [G].

## Background
Inverse LBS Motion Field originates from the need to represent dynamic human avatars in a canonical space for neural volumetric rendering [S1]. The specific formulation $\Phi_{LBS} (x, w, \rho) = \left( \sum_{j=1}^{J} w_{k,j} G_j \right)^{-1} x$ is cited from [S1], which references [35] for the inverse LBS module. The concept is further explored in surveys of implicit neural representations for human modeling, where variants like LEAP and SNARF are discussed [S2]. LEAP adopts reverse skinning to condition occupancy networks [S2], while SNARF uses geometry cycle consistency to solve the inverse [S2].
