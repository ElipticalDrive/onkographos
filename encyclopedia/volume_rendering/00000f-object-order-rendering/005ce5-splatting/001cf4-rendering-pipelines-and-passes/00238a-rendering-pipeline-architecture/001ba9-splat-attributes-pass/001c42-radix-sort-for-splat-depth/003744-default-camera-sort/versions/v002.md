# Default Camera Sort

Also called: Back-to-front sort, Splat Painter's Sort, sort splats for the scene camera by default

## Overview
Default Camera Sort is a compositing technique for oriented Gaussian ellipses (splats) that sorts them back-to-front relative to a camera viewpoint to ensure correct translucent blending [S2, unofficial]. It differs from its siblings by automatically binding the sort order to the active scene camera without requiring explicit provider configuration [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A cloud of splats managed by `SplatNode`, and a camera viewpoint (either the scene camera or a custom provider) [S2, unofficial].
*   **Output:** A compositing order of splats sorted back-to-front relative to the camera [S2, unofficial].

**Data Structures:**
The `SplatNode` manages the `SplatCloud` and triggers the sort operation on a background thread whenever the camera moves [S2, unofficial].

**Steps:**
1.  **Determine Viewpoint:** Check if a `cameraPositionProvider` is set. If `null` (the default), use the scene camera position [S2, unofficial]. If provided, invoke the lambda to retrieve the `Position` object representing the custom viewpoint [S2, unofficial].
2.  **Calculate Depths:** For each splat $i$, calculate the distance $d_i$ from the splat's center position $P_i$ to the camera position $C$:
    $$ d_i = \| P_i - C \| $$
3.  **Sort:** Sort the splats in descending order of $d_i$ (back-to-front) [S2, unofficial]. The sort executes on a background thread to avoid blocking the main rendering loop [S2, unofficial].
4.  **Update Compositing Order:** The node automatically applies the sorted order to the rendering pipeline [S2, unofficial].

**Parameters:**
*   `cameraPositionProvider`: A lambda returning a `Position` object representing the camera's world position. If `null`, the scene camera is used (default). If provided, it enables the back-to-front painter's sort for that specific viewpoint [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Orbiting Artifacts:** If `cameraPositionProvider` is explicitly set to `null` in older versions where it was required for sorting, or if the automatic default sort is inactive, the compositing order remains as loaded. This causes visual popping artifacts when orbiting the camera because the splat order does not update to match the new viewpoint [S2, unofficial].

**Pseudocode:**
```python
# Pseudocode for the Default Camera Sort logic within SplatNode
# Assumes SplatCloud has a list of splats, each with a position vector.

def update_sort_order(splat_cloud, camera_position_provider):
    if splat_cloud is None:
        return

    # Step 1: Determine camera position
    if camera_position_provider is not None:
        camera_pos = camera_position_provider()
    else:
        # Default: use scene camera
        camera_pos = get_scene_camera_position()

    # Step 2: Calculate depths
    # Each splat has a 'pos' attribute (vec3)
    depths = []
    for i in range(splat_cloud.count):
        splat = splat_cloud.splats[i]
        # Euclidean distance
        diff = splat.pos - camera_pos
        depth = (diff.x**2 + diff.y**2 + diff.z**2)**0.5
        depths.append((depth, i))

    # Step 3: Sort back-to-front (descending depth)
    # Stable sort is preferred to maintain original order for equal depths
    depths.sort(key=lambda x: x[0], reverse=True)

    # Step 4: Apply order
    # Reorder the splat cloud or update the index buffer
    sorted_indices = [item[1] for item in depths]
    splat_cloud.apply_render_order(sorted_indices)
```

## Background
The Default Camera Sort was introduced as part of the `SplatNode` implementation in the SceneView library, specifically in commit `e7e8fd4` [S2, unofficial]. It was developed to address visual popping artifacts that occurred when orbiting cameras in Gaussian splat visualizations, which previously relied on a static load order or required an explicit `cameraPositionProvider` [S2, unofficial]. The change was part of a broader effort to improve the robustness of Gaussian splatting on platforms like iOS and VisionOS, removing potential AI-generated bugs associated with previous default sort sources [S1, unofficial].
