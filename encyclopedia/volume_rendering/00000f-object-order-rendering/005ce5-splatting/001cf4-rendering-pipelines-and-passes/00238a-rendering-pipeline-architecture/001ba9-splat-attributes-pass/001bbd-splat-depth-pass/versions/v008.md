# Splat Depth Pass

Also called: Front-Face Depth Pass, Visibility Pass

## Overview
The Splat Depth Pass computes the depth of the front surface of a point sprite (splat) for each fragment, enabling correct occlusion handling during surface splatting [S1, unofficial]. It differs from standard binary depth testing by applying a small epsilon shift to the calculated depth, which prevents z-fighting and gaps between overlapping splats by ensuring consistent blending at surface boundaries [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input**: Fragment shader context including `gl_FragCoord` (window-space coordinates), `gl_PointCoord` (normalized texture coordinates within the point sprite, range [0,1]), and vertex attributes `i.radius` (splat radius in world space) and `i.depth` (or equivalent linear depth of the point center) [S1, unofficial].
*   **Output**: `gl_FragDepth` (window-space depth value written to the depth buffer) [S1, unofficial].

**Data Structures**
No explicit data structures are required; the method operates on per-fragment state provided by the graphics API [G].

**Steps**
1.  **Calculate offset from center**: Compute the 2D vector from the center of the point sprite to the current fragment [S1, unofficial].
2.  **Check circular boundary**: Calculate the squared magnitude of the offset [S1, unofficial]. If the squared magnitude exceeds $0.25$, the fragment lies outside the unit circle and is discarded [S1, unofficial].
3.  **Compute world-space offset**: Scale the normalized offset by the splat's radius to get the world-space 2D offset vector [S1, unofficial].
4.  **Calculate depth offset**: Determine the z-offset from the center of the sphere to the front surface at the current 2D position using the Pythagorean theorem [S1, unofficial].
5.  **Compute final depth**: Subtract the depth offset from the center's linear depth and add an epsilon value to shift the depth slightly towards the camera [S1, unofficial].
6.  **Write depth**: Assign the computed depth to the fragment depth output [S1, unofficial].

**Formulas**
*   **Boundary Check**: $|\mathbf{v}_{center}|^2 \le 0.25$ [S1, unofficial].
*   **Depth Offset**: $d_{offset} = \sqrt{r^2 - |\mathbf{v}_{world}|^2}$ [S1, unofficial].
*   **Final Depth**: $z_{frag} = z_{center} - d_{offset} + \epsilon$ [S1, unofficial].

**Parameters**
*   **epsilon ($\epsilon$)**: A small constant added to the depth to blend splats close to the surface [S1, unofficial]. Value: $0.25$ [S1, unofficial].

**Edge Cases and Pitfalls**
*   **Z-fighting and Gaps**: Without the epsilon shift, overlapping splats at the same depth may cause z-fighting or visible gaps due to precision errors [S1, unofficial]. The epsilon ensures splats near the surface are blended correctly [S1, unofficial].
*   **Precision**: The calculation assumes linear depth [S1, unofficial]. If non-linear depth is used, a conversion function must transform window-space Z to linear eye-space Z before subtraction [G].
*   **Radius Zero**: If the radius is zero, the depth offset is zero, and the depth equals the center depth minus epsilon [S1, unofficial].

**Pseudocode**
```python
def compute_splat_depth(gl_frag_coord_z: float, gl_point_coord: tuple, radius: float, center_linear_depth: float, epsilon: float) -> float:
    # 1. Calculate offset from center
    v_center = (gl_point_coord[0] - 0.5, gl_point_coord[1] - 0.5)

    # 2. Check circular boundary
    mag_sq = v_center[0]**2 + v_center[1]**2
    if mag_sq > 0.25:
        return None  # Fragment outside splat boundary

    # 3. Compute world-space offset
    v_world = (v_center[0] * 2.0 * radius, v_center[1] * 2.0 * radius)

    # 4. Calculate depth offset
    dot_val = v_world[0]**2 + v_world[1]**2
    radius_sq = radius * radius
    depth_offset = (max(radius_sq - dot_val, 0.0)) ** 0.5

    # 5. Compute final depth
    # center_linear_depth replaces linearDepth(gl_FragCoord.z) as a standard conversion [G]
    final_depth = center_linear_depth - depth_offset + epsilon

    # 6. Write depth
    return final_depth
```

## Subtopics

### [Single-Layer Ternary Depth Test](4509-single-layer-ternary-depth-test.md)
A technique that maintains exactly one surface layer per pixel using a depth band to decide blending, replacing, or discarding fragments. It differs from the standard Splat Depth Pass by accommodating depth uncertainty, though it may cause occlusion artifacts in complex geometry.

## Operating characteristics
*   **Time Complexity**: $O(1)$ per fragment [G]. The calculation involves basic arithmetic operations and a square root [G].
*   **Memory Complexity**: $O(1)$ auxiliary memory [G]. No additional buffers are allocated; it writes directly to the depth buffer [G].
*   **Strengths**: Simple to implement in the fragment shader [G]. It effectively handles occlusion for point-based surface rendering [S1, unofficial]. It prevents z-fighting via epsilon adjustment [S1, unofficial].
*   **Limitations**: It relies on the assumption that splats are spherical and uniformly sized [G]. It does not handle transparency or volume accumulation directly, as those are handled by subsequent passes [G].
*   **When to use**: When rendering point clouds as surfaces where correct occlusion is required before color accumulation [S1, unofficial].
*   **When not to use**: For volume rendering where depth is integrated along rays, or when splats are not spherical [G].

## Background
The method is derived from implementations of point cloud surface rendering, specifically those using spherical splats to approximate surfaces [S1, unofficial]. The specific epsilon adjustment technique is documented in the `PointCloudRendering` repository [S1, unofficial].
