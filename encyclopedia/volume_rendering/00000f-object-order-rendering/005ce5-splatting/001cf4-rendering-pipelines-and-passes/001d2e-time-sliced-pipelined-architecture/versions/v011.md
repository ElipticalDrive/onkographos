# Time-Sliced Pipelined Architecture

Also called: Multi-core time-sliced pipeline, Time-slicing

## Overview
The Time-Sliced Pipelined Architecture is a hardware design methodology for volume rendering that achieves real-time performance by overlapping distinct pipeline stages through time-slicing [S1, unofficial]. It solves sequential processing bottlenecks by allowing multiple tasks to run simultaneously on shared or replicated functional blocks, enabling continuous hardware-software communication and interactive frame rates [S1, unofficial].

## How it works
The architecture decomposes the volume rendering pipeline into independent functional blocks that are configured or replicated as sub-cores based on processing requirements [S1, unofficial].

**Inputs and Outputs:**
*   **Input:** Volumetric data (voxels), transformation matrices (Model-View-Projection), and rendering parameters (opacity, shading models) [S1, unofficial][G].
*   **Output:** Final rendered image frame [S1, unofficial].

**Data Structures:**
*   **Context Memory:** A shared RAM structure used for inter-component communication [S1, unofficial]. It stores intermediate results (e.g., dot products) for several clock cycles so they can be accessed by other components [S1, unofficial].
*   **Normal Mode Registers:** Provide a common interface for components to access context memory [S1, unofficial].
*   **Context Address Snooping Mechanism:** Allows components to monitor and access stored information in the context memory [S1, unofficial].
*   **Sub-cores:** Basic functional blocks (multipliers, adders, inner product processors) that are physically considered as sub-cores [S1, unofficial]. They are configured or replicated to execute specific operations [S1, unofficial].

**Numbered Steps:**
1.  **Pipeline Decomposition:** Divide the rendering pipeline into functional blocks: classifier, gradient calculator, shearing-warping block, shader, and composer [S1, unofficial].
2.  **Component Implementation:** Implement these blocks as independent, reusable components/sub-cores [S1, unofficial]. The gradient calculator, shearer-composer, shading processor, and matrix multiplication processor are composed from basic functional blocks like multipliers, adders, or inner product processors [S1, unofficial].
3.  **Configuration/Replication:** Based on the processing required by the calling module, the embedded sub-core is configured or replicated to execute a specific operation [S1, unofficial].
4.  **Time-Sliced Execution:** Use time-slicing to overlap execution stages [S1, unofficial]. This allows the simultaneous processing of several tasks, such as calculating a dot product for a voxel in the classifier and using that same value in the shader and composer within the same time frame [S1, unofficial].
5.  **Inter-Component Communication:** Components communicate via the common interface provided by context RAM, normal mode registers, and the context address snooping mechanism [S1, unofficial]. Calculated values (e.g., dot products) are stored in corresponding RAM cells to be called up by another component [S1, unofficial].

**Pseudocode:**
```python
class TimeSlicedPipeline:
    def __init__(self):
        self.context_memory = {}
        self.stage_stages = ['classifier', 'gradient_calculator', 'shear_warp', 'shader', 'composer']
        self.pipeline_buffer = [None] * len(self.stage_stages)

    def process_voxel(self, voxel_data):
        # Stage 1: Classifier
        self.pipeline_buffer[0] = self._execute_block('classifier', voxel_data)
        # Stage 2: Gradient Calculator
        self.pipeline_buffer[1] = self._execute_block('gradient_calculator', voxel_data)
        # Stage 3: Shear-Warp
        self.pipeline_buffer[2] = self._execute_block('shear_warp', voxel_data)
        # Stage 4: Shader (reads gradient from context memory)
        gradient = self.pipeline_buffer[1]
        dot_product = self._dot_product(self.pipeline_buffer[2], gradient)
        self.context_memory['dot_product'] = dot_product
        self.pipeline_buffer[3] = self._execute_block('shader', self.pipeline_buffer[2], dot_product)
        # Stage 5: Composer (reads dot_product from context memory)
        self.pipeline_buffer[4] = self._execute_block('composer', self.pipeline_buffer[3], self.context_memory['dot_product'])
        return self.pipeline_buffer[4]

    def _execute_block(self, block_name, *args):
        # Hardware mapping: functional blocks are composed of sub-cores
        # (multipliers, adders, inner product processors) configured per operation
        # Exact sub-core configuration logic is not specified in the sources [S1, unofficial]
        return args[0] if args else None

    def _dot_product(self, vec1, vec2):
        return sum(a * b for a, b in zip(vec1, vec2))

    def start_time_slicing(self, voxel_stream):
        # In hardware, time-slicing overlaps stages so multiple voxels are processed concurrently
        # while stage N processes voxel i, stage N+1 processes voxel i-1 [S1, unofficial]
        results = []
        for voxel in voxel_stream:
            results.append(self.process_voxel(voxel))
        return results
```

## Subtopics

### [Vg500 Parallel Pipeline Architecture](2072-vg500-parallel-pipeline-architecture.md)
The Vg500 Parallel Pipeline Architecture is a highly parallel, template-based ray-casting hardware implementation designed for real-time volume rendering. It solves the bandwidth and computation bottlenecks of single-pipeline ray casters by employing four identical rendering pipelines that process adjacent voxel values in the x-direction simultaneously. Unlike general-purpose GPU approaches or the larger VIRIM architecture, the Vg500 integrates the entire ray-casting pipeline (interpolation, gradient estimation, shading, classification, and compositing) into a single ASIC, enabling the rendering of $256^3$ volumes at 30 fps on a standard PCI card.

## Background
The Time-Sliced Pipelined Architecture was developed as part of the Shear-warp factorization volume rendering visualization system (SWE) [S1, unofficial]. It was designed to provide real-time rendering capabilities by implementing a multi-core structure compliant with the rendering pipeline [S1, unofficial]. The architecture emphasizes component reusability and hierarchical design to simplify layout and improve efficiency [S1, unofficial]. It is used in systems like the VolumePro, where the Vg500 ASIC implements a similar pipelined approach [S1, unofficial].
