# Splat Size Culling
Also called: Culling Small Splats
## Overview
Splat Size Culling is a staging optimization for object-order volume rendering that discards primitives smaller than a defined threshold before rasterization [S1]. It trades visual fidelity for real-time frame rates by reducing the workload of splats and fragments generated during the rendering pipeline [S1]. It differs from sibling methods like [Early Splat Termination](811-early-splat-termination.md) by operating at the data staging phase rather than during the per-pixel compositing phase, allowing it to prevent expensive rasterization and memory allocation for negligible contributions entirely [S1].
## How it works
**Inputs and Outputs:**
*   **Input:** A set of volumetric primitives (splats) $S = \{s_1, s_2, \dots, s_N\}$, where each splat $s_i$ has a projected size metric $\sigma_i$ (e.g., screen-space radius or area) and associated attributes (position, color, opacity).
*   **Output:** A filtered subset of splats $S' \subseteq S$ containing only those with $\sigma_i \geq \tau$, where $\tau$ is the culling threshold.

**Data Structures:**
The primitive representation follows the standard splatting model [G]. Each splat $k$ is defined by:
*   Position $\mathbf{p}_k$ (3D coordinates).
*   Density/Opacity $\rho_k$ (scalar).
*   Reconstruction kernel $h$ (typically Gaussian parameters, e.g., covariance matrix or radius) [S1].

**Algorithm:**
1.  **Projection:** Transform each splat $k$ from volume space to screen space using the Model-View-Projection (MVP) matrix .
2.  **Size Estimation:** Calculate the projected size metric $\sigma_k$ for each splat. For Gaussian splats, this is often derived from the determinant of the projected covariance matrix or the screen-space radius [S1].
3.  **Threshold Comparison:** Compare $\sigma_k$ against the threshold $\tau$.
4.  **Filtering:** If $\sigma_k < \tau$, discard splat $k$. Otherwise, include it in the staging buffer.
5.  **Staging:** Pass the filtered set $S'$ to the rasterizer.

**Pseudocode:**
```python
def splat_size_culling(splats, threshold):
    """
    Discards splats with projected size below threshold.
    
    Args:
        splats: List of splat objects with attributes:
            - projected_size: float, the screen-space size metric (e.g., radius or area).
            - position: vec3
            - opacity: float
            - color: vec3
        threshold: float, the minimum projected size to keep.
        
    Returns:
        List of splats that pass the culling test.
    """
    kept_splats = []
    for splat in splats:
        # Step 2 & 3: Check if projected size meets threshold
        if splat.projected_size >= threshold:
            kept_splats.append(splat)
        # Else: discard (implicit)
    return kept_splats
```

**Parameters:**
*   **Threshold ($\tau$):** Not given in the sources. The threshold is user-configurable to balance quality and performance.
*   **Typical Values:** Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Small-Only Scenes:** The method fails for scenes composed entirely of small splats, such as those generated by Mesh2Splat, as all splats may be discarded or the visual quality degrades significantly [S1].
*   **Precision:** Not given in the sources.
*   **Boundaries:** Not given in the sources.

## Subtopics
## Operating characteristics
**Time and Memory Complexity:**
*   **Time:** $O(N)$ for the culling pass, where $N$ is the number of splats. This is negligible compared to the rasterization cost it avoids.
*   **Memory:** Reduces the number of staged splats and generated fragments, lowering memory bandwidth and buffer allocation requirements [S1].

**Measured Performance:**
*   On the GardenF scene, culling reduces staged splats from 5.79M to 1.25M and fragments from 8.16M to 1.99M [S1].
*   Render time decreases from 9.7 ms to 2.1 ms [S1].

**Scaling:**
*   Effectiveness scales with the variance in splat sizes. It works well for datasets with a mixture of wildly different splat sizes, such as 3DGS-generated models [S1].
*   At greater distances, where most splats become small, the majority are discarded, but larger semi-representative splats remain [S1].

**Strengths and Limitations:**
*   **Strengths:** Significant reduction in workload and render time for large, heterogeneous splat datasets [S1].
*   **Limitations:** Not suitable for scenes with uniformly small splats (e.g., Mesh2Splat) [S1]. Visual quality is reduced, though high-quality screenshots can be captured by disabling culling [S1].

**When to Use:**
*   Use for real-time rendering of large Gaussian Splat datasets where performance is critical and some quality loss is acceptable [S1].
*   Do not use for scenes with uniformly small primitives or when high-fidelity reconstruction is required [S1].

## Background
**Origin:**
*   Introduced in "Splatshop: Efficiently Editing Large Gaussian Splat Models" [S1].
*   The method is designed to address the computational bottleneck of rendering millions of splats in real-time by filtering out negligible contributions during the staging phase [S1].

**History and Development:**
*   The technique is part of the broader effort to optimize Gaussian Splatting for interactive editing and rendering [S1].
*   It leverages the observation that small splats contribute minimally to the final image, allowing for aggressive culling without severe visual artifacts in many cases [S1].

**Where it is used:**
*   Used in Splatshop for efficient editing and rendering of large Gaussian Splat models [S1].
