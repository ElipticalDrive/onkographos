# 3D Gaussian Splatting LOD methods

Also called: RTGS

## Overview
3D Gaussian Splatting Level-of-Detail (LOD) methods address the memory and computational bottlenecks of standard 3D Gaussian Splatting (3DGS) in large-scale or high-density scenes by reducing redundancy and selecting appropriate detail levels based on viewing distance or resource constraints [S1, S3, unofficial]. Unlike sibling methods that rely on static spatial partitioning (e.g., [CityGaussian](6143-citygaussian-vastgaussian-dogaussian.md)) or pure attribute compression (e.g., [LightGaussian](8036-lightgaussian.md)), these methods typically employ hierarchical structures, dynamic pruning, or multi-resolution pyramids to enable efficient rendering [S1, S3, unofficial]. They set themselves apart by focusing on the structural organization of Gaussians for LOD selection, such as the Sequential Point Trees (SPTs) used in [Hierarchical SPT](10290-sequential-point-trees-spts.md) or the redundancy reduction strategies in [RTGS](S1).

## How it works
The core mechanism involves constructing a hierarchy or multi-resolution representation of the Gaussian primitives, where coarser levels summarize finer details, allowing the renderer to select the appropriate resolution based on screen-space footprint or camera distance [S1, S3, unofficial].

### Inputs and Outputs
- **Input:** A set of 3D Gaussians $\{G_i\}$ defined by position $\mathbf{p}_i$, covariance $\mathbf{\Sigma}_i$ (or scale $\mathbf{s}_i$ and rotation $\mathbf{q}_i$), opacity $\alpha_i$, and spherical harmonic coefficients $\mathbf{c}_i$.
- **Output:** A hierarchical data structure (e.g., tree, pyramid, or sorted list) and a rendering pipeline that selects Gaussians or clusters for a given view.

### Data Structures
The specific data structure varies by variant:
1.  **Sequential Point Trees (SPTs):** A tree structure where nodes represent merged Gaussians summarizing their children [S3, unofficial]. Each node stores the aggregated radiance and opacity [S1, unofficial].
2.  **Multi-resolution Pyramid:** A set of Gaussian sets at different resolutions, often generated via downsampling [S1, unofficial].
3.  **Morton-ordered Tree:** A global primitive ordering where prefixes define successive approximations of the scene [S1, unofficial].

### Steps
1.  **Hierarchy Construction:**
    -   *Bottom-up:* Group spatially close Gaussians and merge them into parent nodes. The parent Gaussian's parameters (position, scale, opacity, color) are computed to summarize the children, often using moment-matching or weighted averaging [S1, S3, unofficial].
    -   *Top-down:* Start with a full-fidelity model and progressively prune anchors or downsample hierarchical grids to derive coarser levels [S1, unofficial].
    -   *Sorting:* For methods like Budgeted Gaussian Splatting, sort Gaussians using a space-filling curve (e.g., Morton order) to preserve spatial locality [S1, unofficial].

2.  **LOD Selection:**
    -   For each camera view, determine the appropriate LOD level. This is typically driven by the projected size of the Gaussians on the screen or the distance from the camera [S1, S3, unofficial].
    -   In SPT-based methods, traverse the tree to find the cut point where the parent's coverage is sufficient, avoiding the rendering of unnecessary children [S3, unofficial].
    -   In pyramid-based methods, select the resolution layer where the Gaussian footprint matches the pixel grid [S1, unofficial].

3.  **Rendering:**
    -   Rasterize the selected Gaussians or merged nodes.
    -   For hierarchical methods, render the parent node if the LOD cut selects it, otherwise render the children [S3, unofficial].
    -   Apply filtering (e.g., low-pass) if the selected LOD introduces aliasing [S1, unofficial].

### Formulas
-   **Gaussian Projection:** The 2D covariance $\mathbf{\Sigma}'$ in screen space is computed from the 3D covariance $\mathbf{\Sigma}$ using the view matrix $\mathbf{W}$ and Jacobian $\mathbf{J}$:
    $$ \mathbf{\Sigma}' = \mathbf{W} \mathbf{J} \mathbf{\Sigma} \mathbf{J}^T \mathbf{W}^T $$
    [S1, unofficial]
-   **Merging (Moment-Matching):** When merging children into a parent, the parent's covariance $\mathbf{\Sigma}_p$ and mean $\mathbf{p}_p$ are often computed to minimize the reconstruction error of the children's distributions [S1, S3, unofficial]. Exact formulas depend on the specific merging strategy (e.g., weighted average vs. L2-optimal).

### Parameters
-   **LOD Threshold:** The screen-space size or distance threshold that triggers a change in LOD level. Not given in the sources.
-   **Pruning Threshold:** The importance score or redundancy metric below which a Gaussian is removed. Not given in the sources.

### Edge Cases and Pitfalls
-   **Unreachable Gaussians:** In SPT-based methods, a child Gaussian may become larger than its parent, violating the cut condition. These Gaussians are left in RAM but not rendered to avoid derailing training [S3, unofficial].
-   **Quantization Artifacts:** Quantizing opacity can lead to fewer floaters or visual artifacts [S2].
-   **Overlapping Gaussians:** Sharing position or opacity attributes in compression can result in overlapping Gaussians, degrading quality [S2].

## Subtopics

### [CityGaussian / VastGaussian / DoGaussian](6143-citygaussian-vastgaussian-dogaussian.md)
CityGaussian, VastGaussian, and DoGaussian are methods for rendering city-scale (square-kilometer) 3D Gaussian Splatting (3DGS) scenes by partitioning the environment into spatial blocks, training independent Gaussian models per block, and merging them at render time. They solve the memory and performance bottlenecks of monolithic 3DGS in large scenes by enabling level-of-detail (LoD) selection, streaming, and distributed training. They set themselves apart from sibling methods like [Hierarchical 3D Gaussian Splatting (H-3DGS)](10279-hierarchical-3d-gaussian-splatting-h-3dgs.md) by relying on tile-based training and merging rather than a single unified hierarchical structure, and from [LightGaussian](8036-lightgaussian.md) by focusing on spatial partitioning rather than pure compression.

### [LightGaussian](8036-lightgaussian.md)
LightGaussian is a compression method for 3D Gaussian Splatting that reduces model size and improves rendering speed by combining structured pruning with Spherical Harmonic (SH) factorization and vector quantization. It achieves significant size reduction (up to 15$\times$) and high frame rates ($>200$ FPS) with minimal quality degradation ($<0.5$ dB drop). It distinguishes itself from sibling methods by focusing on attribute-level compression (SH factorization, vector quantization, and G-PCC position compression) rather than purely spatial clustering or octree-based spatial pruning.

### TRIPS
TRIPS is a point-based radiance field rendering technique that rasterizes points into a screen-space image pyramid using trilinear splats, followed by a neural reconstruction network to produce hole-free, crisp images [S2]. It solves the blurriness and cloudy artifacts of 3D Gaussian Splatting and the temporal instability and large-gap handling issues of ADOP by projecting neural color descriptors into an image pyramid using trilinear writes to two neighboring resolution layers based on projected point size, avoiding overdraw by rendering only 2x2 splats [S2].

### [Scale-Adaptive Gaussian Splatting](8085-scale-adaptive-gaussian-splatting.md)
Scale-Adaptive Gaussian Splatting (SA-GS) is a rendering optimization for 3D Gaussian Splatting that mitigates aliasing artifacts by applying an adaptive 2D low-pass filter during the splatting process. It distinguishes itself from sibling methods like [Alias-free 4D Gaussian Splatting](9872-alias-free-4d-gaussian-splatting.md) by performing this filtering at test time based on immediate rendering parameters, rather than modifying the Gaussian geometry or training loss.

### [Multi-scale filtering](8244-multi-scale-filtering.md)
Multi-scale filtering is a family of techniques in 3D Gaussian Splatting that mitigates aliasing and geometric artifacts by applying low-pass filters to the Gaussian representation. It addresses rendering quality degradation when the camera zooms out (causing high-frequency aliasing) or zooms in (causing dilation artifacts due to under-sampling) relative to the training resolution. Unlike sibling methods that rely on hierarchical data structures or clustering to reduce Gaussian count, multi-scale filtering modifies the Gaussian's covariance and opacity directly to match the physical sampling limits of the camera sensor [G].

### [Virtual Memory for 3D Gaussian Splatting](8403-virtual-memory-for-3d-gaussian-splatting.md)
Virtual Memory for 3D Gaussian Splatting (Vmem) enables the rendering of large-scale 3D Gaussian Splatting (3DGS) scenes that exceed available GPU memory by applying virtual texturing concepts. It groups Gaussians into fixed-size pages, uses a proxy mesh for visibility culling, and streams only visible pages into a limited GPU buffer. Unlike standard 3DGS which loads all Gaussians or relies on simple distance culling, Vmem separates virtual and physical address spaces, allowing dynamic LOD selection and just-in-time memory allocation to maintain stable frame rates in memory-constrained environments.

### [Gaussian clustering and merging](8436-gaussian-clustering-and-merging.md)
This family of methods reduces the computational cost of 3D Gaussian Splatting (3DGS) by grouping spatially or attribute-similar Gaussians into clusters and replacing them with a single representative Gaussian or a hierarchical structure. It solves the problem of excessive draw calls and memory bandwidth usage in dense scenes by enabling Level of Detail (LOD) selection and spatial culling. Unlike sibling methods that focus on virtual memory paging or specific culling pipelines, this family defines the core algorithms for *how* Gaussians are aggregated—ranging from simple arithmetic averaging to moment-matched L2-optimal merging—and how these aggregates are organized into trees or pages for efficient rendering.

### [Iterative Gaussian Synopsis](9289-iterative-gaussian-synopsis.md)
Iterative Gaussian Synopsis is a top-down strategy for constructing a hierarchy of Level of Detail (LOD) representations for 3D Gaussian Splatting [1]. It begins with a full-fidelity model and progressively derives coarser levels through adaptive, learnable pruning of anchors and downsampling of hierarchical grids, ensuring coherent simplification without the error accumulation inherent in bottom-up training. It sets itself apart from siblings like [LapisGS](6143-citygaussian-vastgaussian-dogaussian.md) by deriving coarse layers from fine ones rather than building up from coarse, and from [H-3DGS](10279-hierarchical-3d-gaussian-splatting-h-3dgs.md) by using a unified optimization with lightweight codebook/MLP updates rather than independent hierarchical structures.

### [Budgeted Gaussian Splatting](9672-budgeted-gaussian-splatting.md)
Budgeted Gaussian Splatting (BCT) is a training and deployment method for large-scale 3D Gaussian Splatting that enables continuous, variable primitive counts (Level of Detail) without retraining. It solves the problem of fixed-budget compression by constructing a Morton-ordered tree of primitives and a coverage-preserving prefix cut, allowing for near-lossless quality at low compression ratios. It distinguishes itself from sibling methods like [Hierarchical 3D Gaussian Splatting (H-3DGS)](10279-hierarchical-3d-gaussian-splatting-h-3dgs.md) and [Iterative Gaussian Synopsis](9289-iterative-gaussian-synopsis.md) by providing a single, global primitive ordering whose prefixes define successive approximations of the scene, rather than camera-dependent hierarchical selectors or discrete hierarchy methods.

### [Hierarchical 3D Gaussian Splatting (H-3DGS)](10279-hierarchical-3d-gaussian-splatting-h-3dgs.md)
Hierarchical 3D Gaussian Splatting (H-3DGS) is a method for large-scale 3D reconstruction that mitigates the memory bottlenecks of standard 3D Gaussian Splatting by training scene chunks independently and merging them into a global Level-of-Detail (LoD) hierarchy. It sets itself apart from siblings like [CityGaussian / VastGaussian / DoGaussian](6143-citygaussian-vastgaussian-dogaussian.md) and [Octree-GS](7341-octree-gs.md) by using a unified training and rendering pipeline with external memory management to handle ultra-large scenes, whereas alternatives often rely on post-processing, manual threshold tuning, or different spatial partitioning strategies.

### [Sequential Point Trees (SPTs)](10290-sequential-point-trees-spts.md)
Sequential Point Trees (SPTs) are a hierarchical data structure originally developed for point cloud rendering, adapted here for efficient, view-dependent Level-of-Detail (LoD) selection in 3D Gaussian Splatting without requiring full tree traversal. Unlike sibling methods that rely on static spatial partitioning or post-training hierarchy construction, SPTs enable dynamic LoD hierarchies that evolve continuously during optimization. They are primarily used within the Hierarchical SPT (HSPT) framework to compute the correct LoD cut efficiently for individual views and camera paths.

### FilterGS
FilterGS is a rendering acceleration method for large-scale Level-of-Detail (LoD) 3D Gaussian Splatting that eliminates inefficient serial tree traversal and reduces redundant Gaussian-tile pairs through parallel filtering and adaptive shrinking [S2]. It differs from its siblings, such as [Hierarchical 3D Gaussian Splatting (H-3DGS)](10279-hierarchical-3d-gaussian-splatting-h-3dgs.md) and [Sequential Point Trees (SPTs)](10290-sequential-point-trees-spts.md), by replacing depth-dependent serial traversal with a traversal-free, parallel filtering structure that selects a single scale for each Gaussian via a learned network, avoiding expensive tree traversal at render time [S1, unofficial][S2].

### LODGE
LODGE is a level-of-detail framework for large-scale 3D Gaussian Splatting that enables efficient rendering by dynamically selecting appropriate detail levels [S1, unofficial].

### EAGLES
EAGLES is a method that quantizes all Gaussian attributes including color, position, opacity, rotation, and scaling [S2]. Quantization of opacity leads to fewer floaters or visual artifacts in the novel view synthesis task [S2]. On the MipNeRF360 dataset, EAGLES achieves SSIM 0.81, PSNR 27.15, LPIPS 0.24, and a size of 68 MB [S2].

### SOGS (Sparse Orthographic Grid Splatting)
SOGS is a method that arranges Gaussian attributes into multiple 2D grids, sorts them, and applies a smoothness regularization to penalize pixels with values very different from their local neighborhood on the 2D grid [S2]. For storage, SOGS compresses the RGB grid with JPEG XL and stores all other attributes as 32-bit OpenEXR images with zip compression [S2]. On the MipNeRF360 dataset, SOGS achieves SSIM 0.801, PSNR 26.98, LPIPS 0.238, and a size of 28.80 MB [S2].

### 3D Gaussian Splatting Compression
This compression method does not quantize opacity and position because sharing them results in overlapping Gaussians [S2]. On the MipNeRF360 dataset, Compact3D achieves SSIM 0.808, PSNR 27.16, LPIPS 0.228, and a size of / MB (unspecified) [S2].

### Unreachable Gaussian Handling
This strategy tolerates cases where a child Gaussian becomes larger than its parent, making it impossible for the parent to fulfill the SPT cut condition, by leaving these Gaussians in RAM but not rendering them [S3, unofficial]. The steps are: identify Gaussians where the child's scale is larger than the parent's, violating the SPT cut condition; do not rebalance the hierarchy; leave these Gaussians in RAM, but never render or transfer them [S3, unofficial]. Rebalancing the hierarchy during training was experimented with but found to be too costly for little benefit. Generating improper cuts to fix this is considered worse as it derails training [S3, unofficial]. This inefficiency affects less than 10% of Gaussians in practice [S3, unofficial].

## Operating characteristics
-   **Time Complexity:** Varies by method. SPT-based methods avoid full tree traversal, offering efficient LOD selection [S3, unofficial]. Pyramid-based methods require selecting the correct resolution level, which is typically $O(1)$ or $O(\log N)$ depending on the implementation [S1, unofficial].
-   **Memory Complexity:** Significantly reduced compared to standard 3DGS. Compression methods like LightGaussian achieve up to 15$\times$ size reduction [S1, S3, unofficial]. Virtual memory methods like Vmem allow rendering scenes larger than GPU memory by streaming pages [S1, unofficial].
-   **Measured Performance:**
    -   LightGaussian: $>200$ FPS with slight quality loss [S1, S3, unofficial].
    -   EAGLES: 68 MB size, SSIM 0.81, PSNR 27.15, LPIPS 0.24 on MipNeRF360 [S2].
    -   SOGS: 28.80 MB size, SSIM 0.801, PSNR 26.98, LPIPS 0.238 on MipNeRF360 [S2].
-   **Strengths:** Enables real-time rendering of large-scale scenes; reduces memory footprint; mitigates aliasing and artifacts.
-   **Limitations:** Potential quality loss due to pruning or quantization; complexity in hierarchy construction and maintenance; edge cases like unreachable Gaussians [S3, unofficial].
-   **When to use:** Large-scale scenes (city-scale), memory-constrained environments, or when high frame rates are required.
-   **When not to use:** Small-scale scenes where standard 3DGS is sufficient, or when maximum fidelity is required without any compression artifacts.

## Background
3D Gaussian Splatting (3DGS) was introduced as a real-time radiance field rendering technique [S1, unofficial]. As applications expanded to large-scale environments (e.g., urban scenes, autonomous driving), the memory and computational demands of standard 3DGS became prohibitive [S1, S3, unofficial]. This led to the development of various LOD and compression methods. RTGS applies multi-level redundancy reduction [S1, unofficial]. Google's LODGE introduces a dynamic LOD framework [S1, unofficial]. Nvidia's HiGS proposes a hierarchical rendering architecture [S1, unofficial]. FilterGS offers a traversal-free parallel filtering structure [S1, unofficial]. These methods build on the foundational 3DGS rasterization pipeline [S1, unofficial].
