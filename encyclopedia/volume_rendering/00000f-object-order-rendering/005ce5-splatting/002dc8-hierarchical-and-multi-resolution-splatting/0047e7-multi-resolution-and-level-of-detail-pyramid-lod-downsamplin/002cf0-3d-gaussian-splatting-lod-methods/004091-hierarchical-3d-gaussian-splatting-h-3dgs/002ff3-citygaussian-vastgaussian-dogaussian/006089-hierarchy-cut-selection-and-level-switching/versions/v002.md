# Hierarchy Cut Selection and Level Switching

Also called: Granularity-based Cut Selection, Smooth Level Switching

## Overview
This method selects a specific cut through a hierarchical tree of 3D Gaussians to maximize rendering performance while maintaining visual quality, based on the projected screen size of nodes [S1]. It enables smooth transitions between hierarchy levels by interpolating Gaussian attributes rather than abruptly swapping nodes, ensuring visual continuity during level-of-detail changes [S1]. It differs from sibling methods by using a granularity-based threshold on the largest dimension of the projected bounding box to determine the cut, and by explicitly handling orientation mismatches during hierarchy generation to prevent interpolation artifacts [S1].

## How it works

### Inputs and Outputs
**Inputs:**
*   A hierarchical tree of 3D Gaussians, where each node $n$ contains a set of leaf Gaussians and stores the axis-aligned bounding box (AABB) of its contained leaf Gaussians [S1].
*   A camera view $V$ [S1].
*   A target granularity parameter $\tau_\epsilon$ (e.g., 1 pixel) [S1].

**Outputs:**
*   A set of nodes forming the "cut" through the hierarchy to be rendered [S1].
*   Interpolation weights $t_n$ for nodes undergoing transition [S1].

### Data Structures
*   **Node Structure:** Each node $n$ in the hierarchy stores:
    *   `children`: List of child nodes [S1].
    *   `parent`: Reference to parent node [S1].
    *   `leaf_gaussians`: List of 3D Gaussian primitives contained directly in this node [S1].
    *   `aabb`: Axis-aligned bounding box encompassing all leaf Gaussians contained within the subtree of $n$, pre-computed during hierarchy generation [S1].
    *   `granularity`: The projected screen size $\epsilon(n)$, computed once per view [S1].

### Step-by-Step Method

1.  **Compute Granularity:** For each node $n$ in the hierarchy, compute its granularity $\epsilon(n)$ for the current view $V$ [S1].
    *   Retrieve the AABB of node $n$ [S1].
    *   Identify the largest dimension of this bounding box, denoted as $L_{max}(n)$ [S1].
    *   Project $L_{max}(n)$ onto the screen plane using the camera projection matrix for view $V$ [S1]. Let the resulting screen-space length be $\epsilon(n)$ [S1].

2.  **Select Cut:** Identify the nodes to include in the rendering cut [S1].
    *   Iterate through all nodes $n$ in the hierarchy [S1].
    *   A node $n$ is included in the cut if:
        1.  $\epsilon(n) < \tau_\epsilon$ (the node's projected size is smaller than the target granularity) [S1].
        2.  $\epsilon(parent(n)) \ge \tau_\epsilon$ (the parent's projected size is not smaller than the target granularity) [S1].
    *   This logic ensures that for any branch, either all children are selected (if the parent is too large) or the parent is selected (if all children are small enough), but never a mix that violates the hierarchy structure [S1].
    *   Due to the hierarchy generation properties, the AABB of a parent can never appear smaller than one of its children in screen space, guaranteeing a valid cut [S1].

3.  **Calculate Interpolation Weights:** For nodes $n$ that are in a transition state, calculate the interpolation weight $t_n$ [S1].
    *   If node $n$ is in the cut and its parent $p$ is not (or vice versa), compute:
        $$ t_n = \frac{\tau_\epsilon - \epsilon(n)}{\epsilon(p) - \epsilon(n)} $$
    *   Clamp $t_n$ to $[0, 1]$ [S1].
    *   If $t_n = 0$, use the parent's attributes [S1]. If $t_n = 1$, use the child's attributes [S1]. Intermediate values blend the attributes [S1].

4.  **Interpolate Gaussian Attributes:** For each Gaussian in the cut (or blending between parent and child), interpolate its properties [S1].
    *   **Position, Color, Spherical Harmonics:** Interpolate linearly using $t_n$ [S1].
    *   **Covariance:** Do not interpolate the covariance matrix directly [S1]. Instead:
        1.  Decompose the covariance into scale and rotation components for both parent and child [S1].
        2.  Interpolate the scale linearly [S1].
        3.  Interpolate the rotation linearly (not using slerp) [S1].
        4.  Reconstruct the covariance from the interpolated scale and rotation [S1].
    *   **Opacity ($\alpha$):** Interpolate opacity carefully to maintain color consistency [S1].
        *   At the start of the transition, the children share the parent's attributes initially [S1].
        *   To ensure the blended color of the children equals the parent's color at the start of the transition, modify the child's opacity $\alpha'$ using the parent's opacity $\alpha_p$ [S1].
        *   For two children, solve for $\alpha'$ in the equation:
            $$ \alpha_p c_p = \alpha' c_p + (1 - \alpha') \alpha' c_p $$
        *   This yields:
            $$ \alpha' = \frac{1}{1 - (1 - \alpha_p) \frac{1}{2}} $$
        *   Use this $\alpha'$ to blend $\alpha$ from the parent to the children using the same linear interpolation scheme as other attributes [S1].

5.  **Orientation Matching (Pre-computation):** During hierarchy generation (not per-frame), perform orientation matching to prevent interpolation artifacts [S1].
    *   Starting from the root, recursively reinterpret the axes of orientation for each child Gaussian [S1].
    *   The goal is to minimize the relative rotation between the child node and its parent [S1].
    *   This is done via exhaustive search over possible axis permutations/rotations [S1].
    *   This step prevents undesired rotations when interpolating Gaussians with the same shape (covariance) but different rotation/scaling orientations [S1].

    depth = camera_view.depth
    if depth == 0:
        depth = 1e-6  # Guard against division by zero [G]
    return (focal_length * length_3d) / depth

def compute_granularity(node, camera_view):
    """Computes the projected screen size of the largest dimension of the node's AABB."""
    aabb_min = node.aabb.min
    aabb_max = node.aabb.max
    max_dim = max(aabb_max.x - aabb_min.x, aabb_max.y - aabb_min.y, aabb_max.z - aabb_min.z)
    return project_to_screen(max_dim, camera_view)

def select_cut(hierarchy_root, target_granularity, camera_view):
    """Selects the cut through the hierarchy based on granularity."""
    cut_nodes = []
    transition_nodes = []
    
    # Pre-compute granularity for all nodes
    for node in hierarchy_root.traverse_all():
        node.granularity = compute_granularity(node, camera_view)
        
    # Find the cut
    for node in hierarchy_root.traverse_all():
        if node.parent is None:
            continue
            
        parent = node.parent
        child_gran = node.granularity
        parent_gran = parent.granularity
        
        # Condition: Child is smaller than threshold, Parent is not
        if child_gran < target_granularity and parent_gran >= target_granularity:
            cut_nodes.append(node)
            # Calculate interpolation weight
            denominator = parent_gran - child_gran
            if denominator == 0:
                t_n = 1.0  # Guard for degenerate case [G]
            else:
                t_n = (target_granularity - child_gran) / denominator
            t_n = max(0.0, min(1.0, t_n))  # Clamp to [0, 1]
            transition_nodes.append((node, parent, t_n))
            
    return cut_nodes, transition_nodes

def interpolate_gaussian_attributes(parent_gauss, child_gauss, t, alpha_p):

### Parameters
*   $\tau_\epsilon$: Target granularity. Typical value: 1 pixel [S1].
*   $\alpha_p$: Parent opacity.

### Edge Cases and Pitfalls
*   **Direct Covariance Interpolation:** Interpolating the covariance matrix directly causes undesired rotation artifacts when Gaussians have the same shape but different rotation/scaling orientations [S1]. This is mitigated by interpolating scale and rotation separately [S1].
*   **Orientation Mismatch:** Without orientation matching during hierarchy generation, interpolating Gaussians with the same covariance but different axes leads to visual disturbances [S1]. Exhaustive search is used to minimize relative rotation between parent and child axes [S1].
*   **Opacity Blending:** Incorrect opacity blending can cause color inconsistencies during transitions [S1]. The specific formula for $\alpha'$ ensures that the blended color of the children matches the parent's color at the start of the transition [S1].
*   **Division by Zero:** If $\epsilon(p) = \epsilon(n)$, the interpolation weight calculation involves division by zero [S1]. A guard value is applied in implementation [G].

## Operating characteristics

*   **Time Complexity:** The cut can be found in linear time $O(N)$ with respect to the number of nodes, or in constant time per node in a massively parallel setting [S1].
*   **Performance:** Maximizes rendering performance by selecting the coarsest possible nodes that still meet the visual quality threshold (granularity) [S1].
*   **Visual Quality:** Maintains visual quality by ensuring smooth transitions between levels of detail through attribute interpolation [S1].
*   **Strengths:** Linear time cut selection, smooth transitions, handles orientation mismatches [S1].
*   **Limitations:** Requires pre-computation of orientation matching during hierarchy generation [S1]. Linear interpolation of rotations may not be as accurate as slerp, but is faster and deemed sufficient [S1].
