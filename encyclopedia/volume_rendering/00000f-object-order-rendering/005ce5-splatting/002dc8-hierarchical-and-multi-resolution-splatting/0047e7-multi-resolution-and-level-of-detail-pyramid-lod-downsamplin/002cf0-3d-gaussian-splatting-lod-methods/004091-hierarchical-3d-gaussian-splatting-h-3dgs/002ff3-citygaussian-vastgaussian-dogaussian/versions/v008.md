# CityGaussian / VastGaussian / DoGaussian

Also called: City-Gaussian, CityGaussian / Hierarchical 3DGS, CityGaussian V2, DoGaussian

## Overview
CityGaussian, VastGaussian, and DoGaussian are block-based partitioning methods that enable large-scale (city-scale) 3D Gaussian Splatting by dividing scenes into overlapping tiles, training independent models per tile, and merging them at render time with Level-of-Detail (LoD) hierarchies [S1, S3, unofficial][S5]. Unlike sibling methods like Octree-GS that build a single unified hierarchy during training, these methods rely on spatial tiling and post-hoc or streaming-based LoD selection to manage memory and computational load for square-kilometer scenes [S3, S4, unofficial].

## How it works
**Inputs:** Raw image sequences (RGB/D) of a large scene; scene bounding box.
**Outputs:** A set of trained Gaussian models per block/tile, ready for merged rendering.

**Data Structures:**
1.  **Block Grid:** The scene is partitioned into a grid of overlapping blocks (tiles). Each block contains a subset of Gaussians.
2.  **Gaussian Attributes:** Standard 3DGS parameters per Gaussian: position $\mathbf{p}$, rotation $\mathbf{q}$, scale $\mathbf{s}$, opacity $\alpha$, and spherical harmonic coefficients $\mathbf{c}_{lm}$ [S1, unofficial][S5].
3.  **LoD Pyramid:** For CityGS variants, multiple compressed versions of the Gaussians are stored per block (e.g., different compression rates $r_0, r_1, r_2$) [S5].

**Steps:**

1.  **Partitioning:** Divide the scene into spatially disjoint or overlapping blocks [S3, S4, unofficial]. VastGaussian uses spatially-disjoint regions with feathered overlap to handle lighting variations [S3, unofficial]. CityGaussian uses overlapping tiles [S3, unofficial].
2.  **Independent Training:** Train a standard 3DGS model independently for each block [S1, S3, unofficial].
    *   *VastGaussian:* Decouples appearance handling to manage varying lighting conditions across blocks [S3, unofficial].
    *   *CityGaussian:* Uses depth regularization and visibility-aware training to improve geometric consistency [S3, unofficial].
    *   *DoGaussian:* Distributes the training process across multiple nodes for scalability [S3, unofficial].
3.  **Merging/Streaming:** At render time, Gaussians from relevant blocks are loaded and merged [S1, S4, unofficial].
    *   *Overlap Handling:* If blocks overlap, Gaussians in the overlap region are merged or blended (feathering) to avoid artifacts [S3, unofficial].
4.  **LoD Selection (CityGS Variant):**
    *   **Detail Level Generation:** Apply compression (e.g., LightGaussian strategy) to trained Gaussians to create levels with different compression rates, reducing point count, feature dimensions, and precision [S5].
    *   **Bound Estimation:** Estimate block bounds $\mathbf{p}_{min}^j, \mathbf{p}_{max}^j$ using Median Absolute Deviation (MAD) to ignore floaters [S5]:
        $$
        MAD_j = \mathrm{median}\left( \left| \mathbf{p}_k^j - \mathrm{median}\left( \mathbf{p}_k^j \right) \right| \right)
        $$
        $$
        \mathbf{p}_{min}^j = \max\left( \min\left( \mathbf{p}_k^j \right), \mathrm{median}\left( \mathbf{p}_k^j \right) - n_{MAD} \times MAD_j \right)
        $$
        $$
        \mathbf{p}_{max}^j = \min\left( \max\left( \mathbf{p}_k^j \right), \mathrm{median}\left( \mathbf{p}_k^j \right) + n_{MAD} \times MAD_j \right)
        $$
        where $\mathbf{p}_k^j$ are the positions of Gaussians in block $j$, and $n_{MAD}$ is a hyperparameter [S5].
    *   **LoD Assignment:** Calculate the minimum distance from the block's eight corners to the camera center. Assign a detail level based on this distance [S5].
    *   **Frustum Culling:** Project corners in front of the camera to screen space, create a bounding box, and calculate Intersection-over-Union (IoU) with the screen area. Include the block if IoU indicates intersection or if the camera is inside the block [S5].
    *   **Fusion:** Concatenate Gaussians from different detail levels directly for rendering [S5].

**Parameters:**
*   $n_{MAD}$: MAD multiplier for bound estimation [S5].
*   Compression rates $r_0, r_1, r_2$: For LoD levels [S5].
*   Block size/overlap: Not given in the sources.

**Edge Cases:**
*   **Floaters:** Standard 3DGS floaters can distort block bounds. MAD is used to mitigate this [S5].
*   **Boundary Artifacts:** Overlapping blocks require careful merging to avoid double-rendering or seams [S3, unofficial].

## Subtopics

### CityGS-X
A method that extends block-based partitioning with a geometry-aware architecture that refines block boundaries according to building footprints, achieving highly accurate urban reconstruction [S1, unofficial]. It targets large-scale urban scenes by combining semantic segmentation to allocate Gaussians only on building facades and road surfaces [S1, unofficial].

### Proxy-GS
A method that uses a coarse proxy mesh to guide Gaussian placement, significantly reducing the number of Gaussians required for background regions [S1, unofficial].

### CityGS Level-of-Detail (LoD)
A rendering optimization technique that generates multiple detail levels of Gaussians and selects them per block based on distance to camera, reducing rasterizer load [S5]. It uses LightGaussian compression to create levels with different compression rates, robust bound estimation via MAD, and IoU-based frustum culling for block selection [S5].

## Operating characteristics
*   **Time Complexity:** Training is parallelizable across blocks/nodes [S3, S4, unofficial]. Rendering complexity depends on the number of visible blocks and their LoD levels.
*   **Memory Complexity:** Significantly reduced compared to flat 3DGS by only loading relevant blocks and lower-detail Gaussians for distant regions [S3, unofficial][S5].
*   **Performance:** Enables interactive exploration of square-kilometer scenes [S2, S3, unofficial].
*   **Strengths:** Scalability to city-scale; modular training; memory efficiency via LoD.
*   **Limitations:** Potential boundary artifacts between blocks; requires careful overlap management; training independence may lead to global consistency issues (addressed by variants like Momentum-GS) [S2, S3, unofficial].

## Background
Originated with VastGaussian (CVPR'24) and CityGaussian (CityGaussian/CityGaussianV2) for city-scale reconstruction [S3, unofficial]. DoGaussian extended this with distributed training [S3, unofficial]. These methods address the memory bottlenecks of standard 3DGS in large scenes by using block-based partitioning and LoD hierarchies [S1, S3, S4, unofficial].
