# Hierarchy Cut Selection and Level Switching

Also called: Granularity-based Cut Selection, Smooth Level Switching

## Overview
This method selects a specific cut through a hierarchical tree of 3D Gaussians to maximize rendering performance while maintaining visual quality, based on the projected screen size of nodes [S1]. It enables smooth transitions between hierarchy levels by interpolating Gaussian attributes (position, color, covariance) rather than abruptly swapping nodes, ensuring visual continuity during level-of-detail changes [S1]. It differs from sibling methods by using a granularity-based threshold on the largest dimension of the projected bounding box to determine the cut, and by explicitly handling orientation mismatches during hierarchy generation to prevent interpolation artifacts [S1].

## How it works

### Inputs and Outputs
**Inputs:**
*   A hierarchical tree of 3D Gaussians, where each node $n$ contains a set of leaf Gaussians and stores the axis-aligned bounding box (AABB) of its contained leaf Gaussians [S1].
*   A camera view $V$ [S1].
*   A target granularity parameter $\tau_\epsilon$ (e.g., 1 pixel) [S1].

**Outputs:**
*   A set of nodes forming the "cut" through the hierarchy to be rendered [S1].
*   Interpolation weights $t_n$ for nodes undergoing transition [S1].

### Data Structures
*   **Node Structure:** Each node $n$ in the hierarchy stores:
    *   `children`: List of child nodes.
    *   `parent`: Reference to parent node.
    *   `leaf_gaussians`: List of 3D Gaussian primitives contained directly in this node (if it is a leaf in the hierarchy, or the base primitives if it is an internal node aggregating leaves).
    *   `aabb`: Axis-aligned bounding box encompassing all leaf Gaussians contained within the subtree of $n$. This is pre-computed during hierarchy generation [S1].
    *   `granularity`: The projected screen size $\epsilon(n)$, computed once per view [S1].

### Step-by-Step Method

1.  **Compute Granularity:** For each node $n$ in the hierarchy, compute its granularity $\epsilon(n)$ for the current view $V$.
    *   Retrieve the AABB of node $n$.
    *   Identify the largest dimension of this bounding box, denoted as $L_{max}(n)$ [S1].
    *   Project $L_{max}(n)$ onto the screen plane using the camera projection matrix for view $V$. Let the resulting screen-space length be $\epsilon(n)$ [S1].

2.  **Select Cut:** Identify the nodes to include in the rendering cut.
    *   Iterate through all nodes $n$ in the hierarchy.
    *   A node $n$ is included in the cut if:
        1.  $\epsilon(n) < \tau_\epsilon$ (the node's projected size is smaller than the target granularity).
        2.  $\epsilon(parent(n)) \ge \tau_\epsilon$ (the parent's projected size is not smaller than the target granularity).
    *   This logic ensures that for any branch, either all children are selected (if the parent is too large) or the parent is selected (if all children are small enough), but never a mix that violates the hierarchy structure [S1].
    *   Note: Due to the hierarchy generation properties, the AABB of a parent can never appear smaller than one of its children in screen space, guaranteeing a valid cut [S1].

3.  **Calculate Interpolation Weights:** For nodes $n$ that are in a transition state (i.e., they are candidates for inclusion but their parent is also being considered or they are blending with their parent), calculate the interpolation weight $t_n$.
    *   If node $n$ is in the cut and its parent $p$ is not (or vice versa, depending on the transition direction), compute:
        $$ t_n = \frac{\tau_\epsilon - \epsilon(n)}{\epsilon(p) - \epsilon(n)} $$
    *   Clamp $t_n$ to $[0, 1]$ [S1].
    *   If $t_n = 0$, use the parent's attributes. If $t_n = 1$, use the child's attributes. Intermediate values blend the attributes [S1].

4.  **Interpolate Gaussian Attributes:** For each Gaussian in the cut (or blending between parent and child), interpolate its properties.
    *   **Position, Color, Spherical Harmonics:** Interpolate linearly using $t_n$ [S1].
    *   **Covariance:** Do **not** interpolate the covariance matrix directly. Instead:
        1.  Decompose the covariance into scale and rotation components for both parent and child.
        2.  Interpolate the scale linearly.
        3.  Interpolate the rotation linearly (not using slerp) [S1].
        4.  Reconstruct the covariance from the interpolated scale and rotation [S1].
    *   **Opacity ($\alpha$):** Interpolate opacity carefully to maintain color consistency.
        *   At the start of the transition (when blending parent to children), the children share the parent's attributes initially.
        *   To ensure the blended color of the children equals the parent's color at the start of the transition, modify the child's opacity $\alpha'$ using the parent's opacity $\alpha_p$.
        *   For two children, solve for $\alpha'$ in the equation:
            $$ \alpha_p c_p = \alpha' c_p + (1 - \alpha') \alpha' c_p $$
        *   This yields:
            $$ \alpha' = \frac{1}{1 - (1 - \alpha_p) \frac{1}{2}} $$
        *   Use this $\alpha'$ to blend $\alpha$ from the parent to the children using the same linear interpolation scheme as other attributes [S1].

5.  **Orientation Matching (Pre-computation):** During hierarchy generation (not per-frame), perform orientation matching to prevent interpolation artifacts.
    *   Starting from the root, recursively reinterpret the axes of orientation for each child Gaussian.
    *   The goal is to minimize the relative rotation between the child node and its parent.
    *   This is done via exhaustive search over possible axis permutations/rotations [S1].
    *   This step prevents undesired rotations when interpolating Gaussians with the same shape (covariance) but different rotation/scaling orientations [S1].

def select_cut(hierarchy_root, target_granularity, camera_view):
    """
    Selects the cut through the hierarchy based on granularity.
    Returns a list of nodes to render and their interpolation weights.
    """
    cut_nodes = []
    transition_nodes = [] # Nodes that need blending with parent
    
    # Pre-compute granularity for all nodes
    # In practice, this can be done in a single pass or cached
    for node in hierarchy_root.traverse_all():
        node.granularity = compute_granularity(node, camera_view)
        
    # Find the cut
    for node in hierarchy_root.traverse_all():
        if node.parent is None:
            continue
            
        parent = node.parent
        child_gran = node.granularity
        parent_gran = parent.granularity
        
        # Condition: Child is smaller than threshold, Parent is not
        if child_gran < target_granularity and parent_gran >= target_granularity:
            cut_nodes.append(node)
            # This node is transitioning from parent to child
            # Calculate interpolation weight
            # t_n = (tau - epsilon(n)) / (epsilon(p) - epsilon(n))
            denominator = parent_gran - child_gran
            if denominator == 0:
                t_n = 1.0 # Avoid division by zero, though logically parent >= child
            else:
                t_n = (target_granularity - child_gran) / denominator
            t_n = clamp(t_n, 0.0, 1.0)
            transition_nodes.append((node, parent, t_n))
            
    return cut_nodes, transition_nodes

### Parameters
*   $\tau_\epsilon$: Target granularity. Typical value: 1 pixel [S1].
*   $\alpha_p$: Parent opacity.

### Edge Cases and Pitfalls
*   **Direct Covariance Interpolation:** Interpolating the covariance matrix directly causes undesired rotation artifacts when Gaussians have the same shape but different rotation/scaling orientations [S1]. This is mitigated by interpolating scale and rotation separately [S1].
*   **Orientation Mismatch:** Without orientation matching during hierarchy generation, interpolating Gaussians with the same covariance but different axes leads to visual disturbances [S1]. Exhaustive search is used to minimize relative rotation between parent and child axes [S1].
*   **Opacity Blending:** Incorrect opacity blending can cause color inconsistencies during transitions. The specific formula for $\alpha'$ ensures that the blended color of the children matches the parent's color at the start of the transition [S1].
*   **Division by Zero:** If $\epsilon(p) = \epsilon(n)$, the interpolation weight calculation involves division by zero. This should be handled by clamping or defaulting to 1.0 [S1].

## Operating characteristics

*   **Time Complexity:** The cut can be found in linear time $O(N)$ with respect to the number of nodes, or in constant time per node in a massively parallel setting [S1].
*   **Memory Complexity:** Requires storing the hierarchy tree and pre-computed AABBs and granularities. The memory overhead is proportional to the number of nodes in the hierarchy [S1].
*   **Performance:** Maximizes rendering performance by selecting the coarsest possible nodes that still meet the visual quality threshold (granularity) [S1].
*   **Visual Quality:** Maintains visual quality by ensuring smooth transitions between levels of detail through attribute interpolation [S1].
*   **Strengths:** Linear time cut selection, smooth transitions, handles orientation mismatches.
*   **Limitations:** Requires pre-computation of orientation matching during hierarchy generation. Linear interpolation of rotations may not be as accurate as slerp, but is faster and deemed sufficient [S1].
