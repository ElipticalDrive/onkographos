# Octree-GS

Also called: Octree Gaussian Splatting, Towards Consistent Real-time Rendering with LOD-Structured 3D Gaussians

## Overview
Octree-GS is a hierarchical Level-of-Detail (LoD) method that builds an octree over the scene, associating each node with a merged Gaussian that summarizes the radiance and opacity of its children [S1, unofficial]. It solves the problem of inconsistent rendering performance and excessive memory usage in large-scale 3D Gaussian Splatting (3DGS) by dynamically selecting appropriate levels from a set of multi-scale Gaussian primitives organized in an octree [S5]. Unlike siblings that require post-processing or manual threshold tuning, Octree-GS achieves LoD effects in a single end-to-end training round using a cumulative LOD strategy and a progressive grow-and-prune mechanism [S5].

## How it works
**Inputs:** Sparse Structure-from-Motion (SfM) points, training images with camera poses and intrinsics [S5].
**Outputs:** An octree-structured set of anchors, each associated with $k$ Gaussian primitives (explicit or neural), and learnable LOD biases [S5].

**Data Structures:**
*   **Octree:** A sparse octree with $K$ layers (levels) [S5].
*   **Anchor:** Defined by position (center of a voxel), a learnable LOD bias $\Delta L_j$, and a set of $k$ Gaussian primitives [S5].
*   **Gaussian Primitive:** Standard 3DGS parameters (mean $\mu$, covariance $\Sigma$, opacity $\alpha$, spherical harmonics coefficients for color) [S5].
*   **Voxel Size:** For layer $L$, voxel size $V_L = \delta / 2^L$, where $\delta$ is the base voxel size for LOD 0 [S5].

**Parameters:**
*   $r_d$: Outlier discard ratio for distance calculation (default 0.999) [S5].
*   $\delta$: Base voxel size for LOD 0 (default 0.02 for intermediate levels, 0.001 for modified anchor versions in comparisons) [S5].
*   $\tau_g$: Gradient threshold for growing (default 0.0002) [S5].
*   $\beta$: Exponential growth difficulty factor (default 0.2) [S5].
*   $\epsilon$: LOD bias increment (default 0.01) [S5].
*   $\tau_v$: Visibility threshold for pruning (0.7 small-scale, 0.01 large-scale, 0.2 multi-scale) [S5].
*   $T$: Densification interval (default 100 iterations) [S5].
*   $s$: Focal scale factor for varying intrinsics [S5].

**Algorithm Steps:**

1.  **Anchor Initialization:**
    *   Calculate distance $d_{ij}$ between each training camera center $i$ and each SfM point $j$ [S5].
    *   Determine $d_{max}$ as the $r_d$-th largest distance and $d_{min}$ as the $r_d$-th smallest distance [S5].
    *   Calculate number of octree layers:
        $$ K = \lfloor \log_2(d_{max}/d_{min}) \rceil + 1 $$
        where $\lfloor \cdot \rceil$ denotes the round operator [S5].
    *   Construct octree grids with $K$ layers [S5].
    *   Initialize anchors at voxel centers for each layer $L \in [0, K-1]$ with voxel size $V_L = \delta / 2^L$ [S5].
    *   Assign initial LOD level $L_j = L$ to anchors in layer $L$ [S5].
    *   Initialize learnable LOD bias $\Delta L_j = 0$ for each anchor $j$ [S5].

2.  **Progressive Training (Grow-and-Prune):**
    *   Run training for $N_{total}$ iterations (40k for small-scale, 100k for large-scale) [S5].
    *   **Progressive Phase (First 10k iterations):**
        *   Optimize anchors with weight $\omega = 1.5$ [S5].
    *   **Densification Phase (Every $T$ iterations):**
        *   Calculate average accumulated gradient $\nabla g$ of spawned Gaussian primitives [S5].
        *   **Growing:**
            *   If $\nabla g > \tau_g$ and the primitive is in an empty voxel, convert to a new anchor [S5].
            *   Assign LOD level using "next-level" growth:
                *   Threshold for level $L$: $\tau_{gL} = \tau_g \cdot 2^{\beta L}$ [S5].
                *   If $\nabla g > \tau_{g(L+1)}$, promote to level $L+1$ [S5].
                *   If $\tau_{gL} < \nabla g \le \tau_{g(L+1)}$, keep at level $L$ [S5].
            *   **Bias Adjustment:**
                *   Calculate anchor gradient $\nabla v$ (average gradient of spawned primitives for that anchor) [S5].
                *   If $\nabla v > \tau_{gL} \cdot 0.25$, update bias: $\Delta L_j \leftarrow \Delta L_j + \epsilon$ [S5].
        *   **Pruning:**
            *   Compute average opacity of Gaussians generated over the last $T$ iterations [S5].
            *   Remove anchors with low average opacity [S5].
            *   Compute view-frequency (probability anchor is selected in training views) [S5].
            *   Remove anchors with view-frequency $< \tau_v$ [S5].

3.  **Rendering (Inference):**
    *   For a given viewpoint $i$ and anchor $j$ at distance $d_{ij}$:
        *   Calculate estimated LOD level:
            $$ \hat{L}_{ij} = \lfloor \Phi(\log_2(d_{max} / (d_{ij} \cdot s))) + \Delta L_j \rfloor $$
            where $\Phi(\cdot)$ clamps the value to $[0, K-1]$ [S5].
        *   **Selection:**
            *   Select anchor $j$ if its assigned level $L_j \le \hat{L}_{ij}$ [S5].
            *   **Opacity Blending:** To ensure smooth transitions, also select "nearly satisfied" anchors where $L_j = \hat{L}_{ij} + 1$ [S5]. Scale their opacities by $(\hat{L}_{ij} - L_j)$ [S5].
    *   Rasterize selected Gaussian primitives using standard 3DGS splatting [S5].

**Edge Cases and Pitfalls:**
*   **Precision:** The fractional LOD level $\log_2(d_{max} / (d_{ij} \cdot s))$ can suffer from floating-point inaccuracies at extreme distances; clamping via $\Phi(\cdot)$ prevents out-of-bounds indexing [S5].
*   **Boundaries:** Anchors at the octree boundary must be handled carefully during voxelization to avoid missing primitives; the sparse octree structure inherently handles this by only allocating nodes for occupied regions [S5].
*   **Degenerate Input:** If $d_{max} \approx d_{min}$, $K$ collapses to 1, degrading to a single-level grid; the source assumes a bounded scene with sufficient depth variation [S5].
*   **Opacity Blending:** The source specifies scaling nearly satisfied anchors by $(\hat{L}_{ij} - L_j)$, which evaluates to $-1$ for integer levels. Implementations should clamp the resulting opacity to $[0, 1]$ or interpret the factor as a weight for piecewise linear interpolation between adjacent LOD levels [S5].

**Pseudocode:**

```python
import math

class Anchor:
    def __init__(self, pos, L):
        self.pos = pos
        self.L = L
        self.delta_L = 0.0
        self.gradients = []
        self.opacity_history = []
        self.view_frequency = 0.0
        self.is_empty_voxel = True
        self.marked_for_removal = False
        self.primitives = []

class GaussianPrimitive:
    def __init__(self):
        self.opacity = 1.0

def average(values):
    return sum(values) / len(values) if values else 0.0

def get_voxel_centers(voxel_size, bounds):
    # Standard grid generation over scene bounds
    centers = []
    x_min, y_min, z_min, x_max, y_max, z_max = bounds
    step = voxel_size
    x = x_min
    while x <= x_max:
        y = y_min
        while y <= y_max:
            z = z_min
            while z <= z_max:
                centers.append((x, y, z))
                z += step
            y += step
        x += step
    return centers

def initialize_octree(sfm_points, camera_centers, rd=0.999, delta=0.02, bounds=(0,0,0,100,100,100)):
    distances = []
    for cam in camera_centers:
        for pt in sfm_points:
            distances.append(math.dist(cam, pt))
    distances.sort()
    n = len(distances)
    idx_max = int(rd * n)
    idx_min = int((1 - rd) * n)
    d_max = distances[idx_max]
    d_min = distances[idx_min]
    K = round(math.log2(d_max / d_min)) + 1
    
    anchors = []
    for L in range(K):
        voxel_size = delta / (2 ** L)
        voxel_centers = get_voxel_centers(voxel_size, bounds)
        for center in voxel_centers:
            anchor = Anchor(center, L)
            anchor.primitives = [GaussianPrimitive() for _ in range(1)]
            anchors.append(anchor)
    return anchors, K, d_max

def select_anchors(anchors, camera, d_max, s, K):
    selected = []
    blended = []
    for anchor in anchors:
        d_ij = math.dist(camera.pos, anchor.pos)
        raw_lod = math.log2(d_max / (d_ij * s)) + anchor.delta_L
        clamped_lod = max(0.0, min(K - 1, raw_lod))
        L_hat = math.floor(clamped_lod)
        
        if anchor.L <= L_hat:
            selected.append(anchor)
        elif anchor.L == L_hat + 1:
            blend_factor = L_hat - anchor.L
            for prim in anchor.primitives:
                prim.opacity = max(0.0, prim.opacity * blend_factor)
            blended.append(anchor)
    return selected, blended

def grow_and_prune(anchors, T, tau_g=0.0002, beta=0.2, epsilon=0.01, tau_v=0.01, opacity_threshold=0.0):
    for anchor in anchors:
        if len(anchor.gradients) > 0:
            avg_grad = average(anchor.gradients)
            tau_L = tau_g * (2 ** (beta * anchor.L))
            tau_L_next = tau_g * (2 ** (beta * (anchor.L + 1)))
            
            if avg_grad > tau_g and anchor.is_empty_voxel:
                if avg_grad > tau_L_next:
                    anchor.L += 1
                if avg_grad > tau_L * 0.25:
                    anchor.delta_L += epsilon
            
        if len(anchor.opacity_history) > 0:
            avg_opa = average(anchor.opacity_history)
            if avg_opa < opacity_threshold:
                anchor.marked_for_removal = True
                
        if anchor.view_frequency < tau_v:
            anchor.marked_for_removal = True
            
    return [a for a in anchors if not a.marked_for_removal()]
```

## Operating characteristics
*   **Time Complexity:** Rendering is $O(N_{selected})$ where $N_{selected}$ is the number of anchors selected for the current view. Training involves densification every $T$ iterations, adding overhead but reducing total primitives compared to vanilla 3DGS [S5].
*   **Memory Complexity:** Significantly reduced compared to vanilla 3DGS and Hierarchical-GS. On MatrixCity, Octree-GS uses 3.59M Gaussians vs 20.8M for Hierarchical-GS [S5].
*   **Performance:** On MatrixCity (2k resolution), Octree-GS achieves 32.0 FPS with 3.59M Gaussians in zoom-out views, compared to 6.91 FPS for Hierarchical-GS [S5]. It is up to 10x faster than state-of-the-art methods in large-scale scenes [S5]. On Mip-NeRF360, training time is 20-23 minutes vs 38-69 minutes for Hierarchical-GS [S5].
*   **Strengths:** End-to-end training, no manual threshold tuning, smooth LOD transitions, handles multi-resolution datasets well [S5].
*   **Limitations:** Requires careful tuning of $\tau_v$ for different scene scales. The opacity blending formula in the source specifies scaling nearly satisfied anchors by $(\hat{L}_{ij} - L_j)$, which evaluates to $-1$ for integer levels and requires clamping or reinterpretation as an interpolation weight [S5].

## Background
Octree-GS was introduced in 2024 by researchers associated with the "CitySuper" project [S5]. It is the first approach to deal with Level-of-Detail in Gaussian representation using an explicit octree structure [S5]. It builds upon Scaffold-GS [3] and 3DGS [5].
