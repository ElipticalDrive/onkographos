# CityGaussian / VastGaussian / DoGaussian

Also called: City-Gaussian, CityGaussian / Hierarchical 3DGS, CityGaussian V2, DoGaussian

## Overview
CityGaussian, VastGaussian, and DoGaussian are methods for large-scale urban reconstruction that partition scenes into overlapping or disjoint blocks, train independent 3D Gaussian Splatting (3DGS) models per block, and merge them at render time using a Level-of-Detail (LoD) hierarchy [S1, S3, unofficial][S5]. They solve the memory and training bottlenecks of standard 3DGS in city-scale scenes by enabling distributed or block-wise training and streaming [S2, S3, unofficial]. They set themselves apart from sibling methods like [Octree-GS](7341-octree-gs.md) by relying on tile-based training and merging rather than a single unified anchor-based hierarchy, and from [Iterative Gaussian Synopsis](9289-iterative-gaussian-synopsis.md) by using explicit spatial partitioning for training rather than iterative synopsis generation [S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Raw images/videos of a large-scale scene (city-scale, square kilometers); camera poses; optionally semantic segmentation or proxy meshes for variants.
*   **Output:** A set of trained 3DGS models per block, a spatial hierarchy (LoD pyramid) for streaming, and a renderer capable of merging blocks with overlap.

**Data Structures:**
*   **Block:** A spatial region (tile) of the scene. Defined by bounding box bounds $\mathbf{p}_{min}^j, \mathbf{p}_{max}^j$ [S5].
*   **Block Gaussian Set:** A standard 3DGS primitive set (position $\mathbf{p}$, covariance $\Sigma$, color SH coefficients, opacity $\alpha$) trained independently for the block [S1, S3, unofficial].
*   **LoD Pyramid:** Multiple compressed versions of each block's Gaussian set, generated via compression strategies like LightGaussian [S5].

**Steps:**

1.  **Partitioning:** Divide the large scene into spatially overlapping or disjoint blocks (tiles) [S1, S3, unofficial][S5]. VastGaussian uses spatially-disjoint regions [S3, unofficial]. CityGaussian uses overlapping tiles to handle boundaries [S3, unofficial].
2.  **Block Training:** Train a standard 3DGS model independently for each block [S1, S3, unofficial].
    *   *VastGaussian:* Handles varying lighting by decoupling appearance handling per block [S3, unofficial].
    *   *DoGaussian:* Distributes training across multiple nodes [S3, unofficial].
    *   *CityGaussian V2:* Uses depth regularization and visibility-aware training [S3, unofficial].
3.  **Boundary Handling (Overlap):** For overlapping blocks, merge Gaussians at boundaries using feathered overlap to reduce artifacts [S3, unofficial].
4.  **LoD Generation (CityGS-X/CityGaussian):** Generate multiple detail levels for each block [S5].
    *   Apply LightGaussian compression strategy to trained Gaussians to create levels with different compression rates $r_0, r_1, r_2$, reducing points, feature dimensions, and precision [S5].
5.  **Bounding Box Estimation:** Estimate robust block bounds to avoid floaters [S5].
    *   Use Median Absolute Deviation (MAD) to determine block bounds $\mathbf{p}_{min}^j, \mathbf{p}_{max}^j$ [S5].
    *   Formula for $j$-th block:
        $$
        \begin{aligned}
        MAD_j &= \mathrm{median}\left( \left| \mathbf{p}_k^j - \mathrm{median}\left( \mathbf{p}_k^j \right) \right| \right), \\
        \mathbf{p}_{min}^j &= \max \left( \min \left( \mathbf{p}_k^j \right), \mathrm{median}\left( \mathbf{p}_k^j \right) - n_{MAD} \times MAD_j \right), \\
        \mathbf{p}_{max}^j &= \min \left( \max \left( \mathbf{p}_k^j \right), \mathrm{median}\left( \mathbf{p}_k^j \right) + n_{MAD} \times MAD_j \right),
        \end{aligned}
        $$
        where $\mathbf{p}_k^j$ are the positions of Gaussians in block $j$, and $n_{MAD}$ is a hyperparameter [S5].
6.  **LoD Selection:** Determine the detail level for each block based on camera distance [S5].
    *   Calculate the minimum distance from the block's eight corners to the camera center.
    *   Assign the detail level based on this distance (closer = higher detail) [S5].
7.  **Frustum Culling:** Determine visible blocks [S5].
    *   Project corners in front of the camera to screen space.
    *   Create a bounding box from projected points.
    *   Calculate Intersection-over-Union (IoU) with screen area.
    *   Include block if IoU indicates intersection or if the camera is inside the block [S5].
8.  **Rendering (Fusion):** Concatenate Gaussians from different detail levels directly for rendering [S5].
    *   For overlapping blocks, merge with feathered overlap [S3, unofficial].
    *   Direct concatenation of different detail levels generates negligible discontinuity [S5].

**Parameters:**
*   $n_{MAD}$: MAD scaling factor for bounding box estimation. Not given in the sources.
*   Compression rates $r_0, r_1, r_2$: LightGaussian compression rates. Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Floaters:** Standard min/max coordinates of Gaussians are often determined by floaters, leading to unreasonably enlarged volumes and fake intersections. MAD is used to mitigate this [S5].
*   **Boundary Artifacts:** Overlapping blocks require careful merging (feathering) to avoid visible seams [S3, unofficial].
*   **Lighting Variations:** VastGaussian addresses this by decoupling appearance handling, as lighting conditions may vary significantly across disjoint blocks [S3, unofficial].

## Subtopics

### CityGS-X
CityGS-X extends block-based partitioning with a geometry-aware architecture that refines block boundaries according to building footprints, achieving highly accurate urban reconstruction [S1, unofficial]. It targets large-scale urban scenes by combining semantic segmentation to allocate Gaussians only on building facades and road surfaces [S1, unofficial].

### Proxy-GS
Proxy-GS uses a coarse proxy mesh to guide Gaussian placement, significantly reducing the number of Gaussians required for background regions [S1, unofficial].

### CityGS Level-of-Detail (LoD)
CityGS Level-of-Detail is a rendering optimization technique that generates multiple detail levels of Gaussians and selects them per block based on distance to camera, reducing rasterizer load [S5]. It generates detail levels using LightGaussian compression, estimates block bounds using MAD, determines LoD per block based on minimum corner distance, performs frustum culling via IoU, and fuses levels via direct concatenation [S5].

## Operating characteristics
*   **Time Complexity:** Training is parallelizable across blocks/nodes [S3, unofficial]. Rendering requires block-wise visibility culling and merging, which adds overhead compared to flat 3DGS but reduces the number of Gaussians processed per frame via LoD [S5].
*   **Memory Complexity:** Significantly reduced compared to training a single global model. Memory is distributed across blocks and compressed via LoD [S3, unofficial][S5].
*   **Measured Performance:** CityGaussian enables real-time rendering of square-kilometer scenes [S3, unofficial]. Production compression baselines (pruning, SH distillation, quantization) can achieve $8\text{–}20\times$ size reduction with $<0.5$ dB PSNR drop [S3, unofficial].
*   **Strengths:** Scalability to city-scale scenes; distributed training; streaming capability via LoD [S2, S3, unofficial].
*   **Limitations:** Potential boundary artifacts between blocks; complexity in managing overlapping regions; dependency on accurate block partitioning [S3, unofficial].
*   **When to use:** Large-scale urban reconstruction, autonomous driving simulation, interactive city exploration [S2, S3, unofficial].
*   **When not to use:** Small-scale scenes where global optimization is feasible and boundary artifacts are undesirable [S3, unofficial].

## Background
CityGaussian, VastGaussian, and DoGaussian originated from the need to scale 3D Gaussian Splatting to city-scale environments [S1, S3, unofficial]. VastGaussian was presented at CVPR'24, focusing on spatially-disjoint regions and decoupled appearance handling [S3, unofficial]. CityGaussian and its V2 variant introduced hierarchical LoD across square kilometers with depth regularization [S3, unofficial]. DoGaussian extended this to distributed training across nodes [S3, unofficial]. These methods build on the principles of Hierarchical 3D Gaussian Splatting (H-3DGS) by implementing block-based partitioning and LoD selection [S1, S3, unofficial].
