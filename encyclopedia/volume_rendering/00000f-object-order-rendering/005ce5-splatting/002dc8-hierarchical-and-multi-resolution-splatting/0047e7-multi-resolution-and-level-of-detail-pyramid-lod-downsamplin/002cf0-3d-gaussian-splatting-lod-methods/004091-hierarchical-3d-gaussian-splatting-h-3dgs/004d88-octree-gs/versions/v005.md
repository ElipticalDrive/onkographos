# Octree-GS

Also called: Octree Gaussian Splatting

## Overview
Octree-GS is a Level-of-Detail (LoD) method for 3D Gaussian Splatting that organizes Gaussian primitives into a sparse octree structure to enable consistent real-time rendering across varying viewing distances and scene complexities [S4]. It solves the problem of inefficient primitive usage and visual artifacts in large-scale scenes by dynamically selecting appropriate LOD levels based on camera distance, ensuring rendering speed remains stable regardless of trajectory changes [S4]. Unlike concurrent methods that require multi-resolution inputs, post-processing, or manual threshold tuning, Octree-GS achieves LoD effects in a single end-to-end training round using an accumulative LOD strategy [S4].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Sparse Structure-from-Motion (SfM) points, training images with camera poses and intrinsics, base voxel size $\delta$ for LOD 0, and hyperparameters ($r_d, \tau_g, \beta, \epsilon, \tau_v, T, \omega$).
*   **Outputs:** An octree-structured set of anchors, each associated with $k$ Gaussian primitives (explicit or neural), optimized for novel view synthesis.

**Data Structures:**
*   **Octree:** A hierarchical grid with $K$ layers (LOD levels). LOD 0 is the coarsest level; higher $L$ implies finer resolution.
*   **Anchor:** Located at the center of a voxel in the octree. Properties include:
    *   Position: Center of the voxel.
    *   LOD Level $L_j$: Integer indicating the granularity.
    *   LOD Bias $\Delta L_j$: Learnable scalar to adjust selection based on local complexity.
    *   Gaussians: A list of $k$ Gaussian primitives associated with the anchor.
*   **Voxel Size:** For layer $L$, voxel size $V_L = \delta / 2^L$.

**Algorithm Steps:**

1.  **Anchor Initialization:**
    *   Calculate distances $d_{ij}$ between each training camera center $i$ and each SfM point $j$.
    *   Determine $d_{max}$ and $d_{min}$ as the $r_d$-th largest and smallest distances, respectively. Typical $r_d = 0.999$ to discard outliers [S4].
    *   Calculate the number of octree layers $K$:
        $$ K = \lfloor \log_2(d_{max} / d_{min}) \rceil + 1 $$
        where $\lfloor \cdot \rceil$ denotes the round operator [S4].
    *   Construct octree-structured grids with $K$ layers.
    *   Initialize anchors at voxel centers for each layer $L$. The voxel size for layer $L$ is:
        $$ V_L = \delta / 2^L $$
        where $\delta$ is the base voxel size for LOD 0 [S4].

3.  **Anchor Growing (Training):**
    *   Every $T$ iterations (default $T=100$), calculate the average accumulated gradient $\nabla_g$ of spawned Gaussian primitives [S4].
    *   If $\nabla_g > \tau_g$ (default $\tau_g = 0.0002$), the primitive is significant.
    *   If the primitive is in an empty voxel, convert it to a new anchor.
    *   **Next-Level Growth:** Assign LOD level based on gradient magnitude. Thresholds increase exponentially: $\tau_{gL} = \tau_g \cdot 2^{\beta L}$ (default $\beta = 0.2$) [S4].
        *   If $\nabla_g > \tau_{g(L+1)}$, promote to level $L+1$.
        *   If $\tau_{gL} < \nabla_g < \tau_{g(L+1)}$, remain at level $L$.
    *   **LOD Bias Adjustment:** Calculate anchor gradient $\nabla_v$ (average gradient of spawned primitives for that anchor). If $\nabla_v > \tau_{gL} \cdot 0.25$, increase the anchor's LOD bias: $\Delta L_j = \Delta L_j + \epsilon$ (default $\epsilon = 0.01$) [S4].

4.  **Anchor Pruning (Training):**
    *   Compute average opacity of Gaussians generated over $T$ iterations.
    *   Remove anchors with low average opacity.
    *   Calculate **view-frequency**: the probability that an anchor is selected in training view frustums.
    *   Remove anchors with view-frequency below visibility threshold $\tau_v$ (default $\tau_v = 0.7$ for small scenes, $0.01$ for large, $0.2$ for multi-scale) [S4].

5.  **Progressive Training:**
    *   Run initial training for 10k iterations with weight $\omega = 1.5$.
    *   Extend densification by an additional 10k iterations [S4].
    *   Total iterations: 40k (densification ends at 20k) for small-scale scenes; 100k (densification ends at 50k) for large-scale scenes [S4].

## Operating characteristics
*   **Time Complexity:** Rendering is $O(N_{selected})$ where $N_{selected}$ is the number of selected anchors, which scales with viewing distance. Training involves octree traversal and gradient accumulation, typically 20-23 minutes for 40k iterations on Mip-NeRF360, significantly faster than Hierarchical-GS (38-69 mins) [S4].
*   **Memory Complexity:** Reduces storage overhead by pruning redundant and invisible anchors. On MatrixCity, Octree-GS uses 3.59M Gaussians compared to 20.8M for Hierarchical-GS [S4].
*   **Performance:** Achieves consistent real-time performance (≥30 FPS) on large-scale scenes. On MatrixCity (2k resolution), it achieves 57.08 FPS (Our-3D-GS) and 40.91 FPS (Our-Scaffold-GS), outperforming baselines which fail to meet real-time performance [S4]. It is up to 10x faster than state-of-the-art methods in large-scale scenes [S4].
*   **Strengths:** End-to-end training, no manual threshold tuning, robust to trajectory changes, handles multi-resolution datasets effectively without erosion artifacts [S4].
*   **Limitations:** Requires careful tuning of hyperparameters ($\tau_v, \tau_g, \beta$) for different scene scales. The opacity blending formula in the source contains a potential sign error ($\hat{L}_{ij} - L_j$ is negative for nearly satisfied anchors) [S4].

## Background
Octree-GS was introduced as a response to the limitations of existing LOD methods in 3D Gaussian Splatting, such as LetsGo, CityGaussian, and Hierarchical-GS, which either require multi-resolution inputs, post-processing, or manual adjustments [S4]. It builds upon the Scaffold-GS representation, introducing a hierarchical octree structure to decouple multi-scale Gaussian primitives into varying LOD levels [S4, S2]. The method was published in IEEE Transactions on Pattern Analysis and Machine Intelligence in 2025 [S4].
