# CityGaussian / VastGaussian / DoGaussian

Also called: City-Gaussian, CityGaussian / Hierarchical 3DGS, CityGaussian V2, DoGaussian

## Overview
CityGaussian, VastGaussian, and DoGaussian are methods for rendering city-scale (square-kilometer) 3D Gaussian Splatting (3DGS) scenes by partitioning the environment into spatial blocks, training independent Gaussian models per block, and merging them at render time [S1, S3, unofficial][S5]. They solve the memory and performance bottlenecks of monolithic 3DGS in large scenes by enabling level-of-detail (LoD) selection, streaming, and distributed training [S2, S3, unofficial]. They set themselves apart from sibling methods like [Hierarchical 3D Gaussian Splatting (H-3DGS)](10279-hierarchical-3d-gaussian-splatting-h-3dgs.md) by relying on tile-based training and merging rather than a single unified hierarchical structure, and from [LightGaussian](8036-lightgaussian.md) by focusing on spatial partitioning rather than pure compression [S3, unofficial].

## How it works
**Inputs:** A large-scale scene (e.g., city-scale) captured via multi-view images; a block partitioning scheme (grid or semantic-aware); training data per block.
**Outputs:** A set of trained 3DGS models for each block, ready for merged rendering with LoD selection.

**Data Structures:**
*   **Block:** A spatial region (cube or tile) containing a subset of Gaussians.
*   **Block Bounds:** Defined by minimum and maximum coordinates $(\mathbf{p}_{min}, \mathbf{p}_{max})$. To avoid inclusion of "floaters" (outlier Gaussians), bounds are estimated using Median Absolute Deviation (MAD) [S5]:
    $$
    MAD_j = \mathrm{median}\left( \left| \mathbf{p}_k^j - \mathrm{median}\left( \mathbf{p}_k^j \right) \right| \right)
    $$
    $$
    \mathbf{p}_{min}^j = \max\left( \min\left( \mathbf{p}_k^j \right), \mathrm{median}\left( \mathbf{p}_k^j \right) - n_{MAD} \times MAD_j \right)
    $$
    $$
    \mathbf{p}_{max}^j = \min\left( \max\left( \mathbf{p}_k^j \right), \mathrm{median}\left( \mathbf{p}_k^j \right) + n_{MAD} \times MAD_j \right)
    $$
    where $\mathbf{p}_k^j$ are the positions of Gaussians in block $j$, and $n_{MAD}$ is a hyperparameter [S5].
*   **LoD Pyramid:** Multiple detail levels per block, generated by applying compression strategies (e.g., LightGaussian) to reduce point count, feature dimensions, and precision [S5].

**Steps:**
1.  **Partition:** Divide the scene into overlapping or disjoint blocks [S1, S3, unofficial]. VastGaussian uses spatially-disjoint regions with feathered overlap for blending [S3, unofficial]. CityGS-X refines boundaries using building footprints [S1, unofficial].
2.  **Train:** Train independent 3DGS models for each block. DoGaussian distributes this training across multiple nodes [S3, unofficial]. CityGaussian V2 uses depth regularization and visibility-aware training [S3, unofficial].
3.  **Generate LoD (Optional but common in CityGaussian):** Apply compression to create detail levels $r_0, r_1, r_2$ with varying compression rates [S5].
4.  **Estimate Bounds:** Calculate robust block bounds using MAD to exclude floaters [S5].
5.  **Select LoD per Block:** Determine the minimum distance from the block's eight corners to the camera center. Assign a detail level based on this distance [S5].
6.  **Frustum Culling:** Project block corners to screen space, create a bounding box, and calculate Intersection-over-Union (IoU) with the screen area. Include the block if IoU indicates intersection or if the camera is inside the block [S5].
7.  **Render/Merge:** Concatenate Gaussians from visible blocks (and their selected LoD) and render. VastGaussian uses feathered blending at overlaps [S3, unofficial]. CityGaussian concatenates directly, noting negligible discontinuity [S5].

**Parameters:**
*   $n_{MAD}$: MAD multiplier for bound estimation. Not given in the sources.
*   Compression rates ($r_0, r_1, r_2$): Determined by the chosen compression strategy (e.g., LightGaussian) [S5].

**Edge Cases and Pitfalls:**
*   **Floaters:** Outlier Gaussians can inflate block bounds, causing false frustum intersections. Solved by MAD-based bound estimation [S5].
*   **Boundary Artifacts:** Overlapping blocks require blending (feathering) to avoid seams. VastGaussian explicitly handles this [S3, unofficial].
*   **Precision:** Higher detail levels require higher precision; lower levels use quantization (e.g., INT6 for SH, 16-bit half for positions) [S3, unofficial][S5].

## Subtopics

### CityGS-X
A method that extends block-based partitioning with a geometry-aware architecture that refines block boundaries according to building footprints, achieving highly accurate urban reconstruction [S1, unofficial]. It targets large-scale urban scenes by combining semantic segmentation to allocate Gaussians only on building facades and road surfaces [S1, unofficial].

### Proxy-GS
A method that uses a coarse proxy mesh to guide Gaussian placement, significantly reducing the number of Gaussians required for background regions [S1, unofficial].

### CityGS Level-of-Detail (LoD)
A rendering optimization technique that generates multiple detail levels of Gaussians and selects them per block based on distance to camera, reducing rasterizer load [S5]. It generates detail levels using LightGaussian compression [S5], estimates block bounds using MAD to ignore floaters [S5], determines LoD per block by calculating the minimum distance from block corners to the camera [S5], performs frustum culling via IoU of projected corners [S5], and fuses Gaussians from different detail levels via direct concatenation [S5].

## Operating characteristics
*   **Time Complexity:** Training is parallelizable across blocks/nodes (DoGaussian) [S3, unofficial]. Rendering complexity scales with the number of visible blocks and their LoD, rather than the total scene size [S5].
*   **Memory Complexity:** Scales with the number of active blocks and their LoD. Full scene storage is not required in memory simultaneously [S3, unofficial].
*   **Measured Performance:** CityGaussian renders 2.7 km² scenes (MatrixCity) in real-time [S5]. Production compression baselines (pruning, SH distillation, quantization) achieve 8–20× size reduction with <0.5 dB PSNR drop [S3, unofficial].
*   **Strengths:** Enables city-scale rendering; supports streaming and LoD; distributed training reduces training time [S3, unofficial].
*   **Limitations:** Requires careful handling of block boundaries to avoid artifacts; training is more complex than monolithic 3DGS [S3, unofficial].
*   **When to use:** Large-scale, static urban scenes requiring interactive exploration [S2, S3, unofficial].
*   **When not to use:** Small scenes where monolithic 3DGS is sufficient; highly dynamic scenes requiring global coherence (consider [StreetGaussians](6161-streetgaussians.md)) [S2, unofficial].

## Background
CityGaussian, VastGaussian, and DoGaussian emerged around 2024-2025 to address the scalability of 3DGS to city scales [S3, unofficial][S5]. VastGaussian (CVPR'24) introduced block-based partitioning with decoupled appearance handling [S3, unofficial]. CityGaussian and its V2 variant introduced hierarchical LoD and depth regularization [S3, unofficial]. DoGaussian focused on distributed training [S3, unofficial]. These methods build on [3D Gaussian Splatting LOD methods](5439-3d-gaussian-splatting-lod-methods.md) by providing specific implementations for large-scale spatial partitioning.
