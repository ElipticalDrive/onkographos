# Cluster Culling (Nanite-style)

Also called: FClusterCullingCS, FClusterCullingResetCS

## Overview
Cluster Culling is a hierarchical frustum culling and Level of Detail (LOD) selection mechanism for 3D Gaussian Splatting, designed to emulate the spatial clustering and culling efficiency of Nanite. It operates on pre-computed Gaussian clusters, testing their bounding volumes against the view frustum and selecting the appropriate LOD based on screen-space error metrics. It distinguishes itself from sibling methods by integrating visibility culling, LOD selection, and indirect draw argument generation into a unified GPU compute pipeline, optimizing for high-performance rendering of large-scale Gaussian scenes.

## How it works
### Inputs and Outputs
**Inputs:**
*   **Cluster Data:** A structured buffer of Gaussian clusters (`FGaussianGPUCluster`), containing position, scale, rotation, opacity, color, and bounding sphere information for each cluster [S1, unofficial].
*   **View Frustum:** Defined by 6 plane vectors (`FrustumPlanes`) in world space [S1, unofficial].
*   **Transforms:** Local-to-World (`LocalToWorld`) and World-to-Clip (`WorldToClip`) matrices [S1, unofficial].
*   **Camera Parameters:** Camera position (`CameraPosition`), screen height (`ScreenHeight`) [S1, unofficial].
*   **Culling Parameters:** `ErrorThreshold` for LOD selection, `LODBias`, `MaxDrawDistance`, `UseLODRendering` flag, and `DebugForceLODLevel` [S1, unofficial].

**Outputs:**
*   **Visible Clusters:** A buffer (`VisibleClusterBuffer`) containing indices of clusters passing culling [S1, unofficial].
*   **Visibility Bitmap:** A bitfield (`ClusterVisibilityBitmap`) indicating cluster visibility status [S1, unofficial].
*   **Indirect Draw Args:** A buffer (`IndirectDrawArgsBuffer`) containing the count and instance data required for indirect drawing [S1, unofficial].
*   **LOD Buffers:** Buffers (`LODClusterBuffer`, `LODClusterCountBuffer`, `LODClusterSelectedBitmap`) managing LOD-specific cluster selection and counts [S1, unofficial].

### Data Structures
The core data structure is `FGaussianGPUCluster`. While the exact field layout is not fully specified in the provided sources, it must contain at minimum:
*   Position ($\mathbf{p}$)
*   Scale/Rotation (defining the bounding sphere)
*   Opacity ($\alpha$)
*   Color ($c$)
*   Bounding Sphere Radius ($r$) [G: Inferred from frustum culling requirement]

The compute shaders operate on several `RWStructuredBuffer<uint>` and `StructuredBuffer` types:
*   `VisibleClusterCountBuffer`: Stores the total count of visible clusters.
*   `IndirectDrawArgsBuffer`: Stores `uint3` (count, first index, stride) for indirect draw calls.
*   `ClusterVisibilityBitmap`: Bitmask for cluster visibility.
*   `SelectedClusterBuffer`: Indices of selected clusters for rendering.
*   `LODClusterBuffer`, `LODClusterCountBuffer`, `LODClusterSelectedBitmap`: Buffers for LOD-specific management.

### Steps
1.  **Reset State:** Execute `FClusterCullingResetCS` to initialize counters, indirect draw arguments, and visibility bitmaps to zero or default states. This prepares the buffers for the current frame's culling pass [S1, unofficial].
2.  **Frustum Culling and LOD Selection:** Execute `FClusterCullingCS`. For each cluster:
    *   **Bounding Sphere Test:** Test the cluster's bounding sphere against the 6 frustum planes. If the sphere is completely outside any plane, the cluster is culled [S1, unofficial].
    *   **Distance Check:** If within `MaxDrawDistance`, proceed; otherwise, cull [S1, unofficial].
    *   **LOD Selection:** Calculate the screen-space error or size of the cluster. Compare this against `ErrorThreshold` adjusted by `LODBias`. Select the appropriate LOD level. If `DebugForceLODLevel` is set (-1 for auto, 0 for leaf, 1+ for specific), override the calculated LOD [S1, unofficial].
    *   **Visibility Output:** Mark the cluster as visible in `ClusterVisibilityBitmap` and append its index to `VisibleClusterBuffer` [S1, unofficial].
3.  **Indirect Draw Argument Generation:** Use the count of visible clusters to populate `IndirectDrawArgsBuffer` for the subsequent rendering pass [S1, unofficial].

```python
# FClusterCullingResetCS
def FClusterCullingResetCS(
    VisibleClusterCountBuffer: RWStructuredBuffer<uint>,
    IndirectDrawArgsBuffer: RWStructuredBuffer<uint>,
    ClusterVisibilityBitmap: RWStructuredBuffer<uint>,
    SelectedClusterBuffer: RWStructuredBuffer<uint>,
    LODClusterBuffer: RWStructuredBuffer<uint>,
    LODClusterCountBuffer: RWStructuredBuffer<uint>,
    LODClusterSelectedBitmap: RWStructuredBuffer<uint>,
    LODSplatTotalBuffer: RWStructuredBuffer<uint>,
    LODSplatOutputCountBuffer: RWStructuredBuffer<uint>,

    LeafClusterCount: uint,
    DebugForceLODLevel: int

    # Initialize counters to zero
    VisibleClusterCountBuffer[0] = 0
    IndirectDrawArgsBuffer[0] = 0 # Count
    IndirectDrawArgsBuffer[1] = 0 # First Index
    IndirectDrawArgsBuffer[2] = 0 # Stride (assumed constant or pre-set)
    
    # Reset visibility bitmap
    for i in range(0, ClusterVisibilityBitmapSize):
        ClusterVisibilityBitmap[i] = 0
        
    # Reset LOD buffers
    LODClusterCountBuffer[0] = 0
    LODSplatTotalBuffer[0] = 0
    LODSplatOutputCountBuffer[0] = 0

# FClusterCullingCS
def FClusterCullingCS(
    ClusterBuffer: StructuredBuffer<FGaussianGPUCluster>,
    VisibleClusterBuffer: RWStructuredBuffer<uint>,
    VisibleClusterCountBuffer: RWStructuredBuffer<uint>,
    IndirectDrawArgsBuffer: RWStructuredBuffer<uint>,
    ClusterVisibilityBitmap: RWStructuredBuffer<uint>,
    SelectedClusterBuffer: RWStructuredBuffer<uint>,
    LODClusterBuffer: RWStructuredBuffer<uint>,
    LODClusterCountBuffer: RWStructuredBuffer<uint>,
    LODClusterSelectedBitmap: RWStructuredBuffer<uint>,
    LODSplatTotalBuffer: RWStructuredBuffer<uint>,
    LODSplatOutputCountBuffer: RWStructuredBuffer<uint>,
    LocalToWorld: FMatrix44f,
    WorldToClip: FMatrix44f,
    ClusterCount: uint,
    LeafClusterCount: uint,
    FrustumPlanes: FVector4f[6], # Each plane: (normal_x, normal_y, normal_z, distance)
    CameraPosition: FVector3f,
    ScreenHeight: float,
    ErrorThreshold: float,
    LODBias: float,
    MaxDrawDistance: float,
    UseLODRendering: uint,
    DebugForceLODLevel: int
):
    thread_id = get_thread_id()
    if thread_id >= ClusterCount:
        return

    cluster = ClusterBuffer[thread_id]
    
    # Transform cluster position to world space if not already
    world_pos = LocalToWorld * cluster.position
    
    # Frustum Culling
    is_visible = True
    for plane in FrustumPlanes:
        # Plane equation: dot(normal, point) + distance <= 0 for inside
        # Assuming FrustumPlanes are stored as (normal, distance)
        dist = dot(plane.xyz, world_pos) + plane.w
        if dist < 0:
            is_visible = False
            break
            
    if not is_visible:
        return

    # Distance Culling
    dist_to_camera = length(world_pos - CameraPosition)
    if dist_to_camera > MaxDrawDistance:
        return

    # LOD Selection
    lod_level = 0 # Default to leaf
    if UseLODRendering:
        # Calculate screen-space size/error
        # Project world_pos to clip space
        clip_pos = WorldToClip * float4(world_pos, 1.0)
        if clip_pos.w > 0:
            ndc_pos = clip_pos.xyz / clip_pos.w
            # Screen space position
            screen_x = (ndc_pos.x + 1.0) * 0.5 * ScreenWidth # ScreenWidth not provided, assume derived or constant
            screen_y = (1.0 - (ndc_pos.y + 1.0) * 0.5) * ScreenHeight
            
            # Estimate screen-space radius of the cluster
            # This requires cluster scale/rotation to be transformed and projected
            # Simplified: use bounding sphere radius projected to screen
            # [G] Exact projection of rotated bounding sphere is complex; 
            # sources imply a screen-space error calculation.
            screen_radius = cluster.radius * (ScreenHeight / (2.0 * dist_to_camera)) # Approximation
            
            # Calculate error metric
            error = screen_radius / ErrorThreshold
            
            # Select LOD based on error and bias
            lod_level = calculate_lod_from_error(error, LODBias)
        else:
            lod_level = 0 # Behind camera or invalid projection
            
    if DebugForceLODLevel != -1:
        lod_level = DebugForceLODLevel

    # Mark as visible
    bitmap_index = thread_id // 32
    bitmap_bit = thread_id % 32
    ClusterVisibilityBitmap[bitmap_index] |= (1 << bitmap_bit)
    
    # Append to visible buffer
    count = atomic_add(VisibleClusterCountBuffer[0], 1)
    VisibleClusterBuffer[count] = thread_id
    
    # Update LOD buffers if LOD rendering is enabled
    if UseLODRendering:
        lod_count = atomic_add(LODClusterCountBuffer[lod_level], 1)
        LODClusterBuffer[lod_level * ClusterCount + lod_count] = thread_id
        lod_bitmap_index = lod_count // 32
        lod_bitmap_bit = lod_count % 32
        LODClusterSelectedBitmap[lod_level * (ClusterCount // 32) + lod_bitmap_index] |= (1 << lod_bitmap_bit)

    # Update Indirect Draw Args
    # [G] Indirect draw args usually need total count and first index.
    # This is typically done in a separate pass or after all clusters are processed.
    # Here, we assume VisibleClusterCountBuffer holds the final count.
    # IndirectDrawArgsBuffer[0] = VisibleClusterCountBuffer[0]
    # IndirectDrawArgsBuffer[1] = 0
    # IndirectDrawArgsBuffer[2] = stride
```

### Parameters
*   `FrustumPlanes`: Array of 6 `FVector4f` defining the view frustum planes [S1, unofficial].
*   `ErrorThreshold`: Threshold for screen-space error calculation for LOD selection [S1, unofficial].
*   `LODBias`: Bias applied to LOD selection [S1, unofficial].
*   `MaxDrawDistance`: Maximum distance for cluster visibility [S1, unofficial].
*   `DebugForceLODLevel`: Debug parameter to force a specific LOD level (-1 = auto, 0 = leaf, 1+ = specific level) [S1, unofficial].
*   `THREADGROUP_SIZE`: Compilation define set to 64 for `FClusterCullingCS` [S1, unofficial].

### Edge Cases and Pitfalls
*   **Precision:** Frustum culling using floating-point plane tests can suffer from precision issues near the frustum boundaries. [G] Use a small epsilon for plane tests.
*   **Degenerate Input:** Clusters with zero radius or invalid transforms should be handled to avoid division by zero or invalid projections.
*   **Boundary Conditions:** Clusters exactly on the frustum plane boundary should be considered visible to avoid flickering.

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of clusters, as each cluster is processed in parallel by the compute shader.
*   **Memory Complexity:** $O(N)$ for storing visibility bitmaps and cluster buffers.
*   **Performance:** Highly efficient on GPU due to parallel processing. The use of indirect draw calls reduces CPU-GPU synchronization overhead.
*   **Strengths:** Efficient culling and LOD selection for large-scale Gaussian scenes. Integrates well with hierarchical clustering.
*   **Limitations:** Requires pre-computed cluster data. LOD selection accuracy depends on the screen-space error metric.
*   **When to Use:** When rendering large-scale 3D Gaussian Splatting scenes with significant variation in cluster density and distance.
*   **When Not to Use:** For small scenes where the overhead of compute shaders outweighs the benefits, or when LOD is not required.

## Background
Cluster Culling is part of the OpenSplat4D project, an unofficial implementation of 4D Gaussian Splatting. It draws inspiration from Nanite's spatial clustering and culling techniques, adapting them for Gaussian splats. The method is implemented using NVIDIA Niagara compute scripts, leveraging GPU compute shaders for efficient processing.
