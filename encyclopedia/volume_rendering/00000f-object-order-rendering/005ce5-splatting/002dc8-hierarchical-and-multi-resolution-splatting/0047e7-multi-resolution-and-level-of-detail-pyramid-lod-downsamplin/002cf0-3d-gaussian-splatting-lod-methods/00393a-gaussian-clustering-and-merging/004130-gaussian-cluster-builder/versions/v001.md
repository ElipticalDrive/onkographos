# Gaussian Cluster Builder

Also called: FGaussianClusterBuilder

## Overview
The Gaussian Cluster Builder is a method for constructing hierarchical cluster structures from 3D Gaussian splat data, implementing a Nanite-style spatial clustering approach [S1, unofficial]. It partitions a set of Gaussians into a tree of clusters to enable Level of Detail (LOD) generation and spatial culling. It differs from sibling methods like [K-wise moment-matched merging](5440-k-wise-moment-matched-merging-with-l2-optimal-amplitude.md) by focusing on hierarchical tree construction via Morton code sorting and recursive merging rather than direct pairwise or k-wise optimization of a flat set [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of 3D Gaussians $G = \{G_i\}$, where each Gaussian $G_i$ is defined by position $\mathbf{t}_i$, covariance matrix $\mathbf{\Sigma}_i$ (or scale $\mathbf{s}_i$ and rotation $\mathbf{q}_i$), opacity $\alpha_i$, and color coefficients $c_i$.
*   **Output:** A hierarchical cluster tree. Leaf nodes contain individual splats or small groups. Internal nodes contain aggregated bounding volumes and error metrics. If LOD generation is enabled, parent nodes also contain representative "LOD splats" derived from their children.

**Data Structures:**
The builder uses a configuration structure `FBuildSettings` with the following fields [S1, unofficial]:
*   `SplatsPerCluster` (`int32`): Number of splats per leaf cluster. Default: `GaussianClusterConstants::DefaultSplatsPerCluster`.
*   `MaxChildrenPerCluster` (`int32`): Maximum children per parent cluster. Default: `GaussianClusterConstants::MaxChildrenPerCluster`.
*   `bReorderSplats` (`bool`): Whether to reorder splat data for cluster locality. Default: `true`.
*   `bGenerateLOD` (`bool`): Whether to generate LOD splats for parent clusters. Default: `true`.
*   `LODReductionRatio` (`int32`): How many original splats per LOD splat. Default: `4`.

**Algorithm Steps:**
1.  **Sort:** Sort the input splats by their Morton code (Z-order curve) to ensure spatial locality in the sorted array [S1, unofficial].
2.  **Reorder (Optional):** If `bReorderSplats` is true, physically reorder the splat data in memory according to the sorted order to improve cache coherence during subsequent operations [S1, unofficial].
3.  **Leaf Clustering:** Group the sorted splats into leaf clusters, each containing exactly `SplatsPerCluster` splats (except possibly the last cluster) [S1, unofficial].
4.  **Recursive Merging:** Recursively merge leaf clusters into parent nodes. A parent cluster is formed by grouping up to `MaxChildrenPerCluster` child clusters.
5.  **Bounding Volume Calculation:** For each cluster (leaf and internal), calculate a bounding volume (e.g., AABB or sphere) that encloses all constituent Gaussians [S1, unofficial].
6.  **Error Metric Calculation:** Calculate an error metric for each cluster, likely representing the approximation error if the cluster were replaced by a single representative or if it were culled [S1, unofficial].
7.  **LOD Generation (Optional):** If `bGenerateLOD` is true, generate representative LOD splats for internal clusters. The number of original splats represented by one LOD splat is determined by `LODReductionRatio` (default 4) [S1, unofficial]. The specific merging formula for these LOD splats is not detailed in the source, but it implies an aggregation of the children's parameters.

*   **Precision:** Morton code calculation must handle floating-point positions robustly. [G] Typically, positions are quantized to integer coordinates before encoding.

## Subtopics

### Gaussian Grouping Strategy
A strategy that implements hierarchical structuring of Gaussians to enable simulations to be performed exclusively on selected Core Gaussians, accelerating the process [S2, unofficial]. It organizes Gaussians into a hierarchy through clustering methods and performs simulation only on the Core Gaussians (highest level of hierarchy) [S2, unofficial]. This approach speeds up computations, especially when using particle-based engines such as Taichi [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Sorting by Morton code is $O(N \log N)$ or $O(N)$ depending on the implementation. Clustering and merging are linear with respect to the number of clusters.
*   **Memory Complexity:** The tree structure adds overhead for cluster nodes. LOD splats add memory if generated.
*   **Strengths:** Efficient spatial culling and LOD selection due to hierarchical structure. Good cache locality if `bReorderSplats` is enabled.
*   **Limitations:** The exact merging formula for LOD splats is not specified, which may affect visual quality. The method relies on spatial locality, which may not be optimal for all scenes.
*   **When to use:** When hierarchical culling and LOD are required for large Gaussian splat scenes.
*   **When not to use:** When a flat set of Gaussians is sufficient or when non-spatial attributes are more important for clustering.

## Background
The Gaussian Cluster Builder is described in the context of the OpenSplat4D project, which implements Nanite-style spatial clustering for Gaussian splats [S1, unofficial]. The concept of hierarchical Gaussian clustering for simulation acceleration is also discussed in the GASP paper, which introduces a Gaussian grouping strategy for physics-based simulations [S2, unofficial].
