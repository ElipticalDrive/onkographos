# Gaussian Cluster Builder

Also called: FGaussianClusterBuilder

## Overview
The Gaussian Cluster Builder is a method for constructing hierarchical cluster structures from 3D Gaussian splat data, implementing a Nanite-style spatial clustering approach [S1, unofficial]. It partitions a set of Gaussians into disjoint subsets and replaces them with representative Gaussians to enable multi-resolution rendering and efficient culling. It is distinguished from sibling methods by its explicit reliance on Morton code sorting for spatial locality and its configurable generation of Level of Detail (LOD) splats for parent clusters [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of 3D Gaussians $G = \{G_i\}$, where each Gaussian $G_i$ is defined by position $\mathbf{t}_i$, covariance $\mathbf{\Sigma}_i$ (or scale $\mathbf{s}_i$ and rotation $\mathbf{q}_i$), opacity $\alpha_i$, and color coefficients $c_i$.
*   **Output:** A hierarchical tree structure where leaf nodes contain original or grouped splats, and internal nodes contain merged representative Gaussians.

**Data Structures:**
The builder uses a configuration structure `FBuildSettings` with the following fields [S1, unofficial]:
*   `int32 SplatsPerCluster`: Number of splats per leaf cluster. Default: `GaussianClusterConstants::DefaultSplatsPerCluster`.
*   `int32 MaxChildrenPerCluster`: Maximum children per parent cluster. Default: `GaussianClusterConstants::MaxChildrenPerCluster`.
*   `bool bReorderSplats`: Whether to reorder splat data for cluster locality. Default: `true`.
*   `bool bGenerateLOD`: Whether to generate LOD splats for parent clusters. Default: `true`.
*   `int32 LODReductionRatio`: How many original splats per LOD splat. Default: `4`.

**Algorithm Steps:**
1.  **Sort:** Sort the input splats by their Morton code (Z-order curve) to ensure spatial locality [S1, unofficial].
2.  **Leaf Clustering:** Group the sorted splats into leaf clusters, each containing `SplatsPerCluster` splats.
3.  **Recursive Merging:** Recursively merge clusters into parent nodes. A parent cluster is formed by grouping up to `MaxChildrenPerCluster` child clusters.
4.  **Aggregation:** For each parent cluster, calculate the bounding volume and the representative Gaussian parameters. The aggregation follows the moment-matching paradigm defined in the parent article [Gaussian clustering and merging](8436-gaussian-clustering-and-merging.md):
    $$ W_j = \sum_{i \in C_j} \alpha_i $$
    $$ \mathbf{t}'_j = \frac{1}{W_j} \sum_{i \in C_j} \alpha_i \mathbf{t}_i $$
    $$ \mathbf{\Sigma}'_j = \frac{1}{W_j} \sum_{i \in C_j} \alpha_i \left( \mathbf{\Sigma}_i + (\mathbf{t}_i - \mathbf{t}'_j)(\mathbf{t}_i - \mathbf{t}'_j)^T \right) $$
5.  **LOD Generation:** If `bGenerateLOD` is true, generate LOD splats for parent clusters. The number of original splats represented by one LOD splat is determined by `LODReductionRatio` (default 4) [S1, unofficial].
6.  **Reordering:** If `bReorderSplats` is true, reorder the splat data in memory to reflect the cluster hierarchy, improving cache locality during rendering [S1, unofficial].

        # Sort splats by Morton code for spatial locality
        splats = sort_by_morton_code(splats)
    
    # Step 1: Create leaf clusters
    leaf_clusters = []
    splats_per_cluster = settings.SplatsPerCluster
    for i in range(0, len(splats), splats_per_cluster):
        cluster_splats = splats[i : i + splats_per_cluster]
        leaf_clusters.append(create_leaf_cluster(cluster_splats))
    
    # Step 2: Recursively build hierarchy
    current_level_clusters = leaf_clusters
    while len(current_level_clusters) > 1:
        next_level_clusters = []
        max_children = settings.MaxChildrenPerCluster
        
        for i in range(0, len(current_level_clusters), max_children):
            children = current_level_clusters[i : i + max_children]
            parent_cluster = create_parent_cluster(children)
            next_level_clusters.append(parent_cluster)
        
        current_level_clusters = next_level_clusters
    
    # Step 3: Generate LOD if enabled
    if settings.bGenerateLOD:
        for cluster in current_level_clusters:
            generate_lod_splats(cluster, settings.LODReductionRatio)
    
    return current_level_clusters

def create_leaf_cluster(splats):
    """
    Aggregates splats into a single representative Gaussian using moment matching.
    """
    total_alpha = sum(s.alpha for s in splats)
    if total_alpha == 0:
        return None
    
    # Calculate weighted mean position
    mean_pos = sum(s.alpha * s.pos for s in splats) / total_alpha
    
    # Calculate weighted covariance
    cov = sum(
        s.alpha * (s.cov + np.outer(s.pos - mean_pos, s.pos - mean_pos))
        for s in splats
    ) / total_alpha
    
    # Calculate weighted color (simple average for color coefficients)
    mean_color = sum(s.color for s in splats) / len(splats)
    
    return {
        'pos': mean_pos,
        'cov': cov,
        'alpha': total_alpha,
        'color': mean_color,
        'children': splats,
        'is_leaf': True
    }

**Edge Cases and Pitfalls:**
*   **Zero Alpha:** If a cluster has zero total alpha, it should be handled gracefully (e.g., skipped or represented by a zero-opacity Gaussian) to avoid division by zero in moment matching [G].
*   **Boundary Conditions:** When `SplatsPerCluster` does not evenly divide the total number of splats, the last leaf cluster will contain fewer splats. The algorithm must handle this variable-sized cluster correctly [G].
*   **Precision:** Floating-point precision issues may arise when calculating covariance matrices for very small or very large clusters. Using double precision for intermediate calculations is recommended [G].

## Subtopics

### Gaussian Grouping Strategy
A strategy that implements hierarchical structuring of Gaussians to enable simulations to be performed exclusively on selected Core Gaussians, accelerating the process [S2, unofficial]. It organizes Gaussians into a hierarchy through clustering methods and performs simulation only on the Core Gaussians (highest level of hierarchy) [S2, unofficial]. This approach speeds up computations, especially when using particle-based engines such as Taichi [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Sorting by Morton code takes $O(N \log N)$ where $N$ is the number of splats. Clustering and merging are linear with respect to the number of clusters, but the recursive nature means the total time is proportional to $N$ with a small constant factor depending on the tree depth.
*   **Memory Complexity:** The hierarchical structure requires storing additional metadata for each cluster (bounding volumes, parent/child pointers). The memory overhead is proportional to the number of clusters, which is $N / \text{SplatsPerCluster}$.
*   **Strengths:** Efficient spatial locality due to Morton code sorting. Configurable LOD generation allows for flexible trade-offs between quality and performance. Nanite-style clustering is effective for culling.
*   **Limitations:** The quality of the merged Gaussians depends on the heterogeneity of the cluster. Large or heterogeneous clusters may introduce geometric artifacts. The method assumes a static scene; dynamic scenes may require frequent rebuilding of the hierarchy.
*   **When to Use:** Suitable for large-scale 3D Gaussian splatting applications where multi-resolution rendering and efficient culling are required.
*   **When Not to Use:** Not suitable for highly dynamic scenes where the hierarchy would need to be rebuilt frequently. Not suitable for scenes with very small clusters where the overhead of the hierarchy outweighs the benefits.

## Background
The Gaussian Cluster Builder is part of the OpenSplat4D project, which implements Nanite-style spatial clustering for 3D Gaussian splatting [S1, unofficial]. The method builds on the principles of hierarchical clustering and moment-matched merging described in the parent article [Gaussian clustering and merging](8436-gaussian-clustering-and-merging.md).
