# LOD Generation for 3DGS

Also called: 3DGS LOD Generation, Gaussian Clustering for LOD

## Overview
This method reduces the number of 3D Gaussians copied, stored, sorted, and rendered by merging Gaussians into clusters based on similar attributes, minimizing distant appearance impact without altering the scene creation stage [S1]. It operates within a virtual memory framework where Gaussians are organized into pages; unlike virtual texturing which uses uniform-sized mip levels, this method reduces the Gaussian count with each LOD level, allowing multiple virtual pages to reside within a single physical page [S1]. It is distinguished from sibling methods by its specific use of k-means clustering on multidimensional attribute space and dynamic threshold adjustment to prevent visual popping [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of 3D Gaussians $G_i$ organized into pages. Each Gaussian has position $\mathbf{t}_i$, rotation $\mathbf{q}_i$ (or scale/rotation), opacity $\alpha_i$, and spherical harmonic coefficients $c_i$.
*   **Output:** A reduced set of merged Gaussians $G'_k$ for each LOD level, and a page table mapping virtual pages to physical LOD levels.

**Data Structures:**
*   **Page Table:** An array of entries. Each entry contains:
    *   `page_id`: Identifier for the virtual page.
    *   `lod_level`: The current Level of Detail index for this page.
    *   `last_use`: Timestamp or frame counter for LRU eviction.
    *   `physical_data`: Pointer or handle to the merged Gaussian data in GPU memory.
*   **Cluster:** A list of indices $\{i\}$ referring to Gaussians in the same page.

**Parameters:**
*   $k$: Number of clusters in k-means. Not given in the sources.
*   $scale\_factor$: Fixed multiplier applied to the merged Gaussian's scale to fill gaps. Not given in the sources.
*   $memory\_limit$: Threshold for memory usage triggering LOD adjustment. Not given in the sources.
*   $threshold\_step$: Initial step size for LOD threshold adjustment. Not given in the sources.

**Steps:**

1.  **Page Assignment:** Assign Gaussians to pages based on spatial proximity or proxy mesh faces [S1].
2.  **Clustering:** For each page, identify clusters of Gaussians using the k-means algorithm. The points in multidimensional space are defined by attributes: position, rotation, and color (spherical harmonics) [S1].
    *   *Pitfall:* Prioritize position attributes during clustering to prevent dispersed clusters [S1].
3.  **Merging:** Replace each cluster $C_k$ with a single representative Gaussian $G'_k$.
    *   Calculate the arithmetic mean for translation, rotation, opacity, and spherical harmonics [S1].
    *   *Pitfall:* Merging scales directly causes the resulting Gaussian to be too small. Scale up the merged Gaussian by a fixed factor to fill gaps [S1].
4.  **LOD Marking:** Mark page table entries with their current LOD level [S1].
5.  **Dynamic Threshold Adjustment:**
    *   Monitor GPU memory usage.
    *   If usage exceeds $memory\_limit$, move LOD thresholds away from the camera (higher LOD, more detail).
    *   If memory is available, move thresholds closer to the camera (lower LOD, less detail) [S1].
    *   *Pitfall:* Setting initial thresholds in fixed increments can cause rapid flipping between levels (popping/flickering) if the step size is too large or adaptation is too slow if too small. Dynamically adjust the step size based on previous moves to stabilize [S1].

**Pseudocode:**

```python
def generate_lod(gaussians, page_table, memory_limit):
    """
    Generates LOD levels for 3DGS by clustering and merging Gaussians.
    """
    for page in page_table:
        # Step 2: Clustering
        # Extract attributes: position, rotation, color
        attributes = extract_attributes(page.gaussians)
        
        # Prioritize position in distance metric
        weights = [10.0, 1.0, 1.0] # Example weights prioritizing position [S1]
        clusters = k_means(attributes, k=page.target_cluster_count, weights=weights)
        
        # Step 3: Merging
        merged_gaussians = []
        for cluster in clusters:
            cluster_gaussians = [page.gaussians[i] for i in cluster.indices]
            
            # Arithmetic mean for most attributes
            new_t = mean([g.t for g in cluster_gaussians])
            new_q = mean_quaternions([g.q for g in cluster_gaussians])
            new_alpha = mean([g.alpha for g in cluster_gaussians])
            new_sh = mean_spherical_harmonics([g.sh for g in cluster_gaussians])
            
            # Scale adjustment to prevent small merged Gaussians [S1]
            new_scale = mean([g.scale for g in cluster_gaussians]) * scale_factor
            
            merged_gaussians.append(Gaussian(new_t, new_q, new_scale, new_alpha, new_sh))
        
        page.merged_data = merged_gaussians
        page.lod_level = calculate_lod_level(page, memory_limit)

def adjust_thresholds(page_table, current_memory_usage, memory_limit, prev_step_direction):
    """
    Dynamically adjusts LOD thresholds to prevent popping/flickering [S1].
    """
    if current_memory_usage > memory_limit:
        # Move thresholds away from camera (increase detail)
        step = adaptive_step(prev_step_direction, "increase")
        for page in page_table:
            page.threshold += step
    else:
        # Move thresholds closer to camera (decrease detail)
        step = adaptive_step(prev_step_direction, "decrease")
        for page in page_table:
            page.threshold -= step
            
    prev_step_direction = "increase" if current_memory_usage > memory_limit else "decrease"
    return prev_step_direction

def adaptive_step(prev_direction, current_direction):
    """
    Adjusts step size based on previous moves to prevent rapid flipping [S1].
    """
    if prev_direction == current_direction:
        return initial_step * 0.5 # Reduce step if continuing in same direction
    else:
        return initial_step * 2.0 # Increase step if reversing direction
```

## Subtopics

### Memory-Efficient 3D GS via Pruning and Clustering
This variant addresses scalability and memory demands in large-scale scenes by combining strategic pruning of low-impact Gaussians (e.g., volume-based masking) with clustering [S2]. Neighboring Gaussians are represented using properties stored within a "local anchor" obtained via clustering [S2]. It specifically employs a hash-grid for clustering operations [S2].

## Operating characteristics
*   **Time Complexity:** Clustering using k-means is $O(N \cdot k \cdot I)$ where $N$ is the number of Gaussians per page, $k$ is the number of clusters, and $I$ is iterations [S1]. Merging is linear $O(N)$ [S1].
*   **Memory Complexity:** Reduces GPU memory usage by lowering the number of Gaussians stored in VRAM. The method allows multiple virtual pages within one physical page, optimizing memory footprint [S1].
*   **Strengths:** Minimizes distant appearance impact without altering scene creation; dynamic thresholding adapts to available memory [S1].
*   **Limitations:** Risk of popping/flickering if thresholds are not adjusted carefully; merging scales requires empirical scaling factors [S1].
*   **When to use:** Large-scale scenes with limited GPU memory where real-time rendering is required [S1].
*   **When not to use:** Scenes requiring high-fidelity detail at all distances without LOD transitions [S1].

## Background
This method originates from research on virtual memory for 3D Gaussian Splatting [S1]. It was developed to address the high memory demands of 3DGS by streaming Gaussians to GPU memory on demand, eliminating the need for static encoding and allowing dynamic LOD management [S1]. It builds on the principles of virtual texturing but adapts them to the non-uniform nature of Gaussian clusters [S1].
