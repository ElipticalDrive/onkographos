# Hierarchical Splatting

Also called: Progressive refinement splatting, Pyramid Splatting, Pyramidal volume splatting

## Overview
Hierarchical splatting is a progressive refinement algorithm for volume rendering that uses a pyramidal volume representation to achieve real-time interactive rendering [S2, unofficial]. It solves the performance bottleneck of rendering large, high-resolution volume datasets by decomposing the volume into cubes of varying sizes based on homogeneity, approximating each homogeneous section with a single large splat projected onto the image plane [S4, unofficial]. Unlike standard splatting which treats all voxels equally, hierarchical splatting adapts the resolution of the rendering primitives to the visual complexity of the data, allowing for efficient culling of distant or homogeneous regions while maintaining fidelity in complex areas [S2, unofficial][S4, unofficial].

## How it works
**Inputs:**
*   A 3D volume dataset of size $N^3$ samples [S3, unofficial][S5, unofficial].
*   A user-specified error threshold $\epsilon$ that measures the desired homogeneity for the volume decomposition [S4, unofficial].

**Outputs:**
*   A rendered image composed of RGBA Gouraud-shaded polygons approximating the splats [S2, unofficial][S4, unofficial].

**Data Structures:**
The core data structure is a **Volume Pyramid** [S3, unofficial][S5, unofficial].
*   **Structure:** A sequence of $\log_2 N$ volumes [S3, unofficial][S5, unofficial].
*   **Level 0:** The original dataset of size $N^3$ [S3, unofficial][S5, unofficial].
*   **Level $k$ ($k > 0$):** Created from Level $k-1$ by averaging each $2 \times 2 \times 2$ group of samples [S3, unofficial][S5, unofficial]. This results in a volume with one-eighth the resolution (linear dimensions halved) of the previous level [S3, unofficial][S5, unofficial].
*   **Node Content:** Each node (voxel) in the pyramid stores:
    *   Average RGB color [S4, unofficial].
    *   Average Alpha (opacity) [S4, unofficial].
    *   Estimated Error ($E$): The approximation cost of representing the node's children with the node's aggregate properties [S4, unofficial]. This error quantifies the deviation if the region is rendered with one average splat instead of the original data [S4, unofficial].

**Algorithm Steps:**

1.  **Pyramid Construction:**
    Build the pyramid from the input volume. For each level $k$ from 1 to $\log_2 N$:
    *   Iterate through all $2 \times 2 \times 2$ blocks of voxels in Level $k-1$ [S3, unofficial].
    *   Compute the average RGB and Alpha for the block to form the voxel at the corresponding position in Level $k$ [S4, unofficial].
    *   Compute the error $E$ for the new voxel [S4, unofficial]. The error represents the variance or deviation of the 8 child values from the parent's average [S4, unofficial].

2.  **Octree Fitting (Traverse and Select):**
    Traverse the pyramid to determine which nodes are rendered as single splats and which are subdivided [S4, unofficial].
    *   Start at the root (Level $\log_2 N$) [S4, unofficial].
    *   For a given node, compare its error $E$ against the user threshold $\epsilon$ [S4, unofficial].
    *   **If $E \le \epsilon$:** The node is homogeneous enough [S4, unofficial]. It is selected as a leaf node. A single splat is generated for this node, scaled to match the projection of the corresponding volume cell [S2, unofficial].
    *   **If $E > \epsilon$:** The node is too heterogeneous [S4, unofficial]. Recursively traverse its children in the next finer level [S4, unofficial].
    *   The traversal continues down the pyramid until the error in a node is less than or equal to the desired threshold [S4, unofficial].

3.  **Footprint Table Generation:**
    For every level of the pyramid, calculate proper-sized footprint tables [S4, unofficial]. These tables define the screen-space footprint (polygon shape and size) for projecting and compositing cells of that specific level [S4, unofficial]. The footprint size scales with the resolution of the pyramid level; higher levels (coarser resolution) have larger footprints [S1, unofficial].

4.  **Rendering (Splatting):**
    *   Identify the set of leaf nodes from the traversal step [S4, unofficial].
    *   Sort these leaf nodes in back-to-front order based on the viewing direction [S2, unofficial][S4, unofficial].
    *   For each leaf node:
        *   Project the volume cell onto the image plane [S4, unofficial].
        *   Approximate the splat as an RGBA Gouraud-shaded polygon [S2, unofficial][S4, unofficial].
        *   Use the pre-calculated footprint table for the node's pyramid level to determine the polygon's geometry [S4, unofficial].
        *   Rasterize the polygon using standard graphics hardware [S1, unofficial][S2, unofficial][S4, unofficial].

**Pseudocode:**

```python
def build_pyramid(volume_data):
    """
    Constructs the volume pyramid.
    volume_data: 3D list of shape (N, N, N) containing (R, G, B, A) tuples.
    Returns: List of pyramid levels, where level 0 is original data.
    """
    pyramid = [volume_data]
    current_level = volume_data
    n = len(current_level)
    
    while n > 1:
        next_n = n // 2
        next_level = []
        next_error = []
        
        for x in range(next_n):
            level_x = []
            error_x = []
            for y in range(next_n):
                level_y = []
                error_y = []
                for z in range(next_n):
                    # Extract 2x2x2 block from current level
                    block = []
                    for dx in range(2):
                        for dy in range(2):
                            for dz in range(2):
                                block.append(current_level[2*x+dx][2*y+dy][2*z+dz])
                    
                    # Compute average RGB and Alpha
                    avg_r = sum(v[0] for v in block) / 8.0
                    avg_g = sum(v[1] for v in block) / 8.0
                    avg_b = sum(v[2] for v in block) / 8.0
                    avg_a = sum(v[3] for v in block) / 8.0
                    avg = (avg_r, avg_g, avg_b, avg_a)
                    level_y.append(avg)
                    
                    # Compute error (variance of children from parent mean)
                    err = sum((v[0]-avg_r)**2 + (v[1]-avg_g)**2 + (v[2]-avg_b)**2 + (v[3]-avg_a)**2 for v in block) / 8.0
                    error_y.append(err)
                level_x.append(level_y)
                error_x.append(error_y)
            next_level.append(level_x)
            next_error.append(error_x)
        
        pyramid.append({'data': next_level, 'error': next_error})
        current_level = next_level
        n = next_n
        
    return pyramid

def traverse_and_select(pyramid, threshold):
    """
    Traverses the pyramid to select leaf nodes for splatting.
    pyramid: List of pyramid levels (index 0 is finest, index -1 is coarsest root)
    threshold: User-specified error threshold epsilon
    Returns: List of leaf nodes, each containing (level_index, x, y, z, rgb, alpha)
    """
    leaves = []
    num_levels = len(pyramid)
    
    def recurse(level_idx, x, y, z):
        node = pyramid[level_idx]
        error = node['error'][x][y][z]
        rgb_alpha = node['data'][x][y][z]
        
        # If error is below threshold, select this node as a leaf
        if error <= threshold:
            leaves.append({
                'level': level_idx,
                'x': x, 'y': y, 'z': z,
                'rgb': rgb_alpha[:3],
                'alpha': rgb_alpha[3]
            })
        else:
            # Recurse to children (finer level)
            if level_idx + 1 < num_levels:
                base_x = 2 * x
                base_y = 2 * y
                base_z = 2 * z
                for dx in range(2):
                    for dy in range(2):
                        for dz in range(2):
                            recurse(level_idx + 1, base_x + dx, base_y + dy, base_z + dz)
            else:
                # Reached base level (original data) but error still high
                leaves.append({
                    'level': level_idx,
                    'x': x, 'y': y, 'z': z,
                    'rgb': rgb_alpha[:3],
                    'alpha': rgb_alpha[3]
                })

    # Start at root (coarsest level)
    root_level = num_levels - 1
    root_size = len(pyramid[root_level]['data'])
    for x in range(root_size):
        for y in range(root_size):
            for z in range(root_size):
                recurse(root_level, x, y, z)
                
    return leaves

def sort_back_to_front(leaves, view_direction, camera_origin):
    """
    Sorts leaf nodes in back-to-front order based on view direction.
    Uses dot product of node center with view direction.
    """
    def depth(leaf):
        cx, cy, cz = leaf['x'], leaf['y'], leaf['z']
        return -(cx * view_direction[0] + cy * view_direction[1] + cz * view_direction[2])
    return sorted(leaves, key=depth)

def project_polygon(leaf, footprint_size, view_transform):
    """
    Projects a volume cell's footprint to screen space.
    Returns a list of 2D screen coordinates for the polygon vertices.
    """
    scale = 2.0 ** (leaf['level'])
    screen_x = (leaf['x'] * scale + footprint_size / 2.0) * view_transform[0]
    screen_y = (leaf['y'] * scale + footprint_size / 2.0) * view_transform[1]
    return [(screen_x, screen_y), (screen_x + footprint_size, screen_y), 
            (screen_x + footprint_size, screen_y + footprint_size), (screen_x, screen_y + footprint_size)]

def rasterize_polygon(screen_polygon, rgb, alpha, image_buffer):
    """
    Rasterizes a polygon onto the image buffer using alpha compositing.
    """
    for sx, sy in screen_polygon:
        if 0 <= sx < len(image_buffer[0]) and 0 <= sy < len(image_buffer):
            prev_r, prev_g, prev_b, prev_a = image_buffer[sy][sx]
            inv_a = 1.0 - alpha
            image_buffer[sy][sx] = (
                rgb[0] * alpha + prev_r * inv_a,
                rgb[1] * alpha + prev_g * inv_a,
                rgb[2] * alpha + prev_b * inv_a,
                alpha + prev_a * inv_a
            )

def render(pyramid, leaves, view_direction, camera_origin, footprint_tables, image_height, image_width):
    """
    Renders the selected leaves using splatting.
    """
    sorted_leaves = sort_back_to_front(leaves, view_direction, camera_origin)
    image = [[(0.0, 0.0, 0.0, 0.0) for _ in range(image_width)] for _ in range(image_height)]
    
    for leaf in sorted_leaves:
        level_idx = leaf['level']
        footprint_size = footprint_tables[level_idx]
        screen_polygon = project_polygon(leaf, footprint_size, (1.0, 1.0, 0.0))
        rasterize_polygon(screen_polygon, leaf['rgb'], leaf['alpha'], image)
        
    return image
```

**Parameters:**
*   **Error Threshold ($\epsilon$):** A user-specified value determining the desired homogeneity [S4, unofficial]. Selecting a larger error results in fewer subvolumes (coarser decomposition), while decreasing the error increases the number of subvolumes (finer decomposition) [S4, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** The error metric computation must be stable. If the volume data has high dynamic range, the error values may require normalization [G].
*   **Boundary Conditions:** The pyramid construction assumes $N$ is a power of 2. If $N$ is not a power of 2, padding or truncation is required [G].
*   **Degenerate Input:** If the volume is completely homogeneous, the error at the root is minimal, so the algorithm selects the root node and renders a single large splat [S4, unofficial].

## Operating characteristics
*   **Time Complexity:** Pyramid construction is $O(N^3)$ [S4, unofficial][S5, unofficial]. Traversal is proportional to the number of leaf nodes, which depends on $\epsilon$ [G]. Rendering is proportional to the number of leaf nodes [G].
*   **Memory Complexity:** The pyramid stores a sequence of volumes at decreasing resolutions, so memory usage is slightly higher than the original volume size [S2, unofficial][S4, unofficial].
*   **Measured Performance:** For binary data, bits can be packed into bytes to produce lower resolution images faster (1/8th time for half linear resolution) [S3, unofficial]. The algorithm enables real-time interactive rendering suitable for applications requiring progressive refinement [S1, unofficial].
*   **Strengths:** Real-time performance, adaptive resolution, efficient use of graphics hardware via polygon approximation [S1, unofficial][S2, unofficial].
*   **Limitations:** The quality is dependent on the choice of $\epsilon$ [S4, unofficial]. Visual artifacts may occur at boundaries between different pyramid levels if blending is not handled correctly [G].

## Background
Hierarchical splatting was introduced by David Laur and Pat Hanrahan in 1991 [S2, unofficial]. It was designed as a progressive refinement algorithm for volume rendering, leveraging the pyramidal volume representation to achieve real-time interactive rendering [S2, unofficial]. The method approximates splats with RGBA Gouraud-shaded polygons to enable efficient rasterization on modern graphics workstations of the time [S2, unofficial]. It is a foundational technique in the family of multi-resolution volume rendering methods [S2, unofficial].
