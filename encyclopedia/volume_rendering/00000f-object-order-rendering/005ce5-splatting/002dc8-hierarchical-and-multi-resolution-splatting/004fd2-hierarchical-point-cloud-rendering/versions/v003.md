# Hierarchical Point Cloud Rendering

Also called: out-of-core hierarchical traversal, view-dependent LOD selection

## Overview
Hierarchical Point Cloud Rendering efficiently displays massive point clouds by organizing data into a spatial hierarchy (typically a uniform grid or octree) and dynamically selecting the Level of Detail (LOD) for each cell based on the viewer's distance [S1][S2, unofficial]. It solves the performance bottleneck of rendering hundreds of millions of points by allowing aggressive pruning in distant or uniform regions while maintaining high fidelity in the foreground [S1]. It distinguishes itself from [Multi Resolution Alpha Blending](12118-multi-resolution-alpha-blending.md), [Octree-based Hierarchy](12129-octree-based-hierarchy.md), and [Multi-Resolution and Level of Detail (Pyramid, LOD, Downsampling)](12128-multi-resolution-and-level-of-detail-pyramid-lod-downsamplin.md) by using distance-driven LOD selection on a uniform grid rather than error metrics or pyramid downsampling [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A massive point cloud dataset (e.g., 150 million points) stored out-of-core, organized into a hierarchical structure (uniform grid cells or octree nodes) [S1][S2, unofficial].
*   **Output:** A rendered image composed of textured splats, where each splat represents a subset of points from a selected LOD level of a spatial cell [S1].

**Data Structures:**
1.  **Hierarchical Index:** A tree structure (uniform grid or octree) held in memory [S1][S2, unofficial]. Each node represents a spatial region [S1][S2, unofficial].
2.  **LOD Levels:** For each cell/node, multiple simplified versions of the point data are pre-computed [S1]. In the uniform grid approach, points are decimated by a factor of 10 for each decreasing LOD level [S1].
3.  **Point Representation:** Points are rendered as textured splats [S1]. The texture includes an alpha channel to preserve the original silhouette, allowing larger splats to be trimmed effectively [S1].

**Algorithm Steps:**
1.  **Preprocessing:**
    *   Generate a discretization of the scene using a uniform grid (or octree) [S1][S2, unofficial].
    *   Store the bulk of the point data out-of-core (on disk or network) [S1][S2, unofficial].
    *   For each cell, produce multiple simplified point sets by decimating the original points [S1]. A common strategy is reducing the point count by a factor of 10 for each subsequent LOD level [S1].
    *   Keep the coarser LOD levels in main memory for fast access, while the finest level (original points) may remain out-of-core [S1].
    *   Compute or store scaling factors for the textured splats at each LOD level to ensure visual consistency [S1].

2.  **Rendering Loop (Per Frame):**
    *   **Frustum Culling:** Identify cells overlapping the view frustum [S1].
    *   **Front-to-Back Traversal:** Traverse the selected cells in front-to-back order relative to the viewpoint [S1]. This order enables early depth culling and correct alpha blending [S1].
    *   **LOD Selection:** For each cell, calculate the distance $d$ from the cell center to the viewpoint [S1]. Dynamically select the most appropriate LOD level based on $d$ [S1]. Closer cells use higher LODs (more points); distant cells use lower LODs (fewer points) [S1].
    *   **Splat Rendering:** For each selected cell at its chosen LOD, render the points as textured splats [S1]. The scaling factor for the splat is adjusted according to the LOD level to maintain visual density [S1].
    *   **Refinement (Optional):** If the viewpoint is static for a duration (e.g., a few seconds), asynchronously load the finest LOD (original points) for visible cells from disk and update the display [S1].

**Pseudocode:**

```python
import math

def distance(a, b):
    """Euclidean distance between two 3D points."""
    return math.sqrt(sum((x - y) ** 2 for x, y in zip(a, b)))

def project(point_pos, camera_view_proj):
    """Standard perspective projection to normalized device coordinates."""
    vec = [point_pos[0], point_pos[1], point_pos[2], 1.0]
    res = [0.0, 0.0, 0.0, 0.0]
    for i in range(4):
        for j in range(4):
            res[i] += camera_view_proj[i][j] * vec[j]
    if res[3] <= 0.0:
        return None
    return (res[0] / res[3], res[1] / res[3], res[2] / res[3])

def select_lod_by_distance(dist, lod_thresholds):
    """Selects LOD index based on distance thresholds. lod_thresholds is sorted ascending."""
    for i, threshold in enumerate(lod_thresholds):
        if dist <= threshold:
            return i
    return len(lod_thresholds) - 1

def is_viewpoint_static(camera_history, threshold=0.001, frames=150):
    """Returns True if camera movement delta is below threshold for N frames."""
    if len(camera_history) < frames:
        return False
    recent = camera_history[-frames:]
    return all(math.sqrt(sum((a-b)**2 for a,b in zip(recent[i], recent[i+1]))) < threshold for i in range(len(recent)-1))

def render_hierarchical_point_cloud(viewpoint, frustum, hierarchy, lod_cache, disk_loader, camera_history, camera_view_proj):
    """
    viewpoint: Camera position (3D vector)
    frustum: View frustum object with overlap test method
    hierarchy: List of cells/nodes, each containing:
        - center: 3D vector
        - lod_levels: List of point sets [L0, L1, ...] where L0 is finest
        - scaling_factors: List of float scalars for each LOD
        - lod_thresholds: List of distance thresholds for LOD selection
        - bounding_box: AABB for frustum culling
    lod_cache: Dictionary mapping cell_id -> current_lod_index
    disk_loader: Function to load finest LOD points from disk for a cell_id
    camera_history: List of recent camera positions
    camera_view_proj: 4x4 view-projection matrix
    """
    # 1. Identify visible cells
    visible_cells = [cell for cell in hierarchy if frustum.overlaps(cell.bounding_box)]
    
    # 2. Sort front-to-back based on distance to viewpoint
    visible_cells.sort(key=lambda c: distance(c.center, viewpoint))

    # 3. Traverse and render
    for cell in visible_cells:
        # Calculate distance for LOD selection
        dist = distance(cell.center, viewpoint)
        
        # Select LOD index based on distance
        lod_index = select_lod_by_distance(dist, cell.lod_thresholds)
        
        # Retrieve points for this LOD
        # LOD levels are pre-decimated by factor of 10 [S1]
        points = cell.lod_levels[lod_index]
        scale = cell.scaling_factors[lod_index]
        
        # Render textured splats
        for point in points:
            # Project point to screen
            screen_pos = project(point.position, camera_view_proj)
            
            if screen_pos is not None:

                pass

    # 4. Background refinement (if static)
    if is_viewpoint_static(camera_history):
        for cell in visible_cells:
            # Load finest LOD from disk if not in cache
            if cell.id not in lod_cache or lod_cache[cell.id] != 0:
                finest_points = disk_loader.load(cell.id, lod_level=0)
                cell.lod_levels[0] = finest_points
                lod_cache[cell.id] = 0
```

**Parameters and Typical Values:**
*   **Decimation Factor:** 10 points per LOD level reduction [S1].
*   **Performance:** On an Intel Core i7-4790K and GeForce GTX 970, rendering ~150 million points achieved 600 fps for far-away views and 300-600 fps for closer views [S1].
*   **Pruning Aggressiveness:** Quality remains good even with 1 point out of 100 retained in areas with uniform sampling density [S1].

**Edge Cases and Pitfalls:**
*   **Static View Latency:** Loading the finest LOD from disk can take several seconds, causing a delay in high-fidelity display [S1].
*   **Visual Consistency:** Scaling factors for splats must be manually tuned per LOD level to avoid visual artifacts or density mismatches [S1].
*   **Uniform Density Assumption:** Aggressive pruning works best in areas with uniform sampling density; non-uniform areas may require finer LOD granularity [S1].

## Subtopics

### Out-of-Core Point Cloud Rendering
A variant where the dataset exceeds RAM capacity [S2, unofficial]. The octree index is kept in RAM, while point data is streamed from disk or network on demand using a paging system [S2, unofficial]. Nodes are loaded asynchronously to prevent render thread blocking, and evicted when they drift out of view [S2, unofficial]. It relies on a streamable layout (e.g., COPC, Potree) that allows fetching a single node with a single byte-range HTTP request [S2, unofficial]. Prefetching based on camera trajectory is critical to avoid pop-in latency [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Rendering time scales with the number of visible splats after frustum culling and LOD selection [S1].
*   **Memory Complexity:** Main memory usage is dominated by the in-memory LOD levels (coarser levels) and the hierarchy index [S1]. Out-of-core variants use a paging system to stream nodes from disk or network, evicting those that drift out of view [S2, unofficial].
*   **Performance:** High frame rates (300-600 fps) are achievable for massive datasets (150M points) on mid-range hardware [S1].
*   **Strengths:** Handles datasets far larger than RAM; maintains visual quality in foreground; efficient culling [S1].
*   **Limitations:** Requires pre-processing to generate LODs; static view refinement has latency; scaling factors may need manual tuning [S1].
*   **When to Use:** Massive point clouds (hundreds of millions of points) where interactive frame rates are required [S1].
*   **When Not to Use:** Small datasets where overhead of hierarchy management is unjustified; scenes with highly non-uniform density requiring complex error metrics not covered by distance-based LOD [S1].

## Background
The method was presented in the paper "View-dependent Hierarchical Rendering of Massive Point Clouds through Textured Splats" (2019) [S1]. It extends standard textured splatting by integrating a uniform grid hierarchy and distance-based LOD selection [S1]. The out-of-core streaming variant is discussed in later educational materials on point cloud level of detail, referencing formats like Potree and COPC [S2, unofficial].
