# AnySplat

Also called: Pose-free feed-forward 3D Gaussian Splatting

## Overview
AnySplat is a pose-free, feed-forward network that reconstructs a 3D Gaussian Splatting (3DGS) scene from uncalibrated image collections without requiring camera pose annotations [S1, unofficial]. It differs from sibling methods like [InstantSplat](6136-instantsplat.md) and [pixelSplat](6464-pixelsplat.md) by jointly predicting 3D Gaussian primitives and per-image intrinsics/extrinsics in a single forward pass, enabling zero-shot evaluation on casual dense or sparse multi-view captures [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A set of $N$ uncalibrated images $\{I_i\}_{i=1}^N$ with no associated camera poses or intrinsics.
- **Output:** A set of 3D Gaussian primitives $\mathcal{G} = \{G_j\}_{j=1}^M$ and per-image camera parameters (intrinsics $K_i$ and extrinsics $R_i, t_i$) for each input image $i$.

**Data Structures:**
The 3D Gaussian primitives follow the standard 3DGS layout [S1, unofficial]:
- Position $\mu_j \in \mathbb{R}^3$
- Covariance $\Sigma_j \in \mathbb{R}^{3 \times 3}$ (parameterized as rotation $R_j \in SO(3)$ and scale $s_j \in \mathbb{R}^3$)
- Opacity $\alpha_j \in [0, 1]$
- Spherical Harmonics coefficients $c_{j, l}$ for color/diffuse appearance.

**Steps:**
1. **Geometry Prior Extraction:** Extract sparse geometric priors from the input images using a pre-trained geometry network (e.g., MASt3R or VGGT) to establish initial correspondences and depth estimates [S1, unofficial].
2. **Feed-Forward Network:** Pass the image collection through a shared encoder-decoder network. The network outputs:
   - Gaussian parameters $\mathcal{G}$ in a global coordinate frame.
   - Per-image camera parameters $\{K_i, R_i, t_i\}_{i=1}^N$.
3. **Differentiable Rendering:** Render the predicted Gaussians using the predicted camera parameters to generate synthetic views for each input image. The rendering process is differentiable with respect to $\mathcal{G}$ and camera parameters [S1, 6136-instantsplat.md, 6464-pixelsplat.md, unofficial].
4. **Loss Computation:** Compute the loss between rendered views and input images. The loss typically combines photometric reconstruction error ($\mathcal{L}_{L1}$ or $\mathcal{L}_{MSE}$) with perceptual metrics ($\mathcal{L}_{MS-SSIM}$ or $\mathcal{L}_{LPIPS}$) [6136-instantsplat.md][6464-pixelsplat.md].
5. **Optimization:** Update the network weights via backpropagation. Since the method is feed-forward, the network weights are trained once on a dataset of image collections with ground-truth poses (or pseudo-labels from geometry priors) [S1, unofficial].

**Pseudocode:**
```python

    # Step 1: Extract geometry priors (e.g., sparse depth/points)
    # This step uses a pre-trained model like MASt3R/VGGT
    geometry_priors = extract_geometry_priors(images)
    
    # Step 2: Feed-forward network
    # The network takes images and optionally geometry priors as input
    # Outputs: Gaussians G, and per-image poses K, R, t
    G, K_list, R_list, t_list = network(images, geometry_priors)
    
    # Step 3: Render for each image
    rendered_images = []
    for i in range(len(images)):
        # Render using Gaussians G and camera i's parameters
        rendered = render_gaussians(G, K_list[i], R_list[i], t_list[i])
        rendered_images.append(rendered)
        
    return G, K_list, R_list, t_list, rendered_images

def train_any_splat(dataset):
```

**Parameters:**
- **Network Architecture:** Not specified in sources. Typically involves a transformer or CNN-based encoder-decoder [S1, unofficial].
- **Loss Weights:** Not specified in sources. Typical values for $\mathcal{L}_{L1}$ and $\mathcal{L}_{MS-SSIM}$ weights are not given [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Precision:** The accuracy of geometry priors (MASt3R/VGGT) directly impacts the quality of the initial Gaussian placement and pose estimation [S1, unofficial].
- **Boundaries:** The method assumes the input images cover the scene adequately. Sparse views may lead to ambiguities in pose and geometry [S1, unofficial].

## Subtopics

### [FreeSplat](15163-freesplat.md)
A feed-forward framework that reconstructs geometrically consistent global 3D Gaussian Splatting from long sparse image sequences to support free-view synthesis across wide view ranges, eliminating redundancy in overlapping regions.

## Operating characteristics
- **Time Complexity:** Training time is not explicitly given, but inference is a single forward pass, enabling real-time rendering latency [S1, unofficial].
- **Memory Complexity:** Depends on the number of Gaussians $M$. A vanilla 3DGS scene averages 1–2 M Gaussians and 200–800 MB on disk [S1, unofficial].
- **Performance:** Matches pose-aware baselines and surpasses prior pose-free methods (NoPoSplat-class) in zero-shot evaluations [S1, unofficial].
- **Strengths:** No pose annotations required; works with casual dense or sparse multi-view captures; real-time rendering [S1, unofficial].
- **Limitations:** Relies on the quality of geometry priors; performance may degrade with very sparse or ambiguous views [S1, unofficial].

## Background
AnySplat was introduced as a pose-free feed-forward network for 3D Gaussian Splatting [S1, unofficial]. It builds on the principles of differentiable rendering and feed-forward reconstruction methods like [InstantSplat](6136-instantsplat.md) and [pixelSplat](6464-pixelsplat.md) [S1, 6136-instantsplat.md, 6464-pixelsplat.md, unofficial]. The method aims to simplify the reconstruction pipeline by eliminating the need for camera pose estimation as a separate step [S1, unofficial].
