# AnySplat

Also called: Pose-free feed-forward 3D Gaussian Splatting

## Overview
AnySplat is a pose-free, feed-forward network that reconstructs 3D Gaussian Splatting (3DGS) scenes from uncalibrated image collections without requiring camera pose annotations [S1, unofficial]. It differs from sibling methods like [InstantSplat](6136-instantsplat.md) and [pixelSplat](6464-pixelsplat.md) by handling arbitrary multi-view inputs (dense or sparse) in a single forward pass, yielding both scene primitives and per-image intrinsics/extrinsics simultaneously [S1, unofficial]. This enables zero-shot evaluation on casual captures where pose data is unavailable, matching the quality of pose-aware baselines while maintaining real-time rendering latency [S1, unofficial].

## How it works
**Inputs:** A set of $N$ uncalibrated images $\{I_1, \dots, I_N\}$ with unknown intrinsics and extrinsics.
**Outputs:** A set of 3D Gaussian primitives $\mathcal{G} = \{g_i\}$, where each $g_i$ is defined by position $\mu_i$, covariance $\Sigma_i$, opacity $\alpha_i$, and spherical harmonics coefficients $\mathbf{c}_i$; plus estimated camera parameters for each input image.

**Data Structures:**
The network outputs a tensor of Gaussian parameters. The exact layout depends on the specific implementation of the feed-forward backbone (e.g., CNN or Transformer), but typically involves a dense or sparse voxel/grid representation that is decoded into individual Gaussians. The covariance $\Sigma_i$ is usually parameterized via a rotation matrix $\mathbf{R}_i$ and a scaling vector $\mathbf{s}_i$ such that $\Sigma_i = \mathbf{R}_i \mathbf{S}_i \mathbf{S}_i^T \mathbf{R}_i^T$, where $\mathbf{S}_i = \text{diag}(\mathbf{s}_i)$ [G].

**Steps:**
1. **Feature Extraction:** Extract multi-scale features from each input image using a shared encoder backbone (e.g., ResNet or ViT) [S1, unofficial].
2. **Geometric Prior Integration:** Utilize geometry priors (such as those from MASt3R or VGGT) to establish sparse correspondences or depth estimates, which guide the initial placement of Gaussians [S1, unofficial].
3. **Joint Prediction:** A single forward pass through the network predicts the Gaussian parameters ($\mu, \Sigma, \alpha, \mathbf{c}$) and the camera poses (intrinsics $K$, extrinsics $R, t$) for all $N$ images simultaneously [S1, unofficial].
4. **Differentiable Rendering:** Render the predicted Gaussians into each input view using standard differentiable rasterization [S1, 6136-instantsplat.md, 6464-pixelsplat.md, unofficial].
5. **Loss Computation:** Compute the loss between rendered and input images. The loss typically combines photometric error ($\mathcal{L}_{L1}$ or $\mathcal{L}_{MSE}$) and perceptual metrics ($\mathcal{L}_{MS-SSIM}$ or $\mathcal{L}_{LPIPS}$) [6136-instantsplat.md][6464-pixelsplat.md].
6. **Optimization:** Update network weights to minimize the loss. Since poses are predicted, no external pose optimization is required [S1, unofficial].

**Parameters:**
- Number of Gaussians: Not given in the sources.
- Training time: Seconds [S1, unofficial].

**Edge Cases:**
- **Degenerate Input:** If images have insufficient overlap, geometric priors may fail to establish correspondences, leading to poor pose estimation [S1, unofficial].
- **Precision:** The accuracy of predicted intrinsics/extrinsics directly impacts rendering quality; errors accumulate in the covariance calculation [G].

## Subtopics

### [FreeSplat](15163-freesplat.md)
A feed-forward framework for long, sparse sequences using adaptive cost volumes and Pixel-aligned Triplet Fusion. It handles wide baselines better than [pixelSplat](52-pixelsplat.md) and [MVSplat](53-mvsplat.md) by using pure CNN backbones.

## Operating characteristics
**Time and Memory Complexity:**
- Training: Seconds for casual captures [S1, unofficial].
- Rendering: Real-time latency [S1, unofficial].
- Memory: A vanilla 3DGS scene averages 1–2 M Gaussians and 200–800 MB on disk; compression is critical for mobile/web/streaming [S1, unofficial].

**Strengths and Limitations:**
- **Strengths:** No pose annotations required; scales to dense or sparse multi-view captures; matches pose-aware baselines in quality [S1, unofficial].
- **Limitations:** Performance depends on the quality of geometry priors (MASt3R/VGGT); may struggle with very sparse views compared to methods with explicit pose optimization [S1, unofficial].

**When to Use:**
- Use when camera poses are unknown or unavailable.
- Use for casual, unstructured image collections.

**When Not to Use:**
- Use [Joint Pose Optimization](6888-joint-pose-optimization.md) if high-precision poses are available and can be optimized.
- Use [Loss Scheduling for Candidate Head](13095-loss-scheduling-for-candidate-head.md) if specific candidate head strategies are needed for pose refinement.

## Background
AnySplat was introduced as a pose-free feed-forward network that yields 3D Gaussian primitives plus per-image intrinsics and extrinsics in a single pass [S1, unofficial]. It addresses the limitation of prior feed-forward methods (like [pixelSplat](52-pixelsplat.md) and MVSplat) which were limited to narrow-range interpolation or required pose inputs [S1, unofficial]. It builds on the principles of differentiable rendering and loss functions combining photometric and perceptual metrics [6136-instantsplat.md][6464-pixelsplat.md].
