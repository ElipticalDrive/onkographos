# Hierarchical Anchor Coupling

Also called: Per-level hierarchical anchor coupling

## Overview
Hierarchical Anchor Coupling (HAC) is a module that establishes cross-level gradient pathways in structured 3D Gaussian splatting by aggregating context from adjacent octree levels and broadcasting a residual feature adjustment to visible anchors [S1, unofficial]. It solves the problem of feature isolation, where backpropagation graphs in anchor-based octrees lack connections between features at level $l_i$ and their neighbors at $l_i \pm 1$ [S1, unofficial]. Unlike sibling methods that rely on spatial lookup or graph edges, HAC operates at the octree level granularity, providing a shared regularization signal that improves performance on dense, repetitive structures while adding negligible parameters [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** The set of visible anchors $V$ for a training camera, where each anchor $i$ has a base feature vector $f_i$ and an octree level $l_i$.
*   **Output:** Enhanced feature vectors $\hat{f}_i$ for all $i \in V$, which replace $f_i$ as input to the downstream Neural Gaussian decoding MLPs.

**Data Structures:**
*   **Visible Anchor Set ($V$):** The subset of all anchors projected into the current camera's frustum.
*   **Level Set ($L_V$):** The set of unique octree levels present in $V$: $L_V = \{l_i : i \in V\}$.
*   **Level-Specific Anchor Sets ($V_l$):** The subset of visible anchors at level $l$: $V_l = \{i \in V : l_i = l\}$.
*   **Context Vectors ($c^l_{self}, c^l_{par}, c^l_{chi}$):** Aggregated features for level $l$, each in $\mathbb{R}^d$.
*   **Triplet ($t_l$):** Concatenated context vector in $\mathbb{R}^{3d}$.
*   **Adjustment ($\delta^l$):** Residual feature vector in $\mathbb{R}^d$.
*   **MLP ($g_\theta$):** A two-layer Multi-Layer Perceptron with hidden dimension $d$ and ReLU activation, mapping $\mathbb{R}^{3d} \to \mathbb{R}^d \to \mathbb{R}^d$ [S1, unofficial].

**Parameters:**
*   **Hidden Dimension ($d$):** Default value is 32 [S1, unofficial].
*   **Granularity:** Per-level (default) computes one $\delta^l$ per visible level. Per-anchor computes one $\delta^i$ per visible anchor [S1, unofficial].

**Steps:**
1.  Identify the set of visible levels $L_V$ and, for each $l \in L_V$, the set of visible anchors $V_l$.
2.  For each level $l \in L_V$, compute the self-context $c^l_{self}$ as the mean of base features in $V_l$:
    $$ c^l_{self} = \frac{1}{|V_l|} \sum_{i \in V_l} f_i $$
3.  Compute the coarser-level context $c^l_{par}$ by aggregating features from level $l-1$ using operator $A_{par}$:
    $$ c^l_{par} = A_{par}(\{f_i\}_{i \in V_{l-1}}) $$
    *Note: $A_{par}$ incorporates octree topology (e.g., Structure-Aware Containment Aggregation) [S1, unofficial].*
4.  Compute the finer-level context $c^l_{chi}$ by aggregating features from level $l+1$ using operator $A_{chi}$:
    $$ c^l_{chi} = A_{chi}(\{f_i\}_{i \in V_{l+1}}) $$
    *Note: $A_{chi}$ incorporates octree topology [S1, unofficial].*
5.  **Boundary Handling:** If level $l$ lacks an adjacent coarser level ($l-1$) or finer level ($l+1$) in $L_V$, the corresponding context vector ($c^l_{par}$ or $c^l_{chi}$) defaults to $c^l_{self}$ [S1, unofficial].
6.  Concatenate the three context vectors into a triplet $t_l$:
    $$ t_l = [c^l_{par}; c^l_{self}; c^l_{chi}] \in \mathbb{R}^{3d} $$
7.  Compute the level-wise adjustment $\delta^l$ using the MLP:
    $$ \delta^l = g_\theta(t_l) $$
8.  Broadcast $\delta^l$ to all visible anchors at level $l$ to produce enhanced features:
    $$ \hat{f}_i = f_i + \delta^l, \quad \forall i \in V_l $$
9.  Pass $\{\hat{f}_i\}_{i \in V}$ to the Neural Gaussian decoding MLPs for rasterization.

**Pseudocode:**
```python
def hierarchical_anchor_coupling(visible_anchors, level_mlp, aggregation_op):
    """
    visible_anchors: List of objects with attributes .id, .level, .feature (f_i)
    level_mlp: Function g_theta taking R^3d and returning R^d
    aggregation_op: Function A taking a list of features and returning a context vector
    
    Returns: List of enhanced features f_hat_i
    """
    # Group anchors by level
    level_groups = {}
    for anchor in visible_anchors:
        l = anchor.level
        if l not in level_groups:
            level_groups[l] = []
        level_groups[l].append(anchor)
        
    levels_present = sorted(level_groups.keys())
    level_set = set(levels_present)
    
    # Pre-compute context vectors for all present levels
    level_contexts = {}
    
    for l in levels_present:
        anchors_l = level_groups[l]
        features_l = [a.feature for a in anchors_l]
        
        # 1. Self-context
        c_self = sum(features_l) / len(features_l)
        
        # 2. Coarser context (l-1)
        if (l - 1) in level_set:
            features_par = [a.feature for a in level_groups[l - 1]]
            c_par = aggregation_op(features_par)
        else:
            c_par = c_self
            
        # 3. Finer context (l+1)
        if (l + 1) in level_set:
            features_chi = [a.feature for a in level_groups[l + 1]]
            c_chi = aggregation_op(features_chi)
        else:
            c_chi = c_self
            
        # 4. Triplet and Adjustment
        triplet = concatenate([c_par, c_self, c_chi])
        delta_l = level_mlp(triplet)
        
        level_contexts[l] = delta_l
        
    # 5. Broadcast and Enhance
    enhanced_features = []
    for anchor in visible_anchors:
        l = anchor.level
        delta = level_contexts[l]
        f_hat = anchor.feature + delta
        enhanced_features.append(f_hat)
        
    return enhanced_features
```

## Subtopics

### Per-level vs. Per-anchor Granularity
Per-level computes one adjustment $\delta^l$ per visible level, scaling MLP cost with the number of levels. Per-anchor computes a distinct $\delta^i$ per visible anchor via spatial lookup, scaling with $|V|$. Per-level is preferred for dense repetitive structures (+1.06 dB on Building), while per-anchor is slightly better for simpler geometry (+0.21 dB on Rubble) [S1, unofficial].

### Structure-Aware Containment Aggregation (SACA)
The aggregation operators $A_{par}$ and $A_{chi}$ often utilize SACA, which uses binary or soft-weighted masks based on octree containment to reduce the influence of topologically isolated anchors [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The MLP evaluation cost scales with the number of visible levels, not the number of visible anchors $|V|$. The aggregation and broadcasting steps scale linearly with $|V|$ [S1, unofficial]. Per-level is ~20% faster in training than per-anchor [S1, unofficial].
*   **Memory Complexity:** Adds 4,160 parameters (for $d=32$) via the shared MLP, representing <0.1% of total parameters [S1, unofficial].
*   **Performance:** Yields a PSNR improvement of +1.91 dB over the baseline on Mill19-Building [S1, unofficial]. In end-to-end rendering, it can improve FPS (e.g., 39.4 FPS vs 29.0 FPS) by allowing fewer Neural Gaussians to be decoded and rasterized while maintaining quality [S1, unofficial].
*   **Strengths:** Alleviates feature isolation; low parameter overhead; effective on large-scale scenes with repetitive structures.
*   **Limitations:** Relies on the quality of the underlying octree structure; performance gain on simple geometry is marginal compared to per-anchor [S1, unofficial].

## Background
Hierarchical Anchor Coupling was introduced in the TopoGS paper by the authors of the provided source [S1, unofficial]. It is integrated into backbones such as CityGS-X, Octree-GS, and Proxy-GS at the anchor-feature aggregation stage [S1, unofficial]. The method addresses limitations in existing anchor-based octree pipelines where backpropagation paths are disconnected across levels [S1, unofficial].
