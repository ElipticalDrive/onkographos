# Fine-tuning

Also called: 3DGS Fine-tuning, Fine-tuning Strategy, Gaussian Splatting Fine-tuning, Per-scene optimization

## Overview
Fine-tuning in 3D Gaussian Splatting refers to a per-scene optimization process that refines an initial set of 3D Gaussian primitives to reconstruct a specific scene with high fidelity [S1, S3]. It addresses the problem of initializing a scene representation from sparse or noisy data by treating the reconstruction as a continuous optimization problem supervised by rendered image losses [S1, S3]. Unlike static initialization methods, fine-tuning actively adjusts geometry, color, and opacity attributes, often enabling dynamic densification (growing and pruning) to adapt the primitive count to the scene's complexity [S3]. It sets itself apart from global training strategies by focusing on optimizing a single, fixed scene representation from a pre-initialized state, rather than learning a generalizable mapping from inputs to outputs [S1, S3].

## How it works
The fine-tuning process generally follows a two-phase structure: initialization via a feed-forward or generative model, followed by differentiable rendering-based optimization [S1, S3].

### Inputs and Outputs
- **Inputs**: An initial set of 3D Gaussian primitives $\mathcal{G}_0 = \{g_1, \dots, g_N\}$, where each $g_k$ is defined by mean position $\mu_k$, covariance $\Sigma_k$ (scale $s_k$, rotation $q_k$), opacity $\alpha_k$, and spherical harmonic coefficients $\mathbf{c}_k$ [Parent]. These are typically derived from a point cloud, a voxel representation, or a direct feed-forward prediction [S1, S3]. A set of training images (scanned color frames or novel views) with known camera poses [S1, S3].
- **Outputs**: An optimized set of 3D Gaussian primitives $\mathcal{G}_{final}$ that minimizes the rendering loss against the training images [S1, S3].

### Data Structures
The Gaussian set $\mathcal{G}$ is stored as a list or array of primitives. Each primitive $g_k$ contains:
- $\mu_k \in \mathbb{R}^3$: Position.
- $s_k \in \mathbb{R}^3$: Scale (often parameterized as log-scale for optimization stability) [G].
- $q_k \in \mathbb{R}^4$: Rotation (quaternion, normalized) [G].
- $\alpha_k \in [0, 1]$: Opacity.
- $\mathbf{c}_k$: Spherical Harmonic coefficients (typically degree 3, requiring 45 coefficients per RGB channel, or fewer if SH degree is reduced) [S3].

### Steps
1. **Initialization**:
   - If using a generative approach (e.g., GPN), obtain a voxel representation of the object using volume density samples along rays, reconstruct a mesh via marching cubes, and predict vertex colors from rendered novel views [S1].
   - If using a feed-forward approach (e.g., EVolSplat), predict a set of 3D Gaussian primitives directly, generating both geometry and color attributes [S3].
   - Initialize the Gaussian set $\mathcal{G}_0$ with these parameters [S1, S3].
2. **Optimization Loop**:
   - For each iteration $t$:
     - Sample a training image and its camera pose from the provided set [S1, S3].
     - Render the current Gaussian set $\mathcal{G}_t$ to produce $I_{render}$ using differentiable rasterization [S1, S3].
     - Compute the rendering loss $\mathcal{L}_{color}$ between $I_{render}$ and the ground truth image [S1, S3].
     - Backpropagate the loss to update the parameters of $\mathcal{G}_t$ (positions, scales, rotations, opacities, SH coefficients) using an optimizer (e.g., Adam) [S3].
     - **Densification**: Enable growing and pruning of 3D primitives during fine-tuning to adapt the density [S3]. This may involve splitting large Gaussians or cloning small ones based on gradient statistics or opacity thresholds, as detailed in [Densification Strategy](6234-densification-strategy.md).
3. **Convergence**:
   - Repeat until the loss converges or a fixed number of iterations is reached [S1, S3].

### Formulas
- **Rendering Loss**:
  $$ \mathcal{L}_{color} = \text{Loss}(I_{render}, I_{gt}) $$
  where $\mathcal{L}_{color}$ denotes the differentiable rendering loss supervised by scanned color frames or training images [S1, S3].
- **Parameter Update**:
  $$ \theta_{t+1} = \theta_t - \eta \nabla_\theta \mathcal{L}_{color} $$
  where $\theta$ represents all Gaussian parameters and $\eta$ is the learning rate (e.g., $1 \times 10^{-3}$) [S3].

### Parameters
- **Learning Rate**: $1 \times 10^{-3}$ for Adam optimizer [S3].
- **SH Degree**: Typically reduced during early training (e.g., degree 0) and increased later to balance speed and detail [S3].
- **Number of Transfer Functions**: In image-space fine-tuning for volumes, 5 transfer functions are typically used [S4, unofficial].

### Edge Cases and Pitfalls
- **Overfitting**: Fine-tuning on a single scene can lead to overfitting if the number of Gaussians becomes too large or if the optimization runs for too many iterations without regularization [S1].
- **Initialization Quality**: Poor initialization (e.g., from a noisy point cloud) can lead to local minima or slow convergence [S1, S3].
- **Memory Usage**: Fine-tuning with growing and pruning can cause memory spikes if not managed carefully [S3].

### Pseudocode
```python
def fine_tune_gaussians(G_0, training_data, num_iterations, lr=1e-3):
    G = G_0  # Initialize Gaussian set from feed-forward or generative model [S1, S3]
    optimizer = Adam(G.parameters(), lr=lr)  # Use Adam optimizer [S3]
    for t in range(num_iterations):
        # Sample training image and camera pose [S1, S3]
        I_gt, P_gt = sample_training_image(training_data)
        # Render current Gaussians via differentiable rasterization [S1, S3]
        I_render = rasterize(G, P_gt)
        # Compute rendering loss [S1, S3]
        loss = compute_rendering_loss(I_render, I_gt)
        # Backpropagate and update parameters [S3]
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        # Enable growing and pruning of 3D primitives [S3]
        G = densify_and_prune(G, loss, t)
    return G
```

## Subtopics

### Image-space Gaussian Fine-tuning
A fine-tuning process for volumetric data that accounts for different visual modes by generating multiple radiance fields using different transfer functions and optimizing the Gaussian set against rendered images [S4, unofficial]. It sets itself apart from standard fine-tuning by handling multi-modal volumes (e.g., medical scans) where a single radiance field cannot capture all features [S4, unofficial]. Choose this when dealing with volumes with distinct density ranges or material properties.
- **Steps**:
  1. Select a series of transfer functions $\{TF_h\}$, where each $TF_h$ is non-zero only within specific value intervals of the physical field $F$ [S4, unofficial].
  2. Generate radiance fields $RF_h = TF_h(F)$ for each mode $h$ [S4, unofficial].
  3. Render 64 images through volumetric integration for each radiance field to provide supervision data [S4, unofficial].
  4. Compute image-space loss and backpropagate to update the Gaussian set $G_h$ [S4, unofficial].
  5. After fine-tuning, Gaussians $G_h$ for each mode can be concatenated or separately rendered [S4, unofficial].
- **Parameters**: 5 transfer functions are selected for each volume in practice [S4, unofficial].

### Ada-GS
A baseline method that trains vanilla 3D Gaussian Splatting directly on 2D stylized images [S5]. It sets itself apart from style transfer methods that operate on rendered images (like GS-Ada) by optimizing the 3D Gaussians directly against stylized supervision [S5]. Choose this when you need to apply a specific style to a 3D scene, but be aware that it requires training from scratch for every new style image, limiting practical usability [S5].
- **Steps**:
  1. Train vanilla 3DGS using 2D stylized views as ground truth supervision [S5].
- **Comparison**: Preserves better details than GS-Ada but requires training from scratch for every new style image [S5].

## Operating characteristics
- **Time Complexity**: Fine-tuning is generally faster than training from scratch because it starts from a reasonable initialization [S3]. However, it still requires multiple iterations of differentiable rendering and backpropagation [S1, S3].
- **Memory Complexity**: Memory usage depends on the number of Gaussians, which can grow during fine-tuning due to densification [S3].
- **Performance**: Can achieve photorealism on par with or surpassing other methods, leveraging powerful pretrained weights [S3].
- **Strengths**: High fidelity, adapts to scene complexity, works with sparse or noisy initialization [S1, S3].
- **Limitations**: Requires per-scene optimization, which can be slow for large scenes; sensitive to initialization quality [S1, S3].
- **When to use**: When you have a specific scene to reconstruct and a good initialization method (e.g., from a point cloud or feed-forward model) [S1, S3].

## Background
Fine-tuning in the context of 3D Gaussian Splatting builds on earlier work in NeRF fine-tuning and generative models. The concept of treating a reconstructed mesh or point cloud as a single-scene NeRF for optimization was introduced in GPN (Generative Point-based NeRF) [S1]. The use of feed-forward models to initialize 3D Gaussians for fine-tuning was later explored in EVolSplat [S3].
