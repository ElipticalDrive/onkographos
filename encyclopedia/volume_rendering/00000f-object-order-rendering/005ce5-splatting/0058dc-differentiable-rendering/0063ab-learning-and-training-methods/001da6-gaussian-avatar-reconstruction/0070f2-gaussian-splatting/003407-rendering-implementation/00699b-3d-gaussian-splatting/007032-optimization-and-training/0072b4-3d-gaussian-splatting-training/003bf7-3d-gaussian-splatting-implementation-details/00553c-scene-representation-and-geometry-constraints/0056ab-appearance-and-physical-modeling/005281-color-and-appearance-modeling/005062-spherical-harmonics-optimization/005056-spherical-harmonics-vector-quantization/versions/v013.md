# Spherical Harmonics Vector Quantization

Also called: SH clustering, SH palette

## Overview
Spherical Harmonics Vector Quantization (SH VQ) is a compression technique for 3D Gaussian Splatting that replaces per-splat Spherical Harmonics (SH) coefficients with indices pointing to a shared palette of distinct SH vectors, significantly reducing memory footprint at the cost of minor lighting artifacts [S1, unofficial]. It distinguishes itself from other optimization methods by targeting the storage of view-dependent appearance data specifically, rather than modifying the rendering equation or camera Jacobian derivation [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A set of 3D Gaussians, each associated with a set of SH coefficients representing view-dependent color.
*   **Output:** A palette of $K$ distinct SH vectors and a 16-bit index for each Gaussian pointing to its closest palette entry.

**Data Structures**
1.  **Palette:** An array of $K$ SH vectors. Each vector contains 45 floating-point numbers (15 per RGB channel), excluding the first coefficient (DC term) which is treated as base color [S1, unofficial]. Stored as FP16 [S1, unofficial].
2.  **Indices:** An array of 16-bit integers, one per Gaussian, storing the index into the Palette [S1, unofficial].

**Parameters**
*   **Palette Size ($K$):** Typically 4,000 to 16,000 distinct SH items [S1, unofficial].
*   **SH Dimensionality:** 45 dimensions per splat (excluding DC term) [S1, unofficial].
*   **Index Bit Depth:** 16 bits per splat [S1, unofficial].

**Algorithm Steps**
1.  Extract all SH data (45 floats per splat) from the Gaussian Splat scene [S1, unofficial].
2.  Cluster the extracted SH data into $K$ distinct items using a variant of mini-batch k-means to form the palette [S1, unofficial].
3.  For each original SH data point, find the closest item in the palette [S1, unofficial].
4.  Store the index of the closest palette item for each splat [S1, unofficial].

**Pseudocode**
```python
def spherical_harmonics_vector_quantization(sh_data: List[List[float]], k: int) -> Tuple[List[List[float]], List[int]]:
    """
    Compress SH coefficients using vector quantization.
    
    Args:
        sh_data: List of SH coefficient vectors for each splat. 
                 Each vector has length 45 (excluding DC term).
        k: Number of palette entries (e.g., 4000 or 16000).
        
    Returns:
        palette: List of k SH vectors (each length 45).
        indices: List of indices into palette for each splat.
    """
    # Step 1: Initialize centroids for k-means
    # [G] Simple random initialization from the dataset is standard.
    centroids = random.sample(sh_data, k)
    
    # Step 2: Mini-batch K-Means Clustering
    # [G] The source notes a custom implementation is used for speed, 
    # but the logic follows standard mini-batch k-means.
    for iteration in range(max_iterations):
        # Sample a mini-batch of data points
        batch = random.sample(sh_data, batch_size)
        
        # Assign each point in batch to nearest centroid
        assignments = []
        for point in batch:
            distances = [euclidean_distance(point, centroid) for centroid in centroids]
            closest_idx = argmin(distances)
            assignments.append(closest_idx)
            
        # Update centroids based on assignments
        for i in range(k):
            members = [batch[j] for j in range(len(batch)) if assignments[j] == i]
            if members:
                centroids[i] = mean(members)
                
    # Step 3: Assign all original data to palette
    indices = []
    for point in sh_data:
        distances = [euclidean_distance(point, centroid) for centroid in centroids]
        closest_idx = argmin(distances)
        indices.append(closest_idx)
        
    return centroids, indices

def euclidean_distance(v1: List[float], v2: List[float]) -> float:
    return sum((a - b) ** 2 for a, b in zip(v1, v2)) ** 0.5

def mean(vectors: List[List[float]]) -> List[float]:
    if not vectors:
        return [0.0] * len(vectors[0])
    dim = len(vectors[0])
    return [sum(v[d] for v in vectors) / len(vectors) for d in range(dim)]
```

**Edge Cases and Pitfalls**
*   **Curse of Dimensionality:** Clustering millions of splats into thousands of items in 45 dimensions is computationally slow [S1, unofficial].
*   **Lighting Artifacts:** The quantization introduces minor lighting artifacts, though they are generally considered acceptable for the compression ratio [S1, unofficial].
*   **Implementation Choice:** Standard libraries like scikit-learn are too slow; Faiss is faster but adds dependencies. A custom mini-batch k-means implementation is preferred for speed and lack of dependencies [S1, unofficial].

## Operating characteristics
*   **Memory Footprint:**
    *   **Palette:** 360KB to 1.44MB (for $K=4k-16k$, stored as FP16) [S1, unofficial].
    *   **Indices:** ~12MB for 6.1M splats (using 16-bit indices) [S1, unofficial].
    *   **Total SH Storage:** ~13MB for scenes like 'bike' or 'garden' at 16k palette size [S1, unofficial].
*   **Performance:**
    *   **Clustering Speed:** Custom mini-batch k-means is ~3x faster than Faiss and provides better quality for this specific task [S1, unofficial].
    *   **Rendering:** No change to rendering time; only memory bandwidth for indices and palette lookup is affected.
*   **Quality:**
    *   **16k Palette (Low Preset):** Retains shininess effects. PSNR ~35.17-35.32 for 'bike' scene [S1, unofficial].
    *   **4k Palette (Very Low Preset):** PSNR ~32.27-31.10 for 'bike' scene [S1, unofficial].
*   **Strengths:** Significant reduction in data size (e.g., from 1.1GB raw SH to ~13MB) while maintaining acceptable visual quality for real-time applications [S1, unofficial].
*   **Limitations:** Introduces quantization artifacts; clustering is slow for very large datasets without optimized implementations [S1, unofficial].

## Background
Spherical Harmonics Vector Quantization was introduced by Aras Pranckevičius in a blog post titled "Making Gaussian Splats more smaller" [S1, unofficial]. It was developed as part of a toy "Gaussian Splatting for Unity" implementation to enable real-time rendering of large scenes on consumer hardware by reducing memory bandwidth requirements [S1, unofficial]. The method draws inspiration from traditional palette-based color compression techniques used in early computer displays [S1, unofficial].
