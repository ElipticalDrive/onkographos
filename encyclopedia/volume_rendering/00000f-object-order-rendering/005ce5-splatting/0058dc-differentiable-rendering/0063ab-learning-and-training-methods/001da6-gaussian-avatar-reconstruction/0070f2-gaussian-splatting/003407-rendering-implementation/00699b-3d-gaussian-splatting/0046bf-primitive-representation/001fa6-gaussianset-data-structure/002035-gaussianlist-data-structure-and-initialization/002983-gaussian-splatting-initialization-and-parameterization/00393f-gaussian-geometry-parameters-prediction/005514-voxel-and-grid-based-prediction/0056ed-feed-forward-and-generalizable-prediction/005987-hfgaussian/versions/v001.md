# HFGaussian

Also called: Human Feature Gaussian

## Overview
HFGaussian is a generalizable, human-centric 3D Gaussian Splatting framework that estimates 3D human avatars with integrated biomechanical features (3D skeleton, 3D keypoints, dense pose) and 3D pose in real time from sparse input images, without per-subject fine-tuning [S1]. It sets itself apart from sibling methods like [AnySplat Pipeline](12847-anysplat-pipeline.md) and [FineSplat](15257-finesplat.md) by explicitly predicting continuous surface embeddings and pose parameters alongside photometric data using a "feature splatting" mechanism, rather than relying on parametric body models (e.g., SMPL) or direct parameterization of Gaussians with features [S1].

## How it works
**Inputs:** A set of $N$ RGB images $\{I_i\}_{i=1}^N$ with associated camera poses (intrinsics and extrinsics). Typically, $N=8$ source views rendered at 45-degree intervals around the subject [S1].
**Outputs:** A set of 3D Gaussians $\mathcal{G}$ representing the human, rendered novel view images, 3D pose (19 keypoints), and human feature maps (dense pose/continuous surface embeddings) [S1].

**Data Structures:**
The scene is represented as a set of 3D Gaussians $\mathcal{G} = \{X, c, r, s, \alpha, f\}$ [S1]:
*   $X \in \mathbb{R}^3$: 3D position.
*   $c \in \mathbb{R}^3$: RGB color.
*   $r \in \mathbb{R}^4$: Rotation (quaternion).
*   $s \in \mathbb{R}^3$: Scaling.
*   $\alpha \in [0, 1]$: Opacity.
*   $f \in \mathbb{R}^k$: Human feature vector (continuous surface embeddings) [S1].

**Algorithm Steps:**

1.  **View Selection:** For a target view, select the two nearest source views, $I_l$ and $I_r$ (left and right), from the input set [S1].
2.  **Feature Extraction:** Feed $I_l$ and $I_r$ into a shared image encoder $\epsilon_{img}$ to generate multiscale image features $f^l_s$ and $f^r_s$, where $s$ denotes the feature scale [S1].
3.  **Cost Volume & Depth Estimation:**
    *   Generate a cost volume $C$ by correlating feature maps $f^l_s$ and $f^r_s$ [S1].
    *   Use an iterative update mechanism on $C$ to estimate depth maps $D_l$ and $D_r$ for the source views [S1].
4.  **Gaussian Feature Generation:**
    *   Encode depth maps $D_l, D_r$ using an encoder $\epsilon_{depth}$ [S1].
    *   Combine encoded depth features with image features $f^l_s, f^r_s$ (concatenation $\oplus$) and pass through a U-Net-like decoder $\epsilon_{params}$ to generate a Gaussian feature map $\Gamma$ [S1]:
        $$ \Gamma = \epsilon_{params}(\epsilon_{img}(I) \oplus \epsilon_{depth}(I)) $$
5.  **Parameter Prediction:** Use four separate convolutional prediction heads on $\Gamma$ to estimate Gaussian parameter maps for foreground pixels $x$:
    *   Rotation: $M_r(x)$
    *   Scaling: $M_s(x)$
    *   Opacity: $M_\alpha(x)$
    *   Human Feature: $M_f(x) = \text{Sigmoid}(h_f(\Gamma(x)))$, where $h_f$ is the feature head [S1].
    *   Color: $M_c(x)$ uses RGB values directly from source images [S1].
    *   Position: $M_p(x)$ maps 2D pixel coordinates $x$ to 3D space $X$ using predicted depth and camera parameters [S1].
6.  **Gaussian Construction:** Construct $\mathcal{G}$ using the predicted parameters. Each Gaussian is defined by $G(x) = \{M_p(x), M_c(x), M_r(x), M_s(x), M_\alpha(x), M_f(x)\}$ [S1].
7.  **Pose Regression (Optional/Parallel):**
    *   Generate point clouds $P_l, P_r$ from depth maps $D_l, D_r$ and camera parameters [S1].
    *   Extract human point clouds using 2D masks and combine them into a single point cloud $P_c$ [S1].
    *   Randomly sample 2048 points from $P_c$ [S1].
    *   Input $P_c$ to a pose regression network (based on DGCNN and PointNet) to estimate 3D pose (19 keypoints) [S1].
8.  **Rendering (Feature Splatting):**
    *   Project 3D Gaussians to 2D space. The 2D covariance matrix $\Sigma'$ is calculated as:
        $$ \Sigma' = J W \Sigma W^T J^T $$
        where $\Sigma$ is the 3D covariance matrix, $W$ is the view transformation matrix, and $J$ is the Jacobian of the affine approximation of the projective transform [S1].
    *   Render final pixel colors $C$ using alpha blending:
        $$ C = \sum_{i \in N} c_i \alpha'_i \prod_{j=1}^{i-1} (1 - \alpha'_j) $$
        where $c_i$ is the learned color, $\alpha'_i$ is the opacity $\alpha_i$ multiplied by the 2D Gaussian, and $N$ is the set of splatted Gaussians [S1].
    *   Render human feature vectors $f_p$ by splatting Gaussian features $f_i$ using the same alpha composition:
        $$ f_p = \sum_{i \in N} f_i \alpha'_i \prod_{j=1}^{i-1} (1 - \alpha'_j) $$
    *   Decode blended feature vectors $f_p$ using an MLP (two linear layers with ReLU, final sigmoid layer) to render continuous surface embeddings [S1].

**Training:**
The model is trained in two stages [S1]:
1.  **Stage 1:** Train the depth estimator module on both source views for 40,000 iterations [S1].
2.  **Stage 2:** Jointly train the Gaussian parameter estimator, feature estimator MLP, and 3D pose estimator for 100,000 iterations [S1].

**Loss Function:**
The combined loss is:
$$ \mathcal{L} = \mathcal{L}_{image} + \mathcal{L}_{depth} + \mathcal{L}_{pose} + \mathcal{L}_{feature} $$
*   $\mathcal{L}_{image} = \beta \mathcal{L}_{MAE} + \gamma \mathcal{L}_{SSIM}$, with $\beta=1.6, \gamma=0.4$ [S1].
*   $\mathcal{L}_{depth} = \sum_{t=1}^{T} \mu^{T-t} \|d_{gt} - d_t\|_1$, with $\mu=0.9$ [S1].
*   $\mathcal{L}_{pose}$: L2 loss between ground truth and estimated 3D keypoints [S1].
*   $\mathcal{L}_{feature}$: L1 loss between ground truth and predicted human features (continuous surface embeddings) [S1].

**Parameters:**
*   Learning rate: $2 \times 10^{-4}$ [S1].
*   Weight decay: $1 \times 10^{-5}$ [S1].
*   Batch size: 4 [S1].
*   Resolution: $512 \times 512$ [S1].
*   Number of keypoints: 19 (nose, neck, shoulders, elbows, wrists, pelvis, hips, knees, ankles, eyes, ears) [S1].

## Operating characteristics
*   **Speed:** Renders at 25 FPS [S1].
*   **Accuracy:** Achieves a PSNR of 32.43 on novel view synthesis, closely matching GPS-Gaussian's 32.55 [S1].
*   **Strengths:** Generalizes to unseen human data without fine-tuning; simultaneously estimates RGB, 3D pose, and dense pose; real-time performance [S1].
*   **Limitations:** Relies on the quality of the initial depth estimation; performance is constrained by the generalizable backbone (GPS-Gaussian) [S1].
*   **When to use:** Real-time 3D human avatar reconstruction, AR/VR, and applications requiring biomechanical features (pose, dense pose) from sparse views [S1].
*   **When not to use:** When high-fidelity non-human scenes are required, or when per-subject optimization is acceptable and higher quality is needed [S1].

## Background
HFGaussian was introduced by Arnab Dey, Cheng-You Lu, Andrew I. Comport, Jean Martinet, Srinath Sridhar, and Chin-Teng Lin in arXiv:2411.03086v1 on 5 Nov 2024 [S1]. It builds on GPS-Gaussian [S1] to address the limitation that existing 3D Gaussian Splatting methods for humans either rely on parametric body models (SMPL/STAR) or fail to incorporate biomechanical features [S1]. It is implemented using PyTorch and the AdamW optimizer [S1].
