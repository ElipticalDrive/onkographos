# BRDF-SMAE

Also called: Smooth Material Auto-Encoder

## Overview
BRDF-SMAE is a method for spatially varying BRDF decomposition that encodes a single BRDF per point in a neural volume, enabling the representation of complex material variations across a scene [S1, unofficial]. It distinguishes itself from sibling methods like [3D Gaussian Splatting with BRDF Embedding](1174-3d-gaussian-splatting-with-brdf-embedding.md) by explicitly enforcing a smooth latent space through an auto-encoder architecture, rather than storing raw or embedded parameters directly [S1, unofficial]. This approach solves the problem of noisy or inconsistent material estimation by ensuring that nearby points with similar appearances share similar latent representations [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A neural volume where each point stores a BRDF embedding; training data consisting of images and corresponding environment maps (for Light-SMAE variants) or material datasets (for BRDF-SMAE) [S1, unofficial].
*   **Output:** A spatially varying BRDF decomposition, where each point in the volume is associated with a decoded BRDF parameter set [S1, unofficial].

**Data Structures:**
*   **Neural Volume:** A 3D grid or implicit representation where each location $(x, y, z)$ stores a latent code or embedding vector [S1, unofficial].
*   **MLP Architectures:** Three distinct Multi-Layer Perceptrons (MLPs) are used: Encoder, Decoder, and Discriminator [S1, unofficial].
    *   **Encoder:** Maps input BRDF parameters or surface properties to a latent code $z$.
    *   **Decoder:** Maps latent code $z$ back to BRDF parameters.
    *   **Discriminator:** Evaluates the realism of the decoded BRDFs [S1, unofficial].
    *   **Layout:** Each MLP consists of 3 layers with 32 output features per layer [S1, unofficial].

**Steps:**
1.  **Encoding:** For each point in the neural volume, the current BRDF parameters (or input representation) are passed through the Encoder MLP to produce a latent code $z$ [S1, unofficial].
2.  **Decoding:** The latent code $z$ is passed through the Decoder MLP to reconstruct the BRDF parameters [S1, unofficial].
3.  **Discrimination:** The decoded BRDF parameters are evaluated by the Discriminator MLP to ensure they lie within the manifold of realistic materials [S1, unofficial].
4.  **Loss Calculation:** The total loss is computed as a weighted sum of reconstruction loss, discriminator loss, and potentially other regularization terms [S1, unofficial].
5.  **Optimization:** The network parameters are updated using the Adam optimizer [S1, unofficial].

**Formulas:**
*   **Reconstruction Loss:** Mean Absolute Error (MAE) on the BRDF parameters [S1, unofficial]:
    $$ L_{rec} = \| \text{BRDF}_{pred} - \text{BRDF}_{target} \|_1 $$
*   **Total Loss:**
    $$ L_{total} = \lambda_1 L_{rec} + \lambda_2 L_{disc} + \lambda_3 L_{other} $$
    Where $\lambda_1 = 0.01$, $\lambda_2 = 0.01$, and $\lambda_3 = 0.001$ [S1, unofficial].

**Parameters:**
*   **MLP Depth/Width:** 3 layers, 32 output features [S1, unofficial].
*   **Loss Weights:** $\lambda_1 = 0.01$, $\lambda_2 = 0.01$, $\lambda_3 = 0.001$ [S1, unofficial].
*   **Latent Interpolation:** 64 steps used for latent space interpolation [S1, unofficial].
*   **Training Steps:** 1.5 million steps [S1, unofficial].
*   **Batch Size:** 256 [S1, unofficial].
*   **Optimizer:** Adam, learning rate $1e-4$ [S1, unofficial].
*   **Hardware:** NVIDIA 1080 TI GPU [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Convergence Time:** Training takes approximately 3.5 hours to converge on the specified hardware [S1, unofficial].
*   **Light-SMAE Specifics:** When handling light (Light-SMAE), the dataset is augmented by rotating environment maps 10 times and blending two maps randomly; environment maps are downscaled to $128 \times 256$ [S1, unofficial]. Loss weights change to $\lambda_1 = 0.01$, $\lambda_2 = 0.0001$, $\lambda_3 = 0.05$ with 5 interpolation steps [S1, unofficial]. High dynamic range requires careful handling to ensure smooth training [S1, unofficial].

## Subtopics

### SVBRDF with Sparse Latent Space
This variant represents Spatially Varying BRDF (SVBRDF) using an encoder-decoder network with a sparse latent space to impose a prior that real-world objects consist of limited types of materials [S2]. It alleviates noisy roughness caused by lack of supervision by transforming the input surface point $x$ to a latent code $z$ using an encoder, then decoding $z$ to diffuse albedo and roughness [S2]. The sparsity constraint is enforced via Kullback-Leibler divergence: $\ell_{KL} = \sum_{j=1}^n KL(\rho || \hat{\rho}_j)$, where $\rho = 0.05$ and $\hat{\rho}_j$ is the average of the $j$-th channel of $z$ over the batch [S2]. A smooth loss $\ell_s = || D(z) - D(z + \xi) ||_1$ is applied, where $\xi$ is drawn from a normal distribution with zero mean and 0.01 variance [S2]. The decoder is a 2-layer network with 32-dimensional input and 128 hidden units, using the Simplified Disney BRDF model with fixed $F_0 = 0.02$ [S2].

## Operating characteristics
*   **Time Complexity:** Training requires 1.5 million steps, taking approximately 3.5 hours on an NVIDIA 1080 TI GPU [S1, unofficial].
*   **Memory Complexity:** Not given in the sources.
*   **Performance:** The method converges in roughly 3.5 hours with a batch size of 256 [S1, unofficial].
*   **Strengths:** Enables spatially varying BRDF decomposition with a smooth latent space [S1, unofficial].
*   **Limitations:** Requires significant training time and specific hardware (NVIDIA 1080 TI) for the reported results [S1, unofficial].
*   **When to use:** When spatially varying material decomposition is required and a smooth latent space is beneficial [S1, unofficial].
*   **When not to use:** When real-time inference is critical without pre-training, or when hardware constraints prevent long training runs [S1, unofficial].

## Background
BRDF-SMAE was introduced in the context of Neural Pre-Integrated Lighting for Reflectance Decomposition [S1, unofficial]. The method leverages a neural volume to store BRDF embeddings, allowing for spatially varying material decomposition [S1, unofficial]. The training is performed on the material dataset of Boss et al. [S1, unofficial]. The approach is part of a broader effort to improve inverse rendering by disentangling material properties from lighting and geometry [S1, unofficial].
