# On-the-Fly GS Progressive Training

Also called: On-the-Fly Gaussian Splatting

## Overview
On-the-Fly GS Progressive Training is a method for optimizing 3D Gaussian Splatting (3DGS) fields incrementally as new images become available, enabling near real-time reconstruction without retraining the entire scene from scratch [S1]. It distinguishes itself from static training methods by combining a hierarchical image weighting scheme with adaptive learning rates and load-balancing losses to prioritize new data while maintaining consistency with previously acquired views [S1].

## How it works

### Inputs and Outputs
**Inputs:**
*   A sequence of incoming images.
*   An initial sparse point cloud and camera poses estimated by On-the-Fly SfM [S1].
*   A pre-existing 3DGS field (initialized in Phase 1) [S1].

**Outputs:**
*   An updated 3DGS field containing Gaussians for the expanded scene [S1].
*   Refined camera poses and sparse point cloud [S1].

### Data Structures
*   **3DGS Field:** Standard 3DGS representation (positions, covariances, opacities, spherical harmonics coefficients) [S1].
*   **Sparse Point Cloud:** Set of 3D points from SfM [S1].
*   **Search Tree:** Spatial index (e.g., KD-tree) built on the existing sparse point cloud to query distances for new points [S1].
*   **Image Overlap Matrix ($M$):** $M_{i,j}$ stores the number of matched feature points between image $i$ and image $j$ [S1].
*   **Gaussian Count per Pixel ($G_p$):** For each pixel $p$ in an image, the number of Gaussians contributing to its splat [S1].

### Parameters
*   $N_0$: Number of initial images for Phase 1 initialization. Typical value: 30 [S1].
*   Initial training iterations for Phase 1. Typical value: 2,000 iterations [S1].
*   $T_I$: Total training iterations performed for each new fly-in image in Phase 2. Typical value: 200 [S1].
*   $N_m$: Number of top-weighted images selected as key training targets for local optimization. Typical value: 10 [S1].
*   $T_a$: Predefined parameter representing iterations required for satisfactory rendering quality. Typical value: 200 [S1].
*   $\eta^0$: Initial learning rate. Typical value: $1.6 \times 10^{-4}$ [S1].
*   $\eta^f$: Final learning rate. Typical value: $1.6 \times 10^{-6}$ [S1].
*   $\lambda_1$: Weight for L1-Loss. Typical value: 0.47 [S1].
*   $\lambda_{load}$: Weight for Load-Balancing-Loss. Typical value: 0.41 [S1].
*   $\lambda_{ssim}$: Weight for SSIM-Loss. Typical value: 0.12 [S1].

### Steps

#### Phase 1: Initial 3DGS Training
1.  On-the-Fly SfM estimates poses and generates a sparse point cloud for the first $N_0$ images [S1].
2.  Train an initial 3DGS field using the original 3DGS training method for 2,000 iterations to prevent overfitting to the small initial set [S1].

#### Phase 2: Progressive 3DGS Training (per new image $n$)
1.  **Pose and Cloud Update:** On-the-Fly SfM estimates the pose of the new image $n$ and optimizes the poses of neighboring connected images via local Bundle Adjustment (BA), updating the sparse point cloud [S1].
2.  **New Gaussian Initialization:**
    *   Construct a search tree for the existing sparse point cloud [S1].
    *   Query points from the new image against the tree.
    *   Points with a shortest distance to existing points exceeding a predefined threshold are classified as newly added [S1].
    *   Initialize these points as new Gaussians and append them to the 3DGS field [S1].
3.  **Hierarchical Image Weighting:** Calculate weights for existing images to determine training priority [S1].
    *   Set weight of new image $\omega_{11} = 1$ [S1].
    *   For images $I_{2i}$ with direct overlap ($M_{i,n} \neq 0$):
        $$ \omega_{2i} = M_{i,n} $$
        where $M_{i,n}$ is the number of matched feature points between image $i$ and new image $n$ [S1].
    *   For images in layer $k$ ($k \ge 3$) with indirect overlap:
        $$ \omega_{ki} = \frac{\sum_{j=1}^{N_{k-1}} \omega_{j}^{(k-1)} \times M_{j,ki}^{(k-1)}}{N_{k-1}} $$
        where $\omega_{j}^{(k-1)}$ is the weight of image $j$ in layer $k-1$, $M_{j,ki}^{(k-1)}$ is the match count between image $j$ and image $i$, and $N_{k-1}$ is the number of images in layer $k-1$ [S1].
4.  **Training Iteration Allocation:** Perform $T_I$ iterations (200) distributed as follows [S1]:
    *   **Local Optimization:** Select top $N_m$ images (10) with highest weights. For key image $i$ with weight $\omega_i$, training iterations $T_{im}$ are:
        $$ T_{im} = \frac{1 - e^{-\omega_i}}{\sum_{j=1}^{N_m} (1 - e^{-\omega_j})} \times T_I $$
    *   **Semi-Global Optimization:** Distribute the remaining $T_I/2$ iterations evenly among other images [S1].
5.  **Adaptive Learning Rate Update:** For each image $j$ trained for $T_j$ iterations, calculate the base learning rate $\eta_j^c$ [S1]:
    *   Progress $t_i = \min(1, T_j / T_a)$ [S1].
    *   $\eta_j^c = (\eta_j^0)^{1-t_i} \times (\eta_j^f)^{t_i}$ [S1].
    *   Adjust for overlapping images $I$ (where $M_{i,j} > 0$):
        $$ \eta_j = \frac{\eta_j^c + \sum_{i \in I} M_{i,j} \times \eta_i^c}{N_I + 1} $$
        where $N_I$ is the count of overlapping images [S1].
6.  **Loss Calculation and Optimization:**
    *   Calculate Load-Balancing-Loss $L_{load} = \text{std}(G_p)$ for $p \in i$, where $G_p$ is the number of Gaussians associated with pixel $p$ [S1].
    *   Total Loss:
        $$ L_{total} = \lambda_1 L_1 + \lambda_{ssim} L_{ssim} + \lambda_{load} L_{load} $$
    *   Perform gradient updates using Splatting-based parallelism (gradient accumulation per Gaussian) [S1].

#### Phase 3: Final Optimization
1.  After all images are acquired, perform global Bundle Adjustment (BA) on estimated poses [S1].
2.  Apply rapid additional optimization to the current 3DGS field [S1].

### Edge Cases and Pitfalls
*   **Overfitting in Phase 1:** Training too long on the initial $N_0$ images can cause overfitting. A strict iteration limit (2,000) is required [S1].
*   **Threshold Selection:** The distance threshold for classifying new points must be small enough to detect new geometry but large enough to handle noise. Not given in the sources [S1].
*   **Learning Rate Dependency:** The adaptive learning rate for image $j$ depends on the learning rates of overlapping images $i$. This requires careful synchronization or iterative calculation to resolve dependencies [S1].
*   **Load Balancing:** Without $L_{load}$, Gaussians may accumulate abnormally in specific regions, increasing total count and slowing training [S1].

## Operating characteristics

### Time and Memory Complexity
*   **Time:** The method aims for "near real-time" optimization [S1]. Each new image triggers $T_I=200$ iterations. The average iterations per image approach 200 as the scene grows [S1]. Splatting-based parallelism accelerates training by eliminating thread contention in gradient accumulation [S1].
*   **Memory:** Memory usage scales with the number of Gaussians. The load-balancing loss helps reduce the total number of Gaussians by preventing abnormal accumulation [S1].

### Measured Performance
*   Evaluated on RGB datasets from 3DGS, Mip-NeRF 360, On-the-Fly SfM, and Replica [S1].
*   Compared against Adr-Gaussian, Taming-3DGS, GS-SLAM, and RTG-SLAM [S1].
*   Hardware: RTX 4090 GPU [S1].

### Strengths and Limitations
*   **Strengths:** Enables incremental updates without full retraining; hierarchical weighting prioritizes new data; load-balancing reduces Gaussian count; adaptive learning rates improve local quality [S1].
*   **Limitations:** Requires On-the-Fly SfM for pose estimation and sparse cloud generation; performance depends on the quality of feature matching ($M_{i,j}$) [S1].

## Background

### Origin
On-the-Fly GS Progressive Training was proposed in the paper "Gaussian On-the-Fly Splatting: A Progressive Framework for Robust Near Real-Time 3DGS Optimization" [S1].

### History and Development
The method builds upon 3D Gaussian Splatting [S1] and On-the-Fly SfM [S1]. It integrates strategies from Taming-3DGS [S1] for parallel gradient accumulation. It is designed for scenarios where images are acquired sequentially, such as in SLAM or UAV mapping [S1].
