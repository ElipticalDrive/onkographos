# Gradient-Weighted Feature Back-Projection

Also called: Back-Projection Equation, Expected Feature Back-Projection, FBP, Feature Back-Projection

## Overview
Gradient-Weighted Feature Back-Projection is a training-free method for feature field rendering in 3D Gaussian Splatting that back-projects 2D features into pre-trained 3D Gaussians using a weighted sum based on each Gaussian's influence (opacity and transmittance) in the final rendering [S1]. It aggregates 2D feature embeddings from training views into 3D Gaussian features by weighting the contribution of each Gaussian based on its influence on the rendered pixel, avoiding the need for distillation or feature field training [S1]. Compared to training-based alternatives like Feature 3DGS, which require iterative optimization of feature parameters, this method computes features in a single pass using the rendering gradients as weights, achieving a 10x speedup while maintaining high-quality 3D segmentation results [S1].

## How it works
The method leverages the differentiable nature of the alpha-compositing equation to determine the influence of each Gaussian on the final rendered image [S1]. It back-projects 2D features (e.g., from LSeg or DINOv2) into 3D space by weighting the contribution of each Gaussian based on its opacity and transmittance [S1].

### Inputs and Outputs
*   **Inputs:**
    *   A set of $N$ 3D Gaussians with fixed parameters (position, scale, rotation, opacity, color) obtained from a standard 3DGS reconstruction [S1].
    *   A set of $V$ training views, each with a corresponding 2D feature map $\mathbf{F}_{2D}$ generated by a pre-trained model (e.g., LSeg or DINOv2) [S1].
    *   The camera parameters for each training view [S1].
*   **Outputs:**
    *   A feature vector $\mathbf{f}_k \in \mathbb{R}^D$ for each Gaussian $k$, where $D$ is the feature dimension [S1].

### Data Structures
*   **Gaussian Attributes:** Each Gaussian $k$ stores its 3D feature vector $\mathbf{f}_k$ [S1]. Initially, this is zero [G].
*   **2D Feature Map:** For each view $n$, a 2D array $\mathbf{F}_{2D}(x, y, n)$ of shape $H \times W \times D$, where $H, W$ are image dimensions [S1].

### Algorithm Steps

1.  **Render and Compute Gradients:**
    For each training view $n$:
    *   Render the scene using the current Gaussian parameters to obtain the rendered color $\mathbf{C}_n(x, y)$ and depth/alpha information [S1].
    *   The rendering follows the standard alpha-compositing equation:
        $$
        \mathbf{C}_n(x, y) = \sum_{k=1}^{N} \mathbf{c}_k \alpha_k(x, y, n) T_k(x, y, n)
        $$
        where $\mathbf{c}_k$ is the color of the $k$-th Gaussian, $\alpha_k(x, y, n)$ is its opacity at pixel $(x, y)$ in view $n$, and $T_k(x, y, n)$ is the transmittance up to the $k$-th Gaussian:
        $$
        T_k(x, y, n) = \prod_{j=1}^{k-1} (1 - \alpha_j(x, y, n))
        $$
    *   Compute the gradient of the rendered color with respect to the $k$-th Gaussian's color $\mathbf{c}_k$ [S1]. This gradient serves as the weight for back-projection:
        $$
        \frac{\partial \mathbf{C}_n(x, y)}{\partial \mathbf{c}_k} = \alpha_k(x, y, n) T_k(x, y, n)
        $$
        Let $w_k(x, y, n) = \alpha_k(x, y, n) T_k(x, y, n)$ [S1].

2.  **Accumulate Features:**
    For each Gaussian $k$, accumulate the weighted 2D features from all views $n$ where the Gaussian contributes to the pixel [S1].
    *   **Expected Feature Back-Projection (Normalized):**
        $$
        \mathbf{f}_k = \frac{\sum_{n} \sum_{(x,y) \in \text{pixels}} \mathbf{F}_{2D}(x, y, n) w_k(x, y, n)}{\sum_{n} \sum_{(x,y) \in \text{pixels}} w_k(x, y, n)}
        $$
    *   **Accumulated Feature Back-Projection (Unnormalized):**
        $$
        \mathbf{f}_k = \sum_{n} \sum_{(x,y) \in \text{pixels}} \mathbf{F}_{2D}(x, y, n) w_k(x, y, n)
        $$
        Note: If Euclidean normalization is applied to $\mathbf{f}_k$ after calculation, the normalized and unnormalized variants become equivalent [S1].

3.  **Pruning:**
    *   Calculate the numerator of the back-projection equation for each Gaussian [S1].
    *   If the numerator is zero (indicating no influence on any screen pixel), prune the Gaussian or mark it as invalid to avoid division by zero or irrelevant data during inference [S1].

4.  **Completion:**
    *   The back-projection is completed in a single pass through all training views [S1]. No iterative optimization is required [S1].

    """
    gaussians: List of Gaussian objects with attributes:
               - position (3,)
               - scale (3,)
               - rotation (4,)
               - opacity (scalar)
               - color (3,)
               - feature (D,) # To be filled
    views: List of view dictionaries with attributes:
           - camera_params
           - gt_features (H, W, D) # Pre-computed by feature_model
    D: Integer, feature dimension.
    """
    # Initialize accumulators
    for g in gaussians:
        g.feature_sum = [0.0] * D
        g.weight_sum = 0.0

    # Step 1 & 2: Render and Accumulate
    for view in views:
        # Forward pass computes alpha_k(x,y) and T_k(x,y) for each Gaussian at each pixel.
        # In practice, this is done via a tile-and-bin rasterization pipeline.
        # weights[k][y][x] = alpha_k(x,y) * T_k(x,y)
        weights = compute_rendering_weights(gaussians, view.camera_params, view.resolution)

        for k, g in enumerate(gaussians):
            w = weights[k]
            F_2D = view.gt_features
            H, W, _ = F_2D.shape

            for y in range(H):
                for x in range(W):
                    alpha_T = w[y][x]
                    if alpha_T > 0:
                        for d in range(D):
                            g.feature_sum[d] += alpha_T * F_2D[y][x][d]
                        g.weight_sum += alpha_T

    # Step 3: Normalize and Prune
    for g in gaussians:
        if g.weight_sum > 0:
            for d in range(D):
                g.feature[d] = g.feature_sum[d] / g.weight_sum
        else:
            g.feature = None
            g.is_pruned = True

    return gaussians

*   **Zero Influence:** If a Gaussian has no influence on any pixel (numerator is zero), it should be pruned before inference to prevent division by zero or irrelevant data [S1].
*   **Normalization:** The normalized (expected) and unnormalized (accumulated) variants are equivalent if Euclidean normalization is applied to the result [S1].

## Subtopics

### 3D Segmentation via Back-Projection
This variant uses the back-projected features for semantic segmentation [S1]. It obtains feature vectors $\{\mathbf{f}_k\} \in \mathbb{R}^D$ for each Gaussian [S1]. A query embedding $\mathbf{q} \in \mathbb{R}^D$ is extracted from a language query or another modality [S1]. Segmentation is performed by computing the similarity $sim(\mathbf{f}_k, \mathbf{q})$ (typically cosine similarity) and thresholding: $G = \{g_k \mid \text{sim}(\mathbf{f}_k, \mathbf{q}) > \theta\}$, where $\theta$ is a user-defined threshold [S1]. 2D segmentation masks are derived similarly by querying rendered 2D features [S1].

### Identity Encoding
This variant encodes each object with a unique vector and back-projects these vectors into the 3D scene [S1]. Two approaches are used:
1.  **Orthogonal Encoding:** Procedurally generated orthogonal vectors are assigned to objects to maximize separation [S1]. This is limited by the embedding dimension $D$ [S1].
2.  **Contrastive Encoding:** Non-orthogonal vectors are made distinct through contrastive learning, which maximizes distance between different objects [S1]. The loss function is $\mathcal{L} = \mathcal{L}_{\text{classification}} + \mathcal{L}_{\text{orthogonality}}$, where $\mathcal{L}_{\text{classification}} = \text{CrossEntropy}(\hat{y}, y)$ and $\mathcal{L}_{\text{orthogonality}} = \|\mathbf{E}\mathbf{E}^T - \mathbf{I}\|_F$ [S1].

### Affordance Transfer
This variant transfers annotated regions from source images to a target object [S1]. DINOv2 features are transferred to the target scene via back-projection [S1]. The closest matching source annotation for each Gaussian is identified by performing k-nearest neighbors (kNN) classification on the feature space [S1].

## Operating characteristics
*   **Time Complexity:** The method requires a single pass through all training views [S1]. The feature back-projection process, including ground truth feature map generation, takes an average of 2–3 minutes [S1].
*   **Inference Speed:** Object segmentation (including text encoding and similarity calculation) takes 30 ms [S1]. Similarity calculation alone takes less than 1 ms [S1].
*   **Speedup:** The method achieves a 900x speedup compared to segmentation using masked gradients [S1]. It is 10x faster than Feature 3DGS (2.5 mins vs 20–30 mins for 7000 iterations) because it does not train a feature field [S1].
*   **Memory:** Not given in the sources.
*   **Strengths:** Training-free, fast, scalable, high-quality 3D segmentation [S1].
*   **Limitations:** Requires pre-trained 3D Gaussians and 2D feature maps from training views [S1]. Performance depends on the quality of the 2D feature model [S1].

## Background
The method was introduced by Bharadwaj Amrutur and Shalabh Bhatnagar from the Indian Institute of Science [S1]. It addresses the limitations of training-based feature field rendering methods, which often perform poorly at 3D segmentation without post-processing [S1]. The approach leverages the gradient of the rendering equation to weight feature contributions, providing a computationally efficient alternative to distillation or feature field training [S1].
