# Splatt3R

Also called: Splatt3R: Zero-Shot Gaussian Splatting from Uncalibrated Image Pairs

## Overview
Splatt3R is a feed-forward method that predicts 3D Gaussian Splat primitives directly from a pair of uncalibrated natural images, without requiring camera intrinsics, extrinsics, or depth information [S1, unofficial]. It extends the MASt3R foundation model by adding a Gaussian prediction head, enabling both interpolation and extrapolation of novel views in a single forward pass [S1, unofficial]. Unlike existing generalizable 3D-GS methods that are limited to interpolating viewpoints between input stereo views, Splatt3R supervises extrapolated viewpoints beyond the stereo baseline using a novel loss masking strategy to prevent destructive updates from unseen scene regions [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Two uncalibrated RGB images $I_1, I_2 \in \mathbb{R}^{H \times W \times 3}$ with resolution $512 \times 512$ [S1, unofficial].
*   **Outputs:** A set of 3D Gaussian primitives $\mathcal{G}$, defined by mean position $\mu$, covariance $\Sigma$, opacity $\alpha$, and color $c$ [S1, unofficial].

**Data Structures:**
The method predicts per-pixel Gaussian parameters. For each pixel $j$, the network outputs:
*   Base position $x_j \in \mathbb{R}^3$ (from MASt3R backbone).
*   Position offset $\Delta x_j \in \mathbb{R}^3$.
*   Rotation quaternion $q_j \in \mathbb{R}^4$.
*   Scale vector $s_j \in \mathbb{R}^3$.
*   Opacity $\alpha_j \in \mathbb{R}$.
*   Color $c_j \in \mathbb{R}^3$ (constant view-independent color) or Spherical Harmonics coefficients [S1, unofficial].

**Numbered Steps:**

1.  **Feature Encoding:** Encode the two input images $I_1, I_2$ using a shared Vision Transformer (ViT) encoder and cross-attention transformers. This backbone is based on MASt3R and is frozen during training [S1, unofficial].
2.  **Point Cloud Prediction:** Use the frozen MASt3R backbone to predict 3D point locations $\hat{X}_1, \hat{X}_2$ and confidence maps $C_1, C_2$ in the coordinate frame of the first image [S1, unofficial].
3.  **Gaussian Parameter Prediction:** Predict Gaussian parameters using a parallel 'Gaussian head' with DPT architecture [45]. This head outputs offsets $\Delta$, rotations $q$, scales $s$, opacities $\alpha$, and spherical harmonics $S$ for each pixel [S1, unofficial].
4.  **Mean Position Calculation:** Calculate the mean position $\mu_j$ of each Gaussian by summing the predicted 3D point $x_j$ and the offset $\Delta x_j$:
    $$ \mu_j = x_j + \Delta x_j $$
    [S1, unofficial][S2]
5.  **Covariance Construction:** Reparameterize the covariance matrix $\Sigma_j$ using the predicted rotation quaternion $q_j$ and scale $s_j$ to ensure positive semi-definiteness:
    $$ \Sigma_j = R(q_j) S(s_j) S(s_j)^T R(q_j)^T $$
    where $R(q_j)$ is the rotation matrix derived from $q_j$ and $S(s_j)$ is the diagonal scale matrix [S1, unofficial][S2].
6.  **Primitive Union:** Construct the final set of Gaussian primitives as the union of the primitives predicted from both input images $I_1$ and $I_2$ [S1, unofficial].
7.  **Rendering:** Render the predicted Gaussians into target views using differentiable rasterization [S1, unofficial].

**Parameters:**
*   **Activation Functions:** Normalization for quaternions, exponential for scales and offsets, and sigmoid for opacities [S1, unofficial].
*   **Color:** Constant, view-independent color $S \in \mathbb{R}^3$ is used in experiments, with ablation for view-dependent spherical harmonics [S1, unofficial].
*   **Overlap Thresholds:** Hyperparameters $\phi$ and $\psi$ control overlap thresholds during training. Typical values tested: Close $(0.9, 0.9)$, Medium $(0.7, 0.7)$, Wide $(0.5, 0.5)$, Very Wide $(0.3, 0.3)$ [S1, unofficial].

**Loss Masking Strategy:**
To handle extrapolated viewpoints where parts of the scene are obscured or outside the frustums of the context images, a loss mask $M$ is calculated [S1, unofficial]:
1.  Unproject target image points and reproject them onto context images.
2.  Check if the rendered depth matches the ground truth depth.
3.  Check if the pixel is inside the frustum of at least one context view.
4.  Apply Mean Squared Error (MSE) and LPIPS loss only to pixels where the mask $M$ is valid [S1, unofficial].

**Training Procedure:**
1.  **Stage 1:** Optimize the 3D point cloud’s geometry loss using the MASt3R backbone (pre-trained) [S1, unofficial].
2.  **Stage 2:** Optimize the novel view synthesis objective by training only the Gaussian prediction head [S1, unofficial].
3.  **Sample Selection:** Select context images such that at least $\phi\%$ of pixels in the second image have correspondences in the first, and target images such that at least $\psi\%$ of pixels are present in at least one context image [S1, unofficial].
4.  **Loss Function:** The total loss $L$ is a weighted sum of masked MSE and LPIPS losses:
    $$ L = \lambda_{MSE} L_{MSE}(M \odot \hat{I}, M \odot I) + \lambda_{LPIPS} L_{LPIPS}(M \odot \hat{I}, M \odot I) $$
    where $\hat{I}$ is the rendered image, $I$ is the ground truth image, and $\odot$ denotes element-wise multiplication [S1, unofficial][S2].

**Pitfalls:**
*   Supervising rendering loss for pixels not visible in context views (obscured or outside frustums) is counterproductive and can destroy model performance [S1, unofficial].
*   The method relies on ground truth depth and poses during training to calculate the loss mask, which are not available at inference [S1, unofficial].

import torch
import torch.nn as nn
import torch.nn.functional as F

class Splatt3R:
    def __init__(self, mastr3r_backbone, gaussian_head):
        """
        Initialize Splatt3R with a frozen MASt3R backbone and a trainable Gaussian head.
        """
        self.mastr3r = mastr3r_backbone
        self.mastr3r.eval()
        for param in self.mastr3r.parameters():
            param.requires_grad = False
        self.gaussian_head = gaussian_head

    def forward(self, I1, I2):
        """
        Predict 3D Gaussian parameters from two uncalibrated images.
        
        Args:
            I1: Tensor of shape (H, W, 3)
            I2: Tensor of shape (H, W, 3)
            
        Returns:
            Gaussians: List of Gaussian primitives (mu, sigma, alpha, color)
        """
        # Step 1 & 2: Encode and predict point cloud using frozen MASt3R
        # Predicts points in the coordinate frame of the first image
        X1, C1 = self.mastr3r(I1, I2) # X1: (H, W, 3), C1: (H, W)
        
        # Step 3: Predict Gaussian parameters using Gaussian Head
        # Outputs offsets, rotations, scales, opacities, and colors
        # Note: Gaussian head takes features from MASt3R or images directly
        # Assuming DPT architecture takes multi-scale features
        offsets = self.gaussian_head.predict_offsets(I1, I2) # (H, W, 3)
        rotations = self.gaussian_head.predict_rotations(I1, I2) # (H, W, 4)
        scales = self.gaussian_head.predict_scales(I1, I2) # (H, W, 3)
        opacities = self.gaussian_head.predict_opacities(I1, I2) # (H, W, 1)
        colors = self.gaussian_head.predict_colors(I1, I2) # (H, W, 3) or (H, W, 3*d)

        # Step 4: Calculate Mean Position
        mu = X1 + offsets # (H, W, 3)

        # Step 5: Construct Covariance Matrix
        # R(q) is rotation matrix from quaternion q
        # S(s) is diagonal scale matrix
        R = quaternion_to_rotation_matrix(rotations)
        S = torch.diag_embed(scales) # (H, W, 3, 3)
        Sigma = torch.bmm(torch.bmm(R, S), torch.transpose(S, 1, 2)) # (H, W, 3, 3)

        # Step 6: Construct Primitives
        # Union of primitives from both images (though X1 is in frame 1, 
        # we might also predict from I2 and transform, but Splatt3R uses union of 
        # primitives predicted from both images in their respective frames? 
        # Source says: "The final set of Gaussian primitives is the union of the 
        # Gaussian primitives predicted from both images." 
        # However, X1, X2 are in frame 1. 
        # Clarification: MASt3R predicts X1, X2 in frame 1. 
        # So we predict Gaussians for pixels in I1 and I2, both mapped to frame 1.
        
        # Predict for I2 as well, mapped to frame 1
        X2_in_frame1, C2 = self.mastr3r(I2, I1) # Note: MASt3R predicts in frame of first arg? 
        # Source: "predicts the 3D locations of all points in the first image’s camera frame"
        # So if we call mastr3r(I2, I1), it predicts in frame of I2.
        # We need to transform X2 to frame 1. 
        # But Splatt3R avoids explicit pose prediction. 
        # Source: "Following MAST3R’s practice of predicting the 3D locations of all points 
        # in the first image’s camera frame... The final set of Gaussian primitives is the union 
        # of the Gaussian primitives predicted from both images."
        # This implies we predict Gaussians for I1 (in frame 1) and I2 (in frame 1).
        # How to get I2 points in frame 1? MASt3R predicts X1, X2 in frame 1.
        # So we use X2 from mastr3r(I1, I2) which is already in frame 1.
        
        # Re-evaluating Step 2: "predict 3D point locations X̂1, X̂2 ... in the coordinate frame of the first image"
        # So X2 is already in frame 1.
        
        # Predict Gaussians for I2 pixels using the same head, but conditioned on I2's position X2
        offsets2 = self.gaussian_head.predict_offsets(I2, I1) # Or use features from I2 branch
        rotations2 = self.gaussian_head.predict_rotations(I2, I1)
        scales2 = self.gaussian_head.predict_scales(I2, I1)
        opacities2 = self.gaussian_head.predict_opacities(I2, I1)
        colors2 = self.gaussian_head.predict_colors(I2, I1)
        
        mu2 = X2 + offsets2
        R2 = quaternion_to_rotation_matrix(rotations2)
        S2 = torch.diag_embed(scales2)
        Sigma2 = torch.bmm(torch.bmm(R2, S2), torch.transpose(S2, 1, 2))
        
        # Union of primitives
        all_mu = torch.cat([mu, mu2], dim=0) # (2*H*W, 3)
        all_sigma = torch.cat([Sigma, Sigma2], dim=0) # (2*H*W, 3, 3)
        all_alpha = torch.cat([opacities, opacities2], dim=0) # (2*H*W, 1)
        all_color = torch.cat([colors, colors2], dim=0) # (2*H*W, 3)
        
        return all_mu, all_sigma, all_alpha, all_color

        Compute masked MSE and LPIPS loss.
        """
        masked_rendered = rendered_image * mask
        masked_gt = ground_truth_image * mask

        lpips_loss = lpips_loss_fn(masked_rendered, masked_gt)

def quaternion_to_rotation_matrix(q):
    """
    Convert quaternion (x, y, z, w) to rotation matrix.
    q: (H, W, 4)
    Returns: (H, W, 3, 3)
    """
    # Standard quaternion to rotation matrix conversion
    # q = [x, y, z, w]
    x, y, z, w = q[..., 0], q[..., 1], q[..., 2], q[..., 3]
    
    # Normalize quaternion
    norm = torch.sqrt(x**2 + y**2 + z**2 + w**2)
    x, y, z, w = x/norm, y/norm, z/norm, w/norm
    
    # Construct rotation matrix
    R = torch.zeros(q.shape[0], q.shape[1], 3, 3, device=q.device)
    R[..., 0, 0] = 1 - 2 * (y**2 + z**2)
    R[..., 0, 1] = 2 * (x*y - z*w)
    R[..., 0, 2] = 2 * (x*z + y*w)
    R[..., 1, 0] = 2 * (x*y + z*w)
    R[..., 1, 1] = 1 - 2 * (x**2 + z**2)
    R[..., 1, 2] = 2 * (y*z - x*w)
    R[..., 2, 0] = 2 * (x*z - y*w)
    R[..., 2, 1] = 2 * (y*z + x*w)
    R[..., 2, 2] = 1 - 2 * (x**2 + y**2)
    
    return R

## Operating characteristics
*   **Time Complexity:** Single forward pass of the network. Construction/export runtime is approximately 1.10 seconds on ScanNet++ with 2 views [S2].
*   **Memory Complexity:** Not given in the sources.
*   **Performance:** On ScanNet++ test scenes, Splatt3R achieves PSNR 19.66, SSIM 0.757, LPIPS 0.234 for Close view overlap ($\phi=0.9, \psi=0.9$) [S1, unofficial]. Another source reports PSNR 23.30, SSIM 0.823, LPIPS 0.125 on ScanNet++ with 2 views [S2].
*   **Strengths:** Pose-free, works with uncalibrated images, generalizes to in-the-wild images, supports extrapolation beyond stereo baseline.
*   **Limitations:** Requires training on a large dataset (ScanNet++), loss masking relies on ground truth depth/poses during training, constant color may limit view-dependent appearance [S1, unofficial].
*   **When to use:** When camera parameters are unknown and per-scene optimization is not feasible.
*   **When not to use:** When high-fidelity view-dependent appearance is required and training data is unavailable.

## Background
Splatt3R was introduced in 2024 by Brandon, Zheng, Iro, and Victor from the University of Oxford [S1, unofficial]. It builds upon the MASt3R foundation model for 3D geometry reconstruction [S1, unofficial]. The method addresses the limitation of existing generalizable 3D-GS methods that only supervise novel viewpoints between input stereo views, by introducing a loss masking strategy to enable extrapolation [S1, unofficial]. It is trained on the ScanNet++ dataset [S1, unofficial].
