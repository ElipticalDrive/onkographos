# Mesh-Embedded Gaussian Splatting

Also called: Gaussian Mesh Splatting, Gaussian-Mesh association

## Overview
Mesh-Embedded Gaussian Splatting is a hybrid 3D representation that anchors 3D Gaussians to a canonical triangle mesh $\mathcal{M}$ to disentangle motion from appearance [S2, unofficial]. It solves the problem of coherent, editable deformation in 3D Gaussian Splatting (3DGS) by parameterizing Gaussian positions via barycentric coordinates and normal displacement on mesh faces, allowing explicit motion control through mesh editing or skeletal animation [S1][S2, unofficial]. It sets itself apart from nearest alternatives like [GaMeS](12542-games-gaussian-mesh-splatting.md) by explicitly controlling Gaussian rotation and translation directly via the mesh geometry rather than relying on implicit MLP-based linear blend skinning (LBS) fields, ensuring compatibility with standard animation techniques [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A canonical triangle mesh $\mathcal{M}$ with vertices $V$, per-vertex normals $n$, and optionally per-vertex quaternions $q_V$; a set of 3D Gaussians initialized on the mesh.
*   **Output:** Posed 3D Gaussians (position $\mu_{pose}$, rotation $q_{pose}$, scale $s_{pose}$) and rendered images for a given pose.

**Data Structures:**
Each Gaussian $i$ is defined by:
1.  **Embedding Parameters ($E_i$):**
    *   $k$: Integer triangle index.
    *   $(u, v)$: Floats representing barycentric coordinates within triangle $k$ ($u \ge 0, v \ge 0, u+v \le 1$).
    *   $d$: Float representing normal displacement along the interpolated normal.
2.  **Invariant Parameters (Pose-invariant):**
    *   $\bar{q}$: Canonical rotation quaternion.
    *   $\bar{s}$: Canonical scale.
    *   $o$: Opacity.
    *   $c$: Color.

**Canonical Position and Normal:**
The canonical position $\mu_{cano}$ and normal $n_{cano}$ are computed via Phong interpolation [S2, unofficial]:
$$
\mu_{cano} = \mathcal{V}(k, u, v) = u V_1 + v V_2 + (1 - u - v) V_3
$$
$$
n_{cano} = \mathcal{N}(k, u, v) = u n_1 + v n_2 + (1 - u - v) n_3
$$
where $V_1, V_2, V_3$ are the vertices of triangle $k$, and $n_1, n_2, n_3$ are the per-vertex normals [S2, unofficial].

**Deformation:**
For a posed frame, the posed position $\mu_{pose}$ is obtained by applying mesh deformation to the canonical position and adding normal displacement [S2, unofficial]:
$$
\mu_{pose} = \text{Deform}(\mu_{cano} + d \cdot n_{cano})
$$
where $\text{Deform}(\cdot)$ applies skeletal or blend-shape animation to the mesh vertices [S2, unofficial].

**Rotation:**
The posed rotation $q_{pose}$ is interpolated from per-vertex quaternions using barycentric weights and combined with the canonical rotation [S2, unofficial]:
$$
q_{pose} = \delta q * \bar{q}
$$
where $\delta q = u q_1 + v q_2 + (1 - u - v) q_3$ is the interpolated rotation from the mesh vertices, and $*$ denotes quaternion multiplication [S2, unofficial]. The per-vertex quaternions $q_V$ are calculated by area-weighted average from surrounding neighbor triangles [S1][S2, unofficial].

**Scale:**
The posed scale $s_{pose}$ is derived from the area change of the embedded triangle relative to the canonical state [S2, unofficial]:
$$
s_{pose} = \left( \frac{A_{pose}}{A_{cano}} \right) \bar{s}
$$
where $A_{pose}$ and $A_{cano}$ are the areas of the triangle in the posed and canonical states, respectively [S2, unofficial].

**Optimization Steps:**
1.  **Initialization:** Initialize Gaussians on the canonical mesh with embedding parameters $(k, u, v, d)$ and invariant parameters $(\bar{q}, \bar{s}, o, c)$ [S2, unofficial].
2.  **Lifted Optimization:** Conduct joint optimization of Gaussian parameters and embedding parameters [S2, unofficial].
3.  **Cross-Triangle Handling:** If an optimization step moves the embedding point across a triangle boundary (i.e., $u < 0$, $v < 0$, or $u+v > 1$), re-express the barycentric update in the neighboring triangle to maintain differentiability [S2, unofficial]. This is described as "walking" on the triangle mesh [S2, unofficial].
4.  **Adaptation:** Adapt the clone and split scheme of 3D Gaussians to suit the mesh-embedded representation [S2, unofficial].

**Pseudocode:**
```python
def compute_posed_gaussian(gaussian, mesh, pose_transform):
    """
    Computes the posed position, rotation, and scale for a single Gaussian.
    
    Args:
        gaussian: Object with attributes k, u, v, d, q_bar, s_bar.
        mesh: Object with attributes vertices (V), normals (n), quaternions (q_V), 
              and method get_triangle_area(tri_idx, state).
        pose_transform: Function that applies skeletal/blend-shape animation to mesh vertices.
        
    Returns:
        mu_pose: Posed position vector.
        q_pose: Posed rotation quaternion.
        s_pose: Posed scale.
    """
    # 1. Retrieve canonical triangle vertices and normals
    tri_idx = gaussian.k
    V1, V2, V3 = mesh.vertices[tri_idx]
    n1, n2, n3 = mesh.normals[tri_idx]
    
    # 2. Compute canonical position and normal (Phong interpolation)
    u, v = gaussian.u, gaussian.v
    mu_cano = u * V1 + v * V2 + (1 - u - v) * V3
    n_cano = u * n1 + v * n2 + (1 - u - v) * n3
    
    # 3. Apply normal displacement
    d = gaussian.d
    displaced_pos = mu_cano + d * n_cano
    
    # 4. Apply mesh deformation (skeletal/blend-shape)
    # Note: Deform applies the pose transform to the mesh vertices.
    # The displaced position is in canonical space, so we must deform it.
    # Assuming Deform applies the same rigid/non-rigid transform to points as to vertices.
    mu_pose = pose_transform(displaced_pos)
    
    # 5. Compute posed rotation
    # Interpolate per-vertex quaternions
    q1, q2, q3 = mesh.quaternions[tri_idx]
    delta_q = u * q1 + v * q2 + (1 - u - v) * q3
    # Normalize delta_q to ensure valid quaternion
    delta_q = delta_q / norm(delta_q)
    q_pose = delta_q * gaussian.q_bar
    
    # 6. Compute posed scale
    # Calculate area of triangle in canonical and posed states
    # Note: A_cano is computed from canonical vertices.
    # A_pose is computed from deformed vertices.
    A_cano = mesh.get_triangle_area(tri_idx, state='canonical')
    A_pose = mesh.get_triangle_area(tri_idx, state='posed')
    
    s_pose = (A_pose / A_cano) * gaussian.s_bar
    
    return mu_pose, q_pose, s_pose

def handle_cross_triangle_update(gaussian, mesh, gradient_u, gradient_v):
    """
    Handles the case where gradient descent moves the embedding point 
    outside the current triangle boundary.
    
    Args:
        gaussian: Current Gaussian embedding (k, u, v, d).
        mesh: Mesh structure to find neighboring triangles.
        gradient_u, gradient_v: Gradients for u and v.
        
    Returns:
        new_gaussian: Updated Gaussian with new triangle index and barycentric coords.
    """
    u, v = gaussian.u, gaussian.v
    
    # Check if point is outside the triangle
    if u < 0 or v < 0 or (u + v) > 1:
        # Find the neighboring triangle that the point has crossed into
        # This requires a mesh traversal or lookup structure
        new_tri_idx = mesh.find_neighbor_triangle(gaussian.k, u, v)
        
        # Re-express the barycentric coordinates in the new triangle
        # This involves mapping the physical position back to the new triangle's local coords
        # The exact mapping depends on the mesh topology and vertex ordering
        new_u, new_v = mesh.remap_barycentric_coords(gaussian.k, new_tri_idx, u, v)
        
        # Update the Gaussian's embedding parameters
        gaussian.k = new_tri_idx
        gaussian.u = new_u
        gaussian.v = new_v
        
        # Note: The gradient update should continue in the new triangle's coordinate system
        # The displacement d remains unchanged as it is along the normal of the new triangle
        # (or interpolated normal, depending on implementation)
        
    return gaussian
```

**Edge Cases and Pitfalls:**
*   **Cross-Triangle Updates:** Barycentric coordinates are only differentiable within a single triangle. If an optimization step moves the embedding point across a triangle boundary, the embedding must be re-expressed in the neighboring triangle to maintain differentiability [S2, unofficial]. Failure to handle this causes Gaussians to stick to boundaries and pile up [S2, unofficial].
*   **Per-Vertex Quaternion Calculation:** Per-vertex quaternions $q_V$ are calculated by area-weighted average from surrounding neighbor triangles [S1][S2, unofficial]. This requires access to the mesh's dual graph or neighbor list.

## Subtopics

### [GaussianMesh](11812-gaussianmesh.md)
Defines 3D Gaussians over an explicit triangle mesh for large-scale, interactive deformations driven by mesh editing. It sets itself apart by utilizing a reconstructed explicit mesh from calibrated images for initialization and employing specific face-split and normal-guidance strategies to handle large deformations without relying on implicit MLP-based skinning.

### [GaMeS (Gaussian Mesh Splatting)](12542-games-gaussian-mesh-splatting.md)
Introduces a hybrid representation where each Gaussian is parameterized by the vertices of a mesh face, inducing coherent changes in Gaussian position, scale, and orientation via classical mesh operations.

## Operating characteristics
*   **Time Complexity:** Real-time rendering is achieved, with reported performance of over 300 FPS on NVIDIA RTX 3090 GPU and 30 FPS on iPhone 13 [S2, unofficial].
*   **Memory Complexity:** Not given in the sources.
*   **Scaling:** The method scales to real-time rendering on mobile devices [S2, unofficial].
*   **Strengths:** Explicit motion control by the mesh, compatibility with skeletal animation, blend shapes, and mesh editing, high-fidelity rendering of high-frequency details [S2, unofficial].
*   **Limitations:** Relies on accurate semantic labels or mesh proxies for initialization [S1]. Cross-triangle updates require careful handling to maintain differentiability [S2, unofficial].
*   **When to use:** When explicit mesh-based deformation and editability are required, and real-time rendering is a priority [S2, unofficial].
*   **When not:** When the input does not include a suitable mesh or when implicit deformation fields are preferred [S1].

*   **Origin:** SplattingAvatar was introduced by Zhijing Shao et al. in 2024 [S2, unofficial].

*   **Usage:** Ported to Unity for real-time rendering [S2, unofficial].
