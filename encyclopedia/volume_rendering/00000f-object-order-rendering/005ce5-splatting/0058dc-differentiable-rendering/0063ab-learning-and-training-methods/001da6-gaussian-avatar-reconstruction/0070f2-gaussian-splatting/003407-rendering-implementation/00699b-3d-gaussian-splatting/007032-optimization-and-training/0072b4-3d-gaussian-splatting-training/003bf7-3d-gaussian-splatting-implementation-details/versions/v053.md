# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, GSGEN Implementation Details, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific hyperparameters, optimization schedules, and engineering implementations required to train and render 3D Gaussian Splatting (3DGS) scenes effectively. It addresses the problem of translating the theoretical differentiable rendering pipeline into a stable, high-performance software system by defining exact densification thresholds, loss weighting, and memory management strategies. It sets itself apart from general optimization discussions by providing concrete numerical values and algorithmic steps for the training loop, such as the specific iteration counts for splitting and pruning, and the handling of half-precision arithmetic in CUDA kernels.

## How it works
The implementation relies on a differentiable rasterizer that renders images from a set of 3D Gaussians. The core optimization mechanism involves computing the gradient of a loss function $\mathcal{L}$ with respect to the Gaussian parameters (position, covariance, opacity, color, SH coefficients) and any auxiliary parameters.

### Inputs and Outputs
*   **Inputs:** A set of $N$ training images with known camera poses (from SfM), an initial point cloud (from SfM), and hyperparameters for the training schedule.
*   **Outputs:** A set of optimized 3D Gaussians $\mathcal{G}$, where each Gaussian $i$ is defined by position $\mu_i$, covariance $\Sigma_i$ (or scale $s_i$ and rotation $q_i$), opacity $\alpha_i$, spherical harmonic coefficients $\mathbf{c}_i$, and SH degree.

### Data Structures
The Gaussian population is stored in a flat array or structure-of-arrays (SoA) layout for efficient GPU access.
*   **Position:** `float3` (x, y, z).
*   **Rotation:** `float4` (quaternion, w, x, y, z).
*   **Scale:** `float3` (log-scale or linear scale).
*   **Opacity:** `float` (sigmoid output).
*   **Color:** `float` array of size $K \times 3$ or $K \times 4$ depending on SH degree $K$.
*   **Attributes:** Additional fields for gradients, age, and visibility flags.

### Training Loop and Optimization Schedule
The training process is iterative, typically running for a fixed budget of iterations, commonly around 30,000 [S9, unofficial]. The loop proceeds as follows:

1.  **Random View Selection:** Randomly select a single training image and its corresponding camera pose from the dataset [S3][S9, unofficial].
2.  **Forward Rendering:** Render the current set of Gaussians from the selected camera pose using the differentiable rasterizer.
3.  **Loss Computation:** Compute the per-image error by comparing the rendered image against the ground-truth photo. The total loss $\mathcal{L}$ is a weighted blend of L1 loss and D-SSIM:
    $$ \mathcal{L} = (1 - \lambda) \mathcal{L}_1 + \lambda \mathcal{L}_{\text{SSIM}} $$
    where $\lambda \approx 0.2$ [S9, unofficial].
4.  **Backpropagation:** Compute gradients of $\mathcal{L}$ with respect to all Gaussian parameters.
5.  **Parameter Update:** Update Gaussian parameters using the Adam optimizer with a learning rate of $1 \times 10^{-3}$ [S3].
6.  **Densification and Pruning:** Periodically modify the Gaussian set based on gradient statistics and opacity thresholds.

### Densification and Pruning Steps
Densification is performed to increase Gaussian density in under-reconstructed regions, while pruning removes redundant Gaussians.

1.  **Splitting:** Every 500 iterations, split Gaussians that have a large view-space position gradient.
    *   **Condition:** If the accumulated view-space position gradient magnitude $g_i > T_{\text{pos}}$, split the Gaussian.
    *   **Threshold:** $T_{\text{pos}} = 0.02$ [S1, S4].
    *   **Method:** Clone the Gaussian and scale down the clone's scale by a factor (typically 1.6) [S4].
2.  **Cloning:** Clone Gaussians with high opacity but low gradient to increase density without introducing noise.
3.  **Pruning:** Every 200 iterations, remove Gaussians with low opacity or excessive size.
    *   **Condition:** If $\alpha_i < \alpha_{\text{min}}$ or the world-space/view-space radius exceeds a limit.
    *   **Threshold:** $\alpha_{\text{min}} = 0.05$ [S1].
4.  **Compactness Densification:** Every 1000 iterations, perform compactness-based densification to ensure uniform distribution [S1].

### Scene Extent Calculation
The default 3DGS implementation calculates scene extent $e_{\text{scene}}$ based on camera positions, which can be biased if cameras are clustered [S4]. A corrected scene extent $e'_{\text{scene}}$ is calculated based on the SfM point cloud:

$$ \bar{C} = \frac{1}{N_{\text{cam}}} \sum_{i=1}^{N_{\text{cam}}} C_i $$

$$ e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2 $$

where $N_{\text{cam}}$ is the number of camera views, $C_i$ is the position of the $i$-th camera, $N_{\text{SfM}}$ is the number of SfM points, and $p_i$ is the $i$-th SfM point [S4].

### Half-Precision Rasterization
To reduce register pressure and memory bandwidth, the rasterization kernels use half-precision (FP16) memory fetches for feature vectors during both forward and backward passes [S2]. An automatic scaling factor is applied to loss values to improve half-precision training stability [S2].

### Pseudocode

```python
def train_3dgs(training_images, camera_poses, initial_points, num_iterations=30000):
    # Initialize Gaussians from SfM points
    gaussians = initialize_gaussians(initial_points)
    
    # Optimizer setup
    optimizer = Adam(gaussians.parameters(), lr=1e-3)
    
    for iteration in range(1, num_iterations + 1):
        # 1. Random View Selection
        idx = random.choice(range(len(training_images)))
        image = training_images[idx]
        camera_pose = camera_poses[idx]
        
        # 2. Forward Rendering
        rendered_image = rasterize(gaussians, camera_pose)
        
        # 3. Loss Computation
        # L = 0.8 * L1 + 0.2 * SSIM
        loss = 0.8 * l1_loss(rendered_image, image) + 0.2 * ssim_loss(rendered_image, image)
        
        # 4. Backpropagation
        optimizer.zero_grad()
        loss.backward()
        
        # 5. Parameter Update
        optimizer.step()
        
        # 6. Densification and Pruning
        if iteration % 500 == 0:
            split_gaussians(gaussians, threshold=0.02)
        
        if iteration % 200 == 0:
            prune_gaussians(gaussians, alpha_min=0.05)
            
        if iteration % 1000 == 0:
            compactness_densification(gaussians)
            
    return gaussians

def split_gaussians(gaussians, threshold):
    for g in gaussians:
        if g.position_gradient > threshold:
            clone = g.clone()
            clone.scale /= 1.6
            gaussians.append(clone)
            remove(g)

def prune_gaussians(gaussians, alpha_min):
    to_remove = []
    for g in gaussians:
        if g.opacity < alpha_min:
            to_remove.append(g)
    for g in to_remove:
        remove(g)
```

### Corrected Scene-Extent
A method to calculate scene extent based on the SfM point cloud rather than camera positions to avoid bias from camera distribution (e.g., orbiting a small object in a large environment) [S4]. The corrected scene extent $e'_{\text{scene}}$ is computed as the average distance from the average camera position to all SfM points [S4]. This prevents incorrect splitting/pruning caused by the default method's dependence on camera distribution [S4].

### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ to selectively enlarge covariances, creating pixel-wise variable blur kernels that match spatially varying scene blurriness [S5]. A compact MLP predicts $\delta s_j$ for each Gaussian, which is added to the base scale to transform the covariance [S5]. This allows for spatially varying blur shapes and magnitudes, unlike naive Gaussian blur which applies a single kernel to the whole image [S5].

### Denoise-GS
A self-supervised denoising method for sparse-view 3D Gaussian Splatting that combines unsupervised image denoising with explicitly differentiable 3DGS [S6]. It uses Noise2Void (N2V) to train a UNet for denoising, processes denoised images through InstantSplat for initialization, and fine-tunes the UNet in a second round using a composite loss [S6]. Unlike supervised methods, it requires no paired clean data and is robust to non-Gaussian noise [S6].

### Multi-Scale Constraint
A technique using position-aware point adaptive control to apply different scales to Gaussians based on viewer distance, improving rendering of distant objects [S7]. It uses a scaling factor $\gamma(\mu)$ based on the distance of the Gaussian center $\mu$ from the camera center $c$ and scene radius $r$ [S7]. Cloning and splitting operations are triggered based on thresholds $g$ and $b$ scaled by $\gamma(\mu)$ [S7].

### LS-Gaussian Viewpoint Transformation
An algorithm that leverages inter-frame continuity for efficient sparse rendering by transforming the viewpoint between consecutive frames, rather than rendering each frame separately [S8]. It operates at the tile/Gaussian level to enable sparse rendering, reducing preprocessing and sorting costs [S8]. Rendering quality degrades as the number of consecutively transformed frames increases due to interpolation error accumulation [S8].

### 3D Gaussian Splatting Training Loop
Per-image error compares one render against one photo, while scene-wide error is the loss averaged across all training views [S9, unofficial]. The loop picks one input photo, renders the current Gaussians, computes error, and updates parameters [S9, unofficial]. Training typically runs for a fixed number of iterations (e.g., 30,000) rather than stopping at a specific loss threshold [S9, unofficial]. The loss is a blend of L1 and D-SSIM with $\lambda \approx 0.2$ [S9, unofficial].

### Camera Localisation for Convergence Basin
Localizes camera pose by minimizing photometric error against the ground-truth colour image of the target view, fixing the initial Gaussians $G_{init}$ during optimization [S10, unofficial]. The estimated pose $T_{CW}^{est}$ is found by minimizing the L1 norm between the rendered image and the target image [S10, unofficial]. Localisation is successful if the estimated pose converges to within 1cm of the target view within 1000 iterations [S10, unofficial].

### DiffGS Framework
Applies an optimization process during Gaussian extraction to optimize Gaussians to exact locations [S11]. It uses a truncation function $\lambda$ and a projection function $\tau$ (either exponential or linear) when modeling the Gaussian Probability Function (GauPF) [S11]. Performance metrics (PSNR, SSIM, LPIPS) improve with the number of Gaussians (50K, 100K, 350K) [S11].

### Opacity Offset Table for DSA
A method that constructs an opacity offset table to model changes in digital subtraction angiography [S12].

### Resolution Guided Primitive Scheduler
Schedules primitive growth using a momentum-based budgeting formula $P_{fin}^{(i)} = \max(P_{fin}^{(i-1)}, \gamma \cdot P_{fin}^{(i-1)} + \eta \cdot P_{add})$ [S13]. The power factor starts at 2 and decreases to 1 to suppress early growth and encourage mid-stage growth [S13]. Too much primitive growth at the end of optimization results in poor convergence, mitigated by the concave-up scheduling function [S13].

### Conditional Splat Approximation
A technique to approximate the influence range of a 3D Gaussian on a slice by using a 2D ellipse splat scaled by the marginal factor [S14, unofficial]. The conditional splat closely matches the true 3D Gaussian iso-probability contours, providing an accurate and efficient approximation [S14, unofficial].

### Deformation-Aware Pruning
A pruning technique that identifies and removes redundant Gaussians by gauging their impact on deformation, distinguishing between stable and deformed Gaussians [S15].

### GEMM-GS
An acceleration approach that utilizes Tensor Cores on GPUs by reformulating the blending process into a GEMM-compatible form [S16]. It transforms the conventional 3DGS blending process into a GEMM-style formulation and develops a CUDA kernel with a three-stage double-buffered pipeline [S16]. GEMM-GS achieves an average 1.42× speedup over vanilla 3DGS and an additional 1.47× speedup when combined with existing acceleration approaches [S16].

## Operating characteristics
*   **Time Complexity:** The training time is dominated by the forward and backward passes of the differentiable rasterizer, which scales with the number of Gaussians and pixels. The densification and pruning steps add overhead but are performed periodically.
*   **Memory Complexity:** Memory usage scales linearly with the number of Gaussians. Each Gaussian stores position, rotation, scale, opacity, and SH coefficients. Large scenes can exceed 1GB of memory [12927-compact-3d-gaussian-representation-c3dgs.md].
*   **Measured Performance:** GEMM-GS achieves an average 1.42× speedup over vanilla 3DGS implementation [S16]. LS-Gaussian achieves a 5.41× speedup over the edge GPU baseline on Jetson AGX Orin [S8].
*   **Strengths:** High rendering quality, real-time rendering capabilities, and explicit representation allows for easy manipulation and editing.
*   **Limitations:** High memory usage for large scenes, sensitivity to initialization, and potential for floating artifacts in large-scale scenes without proper partitioning.
*   **When to Use:** Suitable for applications requiring high-quality novel view synthesis, real-time rendering, and explicit scene representation.
*   **When Not to Use:** Not suitable for applications with strict memory constraints or when dealing with highly dynamic scenes without additional deformation modeling.

## Background
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1]. It represents a scene as a set of 3D Gaussians and uses a differentiable rasterizer to render images. The method has since been extended and optimized in various ways, including densification strategies, compression techniques, and acceleration methods.
