# Frequency Regularization

Also called: Amplitude and Phase Discrepancy Regularization, Improved Optimization via Regularization

## Overview
Frequency Regularization (FR) is a training-time constraint for 3D Gaussian Splatting that minimizes the discrepancy between the frequency spectrum of rendered images and ground truth to alleviate over-reconstruction and improve Gaussian densification [S2]. Unlike naive pixel-wise L1 loss, which fails to provide sufficient gradient signal in over-reconstructed regions, FR explicitly disentangles frequency components (amplitude and phase) to push Gaussians toward high-frequency regions where detail is missing [S2][S3, unofficial]. It sets itself apart from geometric constraints (like depth or normal regularization) by operating in the 2D image domain, targeting spectral errors rather than 3D structural consistency [S2].

## How it works
**Inputs and Outputs:**
- **Inputs:** Rendered image $\hat{I} \in \mathbb{R}^{H \times W \times C}$, Ground truth image $I \in \mathbb{R}^{H \times W \times C}$, and the current 3D Gaussian parameters (position, scale, rotation, opacity, spherical harmonics coefficients).
- **Outputs:** A scalar regularization loss $\mathcal{L}_{FR}$ used to update Gaussian parameters via backpropagation.

**Data Structures:**
- The method operates on standard image tensors. No auxiliary 3D data structures are required beyond those used for standard 3D Gaussian Splatting rasterization.
- Intermediate frequency representations are stored as complex-valued tensors of size $H \times W \times C$.

**Algorithm Steps:**
1. **Render:** Project 3D Gaussians to 2D and render the image $\hat{I}$ using standard alpha-blending [S2].
2. **Transform:** Compute the 2D Discrete Fourier Transform (DFT) for both the rendered image $\hat{I}$ and the ground truth $I$ to obtain frequency representations $\hat{F}$ and $F$ [S2].
3. **Decompose:** For each frequency component $(u, v)$ and channel $c$, decompose the complex frequency values into amplitude and phase [S2]:
   - Amplitude: $|\hat{F}(u, v, c)| = \sqrt{\text{Re}(\hat{F}(u, v, c))^2 + \text{Im}(\hat{F}(u, v, c))^2}$
   - Phase: $\angle \hat{F}(u, v, c) = \arctan\left(\frac{\text{Im}(\hat{F}(u, v, c))}{\text{Re}(\hat{F}(u, v, c))}\right)$
   - Repeat for ground truth $F(u, v, c)$ to get $|F(u, v, c)|$ and $\angle F(u, v, c)$.
4. **Compute Discrepancies:** Calculate the total amplitude discrepancy $d_a$ and total phase discrepancy $d_p$ using the Euclidean metric over all pixels and frequencies [S2]:
   $$ d_a = \sqrt{\frac{1}{HW} \sum_{x=0}^{H-1} \sum_{y=0}^{W-1} \left( |F(u, v)| - |\hat{F}(u, v)| \right)^2 } $$
   $$ d_p = \sqrt{\frac{1}{HW} \sum_{x=0}^{H-1} \sum_{y=0}^{W-1} \left( \angle F(u, v) - \angle \hat{F}(u, v) \right)^2 } $$
   *Note: The summation indices in the source [S2] use $(x,y)$ for spatial coordinates but the formula sums over frequency components $(u,v)$ implicitly or explicitly depending on interpretation. The standard interpretation of spectral loss sums over the frequency domain indices. The source formula (5) and (6) in [S2] explicitly sum over $x,y$ but compare $F(u,v)$ which suggests a potential notation mix-up in the source text where spatial and frequency indices are conflated, or it implies a specific frequency band selection. However, standard spectral loss sums over frequency bins. 5. **Combine:** The total frequency regularization loss is typically a weighted sum of amplitude and phase discrepancies:
   $$ \mathcal{L}_{FR} = \lambda_a d_a + \lambda_p d_p $$
   where $\lambda_a$ and $\lambda_p$ are weighting factors.
6. **Optimize:** Update Gaussian parameters using an optimizer (e.g., Adam) to minimize $\mathcal{L}_{FR}$ [S2].

**Parameters:**
- **Optimizer:** Adam [S2].
- **Framework:** PyTorch [S2].
- **Rasterization:** Custom CUDA kernels from 3D-GS [S2].
- **Weighting:** Not given in the sources.

**Edge Cases and Pitfalls:**
- **Over-reconstruction:** L1 loss fails to differentiate over-reconstructed regions from well-reconstructed ones, leading to redundant Gaussians. FR increases pixel gradients in over-reconstructed regions, enabling adaptive densification [S2].
- **Frequency Annealing:** Naively applying FR can bias splatting towards undesirable artifacts. Progressive frequency regularization (annealing) is used to gradually leverage low-to-high frequencies for coarse-to-fine densification [S2]. This involves incorporating a low-pass filter $H_l$ and dynamic high-pass filter $H_h$ in Fourier space [S2].
- **Precision:** Complex number arithmetic in DFT requires careful handling of numerical stability, especially for high-frequency components with low amplitude.

**Pseudocode:**
```python
import torch
import torch.fft

def frequency_regularization_loss(rendered_image: torch.Tensor, ground_truth: torch.Tensor) -> torch.Tensor:
    """
    Computes the frequency regularization loss based on amplitude and phase discrepancies.
    
    Args:
        rendered_image: Tensor of shape (H, W, C) or (B, H, W, C).
        ground_truth: Tensor of shape (H, W, C) or (B, H, W, C).
        
    Returns:
        Scalar loss tensor.
    """
    # Ensure inputs are float32 for FFT stability
    rendered_image = rendered_image.float()
    ground_truth = ground_truth.float()
    
    # Compute 2D FFT. Shift zero frequency to center is not strictly necessary for magnitude/phase diff
    # but standard practice. We compute FFT directly.
    # torch.fft.fft2 expects complex input or returns complex.
    # Input is real, so we use fft2.
    
    # Shape: (H, W, C) -> FFT along H, W
    # If batched, handle accordingly. Assuming single image for simplicity.
    
    F_rendered = torch.fft.fft2(rendered_image) # Complex tensor (H, W, C)
    F_gt = torch.fft.fft2(ground_truth)         # Complex tensor (H, W, C)
    
    # Compute Amplitude
    amp_rendered = torch.abs(F_rendered)
    amp_gt = torch.abs(F_gt)
    
    # Compute Phase
    phase_rendered = torch.angle(F_rendered)
    phase_gt = torch.angle(F_gt)
    
    # Compute Discrepancies
    # Note: Source [S2] sums over x,y but compares F(u,v). 
    # Standard spectral loss sums over frequency bins (u,v).
    # We sum over the spatial dimensions of the frequency domain (which are H, W).
    
    # Mean Squared Error for Amplitude
    # Source Eq 5: sqrt( 1/HW sum ( |F| - |F_hat| )^2 )
    mse_amp = torch.mean((amp_rendered - amp_gt) ** 2)
    d_a = torch.sqrt(mse_amp)
    
    # Mean Squared Error for Phase
    # Source Eq 6: sqrt( 1/HW sum ( angle(F) - angle(F_hat) )^2 )
    mse_phase = torch.mean((phase_rendered - phase_gt) ** 2)
    d_p = torch.sqrt(mse_phase)
    
    # Combine loss
    # Weights are not specified in sources. Using equal weights as default.
    loss = d_a + d_p
    
    return loss
```

## Subtopics

### DWTGS
DWTGS is a variant designed for sparse-view 3D Gaussian Splatting. It rethinks frequency regularization by applying a Discrete Wavelet Transform (DWT) on the rendered image instead of a Fourier Transform. It penalizes the loss in the wavelet domain to encourage sharper edges [S4, unofficial].

## Operating characteristics
- **Time Complexity:** The DFT operation is $O(HW \log(HW))$ per channel. This adds overhead to each training iteration compared to standard L1 loss.
- **Memory Complexity:** Requires storing complex frequency representations of size $H \times W \times C$, doubling the memory for image buffers during the loss computation step.
- **Performance:** FR significantly increases pixel gradients in over-reconstructed regions, leading to better Gaussian densification and reduced floaters compared to L1 loss alone [S2].
- **Strengths:** Effectively addresses over-reconstruction and improves high-frequency detail recovery.
- **Limitations:** Naive application can cause artifacts; requires careful annealing (progressive frequency regularization) to avoid biasing the optimization [S2].

## Background
Frequency Regularization was introduced in the context of 3D Gaussian Splatting optimization to address the limitations of spatial-domain losses. It is primarily associated with the FreGS method [S2]. The technique leverages the fact that amplitude and phase in the frequency domain capture different aspects of image structure, allowing for more robust supervision than pixel-wise differences. It is part of a broader trend of using spectral constraints to improve the geometric fidelity of neural rendering methods [S1][S3, unofficial].
