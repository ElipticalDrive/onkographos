# Rendering-aware QP Offset Modelling

Also called: Density-based QP scaling, Inter-Sequence QP Modelling, Intra-Sequence QP Modelling

## Overview
This method approximates the optimal Quantization Parameter (QP) distribution for Rate-Distortion Optimized (RDO) RAHT coding in 3D Gaussian Splatting (3DGS) by linking hierarchical structure to visual impact [S1, unofficial]. Unlike analytical solutions that require per-sequence fitting of multiple parameters, it uses a generalized heuristic based on scene density and resolution to generalize QP offsets across diverse scenes without iterative pre-analysis [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:**
    *   $N_{primitives}$: Total number of Gaussian primitives in the scene.
    *   $\{d_j\}_{j=1}^{N_{primitives}}$: Euclidean distance from the $j$-th primitive to its nearest neighbour.
    *   $W, H$: Training resolution width and height.
    *   $\{\bar{N}_i\}$: Average number of Gaussian primitives contained by each node at RAHT layer $i$.
*   **Outputs:**
    *   $\beta, \gamma$: Sequence-dependent fitting parameters for the QP distribution model.
    *   $\Delta q_{p_i}$: The QP offset for layer $i$, derived from the model.

**Data Structures:**
*   **Nearest-Neighbour Distances:** An array of size $N_{primitives}$ storing $d_j$ for each primitive.
*   **Layer Primitive Counts:** An array or map storing $\bar{N}_i$ for each RAHT layer $i$.

**Steps:**

1.  **Calculate Spatial Density ($\rho$):**
    Compute the average inverse square nearest-neighbour distance across all primitives [S1, unofficial]:
    $$
    \rho = \frac{1}{N_{primitives}} \sum_{j=1}^{N_{primitives}} \frac{1}{d_j^2}
    $$
    *Definition:* $\rho$ quantifies the aggregation density of primitives in 3D space. A higher $\rho$ implies more overlapping primitives, increasing the likelihood of multi-primitive accumulation per pixel during splatting [S1, unofficial].

2.  **Calculate Global Scaling Factor ($s$):**
    Modulate the QP offset based on scene density and resolution using the regression-derived formula [S1, unofficial]:
    $$
    s = 10 + 0.029 \cdot \rho \cdot (W \cdot H)^{0.2}
    $$
    *Parameters:* The constants $10$ and $0.029$ are derived from regression across the dataset. The exponent $0.2$ applies to the pixel count $(W \cdot H)$ [S1, unofficial].

3.  **Derive Sequence-Dependent Parameters ($\beta, \gamma$):**
    Analytically derive the global offset and scaling parameters from $s$ [S1, unofficial]:
    $$
    \gamma = s^3
    $$
    $$
    \beta = 0.75 \cdot s
    $$
    *Definitions:*
    *   $\beta$: Accounts for the global offset of the QP distribution.
    *   $\gamma$: Accounts for the scaling of the QP distribution [S1, unofficial].

4.  **Compute Layer-wise QP Offsets ($\Delta q_{p_i}$):**
    Model the shape of layer-wise QP offsets using $\bar{N}_i$ as a proxy for hierarchical impact. Layers closer to the root (smaller index) have higher $\bar{N}_i$ and require smaller QP values to mitigate error accumulation [S1, unofficial]. Solve for $\Delta q_{p_i}$ in the following equation [S1, unofficial]:
    $$
    (\Delta q_{p_i} + \beta)^3 = \gamma \cdot \bar{N}_i
    $$
    Rearranging for implementation:
    $$
    \Delta q_{p_i} = \sqrt[3]{\gamma \cdot \bar{N}_i} - \beta
    $$

**Pseudocode:**

```python
def compute_qp_offsets(primitive_distances, layer_avg_counts, width, height):
    """
    Compute rendering-aware QP offsets for RAHT coding layers.
    
    Args:
        primitive_distances (list[float]): List of nearest-neighbour distances d_j for all primitives.
        layer_avg_counts (dict[int, float]): Map of RAHT layer index i to average primitive count N_bar_i.
        width (int): Training resolution width W.
        height (int): Training resolution height H.
        
    Returns:
        dict[int, float]: Map of RAHT layer index i to QP offset delta_q_p_i.
    """
    n_primitives = len(primitive_distances)
    
    # Step 1: Calculate spatial density rho
    # rho = (1 / N_primitives) * sum(1 / d_j^2)
    inverse_sq_sum = 0.0
    for d in primitive_distances:
        # Guard against division by zero if a primitive is coincident with its neighbour
        if d == 0:
            d = 1e-6 
        inverse_sq_sum += 1.0 / (d * d)
    
    rho = inverse_sq_sum / n_primitives
    
    # Step 2: Calculate global scaling factor s
    # s = 10 + 0.029 * rho * (W * H)^0.2
    pixel_count = width * height
    s = 10.0 + 0.029 * rho * (pixel_count ** 0.2)
    
    # Step 3: Derive sequence-dependent parameters beta and gamma
    # gamma = s^3
    # beta = 0.75 * s
    gamma = s ** 3
    beta = 0.75 * s
    
    # Step 4: Compute layer-wise QP offsets
    # (delta_q_p_i + beta)^3 = gamma * N_bar_i
    # delta_q_p_i = (gamma * N_bar_i)^(1/3) - beta
    offsets = {}
    for layer_index, n_bar_i in layer_avg_counts.items():
        # Guard against negative values inside cube root if gamma * N_bar_i is negative (unlikely given definitions)
        val = gamma * n_bar_i
        if val < 0:
            val = 0.0
        delta_q_p_i = val ** (1.0 / 3.0) - beta
        offsets[layer_index] = delta_q_p_i
        
    return offsets
```

**Edge Cases and Pitfalls:**
*   **Zero Nearest-Neighbour Distance:** If a primitive coincides with its nearest neighbour ($d_j=0$), the inverse square term becomes undefined. A small epsilon (e.g., $10^{-6}$) should be used as a lower bound for $d_j$ [G].
*   **Negative Cube Root Argument:** Theoretically, $\gamma$ and $\bar{N}_i$ are positive, so $\gamma \cdot \bar{N}_i$ is positive. However, numerical precision issues or invalid input data could result in negative values. Clamp to zero before taking the cube root [G].
*   **Resolution Scaling:** The term $(W \cdot H)^{0.2}$ ensures that higher resolutions increase the scaling factor $s$, leading to larger $\gamma$ and $\beta$, which adjusts QP offsets to account for finer sampling [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N_{primitives})$ to compute $\rho$ and $O(L)$ to compute offsets for $L$ layers. This is significantly faster than iterative per-sequence fitting methods.
*   **Memory Complexity:** $O(N_{primitives})$ to store nearest-neighbour distances. $O(L)$ for layer counts.
*   **Strengths:** Generalizes across diverse scenes without per-sequence fitting. Accounts for error accumulation during splatting projection by linking hierarchical structure to visual impact.
*   **Limitations:** Relies on regression-derived constants ($10, 0.029, 0.2, 0.75$) which may not be optimal for all scene types or hardware configurations. Assumes the relationship between density, resolution, and QP offset holds across the dataset used for regression.
*   **When to Use:** When coding 3DGS data with RAHT and needing a fast, generalized method to set QP offsets based on scene properties.
*   **When Not to Use:** When per-sequence optimization is feasible and maximum rate-distortion performance is critical, as analytical solutions with per-sequence fitting may yield better results [S1, unofficial].

## Background
This method was proposed in the context of Rate-Distortion Optimized RAHT coding for 3D Gaussian Splatting [S1, unofficial]. It addresses the limitation that optimal QP offsets exhibit a linear trend relative to the RAHT layer index, but this relationship cannot be directly generalized due to varying numbers of RAHT layers between sequences [S1, unofficial]. The method builds on the observation that error accumulation in splatting projection is constructive for root layers (leading to visual distortion) and random for leaf layers (cancelling out) [S1, unofficial]. It was developed to eliminate the need for per-sequence parameter fitting, enabling robust performance across diverse scenes [S1, unofficial].
