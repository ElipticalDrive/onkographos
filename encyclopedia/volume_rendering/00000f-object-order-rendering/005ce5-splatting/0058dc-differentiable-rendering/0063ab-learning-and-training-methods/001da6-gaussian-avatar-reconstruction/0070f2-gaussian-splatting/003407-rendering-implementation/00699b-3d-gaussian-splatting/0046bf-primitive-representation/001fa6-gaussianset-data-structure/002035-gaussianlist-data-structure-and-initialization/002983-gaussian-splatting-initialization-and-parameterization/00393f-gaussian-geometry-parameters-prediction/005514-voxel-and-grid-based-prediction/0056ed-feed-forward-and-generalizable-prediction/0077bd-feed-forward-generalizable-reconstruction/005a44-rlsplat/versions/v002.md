# RLSplat

Also called: Resource-Linear Budget Control for Feed-forward 3D Gaussian Splatting

## Overview
RLSplat is a resource-linear, budget-controllable feed-forward 3D Gaussian Splatting (FF3DGS) framework that ensures inference latency, peak memory, and representation size scale linearly with the requested Gaussian budget $B$ [S1, unofficial]. Unlike prior budget-controllable methods (e.g., EcoSplat, F4 Splat) that predict a dense set of candidates and prune them—resulting in nearly constant inference costs regardless of $B$—RLSplat learns a Gaussian allocation policy to distribute exactly $B$ Gaussians across local scene regions from the start [S1, unofficial]. It solves the problem of rigid resource usage in real-time applications like AR/VR and robotics by allowing the user to specify a target Gaussian count, with the system adapting the density of primitives to local geometric complexity [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of $V$ uncalibrated context images $\{I_i\}_{i=1}^V$ and a target integer Gaussian budget $B$.
*   **Outputs:** A set of $B$ 3D Gaussians $\mathcal{G} = \{g_b\}_{b=1}^B$ and the context camera parameters $\{P_i\}_{i=1}^V$. Each Gaussian $g_b$ consists of a 3D center, opacity, scale, rotation, and color coefficients [S1, unofficial].

**Data Structures:**
1.  **Anchor Tokens ($\mathcal{A}$):** A set of $N$ tokens $\{a_n\}_{n=1}^N$ extracted from the geometry backbone, each representing a local 3D region.
2.  **Allocation Vector ($\mathbf{k}$):** A discrete vector $\mathbf{k} \in \mathbb{Z}_{\ge 0}^N$ where $k_n$ is the number of Gaussians assigned to anchor $n$, such that $\sum_{n=1}^N k_n = B$.
3.  **Gaussian Tokens:** $B$ tokens generated by spawning $k_n$ tokens per anchor $n$.
4.  **Hierarchical Neighbor Search Structure:** Used to find the $K_{gs}$ nearest Gaussian neighbors for each token efficiently.

**Parameters:**
*   $B$: Target Gaussian budget. Typical evaluation values are 2K (2,048) and 64K [S1, unofficial]. On ACID, $B=8,192$ (1,024 per view) is used; on RE10K, $B=8,000$ is used [S1, unofficial].
*   $K_{gs}$: Number of nearest Gaussian neighbors each token attends to during refinement. Default ablation value is 16. This can be changed at inference without retraining [S1, unofficial].
*   $K_{anc}$: Number of anchor neighbors used in the hierarchical neighbor search. Fixed value in ablations is 16 [S1, unofficial].
*   $C$: Number of rollouts (candidate allocations) drawn per training step for the Group Sequence Policy Optimization (GSPO) [S1, unofficial].

**Algorithm:**

1.  **Geometry Encoding:** The geometry backbone encodes the input images $\{I_i\}$ into $N$ anchor tokens $\{a_n\}_{n=1}^N$ and predicts camera parameters $\{P_i\}$ [S1, unofficial].
2.  **Gaussian Allocation:** The allocation policy $\pi_\psi$ assesses the local significance of each anchor (based on image features like texture complexity) and predicts a discrete allocation vector $\mathbf{k}$ such that $\sum k_n = B$. This policy is trained using GSPO [S1, unofficial].
3.  **Token Spawning:** Each anchor $n$ spawns $k_n$ Gaussian tokens. The total number of Gaussian tokens is exactly $B$ [S1, unofficial].
4.  **Resource-Linear Decoding:**
    *   The decoder instantiates initial Gaussian states (center, scale, rotation, opacity, color) from the spawned tokens.
    *   It refines these Gaussians via local cross-attention. For each Gaussian token, it identifies its $K_{gs}$ nearest Gaussian neighbors using a hierarchical neighbor search.
    *   Each token attends only to these $K_{gs}$ neighbors, rather than all $B$ tokens [S1, unofficial].
5.  **Rendering:** The final set of $B$ Gaussians is rendered using standard differentiable rasterization to compute losses (RGB, depth, geometry) for training the feed-forward network [S1, unofficial].

**Pseudocode:**

```python
def rlsplat_forward(context_images, budget_B):
    """
    Performs a single forward pass of RLSplat.
    
    Args:
        context_images: List of V uncalibrated images {I_i}.
        budget_B: Integer target number of Gaussians B.
        
    Returns:
        gaussians: List of B 3D Gaussian parameters.
        cameras: List of V camera parameters {P_i}.
    """
    # Step 1: Geometry Backbone
    # Encodes images into anchor tokens and predicts camera poses
    anchor_tokens, cameras = geometry_backbone(context_images)
    N = len(anchor_tokens)
    
    # Step 2: Gaussian Allocation Policy
    # Predicts allocation proportions p, then samples discrete allocation k
    # k is a vector of length N, sum(k) == budget_B
    # Trained with GSPO; inference uses the current policy weights
    allocation_proportions = allocation_policy(anchor_tokens)
    k = sample_allocation(allocation_proportions, budget_B)
    
    # Step 3: Spawn Gaussian Tokens
    # Create B tokens. Token list is ordered by anchor index.
    gaussian_tokens = []
    for n in range(N):
        count = k[n]
        # Spawn 'count' tokens for anchor n
        # Initial state is predicted from anchor token a_n
        for _ in range(count):
            token = spawn_token(anchor_tokens[n])
            gaussian_tokens.append(token)
            
    # Step 4: Resource-Linear Decoding with Local Refinement
    # Refine each Gaussian by attending to its K_gs nearest neighbors
    
    # Precompute neighbors using hierarchical search
    # Returns a list of lists: neighbors[b] contains indices of K_gs nearest Gaussians to b
    neighbor_indices = hierarchical_neighbor_search(gaussian_tokens, K_gs=16)
    
    refined_gaussians = []
    for b in range(budget_B):
        token = gaussian_tokens[b]
        neighbor_idxs = neighbor_indices[b]
        
        # Local cross-attention: attend only to neighbors
        # This step is O(K_gs) per token, total O(B * K_gs)
        refined_token = local_cross_attention(token, gaussian_tokens, neighbor_idxs)
        
        # Decode refined token into final Gaussian parameters
        gaussian = decode_gaussian(refined_token)
        refined_gaussians.append(gaussian)
        
    return refined_gaussians, cameras

    In training, this is done via GSPO with multiple rollouts.
    In inference, a deterministic or single-sample strategy is used.
    """

    # To ensure sum(k) == B, a multinomial sampling or rounding strategy
    # constrained to the sum is used.
```

**Edge Cases and Pitfalls:**
*   **Allocation Validity:** The allocation policy must strictly satisfy $\sum k_n = B$. If the policy outputs invalid allocations, the spawning step fails. GSPO training ensures this constraint is met via the sampling mechanism [S1, unofficial].
*   **Neighbor Search Degeneracy:** If $B$ is very small, the hierarchical neighbor search must still function correctly. The parameter $K_{gs}$ can be adjusted at inference, but if $K_{gs} \ge B$, the attention becomes global, breaking the linear complexity guarantee [S1, unofficial].
*   **Projection Loss:** Removing the projection loss causes training to fail entirely, as it ties anchors to their corresponding image regions [S1, unofficial].
*   **Voronoi Loss:** Removing the Voronoi loss causes a significant PSNR drop (2.51 dB) because Gaussians leave their anchor's cell, and the hierarchical search no longer retrieves their true neighbors [S1, unofficial].

## Subtopics

### Gaussian Allocation Policy
A learned policy that distributes the Gaussian budget $B$ across anchors based on local scene significance (e.g., texture complexity). It differs from uniform allocation by concentrating capacity on high-frequency structures (e.g., thin balusters) and sparing smooth areas. It is chosen when adaptive resource distribution is needed [S1, unofficial].

### Resource-Linear Decoder
A refinement module that uses local cross-attention with hierarchical neighbor search instead of global self-attention. It differs from global attention by reducing complexity from $O(B^2)$ to $O(B \cdot K_{gs})$. It is chosen when inference latency and memory must scale linearly with the output size [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The decoding cost is $O(B \cdot K_{gs})$, scaling linearly with the Gaussian budget $B$. This contrasts with global self-attention, which costs $O(B^2)$ [S1, unofficial].
*   **Memory Complexity:** Peak memory scales linearly with $B$, as only $B$ Gaussians are generated and stored, unlike pruning methods that store large candidate sets [S1, unofficial].
*   **Measured Performance:**
    *   At $B=2,048$, RLSplat achieves higher PSNR than F4 Splat while using 9.6× less peak memory and running 4.1× faster [S1, unofficial].
    *   On ACID ($B=8,192$): PSNR 22.84 dB, SSIM 0.643, LPIPS 0.353 [S1, unofficial].
    *   On RE10K ($B=8,000$): Full-view PSNR 26.51 dB, compared to 23.42 dB for F4 Splat and 21.82 dB for EcoSplat [S1, unofficial].
    *   Hierarchical neighbor search ($K_{anc}=16, K_{gs}=16$) is 27× faster (8.1 ms vs. 219.6 ms) than exact search at 65,536 Gaussians [S1, unofficial].
*   **Strengths:** Linear scaling of inference cost with budget; superior quality on thin, high-frequency structures compared to uniform or pruning-based methods; no retraining required to change $B$ or $K_{gs}$ at inference.
*   **Limitations:** Requires training of the allocation policy via GSPO; performance depends on the accuracy of the hierarchical neighbor search.
*   **Usage:** Suitable for AR/VR, robotics, and digital content creation where resource budgets are strict and variable [S1, unofficial].

## Background
RLSplat was proposed by Bae, Park, and Kim from KAIST in 2026 [S1, unofficial]. It addresses the limitations of prior budget-controllable FF3DGS methods like EcoSplat and F4 Splat, which control output size but not inference cost [S1, unofficial]. The method builds on the principles of feed-forward 3D Gaussian Splatting, using a geometry backbone and differentiable rendering [S1, unofficial]. It introduces the concept of resource-linear budget control, where the computational cost itself is a function of the desired output size [S1, unofficial].
