# Unsupervised Asset Grouping

Also called: Asset Grouping via JSD Clustering

## Overview
Unsupervised Asset Grouping is a method for categorizing discovered 3D objects by comparing the distributions of color and semantic features among patches using Jensen-Shannon Divergence (JSD) and agglomerative clustering [S1]. It solves the problem of object categorization in the absence of explicit object pose information, where pixel-wise comparison is suboptimal [S1]. It sets itself apart from sibling methods like SemGauss-SLAM by focusing on post-optimization asset mining and reconfiguration via feature plane discretization rather than joint semantic-geometric optimization during rendering [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** An inferred RGB-DINO ground feature plane $M_{\text{rgb-dino}}$, where each pixel $(x,y)$ is interpolated from $M_{\text{rgb-dino}}$ via decoders $\text{Dec}_{\text{rgb}}$ and $\text{Dec}_{\text{dino}}$ to yield scene color $c$ and semantic features $f_{\text{dino}}$ [S1].
*   **Output:** A set of labeled object feature patches $K$, grouped clusters, selected template objects, and a Bird's Eye View (BEV) layout describing object positions and poses [S1].

**Data Structures:**
*   $M_{\text{rgb-dino}}$: 2D feature plane storing RGB and DINO semantic features.
*   $K$: Set of discrete object feature patches resulting from clustering.
*   $P_{\text{rgb-dino}}$: Set of RGB-DINO feature patches for template matching.

**Steps:**
1.  **Discretization:** Discretize the continuous feature plane $M_{\text{rgb-dino}}$ using a clustering algorithm (e.g., K-means) to produce a set of labeled object feature patches $K$ [S1].
2.  **Similarity Measurement:** For any two object patches $k_i, k_j \in K$, compute the similarity using the Jensen-Shannon Divergence over the distribution of their labels, denoted as $\text{JSD}(k_i || k_j)$ [S1].
3.  **Clustering:** Perform agglomerative clustering using the JSD distance metric to group patches into categories [S1]. The number of clusters is determined by inspecting training views and can be adjusted for desired granularity [S1].
4.  **Template Selection:** Select one template object from each cluster, either randomly or via user definition [S1].
5.  **BEV Layout Extraction:** Extract the scene layout in BEV by optimizing a rotation angle $\theta$ for each copy of the template. This minimizes the pixel-wise loss between the template patch $\hat{p}$ and the rotated copy $p$ [S1].

**Formulas:**
The optimal rotation angle $\theta^*$ is found by:
$$
\theta^* = \arg\min_\theta \sum_i \|\hat{p}_i - R_\theta(p_i)\|_2^2
$$
where $p \in P_{\text{rgb-dino}}$, $\hat{p}$ is the template RGB-DINO feature patch, and $R_\theta$ rotates the input feature patch by $\theta$ [S1].

**Parameters:**
*   Clustering algorithm: K-means (typical) [S1].
*   Distance metric: Jensen-Shannon Divergence [S1].
*   Number of clusters: User-defined or derived from training view inspection [S1].

**Edge Cases and Pitfalls:**
*   **Absence of Pose:** Standard pixel-wise comparison fails without pose information; JSD on distributions is required [S1].
*   **Granularity:** The number of clusters is not automatically determined by the algorithm but requires user inspection or adjustment [S1].

## Subtopics

### Cross-scene Asset Library Construction
A framework to represent a scene using template feature patches, BEV layout, shared vertical feature axes, and MLP decoders, enabling cross-scene asset discovery by sharing vertical axes among different scenes [S1]. It constructs a library storing template feature patches by sharing vertical axes across scenes, allowing newly configured scenes to be rendered directly without retraining using shared axes and decoders with new template patches and layout [S1].

## Operating characteristics
*   **Time Complexity:** Depends on the clustering algorithm (e.g., K-means) and the agglomerative clustering step, which is generally $O(N^2)$ or $O(N \log N)$ depending on implementation, where $N$ is the number of patches [S1].
*   **Memory Complexity:** Requires storing the feature plane $M_{\text{rgb-dino}}$, the set of patches $K$, and the template library [S1].
*   **Strengths:** Enables versatile scene editing at object-, category-, and scene-level; supports cross-scene analogue discovery; allows rendering new scenes without retraining [S1].
*   **Limitations:** Requires an initial inference of the RGB-DINO ground feature plane; relies on user input for cluster count [S1].
*   **When to use:** When the goal is asset mining, categorization, and reconfiguration rather than real-time semantic SLAM [S1].
*   **When not to use:** When real-time joint optimization of geometry and semantics is required (use SemGauss-SLAM instead) .

## Background
Originated in the "AssetField" paper, which proposes a ground feature plane representation for assets mining and reconfiguration [S1]. It addresses the limitation of previous voxel-based neural representations that lacked constraints for cross-scene analogue discovery [S1].
