# 2D Gaussian Splatting Rasterization

Also called: 2D Gaussian Splatting Surfel Rasterization

## Overview
This method renders a scene represented by 2D Gaussian primitives (surfels) into RGB, alpha, and normal maps using a custom rasterization pipeline [S1, unofficial]. It differs from standard 3D Gaussian Splatting by operating on surfels projected into screen space and accumulating color and geometric attributes via front-to-back alpha compositing [Parent]. The core distinction is the use of a closed-form ray-surfel intersection to map screen pixels to local texture coordinates, enabling accurate handling of the 2D Gaussian density distribution [S1, unofficial].

## How it works
**Inputs:**
- `means`: 3D positions of $N$ surfels, shape $[N, 3]$.
- `quats`: Unit quaternions $(w, x, y, z)$ representing orientation, shape $[N, 4]$.
- `scales`: Local scale factors, shape $[N, 3]$.
- `opacities`: Per-surfel opacity values, shape $[N]$.
- `colors`: Per-surfel colors, shape $[N, D]$ (where $D=3$ for RGB) or spherical harmonic coefficients if `sh_degree` is provided.
- `viewmats`: Camera-to-world transformation matrices, shape $[C, 4, 4]$.
- `Ks`: Camera intrinsic matrices, shape $[C, 3, 3]$.
- `width`, `height`: Image dimensions.
- `near_plane`, `far_plane`: Clipping distances.
- `tile_size`: Integer, default 16. Side length of tiles for rasterization.
- `sh_degree`: Spherical harmonic degree (integer or `None`). If `None`, colors are used directly.
- `backgrounds`: Background color per camera, shape $[C, 3]$.

**Outputs:**
- `render_colors`: Shape $[C, H, W, 3]$.
- `render_alphas`: Shape $[C, H, W, 1]$.
- `render_normals`: Shape $[C, H, W, 3]$.

**Data Structures:**
- `means2d`: Projected 2D centers, shape $[C, N, 2]$.
- `radii`: Screen-space radii of bounding circles, shape $[C, N]$.
- `depths`: Z-depth of surfel centers, shape $[C, N]$.
- `ray_transforms`: Local-to-world transformation matrices for ray intersection, shape $[C, N, 3, 3]$.
- `normals`: Surface normals in world space, shape $[C, N, 3]$.
- `isect_offsets`: Encoded intersection offsets for tile-based sorting, shape $[C, T_h, T_w]$.
- `flatten_ids`: Flattened indices of intersecting surfels, shape $[C, T_h, T_w, \text{max\_per\_tile}]$.

**Steps:**

1. **Projection:**
   Project 2D Gaussian surfels to 2D screen space using `fully_fused_projection_2dgs`. Inputs are `means`, `quats`, `scales`, `viewmats`, `Ks`, `width`, `height`, `near_plane`, `far_plane`. Outputs are `radii`, `means2d`, `depths`, `ray_transforms`, and `normals` [S1, unofficial].

2. **Color Preparation:**
   - Broadcast scalar per-surfel opacities $[N]$ to per-camera $[C, N]$ using `mx.broadcast_to(mx.expand_dims(opacities, axis=0), (C, N))` [S1, unofficial].
   - If `sh_degree` is not `None`:
     - Compute view directions: $\text{dirs} = \text{means}[None, :, :] - \text{campos}[:, None, :]$.
     - Normalize `dirs`.
     - Broadcast color coefficients to $[C, N, K, 3]$ (where $K$ is the number of SH coefficients).
     - Evaluate spherical harmonics: $\text{rgb} = \text{spherical\_harmonics}(\text{sh\_degree}, \text{dirs}, \text{coeffs\_broadcast})$.
     - Clamp colors: $\text{rgb} = \max(\text{rgb} + 0.5, 0.0)$ [S1, unofficial].
   - If `sh_degree` is `None`:
     - Broadcast colors $[N, D]$ to $[C, N, D]$ or use colors $[C, N, D]$ directly as `colors_for_raster` [S1, unofficial].

3. **Tile Intersection:**
   - Compute tile dimensions: $T_w = \lceil \text{width} / \text{tile\_size} \rceil$, $T_h = \lceil \text{height} / \text{tile\_size} \rceil$.
   - Call `isect_tiles(means2d, radii, depths, tile_size, tile_width, tile_height, sort=True)` to get `tiles_per_gauss`, `isect_ids`, and `flatten_ids` [S1, unofficial].

4. **Offset Encoding:**
   - Encode intersection offsets using `isect_offset_encode(isect_ids, C, tile_width, tile_height)` to get `isect_offsets` $[C, T_h, T_w]$ [S1, unofficial].

5. **Rasterization (Per-Pixel Ray-Surfel Intersection):**
   For each surfel `gid` in depth order (or processed via the tile-based kernel):
   - Retrieve the projection matrix $M_g$ (derived from `ray_transforms` and camera intrinsics) for the surfel and camera. Specifically, $M_g$ is a $3 \times 3$ matrix representing the local transformation [S1, unofficial].
   - For each pixel $(pxf, pyf)$ within the surfel's bounding box (or processed in parallel by the kernel):
     - Compute ray-surfel intersection vectors:
       $$h_u = -M_g[0, :3] + M_g[2, :3] \cdot pxf$$
       $$h_v = -M_g[1, :3] + M_g[2, :3] \cdot pyf$$
       where $pxf, pyf$ are the pixel coordinates in the local screen space of the surfel [S1, unofficial].
     - Compute cross product and guard against degenerate case:
       $$tmp = \text{cross}(h_u, h_v)$$
       If $|tmp[2]| < 10^{-10}$, skip this intersection [S1, unofficial].
     - Compute intersection coordinates:
       $$us = tmp[0] / tmp[2]$$
       $$vs = tmp[1] / tmp[2]$$
     - Compute 3D sigma from intersection:
       $$\sigma_{3d} = us^2 + vs^2$$
     - Compute 2D fallback sigma from distance to center:
       $$\sigma_{2d} = 2.0 \cdot (dx^2 + dy^2)$$
       where $dx, dy$ are the distances from the pixel to the surfel center in screen space [S1, unofficial].
     - Take tighter bound:
       $$\sigma = 0.5 \cdot \min(\sigma_{3d}, \sigma_{2d})$$
     - Compute alpha clamped to `MAX_ALPHA` (typically 1.0):
       $$\alpha = \min(\text{opacity} \cdot \exp(-\sigma), \text{MAX\_ALPHA})$$
     - If $\alpha > 0$, accumulate color and normal using front-to-back alpha compositing [S1, unofficial].

6. **Final Compositing:**
   - Accumulate `render_colors`, `render_alphas`, and `render_normals` using front-to-back alpha compositing [S1, unofficial].
   - Add background color if alpha < 1.0 [S1, unofficial].

    height: int,
    tile_size: int = 16,

    Rasterize 2D Gaussian surfels to pixels.

    """
    C, N, _ = means2d.shape
    render_colors = np.zeros((C, height, width, 3), dtype=np.float32)
    render_alphas = np.zeros((C, height, width, 1), dtype=np.float32)
    render_normals = np.zeros((C, height, width, 3), dtype=np.float32)
    
    MAX_ALPHA = 1.0
    
    # Iterate over cameras

## Subtopics

### [Per-Primitive Texture Mapping for Reflective Gaussian Splatting](8629-per-primitive-texture-mapping-for-reflective-gaussian-splatt.md)
Enhances 2D Gaussian Splatting by replacing single attribute values per primitive with spatially varying texture maps for material properties and normals. Unlike methods that assign constant attributes to each primitive, this approach decouples geometric representation from appearance, enabling high-frequency specular reconstruction and accurate reflections in reflective scenes without increasing the primitive count. It builds on [2D Gaussian Splatting Rasterization](4815-2d-gaussian-splatting-rasterization.md) by leveraging the closed-form ray-splat intersection to map screen pixels to local texture coordinates, allowing hardware-accelerated rendering via texture atlases.

### [ToF Gaussian Rasterization Forward Pass](9261-tof-gaussian-rasterization-forward-pass.md)
This method implements the forward pass of the C++/CUDA rasterizer for Time-of-Flight Gaussian Splatting. It restructures scene and camera parameters into a single tuple, invokes the CUDA kernel, and returns rendered maps including color, phasor, depth, and auxiliary buffers.

### [Vanilla 2D Gaussian Splatting Rendering](12208-vanilla-2d-gaussian-splatting-rendering.md)
Renders a scene represented by 2D Gaussian primitives into RGB, alpha, normal, and depth maps using a custom rasterizer. It differs from standard 3D Gaussian Splatting by operating on surfels (2D Gaussians) projected into screen space, accumulating color and geometric attributes via front-to-back alpha compositing [Parent].

### [Nexels](13877-nexels.md)
Nexels is a novel view synthesis method that decouples geometry and appearance to achieve a compact representation using a fixed number of primitives per pixel. It uses surfels with a generalized Gaussian kernel for geometry and a shared neural field (Instant-NGP) for view-dependent appearance, rendered via a two-pass process to handle sparse primitives efficiently. Unlike sibling methods that couple appearance to primitives or use slower neural field lookups, Nexels textures only the top-$K$ primitives per pixel, ensuring real-time performance while matching the perceptual quality of 3D Gaussian Splatting with significantly fewer primitives.

## Operating characteristics
- **Time Complexity:** $O(N \cdot H \cdot W)$ in the naive pixel-wise approach, but optimized to $O(N + H \cdot W)$ with tile-based rasterization where $N$ is the number of surfels and $H, W$ are image dimensions. The tile-based approach reduces overhead by only processing surfels that intersect tiles.
- **Memory Complexity:** $O(N + H \cdot W)$ for storing surfel properties and output buffers. The tile-based approach requires additional memory for `isect_offsets` and `flatten_ids`, which is $O(C \cdot T_h \cdot T_w \cdot \text{max\_per\_tile})$.
- **Measured Performance:** The reference implementation in MLX renders 7 Gaussians at 256x256 in approximately 1-2 ms on a modern CPU [S1, unofficial]. Performance scales with the number of surfels and image resolution.
- **Strengths:** Accurate handling of 2D Gaussian density distribution, support for normals and textures, efficient tile-based rasterization.
- **Limitations:** The reference implementation is not differentiable [S1, unofficial]. The CUDA implementation is faster but requires GPU support.
- **When to Use:** When high-quality rendering of 2D Gaussian primitives is required, especially for reflective scenes or when normals are needed.
- **When Not to Use:** When differentiability is required for training (use the differentiable accumulate path instead) [S1, unofficial].

## Background
The method is part of the 2D Gaussian Splatting (2DGS) framework, which extends 3D Gaussian Splatting by using 2D Gaussian primitives (surfels) to represent surfaces. The reference implementation is provided by the `gsplat-mlx` library [S1, unofficial]. The approach leverages the closed-form ray-surfel intersection to accurately compute the contribution of each surfel to each pixel.
