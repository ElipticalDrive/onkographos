# Volume Encoding Gaussians

Also called: Transfer Function-Agnostic 3D Gaussians for Volume Rendering

## Overview
Volume Encoding Gaussians adapts 3D Gaussian Splatting for volume data visualization by removing per-Gaussian color and opacity attributes, training only scalar values to enable interactive transfer function application post-training [S1, unofficial]. It differs from standard Gaussian Splatting Volume Rendering by decoupling the volumetric density representation from the visual appearance, allowing dynamic remapping of scalar fields to color and opacity without retraining [S1, unofficial].

## How it works
**Inputs:** A set of 3D Gaussians defined by position $\mathbf{p}$, covariance matrix $\Sigma$, and a learned scalar value $s$. Camera parameters (view matrix, projection).
**Outputs:** A rendered 2D image with color and alpha channels determined by a user-defined transfer function applied to the projected scalar values.

**Data Structures:**
Each Gaussian primitive $i$ stores:
- $\mathbf{p}_i \in \mathbb{R}^3$: Position.
- $\Sigma_i \in \mathbb{R}^{3 \times 3}$: Covariance matrix (symmetric positive definite).
- $s_i \in \mathbb{R}$: Learned scalar value (density proxy).
- Note: Color $c_i$ and opacity $\alpha_i$ are **not** stored as trainable attributes [S1, unofficial].

**Steps:**
1. **Initialization:** Initialize Gaussians from volume data (e.g., via sampling or optimization against target volume slices). Optimize $\mathbf{p}_i, \Sigma_i, s_i$ to minimize reconstruction error of the scalar field [S1, unofficial].
2. **Projection:** For each Gaussian, compute the 2D covariance $\Sigma_{2D}$ using the view matrix $W$ and perspective Jacobian $J$ as per standard Gaussian Splatting [G]:
   $$ \Sigma_c = J W \Sigma W^T J^T $$
   $$ \Sigma_{2D} = \Sigma_c[:2, :2] $$
3. **Rasterization:** Project Gaussians to screen space. For each pixel $\mathbf{u}$ covered by a Gaussian's bounding box, compute the 2D Gaussian value:
   $$ \mathcal{G}_i(\mathbf{u}) = \exp\left(-\frac{1}{2} (\mathbf{u} - \mathbf{p}_{2D,i})^T \Sigma_{2D,i}^{-1} (\mathbf{u} - \mathbf{p}_{2D,i})\right) $$
4. **Scalar Accumulation:** Accumulate the weighted scalar values for each pixel. Unlike standard alpha blending which accumulates color, this step accumulates a "density" or "scalar sum" $S_{pixel}$:
   $$ S_{pixel} = \sum_{i \in \text{sorted}} s_i \cdot \mathcal{G}_i(\mathbf{u}) \cdot \prod_{j < i} (1 - \mathcal{G}_j(\mathbf{u})) $$
   *Note: The exact compositing formula may vary based on whether opacity is derived from $s_i$ or fixed. The core innovation is that $s_i$ is the primary attribute.* [S1, unofficial]
5. **Transfer Function Application:** Apply a user-defined transfer function $TF(s)$ to the accumulated scalar value $S_{pixel}$ to determine final color $C$ and opacity $\alpha$:
   $$ C = TF_{color}(S_{pixel}) $$
   $$ \alpha = TF_{opacity}(S_{pixel}) $$
   This step is performed per-pixel after rasterization, enabling interactive adjustment [S1, unofficial].

**Parameters:**
- Transfer Function: User-defined, typically piecewise linear or exponential mappings from scalar range to [0,1] for color/alpha [S1, unofficial].
- Scalar Range: Normalized during training, typically [0, 1] or min/max of volume data [S1, unofficial].

**Edge Cases:**
- Zero scalar values: Gaussians with $s_i \approx 0$ contribute negligible density and may be culled [S1, unofficial].
- Transfer function discontinuities: May cause aliasing artifacts; smoothing TFs is recommended [G].

## Subtopics

### [GVGEN](8091-gvgen.md)
GVGEN is a method for 3D generation that operates in 3D space using a 3D Gaussian volume representation. It is distinguished from sibling methods like GaussianCube, which converts a constant number of Gaussians into a voxelized representation via optimal transport, by maintaining a direct 3D Gaussian volume structure.

## Operating characteristics
- **Time Complexity:** Rasterization is $O(N)$ per pixel where $N$ is the number of overlapping Gaussians, similar to standard Gaussian Splatting. Transfer function application is $O(1)$ per pixel.
- **Memory Complexity:** Reduced compared to standard Gaussian Splatting as color and opacity attributes are removed, storing only scalar values [S1, unofficial].
- **Strengths:** Enables interactive exploration of volume data via dynamic transfer functions without retraining [S1, unofficial].
- **Limitations:** Requires a separate training phase to learn scalar values; not suitable for direct color/texture rendering without modification [S1, unofficial].

## Background
Originated from the work "Transfer Function-Agnostic 3D Gaussians for Volume Rendering" [S1, unofficial]. It extends the 3D Gaussian Splatting framework [G] to handle volumetric scalar fields by decoupling geometry/density from appearance.
