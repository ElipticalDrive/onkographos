# Tile-based Depth Sorting

Also called: STP

## Overview
Tile-based Depth Sorting is a rasterization strategy designed to mitigate "popping" artifacts in 3D Gaussian Splatting by replacing per-ray depth sorting with tile-based sorting [S1][S2, unofficial]. It ensures a consistent depth ordering within a local region, addressing the sensitivity of alpha-blending order to viewpoint rotation [S1][S2, unofficial].

## How it works
Inputs: List of $N$ projected 2D Gaussian splats, each with center $(x_i, y_i)$, 2D covariance $\Sigma'_i$, color $c_i$, opacity $\alpha_i$, and depth $Z_c$ [G]. Outputs: A dictionary mapping each tile ID to a list of splats sorted front-to-back by depth [G].
Data structures: A flat list of work items, each containing a 64-bit sort key, a 1D tile ID, and a splat index [Sibling: Tile-based Rasterization with Radix Sort](7921-tile-based-rasterization-with-radix-sort.md). The output is a tile-indexed array of splat lists [G].
Numbered steps:
1. Tile Assignment: Each Gaussian is assigned to every tile its projected 2D splat bounding box touches [Sibling: Tile-based Rasterization with Radix Sort](7921-tile-based-rasterization-with-radix-sort.md). If a splat straddles tile boundaries, it is duplicated into each relevant tile, creating one work item per (splat, tile) pair [Sibling: Tile-based Rasterization with Radix Sort](7921-tile-based-rasterization-with-radix-sort.md).
2. Key Packing: For each work item, a 64-bit integer sort key is constructed by packing the tile ID into the high 32 bits and the splat's depth $Z_c$ into the low 32 bits [Sibling: Tile-based Rasterization with Radix Sort](7921-tile-based-rasterization-with-radix-sort.md).
3. Global Radix Sort: A single GPU radix sort is performed over all work items [Sibling: Tile-based Rasterization with Radix Sort](7921-tile-based-rasterization-with-radix-sort.md). This simultaneously bins splats by tile ID and sorts them by depth within each tile [Sibling: Tile-based Rasterization with Radix Sort](7921-tile-based-rasterization-with-radix-sort.md).
4. Tile Processing: Each tile is processed by one GPU thread block that walks the sorted list, performing front-to-back compositing and breaking early when transmittance $T < \epsilon$ [Sibling: Tile-based Rasterization with Radix Sort](7921-tile-based-rasterization-with-radix-sort.md).
Formulas: The sort key is formed as $\text{key} = (\text{tile\_id} \ll 32) \mid (\text{uint32\_t})Z_c$, where $\text{tile\_id} = y \times \text{grid\_width} + x$ and $Z_c$ is cast to a 32-bit unsigned integer [Sibling: Tile-based Rasterization with Radix Sort](7921-tile-based-rasterization-with-radix-sort.md).
Parameters: Tile dimensions $T_w \times T_h$, typically $16 \times 16$ pixels [Sibling: Tile-based Rasterization with Radix Sort](7921-tile-based-rasterization-with-radix-sort.md).
Edge cases and pitfalls: Per-ray depth sorting causes inconsistent ordering when viewpoints rotate, leading to "popping" artifacts and less faithful view-dependent effects [S1][S2, unofficial]. Tile-based sorting ensures consistent local ordering but may introduce slight depth inaccuracies at tile boundaries if splats are large [G]. Precision loss can occur when casting $Z_c$ to uint32_t if depth values exceed $2^{32}$ units [G].
Pseudocode:
```python
def tile_based_depth_sorting(splats, image_w, image_h, tile_size=16):
    grid_w = (image_w + tile_size - 1) // tile_size
    grid_h = (image_h + tile_size - 1) // tile_size
    tile_splats = {}

    # 1. Tile Assignment & Key Packing
    work_items = []
    for i, s in enumerate(splats):
        min_tx = max(0, int((s['x'] - s['radius']) // tile_size))
        max_tx = min(grid_w - 1, int((s['x'] + s['radius']) // tile_size))
        min_ty = max(0, int((s['y'] - s['radius']) // tile_size))
        max_ty = min(grid_h - 1, int((s['y'] + s['radius']) // tile_size))

        for ty in range(min_ty, max_ty + 1):
            for tx in range(min_tx, max_tx + 1):
                tile_id = ty * grid_w + tx
                key = (tile_id << 32) | (s['Zc'] & 0xFFFFFFFF)
                work_items.append((key, tile_id, i))

    # 2. Global Radix Sort
    work_items.sort(key=lambda x: x[0])

    # 3. Group sorted splats by tile
    for key, tile_id, idx in work_items:
        if tile_id not in tile_splats:
            tile_splats[tile_id] = []
        tile_splats[tile_id].append(splats[idx])

    return tile_splats
```

## Subtopics

### [Per-tile Sorting and Per-pixel Resorting](9984-per-tile-sorting-and-per-pixel-resorting.md)
Per-tile sorting and per-pixel resorting is a rasterization strategy designed to mitigate "popping" artifacts in surface-based volumetric representations (such as 2DGS and QGS) where Gaussian distributions are concentrated on surfaces. It addresses the sensitivity of alpha-blending order by replacing inconsistent per-ray depth sorting with a two-stage approach: coarse global ordering via per-tile depth approximation and fine local ordering via per-pixel resorting. This method sets itself apart from standard 3D Gaussian Splatting by enforcing strict consistency between forward rendering and backward gradient computation traversal orders, thereby eliminating streak-like and blocky artifacts introduced by single-ray approximations.

## Background
StopThePop [S1][S2, unofficial] identifies that standard 3D Gaussian Splatting cheats view-dependent effects by popping Gaussians due to per-ray depth sorting, yielding less faithful results upon viewpoint rotation [S1][S2, unofficial]. To mitigate this, StopThePop replaces per-ray sorting with tile-based sorting to enforce consistent depth ordering within local regions [S1][S2, unofficial].
