# Generalizable Pixel-Wise 3D Gaussian Splatting

Also called: G-3DG, Generalizable 3D Gaussian Splatting, Generalizable 3D-Gaussians

## Overview
Generalizable Pixel-Wise 3D Gaussian Splatting (GPS-Gaussian) is a feed-forward method for real-time novel view synthesis of humans from sparse camera views [S1]. It selects two adjacent source views, predicts pixel-wise Gaussian parameter maps (position, color, rotation, scaling, opacity) for each view, unprojects them to 3D, aggregates them, and renders the target view using differentiable Gaussian splatting [S1]. Unlike original 3D-GS which requires per-subject optimization, or implicit methods like ENeRF that recompute modules per target view, GPS-Gaussian eliminates per-subject fine-tuning and enables instant rendering by regressing Gaussian parameters directly from source images [S1].

## How it works
**Inputs:** Two rectified source RGB images $I_l, I_r \in [0, 1]^{H \times W \times 3}$, their camera projection matrices $K_l, K_r$, and the scene center $O$ [S1].
**Outputs:** A rendered image of the target novel view $I_{tar}$ [S1].

**Data Structures:**
1.  **Feature Maps:** Dense feature maps $f^s \in \mathbb{R}^{H/2^s \times W/2^s \times D_s}$ for scales $s=1,2,3$ [S1].
2.  **Correlation Volume:** $C \in \mathbb{R}^{H/2 \times W/2 \times W/2}$ [S1].
3.  **Depth Maps:** $D_l, D_r \in \mathbb{R}^{H \times W}$ [S1].
4.  **Gaussian Parameter Maps:** Defined on the image plane for each foreground pixel $x$:
    *   Position Map $M_p(x)$: 3D coordinate [S1].
    *   Color Map $M_c(x)$: RGB value [S1].
    *   Rotation Map $M_r(x)$: Normalized rotation vector [S1].
    *   Scaling Map $M_s(x)$: 2D scale vector [S1].
    *   Opacity Map $M_\alpha(x)$: Scalar [S1].
5.  **Gaussian Set $\mathcal{G}$:** The aggregated set of 3D Gaussians $\{\mu, \Sigma, \alpha, c\}$ [Parent].

**Parameters:**
*   $S=3$: Number of feature scales [S1].
*   $\beta=0.8$: Weight for L1 loss [S1].
*   $\gamma=0.2$: Weight for SSIM loss [S1].
*   $\mu=0.9$: Exponential decay weight for depth supervision [S1].
*   $T$: Number of iterative depth estimation steps [S1].
*   Initial Learning Rate: $2 \times 10^{-4}$ (AdamW) [S1].
*   Batch Size: 2 [S1].
*   Input Resolution: $1024 \times 1024$ [S1].

**Steps:**

1.  **View Selection:** Given $N$ input images with camera positions $C_n$ and scene center $O$, compute view vectors $V_n = C_n - O$. Calculate dot products between all input view vectors and the target novel view vector $V_{tar}$. Select the two nearest views $(I_l, I_r)$ as the working set [S1].

2.  **Feature Extraction:** Feed $I_l$ and $I_r$ into a shared image encoder $E_{img}$ to extract dense feature maps $f^s_l, f^s_r \in \mathbb{R}^{H/2 \times W/2 \times D_s}$ for $s=1..S$. The encoder uses residual blocks and downsampling [S1].
    $$ \langle \{f^s_l\}_{s=1}^S, \{f^s_r\}_{s=1}^S \rangle = E_{img}(I_l, I_r) $$
    where $S=3$ [S1].

3.  **Cost Volume Construction:** Compute a 3D correlation volume $C \in \mathbb{R}^{H/2 \times W/2 \times W/2}$ from the deepest feature maps $f^S_l, f^S_r$ using matrix multiplication [S1]:
    $$ C(f^S_l, f^S_r), \quad C_{ijk} = \sum_h (f^S_l)_{ijh} \cdot (f^S_r)_{ikh} $$
    [S1]

4.  **Iterative Depth Estimation:** Predict a sequence of depth estimations $\{d^t_l\}_{t=1}^T$ and $\{d^t_r\}_{t=1}^T$ by looking up in volume $C$. The final outputs $(d^T_l, d^T_r)$ are upsampled to full image resolution via convex upsampling to form $D_l, D_r$. The depth estimation module is formulated as [S1]:
    $$ \langle D_l, D_r \rangle = \Phi_{depth}(f^S_l, f^S_r, K_l, K_r) $$
    [S1]

5.  **Position Map Generation:** For each foreground pixel $x$, unproject from 2D to 3D using the predicted depth map $D(x)$ and projection matrix $P$ (derived from $K$) [S1]:
    $$ M_p(x) = \Pi^{-1}_P (x, D(x)) $$
    [S1]

6.  **Color Map Generation:** For diffuse human scenes, use the source RGB image directly as the color map [S1]:
    $$ M_c(x) = I(x) $$
    [S1]

7.  **Geometric Feature Fusion:** Construct an encoder $E_{depth}$ taking depth map $D$ as input to complement geometric awareness. Fuse image features from $E_{img}$ and spatial features from $E_{depth}$ using a U-Net like decoder $D_{parm}$ to regress Gaussian features $\Gamma \in \mathbb{R}^{H \times W \times D_G}$ [S1]:
    $$ \Gamma = D_{parm} (E_{img}(I) \oplus E_{depth}(D)) $$
    where $\oplus$ denotes concatenation at all feature levels [S1].

8.  **Scaling Map Generation:** Predict scaling $h_s(\Gamma(x))$ and apply Softplus activation [S1]:
    $$ M_s(x) = \text{Softplus}(h_s(\Gamma(x))) $$
    [S1]

9.  **Opacity Map Generation:** Predict opacity $h_\alpha(\Gamma(x))$ and apply Sigmoid activation [S1]:
    $$ M_\alpha(x) = \text{Sigmoid}(h_\alpha(\Gamma(x))) $$
    [S1]

10. **Rotation Map Generation:** Predict rotation $h_r(\Gamma(x))$ and apply normalization [S1]:
    $$ M_r(x) = \text{Norm}(h_r(\Gamma(x))) $$
    [S1]

11. **Aggregation and Rendering:** Unproject Gaussian parameter maps from both source views to 3D space using $M_p$. Aggregate the Gaussians from both views into a single set $\mathcal{G}$. Render the target viewpoint using differentiable Gaussian splatting [S1].

**Pseudocode:**

```python
def gps_gaussian_render(I_l, I_r, K_l, K_r, O, C_tar):
    # 1. View Selection
    V_l = C_l - O
    V_r = C_r - O
    V_tar = C_tar - O
    # Select two views with highest dot product with V_tar
    I_src_l, I_src_r, K_src_l, K_src_r = select_nearest_views(I_l, I_r, V_l, V_r, V_tar)
    
    # 2. Feature Extraction
    # E_img: RAFT-Stereo-like encoder with 5x5 first conv, GroupNorm
    f_l, f_r = E_img(I_src_l), E_img(I_src_r)
    # f_l, f_r are lists of feature maps at scales s=1,2,3
    # Resolution H/2, W/2; Channels 32, 48, 96
    
    # 3. Cost Volume Construction
    # Use deepest features f_l[2], f_r[2]
    C = correlation_volume(f_l[2], f_r[2])
    
    # 4. Iterative Depth Estimation
    D_l, D_r = iterative_depth_estimator(C, K_src_l, K_src_r)
    # Returns full resolution depth maps via convex upsampling
    
    # 5. Position Map Generation
    # Unproject pixel coordinates using depth and camera matrix
    M_p_l = unproject_3d(I_src_l.shape, D_l, K_src_l)
    M_p_r = unproject_3d(I_src_r.shape, D_r, K_src_r)
    
    # 6. Color Map Generation
    M_c_l = I_src_l
    M_c_r = I_src_r
    
    # 7. Geometric Feature Fusion
    # E_depth: Encoder for depth maps
    # D_parm: U-Net decoder
    Gamma_l = D_parm(concat(E_img(I_src_l), E_depth(D_l)))
    Gamma_r = D_parm(concat(E_img(I_src_r), E_depth(D_r)))
    
    # 8. Scaling Map Generation
    M_s_l = softplus(conv_layers(Gamma_l))
    M_s_r = softplus(conv_layers(Gamma_r))
    
    # 9. Opacity Map Generation
    M_alpha_l = sigmoid(conv_layers(Gamma_l))
    M_alpha_r = sigmoid(conv_layers(Gamma_r))
    
    # 10. Rotation Map Generation
    M_r_l = normalize(conv_layers(Gamma_l))
    M_r_r = normalize(conv_layers(Gamma_r))
    
    # 11. Aggregation and Rendering
    # Create Gaussian points from left view
    Gaussians_l = create_gaussians(M_p_l, M_c_l, M_r_l, M_s_l, M_alpha_l)
    # Create Gaussian points from right view
    Gaussians_r = create_gaussians(M_p_r, M_c_r, M_r_r, M_s_r, M_alpha_r)
    
    # Aggregate all Gaussians
    All_Gaussians = Gaussians_l + Gaussians_r
    
    # Render target view
    I_tar = differentiable_splatting(All_Gaussians, K_tar, C_tar)
    
    return I_tar
```

## Subtopics

### Epipolar Sampling and Cross-Attention
Used in variants like G-3DG (Li et al.) to handle pose-free or multi-view generalization by sampling features along epipolar lines and using cross-attention for correspondence [S2].

### Local Self-Attention
Used in G-3DG to propagate depth estimation to parts of the image without epipolar correspondences by splitting features into patches [S2].

## Operating characteristics
**Time Complexity:** The source view computation (depth estimation and Gaussian parameter map regression) dominates the run-time [S1]. Novel view rendering is extremely fast [S1].
**Memory Complexity:** Requires storing feature maps, correlation volume, and Gaussian parameters for two source views [S1].
**Measured Performance:** On an RTX 3090 GPU with $1024 \times 1024$ source images, the source view computation takes 14 ms, and novel view rendering takes 0.8 ms per view [S1]. For 10 concurrent novel views, total time is 35 ms [S1].
**Scaling:** Allows concurrent rendering of multiple novel views because the expensive source view processing is decoupled from the target view [S1].
**Strengths:** Real-time performance (2K resolution > 25 FPS), no per-subject optimization, handles sparse views [S1].
**Limitations:** Performance depends on the quality of depth estimation; occlusions can cause depth ambiguity, though human priors help mitigate this [S1]. Unstable depth estimation in early training impacts regression [S1].
**When to use:** Real-time human novel view synthesis from sparse views [S1].
**When not to use:** Scenes with non-diffuse reflections (uses RGB directly for color) or when per-scene optimization is acceptable for higher quality [S1].

## Background
GPS-Gaussian was introduced by Zheng et al. in 2024 [S1]. It is trained on a large dataset of human scans (1700 from Twindom, 526 from THuman2.0) [S1]. The method addresses the limitations of original 3D-GS (slow optimization, noisy in sparse views) and implicit methods (slow rendering, recomputation per view) [S1]. It uses a joint training strategy with depth estimation, pre-training the depth module for 40k iterations before joint training for 100k iterations [S1].
