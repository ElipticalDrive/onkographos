# Average Contribution Criterion

Also called: Ours

## Overview
The Average Contribution Criterion is a densification strategy for 3D Gaussian Splatting that determines whether a Gaussian should be split or cloned based on its mean blending weight per view rather than a binary view count [S1, unofficial]. It solves the problem of occlusion bias inherent in the original 3D Gaussian Splatting criterion, where fully occluded views inflate the denominator and dilute the gradient signal, leading to inefficient densification [S1, unofficial]. It sets itself apart from siblings like [Multi-View Density Control Criterion](5663-multi-view-density-control-criterion.md) by intrinsically weighting views by their actual contribution, preventing occluded views from biasing the average downward without requiring external guard rails like distance scaling [S1, unofficial].

## How it works
**Inputs:**
*   A set of 3D Gaussians, each with a screen-space mean $\mu_i$ and covariance.
*   Training loss $L$ and its gradients with respect to $\mu_i$ for each view $v$ where the Gaussian contributes.
*   Blending weights $w_{i,p}$ for each pixel $p$ in each view $v$.

**Outputs:**
*   A scalar densification score $\gamma_i^{\text{Ours}}$ for each Gaussian $i$.
*   A boolean decision: split/clone if $\gamma_i^{\text{Ours}} > \tau$, otherwise keep.

**Data Structures:**
*   Per-Gaussian accumulator for the sum of gradient magnitudes: `sum_grad_mag` (float).
*   Per-Gaussian accumulator for the sum of mean blending weights: `sum_mean_w` (float).
*   Per-view temporary storage for gradient vector $g_{i,v}$ and mean blending weight $\bar{w}_{i,v}$.

**Parameters:**
*   Densification threshold $\tau = 0.002$ [S1, unofficial].
*   Denominator floor constant $C = 1$ [S1, unofficial].

**Steps:**
1.  For each Gaussian $i$ observed in $M$ views:
    a. Initialize `sum_grad_mag` = 0 and `sum_mean_w` = 0.
    b. For each view $v$ where Gaussian $i$ contributes to at least one pixel:
        i. Compute the per-view gradient vector $g_{i,v}$:
           $$g_{i,v} = \sum_{p \in \text{pixels in } v} w_{i,p} s_{i,p}$$
           where $s_{i,p}$ is a weight-independent vector combining photometric residual, geometric steering, and local contrast [S1, unofficial].
        ii. Compute the mean blending weight $\bar{w}_{i,v}$:
            $$\bar{w}_{i,v} = \frac{1}{N_{i,v}} \sum_{p \in \text{pixels in } v} w_{i,p}$$
            where $N_{i,v}$ is the number of pixels in view $v$ where Gaussian $i$ contributes, and $w_{i,p} = \alpha_{i,p} T_{i,p}$ is the blending weight [S1, unofficial].
        iii. Add $\|g_{i,v}\|$ to `sum_grad_mag`.
        iv. Add $\bar{w}_{i,v}$ to `sum_mean_w`.
    c. Compute the criterion score:
       $$\gamma_i^{\text{Ours}} = \frac{\text{sum\_grad\_mag}}{1 + \text{sum\_mean\_w}}$$
    d. If $\gamma_i^{\text{Ours}} > 0.002$, mark Gaussian $i$ for densification (split or clone) [S1, unofficial].

**Pseudocode:**
```python
def compute_average_contribution_criterion(gaussians, views, loss_gradients):
    """
    Computes the average contribution criterion score for each Gaussian.
    
    Args:
        gaussians: List of Gaussian objects, each with attributes:
            - id: Unique identifier
            - mu: Screen-space mean (2D vector)
            - views_observed: List of view indices where this Gaussian contributes
        views: List of View objects, each with attributes:
            - id: Unique identifier
            - pixels: List of Pixel objects where this Gaussian contributes
        loss_gradients: Dict mapping (gaussian_id, view_id) to gradient vector g_i,v
            
    Returns:
        Dict mapping gaussian_id to criterion score gamma_i
    """
    scores = {}
    
    for g in gaussians:
        sum_grad_mag = 0.0
        sum_mean_w = 0.0
        
        for v_id in g.views_observed:
            # Get pixels where this Gaussian contributes in this view
            contributing_pixels = [p for p in views[v_id].pixels if p.gaussian_id == g.id]
            N_i_v = len(contributing_pixels)
            
            if N_i_v == 0:
                continue
                
            # Step 1: Compute mean blending weight w_bar_i,v
            sum_w = 0.0
            for p in contributing_pixels:
                # w_i,p = alpha_i,p * T_i,p
                w_i_p = p.alpha * p.transmittance
                sum_w += w_i_p
            w_bar_i_v = sum_w / N_i_v
            
            # Step 2: Get gradient magnitude ||g_i,v||
            # g_i,v is pre-computed and stored in loss_gradients
            g_i_v = loss_gradients[(g.id, v_id)]
            grad_mag = vector_norm(g_i_v)
            
            # Accumulate
            sum_grad_mag += grad_mag
            sum_mean_w += w_bar_i_v
            
        # Step 3: Compute final score with floor constant 1
        denominator = 1.0 + sum_mean_w
        gamma = sum_grad_mag / denominator
        
        scores[g.id] = gamma
        
    return scores

def densify_gaussians(scores, threshold=0.002):
    """
    Marks Gaussians for densification based on the criterion score.
    
    Args:
        scores: Dict mapping gaussian_id to criterion score
        threshold: Densification threshold (default 0.002)
        
    Returns:
        List of gaussian_ids to densify
    """
    to_densify = []
    for g_id, gamma in scores.items():
        if gamma > threshold:
            to_densify.append(g_id)
    return to_densify
```

**Edge Cases and Pitfalls:**
*   **Denominator Floor:** The constant 1 in the denominator is critical. Without it, rarely observed Gaussians (where $\sum_v \bar{w}_{i,v} \to 0$) would receive unbounded scores, causing training divergence [S1, unofficial].
*   **Occlusion Handling:** The criterion is occlusion-aware because $\bar{w}_{i,v}$ includes transmittance $T_{i,p}$. A view where the Gaussian is mostly occluded ($T_{i,p} \to 0$) will have a low $\bar{w}_{i,v}$, reducing its impact on the denominator and preventing dilution of the gradient signal [S1, unofficial].
*   **Threshold Calibration:** The threshold 0.002 was calibrated on the Mip-NeRF360 calibration subset (bicycle, bonsai, counter, garden) and kept fixed for all experiments [S1, unofficial]. Deviations (e.g., 0.001) lead to over-densification and lower PSNR, while higher thresholds (e.g., 0.004) lead to under-densification and higher LPIPS [S1, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
*   The criterion requires computing per-pixel blending weights and gradients for each Gaussian in each observed view. This is $O(\sum_{i} \sum_{v} N_{i,v})$, where $N_{i,v}$ is the number of pixels Gaussian $i$ contributes to in view $v$. This is comparable to the original 3D Gaussian Splatting densification cost, as it reuses existing rasterization outputs [S1, unofficial].
*   Memory overhead is minimal, requiring only per-Gaussian accumulators for `sum_grad_mag` and `sum_mean_w` [S1, unofficial].

**Measured Performance:**
*   On Zip-NeRF scenes (30k iterations): 25.81 PSNR, 0.830 SSIM, 0.330 LPIPS, 0.106 GMSD, using 1.133 million Gaussians in 29.9 minutes [S1, unofficial].
*   On Zip-NeRF scenes (210k iterations): 26.60 PSNR, 0.852 SSIM, 0.282 LPIPS, 0.087 GMSD, using 2.495 million Gaussians in 262.9 minutes [S1, unofficial].
*   On Zip-NeRF scenes (300k iterations): Gaussian count stays bounded at 2.75M while continuing to improve in LPIPS and GMSD [S1, unofficial].
*   On Deep Blending dataset (Reset variant): 29.90 PSNR, 0.902 SSIM, 0.231 LPIPS using 1.656M Gaussians [S1, unofficial].
*   On Deep Blending dataset (Decay variant): 30.03 PSNR, 0.905 SSIM, 0.234 LPIPS using 0.894M Gaussians [S1, unofficial].

**Scaling:**
*   The method is intrinsically self-limiting and does not require distance scaling guard rails, making it stable on large scenes like Zip-NeRF where other criteria (e.g., PixelGS without distance scaling) diverge or overdensify past the ~16.8M trainable-count limit [S1, unofficial].
*   It produces the fewest Gaussians (roughly 55–75% of other criteria's counts) at matched quality [S1, unofficial].

**Strengths and Limitations:**
*   **Strengths:** Occlusion-aware, self-limiting, no distance scaling dependency, efficient (fewer Gaussians), stable on large scenes [S1, unofficial].
*   **Limitations:** Requires calibration of the threshold (though once calibrated, it is fixed across scenes) [S1, unofficial]. Performance on very small scenes may be similar to other criteria, as the main advantage is in occlusion-heavy or large scenes [S1, unofficial].

**When to Use:**
*   Use when occlusion is significant (e.g., Zip-NeRF scenes) [S1, unofficial].
*   Use when memory or training time is constrained, as it produces fewer Gaussians [S1, unofficial].
*   Use when stability on large scenes is a concern [S1, unofficial].

**When Not to Use:**
*   If the scene has minimal occlusion and is small, the benefit may be marginal compared to simpler criteria [S1, unofficial].
*   If the threshold needs to be scene-specific and cannot be fixed, the calibration overhead may not be justified [S1, unofficial].

## Background
The Average Contribution Criterion was introduced in "Counting Contributions, Not Views: Occlusion-Aware Densification for 3D Gaussian Splatting" [S1, unofficial]. It addresses limitations in the original 3D Gaussian Splatting densification criterion, which weights every view equally regardless of visibility, leading to bias from occluded views [S1, unofficial]. The method was developed to improve densification efficiency and stability, particularly in occlusion-heavy and large-scale scenes [S1, unofficial]. It is used in modern 3D Gaussian Splatting implementations to achieve better quality with fewer Gaussians [S1, unofficial].
