# Bézier Gaussian Triangle

Also called: BG-Triangle

## Overview
The Bézier Gaussian Triangle (BG-Triangle) is a hybrid 3D primitive representation that combines Bézier triangle surfaces for explicit geometry with 3D Gaussian sub-primitives for appearance, enabling differentiable rendering with sharp boundaries [S1]. It solves the problem of blurry or aliased edges common in pure Gaussian splatting by defining the object's silhouette and surface topology via parametric Bézier patches, while using Gaussians only for shading and color [S1]. Unlike standard 3D Gaussian Splatting, which relies on the overlap of many opaque Gaussians to form shapes, BG-Triangle maintains distinct, sharp boundaries between primitives, making it particularly suitable for vectorization and compact scene representation [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of Bézier Gaussian Triangle primitives. Each primitive is defined by a degree $n$, a set of 3D control points $\mathbf{p}_{i,j,k}$, color control points $\mathbf{p}_{i,j,k}^c$, and multi-resolution attribute maps $M_h$ for rotation, scaling, and Spherical Harmonic (SH) coefficients [S1].
*   **Output:** A rendered 2D image with photometric accuracy and sharp geometric boundaries [S1].

**Data Structures:**
*   **Primitive Index Map ($I_{id}$):** $\mathbb{Z}^{H \times W}$, storing the index of the primitive covering each pixel [S1].
*   **Barycentric Coordinate Map ($I_{uv}$):** $\mathbb{R}^{H \times W \times 3}$, storing the barycentric coordinates $(u, v, w)$ for each pixel relative to its covering primitive [S1].
*   **Boundary Point Set ($B$):** A 2D set of pixel coordinates identified as boundary pixels (pixels with neighbors having different $I_{id}$ values) [S1].
*   **Attribute Maps ($M_h$):** 2D textures storing rotation, scaling, and SH coefficients for each primitive, sampled based on barycentric coordinates [S1].

**Numbered Steps:**

1.  **Tessellation and Rasterization:**
    The non-linear Bézier triangle surface is tessellated into smaller flat triangles to align with the pixel grid [S1]. The vertices of these flat triangles inherit the primitive ID and barycentric coordinates [S1]. A traditional rasterization pipeline with depth testing is used to render these flat triangles, generating the coordinate map $I_{uv}$ and index map $I_{id}$ [S1].

2.  **Boundary Detection:**
    Pixels are marked as boundary pixels if they have neighboring pixels assigned to different primitive IDs [S1]. These pixels are stored in the 2D boundary point set $B$ [S1].

3.  **3D Coordinate Computation:**
    For each foreground pixel $q$, the 3D position $\mathbf{S}_q$ on the Bézier triangle is computed using the retrieved primitive index $I_{id}(q)$ and barycentric coordinates $I_{uv}(q)$:
    $$
    \mathbf{S}_{\mathbf{q}}(\mathbf{I}_{uv}(\mathbf{q}), \mathbf{I}_{id}(\mathbf{q})) = \sum_{i = 0}^{n} \sum_{j = 0}^{n - i} B_{i, j, k}^{n}(\mathbf{I}_{uv}(\mathbf{q})) \mathbf{p}_{i, j, k}(\mathbf{I}_{id}(\mathbf{q}))
    $$
    where $B_{i, j, k}^{n}$ is the Bernstein polynomial [S1].

4.  **Sub-Primitive Generation:**
    At each computed 3D coordinate $\{\mathbf{S}_q\}$, a 3D Gaussian sub-primitive is generated on the fly [S1]. These Gaussians possess rotation, scaling, and SH coefficients but **no opacity**, as the geometry is defined by the Bézier triangles [S1].

5.  **Attribute Interpolation:**
    *   **Diffuse Color:** Interpolated using barycentric interpolation of color control points $\mathbf{p}_{i, j, k}^c$:
        $$
        \mathbf{c}_{\mathbf{q}}(\mathbf{I}_{uv}(\mathbf{q}), \mathbf{I}_{id}(\mathbf{q})) = \sum_{i = 0}^{n} \sum_{j = 0}^{n - i} B_{i, j, k}^{n}(\mathbf{I}_{uv}(\mathbf{q})) \mathbf{p}_{i, j, k}^{c}(\mathbf{I}_{id}(\mathbf{q}))
        $$
    *   **Other Attributes:** Rotation, scaling, and SH coefficients are interpolated using a multi-resolution 2D attribute map $M_h$ based on barycentric coordinates via a texture interpolation function $\Theta$:
        $$
        \mathbf{a}_h(\mathbf{q}) = \Theta(\mathbf{M}_h(\mathbf{I}_{id}(\mathbf{q})), \mathbf{I}_{uv}(\mathbf{q}))
        $$
        where $h \in \{\text{rotation, scaling, SH coefficients}\}$ [S1].

6.  **Boundary Softening (Discontinuity-Aware Rendering):**
    To handle sharp boundaries without artifacts, the influence of boundary points is softened [S1]:
    *   Each boundary point $b_i \in B$ is treated as an isotropic Gaussian with a fixed scaling factor $r_b$ [S1].
    *   The projected boundary radius $\sigma_i$ is computed for each boundary Gaussian [S1].
    *   The blending coefficient $w(q)$ for a pixel $q$ covered by a splatted Gaussian $G$ is determined by its relation to boundary points $b_i$:
        $$
        w(\mathbf{q}) = \begin{cases} 
        0, & \text{if } \mathbf{I}_{id}(\mathbf{b}_{i}) \neq \mathbf{I}_{id}(\mathbf{q}), \\
        \gamma(\|\mathbf{q} - \mathbf{b}_{i}\|_{2}; \sigma_i), & \text{if } \mathbf{I}_{id}(\mathbf{b}_{i}) = \mathbf{I}_{id}(\mathbf{q}), \\
        1 - \gamma(\|\mathbf{q} - \mathbf{b}_{i}\|_{2}; \sigma_i), & \text{otherwise},
        \end{cases}
        $$
        where $\gamma(d; \sigma) = \min \left( 2^{\frac{d}{\sigma} - 1}, 1 \right)$ [S1].
    *   The alpha value $\alpha(q)$ is computed using $w(q)$ and the Gaussian projection, where $o$ is a constant close to 1.0 to aid optimization [S1].

7.  **Rendering:**
    Point-based alpha blending is applied to obtain the final pixel color [S1].

8.  **Training (Backward Pass):**
    Derivatives of the control points are computed using the chain rule, leveraging the differentiability of the coordinate interpolation and the blending weight [S1]. The photometric loss combines L2 loss and D-SSIM:
    $$
    \mathcal{L} = (1 - \lambda)\mathcal{L}_{2} + \lambda \mathcal{L}_{\text{D-SSIM}}
    $$
    where $\lambda = 0.2$ [S1].

**Pseudocode:**

```python
import math
import numpy as np

def bernstein_polynomial(i, j, k, n, u, v, w):
    """Computes B_{i,j,k}^n(u,v,w) = n!/(i!j!k!) * u^i v^j w^k [S1]"""
    coeff = math.factorial(n) / (math.factorial(i) * math.factorial(j) * math.factorial(k))
    return coeff * (u ** i) * (v ** j) * (w ** k)

def compute_bezier_point(control_points, n, u, v, w):
    """Computes S(u,v,w) on a Bézier triangle [S1]"""
    position = np.zeros(3)
    for i in range(n + 1):
        for j in range(n - i + 1):
            k = n - i - j
            p = control_points[i][j][k]
            b = bernstein_polynomial(i, j, k, n, u, v, w)
            position += b * p
    return position

def gamma_function(d, sigma):
    """Computes gamma(d; sigma) = min(2^(d/sigma - 1), 1) [S1]"""
    if sigma <= 0:
        return 1.0
    return min(2 ** ((d / sigma) - 1), 1.0)

def compute_blending_weight(q_pos, b_i_pos, q_prim_id, b_i_prim_id, sigma_i):
    """Computes w(q) based on relation to boundary point b_i [S1]"""
    dist = np.linalg.norm(q_pos - b_i_pos)
    if b_i_prim_id != q_prim_id:
        return 0.0
    elif b_i_prim_id == q_prim_id:
        return gamma_function(dist, sigma_i)
    else:
        return 1.0 - gamma_function(dist, sigma_i)

def texture_lookup(attr_map, u, v):
    """Standard 2D bilinear texture interpolation [G]"""
    h, w = attr_map.shape[:2]
    u_idx = min(max(int(u * (w - 1)), 0), w - 2)
    v_idx = min(max(int(v * (h - 1)), 0), h - 2)
    u_frac = u * (w - 1) - u_idx
    v_frac = v * (h - 1) - v_idx
    top = attr_map[v_idx, u_idx] * (1 - u_frac) + attr_map[v_idx, u_idx + 1] * u_frac
    bottom = attr_map[v_idx + 1, u_idx] * (1 - u_frac) + attr_map[v_idx + 1, u_idx + 1] * u_frac
    return top * (1 - v_frac) + bottom * v_frac

def project_gaussian_2d(mean_3d, rotation_quat, scaling_vec, view_matrix, proj_jacobian):
    """Standard 2D projection of a 3D Gaussian via covariance transform [G]"""
    # Covariance in world space: Sigma_w = R S S^T R^T
    # Transformed covariance: Sigma = J W Sigma_w W^T J^T
    # Returns 2D mean and covariance matrix
    # Implementation follows standard 3DGS projection pipeline [G]

def render_bg_triangle(primitives, I_id, I_uv, B, image_height, image_width, camera_params):
    """Main rendering loop for BG-Triangle [S1]"""
    final_color = np.zeros((image_height, image_width, 3))
    o = 1.0  # Constant close to 1.0 [S1]

    for y in range(image_height):
        for x in range(image_width):
            q = np.array([x, y])
            prim_id = I_id[y, x]
            uv = I_uv[y, x]
            u, v, w = uv[0], uv[1], uv[2]

            prim = primitives[prim_id]
            control_points = prim['control_points']
            color_control_points = prim['color_control_points']
            attr_maps = prim['attr_maps']

            # 1. Compute 3D position
            S_q = compute_bezier_point(control_points, prim['degree'], u, v, w)

            # 2. Interpolate attributes
            c_q = compute_bezier_point(color_control_points, prim['degree'], u, v, w)
            rotation = texture_lookup(attr_maps['rotation'], u, v)
            scaling = texture_lookup(attr_maps['scaling'], u, v)
            sh_coeffs = texture_lookup(attr_maps['sh'], u, v)

            # 3. Project Gaussian to 2D
            mu_2d, sigma_2d = project_gaussian_2d(S_q, rotation, scaling, camera_params['view'], camera_params['jacobian'])

            # 4. Compute Gaussian contribution
            diff = q - mu_2d
            inv_sigma = np.linalg.inv(sigma_2d)
            dist_sq = diff @ inv_sigma @ diff
            gaussian_val = np.exp(-0.5 * dist_sq)

            # 5. Boundary softening
            w_q = 1.0
            for b_pos, b_id, sigma_i in B:
                w_q *= compute_blending_weight(q, b_pos, prim_id, b_id, sigma_i)

            # 6. Alpha blending
            alpha = gaussian_val * w_q * o
            final_color[y, x] += c_q * alpha

    return final_color
```

**Parameters:**
*   $\lambda$: Weight for D-SSIM term in loss function, set to 0.2 [S1].
*   $r_b$: Fixed scaling factor for isotropic Gaussian treatment of boundary points [S1].
*   $o$: Constant number close to 1.0 used to help optimization in alpha blending [S1].

**Edge Cases and Pitfalls:**
*   **Tessellation Density:** The tessellation of the Bézier triangle must be fine enough to approximate the curved surface without introducing visible artifacts, but coarse enough to maintain performance [S1].
*   **Boundary Artifacts:** Incorrect handling of boundary pixels can lead to gaps or overlaps between primitives [S1]. The discontinuity-aware rendering is crucial for sharp edges [S1].
*   **Gradient Computation:** The differentiability of the Bézier surface and the blending function is essential for training [S1].

## Subtopics

### Splitting and Pruning Scheme for Bézier Gaussian Triangles
A scheme to manage primitive count and quality by splitting under-reconstructed primitives and pruning ineffective ones to improve training efficiency and rendering clarity [S1].
*   **Splitting Criteria:** Primitives are split if: (1) the average gradient norm of their control points exceeds threshold $\tau_g$, indicating under-reconstructed geometry; or (2) the accumulated edge gradients, back-projected from edge detection on training images, exceed threshold $\tau_b$ [S1].
*   **Pruning Criteria:** Primitives are pruned based on: (1) visibility (percentage of training views in which the primitive is visible); (2) area; and (3) aspect ratio [S1].
*   **Parameters:** $\tau_g$ (threshold for average gradient norm), $\tau_b$ (threshold for accumulated edge gradients) [S1].

## Operating characteristics
*   **Time Complexity:** Rendering involves tessellation, rasterization, and per-pixel Gaussian splatting [S1]. The tessellation step is offline or pre-computed [S1]. The rasterization and splatting are similar in complexity to standard 3D Gaussian Splatting, but with additional overhead for boundary detection and attribute interpolation from Bézier control points [S1].
*   **Memory Complexity:** Memory usage is dominated by the storage of control points, color control points, and multi-resolution attribute maps for each primitive [S1]. The approach maintains a compact parameter count compared to purely Gaussian-based models [S1].
*   **Strengths:** Sharp boundaries, differentiable rendering, compact representation, suitability for vectorization [S1].
*   **Limitations:** Complexity of implementation due to hybrid nature (Bézier + Gaussian), sensitivity to tessellation density, potential artifacts at boundaries if not handled correctly [S1].
*   **When to Use:** When sharp geometric boundaries are required, or when a compact representation of complex surfaces is needed [S1].
*   **When Not to Use:** For scenes with highly complex, non-parametric geometry that cannot be well-approximated by Bézier triangles, or when real-time performance is critical and the overhead of tessellation and boundary handling is unacceptable [S1].

## Background
The Bézier Gaussian Triangle (BG-Triangle) was introduced in the paper "BG-Triangle: Bézier Gaussian Triangle for 3D Vectorization and Rendering" [S1]. It builds upon the principles of 3D Gaussian Splatting and Bézier surfaces, aiming to combine the differentiable rendering capabilities of Gaussians with the explicit geometric control of Bézier patches [S1]. The method addresses the limitations of pure Gaussian splatting in representing sharp edges and compact geometry [S1].
