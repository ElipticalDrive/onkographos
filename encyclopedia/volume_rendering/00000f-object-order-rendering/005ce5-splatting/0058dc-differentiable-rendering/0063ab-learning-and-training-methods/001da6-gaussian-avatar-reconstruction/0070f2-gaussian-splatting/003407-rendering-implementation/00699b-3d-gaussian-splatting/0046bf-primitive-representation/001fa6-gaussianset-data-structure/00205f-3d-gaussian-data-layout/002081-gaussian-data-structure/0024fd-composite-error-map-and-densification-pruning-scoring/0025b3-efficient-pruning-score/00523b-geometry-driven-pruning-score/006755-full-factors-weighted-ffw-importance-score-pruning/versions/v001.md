# Full Factors Weighted (FFW) Importance Score Pruning

Also called: MiniGS Pruning, Scorev4

## Overview
Full Factors Weighted (FFW) Importance Score Pruning is a method for selectively removing less important 3D Gaussian primitives during the training of Gaussian Splatting models to reduce memory footprint and rendering latency while preserving visual fidelity [S1]. It addresses the limitation of vanilla 3DGS pruning, which relies solely on opacity and transparency, by incorporating position, color similarity, and opacity into a single importance score [S1]. Unlike its sibling [PointSplat](14667-pointsplat.md), which focuses on point-based approximations, FFW operates directly on the Gaussian primitives using a comprehensive factor analysis aligned with the alpha-blending rendering equation [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $N$ 3D Gaussians $\{G_i\}$, the current camera view (defined by ray $r$ and pixel coordinate $X_r$), the rendered pixel color $c_r$, and the Gaussian parameters (position $X_i$, view-dependent color $c_i$, opacity $\alpha_i$, transparency $T_i$).
*   **Output:** A ranked list of Gaussians and a binary mask indicating which Gaussians to prune (remove) from the scene representation.

**Data Structures:**
The method operates on the standard 3D Gaussian data layout defined in [Gaussian Data Structure](14647-gaussian-data-structure.md). Each Gaussian $G_i$ stores:
*   $X_i \in \mathbb{R}^3$: Center position.
*   $c_i \in \mathbb{R}^3$: View-dependent color (computed from Spherical Harmonics coefficients).
*   $\alpha_i \in [0, 1]$: Intrinsic opacity.
*   $T_i \in [0, 1]$: Blending transparency, calculated during rasterization as $T_i = \prod_{j=1}^{i-1} (1 - \alpha_j)$, where $j$ iterates over Gaussians sorted by depth [S1].
*   $\Sigma \in \mathbb{R}^{3 \times 3}$: 3D covariance matrix.

**Step-by-Step Procedure:**

1.  **Project Covariance (Optional Context):**
    To determine the 2D extent of the Gaussian for rasterization, the 3D covariance matrix $\Sigma$ is projected to the 2D image plane using the world-to-camera projective transform matrix $W$ and the Jacobian $J$ of the projective transform [S1]:
    $$ \Sigma' = J W \Sigma W^T J^T $$
    This step is part of the rendering pipeline that generates the intermediate values ($T_i$) used in the score [S1].

2.  **Compute Importance Score:**
    For each Gaussian $G_i$ contributing to the pixel color $c_r$ along ray $r$, calculate the importance score $S(G_i, r)$ using the Scorev4 formula [S1]:
    $$ S(G_i, r) = (1 - \text{mean}(c_r - c_i)) \cdot \exp(-\|X_r - X_i\|^2) \cdot \alpha_i \cdot T_i $$
    Where:
    *   $c_r$ is the final rendered color of the pixel.
    *   $c_i$ is the view-dependent color of the Gaussian $G_i$.
    *   $\text{mean}(c_r - c_i)$ is the mean absolute difference (or Euclidean distance normalized) between the rendered pixel color and the Gaussian's color. The source uses `mean(cr - ci)` [S1].
    *   $X_r$ is the 2D pixel coordinate of the ray.
    *   $X_i$ is the 3D center position of the Gaussian. The term $\|X_r - X_i\|^2$ represents the squared Euclidean distance between the pixel center and the Gaussian center in the projected space (or 3D space if $X_r$ is treated as a 3D point on the ray, but typically implies spatial proximity in the image plane context for weighting) [S1]. *Note: The source formula explicitly writes $\exp(-\|X_r - X_i\|^2)$ [S1].*
    *   $\alpha_i$ is the blending opacity.
    *   $T_i$ is the transparency (accumulated alpha from previous Gaussians).

3.  **Rank and Prune:**
    *   Aggregate the scores for each Gaussian across all pixels it contributes to, or use the maximum/average score depending on the specific implementation variant (the source implies a global ranking based on the computed importance) [S1].
    *   Rank all Gaussians by their importance score in ascending order.
    *   Remove the Gaussians with the lowest scores until the target number of primitives $K$ is reached [S1].

**Pseudocode:**

```python
def compute_ffw_score(gaussian, pixel_color, pixel_coord, gaussian_color, gaussian_center, opacity, transparency):
    """
    Computes the FFW (Scorev4) importance score for a single Gaussian contribution.
    
    Args:
        gaussian: Object containing Gaussian attributes.
        pixel_color (vec3): Rendered color of the pixel.
        pixel_coord (vec2): 2D coordinate of the pixel.
        gaussian_color (vec3): View-dependent color of the Gaussian.
        gaussian_center (vec3): 3D center of the Gaussian.
        opacity (float): Blending opacity alpha_i.
        transparency (float): Transparency T_i.
        
    Returns:
        float: Importance score.
    """
    # Calculate color similarity factor: (1 - mean(color difference))
    # Note: 'mean' typically refers to the mean across RGB channels for the difference vector
    color_diff = pixel_color - gaussian_color
    color_similarity = 1.0 - np.mean(color_diff)
    
    # Calculate spatial proximity factor: exp(-squared distance)
    # Distance between pixel coordinate and Gaussian center.
    # In practice, X_r is 2D and X_i is 3D. The source formula uses ||X_r - X_i||^2.
    # This implies projecting X_i to 2D or treating X_r as a 3D point.
    # Assuming standard implementation where spatial proximity is in image space:
    # We assume gaussian_center is projected to 2D or X_r is extended.
    # For strict adherence to source formula notation:
    spatial_dist_sq = np.sum((pixel_coord - gaussian_center[:2])**2) # Assuming projection or 2D match
    # If 3D distance is intended, use full vector. Source notation ||X_r - X_i||^2 is ambiguous 
    # regarding dimensionality but implies Euclidean distance.
    # Given X_r is pixel coordinate (2D) and X_i is 3D, we project X_i to 2D for distance.
    spatial_factor = np.exp(-spatial_dist_sq)
    
    # Combine factors
    score = color_similarity * spatial_factor * opacity * transparency
    
    return score

def prune_gaussians(gaussians, render_data, target_count):
    """
    Prunes Gaussians using FFW importance scores.
    
    Args:
        gaussians: List of Gaussian objects.
        render_data: Dictionary containing rendered pixel colors, coordinates, and Gaussian contributions.
        target_count: Integer, number of Gaussians to keep.
        
    Returns:
        List of Gaussian objects: The pruned set.
    """
    scores = []
    
    for i, g in enumerate(gaussians):
        # Aggregate score across all pixels where this Gaussian contributes
        # Or use a representative score. The source implies a global ranking.
        # We sum or average the scores from all contributing pixels.
        pixel_scores = []
        for pixel in render_data.contributing_pixels[i]:
            score = compute_ffw_score(
                gaussian=g,
                pixel_color=pixel.color,
                pixel_coord=pixel.coord,
                gaussian_color=g.color,
                gaussian_center=g.center,
                opacity=g.opacity,
                transparency=g.transparency
            )
            pixel_scores.append(score)
        
        # Aggregate: Mean score across contributing pixels
        if pixel_scores:
            avg_score = np.mean(pixel_scores)
        else:
            avg_score = 0.0
            
        scores.append((i, avg_score))
    
    # Sort by score ascending (lowest importance first)
    scores.sort(key=lambda x: x[1])
    
    # Determine how many to prune
    num_to_prune = len(gaussians) - target_count
    if num_to_prune <= 0:
        return gaussians
        
    # Indices to remove
    indices_to_remove = set([idx for idx, _ in scores[:num_to_prune]])
    
    # Return pruned list
    return [g for i, g in enumerate(gaussians) if i not in indices_to_remove]
```

**Parameters:**
*   **Target Primitive Count ($K$):** The desired number of Gaussians after pruning. Typical values depend on the scene complexity and hardware constraints. The source reports results for $K \approx 400k$ on Mip-NeRF360, $230k$ on Tanks&Temples, and $250k$ on DeepBlending [S1].
*   **Color Difference Metric:** The source uses `mean(cr - ci)` [S1]. This is typically the mean absolute difference across RGB channels.

**Edge Cases and Pitfalls:**
*   **Color Similarity Negative Values:** If `mean(cr - ci)` exceeds 1, the color similarity factor becomes negative. In standard RGB space with normalized values [0,1], the maximum difference is 1.0, so the factor ranges [0, 1]. Ensure inputs are normalized [S1].
*   **Spatial Distance Dimensionality:** The formula $\|X_r - X_i\|^2$ mixes 2D pixel coordinates and 3D Gaussian centers. Implementers must ensure consistent dimensionality, typically by projecting the Gaussian center to the 2D image plane before computing distance [S1].
*   **Transparency Zero:** If $T_i = 0$ (fully occluded by previous Gaussians), the score becomes 0. This correctly identifies the Gaussian as having no visual contribution in the current view, but care must be taken not to prune Gaussians that might become visible in other views [S1].

## Operating characteristics
*   **Time Complexity:** The pruning step requires computing the score for each Gaussian-pixel pair, which is $O(N \cdot P)$ where $N$ is the number of Gaussians and $P$ is the number of pixels they contribute to. Sorting is $O(N \log N)$. This is significantly cheaper than ray-pixel intersection methods used in [Geometry-Driven Pruning Score](14647-geometry-driven-pruning-score.md) siblings that require explicit intersection tests.
*   **Memory Complexity:** $O(N)$ to store the scores. No additional large data structures are required beyond the existing Gaussian attributes.
*   **Measured Performance:**
    *   **Mip-NeRF360:** SSIM 0.798, PSNR 27.10, LPIPS 0.242 with 402.2k primitives [S1].
    *   **Tanks&Temples:** SSIM 0.828, PSNR 23.11, LPIPS 0.207 with 230.7k primitives [S1].
    *   **DeepBlending:** SSIM 0.897, PSNR 25.87, LPIPS 0.316 with 250.7k primitives [S1].
*   **Strengths:** Incorporates color and position information, preventing the removal of visually important Gaussians that have low opacity. Outperforms vanilla opacity-only pruning (Scorevanilla) and other variants (Scorev1-v3) in quantitative metrics [S1].
*   **Limitations:** Requires access to rendered pixel colors and intermediate blending values ($T_i$), which must be stored or recomputed during the pruning phase.

## Background
The Full Factors Weighted (FFW) Importance Score Pruning, also known as Scorev4, was introduced in the MiniGS method [S1]. MiniGS aims to provide an efficient 3D Gaussian splatting pipeline by combining FFW pruning with a Variational Densify Threshold (VDT) module [S1]. The method was developed to address the inefficiency of vanilla 3DGS pruning, which fails to account for color and spatial contributions, leading to suboptimal pruning decisions [S1]. The approach was evaluated on standard NeRF benchmarks (Mip-NeRF360, Tanks&Temples, DeepBlending) using a single NVIDIA H100 GPU [S1].
