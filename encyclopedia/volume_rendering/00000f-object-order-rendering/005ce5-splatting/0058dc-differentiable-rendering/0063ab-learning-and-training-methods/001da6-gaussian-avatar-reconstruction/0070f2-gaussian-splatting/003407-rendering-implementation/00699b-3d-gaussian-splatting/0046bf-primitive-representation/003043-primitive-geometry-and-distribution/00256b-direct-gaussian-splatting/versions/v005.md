# Direct Gaussian Splatting

Also called: dGS, direct conditional parameterization for Gaussian kernel

## Overview
Direct Gaussian Splatting (dGS) is a rendering method for N-dimensional splatting that replaces the covariance-derived conditioning step of standard N-DGS with explicit per-primitive parameters [S1, unofficial]. It solves the problem of expensive per-primitive matrix inversions and regression products required to recover conditional mean, opacity, and covariance in every forward pass [S1, unofficial]. Unlike N-DGS, which tightly couples position and opacity through shared covariance blocks, dGS decouples these effects using a Cholesky precision factor for opacity and a factorized query-to-position regression operator [S1, unofficial]. This allows for efficient view-dependent and dynamic effects modeling without the computational overhead of matrix inversion [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:**
    *   Primitive attributes: Base opacity $\alpha$, base position $\boldsymbol{\mu}_p$, canonical query mean $\boldsymbol{\mu}_q$.
    *   Learnable parameters per primitive: Cholesky precision factor $\mathbf{L}$, spatial coupling factor $\mathbf{V}_{pq}$, per-dimension coupling vector $\boldsymbol{\Lambda}$.
    *   Query vector $\mathbf{q}$ (e.g., view direction or timestamp).
*   **Outputs:**
    *   Conditional opacity $\alpha_{\text{cond}}$.
    *   Conditional position $\boldsymbol{\mu}_{\text{cond}}$.

**Data Structures:**
*   $\mathbf{L}$: Lower triangular Cholesky factor of the query precision matrix $\Sigma_{qq}^{-1}$. Size $C \times C$ where $C$ is the dimensionality of the query space (typically 3 for view direction).
*   $\mathbf{V}_{pq}$: Spatial coupling factor. Size $3 \times C$. Parameterized as $\mathbf{V}_{pq} = \bar{s} \boldsymbol{\Theta}_{pq}$ where $\|\boldsymbol{\Theta}_{pq}\|_F = 1$ and $\bar{s}$ is the mean scale of the primitive [S1, unofficial].
*   $\boldsymbol{\Lambda}$: Per-dimension coupling vector. Size $C$. Interpolates between query-independent position ($\Lambda_i=0$) and full coupling with opacity precision ($\Lambda_i=1$) [S1, unofficial].
*   $\mathbf{V}_{qq}$: Precision-transformed query channels. Defined as $\tilde{\mathbf{V}}_{qq} = \text{diag}(\boldsymbol{\Lambda}) \mathbf{V}_{qq}$ in the position formula, but the base $\mathbf{V}_{qq}$ is derived from the precision matrix structure [S1, unofficial]. Note: The source defines the position update using $\mathbf{V}_{qq}$ directly in the factorization $\mu_{\text{cond}} = \boldsymbol{\mu}_p + \mathbf{V}_{pq} \text{diag}(\boldsymbol{\Lambda}) \mathbf{V}_{qq} \boldsymbol{\delta}$ [S1, unofficial].

**Steps:**
1.  **Compute Query Deviation:** Calculate the deviation of the query from the canonical mean:
    $$ \boldsymbol{\delta} = \mathbf{q} - \boldsymbol{\mu}_q $$
2.  **Compute Opacity:**
    *   Compute the transformed deviation: $\mathbf{z} = \mathbf{L}^T \boldsymbol{\delta}$.
    *   Calculate the conditional opacity:
        $$ \alpha_{\text{cond}} = \alpha \cdot \exp(-\lambda_0 \|\mathbf{L}^T \boldsymbol{\delta}\|_2^2) $$
        where $\lambda_0$ is a scaling factor.
3.  **Compute Position:**
    *   Calculate the conditional position:
        $$ \boldsymbol{\mu}_{\text{cond}} = \boldsymbol{\mu}_p + \mathbf{V}_{pq} \text{diag}(\boldsymbol{\Lambda}) \mathbf{V}_{qq} \boldsymbol{\delta} $$
    *   Note: $\mathbf{V}_{qq}$ here refers to the precision-related transformation applied to the query deviation. **Pseudocode:**

```python
import numpy as np

def direct_gaussian_splatting_conditioning(
    alpha: float,
    mu_p: np.ndarray,      # Base position, shape (3,)
    mu_q: np.ndarray,      # Canonical query mean, shape (C,)
    q: np.ndarray,         # Query vector (e.g. view dir), shape (C,)
    L: np.ndarray,         # Cholesky precision factor, shape (C, C)
    V_pq: np.ndarray,      # Spatial coupling factor, shape (3, C)
    Lambda: np.ndarray,    # Per-dimension coupling vector, shape (C,)
    lambda_0: float = 0.35 # Scaling factor
) -> tuple:
    """
    Computes conditional opacity and position for Direct Gaussian Splatting.
    
    Args:
        alpha: Base opacity.
        mu_p: Base 3D position.
        mu_q: Canonical query mean (e.g. mean view direction).
        q: Current query vector (e.g. current view direction).
        L: Lower triangular Cholesky factor of the query precision matrix.
        V_pq: Spatial coupling factor.
        Lambda: Per-dimension coupling vector.
        lambda_0: Opacity scaling factor.
        
    Returns:
        alpha_cond: Conditional opacity.
        mu_cond: Conditional position.
    """
    C = len(mu_q)
    
    # Step 1: Compute query deviation
    delta = q - mu_q
    
    # Step 2: Compute opacity
    # z = L^T * delta
    z = L.T @ delta
    # alpha_cond = alpha * exp(-lambda_0 * ||z||^2)
    alpha_cond = alpha * np.exp(-lambda_0 * np.dot(z, z))
    
    # Step 3: Compute position
    # mu_cond = mu_p + V_pq * diag(Lambda) * V_qq * delta
    # Based on source analysis, V_qq is derived from L. 
    # The source lists L, V_pq, Lambda as the 3 explicit parameters.
    # The formula uses V_qq. In the context of "Precision-transformed query channels",
    # and given L is the Cholesky of precision, we assume V_qq = L.
    # Note: The source formula is V_pq diag(Lambda) V_qq delta.
    
    V_qq = L  # Assumption based on source structure and parameter count
    
    # diag(Lambda) * V_qq * delta
    # First, Lambda * (V_qq @ delta)
    V_qq_delta = V_qq @ delta
    Lambda_V_qq_delta = Lambda * V_qq_delta
    
    # V_pq * (Lambda_V_qq_delta)
    shift = V_pq @ Lambda_V_qq_delta
    
    mu_cond = mu_p + shift
    
    return alpha_cond, mu_cond
```

**Edge Cases and Pitfalls:**
*   **Precision:** The Cholesky factor $\mathbf{L}$ must be numerically stable. If the precision matrix is not positive definite, Cholesky decomposition will fail [G].
*   **Boundary Conditions:** The coupling vector $\boldsymbol{\Lambda}$ interpolates between 0 and 1. Values outside this range may lead to unstable position shifts [S1, unofficial].
*   **Degenerate Input:** If the query deviation $\boldsymbol{\delta}$ is zero, opacity is base opacity and position is base position.

## Subtopics

### [FactorSplat](4088-factorsplat.md)
FactorSplat is a per-scene N-dimensional Gaussian splatting (N-DGS) proxy that accepts region-specific intensity-to-RGBA transfer function (TF) curves at inference time, allowing appearance changes without retraining or refitting. It solves the problem of image-trained Gaussian proxies baking one transfer function into their appearance, which prevents supporting new presets without rebuilding the proxy. Unlike standard Gaussian Splatting where geometry and appearance are tightly coupled to a single rendering configuration, FactorSplat decouples the geometric primitives from the appearance logic, allowing multiple TFs to share the same underlying Gaussian proxy. It differs from region-aware VEG by using region-specific intensity TFs and cinematic-rendering supervision, combining direct lookup with an image-trained N-DGS proxy.

### Direct Beta Splatting
Direct Beta Splatting (dBS) is a variant of dGS that swaps the Gaussian opacity decay for a Beta opacity decay, following the UBS implementation [S1, unofficial]. It reuses the direct conditional structure ($\mathbf{L}$, $\mathbf{V}_{pq}$, $\mathbf{V}_{qq}$) but derives coupling from bandwidth [S1, unofficial]. Opacity is computed as $\alpha_{\text{cond}} = \alpha \cdot \prod_{i=1}^C (1 - \tanh(z_i^2))^{\beta_i}$, where $z = \mathbf{L}^T \boldsymbol{\delta}$ and $\beta_i = 4 \exp(\beta_{\text{raw}_i})$ [S1, unofficial]. Position is computed as $\boldsymbol{\mu}_{\text{cond}} = \boldsymbol{\mu}_p + \mathbf{V}_{pq} \text{diag}(\boldsymbol{\Lambda}_{\boldsymbol{\beta}}) \mathbf{V}_{qq} \boldsymbol{\delta}$, where $\boldsymbol{\Lambda}_{\boldsymbol{\beta}} = \min(\boldsymbol{\beta}/4, 1)$ [S1, unofficial]. dBS uses 19 conditioning parameters for $C=3$ and 27 for $C=4$, compared to 22/24 for dGS [S1, unofficial]. dBS derives coupling $\boldsymbol{\Lambda}_{\boldsymbol{\beta}}$ from opacity bandwidth $\boldsymbol{\beta}$, whereas dGS uses a separate learned coupling $\boldsymbol{\Lambda}$ [S1, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
*   dGS removes the need for per-primitive matrix inversions and regression products required by N-DGS [S1, unofficial].
*   The conditioning step is replaced by explicit parameter lookups and matrix-vector multiplications, which are computationally cheaper [S1, unofficial].
*   Memory usage is determined by the number of learnable parameters per primitive: $\mathbf{L}$ ($C^2$), $\mathbf{V}_{pq}$ ($3 \times C$), and $\boldsymbol{\Lambda}$ ($C$) [S1, unofficial].

**Measured Performance:**
*   Not given in the sources.

**Scaling:**
*   Not given in the sources.

**Strengths and Limitations:**
*   **Strengths:** Removes expensive matrix inversions; separates position from opacity coupling; allows for efficient view-dependent and dynamic effects modeling [S1, unofficial].
*   **Limitations:** Requires learning additional parameters ($\mathbf{L}$, $\mathbf{V}_{pq}$, $\boldsymbol{\Lambda}$) compared to standard 3DGS [G].

**When to Use:**
*   Use dGS when efficient view-dependent or dynamic splatting is required, and the computational cost of matrix inversions in N-DGS is prohibitive [S1, unofficial].

**When Not to Use:**
*   Use standard 3DGS if view-dependent effects are not needed, or N-DGS if the covariance-derived conditioning is sufficient and the performance overhead is acceptable [S1, unofficial].

## Background
Direct Gaussian Splatting was introduced in the paper "Direct Conditional Parameterization for N-Dimensional Splatting" [S1, unofficial]. It is a direct counterpart to N-DGS, designed to improve efficiency by replacing covariance-derived conditioning with explicit parameters [S1, unofficial]. It is part of the family of N-dimensional splatting methods that model view-dependent and dynamic effects by lifting primitives into a joint distribution over position and conditioning variables [S1, unofficial].
