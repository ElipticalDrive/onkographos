# Local 3DGS Optimization
Also called: Local 3DGS Pose Optimization

## Overview
Local 3DGS Optimization is an iterative method for estimating the relative camera pose (transformation) between two nearby images by optimizing a local 3D Gaussian Splatting representation against photometric loss [S1]. It solves the problem of camera pose estimation without requiring external Structure-from-Motion (SfM) pipelines like COLMAP [S1]. Unlike global optimization methods that update Gaussian attributes, this method freezes the Gaussian primitives' geometric and appearance attributes after initialization, optimizing only the camera pose parameters [S1].

## How it works
**Inputs and Outputs:**
- **Inputs:** Two nearby images $I_t$ and $I_{t+1}$ [S1].
- **Outputs:** The accumulated camera pose $Q_t$ representing the transformation from the initial view to the current view [S1].

**Data Structures:**
- **Local 3DGS ($G_t$):** A set of Gaussian primitives initialized from $I_t$ and its monocular depth map $D_t$. Attributes include position, scale, rotation, opacity, and SH coefficients [S1].
- **Pose ($T_t$):** A transformation matrix (or quaternion + translation vector) initialized to Identity $I$ [S1].
- **Monocular Depth Model:** DPT (Vision Transformers for Dense Prediction) [S1].

**Steps:**
1. **Depth Estimation:** Compute the monocular depth map $D_t$ for the source image $I_t$ using the DPT model [S1].
2. **Local 3DGS Initialization:** Initialize the local 3DGS representation $G_t$ from $I_t$ and $D_t$ using the `InitGauss` function [S1].
3. **Local 3DGS Fitting:** Optimize $G_t$ against $I_t$ to refine the local geometry. This involves rasterizing $G_t$, computing the photometric loss $L$ between the rendered image $\hat{I}_t$ and $I_t$, and updating $G_t$ using the Adam optimizer. This step runs for 500 iterations [S1].
4. **Pose Initialization:** Initialize the pose parameter $T_t$ as the Identity matrix $I$ [S1].
5. **Pose Optimization:** Iteratively optimize the pose $T_t$ to align the local 3DGS with the target image $I_{t+1}$:
   - Transform the frozen local 3DGS $G_t$ by the current pose $T_t$ to obtain $T_t \odot G_t$ [S1].
   - Rasterize the transformed Gaussians to render the image $\hat{I}_{t+1}$ [S1].
   - Compute the photometric loss $L$ between the target image $I_{t+1}$ and the rendered image $\hat{I}_{t+1}$ [S1].
   - Update the pose parameter $T_t$ using the Adam optimizer on the gradient $\nabla L$ [S1].
   - This step runs for 300 steps [S1].
6. **Pose Accumulation:** The final pose $Q_t$ is the product of transformations $T_i$ from $i=1$ to the current step [S1].

**Pseudocode:**
```python
def local_3dgs_optimization(I_t, I_t_plus_1):
    # Step 1: Depth Estimation
    D_t = DPT(I_t)
    
    # Step 2: Local 3DGS Initialization
    G_t = InitGauss(I_t, D_t)
    
    # Step 3: Local 3DGS Fitting (500 iterations)
    for _ in range(500):
        I_hat_t = Rasterize(G_t)
        L = Loss(I_t, I_hat_t)
        G_t = Adam_Update(G_t, gradient(L, G_t))
        
    # Step 4: Pose Initialization
    T_t = Identity()
    
    # Step 5: Pose Optimization (300 steps)
    for _ in range(300):
        # Transform frozen Gaussians by current pose
        G_transformed = Transform(G_t, T_t)
        I_hat_t_plus_1 = Rasterize(G_transformed)
        L = Loss(I_t_plus_1, I_hat_t_plus_1)
        T_t = Adam_Update(T_t, gradient(L, T_t))
        
    # Step 6: Output Pose
    Q_t = T_t
    return Q_t
```

**Parameters:**
- **Local 3DGS Optimization Iterations:** 500 [S1].
- **Pose Learning Optimization Steps:** 300 [S1].
- **Monocular Depth Model:** DPT [S1].
- **Camera Intrinsic Heuristic:** If intrinsic parameters are unknown, Field of View (FoV) is set to $79^\circ$ and principal points are set to the image center [S1].

**Edge Cases and Pitfalls:**
- **Unknown Intrinsics:** Using heuristic intrinsics (FoV $79^\circ$, center principal point) leads to slight degradation in novel view synthesis and camera pose estimation accuracy compared to known intrinsics [S1].
- **High-Resolution Inputs:** High-resolution images can result in a huge amount of point clouds. The method requires downsampling the point cloud before fitting local 3DGS to manage computational load [S1].

## Operating characteristics
- **Time Complexity:** The method involves two distinct optimization phases: 500 iterations for local 3DGS fitting and 300 steps for pose optimization [S1].
- **Memory Complexity:** Memory usage is dominated by the local 3DGS representation, which is initialized from a downsampled point cloud derived from the input image and monocular depth map [S1].
- **Strengths:** Capable of handling dramatic camera motions (large maximum rotation angles between frames) [S1]. Does not require COLMAP or external SfM tools [S1].
- **Limitations:** Performance degrades slightly when camera intrinsics are unknown and heuristics are used [S1]. The method is designed for nearby images; the sampling rate for test images (every 8th frame) suggests it may not handle arbitrarily large baseline changes without intermediate steps [S1].

## Background
- **Origin:** The method is described in "COLMAP-Free 3D Gaussian Splatting" [S1].
- **History:** It was developed to enable 3D Gaussian Splatting optimization without relying on traditional Structure-from-Motion pipelines, allowing for direct initialization from monocular depth estimates [S1].
- **Usage:** Used in datasets such as CO3D-V2 and Tanks and Temples for training and evaluation, particularly in scenarios with dramatic camera motions [S1].
