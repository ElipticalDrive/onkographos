# Cross-scale geometric adaptation

Also called: Lgeo, Reprojection error supervision, Reprojection-based cross-scale geometric adaptation

## Overview
Cross-scale geometric adaptation is a self-adaptive regularization technique that uses reprojection errors across multiple voxel scales to guide geometry learning in few-shot novel view synthesis [S1]. It selects render depths with minimal reprojection error across different scales as pseudo-labels, ensuring geometric integrity without requiring explicit depth ground truth [S1]. Unlike methods that rely on complex scheduling or external priors, it adapts multi-scale voxel geometry by leveraging low-resolution voxels for coarse guidance early in training and high-resolution voxels for detail refinement later [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Training views $i$ and $j$ (where $j$ is a neighboring or novel view), camera intrinsics $K_i, K_j$, camera poses $(R_i, t_i), (R_j, t_j)$, multi-scale depth maps $D_l(p)$ for scale $l \in \{0, \dots, L\}$, and RGB maps $C_i, C_j$.
*   **Outputs:** Geometric adaptation loss $\mathcal{L}_{geo}$ and pseudo-ground truth depth $D'(r_{train})$.

**Data Structures:**
*   **Multi-scale Voxels:** The scene is represented by voxels at $L+1$ scales (e.g., Low, Mid, High). Each scale $l$ produces a depth map $D_l$ and RGB map $C_l$ via volume rendering [S1].
*   **Ray Sampling:** For each training ray $r_{train}$, a 2D pixel coordinate $p_i$ is defined in frame $i$ [S1].

**Steps:**
1.  **Reproject to 3D (Source Frame):** For a pixel $p_i$ in frame $i$ at scale $l$, compute the 3D point in camera coordinates $x_{li}$ using the rendered depth $D_{il}(p_i)$ and camera intrinsics $K_i$:
    $$
    x_{li} = D_{il}(p_i) K_i^{-1} \tilde{p}_i
    $$
    where $\tilde{p}_i$ is the homogeneous augmentation of $p_i$ [S1].
2.  **Transform to World Coordinates:** Transform $x_{li}$ to world coordinates $x_l$ using frame $i$'s rotation $R_i$ and translation $t_i$:
    $$
    x_l = R_i x_{li} + t_i
    $$
    [S1]
3.  **Transform to Target Camera Coordinates:** Transform the world coordinate point $x_l$ to the camera coordinate system of frame $j$ using frame $j$'s rotation $R_j$ and translation $t_j$:
    $$
    x_{li \to j} = R_j^T (x_l - t_j)
    $$
    [S1]
4.  **Project to 2D (Target Frame):** Project $x_{li \to j}$ back to the 2D pixel coordinate system of frame $j$:
    $$
    \tilde{p}_{li \to j} = \pi(K_j x_{li \to j})
    $$
    where $\pi([x, y, z]^T) = [x/z, y/z]^T$ [S1].
5.  **Compute Reprojection Error:** Calculate the RGB difference between the original pixel and the warped pixel:
    $$
    e_l(p_i) = C_i(p_i) - C_j(\tilde{p}_{li \to j})
    $$
    [S1]
6.  **Select Pseudo-Ground Truth Depth:** Identify the scale $l$ with the minimum reprojection error for each ray:
    $$
    D'(r_{train}) = \arg \min_l (e_l(r_{train}))
    $$
    [S1]
7.  **Compute Loss:** Calculate the Mean Squared Error (MSE) between the rendered depth at the selected scale and the pseudo-ground truth depth $D'$:
    $$
    \mathcal{L}_{geo}(r_{train}) = \sum_{l=0}^{L} \| \hat{D}_l(r_{train}) - D'(r_{train}) \|^2
    $$
    Note: The source formula (19) sums over $l$, but the logic implies selecting the best scale. The text states "pseudo-GT depth of the scale with the minimum reprojection error is obtained... utilized to compute the geometric adaptation loss". The loss is typically computed against the depth of the *selected* scale or as a consistency term. Based on Eq 19 in [S1], it appears to be a sum of squared differences, but contextually it acts as a constraint where the model learns to align depths such that the reprojection error is minimized. The text clarifies: "selecting render depths with minimal reprojection error across different scales as pseudo labels". Thus, $D'$ is the depth from the best scale, and the loss penalizes deviation from this consistent geometry. [S1]

**Pseudocode:**
```python
def compute_cross_scale_geo_loss(
    rays, 
    scales, 
    intrinsics_i, intrinsics_j, 
    poses_i, poses_j, 
    render_depths, 
    render_rgbs
):
    """
    rays: list of (p_i, r_train)
    scales: list of scale indices l
    intrinsics_i, intrinsics_j: K_i, K_j
    poses_i, poses_j: (R_i, t_i), (R_j, t_j)
    render_depths: dict (scale, ray) -> depth
    render_rgbs: dict (scale, ray) -> RGB
    """
    geo_loss = 0.0
    pseudo_gt_depths = []
    
    for p_i, r_train in rays:
        min_error = float('inf')
        best_scale = None
        best_depth = None
        
        for l in scales:
            # 1. Reproject to 3D in frame i
            # x_li = D_il(p_i) * K_i^-1 * p_i_homogeneous
            p_i_hom = np.array([p_i[0], p_i[1], 1.0])
            x_li_cam = render_depths[l, r_train] * np.linalg.inv(intrinsics_i) @ p_i_hom
            
            # 2. Transform to World
            # x_l = R_i * x_li + t_i
            x_l_world = poses_i.R @ x_li_cam + poses_i.t
            
            # 3. Transform to frame j camera
            # x_li_j = R_j^T * (x_l - t_j)
            x_li_j_cam = poses_j.R.T @ (x_l_world - poses_j.t)
            
            # 4. Project to frame j 2D
            # p_j = pi(K_j * x_li_j)
            p_j_hom = intrinsics_j @ x_li_j_cam
            p_j = np.array([p_j_hom[0]/p_j_hom[2], p_j_hom[1]/p_j_hom[2]])
            
            # 5. Compute Reprojection Error
            # e_l = C_i(p_i) - C_j(p_j)
            # Note: C_j(p_j) requires interpolation if p_j is not integer
            rgb_i = render_rgbs[l, r_train] # Or C_i(p_i) from scale l? 
            # Source says C_i(p_i) and C_j(p_j). Usually C_i is from the same scale l for consistency in error calc, 
            # or C_i is the reference. Source Eq 18/19 context implies using the depth from scale l to generate the point.
            # Let's assume C_i is the RGB at p_i from scale l, and C_j is RGB at p_j from scale l.
            rgb_j = interpolate(render_rgbs[l], p_j) 
            error = np.linalg.norm(rgb_i - rgb_j)
            
            if error < min_error:
                min_error = error
                best_scale = l
                best_depth = render_depths[l, r_train]
        
        # 6. Compute Loss against best depth
        # L_geo = sum || D_l - D' ||^2 ? 
        # Source Eq 19: sum_{l=0}^L || \hat{D}_l - D' ||^2
        # This penalizes all scales to match the best one? Or just the best one?
        # "pseudo-GT depth ... is obtained ... utilized to compute ... loss"
        # If it's a sum, it forces all scales to converge to the geometrically consistent depth.
        scale_loss = 0.0
        for l in scales:
            d_l = render_depths[l, r_train]
            scale_loss += (d_l - best_depth)**2
        
        geo_loss += scale_loss
        pseudo_gt_depths.append(best_depth)
        
    return geo_loss, pseudo_gt_depths
```

**Parameters:**
*   **Scales:** Typically Low, Mid, High resolutions [S1].
*   **Loss Weight:** $\lambda_{geo}$ (Not given in the sources).

**Edge Cases and Pitfalls:**
*   **Camera Poses:** Requires accurate camera poses; significant viewpoint changes or sparse views can challenge generalization [S1].
*   **Local Minima:** Omitting novel view rays risks local minima and incorrect geometry [S1].
*   **Floaters:** Without this adaptation, all scales perform sub-optimally, and floaters are prevalent [S1].

## Operating characteristics
*   **Time Complexity:** Adds overhead for multi-scale reprojection and error computation per ray per scale.
*   **Memory Complexity:** Requires storing multi-scale depth and RGB maps during training.
*   **Performance:** Significantly reduces floaters and improves convergence quality across scales compared to training without geometric adaptation [S1].
*   **Accuracy:** Achieves lower final depth error than depth prior ($\mathcal{L}_d$) alone, providing a stronger and more robust constraint [S1].
*   **Scaling:** Adapts to diverse scenes [S1].
*   **Strengths:** Self-adaptive, no complex scheduling, no external priors, robust to geometric noise [S1].
*   **Limitations:** Relies on accurate camera poses; struggles with significant viewpoint changes or very sparse training views (e.g., 360° datasets) [S1].

## Background
*   **Origin:** Proposed in FrugalNeRF [S1].
*   **History:** Developed to accelerate and regularize training for extreme few-shot novel view synthesis without learned priors [S1].
*   **Usage:** Used in few-shot NeRF frameworks to guide multi-scale geometry learning [S1].
