# Directed Distance Field (DDF) for Gaussian Splatting

Also called: Directed Distance Function, ray-query oracle

## Overview
The Directed Distance Field (DDF) is a neural implicit representation that serves as a constant-time, constant-memory ray oracle for 3D Gaussian Splatting (3DGS) scenes [S1, unofficial]. It maps a ray origin and direction to the distance to the first surface and a visibility probability, enabling efficient secondary ray queries for shadows, ambient occlusion, and global illumination without requiring a mesh or BVH traversal [S1, unofficial]. Unlike Gaussian rasterization, which only answers camera-view queries, or BVH-based Gaussian tracing, which scales linearly with scene size, the DDF provides flat performance regardless of the number of Gaussians [S1, unofficial].

## How it works
The DDF is trained to approximate the distance to the nearest surface along a ray and the probability that the ray intersects the scene. It replaces the need for iterative sphere tracing or hierarchical traversal structures.

### Inputs and Outputs
*   **Input:** A ray defined by origin $\mathbf{x} \in \mathbb{R}^3$ and unit direction $\mathbf{d} \in S^2$.
*   **Output:** A tuple $(t, \xi)$, where $t$ is the scalar distance to the first surface along $\mathbf{d}$, and $\xi \in [0, 1]$ is the visibility value (probability of hit) [S1, unofficial]. The hit point is $\mathbf{x} + t\mathbf{d}$ when $\xi$ is high.

### Data Structures
The network consists of a multiresolution hash grid encoding for the position and a sinusoidal encoding for the direction, followed by a small MLP [S1, unofficial].

1.  **Multiresolution Hash Grid (Position Encoding):**
    *   **Levels:** 16.
    *   **Features per level:** 2.
    *   **Entries per level:** $2^{19}$ (524,288).
    *   **Base resolution:** 16.
    *   **Growth factor:** 1.5.
    *   **Bounding Box:** A box bounding the normalized object.
    *   **Parameter Count:** $\approx 13$ million.
2.  **Sinusoidal Encoding (Direction Encoding):**
    *   **Bands:** 4 sinusoidal bands.
3.  **MLP (Decoder):**
    *   **Layers:** 2.
    *   **Width:** 64.
    *   **Parameter Count:** $\approx 8,000$.
4.  **Total Memory:** ~52 MB. This size is fixed and independent of the number of Gaussians $N$ [S1, unofficial].

### Training Procedure
The DDF is trained using a combination of distance and visibility supervision derived from the 3DGS scene and auxiliary geometric sources.

**Loss Function:**
$$ L = \text{ClampedL1}(t_{pred}, t_{target}) + \lambda \cdot \text{BCE}(\xi_{pred}, \xi_{target}) $$
Where:
*   $\text{ClampedL1}$ is the L1 loss on distance, clamped to a maximum value (box scale) to prevent far-away surfaces from dominating [S1, unofficial].
*   $\text{BCE}$ is the Binary Cross-Entropy loss on the hit flag $\xi$ [S1, unofficial].
*   $\lambda = 0.3$ is the weight for the visibility term [S1, unofficial].

**Supervision Sources:**
1.  **GS-Rendered Depth:** Provides targets for primary camera rays. Note that this supervision is blurry and fails to recover thin features [S1, unofficial].
2.  **Clean Distance Supervision:** Obtained by sphere-tracing a neural surface (e.g., NeuS) fit to the images or ray-casting ground-truth meshes. This is critical for recovering thin geometry (e.g., mug handles, animal legs) [S1, unofficial].
3.  **Self-Consistency:** To sharpen thin features, for a ray hitting at distance $t$, a point shifted forward by distance $s$ along the ray is sampled. The DDF evaluated at this shifted point must predict distance $t-s$. 30% of the training batch consists of these ray-march shifted points [S1, unofficial].

**Optimization Parameters:**
*   **Optimizer:** Adam.
*   **Steps:** 30,000.
*   **Batch Size:** 16,384 rays.
*   **Learning Rate:** $3 \times 10^{-3}$, decayed by cosine schedule to 5% of initial value.
*   **Hardware:** Single A100 GPU (training time < 1 hour per object) [S1, unofficial].

### Pseudocode

```python
import torch
import torch.nn as nn

class DDF:
    def __init__(self, num_levels=16, features_per_level=2, 
                 entries_per_level=2**19, base_resolution=16, 
                 growth_factor=1.5, num_dir_bands=4, mlp_width=64):
        """
        Initializes the Directed Distance Field.
        """
        super().__init__()
        # Multiresolution Hash Grid for position encoding
        # Implemented via tinycudann or equivalent hash grid structure
        self.pos_encoder = HashGridEncoder(
            num_levels=num_levels,
            features_per_level=features_per_level,
            entries_per_level=entries_per_level,
            base_resolution=base_resolution,
            growth_factor=growth_factor
        )
        
        # Sinusoidal encoding for direction
        self.num_dir_bands = num_dir_bands
        
        # MLP Decoder
        # Input dim: (features_per_level * num_levels) + (2 * num_dir_bands)
        # Output dim: 2 (distance t, visibility xi)
        input_dim = (features_per_level * num_levels) + (2 * num_dir_bands)
        self.mlp = nn.Sequential(
            nn.Linear(input_dim, mlp_width),
            nn.ReLU(),
            nn.Linear(mlp_width, mlp_width),
            nn.ReLU(),
            nn.Linear(mlp_width, 2)
        )

    def encode_direction(self, d):
        """
        Encodes direction d using 4 sinusoidal bands.
        d shape: (..., 3)
        Returns shape: (..., 2 * num_dir_bands)
        """
        # Standard positional encoding for direction
        # bands = 4, so frequencies 2^0 to 2^3
        frequencies = torch.tensor([2**i for i in range(self.num_dir_bands)], device=d.device)
        # d is normalized unit vector
        scaled_d = d.unsqueeze(-1) * frequencies.unsqueeze(0) # (..., 3, 4)
        # Apply sin and cos
        encoded = torch.cat([torch.sin(scaled_d), torch.cos(scaled_d)], dim=-1) # (..., 3, 8)
        # Reshape to (..., 8)
        return encoded.view(*d.shape[:-1], -1)

    def forward(self, x, d):
        """
        Query the DDF.
        x: ray origin, shape (..., 3)
        d: ray direction, shape (..., 3)
        Returns: t (distance), xi (visibility)
        """
        # Encode position
        pos_feat = self.pos_encoder(x) # (..., 32)
        
        # Encode direction
        dir_feat = self.encode_direction(d) # (..., 8)
        
        # Concatenate features
        combined = torch.cat([pos_feat, dir_feat], dim=-1) # (..., 40)
        
        # MLP
        out = self.mlp(combined) # (..., 2)
        
        t = out[..., 0]
        xi = torch.sigmoid(out[..., 1]) # Ensure xi is in [0, 1]
        
        return t, xi

    def compute_loss(self, t_pred, xi_pred, t_target, xi_target):
        """
        Computes the training loss.
        """
        # Clamped L1 loss for distance
        # Clamp to box scale (assume box_scale is a hyperparameter)
        box_scale = 1.0 # Example: normalized object box scale
        l1_loss = torch.clamp(torch.abs(t_pred - t_target), max=box_scale).mean()
        
        # BCE loss for visibility
        bce_loss = nn.functional.binary_cross_entropy(xi_pred, xi_target)
        
        # Weighted sum
        lambda_vis = 0.3
        total_loss = l1_loss + lambda_vis * bce_loss
        
        return total_loss

    def query_shadow(self, surface_point, normal, light_direction, light_distance):
        """
        Query for shadow.
        surface_point: point on surface
        normal: surface normal
        light_direction: unit vector to light
        light_distance: distance to light source
        Returns: True if in shadow
        """
        # Offset surface point along normal to avoid self-intersection
        offset_point = surface_point + normal * 1e-3
        
        # Query DDF
        t, xi = self.forward(offset_point, light_direction)
        
        # If hit distance is less than light distance, it's in shadow
        return (t < light_distance) and (xi > 0.5)

    def query_ambient_occlusion(self, surface_point, normal, num_samples=16):
        """
        Query for ambient occlusion.
        surface_point: point on surface
        normal: surface normal
        num_samples: number of directions to sample over hemisphere
        Returns: AO value (0 to 1)
        """
        # Generate random directions in hemisphere around normal
        # Implementation detail: sample random vectors and project onto hemisphere
        directions = sample_hemisphere_directions(normal, num_samples)
        
        visibilities = []
        for d in directions:
            t, xi = self.forward(surface_point, d)
            visibilities.append(xi)
            
        # Average hit flags
        ao = 1.0 - torch.mean(torch.stack(visibilities))
        return ao
```

### Edge Cases and Pitfalls
*   **Thin Feature Loss:** Supervising solely on 3DGS-rendered depth blurs thin parts (e.g., mug handles) because narrow structures are averaged away by soft Gaussians. Clean distance supervision (from neural surfaces or meshes) is required to recover these features [S1, unofficial].
*   **Compact Objects:** For compact objects where Gaussian depth already captures geometry, clean distance supervision provides little benefit and may hurt if the auxiliary surface is noisy, causing "fattening" [S1, unofficial].
*   **Direct Image Supervision:** Learning directly from volume-rendered color loss does not help recover thin parts because most rays land on background, making the gradient signal from color to distance weak [S1, unofficial].
*   **Step-by-Step Tracing:** Supervising sequential ray-marching steps from images is unstable due to gradient issues in the sequential loop [S1, unofficial].
*   **Ambient Occlusion Accuracy:** AO quality (21.3 dB) is lower than shadow quality (30.3 dB) because averaging many rays accumulates small per-ray errors [S1, unofficial].
*   **Ray Origin Dependency:** The oracle is accurate primarily for ray origins on or near the surface. Rays starting far from the surface (e.g., ground plane below an object) may report false occlusion [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per ray query. The DDF requires a single forward pass regardless of scene size [S1, unofficial].
*   **Memory Complexity:** $O(1)$ with respect to the number of Gaussians $N$. The field size is fixed at ~52 MB [S1, unofficial].
*   **Performance:**
    *   **Speed:** 26 to 72 times faster than sphere tracing an equivalent neural SDF [S1, unofficial].
    *   **Scaling:** Unlike BVH-over-Gaussians, latency does not grow with $N$. BVH latency rises ~9x from 5K to 1M Gaussians, while DDF remains flat [S1, unofficial].
    *   **Comparison to BVH:** On small scenes (< few thousand Gaussians), RT-core BVH is faster per ray. At real scene scales (hundreds of thousands to millions of Gaussians), DDF becomes competitive or faster, especially with CUDA-fused kernels (tinycudann) [S1, unofficial].
    *   **Comparison to Rasterization:** For sparse queries (1K-10K rays), DDF is 600+ times faster than re-rasterizing. At full frame (1M rays), DDF ties rasterization (4.81 ms vs 4.45 ms) because rasterization is bound by frame buffer writing [S1, unofficial].
*   **Quality:**
    *   **Shadows:** Reproduces reference ray-traced shadows at 30.3 dB [S1, unofficial].
    *   **Ambient Occlusion:** Reproduces reference AO at 21.3 dB [S1, unofficial].
    *   **Geometry:** Chamfer distance improves from 0.082 to 0.065 (21% drop) with clean distance supervision [S1, unofficial].
*   **Strengths:** Constant time and memory, no mesh required, no RT-core hardware dependency, supports arbitrary rays.
*   **Limitations:** AO quality is lower than shadows; accuracy degrades for ray origins far from the training surface; relies on the quality of the auxiliary geometric supervision (neural surface or mesh) for thin features [S1, unofficial].

## Background
The Directed Distance Field for Gaussian Splatting was introduced to address the limitation of 3DGS rasterization, which cannot trace secondary rays for global illumination [S1, unofficial]. The method distills a trained 3DGS scene into a small neural field (52 MB) that acts as a ray oracle [S1, unofficial]. It builds on multiresolution hash grid encoding techniques from tinycudann [S1, unofficial]. The approach enables mesh-free global illumination pipelines, allowing for shadows and ambient occlusion in Gaussian Splatting scenes without explicit surface reconstruction [S1, unofficial].
