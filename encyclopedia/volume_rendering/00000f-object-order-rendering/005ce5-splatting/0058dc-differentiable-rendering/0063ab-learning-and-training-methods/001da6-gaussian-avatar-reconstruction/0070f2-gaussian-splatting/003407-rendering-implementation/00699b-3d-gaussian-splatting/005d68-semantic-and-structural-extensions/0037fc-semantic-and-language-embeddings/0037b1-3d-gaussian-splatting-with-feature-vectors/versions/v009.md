# 3D Gaussian Splatting with Feature Vectors

Also called: Semantic-Extended 3D Gaussian Splatting Rendering

## Overview
This method extends standard 3D Gaussian Splatting by attaching a high-dimensional feature vector $\mathbf{f}_i$ to each Gaussian primitive, enabling the rendering of semantic, linguistic, or latent feature maps rather than just color [S1, unofficial][S2]. It solves the problem of integrating 2D vision-language models (e.g., CLIP, LSeg) into a 3D representation, allowing for real-time open-vocabulary semantic segmentation and phrase grounding [S1, unofficial]. It differs from sibling methods by serving as the foundational rasterization mechanism for feature accumulation; while siblings like LangSplat or LSeg Feature Encoding apply specific encoders or decoding heads, this article defines the core differentiable alpha-blending accumulation of arbitrary feature vectors $\mathbf{f}_i \in \mathbb{R}^d$ that underpins the entire family, building on the shared principles of [Semantic and Language Embeddings](8130-semantic-and-language-embeddings.md).

## How it works
**Inputs and Outputs:**
*   **Input:** A set of 3D Gaussians $\mathcal{G} = \{g_i\}$, where each $g_i$ is defined by position $\mathbf{x}_i$, covariance $\mathbf{\Sigma}_i$ (or rotation $\mathbf{R}_i$ and scale $\mathbf{s}_i$), opacity $\alpha_i$, and a feature vector $\mathbf{f}_i \in \mathbb{R}^d$ [S1, unofficial][S2].
*   **Output:** A 2D feature map $\mathbf{F} \in \mathbb{R}^{H \times W \times d}$, where each pixel $p$ contains the accumulated feature vector $\mathbf{F}(p)$ [S1, unofficial].

**Data Structures:**
Each Gaussian $i$ stores:
*   $\mathbf{x}_i \in \mathbb{R}^3$: Center position.
*   $\mathbf{R}_i \in \mathbb{R}^{3 \times 3}$: Rotation matrix (or quaternion).
*   $\mathbf{s}_i \in \mathbb{R}^3$: Scale vector.
*   $\alpha_i \in \mathbb{R}$: Opacity (clamped to $[0, 1]$).
*   $\mathbf{f}_i \in \mathbb{R}^d$: Semantic embedding vector.
*   Spherical harmonic coefficients: View-dependent color.
All attributes are stored contiguously per primitive for rasterization [S2].

**Rendering Steps:**
1.  **Projection:** Project 3D Gaussians to the 2D image plane using an affine approximation of the perspective transformation, yielding 2D Gaussians with a transformed mean and a 2D covariance matrix [S2].
2.  **Sorting:** Sort projected primitives front-to-back according to their depth relative to the camera [S2].
3.  **Accumulation:** Compute the feature vector $\mathbf{F}(p)$ for pixel $p$ using the shared principle of differentiable alpha-blending accumulation:
    $$ \mathbf{F}(p) = \sum_{i \in \mathcal{O}_p} \mathbf{f}_i \cdot \alpha_i \cdot \prod_{j=1}^{i-1} (1 - \alpha_j) $$
    where $\mathcal{O}_p$ is the set of overlapping Gaussians sorted front-to-back [S1, unofficial].
4.  **Post-processing:** The resulting feature map $\mathbf{F}$ is passed to a downstream task, such as a segmentation head or a similarity comparison with text embeddings from a vision-language model (e.g., CLIP) [S1, unofficial].

**Parameters:**
*   Feature dimension $d$: 512 for CLIP, 768 for LSeg/CLIP text, or compressed latent dimensions [S1, unofficial].
*   Opacity $\alpha_i$: Optimized during training via photometric loss [S2].

**Edge Cases and Pitfalls:**
*   **Boundary Bleeding:** Boundary bleeding between visual and semantic regions is eliminated because geometric parameters (position, scale, rotation, opacity) dictate the blending weights for both color and semantic rendering, hard-coding alignment [S2].
*   **Empty Overlap:** If $\mathcal{O}_p$ is empty, $\mathbf{F}(p) = \mathbf{0}$ [S1, unofficial].
*   **Full Opacity:** If $\alpha_i = 1$ for any $i$, subsequent Gaussians in the stack contribute nothing to $\mathbf{F}(p)$ [G].
*   **Precision:** Not given in the sources.
*   **Boundaries:** Not given in the sources.

## Subtopics

### Scale-Aware Semantic Feature Gating
A mechanism to modulate rendered semantic features based on scale, using learned or fixed gate vectors derived from sampled scales [S3, unofficial]. It is chosen when scale-dependent semantic consistency is required, such as in multi-scale segmentation tasks. It differs from standard feature accumulation by introducing a gating factor that multiplies the accumulated feature. The steps are:
1.  Map the distribution of sampled scales to a Gaussian distribution using `self.q_trans(sampled_scales)` [S3, unofficial].
2.  Compute gates: if `scale_aware_dim <= 0` or `scale_aware_dim >= 32`, compute gates by passing sampled scales through `self.scale_gate`: `gates = self.scale_gate(sampled_scales.unsqueeze(-1))` [S3, unofficial]; otherwise, discretize scales to integers `int_sampled_scales = ((1 - sampled_scales.squeeze()) * scale_aware_dim).long()` and lookup pre-computed gates `gates = self.fixed_scale_gate[int_sampled_scales].detach()` [S3, unofficial].
3.  Repeat rendered features for each sampled scale: `feature_with_scale = rendered_features.unsqueeze(0).repeat([sampled_scales.shape[0], 1, 1, 1])` [S3, unofficial].
4.  Multiply features by gate vectors: `feature_with_scale = feature_with_scale * gates.unsqueeze(-1).unsqueeze(-1)` [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot H \cdot W)$ for rasterization, where $N$ is the number of Gaussians and $H \times W$ is the image resolution; feature accumulation adds a constant factor proportional to the feature dimension $d$ [G].
*   **Memory Complexity:** $O(N \cdot d)$ to store feature vectors for all Gaussians, plus $O(H \cdot W \cdot d)$ for the output feature map [G].
*   **Measured Performance:** Real-time frame rates are achievable on modern GPUs due to the efficiency of the Gaussian rasterizer [S1, unofficial].
*   **Strengths:** Enables open-vocabulary understanding without retraining the 3D representation; leverages the speed of 3DGS rasterization [S1, unofficial].
*   **Limitations:** Feature quality depends on the 2D encoder used during training; high-dimensional features increase memory usage [G].
*   **When to use:** When semantic or linguistic understanding is required from a 3D scene, especially for dynamic or real-time applications [S1, unofficial].
*   **When not to use:** When only geometric or photometric rendering is needed; when memory is constrained and $d$ is large [G].

## Background
Originated from the observation that the speed of the 3DGS rasterizer makes it an ideal platform for distilling 2D vision-model features into a 3D representation [S1, unofficial]. Feature-3DGS and LangSplat pioneered this direction by adding high-dimensional feature vectors to Gaussians [S1, unofficial]. Language Embedded 3D Gaussians expanded this to full scene understanding, encoding object-level embeddings for phrase grounding [S1, unofficial]. Subsequent works like SplatTalk and 3D Vision-Language GS further extended these capabilities [S1, unofficial].
