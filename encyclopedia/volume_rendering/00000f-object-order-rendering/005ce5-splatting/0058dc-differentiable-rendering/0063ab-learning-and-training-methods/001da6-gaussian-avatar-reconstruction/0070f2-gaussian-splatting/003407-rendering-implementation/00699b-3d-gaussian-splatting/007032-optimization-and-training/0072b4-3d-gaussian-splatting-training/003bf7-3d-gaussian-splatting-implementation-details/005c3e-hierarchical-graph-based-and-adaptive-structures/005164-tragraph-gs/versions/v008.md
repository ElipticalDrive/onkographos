# TraGraph-GS

Also called: Trajectory Graph-based Gaussian Splatting

## Overview
TraGraph-GS is a rendering method for arbitrary large-scale scenes that uses graph-based adaptive spatial partitioning, regularization constraints for 3D Gaussian Splatting (3DGS), and adaptive region selection to handle vast scales while maintaining real-time performance [S1]. It differs from flat 3DGS by partitioning the scene into connected subgraphs based on camera feature matching, training local representations independently, and using a progressive blending strategy for novel viewpoints to avoid boundary artifacts [S1].

## How it works
**Inputs:** A set of disordered scene photographs (images) and their corresponding poses.
**Outputs:** A rendered image for a novel viewpoint.

**Data Structures:**
*   **Camera Connectivity Graph:** $G = (V, E, w)$, where $V = \{v_1, ..., v_n\}$ are image vertices, $E$ are edges, and $w: E \to \mathbb{R}$ assigns weights based on feature matching counts between image pairs [S1].
*   **Regions:** A partition of $V$ into $k$ sets $\{P_i\}_{i=1}^k$, where each $P_i$ is a connected subgraph with approximately $|V|/k$ nodes [S1].
*   **Local Gaussians:** For each region $P_i$, a set of 3D Gaussians $\mathcal{G}_i$ is trained independently [S1].
*   **Global Gaussians:** A coarse set of 3D Gaussians $\mathcal{G}_{global}$ trained on downsampled data [S1].

**Steps:**

1.  **Graph Construction:** Construct $G$ by computing feature matches between all image pairs. The weight $w(v_i, v_j)$ is the count of matched features [S1].
2.  **Graph Segmentation:** Divide $G$ into $k$ regions using BFS-based segmentation [S1]:
    *   Initialize unassigned nodes $U = V$.
    *   While $U$ is not empty:
        *   Select node $n \in U$ with the highest degree as the seed.
        *   Perform BFS from $n$, adding nodes to the current region until it contains $|V|/k$ nodes.
        *   Remove added nodes from $U$.
        *   For remaining unassigned nodes, calculate a score $s_i$ relative to existing regions and assign them to maintain balance [S1].
3.  **Local Training:** For each region $P_i$, train local Gaussians $\mathcal{G}_i$ using the images in $P_i$. The loss function is [S1]:
    $$ L = (1 - \lambda)L_1 + \lambda L_{SSIM} + L_{mv} $$
    where $L_1$ and $L_{SSIM}$ are standard reconstruction losses [S1].
    *   **Multi-View Constraint ($L_{mv}$):** For textureless regions, render depth and normal maps. For a pixel $p$ in a reference view, establish a spatial plane $(d, n)$. Project $p$ to a neighborhood view $p'$ using homography. Compute Normalized Cross Correlation (NCC) between patches at $p$ and $p'$ [S1]:
        $$ L_{mv} = \sum_{p \in P_i} (1 - \text{NCC}(p, p')) $$
    *   **Multi-Scale Constraint:** Adjust Gaussian scales based on viewer distance. Define $\gamma(\mu)$ where $r$ is scene radius and $c$ is camera center [S1]:
        $$ \gamma(\mu) = \begin{cases} 1 & \text{if } \|\mu - c\|_2 < 2r \\ \|\mu - c\|_2 / r - 1 & \text{if } \|\mu - c\|_2 \ge 2r \end{cases} $$
        If the directional gradient exceeds a threshold:
        *   Clone if $\max(s) < g \cdot \gamma(\mu)$.
        *   Split otherwise.
        *   Prune if $\max(s)$ is too small [S1].
4.  **Global Training:** For novel viewpoints, train a coarse global representation $\mathcal{G}_{global}$ by downsampling point clouds and images, avoiding densification to save memory [S1].
5.  **Adaptive Region Selection (Rendering):**
    *   Render the novel viewpoint using $\mathcal{G}_{global}$ and each $\mathcal{G}_i$ separately.
    *   Calculate a matching score $S$ for each local-global pair [S1]:
        $$ S = (1 - \lambda)L_1 + \lambda L_{SSIM} $$
        Higher $S$ indicates higher likelihood of visibility [S1].
    *   Sort local Gaussians in descending order of $S$: $G_1, G_2, ..., G_k$.
    *   Compute projection opacity $o_i(p)$ for each pixel $p$ [S1]:
        $$ o_i(p) = \alpha_i \prod_{j=1}^{i-1} (1 - \alpha_j) $$
        where $\alpha_i$ is the opacity of Gaussian $G_i$ [S1].
    *   Compute weights $w_i$ based on an overlapped opacity threshold $\beta$ [S1]:
        $$ w_i = \begin{cases} o_i(p) & \text{if } \sum_{j=1}^{i-1} o_j(p) < \beta \\ 0 & \text{if } \sum_{j=1}^{i-1} o_j(p) \ge \beta \end{cases} $$
    *   Compute final pixel color $c(p)$ [S1]:
        $$ c(p) = \sum_{i=1}^k w_i c_i(p) $$
        where $c_i(p)$ is the color rendered by $G_i$ [S1].

**Parameters:**
*   $k$: Number of segmented regions.
*   $\lambda$: Weight for SSIM loss (typical value not given in sources, standard 3DGS uses 0.2 [S1]).
*   $r$: Scene radius.
*   $c$: Camera center.
*   $g$: Scaling factor for cloning threshold [S1].
*   $\beta$: Overlapped opacity threshold for progressive rendering [S1].

**Edge Cases:**
*   **Memory Overflow:** Balanced node distribution prevents memory overflow issues associated with uneven partitioning [S1].
*   **Boundary Artifacts:** The progressive rendering strategy avoids floating artifacts and holes common in methods that simply merge local Gaussians [S1].
*   **Textureless Regions:** Multi-view constraints specifically address geometry reconstruction failures in these areas [S1].

## Operating characteristics
*   **Time Complexity:** Training is parallelized across regions, reducing per-region memory and potentially time compared to global training [S1]. Graph segmentation is $O(|V| + |E|)$ [S1].
*   **Memory Complexity:** Scales with the number of regions and local Gaussian counts. Global training uses downsampled data to minimize memory [S1].
*   **Performance:** Evaluated on large-scale aerial (1,678–3,019 images) and ground-level datasets [S1]. Maintains real-time performance across vastly different scales [S1].
*   **Strengths:** Handles arbitrary large-scale scenes; improves texture details in textureless regions; avoids boundary artifacts; balances connectivity and node distribution [S1].
*   **Limitations:** Requires feature matching for graph construction; performance depends on the choice of $k$ and segmentation quality [S1].

## Background
TraGraph-GS was proposed to address the limitations of existing methods for large-scale scene rendering, which often struggle with memory, boundary artifacts, or textureless regions [S1]. It builds on 3DGS [11] and incorporates ideas from VastGaussian [14] regarding progressive partitioning [S1]. The method was published in IEEE Transactions on Pattern Analysis and Machine Intelligence in 2026 [S1].
