# 3D Gaussian Ray Tracing

Also called: 3DGRT, BVH Ray Tracing for 3D Gaussians, Point-based Ray Tracing on 3D Gaussians, Ray-Splat Intersection via BVH, Splat BVH Traversal

## Overview
3D Gaussian Ray Tracing (3DGRT) is a rendering method that replaces the tile-based rasterization of standard 3D Gaussian Splatting with hardware-accelerated ray tracing using a Bounding Volume Hierarchy (BVH) [S1, unofficial][S4]. It solves the problem of inefficient evaluation in dense scenes where rasterization must process all Gaussians overlapping a tile for every pixel, by traversing a BVH to select and evaluate only the Gaussians intersecting each pixel's ray [S1, unofficial]. Unlike rasterization which relies on screen-space projection, 3DGRT treats Gaussians as semi-transparent volumetric primitives, enabling correct alpha blending and transparency handling through either closest-hit or any-hit shading modes [S3, unofficial].

## How it works
**Inputs:** A set of $N$ 3D Gaussians, each defined by mean $\boldsymbol{\mu}$, covariance $\boldsymbol{\Sigma}$, opacity $\alpha$, and color $\mathbf{c}$. A camera ray $\mathbf{r}(t) = \mathbf{o} + t\mathbf{d}$.
**Outputs:** Pixel color $\mathbf{C}$ and depth.

**Data Structures:**
The method relies on two primary texture-based data structures for GPU acceleration [S3, unofficial]:
1.  **Triangle Texture (`tTriangleTexture`):** Size $2048 \times 2048$ (`TRI_TEXTURE_SIZE`). Each Gaussian (splat) occupies two texels (`id*2` and `id*2+1`).
    *   `vd0.x, y, z`: Position $\boldsymbol{\mu}$ (decoded via `uintBitsToFloat`).
    *   `vd0.w, vd1.x`: First axis vector $\mathbf{u}$ components (decoded via `unpackHalf2x16`).
    *   `vd1.y`: Second component of $\mathbf{u}$.
    *   `vd1.z, w`: RGBA color ($z=$ RGB, $w=$ Alpha).
2.  **AABB Texture (`tAABBTexture`):** Size $4096 \times 4096$ (`AABB_TEXTURE_SIZE`). Each BVH node is one `uvec4`.
    *   `x`: Node ID (negative for inner nodes, positive for leaf splat IDs).
    *   `y`: Min/Max X of AABB (decoded via `unpackHalf2x16`).
    *   `z`: Min/Max Y of AABB.
    *   `w`: Min/Max Z of AABB.

**Algorithm Steps:**

1.  **BVH Construction:** Construct a binary radix tree from the 3D Gaussians. Leaf nodes represent tight bounding boxes of individual Gaussians. Internal nodes denote the bounding box of their two children. This is done using an in-place algorithm to maximize parallelism [S2].
2.  **Ray Tracing Mode Selection:**
    *   **Closest-Hit (`USE_ANYHIT=0`):** Sort children by $t_0$ (near). The stack ensures the closer child is processed first. Used for finding the nearest splat.
    *   **Any-Hit (`USE_ANYHIT=1`):** Sort children by $t_1$ (far). The stack ensures the farther child is processed first. Used for collecting all splats for sorting and correct alpha blending [S3, unofficial].
3.  **BVH Traversal:** Recursively traverse the BVH from the root. Perform intersection tests between the ray and the AABBs of children.
    *   **AABB Intersection:** Compute near/far $t$ values for $x, y, z$ axes.
        $$ t_0 = \max(\max(t_{\min}^x, t_{\min}^y), t_{\min}^z) $$
        $$ t_1 = \min(\min(t_{\max}^x, t_{\max}^y), t_{\max}^z) $$
        Valid if $\max(t_0, 0.0) \le t_1$ [S3, unofficial].
    *   **Pruning:** If `currentStackData.t0 >= t` (current ray hit distance), prune the branch [S3, unofficial].
4.  **Leaf Processing (Splat Intersection):**
    *   If node ID $\ge 0$, fetch the triangle texture for this ID. Decode position $\mathbf{p}$, axis $\mathbf{u}$, axis $\mathbf{v}$, and color/alpha.
    *   Solve for intersection parameters $u, v, t$ in the local space:
        $$ [\mathbf{u} \quad \mathbf{v} \quad \mathbf{d}] \begin{bmatrix} u \\ v \\ -t \end{bmatrix} = \mathbf{o} - \mathbf{p} $$
        Let $\mathbf{uv} = (u, v)$. The hit is valid if $t > 0$ and $\|\mathbf{uv}\|^2 < 1.0$ (inside the unit circle in local space) [S3, unofficial].
    *   **Closest-Hit:** If hit distance $d < t$, update $t$, `splatID`, and `splatRGBA`.
    *   **Any-Hit:** Do not update $t$. Insert the hit into a sorted array `intersects[N_INT]` using insertion sort by depth $d$. Store RGBA. If array is full (`intersectPtr >= N_INT`), return early. $N_{INT} = 32$ [S3, unofficial].
5.  **Equivalent Intersection Point (Analytical Approximation):**
    For semi-transparent Gaussians, the contribution is approximated at an equivalent intersection point $\mathbf{r}_x$ where the Gaussian's contribution peaks [S2]:
    $$ \mathbf{r}_x = \mathbf{o} + t_j \mathbf{d} $$
    $$ t_j = \frac{(\boldsymbol{\mu} - \mathbf{o})^\top \boldsymbol{\Sigma} \mathbf{d}}{\mathbf{d}^\top \boldsymbol{\Sigma} \mathbf{d}} $$
    The opacity contribution $\alpha_j$ is evaluated at this point [S2].
6.  **Transmittance and Color Accumulation:**
    *   **Any-Hit Mode:** Sort collected intersections by depth. Loop through sorted hits.
        $$ \mathbf{C} = \sum T_i \cdot \alpha_i \cdot \mathbf{c}_i $$
        $$ T_i = (1 - \alpha_{i-1}) T_{i-1}, \quad T_1 = 1 $$
        The order of encounter does not affect overall transmittance [S2].
    *   **Closest-Hit Mode (Multi-bounce):** Loop up to 8 bounces.
        $$ \mathbf{C} += T \cdot \text{hitOpacity} \cdot \text{hitColor} $$
        $$ T *= 1.0 - \text{hitOpacity} $$
        Shift ray origin by $t + 10^{-6}$. Break if $T < 0.05$ [S3, unofficial].
7.  **Early Termination:** If transmittance drops below a threshold $T_{min}$, terminate the ray [S2].

**Pseudocode:**

    stack = []
    stack.append((0, 0.0, INFINITY)) # Root node ID 0
    
    hits = [] # List of (depth, alpha, color)
    
    while stack:
        node_id, t0, t1 = stack.pop()
        
        # Fetch AABB from texture
        aabb = fetch_aabb(t_aabb, node_id)
        
        # AABB Intersection Test
        t_min_aabb, t_max_aabb = intersect_aabb(o, d, aabb)
        
        if t_max_aabb < 0.0 or t_min_aabb > t1:
            continue
            
        # Determine valid interval
        t_enter = max(t_min_aabb, t0)
        t_exit = min(t_max_aabb, t1)
        
        if t_enter > t_exit:
            continue
            
        # Check if leaf

        else:

            # Children IDs are derived from node_id (e.g., 2*node_id+1, 2*node_id+2)
            child_left_id = 2 * node_id + 1

## Subtopics

### [GRay](10042-gray.md)
GRay is a fast ray-tracing method for 3D Gaussian Splatting (3DGS) designed to close the performance gap between ray tracing and rasterization by leveraging the algorithmic advantage of ray tracing: it evaluates only intersected Gaussians, allowing logarithmic scaling in dense scenes with tiny Gaussians. Unlike 3DGS rasterization which operates on tiles and evaluates all Gaussians overlapping a tile for every pixel (linear scaling), GRay uses a Bounding Volume Hierarchy (BVH) to select and evaluate exactly the set of Gaussians intersecting each pixel. It builds on [3D Gaussian Ray Tracing](8101-3d-gaussian-ray-tracing.md), [EPBRR](8102-epbrr.md), and [EDGS](8103-edgs.md).

## Operating characteristics
**Time Complexity:** Logarithmic scaling with respect to the number of Gaussians in dense scenes, as the BVH traversal only visits intersected primitives [S1, unofficial]. This contrasts with rasterization's linear scaling per tile.
**Memory Complexity:** Linear with respect to the number of Gaussians for the BVH structure and texture storage [S3, unofficial].
**Performance:** On tested hardware, 3DGRT optimizes about 9× slower than a recent version of 3DGS rasterization [S4].
**Strengths:** Correct handling of transparency and occlusion; efficient culling in sparse or highly occluded scenes; supports multi-bounce reflections/transmissions [S3, unofficial].
**Limitations:** High overhead for simple scenes; register spilling risks requiring batching of evaluations [S4]; precision issues in BVH traversal if float comparisons are not handled carefully [S3, unofficial].
**When to use:** Scenes with high transparency, complex occlusion, or where physical accuracy of light transport is required [S2][S3, unofficial].
**When not to use:** Simple opaque scenes or real-time applications on hardware without efficient BVH traversal support, where rasterization is significantly faster [S4].

## Background
3D Gaussian Ray Tracing was first studied by Moenne-Loccoz et al. in 2024 as an alternative for rendering 3D Gaussians using hardware-accelerated ray tracing (e.g., OptiX) [S4]. It builds on the concept of treating Gaussians as semi-transparent particles with bounding meshes [S1, unofficial]. The method addresses the limitations of rasterization in handling volumetric transparency and complex lighting interactions [S2].
