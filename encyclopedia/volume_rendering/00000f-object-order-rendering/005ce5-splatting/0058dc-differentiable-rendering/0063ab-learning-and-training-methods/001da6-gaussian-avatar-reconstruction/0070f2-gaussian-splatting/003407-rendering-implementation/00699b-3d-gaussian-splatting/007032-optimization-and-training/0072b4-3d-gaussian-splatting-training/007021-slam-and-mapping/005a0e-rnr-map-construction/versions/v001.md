# RNR-Map Construction

Also called: Feature Registration

## Overview
RNR-Map Construction embeds visual information from RGB-D observations into a 2D latent grid map, enabling fast navigation without rendering-based optimization [S1]. It differs from sibling methods like [iMAP](11979-imap.md) by operating directly on latent codes to eliminate the rendering step during mapping, achieving high-frequency operation (91.9Hz) suitable for real-time navigation systems [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** An RGB-D image $I_t \in \mathbb{R}^{H \times W \times 4}$ and the relative pose $\Delta p_t = (\Delta x_t, \Delta y_t, \Delta a_t)$ from the previous pose [S1].
*   **Output:** A local RNR-Map $m_t^l \in \mathbb{R}^{U \times V \times D}$ and a local mask $n_t^l \in \mathbb{Z}^{U \times V}$ [S1].

**Data Structures:**
*   **RNR-Map ($m$):** A 2D grid of size $U \times V$. Each cell $m(u,v)$ stores a latent code vector of dimension $D$ ($m(u,v) \in \mathbb{R}^D$) [S1].
*   **Mask ($n$):** A 2D grid of size $U \times V$. Each cell $n(u,v)$ stores an integer count of the number of latent codes averaged into the corresponding map cell $m(u,v)$ [S1].

**Parameters:**
*   $D$: The channel size (dimensionality) of the latent code feature vector [S1].
*   $K$: Camera intrinsic matrix [S1].
*   $[R|t]$: Extrinsic matrix derived from the agent pose [S1].
*   $s$: Grid resolution (scale factor) mapping world coordinates to grid indices [S1].

**Steps:**
1.  **Pose Estimation:** Compute the absolute pose $p_t$ by cumulating relative pose differences from the start pose $p_0 = (0, 0, 0)$ [S1].
2.  **Encoding:** Encode the input image $I_t$ using a pretrained encoder $\theta_{enc}$ to produce a feature map $C_t \in \mathbb{R}^{H \times W \times D}$ [S1].
3.  **Inverse Projection:** For each pixel $(h, w)$ in $C_t$, calculate its 3D world position $[q_x, q_y, q_z]^T$ using the camera intrinsic $K$, the extrinsic matrix from $p_t$, and the depth value $d_{h,w}$ of the pixel [S1].
4.  **Grid Indexing:** Map the 3D world position to 2D grid indices $(u, v)$:
    $$ u = \left\lfloor \frac{q_x(h,w)}{s} \right\rceil, \quad v = \left\lfloor \frac{q_y(h,w)}{s} \right\rceil $$
    where $\lfloor \cdot \rceil$ denotes rounding to the nearest integer [S1].
5.  **Feature Aggregation:** For each grid cell $(u, v)$, let $X_{(u,v)}$ be the set of feature vectors $c_i$ from pixels mapped to that cell. Update the map and mask:
    $$ m(u,v) = \frac{1}{n(u,v)} \sum_{c_i \in X_{(u,v)}} c_i, \quad n(u,v) = |X_{(u,v)}| $$
    If $n(u,v) = 0$, the cell is empty [S1].

**Pseudocode:**
```python
def rnr_map_construction(I_t, delta_p_t, K, s, theta_enc, prev_m, prev_n):
    """
    Constructs a local RNR-Map from an RGB-D image and relative pose.
    
    Args:
        I_t: RGB-D image tensor of shape (H, W, 4).
        delta_p_t: Relative pose (dx, dy, da) from previous step.
        K: Camera intrinsic matrix.
        s: Grid scale factor.
        theta_enc: Pretrained encoder parameters.
        prev_m: Global map from previous step (U, V, D).
        prev_n: Global mask from previous step (U, V).
        
    Returns:
        m_t_l: Local map (U, V, D).
        n_t_l: Local mask (U, V).
    """
    # 1. Compute absolute pose
    # Note: Cumulative pose logic depends on external state management.
    # Here we assume p_t is computed externally or passed.
    p_t = cumulate_pose(delta_p_t) 
    
    # 2. Encode image
    C_t = encoder(I_t, theta_enc) # Shape: (H, W, D)
    
    # 3. Extract depth and compute 3D positions
    # I_t has 4 channels: R, G, B, Depth
    depth_map = I_t[:, :, 3]
    
    # Initialize local map and mask
    # Using a temporary buffer for the current frame's contributions
    local_m = zeros((U, V, D))
    local_n = zeros((U, V), dtype=int)
    
    H, W, _ = I_t.shape
    
    for h in range(H):
        for w in range(W):
            # Get feature vector
            c = C_t[h, w, :]
            
            # Get depth
            d = depth_map[h, w]
            
            # Inverse projection to get 3D world position
            # Assuming standard pinhole camera model
            # x = K^-1 * [u, v, 1] * d
            # Then transform by extrinsic [R|t]
            # Note: Exact extrinsic matrix construction from p_t is implementation-specific
            # but generally involves rotation and translation based on (x, y, a)
            world_pos = inverse_camera_projection(K, p_t, d, h, w)
            
            q_x, q_y, q_z = world_pos
            
            # Map to grid indices
            u = round(q_x / s)
            v = round(q_y / s)
            
            # Check bounds
            if 0 <= u < U and 0 <= v < V:
                local_m[u, v, :] += c
                local_n[u, v] += 1
                
    # 4. Average features
    for u in range(U):
        for v in range(V):
            if local_n[u, v] > 0:
                local_m[u, v, :] /= local_n[u, v]
                
    return local_m, local_n
```

## Subtopics

### Image-Based Localization (Floc)
Floc finds the grid cell in the RNR-Map closest to a target image $I_{trg}$ by comparing latent codes, outputting a heatmap $E$ and predicted orientation $a_{trg}$ [S1]. It transforms the target image into a local map $m_{trg}$ using $F_{reg}(I_{trg}, p_0; \theta_{enc})$ with origin pose $p_0=(0,0,0)$ [S1]. It processes the global map $m$ and local map $m_{trg}$ through CNNs $F_k$ and $F_q$ to get $m'_k$ and $m'_q$ [S1]. The query map $m'_q$ is rotated into $R$ different angles $\theta_r \in \{0^\circ, ..., 360^\circ \times \frac{R-1}{R}\}$ [S1]. For each rotated query $(m'_q)_r$, it performs cross-correlation (Conv) with $m'_k$ [S1]. The Conv outputs are forwarded to CNN $F_E$ to produce heatmap $E$ and orientation prediction [S1]. The formula is $F_{loc}(m, m_{trg}; \theta_{loc}) = F_E(\mathrm{Conv}(F_k(m), \{F_q(m_{trg})_r\}_1^R))$ [S1]. The loss is $\mathrm{Loss}(\theta_{loc}) = D_{KL}(E_{gt}, \hat{E}) + CE(a_{trg}, \hat{a}_{trg})$, where $D_{KL}$ is KL divergence and $CE$ is cross-entropy for orientation discretized into 18 bins [S1].

## Operating characteristics
*   **Time Complexity:** The mapping operation operates at 91.9Hz [S1].
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:** The mapping and image-based localization frameworks operate at 91.9Hz and 56.8Hz, respectively [S1]. Camera tracking, which requires rendering-based optimization, operates at 5Hz [S1].
*   **Strengths:** Eliminates the rendering step in mapping and localization by directly utilizing latent codes, allowing for fast operation suitable for navigation systems [S1].
*   **Limitations:** Camera tracking still requires rendering-based optimization and is slower (5Hz) [S1].
*   **When to use:** When real-time visual navigation is required and high-frequency mapping is necessary [S1].
*   **When not to use:** When high-precision geometric reconstruction via rendering is required for every step [S1].

## Background
The RNR-Map was introduced in the paper "Renderable Neural Radiance Map for Visual Navigation" [S1]. It is described as the first method combining fast mapping, image-based localization, and navigation capabilities in a single framework [S1]. It is used in various visual navigation tasks including camera tracking, image-based localization, and image-goal navigation [S1].
