# 3D Gaussian Splatting MVP

Also called: 3DGS MVP, pure PyTorch 3DGS

## Overview
3D Gaussian Splatting MVP is a self-contained, pure-PyTorch implementation of the core 3D Gaussian Splatting rendering algorithm, designed as a teaching reference rather than a production renderer [S1, unofficial]. It solves the problem of understanding the mathematical foundations of differentiable Gaussian rasterization by implementing the forward pass and gradient flow without custom CUDA kernels [S1, unofficial]. It sets itself apart from production implementations like [3D Gaussian Splatting Rendering (Software)](2805-3d-gaussian-splatting-rendering-software.md) by using explicit Python loops for rasterization and omitting optimizations such as tile-based sorting, spherical harmonics, and adaptive density control [S1, unofficial].

## How it works
The method renders a set of 3D Gaussians to a 2D image buffer by projecting them into camera space, computing 2D screen-space covariances, sorting by depth, and performing front-to-back alpha compositing [S1, unofficial].

### Inputs and Outputs
*   **Inputs:**
    *   List of $N$ 3D Gaussians, each defined by mean $\mu$, scale $s$, rotation $q$ (unit quaternion), opacity $\alpha$, and RGB color $c$.
    *   Camera parameters: Pinhole camera model with `look_at` function using OpenCV/COLMAP convention [S1, unofficial].
    *   Image dimensions: Height $H$, Width $W$.
*   **Outputs:**
    *   Rendered image tensor of shape $(H, W, 3)$.
    *   (Optional) Depth buffer and transmittance buffer for debugging or further processing.

### Data Structures
Each Gaussian $i$ stores the following fields [S1, unofficial]:
*   `mean`: 3D vector $(x, y, z)$ in world space.
*   `scale`: 3D vector $(s_x, s_y, s_z)$ stored in log-space to ensure positivity during optimization.
*   `rotation`: Unit quaternion $(w, x, y, z)$.
*   `opacity`: Scalar $\alpha \in [0, 1]$.
*   `color`: 3D vector $(r, g, b)$.

The covariance matrix $\Sigma$ is not stored directly but constructed from scale and rotation to ensure it is symmetric positive semi-definite (PSD) [S1, unofficial]:
$$ \Sigma = R S S^T R^T $$
where $R$ is the rotation matrix derived from the unit quaternion, and $S = \text{diag}(e^{s_x}, e^{s_y}, e^{s_z})$ is the scale matrix [S1, unofficial].

### Algorithm Steps
1.  **World-to-Camera Transformation:** Transform each Gaussian mean $\mu_i$ from world space to camera space using the view matrix $W$ [S1, unofficial].
2.  **Covariance Transformation:** Transform the 3D covariance matrix $\Sigma_i$ into the camera frame [S1, unofficial]:
    $$ \Sigma_{i, \text{cam}} = W \Sigma_i W^T $$
3.  **2D Projection:** Project the 3D covariance to the 2D image plane using the EWA / Zwicker-style projection Jacobian $J$ [S1, unofficial]:
    $$ \Sigma_{2d} = J W \Sigma_i W^T J^T $$
    A small isotropic dilation (blur) is added to $\Sigma_{2d}$ for numerical stability [S1, unofficial].
4.  **Depth Sorting:** Sort the Gaussians by their depth (z-coordinate in camera space) in descending order (far to near) using `argsort` [S1, unofficial]. Note that `argsort` is non-differentiable across order changes; gradients flow through the values given the fixed ordering [S1, unofficial].
5.  **Rasterization (Per-Pixel Compositing):** For each pixel $(u, v)$, iterate through the sorted Gaussians that cover the pixel's bounding box. Perform front-to-back alpha compositing using the volume-rendering equation [S1, unofficial]:
    $$ C(u, v) = \sum_{i \in \text{sorted}} c_i \alpha_i T_i $$
    $$ T_i = \prod_{j < i} (1 - \alpha_j) $$
    where $\alpha_i$ is the alpha value of the $i$-th Gaussian at pixel $(u, v)$, computed from the 2D Gaussian distribution:
    $$ \alpha_i = \alpha_{\text{global}, i} \exp\left(-\frac{1}{2} \mathbf{x}^T \Sigma_{2d, i}^{-1} \mathbf{x}\right) $$
    and $\mathbf{x}$ is the vector from the projected mean to the pixel center [S1, unofficial].

### Pseudocode
```python
import torch
import numpy as np

def render_gaussians_mvp(gaussians, camera, H, W):
    """
    Render 3D Gaussians using pure PyTorch.
    
    Args:
        gaussians: Dict with keys 'mean', 'scale', 'rotation', 'opacity', 'color'.
                   Shapes: (N, 3), (N, 3), (N, 4), (N, 1), (N, 3).
        camera: Object with 'view_matrix' (4x4) and 'proj_matrix' (4x4).
        H, W: Image height and width.
        
    Returns:
        image: Tensor (H, W, 3).
    """
    N = gaussians['mean'].shape[0]
    
    # 1. World to Camera Transformation
    # Convert quaternions to rotation matrices
    R = quaternion_to_rotation_matrix(gaussians['rotation']) # (N, 3, 3)
    
    # Construct 3D covariance: Sigma = R S S^T R^T
    S = torch.diag_embed(torch.exp(gaussians['scale'])) # (N, 3, 3)
    Sigma_3d = R @ S @ S.transpose(1, 2) @ R.transpose(1, 2) # (N, 3, 3)
    
    # Transform means to camera space
    means_cam = (camera.view_matrix @ torch.cat([gaussians['mean'], torch.ones(N, 1)], dim=1).unsqueeze(2)).squeeze(2)[:, :3]
    
    # Transform covariance to camera space
    Sigma_cam = camera.view_matrix[:3, :3] @ Sigma_3d @ camera.view_matrix[:3, :3].transpose(1, 2)
    
    # 2. 2D Projection
    # Compute Jacobian J for projection
    # J approximates the projection of 3D points to 2D image plane
    # For pinhole camera: J = K * [I | 0] * W_inv? 
    # Standard EWA projection uses the view matrix and projection matrix.
    # Let's assume a simplified Jacobian for the MVP context as per [S1, unofficial] description.
    # J is typically derived from the projection matrix and the depth.
    # For MVP, we use the standard Zwicker projection:
    # Sigma_2d = J * Sigma_cam * J^T
    # J = K * [1/z 0 -x/z^2; 0 1/z -y/z^2; 0 0 0] ? 
    # Actually, the standard formula is Sigma_2d = J * W * Sigma * W^T * J^T
    # where W is view matrix, J is projection Jacobian.
    
    # Extract depth z
    z = means_cam[:, 2].unsqueeze(1) # (N, 1)
    
    # Projection Jacobian J (simplified for MVP)
    # K is intrinsic matrix. For MVP, we assume normalized device coordinates or simple pinhole.
    # Let's use the standard derivation:
    # x_img = f * X / Z, y_img = f * Y / Z
    # d(x_img)/dX = f/Z, d(x_img)/dZ = -f*X/Z^2
    # This requires intrinsic parameters. MVP uses COLMAP convention.
    # We will assume camera has 'intrinsic_matrix' K.
    K = camera.intrinsic_matrix # (3, 3)
    
    # Compute J
    # J = K * [1/z 0 -x/z^2; 0 1/z -y/z^2; 0 0 0]
    # But we need to transform to screen coordinates.
    # Let's use the standard EWA formula:
    # Sigma_2d = J * Sigma_cam * J^T
    # J = K * [1/z 0 -x/z^2; 0 1/z -y/z^2; 0 0 0]
    
    x = means_cam[:, 0]
    y = means_cam[:, 1]
    
    J = torch.zeros(N, 2, 3)
    J[:, 0, 0] = K[0, 0] / z.squeeze()
    J[:, 0, 2] = -K[0, 0] * x / (z.squeeze()**2)
    J[:, 1, 1] = K[1, 1] / z.squeeze()
    J[:, 1, 2] = -K[1, 1] * y / (z.squeeze()**2)
    
    Sigma_2d = J @ Sigma_cam @ J.transpose(1, 2) # (N, 2, 2)
    
    # Add isotropic blur for stability
    Sigma_2d[:, 0, 0] += 0.3
    Sigma_2d[:, 1, 1] += 0.3
    
    # 3. Depth Sort
    # Sort by z-depth (descending, far to near)
    _, sort_indices = torch.sort(z.squeeze(), descending=True)
    
    sorted_gaussians = {k: v[sort_indices] for k, v in gaussians.items()}
    Sigma_2d_sorted = Sigma_2d[sort_indices]
    means_cam_sorted = means_cam[sort_indices]
    
    # 4. Rasterization
    image = torch.zeros(H, W, 3, device=gaussians['mean'].device)
    T = torch.ones(H, W, 1, device=gaussians['mean'].device) # Transmittance
    
    # Iterate over Gaussians (Python loop for readability [S1, unofficial])
    for i in range(N):
        mu = means_cam_sorted[i]
        sigma = Sigma_2d_sorted[i]
        alpha_global = gaussians['opacity'][i]
        color = gaussians['color'][i]
        
        # Compute bounding box for this Gaussian
        # Eigenvalues of Sigma_2d determine spread
        eigenvalues = torch.linalg.eigvals(sigma)
        radius = torch.sqrt(torch.max(eigenvalues)) * 3.0 # 3 sigma
        radius = max(1.0, radius.item())
        
        cx, cy = mu[0], mu[1]
        min_x, max_x = int(max(0, cx - radius)), int(min(W, cx + radius))
        min_y, max_y = int(max(0, cy - radius)), int(min(H, cy + radius))
        
        # Create grid for pixels in bounding box
        y_coords, x_coords = torch.meshgrid(torch.arange(min_y, max_y), 
                                            torch.arange(min_x, max_x), indexing='ij')
        coords = torch.stack([x_coords, y_coords], dim=-1).float() # (H', W', 2)
        
        # Vector from mean to pixel
        diff = coords - torch.tensor([cx, cy], device=gaussians['mean'].device) # (H', W', 2)
        
        # Compute alpha
        # alpha = alpha_global * exp(-0.5 * diff^T Sigma^{-1} diff)
        sigma_inv = torch.inverse(sigma)
        exponent = -0.5 * (diff @ sigma_inv * diff).sum(dim=-1) # (H', W')
        alpha_local = alpha_global * torch.exp(exponent)
        
        # Composite
        alpha_clamped = torch.clamp(alpha_local, 0, 1)
        contrib = alpha_clamped.unsqueeze(-1) * T * color.unsqueeze(0).unsqueeze(0)
        
        image[min_y:max_y, min_x:max_x] += contrib
        T[min_y:max_y, min_x:max_x] *= (1 - alpha_clamped).unsqueeze(-1)
        
        # Early exit if fully opaque
        if T.min() < 1e-5:
            break
            
    return image

def quaternion_to_rotation_matrix(q):
    """Convert unit quaternion (w, x, y, z) to rotation matrix (3, 3)."""
    w, x, y, z = q[:, 0], q[:, 1], q[:, 2], q[:, 3]
    R = torch.zeros(q.shape[0], 3, 3, device=q.device)
    R[:, 0, 0] = 1 - 2 * (y**2 + z**2)
    R[:, 0, 1] = 2 * (x*y - w*z)
    R[:, 0, 2] = 2 * (x*z + w*y)
    R[:, 1, 0] = 2 * (x*y + w*z)
    R[:, 1, 1] = 1 - 2 * (x**2 + z**2)
    R[:, 1, 2] = 2 * (y*z - w*x)
    R[:, 2, 0] = 2 * (x*z - w*y)
    R[:, 2, 1] = 2 * (y*z + w*x)
    R[:, 2, 2] = 1 - 2 * (x**2 + y**2)
    return R
```

### Parameters
*   **Isotropic Dilation:** A small constant (e.g., 0.3) added to the diagonal of $\Sigma_{2d}$ for stability [S1, unofficial].
*   **Bounding Box Radius:** Typically $3\sigma$ (sqrt of max eigenvalue of $\Sigma_{2d}$) [S1, unofficial].
*   **Iterations:** In the demo, 600 iterations of Adam optimization were used [S1, unofficial].

### Edge Cases and Pitfalls
*   **Depth Sort Non-Differentiability:** The `argsort` operation is non-differentiable when the order of Gaussians changes. Gradients flow through the values given the fixed ordering, which is acceptable for fit-from-scratch demos but can cause instability in complex scenes [S1, unofficial].
*   **Precision:** Using pure PyTorch on CPU is slow; end-to-end run takes ~30 seconds for a 64x64 image [S1, unofficial].
*   **Missing Features:** The MVP intentionally skips tile-based CUDA rasterizer, spherical harmonics, adaptive density control, real captures, and SSIM losses [S1, unofficial].

## Subtopics

### [3D Gaussian Splatting with Gaussian Unpooling](6133-3d-gaussian-splatting-with-gaussian-unpooling.md)
FSGS is a method for reconstructing 3D scenes from sparse-view inputs, addressing the challenge of insufficient initialization data for standard 3D Gaussian Splatting. It distinguishes itself from dense-view baselines by using Gaussian unpooling to expand a sparse set of Structure-from-Motion (SfM) points into a denser set of Gaussians, enabling faithful geometry reconstruction where standard methods fail due to lack of initial coverage.

### [Relightable 3DGS](7851-relightable-3dgs.md)
Relightable 3DGS extends standard 3D Gaussian Splatting by embedding physically-based material properties into each Gaussian, enabling deferred shading and realistic rendering of complex appearances such as reflections, transparency, and glossy surfaces. Unlike standard rasterization which approximates view-dependent colors via spherical harmonics and fails to represent specular reflections or global illumination, this method decomposes outgoing radiance into a BRDF integration that respects material parameters. It sets itself apart from its siblings by decoupling geometry processing from lighting and material computations, adapting a two-pass deferred pipeline to Gaussian Splatting for efficient rendering of high-frequency, view-dependent effects.

### PRoGS
PRoGS is a post-training technique for 3D Gaussian Splatting that approximates each Gaussian's contribution to the final scene to construct a prioritization order, enabling progressive rendering or streaming by dynamically selecting splats to display or transmit [S1, unofficial]. Unlike existing web-viewers that require full scene retrieval before rendering, PRoGS loads a representative subset early, significantly reducing time-to-first-paint while maintaining perceptual quality [S1, unofficial]. It is designed for on-device rendering applications constrained by memory and streaming applications requiring minimal bandwidth [S1, unofficial].

### [3D Gaussian Splatting Rendering Pipeline (RViz Plugin)](10297-3d-gaussian-splatting-rendering-pipeline-rviz-plugin.md)
This article describes the OpenGL-based rendering pipeline for visualizing 3D Gaussian Splatting data within the ROS RViz environment. It solves the problem of efficiently rendering millions of 2D-projected Gaussian splats as a single instanced draw call, handling depth sorting and view-dependent shading. It differs from pure software implementations by leveraging GPU-based sorting and texture buffer objects (TBOs) for data storage, and from other RViz plugins by supporting both exact back-to-front sorting and Order-Independent Transparency (WBOIT) approximations.

### [CPU-based Gaussian Splatting Thumbnailer with JIT Optimization](14069-cpu-based-gaussian-splatting-thumbnailer-with-jit-optimizati.md)
This method provides a lightweight, CPU-only pipeline for generating rapid visual thumbnails from 3D Gaussian Splatting datasets, prioritizing responsiveness and portability over high-fidelity rendering. It distinguishes itself from standard GPU-accelerated splatting by omitting rotation parameters, approximating Gaussians as spheres, and leveraging Python's Numba JIT compiler to achieve near-real-time performance on constrained hardware.

### OmniGS
A novel omnidirectional Gaussian splatting system that takes calibrated monocular 360-degree images and sparse SfM point clouds as input to recover 3D Gaussians for fast radiance field reconstruction and real-time omnidirectional novel view synthesis.

## Operating characteristics
*   **Time Complexity:** $O(N \cdot H \cdot W)$ in the worst case if every Gaussian covers every pixel, but typically $O(N \cdot B)$ where $B$ is the average bounding box area. The MVP implementation uses a Python loop, making it significantly slower than GPU-accelerated versions.
*   **Memory Complexity:** $O(N)$ to store Gaussian parameters and $O(H \cdot W)$ for the image buffer.
*   **Measured Performance:** End-to-end run takes ~30 seconds on CPU for a 64x64 image [S1, unofficial].
*   **Strengths:** High readability, no custom CUDA kernels, easy to debug and modify, suitable for educational purposes.
*   **Limitations:** Slow on CPU, lacks optimizations like tile-based sorting, spherical harmonics, and adaptive density control, not suitable for real-time rendering or large scenes [S1, unofficial].
*   **When to Use:** For learning the mathematical details of 3D Gaussian Splatting, debugging specific components, or when GPU resources are unavailable.
*   **When Not to Use:** For production rendering, real-time applications, or large-scale scenes.

## Background
3D Gaussian Splatting was introduced by Kerbl et al. in SIGGRAPH 2023 [S1, unofficial]. The MVP implementation is a self-contained Jupyter notebook created by Devin AI integration, intended as a teaching reference [S1, unofficial]. It implements the core algorithm in pure PyTorch, allowing users to "grind on the math" without the complexity of custom CUDA kernels [S1, unofficial].
