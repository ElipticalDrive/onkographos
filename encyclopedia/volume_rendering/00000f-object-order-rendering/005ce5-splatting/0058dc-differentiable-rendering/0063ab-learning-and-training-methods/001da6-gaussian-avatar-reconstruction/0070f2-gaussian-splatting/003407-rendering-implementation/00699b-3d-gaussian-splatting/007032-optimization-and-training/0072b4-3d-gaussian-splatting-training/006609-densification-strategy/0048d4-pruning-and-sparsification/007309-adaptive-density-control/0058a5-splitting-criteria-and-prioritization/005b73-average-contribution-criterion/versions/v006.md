# Average Contribution Criterion

Also called: Ours

## Overview
The Average Contribution Criterion is a densification strategy for 3D Gaussian Splatting that determines whether a Gaussian should be split or cloned based on its mean blending weight per view rather than a binary view count [S1, unofficial]. It solves the problem of occlusion bias inherent in the original 3D Gaussian Splatting criterion, where fully occluded views inflate the denominator and dilute the gradient signal, leading to inefficient densification [S1, unofficial]. Unlike sibling methods that rely on pixel counts or distance scaling, this criterion is intrinsically self-limiting and independent of scene extent, producing fewer Gaussians at matched quality [S1, unofficial].

## How it works
The method computes a scalar densification score $\gamma_i^{\text{Ours}}$ for each Gaussian $i$ by aggregating per-view gradient magnitudes and normalizing them by the Gaussian's average visibility across views [S1, unofficial].

**Inputs and Outputs:**
*   **Input:** For a Gaussian $i$, the set of views $v$ in which it contributes to at least one pixel. For each such view, the per-pixel blending weights $w_{i,p}$ and the positional gradients of the training loss with respect to the projected screen-space mean $\mu_i$.
*   **Output:** A scalar score $\gamma_i^{\text{Ours}}$. If $\gamma_i^{\text{Ours}} > \tau$, the Gaussian is densified (split or cloned) [S1, unofficial].

**Data Structures and Formulas:**
The core formula is:
$$ \gamma_i^{\text{Ours}} = \frac{1}{1 + \sum_v \bar{w}_{i,v}} \sum_v \|g_{i,v}\| $$
where:
*   $\bar{w}_{i,v}$ is the mean blending weight of Gaussian $i$ in view $v$.
*   $g_{i,v}$ is the accumulated gradient vector for view $v$.
*   The constant $1$ in the denominator is a floor to prevent divergence for rarely observed Gaussians [S1, unofficial].

The mean blending weight $\bar{w}_{i,v}$ is calculated over the $N_{i,v}$ pixels in view $v$ where Gaussian $i$ contributes ($w_{i,p} > 0$):
$$ \bar{w}_{i,v} = \frac{1}{N_{i,v}} \sum_{p \in \text{pixels}_v} w_{i,p} $$
where $w_{i,p} = \alpha_{i,p} T_{i,p}$ is the blending weight, $\alpha_{i,p}$ is the opacity, and $T_{i,p}$ is the transmittance [S1, unofficial].

The per-view gradient $g_{i,v}$ is accumulated over pixels where the Gaussian contributes:
$$ g_{i,v} = \sum_{p \in \text{pixels}_v} w_{i,p} s_{i,p} $$
where $s_{i,p}$ is a weight-independent vector combining the photometric residual, geometric steering direction, and local contrast of the Gaussian's color against the background [S1, unofficial]. The magnitude $\|g_{i,v}\|$ is the Euclidean norm of this 2D vector [S1, unofficial].

**Parameters:**
*   **Densification Threshold ($\tau$):** 0.002. This value was calibrated on a subset of the Mip-NeRF360 dataset (bicycle, bonsai, counter, garden) and kept fixed for all experiments [S1, unofficial].
*   **Denominator Floor:** 1. This ensures scores increase smoothly for rarely observed Gaussians and prevents unbounded scores when $\sum_v \bar{w}_{i,v} \to 0$ [S1, unofficial].

**Pseudocode:**
```python
def compute_average_contribution_score(gaussian_i, views):
    """
    Computes the densification score for a Gaussian based on average contribution.
    
    Args:
        gaussian_i: The Gaussian object containing its parameters.
        views: A list of view indices where gaussian_i contributes to at least one pixel.
        
    Returns:
        gamma: The densification score.
    """
    sum_gradient_magnitudes = 0.0
    sum_mean_blending_weights = 0.0
    
    for v in views:
        # 1. Calculate mean blending weight for view v
        # Identify pixels p where gaussian_i contributes (w_i,p > 0)
        contributing_pixels = get_contributing_pixels(gaussian_i, v)
        N_i_v = len(contributing_pixels)
        
        if N_i_v == 0:
            continue
            
        sum_w = 0.0
        sum_gradient_vector = [0.0, 0.0] # 2D vector (x, y)
        
        for p in contributing_pixels:
            # Get blending weight w_i,p = alpha_i,p * T_i,p
            w_i_p = get_blending_weight(gaussian_i, p, v)
            
            # Accumulate mean blending weight
            sum_w += w_i_p
            
            # Get weight-independent gradient factor s_i,p
            # s_i,p combines photometric residual, geometric steering, and local contrast
            s_i_p = get_gradient_factor(gaussian_i, p, v)
            
            # Accumulate gradient vector g_i,v = sum(w_i,p * s_i,p)
            sum_gradient_vector[0] += w_i_p * s_i_p[0]
            sum_gradient_vector[1] += w_i_p * s_i_p[1]
            
        # Calculate mean blending weight bar_w_i,v
        bar_w_i_v = sum_w / N_i_v
        sum_mean_blending_weights += bar_w_i_v
        
        # Calculate magnitude of accumulated gradient ||g_i,v||
        g_i_v_x = sum_gradient_vector[0]
        g_i_v_y = sum_gradient_vector[1]
        gradient_magnitude = sqrt(g_i_v_x**2 + g_i_v_y**2)
        sum_gradient_magnitudes += gradient_magnitude
        
    # Calculate final score gamma_i^Ours
    # Denominator floor is 1
    denominator = 1.0 + sum_mean_blending_weights
    gamma = sum_gradient_magnitudes / denominator
    
    return gamma
```

**Edge Cases and Pitfalls:**
*   **Divergence:** Without the denominator floor (1), rarely observed Gaussians with $\sum_v \bar{w}_{i,v} \to 0$ receive unbounded scores, causing training divergence [S1, unofficial].
*   **Threshold Sensitivity:** A threshold of 0.001 leads to over-densification (4.90M Gaussians, lower PSNR), while 0.004 leads to under-densification (0.66M Gaussians, higher LPIPS) [S1, unofficial].
*   **Occlusion Handling:** The criterion is occlusion-aware because $\bar{w}_{i,v}$ includes transmittance $T_{i,p}$. Fully occluded views contribute 0 to the sum of mean blending weights but also 0 to the gradient sum, avoiding the bias of the original 3DGS criterion which weights all views equally [S1, unofficial].

## Operating characteristics
*   **Time and Memory Complexity:** The criterion adds a small overhead per densification step to compute mean blending weights and gradient magnitudes. It is self-limiting, keeping the Gaussian count bounded (e.g., 2.75M at 300k iterations on Zip-NeRF) compared to unstable alternatives [S1, unofficial].
*   **Measured Performance:**
    *   On Zip-NeRF scenes (30k iterations): 25.81 PSNR, 0.830 SSIM, 0.330 LPIPS, 0.106 GMSD, using 1.133M Gaussians in 29.9 minutes [S1, unofficial].
    *   On Zip-NeRF scenes (210k iterations): 26.60 PSNR, 0.852 SSIM, 0.282 LPIPS, 0.087 GMSD, using 2.495M Gaussians in 262.9 minutes [S1, unofficial].
    *   On Deep Blending (Reset): 29.90 PSNR, 0.902 SSIM, 0.231 LPIPS using 1.656M Gaussians [S1, unofficial].
    *   On Deep Blending (Decay): 30.03 PSNR, 0.905 SSIM, 0.234 LPIPS using 0.894M Gaussians [S1, unofficial].
*   **Scaling:** The method scales well to large scenes (Zip-NeRF) without diverging, unlike raw pixel-count criteria which can exceed 16.8M Gaussians and crash [S1, unofficial].
*   **Strengths:** Intrinsically self-limiting, no need for distance scaling guard rails, fewer Gaussians (55–75% of other criteria's counts) at matched quality, occlusion-aware [S1, unofficial].
*   **Limitations:** Requires calibration of the threshold (0.002) on a subset, though it is kept fixed thereafter [S1, unofficial].

## Background
The Average Contribution Criterion was introduced in "Counting Contributions, Not Views: Occlusion-Aware Densification for 3D Gaussian Splatting" [S1, unofficial]. It addresses limitations in the original 3D Gaussian Splatting densification strategy, which weights all observed views equally regardless of visibility [S1, unofficial]. The method was developed to reduce waste from occluded views and improve efficiency on large, occlusion-heavy scenes like Zip-NeRF [S1, unofficial].
