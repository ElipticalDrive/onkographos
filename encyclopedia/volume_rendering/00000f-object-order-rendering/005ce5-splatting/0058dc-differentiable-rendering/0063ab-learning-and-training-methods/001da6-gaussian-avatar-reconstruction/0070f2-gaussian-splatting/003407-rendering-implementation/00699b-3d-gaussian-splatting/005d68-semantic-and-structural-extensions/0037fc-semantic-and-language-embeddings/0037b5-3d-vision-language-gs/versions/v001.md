# 3D Vision-Language GS

Also called: SplatTalk

## Overview
3D Vision-Language GS projects vision-language models into the 3D Gaussian Splatting (3DGS) framework to enable 3D visual question answering and zero-shot semantic reasoning via natural language queries on rendered feature maps [S1, unofficial]. It builds on [Semantic and Language Embeddings](8130-semantic-and-language-embeddings.md) by training a joint embedding space where the differentiable alpha-blending accumulation produces feature vectors directly comparable to text embeddings. Unlike [Language Embedded 3D Gaussians](8103-language-embedded-3d-gaussians.md) which encode object-level embeddings for phrase grounding, this method focuses on querying the continuous feature field with natural language to perform open-vocabulary segmentation and reasoning [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of 3D Gaussians $\mathcal{G}$ with attributes (position, covariance, opacity, color) and a natural language query $q$.
*   **Output:** A segmentation mask or semantic label map corresponding to the query $q$.

**Data Structures:**
*   **Gaussian Set $\mathcal{G}$:** Each Gaussian $i$ has opacity $\alpha_i$, position $\mathbf{p}_i$, and a feature vector $\mathbf{f}_i$ in the joint vision-language embedding space.
*   **Instance Index $I_{stable}$:** A subset of Gaussians or clusters identified as stable semantic instances.

**Algorithm Steps:**
1.  **Instance Filtering:** Identify stable instances $I_{stable}$ using match and miss thresholds:
    $$ I_{stable} = \{ j : \text{match}_j \ge \theta_{match} \land \text{miss}_j \le \theta_{miss} \} $$
    [S2, unofficial]
2.  **Isolated Rendering:** For each instance $j \in I_{stable}$, render the Gaussian $G_j$ alone from its top-$B$ training views $V_j$ (ranked by projected area). All other Gaussians are set to zero opacity to prevent neighboring-instance leakage [S2, unofficial].
3.  **Cropping:** Crop the rendered image to the instance's bounding box.
4.  **Embedding Extraction:** Compute the CLIP image embedding for each crop:
    $$ \mathbf{c}_{j,t} = \text{CLIP}_{\text{img}}(\text{Crop}(I_{\text{isoRender}}(G_j, \text{cam}_t))) $$
    where $t \in V_j$ [S2, unofficial].
5.  **Aggregation:** Average the embeddings across views to get $\bar{\mathbf{c}}_j$:
    $$ \bar{\mathbf{c}}_j = \frac{1}{|V_j|} \sum_{t \in V_j} \mathbf{c}_{j,t} $$
    [S2, unofficial]
6.  **Normalization:** L2-normalize to obtain the instance embedding $\mathbf{e}_j$:
    $$ \mathbf{e}_j = \frac{\bar{\mathbf{c}}_j}{\|\bar{\mathbf{c}}_j\|_2} $$
    [S2, unofficial]
7.  **Query Matching:** At query time, encode the prompt $q$ using CLIP text encoder $\text{CLIP}_{\text{text}}(q)$. Find the best matching instance $j^*$:
    $$ j^* = \arg \max_{j \in I_{stable}} \cos(\mathbf{e}_j, \text{CLIP}_{\text{text}}(q)) $$
    [S2, unofficial]
8.  **Mask Generation:** Render the label map $\hat{L}_{\text{test}}$ at the test viewpoint. The predicted mask is:
    $$ M_q = \mathbb{I}[\hat{L}_{\text{test}} = j^*] $$
    [S2, unofficial]

**Pseudocode:**
```python
def query_3d_vision_language(gs_model, query_text, test_viewpoint):
    """
    gs_model: Object containing 3D Gaussians and rendering functions.
    query_text: String, the natural language query.
    test_viewpoint: Camera parameters for the test view.
    Returns: Binary mask M_q.
    """
    # 1. Encode Query
    query_emb = clip_text_encoder(query_text)
    
    # 2. Retrieve Stable Instances
    # Assumes I_stable is pre-computed or computed via match/miss scores
    stable_instances = get_stable_instances(gs_model)
    
    best_match_score = -1
    best_instance_id = None
    
    # 3. Match against Instance Embeddings
    for inst_id in stable_instances:
        # Retrieve pre-computed or compute on-the-fly instance embedding e_j
        # Note: In training-free inference, e_j is often pre-computed or cached.
        # If computing on-the-fly:
        #   crops = []
        #   for view in inst_id.top_B_views:
        #       # Render G_inst alone
        #       img = render_single_gaussian(gs_model, inst_id, view, zero_out_others=True)
        #       # Crop to bounding box
        #       crop = crop_to_bbox(img, inst_id.bbox)
        #       # Get CLIP embedding
        #       emb = clip_image_encoder(crop)
        #       crops.append(emb)
        #   e_j = normalize(mean(crops))
        
        e_j = get_instance_embedding(inst_id)
        
        # Cosine similarity
        score = cosine_similarity(e_j, query_emb)
        
        if score > best_match_score:
            best_match_score = score
            best_instance_id = inst_id
            
    # 4. Generate Mask
    # Render full label map for test viewpoint
    label_map = render_label_map(gs_model, test_viewpoint)
    
    # Create mask where label matches best instance
    mask = (label_map == best_instance_id).astype(float)
    
    return mask
```

**Parameters:**
*   $\theta_{match}, \theta_{miss}$: Thresholds for instance stability. Not given in the sources.
*   $B$: Number of top training views for instance embedding computation. Not given in the sources.

**Edge Cases:**
*   **Instance Leakage:** Rendering all Gaussians simultaneously can cause neighboring-instance leakage into the embedding. Isolated rendering (zeroing other Gaussians) is required [S2, unofficial].
*   **Empty Query Match:** If no instance exceeds a similarity threshold, the query may return no segmentation.

## Subtopics

### CLIP Visual Retrieval
A variant that uses CLIP image embeddings from isolated renders of individual Gaussians or clusters to match against CLIP text embeddings. It relies on L2-normalized average embeddings from multiple views to form a robust instance representation [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Query time is $O(|I_{stable}|)$ cosine similarities per prompt [S2, unofficial]. Rendering is linear in the number of Gaussians.
*   **Memory Complexity:** Requires storing instance embeddings and label maps.
*   **Strengths:** Enables real-time open-vocabulary semantic segmentation and 3D visual question answering [S1, unofficial].
*   **Limitations:** Relies on the quality of the joint embedding space and the stability of instance detection.

## Background
3D Vision-Language GS, also known as SplatTalk, was introduced to extend 3DGS with vision-language capabilities [S1, unofficial]. It builds on earlier work like Language Embedded 3D Gaussians [104] and projects vision-language models into the 3DGS framework to enable zero-shot semantic reasoning [S1, unofficial].
