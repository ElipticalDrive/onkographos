# Spherical Harmonics Vector Quantization

Also called: SH clustering, SH palette

## Overview
Spherical Harmonics Vector Quantization (SH VQ) is a compression technique for 3D Gaussian Splatting that replaces per-splat SH coefficients with indices pointing to a shared palette of distinct SH vectors, significantly reducing memory footprint at the cost of minor lighting artifacts [S1, unofficial][S2]. Unlike methods that exploit spatial correlation between neighbors, SH VQ treats each Gaussian's SH-AC vector independently, mapping it to the nearest codevector in a pre-computed palette [S2]. This approach is distinct from [Closed-Form Scene Appearance Estimation](16750-closed-form-scene-appearance-estimation.md) which estimates appearance analytically, and [Adaptive SH Regularization](16786-adaptive-sh-regularization.md) which constrains coefficient magnitudes during training; instead, SH VQ operates as a post-processing or offline optimization step to reduce storage and transmission size [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $N$ Gaussian primitives, each with a set of SH coefficients $C_i \in \mathbb{R}^{45}$ (excluding the DC term, which is treated as color). The coefficients represent the directional variation for RGB channels (15 floats per channel, 45 total) [S1, unofficial].
*   **Output:** A palette of $K$ SH vectors $P \in \mathbb{R}^{K \times 45}$ and an index array $I \in \mathbb{Z}^{N}$ where $I_i$ is the index into $P$ for the $i$-th Gaussian [S1, unofficial].

**Data Structures:**
1.  **Palette ($P$):** A list of $K$ vectors. Each vector contains 45 floating-point numbers. Typically stored as FP16 (16-bit float) to save space [S1, unofficial].
2.  **Indices ($I$):** An array of size $N$. Each entry is a 16-bit unsigned integer, allowing for up to 65,536 distinct palette entries [S1, unofficial].

**Parameters:**
*   **Palette Size ($K$):** Typically between 4,000 and 16,000 items [S1, unofficial].
*   **SH Dimensionality:** 45 floats per splat (excluding DC) [S1, unofficial].
*   **Precision:** FP16 for palette storage [S1, unofficial].

**Algorithm Steps:**
1.  **Collect Data:** Gather all $N$ SH coefficient vectors from the scene, excluding the zeroth-order (DC) coefficient [S1, unofficial].
2.  **Cluster:** Perform vector quantization (clustering) on the $N$ vectors to find $K$ representative centroids. This is typically done using a variant of mini-batch k-means [S1, unofficial].
    *   *Note:* Standard libraries like scikit-learn are too slow for this dimensionality and scale. Custom implementations or optimized libraries like Faiss are preferred, though custom mini-batch k-means can be ~3x faster than Faiss for this specific task [S1, unofficial].
3.  **Assign Indices:** For each original SH vector $C_i$, find the index $k$ of the palette vector $P_k$ that minimizes the Euclidean distance $\| C_i - P_k \|_2$ [S1, unofficial].
4.  **Store:** Save the palette $P$ and the index array $I$ [S1, unofficial].

**Pseudocode:**
```python
def spherical_harmonics_vector_quantization(sh_data: List[List[float]], k: int) -> Tuple[List[List[float]], List[int]]:
    """
    sh_data: List of N vectors, each of length 45 (SH-AC coefficients).
    k: Number of palette entries (e.g., 4000 or 16000).
    Returns: (palette, indices)
    """
    n = len(sh_data)
    
    # Step 1: Initialize centroids using k-means++ or random sampling
    # [G] Standard k-means++ initialization is assumed for robustness
    centroids = initialize_centroids(sh_data, k)
    
    # Step 2: Mini-batch K-Means Clustering
    # [G] Using a standard mini-batch k-means loop
    for iteration in range(max_iterations):
        # Sample a mini-batch of indices
        batch_indices = random.sample(range(n), batch_size)
        batch_vectors = [sh_data[i] for i in batch_indices]
        
        # Assign batch vectors to nearest centroid
        assignments = []
        for vec in batch_vectors:
            dists = [euclidean_distance(vec, c) for c in centroids]
            assignments.append(argmin(dists))
            
        # Update centroids based on batch assignments
        for j in range(k):
            members = [batch_vectors[m] for m, a in enumerate(assignments) if a == j]
            if members:
                centroids[j] = mean(members)
                
    palette = centroids
    
    # Step 3: Assign final indices for all splats
    indices = []
    for vec in sh_data:
        dists = [euclidean_distance(vec, p) for p in palette]
        indices.append(argmin(dists))
        
    return palette, indices

def euclidean_distance(v1: List[float], v2: List[float]) -> float:
    return sum((a - b) ** 2 for a, b in zip(v1, v2)) ** 0.5

def argmin(lst: List[float]) -> int:
    return min(range(len(lst)), key=lambda i: lst[i])
```

**Edge Cases and Pitfalls:**
*   **Curse of Dimensionality:** Clustering millions of splats in 45 dimensions is computationally expensive and slow [S1, unofficial].
*   **Localized Color Inconsistency:** Because SH VQ independently quantizes each Gaussian without using spatial predictions from neighbors, a Gaussian may be assigned a codevector with color characteristics differing from its surroundings, causing localized color artifacts [S2]. This is a known limitation compared to methods exploiting spatial correlation [S2].

## Subtopics

### VQ-Based SH-AC Compression
A variant that independently quantizes the SH-AC vector of each Gaussian by mapping it to a VQ codevector, rather than exploiting spatial correlation between neighbors [S2]. It is chosen when bitstream size reduction is prioritized over local color consistency [S2]. At RP2 on the Bartender dataset, this method produces a bitstream size of 7.44 MB, smaller than the anchor's 9.60 MB [S2]. However, it may cause localized color distortions inconsistent with surrounding tones because the codevector selection does not use reconstructed values or spatial predictions of neighboring Gaussians [S2].

## Operating characteristics
*   **Time Complexity:** Clustering is the bottleneck. Mini-batch k-means on millions of 45-dimensional vectors is slow due to the curse of dimensionality [S1, unofficial]. Custom implementations can be ~3x faster than Faiss and significantly faster than scikit-learn [S1, unofficial].
*   **Memory Complexity:**
    *   Palette: $K \times 45 \times 2$ bytes (for FP16). For $K=16,000$, this is ~1.44 MB [S1, unofficial].
    *   Indices: $N \times 2$ bytes. For $N=6.1$ million (Bike scene), this is ~12 MB [S1, unofficial].
    *   Total SH storage: ~13.44 MB for the Bike scene with $K=16,000$ [S1, unofficial].
*   **Measured Performance:**
    *   **Bike Scene (6.1M splats):**
        *   Low Preset ($K=16k$): Data sizes 98MB, 41MB, 93MB; PSNR 35.17, 35.32, 35.00 [S1, unofficial].
        *   Very Low Preset ($K=4k$): Data sizes 79MB, 33MB, 75MB; PSNR 32.27, 30.19, 31.10 [S1, unofficial].
    *   **Bartender Dataset:** VQ-based SH-AC compression yields 7.44 MB bitstream vs 9.60 MB for the anchor at RP2 [S2].
*   **Strengths:** Significant reduction in data size (e.g., from 1.1 GB raw SH to ~13 MB for indices+palette in Bike scene) [S1, unofficial]. Retains "shininess" effects [S1, unofficial].
*   **Limitations:** Minor lighting artifacts and potential localized color inconsistencies [S1, unofficial][S2]. Computationally intensive clustering phase [S1, unofficial].
*   **When to use:** When memory bandwidth or storage is constrained, and slight quality loss is acceptable (e.g., mobile or web deployment) [S1, unofficial].
*   **When not to use:** When high-fidelity color consistency across adjacent Gaussians is critical and spatial correlation methods are viable [S2].

## Background
SH VQ was introduced as a practical compression technique for 3D Gaussian Splatting to address the large memory footprint of SH coefficients, which constitute the majority of raw uncompressed data [S1, unofficial]. It draws inspiration from traditional computer graphics palette-based rendering and vector quantization techniques [S1, unofficial]. The method has been implemented in custom Gaussian Splatting runtimes (e.g., for Unity) to enable lower-quality presets that are still visually usable [S1, unofficial]. A related academic approach, VQ-Based SH-AC Compression, further explores this concept within the context of HEVC-based compression pipelines [S2].
