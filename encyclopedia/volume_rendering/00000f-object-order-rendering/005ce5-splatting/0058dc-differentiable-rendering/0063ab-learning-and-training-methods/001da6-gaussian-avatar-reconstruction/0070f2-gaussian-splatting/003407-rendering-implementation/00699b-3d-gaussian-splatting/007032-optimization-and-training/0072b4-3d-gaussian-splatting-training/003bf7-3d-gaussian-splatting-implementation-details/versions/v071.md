# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, GSGEN Implementation Details, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific hyperparameters, data structures, and optimization schedules required to implement the 3D Gaussian Splatting (3DGS) training pipeline, building on the differentiable rasterization core described in [Optimization and Parallelization](6233-optimization-and-parallelization.md). It solves the problem of translating the theoretical 3DGS formulation into a stable, high-fidelity training loop by specifying densification thresholds, pruning criteria, and hardware-aware precision settings. It sets itself apart from sibling methods by providing the concrete numerical constants and iteration schedules (e.g., gradient thresholds, opacity limits) that govern the adaptive density control, which is critical for preventing overfitting or under-reconstruction in standard implementations.

## How it works

### Inputs and Outputs
**Inputs:**
*   Sparse point cloud from Structure-from-Motion (SfM) [S4].
*   Camera poses and intrinsics for training views [S3].
*   Ground-truth images for supervision [S3].
*   Initial Gaussian parameters: position $\mathbf{p}$, covariance $\mathbf{\Sigma}$ (or scale $\mathbf{s}$ and rotation $\mathbf{q}$), opacity $\alpha$, and spherical harmonic (SH) coefficients $\mathbf{c}$ [S3].

**Outputs:**
*   Optimized set of 3D Gaussians $\mathcal{G}$ with refined parameters.
*   Rendered novel views via differentiable rasterization [6233-optimization-and-parallelization].

### Data Structures
The Gaussian representation consists of a list of primitives. Each Gaussian $i$ stores:
*   **Position:** $\mathbf{p}_i \in \mathbb{R}^3$ [S3].
*   **Rotation:** $\mathbf{q}_i \in \mathbb{R}^4$ (unit quaternion) [S3].
*   **Scale:** $\mathbf{s}_i \in \mathbb{R}^3$ (log-scale for optimization stability) [S3].
*   **Opacity:** $\alpha_i \in \mathbb{R}$ (sigmoid-activated) [S3].
*   **SH Coefficients:** $\mathbf{c}_i \in \mathbb{R}^{3 \times (D+1)^2}$, where $D$ is the SH degree. Default $D=1$ [S3].
*   **Gradients:** Accumulated view-space position gradients $\nabla_{\mathbf{p}} \mathcal{L}$ for densification decisions [S4].

### Parameters and Typical Values
*   **Optimizer:** Adam [S3].
*   **Learning Rate:** $1 \times 10^{-3}$ [S3].
*   **SH Degree:** 1 [S3].
*   **Densification Interval:** Every 100 iterations [S4].
*   **Split Threshold ($T_{pos}$):** 0.02 (view-space position gradient) [S1].
*   **Pruning Interval:** Every 200 iterations [S1].
*   **Opacity Threshold ($\alpha_{min}$):** 0.05 [S1].
*   **Scene Extent ($e_{scene}$):** Calculated based on SfM points to avoid camera bias (see Corrected Scene-Extent) [S4].

### Numbered Steps

1.  **Initialization:** Initialize Gaussians from the SfM point cloud. Calculate the corrected scene extent $e'_{\text{scene}}$ using the average camera position $\bar{C}$ and SfM points $p_i$ [S4]:
    $$ \bar{C} = \frac{1}{N_{\text{cam}}} \sum_{i=1}^{N_{\text{cam}}} C_i $$
    $$ e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2 $$
    This prevents bias from clustered camera positions (e.g., orbiting a small object) [S4].

2.  **Training Loop (Per Iteration):**
    a. Randomly select a single image from a random scene as supervision [S3].
    b. **Forward Pass:** Rasterize Gaussians to image space. Use half-precision (FP16) memory fetches for feature vectors to reduce register pressure [S2]. Apply an automatic scaling factor to loss values to improve half-precision stability [S2].
    c. **Loss Computation:** Compute photometric loss (L1 + SSIM) between rendered and ground-truth images [S3].
    d. **Backward Pass:** Compute gradients $\frac{\partial \mathcal{L}}{\partial \theta}$ for all Gaussian parameters [6233-optimization-and-parallelization].

3.  **Densification (Every 100 Iterations):**
    a. Check accumulated view-space position gradients for each Gaussian [S4].
    b. If gradient magnitude $> T_{pos} = 0.02$, split the Gaussian into two [S1].
    c. If gradient magnitude is small but opacity is high, clone the Gaussian [S4].
    d. Perform compactness-based densification every 1000 iterations to ensure complete geometry [S1].

4.  **Pruning (Every 200 Iterations):**
    a. Remove Gaussians with opacity $\alpha < \alpha_{min} = 0.05$ [S1].
    b. Remove Gaussians with excessively large world-space or view-space radius [S1].

5.  **Optimization Update:** Update Gaussian parameters using Adam optimizer with LR $1 \times 10^{-3}$ [S3].

### Pseudocode

```python
def train_3dgs(gaussians, images, cameras, num_iterations=30000):
    optimizer = Adam(gaussians.parameters(), lr=1e-3)
    
    for iteration in range(1, num_iterations + 1):
        # 1. Sample a random training view
        img_idx = random_choice(len(images))
        gt_image = images[img_idx]
        camera = cameras[img_idx]
        
        # 2. Forward pass with half-precision rasterization
        # gsplat handles the differentiable alpha-blending
        rendered_image = gsplat_rasterize(gaussians, camera, half_precision=True)
        
        # 3. Compute Loss
        # Apply scaling factor for FP16 stability [S2]
        loss = compute_loss(rendered_image, gt_image)
        loss = loss * scaling_factor
        
        # 4. Backward pass
        optimizer.zero_grad()
        loss.backward()
        
        # 5. Optimizer step
        optimizer.step()
        
        # 6. Densification (every 100 iterations)
        if iteration % 100 == 0:
            # Calculate view-space position gradients
            gradients = gaussians.get_view_space_position_gradients()
            
            # Split Gaussians with high gradients
            split_mask = gradients > 0.02  # T_pos = 0.02 [S1]
            gaussians.split(split_mask)
            
            # Clone Gaussians with low gradients and high opacity
            clone_mask = (gradients <= 0.02) & (gaussians.opacity > 0.8)
            gaussians.clone(clone_mask)
            
            # Compactness-based densification every 1000 iterations [S1]
            if iteration % 1000 == 0:
                gaussians.compactify()
        
        # 7. Pruning (every 200 iterations)
        if iteration % 200 == 0:
            # Remove low opacity Gaussians [S1]
            prune_mask = gaussians.opacity < 0.05
            gaussians.remove(prune_mask)
            
            # Remove excessively large Gaussians [S1]
            large_mask = gaussians.get_radius() > threshold
            gaussians.remove(large_mask)
```

### Edge Cases and Pitfalls
*   **Scene Extent Bias:** Using camera positions to calculate scene extent can lead to incorrect splitting/pruning if cameras are clustered (e.g., orbiting a small object in a large environment). Use the corrected scene extent based on SfM points [S4].
*   **Half-Precision Stability:** FP16 training can suffer from gradient underflow/overflow. Apply an automatic scaling factor to loss values [S2].
*   **Over-Densification:** Without gradient thresholds, Gaussians may proliferate uncontrollably. The threshold $T_{pos}=0.02$ controls this [S1].
*   **Under-Pruning:** Low-opacity Gaussians consume memory and compute. Regular pruning at $\alpha < 0.05$ is essential [S1].

## Subtopics

### Corrected Scene-Extent
A method to calculate scene extent based on the SfM point cloud rather than camera positions to avoid bias from camera distribution (e.g., orbiting a small object in a large environment) [S4]. It sets itself apart from standard 3DGS by replacing the max-camera-distance formula with an average-distance-to-SfM-points formula, ensuring the scene volume reflects the actual geometry rather than the capture setup [S4]. Choose this when camera positions are non-uniform or clustered [S4].

### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ to selectively enlarge covariances, creating pixel-wise variable blur kernels that match spatially varying scene blurriness [S5]. It sets itself apart from naive Gaussian blur by allowing spatially varying blur shapes and magnitudes, enabling effective deblurring of defocus blur without blurring sharp regions [S5]. Choose this when training on images with varying depth-of-field or motion blur [S5].

### Denoise-GS
A self-supervised denoising method for sparse-view 3D Gaussian Splatting that combines unsupervised image denoising (Noise2Void) with differentiable 3DGS [S6]. It sets itself apart from supervised methods by requiring no paired clean data, making it robust to non-Gaussian and time-varying noise in sparse viewpoint scenarios [S6]. Choose this when training data is sparse and noisy [S6].

### Multi-Scale Constraint
A technique using position-aware point adaptive control to apply different scales to Gaussians based on viewer distance, improving rendering of distant objects [S7]. It sets itself apart from standard densification by using a distance-dependent scaling factor $\gamma(\mu)$ to adjust cloning and splitting thresholds [S7]. Choose this for large-scale scenes with significant depth variation [S7].

### LS-Gaussian Viewpoint Transformation
An algorithm that leverages inter-frame continuity for efficient sparse rendering by transforming the viewpoint between consecutive frames, rather than rendering each frame separately [S8]. It sets itself apart from naive pixel warping by operating at the tile/Gaussian level to reduce preprocessing and sorting costs [S8]. Choose this for real-time rendering of continuous camera trajectories (e.g., SLAM) [S8].

### Camera Localisation for Convergence Basin
Localizes camera pose by minimizing photometric error against a ground-truth image, fixing initial Gaussians during optimization [S9, unofficial]. It sets itself apart by providing a robust initialization for SLAM systems where pose estimation is critical [S9, unofficial]. Choose this when camera poses are unknown or drift [S9, unofficial].

### DiffGS Framework
Applies an optimization process during Gaussian extraction to optimize Gaussians to exact locations using a Gaussian Probability Function (GauPF) with truncation and projection functions [S10]. It sets itself apart by enabling high-fidelity rendering with fewer Gaussians (e.g., 50K-350K) compared to standard 3DGS [S10]. Choose this when memory is constrained but high PSNR/SSIM is required [S10].

### Opacity Offset Table for DSA
Constructs an opacity offset table to model changes in digital subtraction angiography [S11]. It sets itself apart by handling dynamic opacity changes in medical imaging contexts [S11]. Choose this for medical image reconstruction [S11].

### Conditional Splat Approximation
Approximates the influence range of a 3D Gaussian on a slice by using a 2D ellipse splat scaled by the marginal factor [S12, unofficial]. It sets itself apart by providing an accurate and efficient approximation of 3D Gaussian iso-probability contours for slice-based rendering [S12, unofficial]. Choose this for tomographic reconstruction or slice-based processing [S12, unofficial].

### 3DGS Uncertainty Calculation via Fisher Information
Computes an uncertainty attribute for 3D Gaussians based on the negative log-likelihood of the rendered pixel value, interpreted as Fisher information [S13]. It sets itself apart by providing a differentiable uncertainty metric for active view selection or refinement [S13]. Choose this when uncertainty quantification is needed for downstream tasks [S13].

## Operating characteristics

### Time and Memory Complexity
*   **Time:** $O(N \cdot M)$ per pixel, where $N$ is the number of Gaussians and $M$ is the number of pixels, due to sorting and alpha blending [6233-optimization-and-parallelization]. Densification adds $O(N)$ overhead every 100 iterations [S4].
*   **Memory:** $O(N \cdot D^2)$ for SH coefficients, where $D$ is the SH degree. Default $D=1$ reduces memory footprint [S3]. Half-precision rasterization reduces register pressure [S2].

### Measured Performance
*   **Hardware:** Optimized for NVIDIA GPUs using CUDA kernels [S2].
*   **Resolution:** Scales with image resolution; half-precision helps maintain performance at high resolutions [S2].
*   **Scene:** Performance degrades with very large scenes unless spatial partitioning (e.g., TraGraph-GS) is used [S7].

### Scaling
*   Scales linearly with the number of Gaussians. Densification increases $N$ over time, increasing compute cost [S4].
*   Half-precision training allows larger batch sizes or higher resolutions on memory-constrained GPUs [S2].

### Strengths and Limitations
*   **Strengths:** Real-time rendering, high fidelity, explicit representation allows easy editing [6233-optimization-and-parallelization].
*   **Limitations:** High memory usage for large scenes, sensitive to initialization and densification parameters [S4].

### When to Use
*   Use for real-time novel view synthesis, interactive applications, and scenarios requiring explicit scene editing [6233-optimization-and-parallelization].
*   Use corrected scene extent for non-uniform camera distributions [S4].
*   Use half-precision for memory-constrained hardware [S2].

### When Not to Use
*   Avoid for scenes with extreme dynamic range or complex lighting without additional appearance models [S2].
*   Avoid for sparse-view scenarios without denoising (e.g., Denoise-GS) [S6].

## Background

### Origin
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1, S3]. It builds on the idea of representing scenes as explicit 3D Gaussians and rendering them via differentiable rasterization.

### History and Development
The method has been extended to handle various challenges:
*   **Densification Control:** Initial implementations used fixed thresholds; later work introduced adaptive thresholds and compactness-based densification [S1, S4].
*   **Precision:** Half-precision rasterization was introduced to improve performance on consumer GPUs [S2].
*   **Scene Extent:** Corrected scene extent was proposed to handle camera bias [S4].
*   **Denoising:** Self-supervised denoising methods like Denoise-GS were developed for sparse-view scenarios [S6].

### Where It Is Used
*   **Virtual Reality/Augmented Reality:** Real-time rendering of complex scenes [6233-optimization-and-parallelization].
*   **Robotics:** SLAM and navigation [S9, unofficial].
*   **Medical Imaging:** Digital subtraction angiography [S11].
*   **Photogrammetry:** High-fidelity 3D reconstruction from images [S3].
