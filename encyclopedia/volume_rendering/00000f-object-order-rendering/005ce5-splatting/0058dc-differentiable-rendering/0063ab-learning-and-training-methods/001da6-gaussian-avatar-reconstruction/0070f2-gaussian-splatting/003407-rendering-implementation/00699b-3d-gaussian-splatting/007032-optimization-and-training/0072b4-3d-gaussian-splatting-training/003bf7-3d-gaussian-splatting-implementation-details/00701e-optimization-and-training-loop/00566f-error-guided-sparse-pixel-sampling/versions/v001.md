# Error-Guided Sparse Pixel Sampling

Also called: Err-SPS, Tile-Wise Pixel Sampling (EPS), Tile-wise Sparse Pixel Sampling, sparse pixel training

## Overview
Error-Guided Sparse Pixel Sampling (Err-SPS) is a training optimization strategy for 3D Gaussian Splatting that restricts loss evaluation and gradient computation to a sparse subset of pixels per tile, guided by persistent error and age maps [S1, unofficial]. It solves the problem of redundant gradient computation in well-reconstructed regions by reallocating computation to perceptually informative pixels [S1, unofficial]. Unlike sibling methods that optimize rendering pipelines or data compression, Err-SPS specifically accelerates the optimization phase by sparsifying the pixel-level supervision signal [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Current Gaussian primitives $G$, camera views $V_t$ for tile $t$, ground truth images $I$, current error map $E$, current age map $A$, training progress $\rho_t$, and sampling parameters ($K_t, r_t$).
*   **Outputs:** Updated Gaussian parameters $\Delta G$, updated error map $E$, updated age map $A$, and sparse gradients.

**Data Structures:**
*   **Error Map ($E$):** A 2D array (or tile-aligned buffer) storing the per-pixel reconstruction error (e.g., L1 loss) from previous iterations. Initialized to a high value or zero depending on initialization strategy [G].
*   **Age Map ($A$):** A 2D array storing the number of consecutive iterations a pixel has *not* been sampled. Initialized to zero [G].
*   **Sampling Schedule:** Parameters $K_{max}, K_{min}$ (max/min number of pixels to sample), and current rate $r_t$ [S1, unofficial].

**Numbered Steps:**
1.  **Query Sampling Schedule:** Determine the target number of pixels to sample $K_t$ and sampling rate $r_t$ based on training progress $\rho_t$ [S1, unofficial].
2.  **View Selection:** Select a subset of views $V_t$ for the current tile using geometry-aware view sampling [S1, unofficial].
3.  **Tile-Wise Pixel Sampling:** For each view $v \in V_t$, select a subset of pixels $P_{t,v}$ from the tile based on $E$ and $A$. Pixels with higher error and lower age (more recently sampled) are prioritized [S1, unofficial].
4.  **Gather Ground Truth and Error:** Retrieve ground truth colors $c^*$ and current errors $e^*$ for the sampled pixels $P_{t,v}$ [S1, unofficial].
5.  **Sparse Forward Rendering:** Rasterize the Gaussians only for the sampled pixels $P_{t,v}$ to obtain rendered colors $o$ and depths $d$ [S1, unofficial].
6.  **Sparse Loss Calculation:** Compute the loss $L$ only over the sampled pixels [S1, unofficial]:
    $$ L = \mathbb{E}_{v \in V_t, p \in P_{t,v}} \ell_1(p) + \mathbb{E}_{v \in V_t, \tau} \lambda_\tau^{ncc} L_\tau^{S-NCC} $$
    where $\ell_1(p)$ is the L1 loss at pixel $p$, $\lambda_\tau^{ncc}$ is a weighting coefficient, and $L_\tau^{S-NCC}$ is the sparse Normalized Cross-Correlation term [S1, unofficial].
7.  **EMA Error-Map Update:** Update the error map $E$ using an Exponential Moving Average (EMA) of the computed pixel losses $L_{pix}$ for the sampled pixels [S1, unofficial].
8.  **Gaussian Backward:** Compute gradients $\nabla G$ for the Gaussian properties using the sparse gradients $\nabla c, \nabla d$ from the loss calculation [S1, unofficial].
9.  **Solve Updates:** Apply the hybrid optimizer to update the Gaussians [S1, unofficial].

**Pseudocode:**
```python
def error_guided_sparse_pixel_sampling(G, V_all, I, E, A, rho_t, K_max, K_min, lambda_ncc):
    # 1. Query Sampling Schedule
    K_t = query_sampling_schedule(K_max, K_min, E_init, G, rho_t)
    
    # 2. View Selection (Geometry-Aware)
    V_t = geometry_aware_view_sampling(K_t, rho_t)
    
    # 3. Tile-Wise Pixel Sampling
    # For each tile t (implied loop in parallel execution)
    P_t = {}
    for v in V_t:
        # Select pixels based on Error (E) and Age (A)
        # Higher error -> higher priority. Higher age -> higher priority (to refresh).
        # Sample K_t / |V_t| pixels per view
        P_t[v] = tile_wise_pixel_sampling(V_t, K_t, E, A)
        
    # 4. Gather GT Color & Error
    c_star = get_ground_truth_colors(I, P_t)
    e_star = get_current_errors(E, P_t)
    
    # 5. Sparse Forward Rendering
    # Rasterize only for sampled pixels
    o, d = sparse_rasterize_forward(G, V_t, P_t)
    
    # 6. Sparse Loss & Gradients
    # L1 Loss on sampled pixels
    l1_loss = mean_l1_loss(o, c_star)
    
    # Sparse NCC Loss (structure-aware)
    # Note: S-NCC is computed on sampled pixels to preserve high-frequency details
    sncc_loss = sparse_ncc_loss(o, d, c_star, lambda_ncc)
    
    L = l1_loss + sncc_loss
    
    # 7. EMA Error-Map Update
    # Update E only for sampled pixels
    L_pix = compute_pixel_wise_losses(o, c_star)
    E = update_ema_error_map(E, L_pix, V_t, P_t)
    
    # 8. Gaussian Backward
    # Compute gradients for Gaussians affecting sampled pixels
    grad_c, grad_d = compute_gradients(L, o, d)
    grad_G = sparse_rasterize_backward(grad_c, grad_d, G, P_t)
    
    # 9. Solve Gaussian Updates
    # Apply hybrid optimizer (e.g., Adam with Hessian damping)
    delta_G = solve_gaussian_updates(grad_G, G)
    
    return delta_G, E, A
```

**Parameters:**
*   $K_{max}, K_{min}$: Maximum and minimum number of pixels to sample per tile [S1, unofficial].
*   $\lambda_\tau^{ncc}$: Weighting coefficient for the sparse NCC term [S1, unofficial].
*   $\rho_t$: Training progress, typically $[0, 1)$ [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Degenerate Input:** If all pixels have low error, sampling may become random or biased towards age, potentially missing new errors [S1, unofficial].
*   **Precision:** Relying solely on sparse-pixel L1 supervision degrades reconstruction quality, particularly high-frequency details [S1, unofficial]. This requires complementary geometry-aware view sampling and sparse NCC regularization [S1, unofficial].
*   **Artifacts:** Sparse supervision may introduce subtle rippling artifacts in low-frequency regions with weak texture variations (e.g., walls or ceilings) [S1, unofficial].

## Subtopics

### Geometry-Aware View Sampling
Selects views based on geometric relevance to reduce redundant views [S1, unofficial].

### Sparse NCC Regularization
Adds structure-aware loss to preserve high-frequency details lost by sparse L1 supervision [S1, unofficial].

### Error-Driven Gaussian Density Control
Dynamically allocates model capacity based on error maps [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Significantly reduces training time. On Mip-NeRF 360, Err-SPS reduces training time from 891s to 85s [S1, unofficial].
*   **Memory Complexity:** Reduces the number of Gaussians (NGS) from 2.73M to 0.76M, indicating lower memory usage for primitives [S1, unofficial].
*   **Performance:** Improves PSNR by +0.02 dB over baseline when combined with other TurboGS components [S1, unofficial].
*   **Strengths:** Accelerates training by 10x; reduces Gaussian count; focuses computation on informative pixels.
*   **Limitations:** May introduce rippling artifacts in low-texture regions; requires careful tuning of NCC regularization to avoid quality degradation [S1, unofficial].
*   **When to Use:** When training time is a bottleneck and high-frequency detail preservation is critical.
*   **When Not to Use:** When scene has large uniform regions prone to rippling artifacts, or when random sampling is insufficient for detail preservation [S1, unofficial].

## Background
Err-SPS is a core component of the TurboGS framework, proposed by Hanson et al. in 2026 [S1, unofficial]. It addresses the observation that as training progresses, only a small subset of pixels remains difficult to reconstruct, while most become well-explained and yield marginal gradients [S1, unofficial]. The method builds on the tile-parallel forward execution and per-Gaussian backward mechanism introduced in prior work [S1, unofficial].
