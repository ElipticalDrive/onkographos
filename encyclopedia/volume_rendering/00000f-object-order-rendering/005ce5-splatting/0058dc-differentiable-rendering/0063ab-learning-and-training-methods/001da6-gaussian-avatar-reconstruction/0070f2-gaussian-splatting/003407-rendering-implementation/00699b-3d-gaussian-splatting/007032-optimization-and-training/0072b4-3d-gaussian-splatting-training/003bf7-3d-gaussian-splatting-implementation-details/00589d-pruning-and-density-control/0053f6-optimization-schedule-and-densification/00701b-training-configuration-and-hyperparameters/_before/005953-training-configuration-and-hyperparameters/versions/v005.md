# Training Configuration and Hyperparameters

Also called: Decoder Training Setup, Training Configuration for Gaussian Splatting Decoder

## Overview
This article defines the specific hyperparameters, optimization schedules, and data sampling strategies required to train 3D Gaussian Splatting decoders for generative and downstream tasks. It addresses the configuration of the optimizer, learning rates, and camera view distributions, which vary significantly depending on whether the target application requires full 360° explicit 3D space rendering or restricted frontal view synthesis. It serves as the concrete instantiation of the optimization principles defined in [Optimization Schedule and Densification](15107-optimization-schedule-and-densification.md), providing the numerical values necessary to reproduce training runs for specific datasets like PanoHead or EG3D, and standardized protocols for downstream classification tasks.

## How it works
The training process involves optimizing the Gaussian parameters ($\mathbf{p}_i, \mathbf{s}_i, \mathbf{q}_i, \alpha_i, \mathbf{c}_i$) using an Adam optimizer with specific learning rates and iteration counts. The configuration is dataset-dependent, particularly regarding camera sampling strategies and total training duration.

### Inputs and Outputs
*   **Inputs:** Pre-trained GAN weights (e.g., EG3D, PanoHead), dataset images (FFHQ, LPFF, FFHQ-H), and hyperparameter configuration (learning rate, iterations, loss weights).
*   **Outputs:** Trained Gaussian fields (positions, scales, rotations, opacities, SH coefficients) optimized for the target domain.

### Data Structures
The Gaussian primitives follow the standard representation linked from the parent article. No additional data structures are introduced for the core training configuration itself, though downstream protocols may group Gaussians (e.g., 64 groups of 32).

### Steps
1.  **Initialize** the Gaussian decoder with parameters from a pre-trained GAN or random initialization.
2.  **Sample Cameras:**
    *   For **PanoHead** (360° explicit space): Sample random cameras uniformly distributed around the head (360°) [S1].
    *   For **EG3D** (Frontal focus): Sample mainly frontal views with small vertical and horizontal rotations [S1].
3.  **Optimize:** Run the Adam optimizer for the specified number of iterations (typically 500,000 for generative decoders) [S1].
4.  **Loss Computation:** Compute loss using weights $\lambda = (0.2, 0.5, 1.0, 1.0, 0.2)$ for the five loss terms unless otherwise stated [S1].
5.  **Update:** Update Gaussian parameters based on gradients.

### Parameters and Typical Values
*   **Optimizer:** Adam [S1].
*   **Learning Rate:** $0.0009$ for generative decoder training (PanoHead/EG3D) [S1].
*   **Iterations:** $500,000$ [S1].
*   **Loss Weights:** $\lambda_1=0.2, \lambda_2=0.5, \lambda_3=1.0, \lambda_4=1.0, \lambda_5=0.2$ [S1].
*   **Camera Sampling:**
    *   PanoHead: 360° random views [S1].
    *   EG3D: Frontal views with small rotations [S1].

### Pseudocode
```python
# Configuration for Generative Decoder Training
ITERATIONS = 500000
LEARNING_RATE = 0.0009
LOSS_WEIGHTS = (0.2, 0.5, 1.0, 1.0, 0.2)

def train_decoder(dataset_type, pretrained_gan):
    """
    Trains a 3D Gaussian Splatting decoder for a specific GAN target.
    
    Args:
        dataset_type: 'PanoHead' or 'EG3D'
        pretrained_gan: Path to pre-trained GAN weights
    
    Returns:
        Trained Gaussian parameters
    """
    # Initialize Gaussians from GAN
    gaussians = initialize_gaussians_from_gan(pretrained_gan)
    
    # Setup Optimizer
    optimizer = Adam(gaussians.parameters(), lr=LEARNING_RATE)
    
    for iteration in range(ITERATIONS):
        # Sample cameras based on dataset requirements
        if dataset_type == 'PanoHead':
            # Sample random cameras all around the head (360°)
            cameras = sample_random_cameras_360()
        elif dataset_type == 'EG3D':
            # Sample mainly frontal views with small vertical/horizontal rotations
            cameras = sample_frontal_cameras_with_small_rotations()
        else:
            raise ValueError("Unknown dataset type")
        
        # Render images from current Gaussians and Cameras
        rendered_images = render(gaussians, cameras)
        
        # Get ground truth images from dataset
        gt_images = get_gt_images(cameras)
        
        # Compute loss with specified weights
        loss = compute_loss(rendered_images, gt_images, LOSS_WEIGHTS)
        
        # Backpropagate and update
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        
    return gaussians
```

### Edge Cases and Pitfalls
*   **Run-to-run variation:** ModelNet fine-tuning can exhibit appreciable run-to-run variation, particularly on ModelNet40 [S2, unofficial]. Results should be interpreted with caution regarding small cross-environment differences.
*   **Camera Mismatch:** Using frontal-only sampling for a task requiring 360° consistency (or vice versa) will lead to poor reconstruction in unobserved regions [S1].

## Subtopics

### Standard Downstream Protocols
A standardized training and evaluation pipeline for classification and part segmentation tasks using Gaussian inputs [S2, unofficial]. It differs from generative decoder training by focusing on frozen encoder probing and specific grouping strategies for point-cloud-like tasks.
*   **ModelNet10/40:** Uses 1,024 Gaussians, grouped into 64 groups of 32, utilizing all 14 attributes [S2, unofficial].
*   **Optimization:** Full fine-tuning, linear probing, and three-layer MLP probing run for 300 epochs [S2, unofficial].
*   **Optimizer:** AdamW with learning rate $10^{-3}$, weight decay $0.05$, 5 warm-up epochs, and total batch size 256 [S2, unofficial].
*   **Probing:** For linear and MLP probing, the encoder is frozen, and only the classifier is updated [S2, unofficial].
*   **ShapeNet-Part:** Uses 2,048 Gaussians, grouped into 128 groups of 32 [S2, unofficial].
*   **Optimization:** 300 epochs with AdamW, learning rate $10^{-4}$, and batch size 16 [S2, unofficial].

### StopThePop Framework Integration
A framework that integrates occlusion-aware densification with StopThePop's per-pixel depth ordering to remove popping artifacts and keep occlusion boundaries intact [S3, unofficial]. It replaces the standard visibility filter with an occlusion-aware filter that restricts densification statistics to views where a Gaussian actually contributes [S3, unofficial].
*   **Depth Ordering:** Uses StopThePop's hybrid transparency or per-pixel sorting to determine the order of Gaussians and compute transmittance $T_{i,p}$ [S3, unofficial].
*   **Gradient Accumulation:** Accumulates gradients and statistics only for non-zero weights $w_{i,p}$ [S3, unofficial].
*   **Densification Criterion:** Applies a contribution-based normalization for densification decisions, replacing the raw view-count normalizer with an average-contribution one [S3, unofficial]. This allows the method to stay competitive at a fraction of the competitors' Gaussian count [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** Dominated by the number of iterations (500,000 for generative, 300 epochs for downstream) and the cost of rendering and backpropagation through the Gaussian splatting rasterizer.
*   **Memory Complexity:** Proportional to the number of Gaussians. Generative decoders typically use the full set of Gaussians from the pre-trained GAN. Downstream protocols use fixed counts (1,024 or 2,048) [S2, unofficial].
*   **Strengths:** The configuration is tailored to the specific geometric priors of the target dataset (e.g., 360° vs. frontal), ensuring optimal reconstruction quality for the intended use case [S1]. The standardized downstream protocols allow for fair comparison between Gaussian-based methods and point-cloud baselines [S2, unofficial].
*   **Limitations:** High iteration counts (500k) require significant computational resources. Run-to-run variance in downstream tasks like ModelNet40 can affect reproducibility [S2, unofficial].

## Background
The training configuration for 3D Gaussian Splatting decoders was introduced in the context of adapting Gaussian Splatting for 3D-aware generative models, specifically for GANs like EG3D and PanoHead [S1]. The approach leverages the differentiable nature of Gaussian Splatting to optimize a Gaussian field that approximates the implicit representation of the GAN. The standard downstream protocols were later established to facilitate evaluation of Gaussian representations on standard 3D vision benchmarks like ModelNet and ShapeNet-Part, highlighting the need for specific grouping and probing strategies [S2, unofficial]. The integration with StopThePop addresses artifacts in large-scale scenes by refining the densification process to be occlusion-aware [S3, unofficial].
