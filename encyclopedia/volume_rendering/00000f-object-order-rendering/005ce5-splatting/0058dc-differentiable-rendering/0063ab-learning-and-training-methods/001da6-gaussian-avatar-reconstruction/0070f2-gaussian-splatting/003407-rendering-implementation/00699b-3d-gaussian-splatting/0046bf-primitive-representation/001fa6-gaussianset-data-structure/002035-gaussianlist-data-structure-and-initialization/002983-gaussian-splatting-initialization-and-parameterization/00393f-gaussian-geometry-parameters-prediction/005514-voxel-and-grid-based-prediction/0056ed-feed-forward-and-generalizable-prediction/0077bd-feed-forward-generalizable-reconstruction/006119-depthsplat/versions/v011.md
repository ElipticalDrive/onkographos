# DepthSplat

## Overview
DepthSplat is a feed-forward method for 3D Gaussian Splatting reconstruction that connects multi-view depth estimation with Gaussian rendering by leveraging pre-trained monocular depth features to augment multi-view feature matching [S1]. It solves the problem of robust depth prediction in challenging scenarios (occlusions, low-texture, non-Lambertian surfaces) where standard multi-view stereo fails, and scale ambiguities where monocular estimation fails, by fusing both signals early in the pipeline [S1]. Unlike TranSplat, which uses monocular features to refine coarse depth (vulnerable to error propagation), DepthSplat combines cost volumes and monocular features early, and unlike GS-LRM, it relies on explicit feature matching rather than heavy data-driven priors, making it significantly cheaper to train [S1].
## How it works
**Inputs:** $N$ input images $\{I_i\}_{i=1}^N$ with corresponding projection matrices $\{P_i\}_{i=1}^N$, where $I_i \in \mathbb{R}^{H \times W \times 3}$ and $P_i \in \mathbb{R}^{3 \times 4}$ (computed from intrinsic and extrinsic matrices) [S1].

**Outputs:** A set of 3D Gaussians $\mathcal{G} = \{\mu_j, \alpha_j, \Sigma_j, c_j\}_{j=1}^{H \times W}$ for each view, where $\mu_j$ is the 3D position, $\alpha_j$ is opacity, $\Sigma_j$ is covariance, and $c_j$ is color [S1].

**Data Structures:**
*   **Monocular Features:** Extracted per-view using a Vision Transformer (ViT).
*   **Cost Volume:** $C_i \in \mathbb{R}^{\frac{H}{s} \times \frac{W}{s} \times D}$ for each view $i$, where $s$ is the downsampling factor and $D$ is the number of depth candidates [S1].
*   **Depth Map:** $D_i \in \mathbb{R}^{H \times W}$, dense per-pixel depth prediction [S1].

**Parameters:**
*   **Downsampling factor ($s$):** Controlled by the number of stride-2 $3 \times 3$ convolutions in feature extraction. $s=4$ if two convolutions are used; $s=8$ if three are used [S1].
*   **Depth candidates ($D$):** Uniformly sampled from near/far depth ranges [S1].
*   **Multi-view Transformer:** Contains six stacked self- and cross-attention layers [S1].
*   **Neighbor Selection:** For $N > 2$ views, the top-2 nearest neighboring views are selected based on camera distance to the reference view [S1].

**Steps:**
1.  **Monocular Feature Extraction:** For each view $i$, extract features $F_i$ using a pre-trained monocular depth model (ViT-based) [S1].
2.  **Cost Volume Construction:**
    a. For each view $i$, uniformly sample $D$ depth candidates $\{d_m\}_{m=1}^D$ from the near and far depth ranges [S1].
    b. For each neighboring view $j$ (all views if $N \le 2$, top-2 nearest if $N > 2$), warp the feature $F_j$ to view $i$ using $P_i$ and each depth candidate $d_m$ to obtain warped features $\{F_{j \to i}^m\}_{m=1}^D$ [S1].
    c. Measure feature correlations via dot-product between $F_i$ and $F_{j \to i}^m$ [S1].
    d. Stack correlations to form cost volume $C_i$. If $N > 2$, compute correlations for the top-2 neighbors and combine values with averaging [S1].
3.  **Feature Concatenation:** Concatenate the multi-view cost volumes $C_i$ with the extracted monocular features [S1].
4.  **Depth Regression:** Perform depth regression using a 2D U-Net architecture followed by a softmax layer to predict dense per-pixel depth $D_i$ [S1].
5.  **Gaussian Unprojection:** Unproject the predicted depth maps $D_i$ to 3D space using camera parameters $P_i$ to obtain Gaussian centers $\mu_j$ [S1].
6.  **Parameter Prediction:** Predict remaining Gaussian parameters (opacity $\alpha_j$, covariance $\Sigma_j$, color $c_j$) using an additional lightweight network/head in parallel with the depth regression [S1].
7.  **Rendering:** Render novel views using the splatting operation with the predicted 3D Gaussians [S1].

**Pseudocode:**
```python
def depth_splat(images, projection_matrices):
    """
    images: List of N images, shape (H, W, 3)
    projection_matrices: List of N matrices, shape (3, 4)
    Returns: List of 3D Gaussians (mu, alpha, Sigma, c)
    """
    N = len(images)
    monocular_features = []
    
    # Step 1: Monocular Feature Extraction
    for i in range(N):
        # Extract features using pre-trained monocular depth model (ViT)
        F_i = extract_monocular_features(images[i])
        monocular_features.append(F_i)
        
    # Step 2: Cost Volume Construction
    cost_volumes = []
    for i in range(N):
        # Determine neighbors
        if N <= 2:
            neighbors = [j for j in range(N) if j != i]
        else:
            # Select top-2 nearest neighbors based on camera distance
            distances = compute_camera_distances(projection_matrices[i], projection_matrices)
            sorted_indices = argsort(distances)
            neighbors = [idx for idx in sorted_indices if idx != i][:2]
            
        # Sample depth candidates
        depth_candidates = sample_depth_candidates(near_far_ranges)
        D = len(depth_candidates)
        
        # Initialize cost volume accumulator
        # Shape: (H/s, W/s, D)
        # Note: s is determined by feature extraction convolutions
        H_feat, W_feat = get_feature_resolution(images[i])
        cost_vol = zeros((H_feat, W_feat, D))
        
        for j in neighbors:
            F_j = monocular_features[j]
            warped_correlations = zeros((H_feat, W_feat, D))
            
            for m, d_m in enumerate(depth_candidates):
                # Warp F_j to view i using P_i and d_m
                F_warped = warp_feature(F_j, projection_matrices[i], d_m)
                
                # Dot-product correlation
                # F_i is already at feature resolution
                corr = dot_product(F_i, F_warped)
                warped_correlations[:, :, m] = corr
                
            # Average correlations if multiple neighbors
            cost_vol += warped_correlations
            
        if len(neighbors) > 1:
            cost_vol /= len(neighbors)
            
        cost_volumes.append(cost_vol)
        
    # Step 3 & 4: Depth Regression
    # Concatenate cost volumes with monocular features
    # Note: Monocular features must be downsampled/aligned to match cost volume resolution
    depth_maps = []
    for i in range(N):
        # Concatenate cost volume C_i and monocular features F_i
        # The specific concatenation dimension depends on implementation, 
        # typically channel-wise after alignment.
        combined_input = concatenate(cost_volumes[i], monocular_features[i])
        
        # 2D U-Net followed by softmax
        depth_logit = u_net_2d(combined_input)
        depth_map = softmax(depth_logit, dim=-1) # Or appropriate depth regression head
        depth_maps.append(depth_map)
        
    # Step 5: Gaussian Unprojection
    gaussians = []
    for i in range(N):
        # Unproject depth map D_i using P_i to get mu_j
        # This produces a set of 3D points for each pixel
        mu = unproject_depth(depth_maps[i], projection_matrices[i])
        
        # Step 6: Predict remaining parameters
        # Parallel lightweight head
        alpha, Sigma, c = predict_gaussian_params(combined_input)
        
        gaussians.append((mu, alpha, Sigma, c))
        
    return gaussians
```

**Edge Cases and Pitfalls:**
*   **Occlusions/Low-Texture:** Multi-view depth estimation fails in these areas. DepthSplat mitigates this by augmenting multi-view cost volumes with monocular features [S1].
*   **Scale Ambiguity:** Monocular depth estimation suffers from scale ambiguities. DepthSplat maintains multi-view consistency by using monocular features only as an augmentation to multi-view matching [S1].
*   **Neighbor Selection:** For $N > 2$, selecting only the top-2 nearest neighbors ensures computational tractability and scales efficiently [S1].
## Subtopics

### [Gaussian Graph Network](18863-gaussian-graph-network.md)
Gaussian Graph Network (GGN) is a feed-forward method that generates efficient and generalizable 3D Gaussian representations from multi-view images by modeling relations between Gaussian groups from different views using a Gaussian Graph structure.

## Operating characteristics
*   **Time Complexity:** Not explicitly given in formulas, but reconstruction speed is 0.6 seconds for feed-forward reconstruction from 12 input views at 512x960 resolution [S1].
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:** Achieves state-of-the-art results on ScanNet, RealEstate10K, and DL3DV datasets [S1].
*   **Training Cost:** Trained in 2 days with 4 GPUs, compared to GS-LRM which requires 64 A100 GPUs for 2 days [S1].
*   **Strengths:** Robustness in challenging scenarios (low-texture, reflective surfaces) due to monocular feature augmentation; efficient training; handles large-scale scenes [S1].
*   **Limitations:** Relies on pre-trained monocular depth model; multi-view depth estimation still subject to occlusion issues without monocular augmentation [S1].
*   **When to Use:** Feed-forward 3D Gaussian reconstruction from multiple views, especially in challenging environments where traditional multi-view stereo fails [S1].
*   **When Not to Use:** When per-scene optimization is acceptable and higher quality is needed via iterative refinement; when computational resources for training are extremely limited and pre-trained models are not available [S1].
## Background
DepthSplat was introduced by the authors of the paper "DepthSplat: Connecting Gaussian Splatting and Depth" [S1]. It was trained on TartanAir, ScanNet, RealEstate10K, and DL3DV datasets [S1]. The method explores the synergy between Gaussian splatting and depth estimation, showing that Gaussian splatting can serve as an unsupervised pre-training objective for learning powerful depth models from large-scale multi-view posed datasets [S1].
