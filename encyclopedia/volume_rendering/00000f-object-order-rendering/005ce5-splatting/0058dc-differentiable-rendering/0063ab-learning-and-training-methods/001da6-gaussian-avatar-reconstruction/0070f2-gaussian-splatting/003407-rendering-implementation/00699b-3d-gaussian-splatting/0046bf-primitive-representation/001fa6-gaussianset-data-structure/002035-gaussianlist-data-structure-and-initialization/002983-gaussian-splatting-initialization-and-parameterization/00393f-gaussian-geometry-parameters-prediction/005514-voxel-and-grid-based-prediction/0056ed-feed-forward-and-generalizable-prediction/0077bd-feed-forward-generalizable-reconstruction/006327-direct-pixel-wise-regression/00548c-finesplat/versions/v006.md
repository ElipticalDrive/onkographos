# FineSplat

Also called: Detailed Splats, Fine Patches, Local Groups

## Overview
FineSplat is a feed-forward 3D Gaussian Splatting framework that predicts a set of 3D Gaussians from $N$ context views using a two-stage dual-grouping strategy to balance local detail preservation with global multi-view reasoning [S1, unofficial]. It distinguishes itself from sibling methods like [YoNoSplat](12847-anysplat-pipeline.md) and [ZipSplat](12847-anysplat-pipeline.md) by employing high-resolution 4x4 patch tokens instead of coarser 14x14 patches, combined with a serialized attention mechanism in 3D space to avoid the prohibitive cost of global multi-view attention [S1, unofficial]. This approach preserves fine-grained visual information while maintaining high efficiency, achieving superior quality-per-unit-time metrics compared to explicit k-nearest-neighbor grouping or global attention baselines [S1, unofficial].

## How it works
FineSplat operates in two stages: view-wise token grouping (Stage 1) and 3D spatial token grouping with error feedback (Stage 2) [S1, unofficial].

### Inputs and Outputs
**Inputs:**
*   $N$ context images $I \in \mathbb{R}^{N \times H \times W \times 3}$.
*   Camera poses (intrinsics and extrinsics) for the context views. If poses are unknown, they are predicted by a backbone (e.g., DA3) [S1, unofficial].
*   **Parameters:**
    *   Patch size $p=4$ (pixels).
    *   Number of Stage 2 refinement steps $T=4$.
    *   Sub-patch stride $s=2$.
    *   Number of Gaussians per token $K=4$.
    *   Serialized attention group size $S$ (number of consecutive points along the space-filling curve).

**Outputs:**
*   A set of 3D Gaussian primitives $\Theta = \{\mu, \sigma, r, s, c, \alpha\}$ (means, scales, rotations, colors/spherical harmonics, opacities).
*   Rendered images of novel views.

### Data Structures
1.  **Tokens ($z$):** A tensor of shape $M \times d$, where $M = N \cdot \frac{H}{p} \cdot \frac{W}{p}$ is the number of fine-grained tokens, and $d$ is the feature dimension.
2.  **Gaussian Primitives:** For each token, $K=4$ Gaussians are predicted. Each Gaussian is defined by:
    *   Mean $\mu \in \mathbb{R}^3$ (3D world coordinates).
    *   Scale $s \in \mathbb{R}^3$ (log-scale).
    *   Rotation $r \in \mathbb{R}^4$ (quaternion).
    *   Color $c$ (Spherical Harmonics coefficients or RGB).
    *   Opacity $\alpha \in \mathbb{R}$.
3.  **Error Feature Maps ($F^{err}$):** For each view $n$, a feature map of shape $\frac{H}{p} \times \frac{W}{p} \times d_e$ containing concatenated pixel-level and feature-level error signals.

### Step-by-Step Method

#### Stage 1: View-Wise Token Grouping
1.  **Feature Extraction:** Extract multi-scale features $F^l$ for $l \in \{1, 2, 3\}$ (finest to coarsest) from the input images using a backbone network (e.g., Transformer/CNN) [S1, unofficial].
2.  **Token Initialization:** Fuse features into $M$ fine-grained tokens $z^{(0)}$ using Equation (1):
    $$ z^{(0)} = \text{fuse}\left(\text{up}\left(\text{fuse}\left(\text{up}(F^3) + F^2\right)\right)\right) + F^1 $$
    where $\text{up}(\cdot)$ is bilinear upsampling and $\text{fuse}(\cdot)$ is a convolutional fusion block [S1, unofficial].
3.  **View-Wise Attention:** Encode tokens using attention with restricted scope. Group tokens by view and apply attention within small view groups, exchanging information across all views via coarser global tokens (Multi-View Pyramid architecture) [S1, unofficial].

#### Stage 2: 3D Spatial Token Grouping and Refinement
This stage is repeated for $T=4$ steps. Let $z^{(i)}$ be the tokens at step $i$.

1.  **Gaussian Prediction:** Decode tokens $z^{(i)}$ into an initial set of Gaussians using a lightweight linear decoder head $\mathcal{D}$. Each token predicts $K=4$ Gaussians [S1, unofficial].
2.  **Patch-Aligned Sub-Pixel Gaussian Reconstruction:**
    *   Divide each 4x4 token into four non-overlapping 2x2 sub-patches.
    *   Predict a 2D image-space offset $\Delta = (\Delta_x, \Delta_y)$ for each Gaussian.
    *   Bound the offset to keep the Gaussian within its sub-patch:
        $$ \delta_x = 2s \tanh(\Delta_x), \quad \delta_y = 2s \tanh(\Delta_y) $$
        where $s=2$ is the sub-patch stride. This ensures $\delta_x, \delta_y \in [-1, 1]$ [S1, unofficial].
    *   For a sub-patch with center $(u_c, v_c)$, compute the displaced coordinate $(u, v) = (u_c, v_c) + (\delta_x, \delta_y)$.
    *   **Ray Unprojection:** Unproject $(u, v)$ using predicted camera intrinsics to get a direction vector. Transform and normalize this direction using the camera-to-world rotation. Use the camera translation as the ray origin to compute the 3D mean $\mu$ [S1, unofficial].
3.  **Rendering and Error Computation:**
    *   Render the predicted Gaussians into all $N$ context views to obtain rendered images $\hat{I}_n$.
    *   Compute the signed pixel error map for view $n$:
        $$ E_n = \hat{I}_n - I_n $$
    *   Compute the feature-level difference using a pretrained ResNet-18 encoder $\phi(\cdot)$:
        $$ \Delta\phi_n = \phi(\hat{I}_n) - \phi(I_n) $$
    *   Combine these with the finest-scale features $F_n^1$ from Stage 1 to form the error feature map $F_n^{err}$:
        $$ F_n^{err} = [\mathcal{E}_{err}(E_n, \Delta\phi_n); \mathcal{E}_{feat}(F_n^1)] \in \mathbb{R}^{\frac{H}{p} \times \frac{W}{p} \times d_e} $$
        where $\mathcal{E}_{err}$ and $\mathcal{E}_{feat}$ are linear embedding layers and $[\cdot; \cdot]$ denotes concatenation [S1, unofficial].
4.  **Error Aggregation:**
    *   For each token $j$, compute two error signals:
        *   **Self Error ($e_{self}$):** The error feature from the patch where the token was predicted.
        *   **Aggregated Error ($e_{agg}$):** The average of error features over all context views in which the token is visible (projected into the view's error feature map and masked by visibility/occlusion) [S1, unofficial].
5.  **3D Spatial Grouping (Serialized Attention):**
    *   Lift tokens to 3D space using their predicted Gaussian means.
    *   Order the 3D points along a space-filling curve.
    *   Partition points into groups of $S$ consecutive points.
    *   Apply self-attention within each group. Use four different space-filling curves across four attention blocks so each token meets a different set of neighbors [S1, unofficial].
    *   Update tokens:
        $$ \Delta z_j^{(i)} = \text{Linear}(\text{SerialAttn}(h_j^{(i)})) $$
        $$ z_j^{(i+1)} = z_j^{(i)} + \Delta z_j^{(i)} $$
        where $h_j^{(i)}$ incorporates the token features and aggregated error signals [S1, unofficial].
6.  **Repeat:** Go to Step 1 with $z^{(i+1)}$ for the next refinement step.

    def normalize_scene_scale(self, poses):
        """

        Rescale translations so all camera centers lie within [-1, 1]^3.
        """
        # Compute mean camera frame
        mean_pose = self.compute_mean_pose(poses)
        # Transform poses to mean frame
        transformed_poses = [self.transform_pose(p, mean_pose) for p in poses]
        # Compute scale factor

        max_extent = max(max(c) for c in centers) - min(min(c) for c in centers)
        scale = 2.0 / max_extent if max_extent > 0 else 1.0
        # Rescale
        scaled_poses = [self.rescale_pose(p, scale) for p in transformed_poses]
        return scaled_poses

        F1, F2, F3 = features['F1'], features['F2'], features['F3']

        # 2. Render and Compute Errors

        Compute pixel and feature-level errors.

        self_errors = []
        agg_errors = []

            self_errors.append(errors[source_view_idx][token.patch_coords])
            
            # Aggregated error from all visible views
            visible_views = self.get_visible_views(projections[j])
            agg_error = torch.mean([errors[v][projections[j][v]] for v in visible_views])
            agg_errors.append(agg_error)
            
        return self_errors, agg_errors

    def decode_gaussians(self, z, poses):
        """
        Final decoding of Gaussians from refined tokens.
        """
        return self.gaussian_head(z)

        """
        Extract mean positions from Gaussian primitives.

        return gaussians.means

    def create_groups(self, ordered_indices, group_size):
        """
        Partition ordered indices into groups of consecutive points.
        """
        groups = []
        for i in range(0, len(ordered_indices), group_size):
            groups.append(ordered_indices[i:i+group_size])
        return groups

### Edge Cases and Pitfalls
*   **Scale Ambiguity:** Feed-forward reconstruction suffers from scale ambiguity. This is handled by normalizing scene scale using context camera poses, ensuring all camera centers lie within $[-1, 1]^3$ [S1, unofficial].
*   **Blind Spots in View Grouping:** Fixed view grouping in Stage 1 leaves blind spots where tokens in different groups cannot interact. Stage 2's 3D spatial grouping connects these tokens once lifted to 3D [S1, unofficial].
*   **Precision:** The sub-pixel offset is bounded using $\tanh$ to ensure Gaussians remain within their 2x2 sub-patch, preventing erratic jumps [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** FineSplat is more efficient than global attention methods and explicit k-NN grouping. It uses serialized attention with space-filling curves, which scales favorably with the number of tokens [S1, unofficial].
*   **Memory Complexity:** Uses a compact Gaussian representation. On DL3DV with 6 views, it uses ~62K Gaussians; on Mip-NeRF 360 with 128 views, ~1.6M Gaussians [S1, unofficial].
*   **Performance:**
    *   **DL3DV (6 views):** 27.325 PSNR, 0.871 SSIM, 0.115 LPIPS [S1, unofficial].
    *   **RE10K (6 views):** 27.394 PSNR, 0.886 SSIM, 0.116 LPIPS [S1, unofficial].
    *   **Mip-NeRF 360 (128 views):** 23.463 PSNR, 0.706 SSIM, 0.214 LPIPS [S1, unofficial].
*   **Strengths:** High quality per unit time; preserves fine details with 4x4 patches; robust to varying numbers of input views; no depth supervision required.
*   **Limitations:** Quality may degrade if Stage 2 steps are insufficient for very large scenes with many views; relies on accurate camera poses (or pose prediction) [S1, unofficial].
*   **When to Use:** Novel view synthesis where high fidelity and efficiency are required, especially with a small number of context views (6-24).
*   **When Not to Use:** When depth supervision is available and preferred; when extremely large scenes with very high view counts (>128) are processed without sufficient Stage 2 steps.

## Background
FineSplat was introduced in 2026 by the authors of the paper "FineSplat: Fine Patches, Local Groups, Detailed Splats" [S1, unofficial]. It builds on the principles of 3D Gaussian Splatting and feed-forward reconstruction methods like [YoNoSplat](12847-anysplat-pipeline.md) and [ZipSplat](12847-anysplat-pipeline.md), addressing their limitations in handling fine-grained details and computational cost. The method is trained on the DL3DV dataset and evaluated on DL3DV, RealEstate10K, and Mip-NeRF 360 [S1, unofficial].
