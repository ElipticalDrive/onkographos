# Keyframe Management

Also called: Keyframing

## Overview
Keyframe Management maintains a small window $W_k$ of keyframes to enable efficient joint optimization of camera poses and 3D Gaussian attributes in online SLAM systems [S1, unofficial]. It solves the problem of computational infeasibility when processing full video streams by discarding redundant frames while ensuring sufficient parallax for robust pose estimation [S1, unofficial]. Unlike fixed-interval strategies, this method uses explicit covisibility metrics and geometric displacement to dynamically insert and remove keyframes [S1, unofficial]. It differs from sibling methods like [WildGS-SLAM](5705-wildgs-slam.md), [GS-SLAM](9192-gs-slam.md), [SplaTAM](9193-splatam.md), [Gaussian-SLAM](9195-gaussian-slam.md), and [Gaussian Splatting SLAM](10078-gaussian-splatting-slam.md) by relying on Gaussian visibility ordering for occlusion-aware covisibility estimation [S1, unofficial].

## How it works
**Inputs:** Current camera frame $i$, last keyframe $j$, current keyframe window $W_k$, median scene depth $d_{med}$ [S1, unofficial].
**Outputs:** Updated window $W_k$, boolean flag indicating if frame $i$ is registered as a new keyframe [S1, unofficial].

**Data Structures:**
*   $W_k$: A list of keyframe indices [S1, unofficial].
*   Visible Gaussians: A set of Gaussian indices marked as visible during rasterization; a Gaussian is visible if it is used in rasterization and the accumulated alpha $\alpha$ along the ray has not reached 0.5 [S1, unofficial].

**Steps:**
1.  **Compute Covisibility:** Calculate the Intersection over Union (IoU) of visible Gaussians between the current frame $i$ and the last keyframe $j$. Let $V_i$ be the set of visible Gaussians in frame $i$ and $V_j$ be the set in frame $j$. The covisibility score $C_{ij}$ is:
    $$ C_{ij} = \frac{|V_i \cap V_j|}{|V_i \cup V_j|} $$
    [S1, unofficial]
2.  **Compute Geometric Displacement:** Calculate the relative translation magnitude $t_{ij} = \|T_i - T_j\|$ between the current frame and the last keyframe [S1, unofficial].
3.  **Keyframe Registration:** Register frame $i$ as a new keyframe if either condition is met:
    *   $C_{ij} < \tau_{cov}$ (covisibility drops below threshold $\tau_{cov}$)
    *   $t_{ij} > \tau_{geo} \cdot d_{med}$ (relative translation is large with respect to median depth $d_{med}$)
    [S1, unofficial]
4.  **Keyframe Removal:** If a new keyframe is added, remove a keyframe from the window $W_k$ if its overlap coefficient with the latest keyframe drops below a threshold [S1, unofficial].
5.  **Gaussian Insertion:** Upon registering a new keyframe, initialize new Gaussians. If depth is available, back-project depth measurements to initialize means $\mu_W$. In monocular cases, render the depth and initialize Gaussians around low-variance depth estimates [S1, unofficial].

**Parameters:**
*   $\tau_{cov}$: Covisibility threshold. Not given in the sources.
*   $\tau_{geo}$: Geometric displacement threshold factor. Not given in the sources.
*   Overlap threshold for removal: Not given in the sources.

**Edge Cases:**
*   **Occlusion:** Handled naturally by the visibility ordering of 3D Gaussians along the camera ray; occluded Gaussians are not counted in $V_i$ [S1, unofficial].
*   **Degenerate Input:** If median depth $d_{med}$ is zero or undefined, the geometric displacement check should be skipped or handled with a fallback threshold [G].

## Subtopics

### Greedy Graph Traversal for Subset Selection
An algorithm to find $N$ well-connected keyframes from the entire registered sequence by greedily expanding an active set based on cumulative inlier connectivity [S2]. It initializes an active set $S_t$ with the incoming frame $I_q$, then iteratively adds the candidate node connected to $S_t$ with the maximum cumulative inliers $c(I_i, S_t) = \sum_{I_j \in S_t} \#\text{inliers}(i, j)$ until $N$ keyframes are reached [S2]. Given that each graph node has a small number of connections (around 10 in experiments), this greedy approach is very efficient [S2].

## Operating characteristics
*   **Time Complexity:** Not given in the sources. Joint optimization is limited to the small window $W_k$ to avoid overhead [S1, unofficial].
*   **Memory Complexity:** Not given in the sources.
*   **Strengths:** Selects non-redundant keyframes observing the same area, spans a wide baseline to provide better multiview constraints, and handles occlusions without requiring additional heuristics [S1, unofficial].
*   **Limitations:** Not given in the sources.
*   **When to use:** Online SLAM systems with limited computational resources [S1, unofficial].

## Background
It adapts keyframe management heuristics from Direct Sparse Odometry (DSO) to the context of 3D Gaussian Splatting, leveraging the inherent visibility ordering of splatted Gaussians [S1, unofficial].
