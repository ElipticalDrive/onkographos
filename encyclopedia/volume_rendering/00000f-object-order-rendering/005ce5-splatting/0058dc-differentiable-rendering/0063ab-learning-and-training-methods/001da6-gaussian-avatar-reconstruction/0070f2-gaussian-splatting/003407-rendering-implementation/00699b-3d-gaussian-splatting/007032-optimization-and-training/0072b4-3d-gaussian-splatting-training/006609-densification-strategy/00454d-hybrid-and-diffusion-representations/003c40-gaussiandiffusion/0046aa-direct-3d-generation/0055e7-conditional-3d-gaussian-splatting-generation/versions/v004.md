# Conditional 3D Gaussian Splatting Generation

Also called: Conditional Generation (Text/Image/Partial), DiffGS Conditional

## Overview
Conditional 3D Gaussian Splatting Generation produces 3D Gaussian Splatting (3DGS) representations conditioned on text prompts, input images, or partial 3DGS inputs containing large occlusions [S1]. It differs from its parent [Direct 3D Generation](11810-direct-3d-generation.md) by explicitly leveraging diffusion-based optimization objectives (DiffGS) to handle conditional constraints, rather than purely feedforward mapping [S1]. It is distinguished from [Promptable Explicit Scene Representation](15906-promptable-explicit-scene-representation.md) by generating the primitives themselves from conditions rather than editing existing ones via activation scores [S1, S1].

## How it works
**Inputs and Outputs:**
- **Inputs:** Text prompts, reference images, or partial 3DGS point clouds/attributes.
- **Outputs:** A set of 3D Gaussians defined by position $\mathbf{x}$, covariance $\Sigma$ (or scale/rotation), opacity $\alpha$, and spherical harmonics coefficients for color $\mathbf{c}$.

**Data Structures:**
The method relies on the standard 3DGS primitive structure. For conditional encoding, it utilizes:
1.  **Text/Image Encoder:** Frozen CLIP encoders [S1].
2.  **Partial 3DGS Encoder:** A modified PointNet [S1].

**Steps:**
1.  **Condition Encoding:**
    - For text: Encode prompt $T$ using frozen CLIP text encoder $\gamma_{\text{text}}$ to get embedding $\mathbf{e}_{\text{text}}$ [S1].
    - For image: Encode reference image $I$ using frozen CLIP image encoder $\gamma_{\text{image}}$ to get embedding $\mathbf{e}_{\text{image}}$ [S1].
    - For partial 3DGS: Encode partial input $P$ using modified PointNet $\gamma_{\text{partial}}$ to get embedding $\mathbf{e}_{\text{partial}}$ [S1].

2.  **Diffusion Optimization:**
    - Train the DiffGS model using the conditional optimization objective defined in Eq.(8) of the source [S1]. The specific formula for Eq.(8) is not provided in the sources.

3.  **Generation:**
    - Sample or optimize the Gaussian parameters conditioned on the encoded embeddings [S1].

**Parameters:**
- **Dataset:** ShapeNet chair class with commonly used data splits [S1].
- **Encoders:** Frozen CLIP [S1].
- **Partial Encoder:** Modified PointNet [S1].

**Edge Cases and Pitfalls:**
- **Partial Input Occlusion:** The method is designed to handle highly occluded inputs, but performance depends on the capacity of $\gamma_{\text{partial}}$ to capture global structure from sparse data [S1].
- **Numerical Stability:** In related text-to-3D implementations, Gaussian opacity is clamped to $[0.004, 0.99]$ to ensure stable gradients and prevent overflow/underflow [S3].

## Subtopics

### [Promptable Explicit Scene Representation](15906-promptable-explicit-scene-representation.md)
A mechanism for 3D editing (extraction, deletion, appearance modification) in 3D Gaussian Splatting by computing activation scores of 3D Gaussians based on prompts (text, points, boxes) using cosine similarity and softmax. It differs from implicit NeRF feature fields by operating on explicit Gaussian primitives, allowing direct manipulation of color and opacity parameters for specific semantic subsets.

### Interactive3D
A method operating in two stages for interactive 3D object generation and refinement, optimizing 3D objects through 3DGS and SDS in first stage, then transforming model into InstantNGP structure with interactive hash refinement module in second stage [S2].

### 3D Gaussian Splatting (Text-to-3D Implementation)
A reimplementation of 3D Gaussian Splatting adapted for text-to-3D generation, modified to support a learnable MLP background and specific gradient propagation [S3]. Gradient back-propagation calculates gradients in the forward rendering order, rather than the inverse order used in the official code [S3]. Depth maps are rendered by sampling the view-space depth at the centers of the Gaussians [S3]. A z-variance renderer is implemented to compute z-variance for use in a z-var loss term during optimization [S3]. Gaussian opacity is clamped to a fixed range during rendering and optimization to stabilize gradients and prevent numerical overflow/underflow [S3]. The target number of Gaussians after densification during training is around $[10^5, 10^6]$ [S3]. The official implementation propagates gradients in inverse order (last rendered Gaussians receive gradients first), whereas this variant uses rendering order to simplify per-pixel background integration [S3].

### Gaussian Pulling to Zero-Level Set
A technique that pulls Gaussian centers onto the zero-level set of a neural SDF field to prevent floating ellipsoids and achieve accurate geometry estimation. It also pulls query points to Gaussian disks rather than centers to bridge the gap between continuous SDF fields and sparse Gaussian distributions [S4]. Steps: 1. Pull Gaussian centers to the zero-level set of the SDF field. 2. Pull neighboring space/query points onto Gaussian disks. 3. Use normalized SDF gradient for the pulling operation [S4]. Differs from NeuralPull [45], which pulls query points to Gaussian centers. This method pulls query points to Gaussian disks, better bridging continuous SDF fields and sparse Gaussian distributions [S4].

## Background
Originated with DiffGS (Functional Gaussian Splatting Diffusion) [S1]. The method explores conditional generation capabilities for 3DGS, including text/image-conditional generation and Gaussian Splatting completion [S1]. It is part of the broader field of differentiable and inverse volume rendering, specifically within 3D Gaussian Splatting training optimization and densification strategies involving hybrid and diffusion representations [S1].
