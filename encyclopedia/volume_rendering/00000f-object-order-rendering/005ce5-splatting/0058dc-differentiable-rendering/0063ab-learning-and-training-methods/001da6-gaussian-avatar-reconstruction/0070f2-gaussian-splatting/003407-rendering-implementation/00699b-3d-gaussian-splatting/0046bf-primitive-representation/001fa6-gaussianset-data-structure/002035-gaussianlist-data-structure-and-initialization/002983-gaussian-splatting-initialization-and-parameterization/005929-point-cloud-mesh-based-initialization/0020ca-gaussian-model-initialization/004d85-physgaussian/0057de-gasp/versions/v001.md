# GASP

Also called: GASP (Gaussian Splatting for Physic-Based Simulations), GASP pipeline

## Overview
GASP is a pipeline that integrates Gaussian Splatting with physics-based simulations by converting flat Gaussians into triangle faces using the GaMeS reparametrization, simulating the vertices using a standard Material Point Method (MPM) engine, and reassembling the deformed triangles back into Gaussians [S1, unofficial]. It solves the problem of applying physics to Gaussian representations without the artifacts caused by direct vertex processing or the incompatibility of 2DGS with triangle-based simulation [S1, unofficial]. Unlike [PhysGaussian](6002-physgaussian.md), which uses MPM directly over Gaussians, GASP explicitly converts Gaussians to a mesh, simulates the mesh, and converts back, ensuring stable simulations for flat Gaussian components [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A collection of Gaussians $G = \{(N(m_i, R_i, S_i), \sigma_i, c_i)\}_{i=1}^p$, where $m_i$ is the mean, $R_i$ is the rotation matrix, $S_i$ is the scaling matrix, $\sigma_i$ is the opacity, and $c_i$ is the color [S1, unofficial].
*   **Output:** A deformed collection of Gaussians $G_t = \{(N(T^{-1}(\phi(V_i, t))), \sigma_i, c_i)\}_{i=1}^p$ at time $t$ [S1, unofficial].

**Data Structures**
*   **Gaussian:** Defined by mean $m$, rotation $R$, scaling $S$, opacity $\sigma$, and color $c$ [S1, unofficial].
*   **Mesh (Triangle Soup):** Defined by a set of vertices $V$ and edges $E$ derived from the GaMeS transformation [S1, unofficial].
*   **CoreGaussian/SubGaussian:** Hierarchical structure where CoreGaussians are simulated and SubGaussians inherit movement patterns [S1, unofficial].

**Steps**
1.  **Extract Parameters:** From the input Gaussian collection $G$, extract means $m_i$, scaling matrices $S_i$, and rotation matrices $R_i$ for each Gaussian $i$ [S1, unofficial].
2.  **Convert to Mesh (GaMeS):** Transform the Gaussian parameters into a mesh (triangle soup) using the GaMeS reparametrization. The vertices $V$ are obtained by:
    $$V = \{V_i = T(m_i, R_i, S_i)\}_{i=1}^p$$
    where $T$ is the GaMeS transformation function [S1, unofficial]. Each flat Gaussian is represented by a triangle face with vertices $V = [v_1, v_2, v_3]$, where $v_1 = m_i$ (center), and $v_2, v_3$ lie on the main components of the ellipsoid [S1, unofficial].
3.  **Simulate Vertices:** Apply the physics-based simulation engine (e.g., MPM) to the vertices $V$ individually to obtain deformed vertices $V_t$. The deformation is modeled by a map $\phi(X, t)$:
    $$V_t = \{\phi(V_i, t) : V_i \in V\}$$
    The simulation engine operates as a black box on the point cloud [S1, unofficial].
4.  **Reassemble Triangle Soup:** Combine the deformed vertices $V_t$ with the original edges $E$ to form the deformed triangle soup $(V_t, E_t)$ [S1, unofficial].
5.  **Correction Algorithm:** Mitigate artifacts caused by independent vertex processing. For each Gaussian face with vertices $V = [v_1, v_2, v_3]$:
    *   Check if the distance between transformed nodes exceeds a threshold relative to original nodes:
        $$\|\phi(v_1, t) - \phi(v_i, t)\| > \alpha \|v_1 - v_i\| \quad \text{for } i = 2, 3$$
        where $\alpha$ is a hyperparameter [S1, unofficial].
    *   If the condition is met, correct the scaling parameter $s_i$ (specifically the components corresponding to $v_2, v_3$) to be the original value multiplied by $\alpha$ [S1, unofficial].
6.  **Convert Back to Gaussians:** Use the inverse GaMeS transformation $T^{-1}$ to convert the deformed triangle soup back to Gaussians:
    $$G_t = \{(N(T^{-1}(\phi(V_i, t))), \sigma_i, c_i)\}_{i=1}^p$$
    The opacity $\sigma_i$ and color $c_i$ remain unchanged [S1, unofficial].
7.  **Hierarchical Simulation (Optional):** To accelerate simulation for large scenes:
    *   Use BIRCH clustering to create CoreGaussians [S1, unofficial].
    *   Simulate only the CoreGaussians [S1, unofficial].
    *   Transfer the movement pattern from CoreGaussians to SubGaussians [S1, unofficial].

**Pseudocode**
```python
def GASP_pipeline(Gaussians, physics_engine, alpha):
    """
    GASP: Gaussian Splatting for Physics-Based Simulations.
    
    Args:
        Gaussians: List of Gaussian objects with attributes m, R, S, sigma, c.
        physics_engine: A function or object that applies deformation phi(V, t) to vertices.
        alpha: Hyperparameter for correction algorithm.
        
    Returns:
        Deformed_Gaussians: List of deformed Gaussian objects.
    """
    Deformed_Gaussians = []
    
    # Step 1 & 2: Convert Gaussians to Mesh (Triangle Soup)
    # GaMeS transformation T converts Gaussian parameters to triangle vertices
    # Each Gaussian i becomes a triangle with vertices [v1, v2, v3]
    # v1 = m_i
    # v2 = m_i + s2 * r2 (where s2, r2 are from S_i, R_i)
    # v3 = m_i + s3 * r3
    Mesh_Faces = []
    for g in Gaussians:
        v1 = g.m
        # Extract main components from scaling matrix S and rotation matrix R
        # Assuming S is diagonal with elements s1, s2, s3 and R has columns r1, r2, r3
        s2 = g.S[1, 1]
        s3 = g.S[2, 2]
        r2 = g.R[:, 1]
        r3 = g.R[:, 2]
        
        v2 = g.m + s2 * r2
        v3 = g.m + s3 * r3
        
        Mesh_Faces.append({
            'original_vertices': [v1, v2, v3],
            'gaussian': g
        })
        
    # Step 3: Simulate Vertices
    # Extract all unique vertices from the mesh faces
    All_Vertices = set()
    for face in Mesh_Faces:
        All_Vertices.update(face['original_vertices'])
        
    # Apply physics engine to each vertex
    # phi(V, t) is the deformation map
    Deformed_Vertices = {}
    for v in All_Vertices:
        Deformed_Vertices[v] = physics_engine.phi(v, t=1) # Assuming t=1 for simplicity
        
    # Step 4 & 5: Reassemble and Correct
    for face in Mesh_Faces:
        v1_orig, v2_orig, v3_orig = face['original_vertices']
        g = face['gaussian']
        
        v1_def = Deformed_Vertices[v1_orig]
        v2_def = Deformed_Vertices[v2_orig]
        v3_def = Deformed_Vertices[v3_orig]
        
        # Correction Algorithm
        # Check distance between transformed center and other vertices
        # against original distance scaled by alpha
        dist_12_orig = norm(v1_orig - v2_orig)
        dist_12_def = norm(v1_def - v2_def)
        
        dist_13_orig = norm(v1_orig - v3_orig)
        dist_13_def = norm(v1_def - v3_def)
        
        # Correct scaling if threshold exceeded
        # The correction applies to the scaling parameters s2 and s3
        new_s2 = g.S[1, 1]
        new_s3 = g.S[2, 2]
        
        if dist_12_def > alpha * dist_12_orig:
            new_s2 = g.S[1, 1] * alpha
            
        if dist_13_def > alpha * dist_13_orig:
            new_s3 = g.S[2, 2] * alpha
            
        # Step 6: Convert Back to Gaussians
        # Inverse GaMeS transformation T^-1
        # The new mean is the deformed center v1_def
        # The new scaling is adjusted (new_s2, new_s3)
        # The rotation and other parameters are adjusted accordingly to match the deformed triangle
        # Note: The exact inverse transformation T^-1 is defined by the GaMeS paper [S1, unofficial]
        # Here we assume a function inverse_gaMES that reconstructs Gaussian params from deformed vertices
        Deformed_G = inverse_gaMES([v1_def, v2_def, v3_def], g.sigma, g.c, new_s2, new_s3)
        
        Deformed_Gaussians.append(Deformed_G)
        
    return Deformed_Gaussians

def inverse_gaMES(vertices, sigma, color, new_s2, new_s3):
    """
    Reconstructs a Gaussian from deformed triangle vertices.
    This is a placeholder for the specific inverse GaMeS formula.
    The mean is the first vertex. The orientation and scale are derived from the triangle geometry.
    """
    v1, v2, v3 = vertices
    
    # New mean is the deformed center
    new_m = v1
    
    # Reconstruct rotation and scaling from the deformed triangle edges
    # Edge 1: v2 - v1, Edge 2: v3 - v1
    e1 = v2 - v1
    e2 = v3 - v1
    
    # Normalize to get directions
    r2_new = e1 / norm(e1)
    r3_new = e2 / norm(e2)
    
    # Orthogonalize r3_new against r2_new (Gram-Schmidt)
    r3_new = r3_new - dot(r3_new, r2_new) * r2_new
    r3_new = r3_new / norm(r3_new)
    
    # Compute r1_new as cross product
    r1_new = cross(r2_new, r3_new)
    
    # Construct rotation matrix
    new_R = matrix([r1_new, r2_new, r3_new]).T
    
    # Construct scaling matrix
    # The lengths of e1 and e2 correspond to the scaled components
    s2_new = norm(e1)
    s3_new = norm(e2)
    
    # Ensure diagonal scaling matrix
    new_S = matrix([[s2_new, 0, 0],
                    [0, s3_new, 0],
                    [0, 0, 0]]) # Assuming flat Gaussian, third dimension is 0 or negligible
    
    return Gaussian(m=new_m, R=new_R, S=new_S, sigma=sigma, c=color)
```

**Parameters**
*   $\alpha$: A hyperparameter used in the correction algorithm to scale the Gaussian size $s_i$ when vertex distances exceed the threshold [S1, unofficial].

**Edge Cases and Pitfalls**
*   **Independent Vertex Processing:** Processing each vertex of the triangle soup individually can produce noticeable artifacts if the deformation is large or non-rigid [S1, unofficial]. The correction algorithm mitigates this.
*   **Flat Gaussians:** GASP relies on the GaMeS representation, which is designed for flat Gaussians. It is not naturally compatible with 2DGS or other representations that do not fit the triangle-based simulation setting [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The simulation step operates on the vertices of the triangle soup. Using hierarchical simulation with BIRCH clustering (CoreGaussians) significantly accelerates the process by reducing the number of points simulated [S1, unofficial].
*   **Memory Complexity:** Depends on the number of Gaussians and the mesh representation. The conversion to mesh and back adds overhead but is generally efficient [S1, unofficial].
*   **Strengths:** Stable simulations for flat Gaussians; avoids pointed artifacts and holes; compatible with standard physics engines (Blender, Taichi, Genesis); fast rendering [S1, unofficial].
*   **Limitations:** Requires GaMeS representation (flat Gaussians); correction algorithm adds computational step; hierarchical simulation requires clustering [S1, unofficial].
*   **When to use:** When simulating physics for scenes represented by flat Gaussians and compatibility with standard MPM engines is desired [S1, unofficial].
*   **When not to use:** When the scene contains non-flat Gaussians or when 2DGS is the primary representation [S1, unofficial].

## Background
GASP was introduced in the paper "GASP: Gaussian Splatting for Physic-Based Simulations" [S1, unofficial]. It builds on the GaMeS reparametrization of Gaussian Splatting, which represents flat Gaussians as triangle faces. The method integrates this representation with point-based physics engines, specifically the Material Point Method (MPM) [S1, unofficial]. It addresses the limitations of direct physics application to Gaussians, which often results in artifacts, and the incompatibility of 2DGS with triangle-based simulation [S1, unofficial].
