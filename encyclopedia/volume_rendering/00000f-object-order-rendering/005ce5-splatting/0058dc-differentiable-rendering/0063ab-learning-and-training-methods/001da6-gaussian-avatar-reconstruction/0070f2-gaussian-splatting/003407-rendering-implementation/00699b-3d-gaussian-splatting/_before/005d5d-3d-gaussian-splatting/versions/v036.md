# 3D Gaussian Splatting

Also called: 3D Gaussian Splatting Pipeline, 3DGS Rendering, 3DGS Rasterization, 3D Gaussian Splatting Rasterization, 3D Gaussian Splatting Rendering Pipeline, Standard 3D Gaussian Splatting Rendering, Kerbl et al. pipeline, Original 3DGS

## Overview
3D Gaussian Splatting (3DGS) is a novel view synthesis method that represents a 3D scene as a collection of anisotropic 3D Gaussian primitives, each defined by a mean position, covariance matrix, opacity, and view-dependent color [S1][S6, unofficial][S9]. It solves the problem of real-time, high-fidelity rendering by projecting these 3D Gaussians into 2D screen-space ellipses and rasterizing them using a tile-based, differentiable software rasterizer [S1][S6, unofficial]. Unlike volumetric ray-marching methods like NeRF, 3DGS uses discrete, point-based splatting, and unlike standard triangle rasterization, it handles soft, overlapping primitives with analytic gradients for end-to-end training [S6, unofficial][S14, unofficial]. It sets itself apart from siblings like [3D Gaussian Splatting Rendering (CPU-Sorted, Instanced)](2058-3d-gaussian-splatting-rendering-cpu-sorted-instanced.md) by relying on GPU-accelerated, tile-based sorting and compositing for maximum throughput.

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of $N$ 3D Gaussians, each parameterized by mean $\boldsymbol{\mu} \in \mathbb{R}^3$, rotation quaternion $\mathbf{q} \in \mathbb{R}^4$, scale vector $\mathbf{s} \in \mathbb{R}^3$, opacity $\alpha \in \mathbb{R}$, and spherical harmonics coefficients $\mathbf{c} \in \mathbb{R}^{3 \times K}$ (where $K$ depends on the SH degree). Camera parameters: view matrix $\mathbf{V}$, projection intrinsics ($f_x, f_y, c_x, c_y$), image dimensions ($H, W$), and tile size (typically $16 \times 16$) [S6, unofficial][S10].
*   **Outputs:** An RGB image (and optionally depth/normal maps) of size $H \times W \times 3$.

**Data Structures:**
*   **Gaussian Attributes:** Stored in contiguous arrays (SoA) for efficient GPU access:
    *   `xyz`: `[N, 3]` float32, world-space means.
    *   `rot`: `[N, 4]` float32, quaternions.
    *   `scale`: `[N, 3]` float32, raw scales (exponentiated at render time).
    *   `opacity`: `[N, 1]` float32, raw opacity (sigmoided at render time).
    *   `sh`: `[N, SH_dim]` float32, spherical harmonics coefficients.
    *   [S12, unofficial]
*   **Projection Data:** Computed per Gaussian per camera:
    *   `means_2d`: `[C, N, 2]` screen-space coordinates.
    *   `conics`: `[C, N, 3]` upper-triangular inverse of the 2D covariance matrix ($\Sigma_{2D}^{-1}$), stored as $[\Sigma^{-1}_{00}, \Sigma^{-1}_{01}, \Sigma^{-1}_{11}]$ to save memory and computation [S12, unofficial][S10].
    *   `radii`: `[C, N, 2]` bounding box radius in pixels for tile intersection.
    *   `depths`: `[C, N]` camera-space depth ($\mu'_z$).
    *   [S11, unofficial]

**Numbered Steps:**

1.  **Activation and Covariance Construction:**
    *   Normalize rotations: $\mathbf{q}_{norm} = \mathbf{q} / \|\mathbf{q}\|$.
    *   Exponentiate scales: $\mathbf{s}_{eff} = \exp(\mathbf{s})$.
    *   Sigmoid opacities: $\alpha_{eff} = \sigma(\alpha)$.
    *   Construct rotation matrix $\mathbf{R}$ from $\mathbf{q}_{norm}$.
    *   Construct 3D covariance: $\boldsymbol{\Sigma}_{3D} = \mathbf{R} \mathbf{S} \mathbf{S}^T \mathbf{R}^T$, where $\mathbf{S} = \text{diag}(\mathbf{s}_{eff})$ [S6, unofficial][S13, unofficial].

2.  **Camera Space Transformation:**
    *   Transform means: $\boldsymbol{\mu}' = \mathbf{V} \boldsymbol{\mu}$ (homogeneous coordinates).
    *   Transform covariance: $\boldsymbol{\Sigma}' = \mathbf{V}_{1:3, 1:3} \boldsymbol{\Sigma}_{3D} \mathbf{V}_{1:3, 1:3}^T$, where $\mathbf{V}_{1:3, 1:3}$ is the upper-left $3 \times 3$ submatrix of the view matrix [S6, unofficial][S13, unofficial].

3.  **Projection to Screen Space:**
    *   Compute Jacobian $\mathbf{J}$ of the projective projection at $\boldsymbol{\mu}'$:
        $$ \mathbf{J} = \begin{pmatrix} \frac{f_x}{\mu'_z} & 0 & -\frac{f_x \mu'_x}{\mu'_z^2} \\ 0 & \frac{f_y}{\mu'_z} & -\frac{f_y \mu'_y}{\mu'_z^2} \end{pmatrix} $$
        [S6, unofficial][S10]
    *   Compute 2D screen-space covariance: $\boldsymbol{\Sigma}_{2D} = \mathbf{J} \boldsymbol{\Sigma}' \mathbf{J}^T$.
    *   Compute 2D mean: $\boldsymbol{\mu}_{2D} = \begin{pmatrix} \frac{f_x \mu'_x}{\mu'_z} + c_x \\ \frac{f_y \mu'_y}{\mu'_z} + c_y \end{pmatrix}$.
    *   Compute conic (inverse covariance) for rasterization: $\mathbf{C}_{2D} = \boldsymbol{\Sigma}_{2D}^{-1}$. Store upper triangle $[\mathbf{C}_{2D}(0,0), \mathbf{C}_{2D}(0,1), \mathbf{C}_{2D}(1,1)]$ [S12, unofficial][S10].
    *   Compute bounding radius: $r = \lceil 3.0 \sqrt{\max(\boldsymbol{\Sigma}_{2D}(0,0), \boldsymbol{\Sigma}_{2D}(1,1))} \rceil$ (3-sigma rule) [S12, unofficial][S6, unofficial].

4.  **Culling and Sorting:**
    *   **Near-plane Culling:** Discard Gaussians where $\mu'_z < z_{near}$ (default 0.01) [S10][S11, unofficial].
    *   **Frustum Culling:** Discard Gaussians outside the view frustum (optional, often handled by tile intersection) [S10].
    *   **Sorting:** Sort remaining Gaussians by camera-space depth $\mu'_z$ in ascending order (front-to-back) [S6, unofficial][S10]. This approximates the correct occlusion order for alpha compositing [S6, unofficial].

5.  **Tile Assignment:**
    *   Divide the image into tiles of size $T \times T$ (default 16x16) [S10].
    *   For each Gaussian, determine which tiles its bounding box intersects.
    *   Create a list of `(tile_id, gaussian_index)` pairs and sort by tile ID to process one tile at a time [S1][S11, unofficial].

6.  **Rasterization and Compositing:**
    *   For each tile, initialize accumulated color $\mathbf{C}_{acc} = \mathbf{0}$ and transmittance $T = 1.0$.
    *   For each Gaussian $i$ intersecting the tile (in depth-sorted order):
        *   Compute alpha contribution at pixel $\mathbf{x}$:
            $$ \alpha_i(\mathbf{x}) = \alpha_{eff} \cdot \exp\left(-\frac{1}{2} (\mathbf{x} - \boldsymbol{\mu}_{2D})^T \boldsymbol{\Sigma}_{2D}^{-1} (\mathbf{x} - \boldsymbol{\mu}_{2D})\right) $$
            [S1][S6, unofficial]
        *   Compute view-dependent color $\mathbf{c}_i$ using spherical harmonics evaluated at the viewing direction $\mathbf{d} = \text{normalize}(\boldsymbol{\mu}' - \text{camera\_origin})$ [S6, unofficial][S11, unofficial].
        *   Update color and transmittance:
            $$ \mathbf{C}_{acc} \leftarrow \mathbf{C}_{acc} + T \cdot \alpha_i(\mathbf{x}) \cdot \mathbf{c}_i $$
            $$ T \leftarrow T \cdot (1 - \alpha_i(\mathbf{x})) $$
            [S10][S13, unofficial]
        *   **Early Termination:** If $T < \tau$ (threshold, e.g., 0.003), stop processing further Gaussians for this pixel [S10].
    *   Add background color $\mathbf{c}_{bg}$ scaled by final $T$: $\mathbf{C}_{final} = \mathbf{C}_{acc} + T \cdot \mathbf{c}_{bg}$ [S6, unofficial].

    """
    Render a scene using 3D Gaussian Splatting.
    
    Args:
        gaussians: Dict with keys 'xyz' (N,3), 'rot' (N,4), 'scale' (N,3), 
                   'opacity' (N,1), 'sh' (N, SH_dim).
        camera: Dict with 'view_matrix' (4,4), 'intrinsics' (fx, fy, cx, cy), 
                'width', 'height'.
        image_size: (H, W).
        tile_size: int.
        z_near: float.
        tau: float.
        
    Returns:
        image: (H, W, 3) RGB image.
    """
    N = gaussians['xyz'].shape[0]
    H, W = image_size
    fx, fy, cx, cy = camera['intrinsics']
    V = camera['view_matrix']
    
    # 1. Activation and Covariance Construction
    q_norm = gaussians['rot'] / np.linalg.norm(gaussians['rot'], axis=1, keepdims=True)
    s_eff = np.exp(gaussians['scale'])
    alpha_eff = 1.0 / (1.0 + np.exp(-gaussians['opacity']))
    
    # Construct R from quaternion q_norm
    # [G] Helper function to convert quaternion to rotation matrix
    R = quaternion_to_rotation_matrix(q_norm) # Shape (N, 3, 3)
    S = np.einsum('ni,ij->nij', s_eff, np.eye(3)) # Diagonal scaling matrix
    Sigma_3D = R @ S @ S.T @ R.T # Shape (N, 3, 3)
    
    # 2. Camera Space Transformation
    # Homogeneous coordinates for means
    xyz_h = np.concatenate([gaussians['xyz'], np.ones((N, 1))], axis=1) # (N, 4)
    mu_prime_h = (V @ xyz_h.T).T # (N, 4)
    mu_prime = mu_prime_h[:, :3] # (N, 3)
    
    V_3x3 = V[:3, :3]
    Sigma_prime = V_3x3 @ Sigma_3D @ V_3x3.T # (N, 3, 3)
    
    # 3. Projection to Screen Space
    mu_z = mu_prime[:, 2]
    mu_x = mu_prime[:, 0]
    mu_y = mu_prime[:, 1]
    
    # Jacobian J (N, 2, 3)
    J = np.zeros((N, 2, 3))
    J[:, 0, 0] = fx / mu_z
    J[:, 0, 2] = -fx * mu_x / (mu_z ** 2)
    J[:, 1, 1] = fy / mu_z
    J[:, 1, 2] = -fy * mu_y / (mu_z ** 2)
    
    # 2D Covariance Sigma_2D (N, 2, 2)
    Sigma_2D = np.einsum('nij,njk,nkl->nil', J, Sigma_prime, J.transpose(0, 2, 1))
    
    # 2D Means
    mu_2d = np.zeros((N, 2))
    mu_2d[:, 0] = (fx * mu_x / mu_z) + cx
    mu_2d[:, 1] = (fy * mu_y / mu_z) + cy
    
    # Conics (Inverse Covariance)
    # [G] Compute inverse of 2x2 matrices efficiently
    Sigma_2D_inv = np.zeros((N, 2, 2))
    for i in range(N):
        Sigma_2D_inv[i] = np.linalg.inv(Sigma_2D[i])
        
    conics = np.stack([Sigma_2D_inv[:, 0, 0], Sigma_2D_inv[:, 0, 1], Sigma_2D_inv[:, 1, 1]], axis=1) # (N, 3)
    
    # Radii (3-sigma)
    radii = np.ceil(3.0 * np.sqrt(np.maximum(Sigma_2D[:, 0, 0], Sigma_2D[:, 1, 1]))) # (N,)
    
    # 4. Culling and Sorting
    valid_mask = mu_z > z_near
    valid_indices = np.where(valid_mask)[0]
    
    if len(valid_indices) == 0:
        return np.zeros((H, W, 3))
        
    depths = mu_prime[valid_indices, 2]
    sorted_order = np.argsort(depths)
    sorted_indices = valid_indices[sorted_order]
    
    # 5. Tile Assignment
    # [G] Determine tile grid
    tile_w = int(np.ceil(W / tile_size))
    tile_h = int(np.ceil(H / tile_size))
    
    # For each gaussian, find intersecting tiles
    # [G] Helper to compute bounding box in pixel space
    tile_assignments = []
    for idx in sorted_indices:
        x, y = mu_2d[idx]
        r = radii[idx]
        min_x, max_x = int(np.floor(x - r)), int(np.ceil(x + r))
        min_y, max_y = int(np.floor(y - r)), int(np.ceil(y + r))
        
        min_tx, max_tx = max(0, min_x // tile_size), min(tile_w, (max_x // tile_size) + 1)
        min_ty, max_ty = max(0, min_y // tile_size), min(tile_h, (max_y // tile_size) + 1)
        
        for ty in range(min_ty, max_ty):
            for tx in range(min_tx, max_tx):
                tile_assignments.append((ty * tile_w + tx, idx))
                
    # Sort by tile ID
    tile_assignments.sort(key=lambda x: x[0])
    
    # 6. Rasterization
    image = np.zeros((H, W, 3))
    
    # Process tile by tile
    current_tile = -1
    for tile_id, g_idx in tile_assignments:
        if tile_id != current_tile:
            # Initialize for new tile
            # [G] Get pixel coordinates for this tile
            ty, tx = divmod(tile_id, tile_w)
            y_start, y_end = ty * tile_size, min((ty + 1) * tile_size, H)
            x_start, x_end = tx * tile_size, min((tx + 1) * tile_size, W)
            
            # Precompute pixel coordinates for the tile
            pixel_coords = np.zeros((y_end - y_start, x_end - x_start, 2))
            for dy in range(y_end - y_start):
                for dx in range(x_end - x_start):
                    pixel_coords[dy, dx] = [x_start + dx, y_start + dy]
            
            current_tile = tile_id
            
        # Get gaussian data
        g_mu_2d = mu_2d[g_idx]
        g_conic = conics[g_idx]
        g_alpha = alpha_eff[g_idx]
        g_color = compute_sh_color(gaussians['sh'][g_idx], mu_prime[g_idx], camera) # [G] Helper
        
        # Rasterize this gaussian to the tile
        # [G] Evaluate Gaussian at each pixel in the tile
        dy = np.arange(y_start, y_end)
        dx = np.arange(x_start, x_end)
        Y, X = np.meshgrid(dy, dx, indexing='ij')
        pixel_positions = np.stack([X, Y], axis=-1).reshape(-1, 2)
        
        # Vectorized alpha calculation
        # alpha = alpha_eff * exp(-0.5 * (x - mu)^T Sigma_inv (x - mu))
        diff = pixel_positions - g_mu_2d # (P, 2)
        # Quadratic form: x^T A x = A00 x^2 + 2 A01 xy + A11 y^2
        # Using conics: c00, c01, c11
        alpha_vals = g_alpha * np.exp(-0.5 * (
            g_conic[0] * diff[:, 0]**2 + 
            2 * g_conic[1] * diff[:, 0] * diff[:, 1] + 
            g_conic[2] * diff[:, 1]**2
        ))
        
        # Clip alpha to [0, 1]
        alpha_vals = np.clip(alpha_vals, 0, 1)

## Subtopics

### [3D Gaussian Splatting Differentiable Rasterizer](2813-3d-gaussian-splatting-differentiable-rasterizer.md)
The 3D Gaussian Splatting Differentiable Rasterizer is a screen-space rendering method that projects a set of 3D Gaussian primitives into 2D ellipses and alpha-composites them to produce an RGB image, while providing exact gradients for all Gaussian parameters (position, scale, rotation, opacity, color) and camera poses. It differs from volumetric ray-marching methods like NeRF by using discrete, point-based splatting and from standard OpenGL rasterization by computing analytic gradients for the non-linear projection and compositing operations, enabling end-to-end differentiable training. It builds on [3D Gaussian Splatting Rasterization](2812-3d-gaussian-splatting-rasterization.md) by implementing the specific forward and backward passes required for optimization.

### [3D Gaussian Splatting MVP](3410-3d-gaussian-splatting-mvp.md)
3D Gaussian Splatting MVP is a self-contained, pure-PyTorch implementation of the core 3D Gaussian Splatting rendering algorithm, designed as a teaching reference rather than a production renderer. It solves the problem of understanding the mathematical foundations of differentiable Gaussian rasterization by implementing the full pipeline—camera projection, covariance transformation, depth sorting, and alpha compositing—using standard tensor operations without custom CUDA kernels. It sets itself apart from production implementations like [3D Gaussian Splatting Rendering (Software)](2805-3d-gaussian-splatting-rendering-software.md) by explicitly skipping tile-based optimization, spherical harmonics, and adaptive density control, favoring readability and explicit Python loops over vectorized GPU performance.

### [Ghost Ellipsoids for Chunked Training](3559-ghost-ellipsoids-for-chunked-training.md)
Ghost Ellipsoids for Chunked Training resolves boundary artifacts in chunked volume training by including ellipsoids from neighboring chunks in the loss computation without updating their parameters, providing boundary context without requiring a global volume or merged model. Unlike chunk-based 3DGS methods that resolve boundary inconsistencies by merging chunks into a global coarse model or through post-training stages, this method requires boundary support during training itself without access to a global volume.

### [2D Gaussian Splatting Rasterization](4815-2d-gaussian-splatting-rasterization.md)
This method renders a scene represented by 2D Gaussian primitives (surfels) into RGB, alpha, normal, and depth maps using a custom rasterizer. It differs from standard 3D Gaussian Splatting by operating on surfels projected into screen space, accumulating color and geometric attributes via front-to-back alpha compositing [Parent]. It serves as the Tier-1 NumPy reference implementation for 2D Gaussian Splatting, performing ray-surfel intersection per pixel using the projection matrix.

### [Taming 3DGS](8058-taming-3dgs.md)
Taming 3DGS is a resource-efficiency method for 3D Gaussian Splatting that imposes an explicit cap on the total number of Gaussians to enable high-quality rendering on consumer-grade GPUs. It steers the densification process to spend a fixed budget where it helps most, trading peak quality for faster training and smaller model size. Unlike standard 3DGS which allows unbounded growth, this approach formulates optimization as a mixed-integer problem to maintain a constant Gaussian count.

### [Analytic-Splatting](8084-analytic-splatting.md)
Analytic-Splatting is a rendering method that replaces the point-sampling of 2D Gaussians in 3D Gaussian Splatting (3DGS) with an analytical approximation of the integral of the Gaussian signal over the pixel window area to reduce aliasing artifacts during zooming or resolution changes. Unlike [3D Gaussian Splatting Rendering (Software)](2805-3d-gaussian-splatting-rendering-software.md) which treats pixels as isolated points, or [Mip-Splatting](3410-3d-gaussian-splatting-mvp.md) which uses a hybrid filtering mechanism that suppresses high-frequency components, Analytic-Splatting preserves high-quality details by analytically integrating the signal using a conditioned logistic function approximation of the Gaussian CDF.

### [Projection Geometry and Coordinate Systems](9313-projection-geometry-and-coordinate-systems.md)
This family defines the mathematical framework for transforming 3D Gaussian primitives, defined by mean $\boldsymbol{\mu}$ and covariance $\boldsymbol{\Sigma}$, into 2D distributions suitable for rasterization [G]. It sets apart from standard perspective projection by supporting optimal tangent-plane projections [3293-optimal-gaussian-splatting.md] and specialized geometries such as cone-beam X-ray scanning [3458-3d-gaussian-splatting-rasterization-cone-beam-scanner-space.md].

### [Texture and Appearance Representation](9528-texture-and-appearance-representation.md)
This family extends the standard 3D Gaussian Splatting primitive representation to model high-frequency spatial details and view-dependent optical effects that static isotropic color vectors (Spherical Harmonics) cannot capture. It replaces or augments the per-Gaussian color attribute with explicit textures, neural networks, or directional basis functions, enabling the reconstruction of complex materials, specularities, and fine surface patterns. Unlike the base [3D Gaussian Splatting](2812-3d-gaussian-splatting.md) method which assumes uniform color per primitive, these methods decouple geometry from appearance or enhance the appearance model with directional sensitivity.

### [Point-Based Ray Tracing for Visibility](10934-point-based-ray-tracing-for-visibility.md)
Point-Based Ray Tracing for Visibility serves as a sparse visibility oracle that evaluates transmittance along sampled light directions using a bounding volume hierarchy (BVH) of Gaussian proxies, enabling evaluation from any point in space in any direction. Unlike the camera-tied rasterizer, it decouples visibility estimation from screen-space projection, allowing it to act as a drop-in companion to standard 3D Gaussian Splatting (3DGS) by reusing the same EWA-splatting formulation for consistent blending without requiring training mismatch.

### [Primitive Representation](11838-primitive-representation.md)
Primitive Representation defines the geometric and photometric data structures used to approximate a 3D scene in Gaussian Splatting methods [G]. It solves the problem of representing continuous geometry and appearance with discrete, differentiable primitives that can be efficiently rasterized [G]. It sets itself apart from parent methods by explicitly defining the kernel shape (e.g., isotropic, half-space, or hybrid Bézier) and the associated attribute storage (e.g., opacity, normals, control points) that determine how light interacts with the primitive during rendering [G].

### [Shading and Lighting Models](11924-shading-and-lighting-models.md)
Shading and Lighting Models extend the standard 3D Gaussian Splatting rasterization pipeline to support physically based rendering (PBR), self-occlusion, and anti-aliased forward shading [G]. While standard splatting assumes a fixed, uniform lighting environment and simple alpha blending, this family introduces mechanisms for deferred shading pipelines, light-space rasterization for shadows, and analytic integration approximations for multiscale fidelity [Lighting, Shadowing & Relighting](11894-lighting-shadowing-relighting.md), [Analytic-Splatting Forward Shading](3459-analytic-splatting-forward-shading.md), [Transparency and Blending Models](9274-transparency-and-blending-models.md). It differs from sibling methods like [Analytic-Splatting Forward Shading](3459-analytic-splatting-forward-shading.md) by focusing on material attributes and light interaction rather than just pixel-area integration, and from [Transparency and Blending Models](9274-transparency-and-blending-models.md) by explicitly handling light source geometry and PBR material buffers.

### [Reflective Gaussian Splatting](12321-reflective-gaussian-splatting.md)
Reflective Gaussian Splatting (Ref-Gaussian) is a framework for the real-time, high-quality rendering of reflective objects with inter-reflection effects, addressing the limitations of standard 3D Gaussian Splatting in modeling complex surfaces and multi-view inconsistencies. It distinguishes itself from sibling methods like [3D Gaussian Splatting Rasterization](2812-3d-gaussian-splatting-rasterization.md) by utilizing 2D Gaussian primitives for view-consistent geometry and employing physically based deferred rendering with split-sum approximation to stabilize optimization and enable efficient inter-reflection modeling without heavy Monte Carlo sampling.

### [Ray-Splat Intersection Algorithms](13401-ray-splat-intersection-algorithms.md)
Ray-splat intersection algorithms compute the contribution of 3D Gaussians to a pixel by evaluating the Gaussian function along the viewing ray, rather than projecting the Gaussian onto the 2D image plane. This approach solves the perspective distortion artifacts inherent in the affine approximation of standard 3D Gaussian Splatting [KKLD23] and enables accurate depth estimation and volume rendering. Unlike sibling methods that rely on tile-based rasterization, these algorithms treat Gaussians as volumetric primitives, allowing for correct alpha blending and transparency handling through ray traversal or analytical distance evaluation.

### [Rasterization Pipeline Optimization](15109-rasterization-pipeline-optimization.md)
Rasterization Pipeline Optimization refers to the family of algorithmic and hardware techniques designed to accelerate the rendering of 3D Gaussian Splatting (3DGS) by reducing the computational overhead of tile intersection, sorting, and alpha compositing. It solves the bottleneck where standard rasterization overestimates Gaussian extents, processes non-intersecting pixels, and suffers from serial blending latency. What sets this family apart from sibling methods like [3D Gaussian Splatting Differentiable Rasterizer](2813-3d-gaussian-splatting-differentiable-rasterizer.md) (which focuses on the differentiable math) or [3D Gaussian Splatting MVP](3410-3d-gaussian-splatting-mvp.md) (which focuses on memory layout) is the explicit restructuring of the rendering pipeline stages—specifically moving culling to parallel preprocess phases, replacing coarse bounding-box tests with precise geometric checks, and co-designing hardware units for projection and sorting.

This family extends 3D Gaussian Splatting by attaching high-dimensional feature vectors (semantic, language, or latent) to Gaussian primitives and/or by introducing canonical space representations for deformable geometry. ## Operating characteristics
**Time and Memory Complexity:**
*   **Time:** $O(N \cdot T)$ where $N$ is the number of Gaussians and $T$ is the number of tiles, but effectively linear in the number of visible Gaussians per tile due to culling and early termination. Sorting is $O(N \log N)$ [S14, unofficial].
*   **Memory:** $O(N)$ for storing Gaussian attributes. VRAM usage is high, typically 4GB to view and 12GB to train for complex scenes [S14, unofficial]. Disk size is 1GB+ for a scene [S14, unofficial].

**Measured Performance:**
*   Achieves real-time rendering (60+ FPS) on desktop GPUs for scenes with millions of Gaussians [S1][S6, unofficial].
*   Baseline for AR/VR and desktop GPU rendering, but faces memory/bandwidth limits on mobile/AR-VR edge devices [S10].

**Scaling:**
*   Scales well with GPU parallelism due to tile-based processing.
*   Performance degrades on resource-constrained devices due to high memory bandwidth requirements [S10].

**Strengths and Limitations:**
*   **Strengths:** Real-time rendering, high visual fidelity, differentiable, explicit representation allows for easy editing and compression.
*   **Limitations:** High memory usage, unbounded growth of Gaussians during training can lead to fragmentation, artifacts in highly reflective or transparent scenes without extensions [S14, unofficial][S10].

**When to Use:**
*   Real-time novel view synthesis, interactive 3D visualization, training data generation.
*   **When Not:** Resource-constrained mobile devices without optimization, scenes requiring physically accurate light transport (without extensions).

## Background
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1][S6, unofficial]. It emerged as a response to the computational bottlenecks of Neural Radiance Fields (NeRF), which rely on slow volumetric ray-marching. By using explicit, differentiable Gaussian primitives and a tile-based rasterization pipeline, 3DGS achieved a breakthrough in rendering speed while maintaining high quality [S1][S6, unofficial]. It has since become a standard baseline for 3D reconstruction and novel view synthesis, with numerous extensions for dynamic scenes, avatars, and specialized applications [S7][S9].
