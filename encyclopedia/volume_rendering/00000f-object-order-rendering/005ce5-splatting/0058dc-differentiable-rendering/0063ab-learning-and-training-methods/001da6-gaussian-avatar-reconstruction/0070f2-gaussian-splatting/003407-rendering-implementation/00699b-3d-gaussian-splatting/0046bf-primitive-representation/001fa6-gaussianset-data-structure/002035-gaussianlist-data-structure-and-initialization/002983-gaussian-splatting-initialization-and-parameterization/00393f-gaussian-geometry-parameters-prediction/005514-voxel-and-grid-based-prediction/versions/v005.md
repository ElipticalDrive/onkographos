# Voxel and Grid-Based Prediction

Also called: Direct Multi-Plane Image Gaussian Optimization, DirectMPIGO

## Overview
Voxel and Grid-Based Prediction is a neural rendering method that combines voxel-based density representation with Multi-Plane Image (MPI) depth layers for efficient volume rendering, supporting sparse grids and occupancy caching [S1, unofficial]. It solves the problem of memory-intensive dense voxel storage by using sparse structures and MPI depth planes to approximate continuous volumes, while simultaneously predicting 3D Gaussian parameters from voxel features to enable explicit primitive rendering [S1, unofficial][S2]. Unlike sibling methods that optimize neural feature grids directly or use triplane representations, this approach operates on a voxel grid to predict Gaussian geometry and attributes via residual correction or direct regression [S1, unofficial][S2].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Camera rays (origin $o$, direction $d$), bounding box ($xyz_{min}, xyz_{max}$), scene resolution parameters ($mpi\_depth$, $voxel\_size\_ratio$), and network hyperparameters ($rgbnet\_dim$, $rgbnet\_depth$, $rgbnet\_width$, $viewbase\_pe$).
*   **Outputs:** Rendered image color, depth, and normal maps; updated voxel grid densities and Gaussian parameters.

**Data Structures:**
1.  **Density Grid:** Created via `grid.create_grid` with `density_type` (e.g., 'DenseGrid' or 'SparseGridSpec'), channels=1, and world size derived from scene bounds and `mpi_depth` [S1, unofficial].
2.  **Act Shift Grid (`act_shift`):** A `DenseGrid` tensor of shape `[1, 1, mpi_depth]`, `requires_grad=False`, initialized with logit values to equalize initial alpha contributions across MPI depth layers [S1, unofficial].
3.  **Feature/Color Grid (`k0`):** Created via `grid.create_grid` with `k0_type`. Channels=3 if `rgbnet_dim <= 0` (raw RGB); otherwise channels=`rgbnet_dim` [S1, unofficial].
4.  **Mask Cache (`mask_cache`):** A boolean tensor of shape `mask_cache_world_size`, updated incrementally based on density alpha thresholds [S1, unofficial].
5.  **Color MLP:** A multi-layer perceptron for view-dependent color, defined as:
    *   Input dimension: $dim0 = 3 + 3 \cdot viewbase\_pe \cdot 2 + k0\_dim$ [S1, unofficial].
    *   Layers: `Linear(dim0, rgbnet_width)`, `ReLU`, `(rgbnet_depth-2)` layers of `Linear(rgbnet_width, rgbnet_width)` + `ReLU`, final `Linear(rgbnet_width, 3)` [S1, unofficial].
    *   Initialization: Final layer bias set to 0 [S1, unofficial].
6.  **View Frequency Buffer:** Powers of 2: $[2^0, 2^1, \dots, 2^{(viewbase\_pe-1)}]$ [S1, unofficial].

**Algorithm Steps:**

1.  **Initialization:**
    *   Compute `world_size`:
        $$world\_size[:2] = (xyz_{max} - xyz_{min})[:2] \cdot r$$
        $$r = \sqrt{\frac{num\_voxels}{mpi\_depth \cdot \prod(xyz_{max} - xyz_{min})[:2]}}$$
        $$world\_size[2] = mpi\_depth$$
        [S1, unofficial]
    *   Initialize density grid values $g[i]$ for $i \in [0, mpi\_depth)$:
        $$g[i] = \frac{1.0}{mpi\_depth} - 10^{-6}$$
        This ensures uniform initial transmittance [S1, unofficial].
    *   Compute conditional probability $p[i]$:
        $$p[0] = 1 - g[0]$$
        $$p[i] = \frac{1 - \sum_{j=0}^{i} g[j]}{1 - \sum_{j=0}^{i-1} g[j]} \quad \text{for } i > 0$$
        [S1, unofficial]
    *   Initialize `act_shift` grid value at layer $i$:
        $$act\_shift[i] = \log\left( \left( p[i]^{-1/voxel\_size\_ratio} \right) - 1 \right)$$
        where $voxel\_size\_ratio = 256.0 / mpi\_depth$ [S1, unofficial].
    *   If `mask_cache_path` is provided, load mask; else create all-True mask of size `mask_cache_world_size` [S1, unofficial].

2.  **Ray Sampling:**
    *   Compute ray-box intersection $t_{min}$ and $t_{max}$ for each ray against $xyz_{min}$ and $xyz_{max}$ [S1, unofficial].
    *   Infer number of samples $n\_samples$ per ray based on step distance [S1, unofficial].
    *   Sample points on rays within the bounding box, generating ray IDs and step IDs for batched processing [S1, unofficial].

3.  **Occupancy Caching (Optional Optimization):**
    *   **Update Occupancy Cache:** Query density at cache grid points. Activate voxels. Apply `max_pool3d(kernel=3, padding=1)`. Update mask where alpha > `fast_color_thres` [S1, unofficial].
    *   **Update Occupancy Cache (Low Views):** For each ray batch, sample points. Accumulate gradient counts in `ones.grid.grad`. Update mask where count >= `maskout_lt_nviews` [S1, unofficial].
    *   **Scale Volume Grid:** If new world size product $\le 256^3$, recompute mask cache by combining old mask with alpha > `fast_color_thres` after `max_pool3d` smoothing [S1, unofficial].

4.  **Feature Extraction and Color Prediction:**
    *   Query feature grid `k0` at sampled points.
    *   Compute view-dependent positional encoding using `viewfreq` buffer.
    *   Concatenate raw RGB (if applicable), view PE, and grid features to form input of size $dim0$.
    *   Pass through Color MLP to predict final RGB color [S1, unofficial].

5.  **Gaussian Parameter Prediction (Variant: VolSplat):**
    *   For each voxel $v$, predict a set of learnable Gaussian parameters $\{\bar{\mu}_j, \bar{\alpha}_j, \bar{\Sigma}_j, c_j\} \in \mathbb{R}^{38}$ [S2].
    *   Transform predicted center offset $\bar{\mu}_j$ to final center $\mu_j$:
        $$\mu_j = r \cdot (\sigma(\bar{\mu}_j) - 0.5) + Center_j$$
        where $\sigma$ is sigmoid, $Center_j$ is voxel centroid, and $r = 3 \times voxel\_size$ [S2].
    *   Transform predicted opacity $\bar{\alpha}_j$ to final opacity $\alpha_j$:
        $$\alpha_j = \sigma(\bar{\alpha}_j)$$
        [S2]
    *   The output dimension per Gaussian is 38: offset (3), opacity (1), covariance (6), and spherical harmonic color (28) [S2].

6.  **Rendering:**
    *   Render the scene using the predicted densities (for volume rendering) or Gaussians (for splatting) [S1, unofficial][S2].

**Parameters:**
*   `xyz_min`, `xyz_max`: Bounding box coordinates [S1, unofficial].
*   `mpi_depth`: Number of depth planes [S1, unofficial].
*   `fast_color_thres`: Threshold for occupancy mask updates [S1, unofficial].
*   `rgbnet_dim`: Color feature vector dimension. If $\le 0$, uses raw RGB [S1, unofficial].
*   `rgbnet_depth`, `rgbnet_width`: MLP depth and width [S1, unofficial].
*   `viewbase_pe`: Number of positional encoding frequencies [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Sigmoid Restriction:** The sigmoid activation in Gaussian center prediction restricts the learnable offset to a localized neighborhood. The -0.5 shift facilitates symmetrical, bi-directional movement from the voxel center [S2].
*   **Precision:** Ray-box intersection calculations must handle zero-direction components to avoid division by zero (e.g., using $10^{-6}$) [S1, unofficial].
*   **Memory:** Sparse grids reduce memory usage compared to dense grids, but occupancy caching requires careful threshold tuning (`fast_color_thres`) to avoid aliasing or empty space artifacts [S1, unofficial].

## Subtopics

### [Gaussian Splatting Attribute Prediction](9961-gaussian-splatting-attribute-prediction.md)
Gaussian Splatting Attribute Prediction refines 3D Gaussian primitives by predicting additive residuals to initial rendering attributes, rather than regenerating them from scratch. It solves the problem of high-frequency detail loss in coarse initializations by using a voxel transformer to correct errors on a per-voxel basis. Unlike sibling methods that optimize neural feature grids directly, this approach operates on the Gaussian set's geometric and color parameters via residual correction.

### [GO-Surf Neural Feature Grid Optimization](15383-go-surf-neural-feature-grid-optimization.md)
GO-Surf is a differentiable volume rendering method that optimizes a multi-resolution neural feature grid to reconstruct high-fidelity 3D surfaces from RGB-D observations. It solves the problem of fast, dense surface reconstruction by combining explicit grid-based feature storage with implicit SDF decoding, significantly reducing optimization time compared to fully implicit MLP-based methods like NeuralRGB-D. It sets itself apart by using a multi-resolution grid to store geometry and color features, allowing for faster convergence and higher detail capture, albeit at the cost of higher memory usage.

### [Feed-forward and Generalizable Prediction](15832-feed-forward-and-generalizable-prediction.md)
Feed-forward and Generalizable Prediction refers to a family of methods that map input images directly to a 3D Gaussian Splatting (3DGS) representation without per-scene optimization, enabling instant novel view synthesis on unseen scenes [Parent]. Unlike traditional 3DGS which requires iterative gradient descent for each new scene, these methods use a learned neural network to predict Gaussian parameters ($\mu, \Sigma, \alpha, c$) in a single forward pass [Parent]. This family is distinguished from sibling methods like [Triplane-LRM](16746-feed-forward-generalizable-reconstruction.md) by its explicit prediction of explicit Gaussian primitives rather than latent field representations, and from optimization-based methods by its inference speed and lack of per-scene tuning [Parent].

### [Gaussian Parameter Prediction](18303-gaussian-parameter-prediction.md)
Gaussian Parameter Prediction derives the geometric and appearance parameters of 3D Gaussians from input data to enable novel view synthesis. It solves the problem of regenerating the Gaussian set directly from features or depth maps without iterative optimization. It differs from its siblings by focusing on direct prediction from pooled features or unprojected depth maps rather than iterative densification or mesh embedding.

### 3D Gaussians Prediction from Voxels
Predicts a set of learnable Gaussian parameters for each voxel $v$, including center offset, opacity, covariance, and spherical harmonic color [S2]. The final 3D Gaussian center $\mu_j$ is computed by applying a sigmoid activation to the predicted offset $\bar{\mu}_j$, shifting by -0.5, scaling by $r$, and adding the voxel centroid $Center_j$: $\mu_j = r \cdot (\sigma(\bar{\mu}_j) - 0.5) + Center_j$ [S2]. The output dimension per Gaussian is 38 [S2]. The scaling factor $r$ is set to 3 times the voxel size [S2].

### GS-LRM / Long-LRM
Predicts 3D Gaussians directly (not triplane $\to$ Gaussians), resulting in faster downstream rendering [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** Depends on the number of sampled points per ray and the depth of the color MLP. Sparse grids reduce the number of active voxels, speeding up feature queries [S1, unofficial].
*   **Memory Complexity:** Sparse grids significantly reduce memory usage compared to dense voxel grids, especially for large scenes with empty space [S1, unofficial]. Occupancy caching further optimizes memory by skipping empty regions [S1, unofficial].
*   **Performance:** DirectMPIGO supports sparse grids and MPI depth, offering a balance between rendering quality and memory efficiency compared to dense voxel methods like DVGO [S1, unofficial]. VolSplat's voxel-aligned prediction stabilizes training and preserves coarse voxel information [S2].
*   **Strengths:** Efficient memory usage via sparse grids; stable training via residual correction; fast inference for feed-forward variants [S1, unofficial][S2][S3, unofficial].
*   **Limitations:** Requires careful tuning of occupancy thresholds; sparse grid implementation is more complex than dense grids [S1, unofficial].

## Background
Voxel and Grid-Based Prediction originated from the need to optimize memory usage in neural volume rendering. DirectMPIGO, introduced by Kakao Brain, combines voxel-based density with MPI depth layers to support sparse grids and occupancy caching [S1, unofficial]. VolSplat extends this by predicting 3D Gaussian parameters directly from voxel features, enabling explicit primitive rendering [S2]. These methods build on earlier work like DVGO, which used dense voxel grids, by introducing sparsity and explicit Gaussian representations [S1, unofficial].
