# AnySplat Pipeline

Also called: Feed-forward 3D Gaussian Splatting from Unconstrained Views

## Overview
The AnySplat Pipeline is a feed-forward method for generalizable 3D Gaussian Splatting that operates on uncalibrated input views, simultaneously predicting Gaussian parameters, depth maps, and camera poses without per-scene optimization [S1, unofficial]. It builds on [Feed-forward Generalizable Reconstruction](16746-feed-forward-generalizable-reconstruction.md) by integrating a Differentiable Voxelization module to convert pixel-wise Gaussians into a voxelized representation, enabling stable rendering and geometry supervision via pseudo-geometry priors from a pretrained VGGT model [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A batch of $K$ uncalibrated RGB images $I \in \mathbb{R}^{K \times 3 \times H \times W}$, with tensor shape $[1, K, 3, 448, 448]$ (batch, views, channels, height, width) [S1, unofficial].
*   **Outputs:** A set of pixel-wise 3D Gaussians $\mathcal{G}$ defined by mean $\mu$, scale $\sigma$, rotation $r$, scale $s$, and color $c$; predicted camera poses $p$ (extrinsic and intrinsic matrices); and predicted depth maps $D$ [S1, unofficial].

**Data Structures**
The Gaussian parameters are predicted per-pixel from the feature map. Each pixel corresponds to a 3D Gaussian primitive. The parameters include:
*   $\mu \in \mathbb{R}^3$: 3D position.
*   $\sigma \in \mathbb{R}^3$: Scale parameter.
*   $r \in \mathbb{R}^4$: Rotation (quaternion).
*   $s \in \mathbb{R}^3$: Scale parameter.
*   $c$: Color coefficients.

**Algorithm Steps**
1.  **Feature Encoding:** Input images $I$ are normalized to $[-1, 1]$ range via $(I+1)*0.5$ and passed through a transformer-based geometry encoder [S1, unofficial].
2.  **Parameter Prediction:** Three decoder heads process the encoded features: $F_G$ predicts Gaussian parameters $(\mu, \sigma, r, s, c)$; $F_D$ predicts a dense depth map $D$; $F_C$ predicts camera poses $p$ [S1, unofficial].
3.  **Gaussian Construction:** The predicted parameters construct a set of pixel-wise 3D Gaussians [S1, unofficial].
4.  **Differentiable Voxelization:** The pixel-wise Gaussians are voxelized into a pre-voxel 3D Gaussian representation using a Differentiable Voxelization module [S1, unofficial].
5.  **Rendering:** Multi-view images and depth maps are rendered from the voxelized Gaussians [S1, unofficial].
6.  **Loss Computation:** Rendered images are supervised by an RGB loss against ground truth images [S1, unofficial]. Rendered depth maps, decoded depth $D$, and poses $p$ compute geometry losses [S1, unofficial].
7.  **Geometry Supervision:** Geometries are supervised by pseudo-geometry priors obtained from a pretrained VGGT model [S1, unofficial].
8.  **Inference:** The model takes normalized images and outputs the Gaussians and predicted poses [S1, unofficial].

## Subtopics

### [SubSplat](13524-subsplat.md)
A high-resolution variant that uses a Sub-pixel Gaussian Reparameterizer to increase Gaussian density from low-resolution features.

### [Deformable Radial Kernel (DRK)](13699-deformable-radial-kernel-drk.md)
A variant that replaces radial Gaussians with planar kernels for better geometric fidelity and fewer primitives.

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Strengths:** Handles uncalibrated inputs, provides explicit pose and depth predictions, and uses voxelization for stable rendering [S1, unofficial].
*   **Limitations:** Relies on the quality of the pretrained VGGT model for geometry supervision [S1, unofficial].

## Background
The method is implemented in the AnySplat repository [S1, unofficial]. It builds on the principles of generalizable reconstruction by predicting scene parameters directly from images, while addressing the challenges of uncalibrated inputs through pose prediction and pseudo-geometry supervision [S1, unofficial].
