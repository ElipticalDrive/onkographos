## How it works

### Core Training Loop and Densification
The standard training loop iterates over random camera views, rendering them via differentiable rasterization and computing a photometric loss. The implementation details below specify the hyperparameters and procedural steps for managing Gaussian density.

**Inputs:**
- Initial point cloud from Structure-from-Motion (SfM) [S3].
- Camera poses and intrinsics [S3].
- Ground-truth images [S3].

**Outputs:**
- Optimized set of 3D Gaussians (position, covariance, opacity, spherical harmonic coefficients) [S3].

**Data Structures:**
- **Gaussian Attributes:** Each Gaussian $i$ stores position $\mu_i$, rotation $R_i$, scale $s_i$, opacity $\alpha_i$, and SH coefficients $c_{i,lm}$ [S3].
- **Gradient Accumulation:** Positional gradients are accumulated per Gaussian per iteration to drive densification [S4].

**Numbered Steps:**

1.  **Initialization:** Initialize Gaussians from the SfM point cloud. Calculate the scene extent $e_{\text{scene}}$. By default, this is proportional to the furthest camera distance, but a corrected extent based on SfM points is recommended to avoid bias [S4].
    $$e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2$$
    where $\bar{C}$ is the average camera position and $p_i$ are SfM points [S4].

2.  **Rendering:** For each iteration, select a random image from the training set [S3]. Project 3D Gaussians to 2D screen space. Sort Gaussians by depth. Perform alpha blending to compute the pixel color $\hat{C}$ [6233-optimization-and-parallelization].

3.  **Loss Computation:** Compute the loss $\mathcal{L}$ as a weighted combination of Mean Squared Error (MSE) and Structural Similarity Index Measure (SSIM) [S13, unofficial]:
    $$\mathcal{L} = \lambda \cdot \text{MSE}(C, \hat{C}) + (1 - \lambda) \cdot \text{SSIM}(C, \hat{C})$$
    where $C$ is the ground-truth image and $\lambda$ is a hyperparameter [S13, unofficial].

4.  **Backpropagation:** Compute gradients $\frac{\partial \mathcal{L}}{\partial \theta}$ with respect to Gaussian parameters $\theta$ [6233-optimization-and-parallelization].

5.  **Optimizer Update:** Update parameters using the Adam optimizer with a learning rate of $1 \times 10^{-3}$ [S3].

6.  **Densification (Splitting/Cloning):** Every 100 iterations (or 500 in some variants), evaluate the accumulated positional gradient magnitude for each Gaussian.
    - If the gradient exceeds a threshold $T_{\text{pos}}$ (typically 0.02) [S1], split the Gaussian into two: one at the original position and one offset by the gradient direction, scaled by the learning rate.
    - Alternatively, clone the Gaussian if it is small and has high gradient [S4].
    - Use an exponentially ascending gradient threshold schedule to control the number of splits [S4].

7.  **Pruning:** Every 200 iterations, remove Gaussians with opacity $\alpha < \alpha_{\text{min}}$ (typically 0.05) [S1]. Also remove Gaussians with excessively large world-space or view-space radii [S1].

8.  **Compactness Check:** Every 1000 iterations, perform a compactness-based densification check to ensure efficient spatial distribution [S1].

### Half-Precision Rasterization Implementation
To accelerate training and reduce memory bandwidth, the rasterization kernels can be implemented in half-precision (FP16) [S2].

**Data Structures:**
- Feature vectors (SH coefficients, position, scale) are stored in FP16 [S2].
- Accumulators for color and opacity may require FP32 to prevent precision loss during alpha blending, or use dynamic scaling [S2].

**Steps:**
1.  **Memory Fetch:** Use half-precision memory fetches for feature vectors during both forward and backward passes to reduce register pressure [S2].
2.  **MLP Evaluation:** If using neural attributes (e.g., for view-dependent effects), evaluate Multilayer Perceptrons (MLPs) using tiny-cuda-nn's JIT-compiled cooperative vector MLPs in FP16 [S2].
3.  **Loss Scaling:** Apply an automatic scaling factor to loss values to improve half-precision training stability, preventing gradient underflow [S2].

### Optimizer Configuration
- **Optimizer:** Adam [S3].
- **Learning Rate:** $1 \times 10^{-3}$ for Gaussian parameters [S3].
- **SH Degree:** Typically set to 1 for real-time applications, higher for offline quality [S3].

### Edge Cases and Pitfalls
- **Scene Extent Bias:** Using the default scene extent calculation (based on camera positions) can lead to incorrect splitting/pruning if cameras are clustered (e.g., orbiting a small object in a large environment). Use the corrected scene extent based on SfM points [S4].
- **Gradient Threshold:** If the gradient threshold is too low, excessive splitting occurs, leading to noise. If too high, the scene remains under-reconstructed. An exponentially ascending schedule helps manage this [S4].
- **Opacity Pruning:** Pruning too aggressively can remove valid geometry. Ensure $\alpha_{\text{min}}$ is set appropriately (e.g., 0.05) [S1].
