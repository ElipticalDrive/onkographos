# Cross-scale geometric adaptation

Also called: Lgeo, Reprojection error supervision, Reprojection-based cross-scale geometric adaptation

## Overview
Cross-scale geometric adaptation is a self-adaptive regularization technique that uses reprojection errors across multiple voxel scales to guide geometry learning without requiring explicit depth ground truth [S1]. It sets itself apart from sibling methods like [Frequency Regularization](6130-frequency-regularization.md) and [Hard and Soft Depth Regularization](9178-hard-and-soft-depth-regularization.md) by dynamically selecting pseudo-labels from the scale exhibiting the minimal reprojection error, thereby ensuring geometric integrity and reducing floaters more robustly than static depth priors [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Training view $i$ with pixel coordinate $p_i$, camera intrinsics $K_i$, camera pose $(R_i, t_i)$; Reference view $j$ with RGB map $C_j$; Multi-scale voxel representation providing depth $D_{il}(p_i)$ at scale $l$ for ray $r_{train}$; RGB map $C_i$ of frame $i$.
*   **Outputs:** Geometric adaptation loss $\mathcal{L}_{geo}$; Pseudo-ground truth depth $D'(r_{train})$ corresponding to the optimal scale.

**Data Structures:**
The method operates on a multi-scale voxel grid. For each scale $l \in \{0, \dots, L\}$, the voxel structure provides a depth value $D_{il}(p_i)$ for any 2D pixel coordinate $p_i$ via volume rendering [S1]. The specific bit-packing or memory layout of the voxels is not detailed in the sources, but the abstraction assumes access to $D_{il}(p_i)$ [S1].

**Numbered Steps:**
1.  **Reproject to 3D (Source Frame):** For a 2D pixel coordinate $p_i$ in training frame $i$, compute its homogeneous augmentation $\tilde{p}_i$. Calculate the 3D point $x_{li}$ in the camera coordinate system of frame $i$ at scale $l$ using the rendered depth $D_{il}(p_i)$ and camera intrinsics $K_i$:
    $$ x_{li} = D_{il}(p_i) K_i^{-1} \tilde{p}_i $$
    Alternatively, the 3D point $x_l$ in world coordinates can be determined directly from the ray origin $o_i(p_i)$ and direction $v_i(p_i)$:
    $$ x_l = o_i(p_i) + D_{il}(p_i) v_i(p_i) $$
    [S1]

2.  **Transform to World Coordinates:** Transform the 3D point $x_{li}$ from frame $i$'s camera coordinates to the world coordinate system using frame $i$'s rotation matrix $R_i$ and translation vector $t_i$:
    $$ x_l = R_i x_{li} + t_i $$
    [S1]

3.  **Transform to Reference Camera Coordinates:** Transform the world coordinate point $x_l$ to the camera coordinate system of reference frame $j$ using frame $j$'s rotation matrix $R_j$ and translation vector $t_j$:
    $$ x_{li \to j} = R_j^T (x_l - t_j) $$
    [S1]

4.  **Reproject to 2D (Reference Frame):** Project the 3D point $x_{li \to j}$ back to the 2D pixel coordinate system of frame $j$. Let $\pi([x, y, z]^T) = [x/z, y/z]^T$. The reprojection coordinate $\tilde{p}_{li \to j}$ is:
    $$ \tilde{p}_{li \to j} = \pi(K_j x_{li \to j}) $$
    [S1]

5.  **Compute Reprojection Error:** Calculate the reprojection error $e_l(p_i)$ for scale $l$ as the difference between the original RGB pixel $C_i(p_i)$ and the warped pixel from frame $j$ at the reprojected coordinate $C_j(\tilde{p}_{li \to j})$:
    $$ e_l(p_i) = C_i(p_i) - C_j(\tilde{p}_{li \to j}) $$
    [S1]

6.  **Select Optimal Scale:** Identify the scale $l$ that minimizes the reprojection error for the training ray $r_{train}$. This scale provides the pseudo-ground truth depth $D'(r_{train})$:
    $$ D'(r_{train}) = \arg \min_l (e_l(r_{train})) $$
    [S1]

7.  **Compute Loss:** Calculate the geometric adaptation loss $\mathcal{L}_{geo}$ as the Mean Squared Error (MSE) between the rendered depth at scale $l$ and the selected pseudo-ground truth depth $D'(r_{train})$ over all training rays $r_{train}$:
    $$ \mathcal{L}_{geo}(r_{train}) = \sum_{l=0}^{L} \| \hat{D}_l(r_{train}) - D'(r_{train}) \|^2 $$
    Note: The summation index $l$ in the source formula [S1] implies the loss is computed across scales, or potentially that the loss is applied to the specific scale $l$ that minimizes the error. The source states "the pseudo-GT depth of the scale with the minimum reprojection error is obtained... utilized to compute the geometric adaptation loss (MSE)". The formula provided sums over $l$, but the logic implies selecting the best scale. Given the ambiguity, the implementation should compute $e_l$ for all $l$, select $l^* = \arg \min_l e_l$, and then compute the loss between the depth at $l^*$ and the depth at $l^*$ (which is zero) or potentially the loss is defined on the consistency of the selected scale's depth against the reprojection consistency. However, the source explicitly writes the sum. A safer interpretation for implementation, consistent with "selecting render depths with minimal reprojection error... as pseudo labels", is that the loss encourages the depth at the optimal scale to be consistent. The source formula (19) is:
    $$ \mathcal{L}_{geo}(r_{train}) = \sum_{l=0}^{L} \| \hat{D}_l(r_{train}) - D'(r_{train}) \|^2 $$
    where $D'(r_{train})$ is the depth from the best scale. This penalizes other scales from deviating from the best scale's geometry [S1].

**Pseudocode:**
```python
def compute_cross_scale_geometric_adaptation_loss(
    rays_train, 
    frames, 
    voxel_grids, 
    intrinsics, 
    poses
):
    """
    rays_train: List of rays, each with origin o, direction v, and pixel coords p_i.
    frames: Dict mapping frame_id to {'rgb': C, 'K': K, 'R': R, 't': t}.
    voxel_grids: List of voxel grids, one per scale l.
    intrinsics: Dict mapping frame_id to K.
    poses: Dict mapping frame_id to (R, t).
    """
    total_loss = 0.0
    
    for ray in rays_train:
        p_i = ray.pixel_coords
        frame_i_id = ray.frame_id
        frame_j_id = ray.reference_frame_id # Assuming a reference frame is paired or selected
        
        # Get camera parameters
        K_i = intrinsics[frame_i_id]
        K_j = intrinsics[frame_j_id]
        R_i, t_i = poses[frame_i_id]
        R_j, t_j = poses[frame_j_id]
        
        C_i = frames[frame_i_id]['rgb']
        C_j = frames[frame_j_id]['rgb']
        
        # Get ray direction and origin in world space (assuming ray is defined in world or needs transformation)
        # Note: Source defines x_l = o_i(p_i) + D * v_i(p_i). 
        # We assume o_i and v_i are available or derived from p_i and K_i.
        # For simplicity, assume ray provides o_world and v_world if already in world, 
        # or we transform from camera. Source uses camera coords first.
        
        # Step 1 & 2: Compute 3D points in World Coordinates for each scale
        world_points = []
        reprojection_errors = []
        depths_at_scale = []
        
        for l, voxel_grid in enumerate(voxel_grids):
            # Get depth at scale l for pixel p_i
            D_il = voxel_grid.get_depth(p_i)
            
            # Reproject to camera i coords
            # Homogeneous p_i
            p_i_hom = np.array([p_i[0], p_i[1], 1.0])
            # Inverse intrinsic
            K_i_inv = np.linalg.inv(K_i)
            # Direction in camera i
            dir_cam_i = K_i_inv @ p_i_hom
            # 3D point in camera i
            x_li = D_il * dir_cam_i
            
            # Transform to World
            # x_l = R_i * x_li + t_i
            x_l = R_i @ x_li + t_i
            world_points.append(x_l)
            depths_at_scale.append(D_il)
            
            # Step 3: Transform to Camera j coords
            # x_li_j = R_j^T * (x_l - t_j)
            x_li_j = R_j.T @ (x_l - t_j)
            
            # Step 4: Project to 2D in Frame j
            # pi([x,y,z]) = [x/z, y/z]
            if x_li_j[2] == 0:
                continue # Avoid division by zero
            p_j = np.array([x_li_j[0] / x_li_j[2], x_li_j[1] / x_li_j[2]])
            
            # Step 5: Compute Reprojection Error
            # C_j(p_j) might be out of bounds, handle gracefully
            if is_valid_pixel(p_j, C_j.shape):
                C_j_val = C_j[p_j[1], p_j[0]]
                C_i_val = C_i[p_i[1], p_i[0]]
                e_l = np.linalg.norm(C_i_val - C_j_val)
                reprojection_errors.append(e_l)
            else:
                reprojection_errors.append(np.inf)

        # Step 6: Select Optimal Scale
        if not reprojection_errors:
            continue
            
        min_error_idx = np.argmin(reprojection_errors)
        D_prime = depths_at_scale[min_error_idx]
        
        # Step 7: Compute Loss
        # Sum of squared differences between each scale's depth and the optimal depth
        scale_loss = 0.0
        for l, D_il in enumerate(depths_at_scale):
            scale_loss += (D_il - D_prime) ** 2
            
        total_loss += scale_loss
        
    return total_loss
```

**Parameters:**
*   Number of scales $L$: Not given in the sources.
*   Reference frame selection: Not given in the sources. The method assumes a reference frame $j$ is available for each training frame $i$.

**Edge Cases and Pitfalls:**
*   **Occlusions/Disocclusions:** If frame $j$ does not see the surface point visible in frame $i$ (due to occlusion), the reprojection error will be high or invalid. The sources do not specify how to handle this, but standard practice involves masking invalid pixels [G].
*   **Depth Ambiguity:** In textureless regions, depth estimation may be unstable. The multi-scale approach helps by using low-resolution voxels for coarse geometry early in training [S1].
*   **Numerical Stability:** Division by zero in projection if $z=0$. Guard against this in implementation [G].

## Operating characteristics
*   **Time Complexity:** Adds overhead for reprojection and error computation across all scales for each training ray. The sources do not provide specific timing metrics relative to base training.
*   **Memory Complexity:** Requires storing multi-scale voxel grids. The sources do not specify memory overhead beyond the voxel structures themselves.
*   **Performance:** Significantly reduces floaters and improves convergence quality across scales compared to training without geometric adaptation [S1]. Achieves lower final depth error than depth prior $\mathcal{L}_d$ alone [S1].
*   **Strengths:** Self-adaptive; no complex scheduling required; robust to geometric noise compared to feature-warping methods like GeCoNeRF [S1].
*   **Limitations:** Relies on accurate camera poses. Performance may degrade in few-shot scenarios with significant viewpoint changes or sparse training views [S1].

## Background
Cross-scale geometric adaptation was proposed in **FrugalNeRF** (2025) by the authors of [S1]. It is designed for extreme few-shot novel view synthesis, accelerating training and regularizing geometry without external priors. It builds on the concept of weight-sharing voxels across scales to capture varying scene frequencies [S1].
