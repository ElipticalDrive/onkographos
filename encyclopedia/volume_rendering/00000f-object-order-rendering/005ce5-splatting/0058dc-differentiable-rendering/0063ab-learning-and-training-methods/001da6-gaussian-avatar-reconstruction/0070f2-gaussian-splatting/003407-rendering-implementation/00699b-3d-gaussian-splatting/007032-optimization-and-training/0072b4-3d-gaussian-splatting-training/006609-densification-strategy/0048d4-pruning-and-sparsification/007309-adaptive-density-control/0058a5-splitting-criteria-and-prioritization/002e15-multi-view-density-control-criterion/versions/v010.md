# Multi-View Density Control Criterion

Also called: Absolute-gradient split proxy, FastGS criterion, Multi-view Adaptive Density Control (ADC)

## Overview
The Multi-View Density Control Criterion is a densification strategy for 3D Gaussian Splatting designed to resolve invalid vector arithmetic that occurs when applying standard Adaptive Density Control (ADC) to multi-view training pipelines. Standard ADC sums 2D positional gradients from pixels covering a Gaussian; however, in multi-view training, a single Gaussian is projected onto multiple image planes, and adding 2D vectors from different coordinate spaces results in nullified or incorrect gradients [S1, unofficial]. This method replaces vector addition with the summation of squared norms, ensuring that error metrics are computed in a space-independent manner [S1, unofficial]. It yields higher reconstruction quality with fewer primitives compared to standard positional-gradient rules [S2, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A set of $N$ training viewpoints. For each Gaussian $G$, the set of pixels $\pi$ across all viewpoints that are covered by $G$'s projection. The loss gradient $\nabla_{\pi} \mathcal{L}$ for each such pixel.
*   **Output:** A scalar error score $E_1(G)$ used to determine if $G$ should be split or cloned.

**Data Structures**
*   **Pixel Coverage Map:** A mapping from each Gaussian $G$ to a list of tuples $(\pi, \nabla_{\pi} \mathcal{L})$, where $\pi$ is a pixel index and $\nabla_{\pi} \mathcal{L}$ is the 2D positional gradient vector at that pixel.
*   **Score Buffer:** A scalar value $E_1(G)$ for each Gaussian.

**Algorithm**
1.  Initialize the error score $E_1(G) = 0$ for all Gaussians $G$.
2.  For each training iteration:
    a. Render the scene from $N$ viewpoints and compute the loss $\mathcal{L}$.
    b. Backpropagate to obtain the 2D positional gradients $\nabla_{\pi} \mathcal{L}$ for all pixels $\pi$ in all $N$ views.
    c. For each Gaussian $G$:
        i. Identify all pixels $\pi$ such that $V_{\pi} = k$ (where $V_{\pi}$ is the viewpoint of pixel $\pi$) and $\pi$ is covered by $G$.
        ii. Compute the squared norm of the gradient for each covered pixel: $\|\nabla_{\pi} \mathcal{L}\|^2$.
        iii. Sum these squared norms across all viewpoints $k=1 \dots N$ and all pixels $\pi$ covered by $G$:
        $$ E_1(G) = \sum_{k=1}^{N} \sum_{V_{\pi}=k} \|\nabla_{\pi} \mathcal{L}\|^2 $$
3.  Compare $E_1(G)$ against a threshold $\tau$ (see DS Threshold below). If $E_1(G) > \tau$, mark $G$ for densification.

**Pseudocode**
```python
def compute_multiview_error(gaussians, gradients, num_views):
    """
    gaussians: List of Gaussian objects, each having a 'covered_pixels' attribute.
    gradients: Dict mapping (view_id, pixel_id) to a 2D vector (gradient).
    num_views: Integer N, total number of viewpoints.
    Returns: Dict mapping Gaussian index to scalar error score E1.
    """
    errors = {}
    
    for g_idx, gaussian in enumerate(gaussians):
        score = 0.0
        # Iterate over all pixels covered by this Gaussian
        for view_id, pixel_id in gaussian.covered_pixels:
            # Retrieve the 2D positional gradient for this pixel
            grad_vec = gradients[(view_id, pixel_id)]
            
            # Compute squared L2 norm of the gradient
            # Note: We do NOT add the vectors directly across views
            squared_norm = sum(g * g for g in grad_vec)
            
            # Accumulate the squared norms
            score += squared_norm
            
        errors[g_idx] = score
        
    return errors
```

**Parameters**
*   **Threshold ($\tau$):** The threshold for triggering densification. The default value is typically 30 [S3, unofficial]. For specific scenes like the "playroom" in the DeepBlending dataset, a value of 60 is recommended [S3, unofficial]. Other scenes generally use 30 [S3, unofficial].
*   **Number of Views ($N$):** The number of viewpoints rendered per iteration. Standard implementations often fix this to 4 [S1, unofficial].

**Edge Cases and Pitfalls**
*   **Invalid Vector Addition:** The primary pitfall avoided by this method is the direct summation of 2D positional gradients from different image planes. As shown in [S1, unofficial], adding 2D vectors from different spaces can result in a zero vector even if the underlying 3D gradients are identical and large, leading to missed densification opportunities.
*   **Precision:** Summing squared norms can lead to large values for Gaussians covered by many pixels. Ensure floating-point precision is sufficient to distinguish between high-error and low-error Gaussians.

## Subtopics

### DS Threshold (DSTH)
A hyperparameter threshold that controls the densification constraints of Gaussians. Increasing the threshold imposes stricter constraints, reducing the number of Gaussians (NGS), rendering quality, and training time [S3, unofficial]. The default value is 30 [S3, unofficial]. For the playroom scene in the DeepBlending dataset, it is set to 60; other scenes use 30 [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(P)$, where $P$ is the total number of pixel-Gaussian intersections across all views. The norm calculation is constant time per intersection.
*   **Memory Complexity:** $O(G)$, where $G$ is the number of Gaussians, to store the error scores.
*   **Performance:** On the "garden" scene, the multi-view criterion yields 27.06 dB PSNR and 0.1247 LPIPS using 148,658 primitives, compared to 26.83 dB PSNR and 0.1303 LPIPS using 240,075 primitives with the standard positional-gradient rule [S2, unofficial]. On average, it provides a 0.67 dB PSNR improvement and 0.028 LPIPS improvement while using 28% fewer primitives [S2, unofficial].
*   **Strengths:** Resolves the nullification of gradients in multi-view settings; reduces primitive count without sacrificing quality.
*   **Limitations:** Requires computing squared norms instead of simple vector addition; performance gains are specific to multi-view training regimes.

## Background
The method was proposed to address incompatibilities between standard 3D Gaussian Splatting densification and efficient multi-view training frameworks [S1, unofficial]. Standard ADC, which sums 2D positional gradients, fails in multi-view contexts because gradients from different image planes reside in different coordinate spaces [S1, unofficial]. The authors introduced this space-independent error metric to enable efficient multi-view training with reasonable overhead [S1, unofficial]. It is applied during the teacher training phase to control primitive count and distribution [S2, unofficial].
