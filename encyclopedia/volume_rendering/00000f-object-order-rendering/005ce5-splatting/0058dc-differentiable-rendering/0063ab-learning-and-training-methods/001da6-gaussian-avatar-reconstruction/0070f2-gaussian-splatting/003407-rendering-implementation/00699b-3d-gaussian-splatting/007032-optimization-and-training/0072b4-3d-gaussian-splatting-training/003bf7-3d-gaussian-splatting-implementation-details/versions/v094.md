# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, GSGEN Implementation Details, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific implementation parameters, optimization strategies, and algorithmic variants required to train and render 3D Gaussian Splatting (3DGS) scenes effectively. It addresses the core problem of balancing reconstruction fidelity with computational efficiency by defining precise thresholds for densification, pruning, and gradient accumulation. It sets itself apart from general optimization theory by providing concrete hyperparameters (e.g., opacity thresholds, gradient scales) and specific CUDA-level optimizations (e.g., half-precision fetches) that enable real-time performance.

## How it works
The training and rendering pipeline relies on a differentiable rasterizer [6233-optimization-and-parallelization] that projects 3D Gaussians to 2D ellipses and alpha-blends them. The implementation details below govern the initialization, densification, pruning, and numerical stability of this process.

### Inputs and Outputs
*   **Inputs:** Sparse point cloud from Structure-from-Motion (SfM) [S4], camera poses, and training images.
*   **Outputs:** A set of 3D Gaussian primitives parameterized by mean $\mu$, covariance $\Sigma$ (or scale $s$ and rotation $R$), opacity $\alpha$, and spherical harmonic (SH) coefficients for color $c$.

### Data Structures
*   **Gaussian Attributes:** Each Gaussian stores position (3 floats), scale (3 floats), rotation (4 floats, quaternion), opacity (1 float), and SH coefficients (variable, typically degree 1 or 3).
*   **Covariance:** The 3D covariance matrix $\Sigma$ is constructed from scale $s$ and rotation $R$ as $\Sigma = R S S^T R^T$, where $S$ is a diagonal matrix of scales [S5].

### Training Loop and Densification
The optimization follows an iterative process where Gaussians are split, cloned, or pruned based on gradient magnitudes and opacity [S1, S4].

1.  **Initialization:** Initialize Gaussians from the SfM point cloud. The scene extent $e_{\text{scene}}$ determines the initial scale.
    *   *Pitfall:* Default 3DGS calculates $e_{\text{scene}}$ based on the furthest camera distance from the average camera position:
        $$e_{\text{scene}} = 1.1 \cdot \max_{i=1}^{N_{\text{cam}}} \|\bar{C} - C_i\|_2 \quad (9)$$
        $$\bar{C} = \frac{1}{N_{\text{cam}}} \sum_{i=1}^{N_{\text{cam}}} C_i \quad (10)$$
        This biases the scene extent if cameras are clustered (e.g., orbiting a small object in a large environment), leading to incorrect splitting/pruning [S4].
    *   *Correction:* Use the corrected scene extent based on SfM points:
        $$e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2 \quad (11)$$
        where $N_{\text{SfM}}$ is the number of SfM points and $p_i$ are their positions [S4].

2.  **Optimization Step:**
    *   Randomly select a single image from a random scene as supervision for each iteration [S3].
    *   Render the image using the differentiable rasterizer.
    *   Compute loss (typically MSE and SSIM) and backpropagate gradients [S13, unofficial].
    *   Optimizer: Adam with learning rate $1 \times 10^{-3}$ [S3].

3.  **Densification (Every 100–500 iterations):**
    *   **Splitting:** Split Gaussians where the view-space position gradient exceeds a threshold $T_{\text{pos}}$.
        *   Standard threshold: $T_{\text{pos}} = 0.02$ [S1].
        *   Interval: Every 500 iterations [S1].
    *   **Cloning:** Clone Gaussians with high opacity but low gradient magnitude to fill gaps without creating floaters.
    *   **Compactness:** Perform compactness-based densification every 1000 iterations [S1].

4.  **Pruning (Every 200 iterations):**
    *   Remove Gaussians with opacity $\alpha < \alpha_{\text{min}}$.
        *   Standard threshold: $\alpha_{\text{min}} = 0.05$ [S1].
    *   Remove Gaussians with excessively large world-space or view-space radius [S1].

### Numerical Stability and Precision
*   **Half-Precision Rasterization:** Use half-precision (FP16) memory fetches on feature vectors during rasterization for both forward and backward kernels to reduce register pressure [S2].
*   **Loss Scaling:** Apply an automatic scaling factor to loss values to improve half-precision training stability [S2].
*   **MLP Evaluation:** Use tiny-cuda-nn's JIT-compiled cooperative vector MLPs, trained and evaluated in half precision (FP16) [S2].

### Pseudocode: Training Step
```python
def training_step(gaussians, camera, image_gt, iteration):
    # 1. Forward Pass
    # Project Gaussians to 2D, rasterize, and blend
    image_pred = rasterize(gaussians, camera)
    
    # 2. Loss Computation
    # Combined MSE and SSIM loss [S13, unofficial]
    loss = lambda_mse * MSE(image_pred, image_gt) + \
           (1 - lambda_mse) * SSIM(image_pred, image_gt)
    
    # 3. Backward Pass
    loss.backward()
    
    # 4. Optimizer Step
    optimizer.step()
    optimizer.zero_grad()
    
    # 5. Densification and Pruning
    if iteration % 100 == 0:
        # Compute view-space position gradients
        gradients = compute_position_gradients(gaussians)
        
        # Split high-gradient Gaussians
        split_threshold = 0.02 # T_pos [S1]
        gaussians = split_gaussians(gaussians, gradients, split_threshold)
        
    if iteration % 200 == 0:
        # Prune low-opacity Gaussians
        alpha_min = 0.05 # alpha_min [S1]
        gaussians = prune_gaussians(gaussians, alpha_min)
        
    if iteration % 1000 == 0:
        # Compactness-based densification [S1]
        gaussians = compactness_densify(gaussians)
        
    return gaussians
```

### Corrected Scene-Extent
A method to calculate scene extent based on the SfM point cloud rather than camera positions to avoid bias from camera distribution (e.g., orbiting a small object in a large environment) [S4]. The corrected extent $e'_{\text{scene}}$ is computed as $\frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2$, where $\bar{C}$ is the average camera position and $p_i$ are SfM points [S4]. This prevents incorrect splitting/pruning caused by the default camera-centric extent calculation [S4].

### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ to selectively enlarge covariances, creating pixel-wise variable blur kernels that match spatially varying scene blurriness [S5]. A compact MLP predicts $\delta s_j$ for each Gaussian $j$, which is added to the base scale to transform the covariance. This transformed covariance is projected to 2D space and used as a pixel-wise blur kernel during rasterization [S5]. If $\delta s_j$ is constant, it degrades to a uniform Gaussian blur [S5].

### Denoise-GS
A self-supervised denoising method for sparse-view 3DGS that combines unsupervised image denoising with differentiable 3DGS [S6]. Round 1: Train a UNet using Noise2Void (N2V) for denoising, process denoised images through InstantSplat to initialize/train 3DGS, and filter rendered results by viewpoint [S6]. Round 2: Fine-tune the UNet with a composite loss balancing low-frequency and perceptual detail consistency, then render again [S6]. Unlike supervised methods, it requires no paired clean data [S6].

### Multi-Scale Constraint
Applies different scales to Gaussians based on viewer distance to improve rendering of distant objects [S7]. Uses a position-aware factor $\gamma(\mu)$: $\gamma(\mu) = 1$ if $\|\mu - c\|^2 < 2r$, else $\|\mu - c\|^2 / r - 1$, where $r$ is scene radius and $c$ is camera center [S7]. Cloning is performed if $\max(s) < g \cdot \gamma(\mu)$, splitting if $\max(s) \ge g \cdot \gamma(\mu)$, and elimination if $\max(s) > b \cdot \gamma(\mu)$, where $g$ and $b$ are scale thresholds [S7].

### LS-Gaussian Viewpoint Transformation
Leverages inter-frame continuity for efficient sparse rendering by transforming the viewpoint between consecutive frames, rather than rendering each frame separately [S8]. Used in LS-Gaussian to enable sparse rendering where only one frame in every 6 frames is fully rendered, as demonstrated on Jetson AGX Orin [S8]. Rendering quality degrades as the number of consecutively transformed frames increases due to accumulated interpolation errors [S8].

### Camera Localisation for Convergence Basin
Localizes camera pose by minimizing photometric error against the ground-truth color image of the target view, fixing $G_{init}$ during optimization [S9, unofficial]. Initialize $T_{CW}$ at a test view's position and optimize for 1000 iterations. Success is defined as converging within 1cm of the target view [S9, unofficial]. The estimated pose is found by $\mathbf{T}_{CW}^{est} = \underset{\mathbf{T}_{CW}}{\arg \min} \left\| I(\mathcal{G}_{init}, \mathbf{T}_{CW}) - \bar{I}_{target} \right\|_1$ [S9, unofficial].

### DiffGS Framework
Applies an optimization process during Gaussian extraction to optimize Gaussians to exact locations [S10]. Uses a truncation function $\lambda$ when modeling GauPF (Gaussian Probability Function) and a projection function $\tau$ (either $\tau(x) = e^{-x}$ or linear) [S10]. 50K Gaussians yield PSNR 28.61, SSIM 0.9787, LPIPS 0.0251; 100K yield PSNR 30.35, SSIM 0.9838, LPIPS 0.0151; 350K yield PSNR 34.01, SSIM 0.9879, LPIPS 0.0149 [S10].

### Opacity Offset Table for DSA
Constructs an opacity offset table to model changes in digital subtraction angiography [S11].

### Conditional Splat Approximation
Approximates the influence range of a 3D Gaussian on a slice using a 2D ellipse splat scaled by the marginal factor, closely matching true iso-probability contours [S12, unofficial]. Qualitative validation shows the conditional splat (dashed red contours) closely overlaps with true 3D Gaussian iso-probability contours (solid blue contours) [S12, unofficial].

### PyGS Optimization
Uses a combined MSE and SSIM loss, along with density control strategies adapted from 3DGS, while preserving multi-scale structure [S13, unofficial]. Loss: $L = \lambda \cdot \text{MSE}(C, \hat{C}) + (1 - \lambda) \cdot \text{SSIM}(C, \hat{C})$ [S13, unofficial]. Apply splitting/cloning from 3DGS; newly split/cloned Gaussians remain in their original level. Routinely reassess and reassign levels based on scales to preserve multi-scale characteristics [S13, unofficial].

### GAINS (Gaussian-based Inverse Rendering from Sparse multi-view captures)
A two-stage inverse rendering framework leveraging foundation model priors for geometry and material estimation from sparse multi-view RGB captures [S14]. Stage I: Optimize geometry using monocular depth, normal, and diffusion priors. Stage II: Jointly optimize material parameters and lighting using segmentation, intrinsic image decomposition (IID), and diffusion priors [S14]. Uses 2DGS instead of 3DGS for more accurate geometry [S14]. Typically uses $N=4$ to $32$ input views [S14].

### SAGS (Adaptive Gaussian Splatting)
Utilizes an adaptive 2D low-pass filter at inferencing time based on rendering resolution and camera distance to handle aliasing [S15, unofficial].

### Frequency Gaussian Splatting
Applies frequency-domain regularization to the rendered 2D image to encourage recovery of high-frequency detail, resolving blurring issues [S15, unofficial].

### Neural Illumination Enhancement
A neural module applied only to non-Lambertian regions to model view-dependent highlights [S16, unofficial]. Inputs spatial position, reflection direction, and material features into an MLP. Spatial positions are encoded using HashGrid encoding; reflection directions using Spherical Harmonics (SH); other features (view direction, normals, Fresnel, roughness) are used directly. Final image is $I_g + I_n$, where $I_g$ is explicit Gaussian image and $I_n$ is neural residual [S16, unofficial].

### GraphiGS
A variant of GraphiXS where component distribution $\delta_\theta$ is modeled as a 3D Gaussian primitive, providing compact spatial support and exponential density decay [S17]. $\delta_{GS}(x; \mu, \Sigma) = \exp(-1/2 (x - \mu)^T \Sigma^{-1} (x - \mu))$ [S17]. $\mu \in \mathbb{R}^3$, $\Sigma \in \mathbb{R}^{3 \times 3}$ [S17].

### TRIPS
Attaches a neural feature to Gaussians and renders pyramid-like image feature planes according to the projected Gaussian’s size, similar to ADOP, to resolve blurring issues [S15, unofficial].

## Operating characteristics
*   **Time Complexity:** Rendering is $O(N \cdot P)$ where $N$ is the number of Gaussians and $P$ is the number of pixels, but optimized via tile-based rasterization and sorting [6233-optimization-and-parallelization]. Training complexity depends on the number of iterations and densification steps.
*   **Memory Complexity:** $O(N \cdot D)$ where $D$ is the dimensionality of Gaussian attributes (position, scale, rotation, opacity, SH coefficients). Standard 3DGS scenes can exceed 1GB [12943-data-compression-and-storage-optimization].
*   **Performance:** Real-time rendering (60+ FPS) is achievable on modern GPUs with optimized CUDA kernels [6233-optimization-and-parallelization]. Half-precision rasterization reduces register pressure and improves throughput [S2].
*   **Strengths:** High fidelity, real-time rendering, explicit representation allows for easy editing and compression.
*   **Limitations:** Sensitive to initialization (SfM quality), prone to "floaters" in unobserved regions, and requires significant memory for large scenes.
*   **When to use:** When real-time novel view synthesis is required and high-fidelity reconstruction is needed.
*   **When not to use:** When memory is severely constrained without compression, or when the input data is extremely sparse and noisy without denoising pre-processing [S6].

## Background
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1]. It represents scenes as a set of 3D Gaussians and uses differentiable rasterization for fast rendering. The method has since been extended with various optimization techniques, compression methods, and hardware accelerations to improve efficiency and quality [6233-optimization-and-parallelization].
