# Primitives Growth Control

Also called: Budget control, Growth control

## Overview
Primitives Growth Control is a constraint mechanism applied during the densification phase of 3D Gaussian Splatting to prevent unbounded growth of the primitive count, which can lead to out-of-memory errors [S1]. It sets itself apart from standard Adaptive Densification (ADC) by enforcing a hard upper bound on the total number of Gaussians and limiting the rate of new primitive creation per step, ensuring stable memory usage even when densification remains active for extended training periods [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** The current set of $N$ 3D Gaussian primitives, their associated densification scores (e.g., view-space positional gradients or reconstruction loss metrics), and the target maximum primitive budget $N_{max}$.
*   **Output:** A filtered list of primitives eligible for cloning/splitting, capped such that the total count does not exceed $N_{max}$.

**Data Structures:**
*   **Primitive Set:** A list of $N$ objects, each containing position $\mathbf{p}$, covariance $\mathbf{S}$ (or scale/rotation), opacity $\alpha$, and a scalar densification score $E_k$.
*   **Budget Counter:** An integer tracking the current number of primitives.

**Parameters:**
*   **Growth Fraction ($f$):** The maximum fraction of existing primitives allowed to be added in a single densification step. Typical value: $0.05$ (5%) [S1].
*   **Max Primitives Budget ($N_{max}$):** The absolute upper limit on the number of primitives. Typically set to the median number of primitives generated by the baseline 3D Gaussian Splatting method on the same scene, or the peak count reached during unconstrained training [S1].

**Steps:**
1.  **Identify Candidates:** Evaluate all current primitives to determine which ones meet the criteria for densification (e.g., $E_k > \tau$). Let this set of candidates be $C$.
2.  **Calculate Allowance:** Compute the maximum number of new primitives allowed in this step:
    $$ N_{allow} = \lfloor f \times N \rfloor $$
    where $N$ is the current number of primitives [S1].
3.  **Check Budget:** Determine the remaining budget:
    $$ N_{rem} = N_{max} - N $$
    The effective limit for new primitives is:
    $$ N_{limit} = \min(N_{allow}, N_{rem}) $$
    If $N_{limit} \le 0$, no new primitives are created [S1].
4.  **Rank Candidates:** Sort the candidate set $C$ in descending order based on their densification score $E_k$.
5.  **Select Top-K:** Select the top $K$ candidates from $C$, where $K = N_{limit}$. If $|C| \le N_{limit}$, all candidates are selected.
6.  **Execute Densification:** For each selected candidate, perform the standard cloning or splitting operation as defined in the parent method [Density Control and Densification](5337-density-control-and-densification.md). Primitives not selected are left unchanged.

**Pseudocode:**
```python
def primitives_growth_control(primitives, densification_scores, N_max, growth_fraction=0.05):
    """
    primitives: List of Gaussian primitives.
    densification_scores: List of float scores corresponding to each primitive.
    N_max: Maximum allowed number of primitives.
    growth_fraction: Fraction of current primitives allowed to be added per step.
    """
    N = len(primitives)
    
    # Calculate max new primitives allowed by growth rate
    N_allow = int(growth_fraction * N)
    
    # Calculate remaining budget
    N_rem = N_max - N
    
    # Effective limit is the minimum of growth allowance and remaining budget
    N_limit = min(N_allow, N_rem)
    
    # If no budget, return empty list of indices to densify
    if N_limit <= 0:
        return []
    
    # Identify candidates with positive densification score (or threshold > 0)
    # Assuming densification_scores contains the metric E_k
    # In standard ADC, candidates are those where E_k > threshold.
    # Here we assume the caller has already filtered for E_k > threshold,
    # or we filter here. Let's assume densification_scores are raw metrics
    # and we need to pick the best ones.
    
    # Create list of (index, score)
    candidates = [(i, score) for i, score in enumerate(densification_scores) if score > 0]
    
    # Sort by score descending
    candidates.sort(key=lambda x: x[1], reverse=True)
    
    # Select top N_limit candidates
    selected_indices = [idx for idx, _ in candidates[:N_limit]]
    
    return selected_indices
```

**Edge Cases and Pitfalls:**
*   **Zero Budget:** If $N$ reaches $N_{max}$, $N_{rem}$ becomes 0, and no further densification occurs. This prevents OOM but may halt refinement if the scene still requires higher density [S1].
*   **Score Ties:** If multiple candidates have identical scores, the selection is arbitrary unless a secondary tie-breaker (e.g., index) is defined.
*   **Dynamic $N_{max}$:** $N_{max}$ is typically static per scene, derived from baseline statistics. Setting it too low may degrade reconstruction quality; setting it too high defeats the purpose of growth control [S1].

## Operating characteristics
*   **Time Complexity:** $O(N \log N)$ per densification step due to sorting candidates, where $N$ is the number of primitives. This is negligible compared to the rendering cost.
*   **Memory Complexity:** $O(N)$, as it only stores the primitive list and scores. It prevents memory explosion by capping $N$.
*   **Performance:** Ensures stable memory usage during long training runs (e.g., 27k iterations vs. 15k in standard 3DGS) without significant quality loss [S1].
*   **Strengths:** Prevents out-of-memory errors; allows extended training for better convergence; simple to implement.
*   **Limitations:** May prematurely stop densification in complex regions if $N_{max}$ is set too conservatively; requires tuning $N_{max}$ based on baseline runs [S1].

## Background
Primitives Growth Control was introduced in "Revising Densification in Gaussian Splatting" to address the issue of unpredictable primitive growth in standard Adaptive Densification Control (ADC) [S1]. The authors observed that while ADC stops after 15k iterations in standard 3DGS, keeping it active for longer (e.g., 27k) leads to memory issues without a cap. The method was developed to enable stable, long-duration training by combining a fixed growth fraction with a global budget limit [S1].
