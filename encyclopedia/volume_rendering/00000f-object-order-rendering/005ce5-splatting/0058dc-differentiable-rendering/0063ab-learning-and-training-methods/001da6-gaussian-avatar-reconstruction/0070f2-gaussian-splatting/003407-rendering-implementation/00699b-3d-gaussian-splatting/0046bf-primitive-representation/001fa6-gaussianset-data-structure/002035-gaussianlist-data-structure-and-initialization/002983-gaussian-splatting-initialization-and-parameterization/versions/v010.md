# Gaussian Splatting Initialization and Parameterization

Also called: 3D Gaussian Primitive Initialization, 3D Gaussian Splatting Initialization, COLMAP Initialization, SfM Initialization, Sparse Point Cloud Initialization, Sparse SfM Initialization, Starter Gaussians, Structure from Motion (SfM) Initialization

## Overview
Gaussian Splatting Initialization and Parameterization establishes the initial state of the 3D Gaussian primitives ($\mathcal{G}$) from a sparse Structure-from-Motion (SfM) point cloud, providing geometrically accurate starting positions, colors, and covariances [S2, S8, unofficial]. SfM initialization produces a sparse point cloud that may not cover all geometry, whereas random initialization is denser but lacks normals and accurate initial positions; SfM is preferred if 2D images are available [S2, unofficial]. It sets itself apart from dense MVS initialization by avoiding the baking of MVS errors and redundant geometry, relying instead on the optimizer to create detail during training [S8, unofficial].

## How it works

### Inputs and Outputs
**Inputs:**
*   A set of 2D images (e.g., from COLMAP) [S2, unofficial].
*   Camera poses (extrinsic: rotation $R_{cam}$, translation $T_{cam}$; intrinsic: focal length $f$) estimated via SfM [S2, S8, unofficial].
*   A sparse 3D point cloud $\mathcal{P} = \{p_i\}_{i=1}^N$ containing 3D coordinates $\mathbf{x}_i \in \mathbb{R}^3$ and RGB colors $\mathbf{c}_i \in \mathbb{R}^3$ [S2, S8, unofficial].

**Outputs:**
*   A set of $N$ learnable 3D Gaussian parameters:
    *   Means: $\mathbf{\mu}_i \in \mathbb{R}^3$ (position)
    *   Scales: $\mathbf{s}_i \in \mathbb{R}^3$ (log-space radii)
    *   Rotations: $\mathbf{q}_i \in \mathbb{R}^4$ (unit quaternion)
    *   Opacities: $\alpha_i \in [0, 1]$ (stored as logits)
    *   Colors: $\mathbf{c}_i$ (Spherical Harmonics coefficients)

### Data Structures
The Gaussian parameters are stored as differentiable tensors (e.g., `nn.Parameter` in PyTorch) on the GPU [S6, S1, unofficial].

*   **Means ($\mathbf{\mu}$):** Tensor of shape $(N, 3)$.
*   **Scaling ($\mathbf{s}$):** Tensor of shape $(N, 3)$, storing log-space values.
*   **Rotation ($\mathbf{q}$):** Tensor of shape $(N, 4)$, storing quaternions in $[w, x, y, z]$ format.
*   **Opacity ($\alpha_{logit}$):** Tensor of shape $(N, 1)$, storing logits.
*   **Features ($\mathbf{f}$):** Tensor of shape $(N, 1, 3)$ for the DC component ($f_{dc}$) and $(N, K, 3)$ for higher-order SH coefficients ($f_{rest}$), where $K$ depends on the SH degree [S6, unofficial].

### Initialization Steps

1.  **SfM Reconstruction:**
    Perform Structure-from-Motion on the input images to estimate camera poses and reconstruct a sparse 3D point cloud with associated colors [S2, S7, unofficial].
    *   *Note:* Dense MVS clouds are discouraged as they waste time and bake in MVS errors [S8, unofficial].

2.  **Position Initialization:**
    Copy the 3D coordinates from the SfM point cloud directly to the Gaussian means tensor [S1, S8, unofficial].
    $$ \mathbf{\mu}_i = \mathbf{x}_i $$

3.  **Covariance Initialization (Scale and Rotation):**
    The covariance matrix $\Sigma$ is parameterized by scale $\mathbf{s}$ and rotation $\mathbf{q}$ to ensure positive semi-definiteness [S8, unofficial].
    
    *   **Scale:** Compute the distance to the $k$-nearest neighbors (KNN) for each point. A common implementation uses a fixed base distance or the mean KNN distance [S1, S6, S8, unofficial].
        *   *Method A (Fixed Base):* Use a base distance $d_{base} = 0.1$ [S6, unofficial]. Compute $dist2 = \max(0.1, \min(d_{base}, 1e-7))$ [S6, unofficial]. The scale is initialized isotropically:
            $$ \mathbf{s}_i = [\log(\sqrt{dist2}), \log(\sqrt{dist2}), \log(\sqrt{dist2})]^T $$
            [S6, unofficial]
        *   *Method B (KNN-based):* Compute the mean distance to the 50 nearest neighbors, apply log, and replicate across dimensions [S4, unofficial]. Or use the mean orientation-aware KNN distance multiplied by a factor $s_{init} = 1.5$ [S3, unofficial].
        *   *Clamping:* During optimization, scales are clamped to a maximum value (e.g., 10.0) to prevent excessively large Gaussians [S6, unofficial].
    
    *   **Rotation:** Initialize all quaternions to the identity rotation:
        $$ \mathbf{q}_i = [1, 0, 0, 0]^T $$
        [S4, S6, S8, unofficial]
        *   *Variant (Normal-Aligned):* If surface normals are available (e.g., from depth maps), compute the quaternion that aligns the local z-axis with the estimated surface normal [S3, unofficial].

4.  **Opacity Initialization:**
    Initialize opacities as logits to ensure valid sigmoid output during training [S4, S6, unofficial].
    *   *Method A:* Set pre-activation opacity to 8.0 [S4, unofficial].
        $$ \alpha_{logit, i} = 8.0 \implies \sigma(8.0) \approx 0.9997 $$
        [S4, unofficial]
    *   *Method B:* Set target opacity to 0.1, compute logit:
        $$ \alpha_{logit, i} = \log\left(\frac{0.1}{1 - 0.1}\right) = \log\left(\frac{0.1}{0.9}\right) $$
        [S1, unofficial]
    *   *Clamping:* Clamp initial logit values to a range corresponding to $[1e-4, 0.99]$ to prevent extreme gradients [S6, unofficial].

5.  **Color Initialization (Spherical Harmonics):**
    Initialize the zeroth-degree SH coefficient ($f_{dc}$) from the SfM point's RGB color [S1, unofficial]. Higher-order coefficients ($f_{rest}$) are initialized to zero [S8, unofficial].
    *   Normalize RGB to $[-0.5, 0.5]$.
    *   Divide by the SH basis constant $C_0 = 0.28209479177387814$:
        $$ f_{dc, i} = \frac{\mathbf{c}_i}{C_0} $$
        [S1, S6, unofficial]
    *   Set $f_{rest, i} = \mathbf{0}$ [S1, S8, unofficial].

6.  **Covariance Matrix Construction:**
    During rendering, the 3D covariance matrix $\Sigma$ is reconstructed from $\mathbf{s}$ and $\mathbf{q}$:
    $$ \Sigma = M M^T $$
    Where $M = R \cdot \text{diag}(\exp(\mathbf{s}))$, $R$ is the rotation matrix derived from $\mathbf{q}$, and $\text{diag}(\exp(\mathbf{s}))$ is the diagonal scaling matrix [S6, unofficial].

### Pseudocode

```python
import torch

def initialize_gaussians_from_sfm(sfm_points_xyz, sfm_points_rgb):
    """
    Initialize 3D Gaussian parameters from a sparse SfM point cloud.
    
    Args:
        sfm_points_xyz: Tensor of shape (N, 3), 3D coordinates.
        sfm_points_rgb: Tensor of shape (N, 3), RGB colors in [0, 1].
        
    Returns:
        Dictionary of initialized Gaussian parameters.
    """
    N = sfm_points_xyz.shape[0]
    
    # 1. Positions
    means = sfm_points_xyz.clone().detach()
    
    # 2. Scales (Fixed Base Method per [S6, unofficial])
    base_dist = 0.1
    dist2 = torch.clamp(torch.tensor(base_dist), min=1e-7)
    scales = torch.log(torch.sqrt(dist2)).repeat(N, 3)
    
    # 3. Rotations (Identity)
    rotations = torch.zeros(N, 4)
    rotations[:, 0] = 1.0  # w=1, x=0, y=0, z=0
    
    # 4. Opacities (Logits)
    target_opacity = 0.1
    opacities = torch.log(torch.tensor(target_opacity / (1 - target_opacity))).unsqueeze(0).repeat(N, 1)
    
    # 5. Colors (SH DC component)
    C0 = 0.28209479177387814
    rgb_normalized = sfm_points_rgb - 0.5
    features_dc = (rgb_normalized / C0).unsqueeze(1)
    
    return {
        "means": means,
        "scales": scales,
        "rotations": rotations,
        "opacities": opacities,
        "features_dc": features_dc
    }
```

### Edge Cases and Pitfalls
*   **Division by Zero:** When computing the 2D projection covariance, depth $z$ must be clamped with a small epsilon (e.g., $1e-7$) to prevent division by zero in the Jacobian [S6, unofficial].
*   **Numerical Stability:** Add a bias of 0.3 to the diagonal elements of the 2D covariance matrix to prevent singular matrices during projection [S6, unofficial].
*   **Quaternion Normalization:** Quaternions must be normalized to unit length before converting to rotation matrices to ensure valid rotations [S6, unofficial].
*   **MVS Bias:** Using dense MVS clouds for initialization is discouraged as it wastes time and bakes in MVS errors as starting bias [S8, unofficial].

## Subtopics

### [Random Large-Variance Initialization](6129-random-large-variance-initialization.md)
Random Large-Variance Initialization (RAIN-GS) relaxes the strict Structure-from-Motion (SfM) point cloud assumption required by standard 3D Gaussian Splatting by introducing sparse, large-variance random initialization. Unlike standard methods that rely solely on dense SfM points, this approach allows optimization to proceed even when SfM data is sparse or absent, serving as a fallback or complementary initialization strategy.

### [Temporal Point Cloud Initialization via Chamfer Distance Minimization](6954-temporal-point-cloud-initialization-via-chamfer-distance-min.md)
This method reduces training time for dynamic video scenes by initializing the point cloud of the current frame using the learned model from the previous frame, leveraging temporal correlation between nearby frames. It sets itself apart from static initialization methods by explicitly optimizing geometric alignment between consecutive frames via Chamfer distance minimization before refining radiance parameters.

### [Gaussian Geometry Parameters Prediction](8442-gaussian-geometry-parameters-prediction.md)
Gaussian Geometry Parameters Prediction is a method for initializing and refining the geometric attributes of 3D Gaussian primitives in a feed-forward manner, typically using a global volumetric representation rather than per-pixel alignment. It solves the problem of redundant, inconsistent, and ghosting artifacts that arise when accumulating locally predicted Gaussians from multiple views. Unlike sibling methods that rely on per-scene optimization or local cost volumes, this approach predicts a unified global scene representation by refining noisy depth-initialized points in 3D space, thereby improving global consistency and reducing floating artifacts.

### [Background Hemisphere Initialization](8446-background-hemisphere-initialization.md)
Background Hemisphere Initialization is a technique for handling unbounded scenes in 3D Gaussian Splatting by modeling the distant background (sky) as a separate, fixed-radius hemisphere of Gaussians. It solves the problem of "cloud-like" artifacts and occlusion errors that occur when foreground Gaussians attempt to model distant sky regions, which degrades novel view synthesis quality. It sets itself apart from standard background models by explicitly disentangling the sky from the foreground geometry, often using a hemisphere to avoid occluding the ground plane.

### [ReSplat Initialization](10957-resplat-initialization.md)
ReSplat Initialization predicts an initial set of 3D Gaussians from a sparse point cloud by aggregating local and global 3D context to compensate for information loss incurred by downsampling the input point cloud by 16x. Unlike naive prediction methods that directly map point features to Gaussian parameters, this method uses a transformer-based encoder to enrich features with neighborhood context before decoding. It sets the stage for the subsequent Recurrent Gaussian Update by providing a structured initial state $\mathcal{G}^0$.

### [Point Cloud/Mesh-based Initialization](16343-point-cloud-mesh-based-initialization.md)
This family of methods initializes 3D Gaussian Splatting (3DGS) primitives using pre-existing 3D geometry (point clouds or meshes) rather than relying solely on sparse Structure-from-Motion (SfM) outputs. It solves the problem of initializing high-quality radiance fields when multi-view images are unavailable or when the user possesses dense, surface-aligned volumetric data (e.g., MPEG plenoptic point clouds or meshes). It differs from [Random Large-Variance Initialization](6129-random-large-variance-initialization.md) by anchoring Gaussians to observed geometry, and from [Gaussian Model Initialization](2349-gaussian-model-initialization.md) by supporting dense mesh inputs and optional fixed-position constraints.

### Neural Point Cloud Initialization from COLMAP
A method to initialize the neural point cloud and their features for Point-NeRF using an external point cloud reconstruction (specifically COLMAP) [S10]. It solves the problem of how to provide initial positions, variances, and feature vectors for the neural points [S10]. The variance parameter $\gamma_i$ for each point $p_i$ is initialized to 0.3 [S10]. To acquire the feature vector $f_i$ for a point $p_i$, views where the point is occluded are ruled out, and the view closest to the point is selected [S10].

### Binary Gaussian Hierarchy Construction
The hierarchy is a binary tree [S11, unofficial]. Leaf nodes contain the full set of optimized Gaussian properties (base color, SH coefficients, position, covariance) [S11, unofficial]. Internal nodes store merged approximations of their two child nodes [S11, unofficial].

### Single Ellipsoid Initialization
Initializes a single ellipsoid from a set of 3D points using Principal Component Analysis (PCA) to determine orientation, center, and radii [S12]. The minimum allowed radius $r_{\min}$ is typically 0.005 to avoid numerical problems, and a scaling factor $\alpha$ (typically 3) ensures points are mostly covered [S12].

### MVS-guided Initialization
Aggregates filtered multiview depth maps from an MVS method into a unified 3D point cloud [S13]. An initial optimization phase prunes noisy Gaussians by freezing centers and optimizing other parameters for $N_{prun}$ iterations, removing Gaussians with opacity $\alpha_k < \tau$ [S13]. Afterward, all parameters are unfrozen for standard optimization with Adaptive Density Control [S13].

### Feature Initialization
Initializes the base feature $f_{base}$ and directional feature $f_{dir}$ with the RGB color values of the corresponding SfM points [S14]. The temporal feature $f_{time}$ is initialized as a zero vector [S14].

## Operating characteristics

*   **Performance:** SfM initialization typically yields higher PSNR (e.g., 26.05 vs 20.42 on Average-30K) compared to random initialization [S7, unofficial]. COLMAP initialization takes ~6.0 minutes, while random initialization takes ~0.1 seconds [S5, unofficial].
*   **Strengths:** Provides geometrically accurate starting points, improving convergence and final reconstruction quality [S7, S8, unofficial].
*   **Limitations:** Requires high-quality SfM reconstruction. Dense MVS initialization is discouraged due to bias and computational waste [S8, unofficial].

## Background

The initialization from sparse SfM points was chosen to provide a geometric prior that guides the optimization, as opposed to random initialization which relies entirely on the optimizer to discover the scene geometry [S2, unofficial]. COLMAP is the standard tool used for this purpose [S2, S8, unofficial]. Subsequent work has explored variants such as random initialization for synthetic data [S2, unofficial], MVS-guided initialization [S13], and neural prediction of geometry [S2, unofficial].
