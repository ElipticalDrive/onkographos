# Densification and Splitting

Also called: 3D Gaussian Splatting Densification and Splitting

## Overview
Densification and splitting is the primary mechanism in 3D Gaussian Splatting (3DGS) for adapting the primitive count to scene complexity during training [S1]. It addresses the problem of insufficient geometric detail and surface artifacts by dynamically increasing the density of Gaussians in under-represented regions and refining their shape [S1]. Unlike static initialization, this method iteratively modifies the Gaussian set based on optimization gradients and rendering errors, distinguishing it from sibling methods like [Gaussian Pruning](18664-gaussian-pruning.md) which removes primitives, and [Adaptive Gaussian Refinement Strategy](16570-adaptive-gaussian-refinement-strategy.md) which focuses on parameter updates rather than structural changes.

## How it works
The standard densification and splitting process, as defined in the original 3DGS paper and modified by subsequent variants, operates on a per-iteration basis during the training schedule.

### Inputs and Outputs
*   **Inputs**: The current set of 3D Gaussians $\mathcal{G} = \{g_i\}$, each defined by position $\mu_i$, covariance $\Sigma_i$ (or scale $s_i$ and rotation $R_i$), opacity $\alpha_i$, and spherical harmonics coefficients for color. The set of training camera views $\mathcal{C}$. The current iteration number $t$.
*   **Outputs**: An updated set of Gaussians $\mathcal{G}'$, where some $g_i$ are split into children, some are cloned, and some are pruned (handled by [Gaussian Pruning](18664-gaussian-pruning.md)).

### Data Structures
Each Gaussian $g_i$ stores:
*   $\mu_i \in \mathbb{R}^3$: Mean position.
*   $s_i \in \mathbb{R}^3$: Scale vector (diagonal of covariance in local frame).
*   $q_i \in \mathbb{R}^4$: Rotation quaternion.
*   $\alpha_i \in \mathbb{R}$: Opacity.
*   $c_i$: Color coefficients (SH).
*   $\nabla_{\mu} \in \mathbb{R}^3$: Accumulated position gradient magnitude (normalized).

### Numbered Steps
The standard densification and splitting procedure [S1] proceeds as follows:

1.  **Gradient Accumulation**: During rasterization, accumulate the gradient of the loss with respect to the position $\mu_i$ for each Gaussian. Let $|\nabla_{\mu_i}|$ be the L2 norm of this gradient.
2.  **Selection Criteria**: Identify Gaussians for densification based on two conditions [S1]:
    *   The position gradient magnitude $|\nabla_{\mu_i}|$ exceeds a threshold $\tau_{grad}$.
    *   The scale of the Gaussian (e.g., the maximum dimension of $s_i$) exceeds a threshold $\tau_{scale}$.
    *   *Note*: Some variants, such as [VCR-GauS](16385-training-configuration-and-hyperparameters.md) [S1], replace the gradient-based selection with a scale-only threshold $\beta$ to reduce depth errors caused by normal inaccuracies in large Gaussians.
3.  **Splitting**: For each selected Gaussian $g_i$:
    *   Identify the axis of the scale vector $s_i$ with the largest magnitude.
    *   Create two child Gaussians $g_{i,1}$ and $g_{i,2}$.
    *   **Position Initialization**: The positions are set to evenly divide the maximum scale of the parent. Specifically, if the largest scale is along axis $k$, the new positions are:
        $$ \mu_{i,1} = \mu_i - \frac{s_{i,k}}{2} \hat{u}_k, \quad \mu_{i,2} = \mu_i + \frac{s_{i,k}}{2} \hat{u}_k $$
        where $\hat{u}_k$ is the unit vector along the axis $k$ in the parent's local frame, transformed to world space.
    *   **Scale Initialization**: The scales of the children are reduced. A common factor is $1.6$ reduction in scale (or $0.6$ of original) [S1][S7, unofficial].
    *   **Other Parameters**: Opacity $\alpha$ is halved for each child. Color coefficients $c$ are copied from the parent. Rotation $R$ is copied.
    *   **Parent Removal**: The parent Gaussian $g_i$ is removed from the set.
4.  **Cloning** (Optional/Variant): Some implementations [S7, unofficial] also clone Gaussians that meet the gradient threshold but do not require splitting (e.g., to increase density without reducing scale). The clone has the same parameters as the parent.
5.  **Pruning**: Gaussians with opacity below a threshold $\tau_{opacity}$ are removed [S1].

### Pseudocode
```python
def densify_and_split(gaussians, gradients, iteration, config):
    """
    gaussians: List of Gaussian objects with attributes .mu, .s, .alpha, .c, .R
    gradients: Dict mapping gaussian_id to gradient vector (3,)
    iteration: Current training iteration
    config: Dictionary with thresholds and parameters
    """
    to_split = []
    to_clone = []
    
    # Step 1 & 2: Selection
    for g in gaussians:
        grad_norm = np.linalg.norm(gradients[g.id])
        
        # Check gradient threshold
        if grad_norm > config['grad_threshold']:
            # Check scale threshold (standard 3DGS)
            max_scale = np.max(g.s)
            if max_scale > config['scale_threshold']:
                to_split.append(g)
            else:
                # Optional: Clone if gradient is high but scale is small
                if config['enable_cloning']:
                    to_clone.append(g)
    
    # Step 3: Splitting
    new_gaussians = []
    for g in to_split:
        # Find axis with largest scale
        axis_idx = np.argmax(g.s)
        axis_vec = np.eye(3)[axis_idx]
        
        # Transform axis to world space using rotation
        world_axis = g.R @ axis_vec
        
        # Calculate split offset
        # Standard 3DGS uses 1.6 factor for scale reduction
        # Position split: half the scale in world direction
        offset = (g.s[axis_idx] / 2.0) * world_axis
        
        # Create child 1
        g1 = Gaussian()
        g1.mu = g.mu - offset
        g1.s = g.s / 1.6
        g1.R = g.R
        g1.alpha = g.alpha / 2.0
        g1.c = g.c
        
        # Create child 2
        g2 = Gaussian()
        g2.mu = g.mu + offset
        g2.s = g.s / 1.6
        g2.R = g.R
        g2.alpha = g.alpha / 2.0
        g2.c = g.c
        
        new_gaussians.append(g1)
        new_gaussians.append(g2)
        
    # Step 4: Cloning
    for g in to_clone:
        g_clone = Gaussian()
        g_clone.mu = g.mu.copy()
        g_clone.s = g.s.copy()
        g_clone.R = g.R.copy()
        g_clone.alpha = g.alpha / 2.0 # Opacity halved
        g_clone.c = g.c.copy()
        new_gaussians.append(g_clone)
        
    # Remove parents and add children
    active_ids = {g.id for g in gaussians if g not in to_split and g not in to_clone}
    final_gaussians = [g for g in gaussians if g.id in active_ids] + new_gaussians
    
    return final_gaussians
```

### Parameters
*   $\tau_{grad}$: Gradient threshold. Typical value: $10^{-4}$ to $10^{-5}$ [S1].
*   $\tau_{scale}$: Scale threshold. Typical value: $0.01$ to $0.005$ [S1].
*   $\tau_{opacity}$: Opacity pruning threshold. Typical value: $0.005$ [S1].
*   Scale reduction factor: Typically $1.6$ [S1].
*   Cloning threshold: Often same as splitting gradient threshold but without scale check [S7, unofficial].

### Edge Cases and Pitfalls
*   **Depth Error**: Standard densification based on position gradients can cause depth errors and surface bumps if the Gaussian normals are inaccurate, especially for large Gaussians [S1]. Variants like [VCR-GauS](16385-training-configuration-and-hyperparameters.md) [S1] mitigate this by selecting Gaussians for densification based solely on scale thresholds after collecting first-intersection rays.
*   **Clustering**: Splitting Gaussians from the same parent can lead to clustering if positions are sampled from the Gaussian distribution. Deterministic splitting along the largest axis avoids this [S1].
*   **Hierarchy Degeneration**: In parallel respawn/densify strategies, if two sibling nodes need respawn, only the right node is respawned to prevent degeneration [S3, unofficial].

## Subtopics

### [Score-based Densification](4705-score-based-densification.md)
Score-based Densification is a constructive training strategy for 3D Gaussian Splatting that controls model size by adding new primitives only to those Gaussians that maximize a specific quality score, ensuring the final model adheres to a user-defined budget without requiring pruning. Unlike standard 3D Gaussian Splatting which relies on heuristic thresholds and subsequent culling, this method uses a purely constructive schedule that steers densification toward Gaussians contributing most to reconstruction quality, avoiding optimization instability caused by aggressive removal.

### [Gaussian Insertion and Pruning](10074-gaussian-insertion-and-pruning.md)
Gaussian Insertion and Pruning is a dynamic management strategy for 3D Gaussian primitives used primarily in monocular and RGB-D SLAM systems. It solves the problem of maintaining a coherent 3D structure in real-time by inserting new Gaussians to capture newly visible scene elements and pruning those that are geometrically unstable or contribute negligibly to the render. Unlike static densification strategies that rely on gradient magnitude thresholds, this method relies on visibility consistency across a sliding window of keyframes and opacity thresholds to manage the primitive set.

### [Error-guided Guided Sampling](15896-error-guided-guided-sampling.md)
Error-guided Guided Sampling (EMS) is a densification strategy for 3D Gaussian Splatting that targets regions of high perceptual error rather than relying solely on gradient magnitude or opacity thresholds. It identifies low-SSIM training views, computes a pixel-wise error mask, and spawns new Gaussians specifically in high-error areas while using depth information and spatial masks to prevent overlapping placements and edge artifacts. Unlike standard densification which refines existing primitives based on local gradients, EMS performs a global view-based error analysis to insert new primitives where the current representation fails to reconstruct the image structure.

### [AdpSplit](16061-adpsplit.md)
AdpSplit is an error-driven adaptive split operator for 3D Gaussian Splatting that replaces fixed-cardinality random child placement with view-loss-aware child generation. It determines the number of split children and initializes their parameters from L1-pixel-error region statistics, enabling fewer densification iterations and reduced training time while preserving rendering quality. Unlike vanilla 3DGS which uses a fixed $N=2$ binary split, AdpSplit adaptively determines the number of children based on the observed error structure, avoiding the bottleneck where binary splits require $\log_2 G$ rounds to expose a structure requiring $G$ Gaussians.

### [Child Gaussian Initialization](16063-child-gaussian-initialization.md)
Child Gaussian Initialization is the specific procedure for generating the geometric and photometric properties of new 3D Gaussian primitives during the splitting phase of adaptive densification. It solves the problem of how to accurately map a parent Gaussian's error region—identified in camera space—into a valid 3D Gaussian in world space, ensuring the child is positioned on the scene geometry and oriented correctly relative to the viewing direction. It sets itself apart from generic splitting methods by explicitly unprojecting image-space covariance ellipses into world-space scales and orientations using Mahalanobis distance minimization and perspective-aware clamping, rather than simple isotropic scaling or random sampling.

### Blur Splitting
A densification step added to the 3DGS baseline that improves rendering quality and LPIPS metrics [S2]. Adding Blur Split to 3DGS baseline increases Gaussians from 3.35M to 3.74M, SSIM from 0.815 to 0.819, and LPIPS from 0.216 to 0.195 [S2].

### Parallel Respawning and Densification with Edge Case Handling
A densification strategy where respawn and densify operations are performed in parallel, requiring specific edge case handling to prevent hierarchy degeneration [S3, unofficial]. If two sibling nodes both need to be respawned, only respawn the right node. This causes the left node to become a new dead leaf, which will be respawned in the next densification iteration [S3, unofficial]. If a node needs to be respawned whose sibling is not a leaf node, replace the entire parent node with the subtree of the node being respawned [S3, unofficial]. Apply a pruning strategy: zero the opacity of Gaussians that have not contributed for a number of iterations equal to twice the size of the training set. These will be respawned in the next densification iteration [S3, unofficial].

### Densify and Prune Optimization
Adjusting and removing the `densify_and_split` operation within the `densify_and_prune` process to improve speed without impacting rendering quality [S4, unofficial].

### Mixed-Primitive Densification
When a Gaussian triangle is cloned or split into two new Gaussian triangles, assign $\mu_1$ to each new triangle in the same manner as standard Gaussian Splatting assigns $\mu$ to new ellipses [S5, unofficial]. Assign both new cloned/split Gaussian triangles the same parameters $\mu_2$ and $\mu_3$ as the original Gaussian triangle [S5, unofficial]. When a Gaussian line is cloned or split, assign $\mu_1$ and $\mu_2$ to each new Gaussian line in the same way as $\mu_1$ and $\mu_2$ are assigned to new Gaussian triangles [S5, unofficial].

### Rendering-Guided Densification
A densification strategy that improves the quality of re-observed parts of the environment and allows the map to be extended by densifying regions based on color and depth rendering errors [S6]. On the Replica dataset (Room0), adding densification improved PSNR from 25.58 to 25.96 dB and SSIM from 0.85 to 0.89 [S6]. Unlike methods that use separate neural networks for color and depth (e.g., Point-SLAM), this method optimizes the same Gaussian parameters for both, which can impact depth estimation but allows for unified densification [S6].

### Global-to-local densification framework
A two-phase densification strategy that separates global spatial distribution from local refinement to reduce computational redundancy in early optimization stages [S7, unofficial]. Phase 1 (Global Spread): Apply only the split operation to achieve fast and effective spatial distribution, leveraging minimal Gaussian counts to minimize redundant computation on localized details [S7, unofficial]. Phase 2 (Local Refinement): Employ both split and clone operations. Since satisfactory spatial distribution is established, clone operations enable efficient local refinement [S7, unofficial]. Tdensify: Total densification iteration count. Default value is 25K [S7, unofficial].

## Operating characteristics
*   **Time Complexity**: Densification is performed periodically (e.g., every 100 iterations) [S1]. The cost is proportional to the number of Gaussians selected for splitting, which is typically a small fraction of the total set. However, the overhead of managing the dynamic list of Gaussians and re-rasterizing can be significant.
*   **Memory Complexity**: The number of Gaussians grows over time. Standard 3DGS can reach millions of primitives. Variants like [Mini-Splatting](16385-training-configuration-and-hyperparameters.md) [S2] aim to constrain this growth.
*   **Measured Performance**: On standard datasets, densification increases the Gaussian count from ~100k (initial) to ~1-2M (final) [S1]. [Mini-Splatting] [S2] reports 3.35M Gaussians for baseline 3DGS, increasing to 3.74M with Blur Split.
*   **Strengths**: Allows the representation to adapt to varying scene complexity. Handles fine details and large open spaces effectively.
*   **Limitations**: Can introduce artifacts if thresholds are not tuned correctly (e.g., depth errors [S1]). Training time increases with the number of Gaussians.
*   **When to use**: Essential for high-quality 3DGS reconstruction. Use variants like [Global-to-local densification framework](16385-training-configuration-and-hyperparameters.md) [S7, unofficial] for faster training, or [Rendering-Guided Densification](16385-training-configuration-and-hyperparameters.md) [S6] for SLAM applications.

## Background
The densification and splitting strategy was introduced in the original 3D Gaussian Splatting paper by Kerbl et al. (2023) [S1]. It was designed to address the static nature of Gaussian initialization, allowing the model to learn the geometry of the scene dynamically. Subsequent works have proposed various modifications to improve efficiency, reduce artifacts, or adapt the method to specific applications like SLAM [S6] or compression [S2].
