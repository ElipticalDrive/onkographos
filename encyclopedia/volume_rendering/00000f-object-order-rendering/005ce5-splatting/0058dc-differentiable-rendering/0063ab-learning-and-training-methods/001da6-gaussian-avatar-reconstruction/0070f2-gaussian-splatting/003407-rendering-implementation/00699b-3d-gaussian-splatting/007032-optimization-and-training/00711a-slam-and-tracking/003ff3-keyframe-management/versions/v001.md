# Keyframe Management

Also called: Keyframing

## Overview
Keyframe management maintains a small sliding window $W_k$ of camera poses and corresponding Gaussian representations to enable efficient joint optimization in online Gaussian SLAM systems [S1, unofficial]. By limiting optimization to a subset of non-redundant frames, it avoids the computational infeasibility of processing all historical data while ensuring sufficient multiview constraints for accurate pose estimation and map refinement [S1, unofficial]. It differs from fixed-interval keyframing by using covisibility metrics to select frames that span wide baselines and observe distinct scene areas [S1, unofficial].

## How it works
**Inputs:** Current tracked frame $i$, last keyframe $j$, current keyframe window $W_k$, camera pose estimates, and the current Gaussian set $\mathcal{G}$.
**Outputs:** Updated keyframe window $W_k$, registration of frame $i$ as a new keyframe (or rejection), and removal of obsolete keyframes from $W_k$.

**Data Structures:**
*   $W_k$: A list or queue of keyframe indices/IDs.
*   $\mathcal{G}$: The set of 3D Gaussians, sorted along camera rays for rasterization.
*   $V_i$: The set of visible Gaussians for frame $i$.

**Gaussian Visibility Definition:**
A Gaussian $g \in \mathcal{G}$ is considered visible from a view if it is used in the rasterization process and the accumulated alpha $\alpha$ along the ray has not yet reached 0.5 [S1, unofficial]. This leverages the inherent visibility ordering of 3D Gaussian Splatting to handle occlusions without additional heuristics [S1, unofficial].

**Algorithm Steps:**

1.  **Covisibility Measurement:**
    Calculate the intersection over union (IoU) of visible Gaussians between the current frame $i$ and the last keyframe $j$ [S1, unofficial].
    $$ \text{Covisibility}(i, j) = \frac{|V_i \cap V_j|}{|V_i \cup V_j|} $$
    where $| \cdot |$ denotes the count of visible Gaussians [S1, unofficial].

2.  **Keyframe Registration Criteria:**
    Register frame $i$ as a new keyframe if either of the following conditions is met [S1, unofficial]:
    *   $\text{Covisibility}(i, j) < \tau_{cov}$, where $\tau_{cov}$ is a covisibility threshold.
    *   The relative translation $t_{ij}$ between frame $i$ and keyframe $j$ is large with respect to the median depth of the scene [S1, unofficial].

3.  **Keyframe Removal (Window Management):**
    After adding a new keyframe, evaluate existing keyframes in $W_k$ for removal [S1, unofficial]. A keyframe $k \in W_k$ is removed if its overlap coefficient with the latest keyframe drops below a threshold $\tau_{overlap}$ [S1, unofficial]. This heuristic, adapted from DSO, ensures the window remains small and focused on relevant observations [S1, unofficial].

4.  **Gaussian Insertion/Pruning (Trigger):**
    Upon registering a new keyframe, trigger Gaussian insertion and pruning routines to capture newly visible elements and refine details [S1, unofficial].

**Parameters:**
*   $\tau_{cov}$: Covisibility threshold. Not given in the sources.
*   $\tau_{overlap}$: Overlap coefficient threshold for removal. Not given in the sources.
*   Median Depth: Used to normalize translation magnitude. Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Loopy Motions:** In long-term loops, covisibility may remain high, preventing new keyframe insertion and leading to missing parts of the model or insufficient multi-view constraints [S2]. (Addressed by variants).
*   **Precision:** Covisibility relies on accurate Gaussian visibility tracking; errors in rasterization alpha accumulation can lead to incorrect covisibility estimates [S1, unofficial].

## Subtopics

### Keyframe Selection
A strategy for long-term map consistency that uses an explicit voxel structure to determine keyframe insertion [S2]. Unlike covisibility-based methods, it tests tracked frames against the existing map to count allocatable voxels [S2].
*   **Definition:** Selects keyframes by measuring the ratio of new voxels that would be allocated if the frame were chosen as a keyframe [S2].
*   **Steps:**
    1.  For each successfully tracked frame, perform an intersection test against the existing voxel map to find $N_c$, the number of voxels that would be allocated if the frame is chosen as a new keyframe [S2].
    2.  Let $N_o$ be the number of currently observed voxels in the map [S2].
    3.  Insert a new keyframe if the ratio $p_{kf} = N_c / N_o$ exceeds a threshold [S2].
    4.  Enforce a maximum interval constraint: create a new keyframe if none has been created in the past $N$ frames, preventing missing parts in loopy camera motions [S2].
*   **Parameters:**
    *   $N_c$: Number of voxels that would be allocated if the current frame is chosen as a keyframe [S2].
    *   $N_o$: Number of currently observed voxels in the map [S2].
    *   $N$: Maximum number of frames allowed between keyframe insertions [S2].
*   **When to choose:** When long-term map consistency is critical and the system uses a voxel-based representation (e.g., Vox-Fusion), particularly in environments with loopy trajectories where covisibility metrics might fail to trigger new keyframes [S2].

## Operating characteristics
*   **Time Complexity:** Covisibility calculation is $O(|V_i \cap V_j|)$ or $O(|V_i \cup V_j|)$ depending on implementation, which is significantly faster than full joint optimization of all frames [S1, unofficial]. Voxel-based selection adds $O(N_c)$ cost for intersection testing [S2].
*   **Memory Complexity:** Maintains only a small window $W_k$ of keyframes, keeping memory usage bounded and independent of the total number of captured frames [S1, unofficial].
*   **Strengths:** Reduces computational overhead for online optimization; ensures non-redundant observations; handles occlusions naturally via Gaussian visibility [S1, unofficial].
*   **Limitations:** Covisibility-based methods may fail in loopy motions without additional interval constraints [S2]. Performance depends on accurate visibility estimation [S1, unofficial].
*   **When to use:** Online Gaussian SLAM systems where real-time performance is required and the scene exhibits significant camera motion [S1, unofficial].

## Background
Keyframe management in Gaussian SLAM was introduced to address the infeasibility of jointly optimizing all images from a video stream online [S1, unofficial]. The approach adapts heuristics from traditional Direct Sparse Odometry (DSO) for window management [S1, unofficial]. Variants using voxel-based selection were proposed to improve long-term consistency in voxel-based neural implicit representations [S2].
