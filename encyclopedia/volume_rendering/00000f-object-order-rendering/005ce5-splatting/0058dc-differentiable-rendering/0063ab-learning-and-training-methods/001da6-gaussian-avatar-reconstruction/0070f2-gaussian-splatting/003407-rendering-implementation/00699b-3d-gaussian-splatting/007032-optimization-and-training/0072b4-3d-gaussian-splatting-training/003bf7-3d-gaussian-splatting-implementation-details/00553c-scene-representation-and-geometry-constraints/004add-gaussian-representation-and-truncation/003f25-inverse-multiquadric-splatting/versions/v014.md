# Inverse Multiquadric Splatting

Also called: 3DIQS, Inverse Multiquadric

## Overview
Inverse Multiquadric Splatting replaces the standard Gaussian density function with an inverse multiquadric radial basis function to modify the alpha blending behavior during rendering [S1]. It sets itself apart from the base Gaussian Splatting method by using a function with heavier tails, which can improve the representation of certain geometric structures or reduce artifacts in specific optimization scenarios [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of 3D Gaussians defined by mean $\boldsymbol{\mu}$, 3D covariance $\boldsymbol{\Sigma}$, opacity $\alpha_{base}$, and color. For each pixel/ray intersection, the 2D projected mean $\boldsymbol{\mu}'$ and 2D covariance $\boldsymbol{\Sigma}'_{2 \times 2}$ are computed.
*   **Output:** The final alpha value $\alpha$ for the splat, and gradients for the mean and covariance matrices during backpropagation.

**Data Structures:**
The method operates on the standard 3DGS conic matrix representation for the 2D projection. The conic matrix $\mathbf{C}$ is the inverse of the 2D covariance matrix, often stored in a compact symmetric format. Let $\mathbf{C} = \begin{bmatrix} a & b \\ b & c \end{bmatrix}$, where the entries correspond to the inverse covariance elements. The 2D distance vector is $\mathbf{d} = \mathbf{x} - \boldsymbol{\mu}' = (d.x, d.y)$.

**Parameters:**
*   `correctionFactor`: A scalar multiplier applied to the covariance matrices. Value: $1.38$ [S1].
*   `ellipse_max`: The upper bound for the ellipse term to skip distant splats. Value: $9.0$ [S1].
*   `alpha_max`: The maximum clamped alpha value. Value: $0.99$ [S1].

**Formulas:**
The 3D inverse multiquadric function is defined as [S1]:
$$ f(d_M) = \frac{1}{\frac{1}{\xi} (d_M)^2 + 1} $$
where $d_M \geq 0$. In the implementation, the parameter $\xi$ is absorbed into the correction factor or set such that the term simplifies to the form used in the code. The 2D splat weight $w$ is calculated as [S1]:
$$ w = \frac{1}{\left[ \frac{1}{\xi} (\mathbf{x} - \boldsymbol{\mu}')^T (\boldsymbol{\Sigma}'_{2 \times 2})^{-1} (\mathbf{x} - \boldsymbol{\mu}') + 1 \right]} $$
In the CUDA implementation, the term $\frac{1}{\xi} (\mathbf{x} - \boldsymbol{\mu}')^T (\boldsymbol{\Sigma}'_{2 \times 2})^{-1} (\mathbf{x} - \boldsymbol{\mu}')$ is computed as `ellipse`. The final alpha is [S1]:
$$ \alpha = \min(0.99, w \cdot \alpha_{base}) $$
where $w = \frac{1}{ellipse + 1}$.

**Steps:**
1.  **Covariance Scaling:** Multiply the 3D covariance matrix $\boldsymbol{\Sigma}$ and the projected 2D covariance matrix $\boldsymbol{\Sigma}'_{2 \times 2}$ by `correctionFactor` ($1.38$) [S1].
2.  **Ellipse Calculation:** Compute the quadratic form `ellipse` using the conic matrix entries ($a, b, c$) and the 2D distance vector $\mathbf{d} = (d.x, d.y)$ [S1]:
    $$ ellipse = a \cdot d.x^2 + c \cdot d.y^2 + 2b \cdot d.x \cdot d.y $$
3.  **Boundary Checks:**
    *   If $ellipse \leq 0$, skip the splat [S1].
    *   If $ellipse \geq 9.0$, skip the splat [S1].
4.  **Alpha Computation:** Calculate the weight $G$ (or $w$) and the final alpha [S1]:
    $$ G = \frac{1}{ellipse + 1} $$
    $$ \alpha = \min(0.99, \alpha_{base} \cdot G) $$

**Pseudocode:**
```python
def inverse_multiquadric_forward(con_o, d, alpha_base, correction_factor=1.38):
    """
    con_o: Conic matrix entries (a, b, c, w) where a, b, c form the symmetric 2x2 inverse covariance.
    d: 2D distance vector (dx, dy) from pixel center to gaussian mean.
    alpha_base: The base opacity of the gaussian.
    """
    # 1. Scale covariance (conceptually, affects con_o if derived from cov, 
    # but in the provided code, con_o is already the conic. 
    # The code scales cov2D before inversion to conic. 
    # Here we assume con_o represents the scaled conic.)
    
    # 2. Calculate ellipse term
    a, b, c = con_o.a, con_o.b, con_o.c
    dx, dy = d.dx, d.dy
    
    ellipse = a * dx * dx + c * dy * dy + 2.0 * b * dx * dy
    
    # 3. Boundary checks
    if ellipse <= 0.0 or ellipse >= 9.0:
        return None, None # Skip splat
        
    # 4. Calculate weight and alpha
    G = 1.0 / (ellipse + 1.0)
    alpha = min(0.99, alpha_base * G)
    
    return alpha, G
```

**Edge Cases and Pitfalls:**
*   **Boundary Conditions:** Splats with $ellipse \leq 0$ or $ellipse \geq 9.0$ are skipped. This prevents numerical instability and unnecessary computation for very distant or degenerate projections [S1].
*   **Covariance Scaling:** The correction factor $1.38$ must be applied to the covariance matrices before projection/inversion to ensure the correct shape of the inverse multiquadric function [S1].

## Operating characteristics
*   **Time Complexity:** Similar to standard Gaussian Splatting, as it involves a constant number of arithmetic operations per pixel per Gaussian. The boundary checks may reduce the number of active splats slightly.
*   **Memory Complexity:** No additional memory overhead compared to standard 3DGS, as it uses the same data structures.
*   **Strengths:** Can provide better fitting for certain types of geometry or reduce artifacts compared to Gaussian splatting in specific contexts [S1].
*   **Limitations:** The choice of correction factor and boundary limits is heuristic. It may not generalize as well as Gaussian splatting for all scenes.
*   **When to use:** When standard Gaussian Splatting exhibits artifacts or fails to represent certain features, and when the specific benefits of the inverse multiquadric function are desired [S1].

## Background
Inverse Multiquadric Splatting was introduced in the paper "DARB-Splatting: Generalizing Splatting with Decaying Anisotropic Radial Basis Functions" [S1]. It is part of a family of methods that generalize the radial basis functions used in splatting beyond the standard Gaussian.
