# Frequency Regularization

Also called: Amplitude and Phase Discrepancy Regularization, Improved Optimization via Regularization

## Overview
Frequency Regularization (FR) is a training-time constraint for 3D Gaussian Splatting that minimizes the spectral discrepancy between rendered images and ground truth to alleviate over-reconstruction and improve Gaussian densification [S2]. Unlike standard photometric losses (e.g., L1) which provide small gradients in already well-reconstructed regions, FR increases pixel gradients in over-reconstructed areas, explicitly disentangling frequency components to guide Gaussians toward high-frequency details [S2][S3, unofficial]. It sets itself apart from geometry-based siblings like [Hard and Soft Depth Regularization](9178-hard-and-soft-depth-regularization.md) by operating in the Fourier domain rather than enforcing spatial or depth consistency [S2].

## How it works
**Inputs and Outputs:**
- **Inputs:** Rendered image $\hat{I} \in \mathbb{R}^{H \times W \times C}$, Ground truth image $I \in \mathbb{R}^{H \times W \times C}$, Hyperparameter $\lambda$ (weight for regularization).
- **Outputs:** Regularization loss $\mathcal{L}_{FR}$, updated Gaussian parameters via gradient descent.

**Data Structures:**
- Images are treated as 2D arrays of pixel values.
- Frequency domain representations are complex-valued matrices of size $H \times W$.

**Steps:**
1. **Compute 2D Discrete Fourier Transform (DFT):** Convert both the rendered image $\hat{I}$ and ground truth $I$ into the frequency domain. For a single channel, the DFT $F(u, v)$ is computed as:
   $$ F(u, v) = \sum_{x=0}^{H-1} \sum_{y=0}^{W-1} I(x, y) \cdot e^{-i2\pi(\frac{u}{H}x + \frac{v}{W}y)} $$
   where $(x, y)$ are spatial coordinates, $(u, v)$ are frequency coordinates, and $i$ is the imaginary unit [S2]. This is performed for all channels $C$.

2. **Compute Amplitude and Phase:** For each frequency component $F(u, v)$, calculate the amplitude $|F(u, v)|$ and phase $\angle F(u, v)$:
   $$ |F(u, v)| = \sqrt{\text{Re}(u, v)^2 + \text{Im}(u, v)^2} $$
   $$ \angle F(u, v) = \arctan\left(\frac{\text{Im}(u, v)}{\text{Re}(u, v)}\right) $$
   where $\text{Re}$ and $\text{Im}$ are the real and imaginary components of $F(u, v)$ [S2].

3. **Calculate Discrepancies:** Compute the total amplitude discrepancy $d_a$ and total phase discrepancy $d_p$ between the ground truth ($F$) and rendered ($\hat{F}$) frequency representations:
   $$ d_a = \sqrt{\frac{1}{HW} \sum_{x=0}^{H-1} \sum_{y=0}^{W-1} (|F(u, v)| - |\hat{F}(u, v)|)^2} $$
   $$ d_p = \sqrt{\frac{1}{HW} \sum_{x=0}^{H-1} \sum_{y=0}^{W-1} (\angle F(u, v) - \angle \hat{F}(u, v))^2} $$
   These metrics are averaged across all frequency components and channels [S2].

4. **Compute Loss:** The frequency regularization loss is typically the sum of these discrepancies:
   $$ \mathcal{L}_{FR} = d_a + d_p $$
   [S2].

5. **Optimization:** Add $\mathcal{L}_{FR}$ to the total loss $\mathcal{L}_{total} = \mathcal{L}_{photo} + \lambda \mathcal{L}_{FR}$ and optimize Gaussian parameters (position, scale, rotation, color, opacity) using an optimizer (e.g., Adam) [S2].

**Parameters:**
- $\lambda$: Regularization weight. Not given in the sources.
- Optimizer: Adam [S2].
- Framework: PyTorch [S2].
- Rasterization: Custom CUDA kernels from 3D-GS [S2].

**Edge Cases and Pitfalls:**
- **Over-reconstruction vs. Under-reconstruction:** Naive FR without frequency annealing can bias optimization toward undesirable artifacts and restrict densification [S2].
- **Gradient Vanishing:** In well-reconstructed regions, L1 loss yields small gradients, preventing densification. FR mitigates this by maintaining higher gradients in over-reconstructed regions [S2].
- **Frequency Annealing:** To avoid artifacts, progressive frequency regularization (annealing) is often used, gradually leveraging low-to-high frequencies [S2]. This involves incorporating a low-pass filter $H_l$ and dynamic high-pass filter $H_h$ in Fourier space [S2].

**Pseudocode:**
```python
import torch
import torch.fft

def compute_frequency_regularization_loss(rendered_image: torch.Tensor, ground_truth: torch.Tensor) -> torch.Tensor:
    """
    Computes the Amplitude and Phase Discrepancy Regularization loss.
    
    Args:
        rendered_image: Tensor of shape (H, W, C) or (B, H, W, C)
        ground_truth: Tensor of shape (H, W, C) or (B, H, W, C)
        
    Returns:
        Scalar loss tensor.
    """
    # Ensure inputs are float32
    rendered_image = rendered_image.float()
    ground_truth = ground_truth.float()
    
    # Compute 2D FFT. 
    # torch.fft.fft2 expects input shape (..., H, W). 
    # If input is (B, H, W, C), we need to move C to the last dimension for FFT or handle per-channel.
    # Standard 3D-GS renders RGB, so shape is likely (H, W, 3).
    # We compute FFT for each channel independently or stack them.
    
    # Move channels to last dim if not already, and ensure spatial dims are last for FFT
    # Assuming input is (H, W, C)
    if rendered_image.dim() == 3:
        rendered_image = rendered_image.permute(2, 0, 1) # (C, H, W)
        ground_truth = ground_truth.permute(2, 0, 1)
        
    # Compute FFT
    F_rendered = torch.fft.fft2(rendered_image)
    F_gt = torch.fft.fft2(ground_truth)
    
    # Compute Amplitude and Phase
    # Amplitude: sqrt(Re^2 + Im^2)
    amp_rendered = torch.abs(F_rendered)
    amp_gt = torch.abs(F_gt)
    
    # Phase: arctan2(Im, Re)
    phase_rendered = torch.angle(F_rendered)
    phase_gt = torch.angle(F_gt)
    
    # Compute Discrepancies
    # d_a = sqrt( mean( (amp_gt - amp_rendered)^2 ) )
    # d_p = sqrt( mean( (phase_gt - phase_rendered)^2 ) )
    
    # Note: The source formula uses sum over x,y and divides by HW. 
    # torch.mean computes sum / N.
    
    diff_amp = amp_gt - amp_rendered
    diff_phase = phase_gt - phase_rendered
    
    # Mean squared error for amplitude and phase
    mse_amp = torch.mean(diff_amp ** 2)
    mse_phase = torch.mean(diff_phase ** 2)
    
    d_a = torch.sqrt(mse_amp)
    d_p = torch.sqrt(mse_phase)
    
    # Total Loss
    loss = d_a + d_p
    
    return loss
```

## Subtopics

### [Scale Regularization](9855-scale-regularization.md)
Scale regularization is a training-time constraint used in 3D Gaussian Splatting to prevent the formation of excessively large Gaussians, which can degrade rendering quality, cause aliasing artifacts, and destabilize optimization. It specifically addresses issues arising from unconstrained Gaussian scale growth by penalizing scales that exceed a predefined maximum or geometric resolution threshold. Unlike general isotropic regularization which merely encourages equal scaling in all directions, this method ties the scale limit directly to the geometric resolution of the underlying mesh or the maximum sampling frequency of the scene.

### DWTGS
DWTGS rethinks frequency regularization for sparse-view 3DGS by applying a discrete wavelet transform on the rendered image and penalizing the loss in the wavelet domain to encourage sharper edges [S4, unofficial].

## Operating characteristics
- **Time Complexity:** The addition of 2D FFT and inverse FFT operations increases computational overhead per iteration compared to pure spatial losses. FFT complexity is $O(N \log N)$ where $N=HW$.
- **Memory Complexity:** Requires storing frequency domain representations of the rendered and ground truth images, adding $O(HW)$ memory overhead per channel.
- **Measured Performance:** In scenes like 'Bicycle', FR significantly increases pixel gradients within over-reconstruction regions compared to L1 loss, enabling better adaptive densification [S2].
- **Strengths:** Effectively alleviates over-reconstruction (floaters) and improves Gaussian densification by revealing regions that need more detail [S2]. Pushes Gaussians toward high-frequency regions [S3, unofficial].
- **Limitations:** Naive adoption without frequency annealing can lead to restricted densification and undesirable artifacts [S2].
- **When to use:** When the scene suffers from over-reconstruction or "floaters" and standard densification fails to remove them.
- **When not to use:** When computational resources are extremely limited and the overhead of FFT is prohibitive, or if the scene is very low frequency and simple photometric loss suffices.

## Background
Frequency Regularization was introduced as part of the FreGS method to improve 3D Gaussian Splatting optimization [S2]. It addresses the limitation of standard pixel-wise L1 loss, which cannot differentiate between over-reconstructed and well-reconstructed regions, leading to redundant Gaussians [S2]. The method builds on the observation that frequency components can capture different information (amplitude for magnitude, phase for structure) [S2]. It is cited in surveys on 3D Gaussian Splatting as a key direction for improving optimization via additional regularization [S1].
