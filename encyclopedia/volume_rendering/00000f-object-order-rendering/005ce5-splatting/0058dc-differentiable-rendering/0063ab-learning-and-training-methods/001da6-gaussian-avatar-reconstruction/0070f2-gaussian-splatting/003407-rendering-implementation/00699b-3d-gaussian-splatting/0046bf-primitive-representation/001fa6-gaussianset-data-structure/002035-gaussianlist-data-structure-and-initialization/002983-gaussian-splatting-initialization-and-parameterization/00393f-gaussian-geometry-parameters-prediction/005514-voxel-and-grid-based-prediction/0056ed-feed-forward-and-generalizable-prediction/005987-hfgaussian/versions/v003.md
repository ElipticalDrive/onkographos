# HFGaussian

Also called: Human Feature Gaussian

## Overview
HFGaussian is a generalizable, human-centric 3D Gaussian Splatting framework that estimates 3D human avatars with integrated biomechanical features (3D skeleton, 3D keypoints, dense pose) and 3D pose in real time from sparse input images, without per-subject fine-tuning [S1]. It builds on [Feed-forward and Generalizable Prediction](15832-feed-forward-and-generalizable-prediction.md) by introducing "feature splatting" to decouple human feature representation from photometric Gaussian parameters, allowing separate optimization for features with different spatial frequencies [S1]. Unlike methods relying on parametric body models (SMPL/STAR) or direct parameterization of Gaussians with features, HFGaussian learns additional feature parameters for each Gaussian, decoded after rendering, enabling simultaneous real-time novel view synthesis, pose estimation, and feature rendering [S1].

## How it works
**Inputs and Outputs:**
- **Inputs:** Sparse source views $I_l, I_r$ (RGB images, $H \times W$) of a human subject.
- **Outputs:** Novel view RGB images, 3D pose (19 keypoints), and human features (continuous surface embeddings/dense pose) [S1].

**Data Structures:**
- **3D Gaussians:** A set $G = \{X, c, r, s, \alpha, f\}$ [S1].
  - $X \in \mathbb{R}^3$: 3D position.
  - $c \in \mathbb{R}^3$: RGB color.
  - $r \in \mathbb{R}^4$: Rotation (quaternion).
  - $s \in \mathbb{R}^3$: Scaling.
  - $\alpha \in \mathbb{R}$: Opacity.
  - $f \in \mathbb{R}^k$: Human feature vector (continuous surface embedding) [S1].
- **Gaussian Parameter Maps:** Pixel-wise maps $G(x) = \{M_p(x), M_c(x), M_r(x), M_s(x), M_\alpha(x), M_f(x)\}$ for foreground pixel coordinates $x$ [S1].
  - $M_p$: Position map.
  - $M_c$: Color map.
  - $M_r, M_s, M_\alpha$: Rotation, scaling, opacity maps.
  - $M_f$: Feature map [S1].

**Algorithm Steps:**

1.  **Depth Estimation:**
    - Select two nearest source views $I_l, I_r$ [S1].
    - Feed $I_l, I_r$ into a shared image encoder $\epsilon_{img}$ to generate multiscale image features $f_l^s, f_r^s$ [S1].
    - Generate a cost volume $C$ by correlating $f_l^s$ and $f_r^s$ [S1].
    - Use an iterative update mechanism on $C$ to estimate depth maps $D_l, D_r$ [S1].
    - Encode $D_l, D_r$ using an encoder $\epsilon_{depth}$ [S1].

2.  **Gaussian Parameter Prediction:**
    - Combine encoded depth features and image features to generate a Gaussian feature map $\Gamma$ via a U-Net-like decoder $\epsilon_{params}$ [S1]:
      $$ \Gamma = \epsilon_{params}(\epsilon_{img}(I) \oplus \epsilon_{depth}(I)) $$
      where $\oplus$ is concatenation [S1].
    - Use four separate convolutional prediction heads on $\Gamma$ to estimate:
      - Rotation $M_r$, Scaling $M_s$, Opacity $M_\alpha$ [S1].
      - Human Feature $M_f$:
        $$ M_f = \text{Sigmoid}(h_f(\Gamma(x))) $$
        where $h_f$ is the feature head [S1].
    - Map 2D pixel coordinates $x$ to 3D position $X$ using predicted depth and camera parameters via $M_p$ [S1].
    - Get color $c$ directly from source images via $M_c$ [S1].
    - Construct the set of 3D Gaussians $G$ [S1].

3.  **Pose Regression:**
    - Generate point clouds $P_l, P_r$ from $D_l, D_r$ and camera parameters [S1].
    - Extract human point clouds using 2D masks [S1].
    - Combine point clouds into a single context [S1].
    - Randomly sample 2048 points to form point cloud $P_c$ [S1].
    - Input $P_c$ into a pose regression network (DGCNN + PointNet) to estimate 3D pose (19 keypoints) [S1].

4.  **Feature Splatting and Rendering:**
    - **Feature Rendering:**
      - Splat Gaussian features $f_i$ into the image plane using alpha composition to get blended feature vectors $f_p$ [S1]:
        $$ f_p = \sum_{i \in N} \left( f_i \alpha_i' \prod_{j=1}^{i-1} (1 - \alpha_j') \right) $$
        where $\alpha_i' = \alpha_i \cdot \text{2D Gaussian}$, and $N$ is the set of splatted Gaussians [S1].
      - Decode $f_p$ using an MLP (two linear layers with ReLU, final sigmoid) to render continuous surface embeddings [S1].
    - **Color Rendering:**
      - Project 3D Gaussians to 2D using view matrix $W$ and Jacobian $J$ of the affine approximation of the projective transform [S1].
      - Calculate 2D covariance $\Sigma'$:
        $$ \Sigma' = J W \Sigma W^T J^T $$
        where $\Sigma$ is the 3D covariance matrix derived from $r$ and $s$ [S1].
      - Render final pixel colors $C$ using alpha blending [S1]:
        $$ C = \sum_{i \in N} \left( c_i \alpha_i' \prod_{j=1}^{i-1} (1 - \alpha_j') \right) $$
        where $c_i$ is the learned color [S1].

**Training:**
- **Stage 1:** Train depth estimator module on source views for 40,000 iterations [S1].
- **Stage 2:** Jointly train Gaussian parameter estimator, feature estimator MLP, and 3D pose estimator for 100,000 iterations [S1].
- **Loss Function:**
  $$ L = L_{image} + L_{depth} + L_{pose} + L_{feature} $$
  - $L_{image} = \beta L_{MAE} + \gamma L_{SSIM}$ with $\beta=1.6, \gamma=0.4$ [S1].
  - $L_{depth} = \sum_{t=1}^{T} \mu^{T-t} \|d_{gt} - d_t\|_1$ with $\mu=0.9$ [S1].
  - $L_{pose}$: L2 loss between ground truth and estimated 3D keypoints [S1].
  - $L_{feature}$: L1 loss between ground truth and predicted human features [S1].

**Parameters:**
- Learning rate: $2 \times 10^{-4}$ [S1].
- Weight decay: $1 \times 10^{-5}$ [S1].
- Batch size: 4 [S1].
- Resolution: $512 \times 512$ [S1].
- Source views: 8 images at 45-degree intervals [S1].
- Target views: 3 random viewpoints [S1].
- Keypoints: 19 (nose, neck, shoulders, elbows, wrists, pelvis, hips, knees, ankles, eyes, ears) [S1].

## Operating characteristics
- **Speed:** Renders at 25 FPS [S1].
- **Performance:** Achieves a PSNR of 32.43 on novel view synthesis, closely matching GPS-Gaussian's 32.55 [S1].
- **Strengths:** Real-time generalizable estimation of RGB, 3D pose, and dense pose without per-subject optimization; integrates biomechanical features directly [S1].
- **Limitations:** Relies on the accuracy of the initial depth estimation module; performance is contingent on the quality of the sparse input views [S1].
- **When to use:** Applications requiring real-time 3D human avatars with structural/biomechanical data (AR/VR, medical) from sparse inputs [S1].
- **When not to use:** When per-subject optimization is acceptable and higher photometric fidelity is prioritized over pose/feature integration speed [S1].

## Background
HFGaussian was introduced by Arnab Dey, Cheng-You Lu, Andrew I. Comport, Jean Martinet, Srinath Sridhar, and Chin-Teng Lin in arXiv:2411.03086v1 on 5 Nov 2024 [S1]. It addresses the limitations of classical methods (requiring markers/parametric models like SMPL/STAR) and existing 3DGS methods (requiring per-subject optimization or lacking biomechanical features) [S1]. It uses GPS-Gaussian as a backbone for generalization [S1]. It is implemented in PyTorch with the AdamW optimizer [S1].
