# LangSplat

Also called: Feature 3DGS
## Overview
LangSplat (also known as Feature 3DGS) enables real-time, open-vocabulary semantic segmentation by rendering high-dimensional feature maps from 3D Gaussians that are compared against text embeddings from CLIP [S1, unofficial]. It pioneers the distillation of 2D vision-model features into a 3D representation by attaching a feature vector $\mathbf{f}_i$ to each Gaussian, allowing the resulting 2D feature map to be decoded or matched against text queries without retraining the segmentation head [S1, unofficial].
## How it works
### Inputs and outputs
*   **Inputs**: 3D Gaussian attributes (position, covariance, opacity $\alpha_i$, color) and a high-dimensional semantic feature vector $\mathbf{f}_i \in \mathbb{R}^d$ for each Gaussian [S1, unofficial]. Text labels or category names for querying [S2].
*   **Outputs**: A 2D feature map $\mathbf{F} \in \mathbb{R}^{H \times W \times d}$ and, optionally, semantic segmentation masks or selection scores for 3D Gaussians [S1, unofficial][S2].

### Data structures
*   **Gaussian Attributes**: Each Gaussian $i$ stores $\mathbf{f}_i$ [S2]. The dimension $d$ is typically 512 (matching CLIP ViT-L/16) or a compressed dimension (e.g., 128) if a speed-up module is used [S2].
*   **Text Embeddings**: Text features $t_i \in \mathbb{R}^{512}$ for $C$ categories, encoded using a CLIP text encoder [S2].

### Rendering Pipeline
The rendering of the feature map follows the standard differentiable alpha-blending accumulation defined in the parent article [Semantic and Language Embeddings](8130-semantic-and-language-embeddings.md) [S1, unofficial]. For a pixel $p$, the rendered feature vector $\mathbf{F}(p)$ is:

$$
\mathbf{F}(p) = \sum_{i \in \mathcal{O}_p} \mathbf{f}_i \cdot \alpha_i \cdot \prod_{j=1}^{i-1} (1 - \alpha_j)
$$

where $\mathcal{O}_p$ is the set of Gaussians sorted front-to-back covering pixel $p$ [S1, unofficial][S2].

### Feature Processing and Segmentation (LSeg Variant)
To perform semantic segmentation, the rendered feature map is processed as follows [S2]:
1.  **Reshape**: The rendered feature map of shape $(d, H, W)$ (e.g., $512 \times 360 \times 480$) is reshaped to $(H \times W, d)$ to form the image feature matrix [S2].
2.  **Text Encoding**: Text labels are encoded into features $t_i \in \mathbb{R}^{512}$ for $C$ categories using a CLIP text encoder [S2].
3.  **Alignment**: Matrix multiplication is applied between the image feature matrix and the text feature matrix to align pixel-level features with text queries [S2].
4.  **Regularization**: LSeg spatial regularization blocks are applied to the aligned features to produce the final semantic segmentation mask [S2].

### Language-Guided Semantic Scoring
For 3D Gaussian selection (e.g., for editing), semantic scores are calculated per Gaussian [S2]:
1.  **Text Encoding**: Encode text labels using a CLIP text encoder to obtain text features $t_i \in \mathbb{R}^{512}$ for $C$ categories [S2].
2.  **Inner Product**: Calculate the inner product between the text feature and the 3D Gaussian's semantic feature $\mathbf{f}_i$ [S2].
3.  **Softmax**: Apply a softmax function to the inner product results to obtain semantic scores [S2].

The scores $S \in \mathbb{R}^{N \times C}$ are obtained via:
$$
S_{i,c} = \text{softmax}(\mathbf{f}_i \cdot t_c)
$$
where $N$ is the number of Gaussians and $C$ is the number of categories [S2].

### Selection
Queried by a text label $l$ (or list of labels), selection is performed via [S2]:
*   **Soft Selection**: Based on the category $l$, select the corresponding column $score_l = [s_{1l}, s_{2l}, \dots, s_{Nl}]$ [S2]. Apply binary thresholding: for any $i$ such that $s_{il} \geq t_h$, set position $i$ to 1 (selected); otherwise 0 [S2].
*   **Hard Selection**: Implicitly defined by choosing a single category column and thresholding [S2].

### Parameters
*   **Feature Dimension**: 512 for direct rendering with CLIP ViT-L/16; 128 if using a Speed-up Module with upsampling [S2].
*   **Optimizer**: Adam with learning rate $1e-3$ for main attributes; $1e-4$ for the feature decoder network in the Speed-up Module [S2].
*   **Ground Truth Feature Size**: $360 \times 480$ with dimension 512 for LSeg preparation [S2].

### Edge cases and pitfalls
*   **Precision**: High-dimensional feature vectors (512) increase memory usage [S2]. Using a compressed dimension (128) requires a decoder network, which must be optimized separately [S2].
*   **Boundary**: The number of categories $C$ must match the number of text features encoded [S2].
*   **Degenerate Input**: If no Gaussians cover a pixel, $\mathbf{F}(p) = \mathbf{0}$ [S1, unofficial].
*   **Encoder Conflict**: The source specifies ViT-L/16 for the text encoder in one section, but ViT-B/32 in another [S2]. Implementers should verify the target encoder version or support both [G].

## Subtopics

### LSeg Feature Processing
Preparation of ground-truth features using CLIP ViT-L/16 image encoder (size $360 \times 480$, dim 512) and a CLIP text encoder [S2]. During inference, the rendered feature (shape $512 \times 360 \times 480$) is reshaped to $(360 \times 480, 512)$ for matrix multiplication with text features (shape $C, 512$) to align pixel-level features with text queries [S2]. Chosen when LSeg spatial regularization is required for segmentation [S2]. The source specifies ViT-L/16 for the text encoder in one section, but ViT-B/32 in another [S2].

### Language-Guided Semantic Scoring
Calculation of semantic scores for each 3D Gaussian by comparing its semantic feature with text features from a CLIP encoder [S2]. Text labels are encoded using a CLIP text encoder to obtain $t_i \in \mathbb{R}^{512}$ for $C$ categories [S2]. Scores $S \in \mathbb{R}^{N \times C}$ are obtained via softmax of the inner product [S2]. Chosen when 3D Gaussian-level selection (e.g., for editing) is needed rather than pixel-level segmentation [S2].

## Operating characteristics
*   **Time Complexity**: Real-time rendering is enabled by the speed of the 3DGS rasterizer [S1, unofficial]. Feature processing (matrix multiplication) is $O(H \cdot W \cdot d \cdot C)$ [S2].
*   **Memory Complexity**: Proportional to $N \cdot d$ for storing Gaussian features, where $d=512$ or $128$ [S2].
*   **Strengths**: Enables open-vocabulary semantic segmentation in real time [S1, unofficial]. Supports 3D Gaussian editing via text queries [S2].
*   **Limitations**: Performance is limited by the teacher encoder's capability (e.g., CLIP) [S2]. High-dimensional features increase memory usage [S2].
*   **When to use**: When real-time, open-vocabulary semantic segmentation or text-guided 3D editing is required [S1, unofficial][S2].
*   **When not to use**: When only photometric rendering is needed without semantic understanding [S1, unofficial].

## Background
LangSplat (Feature 3DGS) was introduced to pioneer the distillation of 2D vision-model features into a 3D representation [S1, unofficial]. It leverages the speed of the 3DGS rasterizer to render feature maps that are compared against text embeddings from CLIP, enabling open-vocabulary semantic segmentation in real time [S1, unofficial]. The method builds on 3D Gaussian Splatting by adding a high-dimensional feature vector $\mathbf{f}_i$ to each Gaussian [S1, unofficial].
