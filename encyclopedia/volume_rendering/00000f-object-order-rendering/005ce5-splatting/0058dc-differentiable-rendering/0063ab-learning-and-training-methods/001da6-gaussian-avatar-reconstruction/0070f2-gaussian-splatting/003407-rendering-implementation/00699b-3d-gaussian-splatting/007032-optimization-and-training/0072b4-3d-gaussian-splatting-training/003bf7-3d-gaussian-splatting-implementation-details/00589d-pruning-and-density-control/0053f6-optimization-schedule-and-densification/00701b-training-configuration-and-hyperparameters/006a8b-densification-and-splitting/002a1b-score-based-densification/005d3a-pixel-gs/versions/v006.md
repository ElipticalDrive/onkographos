# Pixel-GS

Also called: AbsGS / Pixel-GS Densification, Better densification triggers, PGS, Pixel-GS Densification, Pixel-aware and Depth-scaled Gradient Densification, Pixel-based densification, Projected area gradient scaling

## Overview
Pixel-GS is a densification strategy for 3D Gaussian Splatting that modifies the gradient-based splitting signal to account for the spatial footprint of each Gaussian primitive [S2][S3, unofficial]. It addresses the baseline's tendency to under-densify regions by scaling the positional gradient by the number of pixels a Gaussian influences and applying a depth-dependent scaling factor to suppress floaters [S1][S4, unofficial]. It recovers detail the baseline misses without simply carpeting the scene in more blobs [S5, unofficial].

## How it works
Pixel-GS operates within the densification loop of 3D Gaussian Splatting training [G]. It replaces the standard densification trigger (average magnitude of positional gradient) with a pixel-weighted, depth-aware metric [S3, unofficial].

**Inputs and Outputs:**
- Input: Current set of 3D Gaussians $\mathcal{G}$, camera poses $\{C_i\}$, input images $\{I_i\}$, and accumulated positional gradients $\nabla_{\mathbf{p}}$ for each Gaussian's position $\mathbf{p}$ [G].
- Output: A subset of Gaussians selected for splitting based on the modified score [S1].

**Data Structures:**
- Each Gaussian $g_j$ maintains:
  - Position $\mathbf{p}_j \in \mathbb{R}^3$
  - Covariance $\Sigma_j$ (or scale/rotation parameters)
  - Opacity $\alpha_j$
  - Accumulated positional gradient magnitude
  - Pixel coverage count $N_{pix, j}$ (number of pixels influenced by $g_j$ across all views) [G]

**Steps:**
1. **Render and Backpropagate:** Render the scene from all training viewpoints. Compute the photometric loss $\mathcal{L}$ and backpropagate to obtain positional gradients $\nabla_{\mathbf{p}_j}$ for each Gaussian $g_j$ [G].
2. **Accumulate Pixel Influence:** For each Gaussian $g_j$, count the number of pixels $N_{pix, j}$ it contributes to in the rendered images across all viewpoints [S1][S4, unofficial].
3. **Compute Depth-Aware Gradient Score:** Calculate the densification score $S_j$ for each Gaussian. The score scales the absolute positional gradient by the pixel coverage and applies a distance-dependent factor to suppress floaters in the background [S1, S2][S3, unofficial].
   $$ S_j = \left( \sum_{v \in \text{views}} |\nabla_{\mathbf{p}_j^{(v)}}| \right) \cdot N_{pix, j} \cdot f(d_j) $$
   Where:
   - $|\nabla_{\mathbf{p}_j^{(v)}}|$ is the magnitude of the positional gradient for Gaussian $j$ in view $v$ [S3, unofficial].
   - $N_{pix, j}$ is the total number of pixels influenced by $g_j$ across all views [S1].
   - $d_j$ is the depth (distance to camera) of Gaussian $j$ [S1].
   - $f(d_j)$ is a depth-dependent scaling factor designed to suppress densification in distant regions to prevent floaters [S1][S4, unofficial].
4. **Select for Splitting:** Compare $S_j$ against a threshold or select the top-$k$ Gaussians with the highest scores [G]. These Gaussians are candidates for splitting [S1].
5. **Split:** For each selected Gaussian $g_j$: Clone $g_j$ to create two new Gaussians, perturb the position of the clone slightly, and adjust the scale and opacity of the parent and child to maintain coverage [G] (standard 3DGS splitting procedure).

**Pseudocode:**
```python
def compute_pixel_gs_score(gaussians, views):
    scores = {}
    for g in gaussians:
        pixel_count = 0
        grad_sum = 0.0
        for view in views:
            pixel_count += count_rasterized_pixels(g, view)
            grad_sum += abs(g.grad_position[view])
        depth_factor = 1.0 / g.depth if g.depth > 0 else 1.0
        scores[g.id] = grad_sum * pixel_count * depth_factor
    return scores

def densify_pixel_gs(gaussians, scores, threshold=None, top_k=None):
    candidates = []
    if top_k is not None:
        candidates = sorted(scores.items(), key=lambda x: x[1], reverse=True)[:top_k]
    elif threshold is not None:
        candidates = [(gid, score) for gid, score in scores.items() if score >= threshold]
    for gid, score in candidates:
        g = gaussians[gid]
        clone = g.clone()
        clone.position += random_perturbation()
        g.scale *= 0.5
        g.opacity *= 0.5
        gaussians.append(clone)
```

**Parameters:**
- Threshold for splitting: Not given in the sources. [G] Typically a percentile-based threshold or a fixed count.
- Depth scaling factor $f(d_j)$: Not given in the sources. [G] Inverse depth is a common heuristic.

**Edge Cases and Pitfalls:**
- **Precision:** Summing gradients across views can lead to large values for Gaussians visible in many views. Normalization may be required if scores are compared across different training steps [G].
- **Boundaries:** Gaussians at the edge of the scene may have lower $N_{pix, j}$ due to partial visibility, potentially leading to under-densification at boundaries [G].
- **Degenerate Input:** If a Gaussian has zero gradient, it will not be split, which is correct behavior [G].

## Subtopics

### [PixelGS Densification Criteria](9689-pixelgs-densification-criteria.md)
Modifies the gradient-based densification strategy to account for the spatial footprint of each Gaussian primitive. It scales the positional gradient by the number of pixels a Gaussian influences and applies a depth-dependent scaling factor to encourage densification in background regions while suppressing it in the foreground. This approach recovers detail the baseline misses without simply carpeting the scene in more blobs.

## Operating characteristics
- **Time Complexity:** The additional cost is proportional to the number of Gaussians and views, as pixel coverage must be tracked and gradients summed [G]. This is negligible compared to the rendering and backpropagation steps [G].
- **Memory Complexity:** Requires storing $N_{pix, j}$ and accumulated gradients for each Gaussian [G]. This is $O(N)$ where $N$ is the number of Gaussians [G].
- **Strengths:** Recovers detail that the baseline misses by weighting gradients by pixel coverage [S3, unofficial]. Suppresses floaters via depth scaling [S1].
- **Limitations:** Higher number of Gaussians increases memory usage and potentially rendering time if not optimized [G].
- **When to use:** When high reconstruction quality is prioritized over model size and rendering speed [G].
- **When not to use:** When memory or rendering speed is constrained, or when the scene is simple and the baseline is sufficient [G].

## Background
Pixel-GS was introduced as part of the evolution of 3D Gaussian Splatting densification strategies [S1]. It differs from the original baseline by changing the densification signal from the average magnitude of the positional gradient to a sum of absolute gradients weighted by pixel coverage [S3, unofficial]. It is related to AbsGS, which also uses absolute gradients but without the pixel coverage weighting [S2]. The method is cited in recent surveys of 3D Gaussian Splatting advancements [S1].
