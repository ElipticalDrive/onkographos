# Appearance Feature Initialization and Training Schedule

Also called: Appearance feature initialization, Training schedule with appearance features

## Overview
This method defines the temporal schedule for introducing and initializing appearance features within a 3D Gaussian Splatting optimization pipeline, specifically within the context of optimized minimal implementations like Mini-Splatting [S1]. It addresses the problem of balancing training stability with the capacity to model complex appearance variations by delaying the introduction of appearance parameters until the geometric structure (scale and rotation) has stabilized. It sets itself apart from standard Gaussian Splatting by decoupling the initialization of static and view-dependent appearance features from the initial scene setup, instead deriving static features from intermediate training states [S1].

## How it works
The method operates on a fixed training schedule of 30,000 iterations. It manages the lifecycle of Gaussian parameters, specifically introducing appearance features at iteration 15,000 and applying quantization in the final phase.

**Inputs and Outputs:**
*   **Input:** A set of 3D Gaussians with initialized positions, covariances (scale/rotation), and initial colors. The current iteration count $t$.
*   **Output:** Updated Gaussian parameters including appearance features and optimized codebooks for quantization.

**Data Structures:**
*   **Appearance Features:** A tensor of shape $(N, D)$, where $N$ is the number of Gaussians and $D=3$ is the feature dimension [S1].
*   **Static Appearance Features:** Initialized from trained SH DC coefficients.
*   **View-Dependent Appearance Features:** Initialized as zero vectors.
*   **SVQ Codebooks:** Fixed indices from K-means clustering; optimized codebooks for Scale, Rotation, and Appearance.

**Steps:**

1.  **Iterations 0–14,999: Geometry-Only Training**
    *   Train scale and rotation parameters from the initial iteration [S1].
    *   Do not train appearance features.

2.  **Iteration 15,000: Appearance Feature Introduction**
    *   Introduce appearance features into the optimization [S1].
    *   **Static Feature Initialization:** Initialize the static appearance features using the spherical harmonics DC coefficients that have been trained up to iteration 15,000. Let $c_{DC}^{(t)}$ be the DC coefficient at iteration $t$. The static feature $a_{static}$ is set as:
        $$ a_{static} = c_{DC}^{(15000)} $$
    *   **View-Dependent Feature Initialization:** Initialize view-dependent appearance features as zero vectors:
        $$ a_{view} = \mathbf{0} $$

3.  **Iterations 15,001–19,999: Appearance Training**
    *   Optimize both static and view-dependent appearance features alongside geometry.

4.  **Iteration 20,000: Simplification with Local Distinctiveness**
    *   Run the simplification process (pruning/densification) [S1].
    *   Incorporate Local Distinctiveness (LD) scoring with factor $\lambda = 2$ [S1].
    *   The LD score $L_i$ for Gaussian $i$ typically influences the decision to prune or split based on its uniqueness relative to neighbors, weighted by $\lambda$.

5.  **Iterations 20,001–28,999: Continued Training**
    *   Continue optimizing all parameters including appearance features.

6.  **Iterations 29,000–29,999: Sub-Vector Quantization (SVQ) Optimization**
    *   Apply SVQ to per-Gaussian features [S1].
    *   Use fixed K-means indices (computed once prior to this phase) and optimize only the codebooks [S1].
    *   **Bit Allocations:**
        *   Scale: Length 1, 26 codes per sub-vector.
        *   Rotation: Length 2, 29 codes per sub-vector.
        *   Appearance features: Length 2, 210 codes per sub-vector [S1].
    *   The length 1 SVQ for scale acts as scalar quantization, dynamically learning the quantization range via codebooks [S1].

**Pseudocode:**

```python
def train_gaussian_splatting_schedule(gaussians, images, cameras, total_iterations=30000):
    # Initialization phase
    gaussians.init_scale_rotation()
    # Appearance features not yet added to optimization
    
    for t in range(total_iterations):
        # Render and compute loss
        rendered_image = render(gaussians, cameras[t % len(cameras)])
        loss = compute_loss(rendered_image, images[t % len(images)])
        
        if t < 15000:
            # Phase 1: Geometry only
            optimize(gaussians.scale, gaussians.rotation, loss)
            
        elif t == 15000:
            # Phase 2: Introduce Appearance
            # Initialize static features from current SH DC coefficients
            gaussians.static_appearance = gaussians.sh_dc_coefficients
            # Initialize view-dependent features as zeros
            gaussians.view_dependent_appearance = zeros_like(gaussians.sh_dc_coefficients)
            # Add appearance parameters to optimizer
            optimizer.add_parameters(gaussians.static_appearance)
            optimizer.add_parameters(gaussians.view_dependent_appearance)
            
        elif t == 20000:
            # Phase 3: Simplification with Local Distinctiveness
            # Lambda factor for LD scoring
            lambda_ld = 2
            simplify_gaussians(gaussians, lambda_ld=lambda_ld)
            
        elif t >= 29000:
            # Phase 4: SVQ Optimization
            # Indices are fixed from prior K-means
            # Only optimize codebooks
            optimize_codebooks(gaussians, lambda_scale=26, lambda_rot=29, lambda_appearance=210)
            
        # Standard optimization step for active parameters
        optimizer.step()
        optimizer.zero_grad()
```

## Subtopics

### [Appearance Embedding](14693-appearance-embedding.md)
Associates each training image with a unique learnable vector to model appearance variations such as lighting changes and shadows. It sets itself apart from standard Gaussian Splatting by decoupling appearance from the static 3D geometry, allowing the radiance field to adapt to per-image illumination conditions without altering the underlying Gaussian parameters.

## Operating characteristics
*   **Time Complexity:** The method adds minimal computational overhead during the first 15,000 iterations. The introduction of appearance features increases memory usage and gradient computation cost from iteration 15,000 onwards. The SVQ phase (29K–30K) involves codebook optimization but uses fixed indices, reducing the search space compared to full quantization training [S1].
*   **Memory Complexity:** Memory usage increases at iteration 15,000 when appearance features (dimension $D=3$) are added to each Gaussian [S1].
*   **Hardware:** Experiments were conducted on an NVIDIA RTX 4090 [S1].
*   **Framework:** Implemented within the Mini-Splatting framework [S1].
*   **Strengths:** Improves training stability by allowing geometry to converge before introducing appearance complexity. The delayed initialization prevents early-stage instability from appearance parameters.
*   **Limitations:** Requires a fixed total iteration count (30K) for the schedule to be effective. The simplification step at 20K is critical and sensitive to the $\lambda=2$ factor [S1].

## Background
This schedule originates from the "Optimized Minimal 3D Gaussian Splatting" paper [S1]. It was developed to enhance training efficiency and reconstruction quality by carefully managing the introduction of appearance parameters and applying quantization techniques in the final stages of training. The method builds on the standard 3D Gaussian Splatting framework but introduces specific temporal controls for parameter optimization.
