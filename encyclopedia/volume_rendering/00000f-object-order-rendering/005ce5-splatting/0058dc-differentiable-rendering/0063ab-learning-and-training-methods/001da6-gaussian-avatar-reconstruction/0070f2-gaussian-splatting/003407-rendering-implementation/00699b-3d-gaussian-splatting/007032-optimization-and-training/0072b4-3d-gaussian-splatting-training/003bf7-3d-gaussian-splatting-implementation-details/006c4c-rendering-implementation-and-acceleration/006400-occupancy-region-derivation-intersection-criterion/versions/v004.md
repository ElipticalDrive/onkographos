# Occupancy Region Derivation & ϵ-Intersection Criterion

Also called: Adaptive Threshold Intersection, Elliptic Occupancy Region

## Overview
This method defines a robust geometric intersection test between 3D Gaussian splats by deriving an elliptic occupancy region $\Omega_i$ from the Gaussian kernel's covariance and opacity, rather than relying on strict binary overlap of infinite support. It solves the problem of robustly determining whether two splats $G_i$ and $G_j$ interact for culling or sorting purposes, avoiding false negatives from minor misalignments or numerical precision issues. It differs from standard bounding-box culling by using a shape-aware elliptic boundary and an $\epsilon$-tolerance for contact detection, providing a balance between geometric accuracy and computational efficiency.

## How it works

### Inputs and Outputs
**Inputs:**
*   Set of $N$ 3D Gaussians $\{G_i\}_{i=1}^N$. Each $G_i$ is defined by mean $p_i$, rotation matrix $R_i = [r_1, r_2, r_3]$, scale parameters $\sigma_1, \sigma_2$, opacity $\alpha_i$, and normal $n_i$ [S1].
*   Intersection tolerance $\epsilon > 0$ [S1].
*   Minimum rendering contribution threshold $c = 1/255$ [S1].
*   Adaptive threshold parameter $\bar{V}_{ip}$ (passed through a sigmoid) [S1].

**Outputs:**
*   For any pair $(i, j)$, a boolean indicating intersection: True if $\delta_{ij} \le \epsilon$, False otherwise [S1].
*   The elliptic occupancy region $\Omega_i$ definition for each Gaussian [S1].

### Data Structures
The method operates on the standard Gaussian attributes defined in [Rendering Implementation and Acceleration](21069-rendering-implementation-and-acceleration.md). No additional complex data structures are required for the core definition, though practical implementation may use spatial hashing or fixed-radius search to accelerate pair queries [S1].

### Steps and Formulas

1.  **Compute Adaptive Threshold $T_i$**
    Calculate the threshold $T_i$ that defines the boundary of the occupancy region based on opacity and an adaptive value:
    $$
    T_i := \max \left( \bar{V}_{ip}, \ln \frac{c}{\alpha_i} \right)
    $$
    where $\bar{V}_{ip}$ is the adaptive threshold, $\alpha_i$ is the opacity, and $c = 1/255$ [S1]. Note that entries with $\alpha_i < c$ are discarded, ensuring $\lambda_i$ is strictly positive [S1].

2.  **Derive Shape Parameter $\lambda_i$**
    Compute the squared Mahalanobis distance threshold:
    $$
    \lambda_i := -2 \ln(T_i)
    $$
    [S1]

3.  **Define Elliptic Occupancy Region $\Omega_i$**
    The region $\Omega_i$ is the set of points $x$ satisfying the Gaussian kernel inequality within the plane orthogonal to the normal. In the local coordinate system $\xi = R_i^\top (x - p_i) = (\xi_1, \xi_2, 0)^\top$, the condition is:
    $$
    \frac{\xi_1^2}{\sigma_1^2} + \frac{\xi_2^2}{\sigma_2^2} < \lambda_i
    $$
    Equivalently, in global coordinates using the Moore–Penrose pseudoinverse $\Sigma_i^+$ of the rank-2 covariance matrix $\Sigma_i$:
    $$
    (x - p_i)^\top \Sigma_i^+ (x - p_i) < \lambda_i, \quad \xi_3 = 0
    $$
    [S1]
    
    Parametrically, $\Omega_i$ is expressed as:
    $$
    \Omega_i = \left\{ p_i + \sqrt{\lambda_i} \rho (\sigma_1 \cos \theta \, r_1 + \sigma_2 \sin \theta \, r_2) \mid \rho \in [0, 1), \theta \in (0, 2\pi] \right\}
    $$
    where $r_1, r_2$ are the orthonormal in-plane directions from $R_i$ [S1].

4.  **Compute Normal-wise Offset $\delta_{ij}$**
    To determine intersection between $\Omega_i$ and $\Omega_j$, define the normal-wise offset $\delta_{ij}$ as the minimum translation distance $t$ along the normal $n_i$ required for $\Omega_j$ to touch $\Omega_i$:
    $$
    \delta_{ij} := \inf_{t \in \mathbb{R}} |t| \quad \text{such that} \quad \Omega_i \cap (\Omega_j - t n_i) \neq \emptyset
    $$
    [S1]
    
    If the splats already intersect, $\delta_{ij} = 0$. If no translation along $n_i$ can produce contact, $\delta_{ij} = +\infty$ [S1].

5.  **Evaluate Intersection**
    Declare that $G_i$ and $G_j$ intersect if:
    $$
    \delta_{ij} \le \epsilon
    $$
    [S1]

### Parameters
*   $\epsilon > 0$: Intersection tolerance. A small positive value (e.g., $10^{-3}$ or similar, though exact typical value not given in sources) [S1].
*   $c = 1/255$: Minimum rendering contribution threshold [S1].
*   $\bar{V}_{ip}$: Adaptive threshold, passed through a sigmoid [S1].

### Edge Cases and Pitfalls
*   **Opacity below threshold:** Gaussians with $\alpha_i < c$ are discarded, so $\lambda_i$ is strictly positive [S1].
*   **Infinite offset:** If no translation along $n_i$ can produce contact, $\delta_{ij} = +\infty$ [S1].
*   **Numerical Approximation:** The exact infimum in $\delta_{ij}$ is approximated by sampling points on the boundary of $\Omega_j$ and finding the minimum $|Z|$ in the local frame of $\Omega_i$ [S1]. The number of samples is not specified in the sources [S1].
*   **Rank-2 Covariance:** The covariance matrix is rank-2 (scale $\sigma_3=0$), requiring the Moore–Penrose pseudoinverse $\Sigma_i^+$ [S1].

## Operating characteristics

*   **Time Complexity:** The core intersection test is $O(1)$ per pair if $\delta_{ij}$ is computed exactly, but the numerical approximation involves sampling $K$ points, making it $O(K)$ per pair. The sources note that an all-pairs comparison has quadratic complexity, so fixed-radius search is used to reduce it to approximately linear in practice [S1].
*   **Memory Complexity:** $O(1)$ additional memory per Gaussian for precomputed parameters ($\lambda_i, r_1, r_2, n_i$) [S1].
*   **Strengths:** Robust to minor misalignments via $\epsilon$-tolerance; shape-aware (elliptic) rather than axis-aligned bounding box; avoids strict binary overlap issues.
*   **Limitations:** Numerical approximation of $\delta_{ij}$ may be inaccurate with few samples; requires precomputation of local frame parameters.
*   **When to use:** When robust culling or sorting of Gaussian splats is needed in differentiable rendering pipelines.
*   **When not:** When exact geometric intersection is required without tolerance, or when computational budget is extremely tight and approximate sampling is too costly.
