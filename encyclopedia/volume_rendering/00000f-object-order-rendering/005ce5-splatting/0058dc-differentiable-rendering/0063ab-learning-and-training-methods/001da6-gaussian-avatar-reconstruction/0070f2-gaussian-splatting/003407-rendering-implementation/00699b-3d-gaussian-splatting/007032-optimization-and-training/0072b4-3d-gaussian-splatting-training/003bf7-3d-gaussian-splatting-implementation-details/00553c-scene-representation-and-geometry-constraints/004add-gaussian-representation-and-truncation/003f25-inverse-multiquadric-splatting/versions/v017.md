# Inverse Multiquadric Splatting

Also called: 3DIQS, Inverse Multiquadric

## Overview
Inverse Multiquadric Splatting replaces the standard Gaussian density function with an inverse multiquadric radial basis function to modulate the alpha contribution of each splat [S1]. It differs from the base Gaussian Splatting method by using a function with heavier tails and a different decay profile, requiring a specific correction factor for the covariance matrix to maintain visual fidelity [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of 3D Gaussians $\{G_i\}$, where each Gaussian has a 3D mean $\boldsymbol{\mu}_i$, 3D covariance $\boldsymbol{\Sigma}_i$, opacity $\alpha_i$, and color $\mathbf{c}_i$. For each pixel, the 2D projected mean $\boldsymbol{\mu}'$ and 2D conic matrix (inverse covariance) $\mathbf{C}' = (\Sigma'_{2 \times 2})^{-1}$ are computed.
*   **Output:** The final alpha value $\alpha$ for the splat at the pixel, and gradients for the mean and conic matrix during backpropagation.

**Data Structures:**
*   `con_o`: A 4D vector representing the 2D conic matrix parameters and opacity weight.
    *   `con_o.x`: $C'_{11}$ (top-left element of $\mathbf{C}'$)
    *   `con_o.y`: $C'_{12}$ (top-right/bottom-left element of $\mathbf{C}'$)
    *   `con_o.z`: $C'_{22}$ (bottom-right element of $\mathbf{C}'$)
    *   `con_o.w`: The opacity weight $\alpha_i$ (or pre-multiplied opacity).
*   `d`: A 2D vector representing the displacement from the pixel center to the splat center: $\mathbf{d} = (x - \mu'_x, y - \mu'_y)$.

**Parameters:**
*   `correctionFactor`: A scalar multiplier applied to the 3D covariance matrix $\boldsymbol{\Sigma}$ and the 2D covariance matrix $\Sigma'_{2 \times 2}$ before projection or during rasterization. Value: $1.38$ [S1].
*   `ellipse_max`: The upper bound for the ellipse term to skip distant splats. Value: $9.0$ [S1].

**Formulas:**
The 2D inverse multiquadric weight $w$ is defined as [S1]:
$$ w = \frac{1}{\frac{1}{\xi} (\mathbf{x} - \boldsymbol{\mu}')^\top (\Sigma'_{2 \times 2})^{-1} (\mathbf{x} - \boldsymbol{\mu}') + 1} $$
In the implementation, the term $\frac{1}{\xi} (\mathbf{x} - \boldsymbol{\mu}')^\top (\Sigma'_{2 \times 2})^{-1} (\mathbf{x} - \boldsymbol{\mu}')$ is computed as `ellipse`. Thus:
$$ w = \frac{1}{\text{ellipse} + 1} $$
The final alpha is clamped and combined with the opacity weight [S1]:
$$ \alpha = \min(0.99, \text{con\_o.w} \cdot w) $$

**Numbered Steps:**

1.  **Covariance Correction:** Multiply the 3D covariance matrix $\boldsymbol{\Sigma}$ by `correctionFactor` ($1.38$) [S1].
2.  **Ellipse Calculation:** Compute the quadratic form `ellipse` using the 2D conic matrix `con_o` and displacement `d` [S1]:
    $$ \text{ellipse} = \text{con\_o.x} \cdot d_x^2 + \text{con\_o.z} \cdot d_y^2 + 2.0 \cdot \text{con\_o.y} \cdot d_x \cdot d_y $$
3.  **Boundary Checks:**
    *   If $\text{ellipse} \le 0$, skip the splat (continue) [S1].
    *   If $\text{ellipse} \ge 9.0$, skip the splat (continue) [S1].
4.  **Weight Calculation:** Compute the inverse quadric term $G$ (which is $w$) [S1]:
    $$ G = \frac{1}{\text{ellipse} + 1} $$
5.  **Alpha Computation:** Compute the final alpha [S1]:
    $$ \alpha = \min(0.99, \text{con\_o.w} \cdot G) $$

**Pseudocode (Forward Pass):**

```python
def inverse_multiquadric_forward(con_o, d):
    """
    con_o: tuple (C11, C12, C22, opacity_weight)
    d: tuple (dx, dy)
    """
    C11, C12, C22, opacity_w = con_o
    dx, dy = d
    
    # 1. Calculate ellipse term (quadratic form)
    ellipse = C11 * (dx * dx) + C22 * (dy * dy) + 2.0 * C12 * dx * dy
    
    # 2. Boundary checks
    if ellipse <= 0.0:
        return None
    if ellipse >= 9.0:
        return None
        
    # 3. Calculate weight G (inverse quadric)
    G = 1.0 / (ellipse + 1.0)
    
    # 4. Calculate alpha
    alpha = min(0.99, opacity_w * G)
    
    return alpha
```

**Pseudocode (Backward Pass):**

The gradients are computed with respect to the loss $L$. Let $dL\_d\alpha$ be the gradient of the loss with respect to alpha.

1.  Compute gradient w.r.t $G$:
    $$ dL\_dG = \text{con\_o.w} \cdot dL\_d\alpha $$
2.  Compute gradient w.r.t `ellipse`:
    $$ \frac{\partial G}{\partial \text{ellipse}} = \frac{-1}{(\text{ellipse} + 1)^2} $$
    $$ dL\_d\text{ellipse} = dL\_dG \cdot \frac{-1}{(\text{ellipse} + 1)^2} $$
3.  Compute gradients w.r.t `con_o` components (which correspond to the conic matrix entries):
    *   $\frac{\partial \text{ellipse}}{\partial C11} = d_x^2$
    *   $\frac{\partial \text{ellipse}}{\partial C22} = d_y^2$
    *   $\frac{\partial \text{ellipse}}{\partial C12} = 2 d_x d_y$
    
    $$ dL\_dC11 = dL\_d\text{ellipse} \cdot d_x^2 $$
    $$ dL\_dC22 = dL\_d\text{ellipse} \cdot d_y^2 $$
    $$ dL\_dC12 = dL\_d\text{ellipse} \cdot 2 d_x d_y $$

4.  **Covariance Correction Gradient:** Since the covariance was multiplied by `correctionFactor`, the gradient w.r.t the original covariance must be scaled by `correctionFactor` [S1].
    $$ dL\_d\Sigma_{original} = dL\_d\Sigma_{computed} \cdot 1.38 $$

**Pseudocode (Backward Pass):**

```python
def inverse_multiquadric_backward(con_o, d, dL_dalpha):
    """
    Returns gradients for con_o (C11, C12, C22, opacity_w)
    """
    C11, C12, C22, opacity_w = con_o
    dx, dy = d
    
    # 1. Gradient w.r.t G
    dL_dG = opacity_w * dL_dalpha
    
    # 2. Gradient w.r.t ellipse
    # G = 1 / (ellipse + 1)
    # dG/d_ellipse = -1 / (ellipse + 1)^2
    denom_sq = (ellipse + 1.0) ** 2
    dL_d_ellipse = dL_dG * (-1.0 / denom_sq)
    
    # 3. Gradients w.r.t conic matrix components
    # ellipse = C11*dx^2 + C22*dy^2 + 2*C12*dx*dy
    dL_dC11 = dL_d_ellipse * (dx * dx)
    dL_dC22 = dL_d_ellipse * (dy * dy)
    dL_dC12 = dL_d_ellipse * (2.0 * dx * dy)
    
    # 4. Gradient w.r.t opacity weight
    # alpha = min(0.99, opacity_w * G)
    # If alpha < 0.99, dL_d_opacity_w = G * dL_dalpha
    # If alpha == 0.99, gradient is 0 (clamped)
    if opacity_w * (1.0 / (ellipse + 1.0)) < 0.99:
        dL_d_opacity_w = (1.0 / (ellipse + 1.0)) * dL_dalpha
    else:
        dL_d_opacity_w = 0.0
        
    return (dL_dC11, dL_dC12, dL_dC22, dL_d_opacity_w)
```

**Edge Cases and Pitfalls:**
*   **Precision:** The `ellipse` term can become large for distant splats. The check `ellipse >= 9.0` prevents numerical instability and unnecessary computation [S1].
*   **Covariance Scaling:** The `correctionFactor` of $1.38$ is critical. Omitting it or using an incorrect value will result in incorrect splat sizes and visual artifacts [S1].
*   **Clamping:** The alpha is clamped at $0.99$. This prevents division by zero or numerical issues in the alpha blending equation when compositing [S1].

## Operating characteristics
*   **Time Complexity:** Same as standard Gaussian Splatting per pixel, $O(1)$ per splat, with the same culling logic.
*   **Memory Complexity:** Same as standard Gaussian Splatting.
*   **Strengths:** Provides an alternative decay profile that may better fit certain types of geometry or appearance data compared to the Gaussian kernel [S1].
*   **Limitations:** Requires a specific correction factor for the covariance matrix, adding a hyperparameter [S1].

## Background
Inverse Multiquadric Splatting was introduced in the paper "DARB-Splatting: Generalizing Splatting with Decaying Anisotropic Radial Basis Functions" [S1]. It is part of a family of methods that generalize the radial basis function used in splatting beyond the standard Gaussian.
