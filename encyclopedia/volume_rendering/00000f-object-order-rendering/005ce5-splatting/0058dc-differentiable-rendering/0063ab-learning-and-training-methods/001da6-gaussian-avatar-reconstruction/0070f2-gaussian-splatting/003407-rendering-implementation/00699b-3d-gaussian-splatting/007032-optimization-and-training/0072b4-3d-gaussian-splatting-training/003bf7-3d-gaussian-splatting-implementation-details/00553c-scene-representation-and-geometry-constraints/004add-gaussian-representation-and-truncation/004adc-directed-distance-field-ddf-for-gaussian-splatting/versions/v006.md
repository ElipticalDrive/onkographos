# Directed Distance Field (DDF) for Gaussian Splatting

Also called: Directed Distance Function, ray-query oracle

## Overview
The Directed Distance Field (DDF) is a neural implicit representation that serves as a constant-time, constant-memory ray-query oracle for 3D Gaussian Splatting (3DGS) scenes [S1, unofficial]. It maps a ray (defined by origin $\mathbf{x}$ and direction $\mathbf{d}$) to the distance $t$ to the first surface and a visibility probability $\xi$, enabling secondary ray queries such as shadows, ambient occlusion, and global illumination without iterative sphere tracing or bounding volume hierarchy (BVH) traversal [S1, unofficial]. Unlike BVH-based Gaussian tracing, which scales linearly with the number of Gaussians, the DDF’s query time and memory footprint remain flat regardless of scene complexity, making it suitable for real-time global illumination in large-scale captures [S1, unofficial].

## How it works
The DDF is trained to approximate the geometric structure of a 3DGS scene by learning from distance supervision derived from the Gaussians or a neural surface. It does not store Gaussian primitives; instead, it compresses the scene geometry into a fixed-size neural field.

### Inputs and Outputs
*   **Input:** Ray origin $\mathbf{x} \in \mathbb{R}^3$ and unit direction $\mathbf{d} \in S^2$.
*   **Output:** Distance $t \in \mathbb{R}$ to the first surface along $\mathbf{d}$, and visibility $\xi \in [0, 1]$ representing the probability that the ray hits the scene. The hit point is $\mathbf{x} + t\mathbf{d}$ when $\xi$ is high [S1, unofficial].

### Data Structures
The network architecture consists of a multiresolution hash grid for position encoding and a small Multi-Layer Perceptron (MLP) [S1, unofficial].

**Hash Grid Encoding (Position $\mathbf{x}$):**
*   **Levels:** 16
*   **Features per level:** 2
*   **Entries per level:** $2^{19}$ (524,288)
*   **Base resolution:** 16
*   **Growth factor:** 1.5
*   **Bounding Box:** Normalized object box [S1, unofficial].

**Direction Encoding ($\mathbf{d}$):**
*   **Method:** 4 sinusoidal bands [S1, unofficial].

**MLP:**
*   **Layers:** 2
*   **Width:** 64
*   **Parameters:** ~8,000 [S1, unofficial].

**Total Memory:** ~52 MB (dominated by the hash table’s ~13M parameters) [S1, unofficial].

### Training
The DDF is trained using Adam optimizer for 30,000 steps with a batch size of 16,384 rays [S1, unofficial].

**Supervision Sources:**
1.  **GS-Rendered Depth:** Cheap supervision from camera rays, but blurs thin features [S1, unofficial].
2.  **Clean Distance:** Sphere-traced distances from a neural surface (e.g., NeuS) or ray-casted ground-truth meshes. This recovers thin parts (e.g., mug handles, animal legs) that GS depth averages away [S1, unofficial].
3.  **Self-Consistency:** To sharpen thin features, for a ray hitting at distance $t$, a point shifted forward by distance $s$ along the ray is sampled. The DDF evaluated at this shifted point must predict distance $t-s$ [S1, unofficial].

**Loss Function:**
$$ L = \text{ClampedL1}(t_{pred}, t_{target}) + 0.3 \cdot \text{BCE}(\xi_{pred}, \xi_{target}) $$
The L1 term is clamped to a maximum value (box scale) to prevent far-away surfaces from dominating the loss. The cross-entropy (BCE) term weights the hit flag at 0.3 [S1, unofficial].

**Data Augmentation:**
30% of each training batch is replaced with ray-march shifted points for self-consistency supervision [S1, unofficial].

**Hyperparameters:**
*   **Learning Rate:** $3 \times 10^{-3}$, decayed by cosine schedule to 5% of initial value [S1, unofficial].

        self.num_bands = 4

        # Let's stick to the source's implicit dimensionality.

        """
        Query the DDF.
        x: (N, 3) ray origins
        d: (N, 3) ray directions
        Returns: (N, 2) tensor [t, xi]
        """
        feat_x = self.encode_position(x)
        feat_d = self.encode_direction(d)
        combined = torch.cat([feat_x, feat_d], dim=1)
        out = self.mlp(combined)
        t = out[:, 0]
        xi = torch.sigmoid(out[:, 1]) # Ensure xi is in [0, 1]
        return t, xi

    def compute_loss(self, t_pred, xi_pred, t_target, xi_target):
        """
        Compute training loss.
        """
        # Clamped L1 for distance
        # Clamp to box scale. Assume box_scale is a hyperparameter.
        box_scale = 1.0 # Normalized box
        l1_loss = torch.clamp(torch.abs(t_pred - t_target), max=box_scale).mean()
        
        # BCE for visibility
        bce_loss = nn.functional.binary_cross_entropy(xi_pred, xi_target)
        
        # Weighted sum
        loss = l1_loss + 0.3 * bce_loss
        return loss

    def train_step(self, optimizer, x_batch, d_batch, t_target, xi_target):
        optimizer.zero_grad()
        t_pred, xi_pred = self.forward(x_batch, d_batch)
        loss = self.compute_loss(t_pred, xi_pred, t_target, xi_target)
        loss.backward()
        optimizer.step()
        return loss.item()

        Check if surface_point is in shadow.

        # Offset surface point along normal

        # Query DDF towards light
        t, xi = self.forward(offset_point.unsqueeze(0), light_direction.unsqueeze(0))
        # If hit distance < light distance, it's in shadow

### Edge Cases and Pitfalls
*   **Thin Feature Loss:** Supervising solely with 3DGS-rendered depth blurs thin parts (e.g., mug handles, animal legs) because narrow structures are averaged away by soft Gaussians. Clean distance supervision (from neural surfaces or meshes) is required to recover these features [S1, unofficial].
*   **Compact Objects:** For compact objects where Gaussian depth already captures geometry, clean distance supervision provides little benefit and may hurt if the sphere-traced point cloud is noisy, causing the surface to "fatten" [S1, unofficial].
*   **Background Rays:** Learning directly from images (volume-rendering color loss) does not help recover thin geometry because most sampled rays land on the background, making the path from color to distance output weak [S1, unofficial].
*   **AO Accuracy:** Ambient occlusion quality (21.3 dB) is lower than shadow quality (30.3 dB) because averaging many rays accumulates small per-ray errors [S1, unofficial].
*   **Ray Origin Dependency:** The oracle is accurate primarily for ray origins on or near the surface. Rays starting far from any surface (e.g., ground plane below an object) may report occlusion incorrectly [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Constant time $O(1)$ per ray query. One forward pass of the neural network [S1, unofficial].
*   **Memory Complexity:** Constant memory $O(1)$, fixed at ~52 MB regardless of the number of Gaussians $N$ [S1, unofficial].
*   **Performance:**
    *   **Speed:** 26 to 72 times faster than sphere tracing an equivalent neural Signed Distance Field (SDF) [S1, unofficial].
    *   **Scaling:** Query latency is flat with respect to the number of Gaussians. In contrast, BVH-over-Gaussians latency rises by ~9x from 5K to 1M Gaussians [S1, unofficial].
    *   **Comparison to BVH:** On small scenes (<155k Gaussians), RT-core BVH is faster per ray. At real scene scales (hundreds of thousands to millions of Gaussians), DDF becomes competitive or faster, especially with CUDA-fused kernels (tinycudann) [S1, unofficial].
    *   **Comparison to Rasterization:** For sparse queries (1K-10K rays), DDF is 600+ times faster than re-rasterizing with gsplat. At full frame (1M rays), DDF ties rasterization (4.81 ms vs 4.45 ms) due to frame buffer write bounds [S1, unofficial].
*   **Quality:** Reproduces reference ray-traced shadows at 30.3 dB and ambient occlusion at 21.3 dB across 142 objects and real scenes [S1, unofficial].
*   **Hardware:** Does not require RT-core hardware. Measured on A100 (no RT cores) and RTX 2080 Ti [S1, unofficial].
*   **When to Use:** Ideal for global illumination (shadows, AO) in large-scale Gaussian Splatting scenes where constant-time queries and low memory are critical, and mesh generation is undesirable [S1, unofficial].
*   **When Not to Use:** Not suitable for generating smooth surface meshes or for scenes with significant volumetric density far from the surface, as the field is trained primarily on surface-adjacent rays [S1, unofficial].

## Background
The Directed Distance Field for Gaussian Splatting was introduced in the paper "Directed Distance Fields for Constant-Time Ray Queries on Gaussian Splatting" [S1, unofficial]. It addresses the limitation of 3DGS rasterization, which cannot natively support secondary rays required for global illumination. The method distills the 3DGS scene into a small neural field using multiresolution hash grid encoding (from tinycudann) and a lightweight MLP. It enables a mesh-free pipeline for global illumination, avoiding the need for explicit mesh extraction or BVH construction [S1, unofficial].
