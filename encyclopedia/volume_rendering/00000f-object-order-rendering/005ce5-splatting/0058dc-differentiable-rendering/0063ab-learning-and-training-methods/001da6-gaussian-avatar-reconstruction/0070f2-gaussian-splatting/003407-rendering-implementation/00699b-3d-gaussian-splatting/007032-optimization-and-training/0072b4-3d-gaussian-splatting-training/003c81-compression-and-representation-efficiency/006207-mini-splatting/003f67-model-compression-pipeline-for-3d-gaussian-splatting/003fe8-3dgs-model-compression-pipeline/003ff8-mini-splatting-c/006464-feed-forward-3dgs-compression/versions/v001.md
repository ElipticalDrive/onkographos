# Feed-Forward 3DGS Compression

Also called: Compression of Feed-Forward 3DGS, Zero-shot Compression

## Overview
Feed-Forward 3DGS Compression (FCGS) is a post-training compression method that reduces the storage size of 3D Gaussian Splatting (3DGS) models generated by feed-forward reconstruction networks without requiring retraining or optimization [S1, unofficial]. Unlike optimization-based compression methods that iteratively refine Gaussian parameters to minimize a loss function, FCGS applies a learned entropy model directly to the existing Gaussian attributes, enabling zero-shot generalization to scenes where ground-truth geometry is unavailable [S1, unofficial]. It sets itself apart by handling the irregular data structures of feed-forward outputs (e.g., from LGM or MVSplat) where traditional mesh-based or optimization-based codecs fail due to the lack of a consistent reference [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A pre-trained 3DGS model (set of Gaussians with position, covariance, opacity, and spherical harmonic coefficients) generated by a feed-forward model (e.g., LGM, MVSplat).
- **Output:** A compressed bitstream representing the Gaussian attributes, achieving significant size reduction.

**Data Structures:**
The 3DGS model consists of $N$ Gaussians. Each Gaussian $i$ is defined by:
- Position $\mathbf{p}_i \in \mathbb{R}^3$
- Rotation $\mathbf{q}_i \in \mathbb{R}^4$ (quaternion)
- Scale $\mathbf{s}_i \in \mathbb{R}^3$
- Opacity $\alpha_i \in \mathbb{R}$
- Color coefficients $\mathbf{c}_i$ (Spherical Harmonics)

**Method Steps:**
1. **Attribute Extraction:** Extract all Gaussian attributes from the feed-forward model. For feed-forward models like LGM, generate multi-view inputs (e.g., 4 views from 1 initial view using [Wang & Shi, 2023]) to create the 3DGS [S1, unofficial].
2. **Masking for Feed-Forward Models:** When compressing 3DGS from feed-forward models, set the mask $m$ for color attributes to all 0s. This indicates that color attributes are not compressed using the standard entropy model but are handled differently (likely discarded or approximated, as ground truth is unavailable for optimization) [S1, unofficial].
3. **Entropy Model Application:** Apply the Memory-Efficient Memory (MEM) module and context models to compress the remaining attributes (position, rotation, scale, opacity). The MEM module adaptively selects high-tolerance color attributes for compression, but for feed-forward models, this step is bypassed for color due to the mask [S1, unofficial].
4. **Bitstream Generation:** Encode the quantized and context-predicted attributes into a bitstream using an entropy coder (e.g., arithmetic coding).

**Parameters:**
- **Mask $m$:** For feed-forward 3DGS, $m = 0$ for all color attributes [S1, unofficial].
- **Compression Ratio:** Achieves 15x compression for MVSplat-generated 3DGS and 5x for LGM-generated 3DGS [S1, unofficial].

**Edge Cases and Pitfalls:**
- **No Ground Truth:** For feed-forward models, ground-truth geometry is unavailable, so fidelity is evaluated by comparing rendered images before and after compression [S1, unofficial].
- **Zero-Shot Generalization:** The method must generalize without retraining, requiring robust entropy models that do not overfit to specific scene distributions [S1, unofficial].

**Pseudocode:**
```python
def compress_feed_forward_3dgs(gaussians, model_type):
    """
    Compress 3DGS from feed-forward models without retraining.
    
    Args:
        gaussians: List of Gaussian objects with attributes (pos, rot, scale, opacity, color).
        model_type: String, 'LGM' or 'MVSplat'.
        
    Returns:
        bitstream: Compressed data.
    """
    # Step 1: Extract attributes
    positions = [g.pos for g in gaussians]
    rotations = [g.rot for g in gaussians]
    scales = [g.scale for g in gaussians]
    opacities = [g.opacity for g in gaussians]
    colors = [g.color for g in gaussians]
    
    # Step 2: Set mask for color attributes to 0 for feed-forward models
    # This disables standard color compression for feed-forward outputs
    color_mask = [0] * len(gaussians)
    
    # Step 3: Apply entropy model to non-color attributes
    # MEM module adaptively selects attributes, but color is masked out
    quantized_positions = quantize(positions)
    quantized_rotations = quantize(rotations)
    quantized_scales = quantize(scales)
    quantized_opacities = quantize(opacities)
    
    # Context modeling and entropy coding
    # Note: Specific context model details are not provided in sources [G]
    bitstream_pos = entropy_encode(quantized_positions)
    bitstream_rot = entropy_encode(quantized_rotations)
    bitstream_scale = entropy_encode(quantized_scales)
    bitstream_opacity = entropy_encode(quantized_opacities)
    
    # Color attributes are not compressed in the standard way for feed-forward models
    # They are either discarded or handled via the mask [S1, unofficial]
    bitstream_color = None 
    
    # Combine bitstreams
    bitstream = combine(bitstream_pos, bitstream_rot, bitstream_scale, bitstream_opacity)
    
    return bitstream
```

## Subtopics

### [FeCoSplat](19396-fecosplat.md)
FeCoSplat is a two-stage feature compression framework for feed-forward 3D Gaussian Splatting (3DGS) that decouples compression into multi-view feature coding and reconstruction-conditioned feedback coding. It allows the receiver to decode directly in the compact feature-state domain without reconstructing intermediate Gaussians, thereby avoiding the heavy computational overhead of image compression and the irregularity challenges of explicit Gaussian compression. Unlike [CodecSplat](19101-feed-forward-3dgs-compression.md) which uses a single coding stage, FeCoSplat uses rendered reconstruction feedback to guide a second-stage refinement, maintaining an implicit Gaussian state for lightweight receiver-side decoding.

## Operating characteristics
- **Compression Ratios:** Achieves 15x compression for MVSplat-generated 3DGS and 5x for LGM-generated 3DGS [S1, unofficial].
- **Performance:** Excellent rate-distortion (RD) performance despite the lack of optimization [S1, unofficial].
- **Hardware/Resolution:** Evaluated on 10 scenes from ACID and 50 scenes from Gobjaverse [S1, unofficial].
- **Strengths:** Zero-shot generalization, no retraining required, handles feed-forward models with no ground truth.
- **Limitations:** Color attributes are not compressed effectively for feed-forward models (mask set to 0), potentially affecting visual fidelity [S1, unofficial].

## Background
FCGS was introduced in "Fast Feedforward 3D Gaussian Splatting Compression" (2024) [S1, unofficial]. It addresses the need for efficient compression of 3DGS models generated by feed-forward networks, which are increasingly popular for rapid 3D reconstruction. Traditional compression methods rely on optimization-based 3DGS, which are not directly applicable to feed-forward outputs due to the lack of ground truth and the irregular nature of the generated Gaussians [S1, unofficial].
