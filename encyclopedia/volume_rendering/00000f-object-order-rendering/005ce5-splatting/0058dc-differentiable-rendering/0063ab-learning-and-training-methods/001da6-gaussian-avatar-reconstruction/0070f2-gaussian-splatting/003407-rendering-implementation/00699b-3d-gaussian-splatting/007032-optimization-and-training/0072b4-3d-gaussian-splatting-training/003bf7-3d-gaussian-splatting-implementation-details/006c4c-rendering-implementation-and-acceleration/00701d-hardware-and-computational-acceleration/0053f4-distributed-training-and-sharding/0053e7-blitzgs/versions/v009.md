# BlitzGS

Also called: BlitzGS: City-Scale Gaussian Splatting at Lightning Speed

## Overview
BlitzGS is a distributed 3D Gaussian Splatting (3DGS) framework designed to accelerate city-scale reconstruction by reducing the active Gaussian workload at system, model, and view levels [S1, unofficial]. Unlike spatial block partitioning which suffers from cross-block redundancy and imbalanced shards, BlitzGS shards Gaussians across GPUs by index parity and applies importance-based filtering to prune redundant primitives and gate spawns [S1, unofficial]. It achieves nearly an order-of-magnitude faster training time compared to baselines like Momen.GS and CityGS-X while maintaining high reconstruction quality [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of calibrated images, initial 3D Gaussian primitives (mean $\mu$, covariance $\Sigma$, opacity $\alpha$, color/radiance), and $M$ GPUs.
*   **Outputs:** Optimized 3D Gaussian scene representation and rendered novel views.

**Data Structures:**
*   **Global Gaussian Set $\mathcal{G}$:** Partitioned into $M$ shards $\mathcal{G}^{(m)}$ for $m \in \{0, \dots, M-1\}$.
*   **Shard Assignment:** Gaussian $i$ is assigned to GPU $m$ based on index parity: $m = i \pmod 2$ (assuming $M=2$ for parity, or generally $i \pmod M$ if extended, but the source specifies parity specifically for avoiding cross-block redundancy) [S1, unofficial]. The source explicitly states "index parity (even/odd indices)" [S1, unofficial].
*   **Tile Ownership:** The image plane is tiled. Each tile is assigned to a specific GPU owner.

**Algorithm Steps:**

1.  **System-Level Sharding:**
    *   Distribute the global Gaussian set $\mathcal{G}$ across $M$ GPUs such that each GPU $m$ holds shard $\mathcal{G}^{(m)}$ containing Gaussians with indices $i$ where $i \pmod M = m$ (specifically parity for $M=2$) [S1, unofficial].
    *   Each GPU maintains its own optimizer state for its shard [S1, unofficial].

2.  **Model-Level Population Control:**
    *   **Importance Scoring:** Perform a pass to score each Gaussian's importance. This signal is used for:
        *   Pruning redundant Gaussians.
        *   Reweighting density control gradients.
        *   View-level filtering [S1, unofficial].
    *   **Spawn Gating:** Use a lightweight gate to predict whether a candidate Gaussian (from densification) will survive. Withhold candidates predicted not to survive before they are spawned into the scene, limiting peak population [S1, unofficial].

3.  **View-Level Filtering:**
    *   **Distance-based LOD Gate:** For each camera, drop Gaussians that are too fine (small scale) for the current camera distance, as they contribute negligibly to the image [S1, unofficial].
    *   **Importance Mask:** Apply the importance signal from Step 2 to skip Gaussians with negligible cross-view contribution, trimming the active set for rendering [S1, unofficial].

4.  **Distributed Rendering:**
    *   Each GPU $m$ projects only its local shard $\mathcal{G}^{(m)}$ to screen space [S1, unofficial].
    *   The image is divided into tiles. Each tile is owned by a specific GPU.
    *   **Cross-GPU Exchange:** Perform a single all-to-all communication step where projected Gaussians are routed to the GPUs owning the tiles they cover [S1, unofficial].
    *   Each GPU composites the pixels for its owned tiles using the received Gaussians and its local projections [S1, unofficial].
    *   The final image is identical to a single-GPU renderer on the full set [S1, unofficial].

**Parameters:**
*   **Hardware:** 4x NVIDIA A6000 GPUs [S1, unofficial].
*   **Sharding Strategy:** Index parity (even/odd) [S1, unofficial].

**Pseudocode:**

```python
def blitzgs_training_loop(images, initial_gaussians, num_gpus=4):
    # 1. System-Level Sharding
    # Assign Gaussians to GPUs based on index parity
    gaussians_per_gpu = [None] * num_gpus
    for i, g in enumerate(initial_gaussians):
        gpu_id = i % num_gpus
        if gaussians_per_gpu[gpu_id] is None:
            gaussians_per_gpu[gpu_id] = []
        gaussians_per_gpu[gpu_id].append(g)
    
    # Initialize optimizer states per GPU
    optimizers = [init_optimizer(gaussians_per_gpu[m]) for m in range(num_gpus)]
    
    # Define tile ownership (simplified: round-robin or fixed assignment)
    # Assume tiles are pre-assigned to GPUs
    tile_owners = get_tile_ownership_map() 
    
    for iteration in range(num_iterations):
        for camera in cameras:
            # 2. Model-Level: Importance Scoring & Spawn Gating
            # Score importance for all active Gaussians
            importance_scores = compute_importance(gaussians_per_gpu, camera)
            
            # Prune redundant Gaussians based on importance
            gaussians_per_gpu = prune_gaussians(gaussians_per_gpu, importance_scores)
            
            # Spawn gating: predict survival for new candidates
            # (Assuming densification happens here or is integrated)
            candidates = get_densification_candidates(gaussians_per_gpu)
            survival_preds = predict_survival(candidates)
            valid_candidates = [c for c, pred in zip(candidates, survival_preds) if pred]
            gaussians_per_gpu = spawn_gaussians(gaussians_per_gpu, valid_candidates)
            
            # Reweight density control gradients using importance
            reweight_gradients(optimizers, importance_scores)
            
            # 3. View-Level: Filtering
            # Distance-based LOD gate
            active_gaussians = []
            for m in range(num_gpus):
                active = []
                for g in gaussians_per_gpu[m]:
                    if is_valid_lod(g, camera):
                        active.append(g)
                active_gaussians.append(active)
            
            # Importance-based mask
            for m in range(num_gpus):
                gaussians_per_gpu[m] = [
                    g for g in active_gaussians[m] 
                    if importance_scores[m][g.id] > threshold
                ]
            
            # 4. Distributed Rendering
            # Projection
            projected_gaussians = [
                project(g, camera) for g in gaussians_per_gpu[m]
            ]
            
            # All-to-All Exchange: Route to tile owners
            # Each GPU sends its projected Gaussians to GPUs owning the tiles they cover
            received_gaussians = all_to_all_exchange(projected_gaussians, tile_owners)
            
            # Composite
            for tile, owner_gpu in tile_owners.items():
                if owner_gpu == m:
                    render_tile(tile, received_gaussians[tile], camera)
        
        # Update parameters
        for m in range(num_gpus):
            optimizers[m].step()
```

**Edge Cases and Pitfalls:**
*   **Imbalanced Shards:** Index parity avoids the imbalance caused by spatial block partitioning where some blocks may have more visible Gaussians than others [S1, unofficial].
*   **Cross-Block Redundancy:** Spatial partitioning can lead to redundant storage and computation for Gaussians near block boundaries. Index parity eliminates this need for a final merge step [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Training time is significantly reduced. On 4x NVIDIA A6000 GPUs, BlitzGS trains the Residence scene in 38 minutes and the Rubble scene in 39 minutes [S1, unofficial].
*   **Memory Complexity:** By pruning redundant Gaussians and gating spawns, the peak population and memory footprint are reduced [S1, unofficial].
*   **Performance:** Achieves scene-average PSNR of 24.66 dB for Residence and 33.79 dB for Rubble [S1, unofficial].
*   **Comparison:** Trains nearly an order of magnitude faster than Momen.GS (5h 03min, PSNR 31.81) and CityGS-X (4h 45min, PSNR 20.12) [S1, unofficial].
*   **Strengths:** Fast city-scale training, efficient multi-GPU scaling, high quality.
*   **Limitations:** Requires careful implementation of importance scoring and spawn gating. Relies on specific hardware (tested on A6000) [S1, unofficial].

## Background
BlitzGS was introduced by Zhongtao Wang, Huishan Au, Yisong Chen, Meng Gai, Yilong Li, Fei Zhu, Mai Su, Haojie Jin, and Guoping Wang in the paper "BlitzGS: City-Scale Gaussian Splatting at Lightning Speed" [S1, unofficial]. It addresses the high cost of city-scale 3DGS training by unifying sharding, importance-based simplification, and LOD filtering [S1, unofficial].
