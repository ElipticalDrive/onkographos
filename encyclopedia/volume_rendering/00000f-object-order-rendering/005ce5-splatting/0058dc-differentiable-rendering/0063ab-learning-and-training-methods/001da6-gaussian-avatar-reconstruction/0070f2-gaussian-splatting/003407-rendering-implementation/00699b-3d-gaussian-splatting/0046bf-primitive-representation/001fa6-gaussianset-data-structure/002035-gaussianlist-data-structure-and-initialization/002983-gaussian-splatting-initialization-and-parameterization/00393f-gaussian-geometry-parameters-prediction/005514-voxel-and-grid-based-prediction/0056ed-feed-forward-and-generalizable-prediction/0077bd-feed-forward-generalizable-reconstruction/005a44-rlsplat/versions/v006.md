# RLSplat

Also called: Resource-Linear Budget Control for Feed-forward 3D Gaussian Splatting

## Overview
RLSplat is a resource-linear, budget-controllable feed-forward 3D Gaussian Splatting (FF3DGS) framework that generates exactly $B$ Gaussians for a given scene, ensuring that inference latency and peak memory scale linearly with the requested budget [S1, unofficial]. Unlike prior budget-controllable methods (e.g., EcoSplat, F4 Splat) that predict a dense set of candidates and prune them—resulting in nearly constant inference costs regardless of the target budget—RLSplat uses a learned Gaussian allocation policy to distribute exactly $B$ Gaussians across local scene regions from the start [S1, unofficial]. This approach allows the representation size, inference latency, and peak memory to decrease linearly as the Gaussian budget $B$ is reduced, while maintaining or exceeding the reconstruction quality of denser baselines at lower resource costs [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of $V$ uncalibrated context images $\{I_i\}_{i=1}^V$ and a target integer Gaussian budget $B$ [S1, unofficial].
*   **Outputs:** A set of $B$ 3D Gaussians $\mathcal{G} = \{g_b\}_{b=1}^B$ and the context camera parameters $\{P_i\}_{i=1}^V$ [S1, unofficial]. Each Gaussian $g_b$ consists of a 3D center, opacity, scale, rotation, and color coefficients [S1, unofficial].

**Data Structures:**
1.  **Anchor Tokens ($\{a_n\}_{n=1}^N$):** A set of $N$ tokens extracted from the geometry backbone, each representing a local 3D region of the scene [S1, unofficial].
2.  **Allocation Vector ($\mathbf{k}$):** A discrete vector $\mathbf{k} \in \mathbb{Z}_{\ge 0}^N$ where $k_n$ is the number of Gaussians assigned to anchor $n$, such that $\sum_{n=1}^N k_n = B$ [S1, unofficial].
3.  **Gaussian Tokens:** A list of $B$ tokens, where anchor $n$ spawns $k_n$ tokens [S1, unofficial].
4.  **Hierarchical Neighbor Search Structure:** Used to efficiently find the $K_{gs}$ nearest Gaussian neighbors for each token [S1, unofficial].

**Parameters:**
*   $B$: Target Gaussian budget. Typical evaluation values are 2,048 (2K) and 64,000 (64K) [S1, unofficial]. On the ACID dataset, $B=8,192$ is used [S1, unofficial].
*   $K_{gs}$: Number of nearest Gaussian neighbors each token attends to during refinement. Default ablation value is 16. This can be changed at inference without retraining [S1, unofficial].
*   $K_{anc}$: Number of anchor neighbors used in the hierarchical neighbor search. Fixed value in ablations is 16 [S1, unofficial].
*   $C$: Number of rollouts (candidate allocations) drawn per training step for the Group Sequence Policy Optimization (GSPO) [S1, unofficial].

**Algorithm Steps:**

1.  **Geometry Encoding:** The geometry backbone encodes the input images $\{I_i\}$ into $N$ anchor tokens $\{a_n\}_{n=1}^N$ and predicts camera parameters $\{P_i\}$ [S1, unofficial].
2.  **Gaussian Allocation:** The allocation policy $\pi_\psi$, conditioned on anchor features, predicts a discrete allocation vector $\mathbf{k}$ such that $\sum k_n = B$. This policy is trained using GSPO to maximize reconstruction reward [S1, unofficial].
3.  **Token Spawning:** Each anchor $n$ spawns $k_n$ Gaussian tokens. The total number of Gaussian tokens is exactly $B$ [S1, unofficial].
4.  **Resource-Linear Decoding:**
    *   **Initialization:** The decoder instantiates initial Gaussian parameters (center, scale, rotation, opacity, color) for each of the $B$ tokens based on their corresponding anchor token [S1, unofficial].
    *   **Neighbor Search:** For each Gaussian token, the hierarchical neighbor search identifies the $K_{gs}$ nearest Gaussian tokens in the current set [S1, unofficial].
    *   **Local Refinement:** Each Gaussian token refines its parameters via local cross-attention with its $K_{gs}$ nearest neighbors. This step ensures consistency among nearby Gaussians [S1, unofficial].
5.  **Rendering:** The final set of $B$ Gaussians is rendered into target views. During policy optimization, rendering is performed without gradient tracking to compute reconstruction loss for the reward signal [S1, unofficial].

**Pseudocode:**

```python
import torch
import torch.nn as nn
from typing import List, Tuple

class RLSplat:
    def __init__(self, geometry_backbone, allocation_policy, decoder, num_anchors: int):
        self.geometry_backbone = geometry_backbone
        self.allocation_policy = allocation_policy
        self.decoder = decoder
        self.num_anchors = num_anchors

    def forward(self, images: torch.Tensor, budget: int) -> Tuple[List[torch.Tensor], torch.Tensor]:
        # Step 1: Geometry Encoding
        anchor_tokens, cameras = self.geometry_backbone(images)
        
        # Step 2: Gaussian Allocation
        allocation = self.allocation_policy(anchor_tokens, budget)
        
        # Step 3: Token Spawning
        gaussian_tokens = []
        for n in range(self.num_anchors):
            count = allocation[n]
            tokens_for_anchor = torch.stack([anchor_tokens[n] for _ in range(count)])
            gaussian_tokens.append(tokens_for_anchor)
        gaussian_tokens = torch.cat(gaussian_tokens, dim=0)
        
        # Step 4: Resource-Linear Decoding
        initial_gaussians = self.decoder.initialize(gaussian_tokens)
        
        # Hierarchical Neighbor Search
        # [G] The sources specify a hierarchical neighbor search for efficiency.
        # Standard implementation computes pairwise distances and selects top-k neighbors.
        neighbor_indices = self.find_neighbors(initial_gaussians[:, :3], k=self.decoder.Kgs)
        
        # Local Refinement via Cross-Attention
        refined_gaussians = self.decoder.refine(initial_gaussians, neighbor_indices)
        
        return refined_gaussians, cameras

    def find_neighbors(self, centers: torch.Tensor, k: int) -> torch.Tensor:
        # Compute pairwise Euclidean distances
        dists = torch.cdist(centers, centers)
        # Select k nearest neighbors (excluding self at index 0)
        _, indices = torch.topk(dists, k=k+1, dim=-1, largest=False)
        return indices[:, 1:]

class Decoder:
    def __init__(self, Kgs: int):
        self.Kgs = Kgs

    def initialize(self, tokens: torch.Tensor) -> torch.Tensor:
        # [G] MLP predicts Gaussian attributes from tokens
        return torch.randn(tokens.shape[0], 14)

    def refine(self, gaussians: torch.Tensor, neighbor_indices: torch.Tensor) -> torch.Tensor:
        B, _ = gaussians.shape
        Kgs = self.Kgs
        neighbor_features = gaussians[neighbor_indices]
        
        # Local Cross-Attention
        q = gaussians.unsqueeze(1)
        k = neighbor_features
        v = neighbor_features
        
        scores = torch.bmm(q, k.transpose(1, 2)) / (14 ** 0.5)
        weights = torch.softmax(scores, dim=2)
        out = torch.bmm(weights, v)
        
        return out.squeeze(1)
```

**Edge Cases and Pitfalls:**
*   **Allocation Policy Failure:** If the allocation policy fails to distribute Gaussians effectively (e.g., assigning zero Gaussians to high-frequency regions), reconstruction quality degrades significantly. The policy is trained with GSPO to concentrate capacity where fine geometric details require it [S1, unofficial].
*   **Neighbor Search Accuracy:** The hierarchical neighbor search must accurately identify true spatial neighbors. Removing the Voronoi loss during training causes Gaussians to leave their anchor's cell, leading to incorrect neighbor retrieval and a 2.51 dB PSNR drop [S1, unofficial].
*   **Projection Loss:** Removing the projection loss causes training to fail entirely, as it ties an anchor's Gaussians to the image region it was encoded from [S1, unofficial].
*   **Local Refinement:** Removing the local refinement module lowers PSNR by 0.96 dB, as Gaussians cannot be made consistent with their neighbors [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The decoding cost is $O(B \cdot K_{gs})$, scaling linearly with the Gaussian budget $B$ [S1, unofficial].
*   **Memory Complexity:** Peak memory usage scales linearly with $B$ [S1, unofficial].
*   **Inference Latency:** Latency scales linearly with $B$ [S1, unofficial].
*   **Performance:**
    *   On ACID ($B=8,192$): PSNR 22.84 dB, SSIM 0.643, LPIPS 0.353 [S1, unofficial].
    *   On RE10K ($B=8,000$): Full-view PSNR 26.51 dB, compared to 23.42 dB for F4 Splat and 21.82 dB for EcoSplat [S1, unofficial].
    *   At 2K Gaussians, RLSplat achieves higher PSNR than F4 Splat while using 9.6× less peak memory and running 4.1× faster [S1, unofficial].
*   **Strengths:**
    *   True resource-linearity: Cost decreases as budget decreases [S1, unofficial].
    *   High quality at low budgets: Outperforms baselines at every tested budget [S1, unofficial].
    *   Efficient neighbor search: Hierarchical search is 27× faster than exact search (8.1 ms vs. 219.6 ms at 65,536 Gaussians) [S1, unofficial].
*   **Limitations:**
    *   Requires training with GSPO, which involves non-differentiable discrete allocations [S1, unofficial].
    *   Performance depends on the accuracy of the hierarchical neighbor search [S1, unofficial].
*   **When to Use:** Applications requiring limited resource budgets, such as AR/VR, robotics, and digital content creation, where inference latency and memory are critical constraints [S1, unofficial].

## Background
RLSplat was proposed by Bae, Park, and Kim from KAIST in 2026 [S1, unofficial]. It addresses the limitations of prior budget-controllable FF3DGS methods like EcoSplat and F4 Splat, which predict dense sets of Gaussians and prune them, resulting in constant inference costs regardless of the target budget [S1, unofficial]. RLSplat introduces a Gaussian allocation policy trained with Group Sequence Policy Optimization (GSPO) and a resource-linear decoder with hierarchical neighbor search to achieve true linear scaling of inference cost with the Gaussian budget [S1, unofficial].
