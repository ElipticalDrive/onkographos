# FlashGS

Also called: FlashGS

## Overview
FlashGS is a multi-GPU rendering and training method for 3D Gaussian Splatting that accelerates the forward pass by partitioning the screen into finer tiles and scheduling them across a multi-GPU pipeline [S1, unofficial]. It differs from single-GPU rasterizers by distributing the tile workload to enable scalability for large scenes, and from primitive-sharding approaches by focusing on screen-space partitioning rather than model-space partitioning [S1, unofficial].

## How it works
FlashGS builds on the tile-based rasterization with radix sort method [Tile-based Rasterization with Radix Sort](7921-tile-based-rasterization-with-radix-sort.md). The core innovation lies in the deployment architecture: the image is divided into a grid of tiles, and these tiles are assigned to multiple GPUs for parallel processing [S1, unofficial].

1.  **Tile Partitioning:** The screen is divided into a grid of tiles. The granularity of these tiles is finer than standard implementations to balance load across GPUs [S1, unofficial].
2.  **Multi-GPU Scheduling:** The set of tiles is distributed among available GPUs. Each GPU processes its assigned subset of tiles independently [S1, unofficial].
3.  **Local Rasterization:** Within each GPU, the standard tile-based rasterization pipeline is executed:
    *   Gaussians are projected and assigned to tiles based on their axis-aligned bounding boxes (AABB) [Tile-based Rasterization with Radix Sort](7921-tile-based-rasterization-with-radix-sort.md).
    *   A global radix sort orders the (splat, tile) pairs by tile ID and depth [Tile-based Rasterization with Radix Sort](7921-tile-based-rasterization-with-radix-sort.md).
    *   Each GPU thread block processes its assigned tiles, performing front-to-back compositing [Tile-based Rasterization with Radix Sort](7921-tile-based-rasterization-with-radix-sort.md).
4.  **Result Assembly:** The rendered images from each GPU are combined to form the final output [S1, unofficial].

No specific pseudocode is provided in the sources for the scheduling logic itself, as it relies on the underlying rasterization kernel [S1, unofficial]. The method assumes the existence of a multi-GPU environment and a mechanism to distribute tile indices [S1, unofficial].

## Subtopics

### [System Level Primitive Sharding](15077-system-level-primitive-sharding.md)
A distributed strategy that partitions the Gaussian model across GPUs rather than the screen. It assigns Gaussians via index parity and distributes cameras, eliminating boundary waste and merge steps. Choose this for city-scale scenes with hundreds of millions of primitives where model size exceeds single-GPU memory. FlashGS focuses on screen partitioning for rendering acceleration.

## Operating characteristics
FlashGS accelerates the forward process by leveraging multiple GPUs [S1, unofficial]. Its performance scales with the number of GPUs and the fineness of the tile partitioning [S1, unofficial]. Specific time and memory complexity figures are not given in the sources [S1, unofficial]. It is suitable for high-performance rendering on multi-GPU setups [S1, unofficial].

## Background
FlashGS was introduced in the context of surveying 3D Gaussian Splatting rasterization techniques [S1, unofficial]. It is cited alongside other optimization methods like gsplat and Mobile-GS [S1, unofficial].
