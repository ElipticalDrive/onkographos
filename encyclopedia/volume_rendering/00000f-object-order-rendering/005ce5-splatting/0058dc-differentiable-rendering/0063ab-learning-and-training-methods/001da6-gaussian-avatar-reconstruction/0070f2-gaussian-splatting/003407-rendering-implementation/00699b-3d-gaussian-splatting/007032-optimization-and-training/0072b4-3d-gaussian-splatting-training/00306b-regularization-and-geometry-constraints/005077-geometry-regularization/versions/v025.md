# Geometry Regularization

Also called: Gaussian Flattening, Normal Consistency and Flattening

## Overview
Geometry regularization is a training technique that improves surface smoothness and reduces floating artifacts by constraining the geometric shape of 3D Gaussians, distinct from depth supervision which only constrains position [S1, S2, unofficial]. It sets itself apart from sibling methods like [Frequency Regularization](6130-frequency-regularization.md) by operating directly on the spatial covariance structure rather than the image frequency spectrum, and from [Hard and Soft Depth Regularization](9178-hard-and-soft-depth-regularization.md) by enforcing orientation and aspect-ratio constraints rather than just depth value consistency.

## How it works
**Inputs and Outputs:**
*   **Inputs:** Per-Gaussian scaling factors $\mathbf{s} \in \mathbb{R}^3$, per-Gaussian rotation matrices $\mathbf{R}$, rendered depth maps, and rendered normal maps.
*   **Outputs:** A scalar regularization loss value $\mathcal{L}_{geo}$ added to the total loss.

**Data Structures:**
*   **Gaussian Scaling:** A vector $\mathbf{s} = [s_x, s_y, s_z]$ representing the scale along the local principal axes.
*   **Gaussian Rotation:** A $3 \times 3$ matrix $\mathbf{R}$ or quaternion defining orientation.
*   **Rendered Normals:** A 2D array of surface normals $\mathbf{n}_{rendered}(u,v)$ corresponding to pixel coordinates.

**Steps:**
1.  **Depth Normal Consistency:**
    *   Compute the normal $\mathbf{n}_{depth}$ from the rendered depth map at each pixel $(u,v)$ using finite differences or a differentiable depth-to-normal operator.
    *   Compute the per-Gaussian normal $\mathbf{n}_{gauss}$ for the Gaussian covering pixel $(u,v)$. This is typically the direction of the smallest axis of the Gaussian ellipsoid, derived from the rotation matrix $\mathbf{R}$ and scaling $\mathbf{s}$. Specifically, if $\mathbf{s}$ is sorted such that $s_{min}$ is the smallest component, the normal is the corresponding column of $\mathbf{R}$ [S2, unofficial].
    *   Calculate the alignment loss as the dot product difference: $\mathcal{L}_{normal} = 1 - |\mathbf{n}_{depth} \cdot \mathbf{n}_{gauss}|$.
2.  **Flattening Surface (Scaling Loss):**
    *   Identify the smallest component of the scaling vector $\mathbf{s}$. Let $s_{min} = \min(s_x, s_y, s_z)$ [S2, unofficial].
    *   Minimize this smallest component towards zero to force the Gaussian into a flat "surflet" shape aligned with the surface [S2, unofficial].
    *   The flattening loss is typically defined as $\mathcal{L}_{flatten} = s_{min}$ or $\mathcal{L}_{flatten} = s_{min}^2$.
3.  **Total Geometry Loss:**
    *   Combine terms: $\mathcal{L}_{geo} = \lambda_{normal} \mathcal{L}_{normal} + \lambda_{flatten} \mathcal{L}_{flatten}$.

**Parameters:**
*   `use_normal_loss`: A boolean flag (e.g., in `OptimizationParams`) that enables the geometry regularization pipeline [S1, unofficial].
*   $\lambda_{normal}, \lambda_{flatten}$: Weights for the respective terms. Not given in the sources.

**Pseudocode:**
```python
def compute_geometry_loss(gaussians, rendered_depth, rendered_normals, params):
    """
    gaussians: object with attributes .s (N,3) scaling, .R (N,3,3) rotation
    rendered_depth: (H, W) depth map
    rendered_normals: (H, W, 3) normal map
    params: object with .use_normal_loss (bool)
    """
    loss = 0.0
    
    # Step 1: Flattening Loss
    # Identify smallest scale component for each Gaussian
    min_scales = torch.min(gaussians.s, dim=1).values # Shape: (N,)
    # Minimize towards zero
    loss += torch.mean(min_scales)
    
    # Step 2: Normal Consistency (if enabled)
    if params.use_normal_loss:
        # Determine Gaussian normals: direction of smallest axis
        # Find index of min scale for each Gaussian
        min_indices = torch.argmin(gaussians.s, dim=1) # Shape: (N,)
        
        # Gather the corresponding rotation column (normal direction)
        # R is (N, 3, 3). We want R[i, :, min_indices[i]]
        # Using advanced indexing or einsum
        gauss_normals = gaussians.R[torch.arange(gaussians.s.shape[0]), :, min_indices] # Shape: (N, 3)
        
        # Map Gaussians to pixels (requires rasterization indices)
        # Assuming we have pixel indices for each Gaussian from the forward pass
        # pixel_u, pixel_v: (N,) integer coordinates
        # rendered_normals is (H, W, 3)
        pixel_normals = rendered_normals[pixel_v, pixel_u] # Shape: (N, 3)
        
        # Dot product
        dot_product = torch.sum(gauss_normals * pixel_normals, dim=1) # Shape: (N,)
        # Align orientation: 1 - |dot|
        normal_loss = torch.mean(1.0 - torch.abs(dot_product))
        loss += normal_loss
        
    return loss
```

**Edge Cases and Pitfalls:**
*   **Depth Refitting:** Depth maps must be refitted against a prior point cloud to the same scale before use; frames that fail refitting are discarded [S1, unofficial].
*   **Ambiguity in Normal Direction:** The smallest axis defines the normal, but the sign (inward vs outward) must be consistent with the depth gradient. The absolute value in the dot product handles sign ambiguity [S2, unofficial].
*   **Degenerate Gaussians:** If a Gaussian becomes perfectly flat ($s_{min} \to 0$), numerical stability in normal computation may degrade.

## Subtopics

### Scaling Loss for Geometry Modeling
A specific implementation of geometry regularization that focuses exclusively on flattening Gaussian kernels into 3D surfels by minimizing the smallest component of the scaling factor $\mathbf{s} \in \mathbb{R}^3$ towards zero [S2, unofficial]. This aids in determining Gaussian normals by explicitly selecting the shortest scaled edge as the surface normal [S2, unofficial]. It is chosen when the primary goal is surface alignment and normal estimation rather than strict depth value matching.

## Operating characteristics
*   **Time Complexity:** Adds $O(N)$ overhead per training step for computing min-scales and dot products, where $N$ is the number of Gaussians. Normal computation from depth is $O(HW)$.
*   **Memory Complexity:** Requires storing rendered depth and normal maps, adding $O(HW)$ memory per frame.
*   **Strengths:** Significantly reduces "floaters" (noise) and improves surface smoothness [S1, unofficial]. Disentangles appearance from geometry by enforcing surfel-like shapes [S2, unofficial].
*   **Limitations:** Requires access to rendered depth and normals, which may not be available in all rendering pipelines. May over-constrain geometry if $\lambda$ is too high, leading to loss of fine detail.
*   **When to use:** When training on multi-view datasets with available depth or when surface smoothness is critical.
*   **When not to use:** When computational budget is extremely tight or when the scene contains significant volumetric/translucent structures that should not be flattened.

## Background
Originating from the need to improve the geometric fidelity of 3D Gaussian Splatting, this method was popularized in implementations like GaussianSplatting.jl and frameworks like GauStudio [S1, S2, unofficial]. It builds on the observation that unconstrained Gaussians tend to form noisy, volumetric clouds rather than crisp surfaces. The technique is closely related to surfel-based rendering methods and has been adopted in various modular frameworks to enhance reconstruction quality [S2, unofficial].
