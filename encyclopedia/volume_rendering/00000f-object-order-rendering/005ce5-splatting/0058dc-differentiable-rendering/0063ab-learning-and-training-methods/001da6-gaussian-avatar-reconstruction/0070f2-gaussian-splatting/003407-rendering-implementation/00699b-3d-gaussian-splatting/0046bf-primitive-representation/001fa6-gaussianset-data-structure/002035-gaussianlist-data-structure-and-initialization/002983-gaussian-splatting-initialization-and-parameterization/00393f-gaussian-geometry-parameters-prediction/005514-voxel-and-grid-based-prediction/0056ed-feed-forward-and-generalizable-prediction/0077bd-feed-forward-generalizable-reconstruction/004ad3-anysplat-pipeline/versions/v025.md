# AnySplat Pipeline

Also called: Feed-forward 3D Gaussian Splatting from Unconstrained Views

## Overview
The AnySplat Pipeline is a feed-forward method for reconstructing 3D scenes from uncalibrated, unconstrained image collections by directly predicting 3D Gaussian primitives and camera poses [S1, unofficial]. It differs from iterative optimization-based Gaussian Splatting by using a transformer-based encoder-decoder to infer scene parameters in a single forward pass, and from other generalizable methods by explicitly predicting camera poses alongside geometry to handle uncalibrated inputs [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $K$ uncalibrated RGB images. The input tensor shape is $[1, K, 3, 448, 448]$ (batch, views, channels, height, width) [S1, unofficial].
*   **Outputs:** A set of 3D Gaussians (defined by mean $\mu$, covariance $\sigma$, rotation $r$, scale $s$, and color $c$) and predicted camera poses $p$ (extrinsic and intrinsic matrices) [S1, unofficial].

**Data Structures:**
The method constructs a set of pixel-wise 3D Gaussians. These are then processed by a Differentiable Voxelization module to produce "pre-voxel 3D Gaussians" suitable for rendering [S1, unofficial]. The specific internal layout of the Gaussian parameters is not detailed beyond the symbolic representation $\mu, \sigma, r, s, c$ [S1, unofficial].

**Steps:**
1.  **Encoding:** Input images are passed through a transformer-based geometry encoder [S1, unofficial].
2.  **Decoding:** Three decoder heads ($F_G, F_D, F_C$) process the encoded features:
    *   $F_G$ predicts Gaussian parameters: mean $\mu$, covariance $\sigma$, rotation $r$, scale $s$, and color $c$ [S1, unofficial].
    *   $F_D$ predicts a depth map $D$ [S1, unofficial].
    *   $F_C$ predicts camera poses $p$ [S1, unofficial].
3.  **Construction:** The predicted parameters are used to construct a set of pixel-wise 3D Gaussians [S1, unofficial].
4.  **Voxelization:** The pixel-wise Gaussians are voxelized into pre-voxel 3D Gaussians using a Differentiable Voxelization module [S1, unofficial].
5.  **Rendering:** Multi-view images and depth maps are rendered from the voxelized Gaussians [S1, unofficial].
6.  **Supervision (RGB):** Rendered images are supervised against ground truth images using an RGB loss [S1, unofficial].
7.  **Supervision (Geometry):** Rendered depth maps, the decoded depth $D$, and the predicted poses $p$ are used to compute geometry losses [S1, unofficial].
8.  **Pseudo-Geometry Priors:** The geometry losses are supervised by pseudo-geometry priors obtained from a pretrained VGGT model [S1, unofficial].

## Subtopics

### [SubSplat](13524-subsplat.md)
SubSplat is a method for high-resolution novel-view synthesis that resolves the trade-off between network computational cost and rendering fidelity in pixel-aligned 3D Gaussian Splatting. It solves the problem of insufficient Gaussian density and artifacts when using low-resolution backbone inputs by introducing a Sub-pixel Gaussian Reparameterizer (SPGR). Unlike prior methods limited by fixed grids or image-space upsamplers, SubSplat subdivides each grid-anchored primary Gaussian into multiple fine-grained sub-pixel primitives, restoring structural density directly from low-resolution features while maintaining stable network latency.

### [Deformable Radial Kernel (DRK)](13699-deformable-radial-kernel-drk.md)
Deformable Radial Kernel (DRK) Splatting is a 3D scene representation method that replaces the fixed radial symmetry of Gaussian primitives with a flexible planar kernel defined by multiple radial basis functions. It solves the overparameterization and geometric fidelity limitations of Gaussian Splatting by allowing adaptive stretching, rotation, and sharp boundary control, enabling high-fidelity rendering with significantly fewer primitives. Unlike standard 2D Gaussian Splatting, which relies on smooth, elliptical distributions, DRK supports straight edges and sharp corners through L1/L2 norm blending and piecewise edge sharpening.

## Background
The AnySplat Pipeline was introduced by InternRobotics as a feed-forward approach to 3D Gaussian Splatting [S1, unofficial]. It builds on the principles of 3D Gaussian Splatting and extends them to a generalizable, feed-forward setting using transformer-based architectures [S1, unofficial].
