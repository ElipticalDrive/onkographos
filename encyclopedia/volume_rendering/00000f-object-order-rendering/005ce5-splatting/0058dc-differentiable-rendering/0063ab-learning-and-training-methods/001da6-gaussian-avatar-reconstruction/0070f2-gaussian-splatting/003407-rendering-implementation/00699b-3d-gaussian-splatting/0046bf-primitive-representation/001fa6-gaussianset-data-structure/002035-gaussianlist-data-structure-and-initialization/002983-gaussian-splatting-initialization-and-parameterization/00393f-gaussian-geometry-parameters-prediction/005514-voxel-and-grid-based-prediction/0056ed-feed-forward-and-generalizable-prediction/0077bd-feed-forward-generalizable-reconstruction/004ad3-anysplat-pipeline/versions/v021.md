# AnySplat Pipeline

Also called: Feed-forward 3D Gaussian Splatting from Unconstrained Views

## Overview
The AnySplat Pipeline is a feed-forward method that reconstructs 3D scenes and renders novel views from uncalibrated, unconstrained image collections without requiring iterative optimization or known camera poses [S1, unofficial]. It differs from iterative 3D Gaussian Splatting by using a transformer-based encoder-decoder to directly predict Gaussian parameters, depth, and poses in a single forward pass, enabling real-time reconstruction from arbitrary image sets [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $K$ uncalibrated RGB images. The input tensor shape is $[1, K, 3, 448, 448]$ (batch, views, channels, height, width) [S1, unofficial].
*   **Outputs:** A set of 3D Gaussians (defined by mean $\mu$, covariance $\sigma$, rotation $r$, scale $s$, and color $c$), predicted depth maps $D$, and camera poses $p$ (intrinsic and extrinsic) [S1, unofficial].

**Data Structures:**
The method constructs a set of pixel-wise 3D Gaussians. These are voxelized into "pre-voxel 3D Gaussians" using a Differentiable Voxelization module [S1, unofficial]. The specific internal layout of the Gaussian parameters (e.g., quaternion vs. axis-angle for rotation $r$, or diagonal vs. full matrix for covariance $\sigma$) is not explicitly detailed in the provided sources [G].

**Steps:**
1.  **Encoding:** Input images are processed by a transformer-based geometry encoder [S1, unofficial].
2.  **Decoding:** Three decoder heads ($F_G, F_D, F_C$) predict:
    *   $F_G$: Gaussian parameters ($\mu, \sigma, r, s, c$) [S1, unofficial].
    *   $F_D$: Depth map $D$ [S1, unofficial].
    *   $F_C$: Camera poses $p$ [S1, unofficial].
3.  **Construction:** The predicted parameters are used to construct a set of pixel-wise 3D Gaussians [S1, unofficial].
4.  **Voxelization:** The pixel-wise Gaussians are voxelized into pre-voxel 3D Gaussians via a Differentiable Voxelization module [S1, unofficial].
5.  **Rendering:** Multi-view images and depth maps are rendered from the voxelized Gaussians [S1, unofficial].
6.  **Supervision (RGB):** Rendered images are supervised against ground truth images using an RGB loss [S1, unofficial].
7.  **Supervision (Geometry):** Geometry losses are computed using rendered depth maps, decoded depth $D$, and poses $p$ [S1, unofficial].
8.  **Priors:** Geometries are supervised by pseudo-geometry priors obtained from a pretrained VGGT model [S1, unofficial].

## Subtopics

### [SubSplat](13524-subsplat.md)
SubSplat is a method for high-resolution novel-view synthesis that resolves the trade-off between network computational cost and rendering fidelity in pixel-aligned 3D Gaussian Splatting. It solves the problem of insufficient Gaussian density and artifacts when using low-resolution backbone inputs by introducing a Sub-pixel Gaussian Reparameterizer (SPGR). Unlike prior methods limited by fixed grids or image-space upsamplers, SubSplat subdivides each grid-anchored primary Gaussian into multiple fine-grained sub-pixel primitives, restoring structural density directly from low-resolution features while maintaining stable network latency.

### [Deformable Radial Kernel (DRK)](13699-deformable-radial-kernel-drk.md)
Deformable Radial Kernel (DRK) Splatting is a 3D scene representation method that replaces the fixed radial symmetry of Gaussian primitives with a flexible planar kernel defined by multiple radial basis functions. It solves the overparameterization and geometric fidelity limitations of Gaussian Splatting by allowing adaptive stretching, rotation, and sharp boundary control, enabling high-fidelity rendering with significantly fewer primitives. Unlike standard 2D Gaussian Splatting, which relies on smooth, elliptical distributions, DRK supports straight edges and sharp corners through L1/L2 norm blending and piecewise edge sharpening.

## Operating characteristics

*   **Memory Complexity:** Not specified in the sources [G].

*   **Strengths:** Handles uncalibrated inputs; no iterative optimization required; feed-forward efficiency [S1, unofficial].
*   **Limitations:** Relies on pretrained VGGT for pseudo-geometry priors; specific rendering quality metrics (e.g., PSNR, SSIM) are not provided in the sources [G].

*   **When not to use:** When iterative optimization for higher fidelity is acceptable and camera poses are known [G].

## Background
AnySplat is developed by InternRobotics and released as an open-source project [S1, unofficial]. It builds on the principles of 3D Gaussian Splatting and feed-forward generalizable reconstruction, aiming to extend these to unconstrained view scenarios [S1, unofficial]. The method utilizes a pretrained VGGT model for geometry priors [S1, unofficial].
