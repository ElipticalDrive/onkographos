# Environment Map Generation from Gaussian Background

Also called: Baking Gaussian Background to EnvMap, SH0 Environment Map Extraction

## Overview
This method converts the distant background components of a 3D Gaussian Splatting scene into a static 2D equirectangular environment map, replacing explicit Gaussian primitives in those regions [S1]. It solves the rendering overhead and visual instability (floaters) associated with distant background Gaussians in interactive applications like VR [S1]. It is distinguished from sibling methods like [DeSplat](12925-desplat.md) or [360 Gaussian Splatting](12929-360-gaussian-splatting.md) by explicitly decoupling the scene into a dynamic foreground (Gaussians) and a static background (EnvMap), trading motion parallax for performance and stability [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A trained 3D Gaussian Splatting scene model containing a set of Gaussians $\mathcal{G}$, each defined by position $\mathbf{t}$, covariance $\mathbf{\Sigma}$ (or rotation $\mathbf{R}$ and scale $\mathbf{S}$), opacity $\alpha$, and spherical harmonic coefficients $\mathbf{c}_{lm}$ for view-dependent color [S1].
*   **Output:** A static equirectangular environment map texture $E$ of resolution $8192 \times 4096$ pixels, and a modified scene representation where background Gaussians are removed [S1].

**Data Structures:**
*   **Environment Map:** A 2D texture of size $8192 \times 4096$ pixels (8K equirectangular) storing RGB color values [S1].
*   **Gaussian Sets:** The foreground set $\mathcal{G}_{FG}$ is retained for active rendering. The background set $\mathcal{G}_{BG}$ is discarded or marked inactive after baking [S1].

**Parameters:**
*   **Resolution:** $8192 \times 4096$ pixels [S1].
*   **Foreground/Background Threshold ($R_i$):** A distance cutoff from the camera origin. Gaussians with centers beyond $R_i$ are classified as background. The rendering effect of Gaussians is limited beyond 20 meters, making $R_i = 20$ m a typical value, though it can be adjusted to preserve parallax for specific mid-distance regions [S1].

**Steps:**
1.  **Segmentation:** Partition $\mathcal{G}$ into foreground $\mathcal{G}_{FG}$ and background $\mathcal{G}_{BG}$ based on the Euclidean distance of each Gaussian's center $\mathbf{t}_i$ from the camera origin.
    $$ \mathcal{G}_{BG} = \{ g_i \in \mathcal{G} \mid \|\mathbf{t}_i\| > R_i \} $$
    $$ \mathcal{G}_{FG} = \{ g_i \in \mathcal{G} \mid \|\mathbf{t}_i\| \le R_i \} $$
2.  **SH0 Extraction:** For each Gaussian $g_i \in \mathcal{G}_{BG}$, retain only the base spherical harmonic band (SH0) to represent the view-independent base color $c_0$ [S1].
3.  **Rasterization/Baking:** Render $\mathcal{G}_{BG}$ onto an equirectangular projection by mapping Gaussian centers to spherical coordinates and splatting them onto the 2D grid [S1].
    *   For each pixel $(u, v)$ in the $8192 \times 4096$ map, compute the corresponding view direction $\mathbf{d}_{uv}$.
    *   Sort contributing $\mathcal{G}_{BG}$ Gaussians by depth along $\mathbf{d}_{uv}$.
    *   Accumulate contributions using standard alpha compositing:
        $$ C_{bg}(u,v) = \sum_{i \in \mathcal{G}_{BG}} \alpha_i \cdot c_{0,i} \cdot \prod_{j < i} (1 - \alpha_j) $$
        where the sum iterates over depth-sorted Gaussians, $\alpha_i$ is opacity, and $c_{0,i}$ is the SH0 color [S1].
4.  **Texture Generation:** Store the accumulated color $C_{bg}(u,v)$ into the environment map texture $E$ [S1].
5.  **Scene Update:** Remove $\mathcal{G}_{BG}$ from the active rendering list. The renderer uses $\mathcal{G}_{FG}$ for near-field rendering and samples $E$ for the background [S1].

**Pseudocode:**
```python
import math

def generate_env_map(gaussians, R_i, width=8192, height=4096):
    # Step 1: Segment Gaussians by distance from camera origin
    bg_gaussians = [g for g in gaussians if math.sqrt(sum(c**2 for c in g.center)) > R_i]
    
    # Step 2: Initialize Environment Map
    env_map = [[0.0, 0.0, 0.0] for _ in range(height * width)]
    
    # Step 3: Bake Gaussians to Equirectangular Map
    for v in range(height):
        for u in range(width):
            # Map pixel to spherical coordinates
            lon = (u / width) * 2 * math.pi - math.pi
            lat = (v / height) * math.pi - math.pi / 2
            # Convert to Cartesian view direction
            dir_x = math.cos(lat) * math.sin(lon)
            dir_y = math.sin(lat)
            dir_z = math.cos(lat) * math.cos(lon)
            view_dir = (dir_x, dir_y, dir_z)
            
            # Sort background Gaussians by depth along view direction
            sorted_bg = sorted(bg_gaussians, key=lambda g: g.center[0]*view_dir[0] + g.center[1]*view_dir[1] + g.center[2]*view_dir[2])
            
            accumulated_color = [0.0, 0.0, 0.0]
            accumulated_alpha = 0.0
            
            for g in sorted_bg:
                # Extract SH0 color (view-independent base color)
                color = g.sh_coeffs[0]
                alpha = g.opacity
                
                # Project 3D Gaussian to 2D tangent plane at view_dir [G]
                center_dir = (g.center[0]/math.sqrt(sum(c**2 for c in g.center)), 
                              g.center[1]/math.sqrt(sum(c**2 for c in g.center)), 
                              g.center[2]/math.sqrt(sum(c**2 for c in g.center)))
                cos_angle = center_dir[0]*view_dir[0] + center_dir[1]*view_dir[1] + center_dir[2]*view_dir[2]
                cos_angle = max(-1.0, min(1.0, cos_angle))
                angle = math.acos(cos_angle)
                
                # Approximate angular spread for spherical splatting [G]
                depth = g.center[0]*view_dir[0] + g.center[1]*view_dir[1] + g.center[2]*view_dir[2]
                if depth <= 0:
                    continue
                sigma_ang = g.scale / depth
                pdf = math.exp(-0.5 * (angle / sigma_ang)**2) / (2 * math.pi * sigma_ang**2)
                
                contribution = alpha * pdf
                if contribution <= 0:
                    continue
                
                # Alpha compositing
                new_alpha = accumulated_alpha + contribution * (1.0 - accumulated_alpha)
                if new_alpha > 0:
                    accumulated_color = [
                        (accumulated_color[0] * accumulated_alpha + color[0] * contribution * (1.0 - accumulated_alpha)) / new_alpha,
                        (accumulated_color[1] * accumulated_alpha + color[1] * contribution * (1.0 - accumulated_alpha)) / new_alpha,
                        (accumulated_color[2] * accumulated_alpha + color[2] * contribution * (1.0 - accumulated_alpha)) / new_alpha
                    ]
                accumulated_alpha = new_alpha
            
            env_map[v * width + u] = accumulated_color
            
    return env_map
```
*[G] The pseudocode implements standard 3D-to-spherical projection and 2D Gaussian evaluation in the tangent plane, which is required to correctly splat 3D Gaussians onto an equirectangular grid.*

**Edge Cases and Pitfalls:**
*   **Parallax Artifacts:** A static environment map cannot reproduce motion parallax for mid-distance objects, causing standard metrics (PSNR/SSIM) to drop compared to ground truth, though it remains acceptable in VR [S1].
*   **Visual Gap:** A visual gap may appear at the boundary $R_i$ under certain viewing conditions, particularly when the camera moves outside the intended navigation area. This can be mitigated with soft transitions or distance-based alpha blending [S1].
*   **Floaters:** The method produces a floater-free background, avoiding pop-up effects common in distant Gaussian reconstructions [S1].

## Operating characteristics
*   **Time Complexity:** Rendering time is significantly reduced. Replacing background Gaussians with an environment map reduces average frame time and increases throughput, as background Gaussians introduce significant rendering overhead even when visually static [S1].
*   **Memory Complexity:** Memory usage is reduced by removing $\mathcal{G}_{BG}$ from the active Gaussian list. The environment map texture ($8192 \times 4096 \times 3$ bytes $\approx 100$ MB for 32-bit float, or less for 16-bit) is added to memory footprint.
*   **Performance:** The method boosts rendering throughput, making it suitable for interactive VR navigation [S1].
*   **Strengths:** Floater-free background, reduced rendering overhead, stable frame rates in VR.
*   **Limitations:** Loss of motion parallax for mid-distance objects, potential visual gaps at $R_i$, lower PSNR/SSIM for distant regions compared to ground truth [S1].
*   **When to Use:** Interactive VR applications, semi-bounded environments with well-defined navigation areas, scenes with significant distant background elements that cause floaters or performance issues.
*   **When Not to Use:** Applications requiring precise motion parallax for mid-distance objects, or where high-fidelity novel view synthesis metrics for distant regions are critical.

## Background
The method originates from the work on "EnvMap-GS: two-stage outdoor Gaussian reconstruction with background-to-environment map baking" by D. Pintani et al. [S1]. It addresses the challenges of rendering large-scale outdoor scenes with 3D Gaussian Splatting, where distant background elements often suffer from noise (floaters) and high computational cost. By baking the background into a static environment map, the method leverages the efficiency of traditional environment map rendering while maintaining the high-quality foreground reconstruction of 3DGS.
