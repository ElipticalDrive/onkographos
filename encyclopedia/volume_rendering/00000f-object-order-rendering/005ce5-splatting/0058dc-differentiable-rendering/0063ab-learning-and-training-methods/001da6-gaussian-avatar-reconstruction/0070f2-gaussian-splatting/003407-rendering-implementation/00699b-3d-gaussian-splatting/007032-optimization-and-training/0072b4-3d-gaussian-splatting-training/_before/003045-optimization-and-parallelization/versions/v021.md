# Optimization and Parallelization

Also called: Distributed Training, Gradient Parallelization

## Overview
This family encompasses the computational strategies required to efficiently train 3D Gaussian Splatting (3DGS) models, focusing on the distribution of the backward pass and the management of large-scale parameter sets. It addresses the bottleneck where standard per-pixel backpropagation becomes computationally prohibitive for high-resolution scenes or large Gaussian counts . It sets itself apart from sibling methods by focusing on the *distribution* of the optimization workload (across splats or GPUs) rather than specific parameter update rules or loss function variants.

## Shared principles
The training process relies on a differentiable rasterizer that renders images from a set of 3D Gaussians. The core optimization mechanism involves computing the gradient of a loss function $\mathcal{L}$ (e.g., L1, SSIM) with respect to the Gaussian parameters (position, covariance, opacity, color, SH coefficients) and any auxiliary parameters.

Key shared mathematical components include:
1.  **Alpha Blending**: The color contribution of a Gaussian $i$ is modulated by its opacity $\alpha_i$ and transmittance $T_i$ from preceding Gaussians.
2.  **Gradient Propagation**: Gradients flow from the loss through the pixel color, through the alpha-blending chain, to the individual Gaussian attributes.
3.  **Parallelization Granularity**: Computation is parallelized across pixels, splats (Gaussians), or batches of views. The standard approach is per-pixel backpropagation, but alternatives exist .
4.  **Memory Management**: Large scenes require managing the Gaussian list in memory, potentially across multiple GPUs or via out-of-core techniques.

## Subtopics

### [MaskGaussian Gradient Computation](4254-maskgaussian-gradient-computation.md)
Computes gradients for probabilistic masks $\mathcal{M}_i$ that modulate Gaussian opacity. It differs from standard backpropagation by explicitly accounting for the interaction between mask-modulated Gaussian contributions and the background color contribution, which is modulated by the final transmittance. Choose this when using adaptive representation or pruning strategies that rely on mask parameters.

### [Training Pipeline](5325-training-pipeline.md)
Defines the high-level iterative loop: view sampling, rasterization, loss computation, and parameter updates. It differs from siblings by orchestrating the training state, including periodic densification and pruning, rather than focusing on specific gradient computations or parallelization strategies. Choose this as the foundational control flow for any 3DGS training implementation.

### [Parallelization for Backpropagation](5989-parallelization-for-backpropagation.md)
Shifts the computational granularity from per-pixel to per-splat (per-Gaussian) to accelerate gradient computation. It addresses training speed obstacles by restructuring the backward pass into a numerically equivalent but faster formulation. Choose this when per-pixel backpropagation is too slow for the target hardware or scene size.

### [Grendel-GS](7349-grendel-gs.md)
A distributed optimization framework that partitions the global set of Gaussian primitives across multiple GPUs. It enables the training of large scenes by allowing each GPU to render its local subset and combining results via inter-GPU communication. Unlike [TideGS](7350-tidegs.md), which streams data from disk on a single GPU, Grendel-GS distributes the parameter store across a multi-GPU cluster. Choose this when single-GPU memory limits prevent training on the available dataset.

### [3D Gaussian Splatting Implementation Details](9128-3d-gaussian-splatting-implementation-details.md)
Provides concrete hyperparameters, data structure layouts, and algorithmic variants (e.g., half-precision rasterization, scene extent calculation) required for effective training. It sets itself apart by providing step-by-step procedures for specific variants like selective defocus blurring and internal rendering. Choose this for the specific engineering configurations needed to stabilize and accelerate the training loop.

## Background
The optimization strategies for 3D Gaussian Splatting evolved from the original 3DGS paper , which introduced the differentiable rasterizer and Adam optimizer. Subsequent works addressed scalability: MaskGaussian introduced mask-based gradients for adaptive control ; Parallelization for Backpropagation optimized the backward pass kernel ; Grendel-GS addressed multi-GPU scaling ; and implementation details were refined to handle half-precision stability and scene extent biases .
