# VastGaussian


## Overview
VastGaussian is a large-scale 3D Gaussian Splatting method that partitions a scene into spatially-disjoint regions to enable scalable training and rendering of massive environments [S2, S3, unofficial]. It solves the memory and computational bottlenecks of global optimization by decoupling appearance handling for varying lighting conditions across regions and merging results with feathered overlap [S2, unofficial]. It distinguishes itself from naive spatial splitting by using a visibility-aware iterative training strategy and explicit appearance embeddings to handle the complex lighting variations found in large-scale urban scenes [S3, unofficial].

## How it works
**Inputs:** A set of images with known camera poses covering a large-scale scene.
**Outputs:** A set of 3D Gaussians organized into spatially-disjoint blocks, along with per-view appearance embeddings.

**Data Structures:**
1.  **Region Partition:** The scene is divided into spatially-disjoint regions. The partitioning logic is based on the distribution of training cameras projected onto the ground plane [S3, unofficial].
2.  **Block Model:** Each region contains an independent set of 3D Gaussians (position, covariance, opacity, spherical harmonics coefficients) and an associated appearance embedding vector [S1, S3, unofficial].
3.  **Appearance Embedding:** An optimizable vector per view (or per region-view pair) that modulates the color output to account for lighting changes [S3, unofficial].

**Steps:**
1.  **Partitioning:** Divide the scene into spatially-disjoint regions based on the spatial distribution of input cameras projected onto the ground [S3, unofficial].
2.  **Initialization:** Initialize 3D Gaussians for each region independently.
3.  **Iterative Training:**
    *   For each region, train the 3D Gaussians and the appearance embeddings.
    *   The training process iteratively adds more viewpoints into the training set based on visibility criteria to ensure sufficient supervision [S3, unofficial].
    *   The appearance embedding is optimized to model appearance changes across different views [S3, unofficial].
4.  **Merging:** At rendering time, combine the Gaussians from all regions. Handle overlapping areas using a feathered overlap technique to ensure smooth transitions between regions [S2, unofficial].

**Formulas:**
*   **Appearance Modulation:** The final color $C$ for a pixel is computed by modulating the base Gaussian color with the appearance embedding $E_v$ for view $v$. The specific modulation function is not detailed in the sources, but it is described as an "optimizable appearance embedding" [S3, unofficial].
*   **Partitioning Criterion:** Regions are defined by camera distribution projected onto the ground [S3, unofficial]. Exact geometric boundaries are not specified beyond "spatially-disjoint" [S2, unofficial] and "overlapping blocks" [S1, unofficial] (note: S1 describes VastGaussian as overlapping blocks, while S2/S3 describe spatially-disjoint regions; this discrepancy is noted in Operating Characteristics).

**Parameters:**
*   **Region Size:** Not given in the sources.
*   **Feathering Width:** Not given in the sources.
*   **Embedding Dimension:** Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Boundary Artifacts:** If the feathered overlap is not implemented correctly, visible seams may appear at region boundaries [S2, unofficial].
*   **Visibility Gaps:** If the iterative viewpoint addition does not cover all areas, some regions may be under-supervised, leading to artifacts [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** Training is parallelized across regions, reducing per-GPU time compared to global optimization [S2, unofficial]. The iterative viewpoint addition adds overhead but ensures convergence [S3, unofficial].
*   **Memory Complexity:** Memory usage is bounded by the size of the largest region, allowing reconstruction of scenes that exceed single-GPU memory [S2, unofficial].
*   **Measured Performance:** Not given in the sources.
*   **Strengths:** Scalable to large-scale urban scenes; handles varying lighting via appearance embeddings [S2, S3, unofficial].
*   **Limitations:** Requires careful handling of region boundaries; partitioning quality depends on camera distribution [S3, unofficial].
*   **When to Use:** Large-scale scenes with significant lighting variations and limited GPU memory.
*   **When Not to Use:** Small-scale scenes where global optimization is feasible and faster.

**Discrepancy Note:** Source [S1, unofficial] describes VastGaussian as partitioning into "overlapping blocks," while [S2, unofficial] and [S3, unofficial] describe it as "spatially-disjoint regions." This article assumes the disjoint region model with feathered merging as described in [S2, S3, unofficial], as it aligns with the iterative training and appearance embedding details.

## Background
VastGaussian was introduced in CVPR'24 [S2, unofficial]. It was developed to address the scalability challenges of 3D Gaussian Splatting in large-scale environments, such as city scenes [S2, S3, unofficial]. It builds on the divide-and-conquer strategy used in methods like City-Gaussian [S1, unofficial].
