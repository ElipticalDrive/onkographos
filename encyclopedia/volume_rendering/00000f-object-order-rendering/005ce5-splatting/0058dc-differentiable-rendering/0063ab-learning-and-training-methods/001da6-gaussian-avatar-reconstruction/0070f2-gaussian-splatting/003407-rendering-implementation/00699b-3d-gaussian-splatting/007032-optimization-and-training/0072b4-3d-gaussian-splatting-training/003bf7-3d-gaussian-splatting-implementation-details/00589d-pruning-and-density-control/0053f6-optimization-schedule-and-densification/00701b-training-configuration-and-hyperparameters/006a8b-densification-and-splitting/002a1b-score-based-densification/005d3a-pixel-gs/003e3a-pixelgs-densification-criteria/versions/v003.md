# PixelGS Densification Criteria

Also called: Pixel-aware and Depth-scaled Gradient Densification

## Overview
PixelGS modifies the gradient-based densification criteria of 3D Gaussian Splatting to account for the number of pixels each Gaussian influences and scales the gradient by depth to encourage densification in background regions [S1]. It sets apart from standard 3D-GS by weighting the positional gradient norm by the visible pixel count and a depth-dependent factor, ensuring that large Gaussians in background regions are densified less frequently despite potentially high positional gradients [S1].

## How it works
**Inputs and Outputs**
*   **Input:** For each Gaussian $k$ and each training view $\nu$, the 2D positional gradient norm $\left\| \frac{\partial \mathcal{L}(I_\nu, f'_\nu)}{\partial \mu_k^\nu} \right\|_2$, the pixel count $\text{count}(g_k^\nu)$ influenced by the Gaussian in view $\nu$, the image depth $\text{depth}(g_k^\nu)$ of the rendered splat, the scene extent $e_{\text{scene}}$, and the hyperparameter $\gamma$.
*   **Output:** The refined densification score $\tau'_k$ for Gaussian $k$.

**Data Structures**
No specific data structures are required beyond standard per-Gaussian accumulators for the numerator and denominator of the refined gradient score across all views.

**Parameters**
*   $\gamma$: Depth scaling hyperparameter. Default value is 0.37 [S1].
*   $e_{\text{scene}}$: The extent of the scene (e.g., bounding box diagonal or max depth range) [S1].

**Steps**
1.  For each training view $\nu = 1 \dots N_{\text{views}}$:
    a. Compute the depth-scaling factor $f_k^\nu$ for Gaussian $k$:
       $$f_k^\nu = \text{clip} \left( \frac{\text{depth}(g_k^\nu)}{\gamma \cdot e_{\text{scene}}}, [0, 1] \right)$$
       where $\text{depth}(g_k^\nu)$ is the image depth of the rendered splat [S1].
    b. Retrieve the pixel count $\text{count}(g_k^\nu)$, which is the number of pixels in view $\nu$ influenced by Gaussian $k$ [S1].
    c. Retrieve the 2D positional gradient norm $\left\| \frac{\partial \mathcal{L}(I_\nu, f'_\nu)}{\partial \mu_k^\nu} \right\|_2$ [S1].
    d. Accumulate the weighted gradient term: $N_k \leftarrow N_k + f_k^\nu \cdot \text{count}(g_k^\nu) \cdot \left\| \frac{\partial \mathcal{L}(I_\nu, f'_\nu)}{\partial \mu_k^\nu} \right\|_2$.
    e. Accumulate the pixel count term: $D_k \leftarrow D_k + \text{count}(g_k^\nu)$.
2.  Compute the refined gradient score:
    $$\tau'_k = \frac{N_k}{D_k}$$
    where $N_k$ is the sum of weighted gradient norms and $D_k$ is the sum of pixel counts across all views [S1].

**Pseudocode**
```python
def compute_pixelgs_densification_score(gaussian_k, views, gamma, scene_extent):
    """
    Computes the PixelGS densification score for a single Gaussian across multiple views.
    
    Args:
        gaussian_k: Object representing the Gaussian primitive.
        views: List of view objects, each containing:
            - view_id: Identifier for the view.
            - get_pixel_count(g): Function returning the number of pixels influenced by g in this view.
            - get_rendered_depth(g): Function returning the image depth of the splat of g in this view.
            - get_pos_gradient_norm(g): Function returning the L2 norm of the positional gradient for g.
        gamma: Depth scaling hyperparameter (default 0.37).
        scene_extent: The extent of the scene (e.g., max depth or bounding box diagonal).
        
    Returns:
        tau_prime_k: The refined densification score.
    """
    numerator = 0.0
    denominator = 0.0
    
    for view in views:
        # Step 1a: Compute depth-scaling factor
        depth_val = view.get_rendered_depth(gaussian_k)
        depth_factor = depth_val / (gamma * scene_extent)
        # Clip to [0, 1]
        depth_factor = max(0.0, min(1.0, depth_factor))
        
        # Step 1b: Get pixel count
        pixel_count = view.get_pixel_count(gaussian_k)
        
        # Step 1c: Get positional gradient norm
        grad_norm = view.get_pos_gradient_norm(gaussian_k)
        
        # Step 1d & 1e: Accumulate
        numerator += depth_factor * pixel_count * grad_norm
        denominator += pixel_count
        
    # Step 2: Compute final score
    if denominator == 0:
        return 0.0
    tau_prime_k = numerator / denominator
    
    return tau_prime_k
```

**Edge Cases and Pitfalls**
*   **Division by Zero:** If a Gaussian influences zero pixels across all views, the denominator is zero. The score should be handled as zero or ignored for densification [G].
*   **Depth Scaling:** The depth value must be consistent with the definition of $e_{\text{scene}}$. If $e_{\text{scene}}$ is not defined consistently with the depth metric, the scaling factor $f_k^\nu$ may be incorrect [S1].
*   **Precision:** Accumulating sums over many views may require double precision to avoid loss of significance if pixel counts or gradient norms vary widely in magnitude [G].

## Subtopics

### [AbsGS Gradient Densification](22906-absgs-gradient-densification.md)
AbsGS Gradient Densification is a strategy for 3D Gaussian Splatting that eliminates gradient collision by computing the homodirectional view-space positional gradient. It uses the absolute value of per-pixel gradient components before summing, ensuring all pixel contributions reinforce the magnitude rather than canceling out due to direction differences. This accurately identifies over-reconstructed Gaussians that standard gradient magnitude misses. Unlike standard 3D-GS, which sums signed gradients and risks cancellation, AbsGS sums absolute values per axis, providing a more robust signal for splitting large, over-reconstructed Gaussians [22906-absgs-gradient-densification.md].

### PixelGS-ours hybrid
A densification aggregation rule that replaces PixelGS's visible-pixel count weight with the average-contribution signal, while retaining PixelGS's weighted-mean gradient structure [S2, unofficial]. The per-view total contribution is computed as $W_{i,v} = \sum_p w_{i,p}$. The densification score is the weighted mean of per-view gradient norms: $\gamma_i = \frac{\sum_v W_{i,v} \|g_{i,v}\|}{\sum_v W_{i,v}}$ [S2, unofficial]. The densification threshold is 0.0003, selected by sweeping thresholds on the Mip-NeRF360 subset to find the operating point [S2, unofficial]. Under the weighted-mean aggregation, the hybrid over-densifies heavily (6.4M Gaussians vs 6.6M for raw PixelGS) and diverges on 3 of 4 Zip-NeRF scenes under a 100k training schedule. The same contribution signal routed through the baseline's sum-and-normalize rule stays compact (1.1M Gaussians) and stable [S2, unofficial].

## Operating characteristics
PixelGS yields state-of-the-art rendering quality but at the cost of considerably more Gaussian primitives compared to the proposed method in [S1]. The method increases computational overhead during training due to the per-pixel gradient accumulation and depth scaling calculations [S1].

## Background
PixelGS was proposed by Zhang et al. in 2024, building on similar ideas from Bulo et al. (2024) [S1]. It is part of the evolution of adaptive density control in 3D Gaussian Splatting, aiming to improve reconstruction quality by addressing the limitations of standard gradient-based densification in handling background regions and large Gaussians [S1].
