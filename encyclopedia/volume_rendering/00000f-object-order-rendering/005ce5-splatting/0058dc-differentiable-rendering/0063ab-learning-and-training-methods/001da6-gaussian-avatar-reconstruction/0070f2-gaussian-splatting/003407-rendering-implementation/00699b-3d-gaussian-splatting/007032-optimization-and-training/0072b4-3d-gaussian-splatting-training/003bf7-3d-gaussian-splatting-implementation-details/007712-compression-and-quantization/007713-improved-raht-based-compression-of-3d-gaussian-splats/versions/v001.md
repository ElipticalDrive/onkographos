# Improved RAHT-based Compression of 3D Gaussian Splats

Also called: RAHT-based Compression for 3DGS

## Overview
This method compresses pre-trained 3D Gaussian Splatting (3DGS) models by treating them as point clouds with rich attributes, applying the Region-Adaptive Hierarchical Transform (RAHT) to decorrelate data and promote sparsity [S1]. It distinguishes itself from sibling methods like [Codebook Quantization](23296-codebook-quantization.md) and [MesonGS](23296-codebook-quantization.md) by systematically applying transform coding to *all* Gaussian attributes rather than a subset, and by requiring no changes to the training pipeline or additional side information in the bitstream, unlike [Scaffold-GS](23296-codebook-quantization.md) [S1].

## How it works
**Inputs:** A trained 3DGS scene representation consisting of $N$ Gaussians, each defined by mean $\mu \in \mathbb{R}^3$, scale $s \in \mathbb{R}^3$, rotation $q \in \mathbb{R}^4$ (quaternion), opacity $\alpha \in \mathbb{R}$, and spherical harmonic (SH) coefficients for view-dependent color.
**Outputs:** A compressed bitstream containing geometry, attributes, and metadata.

### Data Structures
1.  **Gaussian Pruning List:** A list of Gaussian indices to retain after importance-based pruning.
2.  **Octree:** A hierarchical spatial data structure used to voxelize Gaussian means. The depth $d$ is a parameter selected to balance Gaussian preservation and rendering distortion.
3.  **Attribute Blocks:** Each attribute channel is partitioned into blocks based on Morton ordering (Z-order curve) of the voxelized positions to ensure spatial coherence.
4.  **Bitstream:** Contains:
    *   Geometry: Octree structure encoded via MPEG GPCC.
    *   Attributes: Quantized RAHT coefficients.
    *   Metadata: Quantization parameters per channel, pruning mask, and Octree depth.

### Steps

1.  **Gaussian Pruning:**
    Remove redundant Gaussians generated during the baseline 3DGS training [S1]. Compute an importance score $I$ for each Gaussian as the product of a view-dependent score $I_d$ and a view-independent score $I_i$ derived from the Gaussian's volume [S1]. Discard Gaussians with the lowest scores.

2.  **Geometry Voxelization and Encoding:**
    Voxelize the 3D positions ($\mu$) of the remaining Gaussians using an Octree structure. Select the Octree depth $d$ to preserve most Gaussians while minimizing rendering distortion [S1]. Encode the geometry bitstream using the MPEG GPCC codec [S1].

3.  **Attribute Pre-processing:**
    For Gaussians merged or grouped during voxelization, average their attributes [S1]. Replace the rotation quaternion $q \in \mathbb{R}^4$ with an Euler angle representation $e \in \mathbb{R}^3$ to reduce dimensionality [S1].

4.  **Fine-Tuning:**
    Perform a short fine-tuning of the 3DGS parameters. This step balances the rate-distortion (RD) tradeoff and improves compression efficiency by promoting sparsity in the subsequent transform domain [S1]. [G] This typically involves a few iterations of gradient descent on the training images with a regularization term favoring small attribute values or sparsity, without altering the scene geometry significantly.

5.  **RAHT Transform:**
    Partition each attribute channel into blocks based on Morton ordering of the voxelized positions. Apply the RAHT transform independently to each attribute channel. RAHT operates along the Octree hierarchy, applying successive transforms across spatial axes to decorrelate neighboring attribute values [S1].

6.  **Channel-wise Bit Allocation and Quantization:**
    Quantize each block independently using uniform scalar quantizers. A distinct quantization parameter (bit depth) is chosen per channel based on its rendering impact [S1].
    
    To determine the bit depth $b_i$ for attribute $i$, analyze the rendering distortion $D_{render}$ as a function of per-channel bitrate $R_i$:
    $$ D_{render} = f(R_i), \quad i \in [1, n_{attr}] $$
    where $n_{attr}$ is the number of attribute channels [S1].
    
    Procedure for determining $b_i$:
    *   Fix the bit length for all other attributes $j \neq i$ to 8 bits.
    *   Test attribute $i$ with bit depths $b \in \{2, 4, 6, 8, 16, 32\}$ [S1].
    *   Plot the RD curve. Select $b_i$ where the curve saturates (additional precision yields negligible quality improvement) or where the slope indicates high sensitivity to coarse quantization [S1]. For example, rotation may saturate around 8 bits, while second-order SH coefficients may saturate at lower bitrates [S1].

7.  **Entropy Coding:**
    Entropy code all data (geometry, quantized attributes, and metadata) using the deflate algorithm to produce the final bitstream [S1].

### Pseudocode

```python
def compress_3dgs(gaussians, training_images, validation_set):
    """
    Compress a 3DGS model using Improved RAHT-based Compression.
    
    Args:
        gaussians: List of Gaussian objects with attributes (mu, s, q, alpha, sh).
        training_images: List of training views for pruning and fine-tuning.
        validation_set: Validation views for RD curve analysis.
        
    Returns:
        bitstream: Compressed data.
    """
    # Step 1: Gaussian Pruning
    # Compute importance score I = I_d * I_i
    # I_d: view-dependent score (rendering relevance)
    # I_i: view-independent score (volume-based)
    importance_scores = compute_importance_scores(gaussians, training_images)
    pruned_gaussians = prune_gaussians(gaussians, importance_scores, threshold=0.95) # [G] threshold example
    
    # Step 2: Geometry Voxelization
    # Select Octree depth d to minimize distortion
    octree_depth = select_octree_depth(pruned_gaussians, validation_set)
    voxelized_positions = voxelize(pruned_gaussians.mu, octree_depth)
    
    # Encode geometry using MPEG GPCC
    geometry_bitstream = mpeg_gpcc_encode(voxelized_positions)
    
    # Step 3: Attribute Pre-processing
    # Average attributes for merged Gaussians (handled by voxelization structure)
    # Replace quaternion q with Euler angles e
    processed_gaussians = replace_quaternion_with_euler(pruned_gaussians)
    
    # Step 4: Fine-Tuning
    # Short fine-tuning to promote sparsity in transform domain
    fine_tuned_gaussians = fine_tune(processed_gaussians, training_images, iterations=10) # [G] iterations example
    
    # Step 5: RAHT Transform
    # Partition attributes into blocks based on Morton ordering
    attribute_blocks = partition_by_morton_order(fine_tuned_gaussians, voxelized_positions)
    
    # Apply RAHT to each attribute channel
    raht_coefficients = {}
    for attr_name in fine_tuned_gaussians.attribute_names:
        raht_coefficients[attr_name] = apply_raht(attribute_blocks[attr_name])
        
    # Step 6: Channel-wise Bit Allocation
    # Determine optimal bit depth for each attribute
    quantization_params = {}
    for attr_name in fine_tuned_gaussians.attribute_names:
        # Fix other attributes to 8 bits
        other_attrs_fixed = {k: 8 for k in fine_tuned_gaussians.attribute_names if k != attr_name}
        
        # Test bit depths b in {2, 4, 6, 8, 16, 32}
        rd_curve = []
        for b in [2, 4, 6, 8, 16, 32]:
            # Quantize attr_name with b bits, others with fixed bits
            quantized = quantize(raht_coefficients, attr_name, b, other_attrs_fixed)
            # Decode and render
            decoded_gaussians = decode_and_render(quantized, geometry_bitstream)
            distortion = compute_rendering_distortion(decoded_gaussians, validation_set)
            rd_curve.append((b, distortion))
            
        # Select bit depth based on saturation/slope
        quantization_params[attr_name] = select_optimal_bit_depth(rd_curve)
        
    # Quantize all attributes with determined parameters
    final_quantized = quantize(raht_coefficients, quantization_params)
    
    # Step 7: Entropy Coding
    metadata = {
        'octree_depth': octree_depth,
        'quantization_params': quantization_params,
        'pruning_mask': get_pruning_mask(pruned_gaussians)
    }
    
    bitstream = deflate_encode(geometry_bitstream, final_quantized, metadata)
    return bitstream
```

### Edge Cases and Pitfalls
*   **Precision:** Quantization parameters must be chosen carefully to avoid visible artifacts. Attributes like rotation are sensitive to coarse quantization and may require higher bit depths (e.g., 8 bits) compared to SH coefficients [S1].
*   **Boundaries:** The Octree depth $d$ must be selected to avoid losing significant Gaussians. Too shallow a depth causes merging artifacts; too deep increases geometry bitrate [S1].
*   **Degenerate Input:** If the scene has very few Gaussians, the overhead of metadata and Octree structure may dominate the bitstream [G].

## Operating characteristics
*   **Time Complexity:** Dominated by the RAHT transform and the fine-tuning step. The RD curve analysis requires multiple render passes, increasing offline compression time [S1].
*   **Memory Complexity:** Requires storing the Octree structure and intermediate RAHT coefficients. Compatible with standard point cloud compression tools [S1].
*   **Performance:** Achieves competitive compression performance while maintaining compatibility with existing standard coding tools (MPEG GPCC, deflate) [S1].
*   **Strengths:** No training pipeline changes required; operates on pre-trained models; systematic bit allocation improves efficiency over naive uniform quantization [S1].
*   **Limitations:** Requires offline fine-tuning; RD curve analysis is computationally expensive for compression setup [S1].
*   **When to use:** When compressing pre-trained 3DGS models without access to training data or pipeline modifications [S1].
*   **When not to use:** When real-time compression is required or when training-time modifications are acceptable (e.g., Scaffold-GS) [S1].

## Background
The method was proposed in 2025 by researchers from the Laboratoire d'Informatique du Partage et des Systèmes (LIP6), France, as part of the PCS conference proceedings [S1]. It addresses the high storage and bandwidth costs of 3D Gaussian Splatting by leveraging established point cloud compression techniques (RAHT, MPEG GPCC) [S1]. Previous attempts using RAHT on 3DGS showed limited efficiency due to data redundancy and unstructured nature [S1]. This work improves upon [MesonGS](23296-codebook-quantization.md) by applying RAHT to all attributes and avoids the training pipeline changes of [Scaffold-GS](23296-codebook-quantization.md) [S1].
