# LinPrim Differentiable Rendering Pipeline

Also called: LinPrim Rendering, LinPrim rasterizer, Linear Primitive Rendering, Linear Primitives for Differentiable Volumetric Rendering, Octahedron Rendering

## Overview
LinPrim is a differentiable rendering method that replaces the Gaussian primitives of 3D Gaussian Splatting with convex polyhedra, specifically octahedra, to provide bounded, triangular geometry for volumetric scene representation [S1]. It solves the problem of approximating complex, view-dependent surfaces with primitives that have explicit geometric boundaries, enabling differentiable ray-triangle intersections for gradient-based optimization [S1]. Unlike its sibling [Duplex-GS](1988-duplex-gs.md) which uses dual representations, or [GsplatVolumeLighting](2203-gsplatvolumelighting.md) which focuses on lighting integration, LinPrim distinguishes itself by using linear primitives (octahedra) and computing opacity via the Beer-Lambert law based on ray traversal depth through the primitive [S1][S2, unofficial].

## How it works
The method employs a two-stage rendering process: per-primitive preprocessing followed by per-pixel rasterization [S1]. This structure allows for efficient parallelization of primitive construction and culling before the final compositing stage [S1].

### Inputs and Outputs
*   **Inputs:**
    *   Scene primitives defined by position, distances (defining shape), rotation, and Spherical Harmonic (SH) coefficients [S1].
    *   Camera pose (view matrix) and intrinsic parameters [S1].
    *   Screen resolution and tiling configuration [S1].
*   **Outputs:**
    *   Final 2D image with accumulated color and opacity [S1].

### Data Structures
Each primitive stores the following features [S1]:
1.  **Position:** 3D center coordinate $\mathbf{c} \in \mathbb{R}^3$.
2.  **Shape (Distances):** For octahedra, symmetry is enforced such that opposite vertices share the same distance from the center. This reduces the complexity of shape parameters [S1]. A regular octahedron is defined by distances along the principal axes.
3.  **Rotation:** Orientation of the primitive in 3D space [S1].
4.  **Color:** 48 SH coefficients (floats) to capture view-dependent reflectance [S1]. This accounts for the majority of memory per primitive [S1].
5.  **Opacity:** A scalar parameter $\alpha$ associated with the primitive [S1].

### Steps

1.  **Primitive Construction:**
    Construct the polyhedra (octahedra) from the concise set of features (position, distances, rotation) in a fully differentiable manner [S1]. The symmetry constraint ensures the center is the true geometric center, simplifying downstream bounding volume calculations [S1].

2.  **Preprocessing (Per-Primitive):**
    *   **Transformation:** Transform primitives into the camera's coordinate system using the camera pose [S1].
    *   **Color Calculation:** Calculate view-dependent color based on the viewing direction using the stored SH coefficients [S1].
    *   **Projection:** Project primitives into the 3D affine ray space approximation (EWA Splatting) [S1]. This approximation is valid because small primitives are used, keeping approximation error negligible [S1].
    *   **Bounding Box:** Compute the projected bounding box in screen space to determine visibility [S1].
    *   **L1-Slab Parameters:** Store the $L_1$-slab parameters of the projected octahedron [S2, unofficial].

3.  **Global Sorting and Tiling:**
    *   Tile the screen into regions [S1].
    *   Sort primitives within each tile according to an approximate front-to-back order, leveraging techniques from 3D Gaussian Splatting [S1].

4.  **Rasterization (Per-Pixel):**
    *   **Ray Reconstruction:** For each pixel $\mathbf{p}$, reconstruct the pixel ray using the $+0.5$ pixel-center convention [S2, unofficial].
    *   **Intersection Test:** Determine if the pixel ray intersects the convex primitive. Since primitives are convex, the ray intersects either twice or not at all [S1].
    *   **Möller-Trumbore Algorithm:** Use the Möller-Trumbore intersection algorithm (MTIA) to find the entry and exit points of the ray through the primitive's triangular faces [S1]. This algorithm is fully differentiable [S1].
    *   **Opacity Calculation:** If two intersections exist, calculate the opacity based on the distance between the intersection points [S1].
    *   **Normalization:** To handle scale ambiguity, normalize the intersection distances. Determine the smallest distance $d$ among all primitives and scale all distance measurements accordingly [S1].

5.  **Compositing:**
    *   Aggregate color contributions of all visible primitives via alpha blending in front-to-back order [S1].
    *   Stop blending once the cumulative opacity reaches a threshold of $0.999$ [S1].

### Formulas

**Density Definition:**
Given the opacity $\alpha$ and the normalized distances $d_x, d_y, d_z$ (where $d$ is the scaled distance), the density $\sigma$ is defined as [S1]:

$$
\sigma(\alpha) = -\frac{\log(1 - 0.99 \cdot \alpha)}{2 \cdot \min(d_x, d_y, d_z)}
$$

**Opacity from Beer-Lambert Law:**
The contribution of a primitive to a pixel is determined by the Beer-Lambert opacity derived from the ray's entry and exit depths through the octahedron [S2, unofficial]. Let $d_{entry}$ and $d_{exit}$ be the distances to the intersection points. The optical depth is proportional to the path length $L = d_{exit} - d_{entry}$. The transmission is $e^{-\sigma L}$.

### Pseudocode

```python
import math
import numpy as np

def linprim_render(primitives, camera, screen_width, screen_height):
    """
    Renders the scene using the LinPrim pipeline.
    
    Args:
        primitives: List of Primitive objects.
        camera: Camera object with pose and intrinsics.
        screen_width: int
        screen_height: int
        
    Returns:
        image: np.ndarray of shape (H, W, 3)
    """
    # 1. Preprocessing
    transformed_primitives = []
    for p in primitives:
        # Transform to camera space
        p_cam = transform_to_camera(p, camera.pose)
        
        # Calculate view-dependent color
        view_dir = get_view_direction(p_cam.position, camera.origin)
        color = evaluate_sh(p.sh_coeffs, view_dir)
        
        # Project to 3D affine ray space and compute bounding box
        # This determines the screen-space AABB for culling
        aabb = project_primitive(p_cam)
        
        # Store L1-slab parameters for rasterization
        slab_params = compute_l1_slab(p_cam)
        
        transformed_primitives.append({
            'primitive': p_cam,
            'color': color,
            'aabb': aabb,
            'slab_params': slab_params,
            'opacity': p.opacity,
            'distances': p.distances # Original distances for normalization
        })

    # 2. Global Sorting and Tiling
    # Tile the screen and sort primitives within each tile
    tiles = create_tiles(screen_width, screen_height)
    tile_primitives = {t: [] for t in tiles}
    
    for prim in transformed_primitives:
        # Determine which tiles the primitive's AABB overlaps
        overlapping_tiles = get_overlapping_tiles(prim['aabb'], tiles)
        for tile in overlapping_tiles:
            tile_primitives[tile].append(prim)
            
    # Sort primitives within each tile by depth (approximate front-to-back)
    for tile in tiles:
        tile_primitives[tile].sort(key=lambda x: x['primitive'].z_depth)

    # 3. Normalize distances for scale ambiguity
    # Find the minimum distance across all primitives
    min_d = min(min(p['distances']) for p in transformed_primitives)
    for prim in transformed_primitives:
        prim['normalized_distances'] = [d / min_d for d in prim['distances']]

    # 4. Rasterization and Compositing
    image = np.zeros((screen_height, screen_height, 3))
    
    for tile in tiles:
        for prim in tile_primitives[tile]:
            # Get pixels covered by the primitive's AABB
            pixels = get_pixels_in_aabb(prim['aabb'], tile)
            
            for px, py in pixels:
                # Reconstruct pixel ray using +0.5 convention
                ray = reconstruct_ray(px + 0.5, py + 0.5, camera)
                
                # Check intersection with octahedron
                # Use Möller-Trumbore algorithm on the triangular faces
                intersections = intersect_octahedron_ray(ray, prim['primitive'])
                
                if len(intersections) == 2:
                    d_entry, d_exit = sorted(intersections)
                    path_length = d_exit - d_entry
                    
                    # Calculate density using normalized distances
                    # min_dist is the minimum of normalized distances along axes
                    min_dist = min(prim['normalized_distances'])
                    
                    # Density formula
                    alpha = prim['opacity']
                    sigma = -math.log(1 - 0.99 * alpha) / (2 * min_dist)
                    
                    # Beer-Lambert opacity
                    # Note: The exact mapping from path_length to opacity 
                    # depends on the specific implementation of the linear primitive's 
                    # density distribution. Based on [S1], opacity depends on distance 
                    # between intersection points.
                    # Assuming uniform density within the primitive for simplicity 
                    # as per standard volumetric rendering with linear primitives:
                    transmittance = math.exp(-sigma * path_length)
                    contrib_opacity = 1.0 - transmittance
                    
                    # Accumulate color
                    # Current pixel color and accumulated opacity
                    current_color = image[py, px]
                    current_alpha = get_accumulated_alpha(image, py, px) # Assuming alpha channel stored or tracked
                    
                    # Front-to-back blending
                    # I_f = c_i * sigma_i * G_i * product(1 - sigma_j * G_j)
                    # Here, the "G_i" is effectively 1 inside the primitive and 0 outside,
                    # and the opacity contribution is derived from the path length.
                    
                    weight = contrib_opacity * (1.0 - current_alpha)
                    image[py, px] = current_color * (1.0 - weight) + prim['color'] * weight
                    
                    # Update accumulated alpha (stored separately or in alpha channel)
                    set_accumulated_alpha(image, py, px, current_alpha + weight)
                    
                    # Stop blending if threshold reached
                    if current_alpha + weight >= 0.999:
                        break

    return image

def intersect_octahedron_ray(ray, primitive):
    """
    Intersects a ray with an octahedron defined by its center, rotation, and distances.
    Returns a list of intersection distances [d_entry, d_exit] or empty list.
    Uses Möller-Trumbore algorithm for triangle intersections.
    """
    # Construct the 8 vertices of the octahedron from center, rotation, and distances
    vertices = construct_octahedron_vertices(primitive)
    
    # Define the 8 triangular faces of the octahedron
    faces = get_octahedron_faces(vertices)
    
    intersections = []
    for face in faces:
        # Möller-Trumbore intersection
        t, u, v = moller_trumbore(ray.origin, ray.direction, face)
        if t > 0: # Intersection in front of camera
            intersections.append(t)
            
    # Sort intersections
    intersections.sort()
    
    # A convex octahedron should have 0 or 2 intersections for a ray passing through
    if len(intersections) == 2:
        return intersections
    else:
        return []

def moller_trumbore(origin, direction, face):
    """
    Standard Möller-Trumbore ray-triangle intersection.
    Returns (t, u, v) or None if no intersection.
    """
    epsilon = 1e-8
    v0, v1, v2 = face
    
    edge1 = v1 - v0
    edge2 = v2 - v0
    h = np.cross(direction, edge2)
    a = np.dot(edge1, h)
    
    if a > -epsilon and a < epsilon:
        return None # Ray is parallel to triangle
        
    f = 1.0 / a
    s = origin - v0
    u = f * np.dot(s, h)
    
    if u < 0.0 or u > 1.0:
        return None
        
    q = np.cross(s, edge1)
    v = f * np.dot(direction, q)
    
    if v < 0.0 or u + v > 1.0:
        return None
        
    t = f * np.dot(edge2, q)
    
    if t > epsilon:
        return (t, u, v)
    return None

def construct_octahedron_vertices(center, rotation, distances):
    """
    Constructs the 8 vertices of an octahedron.
    distances: [d_x, d_y, d_z] representing the extent along principal axes.
    """
    # Local vertices of a unit octahedron scaled by distances
    local_vertices = np.array([
        [distances[0], 0, 0],
        [-distances[0], 0, 0],
        [0, distances[1], 0],
        [0, -distances[1], 0],
        [0, 0, distances[2]],
        [0, 0, -distances[2]]
    ])
    
    # Apply rotation
    R = rotation_matrix(rotation)
    rotated_vertices = local_vertices @ R.T
    
    # Translate to center
    vertices = rotated_vertices + center
    return vertices

def rotation_matrix(quaternion):
    """Converts a quaternion to a 3x3 rotation matrix."""
    # Standard quaternion to rotation matrix conversion
    q = quaternion / np.linalg.norm(quaternion)
    x, y, z, w = q
    return np.array([
        [1 - 2*y*y - 2*z*z, 2*x*y - 2*z*w, 2*x*z + 2*y*w],
        [2*x*y + 2*z*w, 1 - 2*x*x - 2*z*z, 2*y*z - 2*x*w],
        [2*x*z - 2*y*w, 2*y*z + 2*x*w, 1 - 2*x*x - 2*y*y]
    ])
```

### Parameters
*   **SH Degree:** Degree 3 is used, resulting in 48 coefficients per primitive [S1].
*   **Opacity Threshold:** Blending stops when cumulative opacity reaches $0.999$ [S1].
*   **Normalization Factor:** Distances are normalized by the smallest primitive distance $d$ in the scene [S1].

### Pitfalls and Edge Cases
*   **Scale Ambiguity:** Without normalization, the appearance of primitives varies across different scene sizes. This is handled by scaling distances relative to the smallest primitive distance $d$ [S1].
*   **Approximation Error:** The 3D affine ray space approximation error grows with distance from the center points. However, for small primitives, this error remains negligible [S1].
*   **Intersection Degeneracy:** If a ray grazes a face, the Möller-Trumbore algorithm may return unstable results. A small epsilon threshold is used to filter out intersections behind the camera or on the ray origin [S1].
*   **Memory Usage:** The 48 SH coefficients per primitive consume significant memory. Reducing SH degree or primitive count is necessary for large scenes [S1].

## Operating characteristics
*   **Time Complexity:** The preprocessing stage is $O(N)$ where $N$ is the number of primitives. Sorting is $O(N \log N)$ globally, but tiling reduces the sorting burden per tile. Rasterization is $O(P \cdot K)$ where $P$ is the number of pixels and $K$ is the average number of primitives per pixel.
*   **Memory Complexity:** $O(N)$ per primitive, dominated by the 48 SH coefficients [S1].
*   **Performance:** The method achieves real-time rendering speeds comparable to 3D Gaussian Splatting [S1]. The use of simple ray-triangle intersections and early termination (threshold 0.999) contributes to efficiency [S1].
*   **Strengths:** Bounded, triangular geometry allows for explicit geometric reasoning and differentiable optimization of shape parameters [S1].
*   **Limitations:** Scale ambiguity requires global normalization [S1]. The convexity of octahedra may not capture all complex geometries as well as non-convex primitives, though this is mitigated by using many small primitives [S1].

## Background
LinPrim was introduced in the paper "LinPrim: Linear Primitives for Differentiable Volumetric Rendering" [S1]. It builds upon the 3D Gaussian Splatting pipeline but replaces Gaussian kernels with octahedron and tetrahedron primitives [S1]. The method was developed to provide a more intuitive and modifiable scene representation with explicit geometric boundaries [S1]. It is cited in the context of differentiable rendering pipelines and point-based rendering extensions [S2, unofficial].
