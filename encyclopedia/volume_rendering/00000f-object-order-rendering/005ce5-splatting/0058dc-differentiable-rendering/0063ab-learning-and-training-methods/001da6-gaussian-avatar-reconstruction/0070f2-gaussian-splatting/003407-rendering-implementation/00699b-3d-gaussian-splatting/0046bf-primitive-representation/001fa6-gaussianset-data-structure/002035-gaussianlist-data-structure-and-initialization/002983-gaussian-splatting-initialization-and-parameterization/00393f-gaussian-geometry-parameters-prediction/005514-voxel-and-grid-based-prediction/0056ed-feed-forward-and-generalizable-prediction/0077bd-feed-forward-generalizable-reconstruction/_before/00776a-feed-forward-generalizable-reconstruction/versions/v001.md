# Feed-forward Generalizable Reconstruction

Also called: Feed-forward 3D Gaussian Splatting, Generalizable 3DGS, One-shot 3D Reconstruction

## Overview
Feed-forward generalizable reconstruction maps input images directly to a set of 3D Gaussian parameters $\mathcal{G} = \{\mu, \Sigma, \alpha, c\}$ in a single inference pass, eliminating the per-scene gradient descent optimization required by standard 3D Gaussian Splatting [16746-feed-forward-generalizable-reconstruction.md]. This family is distinguished from iterative optimization by its reliance on learned priors from large-scale datasets to generalize to unseen scenes, and from direct pixel-wise regression by its use of structured intermediate representations (such as voxel grids or latent spaces) to resolve cross-view inconsistencies and geometric ambiguities [16746-feed-forward-generalizable-reconstruction.md].

## Shared principles
All methods in this family share the core objective of mapping input image features to a set of 3D Gaussian parameters $\mathcal{G} = \{\mu, \Sigma, \alpha, c\}$ without per-scene gradient descent [16746-feed-forward-generalizable-reconstruction.md].

1.  **Input Representation:** Inputs are typically one or more RGB images $I \in \mathbb{R}^{H \times W \times 3}$. Some methods require known camera poses $P$, while others (e.g., [Splatt3R](16423-splatt3r.md), [ZeroGS](16425-zerogs.md)) predict poses or operate on uncalibrated inputs [16746-feed-forward-generalizable-reconstruction.md].
2.  **Feature Encoding:** A shared encoder (e.g., Vision Transformer, CNN) extracts multi-scale features from the input images. Cross-attention or cost volumes are often used to aggregate multi-view information [16746-feed-forward-generalizable-reconstruction.md].
3.  **Primitive Prediction:** A decoder head predicts Gaussian attributes. These attributes are usually:
    *   **Mean ($\mu$):** 3D position.
    *   **Covariance ($\Sigma$):** Defined by scale $s$ and rotation $r$ (quaternion or 6D).
    *   **Opacity ($\alpha$):** Scalar.
    *   **Color ($c$):** Spherical Harmonics (SH) coefficients or constant RGB [16746-feed-forward-generalizable-reconstruction.md].
4.  **Differentiable Rendering:** The predicted Gaussians are rendered into target views using differentiable rasterization to compute reconstruction losses (e.g., L1, SSIM, LPIPS) for training the network [16746-feed-forward-generalizable-reconstruction.md].
5.  **Generalization:** The network is trained on a large dataset of scenes to learn priors about geometry and appearance, allowing inference on unseen scenes [16746-feed-forward-generalizable-reconstruction.md].

## Subtopics

### [AnySplat Pipeline](12847-anysplat-pipeline.md)
AnySplat is a transformer-based method that reconstructs 3D scenes from uncalibrated, unconstrained multi-view images without requiring camera poses or depth as input. It differs from iterative optimization-based Gaussian Splatting by predicting Gaussian parameters, depth, and poses directly from images in a single forward pass, and from other generalizable methods by employing a differentiable voxelization module to convert pixel-wise Gaussians into a renderable set.

### [Splatt3R](16423-splatt3r.md)
Splatt3R is a feed-forward model that takes two uncalibrated images as input and outputs 3D Gaussian parameters for geometry and appearance, without requiring camera intrinsics, extrinsics, or depth. It extends the MASt3R architecture by adding a Gaussian prediction head to produce Gaussians directly from uncalibrated image pairs, avoiding per-scene optimization and explicit camera variable estimation. Unlike generalizable 3D-GS methods that only supervise novel viewpoints between input stereo views, Splatt3R supervises extrapolated viewpoints beyond the stereo baseline using a loss masking strategy.

### [RLSplat](16575-rlsplat.md)
RLSplat is a resource-linear, budget-controllable feed-forward 3D Gaussian Splatting (FF3DGS) framework that ensures inference latency, peak memory, and representation size all decrease linearly as the target Gaussian budget $B$ is reduced. Unlike prior budget-controllable methods that predict a dense set of candidates and prune them (resulting in nearly constant inference cost regardless of budget), RLSplat learns a Gaussian allocation policy to distribute exactly $B$ Gaussians across local scene anchors and refines them using a resource-linear decoder with hierarchical neighbor search.

### [LGTM (Less Gaussians, Texture More)](17426-lgtm-less-gaussians-texture-more.md)
LGTM is a feed-forward framework that predicts compact 2D Gaussian primitives coupled with per-primitive texture maps, decoupling geometric complexity from rendering resolution to enable high-fidelity 4K novel view synthesis without per-scene optimization. It solves the problem where existing feed-forward 3DGS methods suffer from quadratic growth in primitive count as resolution increases, making high-resolution synthesis intractable due to memory and compute limits. Unlike standard 3DGS which couples appearance and geometry within each primitive, LGTM allows a compact set of geometric primitives to represent rich texture regions via per-primitive textures.

### [InfiniSplat v2](17642-infinisplat-v2.md)
InfiniSplat v2 is a feed-forward Gaussian reconstruction method for arbitrary input views that decouples geometry and attribute prediction, uses ground-truth (GT) camera poses for alignment during training, and employs large-angle target view supervision to improve rendering quality under large viewpoint changes. It differs from its parent [Feed-forward Generalizable Reconstruction](23725-feed-forward-generalizable-reconstruction.md) and siblings like [DA3-GS](link) by freezing the geometry branch to prevent geometric degradation caused by joint optimization, and by using GT poses to avoid pose errors that misguide the network under large-angle supervision.

### [DepthSplat](18278-depthsplat.md)
DepthSplat is a feed-forward method for 3D Gaussian splatting reconstruction that connects Gaussian splatting and depth estimation by leveraging pre-trained monocular depth features to augment multi-view feature matching. It solves the problem of artifacts and scale ambiguities in multi-view depth prediction, enabling robust reconstruction from sparse input views. Unlike TranSplat, which uses monocular features to refine coarse depth (vulnerable to error propagation), DepthSplat combines cost volumes and monocular features early in the pipeline. Unlike methods like GS-LRM that rely heavily on training data and discard explicit feature matching, DepthSplat uses feature matching and is cheaper to train.

### [VG2GT](18425-vg2gt.md)
VG2GT is a feed-forward, non-pixel-aligned 3D Gaussian Splatting (3DGS) reconstruction framework that directly regresses geometrically accurate Gaussian scenes and camera parameters from an arbitrary number of unposed and uncalibrated images. It distinguishes itself from sibling methods like [AnySplat Pipeline](12847-anysplat-pipeline.md) and [Splatt3R](16423-splatt3r.md) by avoiding intermediate pixel-aligned representations; instead, it decodes Gaussian primitives directly from structured voxel features refined by a multi-scale differentiable voxel module. This approach mitigates the uneven Gaussian distributions and cross-view inconsistencies inherent in pixel-aligned formulations.

### [WildSplat](19321-wildsplat.md)
WildSplat is a feedforward 3D Gaussian Splatting framework for appearance-conditioned novel-view synthesis from sparse, unposed, in-the-wild images. It explicitly decouples geometry from appearance to handle inconsistent photometric conditions, such as varying weather and lighting, which typically cause entangled representations in existing feedforward methods to fail. Unlike optimization-based methods that require precomputed poses and dense inputs, or standard feedforward methods that assume photometric consistency, WildSplat jointly predicts camera poses, 3D Gaussian geometry, and reference-conditioned appearance in a single forward pass.

### [StereoGaussians](19766-stereogaussians.md)
StereoGaussians is a feed-forward method that predicts a metric 3D Gaussian Splatting (3DGS) representation from a single calibrated stereo pair, enabling nearby-view extrapolation without per-scene optimization. It distinguishes itself from siblings like [AnySplat Pipeline](12847-anysplat-pipeline.md) and [Splatt3R](16423-splatt3r.md) by explicitly leveraging frozen pretrained stereo features for geometry anchoring and introducing a second Gaussian layer with an expanded image canvas to handle disoccluded and outside-field-of-view content.

## Background
The shift from iterative optimization to feed-forward generalizable reconstruction in 3D Gaussian Splatting was driven by the need for real-time performance and scalability to large-scale datasets. Traditional 3DGS requires per-scene optimization, which is computationally expensive and prevents generalization to unseen scenes. Early generalizable methods adapted NeRF-based architectures to predict Gaussian parameters, but often suffered from geometric inaccuracies due to pixel-aligned representations. Recent developments, such as those leveraging foundation models (e.g., VGGT, MASt3R) and resource-linear decoding, have improved robustness and efficiency, enabling high-fidelity reconstruction from sparse, uncalibrated, or in-the-wild image collections [16746-feed-forward-generalizable-reconstruction.md].
