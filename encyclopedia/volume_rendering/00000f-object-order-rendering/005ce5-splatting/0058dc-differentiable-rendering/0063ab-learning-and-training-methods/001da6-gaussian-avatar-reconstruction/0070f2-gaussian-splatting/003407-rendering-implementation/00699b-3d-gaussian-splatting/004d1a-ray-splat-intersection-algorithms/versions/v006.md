# Ray-Splat Intersection Algorithms


## Overview
Ray-splat intersection algorithms evaluate the contribution of 3D Gaussians by intersecting viewing rays with the Gaussian primitives directly, rather than projecting them onto the image plane [G]. This family provides exact or analytically derived intersections, enabling correct handling of semi-transparency and degenerate splats [4556-perspective-correct-3d-gaussian-splatting-via-pl-cker-coordi.md, 5992-gaussian-opacity-fields-gof.md, 8101-3d-gaussian-ray-tracing.md]. Unlike standard 3D Gaussian Splatting (3DGS) which approximates the projection as an affine 2D Gaussian, these methods compute the Gaussian's maximum contribution along each ray [5992-gaussian-opacity-fields-gof.md].

## Shared principles
All methods in this family share the goal of computing the Gaussian's contribution $E$ along a ray $\mathbf{r}(t) = \mathbf{o} + t\mathbf{d}$ [G]. The core mathematical operation is finding the point $t_i$ along the ray where the Gaussian's density is maximized, often referred to as the "ray-Gaussian intersection" [S1]. This point is analytically derived from the Gaussian's covariance $\boldsymbol{\Sigma}$, center $\mathbf{p}$, and the ray direction $\mathbf{v}$ [S1]:
$$ t_i = \frac{\mathbf{p}^T \boldsymbol{\Sigma}^{-1} \mathbf{v}}{\mathbf{v}^T \boldsymbol{\Sigma}^{-1} \mathbf{v}} $$
The contribution is then modeled as a 1D Gaussian function along the ray:
$$ \rho(t) = \exp\left(-k_i (t - t_i)^2\right) $$
where $k_i$ is a curvature term derived from the covariance and ray direction [S1]. This reduces the 3D influence to a 1D function, allowing for exact integration or sampling [S1].

```python
import numpy as np

def ray_gaussian_intersection(p: np.ndarray, Sigma: np.ndarray, v: np.ndarray) -> tuple:
    """
    Computes the intersection point t_i and curvature k_i for a 3D Gaussian along a ray.
    p: Gaussian center (3,)
    Sigma: 3x3 covariance matrix
    v: Ray direction (3,)
    Returns: t_i, k_i
    """
    Sigma_inv = np.linalg.inv(Sigma)
    numerator = p.T @ Sigma_inv @ v
    denominator = v.T @ Sigma_inv @ v
    if denominator < 1e-9:
        return 0.0, 0.0
    t_i = numerator / denominator
    k_i = v.T @ Sigma_inv @ v
    return t_i, k_i
```

## Subtopics

### [Perspective-Correct 3D Gaussian Splatting via Plücker Coordinates](4556-perspective-correct-3d-gaussian-splatting-via-pl-cker-coordi.md)
This method provides a differentiable, matrix-inversion-free evaluation of 3D Gaussian densities along per-pixel viewing rays [4556-perspective-correct-3d-gaussian-splatting-via-pl-cker-coordi.md]. It sets itself apart by extending Weyrich et al.'s 2D splatting techniques to 3D using Plücker coordinates, ensuring numerical stability even for degenerate splats where principal axes vanish [4556-perspective-correct-3d-gaussian-splatting-via-pl-cker-coordi.md]. It eliminates the need for special handling of degenerate cases and avoids the numerical instabilities associated with matrix inversions in alternative rasterization-based approaches [4556-perspective-correct-3d-gaussian-splatting-via-pl-cker-coordi.md]. Choose this when perspective correctness is critical and degenerate Gaussians are common [4556-perspective-correct-3d-gaussian-splatting-via-pl-cker-coordi.md].

### [Gaussian Opacity Fields (GOF)](5992-gaussian-opacity-fields-gof.md)
GOF replaces standard 2D projection rasterization with ray-tracing-based volume rendering [5992-gaussian-opacity-fields-gof.md]. It analytically evaluates the maximum Gaussian contribution along each pixel ray, providing accurate depth estimation and facilitating the derivation of level-set surfaces from accumulated opacity [5992-gaussian-opacity-fields-gof.md]. Unlike 3DGS, it does not rely on 2D projection integrals [5992-gaussian-opacity-fields-gof.md]. Choose this when accurate depth and normal extraction are required alongside color rendering [5992-gaussian-opacity-fields-gof.md].

### [3D Gaussian Ray Tracing](8101-3d-gaussian-ray-tracing.md)
This method evaluates 3D Gaussian splats using hardware-accelerated ray tracing instead of rasterization [8101-3d-gaussian-ray-tracing.md]. It solves the problem of linear scaling in dense scenes by using a Bounding Volume Hierarchy (BVH) to traverse only Gaussians that intersect the viewing ray, enabling logarithmic complexity relative to the number of splats [8101-3d-gaussian-ray-tracing.md]. Unlike rasterization-based splatting which evaluates all Gaussians overlapping a tile, 3DGRT explicitly handles semi-transparency by accumulating transmittance through all intersected Gaussians, avoiding the depth-sorting artifacts inherent in tile-based rasterization [8101-3d-gaussian-ray-tracing.md]. Choose this for large-scale scenes or when hardware ray tracing is available [8101-3d-gaussian-ray-tracing.md].

### [QuadBox](9231-quadbox.md)
QuadBox is a Gaussian-tile intersection method that uses four axis-aligned bounding boxes (AABBs) to tightly encapsulate projected 2D Gaussians [9231-quadbox.md]. It sets itself apart by replacing the single conservative AABB with four symmetrically positioned, adaptively stretched sub-boxes that better fit the anisotropic shape of the ellipse [9231-quadbox.md]. This tight fit suppresses empty tile coverage along the minor axis, while the accompanying QPass algorithm ensures deterministic, cache-friendly tile traversal with minimal per-tile overhead [9231-quadbox.md]. Choose this when rasterization performance is prioritized but over-approximation of anisotropic splats is a bottleneck [9231-quadbox.md].

### Ray-Gaussian Intersection
This is the fundamental geometric operation shared by ray-based methods [G]. It involves projecting the 3D Gaussian's covariance and center onto the camera ray to convert the 3D influence into a 1D Gaussian function along that specific ray [S1]. This allows for the analytical computation of the intersection point $t_i$ and the subsequent evaluation of the Gaussian's density along the ray [S1].

## Background
The analytical derivation of the intersection point $t_i$ is based on finding the extremum of the Gaussian function along a line, a technique detailed in "Approximate Differentiable Rendering with Algebraic Surfaces" [S1]. The specific formulation $\rho(t) = \exp(-k_i(t-t_i)^2)$ is used to map 3D Gaussian influence to 1D ray space [S1].
