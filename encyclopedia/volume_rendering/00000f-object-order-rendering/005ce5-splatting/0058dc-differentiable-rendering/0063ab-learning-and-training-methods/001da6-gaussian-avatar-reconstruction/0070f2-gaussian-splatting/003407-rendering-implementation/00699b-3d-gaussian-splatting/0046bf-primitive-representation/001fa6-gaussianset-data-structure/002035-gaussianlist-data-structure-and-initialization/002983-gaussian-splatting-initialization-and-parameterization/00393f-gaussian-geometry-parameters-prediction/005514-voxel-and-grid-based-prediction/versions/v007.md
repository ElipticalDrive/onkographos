# Voxel and Grid-Based Prediction

Also called: Direct Multi-Plane Image Gaussian Optimization, DirectMPIGO

## Overview
Voxel and Grid-Based Prediction is a neural rendering method that combines voxel-based density representation with Multi-Plane Image (MPI) depth layers to perform efficient volume rendering [S1, unofficial]. It solves the problem of memory inefficiency and slow convergence in dense voxel grids by supporting sparse grids and occupancy caching [S1, unofficial]. Unlike sibling methods that optimize neural feature grids directly or use fully implicit MLPs, this approach operates on a structured grid of density and color features, significantly reducing optimization time while maintaining high fidelity [S1, S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Camera rays (origin $\mathbf{o}$, direction $\mathbf{d}$), scene bounding box ($\mathbf{xyz\_min}, \mathbf{xyz\_max}$), and hyperparameters ($mpi\_depth, fast\_color\_thres, rgbnet\_dim$, etc.).
*   **Outputs:** Rendered RGB image and depth map.

**Data Structures:**
1.  **Density Grid:** A `DenseGrid` (or `SparseGridSpec`) storing density values. Shape depends on `world_size`.
2.  **Color Grid ($k_0$):** Stores color features. Channels = 3 if `rgbnet_dim <= 0`, else `rgbnet_dim`.
3.  **Act Shift Grid:** `DenseGrid` tensor of shape `[1, 1, mpi_depth]`. Stores logit shifts to equalize alpha contributions across MPI layers. `requires_grad=False`.
4.  **Mask Cache:** Boolean tensor of shape `mask_cache_world_size`. Tracks occupied voxels to skip empty space queries.

**Parameters:**
*   `xyz_min`, `xyz_max`: Scene bounding box coordinates.
*   `mpi_depth`: Number of depth planes in the MPI representation.
*   `fast_color_thres`: Threshold for occupancy mask updates; voxels with alpha below this are considered empty.
*   `rgbnet_dim`: Dimension of the color feature vector. If $\le 0$, uses raw RGB from $k_0$; otherwise uses MLP output.
*   `rgbnet_depth`, `rgbnet_width`: Depth and width of the color MLP.
*   `viewbase_pe`: Number of positional encoding frequencies for view direction.
*   `voxel_size_ratio`: Constant $256.0 / mpi\_depth$.

**Initialization:**
1.  **Grid Creation:** Initialize density grid using `grid.create_grid` with `density_type`, `channels=1`, and `world_size` derived from `_set_grid_resolution`. Initialize $k_0$ grid with `k0_type` and channels determined by `rgbnet_dim`.
2.  **World Size Calculation:**
    $$ \text{world\_size}[0:2] = (\mathbf{xyz\_max}[0:2] - \mathbf{xyz\_min}[0:2]) \times r $$
    $$ r = \sqrt{\frac{\text{num\_voxels}}{mpi\_depth \times \prod (\mathbf{xyz\_max}[0:2] - \mathbf{xyz\_min}[0:2])}} $$
    $$ \text{world\_size}[2] = mpi\_depth $$
3.  **Act Shift Initialization:**
    *   Set initial density values $g[i] = \frac{1.0}{mpi\_depth} - 10^{-6}$ for all $i \in [0, mpi\_depth)$. This ensures uniform initial transmittance.
    *   Compute conditional probability:
        $$ p[i] = \frac{1 - \sum_{j=0}^{i} g[j]}{1 - \sum_{j=0}^{i-1} g[j]} \quad \text{for } i > 0, \quad p[0] = 1 - g[0] $$
    *   Compute act shift value at layer $i$:
        $$ \text{act\_shift}[i] = \log \left( \left( p[i] \right)^{-1 / \text{voxel\_size\_ratio}} - 1 \right) $$
    *   Initialize `act_shift.grid` with these values.
4.  **Color MLP Initialization:**
    *   If `rgbnet_dim > 0`: Create MLP with input dimension $dim_0 = (3 + 3 \times viewbase\_pe \times 2) + k_0\_dim$.
    *   Layers: `Linear(dim0, rgbnet_width)`, `ReLU`, `(rgbnet_depth-2)` layers of `Linear(rgbnet_width, rgbnet_width)` + `ReLU`, final `Linear(rgbnet_width, 3)`.
    *   Initialize final bias to 0: `nn.init.constant_(self.rgbnet[-1].bias, 0)`.
    *   Initialize view direction positional encoding buffer with powers of 2: $[2^0, 2^1, \dots, 2^{(viewbase\_pe-1)}]$.
    *   If `rgbnet_dim <= 0`: Set `rgbnet` to `None` (coarse stage).
5.  **Mask Cache Initialization:** If `mask_cache_path` is provided, load from file; else create an all-True mask of size `mask_cache_world_size`.

**Rendering Steps:**
1.  **Ray Bounding Box Intersection:**
    For each ray $(\mathbf{o}, \mathbf{d})$, compute intersection $[t_{min}, t_{max}]$ with the bounding box defined by $\mathbf{xyz\_min}$ and $\mathbf{xyz\_max}$.
    ```python

        n_rays = rays_o.shape[0]
        t_min = torch.empty(n_rays)
        t_max = torch.empty(n_rays)
        for i in range(n_rays):
            ox, oy, oz = rays_o[i]
            dx, dy, dz = rays_d[i]
            # Avoid division by zero
            dx = 1e-6 if dx == 0 else dx
            dy = 1e-6 if dy == 0 else dy
            dz = 1e-6 if dz == 0 else dz
            
            # Intersections with min/max planes
            ax = (xyz_max[0] - ox) / dx
            ay = (xyz_max[1] - oy) / dy
            az = (xyz_max[2] - oz) / dz
            bx = (xyz_min[0] - ox) / dx
            by = (xyz_min[1] - oy) / dy
            bz = (xyz_min[2] - oz) / dz
            
            t_min[i] = max(min(max(min(ax, bx), min(ay, by)), min(az, bz)), near)
            t_max[i] = max(min(min(max(ax, bx), max(ay, by)), max(az, bz)), far)
        return t_min, t_max
    ```

3.  **Density and Color Query:**
    For each sample point, query the density grid and color grid ($k_0$). If `rgbnet_dim > 0`, pass color features and view direction through the MLP.
4.  **Volume Rendering:**
    Composite colors and alphas along the ray using the MPI depth layers and density values. Apply `act_shift` to adjust alpha contributions.

**Occupancy Cache Updates:**
1.  **Scale Volume Grid:** If new `world_size` product $\le 256^3$, recompute `mask_cache` by combining old mask with alpha $> fast\_color\_thres$ after `max_pool3d` smoothing.
2.  **Update Occupancy Cache:** Query density at cache grid points, activate, apply `max_pool3d(kernel=3, padding=1)`, update mask where alpha $> fast\_color\_thres$.
3.  **Update Occupancy Cache (Low Views):** For each ray batch, sample points, accumulate gradient counts in `ones.grid.grad`, update mask where count $\ge maskout\_lt\_nviews$.

**Total Variation Gradient Scaling:**
$$ w_{xy} = \text{weight} \times \frac{\max(\text{world\_size}[0:2])}{128} $$
$$ w_z = \text{weight} \times \frac{mpi\_depth}{128} $$

## Subtopics

### 3D Gaussians Prediction from Voxels
Predicts a set of learnable Gaussian parameters for each voxel $v$, including center offset, opacity, covariance, and spherical harmonic color [S2]. It solves the problem of mapping coarse voxel features to explicit Gaussian primitives by applying a sigmoid activation to the predicted offset $\bar{\mu}_j$, shifting by -0.5, scaling by $r$, and adding the voxel centroid $\text{Center}_j$ [S2]. Unlike sibling methods that optimize neural feature grids directly, this approach operates on the Gaussian set's geometric and color parameters via residual correction [S1, unofficial][S2]. The output dimension per Gaussian is 38 (offset 3, opacity 1, covariance 6, SH color 28) [S2]. The scaling factor $r$ is set to 3 times the voxel size [S2].

### GS-LRM / Long-LRM
Predicts 3D Gaussians directly from input data, bypassing the intermediate triplane representation [S3, unofficial]. It solves the problem of slow downstream rendering associated with triplane-based methods by enabling faster rasterization of explicit Gaussians [S3, unofficial]. Unlike sibling methods that use triplane $\to$ Gaussians conversion, this method predicts Gaussians directly, resulting in faster inference times [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** Faster than fully implicit MLP-based methods due to grid-based feature storage and sparse grid support [S1, unofficial].
*   **Memory Complexity:** Higher than fully implicit methods due to grid storage, but lower than dense voxel grids of equivalent resolution due to sparsity and MPI depth compression [S1, unofficial].
*   **Strengths:** Efficient volume rendering, supports sparse grids, occupancy caching reduces computation in empty space [S1, unofficial].
*   **Limitations:** Memory usage increases with resolution; MPI depth adds complexity to initialization [S1, unofficial].
*   **When to use:** When fast training and rendering are required, and scene geometry fits within a bounding box [S1, unofficial].
*   **When not to use:** For scenes with large empty spaces where sparse grids are not supported or effective [S1, unofficial].

## Background
Originated from the kakaobrain/nerf-factory repository, DirectMPIGO combines voxel-based density representation with Multi-Plane Image (MPI) depth layers [S1, unofficial]. It was developed to address the limitations of dense voxel grids in Neural Radiance Fields (NeRF) by introducing sparsity and MPI-based depth representation for more efficient volume rendering [S1, unofficial].
