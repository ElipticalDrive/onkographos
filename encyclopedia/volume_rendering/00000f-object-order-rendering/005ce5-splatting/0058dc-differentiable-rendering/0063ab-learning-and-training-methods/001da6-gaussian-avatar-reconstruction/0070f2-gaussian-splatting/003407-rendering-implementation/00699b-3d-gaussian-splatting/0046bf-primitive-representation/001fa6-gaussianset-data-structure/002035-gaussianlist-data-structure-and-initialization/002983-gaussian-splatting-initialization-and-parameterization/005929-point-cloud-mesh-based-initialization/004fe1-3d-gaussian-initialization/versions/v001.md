# 3D Gaussian Initialization

Also called: Initial Parameter Setup

## Overview
3D Gaussian Initialization establishes the initial state of the Gaussian primitive set before optimization begins, mapping input geometric data (such as point clouds, meshes, or reconstructed volumes) to Gaussian centers, covariances, colors, and opacities. It differs from generic model initialization by specifically deriving scale and opacity heuristics from camera parameters and scene density to ensure stable gradient propagation during the early stages of differentiable rendering [S1, S2]. While [Gaussian Model Initialization](2349-gaussian-model-initialization.md) covers general parameter structures, this method focuses on the geometric and photometric seeding strategies required for convergence in sparse or novel view synthesis contexts [S1, S2].

## How it works
**Inputs:**
- Input geometric primitives: A set of points $\{p_i\}$ with associated colors $c_i$ and, optionally, depth values $D^{\text{init}}_i$ or normals $n_i$.
- Camera parameters: Vertical focal length $f$ and image height $H$.
- View count $N$: The number of input views used for reconstruction.

**Outputs:**
- A Gaussian set defined by tensors for position ($\mathbf{xyz}$), rotation quaternions ($\mathbf{rot}$), scale vectors ($\mathbf{scale}$), opacity scalar ($\alpha$), and spherical harmonic coefficients ($\mathbf{features}$).

**Data Structures:**
Each Gaussian $i$ is represented by:
- $\mathbf{xyz}_i \in \mathbb{R}^3$: Center position.
- $\mathbf{rot}_i \in \mathbb{R}^4$: Unit quaternion $(w, x, y, z)$.
- $\mathbf{scale}_i \in \mathbb{R}^3$: Scale factors along principal axes.
- $\alpha_i \in \mathbb{R}$: Opacity (logit or raw parameter, depending on implementation; sources imply raw parameter mapping to probability).
- $\mathbf{features}_{dc, i} \in \mathbb{R}^3$: Zeroth-order spherical harmonic (RGB color).
- $\mathbf{features}_{rest, i}$: Higher-order SH coefficients, initialized to zero.

**Steps:**

1.  **Position Mapping:**
    Assign the input point coordinates directly to the Gaussian centers.
    $$ \mathbf{xyz}_i = p_i $$

2.  **Rotation Initialization:**
    Initialize all rotation quaternions to the identity quaternion, implying an initial isotropic orientation.
    $$ \mathbf{rot}_i = (1, 0, 0, 0) $$
    [G] In implementations using axis-angle or rotation matrices, this corresponds to the identity matrix $I_{3\times3}$.

3.  **Scale Estimation:**
    Compute the initial scale using an isometric (spherical) assumption. The radius $r$ is derived from the initial depth $D^{\text{init}}$ to ensure the Gaussian covers the corresponding pixel footprint properly [S1].
    $$ r = \frac{f \cdot D^{\text{init}}_i}{H} $$
    The scale vector is then set to isotropic values:
    $$ \mathbf{scale}_i = (r, r, r) $$
    [G] If depth is unavailable, fallback to $k$-nearest neighbor distance heuristics as noted in parent principles.

4.  **Color Initialization:**
    Set the zeroth-order spherical harmonic coefficient to the input color. Higher-order coefficients are zero-initialized.
    $$ \mathbf{features}_{dc, i} = c_i $$
    $$ \mathbf{features}_{rest, i} = \mathbf{0} $$

5.  **Opacity Initialization:**
    Set the initial opacity based on the number of input views $N$ to prevent early overconfidence and ensure gradient flow [S1]. The raw parameter value $\alpha_{raw}$ maps to probability $P$ via sigmoid. The sources specify target probabilities:
    - If $N=2$, target $P=0.6$.
    - If $N=3$, target $P=0.5$.
    - If $N=4$, target $P=0.35$.
    
    To implement this, compute the raw logit:
    $$ \alpha_{raw, i} = \text{sigmoid}^{-1}(P_N) = \ln\left(\frac{P_N}{1 - P_N}\right) $$
    [G] Standard sigmoid inverse is used. For $P=0.1$ (mentioned in parent principles as a generic low value), $\alpha_{raw} \approx -2.197$. The specific values for $N=2,3,4$ are:
    - $N=2: \alpha_{raw} \approx 0.405$
    - $N=3: \alpha_{raw} \approx 0.0$
    - $N=4: \alpha_{raw} \approx -0.847$

**Pseudocode:**

```python
import torch
import math

def initialize_gaussians(points, colors, depths, focal_length, image_height, num_views):
    """
    Initialize 3D Gaussians from point cloud data.
    
    Args:
        points: Tensor of shape (N, 3), input point coordinates.
        colors: Tensor of shape (N, 3), input RGB colors.
        depths: Tensor of shape (N,), initial depth values D_init.
        focal_length: Float, vertical focal length f.
        image_height: Int, image height H.
        num_views: Int, number of input views N.
        
    Returns:
        Dict containing initialized Gaussian parameters.
    """
    N = points.shape[0]
    
    # 1. Position
    xyz = points.clone()
    
    # 2. Rotation (Identity quaternion)
    # w=1, x=0, y=0, z=0
    rot = torch.zeros(N, 4, device=points.device)
    rot[:, 0] = 1.0
    
    # 3. Scale (Isometric)
    # r = (f * D_init) / H
    radius = (focal_length * depths) / image_height
    # Clamp radius to avoid numerical issues
    radius = torch.clamp(radius, min=1e-6)
    scale = torch.stack([radius, radius, radius], dim=1)
    
    # 4. Color (SH DC)
    features_dc = colors.clone()
    # Higher order SH coefficients are zero. 
    # Assuming a standard 3DGS setup with 15 coefficients (degree 2), 
    # but sources only specify DC. Rest is zero.
    # For a complete tensor, we would append zeros. 
    # Here we return just DC as per source specificity, 
    # but in practice features_rest would be zeros(N, 15).
    features_rest = torch.zeros(N, 15, device=points.device) 
    
    # 5. Opacity
    # Map num_views to target probability
    if num_views == 2:
        target_prob = 0.6
    elif num_views == 3:
        target_prob = 0.5
    elif num_views == 4:
        target_prob = 0.35
    else:
        # Fallback to generic low opacity if N not in {2,3,4}
        # Parent notes mention ~0.1 for generic cases
        target_prob = 0.1
        
    # Convert probability to raw logit parameter
    # alpha_raw = log(p / (1-p))
    # Clamp prob to avoid log(0)
    target_prob = torch.clamp(torch.tensor(target_prob), min=1e-6, max=1-1e-6)
    opacity_raw = torch.log(target_prob / (1 - target_prob))
    opacity = torch.full((N,), opacity_raw, device=points.device)
    
    return {
        "xyz": xyz,
        "rot": rot,
        "scale": scale,
        "features_dc": features_dc,
        "features_rest": features_rest,
        "opacity": opacity
    }
```

**Edge Cases and Pitfalls:**
- **Depth Accuracy:** The scale calculation relies on $D^{\text{init}}$. If depth is noisy or missing, scales will be incorrect, leading to artifacts or poor convergence [S1].
- **View Count Sensitivity:** Using an incorrect $N$ for opacity initialization can lead to either vanishing gradients (if opacity is too low) or early saturation (if too high) [S1].
- **Isotropic Assumption:** Initializing as spheres ($r,r,r$) ignores local surface curvature. This may require more optimization iterations to adapt to non-spherical structures [S1].

## Subtopics

### Gaussian Initialization Strategies
This variant compares uniform foreground placement versus FBP (Filtered Back Projection)-image-guided placement. Uniform initialization filters air regions using a threshold and places Gaussians uniformly across the remaining foreground volume with identical covariance and intensity. FBP-image-guided initialization leverages prior information from the FBP reconstruction to place Gaussians. The FBP-guided approach consistently outperforms uniform initialization in reconstruction quality and is comparable to a dedicated two-stage fitting process but avoids the computational overhead of the intermediate fitting stage [S2].

## Operating characteristics
- **Time Complexity:** Initialization is $O(N)$ where $N$ is the number of points, as it involves simple arithmetic operations per point.
- **Memory Complexity:** $O(N)$ to store the initial tensors.
- **Strengths:** Provides a physically meaningful starting point (scale relative to depth) which stabilizes training, especially in sparse view scenarios [S1]. The view-dependent opacity prevents early overfitting [S1].
- **Limitations:** Relies on accurate initial depth or point cloud data. The isotropic scale assumption may be suboptimal for thin structures or complex geometries without further refinement [S1]. Uniform initialization is computationally simple but yields significantly lower quality than guided methods [S2].

## Background
The method originates from adaptations of 3D Gaussian Splatting (3DGS) for sparse view synthesis and coherent reconstruction. Key implementations include CoherentGS, which explicitly details the isometric scale derivation and view-dependent opacity settings [S1], and 3DGR-CT, which explores FBP-guided initialization for CT reconstruction [S2]. The approach builds on the general 3DGS framework but introduces specific heuristics for initialization to handle the ill-posed nature of sparse input data.
