# Multi-Attribute Consistency (MAC) Loss

Also called: MAC loss, MAC-Splat loss

## Overview
The Multi-Attribute Consistency (MAC) loss is a regularization objective for 3D Gaussian Splatting that enforces geometric and photometric agreement between matched Gaussians across different views [S1]. It solves the ambiguity problem in sparse-view reconstruction by using high-confidence 2D pixel correspondences as anchors to jointly constrain position, shape, and appearance in a common world coordinate frame [S1]. Unlike standard photometric losses that only supervise the final rendered image, MAC loss operates directly on the Gaussian parameters, providing robust supervision that is invariant to camera rotation and resistant to outliers [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of matched pixel pairs $M = \{(\mathbf{p}_1^k, \mathbf{p}_2^k)\}_{k=1}^K$ between two training images $I_1$ and $I_2$, where each pair has an associated joint confidence weight $w_k$. Camera-to-world transformation matrices $\mathbf{T}_{wc}^v = [\mathbf{R}^v | \mathbf{t}^v]$ for each view $v \in \{1, 2\}$. Dense predicted parameter maps for each view, containing centroids $\boldsymbol{\mu}_{\text{cam}}$, covariance matrices $\boldsymbol{\Sigma}_{\text{cam}}$, opacities $\alpha$, and spherical harmonic coefficients $\mathbf{c}$, aligned with the descriptor grid.
*   **Outputs:** A scalar loss value $\mathcal{L}_{\text{MAC}}$ and gradients with respect to the Gaussian parameters.

**Data Structures:**
*   **Parameter Maps:** For each view $v$, dense tensors of shape $(H, W, D)$, where $D$ is the dimensionality of the concatenated parameters.
    *   Centroids: $\boldsymbol{\mu}_{\text{cam}} \in \mathbb{R}^3$ per pixel.
    *   Covariance: $\boldsymbol{\Sigma}_{\text{cam}} \in \text{Sym}^+(3)$ per pixel (6 unique elements or 3x3 matrix).
    *   Opacity: $\alpha \in \mathbb{R}$ per pixel.
    *   Color/SH: $\mathbf{c} \in \mathbb{R}^C$ per pixel (where $C$ depends on SH degree).
*   **Matches:** A list of $K$ tuples, each containing pixel coordinates $(u_1, v_1), (u_2, v_2)$ and confidence $w_k$.

**Numbered Steps:**

1.  **Gaussian Pair Extraction:** For each matched pixel pair $k$ with coordinates $\mathbf{p}_1^k$ in view 1 and $\mathbf{p}_2^k$ in view 2:
    *   Bilinearly sample the predicted parameter maps at $\mathbf{p}_1^k$ to obtain Gaussian $G_1^k = (\boldsymbol{\mu}_{\text{cam}}^{1,k}, \boldsymbol{\Sigma}_{\text{cam}}^{1,k}, \alpha^{1,k}, \mathbf{c}^{1,k})$.
    *   Bilinearly sample the predicted parameter maps at $\mathbf{p}_2^k$ to obtain Gaussian $G_2^k = (\boldsymbol{\mu}_{\text{cam}}^{2,k}, \boldsymbol{\Sigma}_{\text{cam}}^{2,k}, \alpha^{2,k}, \mathbf{c}^{2,k})$.

2.  **World-Space Transformation:** Transform the extracted parameters into the common world coordinate system using the camera-to-world matrices $\mathbf{T}_{wc}^v = [\mathbf{R}^v | \mathbf{t}^v]$.
    *   **Centroids:** Compute world-space centroids:
        $$ \boldsymbol{\mu}_{\text{world}}^{v,k} = \mathbf{R}^v \boldsymbol{\mu}_{\text{cam}}^{v,k} + \mathbf{t}^v $$
    *   **Covariances:** Transform covariance matrices to respect the rotation of the world frame:
        $$ \boldsymbol{\Sigma}_{\text{world}}^{v,k} = \mathbf{R}^v \boldsymbol{\Sigma}_{\text{cam}}^{v,k} (\mathbf{R}^v)^\top $$
    *   **Opacity and Color:** These attributes are frame-invariant in this context, so $\alpha_{\text{world}}^{v,k} = \alpha^{v,k}$ and $\mathbf{c}_{\text{world}}^{v,k} = \mathbf{c}^{v,k}$.

3.  **Positional Consistency Loss ($\mathcal{L}_{\text{pos}}$):**
    *   Check validity: Only compute if the depth $z_{\text{cam}} > 0$ for both views (i.e., the Gaussians are in front of the cameras).
    *   Compute the $L_1$ distance between world-space centroids: $d_{\text{pos}} = \|\boldsymbol{\mu}_{\text{world}}^{1,k} - \boldsymbol{\mu}_{\text{world}}^{2,k}\|_1$.
    *   Apply Huber loss $\mathcal{H}$:
        $$ \mathcal{L}_{\text{pos}}^{(k)} = \mathcal{H}(d_{\text{pos}}) $$

4.  **Shape Consistency Loss ($\mathcal{L}_{\text{shape}}$):**
    *   Compute the eigenvalues $\lambda_1, \lambda_2, \lambda_3$ of $\boldsymbol{\Sigma}_{\text{world}}^{1,k}$ and $\boldsymbol{\Sigma}_{\text{world}}^{2,k}$.
    *   Compute the $L_1$ distance between the log-eigenvalues:
        $$ \mathcal{L}_{\text{shape}}^{(k)} = \sum_{i=1}^3 |\log(\lambda_i^{1,k}) - \log(\lambda_i^{2,k})| $$
    *   *Note:* Euclidean distance between covariance matrices is not used because it is not invariant to rotations or uniform scaling and does not respect the geometry of the symmetric positive definite manifold $\text{Sym}^+(3)$ [S1].

5.  **Appearance Consistency Loss ($\mathcal{L}_{\text{app}}$):**
    *   Compute the $L_1$ distance between opacities and spherical harmonic coefficients:
        $$ \mathcal{L}_{\text{app}}^{(k)} = \|\alpha^{1,k} - \alpha^{2,k}\|_1 + \|\mathbf{c}^{1,k} - \mathbf{c}^{2,k}\|_1 $$

6.  **Aggregation:**
    *   Combine the terms using confidence weights $w_k$ and scalar hyperparameters $\lambda_p, \lambda_s, \lambda_a$:
        $$ \mathcal{L}_{\text{MAC}} = \frac{\sum_{k=1}^K w_k \left( \lambda_p \mathcal{L}_{\text{pos}}^{(k)} + \lambda_s \mathcal{L}_{\text{shape}}^{(k)} + \lambda_a \mathcal{L}_{\text{app}}^{(k)} \right)}{\sum_{k=1}^K w_k + \epsilon} $$
    *   $\epsilon$ is a small constant to prevent division by zero.

**Pseudocode:**

```python
import torch
import torch.nn.functional as F

def huber_loss(x, delta=1.0):
    """Standard Huber loss implementation."""
    abs_x = torch.abs(x)
    cond = (abs_x <= delta).float()
    loss = cond * 0.5 * x**2 + (1 - cond) * (delta * abs_x - 0.5 * delta**2)
    return loss

def mac_loss(
    mu_cam_1, sigma_cam_1, alpha_1, c_1,
    mu_cam_2, sigma_cam_2, alpha_2, c_2,
    T_wc_1, T_wc_2,
    matches, w_k,
    lambda_p, lambda_s, lambda_a,
    epsilon=1e-8
):
    """
    Compute MAC Loss.
    
    Args:
        mu_cam: (K, 3) centroids in camera space
        sigma_cam: (K, 3, 3) covariance matrices in camera space
        alpha: (K,) opacities
        c: (K, C) spherical harmonic coefficients
        T_wc_1, T_wc_2: (3, 4) camera-to-world matrices [R | t]
        matches: List of indices or coordinates (not used directly if tensors are aligned by K)
        w_k: (K,) confidence weights
        lambda_p, lambda_s, lambda_a: Scalar weights
        epsilon: Small constant for numerical stability
    """
    # 1. Transform to World Space
    R1, t1 = T_wc_1[:, :3], T_wc_1[:, 3]
    R2, t2 = T_wc_2[:, :3], T_wc_2[:, 3]
    
    # Centroids: mu_world = R * mu_cam + t
    mu_world_1 = torch.matmul(R1, mu_cam_1.T).T + t1
    mu_world_2 = torch.matmul(R2, mu_cam_2.T).T + t2
    
    # Covariances: Sigma_world = R * Sigma_cam * R^T
    sigma_world_1 = torch.matmul(torch.matmul(R1, sigma_cam_1), R1.transpose(0, 1))
    sigma_world_2 = torch.matmul(torch.matmul(R2, sigma_cam_2), R2.transpose(0, 1))
    
    # 2. Positional Consistency
    # Check depth > 0 (assuming z is the 3rd component in camera space)
    # Note: The source specifies checking z_cam > 0. We assume mu_cam_1[:, 2] and mu_cam_2[:, 2] are depths.
    valid_mask = (mu_cam_1[:, 2] > 0) & (mu_cam_2[:, 2] > 0)
    
    pos_diff = torch.norm(mu_world_1 - mu_world_2, p=1, dim=1) # L1 norm
    pos_loss = huber_loss(pos_diff)
    
    # 3. Shape Consistency (Log-Eigenvalues)
    # Compute eigenvalues of symmetric matrices
    eigvals_1 = torch.linalg.eigvalsh(sigma_world_1) # (K, 3)
    eigvals_2 = torch.linalg.eigvalsh(sigma_world_2) # (K, 3)
    
    # Log eigenvalues
    log_eigvals_1 = torch.log(eigvals_1)
    log_eigvals_2 = torch.log(eigvals_2)
    
    shape_loss = torch.sum(torch.abs(log_eigvals_1 - log_eigvals_2), dim=1) # L1 sum over 3 eigenvalues
    
    # 4. Appearance Consistency
    app_alpha_loss = torch.abs(alpha_1 - alpha_2)
    app_c_loss = torch.norm(c_1 - c_2, p=1, dim=1) # L1 norm over SH coefficients
    app_loss = app_alpha_loss + app_c_loss
    
    # 5. Aggregate
    # Apply valid mask to losses and weights
    # If a match is invalid (z <= 0), its contribution should be zero or excluded.
    # The source says "evaluated only if z_cam > 0".
    pos_loss = pos_loss * valid_mask.float()
    shape_loss = shape_loss * valid_mask.float()
    app_loss = app_loss * valid_mask.float()
    w_k_valid = w_k * valid_mask.float()
    
    numerator = w_k_valid * (lambda_p * pos_loss + lambda_s * shape_loss + lambda_a * app_loss)
    denominator = torch.sum(w_k_valid) + epsilon
    
    total_loss = torch.sum(numerator) / denominator
    
    return total_loss
```

**Parameters:**
*   $\lambda_p, \lambda_s, \lambda_a$: Scalar weights for positional, shape, and appearance terms. Typical values are not explicitly given in the sources, but they balance the influence of each term [S1].
*   $\epsilon$: Small constant to prevent division by zero. Value not specified [S1].
*   $\tau_{\text{conf}}$: Confidence threshold for filtering matches. If no match survives ($w_k > \tau_{\text{conf}}$), the loss for that region falls back to zero [S1].

**Edge Cases and Pitfalls:**
*   **Geometric Degeneracy:** As a Gaussian's smallest eigenvalue $\lambda_{\min}$ approaches zero, the gradient of the log-eigenvalue shape loss scales inversely with $\lambda$ ($|\partial \mathcal{L}/\partial \lambda| \propto 1/\lambda$) [S1]. This creates a strong repulsive effect that pushes $\lambda_{\min}$ away from zero, preventing collapsed artifacts [S1].
*   **Ambiguous Regions:** If no match survives the confidence gating, the MAC loss is zero for that region, allowing the network to rely solely on photometric supervision [S1].
*   **Coordinate System:** Covariance matrices must be transformed using the rotation matrix $\mathbf{R}$ to respect the geometry of $\text{Sym}^+(3)$; using Euclidean distance in camera space is incorrect [S1].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of matched pixel pairs $K$. The dominant operations are matrix-vector multiplications for coordinate transformation and eigenvalue decomposition for shape consistency.
*   **Memory Complexity:** Requires storing dense parameter maps for the views being compared. The loss computation itself is memory-efficient as it operates on sampled points.
*   **Strengths:** Robust to outliers due to Huber loss and confidence weighting. Respects the geometry of covariance matrices. Stabilizes training under sparse-view conditions by resolving ambiguities [S1].
*   **Limitations:** Requires high-quality 2D correspondences (e.g., from MASt3R/DINOv3). Performance depends on the accuracy of the pose estimation (ground truth during training, estimated at test time) [S1].
*   **When to use:** Sparse-view reconstruction where photometric loss alone leads to ambiguities or floating artifacts.
*   **When not to use:** Dense-view scenarios where photometric loss is sufficient, or when high-quality correspondences cannot be established.

## Background
The MAC loss was introduced in the MAC-Splat paper by Yang et al. [S1]. It builds on the MASt3R geometric backbone and a frozen DINOv3 encoder to obtain semantically informed 2D correspondences [S1]. The method was designed to improve reconstruction quality in sparse-view settings, showing significant gains over baselines like Splatt3R in terms of PSNR and LPIPS [S1]. It addresses the limitations of conventional losses by jointly regularizing 3D attributes in a common world frame [S1].
