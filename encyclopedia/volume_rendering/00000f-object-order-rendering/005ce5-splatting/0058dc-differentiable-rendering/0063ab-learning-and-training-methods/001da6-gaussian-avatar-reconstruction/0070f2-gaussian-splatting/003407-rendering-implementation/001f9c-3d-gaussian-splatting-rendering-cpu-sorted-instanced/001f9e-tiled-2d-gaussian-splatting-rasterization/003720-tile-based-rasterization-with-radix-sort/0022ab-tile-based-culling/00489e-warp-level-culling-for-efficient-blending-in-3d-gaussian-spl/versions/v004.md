# Warp-Level Culling for Efficient Blending in 3D Gaussian Splatting
## Overview
An optimization for the 3D Gaussian Splatting (3DGS) alpha blending stage that uses warp-level collaboration to subdivide image tiles and cull splats with no geometric overlap, avoiding expensive alpha evaluation [S1]. It improves rendering speed without changing the rendered output, implemented in the existing CUDA differentiable pipeline [S1]. Unlike sibling methods that optimize bounding volumes, this method focuses on geometric culling within the blending kernel to reduce the number of blending operations [S1].
## How it works
**Inputs and Outputs:**
*   **Input:** 3D Gaussian parameters (position, covariance, opacity, spherical harmonics coefficients), camera parameters (view/projection matrices), image resolution, tile configuration (default 16×16 pixels) [S1].
*   **Output:** Final 2D image (RGB + Alpha) [S1].

**Data Structures:**
*   **Gaussian Batch:** A contiguous array of Gaussian primitives processed in batches of 256 splats [S1].
*   **Tile Data:** A 2D grid of tiles covering the image, where each tile contains a list of assigned splats [S1].
*   **Shared Memory:** Used to store the current batch of splats and rearranged data for optimized shared memory access [S1].

**Algorithm Steps:**
The rendering pipeline consists of four stages, with this method optimizing the fourth [S1]:

1.  **Preprocessing:** The `preprocess_cu` kernel selects relevant 3D Gaussians and projects them into screen space as 2D splats [S1].
2.  **Depth Sorting:** Splats are sorted by distance to the camera using CUB Device Radix Sort [S1].
3.  **Instancing:** The image is divided into tiles, and splats are duplicated into each tile they overlap [S1]. During this stage, a coarse culling is performed: the splat’s maximum opacity is computed in each assigned tile [S1]. If the opacity is below the minimum contribution threshold (8-bit RGB value of 1256), the splat is culled from that tile [S1].
4.  **Blend (Warp-Level Culling):** The `blend_cu` kernel performs alpha-over compositing [S1].
    *   **Tile Subdivision:** Each image tile (e.g., 16×16 pixels) is subdivided into sub-tiles [S1]. A GPU thread block is mapped to a tile, and warps within that block collaborate to process sub-tiles [S1].
    *   **Geometric Culling:** For each sub-tile, the warp checks if any splats in the current batch have geometric overlap with the sub-tile's pixel region [S1]. Splats with no geometric overlap are culled, avoiding the expensive alpha evaluation and compositing for those pixels [S1].
    *   **Alpha-Over Compositing:** For remaining splats, the standard alpha-over formula is applied:
        $$ C_{out} = C_{in} (1 - \alpha_{splat}) + C_{splat} \alpha_{splat} $$
        $$ \alpha_{out} = \alpha_{in} (1 - \alpha_{splat}) + \alpha_{splat} $$
    *   **Batch Processing:** Splat data is processed in batches of 256 splats [S1]. Each batch is processed in two synchronization-fenced stages: fetching from DRAM and rendering [S1].
    *   **Data Rearrangement:** Splat data is rearranged into optimized structures for shared memory access to improve throughput [S1].

**Parameters:**
*   **Tile Size:** 16 × 16 pixels (default in Faster-GS) [S1].
*   **Contribution Threshold:** 1256 (minimum 8-bit RGB color value) used during instancing to cull low-opacity splats [S1].
*   **Batch Size:** 256 splats per batch [S1].

**Pseudocode:**
```python
def blend_cu_kernel(tile_id, splat_batches, thread_id):
    TILE_WIDTH = 16
    TILE_HEIGHT = 16
    BATCH_SIZE = 256
    WARPS_PER_TILE = 8
    SUB_TILE_W = TILE_WIDTH // WARPS_PER_TILE
    SUB_TILE_H = TILE_HEIGHT // WARPS_PER_TILE

    warp_id = thread_id // 32
    sub_tile_x = (warp_id % WARPS_PER_TILE) * SUB_TILE_W
    sub_tile_y = (warp_id // WARPS_PER_TILE) * SUB_TILE_H

    tile_color = [0.0, 0.0, 0.0]
    tile_alpha = 0.0

    for batch in splat_batches:
        # Stage 1: Fetch batch from DRAM into shared memory
        splat_data = batch  # Array of 256 splats

        # Stage 2: Render with warp-level geometric culling
        for i in range(len(splat_data)):
            splat = splat_data[i]
            # Sources do not specify the exact geometric overlap formula;
            # standard implementation checks bounding box intersection [G].
            cx, cy = splat.center
            sx, sy = splat.scale
            if abs(cx - (sub_tile_x + SUB_TILE_W / 2)) <= sx + SUB_TILE_W / 2 and \
               abs(cy - (sub_tile_y + SUB_TILE_H / 2)) <= sy + SUB_TILE_H / 2:
                a = splat.opacity
                c = splat.color
                tile_color[0] = tile_color[0] * (1.0 - a) + c[0] * a
                tile_color[1] = tile_color[1] * (1.0 - a) + c[1] * a
                tile_color[2] = tile_color[2] * (1.0 - a) + c[2] * a
                tile_alpha = tile_alpha * (1.0 - a) + a

    write_tile_to_framebuffer(tile_id, tile_color, tile_alpha)
```

## Subtopics

### [GEMM-GS Blending](15814-gemm-gs-blending.md)
GEMM-GS is a rendering optimization for 3D Gaussian Splatting (3DGS) that reformulates the opacity computation into a General Matrix Multiplication (GEMM) compatible dot-product form to leverage GPU Tensor Cores. Unlike [Warp-Level Culling for Efficient Blending in 3D Gaussian Splatting](12278-warp-level-culling-for-efficient-blending-in-3d-gaussian-spl.md), which focuses on geometric culling to reduce the number of blending operations, GEMM-GS accelerates the remaining blending computations themselves. Choose it when Tensor Core utilization is the bottleneck rather than memory bandwidth or culling overhead.

## Operating characteristics
*   **Performance:** On NVIDIA RTX 4090, the method is up to 19% faster than Faster-GS [S1]. On NVIDIA RTX 2070 Super, the method is up to 32% faster [S1]. Across all tested GPUs (RTX 4090, RTX 3090, RTX 2070 Super), the changes reduce frame time over Faster-GS by 17% (+20% FPS) on average (geometric mean) [S1]. On the RTX 2070 Super specifically, the frame time reduction is up to 24% (+32% FPS) [S1].
*   **Complexity:** The baseline alpha-blending GPU kernel (Faster-GS) performs two to three times slower than the optimistic theoretical bound [S1]. This method reduces that gap by eliminating redundant computations [S1].
*   **Strengths:** Maintains identical visual fidelity and differentiability as the original 3DGS implementation [S1]. It stays within the CUDA differentiable framework, unlike methods such as PUP 3D-GS, Sort-Free Gaussians, or VKRayGS which sacrifice image quality or differentiability [S1].
*   **Limitations:** Requires modification of the standard CUDA pipeline [S1]. Performance gains are hardware-dependent (tested on NVIDIA RTX 4090, 3090, 2070 Super) [S1].

## Background
3D Gaussian Splatting (3DGS) [Kerbl et al. 2023] has become a dominant technique for novel view synthesis [S1]. Despite thousands of follow-up methods, there is still room for improvement in rendering speed [S1]. This method analyzes the state-of-the-art inference pipeline (Faster-GS) and improves it by focusing on the alpha blending stage, which is one of the longest-running stages in the pipeline [S1]. The code implementation can be used in the ICG Neural Radiance Fields and Novel View Synthesis Framework (NeRFICG) [Kappel et al. 2026] [S1].
