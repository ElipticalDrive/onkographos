# Non-Pinhole Camera Training

Also called: Non-Pinhole Camera Adaptation

## Overview
Non-Pinhole Camera Training adapts 3D Gaussian Splatting to handle camera models that deviate from the standard pinhole assumption, such as fisheye lenses or uncentered projections [S3]. It solves geometric distortion and coordinate misalignment in non-standard imaging systems by integrating differentiable image-space warping and masking into the training loop [S3]. It sets itself apart from standard 3DGS by explicitly supporting uncentered-distorted and uncentered-undistorted camera models, whereas standard 3DGS assumes a centered pinhole model [S3].

## How it works
The method adapts the differentiable rasterizer to accommodate various non-pinhole camera geometries by modifying the projection pipeline [S3]. The core requirement is that all coordinate transformations and pixel masking operations must remain differentiable to enable end-to-end gradient backpropagation [S3].

### Data Structures
The Gaussian attributes remain standard (position, rotation, scale, opacity, spherical harmonics coefficients) [G]. The camera model structure is extended to support uncentered principal points and radial/tangential distortion parameters [G].

### Steps
1. **Camera Model Selection**: Choose the appropriate camera model based on the dataset: centered-undistorted for the Neural 3D Video Dataset, uncentered-undistorted for the Technicolor Dataset, and uncentered-distorted for the Google Immersive Dataset [S3].
2. **Differentiable Warping**: For distorted models, apply a differentiable image-space warping function to map perspective view coordinates to the distorted image plane (e.g., fish-eye) [S3].
3. **Masking**: Generate a differentiable mask to exclude invalid pixels, such as black borders resulting from undistortion or out-of-bounds warping [S3].
4. **Rasterization**: Render the Gaussians using the adapted projection, computing each Gaussian's contribution to the warped image plane [G].
5. **Loss Computation**: Compute the rendering loss only over valid pixels where the mask is active [S3].
6. **Optimization**: Update Gaussian attributes and camera parameters using gradient descent, relying on the differentiability of the warping and masking steps [S3].

### Edge Cases and Pitfalls
- **Non-Differentiable Masking**: If the mask is not differentiable, gradients may be blocked. The warping and masking must remain differentiable to allow end-to-end training [S3].
- **Black Pixels**: Undistorted images often contain black borders that must be masked out to prevent loss computation on invalid data [S3].

### Pseudocode
```python
def render_non_pinhole(gaussians, camera, image_size, target_image, mask):
    # 1. Project Gaussians to perspective plane
    perspective_coords = project_to_perspective(gaussians, camera)
    
    # 2. Apply differentiable warping for distorted models
    if camera.is_distorted:
        distorted_coords = differentiable_warp(perspective_coords, camera.distortion_coeffs)
    else:
        distorted_coords = perspective_coords
        
    # 3. Rasterize using distorted coordinates
    rendered_image = rasterize(gaussians, distorted_coords, image_size)
    
    # 4. Apply differentiable mask for invalid pixels
    masked_image = rendered_image * mask
    
    # 5. Compute loss against target
    loss = compute_loss(masked_image, target_image, mask)
    
    return loss

def project_to_perspective(gaussians, camera):
    # Standard 3DGS projection: transform 3D Gaussians to 2D screen coordinates
    # using camera extrinsics and intrinsics [G].
    return gaussians.position @ camera.extrinsics + camera.center

def differentiable_warp(coords, distortion_coeffs):
    # Apply radial/tangential distortion to 2D coordinates.
    # Uses bilinear interpolation to maintain differentiability [G].
    distorted = coords
    for k in distortion_coeffs:
        r2 = distorted.x**2 + distorted.y**2
        distorted.x += distorted.x * k * r2
        distorted.y += distorted.y * k * r2
    return distorted

def rasterize(gaussians, coords, image_size):
    # Sort Gaussians by depth, compute 2D covariance, 
    # and accumulate color/opacity per pixel [G].
    image = zeros(image_size, 3)
    for g in gaussians:
        x, y = coords[g.id]
        if 0 <= x < image_size[0] and 0 <= y < image_size[1]:
            image[y, x] += g.color * g.opacity
    return image

def compute_loss(rendered, target, mask):
    # L1 loss over valid pixels
    diff = abs(rendered - target)
    return sum(diff * mask) / sum(mask)
```

## Subtopics

### Aperture Randomized Training
A training technique introduced to disentangle defocus-aware and defocus-independent representations in an unsupervised manner by learning to generate images while randomizing the aperture size and latent codes independently [S2]. During training, the aperture size is changed randomly, and the latent codes are changed randomly [S2]. This technique is similar to techniques commonly used in viewpoint-aware representation learning, which are useful for disentangling the effect of the corresponding factor from latent codes [S2].

### Non-Pinhole Camera Adaptation
Adaptation of the 3DGS pipeline to specific non-pinhole datasets. For the Neural 3D Video Dataset, use the original centered-undistorted camera model [S3]. For the Technicolor Dataset, implement and use an uncentered-undistorted camera model [S3]. For the Google Immersive Dataset, adapt the method to fit an uncentered-distorted camera model using a differentiable image space warping function that maps perspective views to fish-eye distorted views [S3]. For real-time demos, retrain models on undistorted videos and apply a differentiable mask to exclude black pixels resulting from undistortion [S3]. Image warping and masking must remain differentiable to allow end-to-end training despite the coordinate transformations and pixel masking [S3].

## Operating characteristics
- **Time Complexity**: Similar to standard 3DGS, but with additional overhead for warping and masking operations. The differentiable warping adds computational cost per pixel [S3].
- **Memory Complexity**: Not given in the sources.
- **Performance**: Successfully reconstructs scenes on non-pinhole datasets where standard 3DGS fails entirely, such as the Matterport dataset [S1].
- **Strengths**: Handles a wide variety of camera models, including fisheye and uncentered projections. Enables training on real-world data with non-standard lenses [S3].
- **Limitations**: Requires careful implementation of differentiable warping and masking. Performance may degrade if the warping function is not smooth or if the mask is not properly handled [S3].
- **When to Use**: When training on datasets with non-pinhole cameras (e.g., fisheye, wide-angle, uncentered) [S3].
- **When Not to Use**: Not given in the sources.

## Background
Non-Pinhole Camera Training was developed to address the limitations of standard 3DGS in handling non-standard camera models. It builds on the differentiable rasterizer of 3DGS, extending it to support various camera geometries [S3]. The method has been applied to datasets such as the Neural 3D Video Dataset, Technicolor Dataset, and Google Immersive Dataset [S3]. It has also been shown to succeed on the Matterport dataset, where standard 3DGS fails [S1]. The technique of Aperture Randomized Training, while related to defocus disentanglement, shares the principle of randomizing camera parameters during training to improve representation learning [S2].
