# Truncated Gradient Updates for 3D Gaussian Splatting

Also called: TruncGradGS

## Overview
Truncated Gradient Updates is a gradient modification technique that applies truncated gradients to 'dead' Gaussians (those with low opacity) to enable long-range movement and convergence, addressing vanishing gradients in dynamic scenes or poor initialization [S1]. It sets itself apart from standard 3D Gaussian Splatting by introducing a surrogate linear gradient field for Gaussians that fall outside the rasterizer's tile-coverage threshold, allowing them to be pulled toward distant pixels rather than remaining static or diverging [S1]. Unlike sibling methods that might apply such updates globally, this method strictly restricts truncated gradients to dead Gaussians to prevent model divergence [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Raw gradients $\nabla \mathcal{L}$ computed via automatic differentiation through the differentiable rasterizer [G]; Gaussian parameters (mean $\mu$, opacity $\sigma$, alpha $\alpha$); Mahalanobis distance coefficients $a, b, c$ [S1].
*   **Outputs:** Modified gradients $\nabla \theta_{mod}$ passed to the Adam optimizer [G].

**Data Structures:**
*   **Gaussian State:** Standard 3DGS parameters: mean $\mu \in \mathbb{R}^3$, opacity $\sigma \in \mathbb{R}$, spherical harmonics coefficients, scale, rotation [G].
*   **Mahalanobis Coefficients:** $a, b, c$ derived from the Gaussian's 2D covariance matrix in screen space (Eq. 8 of [S1]).
*   **Motion Masks:** Binary masks for dynamic scenes indicating static vs. dynamic pixels, computed via frame-difference and image processing [S1].

**Numbered Steps:**

1.  **Identify Dead Gaussians:** Determine if a Gaussian $i$ is "dead" by checking if its opacity $\sigma_i$ is below the pruning threshold $\tau_{pruning}$ [S1]. Truncated gradients are applied **only** to these Gaussians to prevent divergence in well-fitted regions [S1].

2.  **Compute Mahalanobis Distance:** For each pixel $p$ contributing to the loss, calculate the squared Mahalanobis distance $r_s$ between the Gaussian mean $\mu$ and the pixel center $p$ [S1]:
    $$
    r_s = \|\mu - p\|_2^2 \pm \sqrt{\frac{-2 \log \tau}{K}}
    $$
    where $K$ is defined as:
    $$
    K = a(\mu_x - p_x)^2 + 2b(\mu_x - p_x)(\mu_y - p_y) + c(\mu_y - p_y)^2
    $$
    The coefficients $a, b, c$ are obtained from the Gaussian's 2D covariance matrix [S1]. Note: The source text presents the formula with a $\pm$ and a square root structure involving $\tau$ (likely the alpha-blending threshold or a specific cut-off value), but explicitly states $r_s = \|\mu - p\|_2^2$ in the summary and links $K$ to Eq. (8). The condition for truncation relies on comparing the distance against a threshold $\tau$ [S1].

3.  **Check Alpha Gradient Sign:** Evaluate the gradient with respect to alpha, $\frac{\partial L}{\partial \alpha_i}$ [S1].
    *   If $\frac{\partial L}{\partial \alpha_i} \ge 0$, do **not** apply the truncated gradient. Applying it when positive would cause a "long-range push," making Gaussians repel each other [S1].
    *   If $\frac{\partial L}{\partial \alpha_i} < 0$, proceed to determine the update path [S1].

4.  **Determine Gradient Update Path:** Based on the product of opacity $\sigma$ and alpha $\alpha$ relative to $1/255$ and the Mahalanobis distance, select one of three paths [S1]:
    *   **Normal Path:** If $\sigma\alpha \ge 1/255$ (high-pass filter), the Gaussian receives normal gradients from the rasterizer [S1].
    *   **Truncated Path:** If $\sigma\alpha < 1/255$ (low density or low opacity) AND the Mahalanobis distance is above the threshold, the Gaussian receives truncated gradients [S1].
        *   If the low contribution is due to low opacity $\sigma$, compute the gradient **only** for opacity $\sigma$ [S1].
        *   If due to low alpha $\alpha$ (distance), compute the gradient for the mean $\mu$ using the truncated surrogate [S1].
    *   **Skip Path:** If $\sigma\alpha < 1/255$ AND the Mahalanobis distance is below the threshold, the Gaussian receives **no** gradients [S1].

5.  **Compute Truncated Gradient:** For Gaussians on the Truncated Path, the gradient is derived from a linear surrogate function $G'(x)$, where $x$ is the solution to $G(x) = \tau$ [S1]. The slope parameter $m$ influences the range of action: a lower $m$ yields a near-constant long-range gradient approximating the cut-off gradient, while a higher $m$ yields a sharp decay [S1]. The exact derivation of $G'(x)$ is in the supplementary material of [S1], but the implementation uses the displacement direction towards the pixel $p$ scaled by this surrogate gradient magnitude [S1].

6.  **Expand Tile-Coverage Radius:** For dead Gaussians whose radius is below a threshold, expand the tile-coverage radius [S1]. This addresses tile-based culling of the rasterizer, enabling long-distance pixel error contributions to be registered by the backward pass [S1].

7.  **Interleaved Optimization Strategy:** Alternate between optimization steps using truncated gradients and normal optimization with Adaptive Density Control (ADC) turned on [S1]. This prevents perturbations to the accumulated viewspace gradient from affecting ADC [S1].

8.  **Delay Pruning:** Delay the pruning of primitives until the end of training [S1]. This allows dead Gaussians to receive long-range gradients and converge to distant pixels before being pruned [S1].

9.  **Dynamic Scene Handling (Optional):** For dynamic methods, create viewpoint-dependent motion masks via frame-difference and image processing on input videos [S1]. Ignore contributions of static pixels to reduce computation [S1].

**Parameters:**
*   **Slope parameter $m$:** Influences the range of action of the truncated gradient in the image plane. A lower $m$ yields a near-constant long-range gradient approximating the cut-off gradient; a higher $m$ yields a sharp decay from the cut-off gradient [S1]. Value not given in the sources.
*   **Pruning threshold $\tau_{pruning}$:** Opacity threshold below which a Gaussian is considered "dead" [S1]. Value not given in the sources.
*   **Tile-coverage radius threshold:** Radius below which dead Gaussians are expanded [S1]. Value not given in the sources.

**Edge Cases and Pitfalls:**
*   **Model Divergence:** Accumulated truncated gradients may surpass the true gradient, especially for "very bad fits" (no normal gradients) or "good fits" (true gradient near zero) [S1]. Prevented by applying truncated gradients **only** to dead Gaussians ($\sigma_i < \tau_{pruning}$) [S1].
*   **Repulsion:** Applying truncated gradients when $\frac{\partial L}{\partial \alpha_i} \ge 0$ causes Gaussians to repel each other ("long-range push") [S1].
*   **Performance Overhead:** Without optimizations, the method can be significantly slower. Restricted to dead Gaussians and dynamic motion masks mitigate this [S1].
*   **ADC Perturbation:** Truncated gradients perturb the accumulated viewspace gradient, which can interfere with Adaptive Density Control (ADC). Mitigated by interleaved optimization [S1].

## Operating characteristics
*   **Time Complexity:** Training is 1–10× slower than the baseline 3DGS, depending on the scene and primitive count [S1]. Inference speed is unaffected [S1].
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:**
    *   **Static Scene (Mip-NeRF360, Random Init):** PSNR 25.16 (vs 24.74), SSIM 0.8511 (vs 0.8351), LPIPS 0.1974 (vs 0.2106), #GS 0.799M (vs 1.126M) [S1].
    *   **Dynamic Scene (Neural 3D Video):** PSNR 31.70 (vs 30.22), SSIM 0.9493 (vs 0.9443), LPIPS 0.1339 (vs 0.1360), #GS 1.733M (vs 2.806M) [S1].
*   **Scaling:** The method is plug-and-play and works with 3DGS, 2DGS, 4DGS, CEM-4DGS, and 4DScaffold [S1].
*   **Strengths:** Improves optimization robustness, handles large spatio-temporal divergence, recovers complex motion and fine details, reduces Gaussian count while improving metrics [S1].
*   **Limitations:** Slower training time; requires careful tuning of $m$ and thresholds; risk of divergence if applied to non-dead Gaussians [S1].
*   **When to Use:** Static and dynamic scene reconstruction with poor initialization or large motion; when baseline 3DGS exhibits floaters, blurring, or missing structures [S1].
*   **When Not to Use:** When training speed is critical and baseline performance is sufficient; when scene has no significant divergence or initialization issues [S1].
