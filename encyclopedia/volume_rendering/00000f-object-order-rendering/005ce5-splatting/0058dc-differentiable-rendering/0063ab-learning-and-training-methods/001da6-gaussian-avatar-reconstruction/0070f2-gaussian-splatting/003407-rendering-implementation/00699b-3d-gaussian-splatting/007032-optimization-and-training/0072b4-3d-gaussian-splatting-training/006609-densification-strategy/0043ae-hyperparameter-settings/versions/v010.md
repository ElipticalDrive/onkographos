# Hyperparameter Settings

Also called: Optimizer and Regularization Settings, Optimizer settings, Phys3DGS Hyperparameter Settings, Training Hyperparameters

## Overview
Hyperparameter Settings define the numerical configuration for the optimization process, regularization terms, and learning rates required to stabilize the training of 3D Gaussian Splatting (3DGS) and its variants. This method solves the problem of training instability and convergence failure, particularly in inverse rendering or sparse-view scenarios, by providing specific values for optimizer parameters, loss weights, and per-parameter learning rates. It is distinct from sibling methods like [Adaptive Density Control](9188-adaptive-density-control.md) because it does not dynamically adjust the primitive count but rather fixes the numerical constraints under which the densification and rendering operations occur.

## How it works
The method consists of configuring the Adam optimizer, defining regularization strengths for physical properties, and assigning specific learning rates to each learnable parameter of the Gaussian primitives.

**Inputs:**
*   Model parameters: Position $\mu$, Scale $s$, Rotation $q$, Opacity $\alpha$, Spherical Harmonic coefficients $\mathbf{c}$, and material/lighting parameters (e.g., Base Color, Metallic, Roughness, Reflectivity).
*   Training configuration: Iteration count, dataset type (synthetic vs. real).

**Outputs:**
*   Optimizer state (momentum buffers).
*   Updated model parameters after gradient descent.

**Data Structures:**
The parameters are stored in contiguous buffers for the Adam optimizer. The learning rate is a scalar value associated with each parameter group.

**Steps:**
1.  **Initialize Optimizer:** Configure Adam with $\beta_1 = 0.9$, $\beta_2 = 0.999$, and $\epsilon = 10^{-15}$ [S1][S2, unofficial].
2.  **Set Regularization Strengths:**
    *   For physically-based models, set smoothness regularizer strengths: $\lambda_{smooth} = 0.06$ for Base Color, $0.02$ for Roughness, and $0.02$ for Metallic [S2, unofficial].
    *   Set other regularizer strengths ($\lambda_o, \lambda_{sc}, \lambda_{sr}$) to $1.0$ to prevent instability caused by erroneous Gaussians [S2, unofficial].
3.  **Assign Learning Rates:** Apply the following learning rates (LR) to the respective parameters [S2, unofficial]:
    *   Position: $1.6 \times 10^{-4}$
    *   Color SH: $2.5 \times 10^{-3}$
    *   Scale: $5 \times 10^{-3}$
    *   Opacity: $5 \times 10^{-2}$
    *   Base Color: $1 \times 10^{-2}$
    *   Metallic: $1 \times 10^{-2}$
    *   Roughness: $1 \times 10^{-2}$
    *   Normal Rotation: $1 \times 10^{-3}$
    *   Direct Light SH (deg=0): $2.5 \times 10^{-3}$
    *   Direct Light SH (deg>0): $1 \times 10^{-4}$
    *   Indirect Light SH (deg=0): $2.5 \times 10^{-4}$
    *   Indirect Light SH (deg>0): $1 \times 10^{-3}$
    *   Visibility SH: $0.1$
4.  **Handle Dynamic/Reflective Parameters (if applicable):**
    *   Initialize Reflectivity to $0.1$ [S1].
    *   Set Reflectivity learning rate $\gamma_r = 0.00016$ [S1].
    *   For MLP-based deformations, initialize weights from a normal distribution with $\sigma = 10^{-5}$ [S1].
    *   Set MLP learning rate $\gamma_{MLP} = 0.0008$, decaying exponentially to $1.6 \times 10^{-6}$ over 60,000 iterations [S1].
5.  **Loss Weighting (if applicable):**
    *   Set loss weights $\alpha = 5$ (or $\alpha = 1$ for synthetic scenes) and $\beta = 0.0008$ [S1].

**Pseudocode:**
```python
def configure_optimizer(params, config):
    """
    Configures the Adam optimizer and regularization settings for 3DGS training.
    """
    # 1. Initialize Adam Optimizer
    # beta1=0.9, beta2=0.999, eps=1e-15
    optimizer = Adam(params, lr=1.0, betas=(0.9, 0.999), eps=1e-15)
    
    # 2. Define Parameter Groups with Specific Learning Rates
    # Note: In practice, these are passed as a list of dicts to the optimizer
    param_groups = [
        {"params": params.position, "lr": 1.6e-4},
        {"params": params.color_sh, "lr": 2.5e-3},
        {"params": params.scale, "lr": 5.0e-3},
        {"params": params.opacity, "lr": 5.0e-2},
        {"params": params.base_color, "lr": 1.0e-2},
        {"params": params.metallic, "lr": 1.0e-2},
        {"params": params.roughness, "lr": 1.0e-2},
        {"params": params.normal_rotation, "lr": 1.0e-3},
        {"params": params.direct_light_sh_deg0, "lr": 2.5e-3},
        {"params": params.direct_light_sh_deg_gt0, "lr": 1.0e-4},
        {"params": params.indirect_light_sh_deg0, "lr": 2.5e-4},
        {"params": params.indirect_light_sh_deg_gt0, "lr": 1.0e-3},
        {"params": params.visibility_sh, "lr": 0.1}
    ]
    
    # Re-initialize optimizer with specific LR groups if not already done
    optimizer = Adam(param_groups, betas=(0.9, 0.999), eps=1e-15)
    
    # 3. Set Regularization Strengths
    # For Phys3DGS: smoothness weights
    lambda_smooth_base_color = 0.06
    lambda_smooth_roughness = 0.02
    lambda_smooth_metallic = 0.02
    
    # Other regularizers (opacity, scale, etc.)
    lambda_o = 1.0
    lambda_sc = 1.0
    lambda_sr = 1.0
    
    # 4. Dynamic/Reflective Settings (if using ToRF or similar)
    reflectivity_init = 0.1
    reflectivity_lr = 0.00016
    mlp_lr_init = 0.0008
    mlp_lr_final = 1.6e-6
    mlp_decay_iters = 60000
    
    # Loss weights
    alpha_loss = 5.0 # 1.0 for synthetic
    beta_loss = 0.0008
    
    return optimizer, {
        "lambda_smooth": {
            "base_color": lambda_smooth_base_color,
            "roughness": lambda_smooth_roughness,
            "metallic": lambda_smooth_metallic
        },
        "lambda_other": {"o": lambda_o, "sc": lambda_sc, "sr": lambda_sr},
        "reflectivity": {"init": reflectivity_init, "lr": reflectivity_lr},
        "mlp": {"lr_init": mlp_lr_init, "lr_final": mlp_lr_final, "decay_iters": mlp_decay_iters},
        "loss": {"alpha": alpha_loss, "beta": beta_loss}
    }
```

**Edge Cases and Pitfalls:**
*   **Instability from Erroneous Gaussians:** If a single Gaussian behaves abnormally (e.g., driven to the opposite side of the surface, extremely large scale, or extreme opacity), it causes training instability [S2, unofficial].
*   **Visibility Interference:** Erroneous Gaussians interfere with visibility, occluding global illumination [S2, unofficial].
*   **Gradient Overflow:** The optimizer attempts to compensate for occlusion by increasing local intensity or decreasing opacity to extreme values, leading to large gradients in SH coefficients or opacity, potentially causing overflow [S2, unofficial]. High regularization strengths ($\lambda=1.0$) are used to mitigate this [S2, unofficial].

## Subtopics

### [Conditional 3DGS Optimization and Rendering](11459-conditional-3dgs-optimization-and-rendering.md)
Adapts 3DGS training to handle 7D data (3D spatial, 1D temporal, 3D directional) by converting conditional representations into standard 3DGS formats. It distinguishes itself by leveraging temporal cues for adaptive density control and modifying pruning thresholds to account for time and view-direction modulation.

### [Blended Error Densification and Splitting](13892-blended-error-densification-and-splitting.md)
Uses an auxiliary per-pixel error metric to drive densification, redistributing L1 error norms to primitives proportional to their rendering contribution. It is distinct from gradient-based methods by explicitly using accumulated error as probability weights for splitting.

### GaMeS
A method simplifying mesh generation by utilizing an initial mesh or estimating it in a single-stage training process [S3]. It introduces a pseudo-mesh of unconnected triangle faces with Gaussian components positioned on them to ensure proper alignment [S3]. Deformation is realized by modifying pseudo-mesh positions, which propagate to the Gaussian mesh [S3]. Pitfall: Exhibits artifacts when dealing with significant deformations in meshes with large faces, leading to inaccuracies [S3].

### Sparse Matching Integration
Integrates mid-points derived from feature-matching correspondences with randomly initialized Gaussian points [S4]. It applies geometric regularization specifically to correspondences that pass through an outlier filter [S4]. Unlike dense matcher-based methods that cause blurriness in high-frequency areas, this sparse matching approach yields more precise correspondences and better high-frequency reconstruction [S4]. On LLFF with 3 views, it improves PSNR from 16.50 (Base 3DGS) to 19.90, an improvement of ~3 dB [S4].

## Operating characteristics
*   **Time Complexity:** Determined by the Adam optimizer updates and the forward/backward pass of the rasterizer. The specific hyperparameters do not change the asymptotic complexity but affect convergence speed.
*   **Memory Complexity:** Depends on the number of Gaussians and the size of the SH coefficients. The hyperparameters themselves consume negligible memory.
*   **Strengths:** Provides stable convergence for complex inverse rendering tasks (e.g., Phys3DGS) and sparse-view scenarios (e.g., Sparse Matching Integration).
*   **Limitations:** Requires careful tuning of regularization strengths to prevent instability from erroneous Gaussians. Fixed learning rates may not adapt to varying scene complexities without annealing (as seen in MLP decay).
*   **When to use:** When training 3DGS for inverse rendering, physically-based materials, or sparse-view reconstruction where standard 3DGS hyperparameters lead to instability or poor high-frequency detail.

## Background
The specific hyperparameter settings for Phys3DGS were introduced in "Phys3DGS: Physically-based 3D Gaussian Splatting for Inverse Rendering" (2024) [S2, unofficial]. The settings for dynamic/reflective scenes (ToRF) were introduced in "Time of the Flight of the Gaussians: Optimizing Depth Indirectly in Dynamic Radiance Fields" (2025) [S1]. The sparse matching integration settings were introduced in "SGCNeRF: Few-Shot Neural Rendering via Sparse Geometric Consistency Guidance" (2025) [S4]. GaMeS was surveyed in "A survey on 3D editing based on NeRF and 3DGS" (2026) [S3].
