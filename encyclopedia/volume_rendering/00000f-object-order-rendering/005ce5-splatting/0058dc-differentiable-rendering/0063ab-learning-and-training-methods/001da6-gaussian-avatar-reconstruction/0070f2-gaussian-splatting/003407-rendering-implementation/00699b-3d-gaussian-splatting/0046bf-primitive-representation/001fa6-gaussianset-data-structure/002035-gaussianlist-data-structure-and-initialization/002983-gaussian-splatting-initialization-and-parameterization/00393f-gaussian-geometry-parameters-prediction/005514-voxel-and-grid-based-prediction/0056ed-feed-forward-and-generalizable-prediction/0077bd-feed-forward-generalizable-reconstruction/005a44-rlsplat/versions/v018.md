# RLSplat

Also called: Resource-Linear Budget Control for Feed-forward 3D Gaussian Splatting

## Overview
RLSplat is a resource-linear, budget-controllable feed-forward 3D Gaussian Splatting (FF3DGS) framework that generates exactly $B$ Gaussians from uncalibrated input images, ensuring that inference latency and peak memory scale linearly with the requested Gaussian budget [S1, unofficial]. Unlike prior budget-controllable methods that predict a dense set of candidates and subsequently prune them—resulting in nearly constant computational cost regardless of the target budget—RLSplat learns a discrete allocation policy to distribute the budget across local scene regions and refines the resulting Gaussians via a resource-linear decoder with hierarchical neighbor search [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of $V$ uncalibrated context images $\{I_i\}_{i=1}^V$ and an integer target Gaussian budget $B$.
*   **Outputs:** A set of $B$ 3D Gaussians $\mathcal{G} = \{g_b\}_{b=1}^B$ and the camera parameters $\{P_i\}_{i=1}^V$ for the context images. Each Gaussian $g_b$ consists of a 3D center, opacity, scale, rotation, and color coefficients [S1, unofficial].

**Data Structures:**
1.  **Anchor Tokens:** The geometry backbone encodes the input images into $N$ anchor tokens $\{a_n\}_{n=1}^N$. Each anchor represents a local 3D region of the scene [S1, unofficial].
2.  **Allocation Vector:** A discrete vector $\mathbf{k} \in \mathbb{Z}_{\ge 0}^N$ where $k_n$ is the number of Gaussians assigned to anchor $n$, subject to the constraint $\sum_{n=1}^N k_n = B$ [S1, unofficial].
3.  **Gaussian Tokens:** Each anchor $n$ spawns $k_n$ Gaussian tokens. The total number of Gaussian tokens is exactly $B$ [S1, unofficial].
4.  **Hierarchical Neighbor Search:** Used to find the $K_{gs}$ nearest Gaussian tokens for each token efficiently. This involves searching $K_{anc}$ anchor neighbors first [S1, unofficial].

**Parameters:**
*   $B$: Target Gaussian budget. Typical evaluation values are 2K (2,048) and 64K. On the ACID dataset with 8 views, $B=8,192$ (1,024 per view) is used. On RE10K, $B=8,000$ is used [S1, unofficial].
*   $K_{gs}$: Number of nearest Gaussian neighbors each token attends to during refinement. Default ablation value is 16. This can be changed at inference without retraining [S1, unofficial].
*   $K_{anc}$: Number of anchor neighbors used in the hierarchical neighbor search. Fixed value in ablations is 16 [S1, unofficial].
*   $C$: Number of rollouts (candidate allocations) drawn per training step for the Group Sequence Policy Optimization (GSPO) [S1, unofficial].

**Algorithm Steps:**

1.  **Geometry Encoding:** Given context images $\{I_i\}$, a geometry backbone (e.g., based on Burzio et al., 2026) encodes them into $N$ anchor tokens $\{a_n\}_{n=1}^N$ and predicts the camera parameters $\{P_i\}_{i=1}^V$ [S1, unofficial].
2.  **Gaussian Allocation:** A Gaussian allocation policy $\pi_\psi$ assesses the local significance of each anchor (based on image features like texture complexity) and predicts a discrete allocation $\mathbf{k} \in \mathbb{Z}_{\ge 0}^N$ such that $\sum_{n=1}^N k_n = B$. This policy is trained using Group Sequence Policy Optimization (GSPO) [S1, unofficial].
3.  **Token Spawning:** Each anchor $n$ spawns $k_n$ Gaussian tokens. The total number of Gaussian tokens is exactly $B$ [S1, unofficial].
4.  **Resource-Linear Decoding:**
    *   **Initialization:** The decoder instantiates initial Gaussian states (center, scale, rotation, opacity, color) from the spawned tokens [S1, unofficial].
    *   **Hierarchical Neighbor Search:** For each Gaussian token, the system identifies its $K_{gs}$ nearest Gaussian neighbors. This is done efficiently by first finding $K_{anc}$ nearest anchor neighbors and then searching within those anchors' spawned Gaussians [S1, unofficial].
    *   **Local Refinement:** Each Gaussian token refines its state via local cross-attention over its $K_{gs}$ nearest Gaussian neighbors. This replaces global self-attention, reducing complexity from $O(B^2)$ to $O(B \cdot K_{gs})$ [S1, unofficial].
5.  **Rendering:** The final set of $B$ Gaussians $\mathcal{G}$ is rendered into target views using differentiable rasterization to compute reconstruction losses (e.g., L1, SSIM) for training [S1, unofficial].

**Training Objective:**
The allocation policy $\pi_\psi$ is optimized using GSPO. At each training step:
1.  Draw $C$ candidate allocations $\mathbf{k}^{(c)} \sim \pi_{\text{old}} = \text{Mult}(B, \text{sg}(\mathbf{p}))$, where $\mathbf{p}$ are the policy probabilities and $\text{sg}(\cdot)$ stops gradients [S1, unofficial].
2.  For each rollout $c$, generate the 3DGS representation $\mathcal{G}^{(c)}$ and render an image $\hat{I}^{(c)}$ at novel target views [S1, unofficial].
3.  Compute the reconstruction loss $\mathcal{L}_{\text{recon}}$ against the ground-truth image $I$ without gradient tracking. This loss serves as the reward signal [S1, unofficial].
4.  The model also utilizes specific losses: a projection loss (to tie anchors to image regions), an offset loss, and a Voronoi loss. Removing the projection loss causes training to fail entirely [S1, unofficial].

**Pseudocode:**

```python
def rl_splat_forward(context_images, budget_B):
    """
    Forward pass of RLSplat.
    context_images: List of V uncalibrated RGB images.
    budget_B: Integer, total number of Gaussians to generate.
    Returns: Set of B Gaussians G, Camera parameters P.
    """
    # 1. Geometry Backbone
    # Encodes images into N anchor tokens and predicts camera poses
    anchor_tokens, camera_params = geometry_backbone(context_images)
    N = len(anchor_tokens)
    
    # 2. Gaussian Allocation Policy
    # Predicts allocation proportions p, then samples discrete allocation k
    # In inference, we sample from the trained policy
    allocation_probs = allocation_policy(anchor_tokens)
    # Sample discrete allocation k such that sum(k) == budget_B
    # Implementation detail: Multinomial sampling with stop-gradient on probs
    # k is a list/array of length N, where k[n] >= 0
    k = sample_allocation(allocation_probs, budget_B)
    
    # 3. Spawn Gaussian Tokens
    # Each anchor n spawns k[n] Gaussian tokens
    gaussian_tokens = []
    for n in range(N):
        count = k[n]
        # Spawn 'count' tokens from anchor n
        # Each token gets initial attributes from anchor n
        tokens_for_anchor = spawn_tokens(anchor_tokens[n], count)
        gaussian_tokens.extend(tokens_for_tokens)
        
    # 4. Resource-Linear Decoding
    # Refine tokens via local cross-attention with hierarchical neighbor search
    
    # Precompute neighbor indices for efficiency
    # Find Kanc anchor neighbors for each anchor
    anchor_neighbors = hierarchical_anchor_search(anchor_tokens, Kanc=16)
    
    # For each Gaussian token, find Kgs nearest Gaussian neighbors
    # This involves checking neighbors of the anchor's anchor neighbors
    gaussian_neighbors = hierarchical_gaussian_search(gaussian_tokens, anchor_neighbors, Kgs=16)
    
    # Local refinement
    refined_gaussians = []
    for i, token in enumerate(gaussian_tokens):
        # Get indices of Kgs nearest neighbors
        neighbor_indices = gaussian_neighbors[i]
        neighbor_tokens = [gaussian_tokens[j] for j in neighbor_indices]
        
        # Cross-attention refinement
        refined_token = local_cross_attention(token, neighbor_tokens)
        refined_gaussians.append(refined_token)
        
    return refined_gaussians, camera_params

def rl_splat_train_step(context_images, ground_truth_images, budget_B):
    """
    Training step using GSPO.
    """
    # 1. Get anchor tokens and camera params
    anchor_tokens, camera_params = geometry_backbone(context_images)
    
    # 2. Sample C rollouts from policy
    allocation_probs = allocation_policy(anchor_tokens)
    rollouts = []
    for c in range(C):
        # Sample k with stop-gradient on probs
        k = sample_allocation(allocation_probs, budget_B, stop_grad=True)
        rollouts.append(k)
        
    rewards = []
    for k in rollouts:
        # Generate Gaussians for this allocation
        gaussians = generate_gaussians_from_allocation(anchor_tokens, k)
        
        # Render images
        rendered_images = render_gaussians(gaussians, camera_params)
        
        # Compute reconstruction loss (no gradient)
        loss = compute_reconstruction_loss(rendered_images, ground_truth_images)
        rewards.append(loss)
        
    # 3. Update policy using GSPO
    # Use rewards to update allocation_policy parameters
    update_policy(allocation_policy, rollouts, rewards)
    
    return sum(rewards) / len(rewards)
```

**Edge Cases and Pitfalls:**
*   **Projection Loss:** The projection loss is critical; without it, training fails entirely as there is no constraint tying an anchor's Gaussians to the image region it was encoded from [S1, unofficial].
*   **Voronoi Loss:** Removing the Voronoi loss causes a significant drop in performance (2.51 dB) because Gaussians leave their anchor's cell, and the hierarchical search no longer retrieves their true neighbors [S1, unofficial].
*   **Local Refinement:** Removing the local refinement module lowers PSNR by 0.96 dB, as each Gaussian is predicted from its own token alone and cannot be made consistent with neighbors [S1, unofficial].
*   **Hierarchical Search Accuracy:** The hierarchical neighbor search approximates the nearest neighbors. Using $K_{anc}=16$ and $K_{gs}=16$ provides a good balance between speed and accuracy. Exact search over all $B$ Gaussians is 27× slower (219.6 ms vs 8.1 ms) with negligible quality difference at high budgets [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The decoding cost is $O(B \cdot K_{gs})$, scaling linearly with the Gaussian budget $B$. This contrasts with global self-attention, which costs $O(B^2)$ [S1, unofficial].
*   **Memory Complexity:** Peak memory scales linearly with $B$. At a budget of 2K Gaussians, RLSplat uses 9.6× less peak memory than F4 Splat [S1, unofficial].
*   **Inference Latency:** Latency scales linearly with $B$. At 2K Gaussians, RLSplat runs 4.1× faster than F4 Splat [S1, unofficial].
*   **Performance:**
    *   On ACID (B=8,192): PSNR 22.84 dB, SSIM 0.643, LPIPS 0.353 [S1, unofficial].
    *   On RE10K (B=8,000): Full-view PSNR 26.51 dB, compared to 23.42 dB for F4 Splat and 21.82 dB for EcoSplat [S1, unofficial].
    *   At 2K Gaussians, RLSplat achieves higher PSNR than F4 Splat [S1, unofficial].
*   **Strengths:**
    *   True resource-linearity: Inference cost and memory decrease linearly with the budget.
    *   High fidelity at low budgets: Allocates more Gaussians to high-frequency structures (e.g., thin stair balusters) and fewer to smooth regions.
    *   No retraining required to change $K_{gs}$ or $B$ at inference [S1, unofficial].
*   **Limitations:**
    *   Requires training with GSPO, which involves non-differentiable discrete allocations.
    *   Performance depends on the quality of the hierarchical neighbor search; if $K_{anc}$ or $K_{gs}$ are too small, neighbor retrieval may be inaccurate [S1, unofficial].
*   **When to use:** Applications requiring limited resource budgets, such as AR/VR, robotics, and digital content creation, where inference latency and memory must be strictly controlled [S1, unofficial].
*   **When not to use:** When maximum possible quality is required regardless of resource cost, or when the scene geometry is extremely complex and requires global context that local cross-attention might miss (though hierarchical search mitigates this) [S1, unofficial].

## Background
RLSplat was proposed by Bae, Park, and Kim from KAIST. The paper "RLSplat: Resource-Linear Budget Control for Feed-forward 3D Gaussian Splatting" was published in 2026 (unofficial source, preprint) [S1, unofficial]. It addresses the limitations of prior budget-controllable FF3DGS methods like EcoSplat and F4 Splat, which predict dense sets of Gaussians and then prune them, resulting in constant inference costs. RLSplat introduces a Gaussian allocation policy trained with Group Sequence Policy Optimization (GSPO) and a resource-linear decoder with hierarchical neighbor search to achieve true linear scaling of inference cost with the Gaussian budget [S1, unofficial].
