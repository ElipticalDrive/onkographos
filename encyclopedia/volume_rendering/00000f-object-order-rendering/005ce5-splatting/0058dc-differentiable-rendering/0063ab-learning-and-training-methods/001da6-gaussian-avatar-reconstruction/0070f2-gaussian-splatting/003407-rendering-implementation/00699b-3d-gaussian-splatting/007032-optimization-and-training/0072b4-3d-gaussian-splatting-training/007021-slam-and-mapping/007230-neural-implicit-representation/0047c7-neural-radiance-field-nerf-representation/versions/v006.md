# Neural Radiance Field (NeRF) Representation

Also called: INGP, Instant Neural Graphics Primitives, Photon Field Networks, Photon Fields

## Overview
Neural Radiance Field (NeRF) representation is a method for implicitly encoding a 3D scene as a continuous volumetric function using a neural network, enabling high-fidelity novel view synthesis by differentiating through the volume rendering equation [S1][S2, unofficial]. It differs from explicit representations like 3D Gaussian Splatting by storing scene geometry and appearance within a compact network weight set rather than millions of discrete primitives, trading higher memory usage for implicit smoothness and avoiding the floating artifacts associated with sparse point clouds [S2, unofficial].

## How it works
The NeRF representation maps 3D spatial coordinates and viewing directions to color and volume density. The implementation involves two distinct paradigms found in the literature: the standard implicit radiance field (often associated with Instant Neural Graphics Primitives/INGP) and the Photon Field Network variant which specifically models indirect global illumination.

### Inputs and Outputs
*   **Inputs:** 3D position $x \in \mathbb{R}^3$, view direction $\vec{\omega} \in \mathbb{R}^3$ (normalized spherical coordinates). For Photon Fields, an additional phase function coefficient $g \in [-1, 1]$ is required [S1].
*   **Outputs:** Color vector $(R, G, B)$ and volume density $\sigma$ (standard NeRF) or indirect radiance $L_i$ (Photon Fields) [S1][S2, unofficial].

### Data Structures

#### Standard NeRF / INGP Encoding
The scene is represented by a Multi-Layer Perceptron (MLP) preceded by a positional or hash-based encoding [S1].
*   **Hashgrid Encoding:** Used for positions and directions to accelerate training and inference [S1].
    *   **Levels:** 16 grid levels.
    *   **Features per level:** 8.
    *   **Scaling factor:** $2\times$ between levels.
    *   **Hash table size:** $2^{19}$ [S1].
*   **Network Architecture:**
    *   **Type:** 5-layer MLP.
    *   **Neurons:** 64 per layer.
    *   **Activation:** ReLU between hidden layers; no output activation [S1].
    *   **Input:** Concatenated encoded position and direction (and phase $g$ if applicable). The phase $g$ is left unencoded as it is a unitless scale [S1].

#### Photon Field Specifics
*   **Phase Coefficients ($G$):** A discrete set of coefficients used to bin the phase spectrum. The optimal set identified is $G = \{-0.75, 0.0, 0.75\}$ [S1].
*   **Photon Map:** A GPU-accelerated kd-tree constructed from traced photons to enable fast KNN queries for ground truth generation [S1].

### Training Data Generation (Photon Fields)
To train the field, ground truth indirect radiance is computed from a photon map [S1].

1.  **Photon Tracing:** Photons are generated from random light sources. For each photon, a phase coefficient $g$ is randomly selected from $G$. Photons are traced through the volume using delta tracking. Only photons past their first interaction (bounces $\ge 1$) are stored to capture indirect illumination [S1].
2.  **Sampling:** Training batches of size $2^{16}$ are generated. Each batch contains uniformly sampled grid coordinates $x \in [0,1]^3$, random uniform directions $\vec{\omega}$, and phase coefficients $g$ [S1].
3.  **Radiance Estimation:** For each sample, a KNN query ($K=1024$) is performed on the kd-tree to find nearby photons with the matching phase $g$. The radiance is estimated using an adaptive radius $r$ (distance to the farthest photon in the query):
    $$ L_i(x, \vec{\omega}) \approx \sum_{n=1}^K p_g(x, \vec{\omega}, \vec{\omega}_n) \frac{\Phi_n}{4\pi r^3} $$
    where $\Phi_n$ is the photon intensity and $p_g$ is the Henyey-Greenstein phase function [S1].
4.  **Target Encoding:** Radiance values are log-encoded to normalize them to $[0,1]$ for stable training. Given a precision parameter $\psi$ (typically 4-6):
    $$ L_i'(x, \vec{\omega}) = \begin{cases} -\frac{\log_{10}(L_i(x, \vec{\omega}))}{\psi} & \text{if } L_i(x, \vec{\omega}) > 10^{-\psi} \\ 1 & \text{otherwise} \end{cases} $$
    Values below the threshold are clamped to 1 (which maps to 0 in the inverse transformation) [S1].

### Rendering Process
The scene is rendered by sampling points along camera rays and aggregating color and opacity via alpha compositing [S2, unofficial].

1.  **Ray Sampling:** For a camera ray, sample $N$ points $x_j$ along the segment.
2.  **Network Query:** Query the network at each $x_j$ with the ray direction $\vec{\omega}$ to get color $c_j$ and density $\sigma_j$ (or indirect radiance $L_i$ for Photon Fields) [S1][S2, unofficial].
3.  **Alpha Compositing:** Compute the final color $C$ using front-to-back blending:
    $$ C = \sum_{j=1}^N T_j \alpha_j c_j $$
    where $\alpha_j = 1 - \exp(-\sigma_j \delta_j)$ is the opacity of the sample, $\delta_j$ is the distance between samples, and $T_j = \exp(-\sum_{k=1}^{j-1} \sigma_k \delta_k)$ is the accumulated transmittance [S2, unofficial].

### Optimization
The network parameters are optimized by minimizing the difference between the rendered image and the ground truth training image [S2, unofficial].
*   **Loss Function:** L1 loss combined with a Structural Similarity (SSIM) term [S2, unofficial].
*   **Gradient Descent:** Errors are backpropagated through the differentiable rasterizer/renderer to update the network weights [S2, unofficial].

### Pseudocode: Training Step (Photon Fields)

```python
def train_step(network, photon_kd_tree, batch_size=2**16, psi=4):
    """
    Performs one training step for a Photon Field network.
    """
    # 1. Generate random samples
    # x: shape (batch_size, 3), uniform in [0, 1]
    # omega: shape (batch_size, 3), random uniform directions
    # g: shape (batch_size,), random choice from G = {-0.75, 0.0, 0.75}
    x, omega, g = generate_random_samples(batch_size)
    
    # 2. Encode inputs
    # hash_encode returns concatenated features from 16 grid levels
    x_encoded = hash_encode(x, levels=16, features=8, hash_size=2**19)
    omega_encoded = hash_encode(omega, levels=16, features=8, hash_size=2**19)
    # g is not encoded
    input_features = concatenate([x_encoded, omega_encoded, g])
    
    # 3. Forward pass through MLP
    # Network: 5 layers, 64 neurons, ReLU hidden, linear output
    log_radiance_pred = network.forward(input_features)
    
    # 4. Compute Ground Truth via KNN Query
    # For each sample, find K=1024 nearest photons with matching phase g
    # Compute radiance using adaptive radius r
    gt_radiance = torch.zeros(batch_size)
    for i in range(batch_size):
        photons = photon_kd_tree.query_knn(x[i], g[i], k=1024)
        if len(photons) == 0:
            gt_radiance[i] = 0.0
        else:
            r = distance(x[i], photons[-1].position) # Farthest photon
            # Sum phase function weighted intensities
            radiance_sum = 0.0
            for photon in photons:
                # Henyey-Greenstein phase function p_g
                pg = heney_greenstein_phase(g[i], omega[i], photon.direction)
                radiance_sum += pg * photon.intensity
            gt_radiance[i] = radiance_sum / (4 * math.pi * r**3)
            
    # 5. Encode Ground Truth
    gt_log_radiance = torch.zeros(batch_size)
    for i in range(batch_size):
        L = gt_radiance[i]
        threshold = 10**(-psi)
        if L > threshold:
            gt_log_radiance[i] = -log10(L) / psi
        else:
            gt_log_radiance[i] = 1.0 # Clamped
            
    # 6. Compute Loss
    # MSE between predicted log-radiance and encoded ground truth
    loss = mse_loss(log_radiance_pred, gt_log_radiance)
    
    # 7. Backpropagate and Update
    loss.backward()
    optimizer.step()
    optimizer.zero_grad()
    
    return loss
```

### Edge Cases and Pitfalls
*   **Precision Clamping:** Radiance values below $10^{-\psi}$ are clamped to 1 in the log domain. If $\psi$ is too low, dim details are lost; if too high, training instability may occur. Values of 4-6 are recommended [S1].
*   **KNN Radius:** The adaptive radius $r$ depends on the density of photons. In sparse regions, $r$ becomes large, potentially including irrelevant photons. A custom training schedule adjusts $r$ to limit query scope [S1].
*   **Phase Discretization:** Using a discrete set $G$ approximates continuous scattering. The choice of $G$ affects the trade-off between tracing speed and field quality [S1].

## Subtopics

### [Scene NeRF](12484-scene-nerf.md)
Isolates static background by training exclusively on background-masked pixels and using an emptiness regularizer to prevent artifacts in empty space. Chosen when dynamic foreground elements (e.g., humans) must be excluded from the static scene representation [12484-scene-nerf.md].

### [NeRF-OSR](14477-nerf-osr.md)
Decomposes the scene into spatial occupancy, illumination, shadowing, and diffuse albedo for outdoor scene relighting. Chosen when physical lighting editing and intrinsic decomposition are required, unlike standard NeRF which only captures view-dependent appearance under fixed lighting [14477-nerf-osr.md].

### SLAIM
A SLAM method using a coarse-to-fine tracking pipeline and KL regularization over ray termination distribution to improve photometric bundle adjustment for NeRF mapping. Chosen for NeRF-based SLAM where high-frequency renderings hinder image alignment [S3].

### SNI-SLAM
A dense NeRF-based RGB-D SLAM system with hierarchical semantic encoding and cross-attention. Chosen for real-time 3D semantic mapping requiring mutual reinforcement between appearance, geometry, and semantics [S3].

### KN-SLAM
Integrates local feature correspondences for coarse pose initialization and joint optimization in NeRF-based SLAM. Chosen for scenarios requiring explicit loop detection and pose graph optimization for global consistency [S3].

## Operating characteristics
*   **Time Complexity:** Training time is significantly reduced in variants like INGP due to hashgrid encoding, but remains higher than explicit methods like 3D Gaussian Splatting. Rendering time is generally slower than real-time for standard NeRF (seconds per image) compared to Gaussian Splatting (>100 FPS) [S2, unofficial].
*   **Memory Complexity:** Stores scene implicitly in network weights. Memory usage is low (a few megabytes) compared to explicit representations which require hundreds of megabytes for millions of primitives [S2, unofficial].
*   **Strengths:** High visual fidelity, smooth interpolation, compact storage, and ability to model complex lighting (in Photon Fields) or semantics (in semantic variants) [S1][S2, unofficial][S3].
*   **Limitations:** Slow rendering speeds for standard implementations, potential for floating artifacts in sparse regions (if not using explicit variants), and difficulty in extracting clean meshes directly [S2, unofficial].
*   **When to use:** When high-quality novel view synthesis is prioritized over real-time rendering speed, or when memory constraints are tight.
*   **When not to use:** When real-time interactive rendering is required (use 3D Gaussian Splatting) or when explicit mesh extraction is a primary goal without post-processing.

## Background
Neural Radiance Fields were introduced by Mildenhall et al. in 2020, establishing the paradigm of learning continuous volumetric representations from unstructured images [S1][S2, unofficial]. The concept was extended to Instant Neural Graphics Primitives (INGP) to accelerate training and rendering using hash-based encodings [S1]. Photon Field Networks were later introduced to handle dynamic global illumination in volumetric media by mapping phase coefficients to indirect radiance [S1]. The representation is widely used in virtual reality, film, robotics, and cultural heritage preservation [S2, unofficial].
