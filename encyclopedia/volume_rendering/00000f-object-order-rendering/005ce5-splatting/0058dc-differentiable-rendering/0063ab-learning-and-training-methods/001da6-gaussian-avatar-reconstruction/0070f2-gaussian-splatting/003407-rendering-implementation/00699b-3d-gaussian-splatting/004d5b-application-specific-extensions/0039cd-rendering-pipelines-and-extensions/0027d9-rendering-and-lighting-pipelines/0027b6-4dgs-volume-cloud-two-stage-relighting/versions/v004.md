# 4DGS-Volume-Cloud Two-Stage Relighting

Also called: Frozen Geometry + Environment Network, Stage 1 + Stage 2

## Overview
This method implements a two-stage rendering pipeline for physically parameterized volume clouds using 3D Gaussians, enabling real-time dynamic relighting with arbitrary sun directions [S1, unofficial]. Unlike standard Gaussian Splatting which optimizes view-dependent SH coefficients for color, this approach separates the problem into Stage 1 (training physical medium parameters under a single sun direction) and Stage 2 (training a global environment network to add sky atmospheric scattering) [S1, unofficial]. It sets itself apart by freezing the geometry and physical parameters after Stage 1, allowing Stage 2 to learn only the environmental illumination transfer, thereby decoupling the static cloud structure from the dynamic lighting conditions [S1, unofficial].

## How it works

### Inputs and Outputs
**Inputs:**
*   A dataset of volume cloud images captured under pure sun illumination with a black background (UE SkyAtmosphere brightness factor = 0) [S1, unofficial].
*   Camera poses and sun directions for the training set [S1, unofficial].
*   An initial 3D Gaussian point cloud (typically generated from volume data or SfM) [S1, unofficial].

**Outputs:**
*   A rendered image with physically correct atmospheric scattering and sun transmittance for any given sun direction [S1, unofficial].
*   Saved artifacts: `env_net.pt` (network weights), `sky_transfer.npy` (visibility vectors), `env.json` (configuration), and the PLY file containing frozen Gaussian parameters [S1, unofficial].

### Data Structures

**3D Gaussian Attributes (Stage 1 Optimized, Stage 2 Frozen):**
Each Gaussian $i$ stores the following physical parameters instead of standard SH colors:
*   **Position:** $\mathbf{x}_i \in \mathbb{R}^3$
*   **Scale:** $\mathbf{s}_i \in \mathbb{R}^3$
*   **Rotation:** $\mathbf{q}_i \in \mathbb{R}^4$ (Quaternion)
*   **Extinction Coefficient:** $\sigma_{t,i}$ (Volume integral of extinction). Activated via `softplus`, clamped to 5 [S1, unofficial].
*   **Albedo:** $\omega_i \in \mathbb{R}^3$ (RGB). Activated via `sigmoid` [S1, unofficial].
*   **Anisotropy Factor:** $g_i$. Activated via $0.8 \cdot \tanh(\cdot)$ to ensure forward scattering [S1, unofficial].
*   **Multiple Scattering Weights:** $\mathbf{w}_i \in \mathbb{R}^6$ (Six octave weights for Frostbite/Wrenninge approximation). Activated via `softplus` [S1, unofficial].

**Environment Network (Stage 2 Optimized):**
*   A small global Multi-Layer Perceptron (MLP) that maps view direction to Spherical Harmonic (SH) coefficients for the sky irradiance field $E_{lm}$ [S1, unofficial].
*   SH Order: Default is order 2 (9 coefficients), configurable via `--env_sh_order` [S1, unofficial].

**Precomputed Visibility:**
*   $V_{lm}(\mathbf{x})$: Sky visibility SH transfer vectors. Colorless, purely geometric, computed once on the frozen point set [S1, unofficial].

### Numbered Steps

**Stage 1: Physical Parameter Training**
1.  **Initialize:** Load the initial 3D Gaussian point cloud. Set all physical parameters ($\sigma_t, \omega, g, \mathbf{w}$) to initial values.
2.  **Rasterization Setup:** Configure the differentiable rasterizer to use analytic optical thickness ($\tau$) computation. For each pixel, accumulate the line-integral optical thickness $\tau$ along the ray through the Gaussian [S1, unofficial].
3.  **Compute Transmittance:** Calculate the alpha value using Beer-Lambert law: $\alpha = 1 - \exp(-\tau)$ [S1, unofficial].
4.  **Compute Sun Term:**
    *   Determine the sun direction $\mathbf{v}_l$ from the dataset.
    *   Compute the self-shadowing transmittance $T_{light}$ for each Gaussian. This is done via a "light space rasterization pass" where a narrow FOV camera simulates the sun direction. The CUDA kernel `record_front_tau` records the front-facing cumulative $\tau$ weighted by $\alpha \cdot T$ for each Gaussian [S1, unofficial].
    *   Compute the sun-atmosphere transmittance $T_{sun}(\mathbf{v}_l)$ using the analytic expression:
        $$ T_{sun}(\mathbf{v}_l) = \exp(-m(\theta) \cdot \tau_{rgb}) $$
        where $m(\theta)$ is the Kasten-Young air mass based on sun elevation $\theta$, and $\tau_{rgb} = (\tau_R, \tau_G, \tau_B)$ are learnable zenith optical thicknesses [S1, unofficial].
    *   Compute the per-Gaussian radiance contribution:
        $$ L_i = \omega_i \cdot T_{sun}(\mathbf{v}_l) \cdot \left( \sum_{n=0}^{5} w_{i,n} \cdot T_{light,i}^{b^n} \right) \cdot P(\mathbf{v}_i, \mathbf{v}_o; g_i \cdot c^n) $$
        where $P$ is the Henyey-Greenstein phase function, $\mathbf{v}_i = -\mathbf{v}_l$ (incident direction), and $b$ is a base constant for the octave approximation [S1, unofficial].
5.  **Composite:** Render the image using front-to-back alpha blending with the computed $L_i$ and $\alpha_i$.
6.  **Optimize:** Minimize the difference between the rendered image and the ground truth (which uses a fixed Narkowicz ACES tonemap) using an optimizer. Update $\sigma_t, \omega, g, \mathbf{w}, \tau_{rgb}$ and Gaussian geometry [S1, unofficial].
7.  **Repeat:** Iterate until convergence.

**Stage 2: Environment Network Training**
1.  **Freeze Geometry:** Load the Stage 1 model. Freeze all Gaussian parameters ($\mathbf{x}, \mathbf{s}, \mathbf{q}, \sigma_t, \omega, g, \mathbf{w}$) [S1, unofficial].
2.  **Precompute Visibility:**
    *   For each Gaussian, compute the sky visibility transfer vectors $V_{lm}(\mathbf{x})$.
    *   Scan the hemisphere in $N$ directions using `compute_T_light_raster` to calculate geometric occlusion from the frozen point set [S1, unofficial].
    *   Fit SH coefficients to these visibility samples to obtain $V_{lm}(\mathbf{x})$ [S1, unofficial].
3.  **Initialize Environment Network:** Initialize the global MLP to predict sky irradiance SH coefficients $E_{lm}(\mathbf{v}_l)$ [S1, unofficial].
4.  **Render with Relighting:**
    *   For a given sun direction $\mathbf{v}_l$, compute the sun term $T_{sun}(\mathbf{v}_l)$ as in Stage 1 (using the learned $\tau_{rgb}$) [S1, unofficial].
    *   Compute the sky inscattering term:
        $$ L_{sky} = \omega \cdot \sum_{lm} E_{lm}(\mathbf{v}_l) \cdot V_{lm}(\mathbf{x}) $$
    *   Compute the final radiance:
        $$ L = T_{sun}(\mathbf{v}_l) \odot L_{stage1} + L_{sky} $$
        Note: $T_{sun}$ is multiplicative (attenuation), while $L_{sky}$ is additive (fill) [S1, unofficial].
    *   If the sun is below the horizon, apply a `smoothstep` gate to extinguish the direct sun term [S1, unofficial].
5.  **Optimize:** Train the environment network (MLP weights) using a learning rate of $1e-3$ with an independent optimizer, decaying to $0.1\times$ the initial value. Use the `env-on` dataset (same poses/suns, but UE SkyAtmosphere brightness factor = 0, meaning the background is black but the sky scattering is present) [S1, unofficial].
6.  **Save:** Save `env_net.pt`, `sky_transfer.npy`, and `env.json` alongside the PLY file [S1, unofficial].

### Pseudocode

```python
import torch
import numpy as np

def stage1_render(gaussians, sun_direction, camera):
    """
    Renders the cloud using only direct sun illumination and physical parameters.
    """
    # 1. Project Gaussians to screen space
    # Transform covariance: Sigma_c = J * W * Sigma * W^T * J^T
    # Extract 2D covariance Sigma_2D (upper-left 2x2)
    projected_gaussians = project_gaussians(gaussians, camera)
    
    # 2. Rasterize to compute optical thickness tau
    # Use analytic tau branch in rasterizer
    # tau is the line-integral optical thickness per pixel
    tau = rasterize_analytic_tau(projected_gaussians, camera)
    
    # 3. Compute Alpha
    alpha = 1.0 - torch.exp(-tau)
    
    # 4. Compute Sun Transmittance T_sun
    # m(theta) is Kasten-Young air mass based on sun elevation theta
    # tau_rgb are learnable zenith optical thicknesses
    m_theta = kasten_young_air_mass(sun_direction.elevation)
    T_sun = torch.exp(-m_theta * gaussians.tau_rgb)
    
    # 5. Compute Self-Shadowing T_light
    # This requires a separate light-space rasterization pass
    # Returns T_light per Gaussian (or per pixel if accumulated)
    T_light = compute_light_space_transmittance(gaussians, sun_direction)
    
    # 6. Compute Phase Function P
    # v_i = -sun_direction (incident light direction)
    # v_o is the view direction from pixel to Gaussian
    cos_theta = compute_cosine_phase_angle(gaussians, sun_direction, camera)
    P = heney_greenstein_phase_function(cos_theta, gaussians.g)
    
    # 7. Compute Multiple Scattering Octaves
    # w_n are the 6 octave weights
    # b is a base constant (e.g., 2 or similar for octave approximation)
    scattering_sum = 0.0
    for n in range(6):
        scattering_sum += gaussians.w[n] * (T_light ** (2**n))
        
    # 8. Compute Per-Gaussian Radiance Contribution
    # L_i = omega * T_sun * scattering_sum * P
    # Note: T_sun is applied globally or per-pixel depending on implementation
    # Here we assume T_sun is a scalar multiplier for the sun term
    L_sun_term = gaussians.albedo * T_sun * scattering_sum * P
    
    # 9. Composite
    # Front-to-back blending
    final_color = composite_front_to_back(L_sun_term, alpha, projected_gaussians)
    
    return final_color

def stage2_render(gaussians, env_net, sky_transfer, sun_direction, camera):
    """
    Renders the cloud with frozen geometry and learned environment network.
    """
    # 1. Get Stage 1 Sun Term (Multiplicative)
    # Re-use Stage 1 logic but with frozen parameters
    L_stage1 = stage1_render(gaussians, sun_direction, camera)
    
    # 2. Compute Sky Irradiance E_lm from Environment Network
    # env_net is a global MLP taking view direction
    # Returns SH coefficients E_lm for the sky
    view_directions = get_view_directions(camera)
    E_lm = env_net(view_directions)
    
    # 3. Compute Sky Inscattering (Additive)
    # L_sky = omega * sum(E_lm * V_lm)
    # V_lm is the precomputed sky visibility transfer vector for each Gaussian
    # This term provides fill light from the sky
    
    # Retrieve V_lm for the relevant Gaussians
    V_lm = sky_transfer[gaussians.indices]
    
    # Dot product of SH coefficients and visibility
    # Sum over lm indices
    sky_irradiance = dot_sh(E_lm, V_lm)
    
    L_sky = gaussians.albedo * sky_irradiance
    
    # 4. Combine Terms
    # T_sun is multiplicative (attenuation)
    # L_sky is additive (fill)
    
    # Handle sun below horizon
    if sun_direction.elevation < 0:
        T_sun_gate = smoothstep(0.0, 0.1, sun_direction.elevation) # Example smoothstep
    else:
        T_sun_gate = 1.0
        
    T_sun = torch.exp(-kasten_young_air_mass(sun_direction.elevation) * gaussians.tau_rgb)
    T_sun_final = T_sun * T_sun_gate
    
    # Final Radiance
    L_final = T_sun_final * L_stage1 + L_sky
    
    return L_final
```

### Parameters
*   **Learning Rate (Stage 2):** $1e-3$ for the environment network, decaying to $0.1\times$ [S1, unofficial].
*   **SH Order:** 2 (9 coefficients) by default, configurable via `--env_sh_order` [S1, unofficial].
*   **Tonemap:** Fixed Narkowicz ACES curve by default. Can be disabled with `--no-tonemap_aces` if GT is linear HDR [S1, unofficial].
*   **T_light Computation:** Default is rasterization (`use_analytic_tau`). Voxel-based path available via `--tlight_voxel` [S1, unofficial].

### Edge Cases and Pitfalls
*   **Sun Below Horizon:** The direct sun term must be extinguished when the sun is below the horizon to avoid incorrect lighting. A `smoothstep` gate is used [S1, unofficial].
*   **Multiplicative vs Additive:** The sun term $T_{sun}$ must be multiplicative because a purely additive term cannot express the darkening (attenuation) caused by atmospheric path length [S1, unofficial].
*   **Data Bias:** The dataset must have uniform directional coverage. Biased directions (e.g., missing vertical sun angles) can cause the geometry to escape supervision [S1, unofficial].
*   **Tonemap Mismatch:** If the ground truth is linear HDR, the ACES tonemap must be disabled. Using learnable tonemap coefficients is an insurance policy for different filmic engines but should not be used if the GT is truly linear [S1, unofficial].

## Operating characteristics

*   **Time Complexity:** Stage 1 training is comparable to standard 3DGS but with additional light-space rasterization passes for $T_{light}$. Stage 2 training is faster as geometry is frozen and only a small MLP is trained. Rendering is real-time, dominated by the rasterization pass and the evaluation of the environment network [S1, unofficial].
*   **Memory Complexity:** Stores physical parameters per Gaussian ($\sigma_t, \omega, g, \mathbf{w}$) instead of SH colors. Requires additional storage for precomputed visibility vectors $V_{lm}$ and the environment network weights [S1, unofficial].
*   **Strengths:** Enables arbitrary sun direction relighting without retraining the geometry. Physically plausible atmospheric scattering. Real-time performance [S1, unofficial].
*   **Limitations:** Assumes static geometry (time dimension not implemented in the initial release). Requires a specific dataset with black background and pure sun illumination for Stage 1 [S1, unofficial].
*   **When to Use:** When dynamic relighting of volume clouds is required, and the cloud geometry is static or can be approximated as such.
*   **When Not to Use:** When the cloud geometry is highly dynamic and cannot be captured by a static Gaussian set, or when real-time performance is not a constraint and ray-marching is acceptable [S1, unofficial].

## Background

This method is based on 3D Gaussian Splatting (Kerbl et al., 2023) and the 3DGS-Volume-Cloud project [S1, unofficial]. It was developed to replace ray-marching volume clouds in game engines with a real-time, physically parameterized Gaussian representation [S1, unofficial]. The initial code baseline is commit `69fea2c8d5a13d6c0e41ac12ca45c80b71bd3403` [S1, unofficial]. It is used in the 4DGS-Volume-Cloud project for rendering clouds from the WDAS Cloud dataset [S1, unofficial].
