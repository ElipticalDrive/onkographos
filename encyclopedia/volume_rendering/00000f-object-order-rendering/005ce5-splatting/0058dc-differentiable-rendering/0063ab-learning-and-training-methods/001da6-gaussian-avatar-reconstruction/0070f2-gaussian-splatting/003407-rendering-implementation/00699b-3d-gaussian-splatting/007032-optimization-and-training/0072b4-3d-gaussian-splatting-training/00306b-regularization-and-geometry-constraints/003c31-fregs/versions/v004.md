# FreGS

Also called: Frequency-aware regularization for 3DGS, Progressive frequency regularization

## Overview
FreGS is a regularization method for 3D Gaussian Splatting that prevents overfitting and high-frequency artifacts by penalizing frequency discrepancies between rendered and ground-truth images [S1, unofficial][S2]. It addresses the problem of over-reconstruction, where the model captures noise or excessive detail that degrades generalization, by operating directly in the frequency domain [S2]. Unlike sibling methods that focus on spatial gradient magnitudes or geometric priors, FreGS explicitly aligns the spectral content of the output with the input [S1, unofficial][S2].

## How it works
FreGS augments the standard photometric loss with a frequency-domain regularization term. The method applies this regularization progressively during training to stabilize the optimization of Gaussian primitives [S1, unofficial].

**Inputs and Outputs:**
- **Input:** Rendered image $I_{render}$, Ground-truth image $I_{gt}$, current training step $t$, total training steps $T$.
- **Output:** Regularization loss $\mathcal{L}_{freq}$.

**Data Structures:**
- Images are treated as 2D arrays of pixel values.
- Frequency domain representation uses the 2D Discrete Fourier Transform (DFT).

**Parameters:**
- $\lambda_{freq}$: Weight for the frequency regularization term. Typical values are not explicitly given in the sources, but standard photometric weights (e.g., 0.2 for SSIM) are used in baseline 3DGS [S1, unofficial][S2].
- Progressive schedule: The regularization is applied "progressively," implying a schedule that increases or activates the term as training proceeds. Exact schedule parameters are not given in the sources.

**Steps:**
1. Compute the 2D DFT of the rendered image: $F_{render} = \text{DFT}(I_{render})$.
2. Compute the 2D DFT of the ground-truth image: $F_{gt} = \text{DFT}(I_{gt})$.
3. Calculate the frequency discrepancy. The sources do not specify the exact metric (e.g., L1, L2, or SSIM in frequency domain). [G] A common approach is the L1 or L2 norm of the difference between the magnitude spectra or complex coefficients. Let $D = |F_{render} - F_{gt}|$.
4. Apply a progressive weight $w(t)$ based on the current step $t$. [G] A linear or cosine annealing schedule is typical for progressive regularization.
5. Compute the loss: $\mathcal{L}_{freq} = w(t) \cdot \text{Metric}(D)$.
6. Add to total loss: $\mathcal{L}_{total} = \mathcal{L}_{photo} + \lambda_{freq} \mathcal{L}_{freq}$.

**Pseudocode:**
```python
def compute_freq_regularization(rendered_img, gt_img, step, total_steps, lambda_freq):
    # Compute 2D DFT
    F_render = dft_2d(rendered_img)
    F_gt = dft_2d(gt_img)
    
    # Compute frequency discrepancy (magnitude difference)
    # Note: Exact metric not specified in sources; using L1 of magnitude difference as [G]
    diff = abs(F_render) - abs(F_gt)
    freq_loss = sum(abs(diff)) / diff.size
    
    # Progressive weighting
    # Note: Exact schedule not specified; using linear ramp as [G]
    progress = step / total_steps
    weight = progress 
    
    return lambda_freq * weight * freq_loss
```

**Edge Cases and Pitfalls:**
- **Boundary Effects:** DFT assumes periodic signals, which may introduce artifacts at image boundaries. [G] Windowing functions (e.g., Hanning) may be applied before DFT.
- **Computational Cost:** DFT is $O(N^2 \log N)$, which can be expensive for high-resolution images. [G] FFT is typically used.
- **Degenerate Input:** If images are identical, loss is zero, providing no gradient.

## Operating characteristics
- **Time Complexity:** Adds $O(N^2 \log N)$ per iteration for DFT/FFT.
- **Memory Complexity:** Requires storing frequency domain representations, doubling memory for image buffers.
- **Strengths:** Reduces high-frequency noise and overfitting artifacts.
- **Limitations:** May smooth out fine details if $\lambda_{freq}$ is too high. Computational overhead.
- **When to use:** When training exhibits high-frequency noise or over-reconstruction.
- **When not to use:** When computational resources are limited or fine detail preservation is critical without careful tuning.

## Background
FreGS was introduced to address over-reconstruction in 3D Gaussian Splatting by regularizing frequency discrepancies [S2]. It is cited in surveys on 3DGS rasterization and compression [S1, unofficial][S2]. The method is part of the broader effort to improve the stability and quality of differentiable rendering training.
