# Geometry Regularization

Also called: Gaussian Flattening, Normal Consistency and Flattening

## Overview
Geometry Regularization is a training-time constraint technique for 3D Gaussian Splatting that improves geometric fidelity and surface smoothness by explicitly constraining the shape and orientation of Gaussian primitives [S1, unofficial]. Unlike depth supervision, which primarily constrains the location of Gaussians, this method enforces planarity and normal alignment to reduce artifacts such as "floaters" (spurious, low-opacity Gaussians in empty space) and ensure coherent surface representations [S1, S2, unofficial]. It distinguishes itself from frequency-domain methods by operating directly on the spatial covariance structure of the Gaussians rather than comparing image spectra [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** The current state of the 3D Gaussian scene (centers, covariances, opacities, colors) and rendered depth maps from training views.
*   **Output:** A modified loss function term that penalizes deviations from planar surface assumptions and normal consistency.

**Data Structures:**
*   **Gaussian Scaling Factor ($s$):** A vector $s \in \mathbb{R}^3$ representing the scale along the three principal axes of each Gaussian.
*   **Gaussian Normal ($n_g$):** The normal vector associated with each Gaussian, typically derived from the eigenvector corresponding to the smallest eigenvalue of the covariance matrix (the axis of least extent).
*   **Rendered Depth Normal ($n_d$):** The surface normal estimated from the rendered depth buffer of a training view.

**Parameters:**
*   **`use_normal_loss`:** A boolean flag (default `false`) that enables the geometry regularization module [S1, unofficial].
*   **Weighting Coefficients:** Not explicitly defined in the provided sources; typically tuned hyperparameters balancing the regularization term against the photometric loss [G].

**Steps:**
1.  **Enable Regularization:** If `use_normal_loss` is true, compute the geometry regularization loss terms for each Gaussian during the training step.
2.  **Flattening Constraint:** For each Gaussian, identify the smallest component of its scaling factor vector $s$. Minimize this value towards zero to encourage the Gaussian to flatten into a surfel (surface element) aligned with the local geometry [S2, unofficial].
3.  **Normal Consistency:**
    *   Compute the per-Gaussian normal $n_g$ based on the Gaussian's orientation (specifically the axis corresponding to the smallest scale) [S1, S2, unofficial].
    *   Render a depth map from the current camera view and compute the surface normal $n_d$ at the projected pixel location.
    *   Enforce alignment between $n_g$ and $n_d$ [S1, unofficial].

**Formulas:**
Let $s_i \in \mathbb{R}^3$ be the scaling factors for the $i$-th Gaussian. The flattening loss $L_{flat}$ for a single Gaussian is proportional to the smallest component of $s_i$:
$$ L_{flat} \propto \min(s_{i,1}, s_{i,2}, s_{i,3}) $$
The goal is to minimize this term, driving the smallest scale towards zero [S2, unofficial].

Let $n_{g,i}$ be the normal of the $i$-th Gaussian and $n_{d,j}$ be the normal derived from the rendered depth at pixel $j$. The normal consistency loss $L_{normal}$ encourages the dot product to be close to 1:
$$ L_{normal} \propto 1 - (n_{g,i} \cdot n_{d,j}) $$
This ensures the Gaussian's orientation aligns with the local surface geometry inferred from depth [S1, unofficial].

def compute_geometry_regularization_loss(gaussians, rendered_depth, camera_params, use_normal_loss):
    """
    Computes geometry regularization losses for 3D Gaussian Splatting.
    
    Args:
        gaussians: Object containing per-Gaussian properties:
            - scales: Tensor of shape (N, 3), scaling factors s for each Gaussian.
            - rotations: Tensor of shape (N, 4), quaternions for orientation.
        rendered_depth: Tensor of shape (H, W), depth values for the current view.
        camera_params: Object containing camera pose and intrinsics.
        use_normal_loss: Boolean, whether to enable normal consistency and flattening.
        
    Returns:
        float: Total geometry regularization loss.
    """
    if not use_normal_loss:
        return 0.0

    loss = 0.0
    N = gaussians.scales.shape[0]
    
    # 1. Flattening Loss: Minimize the smallest scaling component
    # Identify the minimum scale along any axis for each Gaussian
    min_scales = torch.min(gaussians.scales, dim=1).values # Shape (N,)
    
    # Sum of minimum scales encourages flattening towards zero
    # Note: Sources do not specify if this is summed or averaged; sum is standard for loss terms.
    loss += torch.sum(min_scales)
    
    # 2. Normal Consistency Loss
    # Compute per-Gaussian normals from rotations
    # The normal is typically the direction of the smallest scale axis.
    # Assuming standard basis alignment before rotation, the axis with min scale
    # is identified, then rotated.
    # For simplicity, we assume the normal is derived from the covariance eigenvector
    # corresponding to the smallest eigenvalue.
    
    # Get the axis indices of the minimum scales
    min_scale_indices = torch.argmin(gaussians.scales, dim=1) # Shape (N,)
    
    # Define basis vectors for the three axes
    basis = torch.tensor([[1, 0, 0], [0, 1, 0], [0, 0, 1]], device=gaussians.scales.device)
    
    # Select the basis vector corresponding to the smallest scale for each Gaussian
    local_normals = basis[min_scale_indices] # Shape (N, 3)
    
    # Rotate local normals to world space using quaternions
    world_normals = rotate_vectors(gaussians.rotations, local_normals) # Shape (N, 3)
    
    # Project Gaussians to 2D to find corresponding depth pixels
    # This requires a rasterization step or projection logic.
    # For each Gaussian, find the pixel (u, v) it projects to.
    # If a Gaussian projects to multiple pixels or none, handle accordingly.
    # Here we assume a simplified mapping where we sample the rendered depth normal
    # at the projected center of each Gaussian.
    
    projected_centers = project_to_screen(gaussians.centers, camera_params) # Shape (N, 2)
    
    # Sample rendered depth normals at projected centers
    # Note: rendered_depth_normals must be pre-computed from rendered_depth

    sampled_normals = sample_depth_normals(projected_centers, rendered_depth_normals) # Shape (N, 3)
    
    # Compute dot product between world normal and sampled depth normal
    dot_products = torch.sum(world_normals * sampled_normals, dim=1) # Shape (N,)
    
    # Loss encourages dot product to be 1 (aligned)
    # 1 - dot_product is 0 when aligned, positive when misaligned
    normal_loss_term = torch.sum(1.0 - dot_products)
    loss += normal_loss_term
    
    return loss

**Edge Cases and Pitfalls:**
*   **Depth Refitting:** Depth maps from different frames may vary in scale. They must be refitted against a prior point cloud to a consistent scale before being used for supervision. Depth maps that fail this refitting process should be discarded [S1, unofficial].
*   **Precision:** Minimizing the smallest scale component towards zero can lead to numerical instability if the scale becomes extremely small. A lower bound or epsilon might be required in implementation [G].
*   **Ambiguity in Normal Direction:** The normal derived from the smallest scale axis has an inherent sign ambiguity (inward vs. outward). Consistency with the camera view direction or surrounding geometry is required to resolve this [G].

## Subtopics

### Scaling Loss for Geometry Modeling
A specific variant of geometry regularization that focuses exclusively on the shape of the Gaussian kernels. It minimizes the smallest component of the scaling factor $s \in \mathbb{R}^3$ towards zero, effectively flattening the Gaussian into a 3D "surflet" aligned with the surface [S2, unofficial]. This approach aids in determining Gaussian normals by explicitly selecting the shortest scaled edge as the surface normal direction. It is particularly useful for disentangling sky/distant background from foreground geometry by encouraging planar structures [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Adds a linear pass over the number of Gaussians $N$ for computing scales and normals, plus the cost of sampling depth normals. The overhead is generally low compared to the rasterization step [S1, S2, unofficial].
*   **Memory Complexity:** Requires storing per-Gaussian normals and potentially pre-computed depth normal maps. No significant additional memory structures are required beyond standard training buffers [S1, S2, unofficial].
*   **Performance:** Improves geometric fidelity and reduces "floaters" (spurious Gaussians) [S1, unofficial]. It can lead to a trade-off where the number of remaining points is reduced, potentially compromising detail if not balanced with other regularization terms like entropy loss for opacity [S2, unofficial].
*   **Strengths:** Directly enforces surface-like properties, improving smoothness and reducing artifacts in complex scenes [S1, unofficial].
*   **Limitations:** Requires accurate depth maps for normal consistency. If depth is noisy or missing, the normal consistency term may introduce errors. The flattening assumption may not hold for volumetric or non-planar objects [S1, S2, unofficial].
*   **When to Use:** When high geometric fidelity and smooth surfaces are required, and depth supervision is available. Particularly effective for scenes with distinct planar structures [S1, S2, unofficial].
*   **When Not to Use:** For highly volumetric or non-planar scenes where the flattening assumption is invalid. If depth maps are unreliable or unavailable [S1, unofficial].

## Background
Geometry Regularization in the context of 3D Gaussian Splatting was introduced as an extension to the standard optimization pipeline to address the lack of explicit geometric constraints in the original method. It builds upon the observation that unconstrained optimization of Gaussian primitives can lead to artifacts such as floaters and poor surface reconstruction [S1, S2, unofficial]. The technique leverages the relationship between the Gaussian's covariance structure (specifically its scaling factors) and the local surface geometry, drawing inspiration from surfel-based rendering methods [S2, unofficial]. It is implemented in various frameworks, including GaussianSplatting.jl, where it is exposed via configuration parameters like `use_normal_loss` [S1, unofficial].
