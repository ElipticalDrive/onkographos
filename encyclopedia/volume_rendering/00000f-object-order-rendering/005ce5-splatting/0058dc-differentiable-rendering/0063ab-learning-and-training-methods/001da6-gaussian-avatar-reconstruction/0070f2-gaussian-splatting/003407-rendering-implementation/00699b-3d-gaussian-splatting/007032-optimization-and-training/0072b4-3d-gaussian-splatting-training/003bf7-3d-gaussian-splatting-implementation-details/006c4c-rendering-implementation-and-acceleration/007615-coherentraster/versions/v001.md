# CoherentRaster

Also called: CoherentRaster: Efficient 3D Gaussian Splatting for Light Field Displays

## Overview
CoherentRaster is a real-time 3D Gaussian Splatting (3DGS) rendering framework optimized for Light Field Displays (LFDs) that utilizes subpixel-level rasterization to generate high-resolution multi-view images [S1]. It distinguishes itself from standard 3DGS and Subpixel-3DGS by eliminating redundant computations across adjacent views and resolving uncoalesced memory access patterns inherent to subpixel rasterization, thereby achieving real-time performance at resolutions where other methods fail [S1].

## How it works
CoherentRaster operates by clustering viewpoints and applying two core optimizations: Cross-view Coherent Attribute Reuse and View-coherent Remapping [S1].

**Inputs and Outputs:**
*   **Inputs:** A set of 3D Gaussians (position, covariance, opacity, spherical harmonics coefficients), a cluster of $|V|$ viewpoints (cameras), and the target subpixel grid resolution for the LFD.
*   **Outputs:** A stack of rendered images (one per viewpoint in the cluster) at the specified subpixel resolution.

**Data Structures:**
The method relies on the standard 3DGS Gaussian representation but introduces a clustering structure for viewpoints.
*   **Gaussian Attributes:** Standard 3DGS attributes (mean $\mu$, covariance $\Sigma$, opacity $\alpha$, spherical harmonics $c$).
*   **View Cluster:** A group of $|V|$ camera poses processed together. The source specifies $|V|=8$ as the optimal cluster size [S1].
*   **Subpixel Grid:** The output image is treated as a grid of subpixels corresponding to the micro-lens array or pixel pitch of the LFD.

**Algorithm Steps:**

1.  **View Clustering:** Group the target viewpoints into clusters of size $|V|$. The source indicates $|V|=8$ provides the best trade-off between efficiency and quality [S1].
2.  **Cross-view Coherent Attribute Reuse:**
    *   Identify Gaussians that contribute to the view frustum of the cluster.
    *   For adjacent views within the cluster, reuse computed attributes (such as projected centers, covariances, and visibility masks) from previously processed views in the same cluster, leveraging the local consistency of the camera motion [S1].
    *   This step eliminates redundant computation for Gaussians that are visible across multiple adjacent viewpoints [S1].
3.  **View-coherent Remapping:**
    *   Map the subpixel-level rasterization targets to a memory layout that ensures coalesced memory access patterns on the GPU [S1].
    *   Standard subpixel rasterization often leads to uncoalesced access because subpixels from different views may be scattered in memory. This remapping reorganizes the write targets so that threads in a warp access contiguous memory locations [S1].
4.  **Subpixel Rasterization:**
    *   Project the 3D Gaussians onto the subpixel grid for each view in the cluster.
    *   Accumulate color and opacity values into the subpixel buffers.
    *   The source notes that this step is more efficient than the per-pixel traversal of depth plane stacks used in MPI-based frameworks [S1].

**Parameters:**
*   **Cluster Size ($|V|$):** The number of viewpoints processed per batch. $|V|=8$ is recommended [S1]. Increasing $|V|$ improves speed but may reduce fidelity due to the assumption of local consistency [S1].

**Edge Cases and Pitfalls:**
*   **High-Frequency Specular Effects:** The Cross-view Coherent Attribute Reuse strategy relies on local consistency. Scenes with high-frequency specular highlights may exhibit visual artifacts because attributes reused from adjacent views may not accurately represent the specular variation [S1].
*   **Dynamic Scenes:** The current framework is restricted to static scenes. It does not support dynamic content [S1].
*   **Discretization Artifacts:** Unlike MPI-based methods, CoherentRaster avoids discretization artifacts caused by limited depth planes, but the subpixel approach requires careful handling of the micro-lens geometry [S1].

**Pseudocode:**

```python
def coherent_rasterize(gaussians, view_cluster, subpixel_resolution):
    """
    Render a cluster of views using CoherentRaster.
    
    Args:
        gaussians: List of 3D Gaussian objects.
        view_cluster: List of camera matrices and intrinsics for |V| views.
        subpixel_resolution: Tuple (width, height) for the subpixel grid.
        
    Returns:
        List of rendered images for each view in the cluster.
    """
    num_views = len(view_cluster)
    # Initialize output buffers for all views in the cluster
    # Shape: (num_views, height, width, channels)
    # Using a layout that supports coalesced access after remapping
    output_buffers = initialize_buffers(num_views, subpixel_resolution)
    
    # Pre-compute view-dependent attributes for the cluster
    # This leverages Cross-view Coherent Attribute Reuse
    reused_attributes = {}
    
    for i, view in enumerate(view_cluster):
        # 1. Project Gaussians for current view
        # Get Gaussians visible in this view's frustum
        visible_gaussians = filter_visible(gaussians, view)
        
        # 2. Reuse attributes from adjacent views if available
        # Check if we can reuse projection data from view i-1 or i+1
        # This step reduces redundant matrix multiplications and sorting
        if i > 0:
            reused_attributes = reuse_from_view(reused_attributes, view_cluster[i-1], view)
        
        # 3. Compute subpixel centers and covariances
        # Project 3D mean to subpixel space
        subpixel_centers = project_to_subpixel(visible_gaussians, view, subpixel_resolution)
        
        # 4. View-coherent Remapping
        # Remap the subpixel write targets to ensure coalesced memory access
        # This involves reordering the Gaussian list or the output buffer indices
        remapped_gaussians = remap_for_coalescing(subpixel_centers, visible_gaussians, view)
        
        # 5. Rasterize
        # Accumulate contributions into the output buffers
        # The remapping ensures that threads writing to adjacent subpixels
        # in the same view access contiguous memory
        rasterize_subpixels(remapped_gaussians, view, output_buffers[i])
        
        # Store attributes for potential reuse in next view
        reused_attributes = update_reused_attributes(visible_gaussians, view)

    return output_buffers
```

## Operating characteristics
*   **Performance:** CoherentRaster achieves real-time rendering speeds significantly higher than standard 3DGS and Subpixel-3DGS. On the Synthetic Blender dataset, it achieves 88 FPS at 2K and 56 FPS at 4K resolution. On the Mip-NeRF 360 dataset, it achieves 30 FPS at 2K and 16 FPS at 4K [S1].
*   **Comparison to Baselines:**
    *   **vs. Subpixel-3DGS:** CoherentRaster is faster because it avoids redundant computations across adjacent views and uncoalesced memory access patterns [S1].
    *   **vs. MPI-based frameworks:** CoherentRaster avoids the latency of per-pixel traversal of depth plane stacks and the discretization artifacts associated with limited depth planes [S1].
*   **Scaling:** Rendering speed improves as the cluster size $|V|$ increases, but fidelity may decrease if the cluster becomes too large to maintain local consistency [S1].
*   **Strengths:** Real-time performance at high resolutions (beyond 2K) for light field displays; high fidelity compared to MPI methods; efficient memory access.
*   **Limitations:** Restricted to static scenes; potential artifacts in scenes with high-frequency specular effects due to attribute reuse [S1].

## Background
CoherentRaster was introduced in the paper "CoherentRaster: Efficient 3D Gaussian Splatting for Light Field Displays" [S1]. It addresses the computational bottleneck of rendering 3D Gaussian Splatting for Light Field Displays, which require generating many high-resolution views simultaneously. Previous methods like Subpixel-3DGS and MPI-based frameworks were either too slow or suffered from quality issues [S1].
