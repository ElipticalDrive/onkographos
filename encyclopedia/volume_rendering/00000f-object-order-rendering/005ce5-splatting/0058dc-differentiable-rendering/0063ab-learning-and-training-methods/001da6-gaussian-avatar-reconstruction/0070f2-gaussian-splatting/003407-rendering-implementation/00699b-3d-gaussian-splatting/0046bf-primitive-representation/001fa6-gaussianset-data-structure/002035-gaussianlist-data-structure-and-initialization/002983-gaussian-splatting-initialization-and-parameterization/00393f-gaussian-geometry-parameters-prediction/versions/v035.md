# Gaussian Geometry Parameters Prediction

Also called: 3D Gaussian Splatting (3DGS), EVolSplat, Efficient Volume-based Gaussian Splatting, GRM, Gaussian MLP Heads, Gaussian Representation Model

## Overview
Gaussian Geometry Parameters Prediction refers to methods that infer the spatial attributes (position, scale, rotation, opacity) of 3D Gaussian primitives from input data, rather than optimizing them via iterative per-scene gradient descent. It solves the problem of slow, optimization-dependent reconstruction by enabling feed-forward or direct prediction of Gaussian sets [S1, S3]. It sets itself apart from standard 3DGS by replacing the per-scene optimization loop with a learned mapping (e.g., via neural networks or analytical filters) that generates a global, consistent scene representation in a single pass or few iterations [S3].

## How it works
The method varies by implementation (e.g., EVolSplat, Gamba, GaMeS), but the core logic involves predicting geometry from a feature volume or direct input. Below is the canonical pipeline for volume-based prediction (EVolSplat) [S3], followed by specific variants.

### Inputs and Outputs
*   **Inputs:** A set of $N$ posed RGB images $\{I_n\}_{n=1}^N$, their intrinsic matrices $\{K_n\}$, extrinsic matrices $\{T_n\}$, and optionally monocular depth estimates $\{D_n\}$ [S3].
*   **Outputs:** A set of $N_p$ 3D Gaussians $\mathcal{G} = \{(\mu_i, \alpha_i, \Sigma_i, c_i)\}_{i=1}^{N_p}$, where $\mu_i$ is the mean, $\alpha_i$ is opacity, $\Sigma_i$ is the covariance, and $c_i$ is the color [S3].

### Data Structures
1.  **Global Point Cloud ($P$):** A sparse set of 3D points in world coordinates, derived from unprojected depth maps. Layout: $N_p \times 3$ float32 array [S3].
2.  **Feature Volume ($F$):** A sparse 3D tensor extracted by a 3D CNN from $P$. Layout: $H \times W \times D \times C$ (spatial resolution $\times$ feature dimension) [S3].
3.  **Gaussian Attributes:**
    *   $\mu \in \mathbb{R}^3$: Position.
    *   $\alpha \in \mathbb{R}$: Opacity.
    *   $\Sigma \in \mathbb{R}^{3 \times 3}$: Covariance (symmetric positive definite).
    *   $c \in \mathbb{R}^L$: Color (Spherical Harmonics coefficients) [S2, unofficial][S3].

### Numbered Steps (Volume-Based Prediction, e.g., EVolSplat)
1.  **Depth Estimation:** Use an off-the-shelf metric depth estimator to predict depth maps $\{D_n\}$ for each input image $\{I_n\}$ [S3].
2.  **Global Point Cloud Construction:** Unproject the RGB images and depth maps into 3D space using $K_n$ and $T_n$ to form a global point cloud $P = \bigcup^N \pi^{-1}(I_n, D_n, T_n, K_n)$ [S3].
3.  **Filtering:**
    *   Apply a **uniform filter** to $P$ to remove duplicate primitives in overlapping regions [S3].
    *   Apply a **statistical filter** to remove floating artifacts/noise from the remaining points [S3].
4.  **Feature Volume Extraction:** Feed the filtered point cloud $P$ into a sparse 3D CNN (e.g., Sparse U-Net) to extract a latent feature volume $F$ [S3].
5.  **Initialization:** Initialize Gaussian centers $\mu^{init}_i$ using the points in $P$ (i.e., $\mu^{init}_i = p_i \in P$) [S3].
6.  **Geometry Prediction (Recursive Update):**
    *   For each Gaussian $i$, query the feature volume $F$ at the current position $\mu^{init}_i + \Delta \mu^{prev}_i$ using trilinear interpolation to get feature vector $f_i$ [S3]:
        $$ f_i = F(\mu^{init}_i + \Delta \mu^{prev}_i) $$
    *   Predict opacity $\alpha_i$ and covariance $\Sigma_i$ using independent MLP heads $\mathcal{D}_{opa}$ and $\mathcal{D}_{cov}$ [S3]:
        $$ \alpha_i = \mathcal{D}_{opa}(f_i), \quad \Sigma_i = \mathcal{D}_{cov}(f_i) $$
    *   Predict position offset $\Delta \mu_i$ using MLP head $\mathcal{D}_{pos}$, scaled by voxel size $v_{size}$ and passed through Tanh [S3]:
        $$ \Delta \mu_i = \text{Tanh}(\mathcal{D}_{pos}(f_i)) \cdot v_{size} $$
    *   Update position: $\mu_i = \mu^{init}_i + \Delta \mu_i$ [S3].
    *   *Note:* During training, $\Delta \mu^{prev}_i$ is the offset from the previous iteration. During inference, initialize $\Delta \mu^{prev}_i = 0$ and recursively execute the update twice to converge [S3].
7.  **Color Prediction:** Project the 3D Gaussians to nearest reference views to retrieve 2D context (color windows $\{c_k\}$ and visibility maps) and decode the final color $c_i$ [S3].
8.  **Background Handling:** Model distant views/sky with a hemisphere Gaussian model where geometry is fixed and color is predicted similarly to the foreground [S3].

### Pseudocode (EVolSplat Geometry Prediction)
```python
def predict_gaussian_geometry(point_cloud_P, feature_volume_F, voxel_size):
    """
    Predicts Gaussian geometry from a global point cloud and feature volume.
    """
    gaussians = []
    
    # Initialize previous offset to zero for inference
    prev_offsets = {p: np.zeros(3) for p in point_cloud_P}
    
    # Recursive update (converged in ~2 iterations for inference)
    for iteration in range(2):
        for p in point_cloud_P:
            # 1. Query Feature
            current_pos = p + prev_offsets[p]
            f_i = feature_volume_F.trilinear_interpolate(current_pos)
            
            # 2. Predict Offset
            # D_pos is an MLP head
            raw_offset = D_pos(f_i)
            delta_mu = np.tanh(raw_offset) * voxel_size
            
            # 3. Update Position
            new_pos = p + delta_mu
            
            # 4. Query Feature at New Position for Alpha/Sigma
            f_i_updated = feature_volume_F.trilinear_interpolate(new_pos)
            
            # 5. Predict Opacity and Covariance
            alpha_i = D_opa(f_i_updated)
            sigma_i = D_cov(f_i_updated)
            
            # Store results
            gaussians.append({
                'mu': new_pos,
                'alpha': alpha_i,
                'sigma': sigma_i,
                'offset': delta_mu
            })
            
            # Update previous offset for next iteration (training) or keep for next query
            prev_offsets[p] = delta_mu
            
    return gaussians
```

### Parameters
*   $N$: Number of input images [S3].
*   $v_{size}$: Voxel size used to scale the position offset output [S3].
*   $K$: Number of nearest reference views for color retrieval [S3].
*   $N=2000, L=2, r=4$: Hyperparameters for Background Generator (initial Gaussians, hierarchy levels, upsampling factor) [S7].

### Edge Cases and Pitfalls
*   **Ghosting Artifacts:** Pixel-aligned methods generate redundant/inconsistent primitives in overlapping regions. Volume-based methods address this by filtering duplicates in 3D space [S3].
*   **Depth Noise:** Monocular depth predictions contain noise. Statistical filtering is required to remove floaters before feature volume extraction [S3].
*   **Convergence:** The recursive position update relies on convergence. Inference typically requires only 2 iterations to stabilize [S3].

## Subtopics

### GSGEN
GSGEN is a text-to-3D generation method that represents 3D content as a set of 3D Gaussians and optimizes them progressively in two stages: geometry optimization and appearance refinement, using 2D and 3D diffusion priors [S1][S2, unofficial]. It differs from NeRF-based methods (e.g., DreamFusion, Magic3D) by using explicit 3D Gaussians, which allows for the incorporation of direct 3D geometry priors and alleviates the Janus problem [S1]. It differs from DreamGaussian by focusing on incorporating 3D prior with more advanced representation, whereas DreamGaussian focuses on fast image-to-3D generation [S1].

### [Deformable 3D Gaussian Splatting](10060-deformable-3d-gaussian-splatting.md)
Deformable 3D Gaussian Splatting is a method for dynamic scene reconstruction that represents a scene as a set of 3D Gaussians in a static **canonical space**, with temporal and spatial deformations modeled by an implicit deformation field implemented as a Multi-Layer Perceptron (MLP). It solves the problem of reconstructing time-varying volumetric scenes by decoupling the static geometry from the motion, allowing for real-time rendering of dynamic content. It sets itself apart from siblings like [GSGEN](8985-gsgen.md) or [Fourier Splatting Primitive](11094-fourier-splatting-primitive.md) by explicitly learning a continuous deformation field to map canonical attributes to observation-space attributes at any timestep, rather than storing explicit trajectories or using frequency-based parameterizations.

### [Fourier Splatting Primitive](11094-fourier-splatting-primitive.md)
The Fourier Splatting primitive is a planar surfel for radiance field rendering that replaces the fixed Gaussian or elliptical falloff with a boundary defined by a Fourier series, allowing the representation of arbitrary closed shapes. Unlike 3D Gaussian Splatting (3DGS) or 2D Gaussian Splatting (2DGS), which are limited to fixed elliptical or disc shapes, this primitive enables higher fidelity representation of complex geometry and fine-grained details. Its key differentiator is inherent scalability: the level of detail (LoD) is controlled by truncating Fourier coefficients at runtime, allowing a single trained model to be rendered at varying complexities without retraining or post-hoc compression.

### [Conditional Slicing Mechanism](11455-conditional-slicing-mechanism.md)
The Conditional Slicing Mechanism conditions a 7-dimensional Gaussian on observed time $t$ and view direction $d$ to yield a conditional 3D Gaussian governing the spatial component. This operation "slices" the full 7D distribution to integrate temporal dynamics and view-dependent effects into the traditional 3D rendering pipeline without introducing additional temporal dependencies in the spherical harmonics. It sets itself apart from static Gaussian Splatting variants by explicitly modeling the joint distribution of space, time, and view, allowing the spatial mean and covariance to shift based on the current rendering context.

### [Structure-Aware 3D Gaussian Splatting (SAGS)](11908-structure-aware-3d-gaussian-splatting-sags.md)
Structure-Aware 3D Gaussian Splatting (SAGS) is a novel-view synthesis method that implicitly encodes scene geometry using a local-global graph representation to facilitate learning complex scenes and enforce meaningful point displacements that preserve structure, thereby reducing floating-point artifacts and storage requirements. Unlike standard 3D Gaussian Splatting which optimizes each Gaussian independently, SAGS leverages inter- and intra-connectivity between 3D point positions via Graph Neural Networks (GNNs) to predict Gaussian attributes, outperforming 3D-GS and Scaffold-GS in capturing high-frequency details while significantly reducing memory footprint.

### [Mesh-embedded representation](12559-mesh-embedded-representation.md)
Mesh-embedded representations parameterize 3D Gaussian primitives relative to an explicit canonical triangle mesh $\mathcal{M}$ to disentangle motion from appearance and enable explicit mesh editing. This family solves the problem of coherent, large-scale deformation and geometric coherence in Gaussian Splatting by tying Gaussian position, rotation, and scale to mesh geometry via barycentric embeddings or vertex parameterization, avoiding the artifacts and rigidity of implicit MLP-based skinning fields. Unlike standard 3DGS, which treats Gaussians as independent entities in free space, this approach ensures that mesh edits or animations propagate deterministically to the radiance field.

### [Inverse Gaussian Splattling](13193-inverse-gaussian-splattling.md)
Inverse Gaussian Splattling is a method for initializing 3D Gaussian primitives by back-projecting optimized 2D Gaussian kernels from image space into world space. It solves the problem of generating high-quality initial geometric parameters (position, rotation, scale) for new 3D Gaussians from 2D renderings, specifically handling foreground-background ambiguity in boundary regions. It differs from standard initialization by using Weighted Principal Component Analysis (WPCA) on clustered 3D points derived from depth maps, followed by a scaling calibration step to align the projected 3D covariance with the original 2D target.

### [Occupancy-Opacity Factorization](13440-occupancy-opacity-factorization.md)
Occupancy-Opacity Factorization decouples a Gaussian primitive's geometric presence from its optical properties by splitting the single standard opacity parameter into two learnable attributes: geometric occupancy ($\sigma$) and optical opacity ($\alpha$). This solves the problem where a single opacity parameter cannot simultaneously model a surface that is geometrically solid (for sharp reflections) yet optically clear (for light transmission). It sets itself apart from siblings like [Textured-GS](9436-textured-gs.md) and [Oriented Gaussian Splatting](9621-oriented-gaussian-splatting.md) by explicitly modeling the probabilistic interaction of rays with the Gaussian substance, enabling deferred shading for high-frequency reflection modeling.

### [CAG-GS Semantic Mapping and Gaussian Generation](15260-cag-gs-semantic-mapping-and-gaussian-generation.md)
CAG-GS generates implicit 3D Gaussians from semantic anchors by encoding spatial positions into high-dimensional semantic vectors via a multi-resolution hash grid, which are then fused with anchor features to predict Gaussian attributes. It distinguishes itself from standard 3D Gaussian Splatting by incorporating semantic guidance and geometric consistency constraints (normal and flattening losses) to improve global consistency in large-scale scenes, utilizing a coarse-to-fine training strategy.

### [Geometry and orientation extension](15381-geometry-and-orientation-extension.md)
This family extends the standard 3D Gaussian primitive to better model explicit geometry, surface orientation, and directional asymmetry, which standard isotropic Gaussians lack [G]. It sets itself apart from standard 3D Gaussian Splatting by introducing learnable normals [9621-oriented-gaussian-splatting.md], skewness [10045-3d-skew-normal-splatting.md], or mesh-constrained parameterizations [15283-barycentric-splat-parameterization.md] to enable surface wrapping, mesh extraction, and view-dependent effects.

### [Voxel and Grid-Based Prediction](15382-voxel-and-grid-based-prediction.md)
Voxel and Grid-Based Prediction is a neural rendering method that combines voxel-based density representation with Multi-Plane Image (MPI) depth layers for efficient volume rendering, supporting sparse grids and occupancy caching. It solves the problem of memory-intensive dense voxel storage by using sparse structures and MPI depth planes to approximate continuous volumes, while simultaneously predicting 3D Gaussian parameters from voxel features to enable explicit primitive rendering. Unlike sibling methods that optimize neural feature grids directly or use triplane representations, this approach operates on a voxel grid to predict Gaussian geometry and attributes via residual correction or direct regression.

### [Functional Gaussian Splatting Representation](15572-functional-gaussian-splatting-representation.md)
Functional Gaussian Splatting (DiffGS Representation) solves the problem of representing discrete, unstructured 3D Gaussian Splatting (3DGS) primitives as continuous, differentiable functions to enable generative modeling. It disentangles the 3DGS representation into three specific functions: Gaussian Probability Function (GauPF) for geometry, Gaussian Color Function (GauCF) for appearance, and Gaussian Transform Function (GauTF) for structural attributes. Unlike sibling methods that modify the primitive shape or storage structure, this representation maps the discrete set of Gaussians to continuous fields, allowing the use of standard generative frameworks like Variational Autoencoders (VAEs) and Latent Diffusion Models (LDMs).

### [InnerGS Volumetric Rendering](15748-innergs-volumetric-rendering.md)
InnerGS is a volumetric rendering method that models continuous 3D density using 3D Gaussians to synthesize novel 2D slices at arbitrary depths, avoiding the discrete projection artifacts of standard 3D Gaussian Splatting (3DGS). Unlike standard 3DGS which renders pixels via perspective projection of splats onto a camera plane, InnerGS calculates the contribution of each Gaussian directly to a pixel on a 2D slice at a specific depth $t$ along a given axis. This approach enables seamless volumetric interpolation and explicit internal structure reconstruction, making it suitable for applications like medical imaging where internal slices are required.

### [Plenoptic Sampling Guided 3DGS Construction](16971-plenoptic-sampling-guided-3dgs-construction.md)
Plenoptic Sampling Guided 3DGS Construction is a method for initializing 3D Gaussian Splatting (3DGS) representations directly from mesh geometry, using plenoptic sampling theory to theoretically derive the minimum sampling rate for views and the optimal distribution of 3D Gaussians. Unlike heuristic initialization methods that rely on trial-and-error, this approach precisely constrains Gaussian density and camera sampling to achieve Nyquist-level performance for global illumination caching. It sets itself apart by grounding the initialization in signal processing principles, ensuring that the number of Gaussians and sampled views is minimized while maintaining high-fidelity rendering.

### [Geometry Guided Gaussian Points Generation](16972-geometry-guided-gaussian-points-generation.md)
Geometry Guided Gaussian Points Generation (MGadapter) is a method that generates structured 3D Gaussian point attributes from an intermediate triangular mesh, providing explicit geometric guidance to 3D Gaussian Splatting (3DGS). It solves the problem of vanilla 3DGS lacking deterministic geometry boundaries and explicit normal directions, which complicates light transport computation and hinders physically-based inverse rendering. Unlike sibling methods that rely on learned approximated normals or real-time optimization to maintain shape consistency, MGadapter uses a predefined heuristic function to map mesh triangles directly to Gaussian points, leveraging well-defined mesh normals for improved accuracy and stable training.

### [Optical and Attribute Enhancement](17107-optical-and-attribute-enhancement.md)
Optical and Attribute Enhancement refers to a family of techniques that refine the visual appearance of 3D Gaussian primitives beyond the standard base parameters (position, scale, rotation, opacity, and low-order Spherical Harmonics). These methods address limitations in standard 3D Gaussian Splatting (3DGS) regarding high-frequency details, spatial texture variation, and optical phenomena like defocus. They set themselves apart from sibling methods by modifying how attributes are predicted, stored, or evaluated—ranging from baking neural offsets into static parameters to evaluating SH coefficients on surface intersection vectors rather than viewing directions.

### [Sampling and Initialization Strategy](17201-sampling-and-initialization-strategy.md)
Sampling and Initialization Strategy defines the methods for generating the initial set of 3D Gaussian primitives from input data (such as SfM points, NeRF models, or anchor points) before the optimization or rendering loop begins [G]. It solves the problem of establishing a valid geometric representation that covers the scene while avoiding the computational bottlenecks and failure modes of standard Structure-from-Motion (SfM) pipelines in large-scale or textureless environments [G]. It differs from sibling methods like [GSGEN](8985-gsgen.md) or [Feed-forward and Generalizable Prediction](15832-feed-forward-and-generalizable-prediction.md) by focusing on the specific geometric sampling techniques (e.g., pyramidal sampling, anchor deviation, or voxel-based decoding) rather than end-to-end generative models or feed-forward networks [G].

### [Wavelet-to-Gaussian Transition Bank](17351-wavelet-to-gaussian-transition-bank.md)
The Wavelet-to-Gaussian Transition Bank is a method for constructing Gaussian surrogates for wavelet kernels by fitting a single canonical Gaussian per subband and obtaining others via spatial translation, avoiding redundant fitting for every wavelet kernel. It solves the computational bottleneck of independently fitting Gaussians to every wavelet coefficient in a multi-scale decomposition, enabling efficient analytical conversion from wavelet bases to Gaussian primitives for real-time volumetric visualization. It differs from sibling methods like [GSGEN](8985-gsgen.md) or [Feed-forward and Generalizable Prediction](15832-feed-forward-and-generalizable-prediction.md) by relying on precomputed analytical mappings derived from the translation properties of the discrete wavelet transform (DWT) rather than learned neural networks or random sampling.

### [EA-3DGS](20636-ea-3dgs.md)
EA-3DGS is a method for large-scale 3D scene representation that addresses the instability and memory inefficiency of standard 3D Gaussian Splatting (3DGS) by using an adaptive tetrahedral mesh for initialization, structure-aware pruning/densification for stability, and vector quantization for compression. It sets itself apart from partitioning-based large-scale methods (e.g., CityGaussian, DoGaussian) by enabling single-GPU training without complex synchronization or merging of multiple nodes, thereby preserving global information like lighting.

### [Hard Prediction Pipeline](21482-hard-prediction-pipeline.md)
The Hard Prediction Pipeline generates 3D Gaussian primitives from a monocular depth predictor and refines their geometry to strictly match a target depth map, particularly within occlusion holes or missing regions. It differs from standard differentiable rendering pipelines by enforcing a "hard" constraint on camera-space Z-coordinates for specific pixels, ensuring that the generated Gaussians do not violate the authoritative depth data while preserving lateral ray positions. This method is designed to integrate external depth priors (referred to as "LingBot" in the source) with a target depth map, using a transition zone to avoid depth cliffs without altering the unmodified background.

### [SHARP Gaussian Generation with Hard Depth Anchor](21493-sharp-gaussian-generation-with-hard-depth-anchor.md)
This method generates SHARP Gaussians for hole filling in 3D Gaussian Splatting by bypassing the learned Alignment UNet of the original SHARP pipeline. It uses completed camera-Z depth as the primary anchor and SHARP's monocular relative gap as a secondary channel to maintain the five-channel decoder contract. It differs from sibling methods like [GSGEN](8985-gsgen.md) by relying on explicit depth anchoring rather than learned generative priors for geometry initialization.

### GaMeS Parametrization
GaMeS Parametrization parameterizes Gaussian components into flat triangle-face meshes, allowing GS to be visualized and manipulated as a triangle soup [S4, unofficial]. For mesh-bound Gaussians, means are assigned to mesh faces via learnable barycentric coordinates of vertices, ensuring they remain bound under deformation [S4, unofficial]. The orientation is defined by the face normal and two in-plane directions derived from the vertices [S4, unofficial].
**Forward Mapping:** Given Gaussian $N(m, R, S)$ with $R=[r_1, r_2, r_3]$ and $S=\text{diag}(\epsilon, s_2, s_3)$, the triangle vertices are $v_1 = m$, $v_2 = m + s_2 r_2$, and $v_3 = m + s_3 r_3$ [S4, unofficial].
**Inverse Mapping:** Given triangle $V=[v_1, v_2, v_3]$, the Gaussian is recovered as $N(\hat{m}, \hat{R}, \hat{S})$ using:
$$ \hat{m} = v_1 $$
$$ \hat{r}_1 = \frac{(v_2 - v_1) \times (v_3 - v_1)}{\|(v_2 - v_1) \times (v_3 - v_1)\|} $$
$$ \hat{r}_2 = \frac{v_2 - v_1}{\|v_2 - v_1\|}, \quad \hat{r}_3 = \text{orth}(v_3 - v_1; \hat{r}_1, \hat{r}_2) $$
$$ \hat{s}_1 = \epsilon, \quad \hat{s}_2 = \|v_2 - v_1\|, \quad \hat{s}_3 = \langle v_3 - v_1, \hat{r}_3 \rangle $$
The covariance matrix is $\hat{\Sigma} = \hat{R}\hat{S}\hat{S}^T\hat{R}^T$ [S4, unofficial].

### Gamba
Gamba predicts Gaussian attributes using the recent Mamba network to better capture the relationship between Gaussians [S5, unofficial].

### Flatness Constraint
Flatness Constraint is a post-optimization constraint that pushes the smallest scale axis of each Gaussian to be thinner relative to the median scale, enforcing flatness [S6, unofficial].
**Steps:**
1. Check if `flatness_lambda > 0`.
2. Find index of minimum scale: `min_idx = exp_s.argmin(dim=-1)`.
3. Compute median scale value: `mid_val = exp_s.median(dim=-1).values`.
4. Compute target thin scale in log space: `target_thin = log(mid_val * (1.0 - flatness_lambda * 0.9))`. Clamp min 1e-7.
5. Get current thin scale: `current_thin = s[torch.arange(len(s)), min_idx]`.
6. Update thin scale: `new_thin = min(current_thin, lerp(current_thin, target_thin, flatness_lambda))`. Only push thinner, do not inflate.
7. Assign `new_thin` to the corresponding scale entry: `s[torch.arange(len(s)), min_idx] = new_thin` [S6, unofficial].
**Parameter:** `flatness_lambda`: Slider controlling flatness strength [S6, unofficial].

### Background Generator
Background Generator is a module for background Gaussians that uses simple linear layers with demodulation and modulation instead of attention and MLP layers to reduce computational cost [S7].
**Steps:**
1. Normalize position parameters synthesized by the generator so that generated Gaussians are located on a sphere with radius 3 [S7].
**Parameters:** Initial Gaussians $N=2000$, hierarchy levels $L=2$, upsampling factor $r=4$, channel size 128. Total background Gaussians: 10,000 [S7].

### Gaussian Normal Vector
The normal of the Gaussian is represented as the direction of the minimized scaling factor [S8].
**Steps:**
1. Transform the normal $n$ and position $p$ into the camera coordination system with the camera extrinsic matrix [S8].
**Formula:**
$$ n = R[k, :] \in \mathbb{R}^3, \quad k = \text{argmin}([s_1, s_2, s_3]) $$
where $R$ is the rotation matrix and $s$ is the scaling factor vector [S8].

## Operating characteristics
*   **Time Complexity:** Feed-forward methods (e.g., EVolSplat, Gamba) are significantly faster than iterative 3DGS, as they avoid per-scene optimization loops [S3][S5, unofficial].
*   **Memory Complexity:** Volume-based methods require storing a 3D feature volume $F$, which scales with the scene size but is often sparser than dense voxel grids [S3].
*   **Performance:** EVolSplat achieves real-time rendering by feed-forward prediction [S3]. It improves global consistency and reduces ghosting artifacts compared to pixel-aligned methods [S3].
*   **Strengths:** Fast inference, global consistency, reduced ghosting, ability to handle large-scale urban scenes [S3].
*   **Limitations:** Relies on the quality of monocular depth estimators; noisy depth can lead to artifacts if not filtered [S3].

## Background
Gaussian Geometry Parameters Prediction emerged as a solution to the slow optimization process of standard 3D Gaussian Splatting [S3]. Early methods like EVolSplat introduced volume-based prediction for urban scenes [S3]. Subsequent works like Gamba integrated Mamba networks for better attribute prediction [S5, unofficial], and GaMeS introduced mesh-based parametrization for physics simulations [S4, unofficial]. The field continues to expand with variants for dynamic scenes, semantic guidance, and generative modeling [S1][S2, unofficial][S7].
