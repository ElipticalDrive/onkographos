# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, GSGEN Implementation Details, Gaussian Splatting Training Configuration, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific implementation parameters, optimization strategies, and variant algorithms required to train and render 3D Gaussian Splatting (3DGS) scenes effectively. It addresses the core differentiable rasterization pipeline, including half-precision arithmetic, adaptive density control, and scene extent calculation, while cataloging minor variants that modify gradient thresholds, blur modeling, or multi-scale constraints. It builds on [Optimization and Parallelization](6233-optimization-and-parallelization.md) by providing the concrete hyperparameters and kernel-level details necessary to realize the shared principles of differentiable alpha-blending and hardware acceleration.

## How it works

### Inputs and Outputs
*   **Inputs**: A sparse point cloud from Structure-from-Motion (SfM) [S4], camera poses, and a set of training images.
*   **Outputs**: A set of 3D Gaussian primitives parameterized by mean $\mu$, covariance $\Sigma$ (or scale $s$ and rotation $R$), opacity $\alpha$, and spherical harmonic (SH) coefficients for color [S3].

### Data Structures
The scene is represented as a list of Gaussian primitives. Each primitive stores:
*   Position $\mu \in \mathbb{R}^3$.
*   Scale $s \in \mathbb{R}^3$ and Rotation $R \in SO(3)$, often stored as a quaternion or rotation matrix to form the covariance matrix $\Sigma = R S S^T R^T$ [S5].
*   Opacity $\alpha \in [0, 1]$.
*   SH coefficients for color, typically up to degree 1 (9 coefficients per RGB channel) [S3].

### Training Loop and Optimization
The training process iteratively optimizes the Gaussian parameters to minimize the difference between rendered images and ground truth.

1.  **Initialization**: Gaussians are initialized from the SfM point cloud. The scene extent $e_{\text{scene}}$ determines the initial scale and splitting thresholds.
2.  **Forward Pass**: For each iteration, a random image is selected [S3]. Gaussians are projected to 2D, sorted by depth, and rasterized using alpha blending [6233-optimization-and-parallelization].
3.  **Loss Computation**: The loss $\mathcal{L}$ is computed between the rendered image $\hat{C}$ and the ground truth $C$. A common formulation combines Mean Squared Error (MSE) and Structural Similarity (SSIM) [S13, unofficial]:
    $$ \mathcal{L} = \lambda \cdot \text{MSE}(C, \hat{C}) + (1 - \lambda) \cdot \text{SSIM}(C, \hat{C}) $$
    where $\lambda$ is a hyperparameter balancing the terms [S13, unofficial].
4.  **Backward Pass**: Gradients are computed with respect to Gaussian parameters using the differentiable rasterizer [6233-optimization-and-parallelization].
5.  **Optimizer Update**: Parameters are updated using the Adam optimizer with a learning rate of $1 \times 10^{-3}$ [S3].

### Adaptive Density Control (Densification)
To manage the number of Gaussians, densification (splitting and cloning) and pruning are performed periodically based on positional gradients.

*   **Splitting**: Gaussians with accumulated view-space position gradients exceeding a threshold $T_{\text{pos}}$ are split. The default threshold is $T_{\text{pos}} = 0.02$ [S1]. Splitting occurs every 500 iterations [S1].
*   **Cloning**: Gaussians with high gradients but low opacity are cloned to increase density without introducing new variance [S1].
*   **Pruning**: Gaussians with opacity $\alpha < \alpha_{\text{min}} = 0.05$ are removed [S1]. Additionally, Gaussians with excessively large world-space or view-space radii are pruned every 200 iterations [S1].
*   **Compactness**: Compactness-based densification is performed every 1000 iterations [S1].

### Half-Precision Rasterization
To reduce register pressure and memory bandwidth, the rasterization kernels (forward and backward) use half-precision (FP16) memory fetches for feature vectors [S2]. An automatic scaling factor is applied to loss values to improve training stability in half-precision [S2].

### Scene Extent Calculation
The default 3DGS scene extent $e_{\text{scene}}$ is proportional to the distance of the furthest camera from the average camera position $\bar{C}$:
$$ e_{\text{scene}} = 1.1 \cdot \max_{i=1}^{N_{\text{cam}}} \|\bar{C} - C_i\|_2 $$
$$ \bar{C} = \frac{1}{N_{\text{cam}}} \sum_{i=1}^{N_{\text{cam}}} C_i $$
This can bias optimization if cameras are clustered (e.g., orbiting a small object in a large environment) [S4]. A corrected scene extent $e'_{\text{scene}}$ uses the SfM point cloud $p_i$:
$$ e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2 $$
where $N_{\text{SfM}}$ is the number of SfM points [S4].

### Pseudocode: Training Step
```python
def train_step(gaussians, camera, image, optimizer, iteration):
    # 1. Forward Pass
    rendered_image = rasterize(gaussians, camera)
    
    # 2. Loss Computation
    mse_loss = mean_squared_error(image, rendered_image)
    ssim_loss = 1 - structural_similarity(image, rendered_image)
    loss = 0.85 * mse_loss + 0.15 * ssim_loss  # Typical lambda=0.85 for MSE
    
    # 3. Backward Pass
    loss.backward()
    
    # 4. Optimizer Update
    optimizer.step()
    optimizer.zero_grad()
    
    # 5. Densification and Pruning
    if iteration % 500 == 0:
        split_gaussians(gaussians, threshold=0.02)
    if iteration % 200 == 0:
        prune_gaussians(gaussians, alpha_min=0.05)
    if iteration % 1000 == 0:
        compactify_gaussians(gaussians)
        
    return loss
```

## Subtopics

### Corrected Scene-Extent
A method to calculate scene extent based on the SfM point cloud rather than camera positions to avoid bias from camera distribution (e.g., orbiting a small object in a large environment) [S4]. It sets itself apart from the default 3DGS extent calculation by using the spatial distribution of the initialized points, ensuring the scene volume is accurately reflected regardless of camera clustering [S4].

### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ to selectively enlarge covariances, creating pixel-wise variable blur kernels that match spatially varying scene blurriness [S5]. It sets itself apart from naive Gaussian blur by allowing spatially varying blur shapes and magnitudes, enabling effective deblurring of defocus artifacts [S5].

### Denoise-GS
A self-supervised denoising method for sparse-view 3D Gaussian Splatting that combines unsupervised image denoising (Noise2Void) with differentiable 3DGS [S6]. It sets itself apart from supervised methods by requiring no paired clean data, making it robust to non-Gaussian and time-varying noise in sparse viewpoint scenarios [S6].

### Multi-Scale Constraint
A technique using position-aware point adaptive control to apply different scales to Gaussians based on viewer distance, improving rendering of distant objects [S7]. It sets itself apart from standard densification by using a distance-dependent scaling factor $\gamma(\mu)$ to adjust cloning and splitting thresholds, ensuring larger Gaussians for distant objects and smaller ones for nearby regions [S7].

### LS-Gaussian Viewpoint Transformation
An algorithm that leverages inter-frame continuity for efficient sparse rendering by transforming the viewpoint between consecutive frames, rather than rendering each frame separately [S8]. It sets itself apart from naive pixel warping by operating at the tile/Gaussian level to reduce preprocessing and sorting costs, enabling sparse rendering where only one frame in every 6 frames is fully rendered [S8].

### Camera Localisation for Convergence Basin
Localizes camera pose by minimizing only the photometric error against the ground-truth colour image of the target view, fixing the initial Gaussians $G_{init}$ during optimization [S9, unofficial]. It sets itself apart from joint optimization methods by decoupling pose estimation from scene reconstruction, allowing for robust initialization within a 1cm convergence basin [S9, unofficial].

### DiffGS Framework
Applies an optimization process during Gaussian extraction to optimize Gaussians to exact locations, using a truncation function $\lambda$ and projection function $\tau$ (e.g., exponential or linear) [S10]. It sets itself apart by focusing on precise Gaussian localization, achieving high PSNR and SSIM with fewer Gaussians (e.g., 50K-350K) compared to standard 3DGS [S10].

### Opacity Offset Table for DSA
Constructs an opacity offset table to model changes in digital subtraction angiography [S11]. It sets itself apart by explicitly handling temporal opacity variations in medical imaging contexts [S11].

### Conditional Splat Approximation
Approximates the influence range of a 3D Gaussian on a slice by using a 2D ellipse splat scaled by the marginal factor, which closely matches the true iso-probability contours [S12, unofficial]. It sets itself apart by providing an accurate and efficient approximation for slice-based rendering or tomographic reconstruction [S12, unofficial].

### PyGS Optimization
Uses a combined MSE and SSIM loss, along with density control strategies adapted from 3DGS, while preserving a multi-scale structure [S13, unofficial]. It sets itself apart by routinely reassessing and reassigning the levels of Gaussians based on their scales to maintain a balanced distribution across different levels in large-scale scenes [S13, unofficial].

### GAINS (Gaussian-based Inverse Rendering from Sparse multi-view captures)
A two-stage inverse rendering framework that leverages foundation model priors to stabilize geometry and material estimation from sparse multi-view RGB captures [S14]. It sets itself apart by using 2DGS for more accurate geometry reconstruction, which is essential for accurate material property estimation, and integrating monocular depth, normal, and diffusion priors [S14].

### SAGS (Adaptive Gaussian Splatting)
Utilizes an adaptive 2D low-pass filter at inferencing time based on rendering resolution and camera distance to handle aliasing [S15, unofficial]. It sets itself apart by dynamically adjusting the filtering based on scene geometry and view parameters to produce aliasing-free images [S15, unofficial].

### Frequency Gaussian Splatting
Applies frequency-domain regularization to the rendered 2D image to encourage recovery of high-frequency detail, resolving blurring issues [S15, unofficial]. It sets itself apart by explicitly targeting high-frequency loss in the frequency domain, unlike spatial-domain smoothing methods [S15, unofficial].

### Neural Illumination Enhancement
A neural module applied only to non-Lambertian regions to model view-dependent highlights and handle non-Lambertian effects that vanilla 3DGS struggles with [S16, unofficial]. It sets itself apart by combining explicit 3DGS representation with a lightweight MLP that predicts a view-dependent color residual, enabling modeling of view-dependent highlights alongside global illumination caching [S16, unofficial].

### GraphiGS
A variant of the GraphiXS framework where the component distribution $\delta_\theta$ is modeled as a 3D Gaussian primitive, providing compact spatial support and exponential density decay [S17]. It sets itself apart by using Gaussian primitives to model uncertainty, offering compact spatial support compared to heavy-tailed distributions [S17].

## Operating characteristics

*   **Time Complexity**: The rasterization step is $O(N \cdot K)$, where $N$ is the number of Gaussians and $K$ is the average number of Gaussians per pixel. Sorting is $O(N \log N)$ per tile. Training time is dominated by the forward and backward passes through the differentiable rasterizer.
*   **Memory Complexity**: Memory usage is proportional to the number of Gaussians, with each Gaussian storing position, covariance, opacity, and SH coefficients. Half-precision rasterization reduces memory bandwidth requirements [S2].
*   **Performance**: Standard 3DGS achieves real-time rendering (60+ FPS) on modern GPUs for scenes with millions of Gaussians [6233-optimization-and-parallelization]. Variants like LS-Gaussian can achieve significant speedups (e.g., 5.41× on Jetson AGX Orin) through sparse rendering [S8].
*   **Strengths**: High rendering quality, real-time performance, and explicit representation allows for easy editing and manipulation.
*   **Limitations**: High memory usage for large scenes, potential for "floaters" or artifacts in sparse-view scenarios, and sensitivity to initialization [S4, S6].
*   **When to use**: Real-time novel view synthesis, interactive applications, and scenarios requiring high-fidelity rendering.
*   **When not to use**: Scenarios with extreme sparsity of views without denoising variants, or when memory constraints are severe without compression variants.

## Background

3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1]. It represents scenes as a set of 3D Gaussians and uses a differentiable rasterizer to render them, achieving high-quality novel view synthesis at real-time frame rates. The method has since been extended with various optimization and training strategies to improve efficiency, quality, and robustness [S1-S17].
