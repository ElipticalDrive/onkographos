# LGTM (Less Gaussians, Texture More)

Also called: Feed-Forward Prediction of Textured Gaussians, Feed-Forward Textured Splatting

## Overview
LGTM is a feed-forward framework that predicts compact 2D Gaussian primitives coupled with per-primitive texture maps, decoupling geometric complexity from rendering resolution to enable high-fidelity 4K novel view synthesis without per-scene optimization [S1, unofficial]. It solves the problem where existing feed-forward 3D Gaussian Splatting methods suffer from quadratic growth in primitive count as resolution increases, making high-resolution synthesis intractable due to memory and compute limits [S1, unofficial]. Unlike standard 3DGS which couples appearance and geometry within each primitive, LGTM decouples them, allowing a compact set of geometric primitives to represent rich texture regions via per-primitive textures [S1, unofficial].

## How it works
**Inputs and Outputs:**
The network $f$ takes a set of input images $\{I^v\}_{v=1}^N$ and their low-resolution counterparts $\{I^v_{low}\}_{v=1}^N$ as input. It outputs a set of textured 2D Gaussians:
$$ f : (I^v, I^v_{low}) \rightarrow \{\mu_i, s_i, r_i, c_i, T^i_c, T^i_\alpha\} $$
where $\mu_i$ is the position, $s_i$ is the scale, $r_i$ is the rotation, $c_i$ is the spherical harmonic (SH) coefficients, $T^i_c$ is the color texture map, and $T^i_\alpha$ is the alpha texture map for primitive $i$ [S1, unofficial].

**Data Structures:**
*   **Primitive Grid:** The primitive network predicts a grid of $h \times w$ 2DGS primitives. Each primitive $i$ has parameters $\mu_i, s_i, r_i, o_i$ (opacity), and $c_i$ [S1, unofficial].
*   **Per-primitive Texture Maps:** Each primitive $i$ has two learnable texture maps:
    *   Color texture: $T^i_c \in \mathbb{R}^{T \times T \times 3}$
    *   Alpha texture: $T^i_\alpha \in \mathbb{R}^{T \times T}$
    *   $T$ is the texture resolution, a tunable parameter trading off primitive size and texture size [S1, unofficial].
    *   $T^i_c$ is zero-initialized [S1, unofficial].

**Formulas:**
1.  **Standard 2DGS Evaluation (for geometry/SH):**
    The alpha value $a_i(u)$ and color $\hat{c}_i(d_i)$ for a sample at local coordinate $u$ on primitive $i$ are:
    $$ a_i(u) = o_i \cdot G(u) $$
    $$ \hat{c}_i(d_i) = SH(c_i, d_i) $$
    where $d_i$ is the view direction, $o_i$ is the base opacity, and $G(u) = \exp(-\frac{1}{2}(u^2 + v^2))$ is the 2D Gaussian function [S1, unofficial].

2.  **Textured Gaussian Evaluation (LGTM):**
    The alpha and color are redefined using the texture maps retrieved via bilinear sampling $T[u]$:
    $$ a_i(u) = o_i \cdot T^i_\alpha[u] $$
    $$ \hat{c}_i(u, d_i) = T^i_c[u] + SH(c_i, d_i) $$
    The alpha texture $T^i_\alpha$ replaces the Gaussian falloff $G(u)$, and the color texture $T^i_c$ adds high-frequency detail to the SH base color [S1, unofficial].

3.  **Final Pixel Color:**
    The final pixel color $C$ is computed by alpha-blending contributions from all primitives sorted by depth:
    $$ C = \sum_i a_i(u_i) \hat{c}_i(d_i) \prod_{j=1}^{i-1} (1 - a_j(u_j)) $$
    [S1, unofficial]

4.  **Projective Prior Feature:**
    To compute projective features $F^{proj}_v$, the source image is mapped back to primitive local coordinates using the inverse transformation $M_{i,v}^{-1}$:
    $$ T^{c,proj}_i[u] = I^v[x] = I^v[M_{i,v}^{-1}(u)] $$
    where $u$ is the local coordinate on the primitive and $x$ is the pixel coordinate in the source image $I^v$ [S1, unofficial].

**Algorithm Steps:**
The method consists of two submodules: a primitive network $f_{prim}$ and a texture network $f_{texture}$.

1.  **Primitive Network ($f_{prim}$):**
    *   Input: Low-resolution image $I^v_{low} \in \mathbb{R}^{h \times w \times 3}$.
    *   Process: Pass $I^v_{low}$ through a ViT encoder-decoder.
    *   Output: Predict primitive grid parameters $\{\mu_i, s_i, r_i, o_i, c_i\}$ and feature maps $F^{prim}_v$. The grid size is $h \times w$ [S1, unofficial].

2.  **Texture Network ($f_{texture}$):**
    *   Input: High-resolution image $I^v$ and primitive features $F^{prim}_v$.
    *   Process:
        a.  **Patch Features:** Extract high-resolution features $F^{patch}_v$ from $I^v$ via image patchification and convolutions.
        b.  **Projective Features:** Compute projective prior textures $T^{c,proj}_i$ using the inverse transformation $M_{i,v}^{-1}$ to map primitive local coordinates $u$ to source image pixels $x$. Extract features $F^{proj}_v$ from these priors.
        c.  **Aggregation:** Aggregate $F^{prim}_v$, $F^{patch}_v$, and $F^{proj}_v$.
    *   Output: Predict per-primitive texture maps $T^i_\alpha$ and $T^i_c$ [S1, unofficial].

3.  **Rendering:**
    *   For a ray-splat intersection point $u$, retrieve color and alpha from texture maps using bilinear sampling: $T[u]$.
    *   Compute $a_i(u)$ and $\hat{c}_i(u, d_i)$ using the textured formulas above.
    *   Alpha-blend as per standard 2DGS [S1, unofficial].

**Training Strategy:**
1.  **Stage 1 (Pre-training):** Train $f_{prim}$ in isolation. Input $I^v_{low}$, predict 2DGS parameters. Supervise at full resolution $H \times W$ (high-resolution supervision) to prevent holes and ensure anti-aliasing, despite low-res input [S1, unofficial].
2.  **Stage 2 (Joint Training):** Jointly train $f_{prim}$ and $f_{texture}$. Freeze or reduce the learning rate of $f_{prim}$ by 0.1x to maintain geometric stability. Initialize $T^i_c$ to zero. Supervise with standard photometric losses (MSE + LPIPS) [S1, unofficial].

**Parameters:**
*   $T$: Texture resolution. Tunable trade-off between primitive count and texture memory [S1, unofficial].
*   Learning Rate Reduction: 0.1x for $f_{prim}$ in Stage 2 [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Holes:** Without high-resolution supervision in Stage 1, predicted Gaussians may result in areas with holes when rendered at high resolution because they are not anti-aliased [S1, unofficial].
*   **Memory:** Standard feed-forward methods fail at 2K+ resolutions due to memory constraints (e.g., NoPoSplat fails at 2K/4K). LGTM handles 2K/4K with <30GB memory [S1, unofficial].

## Operating characteristics
*   **Memory:** LGTM trains successfully at 2K and 4K resolutions using under 30 GB of memory. In contrast, NoPoSplat fails to train at 2K or higher due to Out-Of-Memory (OOM) errors, reaching 61.85 GB at 1024x576 primitives [S1, unofficial].
*   **Scaling:** At inference, a 64x pixel increase adds only modest memory and time overhead [S1, unofficial].
*   **Strengths:** Enables feed-forward 4K novel view synthesis; decouples geometry and appearance; significantly fewer primitives than prior feed-forward methods; versatile (works with monocular, posed/unposed two-view, and multi-view inputs) [S1, unofficial].
*   **Limitations:** Requires a dual-network architecture; relies on high-resolution supervision during training to avoid holes [S1, unofficial].
*   **When to use:** When high-resolution (4K) novel view synthesis is required without per-scene optimization, and memory is constrained [S1, unofficial].

## Background
LGTM was published as a conference paper at ICLR 2026 by Yixing Lao, Xuyang Bai, Xiaoyang Wu, Nuoyuan Yan, Zixin Luo, Jean-Daniel Nahmias, Yanghai Tsin, Shiwei Li, and Hengshuang Zhao from HKU and Apple [S1, unofficial]. It addresses the limitations of prior textured Gaussian methods which required per-scene optimization, and feed-forward methods which suffered from quadratic primitive growth [S1, unofficial].
