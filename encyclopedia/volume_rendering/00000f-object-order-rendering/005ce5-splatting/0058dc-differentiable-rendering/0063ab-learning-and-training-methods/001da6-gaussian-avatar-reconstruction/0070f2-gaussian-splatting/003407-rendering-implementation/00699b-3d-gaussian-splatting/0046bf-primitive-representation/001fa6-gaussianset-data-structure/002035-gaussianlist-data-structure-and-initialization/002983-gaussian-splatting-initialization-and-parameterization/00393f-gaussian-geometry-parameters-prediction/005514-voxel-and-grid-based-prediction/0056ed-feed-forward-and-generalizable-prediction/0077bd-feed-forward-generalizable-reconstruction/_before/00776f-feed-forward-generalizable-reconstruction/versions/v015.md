# Feed-forward Generalizable Reconstruction

Also called: Feed-forward 3D Gaussian Splatting (FF3DGS), Generalizable 3DGS

## Overview
Feed-forward generalizable reconstruction methods predict a set of 3D Gaussian primitives directly from input images in a single forward pass, eliminating the need for per-scene gradient descent optimization [16746-feed-forward-generalizable-reconstruction.md]. This approach solves the latency and compute bottlenecks of iterative reconstruction by leveraging priors learned from large-scale datasets, enabling real-time novel view synthesis on unseen scenes [16746-feed-forward-generalizable-reconstruction.md]. Unlike iterative methods that optimize geometry per scene, these methods generalize by mapping image features to Gaussian parameters via learned neural networks [16746-feed-forward-generalizable-reconstruction.md].

## Shared principles
All methods in this family share the core objective of mapping input image features to a set of 3D Gaussian parameters $\mathcal{G} = \{\mu, \Sigma, \alpha, c\}$ without per-scene gradient descent [16746-feed-forward-generalizable-reconstruction.md].

1.  **Input Representation:** Inputs are typically one or more RGB images $I \in \mathbb{R}^{H \times W \times 3}$. Some methods require known camera poses $P$, while others (e.g., [Splatt3R](16423-splatt3r.md), [ZeroGS](16425-zerogs.md)) predict poses or operate on uncalibrated inputs [16746-feed-forward-generalizable-reconstruction.md].
2.  **Feature Encoding:** A shared encoder (e.g., Vision Transformer, CNN) extracts multi-scale features from the input images. Cross-attention or cost volumes are often used to aggregate multi-view information [16746-feed-forward-generalizable-reconstruction.md].
3.  **Primitive Prediction:** A decoder head predicts Gaussian attributes. These attributes are usually:
    *   **Mean ($\mu$):** 3D position.
    *   **Covariance ($\Sigma$):** Defined by scale $s$ and rotation $r$ (quaternion or 6D).
    *   **Opacity ($\alpha$):** Scalar.
    *   **Color ($c$):** Spherical Harmonics (SH) coefficients or constant RGB [16746-feed-forward-generalizable-reconstruction.md].
4.  **Differentiable Rendering:** The predicted Gaussians are rendered into target views using differentiable rasterization to compute reconstruction losses (e.g., L1, SSIM, LPIPS) for training the network [16746-feed-forward-generalizable-reconstruction.md].
5.  **Generalization:** The network is trained on a large dataset of scenes to learn priors about geometry and appearance, allowing inference on unseen scenes [16746-feed-forward-generalizable-reconstruction.md].

## Subtopics

### [AnySplat Pipeline](12847-anysplat-pipeline.md)
AnySplat is a feed-forward, generalizable reconstruction method that predicts a set of 3D Gaussians directly from uncalibrated input images without per-scene optimization. It solves the problem of requiring known camera poses and per-scene training by jointly predicting Gaussian parameters, depth maps, and camera poses using a transformer-based encoder-decoder architecture. Unlike sibling methods that may rely on fixed grids or specific calibration assumptions, AnySplat operates on unconstrained views and uses a differentiable voxelization module to handle the transition from pixel-wise predictions to a renderable 3D primitive set.

### [Splatt3R](16423-splatt3r.md)
Splatt3R is a feed-forward model that predicts 3D Gaussian Splat parameters directly from a pair of uncalibrated RGB images, without requiring camera intrinsics, extrinsics, or depth maps. It extends the MASt3R foundation model by adding a parallel "Gaussian head" to predict per-pixel Gaussian attributes, enabling novel view synthesis via differentiable rendering. Unlike sibling methods that typically supervise only interpolated views between input cameras, Splatt3R is designed to extrapolate to viewpoints outside the stereo baseline using a novel loss masking strategy.

### [RLSplat](16575-rlsplat.md)
RLSplat is a resource-linear, budget-controllable feed-forward 3D Gaussian Splatting (FF3DGS) framework that generates exactly $B$ Gaussians from uncalibrated input images, ensuring that inference latency and peak memory scale linearly with the requested Gaussian budget. Unlike prior budget-controllable methods that predict a dense set of candidates and subsequently prune them—resulting in nearly constant computational cost regardless of the target budget—RLSplat learns a discrete allocation policy to distribute the budget across local scene regions and refines the resulting Gaussians via a resource-linear decoder with hierarchical neighbor search.

### [LGTM (Less Gaussians, Texture More)](17426-lgtm-less-gaussians-texture-more.md)
LGTM is a feed-forward framework that predicts compact 2D Gaussian primitives coupled with per-primitive texture maps to enable high-fidelity 4K novel view synthesis without per-scene optimization. It solves the quadratic growth in primitive count inherent to pixel-aligned feed-forward 3DGS methods, which makes high-resolution synthesis intractable due to memory and compute limits. Unlike standard 3DGS which couples appearance and geometry within each primitive, LGTM decouples them, allowing a compact set of geometric primitives to represent rich texture regions via per-primitive textures.

### [InfiniSplat v2](17642-infinisplat-v2.md)
InfiniSplat v2 is a feed-forward Gaussian reconstruction method for arbitrary input views that decouples geometry and attribute prediction, uses ground-truth (GT) camera poses for alignment during training, and employs large-angle target view supervision to improve rendering quality under large viewpoint changes. It differs from its sibling [DA3-GS](16423-da3-gs.md) by freezing the geometry branch to prevent geometric degradation caused by joint optimization, and from other feed-forward methods by using GT poses for alignment to avoid pose errors that misguide the network under large-angle supervision.

### [DepthSplat](18278-depthsplat.md)
DepthSplat is a feed-forward method for 3D Gaussian Splatting reconstruction that connects multi-view depth estimation with Gaussian rendering by leveraging pre-trained monocular depth features to augment multi-view feature matching. It solves the problem of robust depth prediction in challenging scenarios (occlusions, low-texture, non-Lambertian surfaces) where standard multi-view stereo fails, and scale ambiguities where monocular estimation fails, by fusing both signals early in the pipeline. Unlike TranSplat, which uses monocular features to refine coarse depth (vulnerable to error propagation), DepthSplat combines cost volumes and monocular features early, and unlike GS-LRM, it relies on explicit feature matching rather than heavy data-driven priors, making it significantly cheaper to train.

### [VG2GT](18425-vg2gt.md)
VG2GT is a feed-forward, non-pixel-aligned 3D Gaussian Splatting (3DGS) reconstruction framework that directly regresses geometrically accurate Gaussian scenes and camera parameters from an arbitrary number of unposed and uncalibrated images. It solves the problem of uneven Gaussian distributions and cross-view inconsistencies inherent in pixel-aligned methods by introducing a multi-scale differentiable voxel module that aggregates point-cloud features into a structured representation. Unlike siblings such as [AnySplat Pipeline](12847-anysplat-pipeline.md), which first regresses pixel-aligned primitives and then aggregates them, VG2GT directly decodes Gaussian primitives from structured voxel features, avoiding the intermediate pixel-aligned representation.

### [Direct Pixel-Wise Regression](18786-direct-pixel-wise-regression.md)
Direct Pixel-Wise Regression is a feed-forward method that predicts a set of 3D Gaussian primitives directly from input image patches, establishing a one-to-one correspondence between 2D pixels and 3D Gaussians. It differs from sibling methods like [Triplane-LRM](16746-feed-forward-generalizable-reconstruction.md) by avoiding fixed-resolution latent representations (e.g., triplanes), thereby enabling pixel-aligned prediction of per-Gaussian colors and scaling Gaussian count with input resolution to capture high-frequency details.

### [WildSplat](19321-wildsplat.md)
WildSplat is a feedforward 3D Gaussian Splatting framework designed for appearance-conditioned novel-view synthesis from sparse, unposed, in-the-wild images. It solves the problem of inconsistent photometric conditions (e.g., varying weather, lighting, or time of day) by explicitly decoupling geometry from appearance. Unlike sibling methods that assume photometric consistency or require precomputed poses, WildSplat jointly predicts camera poses, appearance-invariant 3D geometry, and reference-conditioned appearance attributes in a single forward pass.

### [StereoGaussians](19766-stereogaussians.md)
StereoGaussians is a feed-forward method that predicts a metric 3D Gaussian Splatting (3DGS) representation from a single calibrated stereo pair, enabling nearby-view extrapolation without per-scene optimization. It sets itself apart from its siblings by reusing intermediate representations from frozen pretrained stereo networks to predict Gaussian attributes, while calibrated disparity anchors the geometry. Unlike methods that synthesize images directly (e.g., LVSM) or refine inverse depth through a composer (e.g., SHARP), StereoGaussians uses explicit feed-forward multi-view Gaussian prediction with a second Gaussian layer and an expanded image canvas to provide capacity for disoccluded and outside-field-of-view content.

### [Latent Space Representation](19901-latent-space-representation.md)
Latent Space Representation methods map input images to a compact, structured latent code (tokens, features, or distributions) which is subsequently decoded into explicit 3D Gaussian primitives, enabling generalizable reconstruction without per-scene optimization [16746-feed-forward-generalizable-reconstruction.md]. Unlike sibling methods that predict Gaussians directly from pixel-wise features or cost volumes, this family explicitly models the scene as a set of learnable latent entities (e.g., tokens or entropy-coded features) to enforce global consistency, reduce representation bloat, or handle ambiguity [16746-feed-forward-generalizable-reconstruction.md].

### Sliding Window Large-scale Reconstruction
Use sliding windows to process the sequence and construct a unified large-scale Gaussian scene [S2, unofficial]. Successfully applied to a KITTI street sequence containing over 1,000 frames [S2, unofficial].

## Background
Feed-forward generalizable reconstruction emerged as a response to the high computational cost of per-scene optimization in 3D Gaussian Splatting. Early methods like SplatterImage utilized U-Net architectures to translate single-view images into Gaussian attributes, which could be extended to multi-view inputs via warping [S1, unofficial]. Subsequent works integrated cost volumes (e.g., MVSplat) and foundation models (e.g., MASt3R, VGGT) to improve geometric consistency and generalization across diverse scenes [S1, unofficial]. The field has since diversified into budget-controllable frameworks (RLSplat), texture-decoupled models (LGTM), and methods handling uncalibrated or wild inputs (WildSplat, AnySplat) [S1, unofficial].
