# Data Compression and Storage Optimization

Also called: 3DGS Compression, Gaussian Quantization, Codebook-based Compression

## Overview
This family of methods reduces the storage footprint and transmission bandwidth of 3D Gaussian Splatting models by compressing geometric attributes (position, scale, rotation), opacity, and view-dependent color (spherical harmonics coefficients) [S1, S2, unofficial]. It solves the problem of large model sizes (often hundreds of megabytes) which hinders deployment on resource-constrained devices or web streaming [S1, S2, unofficial]. Unlike sibling methods that focus on rendering speed via hardware acceleration or occupancy culling, these methods focus on data density, often trading minor reconstruction quality for significant size reduction (e.g., 10×–25×) [S1, S2, unofficial].

## Shared principles
All methods in this family operate on the set of $N$ 3D Gaussians $\{G_i\}_{i=1}^N$ defined in [Rendering Implementation and Acceleration](21069-rendering-implementation-and-acceleration.md). The core rendering operation involves projecting these 3D primitives to 2D screen space and performing alpha blending. Acceleration relies on the following shared mechanisms:

1.  **Tiling:** Dividing the image plane into non-overlapping tiles (commonly $16 \times 16$ pixels) to localize Gaussian processing and enable coalesced memory accesses [S2, unofficial].
2.  **Sorting:** Sorting Gaussians within each tile by view-space depth (front-to-back) to enable correct alpha blending [S2, unofficial].
3.  **Culling:** Discarding Gaussians that do not overlap with the camera frustum or specific tiles to reduce enumeration overhead [S2, unofficial].
4.  **Memory Hierarchy Management:** Exploiting the distinction between global memory (VRAM), shared memory (on-chip), and host memory (CPU RAM) to minimize data movement.

## Subtopics

### [ASCII-Based Data Compression](11820-ascii-based-data-compression.md)
A method for optimizing data transmission speed during training by encoding numerical attributes into compact ASCII strings. It differs from siblings by avoiding codebook lookups or neural field substitutions; instead, it relies on direct base-94/base-95 integer encoding of floating-point values to reduce payload size and improve I/O throughput.

### [Sensitivity-Aware Vector Clustering](12167-sensitivity-aware-vector-clustering.md)
A compression scheme that reduces storage requirements by clustering spherical harmonic (SH) coefficients and Gaussian shape parameters (scale and rotation) into compact codebooks using sensitivity-aware vector quantization. It distinguishes itself from standard post-training quantization by deriving a sensitivity measure for each parameter to guide the clustering process, prioritizing the preservation of parameters that significantly affect image quality.

### [Compact 3D Gaussian Representation (C3DGS)](12927-compact-3d-gaussian-representation-c3dgs.md)
A framework that reduces the storage footprint and rendering latency of 3D Gaussian Splatting by eliminating redundant primitives and compressing their attributes via spatial sharing. Unlike standard 3DGS, which stores high-precision per-Gaussian attributes, C3DGS exploits spatial redundancy by replacing per-primitive color data with a shared hash-based neural field and quantizing geometric attributes into a small codebook. This approach achieves over 25× storage compression and up to 40% faster rendering while maintaining or improving reconstruction quality.

### [Monte Carlo Specular Energy Aggregator](15439-monte-carlo-specular-energy-aggregator.md)
A compression technique that maps high-order (e.g., third-order) Spherical Harmonics (SH) radiance energy into a compact lower-order (e.g., first-order) subspace. It solves the problem of high memory overhead and inference latency associated with high-order SH on resource-constrained devices by extracting directional moments of the specular residual via Monte Carlo projection. Unlike distillation-based methods like Mobile-GS, MC-SEA preserves high-frequency specular features without requiring pre-training, distillation, or teacher-student models.

#### Sparse Adaptive Scalable Compact Gaussian Splatting
A compression method that utilizes vector clustering to encode color and geometric attributes [S1, unofficial].

#### 3DGS Quantization Compression
Reduces storage footprint of 3DGS scenes by quantizing per-Gaussian attributes and using codebooks, achieving ~10x smaller sizes without significant quality loss [S2, unofficial]. Per-Gaussian attribute storage layout includes: position (FP16), scales (FP16), opacity (INT8), and spherical harmonic coefficients (INT8 or codebook-based) [S2, unofficial].

## Background
The need for compression in 3D Gaussian Splatting arises from the high memory cost of storing per-Gaussian attributes, particularly high-order spherical harmonics coefficients [S1, unofficial]. Early works like C3DGS [56] and SASCGS [58] introduced codebook-based approaches and sensitivity-aware clustering to reduce redundancy [S1, unofficial]. Subsequent methods like LightGaussian [60] combined pruning with quantization and lossless compression for positions [S1, unofficial]. The field has evolved from simple quantization to complex hybrid approaches involving neural fields, Monte Carlo aggregation for specular details, and sensitivity-aware clustering to maintain visual fidelity while reducing size by 10× to 25× [S1, S2, unofficial].
