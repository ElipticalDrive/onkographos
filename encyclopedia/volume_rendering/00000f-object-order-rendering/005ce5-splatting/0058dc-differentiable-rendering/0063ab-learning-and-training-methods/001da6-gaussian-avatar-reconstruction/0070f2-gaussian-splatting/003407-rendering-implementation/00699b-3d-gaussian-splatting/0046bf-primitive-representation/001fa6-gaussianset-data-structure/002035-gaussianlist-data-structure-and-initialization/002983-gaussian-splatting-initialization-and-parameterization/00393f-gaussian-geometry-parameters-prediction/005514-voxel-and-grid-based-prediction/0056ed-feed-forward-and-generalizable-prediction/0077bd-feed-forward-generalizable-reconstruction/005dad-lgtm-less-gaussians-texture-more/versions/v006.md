# LGTM (Less Gaussians, Texture More)

Also called: Feed-Forward Prediction of Textured Gaussians, Feed-Forward Textured Splatting

## Overview
LGTM is a feed-forward framework that predicts compact 2D Gaussian primitives coupled with per-primitive texture maps, decoupling geometric complexity from rendering resolution to enable high-fidelity 4K novel view synthesis without per-scene optimization [S1, unofficial]. It solves the quadratic growth in primitive count as resolution increases in existing feed-forward 3DGS methods, which makes high-resolution synthesis (e.g., 4K) intractable due to memory and compute limits [S1, unofficial]. Unlike standard 3DGS which couples appearance and geometry within each primitive, LGTM decouples them, allowing a compact set of geometric primitives to represent rich texture regions via per-primitive textures [S1, unofficial].

## How it works
**Inputs and Outputs:**
The network $f$ takes a set of input images $\{I^v\}_{v=1}^N$ and their low-resolution counterparts $\{I^v_{low}\}_{v=1}^N$ as input. The output is a set of textured 2D Gaussians:
$$ f : (I^v, I^v_{low}) \rightarrow \{\mu_i, s_i, r_i, c_i, T^i_c, T^i_\alpha\} $$
where $\mu_i$ is the mean, $s_i$ is the scale, $r_i$ is the rotation, $c_i$ are the spherical harmonic (SH) coefficients, $T^i_c$ is the color texture map, and $T^i_\alpha$ is the alpha texture map for primitive $i$ [S1, unofficial].

**Data Structures:**
*   **Primitive Grid:** The primitive network predicts a grid of $h \times w$ 2DGS primitives, where $h \times w$ corresponds to the resolution of the low-resolution input $I^v_{low}$ [S1, unofficial].
*   **Per-primitive Texture Maps:** Each primitive $i$ has two texture maps:
    *   Color texture: $T^i_c \in \mathbb{R}^{T \times T \times 3}$
    *   Alpha texture: $T^i_\alpha \in \mathbb{R}^{T \times T}$
    *   $T$ is the resolution of the per-primitive texture maps, a tunable parameter trading off primitive size and texture size [S1, unofficial].
    *   $T^i_c$ is zero-initialized [S1, unofficial].

**Rendering Formulas:**
For a ray-splat intersection point $u$ on primitive $i$, the alpha value $a_i(u)$ and color $\hat{c}_i(u, d_i)$ are redefined using textures [S1, unofficial]:
$$ a_i(u) = o_i \cdot T^i_\alpha[u] $$
$$ \hat{c}_i(u, d_i) = T^i_c[u] + SH(c_i, d_i) $$
where $o_i$ is the base opacity, $d_i$ is the view direction, and $T[u]$ denotes bilinear sampling from the texture map at local coordinate $u$. The final pixel color $C$ is computed by alpha-blending contributions from all primitives sorted by depth [S1, unofficial]:
$$ C = \sum_i a_i(u_i) \hat{c}_i(d_i) \prod_{j=1}^{i-1} (1 - a_j(u_j)) $$

**Architecture and Steps:**
The architecture consists of two submodules: a primitive network $f_{prim}$ and a texture network $f_{texture}$ [S1, unofficial].

1.  **Primitive Network ($f_{prim}$):**
    *   Input: Low-resolution image $I^v_{low} \in \mathbb{R}^{h \times w \times 3}$.
    *   Process: Passes through a Vision Transformer (ViT) encoder-decoder.
    *   Output: Predicts primitive grid parameters $\{\mu_i, s_i, r_i, o_i, c_i\}$ and feature maps $F^{v}_{prim}$ [S1, unofficial].
    *   Supervision: High-resolution supervision is used. The network takes low-res inputs but renders and supervises at full resolution $H \times W$ to prevent holes and ensure anti-aliasing [S1, unofficial].

2.  **Texture Network ($f_{texture}$):**
    *   Input: High-resolution image $I^v$ and primitive features $F^{v}_{prim}$.
    *   Process:
        *   **Patch Features ($F^{v}_{patch}$):** Extracted from $I^v$ via image patchification and convolutions [S1, unofficial].
        *   **Projective Features ($F^{v}_{proj}$):** Computed by mapping source image pixels back to primitive local coordinates using the inverse transformation $M_{i,v}^{-1}$. For each primitive $i$, a projective prior texture is computed:
            $$ T^{c,proj}_i[u] = I^v[x] = I^v[M_{i,v}^{-1}(u)] $$
            Features are extracted from this projective prior to provide high-frequency appearance details [S1, unofficial].
        *   **Aggregation:** Features $F^{v}_{prim}$, $F^{v}_{patch}$, and $F^{v}_{proj}$ are aggregated to predict the final per-primitive texture maps $\{T^i_c, T^i_\alpha\}$ [S1, unofficial].

3.  **Training Strategy (Staged):**
    *   **Stage 1:** Pre-train the primitive network $f_{prim}$ in isolation to establish a robust geometric foundation using low-resolution inputs with high-resolution supervision. Loss: MSE + LPIPS [S1, unofficial].
    *   **Stage 2:** Jointly train $f_{prim}$ and $f_{texture}$. Freeze or reduce the learning rate of $f_{prim}$ by 0.1x to maintain geometric stability. The color texture $T^i_c$ is zero-initialized. Loss: MSE + LPIPS [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Memory Constraints:** Standard feed-forward methods fail to train at 2K or higher resolutions due to memory constraints (OOM). LGTM trains successfully at 2K and 4K using under 30 GB of memory [S1, unofficial].
*   **Holes in Rendering:** Without high-resolution supervision, predicted Gaussians may result in areas with holes as they are not anti-aliased. High-resolution supervision forces the network to learn proper coverage [S1, unofficial].
*   **Geometric Stability:** In Stage 2, the primitive network must be trained with a reduced learning rate (0.1x) to maintain geometric stability while the texture network learns appearance details [S1, unofficial].

## Operating characteristics
*   **Memory Usage:** LGTM trains successfully at 2K and 4K resolutions using under 30 GB of memory. In contrast, NoPoSplat fails to train at 2K or higher due to memory constraints (OOM), reaching 61.85 GB for a batch size of 1 at 1024x576 primitives [S1, unofficial].
*   **Scalability:** LGTM scales efficiently at inference; a 64x pixel increase adds only modest memory and time overhead [S1, unofficial].
*   **Performance:** Enables high-fidelity 4K novel view synthesis, a capability previously out of reach for feed-forward methods [S1, unofficial].
*   **Strengths:** Decouples geometry and appearance, allowing compact primitives to represent rich textures. Feed-forward, no per-scene optimization required. Versatile, operating with or without known camera poses (monocular, posed two-view, unposed two-view, multi-view) [S1, unofficial].
*   **Limitations:** Requires a dual-network architecture and staged training. Texture resolution $T$ is a tunable parameter that trades off primitive size and texture size [S1, unofficial].

## Background
LGTM was published as a conference paper at ICLR 2026 by Yixing Lao, Xuyang Bai, Xiaoyang Wu, Nuoyuan Yan, Zixin Luo, Jean-Daniel Nahmias, Yanghai Tsin, Shiwei Li, and Hengshuang Zhao from HKU and Apple [S1, unofficial]. It addresses the limitations of existing feed-forward 3D Gaussian Splatting methods, which suffer from quadratic growth in primitive count as resolution increases, and textured Gaussian methods that require per-scene optimization [S1, unofficial].
