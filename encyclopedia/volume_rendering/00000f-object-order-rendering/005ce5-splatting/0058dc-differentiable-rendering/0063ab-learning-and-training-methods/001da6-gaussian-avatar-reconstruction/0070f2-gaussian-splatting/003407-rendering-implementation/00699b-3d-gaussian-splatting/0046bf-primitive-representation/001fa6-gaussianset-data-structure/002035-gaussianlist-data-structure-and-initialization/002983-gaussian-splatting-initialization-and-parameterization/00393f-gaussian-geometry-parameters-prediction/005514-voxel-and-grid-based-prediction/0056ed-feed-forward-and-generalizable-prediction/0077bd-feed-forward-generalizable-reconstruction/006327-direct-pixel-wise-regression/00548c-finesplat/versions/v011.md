# FineSplat

Also called: Detailed Splats, Fine Patches, Local Groups

## Overview
FineSplat is a feed-forward 3D Gaussian Splatting framework that predicts a set of 3D Gaussians from $N$ context views (with or without known poses) using a two-stage dual-grouping strategy to balance local detail preservation with global multi-view reasoning [S1, unofficial]. It distinguishes itself from sibling methods like YoNoSplat and ZipSplat by using high-resolution 4x4 patch tokens instead of coarser 14x14 patches, combined with a serialized attention mechanism in 3D space to avoid the prohibitive cost of global multi-view attention [S1, unofficial]. This approach preserves fine-grained visual information while maintaining high efficiency, achieving superior quality per unit of time compared to explicit k-nearest-neighbor search or global attention baselines [S1, unofficial].

## How it works
FineSplat operates in two stages: view-wise token grouping (Stage 1) and 3D spatial token grouping with error feedback (Stage 2). It builds on the shared principles of feed-forward prediction, input normalization, feature encoding, and differentiable rendering [15832-feed-forward-and-generalizable-prediction.md].

### Inputs and Outputs
**Inputs:**
*   $N$ context images $I \in \mathbb{R}^{N \times H \times W \times 3}$.
*   Camera poses (optional, but used for normalization and ray unprojection).
*   Camera intrinsics (used for ray unprojection).

**Outputs:**
*   A set of 3D Gaussian primitives defined by mean $\mu$, covariance $\Sigma$ (parameterized by rotation $r$ and scale $s$), opacity $\alpha$, and spherical harmonics coefficients $c$.

### Data Structures
1.  **Tokens ($z$):** A set of $M$ fine-grained tokens, where $M = N \cdot \frac{H}{p} \cdot \frac{W}{p}$. Each token has dimension $d$.
2.  **Gaussian Primitives:** $K$ Gaussians predicted per token.
3.  **Error Feature Maps ($F^{err}$):** For each view, a feature map of size $\frac{H}{p} \times \frac{W}{p} \times d_e$ containing concatenated pixel and feature-level errors.

### Parameters
*   $p$: Patch size. Default: 4x4 pixels [S1, unofficial].
*   $T$: Number of iterative refinement steps in Stage 2. Default: 4 [S1, unofficial].
*   $K$: Number of Gaussian primitives predicted per token.
*   $S$: Size of groups for serialized attention in 3D spatial grouping (number of consecutive points along the space-filling curve) [S1, unofficial].
*   $s$: Sub-patch stride. Default: 2 (for 4x4 tokens divided into 2x2 sub-patches) [S1, unofficial].
*   $N$: Number of input context views. Training samples $N \in \{6, 12, 24, 32\}$ [S1, unofficial].

### Algorithm

#### Stage 1: View-Wise Token Grouping
1.  **Feature Extraction:** Encode input images using a Vision Transformer (e.g., DINOv2) or CNN to extract multi-scale features $F^l$ for $l \in \{1, 2, 3\}$, where $F^1$ is the finest scale and $F^3$ is the coarsest [S1, unofficial].
2.  **Token Initialization:** Fuse features into $M$ fine-grained tokens $z^{(0)}$ using Equation (1):
    $$ z^{(0)} = \text{fuse}\left(\text{up}\left(\text{fuse}\left(\text{up}(F^3) + F^2\right)\right)\right) + F^1 $$
    where $\text{up}(\cdot)$ is bilinear upsampling and $\text{fuse}(\cdot)$ is a convolutional fusion block [S1, unofficial].
3.  **View-Wise Attention:** Apply attention mechanisms within small view groups to exchange information across neighboring views in 2D space. This restricts the attention scope to keep computation affordable [S1, unofficial].

#### Stage 2: 3D Spatial Token Grouping and Refinement
This stage is repeated for $T$ steps (default $T=4$) [S1, unofficial].

1.  **Gaussian Prediction:** Decode each token $z$ into $K$ Gaussian primitives using a lightweight linear decoder head $\mathcal{D}$.
2.  **Patch-Aligned Sub-Pixel Gaussian Reconstruction:**
    *   Predict 4 Gaussians per 4x4 token, assigning each to a non-overlapping 2x2 sub-patch [S1, unofficial].
    *   Learn a 2D image-space offset $\Delta = (\Delta_x, \Delta_y)$ for each Gaussian.
    *   Bound the offset to ensure the Gaussian remains within its 2x2 sub-patch:
        $$ \delta_x = 2s \tanh(\Delta_x), \quad \delta_y = 2s \tanh(\Delta_y) $$
        where $s=2$ is the sub-patch stride. This ensures $\delta_x, \delta_y \in [-s/2, s/2]$ [S1, unofficial].
    *   Compute the displaced image coordinate $(u, v) = (u_c, v_c) + \delta$, where $(u_c, v_c)$ is the center of the sub-patch.
    *   Unproject $(u, v)$ using predicted camera intrinsics to get a ray direction. Transform and normalize this direction using camera-to-world rotation, using camera translation as the ray origin. This yields the 3D center $\mu$ for the Gaussian [S1, unofficial].
3.  **Error Feature Computation:**
    *   Render the predicted Gaussians into every context view $n$ to obtain rendered images $\hat{I}_n$.
    *   Compute the signed pixel error map $E_n = \hat{I}_n - I_n$ [S1, unofficial].
    *   Compute the feature-level difference $\Delta \phi_n = \phi(\hat{I}_n) - \phi(I_n)$ using a pretrained ResNet-18 encoder $\phi(\cdot)$ [S1, unofficial].
    *   Combine these with the finest-scale features $F_n^1$ from Stage 1 via linear embeddings $E_{err}$ and $E_{feat}$:
        $$ F_n^{err} = [E_{err}(E_n, \Delta \phi_n); E_{feat}(F_n^1)] \in \mathbb{R}^{\frac{H}{p} \times \frac{W}{p} \times d_e} $$
        where $[\cdot; \cdot]$ denotes concatenation [S1, unofficial].
4.  **Error Aggregation:**
    *   For each token, gather two error signals:
        *   $e_{self}$: The error feature from the patch where the token was predicted.
        *   $e_{agg}$: The average of error features over all context views in which the token is visible (including views outside the Stage 1 view group) [S1, unofficial].
5.  **3D Spatial Grouping (Serialized Attention):**
    *   Lift tokens to 3D space using their predicted Gaussian centers.
    *   Order tokens along a space-filling curve.
    *   Partition tokens into groups of $S$ consecutive points along the curve.
    *   Apply self-attention within each group to exchange information between geometrically related tokens in 3D space.
    *   Use four attention blocks, each using a different space-filling curve, so that each token meets a different set of neighbors [S1, unofficial].
    *   Update tokens:
        $$ \Delta z_j^{(i)} = \text{Linear}(\text{SerialAttn}(h_j^{(i)})) $$
        $$ z_j^{(i+1)} = z_j^{(i)} + \Delta z_j^{(i)} $$
        where $h_j^{(i)}$ is the aggregated error feature for token $j$ at step $i$ [S1, unofficial].
6.  **Re-decoding:** Decode the updated tokens $z^{(i+1)}$ into a new set of Gaussian primitives.

### Pseudocode

```python
def finesplat(context_images, context_poses, context_intrinsics, N):
    """
    context_images: List of N images, shape (H, W, 3)
    context_poses: List of N camera poses (4x4 matrices)
    context_intrinsics: List of N camera intrinsic matrices
    N: Number of context views
    """
    # 1. Feature Extraction (Stage 1)
    # Extract multi-scale features F^1, F^2, F^3 using ViT/CNN
    features = extract_features(context_images)
    
    # Fuse features into initial tokens z^(0)
    # M = N * (H/p) * (W/p), p=4
    z = fuse_features(features) 
    
    # View-wise attention within groups
    z = view_wise_attention(z, context_images)
    
    # 2. Iterative Refinement (Stage 2)
    for t in range(4): # T=4 steps
        # Decode Gaussians
        gaussians = decode_gaussians(z)
        
        # Render context views
        rendered_images = []
        for n in range(N):
            rendered = differentiable_render(gaussians, context_poses[n], context_intrinsics[n])
            rendered_images.append(rendered)
            
        # Compute Error Features
        error_features = []
        for n in range(N):
            # Pixel error
            E_n = rendered_images[n] - context_images[n]
            # Feature error using ResNet-18
            phi = pretrained_resnet18
            Delta_phi_n = phi(rendered_images[n]) - phi(context_images[n])
            # Finest scale features from Stage 1 (or current stage if re-extracted)
            F_n_1 = features[n][0] # Assuming F^1 is index 0
            
            # Embed and concatenate
            E_err_emb = linear_embed(E_n, Delta_phi_n)
            E_feat_emb = linear_embed(F_n_1)
            F_err_n = concat(E_err_emb, E_feat_emb)
            error_features.append(F_err_n)
            
        # Aggregate errors for each token
        # e_self: error from source patch
        # e_agg: average error from all visible views
        aggregated_errors = aggregate_errors(z, error_features, gaussians)
        
        # 3D Spatial Grouping
        # Lift tokens to 3D
        token_3d_positions = get_token_3d_positions(gaussians)
        
        # Order along space-filling curve (4 different curves for 4 blocks)
        for curve_idx in range(4):
            ordered_indices = sort_by_space_filling_curve(token_3d_positions, curve_idx)
            
            # Group into windows of size S
            groups = create_groups(ordered_indices, S)
            
            # Serialized Attention
            for group in groups:
                group_tokens = [z[i] for i in group]
                group_errors = [aggregated_errors[i] for i in group]
                # Self-attention within group
                updated_group = serialized_attention(group_tokens, group_errors)
                # Update z
                for idx, new_token in zip(group, updated_group):
                    z[idx] = new_token
                    
    # Final Gaussian Prediction
    final_gaussians = decode_gaussians(z)
    return final_gaussians

def decode_gaussians(z):
    """
    Decode tokens into Gaussians with sub-pixel offsets.
    """
    gaussians = []
    for token in z:
        # Predict 4 Gaussians per token
        for sub_patch_idx in range(4):
            # Predict offset delta
            delta_x, delta_y = predict_offset(token, sub_patch_idx)
            
            # Bound offset
            s = 2
            delta_x = 2 * s * tanh(delta_x)
            delta_y = 2 * s * tanh(delta_y)
            
            # Get sub-patch center (u_c, v_c)
            u_c, v_c = get_sub_patch_center(sub_patch_idx)
            
            # Displaced coordinate
            u = u_c + delta_x
            v = v_c + delta_y
            
            # Unproject to 3D
            # Use context view's camera parameters
            # This is simplified; in practice, each token is associated with a specific view
            # and the unprojection uses that view's intrinsics and pose.
            # For the sake of this pseudocode, we assume the token knows its source view.
            # The Gaussian head predicts mean, scale, rotation, opacity, SH.
            # The mean is refined by the sub-pixel offset.
            gaussian = create_gaussian_from_token(token, u, v)
            gaussians.append(gaussian)
    return gaussians
```

### Edge Cases and Pitfalls
*   **Scale Ambiguity:** Feed-forward reconstruction is scale-ambiguous. FineSplat handles this by normalizing scene scale using context camera poses: poses are expressed in the mean context camera frame, and translations are rescaled so that all context camera centers lie within $[-1, 1]^3$ [S1, unofficial].
*   **Blind Spots:** Fixed view grouping in Stage 1 leaves blind spots where fine-grained tokens in different groups cannot interact. Stage 2's 3D spatial grouping connects tokens across view groups once lifted to 3D [S1, unofficial].
*   **Precision:** The sub-pixel offset is bounded by $\tanh$ to ensure Gaussians stay within their 2x2 sub-patch, preventing invalid projections [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** FineSplat is efficient due to its dual-grouping strategy. Stage 1 uses local view-wise attention, and Stage 2 uses serialized attention with space-filling curves, which scales favorably with token count compared to explicit k-nearest-neighbor search or global attention [S1, unofficial].
*   **Memory Complexity:** Depends on the number of tokens $M$ and the number of Gaussians $K$. With 4x4 patches, $M$ is higher than coarser methods, but the serialized attention keeps memory usage manageable [S1, unofficial].
*   **Measured Performance:**
    *   **DL3DV (6 views):** 27.325 PSNR, 0.871 SSIM, 0.115 LPIPS using 62K Gaussians [S1, unofficial].
    *   **RE10K (6 views):** 27.394 PSNR, 0.886 SSIM, 0.116 LPIPS using 75K Gaussians [S1, unofficial].
    *   **Mip-NeRF 360 (128 views):** 23.463 PSNR, 0.706 SSIM, 0.214 LPIPS using 1.6M Gaussians [S1, unofficial].
*   **Scaling:** Quality improves gradually with more Stage 2 steps, but going beyond 4 steps yields no further gain [S1, unofficial]. Quality also improves with more context views, with Stage 2 providing larger gains as view count increases (e.g., 1.22 dB with 6 views vs 1.46 dB with 24 views) [S1, unofficial].
*   **Strengths:** High efficiency, strong quality with small primitive budget, robust to scale ambiguity, handles fine-grained details well.
*   **Limitations:** Requires known camera poses for normalization and ray unprojection (though poses can be predicted). Performance on Mip-NeRF 360 is lower than on DL3DV/RE10K, likely due to domain shift and higher complexity [S1, unofficial].
