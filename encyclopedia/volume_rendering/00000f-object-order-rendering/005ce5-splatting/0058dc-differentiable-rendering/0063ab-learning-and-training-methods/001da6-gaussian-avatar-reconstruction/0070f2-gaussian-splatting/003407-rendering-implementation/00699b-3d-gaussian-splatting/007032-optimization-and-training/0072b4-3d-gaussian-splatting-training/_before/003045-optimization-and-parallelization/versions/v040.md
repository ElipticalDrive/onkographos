# Optimization and Parallelization

Also called: Distributed Training, Per-Splat Backpropagation, Mask Gradient Computation

## Overview
This family encompasses methods that accelerate the training of 3D Gaussian Splatting (3DGS) by optimizing the computational efficiency of the backward pass, managing memory across multiple devices, and handling specialized gradient flows such as those for probabilistic masks. It solves the bottleneck where the $O(N \cdot P)$ complexity of differentiable rasterization (where $N$ is the number of Gaussians and $P$ is the number of pixels) limits scalability to large scenes or complex representations. It is distinguished from standard 3DGS training [9128-3d-gaussian-splatting-implementation-details.md] by explicitly restructuring data flow (per-splat vs. per-pixel), distributing state across GPU clusters [7349-grendel-gs.md], or computing gradients for auxiliary latent variables like masks [4254-maskgaussian-gradient-computation.md].

## Shared principles
The methods in this family share the following foundational mechanisms:

1.  **Differentiable Rasterization Core**: All methods rely on the differentiable alpha-blending rasterizer. The forward pass computes pixel color $\mathbf{c}(\mathbf{x})$ via depth-sorted alpha blending, and the backward pass computes gradients $\frac{\partial \mathcal{L}}{\partial \theta}$ with respect to Gaussian parameters $\theta$ [6233-optimization-and-parallelization].
2.  **Gradient Accumulation**: Gradients are accumulated over multiple training steps or views before an optimizer update. In distributed settings, gradients or intermediate rendering states are synchronized across devices [6233-optimization-and-parallelization].
3.  **Adaptive Representation**: Many optimization variants modify the Gaussian representation or its distribution to improve efficiency or fidelity, requiring corresponding adjustments to the gradient computation or data flow [6233-optimization-and-parallelization].
4.  **Hardware Acceleration**: Methods leverage GPU parallelism, often using CUDA kernels, Tensor Cores (via GEMM reformulation), or half-precision arithmetic to accelerate the rasterization and gradient computation [6233-optimization-and-parallelization].

## Subtopics

### [MaskGaussian Gradient Computation](4254-maskgaussian-gradient-computation.md)
A method for computing the gradient of the loss with respect to probabilistic masks $\mathcal{M}_i$ applied to 3D Gaussians. It solves the problem of backpropagating gradients through a masked alpha-blending process where the mask modulates opacity. It is distinguished from standard backpropagation by explicitly accounting for the gradient contribution of the mask on both the foreground Gaussian color accumulation and the background transmittance path.

### [Training Pipeline](5325-training-pipeline.md)
The iterative optimization loop for 3D Gaussian Splatting that initializes a set of 3D Gaussians and optimizes their parameters via gradient descent. It solves the problem of reconstructing a 3D scene from 2D observations by dynamically adapting the Gaussian representation through pruning, cloning, and splitting. It is distinguished by its core structure: a nested loop over spatial axes and slices that accumulates gradients across multiple views before a single optimizer step, coupled with periodic refinement phases.

### [Parallelization for Backpropagation](5989-parallelization-for-backpropagation.md)
A training optimization that replaces the standard per-pixel backward pass with a per-splat (per-Gaussian) approach. It solves the performance bottleneck of atomic contention in the per-pixel approach, where splats contributing to arbitrary numbers of pixels require frequent global memory synchronization. It yields a 4–5× reduction in training time while maintaining numerical equivalence to the original backpropagation.

### [Grendel-GS](7349-grendel-gs.md)
A distributed optimization framework for 3D Gaussian Splatting that partitions the Gaussian primitive list across multiple GPUs to overcome single-device memory limits. Unlike [TideGS](7350-tidegs.md), which streams data from disk on a single machine, Grendel-GS distributes the parameter table across a GPU cluster, enabling training on scenes with billions of primitives by leveraging inter-GPU communication.

### [3D Gaussian Splatting Implementation Details](9128-3d-gaussian-splatting-implementation-details.md)
Details the specific implementation parameters, optimization strategies, and training configurations required to reconstruct 3D Gaussian Splatting scenes. It addresses the core problem of balancing reconstruction fidelity with computational efficiency by defining hyperparameters for densification, pruning, and loss weighting. It sets itself apart by providing concrete values for thresholds, iteration intervals, and hardware-specific optimizations (such as half-precision rasterization).

## Background
The optimization of 3D Gaussian Splatting training emerged as the number of Gaussians required for high-fidelity reconstruction grew into the millions, exceeding the memory bandwidth and compute capabilities of single GPUs. Early implementations relied on the standard per-pixel backward pass, which suffered from severe warp divergence and atomic contention [5989-parallelization-for-backpropagation.md]. Subsequent work introduced per-splat backpropagation to align with GPU warp architectures [5989-parallelization-for-backpropagation.md]. As scenes scaled to city-scale or high-resolution datasets, single-GPU memory limits became a hard constraint, leading to distributed frameworks like Grendel-GS [7349-grendel-gs.md]. Additionally, extensions to the base method, such as MaskGaussian, required custom gradient derivations to handle latent mask variables [4254-maskgaussian-gradient-computation.md].
