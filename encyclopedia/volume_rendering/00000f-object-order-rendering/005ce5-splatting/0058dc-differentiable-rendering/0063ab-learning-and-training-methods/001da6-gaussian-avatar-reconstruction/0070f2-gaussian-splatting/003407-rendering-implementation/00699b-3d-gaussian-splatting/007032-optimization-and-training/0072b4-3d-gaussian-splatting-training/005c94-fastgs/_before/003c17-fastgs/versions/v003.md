# FastGS

Also called: Fast Gradient Checkpointing for 3DGS, Dynamic Sparse Rasterization for 3DGS

## Overview
FastGS re-engineers the 3D Gaussian Splatting training loop to accelerate optimization by combining dynamic sparse rasterization with fast gradient checkpointing [S1, unofficial]. It sets itself apart from standard training by skipping tiles with negligible transmittance during the forward pass and recomputing only necessary intermediate values during the backward pass, rather than storing all activations [S1, unofficial].

## How it works
FastGS modifies the core rasterization and memory management of the 3D Gaussian Splatting training pipeline [S1, unofficial].

**Inputs and Outputs:**
*   **Input:** A set of 3D Gaussians $\mathcal{G}$, camera poses, and training images.
*   **Output:** Optimized Gaussian parameters (position, scale, rotation, SH coefficients, opacity) and reduced training time.

**Data Structures:**
The method relies on the standard 3D Gaussian representation but optimizes the access patterns during rasterization [S1, unofficial].
*   **Tile Transmittance Map:** A per-tile boolean or float mask indicating whether a tile has significant transmittance (i.e., is not fully occluded or empty). This is computed dynamically during the forward pass.

**Steps:**
1.  **Dynamic Sparse Rasterization (Forward Pass):**
    *   For each training image, project all 3D Gaussians to screen space.
    *   Divide the image into tiles (e.g., $16 \times 16$ pixels).
    *   For each tile, compute the bounding box of all Gaussians covering it.
    *   Calculate the transmittance or coverage of the tile. If the transmittance is below a negligible threshold (effectively empty or fully occluded by background), mark the tile as "inactive" [S1, unofficial].
    *   Perform alpha-blending rasterization *only* for active tiles. Skip computation for inactive tiles [S1, unofficial].

2.  **Fast Gradient Checkpointing (Backward Pass):**
    *   During the backward pass, instead of storing all intermediate activation values from the forward pass (which consumes significant VRAM), store only a subset of checkpoints [S1, unofficial].
    *   Recompute the necessary intermediate values on-the-fly for the tiles that were active in the forward pass.
    *   Compute gradients $\frac{\partial \mathcal{L}}{\partial \theta}$ for the Gaussian parameters $\theta$ [S1, unofficial].

**Parameters:**
*   **Transmittance Threshold:** Not given in the sources. [G: Typically a small value like $10^{-4}$ or based on tile occupancy count.]
*   **Checkpoint Interval:** Not given in the sources. [G: Determined by the trade-off between memory usage and recomputation cost.]

**Pseudocode:**

    # Forward Pass with Dynamic Sparse Rasterization
    active_tiles = []
    rendered_images = []

        rendered_images.append(rendered_image)
        
        # Store active tile indices for backward pass
        active_tiles.append(get_active_tile_indices(tile_status))
        
    # Compute Loss
    loss = compute_loss(rendered_images, images)
    
    # Backward Pass with Fast Gradient Checkpointing
    # Instead of storing all activations, we recompute necessary parts
    # for active tiles only.
    
    # 1. Identify which forward computations need to be re-evaluated
    #    based on the active_tiles mask.
    
    # 2. Recompute forward activations for active tiles
    #    (This is done implicitly by the checkpointing mechanism)
    
    # 3. Compute gradients
    gradients = compute_gradients(loss, gaussians, active_tiles)

## Subtopics

### Accelerated Training for 3DGS
A strategy to improve training time efficiency by separating higher SH bands from the 0th band within the rasterizer, reducing the number of updates for higher SH bands compared to diffused colors [S2]. It modifies the rasterizer to split SH bands from the diffused color, updating SH bands every 16 iterations while updating diffused color at every step [S2]. It also optimizes SSIM loss calculation by replacing the standard 11x11 2D Gaussian kernel with two smaller 1D Gaussian kernels via a fused CUDA kernel [S2]. The total loss is defined as $L = (1 - \lambda_{SSIM})L_1 + \lambda_{SSIM} L_{D-SIM} + \lambda_m L_m + \lambda_{sh} L_{sh}$, where $L_m$ and $L_{sh}$ are defined in papers [11] and [13] respectively [S2].

### 128-bit Splat Data Structure
Restructures splat attributes (color, bounding box, position) into 128-bit aligned vectors to utilize optimized memory load instructions and reduce the total number of memory operations [S3]. The new structure consists of: Field 1: Color (4D float vector, 128 bits, padded from original 96-bit 3D float); Field 2: Bounding Box (4D unsigned integer vector, 64 bits, stored in pixel space using 16-bit unsigned integers); Field 3: Screen Position (2D float vector, 64 bits). The Bounding Box and Screen Position are packed to form a single 128-bit structure [S3]. This trades additional compute instructions required to unpack the data for further reductions in memory operation instructions [S3]. Using the original 96-bit 3D float vector for color does not have an optimized load instruction, leading to inefficient memory access [S3].

## Operating characteristics
*   **Time Complexity:** Reduced training time due to skipping inactive tiles and optimizing memory access patterns [S1, unofficial][S3].
*   **Memory Complexity:** Reduced VRAM usage due to gradient checkpointing, which stores fewer intermediate activations [S1, unofficial].
*   **Performance:** MMGS, which builds on these principles, achieves 10x accelerated training speed while maintaining rendering quality with only 10% primitives [S1, unofficial].
*   **Strengths:** Significant reduction in training time and memory footprint.
*   **Limitations:** Requires careful implementation of dynamic sparse rasterization and gradient checkpointing. The trade-off in 128-bit structure is increased compute instructions for unpacking [S3].

## Background
FastGS was introduced to address the high computational cost of 3D Gaussian Splatting training [S1, unofficial]. It re-engineers the training loop to finish optimization faster using dynamic sparse rasterization and fast gradient checkpointing [S1, unofficial]. The 128-bit data structure optimization is part of broader efforts to optimize memory access patterns in Gaussian Splatting rasterization [S3].
