# Gaussian Mixture Tree Construction

Also called: Hierarchically Merging Gaussians

## Overview
Gaussian Mixture Tree (GMT) Construction is a hierarchical post-processing method that organizes a flat set of 3D Gaussian primitives into a tree structure to identify distinct 3D plane instances in a scene [S1]. It solves the problem of spatial redundancy and semantic ambiguity in standard 3D Gaussian Splatting by grouping primitives that belong to the same planar surface [S1]. Unlike sibling methods that rely on spatial proximity graphs or fixed grid structures, GMT uses a probabilistic merging criterion based on the Bhattacharya distance and plane descriptor similarity to recursively build the hierarchy from leaf nodes to the root [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $N_s$ leaf nodes, where each leaf node $G_i$ represents a local cluster of Gaussian primitives (not raw primitives, to reduce computational cost) [S1]. Each node $G_i$ has parameters: mean $\boldsymbol{\mu}_i$, covariance $\boldsymbol{\Sigma}_i$, normal vector $\mathbf{n}_i \in \mathbb{R}^3$, and plane descriptor $\mathbf{z}_i \in \mathbb{R}^k$ (typically $k=3$) [S1].
*   **Output:** A Gaussian Mixture Tree $G^s$ containing parent nodes $G_{s_k}$ and a counter $L$ representing the number of merged plane nodes [S1].

**Data Structures:**
*   **Leaf Node:** A cluster of Gaussians summarized by a single Gaussian distribution $G(\boldsymbol{\mu}, \boldsymbol{\Sigma})$ augmented with $\mathbf{n}$ and $\mathbf{z}$ [S1].
*   **Tree Node:** Represents a merged Gaussian distribution $G_p(\boldsymbol{\mu}_p, \boldsymbol{\Sigma}_p)$ [S1].

**Parameters:**
*   $\epsilon_B$: Threshold for the Bhattacharya distance [S1].
*   $\epsilon_z$: Threshold for the difference in cosine similarity between plane descriptors ($1 - \langle \mathbf{z}_i \cdot \mathbf{z}_j \rangle \le \epsilon_z$) [S1].

**Formulas:**
1.  **Bhattacharya Distance:** Used to measure the similarity between two Gaussian distributions $G_i$ and $G_j$ [S1]:
    $$
    D_B(G_i, G_j) = \frac{1}{8}(\boldsymbol{\mu}_i-\boldsymbol{\mu}_j)^{T}\boldsymbol{\Sigma}^{-1}(\boldsymbol{\mu}_i-\boldsymbol{\mu}_j) + \frac{1}{2}\ln \left(\frac{\det \boldsymbol{\Sigma}}{\sqrt{\det \boldsymbol{\Sigma}_i \det \boldsymbol{\Sigma}_j}}\right)
    $$
    where $\boldsymbol{\Sigma} = (\boldsymbol{\Sigma}_i + \boldsymbol{\Sigma}_j)/2$ [S1].

2.  **Merging Rule:** When merging $G_i$ and $G_j$ into a parent node $G_p$, the new mean and covariance are calculated as [S1]:
    $$
    \boldsymbol{\Sigma}_p = \boldsymbol{\Sigma}_j \cdot (\boldsymbol{\Sigma}_i+\boldsymbol{\Sigma}_j)^{-1} \cdot \boldsymbol{\Sigma}_i
    $$
    $$
    \boldsymbol{\mu}_p = \boldsymbol{\Sigma}_j \cdot (\boldsymbol{\Sigma}_i+\boldsymbol{\Sigma}_j)^{-1} \cdot \boldsymbol{\mu}_i + \boldsymbol{\Sigma}_i \cdot (\boldsymbol{\Sigma}_i+\boldsymbol{\Sigma}_j)^{-1} \cdot \boldsymbol{\mu}_j
    $$
    [S1].

**Algorithm Steps:**
1.  Initialize $L = 0$ and the set of merged nodes $G = \emptyset$ [S1].
2.  Iterate $i$ from $1$ to $N_s$:
    a.  Check if node $i$ is already a descendant of any existing node in $G$. If yes, skip [S1].
    b.  Iterate $j$ from $i+1$ to $N_s$:
        i.  Check if node $j$ is already a descendant of any existing node in $G$. If yes, skip [S1].
        ii. Calculate $D_B(G_i, G_j)$ and the cosine similarity difference $1 - \langle \mathbf{z}_i \cdot \mathbf{z}_j \rangle$ [S1].
        iii. If $D_B(G_i, G_j) \le \epsilon_B$ AND $1 - \langle \mathbf{z}_i \cdot \mathbf{z}_j \rangle \le \epsilon_z$:
            1.  Compute $G_{ij}^p(\boldsymbol{\mu}_p, \boldsymbol{\Sigma}_p)$ using the merging formulas [S1].
            2.  Update $G_i \leftarrow G_{ij}^p$ [S1].
            3.  Break the inner loop (stop checking further $j$ for this $i$) [S1].
    c.  Insert the current $G_i$ into the result set $G^s$ [S1].
    d.  Increment $L \leftarrow L + 1$ [S1].

def merge_gaussians(node_i, node_j):
    """
    Merges two Gaussian nodes according to the GMT formula.
    """
    Sigma_i = node_i['Sigma']
    Sigma_j = node_j['Sigma']
    mu_i = node_i['mu']
    mu_j = node_j['mu']
    
    # Compute inverse of sum of covariances
    Sigma_sum = Sigma_i + Sigma_j
    inv_Sigma_sum = np.linalg.inv(Sigma_sum)
    
    # Compute Sigma_p
    Sigma_p = Sigma_j @ inv_Sigma_sum @ Sigma_i
    
    # Compute mu_p
    term1 = Sigma_j @ inv_Sigma_sum @ mu_i
    term2 = Sigma_i @ inv_Sigma_sum @ mu_j
    mu_p = term1 + term2
    
    # Plane descriptor and normal vector for the parent are not explicitly defined in the source for the merge step.
    # [G] Typically, these might be averaged or weighted, but the source does not specify. 
    # We return a node with updated mu and Sigma. The z and n fields would need a strategy 
    # (e.g., weighted average) not provided in the text. For strict adherence, we only return mu and Sigma.
    return {'mu': mu_p, 'Sigma': Sigma_p}

def calculate_bhattacharya(node_i, node_j):
    Sigma_i = node_i['Sigma']
    Sigma_j = node_j['Sigma']
    mu_i = node_i['mu']
    mu_j = node_j['mu']
    
    Sigma_avg = (Sigma_i + Sigma_j) / 2.0
    diff = mu_i - mu_j
    
    inv_Sigma_avg = np.linalg.inv(Sigma_avg)
    
    term1 = 0.125 * diff.T @ inv_Sigma_avg @ diff
    
    det_Sigma_avg = np.linalg.det(Sigma_avg)
    det_Sigma_i = np.linalg.det(Sigma_i)
    det_Sigma_j = np.linalg.det(Sigma_j)
    
    term2 = 0.5 * np.log(det_Sigma_avg / np.sqrt(det_Sigma_i * det_Sigma_j))
    
    return term1 + term2

def cosine_similarity(vec1, vec2):
    norm1 = np.linalg.norm(vec1)
    norm2 = np.linalg.norm(vec2)
    if norm1 == 0 or norm2 == 0:
        return 0.0
    return np.dot(vec1, vec2) / (norm1 * norm2)

**Edge Cases and Pitfalls:**
*   **Leaf Node Selection:** Raw Gaussian primitives are not used as leaf nodes due to computational expense; they must be pre-clustered into local clusters [S1].
*   **Descriptor Learning:** The plane descriptors $\mathbf{z}$ and normal vectors $\mathbf{n}$ are learned during optimization using losses derived from 2D normal maps (via Omnidata) and 2D SAM masks, respectively [S1]. If these are not available, the merging criterion cannot be fully applied.
*   **Order Dependence:** The algorithm iterates $i$ from $1$ to $N_s$ and breaks the inner loop upon the first merge. This greedy approach means the final tree structure depends on the initial ordering of the leaf nodes [S1].

## Operating characteristics
*   **Time Complexity:** The algorithm involves nested loops over $N_s$ leaf nodes, resulting in $O(N_s^2)$ comparisons in the worst case. Each comparison involves matrix inversion and determinant calculation for $3 \times 3$ matrices, which is constant time but expensive.
*   **Memory Complexity:** Stores the tree structure and the parameters for each node.
*   **Strengths:** Explicitly identifies distinct 3D plane instances, enabling higher-level scene understanding and potentially more efficient rendering by grouping planar surfaces [S1].
*   **Limitations:** Computationally expensive due to the quadratic merging process and the need for pre-clustering and descriptor learning [S1].

## Background
The Gaussian Mixture Tree was introduced in "Planar Gaussian Splatting" (WACV 2025) to address the limitation of standard 3D Gaussian Splatting, where optimized Gaussians tend to cluster near object surfaces without explicit semantic or structural organization [S1]. The method uses a probabilistic approach to model the 3D scene hierarchically, leveraging Gaussian Mixture Models to join nodes and derive parent nodes, thereby representing the scene in a way that highlights individual 3D plane instances [S1].
