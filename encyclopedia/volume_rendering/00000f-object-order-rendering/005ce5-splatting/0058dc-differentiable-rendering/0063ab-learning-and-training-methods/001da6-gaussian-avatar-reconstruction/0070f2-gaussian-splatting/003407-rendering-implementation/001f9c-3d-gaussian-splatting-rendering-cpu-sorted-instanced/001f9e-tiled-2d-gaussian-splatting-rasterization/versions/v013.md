# Tiled 2D Gaussian Splatting Rasterization

Also called: 3D Gaussian Splatting Rasterization, Tile-based Gaussian Rasterization, Tiled Rendering of 3DGS, 3DGS Rasterization, Gaussian Rasterization (GPU)

## Overview
Tiled 2D Gaussian Splatting Rasterization is a GPU-accelerated, differentiable rendering method for 3D Gaussian Splatting (3DGS) that partitions the image plane into macro-tiles to efficiently composite millions of 2D Gaussian splats [S1, S2, S8, unofficial]. It solves the performance bottleneck of per-pixel sorting and redundant evaluation by assigning a CUDA thread block to each tile, where threads cooperatively fetch pre-sorted Gaussians and perform iterative alpha blending [S1, S7, unofficial]. It sets itself apart from its parent [3D Gaussian Splatting Rendering (CPU-Sorted, Instanced)](2058-3d-gaussian-splatting-rendering-cpu-sorted-instanced.md) by moving the sorting and blending logic entirely to the GPU for real-time performance, and from [Gaussian Splat Rendering (Screen-Space Quad)](2075-gaussian-splat-rendering-screen-space-quad.md) by using explicit tile-based memory management and shared memory synchronization rather than standard graphics pipeline blending [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** 3D Gaussian parameters (means $\mathbf{x}$, opacities $\alpha$, scales $\mathbf{s}$, rotations $\mathbf{r}$, spherical harmonics coefficients $\mathbf{c}$), camera matrices (view $V$, projection $P$), image dimensions ($W, H$), and tile configuration.
*   **Outputs:** Rendered color image $\mathbf{C}$, radii (bounding box sizes for culling), and auxiliary buffers (depth, normals, transmittance) for differentiable training [S1, S5, S8, unofficial].

**Data Structures:**
The method relies on three primary state buffers allocated on the GPU [S7, S8, unofficial]:
1.  **GeometryState:** Per-Gaussian buffers.
    *   `depths`: float, size $P$ (number of Gaussians).
    *   `means2D`: float2, size $P$ (screen-space coordinates).
    *   `cov3D`: float, size $P \times 6$ (symmetric 3D covariance matrix elements).
    *   `conic_opacity`: float4, size $P$ (inverse 2D covariance + opacity).
    *   `rgb`: float, size $P \times 3$ (precomputed or SH-evaluated colors).
    *   `tiles_touched`: uint32_t, size $P$ (count of tiles intersected).
    *   `point_offsets`: uint32_t, size $P$ (start index in the flattened tile list).
2.  **BinningState:** Sorting buffers.
    *   `point_list_keys`: uint64_t, size $P$ (encoded tile ID + Gaussian index).
    *   `point_list_keys_unsorted`: uint64_t, size $P$.
    *   `list_sorting_space`: char*, size $S_{sort}$ (temporary space for radix sort).
3.  **ImageState:** Per-pixel/tile buffers.
    *   `accum_alpha`: float, size $W \times H$.
    *   `n_contrib`: uint32_t, size $W \times H$.
    *   `ranges`: uint2, size $N_{tiles}$ (start/end indices for each tile in the sorted list).

**Steps:**

1.  **Preprocessing and Projection:**
    For each Gaussian $i$:
    *   Transform mean $\mathbf{x}_i$ to camera space: $\mathbf{x}'_i = V \mathbf{x}_i$.
    *   Rotate 3D covariance $\Sigma_i$ to camera space: $\Sigma'_i = R V \Sigma_i V^T R^T$, where $R$ is the rotation part of $V$ [S9, unofficial].
    *   Compute 2D projection covariance $\Sigma^{2D}_i$ using the Jacobian $J$ of the perspective projection and a viewport transformation $W$ [S1, S9, unofficial]:
        $$ \Sigma^{2D}_i = W J \Sigma'_i J^T W^T $$
    *   Compute the 2D conic matrix (inverse covariance) $\mathbf{C}_i = (\Sigma^{2D}_i)^{-1}$ and the opacity $\alpha_i$ using the sigmoid of the log-opacity logit $o_i$:
        $$ \alpha_i = \sigma(o_i) \exp\left(-\frac{1}{2} (\mathbf{p} - \boldsymbol{\mu}_i)^T \mathbf{C}_i (\mathbf{p} - \boldsymbol{\mu}_i)\right) $$
        Note: The opacity term is often separated into a constant part $\sigma(o_i)$ and the spatial decay [S10, unofficial].
    *   Compute the bounding radius $r_i$ (typically $3\sqrt{\lambda_{max}}$) and axis-aligned bounding box (AABB) in screen space [S9, unofficial].

2.  **Frustum Culling and Tile Binning:**
    *   Discard Gaussians outside the camera frustum or with radius 0 [S4, S9, unofficial].
    *   Assign each surviving Gaussian to all tiles it intersects. Two strategies exist:
        *   **SnugBox:** Assign to tiles intersecting the AABB defined by the bounding circle [S1, unofficial].
        *   **AccuTile:** Assign only if the tile intersects the actual ellipse, computed by iterating over the shorter side of the tile extent [S1, unofficial].
    *   Generate a 64-bit key for each Gaussian-tile pair: `(tile_id << 32) | gaussian_index`. The key encodes the tile ID and the depth (view-space Z) of the Gaussian for sorting [S8, unofficial].

3.  **Sorting:**
    *   Perform a device-side radix sort on the keys to group Gaussians by tile and sort them front-to-back (by depth) within each tile [S1, S7, unofficial].
    *   Compute a prefix sum (inclusive scan) of the `tiles_touched` counts to determine the `point_offsets` for each Gaussian in the flattened sorted list [S7, unofficial].
    *   Identify the start and end indices (`ranges`) for each tile in the sorted array [S8, unofficial].

4.  **Tile-Based Rasterization (Forward Pass):**
    *   Launch a CUDA kernel where each thread block corresponds to one tile. Let tile dimensions be $B_X \times B_Y$ (default 16x16 or 32x32) [S1, S9, unofficial].
    *   Each thread $i$ in the block corresponds to a pixel $P_i$ within the tile.
    *   **Shared Memory Loading:** Threads cooperatively load Gaussians from the global sorted list into shared memory `Shmem`. Since Gaussians are sorted by depth, they are fetched in front-to-back order [S2, unofficial].
    *   **Alpha Blending:** For each pixel $P_i$, accumulate color $\mathbf{C}_i$ and transmittance $T_i$:
        $$ \mathbf{C}_i = \sum_{k=1}^{N} \mathbf{c}_k \alpha_k \exp\left(-\frac{1}{2} \mathbf{d}_k^T \mathbf{C}_k \mathbf{d}_k\right) \prod_{j=1}^{k-1} \left(1 - \alpha_j \exp\left(-\frac{1}{2} \mathbf{d}_j^T \mathbf{C}_j \mathbf{d}_j\right)\right) $$
        where $\mathbf{d}_k = P_i - \boldsymbol{\mu}_k$ is the vector from the pixel to the Gaussian mean [S1, S10, unofficial].
    *   **Early Termination:** If the accumulated transmittance $T < \epsilon$ (e.g., $10^{-4}$), stop processing further Gaussians for that pixel [S1, unofficial].
    *   Synchronize threads within the block to ensure all pixels have access to the necessary Gaussians in shared memory [S2, unofficial].

5.  **Gradient Computation (Backward Pass):**
    *   Gradients flow from the loss $L$ through the blending equation.
    *   For each Gaussian $k$, gradients for color $\mathbf{c}_k$ and opacity $\alpha_k$ are accumulated across all affected pixels using `atomicAdd` [S1, unofficial].
    *   Gradients for screen-space means $\boldsymbol{\mu}^{2D}$ are computed and must be retained for backpropagation to 3D means [S4, S5, unofficial].

def mahalanobis_distance(u: torch.Tensor, v: torch.Tensor, conic: torch.Tensor) -> float:
    """
    Computes u^T * C * v
    """
    diff = u - v
    # conic is 2x2 matrix
    return diff[0]**2 * conic[0,0] + 2 * diff[0] * diff[1] * conic[0,1] + diff[1]**2 * conic[1,1]

### Mobile-GS
A memory-centric rendering design for smartphones that loads only the Gaussians visible in the current view frustum from flash storage, uses a quantized integer representation for positions and colors, and performs the blending in a lower-precision shader [S1, unofficial].

### 4D Gaussian Splatting Motion Evaluation
A technique for rendering time-varying 3D captures (volumetric video) by storing static per-splat attributes and per-splat motion coefficients in extra textures, evaluated in the vertex shader from a time uniform, avoiding per-frame CPU sorting and texture uploads [S13, unofficial].
1. Store static per-splat attributes (position, scale, rotation, color) in standard splat buffers.
2. Store per-splat motion coefficients (linear or polynomial trajectory parameters) and temporal opacity window parameters in extra textures.
3. Pass the current playback time as a uniform to the vertex shader.
4. In the vertex shader, evaluate the motion coefficients against the time uniform to compute the current position and opacity for each splat.
5. Perform sorting only occasionally, as motions are assumed to be small enough to not require per-frame sorting for visual correctness [S13, unofficial].

### AABB Culling for Gaussian Splatting
A culling technique that uses an axis-aligned bounding box of the projected Gaussian ellipse to reduce ineffective rendering expenses, specifically addressing the inability of bounding circles to cull low-opacity pairs in the minor axis direction [S14].
1. Set the partial derivatives to 0 to find extrema.
2. Substitute the coordinate relationships into the ellipse function to solve for the maximum coordinate values $x_{max}$ and $y_{max}$.
3. Cull tiles based on the axis-aligned bounding box constructed by $x_{max}$ and $y_{max}$, which correspond to the half-width $w$ and half-height $h$ of the bounding box [S14].

### Adaptive Region Selection
A rendering strategy for novel viewpoints that prioritizes local Gaussians with higher contributions to avoid floating artifacts and holes [S15].
1. Train a coarse global Gaussian representation by downsampling point clouds and images and avoiding densification.
2. Render novel viewpoint using local and global Gaussians separately.
3. Calculate matching score $S$ for each local-global Gaussian pair: $S = (1 - \lambda)L1 + \lambda \cdot LSSIM$.
4. Sort local Gaussians in descending order based on matching scores.
5. Calculate projection opacity $o_i(p)$ for each pixel $p$ and Gaussian $G_i$.
6. Apply weighted blending:
   $$ w_i = o_i(p) \prod_{j=1}^{i-1} (1 - o_j(p)) \quad \text{if} \quad \sum_{j=1}^{i-1} o_j(p) < \beta $$
   $$ w_i = 0 \quad \text{if} \quad \sum_{j=1}^{i-1} o_j(p) \ge \beta $$
   where $\beta$ is a hyperparameter threshold for overlapped opacity [S15].

### Efficient Rendering (Gaussians Cache)
Decomposition of Gaussian generation and novel view splatting to enable real-time rendering at high frame rates (≥ 100 FPS) [S16].
1. Generate and cache all Gaussian points in the scene using the Gaussians Cache.
2. For a query view, retrieve corresponding Gaussians by utilizing nearby reference images' IDs [S16].

### Spatial Partitioning and List Organization
Grouping projected Gaussians into lists for pixel threads to traverse, balancing between list count/reuse and invalid evaluations [S17, unofficial].
*   **Pitfall:** Tile-list imbalance persists across all tested tile sizes [S17, unofficial].
*   **Metrics:** Fine tiles raise $N_{pair}$ (number of pairs/associations) and coarse tiles raise $N_{eval}$ (number of evaluations), while $N_{blend}$ changes little [S17, unofficial].
*   **Comparison:** Large tiles create fewer lists/tasks and improve reuse but include more Gaussians outside individual pixel footprints; fine tiles reduce invalid evaluations at the cost of more lists and scheduling. HiGS uses macro tiles for partitioning/sorting and finer tiles for rasterization. Seele combines view-dependent preprocessing with contribution tests during rasterization to reduce invalid evaluation on mobile GPUs [S17, unofficial].

### FlashGS Precise Intersection Algorithm
An optimization for 3D Gaussian Splatting that reduces redundant computations by incorporating Gaussian opacity into the ellipse boundary definition and using a two-stage filtering process (tight bounding box then exact intersection) to determine which tiles a Gaussian covers [S18].

### Coherent Raster Subpixel-Level Rasterization
A rasterization pipeline that operates at subpixel granularity to synthesize an interlaced light-field image directly, avoiding per-view image generation [S11].
1. **Projection:** For each viewpoint $v_j$, project every Gaussian $G_i$ to get 2D mean $\boldsymbol{\mu}_{i,j}^{2D}$, covariance $\boldsymbol{\Sigma}_{i,j}^{2D}$, depth $d_{i,j}$, and color $\mathbf{c}_{i,j}$.
2. **Key Generation:** Determine overlapping tiles for each projected Gaussian per viewpoint. Assign a key consisting of tile ID, viewpoint ID $j$, and view-space depth $d_{i,j}$.
3. **Sorting:** Sort Gaussian-tile pairs by depth independently for each tile and viewpoint. Store results in a unified contiguous Gaussian list ordered by tile ID and viewpoint ID.
4. **Alpha Blending:** Traverse subpixels in row-major order. For subpixel $(x, y, u)$, load the splat sequence matching its tile index and viewpoint index $V[x, y, u]$. Accumulate contributions front-to-back via alpha blending to produce final image $I_{\text{LFD}}$.
*   **Pitfall:** Naive subpixel-level pipeline suffers from redundant per-view evaluation and uncoalesced memory access due to interlaced layout [S11].

## Operating characteristics
*   **Time Complexity:** $O(N \log N)$ for sorting $N$ Gaussians, followed by $O(P \cdot K)$ for rasterization, where $P$ is the number of pixels and $K$ is the average number of Gaussians per tile. The radix sort is highly optimized on GPU [S1, S7, unofficial].
*   **Memory Complexity:** $O(N + W \cdot H)$ for storing Gaussian attributes and image buffers. Shared memory usage is $O(B_X \cdot B_Y)$ per tile block [S1, S8, unofficial].
*   **Performance:** Achieves real-time rendering (60+ FPS) for scenes with millions of Gaussians on modern GPUs (e.g., RTX 3090) at 1080p resolution [S1, unofficial].
*   **Strengths:** Differentiable, supports arbitrary camera poses, handles view-dependent appearance via SH, and scales well with scene size due to tile-based culling [S1, S3, unofficial].
*   **Limitations:** Restricted to pinhole cameras; cannot compute arbitrary light paths (e.g., reflections, shadows) without extensions [S12]. Performance degrades if tiles are heavily overloaded with Gaussians (overdraw) [S12].
*   **When to Use:** Real-time rendering, training of 3DGS scenes, novel view synthesis.
*   **When Not to Use:** Scenes requiring complex lighting effects (shadows, reflections) without additional passes, or on hardware without sufficient shared memory bandwidth [S12].

## Background
Tiled 2D Gaussian Splatting Rasterization was introduced as part of the original 3D Gaussian Splatting paper by Kerbl et al. (2023) [S1, unofficial]. It was designed to overcome the limitations of previous radiance field methods (like NeRF) and earlier Gaussian splatting implementations that were either too slow for real-time or lacked differentiability for training. The method builds on the concept of splatting 3D Gaussians into 2D ellipses but optimizes the compositing step using tile-based parallelism on the GPU [S1, S10, unofficial]. It has since become the standard rasterization backend for most 3DGS implementations and extensions [S4, S10, unofficial].
