# Gaussian Primitive Training Schedule

Also called: Reduced Iteration Schedule, Two-Phase Training Schedule

## Overview
This method defines a specific training schedule for 3D Gaussian Splatting that significantly reduces the total number of optimization iterations required to converge, leveraging dense initial point cloud initialization. It solves the problem of excessive training time in conventional 3D Gaussian Splatting by splitting the process into two phases with intermediate depth optimization. It is distinguished from the standard [3D Gaussian Splatting Training Loop](15139-3d-gaussian-splatting-training-loop.md) by its reduced iteration count (~6,000 vs. ~300,000) and the insertion of a pseudo-view rendering and depth optimization step between the two training phases.

## How it works
The method modifies the standard optimization loop by adjusting the iteration count, densification frequency, and inserting an intermediate refinement step.

**Inputs:**
*   Initial set of 3D Gaussians $\mathcal{G}$ derived from a sufficiently dense point cloud (e.g., from SfM or a depth estimator like DUSt3R).
*   Training dataset of images and camera poses.
*   Pseudo-view generation parameters (camera poses for synthetic views).

**Outputs:**
*   Optimized set of 3D Gaussians $\mathcal{G}_{final}$.

**Data Structures:**
*   $\mathcal{G}$: List of Gaussian primitives. Each primitive $i$ contains position $\mathbf{p}_i$, covariance $\Sigma_i$ (or rotation $\mathbf{q}_i$, scale $\mathbf{s}_i$), opacity $\alpha_i$, and SH coefficients $\mathbf{c}_{i, l}$.
*   `iteration`: Integer counter for the current training step.

**Parameters:**
*   `phase1_iters`: 3,000 (iterations for the first training phase).
*   `phase2_iters`: 3,000 (iterations for the second training phase).
*   `densify_start`: 1,500 (iterations before densification begins).
*   `densify_freq`: 500 (iterations between densification steps).
*   `total_iters`: 6,000.

**Steps:**
1.  **Initialization:** Initialize $\mathcal{G}$ from a dense point cloud. Set `iteration` = 0.
2.  **Phase 1 Training:**
    *   While `iteration` < `phase1_iters`:
        *   Sample a training view.
        *   Render the view using the current $\mathcal{G}$ [S1].
        *   Compute loss $\mathcal{L}$ (standard photometric loss) [S1].
        *   Backpropagate and update $\mathcal{G}$ using Adam optimizer [S1].
        *   Increment `iteration`.
        *   **Densification Check:** If `iteration` >= `densify_start` and `iteration` % `densify_freq` == 0:
            *   Apply densification strategy (splitting/pruning) based on gradient magnitudes and opacity [S1].
3.  **Intermediate Depth Optimization:**
    *   Generate "pseudo views" (synthetic camera poses) [S1].
    *   Render RGB images for these pseudo views using the current $\mathcal{G}$ [S1].
    *   Perform depth optimization for these pseudo views. This step refines the geometry by optimizing depth consistency for the synthetic views [S1].
4.  **Phase 2 Training:**
    *   While `iteration` < `total_iters`:
        *   Sample a training view.
        *   Render the view using the updated $\mathcal{G}$ [S1].
        *   Compute loss $\mathcal{L}$ [S1].
        *   Backpropagate and update $\mathcal{G}$ [S1].
        *   Increment `iteration`.
        *   **Densification Check:** If `iteration` >= `densify_start` and `iteration` % `densify_freq` == 0:
            *   Apply densification strategy [S1].

**Pseudocode:**
```python
def train_gaussian_schedule(G, training_data, pseudo_view_poses, densify_fn):
    iteration = 0
    phase1_iters = 3000
    phase2_iters = 3000
    densify_start = 1500
    densify_freq = 500
    total_iters = phase1_iters + phase2_iters

    # Phase 1
    while iteration < phase1_iters:
        view = sample_view(training_data)
        rendered_img = render(G, view)
        loss = compute_loss(rendered_img, view.gt_image)
        G = update_params(G, loss)
        iteration += 1
        
        if iteration >= densify_start and iteration % densify_freq == 0:
            G = densify_fn(G, iteration)

    # Intermediate Depth Optimization
    for pose in pseudo_view_poses:
        pseudo_view = create_view(pose)
        rendered_pseudo = render(G, pseudo_view)
        # Depth optimization step: refine G based on pseudo view depth consistency
        depth_loss = compute_depth_loss(rendered_pseudo, pseudo_view)
        G = update_params(G, depth_loss)

    # Phase 2
    while iteration < total_iters:
        view = sample_view(training_data)
        rendered_img = render(G, view)
        loss = compute_loss(rendered_img, view.gt_image)
        G = update_params(G, loss)
        iteration += 1
        
        if iteration >= densify_start and iteration % densify_freq == 0:
            G = densify_fn(G, iteration)

    return G
```

**Edge Cases and Pitfalls:**
*   **Initialization Quality:** The method relies on "sufficiently dense point clouds" for initialization. Poor initialization may prevent convergence within the reduced iteration count [S1].
*   **Densification Timing:** Densification is disabled for the first 1,500 iterations to allow the initial dense cloud to stabilize [S1].
*   **Pseudo View Generation:** The quality of the depth optimization depends on the selection of pseudo views. The source does not specify the exact algorithm for generating these poses [S1].

## Subtopics

### [CompGS Training Loop](19915-compgs-training-loop.md)
The CompGS training loop is the optimization procedure for 3D Gaussian Splatting that incorporates auxiliary parameters and adaptive control mechanisms to refine Gaussian primitives.

## Operating characteristics
*   **Time Complexity:** Significantly reduced compared to standard 3D Gaussian Splatting. Requires ~6,000 total iterations versus ~300,000 for conventional methods [S1].
*   **Memory Complexity:** Similar to standard 3D Gaussian Splatting, as the number of Gaussians is determined by the initial dense cloud and densification strategy, not the iteration count [S1].
*   **Hardware:** Experiments conducted on NVIDIA RTX 4090 GPU [S1].
*   **Strengths:** Drastic reduction in training time while maintaining satisfactory results [S1].
*   **Limitations:** Relies on high-quality initial dense point clouds. The intermediate depth optimization step adds complexity to the pipeline [S1].

## Background
This method is described in the context of Generative Bundle Refinement (GBR) for high-fidelity Gaussian Splatting with enhanced mesh reconstruction. It addresses the computational bottleneck of standard 3D Gaussian Splatting by leveraging dense initialization and a two-phase training schedule with intermediate depth refinement. The approach combines DUSt3R for initialization with Gaussian Splatting-based surface reconstruction [S1].
