# DepthSplat


## Overview
DepthSplat is a feed-forward method for 3D Gaussian splatting reconstruction that connects Gaussian splatting and depth estimation by leveraging pre-trained monocular depth features to augment multi-view feature matching [S1]. It solves the problem of artifacts and scale ambiguities in multi-view depth prediction, enabling robust reconstruction from sparse input views [S1]. Unlike TranSplat, which uses monocular features to refine coarse depth (vulnerable to error propagation), DepthSplat combines cost volumes and monocular features early in the pipeline [S1]. Unlike methods like GS-LRM that rely heavily on training data and discard explicit feature matching, DepthSplat uses feature matching and is cheaper to train [S1].

## How it works
**Inputs:** $N$ input images $\{I_i\}_{i=1}^N$ with corresponding projection matrices $\{P_i\}_{i=1}^N$, where $I_i \in \mathbb{R}^{H \times W \times 3}$ and $P_i \in \mathbb{R}^{3 \times 4}$ [S1].

**Outputs:** A set of 3D Gaussians $\{(\mu_j, \alpha_j, \Sigma_j, c_j)\}_{j=1}^{H \times W}$ for each image, where $\mu_j$ is the position, $\alpha_j$ is the opacity, $\Sigma_j$ is the covariance, and $c_j$ is the color [S1].

**Data Structures:**
*   **Cost Volume $C_i$:** A 3D tensor of size $\frac{H}{s} \times \frac{W}{s} \times D$, where $s$ is the downsampling factor and $D$ is the number of depth candidates [S1].
*   **Monocular Features:** Extracted per-view features $F_i$ using a Vision Transformer (ViT) [S1].
*   **Warped Features:** $F_{j \to i}^m$, the feature from view $j$ warped to view $i$ using depth candidate $d_m$ [S1].

**Parameters:**
*   **Downsampling factor $s$:** Controlled by the number of stride-2 $3 \times 3$ convolutions in the feature extraction. $s=4$ if two convolutions are used; $s=8$ if three are used [S1].
*   **Depth candidates $D$:** Uniformly sampled from near/far depth ranges [S1].
*   **Multi-view Transformer:** Contains six stacked self- and cross-attention layers [S1].
*   **Neighbor selection:** For $N > 2$ views, the top-2 nearest neighboring views are selected based on camera distance to the reference view [S1].

**Steps:**
1.  **Monocular Feature Extraction:** Extract per-view features $F_i$ using a pre-trained ViT (Monocular Branch) [S1].
2.  **Depth Candidate Sampling:** For each view $i$, uniformly sample $D$ depth candidates $\{d_m\}_{m=1}^D$ from the near and far depth ranges [S1].
3.  **Feature Warping:** For each neighboring view $j$, warp the feature $F_j$ to view $i$ using the camera projection matrix $P_i$ and each depth candidate $d_m$ to obtain warped features $\{F_{j \to i}^m\}_{m=1}^D$ [S1].
4.  **Cost Volume Construction:** Measure feature correlations via dot-product between $F_i$ and warped features $F_{j \to i}^m$ to build the cost volume $C_i$ [S1].
    *   If $N > 2$, select the top-2 nearest neighboring views based on camera distance. Compute correlations only for these views and combine values with averaging [S1].
5.  **Feature Concatenation:** Concatenate the multi-view cost volumes $C_i$ with the extracted monocular features $F_i$ [S1].
6.  **Depth Regression:** Perform depth regression using a 2D U-Net architecture followed by a softmax layer to predict dense per-pixel depth $D_i$ [S1].
7.  **Gaussian Unprojection:** Unproject the predicted depth maps $D_i$ to 3D space using camera parameters $P_i$ to obtain Gaussian centers $\mu_j$ [S1].
8.  **Parameter Prediction:** Predict remaining Gaussian parameters (opacity $\alpha_j$, covariance $\Sigma_j$, color $c_j$) using an additional lightweight network/head in parallel [S1].
9.  **Rendering:** Render novel views using the splatting operation with the predicted 3D Gaussians [S1].

    """

    """
    N = len(images)
    H, W = images[0].shape[:2]
    s = 4  # Example downsampling factor
    D = 64 # Example number of depth candidates
    
    # Step 1: Monocular Feature Extraction
    monocular_features = []
    for i in range(N):
        # Extract features using pre-trained ViT
        F_i = extract_monocular_features(images[i])
        monocular_features.append(F_i)
        
    # Step 2-4: Cost Volume Construction
    cost_volumes = []
    for i in range(N):
        # Sample depth candidates
        depth_candidates = sample_depth_candidates(H, W, near=0.1, far=100.0, num=D)
        
        # Determine neighbors
        if N > 2:
            neighbors = get_top_2_neighbors(projection_matrices[i], projection_matrices, exclude=i)
        else:
            neighbors = [j for j in range(N) if j != i]
            
        # Initialize cost volume
        cost_vol = torch.zeros((H//s, W//s, D))
        
        for j in neighbors:
            F_j = monocular_features[j]
            warped_features = []
            
            # Step 3: Feature Warping
            for m, d_m in enumerate(depth_candidates):
                # Warp F_j to view i using P_i and d_m
                F_warped = warp_feature(F_j, projection_matrices[i], d_m)
                warped_features.append(F_warped)
                
            # Step 4: Correlation
            F_i_downsampled = downsample(monocular_features[i], s)
            correlations = []
            for F_warped in warped_features:
                # Dot-product correlation
                corr = dot_product(F_i_downsampled, F_warped)
                correlations.append(corr)
                
            # Combine correlations if multiple neighbors
            if len(correlations) > 1:
                combined_corr = torch.mean(torch.stack(correlations), dim=0)
            else:
                combined_corr = correlations[0]
                
            # Stack correlations for all depth candidates
            cost_vol = torch.stack([combined_corr], dim=-1)
            
        cost_volumes.append(cost_vol)
        
    # Step 5: Concatenation
    # Concatenate cost volumes with monocular features
    # Note: Dimensions must be aligned for concatenation
    concatenated_features = []
    for i in range(N):
        F_i_upsampled = upsample(monocular_features[i], s) # Or appropriate alignment
        concat_feat = torch.cat([cost_volumes[i], F_i_upsampled], dim=-1)
        concatenated_features.append(concat_feat)
        
    # Step 6: Depth Regression
    predicted_depths = []
    for i in range(N):
        # 2D U-Net followed by softmax
        depth_map = depth_regression(concatenated_features[i])
        predicted_depths.append(depth_map)
        
    # Step 7-8: Gaussian Parameter Prediction
    gaussians = []
    for i in range(N):
        # Unproject depth to 3D centers
        centers = unproject_depth(predicted_depths[i], projection_matrices[i])
        
        # Predict other parameters using lightweight head
        # Input: concatenated features or depth map
        other_params = predict_gaussian_params(concatenated_features[i])
        
        gaussians.append({
            'centers': centers,
            'opacity': other_params['opacity'],
            'covariance': other_params['covariance'],
            'color': other_params['color']
        })
        
    return gaussians

**Edge Cases and Pitfalls:**
*   **Occlusions, Low-Texture, Non-Lambertian Surfaces:** Multi-view depth estimation fails in these scenarios. DepthSplat mitigates this by augmenting multi-view cost volumes with monocular features [S1].
*   **Scale Ambiguities:** Monocular depth estimation suffers from scale ambiguities across multiple views. DepthSplat maintains multi-view consistency by using monocular features only as an augmentation to multi-view matching [S1].
*   **Error Propagation:** Unlike TranSplat, which uses monocular features to refine coarse depth (vulnerable to error propagation), DepthSplat combines cost volume and monocular features early [S1].

## Subtopics

### [Gaussian Graph Network](18863-gaussian-graph-network.md)
Gaussian Graph Network (GGN) is a feed-forward method that generates efficient and generalizable 3D Gaussian representations from multi-view images by modeling relations between Gaussian groups from different views using a Gaussian Graph structure. It solves the problem of artifacts and excessive memory costs caused by previous methods that simply combine pixel-aligned Gaussians from multiple views without capturing their inter-view relations. Unlike sibling methods that treat multi-view Gaussians as independent sets, GGN performs message passing and aggregation at the Gaussian level, allowing each Gaussian to benefit from connected groups in other views.

## Operating characteristics
*   **Time Complexity:** Reconstruction speed is 0.6 seconds for feed-forward reconstruction from 12 input views at 512x960 resolution [S1].
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:** Achieves state-of-the-art performance on ScanNet, RealEstate10K, and DL3DV datasets [S1].
*   **Scaling:** For $N > 2$ views, computation scales efficiently by selecting only the top-2 nearest neighboring views for cross-attention, making it tractable with many input views [S1].
*   **Strengths:** Robust multi-view depth prediction, feed-forward 3D Gaussian splatting reconstruction, cheaper to train than data-heavy methods [S1].
*   **Limitations:** Relies on pre-trained monocular depth models, which may have inherent biases [S1].
*   **When to Use:** When robust multi-view depth prediction and efficient feed-forward 3D Gaussian splatting reconstruction are required, especially in challenging scenarios like low-textured regions and reflective surfaces [S1].
*   **When Not to Use:** When ground truth depth supervision is available and per-scene optimization is feasible, as DepthSplat is a feed-forward method [S1].

## Background
DepthSplat was introduced to connect Gaussian splatting and depth estimation, studying their interactions [S1]. It leverages pre-trained monocular depth features to augment multi-view feature matching, leading to high-quality feed-forward 3D Gaussian splatting reconstructions [S1]. The method was validated through extensive ablation and cross-task transfer experiments, showing the synergy between Gaussian splatting and depth estimation [S1]. It was trained on TartanAir, ScanNet, RealEstate10K, and DL3DV datasets [S1]. The model can be trained in 2 days with 4 GPUs, compared to 64 A100 GPUs for 2 days for methods like GS-LRM [S1].
