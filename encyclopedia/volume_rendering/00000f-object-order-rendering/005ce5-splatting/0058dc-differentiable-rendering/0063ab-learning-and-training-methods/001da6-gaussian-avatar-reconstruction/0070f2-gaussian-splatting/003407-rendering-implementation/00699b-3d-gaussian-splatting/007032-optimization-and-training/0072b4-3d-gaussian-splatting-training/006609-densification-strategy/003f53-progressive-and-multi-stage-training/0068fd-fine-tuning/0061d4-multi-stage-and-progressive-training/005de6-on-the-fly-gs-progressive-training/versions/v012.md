# On-the-Fly GS Progressive Training

Also called: On-the-Fly Gaussian Splatting

## Overview
On-the-Fly GS Progressive Training is a method for optimizing 3D Gaussian Splatting (3DGS) fields in a streaming or sequential acquisition context, enabling near real-time reconstruction as new images arrive [S1]. It solves the problem of incremental scene expansion by decoupling the optimization landscape into discrete phases: initial sparse training, progressive incremental updates with hierarchical weighting, and final global refinement [S1]. Unlike static offline training, it dynamically allocates computational resources (iterations and learning rates) based on the overlap and importance of newly acquired images relative to the existing field, preventing overfitting to initial views and ensuring consistent quality across the expanding scene [S1].

## How it works
The method operates in three distinct phases, integrating with an On-the-Fly Structure-from-Motion (SfM) pipeline to estimate poses and sparse point clouds [S1].

### Inputs and Outputs
*   **Inputs:** A sequence of images arriving sequentially; initial sparse point cloud and camera poses from On-the-Fly SfM for the first $N_0$ images [S1].
*   **Outputs:** A fully optimized 3D Gaussian field representing the scene [S1].

### Data Structures
*   **3DGS Field:** Standard 3DGS representation containing Gaussian primitives (position, covariance, opacity, spherical harmonics coefficients) [S1].
*   **Sparse Point Cloud:** A set of 3D points estimated by SfM, used to initialize new Gaussians [S1].
*   **Search Tree:** A spatial index (e.g., KD-tree) built over the existing sparse point cloud to efficiently query distances for new points [S1].
*   **Image Overlap Matrix ($M$):** A matrix where $M_{i,j}$ represents the number of matched feature points between image $i$ and image $j$ [S1].
*   **Gaussian Count per Pixel ($G_p$):** For each pixel $p$ in an image, the number of Gaussians contributing to its splat [S1].

### Parameters
*   $N_0$: Number of initial images for Phase 1. Typical value: 30 [S1].
*   Initial training iterations for Phase 1: 2,000 [S1].
*   $T_I$: Total training iterations performed for each new fly-in image in Phase 2. Typical value: 200 [S1].
*   $N_m$: Number of top-weighted images selected as key training targets for local optimization. Typical value: 10 [S1].
*   $T_a$: Predefined parameter representing iterations required for satisfactory rendering quality. Typical value: 200 [S1].
*   $\eta^0$: Initial learning rate. Typical value: $1.6 \times 10^{-4}$ [S1].
*   $\eta^f$: Final learning rate. Typical value: $1.6 \times 10^{-6}$ [S1].
*   $\lambda_1$: Weight for $L_1$-Loss. Typical value: 0.47 [S1].
*   $\lambda_{ssim}$: Weight for SSIM-Loss. Typical value: 0.12 [S1].
*   $\lambda_{load}$: Weight for Load-Balancing-Loss. Typical value: 0.41 [S1].

### Steps

#### Phase 1: Initial 3DGS Training
1.  On-the-Fly SfM estimates poses and generates a sparse point cloud for the first $N_0$ images [S1].
2.  Train an initial 3DGS field using the standard 3DGS optimization method for 2,000 iterations [S1]. This limit prevents overfitting to the small initial set of images [S1].

#### Phase 2: Progressive 3DGS Training
For each newly acquired image $n$:
1.  **Pose and Point Cloud Update:** On-the-Fly SfM updates the camera pose of image $n$ and optimizes poses of neighboring connected images via local Bundle Adjustment (BA), refining the sparse point cloud [S1].
2.  **New Gaussian Initialization:**
    *   Construct a search tree for the existing sparse point cloud [S1].
    *   Query points from the new image against this tree.
    *   Points with a shortest distance to existing points exceeding a predefined threshold are classified as newly added [S1].
    *   Initialize these points as new Gaussians and append them to the 3DGS field [S1].
3.  **Hierarchical Image Weighting:** Calculate weights for existing images to determine training priority [S1].
    *   Set weight of the new image: $\omega_{11} = 1$ [S1].
    *   For images $I_{2i}$ with direct overlap ($M_{i,n} \neq 0$):
        $$ \omega_{2i} = M_{i,n} $$
        where $M_{i,n}$ is the number of matched feature points between image $i$ and new image $n$ [S1].
    *   For images in layer $k$ ($k \ge 3$) with indirect overlap:
        $$ \omega_{ki} = \frac{\sum_{j=1}^{N_{k-1}} \omega_{j}^{(k-1)} \times M_{j,ki}^{(k-1)}}{N_{k-1}} $$
        where $\omega_{j}^{(k-1)}$ is the weight of image $j$ in layer $k-1$, $M_{j,ki}^{(k-1)}$ is the match count between image $j$ and image $i$, and $N_{k-1}$ is the number of images in layer $k-1$ [S1].
4.  **Adaptive Training Iteration Allocation:** Perform $T_I$ iterations, split into Local and Semi-Global optimization [S1].
    *   **Local Optimization:** Select the top $N_m$ images with the highest weights as key targets. For each key image $i$ with weight $\omega_i$, calculate its specific iteration count $T_{im}$:
        $$ T_{im} = \frac{1 - e^{-\omega_i}}{\sum_{j=1}^{N_m} (1 - e^{-\omega_j})} \times T_I $$
        Train these images for $T_{im}$ iterations each [S1].
    *   **Semi-Global Optimization:** Distribute the remaining $T_I / 2$ iterations evenly among all other registered images [S1].
5.  **Adaptive Learning Rate Updating:** For each image $j$ trained for $T_j$ iterations, calculate its base learning rate $\eta_j^c$ [S1]:
    *   Calculate progress $t_i$:
        $$ t_i = \begin{cases} 1 & \text{if } T_j > T_a \\ T_j / T_a & \text{if } T_j \le T_a \end{cases} $$
    *   Calculate base rate:
        $$ \eta_j^c = (\eta_j^0)^{1-t_i} \times (\eta_j^f)^{t_i} $$
    *   Adjust for overlapping images. Let $I$ be the set of overlapping images with $M_{i,j} > 0$ and $N_I$ be the count. The final learning rate $\eta_j$ is:
        $$ \eta_j = \frac{\eta_j^c + \sum_{i \in I} M_{i,j} \times \eta_i^c}{N_I + 1} $$
        [S1].
6.  **Loss Function:** Optimize the 3DGS field using the total loss [S1]:
    $$ L_{total} = \lambda_1 L_1 + \lambda_{ssim} L_{ssim} + \lambda_{load} L_{load} $$
    where $L_{load} = \text{std}(G_p)$ is the standard deviation of the number of Gaussians $G_p$ associated with each pixel $p$ in the current image [S1].

#### Phase 3: Final Optimization
1.  After all images are acquired, perform global Bundle Adjustment (BA) on the estimated poses [S1].
2.  Apply rapid additional optimization to the current 3DGS field to improve overall rendering quality [S1].

    Computes hierarchical weights for all images based on overlap with the new image.

    weights[new_image_idx] = 1.0

### Edge Cases and Pitfalls
*   **Overfitting in Phase 1:** Training too many iterations on the initial $N_0$ images can cause the field to overfit to the sparse initial view, hindering later generalization [S1].
*   **Threshold Selection:** The distance threshold for classifying new points in the search tree is critical. Too low, and new Gaussians are not added; too high, and existing points are incorrectly re-initialized [S1].
*   **Learning Rate Inconsistency:** Without adaptive learning rates, local quality inconsistencies may arise in the 3DGS field due to varying training exposure across images [S1].
*   **Gaussian Accumulation:** Without Load-Balancing-Loss, Gaussians may accumulate abnormally in specific regions, increasing memory usage and slowing training [S1].
*   **Thread Contention:** Using per-pixel gradient accumulation can lead to serialized atomic operations. Splatting-based parallelism (per-Gaussian accumulation) is required for efficiency [S1].

## Operating characteristics
*   **Time Complexity:** The method is designed for near real-time optimization. Each new image triggers $T_I = 200$ iterations of optimization [S1]. The average number of training iterations per image approaches 200 as the total number of images increases [S1].
*   **Memory Complexity:** The load-balancing loss helps reduce the total number of Gaussians, thereby managing memory usage more effectively than standard 3DGS [S1].
*   **Performance:** Evaluated on RGB datasets (3DGS, Mip-NeRF 360, On-the-Fly SfM, Replica) using an RTX 4090 GPU [S1]. It outperforms offline training solutions like Adr-Gaussian and Taming-3DGS in terms of speed while maintaining competitive quality [S1].
*   **Strengths:** Enables incremental scene expansion; prevents overfitting to initial views; dynamically allocates computational resources; reduces Gaussian count via load balancing; accelerates training via splatting-based parallelism [S1].
*   **Limitations:** Requires integration with On-the-Fly SfM; performance depends on the quality of pose estimation and sparse point cloud generation; hierarchical weighting calculation can be complex for large scenes [S1].
*   **When to Use:** Suitable for streaming or sequential image acquisition scenarios where near real-time reconstruction is required [S1].
*   **When Not to Use:** Not ideal for static, offline optimization where all images are available simultaneously, as the progressive nature adds overhead [S1].

## Background
On-the-Fly GS Progressive Training was proposed in the paper "Gaussian On-the-Fly Splatting: A Progressive Framework for Robust Near Real-Time 3DGS Optimization" [S1]. It builds upon the original 3D Gaussian Splatting method and integrates with On-the-Fly SfM techniques [S1]. The method addresses the limitations of static 3DGS training in dynamic or streaming contexts, where incremental updates are necessary [S1]. It incorporates strategies from Taming 3DGS for parallelism and introduces hierarchical weighting and load-balancing losses for robust incremental optimization [S1].
