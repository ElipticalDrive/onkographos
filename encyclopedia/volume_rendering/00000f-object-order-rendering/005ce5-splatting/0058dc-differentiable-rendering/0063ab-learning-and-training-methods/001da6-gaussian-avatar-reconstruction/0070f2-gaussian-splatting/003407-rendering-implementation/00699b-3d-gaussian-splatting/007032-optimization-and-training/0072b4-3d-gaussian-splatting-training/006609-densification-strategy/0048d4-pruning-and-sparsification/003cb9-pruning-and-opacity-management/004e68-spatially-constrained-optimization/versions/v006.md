# Spatially Constrained Optimization

Also called: Opacity Loss with Re-initialization

## Overview
Spatially Constrained Optimization is a post-processing constraint workflow that applies an opacity loss to ensure full coverage of target objects, followed by the re-initialization of boundary primitives to clean up rendering artifacts [S1, unofficial]. It differs from applying opacity loss alone by specifically addressing the issue where primitives on object boundaries retain low opacity, which degrades qualitative results; adding re-initialization produces the best visual fidelity [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of primitives $\Theta$ (positions, scales, rotations, opacities, colors), a target image $I^{target}$, and a target alpha mask $I_{\alpha}^{target}$.
*   **Output:** Optimized primitives $\Theta$ where foreground objects are rendered with full opacity and background primitives are suppressed or re-initialized.

**Data Structures:**
*   **Primitives:** Each primitive $i$ has an opacity parameter $\sigma(\nu_i)$ derived from its spatial configuration $\nu_i$.
*   **Target Masks:** Binary or continuous masks indicating the presence of foreground content ($I_{\alpha}^{target} > 0$) and the desired alpha channel.

**Parameters:**
*   **Prune threshold:** The opacity value below which primitives are considered transparent and marked for re-initialization. Typical value: $0.3$ [S1, unofficial].
*   **Prune iterations:** The frequency at which re-initialization is performed. Typical value: every $50$ iterations [S1, unofficial].
*   **$\lambda_{\alpha}$:** Weight for the alpha loss term. Not given in the sources.

**Steps:**
1.  **Compute Loss:** Calculate the composite loss $\mathcal{L}$ to penalize deviations in color and alpha from the target, specifically masking the color loss to the foreground region [S1, unofficial].
    $$ \mathcal{L} = \| (I_{\alpha}^{target} > 0) \odot (I - I^{target}) \|_2^2 + \lambda_{\alpha} \| I_{\alpha} - I_{\alpha}^{target} \|_2^2 $$
    Where:
    *   $I$ is the rendered image.
    *   $I^{target}$ is the target image.
    *   $I_{\alpha}$ is the rendered alpha, computed as $1 - T_N$ (where $T_N$ is the accumulated transmittance) [S1, unofficial].
    *   $I_{\alpha}^{target}$ is the target alpha mask.
    *   $\odot$ denotes element-wise multiplication.
    *   $(I_{\alpha}^{target} > 0)$ creates a binary mask selecting foreground pixels.

2.  **Optimize:** Update primitive parameters $\Theta$ using gradient descent on $\mathcal{L}$ [S1, unofficial].

3.  **Identify Boundary Primitives:** After optimization steps, identify primitives $i$ where the computed opacity $\sigma(\nu_i)$ is below the prune threshold [S1, unofficial].

4.  **Re-initialize:** Instead of removing these low-opacity primitives, re-initialize them randomly using the Structure-aware initialization method [S1, unofficial]. This preserves the primitive count and aids coverage in complex regions [S1, unofficial].

5.  **Schedule:** Re-initialization occurs every `prune iterations` (e.g., 50). It is excluded during an initial warmup period and final iterations to prevent destabilization of the optimization [S1, unofficial].

**Pseudocode:**
```python
def spatially_constrained_optimization(primitives, target_image, target_alpha, 
                                      lambda_alpha=1.0, prune_threshold=0.3, 
                                      prune_interval=50, warmup_steps=100, 
                                      total_steps=1000):
    """
    Optimizes primitives to match target image with full foreground opacity.
    Re-initializes low-opacity primitives instead of pruning them.
    """
    for step in range(total_steps):
        # 1. Forward pass: Render image and alpha
        rendered_image, rendered_alpha = render(primitives)
        
        # 2. Compute Loss
        # Mask for foreground pixels where target alpha is non-zero
        foreground_mask = (target_alpha > 0).float()
        
        # Color loss only on foreground
        color_loss = torch.norm(foreground_mask * (rendered_image - target_image), p=2) ** 2
        
        # Alpha loss on all pixels
        alpha_loss = torch.norm(rendered_alpha - target_alpha, p=2) ** 2
        
        loss = color_loss + lambda_alpha * alpha_loss
        
        # 3. Backward pass
        loss.backward()
        optimize_step(primitives) # Standard optimizer step (e.g., Adam)
        
        # 4. Re-initialization logic
        # Skip during warmup and final steps to prevent destabilization
        if step >= warmup_steps and step < total_steps - 50:
            if step % prune_interval == 0:
                reinitialize_low_opacity_primitives(primitives, prune_threshold)
```

## Subtopics

### Structure-aware Re-initialization
A mechanism to handle transparent primitives in spatially constrained rendering by re-initializing them randomly instead of pruning them, to prevent destabilization and ensure coverage [S1, unofficial]. It checks opacity $\sigma(\nu_i)$ for each primitive $i$; if $\sigma(\nu_i) <$ prune threshold (typically 0.3), the primitive is marked for re-initialization [S1, unofficial]. Re-initialization occurs every prune iterations (typically 50), excluding an initial warmup period and final iterations to prevent destabilization [S1, unofficial]. It differs from standard pruning (e.g., [34]) by re-initializing transparent primitives rather than removing them, maintaining the primitive count and potentially aiding coverage in complex regions [S1, unofficial].

### Foreground-only Rendering
A method to render only foreground by optimizing primitive opacity to match target alpha, enabling applications like appearance editing [S1, unofficial]. It optimizes $\Theta$ using the loss $\mathcal{L} = \| (I_{\alpha}^{target} > 0) \odot (I - I^{target}) \|_2^2 + \lambda_{\alpha} \| I_{\alpha} - I_{\alpha}^{target} \|_2^2$, where $I_{\alpha} = 1 - T_N$ [S1, unofficial]. It re-initializes transparent primitives instead of pruning them for further applications [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Per-iteration performance depends on the renderer implementation. On an RTX 3090 at 1024x1024 resolution with 16x16 tiles, forward pass takes ~5514ms and backward pass ~9811ms (FP32) [S1, unofficial]. Custom CUDA kernels can reduce this to ~1393ms forward / ~2477ms backward [S1, unofficial].
*   **Memory Complexity:** VRAM usage scales with resolution and primitive count. At 1024x1024, VRAM usage is ~12.0 GB (FP32) or ~5.0 GB (FP16/CUDA optimized) [S1, unofficial].
*   **Strengths:** Enables full opacity rendering of foreground objects, crucial for post-processing and appearance editing [S1, unofficial]. Re-initialization prevents the loss of coverage in complex boundary regions compared to simple pruning [S1, unofficial].
*   **Limitations:** Requires careful scheduling of re-initialization (warmup/final steps) to avoid destabilization [S1, unofficial]. Performance overhead from re-initialization steps is not explicitly quantified but adds to the per-iteration cost [S1, unofficial].
*   **When to use:** When full opacity of specific objects is required for downstream tasks like appearance editing or compositing [S1, unofficial].
*   **When not to use:** When preserving the exact number of primitives is not critical and simple pruning is sufficient, or when computational resources are extremely limited and the overhead of re-initialization is prohibitive.

## Background
Originated in the DiffBMP paper (2026) by the authors of "DiffBMP: Differentiable Rendering with Bitmap Primitives" [S1, unofficial]. The idea is modified from [52]'s work for triangle mesh rendering [24], but adapted for bitmap primitives by sampling $\beta$ only once per iteration instead of averaging gradients over five samples [S1, unofficial]. It is used in differentiable rendering pipelines to enable foreground-only rendering and appearance editing applications [S1, unofficial].
