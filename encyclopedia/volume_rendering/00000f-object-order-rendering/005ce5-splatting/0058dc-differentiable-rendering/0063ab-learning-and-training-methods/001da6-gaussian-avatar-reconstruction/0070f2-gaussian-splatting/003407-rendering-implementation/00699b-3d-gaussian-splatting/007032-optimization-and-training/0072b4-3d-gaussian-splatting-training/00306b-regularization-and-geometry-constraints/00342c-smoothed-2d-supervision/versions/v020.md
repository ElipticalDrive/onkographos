# Smoothed 2D Supervision

Also called: Adaptive Gaussian blur strategy, Progressive Gaussian Blurring

## Overview
Smoothed 2D Supervision is a regularization technique that stabilizes the joint optimization of camera poses and scene geometry by blurring 2D training images with scheduled Gaussian kernels [S2, unofficial]. It addresses the instability caused by high-frequency noise in photometric gradients during early training, which can lead to poor camera alignment and overfitting to noise [S2, unofficial]. Unlike [Frequency Regularization](6130-frequency-regularization.md) which operates in the Fourier domain, this method operates directly in the image space to restrict the spectrum of the learned 3D scene and produce smoother gradients [S2, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A set of 2D training images $I_{raw}$, a current training iteration $t$, and hyperparameters defining the blur schedule.
- Output: A set of blurred supervision images $I_{blur}$ used in the photometric loss calculation.

**Data Structures:**
- The blur kernel is a 2D Gaussian kernel $K$.
- The schedule is defined by the standard deviation $\sigma(t)$ and potentially the kernel size $k(t)$.

**Steps:**
1. **Initialize Schedule:** Define the initial kernel parameters. According to [S4], a common starting point is a square kernel of size $9 \times 9$ with standard deviation $\sigma = 2.4$.
2. **Schedule Definition:** Define $\sigma(t)$ as a function that decreases over time. [S2, unofficial] notes that the kernel is exponentially reduced to 0 at a specific iteration (e.g., 10k iterations in their context, though [S4] uses a different schedule). [S3] describes this as "progressively reducing the standard variance."
3. **Apply Blur:** For each training image $I_{raw}$, apply the 2D Gaussian blur $K_{\sigma(t)}$ to produce $I_{blur} = I_{raw} * K_{\sigma(t)}$.
4. **Compute Loss:** Calculate the photometric loss (e.g., L1 or L2) between the rendered image and $I_{blur}$ instead of $I_{raw}$.
5. **Update Parameters:** Increment iteration $t$. If $t$ reaches the schedule step (e.g., every $k_b$ iterations), update $\sigma(t)$ and kernel size. [S4] specifies reducing the blur every $k_b = 100$ iterations until iteration 19500.
6. **Adjust for Downsampling:** If image downsampling is active, lower the kernel size by the scale of downsampling at the current stage, as initial hyperparameters are based on original resolution [S4].
7. **Pre-Densification Adjustment:** Lower the blurring kernel size before densifying Gaussians to introduce extra signal on the gradient of erroneous Gaussians as the noise level reduces [S4].

**Formulas:**
The blurred image $I_{blur}(x,y)$ is computed as:
$$ I_{blur}(x,y) = \sum_{i=-k}^{k} \sum_{j=-k}^{k} I_{raw}(x-i, y-j) \cdot G(i,j;\sigma(t)) $$
where $G(i,j;\sigma(t))$ is the 2D Gaussian function:
$$ G(i,j;\sigma(t)) = \frac{1}{2\pi\sigma(t)^2} \exp\left(-\frac{i^2 + j^2}{2\sigma(t)^2}\right) $$
and $k$ is the kernel radius (e.g., $k=4$ for a $9 \times 9$ kernel).

**Parameters:**
- Initial $\sigma$: 2.4 [S4].
- Initial Kernel Size: $9 \times 9$ [S4].
- Schedule Step $k_b$: 100 iterations [S4].
- End of Schedule: Iteration 19500 [S4] or 10k iterations [S2, unofficial]. Note: Sources disagree on the exact end point and reduction rate (exponential vs. linear/progressive). [S2, unofficial] states exponential reduction to 0 at 10k. [S4] states reduction every 100 iterations until 19500. [S3] refers to it as "Adaptive Gaussian Blur" without specific numbers in the text provided.

**Edge Cases and Pitfalls:**
- **Over-smoothing:** If $\sigma$ is too large or reduced too slowly, fine details are lost, leading to blurry reconstructions.
- **Under-smoothing:** If $\sigma$ is too small or reduced too quickly, the optimization remains unstable, leading to camera drift or noise artifacts.
- **Resolution Mismatch:** If the input images are downsampled, the kernel size must be adjusted proportionally to maintain the effective blur radius in world space [S4].

**Pseudocode:**
```python
def compute_blurred_supervision(training_images, iteration, initial_sigma=2.4, kernel_size=9, schedule_step=100, end_iteration=19500, downsampling_scale=1.0):
    """
    Computes blurred supervision images based on the current training iteration.
    
    Args:
        training_images: List of 2D numpy arrays (H, W, C) representing raw training images.
        iteration: Current training iteration number.
        initial_sigma: Initial standard deviation of the Gaussian kernel.
        kernel_size: Initial kernel size (e.g., 9 for 9x9).
        schedule_step: Number of iterations between schedule updates.
        end_iteration: Iteration at which blurring stops (sigma becomes 0).
        downsampling_scale: Factor by which images are downsampled (1.0 for no downsampling).
        
    Returns:
        List of blurred 2D numpy arrays.
    """
    blurred_images = []
    
    # Calculate current sigma based on schedule
    # Sources [S2, unofficial] and [S4] differ on the exact schedule function.
    # [S4] implies a step-wise reduction. [S2, unofficial] implies exponential.
    # We implement a linear interpolation to 0 as a common interpretation of "progressive reduction"
    # when specific functional forms are not unified, but note the discrepancy.
    
    if iteration >= end_iteration:
        current_sigma = 0.0
    else:
        # Linear decay from initial_sigma to 0 over end_iteration
        # Note: [S4] says "gradually reduce", [S2, unofficial] says "exponentially reduced".
        # Using linear as a safe default for "progressive" if not specified, 
        # but implementers should check specific paper supplements for exact curves.
        progress = iteration / end_iteration
        current_sigma = initial_sigma * (1.0 - progress)
        
    # Adjust sigma for downsampling if applicable
    # [S4] mentions lowering kernel size by scale of downsampling.
    # This effectively scales the spatial extent.
    effective_sigma = current_sigma / downsampling_scale if downsampling_scale > 1.0 else current_sigma
    
    # Create Gaussian Kernel
    # Only create kernel if sigma > 0
    if effective_sigma > 1e-6:
        # Determine kernel radius from size
        radius = kernel_size // 2
        y, x = np.ogrid[-radius:radius+1, -radius:radius+1]
        kernel = np.exp(-(x**2 + y**2) / (2 * effective_sigma**2))
        kernel = kernel / np.sum(kernel) # Normalize
    else:
        kernel = None # Identity operation
        
    for img in training_images:
        if kernel is not None:
            # Apply 2D convolution
            # Assuming img is (H, W, C)
            blurred_img = np.zeros_like(img)
            for c in range(img.shape[2]):
                blurred_img[:,:,c] = convolve2d(img[:,:,c], kernel, mode='same')
            blurred_images.append(blurred_img)
        else:
            blurred_images.append(img)
            
    return blurred_images
```

## Subtopics

### [Randomly Scaled Kernel Parameter](7875-randomly-scaled-kernel-parameter.md)
A regularization technique used during joint optimization to mitigate weak and noisy gradient signals. It addresses the insufficiency of using a single-size kernel for diverse real-world scene structures, where a fixed kernel may be overly aggressive in some contexts and overly gentle in others. By randomly scaling the kernel size, it allows combinations of different-sized kernels to guide the optimization, resulting in a more robust training schedule.

### [Multiscale Pre-convolved Representation](10911-multiscale-pre-convolved-representation.md)
A regularization technique for neural illumination fields that stabilizes the decomposition of object materials from environmental illumination by enforcing consistency with pre-computed, roughness-adapted background reflections. It addresses the ambiguity where diffuse object color is incorrectly absorbed into the estimated environment map, a problem inherent to high-dimensional neural illumination representations. Unlike methods that ignore the background or treat it as static, this method explicitly models the relationship between rough refractive surfaces and the convolved background, allowing for realistic specular reflections even when roughness exceeds the kernel scale. The technique builds on [Smoothed 2D Supervision](7213-smoothed-2d-supervision.md) by applying discrete Gaussian blur kernels to the background to stabilize convergence.

### [Soft Rasterization](13687-soft-rasterization.md)
Soft rasterization is a differentiable rendering technique that mitigates the discontinuities inherent in standard rasterization by blending facet contributions for pixels near primitive edges. It solves the problem of sparse and vanishing gradients caused by the non-uniformity of bilinear interpolation operands, which typically have similar values except at object boundaries. Unlike standard hard rasterization, it yields slightly distorted images but allows backpropagating more useful gradients, thereby stabilizing optimization and preventing gradient vanishing at edges.

### Platonic GAN (pGAN)
A learning-based method for 2D supervision per class of reconstructed objects, used here to pre-train a network for per-frame supervision of rising smoke [S5]. It is used to improve depth artifacts but can lead to temporal incoherence if not constrained by temporal self-supervision [S5].

## Operating characteristics
**Time and Memory Complexity:**
- Time: Adding a Gaussian blur step increases the per-iteration cost by the cost of convolution. For a fixed kernel size $k \times k$, this is $O(k^2)$ per pixel. Since the kernel size is small (e.g., $9 \times 9$), this is negligible compared to the rendering cost [S1].
- Memory: Requires storing the blurred images or recomputing them on the fly. Minimal additional memory overhead.

**Measured Performance:**
- On DTU 3-view, Smoothed 2D Supervision (referred to as Adaptive Gaussian Blur in [S3]) achieves 19.72 PSNR, improving over the Baseline of 19.54 PSNR [S3].
- It is experimentally proven crucial for successful pose refinement in ablation studies [S1].

**Strengths and Limitations:**
- Strengths: Stabilizes camera alignment, restricts high-frequency noise, and improves robustness in joint optimization [S2, unofficial].
- Limitations: It is handcrafted and cannot fully align frequency relationships compared to adaptive methods like [FreGS](9212-fregs.md) or [Frequency Regularization](6130-frequency-regularization.md) [S3]. The schedule parameters (start/end sigma, reduction rate) are sensitive and require tuning [S4].

**When to Use:**
- Use when optimizing camera poses jointly with scene geometry, especially in the presence of noise or when initial pose estimates are poor [S1].
- Use when training converges slowly or diverges due to high-frequency artifacts.

**When Not to Use:**
- When high-frequency detail preservation is critical from the start and the scene is well-posed.
- When using adaptive frequency-aware regularization methods that do not require manual scheduling.

## Background
Originating from research into robust joint optimization of camera poses and radiance fields, Smoothed 2D Supervision was introduced to address the instability of photometric gradients in early training stages [S1][S2, unofficial]. It draws inspiration from frequency analysis of rendering losses, noting that high-frequency components can dominate gradients and cause noise [S2, unofficial]. The method has been adopted in various Gaussian Splatting and NeRF-based frameworks to improve convergence stability [S3, S4].
