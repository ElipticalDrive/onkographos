# GS-Cache Inference Framework

Also called: GS-Cache

## Overview
GS-Cache is a holistic rendering framework designed to support real-time rendering of large-scale 3D Gaussian Splatting (3DGS) models, specifically targeting city-level scenes [S1, unofficial]. It achieves an average frame rate exceeding 72 FPS at binocular 2K resolution by employing a cache-centric de-redundancy pipeline and elastic parallel scheduling [S1, unofficial]. Unlike native 3DGS or unstructured methods, GS-Cache specifically targets "Structured Gaussian derivation methods" (such as Scaffold-GS and Octree-GS) which use anchors to derive neural Gaussians, addressing the computational bottleneck of the "Gaussian Derivation Stage" [S1, unofficial]. It sets itself apart by caching decoded Gaussian parameters across frames to eliminate inter-frame redundancy in the derivation stage, while leaving the rasterization stage uncached to preserve visual quality against occlusion changes [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** Camera pose (view/projection matrices), current frame index, and the structured 3DGS model (anchors, MLP weights for derivation).
*   **Output:** Rendered image (binocular stereo frames).

**Data Structures**
*   **Cache:** Stores derived Gaussian parameters (position, covariance, opacity, spherical harmonics coefficients) for specific anchors. The cache is indexed by anchor indices mapped from the model space.
*   **Anchor Set ($X$):** The set of anchors requiring decoding in the current frame.
*   **Newly Decoded Anchors ($X_k'$):** The subset of anchors in $X$ that were not found in the cache (or expired) and require fresh decoding from the previous $k$ frames' context.

**Numbered Steps**
1.  **Anchor Indexing:** Compute anchor indices based on the current camera input. These indices identify which anchors are visible or relevant for the current view frustum [S1, unofficial].
2.  **Cache Lookup and Filtering:** Use the anchor indices to locate corresponding entries in the cache. Filter the anchor set $X$ into two subsets:
    *   Cached anchors: Parameters are retrieved from the cache.
    *   Uncached anchors: Parameters must be decoded [S1, unofficial].
3.  **Dynamic Cache Depth Scheduling:** Calculate the expected reuse depth using the heuristic function $H$ and the update rate [S1, unofficial]:
    $$ \text{depth} = H\left(\frac{|X_k'|}{|X|}\right) $$
    Where:
    *   $|X|$ is the total number of anchors in the current frame's decoding set.
    *   $|X_k'|$ is the number of newly decoded anchors (those not found in the cache) from the previous $k$ frames.
    *   $H$ is the guiding function of the heuristic strategy [S1, unofficial].
    *   $k$ is the number of previous frames considered for the update rate calculation [S1, unofficial].
    The calculated `depth` determines how long parameters remain in the cache before being flushed or updated, balancing performance and visual fidelity [S1, unofficial].
4.  **Cache Scheduling and Loading:** The cache scheduler loads necessary model parameters (MLP weights) and anchor features for the uncached anchors. It also manages the eviction or retention of cached parameters based on the `depth` value [S1, unofficial].
5.  **Anchor Decoding (Derivation Stage):**
    *   For cached anchors, reuse the stored Gaussian parameters from previous frames.
    *   For uncached anchors, decode the anchor features into neural Gaussian parameters using the MLP [S1, unofficial].
    *   Update the cache with the newly decoded parameters [S1, unofficial].
6.  **Gaussian Rasterization:** Project the final set of Gaussian parameters (both cached and newly decoded) to 2D screen space and rasterize them into the image. This stage is **not** cached because slight perspective changes significantly affect occlusion and visual perception [S1, unofficial].

**Pseudocode**
```python
def gs_cache_render(camera, model, cache, k, H):
    """
    Render a single frame using the GS-Cache framework.
    
    Args:
        camera: Camera pose and projection matrices.
        model: Structured 3DGS model containing anchors and MLP weights.
        cache: Dictionary mapping anchor_index -> GaussianParameters.
        k: Number of previous frames to consider for update rate.
        H: Heuristic function for cache depth scheduling.
        
    Returns:
        image: Rendered image buffer.
    """
    # Step 1: Compute anchor indices for the current camera view
    anchor_indices = compute_anchor_indices(camera, model)
    
    # Step 2: Filter anchors into cached and uncached sets
    cached_anchors = []
    uncached_anchors = []
    
    for idx in anchor_indices:
        if idx in cache:
            cached_anchors.append(idx)
        else:
            uncached_anchors.append(idx)
            
    # Step 3: Calculate dynamic cache depth
    # |X| is the total number of anchors to process in this frame
    # |X_k'| is the number of uncached anchors (newly decoded)
    # Note: In a real implementation, |X_k'| might be tracked over k frames.
    # Here we assume |X_k'| is the count of uncached anchors in the current batch
    # relative to the history, or simply the current uncached count if k=1.
    # The source defines |X_k'| as "newly decoded anchors from the previous k frames".
    # For a single frame step, we approximate |X_k'| with the current uncached count
    # if no explicit history buffer is maintained in this simplified view, 
    # or we assume the framework maintains this count externally.
    # To be precise to the source:
    total_anchors = len(anchor_indices)
    newly_decoded_count = len(uncached_anchors) 
    
    # Calculate update rate
    if total_anchors > 0:
        update_rate = newly_decoded_count / total_anchors
    else:
        update_rate = 0.0
        
    # Calculate expected reuse depth
    depth = H(update_rate)
    
    # Step 4: Cache Scheduling (Eviction/Retention logic based on depth)
    # This step manages the cache state. If depth is low, evict old entries.
    # If depth is high, retain entries longer.
    manage_cache_eviction(cache, depth)
    
    # Step 5: Anchor Decoding
    gaussian_params = []
    
    # Retrieve cached parameters
    for idx in cached_anchors:
        params = cache[idx]
        gaussian_params.append((idx, params))
        
    # Decode uncached anchors
    for idx in uncached_anchors:
        # Decode anchor features using MLP
        params = decode_anchor(model, idx)
        # Update cache with new parameters
        cache[idx] = params
        gaussian_params.append((idx, params))
        
    # Step 6: Rasterization
    # Project all Gaussian parameters to screen space
    screen_gaussians = project_gaussians(gaussian_params, camera)
    
    # Rasterize to image
    image = rasterize(screen_gaussians)
    
    return image

def manage_cache_eviction(cache, depth):
    """
    Evict cache entries based on the calculated depth.
    Entries older than 'depth' frames are removed.
    """
    # Implementation detail: [G]
    # The cache must store a timestamp or frame counter for each entry.
    # Entries with age > depth are removed.
    current_frame = get_current_frame_number() # [G]
    keys_to_remove = []
    for idx, entry in cache.items():
        if entry.age > depth:
            keys_to_remove.append(idx)
    for idx in keys_to_remove:
        del cache[idx]
```

**Parameters**
*   $k$: The number of previous frames from which newly decoded anchors ($X_k'$) are considered for the update rate calculation [S1, unofficial].
*   $H$: The guiding function of the heuristic cache reuse depth scheduling strategy [S1, unofficial].
*   Typical values: Not given in the sources.

**Edge Cases and Pitfalls**
*   **Visual Quality vs. Performance:** Caching the rasterization stage is avoided because slight perspective changes significantly affect occlusion. Caching the derivation stage is safe because slight perspective changes cause little color difference for structured methods [S1, unofficial].
*   **Rapid Appearance Changes:** If the same Gaussian parameters are maintained in the cache for too long, it can cause significant rendering errors (e.g., around a centered target). The dynamic cache depth scheduling prevents this by flushing the cache when necessary [S1, unofficial].
*   **Precision:** Not given in the sources.

## Subtopics

### Structured Gaussian Derivation Methods
Methods like Scaffold-GS and Octree-GS that use anchors to derive neural Gaussians. GS-Cache is specifically designed for these methods [S1, unofficial].

### Dynamic Cache Depth Scheduling
A strategy that adjusts the cache reuse depth based on the intensity of decoding calculations, using a heuristic function [S1, unofficial].

## Operating characteristics
*   **Performance:** Achieves an average frame rate exceeding 72 FPS at binocular 2K resolution for large-scale city-level scenes [S1, unofficial].
*   **Complexity:** The framework reduces computational load in the Gaussian Derivation Stage by reusing cached parameters. The rasterization stage remains computationally intensive but is not accelerated by caching [S1, unofficial].
*   **Strengths:** Enables real-time rendering of large-scale 3DGS models, particularly for VR applications requiring binocular stereo [S1, unofficial].
*   **Limitations:** Specifically targets structured Gaussian derivation methods; may not provide the same benefits for unstructured 3DGS [S1, unofficial].
*   **Scaling:** Supports elastic parallel scheduling [S1, unofficial].

## Background
GS-Cache was introduced in the paper "A GS-Cache Inference Framework for Large-Scale Gaussian Splatting Models" [S1, unofficial]. It addresses the challenges of real-time photo-realistic rendering of large-scale 3DGS models, particularly in VR applications where binocular stereo rendering is required. The framework was developed to overcome the bottleneck of the Gaussian Derivation Stage in structured Gaussian derivation methods [S1, unofficial].
