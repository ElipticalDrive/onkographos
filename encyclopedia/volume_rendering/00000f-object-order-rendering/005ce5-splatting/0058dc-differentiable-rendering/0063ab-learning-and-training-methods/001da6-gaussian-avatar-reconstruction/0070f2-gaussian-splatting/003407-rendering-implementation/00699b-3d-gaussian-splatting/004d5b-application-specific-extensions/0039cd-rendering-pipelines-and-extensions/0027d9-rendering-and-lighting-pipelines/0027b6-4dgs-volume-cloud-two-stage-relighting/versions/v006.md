# 4DGS-Volume-Cloud Two-Stage Relighting

Also called: Frozen Geometry + Environment Network, Stage 1 + Stage 2

## Overview
A two-stage rendering pipeline for physically parameterized volume clouds using 3D Gaussians, designed for real-time dynamic relighting with arbitrary sun directions [S1, unofficial]. Unlike standard Gaussian Splatting which learns view-dependent RGB colors, this method separates geometry and physical medium properties (extinction, albedo) from the lighting environment [S1, unofficial]. Stage 1 trains the physical parameters under a single sun direction with a black background, while Stage 2 freezes these parameters and trains a global environment network to add sky atmospheric scattering, enabling arbitrary sun direction relighting [S1, unofficial].

## How it works
The method operates in two distinct phases. Stage 1 establishes the physical representation of the cloud volume. Stage 2 decouples the lighting from the geometry to allow dynamic relighting.

### Inputs and Outputs
**Inputs:**
*   **Stage 1:** A dataset of images captured under pure sun illumination with a black background (UE SkyAtmosphere brightness factor = 0) [S1, unofficial]. The dataset must cover the hemisphere uniformly to ensure healthy geometric shadow gradients [S1, unofficial].
*   **Stage 2:** The trained Stage 1 model (geometry and physical parameters) and a corresponding "env-on" dataset where the sky brightness is zero but the atmospheric scattering on the cloud remains [S1, unofficial].

**Outputs:**
*   **Stage 1:** A set of 3D Gaussians with physical attributes (position, scale, rotation, extinction $\sigma_t$, albedo $\omega$, HG $g$, multiple scattering weights $w_n$) [S1, unofficial].
*   **Stage 2:** The same Gaussian set (frozen) plus an environment network (MLP) and precomputed visibility vectors [S1, unofficial].
*   **Final Render:** Radiance $L$ for any given sun direction [S1, unofficial].

### Data Structures
The Gaussian primitive $\mathcal{G}$ retains the standard 3DGS structure but replaces SH color with physical parameters [S1, unofficial]:
*   $\mathbf{p}_i \in \mathbb{R}^3$: Position.
*   $\mathbf{R}_i \in \mathbb{R}^{3 \times 3}$: Rotation.
*   $\mathbf{S}_i \in \mathbb{R}^{3 \times 3}$: Scale.
*   $\sigma_{t,i}$: Extinction coefficient (volume integral of cross-section). Activated via `softplus`, clamped to 5 [S1, unofficial].
*   $\omega_i \in \mathbb{R}^3$: Scattering albedo (RGB). Activated via `sigmoid` [S1, unofficial].
*   $g_i$: Henyey-Greenstein anisotropy factor. Activated via $0.8 \cdot \tanh$ [S1, unofficial].
*   $w_{n,i}$: Six octave weights for multiple scattering (Frostbite/Wrenninge approximation). Activated via `softplus` [S1, unofficial].

**Stage 2 Sidecar Files:**
*   `env_net.pt`: Weights for the global environment network [S1, unofficial].
*   `sky_transfer.npy`: Precomputed visibility transfer vectors $V_{lm}$ [S1, unofficial].
*   `env.json`: Configuration parameters [S1, unofficial].

### Numbered Steps

#### Stage 1: Physical Parameter Training
1.  **Initialize:** Create $M$ 3D Gaussians. Initialize physical parameters $\sigma_t, \omega, g, w_n$ [S1, unofficial].
2.  **Rasterization Setup:** Use a forked differentiable rasterizer supporting `use_analytic_tau`. This computes per-pixel cumulative optical thickness $\tau$ via line integration, with $\alpha = 1 - \exp(-\tau)$ [S1, unofficial].
3.  **Compute Self-Shadowing ($T_{light}$):**
    *   Perform a "light space" rasterization pass using a narrow FOV perspective camera to simulate the sun direction [S1, unofficial].
    *   For each Gaussian, record the front-facing optical thickness accumulation. This is the energy-weighted mean of $\alpha \cdot T$ over the sun-facing footprint, not just a center-point sample [S1, unofficial].
    *   Enable full continuous gradients for $\tau$, weights, and projection parameters [S1, unofficial].
4.  **Compute Radiance:** For each pixel, sum contributions from Gaussians. The radiance contribution of a Gaussian is:
    $$ L_i = \omega_i \cdot L_{sun} \cdot \sum_{n=0}^{5} w_{n,i} \cdot T_{light,i}^{b^n} \cdot P(\mathbf{v}_i, \mathbf{v}_o; g_i \cdot c^n) $$
    Where $P$ is the Henyey-Greenstein phase function, $\mathbf{v}_i$ is the incident light direction ($-\mathbf{v}_l$), and $b, c$ are base/exponent constants for the octaves [S1, unofficial].
5.  **Optimize:** Minimize loss against the ground truth images. Use fixed Narkowicz ACES tonemapping by default to match the display space of the training data (e.g., UE filmic tonemapped LDR) [S1, unofficial]. If the ground truth is linear HDR, disable tonemapping [S1, unofficial].

#### Stage 2: Environment Network Training
1.  **Freeze Geometry:** Lock all Gaussian attributes ($\mathbf{p}, \mathbf{R}, \mathbf{S}, \sigma_t, \omega, g, w_n$) from Stage 1 [S1, unofficial].
2.  **Precompute Visibility ($V_{lm}$):**
    *   For each Gaussian center $\mathbf{x}$, compute the geometric sky visibility transfer vectors $V_{lm}(\mathbf{x})$.
    *   Scan the hemisphere in $N$ directions using `compute_T_light_raster` to calculate geometric occlusion [S1, unofficial].
    *   Represent $V_{lm}$ using Spherical Harmonics (SH) of order 2 (9 coefficients) by default [S1, unofficial].
    *   This step is colorless and purely geometric; it is computed once on the frozen point set [S1, unofficial].
3.  **Train Environment Network:**
    *   Train a small global MLP to predict the sky irradiance field $E_{lm}(\mathbf{v}_l)$ as a function of sun direction $\mathbf{v}_l$ [S1, unofficial].
    *   Use a learning rate of $10^{-3}$ with an independent optimizer, decaying to $0.1\times$ [S1, unofficial].
4.  **Compute Final Radiance:**
    *   Calculate the sun transmittance $T_{sun}(\mathbf{v}_l)$ using the analytic expression:
        $$ T_{sun}(\mathbf{v}_l) = \exp(-m(\theta) \cdot \tau_{rgb}) $$
        Where $m(\theta)$ is the Kasten-Young air mass based on sun elevation $\theta$, and $\tau_{rgb} = (\tau_R, \tau_G, \tau_B)$ are learnable zenith optical thicknesses [S1, unofficial].
    *   Combine Stage 1 sun term and Stage 2 sky term:
        $$ L = T_{sun}(\mathbf{v}_l) \odot L_{stage1} + \omega \cdot \sum_{lm} E_{lm}(\mathbf{v}_l) \cdot V_{lm}(\mathbf{x}) $$
        Where $L_{stage1}$ is the direct sun term computed in Stage 1 (using the frozen physical parameters) [S1, unofficial].
    *   Apply a `smoothstep` gate to extinguish the direct sun term when the sun is below the horizon [S1, unofficial].

### Pseudocode

```python
# Stage 1: Physical Training
def stage1_train(gaussians, dataset, optimizer):
    for image, sun_direction in dataset:
        # 1. Rasterize with analytic tau
        # Computes per-pixel tau and alpha = 1 - exp(-tau)
        tau_map, alpha_map = rasterize_analytic(gaussians, camera)
        
        # 2. Compute self-shadowing T_light
        # Light-space rasterization pass
        T_light = compute_light_space_transmittance(gaussians, sun_direction)
        
        # 3. Compute Radiance
        # L_stage1 is the direct sun contribution
        L_stage1 = compute_physical_radiance(
            gaussians, 
            sun_direction, 
            T_light, 
            phase_function='henyey_greenstein'
        )
        
        # 4. Apply Tonemapping (if GT is LDR)
        L_rendered = apply_aces_tonemap(L_stage1)
        
        # 5. Backpropagate loss
        loss = mse_loss(L_rendered, image)
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()

# Stage 2: Relighting
def stage2_relight(gaussians_frozen, env_net, sun_direction):
    # 1. Get precomputed visibility V_lm (from sky_transfer.npy)
    V_lm = gaussians_frozen.visibility_vectors # SH order 2
    
    # 2. Compute Sky Irradiance E_lm from MLP
    E_lm = env_net(sun_direction)
    
    # 3. Compute Sun Transmittance T_sun
    theta = sun_elevation(sun_direction)
    m_theta =kasten_young_air_mass(theta)
    tau_rgb = env_net.zenith_optical_thicknesses
    T_sun = exp(-m_theta * tau_rgb)
    
    # 4. Gate sun if below horizon
    if sun_below_horizon(sun_direction):
        T_sun = 0.0
        
    # 5. Compute Stage 1 Direct Term (using frozen params)
    # Note: T_light for the specific sun direction must be recomputed 
    # or approximated if not precomputed for all directions. 
    # In this pipeline, T_light is often recomputed per-frame for the new sun dir
    # or approximated if the geometry is static and T_light was stored.
    # Based on notes, T_light is computed via rasterization pass.
    T_light_new = compute_light_space_transmittance(gaussians_frozen, sun_direction)
    L_stage1_new = compute_physical_radiance(
        gaussians_frozen, 
        sun_direction, 
        T_light_new, 
        phase_function='henyey_greenstein'
    )
    
    # 6. Combine Terms
    # Direct Sun Term (Multiplicative)
    direct_term = T_sun * L_stage1_new
    
    # Sky Insattering Term (Additive)
    # Sum over SH coefficients
    sky_term = 0.0
    for l, m in sh_coefficients(order=2):
        sky_term += E_lm[l, m] * V_lm[l, m]
    sky_term = gaussians_frozen.albedo * sky_term
    
    L_final = direct_term + sky_term
    
    return L_final
```

### Parameters and Edge Cases
*   **SH Order:** Default is 2 (9 coefficients) for both $E_{lm}$ and $V_{lm}$ [S1, unofficial].
*   **Tonemapping:** Default is fixed Narkowicz ACES. If ground truth is linear HDR, disable it (`--no-tonemap_aces`) [S1, unofficial].
*   **Sun Below Horizon:** The direct sun term is extinguished using a `smoothstep` gate [S1, unofficial].
*   **Precision:** The sun term must be multiplicative ($T_{sun} \le 1$) because an additive term cannot express the darkening/attenuation caused by atmospheric path length [S1, unofficial].
*   **Data Uniformity:** The training dataset must have uniform sun direction coverage in the hemisphere to prevent geometric shadow gradient bias [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Stage 1 training is comparable to standard 3DGS but with additional light-space rasterization passes for $T_{light}$. Stage 2 inference is real-time, as the environment network is a small MLP and $V_{lm}$ is precomputed [S1, unofficial].
*   **Memory Complexity:** Requires storing physical parameters instead of SH colors. Stage 2 adds storage for `env_net.pt` and `sky_transfer.npy` [S1, unofficial].
*   **Strengths:** Enables arbitrary sun direction relighting in real-time. Physically plausible scattering (extinction, albedo, HG phase function) [S1, unofficial].
*   **Limitations:** Static geometry in the current implementation (time dimension not implemented) [S1, unofficial]. Requires specific dataset generation (UE SkyAtmosphere settings) [S1, unofficial].

## Background
The method is based on 3D Gaussian Splatting (Kerbl et al., 2023) and the 3DGS-Volume-Cloud project [S1, unofficial]. It was developed as an independent 4D implementation workspace, with an initial code baseline at commit `69fea2c8d5a13d6c0e41ac12ca45c80b71bd3403` [S1, unofficial]. It is used in the 4DGS-Volume-Cloud project for real-time rendering and dynamic relighting of volume clouds, based on the WDAS Cloud dataset [S1, unofficial].
