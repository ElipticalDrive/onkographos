# Texture and Appearance Representation


## Overview
Texture and Appearance Representation defines how color and material properties are stored and sampled for 3D Gaussian primitives, addressing the limitations of static, isotropic color vectors in standard 3D Gaussian Splatting (3DGS). It distinguishes itself from sibling methods by decoupling geometric representation from high-fidelity appearance, enabling high-frequency details via explicit textures [S1] or modeling complex view-dependent effects (e.g., specularities) that low-order Spherical Harmonics (SH) cannot capture [S1].

## Shared principles
All child methods extend the standard 3D Gaussian primitive $i$ with additional appearance attributes $\mathbf{a}_i$ beyond the geometric parameters ($\mathbf{\mu}_i, \mathbf{\Sigma}_i$) and opacity $\alpha_i$ [G]. The rendering pipeline retains the front-to-back alpha-blending equation, but the color contribution $c_i$ of each Gaussian is no longer a static vector. Instead, $c_i$ is computed by evaluating an appearance function that queries $\mathbf{a}_i$ using the viewing direction $\mathbf{v}$, surface normal $\mathbf{n}$, or local UV coordinates $\mathbf{u}_i$ [S1]. The final pixel color is calculated as:

$$
C(p) = \sum_{i \in \text{sorted}} c_i(\mathbf{v}, \mathbf{a}_i) \alpha_i \prod_{j=1}^{i-1} (1 - \alpha_j)
$$

where $c_i$ is the color contribution derived from the specific appearance representation [S1]. This approach involves a trade-off between storage bandwidth, computational cost during decoding, and the complexity of the appearance being modeled [S1].

## Subtopics

### [Textured Gaussians](8061-textured-gaussians.md)
Textured Gaussians replace Spherical Harmonic (SH) coefficients with explicit 2D texture maps $T_i$ and local UV coordinates $\mathbf{u}_i$ for each primitive. This resolves artifacts in semi-transparent scenes and enables high-frequency appearance details without increasing the number of primitives. It decouples geometry from appearance, allowing detailed texture sampling based on local UV coordinates.

### [View-Dependent Appearance Representations](14602-view-dependent-appearance-representations.md)
This family addresses the limitation of static isotropic color vectors by modeling view-dependent appearance. It provides a modular framework for various encoding strategies, including fixed basis functions, neural feature vectors, explicit caching structures, and codebook quantization. It distinguishes itself from sibling methods like [Spec-Gaussian](8087-spec-gaussian.md) by offering a generalizable approach to view-dependent effects.

#### View-Dependent Gaussian Splatting
Models 3DGS to represent 3D shapes and predicts attributes like view-dependent color and opacity using a NeRF-like neural network, replacing the Spherical Harmonic (SH) coefficients used in original 3DGS [S1].

#### Neural BRDF for 3D Gaussian Splatting
Simplifies the BRDF to a neural shader that predicts specular and diffuse components directly from the view direction and a learnable material feature [S2, unofficial].

#### Neural Texture Splatting
Encodes textures as small neural networks evaluated at Gaussian coordinates, which can be deformed to model dynamic appearances and fine geometric displacements [S2, unofficial].

## Background
Standard 3D Gaussian Splatting uses low-order SH coefficients for view-dependent color, which often fails to capture high-frequency details or complex specularities [S1]. To address this, methods like [Textured Gaussians](8061-textured-gaussians.md) introduced explicit 2D textures mapped onto primitives to enable high-frequency appearance details without increasing primitive count [S2, unofficial]. Subsequent work, such as [Neural Texture Splatting](14602-view-dependent-appearance-representations.md), further encoded textures as small neural networks to model dynamic appearances [S2, unofficial]. View-dependent modeling also evolved through methods like [View-Dependent Gaussian Splatting](14602-view-dependent-appearance-representations.md), which replaced SH with NeRF-like networks to predict view-dependent attributes [S1].
