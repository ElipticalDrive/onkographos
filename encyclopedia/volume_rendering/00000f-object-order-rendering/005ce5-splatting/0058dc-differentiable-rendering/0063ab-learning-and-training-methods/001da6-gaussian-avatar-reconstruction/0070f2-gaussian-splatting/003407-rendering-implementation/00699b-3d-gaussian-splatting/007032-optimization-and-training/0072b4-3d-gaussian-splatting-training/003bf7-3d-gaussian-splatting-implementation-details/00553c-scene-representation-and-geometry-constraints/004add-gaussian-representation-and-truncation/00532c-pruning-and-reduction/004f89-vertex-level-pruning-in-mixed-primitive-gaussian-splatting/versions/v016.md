# Vertex-level Pruning in Mixed-Primitive Gaussian Splatting

Also called: Mixed-Primitive Vertex Pruning

## Overview
Vertex-level pruning is a refinement mechanism for Mixed-Primitive Gaussian Splatting (MP-GS) that removes redundant vertices from Gaussian triangles and lines during training to reduce storage overhead and simplify the scene representation [S1, unofficial]. Unlike standard 3D Gaussian Splatting which only performs primitive-level opacity pruning, this method dynamically converts primitives into lower-vertex forms (ellipses or lines) based on geometric proximity and collinearity [S1, unofficial]. It complements [Attribute Pruning](18516-attribute-pruning.md) and [SplatQ](14415-splatq.md) by addressing topological redundancy in mixed primitives rather than attribute quantization or opacity thresholds alone.

## How it works
**Inputs and Outputs**
*   **Input:** A set of mixed-primitive Gaussians $\{G_i\}$, where each primitive is either a Gaussian triangle (3 vertices) or a Gaussian line (2 vertices). Each vertex $k$ has a mean position $\boldsymbol{\mu}_k$.
*   **Output:** A pruned set of primitives with reduced vertex counts where applicable.

**Data Structures**
The method operates on the vertex coordinates $\boldsymbol{\mu}$ of the primitives. No additional data structures are required beyond the existing primitive definitions.

**Parameters**
*   $\omega_{dist}$: Threshold for vertex proximity. Default: $0.5$ [S1, unofficial].
*   $\omega_{pear}$: Threshold for collinearity detection. Default: $0.9$ [S1, unofficial].

**Algorithm**
Vertex-level pruning is triggered simultaneously with primitive-level pruning operations [S1, unofficial]. The process evaluates each primitive based on its current vertex configuration:

1.  **Gaussian Triangle Proximity Check:**
    For a Gaussian triangle with vertices $\boldsymbol{\mu}_1, \boldsymbol{\mu}_2, \boldsymbol{\mu}_3$:
    *   Calculate the maximum pairwise L2 distance:
        $$ d_{max} = \max(\|\boldsymbol{\mu}_1 - \boldsymbol{\mu}_2\|_2, \|\boldsymbol{\mu}_2 - \boldsymbol{\mu}_3\|_2, \|\boldsymbol{\mu}_1 - \boldsymbol{\mu}_3\|_2) $$
    *   If $d_{max} < \omega_{dist}$, the vertices are considered "close." Prune vertices $\boldsymbol{\mu}_2$ and $\boldsymbol{\mu}_3$. Convert the primitive into a Gaussian ellipse centered at $\boldsymbol{\mu}_1$ [S1, unofficial].

2.  **Gaussian Triangle Collinearity Check:**
    If the triangle vertices are not close (i.e., $d_{max} \ge \omega_{dist}$):
    *   Compute the Pearson correlation coefficient $r$ from the coordinates of the three vertices.
    *   If $|r| > \omega_{pear}$, the vertices are considered nearly collinear. Convert the Gaussian triangle into a Gaussian line [S1, unofficial].

3.  **Gaussian Line Proximity Check:**
    For a Gaussian line with vertices $\boldsymbol{\mu}_1, \boldsymbol{\mu}_2$:
    *   Calculate the L2 distance:
        $$ d = \|\boldsymbol{\mu}_1 - \boldsymbol{\mu}_2\|_2 $$
    *   If $d < \omega_{dist}$, the vertices are considered "close." Prune vertex $\boldsymbol{\mu}_2$. Reduce the primitive to a Gaussian ellipse centered at $\boldsymbol{\mu}_1$ [S1, unofficial].

**Pseudocode**
```python
def vertex_level_pruning(primitives, omega_dist=0.5, omega_pear=0.9):
    """
    Prunes vertices from mixed-primitive Gaussians based on proximity and collinearity.
    
    Args:
        primitives: List of primitive objects. Each primitive has a type ('triangle' or 'line')
                    and a list of vertex means (numpy arrays).
        omega_dist: Distance threshold for proximity.
        omega_pear: Correlation threshold for collinearity.
    
    Returns:
        List of pruned primitives.
    """
    pruned_primitives = []
    
    for prim in primitives:
        vertices = prim.vertices # List of numpy arrays [mu1, mu2, ...]
        prim_type = prim.type
        
        if prim_type == 'triangle':
            mu1, mu2, mu3 = vertices[0], vertices[1], vertices[2]
            
            # Check 1: Proximity
            dist_12 = np.linalg.norm(mu1 - mu2)
            dist_23 = np.linalg.norm(mu2 - mu3)
            dist_13 = np.linalg.norm(mu1 - mu3)
            max_dist = max(dist_12, dist_23, dist_13)
            
            if max_dist < omega_dist:
                # Convert to ellipse centered at mu1
                new_prim = create_ellipse(center=mu1, covariance=prim.covariance)
                pruned_primitives.append(new_prim)
                continue
            
            # Check 2: Collinearity (only if not close)
            # Compute Pearson correlation coefficient from vertex coordinates
            # Vertices are 3D points; flatten to 1D arrays for correlation
            coords = np.array([mu1, mu2, mu3]) # Shape (3, 3)
            # Pearson correlation across the 3 points
            # Note: Standard pearsonr takes two 1D arrays. 
            # Here we interpret "computed from these vertices" as the correlation 
            # of their positions along the principal axis or pairwise. 
            # Based on source description, we check if they lie on a line.
            # A robust implementation checks if the covariance matrix has rank 1,
            # or uses the correlation of coordinates.
            # Using pairwise correlation magnitude as proxy for collinearity:
            r_12 = np.corrcoef(mu1, mu2)[0, 1]
            r_23 = np.corrcoef(mu2, mu3)[0, 1]
            r_13 = np.corrcoef(mu1, mu3)[0, 1]
            
            # The source says "absolute value of the Pearson correlation coefficient 
            # computed from these vertices". This implies a single metric.
            # Common interpretation for 3 points: correlation of the projection 
            # onto the line defined by the first two points, or max pairwise.
            # We assume max pairwise absolute correlation as a conservative estimate 
            # or the correlation of the flattened coordinate vectors.
            # Given the ambiguity, we use the max absolute pairwise correlation.
            max_abs_corr = max(abs(r_12), abs(r_23), abs(r_13))
            
            if max_abs_corr > omega_pear:
                # Convert to Gaussian line
                # The line should connect mu1 and mu3 (or mu1 and mu2)
                # Assuming mu1 and mu3 are the endpoints if mu2 is intermediate
                new_prim = create_line(start=mu1, end=mu3, covariance=prim.covariance)
                pruned_primitives.append(new_prim)
            else:
                pruned_primitives.append(prim)
                
        elif prim_type == 'line':
            mu1, mu2 = vertices[0], vertices[1]
            dist = np.linalg.norm(mu1 - mu2)
            
            if dist < omega_dist:
                # Reduce to ellipse centered at mu1
                new_prim = create_ellipse(center=mu1, covariance=prim.covariance)
                pruned_primitives.append(new_prim)
            else:
                pruned_primitives.append(prim)
                
    return pruned_primitives
```

**Edge Cases and Pitfalls**
*   **Collinearity Calculation:** The exact method for computing the "Pearson correlation coefficient computed from these vertices" is not explicitly defined in the source text beyond the threshold [S1, unofficial]. Implementers must choose a robust metric (e.g., correlation of projections onto the principal component) to avoid false positives in non-collinear but compact triangles.
*   **Covariance Preservation:** When converting a triangle to a line or ellipse, the covariance matrix must be appropriately transformed or retained to preserve the visual appearance of the splat. The source does not specify the covariance transformation logic [S1, unofficial].
*   **Interaction with Densification:** Pruning is performed alongside densification (cloning and splitting). Pruning must not interfere with the gradient flow required for densification of nearby primitives [S1, unofficial].

## Operating characteristics
*   **Storage Reduction:** The vertex pruning mechanism reduces the average storage size required to store vertex coordinates by 24% compared to the variant without pruning [S1, unofficial].
*   **Performance:** The method adds minimal computational overhead during training as it is triggered only during existing pruning steps. It improves surface reconstruction quality (e.g., Chamfer distance) by reducing "messy" representations [S1, unofficial].
*   **Limitations:** The method relies on heuristic thresholds ($\omega_{dist}, \omega_{pear}$) which may require tuning for different scene scales. It does not reduce the representation to only point-centered ellipses, as densification continues to create new triangles and lines [S1, unofficial].

## Background
Vertex-level pruning was introduced in the Mixed-Primitive-based Gaussian Splatting (MP-GS) method for surface reconstruction [S1, unofficial]. It addresses the limitation of standard 3D Gaussian Splatting, which uses only point-centered primitives, by allowing mixed primitives (triangles, lines) that can become redundant in certain areas of an object [S1, unofficial]. The method was developed to refine the Gaussian Splatting representation by eliminating unnecessary vertices during the learning procedure [S1, unofficial].
