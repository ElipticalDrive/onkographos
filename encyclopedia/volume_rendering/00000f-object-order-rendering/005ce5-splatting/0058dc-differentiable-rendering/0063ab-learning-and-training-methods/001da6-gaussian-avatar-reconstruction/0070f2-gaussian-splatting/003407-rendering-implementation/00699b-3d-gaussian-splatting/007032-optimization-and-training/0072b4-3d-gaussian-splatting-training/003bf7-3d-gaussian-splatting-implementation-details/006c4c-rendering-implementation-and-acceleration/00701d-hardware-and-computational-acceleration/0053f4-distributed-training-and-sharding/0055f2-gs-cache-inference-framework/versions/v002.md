# GS-Cache Inference Framework

Also called: GS-Cache

## Overview
GS-Cache is a holistic rendering framework designed to support real-time rendering of large-scale 3D Gaussian Splatting (3DGS) models, specifically targeting city-level scenes [S1, unofficial]. It achieves an average frame rate exceeding 72 FPS at binocular 2K resolution by employing a cache-centric de-redundancy pipeline and elastic parallel scheduling [S1, unofficial]. Unlike native 3DGS or unstructured methods, GS-Cache specifically targets "Structured Gaussian derivation methods" (such as Scaffold-GS and Octree-GS) that use anchors to derive neural Gaussians, addressing the computational bottleneck of the Gaussian Derivation Stage [S1, unofficial]. It sets itself apart from siblings like BlitzGS by focusing on inter-frame redundancy elimination in the anchor decoding phase rather than just intra-frame rasterization optimization [S1, unofficial].

## How it works
GS-Cache operates on structured Gaussian representations where 3D Gaussians are derived from a smaller set of learnable anchor features via a neural network (typically an MLP) [S1, unofficial]. The pipeline is divided into two distinct stages with different caching strategies:

1.  **Gaussian Derivation Stage:** Decodes anchor features into neural Gaussian parameters. Slight perspective changes cause little color difference here, making it suitable for cache optimization [S1, unofficial].
2.  **Gaussian Rasterization Stage:** Splat 3D neural Gaussians to 2D and rasterize them. Slight perspective changes significantly affect occlusion and visual perception, so this stage is not accelerated by caching to maintain quality [S1, unofficial].

### Inputs and Outputs
*   **Inputs:** Camera parameters (view/projection matrices), current frame index, previous frame cache state.
*   **Outputs:** Rendered image, updated cache state.

### Data Structures
*   **Anchor Set ($X$):** The total set of anchors available for decoding in the current frame.
*   **Cache:** Stores previously decoded Gaussian parameters.
*   **Anchor Indices:** Computed from camera input to filter anchors.
*   **Cache Indices:** Mapped from anchor indices to locate data in the cache.

### Steps
1.  **Anchor Index Computation:** Use camera input to compute anchor indices. These indices filter the anchors that need to be decoded and locate corresponding entries in the cache [S1, unofficial].
2.  **Index Mapping:** Translate anchor indices to cache indices [S1, unofficial].
3.  **Cache Scheduling:** The cache scheduler performs scheduling based on the filtered anchors, loading necessary model parameters for the decoding stage [S1, unofficial].
4.  **Conditional Decoding:**
    *   If an anchor's parameters are present in the cache and the cache depth strategy permits reuse, the cached Gaussian parameters are retrieved [S1, unofficial].
    *   If an anchor is not in the cache or requires re-decoding, its features are decoded simultaneously using the AnchorDecoder (MLP) [S1, unofficial].
5.  **Cache Update:** Results from new decoding computations are updated in the cache. The cache depth is dynamically adjusted based on the heuristic function [S1, unofficial].
6.  **Rasterization:** The retrieved or newly decoded Gaussian parameters are passed to the rasterizer for splatting and compositing [S1, unofficial].

### Formulas
The dynamic cache depth scheduling strategy adjusts the reuse depth based on the intensity of decoding calculations. The expected reuse depth is calculated as:

$$ \text{depth} = H\left(\frac{|X_k'|}{|X|}\right) $$

Where:
*   $\text{depth}$: The expected reuse depth for the current frame.
*   $H$: The guiding function of the heuristic cache reuse depth scheduling strategy [S1, unofficial].
*   $|X_k'|$: The number of newly decoded anchors from the previous $k$ frames [S1, unofficial].
*   $|X|$: The total anchor set for decoding in the current frame [S1, unofficial].
*   $k$: The number of previous frames considered for the update rate calculation [S1, unofficial].

The ratio $\frac{|X_k'|}{|X|}$ represents the update rate. A higher update rate (more new anchors) typically leads to a lower reuse depth (less caching), while a lower update rate allows for deeper caching [S1, unofficial].

### Parameters
*   $k$: Number of previous frames for anchor history [S1, unofficial].
*   $H$: Heuristic guiding function [S1, unofficial].
*   Typical Values: Not given in the sources.

### Edge Cases and Pitfalls
*   **Cache Flush Timing:** If Gaussian appearance parameters are maintained in the cache for too long, significant rendering errors can occur, especially around centered targets or during rapid camera movement [S1, unofficial].
*   **Rapid Appearance Changes:** Static cache reuse depth can cause rapid changes in scene appearance upon cache flushing. The dynamic strategy suppresses this [S1, unofficial].
*   **Quality vs. Speed:** Inter-frame reuse must be restrained to ensure rendering correctness within an acceptable range, as neural Gaussian appearance has viewpoint correlation [S1, unofficial].

## Subtopics

### Structured Gaussian Derivation
Methods like Scaffold-GS and Octree-GS that use anchors to derive neural Gaussians. GS-Cache is optimized for these, unlike native 3DGS [S1, unofficial].

### Dynamic Cache Depth Scheduling
A strategy that adjusts cache reuse depth based on the update rate of anchors, preventing rapid appearance changes and maintaining quality [S1, unofficial].

## Operating characteristics
*   **Performance:** Achieves an average frame rate exceeding 72 FPS at binocular 2K resolution for large-scale city-level scenes [S1, unofficial].
*   **Complexity:** The framework reduces computational redundancy in the Gaussian Derivation Stage, which dominates computation time in structured methods [S1, unofficial].
*   **Strengths:** Enables real-time photo-realistic rendering of large-scale 3DGS models, particularly for VR applications requiring binocular stereo [S1, unofficial].
*   **Limitations:** The rasterization stage cannot be accelerated by caching due to occlusion sensitivity, limiting overall speedup potential [S1, unofficial].
*   **When to use:** Large-scale city-level scenes with structured Gaussian representations where real-time binocular rendering is required [S1, unofficial].
*   **When not to use:** Small-scale scenes or unstructured Gaussian representations where the derivation stage is not the bottleneck [S1, unofficial].

## Background
GS-Cache was introduced in the paper "A GS-Cache Inference Framework for Large-Scale Gaussian Splatting Models" [S1, unofficial]. It addresses the challenges of real-time photo-realistic rendering of large-scale 3DGS models, particularly in VR applications. The framework was developed to support elastic parallel rendering and maintain rendering quality through a dynamic cache strategy [S1, unofficial].
