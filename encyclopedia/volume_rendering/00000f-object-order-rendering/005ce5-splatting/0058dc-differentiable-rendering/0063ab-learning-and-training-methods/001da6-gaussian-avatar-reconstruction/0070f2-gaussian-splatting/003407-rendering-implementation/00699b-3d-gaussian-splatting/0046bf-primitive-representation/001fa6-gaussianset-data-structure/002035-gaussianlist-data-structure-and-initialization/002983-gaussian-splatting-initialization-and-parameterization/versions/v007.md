# Gaussian Splatting Initialization and Parameterization

Also called: 3D Gaussian Splatting Initialization, SfM Initialization, Sparse SfM Initialization, Starter Gaussians, Structure from Motion Initialization

## Overview
This method creates the initial set of 3D Gaussian primitives for training, typically by converting a sparse Structure-from-Motion (SfM) point cloud into learnable Gaussian parameters [S3, S5, S6, unofficial]. It solves the problem of providing a geometrically plausible starting state for differentiable rendering, avoiding the poor reconstruction quality and slow convergence associated with purely random initialization [S6, S7, unofficial]. Unlike siblings that use random large-variance distributions [6129-random-large-variance-initialization.md] or dense MVS clouds [S7, unofficial], this method relies on sparse SfM points to anchor the geometry, allowing the optimizer to create detail during training rather than requiring a dense starting geometry [S7, unofficial].

## How it works
**Inputs:**
*   Sparse 3D point cloud from SfM (e.g., COLMAP), containing positions $\mathbf{p}_i \in \mathbb{R}^3$ and colors $\mathbf{c}_i \in \mathbb{R}^3$ [S5, S7, unofficial].
*   Optional: Depth maps or normal estimates for orientation [S2, unofficial].
*   Hyperparameters: Base distance for scaling, initial opacity logit, SH degree [S5, S7, unofficial].

**Outputs:**
*   A set of $N$ Gaussians with learnable parameters: means $\mathbf{\mu}$, scaling $\mathbf{s}$, rotation quaternions $\mathbf{q}$, opacities $\alpha$ (stored as logits), and spherical harmonic coefficients $\mathbf{f}$ [S5, S7, unofficial].

**Data Structures:**
*   **Means:** Tensor of shape $(N, 3)$, stored as `nn.Parameter` [S5, unofficial].
*   **Scaling:** Tensor of shape $(N, 3)$, stored as `nn.Parameter` [S5, unofficial]. Represents log-scale values.
*   **Rotation:** Tensor of shape $(N, 4)$, stored as `nn.Parameter` [S5, unofficial]. Format $[w, x, y, z]$ [S5, unofficial].
*   **Opacity:** Tensor of shape $(N, 1)$, stored as `nn.Parameter` [S5, unofficial]. Stored as logits.
*   **Features:** Tensor of shape $(N, 1, 3)$ for DC component $\mathbf{f}_{dc}$ and $(N, \frac{(D+1)(D+2)}{2}-1, 3)$ for rest $\mathbf{f}_{rest}$ [S5, unofficial].

**Steps:**

1.  **Position Initialization:** Copy the 3D coordinates from the SfM point cloud directly to the GPU memory for the means tensor $\mathbf{\mu}$ [S1, S7, unofficial].
2.  **Scaling Initialization:**
    *   Compute the distance to the $k$-nearest neighbors (KNN) for each point. Sources vary on $k$: 50 neighbors [S3, unofficial] or mean orientation-aware KNN distance [S2, unofficial].
    *   Calculate `dist2` as the clamped minimum of the KNN distance (min $10^{-7}$) [S5, unofficial].
    *   Compute the pre-activation scale values: $\mathbf{s} = \log(\sqrt{\text{dist2}})$ repeated for x, y, z dimensions [S5, unofficial].
    *   *Alternative:* Use a fixed base distance of 0.1 for all Gaussians [S5, unofficial].
    *   *Alternative (Surface Splatting):* Set isotropic tangent scales to the mean orientation-aware KNN distance multiplied by a scale factor $s_{init} = 1.5$ [S2, unofficial].
3.  **Rotation Initialization:**
    *   *Standard:* Initialize all quaternions to identity $[1, 0, 0, 0]$ [S3, S5, unofficial].
    *   *Surface-Aligned:* If normal maps are available (e.g., from Depth Anything [S2, unofficial]), compute the quaternion that aligns the local z-axis with the estimated surface normal [S2, unofficial].
    *   *Random:* If no SfM normals are used, generate random quaternions using the method from [Sho94]: generate $u, v, w \sim U[0,1]$, then $q_0 = \sqrt{1-u}\sin(2\pi v)$, $q_1 = \sqrt{1-u}\cos(2\pi v)$, $q_2 = \sqrt{u}\sin(2\pi w)$, $q_3 = \sqrt{u}\cos(2\pi w)$ [S1, unofficial].
4.  **Opacity Initialization:**
    *   Initialize pre-activation opacities (logits) to a constant value, typically 8.0 [S3, unofficial] or the logit of 0.1 ($\log(0.1/0.9)$) [S1, unofficial].
    *   Clamp the initial value to the range $[10^{-4}, 0.99]$ before applying the logit function to prevent extreme values [S5, unofficial].
5.  **Color/Feature Initialization:**
    *   Compute the DC component $\mathbf{f}_{dc}$ by converting the SfM point's RGB color (normalized to $[-0.5, 0.5]$) and dividing by the SH basis constant $C_0 = 0.28209479177387814$ [S1, S7, unofficial].
    *   Initialize all higher-order SH coefficients ($\mathbf{f}_{rest}$) to zero [S1, S7, unofficial].
    *   *Alternative (Surface Splatting):* Initialize albedo from point colors, metallic to 0.5, and roughness to 0.1 [S2, unofficial].
6.  **Covariance Construction:**
    *   Construct the diagonal scaling matrix $\mathbf{S} = \text{diag}(\mathbf{s})$ [S5, unofficial].
    *   Convert the quaternion $\mathbf{q}$ to a rotation matrix $\mathbf{R}$ [S5, unofficial].
    *   Compute the 3D covariance matrix: $\Sigma = \mathbf{R} \mathbf{S} \mathbf{S}^T \mathbf{R}^T$ [S5, unofficial].
    *   *Note:* The split into scale and rotation ensures $\Sigma$ remains positive semi-definite [S7, unofficial].

**Pseudocode:**

```python
import torch
import numpy as np

def initialize_gaussians_from_sfm(sfm_points_xyz, sfm_points_rgb, device='cuda'):
    """
    Initialize 3D Gaussians from a sparse SfM point cloud.
    
    Args:
        sfm_points_xyz: (N, 3) array of 3D coordinates.
        sfm_points_rgb: (N, 3) array of RGB colors in [0, 1].
        device: Target device.
        
    Returns:
        Dictionary of initialized parameters.
    """
    N = sfm_points_xyz.shape[0]
    
    # 1. Means
    means = torch.tensor(sfm_points_xyz, dtype=torch.float32, device=device, requires_grad=True)
    
    # 2. Scaling
    # Compute KNN distance (simplified: assume pre-computed dists or use fixed base)
    # Here we use the fixed base distance method from [S5, unofficial] for simplicity, 
    # or replace with actual KNN logic if available.
    base_dist = 0.1
    # dist2 clamped min 1e-7
    dist2 = torch.clamp(torch.tensor(base_dist, device=device), min=1e-7)
    scales = torch.log(torch.sqrt(dist2)) * torch.ones((N, 3), device=device, requires_grad=True)
    
    # 3. Rotation
    # Identity quaternion [w, x, y, z]
    rotations = torch.zeros((N, 4), device=device, requires_grad=True)
    rotations[:, 0] = 1.0
    
    # 4. Opacity
    # Initialize to logit of 0.5, clamped
    init_opacity_val = 0.5
    init_opacity_val = torch.clamp(torch.tensor(init_opacity_val), min=1e-4, max=0.99)
    opacities = torch.logit(init_opacity_val) * torch.ones((N, 1), device=device, requires_grad=True)
    
    # 5. Features (SH)
    # Normalize RGB to [-0.5, 0.5]
    rgb_norm = (torch.tensor(sfm_points_rgb, dtype=torch.float32, device=device) - 0.5)
    C0 = 0.28209479177387814
    f_dc = rgb_norm / C0
    # f_rest is zeros (degree 0 only for initialization)
    f_rest = torch.zeros((N, 0, 3), device=device, requires_grad=True) # Shape depends on SH degree
    
    return {
        'means': means,
        'scaling': scales,
        'rotation': rotations,
        'opacity': opacities,
        'features_dc': f_dc,
        'features_rest': f_rest
    }

def compute_covariance(scaling, rotation):
    """
    Compute 3D covariance matrix from scale and rotation parameters.
    """
    # Scale to diagonal matrix
    # scaling shape: (N, 3)
    S = torch.zeros((scaling.shape[0], 3, 3), device=scaling.device)
    S[:, 0, 0] = scaling[:, 0]
    S[:, 1, 1] = scaling[:, 1]
    S[:, 2, 2] = scaling[:, 2]
    
    # Rotation matrix from quaternion
    # rotation shape: (N, 4) [w, x, y, z]
    R = quaternion_to_rotation_matrix(rotation)
    
    # Sigma = R S S^T R^T
    # Note: S contains log-scales, so we need exp(S) for actual radii
    # However, mini-splat [S5, unofficial] uses scaling directly in the matrix construction 
    # but clamps exp(scaling) later. The formula in [S5, unofficial] implies S is the diagonal matrix of the stored values.
    # Let's follow [S5, unofficial] strictly: S is diagonal of stored scaling values.
    # But physically, scaling represents log-radii. 
    # [S5, unofficial] code: L = diag(scaling), M = R @ L, cov = M @ M^T.
    # Then later: clamp(torch.exp(self._scaling), max=10.0).
    # This implies the covariance is computed using the raw stored values, 
    # and the exponential is applied during rendering or update? 
    # Actually, [S5, unofficial] says: "Compute diagonal scaling matrix L... by placing scaling values... on diagonal."
    # And "Scaling values are clamped to maximum 10.0 after exponential transformation".
    # This suggests the stored value is log-scale, but the covariance uses the scale directly?
    # No, standard 3DGS uses exp(scaling) for the radii. 
    # Let's assume standard interpretation: Radii = exp(scaling).
    
    radii = torch.exp(scaling)
    S_phys = torch.zeros((scaling.shape[0], 3, 3), device=scaling.device)
    S_phys[:, 0, 0] = radii[:, 0]
    S_phys[:, 1, 1] = radii[:, 1]
    S_phys[:, 2, 2] = radii[:, 2]
    
    cov3d = R @ S_phys @ S_phys.transpose(1, 2) @ R.transpose(1, 2)
    return cov3d

def quaternion_to_rotation_matrix(q):
    """
    Convert quaternion [w, x, y, z] to rotation matrix (N, 3, 3).
    """
    # Normalize
    q = torch.nn.functional.normalize(q, dim=1)
    w, x, y, z = q[:, 0], q[:, 1], q[:, 2], q[:, 3]
    
    R = torch.zeros((q.shape[0], 3, 3), device=q.device)
    R[:, 0, 0] = 1 - 2 * (y**2 + z**2)
    R[:, 0, 1] = 2 * (x*y - w*z)
    R[:, 0, 2] = 2 * (x*z + w*y)
    R[:, 1, 0] = 2 * (x*y + w*z)
    R[:, 1, 1] = 1 - 2 * (x**2 + z**2)
    R[:, 1, 2] = 2 * (y*z - w*x)
    R[:, 2, 0] = 2 * (x*z - w*y)
    R[:, 2, 1] = 2 * (y*z + w*x)
    R[:, 2, 2] = 1 - 2 * (x**2 + y**2)
    return R
```

**Parameters:**
*   $C_0$: SH basis constant, $0.28209479177387814$ [S1, unofficial].
*   Base distance for scaling: $0.1$ [S5, unofficial].
*   Initial opacity logit: $8.0$ [S3, unofficial] or $\log(0.1/0.9)$ [S1, unofficial].
*   Numerical stability bias for 2D covariance: $0.3$ [S5, unofficial].
*   Max scaling value: $10.0$ (applied to $\exp(\mathbf{s})$) [S5, unofficial].
*   Default background color: Magenta $[0.6130, 0.0101, 0.3984]$ [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Division by Zero:** In Jacobian computation for projection, add $10^{-7}$ to depth $z$ [S5, unofficial].
*   **Numerical Stability:** Add $0.3$ to the diagonal elements of the 2D covariance matrix to prevent singular matrices [S5, unofficial].
*   **Scaling Limits:** Clamp $\exp(\mathbf{s})$ to a maximum of $10.0$ to prevent excessively large Gaussians [S5, unofficial].
*   **Quaternion Normalization:** Quaternions must be normalized to unit length before converting to rotation matrices [S5, unofficial].
*   **MVS Bias:** Using dense MVS clouds for initialization is discouraged as it wastes time and bakes in MVS errors as starting bias [S7, unofficial].

## Subtopics

### [Random Large-Variance Initialization](6129-random-large-variance-initialization.md)
Relaxes the SfM assumption by using sparse, large-variance random initialization, useful when SfM data is sparse or absent.

### [Temporal Point Cloud Initialization via Chamfer Distance Minimization](6954-temporal-point-cloud-initialization-via-chamfer-distance-min.md)
Uses the learned model from the previous frame to initialize the current frame, leveraging temporal correlation.

### [Gaussian Geometry Parameters Prediction](8442-gaussian-geometry-parameters-prediction.md)
Predicts geometry (position, opacity, covariance) in a feed-forward manner using a global volumetric representation to reduce ghosting.

### [Background Hemisphere Initialization](8446-background-hemisphere-initialization.md)
Models the distant background (sky) as a separate hemisphere of Gaussians to avoid occlusion errors.

### [ReSplat Initialization](10957-resplat-initialization.md)
Predicts initial Gaussians from a sparse point cloud using a transformer-based encoder to enrich features with neighborhood context.

### [Point Cloud/Mesh-based Initialization](16343-point-cloud-mesh-based-initialization.md)
Initializes Gaussians using pre-existing dense 3D geometry (point clouds or meshes) when multi-view images are unavailable.

### Neural Point Cloud Initialization from COLMAP
A method for Point-NeRF where the variance parameter $\gamma_i$ is initialized to 0.3 for each point $p_i$. Features $f_i$ are acquired by finding the closest view where the point is not occluded and unprojecting onto the feature map [S8].

### Binary Gaussian Hierarchy Construction
A hierarchy where leaf nodes contain full Gaussian properties and internal nodes store merged approximations of their children [S9, unofficial].

### Single Ellipsoid Initialization
Initializes a single ellipsoid from 3D points using PCA. Minimum radius $r_{\min} = 0.005$ and scaling factor $\alpha = 3$ are typical values [S10].

### MVS-guided Initialization
Aggregates filtered multiview depth maps into a 3D point cloud. Prunes noisy Gaussians by freezing centers and optimizing other parameters for $N_{prun}$ iterations, removing those with opacity $\alpha_k < \tau$. Then unfreezes all parameters [S11].

### Feature Initialization
Initializes base feature $f_{base}$ and directional feature $f_{dir}$ with RGB colors of SfM points. Temporal feature $f_{time}$ is initialized to a zero vector [S12].

## Operating characteristics
*   **Time Complexity:** Initialization time is dominated by the SfM process. COLMAP initialization takes approximately 6.0 minutes, compared to 0.1 seconds for random initialization [S4, unofficial].
*   **Memory Complexity:** Linear in the number of points $N$. Parameters are stored as dense tensors [S5, unofficial].
*   **Performance:** SfM initialization yields significantly higher PSNR (e.g., 26.05 on Average-30K) compared to random initialization (20.42) [S6, unofficial]. EndoGaussian's method achieves 37.849 PSNR with 2.0s init time [S4, unofficial].
*   **Strengths:** Provides geometrically accurate starting points, improving reconstruction quality and convergence speed [S6, S7, unofficial].
*   **Limitations:** Requires a successful SfM reconstruction. Dense MVS initialization is discouraged due to bias and wasted time [S7, unofficial].

## Background
The method originates from the original 3D Gaussian Splatting paper, which proposed initializing directly from sparse SfM points rather than dense MVS clouds [S7, unofficial]. This approach leverages the optimizer's ability to create detail during training, avoiding the errors inherent in dense reconstruction pipelines [S7, unofficial]. It has since been adapted in various forms, such as using depth normals for orientation [S2, unofficial] or predicting geometry via neural networks [S2, unofficial][S12].
