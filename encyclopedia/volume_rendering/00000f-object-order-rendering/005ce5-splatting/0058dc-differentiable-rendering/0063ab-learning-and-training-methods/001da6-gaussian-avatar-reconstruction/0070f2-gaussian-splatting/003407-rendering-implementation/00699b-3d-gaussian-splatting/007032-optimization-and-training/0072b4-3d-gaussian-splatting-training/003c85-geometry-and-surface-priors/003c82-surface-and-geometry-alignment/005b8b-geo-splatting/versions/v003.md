# Geo-Splatting


## Overview
Geo-Splatting is a physically-based inverse rendering method that augments 3D Gaussian Splatting (3DGS) with explicit geometric guidance to improve normal estimation and light transport modeling [S2]. It addresses the inaccuracies in material decomposition and relighting caused by the approximated normals and semi-transparent nature of standard Gaussian points [S2]. Unlike sibling methods like [SuGaR](9191-sugar.md) which rely on implicit geometric constraints or approximated normals, Geo-Splatting differentiably constructs surface-aligned Gaussian points from an optimizable explicit mesh, leveraging well-defined mesh normals and an opaque mesh surface for accurate light transport [S2].

## How it works
**Inputs:** Multi-view images and camera poses [S2].
**Outputs:** Optimized 3D Gaussian parameters (centers, covariances, colors, opacities), explicit triangular mesh, material properties (albedo, roughness, normal), and environment light [S2].

**Data Structures:**
1. **Learnable Isovalue Grid:** A 3D scalar field representing the implicit surface distance function [S2].
2. **Triangular Mesh:** Extracted from the isovalue grid using FlexiCubes [S2].
3. **3D Gaussian Points:** Structured points generated on the mesh surface [S2]. Each Gaussian $i$ is defined by center $\mathbf{c}_i$, covariance $\mathbf{\Sigma}_i$ (decomposed into scale $\mathbf{S}_i$ and rotation $\mathbf{R}_i$), opacity $\alpha_i$, and spherical harmonic coefficients for color/view-dependent appearance [S2].
4. **BVH (Bounding Volume Hierarchy):** Acceleration structure built on the explicit mesh for ray tracing [S2].

**Steps:**

1. **Geometry Extraction:**
    Extract an intermediate triangular mesh from the learnable isovalue grids using FlexiCubes [S2]. This provides an explicit, differentiable geometric prior [S2].

2. **Gaussian Generation (MGadapter):**
    Use the Mesh-to-Gaussian adaptor (MGadapter) to generate 3DGS points on the mesh surface in a differentiable manner [S2]. This ensures that Gaussian centers lie on the mesh surface and their orientations align with the mesh normals [S2]. This step differentiably constructs structured Gaussian points grounded on the mesh geometry [S2].

3. **Light Transport Evaluation:**
    Perform BVH-accelerated ray tracing on the extracted mesh to evaluate light transport [S2]. This step accounts for self-occlusion and inter-reflection, which split-sum approximations lack [S2]. Monte Carlo sampling is used to evaluate the rendering equation [19] on the explicit mesh proxy [S2].

4. **PBR Color Computation:**
    Compute per-Gaussian physically-based rendering (PBR) colors by evaluating the rendering equation [19] using the light transport results and material properties (albedo, roughness, normal) [S2].

5. **Rendering:**
    Composite the shaded Gaussian points into final images using the standard 3DGS rasterization algorithm [S2].

6. **Optimization:**
    Optimize the Gaussian parameters, mesh, and material properties end-to-end by minimizing the total loss:
    $$ \mathcal{L}_{total} = \mathcal{L}_{rgb} + \lambda_{geo} \mathcal{L}_{geo} + \lambda_{norm} \mathcal{L}_{norm} $$
    where $\mathcal{L}_{rgb}$ is the photometric loss, $\mathcal{L}_{geo}$ is the geometric consistency loss, and $\mathcal{L}_{norm}$ is the normal consistency loss [S1, unofficial]. The weights $\lambda_{geo}$ and $\lambda_{norm}$ balance photometric fidelity against geometric accuracy [S1, unofficial].

**Pseudocode:**

```python
# Initialization
isovalue_grid = zeros(shape=(grid_res, grid_res, grid_res))  # Learnable 3D scalar field [G]
mesh = flexicubes_extract(isovalue_grid)  # Isosurface extraction from scalar field [S2]
gaussians = mgadapter_generate(mesh)      # Differentiable mesh-to-Gaussian conversion [S2]
bvh = build_bvh(mesh.vertices, mesh.faces) # Bounding Volume Hierarchy construction [S2]
materials = initialize_materials(len(gaussians)) # Albedo, roughness, normal per Gaussian [S2]
light_probe = initialize_environment_light() # Environment light probe [S2]

# Optimization Loop
for step in range(10000):  # Typical training steps [G]
    # 1. Render Image
    rays = generate_camera_rays(camera_poses)  # Cast rays from camera poses [G]
    light_transport = trace_mesh_rays(bvh, rays) # BVH-accelerated ray tracing on mesh [S2]
    
    for g in gaussians:
        # Compute PBR colors using Monte Carlo sampling on mesh proxy [S2]
        g.color = evaluate_pbr(materials[g.id], light_transport, g.normal, light_probe)
        
    rendered_image = rasterize_gaussians(gaussians) # Standard 3DGS alpha blending [S2]
    
    # 2. Compute Losses
    loss_rgb = mean_squared_error(rendered_image, target_image)
    loss_geo = geometric_loss(gaussians.center, mesh.vertices) # Positional consistency [S1, unofficial]
    loss_norm = normal_loss(gaussians.normal, mesh.face_normals) # Normal consistency [S1, unofficial]
    
    total_loss = loss_rgb + lambda_geo * loss_geo + lambda_norm * loss_norm
    
    # 3. Backpropagate
    total_loss.backward()
    optimizer.step()
    optimizer.zero_grad()

# Helper Definitions
def flexicubes_extract(grid): return extract_isosurface(grid)  # [S2]
def mgadapter_generate(mesh): return generate_gaussians_on_surface(mesh)  # [S2]
def build_bvh(vertices, faces): return construct_bvh_acceleration_structure(vertices, faces)  # [S2]
def generate_camera_rays(poses): return cast_rays_from_cameras(poses)  # [G]
def trace_mesh_rays(bvh, rays): return trace_rays_through_bvh(bvh, rays)  # [S2]
def evaluate_pbr(mat, transport, normal, light): return monte_carlo_rendering(mat, transport, normal, light)  # [S2]
def rasterize_gaussians(gaussians): return alpha_blend_gaussians(gaussians)  # [S2]
def mean_squared_error(pred, target): return sum((pred - target)**2) / len(pred)  # [G]
def geometric_loss(centers, vertices): return sum(min_dist(c, vertices) for c in centers)  # [S1, unofficial]
def normal_loss(normals, mesh_normals): return sum(1 - dot(n, nearest_normal(n, mesh_normals)) for n in normals)  # [S1, unofficial]
```

**Parameters:**
*   $\lambda_{geo}, \lambda_{norm}$: Hyperparameters for loss weighting [S1, unofficial]. Values not given in the sources.
*   FlexiCubes: Used for isosurface extraction [S2].
*   MGadapter: Differentiable module for mesh-to-Gaussian conversion [S2].

**Edge Cases and Pitfalls:**
*   Existing 3DGS-based inverse methods suffer from inaccuracies in normal estimation due to approximated normals and semi-transparent Gaussian points, leading to noisy material decomposition and flawed relighting [S2]. Geo-Splatting mitigates this by using explicit mesh normals [S2].
*   Split-sum approximation lacks self-occlusion modeling, leading to inaccurate decomposition under strong shadow effects [S2]. Geo-Splatting uses ray tracing to handle this [S2].
*   Spherical Gaussian (SG) methods struggle with reflective cases due to low-frequency nature [S2]. Geo-Splatting uses Monte Carlo sampling with ray tracing on an explicit mesh proxy to handle reflective surfaces [S2].

## Operating characteristics
*   **Time Complexity:** Training time is 9 minutes on the reported dataset, compared to 56 minutes for R3DG and 13 minutes for GS-IR [S2]. This efficiency is attributed to the use of BVH-accelerated ray tracing on the explicit mesh proxy rather than direct ray tracing on 3D Gaussians [S2].
*   **Memory Complexity:** Not given in the sources [S2].
*   **Performance:** Relighting PSNR of 29.5dB, compared to 26.6dB for R3DG and 20.4dB for GS-IR [S2].
*   **Strengths:** Superior decomposition and relighting quality; excellent training efficiency; accurate light transport modeling via explicit mesh normals and ray tracing; handles self-occlusion and reflective surfaces [S2].
*   **Limitations:** Requires explicit mesh extraction and BVH construction; relies on the quality of the initial isovalue grid and FlexiCubes extraction [S2].
*   **When to use:** When high-fidelity material decomposition and relighting are required, especially in scenes with strong shadows or reflective surfaces [S2].
*   **When not to use:** When computational resources for BVH construction and ray tracing are limited, or when simple photometric reconstruction without physical accuracy is sufficient [S2].

## Background
Geo-Splatting was proposed by Wenzheng Chen, Guanbin Li, et al. from Sun Yat-sen University and Peking University [S2]. It was published in ICCV 2025 [S2]. The work addresses limitations in existing 3DGS-based inverse rendering methods like R3DG and GS-IR, which rely on approximated normals and split-sum approximations [S2]. It builds on prior works in isosurface extraction [41] and physically-based rendering [19] [S2].
