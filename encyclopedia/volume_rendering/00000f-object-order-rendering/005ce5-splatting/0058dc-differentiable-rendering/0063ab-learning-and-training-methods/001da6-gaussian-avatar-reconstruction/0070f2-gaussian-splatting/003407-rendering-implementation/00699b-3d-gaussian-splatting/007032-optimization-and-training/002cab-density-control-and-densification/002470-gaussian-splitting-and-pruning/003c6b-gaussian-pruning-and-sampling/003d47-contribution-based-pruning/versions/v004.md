# Contribution-based Pruning

Also called: Opacity and Scale Pruning, Quantile-based Pruning, Gaussian Culling, Point Pruning, Regularization via Pruning

## Overview
Contribution-based Pruning is a density control strategy for 3D Gaussian Splatting that removes redundant primitives by jointly evaluating their opacity and spatial scale attributes [S2, unofficial]. It solves the problem of excessive Gaussian count and memory usage by culling Gaussians that contribute negligibly to the final image, balancing rendering quality with computational efficiency [S2, unofficial]. It differs from its parent, [Gaussian Pruning and Sampling](9219-gaussian-pruning-and-sampling.md), by using a specific multi-attribute quantile threshold rather than a generic accumulated blending weight score [S2, unofficial]. It differs from [Opacity Pruning](14627-opacity-pruning.md) by incorporating scale statistics to prevent the removal of large, transparent primitives that may still occupy significant spatial volume, making it less aggressive than opacity-only baselines [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** The set of Gaussian primitives $\mathcal{G}$ at iteration $t$, each with learned opacity $o_g$ and scale parameters (diagonal covariance $\Sigma_g$ or axis-aligned scales).
*   **Output:** A pruned set of Gaussians $\mathcal{G}_{\text{new}}$ with reduced cardinality.

**Data Structures:**
*   **Gaussian Attributes:** Each Gaussian $g$ stores scalar opacity $o_g \in [0, 1]$ and scale parameters. The maximum scale $s_{\max}(g)$ is derived from the scale parameters (e.g., the maximum eigenvalue of the covariance matrix or the maximum diagonal element in axis-aligned representation) [S2, unofficial].
*   **Vote Counter:** An integer array $V$ of size $|\mathcal{G}|$, initialized to zero, tracking how many pruning intervals a Gaussian has been identified as a candidate [S2, unofficial].

**Parameters:**
*   **Pruning Threshold ($\tau$):** The quantile level used to identify low-contributing Gaussians. A value of $\tau = 0.2$ is typical, providing a balance between quality and efficiency [S2, unofficial].
*   **Pruning Interval ($I_{\text{prune}}$):** The number of training iterations between pruning checks. Typical value: 1000 [S2, unofficial].
*   **Vote Threshold ($v$):** The number of times a Gaussian must be identified as a candidate before permanent removal. Typical value: 0.6 (interpreted as a fraction of the interval or a fixed count depending on implementation; the source formula uses $I_{\text{prune}} \cdot v$) [S2, unofficial].

**Steps:**
1.  **Compute Statistics:** At iteration $t$, compute the opacity $o_g$ and maximum scale $s_{\max}(g)$ for all Gaussians $g \in \mathcal{G}$ [S2, unofficial].
2.  **Identify Candidates:** Determine the set of opacity candidates $\mathcal{C}_{\text{opacity}}^{(t)}$ and scale candidates $\mathcal{C}_{\text{scale}}^{(t)}$ using the $\tau$-quantile operator $Q_\tau(\cdot)$ [S2, unofficial]:
    $$ \mathcal{C}_{\text{opacity}}^{(t)} = \{g \in \mathcal{G} \mid o_g < Q_\tau(o)\} $$
    $$ \mathcal{C}_{\text{scale}}^{(t)} = \{g \in \mathcal{G} \mid s_{\max}(g) < Q_\tau(s_{\max})\} $$
    The pruning candidate set is the intersection:
    $$ \mathcal{C}_{\text{prune}}^{(t)} = \mathcal{C}_{\text{opacity}}^{(t)} \cap \mathcal{C}_{\text{scale}}^{(t)} $$
    [S2, unofficial].
3.  **Accumulate Votes:** Update the vote count for each Gaussian. If $g \in \mathcal{C}_{\text{prune}}^{(t)}$, increment its vote count [S2, unofficial]:
    $$ V_g^{(t+1)} = V_g^{(t)} + \mathbf{1}_{\{g \in \mathcal{C}_{\text{prune}}^{(t)}\}} $$
    where $\mathbf{1}$ is the indicator function and $V_g^{(0)} = 0$ [S2, unofficial].
4.  **Prune:** If the current iteration $t$ is a multiple of $I_{\text{prune}}$, permanently remove all Gaussians $g$ where $V_g^{(t)} > I_{\text{prune}} \cdot v$ [S2, unofficial]. The updated set is $\mathcal{G}_{\text{new}} = \mathcal{G} \setminus \{g \mid V_g^{(t)} > I_{\text{prune}} \cdot v\}$ [S2, unofficial].
5.  **Reset Votes (Implicit):** After pruning, votes for remaining Gaussians are typically reset or the counter continues; the source implies a continuous accumulation relative to the interval [S2, unofficial]. Note: Some variants apply this only during the initial 25k iterations to prevent excessive removal in later stages [S2, unofficial].

**Pseudocode:**
```python
def contribution_based_pruning(Gaussians, tau, I_prune, v, current_iter):
    """
    Gaussians: List of Gaussian objects with attributes .opacity and .max_scale
    tau: Quantile threshold (e.g., 0.2)
    I_prune: Pruning interval (e.g., 1000)
    v: Vote threshold multiplier (e.g., 0.6)
    current_iter: Current training iteration number
    """
    if len(Gaussians) == 0:
        return Gaussians

    # Step 1 & 2: Identify candidates based on quantiles
    opacities = [g.opacity for g in Gaussians]
    scales = [g.max_scale for g in Gaussians]
    
    # Calculate tau-quantile thresholds
    # Note: Q_tau(x) is the value below which tau fraction of data falls
    opacity_threshold = quantile(opacities, tau)
    scale_threshold = quantile(scales, tau)
    
    candidates = []
    for g in Gaussians:
        if g.opacity < opacity_threshold and g.max_scale < scale_threshold:
            candidates.append(g)
            
    # Step 3: Accumulate votes
    # Assuming Gaussians have a .vote_count attribute initialized to 0
    for g in Gaussians:
        if g in candidates:
            g.vote_count += 1
            
    # Step 4: Prune if interval reached
    if current_iter > 0 and current_iter % I_prune == 0:
        # Threshold for removal
        removal_threshold = I_prune * v
        
        # Remove Gaussians exceeding vote threshold
        # Note: In-place removal requires care; creating new list is safer
        pruned_gaussians = []
        for g in Gaussians:
            if g.vote_count <= removal_threshold:
                pruned_gaussians.append(g)
            else:
                # Optional: Reset vote count for remaining or keep accumulating?
                # Source implies permanent pruning, so we just drop them.
                pass
                
        Gaussians = pruned_gaussians
        
    return Gaussians

def quantile(values, tau):
    """Helper to compute tau-quantile"""
    sorted_vals = sorted(values)
    index = int(tau * len(sorted_vals))
    index = min(index, len(sorted_vals) - 1)
    return sorted_vals[index]
```

**Edge Cases and Pitfalls:**
*   **Early Training Noise:** Opacity and scale values can fluctuate significantly during early training. Immediate pruning based on a single iteration can remove valid primitives. The vote accumulation mechanism mitigates this [S2, unofficial].
*   **Joint vs. Single Attribute:** Pruning based solely on opacity or scale leads to substantial performance degradation compared to using both jointly. Opacity reflects visibility, while scale captures spatial influence; using only one misses redundant primitives that are either small but opaque or large but transparent [S2, unofficial].
*   **Late Stage Removal:** Pruning should be restricted to early training (e.g., first 25k iterations) to avoid removing Gaussians needed for fine details in later stages [S2, unofficial].

## Subtopics

### Accumulated Vote Pruning
A pruning strategy that mitigates noisy fluctuations in opacity or scale during early training by accumulating votes for Gaussians selected as pruning candidates, rather than removing them immediately [S2, unofficial]. It uses the same candidate identification logic ($\mathcal{C}_{\text{prune}}^{(t)} = \mathcal{C}_{\text{opacity}}^{(t)} \cap \mathcal{C}_{\text{scale}}^{(t)}$) but delays permanent removal until the accumulated vote count $V_g^{(t)}$ exceeds $I_{\text{prune}} \cdot v$ [S2, unofficial]. This ensures that only consistently low-contributing Gaussians are removed [S2, unofficial].

### Distribution-based Pruning
A strategy to remove redundant Gaussian primitives and improve efficiency by applying pruning only during the initial 25k iterations to prevent excessive removal in later stages [S2, unofficial]. It uses specific hyperparameters: pruning interval $I_{\text{prune}} = 1000$, vote threshold parameter $v = 0.6$, and redundancy identification threshold $\tau = 0.2$ [S2, unofficial]. This design allows the model to retain representation capacity while substantially reducing unnecessary primitives in early training [S2, unofficial].

### θ+Opacity Rule Pruning
A pruning rule based on theta and opacity that localizes sacrifice at city scale, serving as a complementary export to the score-based export [S3, unofficial]. It is a baseline pruning method compared against score-based exports [S3, unofficial]. At extreme budgets (e.g., 10% primitives), it achieves the best LPIPS scores (e.g., 0.547 vs 0.557 for score export), consistent with its design of removing perceptually redundant mass [S3, unofficial]. However, it may blur fine details like street markings compared to score-based methods [S3, unofficial].

### Iterative Pruning
Removes Gaussian points in multiple sequential iterations to reduce model size while maintaining visual quality [S4]. It involves a schedule of pruning rates (e.g., 0.4 for Iter1-3, then selecting 0.2 for Iter4 based on quality tradeoffs) followed by fine-tuning [S4]. This approach removes up to 87% of points with an average PSNR drop of only 0.23 dB, offering a better quality-size tradeoff than single-pass pruning by adapting to the remaining point distribution [S4].

### GTC-guided Shrinking
A strategy to reduce rendering redundancy by pruning Gaussian-tile pairs based on a Gaussian Tile Contribution (GTC) metric, guided by a scaling factor $\lambda_G$ [S5, unofficial]. It uses a scene-adaptive shrinking threshold $\tau$ determined by the GTC metric, unlike fixed thresholds in other methods [S5, unofficial]. Typical $\lambda_G$ is 0.2 [S5, unofficial]. It preserves high-frequency regions (dense, structurally meaningful Gaussians) while removing redundant low-frequency Gaussians, achieving a 20% FPS improvement with 1% PSNR degradation [S5, unofficial]. A pitfall is visible tile boundaries in low-frequency regions (roads, sand) as $\lambda_G$ increases [S5, unofficial].

### Greedy Selection
A selection algorithm that deletes Gaussians one by one, choosing the one that causes the smallest increase in the unpenalized deletion cost, until the target count is reached [S6, unofficial]. It calculates the cost increment for retaining member $j$ as $\Delta_{\text{add}}(j) = 2(Rz)_j + R_{jj}$ and selects the minimum [S6, unofficial]. It satisfies the count constraint by construction without requiring a count penalty coefficient $\lambda$ [S6, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
*   **Time:** The pruning step involves sorting or selecting quantiles ($O(N \log N)$ or $O(N)$) and iterating over the Gaussian set ($O(N)$). With vote accumulation, the per-iteration cost is low, but the pruning event itself is $O(N)$. Iterative pruning adds multiple $O(N)$ passes [S4][S6, unofficial].
*   **Memory:** Reduces memory usage by decreasing the number of Gaussians stored. For example, on Mobile-GS, it reduces Gaussian count from 0.56M to 0.47M, lowering storage costs [S2, unofficial].

**Measured Performance:**
*   On Mobile-GS (Snapdragon 8 Gen 3 GPU), applying pruning with $\tau=0.2$ reduces Gaussians from 0.56M to 0.47M, maintains PSNR (27.12 vs 27.22), and increases FPS from 109 to 127 [S2, unofficial].
*   Iterative pruning removes 87% of points with an average PSNR drop of 0.23 dB [S4].
*   GTC-guided shrinking achieves a 20% FPS improvement with 1% PSNR degradation [S5, unofficial].

**Strengths and Limitations:**
*   **Strengths:** Effectively reduces computational overhead and memory usage with minimal quality loss when both opacity and scale are used [S2, unofficial]. The vote accumulation mechanism prevents premature removal of valid primitives [S2, unofficial].
*   **Limitations:** Pruning based on a single attribute (opacity or scale) leads to significant quality degradation [S2, unofficial]. Aggressive shrinking (high $\lambda_G$ in GTC-guided) can cause visible artifacts in low-frequency regions [S5, unofficial].

**When to Use:**
*   Use when computational resources are limited (e.g., mobile devices) or when training time/memory is a bottleneck [S2, unofficial].
*   Use when integrating with other compression methods (e.g., quantization) to further reduce size [S2, unofficial].
*   Avoid using single-attribute pruning if quality is critical [S2, unofficial].

## Background
Contribution-based Pruning was introduced as part of the Mobile-GS framework for real-time Gaussian Splatting on mobile devices [S2, unofficial]. It addresses the high computational and memory demands of 3D Gaussian Splatting by identifying and removing redundant primitives based on their learned opacity and spatial scale [S2, unofficial]. The method builds on the insight that Gaussians with low opacity and small scale contribute negligibly to the rendered image [S2, unofficial]. It has been integrated into various lightweight GS variants and compared against other pruning strategies like LightGaussian and RAP [S3, unofficial][S4].
