# Large Reconstruction Model (LRM)
## Overview
Large Reconstruction Model (LRM) is a feedforward transformer-based method for single-image or multi-view to 3D reconstruction that outputs a triplane neural representation in a single forward pass [S1, unofficial][S3, unofficial]. It solves the problem of slow, per-scene optimization in traditional neural rendering by learning 3D priors from large-scale datasets, enabling real-time reconstruction [S1, unofficial][S3, unofficial]. It sets itself apart from its siblings by using a triplane representation as the primary output, whereas [Flash3D](1481-flash3d.md) and [GS-LRM](1483-gs-lrm.md) predict 3D Gaussians directly, and [Reconstruction-based Generation](11811-reconstruction-based-generation.md) focuses on generation pipelines rather than direct reconstruction [S1, unofficial].
## How it works
**Inputs and Outputs:**
- Input: A single image $I$ or a viewset $V=\{I_i\}_{i=1}^N$ with corresponding camera parameters $\{\pi_i\}_{i=1}^N$ [S2].
- Output: A triplane neural representation $\theta$ [S1, unofficial][S2].
- Final Render: Novel view images $\hat{I} = R(\theta, \pi)$ [S2].

**Data Structures:**
- **Trplane Representation $\theta$**: A 3D feature field represented by three 2D planes (XY, YZ, XZ) [S2]. The exact bit-packing or resolution of the triplane is not given in the sources [S2].
- **Transformer Blocks**: A series of transformer blocks process the input features [S2].
- **Splatter Layer**: A component that splats source view features into a new triplane [S2].

**Steps:**
1. **Feature Extraction**: Extract a pixel-wise feature map $\mathbf{v}=\psi(I_i)$ from each image $I_i$ in the input viewset [S2].
2. **Lifting with Splatter**: Lift the feature maps into an intermediate 3D representation $\tilde{\theta}$ using the Splatter component [S2].
3. **Transformer Processing**: Input $\tilde{\theta}$ into the large-scale model $\Phi$ (a transformer) to output the final 3D representations $\theta=\Phi_\theta(\tilde{\theta})$ [S2].
   - The Splatter layer is inserted every 3 transformer blocks (i.e., 5 blocks in total) [S2].
   - The Splatter layer takes previous block outputs as prior shape encoding [S2].
4. **Rendering**: Output novel view images $\hat{I} = R(\theta, \pi)$ from $\theta$ using the Renderer component [S2].
5. **Training**: Train the model by minimizing the loss $L$ between the novel rendered image $\hat{I}$ and the corresponding ground truth $I$ [S2].

**Formulas:**
- Feature extraction: $\mathbf{v}=\psi(I_i)$ [S2].
- Intermediate representation: $\tilde{\theta} = \text{Splatter}(\mathbf{v})$ [S2].
- Final representation: $\theta=\Phi_\theta(\tilde{\theta})$ [S2].
- Rendering: $\hat{I} = R(\theta, \pi)$ [S2].
- Loss: $L(\hat{I}, I)$ [S2].

**Parameters:**
- **Dataset**: Trained on Objaverse + Objaverse-XL [S1, unofficial].
- **Transformer Blocks**: 5 blocks in total, with Splatter inserted every 3 blocks [S2].
- **LPIPS Optimization**: Enabled in the Lightplane-augmented LRM to avoid deferred backpropagation complexity [S2].
- **Resolution**: Training uses low-resolution images (64x64) for some losses, but high-resolution rendering is supported [S2].

**Edge Cases and Pitfalls:**
- **Multi-view Input**: The method supports multi-view inputs, but the specific handling of camera pose errors or inconsistent views is not detailed [S2].
- **Memory Efficiency**: The memory efficiency of the renderer allows for high-resolution rendering and image-level losses, which is a key advantage over the original LRM's deferred backpropagation [S2].

**Pseudocode:**
```python
def LRM_forward(viewset, cameras):
    # Step 1: Feature Extraction
    # Extract pixel-wise feature map v = psi(I_i) from each image I_i [S2]
    feature_maps = []
    for I in viewset:
        v = extract_features(I)
        feature_maps.append(v)

    # Step 2: Lifting with Splatter
    # Lift feature maps into intermediate 3D representation theta_tilde [S2]
    theta_tilde = splat_to_triplane(feature_maps, cameras)

    # Step 3: Transformer Processing
    # Input theta_tilde into model Phi to output final 3D representations theta = Phi_theta(theta_tilde) [S2]
    theta = theta_tilde
    for block_idx in range(5):
        theta = transformer_layer(theta)
        # Insert Splatter layer every 3 transformer blocks (i.e., 5 blocks in total) [S2]
        if (block_idx + 1) % 3 == 0:
            theta = splat_to_triplane(theta, cameras)

    # Step 4: Rendering
    # Output novel view images I_hat = R(theta, pi) from theta [S2]
    rendered_image = render_triplane(theta, cameras[0])

    return rendered_image, theta

def LRM_loss(rendered_image, ground_truth_image):
    # Train the model by minimizing the loss L between the novel rendered image and ground truth I [S2]
    loss = compute_loss(rendered_image, ground_truth_image)
    return loss

# Helper definitions [G]
```

## Subtopics

### [Large Gaussian Reconstruction Model (GRM)](5961-large-gaussian-reconstruction-model-grm.md)
The Large Gaussian Reconstruction Model (GRM) is a feedforward neural network for single-image or multi-view to 3D reconstruction that directly predicts Gaussian maps. It builds on [Large Reconstruction Model (LRM)](5959-large-reconstruction-model-lrm.md) by replacing its output format with Gaussian primitives, supporting both single and multi-view inputs.

## Operating characteristics
- **Time Complexity**: Feedforward model, single transformer pass, enabling real-time reconstruction [S1, unofficial][S3, unofficial].
- **Memory Complexity**: Memory efficient due to the Lightplane renderer, allowing high-resolution rendering and image-level losses without deferred backpropagation [S2].
- **Measured Performance**: Outperforms baseline ViewFormer [41] and overfitting baselines like Voxel and NeRF [S2]. Table 2 in [S2] reports metrics such as 0.113, 0.904, and inference times of 1.6 sec to 2.5 sec for comparable methods.
- **Scaling**: Highly scalable components for neural 3D fields [S2].
- **Strengths**: Real-time reconstruction, high-resolution rendering, memory efficiency, support for multi-view inputs [S1, unofficial][S2][S3, unofficial].
- **Limitations**: Relies on large-scale datasets (Objaverse + Objaverse-XL) for training [S1, unofficial].
- **When to use**: When real-time 3D reconstruction from single or multi-view images is required [S1, unofficial][S3, unofficial].
- **When not to use**: When high-fidelity per-scene optimization is required, or when the input data does not match the training distribution [S2].
## Background
- **Origin**: LRM was introduced by Adobe in 2023 [S1, unofficial].
- **History**: It represents a shift from per-scene optimization to feedforward models for 3D reconstruction [S1, unofficial].
- **Usage**: Used for single-image to 3D reconstruction and generation [S1, unofficial][S3, unofficial].
