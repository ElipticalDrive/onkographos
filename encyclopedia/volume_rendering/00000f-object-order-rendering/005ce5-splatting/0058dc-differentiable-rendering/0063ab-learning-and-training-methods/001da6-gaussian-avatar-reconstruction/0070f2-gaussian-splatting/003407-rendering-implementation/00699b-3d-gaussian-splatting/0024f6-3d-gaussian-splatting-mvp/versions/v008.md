# 3D Gaussian Splatting MVP

Also called: 3DGS MVP, pure PyTorch 3DGS

## Overview
3D Gaussian Splatting MVP is a self-contained, pure-PyTorch implementation of the core 3D Gaussian Splatting rendering algorithm, designed as a teaching reference rather than a production renderer [S1, unofficial]. It solves the problem of understanding the mathematical foundations of differentiable Gaussian rasterization by implementing the full pipeline—camera projection, covariance transformation, depth sorting, and alpha compositing—using standard tensor operations without custom CUDA kernels [S1, unofficial]. It sets itself apart from production implementations like [3D Gaussian Splatting Rendering (Software)](2805-3d-gaussian-splatting-rendering-software.md) by explicitly skipping tile-based optimization, spherical harmonics, and adaptive density control, favoring readability and explicit Python loops over vectorized GPU performance [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of $N$ 3D Gaussians defined by their parameters (mean, scale, rotation, color, opacity); a pinhole camera model defined by extrinsics (view matrix $W$) and intrinsics (projection matrix $P$); and an image resolution $(H, W)$.
*   **Outputs:** A rendered RGB image of size $(H, W, 3)$ and associated gradients for the Gaussian parameters.

**Data Structures:**
Each Gaussian $i$ is stored with the following fields:
*   `mean`: $(3)$ float32, 3D position in world space.
*   `scale`: $(3)$ float32, logarithmic scale factors.
*   `rotation`: $(4)$ float32, unit quaternion $(w, x, y, z)$.
*   `opacity`: $(1)$ float32, scalar opacity $\alpha_i \in [0, 1]$.
*   `color`: $(3)$ float32, RGB color $c_i$.
*   `depth`: $(1)$ float32, distance from mean to image plane (computed during projection).

**Method Steps:**

1.  **Covariance Construction:**
    Construct the 3D covariance matrix $\Sigma$ from the scale and rotation parameters. This ensures the covariance is automatically symmetric positive semi-definite (PSD) [S1, unofficial].
    $$ \Sigma = R S S^T R^T $$
    Where:
    *   $S = \text{diag}(\exp(\text{scale}))$ is the scaling matrix.
    *   $R$ is the rotation matrix derived from the unit quaternion [S1, unofficial].

2.  **World-to-Camera Transformation:**
    Transform the Gaussian mean $\mu$ and the 3D covariance $\Sigma$ into the camera coordinate system using the view transformation $W$ [S1, unofficial].
    $$ \mu_c = W \mu $$
    $$ \Sigma_c = W \Sigma W^T $$

3.  **2D Screen-Space Projection:**
    Project the 3D covariance $\Sigma_c$ onto the 2D image plane using the EWA (Elliptical Weighted Average) / Zwicker-style projection Jacobian $J$ [S1, unofficial].
    $$ \Sigma_{2d} = J W \Sigma W^T J^T = J \Sigma_c J^T $$
    Where $J$ is the Jacobian of the perspective projection. A small isotropic dilation (blur) is added to $\Sigma_{2d}$ for numerical stability [S1, unofficial].

4.  **Depth Sorting:**
    Compute the depth of each Gaussian as the distance from its transformed mean $\mu_c$ to the image plane. Sort the Gaussians in front-to-back order using `argsort` [S1, unofficial].
    *   *Pitfall:* The sort operation is non-differentiable across order changes. Gradients flow through the values given the fixed ordering, which is accepted for this fit-from-scratch demo [S1, unofficial].

5.  **Per-Pixel Alpha Compositing:**
    For each pixel $p$, iterate through the sorted Gaussians that overlap with the pixel's bounding box. Perform front-to-back alpha compositing using the volume-rendering equation with anisotropic 2D Gaussian weights [S1, unofficial].
    $$ C(p) = \sum_{i \in \text{sorted}} T_i \alpha_i c_i $$
    $$ T_{i+1} = T_i (1 - \alpha_i) $$
    $$ T_1 = 1 $$
    Where:
    *   $\alpha_i = \alpha_i^{\text{param}} \cdot \exp\left(-\frac{1}{2} x_p^T \Sigma_{2d,i}^{-1} x_p\right)$ is the effective opacity at pixel $p$, combining the Gaussian's parametric opacity with the 2D spatial weight.
    *   $x_p$ is the 2D offset of pixel $p$ from the Gaussian's projected center.
    *   $c_i$ is the RGB color of Gaussian $i$.

**Pseudocode:**

```python
import torch
import torch.nn.functional as F

def render_gaussians_mvp(gaussians, camera, image_h, image_w):
    """
    Pure PyTorch implementation of 3D Gaussian Splatting MVP.
    
    Args:
        gaussians: Dict with keys 'mean' (N,3), 'scale' (N,3), 'rotation' (N,4), 
                   'opacity' (N,1), 'color' (N,3).
        camera: Dict with 'W' (3,4) view matrix, 'P' (3,3) projection matrix.
        image_h, image_w: Image dimensions.
        
    Returns:
        rendered_image: (H, W, 3)
    """
    N = gaussians['mean'].shape[0]
    
    # 1. Construct 3D Covariance
    # Scale matrix S
    S = torch.diag_embed(torch.exp(gaussians['scale'])) # (N, 3, 3)
    
    # Rotation matrix R from quaternion
    R = quaternion_to_rotation_matrix(gaussians['rotation']) # (N, 3, 3)
    
    # Sigma = R S S^T R^T
    Sigma_3d = R @ S @ S.transpose(1, 2) @ R.transpose(1, 2) # (N, 3, 3)
    
    # 2. World-to-Camera Transform
    # mu_c = W @ mu
    mu_c = (camera['W'][:, :3] @ gaussians['mean'].transpose(0, 1)).transpose(0, 1) + camera['W'][:, 3] # (N, 3)
    
    # Sigma_c = W Sigma W^T
    # Note: W is 3x4, but we only need the upper 3x3 for covariance rotation
    W_rot = camera['W'][:, :3] # (3, 3)
    Sigma_c = W_rot @ Sigma_3d.transpose(1, 2) @ W_rot.transpose(0, 1) # (N, 3, 3)
    
    # 3. Project to 2D
    # Jacobian J for perspective projection
    # z = mu_c[:, 2]
    # J = P @ W_rot ... simplified for MVP: standard EWA projection
    # For MVP, we assume a simplified projection or use the provided Jacobian logic
    # J = d(x,y,z)/d(X,Y,Z) projected to screen
    # Standard EWA: Sigma_2d = J Sigma_c J^T
    # Here we approximate J based on depth and focal length
    fx = camera['P'][0, 0]
    fy = camera['P'][1, 1]
    cx = camera['P'][0, 2]
    cy = camera['P'][1, 2]
    
    z = mu_c[:, 2].unsqueeze(1) # (N, 1)
    # Avoid division by zero
    z = torch.clamp(z, min=1e-3)
    
    # Jacobian components for perspective projection
    # x_screen = fx * X / Z + cx
    # J = [ fx/Z  0   -fx*X/Z^2 ]
    #     [ 0   fy/Z  -fy*Y/Z^2 ]
    #     [ 0     0       0      ]
    # We only need the top 2x3 part for 2D covariance
    
    X = mu_c[:, 0].unsqueeze(1)
    Y = mu_c[:, 1].unsqueeze(1)
    
    J = torch.zeros(N, 2, 3)
    J[:, 0, 0] = fx / z.squeeze()
    J[:, 0, 2] = -fx * X.squeeze() / (z.squeeze() ** 2)
    J[:, 1, 1] = fy / z.squeeze()
    J[:, 1, 2] = -fy * Y.squeeze() / (z.squeeze() ** 2)
    
    Sigma_2d = J @ Sigma_c @ J.transpose(1, 2) # (N, 2, 2)
    
    # Add isotropic blur for stability
    Sigma_2d[:, 0, 0] += 0.3
    Sigma_2d[:, 1, 1] += 0.3
    
    # 4. Depth Sorting
    # Depth is z-coordinate in camera space
    depths = mu_c[:, 2] # (N,)
    sort_indices = torch.argsort(depths, dim=0) # (N,)
    
    # Gather sorted Gaussians
    sorted_means = mu_c[sort_indices]
    sorted_Sigma_2d = Sigma_2d[sort_indices]
    sorted_opacities = gaussians['opacity'][sort_indices]
    sorted_colors = gaussians['color'][sort_indices]
    
    # 5. Rasterization
    # Create pixel grid
    y_coords, x_coords = torch.meshgrid(torch.arange(image_h), torch.arange(image_w), indexing='ij')
    y_coords = y_coords.float().cuda() # (H, W)
    x_coords = x_coords.float().cuda() # (H, W)
    
    # Initialize output
    rendered_image = torch.zeros(image_h, image_w, 3, device=gaussians['mean'].device)
    transmittance = torch.ones(image_h, image_w, device=gaussians['mean'].device)
    
    # Loop over Gaussians (for readability, as per MVP design)
    for i in range(N):
        mu = sorted_means[i] # (3,)
        Sigma = sorted_Sigma_2d[i] # (2, 2)
        alpha_param = sorted_opacities[i].item()
        color = sorted_colors[i] # (3,)
        
        # Projected center
        cx_proj = fx * mu[0] / mu[2] + cx
        cy_proj = fy * mu[1] / mu[2] + cy
        
        # Bounding box for this Gaussian
        # Approximate radius as 3 sigma
        det = Sigma.det()
        if det <= 0: continue
        
        inv_Sigma = Sigma.inverse()
        # Eigenvalues for radius estimation
        eigvals = torch.linalg.eigvals(Sigma).real
        radius = 3.0 * torch.sqrt(torch.max(eigvals))
        
        x_min = max(0, int(cx_proj - radius))
        x_max = min(image_w, int(cx_proj + radius))
        y_min = max(0, int(cy_proj - radius))
        y_max = min(image_h, int(cy_proj + radius))
        
        if x_min >= x_max or y_min >= y_max:
            continue
            
        # Extract pixel coordinates in bounding box
        ys = y_coords[y_min:y_max, x_min:x_max]
        xs = x_coords[y_min:y_max, x_min:x_max]
        
        # Offset from center
        dx = xs - cx_proj
        dy = ys - cy_proj
        
        # 2D Gaussian weight
        # exp(-0.5 * x^T Sigma^-1 x)
        pos = torch.stack([dx.flatten(), dy.flatten()], dim=1) # (K, 2)
        exponent = -0.5 * (pos @ inv_Sigma * pos).sum(dim=1) # (K,)
        exponent = exponent.view(y_max-y_min, x_max-x_min)
        
        alpha = alpha_param * torch.exp(exponent)
        alpha = torch.clamp(alpha, max=1.0)
        
        # Update transmittance and color
        # T_new = T_old * (1 - alpha)
        # C_new = C_old + T_old * alpha * color
        
        # Vectorized update for the bounding box
        T_local = transmittance[y_min:y_max, x_min:x_max] # (H_b, W_b)
        C_local = rendered_image[y_min:y_max, x_min:x_max] # (H_b, W_b, 3)
        
        contribution = T_local.unsqueeze(2) * alpha.unsqueeze(2) * color.unsqueeze(0).unsqueeze(0)
        C_local = C_local + contribution
        T_local = T_local * (1 - alpha)
        
        rendered_image[y_min:y_max, x_min:x_max] = C_local
        transmittance[y_min:y_max, x_min:x_max] = T_local
        
    return rendered_image

def quaternion_to_rotation_matrix(q):
    """Convert quaternion (w, x, y, z) to rotation matrix (3, 3)."""
    w, x, y, z = q[:, 0], q[:, 1], q[:, 2], q[:, 3]
    N = w*w + x*x + y*y + z*z
    w, x, y, z = w/N, x/N, y/N, z/N # Normalize
    
    R = torch.zeros(q.shape[0], 3, 3, device=q.device)
    R[:, 0, 0] = 1 - 2 * (y*y + z*z)
    R[:, 0, 1] = 2 * (x*y - w*z)
    R[:, 0, 2] = 2 * (x*z + w*y)
    R[:, 1, 0] = 2 * (x*y + w*z)
    R[:, 1, 1] = 1 - 2 * (x*x + z*z)
    R[:, 1, 2] = 2 * (y*z - w*x)
    R[:, 2, 0] = 2 * (x*z - w*y)
    R[:, 2, 1] = 2 * (y*z + w*x)
    R[:, 2, 2] = 1 - 2 * (x*x + y*y)
    return R
```

## Subtopics

### [3D Gaussian Splatting with Gaussian Unpooling](6133-3d-gaussian-splatting-with-gaussian-unpooling.md)
FSGS is a method for reconstructing 3D scenes from sparse-view inputs, addressing the challenge of insufficient initialization data for standard 3D Gaussian Splatting. It distinguishes itself from dense-view baselines by using Gaussian unpooling to expand a sparse set of Structure-from-Motion (SfM) points into a denser set of Gaussians, enabling faithful geometry reconstruction where standard methods fail due to lack of initial coverage.

### [Relightable 3DGS](7851-relightable-3dgs.md)
Relightable 3DGS extends standard 3D Gaussian Splatting by embedding physically-based material properties into each Gaussian, enabling deferred shading and realistic rendering of complex appearances such as reflections, transparency, and glossy surfaces. Unlike standard rasterization which approximates view-dependent colors via spherical harmonics and fails to represent specular reflections or global illumination, this method decomposes outgoing radiance into a BRDF integration that respects material parameters. It sets itself apart from its siblings by decoupling geometry processing from lighting and material computations, adapting a two-pass deferred pipeline to Gaussian Splatting for efficient rendering of high-frequency, view-dependent effects.

### PRoGS
PRoGS is a post-training technique for 3D Gaussian Splatting that approximates each Gaussian's contribution to the final scene to construct a prioritization order, enabling progressive rendering or streaming by dynamically selecting splats to display or transmit [S1, unofficial]. Unlike existing web-viewers that require full scene retrieval before rendering, PRoGS loads a representative subset early, significantly reducing time-to-first-paint while maintaining perceptual quality [S1, unofficial]. It is designed for on-device rendering applications constrained by memory and streaming applications requiring minimal bandwidth [S1, unofficial].

### [3D Gaussian Splatting Rendering Pipeline (RViz Plugin)](10297-3d-gaussian-splatting-rendering-pipeline-rviz-plugin.md)
This article describes the OpenGL-based rendering pipeline for visualizing 3D Gaussian Splatting data within the ROS RViz environment. It solves the problem of efficiently rendering millions of 2D-projected Gaussian splats as a single instanced draw call, handling depth sorting and view-dependent shading. It differs from pure software implementations by leveraging GPU-based sorting and texture buffer objects (TBOs) for data storage, and from other RViz plugins by supporting both exact back-to-front sorting and Order-Independent Transparency (WBOIT) approximations.

### [CPU-based Gaussian Splatting Thumbnailer with JIT Optimization](14069-cpu-based-gaussian-splatting-thumbnailer-with-jit-optimizati.md)
This method provides a lightweight, CPU-only pipeline for generating rapid visual thumbnails from 3D Gaussian Splatting datasets, prioritizing responsiveness and portability over high-fidelity rendering. It distinguishes itself from standard GPU-accelerated splatting by omitting rotation parameters, approximating Gaussians as spheres, and leveraging Python's Numba JIT compiler to achieve near-real-time performance on constrained hardware.

### OmniGS
A novel omnidirectional Gaussian splatting system that takes calibrated monocular 360-degree images and sparse SfM point clouds as input to recover 3D Gaussians for fast radiance field reconstruction and real-time omnidirectional novel view synthesis.

### 3D Gaussian Splatting with Vector Clustering and Entropy Encoding
A method that utilizes vector clustering to encode color and geometric attributes into two codebooks, using a sensitivity-aware KMeans method. For disk data storage, SASCGS utilizes the entropy encoding method DEFLATE, which combines the LZ77 algorithm and Huffman coding, to compress the data. On the MipNeRF360 dataset, SASCGS achieves SSIM 0.801, PSNR 26.98, LPIPS 0.238, and a size of 28.80 MB [S2].

### Vol3DGS
Enforces that alpha blending exactly satisfies the front-to-back absorption-emission model by deriving discrete compositing as an unbiased Monte Carlo estimator of the continuous integral. It introduces a continuous density field along the ray to resolve artifacts in scenes with semi-transparent objects. Volumetric alpha computation is defined as $\alpha_i = 1 - \exp(-\int G_i(x) dx)$, accumulating density along the ray in accordance with the volume rendering equation [S3, unofficial].

### HiFi4G
This successfully preserves spatial-temporal consistency in a more compact manner. It combines 3DGS with the non-rigid tracking offered by its dual-graph mechanism for high-fidelity rendering [S2].

### 3D Gaussian Splatting with Mesh UV Parameterization
This enables real-time and high-quality animated humans. It projects the 3D Gaussian learning into a 2D texture space using mesh UV parameterization to capture the appearance [S2].

### Modified Alpha-Blending
A modified alpha-blending function designed to perform image rendering over re-sketched Gaussian lines and Gaussian triangles. It renders the re-sketched primitives using the modified alpha-blending function in a similar manner as original Gaussian ellipses [S4, unofficial].

### Depth Generation via Linear Interpolation
A method to compute accurate depth $\hat{D}$ for a pixel by treating it as a linear interpolation of distances from 3D Gaussians to the image plane, avoiding the floating problem and disc aliasing associated with peak selection in forward mapping splatting. For each pixel, it renders the view using 3D Gaussians to obtain $T_i$, $\alpha_i$, $d_i$, and $n_i$ for all contributing Gaussians $i$. The depth is calculated as $\hat{D} = \sum_{i=1}^{N} \hat{w}_i d_i$, where $\hat{w}_i = \frac{T_i \alpha_i}{\sum_{i=1}^{N} T_i \alpha_i}$, $d_i$ is the distance from the i-th Gaussian to the image plane, $T_i$ is accumulated transmittance, and $\alpha_i$ is opacity [S5].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot H \cdot W)$ in the worst case if every Gaussian overlaps every pixel, but practically bounded by the number of overlapping Gaussians per pixel. The MVP implementation uses a Python loop over $N$ Gaussians, making it significantly slower than vectorized CUDA implementations.
*   **Memory Complexity:** $O(N + H \cdot W)$ for storing Gaussian parameters and the output image/transmittance buffers.
*   **Measured Performance:** End-to-end run takes ~30 seconds on CPU for a 64x64 image with 40 Gaussians [S1, unofficial].
*   **Strengths:** High readability, no custom CUDA kernels required, easy to modify for educational purposes, correct mathematical formulation of EWA projection and alpha compositing.
*   **Limitations:** Extremely slow on CPU due to Python loops; lacks optimizations like tile-based rasterization, spherical harmonics for view-dependent color, and adaptive density control [S1, unofficial]. Not suitable for real-time rendering or large-scale scenes.
*   **When to use:** Educational purposes, debugging the core math, or environments where custom CUDA compilation is not feasible.
*   **When not to use:** Production rendering, real-time applications, or large-scale scene reconstruction.

## Background
3D Gaussian Splatting was introduced by Kerbl et al. in SIGGRAPH 2023, establishing a new paradigm for radiance field representation using explicit 3D Gaussians [S1, unofficial]. The MVP implementation is a self-contained Jupyter notebook (`gauss_splat_mvp.ipynb`) created as a teaching reference to "grind on the math" without relying on black-box CUDA kernels [S1, unofficial]. It demonstrates the core pipeline including pinhole camera projection, covariance construction, and front-to-back alpha compositing, serving as a baseline for understanding the underlying mechanics before layering on optimizations like those found in [Taming 3DGS](8058-taming-3dgs.md) or [Analytic-Splatting](8084-analytic-splatting.md).
