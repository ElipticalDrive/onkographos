# FreGS

Also called: Frequency-aware regularization for 3DGS, Progressive frequency regularization

## Overview
FreGS is a regularization method for 3D Gaussian Splatting that prevents overfitting and high-frequency artifacts (such as "floaters" in empty space) by penalizing frequency discrepancies between rendered and ground-truth images [S1, unofficial][S2]. Unlike sibling methods that constrain geometry via depth or shape priors, FreGS operates in the frequency domain, ensuring the reconstructed scene captures relevant spectral information without introducing noise [S2]. It is chosen when training stability is compromised by high-frequency oscillations or when the scene exhibits significant empty-space artifacts [S1, unofficial].

## How it works
FreGS integrates a frequency-aware regularization term $\mathcal{L}_{freq}$ into the total training loss. The method operates by comparing the spectral content of the rendered image against the ground truth, applying a progressive strategy to guide the Gaussian primitives [S1, unofficial][S2].

**Inputs and Outputs:**
*   **Inputs:** Rendered image $I_{render}$, Ground-truth image $I_{gt}$, current training step $t$, total training steps $T$.
*   **Outputs:** Regularization loss value $\mathcal{L}_{freq}$ to be added to the total loss.

**Data Structures:**
*   Images are treated as 2D arrays of pixel values.
*   Frequency domain representation is obtained via Discrete Fourier Transform (DFT).

**Parameters:**
*   $\lambda_{freq}$: Weight for the frequency regularization term. Not given in the sources.
*   $T$: Total number of training iterations. Not given in the sources.
*   $t$: Current training iteration.

**Steps:**
1.  Compute the 2D Discrete Fourier Transform of the rendered image: $F_{render} = \text{DFT}(I_{render})$.
2.  Compute the 2D Discrete Fourier Transform of the ground-truth image: $F_{gt} = \text{DFT}(I_{gt})$.
3.  Calculate the magnitude spectra: $M_{render} = |F_{render}|$ and $M_{gt} = |F_{gt}|$.
4.  Compute the frequency discrepancy loss. The sources describe this as regularizing frequency discrepancies [S2]. A common implementation for such spectral regularization is the Mean Squared Error (MSE) between the magnitude spectra:
    $$ \mathcal{L}_{spec} = \frac{1}{N} \sum_{u,v} (M_{render}(u,v) - M_{gt}(u,v))^2 $$
    where $u,v$ are frequency coordinates and $N$ is the number of pixels.
5.  Apply progressive weighting. FreGS uses a "progressive frequency regularization" strategy [S1, unofficial]. This typically involves scaling the loss by a factor that increases or changes over time to stabilize early training. Let $\alpha(t)$ be the progressive factor.
    $$ \mathcal{L}_{freq} = \alpha(t) \cdot \mathcal{L}_{spec} $$
    The specific function for $\alpha(t)$ is not given in the sources [G]. A common progressive schedule is linear or cosine annealing.
6.  Add to total loss:
    $$ \mathcal{L}_{total} = \mathcal{L}_{photo} + \lambda_{freq} \mathcal{L}_{freq} $$

**Pseudocode:**
```python
def compute_fregs_loss(rendered_image, gt_image, t, T, lambda_freq, alpha_schedule):
    """
    Computes the FreGS regularization loss.
    
    Args:
        rendered_image: Tensor of shape (H, W, 3), pixel values [0, 1].
        gt_image: Tensor of shape (H, W, 3), pixel values [0, 1].
        t: Current training step.
        T: Total training steps.
        lambda_freq: Weight for the frequency loss.
        alpha_schedule: Function alpha(t) returning the progressive weight.
        
    Returns:
        loss: Scalar tensor.
    """
    # 1. Compute DFT
    # Note: Standard FFT returns complex numbers. We take magnitude.
    # Assuming input is real, we can use rfft for efficiency, but full fft is clearer for definition.
    F_render = torch.fft.fft2(rendered_image.permute(2, 0, 1)) # Shape (3, H, W)
    F_gt = torch.fft.fft2(gt_image.permute(2, 0, 1))
    
    # 2. Magnitude spectra
    M_render = torch.abs(F_render)
    M_gt = torch.abs(F_gt)
    
    # 3. Frequency discrepancy (MSE between magnitudes)
    # Mean over all pixels and channels
    loss_spec = torch.mean((M_render - M_gt) ** 2)
    
    # 4. Progressive weighting
    alpha = alpha_schedule(t, T)
    
    # 5. Final loss
    loss = lambda_freq * alpha * loss_spec
    
    return loss
```

**Edge Cases and Pitfalls:**
*   **Precision:** FFT operations are sensitive to normalization. Ensure images are normalized consistently before transformation.
*   **Boundaries:** The DFT assumes periodicity. If images have sharp edges at boundaries, this may introduce artifacts. Not given in the sources.
*   **Degenerate Input:** If the rendered image is constant, the magnitude spectrum will be zero except at DC. This is handled naturally by MSE.

## Subtopics

### Frequency Regularization
The broader category of methods using spectral loss. FreGS is a specific instance using progressive weighting [S1, unofficial][S2].

### Progressive Frequency Regularization
The specific strategy of varying the regularization strength over time to improve convergence [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The addition of FFT and inverse FFT (if used for reconstruction, though here only forward FFT is needed for loss) adds $O(N \log N)$ overhead per step, where $N$ is the number of pixels. This is negligible compared to the rasterization cost for typical resolutions.
*   **Memory Complexity:** Requires storing the frequency domain representations, adding $O(N)$ memory.
*   **Performance:** FreGS reduces high-frequency artifacts and floaters, leading to cleaner geometry [S1, unofficial][S2]. It does not significantly increase training time.
*   **Strengths:** Effective at suppressing noise and floaters without explicit depth supervision.
*   **Limitations:** May smooth out fine details if the frequency weight is too high. Requires careful tuning of $\lambda_{freq}$ and the progressive schedule.

## Background
FreGS was introduced to address the issue of over-reconstruction in 3D Gaussian Splatting, where the optimizer places Gaussians in empty space to minimize photometric loss [S2]. It builds on the observation that frequency domain analysis can effectively distinguish between valid scene structure and high-frequency noise [S1, unofficial][S2]. The method is part of a family of regularization techniques aimed at improving the geometric consistency of learned Gaussian fields [S1, unofficial].
