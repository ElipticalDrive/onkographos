# 3D Gaussian Splatting Rasterization

Also called: 3D Gaussian Splatting (3DGS), 3DGS Rasterization, Differentiable Gaussian Rasterization, TrimGS, gsplat.rasterization

## Overview
3D Gaussian Splatting Rasterization is a screen-space rendering method that projects a set of 3D Gaussian primitives into 2D ellipses, sorts them by depth, and alpha-composites them to produce an RGB image [S2, S6, unofficial][S9, unofficial]. It solves the problem of efficiently rendering large-scale point-cloud-based scene representations while maintaining full differentiability with respect to all Gaussian parameters (position, scale, rotation, opacity, and color) and camera poses [S2, S6, unofficial][S9, unofficial]. It differs from volumetric ray-marching methods like NeRF by using discrete rasterization of 2D kernels rather than continuous integral evaluation, and from standard OpenGL rasterization by operating on non-polygonal, probabilistic primitives with a custom front-to-back blending order [S2, S6, unofficial][S9, unofficial].

## How it works
**Inputs:**
*   $N$ Gaussians, each defined by mean $\mu \in \mathbb{R}^3$, quaternion $q \in \mathbb{R}^4$, scale $s \in \mathbb{R}^3$, opacity $\alpha \in \mathbb{R}$, and spherical harmonics coefficients $c_{\ell m}$ (or direct RGB color) [S1][S4, unofficial].
*   Camera parameters: View matrix $V \in \mathbb{R}^{4 \times 4}$, projection matrix $K \in \mathbb{R}^{3 \times 3}$ (intrinsics), image dimensions $W \times H$, near plane $z_{near}$, far plane $z_{far}$ [S2, S3, unofficial].
*   Optional: `render_mode` (e.g., "RGB", "D", "ED"), `rasterize_mode` ("classic", "antialiased"), `tile_size` (default 16) [S2, unofficial].

**Outputs:**
*   Rendered image $C_{final} \in \mathbb{R}^{H \times W \times 3}$ (and optionally depth/alpha maps) [S3, unofficial].

**Data Structures:**
*   **Gaussian Attributes:** Stored in contiguous arrays or tensors.
    *   `means`: $[N, 3]$ float32.
    *   `quats`: $[N, 4]$ float32 (normalized).
    *   `scales`: $[N, 3]$ float32.
    *   `opacities`: $[N]$ float32.
    *   `colors`: $[N, D]$ float32 (where $D=3$ for RGB, or higher for SH).
*   **Projection Data (per camera):**
    *   `means_2D`: $[N, 2]$ float32 (screen coordinates).
    *   `conics`: $[N, 3]$ float32, storing the upper triangle of $\Sigma_{2D}^{-1}$ as $[C_{00}, C_{01}, C_{11}]$ [S2, S3, unofficial].
    *   `radii`: $[N, 2]$ int32 (bounding box in pixels).
    *   `depths`: $[N]$ float32 (camera-space $z$).
*   **Rasterization State:**
    *   `isect_offsets`: $[C, H_{tiles}, W_{tiles}]$ int32, mapping tiles to Gaussian lists [S2, unofficial].
    *   `flatten_ids`: $[N_{active}]$ int32, sorted indices of active Gaussians [S2, unofficial].

**Steps:**

1.  **Covariance Construction:** Compute the 3D covariance matrix $\Sigma_{3D}$ from $q$ and $s$. First, construct rotation matrix $R$ from $q$. Then:
    $$ \Sigma_{3D} = R S S^T R^T $$
    where $S = \text{diag}(s_x, s_y, s_z)$ [S1][S3, unofficial].

2.  **Linearized Projection:** Transform $\mu$ and $\Sigma_{3D}$ to camera space and then to 2D screen space.
    *   Camera space mean: $\mu' = V \mu$.
    *   Camera space covariance: $\Sigma' = V_{1:3, 1:3} \Sigma_{3D} V_{1:3, 1:3}^T$ [S3, unofficial].
    *   Compute Jacobian $J$ of the projective projection at $\mu'$:
        $$ J = \begin{pmatrix} \frac{f_x}{\mu'_z} & 0 & -\frac{f_x \mu'_x}{\mu'_z^2} \\ 0 & \frac{f_y}{\mu'_z} & -\frac{f_y \mu'_y}{\mu'_z^2} \end{pmatrix} $$
    *   Screen covariance: $\Sigma_{2D} = J \Sigma' J^T$ [S2, S3, unofficial].

3.  **Conic Inversion:** Compute the inverse 2D covariance $\Sigma_{2D}^{-1}$ and store only the upper triangle as the conic vector $C = [\Sigma_{2D}^{-1}[0,0], \Sigma_{2D}^{-1}[0,1], \Sigma_{2D}^{-1}[1,1]]$ [S2, S3, unofficial].

4.  **Filtering and Sorting:**
    *   Cull Gaussians where $\mu'_z < z_{near}$ or outside the view frustum [S3, S4, unofficial].
    *   Sort remaining Gaussians by camera-space depth $z$ (front-to-back) [S3, S4, unofficial].

5.  **Tile Assignment:** Divide the image into tiles of size `tile_size` $\times$ `tile_size`. For each Gaussian, compute its bounding box in tile coordinates. Assign Gaussians to tiles they intersect [S2, unofficial].

6.  **Rasterization (Pixel Loop):** For each tile, iterate over assigned Gaussians. For each pixel $(x,y)$ in the tile:
    *   Compute vector $\mathbf{x}$ from pixel center to Gaussian mean in screen space.
    *   Compute 2D alpha:
        $$ \alpha_{pixel} = \alpha_i \cdot \exp\left(-\frac{1}{2} \mathbf{x}^T \Sigma_{2D}^{-1} \mathbf{x}\right) $$
    *   Update transmittance $T$ and accumulated color $C_{acc}$:
        $$ C_{acc} \leftarrow C_{acc} + T \cdot \alpha_{pixel} \cdot c_i $$
        $$ T \leftarrow T \cdot (1 - \alpha_{pixel}) $$
    *   If $T$ drops below a threshold (e.g., $10^{-4}$), break early [S3, unofficial].

7.  **Background Compositing:**
    $$ C_{final} = C_{acc} + T \cdot C_{bg} $$
    where $C_{bg}$ is the background color [S3, unofficial].

8.  **Spherical Harmonics Evaluation (Optional):** If `sh_degree` is set, compute view direction $d = \text{normalize}(\mu - \text{campos})$ and evaluate SH coefficients to get color $c_i$ before compositing [S2, unofficial].

**Pseudocode:**

```python
def rasterize_gaussians(means_3d, quats, scales, opacities, colors, viewmats, Ks, width, height, backgrounds, sh_degree=None, tile_size=16):
    """
    Renders 3D Gaussians to 2D images.
    """
    C = viewmats.shape[0] # Number of cameras
    N = means_3d.shape[0] # Number of Gaussians
    
    # 1. Compute 3D Covariance
    # R is rotation matrix from quat, S is diag(scales)
    cov_3d = quat_scale_to_covar(quats, scales) # Shape [N, 3, 3]
    
    # 2. Project to 2D
    # Linearized projection handles camera transform and Jacobian
    means_2d, cov_2d, depths, radii = linearized_project(means_3d, cov_3d, viewmats, Ks, width, height)
    
    # 3. Compute Conics (Inverse Covariance Upper Triangle)
    conics = compute_conics(cov_2d) # Shape [N, 3]
    
    # 4. Filter and Sort
    # Mask for valid Gaussians (in front of near plane, within bounds)
    valid_mask = (depths > 0.0) & (radii[:, 0] >= 0) & (radii[:, 1] >= 0)
    valid_indices = torch.where(valid_mask)[0]
    sorted_indices = valid_indices[torch.argsort(depths[valid_indices])]
    
    # 5. Tile Assignment
    tile_width = (width + tile_size - 1) // tile_size
    tile_height = (height + tile_size - 1) // tile_size
    
    # Map each Gaussian to the tiles it intersects
    tiles_per_gauss, isect_ids, flatten_ids = isect_tiles(means_2d, radii, depths, tile_size, tile_width, tile_height, sort=True)
    
    # 6. Prepare Colors (SH evaluation if needed)
    if sh_degree is not None:
        # Compute view directions and evaluate SH
        campos = viewmats[:, :3, 3]
        dirs = means_3d[None, :, :] - campos[:, None, :]
        dirs = dirs / torch.norm(dirs, dim=-1, keepdim=True).clamp(min=1e-8)
        colors = evaluate_spherical_harmonics(sh_degree, dirs, colors)
    
    # Broadcast opacities to [C, N]
    opacities_cn = opacities[None, :].expand(C, -1)
    
    # 7. Rasterize to Pixels
    # This step is typically fused in GPU kernels
    render_colors, render_alphas = rasterize_to_pixels(
        means2d=means_2d,
        conics=conics,
        colors=colors,
        opacities=opacities_cn,
        width=width,
        height=height,
        tile_size=tile_size,
        isect_offsets=encode_isect_offsets(isect_ids, C, tile_width, tile_height),
        flatten_ids=flatten_ids,
        backgrounds=backgrounds
    )
    
    return render_colors, render_alphas

def quat_scale_to_covar(quats, scales):
    """Compute 3D covariance from quaternion and scale."""
    # Convert quat to rotation matrix R
    R = quat_to_rot_matrix(quats) # [N, 3, 3]
    S = torch.diag_embed(scales)  # [N, 3, 3]
    # Sigma = R S S^T R^T
    cov = R @ S @ S.transpose(1, 2) @ R.transpose(1, 2)
    return cov

def linearized_project(means_3d, cov_3d, viewmats, Ks, width, height):
    """Project 3D mean and covariance to 2D screen space."""
    # Transform mean to camera space
    # means_cam = R_cam * means_3d + t_cam
    R_cam = viewmats[:, :3, :3]
    t_cam = viewmats[:, :3, 3]
    means_cam = torch.einsum("cij,nj->cni", R_cam, means_3d) + t_cam[:, None, :]
    
    # Transform covariance to camera space
    cov_cam = torch.einsum("cij,njk,clk->cnkl", R_cam, cov_3d, R_cam)
    
    # Compute Jacobian J of projection
    fx = Ks[:, 0, 0]
    fy = Ks[:, 1, 1]
    cx = Ks[:, 0, 2]
    cy = Ks[:, 1, 2]
    
    zx = means_cam[..., 0]
    zy = means_cam[..., 1]
    zz = means_cam[..., 2]
    
    # Jacobian components
    J = torch.zeros_like(means_cam)
    J[..., 0, 0] = fx / zz
    J[..., 0, 2] = -fx * zx / (zz * zz)
    J[..., 1, 1] = fy / zz
    J[..., 1, 2] = -fy * zy / (zz * zz)
    
    # Project covariance: Sigma_2d = J * Sigma_cam * J^T
    cov_2d = torch.einsum("cij,njk,clk->cnkl", J, cov_cam, J)
    
    # Extract 2D means and depths
    means_2d = torch.zeros_like(means_cam[..., :2])
    means_2d[..., 0] = (means_cam[..., 0] * fx / zz) + cx
    means_2d[..., 1] = (means_cam[..., 1] * fy / zz) + cy
    
    depths = means_cam[..., 2]
    
    # Compute radii (approximate bounding box)
    # This is a simplification; real implementations use eigenvalues of Sigma_2d
    radii = compute_radii(cov_2d)
    
    return means_2d, cov_2d, depths, radii

def compute_conics(cov_2d):
    """Compute inverse covariance upper triangle."""
    # cov_2d is [C, N, 2, 2]
    # Invert 2x2 matrix for each Gaussian
    det = cov_2d[..., 0, 0] * cov_2d[..., 1, 1] - cov_2d[..., 0, 1] * cov_2d[..., 1, 0]
    inv_00 = cov_2d[..., 1, 1] / det
    inv_01 = -cov_2d[..., 0, 1] / det
    inv_11 = cov_2d[..., 0, 0] / det
    
    # Store as [C, N, 3]
    conics = torch.stack([inv_00, inv_01, inv_11], dim=-1)
    return conics
```

## Subtopics

### [3D Gaussian Splatting Differentiable Rasterizer](2813-3d-gaussian-splatting-differentiable-rasterizer.md)
The 3D Gaussian Splatting Differentiable Rasterizer is a screen-space rendering method that projects a set of 3D Gaussian primitives into 2D ellipses, sorts them by depth, and alpha-composites them to produce an RGB image. It solves the problem of efficiently rendering large-scale point-cloud-based scene representations while maintaining full differentiability with respect to all Gaussian parameters (position, scale, rotation, opacity, and color) and camera poses. It differs from volumetric ray-marching methods like NeRF by using discrete rasterization of 2D kernels rather than continuous integral evaluation, and from standard OpenGL rasterization by operating on non-polygonal, probabilistic primitives with a custom front-to-back blending order.

### [Ghost Ellipsoids for Chunked Training](3559-ghost-ellipsoids-for-chunked-training.md)
Ghost Ellipsoids for Chunked Training resolves boundary artifacts in chunked volume training by including ellipsoids from neighboring chunks in the loss computation without updating their parameters, providing boundary context without requiring a global volume or merged model. Unlike chunk-based 3DGS methods that resolve boundary inconsistencies by merging chunks into a global coarse model or through post-training stages, this method requires boundary support during training itself without access to a global volume.

### [2D Gaussian Splatting Rasterization](4815-2d-gaussian-splatting-rasterization.md)
2D Gaussian Splatting Rasterization renders a scene represented by 2D Gaussian primitives (surfels) into RGB, alpha, and normal maps using a custom rasterizer. It differs from standard 3D Gaussian Splatting by operating on surfels projected into screen space, accumulating color and geometric attributes via front-to-back alpha compositing [Parent]. It serves as the Tier-1 NumPy reference implementation for 2D Gaussian Splatting, performing ray-surfel intersection per pixel using the projection matrix.

### [AdR-Gaussian](8365-adr-gaussian.md)
AdR-Gaussian is a rendering acceleration method for 3D Gaussian Splatting that optimizes the rasterization pipeline by moving serial culling operations to a parallel preprocessing stage and balancing computational loads across pixel threads. It achieves significant speedups without reducing the total number of Gaussians, thereby avoiding the quality degradation associated with pruning-based acceleration methods.

### [Projection Geometry and Coordinate Systems](9313-projection-geometry-and-coordinate-systems.md)
This article defines the mathematical framework for transforming 3D Gaussian primitives from world space into the 2D image plane for rasterization in 3D Gaussian Splatting. It solves the problem of accurately projecting 3D ellipsoids onto a 2D sensor plane while preserving geometric fidelity and enabling differentiable rendering. It sets apart from standard perspective projection by supporting optimal tangent-plane projections [3293-optimal-gaussian-splatting.md] and specialized geometries such as cone-beam X-ray scanning [3458-3d-gaussian-splatting-rasterization-cone-beam-scanner-space.md].

### [Point-Based Ray Tracing for Visibility](10934-point-based-ray-tracing-for-visibility.md)
Point-Based Ray Tracing for Visibility serves as a sparse visibility oracle that evaluates transmittance along sampled light directions using a bounding volume hierarchy (BVH) of Gaussian proxies, enabling evaluation from any point in space in any direction. Unlike the camera-tied rasterizer, it decouples visibility estimation from screen-space projection, allowing it to act as a drop-in companion to standard 3D Gaussian Splatting (3DGS) by reusing the same EWA-splatting formulation for consistent blending without requiring training mismatch.

### [Primitive Representation](11838-primitive-representation.md)
Primitive Representation defines the geometric and photometric data structures used to approximate a 3D scene in Gaussian Splatting methods [G]. It solves the problem of representing continuous geometry and appearance with discrete, differentiable primitives that can be efficiently rasterized [G]. It sets itself apart from parent methods by explicitly defining the kernel shape (e.g., isotropic, half-space, or hybrid Bézier) and the associated attribute storage (e.g., opacity, normals, control points) that determine how light interacts with the primitive during rendering [G].

### [Shading and Lighting Models](11924-shading-and-lighting-models.md)
Shading and Lighting Models extend the standard 3D Gaussian Splatting rasterization pipeline to support physically based rendering (PBR), self-occlusion, and anti-aliased forward shading. While standard splatting assumes a fixed, uniform lighting environment and simple alpha blending, this family introduces mechanisms for deferred shading pipelines, light-space rasterization for shadows, and analytic integration approximations for multiscale fidelity. It differs from sibling methods like [Analytic-Splatting Forward Shading](3459-analytic-splatting-forward-shading.md) by focusing on material attributes and light interaction rather than just pixel-area integration, and from [Transparency and Blending Models](9274-transparency-and-blending-models.md) by explicitly handling light source geometry and PBR material buffers.

### [Reflective Gaussian Splatting](12321-reflective-gaussian-splatting.md)
Reflective Gaussian Splatting (Ref-Gaussian) is a framework for the real-time, high-quality rendering of reflective objects with inter-reflection effects, addressing the limitations of standard 3D Gaussian Splatting in modeling complex surfaces and multi-view inconsistencies. It distinguishes itself from sibling methods like [3D Gaussian Splatting Rasterization](2812-3d-gaussian-splatting-rasterization.md) by utilizing 2D Gaussian primitives for view-consistent geometry and employing physically based deferred rendering with split-sum approximation to stabilize optimization and enable efficient inter-reflection modeling without heavy Monte Carlo sampling.

### [Ray-Splat Intersection Algorithms](13401-ray-splat-intersection-algorithms.md)
Ray-splat intersection algorithms compute the contribution of 3D Gaussians to a pixel by analytically evaluating the Gaussian density along the viewing ray, rather than projecting the 3D Gaussian onto the 2D image plane. This approach solves the problem of numerical instability and geometric inaccuracy that arises when splats become degenerate or when perspective-correct depth estimation is required [3403-perspective-correct-3d-gaussian-splatting-via-pl-cker-coordi.md][5992-gaussian-opacity-fields-gof.md]. Unlike standard rasterization which approximates the 3D Gaussian as a 2D ellipse, these methods treat the Gaussian as a volumetric primitive, enabling accurate depth extraction and surface reconstruction [5992-gaussian-opacity-fields-gof.md].

### [Rasterization Pipeline Optimization](15109-rasterization-pipeline-optimization.md)
Rasterization Pipeline Optimization refers to techniques that accelerate the rendering of 3D Gaussians by improving the efficiency of the rasterization stage, addressing the bottleneck of processing non-intersecting pixels and managing memory bandwidth. It sets itself apart from sibling methods by focusing on the computational pipeline (sorting, hardware acceleration, and culling) rather than the primitive representation or shading models.

### Temporal Marginal Probability Filtering
Pre-rasterization culling step that removes 4D Gaussians with negligible temporal support at the current frame timestamp, stabilizing rendering speed across video length [S6, unofficial]. Compute the marginal probability $p_i(t)$ for each 4D Gaussian $i$ at the current frame's timestamp $t$. Discard Gaussians with negligible $p_i(t)$ before executing standard frustum culling. Unlike methods where Gaussian count scales with video length, this filtering keeps active Gaussians constant, making the approach friendly to long videos in terms of rendering speed [S6, unofficial].

### t-distribution truncation for splatting
A projection truncation technique that replaces the fixed three-sigma rule used in vanilla 3DGS with a $\nu$-dependent critical value interpolation to handle fat-tailed Student's t-distributions [S7]. For t-distributions with thin tails (high $\nu$), apply the standard three-sigma rule directly. For fat-tailed distributions (low $\nu$), obtain critical values for different $\nu$ degrees from reference [9] and interpolate between them to compute the appropriate truncation threshold. Using a fixed three-sigma threshold on fat-tailed t-distributions causes excessive truncation or leakage. Interpolation across $\nu$ degrees resolves this [S7].

### Progressive Normal Propagation
Uses progressive propagation along normals to fill texture-less regions [S5, unofficial].

### Splat TBO Upload & Layout
Packs per-splat data (center, covariance, DC color/alpha, optional SH) into Texture Buffer Objects (TBOs) for GPU consumption [S8, unofficial]. Iterate over splats. For each splat, copy center.xyz as raw float bits to d[0..2]. Pack covariance upper-triangle to d[3..5] using packHalf2x16: d[3]=covA[0],covA[1]; d[4]=covA[2],covB[0]; d[5]=covB[1],covB[2]. Pack DC color/alpha to d[6] using packDCColor. Set d[7]=0. Create GL_TEXTURE_BUFFER buffer with GL_RGBA32UI format. Bind to tbo_tex_. For non-DC SH coefficients, pack each coefficient's RGB into RGBA16F texels (B=0), layout is [splat0_c1, splat0_c2, …, splat1_c1, splat1_c2, …]. Create SH TBO with GL_RGBA16F format. Memory: 32 B/splat for base TBO + 8 B $\times$ sh_coeffs_per_splat_ $\times$ splat_count_ for SH TBO. Base TBO: 2 uvec4 texels per splat (32 B). Texel 0: center.xyz (float bits), packHalf2x16(cov00, cov01). Texel 1: packHalf2x16(cov02, cov11), packHalf2x16(cov12, cov22), packUnorm4x8(DC-baked RGBA), reserved. SH TBO: GL_RGBA16F, 8 B per non-DC SH coefficient per splat. Layout: [splat0_c1, splat0_c2, …, splat1_c1, splat1_c2, …] [S8, unofficial].

### 3D Gaussian Splatting for X-ray Projection Rasterization
A rendering technique that leverages 3D Gaussian Splatting (3DGS) to rasterize X-ray projections by modeling X-ray attenuation using the Beer-Lambert law, treating the volume as a collection of 3D Gaussians with density and isotropic absorption [S9, unofficial]. The exponential transmittance model $T(t)$ is defined as $T(t) = \exp\left(-\int_{t_0}^t \sigma(\mathbf{r}(s)) ds\right)$, where $\mathbf{r}(t) = \mathbf{o} + t\mathbf{d}$ represents a 3D point along a ray with origin $\mathbf{o}$ and direction $\mathbf{d}$, and $\sigma(\mathbf{p})$ denotes the density at point $\mathbf{p}$ [S9, unofficial]. Color attributes are optional and can be excluded from the rendering model, accounting solely for isotropic absorption [S9, unofficial].

### Ray-Gaussian Intersection
Project the 3D Gaussian's covariance and center onto the camera ray to convert the 3D influence into a 1D Gaussian function along that specific ray [S10].

## Operating characteristics
**Time Complexity:** $O(N \cdot P)$ where $N$ is the number of Gaussians and $P$ is the number of pixels, but optimized via tile-based culling to $O(N_{active} + P)$. The dominant cost is sorting $N$ Gaussians by depth, which is $O(N \log N)$ [S4, unofficial].

**Memory Complexity:** $O(N)$ for Gaussian attributes. VRAM usage is high: ~4GB to view, ~12GB to train for typical scenes [S4, unofficial]. Disk size is large: 1GB+ per scene [S4, unofficial].

**Performance:** Real-time rendering rates are achievable on modern GPUs (e.g., RTX 3090/4090) for scenes with millions of Gaussians [S1]. The original implementation uses CUB device radix sort for efficient sorting, which is a bottleneck in non-CUDA environments [S4, unofficial].

**Strengths:** High visual fidelity, real-time performance, differentiable training [S4, unofficial].

**Limitations:** High VRAM/disk usage, static scenes (without extensions like 4DGS), incompatibility with standard graphics pipelines without custom rasterizers [S4, unofficial].

## Background
3D Gaussian Splatting was introduced in the paper "3D Gaussian Splatting for Real-Time Radiance Field Rendering" by Kerbl et al. (2023) [S4, unofficial]. It represents a breakthrough in static scene rendering by using 3D Gaussian primitives instead of neural fields or meshes, enabling real-time rendering with high visual fidelity [S1]. The method builds on Structure from Motion (SfM) to initialize Gaussians from point clouds, followed by differentiable rasterization and stochastic gradient descent for optimization [S4, unofficial].
