# AnySplat Pipeline

Also called: Feed-forward 3D Gaussian Splatting from Unconstrained Views

## Overview
The AnySplat Pipeline is a feed-forward, transformer-based method for reconstructing 3D scenes from uncalibrated, unconstrained multi-view images without requiring camera poses or depth as input [S1, unofficial]. It differs from iterative optimization-based Gaussian Splatting by predicting Gaussian parameters, depth, and poses directly from images in a single forward pass, and from other generalizable methods by employing a differentiable voxelization module to convert pixel-wise Gaussians into a renderable set [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A tensor of $K$ uncalibrated RGB images. The standard input shape is $[1, K, 3, 448, 448]$ (batch, views, channels, height, width) [S1, unofficial]. Images are typically normalized to $[-1, 1]$ before encoding [S1, unofficial].
*   **Outputs:** A set of 3D Gaussians (defined by mean $\mu$, covariance parameters $\sigma, r, s$, and color $c$), predicted camera poses $p$ (extrinsic and intrinsic matrices), and a predicted depth map $D$ [S1, unofficial].

**Data Structures:**
The method constructs a set of pixel-wise 3D Gaussians. Each Gaussian is defined by:
*   $\mu \in \mathbb{R}^3$: 3D mean position.
*   $\sigma, r, s$: Parameters defining the 3D covariance matrix (scale, rotation, etc.).
*   $c \in \mathbb{R}^3$: Color (RGB).
These are voxelized into "pre-voxel 3D Gaussians" using a Differentiable Voxelization module [S1, unofficial].

**Steps:**
1.  **Encoding:** Input images are processed by a transformer-based geometry encoder [S1, unofficial].
2.  **Decoding:** Three decoder heads ($F_G, F_D, F_C$) predict:
    *   $F_G$: Gaussian parameters $(\mu, \sigma, r, s, c)$ [S1, unofficial].
    *   $F_D$: Depth map $D$ [S1, unofficial].
    *   $F_C$: Camera poses $p$ [S1, unofficial].
3.  **Gaussian Construction:** The predicted parameters are used to construct a set of pixel-wise 3D Gaussians [S1, unofficial].
4.  **Voxelization:** The pixel-wise Gaussians are voxelized into pre-voxel 3D Gaussians using the Differentiable Voxelization module [S1, unofficial].
5.  **Rendering:** Multi-view images and depth maps are rendered from the voxelized Gaussians using standard differentiable splatting [S1, unofficial].
6.  **Loss Computation:**
    *   **RGB Loss:** Rendered images are compared against ground truth images [S1, unofficial].
    *   **Geometry Loss:** Rendered depth maps, decoded depth $D$, and poses $p$ are used to compute geometry losses [S1, unofficial].
7.  **Supervision:** Geometries are supervised by pseudo-geometry priors obtained from a pretrained VGGT model [S1, unofficial].

**Pseudocode:**
```python
# Assume model is the trained AnySplat pipeline
# images: torch.Tensor of shape [1, K, 3, 448, 448], normalized to [-1, 1]

# 1. Run Inference
# The model performs encoding, decoding, and voxelization internally
gaussians, pred_context_pose = model.inference((images + 1) * 0.5)

# 2. Extract Outputs
# gaussians: Contains parameters for the 3D Gaussian set
# pred_context_pose: Dictionary containing 'extrinsic' and 'intrinsic' matrices
pred_all_extrinsic = pred_context_pose['extrinsic']
pred_all_intrinsic = pred_context_pose['intrinsic']

# 3. (Optional) Save/Render Video
# Uses the predicted poses and Gaussians to render novel views
save_interpolated_video(
    pred_all_extrinsic, 
    pred_all_intrinsic, 
    batch_size=1, 
    height=448, 
    width=448, 
    gaussians=gaussians, 
    image_folder="output", 
    decoder=model.decoder
)
```

**Parameters and Edge Cases:**
*   **Input Resolution:** Fixed at $448 \times 448$ per view [S1, unofficial].
*   **Number of Views ($K$):** Variable, but the model expects a batch of views. The exact maximum $K$ is not specified in the sources [S1, unofficial].
*   **Uncalibrated Input:** The method handles uncalibrated images, meaning no prior knowledge of camera intrinsics or extrinsics is required [S1, unofficial].
*   **Pseudo-Geometry Priors:** The reliance on VGGT for supervision implies that the quality of geometry is bounded by the accuracy of the VGGT model [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Feed-forward inference is significantly faster than iterative optimization-based Gaussian Splatting, as it avoids per-scene optimization loops [S1, unofficial]. Exact inference time depends on the transformer size and number of views $K$.
*   **Memory Complexity:** Memory usage is dominated by the transformer encoder/decoder and the storage of the predicted Gaussian set. The voxelization step adds overhead compared to direct splatting [S1, unofficial].
*   **Strengths:** Handles unconstrained, uncalibrated image sets; no iterative optimization required; generalizable across scenes [S1, unofficial].
*   **Limitations:** Relies on the quality of the pretrained VGGT model for geometry supervision; fixed input resolution; performance may degrade with very few or highly overlapping views if the transformer fails to generalize [S1, unofficial].
*   **Hardware:** Requires a GPU with CUDA support (tested on CUDA 12.1) [S1, unofficial].

## Background
AnySplat was introduced by InternRobotics as a feed-forward approach to 3D Gaussian Splatting from unconstrained views [S1, unofficial]. It builds on the principles of differentiable rendering and transformer-based scene reconstruction, aiming to bridge the gap between iterative optimization and real-time generalizable reconstruction [S1, unofficial].
