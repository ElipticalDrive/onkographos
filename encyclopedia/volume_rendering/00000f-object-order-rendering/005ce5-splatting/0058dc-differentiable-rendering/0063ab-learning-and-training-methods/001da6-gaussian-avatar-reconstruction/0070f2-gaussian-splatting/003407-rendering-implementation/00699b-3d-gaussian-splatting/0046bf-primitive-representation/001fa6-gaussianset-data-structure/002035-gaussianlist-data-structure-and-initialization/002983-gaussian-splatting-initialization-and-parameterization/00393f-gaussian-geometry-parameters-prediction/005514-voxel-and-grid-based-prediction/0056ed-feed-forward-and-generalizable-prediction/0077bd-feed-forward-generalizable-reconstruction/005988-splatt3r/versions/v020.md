# Splatt3R

Also called: Splatt3R: Zero-Shot Gaussian Splatting from Uncalibrated Image Pairs

## Overview
Splatt3R is a feed-forward model that takes two uncalibrated images as input and outputs 3D Gaussian parameters for geometry and appearance, without requiring camera intrinsics, extrinsics, or depth [S1, unofficial]. It extends the MASt3R architecture by adding a Gaussian prediction head to produce Gaussians directly from uncalibrated image pairs, avoiding per-scene optimization and explicit camera variable estimation [S2]. Unlike generalizable 3D-GS methods that only supervise novel viewpoints between input stereo views, Splatt3R supervises extrapolated viewpoints beyond the stereo baseline using a loss masking strategy [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Inputs:** Two uncalibrated RGB images $I_1, I_2 \in \mathbb{R}^{H \times W \times 3}$ [S1, unofficial].
- **Outputs:** A set of 3D Gaussian primitives defined by mean position $\mu$, covariance $\Sigma$ (parameterized by rotation $q$ and scale $s$), opacity $\alpha$, and color $c$ (or spherical harmonics $S$) [S1, unofficial][S2].

**Data Structures:**
The method predicts per-pixel Gaussians. For each pixel $j$ in the input images, the network outputs:
- Base position $x_j \in \mathbb{R}^3$ [S2].
- Position offset $\Delta x_j \in \mathbb{R}^3$ [S2].
- Rotation quaternion $q_j \in \mathbb{R}^4$ [S2].
- Scale vector $s_j \in \mathbb{R}^3$ [S2].
- Opacity $\alpha_j \in \mathbb{R}$ [S2].
- Color $c_j \in \mathbb{R}^3$ (constant view-independent) or spherical harmonics coefficients [S1, unofficial].

**Algorithm Steps:**

1. **Feature Encoding:** Encode the two input images $I_1, I_2$ using a shared Vision Transformer (ViT) encoder and cross-attention transformers. This backbone is based on MASt3R and is frozen during training [S1, unofficial].
2. **Point Cloud Prediction:** Use the frozen MASt3R backbone to predict 3D point locations $\hat{X}_1, \hat{X}_2$ and confidence maps $C_1, C_2$ in the coordinate frame of the first image [S1, unofficial].
3. **Gaussian Parameter Prediction:** Predict Gaussian parameters using a parallel 'Gaussian head' with DPT architecture [S1, unofficial]. This head outputs offsets $\Delta$, rotations $q$, scales $s$, opacities $\alpha$, and spherical harmonics $S$ for each pixel [S1, unofficial].
4. **Mean Position Calculation:** Calculate the mean position $\mu_j$ of each Gaussian as the sum of the predicted 3D point $x_j$ and the offset $\Delta x_j$:
   $$ \mu_j = x_j + \Delta x_j $$
   [S1, unofficial][S2]
5. **Covariance Construction:** The covariance matrix $\Sigma_j$ is reparameterized using the rotation quaternion $q_j$ and scale $s_j$ to ensure positive semi-definiteness:
   $$ \Sigma_j = R(q_j) S(s_j) S(s_j)^T R(q_j)^T $$
   where $R(q_j)$ is the rotation matrix derived from the quaternion and $S(s_j)$ is the diagonal scale matrix [S1, unofficial][S2].
6. **Primitive Union:** Construct the final set of Gaussian primitives as the union of primitives predicted from both input images [S1, unofficial].
7. **Rendering:** Render the novel view using standard 3D Gaussian Splatting rasterization [S1, unofficial].

**Training Procedure:**
1. **Stage 1 (Geometry):** Optimize the 3D point cloud’s geometry loss using the MASt3R backbone's point prediction head [S1, unofficial].
2. **Stage 2 (Appearance):** Optimize the novel view synthesis objective by training only the Gaussian head [S1, unofficial].
3. **Loss Masking:** Calculate a loss mask $M$ to prevent updates from unseen parts of the scene. For each target image point, unproject it and reproject it onto context images. A pixel is included in the mask if:
   - It is inside the frustum of at least one context view.
   - The rendered depth matches the ground truth depth.
   - The pixel has valid depth in the dataset [S1, unofficial].
4. **Loss Calculation:** The total loss $L$ is a weighted sum of masked MSE and LPIPS losses:
   $$ L = \lambda_{MSE} L_{MSE}(M \odot \hat{I}, M \odot I) + \lambda_{LPIPS} L_{LPIPS}(M \odot \hat{I}, M \odot I) $$
   where $\hat{I}$ is the rendered image, $I$ is the ground truth image, and $\odot$ denotes element-wise multiplication [S1, unofficial].
5. **Context Selection:** During training, select context images such that at least $\phi\%$ of pixels in the second image have correspondences in the first, and target images such that at least $\psi\%$ of pixels are present in at least one context image [S1, unofficial].

**Parameters:**
- Input resolution: $512 \times 512$ pixels [S1, unofficial].
- Activation functions: Normalization for quaternions, exponential for scales and offsets, sigmoid for opacities [S1, unofficial].
- Color parameterization: Constant view-independent color $S \in \mathbb{R}^3$ is used in experiments [S1, unofficial].
- Overlap thresholds: $\phi$ and $\psi$ control overlap. Typical values: Close (0.9, 0.9), Medium (0.7, 0.7), Wide (0.5, 0.5), Very Wide (0.3, 0.3) [S1, unofficial].

**Pitfalls:**
- Supervising rendering loss for pixels not visible in context views (obscured or outside frustums) is counterproductive and destructive to performance [S1, unofficial]. This is addressed by the loss masking strategy [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Single forward pass for reconstruction. Construction/export runtime is 1.10 s on ScanNet++ with 2 views [S2].
- **Memory Complexity:** Not given in the sources.
- **Performance:** On ScanNet++ test scenes, Splatt3R achieves PSNR 19.66, SSIM 0.757, LPIPS 0.234 for Close view overlap ($\phi=0.9, \psi=0.9$) [S1, unofficial]. On ScanNet++ with 2 views, it achieves PSNR 23.30, SSIM 0.823, LPIPS 0.125 [S2].
- **Strengths:** Pose-free, generalizable to uncalibrated in-the-wild images, capable of extrapolating viewpoints beyond the stereo baseline [S1, unofficial].
- **Limitations:** Performance degrades with wider baselines (lower overlap) [S1, unofficial].

## Background
Splatt3R was introduced in 2024 by Brandon, Zheng, Iro, and Victor from the University of Oxford [S1, unofficial]. It builds on the MASt3R foundation model for 3D geometry reconstruction [S1, unofficial]. The method is trained on the ScanNet++ dataset [S1, unofficial].
