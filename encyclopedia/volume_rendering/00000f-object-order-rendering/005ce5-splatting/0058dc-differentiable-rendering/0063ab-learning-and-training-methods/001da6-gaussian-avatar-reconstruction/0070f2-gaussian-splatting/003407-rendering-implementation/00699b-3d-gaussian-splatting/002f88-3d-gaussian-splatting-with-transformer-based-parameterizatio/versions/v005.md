# 3D Gaussian Splatting with Transformer-based Parameterization

Also called: GS-LRM

## Overview
This method enables feed-forward 3D Gaussian Splatting (3DGS) reconstruction by replacing iterative optimization with a transformer-based neural network that directly predicts Gaussian parameters from input images [S1]. It solves the latency bottleneck of standard 3DGS by eliminating the need for per-scene optimization, allowing for immediate novel view synthesis [S1]. Unlike iterative methods, it relies on learning a prior over Gaussian distributions from a training dataset, trading off per-scene adaptability for inference speed [S1].

## How it works
**Inputs:** A set of $N$ input images (typically $N=2$ to $4$) and their corresponding camera parameters (extrinsics and intrinsics) [S1].
**Outputs:** A set of 3D Gaussians defined by position, covariance (scale and rotation), opacity, and spherical harmonic coefficients for color [S1].

**Data Structures:**
1.  **Input Tokens:** Each image is processed into visual tokens. Camera parameters are encoded into embeddings.
2.  **Concatenated Sequence:** Visual tokens and camera embeddings are concatenated into a single sequence [S1].
3.  **Transformer Output:** A sequence of tokens representing the scene's Gaussian attributes [S1].
4.  **Gaussian Parameters:** Decoded from the transformer output tokens into the standard 3DGS parameter set [S1].

**Steps:**
1.  **Feature Extraction and Tokenization:** The input images are processed to extract visual features, which are tokenized. Camera parameters (extrinsics and intrinsics) are encoded into token embeddings [S1].
2.  **Sequence Construction:** The visual tokens and camera parameter embeddings are concatenated to form a unified input sequence [S1].
3.  **Transformer Processing:** The concatenated sequence is passed through a transformer block. The transformer attends to relationships between image features and camera poses to infer 3D structure [S1].
4.  **Parameter Decoding:** The output tokens from the transformer are decoded into the specific parameters for each 3D Gaussian (position, scale, rotation, opacity, and color) [S1].

**Formulas:**
Let $I$ be the set of input images and $C$ be the set of camera parameters.
The input sequence $S$ is formed as:
$$ S = \text{Concat}(\text{Tokenize}(I), \text{Encode}(C)) $$
The transformer function $T$ processes the sequence:
$$ O = T(S) $$
The Gaussian parameters $G$ are decoded from the output tokens $O$:
$$ G = \text{Decode}(O) $$
Where $G$ contains the mean $\mu$, covariance $\Sigma$ (derived from scale $s$ and rotation $r$), opacity $\alpha$, and spherical harmonic coefficients $c$ for each Gaussian primitive [S1].

**Parameters:**
-   Number of input images: Typically 2 to 4 [S1].
-   Transformer depth and width: Not given in the sources.

**Edge Cases and Pitfalls:**
-   **Scale Ambiguity:** If camera intrinsics are unknown or poorly estimated, scale ambiguity may arise. Methods like NoPoSplat address this by using a canonical coordinate system and intrinsics token embeddings [S1].
-   **View Overlap:** Performance may degrade in scenarios with minimal view overlap [S1].

## Subtopics

### [VolSplat](7674-volsplat.md)
VolSplat is a multi-view feed-forward framework for 3D Gaussian Splatting (3DGS) that replaces the standard pixel-aligned Gaussian prediction with a voxel-aligned prediction strategy. It solves the problems of view-biased density distributions and alignment errors (such as floaters) inherent in pixel-aligned methods by aggregating multi-view features into a shared 3D voxel grid before regressing Gaussian parameters. Unlike its parent method, which uses a transformer to decode tokens directly into Gaussian parameters, VolSplat explicitly constructs a 3D voxel feature grid via depth unprojection and refines it with a sparse 3D decoder to enable adaptive density control based on volumetric scene complexity.

### [Sequential Gaussian Attribute Decoding](16432-sequential-gaussian-attribute-decoding.md)
Sequential Gaussian Attribute Decoding is a method for estimating 3D Gaussian Splatting attributes (position, rotation, scale, opacity, and color) from tri-plane features by processing them in a fixed order rather than in parallel. It solves the problem of high degrees of freedom in joint attribute prediction by creating dependencies between attributes, allowing each decoder to specialize based on prior information. It differs from parallel decoders (e.g., HUGS [21]) which compute all attributes simultaneously.

## Operating characteristics
-   **Time Complexity:** Inference time is constant per scene, determined by the forward pass of the transformer and decoder, significantly faster than iterative optimization [S1].
-   **Memory Complexity:** Depends on the transformer size and the number of predicted Gaussians [S1].
-   **Performance:** Achieves high-quality novel view synthesis, particularly in scenarios with sufficient view overlap [S1].
-   **Strengths:** Real-time reconstruction; no per-scene optimization required [S1].
-   **Limitations:** Quality may suffer with minimal view overlap or unknown camera poses without specific adaptations (e.g., NoPoSplat) [S1].
-   **When to use:** When rapid reconstruction from a few views is required.
-   **When not to use:** When iterative optimization is feasible and higher per-scene fidelity is needed, or when camera poses are unknown and not handled by specific variants [S1].

## Background
This approach is part of the evolution of feed-forward neural radiance field (FFN) methods for 3D reconstruction. It builds upon earlier works like MVSplat, which combined multi-view feature extraction through transformers and cost volumes [S1]. GS-LRM specifically tokenizes images and camera parameters to predict Gaussian parameters directly, extending the concept to 3DGS primitives [S1]. NoPoSplat later addressed limitations regarding known camera poses by introducing intrinsics token embeddings [S1].
