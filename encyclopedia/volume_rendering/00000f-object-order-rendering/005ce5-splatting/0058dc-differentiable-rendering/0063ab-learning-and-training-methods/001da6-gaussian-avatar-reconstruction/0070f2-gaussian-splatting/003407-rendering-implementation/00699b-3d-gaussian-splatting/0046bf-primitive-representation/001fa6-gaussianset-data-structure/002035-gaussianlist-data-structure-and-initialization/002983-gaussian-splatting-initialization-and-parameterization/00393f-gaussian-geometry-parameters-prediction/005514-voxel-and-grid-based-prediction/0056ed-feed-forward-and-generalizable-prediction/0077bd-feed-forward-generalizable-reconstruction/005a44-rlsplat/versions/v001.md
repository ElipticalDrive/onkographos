# RLSplat

Also called: Resource-Linear Budget Control for Feed-forward 3D Gaussian Splatting

## Overview
RLSplat is a resource-linear, budget-controllable feed-forward 3D Gaussian Splatting (FF3DGS) framework that generates exactly $B$ Gaussians for a given scene, ensuring that inference latency and peak memory scale linearly with the budget $B$ [S1, unofficial]. Unlike sibling methods such as EcoSplat and F4 Splat, which predict a dense set of candidates and prune them (resulting in nearly constant inference cost regardless of the target budget), RLSplat uses a learned allocation policy to distribute the budget across local scene regions from the start [S1, unofficial]. This approach allows the method to adapt to diverse resource constraints in real-time applications like AR/VR and robotics without retraining [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of $V$ uncalibrated context images $\{I_i\}_{i=1}^V$ and a target Gaussian budget $B$ (an integer).
*   **Outputs:** A set of $B$ 3D Gaussians $\mathcal{G} = \{g_b\}_{b=1}^B$ and the context camera parameters $\{P_i\}_{i=1}^V$ [S1, unofficial]. Each Gaussian $g_b$ consists of a 3D center, opacity, scale, rotation, and color coefficients [S1, unofficial].

**Data Structures:**
1.  **Anchor Tokens:** The geometry backbone encodes the input images into $N$ anchor tokens $\{a_n\}_{n=1}^N$. Each anchor represents a local 3D region of the scene [S1, unofficial].
2.  **Allocation Vector:** A discrete vector $\mathbf{k} \in \mathbb{Z}_{\ge 0}^N$ where $k_n$ is the number of Gaussians assigned to anchor $n$, such that $\sum_{n=1}^N k_n = B$ [S1, unofficial].
3.  **Gaussian Tokens:** For each anchor $n$, $k_n$ Gaussian tokens are spawned. The total number of Gaussian tokens is exactly $B$ [S1, unofficial].

**Parameters:**
*   $B$: Target Gaussian budget. Typical evaluation values include 2K (2,048) and 64K [S1, unofficial]. On the ACID dataset with 8 views, $B=8,192$ (1,024 per view) is used [S1, unofficial]. On RE10K, $B=8,192$ is standard [S1, unofficial].
*   $K_{gs}$: Number of nearest Gaussian neighbors each token attends to during refinement. Default ablation value is 16 [S1, unofficial]. This can be changed at inference without retraining [S1, unofficial].
*   $K_{anc}$: Number of anchor neighbors used in the hierarchical neighbor search. Fixed value in ablations is 16 [S1, unofficial].
*   $C$: Number of rollouts (candidate allocations) drawn per training step for the Group Sequence Policy Optimization (GSPO) [S1, unofficial].

**Algorithm Steps:**

1.  **Geometry Encoding:** The geometry backbone encodes the input images $\{I_i\}$ into $N$ anchor tokens $\{a_n\}_{n=1}^N$ and predicts the camera parameters $\{P_i\}$ [S1, unofficial].
2.  **Gaussian Allocation:** The allocation policy $\pi_\psi$ assesses the local significance of each anchor (based on features like texture complexity) and predicts a discrete allocation $\mathbf{k}$ such that $\sum k_n = B$ [S1, unofficial]. This policy is trained using GSPO [S1, unofficial].
3.  **Token Spawning:** Each anchor $n$ spawns $k_n$ Gaussian tokens. The total number of Gaussian tokens is exactly $B$ [S1, unofficial].
4.  **Resource-Linear Decoding:**
    *   **Initialization:** The decoder instantiates initial Gaussian parameters (center, opacity, scale, rotation, color) from the spawned tokens [S1, unofficial].
    *   **Hierarchical Neighbor Search:** For each Gaussian token, the system identifies its $K_{gs}$ nearest Gaussian neighbors. This is done efficiently using a hierarchical neighbor search over the anchor tokens (using $K_{anc}$ anchor neighbors) to find the corresponding Gaussian neighborhoods [S1, unofficial].
    *   **Local Refinement:** Each Gaussian token refines its parameters through local cross-attention with its $K_{gs}$ nearest Gaussian neighbors [S1, unofficial]. This step ensures consistency among neighboring Gaussians [S1, unofficial].
5.  **Output:** The final set of $B$ refined Gaussians $\mathcal{G}$ and camera parameters $\{P_i\}$ are returned [S1, unofficial].

**Training (GSPO):**
To optimize the non-differentiable discrete allocation policy $\pi_\psi$, RLSplat uses Group Sequence Policy Optimization (GSPO) [S1, unofficial]:
1.  Draw $C$ candidate allocations $\mathbf{k}^{(c)} \sim \pi_{\text{old}} = \text{Mult}(B, \text{sg}(\mathbf{p}))$ for $c \in \{1, \dots, C\}$, where $\mathbf{p}$ are the policy probabilities and $\text{sg}(\cdot)$ stops gradients [S1, unofficial].
2.  For each rollout $c$, generate the 3DGS representation $\mathcal{G}^{(c)}$ and render an image $\hat{I}^{(c)}$ at novel target views [S1, unofficial].
3.  Compute the reconstruction loss $\mathcal{L}_{\text{recon}}$ against the ground-truth image $I$ without gradient tracking [S1, unofficial].
4.  Use $\mathcal{L}_{\text{recon}}$ as the reward signal to update the policy [S1, unofficial].
5.  Additional losses include a projection loss (to tie anchors to image regions) and a Voronoi loss (to maintain local neighborhood structure) [S1, unofficial]. Removing the projection loss causes training to fail entirely [S1, unofficial].

def rlsplat_forward(images, budget_B):
    """
    Forward pass of RLSplat.
    images: List of V context images.
    budget_B: Integer, total number of Gaussians to generate.
    Returns: List of B Gaussians, List of V camera parameters.
    """
    # 1. Geometry Backbone
    # Encodes images into anchor tokens and predicts camera parameters
    anchor_tokens, camera_params = geometry_backbone(images)
    N = len(anchor_tokens)
    
    # 2. Gaussian Allocation Policy
    # Predicts allocation proportions p, then samples discrete allocation k
    # p is the output of the policy network before sampling
    p = allocation_policy(anchor_tokens)
    
    # Sample discrete allocation k such that sum(k) == budget_B
    # In inference, this is typically a deterministic or single-sample draw
    k = sample_allocation(p, budget_B)
    
    # 3. Spawn Gaussian Tokens
    # Create B Gaussian tokens. Each anchor n spawns k[n] tokens.
    gaussian_tokens = []
    for n in range(N):
        for _ in range(k[n]):
            # Initialize token with anchor features
            token = init_gaussian_token(anchor_tokens[n])
            gaussian_tokens.append(token)
            
    # 4. Resource-Linear Decoder
    # Refine Gaussians via local cross-attention
    refined_gaussians = resource_linear_decoder(gaussian_tokens, k, camera_params)
    
    return refined_gaussians, camera_params

    gaussian_tokens: List of B initial Gaussian tokens.

    Returns: List of B refined Gaussian parameters.
    """
    B = len(gaussian_tokens)
    
    # Hierarchical Neighbor Search

    # Uses Kanc anchor neighbors to efficiently locate neighborhoods
    neighbors = hierarchical_neighbor_search(gaussian_tokens, k, Kgs=16, Kanc=16)
    
    # Local Cross-Attention Refinement

        token = gaussian_tokens[i]
        neighbor_tokens = neighbors[i]
        
        # Cross-attention with neighbors
        # Attention mechanism aggregates information from neighbors

    gaussians = decode_gaussians(refined_tokens, camera_params)

**Edge Cases and Pitfalls:**
*   **Precision:** The allocation policy produces discrete integers. Small errors in sampling can lead to $\sum k_n \neq B$. The sampling mechanism must guarantee the sum constraint [S1, unofficial].
*   **Boundary Conditions:** The hierarchical neighbor search relies on $K_{anc}$ and $K_{gs}$. If $K_{gs}$ is too small, local refinement may be insufficient; if too large, the linear complexity advantage diminishes [S1, unofficial].
*   **Training Stability:** Removing the projection loss causes training to fail entirely, as anchors are not tied to their image regions [S1, unofficial]. Removing the Voronoi loss causes a significant PSNR drop (2.51 dB) because Gaussians leave their anchor's cell and the hierarchical search retrieves incorrect neighbors [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The decoding cost is $O(B \cdot K_{gs})$, scaling linearly with the Gaussian budget $B$. This contrasts with global self-attention, which costs $O(B^2)$ [S1, unofficial].
*   **Memory Complexity:** Peak memory usage scales linearly with $B$ [S1, unofficial].
*   **Measured Performance:**
    *   At $B=2,048$, RLSplat achieves higher PSNR than F4 Splat while using 9.6× less peak memory and running 4.1× faster [S1, unofficial].
    *   On ACID ($B=8,192$), RLSplat achieves PSNR 22.84 dB, SSIM 0.643, LPIPS 0.353 [S1, unofficial].
    *   On RE10K ($B=8,192$), RLSplat achieves full-view PSNR 26.51 dB, compared to 23.42 dB for F4 Splat and 21.82 dB for EcoSplat [S1, unofficial].
*   **Strengths:**
    *   True resource-linearity: Latency and memory decrease as $B$ decreases [S1, unofficial].
    *   High-fidelity allocation: Concentrates Gaussians on high-frequency structures (e.g., thin stair balusters) while using fewer on smooth areas [S1, unofficial].
    *   No retraining required to change $B$ or $K_{gs}$ at inference [S1, unofficial].
*   **Limitations:**
    *   Requires reinforcement learning (GSPO) for policy training, which can be complex to implement [S1, unofficial].
    *   Performance is dependent on the quality of the geometry backbone and anchor token extraction [S1, unofficial].
*   **When to Use:** Applications requiring limited resource budgets, such as AR/VR, robotics, and digital content creation, where inference latency and memory are critical constraints [S1, unofficial].

## Background
RLSplat was proposed by Bae, Park, and Kim from KAIST [S1, unofficial]. It addresses the limitations of prior budget-controllable FF3DGS methods like EcoSplat and F4 Splat, which predict dense sets of Gaussians and then prune them, resulting in nearly constant inference latency and memory regardless of the target budget [S1, unofficial]. RLSplat introduces a resource-linear approach by learning a Gaussian allocation policy and using a resource-linear decoder with hierarchical neighbor search [S1, unofficial]. The method is part of the broader field of feed-forward 3D Gaussian Splatting, which aims to reconstruct 3D scenes from images in a single forward pass [S1, unofficial].
