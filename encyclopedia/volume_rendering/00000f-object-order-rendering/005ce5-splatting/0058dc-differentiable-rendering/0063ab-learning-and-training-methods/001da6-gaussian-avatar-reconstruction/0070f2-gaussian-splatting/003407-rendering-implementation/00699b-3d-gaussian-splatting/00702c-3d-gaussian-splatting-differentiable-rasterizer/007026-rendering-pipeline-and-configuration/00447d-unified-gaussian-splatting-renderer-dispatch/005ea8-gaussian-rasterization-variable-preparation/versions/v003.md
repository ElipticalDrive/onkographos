# Gaussian Rasterization Variable Preparation

Also called: render variable setup, splat parameter extraction

## Overview
Gaussian Rasterization Variable Preparation constructs the specific tensor dictionaries required by differentiable Gaussian rasterization kernels, transforming raw learned parameters into the formats expected by the CUDA/C++ backend [S1, unofficial]. It filters active Gaussians by temporal validity, normalizes geometric attributes, and computes derived values such as opacities and 2D means, ensuring the rasterizer receives consistent, normalized inputs for forward and backward passes [S1, unofficial].

## How it works
**Inputs:**
- `params`: A dictionary of PyTorch tensors containing raw Gaussian attributes, including `timestep`, `log_scales`, `logit_opacities`, `unnorm_rotations`, `rgb_colors`, and `means3D` [S1, unofficial].
- `curr_timestep`: An integer or float indicating the current time step for filtering active Gaussians [S1, unofficial].
- `w2c`: World-to-camera transformation matrix, required for depth/silhouette computation in specific variants [S1, unofficial].

**Outputs:**
- `rendervar`: A dictionary of tensors formatted for the standard differentiable Gaussian rasterizer [S1, unofficial].
- `depth_rendervar`: A dictionary formatted for depth/silhouette rendering, containing depth-specific color pre-computation [S1, unofficial].

**Data Structures:**
The output is a Python dictionary (`rendervar`) with the following keys, each mapping to a PyTorch tensor on the CUDA device:
- `means3D`: 3D positions of Gaussians, shape $(N, 3)$ [S1, unofficial].
- `colors_precomp`: Pre-computed colors (RGB), shape $(N, 3)$ [S1, unofficial].
- `rotations`: Normalized quaternions, shape $(N, 4)$ [S1, unofficial].
- `opacities`: Scalar opacities, shape $(N, 1)$ or $(N)$ [S1, unofficial].
- `scales`: Log-scales exponentiated, shape $(N, 3)$ [S1, unofficial].
- `means2D`: Zero-initialized 2D mean positions, shape $(N, 2)$ [S1, unofficial].

**Steps:**
1. **Temporal Filtering:** Identify active Gaussians by applying boolean indexing to `params['timestep']` where `params['timestep'] <= curr_timestep`. Store the resulting indices as `selected_params_idx` [S1, unofficial].
2. **Scale Tiling:** If `selected_params['log_scales'].shape[-1] == 1`, tile the log-scales along the last dimension to shape $(1, 3)$ using `torch.tile` to ensure uniform 3D scaling representation [S1, unofficial].
3. **Opacity Computation:** Compute final opacities from logit opacities using the sigmoid function:
   $$ \text{opacities} = \sigma(\text{logit\_opacities}) $$
   where $\sigma(x) = \frac{1}{1 + e^{-x}}$ [S1, unofficial].
4. **Scale Exponentiation:** Compute physical scales from log-scales:
   $$ \text{scales} = \exp(\text{log\_scales}) $$
   [S1, unofficial].
5. **Rotation Normalization:** Normalize the unnormalized rotation quaternions to unit length:
   $$ \text{rotations} = \text{normalize}(\text{unnorm\_rotations}) $$
   [S1, unofficial].
6. **2D Means Initialization:** Initialize `means2D` as a zero tensor on the CUDA device, matching the shape of `means3D` projected to 2D (typically $(N, 2)$) [S1, unofficial].
7. **Render Variable Construction:** Construct `rendervar` with keys: `means3D`, `colors_precomp` (taken directly from `rgb_colors`), `rotations`, `opacities`, `scales`, and `means2D` [S1, unofficial].
8. **Depth Render Variable Construction:** Construct `depth_rendervar` similarly to `rendervar`, but replace `colors_precomp` with the output of a helper function `get_depth_and_silhouette(selected_params['means3D'], w2c)` which computes depth and silhouette values from 3D means and the world-to-camera matrix [S1, unofficial].

**Pseudocode:**
```python
import torch
import torch.nn.functional as F

def prepare_gaussian_variables(params, curr_timestep, w2c=None):
    """
    Prepares tensors for Gaussian rasterization.
    
    Args:
        params (dict): Dictionary of raw Gaussian parameters.
        curr_timestep (float/int): Current time step for filtering.
        w2c (torch.Tensor): World-to-camera matrix, required for depth variant.
        
    Returns:
        tuple: (rendervar, depth_rendervar)
    """
    # Step 1: Filter by timestep
    # [G] Assuming params['timestep'] is a 1D tensor of shape (N,)
    active_mask = params['timestep'] <= curr_timestep
    selected_params = {k: v[active_mask] for k, v in params.items()}
    
    # Step 2: Handle single-dimension log_scales
    if selected_params['log_scales'].shape[-1] == 1:
        selected_params['log_scales'] = torch.tile(selected_params['log_scales'], (1, 3))
        
    # Step 3: Compute opacities
    opacities = torch.sigmoid(selected_params['logit_opacities'])
    
    # Step 4: Compute scales
    scales = torch.exp(selected_params['log_scales'])
    
    # Step 5: Normalize rotations
    rotations = F.normalize(selected_params['unnorm_rotations'], p=2, dim=1)
    
    # Step 6: Initialize means2D
    # [G] Assuming means3D is shape (N, 3). means2D is (N, 2) zeros on CUDA.
    means3D = selected_params['means3D']
    means2D = torch.zeros(means3D.shape[0], 2, device=means3D.device, dtype=means3D.dtype)
    
    # Step 7: Construct rendervar
    rendervar = {
        'means3D': means3D,
        'colors_precomp': selected_params['rgb_colors'],
        'rotations': rotations,
        'opacities': opacities,
        'scales': scales,
        'means2D': means2D
    }
    
    # Step 8: Construct depth_rendervar
    # [G] get_depth_and_silhouette is a helper not defined in the core method notes.
    # It computes depth/silhouette from means3D and w2c.
    if w2c is not None:
        depth_colors = get_depth_and_silhouette(means3D, w2c)
        depth_rendervar = {
            'means3D': means3D,
            'colors_precomp': depth_colors,
            'rotations': rotations,
            'opacities': opacities,
            'scales': scales,
            'means2D': means2D
        }
    else:
        depth_rendervar = None
        
    return rendervar, depth_rendervar

def get_depth_and_silhouette(means3D, w2c):
    """
    Helper to compute depth and silhouette for depth rendering.
    [G] Implementation details inferred from context: projects 3D means to camera space.
    """
    # Homogeneous coordinates
    ones = torch.ones(means3D.shape[0], 1, device=means3D.device, dtype=means3D.dtype)
    means_homo = torch.cat([means3D, ones], dim=1)
    
    # Transform to camera space
    means_cam = torch.matmul(means_homo, w2c.t())
    
    # Depth is the z-coordinate in camera space (assuming standard OpenGL/Camera convention)
    # Silhouette is typically 1.0 for all points
    depth = means_cam[:, 2]
    silhouette = torch.ones_like(depth)
    
    # Return as RGB tensor for compatibility with colors_precomp
    # [G] Depth is usually single channel, but rasterizer expects RGB.
    # We stack depth and silhouette appropriately or return a dummy RGB.
    # Based on standard practice, depth is often stored in one channel.
    # Here we return a tensor of shape (N, 3) where R=Depth, G=Silhouette, B=0 or similar.
    # Exact channel mapping depends on the specific rasterizer kernel.
    # We assume a simple stacking for the purpose of this variable preparation.
    return torch.stack([depth, silhouette, torch.zeros_like(depth)], dim=1)
```

**Parameters:**
- `curr_timestep`: Integer or float indicating the current time step to filter parameters [S1, unofficial].
- `kernel_size`: Fixed scale applied to all points in PCD Renderer variant. Default: 0.0 [S2, unofficial].
- `scaling_modifier`: Multiplier for Gaussian scales in PCD Renderer variant. Default: 1.0 [S2, unofficial].
- `white_background`: Boolean flag for background color in PCD Renderer variant. Default: True [S2, unofficial].
- `convert_SHs_python`: Boolean flag for SH conversion in PCD Renderer variant. Default: True [S2, unofficial].

**Edge Cases and Pitfalls:**
- **Single-Dimension Scales:** If log-scales have only one dimension, they must be tiled to 3 dimensions to match the expected $(N, 3)$ shape [S1, unofficial].
- **Rotation Normalization:** Unnormalized quaternions must be normalized to unit length to prevent distortion in the rasterization kernel [S1, unofficial].
- **Device Placement:** All tensors in `rendervar` must be on the same CUDA device as the rasterizer kernel to avoid runtime errors [S1, unofficial].
- **Depth Helper Dependency:** The `depth_rendervar` construction relies on an external helper `get_depth_and_silhouette`, which is not defined in the core method notes [S1, unofficial].

## Subtopics

### PCD Renderer
A renderer variant that treats input Gaussians as point clouds by forcing opacity to 1.0, scales to a fixed kernel size, and rotations to identity, while disabling spherical harmonics (SH) [S2, unofficial]. It retrieves 3D positions from the model, sets opacity to 1.0, sets `cov3D_precomp` to None, and initializes rotations as a zero tensor with the first component (w) set to 1.0, then normalized [S2, unofficial]. Precomputed colors are derived by dividing the model's RGB attribute by 255 [S2, unofficial]. It uses parameters `kernel_size` (default 0.0), `scaling_modifier` (default 1.0), `white_background` (default True), and `convert_SHs_python` (default True) [S2, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
The preparation step involves filtering, tensor operations (sigmoid, exp, normalize), and dictionary construction. These are $O(N)$ operations where $N$ is the number of active Gaussians. Memory usage is proportional to the number of active Gaussians, storing multiple copies of attributes (means, rotations, scales, opacities, colors) in the output dictionaries [S1, unofficial].

**Measured Performance:**
Not given in the sources.

**Scaling:**
Performance scales linearly with the number of active Gaussians. Filtering by timestep reduces $N$ if many Gaussians are inactive [S1, unofficial].

**Strengths and Limitations:**
- **Strengths:** Ensures consistent tensor formats for the rasterizer, handles temporal filtering for dynamic scenes, and normalizes geometric attributes [S1, unofficial].
- **Limitations:** Requires careful handling of device placement and tensor shapes. The depth rendering variant depends on an external helper function [S1, unofficial].

**When to Use:**
Use when preparing inputs for differentiable Gaussian rasterization in dynamic scenes or when specific rendering modes (like depth or PCD) are required [S1, S2, unofficial].

## Background
Originating from implementations in SplaTAM and GaussStudio, this method is part of the rendering pipeline for 3D Gaussian Splatting, specifically handling the transition from learned parameters to rasterizer-ready tensors [S1, S2, unofficial]. It supports dynamic scene reconstruction and avatar rendering by managing temporal validity of Gaussians [S1, unofficial].
