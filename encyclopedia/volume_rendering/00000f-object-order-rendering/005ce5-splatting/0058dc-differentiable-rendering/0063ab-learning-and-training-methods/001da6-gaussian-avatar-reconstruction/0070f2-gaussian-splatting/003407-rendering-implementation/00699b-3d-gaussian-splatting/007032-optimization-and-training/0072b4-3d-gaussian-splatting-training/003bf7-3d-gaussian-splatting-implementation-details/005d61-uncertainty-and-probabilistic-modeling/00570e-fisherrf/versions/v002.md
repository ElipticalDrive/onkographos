# FisherRF

Also called: Active View Selection and Mapping with Radiance Fields Using Fisher Information, Expected Information Gain (EIG) via Fisher Information, FisherRF Uncertainty Estimation

## Overview
FisherRF is a method for active view selection and uncertainty quantification in Radiance Fields that directly quantifies observed information on model parameters using Fisher Information, selecting candidate views by maximizing Expected Information Gain (EIG) [S2]. It sets itself apart from sibling methods like [SOGS](13171-sogs-second-order-anchor-for-advanced-3d-gaussian-splatting.md) or [Gaussian Frosting](15863-gaussian-frosting.md) by focusing on the selection of new training views rather than just optimizing existing parameters, leveraging the sparsity of the Hessian to achieve real-time evaluation speeds (70 fps) [S2].

## How it works
**Inputs and Outputs:**
- **Input:** A trained or partially trained Radiance Field model (specifically 3D Gaussian Splatting or Plenoxels), a pool of candidate camera viewpoints, and the current set of training views [S1, S2].
- **Output:** A ranked list of candidate views based on their Expected Information Gain (EIG), or a selected subset of views for active mapping [S2].

**Data Structures:**
- **Hessian Matrix ($H$):** Represents the second-order derivatives of the loss function with respect to the model parameters [S2]. In 3D Gaussian Splatting, this is computed per Gaussian [S2].
- **Fisher Information Matrix (FIM):** Approximated by the Hessian of the negative log-likelihood [S2].

**Method Steps:**
1. **Compute Hessian:** For the current model state, compute the Hessian matrix of the parameters with respect to the negative log-likelihood for each 3D Gaussian [S2]. The Hessian of the objective function in volumetric rendering is independent of ground truth data or actual image measurements, depending only on the camera parameters of the views used for training [S2].
2. **Diagonal Approximation:** Compute $H$ as the sum over all observed rays $D$ of the outer product of the rendering Jacobian weighted by $\Lambda_r$, plus $\epsilon I$ [S1]. Keep only the diagonal elements of $H$ for tractability, allowing the inverse $H^{-1}$ to be computed as element-wise reciprocals [S1].
3. **Compute Candidate Hessians:** For a candidate view $v$, compute $H_v$ using only the rays of view $v$, calculated exactly like $H$ [S1].
4. **Approximate Information Gain:** To make computation tractable, approximate the decrease in entropy (Information Gain) by its upper bound [S2]. This bound is defined as the trace of the product of the Hessian of the candidate view ($H_{cand}$) and the Hessian with respect to all previous views ($H_{prev}$) [S2]:
   $$ \text{EIG} \approx \text{Tr}(H_{cand} \cdot H_{prev}) $$
   The exact formulation is $EIG(v) = \frac{1}{2} \log \det(I + H_v H^{-1})$ [S1].
5. **Leverage Sparsity:** The matrices are highly sparse due to the disentangling of scene parameters with respect to disparate rays [S2]. This sparsity allows for a cost-effective computation of the matrix trace, with complexity comparable to back-propagation [S2].
6. **Rank and Select:** Evaluate all candidate views using the approximation [S2]. Select the next-best view $v^* = \arg\max_v EIG(v)$ [S1].

**Pseudocode:**
```python
import numpy as np

def compute_fisher_information_gain(model, candidate_views, training_views):
    """
    Computes the Expected Information Gain for a set of candidate views
    based on the Fisher Information (Hessian) of the current model.
    
    Args:
        model: A 3D Gaussian Splatting or Plenoxels model instance.
        candidate_views: List of camera poses to evaluate.
        training_views: List of camera poses already used for training.
        
    Returns:
        List of tuples (view, score) sorted by score descending.
    """
    # Step 1: Compute diagonal Hessian for current training views
    # H is independent of ground truth, relying only on camera params.
    # In 3DGS, this is computed per Gaussian and kept diagonal for tractability.
    H_prev = model.compute_diagonal_hessian(training_views)
    
    scores = []
    
    for view in candidate_views:
        # Step 3: Compute diagonal Hessian for the candidate view
        H_cand = model.compute_diagonal_hessian([view])
        
        # Step 4 & 5: Approximate EIG as Trace(H_cand * H_prev)
        # Due to sparsity and diagonal approximation, Tr(A*B) = sum(A_i * B_i)
        eig = np.sum(H_cand * H_prev)
        
        scores.append((view, eig))
        
    # Step 6: Sort by EIG
    scores.sort(key=lambda x: x[1], reverse=True)
    return scores
```

**Parameters:**
- **$\epsilon$:** Small scalar for the prior term $\epsilon I$ added to keep $H$ invertible [S1].
- **$\Lambda_r$:** Confidence weight for ray $r$ [S1]. In FisherRF, all rays share the same isotropic value, reducing the formulation to an unweighted squared-error loss [S1].
- **Performance Metric:** The method evaluates views at 70 fps when using 3D Gaussian Splatting [S2].
- **Hessian Computation Time:** 11.3 ms ± 33.3 µs for the diagonal Hessian computation [S2].

**Edge Cases and Pitfalls:**
- **Sparsity Assumption:** The efficiency relies on the high sparsity of the Hessian due to the disentangling of scene parameters [S2].
- **Approximation Error:** The use of the trace of the product as an upper bound for entropy decrease is an approximation [S2].
- **Invertibility:** The full Hessian is intractable to compute and store, handled by keeping only the diagonal elements [S1].

## Operating characteristics
- **Time Complexity:** The computation of the trace is as cost-effective as back-propagation due to matrix sparsity [S2].
- **Memory Complexity:** Not given in the sources.
- **Measured Performance:** Evaluates views at 70 fps with 3D Gaussian Splatting [S2]. The Hessian computation takes 11.3 ms ± 33.3 µs, compared to 1.1 s ± 2.5 ms for alternative methods like Goli et al. [S2].
- **Strengths:** Direct quantification of uncertainty on model parameters; efficient CUDA implementation for diagonal Hessian computation; state-of-the-art results in view selection and active mapping [S2].
- **Limitations:** Relies on the sparsity of the Hessian; uses a trace approximation for Information Gain [S2].
- **When to use:** When active view selection or active mapping is required for Radiance Fields, particularly 3D Gaussian Splatting or Plenoxels [S2].
- **When not to use:** Not given in the sources.

## Background
FisherRF was introduced by W. Jiang et al. in the paper "FisherRF: Active View Selection and Mapping with Radiance Fields Using Fisher Information" [S2]. It addresses the problem of active "training" view selection for volumetric rendering, a problem that was extensively studied before radiance fields but lacked literature specific to them [S2]. The method builds on the framework of 3D Gaussian Splatting and Plenoxels, leveraging their differentiable nature and parameter structure [S2]. It improves upon previous methods like Goli et al. by computing the Hessian directly rather than relying on hypothetical perturbation fields and multiple backward passes [S2].
