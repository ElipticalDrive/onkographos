# HDR-GS Initialization and Optimization

Also called: HDR-GS loss, HDR-GS training

## Overview
HDR-GS initialization and optimization is a method for initializing 3D Gaussian primitives and training a Gaussian Splatting model for High Dynamic Range (HDR) novel view synthesis. It addresses the limitation of standard 3D Gaussian Splatting (3DGS) which relies on Low Dynamic Range (LDR) images and often lacks accurate Structure-from-Motion (SfM) point clouds for initialization in HDR datasets. Unlike standard 3DGS which initializes from SfM points of LDR inputs, HDR-GS recalibrates camera parameters using SfM on LDR views captured at a single exposure time to generate initial 3D Gaussian positions, then optimizes the scene using a combined pixel-wise loss and a µ-law domain constraint loss. This approach establishes a robust data foundation for 3DGS-based algorithms in 3D HDR imaging.

## How it works

### Inputs and Outputs
**Inputs:**
*   A multi-view HDR dataset containing $N_v$ viewpoints.
*   For each viewpoint $j$, LDR images $\hat{I}_{lj}(t_s)$ captured at a specific exposure time $t_s$.
*   Ground truth HDR images $I_{hj}$ (available for synthetic scenes, not for real scenes).
*   Rendered LDR images $\hat{I}_{lj}(\Delta t_j)$ and HDR images $\hat{I}_{hj}$ generated from the current Gaussian set $G$.

**Outputs:**
*   Recalibrated camera intrinsics $M_{int}$ and extrinsics $\{M_j^{ext}\}_{j=1}^{N_v}$.
*   Initial number of points $N_p$ and their 3D positions $\{\mu_i\}_{i=1}^{N_p}$.
*   Optimized Gaussian parameters (position, features, opacity, scaling, rotation) and tone mapper network weights.

### Data Structures
The method initializes the Gaussian set $G$ as described in [GaussianList Data Structure and Initialization](9768-gaussian-list-data-structure-and-initialization.md).
*   **Positions:** Initialized from SfM output $\{\mu_i\}$.
*   **Other Parameters:** Randomly initialized.

### Algorithm Steps

1.  **SfM Initialization:**
    Select LDR images $\{\hat{I}_j(t_s)\}_{j=1}^{N_v}$ from the multi-view HDR dataset where all images share the same exposure time $t_s$. This constraint is critical because SfM relies on multi-view feature detection and matching, and exposure changes degrade accuracy [S1].
    Apply the SfM mapping function $F_{SfM}$ to obtain camera parameters and initial point cloud:
    $$ M_{int}, \{M_j^{ext}\}_{j=1}^{N_v}, N_p, \{\mu_i\}_{i=1}^{N_p} = F_{SfM}(\{\hat{I}_j(t_s)\}_{j=1}^{N_v}) $$
    where $N_v$ is the number of viewpoints, $M_{int}$ is the intrinsic matrix (constant across viewpoints), and $\{\mu_i\}$ are the initial 3D Gaussian positions [S1].

2.  **Gaussian Initialization:**
    Initialize the Gaussian set $G$ with $N_p$ points at positions $\{\mu_i\}$. Randomly initialize all other learnable parameters of $G$ (features, opacity, scaling, rotation) [S1].

3.  **Training Loop:**
    For each training iteration (total $3 \times 10^4$ iterations):
    a. **Rendering:** Render LDR images $\hat{I}_{lj}(\Delta t_j)$ and HDR images $\hat{I}_{hj}$ for a batch of $B$ viewpoints using the current Gaussian set $G$ and camera poses $\{M_j^{ext}\}$ [S1].
    b. **Loss Calculation:** Compute the total loss $L = L_p + \gamma \cdot L_c$ [S1].
    c. **Optimization:** Update parameters using the Adam optimizer [S1].

### Formulas

**Pixel-wise Loss ($L_p$):**
Combines L1 loss and D-SSIM loss on LDR images to ensure photometric consistency [S1]:
$$ L_p = \sum_{j=1}^B L_1(I_{lj}(\Delta t_j), \hat{I}_{lj}(\Delta t_j)) + \lambda \cdot L_{D-SSIM}(I_{lj}(\Delta t_j), \hat{I}_{lj}(\Delta t_j)) $$
where $B$ is the batch size, $I_{lj}$ is the ground truth LDR image, $\hat{I}_{lj}$ is the rendered LDR image, and $\lambda$ is a hyperparameter [S1].

**µ-law Domain Constraint Loss ($L_c$):**
Enforces a constraint on the rendered HDR image in the µ-law LDR domain, primarily for synthetic scenes where ground truth HDR is available [S1]:
$$ L_c = \sum_{j=1}^B \left( \frac{\log(1 + \mu \cdot norm(I_{hj}))}{\log(1 + \mu)} - \frac{\log(1 + \mu \cdot norm(\hat{I}_{hj}))}{\log(1 + \mu)} \right)^2 $$
where $I_{hj}$ is the ground truth HDR image, $\hat{I}_{hj}$ is the rendered HDR image, $\mu$ is the compression amount, and $norm(\cdot)$ is min-max normalization [S1].

**Total Loss:**
$$ L = L_p + \gamma \cdot L_c $$
where $\gamma$ controls the relative importance of $L_c$ [S1].

### Parameters and Hyperparameters

*   **$\mu$ (Compression):** The amount of compression in the µ-law normalization [S1].
*   **$\gamma$ (Constraint Weight):**
    *   Synthetic datasets: $\gamma = 0.6$ [S1].
    *   Real datasets: $\gamma = 0$ (since ground truth HDR images are unavailable) [S1].
*   **$\lambda$ (D-SSIM Weight):** Hyperparameter for the D-SSIM term in $L_p$. Value not explicitly given in the source text, but cited as part of the loss formulation [S1].
*   **Optimizer:** Adam [S1].
    *   $\beta_1 = 0.9$
    *   $\beta_2 = 0.999$
    *   $\epsilon = 1 \times 10^{-15}$ [S1]
*   **Learning Rates:**
    *   Point cloud position: Initial $1.6 \times 10^{-4}$, exponentially decaying to $1.6 \times 10^{-6}$ [S1].
    *   Point feature: $2.5 \times 10^{-3}$ [S1].
    *   Opacity: $5 \times 10^{-2}$ [S1].
    *   Scaling: $5 \times 10^{-3}$ [S1].
    *   Rotation: $1 \times 10^{-3}$ [S1].
    *   Tone mapper network: Initial $5 \times 10^{-4}$, exponentially decaying to $5 \times 10^{-5}$ [S1].
*   **Training Iterations:** $3 \times 10^4$ [S1].

### Edge Cases and Pitfalls
*   **SfM Input Constraint:** Only HDR views under the same exposure time are used as SfM inputs. Using images with different exposure times degrades the accuracy of SfM due to feature detection/matching failures [S1].
*   **Real vs. Synthetic Scenes:** The µ-law constraint loss $L_c$ is not used for real scenes because ground truth HDR images are not provided. In these cases, $\gamma$ is set to 0 [S1].

## Background

HDR-GS was introduced in the paper "HDR-GS: Efficient High Dynamic Range Novel View Synthesis at 1000x Speed via Gaussian Splatting" [S1]. The method addresses the limitations of voxel-based methods and the original 3DGS, which do not natively support HDR imaging and often lack SfM point clouds for initialization in HDR datasets [S1]. It builds on the 3DGS framework [15] and incorporates techniques from HDR-NeRF [14] for handling HDR data. The method was implemented using PyTorch [75] and tested on datasets collected by [14], including real and synthetic scenes from Blender [74].
