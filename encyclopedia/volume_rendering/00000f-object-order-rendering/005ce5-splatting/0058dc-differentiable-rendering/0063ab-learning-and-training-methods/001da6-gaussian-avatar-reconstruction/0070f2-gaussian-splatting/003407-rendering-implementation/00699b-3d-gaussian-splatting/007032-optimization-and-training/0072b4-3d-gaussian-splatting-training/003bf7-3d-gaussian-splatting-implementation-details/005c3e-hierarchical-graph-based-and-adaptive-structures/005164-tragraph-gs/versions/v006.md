# TraGraph-GS

Also called: Trajectory Graph-based Gaussian Splatting

## Overview
TraGraph-GS is a rendering method for arbitrary large-scale scenes that combines graph-based adaptive spatial partitioning with regularization constraints and adaptive region selection [S1]. It addresses the limitations of standard 3D Gaussian Splatting (3DGS) in large-scale contexts, specifically memory overflow, textureless region artifacts, and floating boundary artifacts during novel view synthesis [S1]. Unlike standard 3DGS which treats the scene as a monolithic set of primitives, TraGraph-GS decouples the scene into connected local regions and a coarse global representation, rendering novel views by progressively combining these sources based on visibility matching [S1].

## How it works
**Inputs:** A set of disordered scene photographs (images) and their associated camera poses.
**Outputs:** Rendered images for novel viewpoints.

**Data Structures:**
1.  **Camera Connectivity Graph:** $G = (V, E, w)$.
    *   $V = \{v_1, ..., v_n\}$: Vertices representing input images.
    *   $E = \{(v_i, v_j) | v_i, v_j \in V\}$: Edges connecting image pairs.
    *   $w: E \rightarrow \mathbb{R}$: Edge weights defined by the count of feature matches between image pairs. Higher weights indicate larger co-visible regions [S1].
2.  **Local Gaussian Sets:** $\{G_i\}_{i=1}^k$, where $k$ is the number of segmented regions. Each $G_i$ contains 3D Gaussian primitives $\{ \mu_j, \Sigma_j, \alpha_j, c_j \}$ (position, covariance, opacity, color) trained independently for region $i$ [S1].
3.  **Global Gaussian Set:** $G_{global}$: A coarse representation trained on downsampled data, avoiding densification [S1].

**Algorithm Steps:**

1.  **Graph Construction:** Construct $G$ by computing feature matches between all image pairs. Set $w(v_i, v_j)$ to the number of matches [S1].
2.  **Graph Segmentation:** Divide $G$ into $k$ regions $\{P_i\}_{i=1}^k$ using BFS-based segmentation to ensure connectivity and balanced node distribution [S1].
    *   Initialize unassigned nodes $U = V$.
    *   Select seed node $n \in U$ with the highest degree.
    *   Perform BFS from $n$, adding nodes to the current region until it contains $|V|/k$ nodes.
    *   For remaining unassigned nodes, calculate a score $s_i$ relative to existing regions and assign them to maintain balance [S1].
3.  **Local Training:** Train local 3D Gaussians independently for each region $P_i$. The training loss $L$ for each region is:
    $$ L = (1 - \lambda)L_1 + \lambda L_{SSIM} + L_{mv} $$
    where $L_1$ and $L_{SSIM}$ are standard reconstruction losses [S1].
4.  **Multi-View Constraint ($L_{mv}$):** To improve geometry in textureless regions, render depth and normal maps for each image. For a pixel $p$ in a reference view, establish a spatial plane with normal $n$ and distance $d$. Project $p$ to a corresponding pixel $p'$ in a neighborhood view using homography warping. Compute Normalized Cross Correlation (NCC) between patches at $p$ and $p'$:
    $$ L_{mv} = \sum_{p \in P_i} (1 - \text{NCC}(p, p')) $$
    [S1]
5.  **Multi-Scale Constraint:** Apply position-aware point adaptive control to adjust Gaussian scales based on viewer distance. Define a scaling factor $\gamma(\mu)$:
    $$ \gamma(\mu) = \begin{cases} 1 & \text{if } \|\mu - c\|_2 < 2r \\ \|\mu - c\|_2 / r - 1 & \text{if } \|\mu - c\|_2 \ge 2r \end{cases} $$
    where $r$ is the scene radius and $c$ is the camera center [S1].
    *   If $\max(s) < g \cdot \gamma(\mu)$, clone the Gaussian.
    *   Otherwise, split the Gaussian.
    *   Remove Gaussians where $\max(s)$ exceeds a threshold [S1].
6.  **Global Training:** Train $G_{global}$ by downsampling point clouds and images. Explicitly avoid the Gaussian densification process to prevent excessive memory consumption [S1].
7.  **Novel View Rendering:**
    *   Render the novel viewpoint using $G_{global}$ and each local set $G_i$ separately.
    *   Calculate a matching score $S$ for each local-global pair:
        $$ S = (1 - \lambda)L_1 + \lambda L_{SSIM} $$
        Higher $S$ indicates higher likelihood of visibility [S1].
    *   Sort local Gaussians in descending order of $S$: $G_1, G_2, ..., G_k$.
    *   Compute projection opacity $o_i(p)$ for each pixel $p$:
        $$ o_i(p) = \sum_{i=1}^{N} \alpha_i \prod_{j=1}^{i-1} (1 - \alpha_j) $$
        [S1]
    *   Compute final pixel color $c(p)$ using progressive rendering with weights $w_i$:
        $$ w_i = \begin{cases} o_i(p) & \text{if } \sum_{j=1}^{i-1} o_j(p) < \beta \\ 0 & \text{otherwise} \end{cases} $$
        $$ c(p) = \sum_{i=1}^{k} w_i c_i(p) $$
        where $\beta$ is an overlapped opacity threshold [S1].

    # 1. Graph Construction
    graph = build_camera_connectivity_graph(images) # Edges weighted by feature match count
    
    # 2. Graph Segmentation
    regions = bfs_graph_segmentation(graph, k=10) # Returns list of node sets
    
    # 3. Local Training
    local_gaussians = []
    for region_nodes in regions:
        # Apply Multi-View and Multi-Scale constraints during training

    scores = []
    for i, g_local in enumerate(local_gaussians):

        s = compute_matching_score(g_local, global_gaussians, camera_pose)
        scores.append((s, i))
        
    # Sort local Gaussians by score descending
    scores.sort(key=lambda x: x[0], reverse=True)
    sorted_indices = [idx for _, idx in scores]

    accumulated_opacity = zeros_like(final_color)

        color_i = render_gaussians(camera_pose, g)

        final_color = final_color * (1 - opacity_i) + color_i * opacity_i
        accumulated_opacity = accumulated_opacity + opacity_i * (1 - accumulated_opacity)
        
        # Apply weight logic from Eq 11/10
        # w_i is effectively opacity_i if condition met, else 0
        # However, Eq 10 sums w_i * c_i. Eq 11 defines w_i.
        # The standard alpha blending is implicit in the accumulation if we just blend.
        # The specific TraGraph logic uses w_i to gate the contribution.
        
        # Re-evaluating Eq 10/11 strictly:
        # c(p) = sum(w_i * c_i(p))
        # w_i = o_i(p) if sum_{j=1}^{i-1} o_j(p) < beta else 0
        
        # We need to re-calculate based on the sorted order

    final_color = zeros_like(color_global)
    prev_opacity_sum = zeros_like(final_color)
    
    for idx in sorted_indices:
        g = local_gaussians[idx]
        color_i = render_gaussians(camera_pose, g)
        opacity_i = compute_opacity(camera_pose, g)
        
        # Determine weight w_i
        # Condition: sum of opacities of PREVIOUSLY processed (higher score) Gaussians < beta
        weight = where(prev_opacity_sum < beta, opacity_i, 0.0)
        
        final_color += weight * color_i
        prev_opacity_sum += opacity_i
        
    return final_color

**Edge Cases and Pitfalls:**
*   **Memory Overflow:** Standard 3DGS densification on large scenes causes memory overflow. TraGraph-GS mitigates this by training locally and avoiding densification in the global model [S1].
*   **Boundary Artifacts:** Naive combination of local Gaussians causes floating artifacts or holes. The progressive rendering strategy with matching scores resolves this [S1].
*   **Textureless Regions:** Without multi-view constraints, geometry reconstruction fails. The NCC-based $L_{mv}$ is critical here [S1].

## Operating characteristics
*   **Time Complexity:** Training is parallelized across regions, reducing per-GPU memory load but increasing total training time due to multiple optimization runs and global training. Rendering novel views requires sorting local Gaussians and progressive blending, adding overhead compared to standard 3DGS [S1].
*   **Memory Complexity:** Significantly lower peak memory usage than monolithic 3DGS for large scenes, as local models are smaller and the global model is coarse and undensified [S1].
*   **Performance:** Evaluated on large-scale aerial (Mill-19, UrbanScene3D) and ground-level datasets (SmallCity, Campus, Road, General) with thousands of images [S1].
*   **Strengths:** Handles arbitrary large-scale scenes; maintains real-time performance; improves texture in textureless regions; reduces boundary artifacts.
*   **Limitations:** Requires initial feature matching and graph segmentation; parameter tuning for $k$ (regions) and $\beta$ (opacity threshold) is necessary [S1].

## Background
TraGraph-GS was proposed to address the scalability issues of 3D Gaussian Splatting in large-scale environments. It builds upon the standard 3DGS framework [11] but introduces structural constraints via graph theory. The method was published in 2026 [S1].
