# TraGraph-GS

Also called: Trajectory Graph-based Gaussian Splatting

## Overview
TraGraph-GS is a high-quality rendering method for arbitrary large-scale scenes that employs graph-based adaptive spatial partitioning, regularization constraints, and adaptive region selection to maintain real-time performance across vastly different scales [S1]. It distinguishes itself from sibling methods like FlexGS and Mipmap-GS by explicitly constructing a camera connectivity graph to drive spatial partitioning and using a progressive rendering strategy with matching scores to blend local and global Gaussian representations for novel viewpoints, thereby avoiding boundary artifacts common in simple global aggregation [S1].

## How it works
**Inputs:** A set of disordered scene photographs (images) and their associated camera poses.
**Outputs:** A rendered image for a novel viewpoint.

**Data Structures:**
1.  **Camera Connectivity Graph:** $G = (V, E, w)$, where $V = \{v_1, ..., v_n\}$ are vertices (images), $E$ are edges, and $w: E \to \mathbb{R}$ are weights representing feature matching counts between image pairs [S1].
2.  **Regions:** A partition of $V$ into $k$ disjoint sets $\{P_i\}_{i=1}^k$.
3.  **Local Gaussians:** For each region $P_i$, a set of 3D Gaussians $\{G_{i,j}\}$ optimized independently. Each Gaussian $G$ has mean $\mu$, covariance $\Sigma$ (parameterized by rotation $\mathbf{R}$ and scaling $\mathbf{S}$), opacity $\alpha$, and color $c$.
4.  **Global Gaussians:** A coarse set of Gaussians $\{G_{global}\}$ trained on downsampled data [S1].

**Parameters:**
*   $k$: Number of segmented regions.
*   $\lambda$: Weight for SSIM in loss functions (typical value from 3DGS [11], not explicitly specified in [S1] but implied by standard usage).
*   $\beta$: Overlapped opacity threshold for progressive rendering (Not given in the sources).
*   $r$: Scene radius.
*   $c$: Center of cameras.
*   $g$: Threshold multiplier for cloning/splitting (Not given in the sources).

**Steps:**

1.  **Graph Construction:** Construct $G$ by computing feature matches between all image pairs. Set $w(v_i, v_j)$ to the count of matches [S1].
2.  **Graph Segmentation:** Divide $G$ into $k$ regions using BFS-based segmentation:
    a. Initialize unassigned nodes $U = V$.
    b. While $U$ is not empty:
        i. Select seed node $n \in U$ with the highest degree.
        ii. Perform BFS from $n$, adding nodes to the current region until it contains $|V|/k$ nodes.
        iii. For remaining unassigned nodes, calculate a score $s_i$ relative to existing regions and assign them to maintain balance [S1].
3.  **Local Training:** For each region $P_i$:
    a. Initialize Gaussians from the point cloud of images in $P_i$.
    b. Optimize Gaussians using the loss function:
       $$ L = (1 - \lambda)L_1 + \lambda L_{SSIM} + L_{mv} $$
       where $L_1$ and $L_{SSIM}$ are standard reconstruction losses [S1].
    c. **Multi-View Constraint ($L_{mv}$):** Render depth and normal maps. For each pixel $p$ in a reference view, establish a spatial plane $(d, n)$. Project $p$ to neighborhood view $p'$ using homography. Compute Normalized Cross Correlation (NCC) between patches at $p$ and $p'$.
       $$ L_{mv} = \sum_{p \in P_i} (1 - NCC(p, p')) $$
    d. **Multi-Scale Constraint:** Apply position-aware point adaptive control. Define scale factor $\gamma(\mu)$:
       $$ \gamma(\mu) = \begin{cases} 1 & \text{if } \|\mu - c\|_2 < 2r \\ \|\mu - c\|_2 / r - 1 & \text{if } \|\mu - c\|_2 \ge 2r \end{cases} $$
       If directional gradient exceeds threshold:
       - If $\max(s) < g \cdot \gamma(\mu)$, clone the Gaussian.
       - Else, split the Gaussian.
       - Prune Gaussians with $\max(s)$ below a threshold [S1].
4.  **Global Training:** Train a coarse global Gaussian representation by downsampling point clouds and images, explicitly avoiding densification to prevent memory overflow [S1].
5.  **Novel View Rendering:**
    a. Render the novel viewpoint using local Gaussians and global Gaussians separately.
    b. Calculate matching score $S$ for each local Gaussian $G_i$:
       $$ S = (1 - \lambda)L_1 + \lambda L_{SSIM} $$
       Higher $S$ indicates higher visibility likelihood [S1].
    c. Sort local Gaussians in descending order of $S$: $G_1, G_2, ..., G_k$.
    d. Compute projection opacity $o_i(p)$ for each pixel $p$:
       $$ o_i(p) = \alpha_i \prod_{j=1}^{i-1} (1 - \alpha_j) $$
    e. Compute final color $c(p)$ using progressive rendering:
       $$ c(p) = \sum_{i=1}^k w_i c_i(p) $$
       where weight $w_i$ is:
       $$ w_i = \begin{cases} o_i(p) & \text{if } \sum_{j=1}^{i-1} o_j(p) < \beta \\ 0 & \text{if } \sum_{j=1}^{i-1} o_j(p) \ge \beta \end{cases} $$
       This prioritizes local Gaussians with higher contributions and refines regions with lower contributions [S1].

## Operating characteristics
*   **Time Complexity:** Training is parallelized across regions, reducing per-region memory and time. Global training is coarse and fast. Novel view rendering requires sorting local Gaussians and computing matching scores, adding overhead compared to standard splatting.
*   **Memory Complexity:** Partitioning allows handling large scenes that would exceed GPU memory for a single global set. Global training uses downsampling to minimize memory.
*   **Strengths:** Handles large-scale scenes with varying distances and textureless regions effectively. Avoids floating artifacts at region boundaries.
*   **Limitations:** Requires feature matching for graph construction. Performance depends on the quality of graph segmentation. Progressive rendering adds computational cost per pixel.
*   **When to use:** Large-scale scenes with sparse or disordered camera trajectories where standard 3DGS fails due to memory or quality issues.
*   **When not to use:** Small-scale scenes where standard 3DGS is sufficient and faster.

## Background
TraGraph-GS was proposed in "TraGraph-GS: Trajectory Graph-based Gaussian Splatting for Arbitrary Large-Scale Scene Rendering" [S1]. It addresses limitations of previous methods like VastGaussian [14] and others [2, 1] that either neglect structural information or produce artifacts. It builds on the 3D Gaussian Splatting framework [11] and integrates concepts from graph segmentation and multi-view geometry.
