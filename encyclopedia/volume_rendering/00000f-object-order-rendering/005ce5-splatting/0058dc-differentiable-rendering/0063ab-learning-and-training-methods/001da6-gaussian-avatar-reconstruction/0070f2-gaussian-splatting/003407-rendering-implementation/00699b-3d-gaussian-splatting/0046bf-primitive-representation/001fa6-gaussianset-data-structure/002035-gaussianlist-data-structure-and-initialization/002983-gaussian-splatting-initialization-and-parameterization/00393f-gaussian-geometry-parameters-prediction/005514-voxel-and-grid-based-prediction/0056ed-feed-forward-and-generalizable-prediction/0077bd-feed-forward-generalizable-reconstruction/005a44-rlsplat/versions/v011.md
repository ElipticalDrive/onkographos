# RLSplat

Also called: Resource-Linear Budget Control for Feed-forward 3D Gaussian Splatting

## Overview
RLSplat is a resource-linear, budget-controllable feed-forward 3D Gaussian Splatting (FF3DGS) framework that generates exactly $B$ Gaussians from uncalibrated input images, ensuring that inference latency and peak memory scale linearly with the requested Gaussian budget $B$ [S1, unofficial]. Unlike prior budget-controllable methods (e.g., EcoSplat, F4 Splat) that predict a dense set of candidates and subsequently prune or select them—resulting in nearly constant inference costs regardless of the target budget—RLSplat learns a Gaussian allocation policy to distribute exactly $B$ Gaussians across local scene regions from the start [S1, unofficial]. It solves the problem of rigid resource usage in real-time applications like AR/VR and robotics by allowing the user to trade rendering quality for computational cost without retraining the model [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** $V$ uncalibrated context images $\{I_i\}_{i=1}^V$, a target Gaussian budget $B$ (integer), and hyperparameters $K_{gs}$ (number of Gaussian neighbors for refinement) and $K_{anc}$ (number of anchor neighbors for hierarchical search) [S1, unofficial].
*   **Outputs:** A set of $B$ 3D Gaussians $\mathcal{G} = \{g_b\}_{b=1}^B$, where each $g_b$ consists of a 3D center, opacity, scale, rotation, and color coefficients, along with the predicted camera parameters $\{P_i\}_{i=1}^V$ for the context images [S1, unofficial].

**Data Structures:**
1.  **Anchor Tokens:** A set of $N$ tokens $\{a_n\}_{n=1}^N$ extracted from the geometry backbone, each representing a local 3D region of the scene [S1, unofficial].
2.  **Allocation Vector:** A discrete vector $k \in \mathbb{Z}_{\ge 0}^N$ where $k_n$ is the number of Gaussians assigned to anchor $n$, such that $\sum_{n=1}^N k_n = B$ [S1, unofficial].
3.  **Gaussian Tokens:** A set of $B$ tokens generated by spawning $k_n$ tokens at each anchor $n$ [S1, unofficial].
4.  **Hierarchical Neighbor Search Structure:** A data structure enabling efficient retrieval of the $K_{gs}$ nearest Gaussian tokens and $K_{anc}$ nearest anchor tokens for any given token [S1, unofficial].

**Algorithm Steps:**

1.  **Geometry Encoding:** The geometry backbone encodes the input images $\{I_i\}$ into $N$ anchor tokens $\{a_n\}_{n=1}^N$ and predicts the camera parameters $\{P_i\}_{i=1}^V$ [S1, unofficial].
2.  **Gaussian Allocation:** The allocation policy $\pi_\psi$ assesses the local significance of each anchor (based on image features like texture complexity) and predicts a discrete allocation vector $k$ [S1, unofficial]. The policy is trained using Group Sequence Policy Optimization (GSPO) [S1, unofficial].
    *   During training, $C$ rollouts (candidate allocations) are drawn from the policy: $k^{(c)} \sim \pi_{old} = \text{Mult}(B, \text{sg}(p))$, where $\text{sg}(\cdot)$ stops gradients [S1, unofficial].
    *   For each rollout, the representation is generated, rendered to novel views, and a reconstruction loss $\mathcal{L}_{recon}$ is computed against ground-truth images to serve as the reward signal [S1, unofficial].
3.  **Token Spawning:** Each anchor $n$ spawns exactly $k_n$ Gaussian tokens. The total number of Gaussian tokens is exactly $B$ [S1, unofficial].
4.  **Resource-Linear Decoding:**
    *   **Initialization:** The decoder instantiates initial Gaussian parameters (center, scale, rotation, opacity, color) from the $B$ Gaussian tokens [S1, unofficial].
    *   **Hierarchical Neighbor Search:** For each Gaussian token, the system identifies its $K_{gs}$ nearest Gaussian neighbors and $K_{anc}$ nearest anchor neighbors using a hierarchical neighbor search [S1, unofficial].
    *   **Local Refinement:** Each Gaussian token refines its parameters via local cross-attention over its $K_{gs}$ nearest Gaussian neighbors [S1, unofficial]. This step ensures consistency among neighboring Gaussians [S1, unofficial].
5.  **Rendering:** The final set of $B$ Gaussians $\mathcal{G}$ is rendered into target views using differentiable rasterization [Parent].

**Formulas:**
The mapping from inputs to output is defined as:
$$ (\mathcal{G}, \{P_i\}_{i=1}^V) = F_\theta(\{I_i\}_{i=1}^V, B) $$
$$ \mathcal{G} = \{g_b\}_{b=1}^B $$
where $g_b$ contains the 3D center, opacity, scale, rotation, and color coefficients [S1, unofficial].

The allocation constraint is:
$$ k \in \mathbb{Z}_{\ge 0}^N, \quad \sum_{n=1}^N k_n = B $$
[S1, unofficial]

**Parameters:**
*   $B$: Target Gaussian budget. Typical values: 2K (2,048), 8K (8,192), 64K [S1, unofficial].
*   $K_{gs}$: Number of nearest Gaussian neighbors for refinement. Default ablation value: 16. Can be changed at inference without retraining [S1, unofficial].
*   $K_{anc}$: Number of anchor neighbors for hierarchical search. Fixed value in ablations: 16 [S1, unofficial].
*   $C$: Number of rollouts (candidate allocations) drawn per training step for GSPO. Not given in the sources.

**Pseudocode:**

```python
def RLSplat(context_images, budget_B, K_gs, K_anc):
    """
    RLSplat inference pipeline.
    
    Args:
        context_images: List of V uncalibrated RGB images.
        budget_B: Integer, total number of Gaussians to generate.
        K_gs: Integer, number of Gaussian neighbors for local refinement.
        K_anc: Integer, number of anchor neighbors for hierarchical search.
        
    Returns:
        gaussians: List of B 3D Gaussian objects.
        cameras: List of V camera parameters.
    """
    # Step 1: Geometry Encoding
    # Encodes images into anchor tokens and predicts camera poses
    anchor_tokens, cameras = GeometryBackbone(context_images)
    N = len(anchor_tokens)
    
    # Step 2: Gaussian Allocation
    # Policy predicts discrete allocation k summing to B
    # In training, this uses GSPO with C rollouts.
    # In inference, it is a single forward pass of the policy network.
    allocation_k = GaussianAllocationPolicy(anchor_tokens, budget_B)
    
    # Validate allocation sum
    assert sum(allocation_k) == budget_B
    
    # Step 3: Token Spawning
    # Spawn k_n Gaussian tokens for each anchor n
    gaussian_tokens = []
    for n in range(N):
        count = allocation_k[n]
        # Spawn 'count' tokens at anchor n
        # The specific spawning mechanism (e.g., jittering, copying) 
        # is part of the decoder initialization.
        tokens_for_anchor = SpawnTokens(anchor_tokens[n], count)
        gaussian_tokens.extend(tokens_for_tokens)
        
    B = len(gaussian_tokens)
    
    # Step 4: Resource-Linear Decoding
    # Initialize Gaussian parameters from tokens
    gaussians = InitializeGaussians(gaussian_tokens)
    
    # Hierarchical Neighbor Search
    # Build structure to find K_gs nearest Gaussian neighbors
    # and K_anc nearest anchor neighbors
    neighbor_search_structure = BuildHierarchicalSearch(
        gaussians, 
        anchor_tokens, 
        K_gs=K_gs, 
        K_anc=K_anc
    )
    
    # Local Refinement via Cross-Attention
    refined_gaussians = []
    for i in range(B):
        # Find K_gs nearest Gaussian neighbors
        neighbor_indices = neighbor_search_structure.FindGaussianNeighbors(i, K_gs)
        neighbor_gaussians = [gaussians[j] for j in neighbor_indices]
        
        # Find K_anc nearest anchor neighbors (if needed for context)
        # Note: The core refinement is cross-attention over Gaussian neighbors
        anchor_neighbors = neighbor_search_structure.FindAnchorNeighbors(i, K_anc)
        
        # Refine Gaussian i using local cross-attention
        refined_g = LocalCrossAttention(
            gaussians[i], 
            neighbor_gaussians, 
            anchor_neighbors
        )
        refined_gaussians.append(refined_g)
        
    return refined_gaussians, cameras

def LocalCrossAttention(gaussian, neighbors, anchors):
    """
    Refines a single Gaussian using attention over its neighbors.
    """
    # Compute attention weights between gaussian and neighbors
    # This step is O(K_gs)
    attention_weights = ComputeAttention(gaussian, neighbors)
    
    # Aggregate information from neighbors
    aggregated_features = AggregateFeatures(attention_weights, neighbors)
    
    # Update Gaussian parameters (center, scale, rotation, opacity, color)
    # based on aggregated features and its own token features
    updated_gaussian = UpdateParameters(gaussian, aggregated_features)
    
    return updated_gaussian
```

**Edge Cases and Pitfalls:**
*   **Allocation Failure:** The allocation policy must strictly sum to $B$. If the policy outputs non-integer or negative values, they must be rounded/clamped and adjusted to satisfy the sum constraint [S1, unofficial].
*   **Neighbor Search Degeneracy:** If $B$ is very small, the hierarchical neighbor search may fail to find $K_{gs}$ distinct neighbors. The implementation must handle cases where fewer than $K_{gs}$ neighbors exist [S1, unofficial].
*   **Training Stability:** Removing the projection loss causes training to fail entirely, as it ties anchors to image regions [S1, unofficial]. Removing the Voronoi loss causes a significant PSNR drop (2.51 dB) because Gaussians leave their anchor's cell and the hierarchical search retrieves incorrect neighbors [S1, unofficial].

## Subtopics

### Gaussian Allocation Policy
A learned policy that distributes the Gaussian budget $B$ across anchors based on local scene significance (e.g., texture complexity). It differs from uniform allocation by concentrating capacity in high-frequency regions. Choose this when you need adaptive resource distribution. ### Resource-Linear Decoder
A decoder that refines Gaussians via local cross-attention with hierarchical neighbor search, ensuring $O(B \cdot K_{gs})$ complexity. Choose this when you need inference cost to scale linearly with $B$. ## Operating characteristics
*   **Time Complexity:** The decoding cost is $O(B \cdot K_{gs})$, scaling linearly with the Gaussian budget $B$, compared to global self-attention which costs $O(B^2)$ [S1, unofficial].
*   **Memory Complexity:** Peak memory scales linearly with $B$ [S1, unofficial].
*   **Measured Performance:**
    *   On ACID dataset ($B=8,192$, 8 views): PSNR 22.84 dB, SSIM 0.643, LPIPS 0.353 [S1, unofficial].
    *   On RE10K ($B=8,192$): Full-view PSNR 26.51 dB, compared to 23.42 dB for F4 Splat and 21.82 dB for EcoSplat [S1, unofficial].
    *   At $B=2,048$: RLSplat achieves higher PSNR than F4 Splat while using 9.6× less peak memory and running 4.1× faster [S1, unofficial].
*   **Scaling:** Inference latency and peak memory decrease linearly as $B$ is reduced [S1, unofficial].
*   **Strengths:**
    *   True resource-linearity: cost scales with output size.
    *   Adaptive allocation: concentrates Gaussians on high-frequency details (e.g., thin structures) while sparing smooth regions [S1, unofficial].
    *   No retraining required to change $B$ or $K_{gs}$ at inference [S1, unofficial].
*   **Limitations:**
    *   Requires reinforcement learning (GSPO) for training the allocation policy, which may be complex to implement [S1, unofficial].
    *   Performance depends on the quality of the hierarchical neighbor search [S1, unofficial].
*   **When to Use:** Applications requiring limited resource budgets, such as AR/VR, robotics, and digital content creation, where the number of Gaussians must be strictly controlled [S1, unofficial].
*   **When Not to Use:** When maximum possible quality is required regardless of resource cost, or when the scene has uniform complexity where uniform allocation might suffice [S1, unofficial].

## Background
RLSplat was proposed by Bae, Park, and Kim from KAIST in 2026 [S1, unofficial]. It addresses the limitations of prior budget-controllable FF3DGS methods like EcoSplat and F4 Splat, which predict dense sets of Gaussians and then prune them, resulting in constant inference costs [S1, unofficial]. RLSplat introduces a resource-linear framework where the allocation policy and decoder ensure that both representation size and inference cost scale linearly with the budget [S1, unofficial]. It is used in feed-forward 3D Gaussian Splatting for real-time applications [S1, unofficial].
