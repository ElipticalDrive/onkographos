# TexGS-VolVis Representation and Optimization

Also called: TexGS-VolVis

## Overview
TexGS-VolVis is a method for representing and editing volume visualization (VolVis) scenes using textured 2D Gaussian Splatting (2DGS) [S1]. It solves the problem of decoupling geometry from appearance in text-driven non-photorealistic style editing (NPSE), allowing for geometry-consistent stylization without the elliptical artifacts common in coupled representations [S1]. Unlike methods that freeze geometry to prevent distortion, TexGS-VolVis uses explicit 2D texture maps to store appearance, preserving geometric fidelity while enabling rich visual expressiveness [S1].

## How it works
**Inputs:** Multi-view images of a volumetric dataset and text prompts for style transfer or refinement [S1].
**Outputs:** A scene representation consisting of 2D Gaussian primitives with geometry, shading, and texture attributes, along with rendered stylized images [S1].

**Data Structures:**
The scene is represented by $N$ 2D Gaussian primitives [S1]. Each primitive stores attributes in 32-bit floating-point format [S1].
1.  **Geometry Attributes:**
    *   $\mu$: Center position (3 floats) [S1].
    *   $t_u, t_v$: Orientation vectors, represented as a quaternion (4 floats) [S1].
    *   $s_u, s_v$: Scale factors (2 floats) [S1].
    *   $o$: Opacity (1 float) [S1].
2.  **Shading Attributes:**
    *   $k_a$: Ambient coefficient (1 float) [S1].
    *   $k_d$: Diffuse coefficient (1 float) [S1].
    *   $k_s$: Specular coefficient (1 float) [S1].
    *   $\beta$: Shininess/exponent (1 float) [S1].
3.  **Texture Attribute:**
    *   Stored separately from individual splats [S1].
    *   It is a global texture map shared by the scene [S1].
    *   The total number of texels $T_{total}$ is fixed per basic scene [S1].

**Parameter Count:**
Given $N$ primitives, the total number of parameters for geometry and shading is calculated as [S1]:
$$ \text{# params} = 3N + 4N + N + N + N + N + N + N + N $$
Where:
*   $3N$ corresponds to $\mu$ [S1].
*   $4N$ corresponds to the quaternion for $\{t_u, t_v\}$ [S1].
*   The remaining $N$ terms correspond to $s_u, s_v, o, k_a, k_d, k_s, \beta$ (1 float each) [S1].

**Optimization Phases:**
The method proceeds in three sequential phases [S1]:
1.  **2DGS Initialization:** Initialize the geometry and basic appearance using 2DGS [S1]. This phase uses explicit ray-splat intersection for perspective-correct splatting and accurate geometry reconstruction [S1].
2.  **Shading Attributes Optimization:** Optimize $\{k_a, k_d, k_s, \beta\}$ [S1]. This improves reconstruction accuracy by modeling view-dependent color variations [S1].
3.  **Texture Attribute Optimization:** Optimize the global texture map [S1]. This phase introduces a sparsity regularization term that encourages minimal texture values, which may slightly reduce reconstruction accuracy compared to the shading-only phase [S1]. Spherical harmonic parameters and view-independent color $c_{ind}$ are used only in early phases and are not retrained in the final representation [S1].

**Scene Editing and Composition:**
*   **Text Prompt Refinement:** Users can iteratively apply new text prompts to an already stylized scene [S1]. The previous style pattern is partially preserved while being updated according to the latest prompt [S1].
*   **Multi-Scene Composition:** The framework accommodates multiple basic scenes (e.g., different transfer functions) in a single visualization [S1]. Each basic scene is edited independently and then seamlessly composed [S1]. This composition requires no additional optimization, incurring zero extra training costs [S1].
*   **Relighting:** Lighting direction is adjusted by modifying azimuthal and polar angles, achieving smooth and consistent relighting across the scene [S1].

**Pseudocode:**
```python
def texgs_volvis_optimize(multi_view_images, text_prompts, num_primitives_target):
    N = num_primitives_target
    # Phase 1: 2DGS Initialization
    mu = zeros((N, 3))  # Center positions
    quat_t = random_unit_quaternions(N)  # Orientation for {tu, tv}
    su = ones(N)  # Scale u
    sv = ones(N)  # Scale v
    o = ones(N)   # Opacity
    primitives = {'mu': mu, 'quat_t': quat_t, 'su': su, 'sv': sv, 'o': o}

    # Phase 2: Shading Attributes Optimization
    ka = zeros(N); kd = zeros(N); ks = zeros(N); beta = ones(N)
    shading = {'ka': ka, 'kd': kd, 'ks': ks, 'beta': beta}
    for _ in range(shading_iterations):
        rendered = project_and_rasterize(primitives, shading, multi_view_images)
        loss = mean_squared_error(rendered, multi_view_images)
        shading = gradient_descent_step(shading, loss)

    # Phase 3: Texture Attribute Optimization
    T_total = 10_000_000
    texture_map = zeros(T_total)
    for _ in range(texture_iterations):
        rendered = project_and_rasterize(primitives, shading, texture_map, multi_view_images)
        loss = mean_squared_error(rendered, multi_view_images) + sparsity_lambda * sum(texture_map)
        texture_map = gradient_descent_step(texture_map, loss)

    return primitives, shading, texture_map

def edit_scene(primitives, shading, texture_map, new_text_prompt):
    updated_texture = apply_ip2p_refinement(texture_map, new_text_prompt)
    return primitives, shading, updated_texture

def compose_scenes(scene_list):
    composed = concatenate_attributes(scene_list)
    return composed

def relight_scene(primitives, shading, texture_map, azimuth, polar):
    rendered = project_and_rasterize(primitives, shading, texture_map, light_azimuth=azimuth, light_polar=polar)
    return rendered
```

**Edge Cases and Pitfalls:**
*   **Low-Texture Styles:** Flat or low-texture styles cause overly smoothed results, obscuring internal details [S1].
*   **Complex Structures:** Fragmented or complex structures lack continuous surfaces, preventing coherent style application [S1].
*   **Prompt Misinterpretation:** Text-driven editing relies on the pretrained IP2P model, which can misinterpret prompts (e.g., associating 'leaf beetle' with green instead of red/yellow/black) [S1].
*   **Rugged Surfaces:** Rugged or highly detailed surfaces (e.g., wood) are harder to fit than smooth ones (e.g., five jets) because they produce complex lighting effects in multi-view images, complicating geometry reconstruction [S1].

## Operating characteristics
**Time and Memory Complexity:**
*   **Memory:** The texture attribute dominates memory usage [S1]. For a fixed $T_{total} = 1 \times 10^7$ texels, the texture consumes ~114.5 MB per basic scene, regardless of the number of primitives $N$ [S1]. Geometry and shading attributes scale linearly with $N$ [S1]. On the beetle dataset (47,767 primitives), geometry uses 1.8 MB, shading uses 0.7 MB, texture uses 114.5 MB, and the total is ~117 MB [S1]. Texture accounts for >95% of model size [S1].
*   **Time:** Fitting performance is fast [S1]. On the five jets dataset (56,836 primitives), fitting takes 0.8 minutes [S1].

**Measured Performance:**
*   **Five Jets Dataset:** PSNR is 36.83 dB, SSIM is 0.9889, CPU/GPU memory is 10.0/5.6 GB, and primitives count is 56,836 [S1].
*   **Other Datasets:** PSNR ranges from 24.58 dB (Ionization) to 36.83 dB (Five Jets), and SSIM ranges from 0.8565 to 0.9889 [S1].

**Strengths and Limitations:**
*   **Strengths:** Decoupling geometry and appearance eliminates elliptical artifacts in text-driven NPSE while preserving visual expressiveness [S1]. The method supports iterative text refinement and multi-scene composition with zero extra training cost [S1]. It uses 2DGS for accurate geometry reconstruction and perspective-correct splatting [S1].
*   **Limitations:** Texture memory usage is high and fixed per scene, making compression necessary for large-scale applications [S1]. The method struggles with rugged surfaces and low-texture styles [S1]. It relies on an external IP2P model for text interpretation, which can be unreliable [S1].

**When to Use:**
*   Use for text-driven non-photorealistic style editing of volume visualizations where geometry consistency is critical [S1].
*   Use when multiple basic scenes (e.g., different transfer functions) need to be composed [S1].
*   Do not use for scenes with highly fragmented structures or when low-texture styles are required, as results may be overly smoothed or incoherent [S1].

## Background
TexGS-VolVis was introduced in the paper "TexGS-VolVis: Expressive Scene Editing for Volume Visualization via Textured Gaussian Splatting" [S1]. It builds upon 2D Gaussian Splatting (2DGS), which uses explicit ray-splat intersection for perspective-correct splatting and natively supports 2D texture maps, making it superior for geometry-consistent editing compared to standard 3DGS [S1]. The method addresses limitations in previous text-driven NPSE methods that either froze geometry (reducing expressiveness) or coupled geometry and appearance (causing artifacts) [S1].
