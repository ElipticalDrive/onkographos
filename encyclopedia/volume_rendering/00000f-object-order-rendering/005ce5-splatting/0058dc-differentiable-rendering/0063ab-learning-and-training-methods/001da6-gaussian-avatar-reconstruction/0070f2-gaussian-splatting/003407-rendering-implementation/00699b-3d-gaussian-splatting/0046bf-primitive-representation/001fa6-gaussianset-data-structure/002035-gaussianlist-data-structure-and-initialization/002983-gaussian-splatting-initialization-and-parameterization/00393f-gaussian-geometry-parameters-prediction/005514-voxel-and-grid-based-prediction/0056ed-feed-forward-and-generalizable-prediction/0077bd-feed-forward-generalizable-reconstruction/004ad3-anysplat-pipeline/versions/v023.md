# AnySplat Pipeline

Also called: Feed-forward 3D Gaussian Splatting from Unconstrained Views

## Overview
AnySplat is a feed-forward, generalizable reconstruction method that predicts a set of 3D Gaussians directly from uncalibrated input images, eliminating the need for per-scene optimization or known camera poses [S1, unofficial]. It differs from sibling methods like [Splatt3R](16423-splatt3r.md) and [ZeroGS](16425-zerogs.md) by explicitly predicting camera poses and depth maps alongside Gaussian parameters within a unified transformer-based architecture, enabling robust reconstruction from unconstrained view sets [S1, unofficial].

## How it works
The pipeline maps input images to a 3D Gaussian representation $\mathcal{G}$ and camera parameters via a single forward pass of a neural network.

**Inputs and Outputs:**
*   **Input:** A batch of $K$ RGB images $I \in \mathbb{R}^{1 \times K \times 3 \times 448 \times 448}$ (batch, views, channels, height, width). Images are normalized to $[-1, 1]$ before encoding [S1, unofficial].
*   **Outputs:**
    *   A set of 3D Gaussians defined by mean $\mu$, scale $s$, rotation $r$, and color $c$.
    *   Predicted depth map $D$.
    *   Predicted camera poses $p$ (extrinsic $E$ and intrinsic $K$ matrices).

**Data Structures:**
The Gaussian parameters are predicted per-pixel in the input view space, forming a "pixel-wise" Gaussian field. These are then voxelized.
*   **Gaussian Parameters:** $\mu \in \mathbb{R}^3$, $s \in \mathbb{R}^3$, $r \in \mathbb{R}^4$ (quaternion), $c \in \mathbb{R}^3$ (RGB).
*   **Voxelized Gaussians:** The "pre-voxel" Gaussians are aggregated into a voxel grid structure for efficient rendering.

**Steps:**
1.  **Feature Encoding:** Input images are processed by a transformer-based geometry encoder to extract multi-scale features [S1, unofficial].
2.  **Parameter Prediction:** Three decoder heads ($F_G, F_D, F_C$) predict:
    *   $F_G$: Gaussian parameters ($\mu, \sigma, r, s, c$). Note: $\sigma$ in the source likely refers to scale parameters or covariance components derived from $s$ and $r$ [S1, unofficial].
    *   $F_D$: Depth map $D$.
    *   $F_C$: Camera poses $p$ (extrinsic and intrinsic matrices) [S1, unofficial].
3.  **Gaussian Construction:** Pixel-wise 3D Gaussians are constructed using the predicted $\mu, s, r, c$ [S1, unofficial].
4.  **Differentiable Voxelization:** The pixel-wise Gaussians are voxelized into "pre-voxel 3D Gaussians" using a Differentiable Voxelization module. This step aggregates overlapping Gaussians into a voxel grid [S1, unofficial].
5.  **Rendering:** Multi-view images and depth maps are rendered from the voxelized Gaussians using differentiable rasterization [S1, unofficial].
6.  **Loss Computation:**
    *   **RGB Loss:** Between rendered images and ground truth images.
    *   **Geometry Loss:** Between rendered depth maps, decoded depth $D$, and pseudo-geometry priors from a pretrained VGGT model. The predicted poses $p$ are used to align these geometry losses [S1, unofficial].
7.  **Inference:** The model outputs the final Gaussians and predicted poses [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Uncalibrated Inputs:** The method handles unknown camera poses, but accuracy depends on the quality of the predicted poses $p$ [S1, unofficial].
*   **Voxelization Artifacts:** The Differentiable Voxelization module may introduce artifacts if Gaussians are sparse or highly overlapping. The source does not specify voxel grid resolution [S1, unofficial].
*   **Pseudo-Geometry Dependence:** Geometry supervision relies on pretrained VGGT priors, which may fail on out-of-distribution scenes [S1, unofficial].

## Subtopics

### [SubSplat](13524-subsplat.md)
SubSplat is a method for high-resolution novel-view synthesis that resolves the trade-off between network computational cost and rendering fidelity in pixel-aligned 3D Gaussian Splatting. It solves the problem of insufficient Gaussian density and artifacts when using low-resolution backbone inputs by introducing a Sub-pixel Gaussian Reparameterizer (SPGR). Unlike prior methods limited by fixed grids or image-space upsamplers, SubSplat subdivides each grid-anchored primary Gaussian into multiple fine-grained sub-pixel primitives, restoring structural density directly from low-resolution features while maintaining stable network latency.

### [Deformable Radial Kernel (DRK)](13699-deformable-radial-kernel-drk.md)
Deformable Radial Kernel (DRK) Splatting is a 3D scene representation method that replaces the fixed radial symmetry of Gaussian primitives with a flexible planar kernel defined by multiple radial basis functions. It solves the overparameterization and geometric fidelity limitations of Gaussian Splatting by allowing adaptive stretching, rotation, and sharp boundary control, enabling high-fidelity rendering with significantly fewer primitives. Unlike standard 2D Gaussian Splatting, which relies on smooth, elliptical distributions, DRK supports straight edges and sharp corners through L1/L2 norm blending and piecewise edge sharpening.

## Operating characteristics
*   **Time Complexity:** Inference is $O(1)$ with respect to scene complexity, as it is a feed-forward pass. Training time depends on the dataset size and network depth.
*   **Memory Complexity:** Memory usage is dominated by the voxel grid size and the number of Gaussians. The source does not specify memory consumption metrics [S1, unofficial].
*   **Performance:** The method enables real-time novel-view synthesis after training. Performance on unseen scenes depends on the generalization capability of the transformer encoder and the quality of VGGT priors [S1, unofficial].
*   **Strengths:** Handles uncalibrated inputs; no per-scene optimization required; unified pose and geometry prediction.
*   **Limitations:** Relies on pseudo-geometry priors which may be inaccurate; voxelization may lose fine details; performance on highly dynamic or non-rigid scenes is not specified [S1, unofficial].

## Background
AnySplat was introduced by InternRobotics as a feed-forward approach to 3D Gaussian Splatting from unconstrained views [S1, unofficial]. It builds on the principles of generalizable reconstruction, leveraging transformer architectures for feature extraction and pose estimation. The method integrates differentiable voxelization to bridge pixel-wise predictions and efficient rendering [S1, unofficial].
