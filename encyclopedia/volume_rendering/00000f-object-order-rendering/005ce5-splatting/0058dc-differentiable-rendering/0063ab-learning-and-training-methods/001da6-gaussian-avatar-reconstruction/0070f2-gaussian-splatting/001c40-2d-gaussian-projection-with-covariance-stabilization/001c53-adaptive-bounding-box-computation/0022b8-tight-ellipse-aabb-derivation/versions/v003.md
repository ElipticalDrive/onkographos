# Tight Ellipse AABB Derivation

Also called: Ellipse AABB Computation, Tight AABB Ellipse Culling, Tight Elliptical Bounding Box, Tight bounding box for ellipse

## Overview
An algorithm to compute the axis-aligned tight bounding box (AABB) of a projected 2D Gaussian ellipse in constant time, used to determine the rectangular tile extent for rasterization [S1, S2]. It replaces the loose circular bounding box of standard 3D Gaussian Splatting (3DGS) with a tight fit around the ellipse defined by an opacity threshold, significantly reducing false-positive tile intersections [S1, S2]. Unlike [AccuTile](3037-accutile.md), which iterates to find exact intersections, this method provides a static geometric bound suitable for initial culling and spatial indexing [S1, S2].

## How it works
**Inputs and Outputs:**
*   **Input:** Two 2D basis vectors $\mathbf{a}, \mathbf{b} \in \mathbb{R}^2$ defining the orientation and scale of the projected 2D Gaussian ellipse.
*   **Output:** The minimum and maximum coordinates $(x_{min}, y_{min})$ and $(x_{max}, y_{max})$ of the axis-aligned bounding box enclosing the ellipse.

**Data Structures:**
*   $\mathbf{a} = [a_x, a_y]^T$
*   $\mathbf{b} = [b_x, b_y]^T$
*   Matrix $D \in \mathbb{R}^{2 \times 2}$
*   Matrix $C \in \mathbb{R}^{2 \times 2}$

**Steps:**
1.  **Construct Matrix D:** Compute the symmetric $2 \times 2$ matrix $D$ using the outer products of the basis vectors:
    $$ D \coloneqq \mathbf{a}\mathbf{a}^T + \mathbf{b}\mathbf{b}^T $$
    Explicitly:
    $$ D = \begin{bmatrix} a_x^2 + b_x^2 & a_x a_y + b_x b_y \\ a_x a_y + b_x b_y & a_y^2 + b_y^2 \end{bmatrix} $$

2.  **Compute Inverse Matrix C:** Calculate the inverse of $D$:
    $$ C \coloneqq D^{-1} $$
    Let $C = \begin{bmatrix} c_{00} & c_{01} \\ c_{10} & c_{11} \end{bmatrix}$. Since $D$ is symmetric, $C$ is also symmetric ($c_{01} = c_{10}$).

3.  **Define Implicit Equation:** The ellipse is defined by the implicit equation $f(x, y) = 0$ derived from $C$. While the explicit form is omitted in the source, it generally takes the form $\mathbf{x}^T C \mathbf{x} = 1$ (assuming unit threshold scaling) or scaled by the opacity threshold $\alpha_i(p) = \sigma_i g_i(p)$ [S1, S2].

4.  **Compute Vertical Extents:** Find the points on the ellipse where the gradient $\nabla f$ is horizontal (i.e., the tangent is vertical). This corresponds to the left and right edges of the AABB.
    *   The source notes that the extent along $x$ is calculated using the basis vectors, referencing a simplified formula that saves arithmetic instructions compared to Hanson et al. [HTL*25] [S2].
    *   Mathematically, for an ellipse $\mathbf{x}^T C \mathbf{x} = 1$, the vertical tangents occur where $\frac{\partial f}{\partial y} = 0$. This leads to $x = \pm \sqrt{\frac{c_{11}}{c_{00}c_{11} - c_{01}^2}}$ if normalized, or derived directly from the basis vectors. The source states the extent is derived from $\mathbf{a}$ and $\mathbf{b}$ [S2].

5.  **Compute Horizontal Extents:** Apply the same derivation swapping $x$ and $y$ (and indices 0 and 1) to find the top and bottom edges of the AABB [S2].

6.  **Combine Bounds:** The final AABB bounds are determined by the computed extents. In the context of rasterization, these coordinates are divided by tile size, rounded, and clipped to the image boundary to obtain the rectangular tile extent [S1].

**Pseudocode:**
```python
def compute_tight_ellipse_aabb(a_x, a_y, b_x, b_y):
    # Step 1: Construct D = aa^T + bb^T
    d00 = a_x * a_x + b_x * b_x
    d01 = a_x * a_y + b_x * b_y
    d11 = a_y * a_y + b_y * b_y
    
    # Step 2: Compute C = D^-1
    # Determinant of D
    det_D = d00 * d11 - d01 * d01
    
    # Inverse of 2x2 symmetric matrix
    # C = 1/det_D * [d11, -d01; -d01, d00]
    c00 = d11 / det_D
    c01 = -d01 / det_D
    c11 = d00 / det_D
    
    # Step 3 & 4: Compute x-extent (vertical edges)
    # The source references a simplified formula for the extent.
    # For an ellipse defined by C, the max x coordinate is sqrt(c11 / det_C_ellipse)
    # However, the source emphasizes using the basis vectors directly for a simplified formula.
    # Based on [S2], the extent is derived from a and b.
    # A standard derivation for tight AABB of ellipse spanned by a, b:
    # The bounding box limits are the max/min of the projection of the ellipse onto axes.
    # The ellipse is { u*a + v*b | u^2 + v^2 <= 1 } (assuming standard covariance decomposition).
    # Actually, the implicit form x^T C x = 1 implies the ellipse is the image of the unit circle under D^(1/2).
    # The tight AABB of an ellipse defined by C is given by:
    # x_max = sqrt( C_11 / (C_00*C_11 - C_01^2) ) ? No, that's for specific forms.
    
    # Let's use the explicit derivative method described in [S2]:
    # "Points (x, y)^T on the vertical edge ... where gradient is horizontal"
    # f(x,y) = c00*x^2 + 2*c01*x*y + c11*y^2 - 1 = 0
    # df/dy = 2*c01*x + 2*c11*y = 0 => y = -(c01/c11)*x
    # Substitute into ellipse eq:
    # c00*x^2 + 2*c01*x*(-c01/c11*x) + c11*(-c01/c11*x)^2 = 1
    # x^2 * (c00 - 2*c01^2/c11 + c01^2/c11) = 1
    # x^2 * (c00 - c01^2/c11) = 1
    # x^2 * ( (c00*c11 - c01^2) / c11 ) = 1
    # x^2 = c11 / (c00*c11 - c01^2)
    # Note: c00*c11 - c01^2 = det(C) = 1/det(D)
    # So x^2 = c11 * det(D)
    
    det_C = c00 * c11 - c01 * c01
    
    x_extent = (c11 / det_C) ** 0.5
    y_extent = (c00 / det_C) ** 0.5
    
    # Step 5: Combine bounds
    x_min = -x_extent
    x_max = x_extent
    y_min = -y_extent
    y_max = y_extent
    
    return (x_min, y_min, x_max, y_max)
```

**Parameters:**
*   Opacity threshold $\sigma_i$: Determines the exact pixel extent of the Gaussian as an ellipse [S1].

**Edge Cases and Pitfalls:**
*   **False Negatives:** Using an approximate tile-ellipse intersection test may produce occasional false-negatives. This is acceptable for editors operating on fully-trained models but would negatively influence convergence in gradient descent-based optimization [S2].
*   **Precision:** The method relies on constant-time arithmetic. Numerical stability of the matrix inversion $D^{-1}$ should be considered if $D$ is near-singular (degenerate ellipse) [G].

## Subtopics

### [AccuTile](3037-accutile.md)
Extends SnugBox by iterating over the shorter side of the SnugBox tile extent to compute exact Gaussian-to-tile intersections, reducing the number of tiles further than SnugBox.

### [Three-Sigma AABB Blended Radius](20577-three-sigma-aabb-blended-radius.md)
Computes a single scalar radius blending volume-equivalent and RMS radii with an aspect penalty, converting the derived ellipse basis vectors into a conservative AABB extent suitable for spatial indexing.

## Operating characteristics
*   **Time Complexity:** Constant time $O(1)$ per splat for the bounding box computation [S1].
*   **Memory Complexity:** Minimal additional memory; only requires storing the basis vectors and the resulting 4 scalar bounds [S1, S2].
*   **Performance:** Significantly improves performance by removing the majority of false-positives compared to 3DGS's bounding circle approach [S2]. The simplified formula saves arithmetic instructions compared to Hanson et al. [HTL*25] [S2].
*   **Strengths:** Tight fit reduces redundant rasterization; constant time computation; simple implementation [S1, S2].
*   **Limitations:** Approximate tests may cause false-negatives, which are detrimental to optimization convergence [S2].

## Background
The method originates from the SnugBox algorithm, introduced to address the inefficiency of 3D Gaussian Splatting's circular bounding boxes [S1]. It was concurrently developed with similar work by Hanson et al. [HTL*25] [S2]. The derivation is detailed in Appendix A of the Splatshop paper [S2].
