# GaussianCube

Also called: Differentiable 3D Gaussian Splatting, GaussianCube representation

## Overview
GaussianCube is a scene representation method that utilizes an unstructured, explicit set of 3D Gaussians to achieve real-time radiance field rendering [S1, unofficial]. It solves the problem of high-quality novel-view synthesis by combining the expressiveness of continuous volumetric radiance fields with the computational efficiency of discrete point-based rasterization [S1, unofficial]. Unlike NeRF methods that rely on costly volumetric ray-marching and stochastic sampling, GaussianCube uses anisotropic splatting with depth sorting to respect visibility order, enabling fast, differentiable rendering and training [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A set of images of a static scene and corresponding camera poses calibrated via Structure-from-Motion (SfM), which provides a sparse point cloud [S1, unofficial].
*   **Output:** A radiance field representation consisting of a set of 3D Gaussians, each defined by position, covariance, opacity, and spherical harmonics (SH) coefficients, optimized to minimize rendering error [S1, unofficial].

**Data Structures**
Each 3D Gaussian $i$ in the set is defined by the following parameters:
1.  **Position:** Mean vector $\mu_i \in \mathbb{R}^3$ [S1, unofficial].
2.  **Covariance:** A full 3D covariance matrix $\Sigma_i \in \mathbb{R}^{3 \times 3}$, parameterized for optimization as:
    *   A scaling vector $s_i \in \mathbb{R}^3$ (stored as unconstrained values, transformed via exponential activation) [S1, unofficial].
    *   A rotation quaternion $q_i \in \mathbb{R}^4$ (normalized to unit length) [S1, unofficial].
    *   The matrix is reconstructed as $\Sigma_i = R S S^T R^T$, where $R$ is the rotation matrix derived from $q_i$ and $S$ is the diagonal scaling matrix derived from $s_i$ [S1, unofficial].
3.  **Opacity:** A scalar $\alpha_i \in (0, 1)$, constrained via sigmoid activation [S1, unofficial].
4.  **Color:** Spherical Harmonics (SH) coefficients representing directional color [S1, unofficial].

**Algorithm Steps**
1.  **Initialization:** Initialize the set of 3D Gaussians using the sparse point cloud produced by SfM [S1, unofficial]. The initial covariance is estimated as an isotropic Gaussian with axes equal to the mean distance to the three closest points [S1, unofficial].
2.  **Interleaved Optimization:** Perform alternating steps of parameter optimization and adaptive density control [S1, unofficial].
    *   **Parameter Optimization:** Update $\mu_i, s_i, q_i, \alpha_i$, and SH coefficients using Stochastic Gradient Descent (SGD) with custom CUDA kernels [S1, unofficial]. The loss function is $\mathcal{L} = (1 - \lambda)\mathcal{L}_1 + \lambda\mathcal{L}_{\text{D-SSIM}}$, with $\lambda = 0.2$ [S1, unofficial]. An exponential decay schedule is applied to positions [S1, unofficial].
    *   **Density Control:** Add new Gaussians in regions of high gradient or low opacity, and remove or clone Gaussians to maintain a compact representation (typically 1-5 million Gaussians) [S1, unofficial].
3.  **Rendering (Forward Pass):**
    *   Project each 3D Gaussian to 2D camera space. The 3D covariance $\Sigma$ is transformed to camera coordinates using the viewing transformation $W$ and the Jacobian $J$ of the affine approximation of the projective transformation: $\Sigma' = J W \Sigma W^T J^T$ [S1, unofficial].
    *   The 2D covariance is obtained by skipping the third row and column of $\Sigma'$, resulting in a $2 \times 2$ matrix [S1, unofficial].
    *   Sort Gaussians by depth within tiles (inspired by tile-based rasterization) to respect visibility order [S1, unofficial].
    *   Rasterize by alpha-blending the anisotropic splats. The color $C$ of a pixel is computed as:
        $$ C = \sum_{i=1}^N T_i \alpha_i \mathbf{c}_i $$
        where $\mathbf{c}_i$ is the color of the $i$-th Gaussian, $\alpha_i = 1 - \exp(-\sigma_i \delta_i)$ is the opacity contribution, and $T_i = \prod_{j=1}^{i-1} (1 - \alpha_j)$ is the accumulated transmittance [S1, unofficial].
4.  **Backward Pass:** Compute gradients by tracking the accumulated transmittance values during the forward pass, allowing gradients to flow to all splats contributing to the pixel color [S1, unofficial].

def project_covariance(Sigma_3d, W):
    """
    Projects 3D covariance to 2D camera space.
    Sigma_2d = J @ W @ Sigma_3d @ W.T @ J.T, then drop 3rd row/col.
    """
    # W is 4x4 viewing transformation
    # J is 3x4 Jacobian of affine approximation of projective transform
    # For a standard pinhole camera, J can be derived from the projection matrix
    # This is a placeholder for the specific Jacobian calculation
    J = compute_jacobian(W) 
    
    Sigma_prime = J @ W @ Sigma_3d @ W.T @ J.T
    
    # Skip third row and column to get 2x2 covariance
    Sigma_2d = Sigma_prime[:2, :2]
    return Sigma_2d

**Parameters**
*   **Number of Gaussians:** 1-5 million for typical scenes [S1, unofficial].
*   **Loss Weight $\lambda$:** 0.2 for the D-SSIM term [S1, unofficial].
*   **Activation Functions:** Sigmoid for opacity $\alpha$, Exponential for scale $s$ [S1, unofficial].

**Pitfalls**
*   **Covariance Validity:** Directly optimizing the covariance matrix $\Sigma$ is invalid because gradient descent cannot easily constrain it to remain positive semi-definite, leading to invalid matrices [S1, unofficial]. This is mitigated by parameterizing $\Sigma$ via scale and rotation [S1, unofficial].
*   **Empty Space:** Unlike continuous representations, explicit Gaussians do not implicitly represent empty space, requiring careful density control to avoid unnecessary computation [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Rendering is $O(N)$ where $N$ is the number of Gaussians, but optimized via tile-based sorting and culling. Training time is competitive with NeRF methods but allows real-time rendering ($\ge 30$ fps) at 1080p [S1, unofficial].
*   **Memory Complexity:** Memory usage is proportional to the number of Gaussians (1-5 million) and their SH coefficients. It is generally lower than dense voxel-based NeRFs for high-resolution scenes [S1, unofficial].
*   **Strengths:** Real-time rendering, high visual quality, explicit representation allows easy manipulation (add/remove/move Gaussians), no need for MVS data (only SfM points) [S1, unofficial].
*   **Limitations:** Unstructured representation may require more memory than highly compressed voxel grids for very simple scenes; anisotropic splatting can be complex to implement efficiently [S1, unofficial].
*   **When to Use:** When real-time novel-view synthesis is required, and input data is limited to SfM points.
*   **When Not to Use:** When a compact, implicit representation is preferred, or when MVS data is available and higher geometric fidelity is needed without the overhead of Gaussian optimization.

## Background
GaussianCube, often referred to in the context of 3D Gaussian Splatting, was introduced by Kerbl, Kopanas, et al. [S1, unofficial]. It builds on the principles of point-based rendering and radiance fields, aiming to combine the best of both worlds: the flexibility of discrete points and the volumetric properties of continuous fields [S1, unofficial]. The method was developed to address the computational costs of volumetric ray-marching in NeRFs and the limitations of order-independent rendering in previous point-based methods like Pulsar [S1, unofficial]. It has since been used as a basis for generative models, such as GaussianCube, which trains a 3D diffusion model based on a GaussianCube representation converted from Gaussians via optimal transport [S2, unofficial].
