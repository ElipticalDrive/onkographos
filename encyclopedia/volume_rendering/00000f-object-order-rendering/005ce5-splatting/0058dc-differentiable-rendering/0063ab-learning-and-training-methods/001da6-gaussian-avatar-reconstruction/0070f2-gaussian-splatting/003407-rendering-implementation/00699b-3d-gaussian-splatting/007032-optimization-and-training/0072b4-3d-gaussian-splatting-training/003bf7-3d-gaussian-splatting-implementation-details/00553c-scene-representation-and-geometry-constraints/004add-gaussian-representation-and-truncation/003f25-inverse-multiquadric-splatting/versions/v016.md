# Inverse Multiquadric Splatting

Also called: 3DIQS, Inverse Multiquadric

## Overview
Inverse Multiquadric Splatting is a rendering technique that replaces the standard Gaussian density function with an inverse multiquadric radial basis function to define the splat's alpha contribution. It solves the problem of inaccurate opacity estimation in standard 3D Gaussian Splatting by providing a different decay profile for the splat's falloff. It differs from its siblings by using a specific algebraic decay form rather than the exponential decay of Gaussians or the cosine/sinc variants found in other decaying anisotropic RBF methods.

## How it works
**Inputs and Outputs:**
*   **Input:** A set of 3D Gaussians $\{G_i\}$, each defined by mean $\boldsymbol{\mu}_i$, covariance $\boldsymbol{\Sigma}_i$, opacity $\alpha_i$, and color $\mathbf{c}_i$. The rasterizer receives the projected 2D conic matrix $\mathbf{C}'$ (inverse of the 2D covariance) and the 2D mean $\boldsymbol{\mu}'$.
*   **Output:** The alpha value $\alpha$ for each pixel covered by the splat, and gradients $\frac{\partial L}{\partial \boldsymbol{\mu}'}$, $\frac{\partial L}{\partial \mathbf{C}'}$ for backpropagation.

**Data Structures:**
The method modifies the standard CUDA rasterizer kernel. Key variables include:
*   `con_o`: A struct or vector containing the conic matrix elements. Typically, `con_o.x` corresponds to $C'_{xx}$, `con_o.y` to $C'_{xy}$, `con_o.z` to $C'_{yy}$, and `con_o.w` to the pre-computed opacity term (often derived from the original 3D opacity and Jacobian determinant).
*   `d`: A 2D vector $(d.x, d.y)$ representing the offset from the splat center to the pixel center ($\mathbf{x} - \boldsymbol{\mu}'$).
*   `correctionFactor`: A scalar multiplier applied to the covariance matrices.

**Parameters:**
*   `correctionFactor`: A scalar value of $1.38$ [S1]. This factor is applied to the 3D covariance matrix $\boldsymbol{\Sigma}$ and the 2D covariance matrix $\boldsymbol{\Sigma}'_{2 \times 2}$ during the forward and backward passes to correct for the different normalization of the inverse multiquadric function compared to the Gaussian [S1].

**Formulas:**
The 3D inverse multiquadric function is defined as [S1]:
$$ f(d_M) = \frac{1}{\frac{1}{\xi} (d_M)^2 + 1}, \quad d_M \geq 0 $$
where $\xi$ is a parameter related to the scale. In the 2D rasterization step, the weight $w$ is computed as [S1]:
$$ w = \frac{1}{\left[ \frac{1}{\xi} (\mathbf{x} - \boldsymbol{\mu}')^T (\boldsymbol{\Sigma}'_{2 \times 2})^{-1} (\mathbf{x} - \boldsymbol{\mu}') + 1 \right]} $$
In the implementation, the term $(\mathbf{x} - \boldsymbol{\mu}')^T (\boldsymbol{\Sigma}'_{2 \times 2})^{-1} (\mathbf{x} - \boldsymbol{\mu}')$ is computed as `ellipse`. The final alpha is calculated as [S1]:
$$ \alpha = \min(0.99, w \cdot \text{con\_o.w}) $$
where `con_o.w` represents the base opacity contribution. Note that some source snippets refer to a "Cosine" term, but the explicit code for Inverse Multiquadric (Listing 7) uses `con_o.w * (1.f / (ellipse + 1.f))` [S1].

**Numbered Steps:**
1.  **Covariance Correction:** Multiply the 3D covariance matrix $\boldsymbol{\Sigma}$ and the projected 2D covariance matrix $\boldsymbol{\Sigma}'_{2 \times 2}$ by `correctionFactor` ($1.38$) [S1].
2.  **Ellipse Calculation:** Compute the quadratic form `ellipse` for the pixel offset `d` using the 2D conic matrix elements `con_o.x`, `con_o.y`, `con_o.z` [S1]:
    $$ \text{ellipse} = \text{con\_o.x} \cdot d.x^2 + \text{con\_o.z} \cdot d.y^2 + 2 \cdot \text{con\_o.y} \cdot d.x \cdot d.y $$
3.  **Boundary Check:** If `ellipse <= 0` or `ellipse >= 9`, skip the splat for this pixel (continue) [S1]. The upper bound of 9 limits the effective support of the splat.
4.  **Weight Calculation:** Compute the inverse multiquadric weight $G$ (equivalent to $w$ in the formula above, assuming $\xi=1$ in the normalized conic representation) [S1]:
    $$ G = \frac{1}{\text{ellipse} + 1} $$
5.  **Alpha Computation:** Calculate the final alpha [S1]:
    $$ \alpha = \min(0.99, \text{con\_o.w} \cdot G) $$

**Pseudocode:**
```python
def inverse_multiquadric_splat(con_o, d, correction_factor=1.38):
    """
    con_o: dict or object with attributes x, y, z, w representing the 2D conic matrix and base opacity.
           con_o.x = C_xx, con_o.y = C_xy, con_o.z = C_yy, con_o.w = base_opacity
    d: dict or object with attributes x, y representing the pixel offset (x - mu_x, y - mu_y).
    """
    # 1. Ellipse calculation (quadratic form)
    ellipse = con_o.x * d.x * d.x + con_o.z * d.y * d.y + 2.0 * con_o.y * d.x * d.y
    
    # 2. Boundary checks
    if ellipse <= 0.0 or ellipse >= 9.0:
        return None, None, None  # Skip pixel
    
    # 3. Compute weight G (inverse quadric)
    G = 1.0 / (ellipse + 1.0)
    
    # 4. Compute alpha
    alpha = min(0.99, con_o.w * G)
    
    return alpha, ellipse, G

def inverse_multiquadric_backward(alpha, con_o, d, ellipse, G, dL_dalpha):
    """
    Computes gradients w.r.t. mean and conic matrix.
    dL_dalpha: gradient of loss w.r.t. alpha.
    """
    # Gradient w.r.t. G
    dL_dG = con_o.w * dL_dalpha
    
    # Gradient w.r.t. ellipse
    # dG/d(ellipse) = -1 / (ellipse + 1)^2
    # dL_d(ellipse) = dL_dG * dG/d(ellipse)
    dL_dellipse = dL_dG * (-1.0 / ((ellipse + 1.0) ** 2))
    
    # Gradients w.r.t. conic matrix elements (x, y, z)
    # ellipse = C_xx * dx^2 + C_yy * dy^2 + 2 * C_xy * dx * dy
    # d(ellipse)/d(C_xx) = dx^2
    # d(ellipse)/d(C_yy) = dy^2
    # d(ellipse)/d(C_xy) = 2 * dx * dy
    
    dL_dC_xx = dL_dellipse * (d.x * d.x)
    dL_dC_yy = dL_dellipse * (d.y * d.y)
    dL_dC_xy = dL_dellipse * (2.0 * d.x * d.y)
    
    # Note: The source code applies correctionFactor to the gradients of the covariance/conic matrix.
    # The provided source snippet for backward pass (Listing 7/8 context) shows:
    # dL_da = correctionFactor * ...
    # We assume the gradients computed above need to be scaled by correctionFactor if they are 
    # gradients w.r.t the original covariance parameters before correction.
    # However, the snippet specifically updates dL_dconic2D.
    
    # Applying correction factor to gradients w.r.t conic matrix entries
    # as per source: dL_da = correctionFactor * ...
    dL_dC_xx *= correction_factor
    dL_dC_yy *= correction_factor
    dL_dC_xy *= correction_factor
    
    # Gradients w.r.t. mean (d.x, d.y)
    # d(ellipse)/d(dx) = 2 * C_xx * dx + 2 * C_xy * dy
    # d(ellipse)/d(dy) = 2 * C_yy * dy + 2 * C_xy * dx
    dL_ddx = dL_dellipse * (2.0 * con_o.x * d.x + 2.0 * con_o.y * d.y)
    dL_ddy = dL_dellipse * (2.0 * con_o.z * d.y + 2.0 * con_o.y * d.x)
    
    return dL_dC_xx, dL_dC_xy, dL_dC_yy, dL_ddx, dL_ddy
```
*Note: The source code snippet for backward propagation (Listing 7/8 in [S1]) uses specific variable names like `dL_dG`, `ellipsepow`, `dG_ddelx`. The pseudocode above derives the standard chain rule equivalents. The source code explicitly calculates `dG_ddelx` as `ellipsepow * (d.x * con_o.x + d.y * con_o.y)` where `ellipsepow` is `-2 * dL_dG / (ellipse + 1)^2`. This matches the derivation `dL_ddx = dL_dG * (-2/(ellipse+1)^2) * (C_xx*dx + C_xy*dy)`.*

## Operating characteristics
*   **Time Complexity:** Same as standard Gaussian splatting, $O(N \cdot K)$ where $N$ is the number of Gaussians and $K$ is the number of pixels covered, as it replaces the exponential evaluation with a simple rational function evaluation.
*   **Memory Complexity:** No additional memory overhead compared to standard 3DGS, as it uses the same data structures.
*   **Strengths:** Provides a different decay profile that can better fit certain types of geometry or texture details compared to the Gaussian RBF. The correction factor helps align the energy distribution.
*   **Limitations:** The algebraic decay ($1/r^2$) is slower than the exponential decay of Gaussians, potentially requiring more Gaussians to achieve the same sharpness or leading to longer tails if not truncated. The hard cutoff at `ellipse >= 9` is an implementation detail that limits the support.

## Background
Inverse Multiquadric Splatting was introduced in the context of generalizing splatting with decaying anisotropic radial basis functions. It is presented in the paper "DARB-Splatting: Generalizing Splatting with Decaying Anisotropic Radial Basis Functions" [S1]. The method is part of a family of techniques that explore alternative RBFs for 3D Gaussian Splatting rendering.
