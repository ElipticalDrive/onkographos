# FineSplat

Also called: Detailed Splats, Fine Patches, Local Groups

## Overview
FineSplat is a feed-forward 3D Gaussian Splatting framework that predicts a set of 3D Gaussian primitives from $N$ context views (with or without known poses) using a two-stage dual-grouping strategy [S1, unofficial]. It balances local detail preservation with global multi-view reasoning by employing high-resolution 4x4 patch tokens and a dual-grouping mechanism that combines view-wise token grouping in 2D with 3D spatial grouping [S1, unofficial]. This approach preserves fine-grained visual information while avoiding the prohibitive computational cost of global multi-view attention [S1, unofficial].

## How it works
FineSplat operates in two stages: Stage 1 performs view-wise token grouping to encode fine-grained features, and Stage 2 performs 3D spatial token grouping to refine the Gaussian prediction using rendering errors [S1, unofficial].

### Inputs and Outputs
*   **Inputs:** $N$ context images $\{I_n\}_{n=1}^N$ with known or unknown camera poses.
*   **Outputs:** A set of $K_{total}$ 3D Gaussian primitives $\mathcal{G} = \{\mu_k, \Sigma_k, c_k, \alpha_k\}_{k=1}^{K_{total}}$, where $K_{total} = M \times K$ and $M$ is the number of tokens.

### Data Structures
*   **Tokens:** $z \in \mathbb{R}^{M \times d}$, where $M = N \cdot \frac{H}{p} \cdot \frac{W}{p}$ is the total number of tokens, $H, W$ are image dimensions, $p$ is the patch size, and $d$ is the token dimension.
*   **Gaussians:** Each token predicts $K$ Gaussians. For a 4x4 patch, $K=4$, with each Gaussian assigned to a non-overlapping 2x2 sub-patch.
*   **Error Feature Maps:** $F_n^{err} \in \mathbb{R}^{\frac{H}{p} \times \frac{W}{p} \times d_e}$, computed per view $n$.

### Parameters
*   **Patch size $p$:** 4 pixels (4x4 patches) [S1, unofficial].
*   **Sub-patch stride $s$:** 2 pixels (2x2 sub-patches) [S1, unofficial].
*   **Gaussians per token $K$:** 4 [S1, unofficial].
*   **Stage 2 steps $T$:** 4 [S1, unofficial].
*   **Attention group size $S$:** Number of consecutive points along the space-filling curve for serialized attention [S1, unofficial].
*   **Context views $N$:** Sampled from $\{6, 12, 24, 32\}$ during training; evaluated on $\{6, 12, 24\}$ (DL3DV), $\{6\}$ (RE10K), and $\{32, 64, 128\}$ (Mip-NeRF 360) [S1, unofficial].

### Algorithm

#### Scene Normalization
To handle scale ambiguity in feed-forward reconstruction, scene scale is normalized using context camera poses [S1, unofficial]:
1.  Express all context camera poses in the mean context camera frame.
2.  Rescale translations so that all context camera centers lie within $[-1, 1]^3$ [S1, unofficial].
3.  Apply the same transformation to target poses [S1, unofficial].

#### Stage 1: View-Wise Token Grouping
1.  **Feature Extraction:** Extract multi-scale features $F^l$ for $l \in \{1, 2, 3\}$ (finest to coarsest) from the input images using a backbone network [S1, unofficial].
2.  **Token Initialization:** Fuse features into $M$ fine-grained tokens $z^{(0)}$ using Equation (1) [S1, unofficial]:
    $$ z^{(0)} = \text{fuse}\left(\text{up}\left(\text{fuse}\left(\text{up}(F^3) + F^2\right)\right)\right) + F^1 $$
    where $\text{up}(\cdot)$ is bilinear upsampling and $\text{fuse}(\cdot)$ is a convolutional fusion block [S1, unofficial].
3.  **View-Wise Attention:** Encode tokens using attention with restricted scope. Group-wise attention is applied over small view groups to keep multi-view reasoning affordable [S1, unofficial].

#### Stage 2: 3D Spatial Token Grouping (Iterative Refinement)
For $t = 1$ to $T$ (default $T=4$):

1.  **Gaussian Prediction:** Decode tokens $z^{(t-1)}$ into an initial set of Gaussians using a lightweight linear Gaussian head $\mathcal{D}$ [S1, unofficial].
    *   **Patch-Aligned Sub-Pixel Reconstruction:** For each token, predict 4 Gaussians. Each Gaussian is assigned to a 2x2 sub-patch.
    *   **Offset Prediction:** Learn a 2D image-space offset $\Delta = (\Delta_x, \Delta_y)$ for each Gaussian.
    *   **Bounding Offsets:** Compute bounded shifts $\delta_x, \delta_y$ to ensure Gaussians remain within their 2x2 sub-patch [S1, unofficial]:
        $$ \delta_x = 2s \tanh(\Delta_x), \quad \delta_y = 2s \tanh(\Delta_y) $$
        where $s=2$ is the sub-patch stride. This ensures $\delta_x, \delta_y \in [-s/2, s/2]$ [S1, unofficial].
    *   **Ray Unprojection:** For a sub-patch with center $(u_c, v_c)$, compute displaced coordinate $(u, v) = (u_c, v_c) + (\delta_x, \delta_y)$. Unproject using predicted camera intrinsics to get a direction vector. Transform and normalize this direction using the camera-to-world rotation, using the camera translation as the ray origin [S1, unofficial].

2.  **Rendering:** Render the predicted Gaussians back into all $N$ context views to obtain rendered images $\{\hat{I}_n\}_{n=1}^N$ [S1, unofficial].

3.  **Error Feature Computation:** For each view $n$, compute error features $F_n^{err}$ [S1, unofficial]:
    *   **Pixel Error:** $E_n = \hat{I}_n - I_n$ [S1, unofficial].
    *   **Feature Difference:** $\Delta\phi_n = \phi(\hat{I}_n) - \phi(I_n)$, where $\phi(\cdot)$ is a pretrained ResNet-18 encoder [S1, unofficial].
    *   **Concatenation:** Combine with finest-scale features $F_n^1$ from Stage 1 via linear embeddings $E_{err}$ and $E_{feat}$ [S1, unofficial]:
        $$ F_n^{err} = [E_{err}(E_n, \Delta\phi_n); E_{feat}(F_n^1)] \in \mathbb{R}^{\frac{H}{p} \times \frac{W}{p} \times d_e} $$
        where $[\cdot; \cdot]$ denotes concatenation [S1, unofficial].

4.  **Error Aggregation:** For each token, gather two error signals [S1, unofficial]:
    *   **Self Error ($e_{self}$):** Error feature from the patch where the token was predicted.
    *   **Aggregated Error ($e_{agg}$):** Average of error features over all context views in which the token is visible (including views outside the Stage 1 view group) [S1, unofficial].

5.  **3D Spatial Grouping:**
    *   Lift tokens to 3D space using their predicted Gaussian centers.
    *   Order tokens along a space-filling curve.
    *   Partition tokens into groups of $S$ consecutive points.
    *   Apply serialized self-attention within each group to exchange error signals with 3D neighbors [S1, unofficial].
    *   Update tokens: $\Delta z_j^{(t)} = \text{Linear}(\text{SerialAttn}(h_j^{(t)}))$, $z_j^{(t)} = z_j^{(t-1)} + \Delta z_j^{(t)}$ [S1, unofficial].
    *   Use four attention blocks in Stage 2, each using a different space-filling curve, so each token meets a different set of neighbors [S1, unofficial].

6.  **Repeat:** Use updated tokens $z^{(t)}$ for the next iteration.

### Edge Cases and Pitfalls
*   **Blind Spots in View Grouping:** Fixed view grouping in Stage 1 prevents fine-grained tokens in different groups from interacting. This is mitigated by Stage 2's 3D spatial grouping, which connects tokens across view groups once lifted to 3D [S1, unofficial].
*   **Scale Ambiguity:** Feed-forward reconstruction suffers from scale ambiguity. This is handled by normalizing the scene scale using context camera poses, ensuring all camera centers lie within $[-1, 1]^3$ [S1, unofficial].
*   **Precision:** The bounding of offsets $\delta_x, \delta_y$ using $\tanh$ ensures Gaussians stay within their 2x2 sub-patch, preventing invalid placements [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** FineSplat is efficient due to its dual-grouping strategy. Stage 1 uses local view-wise attention, and Stage 2 uses serialized 3D spatial attention, avoiding global multi-view attention costs [S1, unofficial]. It is faster than YoNoSplat and ZipSplat for 6 and 12 input views, and still faster than ZipSplat with 24 views [S1, unofficial].
*   **Memory Complexity:** Uses a compact Gaussian representation (62K Gaussians for DL3DV with 6 views) [S1, unofficial].
*   **Performance:**
    *   **DL3DV (6 views):** 27.325 PSNR, 0.871 SSIM, 0.115 LPIPS with 62K Gaussians [S1, unofficial].
    *   **RE10K (6 views):** 27.394 PSNR, 0.886 SSIM, 0.116 LPIPS with 75K Gaussians [S1, unofficial].
    *   **Mip-NeRF 360 (128 views):** 23.463 PSNR, 0.706 SSIM, 0.214 LPIPS with 1.6M Gaussians [S1, unofficial].
*   **Strengths:** High quality with small primitive budget; efficient reconstruction time; strong generalization to unseen datasets (zero-shot) [S1, unofficial].
*   **Limitations:** Quality may degrade if Stage 1 alone is used for large scenes with many views; requires 4 steps of Stage 2 for optimal performance [S1, unofficial].
*   **When to Use:** Novel view synthesis where high fidelity and efficiency are required, especially with limited context views [S1, unofficial].
*   **When Not to Use:** When depth supervision is available and preferred, or when global attention is feasible and necessary for very large scenes with many views [S1, unofficial].

## Background
FineSplat was introduced in 2026 by authors associated with the arXiv preprint 2610.25011 [S1, unofficial]. It builds on the principles of feed-forward 3D Gaussian Splatting, addressing the limitations of coarser patch-based methods (like YoNoSplat and ZipSplat) by using finer 4x4 patches and a dual-grouping strategy [S1, unofficial]. The method is trained on the DL3DV dataset and evaluated on DL3DV, RealEstate10K, and Mip-NeRF 360 [S1, unofficial].
