# Rendering-aware QP Offset Modelling

Also called: Density-based QP scaling, Inter-Sequence QP Modelling, Intra-Sequence QP Modelling

## Overview
Rendering-aware QP Offset Modelling is a method for approximating optimal Quantization Parameter (QP) distributions in Rate-Distortion Optimized (RDO) RAHT coding for 3D Gaussian Splatting (3DGS) [S1, unofficial]. It solves the problem of generalizing QP allocation across diverse scenes and resolutions without requiring per-sequence iterative fitting [S1, unofficial]. Unlike the analytical solution in [Optimal Layer-wise QP Offset Derivation](16342-optimal-layer-wise-qp-offset-derivation.md) which requires fitting multiple sequence-specific parameters ($k_i, C_i, \nu_i, Z_i, \mu$), this method uses a generalized heuristic based on spatial density and resolution to account for error accumulation during splatting projection [S1, unofficial].

## How it works
The method models the relationship between RAHT layer indices and optimal QP offsets by linking the hierarchical structure of the 3D data to its visual impact, specifically addressing constructive error accumulation in overlapping primitives [S1, unofficial].

**Inputs and Outputs:**
*   **Inputs:**
    *   $N_{primitives}$: Total number of Gaussian primitives in the scene.
    *   $\{d_j\}_{j=1}^{N_{primitives}}$: Euclidean distance from the $j$-th primitive to its nearest neighbour.
    *   $W, H$: Training resolution width and height.
    *   $\bar{N}_i$: Average number of Gaussian primitives contained by each node at RAHT layer $i$.
*   **Outputs:**
    *   $\Delta q_{p_i}$: The QP offset for layer $i$.
    *   $\beta, \gamma$: Sequence-dependent fitting parameters derived analytically.

**Data Structures:**
No complex data structures are required beyond standard scalar values for density, resolution, and layer statistics. The core calculation relies on scalar arithmetic.

**Steps:**

1.  **Calculate Spatial Density ($\rho$):**
    Compute the average inverse square nearest-neighbour distance to quantify the aggregation density of primitives [S1, unofficial]:
    $$
    \rho = \frac{1}{N_{primitives}} \sum_{j=1}^{N_{primitives}} \frac{1}{d_j^2}
    $$

2.  **Calculate Global Scaling Factor ($s$):**
    Modulate the QP offset based on scene density and rendering resolution using regression-derived coefficients [S1, unofficial]:
    $$
    s = 10 + 0.029 \cdot \rho \cdot (W \cdot H)^{0.2}
    $$

3.  **Derive Sequence-Dependent Parameters ($\beta, \gamma$):**
    Analytically derive the global offset and scaling parameters from $s$ [S1, unofficial]:
    $$
    \gamma = s^3
    $$
    $$
    \beta = 0.75 \cdot s
    $$

4.  **Compute Layer-wise QP Offsets ($\Delta q_{p_i}$):**
    For each RAHT layer $i$, calculate the QP offset using the average primitive count $\bar{N}_i$ as a proxy for hierarchical impact [S1, unofficial]:
    $$
    (\Delta q_{p_i} + \beta)^3 = \gamma \cdot \bar{N}_i
    $$
    Solving for $\Delta q_{p_i}$:
    $$
    \Delta q_{p_i} = \sqrt[3]{\gamma \cdot \bar{N}_i} - \beta
    $$

**Parameters:**
*   $\beta$: Sequence-dependent fitting parameter accounting for the global offset of the QP distribution [S1, unofficial].
*   $\gamma$: Sequence-dependent fitting parameter accounting for the scaling of the QP distribution [S1, unofficial].
*   $N_{primitives}$: Total number of Gaussians in the scene [S1, unofficial].
*   $d_j$: Euclidean distance from the $j$-th primitive to its nearest neighbour [S1, unofficial].
*   $W$: Training resolution width [S1, unofficial].
*   $H$: Training resolution height [S1, unofficial].

**Pseudocode:**
```python
def compute_qp_offsets(N_primitives, distances, W, H, N_bar_per_layer):
    """
    Compute QP offsets for RAHT layers based on rendering-aware modelling.
    
    Args:
        N_primitives (int): Total number of Gaussian primitives.
        distances (list[float]): Euclidean distances to nearest neighbour for each primitive.
        W (int): Training resolution width.
        H (int): Training resolution height.
        N_bar_per_layer (list[float]): Average number of primitives per node for each RAHT layer i.
        
    Returns:
        list[float]: QP offsets for each RAHT layer.
    """
    # Step 1: Calculate Spatial Density (rho)
    # rho = (1 / N_primitives) * sum(1 / d_j^2)
    sum_inv_sq_dist = sum(1.0 / (d ** 2) for d in distances)
    rho = sum_inv_sq_dist / N_primitives
    
    # Step 2: Calculate Global Scaling Factor (s)
    # s = 10 + 0.029 * rho * (W * H)^0.2
    resolution_term = (W * H) ** 0.2
    s = 10 + 0.029 * rho * resolution_term
    
    # Step 3: Derive Sequence-Dependent Parameters
    # gamma = s^3
    # beta = 0.75 * s
    gamma = s ** 3
    beta = 0.75 * s
    
    # Step 4: Compute Layer-wise QP Offsets
    # (delta_qp_i + beta)^3 = gamma * N_bar_i
    # delta_qp_i = (gamma * N_bar_i)^(1/3) - beta
    qp_offsets = []
    for N_bar_i in N_bar_per_layer:
        term = gamma * N_bar_i
        # Cube root calculation
        delta_qp_i = term ** (1.0 / 3.0) - beta
        qp_offsets.append(delta_qp_i)
        
    return qp_offsets
```

**Edge Cases and Pitfalls:**
*   **Zero Distance:** If $d_j = 0$ (co-located primitives), the term $1/d_j^2$ becomes undefined. In practice, nearest-neighbour distances in 3DGS are non-zero due to distinct centers, but numerical stability should be considered if primitives overlap exactly [G].
*   **Resolution Scaling:** The exponent $0.2$ on $(W \cdot H)$ is derived from regression on specific datasets. Applying this to resolutions significantly outside the training range may yield suboptimal $\beta, \gamma$ values [S1, unofficial].
*   **Layer Index Generalization:** The model assumes $\bar{N}_i$ is a valid proxy for hierarchical impact. If the RAHT tree structure varies significantly from the assumed hierarchy, the linear trend observed in Fig. 5 of [S1, unofficial] may not hold [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N_{primitives})$ to compute density $\rho$, and $O(L)$ to compute offsets for $L$ layers. This is significantly faster than iterative per-sequence fitting required by analytical solutions [S1, unofficial].
*   **Memory Complexity:** $O(N_{primitives})$ to store distances, or $O(1)$ if $\rho$ is pre-computed. No large lookup tables are required.
*   **Performance:** On the MPEG 3DGS dataset, configurable fixed-point RAHT precision (20 bits) with this modelling achieved BD-rate reductions of 19% for RGB-PSNR and 14% for YUV-PSNR on facing sequences, and 17% for RGB-PSNR on object-centric sequences [S1, unofficial].
*   **Strengths:** Eliminates the need for per-sequence parameter fitting; generalizes across diverse scenes and resolutions; accounts for error accumulation in splatting projection [S1, unofficial].
*   **Limitations:** Relies on regression-derived constants ($0.029, 0.2, 0.75$) which may not be optimal for all types of scenes or hardware [S1, unofficial].

## Background
The method was proposed in the context of Rate-Distortion Optimized RAHT coding for 3D Gaussian Splatting [S1, unofficial]. It addresses the limitation that optimal QP offsets exhibit a linear trend relative to the RAHT layer index, but this relationship cannot be directly generalized due to varying numbers of RAHT layers between sequences [S1, unofficial]. The approach builds on the observation that error accumulation during splatting projection is constructive for root layers (smaller index) and random/canceling for leaf layers [S1, unofficial].
