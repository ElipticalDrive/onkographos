# Mini-Splatting Pipeline

Also called: Mini-Splatting, Mini-Splatting-D, Mini-Splatting-C

## Overview
The Mini-Splatting Pipeline is a training methodology for 3D Gaussian Splatting [3D Gaussian Splatting](3D-Gaussian-Splatting.md) designed to reconstruct scenes using a constrained, minimal number of Gaussians. It solves the problem of excessive memory consumption and redundant Gaussian proliferation inherent in standard 3DGS by integrating densification, simplification, and depth-based reinitialization phases. It sets itself apart from the base training loop [3D Gaussian Splatting Training](3761-3d-gaussian-splatting-training.md) by explicitly managing the Gaussian count through iterative pruning and re-initialization, rather than relying solely on adaptive density control.

## How it works
The pipeline manages the lifecycle of 3D Gaussians through three distinct phases: densification, simplification, and depth reinitialization. It operates on a loop that continues until convergence, adjusting the Gaussian population based on geometric consistency and rendering error.

### Inputs and Outputs
- **Inputs**: Sparse Structure-from-Motion (SfM) points, a set of training images with known camera poses, and hyperparameters for iteration counts and sampling ratios.
- **Outputs**: A set of 3D Gaussians (centers, covariances, opacities, spherical harmonics coefficients) optimized to render the input views.

### Data Structures
The core data structure is a list of Gaussians. Each Gaussian $g_i$ contains:
- **Center**: $\mathbf{c}_i \in \mathbb{R}^3$
- **Covariance**: $\mathbf{\Sigma}_i$ (represented via rotation $\mathbf{R}_i$ and scale $\mathbf{s}_i$)
- **Opacity**: $\alpha_i \in [0, 1]$
- **Spherical Harmonics (SH) Coefficients**: $\mathbf{c}_{SH, i}$

In the **Mini-Splatting-C** variant, attributes are stored differently for compression:
- Centers are stored as `float32`.
- Scales and SH coefficients are processed using Region-adaptive Hierarchical Transform (RHT) [6] with depth level 16 and quantization step 0.02, then compressed via `numpy.savez_compressed()`.

### Algorithm Steps
The training loop is summarized below. Let $i$ be the current iteration counter.

1. **Initialization**: Initialize the set of Gaussians $\mathcal{G}$ from SfM points. Set $i = 0$.
2. **Loop**: While not converged:
    1. **Densification**:
        - If $i \le \text{DensificationIteration}$ (15K):
            - Perform importance-weighted sampling to identify regions requiring more Gaussians.
            - Clone and split Gaussians based on gradient magnitude or rendering error.
            - Update $\mathcal{G}$.
    2. **Depth Reinitialization**:
        - If $i \pmod{5000} == 0$ (enabled every 5K iterations):
            - For Gaussians with low opacity or high uncertainty, reinitialize their centers using depth information from the training views.
            - *Note*: This strategy relies on accurate depth values.
    3. **Simplification**:
        - If $i \ge \text{SimplificationIteration1}$ (15K) and $i < \text{SimplificationIteration2}$ (20K):
            - Remove redundant Gaussians using intersection-preserving sampling.
            - Merge or prune Gaussians that contribute minimally to the final image.
        - If $i \ge \text{SimplificationIteration2}$ (20K):
            - Perform final simplification passes to ensure minimal Gaussian count.
    4. **Optimization**:
        - Render images from current camera poses using the current $\mathcal{G}$.
        - Compute loss (e.g., L1, SSIM) against ground truth images.
        - Update Gaussian parameters (centers, scales, rotations, opacities, SH coefficients) using an optimizer (typically Adam).
    5. **Increment**: $i \leftarrow i + 1$.

    """
    Implements the Mini-Splatting training loop.
    
    Args:
        sfm_points: List of 3D points from SfM.
        training_images: List of (image, camera_pose) tuples.
        hyperparams: Dict containing DensificationIteration, SimplificationIteration1,

    Returns:
        optimized_gaussians: List of Gaussian objects.
    """
    # Initialize Gaussians from SfM points
    gaussians = initialize_from_sfm(sfm_points)
    
    i = 0
    while not converged(gaussians, training_images):
        # 1. Densification Phase
        if i <= hyperparams['DensificationIteration']:
            # Identify regions with high error or low coverage
            important_regions = importance_weighted_sampling(gaussians, training_images)
            # Clone and split Gaussians in important regions
            gaussians = densify(gaussians, important_regions)
        
        # 2. Depth Reinitialization Phase
        # Enabled every 5K iterations
        if i % 5000 == 0:
            gaussians = depth_reinitialize(gaussians, training_images)
        
        # 3. Simplification Phase
        if i >= hyperparams['SimplificationIteration1']:
            # Remove redundant Gaussians
            gaussians = simplify(gaussians, training_images)
            
        if i >= hyperparams['SimplificationIteration2']:
            # Final simplification
            gaussians = final_simplify(gaussians, training_images)
            
        # 4. Optimization Step
        # Render current view
        rendered_images = render(gaussians, training_images)
        # Compute loss
        loss = compute_loss(rendered_images, training_images)
        # Update parameters
        gaussians = optimize(gaussians, loss)
        
        i += 1
        
    return gaussians

### Parameters
- **DensificationIteration**: 15,000 iterations. Densification occurs up to this point.
- **SimplificationIteration1**: 15,000 iterations. Simplification begins here.
- **SimplificationIteration2**: 20,000 iterations. Final simplification phase begins here.
- **Depth Reinitialization Interval**: Every 5,000 iterations.
- **Sampling Ratio**: Manually controlled to limit Gaussian count. A high ratio can lead to background distortion.

### Edge Cases and Pitfalls
- **Depth Reinitialization Failure**: The depth-based reinitialization strategy fails in areas without reliable depth values, such as the sky or transparent objects [S1].
- **Background Distortion**: A high sampling ratio (too few Gaussians) leads to distortion in the background [S1].
- **Manual Tuning**: The number of Gaussians is manually controlled by the sampling ratio, which requires careful tuning to balance quality and memory [S1].

## Subtopics

### Mini-Splatting-D
A variant of Mini-Splatting where the simplification process is simply disabled. It retains densification and depth reinitialization but does not prune Gaussians after the densification phase. This results in a higher Gaussian count compared to the standard Mini-Splatting but may preserve more detail in complex regions.

### Mini-Splatting-C
A variant focused on memory efficiency and storage compression. It is based on the standard Mini-Splatting pipeline but applies specific compression techniques to the Gaussian attributes. Gaussian centers are stored as `float32`, while scales and SH coefficients are processed using Region-adaptive Hierarchical Transform (RHT) with a depth level of 16 and a quantization step of 0.02. The transformed coefficients are then losslessly compressed using `numpy.savez_compressed()`. This variant is suitable for scenarios where storage size is a critical constraint.

## Operating characteristics
- **Memory Usage**: Significantly lower than standard 3DGS due to the constrained number of Gaussians. The exact reduction depends on the sampling ratio and simplification aggressiveness.
- **Training Time**: Comparable to or slightly longer than standard 3DGS due to the additional simplification and reinitialization steps.
- **Rendering Speed**: Faster than standard 3DGS due to fewer Gaussians to rasterize.
- **Quality**: On the Mip-NeRF 360 dataset, Mini-Splatting achieves competitive results:
    - **SSIM**: 0.772 (bicycle), 0.626 (flowers), 0.847 (garden), 0.806 (stump), 0.654 (treehill), 0.921 (room), 0.904 (counter), 0.926 (kitchen), 0.940 (bonsai), 0.874 (truck), 0.796 (train), 0.904 (johnson), 0.912 (playroom) [S1].
    - **PSNR**: 25.15 (bicycle), 21.58 (flowers), 26.84 (garden), 27.26 (stump), 22.72 (treehill), 31.39 (room), 28.41 (counter), 31.17 (kitchen), 31.57 (bonsai), 25.09 (truck), 21.28 (train), 29.47 (johnson), 30.49 (playroom) [S1].
    - **LPIPS**: 0.225 (bicycle), 0.327 (flowers), 0.150 (garden), 0.199 (stump), 0.312 (treehill), 0.211 (room), 0.199 (counter), 0.130 (kitchen), 0.199 (bonsai), 0.159 (truck), 0.245 (train), 0.257 (johnson), 0.250 (playroom) [S1].
- **Strengths**: Reduced memory footprint, faster rendering, competitive image quality.
- **Limitations**: Requires manual tuning of sampling ratio, depth reinitialization fails in sky/transparent areas, potential background distortion if too few Gaussians are used.

## Background
Mini-Splatting was introduced to address the memory and computational overhead of standard 3D Gaussian Splatting. It builds on the 3DGS rendering pipeline but introduces explicit mechanisms to control the number of Gaussians. The method was proposed in "Mini-Splatting: Representing Scenes with a Constrained Number of Gaussians" [S1].
