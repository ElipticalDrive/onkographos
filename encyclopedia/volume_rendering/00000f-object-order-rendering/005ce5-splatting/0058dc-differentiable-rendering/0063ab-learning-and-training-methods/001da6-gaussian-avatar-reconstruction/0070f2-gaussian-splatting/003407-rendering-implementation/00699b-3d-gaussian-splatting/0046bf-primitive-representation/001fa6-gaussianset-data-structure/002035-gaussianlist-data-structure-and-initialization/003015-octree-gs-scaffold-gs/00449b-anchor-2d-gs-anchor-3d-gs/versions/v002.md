# Anchor-2D-GS / Anchor-3D-GS
Also called: Anchor-GS, modified versions of 2D-GS and 3D-GS

## Overview
Anchor-2D-GS and Anchor-3D-GS are modified variants of 2D-GS [15] and 3D-GS [5] that employ an anchor grid structure to organize Gaussian primitives more efficiently, reducing redundancy and storage overhead [S1]. They achieve competitive rendering quality with fewer file storage than original methods, demonstrating that the anchor design organizes primitives more efficiently [S1].

## How it works
**Inputs and Outputs:**
Input: Sparse Structure-from-Motion (SfM) points [S1]. Output: A set of 2D or 3D Gaussians organized within an anchor grid structure [S1].

**Data Structures:**
The method voxelize the input SfM points to create anchors [S1]. Each anchor is assigned 2D or 3D Gaussians [S1]. The exact layout of Gaussian attributes (fields, sizes, bit packing) is Not given in the sources, but follows the standard definitions of the parent method with spatial distribution constrained by the anchor grid [S1].

**Numbered Steps:**
1. Voxelize the input SfM points to generate the anchor grid [S1].
2. Assign 2D or 3D Gaussians to each anchor [S1].
3. Optimize the Gaussian parameters using the specified loss functions and densification strategy [S1].

**Formulas:**
For Anchor-3D-GS, standard L1 and SSIM losses are used [S1]. For Anchor-2D-GS, the distortion loss is $L_d = \sum_{i,j} \omega_i \omega_j |z_i - z_j|$ and the normal loss is $L_n = \sum_i \omega_i (1 - \mathbf{n}_i^T \mathbf{N})$, where $\omega_i$ and $\omega_j$ are opacities, $z_i$ and $z_j$ are depths, $\mathbf{n}_i$ is the predicted normal, and $\mathbf{N}$ is the target normal [S1].

**Parameters:**
Voxel size for the anchor grid is 0.001 for all scenes [S1]. Training runs for 40k iterations with densification concluding at 20k iterations for standard scenes, or 100k iterations with densification ending at 50k iterations for large-scale scenes [S1]. The densification interval is $T = 100$ [S1]. The visibility threshold is $\tau_v = 0.7$ for small-scale scenes [S1]. Loss weights are 0.8 (L1) and 0.2 (SSIM) for Anchor-3D-GS, and 0.01 (distortion) and 0.05 (normal) for Anchor-2D-GS [S1].

**Edge Cases and Pitfalls:**
The method assumes the input consists of SfM points [S1]. Not all layers are fully densified during progressive training, which may require extending densification by an additional 10k iterations [S1].

## Subtopics

### Anchor Gaussian Handling
Anchor Gaussians are hypothesized to constrain and regularize parameters of coarser-level Gaussians, typically having larger scales than regular Gaussians [S2]. They do not have actual opacity for rendering; for visualization, their opacity is manually set to $\text{sigmoid}(1)$ [S2]. The average scale of anchors is $e^{-5.08}$ across 100 randomly sampled scenes, while the average scale of Gaussians is $e^{-7.12}$ [S2]. This size difference suggests that Gaussians adjust their scales to represent sharp details in real-world images, whereas anchor Gaussians serve a regularization role [S2].

## Operating characteristics
The method achieves fewer file storage than original 2D-GS and 3D-GS methods [S1]. It delivers competitive rendering quality compared to original methods [S1]. The anchor design creates a more compact representation by reducing redundancy [S1]. While Anchor-2D/3D-GS reduce storage, Octree-GS delivers better visual performance and fewer Gaussian primitives due to its explicit, multi-level anchor design [S1].

## Background
Introduced in Octree-GS [S1], the method modifies 2D-GS [15] and 3D-GS [5] by voxelizing input SfM points into an anchor grid and assigning Gaussians to each anchor, while adopting Scaffold-GS's densification strategy [S1].
