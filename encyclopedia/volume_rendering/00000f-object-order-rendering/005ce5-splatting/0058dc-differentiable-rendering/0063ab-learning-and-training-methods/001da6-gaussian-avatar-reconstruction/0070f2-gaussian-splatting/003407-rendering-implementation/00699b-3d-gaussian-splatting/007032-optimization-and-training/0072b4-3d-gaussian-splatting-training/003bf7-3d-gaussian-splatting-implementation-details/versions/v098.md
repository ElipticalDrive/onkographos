# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, GSGEN Implementation Details, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific implementation parameters, optimization strategies, and variant algorithms used to train and render 3D Gaussian Splatting (3DGS) scenes. It addresses the practical challenges of differentiable rasterization, including half-precision stability, adaptive density control, and handling of specific scene properties like defocus blur or non-Lambertian reflections. Unlike the base [3D Gaussian Splatting](9128-3d-gaussian-splatting.md) method which defines the core mathematical formulation, these details focus on the engineering choices and algorithmic variants required for robust, high-fidelity reconstruction in diverse scenarios.

## How it works

### Core Training Loop and Optimization
The standard training loop iterates over a dataset of images, optimizing Gaussian parameters (position $\mathbf{p}$, covariance $\mathbf{\Sigma}$, opacity $\alpha$, and spherical harmonic coefficients $\mathbf{c}$) via gradient descent [S3].

**Inputs:**
- Camera poses $\mathbf{T}_{cw}$ and intrinsics $\mathbf{K}$.
- Ground truth images $\mathbf{I}_{gt}$.
- Initial point cloud from Structure-from-Motion (SfM).

**Outputs:**
- Optimized set of 3D Gaussians $\mathcal{G}$.

**Data Structures:**
- **Gaussian Attributes:** Each Gaussian $j$ stores:
  - Position $\mathbf{p}_j \in \mathbb{R}^3$.
  - Rotation $\mathbf{q}_j \in \mathbb{R}^4$ (quaternion) or $\mathbf{R}_j \in \mathbb{R}^{3 \times 3}$.
  - Scale $\mathbf{s}_j \in \mathbb{R}^3$.
  - Opacity $\alpha_j \in [0, 1]$.
  - SH Coefficients $\mathbf{c}_j$ (typically degree 1, 12 coefficients per RGB channel) [S3].
- **Accumulated Gradients:** Stores positional gradients $\nabla_{\mathbf{p}}$ for densification decisions [S1].

**Parameters:**
- Optimizer: Adam with learning rate $1 \times 10^{-3}$ [S3].
- Loss Weight $\lambda$: Balances MSE and SSIM in PyGS [S13, unofficial].
- Opacity Threshold $\alpha_{min} = 0.05$ for pruning [S1].
- Position Gradient Threshold $T_{pos} = 0.02$ for splitting [S1].

**Numbered Steps:**
1. **Random View Selection:** Randomly select a single image from a random scene as supervision for each iteration [S3].
2. **Forward Rasterization:** Project 3D Gaussians to 2D, sort by depth, and alpha-blend to produce rendered image $\hat{\mathbf{I}}$ [6233-optimization-and-parallelization].
3. **Loss Computation:** Compute loss $\mathcal{L}$ between $\hat{\mathbf{I}}$ and $\mathbf{I}_{gt}$. Standard loss is a combination of L1 and SSIM [S13, unofficial].
4. **Backward Pass:** Compute gradients $\frac{\partial \mathcal{L}}{\partial \theta}$ for all Gaussian parameters [6233-optimization-and-parallelization].
5. **Optimizer Update:** Update Gaussian parameters using Adam [S3].
6. **Densification (Every 100-1000 iterations):**
   - Check accumulated positional gradients.
   - Split Gaussians with gradient magnitude $> T_{pos}$ [S1].
   - Clone Gaussians with large scales but low gradients [Parent].
   - Prune Gaussians with $\alpha < \alpha_{min}$ or excessive radius every 200 iterations [S1].

**Pseudocode:**
```python
# Standard 3DGS Training Loop Variant
def train_step(camera, gt_image, gaussians, optimizer):
    # 1. Forward Pass
    projected_gaussians = project_3d_to_2d(gaussians, camera)
    sorted_gaussians = sort_by_depth(projected_gaussians)
    rendered_image = alpha_blend(sorted_gaussians)
    
    # 2. Loss Calculation
    # Standard 3DGS uses L1 + SSIM. PyGS uses MSE + SSIM [S13, unofficial].
    loss = compute_loss(rendered_image, gt_image)
    
    # 3. Backward Pass
    gradients = compute_gradients(loss, gaussians)
    
    # 4. Optimizer Step
    optimizer.step(gaussians, gradients)
    
    # 5. Densification (Example: every 1000 iterations)
    if iteration % 1000 == 0:
        accumulate_position_gradients(gaussians, gradients)
        split_gaussians(gaussians, threshold=T_pos)
        prune_gaussians(gaussians, alpha_min=0.05)
        
    return loss

# Half-Precision Stability Variant (gsplat)
def train_step_half_precision(camera, gt_image, gaussians, optimizer):
    # Use half-precision memory fetches on feature vectors [S2]
    with torch.cuda.amp.autocast():
        rendered_image = forward_rasterization(gaussians, camera)
        loss = compute_loss(rendered_image, gt_image)
        
    # Apply automatic scaling factor to loss values [S2]
    scaled_loss = loss * scale_factor
    
    # Backward pass in mixed precision
    optimizer.zero_grad()
    scaled_loss.backward()
    optimizer.step()
```

### Adaptive Density Control and Scene Extent
Standard 3DGS uses a fixed scene extent $e_{scene}$ based on camera positions, which can bias densification if cameras are clustered [S4].

**Corrected Scene Extent:**
To avoid bias from camera distribution (e.g., orbiting a small object), the scene extent is calculated based on the SfM point cloud [S4]:
$$ \bar{C} = \frac{1}{N_{cam}} \sum_{i=1}^{N_{cam}} C_i $$
$$ e'_{scene} = \frac{1}{N_{SfM}} \sum_{i=1}^{N_{SfM}} \|\bar{C} - p_i\|_2 $$
where $N_{SfM}$ is the number of SfM points, $\bar{C}$ is the average camera position, and $p_i$ are SfM points [S4].

**Multi-Scale Constraint:**
For large-scale scenes, a position-aware adaptive control applies different scales based on viewer distance [S7]:
$$ \gamma(\mu) = \begin{cases} 1 & \text{if } \|\mu - c\|^2 < 2r \\ \|\mu - c\|^2 / r - 1 & \text{if } \|\mu - c\|^2 \ge 2r \end{cases} $$
where $r$ is scene radius, $c$ is camera center, and $\mu$ is Gaussian position [S7]. Cloning occurs if $\max(s) < g \cdot \gamma(\mu)$, splitting if $\max(s) \ge g \cdot \gamma(\mu)$, and elimination if $\max(s) > b \cdot \gamma(\mu)$ [S7].

### Half-Precision Rasterization
To reduce register pressure and memory bandwidth, the `gsplat` implementation uses half-precision (FP16) for feature vector fetches during both forward and backward passes [S2]. An automatic scaling factor is applied to loss values to improve training stability in FP16 [S2]. Tiny-cuda-nn's JIT-compiled cooperative vector MLPs are used for training and evaluation in half precision [S2].

### Camera Localization
For SLAM applications, camera pose $T_{CW}$ is localized by minimizing photometric error against a target view while fixing the initial Gaussian set $G_{init}$ [S9, unofficial]:
$$ \mathbf{T}_{CW}^{est} = \underset{\mathbf{T}_{CW}}{\arg \min} \left\| I(\mathcal{G}_{init}, \mathbf{T}_{CW}) - \bar{I}_{target} \right\|_1 $$
Optimization runs for 1000 iterations, with success defined as convergence within 1cm of the target view [S9, unofficial].

## Subtopics

### Corrected Scene-Extent
A method to calculate scene extent based on the SfM point cloud rather than camera positions to avoid bias from camera distribution (e.g., orbiting a small object in a large environment) [S4]. It sets itself apart from standard 3DGS by using the spatial distribution of reconstructed points to define the bounding volume, ensuring appropriate Gaussian splitting and pruning for large outdoor scenes [S4].

### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ to selectively enlarge covariances, creating pixel-wise variable blur kernels that match spatially varying scene blurriness [S5]. It sets itself apart from naive Gaussian blur by allowing spatially varying blur shapes and magnitudes, enabling effective deblurring of defocus artifacts without blurring sharp regions [S5].

### Denoise-GS
A self-supervised denoising method for sparse-view 3D Gaussian Splatting that combines unsupervised image denoising (Noise2Void) with differentiable 3DGS [S6]. It solves the problem of suboptimal reconstruction in noisy, sparse-view scenarios by using a two-round process: initial denoising and training, followed by fine-tuning the denoiser with a composite loss based on rendered views [S6].

### Multi-Scale Constraint
A technique using position-aware point adaptive control to apply different scales to Gaussians based on viewer distance, improving rendering of distant objects [S7]. It sets itself apart from standard densification by dynamically adjusting cloning, splitting, and elimination thresholds based on the Gaussian's distance from the camera center [S7].

### LS-Gaussian Viewpoint Transformation
An algorithm that leverages inter-frame continuity for efficient sparse rendering by transforming the viewpoint between consecutive frames, rather than rendering each frame separately [S8]. It sets itself apart from naive pixel warping by operating at the tile/Gaussian level to reduce preprocessing and sorting costs, enabling sparse rendering where only one frame in every 6 is fully rendered [S8].

### DiffGS Framework
Applies an optimization process during Gaussian extraction to optimize Gaussians to exact locations using a Gaussian Probability Function (GauPF) with a truncation function $\lambda$ and projection function $\tau$ [S10]. It sets itself apart by explicitly modeling the probability distribution of Gaussians, achieving high PSNR/SSIM with fewer Gaussians (e.g., 50K-350K) compared to standard 3DGS [S10].

### Conditional Splat Approximation
A technique to approximate the influence range of a 3D Gaussian on a slice by using a 2D ellipse splat scaled by the marginal factor, which closely matches the true iso-probability contours [S12, unofficial]. It sets itself apart by providing an accurate and efficient approximation for slice-based rendering or tomographic reconstruction [S12, unofficial].

### PyGS Optimization
The optimization process using a combined MSE and SSIM loss, along with density control strategies adapted from 3DGS, while preserving the multi-scale structure [S13, unofficial]. It sets itself apart by routinely reassessing and reassigning the levels of Gaussians based on their scales to preserve multi-scale characteristics in large-scale scenes [S13, unofficial].

### GAINS (Gaussian-based Inverse Rendering from Sparse multi-view captures)
A two-stage inverse rendering framework that leverages foundation model priors to stabilize geometry and material estimation from sparse multi-view RGB captures [S14]. It sets itself apart by using 2DGS for more accurate geometry reconstruction, which is essential for accurate material property estimation, and integrating monocular depth, normal, and diffusion priors [S14].

### SAGS (Adaptive Gaussian Splatting)
A method that utilizes an adaptive 2D low-pass filter at inferencing time based on rendering resolution and camera distance to handle aliasing [S15, unofficial]. It sets itself apart from standard 3DGS by dynamically adjusting the filtering based on scene geometry and view parameters to produce aliasing-free images [S15, unofficial].

### Frequency Gaussian Splatting
A method that applies frequency-domain regularization to the rendered 2D image to encourage recovery of high-frequency detail, resolving blurring issues [S15, unofficial]. It sets itself apart by operating in the frequency domain to specifically target high-frequency loss common in standard 3DGS [S15, unofficial].

### Neural Illumination Enhancement
A neural module applied only to non-Lambertian regions to model view-dependent highlights and handle non-Lambertian effects that vanilla 3DGS struggles with [S16, unofficial]. It sets itself apart by predicting a view-dependent color residual using a lightweight MLP (with HashGrid and SH encodings) and adding it to the explicit Gaussian image, enabling modeling of view-dependent highlights alongside global illumination caching [S16, unofficial].

### GraphiGS
A variant of the GraphiXS framework where the component distribution $\delta_\theta$ is modeled as a 3D Gaussian primitive, providing compact spatial support and exponential density decay [S17]. It sets itself apart by using Gaussian primitives to model uncertainty, offering compact spatial support compared to heavy-tailed distributions [S17].

## Operating characteristics

### Time and Memory Complexity
- **Memory:** Standard 3DGS requires significant memory for millions of Gaussians, often exceeding 1GB for real-world datasets [12943-data-compression-and-storage-optimization]. Half-precision implementations reduce register pressure and memory bandwidth usage [S2].
- **Time:** Rendering is $O(N \cdot M)$ where $N$ is pixels and $M$ is Gaussians per pixel, but optimized via tile-based sorting and rasterization [6233-optimization-and-parallelization]. Sparse rendering techniques (e.g., LS-Gaussian) reduce computation by rendering only every $k$-th frame [S8].

### Measured Performance
- **DiffGS:** 50K Gaussians: PSNR 28.61, SSIM 0.9787, LPIPS 0.0251; 100K Gaussians: PSNR 30.35, SSIM 0.9838, LPIPS 0.0151; 350K Gaussians: PSNR 34.01, SSIM 0.9879, LPIPS 0.0149 [S10].
- **LS-Gaussian:** 5.41× speedup over edge GPU baseline on Jetson AGX Orin, up to 17.3× with custom accelerator [S8].

### Strengths and Limitations
- **Strengths:** Real-time rendering, high fidelity, differentiable optimization [6233-optimization-and-parallelization].
- **Limitations:** Sensitive to initialization, prone to floaters, high memory usage [12943-data-compression-and-storage-optimization]. Half-precision requires careful loss scaling [S2].

### When to Use
- Use standard implementation for general high-quality novel view synthesis.
- Use half-precision for memory-constrained GPUs or large scenes [S2].
- Use Corrected Scene-Extent for scenes with clustered cameras [S4].
- Use Selective Defocus Blurring for scenes with varying depth of field [S5].
- Use Denoise-GS for sparse, noisy inputs [S6].
- Use Multi-Scale Constraint for large-scale outdoor scenes [S7].
- Use LS-Gaussian for real-time video stream processing [S8].
- Use DiffGS for compact representations with fewer Gaussians [S10].
- Use PyGS for large-scale multi-scale scenes [S13, unofficial].
- Use GAINS for inverse rendering from sparse views [S14].
- Use SAGS/Frequency GS for aliasing/high-frequency detail [S15, unofficial].
- Use NIE for non-Lambertian materials [S16, unofficial].
- Use GraphiGS for uncertainty modeling [S17].

## Background

### Origin
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [9128-3d-gaussian-splatting]. The implementation details described here stem from subsequent research and engineering efforts to optimize, stabilize, and extend the base method for various applications.

### History and Development
- **2023:** Base 3DGS released [9128-3d-gaussian-splatting].
- **2024-2026:** Various extensions for half-precision [S2], defocus blur [S5], denoising [S6], large-scale scenes [S7][S13, unofficial], inverse rendering [S14], and aliasing [S15, unofficial] were developed.

### Usage
Used in computer graphics, robotics (SLAM), and virtual reality for real-time novel view synthesis and scene reconstruction.
