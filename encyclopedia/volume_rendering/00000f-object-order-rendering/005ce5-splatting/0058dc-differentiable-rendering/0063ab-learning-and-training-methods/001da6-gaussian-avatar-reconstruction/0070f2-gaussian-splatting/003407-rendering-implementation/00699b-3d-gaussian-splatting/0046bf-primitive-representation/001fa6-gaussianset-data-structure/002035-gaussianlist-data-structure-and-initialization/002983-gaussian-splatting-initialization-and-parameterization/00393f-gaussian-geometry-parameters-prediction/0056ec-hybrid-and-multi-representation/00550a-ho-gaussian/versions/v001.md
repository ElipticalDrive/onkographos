# HO-Gaussian

Also called: Hybrid Optimization of 3D Gaussian Splatting

## Overview
HO-Gaussian is a point-free representation method for multi-camera urban scenes that combines a grid-based volume with the 3D Gaussian Splatting (3DGS) pipeline to eliminate dependency on Structure-from-Motion (SfM) point initialization [S1]. It solves the problem of rendering low-texture, sky, and distant areas in large-scale urban environments where standard 3DGS fails due to sparse or outlier-prone SfM data [S1]. Unlike standard 3DGS, which relies on well-initialized point clouds, HO-Gaussian learns Gaussian positions directly from a grid volume, using Gaussian Directional Encoding to replace spherical harmonics for view-dependent color, and neural warping to ensure consistency across multiple camera viewpoints [S1].

## How it works
**Inputs:** Multi-view RGB images from a multi-camera setup (e.g., autonomous driving rigs); no SfM point cloud or LiDAR data required [S1].
**Outputs:** A set of 3D Gaussians with optimized positions, covariances, opacities, and view-dependent colors; rendered novel views [S1].

**Data Structures:**
1.  **Grid-Based Volume:** A 3D voxel grid storing features used for position prediction and directional encoding. The specific resolution and channel dimensions are not given in the sources [S1].
2.  **Gaussian Set:** A collection of $N$ Gaussians. Each Gaussian $i$ is defined by:
    *   Position $\mathbf{p}_i$: Learned from the grid volume, not initialized from points [S1].
    *   Covariance $\Sigma_i$: Parameterized as standard in 3DGS (rotation matrix $\mathbf{R}$ and scaling vector $\mathbf{s}$) [S1].
    *   Opacity $\alpha_i$: Standard scalar [S1].
    *   Color $\mathbf{c}_i$: Encoded via Gaussian Directional Encoding (GDE) from the grid volume, replacing spherical harmonics coefficients [S1].

**Numbered Steps:**

1.  **Initialization:** Initialize the grid-based volume with random or zero values. Initialize the Gaussian set with a sparse distribution or empty state, as no SfM points are used [S1].
2.  **Position Learning:** For each Gaussian, query the grid-based volume to predict its 3D position $\mathbf{p}_i$. This allows the optimization of geometric information in sky, distant, and low-texture areas where SfM fails [S1].
3.  **Gaussian Directional Encoding (GDE):** Instead of storing high-order spherical harmonic coefficients (which require gigabytes of disk space for large scenes), compute view-dependent color $\mathbf{c}_i$ using the grid volume features [S1]. The grid volume acts as a compact directional encoder, significantly reducing disk space usage (e.g., from 557MB to 123MB in experiments) [S1].
4.  **Neural Warping:** To handle multi-camera consistency, introduce virtual viewpoints. Use neural warping to warp features from observed cameras to these virtual viewpoints, providing additional supervisory signals to the Gaussian pipeline. This enhances consistent appearance and geometry across different cameras and reduces overfitting to specific viewpoints [S1].
5.  **Hybrid Optimization:** Iteratively optimize the grid-based volume and the Gaussian parameters (positions, covariances, opacities, GDE features) using gradient descent on the rendering loss (e.g., L1 loss, SSIM loss) between rendered images and ground truth RGB images [S1].
6.  **Point Densification:** At regular intervals during training, perform point densification. Add new Gaussian positions to regions with high error, low texture, or distant areas. Fine-tune these new positions via gradient descent in the Gaussian pipeline [S1].

**Pseudocode:**

```python
def ho_gaussian_training(images, camera_poses, num_iterations):
    # Initialize grid volume (e.g., 3D convolutional network or voxel grid)
    grid_volume = initialize_grid_volume()
    
    # Initialize Gaussian set (positions, covariances, opacities, GDE features)
    # Positions are not from SfM; start with sparse or random initialization
    gaussians = initialize_gaussians_sparse()
    
    for iteration in range(num_iterations):
        # 1. Sample a batch of images and corresponding camera poses
        batch_images, batch_cameras = sample_batch(images, camera_poses)
        
        # 2. Predict Gaussian positions from grid volume
        # This step learns geometry without SfM points
        predicted_positions = predict_positions_from_grid(grid_volume, gaussians)
        gaussians.positions = predicted_positions
        
        # 3. Compute view-dependent color using Gaussian Directional Encoding (GDE)
        # Replaces spherical harmonics to save disk space
        colors = compute_gde_color(grid_volume, gaussians, batch_cameras)
        
        # 4. Neural Warping for multi-camera consistency
        # Generate virtual viewpoints and warp features
        virtual_views = generate_virtual_views(batch_cameras)
        warped_features = neural_warp(grid_volume, batch_cameras, virtual_views)
        
        # 5. Render images from current Gaussian set
        rendered_images = render_gaussians(gaussians, batch_cameras)
        
        # 6. Compute loss (e.g., L1 + SSIM)
        # Include loss from virtual views if using neural warping supervision
        loss = compute_rendering_loss(rendered_images, batch_images)
        loss += compute_warping_loss(warped_features, batch_images)
        
        # 7. Backpropagate and update grid volume and Gaussian parameters
        update_parameters(grid_volume, gaussians, loss)
        
        # 8. Point Densification at regular intervals
        if iteration % densification_interval == 0:
            gaussians = densify_gaussians(gaussians, grid_volume, rendering_errors)
            
    return grid_volume, gaussians
```

**Parameters:**
*   **Densification Interval:** Not given in the sources [S1].
*   **Grid Resolution:** Not given in the sources [S1].
*   **Spherical Harmonics Degree:** Replaced by GDE; standard 3DGS uses degree 3 or 4, but HO-Gaussian avoids this entirely [S1].

**Edge Cases and Pitfalls:**
*   **Low-Texture Regions:** Standard 3DGS treats these as outliers; HO-Gaussian uses grid volume learning and densification to address this [S1].
*   **Distant/Sky Areas:** SfM points are sparse here; HO-Gaussian learns positions from the grid volume to improve representation [S1].
*   **Multi-Camera Consistency:** Without neural warping, views from different cameras may conflict; warping ensures mutual learning [S1].
*   **Disk Space:** Standard 3DGS with spherical harmonics requires gigabytes for large scenes; HO-Gaussian reduces this to ~123MB for the evaluated scene [S1].

## Subtopics

### Gaussian Directional Encoding
A technique replacing spherical harmonics with grid-based directional encoding to reduce disk space and model view-dependent color. It sets itself apart by eliminating the need to store high-order coefficients. Choose it when disk space is a constraint in large-scale scenes. [Link](9436-textured-gs.md) is a sibling but focuses on textured primitives, not directional encoding.

### Neural Warping
A scheme for multi-camera consistency by warping features to virtual viewpoints. It sets itself apart by enabling mutual learning between camera perspectives. Choose it for multi-camera urban scenes. [Link](10060-deformable-3d-gaussian-splatting.md) is a sibling but focuses on deformation, not warping for consistency.

## Operating characteristics
*   **Time Complexity:** Training time is 76 minutes on the evaluated urban scene (Argoverse dataset) [S1].
*   **Memory Complexity:** Model size is 123MB, significantly smaller than baseline 3DGS (557MB) and NeRF-based methods (e.g., LocalRF 3762MB) [S1].
*   **Measured Performance:** On the Argoverse dataset, HO-Gaussian achieves PSNR 30.98, SSIM 0.9043, LPIPS 0.2287 with RGB input only [S1].
*   **Rendering Speed:** 71 FPS on the evaluated urban scene [S1].
*   **Scaling:** The method is designed for large-scale urban scenes and multi-camera systems. It scales by using grid-based volume for efficient position and color encoding, avoiding the $O(N)$ storage of spherical harmonics per Gaussian [S1].
*   **Strengths:** Point-free initialization (no SfM/LiDAR needed), reduced disk space, real-time rendering, good performance in low-texture/distant areas, multi-camera consistency.
*   **Limitations:** Relies on grid volume learning which may require careful tuning; performance may vary in extremely unbounded or dynamic scenes not covered in the evaluation [S1].
*   **When to use:** Large-scale urban scene reconstruction from multi-camera RGB data where SfM points are sparse or unreliable.
*   **When not to use:** Small-scale object-centric scenes where SfM points are abundant and high-fidelity spherical harmonics are preferred for view-dependent effects.

## Background
HO-Gaussian was proposed by Li et al. in the paper "HO-Gaussian: Hybrid Optimization of 3D Gaussian Splatting for Urban Scenes" [S1]. It addresses limitations of previous 3DGS-based methods in urban scenes, specifically their reliance on SfM points and difficulties in rendering distant, sky, and low-texture areas [S1]. The method was evaluated on the Argoverse and Waymo datasets for autonomous driving scenarios [S1]. It builds on the 3D Gaussian Splatting pipeline [S1] but introduces hybrid optimization with a grid-based volume, Gaussian Directional Encoding, and neural warping [S1].
