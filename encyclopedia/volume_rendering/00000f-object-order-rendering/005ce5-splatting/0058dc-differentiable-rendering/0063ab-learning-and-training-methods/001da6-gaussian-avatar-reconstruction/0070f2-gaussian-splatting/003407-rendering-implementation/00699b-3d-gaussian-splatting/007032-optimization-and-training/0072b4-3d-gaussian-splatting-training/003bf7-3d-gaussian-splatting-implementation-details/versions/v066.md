# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, GSGEN Implementation Details, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific hyperparameters, data structures, and optimization schedules required to implement the 3D Gaussian Splatting (3DGS) training pipeline from scratch. It addresses the problem of translating the theoretical differentiable rasterization core into a stable, convergent optimization process by defining the densification schedule, pruning criteria, and numerical precision strategies. It sets itself apart from sibling methods like [MaskGaussian Gradient Computation](4254-maskgaussian-gradient-computation.md) or [Parallelization for Backpropagation](5989-parallelization-for-backpropagation.md) by focusing on the *configuration* of the standard training loop rather than architectural changes to the gradient flow or hardware acceleration layers.

## How it works

### Inputs and Outputs
*   **Inputs**: A set of $N$ training images with known camera poses (extrinsics $C_i$ and intrinsics), and an initial sparse point cloud from Structure-from-Motion (SfM) [S3, S4].
*   **Outputs**: A set of $M$ 3D Gaussian primitives $\mathcal{G} = \{g_1, \dots, g_M\}$, where each $g_j$ is parameterized by position $\mu_j$, covariance $\Sigma_j$ (or scale $s_j$ and rotation $q_j$), opacity $\alpha_j$, and spherical harmonic coefficients $\mathbf{c}_j$ [S5][S9, unofficial].

### Data Structures
The Gaussian primitive $g_j$ is stored in a flat array or Struct-of-Arrays (SoA) layout for efficient GPU access [S2].
*   **Position**: $\mu_j \in \mathbb{R}^3$ (float32).
*   **Rotation**: $q_j \in \mathbb{R}^4$ (unit quaternion, float32) [S2].
*   **Scale**: $s_j \in \mathbb{R}^3$ (log-space scale, float32) [S2].
*   **Opacity**: $\alpha_j \in \mathbb{R}$ (sigmoid output, float32) [S2].
*   **Features**: $\mathbf{c}_j \in \mathbb{R}^{K \times 3}$, where $K$ is the number of SH bands. For SH Degree 1, $K=4$, resulting in 12 floats per Gaussian [S3].
*   **Accumulated Gradients**: $\nabla \mu_j, \nabla \alpha_j$ (float32, zero-initialized per iteration) [S1, S4].

### Training Loop Steps
The training process follows a stochastic gradient descent loop [S9, unofficial].

1.  **Initialization**: Initialize Gaussians from the SfM point cloud. Set initial covariance $\Sigma_j$ based on the distance to the $k$-nearest neighbors in the point cloud [S4].
2.  **Iteration Start**:
    a.  **Random View Selection**: Randomly select one training image $I_{target}$ and its camera pose $C_{target}$ from the dataset [S3][S9, unofficial].
    b.  **Rasterization**: Render the current set of Gaussians $\mathcal{G}$ from $C_{target}$ to produce image $\hat{I}$ using differentiable alpha blending [6233-optimization-and-parallelization].
    c.  **Loss Computation**: Compute the loss $\mathcal{L}$ between $\hat{I}$ and $I_{target}$:
        $$ \mathcal{L} = (1 - \lambda) \mathcal{L}_1(\hat{I}, I_{target}) + \lambda \mathcal{L}_{SSIM}(\hat{I}, I_{target}) $$
        where $\lambda \approx 0.2$ [S9, unofficial].
    d.  **Backpropagation**: Compute gradients $\frac{\partial \mathcal{L}}{\partial \theta}$ for all Gaussian parameters $\theta$ [6233-optimization-and-parallelization].
    e.  **Optimizer Step**: Update parameters using Adam with learning rate $1 \times 10^{-3}$ [S3].
3.  **Densification and Pruning (Periodic)**: Every $N_{dens}$ iterations, perform adaptive density control [S1, S4].
    a.  **Gradient Check**: For each Gaussian, check the accumulated view-space position gradient magnitude $\|\nabla \mu_j\|$.
    b.  **Splitting**: If $\|\nabla \mu_j\| > T_{pos}$, split the Gaussian into two. The new positions are $\mu_j \pm \delta \mu$, where $\delta \mu$ is scaled by the original scale [S1, S4].
    c.  **Cloning**: If $\|\nabla \mu_j\| > T_{pos}$ but the Gaussian is already small, clone it instead of splitting to avoid excessive fragmentation [S4].
    d.  **Pruning**: If opacity $\alpha_j < \alpha_{min}$ or the world-space radius exceeds a threshold, remove the Gaussian [S1].

### Formulas and Parameters
*   **Scene Extent ($e_{scene}$)**: Critical for initializing Gaussian scales. The default 3DGS implementation uses camera positions, which is biased [S4].
    *   *Default (Biased)*: $e_{\text{scene}} = 1.1 \cdot \max_{i=1}^{N_{\text{cam}}} \|\bar{C} - C_i\|_2$, where $\bar{C} = \frac{1}{N_{\text{cam}}} \sum C_i$ [S4].
    *   *Corrected*: $e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2$, where $p_i$ are SfM points [S4].
*   **Densification Thresholds**:
    *   $T_{pos} = 0.02$ (view-space position gradient threshold) [S1].
    *   $\alpha_{min} = 0.05$ (opacity pruning threshold) [S1].
*   **Iteration Schedule**:
    *   Split/Clone: Every 500 iterations [S1].
    *   Compactness Densification: Every 1000 iterations [S1].
    *   Pruning: Every 200 iterations [S1].
    *   Total Iterations: Typically 30,000 [S9, unofficial].

### Pseudocode
```python
# Initialization
gaussians = initialize_from_sfm(sfm_points)
optimizer = Adam(gaussians.parameters(), lr=1e-3)

for iteration in range(1, 30001):
    # 1. Random View Selection
    target_image, camera_pose = random_sample(training_dataset)
    
    # 2. Forward Pass (Rasterization)
    rendered_image = rasterize(gaussians, camera_pose)
    
    # 3. Loss Computation
    l1_loss = l1_loss(rendered_image, target_image)
    ssim_loss = ssim_loss(rendered_image, target_image)
    loss = 0.8 * l1_loss + 0.2 * ssim_loss
    
    # 4. Backward Pass
    optimizer.zero_grad()
    loss.backward()
    
    # 5. Optimizer Step
    optimizer.step()
    
    # 6. Periodic Densification and Pruning
    if iteration % 200 == 0:
        prune_gaussians(gaussians, alpha_min=0.05)
        
    if iteration % 500 == 0:
        densify_gaussians(gaussians, threshold=0.02)
        
    if iteration % 1000 == 0:
        compactness_densify(gaussians)
```

### Edge Cases and Pitfalls
*   **Scene Extent Bias**: Using camera positions to calculate scene extent causes incorrect splitting/pruning if cameras are clustered (e.g., orbiting a small object in a large environment) [S4]. Use SfM points for extent calculation [S4].
*   **Half-Precision Stability**: Training in FP16 requires an automatic scaling factor for loss values to prevent gradient underflow [S2].
*   **Register Pressure**: Fetching feature vectors in half-precision during rasterization reduces register pressure but requires careful handling of precision loss in the backward pass [S2].

## Subtopics

### Corrected Scene-Extent
A method to calculate scene extent based on the SfM point cloud rather than camera positions to avoid bias from camera distribution (e.g., orbiting a small object in a large environment). It sets itself apart from the default 3DGS implementation by using $e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2$. Choose this when camera poses are non-uniformly distributed. Link: [Corrected Scene-Extent](12926-corrected-scene-extent.md) (inferred).

### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ to selectively enlarge covariances, creating pixel-wise variable blur kernels that match spatially varying scene blurriness. It sets itself apart from naive Gaussian blur by allowing spatially varying blur shapes and magnitudes via a compact MLP. Choose this for scenes with defocus blur. Link: [Selective Defocus Blurring](12927-selective-defocus-blurring.md) (inferred).

### Denoise-GS
A self-supervised denoising method for sparse-view 3D Gaussian Splatting that combines unsupervised image denoising (Noise2Void) with 3DGS. It sets itself apart from supervised methods by requiring no paired clean data, making it robust to non-Gaussian noise in sparse viewpoints. Choose this for sparse-view or noisy input data. Link: [Denoise-GS](12928-denoise-gs.md) (inferred).

### Multi-Scale Constraint
A technique using position-aware point adaptive control to apply different scales to Gaussians based on viewer distance, improving rendering of distant objects. It sets itself apart by dynamically adjusting cloning/splitting thresholds based on distance $\gamma(\mu)$. Choose this for large-scale scenes with significant depth variation. Link: [Multi-Scale Constraint](12929-multi-scale-constraint.md) (inferred).

### LS-Gaussian Viewpoint Transformation
An algorithm that leverages inter-frame continuity for efficient sparse rendering by transforming the viewpoint between consecutive frames, rather than rendering each frame separately. It sets itself apart by operating at the tile/Gaussian level to enable sparse rendering, reducing preprocessing costs. Choose this for real-time rendering of continuous video streams. Link: [LS-Gaussian Viewpoint Transformation](12930-ls-gaussian-viewpoint-transformation.md) (inferred).

### [3D Gaussian Splatting Training Loop](15139-3d-gaussian-splatting-training-loop.md)
The core per-image error computation and gradient descent loop. It sets itself apart by using a fixed iteration budget (30,000) and a specific loss blend (0.8 L1 + 0.2 SSIM). Choose this as the baseline training strategy. Link: [3D Gaussian Splatting Training Loop](12931-3d-gaussian-splatting-training-loop.md) (inferred).

### Camera Localisation for Convergence Basin
Localizes camera pose by minimizing photometric error against a ground-truth image while fixing the Gaussian initialization. It sets itself apart by providing a robust initialization for SLAM tasks. Choose this when camera poses are unknown or inaccurate. Link: [Camera Localisation for Convergence Basin](12932-camera-localisation-for-convergence-basin.md) (inferred).

### DiffGS Framework
Applies an optimization process during Gaussian extraction to optimize Gaussians to exact locations using a Gaussian Probability Function (GauPF). It sets itself apart by introducing a truncation function $\lambda$ and projection function $\tau$ to improve PSNR/SSIM metrics. Choose this for high-fidelity reconstruction. Link: [DiffGS Framework](12933-diffgs-framework.md) (inferred).

### Opacity Offset Table for DSA
Constructs an opacity offset table to model changes in digital subtraction angiography. It sets itself apart by handling dynamic opacity changes in medical imaging. Choose this for dynamic medical volume rendering. Link: [Opacity Offset Table for DSA](12934-opacity-offset-table-for-dsa.md) (inferred).

### Resolution Guided Primitive Scheduler
Schedules primitive growth using a concave-up function to suppress early growth and encourage mid-stage growth, mitigating poor convergence at the end of optimization. It sets itself apart from naive scheduling by using a momentum-based budget $P_{fin}^{(i)} = \max(P_{fin}^{(i-1)}, \gamma \cdot P_{fin}^{(i-1)} + \eta \cdot P_{add})$. Choose this for faster convergence. Link: [Resolution Guided Primitive Scheduler](12935-resolution-guided-primitive-scheduler.md) (inferred).

### Conditional Splat Approximation
Approximates the influence range of a 3D Gaussian on a slice by using a 2D ellipse splat scaled by the marginal factor. It sets itself apart by providing an accurate and efficient approximation of 3D Gaussian iso-probability contours. Choose this for slice-based rendering or tomographic reconstruction. Link: [Conditional Splat Approximation](12936-conditional-splat-approximation.md) (inferred).

## Operating characteristics

*   **Time Complexity**: $O(N \cdot M)$ per iteration, where $N$ is the number of pixels and $M$ is the number of Gaussians. The sorting step is $O(M \log M)$ per tile [6233-optimization-and-parallelization].
*   **Memory Complexity**: $O(M)$ to store Gaussian parameters. For SH Degree 1, each Gaussian requires $3 + 4 + 3 + 1 + 12 = 23$ floats [S3].
*   **Measured Performance**: On a standard GPU, 30,000 iterations take several hours to days depending on scene complexity and resolution [S9, unofficial].
*   **Strengths**: Fast training convergence, high-quality novel view synthesis, explicit representation allows for easy manipulation [S9, unofficial].
*   **Limitations**: High memory usage for large scenes, sensitive to initialization and hyperparameters (e.g., scene extent) [S4].
*   **When to Use**: When high-fidelity novel view synthesis is required and computational resources are available for training.
*   **When Not to Use**: When real-time training is required, or when memory is severely constrained without compression techniques [12943-data-compression-and-storage-optimization.md].

## Background

3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1][S9, unofficial]. It builds on the idea of representing scenes as explicit Gaussian primitives, allowing for real-time rendering via differentiable rasterization. The method was developed to address the slow training and rendering speeds of NeRF-based methods [S9, unofficial]. The implementation details described here are based on the original paper and subsequent community implementations (e.g., gsplat) [S2, S3].
