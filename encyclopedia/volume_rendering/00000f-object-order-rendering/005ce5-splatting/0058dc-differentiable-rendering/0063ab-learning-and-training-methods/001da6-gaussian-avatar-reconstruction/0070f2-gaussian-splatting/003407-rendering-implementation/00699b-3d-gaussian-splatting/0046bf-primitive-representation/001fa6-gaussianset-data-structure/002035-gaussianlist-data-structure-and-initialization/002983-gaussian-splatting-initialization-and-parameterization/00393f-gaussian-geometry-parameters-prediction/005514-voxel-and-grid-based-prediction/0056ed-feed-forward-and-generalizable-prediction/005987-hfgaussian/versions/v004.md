# HFGaussian

Also called: Human Feature Gaussian

## Overview
HFGaussian is a generalizable, feed-forward framework for real-time 3D human avatar reconstruction that simultaneously estimates novel views, 3D pose, and integrated biomechanical features (such as dense pose and continuous surface embeddings) from sparse input images [S1]. Unlike standard 3D Gaussian Splatting methods that require per-subject optimization or rely on parametric body models like SMPL, HFGaussian predicts Gaussian parameters directly from image features without fine-tuning on unseen data [S1]. It distinguishes itself by decoupling photometric rendering from feature estimation: while standard Gaussians handle color and geometry, separate optimized feature parameters are splatted and decoded to represent high-frequency biomechanical attributes, overcoming the performance constraints of parameterizing all features with the same Gaussian opacity and scaling [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** Two sparse source views, $I_l$ and $I_r$ (RGB images of size $H \times W$), representing the left and right nearest neighbors to the target view [S1].
*   **Outputs:**
    *   A set of 3D Gaussians $G = \{X, c, r, s, \alpha, f\}$, where $X$ is position, $c$ is color, $r$ is rotation, $s$ is scaling, $\alpha$ is opacity, and $f$ is the human feature vector [S1].
    *   Rendered novel view RGB images.
    *   Estimated 3D pose (19 keypoints) and dense pose (continuous surface embeddings) [S1].

**Data Structures:**
*   **Gaussian Set:** Each Gaussian $i$ is defined by:
    *   $X_i \in \mathbb{R}^3$: 3D position.
    *   $c_i \in \mathbb{R}^3$: RGB color.
    *   $r_i \in \mathbb{R}^4$: Rotation quaternion.
    *   $s_i \in \mathbb{R}^3$: Scaling factors.
    *   $\alpha_i \in [0, 1]$: Opacity.
    *   $f_i \in \mathbb{R}^k$: Human feature vector (dimension $k$ depends on the feature type, e.g., dense pose embeddings) [S1].
*   **Gaussian Parameter Maps:** The scene is represented on 2D planes via maps $G(x) = \{M_p(x), M_c(x), M_r(x), M_s(x), M_\alpha(x), M_f(x)\}$ for foreground pixel coordinates $x$ [S1].

**Algorithm Steps:**

1.  **Feature Encoding:**
    Feed $I_l$ and $I_r$ into a shared image encoder $\epsilon_{img}$ to generate multiscale image features $f_l^s$ and $f_r^s$, where $s$ denotes the feature scale [S1].

2.  **Cost Volume and Depth Estimation:**
    *   Generate a cost volume $C$ by correlating the feature maps $f_l^s$ and $f_r^s$ [S1].
    *   Use an iterative update mechanism on $C$ to estimate depth maps $D_l$ and $D_r$ for the left and right views, respectively [S1].

3.  **Gaussian Feature Generation:**
    *   Encode the depth maps $D_l, D_r$ using a depth encoder $\epsilon_{depth}$ [S1].
    *   Combine the encoded depth features with the image features $f_l^s, f_r^s$ (concatenation $\oplus$) and pass them through a U-Net-like decoder $\epsilon_{params}$ to generate a Gaussian feature map $\Gamma$ [S1]:
        $$ \Gamma = \epsilon_{params}(\epsilon_{img}(I) \oplus \epsilon_{depth}(I)) $$
    *   Apply four separate convolutional prediction heads to $\Gamma$ to estimate parameter maps:
        *   Rotation $M_r$
        *   Scaling $M_s$
        *   Opacity $M_\alpha$
        *   Human Feature $M_f$ [S1]
    *   The human feature map is defined as:
        $$ M_f = \text{Sigmoid}(h_f(\Gamma(x))) $$
        where $h_f$ is the feature head and $x$ is the foreground pixel coordinate [S1].

4.  **3D Gaussian Construction:**
    *   **Position ($X$):** Map 2D pixel coordinates $x$ to 3D space using the predicted depth and known camera parameters via map $M_p$ [S1].
    *   **Color ($c$):** Directly sample RGB color values from the source images using map $M_c$ [S1].
    *   **Rotation, Scaling, Opacity:** Retrieve from $M_r, M_s, M_\alpha$ [S1].
    *   **Feature ($f$):** Retrieve from $M_f$ [S1].

5.  **Pose Regression (Optional/Parallel Branch):**
    *   Generate point clouds $P_l, P_r$ from depth maps $D_l, D_r$ and camera parameters [S1].
    *   Extract human point clouds using 2D masks and combine them into a single point cloud [S1].
    *   Randomly sample 2048 points to form $P_c$ [S1].
    *   Input $P_c$ into a pose regression network (based on DGCNN and PointNet) to estimate 3D pose (19 keypoints) [S1].

6.  **Feature Splatting and Rendering:**
    *   **Projection:** Project 3D Gaussians into 2D space. The 2D covariance matrix $\Sigma'$ is calculated as:
        $$ \Sigma' = J W \Sigma W^T J^T $$
        where $\Sigma$ is the 3D covariance matrix (derived from $r$ and $s$), $W$ is the view transformation matrix, and $J$ is the Jacobian of the affine approximation of the projective transform [S1].
    *   **Feature Blending:** Estimate human feature vectors $f_p$ by splatting Gaussian features $f_i$ in the image plane and blending using alpha composition:
        $$ f_p = \sum_{i \in N} \left( f_i \alpha_i' \prod_{j=1}^{i-1} (1 - \alpha_j') \right) $$
        where $N$ is the set of splatted Gaussians, and $\alpha_i' = \alpha_i \cdot \text{2D Gaussian}(x)$ [S1].
    *   **Feature Decoding:** Decode the blended feature vectors $f_p$ using an MLP with two linear layers (ReLU activation) followed by a final sigmoid layer to render continuous surface embeddings [S1].
    *   **Color Rendering:** Render final pixel colors $C$ using alpha blending:
        $$ C = \sum_{i \in N} \left( c_i \alpha_i' \prod_{j=1}^{i-1} (1 - \alpha_j') \right) $$
        where $c_i$ is the learned color [S1].

**Training:**
The model is trained in two stages:
1.  **Depth Estimation:** Train the depth estimator module on both source views for 40,000 iterations [S1].
2.  **Joint Training:** Jointly train the Gaussian parameter estimator, feature estimator MLP, and 3D pose estimator for 100,000 iterations [S1].

**Loss Function:**
The combined loss is:
$$ L = L_{image} + L_{depth} + L_{pose} + L_{feature} $$
*   $L_{image} = \beta L_{MAE} + \gamma L_{SSIM}$ with $\beta=1.6, \gamma=0.4$ [S1].
*   $L_{depth} = \sum_{t=1}^{T} \mu^{T-t} \|d_{gt} - d_t\|_1$ with $\mu=0.9$ [S1].
*   $L_{pose}$: L2 loss between ground truth and estimated 3D keypoints [S1].
*   $L_{feature}$: L1 loss between ground truth and predicted human features (continuous surface embeddings) [S1].

**Parameters:**
*   Optimizer: AdamW [S1].
*   Learning Rate: $2 \times 10^{-4}$ [S1].
*   Weight Decay: $1 \times 10^{-5}$ [S1].
*   Batch Size: 4 [S1].
*   Resolution: $512 \times 512$ [S1].
*   Source Views: 8 images at 45-degree intervals [S1].
*   Target Views: 3 random viewpoints [S1].
*   Keypoints: 19 (nose, neck, shoulders, elbows, wrists, pelvis, hips, knees, ankles, eyes, ears) [S1].

## Operating characteristics
*   **Performance:** Achieves a PSNR of 32.43 on novel view synthesis, closely matching GPS-Gaussian's 32.55 [S1].
*   **Speed:** Renders at 25 FPS [S1].
*   **Generalization:** Generalizes to unseen human data without per-subject fine-tuning or optimization [S1].
*   **Strengths:** Simultaneously renders RGB, 3D pose, and biomechanical features (dense pose) in real time; does not rely on parametric body models (SMPL/STAR) during inference [S1].
*   **Limitations:** Requires sparse input views (typically 2 nearest neighbors for inference, trained on 8 views) [S1]. Performance on complex occlusions or extreme poses depends on the quality of the initial depth estimation and the generalization capability of the backbone [S1].
*   **Hardware:** Implemented using PyTorch; training takes ~14 hours on the dataset [S1].

## Background
HFGaussian was introduced by Arnab Dey, Cheng-You Lu, Andrew I. Comport, Jean Martinet, Srinath Sridhar, and Chin-Teng Lin in November 2024 [S1]. It builds upon GPS-Gaussian, which provides a generalizable backbone for 3D human representation using 2D Gaussian parameter maps [S1]. The method addresses the limitations of previous approaches that either required substantial computational resources for parametric fitting (SMPL/STAR) or failed to incorporate essential biomechanical features like dense pose and 3D skeleton structure [S1]. It is applicable to augmented reality, virtual reality, entertainment, and medical domains [S1].
