# Unity Sentis Implementation for Gaussian Splats

Also called: Runtime MLP Inference via Sentis, Sentis-based Gaussian Splatting

## Overview
This method implements the rendering phase of Gaussian Avatar Reconstruction by leveraging the Unity Sentis framework to execute Multi-Layer Perceptrons (MLPs) as custom compute shaders on the GPU [S1]. It solves the problem of dynamically predicting 3D Gaussian attributes from static anchor features and a time-varying context encoding $\Psi(x)$ without CPU-GPU synchronization bottlenecks [S1]. Unlike static splatting, this approach allows for real-time appearance changes by invoking the MLP with different encodings, while maintaining a fixed memory footprint since the number of predicted Gaussians remains constant [S1].

## How it works
**Inputs:**
1. **Anchor Features:** A set of feature vectors and their corresponding 3D positions, uploaded to GPU memory at initialization [S1].
2. **Context Encoding $\Psi(x)$:** A dynamic input vector used to modulate the Gaussian attributes [S1].
3. **MLP Models:** Serialized `.sentis` models derived from `.onnx` files, representing the mapping from anchors/encoding to Gaussian parameters [S1].

**Outputs:**
1. **Compute Buffers:** Containing the predicted 3D Gaussian attributes (position, covariance, opacity, SH coefficients) [S1].
2. **Rasterized Image:** The final rendered frame passed to the standard 3D Gaussian Splatting (3DGS) renderer [S1].

**Data Structures:**
* **Anchor Data:** Pinned in GPU memory to prevent readbacks. Layout includes position $(x, y, z)$ and feature vector $f$ [S1].
* **Gaussian Attributes:** Predicted per anchor. Includes mean $\mu$, covariance $\Sigma$ (decomposed into rotation $R$ and scale $S$ via 2D screen-space eigenvalues), opacity $\alpha$, and spherical harmonics coefficients $c_{lm}$ [S1].
* **Compute Buffers:** Structured buffers holding the output of the Sentis inference, directly consumed by the rasterizer [S1].

**Steps:**
1. **Initialization:**
   1. Serialize trained MLPs from `.onnx` format to `.sentis` models [S1].
   2. Build the model graphs using the Unity Sentis framework [S1].
   3. Upload anchor features and positions to pinned GPU memory [S1].
2. **Runtime Inference (Per Frame):**
   1. Compute the context encoding $\Psi(x)$ based on the current application state [G].
   2. Invoke the Sentis model as a custom compute shader. The shader reads the pinned anchor features and the encoding $\Psi(x)$ [S1].
   3. The MLP predicts the full set of Gaussian attributes for each anchor [S1].
   4. Store the results in compute buffers [S1].
3. **Culling:**
   1. Iterate through the predicted Gaussians in the compute buffers [S1].
   2. Check the predicted opacity $\alpha$ [S1].
   3. If $\alpha < 0$, mark the Gaussian for culling (do not render) [S1]. This prevents unnecessary rendering of Gaussians that may not contribute to the current visualized modality [S1].
4. **Rendering:**
   1. Pass the valid Gaussians from the compute buffers to the standard 3DGS renderer [S1].
   2. The renderer decomposes the covariance $\Sigma$ into rotation $R$ and scale $S$ components based on 2D screen-space eigenvalues to generate tight-fitting quads, minimizing overdraw [S1].

**Pseudocode:**
```python
# Initialization
# Helper definitions: serialize_onnx_to_sentis, allocate_pinned_gpu_buffer, 
# execute_sentis_compute_shader, and standard_gaussian_rasterization are standard 
# operations for model conversion, GPU memory management, compute shader dispatch, 
# and Gaussian rasterization respectively.
sentis_models = serialize_onnx_to_sentis(onnx_files)
anchor_buffer = allocate_pinned_gpu_buffer(num_anchors)
for i in range(num_anchors):
    anchor_buffer[i].position = anchor_positions[i]
    anchor_buffer[i].features = anchor_vectors[i]

# Per-Frame Execution
def render_frame(context_encoding):
    # 1. Invoke MLP via Sentis Compute Shader
    gaussian_attributes = execute_sentis_compute_shader(
        models=sentis_models,
        anchors=anchor_buffer,
        encoding=context_encoding
    )
    
    # 2. Culling
    valid_gaussians = []
    for gauss in gaussian_attributes:
        if gauss.opacity >= 0:
            valid_gaussians.append(gauss)
            
    # 3. Rasterization
    image = standard_gaussian_rasterization(valid_gaussians)
    
    return image
```

**Parameters:**
* **Memory Allocation:** Fixed at initialization. No reallocation occurs during runtime because the number of anchors (and thus predicted Gaussians) is constant [S1].
* **Culling Threshold:** Opacity $\alpha < 0$ [S1].

**Edge Cases and Pitfalls:**
* **Negative Opacity:** Gaussians trained for specific modalities may have negative opacity in others [S1].
* **Memory Pinning:** Anchor data must be pinned in GPU memory to avoid CPU-GPU readbacks during inference [S1].

## Subtopics

### Unity VR Deployment
This variant involves deploying the Sentis-based Gaussian Splatting pipeline to a Meta Quest 3 headset to verify suitability for interactive VR navigation [S2]. The implementation uses the Unity Gaussian Splatting plugin viewer to render Gaussian environments, potentially hybridized with environment maps to remove background floaters and improve throughput [S2]. However, a critical pitfall exists: the Unity Gaussian Splatting plugin relies on compute shaders that are not natively supported by the mobile VR standalone pipeline on ARM architectures [S2]. Consequently, real-time performance is achieved by offloading rendering computation to a connected PC and streaming the output to the headset, rather than running natively on the device [S2].

## Operating characteristics
* **Memory Complexity:** Fixed at initialization. Anchor features and Gaussian attribute buffers are allocated once and reused [S1].
* **Performance:** On PC hardware, real-time performance is achievable [S2]. On mobile VR standalone hardware (ARM), native compute shader support is lacking, requiring PC offloading for real-time frame rates [S2].
* **Strengths:** No CPU-GPU readbacks for anchors; dynamic appearance changes without memory reallocation; effective culling of non-contributing Gaussians [S1].
* **Limitations:** Dependency on Unity Sentis framework; lack of native compute shader support on ARM mobile VR pipelines [S1, S2].

## Background
This method builds on the existing 3DGS rendering implementation in Unity and improvements by Kleinbeck et al. [S1]. It utilizes the Unity Sentis framework to bridge deep learning inference with real-time rendering [S1]. The approach was developed to enable real-time context translation for Gaussian Splatting in VR, allowing for dynamic avatar reconstruction and appearance changes [S1]. It was validated in the context of "Shape-Shifting Splats" and "EnvMap-GS" for VR navigation and outdoor reconstruction [S1, S2].
