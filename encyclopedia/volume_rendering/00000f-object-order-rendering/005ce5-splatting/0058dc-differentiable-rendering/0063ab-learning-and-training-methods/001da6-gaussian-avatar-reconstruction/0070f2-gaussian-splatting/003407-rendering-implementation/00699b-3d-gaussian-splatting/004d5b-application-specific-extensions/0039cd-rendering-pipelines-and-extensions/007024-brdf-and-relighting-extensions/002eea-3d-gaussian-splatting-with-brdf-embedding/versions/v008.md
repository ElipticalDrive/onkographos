# 3D Gaussian Splatting with BRDF Embedding

Also called: 3D Gaussian Splatting (3DGS), Gao et al. BRDF Embedding, Gao et al. BRDF Method

## Overview
This method extends 3D Gaussian Splatting by embedding physically based rendering (PBR) parameters into each Gaussian primitive, enabling per-point BRDF evaluation and dynamic relighting [S1][S2, unofficial]. It addresses the limitation of standard 3DGS, which bakes lighting into spherical harmonics (SH) coefficients, thereby restricting performance on reflective surfaces and preventing relighting [S1]. It is distinguished from sibling methods like [GaussianShader](8013-gaussianshader-material-model.md) by its specific embedding of incident lighting alongside material properties [S1][S2, unofficial].

## How it works
**Inputs:** A set of 3D Gaussians optimized from multi-view images; an environment map for direct lighting.
**Outputs:** A rendered image with physically based shading.

**Data Structures:**
Each Gaussian $i$ stores the following fields in addition to standard 3DGS attributes (position $\mathbf{p}$, covariance $\mathbf{\Sigma}$, opacity $\alpha$, SH coefficients for indirect lighting):
1.  **Albedo** ($\mathbf{c}_d$): A 3-component vector representing diffuse color.
2.  **Roughness** ($\alpha_r$): A scalar value controlling specular width.
3.  **Surface Normal** ($\mathbf{n}$): A 3-component unit vector.
4.  **Incident Lighting** ($\mathbf{L}_{inc}$): Parameters or coefficients representing the incoming light field, often derived from or combined with environment maps [S1][S2, unofficial].

**Steps:**
1.  **Rasterization:** Project Gaussians to screen space using the standard 3DGS projection pipeline [S1][S2, unofficial].
2.  **Shading Evaluation:** For each pixel covered by a Gaussian, evaluate the BRDF using the stored parameters:
    *   Retrieve $\mathbf{c}_d$, $\alpha_r$, $\mathbf{n}$, and $\mathbf{L}_{inc}$ for the contributing Gaussian.
    *   Compute the view direction $\mathbf{v}$ and half-vector $\mathbf{h}$ based on the camera position and light direction.
    *   Calculate the direct lighting contribution using the environment map and the BRDF model (e.g., GGX) [S1][S2, unofficial].
    *   Calculate the indirect lighting contribution using the stored SH coefficients [S1][S2, unofficial].
3.  **Compositing:** Alpha-composite the shaded colors from front to back, similar to standard 3DGS, but using the physically based color values instead of emission colors [S1][S2, unofficial].

**Parameters:**
*   **Environment Map Resolution:** Not given in the sources.
*   **SH Degree for Indirect Lighting:** Not given in the sources.

**Edge Cases:**
*   **Precision:** Standard floating-point precision is assumed for BRDF calculations [G].
*   **Boundaries:** Gaussians at object boundaries may have inaccurate normals if not properly constrained during optimization [G].

### [3DGS-DR](1471-3dgs-dr.md)
Incorporates classical reflection and shading concepts into 3DGS, addressing the emission-absorption limitation of standard 3DGS. Choose when classical shading models are preferred over full PBR embedding.

## Operating characteristics
*   **Time Complexity:** Higher than standard 3DGS due to per-pixel BRDF evaluation and environment map lookups [S1][S2, unofficial].
*   **Memory Complexity:** Increased storage per Gaussian for albedo, roughness, normal, and incident lighting parameters [S1][S2, unofficial].
*   **Strengths:** Enables dynamic relighting and accurate rendering of reflective surfaces [S1][S2, unofficial].
*   **Limitations:** Requires more complex optimization and storage; performance depends on environment map resolution [S1][S2, unofficial].
*   **When to use:** Scenes requiring dynamic lighting or high-fidelity reflections.
*   **When not to use:** Static lighting scenarios where standard 3DGS suffices.

## Background
Originated from work by Gao et al., this method embeds BRDF parameters into Gaussians to enable per-point physically based rendering [S1][S2, unofficial]. It builds on the 3DGS framework by integrating classical reflection and shading concepts [S1][S2, unofficial].
