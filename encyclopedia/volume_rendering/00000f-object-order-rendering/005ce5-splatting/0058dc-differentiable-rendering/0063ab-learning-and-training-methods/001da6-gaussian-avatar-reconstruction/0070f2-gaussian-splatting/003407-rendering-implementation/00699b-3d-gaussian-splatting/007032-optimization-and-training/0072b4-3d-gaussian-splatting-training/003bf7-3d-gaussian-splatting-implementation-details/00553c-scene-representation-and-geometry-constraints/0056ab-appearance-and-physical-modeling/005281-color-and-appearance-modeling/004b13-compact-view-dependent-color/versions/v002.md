# Compact View-dependent Color
Also called: Grid-based Neural Field for Color

## Overview
Compact View-dependent Color replaces per-Gaussian Spherical Harmonics (SH) coefficients with a shared grid-based neural field to represent view-dependent color, reducing parameters from 48 per Gaussian to a compact shared representation [S1, S2]. Unlike sibling methods that apply post-processing transformations [DAVIGS](12021-davigs.md), factorize illumination [3iGS](13977-3igs-factorised-tensorial-illumination-for-3d-gaussian-splat.md), or use image-conditioned modulation [SWAG](14315-swag-splatting-in-the-wild-images-with-appearance-conditione.md), this method substitutes directional encoding with a spatial-hash-based MLP, addressing disk space explosion from high-order SH storage [S2].

## How it works
**Inputs and Outputs:**
*   **Input:** 3D position $\mathbf{p}_n \in \mathbb{R}^3$ and view direction $\mathbf{d} \in \mathbb{R}^3$ for a specific Gaussian $n$ [S1, S3].
*   **Output:** View-dependent color $\mathbf{c}_n(\mathbf{d}) \in \mathbb{R}^3$ [S1].

**Data Structures:**
1.  **Hash Grid:** A sparse hash table mapping contracted 3D coordinates to feature vectors [S3].
2.  **Tiny MLP:** A small multi-layer perceptron $f(\cdot; \theta)$ that takes positional features and view direction to predict RGB color [S1].
3.  **Gaussian Attributes:** Each Gaussian $i$ stores the contracted 3D position $\mathbf{x}_{\text{encoding}}^{(i)}$, covariance matrix $\boldsymbol{\Sigma}_i$, base opacity $\alpha_i$, and retrieves color $\mathbf{c}_i$ from the neural field [S2]. The Gaussian no longer stores SH coefficients [S1].

**Numbered Steps:**
1.  **Contraction:** Map the unbounded 3D position $\mathbf{p}_n$ to a bounded range using the mip-NeRF 360 contraction function [S1]:
    $$
    \text{contract}(\mathbf{p}_n) = 
    \begin{cases} 
    \mathbf{p}_n & \text{if } \|\mathbf{p}_n\| \le 1 \\
    \frac{\mathbf{p}_n}{\|\mathbf{p}_n\|} (2 - \|\mathbf{p}_n\|) & \text{if } \|\mathbf{p}_n\| > 1
    \end{cases}
    $$
    Let $\mathbf{p}'_n = \text{contract}(\mathbf{p}_n)$ [S1].
2.  **Hash Encoding:** Query the hash grid using $\mathbf{p}'_n$ to retrieve a positional feature vector $\mathbf{f}_{\text{pos}}$ [S3].
3.  **Color Prediction:** Compute the view-dependent color using the tiny MLP [S1]:
    $$
    \mathbf{c}_n(\mathbf{d}) = f(\mathbf{p}'_n, \mathbf{d}; \theta)
    $$
4.  **Base Color Initialization:** Use 0-degree SH components (constant color, same channels as RGB) converted to RGB as a base term, which improves performance over direct RGB representation [S1].

**Parameters:**
*   **Hash Grid Resolution/Size:** Not given in the sources.
*   **MLP Architecture:** Described as "tiny" [S1]. Specific layer sizes and activation functions are not given in the sources.
*   **Contraction Function:** Standard mip-NeRF 360 contraction [S1].

**Edge Cases and Pitfalls:**
*   **Unbounded Space:** The contraction function is critical to handle unbounded scenes; without it, hash grid queries for distant points would be invalid or require infinite grid size [S1].
*   **Precision:** The contraction maps large coordinates to the unit sphere boundary, potentially losing fine-grained positional detail for very distant points [S1].

## Subtopics

### DAVIGS
Applies a learned affine transformation to the rendered image based on 3D position and view embedding [G]. Choose when you want to preserve per-Gaussian SH but correct global color shifts. [DAVIGS](12021-davigs.md)

### 3iGS (Factorised Tensorial Illumination)
Separates scene lighting (tensor grid) from material properties (BRDF features) to model specular effects [G]. Choose when modeling specular effects and complex lighting is required. [3iGS](13977-3igs-factorised-tensorial-illumination-for-3d-gaussian-splat.md)

### Spherical Harmonics Optimization
Optimizes the SH coefficients directly or reduces their degree [G]. Choose when you need standard view-dependent shading without neural network overhead. [Spherical Harmonics Optimization](14206-spherical-harmonics-optimization.md)

### SWAG
Uses an MLP and per-image embeddings to modulate color and opacity [G]. Choose when handling transient objects or appearance synthesis across different images. [SWAG](14315-swag-splatting-in-the-wild-images-with-appearance-conditione.md)

## Operating characteristics
*   **Time Complexity:** Rendering time depends on the hash grid lookup and MLP inference per Gaussian [S1].
*   **Memory Complexity:** Significantly reduces memory usage compared to base 3DGS [S1, S2]. Base 3DGS uses 48 parameters (SH degree 3) per Gaussian for color [S1]. This method replaces those 48 parameters with a shared grid and MLP, storing only the base attributes and shared network weights [S1, S2].
*   **Measured Performance:** On Mip-NeRF 360, the method achieved PSNR 29.91 with training time 17m 51s and 254 fps, compared to 3DGS PSNR 29.87, 19m 22s, and 154 fps [S1].
*   **Strengths:** Reduces disk space explosion from high-order SH; improves training speed and rendering FPS; handles unbounded scenes via contraction [S1, S2].
*   **Limitations:** Relies on a neural network for color, which may introduce slight inference overhead compared to simple SH evaluation; requires careful tuning of hash grid and MLP [S1].
*   **When to use:** When disk space is a constraint, or when high-order SH causes overfitting or slow training [G].
*   **When not to use:** When maximum rendering speed is critical and SH evaluation is faster than MLP inference on the target hardware; when precise control over per-Gaussian directional shading is needed without shared field assumptions [G].

## Background
The method was introduced in [S1], motivated by the parameter inefficiency of storing 48 SH coefficients per Gaussian in standard 3D Gaussian Splatting [S1]. It draws inspiration from mip-NeRF 360's contraction function for handling unbounded spaces [S1]. A similar approach is also discussed in [S2], which highlights the reduction in disk space and the use of 0-degree SH for base color [S2].
