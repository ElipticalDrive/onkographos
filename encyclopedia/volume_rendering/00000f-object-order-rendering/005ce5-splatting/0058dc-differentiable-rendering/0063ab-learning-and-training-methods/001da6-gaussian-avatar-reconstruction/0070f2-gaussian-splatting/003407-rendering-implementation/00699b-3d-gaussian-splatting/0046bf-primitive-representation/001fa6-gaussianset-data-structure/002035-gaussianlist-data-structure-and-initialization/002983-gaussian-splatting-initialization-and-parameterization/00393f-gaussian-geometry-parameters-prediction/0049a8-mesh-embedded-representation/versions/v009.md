# Mesh-embedded representation


## Overview
Mesh-embedded representations parameterize 3D Gaussian primitives relative to an explicit canonical triangle mesh $\mathcal{M}$ to disentangle motion from appearance and enable explicit mesh editing [S2]. This family solves the problem of coherent, large-scale deformation and geometric coherence in Gaussian Splatting by tying Gaussian position, rotation, and scale to mesh geometry via barycentric embeddings or vertex parameterization, avoiding the artifacts and rigidity of implicit MLP-based skinning fields [S2]. Unlike standard 3DGS, which treats Gaussians as independent entities in free space, this approach ensures that mesh edits or animations propagate deterministically to the radiance field [S2].

## Shared principles
The core mechanism relies on parameterizing Gaussian attributes relative to a canonical triangle mesh $\mathcal{M}$ with vertices $V$, normals $n$, and faces $F$ [G].

**Embedding Definition:**
Each Gaussian $i$ is defined by an embedding tuple $E_i = \{k, u, v, d\}$ [S2]:
* $k$: Integer index of the triangle $k \in F$ in the canonical mesh.
* $(u, v)$: Barycentric coordinates within triangle $k$, constrained such that $u \ge 0, v \ge 0, u+v \le 1$.
* $d$: Scalar normal displacement along the interpolated surface normal.

**Canonical Position and Normal:**
The canonical mean $\mu_{cano}$ and normal $n_{cano}$ are computed via Phong interpolation on the canonical mesh [S2]:
$$
\mu_{cano} = \mathcal{V}(k, u, v) = u V_1 + v V_2 + (1 - u - v) V_3
$$
$$
n_{cano} = \mathcal{N}(k, u, v) = u n_1 + v n_2 + (1 - u - v) n_3
$$
where $V_j$ and $n_j$ are the vertices and per-vertex normals of triangle $k$ [S2].

**Posed State Computation:**
When the mesh is deformed by an animation function $\text{Deform}(\cdot)$, the posed position $\mu_{pose}$ is derived by applying the deformation to the displaced canonical position [S2]:
$$
\mu_{pose} = \text{Deform}(\mu_{cano} + d \cdot n_{cano})
$$
The posed rotation $q_{pose}$ and scale $s_{pose}$ are derived from mesh attributes to maintain coherence [S2]:
* **Rotation:** Per-vertex quaternions $q_1, q_2, q_3$ are interpolated using barycentric weights to get $\delta q$, which is then combined with the canonical rotation $\bar{q}$:
$$
q_{pose} = \delta q * \bar{q}, \quad \delta q = u q_1 + v q_2 + (1 - u - v) q_3
$$
* **Scale:** Scale is proportional to the area change of the embedded triangle relative to the canonical state:
$$
s_{pose} = \left( \frac{A_{pose}}{A_{cano}} \right) \bar{s}
$$
where $A_{pose}$ and $A_{cano}$ are the areas of the triangle in the posed and canonical states, respectively [S2].

**Cross-Triangle Handling:**
Barycentric coordinates are differentiable only within a single triangle. If optimization moves an embedding point across a boundary ($u < 0$, $v < 0$, or $u+v > 1$), the embedding must be re-expressed in the neighboring triangle to maintain differentiability [S2]. Failure to handle this causes Gaussians to stick to boundaries and pile up [S2].

**Pseudocode:**
```python
import numpy as np

def compute_posed_gaussian(gaussian, mesh, pose_transform):
    """
    Computes the posed position, rotation, and scale for a single Gaussian.
    
    Args:
        gaussian: Dict with keys 'k', 'u', 'v', 'd', 'q_canon', 's_canon'.
        mesh: Dict with 'faces' (list of dicts with 'vertices', 'vertex_normals', 'vertex_quaternions').
        pose_transform: Function that applies deformation to mesh vertices.
        
    Returns:
        mu_pose: Posed mean position.
        q_pose: Posed rotation quaternion.
        s_pose: Posed scale vector.
    """
    k = gaussian['k']
    u = gaussian['u']
    v = gaussian['v']
    d = gaussian['d']
    
    face = mesh.faces[k]
    V1, V2, V3 = face['vertices']
    n1, n2, n3 = face['vertex_normals']
    
    # Canonical position and normal
    mu_cano = u * V1 + v * V2 + (1 - u - v) * V3
    n_cano = u * n1 + v * n2 + (1 - u - v) * n3
    
    # Posed position
    displaced_pos = mu_cano + d * n_cano
    mu_pose = pose_transform(displaced_pos)
    
    # Posed rotation
    q1, q2, q3 = face['vertex_quaternions']
    delta_q = u * q1 + v * q2 + (1 - u - v) * q3
    q_pose = delta_q * gaussian['q_canon']
    
    # Posed scale
    V1_pose, V2_pose, V3_pose = pose_transform(V1), pose_transform(V2), pose_transform(V3)
    A_pose = 0.5 * np.linalg.norm(np.cross(V2_pose - V1_pose, V3_pose - V1_pose))
    A_cano = 0.5 * np.linalg.norm(np.cross(V2 - V1, V3 - V1))
    s_pose = (A_pose / A_cano) * gaussian['s_canon']
    
    return mu_pose, q_pose, s_pose
```

## Subtopics

### [Mesh-Embedded Gaussian Splatting](9553-mesh-embedded-gaussian-splatting.md)
A hybrid representation that defines 3D Gaussians over an explicit canonical triangle mesh to enable large-scale, interactive deformations. It sets itself apart by explicitly controlling Gaussian pose through mesh warping, enabling compatibility with skeletal animation and direct mesh editing without relying on implicit MLP-based skinning fields. Choose when coherent motion transfer and explicit mesh editing are required.

### [Mesh-Embedded Gaussian Initialization and Deformation](9559-mesh-embedded-gaussian-initialization-and-deformation.md)
This method initializes and deforms 3D Gaussians by anchoring them to a canonical triangle mesh using barycentric coordinates and normal displacement. It sets itself apart by defining a local triangle space to ensure robust results even with inaccurate meshes, tracking Gaussians through mesh topology rather than direct vertex positions. Choose when maintaining geometric coherence during mesh deformation is needed.

### [GaMeS (Gaussian Mesh Splatting)](12542-games-gaussian-mesh-splatting.md)
GaMeS integrates 3DGS with mesh-based parameterization, allowing Gaussian components to be modified and deformed in the same manner as a traditional triangle mesh. It sets itself apart by providing a direct, one-stage parameterization that supports real-time editing and animation, unlike methods relying on expensive pre-processing or SDF regularization. Choose for direct mesh editing and animation.

### [SuGaR / Gaussian Frosting](13542-sugar-gaussian-frosting.md)
SuGaR and Gaussian Frosting extract a canonical triangle mesh from an optimized 3DGS scene to enable explicit mesh editing while preserving high-fidelity rendering. They set themselves apart by combining the editing capabilities of explicit meshes with differentiable Gaussian splatting via an adaptive Gaussian layer with variable thickness. Choose when extracting editable meshes from optimized Gaussians is needed.

### [Mesh to DRK Conversion](13700-mesh-to-drk-conversion.md)
Mesh to DRK Conversion is a training-free procedure that converts traditional triangle and polygon mesh faces into Deformable Radial Kernel (DRK) primitives for seamless integration into radiance field scenes. It sets itself apart by providing a direct, deterministic mapping that eliminates the need for training data rendering or model optimization. Choose for converting traditional 3D assets to splatting representations.

### [Gaussian Extraction Algorithm](15577-gaussian-extraction-algorithm.md)
The Gaussian Extraction Algorithm extracts discrete 3D Gaussian primitives from continuous Gaussian Splatting Functions at arbitrary densities. It sets itself apart by using an octree-guided progressive sampling strategy to locate high-probability regions, followed by gradient-based optimization of proxy points, rather than fixed-grid voxelization or direct mesh embedding. Choose when converting continuous neural fields to discrete Gaussians is needed.

### [GauMesh](17295-gaumesh.md)
GauMesh combines tracked textured meshes with canonical 3D Gaussians and a learnable deformation field for dynamic human head avatars. It sets itself apart by introducing a learnable deformation field rather than relying solely on rigid or skeletal mesh transforms. Choose for dynamic avatar synthesis from few views.

### [MiraGe](20016-mirage.md)
MiraGe edits 2D images by temporarily interpreting selected regions as 3D objects via Gaussian Splatting. It sets itself apart by using the source image as a strict reference for explicit 3D reconstruction rather than synthesizing new content, and from Implicit Neural Representations by providing addressable Cartesian coordinates. Choose for intuitive 2D image editing with 3D manipulation.

### GauS (Gaussian Splatting Surface Reconstruction)
GauS is a render-then-fuse approach for high-fidelity mesh reconstruction from 3DGS inputs without fine-tuning. It sets itself apart by converting optimized Gaussians directly into textured meshes as a plug-and-play solution, unlike NeRF-based re-training or further fine-tuning required for explicit surface modeling in other methods. Choose for explicit surface modeling from 3DGS.

### Deformation Transfer via ACAP
This method transfers mesh deformation to 3D Gaussians by calculating vertex transformations using ACAP, interpolating them via barycentric coordinates, and averaging transformations across 8 bound faces. It sets itself apart by using Gaussian-centric binding and averaging operations for robust deformation transfer. Choose for transferring cage or box deformations to Gaussians.

## Background
The concept of embedding Gaussian primitives onto explicit geometry emerged to address the limitations of free-space 3DGS in handling dynamic scenes and editable assets [S2]. Early works introduced barycentric parameterization to tie Gaussians to canonical meshes for animation [S2]. Subsequent developments refined this by aligning Gaussians to reconstructed surfaces or extracting meshes from optimized Gaussians, enabling hybrid rendering and editing [S2]. The family also includes training-free conversions and neural-to-discrete extraction methods, expanding the applicability of mesh-embedded concepts to broader radiance field representations [S2].
