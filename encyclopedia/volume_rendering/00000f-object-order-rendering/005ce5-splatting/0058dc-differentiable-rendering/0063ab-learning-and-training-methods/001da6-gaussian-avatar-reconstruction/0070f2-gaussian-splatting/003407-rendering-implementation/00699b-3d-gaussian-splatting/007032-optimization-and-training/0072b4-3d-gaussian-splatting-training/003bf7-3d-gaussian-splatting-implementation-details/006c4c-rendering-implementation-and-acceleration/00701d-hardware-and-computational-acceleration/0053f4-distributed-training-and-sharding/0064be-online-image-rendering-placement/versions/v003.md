# Online Image Rendering Placement

Also called: Image patch placement, Online placement of image rendering

## Overview
Online Image Rendering Placement is a distributed training optimization method that dynamically assigns image patches to GPUs at each training iteration to minimize inter-node communication and balance computational load [S1, unofficial]. It distinguishes itself from static partitioning schemes by solving an Integer Linear Programming (ILP) problem online using a fast heuristic (Linear Sum Assignment followed by local search) rather than an offline solver, allowing it to adapt to the random batch selection inherent in stochastic gradient descent [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Inputs:**
    *   $B$: Batch size of training images (typically 16–64) [S1, unofficial].
    *   $N$: Number of GPUs in the cluster [S1, unofficial].
    *   $H, W$: Resolution of each training image [S1, unofficial].
    *   $p$: Patch granularity factor (typically 2–8), dividing each image into $p^2$ patches of size $H_p \times W_p$ [S1, unofficial].
    *   $\alpha, \beta, \gamma, \delta$: Configurable coefficients for the objective function [S1, unofficial].
    *   Local 3D Gaussian primitives stored on each GPU (defined by mean $\mu$, covariance $\Sigma$, opacity $\alpha$, and color) [S1, unofficial].
*   **Outputs:**
    *   $W$: A placement vector where $W_j$ denotes the GPU ID assigned to render image patch $j$ [S1, unofficial].

**Data Structures**
*   **Patch-GPU Access Pattern Matrix ($A$):** A $B \times N$ matrix where $A_{j,k}$ represents the number of 3D Gaussian points required from GPU $k$ to render image patch $j$. This matrix is constructed by exchanging frustum culling results across all GPUs [S1, unofficial].

**Algorithm Steps**
1.  **Frustum Culling:** At each training iteration, every GPU receives the entire batch of $B$ image patches. Each GPU performs frustum culling against its locally stored 3D Gaussian primitives to determine which points are visible for each patch [S1, unofficial].
2.  **Access Pattern Construction:** All GPUs exchange their culling results to build the global access pattern matrix $A$, where $A_{j,k}$ is the count of points needed from GPU $k$ for patch $j$ [S1, unofficial].
3.  **Initial Placement (LSA):** Solve a Linear Sum Assignment (LSA) problem to find an initial placement $W_{init}$ that minimizes total communication volume. This is solved using the Hungarian method with time complexity $O(B^3)$ [S1, unofficial]. The LSA objective minimizes:
    $$ \sum_{j=1}^{B} \sum_{k=1}^{N} A_{j,k} \cdot \mathbb{I}(W_j \neq k) $$
    subject to the constraint that each GPU is assigned exactly $B/N$ patches:
    $$ \sum_{j=1}^{B} \mathbb{I}(W_j = k) = \frac{B}{N}, \quad \forall k \in \{1, \dots, N\} $$
    where $\mathbb{I}(\cdot)$ is the indicator function [S1, unofficial].
4.  **Local Search Refinement:** Iteratively refine $W_{init}$ using a greedy steepest-ascent strategy. In each step, swap the GPU assignments of two image patches if it improves the relaxed objective function. Continue until convergence or a time budget is reached [S1, unofficial].
5.  **Hierarchical Assignment (Optional):** For multi-node clusters, first assign patches across machines, then assign a machine's patches among its local GPUs. For intra-node assignment, set $\alpha = 0$ to de-prioritize communication volume, as intra-node bandwidth is high [S1, unofficial].

**Formulas**
The optimization aims to minimize a weighted sum of communication and compute imbalances. The loads for GPU $k$ are defined as:

*   **Send Load:** The number of points GPU $k$ must send to other GPUs for patches assigned to it.
    $$ \text{send}_k = \sum_{j=1}^{B} \mathbb{I}(W_j \neq k) \cdot A_{j,k} $$
*   **Receive Load:** The number of points GPU $k$ must receive from other GPUs for patches assigned to it.
    $$ \text{recv}_k = \sum_{j=1}^{B} \mathbb{I}(W_j = k) \cdot \left( \sum_{i=1}^{N} A_{j,i} - A_{j,k} \right) $$
*   **Compute Load:** The total number of points GPU $k$ must process for patches assigned to it.
    $$ \text{comp}_k = \sum_{j=1}^{B} \mathbb{I}(W_j = k) \cdot \sum_{i=1}^{N} A_{j,i} $$

The relaxed objective function used in local search to avoid plateaus caused by non-smooth max terms is:
$$ \beta \cdot \|\text{send}\|_p + \gamma \cdot \|\text{recv}\|_p + \delta \cdot \|\text{comp}\|_p $$
where $\|\text{send}\|_p = \left( \sum_{k=1}^{N} \text{send}_k^p \right)^{1/p}$, and similarly for $\|\text{recv}\|_p$ and $\|\text{comp}\|_p$ [S1, unofficial].

**Pseudocode**

```python
def online_image_rendering_placement(A, B, N, p_norm=2, time_budget=0.1):
    """
    A: Access pattern matrix of shape (B, N). A[j, k] is points needed from GPU k for patch j.
    B: Batch size (number of patches).
    N: Number of GPUs.
    p_norm: p-norm exponent for load balancing (default 2).
    time_budget: Max seconds for local search.
    Returns: W, placement vector of shape (B,) where W[j] is GPU ID.
    """
    # Step 1: Linear Sum Assignment (LSA) for initial placement
    # Minimize total communication: sum(A[j, k] for all j, k where W[j] != k)
    # Subject to: each GPU gets exactly B/N patches.
    # This is equivalent to maximizing sum(A[j, k] for all j, k where W[j] == k)
    # because total points is constant.
    
    # Create cost matrix for Hungarian algorithm.
    # We want to maximize communication saved (points accessed locally).
    # Cost[i, j] = -A[i, j] (negative because Hungarian minimizes)
    cost_matrix = -A
    
    # Hungarian algorithm returns row assignments (patch index) to column assignments (GPU index)
    # Assuming B is divisible by N and we need balanced assignment.
    # Standard Hungarian assumes 1-to-1. Here we have B patches to N GPUs with capacity B/N.
    # We expand the problem: Create a bipartite graph with B patches on left, 
    # and N* (B/N) = B "GPU slots" on right.
    # However, the source states LSA solves the ILP constraints directly.
    # Implementation detail: Use a library or implement Hungarian on expanded matrix.
    # For clarity, we assume a function `solve_lsa(cost_matrix, B, N)` exists 
    # that returns W_init minimizing sum(A[j, W[j]]) subject to load balance.
    
    W = solve_lsa(cost_matrix, B, N)
    
    # Step 2: Local Search Refinement
    start_time = time.time()
    improved = True
    while improved and (time.time() - start_time) < time_budget:
        improved = False
        # Try all pairs of patches to swap
        for i in range(B):
            for j in range(i + 1, B):
                # Current assignment
                gpu_i = W[i]
                gpu_j = W[j]
                
                # Calculate current objective contribution of these two patches
                # We only need to check if swapping improves the global objective.
                # Global Objective = beta * ||send||_p + gamma * ||recv||_p + delta * ||comp||_p
                
                # Calculate loads for all GPUs before swap
                send_before = compute_send_loads(W, A, B, N)
                recv_before = compute_recv_loads(W, A, B, N)
                comp_before = compute_comp_loads(W, A, B, N)
                
                obj_before = (beta * norm_p(send_before, p_norm) + 
                              gamma * norm_p(recv_before, p_norm) + 
                              delta * norm_p(comp_before, p_norm))
                
                # Swap assignments
                W[i], W[j] = gpu_j, gpu_i
                
                # Calculate loads after swap
                send_after = compute_send_loads(W, A, B, N)
                recv_after = compute_recv_loads(W, A, B, N)
                comp_after = compute_comp_loads(W, A, B, N)
                
                obj_after = (beta * norm_p(send_after, p_norm) + 
                             gamma * norm_p(recv_after, p_norm) + 
                             delta * norm_p(comp_after, p_norm))
                
                # Steepest ascent: if new objective is lower (better), keep swap
                if obj_after < obj_before:
                    improved = True
                    # Continue searching with new W
                    # Note: In a true steepest-ascent, we might pick the best swap.
                    # Here we accept the first improving swap (greedy).
                    break 
            if improved:
                break
                
    return W

def compute_send_loads(W, A, B, N):
    send = [0] * N
    for j in range(B):
        k = W[j]
        for i in range(N):
            if i != k:
                send[k] += A[j, i] # Wait, definition: send_k is points sent FROM k TO others.
                # Source: send_k = sum_{j} [W_j != k] * A_{j,k}
                # This is points needed FROM k for patches NOT assigned to k.
                pass
    # Correct implementation based on source formula:
    send = [0] * N
    for k in range(N):
        for j in range(B):
            if W[j] != k:
                send[k] += A[j, k]
    return send

def compute_recv_loads(W, A, B, N):
    recv = [0] * N
    for k in range(N):
        for j in range(B):
            if W[j] == k:
                # Points needed from others = Total points for patch j - Points from k
                total_points_j = sum(A[j, i] for i in range(N))
                recv[k] += (total_points_j - A[j, k])
    return recv

def compute_comp_loads(W, A, B, N):
    comp = [0] * N
    for k in range(N):
        for j in range(B):
            if W[j] == k:
                comp[k] += sum(A[j, i] for i in range(N))
    return comp

def norm_p(vector, p):
    return sum(x**p for x in vector)**(1/p)
```

**Parameters**
*   $\alpha$: Weight for total communication volume. Set to 0 for intra-node assignment [S1, unofficial].
*   $\beta, \gamma, \delta$: Weights for send, receive, and compute load imbalance, respectively [S1, unofficial].
*   $p$: Patch granularity factor (2–8) [S1, unofficial].
*   $B$: Batch size (16–64) [S1, unofficial].

**Pitfalls**
*   Using general ILP solvers (e.g., Gurobi) is too slow and unpredictable for online optimization per iteration [S1, unofficial].
*   Whole-image assignment severely limits scalability to many GPUs due to small batch sizes in training (PBDR) [S1, unofficial].
*   The non-smooth max terms in the original ILP can cause plateaus in local search; using $p$-norms mitigates this [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The Linear Sum Assignment step using the Hungarian method has a time complexity of $O(B^3)$ [S1, unofficial]. The local search step depends on the number of swaps and the time budget, but is designed to be fast enough for online use.
*   **Memory Complexity:** Requires storing the access pattern matrix $A$ of size $B \times N$ and the placement vector $W$ of size $B$ [S1, unofficial].
*   **Strengths:** Reduces inter-node communication significantly by co-locating rendering with data access. Balances computational load across GPUs. Adapts to the dynamic nature of training batches.
*   **Limitations:** Adds overhead to each training iteration. Performance depends on the quality of the heuristic.
*   **When to use:** Large-scale distributed training of 3D Gaussian Splatting where communication bandwidth is a bottleneck and batch sizes are small [S1, unofficial].

## Background
The method was introduced in the paper "Scaling Point-based Differentiable Rendering for Large-scale Reconstruction" (Gaian) [S1, unofficial]. It addresses the challenge of scaling 3D Gaussian Splatting training to large scenes and many GPUs, where static partitioning fails to account for the random batch selection and varying data access patterns of different images [S1, unofficial].
