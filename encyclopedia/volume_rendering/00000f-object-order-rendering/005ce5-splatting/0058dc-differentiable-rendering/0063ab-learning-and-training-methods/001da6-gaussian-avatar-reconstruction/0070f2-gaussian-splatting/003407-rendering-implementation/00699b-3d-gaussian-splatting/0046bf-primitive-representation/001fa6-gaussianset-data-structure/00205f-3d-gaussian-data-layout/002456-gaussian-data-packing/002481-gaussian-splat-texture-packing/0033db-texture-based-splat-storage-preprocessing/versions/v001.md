# Texture-Based Splat Storage Preprocessing

Also called: Splat Texture Generation, Gaussian Texture Packing Preprocessing

## Overview
This method preprocesses parsed 3D Gaussian splat data into a set of 32-bit floating-point RGBA textures, enabling efficient on-demand loading and rendering via GPU particle systems such as Unreal Engine's Niagara. It solves the problem of memory fragmentation and inefficient CPU-GPU transfer by organizing splat attributes (position, scale, rotation, color, and spherical harmonics) into contiguous texture resources. It differs from sibling methods like [Packed Splat Reading](6819-packed-splat-reading.md) by focusing on the *creation* and *formatting* of the storage assets rather than the *consumption* of them during the rendering pipeline.

## How it works
**Inputs and Outputs:**
*   **Input:** A list of Gaussian splats, where each splat contains position (vec3), scale (vec3), rotation (quaternion), color (RGB), opacity (scalar), and spherical harmonics coefficients.
*   **Output:** A collection of 8 separate `UTexture2D` assets (or equivalent texture objects), each with format `RGBA32F` (32-bit floating point RGBA).

**Data Structures:**
The method organizes data into a structure `FGaussianSplattingTextureData` containing the following fields, each being an array of 4-component vectors (`FLinearColor` or equivalent):
1.  `PositionTextureData`: Stores the 3D position of each splat.
2.  `ScaleTextureData`: Stores the 3D scale (size) of each splat.
3.  `RotationTextureData`: Stores the 3D rotation (quaternion) of each splat.
4.  `ColorTextureData`: Stores the base color and opacity.
5.  `HarmonicsL1TextureData`: Stores the first-order spherical harmonics coefficients.
6.  `HarmonicsL2TextureData`: Stores the second-order spherical harmonics coefficients.
7.  `HarmonicsL31TextureData`: Stores the third-order spherical harmonics coefficients (part 1).
8.  `HarmonicsL32TextureData`: Stores the third-order spherical harmonics coefficients (part 2).

**Steps:**
1.  **Initialize Texture Assets:** For each of the 8 attribute types, create a new texture asset. Configure the texture settings as follows:
    *   `SRGB`: False (linear space).
    *   `MipGenSettings`: `TMGS_NoMipmaps` (no mipmaps generated).
    *   `Compression`: `None` (lossless floating-point storage).
    *   `Filter`: `TF_Nearest` (nearest-neighbor filtering to preserve exact values).
2.  **Set Source Format:** Set the internal texture source format to `TSF_RGBA32F` (32-bit floating point RGBA).
3.  **Populate Data Arrays:** Convert the raw splat data into arrays of 4-component vectors (`FLinearColor` or `vec4`) matching the layout defined in `FGaussianSplattingTextureData`.
    *   *Note:* The exact mapping of splat fields to RGBA channels is implementation-specific but generally follows the order: Position (XYZ + padding/unused), Scale (XYZ + padding), Rotation (XYZW), Color (RGB + Opacity), etc.
4.  **Lock and Copy:** For each texture, lock the memory of Mip Level 0. Copy the corresponding data array into the locked memory using a bulk memory copy operation (e.g., `FMemory::Memcpy`).
5.  **Unlock and Update:** Unlock the memory and trigger a resource update to make the texture available to the GPU.

**Pseudocode:**
```python
def preprocess_splats_to_textures(splats: List[Splat]) -> Dict[str, Texture2D]:
    """
    Converts a list of splats into 8 RGBA32F textures.
    """
    textures = {}
    
    # Define the 8 required textures
    texture_names = [
        "Position", "Scale", "Rotation", "Color",
        "HarmonicsL1", "HarmonicsL2", "HarmonicsL31", "HarmonicsL32"
    ]
    
    for name in texture_names:
        # 1. Create Texture Asset
        tex = create_texture2d()
        tex.srgb = False
        tex.mip_gen = TMGS_NoMipmaps
        tex.compression = CompressionNone
        tex.filter = TF_Nearest
        
        # 2. Set Format
        tex.source_format = TSF_RGBA32F
        
        # 3. Prepare Data Array
        # Extract the specific attribute for all splats into a list of vec4
        data_array = extract_attribute_for_all_splats(splats, name)
        
        # 4. Lock and Copy
        tex.lock_mip(0)
        dest_ptr = tex.get_mip_data(0)
        mem_copy(dest_ptr, data_array)
        tex.unlock_mip(0)
        
        # 5. Update Resource
        tex.update_resources()
        
        textures[name] = tex
        
    return textures

def extract_attribute_for_all_splats(splats: List[Splat], attr_name: str) -> List[vec4]:
    """
    Extracts a specific attribute from all splats and pads to vec4.
    """
    result = []
    for splat in splats:
        vec4 = vec4(0.0)
        if attr_name == "Position":
            vec4.x = splat.position.x
            vec4.y = splat.position.y
            vec4.z = splat.position.z
            vec4.w = 0.0 # Padding
        elif attr_name == "Scale":
            vec4.x = splat.scale.x
            vec4.y = splat.scale.y
            vec4.z = splat.scale.z
            vec4.w = 0.0 # Padding
        elif attr_name == "Rotation":
            vec4.x = splat.rotation.x
            vec4.y = splat.rotation.y
            vec4.z = splat.rotation.z
            vec4.w = splat.rotation.w
        elif attr_name == "Color":
            vec4.x = splat.color.r
            vec4.y = splat.color.g
            vec4.z = splat.color.b
            vec4.w = splat.opacity
        elif attr_name == "HarmonicsL1":
            # Map SH L1 coefficients to RGBA
            vec4.x = splat.sh_l1[0]
            vec4.y = splat.sh_l1[1]
            vec4.z = splat.sh_l1[2]
            vec4.w = 0.0
        elif attr_name == "HarmonicsL2":
            # Map SH L2 coefficients to RGBA
            vec4.x = splat.sh_l2[0]
            vec4.y = splat.sh_l2[1]
            vec4.z = splat.sh_l2[2]
            vec4.w = 0.0
        elif attr_name == "HarmonicsL31":
            # Map first part of SH L3 coefficients
            vec4.x = splat.sh_l3_1[0]
            vec4.y = splat.sh_l3_1[1]
            vec4.z = splat.sh_l3_1[2]
            vec4.w = 0.0
        elif attr_name == "HarmonicsL32":
            # Map second part of SH L3 coefficients
            vec4.x = splat.sh_l3_2[0]
            vec4.y = splat.sh_l3_2[1]
            vec4.z = splat.sh_l3_2[2]
            vec4.w = 0.0
        result.append(vec4)
    return result
```

**Parameters:**
*   **Texture Format:** `TSF_RGBA32F` (32-bit floating point per channel) [S1, unofficial].
*   **Filtering:** `TF_Nearest` to prevent interpolation artifacts in attribute data [S1, unofficial].
*   **Mipmaps:** Disabled (`TMGS_NoMipmaps`) as splats are sampled at specific indices, not via texture filtering [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** Using `RGBA32F` ensures no quantization error for position, scale, and rotation, which is critical for accurate rendering [S1, unofficial].
*   **Memory Usage:** Storing 8 textures for 2 million splats requires significant VRAM. Each texture is $N \times 4 \times 4$ bytes. For $N=2,000,000$, one texture is ~32 MB, totaling ~256 MB for all 8 [S1, unofficial].
*   **Transformations:** Moving, rotating, or scaling the parent actor in the world may break rendering if the texture data is not updated or if the engine does not support dynamic texture updates efficiently [S1, unofficial].
*   **Spherical Harmonics:** Support for SH may be limited or incomplete in some implementations [S1, unofficial].

## Subtopics

### [Chunked Bounding Box Computation and Normalization](17031-chunked-bounding-box-computation-and-normalization.md)
A preprocessing step that divides a list of Gaussian splats into chunks of size `kChunkSize`, computes the bounding box (min/max) for position, scale, color (DC0 + opacity), and spherical harmonics (SH coefficients) for each chunk, and normalizes the splat data within that chunk to the range [0, 1] based on these bounds.

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of splats, as each splat's attributes are copied once into the texture memory.
*   **Memory Complexity:** $O(N)$, specifically $8 \times N \times 16$ bytes for 8 RGBA32F textures.
*   **Performance:** Designed for real-time applications, including VR and interactive walkthroughs [S1, unofficial]. Supports models with up to 2 million splats [S1, unofficial].
*   **Strengths:** Efficient on-demand loading by Niagara; high performance due to contiguous memory layout; integration with Unreal Engine's VFX pipeline [S1, unofficial].
*   **Limitations:** Static model support is primary; dynamic transformations (move/rotate/scale of the actor) are not fully supported and may break rendering [S1, unofficial]. SH support may be incomplete [S1, unofficial].

## Background
This method is part of the "unreal-splat" plugin by JI20, which provides a pipeline for rendering 3D Gaussian Splatting in Unreal Engine using Niagara for GPU acceleration [S1, unofficial]. It was developed to address the need for efficient large-scale splat rendering in real-time engines, leveraging texture-based storage for optimal memory and performance [S1, unofficial].
