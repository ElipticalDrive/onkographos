# Online Image Rendering Placement

Also called: Image patch placement, Online placement of image rendering

## Overview
Online Image Rendering Placement is a per-iteration optimization step in distributed 3D Gaussian Splatting training that assigns image patches to GPUs to minimize inter-node communication and balance computational load [S1, unofficial]. Unlike offline graph partitioning which clusters both points and images for the entire dataset, this method dynamically assigns rendering tasks for a small random batch of images at each training step, adapting to the changing frustum visibility of the scene [S1, unofficial]. It distinguishes itself from static sharding by using a fast heuristic solver (Linear Sum Assignment followed by local search) to solve an Integer Linear Programming (ILP) problem within the latency constraints of online training [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** The current batch of $B$ image patches; the set of $N$ GPUs; the frustum culling results for each GPU; configurable coefficients $\alpha, \beta, \gamma, \delta$.
*   **Outputs:** A placement vector $W$, where $W_j$ is the GPU ID assigned to render image patch $j$.

**Data Structures:**
*   **Patch-GPU Access Pattern Matrix ($A$):** A $B \times N$ matrix where $A_{j,k}$ is the number of 3D Gaussian points stored on GPU $k$ that are required to render image patch $j$. This matrix is constructed by exchanging frustum culling results across all GPUs [S1, unofficial].
*   **Placement Vector ($W$):** A vector of length $B$ where each element $W_j \in \{1, \dots, N\}$ indicates the GPU assigned to patch $j$ [S1, unofficial].

**Numbered Steps:**
1.  **Input Distribution:** At each training iteration, every GPU receives the entire batch of $B$ image patches [S1, unofficial].
2.  **Frustum Culling:** Each GPU performs frustum culling on its locally stored 3D points to determine which points are visible for each of the $B$ image patches [S1, unofficial].
3.  **Access Pattern Construction:** All GPUs exchange their culling results to build the matrix $A$, where $A_{j,k}$ represents the count of points needed from GPU $k$ for patch $j$ [S1, unofficial].
4.  **Initial Placement (LSA):** Solve a Linear Sum Assignment (LSA) problem to obtain an initial placement $W_{init}$ that minimizes total communication volume. This is done using the Hungarian method [S1, unofficial].
5.  **Load Balancing Refinement (Local Search):** Iteratively refine $W_{init}$ using a greedy steepest-ascent local search. In each step, swap the GPU assignments of two image patches if it improves the relaxed objective function. Stop when convergence is reached or a time budget is exceeded [S1, unofficial].
6.  **Hierarchical Assignment (Optional):** If operating across multiple machines, first assign patches to machines, then assign a machine's patches to its local GPUs. For intra-node assignment, set $\alpha=0$ to de-prioritize communication [S1, unofficial].

**Formulas:**
The optimization aims to minimize communication and balance loads. The loads for GPU $k$ are defined as:

$$
\text{send}_k = \sum_{j=1}^{B} [W_j \neq k] \cdot A_{j,k}
$$

$$
\text{recv}_k = \sum_{j=1}^{B} [W_j = k] \cdot \left(\sum_{i=1}^{N} A_{j,i} - A_{j,k}\right)
$$

$$
\text{comp}_k = \sum_{j=1}^{B} [W_j = k] \cdot \sum_{i=1}^{N} A_{j,i}
$$

Where $[P]$ is the indicator function returning 1 if predicate $P$ is true, 0 otherwise [S1, unofficial].

The relaxed objective function used in local search to avoid plateaus caused by non-smooth max terms is:

$$
\text{Objective} = \beta \cdot \|\text{send}\|_p + \gamma \cdot \|\text{recv}\|_p + \delta \cdot \|\text{comp}\|_p
$$

Where $\|\text{send}\|_p = \left(\sum_{k=1}^{N} \text{send}_k^p\right)^{1/p}$, and similarly for recv and comp. The parameter $p$ is typically set to a small value (e.g., 2) [S1, unofficial].

The full ILP formulation (solved heuristically) includes the constraint that each GPU must be assigned an equal number of patches:

$$
\sum_{j=1}^{B} [W_j = k] = \frac{B}{N}, \quad \forall k \in \{1, \dots, N\}
$$

**Parameters:**
*   $B$: Batch size of training images. Typical value: 16–64 [S1, unofficial].
*   $N$: Number of GPUs [S1, unofficial].
*   $p$: Power for the $p$-norm in the relaxed objective. Typical value: 2–8 (for patch division) or 2 (for norm). Note: The source uses $p$ for both patch division granularity and norm power; context distinguishes them. Patch division $p$ is typically 2–8 [S1, unofficial].
*   $\alpha, \beta, \gamma, \delta$: Configurable coefficients trading off communication volume ($\alpha$), send imbalance ($\beta$), receive imbalance ($\gamma$), and compute imbalance ($\delta$) [S1, unofficial].

    return beta * send_norm + gamma * recv_norm + delta * comp_norm

**Edge Cases and Pitfalls:**
*   **ILP Solver Speed:** Standard ILP solvers (e.g., Gurobi) are too slow and unpredictable for online optimization per iteration [S1, unofficial].
*   **Batch Size:** Small batch sizes (16–64) are typical for PBDR training. Whole-image assignment severely limits scalability to many GPUs [S1, unofficial].
*   **Precision:** The use of $p$-norms in the relaxed objective avoids plateaus caused by non-smooth max terms in the original ILP [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The Linear Sum Assignment step using the Hungarian method has a time complexity of $O(B^3)$ [S1, unofficial]. The local search step's complexity depends on the number of swaps and the time budget, but is generally fast enough for online use.
*   **Memory Complexity:** Requires storing the $B \times N$ access pattern matrix $A$ and the placement vector $W$. This is negligible compared to the 3D Gaussian data [S1, unofficial].
*   **Measured Performance:** The method enables scalable training across many GPUs by reducing communication overhead and balancing load [S1, unofficial].
*   **Strengths:** Fast heuristic solver suitable for online optimization; fine-grained patch placement improves load balance and reduces communication; hierarchical assignment leverages intra-node bandwidth [S1, unofficial].
*   **Limitations:** Relies on accurate frustum culling; assumes $B$ is divisible by $N$ for equal distribution; heuristic may not find the global optimum [S1, unofficial].
*   **When to Use:** Distributed 3D Gaussian Splatting training with large scenes and many GPUs [S1, unofficial].
*   **When Not to Use:** Small-scale training with few GPUs where communication is not a bottleneck; offline rendering where per-iteration optimization is not needed [S1, unofficial].

## Background
Online Image Rendering Placement was introduced in the Gaian system for scaling point-based differentiable rendering for large-scale reconstruction [S1, unofficial]. It addresses the limitations of offline graph partitioning, which is static and does not adapt to the dynamic nature of training batches [S1, unofficial]. The method uses a combination of Linear Sum Assignment and local search to solve the placement problem efficiently [S1, unofficial].
