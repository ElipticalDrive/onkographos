# Fixed-Pool Relocation

Also called: Component Recycling, Dynamic Operations, Relocating low opacity components to high opacity component

## Overview
Fixed-Pool Relocation is a densification strategy that redistributes a fixed budget of splats to areas of high reconstruction error without increasing the total component count. It identifies low-importance splats and moves them to local maxima of the positive reconstruction residual, reinitializing them to explore new geometry. Unlike [Adaptive Densification](3034-adaptive-densification.md), which increases the Gaussian count via cloning and splitting, Fixed-Pool Relocation maintains a constant budget by recycling existing components, making it suitable for memory-constrained environments or scenes where the total number of primitives must remain strictly bounded.

## How it works
**Inputs:**
- Current set of splats (Gaussians) with positions $\mu$, covariances $\Sigma$, opacities $O$, and Adam optimizer states.
- Current view volume $V$ and reconstructed volume $\hat{V}$.
- Residual threshold parameters (e.g., bottom 1%, max 64 splats).
- Iteration counter.

**Outputs:**
- Updated set of splats with modified positions, opacities, and covariances.

**Data Structures:**
- **Splat Pool:** A list of splats. Each splat contains:
  - `mu`: 3D position vector.
  - `sigma`: Isotropic scale parameter (or covariance matrix).
  - `opacity`: Scalar opacity value.
  - `adam_m`: First moment estimate (vector).
  - `adam_v`: Second moment estimate (vector).
  - `last_relocated_iter`: Integer iteration index of last relocation (for cooldown).
- **Residual Volume:** A 3D grid or sparse structure storing $(V - \hat{V})_+$ values.

**Steps:**

1. **Identify Candidates:**
   Calculate an importance score $a_k$ for each splat $k$, defined as amplitude times approximate volume ($L_{k,ii}$). Sort splats by this score. Select the bottom 1% of splats that also sit at low residual. Limit the selection to at most 64 splats per step, ensuring at most one splat is selected per detected residual peak [S1, unofficial].

2. **Find Relocation Targets:**
   Compute the positive reconstruction residual $R = (V - \hat{V})_+$. Find local maxima of $R$ using non-maximum suppression over the volume [S1, unofficial].

3. **Relocate and Reinitialize:**
   For each selected splat $k$:
   a. Move its position $\mu_k$ to the location of a local residual maximum.
   b. Reinitialize the scale isotropically to $\sigma = 0.5$ voxels [S1, unofficial].
   c. Zero the Adam first- and second-moment estimates ($adam\_m = 0, adam\_v = 0$) to allow fresh learning [S1, unofficial].
   d. Update `last_relocated_iter` to the current iteration.

4. **Opacity Preservation (Component Recycling):**
   When relocating $N$ new components to the location of an old component ($\mu_{new} = \mu_{old}$), preserve the total distribution by adjusting opacity. The new opacity $O_{new}$ is calculated from the old opacity $O_{old}$ using:
   $$ (1 - O_{new})^N = (1 - O_{old}) $$
   $$ O_{new} = 1 - (1 - O_{old})^{1/N} $$
   where $N$ is the number of new components created from the old one [S2]. Note: In the standard Fixed-Pool Relocation described in [S1, unofficial], splats are moved rather than split, but the opacity preservation logic is critical when the method is used for densification via relocation (see Subtopics).

5. **Cooldown:**
   Prevent the same splat from being relocated again before it adapts. Enforce a cooldown period of at least 1 relocation step (i.e., `current_iter - last_relocated_iter >= 1`) [S1, unofficial].

6. **Cache Reordering (Periodic):**
   Every 1,000 iterations, reorder the splats along a Morton (Z-order) curve to improve GPU cache locality [S1, unofficial].

7. **Conservative Culling (Post-Fitting):**
   After fitting completes, perform a single pass of conservative culling. Remove splats accounting for the lowest fraction of cumulative amplitude. Default retention is 99.9% (removing 0.1%), though 5% removal is used in some Python API defaults [S1, unofficial].

**Pseudocode:**

```python
def fixed_pool_relocation(splats, residual_volume, current_iter, config):
    """
    splats: List of Splat objects
    residual_volume: 3D grid or sparse map of (V - V_hat)_+
    current_iter: int
    config: dict with keys 'relocation_interval', 'max_relocations', 'residual_threshold', 'cooldown'
    """
    if current_iter % config['relocation_interval'] != 0:
        return splats

    # Step 1: Identify bottom 1% low-residual splats
    scores = [s.amplitude * s.volume for s in splats]
    sorted_indices = np.argsort(scores)
    num_to_relocate = max(1, int(len(splats) * 0.01))
    candidates = sorted_indices[:num_to_relocate]
    
    # Limit to max_relocations (e.g., 64)
    candidates = candidates[:config['max_relocations']]
    
    # Filter by cooldown
    candidates = [s for s in candidates if (current_iter - s.last_relocated_iter) >= config['cooldown']]
    
    # Step 2: Find local maxima in residual volume
    # This requires non-maximum suppression on residual_volume
    peaks = find_local_maxima(residual_volume)
    
    # Assign peaks to candidates (one per peak, up to len(peaks))
    assignments = list(zip(candidates, peaks[:len(candidates)]))
    
    for splat_idx, peak_pos in assignments:
        splat = splats[splat_idx]
        
        # Step 3: Relocate
        splat.mu = peak_pos
        
        # Reinitialize isotropically
        splat.sigma = 0.5 # voxels
        
        # Zero Adam moments
        splat.adam_m = np.zeros(3)
        splat.adam_v = np.zeros(3)
        
        # Update cooldown timestamp
        splat.last_relocated_iter = current_iter
        
        # Note: Opacity adjustment depends on variant. 
        # In pure relocation (S1), opacity is kept or re-initialized.
        # In Component Recycling (S2/S3), opacity is preserved via formula.
        # If this is a split/relocation hybrid, apply opacity formula:
        # O_new = 1 - (1 - O_old)^(1/N)
        
    # Step 6: Cache Reordering every 1000 iterations
    if current_iter % 1000 == 0:
        splats = reorder_morton(splats)
        
    return splats
```

## Subtopics

### Primitive Relocation (Densification)
A variant where relocation is used to densify rather than just redistribute. When a primitive with opacity $o$, circumradius $R$, and sharpness $\sigma$ is replaced by $N$ co-located copies, the new opacity is computed as $o_{\text{new}} = 1 - (1 - o)^{1/N}$ [S3]. For $N=2$ (standard densification), one child is placed at the sampled position, and the other is offset in the primitive's tangent plane by $\eta \epsilon$, where $\epsilon \sim \mathcal{N}(0, I)$ and $\eta$ is a noise scale [S3]. The scale (circumradius) is corrected to maintain the rendered image using the denominator $D = \sum_{i=1}^{N}\sum_{k=0}^{i-1} \binom{i-1}{k}(-1)^k \frac{o_{\text{new}}^{k+1}}{(\sigma(k+1)+1)(\sigma(k+1)+2)}$ and the formula $R_{\text{new}} = R \sqrt{\frac{o}{(\sigma+1)(\sigma+2) \cdot D}}$ [S3]. This variant is chosen when the goal is to increase density in under-reconstructed regions while strictly preserving the visual output of the parent primitive before splitting [S3].

## Operating characteristics
- **Time Complexity:** $O(N)$ to score and sort splats, where $N$ is the number of splats. Finding residual peaks depends on the resolution of the residual volume. Morton reordering is $O(N \log N)$ or $O(N)$ with efficient encoding.
- **Memory Complexity:** $O(N)$ for the splat pool. Requires additional memory for the residual volume if stored explicitly.
- **Performance:** Maintains a fixed memory footprint, unlike densification methods that grow $N$. The 50-iteration interval balances responsiveness with computational overhead. The 1,000-iteration Morton reordering is lightweight but improves rendering throughput [S1, unofficial].
- **Strengths:** Prevents unbounded growth of Gaussian count. Effective for filling holes in sparse reconstructions without adding memory pressure.
- **Limitations:** May struggle in highly dynamic scenes if the relocation target (residual peak) moves faster than the splat can adapt. The fixed budget may limit detail in very complex scenes compared to unbounded densification.
- **When to use:** Memory-constrained applications, microscopy data (Luxar), or when a strict upper bound on primitive count is required.
- **When not to use:** Scenes requiring extremely high detail that exceeds the fixed budget's capacity, or when dynamic objects change structure rapidly.

## Background
Fixed-Pool Relocation was introduced in the context of scalable Gaussian splatting for microscopy and scientific data visualization, specifically in the Luxar framework [S1, unofficial]. It is also referred to as "Dynamic Operations" in that context. The concept of "Component Recycling" appears in 3D Student Splatting, where it is used to maintain distribution consistency when moving components [S2]. The variant involving primitive relocation with scale correction is detailed in Fourier Splatting, which generalizes the approach to non-Gaussian primitives [S3]. The method addresses the problem of inefficient coverage in sparse initializations or regions with high reconstruction error, without the memory overhead of traditional densification.
