# LGTM (Less Gaussians, Texture More)
Also called: Feed-Forward Prediction of Textured Gaussians, Feed-Forward Textured Splatting

## Overview
LGTM is a feed-forward framework that predicts compact 2D Gaussian primitives coupled with per-primitive texture maps, decoupling geometric complexity from rendering resolution to enable high-fidelity 4K novel view synthesis without per-scene optimization [S1, unofficial]. It solves the problem where existing feed-forward 3DGS methods suffer from quadratic growth in primitive count as resolution increases, making high-resolution synthesis intractable due to memory and compute limits [S1, unofficial]. Unlike standard 3DGS which couples appearance and geometry within each primitive, LGTM allows a compact set of geometric primitives to represent rich texture regions via per-primitive textures [S1, unofficial].

## How it works
**Inputs and Outputs:**
The network $f$ takes a set of input images $\{I^v\}_{v=1}^N$ and their low-resolution counterparts $\{I^v_{low}\}_{v=1}^N$ as input. It predicts a set of textured 2D Gaussians:
$$ f : (I^v, I^v_{low}) \rightarrow \{\mu_i, s_i, r_i, c_i, T^i_c, T^i_\alpha\} $$
where $\mu_i$ is the center, $s_i$ is the scale, $r_i$ is the rotation, $c_i$ is the spherical harmonic (SH) coefficients, $T^i_c$ is the color texture map, and $T^i_\alpha$ is the alpha texture map for primitive $i$ [S1, unofficial].

**Data Structures:**
*   **Primitive Grid:** The primitive network predicts a grid of $h \times w$ 2DGS primitives. Each primitive $i$ contains parameters $\mu_i, s_i, r_i, o_i$ (base opacity), and $c_i$ [S1, unofficial].
*   **Per-primitive Texture Maps:** Each primitive $i$ has two learnable texture maps:
    *   Color texture: $T^i_c \in \mathbb{R}^{T \times T \times 3}$
    *   Alpha texture: $T^i_\alpha \in \mathbb{R}^{T \times T}$
    *   $T$ is the texture resolution, a tunable parameter trading off primitive size and texture size [S1, unofficial].
*   **Intermediate Features:**
    *   $F^{v}_{prim}$: Feature maps from the ViT decoder of the primitive network, shared with the texture network [S1, unofficial].
    *   $F^{v}_{patch}$: High-resolution features extracted from $I^v$ via patchification and convolutions [S1, unofficial].
    *   $F^{v}_{proj}$: Projective features extracted from the projective prior texture [S1, unofficial].

**Rendering Formulas:**
In standard 2DGS, the alpha and color for a sample at local coordinate $u$ on primitive $i$ are:
$$ a_i(u) = o_i \cdot G(u) $$
$$ \hat{c}_i(d_i) = SH(c_i, d_i) $$
where $G(u) = \exp(-\frac{1}{2}(u^2 + v^2))$ is the 2D Gaussian function, $d_i$ is the view direction, and $u=(u,v)$ are local coordinates on the primitive's plane [S1, unofficial].

In LGTM, these are redefined using textures. At a ray-splat intersection point $u$, color and alpha values are retrieved from the texture maps using bilinear sampling, denoted by $T[u]$. The alpha texture replaces the Gaussian falloff, and the color texture adds detail to the SH base color:
$$ a_i(u) = o_i \cdot T^i_\alpha[u] $$
$$ \hat{c}_i(u, d_i) = T^i_c[u] + SH(c_i, d_i) $$
The final pixel color $C$ is computed by alpha-blending contributions from all primitives sorted by depth:
$$ C = \sum_i a_i(u_i) \hat{c}_i(d_i) \prod_{j=1}^{i-1} (1 - a_j(u_j)) $$
[S1, unofficial]

**Algorithm Steps:**

1.  **Primitive Network Prediction ($f_{prim}$):**
    *   Input: Low-resolution image $I^v_{low} \in \mathbb{R}^{h \times w \times 3}$.
    *   Process: Pass $I^v_{low}$ through a ViT encoder-decoder.
    *   Output: Predict primitive grid parameters $\{\mu_i, s_i, r_i, o_i, c_i\}$ and feature maps $F^{v}_{prim}$.
    *   Note: The network is trained with high-resolution supervision (rendering at $H \times W$) despite low-res input to ensure anti-aliasing and robust geometry [S1, unofficial].

2.  **Texture Network Prediction ($f_{texture}$):**
    *   Input: High-resolution image $I^v$ and primitive features $F^{v}_{prim}$.
    *   Step 2.1: Compute patch features $F^{v}_{patch}$ from $I^v$ via image patchification and convolutional layers [S1, unofficial].
    *   Step 2.2: Compute projective features $F^{v}_{proj}$.
        *   For each primitive $i$, compute the projective prior texture $T^{i, proj}_c$ using the inverse transformation $M^{-1}_{i,v}$ which maps primitive local coordinates $u$ to source image pixel coordinates $x$:
            $$ T^{i, proj}_c[u] = I^v[x] = I^v[M^{-1}_{i,v}(u)] $$
        *   Extract features $F^{v}_{proj}$ from $T^{i, proj}_c[u]$ [S1, unofficial].
    *   Step 2.3: Aggregate features $F^{v}_{prim}$, $F^{v}_{patch}$, and $F^{v}_{proj}$ to predict per-primitive texture maps $T^i_\alpha$ and $T^i_c$ [S1, unofficial].

3.  **Rendering:**
    *   For each ray, find intersection $u$ with primitives.
    *   Retrieve $a_i(u)$ and $\hat{c}_i(u, d_i)$ using the texture sampling formulas above.
    *   Perform alpha blending [S1, unofficial].

**Training Strategy:**
1.  **Stage 1 (Primitive Pre-training):** Train $f_{prim}$ in isolation. Input $I^v_{low}$, predict 2DGS parameters. Supervise with high-resolution rendering using standard photometric losses (MSE + LPIPS) [S1, unofficial].
2.  **Stage 2 (Joint Training):** Jointly train $f_{prim}$ and $f_{texture}$.
    *   Freeze or reduce the learning rate of $f_{prim}$ by 0.1x to maintain geometric stability [S1, unofficial].
    *   Initialize color texture $T^i_c$ to zero.
    *   Supervise with standard photometric losses (MSE + LPIPS) [S1, unofficial].

    """
    Standard 2DGS rasterization with texture lookup.
    """
    # Initialize output image
    H, W = camera_params.image_height, camera_params.image_width
    color_img = np.zeros((H, W, 3))
    alpha_img = np.zeros((H, W))
    
    # For each pixel, find contributing primitives
    # This is typically done via tile-based rasterization in practice
    # Here we describe the per-pixel logic for clarity
    
    for y in range(H):
        for x in range(W):
            ray = get_ray(x, y, camera_params)
            intersections = find_ray_splat_intersections(ray, primitives)
            
            # Sort intersections by depth
            intersections.sort(key=lambda p: p.depth)
            
            accumulated_alpha = 0.0
            accumulated_color = np.zeros(3)
            
            for prim in intersections:
                # Get local coordinates u on the primitive plane
                u = get_local_coordinates(prim, ray)
                
                # Sample alpha texture
                # T_alpha is T x T, u is normalized or in pixel coords depending on implementation
                # Assuming bilinear sampling into [0, T-1] range
                alpha_val = sample_texture(prim.alpha_texture, u, texture_resolution)
                
                # Sample color texture
                color_val = sample_texture(prim.color_texture, u, texture_resolution)
                
                # Base opacity and SH color
                base_alpha = prim.opacity
                sh_color = evaluate_sh(prim.sh_coeffs, ray.direction)
                
                # Final alpha and color for this primitive
                a_i = base_alpha * alpha_val
                c_i = color_val + sh_color
                
                # Alpha blending
                weight = a_i * (1.0 - accumulated_alpha)
                accumulated_color += weight * c_i
                accumulated_alpha += weight
                
                if accumulated_alpha > 0.99:
                    break
            
            color_img[y, x] = accumulated_color
            alpha_img[y, x] = accumulated_alpha
            
    return color_img, alpha_img

def sample_texture(texture_map, u, T):
    """
    Bilinear sampling from texture map T x T.
    u is assumed to be in local coordinates, mapped to [0, T-1] range.
    """
    # Map local coordinates u to texture coordinates
    # In 2DGS, u is in the primitive's local frame.
    # The texture map is defined on a T x T grid.
    # We need to map the intersection point to the texture grid.
    # This mapping is implicit in the "bilinear sampling" description.
    # Typically, the primitive's scale and rotation define the bounding box

**Edge Cases and Pitfalls:**
*   **Memory Constraints:** Standard feed-forward methods fail at 2K+ resolutions due to memory (e.g., NoPoSplat requires >61GB at 1024x576). LGTM uses <30GB at 4K [S1, unofficial].
*   **Geometric Stability:** In Stage 2, the primitive network must be trained with a reduced learning rate (0.1x) to prevent geometric collapse while learning textures [S1, unofficial].
*   **Texture Initialization:** Color texture $T^i_c$ is zero-initialized to ensure the SH base color dominates initially, preventing high-frequency noise [S1, unofficial].
*   **Anti-aliasing:** High-resolution supervision is critical in Stage 1; without it, predicted Gaussians may result in holes when rendered at high resolution [S1, unofficial].

## Operating characteristics
*   **Time and Memory Complexity:** LGTM scales efficiently at inference; a 64x pixel increase adds only modest memory and time overhead [S1, unofficial]. It trains successfully at 2K and 4K resolutions using under 30 GB of memory [S1, unofficial].
*   **Measured Performance:** LGTM enables high-fidelity 4K novel view synthesis, a capability previously out of reach for feed-forward methods [S1, unofficial].
*   **Strengths:** Decouples geometry and appearance; enables high-resolution rendering with significantly fewer primitives; no per-scene optimization required; versatile (works with monocular, posed/unposed two-view, and multi-view inputs) [S1, unofficial].
*   **Limitations:** Requires a dual-network architecture; relies on the quality of the baseline method (Flash3D, DepthSplat, etc.) for initial geometry prediction [S1, unofficial].
*   **When to use:** When high-resolution (4K) novel view synthesis is required without per-scene optimization, and computational resources are limited (<30GB VRAM).
*   **When not to use:** When per-scene optimization is acceptable and lower resolution is sufficient, or when input does not include high-resolution images for the texture network [S1, unofficial].
