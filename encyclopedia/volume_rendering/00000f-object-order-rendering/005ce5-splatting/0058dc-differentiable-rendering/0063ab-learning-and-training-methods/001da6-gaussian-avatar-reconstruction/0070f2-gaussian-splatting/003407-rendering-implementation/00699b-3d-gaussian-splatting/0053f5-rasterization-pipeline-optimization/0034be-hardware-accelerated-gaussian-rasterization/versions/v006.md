# Hardware-Accelerated Gaussian Rasterization

Also called: GauRast, Hardware Architecture Pipeline, Hardware-algorithm co-design for Gaussian rasterization

## Overview
Hardware-Accelerated Gaussian Rasterization is a hardware-algorithm co-design that augments standard triangle rasterizers with dedicated units for Gaussian projection and blending, achieving an order of magnitude speedup in the rasterization stage [S1, unofficial][S2]. It implements a four-stage pipeline where preprocessing (Stages 0–1) is point-based and rendering (Stages 2–3) is tile-based [S2]. It differs from sibling methods like [Speedy-Splat Rendering Pipeline](3543-speedy-splat-rendering-pipeline.md) by its specific focus on dedicated silicon units for projection and sorting rather than purely algorithmic software optimizations [S2].

## How it works
The method implements a four-stage hardware pipeline [S2]. The first two stages constitute preprocessing (point-based), and the last two constitute rendering (tile-based) [S2].

**Inputs and Outputs:**
*   **Input:** 3D Gaussian parameters (position, covariance, opacity, spherical harmonics coefficients) and camera matrices [G].
*   **Output:** Final 2D image pixels [G].

**Data Structures:**
*   **Tile Assignment:** The image is divided into $16 \times 16$ pixel tiles [S2]. Each tile is assigned to an independent SRAM bank with a fixed entry depth and address offset controller [S2].
*   **Codebook:** An index is used to look up corresponding values stored in the SRAM codebook [S2].
*   **Sorting Buffer:** The sorting unit outputs the current maximum value in a linear sorting delay, aligning with the rasterization unit's need to process one point at a time [S2].

**Pipeline Stages:**

1.  **Stage 0: Near-plane Culling**
    *   Eliminates parameter access for invisible regions using an Axis-Aligned Bounding Box (AABB) depth-interval test [S2].
    *   This stage is isolated to handle the largest number of Gaussian points efficiently [S2].

2.  **Stage 1: Projection**
    *   Projects 3D Gaussians onto the 2D image plane [S2].
    *   Uses a 6x1 multiplier-accumulator array [S2].
    *   Implements zero-Jacobian skipping to optimize computation [S2].

3.  **Stage 2: Gaussian Sorting**
    *   Sorts Gaussians per tile to enable correct front-to-back alpha compositing [S2].
    *   Uses a four-way sub-sorter parallelism based on a comparison-free sorter design [S2].
    *   Each sub-sorter processes 256 data elements at a time [S2].
    *   The design outputs the current maximum value in a linear sorting delay, which aligns with the rasterization unit's need to process one point at a time [S2].

4.  **Stage 3: Rasterization**
    *   Performs alpha-blending, processing one point at a time aligned with the sorting output [S2].
    *   Uses the tile-based model where each tile operates on its assigned SRAM bank [S2].

**Alpha Compositing:**
The final pixel color $C(p)$ is computed via front-to-back blending [G]:
$$ C(p) = \sum_{i \in \mathcal{N}} c_i \alpha_i(p) \prod_{j=1}^{i-1} (1 - \alpha_j(p)) $$
where $\mathcal{N}$ is the set of surviving Gaussians in the tile, sorted by depth [G]. The opacity $\alpha_i(p)$ is defined as:
$$ \alpha_i(p) = \sigma_i g_i(p) $$
where $\sigma_i$ is the Gaussian opacity and $g_i(p)$ is the projected 2D Gaussian value at pixel $p$ [G].

**Pseudocode:**
```python
import math

def stage_0_cull(gaussians, camera_near_plane):
    """Stage 0: Near-plane Culling. Eliminates Gaussians outside the near-plane using AABB depth test."""
    valid = []
    for g in gaussians:
        if g.min_depth > camera_near_plane:
            valid.append(g)
    return valid

def stage_1_project(gaussians, camera_matrix):
    """Stage 1: Projection. Projects 3D Gaussians to 2D with zero-Jacobian skipping."""
    projected = []
    for g in gaussians:
        proj = project_3d_to_2d(g, camera_matrix)
        if abs(proj.jacobian_det) > 1e-6:
            projected.append(proj)
    return projected

def project_3d_to_2d(g, cam):
    """Standard 3D to 2D projection helper [G]."""
    return type('Gaussian2D', (), {
        'x': g.x, 'y': g.y, 'cov': g.cov,
        'jacobian_det': 1.0, 'opacity': g.opacity, 'color': g.color, 'depth': g.z
    })()

def stage_2_sort(projected_gaussians, tile_size=16):
    """Stage 2: Gaussian Sorting. Sorts Gaussians per tile using comparison-free sub-sorters."""
    tiles = {}
    for g in projected_gaussians:
        tx, ty = int(g.x // tile_size), int(g.y // tile_size)
        key = (tx, ty)
        if key not in tiles:
            tiles[key] = []
        tiles[key].append(g)

    sorted_tiles = []
    for key, g_list in tiles.items():
        # Hardware uses four-way sub-sorter parallelism (256 elements/sub-sorter)
        # Outputs current maximum value in linear sorting delay
        sorted_g = sorted(g_list, key=lambda x: x.depth, reverse=True)
        sorted_tiles.append({'key': key, 'gaussians': sorted_g})
    return sorted_tiles

def stage_3_rasterize(sorted_tiles, image_width, image_height):
    """Stage 3: Rasterization. Performs alpha-blending per tile using SRAM codebook lookup."""
    image = [[0.0, 0.0, 0.0] for _ in range(image_height * image_width)]
    for tile in sorted_tiles:
        tile_data = lookup_sram(tile['key'])
        tx, ty = tile['key']
        for g in tile['gaussians']:
            for py in range(ty * 16, min((ty + 1) * 16, image_height)):
                for px in range(tx * 16, min((tx + 1) * 16, image_width)):
                    idx = py * image_width + px
                    alpha = g.opacity * gaussian_value(g, (px, py))
                    if alpha > 1e-4:
                        current = image[idx]
                        image[idx] = [
                            current[0] * (1 - alpha) + g.color[0] * alpha,
                            current[1] * (1 - alpha) + g.color[1] * alpha,
                            current[2] * (1 - alpha) + g.color[2] * alpha
                        ]
    return image

def gaussian_value(g, pixel):
    """Evaluate projected 2D Gaussian at pixel [G]."""
    dx, dy = pixel[0] - g.x, pixel[1] - g.y
    var = g.cov[0][0] if len(g.cov) > 0 else 1.0
    return math.exp(-0.5 * (dx**2 + dy**2) / var)

def update_pixel_alpha_blend(image, pixel, color, alpha):
    """Front-to-back alpha compositing update [G]."""
    px, py = pixel
    idx = py * image.shape[1] + px
    current = image[idx]
    image[idx] = current * (1 - alpha) + color * alpha

def lookup_sram(tile_key):
    """Simulate SRAM codebook lookup for tile metadata [G]."""
    return tile_key
```

## Subtopics

### Compressed 3D Gaussian Splatting Renderer
A renderer for compressed scenes using GPU sorting and rasterization, enabling real-time novel view synthesis on low-end devices and integration with polygonal rendering [S4]. It renders the scene using hardware rasterization instead of the specialized compute pipeline used in original 3D Gaussian Splatting [S4]. This differs from the original compute pipeline by using hardware rasterization, allowing seamless integration into VR/AR environments or games alongside polygon models [S4].

### LS-Gaussian Hardware Architecture
A dedicated hardware accelerator designed to accelerate 3DGS by enabling early stages to process subsequent frames while later stages execute previous ones, improving parallelism and pipeline efficiency [S5]. It enhances the Culling and Conversion Unit (CCU) by replacing GSCore’s dual OBB Intersection Test Units (OIUs) with a square root and logarithmic operator to support the two-stage accurate intersection test [S5]. The Viewpoint Transformation Unit (VTU) performs sparse rendering by retrieving pixel colors and maximum depths from the reference frame and performing three matrix multiplications: mapping 2D pixels to 3D space, transforming the point cloud, and reprojecting onto the new camera plane [S5]. The VTU Tile Classification uses a counter array to track validly projected pixels per tile; if the count exceeds 56 (of total pixels in tile), the tile is interpolated, otherwise it is forwarded to the Volume Rendering Unit (VRU) for full re-rendering [S5]. The architecture includes CCU, Load Distribution Unit (LDU), VTU, VRU, Sorting Unit, and Interpolation Unit [S5].

## Operating characteristics
*   **Performance:** Achieves an order of magnitude speedup in the rasterization stage compared to standard compute pipelines [S1, unofficial].
*   **Hardware:** Implemented as a dedicated hardware accelerator, often built upon existing graphics cores (e.g., GSCore) with enhanced units [S5].
*   **Complexity:** The pipeline isolates near-plane culling to handle the largest number of points, optimizing computational resources [S2].
*   **Limitations:** Data dependencies in the multiplier-accumulator arrays limit the ability to fully parallelize operations, as certain computations must wait for completion of others [S2].
*   **Use Case:** Suitable for real-time rendering on constrained hardware or when integration with standard polygonal rasterization is required [S4].

## Background
Hardware-accelerated Gaussian rasterization emerged as a hardware-algorithm co-design to augment standard triangle rasterizers with dedicated units for Gaussian projection and blending [S1, unofficial][S2]. Subsequent developments, such as LS-Gaussian, introduced streaming mechanisms and specific hardware enhancements like square root and logarithmic operators to improve pipeline efficiency and reduce stalls [S5]. The approach represents a shift from purely algorithmic optimizations to dedicated silicon implementations [S2][S5].
