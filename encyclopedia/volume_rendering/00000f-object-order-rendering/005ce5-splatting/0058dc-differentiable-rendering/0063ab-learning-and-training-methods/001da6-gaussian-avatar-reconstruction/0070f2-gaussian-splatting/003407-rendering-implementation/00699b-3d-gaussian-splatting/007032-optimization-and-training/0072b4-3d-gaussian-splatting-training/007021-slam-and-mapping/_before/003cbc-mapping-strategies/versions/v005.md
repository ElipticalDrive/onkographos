# Mapping Strategies

Also called: Pixel mapping strategies, Scene alignment strategies

## Overview
Mapping strategies define the correspondence mechanism used to align pixels or features between two distinct scene representations, typically for tasks such as 3D editing, style transfer, or multi-scene fusion. Unlike standard SLAM mapping which updates a single scene's geometry and appearance, these strategies solve the problem of transferring visual attributes (density, radiance, color) from a source scene to a target scene while maintaining structural fidelity. They are distinguished from sibling methods like [Semantic-aware mapping](12053-semantic-aware-mapping.md) by their focus on explicit pixel-to-pixel or region-to-region correspondence algorithms rather than high-level semantic label propagation.

## How it works
The method operates by establishing a mapping function $M$ that associates elements of a source scene $\mathcal{S}_{src}$ with elements of a target scene $\mathcal{S}_{tgt}$. The implementation depends on the chosen strategy, which dictates how spatial alignment is computed.

**Inputs:**
*   Source scene representation $\mathcal{S}_{src}$ (e.g., radiance field parameters, Gaussian splats).
*   Target scene representation $\mathcal{S}_{tgt}$.
*   Camera poses for both scenes (if not aligned in a common coordinate frame).

**Outputs:**
*   A correspondence map $C_{map}$ linking source pixels/regions to target pixels/regions.
*   Modified target scene parameters incorporating source attributes.

**Data Structures:**
*   **Feature Grid:** A dense tensor storing semantic features extracted from the source and target views.
*   **Segmentation Mask:** A boolean or integer array indicating semantically meaningful parts of the image.

**Strategies and Steps:**

1.  **Identity Mapping:**
    *   Assumes a direct 1:1 pixel correspondence based on camera projection without spatial correction.
    *   Step: For each pixel $p$ in the target view, map directly to pixel $p$ in the source view.
    *   Limitation: Lacks spatial alignment accuracy if camera poses or scene geometries differ [S1].

2.  **Semantic Correspondence-based Mapping:**
    *   Uses deep learning features to find spatial matches.
    *   Step 1: Extract dense semantic features from source and target images using a Vision Transformer (ViT) [Dosovitskiy 2020] and DINO [Amir et al. 2021].
    *   Step 2: Compute similarity scores between feature vectors of source pixels and target pixels.
    *   Step 3: Establish correspondence by matching pixels with the highest similarity scores.
    *   Benefit: Improves spatial matching accuracy over identity mapping [S1].

3.  **Co-segmentation-based Mapping:**
    *   Refines alignment by grouping pixels into semantically meaningful parts.
    *   Step 1: Perform clustering on DINO features to segment images into coherent parts.
    *   Step 2: Match corresponding segments between source and target scenes.
    *   Step 3: Map pixels within matched segments, ensuring semantic boundaries are preserved.
    *   Benefit: Yields finer correspondence and maintains semantic integrity [S1].

**Resampling (Contextual Step):**
When mapping density and radiance, initial uniform sampling along rays may fail due to misalignment. A density-based resampling strategy is often employed:
*   Identify density peaks along corresponding rays in both scenes.
*   Adjust sampling points to align these key points.
*   This ensures color-geometry consistency during the fusion of visual attributes [S1].

**Pseudocode for Semantic Correspondence:**

```python
def semantic_mapping(source_image, target_image, vit_model, dino_model):
    # Extract features
    src_features = dino_model.forward(vit_model.forward(source_image))
    tgt_features = dino_model.forward(vit_model.forward(target_image))
    
    # Compute similarity matrix
    # Flatten features to 2D: [num_pixels, feature_dim]
    src_flat = src_features.reshape(-1, src_features.shape[-1])
    tgt_flat = tgt_features.reshape(-1, tgt_features.shape[-1])
    
    # Normalize features
    src_flat = src_flat / torch.norm(src_flat, dim=1, keepdim=True)
    tgt_flat = tgt_flat / torch.norm(tgt_flat, dim=1, keepdim=True)
    
    # Similarity is dot product
    similarity_matrix = torch.matmul(src_flat, tgt_flat.T)
    
    # Find best match for each target pixel
    # Correspondence index in source for each target pixel
    correspondence_indices = torch.argmax(similarity_matrix, dim=0)
    
    return correspondence_indices
```

## Subtopics

### [iMAP](11979-imap.md)
iMAP is the first NeRF-based dense online SLAM model that jointly optimizes camera pose and an implicit scene representation. It solves the problem of simultaneous localization and mapping by treating the scene as a continuous radiance field rather than a discrete mesh or point cloud. It sets itself apart from its siblings by being the foundational method that introduced the iterative two-step approach of tracking and mapping to NeRF-based SLAM, upon which NICE-SLAM and subsequent methods build.

## Operating characteristics
*   **Identity Mapping:** $O(1)$ per pixel. Fastest but inaccurate for misaligned scenes.
*   **Semantic Correspondence:** $O(N \cdot D)$ where $N$ is number of pixels and $D$ is feature dimension. Requires GPU acceleration for ViT/DINO inference.
*   **Co-segmentation:** Higher computational cost due to clustering. Provides best semantic fidelity but is sensitive to clustering parameters.
*   **Strengths:** Enables view-consistent 3D editing and multi-scene fusion.
*   **Limitations:** Identity mapping fails under geometric variation; semantic methods depend on feature quality and may struggle with textureless regions.

## Background
The concept of mapping strategies in the context of radiance fields and 3D editing was formalized in the work on Generalized TensoRF. The method addresses the challenge of transferring visual styles and attributes between scenes while preserving structural consistency. It builds upon earlier NeRF-based SLAM approaches like iMAP [S1].
