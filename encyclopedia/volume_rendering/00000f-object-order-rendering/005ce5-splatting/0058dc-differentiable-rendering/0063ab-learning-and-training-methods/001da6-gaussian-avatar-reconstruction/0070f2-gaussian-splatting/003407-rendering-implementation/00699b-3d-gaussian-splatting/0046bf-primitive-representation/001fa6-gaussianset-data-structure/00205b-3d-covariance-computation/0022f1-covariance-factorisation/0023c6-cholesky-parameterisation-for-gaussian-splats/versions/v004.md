# Cholesky Parameterisation for Gaussian Splats

Also called: Cholesky Decomposition for Covariance, Cholesky-based Covariance Parameterization

## Overview
This method parameterizes the 3D Gaussian covariance matrix using Cholesky decomposition to guarantee positive-definiteness by construction during gradient-based optimization [S1, unofficial]. It stores $D(D+1)/2$ elements per splat (6 for 3D), ensuring the covariance matrix remains valid without requiring post-hoc projection or regularization [S1, unofficial]. It differs from sibling methods like [Quaternion-Scale Covariance Parameterization](11801-quaternion-scale-covariance-parameterization.md) by avoiding explicit rotation parameterization, instead relying on the triangular structure of the Cholesky factor to encode orientation and scale implicitly [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Unconstrained optimization variables representing the Cholesky factor elements and amplitude parameters.
*   **Output:** A valid, positive-definite $3 \times 3$ covariance matrix $\Sigma$ and a non-negative amplitude $\alpha$ for each Gaussian splat.

**Data Structures:**
For a 3D Gaussian, the covariance matrix $\Sigma$ is factorized as $\Sigma = L L^T$, where $L$ is a lower triangular matrix with positive diagonal entries. The Cholesky parameterization stores the 6 unique elements of $L$:
$$
L = \begin{bmatrix}
l_{11} & 0 & 0 \\
l_{21} & l_{22} & 0 \\
l_{31} & l_{32} & l_{33}
\end{bmatrix}
$$
These 6 values are stored directly in the splat's attribute buffer.

**Steps:**
1.  **Initialize Parameters:** Store 6 unconstrained real numbers for the lower triangular Cholesky factor $L$. Store 1 unconstrained real number for the amplitude log-scale and 1 for the minimum standard deviation floor if not fixed.
2.  **Enforce Diagonal Positivity:** The diagonal elements $l_{ii}$ must be positive to ensure $\Sigma$ is positive-definite. This is achieved by parameterizing the diagonal as:
    $$ l_{ii} = \sigma_{min} + \text{softplus}(z_i) $$
    where $z_i$ is the learned unconstrained variable, $\text{softplus}(x) = \ln(1 + e^x)$, and $\sigma_{min}$ is a small constant [S1, unofficial].
3.  **Construct Covariance:** Compute $\Sigma = L L^T$. This guarantees $\Sigma$ is symmetric and positive-definite by construction [S1, unofficial].
4.  **Parameterize Amplitude:** The amplitude $\alpha$ is made non-negative using a softplus activation on a learned variable $a$:
    $$ \alpha = \text{softplus}(a) $$
    Optionally, $\alpha$ is upper-bounded by a configurable maximum $a_{max}$:
    $$ \alpha = \min(\alpha, a_{max}) $$
    [S1, unofficial].
5.  **Compute Density:** Use the standard Gaussian density formula with the computed $\Sigma$ and mean $\mu$ for rendering [S1, unofficial].

**Formulas and Definitions:**
*   $\Sigma = L L^T$: Covariance matrix reconstruction.
*   $l_{ii} = \sigma_{min} + \text{softplus}(z_i)$: Diagonal parameterization.
*   $\sigma_{min} = 1/\sqrt{12}$ voxels: The minimum standard deviation floor, representing the standard deviation of a uniform voxel [S1, unofficial]. This ensures no splat is narrower than a voxel’s own spread.
*   $\alpha = \min(\text{softplus}(a), a_{max})$: Amplitude parameterization with upper bound [S1, unofficial].

**Parameters:**
*   $\sigma_{min}$: Minimum standard deviation floor. Typical value: $1/\sqrt{12}$ voxels [S1, unofficial].
*   $a_{max}$: Maximum amplitude bound. Configurable, not given in the sources.

**Edge Cases and Pitfalls:**
*   **Precision:** The softplus function can suffer from overflow or underflow for large positive or negative inputs. Use numerically stable implementations (e.g., `log1p(exp(x))` for softplus).
*   **Degenerate Input:** If $l_{ii}$ becomes too small, the Gaussian becomes extremely narrow, potentially causing numerical instability in rasterization. The $\sigma_{min}$ floor prevents this [S1, unofficial].
*   **Boundary Conditions:** The Cholesky factorization is undefined for non-positive-definite matrices. By construction, this method avoids this issue, but gradient updates must not violate the softplus constraint (which they won't if implemented correctly).

**Pseudocode:**
```python
import torch
import torch.nn.functional as F

def cholesky_covariance_from_params(L_elements, sigma_min=1.0/12**0.5):
    """
    Reconstructs a 3x3 covariance matrix from 6 Cholesky elements.
    
    Args:
        L_elements: Tensor of shape (N, 6) containing [l11, l21, l22, l31, l32, l33]
        sigma_min: Minimum standard deviation floor (default: 1/sqrt(12))
        
    Returns:
        Sigma: Tensor of shape (N, 3, 3) representing the covariance matrix
    """
    # Reshape to (N, 3, 3) lower triangular
    L = torch.zeros(L_elements.shape[0], 3, 3, device=L_elements.device)
    
    # Extract elements
    l11 = L_elements[:, 0]
    l21 = L_elements[:, 1]
    l22 = L_elements[:, 2]
    l31 = L_elements[:, 3]
    l32 = L_elements[:, 4]
    l33 = L_elements[:, 5]
    
    # Apply softplus to diagonal elements and add sigma_min
    # Ensure diagonal is positive
    l11 = sigma_min + F.softplus(l11)
    l22 = sigma_min + F.softplus(l22)
    l33 = sigma_min + F.softplus(l33)
    
    # Fill lower triangular matrix
    L[:, 0, 0] = l11
    L[:, 1, 0] = l21
    L[:, 1, 1] = l22
    L[:, 2, 0] = l31
    L[:, 2, 1] = l32
    L[:, 2, 2] = l33
    
    # Compute Sigma = L @ L.T
    Sigma = torch.bmm(L, L.transpose(1, 2))
    
    return Sigma

def compute_amplitude(amplitude_log, a_max=None):
    """
    Computes non-negative amplitude with optional upper bound.
    
    Args:
        amplitude_log: Tensor of shape (N,) containing log-amplitude
        a_max: Optional maximum amplitude bound
        
    Returns:
        alpha: Tensor of shape (N,) representing the amplitude
    """
    alpha = F.softplus(amplitude_log)
    if a_max is not None:
        alpha = torch.min(alpha, torch.full_like(alpha, a_max))
    return alpha
```

## Operating characteristics
*   **Time Complexity:** $O(1)$ per splat for covariance reconstruction (constant number of multiplications for 3D).
*   **Memory Complexity:** $O(1)$ per splat, storing 6 floats for the Cholesky factor plus amplitude parameters.
*   **Strengths:** Guarantees positive-definiteness by construction, simplifying optimization. No need for post-hoc projection or regularization.
*   **Limitations:** Loses explicit spatial rotation structure compared to quaternion-based methods. The triangular structure may introduce correlations between scale and rotation parameters that are not immediately interpretable.
*   **When to Use:** When positive-definiteness is critical and explicit rotation parameterization is not required. Suitable for general-purpose Gaussian splatting where simplicity and stability are prioritized.
*   **When Not to Use:** When explicit control over rotation is needed, or when generalizing to dimensions beyond 3D where quaternion parameterization is more natural.

## Background
This method is described in the Luxar paper, which applies Gaussian splatting to microscopy and multidimensional scientific data visualization [S1, unofficial]. It leverages the mathematical property that Cholesky decomposition of a positive-definite matrix yields a unique lower triangular matrix with positive diagonal entries, ensuring the covariance matrix remains valid during optimization.
