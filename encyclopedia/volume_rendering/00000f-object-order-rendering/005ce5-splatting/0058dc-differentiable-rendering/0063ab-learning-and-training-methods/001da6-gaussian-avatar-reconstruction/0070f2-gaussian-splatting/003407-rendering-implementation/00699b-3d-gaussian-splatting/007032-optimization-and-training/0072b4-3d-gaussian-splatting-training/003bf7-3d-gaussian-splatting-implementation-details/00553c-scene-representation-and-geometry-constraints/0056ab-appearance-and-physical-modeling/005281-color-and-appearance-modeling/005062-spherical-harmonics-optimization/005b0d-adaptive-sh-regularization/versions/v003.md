# Adaptive SH Regularization

Also called: Directional support-aware SH regularization

## Overview
Adaptive SH Regularization stabilizes spherical harmonic (SH) coefficient estimation in sparse or unevenly observed scenes by suppressing higher-order SH components that lack sufficient directional support [S1, unofficial]. It prevents overfitting to input views and improves generalization to unseen viewpoints, distinguishing itself from methods that rely on iterative optimization or fixed SH complexity [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A set of $N$ 3D Gaussians $\{G_i\}_{i=1}^N$ with means $\boldsymbol{\mu}_i$, covariances $\boldsymbol{\Sigma}_i$, opacities $\alpha_i$, and initial SH coefficients $\mathbf{c}_i$, plus $K$ observed camera views with poses $\{\mathbf{P}_k\}_{k=1}^K$ [G].
*   **Output:** Regularized SH coefficients $\hat{\mathbf{c}}_i$ for each Gaussian [S1, unofficial].

**Data Structures**
*   **SH Coefficients:** Stored as a flattened vector of size $(L+1)^2$ for degree $L$ [G].
*   **Directional Support Metric:** A scalar value per Gaussian per SH band, derived from the distribution of viewing directions relative to the Gaussian's local frame [S1, unofficial].

**Steps**
1.  **Evaluate Directional Support:** For each Gaussian $i$ and each SH band $l$, calculate a support metric based on the angular spread of viewing directions from the $K$ input cameras relative to the Gaussian's local frame [S1, unofficial].
2.  **Apply Support Criterion:** Compare the support metric against a threshold (implicitly defined in equation 25 of the source) [S1, unofficial].
    *   If the support is **insufficient** (weakly supported), apply strong regularization to the non-DC components ($l > 0$) of that band [S1, unofficial].
    *   If the support is **sufficient** (well-supported), apply weak regularization or none, preserving the directional detail [S1, unofficial].
3.  **Preserve DC Component:** The zeroth-order (DC, $l=0$) component is always preserved regardless of support, as it represents the average color [S1, unofficial].
4.  **Solve Regularized System:** Incorporate the adaptive regularization weights into the linear least squares (LLS) system used to estimate or refine the SH coefficients [S1, unofficial]. This improves the conditioning of the system, allowing faster convergence [S1, unofficial].

**Formulas**
*   **Regularization Weight:** The regularization strength $\lambda_{i,l}$ for Gaussian $i$ and band $l$ is determined by the support criterion [S1, unofficial].
    *   If support $< \text{threshold}$: $\lambda_{i,l} = \lambda_{\text{strong}}$ for $l > 0$ [S1, unofficial].
    *   If support $\ge \text{threshold}$: $\lambda_{i,l} = \lambda_{\text{weak}}$ for $l > 0$ [S1, unofficial].
    *   For $l=0$: $\lambda_{i,0} = 0$ [S1, unofficial].
*   **LLS System:** The system solved is of the form $(\mathbf{A}^\top \mathbf{A} + \mathbf{\Lambda}) \mathbf{c} = \mathbf{A}^\top \mathbf{b}$, where $\mathbf{\Lambda}$ is a diagonal matrix containing the adaptive regularization weights $\lambda_{i,l}$ [G].

**Parameters**
*   **Support Threshold:** Implicitly defined in equation (25) of the source [S1, unofficial]. Not given in the sources.
*   **SH Degree ($L$):** Typically 3 [S1, unofficial].

**Edge Cases and Pitfalls**
*   **Overfitting:** Without regularization, unconstrained SH coefficients lacking sufficient directional constraints overfit input views and generalize poorly to unseen viewpoints, producing noisy colors [S1, unofficial].
*   **Convergence Failure:** Unregularized systems may fail to converge within a reasonable iteration count (e.g., $T_{\text{max}}=300$) due to poor conditioning [S1, unofficial].
*   **Degenerate Input:** In scenes with very few views ($K$ small), many Gaussians will have insufficient support, leading to heavy suppression of non-DC components and potentially oversmoothed appearance [S1, unofficial].

**Pseudocode**
```python
import numpy as np

def adaptive_sh_regularization(gaussians, sh_degree, support_threshold):
    """
    Applies adaptive SH regularization based on directional support.
    
    Args:
        gaussians: List of dictionaries with keys:
            - 'cov': covariance matrix (3,3)
            - 'sh_coeffs': array of shape ((sh_degree+1)**2,)
            - 'view_dirs': list of viewing directions from input cameras (3,)
        sh_degree: Integer, degree of spherical harmonics
        support_threshold: Float, threshold for directional support metric
        
    Returns:
        Regularized SH coefficients for each Gaussian
    """
    num_bands = (sh_degree + 1) ** 2
    regularized_coeffs = []
    
    for g in gaussians:
        coeffs = g['sh_coeffs'].copy()
        regularization_weights = np.zeros(num_bands)
        
        # Calculate directional support for each degree l
        for l in range(sh_degree + 1):
            start_idx = l * l
            num_l_bands = 2 * l + 1
            
            # [G] The exact metric is implicit in source eq (25).
            # Implemented here as angular spread of viewing directions
            # projected onto the Gaussian's local frame.
            view_dirs = np.array(g['view_dirs'])
            if len(view_dirs) > 0:
                L_mat = np.linalg.cholesky(g['cov'])
                local_dirs = np.linalg.solve(L_mat, view_dirs.T).T
                local_dirs = local_dirs / np.linalg.norm(local_dirs, axis=1, keepdims=True)
                angles = np.arccos(np.clip(np.dot(local_dirs, local_dirs[0]), -1.0, 1.0))
                support_metric = np.std(angles)
            else:
                support_metric = 0.0
            
            # Apply regularization based on support
            if support_metric < support_threshold:
                # Weakly supported: strong regularization for non-DC
                if l > 0:
                    regularization_weights[start_idx:start_idx + num_l_bands] = 1.0
                else:
                    # DC component preserved
                    regularization_weights[start_idx:start_idx + num_l_bands] = 0.0
            else:
                # Well-supported: weak or no regularization
                regularization_weights[start_idx:start_idx + num_l_bands] = 0.0
        
        # [G] A and b are the observation matrix and target vector from the rendering pipeline [G].
        # Lambda is constructed from the computed weights.
        Lambda = np.diag(regularization_weights)
        # Solve normal equations for regularized least squares
        c = np.linalg.solve(A.T @ A + Lambda, A.T @ b)
        regularized_coeffs.append(c)
        
    return regularized_coeffs
```

## Operating characteristics
*   **Time Complexity:** Solving the global LLS system scales with the number of observations, but remains more efficient than iterative optimization of large parameter sets [S1, unofficial].
*   **Memory Complexity:** No significant additional memory overhead compared to standard SH storage, as regularization weights are computed on-the-fly [G].
*   **Measured Performance:** On the C3VD c t1 b scene with $K=7$ views and $L=3$, adaptive regularization improves test-view PSNR from 33.66 to 34.69 [S1, unofficial].
*   **Convergence:** With regularization, the PCG residual decreases rapidly; without it, the system fails to converge within $T_{\text{max}}=300$ iterations [S1, unofficial].
*   **Strengths:** Improves conditioning of the appearance estimation problem, reduces unstable view-dependent appearance, and yields more stable fidelity gains as the number of views increases [S1, unofficial].
*   **Limitations:** Requires careful tuning of the support threshold; may oversmooth appearance in regions with very sparse observations [S1, unofficial].
*   **When to Use:** Sparse or unevenly observed scenes, scenes with limited input views, or when stable generalization to unseen viewpoints is critical [S1, unofficial].

## Background
Adaptive SH Regularization was introduced in the context of CF-Splat (Closed-Form Triangle Splatting with Mesh Priors) [S1, unofficial]. It addresses the challenge of overfitting in SH-based appearance modeling when directional support is insufficient [S1, unofficial]. The method builds on the principle that SH coefficients should be constrained based on the available viewing directions, rather than being optimized unconstrained [S1, unofficial].
