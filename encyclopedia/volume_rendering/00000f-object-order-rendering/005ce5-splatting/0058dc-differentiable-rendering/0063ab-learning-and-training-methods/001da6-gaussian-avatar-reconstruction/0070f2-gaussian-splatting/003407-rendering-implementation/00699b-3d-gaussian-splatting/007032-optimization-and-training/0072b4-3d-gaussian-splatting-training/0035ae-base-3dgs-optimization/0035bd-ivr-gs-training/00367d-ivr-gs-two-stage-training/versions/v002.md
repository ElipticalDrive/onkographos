# iVR-GS Two-Stage Training

Also called: Base 3DGS + Editable Gaussian Optimization, Two-Stage Training for 3DGS

## Overview
iVR-GS Two-Stage Training is a training pipeline for the iVR-GS method that decouples the reconstruction of static scene geometry from the optimization of deformation-aware primitives. It solves the problem of inefficient and unstable joint optimization of base geometry and editable deformation fields in 3D Gaussian Splatting. Unlike one-stage training which optimizes all parameters from scratch, this method first establishes a robust base 3DGS model and then refines editable Gaussian primitives on top of it, accelerating convergence and reducing memory footprint while maintaining reconstruction quality [S1].

## How it works
The method consists of two sequential optimization phases.

**Inputs:**
- Initial 3D Gaussian point cloud (typically from COLMAP or similar structure-from-motion).
- Set of training images with camera poses.
- Target volume rendering configuration (transfer functions, etc.).

**Outputs:**
- A base 3DGS model with optimized positions, rotations, scales, colors (SH coefficients), and opacities.
- An optimized set of editable Gaussian primitives with deformation parameters.

**Data Structures:**
1. **Base 3DGS Model:** Standard 3DGS attributes: position $\mathbf{p}$, rotation quaternion $\mathbf{q}$, scale $\mathbf{s}$, spherical harmonics coefficients $\mathbf{c}$, and opacity $\alpha$.
2. **Editable Gaussian Primitives:** A subset or distinct set of Gaussians associated with deformation fields. These include the standard 3DGS attributes plus additional parameters for deformation (e.g., weights for radial features or deformation graph influences) as defined in the parent [iVR-GS Training](7578-ivr-gs-training.md).

**Steps:**

1. **Stage I: Base 3DGS Training**
   - Optimize the base 3DGS model to capture the basic scene geometry.
   - Loss function: Standard differentiable rendering loss (e.g., L1 + D-SSIM) between rendered images and ground truth.
   - Iterations: 30,000 [S1].
   - Goal: Produce a stable, high-fidelity representation of the static scene structure.

2. **Stage II: Editable Gaussian Optimization**
   - Initialize editable Gaussian primitives using the geometry from Stage I.
   - Optimize the deformation-related parameters of these primitives to enable scene editing.
   - Loss function: Standard rendering loss plus any specific deformation consistency losses defined in the iVR-GS framework.
   - Iterations: 10,000 [S1].
   - Goal: Align the deformed 3D Gaussians with the deformed radiance field, ensuring faithful capture of field-wise deformation [S1].

**Pseudocode:**

```python
def ivr_gs_two_stage_training(initial_points, training_images, num_iterations_stage1=30000, num_iterations_stage2=10000):
    # Stage I: Train Base 3DGS
    base_gaussians = initialize_3dgs(initial_points)
    for i in range(num_iterations_stage1):
        # Sample a random camera pose and render
        image = render(base_gaussians, training_images[i % len(training_images)])
        # Compute loss (L1 + D-SSIM)
        loss = compute_rendering_loss(image, training_images[i % len(training_images)].gt)
        # Backpropagate and update base gaussians
        base_gaussians.backward(loss)
        base_gaussians.step()
    
    # Stage II: Optimize Editable Gaussians
    # Initialize editable primitives based on base geometry
    editable_gaussians = initialize_editable_gaussians(base_gaussians)
    
    for i in range(num_iterations_stage2):
        # Sample a random camera pose and render deformed scene
        # Note: Deformation parameters are optimized here
        image = render_deformed(editable_gaussians, training_images[i % len(training_images)])
        # Compute loss including deformation consistency
        loss = compute_rendering_loss(image, training_images[i % len(training_images)].gt)
        # Backpropagate and update editable gaussians
        editable_gaussians.backward(loss)
        editable_gaussians.step()
        
    return base_gaussians, editable_gaussians
```

**Edge Cases and Pitfalls:**
- **Initialization:** Poor initialization in Stage II can lead to suboptimal deformation fields. Using the converged base model from Stage I is critical [S1].
- **Iteration Count:** The specified iteration counts (30k and 10k) are tuned for the reported datasets. Deviations may require re-tuning [S1].
- **Primitive Count:** One-stage training tends to use more primitives to achieve similar quality. Two-stage training achieves similar quality with fewer primitives [S1].

## Subtopics

### [Stage II: Align 3DGS with Radiance Field](20015-stage-ii-align-3dgs-with-radiance-field.md)
This method is the second stage of the iVR-GS training pipeline, designed to minimize the discrepancy between the rendering of deformed 3D Gaussian Splatting (3DGS) and the rendering of the deformed radiance field defined by radial features.

## Operating characteristics
- **Time Complexity:** Two-stage training uses 40,000 total iterations (30k + 10k), which is comparable to one-stage training (40,000 iterations). However, due to better initialization and separation of concerns, two-stage training reduces actual training time by over 2× compared to one-stage training [S1].
- **Memory Complexity:** Two-stage training uses fewer primitives to represent the scene, resulting in smaller file sizes (e.g., 8.8 MB vs 16.7 MB for VolVis scene in one source example) [S1].
- **Quality:** Maintains similar reconstruction quality (PSNR, LPIPS) to one-stage training [S1].
- **Strengths:** Faster optimization, smaller model size, better stability.
- **Limitations:** Requires two distinct training phases, potentially increasing implementation complexity.

## Background
The iVR-GS method was introduced in "iVR-GS: Inverse Volume Rendering for Explorable Visualization via Editable 3D Gaussian Splatting" [S1]. The two-stage training strategy was proposed to address the inefficiencies of optimizing editable Gaussian primitives from scratch, leveraging the established geometry of a base 3DGS model to accelerate convergence and reduce resource usage [S1].
