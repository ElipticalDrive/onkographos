# RLSplat

Also called: Resource-Linear Budget Control for Feed-forward 3D Gaussian Splatting

## Overview
RLSplat is a resource-linear, budget-controllable feed-forward 3D Gaussian Splatting (FF3DGS) framework that ensures inference latency, peak memory, and representation size all decrease linearly as the target Gaussian budget $B$ is reduced [S1, unofficial]. Unlike prior budget-controllable methods (e.g., EcoSplat, F4 Splat) that predict a dense set of candidates and prune them—resulting in nearly constant inference costs regardless of $B$—RLSplat learns a Gaussian allocation policy to distribute exactly $B$ Gaussians across scene anchors from the start, followed by a resource-linear decoder that refines them via local cross-attention [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Inputs:** A set of $V$ uncalibrated context images $\{I_i\}_{i=1}^V$ and a target integer Gaussian budget $B$.
- **Outputs:** A set of $B$ 3D Gaussians $\mathcal{G} = \{g_b\}_{b=1}^B$ and the context camera parameters $\{P_i\}_{i=1}^V$. Each Gaussian $g_b$ consists of a 3D center, opacity, scale, rotation, and color coefficients [S1, unofficial].

**Data Structures:**
1.  **Anchor Tokens:** The geometry backbone encodes the input images into $N$ anchor tokens $\{a_n\}_{n=1}^N$, where each token represents a local 3D region of the scene [S1, unofficial].
2.  **Allocation Vector:** A discrete allocation vector $\mathbf{k} \in \mathbb{Z}_{\ge 0}^N$ such that $\sum_{n=1}^N k_n = B$, where $k_n$ is the number of Gaussians assigned to anchor $n$ [S1, unofficial].
3.  **Gaussian Tokens:** Each anchor $n$ spawns $k_n$ Gaussian tokens. The total number of Gaussian tokens is exactly $B$ [S1, unofficial].

**Parameters:**
-   $B$: Target Gaussian budget. Typical evaluation values are 2K (2,048) and 64K [S1, unofficial]. On the ACID dataset with 8 views, $B=8,192$ (1,024 per view) is used [S1, unofficial]. On RE10K, $B=8,192$ is standard [S1, unofficial].
-   $K_{gs}$: Number of nearest Gaussian neighbors each token attends to during refinement. Default ablation value is 16 [S1, unofficial]. This can be changed at inference without retraining [S1, unofficial].
-   $K_{anc}$: Number of anchor neighbors used in the hierarchical neighbor search. Fixed value in ablations is 16 [S1, unofficial].
-   $C$: Number of rollouts (candidate allocations) drawn per training step for the Group Sequence Policy Optimization (GSPO) [S1, unofficial].

**Algorithm Steps:**

1.  **Geometry Encoding:** Given $\{I_i\}$ and $B$, a geometry backbone (e.g., Burzio et al., 2026) encodes the images into $N$ anchor tokens $\{a_n\}_{n=1}^N$ and predicts camera parameters $\{P_i\}_{i=1}^V$ [S1, unofficial].
2.  **Gaussian Allocation:** A policy $\pi_\psi$ assesses the local significance of each anchor (based on image features like texture complexity) to predict a discrete allocation $\mathbf{k}$ such that $\sum k_n = B$ [S1, unofficial]. This policy is trained using Group Sequence Policy Optimization (GSPO) [S1, unofficial].
3.  **Token Spawning:** Each anchor $n$ spawns $k_n$ Gaussian tokens. The total number of Gaussian tokens is exactly $B$ [S1, unofficial].
4.  **Resource-Linear Decoding:**
    a.  **Initialization:** The decoder instantiates initial Gaussian parameters (center, opacity, scale, rotation, color) from the spawned tokens [S1, unofficial].
    b.  **Hierarchical Neighbor Search:** For each Gaussian token, find its $K_{gs}$ nearest Gaussian neighbors. This is done efficiently using a hierarchical neighbor search over anchor tokens (using $K_{anc}$ anchor neighbors) to identify candidate Gaussian neighborhoods [S1, unofficial].
    c.  **Local Refinement:** Refine each Gaussian token through local cross-attention over its $K_{gs}$ nearest Gaussian tokens [S1, unofficial]. This step ensures consistency with neighbors and corrects for Gaussians leaving their anchor's cell [S1, unofficial].
5.  **Output:** The final set of $B$ Gaussians $\mathcal{G}$ and camera parameters $\{P_i\}$ are returned [S1, unofficial].

**Training Objective (GSPO):**
To optimize the policy $\pi_\psi$ over non-differentiable discrete allocations, GSPO is used [S1, unofficial]:
1.  Draw $C$ rollouts $\mathbf{k}^{(c)} \sim \pi_{\text{old}} = \text{Mult}(B, \text{sg}(\mathbf{p}))$ for $c \in \{1, \dots, C\}$, where $\mathbf{p}$ are the policy probabilities and $\text{sg}(\cdot)$ stops gradients [S1, unofficial].
2.  For each rollout, generate the 3DGS representation $\mathcal{G}^{(c)}$ and render an image $\hat{I}^{(c)}$ at novel target views [S1, unofficial].
3.  Compute the reconstruction loss $\mathcal{L}_{\text{recon}}$ against the ground-truth image $I$ without gradient tracking. This loss serves as the reward signal [S1, unofficial].
4.  Additional losses include a projection loss $\mathcal{L}_{\text{proj}}$ (tying anchors to image regions), an offset loss $\mathcal{L}_{\text{offset}}$, and a Voronoi loss $\mathcal{L}_{\text{vor}}$ [S1, unofficial]. Removing $\mathcal{L}_{\text{proj}}$ causes training to fail entirely [S1, unofficial].

## Operating characteristics
-   **Time Complexity:** The decoding cost is $O(B \cdot K_{gs})$, scaling linearly with the Gaussian budget $B$, compared to global self-attention which costs $O(B^2)$ [S1, unofficial]. The hierarchical neighbor search is significantly faster than exact search; at 65,536 Gaussians, it is 27× faster (8.1 ms vs. 219.6 ms) [S1, unofficial].
-   **Memory Complexity:** Peak memory scales linearly with $B$ [S1, unofficial]. At 2K Gaussians, RLSplat uses 9.6× less peak memory than F4 Splat [S1, unofficial].
-   **Performance:**
    -   On ACID (B=8,192): PSNR 22.84 dB, SSIM 0.643, LPIPS 0.353 [S1, unofficial].
    -   On RE10K (B=8,192): Full-view PSNR 26.51 dB, compared to 23.42 dB for F4 Splat and 21.82 dB for EcoSplat [S1, unofficial].
    -   At 2K Gaussians, RLSplat achieves higher PSNR than F4 Splat while running 4.1× faster [S1, unofficial].
-   **Strengths:** Resource-linear scaling allows adaptation to diverse resource budgets (AR/VR, robotics) without retraining. Better allocation of Gaussians to high-frequency structures (e.g., thin stair balusters) leads to superior local and full-view PSNR [S1, unofficial].
-   **Limitations:** Requires training with GSPO, which involves non-differentiable discrete allocations. The hierarchical neighbor search adds implementation complexity compared to simple global attention [S1, unofficial].

## Background
RLSplat was proposed by Bae, Park, and Kim from KAIST [S1, unofficial]. It addresses the limitations of prior budget-controllable FF3DGS methods like EcoSplat and F4 Splat, which predict dense sets of Gaussians and prune them, resulting in constant inference costs [S1, unofficial]. The method builds on feed-forward 3D Gaussian Splatting frameworks and uses Group Sequence Policy Optimization (GSPO) for policy training [S1, unofficial]. It is used for applications requiring limited resource budgets, such as AR/VR, robotics, and digital content creation [S1, unofficial].
