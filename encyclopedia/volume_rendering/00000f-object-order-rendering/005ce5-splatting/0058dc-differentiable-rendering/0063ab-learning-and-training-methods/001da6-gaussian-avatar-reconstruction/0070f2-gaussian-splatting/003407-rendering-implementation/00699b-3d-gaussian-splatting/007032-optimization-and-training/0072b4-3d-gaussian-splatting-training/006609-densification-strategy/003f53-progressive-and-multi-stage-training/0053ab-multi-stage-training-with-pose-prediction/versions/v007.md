# Multi-stage Training with Pose Prediction

Also called: FineSplat training phases, Training and Inference Protocol, Two-stage Training with Pose-free Inference

## Overview
Multi-stage training with pose prediction addresses the instability of jointly optimizing camera poses and 3D Gaussian attributes in feed-forward novel view synthesis. It decouples the learning process into sequential phases: first establishing a robust geometric prior with ground-truth or stabilized poses, then refining the scene representation, and finally enabling end-to-end pose-free inference. This approach sets itself apart from single-stage training by preventing pose errors from corrupting the Gaussian density distribution during early optimization [S1, S2, unofficial]. It differs from pure curriculum learning by explicitly freezing and unfreezing specific model branches (pose estimator vs. Gaussian decoder) rather than just changing input resolution [S1, S2, unofficial].

## How it works
The method partitions optimization into discrete stages $S_1, \dots, S_k$. Each stage modifies which parameters are trainable and which loss functions are active. The Gaussian set $\mathcal{G}$ is defined as in [Densification Strategy](6234-densification-strategy.md).

### Inputs and Outputs
*   **Inputs:** Input views $\{I_v\}_{v=1}^V$ with associated intrinsics $K_v$ and poses $P_v$ (GT or predicted). Target views $I_{tgt}$ for supervision.
*   **Outputs:** Refined Gaussian set $\mathcal{G}$ and, in later stages, predicted camera poses $\hat{P}$ for target views.

### Data Structures
The model typically consists of:
1.  **Pose Estimator/Reconstructor:** Outputs camera poses $\hat{P}$ and potentially scene scale normalization factor $s_{norm}$ [S1, S2, unofficial].
2.  **Gaussian Decoder/Refiner:** Takes features and poses to output Gaussian attributes $\mathcal{G} = \{\mu, \sigma, \mathbf{c}, \alpha\}$ [S1, S2, unofficial].
3.  **Scene Representation:** The set of Gaussians $\mathcal{G}$, where each Gaussian $g_i$ has mean $\mu_i$, covariance $\Sigma_i$ (parameterized by scale $s_i$ and rotation $q_i$), spherical harmonic coefficients $\mathbf{c}_i$, and opacity $\alpha_i$ [S1, S2, unofficial].

### Numbered Steps

**Stage 1: Initial Geometry and Pose Learning**
1.  **Setup:** Initialize the pose estimator and Gaussian decoder. Use ground-truth (GT) poses for input views if available, or predict them [S1, S2, unofficial].
2.  **Forward Pass:** Render input and sampled target views using the current $\mathcal{G}$ and predicted/GT poses.
3.  **Loss Calculation:** Compute reconstruction loss $\mathcal{L}_{recon}$ (e.g., L1, MSE, LPIPS) between rendered and GT target views [S1, S2, unofficial]. Compute camera loss $\mathcal{L}_{cam}$ if poses are predicted [S1, S3, unofficial].
4.  **Update:** Update the attribute branch’s last $K$ Transformer blocks and the Gaussian decoder. In some variants, update the pose estimator as well [S1, S2, unofficial].
5.  **Iteration:** Repeat for $N_1$ iterations (e.g., 120K for FineSplat, 40K for RLSplat) [S1, S3, unofficial].

**Stage 2: Pose-Free Refinement and Correction**
1.  **Freeze:** Freeze the Stage 1 pose estimator/geometry backbone to prevent pose drift from affecting the refined geometry [S1, S2, unofficial].
2.  **Setup:** Use GT poses for input views to ensure the Gaussian decoder learns to correct geometric errors independently of pose inaccuracies [S1, unofficial].
3.  **Forward Pass:** Render views. In iterative refiners (e.g., FineSplat), perform $T$ steps (e.g., $T=4$). Detach tokens between steps to prevent gradient flow across refinement steps [S1, unofficial].
4.  **Loss Calculation:** Compute loss averaged over all refinement steps $i=0 \dots T$:
    $$ \mathcal{L} = \frac{1}{T} \sum_{i=1}^{T} \left( \mathcal{L}_2(\hat{I}^{(i)}, I) + \lambda \mathcal{L}_{perc}(\hat{I}^{(i)}, I) \right) $$
    where $\hat{I}^{(i)}$ is the render at step $i$, $\mathcal{L}_2$ is MSE, $\mathcal{L}_{perc}$ is VGG-19 perceptual loss, and $\lambda = 0.2$ [S1, unofficial].
5.  **Update:** Update the Gaussian decoder/refiner. In RLSplat, this stage introduces a policy head for Gaussian allocation [S3, unofficial].
6.  **Iteration:** Repeat for $N_2$ iterations (e.g., 80K for FineSplat, 5K for RLSplat) [S1, S3, unofficial].

**Stage 3: End-to-End Pose-Free Fine-Tuning**
1.  **Unfreeze:** Unfreeze all parameters, including the pose estimator and Gaussian head [S1, unofficial].
2.  **Setup:** Enter fully pose-free setting. Predict both context and target cameras. No camera loss is used [S1, unofficial].
3.  **Forward Pass:** Render views using predicted poses.
4.  **Loss Calculation:** Supervise the Stage 1 Gaussians and final output. Loss is averaged over steps $i=0 \dots T$ [S1, unofficial].
5.  **Update:** Update the full model [S1, unofficial].
6.  **Iteration:** Repeat for $N_3$ iterations (e.g., 10K for FineSplat) [S1, unofficial].

**Inference (Pose-Free)**
1.  **Pose Prediction:** Use the trained geometry branch to predict camera poses $\hat{P}$ for target views [S2, unofficial].
2.  **Normalization:** Normalize translations by $s_{norm}$ (derived from context camera distances or depth) [S1, S2, unofficial].
3.  **Rendering:** Render input views for refinement feedback if a refiner is used. Update scene attributes $\mathcal{G}$ while keeping network weights fixed [S2, unofficial].

### Formulas
*   **Reconstruction Loss (FineSplat/RLSplat):**
    $$ \mathcal{L}_{recon} = \mathcal{L}_{MSE}(\hat{I}, I) + \lambda \mathcal{L}_{LPIPS}(\hat{I}, I) $$
    [S1, S3, unofficial]
*   **Camera Loss (RLSplat):**
    Supervises translation, rotation, and field-of-view of predicted context cameras [S3, unofficial].
*   **Projection Loss (RLSplat):**
    Reprojects anchor Gaussians toward source image patch with cheirality penalty:
    $$ \mathcal{L}_{proj} = \mathcal{L}_{reproj} + \mathcal{L}_{cheirality} $$
    [S3, unofficial]
*   **Policy Loss (RLSplat):**
    $$ \mathcal{L}_{policy} = -J_{policy} $$
    [S3, unofficial]
*   **Total Loss (RLSplat):**
    $$ \mathcal{L}_{total} = \mathcal{L}_{recon} + \mathcal{L}_{cam} + \mathcal{L}_{proj} + \mathcal{L}_{vor} + \mathcal{L}_{offset} + \mathcal{L}_{policy} $$
    [S3, unofficial]

### Parameters
*   **Optimization:** AdamW with $\beta_1=0.9, \beta_2=0.95$, weight decay 0.05 (multi-dimensional params only), gradient clipping max norm 1.0, bfloat16 mixed precision [S1, unofficial].
*   **Learning Rates:**
    *   Stage 1: $2 \times 10^{-5}$, no warm-up, cosine decay [S1, unofficial].
    *   Stage 2: $1 \times 10^{-4}$, 200-iteration linear warm-up, constant until 80%, cosine decay [S1, unofficial].
    *   End-to-End: $2 \times 10^{-5}$, 200-iteration linear warm-up, cosine decay [S1, unofficial].
*   **Loss Weights:** $\lambda = 0.2$ for perceptual loss [S1, unofficial].
*   **Budgets (RLSplat):** Gaussian budget sampled from $[2048, 16384V]$ where $V$ is input views [S3, unofficial].
*   **Steps:** $T=4$ refinement steps in FineSplat [S1, unofficial].

### Edge Cases and Pitfalls
*   **Pose Drift:** If Stage 1 is not sufficiently stable, Stage 2 refinement may amplify errors. Freezing the pose estimator in Stage 2 mitigates this [S1, unofficial].
*   **Cheirality:** Gaussians behind the camera cause artifacts. The projection loss in RLSplat includes a cheirality penalty to prevent this [S3, unofficial].
*   **Scale Normalization:** Scene scale is not fixed by input images. Methods use context camera distances (FineSplat) or estimated depth (ZipSplat) to normalize translations [S1, unofficial]. Failure to normalize leads to inconsistent scene scales across datasets [S1, S2, unofficial].
*   **Gradient Flow:** In iterative refiners, tokens must be detached between steps to ensure each step learns to improve the state it receives, preventing vanishing/exploding gradients across long chains [S1, unofficial].

## Subtopics

### RLSplat Training
RLSplat uses a two-stage training process focused on budget control. Stage 1 (Base Training) trains the geometry backbone and decoder with random Gaussian allocations for 40,000 steps, sampling budgets over $[2048, 16384V]$ to expose the decoder to diverse allocation counts [S3, unofficial]. Stage 2 (Policy Training) adds a policy head initialized to uniform probabilities and fine-tunes the entire model with policy loss $\mathcal{L}_{policy}$ for 5,000 steps. Budgets are skewed toward the lower end during this stage [S3, unofficial]. It differs from FineSplat by explicitly optimizing a discrete allocation policy via GSPO rather than iterative refinement [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** Multi-stage training increases total training time compared to single-stage methods. FineSplat requires ~210K iterations (120K + 80K + 10K) [S1, unofficial]. RLSplat requires 45K steps [S3, unofficial].
*   **Memory Complexity:** Similar to standard 3DGS, but iterative refinement (FineSplat) may require storing intermediate states for $T$ steps, increasing VRAM usage during training [S1, unofficial].
*   **Performance:** Enables high-quality novel view synthesis with predicted poses, reducing the need for GT camera data at inference [S1, S2, unofficial]. RLSplat achieves superior performance at low Gaussian budgets compared to fixed-budget methods [S3, unofficial].
*   **Strengths:** Robustness to pose initialization errors; ability to refine geometry independently of pose; flexible budget control (RLSplat) [S1, S2, S3, unofficial].
*   **Limitations:** Complex training pipeline; requires careful tuning of stage transitions and learning rates; inference may be slower if iterative refinement is used [S1, S2, unofficial].
*   **When to Use:** When GT poses are unavailable or noisy; when high-fidelity detail is needed beyond what a single-stage model can achieve; when resource constraints require dynamic Gaussian allocation [S1, S2, S3, unofficial].
*   **When Not to Use:** When training time is limited; when GT poses are available and high-quality, making pose-free training unnecessary [S1, unofficial].

## Background
Multi-stage training with pose prediction originated in feed-forward 3D Gaussian Splatting methods to address the challenge of learning camera poses and scene geometry simultaneously. FineSplat introduced the three-phase approach (Stage 1: pixel-aligned, Stage 2: patch-aligned refinement, Stage 3: end-to-end pose-free) to stabilize training [S1, unofficial]. InfiniSplat v2 adopted a similar two-stage protocol with pose-free inference using normalized scene scales [S2, unofficial]. RLSplat extended the concept to include a policy-based allocation strategy, using base training to expose the decoder to varied budgets before policy optimization [S3, unofficial]. These methods build on the foundational 3DGS optimization framework [Densification Strategy](6234-densification-strategy.md) and the need for robust feed-forward reconstruction [15018-multi-stage-training-with-pose-prediction.md].
