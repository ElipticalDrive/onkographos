# Textured Gaussians

Also called: Textured Gaussas

## Overview
Textured Gaussians replace spherical harmonic (SH) coefficients with explicit 2D textures mapped onto each 3D Gaussian primitive to resolve artifacts in semi-transparent scenes and enable high-frequency appearance details without increasing the number of primitives [S1, unofficial]. Unlike standard 3D Gaussian Splatting which uses low-order SH for view-dependent color, this method decouples geometric representation from high-fidelity appearance, allowing for detailed texture sampling based on local UV coordinates [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of 3D Gaussians $\{G_i\}$, where each $G_i$ contains position $\mathbf{\mu}_i$, covariance $\mathbf{\Sigma}_i$, opacity $\alpha_i$, and a unique 2D texture map $T_i$ along with UV coordinates $\mathbf{u}_i$.
*   **Output:** A rendered image where each pixel color is determined by alpha-blending contributions sampled from the respective Gaussian textures.

**Data Structures:**
Each Gaussian primitive $i$ stores:
1.  **Geometric Parameters:** $\mathbf{\mu}_i \in \mathbb{R}^3$, $\mathbf{\Sigma}_i \in \mathbb{R}^{3 \times 3}$ (or its Cholesky decomposition), $\alpha_i \in [0, 1]$.
2.  **Appearance Parameters:**
    *   $T_i$: A 2D texture map (e.g., RGB image) associated with the primitive.
    *   $\mathbf{u}_i \in [0, 1]^2$: Local UV coordinates mapping the 3D surface point to the 2D texture space.

**Rendering Steps:**
1.  **Projection:** For each camera view, project the 3D Gaussians to 2D screen space. Compute the 2D covariance matrix $\mathbf{\Sigma}'_i$ using the Jacobian of the projection transformation [G].
2.  **Sorting:** Sort the projected Gaussians front-to-back based on their depth relative to the camera.
3.  **Rasterization:** For each pixel $p$, iterate through the sorted Gaussians.
4.  **Contribution Calculation:**
    *   Calculate the 2D Gaussian weight $w_i(p)$ at pixel $p$ using the projected covariance $\mathbf{\Sigma}'_i$.
    *   Determine the UV coordinate $\mathbf{u}_i(p)$ corresponding to the intersection of the ray and the Gaussian's local surface. This typically involves mapping the 3D position of the Gaussian center or the splat center to the UV space [S1, unofficial].
    *   Sample the color $c_i$ from the texture $T_i$ using $\mathbf{u}_i(p)$: $c_i = T_i(\mathbf{u}_i(p))$.
    *   Compute the transmittance and color contribution:
        $$ c_i(p) = c_i \cdot w_i(p) $$
        $$ \alpha_i(p) = \alpha_i \cdot w_i(p) $$
5.  **Alpha Blending:** Accumulate the color and opacity using front-to-back blending:
    $$ C(p) = \sum_{i \in \text{sorted}} c_i(p) \prod_{j=1}^{i-1} (1 - \alpha_j(p)) $$

**Parameters:**
*   Texture resolution: Not given in the sources.
*   UV mapping strategy: Not given in the sources.

**Edge Cases and Pitfalls:**
*   **UV Mapping Ambiguity:** If the UV mapping is not well-defined for semi-transparent or volumetric primitives, sampling may produce artifacts. The method assumes a valid local UV coordinate exists for each primitive [S1, unofficial].
*   **Texture Memory:** Storing a unique texture per Gaussian increases memory usage significantly compared to SH coefficients.

## Subtopics

### Texture-GS
A method that disentangles the geometry and appearance of 3D Gaussian Splatting [S2, unofficial]. It learns a UV mapping network for points near the underlying surface, enabling manipulation such as texture painting and texture swapping [S2, unofficial].

### 3DGM
A method that represents a 3D scene with a proxy mesh with fixed UV mapping where Gaussians are stored on the texture map [S2, unofficial]. This disentangled representation allows for animation and texture editing [S2, unofficial].

## Operating characteristics
*   **Memory:** Higher memory usage than SH-based methods due to the storage of explicit 2D textures for each primitive. The exact overhead depends on texture resolution and the number of primitives.
*   **Compute:** Rendering requires texture sampling operations, which are generally efficient on modern GPUs but add a lookup cost compared to simple vector arithmetic used in SH evaluation.
*   **Quality:** Enables high-frequency appearance details and resolves artifacts in semi-transparent scenes that SH coefficients struggle with [S1, unofficial].
*   **Use Cases:** Scenes requiring detailed textures, semi-transparent objects, or where texture editing/manipulation is desired.

## Background
Textured Gaussians were introduced as an extension to 3D Gaussian Splatting to address limitations in representing complex, high-frequency, and semi-transparent appearances using spherical harmonics [S1, unofficial]. The approach abandons SH coefficients in favor of explicit 2D textures, allowing for more flexible and detailed appearance modeling [S1, unofficial].
