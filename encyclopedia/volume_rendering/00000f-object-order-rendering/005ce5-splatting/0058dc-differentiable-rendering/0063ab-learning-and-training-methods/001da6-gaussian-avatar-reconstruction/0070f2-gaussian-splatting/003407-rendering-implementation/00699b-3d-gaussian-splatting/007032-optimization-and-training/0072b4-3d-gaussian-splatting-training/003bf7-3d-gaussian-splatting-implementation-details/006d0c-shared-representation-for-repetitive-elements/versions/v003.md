# Shared Representation for Repetitive Elements

Also called: Instance Sharing, Shared 3DGS

## Overview
This method improves the 3D reconstruction of repetitive objects by creating a single shared Gaussian representation for all instances of the same object type [S1]. It allows information propagation, such as geometry completion and detail propagation, across instances while handling appearance differences via per-instance offsets [S1]. Unlike standard 3D Gaussian Splatting where each instance is independent, this method shares geometry parameters across instances, improving reconstruction quality for occluded or low-quality regions by leveraging multi-view information from all instances [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Initial camera poses, an initial set of 3D Gaussians for each instance, and a pre-identification of instances belonging to the same object type [S1].
*   **Outputs:** A shared set of 3D Gaussian parameters (position, scale, rotation, opacity, shared SH coefficients) and per-instance parameters (rigid transformation, SH offset coefficients) [S1].

**Data Structures:**
The method maintains two primary data structures for each object type:
1.  **Shared Representation:** A list of Gaussian primitives. Each primitive stores:
    *   $\mathbf{p}_{\text{shared}}$: Position (3 floats) [S1].
    *   $\mathbf{s}_{\text{shared}}$: Scale (3 floats) [S1].
    *   $\mathbf{q}_{\text{shared}}$: Rotation (4 floats, quaternion) [S1].
    *   $\alpha_{\text{shared}}$: Opacity (1 float) [S1].
    *   $\mathbf{c}_{\text{shared}}^{\ell m}$: Shared Spherical Harmonics (SH) coefficients for degree $\ell$ and order $m$ (3 floats per coefficient) [S1].
2.  **Instance Parameters:** For each instance $i$ of the object type:
    *   $\mathbf{T}_i$: Rigid transformation matrix (4x4) mapping instance space to template space [S1].
    *   $\mathbf{c}_{\text{offset}, i}^{\ell m}$: Per-instance SH offset coefficients (3 floats per coefficient) [S1].

**Numbered Steps:**
1.  Transform all instance Gaussians into a common template coordinate system using computed rigid transformations [S1].
2.  Create the initial shared representation by taking the union of all instances in this common coordinate system [S1].
3.  For each Gaussian primitive, share all parameters (position, scale, rotation, opacity) across all instances of the same object [S1].
4.  Decompose Spherical Harmonics (SH) coefficients into a shared component and an instance-specific offset term [S1].
5.  Optimization: Replace each instance with a reference to the shared representation [S1]. Apply per-instance geometric transform and SH offset during rendering [S1]. Propagate gradients from all instances to the shared representation [S1]. Jointly optimize shared geometry, SHs, and pose parameters using gradient descent [S1].

**Formula:**
$$
\mathbf{c}^{\ell m} = \lambda \mathbf{c}_{\text{shared}}^{\ell m} + (1 - \lambda) \mathbf{c}_{\text{offset}}^{\ell m}
$$
where $\ell$ is the SH degree, $m$ is the order, $\mathbf{c}_{\text{shared}}^{\ell m}$ is the shared SH coefficient, $\mathbf{c}_{\text{offset}}^{\ell m}$ is the per-instance offset coefficient, and $\lambda$ is a mixing weight set to 0.8 [S1].

**Parameters:**
*   $\lambda$: Mixing weight for SH decomposition, set to 0.8. Controls the balance between shared appearance and instance-specific appearance [S1].
*   $\lambda_{l1}$: Weight for the $\ell_1$ penalty on offset parameters. Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Symmetric Objects:** For symmetric objects (e.g., pawns in the Chessboard scene), the matching procedure finds correspondences based on appearance. Multiple rigid transformations are valid depending on the type of symmetry [S1].
*   **Textureless Objects:** Similar to symmetric objects, multiple valid rigid transformations may exist [S1].
*   **Resolution:** The method handles this by finding one valid transformation during registration, which is sufficient for fine-tuning the shared representation [S1].
