# GlobalSplat

Also called: GlobalSplat: Efficient Feed-Forward 3D Gaussian Splatting via Global Scene Tokens

## Overview
GlobalSplat is a feed-forward 3D Gaussian Splatting framework that aligns multi-view inputs into a fixed set of global latent scene tokens before decoding explicit 3D geometry, preventing representation bloat and ensuring global consistency [S1]. Unlike sibling methods such as [AnySplat Pipeline](12847-anysplat-pipeline.md) or [C3G](12847-anysplat-pipeline.md) which rely on full self-attention or single-Gaussian decoding, GlobalSplat uses an iterative, disentangled dual-branch architecture and a coarse-to-fine capacity curriculum to achieve a superior quality-efficiency trade-off in large-context settings [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $C$ input views $\mathcal{I} = \{I_i\}_{i=1}^C$, each with associated camera poses $T_i$ and intrinsics $\kappa_i$.
*   **Output:** A fixed set of $N$ 3D Gaussians $\{g_k\}_{k=1}^N$, where each Gaussian $g_k$ is defined by mean $\mu_k$, scale $s_k$, rotation $r_k$, opacity $\alpha_k$, and spherical harmonic coefficients $c_k$.

**Data Structures:**
1.  **Latent Tokens:** A set of $M=2048$ learnable latent tokens $l_j \in \mathbb{R}^{512}$ and learnable register tokens [S1].
2.  **Input Patches:** Image patches of size $8 \times 8$. For an input image resized to $256 \times 256$, there are $32 \times 32 = 1024$ patches per view [S1].
3.  **Gaussian Candidates:** For each latent token $p$, the decoder predicts $K_s=16$ candidates. The attributes for token $p$ are stored as:
    *   $\mathbf{X}_p \in \mathbb{R}^{16 \times 3}$: Means
    *   $\mathbf{S}_p \in \mathbb{R}^{16 \times 3}$: Scales (log-space)
    *   $\mathbf{R}_p \in \mathbb{R}^{16 \times 6}$: Rotations (6D parameterization)
    *   $\mathbf{O}_p \in \mathbb{R}^{16 \times 1}$: Opacity (logit-space)
    *   $\boldsymbol{\ell}_p \in \mathbb{R}^{16 \times 1}$: Importance scores (gates)
    *   $\mathbf{C}_p \in \mathbb{R}^{16 \times (3 D_{\text{SH}})}$: Appearance coefficients, where $D_{\text{SH}} = (3+1)^2 = 16$ [S1].

**Preprocessing:**
1.  **Scene Normalization:**
    *   Compute the canonical frame origin: $\bar{o} = \frac{1}{C} \sum_{i=1}^C o_i$ [S1].
    *   Compute axes by averaging camera viewing directions and re-orthonormalizing. Let $T_{\text{avg}}$ be the resulting average pose [S1].
    *   Transform all cameras: $\hat{T}_i = T_{\text{avg}}^{-1} T_i$ [S1].
    *   Compute scene scale: $s = \max_{a,b} \|\hat{o}_a - \hat{o}_b\|_2$ [S1].
    *   Scale camera translations: $\tilde{o}_i = \frac{\hat{o}_i}{s}$ [S1].
2.  **Image Preprocessing:**
    *   Resize image to height 256 preserving aspect ratio.
    *   Round width to a multiple of patch size 8.
    *   Update intrinsics accordingly.
    *   Apply centered square crop.
    *   Final resize to $256 \times 256$ [S1].

**Algorithm:**

1.  **Input Context Construction:**
    *   Extract RGB patch features $u_{i,p}^{\text{rgb}}$ for each view $i$ and patch $p$ [S1].
    *   Compute dense Plücker-ray features and patchify to get $r_{i,p}$ [S1].
    *   Map ray features: $\hat{r}_{i,p} = W_{\text{ray}} r_{i,p}$ [S1].
    *   Compute per-view camera code $e_i$ using Fourier positional encoding for center $o_i$ and MLP for intrinsics $\kappa_i$:
        $$e_i = W_{\text{proj}}\Big ([\text{MLP}_{K}(\phi (\kappa _i));\ \text{PE}(o_i)]\Big )$$ [S1].
    *   Add camera code to patches: $u_{i,p}^{\text{cam}} = \hat{r}_{i,p} + e_i$ [S1].
    *   Concatenate to form input context: $u_{i,p} = [u_{i,p}^{\text{cam}} ; u_{i,p}^{\text{rgb}}]$ [S1].

2.  **Dual-Branch Iterative Encoder:**
    *   Initialize latent tokens $l_j^{(0)}$ [S1].
    *   For each encoder block $b \in \{0, \dots, B-1\}$ with $B=4$:
        *   Project latent tokens into geometry and appearance streams:
            $$f_{\text{geo}}^{(b)}, f_{\text{app}}^{(b)} = \text{Proj}_{\text{geo}}(l^{(b)}), \text{Proj}_{\text{app}}(l^{(b)})$$ [S1].
        *   For each branch $i \in \{\text{geo}, \text{app}\}$:
            *   Apply cross-attention with input patches $x$ (the collection of all $u_{i,p}$):
                $$f_{i}^{(b, \text{cross})} = \text{CrossAtt}_{i}(x, f_{i}^{(b)})$$ [S1].
            *   Apply $L=2$ self-attention blocks:
                $$f_{i}^{(b+1)} = \text{SelfAtt}_{i}(\dots \text{SelfAtt}_{i}(f_{i}^{(b, \text{cross})}) \dots)$$ [S1].
        *   Fuse streams using a 2-layer mixer MLP to update latent tokens for the next block:
            $$l^{(b+1)} = \text{MLP}(\text{Concat}(f_{\text{geo}}^{(b+1)}, f_{\text{app}}^{(b+1)}))$$ [S1].

3.  **Decoder Candidate Prediction:**
    *   For each latent token $p$ in the final latent set $l^{(B)}$, predict the 16 candidates for geometry ($\mathbf{X}_p, \mathbf{S}_p, \mathbf{R}_p, \mathbf{O}_p, \boldsymbol{\ell}_p$) and appearance ($\mathbf{C}_p$) using the dual-branch decoder [S1].

4.  **Coarse-to-Fine Merging (Inference/Training):**
    *   The model operates in stages $s \in \{0, 1, 2, 3, 4\}$. The final model uses stage $s=3$ [S1].
    *   At stage $s$, partition the 16 candidates into $G = 2^s$ groups, each of size $b_s = 16/G$ [S1].
    *   For each group $g$ and candidate $i$ within that group:
        *   Compute normalized gate weights using temperature $\tau$:
            $$w_{p,g,i} = \frac{\exp (\ell _{p,g,i}/\tau )}{\sum _{j=1}^{b_s}\exp (\ell _{p,g,j}/\tau )}$$ [S1].
        *   Merge attributes for any attribute $z$ (e.g., mean, scale, color):
            $$\bar{\mathbf{z}}_{p,g} = \sum _{i=1}^{b_s} w_{p,g,i}\,\mathbf{z}_{p,g,i}$$ [S1].
    *   The final set of Gaussians consists of $M \times G$ merged Gaussians [S1].

5.  **Gaussian Parameterization (Initialization):**
    *   Means: Initialized with a fixed forward offset of 1.5 [S1].
    *   Scales: Predicted in log space as an offset from -2 [S1].
    *   Opacity: Predicted in logit space as an offset from -5 [S1].
    *   Rotations: Continuous 6D parameterization as residual offsets from a static rotation [S1].

**Training Objective:**
The total loss is $\mathcal{L} = \lambda_{\text{ren}}\mathcal{L}_{\text{ren}} + \lambda_{\text{con}}\mathcal{L}_{\text{con}} + \lambda_{\text{reg}}\mathcal{L}_{\text{reg}}$ [S1].
*   **Rendering Loss:** $\mathcal{L}_{\text{ren}} = \|I_t - \hat{I}_t\|_2^2 + \lambda_{\text{perc}}\mathcal{L}_{\text{perc}}(I_t, \hat{I}_t)$ [S1].
*   **Self-Supervised Consistency Loss:** Partition views into $\mathcal{I}_a, \mathcal{I}_b$.
    $$\mathcal{L}_{\text{con}} = \|O(\mathcal{I}_a) - \text{sg}(O(\mathcal{I}_b))\|_2^2 + \|D(\mathcal{I}_a) - \text{sg}(D(\mathcal{I}_b))\|_2^2$$ [S1], where $O$ and $D$ are rendered opacity and depth maps.
*   **Regularization Loss:** $\mathcal{L}_{\text{reg}} = \lambda_{\text{thr}}\mathcal{L}_{\text{thr}} + \lambda_{\text{fru}}\mathcal{L}_{\text{fru}}$ (soft thresholding and frustum constraint) [S1].

**Rendering:**
Gaussians are sorted by depth and rendered via front-to-back alpha blending:
$$C = \sum _{i=1}^{M} c_i \alpha '_i \prod _{j=1}^{i-1} (1 - \alpha '_j)$$ [S1], where $\alpha '_i$ is the product of base opacity $\alpha_i$ and projected 2D Gaussian density [S1].

## Operating characteristics
*   **Complexity:** The number of Gaussians is fixed at $N = 16,384$ (range 2K-32K) regardless of the number of input views [S1].
*   **Performance:** On RealEstate10K with 24 input views, GlobalSplat achieves 28.5 PSNR with 16K Gaussians, 4 MB disk size, 1.79 GB peak GPU memory, and <78 ms inference time [S1].
*   **Scaling:** The method maintains a strict, view-invariant budget of Gaussians, preventing the representation bloat seen in dense pipelines as input views increase [S1].
*   **Strengths:** Ultra-low GPU memory usage, minimal disk size, and extremely fast inference times compared to baselines like C3G or NoPoSplat [S1].
*   **Limitations:** Relies on a fixed number of latent tokens and candidates, which may limit the complexity of extremely dense scenes compared to adaptive methods, though the coarse-to-fine curriculum mitigates this [S1].

## Background
GlobalSplat was introduced by R. Itkin et al. in the paper "GlobalSplat: Efficient Feed-Forward 3D Gaussian Splatting via Global Scene Tokens" [S1]. It addresses the limitation of current feed-forward 3DGS pipelines where primitives are formed in dense view-aligned spaces, causing redundancy and fragility in global consistency when many views are added [S1]. It builds on [Feed-forward Generalizable Reconstruction](16746-feed-forward-generalizable-reconstruction.md) by introducing a global latent scene token approach [S1].
