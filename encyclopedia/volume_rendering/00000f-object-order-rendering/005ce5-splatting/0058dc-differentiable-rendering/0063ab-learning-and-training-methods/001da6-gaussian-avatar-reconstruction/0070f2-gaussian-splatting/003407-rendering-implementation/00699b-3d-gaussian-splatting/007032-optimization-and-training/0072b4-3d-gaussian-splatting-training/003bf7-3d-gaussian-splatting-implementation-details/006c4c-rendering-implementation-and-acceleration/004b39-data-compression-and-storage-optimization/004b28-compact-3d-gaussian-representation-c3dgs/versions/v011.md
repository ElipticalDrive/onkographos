# Compact 3D Gaussian Representation (C3DGS)
## Overview
Compact 3D Gaussian Representation (C3DGS) is a method for reducing the memory footprint and storage requirements of 3D Gaussian Splatting (3DGS) by exploiting spatial redundancy in Gaussian attributes and pruning redundant primitives. It solves the problem of excessive storage (often >1GB for large scenes) and high computational cost associated with storing per-Gaussian attributes for every primitive. Unlike standard 3DGS, which treats each Gaussian as an independent entity, C3DGS shares view-dependent color attributes via a hash-based grid neural field and quantizes geometric attributes (scale and rotation) using a codebook, achieving over 25× compression while maintaining or improving reconstruction quality [S1].

## How it works
**Inputs:** A set of 3D Gaussians $\{G_i\}$ optimized via standard 3DGS training, where each Gaussian $G_i$ is defined by position $\mathbf{p}_i$, opacity $\alpha_i$, scale $\mathbf{s}_i$, rotation $\mathbf{q}_i$, and spherical harmonic (SH) coefficients $\mathbf{c}_i$ for view-dependent color.
**Outputs:** A compressed scene representation consisting of:
1.  A subset of active Gaussians identified by a learnable mask.
2.  A hash-based grid neural field for color prediction.
3.  A codebook for geometric attributes (scale and rotation).
4.  Indices mapping each Gaussian to its corresponding grid entry and codebook entry.

**Data Structures:**
1.  **Gaussian Attributes:** For each active Gaussian $i$, store:
    *   Position $\mathbf{p}_i \in \mathbb{R}^3$ (float32).
    *   Opacity $\alpha_i \in [0, 1]$ (float32).
    *   Codebook index for scale $idx_{s,i} \in \mathbb{Z}$ (integer).
    *   Codebook index for rotation $idx_{q,i} \in \mathbb{Z}$ (integer).
    *   Grid hash index $idx_{grid,i}$ (integer, used to query color).
2.  **Hash Grid:** A multi-resolution hash table (Instant NGP style) mapping spatial coordinates to feature vectors. The feature vector dimension is determined by the SH degree used for color approximation.
3.  **Codebook:** A lookup table storing representative scale vectors $\mathbf{S}_k$ and rotation quaternions $\mathbf{Q}_k$ for $k \in \{0, \dots, N_{codebook}-1\}$.

**Steps:**

1.  **Volume-Based Masking (Pruning):**
    During training, introduce a learnable scalar mask $m_i \in [0, 1]$ for each Gaussian $G_i$. This mask acts as a soft selector. The rendering loss is computed using the masked Gaussians. A regularization term encourages sparsity in $m_i$. Gaussians with $m_i$ below a threshold are effectively removed from the rendering pipeline, reducing the number of primitives without permanently deleting them during the optimization process [S1].

2.  **Grid-Based Color Compression:**
    Instead of storing SH coefficients $\mathbf{c}_i$ for each Gaussian, C3DGS uses a hash-based grid neural field $F_{grid}(\mathbf{p}, \mathbf{v})$ to predict view-dependent color.
    *   Given a Gaussian at position $\mathbf{p}_i$ and a viewing direction $\mathbf{v}$, the color $\mathbf{C}_i$ is obtained by querying the grid:
        $$ \mathbf{C}_i = F_{grid}(\mathbf{p}_i, \mathbf{v}) $$
    *   The grid is initialized and updated during training. This exploits the spatial coherence of colors, where neighboring Gaussians share similar appearance features [S1].

3.  **Codebook-Based Geometry Compression:**
    Geometric attributes (scale $\mathbf{s}_i$ and rotation $\mathbf{q}_i$) are quantized using a codebook.
    *   A codebook of size $N_{codebook}$ is learned.
    *   For each Gaussian, the scale $\mathbf{s}_i$ and rotation $\mathbf{q}_i$ are replaced by indices $idx_{s,i}$ and $idx_{q,i}$ pointing to entries in the codebook.
    *   The actual scale and rotation used in rendering are retrieved as:
        $$ \mathbf{s}_i = \mathbf{S}_{idx_{s,i}}, \quad \mathbf{q}_i = \mathbf{Q}_{idx_{q,i}} $$
    *   This reduces the storage of geometry from continuous floats to small integers [S1].

4.  **Training with Quantization-Aware Simulation:**
    The training process simulates the compression in the forward pass. The gradients flow through the grid and codebook lookups. After training, the indices and grid/codebook parameters are finalized. Post-processing steps like entropy coding can be applied to the indices for further compression [S1].

**Parameters:**
*   **Grid Type:** Hash-based grid (Instant NGP) is used for compactness and speed [S1].
*   **Codebook Size:** Not explicitly specified in the source, but described as "quite small" to minimize overhead [S1].
*   **Masking Threshold:** Not explicitly specified; implemented as a learnable mask with sparsity regularization [S1].

**Edge Cases and Pitfalls:**
*   **Precision:** The hash grid and codebook introduce approximation errors. The quality of reconstruction depends on the capacity of the grid and codebook. If the codebook is too small, geometric details may be lost. If the grid resolution is too low, color artifacts may appear.
*   **Boundaries:** The hash grid must handle out-of-bounds queries gracefully. The codebook must cover the range of scales and rotations present in the scene.
*   **Degenerate Input:** If the scene has high geometric diversity, a small codebook may fail to represent it accurately. The method assumes spatial redundancy in both color and geometry [S1].

## Subtopics

### [Optimized Minimal 3D Gaussian Splatting (OMG)](13978-optimized-minimal-3d-gaussian-splatting-omg.md)
OMG extends C3DGS by retaining per-Gaussian parameterization for geometry to handle sparsity better, while using Sub-Vector Quantization (SVQ) and a neural field for appearance. It addresses C3DGS's weakness in sparse settings where neural fields may struggle due to larger distances between Gaussians.

## Operating characteristics
*   **Storage Reduction:** C3DGS achieves approximately 15× reduced storage compared to standard 3DGS across various datasets. With post-processing (quantization and entropy coding), it achieves over 25× compression. On the Deep Blending dataset, it achieves over 28× enhancement in storage efficiency [S1].
*   **Rendering Speed:** C3DGS provides nearly 40% increase in rendering speed on the Deep Blending dataset and generally enhanced rendering speed across datasets due to the reduced number of Gaussians and efficient grid lookups [S1].
*   **Reconstruction Quality:** C3DGS outperforms standard 3DGS in reconstruction quality (PSNR) on the Deep Blending dataset, setting a new state-of-the-art benchmark [S1].
*   **Complexity:** The computational complexity is linearly proportional to the number of active Gaussians. The hash grid lookup is designed for fast processing [S1].
*   **Strengths:** Significant reduction in memory and storage, faster rendering, high-quality reconstruction.
*   **Limitations:** Relies on spatial redundancy; may not perform as well in highly sparse or geometrically diverse scenes compared to methods that retain per-Gaussian geometry (like OMG) [S1].

## Background
C3DGS was proposed to address the critical large memory and storage issue in 3D Gaussian Splatting (3DGS), which often requires >1GB for large real-world scenes. The method was introduced in the paper "Compact 3D Gaussian Representation for Radiance Field" [S1]. It builds on the observation that standard 3DGS densification produces many redundant and unnecessary Gaussians and does not exploit spatial redundancy in attributes. The method uses a hash-based grid representation (Instant NGP) for color and a codebook for geometry, inspired by techniques used in neural radiance fields and signal compression [S1].
