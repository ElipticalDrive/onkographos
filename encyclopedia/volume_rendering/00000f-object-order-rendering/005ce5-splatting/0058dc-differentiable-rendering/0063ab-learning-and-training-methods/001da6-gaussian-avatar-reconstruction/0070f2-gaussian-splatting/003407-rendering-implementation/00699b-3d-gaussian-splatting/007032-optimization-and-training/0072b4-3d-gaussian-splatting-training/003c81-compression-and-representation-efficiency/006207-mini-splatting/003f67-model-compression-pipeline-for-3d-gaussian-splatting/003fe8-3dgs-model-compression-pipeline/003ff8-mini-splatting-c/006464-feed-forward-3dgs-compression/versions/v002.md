# Feed-Forward 3DGS Compression

Also called: Compression of Feed-Forward 3DGS, Zero-shot Compression

## Overview
Feed-Forward 3DGS Compression (FCGS) is a post-training compression method that reduces the storage size of 3D Gaussian Splatting (3DGS) models generated by feed-forward reconstruction networks without requiring retraining or optimization [S1, unofficial]. It applies a learned entropy model directly to existing Gaussian attributes, enabling zero-shot generalization to scenes where ground-truth geometry is unavailable [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A pre-trained 3DGS model generated by a feed-forward model (e.g., MVSplat, LGM) [S1, unofficial].
- **Output:** A compressed bitstream representing the Gaussian attributes [S1, unofficial].

**Data Structures:**
The 3DGS model consists of $N$ Gaussians [G]. Each Gaussian $i$ is defined by position $\mathbf{p}_i \in \mathbb{R}^3$, rotation $\mathbf{q}_i \in \mathbb{R}^4$ (quaternion), scale $\mathbf{s}_i \in \mathbb{R}^3$, opacity $\alpha_i \in \mathbb{R}$, and color coefficients $\mathbf{c}_i$ (Spherical Harmonics) [G].

**Method Steps:**
1. **Attribute Extraction:** Extract all Gaussian attributes from the feed-forward model. For LGM, generate the remaining 3 views from an initial 1 view using (Wang & Shi, 2023), then input all 4 views into LGM for 3DGS creation [S1, unofficial].
2. **Masking for Feed-Forward Models:** When compressing 3DGS from feed-forward models, set the mask $m$ to all 0s for color attributes [S1, unofficial].
3. **Entropy Model Application:** Apply the Memory-Efficient Memory (MEM) module and context models to compress the remaining attributes (position, rotation, scale, opacity) [S1, unofficial]. The MEM module adaptively selects attributes, but color is bypassed due to the mask [S1, unofficial].
4. **Bitstream Generation:** Encode the quantized and context-predicted attributes into a bitstream using an entropy coder [G].

**Parameters:**
- **Mask $m$:** For feed-forward 3DGS, $m = 0$ for all color attributes [S1, unofficial].
- **Compression Ratio:** Achieves 15× compression for MVSplat-generated 3DGS and 5× for LGM-generated 3DGS [S1, unofficial].

**Edge Cases and Pitfalls:**
- **No Ground Truth:** For feed-forward models, ground-truth geometry is unavailable, so fidelity is evaluated by measuring the similarity of images rendered from the 3DGS before and after compression [S1, unofficial].
- **Zero-Shot Generalization:** The method generalizes without retraining, requiring robust entropy models that do not overfit to specific scene distributions [S1, unofficial].

**Pseudocode:**
```python
def compress_feed_forward_3dgs(gaussians):
    # Step 1: Extract attributes
    positions = [g.position for g in gaussians]
    rotations = [g.rotation for g in gaussians]
    scales = [g.scale for g in gaussians]
    opacities = [g.opacity for g in gaussians]
    colors = [g.color for g in gaussians]

    # Step 2: Set mask for color attributes to 0 for feed-forward models
    color_mask = [0] * len(gaussians)

    # Step 3: Quantize non-color attributes
    q_positions = [round(p, 6) for p in positions]
    q_rotations = [round(r, 6) for r in rotations]
    q_scales = [round(s, 6) for s in scales]
    q_opacities = [round(o, 6) for o in opacities]

    # Step 4: Context modeling and entropy coding (specific models not provided [G])
    # MEM module adaptively selects attributes, but color is masked out
    bitstream_pos = arithmetic_encode(q_positions)
    bitstream_rot = arithmetic_encode(q_rotations)
    bitstream_scale = arithmetic_encode(q_scales)
    bitstream_opacity = arithmetic_encode(q_opacities)

    # Color attributes are not compressed in the standard way for feed-forward models
    bitstream_color = None

    # Combine bitstreams
    bitstream = bitstream_pos + bitstream_rot + bitstream_scale + bitstream_opacity
    return bitstream

def arithmetic_encode(data):
    # Standard arithmetic coding implementation [G]
    return bytes(data)
```

## Subtopics

### [FeCoSplat](19396-fecosplat.md)
FeCoSplat is a two-stage feature compression framework for feed-forward 3D Gaussian Splatting (3DGS) that decouples compression into multi-view feature coding and reconstruction-conditioned feedback coding. It allows the receiver to decode directly in the compact feature-state domain without reconstructing intermediate Gaussians, thereby avoiding the heavy computational overhead of image compression and the irregularity challenges of explicit Gaussian compression. Unlike [CodecSplat](19101-feed-forward-3dgs-compression.md) which uses a single coding stage, FeCoSplat uses rendered reconstruction feedback to guide a second-stage refinement, maintaining an implicit Gaussian state for lightweight receiver-side decoding.

## Operating characteristics
- **Compression Ratios:** Achieves 15× compression for MVSplat-generated 3DGS and 5× for LGM-generated 3DGS [S1, unofficial].
- **Performance:** Excellent rate-distortion (RD) performance despite the lack of optimization [S1, unofficial].
- **Hardware/Resolution:** Evaluated on 10 scenes from ACID and 50 scenes from Gobjaverse [S1, unofficial].
- **Strengths:** Zero-shot generalization, no retraining required, handles feed-forward models with no ground truth [S1, unofficial].
- **Limitations:** Color attributes use mask $m=0$, potentially affecting visual fidelity [S1, unofficial].

## Background
FCGS was published at ICLR 2025 [S1, unofficial]. It addresses the need for efficient compression of 3DGS models generated by feed-forward networks, which are increasingly popular for rapid 3D reconstruction [S1, unofficial].
