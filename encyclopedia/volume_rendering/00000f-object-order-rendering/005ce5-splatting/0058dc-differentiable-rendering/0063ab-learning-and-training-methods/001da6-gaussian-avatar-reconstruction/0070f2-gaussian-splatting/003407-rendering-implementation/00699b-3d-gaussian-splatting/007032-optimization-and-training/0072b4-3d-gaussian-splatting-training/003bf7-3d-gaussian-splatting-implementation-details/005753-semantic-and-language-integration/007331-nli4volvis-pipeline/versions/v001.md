# NLI4VolVis Pipeline

Also called: Natural Language Interaction for Volume Visualization via LLM Multi-Agents and Editable 3D Gaussian Splatting

## Overview
NLI4VolVis is a framework that enables natural language interaction with volumetric datasets by integrating multi-view semantic segmentation, 3D open-vocabulary scene understanding, and editable 3D Gaussian Splatting (3DGS) [S1]. It solves the problem of making scientific visualization (SciVis) accessible and interactive by allowing users to query, edit, and stylize volumetric scenes via natural language commands processed by Large Language Model (LLM) agents [S1]. Unlike sibling methods that primarily focus on static semantic feature accumulation or single-model training, NLI4VolVis decomposes the scene into independent, editable Gaussian components per semantic segment and composes them, while employing a 2D stylization approach (InstructPix2Pix) rather than 3D style transfer to avoid artifacts and training overhead [S1].

## How it works
The pipeline consists of six stages: (a) Multi-view segmentation, (b) semantic understanding via CLIP, (c) editable Gaussian training, (d) composition, (e) function-calling tools, and (f) perception-action (VPA) loop [S1].

**Inputs and Outputs:**
- **Input:** A new volumetric dataset.
- **Output:** An interactive, editable 3D scene representation supporting real-time color/opacity/lighting editing, open-vocabulary querying, and 2D stylization, controlled via natural language [S1].

**Data Structures:**
The system maintains independent 3DGS models for each segmented semantic component. Each model consists of Gaussian parameters $\Theta_i = \{x_i, q_i, s_i, \alpha_i, c_i\}$ [S1, 15902-feature-3d-gaussian-splatting.md]. The final scene is represented by the concatenation of these component models [S1].

**Steps:**
1.  **Multi-view Rendering:** Render multi-view images of the volumetric dataset using a preset Transfer Function (TF) in ParaView [S1].
2.  **Multi-view Segmentation:** Process the rendered multi-view images using a selected multi-view semantic segmentation method to identify semantic components [S1].
3.  **View Selection and Embedding:** For each segmented component, perform entropy-guided view selection to identify the most informative frames [S1]. Embed these informative frames and associated textual descriptions using the CLIP model to achieve robust open-vocabulary scene understanding [S1].
4.  **Editable Gaussian Training:** Train an independent, editable 3DGS model (specifically using iVR-GS [58]) for each segmented semantic component [S1]. This allows each component to be queried and edited separately [S1].
5.  **Composition:** Assemble the final scene by combining the trained component models. This is achieved through the concatenation of Gaussian parameters, enabling composability [S1].
6.  **LLM Agent Interaction:** Deploy a hierarchical multi-agent system powered by LLMs [S1]. Agents utilize external function-calling tools to interpret user intents and execute actions such as open-vocabulary querying, optimal view selection, interactive scene editing, and 2D stylization [S1].
7.  **VPA Loop:** Collaborative agents follow the Vision-Perception-Action (VPA) loop [38] to iteratively refine visualizations based on user input [S1].

**Pseudocode:**
```python
def nli4volvis_pipeline(volumetric_dataset):
    # Stage 1: Multi-view Segmentation
    # Render multi-view images using a preset Transfer Function (TF) in ParaView
    multi_view_images = render_with_preset_tf(volumetric_dataset)
    
    # Process images with a selected multi-view semantic segmentation method
    segmented_components = multi_view_segmentation(multi_view_images)
    
    component_models = []
    
    # Stage 2 & 3: Semantic Understanding and Editable Gaussian Training
    for component in segmented_components:
        # Entropy-guided view selection to find informative frames
        informative_frames = entropy_guided_view_selection(component)
        
        # Embed frames and text with CLIP for open-vocabulary understanding
        # This aligns user queries with volumetric structures
        semantic_embeddings = clip_embed(informative_frames, text_descriptions)
        
        # Train independent editable 3DGS model (iVR-GS) for this component
        # Supports real-time editing of color, opacity, and lighting
        model = train_editable_3dgs(component, informative_frames, semantic_embeddings)
        component_models.append(model)
        
    # Stage 4: Composition
    # Combine component models via concatenation of Gaussian parameters
    full_scene_model = concatenate_models(component_models)
    
    # Stage 5 & 6: LLM Agent Interaction
    # Initialize LLM agents with function-calling tools
    agents = initialize_llm_agents(functions=[
        open_vocabulary_query,
        select_view,
        edit_scene_attributes,
        apply_2d_stylization
    ])
    
    # Stage 7: VPA Loop
    while user_interaction_active():
        user_input = get_user_natural_language_input()
        
        # Agents interpret intent and generate declarative commands
        action_plan = agents.plan(user_input)
        
        # Execute actions and refine visualization
        for command in action_plan:
            if command.type == "query":
                result = open_vocabulary_query(full_scene_model, command.args)
            elif command.type == "edit":
                full_scene_model = edit_scene_attributes(full_scene_model, command.args)
            elif command.type == "stylize":
                # Use InstructPix2Pix (IP2P) for 2D stylization
                # Note: This does not maintain multi-view consistency but offers
                # greater stylistic versatility than 3D style transfer [S1]
                stylized_image = apply_2d_stylization(full_scene_model, command.args)
                render_output = stylized_image
            else:
                render_output = render(full_scene_model)
                
        display(render_output)
```

**Parameters:**
- **Transfer Function (TF):** Preset TF used in ParaView for initial rendering [S1].
- **Stylization Method:** InstructPix2Pix (IP2P) [3] is used for 2D stylization [S1].
- **Segmentation Model:** A selected multi-view semantic segmentation method [S1].
- **Embedding Model:** CLIP [S1].
- **Base 3DGS Variant:** iVR-GS [58] is used for editable training [S1].

**Edge Cases and Pitfalls:**
- **3D Style Transfer Artifacts:** Applying 3D style transfer methods like StyleGaussian [36] to SciVis data introduces noticeable artifacts and requires substantial training time for each scene [S1]. NLI4VolVis avoids this by using 2D stylization [S1].
- **Multi-view Consistency:** The 2D stylization approach using IP2P has known limitations in maintaining multi-view consistency [S1].
- **Geometry Preservation:** Most 3D style transfer methods alter only color attributes while preserving geometry, limiting expressiveness for creative or structural editing [S1].

## Operating characteristics
- **Time Complexity:** Training requires substantial time if 3D style transfer were used, but NLI4VolVis uses independent component training which scales with the number of segments [S1]. The VPA loop adds latency per interaction step based on LLM inference and tool execution [S1].
- **Memory Complexity:** Memory usage scales with the number of semantic components, as each is stored as an independent 3DGS model [S1].
- **Strengths:** Enables real-time editing of color, opacity, and lighting; supports composability; allows open-vocabulary querying and interactive editing via natural language; offers greater stylistic versatility through 2D stylization [S1].
- **Limitations:** 2D stylization does not maintain multi-view consistency; relies on external tools (ParaView, CLIP, IP2P); performance depends on the quality of multi-view segmentation [S1].
- **When to use:** When natural language interaction, open-vocabulary querying, and flexible 2D stylization are required for volumetric data, and multi-view consistency during stylization is not critical [S1].
- **When not to use:** When strict multi-view consistency during stylization is required, or when 3D structural editing is needed beyond color/opacity changes [S1].

## Background
NLI4VolVis was introduced to make Volume Visualization (VolVis) more accessible across various scenarios by harnessing LLMs' planning and reasoning capabilities [S1]. It integrates concepts from 3D open-vocabulary segmentation, editable Gaussian Splatting (iVR-GS), and multi-agent systems [S1]. The framework addresses limitations of previous 3D style transfer methods like StyleGaussian, which suffer from artifacts in SciVis and lack structural editing capabilities [S1].
