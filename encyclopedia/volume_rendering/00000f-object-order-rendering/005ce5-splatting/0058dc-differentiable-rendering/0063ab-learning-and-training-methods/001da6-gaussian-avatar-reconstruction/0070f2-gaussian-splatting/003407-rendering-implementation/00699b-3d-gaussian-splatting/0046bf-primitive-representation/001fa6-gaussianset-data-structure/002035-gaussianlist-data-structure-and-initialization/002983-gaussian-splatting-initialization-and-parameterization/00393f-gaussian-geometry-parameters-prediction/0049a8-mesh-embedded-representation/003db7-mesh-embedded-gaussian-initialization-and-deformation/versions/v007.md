# Mesh-Embedded Gaussian Initialization and Deformation

Also called: Gaussian Embedding, Triangle Embedding

## Overview
This method initializes and deforms 3D Gaussians by anchoring them to a canonical triangle mesh $\mathcal{M}$ using barycentric coordinates and normal displacement [S1, unofficial]. It solves the problem of maintaining geometric coherence and differentiability during mesh deformation (e.g., animation) by tracking Gaussians through mesh topology rather than direct vertex positions [S1, unofficial]. It sets itself apart from direct Gaussian optimization by binding Gaussians to the surface, ensuring they follow mesh deformations naturally, though it requires handling cross-triangle boundaries to prevent Gaussians from sticking to edges [Parent].

## How it works
**Inputs and Outputs:**
*   **Input:** Canonical triangle mesh $\mathcal{M}$ with vertices $V$, per-vertex normals $n$, and faces $F$; deformation function $\text{Deform}(\cdot)$; initial canonical Gaussian rotation $\bar{q}$ and scale $\bar{s}$.
*   **Output:** Posed Gaussian parameters: mean $\mu_{pose}$, rotation $q_{pose}$, scale $s_{pose}$, and color (Spherical Harmonics disabled for simplicity [S1, unofficial]).

**Data Structures:**
Each Gaussian $i$ is defined by an embedding tuple $E_i = \{k, u, v, d\}$:
*   $k$: Index of the triangle $k \in F$ in the canonical mesh.
*   $(u, v)$: Barycentric coordinates within triangle $k$, such that $u \ge 0, v \ge 0, u+v \le 1$.
*   $d$: Normal displacement along the interpolated surface normal.

**Canonical Position and Normal:**
The canonical mean $\mu_{cano}$ and normal $n_{cano}$ are computed via Phong interpolation on the canonical mesh [Parent, S1, unofficial]:
$$
\mu_{cano} = \mathcal{V}(k, u, v) = u V_1 + v V_2 + (1 - u - v) V_3
$$
$$
n_{cano} = \mathcal{N}(k, u, v) = u n_1 + v n_2 + (1 - u - v) n_3
$$
where $V_j$ and $n_j$ are the vertices and per-vertex normals of triangle $k$ [Parent, S1, unofficial].

**Posed State Computation:**
When the mesh is deformed, the posed position $\mu_{pose}$ is derived by applying the mesh deformation function $\text{Deform}(\cdot)$ to the displaced canonical position [Parent]:
$$
\mu_{pose} = \text{Deform}(\mu_{cano} + d \cdot n_{cano})
$$
The posed rotation $q_{pose}$ and scale $s_{pose}$ are derived from mesh attributes to maintain coherence [Parent, S1, unofficial]:
*   **Rotation:** Interpolate per-vertex quaternions $q_1, q_2, q_3$ using barycentric weights to get $\delta q$, then combine with canonical rotation $\bar{q}$:
    $$
    q_{pose} = \delta q * \bar{q}, \quad \delta q = u q_1 + v q_2 + (1 - u - v) q_3
    $$
*   **Scale:** Scale is proportional to the area change of the embedded triangle relative to the canonical state:
    $$
    s_{pose} = \left( \frac{A_{pose}}{A_{cano}} \right) \bar{s}
    $$
    where $A_{pose}$ and $A_{cano}$ are the areas of the triangle in the posed and canonical states, respectively [Parent, S1, unofficial].

**Initialization:**
1.  Randomly select $N$ pairs of triangle indices and barycentric coordinates on the canonical mesh (e.g., $N=10,000$) [S1, unofficial].
2.  Set the initial barycentric coordinates $(u, v)$ for each Gaussian.
3.  Initialize all normal displacements $d$ to zero [S1, unofficial].
4.  Compute canonical positions $\mu_{cano}$ and normals $n_{cano}$ for all Gaussians.
5.  Initialize other Gaussian properties (opacity, color) based on the canonical state [S1, unofficial].

**Cross-Triangle Handling:**
Barycentric coordinates are only differentiable within a single triangle. If optimization moves an embedding point across a boundary ($u < 0$, $v < 0$, or $u+v > 1$), the embedding must be re-expressed in the neighboring triangle to maintain differentiability [Parent, S1, unofficial]. Failure to handle this causes Gaussians to stick to boundaries and pile up [Parent]. This is often managed by constraint mechanisms like "Walking on Triangle" [Subtopics].

**Pseudocode:**
```python
def compute_posed_gaussian(E, mesh, deformation_func, canonical_q, canonical_s):
    """
    E: tuple (k, u, v, d)
    mesh: object with vertices V, normals n, faces F, and method to get area
    deformation_func: function that deforms a point
    canonical_q: quaternion q_bar
    canonical_s: scalar s_bar
    """
    k, u, v, d = E
    
    # Get triangle vertices and normals
    V1, V2, V3 = mesh.get_triangle_vertices(k)
    n1, n2, n3 = mesh.get_triangle_normals(k)
    
    # Canonical position and normal (Phong interpolation)
    mu_cano = u * V1 + v * V2 + (1 - u - v) * V3
    n_cano = u * n1 + v * n2 + (1 - u - v) * n3
    
    # Displaced canonical position
    mu_displaced = mu_cano + d * n_cano
    
    # Posed position
    mu_pose = deformation_func(mu_displaced)
    
    # Posed rotation
    q1, q2, q3 = mesh.get_triangle_quaternions(k)
    delta_q = u * q1 + v * q2 + (1 - u - v) * q3
    q_pose = delta_q * canonical_q
    
    # Posed scale
    A_cano = mesh.get_triangle_area(k, canonical=True)
    A_pose = mesh.get_triangle_area(k, canonical=False)
    s_pose = (A_pose / A_cano) * canonical_s
    
    return mu_pose, q_pose, s_pose

def initialize_gaussians(mesh, num_gaussians=10000):
    """
    Initialize Gaussians on the canonical mesh.
    """
    embeddings = []
    for i in range(num_gaussians):
        k = random.choice(mesh.faces)
        u, v = random_barycentric_coords()
        d = 0.0
        embeddings.append((k, u, v, d))
    return embeddings
```

## Subtopics

### [Walking on Triangle](9700-walking-on-triangle.md)
A constraint mechanism that binds Gaussians to the surface of a triangle mesh, ensuring they remain within the boundaries of their corresponding triangles during optimization and deformation. It solves the problem of Gaussians drifting off-mesh or piling up at triangle edges when the underlying mesh is manipulated, animated, or deformed. Unlike methods that rely heavily on precise mesh accuracy, it defines a local triangle space to ensure robust results even with inaccurate meshes.

## Operating characteristics
*   **Time Complexity:** Initialization is $O(N)$ where $N$ is the number of Gaussians. Posed state computation is $O(1)$ per Gaussian per frame, assuming mesh queries are $O(1)$.
*   **Memory Complexity:** $O(N)$ for storing embeddings and Gaussian parameters.
*   **Strengths:** Ensures Gaussians follow mesh deformations naturally; reduces the number of parameters to optimize (only $d$ and potentially $u, v$ if allowed to move); robust to mesh inaccuracies when combined with constraints .
*   **Limitations:** Requires a valid triangle mesh; differentiability issues at triangle boundaries if not handled; limited to surface geometries unless displacement $d$ is large [S1, unofficial].
*   **When to use:** When rendering animated or deforming meshes where Gaussians should stick to the surface.
*   **When not to use:** For static scenes where direct Gaussian optimization is simpler; for volumetric data not easily represented as a surface mesh.

## Background
This method originates from the SplattingAvatar paper, which introduced Gaussian Embedding for animatable human avatars [S1, unofficial]. It builds on the principles of Mesh-embedded representation [Parent] and adapts them for differentiable rendering of dynamic scenes. The approach leverages the efficiency of Gaussian Splatting [23] while incorporating the geometric priors of triangle meshes [S1, unofficial].
