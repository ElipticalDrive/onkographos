# Spatially Constrained Optimization

Also called: Opacity Loss with Re-initialization

## Overview
Spatially Constrained Optimization is a post-processing constraint workflow used in differentiable rendering to enforce full opacity on target objects and manage boundary artifacts [S1, unofficial]. It solves the problem of incomplete coverage and low-opacity boundary primitives that persist when using opacity loss alone, by combining an opacity loss term with a re-initialization mechanism for transparent primitives [S1, unofficial]. Unlike standard pruning methods that remove transparent primitives, this method re-initializes them to maintain primitive count and ensure stable coverage in complex regions [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Current set of primitives $\Theta$, target image $I^{\text{target}}$, target alpha mask $I_{\alpha}^{\text{target}}$, current rendered image $I$, current rendered alpha $I_{\alpha}$, prune threshold (typically 0.3), prune iterations frequency (typically 50), warmup period flag, final iteration flag.
*   **Outputs:** Updated primitive parameters $\Theta$ after optimization step and potential re-initialization.

**Data Structures:**
*   **Primitives:** Each primitive $i$ has parameters $\nu_i$ (position, scale, rotation, color, opacity $\sigma(\nu_i)$).
*   **Images:** $I$ and $I_{\alpha}$ are rasterized images of the current primitive set. $I^{\text{target}}$ and $I_{\alpha}^{\text{target}}$ are the ground truth or target images.

**Steps:**
1.  **Compute Loss:** Calculate the spatially constrained loss $\mathcal{L}$ to optimize primitive parameters $\Theta$. The loss consists of two terms: a color reconstruction loss applied only where the target alpha is non-zero, and an opacity matching loss [S1, unofficial].
    $$
    \mathcal{L} = \| (I_{\alpha}^{\text{target}} > 0) \odot (I - I^{\text{target}}) \|_2^2 + \lambda_{\alpha} \| I_{\alpha} - I_{\alpha}^{\text{target}} \|_2^2
    $$
    Where:
    *   $I_{\alpha} = 1 - T_N$ is the rendered alpha, with $T_N$ being the accumulated transmittance [S1, unofficial].
    *   $\odot$ denotes element-wise multiplication.
    *   $\lambda_{\alpha}$ is the weight for the opacity loss term [S1, unofficial].
    *   $(I_{\alpha}^{\text{target}} > 0)$ creates a binary mask selecting foreground pixels [S1, unofficial].

2.  **Optimize:** Perform gradient descent on $\Theta$ using $\mathcal{L}$ [S1, unofficial].

3.  **Identify Low-Opacity Primitives:** After optimization, identify primitives $i$ where the opacity $\sigma(\nu_i)$ is below the prune threshold [S1, unofficial].

4.  **Re-initialize (Conditional):** If the current iteration is not within the initial warmup period and not in the final iterations, re-initialize the identified low-opacity primitives [S1, unofficial].
    *   Instead of removing these primitives, re-initialize their parameters randomly using the Structure-aware initialization method [S1, unofficial].
    *   This re-initialization occurs every `prune iterations` (e.g., 50) [S1, unofficial].

**Pseudocode:**
```python
def spatially_constrained_optimization_step(primitives, target_image, target_alpha, 
                                           lambda_alpha, prune_threshold, 
                                           prune_iterations, current_iter, 
                                           warmup_iters, final_iters, 
                                           structure_aware_init):
    """
    One step of spatially constrained optimization.
    
    Args:
        primitives: List of primitive objects with parameters nu_i and opacity sigma(nu_i).
        target_image: Ground truth RGB image.
        target_alpha: Ground truth alpha mask.
        lambda_alpha: Weight for opacity loss.
        prune_threshold: Threshold below which primitives are re-initialized.
        prune_iterations: Frequency of re-initialization checks.
        current_iter: Current training iteration number.
        warmup_iters: Number of initial iterations to skip re-initialization.
        final_iters: Number of final iterations to skip re-initialization.
        structure_aware_init: Function to re-initialize primitives randomly.
        
    Returns:
        Updated primitives list.
    """
    # Step 1: Render current primitives
    rendered_image, rendered_alpha = render(primitives)
    
    # Step 2: Compute Loss
    # Mask for foreground pixels where target alpha > 0
    foreground_mask = (target_alpha > 0).astype(float)
    
    # Color loss: only applied to foreground
    color_loss = torch.sum((foreground_mask * (rendered_image - target_image))**2)
    
    # Opacity loss: match target alpha
    opacity_loss = torch.sum((rendered_alpha - target_alpha)**2)
    
    # Total loss
    loss = color_loss + lambda_alpha * opacity_loss
    
    # Step 3: Optimize primitives using gradient descent
    # (Assuming an optimizer step is performed here)
    loss.backward()
    optimizer.step()
    optimizer.zero_grad()
    
    # Step 4: Re-initialization check
    # Check if we are in warmup or final phase
    in_warmup = current_iter < warmup_iters
    in_final = current_iter > (total_iterations - final_iters)
    should_prune = (current_iter % prune_iterations == 0)
    
    if should_prune and not in_warmup and not in_final:
        for primitive in primitives:
            # Check opacity
            if primitive.opacity < prune_threshold:
                # Re-initialize instead of pruning
                structure_aware_init(primitive)
                
    return primitives
```

**Parameters:**
*   **Prune threshold:** Threshold for opacity below which primitives are re-initialized. Typical value: 0.3 [S1, unofficial].
*   **Prune iterations:** Frequency of re-initialization. Typical value: every 50 iterations [S1, unofficial].
*   **$\lambda_{\alpha}$:** Weight for opacity loss. Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Destabilization:** Re-initialization is excluded during an initial warmup period and final iterations to prevent destabilization of the optimization [S1, unofficial].
*   **Boundary Artifacts:** Using opacity loss alone leaves low-opacity primitives on boundaries; adding re-initialization produces the best qualitative results [S1, unofficial].
*   **Coverage:** Re-initialization ensures full coverage by preventing primitives from being pruned, which is crucial for applications like appearance editing [S1, unofficial].

## Subtopics

### Structure-aware Re-initialization
A mechanism to handle transparent primitives in spatially constrained rendering by re-initializing them randomly instead of pruning them, to prevent destabilization and ensure coverage [S1, unofficial]. It checks opacity $\sigma(\nu_i)$ for each primitive $i$ and marks those below the prune threshold (typically 0.3) for re-initialization [S1, unofficial]. Instead of removing the primitive, it re-initializes it randomly using the Structure-aware initialization method [S1, unofficial]. This differs from standard pruning (e.g., [34]) by maintaining the primitive count and potentially aiding coverage in complex regions [S1, unofficial]. Re-initialization occurs every prune iterations (50), excluding an initial warmup period and final iterations to prevent destabilization [S1, unofficial].

### Foreground-only Rendering
A method to render only foreground by optimizing primitive opacity to match target alpha, enabling applications like appearance editing [S1, unofficial]. It optimizes $\Theta$ using the loss $\mathcal{L} = \| (I_{\alpha}^{target} > 0) \odot (I - I^{target}) \|_2^2 + \lambda_{\alpha} \| I_{\alpha} - I_{\alpha}^{target} \|_2^2$, where $I_{\alpha} = 1 - T_N$, $I^{target}$ is the target image, $I_{\alpha}^{target}$ is the target alpha, and $\lambda_{\alpha}$ is the weight [S1, unofficial]. It re-initializes transparent primitives instead of pruning them for further applications [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The method adds a re-initialization step every `prune iterations` (e.g., 50), which is negligible compared to the rendering and gradient computation steps [S1, unofficial]. The loss computation involves element-wise operations on images, scaling with image resolution [S1, unofficial].
*   **Memory Complexity:** No significant additional memory overhead compared to standard differentiable rendering, as it reuses existing primitive structures [S1, unofficial].
*   **Measured Performance:** On an RTX 3090, per-iteration forward/backward runtime and VRAM usage depend on image resolution and tile size. For 1024x1024 resolution with 16x16 tile size, forward runtime is 5514ms, backward is 9811ms, and VRAM is 12.0 GB [S1, unofficial].
*   **Strengths:** Produces best qualitative results by cleaning up boundary artifacts and ensuring full coverage [S1, unofficial]. Enables foreground-only rendering for downstream applications [S1, unofficial].
*   **Limitations:** Requires careful tuning of warmup and final iteration periods to avoid destabilization [S1, unofficial].
*   **When to Use:** When full opacity on target objects is required, and boundary artifacts from opacity loss alone are problematic [S1, unofficial]. Suitable for applications like appearance editing where foreground isolation is needed [S1, unofficial].
*   **When Not to Use:** When computational resources are extremely limited and the overhead of re-initialization checks is prohibitive (though minimal) [S1, unofficial]. When standard pruning is sufficient and boundary artifacts are not a concern [S1, unofficial].

## Background
Originated in the DiffBMP paper (2026) by the authors of "DiffBMP: Differentiable Rendering with Bitmap Primitives" [S1, unofficial]. The idea is modified from [52]'s work for triangle mesh rendering [24], but samples only once per iteration instead of five times [S1, unofficial]. It is used in the context of differentiable rendering with bitmap primitives to support creative workflows and appearance editing [S1, unofficial].
