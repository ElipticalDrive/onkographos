# Average Contribution Criterion

Also called: Ours

## Overview
The Average Contribution Criterion is a densification strategy for 3D Gaussian Splatting that determines whether a Gaussian should be split or cloned based on its mean blending weight per view rather than a binary view count [S1, unofficial]. It solves the problem of occlusion bias inherent in the original 3D Gaussian Splatting criterion, where fully occluded views inflate the denominator and dilute the gradient signal, leading to inefficient densification [S1, unofficial]. It sets itself apart from siblings like [Multi-View Density Control Criterion](5663-multi-view-density-control-criterion.md) and [Complexity-Aware Adaptive Density Control](16126-complexity-aware-adaptive-density-control.md) by being intrinsically self-limiting without requiring external guard rails like distance scaling, and by weighting views by their actual contribution rather than treating all observed views equally [S1, unofficial].

## How it works
The method computes a scalar score $S(G)$ for each Gaussian $G$ (indexed as $i$) by aggregating positional gradients across all views where the Gaussian contributes, normalized by the mean blending weight in those views.

### Inputs and Outputs
*   **Input:** For each Gaussian $i$, the set of views $v$ where it contributes to at least one pixel. For each such view, the per-pixel blending weights $w_{i,p}$ and the gradient of the training loss $\mathcal{L}$ with respect to the Gaussian's projected screen-space mean $\mu_i$.
*   **Output:** A scalar densification score $\gamma_i^{\text{Ours}}$. If $\gamma_i^{\text{Ours}} > \tau$, the Gaussian is marked for splitting or cloning.

### Data Structures
*   **Per-Gaussian State:**
    *   `sum_grad_norm`: Accumulator for $\sum_v \|g_{i,v}\|$.
    *   `sum_mean_weight`: Accumulator for $\sum_v \bar{w}_{i,v}$.
*   **Per-View State (temporary during accumulation):**
    *   `view_grad`: Vector $g_{i,v}$ for the current view.
    *   `pixel_weights`: List of $w_{i,p}$ for pixels $p$ where $w_{i,p} > 0$.

### Formulas
The core score is defined as [S1, unofficial]:

$$
\gamma_i^{\text{Ours}} = \frac{1}{1 + \sum_v \bar{w}_{i,v}} \sum_v \|g_{i,v}\|
$$

Where:
*   $g_{i,v}$ is the per-view gradient vector, computed as:
    $$
    g_{i,v} = \sum_p w_{i,p} s_{i,p}
    $$
    Here, $s_{i,p}$ is a weight-independent vector combining the photometric residual, geometric steering direction, and local contrast of the Gaussian's color against the background [S1, unofficial].
*   $w_{i,p}$ is the blending weight for pixel $p$ in view $v$:
    $$
    w_{i,p} = \alpha_{i,p} T_{i,p}
    $$
    where $\alpha_{i,p}$ is the Gaussian's opacity and $T_{i,p}$ is the transmittance [S1, unofficial].
*   $\bar{w}_{i,v}$ is the mean blending weight for Gaussian $i$ in view $v$:
    $$
    \bar{w}_{i,v} = \frac{1}{N_{i,v}} \sum_p w_{i,p}
    $$
    where $N_{i,v}$ is the number of pixels in view $v$ where Gaussian $i$ contributes ($w_{i,p} > 0$) [S1, unofficial].

### Parameters
*   **Densification Threshold ($\tau$):** 0.002. This value is fixed across all experiments, calibrated once on the Mip-NeRF360 sweep subset (bicycle, bonsai, counter, garden) to optimize PSNR/SSIM/GMSD [S1, unofficial].
*   **Denominator Floor:** 1. Added to the sum of mean blending weights to prevent unbounded scores for rarely observed Gaussians [S1, unofficial].

### Pseudocode
The following algorithm computes the score for a single Gaussian $i$ given the gradients and blending weights from all relevant views.

```python
def compute_average_contribution_score(gauss_i, views):
    """
    Computes the Average Contribution Criterion score for Gaussian i.
    
    Args:
        gauss_i: Object containing Gaussian properties (not directly used in score calc).
        views: List of view indices v where gauss_i contributes to at least one pixel.
        
    Returns:
        float: The densification score gamma_i_Ours.
    """
    sum_grad_norm = 0.0
    sum_mean_weight = 0.0
    
    for v in views:
        # 1. Compute per-view gradient g_{i,v}
        # g_{i,v} is the sum of weight-independent vectors s_{i,p} scaled by blending weights w_{i,p}
        # s_{i,p} is derived from photometric residual, geometric steering, and local contrast.
        # w_{i,p} = alpha_{i,p} * T_{i,p}
        
        view_gradient = Vector2(0.0, 0.0)
        sum_weights = 0.0
        pixel_count = 0
        
        # Iterate over all pixels p where Gaussian i contributes in view v
        for p in gauss_i.contributing_pixels_in_view[v]:
            w_ip = gauss_i.blending_weight(p, v) # alpha * T
            s_ip = gauss_i.weight_independent_gradient_vector(p, v) # Derived from loss gradient and weights
            
            view_gradient += w_ip * s_ip
            sum_weights += w_ip
            pixel_count += 1
            
        # 2. Calculate mean blending weight w_bar_{i,v}
        if pixel_count > 0:
            w_bar = sum_weights / pixel_count
        else:
            w_bar = 0.0
            
        # 3. Accumulate norms and mean weights
        sum_grad_norm += norm(view_gradient)
        sum_mean_weight += w_bar
        
    # 4. Compute final score with denominator floor
    # Denominator is 1 + sum of mean blending weights
    denominator = 1.0 + sum_mean_weight
    
    if denominator == 0:
        # Should not happen if views list is non-empty and floor is 1, 
        # but guard against division by zero if views is empty.
        return 0.0
        
    score = sum_grad_norm / denominator
    
    return score
```

### Edge Cases and Pitfalls
*   **Denominator Floor:** Without the constant floor of 1 in the denominator, rarely observed Gaussians (where $\sum_v \bar{w}_{i,v} \to 0$) would receive unbounded scores, causing training divergence [S1, unofficial].
*   **Occlusion Bias:** Unlike the original 3D Gaussian Splatting criterion which weights every view equally regardless of visibility, this criterion weights views by their actual contribution, preventing occluded views from diluting the average [S1, unofficial].
*   **Threshold Sensitivity:** Over-densification (e.g., threshold 0.001) lowers PSNR, while under-densification (e.g., threshold 0.004) raises LPIPS [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The score computation requires iterating over all pixels where the Gaussian contributes across all views. This is proportional to the total number of splats rendered for the Gaussian, which is typically small compared to the total pixel count.
*   **Memory Complexity:** Requires storing per-view gradient accumulators and mean blending weights per Gaussian. No additional large data structures are needed.
*   **Measured Performance:** On Zip-NeRF scenes with a 30k iteration schedule, the method achieves 25.81 PSNR, 0.830 SSIM, 0.330 LPIPS, and 0.106 GMSD using 1.133 million Gaussians in 29.9 minutes [S1, unofficial]. On a 210k iteration schedule, it achieves 26.60 PSNR, 0.852 SSIM, 0.282 LPIPS, and 0.087 GMSD using 2.495 million Gaussians in 262.9 minutes [S1, unofficial]. At 300k iterations, the Gaussian count stays bounded at 2.75M while continuing to improve in LPIPS and GMSD [S1, unofficial].
*   **Strengths:** It is intrinsically self-limiting, producing the fewest Gaussians (roughly 55–75% of other criteria's counts) at matched quality [S1, unofficial]. It avoids the instability of raw pixel-count criteria (which can overdensify to >16.8M Gaussians and crash) and the suppression of detail by distance scaling [S1, unofficial].
*   **Limitations:** It requires a one-time recalibration of the densification threshold (set to 0.002) due to the change in score scale [S1, unofficial].

## Background
The Average Contribution Criterion was introduced in the paper "Counting Contributions, Not Views: Occlusion-Aware Densification for 3D Gaussian Splatting" [S1, unofficial]. It addresses limitations in the original 3D Gaussian Splatting densification strategy, which averages positional gradients across observed views without accounting for the visibility of the Gaussian in those views. The method was developed to provide a more faithful measure of observation by using mean blending weights, which are independent of screen-space footprint and occlusion-aware.
