# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, GSGEN Implementation Details, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific implementation parameters, optimization strategies, and training configurations required to reconstruct 3D Gaussian Splatting (3DGS) scenes from multi-view images or text prompts. It addresses the core problem of balancing reconstruction fidelity with computational efficiency by defining the hyperparameters for densification, pruning, and loss weighting. It sets itself apart from general optimization theory by providing concrete values for thresholds, iteration intervals, and hardware-specific optimizations (such as half-precision rasterization) necessary for a working implementation.

## How it works

### Inputs and Outputs
*   **Inputs:** A set of $N$ input images $\{I_i\}$ with known camera poses $\{C_i\}$ and intrinsics $\{K_i\}$, or a text prompt for text-to-3D generation.
*   **Outputs:** A set of 3D Gaussian primitives $\mathcal{G} = \{\mu_j, \Sigma_j, R_j, s_j, \alpha_j, c_j\}$, where $\mu$ is position, $\Sigma$ is covariance, $R$ is rotation, $s$ is scale, $\alpha$ is opacity, and $c$ is spherical harmonic (SH) coefficients for color.

### Data Structures
The Gaussian representation is stored in flat arrays for GPU access:
*   **Position:** Float32, size $3 \times N_{gauss}$.
*   **Rotation:** Quaternions (Float32, size $4 \times N_{gauss}$) or Rotation Matrices.
*   **Scale:** Float32, size $3 \times N_{gauss}$ (log-space storage is common to ensure positivity).
*   **Opacity:** Float32, size $1 \times N_{gauss}$.
*   **Color:** SH coefficients. For SH degree 1, this is $3 \times 4 = 12$ floats per Gaussian. For SH degree 3, it is $3 \times 9 = 27$ floats.
*   **Optimizer State:** Adam state (mean and variance) for each parameter, requiring additional memory proportional to the parameter count.

### Training Loop and Optimization Steps
The training process minimizes a loss function $\mathcal{L}$ between rendered images $\hat{I}$ and ground truth $I$.

1.  **Initialization:** Initialize Gaussians from Structure-from-Motion (SfM) points.
    *   *Note:* Use **Corrected Scene-Extent** [S4] to avoid bias from camera distribution. Calculate average camera position $\bar{C} = \frac{1}{N_{\text{cam}}} \sum C_i$ [S4]. Compute corrected extent $e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2$ [S4].
2.  **Rendering:** For each training step, select a random camera view. Render the image using differentiable alpha-blending rasterization [6233-optimization-and-parallelization].
    *   *Half-Precision:* Use half-precision (FP16) memory fetches on feature vectors during rasterization for both forward and backward kernels to reduce register pressure [S2]. Apply an automatic scaling factor to loss values to improve half-precision training stability [S2].
3.  **Loss Computation:** Compute the photometric loss.
    *   Standard 3DGS uses a combination of L1 loss and D-SSIM [S3][S13, unofficial]:
        $$ \mathcal{L} = (1 - \lambda) \mathcal{L}_1 + \lambda \mathcal{L}_{SSIM} $$
        where $\lambda$ is a hyperparameter (typically 0.2) [S13, unofficial].
    *   For text-to-3D, use SDS (Score Distillation Sampling) loss from a pre-trained diffusion model (e.g., StableDiffusion v1.5 checkpoint `runwayml/stable-diffusion-v1-5`) with a guidance scale of 100 [S1].
4.  **Backpropagation:** Compute gradients $\frac{\partial \mathcal{L}}{\partial \theta}$ for all Gaussian parameters.
5.  **Optimizer Update:** Update parameters using Adam optimizer with learning rate $1 \times 10^{-3}$ [S3].
6.  **Densification (Adaptive Density Control):**
    *   **Splitting:** Every 500 iterations, split Gaussians based on view-space position gradient. If gradient $> T_{pos} = 0.02$, split the Gaussian [S1].
    *   **Cloning:** Clone Gaussians with high opacity but low gradient to expand volume without increasing complexity [S1].
    *   **Compactness:** Perform compactness-based densification every 1000 iterations [S1].
    *   *Exponential Threshold:* Use an exponentially ascending gradient threshold schedule to control the number of split Gaussians [S4].
7.  **Pruning:** Every 200 iterations, remove Gaussians that are:
    *   Opacity $\alpha < \alpha_{min} = 0.05$ [S1].
    *   Excessively large in world-space or view-space radius [S1].

### Pseudocode

```python
def train_3dgs(images, poses, intrinsics, num_iterations=30000):
    # 1. Initialization
    gaussians = initialize_from_sfm(images, poses)
    optimizer = Adam(gaussians.parameters(), lr=1e-3)
    
    # 2. Corrected Scene Extent Calculation [S4]
    avg_cam_pos = mean([pose.position for pose in poses])
    sfm_points = get_sfm_points()
    scene_extent = mean([norm(avg_cam_pos - p) for p in sfm_points])
    
    for iteration in range(1, num_iterations + 1):
        # 3. Random View Selection
        view_idx = random_choice(len(images))
        image = images[view_idx]
        pose = poses[view_idx]
        
        # 4. Forward Pass (Half-Precision Rasterization) [S2]
        with torch.cuda.amp.autocast():
            rendered_image = render(gaussians, pose, intrinsics)
            
            # 5. Loss Computation
            # Standard photometric loss [S13, unofficial]
            l1_loss = l1_loss(rendered_image, image)
            ssim_loss = ssim_loss(rendered_image, image)
            loss = 0.2 * l1_loss + 0.8 * ssim_loss
            
            # For text-to-3D, replace with SDS loss [S1]
            # loss = compute_sds_loss(rendered_image, prompt, diffusion_model)
            
        # 6. Backward Pass
        optimizer.zero_grad()
        loss.backward()
        
        # 7. Optimizer Step
        optimizer.step()
        
        # 8. Densification and Pruning
        if iteration % 500 == 0:
            # Split based on position gradient threshold T_pos = 0.02 [S1]
            split_gaussians(gaussians, threshold=0.02)
            
        if iteration % 1000 == 0:
            # Compactness-based densification [S1]
            compactness_densify(gaussians)
            
        if iteration % 200 == 0:
            # Prune low opacity and large radius Gaussians [S1]
            prune_gaussians(gaussians, alpha_min=0.05)
            
    return gaussians
```

### Edge Cases and Pitfalls
*   **Scene Extent Bias:** Default 3DGS scene extent is proportional to the furthest camera distance, causing bias if cameras are clustered (e.g., orbiting a small object). This leads to incorrect splitting/pruning. Use the corrected scene extent based on SfM points [S4].
*   **Half-Precision Instability:** Training in FP16 can lead to gradient overflow or underflow. Apply automatic loss scaling [S2].
*   **Over-Splitting:** If the gradient threshold is too low, the number of Gaussians explodes. Use an exponentially ascending threshold schedule [S4].
*   **Floaters:** Pruning opacity below 0.05 helps remove transient artifacts, but may remove valid thin structures. Monitor visual quality [S1].

## Subtopics

### Corrected Scene-Extent
A method to calculate scene extent based on the SfM point cloud rather than camera positions to avoid bias from camera distribution (e.g., orbiting a small object in a large environment) [S4]. It solves the problem where default 3DGS scene extent ($e_{\text{scene}}$) is proportional to the distance of the furthest camera from the average camera position, causing bias if cameras are clustered [S4]. The corrected extent is $e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2$ [S4].

### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ to selectively enlarge covariances, creating pixel-wise variable blur kernels that match spatially varying scene blurriness [S5]. It sets itself apart from naive Gaussian blur (which applies a single kernel to the whole image) by allowing spatially varying blur shapes and magnitudes [S5]. If $\delta s_j$ is predicted as a constant for all Gaussians, it degrades to a uniform Gaussian blur [S5].

### Denoise-GS
A self-supervised denoising method for sparse-view 3D Gaussian Splatting that combines unsupervised image denoising (Noise2Void) with explicitly differentiable 3DGS [S6]. It solves the problem of suboptimal reconstruction in sparse view and noisy scenes where supervised methods fail due to lack of clean annotations [S6]. It uses a two-round process: Round 1 trains a UNet with N2V and initializes 3DGS; Round 2 fine-tunes the UNet and re-renders [S6].

### Multi-Scale Constraint
A technique using position-aware point adaptive control to apply different scales to Gaussians based on viewer distance, improving rendering of distant objects [S7]. It uses a scaling factor $\gamma(\mu)$ based on distance from camera center $c$ and scene radius $r$: $\gamma(\mu) = 1$ if $\|\mu - c\|^2 < 2r$, else $\|\mu - c\|^2 / r - 1$ [S7]. Cloning occurs if $\max(s) < g \cdot \gamma(\mu)$, splitting if $\max(s) \ge g \cdot \gamma(\mu)$, and elimination if $\max(s) > b \cdot \gamma(\mu)$ [S7].

### LS-Gaussian Viewpoint Transformation
An algorithm that leverages inter-frame continuity for efficient sparse rendering by transforming the viewpoint between consecutive frames, rather than rendering each frame separately [S8]. It sets itself apart from naive pixel warping by operating at the tile/Gaussian level to reduce preprocessing and sorting costs [S8]. Rendering quality degrades noticeably as the number of consecutively transformed frames increases due to accumulated interpolation errors [S8]. Used in LS-Gaussian to enable sparse rendering where only one frame in every 6 frames is fully rendered [S8].

### Camera Localisation for Convergence Basin
Localizes camera pose by minimizing only the photometric error against the ground-truth colour image of the target view, fixing the initial Gaussians $G_{init}$ during optimization [S9, unofficial]. It solves the problem of initializing camera poses for novel views. The estimated pose $T_{CW}^{est}$ is found by $\mathbf{T}_{CW}^{est} = \underset{\mathbf{T}_{CW}}{\arg \min} \left\| I(\mathcal{G}_{init}, \mathbf{T}_{CW}) - \bar{I}_{target} \right\|_1$ [S9, unofficial].

### DiffGS Framework
Applies an optimization process during Gaussian extraction to optimize Gaussians to exact locations using a Gaussian Probability Function (GauPF) [S10]. It uses a truncation function $\lambda$ and a projection function $\tau(x) = e^{-x}$ or linear projection [S10]. It achieves high PSNR/SSIM with fewer Gaussians (e.g., 350K Gaussians: PSNR 34.01, SSIM 0.9879) [S10].

### Opacity Offset Table for DSA
Constructs an opacity offset table to model changes in digital subtraction angiography [S11].

### Conditional Splat Approximation
Approximates the influence range of a 3D Gaussian on a slice by using a 2D ellipse splat scaled by the marginal factor, which closely matches the true iso-probability contours [S12, unofficial]. It provides an accurate and efficient approximation of the original 3D Gaussian’s influence range for slice-based rendering [S12, unofficial].

### PyGS Optimization
Optimization process using a combined MSE and SSIM loss, along with density control strategies adapted from 3DGS, while preserving the multi-scale structure [S13, unofficial]. Newly split/cloned Gaussians remain in their original level and cluster. Levels are routinely reassessed based on scales to preserve multi-scale characteristics [S13, unofficial]. Loss: $L = \lambda \cdot \text{MSE}(C, \hat{C}) + (1 - \lambda) \cdot \text{SSIM}(C, \hat{C})$ [S13, unofficial].

### GAINS (Gaussian-based Inverse Rendering from Sparse multi-view captures)
A two-stage inverse rendering framework that leverages foundation model priors to stabilize geometry and material estimation from sparse multi-view RGB captures [S14]. Stage I optimizes geometry using monocular depth, normal, and diffusion priors. Stage II jointly optimizes material parameters and lighting using segmentation, intrinsic image decomposition, and diffusion priors [S14]. It uses 2DGS instead of 3DGS for more accurate geometry reconstruction [S14].

### SAGS (Adaptive Gaussian Splatting)
Utilizes an adaptive 2D low-pass filter at inferencing time based on rendering resolution and camera distance to handle aliasing [S15, unofficial].

### Frequency Gaussian Splatting
Applies frequency-domain regularization to the rendered 2D image to encourage recovery of high-frequency detail, resolving blurring issues [S15, unofficial].

### Sparse Adaptive Scalable Compact Gaussian Splatting
A compression method that utilizes vector clustering to encode color and geometric attributes [S15, unofficial].

## Operating characteristics

*   **Time Complexity:** The forward pass is $O(N \cdot M)$ where $N$ is the number of Gaussians and $M$ is the number of pixels, but optimized via tile-based rasterization to be effectively linear in practice. The backward pass is similar. Densification adds $O(N)$ overhead every few hundred iterations.
*   **Memory Complexity:** $O(N \cdot D)$ where $D$ is the dimensionality of Gaussian attributes (position, rotation, scale, opacity, SH coefficients). For SH degree 3, $D \approx 30$. Memory usage scales linearly with the number of Gaussians, which can reach millions for high-fidelity scenes.
*   **Measured Performance:** On standard datasets (e.g., Mip-NeRF 360), 3DGS achieves real-time rendering (>100 FPS) on modern GPUs (e.g., RTX 3090/4090) at 1080p resolution. Training time is typically 10-30 minutes per scene.
*   **Strengths:** Real-time rendering, high visual fidelity, explicit representation allows for easy editing and compression.
*   **Limitations:** High memory usage for large scenes, potential for "floaters" (transient artifacts), sensitivity to initialization and densification parameters.
*   **When to use:** When real-time novel view synthesis is required and high visual quality is prioritized over memory efficiency.
*   **When not to use:** When memory is severely constrained (consider compression methods like [Data Compression and Storage Optimization](12943-data-compression-and-storage-optimization.md)) or when the scene is extremely large (consider hierarchical methods like [Hierarchical, Graph-Based, and Adaptive Structures](17106-hierarchical-graph-based-and-adaptive-structures.md)).

## Background

3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1, S3]. It revolutionized neural rendering by providing a real-time alternative to NeRFs, using explicit 3D Gaussians instead of implicit neural fields. The method builds on the concept of splatting, where 3D primitives are projected and rasterized onto the 2D image plane. The implementation details described here are based on the original paper and subsequent optimizations for training stability, efficiency, and specific use cases like text-to-3D generation [S1] and sparse-view reconstruction [S6].
