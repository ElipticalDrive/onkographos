# Truncated Gradient Updates for 3D Gaussian Splatting

Also called: TruncGradGS, Truncated Gradient Method

## Overview
Truncated Gradient Updates for 3D Gaussian Splatting is a gradient modification technique that applies surrogate gradients to 'dead' Gaussians (those with low opacity) to enable long-range movement and convergence, addressing vanishing gradients in dynamic scenes or poor initialization [S1]. It sets itself apart from standard 3D Gaussian Splatting [3D-GS](52-3d-gaussian-splatting.md) by extending the gradient signal beyond the rasterization cutoff threshold, allowing Gaussians outside the immediate pixel footprint to receive optimization signals, while distinguishing itself from [Bézier-boundary gradient approximation](13137-b-zier-boundary-gradient-approximation.md) by using a linear surrogate based on Mahalanobis distance rather than boundary approximations.

## How it works
**Inputs and Outputs:**
*   **Inputs:** Current Gaussian parameters (mean $\mu$, opacity $\sigma$, alpha $\alpha$), pixel center $p$, loss gradient with respect to alpha $\frac{\partial L}{\partial \alpha_i}$, and optimization state (pruning threshold $\tau_{pruning}$).
*   **Outputs:** Modified gradient for the Gaussian mean $\mu$ (and opacity $\sigma$ if applicable) to be passed to the optimizer.

**Data Structures:**
The method operates on the standard 3D Gaussian Splatting primitive structure. Key fields accessed are:
*   $\mu \in \mathbb{R}^3$: 3D mean position.
*   $\sigma \in \mathbb{R}$: Opacity (often stored as a logit or sigmoid output, denoted as $\sigma$ in the source).
*   $\alpha \in \mathbb{R}$: Alpha value (transmittance contribution), derived from density and opacity.
*   $K$: A scalar derived from the Gaussian's covariance matrix components $a, b, c$ (from the 2D covariance projection).

**Numbered Steps:**

1.  **Check Gradient Sign:** Calculate the gradient with respect to alpha, $\frac{\partial L}{\partial \alpha_i}$. If $\frac{\partial L}{\partial \alpha_i} \ge 0$, do not apply the truncated gradient. Applying it when positive would cause a long-range push, making Gaussians repel each other [S1].
2.  **Calculate Mahalanobis Distance:** Compute the squared Mahalanobis distance $r_s$ between the Gaussian mean $\mu$ and the pixel center $p$:
    $$ r_s = \|\mu - p\|_2^2 $$
    Define the threshold coefficient $K$ using the projected covariance coefficients $a, b, c$ (from Eq. 8 of the source paper):
    $$ K = a(\mu_x - p_x)^2 + 2b(\mu_x - p_x)(\mu_y - p_y) + c(\mu_y - p_y)^2 $$
    The cut-off threshold condition involves solving for the distance where the Gaussian contribution equals a small value $\tau$ (typically related to the rasterization cutoff). The solution $x$ for $G(x) = \tau$ determines the cut-off point [S1].
3.  **Determine Update Path:** Evaluate the product $\sigma\alpha$ and the Mahalanobis distance relative to the threshold:
    *   **Normal Path:** If $\sigma\alpha \ge 1/255$ (high-pass filter), the Gaussian contributes significantly. Receive normal gradients from the rasterization process. No truncated gradient is applied [S1].
    *   **Truncated Path:** If $\sigma\alpha < 1/255$ (low density or low opacity) AND the Mahalanobis distance is above the threshold (the splat is filtered out by the rasterizer but is far from the pixel), apply the truncated gradient. If the low contribution is due to low opacity $\sigma$, compute the gradient only for $\sigma$ [S1].
    *   **Skip Path:** If $\sigma\alpha < 1/255$ AND the Mahalanobis distance is below the threshold, the Gaussian is close but contributes negligibly. Do not receive any gradients [S1].
4.  **Compute Truncated Gradient:** For the Truncated Path, the gradient is a linear surrogate. The slope parameter $m$ influences the range of action: a lower $m$ yields a near-constant long-range gradient approximating the cut-off gradient, and a higher $m$ yields a sharp decay from the cut-off gradient. The cut-off gradient is defined as $G'(x)$, where $x$ is the solution to $G(x) = \tau$ [S1].
5.  **Apply Interleaved Optimization:** To prevent divergence, use an interleaved strategy: alternate between optimization via the truncated gradient and normal optimization with Adaptive Density Control (ADC) turned on. This prevents perturbations to the accumulated viewspace gradient from affecting ADC [S1].
6.  **Expand Tile-Coverage Radius:** For dead Gaussians (those with $\sigma_i < \tau_{pruning}$), expand the tile-coverage radius if it is below a threshold. This addresses tile-based culling of the rasterizer, enabling long-distance pixel error contributions using the truncated gradient field [S1].
7.  **Delay Pruning:** Delay the pruning of primitives until the end of training. This allows dead Gaussians to receive long-range gradients and converge to distant pixels before being pruned [S1].

**Pseudocode:**

```python
def apply_truncated_gradient(gaussian, pixel_center, loss_grad_alpha, 
                             tau_pruning, m, threshold_coeff_K):
    """
    Applies truncated gradient updates to a Gaussian primitive.
    
    Args:
        gaussian: Object containing mean (mu), opacity (sigma), alpha (alpha), 
                  and covariance coefficients (a, b, c).
        pixel_center: 2D pixel coordinates (px, py).
        loss_grad_alpha: Gradient of loss w.r.t alpha (dL/d_alpha).
        tau_pruning: Pruning threshold for opacity.
        m: Slope parameter for the truncated gradient decay.
        threshold_coeff_K: Precomputed K value for the Gaussian.
        
    Returns:
        modified_grad_mu: Modified gradient for the mean.
        modified_grad_sigma: Modified gradient for opacity (if applicable).
    """
    # Step 1: Check gradient sign
    if loss_grad_alpha >= 0:
        return None, None  # Do not apply truncated gradient

    # Step 2: Calculate Mahalanobis distance components
    dx = gaussian.mu[0] - pixel_center[0]
    dy = gaussian.mu[1] - pixel_center[1]
    
    # K is computed from covariance coefficients a, b, c
    # K = a*dx^2 + 2*b*dx*dy + c*dy^2
    # Note: In practice, K is derived from the projected 2D covariance matrix.
    # The source defines K using coefficients from Eq. (8).
    K = threshold_coeff_K 
    
    # Calculate squared Mahalanobis distance r_s
    # r_s = ||mu - p||^2_2
    r_s = dx*dx + dy*dy
    
    # Determine if distance is above threshold
    # The threshold is related to the solution x where G(x) = tau.
    # For implementation, we check if the Gaussian is "far" enough.
    # The source states: "If the distance is greater than the cut-off threshold"
    # We assume a function is_distance_above_threshold(r_s, K, tau) exists.
    is_far = is_distance_above_threshold(r_s, K, tau=1/255) # tau approx
    
    # Step 3: Determine Update Path
    product_sa = gaussian.sigma * gaussian.alpha
    
    if product_sa >= 1/255:
        # Normal Path: High contribution
        return None, None # Use standard gradients
        
    elif is_far:
        # Truncated Path: Low contribution, far away
        # Apply truncated gradient
        # The gradient is a linear surrogate with slope m
        # Cut-off gradient G'(x) where x solves G(x) = tau
        
        # Compute the cut-off point x
        # G(x) is the Gaussian contribution function. 
        # For a 2D Gaussian, G(x) ~ exp(-x^2 / (2*sigma^2)).
        # Solving G(x) = tau for x gives the boundary.
        # The source provides the solution for r_s involving log(tau).
        # r_s_solution = ... (see source Eq. 16/17)
        
        # Simplified surrogate gradient calculation
        # The gradient magnitude is scaled by m and the distance
        # The direction is towards the pixel center
        
        grad_mu = compute_truncated_grad_mu(gaussian, pixel_center, m, K)
        
        # If low opacity is the cause, also compute grad for sigma
        if gaussian.sigma < 1/255: # Heuristic for "low opacity" cause
            grad_sigma = compute_truncated_grad_sigma(gaussian, pixel_center, m, K)
        else:
            grad_sigma = None
            
        return grad_mu, grad_sigma
        
    else:
        # Skip Path: Low contribution, close by
        return None, None

    dx = gaussian.mu[0] - pixel_center[0]
    dy = gaussian.mu[1] - pixel_center[1]

    dist = math.sqrt(dx*dx + dy*dy)
    if dist == 0:
        return [0, 0, 0]
        
    # Normalize direction

    dir_y = dy / dist

    # "a higher value of m yields a sharp decay"
    # Cut-off gradient G'(x) where x is solution to G(x) = tau
    
    # Approximate cut-off gradient magnitude

    # r_s_solution = -2 * log(tau) / K
    tau = 1/255

    # "long-range pull" suggests it pulls the Gaussian towards the pixel.

    if dist <= cutoff_dist:
        return [0, 0, 0] # Should not happen in Truncated Path

    # Or linear: Grad = m * G'(cutoff) * (1 - (dist - cutoff_dist)/max_range)?

    # The gradient is a linear function of distance.

    # G'(x) for a Gaussian is -x/sigma^2 * G(x).
    # At cutoff, G(x) = tau.

    # Let's define the cut-off gradient magnitude as:
    cutoff_grad_mag = m * cutoff_dist * K * tau / 2 
    
    # Linear decay from cutoff
    # grad_mag = cutoff_grad_mag * (1 - (dist - cutoff_dist) / max_range)
    # But max_range is not given.
    
    # Alternative: The source says "approximating the cut-off gradient" for low m.
    # This implies the gradient is roughly constant.
    # Let's use: grad_mag = m * cutoff_grad_mag_base
    # where cutoff_grad_mag_base is the gradient at the cutoff point.
    
    # We will use a simple constant gradient scaled by m for the truncated path,
    # as the "linear" aspect might refer to the surrogate function's shape in the 
    # optimization landscape, not necessarily the spatial decay.
    
    # However, "sharp decay" for high m suggests spatial dependence.
    # Let's use: grad_mag = m * exp(-m * (dist - cutoff_dist))
    
    decay = math.exp(-m * (dist - cutoff_dist))
    grad_mag = cutoff_grad_mag * decay
    
    grad_mu_x = -grad_mag * dir_x
    grad_mu_y = -grad_mag * dir_y
    grad_mu_z = 0 # 2D mean gradient
    
    return [grad_mu_x, grad_mu_y, grad_mu_z]

def compute_truncated_grad_sigma(gaussian, pixel_center, m, K):
    """
    Computes the truncated gradient for opacity sigma.
    """
    # Similar to mu, but for sigma.
    # The source says "compute the gradient only for the opacity sigma"
    # in the case of low opacity.
    # The direction is not spatial, but the magnitude is derived from the same surrogate.
    
    dx = gaussian.mu[0] - pixel_center[0]
    dy = gaussian.mu[1] - pixel_center[1]
    dist = math.sqrt(dx*dx + dy*dy)
    
    tau = 1/255
    r_s_cutoff = -2 * math.log(tau) / K
    cutoff_dist = math.sqrt(r_s_cutoff)
    
    if dist <= cutoff_dist:
        return 0
        
    cutoff_grad_mag = m * cutoff_dist * K * tau / 2
    decay = math.exp(-m * (dist - cutoff_dist))
    grad_mag = cutoff_grad_mag * decay
    
    # The gradient for sigma is positive if we want to increase opacity?
    # The loss gradient dL/d_alpha is negative (from Step 1 check).
    # We want to reduce the error.
    # If alpha is too low, we want to increase sigma.
    # So the gradient should be positive.
    
    return grad_mag
```

**Parameters:**
*   **Slope parameter $m$:** Influences the range of action of the truncated gradient in the image plane. A lower $m$ yields a near-constant long-range gradient approximating the cut-off gradient; a higher $m$ yields a sharp decay from the cut-off gradient [S1]. Typical values are not given in the sources.
*   **Pruning threshold $\tau_{pruning}$:** Used to identify 'dead' Gaussians. Only applied to Gaussians with $\sigma_i < \tau_{pruning}$ to prevent divergence [S1].
*   **Rasterization Cutoff:** Implicitly $1/255$ for the $\sigma\alpha$ product check [S1].

**Edge Cases and Pitfalls:**
*   **Model Divergence:** Accumulated truncated gradient may surpass the true gradient, especially for 'very bad fits' (no normal gradients) or 'good fits' (true gradient near zero). This is prevented by applying the truncated gradient ONLY for dead Gaussians ($\sigma_i < \tau_{pruning}$) [S1].
*   **Repulsion:** If the alpha gradient is positive, applying the truncated gradient causes a long-range push, making Gaussians repel each other. The sign check in Step 1 prevents this [S1].
*   **Tile Culling:** Dead Gaussians may be culled by the rasterizer's tile-based culling. Expanding the tile-coverage radius for dead Gaussians addresses this [S1].
*   **Performance Overhead:** The method can be 1–10× slower to train than the baseline. Optimizations include restricting radius expansion and truncated gradient computation to dead Gaussians and using motion masks for dynamic scenes [S1].

## Operating characteristics
*   **Time Complexity:** Training is 1–10× slower than the baseline 3D Gaussian Splatting, depending on the scene and primitive count [S1]. Inference speed is unaffected [S1].
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:**
    *   **Static Scene (Mip-NeRF360, Random Init):** 3DGS + Ours achieves PSNR 25.16 (vs 24.74), SSIM 0.8511 (vs 0.8351), LPIPS 0.1974 (vs 0.2106), and #GS 0.799M (vs 1.126M) [S1].
    *   **Dynamic Scene (Neural 3D Video):** 4DGS + Ours achieves PSNR 31.70 (vs 30.22), SSIM 0.9493 (vs 0.9443), LPIPS 0.1339 (vs 0.1360), and #GS 1.733M (vs 2.806M) [S1].
*   **Scaling:** The method scales with the number of primitives, but the overhead is mitigated by only applying the truncated gradient to dead Gaussians [S1].
*   **Strengths:** Improves optimization robustness by enlarging the effective support region of Gaussian primitives, allowing poorly initialized or weakly constrained Gaussians to converge. It is a plug-and-play module compatible with 3DGS, 2DGS, 4DGS, CEM-4DGS, and 4DScaffold [S1].
*   **Limitations:** Can cause divergence if applied to all Gaussians. Requires careful interleaving with ADC and delayed pruning [S1].

## Background
*   **Origin:** The method was introduced by T. Morales, N.-Q. Le-Pham, R. Atkins & B.-S. Hua in the paper "TruncGradGS: Improved 3D Gaussian Splatting via Truncated Gradient Updates" [S1].
*   **History:** It addresses the issue of vanishing gradients in dynamic scenes and poor initialization, which are common challenges in 3D Gaussian Splatting [S1].
*   **Usage:** Used as a plug-and-play module on top of 3DGS, 2DGS, 4DGS, CEM-4DGS, and 4DScaffold for both static and dynamic scene reconstruction [S1].
