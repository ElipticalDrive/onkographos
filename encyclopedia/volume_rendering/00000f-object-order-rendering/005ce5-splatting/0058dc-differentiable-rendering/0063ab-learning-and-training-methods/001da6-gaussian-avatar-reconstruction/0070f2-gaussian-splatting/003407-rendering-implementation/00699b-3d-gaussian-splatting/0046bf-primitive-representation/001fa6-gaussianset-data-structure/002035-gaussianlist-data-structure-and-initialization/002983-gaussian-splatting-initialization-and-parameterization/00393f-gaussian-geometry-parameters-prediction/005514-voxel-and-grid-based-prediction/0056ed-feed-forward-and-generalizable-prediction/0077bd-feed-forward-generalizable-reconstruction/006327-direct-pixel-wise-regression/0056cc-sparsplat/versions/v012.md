# SparSplat

Also called: Generalizable 2D Gaussian Splatting, SparSplat Model, SparSplat: Fast Multi-View Reconstruction with Generalizable 2D Gaussian Splatting

## Overview
SparSplat is a generalizable, feed-forward model that maps a sparse set of input images (typically 3) and their camera poses directly to a pixel-aligned map of 2D Gaussian Splatting (2DGS) parameters for a target view [S1, unofficial]. It solves the joint problem of fast multi-view 3D shape reconstruction and novel view synthesis (NVS) without per-scene optimization [S1, unofficial]. Unlike its sibling [MVSGaussian](15257-mvsgaussian.md) which uses 3D primitives, SparSplat uses 2D planar surface elements to ensure geometric consistency across views, enabling coherent TSDF mesh extraction [S1, unofficial]. It differs from prior generalizable GS methods by being explicitly fit for feed-forward surface reconstruction rather than NVS-only [S1, unofficial].

## How it works
**Inputs:**
*   $N$ input color images $\{I_i\}_{i=1}^N$, where $I_i \in \mathbb{R}^{H \times W \times 3}$.
*   Camera poses $\{P_i\}_{i=1}^N$ for the input images.
*   Target view pose $P_t$.

**Outputs:**
*   A 2DGS parameter map $O_t = \{s, q, p, \alpha, c\} \in \mathbb{R}^{H \times W \times (2+4+3+1+3)}$ for the target view [S1, unofficial].
    *   $s$: Scale (2D, 2 components).
    *   $q$: Rotation (Quaternion, 4 components).
    *   $p$: 3D Position (centroid, 3 components).
    *   $\alpha$: Opacity (1 component).
    *   $c$: Color (3 components).
*   Optional: A 3D triangle mesh $S$ derived from the rendered depths [S1, unofficial].

**Data Structures:**
*   **Feature Maps:** 2D tensors extracted from input images.
*   **Cost Volume:** 3D tensor constructed from warped features.
*   **Probability Volume:** 3D tensor representing depth likelihoods.
*   **Parameter Map:** 5D tensor $O_t$ containing Gaussian attributes per pixel.

**Algorithm Steps:**

1.  **Feature Encoding:**
    *   Extract monocular 2D semantic features from each input image $I_i$ using DINOv2 [S1, unofficial].
    *   Extract pairwise dense correspondence features from input images using MASt3R [S1, unofficial].
    *   Predict a 2D feature map $f_i$ for each input image $I_i$ using a Feature Pyramid Network (FPN) [S1, unofficial].

2.  **Feature Warping:**
    *   For the target view $P_t$, warp the feature maps $f_i$ from each input view $P_i$ to the target view coordinate system using homography based on relative poses $P_t / P_i$ [S1, unofficial].
    *   Let the warped features be $f_{t,i}$ [S1, unofficial].

3.  **Deep MVS Branch (Depth Prediction):**
    *   Merge the warped features $f_{t,i}$ into a cost volume [S1, unofficial].
    *   Process the cost volume into a probability volume using a 3D convolutional network [S1, unofficial].
    *   Sample depth planes: 64 planes for the coarse stage and 8 planes for the fine stage [S1, unofficial].
    *   Produce a depth prediction [S1, unofficial].
    *   Unproject the predicted depth using camera intrinsics $K$ to obtain the 3D position attribute $p$ [S1, unofficial].

4.  **Pixel-Aligned Prediction Branch (Gaussian Attributes):**
    *   Pool the warped features $f_{t,i}$ into a target feature map $f_t$ [S1, unofficial].
    *   Pass $f_t$ through a 2D convolutional network and an MLP [S1, unofficial].
    *   Predict the remaining Gaussian primitive attributes $\{s, q, \alpha, c\}$ [S1, unofficial].

5.  **Parameter Map Assembly:**
    *   Combine the predicted attributes to form the full parameter map $O_t = \{s, q, p, \alpha, c\}$ [S1, unofficial].

6.  **Rendering and Mesh Extraction (Inference):**
    *   Render the scene for the target view using perspective-accurate 2D Gaussian Splatting rasterization [S1, unofficial].
    *   To extract an explicit 3D triangle mesh $S$:
        *   Render depth maps $D_i$ for all $N$ input views using their respective inferred splat maps $O_i = \Phi(P_i | I_1, ..., I_N)$ [S1, unofficial].
        *   Perform Truncated Signed Distance Function (TSDF) fusion on the mean splatted depths [S1, unofficial].
        *   Set TSDF voxel size to 1.5 [S1, unofficial].

**Loss Functions and Training:**
*   Training uses an image resolution of $640 \times 512$ and $N=3$ source images [S1, unofficial].
*   Optimizer: Adam, initial learning rate $5 \times 10^{-4}$, 300k steps on a single RTX A6000 GPU [S1, unofficial].
*   Loss weights: $\lambda_s = 0.1$, $\lambda_p = 0.05$, $\lambda_\alpha = 0.05$, $\lambda_\beta = 0.05$, $\lambda_\gamma = 0.05$, $\lambda_1 = 0.5$, $\lambda_2 = 1$ [S1, unofficial].
*   Depth loss ($L_{depth}$): Supervision on the mean 2DGS splatted depth using ground truth depth from the DTU dataset [S1, unofficial].

**Pseudocode:**

```python
import torch
import torch.nn as nn

class SparSplat:
    def __init__(self):
        # Feature encoders
        self.dinov2_encoder = DINOv2() # Monocular semantic features
        self.mast3r_encoder = MASt3R() # Pairwise dense correspondence features
        self.fpn = FPN() # Feature Pyramid Network
        
        # MVS Backbone (Deep MVS Branch)
        self.cost_volume_net = CostVolumeNetwork()
        self.prob_volume_net = ProbVolumeNetwork()
        self.depth_decoder = DepthDecoder(coarse_planes=64, fine_planes=8)
        
        # Gaussian Attribute Predictor (Pixel-Aligned Branch)
        self.feature_pooler = FeaturePooler()
        self.attr_predictor = AttrPredictor() # 2D Conv + MLP
        
        # Loss weights
        self.lambda_s = 0.1
        self.lambda_p = 0.05
        self.lambda_alpha = 0.05
        self.lambda_beta = 0.05
        self.lambda_gamma = 0.05
        self.lambda_1 = 0.5
        self.lambda_2 = 1

    def forward(self, images, poses, target_pose, intrinsics):
        """
        images: List of N input images [H, W, 3]
        poses: List of N camera poses [R, t]
        target_pose: Target camera pose [R, t]
        intrinsics: Camera intrinsics K
        """
        N = len(images)
        
        # 1. Feature Encoding
        # Extract monocular features
        mono_features = [self.dinov2_encoder(img) for img in images]
        # Extract pairwise features (MASt3R handles dense correspondences)
        pairwise_features = self.mast3r_encoder(images)
        
        # Predict 2D feature maps via FPN
        f_i = [self.fpn(img) for img in images]
        
        # 2. Feature Warping
        # Warp features to target view using homography from relative poses
        f_t_i = []
        for i in range(N):
            # Homography H based on target_pose / poses[i]
            H = compute_homography(target_pose, poses[i])
            f_t_i.append(warp_homography(f_i[i], H))
            
        # 3. Deep MVS Branch
        # Merge warped features into cost volume
        cost_volume = merge_features(f_t_i)
        
        # Process into probability volume
        prob_volume = self.prob_volume_net(self.cost_volume_net(cost_volume))
        
        # Predict depth
        depth_pred = self.depth_decoder(prob_volume)
        
        # Unproject depth to 3D position p
        # p is obtained by unprojecting depth_pred using intrinsics K
        p = unproject_depth(depth_pred, intrinsics)
        
        # 4. Pixel-Aligned Prediction Branch
        # Pool warped features into target feature map
        f_t = self.feature_pooler(f_t_i)
        
        # Predict Gaussian attributes {s, q, alpha, c}
        attrs = self.attr_predictor(f_t)
        s, q, alpha, c = attrs
        
        # 5. Assemble Parameter Map
        # O_t = {s, q, p, alpha, c}
        O_t = {
            's': s,
            'q': q,
            'p': p,
            'alpha': alpha,
            'c': c
        }
        
        return O_t

    def compute_loss(self, O_t, target_image, target_depth):
        # Render image from O_t using 2DGS rasterizer
        rendered_image = render_2dgs(O_t)
        
        # Render depth from O_t
        rendered_depth = render_depth_2dgs(O_t)
        
        # Photometric loss
        loss_rgb = mse_loss(rendered_image, target_image)
        
        # Depth loss
        loss_depth = mse_loss(rendered_depth, target_depth)
        
        # Other losses (scale, position, etc. as per paper weights)
        # Note: Specific formulas for s, q, alpha losses are not detailed in sources
        # [G] Assuming standard Gaussian regularization losses for stability
        loss_s = regularization(O_t['s'])
        loss_q = regularization(O_t['q'])
        loss_alpha = regularization(O_t['alpha'])
        
        total_loss = (
            self.lambda_2 * loss_rgb +
            self.lambda_1 * loss_depth +
            self.lambda_s * loss_s +
            self.lambda_p * 0 + # Position loss often implicit in depth supervision
            self.lambda_alpha * loss_alpha +
            self.lambda_beta * 0 + # Placeholder for other regularizations
            self.lambda_gamma * 0 # Placeholder for other regularizations
        )
        
        return total_loss

    def extract_mesh(self, images, poses, intrinsics):
        """
        Extract 3D mesh using TSDF fusion from rendered depths.
        """
        depths = []
        for i in range(len(images)):
            # Infer splat map for each input view
            O_i = self.forward(images, poses, poses[i], intrinsics)
            # Render depth for this view
            D_i = render_depth_2dgs(O_i)
            depths.append(D_i)
            
        # TSDF Fusion
        # Voxel size 1.5
        mesh = tsdf_fusion(depths, poses, intrinsics, voxel_size=1.5)
        return mesh
```

**Edge Cases and Pitfalls:**
*   **3DGS vs 2DGS:** Using 3DGS instead of 2DGS causes depth inconsistencies across views, leading to TSDF producing incorrect fusions with warped/disconnected surfaces [S1, unofficial].
*   **Prior Method Failure:** Prior SOTA generalizable GS method [MVSGaussian](15257-mvsgaussian.md) fails to give coherent reconstructions on TSDF fusion of rendered depth maps [S1, unofficial].
*   **Feature Choice:** Using only image features or DINOv2 features yields poor results compared to MASt3R. MASt3R provides an 11.11% boost over image-only features, while DINOv2 provides only a 0.85% boost [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Inference is nearly 2 orders of magnitude faster than prior state-of-the-art feed-forward sparse view reconstruction based on volume rendering of implicit representations [S1, unofficial].
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:**
    *   Inference time: 0.8s (reproduced 0.88s) on RTX A6000 [S1, unofficial].
    *   Comparison: 66s for UfoRecon, 32s for GeoTransfer [S1, unofficial].
    *   DTU Test Set (NVS): PSNR 28.33, SSIM 0.938, LPIPS 0.073 [S1, unofficial].
    *   DTU Test Set (Reconstruction): Mean Chamfer Distance 1.04 (with MASt3R and depth loss) [S1, unofficial].
*   **Scaling:** Performance improves with the addition of depth loss $L_{depth}$, improving mean chamfer distance by 71.8% (from 4.37 to 1.04) [S1, unofficial].
*   **Strengths:**
    *   Fast multi-view reconstruction and novel view synthesis from sparse views (3 views) [S1, unofficial].
    *   Coherent 3D geometry reconstruction due to 2DGS representation [S1, unofficial].
    *   Strong generalization on unseen scenes (DTU, BlendedMVS, Tanks and Temples) [S1, unofficial].
*   **Limitations:**
    *   Requires camera poses for input images [S1, unofficial].
    *   TSDF fusion quality depends on the consistency of the rendered depths, which is why 2DGS is preferred over 3DGS [S1, unofficial].
*   **When to use:** When fast, generalizable 3D reconstruction and NVS from sparse views (e.g., 3 images) is required, and explicit mesh extraction is needed.
*   **When not to use:** When dense input views are available and per-scene optimization is acceptable, or when 3DGS is strictly required for other reasons (though it harms TSDF fusion here).

## Background
*   **Origin:** SparSplat was proposed by Shubhendu Jena et al. in 2025 [S1, unofficial].
*   **History:** It extends the MVSGaussian framework [48] by replacing 3D primitives with 2D Gaussian Splatting (2DGS) [28] to improve geometric consistency. It incorporates features from foundation models DINOv2 [59] and MASt3R [41], inspired by MVSFormer++ [6].
*   **Usage:** Evaluated on DTU sparse 3D reconstruction benchmark, BlendedMVS, and Tanks and Temples datasets [S1, unofficial].
