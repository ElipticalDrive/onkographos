# Warp-Level Culling for Efficient Blending in 3D Gaussian Splatting

Also called: Warp-level sub-tile culling, Faster-GS blending optimization

## Overview
An optimization for the 3D Gaussian Splatting (3DGS) alpha blending stage that uses warp-level collaboration to subdivide image tiles and cull splats with no geometric overlap, avoiding expensive alpha evaluation [S1]. It improves rendering speed without changing the rendered output, implemented in the existing CUDA differentiable pipeline [S1]. Unlike [SnugBox](3378-snugbox.md), which focuses on tighter bounding boxes, this method focuses on geometric culling within the blending kernel to reduce the number of blending operations [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** 3D Gaussian parameters (position, covariance, opacity, spherical harmonics coefficients), camera parameters (view/projection matrices), image resolution, tile configuration (default 16×16 pixels).
*   **Output:** Final 2D image (RGB + Alpha).

**Data Structures:**
*   **Gaussian Batch:** A contiguous array of Gaussian primitives. Each Gaussian contains screen-space center $(u, v)$, covariance matrix elements (or eigenvalues/vectors), opacity $\alpha$, and color coefficients.
*   **Tile Data:** A 2D grid of tiles covering the image. Each tile contains a list of assigned splats.
*   **Shared Memory:** Used to store the current batch of splats (size 256 splats) and intermediate accumulation buffers for the tile [S1].

**Algorithm Steps:**
The rendering pipeline consists of four stages, with this method optimizing the fourth [S1]:

1.  **Preprocessing:** The `preprocess_cu` kernel selects relevant 3D Gaussians and projects them into screen space as 2D splats [S1].
2.  **Depth Sorting:** Splats are sorted by distance to the camera using CUB Device Radix Sort [S1].
3.  **Instancing:** The image is divided into tiles, and splats are duplicated into each tile they overlap. During this stage, a coarse culling is performed: the splat’s maximum opacity is computed in each assigned tile. If the opacity is below the minimum contribution threshold (8-bit RGB value of 1256), the splat is culled from that tile [S1].
4.  **Blend (Warp-Level Culling):** The `blend_cu` kernel performs alpha-over compositing [S1].
    *   **Tile Subdivision:** Each image tile (e.g., 16×16 pixels) is subdivided into sub-tiles. A GPU thread block is mapped to a tile, and warps within that block collaborate to process sub-tiles [S1].
    *   **Geometric Culling:** For each sub-tile, the warp checks if any splats in the current batch have geometric overlap with the sub-tile's pixel region. Splats with no geometric overlap are culled, avoiding the expensive alpha evaluation and compositing for those pixels [S1].
    *   **Alpha-Over Compositing:** For remaining splats, the standard alpha-over formula is applied:
        $$ C_{out} = C_{in} (1 - \alpha_{splat}) + C_{splat} \alpha_{splat} $$
        $$ \alpha_{out} = \alpha_{in} (1 - \alpha_{splat}) + \alpha_{splat} $$
        where $C$ is color and $\alpha$ is opacity [S1].
    *   **Batch Processing:** Splat data is processed in batches of 256 splats. Each batch is processed in two synchronization-fenced stages: fetching from DRAM and rendering [S1].
    *   **Data Rearrangement:** Splat data is rearranged into optimized structures for shared memory access to improve throughput [S1].

**Parameters:**
*   **Tile Size:** 16 × 16 pixels (default in Faster-GS) [S1].
*   **Contribution Threshold:** 1256 (minimum 8-bit RGB color value) used during instancing to cull low-opacity splats [S1].
*   **Batch Size:** 256 splats per batch [S1].

**Pseudocode:**
```python
# Pseudocode for the Warp-Level Culling Blend Kernel
# Assumes thread block handles one tile (e.g., 16x16 pixels)
# Assumes warp-level parallelism within the block

def blend_cu_kernel(tile_id, splat_batches, tile_splat_indices):
    # 1. Load tile configuration and sub-tile boundaries
    tile_bounds = get_tile_bounds(tile_id) # e.g., (x_start, y_start, width, height)
    sub_tile_bounds = subdivide_tile(tile_bounds, warp_id) # Subdivide based on warp index
    
    # 2. Initialize output buffers for this tile
    tile_color = vec3(0.0)
    tile_alpha = 0.0
    
    # 3. Iterate through splat batches assigned to this tile
    for batch_idx in range(num_batches):
        splat_batch = splat_batches[batch_idx]
        
        # 4. Warp-level collaboration for culling
        # Each warp handles a subset of splats or pixels within the sub-tile
        # Check geometric overlap between splats and sub-tile pixels
        culled_splats = []
        for i in range(batch_size): # batch_size = 256
            splat = splat_batch[i]
            if not geometric_overlap(splat, sub_tile_bounds):
                culled_splats.append(i)
        
        # 5. Compositing for non-culled splats
        for i in range(batch_size):
            if i in culled_splats:
                continue
            
            splat = splat_batch[i]
            # Alpha-over compositing
            alpha_splat = splat.opacity
            color_splat = splat.color
            
            tile_color = tile_color * (1.0 - alpha_splat) + color_splat * alpha_splat
            tile_alpha = tile_alpha * (1.0 - alpha_splat) + alpha_splat
            
    # 6. Write final tile color and alpha to global memory
    write_to_framebuffer(tile_id, tile_color, tile_alpha)
```

## Subtopics

## Operating characteristics
*   **Performance:** On NVIDIA RTX 4090, the method is up to 19% faster than Faster-GS. On NVIDIA RTX 2070 Super, it is up to 32% faster. Across all tested GPUs (RTX 4090, RTX 3090, RTX 2070 Super), the changes reduce frame time over Faster-GS by 17% (+20% FPS) on average (geometric mean). On the RTX 2070 Super specifically, the frame time reduction is up to 24% (+32% FPS) [S1].
*   **Complexity:** The baseline alpha-blending GPU kernel (Faster-GS) performs two to three times slower than the optimistic theoretical bound. This method reduces that gap by eliminating redundant computations [S1].
*   **Strengths:** Maintains identical visual fidelity and differentiability as the original 3DGS implementation. It stays within the CUDA differentiable framework, unlike methods such as PUP 3D-GS, Sort-Free Gaussians, or VKRayGS which sacrifice image quality or differentiability [S1].
*   **Limitations:** Requires modification of the standard CUDA pipeline. Performance gains are hardware-dependent (tested on NVIDIA RTX 4090, 3090, 2070 Super) [S1].

## Background
3D Gaussian Splatting (3DGS) [Kerbl et al. 2023] has become a dominant technique for novel view synthesis. Despite thousands of follow-up methods, there is still room for improvement in rendering speed. This method analyzes the state-of-the-art inference pipeline (Faster-GS) and improves it by focusing on the alpha blending stage, which is one of the longest-running stages in the pipeline [S1]. The code implementation can be used in the ICG Neural Radiance Fields and Novel View Synthesis Framework (NeRFICG) [Kappel et al. 2026] [S1].
