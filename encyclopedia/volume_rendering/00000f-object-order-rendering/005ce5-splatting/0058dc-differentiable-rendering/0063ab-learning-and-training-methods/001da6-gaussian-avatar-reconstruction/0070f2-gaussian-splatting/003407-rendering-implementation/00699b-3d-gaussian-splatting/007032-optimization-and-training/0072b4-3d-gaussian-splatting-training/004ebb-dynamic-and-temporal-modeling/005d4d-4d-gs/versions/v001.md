# 4D-GS
Also called: 4D Gaussian Splatting
## Overview
4D-GS extends 3D Gaussian Splatting to dynamic scenes by parameterizing Gaussian attributes as functions of time, enabling the reconstruction and rendering of non-rigidly deforming objects [S1, unofficial]. It distinguishes itself from sibling NeRF-based dynamic methods by retaining the efficient splatting rasterization pipeline while replacing static positional encoding with multi-resolution hexplane voxels to capture spatiotemporal correlations [S1, unofficial].
## How it works
**Inputs and Outputs:**
*   **Input:** A sequence of images $\{I_t\}$ of a dynamic scene at times $t$.
*   **Output:** A set of 4D Gaussians parameterized by time, allowing rendering of arbitrary viewpoints and timestamps.

**Data Structures:**
Each Gaussian $i$ maintains base attributes in a canonical space (typically $t=0$) and deformation parameters. The key innovation is the encoding of the spatiotemporal context.
*   **Hexplane Voxels:** A multi-resolution structure consisting of three 2D planes (XY, YZ, XZ) for spatial features and three 2D planes (TX, TY, TZ) for temporal features, or similar combinations, storing feature vectors. This replaces the standard positional encoding used in static 3DGS [S1, unofficial].
*   **Attribute MLPs:** Compact Multi-Layer Perceptrons (MLPs) map the hexplane features to specific Gaussian attributes. Separate MLPs are used for different attributes (e.g., one for position/rotation, another for scale, another for color) to ensure stable optimization [S1, unofficial].

**Steps:**
1.  **Static Initialization:** First, optimize a static 3DGS representation using the first frame or a static subset of the data. This provides a stable base geometry [S1, unofficial].
2.  **Deformation Field Construction:** Initialize the hexplane voxels and attribute MLPs. The hexplanes encode the spatiotemporal coordinates $(x, y, z, t)$ of each Gaussian.
3.  **Attribute Prediction:** For a Gaussian at time $t$:
    *   Query the hexplane voxels at the spatial position $(x,y,z)$ and time $t$ to obtain feature vectors.
    *   Pass these features through the respective compact MLPs to predict the delta values or absolute values for attributes:
        *   Position $\mathbf{p}(t)$ and Rotation $\mathbf{q}(t)$ are derived from the deformation MLP.
        *   Scale $\mathbf{s}(t)$ and Opacity $\alpha(t)$ are derived from their respective MLPs.
        *   Color $\mathbf{c}(t)$ is derived from the color MLP.
4.  **Rendering:** Project the time-dependent Gaussians to 2D and rasterize using standard alpha blending [S1, unofficial].
5.  **Temporal Smoothing:** To prevent flickering and amplify temporal consistency, linearly decaying Gaussian noise is added to the encoded time vector during training [S1, unofficial].
6.  **Optimization:** Minimize photometric loss (L1) between rendered and ground truth images. The training proceeds by optimizing the hexplane features and MLP weights while keeping the base static geometry stable [S1, unofficial].

**Formulas:**
Let $F_{hex}(x, y, z, t)$ be the feature vector extracted from the multi-resolution hexplane voxels at spatial coordinates $(x,y,z)$ and time $t$.
The attributes are predicted as:
$$ \mathbf{A}(t) = \text{MLP}_A(F_{hex}(x, y, z, t)) $$
where $\mathbf{A}$ represents specific attributes like position, rotation, scale, or color [S1, unofficial].

**Parameters:**
*   **Hexplane Resolution:** Not given in the sources.
*   **MLP Size:** Compact MLPs are used, but exact layer sizes are not given in the sources.
*   **Noise Scale:** The magnitude of the linearly decaying Gaussian noise added to the time vector is not given in the sources.

**Edge Cases and Pitfalls:**
*   **Temporal Interpolation:** Discrete 3DGS can amplify artifacts during time interpolation; the hexplane encoding and noise injection mitigate this [S1, unofficial].
*   **Stability:** Optimizing deformation fields directly can be unstable; the two-stage process (static first, then deformation) ensures stability [S1, unofficial].
## Subtopics
## Operating characteristics
*   **Time Complexity:** Rendering remains efficient as it uses the same splatting pipeline as 3DGS, but attribute prediction requires querying hexplanes and MLP inference per Gaussian per frame [S1, unofficial].
*   **Memory Complexity:** Higher than static 3DGS due to the storage of hexplane voxels and MLP parameters [S1, unofficial].
*   **Strengths:** Efficient rendering, stable training via two-stage optimization, good temporal coherence [S1, unofficial].
*   **Limitations:** Requires careful tuning of hexplane resolution and MLP capacity; may struggle with highly complex non-rigid deformations if the canonical space assumption is violated [S1, unofficial].
## Background
4D-GS was introduced to address the limitations of static 3D Gaussian Splatting in dynamic scenes. It builds on the efficiency of 3DGS while incorporating temporal modeling techniques similar to those in dynamic NeRFs, but adapted for the Gaussian representation. The method was proposed in [S1, unofficial].
