# ASCII-Based Data Compression

Also called: Anywhere Compression, Base 94 Floating-Point Compression, Base 95 Integer Compression

## Overview
ASCII-Based Data Compression is a method for optimizing data transmission speed during the training of 3D Gaussian Splatting models by encoding numerical attributes into compact ASCII strings [S1, unofficial]. It improves training throughput by reducing the volume of data exchanged between processes, achieving approximately 6% or less improvement in training speed [S1, unofficial]. It differs from sibling methods like [Sensitivity-Aware Vector Clustering](12167-sensitivity-aware-vector-clustering.md) and [Compact 3D Gaussian Representation (C3DGS)](12927-compact-3d-gaussian-representation-c3dgs.md) by focusing on transmission efficiency via character encoding rather than spatial redundancy or vector quantization.

## How it works
The method encodes floating-point and integer values into ASCII strings to minimize transmission overhead. It applies specific constraints to the data domain to ensure valid character mapping.

**Inputs and Outputs:**
*   **Input:** Numerical attributes (e.g., Gaussian parameters, color matrix values) to be transmitted.
*   **Output:** ASCII strings representing the numerical values.

**Data Structures:**
*   **Integer Encoding:** Maps values in the range $[0, 95]$ to a single ASCII character.
*   **Floating-Point Encoding:** Maps the integer component to a range $[0, 94]$ using a single ASCII character, followed by a separator, then the fractional part encoded as a decimal place count.

**Steps:**

1.  **Integer Compression:**
    *   Select ASCII characters with codes 32 to 126 (inclusive).
    *   Map each integer value $v \in [0, 95]$ to a unique character $c$ from this set.
    *   The resulting string consists of one character per integer value.

2.  **Floating-Point Compression:**
    *   Select ASCII characters with codes 32 to 125 (inclusive) for the integer component.
    *   Select ASCII character 126 (`~`) as the separator between the integer and fractional parts.
    *   For a floating-point number, extract the integer part $I$ and the number of decimal places $d$.
    *   Encode $I$ (clamped or mapped to $[0, 94]$) as a single ASCII character.
    *   Append the separator character (ASCII 126).
    *   Encode $d$ (the number of decimal places) as a single ASCII character (using the same range 32-125, assuming $d$ fits within the base-94 range or is handled separately as per implementation details not fully specified). *Note: The source describes splitting into integer part $I$ and decimal places $d$, but does not explicitly detail the encoding of $d$ beyond it being part of the string structure.*

3.  **Decoding Integer:**
    *   Parse the ASCII string.
    *   Convert each character directly back to its decimal integer value based on the ASCII code mapping.

4.  **Decoding Floating-Point:**
    *   Split the ASCII string at the separator character (ASCII 126).
    *   Let the first part be the ASCII string for the integer component $I$.
    *   Let the second part be the ASCII string for the decimal places $d$.
    *   Calculate the final floating-point value $f$ using the formula:
        $$ f = I \times 10^{-d} $$
    *   *Note: The source formula $f = I10^{-d}$ implies $I$ is the integer part and $d$ is the exponent for the decimal shift.*

5.  **Color Matrix Optimization:**
    *   Compress each item of the output color matrix to only one decimal place.
    *   The value range is restricted to $[0.0, 2.0]$.
    *   This results in 21 alternative numbers ($0.0, 0.1, ..., 2.0$).
    *   Apply ASCII string compression to these quantized values to reduce data size significantly.

**Parameters:**
*   **Integer Base:** 95 (ASCII 32-126).
*   **Floating-Point Integer Base:** 94 (ASCII 32-125).
*   **Separator:** ASCII 126 (`~`).
*   **Color Precision:** 1 decimal place.
*   **Color Range:** $[0.0, 2.0]$.

**Edge Cases and Pitfalls:**
*   **Matrix Traversal Speed:** Compressing large color matrices into ASCII strings is difficult because traversing the matrix takes significant processing time [S1, unofficial].
*   **Library Limitations:** Using internal functions like `torch::where` and `torch::index_select` to replace loops improves speed but is not fast enough to fully support compression replacement [S1, unofficial].
*   **Line Breaks:** Using line break characters adds an extra operator in ASCII string writing and decoding, which should be avoided [S1, unofficial].
*   **Performance Gain:** The method gains about 6% or less improvement in training speed [S1, unofficial].

**Pseudocode:**

```python
# ASCII codes for reference
ASCII_32 = 32
ASCII_125 = 125
ASCII_126 = 126

def encode_integer(value):
    """
    Encode an integer in range [0, 95] to a single ASCII character.
    """
    if not (0 <= value <= 95):
        raise ValueError("Integer value out of range [0, 95]")
    # Map 0-95 to ASCII 32-126
    ascii_code = ASCII_32 + value
    return chr(ascii_code)

def decode_integer(char):
    """
    Decode a single ASCII character back to an integer in range [0, 95].
    """
    ascii_code = ord(char)
    if not (ASCII_32 <= ascii_code <= ASCII_126):
        raise ValueError("Invalid ASCII character for integer decoding")
    return ascii_code - ASCII_32

def encode_floating_point(value):
    """
    Encode a floating-point number into an ASCII string.
    Assumes value is split into integer part I and decimal places d.
    I is mapped to [0, 94] using ASCII 32-125.
    d is the number of decimal places.
    Separator is ASCII 126.
    """
    # Note: The source does not specify how to handle negative numbers or 
    # values where I > 94. We assume I is non-negative and <= 94.
    # We also assume d is an integer representing the number of decimal places.
    
    # Extract integer part I
    I = int(value)
    
    # Determine decimal places d
    # This step is ambiguous in the source. We assume d is provided or calculated.
    # For example, if value is 12.34, I=12, d=2.
    # However, the source formula f = I * 10^-d suggests I is the significant 
    # integer and d is the exponent. 
    # Let's assume the input to this function is already processed to have 
    # I in [0, 94] and d is the number of decimal places used.
    
    # Encode I
    if not (0 <= I <= 94):
        raise ValueError("Integer part I out of range [0, 94]")
    char_I = chr(ASCII_32 + I)
    
    # Separator
    separator = chr(ASCII_126)
    
    # Encode d
    # The source says "ASCII string for the decimal places d". 
    # It does not specify if d is encoded as a character or a string of digits.
    # Given the base-94 context, we assume d is also encoded as a single character
    # if d < 94. If d is the number of decimal places, it is likely small.
    # Let's assume d is encoded similarly to I.
    if not (0 <= d <= 94):
        raise ValueError("Decimal places d out of range [0, 94]")
    char_d = chr(ASCII_32 + d)
    
    return char_I + separator + char_d

def decode_floating_point(s):
    """
    Decode an ASCII string back to a floating-point number.
    Format: [Char for I][Separator][Char for d]
    """
    if len(s) < 3:
        raise ValueError("Invalid ASCII string length")
    
    char_I = s[0]
    separator = s[1]
    char_d = s[2]
    
    if ord(separator) != ASCII_126:
        raise ValueError("Invalid separator character")
    
    I = decode_integer(char_I)
    d = decode_integer(char_d)
    
    f = I * (10 ** -d)
    return f

def compress_color_matrix(matrix):
    """
    Compress a color matrix by quantizing to 1 decimal place in [0.0, 2.0]
    and then encoding.
    """
    # Quantize to 1 decimal place
    # Range [0.0, 2.0] with step 0.1 -> 21 values
    quantized = []
    for val in matrix.flatten():
        # Round to 1 decimal place
        rounded = round(val * 10) / 10.0
        # Clamp to [0.0, 2.0]
        rounded = max(0.0, min(2.0, rounded))
        quantized.append(rounded)
    
    # Encode each value
    # Each value is in [0.0, 2.0] with 1 decimal place.
    # This can be represented as an integer 0-20 (0.0->0, 0.1->1, ..., 2.0->20)
    # Then encode as integer.
    encoded_chars = []
    for val in quantized:
        int_val = int(round(val * 10))
        encoded_chars.append(encode_integer(int_val))
    
    return "".join(encoded_chars)
```

## Operating characteristics
*   **Time Complexity:** Not explicitly given, but matrix traversal is a bottleneck. Using `torch::where` and `torch::index_select` helps but is not fast enough for full replacement [S1, unofficial].
*   **Memory Complexity:** Reduces data size significantly for color matrices by quantizing to 1 decimal place and using ASCII encoding [S1, unofficial].
*   **Measured Performance:** Gains about 6% or less improvement in training speed [S1, unofficial].
*   **Strengths:** Simple implementation, reduces transmission overhead for numerical data.
*   **Limitations:** Matrix traversal speed is a bottleneck; not fast enough to fully replace standard transmission methods; limited performance gain (6% or less).
*   **When to Use:** When training speed is bottlenecked by data transmission and the overhead of complex compression is not justified.
*   **When Not to Use:** When higher compression ratios are needed or when matrix traversal speed is critical and cannot be optimized further.

## Background
The method was proposed in the paper "I3DGS: Improve 3D Gaussian Splatting from Multiple Dimensions" by F. Author et al. [S1, unofficial]. It is part of a broader effort to improve the training speed of 3D Gaussian Splatting models by exploring various dimensions including color, learning, structure design, and compression.
