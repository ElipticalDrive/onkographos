# SLAM and Mapping


## Overview
SLAM and Mapping in the context of 3D Gaussian Splatting (3DGS) refers to the joint estimation of camera poses and the optimization of a 3D Gaussian scene representation from a sequence of images or RGB-D frames [G]. It solves the problem of reconstructing a consistent 3D model while tracking the camera trajectory in real-time or offline [G]. Unlike standard 3DGS training which assumes known camera poses, SLAM methods must handle pose uncertainty, often integrating geometric constraints, depth information, or neural field representations to maintain consistency [G]. This family distinguishes itself by coupling the differentiable rendering of Gaussians (or hybrid neural fields) with optimization loops that update both the scene geometry/appearance and the camera extrinsics simultaneously [G].

## How it works
Inputs: sequence of images or RGB-D frames, optional initial camera poses [G].
Outputs: optimized camera poses $T$, 3D Gaussian parameters $\mathcal{G}$ (position $\mathbf{p}$, covariance $\Sigma$, opacity $\alpha$, color $\mathbf{c}$, spherical harmonics coefficients) [G].
Data structures: Gaussian primitives stored in a flat array or spatial hash grid for acceleration [G].
Numbered steps:
1. Initialize scene representation and camera poses [G].
2. Render image $\hat{I}$ and depth $\hat{D}$ from current pose $T$ via differentiable rendering (alpha-compositing for Gaussians, volume rendering for neural fields) [G].
3. Compute loss $\mathcal{L}$ between rendered and ground-truth inputs (photometric $\mathcal{L}_{rgb}$, geometric $\mathcal{L}_{depth}$) [G].
4. Backpropagate gradients $\partial \mathcal{L}/\partial T$ and $\partial \mathcal{L}/\partial \mathcal{G}$ through the renderer [G].
5. Update $T$ and $\mathcal{G}$ using gradient descent (e.g., Adam) or bundle adjustment [G].
Edge cases and pitfalls: pose drift from accumulated errors, geometric inconsistency in textureless regions, and representation choice trade-offs between explicit Gaussians and implicit fields [G].

## Subtopics

### Combined ORB-SLAM + 3DGS
Combines an existing frame-based tracking system (ORB-SLAM) with 3DGS mapping [S2, unofficial]. ORB-SLAM recovers poses, and 3DGS is trained with poses and sensor depth of keyframes, equivalent to offline splatting [S2, unofficial]. On EuRoC Machine Hall (Stereo Depth), ATE RMSE (m): ORB-SLAM3 0.052, Ours 3.190 [S2, unofficial]. Point-SLAM fails on all sequences [S2, unofficial]. ORB-SLAM achieves best ATE, but combined approach shows no significant difference in rendering metrics compared to unified 3DGS SLAM [S2, unofficial]. Unified approach is preferred for exploring 3DGS throughout the entire algorithm [S2, unofficial].

### CP-SLAM
A neural point-based hybrid neural field SLAM system enabling multi-agent cooperative localization and mapping with loop closure [S3]. Uses a keyframe-associated neural point representation inspired by PointNeRF, allowing per-point features to be adjusted during pose graph optimization [S3]. Employs a two-stage distributed-to-centralized training scheme: initial decoders are trained separately for each agent, then fused and fine-tuned jointly [S3]. Integrates odometry, loop detection, sub-map fusion, and global refinement into a unified framework [S3].

### MNE-SLAM
The first fully distributed multi-agent neural SLAM framework enabling accurate collaborative mapping and robust camera tracking without centralized training or raw data exchange [S3]. Uses a triplane+MLP hybrid neural field representation as a mapping module [S3]. Introduces an intra-to-inter loop closure strategy to reduce pose drift and align submaps across agents through peer-to-peer feature sharing and global consistency loss [S3].

### HERO-SLAM
A SLAM method employing a novel multiscale patch-based loss that aligns feature points, maps, and RGB-D pixels through warpings [S3]. Uses an INGP-like multiresolution hybrid feature grid+MLP representation for neural SDF learning [S3].

### PIN-SLAM
A globally consistent SLAM system using a point-based implicit neural (PIN) representation [S3]. Replaces grid structures with neural feature points, offering spatial flexibility and elastic correction during loop closure [S3]. Mapping alternates with odometry. Mapping step is based on a hybrid neural SDF representation with explicit neural points and implicit MLP decoders [S3]. Odometry is performed correspondence-free via second-order scan-to-map optimization [S3]. A sliding window replay buffer ensures stable incremental updates [S3]. Loop closures trigger pose graph optimization and elastic deformation of neural points, enabling consistent large-scale mapping [S3].

### Active 3D Reconstruction Algorithm
An active SLAM approach that plans camera trajectories to maximize information gain during reconstruction [S4, unofficial].
1. Initialization: Initialize 3D bounding box, uniformly sample goal-state candidates $S_g$ from view space, initialize DVGO coarse model $M(c)$ and agent state $s_0$, append initial image to database $\{I\}$ [S4, unofficial].
2. Global Policy: Select next-best-view $s^*_g$ from goal candidates $S_g$ using criterion: $s^*_g = \arg\min_{s_g \in S_g} (\lambda_{cp} l_{cp}(x_{s_g}) - \lambda_{ig} E_s(s_g))$, where $x_{s_g}$ is 3D location of $s_g$ [S4, unofficial].
3. Local Policy: Execute planning optimization to obtain optimized trajectory $S^*$ and local next-best view $s^*$ [S4, unofficial].
4. Action: Move agent to $s^*$ [S4, unofficial].
5. Observation: Obtain new image observation $I_t$ [S4, unofficial].
6. Update Database: Add new observation to database $\{I\}_{i=0}^{t+1}$ [S4, unofficial].
7. Mapping Optimization: Optimize DVGO model $M_t$ to $M_{t+1}$ by sampling pixels from database, including synchronizing entropy volume $V(E,c)$ [S4, unofficial].
8. Stop Check: Stop if (1) change in entropy volume is below threshold, or (2) maximum information gain of feasible goal candidates is below threshold [S4, unofficial].
9. Fine Stage: After exploration, initialize DVGO fine model $M(f)$ with trained coarse model $M_T(c)$ [S4, unofficial]. Perform stochastic training by sampling pixels from database $\{I\}_{i=0}^T$ for $N$ iterations, optimizing every $m$ iterations [S4, unofficial].

### Lightness-Decoupled Camera Tracking
A camera tracking method that decouples lightness from the image to handle lighting changes, by converting images to LAB space and discarding the L (lightness) channel during comparison [S5].
1. Parameterize camera pose as $T = (t, q)$ with 3D translation $t$ and rotation quaternion $q$ [S5].
2. Initialize camera pose assuming constant camera velocity [S5].
3. Convert input image $C$ and rendered image $\hat{C}$ to LAB space using $\rho$ [S5].
4. Discard the L channel [S5].
5. Minimize $L_{tracking}$ using color (A/B channels) and depth differences [S5].
Formula: $L_{tracking} = \lambda_{color} |\rho(\hat{C}) - \rho(C)| + \lambda_{depth} |\hat{D} - D|$, where $\rho$ is the operation of converting the image from RGB to LAB space, $C$ is the input image, $\hat{C}$ is the rendered image, $D$ is the input depth, and $\hat{D}$ is the rendered depth [S5].
Parameters: $\lambda_{color} = 0.5$, weight for the color term in the tracking loss. $\lambda_{depth} = 1.0$, weight for the depth term in the tracking loss [S5].

### Active Mapping with 3D Gaussian Splatting
Extends passive mapping with active view selection to maximize information gain [S6].
Mechanism: Reconstruct environment using 3D Gaussians (e.g., via SplaTAM). Propose path candidates using frontier-based exploration [S6]. Sample cameras along the path concerning the mobility of the agent [S6]. Compute EIG for each path and choose the one with the highest EIG to continue exploration [S6].
Formula: $P_j = \arg \max_{P_j} \text{tr} \left( \sum_{x_{acq_i} \in P_j} H''[y_{i\_acq}|x_{acq_i}, w*] \right) H''[w*|D_{train}]^{-1}$ [S6].

### Joint Mapping and Pose Update
A mapping subroutine that fuses tracked RGB-D frames into the existing scene map by jointly optimizing scene geometry, camera poses, and feature embeddings using a sliding window of keyframes [S7].
1. Randomly select $N_{kf}$ keyframes for each frame to form an optimization window [S7].
2. For each frame in the optimization window, randomly sample $N_m$ rays and transform them into the world coordinate system with estimated frame poses [S7].
3. Sample points within sparse voxels, render pixels, and calculate loss functions using the method from Section 4.1 [S7].
Parameters: $N_{kf}$: Number of keyframes randomly selected for the optimization window. $N_m$: Number of rays randomly sampled for each frame in the optimization window [S7].

### Salient 3D Landmark Selection
A greedy search algorithm to select N effective and non-redundant 3D landmarks from Gaussian primitives to maximize overall saliency score and ensure even scene coverage for visual localization [S8].
1. Initialize selected set S as empty. Select the primitive with the highest saliency score H(p) as the initial landmark and add to S [S8].
2. Search for the primitive with the highest saliency score that is located at a distance greater than the current search radius from any landmark already in S [S8].
3. If a suitable primitive is found, add it to S. If no suitable primitive is found, reduce the search radius and repeat the search [S8].
4. Continue the process until the size of the selected set S reaches the target number N, then stop [S8].
Parameters: N: The target number of selected 3D landmarks. tr: Distance error threshold parameter used in the Generalizability term calculation [S8].

### Multi-process Tracking and Mapping Architecture
A parallel execution model that separates camera pose tracking and map optimization into independent processes to minimize resource contention [S7].
1. Create a local copy of shared resources (voxels, features, implicit decoder) for the tracking process each time the map is updated [S7].
2. Execute tracking and mapping concurrently, relying on the local copies to avoid locks [S7].
Pitfall: Shared resource access latency can degrade performance; lock-free structures are recommended but not implemented in this work [S7].

### Gaussian SLAM Map Refinement
A refinement procedure for a global Gaussian Splatting map using a merged point cloud and training keyframes, optimizing color, depth, and scaling regularization losses [S9, unofficial].
1. Initialize GaussianModel with SH degree 3, add points from the merged point cloud, and setup optimization parameters [S9, unofficial].
2. Iterate for max_iterations: retrieve next training frame, extract ground truth color/depth and render settings [S9, unofficial].
3. Render the Gaussian model using the render settings to get rendered color and depth [S9, unofficial].
4. Compute isotropic scaling regularization loss [S9, unofficial].
5. Create a depth mask for valid pixels (depth > 0) [S9, unofficial].
6. Compute color loss as weighted sum of L1 loss on valid pixels and SSIM loss on all pixels [S9, unofficial].
7. Compute depth loss as L1 loss between rendered and ground truth depth on valid pixels [S9, unofficial].
8. Sum losses and perform backward pass [S9, unofficial].
9. Every 500 iterations, prune points with opacity less than 0.005 [S9, unofficial].
10. Step the optimizer and zero gradients [S9, unofficial].

### Local Submap Pose Optimization
1. Use color ICP as initial odometry [S10, unofficial].
2. Process a sliding window of 10 frames with a stride of 10 [S10, unofficial].
3. Disable pose regularization [S10, unofficial].
4. Introduce pose as an optimizable variable [S10, unofficial].
5. Use cost functions for SDF and CLIP [S10, unofficial].
6. Optimize jointly with SDF-only or SDF+CLIP supervision [S10, unofficial].
Numbers: ScanNet scene 0000: Color ICP + Mapping Tran err = 40.86cm, Rot err = 10.17deg, C-l1 = 15.04cm. Color ICP + SLAM(SDF) Tran err = 17.33cm, Rot err = 4.16deg, C-l1 = 11.77cm [S10, unofficial]. Color ICP + SLAM(SDF+CLIP) Tran err = 20.11cm, Rot err = 10.17deg, C-l1 = 11.72cm [S10, unofficial].
