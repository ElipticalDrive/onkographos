# Parameter Initialization

Also called: Emission, Roughness, and Specular Initialization, Median Texture Initialization for Diffuse Color

## Overview
This method defines the deterministic initialization of material parameters (emission, roughness, specular albedo, diffuse color) and geometric priors (SDF, environment map) for differentiable rendering pipelines, specifically those utilizing spherical Gaussian basis functions or texture-space sampling [S1, S2]. It solves the problem of optimization instability caused by poor initial guesses in non-convex inverse rendering problems, such as MLPs getting stuck in local minima or incorrect exposure handling [S1]. It is distinct from sibling methods like Spherical Harmonics Initialization by focusing on physical material properties and spatially-varying diffuse textures via median filtering rather than frequency-domain coefficients [S2].

## How it works

### Inputs and Outputs
**Inputs:**
*   Set of reference images $I_{ref}$ with varying exposures.
*   Object bounding box or mesh geometry.
*   Number of environment map lobes $N_{env}$.

**Outputs:**
*   Initialized SDF weights $\Theta$.
*   Initialized diffuse albedo function $a(x; \Phi)$ or texture.
*   Initialized scalar material parameters: emission $E$, roughness $r$, specular albedo $\mu$.
*   Initialized specular lobe sharpness $\lambda$.
*   Initialized environment map lobes $L_{env}$.

### Data Structures
*   **SDF Network:** Weights $\Theta$ for a Multi-Layer Perceptron (MLP) mapping 3D coordinates to signed distance values.
*   **Diffuse Albedo:**
    *   *Option A (MLP):* Parameters $\Phi$ for a function $a(x; \Phi)$.
    *   *Option B (Texture):* A 2D texture map $T_{diffuse}$ of resolution $W \times H$.
*   **Material Scalars:** Float values for $E, r, \mu, \lambda$.
*   **Environment Map:** A list of $N_{env}$ lobes, each containing a position vector $\mathbf{p}_i \in \mathbb{R}^3$ (unit sphere) and an amplitude scalar $A_i$.

### Initialization Steps

1.  **Input Image Normalization [S1]:**
    Scale all input reference images by a constant factor $k$ such that the median intensity of all pixels across all images is $0.5$. This handles varying exposure levels.

2.  **SDF Initialization [S1]:**
    Initialize the SDF network weights $\Theta$ using the method from [12] (not detailed in these sources) to ensure the initial implicit surface is roughly a sphere.

3.  **Diffuse Albedo Initialization [S1, S2]:**
    *   *For MLP-based albedo [S1]:* Initialize parameters $\Phi$ such that the predicted albedo $a(x; \Phi) \approx 0.5$ for all locations $x$ inside the object's bounding box.
    *   *For Texture-based albedo [S2]:* Construct a median texture $T_{diffuse}$:
        a. Iterate over all available reference pictures.
        b. Project each image into texture space.
        c. Use an online median estimator to update the texture values. This avoids memory issues with tens of thousands of views and suppresses view-dependent effects like specular reflections, which would be amplified by a mean filter.

4.  **Material Parameter Initialization [S2]:**
    Set constant initial values for the remaining material parameters:
    *   Emission $E = 0$.
    *   Roughness $r = 0.5$.
    *   Specular albedo $\mu = 0.5$ (Note: [S1] specifies a range for $\mu$, see below).

5.  **Specular BRDF Initialization [S1]:**
    *   Initialize lobe sharpness $\lambda$ by drawing randomly from the uniform distribution $U[95, 125]$.
    *   Initialize specular albedo $\mu$ by drawing randomly from the uniform distribution $U[0.18, 0.26]$.
    *   *Conflict Note:* [S2] suggests $\mu=0.5$ for general material parameters, while [S1] specifies $[0.18, 0.26]$ specifically for the specular BRDF component. Implementers should verify which parameter set corresponds to their specific BRDF model (e.g., whether $\mu$ in [S2] refers to a different specular term or if [S1] is more specific to the spherical Gaussian lobes).

6.  **Environment Map Initialization [S1]:**
    *   Distribute $N_{env}$ lobes uniformly on the unit sphere using a spherical Fibonacci lattice [18].
    *   Assign monochrome colors to the lobes.
    *   Randomly initialize the amplitude $A_i$ for each lobe.
    *   Scale the amplitudes such that the initial rendered pixel intensity is $\approx 0.5$.

def generate_spherical_fibonacci_lattice(n):
    """
    Generates n points uniformly distributed on a unit sphere.
    """
    indices = np.arange(0, n, dtype=float) + 0.5
    phi = np.arccos(1 - 2 * indices / n)
    theta = np.pi * (1 + np.sqrt(5)) * indices
    
    x = np.sin(phi) * np.cos(theta)
    y = np.sin(phi) * np.sin(theta)
    z = np.cos(phi)
    
    return np.stack([x, y, z], axis=-1)

### Edge Cases and Pitfalls
*   **Environment Map Intensity:** If the initial environment map is too bright or too dark, the diffuse albedo MLP may get stuck, predicting all zeros or ones during training [S1]. The scaling step in Step 6 is critical to prevent this [S1].
*   **Median vs. Mean:** Using a mean filter for diffuse color initialization can incorporate view-dependent effects (specular reflections) into the diffuse base color. The median estimator is preferred to suppress these effects [S2].
*   **Parameter Conflict:** There is a discrepancy in the initialization of specular albedo $\mu$ between [S1] ($[0.18, 0.26]$) and [S2] ($0.5$). This likely reflects different BRDF parameterizations or material definitions.

## Operating characteristics
*   **Time Complexity:** The median texture construction is $O(N \cdot M)$ where $N$ is the number of views and $M$ is the number of texture pixels, assuming an $O(1)$ online median update. The environment map generation is $O(N_{env})$.
*   **Memory Complexity:** The median texture requires $O(W \cdot H)$ memory. The online estimator adds minimal overhead compared to storing all projected views.
*   **Strengths:** Robust against exposure variations in input data; prevents optimization divergence in inverse rendering; effectively separates diffuse and specular components during initialization.
*   **Limitations:** The median texture method may be slow for very high-resolution textures or massive numbers of views if not optimized. The SDF initialization relies on an external method [12].

## Background
This initialization strategy originates from inverse rendering research aiming to reconstruct physically-based materials and lighting from images.
*   **PhySG [S1]:** Introduced the specific initialization for spherical Gaussian environment maps and BRDF parameters to enable stable training of neural implicit representations for physics-based material editing and relighting.
*   **Texture-space DR [S2]:** Proposed the median texture initialization for spatially-varying diffuse color to handle complex indoor scenes with many reference views, leveraging texture-space differentiable rendering.
