# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, GSGEN Implementation Details, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific algorithmic parameters, data structures, and optimization schedules required to implement the 3D Gaussian Splatting (3DGS) training and rendering pipeline. It addresses the problem of translating the theoretical differentiable volume rendering formulation into a stable, high-performance software system. It sets itself apart from general optimization strategies by providing concrete hyperparameters (e.g., gradient thresholds, iteration intervals) and low-level implementation choices (e.g., half-precision fetches, specific libraries) necessary for reproducibility.

## How it works
The implementation relies on a differentiable rasterization core that computes pixel color via depth-sorted alpha blending and computes gradients with respect to Gaussian parameters [6233-optimization-and-parallelization]. The following details specify the training loop, densification logic, and rendering optimizations.

### Inputs and Outputs
*   **Inputs:** Multi-view RGB images, camera poses (extrinsics $C_i$ and intrinsics), and an initial point cloud (typically from Structure-from-Motion, SfM).
*   **Outputs:** A set of 3D Gaussians $\mathcal{G}$ parameterized by position $\mu$, covariance $\Sigma$ (or scale $s$ and rotation $q$), opacity $\alpha$, and spherical harmonic coefficients $\mathbf{c}$, along with rendered novel views.

### Data Structures
*   **Gaussian Attributes:** Each Gaussian $j$ stores:
    *   Position $\mu_j \in \mathbb{R}^3$.
    *   Scale $s_j \in \mathbb{R}^3$ and Rotation $q_j \in \mathbb{R}^4$ (quaternion).
    *   Opacity $\alpha_j \in [0, 1]$.
    *   Spherical Harmonic (SH) coefficients $\mathbf{c}_j$. The default implementation uses Degree 1 (9 coefficients per RGB channel) [S3].
*   **Scene Extent:** Used for densification thresholds. The default 3DGS implementation calculates scene extent $e_{\text{scene}}$ based on camera positions:
    $$ e_{\text{scene}} = 1.1 \cdot \max_{i=1}^{N_{\text{cam}}} \|\bar{C} - C_i\|_2 $$
    where $\bar{C} = \frac{1}{N_{\text{cam}}} \sum_{i=1}^{N_{\text{cam}}} C_i$ is the average camera position [S4].
    *   *Pitfall:* This default formulation is biased if cameras are clustered (e.g., orbiting a small object in a large environment), leading to incorrect splitting/pruning [S4]. A corrected extent $e'_{\text{scene}}$ can be computed using SfM points $p_i$:
        $$ e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2 $$
        where $N_{\text{SfM}}$ is the number of SfM points [S4].

### Training Loop and Densification
The training process iteratively optimizes Gaussian parameters using gradient descent.

1.  **Initialization:** Initialize Gaussians from SfM points.
2.  **Iteration:**
    *   Randomly select a single image from the training set as supervision [S3].
    *   **Rasterization:** Project Gaussians to 2D, sort by depth, and render the image using alpha blending.
    *   **Loss Computation:** Compute loss (e.g., L1 + SSIM) between rendered and ground-truth image.
    *   **Backpropagation:** Compute gradients $\frac{\partial \mathcal{L}}{\partial \theta}$ for all Gaussian parameters [6233-optimization-and-parallelization].
    *   **Optimizer Update:** Update parameters using Adam with learning rate $1 \times 10^{-3}$ [S3].
    *   **Densification (Every 100 iterations):**
        *   Calculate accumulated view-space position gradients for each Gaussian.
        *   **Split:** If gradient > threshold $T_{\text{pos}}$, split the Gaussian into two. Default $T_{\text{pos}} = 0.02$ [S1].
        *   **Clone:** If gradient > threshold but scale is small, clone the Gaussian.
    *   **Pruning (Every 200 iterations):**
        *   Remove Gaussians with opacity $\alpha < \alpha_{\text{min}} = 0.05$ [S1].
        *   Remove Gaussians with excessively large world-space or view-space radius [S1].
    *   **Compactness Densification (Every 1000 iterations):** Perform additional densification based on compactness metrics to ensure complete geometry [S1].

### Rendering Optimizations
*   **Half-Precision Rasterization:** To reduce register pressure and memory bandwidth, feature vectors are fetched in half-precision (FP16) during both forward and backward rasterization kernels [S2].
*   **Loss Scaling:** An automatic scaling factor is applied to loss values to improve stability during half-precision training [S2].
*   **Library Implementation:** The rasterization core is often implemented using libraries like `gsplat` [S3] or custom CUDA kernels based on the 3DGUT formulation [S2].

### Pseudocode
```python
# Initialization
gaussians = initialize_from_sfm(sfm_points)
optimizer = Adam(gaussians.parameters(), lr=1e-3)
T_pos = 0.02
alpha_min = 0.05

for iteration in range(num_iterations):
    # 1. Sample Image
    image_idx = random_select_training_image()
    gt_image = get_image(image_idx)
    camera_pose = get_camera_pose(image_idx)
    
    # 2. Forward Pass (Rasterization)
    # Uses half-precision fetches for feature vectors [S2]
    rendered_image = rasterize(gaussians, camera_pose, SH_degree=1)
    
    # 3. Loss Computation
    # Apply loss scaling for FP16 stability [S2]
    loss = compute_loss(rendered_image, gt_image)
    
    # 4. Backward Pass
    optimizer.zero_grad()
    loss.backward()
    
    # 5. Optimizer Step
    optimizer.step()
    
    # 6. Densification (Every 100 iterations)
    if iteration % 100 == 0:
        gradients = get_view_space_position_gradients(gaussians)
        for g in gaussians:
            if gradients[g] > T_pos:
                split_gaussian(g) # Split if gradient is high
            elif gradients[g] > T_pos and scale(g) < threshold:
                clone_gaussian(g) # Clone if gradient is high but scale is small

    # 7. Pruning (Every 200 iterations)
    if iteration % 200 == 0:
        for g in gaussians:
            if opacity(g) < alpha_min:
                remove_gaussian(g)
            if radius(g) > max_radius:
                remove_gaussian(g)

    # 8. Compactness Densification (Every 1000 iterations)
    if iteration % 1000 == 0:
        compactness_densify(gaussians)
```

### Corrected Scene-Extent
A method to calculate scene extent based on the SfM point cloud rather than camera positions to avoid bias from camera distribution (e.g., orbiting a small object in a large environment) [S4]. The corrected extent is $e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2$, where $\bar{C}$ is the average camera position and $p_i$ are SfM points [S4]. The default extent $e_{\text{scene}} = 1.1 \cdot \max_{i} \|\bar{C} - C_i\|_2$ causes bias if cameras are clustered [S4].

### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ to selectively enlarge covariances, creating pixel-wise variable blur kernels [S5]. A compact MLP predicts $\delta s_j$ for each Gaussian $j$, which is added to the base scale to transform the covariance before projection [S5]. If $\delta s_j$ is constant, it degrades to uniform blur [S5]. This allows spatially varying blur shapes, unlike naive Gaussian blur [S5].

### Denoise-GS
A self-supervised denoising method for sparse-view 3DGS combining unsupervised image denoising with differentiable 3DGS [S6]. Round 1: Train UNet with Noise2Void (N2V) for denoising, process through InstantSplat to initialize/train 3DGS, and filter rendered results [S6]. Round 2: Fine-tune UNet with composite loss (low-frequency and perceptual consistency) and render again [S6]. N2V is used because it requires no paired data, unlike N2N, making it suitable for sparse viewpoints [S6].

### Multi-Scale Constraint
Applies different scales to Gaussians based on viewer distance to improve distant object rendering [S7]. Uses a position-aware factor $\gamma(\mu) = 1$ if $\|\mu - c\|^2 < 2r$, else $\|\mu - c\|^2 / r - 1$, where $r$ is scene radius and $c$ is camera center [S7]. Cloning occurs if $\max(s) < g \cdot \gamma(\mu)$, splitting if $\max(s) \ge g \cdot \gamma(\mu)$, and elimination if $\max(s) > b \cdot \gamma(\mu)$, with $g, b$ as threshold parameters [S7].

### LS-Gaussian Viewpoint Transformation
Leverages inter-frame continuity by transforming the viewpoint between consecutive frames for efficient sparse rendering [S8]. Unlike naive pixel warping, it operates at the tile/Gaussian level to reduce preprocessing costs [S8]. Used in LS-Gaussian to render only one frame in every 6 frames fully [S8]. Rendering quality degrades as consecutive transformed frames increase due to interpolation error accumulation [S8].

### Camera Localisation for Convergence Basin
Localizes camera pose by minimizing photometric error against ground-truth color image, fixing $G_{init}$ during optimization [S9, unofficial]. Initialize $T_{CW}$ at a test view's position and optimize for 1000 iterations [S9, unofficial]. Success if estimated pose converges to within 1cm of target view [S9, unofficial]. Pose is found by $\mathbf{T}_{CW}^{est} = \underset{\mathbf{T}_{CW}}{\arg \min} \left\| I(\mathcal{G}_{init}, \mathbf{T}_{CW}) - \bar{I}_{target} \right\|_1$ [S9, unofficial].

### DiffGS Framework
Applies optimization during Gaussian extraction to optimize Gaussians to exact locations [S10]. Uses a truncation function $\lambda$ in modeling GauPF and a projection function $\tau$ (e.g., $\tau(x) = e^{-x}$ or linear) [S10]. 50K Gaussians: PSNR 28.61, SSIM 0.9787, LPIPS 0.0251; 100K: PSNR 30.35, SSIM 0.9838, LPIPS 0.0151; 350K: PSNR 34.01, SSIM 0.9879, LPIPS 0.0149 [S10].

### Opacity Offset Table for DSA
Constructs an opacity offset table to model changes in digital subtraction angiography [S11].

### Conditional Splat Approximation
Approximates the influence range of a 3D Gaussian on a slice using a 2D ellipse splat scaled by the marginal factor [S12, unofficial]. Qualitative validation shows the conditional splat (dashed red contours) closely overlaps with true 3D Gaussian iso-probability contours (solid blue contours) [S12, unofficial].

### 3DGS Uncertainty Calculation via Fisher Information
Computes an uncertainty attribute $\bar{C}_{V;G} = -\log p_f(\pi|V; G)$ based on the negative log-likelihood of the rendered pixel value [S13]. Computed as the dot product of the gradient with itself [S13]. Assumes volume rendering meets regularity conditions: partial derivative exists almost everywhere, integral differentiability, and support independence from $G$ [S13].

## Operating characteristics
*   **Time Complexity:** Rendering is $O(N \cdot T)$ where $N$ is the number of Gaussians and $T$ is the number of tiles/pixels, dominated by sorting and alpha blending [6233-optimization-and-parallelization]. Training time is significant due to iterative densification and backpropagation through millions of parameters.
*   **Memory Complexity:** $O(N \cdot D)$ where $D$ is the dimensionality of Gaussian attributes (position, scale, rotation, opacity, SH coefficients). For high-resolution scenes, this can exceed 1GB [12943-data-compression-and-storage-optimization.md].
*   **Performance:** Real-time rendering (30-100+ FPS) is achievable on modern GPUs with optimized CUDA kernels [6233-optimization-and-parallelization]. Training can take hours to days depending on scene size and densification steps.
*   **Strengths:** High visual fidelity, real-time rendering, explicit representation allows for easy editing and compression.
*   **Limitations:** High memory usage, sensitivity to initialization, potential for artifacts in textureless regions or with sparse views.
*   **When to Use:** Real-time novel view synthesis, interactive applications, scenes with complex geometry and appearance.
*   **When Not to Use:** Resource-constrained environments without GPU acceleration, scenes requiring explicit surface meshes without post-processing.

## Background
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1, S2, S3]. It builds on the concept of differentiable volume rendering and explicit scene representations, offering a faster alternative to NeRF-based methods. The method has since been extended in numerous directions, including compression, dynamic scenes, and semantic integration.
