# Sparse View Input Scalability

Also called: Arbitrary View Count Scalability, Progressive Multi-View Reconstruction

## Overview
Sparse View Input Scalability is the capability of generalizable neural rendering methods to process an arbitrary number of input views, with reconstruction quality progressively improving as more views are added [S1]. It leverages cost volume representations as input to attribute prediction networks for Gaussians [S2, unofficial].

## How it works
**Inputs and Outputs:**
- **Inputs:** A set of $N$ input images [S1].
- **Outputs:** A set of 3D Gaussian attributes predicted by a neural network, which are rendered via differentiable rasterization [G].

**Data Structures:**
- **Cost Volume:** A representation brought into sparse view reconstruction to serve as input for the attribute prediction network [S2, unofficial].

**Steps:**
1. Construct a cost volume representation from the input views [S2, unofficial].
2. Pass the cost volume to an attribute prediction network for Gaussians [S2, unofficial].
3. The network outputs Gaussian attributes, which are rasterized to produce the output image [G].

**Formulas:**
- The Gaussian attributes $A$ are predicted by the network $f_\theta$ from the cost volume $C$:
  $$ A = f_\theta(C) $$
  where $C$ is the cost volume representation and $A$ denotes the predicted Gaussian attributes [G].

**Parameters:**
- **Number of Views ($N$):** The method supports an arbitrary number of input views, with experiments conducted using $N \in [2, 8]$ [S1].

**Edge Cases and Pitfalls:**
- **Few Views ($N=2$):** The method produces plausible geometries using only two views, but accuracy is lower than with more views [S1].

## Operating characteristics
- **Performance:** On the DTU dataset (Scan105), the method produces plausible geometries with 2 views. Quality progressively improves and converges to a fairly low reconstruction error as views increase from 2 to 8 [S1].
- **Strengths:** Generalizable to unseen scenes; handles arbitrary view counts; produces smoother surfaces compared to density-based methods like MVSNerf [S1].

## Background
The capability to handle arbitrary view counts with progressive quality improvement was demonstrated in SparseNeuS, which showed results from 2 to 8 views on the DTU dataset [S1]. The specific integration of cost volume representations into Gaussian Splatting for sparse view reconstruction was introduced by MVSplat, building on [Sparse Input Reconstruction via Generalizability](11788-sparse-input-reconstruction-via-generalizability.md) and earlier generalizable reconstruction work [S2, unofficial].
