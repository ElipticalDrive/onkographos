# 4D-GS
## Overview
4D-GS extends 3D Gaussian Splatting to dynamic scenes by parameterizing Gaussian attributes as functions of time, enabling the reconstruction and rendering of non-rigidly deforming objects from multi-view video [S1, unofficial]. It distinguishes itself from other dynamic Gaussian methods by replacing standard positional encoding with multi-resolution hexplane voxels for spatiotemporal information and employing a two-stage optimization process that first stabilizes the static scene before learning the deformation field [S1, unofficial].
## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of multi-view images $\{I_v\}$ with known camera poses and timestamps $t$ [S1, unofficial].
*   **Outputs:** A set of 4D Gaussians, where each Gaussian is defined by a base set of static attributes and a time-dependent deformation field [S1, unofficial].

**Data Structures:**
1.  **Static Gaussians:** Each Gaussian $i$ stores base attributes: position $\mathbf{c}_i$, rotation quaternion $\mathbf{q}_i$, scale $\mathbf{s}_i$, opacity $\alpha_i$, and spherical harmonic coefficients $\mathbf{c}_{i, SH}$ [G].
2.  **Hexplane Voxels:** A multi-resolution structure encoding spatiotemporal information, replacing positional encoding [S1, unofficial].
3.  **Attribute MLPs:** Compact Multi-Layer Perceptrons (MLPs) dedicated to predicting delta values for specific attributes based on inputs from the hexplane voxels and the query time $t$ [S1, unofficial].

**Algorithm Steps:**
1.  **Initialization:** Initialize a static 3D Gaussian point cloud using standard 3DGS initialization (e.g., from SfM points) [G].
2.  **Stage 1: Static Optimization:** Optimize the static Gaussian attributes ($\mathbf{c}_i, \mathbf{q}_i, \mathbf{s}_i, \alpha_i, \mathbf{c}_{i, SH}$) using standard 3DGS rendering and photometric loss until convergence [S1, unofficial].
3.  **Stage 2: Deformation Field Learning:**
    *   **Voxel Encoding:** For each Gaussian $i$ and query time $t$, encode its spatial position $\mathbf{c}_i$ and time $t$ into the multi-resolution hexplane voxels [S1, unofficial].
    *   **Temporal Smoothing:** Add linearly decaying Gaussian noise to the encoded time vector to improve temporal smoothing without additional computational overhead [S1, unofficial].
    *   **Delta Prediction:** Pass the encoded spatiotemporal features through attribute-specific compact MLPs to predict delta values ($\Delta \mathbf{c}, \Delta \mathbf{q}, \Delta \mathbf{s}$, etc.) [S1, unofficial].
    *   **Attribute Update:** Compute the dynamic attributes for time $t$ by applying the predicted deltas to the base attributes [G]. Rotation quaternions are normalized after delta application [G].
    *   **Rendering:** Render the scene using the time-dependent attributes $\mathbf{c}_i(t), \mathbf{q}_i(t), \mathbf{s}_i(t)$ for the camera timestamp $t$ [S1, unofficial].
    *   **Optimization:** Minimize photometric loss (L1) between rendered and ground truth images while optimizing the MLP weights representing the deformation field [S1, unofficial].

**Formulas:**
The exact mathematical formulations for the hexplane voxel lookup and MLP forward pass are not provided in the sources [S1, unofficial]. Attributes are updated as $\mathbf{a}_i(t) = \mathbf{a}_i + \Delta \mathbf{a}_i(t)$, where $\Delta \mathbf{a}_i(t)$ is predicted by the attribute-specific MLP [S1, unofficial].

**Parameters:**
*   **Hexplane Resolution:** Not given in the sources [S1, unofficial].
*   **MLP Architecture:** Compact MLPs; specific layer sizes not given in the sources [S1, unofficial].
*   **Noise Schedule:** Linearly decaying Gaussian noise on the time vector; decay rate not given in the sources [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Temporal Artifacts:** Without noise injection, time interpolation can amplify artifacts [S1, unofficial].
*   **Optimization Stability:** Jointly optimizing static and dynamic attributes from scratch can be unstable; the two-stage approach mitigates this [S1, unofficial].

## Subtopics

### GraphiXS
A probabilistic graphical model for 4D Gaussian Splatting that reformulates reconstruction as a Maximum a Posteriori (MAP) estimation problem, introducing structured dependencies among cameras, time, and components to handle uncertainty [S1, unofficial]. Unlike deterministic 4DGS methods that minimize photometric error directly, GraphiXS uses stochastic priors and Bayesian inference to regularize dynamics and component visibility, making it robust to sparse views and missing frames [S1, unofficial].

## Operating characteristics
*   **Complexity:** Rendering complexity is similar to 3DGS, but training involves additional overhead from hexplane voxel lookups and MLP inference for each Gaussian at each time step [G].
*   **Performance:** Not given in the sources [S1, unofficial].
*   **Strengths:** Stable training via two-stage optimization; efficient spatiotemporal encoding via hexplanes; robust temporal smoothing via noise injection [S1, unofficial].
*   **Limitations:** Requires a static baseline optimization phase [S1, unofficial].
