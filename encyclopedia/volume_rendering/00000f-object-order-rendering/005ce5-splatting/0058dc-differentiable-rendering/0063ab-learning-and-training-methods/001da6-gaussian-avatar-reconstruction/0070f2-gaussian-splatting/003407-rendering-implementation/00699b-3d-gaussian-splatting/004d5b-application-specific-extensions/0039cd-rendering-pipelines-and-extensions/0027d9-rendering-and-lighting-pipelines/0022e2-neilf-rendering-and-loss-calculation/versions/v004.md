# NeILF Rendering and Loss Calculation

Also called: inverse rendering with Blinn-Phong

## Overview
NeILF (Neural Inverse Lighting Field) is a rendering pipeline that decomposes 3D Gaussian Splatting features into physically based diffuse, specular, and ambient components using a Blinn-Phong model, enabling inverse rendering via specialized loss functions on depth, normals, and color sparsity [S1, unofficial]. It distinguishes itself from standard Gaussian Splatting by explicitly modeling lighting interactions through learnable material parameters (diffuse factor, shininess, ambient factor, specular factor) rather than relying solely on view-dependent color encoding [S1, unofficial].

## How it works
**Inputs:**
- Camera parameters: pose (view matrix $W$), intrinsics ($f_x, f_y, c_x, c_y$), resolution ($H, W$) [S1, unofficial].
- 3D Gaussian primitives: position, covariance $\Sigma$, opacity $\alpha$, and feature vectors including `diffuse_factor`, `shininess`, `ambient_factor`, `specular_factor`, and `offset_color` [S1, unofficial].
- Light configuration: `light_transform` (optional transformation for light direction) [S1, unofficial].
- Ground truth: `gt_image`, `gt_depth`, `image_mask`, `depth_mask` [S1, unofficial].
- Optimization weights: `lambda_render`, `lambda_phong`, `lambda_depth`, `lambda_opacity`, `lambda_normal_render_depth`, `lambda_normal_mvs_depth`, `lambda_offset_color_sparsity`, `lambda_diffuse_factor_smooth`, `lambda_ambient_factor_smooth`, `lambda_normal_smooth`, `lambda_dssim` [S1, unofficial].
- `sample_num`: Number of incident rays sampled for normal-based lighting, default 24 [S1, unofficial].

**Outputs:**
- `render`: Final composite image [S1, unofficial].
- `phong`: Blinn-Phong composite image [S1, unofficial].
- `normal`: Rendered surface normals [S1, unofficial].
- `pseudo_normal`: Normals derived from depth [S1, unofficial].
- `opacity`, `depth`, `diffuse_factor`, `specular_factor`, `ambient_factor`, `shininess`, `offset_color` [S1, unofficial].
- `loss`: Scalar loss value if in training mode [S1, unofficial].

**Data Structures:**
The `results` dictionary contains the following keys, all of which are tensors or lists compatible with the rendering pipeline:
- `render`: $(3, H, W)$ float tensor, final color.
- `phong`: $(3, H, W)$ float tensor, Phong model color.
- `normal`: $(3, H, W)$ float tensor, surface normals in camera space.
- `pseudo_normal`: $(3, H, W)$ float tensor, normals from depth.
- `surface_xyz`: $(N, 3)$ float tensor, 3D positions of splats.
- `opacity`: $(H, W)$ float tensor, accumulated opacity.
- `depth`: $(H, W)$ float tensor, accumulated depth.
- `viewspace_points`: List of viewspace points for each splat.
- `visibility_filter`: Boolean mask for splats with `radii > 0` [S1, unofficial].
- `radii`: $(N)$ int tensor, projected radii of splats.
- `num_rendered`: Int, number of splats rendered.
- `num_contrib`: $(H, W)$ int tensor, number of contributing splats per pixel.
- `diffuse_factor`: $(N, 3)$ float tensor, diffuse color factor.
- `offset_color`: $(N, 3)$ float tensor, view-dependent offset color.
- `shininess`: $(N)$ float tensor, specular exponent.
- `ambient_factor`: $(N)$ float tensor, ambient intensity.
- `specular_factor`: $(N, 3)$ float tensor, specular color factor.
- `diffuse_term`, `specular_term`, `ambient_term`: $(3, H, W)$ float tensors, individual lighting components.
- `hdr`: Boolean, whether output is HDR [S1, unofficial].
- `val_gamma`: Float, gamma value for LDR conversion [S1, unofficial].
- `tb_dict`: Dictionary for TensorBoard logging [S1, unofficial].
- `loss`: Float, total loss value [S1, unofficial].

**Algorithm Steps:**

1. **Base Rendering:** Call the standard Gaussian Splatting `render_view` function to obtain base features, including `diffuse_factor`, `offset_color`, `shininess`, `ambient_factor`, `specular_factor`, `normal`, `opacity`, `depth`, and `visibility_filter` [S1, unofficial].

2. **Lighting Transformation:** If `light_transform` is provided, apply it to the material factors. This involves multiplying and adding offsets to `diffuse_factor`, `shininess`, `ambient_factor`, and `specular_factor` to account for light position/orientation relative to the camera [S1, unofficial].

3. **Diffuse Color Computation:**
   - Compute `offset_color_norm` as the sum of squared `offset_color` along the last two dimensions (channel and splat index), keeping dimensions:
     $$ \text{offset\_color\_norm} = \sum_{c} (\text{offset\_color}_c)^2 $$
   - For multi-Gaussian rendering (if `len(num_GSs_TFs) > 1`), iterate through groups $i$:
     - Set `diffuse_color[start_GS:end_GS]` to `offset_color + palette_color.clamp(0, 1).detach()` [S1, unofficial].
     - Multiply opacity by `opacity_factors[i]` if present [S1, unofficial].
   - Compute diffuse intensity:
     $$ I_{diffuse} = \text{diffuse\_factor} \cdot |\mathbf{n} \cdot \mathbf{l}| $$
     where $\mathbf{n}$ is the surface normal and $\mathbf{l}$ is the incident light direction [S1, unofficial].
   - Compute final diffuse color:
     $$ C_{diffuse} = (\text{ambient\_factor} + I_{diffuse}) \cdot C_{diffuse\_base} $$
     where $C_{diffuse\_base}$ is the base diffuse color derived from `diffuse_factor` and `offset_color` [S1, unofficial].

4. **Specular Color Computation:**
   - Compute the half-vector $\mathbf{h}$:
     $$ \mathbf{h} = \frac{\mathbf{l} + \mathbf{v}}{\|\mathbf{l} + \mathbf{v}\|} $$
     where $\mathbf{v}$ is the view direction [S1, unofficial].
   - Compute cosine of the angle between normal and half-vector:
     $$ \cos_h = \mathbf{n} \cdot \mathbf{h} $$
   - Compute cosine of the angle between normal and light:
     $$ \cos_l = \mathbf{n} \cdot \mathbf{l} $$
   - Compute specular intensity:
     $$ I_{specular} = \text{specular\_factor} \cdot \begin{cases} |\cos_h|^{\text{shininess}} & \text{if } \cos_l \neq 0 \\ 0 & \text{otherwise} \end{cases} $$
     [S1, unofficial]
   - Compute final specular color:
     $$ C_{specular} = I_{specular} \cdot C_{specular\_base} $$
     where $C_{specular\_base}$ is derived from `specular_factor` [S1, unofficial].

5. **PBR Combination:**
   - Combine diffuse and specular components:
     $$ C_{PBR} = C_{diffuse} + C_{specular} $$
   - Clamp the result to $[0, 1]$ [S1, unofficial].

6. **Loss Calculation (if `is_training` is true):**
   - **Render Loss:** If `lambda_render > 0`:
     - Compute L1 and SSIM between `rendered_image` and `gt_image`.
     - $$ L_{render} = (1 - \lambda_{dssim}) \cdot L1 + \lambda_{dssim} \cdot (1 - SSIM) $$
   - **Phong Loss:** If `lambda_phong > 0`:
     - Compute L1 and SSIM between `rendered_phong` and `gt_image`.
     - $$ L_{phong} = \lambda_{phong} \cdot ((1 - \lambda_{dssim}) \cdot L1_{pbr} + \lambda_{dssim} \cdot (1 - SSIM_{pbr})) $$
   - **Depth Loss:** If `lambda_depth > 0`:
     - Compute L1 between `rendered_depth` and `gt_depth`.
     - Exclude pixels where `image_mask XOR depth_mask` is true [S1, unofficial].
   - **Opacity Loss:** If `lambda_opacity > 0`:
     - Clamp `rendered_opacity` to $[10^{-6}, 1 - 10^{-6}]$ [G].
     - Compute L1 and SSIM against `image_mask`.
     - Add weighted sum to loss [S1, unofficial].
   - **Normal Loss (Render Depth):** If `lambda_normal_render_depth > 0`:
     - Compute MSE between `rendered_normal` and `pseudo_normal` (from results) masked by `image_mask` [S1, unofficial].
   - **Normal Loss (MVS Depth):** If `lambda_normal_mvs_depth > 0` and MVS normal is zero:
     - Compute `pseudo_normal` from `gt_depth` using `kornia.depth_to_normals` [S1, unofficial].
     - Transform `pseudo_normal` to world space via `camera.intrinsics` and `world_view_transform` [S1, unofficial].
     - Compute MSE against `rendered_normal` masked by `depth_mask` [S1, unofficial].
   - **Sparsity Loss:** If `lambda_offset_color_sparsity > 0`:
     - Compute sparsity loss on `rendered_offset_color_norm` masked by `image_mask` [S1, unofficial].
   - **Smoothness Losses:**
     - If `lambda_diffuse_factor_smooth > 0`: Compute bilateral smooth loss on `rendered_diffuse_factor`, `gt_image`, and `image_mask` [S1, unofficial].
     - If `lambda_ambient_factor_smooth > 0`: Compute bilateral smooth loss on `rendered_specular_intensity` and `rendered_ambient_intensity` separately, adding to loss [S1, unofficial].
     - If `lambda_normal_smooth > 0`: Compute bilateral smooth loss on `rendered_normal`, `gt_image`, and `image_mask` [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Dominated by the Gaussian rasterization step, which is $O(N)$ where $N$ is the number of splats, plus the cost of computing lighting terms per pixel. The loss calculation adds overhead proportional to the number of loss terms [S1, unofficial].
- **Memory Complexity:** Requires storing additional material parameters (`diffuse_factor`, `shininess`, `ambient_factor`, `specular_factor`, `offset_color`) per Gaussian, increasing memory usage compared to standard Gaussian Splatting [S1, unofficial].
- **Performance:** The method supports real-time rendering if the underlying Gaussian rasterization is optimized, but the additional lighting calculations and loss computations can slow down training [S1, unofficial].
- **Strengths:** Enables inverse rendering by separating lighting and material properties, allowing for more realistic relighting and material estimation [S1, unofficial].
- **Limitations:** Relies on the Blinn-Phong model, which may not capture complex lighting effects like global illumination or subsurface scattering [S1, unofficial]. The quality of normal estimation is critical for the lighting calculations [S1, unofficial].

## Background
NeILF was introduced in the context of 3D Gaussian Splatting to enable inverse rendering by decomposing features into physically based components [S1, unofficial]. It builds on the principles of Gaussian Splatting and extends them with a Blinn-Phong lighting model and specialized loss functions for training [S1, unofficial].
