# SimpleRenderer (CPU Gaussian Splatting)
Also called: Painter's Algorithm Gaussian Rendering, Simplified Gaussian Renderer

## Overview
SimpleRenderer is a CPU-based rendering method for 3D Gaussian point clouds that approximates Gaussian Splatting using a painter's algorithm [S1, unofficial]. It projects 3D Gaussians to 2D screen ellipses and composites them to generate an RGB image, suitable for visualization and small-scale point clouds where GPU acceleration is unavailable [S1, unofficial]. Unlike standard 3DD Gaussian Splatting which relies on CUDA-based tile-based rasterization for performance and differentiability, SimpleRenderer uses a simplified 2D ellipse approximation and non-differentiable alpha blending [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of 3D Gaussians (defined by mean position $\mu$, covariance matrix $\Sigma$, opacity $\alpha$, and spherical harmonic coefficients for color), a camera configuration (intrinsic and extrinsic parameters), and a `RenderConfig`.
*   **Outputs:** An RGB image buffer of shape $(H, W, 3)$ with `float32` dtype, with values in $[0, 1]$.

**Data Structures:**
*   **RenderConfig:** A dataclass containing:
    *   `background_color`: Tuple of floats, default `(0.05, 0.05, 0.08)`.
    *   `alpha_threshold`: Float, default `0.01`.
    *   `near_plane`: Float, default `0.1`.
    *   `far_plane`: Float, default `50.0`.
*   **PinholeCamera:** Defines the projection geometry:
    *   `width`, `height`: Image dimensions.
    *   `fx`, `fy`: Focal lengths in pixels.
    *   `cx`, `cy`: Principal point coordinates.
    *   `position`: Camera position in world coordinates $(3,)$.
    *   `look_at`: Target point in world coordinates $(3,)$.
    *   `up`: Up vector in world coordinates $(3,)$.

**Steps:**
1.  **Initialize Buffer:** Create an output image buffer $I$ of shape $(H, W, 3)$ initialized to `background_color`.
2.  **Iterate Gaussians:** Loop through each Gaussian $g$ in the cloud.
3.  **Project Center:**
    *   Transform the Gaussian center $\mu_g$ to camera coordinates: $\mu_c = R^T (\mu_g - t)$, where $R$ and $t$ are derived from `position`, `look_at`, and `up`.
    *   Project to pixel coordinates: $u = \frac{f_x \cdot \mu_c.x}{\mu_c.z} + c_x$, $v = \frac{f_y \cdot \mu_c.y}{\mu_c.z} + c_y$.
4.  **Culling:** Skip the Gaussian if:
    *   Its opacity $\alpha_g < \text{alpha\_threshold}$.
    *   Its depth $\mu_c.z$ is outside $[\text{near\_plane}, \text{far\_plane}]$.
5.  **Project Covariance:**
    *   Compute the 2D screen-space covariance matrix $\Sigma_{2D}$ by projecting the 3D covariance $\Sigma_g$. This involves the Jacobian $J$ of the perspective projection and the rotation matrix $R$:
        $$ \Sigma_{2D} = J R \Sigma_g R^T J^T $$
    *   The Jacobian $J$ for a point at depth $z$ is:
        $$ J = \begin{bmatrix} f_x/z & 0 & -f_x \cdot x/z^2 \\ 0 & f_y/z & -f_y \cdot y/z^2 \end{bmatrix} $$
    *   (Note: Exact implementation details for the projection of the full 3D covariance to 2D screen space may vary slightly in approximation, but the core principle is the linearization of the projection onto the tangent plane at the Gaussian center [S1, unofficial]).
6.  **Render Ellipse:**
    *   For each pixel $(x, y)$ within the bounding box of the projected ellipse:
        *   Calculate the squared Mahalanobis distance: $D^2 = (\mathbf{p} - \mathbf{c})^T \Sigma_{2D}^{-1} (\mathbf{p} - \mathbf{c})$, where $\mathbf{p} = [x, y]^T$ and $\mathbf{c} = [u, v]^T$.
        *   Compute the 2D Gaussian weight: $w = \exp(-0.5 \cdot D^2)$.
        *   Compute the final opacity contribution: $\alpha_{final} = \alpha_g \cdot w$.
        *   Compute the color $C_g$ from spherical harmonics or stored RGB.
        *   Perform alpha blending into the image buffer $I$ at $(x, y)$:
            $$ I_{new} = I_{old} \cdot (1 - \alpha_{final}) + C_g \cdot \alpha_{final} $$
            (Note: Standard volume rendering compositing is $C = \sum c_i \alpha_i \prod_{j<i} (1-\alpha_j)$. SimpleRenderer often uses a simpler additive blend or assumes opaque compositing order if not strictly sorting. The source notes imply "accumulating opacity and color" via alpha blending [S1, unofficial]).
7.  **Finalize:** Return the image buffer $I$.

**Pseudocode:**
```python
import numpy as np

def simple_renderer(gaussians, camera, config):
    """
    Render 3D Gaussians using a CPU-based painter's algorithm.
    
    Args:
        gaussians: List of Gaussian objects with attributes:
            - mean: np.ndarray (3,)
            - cov: np.ndarray (3, 3)
            - opacity: float
            - color: np.ndarray (3,) or SH coefficients
        camera: PinholeCamera object with attributes:
            - width, height, fx, fy, cx, cy
            - position, look_at, up
        config: RenderConfig object with attributes:
            - background_color, alpha_threshold, near_plane, far_plane
            
    Returns:
        np.ndarray: Image buffer (H, W, 3)
    """
    H, W = camera.height, camera.width
    # Initialize output buffer
    image = np.full((H, W, 3), config.background_color, dtype=np.float32)
    
    # Compute camera rotation matrix R and translation t
    # z-axis: normalized look_at - position
    z_axis = camera.look_at - camera.position
    z_axis /= np.linalg.norm(z_axis)
    # x-axis: cross(up, z)
    x_axis = np.cross(camera.up, z_axis)
    x_axis /= np.linalg.norm(x_axis)
    # y-axis: cross(z, x)
    y_axis = np.cross(z_axis, x_axis)
    
    R = np.stack([x_axis, y_axis, z_axis], axis=0).T # 3x3 rotation matrix from world to camera
    t = camera.position
    
    for g in gaussians:
        # 1. Project center to camera coordinates
        mu_world = g.mean
        mu_cam = R.T @ (mu_world - t) # (3,)
        
        depth = mu_cam[2]
        
        # 2. Culling
        if g.opacity < config.alpha_threshold:
            continue
        if depth < config.near_plane or depth > config.far_plane:
            continue
            
        # 3. Project to pixel coordinates
        u = (camera.fx * mu_cam[0] / depth) + camera.cx
        v = (camera.fy * mu_cam[1] / depth) + camera.cy
        
        # 4. Project covariance to 2D screen space
        # Jacobian of perspective projection at mu_cam
        # J = d(x,y)/d(X,Y,Z)
        fx = camera.fx
        fy = camera.fy
        J = np.array([
            [fx / depth, 0, -fx * mu_cam[0] / (depth**2)],
            [0, fy / depth, -fy * mu_cam[1] / (depth**2)]
        ]) # 2x3
        
        # Sigma_2D = J * R * Sigma_3D * R.T * J.T
        Sigma_2D = J @ R @ g.cov @ R.T @ J.T # 2x2
        
        # 5. Determine bounding box for the ellipse
        # Eigenvalues of Sigma_2D to get axis lengths
        eigenvalues, _ = np.linalg.eigh(Sigma_2D)
        # Use 3 sigma for bounding box to capture most energy
        radius_x = 3.0 * np.sqrt(eigenvalues[0])
        radius_y = 3.0 * np.sqrt(eigenvalues[1])
        
        min_x = int(max(0, u - radius_x))
        max_x = int(min(W - 1, u + radius_x))
        min_y = int(max(0, v - radius_y))
        max_y = int(min(H - 1, v + radius_y))
        
        if min_x > max_x or min_y > max_y:
            continue
            
        # 6. Render ellipse
        # Precompute inverse covariance for Mahalanobis distance
        try:
            Sigma_2D_inv = np.linalg.inv(Sigma_2D)
        except np.linalg.LinAlgError:
            continue
            
        for y in range(min_y, max_y + 1):
            for x in range(min_x, max_x + 1):
                p = np.array([x - u, y - v])
                D2 = p @ Sigma_2D_inv @ p
                weight = np.exp(-0.5 * D2)
                alpha_final = g.opacity * weight
                
                if alpha_final < 1e-6: # Optimization: skip negligible contributions
                    continue
                    
                color = g.color # Assuming pre-computed color for this Gaussian
                # Alpha blending
                # I_new = I_old * (1 - alpha) + C * alpha
                image[y, x] = image[y, x] * (1.0 - alpha_final) + color * alpha_final
                
    return image
```

**Parameters:**
*   `alpha_threshold`: Default `0.01`. Gaussians below this opacity are skipped.
*   `near_plane`: Default `0.1`.
*   `far_plane`: Default `50.0`.

**Edge Cases and Pitfalls:**
*   **Precision:** Floating point precision issues may arise when computing the inverse of $\Sigma_{2D}$ if the Gaussian is degenerate (e.g., very thin or flat). A small regularization term may be needed [G].
*   **Boundaries:** The bounding box calculation must be clamped to the image dimensions $[0, W-1] \times [0, H-1]$ to avoid out-of-bounds access.
*   **Non-differentiable:** This method is not differentiable and cannot be used for training. Real 3DGS training requires a CUDA differentiable rasterizer [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot B)$, where $N$ is the number of Gaussians and $B$ is the average number of pixels covered by each Gaussian's bounding box. This is significantly slower than GPU-based tile-based rasterization for large $N$.
*   **Memory Complexity:** $O(H \cdot W)$ for the image buffer. No additional large data structures are required for sorting or tiling.
*   **Performance:** Suitable for small-scale point clouds and visualization. Not suitable for real-time rendering or large scenes due to CPU limitations [S1, unofficial].
*   **Strengths:** No GPU required, simple implementation, easy to debug.
*   **Limitations:** Slow, non-differentiable, limited to small scenes.
*   **When to use:** Visualization, debugging, environments without GPU support.
*   **When not to use:** Training, real-time rendering, large-scale scenes.

## Background
SimpleRenderer is part of the GaussianScan-Recon project, an unofficial implementation of Gaussian Splatting for reconstruction tasks [S1, unofficial]. It was developed to provide a CPU-based alternative to the standard CUDA-based 3DGS renderer, enabling visualization and testing without GPU hardware. The method is explicitly noted as not suitable for training, which requires a differentiable CUDA rasterizer [S1, unofficial].
