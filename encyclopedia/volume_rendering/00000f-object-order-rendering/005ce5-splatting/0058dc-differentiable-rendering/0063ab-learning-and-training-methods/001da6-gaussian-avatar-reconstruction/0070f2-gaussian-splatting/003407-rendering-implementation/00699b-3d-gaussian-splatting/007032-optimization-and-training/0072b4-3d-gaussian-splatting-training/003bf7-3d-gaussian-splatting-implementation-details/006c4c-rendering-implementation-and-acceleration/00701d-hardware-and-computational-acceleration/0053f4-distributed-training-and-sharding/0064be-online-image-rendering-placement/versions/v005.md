# Online Image Rendering Placement

Also called: Image patch placement, Online placement of image rendering

## Overview
Online Image Rendering Placement is a distributed training optimization method that dynamically assigns image patches to GPUs at each training iteration to minimize inter-node communication and balance computational load [S1, unofficial]. It distinguishes itself from static partitioning methods by solving an Integer Linear Programming (ILP) problem online using a fast heuristic solver, allowing it to adapt to the random batch selection inherent in differentiable rendering training [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** The current batch of $B$ image patches (derived from training images), the set of $N$ GPUs, the location of 3D Gaussian primitives stored on each GPU, and configuration coefficients $\alpha, \beta, \gamma, \delta$.
*   **Outputs:** A placement vector $W$, where $W_j$ is the GPU ID assigned to render image patch $j$.

**Data Structures:**
*   **Access Pattern Matrix $A$:** A $B \times N$ integer matrix where $A_{j,k}$ represents the number of 3D Gaussian primitives required from GPU $k$ to render image patch $j$.
*   **Placement Vector $W$:** An array of length $B$ storing GPU indices.

**Steps:**
1.  **Image Partitioning:** Divide each training image of size $H \times W$ into $p^2$ patches of size $H_p \times W_p$. Typical values for $p$ are 2–8 [S1, unofficial].
2.  **Frustum Culling:** On each GPU $k$, perform frustum culling against the locally stored 3D Gaussian primitives for every image patch $j$ in the batch. Determine the subset of points needed for rendering [S1, unofficial].
3.  **Matrix Construction:** Exchange the results of frustum culling across all GPUs to construct the access pattern matrix $A$, where $A_{j,k}$ is the count of points needed from GPU $k$ for patch $j$ [S1, unofficial].
4.  **Initial Placement (LSA):** Solve a Linear Sum Assignment (LSA) problem to obtain an initial placement $W_{init}$ that minimizes total communication volume. This is solved using the Hungarian method [S1, unofficial].
5.  **Load Balancing (Local Search):** Refine $W_{init}$ using a greedy local search. Iteratively swap the GPU assignments of two image patches to minimize a relaxed objective function involving send, receive, and compute loads. Stop when convergence is reached or a time budget expires [S1, unofficial].
6.  **Hierarchical Assignment (Optional):** If operating across multiple machines, first assign patches to machines, then assign a machine's patches to its local GPUs. For intra-node assignment, set $\alpha=0$ to prioritize load balancing over communication [S1, unofficial].

**Formulas:**
The optimization aims to minimize the following objective, subject to the constraint that each GPU renders exactly $B/N$ patches:

$$
\text{minimize } \alpha \cdot \sum_{j=1}^{B} \sum_{k=1}^{N} A_{j,k} \cdot [W_j \neq k] + \beta \cdot \|\text{send}\|_p + \gamma \cdot \|\text{recv}\|_p + \delta \cdot \|\text{comp}\|_p
$$

Where the loads for GPU $k$ are defined as:

$$
\text{send}_k = \sum_{j=1}^{B} [W_j \neq k] \cdot A_{j,k}
$$

$$
\text{recv}_k = \sum_{j=1}^{B} [W_j = k] \cdot \left( \sum_{i=1}^{N} A_{j,i} - A_{j,k} \right)
$$

$$
\text{comp}_k = \sum_{j=1}^{B} [W_j = k] \cdot \sum_{i=1}^{N} A_{j,i}
$$

The relaxed norm is defined as $\|\text{send}\|_p = \left( \sum_{k=1}^{N} \text{send}_k^p \right)^{1/p}$, and similarly for $\text{recv}$ and $\text{comp}$ [S1, unofficial].

**Parameters:**
*   $B$: Batch size of training images/patches. Typical value: 16–64 [S1, unofficial].
*   $N$: Number of GPUs [S1, unofficial].
*   $p$: Power for the $p$-norm in the relaxed objective. Not given in the sources.
*   $\alpha, \beta, \gamma, \delta$: Configurable coefficients trading off communication volume, send imbalance, receive imbalance, and compute imbalance [S1, unofficial].

**Pseudocode:**

```python
def online_image_rendering_placement(batch_patches, num_gpus, gaussian_points_per_gpu, alpha, beta, gamma, delta, p_norm=2, time_budget=1.0):
    """
    batch_patches: List of B image patches.
    num_gpus: N, total number of GPUs.
    gaussian_points_per_gpu: Dict mapping gpu_id -> list of 3D Gaussian primitives.
    alpha, beta, gamma, delta: Objective coefficients.
    p_norm: Power for relaxed objective norms.
    time_budget: Max seconds for local search.
    Returns: W, list of GPU assignments for each patch.
    """
    B = len(batch_patches)
    N = num_gpus
    
    # Step 1: Frustum Culling and Matrix Construction
    # A[j, k] = number of points needed from GPU k to render patch j
    A = [[0] * N for _ in range(B)]
    
    for j, patch in enumerate(batch_patches):
        for k in range(N):
            # Perform frustum culling for patch j against points on GPU k
            # [G] Implementation detail: project 3D Gaussians to 2D screen space 
            # and count those intersecting the patch bounding box.
            points_on_gpu_k = gaussian_points_per_gpu[k]
            A[j][k] = count_intersecting_gaussians(patch, points_on_gpu_k)
            
    # Step 2: Linear Sum Assignment (LSA) for initial placement
    # Minimize total communication: sum(A[j, k] for all j,k where W[j] != k)
    # This is equivalent to maximizing sum(A[j, W[j]])
    # Using Hungarian algorithm for O(B^3) complexity
    # [G] Construct cost matrix C where C[j, k] = -A[j, k]
    cost_matrix = [[-A[j][k] for k in range(N)] for j in range(B)]
    
    # [G] The Hungarian method typically requires a square matrix. 
    # If B != N, pad with zeros or handle rectangular assignment.
    # Assuming B <= N for standard LSA formulation in this context.
    # If B > N, the constraint W_j = k = B/N implies B must be divisible by N.
    # The source implies B/N is an integer.
    
    assignment = hungarian_algorithm(cost_matrix)
    W = assignment # W[j] is the GPU assigned to patch j
    
    # Step 3: Local Search for Load Balancing
    start_time = time.time()
    
    # Define objective function
    def compute_objective(W_current):
        send = [0] * N
        recv = [0] * N
        comp = [0] * N
        
        for j in range(B):
            gpu = W_current[j]
            total_points_for_patch = sum(A[j])
            
            for k in range(N):
                if gpu != k:
                    send[k] += A[j][k]
                else:
                    recv[k] += (total_points_for_patch - A[j][k])
                    comp[k] += total_points_for_patch
                    
        # Relaxed objective
        send_norm = (sum(s**p_norm for s in send))**(1/p_norm)
        recv_norm = (sum(r**p_norm for r in recv))**(1/p_norm)
        comp_norm = (sum(c**p_norm for c in comp))**(1/p_norm)
        
        return alpha * sum(A[j][W_current[j]] for j in range(B)) + \
               beta * send_norm + \
               gamma * recv_norm + \
               delta * comp_norm

    current_obj = compute_objective(W)
    
    # Greedy steepest-ascent local search
    improved = True
    while improved and (time.time() - start_time) < time_budget:
        improved = False
        best_swap_obj = current_obj
        
        # Try all pairs of patches
        for i in range(B):
            for j in range(i + 1, B):
                # Swap assignments
                W[i], W[j] = W[j], W[i]
                
                new_obj = compute_objective(W)
                
                # We want to minimize the objective. 
                # If new_obj < current_obj, we keep the swap.
                if new_obj < current_obj:
                    current_obj = new_obj
                    improved = True
                    # Do not revert, keep the swap
                else:
                    # Revert swap
                    W[i], W[j] = W[j], W[i]
                    
    return W
```

## Operating characteristics
*   **Time Complexity:** The Linear Sum Assignment step has a time complexity of $O(B^3)$ using the Hungarian method [S1, unofficial]. The local search step's complexity depends on the number of swaps and the cost of recomputing loads, but is bounded by the time budget [S1, unofficial].
*   **Memory Complexity:** Requires storing the access pattern matrix $A$ of size $B \times N$ and the Gaussian primitives on each GPU [S1, unofficial].
*   **Strengths:** Adapts to the random batch selection in training, reducing communication overhead compared to static partitioning. Fine-grained patch placement allows better load balancing and co-location of rendering with data [S1, unofficial].
*   **Limitations:** Requires communication of frustum culling results at every iteration. ILP solvers like Gurobi are too slow for online use, necessitating the heuristic approach [S1, unofficial].
*   **When to use:** Large-scale distributed training of 3D Gaussian Splatting where communication bandwidth is a bottleneck and batch sizes are small (16–64) [S1, unofficial].

## Background
Online Image Rendering Placement is part of the Gaian system, which scales point-based differentiable rendering for large-scale reconstruction. It was introduced to address the inefficiencies of static graph partitioning when applied to the dynamic nature of training batches in differentiable rendering [S1, unofficial].
