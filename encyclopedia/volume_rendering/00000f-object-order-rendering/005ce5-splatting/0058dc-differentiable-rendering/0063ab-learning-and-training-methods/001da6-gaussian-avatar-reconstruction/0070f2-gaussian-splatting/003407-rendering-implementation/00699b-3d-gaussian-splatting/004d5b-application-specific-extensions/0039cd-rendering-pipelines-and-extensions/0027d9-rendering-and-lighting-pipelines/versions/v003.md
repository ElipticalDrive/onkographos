# Rendering and Lighting Pipelines


## Overview
This family defines the rendering and lighting architectures for 3D Gaussian Splatting (3DGS) and its extensions, addressing the limitations of standard alpha-blended splatting regarding transparency artifacts, sharp geometry reconstruction, volumetric occlusion, and physically-based relighting. Unlike standard 3DGS which renders a single composite color via front-to-back blending, these methods introduce order-independent transparency, explicit geometric primitives, volume density textures, and decomposed lighting models to enable inverse rendering and dynamic relighting.

## Shared principles
All methods in this family share the core mechanism of projecting 3D primitives into 2D screen space and accumulating color based on depth order or spatial locality [G].

1.  **Projection:** Primitives are transformed from world space to camera space [G]. The 3D covariance matrix $\Sigma$ is transformed using the view matrix $W$ and the Jacobian $J$ of the perspective projection approximation: $\Sigma_c = J W \Sigma W^T J^T$ [G]. The 2D covariance $\Sigma_{2D}$ is extracted as the upper-left $2\times2$ block [G].
2.  **Rasterization:** Primitives are assigned to screen tiles [G]. Visibility is determined by bounding boxes or projected extents [G].
3.  **Compositing:** Color is accumulated using front-to-back alpha blending or order-independent techniques [G]. The final intensity for a pixel is $I_f = \sum_{i=1}^N c_i \tilde{\sigma}_i \tilde{\mathcal{G}}_i(\mathbf{p}) \prod_{j=1}^{i-1} (1 - \tilde{\sigma}_j \tilde{\mathcal{G}}_j(\mathbf{p}))$, where $c_i$ is color, $\tilde{\sigma}_i$ is opacity or density, and $\tilde{\mathcal{G}}_i(\mathbf{p})$ is the 2D Gaussian value at pixel $\mathbf{p}$ [G].
4.  **Sorting:** Most methods require sorting primitives by depth within tiles to ensure correct front-to-back compositing, although some variants use spatial hashing or cell-level sorting to approximate this or enable order-independent transparency [G].

```python
def render_pipeline(primitives, camera, tile_size=16):
    H, W = camera['height'], camera['width']
    tiles = [(y, x) for y in range(0, H, tile_size) for x in range(0, W, tile_size)]
    tile_prims = {t: [] for t in tiles}
    
    # 1. Project & Filter
    for p in primitives:
        p_cam = transform_to_camera(p, camera['view_matrix'])
        J = perspective_jacobian(p_cam['z'])
        W_mat = camera['view_matrix']
        Sigma_2d = (J @ W_mat) @ p['Sigma'] @ (W_mat.T @ J.T)
        Sigma_2d = Sigma_2d[:2, :2]
        bbox = compute_2d_bbox(p_cam['xy'], Sigma_2d)
        for t in tiles:
            if intersects_bbox(bbox, t, tile_size):
                tile_prims[t].append({'data': p_cam, 'sigma_2d': Sigma_2d, 'depth': p_cam['z']})
    
    # 2. Sort & Rasterize
    image = zeros((H, W, 3))
    for t in tiles:
        prims = tile_prims[t]
        prims.sort(key=lambda x: x['depth'])
        for y in range(t[0], min(t[0] + tile_size, H)):
            for x in range(t[1], min(t[1] + tile_size, W)):
                acc_color = zeros(3)
                T = 1.0
                for prim in prims:
                    diff = vec2(x, y) - prim['data']['xy']
                    inv_sig = inverse_2x2(prim['sigma_2d'])
                    g_val = exp(-0.5 * dot(diff, inv_sig @ diff))
                    alpha = prim['data']['opacity'] * g_val
                    color = evaluate_color(prim['data'])
                    weight = alpha * T
                    acc_color += color * weight
                    T *= (1.0 - alpha)
                    if T < 1e-4: break
                image[y, x] = acc_color
    return image

def transform_to_camera(p, view_mat):
    pos = view_mat[:3, :3] @ p['pos'] + view_mat[:3, 3]
    return {'pos': pos, 'xy': pos[:2], 'z': pos[2], 'opacity': p['opacity'], 'Sigma': p['Sigma']}

def perspective_jacobian(z):
    return [[1.0/z, 0.0], [0.0, 1.0/z]]

def compute_2d_bbox(xy, Sigma_2d):
    eigenvalues = eigvals(Sigma_2d)
    radii = 3.0 * sqrt(eigenvalues)
    return {'min': xy - radii, 'max': xy + radii}

def intersects_bbox(bbox, t, tile_size):
    return bbox['min'][0] < t[1] + tile_size and bbox['max'][0] > t[1] and \
           bbox['min'][1] < t[0] + tile_size and bbox['max'][1] > t[0]

def inverse_2x2(M):
    det = M[0][0]*M[1][1] - M[0][1]*M[1][0]
    return [[M[1][1]/det, -M[0][1]/det], [-M[1][0]/det, M[0][0]/det]]

def dot(a, b): return sum(a[i]*b[i] for i in range(len(a)))
def vec2(x, y): return [x, y]
def zeros(n): return [0.0]*n if isinstance(n, int) else [[0.0]*n[1] for _ in range(n[0])]
def eigvals(M): return [M[0][0]+M[1][1], M[0][0]-M[1][1]] # Simplified for pseudocode [G]
def sqrt(x): return x**0.5
def evaluate_color(p): return p.get('color', [0.5, 0.5, 0.5]) # Placeholder for SH/BRDF [G]
```

## Subtopics

### [Duplex-GS](1988-duplex-gs.md)
Duplex-GS is a dual-hierarchy framework for real-time order-independent Gaussian Splatting that combines alpha-blending with reformulated Weighted-Sum Rendering (WSR) to eliminate popping and transparency artifacts while reducing sorting overhead. Unlike vanilla OIT-based Gaussian Splatting which lacks physical constraints and causes transparency artifacts, Duplex-GS reintroduces physical constraints via cell-level transmittance decay, eliminating transparency artifacts and enabling early termination. It differs from Sort-free Gaussian Splatting by using cell-level sorting to compute a physically grounded transmittance that decays rapidly upon encountering opaque objects, rather than using linear depth decay.

### [LinPrim Differentiable Rendering Pipeline](2195-linprim-differentiable-rendering-pipeline.md)
LinPrim is a differentiable rendering pipeline that replaces standard 3D Gaussian ellipsoids with convex polyhedral primitives (octahedra and tetrahedra) to enable explicit geometric optimization via ray-triangle intersections. It solves the problem of reconstructing scenes with sharp, bounded geometry while maintaining real-time performance through a two-stage preprocessing and rasterization architecture. Unlike its sibling [Duplex-GS](1988-duplex-gs.md) which uses dual representations, or [GsplatVolumeLighting](2203-gsplatvolumelighting.md) which focuses on volumetric lighting, LinPrim relies on explicit convex hulls and differentiable Möller-Trumbore intersections to backpropagate gradients directly onto geometric vertices.

### [GsplatVolumeLighting](2203-gsplatvolumelighting.md)
GsplatVolumeLighting is a volume lighting and occlusion technique for 3D Gaussian Splatting (3DGS) that ray-marches through a 3D density texture to compute transmittance for shadow and volume occlusion, combined with per-light attenuation and diffuse shading. It is implemented within the per-splat lighting evaluation loop using a shared 3D density texture.

### [NeILF Rendering and Loss Calculation](2920-neilf-rendering-and-loss-calculation.md)
NeILF Rendering and Loss Calculation is a differentiable rendering pipeline that decomposes Gaussian Splatting features into diffuse, specular, and ambient components using a Blinn-Phong shading model. It enables inverse rendering by optimizing scene parameters against ground-truth images, depth, and normals through a composite loss function. Unlike standard Gaussian Splatting which renders a single composite color, this method explicitly separates lighting terms to support material editing and physically-based constraints.

### [4DGS-Volume-Cloud Two-Stage Relighting](4101-4dgs-volume-cloud-two-stage-relighting.md)
A two-stage rendering pipeline for physically parameterized volume clouds using 3D Gaussians, designed for real-time rendering and dynamic relighting with arbitrary sun directions. It separates the optimization of static cloud geometry and physical scattering properties (Stage 1) from the learning of global environment lighting (Stage 2), allowing the cloud structure to remain frozen while the environment network adapts to new illumination conditions. Unlike sibling methods that may bake lighting into the primitives or use differentiable volume rendering for both geometry and lighting simultaneously, this method explicitly decouples the geometric occlusion and physical parameters from the environmental inscattering, enabling efficient arbitrary-direction relighting without re-optimizing the cloud itself.

## Background
The family originates from the foundational 3D Gaussian Splatting paper [17] (cited in [S2]), which established the core rasterization pipeline. Subsequent extensions addressed specific limitations: transparency artifacts ([Duplex-GS]), sharp geometry ([LinPrim]), volumetric effects ([GsplatVolumeLighting]), inverse rendering ([NeILF]), and dynamic atmospheric relighting ([4DGS-Volume-Cloud]).
