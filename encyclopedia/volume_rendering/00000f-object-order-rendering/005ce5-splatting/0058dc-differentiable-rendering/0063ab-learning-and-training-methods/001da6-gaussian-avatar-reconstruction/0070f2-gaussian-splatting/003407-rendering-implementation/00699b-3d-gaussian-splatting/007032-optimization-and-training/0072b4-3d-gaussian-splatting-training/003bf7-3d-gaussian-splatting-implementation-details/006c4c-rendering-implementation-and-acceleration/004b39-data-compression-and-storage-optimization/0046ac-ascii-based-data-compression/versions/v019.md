# ASCII-Based Data Compression
Also called: Anywhere Compression, Base 94 Floating-Point Compression, Base 95 Integer Compression

## Overview
This method accelerates data transmission during the training of 3D Gaussian Splatting models by compressing numerical values into ASCII strings using base-95 and base-94 encoding schemes [S1, unofficial]. It specifically targets the optimization of color matrix data by limiting precision to one decimal place, thereby reducing the volume of data transferred between components without significantly impacting rendering quality [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Numerical data (integers, floating-point numbers, and color matrix elements) intended for transmission during training steps such as `densify_and_prune` [S1, unofficial].
*   **Output:** Compressed ASCII strings for integers and floating-point numbers; quantized and compressed ASCII strings for color matrix elements [S1, unofficial].

**Data Structures:**
The method operates on standard numerical types but maps them to ASCII character codes. No complex binary structures are defined; the output is a sequence of ASCII characters [S1, unofficial].

**Parameters:**
*   **Integer Base:** 95.
*   **Floating-Point Integer Base:** 94.
*   **Color Precision:** 1 decimal place.
*   **Color Range:** [0.0, 2.0].

**Steps:**

1.  **Integer Compression (Base 95):**
    *   Map an integer value $v$ in the range $[0, 95]$ to a single ASCII character.
    *   The character set is ASCII codes 32 to 126 inclusive.
    *   Encoding: $char = \text{chr}(32 + v)$ [S1, unofficial].
    *   Decoding: $v = \text{ord}(char) - 32$ [S1, unofficial].

2.  **Floating-Point Compression (Base 94):**
    *   Split a floating-point number into an integer part $I$ and a decimal place count $d$.
    *   The integer part $I$ must be in the range $[0, 94]$.
    *   Encode $I$ using ASCII codes 32 to 125 (Base 94).
    *   Use ASCII code 126 (`~`) as a delimiter to connect the integer part and the fractional part representation [S1, unofficial].
    *   Decoding: Split the string at the delimiter. Let the integer part string be $S_I$ and the decimal part string be $S_d$.
    *   Calculate $I = \text{ord}(S_I) - 32$.
    *   Calculate $d$ from $S_d$ (interpreted as a decimal integer representing the scale) [S1, unofficial].
    *   Reconstruct the value: $f = I \times 10^{-d}$ [S1, unofficial].

3.  **Color Matrix Optimization:**
    *   Quantize each element of the color matrix to one decimal place within the range $[0.0, 2.0]$.
    *   This results in 21 possible alternative numbers for each element ($0.0, 0.1, ..., 2.0$) [S1, unofficial].
    *   Apply ASCII compression to these quantized values to reduce data size significantly [S1, unofficial].

4.  **Implementation Considerations:**
    *   Avoid using line break characters in the ASCII strings, as they add extra operators during writing and decoding [S1, unofficial].
    *   For large matrix traversals, use optimized internal functions (e.g., `torch::where`, `torch::index_select`) instead of explicit loops to improve speed, though full replacement of loops with compression may not be fast enough [S1, unofficial].

    """
    Compress an integer in range [0, 95] to a single ASCII character.
    """
    if not (0 <= value <= 95):
        raise ValueError("Integer out of range [0, 95]")
    # ASCII 32 to 126
    return chr(32 + value)

def decompress_integer_base95(char: str) -> int:
    """
    Decompress a single ASCII character back to an integer.
    """
    code = ord(char)
    if not (32 <= code <= 126):
        raise ValueError("Invalid ASCII character for integer compression")
    return code - 32

def compress_color_matrix(matrix):
    """
    Compress color matrix elements to 1 decimal place in [0.0, 2.0].

    # Quantize
    quantized = torch.round(matrix * 10) / 10
    # Clip to [0.0, 2.0]
    quantized = torch.clamp(quantized, 0.0, 2.0)
    
    # Map to integer [0, 20]
    # 0.0 -> 0, 0.1 -> 1, ..., 2.0 -> 20
    int_values = (quantized * 10).long()

    # This requires traversing the matrix.

    # Map 0-20 to ASCII 32-52

    return ascii_chars

**Edge Cases and Pitfalls:**
*   **Color Matrix Traversal:** Compressing the entire color matrix into ASCII strings is computationally expensive due to matrix traversal. Using `torch::where` and `torch::index_select` improves speed but may not be sufficient for full replacement of loops [S1, unofficial].
*   **Line Breaks:** Using line break characters in the ASCII string adds overhead during writing and decoding; they should be avoided [S1, unofficial].
*   **Value Range:** The integer component of the floating-point number is strictly limited to $[0, 94]$. Values outside this range require scaling via $d$ or are not supported by this specific encoding scheme [S1, unofficial].

## Operating characteristics
*   **Performance Gain:** Improves training speed by approximately 6% or less [S1, unofficial].
*   **Data Size:** Significantly reduces the size of color matrix data by limiting precision to one decimal place (21 alternative numbers) and using ASCII compression [S1, unofficial].
*   **Limitations:** Not suitable for compressing the entire color matrix efficiently due to traversal overhead. The floating-point encoding is restrictive regarding the magnitude of the integer component [S1, unofficial].
*   **When to Use:** When training speed is bottlenecked by data transmission and the model allows for quantization of color values to 1 decimal place without perceptible quality loss [S1, unofficial].

This method was proposed in the context of improving 3D Gaussian Splatting training speed from multiple dimensions, including compression [S1, unofficial]. It is part of the "I3DGS" research which explores various optimizations for the 3D Gaussian Splatting model [S1, unofficial].
