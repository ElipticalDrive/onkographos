# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, GSGEN Implementation Details, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific algorithmic steps, hyperparameters, and data structures required to implement the training and rendering pipeline of 3D Gaussian Splatting (3DGS). It covers the initialization from Structure-from-Motion (SfM) points, the differentiable rasterization core, the adaptive densification and pruning strategies, and the optimization loop. It sets itself apart from general volume rendering articles by providing the exact numerical thresholds, iteration schedules, and memory management techniques (such as half-precision fetches) necessary to reproduce the performance and fidelity of the original 3DGS method and its immediate variants.

## How it works

### Inputs and Outputs
**Inputs:**
*   A set of $N_{cam}$ calibrated camera views $\{I_i, C_i\}_{i=1}^{N_{cam}}$, where $I_i$ is the image and $C_i$ is the camera pose (extrinsics) and intrinsics.
*   An initial sparse point cloud $\{p_j\}_{j=1}^{N_{SfM}}$ from Structure-from-Motion (SfM) [S4].
*   Optimization hyperparameters: learning rate, loss weights, densification intervals, and thresholds [S1, S3].

**Outputs:**
*   A set of $N$ 3D Gaussian primitives $\mathcal{G} = \{\mu_k, \Sigma_k, \alpha_k, \mathbf{c}_k\}_{k=1}^{N}$, where $\mu_k$ is position, $\Sigma_k$ is covariance, $\alpha_k$ is opacity, and $\mathbf{c}_k$ are spherical harmonic (SH) coefficients for color [S3].
*   Rendered novel view images and depth maps.

### Data Structures
The Gaussian representation is stored in flat arrays (SoA - Structure of Arrays) for efficient GPU access [S2]:
*   **Positions ($\mu$):** Float32, size $3 \times N$.
*   **Rotations ($q$):** Quaternions, size $4 \times N$, normalized after update.
*   **Scales ($s$):** Float32, size $3 \times N$.
*   **Opacities ($\alpha$):** Float32, size $1 \times N$.
*   **SH Coefficients ($\mathbf{c}$):** Float32, size $(D+1)^2 \times 3 \times N$, where $D$ is the SH degree [S3]. For $D=1$, this is $12 \times 3 \times N$.
*   **Gradients:** Accumulated per-step gradients for $\mu, q, s, \alpha, \mathbf{c}$ [6233-optimization-and-parallelization].

### Initialization
1.  **Scene Extent Calculation:** Calculate the scene extent $e_{scene}$ to determine the initial scale of Gaussians. The default 3DGS method uses camera positions, which can be biased [S4]. A corrected extent $e'_{scene}$ is often used, based on the SfM point cloud:
    $$ \bar{C} = \frac{1}{N_{cam}} \sum_{i=1}^{N_{cam}} C_i $$
    $$ e'_{scene} = \frac{1}{N_{SfM}} \sum_{j=1}^{N_{SfM}} \|\bar{C} - p_j\|_2 $$
    where $\bar{C}$ is the average camera position and $p_j$ are SfM points [S4].
2.  **Gaussian Creation:** For each SfM point $p_j$:
    *   Position $\mu_j = p_j$.
    *   Scale $s_j$ is set proportional to $e'_{scene}$ [S4].
    *   Rotation $q_j$ is set to identity (or aligned with camera view if available).
    *   Opacity $\alpha_j$ is initialized to a small value (e.g., 0.1).
    *   SH coefficients $\mathbf{c}_j$ are initialized to the average color of the point from the SfM reconstruction or zero [S3].

### Rendering Pipeline (Forward Pass)
The rendering is performed using a differentiable rasterizer [6233-optimization-and-parallelization].
1.  **Projection:** For each Gaussian $k$, compute the 3D-to-2D projection matrix $J$ (Jacobian of the projection) and the view-space covariance $\Sigma' = J W \Sigma W^T J^T$, where $W$ is the world-to-view rotation [S2].
2.  **Screen-space Ellipse:** Compute the 2D covariance $\Sigma'' = \text{upper\_left\_2x2}(\Sigma')$ and the screen-space center $c_k$.
3.  **Tile Assignment:** Assign Gaussians to tiles based on their bounding box in screen space.
4.  **Sorting:** Sort Gaussians within each tile by depth (front-to-back) [6233-optimization-and-parallelization].
5.  **Alpha Blending:** For each pixel, compute color $C$ and opacity $A$ via alpha blending:
    $$ C = \sum_{k \in \text{sorted}} c_k \alpha_k \prod_{m < k} (1 - \alpha_m) $$
    $$ A = \sum_{k \in \text{sorted}} \alpha_k \prod_{m < k} (1 - \alpha_m) $$
    where $c_k$ is the color evaluated from SH coefficients at the viewing direction [S3].
6.  **Half-Precision Optimization:** During rasterization, feature vectors (SH coefficients) are fetched in half-precision (FP16) to reduce register pressure and memory bandwidth, with automatic loss scaling applied for stability [S2].

### Training Loop (Backward Pass and Optimization)
The training minimizes a loss function $\mathcal{L}$ between rendered images and ground truth.
1.  **Loss Function:**
    $$ \mathcal{L} = \lambda_{L1} \mathcal{L}_{L1} + \lambda_{SSIM} \mathcal{L}_{SSIM} $$
    where $\mathcal{L}_{L1}$ is the L1 loss and $\mathcal{L}_{SSIM}$ is the SSIM loss [S3]. In some variants, MSE is used: $\mathcal{L} = \lambda \cdot \text{MSE} + (1-\lambda) \cdot \text{SSIM}$ [S13, unofficial].
2.  **Gradient Accumulation:** Gradients are accumulated over iterations [6233-optimization-and-parallelization].
3.  **Optimizer:** Adam optimizer with learning rate $1 \times 10^{-3}$ [S3].
4.  **Densification (Every 100-500 iterations):**
    *   **Splitting:** If a Gaussian's accumulated position gradient magnitude exceeds a threshold $T_{pos}$ (e.g., 0.02) and its opacity is high, split it into two Gaussians [S1]. The new Gaussians inherit the position and scale, with slight perturbations.
    *   **Cloning:** If a Gaussian's scale is small (indicating it covers a small area) but its gradient is high, clone it [S1].
    *   **Compactness:** Perform compactness-based densification every 1000 iterations to ensure complete geometry [S1].
5.  **Pruning (Every 200 iterations):**
    *   Remove Gaussians with opacity $\alpha < \alpha_{min}$ (e.g., 0.05) [S1].
    *   Remove Gaussians with excessively large world-space or view-space radius [S1].
6.  **View Selection:** Randomly select a single image from a random scene as supervision for each iteration [S3].

### Pseudocode
```python
def train_3dgs(cameras, images, sfm_points, num_iterations):
    # Initialization
    gaussians = initialize_gaussians(sfm_points)
    optimizer = Adam(gaussians.parameters(), lr=1e-3)
    
    for step in range(num_iterations):
        # 1. View Selection
        cam_idx = random_choice(len(cameras))
        camera = cameras[cam_idx]
        target_image = images[cam_idx]
        
        # 2. Forward Pass (Differentiable Rasterization)
        # Uses half-precision fetches for SH coefficients [S2]
        rendered_image = rasterize(gaussians, camera)
        
        # 3. Loss Computation
        l1_loss = L1Loss(rendered_image, target_image)
        ssim_loss = SSIMLoss(rendered_image, target_image)
        loss = 0.8 * l1_loss + 0.2 * ssim_loss # Typical weights [S3]
        
        # 4. Backward Pass
        optimizer.zero_grad()
        loss.backward()
        
        # 5. Optimization Step
        optimizer.step()
        
        # 6. Densification and Pruning
        if step % 100 == 0:
            # Accumulate gradients for densification metrics
            accumulate_gradient_metrics(gaussians)
            
        if step % 1000 == 0:
            # Splitting based on position gradient threshold T_pos = 0.02 [S1]
            split_gaussians(gaussians, threshold=0.02)
            # Compactness-based densification [S1]
            compactness_densify(gaussians)
            
        if step % 200 == 0:
            # Pruning low opacity and large radius Gaussians [S1]
            prune_gaussians(gaussians, alpha_min=0.05)
            
        if step % 500 == 0:
            # View-space position gradient splitting [S1]
            split_by_view_gradient(gaussians, threshold=0.02)

    return gaussians
```

## Subtopics

### Corrected Scene-Extent
A method to calculate scene extent based on the SfM point cloud rather than camera positions to avoid bias from camera distribution (e.g., orbiting a small object in a large environment) [S4]. It sets itself apart from standard 3DGS by using $e'_{scene} = \frac{1}{N_{SfM}} \sum_{i=1}^{N_{SfM}} \|\bar{C} - p_i\|_2$ instead of the max camera distance [S4].

### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ to selectively enlarge covariances, creating pixel-wise variable blur kernels that match spatially varying scene blurriness [S5]. It sets itself apart from uniform Gaussian blur by allowing spatially varying blur shapes and magnitudes [S5].

### Denoise-GS
A self-supervised denoising method for sparse-view 3D Gaussian Splatting that combines unsupervised image denoising (Noise2Void) with explicitly differentiable 3DGS [S6]. It sets itself apart from supervised methods by requiring no paired clean data and being robust to non-Gaussian noise [S6].

### Multi-Scale Constraint
A technique using position-aware point adaptive control to apply different scales to Gaussians based on viewer distance, improving rendering of distant objects [S7]. It sets itself apart by using a distance-dependent scaling factor $\gamma(\mu)$ to control cloning and splitting thresholds [S7].

### LS-Gaussian Viewpoint Transformation
An algorithm that leverages inter-frame continuity for efficient sparse rendering by transforming the viewpoint between consecutive frames, rather than rendering each frame separately [S8]. It sets itself apart by operating at the tile/Gaussian level to enable sparse rendering, reducing preprocessing and sorting costs [S8].

### Camera Localisation for Convergence Basin
Localizes camera pose by minimizing only the photometric error against the ground-truth colour image of the target view, fixing the initial Gaussians during optimization [S9, unofficial]. It sets itself apart by using a dedicated optimization step for pose estimation before full scene optimization [S9, unofficial].

### DiffGS Framework
Applies an optimization process during Gaussian extraction to optimize Gaussians to exact locations, using a truncation function $\lambda$ and projection function $\tau$ [S10]. It sets itself apart by modeling Gaussian Probability Functions (GauPF) to improve reconstruction quality with fewer Gaussians [S10].

### Opacity Offset Table for DSA
Constructs an opacity offset table to model changes in digital subtraction angiography [S11]. It sets itself apart by explicitly handling temporal opacity changes in medical imaging contexts [S11].

### Conditional Splat Approximation
Approximates the influence range of a 3D Gaussian on a slice by using a 2D ellipse splat scaled by the marginal factor, which closely matches the true iso-probability contours [S12, unofficial]. It sets itself apart by providing an accurate and efficient approximation for slice-based rendering [S12, unofficial].

### PyGS Optimization
The optimization process using a combined MSE and SSIM loss, along with density control strategies adapted from 3DGS, while preserving the multi-scale structure [S13, unofficial]. It sets itself apart by routinely reassessing and reassigning the levels of Gaussians based on their scales to preserve multi-scale characteristics [S13, unofficial].

### GAINS (Gaussian-based Inverse Rendering from Sparse multi-view captures)
A two-stage inverse rendering framework that leverages foundation model priors to stabilize geometry and material estimation from sparse multi-view RGB captures [S14]. It sets itself apart by using 2DGS for more accurate geometry reconstruction and integrating monocular depth, normal, and diffusion priors [S14].

### View-Dependent Gaussian Splatting (VDGS)
Produces more faithful view-dependent effects by modeling 3DGS to represent 3D shapes and predicting attributes like view-dependent color and opacity with a NeRF-like neural network instead of spherical harmonic coefficients [S15, unofficial]. It sets itself apart by replacing SH coefficients with a neural network for view-dependent appearance [S15, unofficial].

### SAGS (Adaptive Gaussian Splatting)
Utilizes an adaptive 2D low-pass filter at inferencing time based on rendering resolution and camera distance to handle aliasing [S15, unofficial]. It sets itself apart by dynamically adjusting the filter based on rendering context [S15, unofficial].

### Frequency Gaussian Splatting
Applies frequency-domain regularization to the rendered 2D image to encourage recovery of high-frequency detail, resolving blurring issues [S15, unofficial]. It sets itself apart by operating in the frequency domain to enhance high-frequency details [S15, unofficial].

### Sparse Adaptive Scalable Compact Gaussian Splatting
A compression method that utilizes vector clustering to encode color and geometric attributes [S15, unofficial]. It sets itself apart by using vector clustering for efficient encoding of attributes [S15, unofficial].

## Operating characteristics
*   **Time Complexity:** The forward pass is $O(N \cdot T)$ where $N$ is the number of Gaussians and $T$ is the number of tiles. The backward pass is similar. Densification adds $O(N \log N)$ for sorting and splitting.
*   **Memory Complexity:** $O(N \cdot D^2)$ for SH coefficients, where $D$ is the degree. For $D=1$, this is significant. Half-precision fetches reduce memory bandwidth pressure [S2].
*   **Measured Performance:** On standard datasets, 3DGS achieves real-time rendering (30-100+ FPS) on modern GPUs [S8]. With optimizations like LS-Gaussian, speedups of 5.41× to 17.3× are achieved on edge devices [S8].
*   **Strengths:** Real-time rendering, high fidelity, explicit representation.
*   **Limitations:** High memory usage for large scenes, sensitivity to initialization, potential for "floaters" [S15, unofficial].
*   **When to use:** Real-time novel view synthesis, high-quality 3D reconstruction from images.
*   **When not to use:** Scenes with extreme dynamic range or complex lighting without inverse rendering extensions, very sparse views without denoising [S6].

## Background
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1, S3]. It builds on the concept of splatting, where 3D primitives are projected and rasterized to 2D. The method was developed to address the slow rendering speeds of NeRFs and the lack of explicit representation in neural fields. It has since become a standard for real-time neural rendering. Variants have been developed for text-to-3D [S1], denoising [S6], and large-scale scenes [S7].
