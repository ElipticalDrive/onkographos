# 3DGS Custom Initialization from Point Cloud/Mesh

Also called: 3DGS Model Learning Initialization from Point Cloud/Mesh, Custom Initialisation for 3DGS from Point Cloud/Mesh, Custom Initialization from Point Cloud/Mesh, Geometry-guided 3DGS Initialization, Point Cloud/Mesh Initialization for 3DGS

## Overview
This method initializes 3D Gaussian Splatting (3DGS) learning using a known 3D point cloud or mesh as the starting geometry, replacing the standard Structure-from-Motion (SfM) sparse point cloud initialization [S1, unofficial]. It solves the problem of creating high-quality 3DGS models from existing volumetric data (e.g., MPEG plenoptic point clouds or meshes) when the original multi-view images are unavailable [S1, unofficial]. Unlike standard 3DGS which relies on sparse SfM points and adaptive density control (leading to potential misalignment and 'floater' artifacts), this method uses dense, surface-aligned initial points, resulting in cleaner models, fewer splats, and significantly faster convergence [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D plenoptic point cloud or mesh. The input must contain view-dependent colors if available, as 3DGS is useful for non-Lambertian surfaces [S1, unofficial].
*   **Output:** A 3DGS model (set of Gaussians) initialized with centers aligned to the input geometry, ready for optimization [S1, unofficial].

**Data Structures:**
The method utilizes the standard 3DGS Gaussian data structure, but initializes the `position` field specifically from the input geometry. The other attributes (`opacity`, `scale`, `rotation`, `color`) are initialized according to standard 3DGS defaults or derived from the input data where possible [S1, unofficial].

**Steps:**
1.  **Generate Multi-view Images:** Render multi-view images from the input 3D point cloud or mesh using a renderer (e.g., PccAppRenderer) [S1, unofficial].
2.  **Obtain Camera Parameters:** Extract or compute camera parameters (extrinsic and intrinsic) for the viewpoints used to generate the multi-view images. Transform these parameters to the target coordinate system (e.g., COLMAP) [S1, unofficial].
3.  **Select Initial Points:**
    *   If the input is a **point cloud**, use the vertices $(x, y, z)$ as the initial centers of the splats [S1, unofficial].
    *   If the input is a **mesh**, use the vertices or the center point of each mesh face (or a subset of faces) as the initial centers [S1, unofficial].
4.  **Configure Adaptive Density Control:**
    *   If the input point cloud/mesh is already dense and clean, **deactivate** adaptive density control (cloning/splitting of splats) to preserve the initial point density and reduce learning time [S1, unofficial].
    *   If the input model is noisy, sparse, or has holes, **keep** adaptive density control active to ensure quality [S1, unofficial].
5.  **Set Learning Rates:**
    *   Set the position learning rate for the splat centers to $0$ [S1, unofficial].
    *   Retain a learning rate $> 0$ for other splat attributes (opacity, scale, rotation, color) [S1, unofficial].
6.  **Optimize:** Run the 3DGS optimization process using the generated multi-view images and the configured parameters [S1, unofficial].

**Parameters:**
*   **Input Data:** Plenoptic point cloud or mesh. Must contain view-dependent colors if available [S1, unofficial].
*   **Position Learning Rate:** $0$ [S1, unofficial].
*   **Other Learning Rates:** $> 0$ [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Noisy/Sparse Input:** If the input 3D model is noisy, sparse, or has holes, deactivating adaptive density control should be avoided to ensure quality [S1, unofficial]. In such cases, the default SfM initialization may be preferred or adaptive control kept active [S1, unofficial].
*   **Precision:** Setting position learning rate to $0$ ensures splats do not move far from the original surface, which is critical for applications requiring retention of original geometry [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Converges significantly faster than SfM-based initialization. In the Thaidancer sequence test, custom initialization converged in 5,000 iterations compared to 15,000 iterations for SfM initialization [S1, unofficial].
*   **Memory Complexity:** Produces models with fewer splats than the original dense point clouds. For the first frame of the Thaidancer sequence, the raw PLY file size was ~201MB for the original point cloud (~3M voxels) and ~61MB for the 3DGS model (~250k splats) [S1, unofficial].
*   **Measured Performance:** On the Thaidancer sequence, the custom initialization produced 3DGS models with ~250k splats per frame, achieving comparable visual quality to the original ~3M voxel point cloud [S1, unofficial].
*   **Strengths:** Faster convergence, cleaner surface representation, fewer 'floater' artifacts, and preliminary compression benefits [S1, unofficial].
*   **Limitations:** Requires high-quality input geometry; if the input is poor, the method may not yield optimal results without adaptive density control [S1, unofficial].
*   **When to Use:** When original multi-view images are unavailable, and a high-quality 3D point cloud or mesh is available. Ideal for applications requiring retention of original geometry and faster training times [S1, unofficial].
*   **When Not to Use:** When the input geometry is noisy, sparse, or has significant holes, and adaptive density control cannot be effectively managed [S1, unofficial].

## Background
*   **Origin:** Proposed in the paper "Transcoding a 3D Gaussian Splatting Model from a Plenoptic Point Cloud or Mesh without the Original Multi-view Images" [S1, unofficial].
*   **History:** Developed to address the need for creating 3DGS representations from existing volumetric media formats (like MPEG plenoptic point clouds) when original multi-view images are unavailable [S1, unofficial].
*   **Usage:** Used in transcoding pipelines for volumetric content, particularly in contexts where 3DGS is preferred for rendering but the source data is in point cloud or mesh format [S1, unofficial].
