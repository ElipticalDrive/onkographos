# Language Embedded 3D Gaussians

Also called: LE3DG

## Overview
Language Embedded 3D Gaussians (LE3DG) extends the feature blending of 3D Gaussian Splatting to enable full scene understanding by encoding object-level embeddings for phrase grounding in addition to standard pixel-level features [S1, unofficial]. It differs from sibling methods like [LangSplat](8104-langsplat.md) and [3D Vision-Language GS](8105-3d-vision-language-gs.md) by explicitly supporting open-vocabulary semantic segmentation and zero-shot semantic reasoning through the alignment of rendered feature maps with text embeddings from vision-language models (VLMs) such as CLIP [S1, unofficial].

## How it works
LE3DG builds on the differentiable alpha-blending accumulation defined in [Semantic and Language Embeddings](8130-semantic-and-language-embeddings.md). The method optimizes 3D Gaussians to carry feature vectors $\mathbf{f}_i$ that reside in a joint embedding space shared with a VLM.

**Inputs and Outputs:**
*   **Input:** A set of 3D Gaussians $\mathcal{G} = \{\mathbf{g}_i\}$, where each $\mathbf{g}_i$ includes position, covariance, opacity $\alpha_i$, and a feature vector $\mathbf{f}_i \in \mathbb{R}^d$. A set of training images with corresponding camera poses. A text prompt or vocabulary for the target VLM (e.g., CLIP text encoder).
*   **Output:** A 3D Gaussian scene where each Gaussian encodes semantic information, allowing for real-time open-vocabulary segmentation and phrase grounding.

**Data Structures:**
*   **Gaussian Feature Vector ($\mathbf{f}_i$):** A dense vector of size $d$ (typically 512 or 768 for CLIP embeddings). Unlike color, this vector is not directly visible but is accumulated per-pixel.
*   **VLM Text Embeddings:** Pre-computed embeddings for target object categories or phrases.

**Numbered Steps:**
1.  **Initialization:** Initialize 3D Gaussians using standard SfM points. Initialize feature vectors $\mathbf{f}_i$ either randomly or by projecting 2D features from initial views into the VLM embedding space.
2.  **Rasterization:** For each training view, sort Gaussians front-to-back. Compute the rendered feature map $\mathbf{V}(p)$ for each pixel $p$ using the shared principle:
    $$
    \mathbf{V}(p) = \sum_{i \in \mathcal{O}_p} \mathbf{f}_i \cdot \alpha_i \cdot \prod_{j=1}^{i-1} (1 - \alpha_j)
    $$
    where $\mathbf{f}_i$ is the feature vector of the $i$-th Gaussian [S1, unofficial].
3.  **Loss Computation:**
    *   **Photometric Loss:** Standard RGB reconstruction loss between rendered color and ground truth.
    *   **Semantic/Language Loss:** Compare the rendered feature vector $\mathbf{V}(p)$ against the text embedding $\mathbf{t}_k$ of the ground truth label for pixel $p$. A common metric is the cosine similarity or negative cosine distance:
        $$
        \mathcal{L}_{sem} = 1 - \frac{\mathbf{V}(p) \cdot \mathbf{t}_k}{\|\mathbf{V}(p)\| \|\mathbf{t}_k\|}
        $$
    *   **Total Loss:** $\mathcal{L} = \mathcal{L}_{rgb} + \lambda_{sem} \mathcal{L}_{sem}$.
4.  **Optimization:** Update Gaussian parameters (including $\mathbf{f}_i$) via gradient descent. The gradients flow through the alpha-blending operation, allowing the 3D features to align with the 2D VLM space.
5.  **Inference (Segmentation):** To segment an object described by text:
    *   Encode the text prompt into $\mathbf{t}_{query}$ using the VLM.
    *   Render the feature map $\mathbf{V}(p)$ for the desired view.
    *   Compute similarity $S(p) = \text{sim}(\mathbf{V}(p), \mathbf{t}_{query})$.
    *   Threshold $S(p)$ to obtain a binary mask.

**Parameters:**
*   $\lambda_{sem}$: Weight for the semantic loss. Not given in the sources.
*   $d$: Dimension of the feature vector. Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Precision:** Feature vectors may suffer from quantization errors if stored in lower precision. [G] Use FP16 or FP32 for feature vectors to maintain semantic alignment.
*   **Boundary Ambiguity:** At object boundaries, alpha-blending mixes features from different objects. [G] High opacity gradients can cause "bleeding" of semantic labels. Regularization on feature smoothness may be required.
*   **Degenerate Input:** If a Gaussian has $\alpha_i \approx 0$, it contributes nothing to the sum but still consumes memory. [G] Prune low-opacity Gaussians during training.

## Subtopics

### Vision-Language Embedding Fusion
A strategy to extract vision-language embeddings for 3DGS by aligning each Gaussian directly in the image-embedding space using a dynamic weighting mechanism that combines global, local, and masked features [S2]. It differs from standard LE3DG by explicitly balancing contextual information to handle integrated vs. isolated objects.
*   **Step 1:** Extract embeddings from the frames used to optimize the 3DGS [S2].
*   **Step 2:** Combine three distinct features using a dynamic weighting mechanism: global context from the entire frame, local features with background, and masked features without background [S2].
*   **Step 3:** Automatically balance contributions based on each segment's contextual relationship, emphasizing background-inclusive features for integrated objects and object-specific features for isolated objects [S2].

## Operating characteristics
*   **Time Complexity:** Rasterization remains $O(N)$ per pixel where $N$ is the number of overlapping Gaussians, similar to standard 3DGS. The additional cost is the VLM text encoding (offline) and the similarity computation during inference.
*   **Memory Complexity:** Increases by $O(N \cdot d)$ to store feature vectors $\mathbf{f}_i$ for each Gaussian. For CLIP ViT-L/14 ($d=768$), this adds significant memory overhead compared to RGB (3 channels).
*   **Strengths:** Enables real-time open-vocabulary segmentation and phrase grounding without retraining for new categories (zero-shot).
*   **Limitations:** Requires a VLM for inference; semantic quality depends on the alignment between 3D features and the VLM space; potential for semantic bleeding at boundaries.
*   **When to use:** When semantic understanding, object retrieval, or phrase grounding is required in a 3D scene.
*   **When not to use:** When memory is constrained or only photometric accuracy is needed.

## Background
Language Embedded 3D Gaussians (LE3DG) was introduced as an extension to 3D Gaussian Splatting to incorporate semantic understanding [S1, unofficial]. It builds upon the principle that feature vectors can be differentially accumulated during rasterization. The method enables tasks like 3D visual question answering and zero-shot semantic reasoning by projecting vision-language models into the 3DGS framework [S1, unofficial]. It is part of a broader trend of integrating VLMs with neural radiance fields and Gaussian splatting for embodied AI and robotics applications.
