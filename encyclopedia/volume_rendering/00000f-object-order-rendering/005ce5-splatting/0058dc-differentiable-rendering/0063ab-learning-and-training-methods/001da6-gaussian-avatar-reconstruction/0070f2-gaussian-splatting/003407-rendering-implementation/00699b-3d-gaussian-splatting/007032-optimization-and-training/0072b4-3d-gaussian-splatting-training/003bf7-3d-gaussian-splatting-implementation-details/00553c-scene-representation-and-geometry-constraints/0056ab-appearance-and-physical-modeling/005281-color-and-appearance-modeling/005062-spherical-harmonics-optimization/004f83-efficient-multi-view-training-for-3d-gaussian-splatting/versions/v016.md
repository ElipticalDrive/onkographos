# Efficient Multi-View Training for 3D Gaussian Splatting

Also called: Multi-View Mini-Batch Training for 3DGS, Thread-Efficient Partial Rendering for Multi-View 3DGS

## Overview
This method enables stable optimization of 3D Gaussian Splatting (3DGS) by processing multiple training images per iteration, addressing the high variance of gradients inherent in the standard single-view approach. Unlike standard 3DGS which renders one image per iteration due to rasterization overhead, this method uses thread-efficient partial rendering to gather pixels from multiple views without idle thread waste, while replacing the standard Adaptive Density Control (ADC) with a 3D-space compatible densification strategy to prevent arithmetic errors between different image planes.

## How it works
### Inputs and Outputs
**Inputs:**
*   A set of $N$ training images with corresponding camera poses.
*   A set of 3D Gaussian primitives $\{G_j\}_{j=1}^M$, each defined by 3D mean $\mu$, covariance (scale $S$, rotation $R$), opacity $o$, and spherical harmonic coefficients $c_l^m$ for color.
*   A mini-batch size $K$ (number of images sampled per iteration).

**Outputs:**
*   Updated Gaussian parameters (means, covariances, opacities, SH coefficients) after gradient descent.
*   Rendered images for the sampled mini-batch.

### Data Structures
The rasterizer uses a tile-based structure. The image is split into tiles. A single thread block is allocated to a single tile. Threads within a block cooperate to preprocess Gaussians and render pixels. A thread is freed only when all peer threads in the same block have completed their work [S1, unofficial].

### Rendering Formula
The rendered color $\hat{C}(p)$ for a pixel $p$ is computed by alpha-blending sorted Gaussians $\{G_j\}_{j=1}^M$ projected to 2D:
$$ \hat{C}(p) = \sum_{i=1}^{M} c_i T_i o_i G_i(p) $$
where:
*   $T_i = \prod_{k=1}^{i-1} (1 - o_k G_k(p))$ is the accumulated transmittance.
*   $G_i(p) = \exp\left(-\frac{1}{2}(p - \mu'_i)^T (\Sigma'_i)^{-1} (p - \mu'_i)\right)$ is the 2D Gaussian kernel.
*   $\mu'$ and $\Sigma'$ are the projected 2D mean and covariance derived from the 3D mean $\mu$, scale $S$, rotation $R$, color $c$, and opacity $o$ [S1, unofficial].

### Variance Estimation
The method relies on the observation that multi-view training reduces the variance of mini-batch gradients, leading to more stable optimization. The variance of vectors $x$ is defined as:
$$ V(x) := E[\|x - \mu\|_2^2] \quad \text{where} \quad E[x] = \mu $$
The variance of the mini-batch gradient $\nabla \bar{\phi}_k$ is estimated using Monte Carlo sampling over $K$ sampled mini-batches $S$:
$$ V_{B_k \in S} (\nabla \bar{\phi}_k) = E[\|\nabla \bar{\phi}_k - P(w_t)\|_2^2] $$
where $P(w_t)$ is the projection or mean estimate at iteration $t$ [S1, unofficial].

### Algorithm Steps
1.  **Sample Mini-Batch:** Randomly select $K$ images from the training dataset to form a mini-batch.
2.  **Thread-Efficient Partial Rendering:**
    *   Instead of rendering full images (which causes idle threads in naive multi-view rendering), the rasterizer processes only the relevant tiles for the sampled views.
    *   Allocate one thread block per tile.
    *   Ensure threads are synchronized within blocks to prevent idle time when peer threads finish early [S1, unofficial].
3.  **Gradient Computation:** Compute the loss $\mathcal{L}$ between rendered pixels and ground truth for all pixels in the $K$ sampled images. Compute the gradient $\nabla \bar{\phi}_k$ of the loss with respect to the Gaussian parameters.
4.  **3D-Space Densification:**
    *   Standard ADC assumes gradients reside in a single 2D plane. This method modifies densification to operate in 3D space or aggregates gradients in a way that avoids arithmetic between vectors from different image planes [S1, unofficial].
    *   *Note:* The specific mathematical formulation for the new densification is not detailed in the provided notes, but it is required to make ADC compatible with multi-view training [S1, unofficial].
5.  **Parameter Update:** Update weights using the mini-batch gradient:
    $$ w_{t+1} = w_t - \eta_t \nabla \bar{\phi}_k (w_t) $$
    where $\eta_t$ is the learning rate [S1, unofficial].

### Pseudocode
```python
def train_step(gaussians, camera_poses, gt_images, learning_rate, num_views):
    """
    One training iteration using efficient multi-view rendering.
    """
    # 1. Sample mini-batch of views
    batch_indices = random_sample(camera_poses, num_views)
    batch_cameras = [camera_poses[i] for i in batch_indices]
    batch_gt = [gt_images[i] for i in batch_indices]
    
    # 2. Thread-Efficient Partial Rendering
    # Render all pixels for the batch views.
    # The rasterizer splits images into tiles.
    # One block per tile. Threads sync within blocks.
    rendered_images = []
    for cam, gt in zip(batch_cameras, batch_gt):
        # Render using the tile-based rasterizer
        # This avoids idle threads by processing only necessary tiles
        rendered = render_tile_efficient(gaussians, cam)
        rendered_images.append(rendered)
        
    # 3. Compute Loss and Gradients
    total_loss = 0
    for rendered, gt in zip(rendered_images, batch_gt):
        # D-SSIM loss or similar photometric loss
        loss = compute_dssim_loss(rendered, gt)
        total_loss += loss
        
    # Backpropagate to get gradients for all Gaussian parameters
    gradients = backward_pass(total_loss, gaussians)
    
    # 4. Update Parameters
    # w_{t+1} = w_t - eta * grad
    gaussians.update(gradients, learning_rate)
    
    return total_loss
```

### Edge Cases and Pitfalls
*   **Idle Threads:** Naive multi-view training allocates a single block to a single tile. Rendering multiple images creates idle threads when peer threads in the same block complete work. The thread-efficient partial rendering scheme mitigates this [S1, unofficial].
*   **ADC Incompatibility:** Standard Adaptive Density Control assumes all 2D positional gradients reside within a single plane. Multi-view training risks performing arithmetic between vectors in different spaces (different image planes), resulting in a suboptimal densification process. A new densification method compatible with multi-view training is required [S1, unofficial].

## Operating characteristics
*   **Variance:** Multi-view mini-batch training results in a smaller variance of mini-batch gradients compared to single-view training, leading to more stable optimization [S1, unofficial].
*   **Overhead:** Standard 3DGS uses single-view training because gathering individual pixels from multiple images is difficult with its rasterization pipeline, requiring rendering every pixel of all images in a single iteration which incurs considerable overhead. The proposed method reduces this overhead via thread-efficient partial rendering [S1, unofficial].
*   **Performance:** The method allows 3DGS to benefit from the stability of multi-view learning, similar to NeRF, without the prohibitive cost of naive multi-view rendering [S1, unofficial].

## Background
3D Gaussian Splatting (3DGS) has emerged as a preferred choice alongside Neural Radiance Fields (NeRF) in inverse rendering due to its superior rendering speed. Currently, the common approach in 3DGS is to utilize "single-view" mini-batch training, where only one image is processed per iteration, in contrast to NeRF's "multi-view" mini-batch training. The difference in mini-batch composition mainly stems from different rendering schemes. NeRF randomly samples data from the all training dataset to form a mini-batch, while 3DGS typically uses a single-view image to form a minibatch. It was found that multi-view training leads to a smaller variance of mini-batch gradients than single-view training, suggesting that the current single-view learning approach for 3DGS may degrade performance [S1, unofficial].
