# Distributed 3D Gaussian Splatting

Also called: Distributed 3D Gaussian Splatting for Scientific Visualization, Distributed 3D-GS, Multi-GPU 3D-GS

## Overview
Distributed 3D Gaussian Splatting is a multi-GPU extension of the 3D Gaussian Splatting (3D-GS) pipeline designed for scientific visualization [S1]. It solves the problem of single-GPU memory capacity limits, enabling the scalable processing of large-scale scientific datasets that exceed the memory of a single accelerator (e.g., >11.2M Gaussians on an NVIDIA A100) [S1]. Unlike standard 3D-GS which operates on a single device, this method distributes the global point cloud and Gaussian parameters across multiple GPUs, allowing for the training and rendering of high-resolution scenes that are otherwise infeasible [S1]. It builds on [3D Gaussian Splatting](15108-3d-gaussian-splatting.md) and adapts the distributed training design from [Grendel](19770-grendel.md) [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** Scientific volume data (e.g., VTK, HDF5), target image resolution (e.g., 512x512 to 2048x2048), number of GPUs $N_{GPU}$, number of synthetic camera views $N_{views}$ [S1].
*   **Output:** Optimized set of 3D Gaussian primitives (mean $\mu$, covariance $\Sigma$, opacity $\alpha$, spherical harmonics coefficients for color) distributed across $N_{GPU}$ devices, and rendered images [S1].

**Data Structures:**
The global state consists of a point cloud and associated Gaussian parameters. This global state is sharded across $N_{GPU}$ workers.
*   **Global Point Cloud:** A set of $N$ points extracted from the isosurface.
*   **Gaussian Parameters:** For each point $i$, parameters include mean $\mu_i \in \mathbb{R}^3$, scale $s_i \in \mathbb{R}^3$, rotation $q_i \in \mathbb{R}^4$ (quaternion), opacity $\alpha_i \in \mathbb{R}$, and color coefficients [S1, Parent].
*   **Sharding:** The global set of $N$ Gaussians is partitioned into $N_{GPU}$ shards. Each GPU $k$ holds a subset of indices $\mathcal{I}_k$ such that $\bigcup_k \mathcal{I}_k = \{0, \dots, N-1\}$ and $\mathcal{I}_k \cap \mathcal{I}_j = \emptyset$ for $k \neq j$ [S1].
*   **Training Data:** The set of $N_{views}$ synthetic camera views is distributed across workers. Typically, each worker processes a subset of the views or the views are replicated depending on the specific communication pattern, but gradients must be synchronized globally [S1].

**Algorithm Steps:**

1.  **Initialization:**
    *   Extract an isosurface point cloud directly from the scientific volume data using a tool like ParaView [S1].
    *   Initialize Gaussian primitives at these points. The covariance $\Sigma$ is derived from scale $s$ and rotation $q$ as $\Sigma = R S S^\top R^\top$, where $R$ is the rotation matrix from $q$ and $S$ is the diagonal scale matrix [Parent].
    *   Distribute the global point cloud and Gaussian parameters to the $N_{GPU}$ workers. Each worker $k$ initializes its local shard $\mathcal{G}_k$ [S1].

2.  **Camera Setup:**
    *   Generate $N_{views}$ synthetic camera views in a structured orbit around the scene [S1].
    *   Typical value: $N_{views} = 448$ (increased from 250 used in prior work [4]) to support data complexity [S1].

3.  **Distributed Training Loop:**
    *   For each training iteration:
        a.  **Data Distribution:** Assign a batch of target images (from the $N_{views}$ set) to each GPU worker. The distribution strategy ensures that the union of processed views covers the necessary angular coverage for reconstruction [S1].
        b.  **Local Forward Pass:** Each worker $k$ renders its assigned views using its local shard $\mathcal{G}_k$ and the global camera parameters.
            *   Project 3D Gaussians to 2D screen space using the affine approximation of the projective transformation [Parent].
            *   Compute the Gaussian density $P(x|\mu, \Sigma) = \exp\left(-\frac{1}{2}(x - \mu)^\top \Sigma^{-1} (x - \mu)\right)$ [Parent].
            *   Perform alpha blending to produce the rendered image $I_{rendered}$ [Parent].
        c.  **Loss Computation:** Compute the loss $\mathcal{L}$ between $I_{rendered}$ and the ground truth image $I_{ground\_truth}$ for the assigned views. Common losses include L1 loss and D-SSIM [S1, implied by standard 3D-GS].
        d.  **Gradient Synchronization:**
            *   Compute local gradients $\nabla \mathcal{L}_k$ with respect to the local Gaussian parameters [S1].
            *   Perform a **fused all-reduce** operation across all $N_{GPU}$ workers to synchronize the gradients for the global parameters. This ensures that the update to each Gaussian primitive incorporates information from all views processed by any GPU [S1].
        e.  **Parameter Update:** Update the Gaussian parameters using an optimizer (e.g., Adam) based on the synchronized gradients [S1].

**Pseudocode:**

```python
# Distributed 3D Gaussian Splatting Training
# Inputs: volume_data, num_gpus, num_views=448, resolution=(2048, 2048)
# Global variables are sharded across num_gpus workers

def distributed_training(volume_data, num_gpus):
    # 1. Initialization
    # Extract isosurface point cloud using external tool (e.g., ParaView)
    point_cloud = extract_isosurface(volume_data)
    
    # Initialize Gaussian parameters for all points
    # mu: mean, s: scale, q: rotation, alpha: opacity, sh: spherical harmonics
    global_gaussians = initialize_gaussians(point_cloud)
    
    # Shard the global data across GPUs
    # Each GPU k gets a subset of indices
    shards = shard_data(global_gaussians, num_gpus)
    
    # Generate synthetic camera views
    cameras = generate_orbit_cameras(num_views)
    
    # 2. Training Loop
    for iteration in range(max_iterations):
        # Distribute training data (views) to workers
        # Strategy: Round-robin or random subset assignment
        local_views = assign_views(cameras, num_gpus)
        
        # Collect gradients from all GPUs
        global_gradients = None
        
        for gpu_id in range(num_gpus):
            # Local forward pass
            local_gaussians = shards[gpu_id]
            rendered_images = []
            
            for cam in local_views[gpu_id]:
                # Project Gaussians to 2D
                projected = project_gaussians(local_gaussians, cam)
                # Render via alpha blending
                img = render_splats(projected, cam.resolution)
                rendered_images.append(img)
            
            # Compute loss against ground truth
            losses = compute_loss(rendered_images, local_views[gpu_id].ground_truth)
            total_loss = sum(losses)
            
            # Compute local gradients
            local_grads = compute_gradients(total_loss, local_gaussians)
            
            # Synchronize gradients using fused all-reduce
            # This aggregates gradients for the global parameter set
            if global_gradients is None:
                global_gradients = sync_gradients(local_grads, num_gpus)
            else:
                global_gradients = sync_gradients_add(global_gradients, local_grads, num_gpus)
        
        # Update global parameters using synchronized gradients
        update_gaussians(global_gaussians, global_gradients)
        
        # Reshard if necessary (e.g., if Gaussians are split/merged)
        shards = reshard_data(global_gaussians, num_gpus)

    return global_gaussians
```

**Edge Cases and Pitfalls:**
*   **Memory Limits:** A single NVIDIA A100 GPU supports up to approximately 11.2M Gaussians. Datasets larger than this (e.g., Miranda with ~18M Gaussians) fail on a single GPU due to memory exhaustion [S1].
*   **Precision:** High-resolution rendering (2048x2048) increases memory bandwidth requirements. Ensure sufficient VRAM per GPU for the shard size plus gradient buffers [S1].
*   **Synchronization Overhead:** The fused all-reduce scheme must be efficient to avoid becoming the bottleneck. Network bandwidth between GPUs (e.g., NVLink) is critical [S1].

## Operating characteristics
*   **Time Complexity:** Training time scales sub-linearly with the number of GPUs due to communication overhead. For the Kingsnake dataset (4M Gaussians) at 2048x2048 resolution, training time reduced from 48.00 minutes (1 GPU) to 8.50 minutes (4 GPUs), a 5.6x speedup [S1].
*   **Memory Complexity:** Memory usage per GPU is $O(N / N_{GPU})$, where $N$ is the total number of Gaussians. This allows $N$ to exceed single-GPU capacity [S1].
*   **Measured Performance:**
    *   **Kingsnake (4M Gaussians, 110.3 MB):** 4 GPUs, 2048x2048: PSNR 29.32, SSIM 0.97, LPIPS 0.03 [S1].
    *   **Miranda (18M Gaussians, 491 MB):** 4 GPUs, 2048x2048: PSNR 36.37, SSIM 0.99, LPIPS 0.011 [S1].
*   **Strengths:** Enables training of large-scale scientific datasets that exceed single-GPU memory; improves training throughput.
*   **Limitations:** Requires multi-GPU hardware and infrastructure (e.g., HPC node with NVLink); communication overhead limits perfect linear scaling.
*   **When to use:** When the number of Gaussian primitives exceeds the VRAM of a single GPU (e.g., >11M on A100) or when high-resolution rendering of large scenes is required [S1].
*   **When not to use:** For small scenes that fit comfortably on a single GPU, where the overhead of distributed training is unnecessary.

## Background
*   **Origin:** The method was presented in 2025 by Mateevitsi, Papka, Petruzza, and Sizzi from the University of Illinois Chicago, Argonne National Laboratory, and Utah State University [S1].
*   **History:** It builds on prior work by Sewell et al. [4] which demonstrated high-fidelity isosurface reconstruction using Gaussian primitives from scientific data. It adapts the distributed training design from Grendel-GS [6] to the 3D-GS pipeline [S1].
*   **Usage:** Designed for HPC-based scientific workflows, enabling real-time post hoc and in situ visualization of complex simulations [S1].
