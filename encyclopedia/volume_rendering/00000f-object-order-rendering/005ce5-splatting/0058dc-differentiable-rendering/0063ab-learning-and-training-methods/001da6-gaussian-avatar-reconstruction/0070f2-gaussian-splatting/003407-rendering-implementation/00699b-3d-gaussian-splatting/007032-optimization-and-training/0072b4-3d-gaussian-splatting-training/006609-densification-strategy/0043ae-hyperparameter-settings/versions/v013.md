# Hyperparameter Settings

Also called: Optimizer and Regularization Settings, Optimizer settings, Phys3DGS Hyperparameter Settings, Training Hyperparameters

## Overview
Hyperparameter settings define the numerical configuration for the optimizer, loss functions, and regularization terms used during the training and densification of 3D Gaussian Splatting (3DGS) models. This method solves the problem of unstable convergence, over-densification, and material ambiguity by providing specific values for learning rates, loss weights, and threshold scalars. It sets itself apart from generic training setups by providing calibrated values for specific variants, such as the contribution-based densification criterion [S3, unofficial] or physically-based inverse rendering [S2, unofficial], ensuring that gradient magnitudes and primitive counts remain within optimal bounds.

## How it works
The method consists of configuring the optimization loop parameters, loss function composition, and densification thresholds.

### Inputs and Outputs
*   **Inputs:** Training dataset (images, camera poses), initial Gaussian set $\mathcal{G}$, and hyperparameter configuration dictionary.
*   **Outputs:** Optimized Gaussian parameters (means $\mu$, covariances $\Sigma$, opacities $\alpha$, spherical harmonic coefficients $\mathbf{c}$, and potentially material properties).

### Data Structures
The hyperparameters are stored in a configuration object or dictionary. Key fields include:
*   `optimizer`: String identifier (e.g., "Adam").
*   `lr`: Dictionary mapping parameter names to learning rates.
*   `loss`: Dictionary mapping loss types (e.g., "L1", "SSIM", "L2") to weights.
*   `densification`: Dictionary containing thresholds (e.g., `threshold`, `alpha_min`).
*   `regularization`: Dictionary containing smoothness weights (e.g., `lambda_smooth`).

### Numbered Steps
1.  **Initialize Optimizer:** Configure the Adam optimizer with specific beta and epsilon values [S1][S2, unofficial].
2.  **Set Learning Rates:** Assign distinct learning rates to different Gaussian attributes to balance convergence speed and stability [S2, unofficial].
3.  **Configure Loss Function:** Select the loss combination (e.g., L1+SSIM, L2) and set their weights [S4].
4.  **Set Densification Threshold:** Define the scalar threshold for the densification criterion [S3, unofficial].
5.  **Apply Regularization:** Set smoothness weights for material properties if performing inverse rendering [S2, unofficial].
6.  **Iterate:** Run the training loop, applying the optimizer updates and periodic densification based on the configured thresholds.

### Formulas
**Adam Optimizer Update:**
$$ \theta_{t+1} = \theta_t - \frac{\eta \sqrt{1-\beta_2^t}}{1-\beta_1^t} \frac{\hat{m}_t}{\sqrt{\hat{v}_t} + \epsilon} $$
Where $\eta$ is the learning rate, $\beta_1=0.9$, $\beta_2=0.999$, and $\epsilon=10^{-15}$ [S1][S2, unofficial].

**Densification Criterion (Contribution-Based):**
The gradient magnitude is normalized by the mean contribution $\bar{w}_i$ rather than the number of pixels [S3, unofficial]:
$$ \bar{w}_i = \frac{1}{N_i} \sum_p w_{i,p} $$
Where $w_{i,p} = \alpha_{i,p}T_{i,p}$ is the contribution weight at pixel $p$, $\alpha_{i,p}$ is opacity, and $T_{i,p}$ is transmittance [S3, unofficial]. The gradient component $g_{i,x}$ is:
$$ g_{i,x} = \sum_p \frac{\partial L_p}{\partial C_p} \cdot (c_i - A_{i,p}) \cdot w_{i,p} \cdot \frac{\partial \ln(G_{i,p})}{\partial \mu_{i,x}} $$
Where $G_{i,p} = \exp\left(-\frac{1}{2} (p - \mu_i)^T \Sigma_i^{-1} (p - \mu_i)\right)$ is the projected footprint [S3, unofficial].

**Loss Functions:**
Standard 3DGS uses weighted L1 and SSIM [S4]:
$$ L = 0.8 \cdot L_{SSIM} + 0.2 \cdot L_{L1} $$
Mipmap-GS simplifies this to L2 for optimization [S4]:
$$ L = L_{L2} $$

### Parameters with Typical Values
*   **Optimizer:** Adam [S1][S2, unofficial].
*   **Beta:** $(0.9, 0.999)$ [S1][S2, unofficial].
*   **Epsilon:** $10^{-15}$ [S1][S2, unofficial].
*   **Learning Rates (Phys3DGS):**
    *   Position: $1.6 \times 10^{-4}$
    *   Color SH: $2.5 \times 10^{-3}$
    *   Scale: $5 \times 10^{-3}$
    *   Opacity: $5 \times 10^{-2}$
    *   Base Color: $1 \times 10^{-2}$
    *   Metallic: $1 \times 10^{-2}$
    *   Roughness: $1 \times 10^{-2}$
    *   Normal Rotation: $1 \times 10^{-3}$
    *   Direct Light SH (deg=0): $2.5 \times 10^{-3}$
    *   Direct Light SH (deg>0): $1 \times 10^{-4}$
    *   Indirect Light SH (deg=0): $2.5 \times 10^{-4}$
    *   Indirect Light SH (deg>0): $1 \times 10^{-3}$
    *   Visibility SH: $0.1$ [S2, unofficial].
*   **Regularization Weights (Phys3DGS):**
    *   $\lambda_{smooth}$ (Base Color): $0.06$
    *   $\lambda_{smooth}$ (Roughness): $0.02$
    *   $\lambda_{smooth}$ (Metallic): $0.02$
    *   Other regularizers ($\lambda_o, \lambda_{sc}, \lambda_{sr}$): $1.0$ [S2, unofficial].
*   **Densification Threshold:**
    *   Default: $0.002$ (improves metrics, increases count) [S3, unofficial].
    *   Reduced Count: $0.003$ (retains gains, lower count) [S3, unofficial].
    *   Under-densification: $> 0.004$ [S3, unofficial].
*   **Loss Weights (Standard 3DGS):** SSIM: $0.8$, L1: $0.2$ [S4].
*   **Reflectivity (ToRF):** Initialization: $0.1$, Learning Rate: $0.00016$ [S1].
*   **MLP Learning Rate (ToRF):** Starts at $0.0008$, decays to $1.6 \times 10^{-6}$ over 60,000 iterations [S1].

### Edge Cases and Pitfalls
*   **Cloning Over-densification:** The clone operation can cause inflated Gaussian counts without quality improvement. Mitigation: Disable cloning by overriding scene extent to force split-only densification [S3, unofficial].
*   **Abnormal Gaussian Behavior:** If a single Gaussian behaves abnormally (e.g., extreme scale, opacity, or position), it can occlude global illumination, causing the optimizer to compensate with extreme intensity/opacity changes, leading to gradient overflow in SH coefficients or opacity [S2, unofficial]. High regularization weights ($\lambda=1.0$) help mitigate this [S2, unofficial].
*   **View Selection for Zoom-in:** Using training views for optimization focuses on known-view fitting and degrades novel-view performance. Use test views or synthetic views (e.g., 50 synthetic views) instead [S4].
*   **Loss Function Choice:** L2 loss performs comparably to L1+SSIM in Mipmap-GS (PSNR 28.57 vs 28.57), while L2+SSIM degrades performance (27.17) [S4].

### Pseudocode
```python
def configure_hyperparameters(method="standard"):
    """
    Returns a dictionary of hyperparameters based on the selected method.
    """
    params = {}
    
    # Common Optimizer Settings
    params['optimizer'] = 'Adam'
    params['beta1'] = 0.9
    params['beta2'] = 0.999
    params['epsilon'] = 1e-15
    
    if method == "standard":
        # Standard 3DGS Loss
        params['loss_weights'] = {'SSIM': 0.8, 'L1': 0.2}
        # Standard Densification Threshold
        params['densification_threshold'] = 0.002
        
    elif method == "phys3dgs":
        # Phys3DGS Learning Rates
        params['learning_rates'] = {
            'position': 1.6e-4,
            'color_sh': 2.5e-3,
            'scale': 5e-3,
            'opacity': 5e-2,
            'base_color': 1e-2,
            'metallic': 1e-2,
            'roughness': 1e-2,
            'normal_rotation': 1e-3,
            'direct_light_sh_deg0': 2.5e-3,
            'direct_light_sh_deg_gt0': 1e-4,
            'indirect_light_sh_deg0': 2.5e-4,
            'indirect_light_sh_deg_gt0': 1e-3,
            'visibility_sh': 0.1
        }
        # Phys3DGS Regularization
        params['regularization'] = {
            'lambda_smooth_base_color': 0.06,
            'lambda_smooth_roughness': 0.02,
            'lambda_smooth_metallic': 0.02,
            'lambda_o': 1.0,
            'lambda_sc': 1.0,
            'lambda_sr': 1.0
        }
        
    elif method == "mipmap_gs":
        # Mipmap-GS Loss (Simplified to L2)
        params['loss_weights'] = {'L2': 1.0}
        # Mipmap-GS uses test views for optimization
        params['optimization_views'] = 'test'
        
    elif method == "torf":
        # ToRF Specifics
        params['reflectivity_init'] = 0.1
        params['reflectivity_lr'] = 0.00016
        params['mlp_lr_init'] = 0.0008
        params['mlp_lr_final'] = 1.6e-6
        params['mlp_decay_iterations'] = 60000
        
    elif method == "contribution_based":
        # Contribution-based Densification (StopThePop/3DGS port)
        # Threshold 0.002 improves metrics but increases count
        # Threshold 0.003 reduces count while retaining gains
        params['densification_threshold'] = 0.003
        # Disable cloning to prevent over-densification
        params['disable_cloning'] = True
        
    return params

def train_step(gaussians, images, params):
    """
    Performs a single training step using the configured hyperparameters.
    """
    optimizer = Adam(gaussians.parameters(), 
                     lr=params['learning_rates'], 
                     betas=(params['beta1'], params['beta2']), 
                     eps=params['epsilon'])
    
    # Compute Loss
    rendered_images = render(gaussians, images.cameras)
    loss = compute_loss(rendered_images, images.gt, params['loss_weights'])
    
    # Apply Regularization if present
    if 'regularization' in params:
        reg_loss = compute_regularization(gaussians, params['regularization'])
        loss += reg_loss
        
    # Backpropagate
    loss.backward()
    optimizer.step()
    
    # Densification Check (every N iterations)
    if current_iteration % refine_every == 0:
        densify(gaussians, params['densification_threshold'], 
                disable_cloning=params.get('disable_cloning', False))
```

## Subtopics

### [Conditional 3DGS Optimization and Rendering](11459-conditional-3dgs-optimization-and-rendering.md)
Conditional 3DGS Optimization and Rendering extends 3D Gaussian Splatting to handle dynamic scenes by incorporating temporal and directional dependencies into the Gaussian representation. It solves the problem of rendering animated or view-dependent content by conditioning the Gaussian parameters on time and view direction, allowing for unified spatial-temporal-angular optimization. Unlike static 3DGS, this method leverages temporal cues for densification and uses conditional covariance matrices to capture motion dynamics, distinguishing it from siblings like [Blended Error Densification and Splitting](13892-blended-error-densification-and-splitting.md) which focus on spatial error metrics alone.

### [Blended Error Densification and Splitting](13892-blended-error-densification-and-splitting.md)
Blended Error Densification and Splitting is a strategy for growing Gaussian primitives in 3D Gaussian Splatting that uses an auxiliary per-pixel error metric to drive densification decisions, rather than relying on positional gradient magnitudes. It solves the limitation of gradient-based methods, which are sensitive to error changes but blind to absolute error values in high-frequency areas, by redistributing per-pixel errors to primitives proportional to their rendering contribution. This method is distinct from sibling strategies like [Conditional 3DGS Optimization and Rendering](11459-conditional-3dgs-optimization-and-rendering.md) by explicitly utilizing accumulated L1 error norms as probability weights for splitting.

### [Adaptive Gaussian Selector](16104-adaptive-gaussian-selector.md)
The Adaptive Gaussian Selector is a learnable module within the FlexGS framework that adaptively selects a subset of 3D Gaussians during training based on their attributes and a desired elastic ratio $e$, using a differentiable mask to enable gradient-based optimization. It sets itself apart from non-differentiable thresholding or hard masking by allowing gradients to flow through the selection decision via the Straight-Through Estimator (STE) applied to Gumbel-Softmax outputs, unlike sibling methods that rely on fixed heuristics or non-differentiable hard thresholds.

## Operating characteristics
*   **Time Complexity:** Training time depends on the number of Gaussians and iterations. Mipmap-GS converges in ~1K iterations for zoom-in [S4]. ToRF uses 60,000 iterations for MLP decay [S1].
*   **Memory Complexity:** Proportional to the number of Gaussians. Standard 3DGS uses ~1.8-2.8M Gaussians on Mip-NeRF360 [S3, unofficial]. Contribution-based criterion reduces this to 1.48-1.68M on Zip-NeRF scenes [S3, unofficial].
*   **Performance:** L2 loss achieves PSNR 28.57 on Mip-NeRF 360, comparable to L1+SSIM [S4]. Phys3DGS requires careful regularization to prevent instability from abnormal Gaussians [S2, unofficial].
*   **Strengths:** Specific learning rates and regularization prevent gradient overflow and material ambiguity [S2, unofficial]. Contribution-based thresholds optimize Gaussian count vs. quality [S3, unofficial].
*   **Limitations:** Cloning can cause over-densification if not disabled [S3, unofficial]. Abnormal Gaussians can destabilize training [S2, unofficial].

## Background
Hyperparameter settings for 3D Gaussian Splatting have evolved from the original Kerbl et al. [13] configuration (Adam, L1+SSIM) to specialized variants for specific tasks. Phys3DGS introduced material-specific learning rates and smoothness regularizers for inverse rendering [S2, unofficial]. Mipmap-GS simplified the loss to L2 and used test views for super-resolution optimization [S4]. ToRF adapted settings for dynamic scenes with temporal MLPs [S1]. The contribution-based criterion was introduced to address bias in gradient-based densification [S3, unofficial].
