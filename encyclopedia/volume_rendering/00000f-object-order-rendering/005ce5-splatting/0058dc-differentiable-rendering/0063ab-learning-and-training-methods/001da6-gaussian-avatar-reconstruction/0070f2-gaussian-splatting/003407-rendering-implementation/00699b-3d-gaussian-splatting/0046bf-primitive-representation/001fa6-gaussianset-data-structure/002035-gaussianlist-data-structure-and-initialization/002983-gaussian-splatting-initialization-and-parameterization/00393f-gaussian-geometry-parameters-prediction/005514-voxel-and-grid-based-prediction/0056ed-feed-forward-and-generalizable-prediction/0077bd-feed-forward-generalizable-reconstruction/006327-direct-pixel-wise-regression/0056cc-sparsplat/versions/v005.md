# SparSplat

Also called: Generalizable 2D Gaussian Splatting, SparSplat Model, SparSplat: Fast Multi-View Reconstruction with Generalizable 2D Gaussian Splatting

## Overview
SparSplat is a generalizable, feed-forward model that maps a sparse set of input images to 2D Gaussian Splatting (2DGS) parameters in a single forward pass to perform both 3D shape reconstruction and novel view synthesis [S1, unofficial]. It differs from its sibling [MVSGaussian](12847-anysplat-pipeline.md) by using 2D primitives instead of 3D Gaussians, which ensures multi-view depth consistency required for coherent TSDF mesh fusion, and it differs from prior generalizable methods by being explicitly fit for feed-forward surface reconstruction rather than novel view synthesis alone [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $N$ color images $\{I_i\}_{i=1}^N$ where $I_i \in \mathbb{R}^{H \times W \times 3}$, and their corresponding camera poses $P_i$ (rotation and translation). The model assumes known poses.
*   **Output:** For a target view $P_t$, a pixel-aligned 2DGS parameter map $O_t = \{s, q, p, \alpha, c\} \in \mathbb{R}^{H \times W \times (2+4+3+1+3)}$ [S1, unofficial].
    *   $s$: Scale (2 values).
    *   $q$: Rotation quaternion (4 values).
    *   $p$: 3D position/centroid (3 values).
    *   $\alpha$: Opacity (1 value).
    *   $c$: Color (3 values).
*   **Mesh:** An explicit 3D triangle mesh $S$ is obtained by rendering depth maps from the predicted splats and fusing them using Truncated Signed Distance Function (TSDF) fusion [S1, unofficial].

**Data Structures:**
The core data structure is the Gaussian primitive attribute map $O_t$. The layout is fixed per pixel:
1.  Scale: 2 floats.
2.  Rotation: 4 floats (quaternion).
3.  Position: 3 floats (unprojected depth).
4.  Opacity: 1 float.
5.  Color: 3 floats.
Total: 13 floats per pixel.

**Algorithm Steps:**
The model $\Phi$ processes the input images to predict $O_t$ for a target view $P_t$ as follows [S1, unofficial]:

1.  **Feature Extraction:**
    *   Extract monocular 2D semantic features from each input image $I_i$ using DINOv2 [S1, unofficial].
    *   Extract pairwise dense correspondence features from input images using MASt3R [S1, unofficial].
    *   Pass each input image $I_i$ through a Feature Pyramid Network (FPN) to predict a 2D feature map $f_i$ [S1, unofficial].

2.  **Homography Warping:**
    *   Compute relative poses $P_t / P_i$ between the target view and each source view.
    *   Warp the feature maps $f_i$ to the target view coordinate system using homography warping based on the relative poses, resulting in warped feature maps $f_{t,i}$ [S1, unofficial].

3.  **Multi-View Aggregation (DeepMVS Branch):**
    *   Merge the warped feature maps $f_{t,i}$ into a 3D cost volume [S1, unofficial].
    *   Process the cost volume with a 3D convolutional network to produce a probability volume [S1, unofficial].
    *   Sample depth planes to predict a coarse depth map (64 planes) and a fine depth map (8 planes) [S1, unofficial].
    *   Unproject the predicted depth using camera intrinsics $K$ to determine the 3D position attribute $p$ for the Gaussians [S1, unofficial].

4.  **Parameter Prediction (Pixel-Aligned Branch):**
    *   Pool the warped features $f_{t,i}$ into a target feature map $f_t$ [S1, unofficial].
    *   Process $f_t$ with a 2D convolutional network and an MLP to predict the remaining Gaussian primitive attributes: scale $s$, rotation $q$, opacity $\alpha$, and color $c$ [S1, unofficial].

5.  **Assembly:**
    *   Combine the predicted attributes $\{s, q, \alpha, c\}$ from step 4 with the position $p$ from step 3 to form the final parameter map $O_t$ [S1, unofficial].

6.  **Rendering and Meshing (Inference):**
    *   Render the scene using perspective-accurate 2D Gaussian Splatting to generate novel views [S1, unofficial].
    *   Render depth maps for all training views $P_i$ using their respective predicted splat maps $O_i = \Phi(P_i | I_1, ..., I_N)$ [S1, unofficial].
    *   Perform TSDF fusion on the $N$ mean splatted depths to extract the 3D mesh $S$. The TSDF voxel size is set to 1.5 [S1, unofficial].

**Training Loss:**
The network is trained using a combination of losses. The specific weights used are $\lambda_s = 0.1$, $\lambda_p = 0.05$, $\lambda_\alpha = 0.05$, $\lambda_\beta = 0.05$, $\lambda_\gamma = 0.05$, $\lambda_1 = 0.5$, and $\lambda_2 = 1$ [S1, unofficial]. A depth loss $L_{depth}$ is applied to guide the mean 2DGS splatted depth with ground truth depth supervision [S1, unofficial].

**Parameters and Settings:**
*   **Training Resolution:** $640 \times 512$ [S1, unofficial].
*   **Number of Source Images ($N$):** 3 [S1, unofficial].
*   **Optimizer:** Adam, initial learning rate $5 \times 10^{-4}$ [S1, unofficial].
*   **Training Steps:** 300,000 steps [S1, unofficial].
*   **Hardware:** Single RTX A6000 GPU [S1, unofficial].

**Edge Cases and Pitfalls:**
*   Using 3DGS instead of 2DGS causes depth inconsistencies across views, leading to TSDF producing incorrect fusions with warped/disconnected surfaces [S1, unofficial].
*   Prior state-of-the-art generalizable GS methods (e.g., MVSGaussian) fail to give coherent reconstructions on TSDF fusion of rendered depth maps [S1, unofficial].

## Operating characteristics
*   **Speed:** Inference time is approximately 0.8s (reproduced 0.88s) on an RTX A6000, which is almost 2 orders of magnitude faster than prior state-of-the-art feed-forward sparse view reconstruction methods based on implicit volume rendering (e.g., UfoRecon 66s, GeoTransfer 32s) [S1, unofficial].
*   **Accuracy (NVS):** On the DTU test set, SparSplat achieves PSNR 28.33, SSIM 0.938, and LPIPS 0.073 [S1, unofficial]. It outperforms MVSGaussian in novel-view synthesis, particularly in regions with low input view overlap [S1, unofficial].
*   **Accuracy (Reconstruction):** On the DTU sparse 3D reconstruction benchmark, it achieves a mean Chamfer Distance of 1.04 [S1, unofficial]. Adding depth loss improves mean Chamfer distance by 71.8% (from 4.37 to 1.04) [S1, unofficial].
*   **Feature Impact:** Using MASt3R features provides an 11.11% boost in reconstruction quality over using only image features, compared to a 0.85% boost from DINOv2 [S1, unofficial].
*   **Strengths:** Fast inference, state-of-the-art performance in both 3D reconstruction and novel view synthesis for sparse views, coherent mesh extraction via TSDF.
*   **Limitations:** Requires known camera poses (though poses can be predicted by other modules). Performance depends on the quality of foundation model features (MASt3R/DINOv2).

## Background
SparSplat was proposed by Shubhendu Jena et al. in 2025 [S1, unofficial]. It builds upon the MVSGaussian framework [48] but replaces 3D Gaussians with 2D Gaussian Splatting (2DGS) [28] to improve 3D geometry consistency. It is inspired by MVSFormer++ [6], which uses DINOv2 for feature encoding. The method is designed to address the challenge of generalizable sparse 3D reconstruction and novel view synthesis jointly, leveraging deep features from foundation models like DINOv2 and MASt3R [S1, unofficial]. It is evaluated on the DTU, BlendedMVS, and Tanks and Temples datasets [S1, unofficial].
