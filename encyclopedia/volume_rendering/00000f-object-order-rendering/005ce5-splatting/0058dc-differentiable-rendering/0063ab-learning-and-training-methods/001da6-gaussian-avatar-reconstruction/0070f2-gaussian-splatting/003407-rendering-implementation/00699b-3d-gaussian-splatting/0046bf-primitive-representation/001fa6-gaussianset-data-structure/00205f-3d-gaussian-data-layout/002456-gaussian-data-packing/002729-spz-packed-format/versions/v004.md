# SPZ Packed Format

Also called: NGSP, Niantic Gaussian Packed

## Overview
SPZ Packed Format is a binary storage format for 3D Gaussian splats designed for low-precision, non-interleaved data storage with ZSTD compression [S1, unofficial]. It solves the problem of efficiently loading high-fidelity Gaussian splat captures in environments lacking native system-level decompression libraries, such as web browsers . It is distinguished from earlier SPZ versions (1–3) by using per-attribute ZSTD compression instead of a single gzip stream, and from generic PLY parsers by its specific handling of quantized fields and coordinate system transformations .

## How it works
**Inputs:** A binary stream containing the SPZ file data.
**Outputs:** A `GaussianCloud` structure containing unpacked positions, rotations, scales, alphas, colors, and spherical harmonics (SH) coefficients.

**Data Structures:**
The format uses a header followed by parallel attribute buffers.

1.  **Header (`PackedGaussians`):**
    *   `version` (`uint32_t`): Format version. Default is `LATEST_SPZ_HEADER_VERSION` (4) [S1, unofficial].
    *   `numPoints` (`int32_t`): Number of Gaussian primitives [S1, unofficial].
    *   `shDegree` (`int32_t`): Degree of spherical harmonics (0–4) [S1, unofficial].
    *   `fractionalBits` (`int32_t`): Precision bits for position/scale quantization [S1, unofficial].
    *   `antialiased` (`bool`): Flag indicating antialiasing support [S1, unofficial].
    *   `usesQuaternionSmallestThree` (`bool`): Default `true` [S1, unofficial].
    *   `hadSkippedExtensions` (`bool`): Flag for unknown extensions [S1, unofficial].
    *   *Note:* Data is stored in separate `std::vector<uint8_t>` buffers for positions, scales, rotations, alphas, colors, and SH [S1, unofficial].

2.  **Single Point View (`PackedGaussian`):**
    *   Represents a single Gaussian for indexing purposes (92 bytes for SH degree 4) [S1, unofficial]:
        *   `position`: `std::array<uint8_t, 9>` (3 floats, 3 bytes each) [S1, unofficial].
        *   `rotation`: `std::array<uint8_t, 4>` (4 bytes) [S1, unofficial].
        *   `scale`: `std::array<uint8_t, 3>` (3 bytes) [S1, unofficial].
        *   `color`: `std::array<uint8_t, 3>` (3 bytes) [S1, unofficial].
        *   `alpha`: `uint8_t` [S1, unofficial].
        *   `shR`, `shG`, `shB`: `std::array<uint8_t, 24>` each (24 coefficients for degree 4) [S1, unofficial].

**Parameters:**
*   `SH_MAX_COEFFS`: 24 (for degree 4) [S1, unofficial].
*   `DEFAULT_SH1_BITS`: 5 (bits for first SH coefficient) [S1, unofficial].
*   `DEFAULT_SH_REST_BITS`: 4 (bits for remaining SH coefficients) [S1, unofficial].
*   `LATEST_SPZ_HEADER_VERSION`: 4 [S1, unofficial].
*   `MIN_ZSTD_SPZ_HEADER_VERSION`: 4 (minimum version supporting ZSTD) [S1, unofficial].
*   `MIN_SMALLEST_THREE_QUATERNIONS_VERSION`: 3 (minimum version using SmallestThree encoding) [S1, unofficial].

**Steps:**

1.  **Read Header:** Read the 8-byte magic number `0x5053474e` ("NGSP"). Read the header fields. If `version < MIN_ZSTD_SPZ_HEADER_VERSION`, decompression must be handled differently (e.g., gzip) [S1, unofficial].
2.  **Decompress Buffers:** Decompress each attribute buffer (positions, rotations, etc.) using ZSTD. The compression is applied per attribute, not to the entire file as a single stream .
3.  **Decode Positions:** Each position is 9 bytes (3 floats). Unquantize using `fractionalBits`.
4.  **Decode Rotations:** Depending on `version` and `usesQuaternionSmallestThree`:
    *   If `version >= MIN_SMALLEST_THREE_QUATERNIONS_VERSION` and `usesQuaternionSmallestThree` is true, use **SmallestThree** decoding [S1, unofficial].
    *   Otherwise, use **FirstThree** decoding [S1, unofficial].
5.  **Decode Scales:** Unquantize from uint8 to float.
6.  **Decode Colors:** Unquantize from uint8 to float. Apply base color scale factor $C_{base} = C_{raw} \times 0.15$ [S1, unofficial].
7.  **Decode Alphas:** Unquantize from uint8 to float.
8.  **Decode SH Coefficients:** Unquantize uint8 values to float using $v = \frac{x - 128.0}{128.0}$ [S1, unofficial].
9.  **Apply Extensions:** If `hadSkippedExtensions` is true, parse optional extension blocks (e.g., `CoordinateSystemAdobe`, `SafeOrbitCameraAdobe`) [S1, unofficial].

    Decodes quaternion rotations.

        for i in range(0, len(raw_bytes), 4):

            i_largest = comp >> 30
            rotation = [0.0] * 4
            sum_squares = 0.0
            temp_comp = comp
            
            # Extract 3 components
            for j in range(3, -1, -1):
                if j != i_largest:
                    mag = temp_comp & 0x1FF
                    negbit = (temp_comp >> 9) & 1
                    temp_comp >>= 10
                    
                    val = math.sqrt(0.5) * mag / 511.0
                    if negbit:
                        val = -val
                    rotation[j] = val
                    sum_squares += val * val
            
            # Calculate largest component
            rotation[i_largest] = math.sqrt(max(0.0, 1.0 - sum_squares))
            
            # Flip Q if necessary (coordinate system adjustment)
            # Note: c.flipQ is typically -1 or 1 depending on coordinate system
            # Assuming standard right-handed to left-handed or similar flip
            # The source mentions c.flipQ applied to first 3 components.

            flip_q = 1.0 
            rotation[0] *= flip_q
            rotation[1] *= flip_q
            rotation[2] *= flip_q

    else:

        for i in range(0, len(raw_bytes), 3):

            y = (raw_bytes[i+1] / 127.5) - 1.0
            z = (raw_bytes[i+2] / 127.5) - 1.0

            flip_q = 1.0
            x *= flip_q
            y *= flip_q
            z *= flip_q

            rotations.append([x, y, z, w])
            
    return rotations

    """
    colors = []
    for i in range(0, len(raw_bytes), 3):

**Edge Cases and Pitfalls:**
*   **Quaternion Reconstruction:** If numerical error causes $1 - \sum_{i=0}^{2} r_i^2 < 0$, use `std::max(0.0f, ...)` to ensure the sqrt argument is non-negative [S1, unofficial].
*   **WASM Memory View:** In JavaScript/WebAssembly environments, the typed memory view must be consumed immediately because it detaches if any subsequent WASM allocation grows the heap [S1, unofficial].
*   **Coordinate Systems:** Extensions like `CoordinateSystemAdobe` may require flipping quaternion components or axes. Check `hadSkippedExtensions` and parse extensions if present [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Decompression is linear with respect to the number of bytes, $O(N)$, where $N$ is the file size. Decoding is also $O(N)$.
*   **Memory Complexity:** $O(N)$ for storing the decompressed cloud.
*   **Performance:** ZSTD compression provides high compression ratios for quantized data, reducing file size significantly compared to uncompressed PLY.
*   **Strengths:** Efficient storage, fast decompression, browser-friendly (via WASM ZSTD), supports high-degree SH.
*   **Limitations:** Requires ZSTD library for decompression. Non-interleaved layout may complicate certain GPU upload strategies compared to interleaved formats.
*   **When to Use:** When storage efficiency and fast loading are critical, especially in web or mobile environments.
*   **When Not to Use:** When random access to individual Gaussian attributes is required without decompressing the entire file, or when ZSTD is not available.

## Background
The SPZ format was developed by Niantic Labs [S1, unofficial]. It is an evolution of earlier Gaussian Splatting storage formats, designed to address the limitations of PLY files in terms of size and loading speed. Version 4 introduced ZSTD compression and SmallestThree quaternion encoding [S1, unofficial].
