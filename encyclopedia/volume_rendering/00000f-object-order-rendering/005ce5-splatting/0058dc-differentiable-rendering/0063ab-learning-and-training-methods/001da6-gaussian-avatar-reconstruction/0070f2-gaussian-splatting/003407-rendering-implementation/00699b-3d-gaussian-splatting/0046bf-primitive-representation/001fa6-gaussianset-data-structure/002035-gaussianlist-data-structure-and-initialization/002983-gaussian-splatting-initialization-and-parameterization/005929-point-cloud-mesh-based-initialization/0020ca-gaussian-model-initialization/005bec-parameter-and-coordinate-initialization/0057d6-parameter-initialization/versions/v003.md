# Parameter Initialization

Also called: Emission, Roughness, and Specular Initialization, Median Texture Initialization for Diffuse Color

## Overview
Parameter initialization establishes neutral or geometrically plausible starting values for material and lighting parameters in inverse rendering pipelines, preventing optimization divergence and gradient explosion [S1, S2]. Unlike position or opacity initialization, which derives directly from input geometry, these parameters (albedo, roughness, environment lighting) are initialized to neutral states (e.g., albedo ~0.5, emission 0) to ensure the initial render is physically plausible and stable [S1, S2].

## How it works
The method initializes parameters for inverse rendering models, specifically focusing on diffuse albedo, specular BRDF, environment lighting, and material properties like emission and roughness.

**Inputs:**
- Input images (reference views) with potentially varying exposure.
- Object bounding box or mesh geometry.
- Number of environment map lobes (if applicable).

**Outputs:**
- Initialized parameters for the rendering model:
  - Diffuse albedo field/texture.
  - Specular BRDF parameters (sharpness, albedo).
  - Environment map lobes.
  - Material parameters (emission, roughness).

**Data Structures:**
- **Environment Map Lobes:** A list of vectors representing spherical Gaussian lobes. Each lobe has a direction (unit vector), an amplitude (scalar), and a sharpness parameter (scalar).
- **Diffuse Albedo:** A texture or field defined over the object's surface or bounding volume.
- **Material Parameters:** Scalars for emission, roughness, and specular albedo.

**Steps:**

1. **Input Image Normalization:**
   Scale all input images by a constant factor such that the median intensity of all scaled images is 0.5. This handles varying exposure across captures [S1, S2].

2. **Diffuse Albedo Initialization:**
   Initialize the diffuse albedo $a(x; \Phi)$ such that the predicted albedo is approximately 0.5 at all locations inside the object's bounding box. This can be achieved by:
   - Building a median texture: Iterate over all available reference pictures and project them into texture space. Use an online median estimator to compute the median color at each texel, avoiding memory issues with large numbers of views. The median is preferred over the mean to suppress view-dependent effects like specular reflections [S2].
   - Alternatively, for neural implicit representations, initialize the network weights such that the output albedo is ~0.5 for all inputs within the bounding box [S1].

3. **Specular BRDF Initialization:**
   - Initialize the specular BRDF lobe sharpness $\lambda$ by drawing randomly from the interval $[95, 125]$ [S1].
   - Initialize the specular albedo $\mu$ by drawing randomly from the interval $[0.18, 0.26]$ [S1].

4. **Environment Map Initialization:**
   - Initialize the environment map lobes to distribute uniformly on the unit sphere using a spherical Fibonacci lattice [S1].
   - Assign monochrome colors to the lobes [S1].
   - Scale the randomly initialized lobes' amplitudes so that the initial rendered pixel intensity output by the pipeline is approximately 0.5 [S1].

5. **Material Parameter Initialization:**
   - Initialize emission to 0 [S2].
   - Initialize roughness to 0.5 [S2].
   - Initialize specular to 0.5 [S2].

6. **SDF Initialization (if applicable):**
   If using Signed Distance Functions (SDF), initialize the SDF weights $\Theta$ using the method of [12] such that the initial shape is roughly a sphere [S1].

def spherical_fibonacci_lattice(n):
    """
    Generate n points uniformly distributed on a unit sphere using spherical Fibonacci lattice.
    """
    points = []
    golden_angle = np.pi * (3 - np.sqrt(5))
    for i in range(n):
        y = 1 - (i / (n - 1)) * 2  # from 1 to -1
        radius = np.sqrt(1 - y * y)
        theta = golden_angle * i
        x = np.cos(theta) * radius
        z = np.sin(theta) * radius
        points.append([x, y, z])
    return np.array(points)

**Edge Cases and Pitfalls:**
- If the initial environment map is too bright or too dark, the diffuse albedo MLP may get stuck, predicting all zeros or ones during training [S1]. Proper scaling of environment map amplitudes is critical [S1].
- Using the mean instead of the median for diffuse color initialization may retain view-dependent effects like specular reflections, leading to inaccurate albedo estimates [S2].

## Operating characteristics
- **Time Complexity:** Initialization is generally fast, dominated by the computation of the median texture or the generation of the spherical Fibonacci lattice. The median texture computation scales linearly with the number of views and texels.
- **Memory Complexity:** The median texture requires memory proportional to the number of texels. An online median estimator helps manage memory for large numbers of views [S2].
- **Strengths:** Prevents optimization divergence by starting from neutral, physically plausible values. The median texture initialization effectively suppresses specular highlights, leading to better albedo estimates [S2].
- **Limitations:** The quality of the initial environment map depends on the accuracy of the amplitude scaling, which may require a preliminary forward pass [S1]. The method assumes that the input images are reasonably well-exposed and aligned.

## Background
This initialization strategy is primarily used in inverse rendering pipelines that reconstruct materials and lighting from images, such as PhySG [S1] and texture-space differentiable rendering methods [S2]. It addresses the challenge of optimizing complex material and lighting parameters, which are sensitive to initial values and can lead to poor local minima if not initialized carefully. The use of median textures for albedo initialization was introduced to handle view-dependent effects in multi-view reconstruction [S2].
