# Online Image Rendering Placement

Also called: Image patch placement, Online placement of image rendering

## Overview
Online Image Rendering Placement is a per-iteration optimization step in distributed 3D Gaussian Splatting training that assigns image patches to GPUs to minimize inter-node communication and balance computational load [S1, unofficial]. Unlike static partitioning methods that assign entire images or fixed regions, this method dynamically determines the optimal GPU owner for each small image patch based on the current batch's frustum culling results [S1, unofficial]. It sets itself apart from siblings like [BlitzGS](15088-blitzgs.md) or [Distributed 3D Gaussian Splatting](16979-distributed-3d-gaussian-splatting.md) by treating placement as a fast, online heuristic problem solved at every training step rather than an offline graph partitioning task [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** The current training batch of $B$ image patches; the global set of $N$ GPUs; the local shard of 3D Gaussians $\mathcal{G}^{(m)}$ stored on each GPU $m$; and configurable coefficients $\alpha, \beta, \gamma, \delta$.
*   **Outputs:** A placement vector $W$ of size $B$, where $W_j \in \{0, \dots, N-1\}$ indicates the GPU assigned to render image patch $j$.

**Data Structures:**
*   **Patch-GPU Access Pattern Matrix ($A$):** A $B \times N$ integer matrix. $A_{j,k}$ stores the number of 3D Gaussians from GPU $k$'s local shard that are required to render image patch $j$.
*   **Placement Vector ($W$):** A vector of length $B$ storing the assigned GPU index for each patch.

**Numbered Steps:**
1.  **Frustum Culling:** Each GPU $m$ performs frustum culling on its local Gaussian shard $\mathcal{G}^{(m)}$ for every image patch $j$ in the batch. It counts the number of visible Gaussians from its shard for each patch.
2.  **Exchange Access Patterns:** All GPUs exchange their culling results to construct the global matrix $A$. Specifically, GPU $m$ sends its counts to all other GPUs, and receives counts from them. $A_{j,k}$ is now known to all GPUs.
3.  **Initial Placement via Linear Sum Assignment (LSA):** Solve a relaxed assignment problem to minimize communication volume. The objective is to minimize $\sum_{j=1}^{B} \sum_{k \neq W_j} A_{j,k}$, subject to the constraint that each GPU is assigned approximately $B/N$ patches. This is solved using the Hungarian method [S1, unofficial].
4.  **Local Search Refinement:** Iteratively refine $W$ to balance load. In each step, select two patches $j_1, j_2$ and swap their assigned GPUs ($W_{j_1} \leftrightarrow W_{j_2}$) if it reduces the relaxed objective function. Repeat until convergence or a time budget is exhausted.
5.  **Hierarchical Assignment (Optional):** If nodes contain multiple GPUs, first assign patches to machines (nodes), then assign patches within a machine to its local GPUs. For intra-node assignment, set $\alpha=0$ to ignore communication volume [S1, unofficial].

**Formulas:**
Let $W_j$ be the GPU assigned to patch $j$. Let $N$ be the total number of GPUs.
The load metrics for GPU $k$ are defined as:
$$ \text{send}_k = \sum_{j=1}^{B} [W_j \neq k] \cdot A_{j,k} $$
$$ \text{recv}_k = \sum_{j=1}^{B} [W_j = k] \cdot \left( \sum_{i=1}^{N} A_{j,i} - A_{j,k} \right) $$
$$ \text{comp}_k = \sum_{j=1}^{B} [W_j = k] \cdot \sum_{i=1}^{N} A_{j,i} $$
where $[P]$ is the indicator function, returning 1 if predicate $P$ is true, 0 otherwise [S1, unofficial].

The relaxed objective function for local search is:
$$ \text{Cost} = \beta \cdot \|\text{send}\|_p + \gamma \cdot \|\text{recv}\|_p + \delta \cdot \|\text{comp}\|_p $$
where $\|\text{send}\|_p = \left( \sum_{k=1}^{N} \text{send}_k^p \right)^{1/p}$, and similarly for $\|\text{recv}\|_p$ and $\|\text{comp}\|_p$. The parameter $p$ is typically set to 1 or 2 to avoid non-smooth max terms [S1, unofficial].

**Parameters:**
*   $B$: Batch size of training images/patches. Typical value: 16–64 [S1, unofficial].
*   $N$: Number of GPUs [S1, unofficial].
*   $p$: Power for the norm in the relaxed objective. Not given in the sources.
*   $\alpha, \beta, \gamma, \delta$: Configurable coefficients. $\alpha$ weights communication volume (minimized in LSA stage). $\beta, \gamma, \delta$ weight send, receive, and compute imbalance respectively [S1, unofficial].
*   $p_{grid}$: Grid subdivision factor. Each $H \times W$ image is divided into $p_{grid}^2$ patches. Typical $p_{grid}$: 2–8 [S1, unofficial].

**Pseudocode:**
```python
def online_image_rendering_placement(batch_patches, gaussians_shards, num_gpus, alpha, beta, gamma, delta, p_norm, time_budget):
    """
    batch_patches: List of B image patches.
    gaussians_shards: List of N Gaussian shards, one per GPU.
    num_gpus: N.
    alpha, beta, gamma, delta: Coefficients.
    p_norm: Power for norm calculation.
    time_budget: Max seconds for local search.
    Returns: W, list of length B, W[j] is GPU index for patch j.
    """
    B = len(batch_patches)
    
    # Step 1 & 2: Frustum Culling and Exchange
    # Each GPU computes local counts and exchanges to build A
    # A[j, k] = number of gaussians from GPU k needed for patch j
    A = compute_access_pattern_matrix(batch_patches, gaussians_shards, num_gpus)
    
    # Step 3: Linear Sum Assignment for initial placement
    # Minimize communication: sum over j of sum over k!=W[j] of A[j,k]
    # Constraint: Each GPU gets approx B/N patches
    # Using Hungarian method for O(B^3) complexity
    W = linear_sum_assignment(A, num_gpus, B)
    
    # Step 4: Local Search Refinement
    start_time = time.time()
    improved = True
    while improved and (time.time() - start_time < time_budget):
        improved = False
        # Greedy steepest-ascent: try swapping pairs
        # In practice, sample random pairs or iterate systematically
        for i in range(B):
            for j in range(i + 1, B):
                # Current cost
                current_cost = compute_relaxed_cost(W, A, num_gpus, beta, gamma, delta, p_norm)
                
                # Proposed swap
                W[i], W[j] = W[j], W[i]
                new_cost = compute_relaxed_cost(W, A, num_gpus, beta, gamma, delta, p_norm)
                
                if new_cost < current_cost:
                    improved = True
                    # Keep swap
                else:
                    # Revert swap
                    W[i], W[j] = W[j], W[i]
                    
    return W

def compute_access_pattern_matrix(patches, shards, num_gpus):
    """
    Simulates distributed frustum culling and data exchange.
    Returns B x N matrix A.
    """
    B = len(patches)
    A = zeros((B, num_gpus))
    
    # In a real distributed system, this happens in parallel on GPUs
    # Here we simulate the result:
    for j, patch in enumerate(patches):
        for k in range(num_gpus):
            # Count visible gaussians in shard k for patch j
            A[j, k] = count_visible_gaussians(patch, shards[k])
            
    return A

def compute_relaxed_cost(W, A, num_gpus, beta, gamma, delta, p_norm):
    """
    Computes the relaxed objective function value.
    """
    send_load = zeros(num_gpus)
    recv_load = zeros(num_gpus)
    comp_load = zeros(num_gpus)
    
    for k in range(num_gpus):
        s = 0
        r = 0
        c = 0
        for j in range(len(W)):
            if W[j] != k:
                s += A[j, k]
            if W[j] == k:
                total_needed = sum(A[j, :])
                r += (total_needed - A[j, k])
                c += total_needed
        send_load[k] = s
        recv_load[k] = r
        comp_load[k] = c
        
    # Compute p-norms
    send_norm = norm(send_load, p=p_norm)
    recv_norm = norm(recv_load, p=p_norm)
    comp_norm = norm(comp_load, p=p_norm)
    
    return beta * send_norm + gamma * recv_norm + delta * comp_norm
```

**Edge Cases and Pitfalls:**
*   **ILP Solver Speed:** Standard ILP solvers (e.g., Gurobi) are too slow and unpredictable for online use per iteration [S1, unofficial]. The LSA+Local Search heuristic is mandatory.
*   **Batch Size Scaling:** Whole-image assignment limits scalability to many GPUs. Using small patches ($p_{grid}=2-8$) is critical for small batch sizes (16-64) typical in PBDR training [S1, unofficial].
*   **Intra-node Communication:** For GPUs within the same node, communication bandwidth is high. Setting $\alpha=0$ during intra-node assignment de-prioritizes communication volume in favor of load balancing [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The Linear Sum Assignment step using the Hungarian method has time complexity $O(B^3)$ [S1, unofficial]. The local search step's complexity depends on the number of swaps performed and the time budget, but is designed to be fast enough for online execution.
*   **Memory Complexity:** Requires storing the $B \times N$ access pattern matrix $A$. For typical $B=64$ and $N=8$, this is negligible.
*   **Strengths:** Minimizes inter-node communication volume while balancing compute load. Adapts to the dynamic nature of training batches.
*   **Limitations:** Adds overhead per iteration. The heuristic may not find the global optimum. Performance depends on the quality of frustum culling results.
*   **When to Use:** Distributed training of 3D Gaussian Splatting with large scenes and many GPUs, especially when communication bandwidth is a bottleneck.
*   **When Not to Use:** Single-GPU training, or very small scenes where communication overhead is negligible compared to compute.

## Background
Online Image Rendering Placement was introduced in the paper "Scaling Point-based Differentiable Rendering for Large-scale Reconstruction" (Gaian) [S1, unofficial]. The method addresses the challenge of efficiently distributing rendering workloads across multiple GPUs in a distributed training setting. It builds on the principles of distributed training and sharding [15108-distributed-training-and-sharding.md], specifically optimizing the image rendering phase. The approach was developed to overcome the limitations of static partitioning and slow ILP solvers in an online context.
