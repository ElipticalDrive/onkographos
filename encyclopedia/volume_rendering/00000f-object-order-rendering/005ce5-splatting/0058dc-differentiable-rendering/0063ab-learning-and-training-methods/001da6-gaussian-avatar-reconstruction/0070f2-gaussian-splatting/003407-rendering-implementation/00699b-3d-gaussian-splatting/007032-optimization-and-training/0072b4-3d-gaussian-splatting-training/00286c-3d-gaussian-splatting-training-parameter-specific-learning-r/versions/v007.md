# 3D Gaussian Splatting Training > Parameter-Specific Learning Rates

Also called: Per-parameter group learning rates, Adam parameter learning rates, Gaussian Optimizer Configuration

## Overview
Parameter-Specific Learning Rates configures the Adam optimizer with distinct learning rates for each Gaussian attribute group (means, opacities, scales, colors, rotations) to stabilize training and prevent rapid divergence [S3, unofficial][S1, S2]. Unlike a uniform learning rate, this method assigns higher rates to attributes requiring aggressive adaptation (e.g., colors) and lower rates to stable geometric parameters (e.g., means), addressing the varying sensitivity of different Gaussian properties during differentiable rasterization [S3, unofficial]. It sets itself apart from sibling methods like [CLM](7351-clm.md) or [FastGS](9177-fastgs.md) by focusing exclusively on the optimizer's parameter grouping strategy rather than modifying the rasterization core or representation density [6233-optimization-and-parallelization].

## How it works
**Inputs:**
- Gaussian parameters $\theta$: means $\mathbf{p}$, opacities $\alpha$, scales $\mathbf{s}$, colors $\mathbf{c}$ (and optionally rotations $\mathbf{q}$ or spherical harmonics coefficients).
- Optimizer hyperparameters: base Adam settings ($\beta_1, \beta_2, \epsilon$).

**Outputs:**
- Updated Gaussian parameters $\theta'$ after an optimization step.

**Data Structures:**
The optimizer maintains separate state buffers (first and second moment estimates) for each parameter group. The parameter groups are defined as lists of tensors, where each tensor corresponds to a specific attribute of all active Gaussians.

**Numbered Steps:**
1.  **Initialization:** Initialize the Adam optimizer with a base learning rate of $0.0$ (since rates are handled per group) and $\epsilon = 1\times10^{-15}$ [S3, unofficial][S1]. Set $\beta_1 = 0.9$ and $\beta_2 = 0.999$ [S1].
2.  **Parameter Group Definition:** Define parameter groups with specific learning rates. The standard configuration for 3D Gaussian Splatting assigns rates as follows [S3, unofficial]:
    -   Opacities: $lr_{\alpha} = 0.00085$
    -   Scales: $lr_{\mathbf{s}} = 0.001$
    -   Colours: $lr_{\mathbf{c}} = 0.02$
    -   Means: $lr_{\mathbf{p}} = 0.00015$
    -   *Note:* Some implementations use pre-activation values for opacities and scales with a higher learning rate of $0.05$ [S3, unofficial].
3.  **Trainability Check:** Verify that all required parameters are marked as trainable. In isotropic mode, quaternions are excluded from optimization; attempting to optimize them raises a `RuntimeError` [S3, unofficial].
4.  **Optimizer Step:** For each training iteration:
    -   Compute gradients $\frac{\partial \mathcal{L}}{\partial \theta}$ via the backward pass of the differentiable rasterizer.
    -   Execute `optimizer.step()`, which applies the Adam update rule using the group-specific learning rates.
    -   Execute `optimizer.zero_grad(set_to_none=True)` to free memory [S4, unofficial].
5.  **Cache Management:** Immediately after the optimizer step, call `torch.cuda.empty_cache()` to release unused GPU memory [S4, unofficial].

**Formulas:**
The Adam update for a parameter group $g$ with learning rate $lr_g$ is:
$$
\mathbf{m}_t = \beta_1 \mathbf{m}_{t-1} + (1 - \beta_1) \mathbf{g}_t
$$
$$
\mathbf{v}_t = \beta_2 \mathbf{v}_{t-1} + (1 - \beta_2) \mathbf{g}_t^2
$$
$$
\hat{\mathbf{m}}_t = \frac{\mathbf{m}_t}{1 - \beta_1^t}, \quad \hat{\mathbf{v}}_t = \frac{\mathbf{v}_t}{1 - \beta_2^t}
$$
$$
\theta_{t+1} = \theta_t - lr_g \cdot \frac{\hat{\mathbf{m}}_t}{\sqrt{\hat{\mathbf{v}}_t} + \epsilon}
$$
Where $\mathbf{g}_t$ is the gradient for the group, and $\theta_t$ represents the parameters in that group (e.g., all means, all colors).

**Parameters with Typical Values:**
-   **Standard 3DGS [S3, unofficial]:** $lr_{\alpha}=0.00085$, $lr_{\mathbf{s}}=0.001$, $lr_{\mathbf{c}}=0.02$, $lr_{\mathbf{p}}=0.00015$.
-   **X-Gaussian Variant [S1]:** Position $lr$ starts at $1.9\times10^{-4}$ and decays exponentially to $1.9\times10^{-6}$. Point feature $lr = 2\times10^{-3}$. Opacity $lr = 8\times10^{-3}$. Scaling $lr = 5\times10^{-3}$. Rotation $lr = 1\times10^{-3}$.
-   **Gaussian-Flow Variant [S2]:** Position $lr = 4\times10^{-4}$ with exponential decay of $8\times10^{-7}$. Rotation $lr = 0.002$. DDDM parameters $lr = 4\times10^{-4}$. Weight decay $8\times10^{-7}$ applied to all parameters.
-   **2D Gaussian Variant [S5, S5, unofficial]:** Image-space coordinates $lr = 0.001 \times \text{mean}(\text{width}, \text{height})$. Color $lr = 0.01$. Opacity $lr = 0.02$. Scale $lr = 0.001$. Rotation angle $lr = 0.02$.

**Edge Cases and Pitfalls:**
-   **Isotropic Mode:** If the Gaussian representation is isotropic, rotation parameters (quaternions) are not optimized. The training code must check `check_if_trainable()` to avoid runtime errors [S3, unofficial].
-   **Precision:** The epsilon value is set to $1\times10^{-15}$ to prevent division by zero in the Adam update, which is critical for small gradients in opacity or scale [S1][S3, unofficial].
-   **Memory:** Frequent optimizer steps without cache management can lead to OOM errors; `torch.cuda.empty_cache()` is recommended after each step [S4, unofficial].

**Pseudocode:**
```python
import torch
import torch.optim as optim

def setup_optimizer(gaussians, config):
    """
    Setup parameter-specific Adam optimizer for 3D Gaussian Splatting.
    
    Args:
        gaussians: Object containing trainable parameters (means, opacities, scales, colors, rotations).
        config: Dictionary containing hyperparameters.
        
    Returns:
        optimizer: Adam optimizer instance.
    """
    # Extract parameters based on trainability flags
    # Note: In isotropic mode, rotations are excluded
    means = gaussians.get_means()
    opacities = gaussians.get_opacities()
    scales = gaussians.get_scales()
    colors = gaussians.get_colors()
    
    # Check if rotations should be included
    if gaussians.is_isotropic():
        rotations = None
    else:
        rotations = gaussians.get_rotations()
        
    # Define parameter groups with specific learning rates
    # Standard 3DGS rates [S3, unofficial]
    lr_means = 0.00015
    lr_opacities = 0.00085
    lr_scales = 0.001
    lr_colors = 0.02
    lr_rotations = 0.001 # Default, varies by variant [S1]
    
    param_groups = [
        {'params': means, 'lr': lr_means},
        {'params': opacities, 'lr': lr_opacities},
        {'params': scales, 'lr': lr_scales},
        {'params': colors, 'lr': lr_colors},
    ]
    
    if rotations is not None:
        param_groups.append({'params': rotations, 'lr': lr_rotations})
        
    # Initialize Adam with base lr=0.0 (rates are per group) and eps=1e-15 [S3, unofficial][S1]
    optimizer = optim.Adam(param_groups, lr=0.0, eps=1e-15, betas=(0.9, 0.999))
    
    return optimizer

def training_step(gaussians, optimizer, loss):
    """
    Perform one optimization step.
    """
    # Zero gradients
    optimizer.zero_grad(set_to_none=True)
    
    # Compute loss (forward pass + backward pass handled by autograd)
    # loss = compute_rendering_loss(gaussians, cameras, gt_images)
    
    # Backward pass
    loss.backward()
    
    # Optimizer step
    optimizer.step()
    
    # Release GPU cache [S4, unofficial]
    torch.cuda.empty_cache()
    
    return loss
```

## Subtopics

### [BOGausS Optimizer](9298-bogauss-optimizer.md)
BOGausS (Better Optimized Gaussian Splatting) is a modified Stochastic Gradient Descent optimizer designed to ensure unbiased state estimation for sparsely-viewed and split Gaussians. It addresses performance degradation caused by biased moment estimates in standard Adam when Gaussians are occluded or rarely updated. It sets itself apart by using Gaussian-dependent time steps and precision-aware scaling factors derived from reconstruction confidence intervals, rather than global iteration counts and uniform learning rates.

### Optimizer Step & GPU Cache Management
This variant emphasizes the operational sequence of the optimizer step and memory management. It specifies that `gaussians.optimizer.step()` must be followed immediately by `gaussians.optimizer.zero_grad(set_to_none=True)` and `torch.cuda.empty_cache()` to release unused GPU memory back to the system [S4, unofficial].

### 2D Gaussian Optimization
This variant optimizes 2D Gaussian primitives in image space using the Adam optimizer [S5, S5, unofficial]. It adds 20% of new Gaussian primitives every 200 iterations and prunes those with opacity below 0.005 or covering fewer than 25 pixels [S5, S5, unofficial]. Learning rates are scaled by image dimensions: coordinates $lr = 0.001 \times \text{mean}(\text{width}, \text{height})$, color $lr = 0.01$, opacity $lr = 0.02$, scale $lr = 0.001$, and rotation angle $lr = 0.02$ [S5, S5, unofficial].

### 2D Gaussian Primitive Optimization
A specific implementation of 2D Gaussian optimization that includes clustering of sampling pixels to remove foreground/background before projection [S5, unofficial]. It calculates the initial value of parameter $T$ for supplementary Gaussians as $T = \frac{7\bar{\theta}_i}{\pi}$, constrained to $[0.01, 1.0]$ [S5, unofficial].

## Operating characteristics
-   **Time Complexity:** The optimization step is $O(N)$ with respect to the number of Gaussians $N$, as Adam updates are element-wise operations on the parameter tensors [S1][S3, unofficial].
-   **Memory Complexity:** $O(N)$ for storing the parameters and their first/second moment estimates. The use of `set_to_none=True` in zero_grad helps mitigate memory fragmentation [S4, unofficial].
-   **Performance:** Using distinct learning rates stabilizes training, preventing the rapid divergence often seen with uniform high learning rates on sensitive parameters like colors or scales [S3, unofficial].
-   **Strengths:** Improves convergence stability; allows fine-tuning of geometric vs. photometric attributes independently [S3, unofficial][S1].
-   **Limitations:** Requires careful tuning of per-group rates; different variants (e.g., X-Gaussian vs. Standard 3DGS) use significantly different values, making transfer of settings non-trivial [S1][S3, unofficial].
-   **When to use:** Standard 3DGS training where stability is prioritized over speed; scenes with high dynamic range or complex lighting where color convergence is slow [S3, unofficial].
-   **When not to use:** When using variants like BOGausS that require adaptive, Gaussian-dependent learning rates [S1].

## Background
The concept of parameter-specific learning rates in 3D Gaussian Splatting was introduced in the original 3DGS paper and subsequent implementations to handle the disparate convergence speeds of different Gaussian attributes [S3, unofficial]. The Adam optimizer with $\beta_1=0.9, \beta_2=0.999, \epsilon=10^{-15}$ is the standard baseline [S1]. Variants like X-Gaussian [S1] and Gaussian-Flow [S2] have adapted these rates for specific domains (X-ray, 4D reconstruction), while 2D Gaussian methods [S5, S5, unofficial] extend the concept to image-space primitives.
