# SplatXR On-Headset 3D Gaussian Splatting Renderer

Also called: On-Headset Splatting, SplatXR Renderer

## Overview
SplatXR is a Unity-based renderer designed to display 3D Gaussian Splatting (3DGS) assets directly on Extended Reality (XR) headsets, supporting both in-editor previews and on-headset execution with automatic camera switching [S1]. It distinguishes itself from general-purpose GPU-sorted renderers by offloading the depth-sorting of splats to a background CPU thread at a configurable rate, allowing the GPU shader to focus solely on rasterization and alpha-blending [S1]. This approach trades off sorting latency for reduced GPU overhead, making it suitable for mobile XR hardware where computational budgets are shared with other system tasks [S1].

## How it works

### Inputs and Outputs
**Inputs:**
*   A standard 3D Gaussian Splatting file in PLY format [S1].
*   Camera parameters (view and projection matrices) for the current rendering context (editor or headset) [S1].

**Outputs:**
*   A rasterized image with alpha-blended 3D Gaussian splats [S1].

### Data Structures

**Custom Splat File Format (CSV)**
At design time, the PLY file is converted into a custom CSV format [S1]. This file stores the precomputed attributes required for rendering:
*   **Covariance Matrix:** Precomputed $3 \times 3$ covariance matrix $\Sigma$ for each Gaussian [S1].
*   **Color:** Denormalized color values (RGB) [S1].
*   **Alpha:** Denormalized transparency values [S1].

**Triangle Arrangement**
At runtime, the renderer assembles an arrangement of triangles corresponding to the splats [S1]. Each Gaussian is represented by a triangle in screen space derived from the covariance and position [S1]. These triangles are stored in shader memory [S1].

### Numbered Steps

1.  **Import and Preprocessing (Design Time):**
    *   The user specifies a PLY file in the Unity import panel [S1].
    *   The plugin computes the covariance matrix for each Gaussian [S1].
    *   Color and transparency information are denormalized [S1].
    *   The data is saved in the custom CSV format [S1].
    *   A game object is added to the scene hierarchy with a predefined splat material and rendering script [S1].

2.  **Runtime Initialization:**
    *   The rendering script reads the custom CSV file containing covariance, color, and alpha attributes [S1].
    *   The script determines the rendering context (in-editor or on-headset) and switches to the appropriate camera and parameters [S1].

3.  **Background Sorting:**
    *   Triangles are sorted from the perspective of the current camera [S1].
    *   Sorting occurs in a background CPU thread [S1].
    *   The sorting frequency is adjustable, defaulting to 1 Hz [S1].

4.  **Rendering:**
    *   The shader receives the sorted triangle arrangement in memory [S1].
    *   For each splat-associated triangle, the shader computes the screen-space coverage based on the covariance [S1].
    *   The shader performs alpha-blending to produce the final pixel color [S1].

### Parameters
*   **Sorting Rate:** The frequency at which triangles are re-sorted from the camera's perspective. Default value is 1 Hz [S1].

### Pitfalls
*   **High-Resolution Performance:** Splats with 1 million or more Gaussians cause noticeable frame drops and are infeasible on mobile GPUs like the Qualcomm Snapdragon XR2 Gen 2 (found in Quest 3) due to shared computational budgets [S1].
*   **Passthrough Limitations:** On Apple Vision Pro, passthrough shader functionality is limited by Apple’s PolySpatial platform [S1].

### Subtopics
*   **Level-of-Detail (LoD) Rendering:** A technique implemented within SplatXR to mitigate performance issues on high-resolution splats [S1]. It displays high-resolution splats only in close proximity to the user while rendering lower-resolution splats at increasing distances [S1]. It uses three levels of detail [S1]. ## Operating characteristics

**Time and Memory Complexity:**
*   Sorting complexity is $O(N \log N)$ where $N$ is the number of Gaussians, performed on the CPU at a throttled rate (default 1 Hz) [S1].
*   Rendering complexity is $O(N)$ per frame for rasterization and blending, performed on the GPU [S1].

**Measured Performance:**
*   On mobile GPUs such as the Qualcomm Snapdragon XR2 Gen 2, high-resolution splats (1 million+ Gaussians) are infeasible due to computational budget constraints shared with other device tasks [S1].
*   The renderer supports Apple Vision Pro, though passthrough features are limited [S1].

**Strengths and Limitations:**
*   **Strengths:** Supports both in-editor and on-headset rendering with automatic camera switching; reduces GPU load by offloading sorting to CPU; supports LoD for high-resolution assets [S1].
*   **Limitations:** Sorting latency (1 Hz default) may cause visual jitter if the camera moves rapidly between sorts; high-resolution splats are not feasible on current mobile XR hardware without LoD [S1].

**When to Use:**
*   Use for XR applications requiring 3DGS visualization where GPU resources are constrained and moderate sorting latency is acceptable [S1].
*   Use when integrating 3DGS into Unity workflows with automatic headset detection [S1].

**When Not to Use:**
*   Do not use for scenes with >1 million Gaussians on mobile XR hardware without implementing LoD [S1].
*   Do not use if real-time, frame-accurate sorting is required for every frame (e.g., fast-moving VR interactions) without adjusting the sorting rate, which may increase CPU load [S1].

## Background
SplatXR was introduced in the paper "SplatXR: A Toolkit for Multi-Layered Extended Reality via On-Headset 3D Gaussian Splatting" [S1]. It addresses the need for efficient 3DGS rendering on mobile XR devices, which have limited computational resources compared to desktop GPUs [S1]. The toolkit provides a Unity plugin that automates the conversion of PLY files to a custom CSV format and handles the rendering pipeline, including background sorting and alpha blending [S1]. It supports multiple layers and includes features like cropping, planar flattening, and auto color adjustment for passthrough environments [S1].
