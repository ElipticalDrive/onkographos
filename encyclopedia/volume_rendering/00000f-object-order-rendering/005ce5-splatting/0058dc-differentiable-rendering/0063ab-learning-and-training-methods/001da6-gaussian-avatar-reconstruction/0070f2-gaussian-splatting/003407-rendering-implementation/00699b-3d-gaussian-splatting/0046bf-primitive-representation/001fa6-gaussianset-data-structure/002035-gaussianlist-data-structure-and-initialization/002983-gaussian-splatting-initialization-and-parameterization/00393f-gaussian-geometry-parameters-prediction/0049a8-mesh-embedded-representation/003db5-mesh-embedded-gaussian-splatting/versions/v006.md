# Mesh-Embedded Gaussian Splatting

Also called: Gaussian Mesh Splatting, Gaussian-Mesh association

## Overview
Mesh-Embedded Gaussian Splatting is a hybrid 3D representation that defines 3D Gaussians over an explicit triangle mesh to enable large-scale, interactive deformations driven by mesh editing [S1][S2, unofficial]. It solves the problem of coherent motion transfer in 3D Gaussian Splatting (3DGS) by tying Gaussian parameters to mesh geometry via joint refinement, where GS rendering guides adaptive splitting and mesh constraints regularize Gaussian shapes [S1]. It sets itself apart from its siblings by utilizing a reconstructed explicit mesh for initialization and employing specific face-split and normal-guidance strategies to handle large deformations without relying on implicit MLP-based skinning fields [S2, unofficial]. Unlike methods that use MLP-based linear blend skinning (LBS) for motion, this approach controls Gaussian rotation and translation directly by the mesh, enabling compatibility with skeletal animation, blend shapes, and mesh editing [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A canonical triangle mesh (e.g., SMPL-X or FLAME) with vertices $V_i$, per-vertex normals $n_i$, and per-vertex quaternions $q_i$; monocular video frames for training.
*   **Output:** A set of 3D Gaussians parameterized by their embedding on the mesh, capable of real-time rendering in posed states.

**Data Structures:**
Each Gaussian is defined by an embedding tuple $E = \{k, u, v, d\}$ [S2, unofficial]:
*   $k$: The index of the triangle $k$ in the canonical mesh.
*   $(u, v)$: Local barycentric coordinates within triangle $k$.
*   $d$: Normal displacement along the interpolated normal vector.
*   **Pose-invariant properties:** Canonical rotation $\bar{q}$, canonical scale $\bar{s}$, opacity $o$, and color $c$ [S2, unofficial].
*   **Pose-dependent properties:** Derived dynamically from the mesh pose [S2, unofficial].

**Numbered Steps:**

1.  **Initialization:** Initialize Gaussians on the canonical mesh. The embedding point $P$ on triangle $k$ with barycentric coordinates $(u, v)$ is calculated as [S2, unofficial]:
    $$
    P = \mathcal{V}(k, u, v) = u V_1 + v V_2 + (1 - u - v) V_3
    $$
    where $V_1, V_2, V_3$ are the triangle vertices. The interpolated normal $n$ is calculated as [S2, unofficial]:
    $$
    n = \mathcal{N}(k, u, v) = u n_1 + v n_2 + (1 - u - v) n_3
    $$
    where $n_1, n_2, n_3$ are the per-vertex normals.

2.  **Pose Computation:** When the mesh is deformed by animation (e.g., skeletal animation or blend shapes), the posed position $\mu_{pose}$ is obtained by applying a mesh deformation function $\text{Deform}(\cdot)$ to the displaced canonical position [Parent]:
    $$
    \mu_{pose} = \text{Deform}(\mu_{cano} + d \cdot n_{cano})
    $$
    where $\mu_{cano} = P$ and $n_{cano} = n$.

3.  **Rotation and Scale Derivation:**
    *   **Rotation:** The posed rotation $q_{pose}$ is computed by interpolating per-vertex quaternions $q_1, q_2, q_3$ using barycentric weights to get $\delta q$, then combining with the canonical rotation $\bar{q}$ [Parent]:
        $$
        q_{pose} = \delta q * \bar{q}, \quad \delta q = u q_1 + v q_2 + (1 - u - v) q_3
        $$
        The per-vertex quaternions $q_V$ are calculated by area-weighted average from surrounding neighbor triangles [Parent].
    *   **Scale:** The posed scale $s_{pose}$ is derived from the area change of the embedded triangle relative to the canonical state [Parent]:
        $$
        s_{pose} = \left( \frac{A_{pose}}{A_{cano}} \right) \bar{s}
        $$
        where $A_{pose}$ and $A_{cano}$ are the areas of the triangle in the posed and canonical states, respectively.

4.  **Lifted Optimization:** During training, Gaussian parameters and embedding parameters are updated simultaneously [S2, unofficial]. The optimization uses a "lifted" approach where embedding points "walk" on the triangle mesh [S2, unofficial].

5.  **Cross-Triangle Handling:** If an optimization step moves the embedding point across a triangle boundary ($u < 0$, $v < 0$, or $u+v > 1$), the embedding must be re-expressed in the neighboring triangle to maintain differentiability [Parent, S2]. This is handled by re-expressing the barycentric update in the neighboring triangle as if the Gaussian is walking on the mesh [S2, unofficial].

6.  **Adaptation:** The clone and split scheme of 3D Gaussians is adapted to better suit the mesh-embedded representation needs [S2, unofficial].

**Pseudocode:**

```python
def compute_posed_gaussian(embedding, mesh_canonical, mesh_posed, canonical_params):
    """
    Computes the posed position, rotation, and scale for a Gaussian given its embedding.
    
    Args:
        embedding: Tuple (k, u, v, d)
            k: Triangle index in canonical mesh
            u, v: Barycentric coordinates
            d: Normal displacement
        mesh_canonical: Object containing vertices V, normals n, quaternions q for canonical mesh
        mesh_posed: Object containing deformed vertices V', normals n', quaternions q' for posed mesh
        canonical_params: Tuple (q_bar, s_bar, o, c)
            q_bar: Canonical rotation quaternion
            s_bar: Canonical scale
            o: Opacity
            c: Color
            
    Returns:
        Tuple (mu_pose, q_pose, s_pose, o, c)
    """
    k, u, v, d = embedding
    
    # 1. Get canonical triangle vertices and normals
    V1, V2, V3 = mesh_canonical.vertices[k]
    n1, n2, n3 = mesh_canonical.normals[k]
    
    # 2. Compute canonical position and normal (Phong interpolation)
    mu_cano = u * V1 + v * V2 + (1 - u - v) * V3
    n_cano = u * n1 + v * n2 + (1 - u - v) * n3
    
    # 3. Get posed triangle vertices and normals
    V1_p, V2_p, V3_p = mesh_posed.vertices[k]
    n1_p, n2_p, n3_p = mesh_posed.normals[k]
    q1_p, q2_p, q3_p = mesh_posed.quaternions[k]
    
    # 4. Compute posed position
    # Note: Deform function is implicit in the mesh_posed vertices
    mu_pose = u * V1_p + v * V2_p + (1 - u - v) * V3_p + d * n_cano
    
    # 5. Compute posed rotation
    # Interpolate per-vertex quaternions
    delta_q = u * q1_p + v * q2_p + (1 - u - v) * q3_p
    # Combine with canonical rotation
    q_pose = delta_q * canonical_params.q_bar
    
    # 6. Compute posed scale
    # Calculate areas of canonical and posed triangles
    A_cano = triangle_area(V1, V2, V3)
    A_pose = triangle_area(V1_p, V2_p, V3_p)
    
    # Scale is proportional to area change
    s_pose = (A_pose / A_cano) * canonical_params.s_bar
    
    return mu_pose, q_pose, s_pose, canonical_params.o, canonical_params.c

def handle_cross_triangle_update(embedding, gradient, mesh_canonical):
    """
    Handles the case where a gradient update moves the embedding point outside its current triangle.
    Re-expresses the embedding in the neighboring triangle.
    
    Args:
        embedding: Tuple (k, u, v, d)
        gradient: Gradient of the loss with respect to (u, v)
        mesh_canonical: Mesh object with adjacency info
        
    Returns:
        New embedding tuple and adjusted gradient
    """
    k, u, v, d = embedding
    
    # Check if point is outside triangle
    if u < 0 or v < 0 or (u + v) > 1:
        # Find neighboring triangle that contains the point
        # This requires walking on the mesh or using a spatial index
        k_new, u_new, v_new = find_neighboring_triangle(k, u, v, mesh_canonical)
        
        # Adjust gradient to reflect the new coordinate system
        # The gradient needs to be transformed to the new barycentric frame
        # This is a complex operation involving the Jacobian of the coordinate transformation
        # For simplicity, we assume the gradient is re-computed or adjusted based on the new triangle
        gradient = adjust_gradient_for_new_triangle(gradient, k, k_new, u, v, u_new, v_new)
        
        embedding = (k_new, u_new, v_new, d)
        
    return embedding, gradient

def triangle_area(V1, V2, V3):
    """
    Computes the area of a triangle given its vertices.
    """
    # Area = 0.5 * | (V2 - V1) x (V3 - V1) |
    cross_product = cross(V2 - V1, V3 - V1)
    return 0.5 * norm(cross_product)
```

**Parameters:**
*   **Embedding $E$:** $\{k, u, v, d\}$ [S2, unofficial].
*   **Performance:** Achieves over 300 FPS on an NVIDIA RTX 3090 GPU and 30 FPS on an iPhone 13 [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Cross-triangle updates:** Because the embedding point defined in barycentric coordinates is differentiable only inside the corresponding triangle, updates that move the embedding across a triangle boundary must be handled by re-expressing the barycentric update in the neighboring triangle [S2, unofficial]. Failure to handle this causes Gaussians to stick to boundaries and pile up [Parent].
*   **Precision:** Barycentric coordinates are sensitive to numerical precision near triangle edges.

## Subtopics

### [GaussianMesh](11812-gaussianmesh.md)
GaussianMesh is a method that defines 3D Gaussians over an explicit triangle mesh to enable large-scale, interactive deformations driven by mesh editing. It solves the problem of coherent motion transfer in 3D Gaussian Splatting (3DGS) by tying Gaussian parameters to mesh geometry via joint refinement, where GS rendering guides adaptive splitting and mesh constraints regularize Gaussian shapes. It sets itself apart from parent methods by utilizing a reconstructed explicit mesh from calibrated images for initialization and employing specific face-split and normal-guidance strategies to handle large deformations without relying on implicit MLP-based skinning.

## Operating characteristics
*   **Time Complexity:** Real-time rendering is achieved, with over 300 FPS on an NVIDIA RTX 3090 GPU and 30 FPS on an iPhone 13 [S2, unofficial].
*   **Memory Complexity:** Not given in the sources.
*   **Strengths:** Explicit motion control by the mesh allows compatibility with various animation techniques (skeletal animation, blend shapes, mesh editing) [S2, unofficial]. The mesh represents low-frequency motion and surface deformation, while Gaussians capture high-frequency geometry and detailed appearance [S2, unofficial].
*   **Limitations:** Relies on accurate semantic labels or mesh proxies [S1]. Cross-triangle updates require careful handling to maintain differentiability [S2, unofficial].
*   **When to use:** When explicit mesh-based animation and editing are required for 3D Gaussian Splatting, especially for human avatars [S2, unofficial].
*   **When not to use:** When the input geometry is not well-represented by a triangle mesh or when implicit deformation fields are preferred for simplicity [S2, unofficial].

## Background
*   **Origin:** SplattingAvatar, presented by Zhijing Shao et al. [S2, unofficial].
*   **History:** The method builds on 3D Gaussian Splatting [23] and Phong surface interpolation [38]. It addresses the limitations of MLP-based linear blend skinning (LBS) fields for motion in 3DGS [S2, unofficial].
*   **Usage:** The method is ported to Unity for real-time rendering [S2, unofficial]. It is trained from monocular videos for both full-body and head avatars [S2, unofficial].
