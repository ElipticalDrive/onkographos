# FlexGS

Also called: Flexible 3D Gaussian Splatting, Elastic 3D Gaussian Splatting

## Overview
FlexGS is an elastic inference method for 3D Gaussian Splatting (3DGS) that enables a single trained model to adapt to varying computational constraints at inference time by selecting and transforming a subset of Gaussians based on a desired model size ratio, without requiring additional fine-tuning [S1]. It solves the problem that standard 3DGS models require significant GPU memory, limiting their use on devices with restricted resources, and that previous compression methods required costly retraining or separate model generation for each target hardware constraint [S1]. Unlike post-hoc compression methods that use fixed heuristics to retain Top-K Gaussians and require separate runs for each ratio, FlexGS jointly trains a learnable module to adaptively select points based on attributes and the desired ratio during training [S1].

## How it works
FlexGS consists of two main modules: a learnable Gaussian selector and a ratio-dependent Gaussian transformation field [S1]. The selector adaptively chooses a subset of Gaussians based on a target ratio, while the transformation field displaces the selected Gaussians to compensate for missing details caused by the reduction in Gaussian count [S1].

### Inputs and Outputs
*   **Input:** A trained 3DGS model consisting of $N$ Gaussians, each characterized by position $\mathbf{X}$, scaling vector $\mathbf{s}$, rotation quaternion $\mathbf{q}$, opacity $\alpha$, and spherical harmonics coefficients $\mathbf{SH}$ [S1]. A target ratio $e \in (0, 1]$ representing the desired percentage of remaining Gaussians [S1].
*   **Output:** A rendered image using a subset of $K = eN$ Gaussians, where the selected Gaussians have transformed parameters to maintain visual fidelity [S1].

### Data Structures
Each Gaussian $i$ is defined by:
*   Mean position $\mathbf{X} \in \mathbb{R}^3$ [S1].
*   Scaling vector $\mathbf{s} \in \mathbb{R}^3$ [S1].
*   Rotation quaternion $\mathbf{q} \in \mathbb{R}^3$ (used to construct rotation matrix $\mathbf{R}$) [S1].
*   Opacity $\alpha \in \mathbb{R}$ [S1].
*   Color $\mathbf{c}$ defined by spherical harmonics coefficients $\mathbf{SH} \in \mathbb{R}^{(d+1)}$, where $d$ is the SH degree [S1].

The covariance matrix $\Sigma$ is decomposed into scaling matrix $\mathbf{S}$ and rotation matrix $\mathbf{R}$ as:
$$ \Sigma = \mathbf{R} \mathbf{S} \mathbf{S}^\top \mathbf{R}^\top $$
The Gaussian function is:
$$ G(\mathbf{X}) = e^{-\frac{1}{2} \mathbf{X} \Sigma^{-1} \mathbf{X}} $$
[ S1 ]

### Steps
1.  **Gaussian Selection:** For a 3DGS with $N$ Gaussians and a target ratio $e$, the method predicts a binary scaler $\lambda_i$ for each Gaussian $i$, where $\lambda_i = 1$ if selected and $0$ if not [S1]. The selection must satisfy the constraint:
    $$ \sum_{i=1}^{N} \lambda_i = eN $$
    [ S1 ]
    The selection is performed by a learnable module that takes Gaussian attributes and the ratio $e$ as input, using a Gumbel-Softmax approximation to allow gradient-based optimization of the discrete selection variables [S1].

2.  **Gaussian Transformation:** For the selected Gaussians ($\lambda_i = 1$), a ratio-dependent transformation field adjusts their parameters (e.g., position, scale) to compensate for the missing details from the unselected Gaussians [S1]. This field is conditioned on the target ratio $e$ [S1].

3.  **Rendering:** The transformed and selected Gaussians are rendered using standard 3DGS differentiable splatting [S1]. The color $C$ for a pixel is computed by blending $N$ ordered points overlapping the pixel:
    $$ C = \sum_{i \in N} c_i \alpha_i \prod_{j=1}^{i-1} (1 - \alpha_j) $$
    [ S1 ]

### Parameters
*   **Target Ratio ($e$):** The desired percentage of remaining Gaussians. Typical values depend on the hardware constraints, ranging from high fidelity (e.g., $e=1.0$) to extreme compression (e.g., $e=0.01$) [S1].
*   **Number of Gaussians ($N$):** The total number of Gaussians in the trained model [S1].

### Edge Cases and Pitfalls
*   **Extreme Compression:** Fixed heuristic selection rules may fail to generalize in extreme cases, such as when selecting only 1% of Gaussians, because importance scores must be frequently re-computed as Gaussian attributes evolve during training [S1]. FlexGS addresses this by jointly training the selector during the initial training phase [S1].
*   **Precision:** The binary selection variable $\lambda_i$ is discrete, which makes traditional gradient descent ineffective. FlexGS uses a Gumbel-Softmax approximation during training to handle this [S1].

## Operating characteristics
*   **Time Complexity:** Inference time is proportional to the number of selected Gaussians $K = eN$. Since $K$ can be significantly smaller than $N$, rendering speed increases as $e$ decreases [S1].
*   **Memory Complexity:** Memory usage is proportional to $K \times \text{size\_per\_gaussian}$. This allows FlexGS to fit models into memory-constrained devices like smartphones and standalone VR headsets [S1].
*   **Strengths:**
    *   **Elastic Inference:** A single trained model can adapt to any desired model size ratio without retraining or fine-tuning [S1].
    *   **Adaptive Selection:** The learnable selector adapts to the evolving Gaussian attributes during training, providing better generalization than fixed heuristics [S1].
    *   **Compensation:** The transformation field helps maintain visual quality even at low ratios by adjusting selected Gaussians [S1].
*   **Limitations:**
    *   Requires a specific training phase to learn the selector and transformation fields [S1].
    *   Performance at extreme compression ratios (e.g., 1%) may still be challenging, though better than heuristics [S1].
*   **When to Use:** When deploying 3DGS on diverse hardware with varying computational constraints (e.g., mobile, VR) and a single model needs to support multiple quality levels [S1].
*   **When Not to Use:** When the highest possible fidelity is required for all scenarios and memory is not a constraint, standard 3DGS may be simpler [S1].

## Background
FlexGS was introduced by Hengyu Liu, Yuehao Wang, Chenxin Li, Ruisi Cai, Kevin Wang, Wuyang Li, Pavlo Molchanov, Peihao Wang, and Zhangyang Wang from The Chinese University of Hong Kong, University of Texas at Austin, and Nvidia [S1]. It was published in CVPR 2025 (arXiv:2506.04174v1, June 4, 2025) [S1]. The work addresses the limitations of standard 3DGS in terms of memory overhead and the lack of adaptability for different devices, building on the foundation of 3D Gaussian Splatting [S1].
