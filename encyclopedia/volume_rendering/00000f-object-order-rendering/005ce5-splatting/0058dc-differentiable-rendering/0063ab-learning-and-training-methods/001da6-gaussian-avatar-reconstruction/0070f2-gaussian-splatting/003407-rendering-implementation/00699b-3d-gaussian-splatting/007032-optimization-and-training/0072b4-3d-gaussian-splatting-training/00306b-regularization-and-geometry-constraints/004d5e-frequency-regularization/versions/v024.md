# Frequency Regularization

Also called: Amplitude and Phase Discrepancy Regularization, Improved Optimization via Regularization

## Overview
Frequency Regularization (FR) is a training-time constraint used in 3D Gaussian Splatting to mitigate over-reconstruction and improve Gaussian densification by minimizing the discrepancy between the frequency spectrum of rendered images and ground truth [S2]. Unlike naive pixel-wise L1 loss, which yields small gradients in over-reconstructed regions and fails to trigger densification, FR explicitly disentangles frequency components to increase pixel gradients in these areas, thereby guiding Gaussians toward high-frequency regions [S2][S3, unofficial]. It sets itself apart from sibling methods like [Smoothed 2D Supervision](7213-smoothed-2d-supervision.md) by operating in the Fourier domain rather than the spatial domain, and from [FreGS](9212-fregs.md) by serving as the foundational mechanism that FreGS extends with progressive annealing.

## How it works
**Inputs and Outputs:**
*   **Inputs:** Rendered image $\hat{I} \in \mathbb{R}^{H \times W \times C}$, Ground truth image $I \in \mathbb{R}^{H \times W \times C}$.
*   **Outputs:** Scalar regularization loss $L_{FR} = d_a + d_p$, where $d_a$ is amplitude discrepancy and $d_p$ is phase discrepancy.

**Data Structures:**
*   **Frequency Domain:** Complex-valued matrices $F(u, v)$ and $\hat{F}(u, v)$ of size $H \times W$ per channel.
*   **Amplitude/Phase:** Real-valued matrices $|F(u, v)|$ and $\angle F(u, v)$ of size $H \times W$.

**Steps:**
1.  **Fourier Transform:** Compute the 2D Discrete Fourier Transform (DFT) for the rendered image $\hat{I}$ and ground truth $I$. For a single channel, the frequency value $F(u, v)$ at coordinates $(u, v)$ is calculated as:
    $$F(u, v) = \sum_{x=0}^{H-1} \sum_{y=0}^{W-1} I(x, y) \cdot e^{-i2\pi(\frac{u}{H}x + \frac{v}{W}y)}$$
    where $(x, y)$ are spatial coordinates, $(u, v)$ are frequency coordinates, and $I(x, y)$ is the pixel intensity [S2].
2.  **Decomposition:** Decompose the complex frequency values into amplitude and phase:
    $$|F(u, v)| = \sqrt{\text{Re}(u, v)^2 + \text{Im}(u, v)^2}$$
    $$\angle F(u, v) = \arctan\left(\frac{\text{Im}(u, v)}{\text{Re}(u, v)}\right)$$
    where $\text{Re}$ and $\text{Im}$ are the real and imaginary components of $F(u, v)$ [S2].
3.  **Discrepancy Calculation:** Compute the total amplitude discrepancy $d_a$ and total phase discrepancy $d_p$ using the Euclidean metric averaged over all pixels and channels:
    $$d_a = \sqrt{\frac{1}{HW} \sum_{x=0}^{H-1} \sum_{y=0}^{W-1} (|F(u, v)| - |\hat{F}(u, v)|)^2}$$
    $$d_p = \sqrt{\frac{1}{HW} \sum_{x=0}^{H-1} \sum_{y=0}^{W-1} (\angle F(u, v) - \angle \hat{F}(u, v))^2}$$
    where $F$ and $\hat{F}$ represent the ground truth and rendered frequency values respectively [S2].
4.  **Loss Aggregation:** The final frequency regularization loss is the sum of the discrepancies: $L_{FR} = d_a + d_p$ [S2].

**Parameters:**
*   **Optimizer:** Adam optimizer [S2].
*   **Framework:** PyTorch [S2].
*   **Rasterization:** Custom CUDA kernels from 3D-GS are retained [S2].
*   **Typical Values:** Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Over-reconstruction Bias:** Naively applying FR without distinguishing between low and high frequencies can bias the optimization toward undesirable artifacts and restrict Gaussian densification [S2]. This is addressed in variants like FreGS via frequency annealing.
*   **Gradient Vanishing:** In regions that are already well-reconstructed, the frequency gradient may be small, similar to L1 loss, but FR is specifically noted for increasing gradients in *over-reconstructed* regions where L1 fails [S2].

**Pseudocode:**
```python
import torch
import torch.fft

def frequency_regularization_loss(rendered_image: torch.Tensor, ground_truth: torch.Tensor) -> torch.Tensor:
    """
    Computes the Frequency Regularization loss based on amplitude and phase discrepancy.
    
    Args:
        rendered_image: Tensor of shape (H, W, C) or (B, H, W, C).
        ground_truth: Tensor of shape (H, W, C) or (B, H, W, C).
        
    Returns:
        Scalar loss tensor.
    """
    # Ensure inputs are float32 for FFT stability
    rendered = rendered_image.float()
    ground = ground_truth.float()
    
    # Compute 2D FFT. torch.fft.fft2 expects (..., H, W)
    # If input is (B, H, W, C), we need to move C to the last dimension or handle accordingly.
    # Assuming standard (H, W, C) or (B, H, W, C) layout where C is last.
    # FFT is computed over spatial dimensions H and W.
    
    # Shift zero frequency to center is not strictly necessary for magnitude/phase diff,
    # but standard DFT definition in source [S2] does not explicitly mention shift.
    # We use standard FFT.
    
    F_rendered = torch.fft.fft2(rendered, dim=(-2, -1))
    F_ground = torch.fft.fft2(ground, dim=(-2, -1))
    
    # Compute Amplitude
    amp_rendered = torch.abs(F_rendered)
    amp_ground = torch.abs(F_ground)
    
    # Compute Phase
    phase_rendered = torch.angle(F_rendered)
    phase_ground = torch.angle(F_ground)
    
    # Compute Discrepancies
    # Source [S2] defines d_a and d_p as RMS errors over H*W.
    # We average over spatial dimensions and channels.
    
    # Amplitude discrepancy
    # Note: Source formula sums over x,y. We sum over H, W, C.
    # The source divides by HW. If C > 1, we typically average over C as well for a scalar loss.
    # Assuming the source implies per-channel or averaged. 
    # Standard practice is to average over all dimensions.
    
    amp_diff_sq = (amp_rendered - amp_ground) ** 2
    d_a = torch.sqrt(torch.mean(amp_diff_sq))
    
    phase_diff_sq = (phase_rendered - phase_ground) ** 2
    d_p = torch.sqrt(torch.mean(phase_diff_sq))
    
    return d_a + d_p
```

## Subtopics

### FreGS
FreGS (Frequency Gaussian Splatting) is a variant that extends basic FR by introducing **progressive frequency regularization** (frequency annealing). It applies low-pass and dynamic high-pass filters in the Fourier space to gradually leverage low-to-high frequencies, achieving coarse-to-fine Gaussian densification and mitigating the artifacts caused by naive FR. It is chosen when over-reconstruction is severe and standard FR leads to biased artifacts. Link: [FreGS](9212-fregs.md).

### DWTGS
DWTGS rethinks frequency regularization for **sparse-view** 3DGS by applying a **Discrete Wavelet Transform (DWT)** instead of DFT. It penalizes the loss in the wavelet domain to encourage sharper edges, addressing the specific challenges of limited input views. It is chosen for sparse-view reconstruction scenarios where edge sharpness is critical. Link: [DWTGS](9212-fregs.md) (Note: DWTGS is a minor variant listed under FreGS in the source structure, but distinct in method).

## Operating characteristics
*   **Time Complexity:** The addition of 2D FFT and inverse operations per iteration increases computational overhead compared to pure spatial L1 loss. FFT complexity is $O(N \log N)$ where $N=H \times W$.
*   **Memory Complexity:** Requires storing complex frequency matrices for both rendered and ground truth images, doubling the temporary memory for frequency domain data per channel.
*   **Measured Performance:** In the 'Bicycle' scene, FR significantly increased pixel gradients in over-reconstruction regions compared to the baseline (w/o FR) [S2]. It allows for adaptive densification where L1 loss fails [S2].
*   **Strengths:** Effectively identifies over-reconstructed regions; prevents the creation of redundant Gaussians in well-reconstructed areas; improves convergence in high-frequency details.
*   **Limitations:** Naive application can cause artifacts if low/high frequencies are not annealed; computationally more expensive than spatial losses.
*   **When to use:** When the scene exhibits over-reconstruction or when Gaussian densification stalls in specific regions due to low spatial gradients.
*   **When not to use:** In very low-resolution settings where frequency domain analysis may be noisy, or if computational budget is extremely tight and spatial losses suffice.

## Background
Frequency Regularization was introduced to address the limitations of pixel-wise L1 loss in 3D Gaussian Splatting optimization, specifically the issue of over-reconstruction and insufficient gradient signals for densification [S2]. The method was formalized in the **FreGS** paper (CVPR 2024) [S2]. It builds on the observation that frequency components (amplitude and phase) capture different image information and can better guide the optimization landscape than spatial errors alone [S2]. It is part of the broader family of regularization techniques aimed at improving geometric fidelity and visual quality in Gaussian Avatar Reconstruction [S1][S3, unofficial].
