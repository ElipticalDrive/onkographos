# Distributed 3DGS Training Loop with Adaptive Workload Division

Also called: Batched Distributed 3DGS Training, Grendel-GS Training Pipeline

## Overview
This method implements a distributed training workflow for 3D Gaussian Splatting that batches camera selection, divides rendering workloads across multiple GPUs using an adaptive strategy history, synchronizes losses, and schedules densification and spherical harmonics (SH) degree updates [S1, unofficial]. It differs from standard gradient accumulation by optionally scaling gradients by batch size to avoid explicit accumulation buffers, and it dynamically balances computational load based on historical rendering statistics [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A dataset of training images and camera poses, a set of 3D Gaussians $\mathcal{G}$, a distributed process group (rank and world size), and configuration arguments (`args`).
*   **Outputs:** Optimized Gaussian parameters, strategy history logs, and periodic checkpoints.

**Data Structures:**
*   `batched_screenspace_pkg`: A dictionary containing rendering state. Key field: `"batched_cuda_args"`, a list of CUDA argument structures. Each structure contains a `"stats_collector"` field used for adaptive workload division [S1, unofficial].
*   `batched_losses`: A tensor of shape $(N, 2)$, where $N$ is the batch size. Index 0 holds the first loss component (L1), and index 1 holds the second loss component (used for DSSIM calculation) [S1, unofficial].
*   `strategy_history`: A log of past workload divisions and their associated performance statistics, used to adapt future assignments [S1, unofficial].

**Parameters:**
*   `args.bsz`: Batch size per iteration step. Controls the loop range and the divisor for gradient scaling [S1, unofficial].
*   `args.lambda_dssim`: Weight for the DSSIM loss component in the combined loss calculation. Default value not specified in sources [S1, unofficial].
*   `args.lr_scale_mode`: String controlling gradient scaling. If not equal to `"accumu"`, gradients are explicitly divided by `args.bsz` before the optimizer step [S1, unofficial].
*   `args.local_sampling`: Boolean flag. If true, enables distributed camera index gathering across GPUs using `torch.distributed.all_gather_into_tensor` [S1, unofficial].
*   `args.save_iterations` / `args.checkpoint_iterations`: Lists of iteration numbers triggering Gaussian saves or full checkpoint saves, respectively [S1, unofficial].
*   `args.backend`: String specifying the rendering backend (e.g., `"gsplat"` or default) [S1, unofficial].

**Numbered Steps:**

1.  **Initialization:** Initialize the training loop from `start_from_this_iteration` to `opt_args.iterations` with a step size of `args.bsz`. Initialize an exponential moving average (EMA) loss variable `ema_loss_for_log` to `None`. Initialize a `strategy_history` data structure [S1, unofficial].

2.  **Iteration Loop:** For each iteration $k$ from `start_from_this_iteration` to `opt_args.iterations` with step `args.bsz`:
    a.  **Progress Logging:** If `iteration // args.bsz % 30 == 0`, log the EMA loss to the progress bar [S1, unofficial].
    b.  **Hyperparameter Updates:** Update the learning rate and increment the trained batch counter. Clear timing accumulators. Start an NVTX profiling range if enabled [S1, unofficial].
    c.  **SH Degree Update:** Check if the current iteration is a multiple of 1000 batches. If so, upscale the spherical harmonics degree by one level using `utils.check_update_at_this_iter(iteration, args.bsz, 1000, 0)` [S1, unofficial].
    d.  **Camera Selection:**
        i.  If `args.local_sampling` is true: Assert that `args.bsz` is divisible by `utils.WORLD_SIZE`. Gather local camera indices across all GPUs using `torch.distributed.all_gather_into_tensor`. Convert indices to numpy and fetch camera objects [S1, unofficial].
        ii. Otherwise: Fetch batched cameras directly via `train_dataset.get_batched_cameras(args.bsz)` [S1, unofficial].
    e.  **Workload Division Strategy Initialization:** Call `start_strategy_final(batched_cameras, strategy_history)` to compute `batched_strategies` and a mapping `gpuid2tasks` (mapping GPU IDs to assigned camera tasks) [S1, unofficial].
    f.  **Data Loading:** Load camera data from CPU to all GPUs using `load_camera_from_cpu_to_all_gpu(batched_cameras, batched_strategies, gpuid2tasks)` [S1, unofficial].
    g.  **Preprocessing:** Preprocess 3D Gaussians and perform all-to-all communication. If `args.backend == "gsplat"`, call `gsplat_distributed_preprocess3dgs_and_all2all_final`; otherwise, call `distributed_preprocess3dgs_and_all2all_final` [S1, unofficial].
    h.  **Rendering:** Render images and extract compute locations. Call `gsplat_render_final` or `render_final` with `batched_screenspace_pkg` and `batched_strategies`. Extract `batch_statistic_collector` from `batched_screenspace_pkg["batched_cuda_args"]` [S1, unofficial].
    i.  **Loss Computation:** Compute the loss by calling `batched_loss_computation` with rendered images, cameras, compute locations, strategies, and statistic collectors. Store results in `batched_losses` [S1, unofficial].
    j.  **Backpropagation:** Execute the backward pass: `loss_sum.backward()` [S1, unofficial].
    k.  **Strategy Update:** Update the workload division strategy by calling `finish_strategy_final(batched_cameras, strategy_history, batched_strategies, batch_statistic_collector)` to record performance for future adaptive decisions [S1, unofficial].
    l.  **Loss Synchronization:** Synchronize losses across all GPUs using `dist.all_reduce(batched_losses, op=dist.ReduceOp.SUM, group=utils.DEFAULT_GROUP)` [S1, unofficial].
    m.  **EMA Update:** If `ema_loss_for_log` is `None`, set it to the mean of `batched_loss_cpu`. Otherwise, update using the formula:
        $$ EMA = 0.6 \cdot EMA + 0.4 \cdot \text{mean}(batched\_loss\_cpu) $$
        [S1, unofficial].
    n.  **Evaluation:** If the current iteration matches `testing_iterations`, trigger evaluation. Log validation configurations for test and train sets [S1, unofficial].
    o.  **Densification:** Perform densification by calling `gsplat_densification` or `densification` with the current iteration, scene, gaussians, and screenspace package [S1, unofficial].
    p.  **Saving:**
        i.  If the iteration is in `args.save_iterations`, save the current Gaussians.
        ii. If `args.save_strategy_history` is true, write `strategy_history` to JSON.
        iii. If the iteration is in `args.checkpoint_iterations`, create a directory (Rank 0 only), synchronize all ranks via `torch.distributed.barrier`, and save `gaussians.capture()` and the iteration number to a `.pth` file [S1, unofficial].

3.  **Gradient Scaling:** If `args.lr_scale_mode != "accumu"`, explicitly divide gradients by `args.bsz` before the optimizer step to scale them correctly for the batch size [S1, unofficial].

**Formulas:**
*   **Combined Batch Loss:**
    $$ L_{batch} = (1 - \lambda_{dssim}) \cdot L_{0} + \lambda_{dssim} \cdot (1 - L_{1}) $$
    Where $L_{0}$ is the first loss component (L1), $L_{1}$ is the second loss component (D-SSIM related), and $\lambda_{dssim}$ is `args.lambda_dssim` [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Local Sampling Constraint:** When `args.local_sampling` is enabled, `args.bsz` must be divisible by `utils.WORLD_SIZE`. The implementation asserts this condition: `assert args.bsz % utils.WORLD_SIZE == 0` [S1, unofficial].
*   **Checkpoint Race Conditions:** Saving checkpoints requires rank synchronization to prevent race conditions during directory creation. Rank 0 creates the folder, and all ranks must call `torch.distributed.barrier` before saving [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The method reduces per-GPU rendering time by distributing camera batches. The adaptive workload division aims to balance load based on historical complexity, potentially reducing stragglers compared to static distribution.
*   **Memory Complexity:** Memory usage scales with the number of Gaussians and the batch size. By distributing cameras, it allows larger effective batch sizes than single-GPU training, limited by total system memory and interconnect bandwidth.
*   **Performance:** Sources indicate throughput improvements with increased GPU counts (e.g., 4 GPUs vs 1 GPU) and batch sizes, though specific metrics depend on scene complexity and resolution [S1, unofficial].
*   **Strengths:** Enables training on large scenes with many Gaussians that do not fit on a single GPU; adaptive strategy reduces load imbalance.
*   **Limitations:** Requires complex inter-GPU communication (all-to-all); sensitive to network latency; requires careful tuning of batch size relative to world size.

## Background
This method originates from the Grendel-GS project, a distributed training pipeline for 3D Gaussian Splatting [S1, unofficial]. It addresses the scalability limitations of single-GPU training by introducing adaptive workload division and efficient distributed communication primitives.
