# Primitives Growth Control

Also called: Budget control, Growth control

## Overview
Primitives Growth Control is a constraint mechanism applied during the densification phase of 3D Gaussian Splatting to prevent unbounded growth of the primitive count, which can lead to out-of-memory errors [S1]. It sets itself apart from standard Adaptive Densification (ADC) by enforcing a hard upper bound on the total number of Gaussians and limiting the rate of new primitive creation per step, ensuring stable memory usage even when densification remains active for extended training periods [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** The current set of $N$ 3D Gaussian primitives, their associated densification scores $E_k$, and the target maximum primitive budget $N_{\max}$ [S1].
*   **Output:** A filtered subset of primitives eligible for cloning or splitting, capped such that the total count does not exceed $N_{\max}$ [S1].

**Data Structures:**
*   **Primitive Set:** A list of $N$ objects, each containing position $\mathbf{p}$, covariance $\mathbf{S}$ (or scale and rotation), opacity $\alpha$, and a scalar densification score $E_k$ [S1].

**Parameters:**
*   **Growth Fraction ($f$):** The maximum fraction of existing primitives allowed to be added in a single densification step [S1]. Typical value: $0.05$ (5%) [S1].
*   **Max Primitives Budget ($N_{\max}$):** The absolute upper limit on the number of primitives [S1]. Typically set to the median number of primitives generated by the baseline 3D Gaussian Splatting method on the same scene, or the peak count reached during unconstrained training [S1].

**Steps:**
1.  **Identify Candidates:** Evaluate all current primitives to determine which ones meet the criteria for densification (e.g., $E_k > 0.1$) [S1]. Let this set of candidates be $C$.
2.  **Calculate Allowance:** Compute the maximum number of new primitives allowed in this step based on the growth fraction:
    $$ N_{\text{allow}} = \lfloor f \times N \rfloor $$
    where $N$ is the current number of primitives [S1].
3.  **Check Budget:** Determine the remaining budget:
    $$ N_{\text{rem}} = N_{\max} - N $$
    The effective limit for new primitives is:
    $$ N_{\text{limit}} = \min(N_{\text{allow}}, N_{\text{rem}}) $$
4.  **Rank and Select:** If the number of candidates $|C|$ exceeds $N_{\text{limit}}$, retain only the candidates with the highest densification scores $E_k$ [S1]. Otherwise, select all candidates.
5.  **Execute Densification:** For each selected candidate, perform the standard cloning or splitting operation as defined in the parent method [Density Control and Densification](5337-density-control-and-densification.md) [S1, G]. Primitives not selected are left unchanged [G].

**Pseudocode:**
```python
def primitives_growth_control(primitives, scores, N_max, growth_fraction=0.05, threshold=0.1):
    """
    primitives: List of Gaussian primitives.
    scores: List of float densification scores E_k corresponding to each primitive.
    N_max: Maximum allowed number of primitives.
    growth_fraction: Fraction of current primitives allowed to be added per step.
    threshold: Minimum score E_k required to be considered a candidate.
    """
    N = len(primitives)
    N_allow = int(growth_fraction * N)
    N_rem = N_max - N
    N_limit = min(N_allow, N_rem)
    if N_limit <= 0:
        return []
    candidates = [(i, s) for i, s in enumerate(scores) if s > threshold]
    candidates.sort(key=lambda x: x[1], reverse=True)
    selected_indices = [idx for idx, _ in candidates[:N_limit]]
    return selected_indices
```

**Edge Cases and Pitfalls:**
*   **Zero Budget:** If $N$ reaches $N_{\max}$, $N_{\text{rem}}$ becomes $0$, and no further densification occurs [S1].
*   **Score Ties:** If multiple candidates have identical scores, the selection is arbitrary unless a secondary tie-breaker (e.g., index) is defined [G].
*   **Dynamic $N_{\max}$:** $N_{\max}$ is typically static per scene, derived from baseline statistics [S1].

## Subtopics

### [DashGaussian Primitive Growth Control](15744-dashgaussian-primitive-growth-control.md)
DashGaussian Primitive Growth Control is a densification scheme that limits the final number of 3D Gaussian primitives ($N_{GS}$) by combining a threshold-based selection with a top-$k$ selection, preventing primitive explosion while maintaining reconstruction quality. It sets itself apart from standard 3D Gaussian Splatting densification by introducing a primitive budget upper-bound ($P_{fin}$) and a scheduler that dynamically constrains growth in both early low-resolution (LR) and late high-resolution (HR) optimization stages. Choose it when strict memory caps are required across multi-resolution training pipelines.

### Adaptive Control of Primitives
Adaptive Control of Primitives is a triangle-based variant that dynamically adjusts the primitive set to balance reconstruction fidelity with a compact budget [S2, unofficial]. To avoid overly large primitives that compromise high-frequency detail, it periodically subdivides edges whose view-space length exceeds a prescribed fraction of the image height (1/5 in experiments) [S2, unofficial]. This encourages approximately uniform view-space edge lengths and improves the effective use of texture resolution [S2, unofficial]. Conversely, it enforces the target primitive count by pruning triangles with low pixel coverage across the training views until the desired budget is met [S2, unofficial]. In practice, edge splitting and triangle removal are performed every 100 iterations [S2, unofficial]. For edge splitting, view-space edge lengths are computed on a randomly sampled subset of 20 training views to reduce overhead [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources [G].
*   **Memory Complexity:** Not given in the sources [G].
*   **Performance:** Ensures stable memory usage during long training runs (e.g., 27k iterations vs. 15k in standard 3DGS) without significant quality loss [S1].
*   **Strengths:** Prevents out-of-memory errors; allows extended training for better convergence; simple to implement [S1].
*   **Limitations:** May prematurely stop densification in complex regions if $N_{\max}$ is set too conservatively; requires tuning $N_{\max}$ based on baseline runs [S1].

## Background
Primitives Growth Control was introduced in "Revising Densification in Gaussian Splatting" to address the issue of unpredictable primitive growth in standard Adaptive Densification Control (ADC) [S1]. The authors observed that while ADC stops after 15k iterations in standard 3DGS, keeping it active for longer (e.g., 27k) leads to memory issues without a cap [S1]. The method was developed to enable stable, long-duration training by combining a fixed growth fraction with a global budget limit [S1].
