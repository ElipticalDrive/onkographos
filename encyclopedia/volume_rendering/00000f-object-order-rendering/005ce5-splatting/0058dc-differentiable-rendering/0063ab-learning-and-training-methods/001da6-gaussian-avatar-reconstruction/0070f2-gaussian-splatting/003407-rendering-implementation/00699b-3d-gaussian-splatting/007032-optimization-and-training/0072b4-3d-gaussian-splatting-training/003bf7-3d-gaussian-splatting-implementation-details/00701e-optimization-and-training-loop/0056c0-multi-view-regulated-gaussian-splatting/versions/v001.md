# Multi-View Regulated Gaussian Splatting

Also called: Multi-View Regulated Training, Multi-view Regulated Learning, Multi-view gradient aggregation

## Overview
Multi-View Regulated Gaussian Splatting (MVGS) is a training optimization strategy for 3D Gaussian Splatting that imposes multi-view coherent (MVC) constraints throughout the optimization process to enhance multi-view consistency and ensure smoother gradient updates [S1]. It addresses the unstable gradients and suboptimal rendering quality caused by the single-view optimization paradigms typical in existing Gaussian-based methods [S1]. Unlike single-view training where only partial Gaussians are updated and gradients may conflict with physical restrictions, MVGS jointly updates 3D Gaussians observed by multiple views, leading to stable gradients and better performance [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $N$ 3D Gaussians $\mathcal{G} = \{\theta_i\}_{i=1}^N$ initialized from Structure-from-Motion (SfM) point clouds, and a set of $M$ training views (images) with corresponding camera poses.
*   **Output:** Optimized 3D Gaussian parameters $\theta_i$ that minimize the multi-view reconstruction loss.

**Data Structures:**
Each 3D Gaussian $\theta_i$ is parameterized by:
*   Position $\mu_i \in \mathbb{R}^3$.
*   Covariance $\Sigma_i \in \mathbb{S}^{3++}$ (symmetric positive-definite matrix), often represented via a rotation matrix $R_i$ and scaling vector $s_i$ such that $\Sigma_i = R_i S_i S_i^T R_i^T$ [S1].
*   View-dependent color $c_i \in \mathbb{R}^3$, represented using spherical harmonics basis $\psi(\omega): \mathbb{S}^2 \to \mathbb{R}^3$ where $\omega$ is the view direction [S1].
*   Opacity $o_i \in [0, 1]$ controlling light transmission [S1].

**Rendering Equation:**
The color $C$ of a pixel is computed via alpha blending [S1]:
$$
C = \sum_{i=1}^N c_i \alpha_i \prod_{j=1}^{i-1}(1-\alpha_j)
$$
where the opacity $\alpha_i$ of the $i$-th Gaussian projected onto the pixel is:
$$
\alpha_i = o_i \exp \left (-\frac {1}{2}\Delta x_i^T\Sigma_i^{-1}\Delta x_i\right )
$$
and $\Delta x_i = x_i - \mu_i$ denotes the positional offset from the Gaussian position to the sampled point $x_i$ [S1].

**Algorithm Steps:**
The method consists of three core components: Multi-View Regulated Learning (MVRL), Cross-Intrinsic Guidance (CIG), and Multi-View Cross-Ray Densification.

1.  **Initialization:** Initialize 3D Gaussians from SfM point clouds [S1].
2.  **Cross-Intrinsic Guidance (CIG):**
    *   Train from low-resolution to high-resolution [S1].
    *   In the low-resolution phase, employ more multi-view images to capture global/coarse appearances [S1].
    *   Initialize finer-scale Gaussians from coarsely estimated ones rather than optimizing from scratch [S1].
3.  **Multi-View Regulated Training (MVRL) Loop:**
    *   For each optimization iteration, select $M$ training views [S1].
    *   Compute the loss $L_m$ for each view $m$ using the standard 3DGS loss formulation: $\mathcal{L} = (1-\lambda ) \mathcal{L}_1 + \lambda \mathcal{L}_\text {D-SSIM}$, where $\mathcal{L}_1$ is the mean absolute error and $\mathcal{L}_\text {D-SSIM}$ is the D-SSIM loss [S1].
    *   Compute the gradient chain by summing the gradients of the Gaussian primitive parameters $\theta$ (position $\mu_i$, covariance $\Sigma_i$, opacity $o_i$, color $c_i$) across all $M$ views [S1]:
        $$
        \frac {\partial \mathcal {L}_{\text {MV}}}{\partial \boldsymbol {\theta }} = \sum _{m=1}^M\frac {\partial \mathcal {L}_m}{\partial \boldsymbol {\theta }}
        $$
    *   **Crucial Detail:** Do not average the gradient; sum it to increase gradient magnitude for jointly observed Gaussians [S1]. This is equivalent to optimizing the summed multi-view loss and adaptively increases the effective learning rate for Gaussians observed by multiple views [S1].
    *   Update the Gaussian parameters $\theta$ using the summed gradient [S1].
4.  **Multi-View Cross-Ray Densification:**
    *   When input views exhibit minimal overlap, apply multi-view augmented densification to enhance 3D Gaussians [S1].
    *   In overlapped 3D space where rays from multiple views intersect, apply cross-ray densification to split Gaussians dynamically [S1]. This accommodates drastic viewpoint variations and improves multi-view consistency [S1].

**Pseudocode:**

```python
def mvgs_training(gaussians, training_views, num_iterations, M=4):
    """
    MVGS Training Loop.
    gaussians: List of Gaussian objects with attributes mu, Sigma, c, o.
    training_views: List of view data (image, camera pose).
    num_iterations: Total number of optimization steps.
    M: Number of views to aggregate per iteration.
    """
    for iteration in range(num_iterations):
        # 1. Select M training views for this iteration
        selected_views = sample_views(training_views, M)
        
        # Initialize summed gradient accumulator
        summed_gradients = {
            'mu': np.zeros_like(gaussians[0].mu),
            'Sigma': np.zeros_like(gaussians[0].Sigma),
            'c': np.zeros_like(gaussians[0].c),
            'o': np.zeros_like(gaussians[0].o)
        }
        
        # 2. Compute gradients for each selected view
        for view in selected_views:
            # Render image from current Gaussians for this view
            rendered_image = render_gaussians(gaussians, view.camera_pose)
            
            # Compute loss L_m (L1 + D-SSIM)
            loss_m = compute_loss(rendered_image, view.target_image)
            
            # Compute gradients dL_m / d_theta for all Gaussians
            # Note: Only Gaussians contributing to the rendered pixels have non-zero gradients
            gradients_m = compute_gradients(loss_m, gaussians, view.camera_pose)
            
            # 3. Sum gradients (do not average)
            for i in range(len(gaussians)):
                if gradients_m[i] is not None:
                    summed_gradients['mu'][i] += gradients_m[i]['mu']
                    summed_gradients['Sigma'][i] += gradients_m[i]['Sigma']
                    summed_gradients['c'][i] += gradients_m[i]['c']
                    summed_gradients['o'][i] += gradients_m[i]['o']
        
        # 4. Update Gaussians using summed gradients
        # Apply optimizer step (e.g., Adam) with summed_gradients
        update_gaussians(gaussians, summed_gradients, learning_rate)
        
        # 5. Densification (if applicable)
        if should_densify(iteration):
            # Apply multi-view cross-ray densification
            gaussians = multi_view_cross_ray_densification(gaussians, training_views)
            
        # 6. Cross-Intrinsic Guidance (Resolution Scaling)
        # Adjust resolution and M based on training phase
        current_resolution = get_resolution_for_iteration(iteration)
        current_M = get_num_views_for_resolution(current_resolution)
        # Note: M is typically larger in low-resolution phases
```

**Parameters:**
*   $M$: The number of training views used for gradient aggregation. Typical values are not explicitly fixed in the sources, but the text discusses increasing $M$ for variance reduction [S1]. In low-resolution phases, more multi-view images are employed [S1].
*   $\lambda$: Weight for D-SSIM loss in the composite loss function $\mathcal{L} = (1-\lambda ) \mathcal{L}_1 + \lambda \mathcal{L}_\text {D-SSIM}$ [S1].

**Edge Cases and Pitfalls:**
*   **Minimal Overlap:** 3D Gaussians struggle to fit 2D training views with minimal overlap. The method addresses this via multi-view augmented densification [S1].
*   **Gradient Conflict:** Single-view supervision can lead to Gaussians satisfying single-view image supervision but conflicting with physical restrictions, causing unstable gradients. Summing gradients from multiple views mitigates this by enforcing consistency [S1].
*   **Suboptimal Solutions:** Single-scale training can lead to suboptimal solutions. The coarse-to-fine Cross-Intrinsic Guidance scheme is used to improve convergence [S1].

## Operating characteristics
*   **Time Complexity:** The explicit representation enables real-time rendering through tile-based rasterization with $O(N)$ complexity, where $N$ is the number of Gaussians [S1]. Training complexity increases with $M$ due to the computation of gradients for $M$ views per iteration, but the method is described as a "plug-and-play optimizer" compatible with existing methods [S1].
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:** Extensive experiments demonstrate that MVGS improves existing Gaussian-based methods and achieves state-of-the-art performance in Novel View Synthesis (NVS) [S1].
*   **Variance Reduction:** The variance of the multi-view gradient is bounded by:
    $$
    \mathrm {Var}\left [\frac {\partial \mathcal {L}_{\text {MV}}}{\partial \boldsymbol {\theta }}\right ] \leq M\sigma ^2\left (1 + (M-1)\rho \right )
    $$
    where $\sigma^2$ is the single-view gradient variance, $M$ is the number of views, and $\rho$ is the average correlation coefficient defined as $\rho = \frac{1}{\sigma^2}E[\mathrm{Tr} \mathrm{Cov}[\frac {\partial \mathcal {L}_i}{\partial \boldsymbol {\theta }}, \frac {\partial \mathcal {L}_j}{\partial \boldsymbol {\theta }}]]$ [S1]. Empirical validation shows faster variance decay with increasing $M$ compared to independent gradients [S1].
*   **Strengths:** Enhances multi-view consistency, ensures smoother gradient updates, addresses unstable gradients from single-view optimization, and is compatible with many 3DGS variants without relying on pre-trained models [S1].
*   **Limitations:** Not given in the sources.
*   **When to use:** When single-view optimization leads to unstable gradients or suboptimal rendering quality, and multi-view consistency is desired [S1].
*   **When not to use:** Not given in the sources.

## Background
*   **Origin:** MVGS was introduced in the paper "MVGS: Multi-view-regulated Gaussian Splatting for Novel View Synthesis" [S1].
*   **History and Development:** The method addresses the limitation of existing Gaussian-based methods that typically follow a single-view optimization paradigm, which suffers from unstable gradients [S1]. It proposes a multi-view coherent (MVC) constraint to enhance 3D Gaussian multi-view consistency [S1].
*   **Usage:** Used for Novel View Synthesis (NVS) and photorealistic rendering of unbounded scenes or objects [S1].
