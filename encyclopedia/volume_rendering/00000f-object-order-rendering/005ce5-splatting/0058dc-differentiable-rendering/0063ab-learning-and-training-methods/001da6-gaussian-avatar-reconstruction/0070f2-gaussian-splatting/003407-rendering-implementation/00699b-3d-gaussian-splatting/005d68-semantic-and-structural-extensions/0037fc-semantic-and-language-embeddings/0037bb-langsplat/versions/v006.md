# LangSplat

Also called: LangSplat [S1, unofficial][S2]

## Overview
LangSplat enables real-time open-vocabulary semantic segmentation and language-guided manipulation in 3D Gaussian Splatting by distilling vision-language features directly into Gaussian primitives [S1, unofficial][S2]. Unlike methods that align primitives in image-embedding space to preserve richer latent semantics [S2], LangSplat learns a scene-specific latent space via an autoencoder to compress features, allowing efficient querying of 3D Gaussians using natural language text embeddings from CLIP [S1, unofficial][S2].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of 3D Gaussians $\mathcal{G}$, each with position $\mathbf{x}_i$, covariance $\Sigma_i$, opacity $\alpha_i$, and a learned feature vector $\mathbf{f}_i$.
*   **Output:** A rendered feature map $F(p)$ at pixel $p$, which is compared against text embeddings to produce semantic masks or selection regions [S1, unofficial][S2].

**Data Structures:**
*   **Gaussian Feature Vector $\mathbf{f}_i$:** The core innovation is the representation of $\mathbf{f}_i$. LangSplat uses a scene-specific latent space learned via an autoencoder [S2]. This reduces memory consumption compared to storing full-dimensional CLIP features directly [S2]. The exact dimension of the latent vector is not specified in the sources, but it is lower than the original CLIP feature dimension (512) [S2].
*   **Text Embeddings:** Text queries are encoded using a CLIP text encoder (ViT-L/16) into a feature matrix of shape $(C, 512)$, where $C$ is the number of categories [S3].

**Steps:**
1.  **Feature Distillation:** During training, CLIP features are distilled into the Gaussian primitives to create a 3D language field [S2]. This involves optimizing the Gaussian features $\mathbf{f}_i$ such that the rendered feature map aligns with the 2D CLIP features of the input images [S1, unofficial][S2].
2.  **Rendering:** For a pixel $p$, the feature map $F(p)$ is computed by sorting overlapping Gaussians $\mathcal{O}_p$ front-to-back and applying alpha-blending:
    $$
    F(p) = \sum_{i \in \mathcal{O}_p} \mathbf{f}_i \cdot \alpha_i \cdot \prod_{j=1}^{i-1} (1 - \alpha_j)
    $$
    where $\mathbf{f}_i$ is the latent feature vector of the $i$-th Gaussian [S1, unofficial].
3.  **Semantic Querying:** To query a region (e.g., "windows"), the text embedding $\mathbf{t}$ is compared against the rendered feature map $F(p)$. The sources describe this as comparing rendered feature maps against text embeddings from CLIP [S1, unofficial]. While LSeg (a related method) uses matrix multiplication between reshaped image features and text features [S3], LangSplat's specific inference formula for the latent space is not explicitly detailed beyond the general comparison mechanism [S1, unofficial][S2].

**Parameters:**
*   **Autoencoder:** Used to compress CLIP features into a latent space [S2].
*   **Optimizer:** Adam optimizer is used for training [S3].

**Edge Cases and Pitfalls:**
*   **Loss of High-Frequency Details:** The autoencoder compression causes a loss of high-frequency details, manifesting as blurring of facade textures or softening of sharp edges [S2]. This is a critical limitation for applications requiring photorealism, such as infrastructure inspection [S2].
*   **Modal Bias:** The language model-driven feature extraction exhibits modal bias [S2].
*   **Tearing:** Feature projection processes can lead to tearing in view-dependent textures [S2].

## Subtopics

### [Language-Guided Semantic Scoring](15945-language-guided-semantic-scoring.md)
Language-Guided Semantic Scoring computes per-Gaussian semantic probabilities by comparing learned visual features against text embeddings from a vision-language model (VLM) such as CLIP. It enables open-vocabulary semantic segmentation and editing in 3D Gaussian Splatting by rendering feature maps that are compared against text embeddings. Unlike methods that align primitives directly in image-embedding space to preserve richer latent semantics, this approach typically operates in a text-embedding space using inner products followed by softmax normalization.

## Operating characteristics
*   **Time Complexity:** Real-time performance is achieved due to the speed of the 3DGS rasterizer [S1, unofficial].
*   **Memory Complexity:** Reduced memory consumption compared to storing full-dimensional features, due to the autoencoder-based latent space compression [S2].
*   **Strengths:** Enables real-time semantic querying and manipulation using natural language [S2]. Highly suitable for resource-constrained applications [S2].
*   **Limitations:** Loss of high-frequency details (blurring, softening of edges) due to compression [S2]. Modal bias in feature extraction [S2]. Potential for tearing in view-dependent textures [S2].
*   **When to Use:** When real-time open-vocabulary semantic segmentation and language-guided editing are required, and some loss of fine geometric detail is acceptable [S2].
*   **When Not to Use:** For large-scale UAV scenes or applications where photorealism and fine-grained detail are paramount (e.g., infrastructure inspection, urban heritage preservation) [S2].

## Background
LangSplat was introduced by [S1, unofficial][S2] as a pioneer in distilling 2D vision-model features into a 3D representation using 3D Gaussian Splatting. It builds on the principle of adding high-dimensional feature vectors to Gaussians for alpha-blended rendering [S1, unofficial]. The method specifically addresses the challenge of semantic understanding by learning a scene-specific latent space that aligns with natural language features [S2]. It allows users to select and manipulate regions using natural language queries in real-time [S2].
