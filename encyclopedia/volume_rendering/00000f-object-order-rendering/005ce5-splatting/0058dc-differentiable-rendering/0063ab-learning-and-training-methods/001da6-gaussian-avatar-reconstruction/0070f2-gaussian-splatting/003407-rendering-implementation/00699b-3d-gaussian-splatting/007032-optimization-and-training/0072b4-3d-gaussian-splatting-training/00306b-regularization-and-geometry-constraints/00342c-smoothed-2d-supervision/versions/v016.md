# Smoothed 2D Supervision

Also called: Adaptive Gaussian blur strategy, Progressive Gaussian Blurring

## Overview
Smoothed 2D Supervision is a regularization technique that stabilizes the joint optimization of camera poses and 3D scene representations by blurring the 2D training image supervision signal with a scheduled set of 2D Gaussian kernels [S2, unofficial]. It solves the problem of noisy, high-frequency gradients during early training stages, which can destabilize camera alignment and lead to overfitting of high-frequency noise in the learned 3D scene [S2, unofficial]. Unlike frequency regularization methods that modify the positional encoding or loss weights directly in the spectral domain, this method operates in the pixel space by progressively reducing the blur applied to the ground truth images [S3]. It is distinct from geometric constraints like half-Gaussian splatting or depth regularization, as it does not modify the Gaussian parameters or enforce geometric priors, but rather smooths the target signal to guide the optimization trajectory [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A sequence of 2D training images $I_t$ at iteration $t$, and a schedule of Gaussian blur kernel parameters $(\sigma_t, k_t)$ where $\sigma$ is the standard deviation and $k$ is the kernel size.
*   **Output:** A smoothed supervision image $I_{smoothed, t}$ used in the photometric loss calculation.

**Data Structures:**
*   **Kernel Schedule:** A list or function mapping iteration number to $(\sigma, k)$.
*   **Gaussian Kernel:** A 2D discrete Gaussian kernel $K$ of size $k \times k$.

**Steps:**
1.  **Initialize Schedule:** Define the initial blur parameters. According to [S4], start with a square kernel of size $9 \times 9$ and standard deviation $\sigma = 2.4$.
2.  **Schedule Decay:** Reduce the blur parameters over training iterations. [S4] specifies reducing the blur every $k_b = 100$ iterations until iteration 19,500. [S2, unofficial] notes that in some implementations (e.g., tensor-based radiance fields), $\sigma$ may be exponentially reduced to 0 at 10,000 iterations.
3.  **Apply Downsampling Adjustment:** If image downsampling is active, adjust the kernel size. [S4] states that the kernel size should be lowered by the scale of downsampling at the current stage, as the initial hyperparameters are based on original image resolutions.
4.  **Pre-Densification Adjustment:** Before densifying Gaussians, lower the kernel size. [S4] indicates this introduces extra signal on the gradient of erroneous Gaussians as the noise level reduces.
5.  **Convolution:** For each training image $I_t$, convolve with the current kernel $K_t$ to produce $I_{smoothed, t}$.
    $$ I_{smoothed, t} = I_t * K_t $$
    Where $*$ denotes 2D convolution.
6.  **Loss Calculation:** Compute the photometric loss $\mathcal{L}_{photometric}$ between the rendered image and $I_{smoothed, t}$ instead of the raw image $I_t$.

**Pseudocode:**
```python
def get_blur_kernel_params(iteration, initial_sigma=2.4, initial_kernel_size=9, decay_interval=100, max_iter=19500, downscale_factor=1.0):
    """
    Returns (sigma, kernel_size) for the current iteration.
    Based on [S4] and [S2, unofficial].
    """
    if iteration > max_iter:
        return 0.0, 1  # No blur after max_iter
    
    # Calculate decay steps
    steps = iteration // decay_interval
    
    # Linear decay of sigma or kernel size? 
    # [S4] says "Gradually reduce the blur". [S2, unofficial] mentions exponential reduction to 0.
    # We implement a linear reduction of sigma as a common interpretation of "gradually reduce" 
    # when specific functional form isn't mandated, but note [S2, unofficial] uses exponential.
    # Here we follow [S4] specific numbers: start 2.4, reduce every 100 iters.
    # Assuming linear reduction to 0 over 19500 iters (195 steps).
    
    sigma = initial_sigma * (1.0 - steps / (max_iter / decay_interval))
    sigma = max(sigma, 0.0)
    
    # Kernel size reduction
    # [S4] says "lower the blurring kernel size". 
    # A 9x9 kernel at start. 
    # We assume linear reduction of kernel size to 1x1 (or minimal)
    kernel_size = initial_kernel_size * (1.0 - steps / (max_iter / decay_interval))
    kernel_size = max(kernel_size, 1.0)
    kernel_size = int(round(kernel_size))
    if kernel_size % 2 == 0:
        kernel_size += 1 # Ensure odd size for centering
        
    # Adjust for downsampling [S4]
    kernel_size = int(kernel_size / downscale_factor)
    if kernel_size < 1:
        kernel_size = 1
        
    return sigma, kernel_size

def create_gaussian_kernel(sigma, kernel_size):
    """
    Creates a 2D Gaussian kernel.
    """
    if sigma == 0:
        # Identity kernel
        kernel = np.zeros((kernel_size, kernel_size))
        center = kernel_size // 2
        kernel[center, center] = 1.0
        return kernel
    
    # Create coordinate grid
    ax = np.linspace(-(kernel_size // 2), kernel_size // 2, kernel_size)
    xx, yy = np.meshgrid(ax, ax)
    
    # 2D Gaussian
    kernel = np.exp(-(xx**2 + yy**2) / (2.0 * sigma**2))
    
    # Normalize
    kernel = kernel / np.sum(kernel)
    return kernel

def apply_smoothed_2d_supervision(image, iteration, downscale_factor=1.0):
    """
    Applies smoothed 2D supervision to a single image.
    """
    sigma, k_size = get_blur_kernel_params(iteration, downscale_factor=downscale_factor)
    
    if sigma == 0 and k_size == 1:
        return image
        
    kernel = create_gaussian_kernel(sigma, k_size)
    
    # Convolve image with kernel
    # Assuming image is H x W x C
    smoothed_image = np.zeros_like(image)
    for c in range(image.shape[2]):
        smoothed_image[:, :, c] = convolve2d(image[:, :, c], kernel, mode='same')
        
    return smoothed_image
```

**Parameters:**
*   $\sigma_{init}$: Initial standard deviation. Typical value: 2.4 [S4].
*   $k_{init}$: Initial kernel size. Typical value: $9 \times 9$ [S4].
*   $k_b$: Iteration interval for reduction. Typical value: 100 [S4].
*   $T_{end}$: Iteration at which blur is removed or minimized. Typical value: 19,500 [S4] or 10,000 [S2, unofficial].
*   **Note:** [S2, unofficial] and [S4] differ on the decay function (exponential vs. gradual/linear) and end iteration. Implementers should choose based on the specific renderer context (NeRF vs. Gaussian Splatting).

**Edge Cases and Pitfalls:**
*   **Boundary Effects:** Convolution near image borders can cause artifacts. Use 'same' padding or reflect padding.
*   **Zero Sigma:** When $\sigma$ reaches 0, the kernel becomes a delta function. Ensure the code handles this to avoid division by zero or empty kernels.
*   **Downsampling Mismatch:** If the image is downsampled, the effective blur in the original resolution space is larger. [S4] explicitly requires scaling down the kernel size to compensate. Failure to do so results in over-smoothing.
*   **Densification Timing:** Applying heavy blur during densification can mask errors in Gaussian placement. [S4] advises reducing kernel size *before* densification to allow gradients to correct erroneous Gaussians.

## Subtopics

### [Randomly Scaled Kernel Parameter](7875-randomly-scaled-kernel-parameter.md)
Randomly Scaled Kernel Parameter is a regularization technique used during joint optimization to mitigate weak and noisy gradient signals. It addresses the insufficiency of using a single-size kernel for diverse real-world scene structures, where a fixed kernel may be overly aggressive in some contexts and overly gentle in others. By randomly scaling the kernel size, it allows combinations of different-sized kernels to guide the optimization, resulting in a more robust training schedule.

### [Multiscale Pre-convolved Representation](10911-multiscale-pre-convolved-representation.md)
A regularization technique for neural illumination fields that stabilizes the decomposition of object materials from environmental illumination by enforcing consistency with pre-computed, roughness-adapted background reflections. It addresses the ambiguity where diffuse object color is incorrectly absorbed into the estimated environment map, a problem inherent to high-dimensional neural illumination representations. Unlike methods that ignore the background or treat it as static, this method explicitly models the relationship between rough refractive surfaces and the convolved background, allowing for realistic specular reflections even when roughness exceeds the kernel scale. The technique builds on Smoothed 2D Supervision by applying discrete Gaussian blur kernels to the background to stabilize convergence.

### [Soft Rasterization](13687-soft-rasterization.md)
Soft rasterization is a differentiable rendering technique that mitigates the discontinuities inherent in standard rasterization by blending facet contributions for pixels near primitive edges. It solves the problem of sparse and vanishing gradients caused by the non-uniformity of bilinear interpolation operands, which typically have similar values except at object boundaries. Unlike standard hard rasterization, it yields slightly distorted images but allows backpropagating more useful gradients, thereby stabilizing optimization and preventing gradient vanishing at edges.

## Operating characteristics
*   **Time Complexity:** Adds $O(k^2)$ per pixel per channel for convolution, where $k$ is the kernel size. Since $k$ is small (e.g., 9x9) and decreases, the overhead is negligible compared to the rendering cost.
*   **Memory Complexity:** Requires storing the blurred image or recomputing it on the fly. No additional large data structures.
*   **Measured Performance:** [S3] reports that Adaptive Gaussian Blur improves PSNR from 19.54 (Baseline) to 19.72 on DTU 3-view, with SSIM improving from 0.766 to 0.771 and LPIPS from 0.221 to 0.218.
*   **Strengths:** Stabilizes camera alignment [S2, unofficial]; restricts high-frequency noise in the learned scene [S2, unofficial]; reduces training iterations required for convergence [S1].
*   **Limitations:** Handcrafted schedule [S3]; cannot fully align frequency relationships between positional encoding and pixel supervision as effectively as adaptive methods [S3].
*   **When to Use:** Early stages of joint optimization, especially when camera poses are being refined [S1]. Crucial for robustness in pose refinement [S1].
*   **When Not to Use:** Late-stage training where high-frequency details are needed; if an adaptive frequency-aware loss is available, it may be superior [S3].

## Background
Smoothed 2D Supervision was introduced as part of techniques to improve the robustness of joint optimization for camera poses and radiance fields [S1][S2, unofficial]. It was inspired by spectral analysis showing that blurring supervision images produces smoother gradients [S2, unofficial]. The method is analogous to the Gaussian schedule used in 3D radiance fields (NeRF) but applied to the 2D image space [S2, unofficial]. It has been adopted in various forms in Gaussian Splatting variants (e.g., Trick-GS [S4]) and NeRF regularization (e.g., Few-shot NeRF [S3]).
