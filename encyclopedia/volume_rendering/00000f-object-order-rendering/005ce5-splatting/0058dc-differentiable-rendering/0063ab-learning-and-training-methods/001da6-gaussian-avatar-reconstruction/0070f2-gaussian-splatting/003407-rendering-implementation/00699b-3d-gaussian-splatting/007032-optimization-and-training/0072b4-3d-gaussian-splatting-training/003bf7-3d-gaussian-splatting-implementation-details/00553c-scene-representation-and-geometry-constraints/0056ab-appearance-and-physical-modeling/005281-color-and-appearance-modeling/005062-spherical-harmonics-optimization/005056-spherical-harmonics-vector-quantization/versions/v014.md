# Spherical Harmonics Vector Quantization

Also called: SH clustering, SH palette

## Overview
Spherical Harmonics Vector Quantization (SH VQ) is a compression technique for 3D Gaussian Splatting that replaces per-splat SH coefficients with indices pointing to a shared palette of distinct SH vectors, reducing memory footprint at the cost of minor lighting artifacts [S1, unofficial]. It differs from [First-order Spherical Harmonics Distillation](9467-first-order-spherical-harmonics-distillation.md) by retaining full SH basis functions (rather than reducing to first-order) and from [Explicit Camera Jacobian Derivation](10077-explicit-camera-jacobian-derivation.md) by focusing on storage compression rather than gradient computation. It is chosen when memory bandwidth or storage size is the primary bottleneck and view-dependent specular effects must be preserved better than simple color quantization allows.

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $N$ Gaussian splats, each with a view-dependent color defined by SH coefficients $\mathbf{c}_i \in \mathbb{R}^{45}$ (excluding the zeroth-order term, which is treated as base color).
*   **Output:** A palette $\mathcal{P} \in \mathbb{R}^{K \times 45}$ of $K$ distinct SH vectors, and an index array $\mathbf{I} \in \mathbb{Z}^{N}$ where $\mathbf{I}[i]$ is the index into $\mathcal{P}$ for splat $i$.

**Data Structures:**
1.  **Palette ($\mathcal{P}$):** A list of $K$ vectors. Each vector contains 45 floating-point numbers (15 per RGB channel). Stored as FP16.
2.  **Indices ($\mathbf{I}$):** An array of $N$ integers. Each integer is 16 bits wide, capable of addressing up to 65,536 palette entries.

**Parameters:**
*   $K$ (Palette Size): Typically 4,000 to 16,000 items [S1, unofficial].
*   $N$ (Number of Splats): Scene-dependent (e.g., 6.1 million for the 'bike' scene) [S1, unofficial].
*   Dimensionality $D$: 45 (excluding the 0th-order SH coefficient) [S1, unofficial].

**Steps:**
1.  **Extract SH Data:** Collect the 45-dimensional SH coefficient vector for every splat in the scene, excluding the 0th-order coefficient.
2.  **Cluster:** Perform vector quantization (clustering) on the $N$ data points in $\mathbb{R}^{45}$ to find $K$ cluster centers. This forms the palette $\mathcal{P}$.
    *   *Note:* Standard k-means is too slow for millions of splats in 45 dimensions. A mini-batch k-means variant is used [S1, unofficial].
3.  **Assign Indices:** For each splat $i$, find the palette index $k$ such that the Euclidean distance between the splat's SH vector $\mathbf{c}_i$ and the palette entry $\mathcal{P}[k]$ is minimized:
    $$ \mathbf{I}[i] = \arg \min_{k \in \{0, \dots, K-1\}} \| \mathbf{c}_i - \mathcal{P}[k] \|_2^2 $$
4.  **Store:** Save $\mathcal{P}$ and $\mathbf{I}$.

**Pseudocode:**
```python
import numpy as np

def spherical_harmonics_vector_quantization(sh_data: np.ndarray, k: int) -> tuple:
    """
    Compress SH coefficients using vector quantization.
    
    Args:
        sh_data: Array of shape (N, 45) containing SH coefficients for N splats.
                 Excludes the 0th-order coefficient.
        k: Number of palette entries (cluster centers).
        
    Returns:
        palette: Array of shape (k, 45) containing the cluster centers.
        indices: Array of shape (N,) containing the index of the closest palette entry for each splat.
    """
    n_splats = sh_data.shape[0]
    
    # Step 1: Initialize centroids randomly from the data
    # [G] Standard k-means initialization; random subset of data points
    rng = np.random.default_rng()
    initial_indices = rng.choice(n_splats, k, replace=False)
    centroids = sh_data[initial_indices].copy()
    
    # Step 2: Mini-batch K-Means Clustering
    # [G] Using a fixed number of iterations for determinism; 
    # in practice, convergence criteria or max iterations are used.
    max_iterations = 100
    batch_size = 256
    
    for iteration in range(max_iterations):
        # Sample a mini-batch of indices
        batch_indices = rng.choice(n_splats, batch_size, replace=False)
        batch_data = sh_data[batch_indices]
        
        # Assign each point in the batch to the nearest centroid
        # Calculate distances: (batch_size, k)
        # dist = ||x - c||^2 = ||x||^2 + ||c||^2 - 2 * x.c
        # [G] Efficient distance calculation without explicit loop
        sq_norms_data = np.sum(batch_data ** 2, axis=1, keepdims=True)
        sq_norms_centroids = np.sum(centroids ** 2, axis=1, keepdims=True).T
        distances = sq_norms_data + sq_norms_centroids - 2 * np.dot(batch_data, centroids.T)
        
        assignments = np.argmin(distances, axis=1)
        
        # Update centroids based on the batch
        for j in range(k):
            mask = assignments == j
            if np.any(mask):
                batch_points = batch_data[mask]
                centroids[j] = np.mean(batch_points, axis=0)
                
    # Step 3: Final Assignment for all splats
    # Calculate distances for all splats to all centroids
    sq_norms_all = np.sum(sh_data ** 2, axis=1, keepdims=True)
    sq_norms_centroids_final = np.sum(centroids ** 2, axis=1, keepdims=True).T
    final_distances = sq_norms_all + sq_norms_centroids_final - 2 * np.dot(sh_data, centroids.T)
    
    indices = np.argmin(final_distances, axis=1)
    
    # Convert to FP16 for storage as per source
    palette_fp16 = centroids.astype(np.float16)
    
    return palette_fp16, indices
```

**Edge Cases and Pitfalls:**
*   **Curse of Dimensionality:** Clustering millions of splats in 45 dimensions is computationally expensive and slow [S1, unofficial].
*   **Lighting Artifacts:** Quantization introduces minor lighting artifacts, particularly in specular highlights, though shininess effects are generally retained [S1, unofficial].
*   **Index Size:** Indices are stored as 16 bits regardless of whether $K < 65,536$, wasting some bits if $K$ is small [S1, unofficial].

## Operating characteristics
*   **Memory Footprint:**
    *   Palette: $K \times 45 \times 2$ bytes (FP16). For $K=16,000$, this is ~1.44 MB [S1, unofficial].
    *   Indices: $N \times 2$ bytes. For $N=6.1$ million, this is ~12 MB [S1, unofficial].
    *   Total SH storage: ~13.44 MB for the 'bike' scene with $K=16,000$ [S1, unofficial].
*   **Compression Ratio:** Achieves ~14.9x compression for the 'Low' preset (SH clustered into 16k) compared to uncompressed PLY, reducing total scene data from 1.4 GB to ~98-93 MB depending on other components [S1, unofficial].
*   **Quality:**
    *   'Low' preset ($K=16,000$): PSNR ~35.17-35.32 [S1, unofficial].
    *   'Very Low' preset ($K=4,000$): PSNR ~30.19-32.27 [S1, unofficial].
    *   Retains "shininess" effects better than lower-dimensional approximations [S1, unofficial].
*   **Performance:**
    *   Clustering time: Custom mini-batch k-means is ~3x faster than Faiss and significantly faster than scikit-learn [S1, unofficial].
    *   Rendering: No change in rendering complexity; index lookup is $O(1)$ per splat.
*   **Strengths:** Significant memory reduction; preserves view-dependent effects; simple to implement.
*   **Limitations:** Introduces quantization artifacts; clustering is slow for very large scenes; requires pre-processing.

## Background
Spherical Harmonics Vector Quantization was introduced by Aras Pranckevičius in a blog post titled "Making Gaussian Splats more smaller" [S1, unofficial]. It was developed as part of a toy "Gaussian Splatting for Unity" implementation to enable efficient real-time rendering of large scenes on constrained hardware. The method draws inspiration from traditional computer graphics palette-based rendering and vector quantization techniques [S1, unofficial].
