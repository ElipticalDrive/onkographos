# Consensus-Inheritance Extension

Also called: Consensus Inheritance, Consensus Weight Inheritance

## Overview
The Consensus-Inheritance Extension is a mechanism for maintaining correspondence between fixed consensus statistics and newly created Gaussian primitives during densification (splitting or cloning) in 3D Gaussian Splatting [S1, unofficial]. It prevents the breaking of the fixed-consensus protocol by ensuring that new Gaussians inherit relevant prior information, thereby allowing consensus statistics to evolve with the Gaussian population while retaining contamination-resistant properties [S1, unofficial]. It is distinct from sibling methods like [Conditional 3DGS Optimization and Rendering](11459-conditional-3dgs-optimization-and-rendering.md) and [Blended Error Densification and Splitting](13892-blended-error-densification-and-splitting.md) by explicitly managing the inheritance of consensus weights and periodic re-estimation thresholds rather than altering the densification criteria or loss functions directly.

## How it works
The method extends the standard 3DGS training loop by introducing three specific behaviors: inheritance during creation, periodic re-estimation with validation, and synchronization with opacity resets.

### Inputs and Outputs
*   **Inputs**:
    *   Parent Gaussian primitive $p$ with consensus color $c^{\bullet}_p$ and consensus weight $w^{\bullet}_p$.
    *   Current Gaussian population centers $\{x_i\}$.
    *   Current consensus statistics $c^{\bullet}$.
    *   Opacity reset magnitude $\Delta \alpha$.
*   **Outputs**:
    *   Updated consensus statistics $c^{\bullet}_{new}$ (if accepted).
    *   New child Gaussian primitives with inherited consensus attributes.
    *   Updated consensus weights for Gaussians affected by opacity resets.

### Data Structures
The consensus statistics are typically maintained as a global or per-region vector $c^{\bullet}$ (e.g., color or feature vector) and a scalar or vector weight $w^{\bullet}$. The exact layout depends on the backend implementation of the consensus mechanism, but generally includes:
*   $c^{\bullet}$: The consensus value (e.g., RGB color).
*   $w^{\bullet}$: The weight associated with the consensus.

### Parameters
*   $\text{inh}$: Inter-generation decay factor for consensus weight inheritance. Range: $(0, 1)$. Candidate value: $0.5$ [S1, unofficial].
*   $k$: Refresh interval in iterations. Candidate value: $1,000$ [S1, unofficial].
*   $\tau$: MAD threshold multiplier for validating consensus updates. Candidate value: $3.0$ [S1, unofficial].

### Steps

1.  **Split/Clone Inheritance**:
    When a parent Gaussian $p$ is split or cloned to create a child Gaussian $c$:
    *   The child inherits the parent's consensus color: $c^{\bullet}_c = c^{\bullet}_p$.
    *   The child's consensus weight is decayed: $w^{\bullet}_c = \text{inh} \times w^{\bullet}_p$ [S1, unofficial].

2.  **Contamination-Resistant Periodic Re-estimation**:
    Every $k$ iterations:
    *   Reproject current Gaussian centers to compute a candidate consensus $\tilde{c}^{\bullet}$.
    *   Calculate the channel-wise deviation between the candidate and the current consensus: $\delta = \|\tilde{c}^{\bullet} - c^{\bullet}\|_{\infty}$.
    *   Calculate the Median Absolute Deviation (MAD) of the deviations across channels or samples.
    *   Accept the update if $\delta \leq \tau \times \text{MAD}$. Otherwise, retain $c^{\bullet}$ [S1, unofficial].
    *   This step prevents rendering errors from being written back into the supervision target, preserving the anti-circular-dependency property [S1, unofficial].

3.  **Opacity-Reset Synchronization**:
    After an opacity-reset event affecting a set of Gaussians $G_{reset}$:
    *   For each $g \in G_{reset}$, decay its consensus weight $w^{\bullet}_g$ in proportion to the opacity reset magnitude $\Delta \alpha$. The exact proportionality is not specified in the sources [S1, unofficial].

### Pseudocode

```python
def consensus_inheritance_extension(parent_gaussian, current_consensus, iteration, opacity_reset_magnitude):
    """
    Implements the Consensus-Inheritance Extension for 3D Gaussian Splatting.
    
    Args:
        parent_gaussian: Object with attributes .consensus_color, .consensus_weight
        current_consensus: Object with attributes .color, .weight
        iteration: Current training iteration number
        opacity_reset_magnitude: Float representing the magnitude of opacity reset
        
    Returns:
        child_gaussian: New Gaussian object with inherited consensus
        updated_consensus: Updated consensus object (if re-estimation occurred)
    """
    # Parameters
    inh = 0.5
    refresh_interval = 1000
    mad_threshold = 3.0
    
    # Step 1: Split/Clone Inheritance
    child = Gaussian()
    child.consensus_color = parent_gaussian.consensus_color
    child.consensus_weight = inh * parent_gaussian.consensus_weight
    
    # Step 2: Periodic Re-estimation
    updated_consensus = current_consensus
    if iteration % refresh_interval == 0:
        # Reproject centers and compute candidate consensus
        candidate_consensus_color = reproject_centers_and_compute_consensus()
        
        # Calculate deviation
        deviation = abs(candidate_consensus_color - current_consensus.color)
        mad = median_absolute_deviation(deviation)
        
        # Validate update
        if max(deviation) <= mad_threshold * mad:
            updated_consensus.color = candidate_consensus_color
            # Weight update logic not fully specified in sources
        else:
            updated_consensus = current_consensus
            
    # Step 3: Opacity-Reset Synchronization
    # Decay consensus weights for affected Gaussians
    # Note: Exact proportionality formula not given in sources [G]
    if opacity_reset_magnitude > 0:
        for gaussian in affected_gaussians:
            gaussian.consensus_weight *= (1.0 - opacity_reset_magnitude)
            
    return child, updated_consensus
```

### Edge Cases and Pitfalls
*   **Precision**: The infinity norm $\|\cdot\|_{\infty}$ is used for deviation calculation, which may be sensitive to outliers in specific channels [S1, unofficial].
*   **Boundaries**: The decay factor $\text{inh}$ must be strictly within $(0, 1)$ to prevent weight explosion or vanishing [S1, unofficial].
*   **Degenerate Input**: If the MAD is zero (e.g., all deviations are identical), the threshold check may fail or behave unexpectedly. This case is not addressed in the sources [S1, unofficial].

## Operating characteristics
*   **Time Complexity**: The periodic re-estimation step adds overhead every $k$ iterations. The cost depends on the number of Gaussians and the complexity of reprojecting centers. The inheritance step is $O(1)$ per new Gaussian.
*   **Memory Complexity**: No significant additional memory is required beyond storing the consensus statistics and weights for each Gaussian.
*   **Performance**: The method is designed to maintain training stability by preventing contamination from rendering errors [S1, unofficial]. The specific performance metrics (PSNR, SSIM, training time) are not provided in the sources, as the experiments were limited to parameter calibration on a single scene (Drums) [S1, unofficial].
*   **Strengths**: Preserves the anti-circular-dependency property; allows consensus to evolve with the population.
*   **Limitations**: Relies on heuristic parameters ($\text{inh}$, $k$, $\tau$) that require calibration; opacity-reset synchronization details are not fully specified.

## Background
The Consensus-Inheritance Extension was introduced in the context of "Visibility-Aware Texture Consensus and Local Structural Constraints for 3D Gaussian Reconstruction in Texture-Degraded Scenes" [S1, unofficial]. It addresses the issue that default 3DGS configurations build consensus statistics once before training, which breaks correspondence when cloning and splitting alter the Gaussian population [S1, unofficial]. The method was calibrated using a $3 \times 3 \times 3$ full-factorial grid on the Drums scene with seed 17 for 3,000 iterations [S1, unofficial].
