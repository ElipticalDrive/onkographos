# WildGaussians

Also called: Splatting in the Wild images with Appearance-conditioned Gaussians, SWAG

## Overview
WildGaussians extends 3D Gaussian Splatting (3DGS) to handle "in-the-wild" photo collections characterized by unconstrained lighting, transient occluders (e.g., pedestrians), and appearance variations [S2, S4]. It addresses the limitation of standard 3DGS, which lacks shared parameters and struggles with such variability, by integrating robust DINO features for uncertainty modeling and a lightweight appearance modeling module [S1, S2]. Unlike NeRF-based methods that use global scene embeddings or other 3DGS variants that apply post-processing CNNs, WildGaussians embeds appearance vectors directly within each Gaussian and uses an MLP to predict color transformations, preserving real-time rendering speeds while enabling the trained appearance to be "baked" back into the standard 3DGS formulation [S2, S4].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of uncalibrated or calibrated images $\{I_j\}_{j=1}^N$ from an unconstrained collection.
*   **Outputs:** A set of 3D Gaussians $\{G_i\}$ optimized for static scene reconstruction, with parameters allowing for appearance conditioning and transient object separation.

**Data Structures:**
1.  **Gaussian $G_i$:** Defined by mean $\mu_i$, positive semi-definite covariance matrix $\Sigma_i$, opacity $\alpha_i$, and view-dependent color parametrized using spherical harmonics (SH) coefficients [S2].
2.  **Per-Image Embedding $l_I$:** A trainable vector of size $n=24$ for each training image $I$ [S4].
3.  **Hash Grid Encoding:** A hash table of size $T=2^{19}$ with $L=12$ levels, finest resolution $N_{max}=2048$, and coarsest resolution $N_{min}=16$, used to encode Gaussian centers $x$ into $emb(x)$ [S4].
4.  **Appearance MLP $F_\theta$:** A 3-layer MLP with 64 hidden units. Inputs: Gaussian color $c$ (from SH), center embedding $emb(x)$, and image embedding $l_I$. Outputs: image-dependent color $c^I$ and opacity variation parameter $\Delta \alpha^I$ [S4].

**Numbered Steps:**

1.  **Initialization:** Initialize 3D Gaussians using standard SfM points. Initialize per-image embeddings $l_I$, Hash Grid, and MLP $F_\theta$ [S4].
2.  **Projection:** For each camera view, project 3D Gaussians to 2D. Compute the 2D covariance matrix $\Sigma'_i$ in image space:
    $$ \Sigma'_i = J_{W} \Sigma_i W^T J_{1:2,1:2}^T $$
    where $J$ is the Jacobian of the affine approximation of the projection, $W$ is the viewing transformation, and $(\cdot)_{1:2,1:2}$ denotes the first two rows and columns [S2].
3.  **Appearance Modeling (Training):**
    a. Compute the center embedding $emb(x)$ for each Gaussian center $x$ using the Hash Grid [S4].
    b. Pass the Gaussian color $c$, $emb(x)$, and the current image's embedding $l_I$ through $F_\theta$:
    $$ (c^I, \Delta \alpha^I) = F_\theta(c, emb(x), l_I) $$
    c. Sample the opacity variation $\Delta \tilde{\alpha}^I$ from the Binary Concrete distribution using $\Delta \alpha^I$, temperature $T$, and random variable $U \sim \text{Uniform}(0,1)$:
    $$ \Delta \tilde{\alpha}^I = \text{sigmoid} \left[ \frac{1}{T} \left( \log(|\Delta \alpha^I|) + \log(U) - \log(1-U) \right) \right] $$
    d. Compute the final image-dependent opacity $\alpha^I$:
    $$ \alpha^I = \max(\alpha - \Delta \tilde{\alpha}^I, 0) $$
    e. Render the image using colors $c^I$ and opacities $\alpha^I$ via standard alpha-compositing [S4].
4.  **Uncertainty Modeling:**
    a. Extract DINO v2 features from the ground truth image and the rendered image [S2].
    b. Pass the ground truth DINO features through a trainable affine transformation to predict per-pixel uncertainty, encoding static regions vs. occluders [S2].
    c. Optimize the uncertainty predictor by minimizing the cosine similarity between the DINO features of the ground truth and the rendered image [S2].
5.  **Loss Computation and Optimization:**
    a. Compute the DSSIM and L1 losses between predicted colors $\hat{C}$ and ground truth colors $C$, masked by the uncertainty mask to exclude occluders [S2].
    b. The total loss is:
    $$ L_{3DGS} = \lambda_{dssim} DSSIM(\hat{C}, C) + (1 - \lambda_{dssim}) \|\hat{C} - C\|_1 $$
    c. Optimize 3D Gaussian parameters, MLP weights $F_\theta$, Hash Encoder parameters, and per-image embeddings $l_I$ [S4].
6.  **Transient Separation (Post-Training):**
    a. Identify transient Gaussians as those with non-zero variance of $\Delta \tilde{\alpha}^I$ across all training images: $\text{Var}(\Delta \tilde{\alpha}^I) \neq 0$ [S2, S4].
    b. Discard transient Gaussians to retain only the static scene representation [S4].
7.  **Baking (Optional):** After training, the appearance can be baked into the standard 3DGS formulation by storing the final appearance-conditioned colors and opacities, ensuring fast rendering without the MLP [S2].

**Parameters:**
*   Temperature $T$: Set to $0.1$ to force a binary distribution from the start. No annealing is used [S4].
*   Evaluation $U$: Fixed at $0.5$ during evaluation [S4].
*   Latent embedding size $n$: $24$ [S4].
*   Hash table size $T$: $2^{19}$ [S4].
*   Finest resolution $N_{max}$: $2048$ [S4].
*   Number of levels $L$: $12$ [S4].
*   Coarsest resolution $N_{min}$: $16$ [S4]
*   $\lambda_{dssim}$: Weighting factor for DSSIM loss [S2].

**Pitfalls:**
*   Incorrect training signals can lead to irreversibly removing geometry parts due to 3DGS's primitive growth/pruning, unlike NeRFs which can recover [S2].
*   Failure cases include over-construction of static parts, observed as black spots on roads (Brandenburg Gate) and fountain water (Trevi Fountain) [S4].
*   Affine color transformations alone cannot model all in-the-wild appearance changes; direct color prediction via MLP is required [S4].

## Operating characteristics
*   **Time and Memory Complexity:** Training is one order of magnitude faster than previous implicit methods (NeRF-W, Ha-NeRF, CR-NeRF, RefinedFields) [S4]. Rendering speed matches real-time 3DGS [S2].
*   **Measured Performance:** Improves 3DGS PSNR by an average margin of 5.01 dB on Phototourism scenes and 5 dB on NeRF-OSR [S4].
*   **Scaling:** Uses less frequent densification steps than original 3DGS but injects image-dependent information, resulting in a finer representation with more Gaussians [S4].
*   **Strengths:** Handles unconstrained photo collections, transient objects, and varying illumination; enables appearance editing via interpolation of learned embeddings; allows baking to standard 3DGS [S2, S4].
*   **Limitations:** May over-construct static parts in specific failure cases; requires careful handling of transient Gaussians to avoid artifacts [S4].
*   **When to use:** When reconstructing scenes from in-the-wild photo collections with occlusions and appearance changes, requiring real-time rendering and editability [S2, S4].
*   **When not to use:** For static, controlled studio scenes where standard 3DGS suffices, or when computational resources for MLP evaluation during training are limited [S4].

## Background
WildGaussians was introduced to address the challenges of 3D reconstruction in unconstrained environments, where traditional 3DGS struggles with occlusions and appearance variations [S2]. It builds on the 3DGS framework [14] and incorporates insights from NeRF-based methods that use per-image embeddings [S2]. The method was evaluated on the Phototourism dataset (Brandenburg Gate, Sacre Coeur, Trevi Fountain) and the NeRF-OSR benchmark [S4].
