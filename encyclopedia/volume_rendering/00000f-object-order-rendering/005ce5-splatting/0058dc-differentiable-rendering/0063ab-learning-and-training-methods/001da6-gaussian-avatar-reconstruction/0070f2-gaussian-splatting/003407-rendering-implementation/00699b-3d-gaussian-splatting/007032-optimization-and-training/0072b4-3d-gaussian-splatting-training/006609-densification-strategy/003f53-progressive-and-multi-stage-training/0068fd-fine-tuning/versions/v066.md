# Fine-tuning

Also called: 3DGS Fine-tuning, Fine-tuning Strategy, Gaussian Splatting Fine-tuning, Per-scene optimization

## Overview
Fine-tuning in the context of 3D Gaussian Splatting (3DGS) refers to a per-scene optimization process that refines an initial Gaussian representation to achieve high-fidelity reconstruction or adaptation to specific constraints. It addresses the limitation of static initialization or coarse generative priors by treating the scene as a single-scene optimization problem, allowing for the adjustment of geometry, color, and opacity attributes using rendered supervision [S1, S3]. It sets itself apart from sibling methods like [Hybrid Coarse-to-Fine Strategy](7173-hybrid-coarse-to-fine-strategy.md) by focusing on the refinement of a specific initialized state (often from a generative model or sparse input) rather than a curriculum of increasing complexity, and from [Curriculum Learning with Slice and Voxel Supervision](12921-curriculum-learning-with-slice-and-voxel-supervision.md) by typically operating in image space with full-resolution supervision from the outset [S1, S3].

## How it works
### Inputs and Outputs
- **Inputs:** An initial set of 3D Gaussian primitives $\mathcal{G}_0$ (with positions $\mu$, covariances $\Sigma$, opacities $\alpha$, and spherical harmonic coefficients $\mathbf{c}$), a set of training images $\{I_v\}$ with known camera poses, and optionally a point cloud or mesh prior [S1, S3].
- **Outputs:** An optimized set of Gaussian primitives $\mathcal{G}^*$ that minimizes the rendering loss against the training images [S1, S3].

### Data Structures
The Gaussian set $\mathcal{G}$ follows the standard 3DGS layout [15018-multi-stage-training-with-pose-prediction.md]:
- **Position:** $\mu \in \mathbb{R}^3$
- **Covariance:** $\Sigma \in \mathbb{R}^{3 \times 3}$ (parameterized by rotation $R \in SO(3)$ and scale $s \in \mathbb{R}^3$)
- **Opacity:** $\alpha \in [0, 1]$
- **Color:** $\mathbf{c} \in \mathbb{R}^{3 \times (N_{SH}+1)^2}$ (Spherical Harmonic coefficients)

### Steps
1. **Initialization:**
   - *Generative/Point-based:* If starting from a point cloud or generative prior, predict initial 3D Gaussian primitives via a feed-forward network where geometry and color attributes are generated simultaneously [S3]. Alternatively, obtain a voxel representation using volume density samples along rays and reconstruct a mesh using marching cubes, then predict vertex colors from rendered novel views [S1].
   - *Direct:* Initialize with sparse SfM points or a coarse Gaussian set [S3].
2. **Optimization Setup:**
   - Treat the scene as a single-scene NeRF or radiance field [S1].
   - Define the loss function $\mathcal{L}$, typically combining L1 photometric loss and SSIM loss, as in vanilla 3DGS [S3].
   - Enable densification mechanisms (growing and pruning) during fine-tuning to adapt the Gaussian count to the scene complexity [S3].
3. **Training Loop:**
   - Render images from training views using differentiable rasterization [S3].
   - Compute the image-space loss $\mathcal{L}_{color}$ (and potentially entropy or other regularizers) [S1, S3].
   - Backpropagate gradients to update all geometry ($\mu, \Sigma$) and color ($\mathbf{c}$) attributes [S3]. Opacity $\alpha$ is also updated [S3].
   - Apply Adam optimizer with a learning rate typically around $1 \times 10^{-3}$ [S3].
4. **Densification and Pruning:**
   - Monitor gradient magnitudes or position changes to trigger splitting or cloning of Gaussians in under-reconstructed regions [S3].
   - Prune Gaussians with low opacity to reduce memory consumption and prevent overfitting [S3].

### Pseudocode
```python
def fine_tune_gaussians(G_initial, images, poses, num_iterations):
    """
    Fine-tune 3D Gaussian Splatting representation.
    
    Args:
        G_initial: Initial set of Gaussians (positions, covariances, opacities, SH coeffs)
        images: List of training images
        poses: List of camera poses corresponding to images
        num_iterations: Number of optimization steps
        
    Returns:
        G_optimized: Optimized set of Gaussians
    """
    G = G_initial
    optimizer = Adam([G.positions, G.covariances, G.opacities, G.colors], lr=1e-3)
    
    for i in range(num_iterations):
        # Sample a random training view
        idx = random.randint(0, len(images) - 1)
        image = images[idx]
        pose = poses[idx]
        
        # Render the scene
        rendered_image = render(G, pose)
        
        # Compute loss
        loss = compute_loss(rendered_image, image)
        
        # Backpropagate and update
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        
        # Densification and Pruning (e.g., every 100 iterations)
        if i % 100 == 0:
            G = densify_and_prune(G, threshold=0.0002)
            
    return G
```

### Parameters
- **Learning Rate:** $1 \times 10^{-3}$ [S3].
- **Optimizer:** Adam [S3].
- **Densification Threshold:** Typically $2 \times 10^{-4}$ for position gradient norm [S3, G].
- **Pruning Threshold:** Opacity threshold typically $0.005$ [S3, G].
- **SH Degree:** Often starts low and increases, or uses full degree depending on initialization [S3].

### Edge Cases and Pitfalls
- **Overfitting:** Fine-tuning on a small number of views can lead to overfitting, resulting in artifacts in novel views. Regularization or pruning is essential [S3].
- **Initialization Quality:** Poor initialization (e.g., from a noisy point cloud) can lead to slow convergence or local minima. Generative priors can help but may introduce bias [S1, S3].
- **Memory Usage:** Enabling growing and pruning requires careful management of memory, especially for large scenes [S3].

## Subtopics

### Image-space Gaussian Fine-tuning
A fine-tuning process for volumetric data that accounts for different visual modes by generating multiple radiance fields using different transfer functions. It optimizes a separate Gaussian set $G_h$ for each mode $h$ against rendered images [S4, unofficial]. It sets itself apart from standard fine-tuning by handling multi-modal volumes (e.g., medical scans with varying dynamic ranges) through transfer functions $TF_h$ that isolate specific value intervals of the physical field $F$ [S4, unofficial]. Typically, 5 transfer functions are used per volume [S4, unofficial].

### Ada-GS
A baseline method that trains vanilla 3D Gaussian Splatting directly on 2D stylized images. It preserves better details than GS-Ada but requires training from scratch for every new style image, limiting practical usability [S5]. It sets itself apart from style transfer methods that operate on rendered images post-hoc by integrating style supervision directly into the 3DGS optimization loop [S5].

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of Gaussians and training iterations. Fine-tuning from a generative prior can accelerate convergence compared to training from scratch [S3].
- **Memory Complexity:** Linear with respect to the number of Gaussians. Pruning helps manage memory usage [S3].
- **Performance:** Can achieve photorealism on par with or surpassing other methods when leveraging pretrained weights [S3].
- **Strengths:** High fidelity, flexible initialization, ability to adapt to specific constraints [S1, S3].
- **Limitations:** Requires per-scene optimization, which can be computationally expensive for large datasets. Sensitive to initialization quality [S1, S3].
- **When to use:** When high-fidelity reconstruction is needed for a specific scene, or when adapting a generative prior to a specific object [S1, S3].
- **When not to use:** When real-time inference is required without per-scene optimization, or when dealing with very large-scale scenes where per-scene optimization is prohibitive [S3].

## Background
Fine-tuning in 3DGS is inspired by techniques in NeRF and CNNs. In NeRF, per-scene optimization is standard for high-quality reconstruction [S1]. In CNNs, fine-tuning involves fixing lower layers and training upper layers on specific datasets [S2]. The application of fine-tuning to 3DGS allows for the refinement of generative priors or sparse initializations to achieve high-quality novel view synthesis [S1, S3].
