# Connectivity-based Visibility for 3D Gaussian Splatting

Also called: 3DGS + Our Connectivity, Connectivity relationship for 3DGS

## Overview
This method replaces the standard depth-ordered blending of all overlapping points in 3D Gaussian Splatting (3DGS) with a visibility filtering step based on a connectivity relationship graph [S1]. By retrieving only visible points from the point cloud for blending, it reduces memory consumption and accelerates rendering, enabling the optimization of large-scale scenes (e.g., autonomous driving sequences with tens of millions of points) that would otherwise exceed GPU memory limits [S1]. It sets itself apart from standard 3DGS by explicitly discarding unseen points during the compositing phase, whereas standard 3DGS blends a set of depth-ordered points including many unseen ones [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D point cloud with associated Gaussian attributes (position, covariance, opacity, spherical harmonics coefficients) and a camera pose [S1].
*   **Output:** A rendered image where pixel colors are computed using only the subset of Gaussians determined to be visible via the connectivity graph [S1].

**Data Structures:**
*   **Connectivity Graph:** A graph structure representing the spatial or topological relationships between points in the cloud, used to identify visible points relative to the camera view [S1]. The specific construction algorithm for the graph is not detailed in the sources [G].
*   **Visibility Mask:** A boolean array or list of indices indicating which points from the full cloud are visible [S1].

**Steps:**
1.  **Deactivate Densification:** Disable the standard 3DGS densification (splitting/cloning) process because the accumulated LiDAR point cloud is relatively dense [S1].
2.  **Retrieve Visible Points:** Query the connectivity relationship graph from the whole point cloud to retrieve only the subset of points that are visible from the current camera viewpoint [S1].
3.  **Blend Visible Points:** Perform the standard 3DGS alpha-blending operation using only the retrieved visible points to compute the color for each pixel [S1].

**Pseudocode:**
```python
def render_connectivity_3dgs(points, gaussians, camera_intrinsics, camera_extrinsics, connectivity_graph):
    """
    Render a frame using connectivity-based visibility for 3DGS.
    
    Args:
        points: Array of 3D point positions (N, 3).
        gaussians: Dictionary of Gaussian attributes (covariances, opacities, SH coeffs).
        camera_intrinsics: 3x3 intrinsic matrix.
        camera_extrinsics: 4x4 extrinsic matrix (world to camera).
        connectivity_graph: Object providing get_visible_points(points, camera_extrinsics).
        
    Returns:
        rendered_image: Rendered RGB image (H, W, 3).
    """
    # Step 1: Retrieve visible points using the connectivity graph
    visible_indices = connectivity_graph.get_visible_points(points, camera_extrinsics)
    
    # Filter Gaussian attributes to the visible subset
    visible_covs = gaussians['covariances'][visible_indices]
    visible_opacities = gaussians['opacities'][visible_indices]
    visible_sh = gaussians['sh_coeffs'][visible_indices]
    visible_pos = points[visible_indices]
    
    # Step 2: Project visible points to screen space
    cam_pos = camera_extrinsics[:3, 3]
    rel_pos = visible_pos - cam_pos
    rot = camera_extrinsics[:3, :3]
    view_pos = rot @ rel_pos.T  # (3, M)
    
    # Clip points behind camera
    valid_mask = view_pos[2, :] > 0.01
    view_pos = view_pos[:, valid_mask]
    visible_covs = visible_covs[valid_mask]
    visible_opacities = visible_opacities[valid_mask]
    visible_sh = visible_sh[valid_mask]
    
    # Project covariance to screen space (simplified 3DGS projection)
    tan_fovx = np.tan(camera_intrinsics[0, 0] / 2)
    tan_fovy = np.tan(camera_intrinsics[1, 1] / 2)
    aspect = camera_intrinsics[0, 0] / camera_intrinsics[1, 1]
    
    # Compute screen-space covariance and bounding box for each visible Gaussian
    # (Standard 3DGS projection logic)
    # For brevity, we assume a helper computes screen-space bounds and 2D covariance
    screen_bounds = compute_screen_bounds(view_pos, visible_covs, camera_intrinsics)
    
    # Step 3: Alpha-blend visible Gaussians per pixel
    H, W = 1080, 1920  # Example resolution
    rendered_image = np.zeros((H, W, 3), dtype=np.float32)
    accumulated_opacity = np.zeros((H, W), dtype=np.float32)
    
    for i in range(len(screen_bounds)):
        x0, y0, x1, y1 = screen_bounds[i]
        x0, y0 = int(np.clip(x0, 0, W-1)), int(np.clip(y0, 0, H-1))
        x1, y1 = int(np.clip(x1, 0, W-1)), int(np.clip(y1, 0, H-1))
        
        # Extract 2D covariance and opacity for this Gaussian
        cov2d = compute_2d_covariance(visible_covs[i], view_pos[:, i], camera_intrinsics)
        alpha = visible_opacities[i]
        color = compute_sh_color(visible_sh[i], camera_extrinsics)
        
        # Rasterize this Gaussian to the pixel grid
        for y in range(y0, y1 + 1):
            for x in range(x0, x1 + 1):
                dx, dy = x - view_pos[0, i], y - view_pos[1, i]
                sigma = 0.5 * (dx**2 * cov2d[0,0] + dy**2 * cov2d[1,1] + 2*dx*dy*cov2d[0,1])
                g_alpha = alpha * np.exp(-sigma)
                g_alpha = np.clip(g_alpha, 0, 1)
                
                # Alpha blending
                prev_color = rendered_image[y, x]
                rendered_image[y, x] = prev_color * (1 - g_alpha) + color * g_alpha
                accumulated_opacity[y, x] += g_alpha * (1 - accumulated_opacity[y, x])
                
    return rendered_image
```

**Parameters:**
*   **Densification:** Disabled (Boolean: `False`) [S1].
*   **GPU Memory:** The method is designed to fit within limited resources (e.g., 48 GB), whereas standard 3DGS fails on large datasets [S1].

**Edge Cases and Pitfalls:**
*   **Sparse Coverage:** The method may underperform in scenes with sparse coverage (e.g., fast-moving camera paths in autonomous driving) where the connectivity graph might not adequately capture visible structure [S1].
*   **Graph Construction:** The performance depends on the efficiency and accuracy of the connectivity graph. If the graph fails to identify visible points correctly, rendering quality degrades [G].

## Operating characteristics
*   **Time Complexity:** Rendering time is significantly reduced. On KITTI-4-reduced (19.4 million points), rendering time decreased from 0.046s (21.6 FPS) to 0.00089s (1114 FPS), an acceleration of more than 50 times [S1].
*   **Memory Complexity:** Reduces GPU memory requirements by only processing visible points. Standard 3DGS failed on full KITTI-4 (approx. 36.3 million points) due to memory constraints, while this method succeeded on the same hardware (48 GB GPU) [S1].
*   **Measured Performance:** On KITTI-4-reduced, PSNR improved from 19.61 to 28.57, SSIM from 0.58 to 0.83, and LPIPS from 0.57 to 0.23 [S1].
*   **Strengths:** Enables optimization and rendering of very large scenes (tens of millions of points) that exceed standard GPU memory. Significantly faster rendering speeds [S1].
*   **Limitations:** Performance may degrade in scenes with sparse coverage (e.g., fast-moving cameras) where the connectivity graph may not accurately capture visible structure [S1].
*   **When to Use:** Large-scale scenes with dense initial point clouds (e.g., LiDAR scans) where standard 3DGS fails due to memory or is too slow [S1].
*   **When Not to Use:** Scenes where the initial point cloud is sparse and requires densification to fill gaps, as the method deactivates densification due to its reliance on dense accumulated LiDAR data [S1].

## Background
The method was introduced in the paper "CE-NPBG: Connectivity Enhanced Neural Point-Based Graphics for Novel View Synthesis in Autonomous Driving Scenes" (2025) [S1]. It addresses the scalability issues of 3D Gaussian Splatting when applied to large-scale autonomous driving datasets like KITTI-360 [S1]. The authors observed that standard 3DGS blends many unseen points, leading to unnecessary computation and memory usage [S1]. By introducing a connectivity relationship graph to filter visible points, they achieved better scene fitting and scalability [S1].
