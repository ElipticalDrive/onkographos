# Gaussian Splatting Volume Rendering

Also called: 3D Gaussian Splatting (3DGS), Volume Splatting

## Overview
Gaussian Splatting Volume Rendering is a differentiable rendering technique that synthesizes images by projecting 3D Gaussian kernels onto the image plane (splatting) and alpha-compositing them along viewing rays using a tile-based rasterization strategy [S1]. Unlike traditional triangle-based renderers or NeRFs, it uses explicit Gaussian probability distributions as primitives, enabling real-time performance and high-quality novel view synthesis [S2, S4, unofficial]. It sets itself apart from siblings like [Volume Encoding Gaussians](6093-volume-encoding-gaussians.md) by rasterizing Gaussians volumetrically to avoid the computational overhead of iterative ray marching [S4, unofficial], and from [BRDF and Relighting Extensions](6227-brdf-and-relighting-extensions.md) by typically using an emission-absorption model that bakes lighting into spherical harmonics, limiting direct relighting capabilities [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $M$ 3D Gaussians $\mathcal{G} = \{G_i\}_{i=1}^M$ stored in a PLY file or in-memory structure, and camera parameters (view and projection matrices).
*   **Output:** A 2D image (RGB) and optionally depth or other auxiliary channels.

**Data Structures:**
The core primitive is the `GaussianSplat` struct [S2, unofficial]. While the parent article defines the geometric covariance $\mathbf{\Sigma}_i$, the rendering implementation stores reparameterized attributes for optimization stability [S2, unofficial]:

```python
# Pseudocode for GaussianSplat layout (based on [S2, unofficial])
struct GaussianSplat:
    centroid: vec3          # World-space position (x, y, z)
    opacity: float          # Scalar opacity (0.0 to 1.0)
    spherical_harmonics: array[float, 48] # 16 coefficients * 3 RGB channels
    scale: array[float, 3]  # Log-space scale factors (log(s_x), log(s_y), log(s_z))
    rotation: array[float, 4] # Quaternion (w, x, y, z)
```

**Number of Gaussians:**
Typically 200,000–500,000 for complex scenes [S1].

**Steps:**

1.  **Load Scene:** Parse the PLY file into an array of `GaussianSplat` objects [S2, unofficial].
2.  **Project Gaussians:** For each Gaussian $i$, transform the centroid $\mathbf{p}_i$ to camera space. Compute the projected 2D covariance $\mathbf{\hat{\Sigma}}_i$ using the Jacobian $J$ of the affine approximation of the projection and the rotation part $W$ of the extrinsic matrix:
    $$ \mathbf{\hat{\Sigma}}_i = J W \mathbf{\Sigma}_i W^T J^T $$
    [G]. Note: $\mathbf{\Sigma}_i$ is reconstructed from the stored scale and rotation: $\mathbf{\Sigma}_i = \mathbf{R}_i \mathbf{S}_i \mathbf{S}_i^\top \mathbf{R}_i^\top$, where $\mathbf{S}_i = \text{diag}(\exp(\text{scale}_i))$ and $\mathbf{R}_i$ is derived from the quaternion [S2, unofficial].
3.  **Rasterize (Splat):** Project the 2D Gaussian onto the image plane. Use a tile-based rasterization strategy to parallelize this step [S1]. Determine the bounding quad for each Gaussian in screen space.
4.  **Sort:** Sort the Gaussians intersecting each pixel (or tile) by depth (z-coordinate in camera space) [S1].
5.  **Compute Color:** For each Gaussian $i$ and pixel $p$, compute the view-dependent color $c_i$ using spherical harmonics (SH) [S2, unofficial]:
    $$ \text{rgb} = \text{vec3}(0.5) $$
    $$ \text{for } k \in 0 \dots 15: \quad \text{rgb} += \text{sh\_coefficients}[k] \times \text{sh\_basis}(k, \mathbf{d}) $$
    $$ \text{rgb} = \text{clamp}(\text{rgb}, 0.0, 1.0) $$
    where $\mathbf{d}$ is the viewing direction from the camera to the centroid [S2, unofficial].
    *Note: Some volumetric variants use isotropic volumes with base colors instead of SH to avoid view-dependent shifts, but standard 3DGS uses SH [S3, unofficial].*
6.  **Alpha Composite:** Compute the final intensity $I_f$ at pixel $p$ by alpha-compositing the sorted Gaussians [S1]:
    $$ I_f \approx \sum_{i=1}^N c_i \tilde{\sigma}_i \tilde{\mathcal{G}}_i(\mathbf{p}) \prod_{j=1}^{i-1} \left(1 - \tilde{\sigma}_j \tilde{\mathcal{G}}_j(\mathbf{p})\right) $$
    where:
    *   $N$ is the number of Gaussians intersecting the ray.
    *   $c_i$ is the color of Gaussian $i$.
    *   $\tilde{\sigma}_i$ is the opacity of Gaussian $i$.
    *   $\tilde{\mathcal{G}}_i(\mathbf{p})$ is the 2D Gaussian value at pixel $p$:
        $$ \tilde{\mathcal{G}}_i(\mathbf{p}) = \exp\left(-\frac{1}{2} (\mathbf{p} - \mathbf{\hat{\mu}}_i)^T \mathbf{\hat{\Sigma}}_i^{-1} (\mathbf{p} - \mathbf{\hat{\mu}}_i)\right) $$
        where $\mathbf{\hat{\mu}}_i$ is the projected 2D centroid [S1].
    *   The product term represents the transmittance from previous Gaussians $j < i$ [S1].

**Parameters:**
*   `SH_COUNT`: 16 (number of SH coefficients per channel) [S2, unofficial].
*   `SH_CHANNEL_COUNT`: 3 (RGB) [S2, unofficial].
*   `SH_FLOAT_COUNT`: 48 (total coefficients) [S2, unofficial].
*   `smoke_density_factor`: 600 (used in specific volumetric implementations for density scaling) [S3, unofficial].
*   `ray_tracing_step_size_factor`: 0.5 (used in hybrid ray-tracing extensions for step size) [S3, unofficial].

**Edge Cases and Pitfalls:**
*   **Aliasing:** High-frequency content causes aliasing artifacts. 3DGS uses a dilation-based filter to reduce these, but it may fail with varying focal lengths or camera distances [S1]. MIP-Splatting introduces 2D/3D Gaussian filters for robustness [S1].
*   **Covariance Validity:** Directly updating the entries of $\mathbf{\Sigma}$ during training does not guarantee it remains positive semi-definite (PSD). Using scale and rotation parameters ensures the reconstructed $\mathbf{\Sigma}$ is always a valid covariance matrix [S2, unofficial].
*   **Color Dimness:** If using isotropic volume rendering without SH, scenes may appear dimmer and less vibrant because view-dependent color shifts are lost [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(M \log M)$ for sorting Gaussians, where $M$ is the number of Gaussians. Rasterization is $O(N)$ per pixel, where $N$ is the number of splats per pixel.
*   **Memory Complexity:** $O(M)$, storing centroid, opacity, SH coefficients, scale, and rotation per Gaussian [S1]. Memory demands are significant (200k–500k Gaussians) compared to NeRFs [S1].
*   **Performance:** Demonstrates up to 100x speedups in interactive applications compared to traditional ray marching [S4, unofficial]. Achieves real-time performance through explicit storage and rasterization [S4, unofficial].
*   **Strengths:** Real-time rendering, high visual quality, explicit scene representation.
*   **Limitations:** High memory usage, limited relighting capabilities due to emission-absorption model baking lighting into SH coefficients [S1], aliasing artifacts without filtering [S1].

## Background
Originating from radiance field representations in 2023, 3D Gaussian Splatting was introduced as a method for 3D reconstruction from posed images using Gaussian splats instead of triangles [S2, S4, unofficial]. Extensions to volumetric rendering by 2025 achieved real-time performance by rasterizing Gaussians volumetrically [S4, unofficial]. It is widely used in novel view synthesis, avatar creation, and surface reconstruction [S1].
