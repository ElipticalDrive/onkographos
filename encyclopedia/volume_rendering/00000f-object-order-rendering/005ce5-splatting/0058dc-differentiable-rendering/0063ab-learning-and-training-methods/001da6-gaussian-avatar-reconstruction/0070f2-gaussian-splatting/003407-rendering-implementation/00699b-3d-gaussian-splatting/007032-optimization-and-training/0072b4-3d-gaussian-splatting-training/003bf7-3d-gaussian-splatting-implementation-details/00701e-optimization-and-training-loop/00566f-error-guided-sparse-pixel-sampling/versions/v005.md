# Error-Guided Sparse Pixel Sampling

Also called: Err-SPS, Tile-Wise Pixel Sampling (EPS), Tile-wise Sparse Pixel Sampling, sparse pixel training

## Overview
Error-Guided Sparse Pixel Sampling (Err-SPS) is a training acceleration strategy for 3D Gaussian Splatting that restricts loss evaluation and gradient computation to a sparse subset of pixels per tile, guided by persistent error and age maps [S1, unofficial]. It solves the problem of redundant gradient computation in well-reconstructed regions by reallocating optimization effort to perceptually informative, challenging pixels [S1, unofficial]. Unlike random sampling methods, Err-SPS prioritizes high-error regions to preserve high-frequency details, avoiding the quality degradation associated with uniform sparse sampling [S1, unofficial].

## How it works
**Inputs:**
*   Set of training views $V_t$ for the current tile $t$.
*   Current Gaussian set $\mathcal{G}$.
*   Persistent per-pixel error map $E$ and age map $\Theta$ (initialized to zero or small values).
*   Ground-truth images $I$.
*   Sampling rate parameters $K_t$ (number of pixels) and $r_t$ (rate).

**Outputs:**
*   Sparse set of sampled pixels $P_{t,v}$ for each view $v \in V_t$.
*   Gradients $\nabla \mathcal{G}$ computed only over $P_{t,v}$.

**Data Structures:**
*   **Error Map ($E$):** A 2D array (or tile-aligned buffer) storing the running average reconstruction error for each pixel.
*   **Age Map ($\Theta$):** A 2D array storing the number of iterations since a pixel was last sampled or updated, used to prevent starvation of low-error pixels.
*   **Sampled Pixel Set ($P_{t,v}$):** A list of $(u, v)$ coordinates for view $v$ in tile $t$.

**Algorithm Steps:**
1.  **Initialize Statistics:** At the start of training, initialize error map $E$ and age map $\Theta$ to zero.
2.  **Query Sampling Schedule:** Determine the target number of pixels $K_t$ and sampling rate $r_t$ based on training progress $\rho_t$ [S1, unofficial].
3.  **Tile-Wise Pixel Sampling:** For each tile $t$ and view $v \in V_t$:
    *   Identify candidate pixels within the tile.
    *   Compute a sampling probability or priority score for each pixel based on $E$ and $\Theta$. High error increases priority; high age increases priority (to ensure coverage).
    *   Select the top $K_t$ pixels (or a fraction $r_t$ of total pixels) to form $P_{t,v}$ [S1, unofficial].
4.  **Sparse Forward Rendering:** Render the scene using the standard 3DGS rasterizer, but restrict the accumulation and output to the sampled pixels $P_{t,v}$ [S1, unofficial]. This preserves tile-parallel execution.
5.  **Compute Sparse Loss:** Calculate the loss $\mathcal{L}$ only over the sampled pixels $P_{t,v}$ [S1, unofficial]:
    $$ \mathcal{L} = \mathbb{E}_{v \in V_t, p \in P_{t,v}} [\ell_1(p)] + \mathbb{E}_{v \in V_t, \tau} \lambda_\tau^{ncc} L_\tau^{S-NCC} $$
    where $\ell_1(p)$ is the L1 loss at pixel $p$, $\lambda_\tau^{ncc}$ is a weighting coefficient, and $L_\tau^{S-NCC}$ is a sparse Normalized Cross-Correlation term [S1, unofficial].
6.  **Update Error and Age Maps:** Update $E$ and $\Theta$ using an Exponential Moving Average (EMA) of the computed losses and sampling events [S1, unofficial].
7.  **Sparse Backward Pass:** Compute gradients $\nabla \mathcal{G}$ using a per-Gaussian backward mechanism. This restricts gradient computation to Gaussians that contribute to the sampled pixels $P_{t,v}$, enabling efficient splat-parallel computation [S1, unofficial].
8.  **Optimize:** Update Gaussian parameters using the optimizer (e.g., Adam or a hybrid solver) [S1, unofficial].

**Pseudocode:**
```python
# Initialization
E = zeros(H, W)  # Error map
Theta = zeros(H, W)  # Age map
G = initialize_gaussians()

for iteration in range(max_iterations):
    # 1. Query sampling parameters based on progress rho
    K_t, r_t = query_sampling_schedule(K_max, K_min, E_init, Theta, iteration)
    
    # 2. View Selection (Optional Geometry-Aware, but core is pixel sampling)
    V_t = select_views() 
    
    # 3. Tile-Wise Sparse Pixel Sampling
    P_t = {} # Dictionary: view -> list of pixels
    for v in V_t:
        # Get candidates in tile t for view v
        candidates = get_tile_pixels(v, t)
        
        # Compute sampling weights based on Error and Age
        # Higher error -> higher weight. Higher age -> higher weight.
        weights = compute_sampling_weights(E[candidates], Theta[candidates])
        
        # Sample K_t pixels (or r_t fraction)
        # Implementation note: Use weighted random sampling or top-k selection
        P_t[v] = sample_pixels(candidates, weights, K_t)
        
    # 4. Sparse Forward Rendering
    # Render only for pixels in P_t
    rendered_colors = {}
    rendered_depths = {}
    for v in V_t:
        rendered_colors[v], rendered_depths[v] = rasterize_forward(G, v, P_t[v])
        
    # 5. Compute Sparse Loss
    loss = 0.0
    pixel_losses = {} # Store per-pixel losses for EMA update
    for v in V_t:
        gt_colors = get_gt_colors(v, P_t[v])
        # L1 Loss
        l1_loss = mean(abs(rendered_colors[v] - gt_colors))
        loss += l1_loss
        
        # Sparse NCC Loss (optional but recommended)
        ncc_loss = compute_sparse_ncc(rendered_depths[v], gt_depths, P_t[v])
        loss += lambda_ncc * ncc_loss
        
        pixel_losses[v] = l1_loss # Store for error map update
        
    # 6. Update Error and Age Maps (EMA)
    for v in V_t:
        for p in P_t[v]:
            # Update error with EMA
            E[p] = alpha * pixel_losses[v][p] + (1 - alpha) * E[p]
            # Reset age for sampled pixels
            Theta[p] = 0
        # Increment age for unsampled pixels in the tile/view
        for p in all_pixels_in_tile(v, t):
            if p not in P_t[v]:
                Theta[p] += 1
                
    # 7. Sparse Backward Pass
    # Compute gradients only for Gaussians affecting P_t
    grads = compute_gradients_backward(G, rendered_colors, gt_colors, P_t)
    
    # 8. Update Gaussians
    G = optimizer_step(G, grads)
```

**Parameters:**
*   $\lambda_\tau^{ncc}$: Weight for sparse NCC loss. Not given in the sources.
*   $\alpha$: EMA decay factor for error map. Not given in the sources.
*   $K_t$: Number of pixels to sample per tile. Scales with training progress.
*   $r_t$: Sampling rate.

**Edge Cases and Pitfalls:**
*   **Relying solely on sparse-pixel L1 supervision degrades reconstruction quality**, particularly high-frequency details [S1, unofficial]. It requires complementary geometry-aware view sampling and sparse NCC regularization [S1, unofficial].
*   **Random Pixel Sampling (RPS)** as a substitute for Err-SPS causes failure to preserve high-frequency details and drops in PSNR [S1, unofficial].
*   **Starvation:** If age is not considered, pixels with consistently low error may never be sampled, leading to stagnation in those regions.

## Subtopics

### TurboGS
The primary framework that introduces Err-SPS. It combines Err-SPS with geometry-aware view sampling, sparse NCC regularization, error-driven density control, and a hybrid optimizer. Choose TurboGS when maximum training speed is required without significant quality loss. [TurboGS](15697-turbogs.md)

### 3D Gaussian Splatting Training Loop
The baseline method that renders and optimizes over all pixels. Choose this for maximum quality when training time is not a constraint. [3D Gaussian Splatting Training Loop](15139-3d-gaussian-splatting-training-loop.md)

## Operating characteristics
*   **Time Complexity:** Significantly reduced compared to full pixel rendering. On Mip-NeRF 360, Err-SPS reduces training time from 891s to 85s [S1, unofficial].
*   **Memory Complexity:** Reduced memory usage for gradient computation and rasterization buffers, as only sampled pixels are processed. Number of Gaussians (NGS) processed drops from 2.73M to 0.76M [S1, unofficial].
*   **Strengths:** Accelerates training by 10x or more; reallocates computation to informative pixels; preserves high-frequency details when combined with NCC.
*   **Limitations:** May introduce subtle rippling artifacts in low-frequency regions with weak texture variations (e.g., walls or ceilings) if sparse supervision is not balanced [S1, unofficial]. Requires careful tuning of error and age map updates.
*   **When to use:** When training time is a bottleneck and the scene has varying levels of reconstructability.
*   **When not to use:** When maximum photometric accuracy is required regardless of training time, or in scenes with uniformly low texture where error maps may not be informative.

## Background
Err-SPS was introduced in the TurboGS paper by Hanson et al. in 2026 (preprint) [S1, unofficial]. It addresses the observation that as 3DGS training progresses, only a small subset of pixels remains difficult to reconstruct, while most become well-explained and yield marginal gradients [S1, unofficial]. The method builds on the tile-wise rasterization structure of 3DGS and adapts it for sparse supervision.
