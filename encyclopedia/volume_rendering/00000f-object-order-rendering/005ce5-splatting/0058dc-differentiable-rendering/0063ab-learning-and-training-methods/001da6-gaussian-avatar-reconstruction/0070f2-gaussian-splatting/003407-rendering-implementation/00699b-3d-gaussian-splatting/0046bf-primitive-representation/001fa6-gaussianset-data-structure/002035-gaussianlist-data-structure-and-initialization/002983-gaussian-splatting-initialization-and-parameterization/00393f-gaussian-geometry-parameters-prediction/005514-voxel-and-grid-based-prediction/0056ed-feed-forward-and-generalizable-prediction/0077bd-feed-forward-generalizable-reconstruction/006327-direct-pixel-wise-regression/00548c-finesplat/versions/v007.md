# FineSplat

Also called: Detailed Splats, Fine Patches, Local Groups

## Overview
FineSplat is a feed-forward 3D Gaussian Splatting framework that predicts a set of 3D Gaussians from $N$ context views using a two-stage dual-grouping strategy to balance local detail preservation with global multi-view reasoning [S1, unofficial]. It builds on [Feed-forward and Generalizable Prediction](15832-feed-forward-and-generalizable-prediction.md) by employing high-resolution 4x4 patch tokens and a dual-grouping mechanism (view-wise and 3D spatial locality) to preserve fine-grained visual information while avoiding the computational costs of global multi-view attention [S1, unofficial]. Unlike sibling methods such as [YoNoSplat](12847-anysplat-pipeline.md) and [ZipSplat](16425-zerogs.md) which use coarser 14x14 patches and global or broader interactions, FineSplat restricts attention scope in Stage 1 and uses serialized attention in Stage 2 to connect tokens across view groups once lifted to 3D [S1, unofficial].

## How it works
**Inputs:** A set of $N$ RGB images $\{I_n\}_{n=1}^N$ with associated camera poses (intrinsics and extrinsics). The number of views $N$ is sampled from $\{6, 12, 24, 32\}$ during training and varies during evaluation [S1, unofficial].

**Outputs:** A set of 3D Gaussian primitives $\Theta = \{\mu_k, \Sigma_k, c_k, \alpha_k\}_{k=1}^K$, where $\mu_k$ is the mean, $\Sigma_k$ is the covariance (parameterized by scale and rotation), $c_k$ is the color (via spherical harmonics), and $\alpha_k$ is the opacity [S1, unofficial].

**Data Structures:**
1.  **Feature Maps:** Multi-scale feature maps $F^l \in \mathbb{R}^{N \times (H/p) \times (W/p) \times d_l}$ for $l \in \{1, 2, 3\}$, where $l=1$ is the finest scale and $l=3$ is the coarsest. $p$ is the patch size (4) [S1, unofficial].
2.  **Tokens:** A set of $M$ fine-grained tokens $z \in \mathbb{R}^{M \times d}$, where $M = N \cdot (H/p) \cdot (W/p)$ [S1, unofficial].
3.  **Gaussians:** $K$ Gaussian primitives predicted per token. Specifically, $K=4$ Gaussians are predicted per 4x4 token, assigned to non-overlapping 2x2 sub-patches [S1, unofficial].
4.  **Error Feature Maps:** $F_n^{err} \in \mathbb{R}^{(H/p) \times (W/p) \times d_e}$ for each view $n$, combining pixel and feature-level errors [S1, unofficial].

**Parameters:**
*   $p$: Patch size, set to 4 [S1, unofficial].
*   $T$: Number of iterative refinement steps in Stage 2, set to 4 [S1, unofficial].
*   $s$: Sub-patch stride, set to 2 [S1, unofficial].
*   $S$: Size of groups for serialized attention in 3D spatial grouping [S1, unofficial].
*   $K$: Number of Gaussian primitives per token (4) [S1, unofficial].

**Algorithm:**

1.  **Scene Normalization:** To handle scale ambiguity in feed-forward reconstruction, normalize scene scale using context camera poses. Express poses in the mean context camera frame. Rescale translations so that all context camera centers lie within $[-1, 1]^3$. Apply the same transform to target poses [S1, unofficial].

2.  **Stage 1: View-wise Token Grouping:**
    *   Extract multi-scale features $F^1, F^2, F^3$ from input images using a backbone (e.g., MVP architecture) [S1, unofficial].
    *   Fuse features into initial tokens $z^{(0)}$ using Equation (1):
        $$ z^{(0)} = \text{fuse}\left(\text{up}\left(\text{fuse}\left(\text{up}(F^3) + F^2\right)\right)\right) + F^1 $$
        where $\text{up}(\cdot)$ is bilinear upsampling and $\text{fuse}(\cdot)$ is a convolutional fusion block [S1, unofficial].
    *   Perform view-wise token grouping. Divide views into groups. Apply attention within small view groups and exchange information across all views via coarser global tokens. This restricts attention scope to keep fine-grained multi-view reasoning affordable [S1, unofficial].

3.  **Stage 2: 3D Spatial Token Grouping (Iterative Refinement):**
    *   Initialize $z = z^{(0)}$.
    *   For $t = 1$ to $T$:
        1.  **Gaussian Prediction:** Decode tokens $z$ into an initial set of Gaussians using a lightweight linear Gaussian head $\mathcal{D}$. For each 4x4 token, predict 4 Gaussians.
        2.  **Patch-Aligned Sub-Pixel Gaussian Reconstruction:**
            *   Assign each of the 4 Gaussians to a non-overlapping 2x2 sub-patch of the 4x4 token.
            *   Learn a 2D image-space offset $\Delta = (\Delta_x, \Delta_y)$ for each Gaussian.
            *   Bound the offset to keep the Gaussian within its sub-patch:
                $$ \delta_x = 2s \tanh(\Delta_x), \quad \delta_y = 2s \tanh(\Delta_y) $$
                where $s=2$. This ensures $\delta_x, \delta_y \in [-s/2, s/2]$ [S1, unofficial].
            *   For a sub-patch with center $(u_c, v_c)$, compute displaced coordinate $(u, v) = (u_c, v_c) + \delta$.
            *   Unproject $(u, v)$ using predicted camera intrinsics to get a ray direction. Transform and normalize the direction using camera-to-world rotation. Use camera translation as ray origin to determine $\mu$ [S1, unofficial].
        3.  **Differentiable Rendering:** Render the predicted Gaussians into every context view $n$ to obtain rendered images $\hat{I}_n$ [S1, unofficial].
        4.  **Error Feature Computation:**
            *   Compute signed pixel error map: $E_n = \hat{I}_n - I_n$ [S1, unofficial].
            *   Compute feature-level difference: $\Delta\phi_n = \phi(\hat{I}_n) - \phi(I_n)$, where $\phi(\cdot)$ is a pretrained ResNet-18 encoder [S1, unofficial].
            *   Combine with finest-scale features $F_n^1$ from Stage 1:
                $$ F_n^{err} = [E_{err}(E_n, \Delta\phi_n); E_{feat}(F_n^1)] \in \mathbb{R}^{(H/p) \times (W/p) \times d_e} $$
                where $E_{err}$ and $E_{feat}$ are linear embedding layers, and $[\cdot; \cdot]$ is concatenation [S1, unofficial].
        5.  **Error Aggregation:** For each token, gather two error signals:
            *   Self error feature $e_{self}$ from the patch where the token was predicted.
            *   Aggregated error feature $e_{agg}$ averaged over all context views where the token is visible (projected onto error feature maps and filtered by frustum/occlusion) [S1, unofficial].
        6.  **3D Spatial Grouping:**
            *   Lift tokens to 3D space using their predicted Gaussian centers.
            *   Order tokens along a space-filling curve.
            *   Partition tokens into groups of $S$ consecutive points.
            *   Apply serialized self-attention within each group. Use four attention blocks in Stage 2, each using a different space-filling curve, so each token meets a different set of neighbors [S1, unofficial].
            *   Update tokens:
                $$ \Delta z_j^{(i)} = \text{Linear}(\text{SerialAttn}(h_j^{(i)})) $$
                $$ z_j^{(i+1)} = z_j^{(i)} + \Delta z_j^{(i)} $$
                where $h_j^{(i)}$ includes the token features and aggregated error signals [S1, unofficial].
    *   Final Gaussians are decoded from the final tokens $z^{(T)}$ [S1, unofficial].

**Training:**
*   Train end-to-end using photometric losses (Mean Squared Error and perceptual term) on rendered views [S1, unofficial].
*   No depth supervision is used [S1, unofficial].
*   Train on DL3DV dataset. Sample $N \in \{6, 12, 24, 32\}$ context views per scene [S1, unofficial].

**Pitfalls:**
*   **Blind Spots:** Fixed view grouping in Stage 1 leaves blind spots where fine-grained tokens in different groups cannot interact. Stage 2 3D spatial grouping connects these tokens once lifted to 3D [S1, unofficial].
*   **Scale Ambiguity:** Feed-forward reconstruction suffers from scale ambiguity. Handled by normalizing scene scale using context camera poses as described in Step 1 [S1, unofficial].
*   **Diminishing Returns:** Quality improves with more Stage 2 steps, but going beyond $T=4$ yields no further gain [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** FineSplat is efficient due to the dual-grouping strategy. Stage 1 uses local view-wise attention, and Stage 2 uses serialized attention with space-filling curves, which scales favorably with token count compared to explicit k-nearest-neighbor search [S1, unofficial]. It is faster than [ZipSplat](16425-zerogs.md) and [YoNoSplat](12847-anysplat-pipeline.md) for 6 and 12 input views, and still faster than ZipSplat for 24 views [S1, unofficial].
*   **Memory Complexity:** Uses a small primitive budget. On DL3DV with 6 views, it uses 62K Gaussians [S1, unofficial]. On Mip-NeRF 360 with 128 views, it uses 1.6M Gaussians [S1, unofficial].
*   **Performance:**
    *   DL3DV (6 views): 27.325 PSNR, 0.871 SSIM, 0.115 LPIPS [S1, unofficial].
    *   RE10K (6 views): 27.394 PSNR, 0.886 SSIM, 0.116 LPIPS [S1, unofficial].
    *   Mip-NeRF 360 (128 views): 23.463 PSNR, 0.706 SSIM, 0.214 LPIPS [S1, unofficial].
*   **Strengths:** Preserves fine-grained visual information with 4x4 patches while avoiding global attention costs. Strong zero-shot generalization. High quality per unit of time.
*   **Limitations:** Requires known camera poses for scene normalization and ray unprojection. Performance on Mip-NeRF 360 (indoor/outdoor mix) is lower than on DL3DV, possibly due to domain shift [S1, unofficial].

## Background
FineSplat was introduced in 2026 by [S1, unofficial]. It addresses the trade-off between fine-grained detail and computational efficiency in feed-forward 3D Gaussian Splatting. It is trained on the DL3DV dataset and evaluated on DL3DV, RealEstate10K, and Mip-NeRF 360 for novel view synthesis [S1, unofficial].
