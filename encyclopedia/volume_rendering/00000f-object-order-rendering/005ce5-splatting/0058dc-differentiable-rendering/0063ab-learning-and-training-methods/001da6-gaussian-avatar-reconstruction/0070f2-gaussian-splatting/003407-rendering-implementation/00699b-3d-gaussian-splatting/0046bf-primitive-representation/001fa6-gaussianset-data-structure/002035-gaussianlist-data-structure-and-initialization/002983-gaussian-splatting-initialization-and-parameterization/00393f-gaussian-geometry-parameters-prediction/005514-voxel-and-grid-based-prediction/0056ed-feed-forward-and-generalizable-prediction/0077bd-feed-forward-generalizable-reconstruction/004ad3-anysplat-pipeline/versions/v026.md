# AnySplat Pipeline

Also called: Feed-forward 3D Gaussian Splatting from Unconstrained Views

## Overview
AnySplat is a feed-forward, generalizable reconstruction method that predicts a set of 3D Gaussians directly from uncalibrated input images, eliminating the need for per-scene optimization [S1, unofficial]. It distinguishes itself from sibling methods by predicting camera poses and depth maps alongside Gaussian parameters, using pseudo-geometry priors from a pretrained Vision Transformer (VGGT) to supervise the geometry, thereby enabling robust reconstruction from unconstrained, uncalibrated views [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A batch of $K$ uncalibrated RGB images $I \in \mathbb{R}^{1 \times K \times 3 \times 448 \times 448}$ [S1, unofficial].
*   **Outputs:** A set of 3D Gaussians $\mathcal{G}$ (defined by mean $\mu$, scale $s$, rotation $r$, opacity $\alpha$, and color $c$) and predicted camera poses (extrinsic $E$ and intrinsic $K$) [S1, unofficial].

**Data Structures:**
The method constructs pixel-wise 3D Gaussians. Each Gaussian is parameterized by:
*   $\mu \in \mathbb{R}^3$: 3D position.
*   $s \in \mathbb{R}^3$: Scale (log-space or linear, source implies standard Gaussian Splatting parameterization).
*   $r \in \mathbb{R}^4$: Rotation (quaternion).
*   $\alpha \in [0, 1]$: Opacity.
*   $c$: Color (Spherical Harmonics coefficients or RGB).

**Steps:**
1.  **Feature Encoding:** Input images are processed by a transformer-based geometry encoder to extract multi-scale features [S1, unofficial].
2.  **Parameter Prediction:** Three decoder heads ($F_G, F_D, F_C$) predict:
    *   $F_G$: Gaussian parameters $(\mu, \sigma, r, s, c)$ [S1, unofficial]. Note: $\sigma$ likely refers to scale or covariance components.
    *   $F_D$: Depth map $D$.
    *   $F_C$: Camera poses $p$ (extrinsic and intrinsic matrices) [S1, unofficial].
3.  **Gaussian Construction:** The predicted parameters are used to construct a set of pixel-wise 3D Gaussians [S1, unofficial].
4.  **Differentiable Voxelization:** The pixel-wise Gaussians are voxelized into "pre-voxel 3D Gaussians" using a Differentiable Voxelization module [S1, unofficial]. This step aggregates overlapping Gaussians and handles density.
5.  **Rendering:** Multi-view images and depth maps are rendered from the voxelized Gaussians using differentiable rasterization [S1, unofficial].
6.  **Loss Computation:**
    *   **RGB Loss:** Rendered images are compared against ground truth images using an RGB loss (e.g., L1 or LPIPS) [S1, unofficial].
    *   **Geometry Loss:** Rendered depth maps, decoded depth $D$, and predicted poses $p$ are used to compute geometry losses [S1, unofficial].
    *   **Pseudo-Geometry Supervision:** The predicted geometries are supervised by pseudo-geometry priors obtained from a pretrained VGGT model [S1, unofficial]. This provides a strong prior for depth and pose consistency without requiring ground-truth poses for every training scene.

**Pseudocode:**
```python
import torch

def anysplat_pipeline(images, model):
    """
    images: torch.Tensor of shape [1, K, 3, 448, 448]
    model: AnySplat model instance
    """
    # Preprocess images to [-1, 1] range if necessary, though source uses (images+1)*0.5
    # Source code shows: model.inference((images+1)*0.5)
    # Assuming input images are in [0, 1] range for this normalization
    normalized_images = (images + 1.0) * 0.5
    
    # Run inference to get Gaussians and predicted poses
    gaussians, pred_context_pose = model.inference(normalized_images)
    
    # Extract predicted poses
    pred_all_extrinsic = pred_context_pose['extrinsic']
    pred_all_intrinsic = pred_context_pose['intrinsic']
    
    # Gaussians are now ready for rendering or saving
    return gaussians, pred_all_extrinsic, pred_all_intrinsic
```

**Parameters:**
*   Input resolution: $448 \times 448$ [S1, unofficial].
*   Number of views $K$: Not specified, but typically small (e.g., 3-5) for unconstrained inputs [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Uncalibrated Inputs:** The method must handle varying intrinsic and extrinsic parameters. The prediction of poses is critical and relies on the VGGT prior [S1, unofficial].
*   **Voxelization Artifacts:** The Differentiable Voxelization module must handle overlapping Gaussians correctly to avoid density artifacts [S1, unofficial].

## Subtopics

### [SubSplat](13524-subsplat.md)
SubSplat is a method for high-resolution novel-view synthesis that resolves the trade-off between network computational cost and rendering fidelity in pixel-aligned 3D Gaussian Splatting. It solves the problem of insufficient Gaussian density and artifacts when using low-resolution backbone inputs by introducing a Sub-pixel Gaussian Reparameterizer (SPGR). Unlike prior methods limited by fixed grids or image-space upsamplers, SubSplat subdivides each grid-anchored primary Gaussian into multiple fine-grained sub-pixel primitives, restoring structural density directly from low-resolution features while maintaining stable network latency.

### [Deformable Radial Kernel (DRK)](13699-deformable-radial-kernel-drk.md)
Deformable Radial Kernel (DRK) Splatting is a 3D scene representation method that replaces the fixed radial symmetry of Gaussian primitives with a flexible planar kernel defined by multiple radial basis functions. It solves the overparameterization and geometric fidelity limitations of Gaussian Splatting by allowing adaptive stretching, rotation, and sharp boundary control, enabling high-fidelity rendering with significantly fewer primitives. Unlike standard 2D Gaussian Splatting, which relies on smooth, elliptical distributions, DRK supports straight edges and sharp corners through L1/L2 norm blending and piecewise edge sharpening.

## Operating characteristics
*   **Time Complexity:** Inference is feed-forward, making it significantly faster than per-scene optimization methods like original 3D Gaussian Splatting. The exact time depends on the transformer encoder and decoder heads, but it is designed for real-time or near-real-time performance [S1, unofficial].
*   **Memory Complexity:** Memory usage is dominated by the transformer encoder/decoder and the storage of the predicted Gaussians. The voxelization step may require additional memory for the voxel grid [S1, unofficial].
*   **Performance:** The method achieves high-quality novel-view synthesis from unconstrained views, leveraging the VGGT prior for geometry [S1, unofficial].
*   **Strengths:** No per-scene optimization required; handles uncalibrated inputs; robust geometry via VGGT prior.
*   **Limitations:** Relies on the quality of the VGGT prior; performance may degrade on scenes with extreme outliers or non-Lambertian surfaces not captured by the prior [S1, unofficial].

## Background
AnySplat was introduced by InternRobotics as a feed-forward generalizable reconstruction method [S1, unofficial]. It builds on the principles of 3D Gaussian Splatting and generalizable neural rendering, aiming to simplify the reconstruction pipeline by predicting all necessary parameters (including poses) in a single forward pass [S1, unofficial].
