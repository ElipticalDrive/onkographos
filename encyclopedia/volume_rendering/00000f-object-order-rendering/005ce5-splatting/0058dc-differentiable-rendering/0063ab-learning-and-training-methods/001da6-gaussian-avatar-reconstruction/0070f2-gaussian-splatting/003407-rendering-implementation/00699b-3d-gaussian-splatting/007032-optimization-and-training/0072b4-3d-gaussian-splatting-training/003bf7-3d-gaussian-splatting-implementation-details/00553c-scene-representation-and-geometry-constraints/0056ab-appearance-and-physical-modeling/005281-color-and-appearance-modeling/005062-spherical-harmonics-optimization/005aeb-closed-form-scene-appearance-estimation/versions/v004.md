# Closed-Form Scene Appearance Estimation

Also called: Global LLS System, Normal System Solution

## Overview
Closed-Form Scene Appearance Estimation solves the problem of estimating view-dependent spherical harmonic (SH) coefficients for mesh vertices by formulating a global weighted least-squares problem across all calibrated input views [S1, unofficial]. It differs from iterative optimization methods by providing an analytical solution to the normal system, utilizing adaptive regularization to handle varying view support and a matrix-free Preconditioned Conjugate Gradient (PCG) solver to avoid explicit matrix inversion [S1, unofficial].

## How it works
**Inputs:** A textured mesh $M$ with $N_v$ vertices, $K$ calibrated RGB images $\{I_k\}_{k=1}^K$, SH degree $L$ (typically up to order 2 for real-time constraints), regularization strengths $\gamma_s$ (supported) and $\gamma_u$ (under-supported), and solver parameters (tolerance $\delta$, max iterations $T_{max}$) [S1, unofficial].
**Outputs:** Estimated SH coefficients $X^*$ for each vertex [S1, unofficial].

**Data Structures:**
*   **Rasterization Records ($R$):** Stores per-pixel data including vertex indices $i_{s,k,r}$, SH basis features $\phi_{s,k,r}$, and confidence weights $w_{k,r}$ [S1, unofficial].
*   **Global Matrices:**
    *   $A \in \mathbb{R}^{(K \cdot H \cdot W) \times (q N_v)}$: The design matrix, where $q$ is the number of SH coefficients per vertex and $N_v$ is the number of vertices.
    *   $B \in \mathbb{R}^{(K \cdot H \cdot W) \times 3}$: The observation matrix containing RGB pixel values.
    *   $W \in \mathbb{R}^{(K \cdot H \cdot W) \times (K \cdot H \cdot W)}$: A diagonal matrix of confidence weights.
    *   $\Lambda \in \mathbb{R}^{(q N_v) \times (q N_v)}$: Block-diagonal regularization matrix [S1, unofficial].

**Steps:**

1.  **Initialization:** Initialize rasterization records $R$ and view counts $\{n^v_i\}_{i=1}^{N_v}$ to zero [S1, unofficial].
2.  **Per-View Rasterization:** For each view $k = 1 \dots K$:
    a. Rasterize mesh $M$ to establish pixel-to-triangle correspondence. Initialize per-view matrix $A_k$ [S1, unofficial].
    b. For each valid pixel $p_{k,r}$:
        i. Retrieve the SH features $\{i_{s,k,r}, \lambda_{s,k,r}\}_{s=0}^2$ associated with the covering triangle/vertex [S1, unofficial].
        ii. Compute the SH basis evaluation: $\phi_{s,k,r} \leftarrow \lambda_{s,k,r} Y(d_k)$, where $Y(d_k)$ is the SH basis vector for direction $d_k$ [S1, unofficial].
        iii. Set the row in $A_k$ corresponding to pixel $r$ and vertex index $i_{s,k,r}$: $[A_k]_{r, i_{s,k,r}} \leftarrow (\phi_{s,k,r})^\top$ [S1, unofficial].
        iv. Compute confidence weight $w_{k,r}$ based on viewing angle (e.g., grazing angle down-weighting) [S1, unofficial].
        v. Store $\{i_{s,k,r}, \phi_{s,k,r}\}_{s=0}^2$ and $w_{k,r}$ in $R$ [S1, unofficial].
    c. Construct observation vector $B_k \leftarrow [I_k(p_{k,1}) \dots I_k(p_{k,HW})]^\top$ [S1, unofficial].
    d. Construct weight matrix $W_k \leftarrow \text{diag}(w_{k,1}, \dots, w_{k,HW})$ [S1, unofficial].
    e. Update view counts $\{n^v_i\}$ based on which vertices contributed to valid pixels [S1, unofficial].
3.  **Global Assembly:**
    a. Assemble global matrices: $A \leftarrow [A_1^\top \dots A_K^\top]^\top$, $B \leftarrow [B_1^\top \dots B_K^\top]^\top$, $W \leftarrow \text{blkdiag}(W_1, \dots, W_K)$ [S1, unofficial].
4.  **Regularization Construction:**
    a. For each vertex $i = 1 \dots N_v$:
        i. Construct regularization block $\Lambda_i$ using the view count $n^v_i$, $\gamma_s$, and $\gamma_u$ [S1, unofficial]. If $n^v_i$ is high, use $\gamma_s$; if low, use $\gamma_u$ [S1, unofficial].
    b. Assemble $\Lambda \leftarrow \text{blkdiag}(\Lambda_1, \dots, \Lambda_{N_v})$ [S1, unofficial].
5.  **Normal System Formation:**
    a. Compute $H \leftarrow A^\top W A + \Lambda$ [S1, unofficial].
    b. Compute $G \leftarrow A^\top W B$ [S1, unofficial].
    c. The system to solve is $H X^* = G$ [S1, unofficial].
6.  **Solution:** Solve for $X^*$ using a matrix-free PCG solver (see Pseudocode). Do not explicitly compute $H^{-1}$ [S1, unofficial].

**Formulas:**
*   **Normal System:**
    $$X^\star = \arg \min_X \| W^{1/2} (A X - B) \|_2^2 + \| \Lambda^{1/2} X \|_2^2$$
    Leading to:
    $$H X^\star = G, \quad H = A^\top W A + \Lambda, \quad G = A^\top W B$$
    Where $H \in \mathbb{R}^{qN_v \times qN_v}$ and $G \in \mathbb{R}^{qN_v \times 3}$ [S1, unofficial].
*   **Gradient-Guided Densification (Preprocessing):**
    To improve spatial resolution, triangles are subdivided based on image-space variation:
    $$S_j \triangleq \sum_{k=1}^K \sum_{p \in \Omega_{k,j}} \|\nabla I_k(p)\|^2$$
    Triangles with large $S_j$ are selected for subdivision [S1, unofficial].

**Parameters:**
*   $\gamma_s$: Supported SH regularization strength. Typical value: $0 < \gamma_s \ll \gamma_u$ [S1, unofficial].
*   $\gamma_u$: Under-supported SH regularization strength. Typical value: $\gamma_u \gg \gamma_s$ [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Explicit Inversion:** Explicitly forming $H^{-1}$ is computationally prohibitive for large scenes due to memory and time complexity. The method must use an iterative solver like PCG [S1, unofficial].
*   **Positive Definiteness:** The adaptive SH regularization ensures $\Lambda \succ 0$ and $W \succ 0$, guaranteeing $H \succ 0$ and a unique global minimizer [S1, unofficial].
*   **View Support:** Vertices with zero view support ($n^v_i = 0$) may result in singular blocks if not handled by the regularization term $\Lambda$ [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The global LLS solve is dominated by PCG iterations. Setup is $O(KHWq^2 + N_v q^3)$. Each PCG iteration is $O(KHWq + N_v q^2)$. Total solve time is $T_{solve} = O(KHWq^2 + N_v q^3) + O(T_{pcg}(KHWq + N_v q^2)) + O(KHWq + N_v q)$ [S1, unofficial].
*   **Memory Complexity:** Dominated by storing matrices $A$, $B$, $W$, and $\Lambda$. $A$ is sparse but large. $\Lambda$ is block diagonal.
*   **Strengths:** Analytical solution avoids local minima; adaptive regularization handles sparse views; PCG solver avoids explicit inversion.
*   **Limitations:** Requires all views to be available simultaneously (batch processing); sensitive to rasterization accuracy; preconditioning is critical for PCG convergence.
*   **When to use:** When high-quality view-dependent appearance is needed for mesh-based representations and computational resources allow for batch processing.
*   **When not to use:** For real-time streaming where incremental updates are required, or when memory is extremely constrained.
