# Gaussian Rasterization Key Generation

Also called: Gaussian Tile Key Generation, Gaussian Tile Overlap Key Generation, Gaussian to Tile Mapping, Gaussian-to-Tile Key Generation, duplicateWithKeys, duplicateWithKeys kernel

## Overview
This method generates key-value pairs for all Gaussians overlapping with tiles, enabling spatial sorting by tile ID and depth [S1, S2, S3, unofficial]. It identifies which tiles each projected 2D Gaussian overlaps and constructs a 64-bit sort key combining the tile ID and the Gaussian's depth [S1, S3, unofficial]. This output serves as the direct input for the global radix sort performed by the parent method [Tile-based Rasterization with Radix Sort](7921-tile-based-rasterization-with-radix-sort.md) [S1, S2, S3, unofficial]. It differs from sibling methods like [Tile-Based Culling](2819-tile-based-culling.md) by explicitly generating the full set of overlaps for sorting rather than just filtering, and from [Tile-based Depth Sorting](8038-tile-based-depth-sorting.md) by focusing on the key construction phase rather than the sorting algorithm itself [S1, S2, S3, unofficial].

## How it works
**Inputs:**
- `points_xy`: Array of shape $(N, 2)$ containing the 2D screen-space centers of $N$ Gaussians [S3, unofficial].
- `radii`: Array of shape $(N,)$ containing the radius of each Gaussian in pixels [S3, unofficial].
- `depths`: Array of shape $(N,)$ containing the camera-space depth $Z_c$ for each Gaussian [S1, S3, unofficial].
- `grid_width`: Integer specifying the number of tiles in the x direction [S3, unofficial].
- `grid_height`: Integer specifying the number of tiles in the y direction [S3, unofficial].
- `tile_size`: Integer, typically 16 pixels [Sibling: Tile-based Rasteriser].

**Outputs:**
- `gaussian_keys_unsorted`: Array of 64-bit integers (uint64_t), one per generated overlap [S1, S3, unofficial].
- `gaussian_values_unsorted`: Array of 32-bit integers (uint32_t), storing the original Gaussian index `idx` corresponding to each key [S1, S3, unofficial].
- `num_overlaps`: Integer count of total key-value pairs generated [S1, S3, unofficial].

**Data Structures:**
- Keys are packed 64-bit integers [S3, unofficial].
  - Bits [63:32] (Upper 32): 1D Tile ID, calculated as $y_{tile} \times W_{tiles} + x_{tile}$ [S1, S3, unofficial].
  - Bits [31:0] (Lower 32): Depth $Z_c$, cast to `uint32_t` [S1, S3, unofficial].
- Values are 32-bit integers storing the source Gaussian index `idx` [S1, S3, unofficial].

**Steps:**
1. Initialize empty lists `gaussian_keys_unsorted` and `gaussian_values_unsorted` [S1, S3, unofficial].
2. For each Gaussian index `idx` from $0$ to $N-1$:
   a. If any radius component is $\le 0$, skip this Gaussian [S1, unofficial].
   b. Calculate the bounding rectangle in tile coordinates:
      - $x_{min} = \lfloor (points\_xy[idx, 0] - radii[idx]) / tile\_size \rfloor$ [S3, unofficial].
      - $x_{max} = \lceil (points\_xy[idx, 0] + radii[idx]) / tile\_size \rceil$ [S3, unofficial].
      - $y_{min} = \lfloor (points\_xy[idx, 1] - radii[idx]) / tile\_size \rfloor$ [S3, unofficial].
      - $y_{max} = \lceil (points\_xy[idx, 1] + radii[idx]) / tile\_size \rceil$ [S3, unofficial].
   c. Clamp $x_{min}, x_{max}, y_{min}, y_{max}$ to the valid tile grid boundaries $[0, W_{tiles})$ and $[0, H_{tiles})$ [G].
   d. Iterate over tile rows $y$ from $y_{min}$ to $y_{max} - 1$:
      i. Iterate over tile columns $x$ from $x_{min}$ to $x_{max} - 1$:
         1. Calculate 1D tile ID: $tile\_id = y \times W_{tiles} + x$ [S1, S3, unofficial].
         2. Construct key: $key = (tile\_id \ll 32) \mid (\text{uint32\_t})depths[idx]$ [S1, S3, unofficial].
         3. Append $key$ to `gaussian_keys_unsorted` and `idx` to `gaussian_values_unsorted` [S1, S3, unofficial].

**Pseudocode:**
```python
import math

def generate_gaussian_rasterization_keys(points_xy, radii, depths, grid_width, grid_height, tile_size):
    """
    Generates key-value pairs for Gaussian-tile overlaps.
    
    Args:
        points_xy: (N, 2) array, screen space centers.
        radii: (N,) array, radii in pixels.
        depths: (N,) array, camera space depths.
        grid_width: int, number of tiles horizontally.
        grid_height: int, number of tiles vertically.
        tile_size: int, pixels per tile.
        
    Returns:
        keys: List of uint64_t sort keys.
        values: List of uint32_t Gaussian indices.
    """
    keys = []
    values = []
    N = len(points_xy)
    
    for idx in range(N):
        r = radii[idx]
        if r <= 0:
            continue
                
        cx, cy = points_xy[idx]
        
        # Calculate bounding rect in tile coordinates [S3, unofficial]
        x_min = int(math.floor((cx - r) / tile_size))
        x_max = int(math.ceil((cx + r) / tile_size))
        y_min = int(math.floor((cy - r) / tile_size))
        y_max = int(math.ceil((cy + r) / tile_size))
        
        # Clamp to grid bounds [G]
        x_min = max(0, x_min)
        x_max = min(grid_width, x_max)
        y_min = max(0, y_min)
        y_max = min(grid_height, y_max)
        
        # Cast depth to uint32_t [S1, S3, unofficial]
        depth_uint = int(depths[idx]) & 0xFFFFFFFF
        
        for y in range(y_min, y_max):
            for x in range(x_min, x_max):
                tile_id = y * grid_width + x
                key = (tile_id << 32) | depth_uint
                keys.append(key)
                values.append(idx)
                    
    return keys, values
```

**Parameters:**
- `tile_size`: Typically 16 pixels [Sibling: Tile-based Rasteriser].
- `grid_width`: Determined by image width and tile size [Sibling: Tile-based Rasteriser].

**Edge Cases:**
- **Zero Radius:** Gaussians with radius $\le 0$ are skipped [S1, unofficial].
- **Boundary Clamping:** Tile coordinates must be clamped to the valid grid range to prevent out-of-bounds access [G].
- **Depth Casting:** Depth is cast to `uint32_t` [S1, S3, unofficial]. Standard practice assumes positive depth within the 32-bit unsigned integer range [G].

## Subtopics

### [Gaussian-to-Intersect Mapping and Sorting](12245-gaussian-to-intersect-mapping-and-sorting.md)
A CUDA-based preprocessing pipeline that culls invisible Gaussians, maps 3D Gaussian projections to tile-based intersection IDs, and sorts them. It generates key-value pairs for all Gaussian-tile overlaps to enable efficient tile-based rasterization. Unlike differentiable rendering steps, this mapping and sorting process is not differentiable to any input.

## Operating characteristics
- **Time Complexity:** $O(N \cdot A)$, where $N$ is the number of Gaussians and $A$ is the average number of tiles each Gaussian overlaps [S1, S3, unofficial].
- **Memory Complexity:** $O(N \cdot A)$ for storing the keys and values arrays [S1, S3, unofficial].
- **Performance:** This step is a simple parallel loop and is extremely fast compared to the subsequent radix sort [S1, S3, unofficial]. It scales linearly with the number of Gaussians and their spatial extent [S1, S3, unofficial].
- **Strengths:** Simple logic, minimal memory overhead, highly parallelizable [S1, S3, unofficial].
- **Limitations:** Generates duplicate entries for Gaussians spanning multiple tiles, increasing the workload for the subsequent sort [S1, S3, unofficial].

## Background
This method is part of the rendering implementation pipeline for 3D Gaussian Splatting, specifically the CPU-sorted or tile-based rasterization variants [Sibling: Tile-based Rasteriser] [S1, S2, S3, S4, unofficial]. It was introduced in the context of efficient rasterization for Gaussian Avatar Reconstruction and Learning Methods [Sibling: Tile-based Rasteriser] [S1, S2, S3, S4, unofficial]. The specific implementation details (key packing, tile iteration) are derived from open-source implementations of Gaussian Splatting rasterizers [S1, S2, S3, S4, unofficial].
