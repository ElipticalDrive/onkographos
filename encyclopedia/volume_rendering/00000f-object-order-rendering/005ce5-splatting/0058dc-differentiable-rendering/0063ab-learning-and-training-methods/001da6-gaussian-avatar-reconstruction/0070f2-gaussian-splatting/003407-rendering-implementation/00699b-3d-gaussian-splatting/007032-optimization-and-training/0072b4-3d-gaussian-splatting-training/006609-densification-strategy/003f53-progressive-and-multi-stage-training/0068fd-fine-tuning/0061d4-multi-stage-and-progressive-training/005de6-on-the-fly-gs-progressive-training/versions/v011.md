# On-the-Fly GS Progressive Training

Also called: On-the-Fly Gaussian Splatting

## Overview
On-the-Fly GS Progressive Training is a method for optimizing 3D Gaussian Splatting (3DGS) fields in a streaming or incremental setting, where images are acquired sequentially and the scene representation must be updated in near real-time. It solves the problem of catastrophic forgetting and overfitting that occurs when naively retraining a 3DGS model on a growing dataset. It sets itself apart from standard offline training by partitioning the optimization into an initial phase, a progressive per-image update phase, and a final global optimization, while dynamically allocating training resources and learning rates based on hierarchical image overlap and load balancing [S1].

## How it works
The method operates in three distinct phases. It takes as input a sequence of images and their associated poses (estimated via On-the-Fly SfM) and outputs a final 3D Gaussian field.

### Data Structures
*   **Sparse Point Cloud**: A set of 3D points $\mathbf{P}$ with associated features, maintained and refined by the SfM backend.
*   **3D Gaussian Field**: A collection of Gaussians $\mathcal{G} = \{g_1, \dots, g_N\}$, where each Gaussian $g_i$ has position $\mathbf{x}_i$, covariance $\Sigma_i$, opacity $\alpha_i$, and spherical harmonics coefficients for color.
*   **Search Tree**: A spatial index (e.g., KD-tree) built over the existing sparse point cloud $\mathbf{P}$ to facilitate nearest-neighbor queries.
*   **Image Overlap Matrix**: A matrix $M$ where $M_{i,j}$ represents the number of matched feature points between image $i$ and image $j$.

### Phase 1: Initial 3DGS Training
1.  **Initialization**: Select $N_0$ initial images.
2.  **SfM**: Run On-the-Fly SfM to estimate poses and generate a sparse point cloud for these $N_0$ images.
3.  **Training**: Train the initial 3DGS field using the standard 3DGS optimization algorithm.
4.  **Constraint**: Limit the number of iterations to $T_{init}$ to prevent overfitting to the small initial subset.

### Phase 2: Progressive 3DGS Training
For each newly acquired image $n$:
1.  **SfM Update**: Estimate the pose of image $n$ and perform local Bundle Adjustment (BA) to refine poses of neighboring images and update the sparse point cloud $\mathbf{P}$.
2.  **New Point Detection**:
    *   Construct a search tree for the current sparse point cloud $\mathbf{P}$.
    *   Query the 3D points from the new image $n$ against the tree.
    *   Identify points $\mathbf{p}_{new}$ where the distance to the nearest existing point in $\mathbf{P}$ exceeds a predefined threshold.
3.  **Gaussian Initialization**: Initialize new Gaussians from $\mathbf{p}_{new}$ and append them to the 3DGS field $\mathcal{G}$.
4.  **Hierarchical Weight Calculation**: Calculate training weights $\omega$ for all registered images to determine optimization priority.
    *   Let image $n$ be the new image with weight $\omega_{11} = 1$.
    *   **Direct Overlap (Layer 2)**: For images $i$ with direct overlap ($M_{i,n} > 0$), calculate:
        $$ \omega_{2i} = M_{i,n} $$
    *   **Indirect Overlap (Layer $k \ge 3$)**: For images in layer $k$, let $N_{k-1}$ be the number of images in layer $k-1$. The weight $\omega_{ki}$ for image $i$ in layer $k$ is:
        $$ \omega_{ki} = \frac{\sum_{j=1}^{N_{k-1}} \omega_{j}^{(k-1)} \times M_{j,ki}^{(k-1)}}{N_{k-1}} $$
        where $\omega_{j}^{(k-1)}$ is the weight of image $j$ in layer $k-1$, and $M_{j,ki}^{(k-1)}$ is the match count between image $j$ and image $i$.
5.  **Training Iteration Allocation**: Perform $T_I$ total training iterations on the current 3DGS field.
    *   **Local Optimization**: Select the top $N_m$ images with the highest weights as key targets. For each key image $i$ with weight $\omega_i$, the allocated iterations $T_{im}$ are:
        $$ T_{im} = \frac{1 - e^{-\omega_i}}{\sum_{j=1}^{N_m} (1 - e^{-\omega_j})} \times T_I $$
    *   **Semi-Global Optimization**: Distribute the remaining $T_I / 2$ iterations evenly among the other (non-key) images.
6.  **Adaptive Learning Rate**: For each image $j$ trained for $T_j$ iterations, calculate the base learning rate $\eta_j^c$:
    *   Progress $t_i = \min(1, T_j / T_a)$.
    *   $\eta_j^c = (\eta_j^0)^{1-t_i} \times (\eta_j^f)^{t_i}$.
    *   Adjust for overlapping images $I$ (where $M_{i,j} > 0$):
        $$ \eta_j = \frac{\eta_j^c + \sum_{i \in I} M_{i,j} \times \eta_i^c}{N_I + 1} $$
        where $N_I$ is the count of overlapping images.
7.  **Loss Function**: Optimize the 3DGS parameters using the total loss:
    $$ L_{total} = \lambda_1 L_1 + \lambda_{ssim} L_{ssim} + \lambda_{load} L_{load} $$
    where $L_{load} = \text{std}(G_p)$ is the standard deviation of the number of Gaussians $G_p$ associated with each pixel $p$ in the current image.

### Phase 3: Final Optimization
1.  **Global BA**: Perform global Bundle Adjustment on all estimated poses.
2.  **Rapid Optimization**: Apply additional optimization iterations to the final 3DGS field to improve overall rendering quality.

### Parameters
*   $N_0$: Number of initial images. Typical value: 30 [S1].
*   Initial training iterations ($T_{init}$): Typical value: 2,000 [S1].
*   $T_I$: Total training iterations per new image. Typical value: 200 [S1].
*   $N_m$: Number of top-weighted images for local optimization. Typical value: 10 [S1].
*   $T_a$: Predefined parameter for satisfactory rendering quality iterations. Typical value: 200 [S1].
*   $\eta_0$: Initial learning rate. Typical value: $1.6 \times 10^{-4}$ [S1].
*   $\eta_f$: Final learning rate. Typical value: $1.6 \times 10^{-6}$ [S1].
*   $\lambda_1$: Weight for $L_1$-Loss. Typical value: 0.47 [S1].
*   $\lambda_{load}$: Weight for Load-Balancing-Loss. Typical value: 0.41 [S1].
*   $\lambda_{ssim}$: Weight for SSIM-Loss. Typical value: 0.12 [S1].

### Edge Cases and Pitfalls
*   **Overfitting in Phase 1**: Training too many iterations on the initial $N_0$ images leads to poor generalization for subsequent images. A strict iteration limit is required [S1].
*   **Threshold Selection**: The distance threshold for new point detection must be tuned to balance between missing new geometry and incorrectly initializing Gaussians from existing points [S1].
*   **Gradient Contention**: Using per-pixel gradient accumulation can cause thread contention. The method recommends splatting-based parallelism (accumulating gradients per Gaussian) to accelerate training [S1].

## Operating characteristics
*   **Time Complexity**: The method is designed for near real-time optimization. Each new image triggers $T_I$ iterations. The average iterations per image approach $T_I$ as the scene grows [S1].
*   **Memory Complexity**: The number of Gaussians grows with the number of images, but the load-balancing loss helps prevent abnormal accumulation, keeping the total count lower than naive approaches [S1].
*   **Performance**: On an RTX 4090 GPU, the method achieves faster training times compared to standard 3DGS and other SLAM-based methods like GS-SLAM and RTG-SLAM [S1].
*   **Strengths**: Prevents catastrophic forgetting, adapts to new views efficiently, and reduces training time via parallelism and load balancing [S1].
*   **Limitations**: Requires a robust On-the-Fly SfM backend for pose estimation and sparse point cloud generation [S1].

## Background
On-the-Fly GS Progressive Training was introduced in the paper "Gaussian On-the-Fly Splatting: A Progressive Framework for Robust Near Real-Time 3DGS Optimization" [S1]. It builds on the principles of 3D Gaussian Splatting [S1] and integrates techniques from Taming 3DGS for parallelism [S1]. The method addresses the limitations of offline training in dynamic or streaming scenarios [S1].
