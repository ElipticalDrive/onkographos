# 3D Gaussian Splatting Rasterization

Also called: 3D Gaussian Splatting (3DGS), 3DGS Rasterization, Differentiable Gaussian Rasterization, TrimGS, gsplat.rasterization

## Overview
3D Gaussian Splatting Rasterization is a screen-space rendering method that projects a set of 3D Gaussian primitives into 2D ellipses and accumulates their color and opacity via alpha compositing [S2, S3, S6, unofficial]. It solves the problem of real-time, high-fidelity novel view synthesis by replacing volumetric ray marching with a differentiable rasterization pipeline, allowing gradients to flow from the rendered image back to Gaussian parameters (position, scale, rotation, opacity, color) and camera poses [S8, S9, unofficial]. It differs from its siblings, such as [2D Gaussian Splatting Rasterization](4815-2d-gaussian-splatting-rasterization.md) which uses planar primitives, and [Ghost Ellipsoids for Chunked Training](3559-ghost-ellipsoids-for-chunked-training.md) which optimizes memory usage during training, by relying on full 3D covariance projection and tile-based depth sorting to handle arbitrary 3D geometry and occlusion [S3, unofficial][S9, unofficial].

## How it works
**Inputs:**
*   **Gaussian Attributes:**
    *   Means $\mu \in \mathbb{R}^{N \times 3}$: 3D positions.
    *   Quaternions $q \in \mathbb{R}^{N \times 4}$: Rotations (normalized).
    *   Scales $s \in \mathbb{R}^{N \times 3}$: Log-scales or linear scales (activation applied).
    *   Opacities $\alpha \in \mathbb{R}^N$: Scalar opacity per Gaussian.
    *   Colors: Either direct RGB $c \in \mathbb{R}^{N \times 3}$ or Spherical Harmonics coefficients $c_{\ell m}$ for view-dependent color.
*   **Camera Parameters:**
    *   View matrices $V \in \mathbb{R}^{C \times 4 \times 4}$: World-to-camera transformation.
    *   Intrinsics $K \in \mathbb{R}^{C \times 3 \times 3}$: Focal lengths ($f_x, f_y$) and principal point ($c_x, c_y$).
    *   Image dimensions: Width $W$, Height $H$.
    *   Clipping planes: Near $z_{near}$, Far $z_{far}$.
*   **Rasterization Settings:**
    *   Tile size $T$ (default 16).
    *   Render mode: "RGB", "D" (depth), "ED" (expected depth), etc.
    *   Camera model: "pinhole", "ortho", "fisheye".
    *   Rasterize mode: "classic" or "antialiased".

**Outputs:**
*   Rendered image $I \in \mathbb{R}^{C \times H \times W \times D}$ (where $D$ depends on mode, e.g., 3 for RGB).
*   Alpha mask $A \in \mathbb{R}^{C \times H \times W \times 1}$.

**Data Structures:**
1.  **Covariance Matrix ($\Sigma_{3D}$):** Constructed from rotation $R$ (derived from $q$) and scaling $S = \text{diag}(s)$:
    $$ \Sigma_{3D} = R S S^T R^T $$
    [S1][S3, unofficial]
2.  **Conic Representation ($C$):** The inverse 2D covariance $\Sigma_{2D}^{-1}$ is stored as a 3-element vector to avoid repeated inversions:
    $$ C = [\Sigma_{2D}^{-1}[0,0], \Sigma_{2D}^{-1}[0,1], \Sigma_{2D}^{-1}[1,1]] $$
    [S2, S3, unofficial]
3.  **Tile Intersection Data:**
    *   `tiles_per_gauss`: List of tile indices intersected by each Gaussian.
    *   `isect_ids`: Flattened list of Gaussian IDs sorted by tile.
    *   `isect_offsets`: Array mapping tile coordinates to indices in `isect_ids`.

**Steps:**

1.  **Input Validation & Setup:**
    *   Validate `render_mode`, `rasterize_mode`, and `camera_model`.
    *   Compute tile dimensions: $T_x = \lceil W/T \rceil, T_y = \lceil H/T \rceil$.
    *   Initialize output buffers for colors and alphas.

2.  **Covariance Construction:**
    *   Compute 3D covariance matrices from quaternions and scales:
        ```python
        # Assuming quats are normalized and scales are applied
        R = quat_to_rot_matrix(quats)
        S = diag(scales)
        cov_3D = R @ S @ S.T @ R.T  # Shape [N, 3, 3]
        ```
    [S2, S3, unofficial]

3.  **Projection to 2D Screen Space:**
    *   Transform means to camera space: $\mu' = V \mu$.
    *   Transform covariance to camera space: $\Sigma' = V_{1:3, 1:3} \Sigma_{3D} V_{1:3, 1:3}^T$.
    *   Compute the Jacobian $J$ of the projective projection:
        $$ J = \begin{pmatrix} \frac{f_x}{\mu'_z} & 0 & -\frac{f_x \mu'_x}{\mu'_z^2} \\ 0 & \frac{f_y}{\mu'_z} & -\frac{f_y \mu'_y}{\mu'_z^2} \end{pmatrix} $$
    [S2, S3, unofficial]
    *   Compute 2D screen covariance: $\Sigma_{2D} = J \Sigma' J^T$.
    *   Compute conics $C = \Sigma_{2D}^{-1}$ (only upper triangle needed).
    *   Compute 2D means $\mu_{2D}$ and radii (bounding box) for culling.
    [S2, S3, unofficial]

4.  **Culling and Sorting:**
    *   **Frustum Culling:** Discard Gaussians where $\mu'_z < z_{near}$ or outside the view frustum.
    *   **Temporal Filtering (Optional):** For 4DGS, compute marginal probability $p_i(t)$ and discard Gaussians with negligible support at current frame $t$ [S6, unofficial].
    *   **Depth Sorting:** Sort remaining Gaussians by camera-space depth $z$ for front-to-back compositing. The original implementation uses CUB device radix sort for efficiency [S4, unofficial].

5.  **Tile Intersection:**
    *   For each Gaussian, determine which tiles it intersects based on its 2D bounding box.
    *   Encode intersections into `isect_offsets` and `isect_ids` for efficient GPU access.

6.  **Color Computation (Spherical Harmonics):**
    *   If SH is enabled, compute view directions $d = \text{normalize}(\mu - \text{campos})$.
    *   Evaluate SH basis functions $Y_{\ell m}(d)$ and compute color:
        $$ c(d) = \sum_{\ell=0}^{N} \sum_{m=-\ell}^{\ell} \beta_{\ell m} Y_{\ell m}(d) $$
    [S1][S2, unofficial]
    *   Clamp color values to valid range (e.g., $[0, 1]$ or $[-0.5, 0.5]$ depending on encoding).

7.  **Rasterization (Tile-based):**
    *   Iterate over each tile.
    *   For each Gaussian intersecting the tile:
        *   Compute alpha contribution at each pixel within the tile's bounding box:
            $$ \alpha_{pixel} = \alpha_i \cdot \exp\left(-\frac{1}{2} \mathbf{x}^T \Sigma_{2D}^{-1} \mathbf{x}\right) $$
            where $\mathbf{x}$ is the vector from the pixel center to the Gaussian mean $\mu_{2D}$.
        *   If `rasterize_mode` is "antialiased", apply compensation factors to account for sub-pixel sampling [S2, unofficial].
    *   Perform front-to-back alpha compositing for each pixel:
        ```python
        T = 1.0  # Transmittance
        C_acc = 0.0
        for gaussian in sorted_gaussians_intersecting_pixel:
            alpha = gaussian.alpha * exp(-0.5 * dot(x, conic @ x))
            C_acc += T * alpha * gaussian.color
            T *= (1.0 - alpha)
        final_color = C_acc + T * background_color
        ```
    [S3, unofficial]

8.  **Post-Processing:**
    *   If depth is requested, compute weighted average depth or expected depth (normalized by alpha).
    *   Composite background color where alpha mask is zero.

**Parameters:**
*   `tile_size`: Integer, default 16. Side length of tiles.
*   `near_plane`: Float, default 0.01.
*   `far_plane`: Float, default 1e10.
*   `sh_degree`: Integer or None. If not None, enables SH.
*   `render_mode`: String, e.g., "RGB", "D", "ED".
*   `rasterize_mode`: String, "classic" or "antialiased".
*   `camera_model`: String, "pinhole", "ortho", "fisheye".

**Edge Cases and Pitfalls:**
*   **Degenerate Gaussians:** If $\Sigma_{2D}$ is singular or near-singular, inversion fails. Guard against this by adding a small epsilon to the diagonal or culling.
*   **Perspective Distortion:** At extreme angles or close to the camera, the linearized projection approximation may introduce artifacts. Antialiased mode helps mitigate this [S2, unofficial].
*   **Sorting Bottleneck:** Sorting millions of Gaussians is the primary bottleneck. Efficient radix sort is required for real-time performance [S4, unofficial].
*   **Memory Constraints:** High VRAM usage (4GB to view, 12GB to train) due to large number of Gaussians and intermediate buffers [S4, unofficial].

## Subtopics

### [3D Gaussian Splatting Differentiable Rasterizer](2813-3d-gaussian-splatting-differentiable-rasterizer.md)
The 3D Gaussian Splatting Differentiable Rasterizer is a screen-space rendering method that projects a set of 3D Gaussian primitives into 2D ellipses and accumulates their color and opacity via alpha compositing. It solves the problem of real-time, high-fidelity novel view synthesis by replacing volumetric ray marching with a differentiable rasterization pipeline, allowing gradients to flow from the rendered image back to Gaussian parameters (position, scale, rotation, opacity, color) and camera poses. It differs from its siblings, such as [2D Gaussian Splatting Rasterization](4815-2d-gaussian-splatting-rasterization.md) which uses planar primitives, and [Ghost Ellipsoids for Chunked Training](3559-ghost-ellipsoids-for-chunked-training.md) which optimizes memory usage during training, by relying on full 3D covariance projection and tile-based depth sorting to handle arbitrary 3D geometry and occlusion.

### [Ghost Ellipsoids for Chunked Training](3559-ghost-ellipsoids-for-chunked-training.md)
Ghost Ellipsoids for Chunked Training resolves boundary artifacts in chunked volume training by including ellipsoids from neighboring chunks in the loss computation without updating their parameters, providing boundary context without requiring a global volume or merged model. Unlike chunk-based 3DGS methods that resolve boundary inconsistencies by merging chunks into a global coarse model or through post-training stages, this method requires boundary support during training itself without access to a global volume.

### [2D Gaussian Splatting Rasterization](4815-2d-gaussian-splatting-rasterization.md)
2D Gaussian Splatting Rasterization renders a scene represented by 2D Gaussian primitives (surfels) into RGB, alpha, and normal maps using a custom rasterizer. It differs from standard 3D Gaussian Splatting by operating on surfels projected into screen space, accumulating color and geometric attributes via front-to-back alpha compositing [Parent]. It serves as the Tier-1 NumPy reference implementation for 2D Gaussian Splatting, performing ray-surfel intersection per pixel using the projection matrix.

### [AdR-Gaussian](8365-adr-gaussian.md)
AdR-Gaussian is a rendering acceleration method for 3D Gaussian Splatting that optimizes the rasterization pipeline by moving serial culling operations to a parallel preprocessing stage and balancing computational loads across pixel threads. It achieves significant speedups without reducing the total number of Gaussians, thereby avoiding the quality degradation associated with pruning-based acceleration methods.

### [Projection Geometry and Coordinate Systems](9313-projection-geometry-and-coordinate-systems.md)
This article defines the mathematical framework for transforming 3D Gaussian primitives from world space into the 2D image plane for rasterization in 3D Gaussian Splatting. It solves the problem of accurately projecting 3D ellipsoids onto a 2D sensor plane while preserving geometric fidelity and enabling differentiable rendering. It sets apart from standard perspective projection by supporting optimal tangent-plane projections [3293-optimal-gaussian-splatting.md] and specialized geometries such as cone-beam X-ray scanning [3458-3d-gaussian-splatting-rasterization-cone-beam-scanner-space.md].

### [Point-Based Ray Tracing for Visibility](10934-point-based-ray-tracing-for-visibility.md)
Point-Based Ray Tracing for Visibility serves as a sparse visibility oracle that evaluates transmittance along sampled light directions using a bounding volume hierarchy (BVH) of Gaussian proxies, enabling evaluation from any point in space in any direction. Unlike the camera-tied rasterizer, it decouples visibility estimation from screen-space projection, allowing it to act as a drop-in companion to standard 3D Gaussian Splatting (3DGS) by reusing the same EWA-splatting formulation for consistent blending without requiring training mismatch.

### [Primitive Representation](11838-primitive-representation.md)
Primitive Representation defines the geometric and photometric data structures used to approximate a 3D scene in Gaussian Splatting methods [G]. It solves the problem of representing continuous geometry and appearance with discrete, differentiable primitives that can be efficiently rasterized [G]. It sets itself apart from parent methods by explicitly defining the kernel shape (e.g., isotropic, half-space, or hybrid Bézier) and the associated attribute storage (e.g., opacity, normals, control points) that determine how light interacts with the primitive during rendering [G].

### [Shading and Lighting Models](11924-shading-and-lighting-models.md)
Shading and Lighting Models extend the standard 3D Gaussian Splatting rasterization pipeline to support physically based rendering (PBR), self-occlusion, and anti-aliased forward shading. While standard splatting assumes a fixed, uniform lighting environment and simple alpha blending, this family introduces mechanisms for deferred shading pipelines, light-space rasterization for shadows, and analytic integration approximations for multiscale fidelity. It differs from sibling methods like [Analytic-Splatting Forward Shading](3459-analytic-splatting-forward-shading.md) by focusing on material attributes and light interaction rather than just pixel-area integration, and from [Transparency and Blending Models](9274-transparency-and-blending-models.md) by explicitly handling light source geometry and PBR material buffers.

### [Reflective Gaussian Splatting](12321-reflective-gaussian-splatting.md)
Reflective Gaussian Splatting (Ref-Gaussian) is a framework for the real-time, high-quality rendering of reflective objects with inter-reflection effects, addressing the limitations of standard 3D Gaussian Splatting in modeling complex surfaces and multi-view inconsistencies. It distinguishes itself from sibling methods like [3D Gaussian Splatting Rasterization](2812-3d-gaussian-splatting-rasterization.md) by utilizing 2D Gaussian primitives for view-consistent geometry and employing physically based deferred rendering with split-sum approximation to stabilize optimization and enable efficient inter-reflection modeling without heavy Monte Carlo sampling.

### [Ray-Splat Intersection Algorithms](13401-ray-splat-intersection-algorithms.md)
Ray-splat intersection algorithms compute the contribution of 3D Gaussians to a pixel by analytically evaluating the Gaussian density along the viewing ray, rather than projecting the 3D Gaussian onto the 2D image plane. This approach solves the problem of numerical instability and geometric inaccuracy that arises when splats become degenerate or when perspective-correct depth estimation is required [3403-perspective-correct-3d-gaussian-splatting-via-pl-cker-coordi.md][5992-gaussian-opacity-fields-gof.md]. Unlike standard rasterization which approximates the 3D Gaussian as a 2D ellipse, these methods treat the Gaussian as a volumetric primitive, enabling accurate depth extraction and surface reconstruction [5992-gaussian-opacity-fields-gof.md].

### [Rasterization Pipeline Optimization](15109-rasterization-pipeline-optimization.md)
Rasterization Pipeline Optimization refers to techniques that accelerate the rendering of 3D Gaussians by improving the efficiency of the rasterization stage, addressing the bottleneck of processing non-intersecting pixels and managing memory bandwidth. It sets itself apart from sibling methods by focusing on the computational pipeline (sorting, hardware acceleration, and culling) rather than the primitive representation or shading models.

### Temporal Marginal Probability Filtering
Pre-rasterization culling step that removes 4D Gaussians with negligible temporal support at the current frame timestamp, stabilizing rendering speed across video length [S6, unofficial]. Compute the marginal probability $p_i(t)$ for each 4D Gaussian $i$ at the current frame's timestamp $t$. Discard Gaussians with negligible $p_i(t)$ before executing standard frustum culling. Unlike methods where Gaussian count scales with video length, this filtering keeps active Gaussians constant, making the approach friendly to long videos in terms of rendering speed [S6, unofficial].

### t-distribution truncation for splatting
A projection truncation technique that replaces the fixed three-sigma rule used in vanilla 3DGS with a $\nu$-dependent critical value interpolation to handle fat-tailed Student's t-distributions [S7]. For t-distributions with thin tails (high $\nu$), apply the standard three-sigma rule directly. For fat-tailed distributions (low $\nu$), obtain critical values for different $\nu$ degrees from reference [9] and interpolate between them to compute the appropriate truncation threshold. Using a fixed three-sigma threshold on fat-tailed t-distributions causes excessive truncation or leakage. Interpolation across $\nu$ degrees resolves this [S7].

### Progressive Normal Propagation
Uses progressive propagation along normals to fill texture-less regions [S5, unofficial].

### Splat TBO Upload & Layout
Packs per-splat data (center, covariance, DC color/alpha, optional SH) into Texture Buffer Objects (TBOs) for GPU consumption [S8, unofficial]. Iterate over splats. For each splat, copy center.xyz as raw float bits to d[0..2]. Pack covariance upper-triangle to d[3..5] using packHalf2x16: d[3]=covA[0],covA[1]; d[4]=covA[2],covB[0]; d[5]=covB[1],covB[2]. Pack DC color/alpha to d[6] using packDCColor. Set d[7]=0. Create GL_TEXTURE_BUFFER buffer with GL_RGBA32UI format. Bind to tbo_tex_. For non-DC SH coefficients, pack each coefficient's RGB into RGBA16F texels (B=0), layout is [splat0_c1, splat0_c2, …, splat1_c1, splat1_c2, …]. Create SH TBO with GL_RGBA16F format. Memory: 32 B/splat for base TBO + 8 B × sh_coeffs_per_splat_ × splat_count_ for SH TBO. Base TBO: 2 uvec4 texels per splat (32 B). Texel 0: center.xyz (float bits), packHalf2x16(cov00, cov01). Texel 1: packHalf2x16(cov02, cov11), packHalf2x16(cov12, cov22), packUnorm4x8(DC-baked RGBA), reserved. SH TBO: GL_RGBA16F, 8 B per non-DC SH coefficient per splat. Layout: [splat0_c1, splat0_c2, …, splat1_c1, splat1_c2, …] [S8, unofficial].

### 3D Gaussian Splatting for X-ray Projection Rasterization
A rendering technique that leverages 3D Gaussian Splatting (3DGS) to rasterize X-ray projections by modeling X-ray attenuation using the Beer-Lambert law, treating the volume as a collection of 3D Gaussians with density and isotropic absorption [S9, unofficial]. The exponential transmittance model $T(t)$ is defined as $T(t) = \exp\left(-\int_{t_0}^t \sigma(\mathbf{r}(s)) ds\right)$, where $\mathbf{r}(t) = \mathbf{o} + t\mathbf{d}$ represents a 3D point along a ray with origin $\mathbf{o}$ and direction $\mathbf{d}$, and $\sigma(\mathbf{p})$ denotes the density at point $\mathbf{p}$ [S9, unofficial]. Color attributes are optional and can be excluded from the rendering model, accounting solely for isotropic absorption [S9, unofficial].

### Ray-Gaussian Intersection
Project the 3D Gaussian's covariance and center onto the camera ray to convert the 3D influence into a 1D Gaussian function along that specific ray [S10].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot T)$ where $N$ is the number of Gaussians and $T$ is the number of tiles, but effectively linear with respect to the number of visible Gaussians per pixel due to culling and tile-based processing. The sorting step is $O(N \log N)$ or $O(N)$ with radix sort.
*   **Memory Complexity:** $O(N)$ for Gaussian attributes. Intermediate buffers for projection and sorting also scale with $N$. High VRAM usage (4GB to view, 12GB to train) is a known limitation [S4, unofficial].
*   **Measured Performance:** Real-time rendering (60+ FPS) is achievable on modern GPUs (e.g., RTX 3090/4090) for scenes with millions of Gaussians at 1080p resolution.
*   **Scaling:** Scales well with resolution and number of Gaussians due to tile-based parallelism. Performance degrades if the number of overlapping Gaussians per pixel is very high.
*   **Strengths:** Real-time rendering, high visual fidelity, differentiable, easy to integrate with existing pipelines (with adaptations).
*   **Limitations:** High memory usage, static scenes (original), sorting bottleneck on non-CUDA hardware, potential artifacts with degenerate Gaussians.
*   **When to use:** Real-time novel view synthesis, interactive applications, training of Gaussian representations.
*   **When not to use:** Memory-constrained environments, scenes requiring explicit mesh extraction without post-processing, non-CUDA hardware without optimized sorting.

## Background
3D Gaussian Splatting was introduced in the paper "3D Gaussian Splatting for Real-Time Radiance Field Rendering" by Kerbl et al. in 2023 [S4, unofficial]. It represents a breakthrough in static scene rendering by replacing neural radiance fields (NeRFs) with explicit 3D Gaussian primitives, enabling real-time rendering rates while maintaining high visual fidelity. The method builds on earlier work in point-based rendering and splatting techniques. It has since been extended to dynamic scenes (4DGS), view-dependent effects (6DGS), and various other domains [S1][S6, unofficial].
