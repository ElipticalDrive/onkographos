# AbsGS Gradient Densification

Also called: Homodirectional Gradient

## Overview
AbsGS Gradient Densification is a strategy for 3D Gaussian Splatting that eliminates gradient collision by computing the homodirectional view-space positional gradient [S1]. It uses the absolute value of per-pixel gradient components before summing, ensuring all pixel contributions reinforce the magnitude rather than canceling out due to direction differences [S1]. This accurately identifies over-reconstructed Gaussians that standard gradient magnitude misses [S1]. Unlike standard 3D-GS, which sums signed gradients and risks cancellation, AbsGS sums absolute values per axis, providing a more robust signal for splitting large, over-reconstructed Gaussians [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** The set of active 3D Gaussians $\{G_i\}$, the current training iteration counter, and the loss function $L$ [S1].
*   **Output:** A binary decision for each Gaussian $G_i$ indicating whether it should be split [S1].

**Data Structures:**
*   **Gaussian $G_i$:** Contains position $\mu_i$, scale $S_i$, opacity $\alpha_i$, and color $c_i$ [G]. The position $\mu_i$ is in 3D world space, but gradients are computed in view space [S1].
*   **Gradient Accumulator:** For each Gaussian $G_i$, two accumulators are maintained: `sum_abs_x` and `sum_abs_y` [S1].

**Numbered Steps:**
1.  **Iteration Check:** The densification check is performed every 100 training iterations [S1].
2.  **Gradient Accumulation:** For each Gaussian $G_i$ that influences at least one pixel:
    a. Initialize `sum_abs_x = 0` and `sum_abs_y = 0` [S1].
    b. Identify all pixels $j$ covered by the projection of $G_i$ [S1].
    c. For each pixel $j$, compute the partial derivatives of the loss $L_j$ with respect to the view-space position components of $G_i$: $\frac{\partial L_j}{\partial \mu_{i,x}}$ and $\frac{\partial L_j}{\partial \mu_{i,y}}$ [S1].
    d. Take the absolute value of these components and add them to the respective accumulators:
       $$ \text{sum\_abs\_x} \leftarrow \text{sum\_abs\_x} + \left| \frac{\partial L_j}{\partial \mu_{i,x}} \right| $$
       $$ \text{sum\_abs\_y} \leftarrow \text{sum\_abs\_y} + \left| \frac{\partial L_j}{\partial \mu_{i,y}} \right| $$ [S1].
3.  **Homodirectional Gradient Calculation:** Compute the final scalar gradient magnitude $\text{abs}(G_i)$ as the L2 norm of the summed absolute components:
    $$ \text{abs}(G_i) = \sqrt{\text{sum\_abs\_x}^2 + \text{sum\_abs\_y}^2} $$
    This value $\hat{g}_i$ represents the homodirectional gradient [S1].
4.  **Densification Criteria Check:** Compare $\text{abs}(G_i)$ against the gradient threshold $\tau_p$ and the Gaussian's scale against the scale threshold $\tau_S$ [S1].
5.  **Split Decision:** If $\text{abs}(G_i) > \tau_p$ AND the scale of $G_i$ $> \tau_S$, trigger a split operation for $G_i$ [S1]. The clone operation follows the original 3D-GS strategy, not AbsGS [S1].

**Formulas:**
The core formula for the homodirectional gradient magnitude is:
$$ \hat{g}_i = \sqrt{ \left( \sum_{j=1}^m \left| \frac{\partial L_j}{\partial \mu_{i,x}} \right| \right)^2 + \left( \sum_{j=1}^m \left| \frac{\partial L_j}{\partial \mu_{i,y}} \right| \right)^2 } $$
Where:
*   $m$ is the number of pixels covered by Gaussian $G_i$ [S1].
*   $\frac{\partial L_j}{\partial \mu_{i,x}}$ is the gradient of the loss at pixel $j$ with respect to the x-component of the Gaussian's view-space position [S1].
*   $\frac{\partial L_j}{\partial \mu_{i,y}}$ is the gradient of the loss at pixel $j$ with respect to the y-component of the Gaussian's view-space position [S1].

**Parameters:**
*   **Gradient Threshold ($\tau_p$):** The minimum homodirectional gradient magnitude required to trigger a split [S1].
    *   Default for AbsGS: 0.0002 [S1].
    *   AbsGS typical values: 0.0004 or 0.0008 [S1]. Higher values are used in AbsGS experiments to account for the increased magnitude resulting from the absolute value summation [S1].
*   **Scale Threshold ($\tau_S$):** The minimum scale required to trigger a split [S1].
    *   Default in standard 3D-GS: 0.01 [S1].
    *   AbsGS typical value: 0.001 [S1]. This reduction allows splitting of smaller details that might be missed by the default threshold [S1].

**Edge Cases and Pitfalls:**
*   **Gradient Collision:** In standard 3D-GS, gradients from different pixels covering the same Gaussian may point in opposite directions, causing cancellation when summed [S1]. This is particularly problematic for large Gaussians covering many pixels, where maintaining consistent gradient directions is challenging [S1]. AbsGS mitigates this by using absolute values [S1].
*   **Over-reconstruction:** Standard gradient magnitude may fail to surpass $\tau_p$ for over-reconstructed Gaussians due to cancellation, hindering necessary splits [S1]. AbsGS accurately identifies these regions [S1].
*   **Small Details:** If $\tau_S$ is too high (e.g., default 0.01), small-scale details may not trigger splits [S1]. Reducing $\tau_S$ to 0.001 improves the capture of fine details [S1].

**Pseudocode:**
```python
def absgs_densification_step(gaussians, tau_p=0.0004, tau_S=0.001):
    for gaussian in gaussians:
        pixels_covered = gaussian.get_covered_pixels()
        if not pixels_covered:
            continue
        sum_abs_x = 0.0
        sum_abs_y = 0.0
        for pixel_j in pixels_covered:
            grad_x_j = gaussian.view_space_grad_x[pixel_j]
            grad_y_j = gaussian.view_space_grad_y[pixel_j]
            sum_abs_x += abs(grad_x_j)
            sum_abs_y += abs(grad_y_j)
        abs_G_i = (sum_abs_x**2 + sum_abs_y**2)**0.5
        scale_i = max(gaussian.scale_x, gaussian.scale_y, gaussian.scale_z)
        if abs_G_i > tau_p and scale_i > tau_S:
            gaussian.split()
```

## Operating characteristics
*   **Time Complexity:** The gradient computation requires iterating over all pixels covered by each Gaussian. For a Gaussian covering $m$ pixels, the complexity is $O(m)$. Summing over all Gaussians, the total complexity per densification step is proportional to the total number of splats-pixel interactions [S1].
*   **Memory Complexity:** Requires storing two accumulators (`sum_abs_x`, `sum_abs_y`) per Gaussian, which is $O(1)$ per Gaussian [S1].
*   **Measured Performance:** Experiments on the Mip-NeRF360 dataset using a single NVIDIA V100 GPU show that AbsGS achieves competitive PSNR and SSIM scores compared to standard 3D-GS and 3D-GS* (3D-GS with reduced $\tau_S$) [S1]. Memory usage varies by scene and threshold setting, with AbsGS configurations generally requiring comparable or slightly higher memory than baselines due to increased Gaussian counts [S1].
*   **Strengths:** Effectively identifies over-reconstructed Gaussians that standard gradient magnitude misses due to gradient collision [S1]. Allows for better capture of fine details when combined with a reduced scale threshold [S1].
*   **Limitations:** The absolute value summation increases the magnitude of the gradient, requiring careful tuning of $\tau_p$ [S1]. The method is specifically designed for the split operation; the clone operation remains unchanged from 3D-GS [S1].

## Background
AbsGS (AbsGS: Recovering Fine Details in 3D Gaussian Splatting) was proposed to address the issue of gradient collision in 3D Gaussian Splatting optimization [S1]. The method was introduced in the paper "AbsGS: Recovering Fine Details in 3D Gaussian Splatting" [S1]. The authors observed that standard gradient magnitude computation in 3D-GS is weakened by irrelevant gradient directions and collision effects, particularly for large Gaussians covering many pixels [S1]. AbsGS eliminates this by computing the homodirectional view-space positional gradient [S1]. The method was evaluated on 13 distinct environments from the Mip-NeRF360 dataset and other sources, demonstrating improved ability to recover fine details compared to baseline 3D-GS and Instant-NGP [S1].
