# Tile-Based Comparison-Free Sorting

Also called: Comparison-Free Depth Sorting, Tile-Local Sorting

## Overview
Tile-Based Comparison-Free Sorting restricts depth sorting operations to individual image tiles to avoid global synchronization, reduce hardware complexity, and achieve fixed latency per output [S1]. Unlike full-scene sorting methods that incur high memory overhead and variable latency due to global scans and prefix sums, this method processes Gaussians locally within tiles using a deterministic, comparator-free algorithm [S1]. It is specifically designed for hardware accelerators where predictable scheduling and low power consumption are critical, such as in AR/VR rendering pipelines [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $N$ 3D Gaussians projected into 2D, each associated with a tile identifier and a depth value [S1]. The depth values are non-negative because near-plane culling excludes points with depth $< 0$ [S1].
*   **Output:** The Gaussians sorted front-to-back (increasing depth) within each tile, ready for alpha compositing [S1].

**Data Structures:**
*   **Sorting Key:** A tuple $\langle \text{tile-id}, \text{depth} \rangle$ [S1].
*   **Element Vector Table (EVT):** A binary vector of size $N$ used to track the status of elements [S1]. It is initialized to all 1s, indicating all elements are unsorted [S1]. An element is marked as sorted by setting its corresponding bit to 0 [S1].
*   **Bit Width ($n$):** The number of bits used to represent the depth value [S1].

**Algorithm Steps:**
The sorting process identifies the Largest Element (LE) iteratively $N$ times [S1]. For each iteration, the LE is removed from the unsorted set, and the process repeats until the EVT is all 0s [S1].

1.  **Initialization:** Initialize the EVT of size $N$ with all bits set to 1 [S1].
2.  **Concurrent Phase (Bitwise Filtering):**
    *   Process the $N$ elements in $k$ parallel clusters [S1].
    *   Iterate through the bits of the depth value from the Most Significant Bit (MSB) to the Least Significant Bit (LSB) [S1].
    *   **Sign Bit Handling:** Skip the sign bit operation because near-plane culling ensures depth is always non-negative (sign bit is always 0) [S1].
    *   For each bit position, filter out elements that are smaller than the current candidate maximum using bitwise AND operations and multiplexer-based selection within cascaded blocks [S1].
3.  **Sequential Phase (Refinement):**
    *   Pass the outputs from the concurrent phase clusters to a linear array of $k$ cascaded blocks [S1].
    *   Further refine the selection to identify the single Largest Element (LE) among the currently unsorted elements (those with EVT bit = 1) [S1].
4.  **Data Conflict Resolution (Duplicate Handling):**
    *   If multiple elements have the same maximum depth value, the EVT might return multiple "1"s, leading to ambiguity [S1].
    *   Resolve conflicts using bitwise inverter, bitwise AND, and an adder to uniquely identify one instance [S1].
    *   Compute the new flag $FO_{NEW}$ to update the EVT:
        $$FO_{NEW} = Fo \ \& \ (\sim Fo + 1'b1)$$
        where $Fo$ is the current flag vector [S1]. This operation isolates the least significant bit of the conflict set, ensuring deterministic selection of one element among duplicates [S1].
5.  **Update and Iterate:**
    *   Set the bit corresponding to the identified LE in the EVT to 0 [S1].
    *   Repeat steps 2–4 until the EVT contains all 0s, indicating all $N$ elements are sorted [S1].

**Pseudocode:**
```python
def tile_based_comparison_free_sort(gaussians, n_bits):
    """
    Sorts Gaussians within a tile using comparison-free sorting.
    gaussians: List of objects with attributes .depth (n-bit integer) and .id.
    n_bits: Total number of bits in the depth representation (includes sign bit).
    Returns: List of Gaussians sorted by depth (front-to-back).
    """
    N = len(gaussians)
    if N == 0:
        return []

    # EVT tracks unsorted elements: 1 means unsorted, 0 means sorted
    evt = [1] * N
    sorted_gaussians = []
    
    # Iterate N times to extract one element per cycle
    for _ in range(N):
        # Concurrent Phase: Filter candidates by bits MSB to LSB
        candidates = [i for i in range(N) if evt[i] == 1]
        if not candidates:
            break
            
        # Skip sign bit (index n_bits-1) as depth is guaranteed non-negative [S1]
        for bit_pos in range(n_bits - 2, -1, -1):
            if len(candidates) <= 1:
                break
            # Hardware filters out smaller values via bitwise AND and MUX selection [S1]
            has_one = any((gaussians[i].depth >> bit_pos) & 1 for i in candidates)
            if has_one:
                candidates = [i for i in candidates if (gaussians[i].depth >> bit_pos) & 1]
            else:
                candidates = [i for i in candidates if not ((gaussians[i].depth >> bit_pos) & 1)]
                
        # Sequential Phase & Conflict Resolution
        # If multiple candidates remain (duplicate depths), isolate one deterministically [S1]
        if len(candidates) > 1:
            # Hardware uses FO_NEW = Fo & (~Fo + 1) to pick the LSB of the conflict set [S1]
            # Simulated here by selecting the lowest index to match the hardware behavior
            le_index = candidates[0]
        else:
            le_index = candidates[0]
            
        # Update EVT: Mark this element as sorted
        evt[le_index] = 0
        sorted_gaussians.append(gaussians[le_index])
        
    return sorted_gaussians
```

**Parameters:**
*   $N$: Number of Gaussians in the tile [S1].
*   $n$: Bit width of the depth value [S1].
*   $k$: Number of parallel clusters (hardware-dependent) [S1].

**Edge Cases and Pitfalls:**
*   **Duplicate Depths:** The algorithm must handle duplicate depth values [S1]. The conflict resolution logic ($FO_{NEW}$) is critical to ensure deterministic selection and avoid errors in the final result [S1].
*   **Sign Bit:** The sign bit is always 0 due to near-plane culling [S1]. Removing the sign bit operation reduces unnecessary computations [S1].
*   **Variable $N$:** The number of Gaussians per tile varies significantly [S1]. The algorithm must handle arbitrary $N$ without fixed-size buffers that assume a maximum scene complexity [S1].

## Subtopics

### Parallel Comparison-Free Sorting
A tile-based, comparison-free sorting algorithm that uses an Element Vector Table (EVT) to identify the largest element in $O(N)$ deterministic cycles, avoiding the high memory overhead of radix sort [S1]. It employs concurrent and sequential phases with bitwise operations to filter elements, making it suitable for hardware implementation where low gate count and predictable latency are required [S1].

## Operating characteristics
*   **Time Complexity:** $O(N)$ deterministic cycles for sorting $N$ elements [S1].
*   **Hardware Complexity:** Low gate count compared to radix sort, which requires parallel scans and prefix sums [S1].
*   **Latency:** Fixed per-output latency, avoiding the latency spikes associated with global synchronization in full-scene sorting [S1].
*   **Performance:** Achieves full-HD rendering at 129 FPS, offering 3× higher throughput and 5.98× smaller area compared to prior 3DGS accelerators like GSCore [S1].
*   **Strengths:** Predictable scheduling, low power consumption, suitability for AR/VR hardware, and efficient handling of variable Gaussian counts per tile [S1].

## Background
The method originates from research into hardware accelerators for 3D Gaussian Splatting, specifically addressing the bottleneck of depth sorting in real-time rendering [S1]. Traditional sorting methods like radix sort are resource-intensive and suffer from variable latency, making them unsuitable for low-power AR/VR hardware [S1]. The tile-based comparison-free approach builds on parallel comparison-free algorithms [21, 22] (cited in [S1]) but adds optimizations such as sign bit skipping and conflict resolution for duplicate values [S1]. It was implemented in a hardware accelerator that demonstrated significant improvements in throughput and area efficiency over previous designs like GSCore [10] [S1].
