# Scene Flow Prior

Also called: Flow MLP for motion estimation

## Overview
Scene Flow Prior enhances the temporal consistency of 4D spatio-temporal representations by incorporating a flow Multi-Layer Perceptron (MLP) for motion estimation [S1]. It maps spatio-temporal coordinates from $\mathbb{R}^4$ to motion fields in $\mathbb{R}^3$, predicting displacement only between adjacent frames to avoid the difficulty of establishing long-term correspondences in deformable scenes [S1]. Unlike its parent method, Gaussian Splatting Lucas-Kanade, which applies optical flow to rendered Gaussians, this method operates on explicit geometric point clouds derived from LiDAR data to impose a motion prior and geometric supervision [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Spatio-temporal coordinates $(\mathbf{x}, t)$ where $\mathbf{x} \in \mathbb{R}^3$ and $t$ is the time index; LiDAR point clouds $S_i$ for frame $i$.
*   **Outputs:** Predicted scene flow displacement $\Delta \mathbf{x}$; transformed point cloud $\mathbf{x}'$.

**Data Structures:**
*   **Flow MLP:** A standard Multi-Layer Perceptron. The input is processed via positional encoding $\gamma(\mathbf{x}, t)$ [S1].
*   **Positional Encoding:** $\gamma(x) = (\sin(2^0 x), \cos(2^0 x), ..., \sin(2^{L-1} x), \cos(2^{L-1} x))$ [S1].
*   **Point Clouds:** Sets of 3D points $S$ and $\hat{S}$ representing two adjacent frames.

**Parameters:**
*   $L$: Number of frequency bands in positional encoding. Not given in the sources.
*   $K$: Number of points in the point cloud sets. Not given in the sources.
*   $n$: Total number of frames.

**Steps:**
1.  **Positional Encoding:** Encode the input coordinate $\mathbf{x}$ and time $t$ using $\gamma(\mathbf{x}, t)$.
2.  **Flow Prediction:** Feed the encoded coordinates into the flow MLP to predict the displacement vector $\Delta \mathbf{x}$:
    $$ \Delta \mathbf{x} = \mathrm{MLP}_\mathrm{flow}(\gamma(\mathbf{x}, t)) $$
3.  **Motion Application:** Compute the transformed coordinate $\mathbf{x}'$:
    $$ \mathbf{x}' = \mathbf{x} + \Delta \mathbf{x} $$
4.  **Geometric Loss Calculation:** To supervise the motion prediction, calculate the Chamfer Distance (CD) between the predicted transformed point cloud and the ground truth point cloud of the adjacent frame. The flow loss $\mathcal{L}_\mathrm{flow}$ is the sum of Chamfer Distances for forward and backward adjacent frames:
    $$ \mathcal{L}_\mathrm{flow} = \sum_{j \in \pm 1} \mathrm{CD}(S_i + \mathrm{MLP}_\mathrm{flow}(S_i), S_{i+j}) $$
    where $i \in (0, n-1)$ [S1].
5.  **Chamfer Distance Definition:** The Chamfer Distance between two point cloud sets $S$ and $\hat{S}$ is defined as:
    $$ \mathrm{CD} = \frac{1}{K} \sum_{\hat{p}_i \in \hat{S}} \min_{p_i \in S} \|\hat{p}_i - p_i\|_2^2 + \frac{1}{K} \sum_{p_i \in S} \min_{\hat{p}_i \in \hat{S}} \|p_i - \hat{p}_i\|_2^2 $$
    where $S$ and $\hat{S}$ are two frames of point clouds [S1].

def positional_encoding(x, t, L):
    """
    Applies positional encoding to coordinates and time.
    x: (N, 3) array of 3D coordinates
    t: (N,) array of time indices
    L: int, number of frequency bands
    Returns: (N, 2 * 3 * L) encoded vector
    """
    # Concatenate x and t for encoding
    coords = np.concatenate([x, t.reshape(-1, 1)], axis=1)
    # Apply sine/cosine frequencies
    frequencies = 2.0 ** np.arange(L)
    encoded = []
    for freq in frequencies:
        encoded.append(np.sin(coords * freq))
        encoded.append(np.cos(coords * freq))
    return np.concatenate(encoded, axis=1)

def flow_mlp_forward(encoded_coords, weights):
    """
    Forward pass of the Flow MLP.
    encoded_coords: (N, D_in)
    weights: list of (W_l, b_l) for each layer
    Returns: (N, 3) displacement vector delta_x
    """
    x = encoded_coords
    for W, b in weights:
        x = x @ W + b
        # ReLU activation is standard for MLPs, assumed here [G]
        x = np.maximum(0, x)
    return x

def chamfer_distance(points_S, points_S_hat):
    """
    Computes Chamfer Distance between two point clouds.
    points_S: (K, 3)
    points_S_hat: (K, 3)
    Returns: float, CD value
    """
    K = points_S.shape[0]
    
    # Compute pairwise distances
    # dists[i, j] = ||S[i] - S_hat[j]||^2
    dists = np.sum((points_S[:, np.newaxis, :] - points_S_hat[np.newaxis, :, :]) ** 2, axis=2)
    
    # Min distances for each point in S_hat to S
    min_dist_S_hat_to_S = np.min(dists, axis=1)
    
    # Min distances for each point in S to S_hat
    min_dist_S_to_S_hat = np.min(dists, axis=0)
    
    cd = (1.0 / K) * np.sum(min_dist_S_hat_to_S) + (1.0 / K) * np.sum(min_dist_S_to_S_hat)
    return cd

**Edge Cases and Pitfalls:**
*   **Long-term Correspondences:** The method explicitly avoids long-term correspondences to canonical space because vehicle motion range may span a long distance in autonomous driving scenarios, making such correspondences hard to establish [S1].
*   **Precision:** The Chamfer Distance involves squared Euclidean norms, which can be sensitive to outliers. The normalization by $K$ helps but large point clouds may require efficient nearest-neighbor search [S1].
*   **Boundary Conditions:** The index $i$ ranges from $0$ to $n-1$, implying the loss is computed for frames that have at least one adjacent neighbor. The first and last frames might have only one adjacent frame, affecting the sum in $\mathcal{L}_\mathrm{flow}$ [S1].

## Operating characteristics
*   **Time Complexity:** The flow MLP inference is $O(N \cdot D \cdot L_{mlp})$ where $N$ is the number of points, $D$ is input dimension, and $L_{mlp}$ is MLP depth. Chamfer Distance computation is $O(K^2)$ naively, but can be optimized to $O(K \log K)$ with spatial indexing.
*   **Memory Complexity:** Requires storing point clouds for adjacent frames and the MLP weights.
*   **Strengths:** Enhances temporal consistency by leveraging explicit geometric constraints from LiDAR point clouds. Imposes a motion prior that helps in dynamic scenes [S1].
*   **Limitations:** Relies on the availability of LiDAR point clouds. Predicting motion only between adjacent frames may accumulate errors over long sequences if not aggregated properly.
*   **When to Use:** Suitable for dynamic scene reconstruction in autonomous driving scenarios where LiDAR data is available and temporal consistency is critical [S1].

## Background
The Scene Flow Prior method is part of the LiDAR4D framework, introduced in the paper "LiDAR4D: Dynamic Neural Fields for Novel Space-Time View LiDAR Synthesis" [S1]. It was developed to address the challenges of reconstructing dynamic scenes from LiDAR data, specifically focusing on temporal consistency and geometric accuracy. The method builds on the idea of using flow MLPs for motion estimation, as seen in prior works [20, 46] cited in the source [S1].
