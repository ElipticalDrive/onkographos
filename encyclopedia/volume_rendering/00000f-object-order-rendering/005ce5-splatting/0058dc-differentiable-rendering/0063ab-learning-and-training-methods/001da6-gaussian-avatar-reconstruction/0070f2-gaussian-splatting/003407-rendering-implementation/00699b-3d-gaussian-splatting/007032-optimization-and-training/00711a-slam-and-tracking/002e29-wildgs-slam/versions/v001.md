# WildGS-SLAM


## Overview
WildGS-SLAM is a robust monocular RGB 3D Gaussian Splatting SLAM system designed for dynamic "in-the-wild" scenes [S2, unofficial]. It solves the problem of tracking and mapping failure caused by dynamic distractors (moving objects/people) by making the optimization residual uncertainty-aware [S1]. Unlike standard Gaussian SLAM methods that treat all pixels as static map constraints, WildGS-SLAM uses a learned uncertainty map to weight photometric and geometric errors, effectively suppressing unreliable observations from moving objects during bundle adjustment [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** Monocular RGB video stream; pre-extracted DINOv2 features for each frame [S2, unofficial].
*   **Output:** Camera poses, a static 3D Gaussian map, and an uncertainty map per frame [S2, unofficial].

**Data Structures:**
*   **Gaussian Set:** Inherits the standard 3D Gaussian data layout (position, covariance, opacity, spherical harmonics) from the parent [SLAM and Tracking](6236-slam-and-tracking.md).
*   **Uncertainty Map:** A per-pixel scalar field $\beta(u)$ predicted by a shallow MLP [S2, unofficial].
*   **Keyframe Window:** A sliding window of keyframes $W$ maintained for joint optimization, following the shared principles of the parent [S1][S2, unofficial].

**Algorithm Steps:**
1.  **Feature Extraction:** For each new frame, extract DINOv2 features [S2, unofficial].
2.  **Uncertainty Prediction:** Pass DINOv2 features through a shallow MLP to predict the uncertainty map $\beta(u)$ for each pixel $u$ [S2, unofficial]. High $\beta(u)$ indicates dynamic or unreliable regions [S1].
3.  **Tracking:** Perform pose estimation using the current Gaussian map. Utilize the uncertainty map to guide dynamic-object removal, ensuring only static scene elements contribute to the pose estimate [S2, unofficial].
4.  **Keyframe Selection:** Select new keyframes based on covisibility and geometric displacement, maintaining a sparse set $W$ [S1][S2, unofficial].
5.  **Mapping (Uncertainty-Aware Optimization):** Jointly optimize camera poses and Gaussian attributes within the keyframe window $W$. The optimization minimizes the mapping loss $L_{map}$ [S1]:
    $$ L_{map} = \sum_u \frac{\lambda_I L_I(u) + \lambda_D L_D(u)}{\beta(u)^2} + \lambda_{iso} L_{iso} $$
    Where:
    *   $u$ iterates over pixels.
    *   $L_I(u)$ is the photometric loss for pixel $u$ [S1].
    *   $L_D(u)$ is the geometric loss for pixel $u$ [S1].
    *   $\beta(u)$ is the uncertainty weight for pixel $u$ [S1].
    *   $\lambda_I, \lambda_D, \lambda_{iso}$ are scalar weights [S1].
    *   $L_{iso}$ is an isotropy loss term [S1].
    *   The term $\frac{1}{\beta(u)^2}$ acts as a weight; larger uncertainty suppresses the contribution of that pixel to the loss [S1].
6.  **Gaussian Initialization:** Initialize new Gaussians from new keyframes via back-projection or rendering with low variance, as per standard incremental mapping principles [S1][S2, unofficial].

**Parameters:**
*   $\lambda_I, \lambda_D, \lambda_{iso}$: Loss weights. Specific values are not given in the sources [S1].
*   MLP Architecture: Shallow MLP. Specific layer sizes are not given in the sources [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Dynamic Scenes:** The method is specifically designed to handle dynamic distractors. Standard Gaussian SLAM may fail or produce ghosting in such scenes [S2, unofficial].
*   **Uncertainty Calibration:** The effectiveness relies on the MLP accurately predicting $\beta(u)$. If $\beta(u)$ is poorly calibrated, static regions might be suppressed or dynamic regions included [S1].
*   **Monocular Ambiguity:** As a monocular system, scale ambiguity exists. The reported metrics use full-trajectory RMSE, which is scale-invariant for translation-only errors but sensitive to scale drift [S1].

## Operating characteristics
*   **Performance:** On the monocular Crowd sequence, WildGS-SLAM processes frames at 1525.64 ms/frame (0.655 frames/s) [S1]. The wrapped timing includes preprocessing, pose estimation, mapping/update, rendering, and finalization [S1].
*   **Accuracy:** Full-trajectory RMSE is 0.00665 m; keyframe RMSE is 0.00371 m [S1].
*   **Model Size:** The reconstructed Gaussian map size is 9.78 MiB [S1].
*   **Comparison:** These metrics are not directly comparable to RGB-D systems like MonoGS or RTG-SLAM due to different sequences (monocular vs. RGB-D) and metrics (RMSE vs. ATE) [S1].
*   **Strengths:** Robustness to dynamic in-the-wild scenes; clean static map reconstruction despite moving distractors [S2, unofficial].
*   **Limitations:** Lower throughput (0.655 fps) compared to real-time rendering targets; relies on external feature extractor (DINOv2) [S2, unofficial].

## Background
WildGS-SLAM [69] is a Gaussian SLAM method that addresses the failure mode of dynamic distractors by making the residual uncertainty-aware [S1]. It was marked as a 2026 SOTA update in the context of Gaussian Splatting variants [S2, unofficial]. It builds on the coupled camera estimation and Gaussian-map optimization framework established by systems like MonoGS [S1].
