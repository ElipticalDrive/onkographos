# SplattingAvatar

Also called: Realistic Real-Time Human Avatars with Mesh-Embedded Gaussian Splatting

## Overview
SplattingAvatar is a real-time human avatar rendering method that embeds 3D Gaussians directly onto a driving mesh (FLAME or NHA) in mesh tangent space [S2, unofficial]. It solves the problem of noisy, unstable deformation in complex geometry (e.g., eyes, hair) caused by nearest-triangle sampling in canonical space [S2, unofficial]. Unlike methods that focus on accurate geometry reconstruction, SplattingAvatar prioritizes photometric quality and rendering efficiency, achieving over 300 FPS on consumer hardware [S2, unofficial].

## How it works
**Inputs:**
*   Multi-angle video of a subject (typically 30 seconds) [S1, unofficial].
*   Pre-fitted mesh parameters (FLAME or NHA) obtained via tools like MICA or DECA [S1, unofficial].
*   SMPL-X rig structure [S1, unofficial].

**Outputs:**
*   A set of 3D Gaussians embedded on the mesh surface.
*   Trainable embeddings for motion control.
*   Real-time animatable avatar rendering.

**Data Structures:**
*   **Gaussian Attributes:** Position, covariance, opacity, spherical harmonics coefficients, and trainable embeddings.
*   **Mesh Embedding:** Each Gaussian is associated with a specific triangle on the driving mesh and its local tangent space coordinates [S2, unofficial].
*   **Rendering Primitive:** One quad primitive per Gaussian in the Unity implementation [S2, unofficial].

**Parameters:**
*   Loss weight for L1 loss ($\lambda_l$): 0.01 [S2, unofficial].
*   Other loss weights: $\lambda_s = 1.0$, $T_s = 10.0$, $T_r = 0.008$ [S2, unofficial].
*   Total training iterations: 30,000 [S2, unofficial].

**Algorithm Steps:**

1.  **Initialization:** Initialize one Gaussian per mesh triangle in the mesh tangent space [S1, unofficial].
2.  **Training Loop (30,000 iterations):**
    *   **Iterations 0–599:** Standard 3D Gaussian Splatting optimization without densification/pruning [S2, unofficial].
    *   **Iterations 600–15,000:**
        *   Every 100 iterations: Perform densify and prune operations [S2, unofficial].
        *   Every 3,000 iterations: Reset the opacity of all Gaussians to zero to remove redundant Gaussians [S2, unofficial].
        *   After densify/prune: Perform the "walking on triangle" step to ensure Gaussians remain within their assigned mesh triangles [S2, unofficial].
    *   **Iterations 15,001–30,000:** Continue optimization without densify, prune, or opacity-reset steps [S2, unofficial].
3.  **Motion Control (Rendering):**
    *   Use trainable embeddings ported to compute shaders to control Gaussian motion based on pose/expression parameters [S2, unofficial].
    *   Avoid nearest-triangle sampling for deformation from posed space to canonical space to prevent noise [S2, unofficial].
4.  **Rendering:**
    *   Draw one quad primitive per Gaussian [S2, unofficial].
    *   Use $\alpha^*$-blending [S2, unofficial].

**Pseudocode:**

```python
def train_splatting_avatar(mesh, video_frames, num_iterations=30000):
    # Initialize Gaussians in mesh tangent space
    gaussians = initialize_gaussians_per_triangle(mesh)
    
    for iter in range(num_iterations):
        # Sample a frame and corresponding pose/expression parameters
        frame, pose_params = sample_video_frame(video_frames)
        
        # Render the frame using current Gaussian attributes and pose_params
        rendered_image = render_gaussians(gaussians, pose_params)
        
        # Compute loss
        loss = compute_loss(rendered_image, frame)
        
        # Backpropagate and update Gaussian attributes
        update_gaussians(gaussians, loss)
        
        # Densify and Prune schedule
        if iter >= 600 and iter <= 15000:
            if iter % 100 == 0:
                densify_and_prune(gaussians)
                # Ensure Gaussians stay within mesh triangles
                walking_on_triangle(gaussians)
            
            if iter % 3000 == 0:
                reset_opacity(gaussians)

def render_gaussians(gaussians, pose_params):
    # Use trainable embeddings for motion control
    # Avoid nearest-triangle sampling
    transformed_gaussians = apply_embedding_motion_control(gaussians, pose_params)
    
    # Draw quad primitives and blend
    image = unity_render_quad_primitives(transformed_gaussians)
    return image

def walking_on_triangle(gaussians):
    # Adjust Gaussian positions to remain within their assigned mesh triangles
    # This prevents sticking/piling up on triangle boundaries
    for gaussian in gaussians:
        gaussian.position = project_to_triangle(gaussian.position, gaussian.triangle_index)
```

**Edge Cases and Pitfalls:**
*   **Nearest-Triangle Sampling:** Using nearest-triangle sampling for deformation (as in INSTA) causes unstable sampling in canonical space and strong noise in complex geometries like the eye region [S2, unofficial].
*   **Disabling "Walking on Triangle":** Disabling this mechanism and clipping UV values causes Gaussians to stick and pile up on mesh triangle boundaries, leading to performance drops in PSNR, SSIM, and LPIPS [S2, unofficial].

## Operating characteristics
*   **Performance:** Over 300 FPS on an NVIDIA RTX 3090 GPU [S2, unofficial].
*   **Runtime Costs:** The "walking on triangle" step takes approximately 3.5 ms per frame (pybind11 implementation). Densify-clone takes 2.5 ms, and densify-split takes 6 ms [S2, unofficial].
*   **Quality (Head Avatar Dataset):**
    *   Ours+FLAME: PSNR 28.19, SSIM 0.931, LPIPS 0.063 [S2, unofficial].
    *   Ours+NHA: PSNR 28.86, SSIM 0.931, LPIPS 0.060 [S2, unofficial].
*   **Comparison:** Outperforms FLARE in photometric quality and rendering efficiency, though FLARE focuses more on accurate geometry and materials reconstruction [S2, unofficial].
*   **Strengths:** Non-ambiguous motion control, high-fidelity rendering of complex geometries (eyes, hair), real-time performance.
*   **Limitations:** Does not focus on accurate geometry reconstruction; relies on pre-fitted mesh parameters.

## Background
SplattingAvatar was introduced as a method for realistic real-time human avatar rendering [S2, unofficial]. It builds on the 3D Gaussian Splatting framework but modifies the representation to embed Gaussians in mesh tangent space [S1, unofficial]. It addresses limitations of previous methods like INSTA, which used nearest-triangle sampling and suffered from noise in complex regions [S2, unofficial]. The method is part of a broader trend of using mesh-embedded Gaussians for avatar reconstruction, alongside methods like HUGS, 3DGS-Avatar, and GaussianAvatars [S1, unofficial].
