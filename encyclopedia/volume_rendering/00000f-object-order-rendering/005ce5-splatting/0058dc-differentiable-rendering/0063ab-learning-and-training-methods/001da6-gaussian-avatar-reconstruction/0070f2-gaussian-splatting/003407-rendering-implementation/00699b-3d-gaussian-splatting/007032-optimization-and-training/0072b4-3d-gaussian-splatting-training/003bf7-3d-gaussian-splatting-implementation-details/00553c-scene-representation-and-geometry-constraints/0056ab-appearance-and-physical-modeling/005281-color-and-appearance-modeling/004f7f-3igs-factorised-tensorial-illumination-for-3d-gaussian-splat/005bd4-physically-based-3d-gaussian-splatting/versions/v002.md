# Physically-Based 3D Gaussian Splatting

Also called: 3DGS PBR Framework, PBR Color Computation, PBR with 3D Gaussians, Physically-Based Rendering (PBR) with 3D Gaussians, Physically-based Gaussian Rendering

## Overview
Physically-Based 3D Gaussian Splatting (PBR 3DGS) is a framework that assigns physically interpretable rendering attributes to Gaussian primitives and evaluates the rendering equation to produce per-Gaussian PBR colors, replacing the view-dependent spherical harmonics used in vanilla 3DGS with a physical Bidirectional Reflectance Distribution Function (BRDF) [S1, S2]. It solves the problem of inverse rendering and relighting by enabling the simulation of complex lighting interactions, which vanilla 3DGS cannot natively represent due to its lack of physical material definitions [S1]. Unlike vanilla 3DGS, which uses $k$-order spherical harmonics for view-dependent effects that lack physical interpretability, this method provides physical interpretability by explicitly modeling albedo, roughness, and metalness [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of 3D Gaussian points $\{G_i\}$, each defined by position $\mu_i$, scale $S_i$, rotation $R_i$, and opacity $\alpha_i$ [S1]. The method requires a learnable environment light probe $L(\omega_i)$ [S2].
*   **Outputs:** Final rendered images via alpha compositing of shaded Gaussian points [S1].

**Data Structures:**
*   **Gaussian Attributes:** Each Gaussian $i$ stores learnable PBR attributes queried from multi-resolution hash grids based on its position $\mu_i$ [S1].
    *   **Diffuse Albedo ($a_i$):** Queried from hash grid $\mathcal{E}_d$ [S1].
    *   **Roughness ($\rho_i$) and Metalness ($m_i$):** Queried from hash grid $\mathcal{E}_s$ [S1].
    *   **Normal ($n_i$):** Derived from the Gaussian's geometry or mesh surface [S1, S2].
*   **Light Probe:** A learnable environment light $L(\omega_i)$ stored in latitude-longitude format with dimensions $32 \times 64 \times 1$ [S2].
*   **Visibility ($v_i$):** Modeled as a 3-degree Spherical Harmonic (SH) coefficient set to represent occlusion [S2].

**Formulas:**
The core of the method is the evaluation of the rendering equation [S1, S2]:
$$ L_o(x, \omega_o) = \int_{\mathcal{H}} f_r(x, \omega_i, \omega_o) L_i(x, \omega_i) |n \cdot \omega_i| d\omega_i $$
Where:
*   $L_o(x, \omega_o)$ is the outgoing radiance in direction $\omega_o$ [S1, S2].
*   $f_r(x, \omega_i, \omega_o)$ is the BRDF [S1, S2].
*   $L_i(x, \omega_i)$ is the incoming light [S1, S2].
*   $n$ is the surface normal [S1, S2].
*   $\omega_i$ is the incoming light direction [S1, S2].
*   $\omega_o$ is the outgoing/view direction [S1, S2].
*   $\mathcal{H}$ is the hemisphere [S1, S2].

The BRDF $f_r$ is modeled using the GGX microfacet model (Disney BRDF) [S1, S2]:
$$ f_r(x, \omega_i, \omega_o) = (1 - m) \frac{a}{\pi} + \frac{D \cdot F \cdot G}{4 |n \cdot \omega_i| |n \cdot \omega_o|} $$
Where:
*   $m$ is metalness [S1, S2].
*   $a$ is albedo [S1, S2].
*   $D$ is the microfacet distribution function (influenced by roughness $\rho$) [S2].
*   $F$ is the Fresnel reflection term [S2].
*   $G$ is the geometric shadowing factor (influenced by roughness $\rho$) [S2].
*   $D \cdot F \cdot G$ is collectively referred to as $DFG$ in some implementations [S1].

The incoming light $L_i$ is computed as:
$$ L_i(x, \omega_i) = v(x, \omega_i) L(\omega_i) $$
Where $v(x, \omega_i)$ is the visibility (occlusion) and $L(\omega_i)$ is the environment light [S2].

**Parameters:**
*   **Environment Light Resolution:** $32 \times 64$ latitude-longitude map [S2].
*   **Visibility SH Degree:** 3-degree [S2].
*   **Metalness:** Can be manually set to zero to simplify modeling in avatar reconstruction [S2].

**Numbered Steps:**
1.  **Attribute Query:** For each Gaussian point $i$ with position $\mu_i$, query the multi-resolution hash grids to obtain PBR attributes: $a_i = \mathcal{E}_d(\mu_i)$ and $(\rho_i, m_i) = \mathcal{E}_s(\mu_i)$ [S1].
2.  **Light Transport Evaluation:** Evaluate the incident lighting $L_i(x, \omega_i)$ by querying the learnable environment light probe $L(\omega_i)$ and applying the visibility term $v(x, \omega_i)$ [S2].
3.  **BRDF Computation:** Compute the BRDF $f_r$ using the queried attributes ($a_i, \rho_i, m_i$) and the normal $n_i$ via the GGX model [S1, S2].
4.  **Rendering Equation Solution:** Differentiably solve the rendering equation using Monte Carlo sampling to obtain the PBR color (outgoing radiance $L_o$) for each Gaussian point [S1].
5.  **Rasterization:** Process the shaded Gaussian points using standard 3DGS rasterization [S1].
6.  **Compositing:** Render the final images via alpha compositing of the shaded Gaussians [S1].
7.  **Optimization:** Apply backpropagation to optimize the PBR attributes (hash grid values, light probe, visibility) through photometric supervision [S1].

**Pseudocode:**
```python
import math
import numpy as np

def sample_hemisphere(normal):
    u = np.random.uniform(0, 1)
    v = np.random.uniform(0, 1)
    phi = 2 * math.pi * u
    cos_theta = math.sqrt(v)
    sin_theta = math.sqrt(1 - cos_theta**2)
    x, y, z = sin_theta * math.cos(phi), sin_theta * math.sin(phi), cos_theta
    up = np.array([0, 0, 1]) if abs(normal[2]) < 0.999 else np.array([1, 0, 0])
    tangent = np.cross(up, normal)
    tangent /= np.linalg.norm(tangent)
    bitangent = np.cross(normal, tangent)
    return tangent * x + bitangent * y + normal * z

def direction_to_lat_lon(direction):
    lat = int(math.acos(direction[2]) / math.pi * 32) % 32
    lon = int((math.atan2(direction[1], direction[0]) / (2 * math.pi) + 0.5) * 64) % 64
    return lat, lon

def evaluate_sh(coeffs, direction):
    # Standard 3-degree SH basis evaluation for mono-channel visibility
    return np.dot(coeffs, np.array([1, direction[0], direction[1], direction[2], 
                                    direction[0]*direction[1], direction[1]*direction[2],
                                    3*direction[2]**2-1, direction[2]*direction[0], direction[0]**2-direction[1]**2]))

def ggx_distribution(roughness, normal, omega_i):
    alpha = roughness ** 2
    cos_theta_i = max(0.0, np.dot(normal, omega_i))
    denom = cos_theta_i**2 * (alpha**2 - 1) + 1
    return alpha**2 / (math.pi * denom**2)

def fresnel(metalness, albedo, normal, omega_i):
    cos_theta_i = max(0.0, np.dot(normal, omega_i))
    F0 = metalness + (1 - metalness) * 0.04
    return F0 + (1 - F0) * (1 - cos_theta_i)**5

def geometric_shadowing(roughness, normal, omega_i):
    cos_theta_i = max(0.0, np.dot(normal, omega_i))
    k = (roughness + 1)**2 / 8
    return cos_theta_i / (cos_theta_i * (1 - k) + k)

def composite(image, color, alpha):
    return image * (1 - alpha) + color * alpha

def compute_pbr_color(gaussian, hash_grids, light_probe, visibility_sh, view_direction):
    albedo = hash_grids['Ed'](gaussian.mu)
    roughness, metalness = hash_grids['Es'](gaussian.mu)
    Lo = 0.0
    num_samples = 1024
    for _ in range(num_samples):
        omega_i = sample_hemisphere(gaussian.n)
        lat, lon = direction_to_lat_lon(omega_i)
        Li = light_probe[lat, lon, :]
        v = evaluate_sh(visibility_sh, omega_i)
        Li_effective = v * Li
        diffuse_term = (1 - metalness) * (albedo / math.pi)
        D = ggx_distribution(roughness, gaussian.n, omega_i)
        F = fresnel(metalness, albedo, gaussian.n, omega_i)
        G = geometric_shadowing(roughness, gaussian.n, omega_i)
        denom = 4 * abs(np.dot(gaussian.n, omega_i)) * abs(np.dot(gaussian.n, view_direction))
        specular_term = (D * F * G) / denom if denom > 1e-6 else 0.0
        fr = diffuse_term + specular_term
        cos_theta = abs(np.dot(gaussian.n, omega_i))
        Lo += fr * Li_effective * cos_theta
    return Lo / num_samples

def render_gaussians(gaussians, camera, hash_grids, light_probe, visibility_sh):
    image = np.zeros((camera.height, camera.width, 3))
    projected = [(g, camera.project(g)) for g in gaussians]
    sorted_gaussians = sorted(projected, key=lambda x: x[1].depth)
    for g, proj in sorted_gaussians:
        view_direction = camera.pos - g.mu
        view_direction /= np.linalg.norm(view_direction)
        color = compute_pbr_color(g, hash_grids, light_probe, visibility_sh, view_direction)
        alpha = g.opacity
        image = composite(image, color, alpha)
    return image
```

**Edge Cases and Pitfalls:**
*   **Boundaries:** The hash grid queries must handle out-of-bounds positions gracefully, typically by clamping or using periodic boundary conditions inherent to hash grids [S1].
*   **Degenerate Input:** If the Gaussian normal is undefined (e.g., at initialization), the BRDF evaluation may fail; a default normal or fallback to spherical harmonics might be needed [G].

## Subtopics

### Geometry Guided Gaussian Points Generation
Generates Gaussian points on a mesh surface extracted via FlexiCubes, ensuring geometric consistency [S1].

### Light Transport Modeling
Uses BVH-accelerated ray tracing on the extracted mesh to evaluate light transport and occlusion, distinguishing it from methods that approximate occlusion with contiguous forms [S1].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:** Not given in the sources.
*   **Strengths:** Provides physically interpretable materials (albedo, roughness, metalness) and enables relighting and inverse rendering, which vanilla 3DGS cannot do [S1].
*   **Limitations:** More computationally expensive than vanilla 3DGS due to the BRDF evaluation and Monte Carlo sampling [S1].
*   **When to use:** When physically accurate lighting, relighting, or material estimation is required [S1].
*   **When not to use:** When real-time performance is critical and physical accuracy is not needed; vanilla 3DGS is faster [S1].

## Background
The method originates from the need to extend 3D Gaussian Splatting beyond view-dependent appearance modeling to physically based inverse rendering [S1]. Vanilla 3DGS uses spherical harmonics for view-dependent effects, which lack physical interpretability [S1]. GeoSplatting introduced the use of the rendering equation with GGX BRDF for physical interpretability [S1]. The specific framework described here utilizes multi-resolution hash grids for efficient attribute querying and learnable environment lights for relighting [S1, S2].
