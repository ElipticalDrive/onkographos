# Spherical Harmonics Encoder

Also called: SH Encoding, Spherical Harmonics Basis

## Overview
A neural network module that encodes a 3D direction vector into spherical harmonics (SH) coefficients up to a specified degree [S1, unofficial]. It solves the problem of representing directional information (view direction) in a differentiable, basis-function expansion for view-dependent rendering [S1, unofficial]. It differs from [Spherical Harmonics Evaluation](3848-spherical-harmonics-evaluation.md) by providing the raw basis coefficients rather than the final RGB color, and from [Neural Basis Functions](19516-neural-basis-functions.md) by relying on standard orthogonal polynomial bases rather than custom analytic forms [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A direction vector $\mathbf{d} = (x, y, z)$ of dimension 3.
- Output: A tensor of SH coefficients with shape `(*input.shape[:-1], out_dim)`, where `out_dim` is the total number of coefficients for the specified degree [S1, unofficial]. The last dimension holds coefficients in $m$-order (m=0, then m=-1,1, then m=-2,0,2, etc.) [S1, unofficial].

**Steps:**
1.  Unbind the input direction vector into components $x, y, z$:
    ```python
    x, y, z = input.unbind(-1)
    ```
2.  Compute degree 0 ($l=0, m=0$) coefficient:
    ```python
    result[..., 0] = self.C0
    ```
3.  If `degree` > 1, compute degree 1 ($l=1$) coefficients at indices 1, 2, 3:
    ```python
    result[..., 1] = -self.C1 * y
    result[..., 2] = self.C1 * z
    result[..., 3] = -self.C1 * x
    ```
4.  If `degree` > 2, compute intermediate quadratic terms:
    ```python
    xx, yy, zz = x * x, y * y, z * z
    xy, yz, xz = x * y, y * z, x * z
    ```
    Compute degree 2 ($l=2$) coefficients at indices 4-8:
    ```python
    result[..., 4] = self.C2[0] * xy
    result[..., 5] = self.C2[1] * yz
    result[..., 6] = self.C2[2] * (2.0 * zz - xx - yy)
    result[..., 7] = self.C2[3] * xz
    result[..., 8] = self.C2[4] * (xx - yy)
    ```
5.  If `degree` > 3, compute degree 3 ($l=3$) coefficients at indices 9-15 using constants $C_3$ and cubic terms involving $x, y, z, xx, yy, zz$ [S1, unofficial].
6.  If `degree` > 4, compute degree 4 ($l=4$) coefficients at indices 16-24 using constants $C_4$ and quartic terms [S1, unofficial].

**Pitfalls:**
- For degree 2, index 6, an alternative formula `self.C2[2] * (3.0 * zz - 1)` exists but is commented out in the source because `xx + yy + zz == 1` on the unit sphere, yet this alternative leads to different backward gradients [S1, unofficial].
- The input direction vector should ideally be normalized, although the encoder itself does not enforce normalization in the forward pass logic provided [S1, unofficial].

## Subtopics

### [SH Feature Encoding](6642-sh-feature-encoding.md)
SH Feature Encoding is a method for modeling view-dependent effects in neural radiance fields by multiplying each Spherical Harmonics (SH) basis coefficient with a learnable feature vector, rather than using the vanilla scalar SH encoding. It solves the problem of representing directional information (view direction) in a differentiable, basis-function expansion for view-dependent rendering by allowing the magnitude and orientation of the SH response to be modulated by spatially varying features. It differs from vanilla SH encoding [Spherical Harmonics Evaluation](4391-spherical-harmonics-evaluation.md) by introducing learnable per-coefficient feature vectors predicted from the scene's spatial features, and differs from the [SPZ Encoder](6850-spz-encoder.md) by relying on the explicit SH basis expansion rather than a direct parameterization.

### [SPZ Encoder](6850-spz-encoder.md)
The SPZ Encoder serializes Spherical Harmonics (SH) coefficients into a compact byte array. It handles degree clamping, dimension mapping, and fixed-point quantization for view-dependent color data.

### [Neural Basis Functions](19516-neural-basis-functions.md)
Neural Basis Functions are a set of parameterized mathematical functions used to represent the directional component $\tilde{H}$ in the rendering equation, allowing for the ablation and comparison of different functional forms for view-dependent color prediction. They solve the problem of encoding viewing direction into a differentiable feature vector that a neural network can process. What sets them apart from siblings like [Spherical Harmonics Encoder](4390-spherical-harmonics-encoder.md) is the explicit use of custom analytic forms (Fourier, Ka,b, Pa,b) tailored to specific viewing constraints (e.g., forward-facing hemispheres) rather than relying on standard orthogonal polynomial bases.

### Non-spatial Input Encoding
Encode auxiliary non-spatial dimensions (e.g., view direction, material parameters) using established techniques like one-blob encoding or spherical harmonics basis, as the hash encoding targets low-dimensional spatial coordinates [S2, unofficial].

## Background
Spherical Harmonics are widely used in computer graphics for representing functions on the sphere. In the context of neural rendering, they were adopted to encode view-dependent appearance, such as specular highlights, in a differentiable manner suitable for gradient-based optimization [S2, unofficial]. The specific implementation details provided in [S1, unofficial] are from the HashNeRF-pytorch repository, which implements a standard SH encoder for NeRF-like architectures.
