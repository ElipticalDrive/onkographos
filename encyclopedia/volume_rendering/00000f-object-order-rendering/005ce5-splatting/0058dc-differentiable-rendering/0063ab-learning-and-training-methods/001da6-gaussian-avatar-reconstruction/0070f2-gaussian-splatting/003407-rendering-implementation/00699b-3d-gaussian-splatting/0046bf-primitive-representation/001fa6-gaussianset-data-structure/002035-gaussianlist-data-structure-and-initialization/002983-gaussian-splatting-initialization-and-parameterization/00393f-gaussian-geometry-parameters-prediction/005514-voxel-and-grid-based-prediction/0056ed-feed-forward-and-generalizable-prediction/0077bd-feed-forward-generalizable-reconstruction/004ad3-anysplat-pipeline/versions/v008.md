# AnySplat Pipeline

Also called: Feed-forward 3D Gaussian Splatting from Unconstrained Views

## Overview
AnySplat is a feed-forward method for 3D Gaussian Splatting that predicts scene geometry and appearance directly from uncalibrated input images, eliminating the need for Structure-from-Motion (SfM) preprocessing [S1, unofficial]. It differs from sibling methods like Splatt3R and ZeroGS by explicitly predicting camera poses and depth maps alongside Gaussian parameters through a unified transformer-based architecture, enabling end-to-end differentiable training with geometry supervision [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A batch of $K$ RGB images $\{I_i\}_{i=1}^K$. The tensor shape is $[1, K, 3, 448, 448]$ (batch, views, channels, height, width) [S1, unofficial].
*   **Outputs:** A set of 3D Gaussians defined by parameters $\Theta = \{\mu, \sigma, r, s, c\}$ (mean, scale, rotation, color/spherical harmonics, opacity) and predicted camera poses $p$ (intrinsics and extrinsics) [S1, unofficial].

**Data Structures:**
The method constructs pixel-wise 3D Gaussians from the decoder outputs. These are then processed by a Differentiable Voxelization module to create "pre-voxel 3D Gaussians" suitable for rasterization [S1, unofficial]. The specific internal layout of the Gaussian parameter tensor is not detailed in the sources, but standard 3DGS parameters are implied [G].

**Steps:**
1.  **Feature Extraction:** Input images are passed through a transformer-based geometry encoder.
2.  **Parameter Prediction:** Three decoder heads ($F_G, F_D, F_C$) predict:
    *   $F_G$: Gaussian parameters $\mu, \sigma, r, s, c$.
    *   $F_D$: Depth map $D$.
    *   $F_C$: Camera poses $p$.
3.  **Gaussian Construction:** The predicted parameters are used to construct a set of pixel-wise 3D Gaussians [S1, unofficial].
4.  **Differentiable Voxelization:** The pixel-wise Gaussians are voxelized into pre-voxel 3D Gaussians using the Differentiable Voxelization module [S1, unofficial].
5.  **Rendering:** Multi-view images and depth maps are rendered from the voxelized Gaussians using differentiable rasterization [S1, unofficial].
6.  **Loss Computation:**
    *   **RGB Loss:** Rendered images are compared against ground truth images.
    *   **Geometry Loss:** Rendered depth maps, decoded depth $D$, and predicted poses $p$ are used to compute geometry losses [S1, unofficial].
7.  **Supervision:** Geometries are supervised by pseudo-geometry priors obtained from a pretrained VGGT model [S1, unofficial].

**Pseudocode:**
```python
# Inference
def inference(model, image_paths):
    # Load and preprocess images
    images = []
    for path in image_paths:
        img = process_image(path) # Returns tensor normalized to [-1, 1]
        images.append(img)
    
    # Stack images: [1, K, 3, 448, 448]
    images_tensor = torch.stack(images, dim=0).unsqueeze(0).to(device)
    
    # Run model inference
    # Input normalization: (images + 1) * 0.5 maps [-1, 1] to [0, 1]
    gaussians, pred_context_pose = model.inference((images_tensor + 1) * 0.5)
    
    # Extract poses
    pred_all_extrinsic = pred_context_pose['extrinsic']
    pred_all_intrinsic = pred_context_pose['intrinsic']
    
    return gaussians, pred_all_extrinsic, pred_all_intrinsic

# Training (Conceptual)
def train_step(model, images, gt_images, vggt_priors):
    # Forward pass
    gaussians, pred_context_pose = model.inference((images + 1) * 0.5)
    
    # Render
    rendered_images, rendered_depths = render(gaussians, pred_context_pose)
    decoded_depth = pred_context_pose['depth']
    poses = pred_context_pose['pose']
    
    # Losses
    rgb_loss = compute_rgb_loss(rendered_images, gt_images)
    geometry_loss = compute_geometry_loss(rendered_depths, decoded_depth, poses, vggt_priors)
    
    total_loss = rgb_loss + geometry_loss
    return total_loss
```

**Parameters:**
*   **Image Resolution:** 448x448 [S1, unofficial].
*   **Framework:** PyTorch 2.2.0, CUDA 12.1 [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Uncalibrated Inputs:** The method handles uncalibrated views, but accuracy depends on the quality of the pseudo-geometry priors from VGGT [S1, unofficial].
*   **Voxelization:** The choice of voxelization parameters (not specified) affects the density and rendering quality of the pre-voxel Gaussians [S1, unofficial].
