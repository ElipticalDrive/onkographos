# Tile-based Rasteriser

Also called: Tile-based Rasterizer

## Overview
The tile-based rasteriser sorts projected 2D Gaussian splats once per frame to serve both forward rendering and backpropagation [S1, unofficial]. It solves the depth-ordering problem for millions of splats by dividing the image into $16 \times 16$ tiles and using a single global radix sort, eliminating sequential primitive processing steps [S2][S3, unofficial]. Unlike per-pixel sorting, which is too slow for real-time performance, this method achieves parallel depth resolution and compact per-tile lists, enabling the backward pass to reuse the same sorted lists for gradient computation without additional sorting [S1, unofficial][S2].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A list of $N$ projected 2D Gaussian splats. Each splat $i$ is defined by its center $(x_i, y_i)$, 2D covariance matrix $\Sigma'_i$, color $c_i$, opacity $\alpha_i$, and depth $Z_c$ [S1, unofficial][S2].
*   **Outputs:** A sorted list of (splat, tile) pairs, and the final rendered image with alpha-blended colors [S1, unofficial][S2].

**Data Structures:**
*   **Splat List:** An array of $N$ splats [S1, unofficial][S2].
*   **Tile Grid:** The image is divided into a grid of tiles with dimensions $T_w \times T_h$. The standard tile size is $16 \times 16$ pixels [S2][S3, unofficial][S4, unofficial].
*   **Sort Key:** A 64-bit integer key for each (splat, tile) pair. The key is constructed as:
    $$ \text{key} = (\text{tile\_id} \ll 32) \mid (\text{uint32\_t})Z_c $$
    where `tile_id` is the 1D tile index ($y \times \text{grid\_width} + x$) and $Z_c$ is cast to a 32-bit unsigned integer [S2][S3, unofficial]. The exact size of the tile index depends on the number of tiles fitting the current resolution [S2][S3, unofficial].

**Steps:**
1.  **Tile Assignment:** Each Gaussian is assigned to every tile its projected 2D splat touches. If a splat straddles tile boundaries, it is duplicated into each relevant tile, creating one work item per (Gaussian, tile) pair [S1, unofficial][S4, unofficial].
2.  **Key Packing:** For each (splat, tile) pair, a 64-bit integer sort key is constructed. The tile ID is packed into the high bits, and the splat's depth $Z_c$ is packed into the low bits [S2][S4, unofficial].
3.  **Global Radix Sort:** A single GPU radix sort is performed over all (splat, tile) pairs [S2][S3, unofficial]. This simultaneously bins splats by tile ID (ensuring contiguity) and sorts them by depth within each tile [S3, unofficial][S4, unofficial].
4.  **Range Identification:** Per-tile ranges in the sorted array are identified by comparing the higher 32 bits of each element with its two neighbors using one thread per 64-bit element [S2][S3, unofficial]. This eliminates sequential primitive processing steps and produces more compact per-tile lists [S2][S3, unofficial].
5.  **Rendering:** Each tile is processed by one GPU thread block that walks the sorted list. For each pixel in a tile, front-to-back compositing is performed using the tile's sorted list of splats, evaluating per-pixel alpha $\alpha_i(\mathbf{x})$ and breaking early when transmittance $T < \epsilon$ [S1, unofficial][S4, unofficial].
6.  **Backpropagation:** The same sorted lists are reused for backpropagation, allowing gradients to flow to position, shape, opacity, and color without additional sorting [S1, unofficial].

**Parameters:**
*   **Tile Size:** $16 \times 16$ pixels [S2][S3, unofficial][S4, unofficial].
*   **Key Size:** 64 bits (32 bits depth, 32 bits tile index) [S2][S3, unofficial].
*   **Alpha Clamping:** Alpha is clamped with 0.99 from above [S2].
*   **Blending Stop:** Before including a Gaussian in the forward pass, the accumulated opacity if it were included is computed, and front-to-back blending stops before it can exceed 0.9999 [S2].
*   **Skip Threshold:** Blending updates with $\alpha < 1/255$ are skipped [S2].

**Pseudocode:**
```python
import math

def tile_based_rasterization(splats, image_width, image_height, tile_size=16):
    """
    Renders 3D Gaussian splats using tile-based rasterization.
    
    Args:
        splats: List of N splats, each with attributes:
            - center: (x, y) in screen space
            - cov2d: 2x2 covariance matrix Sigma'
            - color: RGB color
            - opacity: alpha value
            - depth: Z_c (view space depth)
        image_width: Width of the image in pixels
        image_height: Height of the image in pixels
        tile_size: Size of each tile in pixels (default 16)
        
    Returns:
        rendered_image: Image buffer with final colors
    """
    tile_width = math.ceil(image_width / tile_size)
    tile_height = math.ceil(image_height / tile_size)
    
    work_items = []
    
    for i, splat in enumerate(splats):
        min_x, max_x, min_y, max_y = get_splat_tile_bounds(splat.center, splat.cov2d, tile_size)
        
        min_tx = math.floor(min_x / tile_size)
        max_tx = math.floor(max_x / tile_size)
        min_ty = math.floor(min_y / tile_size)
        max_ty = math.floor(max_y / tile_size)
        
        for ty in range(max(0, min_ty), min(tile_height, max_ty + 1)):
            for tx in range(max(0, min_tx), min(tile_width, max_tx + 1)):
                tile_id = ty * tile_width + tx
                key = (tile_id << 32) | (splat.depth & 0xFFFFFFFF)
                work_items.append((i, tile_id, key))
    
    # 2. Key Packing & 3. Global Radix Sort: Sort work_items by key using a GPU radix sort. 
    # This bins by tile_id and sorts by depth within each tile.
    work_items.sort(key=lambda item: item[2])
    
    # 4. Range Identification
    tile_ranges = {}
    if not work_items:
        return empty_image(image_width, image_height)
        
    current_tile = work_items[0][1]
    start_idx = 0
    
    for idx, item in enumerate(work_items):
        tile_id = item[1]
        if tile_id != current_tile:
            tile_ranges[current_tile] = (start_idx, idx)
            current_tile = tile_id
            start_idx = idx
    tile_ranges[current_tile] = (start_idx, len(work_items))
    
    # 5. Rendering
    rendered_image = empty_image(image_width, image_height)
    epsilon = 1e-4
    
    for tile_id, (start, end) in tile_ranges.items():
        tile_splat_indices = [work_items[i][0] for i in range(start, end)]
        ty = tile_id // tile_width
        tx = tile_id % tile_width
        
        for py in range(ty * tile_size, min((ty + 1) * tile_size, image_height)):
            for px in range(tx * tile_size, min((tx + 1) * tile_size, image_width)):
                T = 1.0
                color = (0.0, 0.0, 0.0)
                
                for splat_idx in tile_splat_indices:
                    splat = splats[splat_idx]
                    alpha = evaluate_gaussian_alpha(splat.center, splat.cov2d, px, py)
                    
                    if alpha < 1/255:
                        continue
                    
                    alpha = min(alpha, 0.99)
                    
                    new_alpha = 1.0 - T * (1.0 - alpha)
                    if new_alpha > 0.9999:
                        break
                        
                    color += splat.color * alpha * T
                    T *= (1.0 - alpha)
                    
                    if T < epsilon:
                        break
                
                rendered_image[py, px] = color
                
    return rendered_image

def evaluate_gaussian_alpha(center, cov2d, px, py):
    dx = px - center[0]
    dy = py - center[1]
    inv_cov = invert_matrix(cov2d)
    exponent = -0.5 * (dx * inv_cov[0][0] * dx + 2 * dx * inv_cov[0][1] * dy + dy * inv_cov[1][1] * dy)
    return math.exp(exponent)

def empty_image(width, height):
    return [[(0.0, 0.0, 0.0) for _ in range(width)] for _ in range(height)]

def get_splat_tile_bounds(center, cov2d, tile_size):
    eigenvalues = compute_eigenvalues(cov2d)
    sigma_x = math.sqrt(eigenvalues[0])
    sigma_y = math.sqrt(eigenvalues[1])
    min_x = center[0] - 3 * sigma_x
    max_x = center[0] + 3 * sigma_x
    min_y = center[1] - 3 * sigma_y
    max_y = center[1] + 3 * sigma_y
    return min_x, max_x, min_y, max_y

def compute_eigenvalues(matrix):
    a, b = matrix[0][0], matrix[0][1]
    c, d = matrix[1][0], matrix[1][1]
    trace = a + d
    det = a * d - b * c
    discriminant = trace * trace - 4 * det
    if discriminant < 0:
        discriminant = 0
    sqrt_disc = math.sqrt(discriminant)
    eig1 = (trace + sqrt_disc) / 2
    eig2 = (trace - sqrt_disc) / 2
    return eig1, eig2

def invert_matrix(matrix):
    a, b = matrix[0][0], matrix[0][1]
    c, d = matrix[1][0], matrix[1][1]
    det = a * d - b * c
    if det == 0:
        return [[1.0, 0.0], [0.0, 1.0]]
    inv_det = 1.0 / det
    return [[d * inv_det, -b * inv_det], [-c * inv_det, a * inv_det]]
```

**Edge Cases and Pitfalls:**
*   **Numerical Instability:** During the backward pass, reconstructing intermediate opacity values by dividing accumulated opacity by Gaussian opacity alpha is prone to numerical instabilities (e.g., division by 0) [S2]. This is addressed by skipping blending updates with $\alpha < 1/255$ and clamping $\alpha$ with 0.99 from above [S2].
*   **Sorting Complexity:** Sorting per pixel is too slow for millions of splats; tile-based sorting with a single global radix sort is required for real-time performance [S1, unofficial].
*   **Straddling Splats:** A splat straddling tile boundaries is duplicated into each relevant tile. This results in a moderate increase in Gaussians to process, which is amortized by simpler control flow and high parallelism of optimized GPU Radix sort [S2][S3, unofficial].

## Operating characteristics
*   **Time Complexity:** One O(n) radix sort over all (splat, tile) pairs replaces thousands of per-tile sorts [S4, unofficial]. The sorting is performed once per frame [S1, unofficial].
*   **Memory Complexity:** The number of work items increases due to splat duplication across tiles, but this is moderate and amortized by the efficiency of the radix sort [S2][S3, unofficial].
*   **Measured Performance:** On the Mip-NeRF360 benchmark, the method reaches 27.21 dB PSNR and 0.214 LPIPS at 134 fps, surpassing the previous quality leader in perceptual similarity while trailing marginally in PSNR and rendering roughly three orders of magnitude faster [S1, unofficial].
*   **Strengths:** Eliminates sequential primitive processing steps, produces more compact per-tile lists, and allows the backward pass to reuse the same sorted lists for training [S2][S3, unofficial][S1, unofficial].
*   **Limitations:** Numerical instability during the backward pass if not handled with clamping and thresholding [S2].
*   **When to Use:** When real-time rendering and training of 3D Gaussian Splatting are required, especially with millions of splats [S1, unofficial].

## Background
The tile-based rasteriser was introduced in the paper "3D Gaussian Splatting for Real-Time Radiance Field Rendering" by Kerbl et al. [S2][S3, unofficial]. It is a key component of the 3D Gaussian Splatting rendering pipeline, which also includes anisotropic 3D Gaussian projection, EWA projection, and adaptive density control [S1, unofficial]. The method builds on the assumption of a high load of small splats and optimizes for this by sorting splats once for each frame using radix sort [S2][S3, unofficial]. It eliminates sequential primitive processing steps compared to previous methods like [Lassner and Zollhofer 2021] [S2][S3, unofficial].
