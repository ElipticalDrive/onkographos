# GlobalSplat

Also called: GlobalSplat: Efficient Feed-Forward 3D Gaussian Splatting via Global Scene Tokens

## Overview
GlobalSplat is a feed-forward 3D Gaussian Splatting framework that aligns multi-view inputs into a fixed set of global latent scene tokens before decoding explicit 3D geometry, preventing representation bloat and ensuring global consistency [S1]. Unlike sibling methods such as [C3G](12847-anysplat-pipeline.md) which rely on full self-attention and single-Gaussian decoding, GlobalSplat uses an iterative, disentangled dual-branch architecture and a coarse-to-fine capacity curriculum to achieve a superior quality-efficiency trade-off in large-context settings [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $C$ RGB images $I \in \mathbb{R}^{H \times W \times 3}$ with known camera poses $T_i$ (rotation $R_i$, translation $t_i$) and intrinsics $K_i$ [S1].
*   **Output:** A set of $N$ 3D Gaussians $\mathcal{G} = \{g_n\}_{n=1}^N$, where each Gaussian $g_n$ is defined by mean $\mu_n$, covariance $\Sigma_n$ (parameterized by scale $s_n$ and rotation $r_n$), opacity $\alpha_n$, and spherical harmonics coefficients $c_n$ [S1].

**Data Structures:**
*   **Latent Tokens:** A fixed set of $M=2048$ learnable latent tokens $l_j \in \mathbb{R}^{512}$ and learnable register tokens [S1].
*   **Gaussian Candidates:** For each latent token, the decoder predicts $K_s=16$ candidates [S1].
    *   Geometry: $\mathbf{X}_p \in \mathbb{R}^{16 \times 3}$ (means), $\mathbf{S}_p \in \mathbb{R}^{16 \times 3}$ (log-scales), $\mathbf{R}_p \in \mathbb{R}^{16 \times 6}$ (6D rotations), $\mathbf{O}_p \in \mathbb{R}^{16 \times 1}$ (opacity logits), $\boldsymbol{\ell}_p \in \mathbb{R}^{16 \times 1}$ (importance scores) [S1].
    *   Appearance: $\mathbf{C}_p \in \mathbb{R}^{16 \times (3 D_{\text{SH}})}$ (SH coefficients), where $D_{\text{SH}} = (3+1)^2 = 16$ [S1].
*   **Merged Gaussians:** At stage $s$, candidates are grouped into $G=2^s$ groups of size $b_s = 16/G$ [S1]. The merged attributes $\bar{\mathbf{z}}_{p,g}$ are computed via weighted aggregation using temperature-scaled softmax weights [S1].

**Preprocessing:**
1.  **Scene Normalization:**
    *   Compute canonical frame origin: $\bar{o} = \frac{1}{C} \sum_{i=1}^C o_i$ [S1].
    *   Compute axes by averaging camera viewing directions and re-orthonormalizing. Let $T_{\text{avg}}$ be the resulting average pose [S1].
    *   Transform all cameras: $\hat{T}_i = T_{\text{avg}}^{-1} T_i$ [S1].
    *   Compute scene scale: $s = \max_{a,b} \|\hat{o}_a - \hat{o}_b\|_2$ [S1].
    *   Scale translations: $\tilde{o}_i = \frac{\hat{o}_i}{s}$ [S1].
2.  **Image Preprocessing:**
    *   Resize image to height 256 preserving aspect ratio [S1].
    *   Round width to a multiple of patch size 8 [S1].
    *   Update intrinsics accordingly [S1].
    *   Apply centered square crop [S1].
    *   Final resize to $256 \times 256$ [S1].
3.  **Input Context Construction:**
    *   Extract patchified RGB tokens $u_{i,p}^{\text{rgb}}$ from input view $i$ and patch $p$ [S1].
    *   Compute dense Plücker-ray features $r_{i,p}$ and patchify [S1].
    *   Map rays: $\hat{r}_{i,p} = W_{\text{ray}} r_{i,p}$ [S1].
    *   Compute per-view code $e_i$ from absolute camera center $o_i$ and intrinsics $\kappa_i$:
        $$e_i = W_{\text{proj}}\Big ([\text{MLP}_{K}(\phi (\kappa _i));\ \text{PE}(o_i)]\Big )$$
        where $\phi$ uses resolution-normalized intrinsics and PE is Fourier positional encoding [S1].
    *   Combine: $u_{i,p}^{\text{cam}} = \hat{r}_{i,p} + e_i$ [S1].
    *   Concatenate: $u_{i,p} = [u_{i,p}^{\text{cam}} ; u_{i,p}^{\text{rgb}}]$ [S1].

**Algorithm:**

```python
def GlobalSplat(input_images, camera_poses, intrinsics):
    # 1. Scene Normalization [S1]
    origins = [pose.translation for pose in camera_poses]
    viewing_dirs = [pose.viewing_direction for pose in camera_poses]
    avg_origin = sum(origins) / len(origins)
    avg_dir = sum(viewing_dirs) / len(viewing_dirs)
    avg_dir = avg_dir / norm(avg_dir)
    T_avg = build_pose(avg_origin, avg_dir)
    normalized_poses = [inverse(T_avg) @ T for T in camera_poses]
    
    max_dist = max(norm(normalized_poses[a].translation - normalized_poses[b].translation) 
                   for a in range(len(normalized_poses)) for b in range(len(normalized_poses)))
    scaled_poses = [T for T in normalized_poses]
    for T in scaled_poses:
        T.translation = T.translation / max_dist

    # 2. Image Preprocessing & Context Construction [S1]
    processed_images = []
    for img in input_images:
        img = resize_height(img, 256)
        img = round_width_multiple(img, 8)
        img = centered_crop(img)
        img = resize(img, 256, 256)
        processed_images.append(img)

    input_context = []
    for i, img in enumerate(processed_images):
        patches = patchify(img, patch_size=8)
        rgb_tokens = extract_features(patches) # [num_patches, 512]
        
        rays = compute_plucker_rays(scaled_poses[i], intrinsics[i])
        ray_patches = patchify(rays, patch_size=8)
        ray_emb = linear_layer_rays(ray_patches) # [num_patches, 256]
        
        center_pe = fourier_encoding(scaled_poses[i].translation)
        intr_mlp = mlp_intrinsics(resolution_normalize(intrinsics[i]))
        cam_code = linear_layer_proj(concat(intr_mlp, center_pe)) # [256]
        
        cam_tokens = ray_emb + broadcast(cam_code, num_patches)
        context_tokens = concat(cam_tokens, rgb_tokens, dim=-1) # [num_patches, 768]
        input_context.append(context_tokens)

    # 3. Dual-Branch Encoder [S1]
    M = 2048
    d = 512
    B = 4
    L = 2
    latent_tokens = initialize_latent_tokens(M, d)
    
    for b in range(B):
        f_geo = linear_proj_geo(latent_tokens)
        f_app = linear_proj_app(latent_tokens)
        
        x = flatten_context(input_context)
        
        for j in range(L):
            f_geo = self_attention(cross_attention(x, f_geo))
            f_app = self_attention(cross_attention(x, f_app))
            
        fused = concat(f_geo, f_app, dim=-1)
        latent_tokens = mixer_mlp(fused)

    # 4. Dual-Branch Decoder & Candidate Prediction [S1]
    geo_tokens = linear_proj_geo_decoder(latent_tokens)
    app_tokens = linear_proj_app_decoder(latent_tokens)
    
    # Predict 16 candidates per latent token [S1]
    candidates = decoder_predict(geo_tokens, app_tokens)
    # candidates shape: [M, 16, attr_dim]

    # 5. Coarse-to-Fine Merging (Stage s=3 for final model) [S1]
    s = 3
    G = 2 ** s
    b_s = 16 // G
    tau = 0.1 # Temperature hyperparameter
    
    gaussians = []
    for p in range(M):
        for g in range(G):
            group = candidates[p, g*b_s : (g+1)*b_s]
            logits = group['l']
            weights = softmax(logits / tau)
            
            mean = weighted_sum(group['X'], weights)
            scale = weighted_sum(group['S'], weights)
            rotation = weighted_sum(group['R'], weights)
            opacity = weighted_sum(group['O'], weights)
            color = weighted_sum(group['C'], weights)
            
            final_mean = mean + 1.5
            final_scale = exp(scale - 2)
            final_opacity = sigmoid(opacity - 5)
            final_rotation = residual_6d_to_quat(rotation)
            
            gaussians.append(Gaussian(final_mean, final_scale, final_rotation, final_opacity, color))
            
    return gaussians
```

**Gaussian Parameterization Details:**
*   **Means:** Predicted values are treated as offsets from a fixed forward offset of 1.5 [S1].
*   **Scales:** Predicted in log space as an offset from -2. Final scale $s = \exp(\text{pred} - 2)$ [S1].
*   **Opacity:** Predicted in logit space as an offset from -5. Final opacity $\alpha = \sigma(\text{pred} - 5)$ [S1].
*   **Rotations:** Continuous 6D parameterization as residual offsets from a static rotation [S1].

**Training Objectives:**
The total loss is $\mathcal{L} = \lambda_{\text{ren}}\mathcal{L}_{\text{ren}} + \lambda_{\text{con}}\mathcal{L}_{\text{con}} + \lambda_{\text{reg}}\mathcal{L}_{\text{reg}}$ [S1].
*   **Rendering Loss:** $\mathcal{L}_{\text{ren}} = \|I_t - \hat{I}_t\|_2^2 + \lambda_{\text{perc}}\mathcal{L}_{\text{perc}}(I_t, \hat{I}_t)$ [S1].
*   **Self-Supervised Consistency Loss:** Partition views into $I_a, I_b$. $\mathcal{L}_{\text{con}} = \|O(I_a) - \text{sg}(O(I_b))\|_2^2 + \|D(I_a) - \text{sg}(D(I_b))\|_2^2$, where $O, D$ are rendered opacity and depth maps [S1].
*   **Regularization:** $\mathcal{L}_{\text{reg}} = \lambda_{\text{thr}}\mathcal{L}_{\text{thr}} + \lambda_{\text{fru}}\mathcal{L}_{\text{fru}}$ (soft thresholding and frustum constraint) [S1].

**Coarse-to-Fine Curriculum:**
Training starts with stage $s=0$ ($G=1$, all 16 candidates merged into 1 Gaussian) [S1]. Capacity increments to $G \in \{2, 4, 8\}$ [S1]. The final model uses $G=8$, resulting in $N = 2048 \times 8 = 16,384$ Gaussians [S1].

**Edge Cases and Pitfalls:**
*   **Precision:** Log-space predictions for scale and opacity require careful handling of numerical stability during exponentiation and sigmoid application [S1].
*   **Boundaries:** Scene normalization relies on the diameter of the camera constellation; scenes with widely dispersed cameras may require robust outlier handling in the scale computation $s$ [S1].
*   **Degenerate Input:** If input views have insufficient overlap, the cross-attention mechanism may fail to align features correctly, leading to poor latent token refinement [S1].

## Operating characteristics
*   **Time Complexity:** Inference is a single forward pass through the encoder-decoder network. On RealEstate10K with 24 input views, inference takes <78 ms [S1].
*   **Memory Complexity:** Peak GPU memory is 1.79 GB for 24 views on RealEstate10K [S1]. Disk size is ~4 MB for the 16K Gaussian representation [S1].
*   **Performance:** On RealEstate10K with 12 views, GlobalSplat16K achieves PSNR 28.57, SSIM 0.885, LPIPS 0.138 [S1]. GlobalSplat32K achieves PSNR 29.54, SSIM 0.903, LPIPS 0.121 [S1]. GlobalSplat2K achieves PSNR 26.83, SSIM 0.838, LPIPS 0.198 [S1].
*   **Strengths:** Compact representation (16K Gaussians) regardless of input view count; fast inference; low memory footprint; global consistency [S1].
*   **Limitations:** Fixed number of Gaussians may limit detail in very complex scenes compared to dense methods; relies on known camera poses (unlike [Splatt3R](16423-splatt3r.md) or [ZeroGS](16425-zerogs.md)) [S1].

## Background
GlobalSplat was introduced by R. Itkin et al. in 2025 [S1]. It addresses the limitation of existing feed-forward 3DGS pipelines that form primitives in dense view-aligned spaces, leading to representation bloat and fragile global consistency as more views are added [S1]. By aligning first and decoding later, it provides a more efficient operating point for large-context novel view synthesis [S1].
