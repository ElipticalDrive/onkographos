# Joint Fine-tuning
Also called: Progressive Joint Optimization
## Overview
Joint Fine-tuning is a training strategy within the GPS-Gaussian framework that progressively co-optimizes a 3D Gaussian Splatting model and an Unsigned Distance Function (UDF) model to refine scene geometry [S1]. It addresses the ambiguity in pulling Gaussians to a surface by using dense queries around the UDF zero-level set as geometric cues, preventing error accumulation [S1]. Unlike methods that regress Gaussian parameters directly from sparse views without optimization [S2, unofficial], this approach iteratively improves both representations [S1].
## How it works
### Inputs and Outputs
**Inputs:** Sparse source views, initial 3D Gaussian distribution (positions, scales, rotations, opacities, colors), initial UDF field parameterized by a neural network, and camera poses [S1][S3, unofficial].
**Outputs:** Refined 3D Gaussian parameters and refined UDF field [S1].

### Data Structures
*   **Gaussian Model:** Set of $N$ Gaussians. Each Gaussian $k$ has position $\mathbf{p}_k$, covariance $\mathbf{\Sigma}_k$, opacity $\alpha_k$, and color $\mathbf{c}_k$ [S1][G].
*   **UDF Model:** Neural network $f_{\theta}(\mathbf{x})$ predicting unsigned distance at point $\mathbf{x}$ [S1].
*   **Ray $V_k$:** Ray passing through Gaussian $k$'s center [S1].

### Numbered Steps
1.  **Initialization:** Initialize the Gaussian model and UDF model [S1].
2.  **Progressive Joint Optimization Loop:**
    a.  **Ray Casting:** For each Gaussian $k$, define ray $V_k$ passing through its center [S1].
    b.  **Depth Projection:** Calculate $d_t$, the depth of the projection point from Gaussian $k$ onto $V_k$ [S1].
    c.  **UDF Query:** Query the UDF at the Gaussian's position to obtain $d_n$, the depth of the surface point $\{q_n\}$ along the ray direction [S1].
    d.  **Loss Calculation:** Compute a geometric consistency loss using the depth difference, applying the stop-gradient operation $sg(\cdot)$ to the UDF prediction to stabilize training [S1].
    e.  **Gradient Update:** Update both the Gaussian parameters and the UDF network parameters $\theta$ jointly via backpropagation [S1].
    f.  **Iteration:** Repeat steps 2a-2e for multiple epochs, progressively refining geometry over time [S1].
    g.  **Joint Refinement Training:** Train the backbone $f_\theta$ and refinement module $h_\phi$ jointly in an end-to-end manner by supervising the output of the final refinement iteration [S3, unofficial].
    h.  **Unrolled Gradients:** Compute the total loss after all $K$ refinement iterations, allowing gradients to propagate through the rasterizer and the entire unrolled sequence of updates [S3, unofficial].
    i.  **Per-Attribute Heads:** Use three parallel MLPs for position, opacity, and color updates, with all output layers zero-initialized so refinement starts at $\Delta = 0$ [S3, unofficial].

### Formulas
The geometric loss leverages the depth difference between the Gaussian projection and the UDF surface [S1]. Let $d_t$ be the depth of the Gaussian's projection onto ray $V_k$ and $d_n$ be the depth of the surface point $\{q_n\}$ predicted by the UDF [S1]. The update involves a stop-gradient operation $sg(\cdot)$ on the UDF term [S1]:
$$ \mathcal{L}_{\text{geo}} = \| d_t - sg(d_n) \|^2 $$
The total training loss combines pixel-wise mean squared error with a perceptual loss over all rendered views [S3, unofficial]:
$$ \mathcal{L} = \sum_{i \in C \cup T} \| \hat{I}^{(K)}_i - I_i \|_2^2 + \lambda_{\text{lp}} \text{LPIPS}(\hat{I}^{(K)}_i, I_i) $$
where $\hat{I}^{(K)}_i$ is the rendering of the final Gaussian set $G^{(K)}$ at camera $p_i$, $\|\cdot\|_2^2$ denotes mean squared error over pixels, and $\lambda_{\text{lp}}$ is the perceptual loss weight [S3, unofficial].

### Parameters
*   $\lambda_{\text{lp}} = 0.1$ with a VGG backbone [S3, unofficial].
*   $K = 3$ refinement iterations [S3, unofficial].
*   Training runs for 50,000 steps with shared weights across iterations [S3, unofficial].
*   **Progressive Schedule:** Not given in the sources.
*   **Learning Rate:** Not given in the sources.

### Edge Cases and Pitfalls
*   **Ambiguous Pulling Directions:** Directly pulling Gaussians to the UDF zero-level set can cause error accumulation due to ambiguous directions [S1]. This method avoids this by using dense queries around the zero-level set [S1].
*   **UDF Accuracy:** The UDF is not perfectly accurate initially, but provides reliable optimization directions [S1]. Poor initial UDF quality may slow convergence [G].

### Pseudocode
```python
def joint_fine_tuning(gaussians, udf_net, source_views, cameras, epochs=50000, K=3, lambda_lp=0.1, learning_rate=0.01):
    # Initialize parameter lists for optimization
    gauss_params = [g.position for g in gaussians] + [g.covariance for g in gaussians] + [g.opacity for g in gaussians] + [g.color for g in gaussians]
    udf_params = list(udf_net.parameters())
    
    for step in range(epochs):
        for gaussian in gaussians:
            # 1. Define ray Vk through Gaussian center
            ray_origin = gaussian.position
            ray_direction = normalize(gaussian.position - cameras.center)
            
            # 2. Compute depth dt of Gaussian projection onto Vk
            dt = gaussian.depth_along_ray(ray_origin, ray_direction)
            
            # 3. Query UDF for surface depth dn
            dn = udf_net.query_surface_depth(ray_origin, ray_direction)
            
            # 4. Compute geometric loss with stop-gradient on UDF term
            loss = (dt - stop_gradient(dn)) ** 2
            
            # 5. Backpropagate to update both models
            loss.backward()
            
        # 6. Update parameters using gradient descent
        for p in gauss_params:
            p.data -= learning_rate * p.grad
        for p in udf_params:
            p.data -= learning_rate * p.grad
            
        # Clear gradients
        for p in gauss_params + udf_params:
            p.grad = None
        
    return gaussians, udf_net

def stop_gradient(tensor):
    return tensor.detach()

def normalize(v):
    return v / magnitude(v)
```
## Subtopics

### [FaCT-GS](10199-fact-gs.md)
A method for compressing 3D Gaussian Splatting models. It focuses on reducing memory footprint through factorization, unlike Joint Fine-tuning which focuses on geometric refinement via UDFs.

### [SegAnySplatting Feature Optimization](12209-seganysplatting-feature-optimization.md)
Optimizes features for segmentation-aware Gaussian Splatting. It targets semantic feature learning rather than geometric refinement through joint UDF optimization.

## Operating characteristics
*   **Time Complexity:** Higher than non-optimizing methods like the initial GPS-Gaussian regression because it involves iterative joint optimization of Gaussians and a UDF network [S1][S2, unofficial].
*   **Memory Complexity:** Requires storing both the Gaussian parameters and the UDF network parameters [S1].
*   **Strengths:** Prevents error accumulation from ambiguous pulling directions by using dense queries around the zero-level set [S1]. Continuously improves geometry over time [S1].
*   **Limitations:** Computationally expensive due to joint optimization [S1]. Relies on the UDF providing reliable directions despite not being perfectly accurate [S1].
*   **When to Use:** When high-fidelity geometry is required and sparse views are available, and computational resources allow for iterative optimization [S1].
*   **When Not to Use:** When real-time inference without fine-tuning is required, as this method is a training-time optimization [S2, unofficial].

## Background
Joint Fine-tuning, also known as Progressive Joint Optimization, was introduced in the VRP-UDF paper [S1]. It builds on the GPS-Gaussian framework [S2, unofficial], which initially introduced Gaussian parameter maps on sparse source views to regress parameters jointly with a depth estimation module without fine-tuning [S2, unofficial]. The Joint Fine-tuning method extends this by adding a progressive joint optimization step to refine the geometry further [S1]. It addresses limitations in existing methods that directly pull Gaussians to the UDF zero-level set [S1].
