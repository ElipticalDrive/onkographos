# RLSplat

Also called: Resource-Linear Budget Control for Feed-forward 3D Gaussian Splatting

## Overview
RLSplat is a resource-linear, budget-controllable feed-forward 3D Gaussian Splatting (FF3DGS) framework that generates exactly $B$ 3D Gaussians from uncalibrated input images, ensuring that inference latency and peak memory scale linearly with the requested Gaussian budget $B$ [S1, unofficial]. Unlike prior budget-controllable methods (e.g., EcoSplat, F4 Splat) that predict a dense set of candidates and subsequently prune or select a subset—resulting in nearly constant inference costs regardless of the target budget—RLSplat allocates the budget directly to local scene regions via a learned policy and refines them using a resource-linear decoder [S1, unofficial]. This approach allows the representation size, latency, and memory usage to decrease linearly as $B$ is reduced, while maintaining higher reconstruction quality than pruning-based baselines at low budgets [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of $V$ uncalibrated context images $\{I_i\}_{i=1}^V$ and an integer target Gaussian budget $B$.
*   **Outputs:** A set of $B$ 3D Gaussians $\mathcal{G} = \{g_b\}_{b=1}^B$, where each $g_b$ consists of a 3D center, opacity, scale, rotation, and color coefficients, along with the predicted camera parameters $\{P_i\}_{i=1}^V$ for the context images [S1, unofficial].

**Data Structures:**
1.  **Anchor Tokens:** The geometry backbone encodes the input images into $N$ anchor tokens $\{a_n\}_{n=1}^N$. Each anchor represents a local 3D region of the scene [S1, unofficial].
2.  **Allocation Vector:** A discrete allocation vector $\mathbf{k} \in \mathbb{Z}_{\ge 0}^N$, where $k_n$ is the number of Gaussians assigned to anchor $n$. The constraint $\sum_{n=1}^N k_n = B$ must hold strictly [S1, unofficial].
3.  **Gaussian Tokens:** Each anchor $n$ spawns $k_n$ Gaussian tokens. The total number of Gaussian tokens is exactly $B$ [S1, unofficial].
4.  **Hierarchical Neighbor Search Structures:** Used to efficiently find the $K_{gs}$ nearest Gaussian neighbors for each token. This involves searching among $K_{anc}$ anchor neighbors [S1, unofficial].

**Parameters:**
*   $B$: The target Gaussian budget. Typical evaluation values include 2K (2,048) and 64K. On the ACID dataset with 8 views, $B=8,192$ (1,024 per view) is used. On RE10K, $B=8,000$ is typical [S1, unofficial].
*   $K_{gs}$: The number of nearest Gaussian neighbors each token attends to during refinement. Default ablation value is 16. This can be changed at inference without retraining [S1, unofficial].
*   $K_{anc}$: The number of anchor neighbors used in the hierarchical neighbor search. Fixed value in ablations is 16 [S1, unofficial].
*   $C$: The number of rollouts (candidate allocations) drawn per training step for the Group Sequence Policy Optimization (GSPO) [S1, unofficial].

**Algorithm Steps:**

1.  **Geometry Encoding:** Given $V$ uncalibrated images $\{I_i\}$, a geometry backbone (e.g., based on Burzio et al., 2026) encodes the images into $N$ anchor tokens $\{a_n\}_{n=1}^N$ and predicts camera parameters $\{P_i\}_{i=1}^V$ [S1, unofficial].

2.  **Gaussian Allocation Policy:** A policy network $\pi_\psi$ assesses the local significance of each anchor (based on image features like texture complexity) to predict a probability distribution over allocations. A discrete allocation $\mathbf{k}$ is sampled such that $\sum k_n = B$. This policy is trained using Group Sequence Policy Optimization (GSPO) [S1, unofficial].
    *   At each training step, $C$ candidate allocations $\mathbf{k}^{(c)} \sim \pi_{\text{old}} = \text{Mult}(B, \text{sg}(\mathbf{p}))$ are drawn, where $\text{sg}(\cdot)$ stops gradients [S1, unofficial].
    *   For each rollout, the representation $\mathcal{G}^{(c)}$ is generated, rendered to novel views, and the reconstruction loss $\mathcal{L}_{\text{recon}}$ against ground-truth images is computed as the reward signal [S1, unofficial].

3.  **Token Spawning:** Each anchor $n$ spawns $k_n$ Gaussian tokens. The total number of Gaussian tokens is exactly $B$ [S1, unofficial].

4.  **Resource-Linear Decoding and Refinement:**
    *   The decoder instantiates initial Gaussians from the tokens.
    *   It refines these Gaussians via local cross-attention. For each Gaussian token, the $K_{gs}$ nearest Gaussian tokens are found using a hierarchical neighbor search over $K_{anc}$ anchor neighbors [S1, unofficial].
    *   The computational cost of this step is $O(B \cdot K_{gs})$, scaling linearly with $B$, compared to global self-attention which costs $O(B^2)$ [S1, unofficial].
    *   Training includes specific losses: a projection loss (to tie anchors to image regions), an offset loss (for initial positions), and a Voronoi loss (to ensure neighbors are retrieved correctly even if Gaussians leave their anchor's cell) [S1, unofficial].

**Pseudocode:**

```python
def rl_splat_forward(context_images, budget_B):
    """
    Forward pass of RLSplat.
    context_images: List of V uncalibrated RGB images.
    budget_B: Integer, total number of Gaussians to generate.
    Returns:
        gaussians: List of B 3D Gaussian objects (center, opacity, scale, rotation, color).
        cameras: List of V camera parameters.
    """
    # Step 1: Geometry Backbone
    # Encodes images into anchor tokens and predicts camera poses
    anchor_tokens, cameras = geometry_backbone(context_images)
    N = len(anchor_tokens)
    
    # Step 2: Gaussian Allocation Policy
    # Predict allocation proportions p, then sample discrete allocation k
    # Note: In inference, we sample from the trained policy.
    # In training, we use GSPO with C rollouts.
    allocation_probs = allocation_policy(anchor_tokens)
    
    # Sample discrete allocation k such that sum(k) == budget_B
    # Implementation detail: Multinomial sampling with reparameterization or REINFORCE
    # For the purpose of this structural description, we assume a valid sampler exists.
    k = sample_allocation(allocation_probs, budget_B)
    
    # Step 3: Spawn Gaussian Tokens
    # Each anchor n spawns k[n] Gaussian tokens
    gaussian_tokens = []
    for n in range(N):
        count = k[n]
        # Spawn 'count' tokens for anchor n
        # Initial state prediction might be done here or in decoder
        tokens_for_anchor = spawn_tokens(anchor_tokens[n], count)
        gaussian_tokens.extend(tokens_for_tokens)
        
    # Step 4: Resource-Linear Decoding
    # Refine Gaussians via local cross-attention
    # Find Kgs nearest neighbors for each Gaussian token
    Kgs = 16 # Default parameter
    Kanc = 16 # Fixed parameter for anchor search
    
    # Hierarchical neighbor search to find neighbors efficiently
    # This avoids O(B^2) global attention
    neighbors = hierarchical_neighbor_search(gaussian_tokens, Kgs, Kanc)
    
    # Local cross-attention refinement
    refined_gaussians = local_cross_attention_refinement(
        gaussian_tokens, 
        neighbors, 
        Kgs
    )
    
    return refined_gaussians, cameras

def rl_splat_train_step(context_images, ground_truth_images, budget_B):
    """
    Training step using GSPO.
    """
    C = 8 # Number of rollouts, typical value
    
    # Get anchor tokens and cameras
    anchor_tokens, cameras = geometry_backbone(context_images)
    
    # Get allocation probabilities from current policy
    allocation_probs = allocation_policy(anchor_tokens)
    
    total_loss = 0
    
    for c in range(C):
        # Sample allocation with stopped gradients for policy gradient
        k_c = sample_allocation(allocation_probs, budget_B, stop_grad=True)
        
        # Generate Gaussians for this rollout
        gaussian_tokens_c = spawn_tokens_from_allocation(anchor_tokens, k_c)
        
        # Decode/Refine (same as forward, but no gradient needed for reward)
        # Note: The paper states rendering is done without gradient tracking for the reward
        gaussians_c = decode_gaussians(gaussian_tokens_c)
        
        # Render image from gaussians_c using predicted cameras
        rendered_image = render(gaussians_c, cameras)
        
        # Compute reconstruction loss (Reward)
        # L_recon against ground_truth_images
        loss_c = reconstruction_loss(rendered_image, ground_truth_images)
        
        # Accumulate loss for policy update
        # In GSPO, this loss serves as the reward signal
        total_loss += loss_c
        
    # Update policy using GSPO with the accumulated reward/loss
    # This involves updating allocation_policy parameters
    update_policy(allocation_policy, total_loss / C)
    
    # Additionally, update the decoder and geometry backbone
    # using gradients from a differentiable pass or combined objective
    # The paper mentions projection, offset, and Voronoi losses for training stability
    return total_loss
```

**Edge Cases and Pitfalls:**
*   **Training Failure:** Removing the projection loss causes training to fail entirely, as nothing ties an anchor's Gaussians to the image region it was encoded from [S1, unofficial].
*   **Neighbor Retrieval:** Removing the Voronoi loss causes a significant PSNR drop (2.51 dB) because Gaussians may leave their anchor's cell, and the hierarchical search would no longer retrieve their true neighbors [S1, unofficial].
*   **Local Consistency:** Removing the local refinement module lowers PSNR by 0.96 dB, as each Gaussian is predicted from its own token alone and cannot be made consistent with its neighbors [S1, unofficial].
*   **Budget Constraint:** The allocation policy must strictly enforce $\sum k_n = B$. The use of GSPO with multinomial sampling ensures this constraint is met during training [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The decoding cost is $O(B \cdot K_{gs})$, scaling linearly with the Gaussian budget $B$. This contrasts with global self-attention, which costs $O(B^2)$ [S1, unofficial].
*   **Memory Complexity:** Peak memory scales linearly with $B$. At a budget of 2K Gaussians, RLSplat uses 9.6× less peak memory than F4 Splat [S1, unofficial].
*   **Inference Latency:** Latency scales linearly with $B$. At 2K Gaussians, RLSplat runs 4.1× faster than F4 Splat [S1, unofficial].
*   **Performance:**
    *   On ACID (B=8,192): PSNR 22.84 dB, SSIM 0.643, LPIPS 0.353 [S1, unofficial].
    *   On RE10K (B=8,000): Full-view PSNR 26.51 dB, compared to 23.42 dB for F4 Splat and 21.82 dB for EcoSplat [S1, unofficial].
    *   At 2K Gaussians, RLSplat achieves higher PSNR than F4 Splat [S1, unofficial].
*   **Strengths:**
    *   True resource-linearity: Inference cost and memory decrease as $B$ decreases.
    *   Better allocation: Concentrates Gaussians on high-frequency structures (e.g., thin stair balusters) while using fewer on smooth areas, leading to better local and full-view PSNR [S1, unofficial].
    *   No retraining required to change $K_{gs}$ at inference [S1, unofficial].
*   **Limitations:**
    *   Requires training with GSPO, which involves reinforcement learning techniques.
    *   Performance depends on the quality of the geometry backbone and the learned allocation policy.
*   **When to use:** Applications requiring limited resource budgets, such as AR/VR, robotics, and digital content creation, where inference latency and memory must be tightly controlled [S1, unofficial].
*   **When not to use:** When maximum possible quality is required regardless of resource cost, or when the scene geometry is extremely complex and requires a very large $B$ that negates the efficiency benefits.

## Background
RLSplat was proposed by Bae, Park, and Kim from KAIST. The work addresses the limitations of previous budget-controllable FF3DGS methods like EcoSplat and F4 Splat, which predict dense sets of Gaussians and then prune them, resulting in constant inference costs [S1, unofficial]. RLSplat introduces a resource-linear approach by formulating Gaussian generation as an allocation problem and using a learned policy to distribute the budget across local scene regions. The method uses Group Sequence Policy Optimization (GSPO) for training the allocation policy and a hierarchical neighbor search for efficient local refinement.
