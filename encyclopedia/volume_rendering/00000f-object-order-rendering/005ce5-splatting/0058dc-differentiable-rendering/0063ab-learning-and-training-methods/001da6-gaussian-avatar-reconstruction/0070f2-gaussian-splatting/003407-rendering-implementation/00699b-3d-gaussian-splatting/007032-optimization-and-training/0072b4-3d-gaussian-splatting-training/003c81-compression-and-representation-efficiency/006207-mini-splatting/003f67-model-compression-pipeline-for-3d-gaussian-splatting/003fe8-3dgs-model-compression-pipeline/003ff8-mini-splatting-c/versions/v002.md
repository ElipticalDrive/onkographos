# Mini-Splatting-C

Also called: Ours+PP, Post-processed Compact 3D Gaussian

## Overview
Mini-Splatting-C is a storage-compression variant of the Mini-Splatting method designed for scenarios requiring minimal model footprint [S1]. It achieves significant size reduction by applying post-processing techniques to the attributes of a pre-trained Mini-Splatting model, including transform coding, quantization, and entropy encoding [S1, S2]. Unlike Mini-Splatting-D, which prioritizes rendering quality, Mini-Splatting-C optimizes for storage efficiency, demonstrating superior performance compared to other compression-oriented works applied to 3D Gaussian Splatting (3DGS) [S1]. It builds on the [3DGS Model Compression Pipeline](10101-3dgs-model-compression-pipeline.md) framework and contrasts with siblings like the [Hybrid Compression Framework](15040-hybrid-compression-framework.md) and [Prune2TargetSize](15817-prune2targetsize.md) by focusing exclusively on post-training attribute compression.

## How it works
**Inputs and Outputs:**
*   **Input:** A pre-trained Mini-Splatting model containing Gaussian centers, scales, spherical harmonic (SH) coefficients, opacity, and hash grid parameters [S1, S2].
*   **Output:** A compressed binary stream representing the Gaussian scene representation [S1, S2].

**Data Structures and Layout:**
The method distinguishes between attributes stored in high precision and those processed for compression [S1]:
1.  **Gaussian Centers:** Stored as `float32` (32-bit floating point) without compression [S1].
2.  **Other Attributes:** Scales and SH coefficients undergo transform coding [S1].
3.  **Quantized Attributes:** Opacity and hash grid parameters are quantized to 8-bit integers using min-max quantization [S2].
4.  **Encoded Indices:** R-VQ (Residual Vector Quantization) indices are generated for the quantized attributes [S2].

**Steps:**
1.  **Training:** Train a standard Mini-Splatting model [S1].
2.  **Center Storage:** Store Gaussian centers as `float32` values [S1].
3.  **Transform Coding:** Apply transform coding to scales and SH coefficients [S1].
4.  **Quantization:** Apply 8-bit min-max quantization to opacity and hash grid parameters [S2].
    *   Formula: $q = \text{clip}(\lfloor \frac{v - v_{\min}}{v_{\max} - v_{\min}} \times 255 + 0.5 \rfloor, 0, 255)$, where $v$ is the original value, and $v_{\min}, v_{\max}$ are the attribute's minimum and maximum values [G].
5.  **Pruning:** Prune hash grid parameters with values below 0.1 [S2].
6.  **Entropy Encoding:** Apply Huffman encoding to the quantized opacity, hash parameters, and R-VQ indices [S2].
7.  **Final Compression:** Apply standard ZIP compression to the resulting data stream [S1].

**Pseudocode:**
```python
def compress_mini_splatting_c(centers, scales, sh_coeffs, opacity, hash_params):
    # Step 1: Store Gaussian centers as float32
    centers_bytes = centers.tobytes()

    # Step 2: Apply transform coding to scales and SH coefficients
    # Sources do not provide the algorithm for transform coding [S1]
    scales_transformed = scales
    sh_transformed = sh_coeffs

    # Step 3: Apply 8-bit min-max quantization to opacity and hash grid parameters
    def quantize(v):
        v_min, v_max = min(v), max(v)
        if v_max == v_min:
            return [0] * len(v)
        return [max(0, min(255, int((x - v_min) / (v_max - v_min) * 255 + 0.5))) for x in v]

    opacity_q = quantize(opacity)
    hash_q = quantize(hash_params)

    # Step 4: Prune hash grid parameters with values below 0.1
    threshold = 0.1
    valid_mask = [v >= threshold for v in hash_params]
    hash_q_pruned = [hash_q[i] for i in range(len(hash_params)) if valid_mask[i]]

    # Step 5: Generate R-VQ indices
    # Sources do not provide the algorithm for R-VQ [S2]
    rvq_indices = [0] * len(hash_q_pruned)

    # Step 6: Apply Huffman encoding to quantized opacity, hash parameters, and R-VQ indices
    # Sources do not provide the algorithm for Huffman encoding [S2]
    opacity_huff = opacity_q
    hash_huff = hash_q_pruned
    rvq_huff = rvq_indices

    # Step 7: Apply standard ZIP compression to the result
    # Sources do not provide the ZIP implementation details [S1]
    combined = centers_bytes + scales_transformed + sh_transformed + \
               opacity_huff + hash_huff + rvq_huff
    return combined
```

**Parameters:**
*   **Center Precision:** `float32` [S1].
*   **Quantization Bits:** 8-bit for opacity and hash parameters [S2].
*   **Pruning Threshold:** 0.1 for hash grid parameters [S2].

**Edge Cases and Pitfalls:**
*   **Precision Loss:** Quantization to 8-bit may introduce visual artifacts, particularly in opacity and fine details captured by hash parameters [S2].
*   **Pruning Artifacts:** Pruning hash grid parameters below 0.1 may remove valid but small contributions, potentially affecting rendering quality in sparse regions [S2].
*   **Transform Coding Dependency:** The effectiveness of the compression relies on the specific transform coding algorithm referenced as [6] in [S1], which is not detailed in the provided notes [S1].

## Operating characteristics
**Time and Memory Complexity:**
*   **Storage:** On the NeRF-Synthetic dataset, Mini-Splatting-C achieves a storage size of 2.67 MB, which is 0.04x the size of standard 3DGS [S2]. This represents a reduction from the 5.55 MB storage of the base Mini-Splatting method [S2].
*   **Rendering Speed:** On the NeRF-Synthetic dataset, Mini-Splatting-C achieves 545 FPS, which is 1.52x faster than the base Mini-Splatting method's 359 FPS [S2].
*   **Training Time:** The training time for the base Mini-Splatting method is 8 minutes and 4 seconds on the NeRF-Synthetic dataset [S2].

**Strengths and Limitations:**
*   **Strengths:** Significant storage reduction compared to 3DGS and base Mini-Splatting [S1, S2]. Improved rendering speed due to reduced model size [S2]. Superior performance compared to other compression-oriented works applied to 3DGS [S1].
*   **Limitations:** Slight PSNR drop from 33.33 to 32.88 on the NeRF-Synthetic dataset [S2]. The compression pipeline adds complexity to the post-processing step [S1].

**When to Use:**
*   Use Mini-Splatting-C when storage size is the primary constraint and slight quality degradation is acceptable [S1].
*   Suitable for hardware deployment scenarios where bandwidth and memory are limited [S1].

**When Not to Use:**
*   Use Mini-Splatting-D if rendering quality is prioritized over storage size [S1].
*   Use standard 3DGS if high fidelity is required and storage or bandwidth are not constraints.

## Background
Mini-Splatting-C is part of the Mini-Splatting family, which aims to represent scenes with a constrained number of Gaussians [S1]. It was introduced in the paper "Mini-Splatting: Representing Scenes with a Constrained Number of Gaussians" [S1]. The method builds on the Mini-Splatting representation and adds post-processing compression techniques to further reduce storage size [S1]. It is designed to address the large storage requirements of 3D Gaussian Splatting [S1].
