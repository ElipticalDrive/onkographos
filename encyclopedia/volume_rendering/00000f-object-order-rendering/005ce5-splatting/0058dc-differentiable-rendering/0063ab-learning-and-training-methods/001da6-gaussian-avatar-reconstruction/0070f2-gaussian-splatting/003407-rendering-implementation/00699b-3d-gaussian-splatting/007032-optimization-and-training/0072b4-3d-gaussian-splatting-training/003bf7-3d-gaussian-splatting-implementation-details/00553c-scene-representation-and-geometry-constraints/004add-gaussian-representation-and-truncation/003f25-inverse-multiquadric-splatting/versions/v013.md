# Inverse Multiquadric Splatting

Also called: 3DIQS, Inverse Multiquadric

## Overview
Inverse Multiquadric Splatting is a rendering technique that replaces the standard Gaussian radial basis function with an inverse multiquadric function to define the spatial response of 3D Gaussian primitives [S1]. It solves the problem of artifact-prone rendering in regions of high density or sharp edges by providing a different decay profile that better matches certain natural phenomena or optimization landscapes [S1]. It sets itself apart from the standard Gaussian splatting method by using a rational function rather than an exponential one, requiring a specific correction factor for the covariance matrix to maintain visual consistency [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $N$ 3D Gaussian primitives defined by position $\mu_i$, rotation $q_i$, scale $s_i$, opacity $\omega_i$, and spherical harmonic coefficients $c_i$ [S1].
*   **Output:** A 2D image where each pixel color is computed via alpha compositing [S1].

**Data Structures:**
The Gaussian representation follows the standard structure defined in [Gaussian Representation and Truncation](12855-gaussian-representation-and-truncation.md):
*   **Position ($\mu_i$):** $\mathbb{R}^3$
*   **Rotation ($q_i$):** Unit quaternion $\mathbb{R}^4$
*   **Scale ($s_i$):** $\mathbb{R}^3$
*   **Opacity ($\omega_i$):** Scalar $\mathbb{R} \in [0, 1]$
*   **Color ($c_i$):** SH coefficients [S1]

The 3D covariance $\Sigma_i$ is constructed from scale and rotation as $\Sigma_i = R_i S_i S_i^T R_i^T$ [S1]. During projection, the 2D covariance $\Sigma'_{2 \times 2}$ is derived from the 3D covariance using the camera Jacobian [S1]. The inverse of the 2D covariance, often referred to as the conic matrix, is denoted as $(\Sigma'_{2 \times 2})^{-1}$ with components $con\_o = [a, b, c, w]$ corresponding to the symmetric matrix $\begin{bmatrix} a & b \\ b & c \end{bmatrix}$ and determinant term $w$ [S1].

**Parameters:**
*   **Correction Factor:** A scalar multiplier applied to the covariance matrices. Value: $1.38$ [S1].
*   **Ellipse Limit:** The maximum value for the squared Mahalanobis distance (ellipse) before culling. Value: $9.0$ [S1].
*   **Alpha Cap:** The maximum opacity contribution per primitive. Value: $0.99$ [S1].

**Algorithm Steps:**

1.  **Covariance Correction:**
    Multiply the 3D covariance matrix $\Sigma$ and the projected 2D covariance matrix $\Sigma'_{2 \times 2}$ by the correction factor $\gamma = 1.38$ [S1].
    $$ \Sigma \leftarrow \gamma \Sigma $$
    $$ \Sigma'_{2 \times 2} \leftarrow \gamma \Sigma'_{2 \times 2} $$
    Consequently, the conic matrix (inverse covariance) is scaled by $1/\gamma$ implicitly if computed from the corrected covariance, or explicitly adjusted in the gradient path [S1]. The source code applies `cov2D *= correctionFactor` before computing the conic or uses the factor in gradient scaling [S1]. Note: The source code snippet `cov2D *= correctionFactor` suggests the covariance itself is scaled, which means the inverse (conic) is divided by it. However, the gradient updates explicitly multiply by `correctionFactor`, implying the derivative chain rule accounts for this scaling [S1].

2.  **Forward Pass (Rasterization):**
    For each pixel fragment covered by a Gaussian:
    a. Calculate the displacement vector $z = x - \mu'$, where $x$ is the pixel coordinate and $\mu'$ is the projected 2D mean [S1].
    b. Compute the ellipse value (squared Mahalanobis distance):
       $$ ellipse = z^T (\Sigma'_{2 \times 2})^{-1} z = a \cdot z_x^2 + c \cdot z_y^2 + 2b \cdot z_x z_y $$
       where $a, b, c$ are the components of the conic matrix $(\Sigma'_{2 \times 2})^{-1}$ [S1].
    c. **Culling:** If $ellipse \le 0$ or $ellipse \ge 9$, skip the primitive [S1].
    d. Compute the inverse multiquadric weight $w$:
       $$ w = \frac{1}{ellipse + 1} $$
       [S1]
    e. Compute the final alpha:
       $$ \alpha = \min(0.99, \omega_i \cdot w) $$
       [S1]
    f. Compute color $C_i$ using SH coefficients and view direction [S1].
    g. Composite into the image buffer using standard alpha blending [S1].

3.  **Backward Pass (Gradient Computation):**
    Compute gradients with respect to the loss $L$. Let $dL\_d\alpha$ be the gradient of the loss w.r.t. alpha [S1].
    a. Compute gradient w.r.t. the weight term $G = w$:
       $$ dL\_dG = \omega_i \cdot dL\_d\alpha $$
       [S1]
    b. Compute gradient w.r.t. the ellipse value:
       $$ \frac{\partial G}{\partial ellipse} = \frac{-1}{(ellipse + 1)^2} $$
       $$ dL\_dellipse = dL\_dG \cdot \frac{-1}{(ellipse + 1)^2} $$
       [S1]
    c. Compute gradients w.r.t. the 2D mean components ($z_x, z_y$):
       $$ \frac{\partial ellipse}{\partial z_x} = 2(a z_x + b z_y) $$
       $$ \frac{\partial ellipse}{\partial z_y} = 2(b z_x + c z_y) $$
       $$ dL\_d\mu'_x = dL\_dellipse \cdot \frac{\partial ellipse}{\partial z_x} $$
       $$ dL\_d\mu'_y = dL\_dellipse \cdot \frac{\partial ellipse}{\partial z_y} $$
       [S1]
    d. Compute gradients w.r.t. the conic matrix components ($a, b, c$):
       $$ \frac{\partial ellipse}{\partial a} = z_x^2 $$
       $$ \frac{\partial ellipse}{\partial b} = 2 z_x z_y $$
       $$ \frac{\partial ellipse}{\partial c} = z_y^2 $$
       $$ dL\_da = dL\_dellipse \cdot z_x^2 $$
       $$ dL\_db = dL\_dellipse \cdot 2 z_x z_y $$
       $$ dL\_dc = dL\_dellipse \cdot z_y^2 $$
       [S1]
    e. **Correction Factor Gradient Scaling:**
       The gradients w.r.t. the covariance entries must be scaled by the correction factor $\gamma = 1.38$ because the covariance was scaled in the forward pass [S1]. The source code shows `dL_da = correctionFactor * ...` [S1].

**Pseudocode:**

```python
import math

def inverse_multiquadric_forward(ellipse, opacity):
    """
    Computes the alpha contribution for a single Gaussian splat.
    
    Args:
        ellipse (float): The squared Mahalanobis distance (z^T * conic * z).
        opacity (float): The primitive's opacity omega_i.
        
    Returns:
        float: The alpha value to be used in compositing.
    """
    # Culling conditions
    if ellipse <= 0.0 or ellipse >= 9.0:
        return 0.0
    
    # Inverse multiquadric weight
    # w = 1 / (ellipse + 1)
    weight = 1.0 / (ellipse + 1.0)
    
    # Final alpha with cap
    alpha = min(0.99, opacity * weight)
    
    return alpha

def inverse_multiquadric_backward(ellipse, opacity, dL_dalpha, conic_a, conic_b, conic_c, dz_x, dz_y):
    """
    Computes gradients for the inverse multiquadric splatting.
    
    Args:
        ellipse (float): The squared Mahalanobis distance.
        opacity (float): The primitive's opacity omega_i.
        dL_dalpha (float): Gradient of loss w.r.t. alpha.
        conic_a (float): Conic matrix element (0,0).
        conic_b (float): Conic matrix element (0,1) and (1,0).
        conic_c (float): Conic matrix element (1,1).
        dz_x (float): x-component of displacement (pixel_x - mean_x).
        dz_y (float): y-component of displacement (pixel_y - mean_y).
        
    Returns:
        tuple: (dL_dmean_x, dL_dmean_y, dL_dconic_a, dL_dconic_b, dL_dconic_c)
    """
    correction_factor = 1.38
    
    # Gradient w.r.t. the weight term G (which is w)
    # dL_dG = opacity * dL_dalpha
    dL_dG = opacity * dL_dalpha
    
    # Gradient w.r.t. ellipse
    # dL_dellipse = dL_dG * (-1 / (ellipse + 1)^2)
    denom_sq = (ellipse + 1.0) ** 2
    dL_dellipse = dL_dG * (-1.0 / denom_sq)
    
    # Gradients w.r.t. mean (dz_x, dz_y)
    # d(ellipse)/d(z_x) = 2 * (conic_a * dz_x + conic_b * dz_y)
    # d(ellipse)/d(z_y) = 2 * (conic_b * dz_x + conic_c * dz_y)
    
    d_ellipse_dz_x = 2.0 * (conic_a * dz_x + conic_b * dz_y)
    d_ellipse_dz_y = 2.0 * (conic_b * dz_x + conic_c * dz_y)
    
    dL_dmean_x = dL_dellipse * d_ellipse_dz_x
    dL_dmean_y = dL_dellipse * d_ellipse_dz_y
    
    # Gradients w.r.t. conic matrix
    # d(ellipse)/d(a) = dz_x^2
    # d(ellipse)/d(b) = 2 * dz_x * dz_y
    # d(ellipse)/d(c) = dz_y^2
    
    d_ellipse_da = dz_x * dz_x
    d_ellipse_db = 2.0 * dz_x * dz_y
    d_ellipse_dc = dz_y * dz_y
    
    # Apply correction factor scaling for covariance gradients
    # The source code applies correctionFactor to the gradient updates for conic entries
    # Note: In the source, dL_da is updated with correctionFactor * ...
    dL_dconic_a = correction_factor * dL_dellipse * d_ellipse_da
    dL_dconic_b = correction_factor * dL_dellipse * d_ellipse_db
    dL_dconic_c = correction_factor * dL_dellipse * d_ellipse_dc
    
    return (dL_dmean_x, dL_dmean_y, dL_dconic_a, dL_dconic_b, dL_dconic_c)
```

## Operating characteristics
*   **Time Complexity:** Same as standard Gaussian splatting, $O(N \cdot P)$ where $N$ is the number of Gaussians and $P$ is the number of pixels covered, due to the similar rasterization loop structure [S1].
*   **Memory Complexity:** Identical to standard Gaussian splatting, storing the same set of primitives [S1].
*   **Performance:** The inverse multiquadric function involves a division and addition, which is computationally comparable to the exponential function used in Gaussian splatting, though the exact performance difference depends on the hardware's transcendental function unit [S1].
*   **Strengths:** Provides a different decay profile that may reduce artifacts in specific optimization scenarios or scene types compared to the Gaussian kernel [S1].
*   **Limitations:** Requires a correction factor to align with the visual scale of Gaussian splatting, adding a hyperparameter [S1]. The culling range is fixed at $ellipse \ge 9$, which may not be optimal for all scales [S1].

## Background
Inverse Multiquadric Splatting was introduced in the context of generalizing splatting with decaying anisotropic radial basis functions, specifically in the DARB-Splatting paper [S1]. It is part of a family of methods that explore alternative radial basis functions for 3D Gaussian Splatting to improve rendering quality or optimization stability [S1].
