# Smoothed 2D Supervision

Also called: Adaptive Gaussian blur strategy, Progressive Gaussian Blurring

## Overview
Smoothed 2D Supervision is a regularization technique that enhances the robustness of joint optimization by smoothing the 2D supervision signal [S1][S2, unofficial]. It solves the problem of weak and noisy gradient signals during camera alignment and 3D scene reconstruction by blurring 2D training images with a parallel set of scheduled 2D Gaussian kernels [S2, unofficial]. This produces smoothed image gradients, stabilizes camera alignment, and restricts the spectrum of the learned 3D scene [S2, unofficial]. It sets itself apart from siblings like [Frequency Regularization](6130-frequency-regularization.md) by operating directly on the pixel supervision signal via explicit spatial blurring rather than frequency-domain weighting or positional encoding adjustments [S3].

## How it works
**Inputs and Outputs:**
*   **Input:** 2D training images $I$, camera parameters (pose, intrinsics), and a Gaussian blur schedule defined by kernel size $k$ and standard deviation $\sigma$.
*   **Output:** Smoothed supervision images $I_{smooth}$ used in the photometric loss calculation.

**Data Structures:**
*   **Gaussian Kernel:** A 2D separable Gaussian kernel $K(x, y)$ defined by standard deviation $\sigma$. For implementation, a 1D kernel is sufficient due to separability.
*   **Schedule Parameters:** Initial kernel size (e.g., $9 \times 9$), initial $\sigma$ (e.g., 2.4), iteration interval for reduction $k_b$ (e.g., 100), and total iterations (e.g., 19500) [S4].

**Steps:**
1.  **Initialize Schedule:** Set initial kernel size $k_{init}$ and standard deviation $\sigma_{init}$. Define the reduction interval $k_b$ and the target iteration $T_{end}$ where $\sigma$ reaches 0 [S2, unofficial][S4].
2.  **Compute Current Kernel:** At iteration $t$, calculate the current standard deviation $\sigma_t$. If $t < T_{end}$, $\sigma_t$ decreases from $\sigma_{init}$ to 0. If $t \ge T_{end}$, $\sigma_t = 0$ [S2, unofficial][S4].
    *   Note: The kernel size may also be adjusted based on downsampling scales if active [S4].
3.  **Apply Blur:** Convolve each training image $I$ with the 2D Gaussian kernel $K_{\sigma_t}$ to produce the smoothed image $I_{smooth}$:
    $$ I_{smooth} = I * K_{\sigma_t} $$
    [S2, unofficial][S4]
4.  **Compute Loss:** Calculate the photometric loss (e.g., L1 or LPIPS) between the rendered image $I_{render}$ and the smoothed image $I_{smooth}$:
    $$ \mathcal{L}_{smooth} = \mathcal{L}(I_{render}, I_{smooth}) $$
    [S2, unofficial]
5.  **Update:** Backpropagate gradients through $\mathcal{L}_{smooth}$ to update camera poses and scene parameters [S2, unofficial].

**Parameters:**
*   Initial kernel size: $9 \times 9$ [S4].
*   Initial $\sigma$: 2.4 [S4].
*   Reduction interval $k_b$: 100 iterations [S4].
*   End iteration $T_{end}$: 19500 [S4].
*   $\sigma$ reaches 0 at $T_{end}$ and remains 0 afterward [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Downsampling:** When downsampling and blurring are activated together, the kernel size must be lowered by the scale of downsampling at the current stage, as the initial hyperparameter choice is based on original image resolutions [S4].
*   **Densification:** The blurring kernel size should be lowered before densifying Gaussians to introduce extra signal on the gradient of erroneous Gaussians as the noise level reduces [S4].
*   **Handcrafted Nature:** This strategy is handcrafted and cannot fully align frequency relationships compared to adaptive methods, potentially leading to suboptimal results in complex scenarios [S3].

**Pseudocode:**

    """
    Calculate the standard deviation of the Gaussian blur kernel at iteration t.
    """
    if t >= t_end:
        return 0.0
    # Linear decay from sigma_init to 0 over t_end iterations
    # Note: Source [S2, unofficial] mentions exponential reduction in one context but [S4] implies a schedule.
    # We follow the explicit schedule parameters from [S4] which are concrete.
    # However, [S2, unofficial] says "exponentially reduced". [S4] says "Gradually reduce... for every k_b".
    # Given the conflict, we implement the explicit step-wise reduction from [S4] as it provides concrete numbers.
    # If exponential is required, the formula would be sigma_init * exp(-alpha * t).
    # Here we assume linear decay as per the "schedule" description in [S4] context of Trick-GS.
    # To be safe, we note the discrepancy. [S2, unofficial] says "similar to 3D radiance fields" which often use exponential.
    # But [S4] gives specific numbers. We use the specific numbers from [S4].
    progress = t / t_end
    return sigma_init * (1 - progress)

## Subtopics

### [Randomly Scaled Kernel Parameter](7875-randomly-scaled-kernel-parameter.md)
Randomly Scaled Kernel Parameter is a regularization technique used during joint optimization to mitigate weak and noisy gradient signals. It addresses the insufficiency of using a single-size kernel for diverse real-world scene structures, where a fixed kernel may be overly aggressive in some contexts and overly gentle in others. By randomly scaling the kernel size, it allows combinations of different-sized kernels to guide the optimization, resulting in a more robust training schedule.

### [Multiscale Pre-convolved Representation](10911-multiscale-pre-convolved-representation.md)
A regularization technique for neural illumination fields that stabilizes the decomposition of object materials from environmental illumination by enforcing consistency with pre-computed, roughness-adapted background reflections. It addresses the ambiguity where diffuse object color is incorrectly absorbed into the estimated environment map, a problem inherent to high-dimensional neural illumination representations. Unlike methods that ignore the background or treat it as static, this method explicitly models the relationship between rough refractive surfaces and the convolved background, allowing for realistic specular reflections even when roughness exceeds the kernel scale. The technique builds on [Smoothed 2D Supervision](7213-smoothed-2d-supervision.md) by applying discrete Gaussian blur kernels to the background to stabilize convergence.

### [Soft Rasterization](13687-soft-rasterization.md)
Soft rasterization is a differentiable rendering technique that mitigates the discontinuities inherent in standard rasterization by blending facet contributions for pixels near primitive edges. It solves the problem of sparse and vanishing gradients caused by the non-uniformity of bilinear interpolation operands, which typically have similar values except at object boundaries. Unlike standard hard rasterization, it yields slightly distorted images but allows backpropagating more useful gradients, thereby stabilizing optimization and preventing gradient vanishing at edges.

## Operating characteristics
*   **Time Complexity:** Adds a convolution step per iteration. Since the kernel is small and separable, the cost is low relative to the rendering step.
*   **Memory Complexity:** No additional memory required beyond the smoothed image buffer.
*   **Performance:** Achieves 19.72 PSNR on DTU 3-view, improving over the Baseline (19.54) [S3].
*   **Strengths:** Stabilizes camera alignment, reduces noise in gradients, and restricts high-frequency artifacts [S2, unofficial].
*   **Limitations:** Handcrafted schedule may not optimally align with the scene's frequency content compared to adaptive methods [S3].
*   **When to Use:** When joint optimization of camera poses and scene geometry is unstable or prone to local minima [S1].
*   **When Not to Use:** When high-frequency detail preservation is critical and adaptive frequency regularization is available [S3].

## Background
Smoothed 2D Supervision was introduced as part of techniques to improve robustness in joint optimization of camera poses and radiance fields [S1][S2, unofficial]. It is inspired by the analysis of spectral modulation in radiance fields [S2, unofficial]. The method is experimentally proven crucial for successful pose refinement [S1]. It is used in methods like Trick-GS [S4] and Few-shot NeRF [S3].
