# Distributed 3D Gaussian Splatting

Also called: Distributed 3D Gaussian Splatting for Scientific Visualization, Distributed 3D-GS, Multi-GPU 3D-GS

## Overview
Distributed 3D Gaussian Splatting is a multi-GPU extension of the 3D Gaussian Splatting (3D-GS) pipeline designed for scientific visualization, enabling the scalable processing of large datasets that exceed single-GPU memory capacity [S1]. It differs from single-GPU baselines by distributing the global point cloud and Gaussian parameters across multiple GPUs, allowing for the reconstruction of scenes with tens of millions of primitives [S1]. Unlike [BlitzGS](15088-blitzgs.md) which focuses on inference acceleration, this method specifically addresses the training scalability for high-fidelity isosurface reconstruction from scientific volume data [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** Scientific volume data (e.g., CFD simulation outputs), number of GPUs ($N_{GPU}$), image resolution ($R \times R$), number of synthetic camera views ($N_{views}$).
*   **Output:** Optimized set of 3D Gaussian primitives (mean $\mu$, covariance $\Sigma$, opacity $\alpha$, spherical harmonics coefficients for color) distributed across $N_{GPU}$ devices, and rendered images matching the synthetic views.

**Data Structures:**
The global state consists of a point cloud and associated Gaussian parameters. This global state is sharded across $N_{GPU}$ workers.
*   **Global Point Cloud:** A set of $M$ points extracted from the isosurface.
*   **Gaussian Parameters:** For each point $i$, parameters include:
    *   Mean position $\mu_i \in \mathbb{R}^3$.
    *   Scale $s_i \in \mathbb{R}^3$ and Rotation $q_i \in \mathbb{R}^4$ (used to construct covariance $\Sigma_i$).
    *   Opacity $\alpha_i \in [0, 1]$.
    *   Color coefficients (Spherical Harmonics).
*   **Sharding:** The global set of $M$ Gaussians is partitioned into $N_{GPU}$ shards. Each GPU $k$ holds a subset of indices $I_k$ such that $\bigcup I_k = \{0, \dots, M-1\}$ and $I_j \cap I_k = \emptyset$ for $j \neq k$. The training images (synthetic views) are also distributed or replicated across workers.

**Steps:**
1.  **Initialization:** Extract an isosurface point cloud directly from the scientific volume data using external tools (e.g., ParaView) [S1]. These points serve as the initial means $\mu_i$ for the Gaussian primitives, bypassing image-based reconstruction initialization [S1].
2.  **Camera Setup:** Generate a set of $N_{views}$ synthetic camera views in a structured orbit around the data [S1]. The number of views is set to 448 to support data complexity, an increase from the 250 views used in prior work [S1].
3.  **Distribution:** Distribute the global point cloud and Gaussian parameters such that each GPU holds a shard of the data [S1]. Distribute the training data (images) across workers [S1].
4.  **Training Loop:**
    a. Each GPU renders its local shard of Gaussians into the assigned subset of images using the standard 3D-GS splatting algorithm (projecting 3D Gaussians to 2D, sorting, and alpha blending) [S1].
    b. Compute the loss (e.g., L1 loss + D-SSIM) between the rendered images and the ground truth synthetic views [S1].
    c. Compute gradients for the Gaussian parameters ($\mu, \Sigma, \alpha, \text{color}$) with respect to the loss [S1].
    d. **Synchronization:** Synchronize gradients across all GPUs via a fused all-reduce scheme [S1]. This ensures that the global model state is updated consistently despite the data sharding.
    e. Update the local Gaussian parameters using an optimizer (e.g., Adam) [S1].
    f. Repeat until convergence.

**Parameters:**
*   **Number of Synthetic Camera Views:** 448 [S1].
*   **Image Resolutions:** 512x512, 1024x1024, 2048x2048 [S1].
*   **Hardware:** NVIDIA A100 GPUs [S1].

**Pitfalls:**
*   **Memory Limits:** A single A100 GPU supports up to approximately 11.2M Gaussians [S1]. Datasets larger than this (e.g., Miranda with ~18M Gaussians) are infeasible on a single GPU and will fail due to out-of-memory errors [S1].
*   **Scalability:** Performance scaling is not perfectly linear due to communication overhead and load imbalance, though significant speedups are observed [S1].

**Pseudocode:**
```python
# Distributed 3D Gaussian Splatting Training
# Assumes a distributed environment with N_GPUs workers

def distributed_3dgs_train(volume_data, num_gpus, image_res, num_views=448):
    # 1. Initialization
    # Extract isosurface point cloud using external tool (e.g., ParaView)
    global_point_cloud = extract_isosurface_point_cloud(volume_data)
    
    # Initialize Gaussian parameters for each point
    # mu: mean, scale: scale, rot: rotation, alpha: opacity, sh: spherical harmonics
    global_gaussians = initialize_gaussians(global_point_cloud)
    
    # 2. Distribution
    # Shard the global data across GPUs
    # Each GPU gets a subset of Gaussians and a subset of training images
    local_gaussians = shard_data(global_gaussians, rank=GPU_ID)
    local_images = shard_data(generate_synthetic_views(num_views), rank=GPU_ID)
    
    # 3. Training Loop
    for epoch in range(max_epochs):
        # Forward pass: Render local Gaussians
        rendered_images = []
        for image_view in local_images:
            # Project local Gaussians to 2D screen space
            # Sort by depth, splat, and alpha blend
            rendered = render_3dgs(local_gaussians, image_view.camera_params, image_res)
            rendered_images.append(rendered)
        
        # Compute Loss
        # Compare rendered images with ground truth synthetic views
        loss = compute_loss(rendered_images, local_images)
        
        # Backward pass
        gradients = compute_gradients(loss, local_gaussians)
        
        # Synchronize Gradients
        # Fused all-reduce across all GPUs
        synchronized_gradients = all_reduce(gradients, op='sum')
        
        # Update Parameters
        local_gaussians = optimizer_step(local_gaussians, synchronized_gradients)
        
    return global_gaussians
```

## Subtopics

### BlitzGS
Focuses on inference acceleration and caching for faster rendering, rather than distributed training scalability [15088-blitzgs.md].

### GS-Cache Inference Framework
Optimizes inference time through caching mechanisms, distinct from the training distribution focus of this method [15588-gs-cache-inference-framework.md].

### Distributed Batched Rendering Loop
Addresses rendering throughput via batching, potentially applicable to inference or training but distinct in its loop structure [18495-distributed-batched-rendering-loop.md].

### Online Image Rendering Placement
Deals with dynamic placement of rendering tasks, not the static sharding of Gaussian primitives for training [19195-online-image-rendering-placement.md].

### Grendel
The underlying distributed training framework adapted by this method; Grendel provides the parallel training strategy for neural fields and splatting [19770-grendel.md].

## Operating characteristics
*   **Time Complexity:** Training time decreases significantly with the number of GPUs. For the Kingsnake dataset (4M Gaussians) at 2048x2048 resolution, training time drops from 48.00 minutes on 1 GPU to 8.50 minutes on 4 GPUs, a 5.6x speedup [S1].
*   **Memory Complexity:** Scales linearly with the number of Gaussians. The method is necessary when the number of Gaussians exceeds the single-GPU memory limit (~11.2M on A100) [S1].
*   **Measured Performance:**
    *   **Kingsnake (4M Gaussians, 110.3 MB):** At 2048x2048 with 4 GPUs, PSNR 29.32, SSIM 0.97, LPIPS 0.03 [S1].
    *   **Miranda (18M Gaussians, 491 MB):** At 2048x2048 with 4 GPUs, PSNR 36.37, SSIM 0.99, LPIPS 0.011 [S1].
*   **Strengths:** Enables training of large-scale scientific datasets (e.g., 18M Gaussians) that are impossible on single GPUs; high reconstruction fidelity for isosurfaces [S1].
*   **Limitations:** Requires multi-GPU infrastructure; communication overhead limits perfect linear scaling; initialization relies on external tools like ParaView [S1].
*   **When to use:** When reconstructing large scientific volume data with millions of Gaussians that exceed single-GPU memory.
*   **When not to use:** For small scenes that fit on a single GPU, where the overhead of distributed training is unnecessary.

## Background
This method was presented by Mateevitsi, Papka, Petruzza, and Sizzi from the University of Illinois Chicago, Argonne National Laboratory, and Utah State University [S1]. It was published in 2025 at the IEEE International Conference on e-Science (e-Science) [S1]. The work builds on previous research by Sewell et al. [4] which demonstrated high-fidelity isosurface reconstruction using Gaussian primitives, and adapts the distributed training design from Grendel-GS [6] to the 3D-GS pipeline. It aims to integrate 3D-GS into HPC-based scientific workflows for real-time post hoc and in situ visualization [S1].
