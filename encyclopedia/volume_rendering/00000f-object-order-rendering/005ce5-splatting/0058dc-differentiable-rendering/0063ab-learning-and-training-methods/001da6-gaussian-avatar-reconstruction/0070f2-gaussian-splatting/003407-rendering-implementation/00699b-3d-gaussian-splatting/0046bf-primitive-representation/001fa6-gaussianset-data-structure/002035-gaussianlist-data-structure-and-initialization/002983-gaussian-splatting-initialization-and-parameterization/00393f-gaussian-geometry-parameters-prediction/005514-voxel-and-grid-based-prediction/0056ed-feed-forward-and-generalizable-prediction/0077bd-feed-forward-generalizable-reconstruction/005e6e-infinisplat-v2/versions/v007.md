# InfiniSplat v2

Also called: InfiniSplat

## Overview
InfiniSplat v2 is a feed-forward Gaussian reconstruction method for arbitrary input views that decouples geometry and attribute prediction, uses ground-truth (GT) camera poses for alignment during training, and employs large-angle target view supervision to improve rendering quality under large viewpoint changes [S1, unofficial]. It differs from its parent [Feed-forward Generalizable Reconstruction](16746-feed-forward-generalizable-reconstruction.md) and siblings like [DA3-GS](16423-splatt3r.md) by freezing the geometry branch to prevent geometric degradation caused by joint optimization, and by using GT poses to avoid pose errors that misguide the network under large-angle supervision [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** $N$ input RGB images $I_C = \{I_i\}_{i \in C}$ and optional pose conditions $Q_C$ (camera intrinsics and poses). In the pose-free setting, $Q_C = \emptyset$ [S1, unofficial].
*   **Outputs:** A set of $M$ 3D Gaussians $\mathcal{G} = \{(\mu_m, \xi_m)\}_{m=1}^M$, where $\mu_m \in \mathbb{R}^3$ is the center and $\xi_m = (\alpha_m, s_m, q_m, c_m)$ contains opacity, three-axis scale, rotation (quaternion), and zeroth-order spherical harmonic (SH) color [S1, unofficial].

**Data Structures:**
*   **Gaussian Set:** A list of $M$ Gaussians. Each Gaussian stores $\mu_m, \alpha_m, s_m, q_m, c_m$.
*   **Hidden State:** A 16-dimensional vector per Gaussian, used in Stage II refinement [S1, unofficial].
*   **KNN Graph:** A global graph storing neighbor indices for each Gaussian, reused across refinement steps [S1, unofficial].

**Parameters:**
*   Voxel merging side length: $0.004$ in the scale-normalized reconstruction frame [S1, unofficial].
*   Opacity pruning threshold $\tau_\alpha$: $0.01$ [S1, unofficial].
*   Mask thresholds: $\tau_{abs} = 0.03$, $\tau_{rel} = 0.01$ [S1, unofficial].
*   AdamW: $\beta = (0.9, 0.95)$, global batch size 16, L2 gradient clipping at 1.0 [S1, unofficial].
*   Stage I learning rates: $10^{-6}$ for last ten attribute-backbone Transformer blocks, $2 \times 10^{-4}$ for Gaussian head [S1, unofficial].
*   Stage I steps: 25,000 steps, 2,000 steps linear warmup, cosine decay to 0.1 times peaks [S1, unofficial].
*   Stage II learning rate: $2 \times 10^{-4}$, cosine decay to 0.1 times initial value, 5,000 steps [S1, unofficial].
*   Stage II updates: $K_r$ sampled uniformly from $\{1, 2, 3\}$ during training, 3 at inference [S1, unofficial].

**Algorithm:**

The method consists of two stages. Stage I initializes the scene using a dual-branch architecture. Stage II refines attributes using a KNN Transformer.

### Stage I: Initialization

1.  **Feature Extraction:**
    *   Initialize two branches from pretrained DA3 weights: a frozen geometry branch $\Phi_{geo}$ and a trainable attribute branch $\Phi_{attr}$ [S1, unofficial].
    *   Compute predicted depth $\hat{D}$ and cameras $\hat{\Pi}_C$ using $\Phi_{geo}(I_C; Q_C)$ [S1, unofficial].
    *   Compute multi-layer patch features $F_C$ using $\Phi_{attr}(I_C; Q_C)$ [S1, unofficial]. Only the last $K$ Transformer blocks of $\Phi_{attr}$ are fine-tuned [S1, unofficial].

2.  **Scale Alignment:**
    *   Express predicted and GT poses relative to their respective reference cameras (first input view in sorted order) [S1, unofficial].
    *   Normalize predicted depths and translations by $s_{norm} > 0$ [S1, unofficial].
    *   Fit an Umeyama similarity transform from the GT trajectory to the normalized predicted trajectory using only input-camera center correspondences. Retain the scale $s_C$ [S1, unofficial].
    *   Align GT translations: $t^\star_v = s_C t^\star_v$, while rotations remain unchanged: $R^\star_v = R^\star_v$ [S1, unofficial].

3.  **Point Construction:**
    *   Construct Gaussian centers $\mu_m$ from normalized predicted $z$-depth, GT intrinsics, and scale-aligned GT poses [S1, unofficial].
    *   Predict initial attributes $\xi^{(0)}$ from $F_C$ using a DPT decoder [S1, unofficial].

4.  **Voxel Merging and Pruning:**
    *   Merge Gaussians using voxel merging with side length $0.004$ [S1, unofficial].
    *   Prune Gaussians with opacity $\alpha < \tau_\alpha = 0.01$ [S1, unofficial].
    *   Let the resulting scene be $\mathcal{G}_0$ with $M$ Gaussians [S1, unofficial].

5.  **Stage I Loss:**
    *   Render $\mathcal{G}_0$ into input and target views $v \in V = C \cup T$: $\hat{I}_v = R(\mathcal{G}_0; \Pi^\star_v)$ [S1, unofficial].
    *   Construct visibility masks $M_v$: A target pixel is retained if it has finite GT depth $> 10^{-6}$, passes validity mask, and satisfies $|z_{proj} - d_{src}| \le \max(\tau_{abs}, \tau_{rel} d_{src})$ where $z_{proj}$ is point depth in input camera and $d_{src}$ is sampled depth [S1, unofficial].
    *   Compute LPIPS spatial distance map: $d_v = \text{LPIPS}_{spatial}(M_v \odot \hat{I}_v, M_v \odot I_v)$, with invalid regions zeroed before normalization [S1, unofficial].
    *   Compute loss $\mathcal{L}_I$ over valid pixels:
        $$ \mathcal{L}_I = \frac{\sum_{v \in V} \sum_{p} M_v(p) [e_v(p) + d_v(p)]}{\max(1, \sum_{v \in V} \sum_{p} M_v(p))} $$
        where $e_v(p)$ is the RGB-channel-averaged absolute error [S1, unofficial].

### Stage II: Refinement

1.  **Feature Preparation:**
    *   Project DPT features to 8 channels via learnable $1 \times 1$ conv, merge using Gaussian voxel groups/weights, and reuse [S1, unofficial].
    *   Initialize 16-dim hidden state $h$ via linear projection [S1, unofficial].

2.  **Refinement Loop (for $k = 1$ to $K_r$):**
    *   **Input Concatenation:** Concatenate image features, current attributes, gradient feedback, neighbor distances, and hidden states. Project to 64 dims [S1, unofficial].
    *   **KNN Transformer:** Process through four KNN Transformer blocks. Each block:
        *   Single-head attention over 8 neighbors.
        *   LayerNorm, MLP, residual connections.
        *   Output concatenated with original input, passed through MLP to predict increments $\Delta x$ and hidden-state increments $\Delta h$ [S1, unofficial].
    *   **Attribute Update:**
        *   Scales: $s_{new} = s_{old} \exp(\Delta \log s)$ [S1, unofficial].
        *   Opacity-logit, local rotation-vector, RGB-logit: $\text{tanh}(a \cdot \text{raw})$ with $a = 0.1, 0.25, 1.0$ respectively [S1, unofficial].
        *   Hidden-state: $0.1 \cdot \text{tanh}(\text{raw})$ [S1, unofficial].
        *   Clamp logit inputs to $[10^{-6}, 1-10^{-6}]$ [S1, unofficial].
        *   Centers, counts, and correspondence remain fixed [S1, unofficial].
    *   **Feedback Loss:**
        *   Render current scene into input views.
        *   Compute $\ell_{fb} = 0.8 L_1 + 0.2 L_{DSSIM}$, where $L_{DSSIM} = (1 - \text{SSIM})/2$ over valid regions [S1, unofficial].
        *   Compute gradients w.r.t attributes, normalize, and detach [S1, unofficial].
    *   **Outer Loss:**
        *   Compute $\ell_{out} = 0.8 L_1 + 0.2 L_{DSSIM} + 0.5 L_{LPIPS}$ for input and target views [S1, unofficial].
    *   **First-Order Surrogate Loss:**
        *   Let $x_k$ collect updated parameters. Compute rendering gradients on independent leaf copies $z_k = \text{sg}(x_k)$ to form $r_k = \text{sg}(\nabla_z \mathcal{L}_{render}(z_k))$ [S1, unofficial].
        *   Proxy loss: $\mathcal{L}_{kproxy} = \text{sg}(\mathcal{L}_{render}(z_k)) + \langle x_k - \text{sg}(x_k), r_k \rangle$ [S1, unofficial].

3.  **Stage II Objective:**
    *   Multi-step objective:
        $$ \mathcal{L}_{II} = \sum_{k=1}^{K_r} 0.9^{K_r-k} \mathcal{L}_{krender} + 0.1 \mathcal{L}_{opacity} $$
        where $\mathcal{L}_{krender}$ is the grouped outer loss after update $k$ [S1, unofficial].
    *   Opacity Regularization:
        $$ \mathcal{L}_{opacity} = \frac{1}{M} \sum_{m=1}^M [\text{logit}_\epsilon(\alpha_m^{K_r}) - \text{logit}_\epsilon(\alpha_m^0)]^2, \quad \epsilon = 10^{-6} $$
        where $\text{logit}_\epsilon(p) = \log(p / (1-p))$ clamped to valid range [S1, unofficial].

4.  **Chunked Execution:**
    *   Reuse global KNN graph [S1, unofficial].
    *   Stable sort along longest voxel-coordinate axis.
    *   Expand core sets of at most 200,000 points with four-hop neighborhoods [S1, unofficial].
    *   Recursively bisect chunks exceeding 300,000 points by point count along core sets' longest axes, recomputing neighborhoods [S1, unofficial].
    *   Retain only core-point outputs; use gradient checkpointing during training [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Stage I is dominated by the forward pass of the DA3 backbone and DPT decoder. Stage II involves $K_r$ refinement steps, each requiring KNN graph operations and Transformer blocks. Chunked execution limits memory usage but adds overhead for sorting and neighborhood recomputation [S1, unofficial].
*   **Memory Complexity:** Depends on the number of Gaussians $M$ and the KNN graph size. Chunked execution with core sets of up to 200,000 points and recursive bisection for chunks > 300,000 points helps manage memory [S1, unofficial].
*   **Performance:** Achieves state-of-the-art mean LPIPS and DISTS on six datasets in both pose-conditioned and pose-free settings. In the pose-conditioned setting, mean LPIPS and DISTS decrease by 25.8% and 32.9% respectively compared to strongest baselines [S1, unofficial].
*   **Strengths:** Decoupled geometry and attribute prediction prevents geometric degradation. GT pose alignment avoids pose errors under large-angle supervision. Large-angle target view supervision improves rendering quality under large viewpoint changes. Opacity learning suppresses geometrically inconsistent points (outliers) [S1, unofficial].
*   **Limitations:** Requires GT camera poses during training for alignment. Pose-free setting relies on reference input cameras for evaluation reference frame and translation scale estimation, not for reconstruction [S1, unofficial].
*   **When to use:** When high-quality novel view rendering under large viewpoint changes is required, and GT poses are available for training.
*   **When not to use:** When GT poses are not available and pose-free inference is required without reference cameras, or when computational resources are limited for the two-stage training process [S1, unofficial].

## Background
InfiniSplat v2 was introduced by Lin et al. in 2025/2026 as an improvement over DA3-GS and InfiniSplat [S1, unofficial]. It addresses limitations in Gaussian attribute learning, such as flying-point artifacts and pose errors under large-angle supervision [S1, unofficial]. The method builds on Depth Anything 3 (DA3) and uses a dual-branch architecture [S1, unofficial].
