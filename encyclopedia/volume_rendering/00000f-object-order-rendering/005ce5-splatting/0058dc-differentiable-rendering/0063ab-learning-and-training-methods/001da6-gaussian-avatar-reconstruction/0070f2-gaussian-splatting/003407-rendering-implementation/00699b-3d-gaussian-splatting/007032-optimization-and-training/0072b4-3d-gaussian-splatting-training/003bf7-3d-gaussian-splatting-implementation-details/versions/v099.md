# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, GSGEN Implementation Details, Gaussian Splatting Training Configuration, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific implementation parameters, optimization strategies, and variant algorithms used to train and render 3D Gaussian Splatting (3DGS) scenes. It addresses the practical challenges of differentiable rasterization, including half-precision stability, adaptive density control, and handling of complex scene properties like blur, noise, and non-Lambertian effects. It sets itself apart from general optimization theory by providing concrete thresholds, kernel behaviors, and specific variant formulations (e.g., corrected scene extent, selective defocus) required for a robust implementation.

## How it works

### Inputs and Outputs
*   **Inputs**: Camera poses ($C_i$), intrinsics, training images, and an initial point cloud (typically from Structure-from-Motion, SfM).
*   **Outputs**: A set of 3D Gaussian primitives $\mathcal{G} = \{\mu_j, \Sigma_j, \alpha_j, c_j\}$, where $\mu_j$ is position, $\Sigma_j$ is covariance, $\alpha_j$ is opacity, and $c_j$ are spherical harmonic (SH) coefficients for color.

### Data Structures
*   **Gaussian Attributes**: Each Gaussian stores position (3 floats), scale (3 floats), rotation (4 floats/quaternion), opacity (1 float), and SH coefficients (variable, typically degree 1 or 3).
*   **Rasterization State**: For each pixel, the forward pass maintains a depth-sorted list of contributing Gaussians to compute alpha-blended color and depth.

### Training Optimization and Initialization

#### Standard 3DGS Training Loop
The core training loop iterates over random camera views, rendering them, computing loss, and updating parameters [S3].

1.  **Initialization**: Initialize Gaussians from SfM points. Set SH degree to 1 initially [S3].
2.  **Iteration**:
    *   Randomly select a training image [S3].
    *   **Rasterization**: Project 3D Gaussians to 2D, sort by depth, and alpha-blend to produce the rendered image $\hat{C}$ [6233-optimization-and-parallelization].
    *   **Loss Computation**: Compute loss $\mathcal{L}$ between $\hat{C}$ and ground truth $C$. Typical loss is a combination of L1 and SSIM [S13, unofficial].
    *   **Backpropagation**: Compute gradients $\frac{\partial \mathcal{L}}{\partial \theta}$ for all Gaussian parameters [6233-optimization-and-parallelization].
    *   **Optimizer Update**: Use Adam optimizer with learning rate $1 \times 10^{-3}$ [S3].

#### Adaptive Density Control (Densification)
To manage the number of Gaussians, densification occurs periodically based on positional gradients [S1].

1.  **Splitting**: Every 500 iterations, split Gaussians whose accumulated view-space position gradient exceeds $T_{pos} = 0.02$ [S1].
2.  **Cloning**: Clone Gaussians with large gradients but small scales to increase density without creating thin artifacts [S1].
3.  **Pruning**: Every 200 iterations, remove Gaussians with opacity $\alpha < \alpha_{min} = 0.05$ or those with excessively large world-space/view-space radii [S1].
4.  **Compactness Check**: Perform compactness-based densification every 1000 iterations to ensure uniform distribution [S1].

#### Half-Precision Implementation
To reduce memory bandwidth and register pressure, implementations like `gsplat` use half-precision (FP16) arithmetic [S2].

1.  **Memory Fetches**: Use half-precision memory fetches for feature vectors during rasterization forward and backward passes [S2].
2.  **MLP Evaluation**: Use tiny-cuda-nn's JIT-compiled cooperative vector MLPs trained and evaluated in FP16 [S2].
3.  **Stability**: Apply an automatic scaling factor to loss values to prevent gradient underflow/overflow during half-precision training [S2].

### Variant Algorithms and Corrections

#### Corrected Scene Extent
Standard 3DGS calculates scene extent $e_{scene}$ based on camera positions, which biases densification if cameras are clustered (e.g., orbiting a small object in a large scene) [S4].

1.  **Calculate Average Camera Position**:
    $$ \bar{C} = \frac{1}{N_{cam}} \sum_{i=1}^{N_{cam}} C_i $$
2.  **Calculate Corrected Extent**: Use the SfM point cloud $p_i$ instead of cameras:
    $$ e'_{scene} = \frac{1}{N_{SfM}} \sum_{i=1}^{N_{SfM}} \|\bar{C} - p_i\|_2 $$
    This prevents incorrect splitting/pruning due to camera distribution bias [S4].

#### Selective Defocus Blurring
To handle spatially varying blur, predict a per-Gaussian scale offset $\delta s_j$ [S5].

1.  **Prediction**: Use a compact MLP to predict $\delta s_j$ for each Gaussian $j$.
2.  **Covariance Transformation**: Add $\delta s_j$ to the base scale to transform the covariance matrix.
3.  **Rasterization**: Project the transformed covariance to 2D space. This acts as a pixel-wise blur kernel, allowing different Gaussians to contribute differently to blurred regions [S5].

#### Denoise-GS for Sparse/Noisy Views
A two-round self-supervised denoising pipeline [S6].

1.  **Round 1**: Train a UNet using Noise2Void (N2V) on input images. Process denoised images through InstantSplat to initialize and train 3DGS. Render results and filter by viewpoint for stability.
2.  **Round 2**: Fine-tune the UNet using a composite loss (low-frequency consistency + perceptual detail). Render again on selected viewpoints to generate final denoised views [S6].

#### Multi-Scale Constraint
For large scenes, apply position-aware adaptive control based on viewer distance [S7].

1.  **Compute Gamma**:
    $$ \gamma(\mu) = \begin{cases} 1 & \text{if } \|\mu - c\|^2 < 2r \\ \|\mu - c\|^2 / r - 1 & \text{if } \|\mu - c\|^2 \ge 2r \end{cases} $$
    where $r$ is scene radius and $c$ is camera center.
2.  **Density Control**:
    *   If $\max(s) < g \cdot \gamma(\mu)$, clone the Gaussian.
    *   If $\max(s) \ge g \cdot \gamma(\mu)$, split the Gaussian.
    *   If $\max(s) > b \cdot \gamma(\mu)$, eliminate the Gaussian.
    *   $g$ and $b$ are scale threshold parameters [S7].

#### LS-Gaussian Viewpoint Transformation
For sparse rendering in video sequences, transform viewpoints between consecutive frames rather than rendering each independently [S8].

1.  **Transformation**: Leverage inter-frame continuity to transform the Gaussian set from frame $t$ to $t+1$.
2.  **Sparse Rendering**: Fully render only one frame in every 6 frames, interpolating the rest via transformation.
3.  **Pitfall**: Quality degrades as the number of consecutively transformed frames increases due to accumulated interpolation errors [S8].

#### Neural Illumination Enhancement (NIE)
To model non-Lambertian effects (specular highlights), add a neural residual to the explicit Gaussian rendering [S16, unofficial].

1.  **Inputs**: Spatial position (HashGrid encoded), reflection direction (SH encoded), and material features (view direction, normals, Fresnel, roughness).
2.  **MLP**: Predict view-dependent color residual $I_n$ using a lightweight MLP.
3.  **Final Image**: $I = I_g + I_n$, where $I_g$ is the standard 3DGS render [S16, unofficial].

#### PyGS Optimization
For multi-scale pyramidal representations, preserve level assignments during densification [S13, unofficial].

1.  **Loss**: $L = \lambda \cdot MSE(C, \hat{C}) + (1 - \lambda) \cdot SSIM(C, \hat{C})$.
2.  **Density Control**: Apply standard 3DGS splitting/cloning, but newly created Gaussians remain in their original level/cluster.
3.  **Reassignment**: Routinely reassess Gaussian levels based on their scales to maintain balanced distribution across pyramidal levels [S13, unofficial].

#### GAINS Inverse Rendering
A two-stage framework for sparse-view inverse rendering using 2DGS for better geometry [S14].

1.  **Stage I (Geometry)**: Optimize geometry using monocular depth, normal, and diffusion priors.
2.  **Stage II (Material/Lighting)**: Jointly optimize material parameters and lighting using segmentation, intrinsic image decomposition (IID), and diffusion priors to minimize re-rendering loss.
3.  **Input**: Typically 4–32 views [S14].

#### Conditional Splat Approximation
For slice-based rendering or tomography, approximate the 3D Gaussian influence on a slice using a 2D ellipse scaled by a marginal factor [S12, unofficial]. This closely matches true iso-probability contours, providing an efficient and accurate approximation of the 3D Gaussian's influence range [S12, unofficial].

#### Opacity Offset Table for DSA
Construct an opacity offset table to model changes in Digital Subtraction Angiography (DSA) scenes, allowing dynamic adjustment of Gaussian opacity to account for temporal variations in contrast agents [S11].

#### GraphiGS Uncertainty Modeling
Model the component distribution $\delta_\theta$ as a 3D Gaussian primitive to provide compact spatial support and exponential density decay [S17].

$$ \delta_{GS}(x; \mu, \Sigma) = \exp\left(-\frac{1}{2} (x - \mu)^T \Sigma^{-1} (x - \mu)\right) $$

where $\mu \in \mathbb{R}^3$ and $\Sigma \in \mathbb{R}^{3 \times 3}$ [S17].

#### Camera Localisation for Convergence Basin
To localize a camera pose for a target view:

1.  **Initialize**: Set $T_{CW}$ to the position of a test view.
2.  **Optimize**: Minimize photometric error against the target view's ground-truth color image, fixing the initial Gaussian set $G_{init}$.
3.  **Convergence**: If the estimated pose $T_{CW}^{est}$ converges to within 1cm of the target view within 1000 iterations, localization is successful [S9, unofficial].

$$ \mathbf{T}_{CW}^{est} = \underset{\mathbf{T}_{CW}}{\arg \min} \left\| I(\mathcal{G}_{init}, \mathbf{T}_{CW}) - \bar{I}_{target} \right\|_1 $$

#### DiffGS Framework
Optimizes Gaussians to exact locations using a Gaussian Probability Function (GauPF) with a truncation function $\lambda$ and projection function $\tau$ (e.g., $\tau(x) = e^{-x}$) [S10].

*   **Performance**: 50K Gaussians yield PSNR 28.61, SSIM 0.9787, LPIPS 0.0251. 100K Gaussians yield PSNR 30.35, SSIM 0.9838, LPIPS 0.0151. 350K Gaussians yield PSNR 34.01, SSIM 0.9879, LPIPS 0.0149 [S10].

#### SAGS and Frequency GS
*   **SAGS**: Uses an adaptive 2D low-pass filter at inference time based on rendering resolution and camera distance to handle aliasing [S15, unofficial].
*   **Frequency GS**: Applies frequency-domain regularization to the rendered 2D image to encourage recovery of high-frequency details, resolving blurring issues [S15, unofficial].

## Operating characteristics
*   **Time Complexity**: Rendering is $O(N \cdot M)$ where $N$ is the number of Gaussians and $M$ is the number of pixels, but optimized via tile-based rasterization and sorting. Training time is dominated by the iterative densification and backpropagation steps.
*   **Memory Complexity**: Scales linearly with the number of Gaussians. Standard 3DGS scenes can exceed 1GB [12943-data-compression-and-storage-optimization.md].
*   **Performance**: Real-time rendering (60+ FPS) is achievable on modern GPUs for scenes with millions of Gaussians [17349-human-gaussian-splatting.md].
*   **Strengths**: High fidelity, real-time rendering, explicit representation.
*   **Limitations**: High memory usage, sensitivity to initialization, potential for floaters and aliasing without variants [15421-scene-representation-and-geometry-constraints.md].

## Background
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 as a real-time explicit scene representation method [S1]. It builds on the concept of splatting, adapting it for differentiable rendering with 3D Gaussians. The method has since spawned numerous variants for compression, dynamic scenes, and specialized rendering tasks.
