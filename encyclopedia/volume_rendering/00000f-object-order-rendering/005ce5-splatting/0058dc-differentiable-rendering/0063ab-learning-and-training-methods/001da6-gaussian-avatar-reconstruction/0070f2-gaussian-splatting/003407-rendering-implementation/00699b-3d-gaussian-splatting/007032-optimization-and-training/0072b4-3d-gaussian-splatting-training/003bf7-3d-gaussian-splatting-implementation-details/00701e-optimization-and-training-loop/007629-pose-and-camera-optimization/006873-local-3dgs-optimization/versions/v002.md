# Local 3DGS Optimization
Also called: Local 3DGS Pose Optimization

## Overview
Local 3DGS Optimization is an iterative method for estimating the relative camera pose (transformation) between two nearby images by optimizing a local 3D Gaussian Splatting representation against photometric loss [S1]. It solves the problem of camera pose estimation in COLMAP-free pipelines where initial camera intrinsics may be unknown or approximate [S1]. It differs from global optimization methods by freezing the geometric attributes of a locally initialized Gaussian set and learning only the rigid body transformation (pose) parameters to align the local representation with a target view [S1].

## How it works
**Inputs:**
*   Two nearby images: current image $I_t$ and target image $I_{t+1}$ [S1].
*   Monocular depth estimation model $DPT$ (Vision Transformers for dense prediction) [S1].
*   Optional camera intrinsics; if unknown, Field of View (FoV) is set to $79^\circ$ and principal points to the image center [S1].

**Outputs:**
*   Estimated relative pose $Q_t$, defined as the cumulative product of transformations $T_i$ from the start of the sequence to the current step [S1].

**Data Structures:**
*   **Local 3DGS ($G_t$):** A set of 3D Gaussians initialized from $I_t$ and its estimated depth $D_t$. Attributes include position, spherical harmonics (SH) coefficients, opacity, scale, and rotation [S1].
*   **Pose Parameter ($T_t$):** A learnable rigid transformation represented by a quaternion vector and a translation vector [S1]. Initialized as the Identity matrix $I$ [S1].

**Algorithm Steps:**

1.  **Local Initialization:**
    *   Compute monocular depth map $D_t = DPT(I_t)$ [S1].
    *   Initialize the local Gaussian set $G_t$ using the function $InitGauss(I_t, D_t)$ [S1]. This typically involves generating a point cloud from the depth map, downsampling it to manage memory, and fitting 3D Gaussians to this point cloud [S1].
    *   The local Gaussian attributes (position, SH, opacity, scale, rotation) are fixed after this initialization phase [S1].

2.  **Local Fitting (Optional Pre-computation):**
    *   The text describes a preliminary optimization step where the downsampled point cloud is fitted via photometric loss for 500 iterations [S1]. During this phase, the Gaussian attributes are optimized [S1]. Note: The core pose estimation algorithm described in Algorithm 1 assumes $G_t$ is already initialized and potentially pre-fitted [S1].

3.  **Pose Optimization Loop:**
    *   Initialize pose $T_t \leftarrow I$ [S1].
    *   While not converged (typically up to 300 steps):
        1.  **Transform:** Apply the current pose $T_t$ to the fixed local Gaussians $G_t$ [S1].
        2.  **Render:** Rasterize the transformed Gaussians to produce the rendered image $\hat{I}_{t+1}$ [S1].
        3.  **Loss:** Compute the photometric loss $\mathcal{L}$ between the target image $I_{t+1}$ and the rendered image $\hat{I}_{t+1}$ [S1]. The loss is typically a combination of L1 and D-SSIM, consistent with standard 3DGS training [S1].
        4.  **Update:** Compute gradients $\nabla \mathcal{L}$ with respect to the pose parameters $T_t$ [S1]. Update $T_t$ using the Adam optimizer [S1].
        5.  **Freeze Attributes:** Crucially, the gradients are *not* backpropagated to the Gaussian attributes (position, SH, opacity, scale, rotation); only the pose parameters are updated [S1].

4.  **Pose Accumulation:**
    *   The final relative pose $Q_t$ is computed as the product of transformations: $Q_t = \prod_{i=1}^{t} T_i$ [S1].

**Pseudocode:**

```python
def Local3DGSPoseOptimization(I_t, I_t_plus_1, DPT_model, max_pose_steps=300):
    """
    Estimates the relative pose between I_t and I_t_plus_1 using Local 3DGS.
    
    Args:
        I_t: Current image (tensor or array)
        I_t_plus_1: Target image (tensor or array)
        DPT_model: Monocular depth estimation model
        max_pose_steps: Maximum number of optimization steps for pose
        
    Returns:
        T_t: Optimized pose transformation (quaternion + translation)
    """
    # 1. Initialize Local 3DGS from current view
    D_t = DPT_model(I_t)
    G_t = InitGauss(I_t, D_t)
    
    # Optional: Pre-fit local Gaussians for 500 iterations if not already done
    # for _ in range(500):
    #     I_hat = Rasterize(G_t)
    #     L = PhotometricLoss(I_t, I_hat)
    #     G_t = AdamUpdate(G_t, grad(L))
    # Note: Attributes of G_t are frozen after this point for pose estimation
    
    # 2. Initialize Pose
    T_t = IdentityPose()
    
    # 3. Optimize Pose
    for step in range(max_pose_steps):
        # Transform fixed Gaussians by current pose
        G_transformed = Transform(G_t, T_t)
        
        # Render transformed Gaussians
        I_hat = Rasterize(G_transformed)
        
        # Compute loss against target image
        L = PhotometricLoss(I_t_plus_1, I_hat)
        
        # Compute gradients w.r.t. Pose ONLY
        grad_pose = Gradient(L, T_t)
        
        # Update Pose using Adam
        T_t = AdamUpdate(T_t, grad_pose)
        
        # Check convergence criteria (e.g., loss change threshold)
        if CheckConvergence(L, step):
            break
            
    return T_t

def AccumulatePoses(pose_history):
    """
    Computes the cumulative relative pose.
    
    Args:
        pose_history: List of relative poses [T_1, T_2, ..., T_t]
        
    Returns:
        Q_t: Cumulative pose
    """
    Q_t = IdentityPose()
    for T_i in pose_history:
        Q_t = MultiplyPoses(Q_t, T_i)
    return Q_t
```

**Parameters:**
*   **Local Fitting Iterations:** 500 iterations for fitting the downsampled point cloud via photometric loss [S1].
*   **Pose Optimization Steps:** 300 steps [S1].
*   **Camera Intrinsics (Heuristic):** FoV $79^\circ$, principal point at image center [S1].

**Edge Cases and Pitfalls:**
*   **Unknown Intrinsics:** If camera intrinsics are unknown, using heuristic values ($79^\circ$ FoV) leads to slight degradation in novel view synthesis and pose estimation accuracy compared to optimized intrinsics [S1].
*   **Dramatic Motion:** The method is designed to handle dramatic camera motions (large relative rotation angles), as validated on datasets like Tanks and Temples and CO3D-V2 [S1].
*   **Freezing Attributes:** Failure to freeze Gaussian attributes during the pose optimization step will result in incorrect gradient flow and poor pose estimation [S1].

## Operating characteristics
*   **Time Complexity:** The method is computationally efficient for pose estimation as it optimizes only 6 degrees of freedom (pose) rather than the full Gaussian set. The pose optimization is limited to 300 steps [S1].
*   **Memory Complexity:** Depends on the size of the local Gaussian set $G_t$, which is derived from a downsampled point cloud of the current image $I_t$ [S1].
*   **Strengths:** Enables COLMAP-free pipelines; handles large relative rotations; does not require initial camera poses or intrinsics (can use heuristics) [S1].
*   **Limitations:** Performance degrades if heuristic intrinsics are used instead of optimized ones [S1]; relies on the quality of the monocular depth estimator [S1].

## Background
Local 3DGS Optimization was introduced in the supplementary material of "COLMAP-Free 3D Gaussian Splatting" by Zhou et al. (CVPR 2024) [S1]. It is part of a pipeline that eliminates the need for Structure-from-Motion (SfM) tools like COLMAP by using monocular depth estimation and local Gaussian optimization for pose estimation [S1].
