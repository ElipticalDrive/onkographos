# Training Configuration and Hyperparameters

Also called: Decoder Training Setup, Hyperparameter Tuning, Training Configuration for Gaussian Splatting Decoder

## Overview
This article defines the specific hyperparameters, optimization schedules, and training protocols required to stabilize and accelerate the convergence of 3D Gaussian Splatting (3DGS) decoders. While the parent method [Optimization Schedule and Densification](15107-optimization-schedule-and-densification.md) handles the dynamic growth of primitives, this configuration ensures that the learning rate, loss weights, and initialization strategies are tuned to prevent gradient instability, particularly when integrating semantic features or handling sparse view inputs. It addresses the problem of chaotic densification and poor spatial convergence by decoupling geometric and semantic optimization phases and standardizing downstream evaluation protocols.

## How it works
The training process is governed by a set of fixed hyperparameters and adaptive strategies that vary by application domain (e.g., generative decoding vs. semantic segmentation).

### Inputs and Outputs
*   **Inputs:** Pre-trained GAN features (for generative tasks), SfM point clouds (for initialization), multi-view images, and camera poses.
*   **Outputs:** Optimized Gaussian primitives $\{\mathbf{p}_i, \mathbf{s}_i, \mathbf{q}_i, \alpha_i, \mathbf{c}_i\}$ and, in semantic variants, aligned cross-modal embeddings.

### Data Structures
The standard 3DGS primitive representation is used [Parent]:
*   Position $\mathbf{p}_i \in \mathbb{R}^3$
*   Scale $\mathbf{s}_i \in \mathbb{R}^3$
*   Rotation $\mathbf{q}_i \in \mathbb{R}^4$ (quaternion)
*   Opacity $\alpha_i \in [0, 1]$
*   Color coefficients $\mathbf{c}_i$ (Spherical Harmonics)

For semantic tasks, an additional embedding vector $\mathbf{e}_i$ is appended to each primitive.

### Optimization Schedule and Parameters
The core optimization uses the Adam optimizer. The specific configuration depends on the task:

1.  **Generative Decoder (e.g., PanoHead, EG3D):**
    *   **Iterations:** 500,000 [S2].
    *   **Learning Rate:** 0.0009 [S2].
    *   **Loss Weights:** $\lambda_1=0.2, \lambda_2=0.5, \lambda_3=1.0, \lambda_4=1.0, \lambda_5=0.2$ [S2].
    *   **Camera Sampling:** For PanoHead, random cameras are sampled all around the head (360°). For EG3D, sampling is restricted to frontal views with small vertical and horizontal rotations [S2].

2.  **Voxel-Aligned 3DGS (VoxelTTO):**
    *   **Voxel Size:** 0.002 meters [S1, unofficial].
    *   **Splits per Voxel:** 2 splits [S1, unofficial].
    *   **TTO Iterations:** 20 iterations for test-time optimization [S1, unofficial].
    *   **Depth Loss:** Included to improve geometric accuracy; removing it causes a slight reduction in accuracy [S1, unofficial].

3.  **Semantic 3DGS (Phased Optimization):**
    *   **Phase 1 (Geometry):** Semantic learning rate is set to 0. The model optimizes only spatial geometry and photometric appearance using visual loss functions. This phase continues until the geometric structure stabilizes [S8].
    *   **Phase 2 (Semantics):** The semantic learning rate is gradually warmed up to activate semantic embedding optimization [S8].
    *   **Pitfall:** Simultaneous optimization of geometry and semantics from initialization causes unstable gradients, chaotic densification, poor spatial convergence, and failure to localize semantic concepts [S8].

4.  **Downstream Protocols (Classification/Segmentation):**
    *   **ModelNet10/40:** 1,024 Gaussians, 64 groups of 32, all 14 attributes. Full fine-tuning, linear probing, and three-layer MLP probing run for 300 epochs. Optimizer: AdamW, learning rate $10^{-3}$, weight decay 0.05, 5 warm-up epochs, total batch size 256. Frozen probing updates only the classifier [S3, unofficial].
    *   **ShapeNet-Part:** 2,048 Gaussians, 128 groups of 32. Batch size 16, learning rate $10^{-4}$, 300 epochs [S3, unofficial].

### Photometric Stereo Specifics
For calibrated photometric stereo, the training minimizes a composite loss $L = L_c + \lambda L_n$ [S5]:
*   $L_c$: L1 photometric loss between rendered and observed images.
*   $L_n$: Normal regularization term ensuring Gaussians align with the true object surface, calculated via the gradient of the depth map.
*   **Lighting Model:** Uses the Lambertian reflectance model:
    $$ I(x,y) \propto l^T \cdot n(x,y) $$
    where $I(x,y)$ is image intensity, $l$ is light direction, and $n(x,y)$ is surface normal [S5]. Self-occlusions (shadows) are calculated by analyzing surface alignment with the light direction [S5].

### Selective Update Strategy
In sparse view scenarios, continuous densification degrades performance. Instead, a selective update strategy is employed [S7]:
1.  Warp an image patch from a source view to a target view using the Gaussian primitive's position $\mathbf{p}$ and orientation $\mathbf{R}$ [S7].
2.  Compute Normalized Cross-Correlation (NCC) for Gaussian primitive warping ($NCC_G$) and for warping using rendered pixel-wise depth and normals ($NCC_R$) [S7]:
    $$ NCC(x, y) = \frac{\sum_{l=1}^{n} (x_l - \bar{x})(y_l - \bar{y})}{\sqrt{\sum_{l=1}^{n} (x_l - \bar{x})^2 \sum_{l=1}^{n} (y_l - \bar{y})^2}} $$
3.  If $NCC_R > NCC_G$, reproject the rendered depth into a 3D point and update the position of the corresponding Gaussian primitive [S7].
4.  **Frequency:** Positions are updated every 100 training steps [S7].

### Initialization Strategies
*   **Standard SfM:** Initialize from Structure-from-Motion point clouds [S4, unofficial].
*   **RAIN-GS:** Initialize Gaussians sparsely with large variance from the SfM point cloud and progressively apply low-pass filtering to avoid 2D Gaussian projections smaller than a pixel, addressing sensitivity to initialization [S4, unofficial].
*   **3DGSR (Synthetic):** Initialize the implicit function as a sphere and randomly initialize Gaussian positions [S6].
*   **3DGSR (Real-world):** Adopt SfM points as initialized Gaussian positions [S6].

## Subtopics

### [Adaptive Gaussian Refinement Strategy](16570-adaptive-gaussian-refinement-strategy.md)
The Adaptive Gaussian Refinement Strategy is a densification and pruning mechanism for 3D Gaussian Splatting that dynamically adjusts the number and size of Gaussians during training based on 2D gradient magnitude and screen-space size. It solves the problem of fixed Gaussian counts by growing Gaussians in regions with high reconstruction error and pruning those that are redundant or overly large. It differs from standard densification by explicitly tracking screen-space radii to enable screen-aware splitting and pruning, and by using a reset-based accumulation of gradient statistics to avoid bias from early training steps.

### [Spectrum and Edge-based Gaussian Splat Count Estimation](19432-spectrum-and-edge-based-gaussian-splat-count-estimation.md)
This method determines the expected number of 3D Gaussian splats per semantic group by analyzing image spectral complexity and edge energy to control geometric detail. It differs from naive frequency magnitude statistics by using a high-pass threshold strategy (implemented via Canny edge detection) to isolate high-frequency signals, which directly dictate Gaussian refinement. This approach outperforms naive mean magnitude because it suppresses dominant low-frequency noise and targets the high-frequency geometric details that require denser Gaussian representation.

### [Densification and Splitting](20677-densification-and-splitting.md)
Densification and splitting is the primary mechanism in 3D Gaussian Splatting (3DGS) for adapting the primitive population to scene complexity during optimization. It addresses the problem of insufficient geometric detail by subdividing existing Gaussians into smaller, more numerous primitives in regions where the current representation fails to reconstruct the input images accurately. Unlike static initialization methods, this dynamic process allows the model to grow its capacity iteratively, balancing reconstruction fidelity against computational cost. It sets itself apart from sibling methods like [Gaussian Pruning and Removal](21353-gaussian-pruning-and-removal.md) by focusing on constructive growth rather than destructive culling, although the two are often paired in a complete density control loop.

### [LiDAR-Guided Structural Initialization](20693-lidar-guided-structural-initialization.md)
LiDAR-Guided Structural Initialization is a method for initializing the geometric structure and density priors of a sparse voxel grid for driving scene reconstruction, specifically within the DrivingVoxels framework. It solves the problem of initializing a volumetric representation that is both sparse enough for efficiency and geometrically plausible enough to guide optimization, by using LiDAR point clouds to define voxel subdivision and density values. It differs from sibling methods like [Adaptive Gaussian Refinement Strategy](16570-adaptive-gaussian-refinement-strategy.md) by operating on a voxel grid rather than Gaussian splats, and from [Gaussian Pruning](18664-gaussian-pruning.md) by focusing on initial structural creation rather than post-training cleanup.

### Standard Downstream Protocols
A standardized training and evaluation pipeline for classification and part segmentation tasks using Gaussian inputs [S3, unofficial]. For ModelNet10/40, use 1,024 Gaussians, 64 groups of 32, and all 14 attributes. Run full fine-tuning, linear probing, and three-layer MLP probing for 300 epochs with AdamW, learning rate 1e-3, weight decay 0.05, 5 warm-up epochs, and total batch size 256. For linear and MLP probing, freeze the encoder and update only the classifier. For ShapeNet-Part, use 2,048 Gaussians, 128 groups of 32, batch size 16, learning rate 1e-4, and 300 epochs [S3, unofficial].

### RAIN-GS
A method that initializes Gaussians sparsely with large variance from the SfM point cloud and progressively applies low-pass filtering to avoid 2D Gaussian projections smaller than a pixel, addressing sensitivity to initialization [S4, unofficial].

### Photometric Stereo with Gaussian Splatting
A calibrated photometric stereo method that reconstructs 3D normal maps from multiple images with different lighting by optimizing Gaussian Splatting parameters using inverse rendering and a Lambertian reflectance model [S5]. It uses the Lambertian model to calculate self-occlusions (shadows) by analyzing if surfaces are aligned with the light direction, enabling view-dependent rendering despite a fixed camera. The loss function minimizes $L = L_c + L_n$, where $L_c$ is the L1 photometric loss and $L_n$ is a normal regularization term ensuring Gaussians align with the true object surface, calculated via the gradient of the depth map [S5].

### 3DGSR Initialization and Adaptive Control
For synthetic data, initialize the implicit function as a sphere and randomly initialize Gaussian positions. Increase the number of 3D Gaussian primitives during training following the adaptive control strategy in 3DGS. Implemented with CUDA and tinycudann, building upon the framework of 3DGS, with customized normal and depth maps CUDA rendering kernels [S6].

### Selective Gaussian Update
A strategy to selectively update Gaussian primitive positions using rendered geometric cues (depth/normal) instead of continuous densification, which degrades under sparse views [S7]. It warps image patches using Gaussian position and orientation, computes NCC for Gaussian warping ($NCC_G$) and rendered cue warping ($NCC_R$), and updates positions if $NCC_R > NCC_G$. Positions are updated every 100 training steps [S7].

### Phased Optimization Schedule
A training strategy that separates geometric and semantic optimization into phases to prevent unstable gradients and chaotic densification caused by simultaneous optimization [S8]. Phase 1 sets semantic learning rate to zero to optimize only spatial geometry and photometric appearance. Phase 2 gradually warms up the semantic learning rate after the geometric structure stabilizes [S8].

## Operating characteristics
*   **Time Complexity:** Training duration is significant, typically 500,000 iterations for generative decoders [S2]. Test-Time Optimization (TTO) adds negligible overhead (e.g., 2.304s for 10 images vs 2.293s without TTO) [S1, unofficial].
*   **Memory Complexity:** Depends on the number of Gaussians. Standard protocols use 1,024–2,048 Gaussians for downstream tasks [S3, unofficial]. Voxel-aligned methods use a fixed voxel size (0.002m) to bound density [S1, unofficial].
*   **Strengths:** Phased optimization prevents semantic-geometry conflict [S8]. Selective updates improve geometry in sparse views [S7]. RAIN-GS reduces initialization sensitivity [S4, unofficial].
*   **Limitations:** Simultaneous optimization of geometry and semantics fails [S8]. Continuous densification degrades under sparse views [S7].
*   **When to use:** Use phased optimization for semantic 3DGS [S8]. Use selective updates for sparse view reconstruction [S7]. Use RAIN-GS for SfM-initialized scenes [S4, unofficial].

## Background
3D Gaussian Splatting was introduced by Müller et al. [Müller 2021] as a real-time explicit scene representation. Subsequent works have adapted its training protocols for specific domains: generative decoding (PanoHead, EG3D) [S2], voxel-aligned feed-forward models (VoxelTTO) [S1, unofficial], semantic segmentation (Gaussian-JEPA) [S3, unofficial], photometric stereo [S5], and sparse view reconstruction (Sparse2DGS) [S7]. The phased optimization schedule was proposed to handle cross-modal alignment in open-world scene representations [S8].
