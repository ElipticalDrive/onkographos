# SplattingAvatar

Also called: SplattingAvatar: Realistic Real-Time Human Avatars with Mesh-Embedded Gaussian Splatting

## Overview
SplattingAvatar is a real-time human avatar rendering method that embeds 3D Gaussians directly onto a driving mesh (FLAME or SMPL-X) in mesh tangent space [S2, unofficial]. It solves the noise and instability associated with nearest-triangle sampling in canonical space, particularly for complex geometries like eyes and hair [S2, unofficial]. It sets itself apart from siblings like [GauHuman](9198-gauhuman.md) and [GaussianBody](9209-gaussianbody.md) by using trainable embeddings for motion control rather than physical priors or redesigned densification primitives, and avoids the artifacts of [Inpainting for Displaced Objects](9523-inpainting-for-displaced-objects.md) by maintaining strict mesh adherence [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Multi-view video of a human subject; a parametric head/body model (FLAME or SMPL-X) fitted to the subject; camera poses and intrinsics.
*   **Outputs:** A set of 3D Gaussians with attributes (position, covariance, color, opacity) embedded in mesh tangent space; a trained embedding network for motion control; a Unity-compatible rendering implementation.

**Data Structures:**
*   **Gaussian Attributes:** Each Gaussian $i$ has:
    *   Position $\mathbf{p}_i$ in mesh tangent space (local to the mesh triangle).
    *   3D covariance $\Sigma_i$ (represented as rotation $\mathbf{R}_i$ and scale $\mathbf{s}_i$).
    *   Color $\mathbf{c}_i$ (SH coefficients).
    *   Opacity $\alpha_i$.
    *   Trainable embedding vector $\mathbf{e}_i$ used for pose/expression conditioning.
*   **Mesh:** Parametric mesh (FLAME/SMPL-X) with vertices $\mathbf{V}$, faces $\mathbf{F}$, and UV coordinates.

**Numbered Steps:**
1.  **Initialization:** Fit a parametric mesh (FLAME or SMPL-X) to the input video using a fitting tool (e.g., MICA/DECA) [S1, unofficial]. Initialize one Gaussian per mesh triangle in the mesh tangent space [S1, unofficial].
2.  **Embedding-Based Motion Control:** Instead of deforming Gaussians via nearest-triangle sampling in canonical space (which causes noise [S2, unofficial]), use trainable embeddings $\mathbf{e}_i$ to predict pose- and expression-dependent offsets. These embeddings are ported to compute shaders for real-time motion control [S2, unofficial].
3.  **Training Optimization:**
    *   Total iterations: 30,000 [S2, unofficial].
    *   Loss weights: $\lambda_l = 0.01$ for L1 loss [S2, unofficial]. Other weights: $\lambda_s = 1.0$, $T_s = 10.0$, $T_r = 0.008$ [S2, unofficial].
    *   Iterations 0–599: No densification/pruning.
    *   Iterations 600–14,999: Densify and prune every 100 iterations [S2, unofficial].
    *   Every 3,000 iterations: Reset all Gaussian opacities to zero to remove redundant Gaussians [S2, unofficial].
    *   Iterations 15,000–29,999: No densification/pruning/opacity reset.
    *   "Walking on triangle" step: Performed after densifying and pruning to ensure Gaussians remain within their assigned mesh triangles [S2, unofficial].
4.  **Rendering:** Draw one quad primitive per Gaussian in a Unity implementation, using $\alpha^*$-blending [S2, unofficial].

**Pseudocode:**
```python
# SplattingAvatar Training Loop
def train_splatting_avatar(mesh, images, poses, expressions, num_iterations=30000):
    # 1. Initialization
    gaussians = initialize_gaussians_per_triangle(mesh) # One Gaussian per triangle
    embeddings = init_trainable_embeddings(gaussians)
    
    for iter in range(num_iterations):
        # 2. Motion Control via Embeddings
        # Predict offsets based on pose/expression and embeddings
        offsets = predict_offsets(embeddings, poses[iter], expressions[iter])
        gaussians.positions += offsets
        
        # 3. "Walking on Triangle" Step
        # Ensure Gaussians stay within their mesh triangle boundaries
        gaussians = walking_on_triangle(gaussians, mesh)
        
        # 4. Rendering and Loss Calculation
        rendered_image = render_gaussians(gaussians, camera_params)
        loss = compute_loss(rendered_image, images[iter], lambda_l=0.01)
        
        # 5. Optimization Step
        optimize(gaussians, embeddings, loss)
        
        # 6. Densification and Pruning Schedule
        if 600 <= iter < 15000:
            if iter % 100 == 0:
                gaussians = densify_and_prune(gaussians, threshold=0.008)
            if iter % 3000 == 0:
                gaussians.opacity = 0 # Reset opacity to remove redundant Gaussians
                
    return gaussians, embeddings

def walking_on_triangle(gaussians, mesh):
    # Clip Gaussian positions to their assigned mesh triangle in tangent space
    # This prevents Gaussians from sticking to triangle boundaries
    for g in gaussians:
        g.position = clip_to_triangle(g.position, g.triangle_index, mesh)
    return gaussians
```

**Parameters:**
*   $\lambda_l$ (L1 loss weight): 0.01 [S2, unofficial].
*   $\lambda_s$ (SSIM loss weight): 1.0 [S2, unofficial].
*   $T_s$ (Scale threshold): 10.0 [S2, unofficial].
*   $T_r$ (Rotation threshold): 0.008 [S2, unofficial].
*   Total iterations: 30,000 [S2, unofficial].
*   Densify/Prune frequency: Every 100 iterations (iterations 600–14,999) [S2, unofficial].
*   Opacity reset frequency: Every 3,000 iterations [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Nearest-Triangle Sampling:** Using nearest-triangle sampling for deformation (as in INSTA) causes unstable sampling in canonical space and strong noise in complex geometries like the eye region [S2, unofficial]. SplattingAvatar avoids this by using embeddings-based motion control [S2, unofficial].
*   **Disabling "Walking on Triangle":** Disabling this mechanism and clipping UV values causes Gaussians to stick and pile up on the boundaries of mesh triangles, leading to performance drops in PSNR, SSIM, and LPIPS metrics [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:** Over 300 FPS on an NVIDIA RTX 3090 GPU in a Unity implementation [S2, unofficial].
*   **Quantitative Results (Head Avatar Dataset):**
    *   Ours+FLAME: PSNR 28.19, SSIM 0.931, LPIPS 0.063 [S2, unofficial].
    *   Ours+NHA: PSNR 28.86, SSIM 0.931, LPIPS 0.060 [S2, unofficial].
*   **Scaling:** Not given in the sources.
*   **Strengths:** High-fidelity rendering of complex geometries (eyes, hair, glasses); non-ambiguous motion control; real-time performance; significant improvement in photometric quality over mesh-based methods like FLARE [S2, unofficial].
*   **Limitations:** Does not focus on accurate geometry and materials reconstruction compared to methods like FLARE [S2, unofficial]. Performance can drop if "walking on triangle" is disabled [S2, unofficial].
*   **When to use:** When real-time, high-quality human avatar rendering is required, especially for complex facial features.
*   **When not to use:** When accurate geometry and materials reconstruction are the primary goals (use FLARE instead) [S2, unofficial].

## Background
SplattingAvatar was introduced in the paper "SplattingAvatar: Realistic Real-Time Human Avatars with Mesh-Embedded Gaussian Splatting" [S2, unofficial]. It builds on the principles of 3D Gaussian Splatting [S1, unofficial] and addresses limitations in previous avatar methods like INSTA [S2, unofficial] and FLARE [S2, unofficial]. It is part of the family of application-specific reconstructions in differentiable volume rendering [S1, unofficial].
