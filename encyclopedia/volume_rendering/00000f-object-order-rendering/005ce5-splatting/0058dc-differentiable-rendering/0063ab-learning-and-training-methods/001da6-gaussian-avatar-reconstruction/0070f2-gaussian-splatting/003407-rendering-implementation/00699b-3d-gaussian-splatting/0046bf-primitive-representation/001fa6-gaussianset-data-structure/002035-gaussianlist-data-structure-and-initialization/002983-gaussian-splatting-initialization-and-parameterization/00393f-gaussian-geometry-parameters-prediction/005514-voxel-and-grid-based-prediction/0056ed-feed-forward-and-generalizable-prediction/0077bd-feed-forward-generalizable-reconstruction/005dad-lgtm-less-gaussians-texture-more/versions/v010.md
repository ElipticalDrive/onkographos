# LGTM (Less Gaussians, Texture More)
Also called: Feed-Forward Prediction of Textured Gaussians, Feed-Forward Textured Splatting

## Overview
LGTM is a feed-forward framework that predicts compact 2D Gaussian primitives coupled with per-primitive texture maps, decoupling geometric complexity from rendering resolution to enable high-fidelity 4K novel view synthesis without per-scene optimization [S1, unofficial]. It solves the problem where existing feed-forward 3DGS methods suffer from quadratic growth in primitive count as resolution increases, making high-resolution synthesis intractable due to memory and compute limits [S1, unofficial]. Unlike standard 3DGS which couples appearance and geometry within each primitive, LGTM allows a compact set of geometric primitives to represent rich texture regions via per-primitive textures [S1, unofficial].

## How it works
**Inputs and Outputs:**
The network $f$ takes a set of input images $\{I^v\}_{v=1}^N$ and their low-resolution counterparts $\{I^v_{low}\}_{v=1}^N$ as input. It predicts a set of textured 2D Gaussians:
$$ f : (I^v, I^v_{low}) \rightarrow \{\mu_i, s_i, r_i, c_i, T^i_c, T^i_\alpha\} $$
where $\mu_i$ is the center, $s_i$ is the scale, $r_i$ is the rotation, $c_i$ is the spherical harmonic (SH) coefficients, $T^i_c$ is the color texture map, and $T^i_\alpha$ is the alpha texture map for primitive $i$ [S1, unofficial].

**Data Structures:**
*   **Primitive Grid:** The primitive network predicts a grid of $h \times w$ 2DGS primitives, where $h \times w$ is the resolution of the low-resolution input $I^v_{low}$ [S1, unofficial].
*   **Per-primitive Texture Maps:** Each primitive $i$ has two texture maps:
    *   Color texture: $T^i_c \in \mathbb{R}^{T \times T \times 3}$
    *   Alpha texture: $T^i_\alpha \in \mathbb{R}^{T \times T}$
    *   $T$ is the texture resolution, a tunable parameter trading off primitive size and texture size [S1, unofficial].
    *   $T^i_c$ is zero-initialized [S1, unofficial].

**Architecture:**
The architecture consists of two submodules:
1.  **Primitive Network ($f_{prim}$):** Processes low-resolution images to predict compact geometric primitives ($\mu, s, r, c$) and base opacity $o_i$. It uses a ViT encoder-decoder to process $I^v_{low} \in \mathbb{R}^{h \times w \times 3}$ and predict an $h \times w$ primitive grid [S1, unofficial]. It also outputs feature maps $F^{v}_{prim}$ from the ViT decoder, which are shared with the texture network [S1, unofficial].
2.  **Texture Network ($f_{texture}$):** Processes high-resolution inputs to predict detailed per-primitive texture maps. It extracts high-resolution features via image patchification and projective mapping, then fuses them with geometric features from the primitive network [S1, unofficial].

**Steps:**

1.  **Primitive Prediction:**
    *   Input $I^v_{low}$ into the ViT encoder-decoder of $f_{prim}$.
    *   Predict primitive parameters $\{\mu_i, s_i, r_i, o_i, c_i\}$ for each of the $h \times w$ primitives.
    *   Extract feature maps $F^{v}_{prim}$ from the decoder [S1, unofficial].

2.  **Feature Extraction for Texture:**
    *   **Patch Features ($F^{v}_{patch}$):** Compute from the high-resolution image $I^v$ via patchification and convolutional layers [S1, unofficial].
    *   **Projective Features ($F^{v}_{proj}$):**
        *   For each primitive $i$, compute the inverse transformation $M^{-1}_{i,v}$ mapping primitive local coordinates $u$ to source image pixel coordinates $x$ [S1, unofficial].
        *   Compute the projective prior texture $T^{i, proj}_c$ by sampling the high-resolution source image $I^v$ at $x$:
            $$ T^{i, proj}_c[u] = I^v[x] = I^v[M^{-1}_{i,v}(u)] $$
        *   Extract features $F^{v}_{proj}$ from $T^{i, proj}_c$ [S1, unofficial].
    *   **Aggregation:** Aggregate $F^{v}_{prim}$, $F^{v}_{patch}$, and $F^{v}_{proj}$ to predict the final per-primitive textures $\{T^i_c, T^i_\alpha\}$ [S1, unofficial].

3.  **Rendering:**
    *   For a ray passing through pixel $x$, find the ray-splat intersection point $u$ on primitive $i$ using the homography transformation $M_{i,v}$, such that $u = M_{i,v}(x)$ [S1, unofficial].
    *   Retrieve alpha and color from the texture maps using bilinear sampling, denoted by $T[u]$ [S1, unofficial].
    *   Compute the alpha value $a_i(u)$ and color $\hat{c}_i(u, d_i)$ for the sample:
        $$ a_i(u) = o_i \cdot T^i_\alpha[u] $$
        $$ \hat{c}_i(u, d_i) = T^i_c[u] + SH(c_i, d_i) $$
        where $d_i$ is the view direction, $o_i$ is the base opacity, and $SH(c_i, d_i)$ is the spherical harmonic evaluation [S1, unofficial].
    *   Compute the final pixel color $C$ by alpha-blending contributions from all primitives sorted by depth:
        $$ C = \sum_i a_i(u_i) \hat{c}_i(d_i) \prod_{j=1}^{i-1} (1 - a_j(u_j)) $$
        [S1, unofficial].

**Training Strategy:**
*   **Stage 1:** Pre-train the primitive network $f_{prim}$ in isolation. Input $I^v_{low}$, predict 2DGS parameters, and render at full resolution $H \times W$ for high-resolution supervision. Loss: MSE + LPIPS [S1, unofficial].
*   **Stage 2:** Jointly train $f_{prim}$ and $f_{texture}$. Freeze or reduce the learning rate of $f_{prim}$ by 0.1x to maintain geometric stability. Initialize $T^i_c$ to zero. Loss: MSE + LPIPS [S1, unofficial].

**Pseudocode:**

```python
def lgtm_forward(input_images, low_res_images, camera_intrinsics, camera_poses):
    """
    Forward pass of LGTM.
    input_images: List of high-res images I^v
    low_res_images: List of low-res images I^v_low
    Returns: Predicted Gaussian primitives and texture maps
    """
    # Stage 1: Primitive Network
    # f_prim takes low-res images and predicts geometric primitives
    primitives, prim_features = f_prim(low_res_images)
    # primitives contains: mu, s, r, c, o for each of h*w primitives
    
    # Stage 2: Texture Network
    # f_texture takes high-res images and primitive features
    # Extract patch features from high-res images
    patch_features = extract_patch_features(input_images)
    
    # Compute projective features
    # Map primitive local coordinates back to image pixels
    projective_prior_textures = []
    for i, prim in enumerate(primitives):
        # Get homography M_inv for primitive i and view v
        M_inv = compute_inverse_homography(prim, camera_poses)
        # Sample high-res image at mapped coordinates
        # This creates a texture map T_c_proj for the primitive
        t_c_proj = sample_image_at_coords(input_images, M_inv)
        projective_prior_textures.append(t_c_proj)
        
    proj_features = extract_features_from_textures(projective_prior_textures)
    
    # Aggregate features and predict texture maps
    texture_maps = f_texture(prim_features, patch_features, proj_features)
    # texture_maps contains: T_c, T_alpha for each primitive
    
    return primitives, texture_maps

def lgtm_render(primitives, texture_maps, rays):
    """
    Render image from predicted Gaussians and textures.
    rays: List of rays with intersection points u on primitives
    Returns: Rendered image
    """
    # Sort primitives by depth for each ray
    sorted_primitives = sort_primitives_by_depth(primitives, rays)
    
    final_color = 0
    accumulated_alpha = 0
    
    for prim in sorted_primitives:
        # Get intersection point u for this primitive
        u = get_intersection_point(prim, rays)
        
        # Sample texture maps
        # T_alpha[u] returns scalar, T_c[u] returns RGB vector
        alpha_tex = sample_bilinear(texture_maps[prim.id].T_alpha, u)
        color_tex = sample_bilinear(texture_maps[prim.id].T_c, u)
        
        # Compute alpha and color
        # o is base opacity from primitive
        a = prim.o * alpha_tex
        
        # SH evaluation for base color
        base_color = evaluate_sh(prim.c, prim.view_direction)
        
        # Final color is texture color + SH base color
        c = color_tex + base_color
        
        # Alpha blending
        weight = a * (1 - accumulated_alpha)
        final_color += weight * c
        accumulated_alpha += weight
        
        if accumulated_alpha > 0.99: # Early exit optimization
            break
            
    return final_color
```

**Edge Cases and Pitfalls:**
*   **Memory Constraints:** Standard feed-forward methods fail at 2K+ resolutions due to memory (e.g., NoPoSplat fails at 2K). LGTM handles 2K/4K with <30GB memory [S1, unofficial].
*   **Holes in Rendering:** Without high-resolution supervision, predicted Gaussians may result in holes as they are not anti-aliased. High-res supervision forces the network to learn proper coverage [S1, unofficial].
*   **Geometric Stability:** In Stage 2, the primitive network must be trained with a reduced learning rate (0.1x) to prevent destabilizing the geometry learned in Stage 1 [S1, unofficial].

## Operating characteristics
*   **Time and Memory Complexity:** LGTM scales efficiently at inference; a 64x pixel increase adds only modest memory and time overhead [S1, unofficial]. It trains successfully at 2K and 4K resolutions using under 30 GB of memory, whereas methods like NoPoSplat fail to train at 2K or higher due to memory constraints (OOM) [S1, unofficial].
*   **Strengths:** Enables high-fidelity 4K novel view synthesis without per-scene optimization; decouples geometry and appearance; significantly fewer primitives than prior feed-forward methods [S1, unofficial].
*   **Limitations:** Requires a staged training strategy; relies on the quality of the baseline method (Flash3D, DepthSplat, etc.) for initial geometry [S1, unofficial].
*   **When to use:** When high-resolution (4K) novel view synthesis is required from feed-forward inputs (monocular, two-view, multi-view) without per-scene optimization [S1, unofficial].
*   **When not to use:** When per-scene optimization is acceptable and lower resolution is sufficient, or when computational resources for training the dual-network architecture are unavailable [S1, unofficial].
