# On-the-Fly GS Progressive Training

Also called: On-the-Fly Gaussian Splatting

## Overview
On-the-Fly GS Progressive Training is a method for optimizing 3D Gaussian Splatting (3DGS) fields incrementally as new images are acquired, enabling near real-time reconstruction without retraining the entire scene from scratch [S1]. It distinguishes itself from offline training by decoupling the optimization domain temporally, using hierarchical image weighting and adaptive learning rates to balance the stability of existing geometry with the plasticity required to integrate new data [S1]. Unlike [Two-stage Optimization](14857-two-stage-optimization.md) which splits parameters into base and attribute phases, this method splits the training process into sequential phases where the field is continuously updated and refined as the input stream grows [S1].

## How it works
The method operates in three distinct phases: Initial Training, Progressive Training, and Final Optimization [S1].

### Inputs and Outputs
**Inputs:**
*   A stream of images arriving sequentially.
*   Camera poses and sparse point clouds estimated by an On-the-Fly SfM system [S1].
*   Hyperparameters: $N_0$ (initial images), $T_I$ (iterations per new image), $N_m$ (key images), $T_a$ (satisfactory iterations threshold), $\eta^0$ (initial LR), $\eta^f$ (final LR), $\lambda_1, \lambda_{ssim}, \lambda_{load}$ (loss weights) [S1].

**Outputs:**
*   A 3D Gaussian field (set of Gaussians with position, covariance, opacity, and spherical harmonics coefficients) optimized for the accumulated images [S1].

### Data Structures
*   **3DGS Field:** A collection of Gaussian primitives. Each Gaussian contains position $\mathbf{p}$, covariance matrix $\mathbf{\Sigma}$ (or quaternion/scale representation), opacity $\alpha$, and color coefficients [S1].
*   **Sparse Point Cloud:** A set of 3D points $\mathbf{X}$ with associated 2D image coordinates from the SfM system [S1].
*   **Search Tree:** A spatial index (e.g., KD-Tree) built on the existing sparse point cloud to query distances for new points [S1].
*   **Image Overlap Matrix $M$:** $M_{i,j}$ stores the number of matched feature points between image $i$ and image $j$ [S1].
*   **Gaussian Count per Pixel $G_p$:** For each pixel $p$ in a training image, the number of Gaussians splatting onto it [S1].

### Numbered Steps

#### Phase 1: Initial 3DGS Training
1.  Acquire the first $N_0$ images.
2.  Run On-the-Fly SfM to estimate poses and generate a sparse point cloud for these $N_0$ images [S1].
3.  Initialize the 3DGS field using the standard 3DGS training algorithm on these $N_0$ images [S1].
4.  Limit training to a strict iteration count (e.g., 2,000) to prevent overfitting to the small initial subset [S1].

#### Phase 2: Progressive 3DGS Training (per new image $n$)
For each newly acquired image $n$:
1.  **Pose and Cloud Update:** On-the-Fly SfM estimates the pose of image $n$ and performs local Bundle Adjustment (BA) to optimize poses of neighboring images, updating the sparse point cloud [S1].
2.  **New Point Identification:**
    *   Construct a search tree for the existing sparse point cloud [S1].
    *   Query points from the new image against the tree.
    *   Points with a shortest distance to the existing cloud exceeding a predefined threshold are classified as "newly added" [S1].
3.  **Gaussian Initialization:** Initialize these newly added points as new Gaussians and append them to the current 3DGS field [S1].
4.  **Hierarchical Image Weighting:** Calculate weights for training images based on their overlap with the new image $n$ [S1]:
    *   **Layer 1 (New Image):** Weight $\omega_{11} = 1$ [S1].
    *   **Layer 2 (Direct Overlap):** For images $i$ with direct overlap ($M_{i,n} \neq 0$), calculate weight:
        $$ \omega_{2i} = M_{i,n} $$
        where $M_{i,n}$ is the number of matched feature points between image $i$ and new image $n$ [S1].
    *   **Layer $k$ (Indirect Overlap, $k \ge 3$):** For images $i$ in layer $k$, calculate weight based on images in layer $k-1$:
        $$ \omega_{ki} = \frac{\sum_{j=1}^{N_{k-1}} \omega_{j}^{(k-1)} \times M_{j,ki}^{(k-1)}}{N_{k-1}} $$
        where $\omega_{j}^{(k-1)}$ is the weight of image $j$ in layer $k-1$, $M_{j,ki}^{(k-1)}$ is the match count between image $j$ and image $i$, and $N_{k-1}$ is the number of images in layer $k-1$ [S1].
5.  **Training Iteration Allocation:** Perform $T_I$ total iterations. Split into Local and Semi-Global optimization [S1]:
    *   **Local Optimization:** Select the top $N_m$ images with highest weights as key targets. Distribute $T_I/2$ iterations among them. For key image $i$ with weight $\omega_i$, iterations $T_{im}$ are:
        $$ T_{im} = \frac{1 - e^{-\omega_i}}{\sum_{j=1}^{N_m} (1 - e^{-\omega_j})} \times T_I $$
        [S1].
    *   **Semi-Global Optimization:** Distribute the remaining $T_I/2$ iterations evenly among all other registered images [S1].
6.  **Adaptive Learning Rate Update:** For each image $j$ trained for $T_j$ iterations, calculate the base learning rate $\eta_j^c$ [S1]:
    *   Progress $t_i$:
        $$ t_i = \begin{cases} 1 & \text{if } T_j > T_a \\ T_j / T_a & \text{if } T_j \le T_a \end{cases} $$
    *   Base rate:
        $$ \eta_j^c = (\eta_j^0)^{1-t_i} \times (\eta_j^f)^{t_i} $$
        [S1].
    *   Adjusted rate $\eta_j$ considering overlapping images $I$ (where $M_{i,j} > 0$):
        $$ \eta_j = \frac{\eta_j^c + \sum_{i \in I} M_{i,j} \times \eta_i^c}{N_I + 1} $$
        where $N_I$ is the count of overlapping images [S1].
7.  **Loss Calculation and Optimization:**
    *   Calculate Load-Balancing-Loss $L_{load}$ for the current image:
        $$ L_{load} = \text{std}(G_p) $$
        where $G_p$ is the number of Gaussians associated with pixel $p$ [S1].
    *   Total Loss:
        $$ L_{total} = \lambda_1 L_1 + \lambda_{ssim} L_{ssim} + \lambda_{load} L_{load} $$
        [S1].
    *   Perform gradient descent using the adaptive learning rates [S1].
    *   **Splatting-based Parallelism:** Accumulate gradients per Gaussian rather than per pixel to eliminate thread contention and serialized atomic operations [S1].

#### Phase 3: Final Optimization
1.  After all images are acquired, perform global Bundle Adjustment (BA) on all estimated poses [S1].
2.  Apply rapid additional optimization to the current 3DGS field to improve overall rendering quality [S1].

def calculate_hierarchical_weights(new_img_id, M):
    """
    Calculates hierarchical weights for images based on overlap with new_img_id.
    """
    weights = {}
    # Layer 1: New image
    weights[new_img_id] = 1.0
    
    # Layer 2: Direct overlap
    layer_2_imgs = [i for i in M.columns if i != new_img_id and M[i, new_img_id] > 0]
    for i in layer_2_imgs:
        weights[i] = M[i, new_img_id]
        
    # Layer k: Indirect overlap (Iterative)
    # Note: The source describes a recursive definition. 
    # Implementation requires iterating layers until no new images are added.
    current_layer_imgs = layer_2_imgs
    layer_k = 2
    while current_layer_imgs:
        next_layer_imgs = []
        for i in current_layer_imgs:
            # Find neighbors of i that are not yet weighted and not in new_img_id
            neighbors = [j for j in M.columns if M[i, j] > 0 and j not in weights and j != new_img_id]
            next_layer_imgs.extend(neighbors)
            
        # Deduplicate and process
        unique_next = list(set(next_layer_imgs))
        
        for i in unique_next:
            # Find images in previous layer (k-1) that overlap with i
            prev_layer_imgs = [j for j in current_layer_imgs if M[j, i] > 0]
            if prev_layer_imgs:
                N_k_minus_1 = len(prev_layer_imgs)
                sum_weighted_matches = sum(weights[j] * M[j, i] for j in prev_layer_imgs)
                weights[i] = sum_weighted_matches / N_k_minus_1
            else:
                weights[i] = 0 # Or handle appropriately
                
        current_layer_imgs = unique_next
        layer_k += 1
        
    return weights

def calculate_base_lr(Tj, Ta, eta0, etaF):
    """
    Calculates base learning rate based on iterations trained.
    """
    if Tj > Ta:
        ti = 1.0
    else:
        ti = Tj / Ta
        
    # Geometric interpolation: eta0^(1-ti) * etaF^ti
    # Equivalent to exp((1-ti)*ln(eta0) + ti*ln(etaF))
    lr = math.exp((1 - ti) * math.log(eta0) + ti * math.log(etaF))
    return lr

### Parameters
*   $N_0$: Number of initial images. Typical value: 30 [S1].
*   Initial training iterations (Phase 1). Typical value: 2,000 iterations [S1].
*   $T_I$: Total training iterations per new fly-in image. Typical value: 200 [S1].
*   $N_m$: Number of top-weighted key training images. Typical value: 10 [S1].
*   $T_a$: Predefined parameter for satisfactory rendering quality iterations. Typical value: 200 [S1].
*   $\eta^0$: Initial learning rate. Typical value: $1.6 \times 10^{-4}$ [S1].
*   $\eta^f$: Final learning rate. Typical value: $1.6 \times 10^{-6}$ [S1].
*   $\lambda_1$: Weight for $L_1$-Loss. Typical value: 0.47 [S1].
*   $\lambda_{load}$: Weight for Load-Balancing-Loss. Typical value: 0.41 [S1].
*   $\lambda_{ssim}$: Weight for SSIM-Loss. Typical value: 0.12 [S1].

### Edge Cases and Pitfalls
*   **Overfitting in Phase 1:** Training too long on the initial $N_0$ images can cause overfitting to the small subset. A stricter iteration limit is required [S1].
*   **Threshold Selection:** The distance threshold for identifying new points in the sparse cloud must be carefully chosen; too low may miss new geometry, too high may add redundant Gaussians [S1].
*   **Learning Rate Inconsistency:** Using a single global learning rate can cause local quality inconsistencies. The adaptive per-image learning rate is critical for stability [S1].
*   **Thread Contention:** Using per-pixel gradient accumulation leads to serialized atomic operations. Splatting-based parallelism (per-Gaussian accumulation) is necessary for performance [S1].

## Operating characteristics
*   **Time Complexity:** The method is designed for near real-time optimization. Each new image triggers $T_I$ iterations (typically 200) on the current field, rather than retraining the entire scene [S1]. The average iterations per image approach $T_I$ as the scene grows [S1].
*   **Memory Complexity:** The 3DGS field grows incrementally. The load-balancing loss helps reduce the total number of Gaussians by preventing abnormal accumulation in specific regions [S1].
*   **Performance:** Tested on RTX 4090 GPU, the method achieves faster training times compared to offline methods like Adr-Gaussian and Taming-3DGS, and SLAM-based methods like GS-SLAM and RTG-SLAM [S1].
*   **Strengths:** Enables continuous reconstruction from streaming data; reduces training time via incremental updates and parallelism; prevents Gaussian over-accumulation via load-balancing loss [S1].
*   **Limitations:** Requires an On-the-Fly SfM system for pose estimation and sparse cloud generation; quality depends on the accuracy of the SfM updates [S1].

## Background
On-the-Fly GS Progressive Training was proposed in the paper "Gaussian On-the-Fly Splatting: A Progressive Framework for Robust Near Real-Time 3DGS Optimization" [S1]. It builds upon the original 3D Gaussian Splatting method [S1] and integrates concepts from Taming 3DGS regarding gradient accumulation parallelism [S1]. The method addresses the need for efficient, incremental 3D reconstruction from sequential image streams, such as those from SLAM systems or UAVs [S1].
