# Gaussian Splatting Initialization and Parameterization

Also called: SfM Initialization, COLMAP Initialization, Structure from Motion Initialization

## Overview
Gaussian Splatting Initialization and Parameterization constructs the initial set of 3D Gaussian primitives from input data, typically a sparse point cloud generated by Structure from Motion (SfM) or random sampling [S2, S4, unofficial]. It solves the problem of providing geometrically plausible starting positions, orientations, scales, and appearance attributes for the differentiable renderer, avoiding the poor convergence and artifacts associated with purely random initialization [S7, S8, unofficial]. It sets itself apart from sibling methods like [Random Gaussian Generation](14047-random-gaussian-generation.md) by initializing directly from sparse Structure from Motion (SfM) points rather than random coordinates, and from [Random Large-Variance Initialization](6129-random-large-variance-initialization.md) by relying on deterministic feature matching rather than stochastic sampling [S2, S8, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of 2D images, camera poses (extrinsics and intrinsics), and a sparse 3D point cloud with RGB colors (typically from COLMAP) [S2, S8, unofficial]. Alternatively, random coordinates and colors if SfM is unavailable [S2, unofficial].
*   **Output:** A `GaussianList` data structure containing $N$ learnable parameters: positions ($\mathbf{x}$), scales ($\mathbf{s}$), rotations ($\mathbf{q}$), opacities ($\alpha$), and spherical harmonic coefficients ($\mathbf{f}$) [S6, S8, unofficial].

**Data Structures:**
The parameters are stored as PyTorch `nn.Parameter` tensors on the GPU [S6, unofficial]:
*   `_xyz`: Shape $(N, 3)$, float32.
*   `_features_dc`: Shape $(N, 1, 3)$, float32. Stores the zero-order (DC) spherical harmonic coefficients [S9].
*   `_scaling`: Shape $(N, 3)$, float32. Stores the logarithm of the scale factors [S6, unofficial].
*   `_rotation`: Shape $(N, 4)$, float32. Stores quaternions in $[w, x, y, z]$ format [S6, unofficial].
*   `_opacity`: Shape $(N, 1)$, float32. Stores the logit of the opacity.

**Numbered Steps:**

1.  **SfM Reconstruction (if not pre-computed):**
    *   Input 2D images.
    *   Estimate camera intrinsic parameters (focal length, principal point) and extrinsic parameters (rotation $\mathbf{R}_{cam}$, translation $\mathbf{T}_{cam}$) [S2, unofficial].
    *   Match feature points across images and back-project pixels to 3D space using the inverse projection matrix to generate a sparse 3D point cloud with associated RGB colors [S2, unofficial].
    *   *Note:* Using dense Multi-View Stereo (MVS) clouds is discouraged for standard initialization as it wastes time and bakes in MVS errors as starting bias; sparse SfM is sufficient because the optimizer creates detail during training [S8, unofficial].

2.  **Position Initialization:**
    *   Copy the 3D coordinates $(X, Y, Z)$ from the SfM point cloud directly to the `_xyz` tensor [S1, S8, unofficial].

3.  **Scale Initialization:**
    *   Compute the distance to the $k$-nearest neighbors (KNN) for each point [S4, unofficial].
    *   Calculate the scale parameter as the logarithm of the distance [S6, unofficial].
    *   *Method A (Fixed Base):* Use a base distance $d_{base} = 0.1$ [S6, unofficial]. Compute $dist2 = \text{clamp}(d_{base}, \min=10^{-7})$. Set $\mathbf{s} = \log(\sqrt{dist2})$ repeated for x, y, z dimensions [S6, unofficial].
    *   *Method B (KNN):* Compute mean distance to $k$ nearest neighbors [S4, unofficial]. Apply log. Set $\mathbf{s} = \log(\text{mean\_dist})$ [S4, unofficial].
    *   *Method C (Isotropic Flag):* If `isotropic` is true, replicate the single scale value across all three dimensions [S4, unofficial].

4.  **Rotation Initialization:**
    *   Set all quaternions to the identity rotation $[1, 0, 0, 0]$ [S4, S6, S8, unofficial].
    *   *Alternative (Normal-based):* If surface normals are available (e.g., from depth maps), compute the quaternion that aligns the local z-axis with the estimated surface normal [S3, unofficial].

5.  **Opacity Initialization:**
    *   Initialize the logit parameter `_opacity` to a value that yields a sigmoid output close to, but less than, 1.0 [S4, unofficial].
    *   *Method A:* Set pre-activation value to 8.0. $\sigma(8.0) \approx 0.9997$ [S4, unofficial].
    *   *Method B:* Set target opacity to 0.1 or 0.5 [S1, unofficial]. Compute logit: $\text{logit}(p) = \log(p / (1-p))$ [G]. Clamp the resulting logit to $[10^{-4}, 0.99]$ to prevent extreme values [S6, unofficial].

6.  **Color (Spherical Harmonics) Initialization:**
    *   Normalize the SfM point's RGB color to the range $[-0.5, 0.5]$ [S1, unofficial].
    *   Compute the DC coefficient $\mathbf{f}_{dc}$ by dividing the normalized RGB by the SH basis constant $C_0 = 0.28209479177387814$ [S1, S4, unofficial].
    *   Initialize all higher-order AC coefficients (`_features_rest`) to zero [S1, S8, unofficial][S9].

7.  **Covariance Construction (Runtime/Forward Pass):**
    *   Construct the diagonal scaling matrix $\mathbf{S}$ from `_scaling`:
        $$ \mathbf{S} = \begin{bmatrix} e^{s_x} & 0 & 0 \\ 0 & e^{s_y} & 0 \\ 0 & 0 & e^{s_z} \end{bmatrix} $$
    *   Normalize the quaternion $\mathbf{q}$ to unit length and convert to a rotation matrix $\mathbf{R}$ [S6, unofficial].
    *   Compute the 3D covariance matrix $\Sigma$:
        $$ \Sigma = \mathbf{R} \mathbf{S} \mathbf{S}^T \mathbf{R}^T $$
    *   *Note:* This split into scale and rotation ensures $\Sigma$ remains positive semi-definite during optimization [S8, unofficial].

8.  **2D Projection Covariance (Runtime/Forward Pass):**
    *   Transform 3D positions to camera coordinates: $\mathbf{x}_{cam} = \mathbf{R}_{cam} \mathbf{x} + \mathbf{T}_{cam}$ [S6, unofficial].
    *   Compute the Jacobian $\mathbf{J}$ of the perspective projection [S6, unofficial]. With focal length $f$ and depth $z$ (clamped with $10^{-7}$ to prevent division by zero):
        $$ \mathbf{J} = \begin{bmatrix} f/z & 0 & -fx/z^2 \\ 0 & f/z & -fy/z^2 \end{bmatrix} $$
    *   Compute the 2D covariance $\Sigma'$:
        $$ \Sigma' = \mathbf{J} \mathbf{W} \Sigma \mathbf{W}^T \mathbf{J}^T $$
        where $\mathbf{W}$ is the world-to-camera rotation matrix [S6, unofficial].
    *   Add a numerical stability bias of 0.3 to the diagonal elements $\Sigma'_{0,0}$ and $\Sigma'_{1,1}$ [S6, unofficial].

**Pseudocode:**

```python
import torch
import numpy as np

SH_C0 = 0.28209479177387814
BASE_DISTANCE = 0.1
NUM_NEIGHBORS = 50
OPACITY_LOGIT_INIT = 8.0

def initialize_gaussians(sfm_points_xyz, sfm_points_rgb, use_knn=True):
    """
    Initialize Gaussian parameters from SfM data.
    
    Args:
        sfm_points_xyz: Tensor of shape (N, 3)
        sfm_points_rgb: Tensor of shape (N, 3), values in [0, 1]
        use_knn: Boolean flag to choose between KNN (default) or fixed base scaling.
        
    Returns:
        Dictionary of initialized parameters
    """
    N = sfm_points_xyz.shape[0]
    device = sfm_points_xyz.device
    
    # 1. Positions
    xyz = sfm_points_xyz.clone()
    
    # 2. Scales
    if use_knn:
        # Compute pairwise distances
        dists = torch.cdist(sfm_points_xyz, sfm_points_xyz)
        # Exclude self-distance by setting diagonal to infinity
        dists = dists + torch.eye(N, device=device) * 1e9
        # Get distances to k nearest neighbors
        knn_dists, _ = torch.topk(dists, k=NUM_NEIGHBORS, largest=False, dim=1)
        mean_knn_dist = torch.mean(knn_dists, dim=1, keepdim=True)
        scaling = torch.log(mean_knn_dist)
    else:
        # Fixed base distance method [S6, unofficial]
        dist2 = torch.clamp(torch.full((N, 1), BASE_DISTANCE, device=device), min=1e-7)
        scaling = torch.log(torch.sqrt(dist2)).repeat(1, 3)
        
    # 3. Rotations (Identity)
    rotation = torch.zeros(N, 4, device=device)
    rotation[:, 0] = 1.0  # w=1, x=y=z=0
    
    # 4. Opacity (Logit)
    opacity = torch.full((N, 1), OPACITY_LOGIT_INIT, device=device)
    
    # 5. Colors (SH DC)
    rgb_norm = sfm_points_rgb - 0.5  # Normalize to [-0.5, 0.5]
    features_dc = (rgb_norm / SH_C0).unsqueeze(1)  # Shape (N, 1, 3)
    features_rest = torch.zeros(N, 12, 3, device=device)  # Degree 1 SH AC coefficients
    
    return {
        '_xyz': xyz,
        '_scaling': scaling,
        '_rotation': rotation,
        '_opacity': opacity,
        '_features_dc': features_dc,
        '_features_rest': features_rest
    }

def compute_covariance(scaling, rotation):
    """
    Compute 3D covariance matrix from scale and rotation parameters.
    """
    scales = torch.exp(scaling)
    S = torch.zeros(scaling.shape[0], 3, 3, device=scaling.device)
    S[:, 0, 0] = scales[:, 0]
    S[:, 1, 1] = scales[:, 1]
    S[:, 2, 2] = scales[:, 2]
    
    q_norm = torch.nn.functional.normalize(rotation, p=2, dim=1)
    w, x, y, z = q_norm[:, 0], q_norm[:, 1], q_norm[:, 2], q_norm[:, 3]
    R = torch.stack([
        1 - 2*(y**2 + z**2), 2*(x*y - w*z), 2*(x*z + w*y),
        2*(x*y + w*z), 1 - 2*(x**2 + z**2), 2*(y*z - w*x),
        2*(x*z - w*y), 2*(y*z + w*x), 1 - 2*(x**2 + y**2)
    ], dim=1).reshape(-1, 3, 3)
    
    Sigma = R @ (S * S) @ R.transpose(1, 2)
    return Sigma
```

**Parameters:**
*   $C_0$: SH basis constant, $0.28209479177387814$ [S1, S4, unofficial].
*   Base Distance: $0.1$ (used in fixed-scale initialization) [S6, unofficial].
*   Opacity Pre-activation: $8.0$ (yields $\sigma \approx 0.9997$) [S4, unofficial].
*   Numerical Stability Bias: $0.3$ added to 2D covariance diagonal [S6, unofficial].
*   Max Scaling: $10.0$ (clamped after exponential transformation) [S6, unofficial].
*   Learning Rates (Adam): Means: $0.00016$, Scales: $0.005$, Quats: $0.001$, Features DC: $0.0025$, Features Rest: $0.000125$, Opacities: $0.05$ [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Division by Zero:** In Jacobian computation, depth $z$ must be clamped with $10^{-7}$ [S6, unofficial].
*   **Singular Covariance:** Adding $0.3$ to the diagonal of the 2D covariance matrix prevents singular matrices during projection [S6, unofficial].
*   **Invalid Rotations:** Quaternions must be normalized to unit length before converting to rotation matrices [S6, unofficial].
*   **Excessive Scale:** Scaling values are clamped to a maximum of $10.0$ after exponential transformation to prevent excessively large Gaussians [S6, unofficial].
*   **MVS Bias:** Using dense MVS clouds for initialization is discouraged as it wastes time and bakes in MVS errors as starting bias [S8, unofficial].

## Subtopics

### [Random Large-Variance Initialization](6129-random-large-variance-initialization.md)
Random Large-Variance Initialization is a method for initializing 3D Gaussian primitives that relaxes the assumption of using only Structure-from-Motion (SfM) point cloud data. It addresses the problem of generating a geometrically plausible starting configuration when SfM data is sparse or absent by sampling Gaussians randomly with large variance. It sets itself apart from [SfM-Based Triangle Initialization](9766-sfm-based-triangle-initialization.md) by relying on stochastic sampling rather than deterministic SfM-derived positions and local density scaling.

### [Temporal Point Cloud Initialization via Chamfer Distance Minimization](6954-temporal-point-cloud-initialization-via-chamfer-distance-min.md)
This method reduces training time for dynamic video scenes by initializing the point cloud of the current frame using the learned model from the previous frame, leveraging temporal correlation between nearby frames. It sets itself apart from static initialization methods by explicitly optimizing geometric alignment between consecutive frames via Chamfer distance minimization before refining radiance parameters.

### [Gaussian Geometry Parameters Prediction](8442-gaussian-geometry-parameters-prediction.md)
Gaussian Geometry Parameters Prediction is a method for initializing and refining the geometric attributes of 3D Gaussian primitives in a feed-forward manner, typically using a global volumetric representation rather than per-pixel alignment. It solves the problem of redundant, inconsistent, and ghosting artifacts that arise when accumulating locally predicted Gaussians from multiple views. Unlike sibling methods that rely on per-scene optimization or local cost volumes, this approach predicts a unified global scene representation by refining noisy depth-initialized points in 3D space, thereby improving global consistency and reducing floating artifacts.

### [Background Hemisphere Initialization](8446-background-hemisphere-initialization.md)
Background Hemisphere Initialization is a technique for handling unbounded scenes in 3D Gaussian Splatting by modeling the distant background as a separate, fixed-radius hemisphere of Gaussians. It solves the problem of representing distant regions (hundreds of meters away) that would otherwise require foreground Gaussians to extend to infinity, which degrades novel view synthesis quality. It sets itself apart from standard background models by explicitly disentangling the sky from the foreground geometry using a moving hemisphere that maintains a fixed relative distance to the target camera.

### [ReSplat Initialization](10957-resplat-initialization.md)
ReSplat Initialization predicts an initial set of 3D Gaussians from a sparse point cloud by aggregating local and global 3D context to compensate for information loss incurred by downsampling the input point cloud by 16x. Unlike naive prediction methods that directly map point features to Gaussian parameters, this method uses a transformer-based encoder to enrich features with neighborhood context before decoding. It sets the stage for the subsequent Recurrent Gaussian Update by providing a structured initial state $\mathcal{G}^0$.

### [Point Cloud/Mesh-based Initialization](16343-point-cloud-mesh-based-initialization.md)
This family of methods initializes 3D Gaussian Splatting (3DGS) primitives using pre-existing 3D geometry (point clouds or meshes) rather than relying solely on sparse Structure-from-Motion (SfM) outputs [G]. It solves the problem of initializing high-quality radiance fields when multi-view images are unavailable or when the user possesses dense, surface-aligned volumetric data (e.g., MPEG plenoptic point clouds or meshes) [16108-3dgs-custom-initialization-from-point-cloud-mesh.md]. It differs from [Random Large-Variance Initialization](6129-random-large-variance-initialization.md) by anchoring Gaussians to observed geometry, and from [Gaussian Model Initialization](2349-gaussian-model-initialization.md) by supporting dense mesh inputs and optional fixed-position constraints [16108-3dgs-custom-initialization-from-point-cloud-mesh.md].

### [Cone Scatter Initialization](21774-cone-scatter-initialization.md)
Cone Scatter Initialization (CSI) is a technique for 3D Gaussian Splatting that enriches sparse point clouds (typically from COLMAP) by scattering new points within a predefined viewing frustum, specifically to address depth coverage issues in low-light or nighttime scenes where COLMAP fails to produce high-quality distant points. Unlike standard initialization which relies solely on existing sparse matches, CSI ensures Gaussians form at correct, deeper depths, preventing the generation of structures at incorrect depths and lack of fine details.

### Neural Point Cloud Initialization from COLMAP
A method to initialize the neural point cloud and their features for Point-NeRF using an external point cloud reconstruction (specifically COLMAP) [S10]. It solves the problem of how to provide initial positions, variances, and feature vectors for the neural points [S10]. The variance parameter $\gamma_i$ for each point $p_i$ is initialized to 0.3 [S10]. To acquire the feature vector $f_i$ for a point $p_i$, views where the point is occluded are ruled out, and the view where the camera is closest to the point is selected [S10]. The point is unprojected onto the feature maps extracted by the Image Feature Extraction 2D CNN (Gf) from the selected closest view to obtain $f_i$ [S10]. During optimization, the confidence score of valid points is pushed to 1 [S10].

### Binary Gaussian Hierarchy Construction
The hierarchy is a binary tree. Leaf nodes contain the full set of optimized Gaussian properties (base color, SH coefficients, position, covariance) [S11, unofficial]. Internal nodes store merged approximations of their two child nodes [S11, unofficial].

### Single Ellipsoid Initialization
Initializes a single ellipsoid from a set of 3D points using Principal Component Analysis (PCA) to determine orientation, center, and radii [S12]. The minimum allowed radius $r_{\min}$ is typically 0.005 to avoid numerical problems [S12]. A scaling factor $\alpha$ (typically 3) is used to ensure points are mostly covered [S12].

### MVS-guided Initialization
Aggregates filtered multiview depth maps from an MVS method into a unified 3D point cloud. An initial optimization phase prunes noisy Gaussians by freezing Gaussian centers and optimizing other parameters for $N_{prun}$ iterations, removing Gaussians with opacity $\alpha_k < \tau$. Afterward, all parameters are unfrozen for standard optimization with Adaptive Density Control [S13].

### Feature Initialization
Initializes the base feature $f_{base}$ and directional feature $f_{dir}$ with the RGB color values of the corresponding SfM points. The temporal feature $f_{time}$ is initialized as a zero vector [S14].

### MVS Reference Geometry Generation
The MVS point cloud is generated in the same coordinate system as the SfM reconstruction used to initialize 3DGS, allowing direct comparison with Gaussian centers. A dense MVS point cloud is generated from the wall image sequence using COLMAP, and a uniform scale factor is applied to both the MVS point cloud and the Gaussian centers [S15].

### 3DGR-CT Initialization
Initializes each image volume with 50,000 Gaussians. The background threshold is 0.05, and the intensity initialization coefficient $c_i$ is 0.15. This initialization yields performance comparable to fitting Gaussians to an FBP-reconstructed image but avoids extra computational overhead [S16].

## Operating characteristics
*   **Time Complexity:** SfM initialization is significantly slower than random initialization due to the feature matching and triangulation steps. COLMAP initialization takes approximately 6 minutes compared to 0.1 seconds for random initialization [S5, unofficial].
*   **Memory Complexity:** Linear in the number of points $N$. The SfM point cloud size varies by scene but is typically sparse (e.g., 150,000 points for large scenes) [S2, unofficial].
*   **Performance:** SfM initialization yields higher quality results. On the Average-30K dataset, SfM initialization achieves a PSNR of 26.05, while random initialization drops to 20.42 [S7, unofficial]. In other benchmarks, COLMAP initialization achieves 35.201 PSNR, while random initialization yields 6.023 PSNR [S5, unofficial].
*   **Strengths:** Provides geometrically accurate starting points, improving overall reconstruction quality and convergence speed [S7, S8, unofficial].
*   **Limitations:** Requires a successful SfM reconstruction; fails if image coverage is too thin or if there are insufficient feature matches [S8, unofficial]. Random initialization is faster but results in poorer background quality and lower PSNR [S7, unofficial].
*   **When to Use:** Use SfM initialization when 2D images are available and sufficient feature matches can be found. Use random initialization only when camera poses are known (e.g., synthetic datasets) or SfM fails [S2, unofficial].

## Background
The method originates from the original 3D Gaussian Splatting paper, which proposed initializing Gaussians from sparse Structure from Motion (SfM) points [S8, unofficial]. SfM is a well-established computer vision technique used to reconstruct 3D structure and camera poses from 2D images [S2, unofficial]. The use of COLMAP, a goto implementation for SfM, is standard in the community [S2, S8, unofficial]. The approach was shown to be superior to random initialization, which was previously used in some NeRF variants but led to slower convergence and lower quality [S7, S8, unofficial].
