# SWAG (Splatting in the Wild images with Appearance-conditioned Gaussians)

## Overview
SWAG is an extension of 3D Gaussian Splatting (3DGS) designed to reconstruct 3D scenes from unstructured, in-the-wild image collections that exhibit significant photometric variations and contain transient occluders (e.g., tourists, clouds) [S1]. It distinguishes itself from standard 3DGS and its siblings by explicitly modeling appearance variations through image-dependent color conditioning and handling transient objects via adaptive opacity modulation, thereby disentangling static scene geometry from dynamic elements without supervision [S1]. Unlike [DAVIGS](12021-davigs.md) or [Compact View-dependent Color](12904-compact-view-dependent-color.md) which focus primarily on view-dependent shading, SWAG conditions appearance on a per-image latent embedding to handle lighting changes across different capture times, while simultaneously learning to identify and isolate transient Gaussians [S1].

## How it works
SWAG adapts the 3DGS representation by adding learnable parameters to each Gaussian and introducing a conditioning mechanism based on the input image. The method optimizes the scene representation to support both appearance interpolation and transient object removal.

### Inputs and Outputs
*   **Inputs:** A set of unstructured images $I_k$ with known camera poses, and an initial sparse point cloud from Structure-from-Motion (SfM) [S1].
*   **Outputs:** A set of 3D Gaussians representing the static scene, a set of Gaussians representing transient objects, and a latent appearance space allowing for novel appearance synthesis [S1].

### Numbered Steps

1.  **Initialization:** Initialize 3D Gaussians using the sparse SfM points. Each Gaussian has base parameters $\mathbf{x}, \mathbf{S}, \mathbf{R}, \alpha, \mathbf{c}$ [S1].
2.  **Encoding:** For each Gaussian $g$ and each training image $I_k$:
    *   Compute the position encoding $\text{emb}(\mathbf{x}_g)$ using the Hash Grid [S1].
    *   Retrieve the per-image embedding $\mathbf{l}_{I_k}$ [S1].
3.  **Appearance and Opacity Conditioning:**
    *   Pass the base color $\mathbf{c}_g$, the image embedding $\mathbf{l}_{I_k}$, and the position encoding $\text{emb}(\mathbf{x}_g)$ into the MLP $F_\theta$ [S1].
    *   The MLP outputs an image-dependent color variation $c_I$ and an image-dependent opacity variation parameter $\Delta \alpha_I$ [S1].
4.  **Opacity Modulation (Concrete Distribution):**
    *   The parameter $\Delta \alpha_I$ serves as the location variable for a concrete distribution (likely a Gumbel-Softmax or similar reparameterization trick for discrete-like selection, though the text calls it a "concrete distribution") [S1].
    *   Sample from this distribution to obtain the opacity variation $\tilde{\Delta \alpha}_I$ [S1].
    *   The final opacity for the Gaussian in image $I_k$ is modulated by $\tilde{\Delta \alpha}_I$ [S1].
5.  **Rendering:**
    *   Render the image using standard 3DGS splatting, but with the conditioned color $\mathbf{c}' = \mathbf{c} + c_I$ (or similar combination) and the modulated opacity [S1].
6.  **Optimization:**
    *   Minimize the reconstruction loss between the rendered image and the ground truth image $I_k$ [S1].
    *   Optimize $\mathbf{x}, \mathbf{S}, \mathbf{R}, \alpha, \mathbf{c}$, $\text{emb}(\mathbf{x})$, $\mathbf{l}_{I_k}$, and MLP weights $\theta$ [S1].
    *   Use 3DGS densification every 2000 iterations, ending at iteration 30,000 [S1].

### Edge Cases and Pitfalls
*   **Transient Object Holes:** In areas with frequent transient objects (e.g., clouds, tourists), the method may detect static parts as transient. Eliminating all transient Gaussians (those with high variance in $\tilde{\Delta \alpha}_I$) can leave black spots/holes in the scene [S1].
*   **Mitigation:** To solve holes, Gaussians can be removed based on an adaptive threshold $\lambda$ rather than requiring zero variance ($\text{Var}(\tilde{\Delta \alpha}_I) < \lambda$). This requires manual tuning of $\lambda$ [S1].
*   **Transient Percentage:** On average, less than 20% of Gaussians capture transient objects, ensuring the static scene is reconstructed without the blurry elongated Gaussians typical of view-dependent 3DGS [S1].

## Operating characteristics
*   **Training Time:** Almost doubles compared to standard 3DGS [S1]. However, it is orders of magnitude faster than previous in-the-wild NeRF-based baselines [S1].
*   **Inference Time:** 10 times longer per frame than standard 3DGS due to the MLP and Hash Grid lookups [S1].
*   **Memory:** Increased memory usage due to the storage of Hash Grids, Image Embeddings, and MLP weights [S1].
*   **Strengths:** Handles unstructured in-the-wild data; disentangles static and dynamic elements; enables controllable appearance via interpolation of image embeddings [S1].
*   **Limitations:** Slower inference than 3DGS; requires manual tuning of threshold $\lambda$ for transient removal to avoid holes; sensitive to the percentage of transient Gaussians [S1].
*   **When to Use:** When reconstructing scenes from unstructured internet photo collections with significant lighting changes and transient occluders [S1].
*   **When Not to Use:** When real-time performance comparable to standard 3DGS is required, or when the scene is static and well-structured [S1].

## Background
SWAG was proposed by H. Dahmani et al. in 2024 [S1]. It builds upon the 3D Gaussian Splatting framework [S1]. The method was evaluated on the Phototourism Dataset (Brandenburg Gate, Sacré Cœur, Trevi Fountain) and the NeRF-OSR Dataset [S1]. It addresses the limitations of 3DGS in unstructured scenarios, where view-dependent SH coefficients often lead to blurry artifacts and floaters caused by transient objects [S1].
