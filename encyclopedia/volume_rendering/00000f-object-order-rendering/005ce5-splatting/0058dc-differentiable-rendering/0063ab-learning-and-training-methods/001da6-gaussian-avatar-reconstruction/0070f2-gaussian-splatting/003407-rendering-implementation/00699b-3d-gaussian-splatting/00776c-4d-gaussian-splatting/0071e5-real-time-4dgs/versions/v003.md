# Real-time 4DGS

Also called: RealTime4DGS

## Overview
Real-time 4DGS achieves interactive frame rates by building a specialized renderer that fuses static background Gaussians with a small, fast-updating set of dynamic foreground Gaussians [S1, unofficial]. It distinguishes itself from general 4D Gaussian Splatting by being the first to reformulate 3D-GS into 4D-GS, treating the time dimension equally with spatial dimensions [S2, unofficial].

## How it works
**Inputs:** A set of 4D Gaussians representing the scene, where each Gaussian is defined in 4D space-time [S2, unofficial].
**Outputs:** A rendered image frame for a specific timestamp $t$ [G].

**Data Structures:**
The method separates Gaussians into two sets:
1.  **Static Background Gaussians:** Stored in a standard 3D-GS tile-based rasterization structure [S1, unofficial].
2.  **Dynamic Foreground Gaussians:** A smaller set of Gaussians that are updated frequently [S1, unofficial].

**Method Steps:**
1.  **Reformulation:** The method reformulates 3D-GS into 4D-GS, representing each Gaussian with a 4D scaling matrix and a pair of isotropic rotations to define 4D rotation [S2, unofficial].
2.  **Time Conditioning:** The 4D Gaussians are conditioned on time $t$ multiplied by the marginal distribution to render the dynamic scene [S2, unofficial].
3.  **Sampling:** At the current rendering timestamp $t$, the 4D Gaussians are sampled into 3D Gaussians [S2, unofficial].
4.  **Rendering:** The sampled 3D Gaussians from both the static background and the projected dynamic foreground are rasterized using the tile-based approach to produce the final image [S2, unofficial].

**Pseudocode:**
```python
def render_realtime_4dgs(static_gaussians, dynamic_4d_gaussians, timestamp):
    # Step 1: Sample dynamic 4D Gaussians into 3D Gaussians at the current timestamp
    # [G] Project 4D primitives to 3D spatial slice at time t using 4D scaling and rotation
    dynamic_3d_gaussians = []
    for g in dynamic_4d_gaussians:
        mean_3d = g.mean[:3]
        cov_3d = evaluate_4d_gaussian_slice(g, timestamp)
        dynamic_3d_gaussians.append({'mean': mean_3d, 'cov': cov_3d, 'color': g.color, 'opacity': g.opacity})
    
    # Step 2: Combine static and dynamic sets
    all_gaussians = static_gaussians + dynamic_3d_gaussians
    
    # Step 3: Rasterize using the tile-based approach
    # [G] Standard tile-based rasterization: tile culling, depth sorting, alpha blending
    image = zeros_like(target_resolution)
    for tile in tiles:
        tile_gaussians = [g for g in all_gaussians if g.bounds_overlap_tile(tile)]
        tile_gaussians.sort(key=lambda g: g.depth)
        for pixel in tile.pixels:
            color = zeros(3)
            alpha = 0.0
            for g in tile_gaussians:
                contribution = g.opacity * gaussian_pdf(pixel, g.mean, g.cov)
                color += contribution * g.color
                alpha += contribution
            image[tile.y:tile.y+tile.height, tile.x:tile.x+tile.width] += color
    return image
```

**Parameters:**
*   **Timestamp:** The specific time instance for which the frame is rendered [S2, unofficial].
*   **Update Frequency:** The rate at which dynamic foreground Gaussians are updated [G].

## Operating characteristics
*   **Time Complexity:** Interactive frame rates are achieved by limiting expensive 4D-to-3D sampling and updates to a small set of dynamic foreground Gaussians, while leveraging the optimized tile-based rasterizer for the static background [S1, unofficial].
*   **Memory Complexity:** Not given in the sources [S2, unofficial].
*   **Strengths:** High rendering speed (interactive); effective separation of static and dynamic content; leverages mature 3D-GS rasterization infrastructure [S1, unofficial].
*   **Limitations:** Not given in the sources [S2, unofficial].
*   **When to use:** Real-time applications requiring dynamic scenes with a dominant static background [S1, unofficial].
*   **When not to use:** Not given in the sources [S2, unofficial].

## Background
Real-time 4DGS is cited as the first method to reformulate 3D-GS into 4D-GS by treating time and space dimensions equally [S2, unofficial]. It was developed to address the computational bottleneck of rendering dynamic scenes in Gaussian Splatting by introducing a specialized renderer that fuses static and dynamic components [S1, unofficial].
