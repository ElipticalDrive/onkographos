# Self-Organizing Gaussian Grids

Also called: Self-Organizing Gaussians

## Overview
Self-Organizing Gaussian Grids is a compact 3D scene representation that organizes the high-dimensional parameters of 3D Gaussian Splatting into a 2D grid with local homogeneity to reduce storage size without compromising visual quality [S1]. It exploits perceptual redundancies in natural scenes, where numerous permutations of Gaussian parameters can equivalently represent the same scene [S1]. Unlike fixed-ordering methods such as Z-order curves or tri-planes, this representation is learned per scene via unsupervised competitive learning, allowing neighbors in all dimensions to be modeled effectively [S2].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $N$ 3D Gaussians $\mathcal{G} = \{g_1, \dots, g_N\}$, where each Gaussian $g_i$ contains position $\mathbf{t}_i \in \mathbb{R}^3$, covariance $\mathbf{\Sigma}_i \in \mathbb{R}^{3 \times 3}$ (or quaternion $\mathbf{q}_i$ and scale $\mathbf{s}_i$), opacity $\alpha_i \in \mathbb{R}$, and spherical harmonics coefficients $\mathbf{c}_{i,k} \in \mathbb{R}^d$ for $k$ bands [S1].
*   **Output:** A 2D grid of size $H \times W$ containing the reorganized Gaussian parameters, along with the learned mapping (indices) that defines the spatial arrangement [S1, S2].

**Data Structures:**
The method organizes attributes into multiple data layers that share a consistent 2D layout [S2]. Each layer corresponds to a specific attribute type (e.g., position, scale, color). The uncompressed Gaussians use the same structure as standard 3DGS, ensuring seamless integration with established renderers [S1]. The grid dimensions $H \times W$ are chosen such that $H \times W \approx N$ or a compressed subset thereof, though the sources do not specify the exact compression ratio formula for grid dimensions, only the resulting storage reduction [S1].

**Algorithm Steps:**
1.  **Initialization:** Initialize a 2D grid of size $H \times W$ with random or randomly sampled Gaussian parameters from the input set $\mathcal{G}$ [S2].
2.  **Self-Organization (Competitive Learning):** Optimize the 2D representation for each scene using an unsupervised learning model based on Self-Organizing Maps (SOM) [S2]. This involves competitive learning where grid nodes compete to represent input Gaussians, preserving topological relationships [S2].
    *   For each input Gaussian $g_i$, find the best matching unit (BMU) in the grid: $b = \arg\min_{j} \| \mathbf{p}_j - \mathbf{p}_i \|$, where $\mathbf{p}$ represents the concatenated high-dimensional parameter vector [S2].
    *   Update the BMU and its neighbors in the grid to be more similar to $g_i$. The update rule follows standard SOM dynamics:
        $$ \mathbf{p}_j(t+1) = \mathbf{p}_j(t) + \eta(t) h_{bj}(t) (\mathbf{p}_i - \mathbf{p}_j(t)) $$
        where $\eta(t)$ is the learning rate and $h_{bj}(t)$ is the neighborhood function (typically Gaussian) centered at the BMU $b$ [S2].
3.  **Smoothness Enforcement:** During training, enforce local smoothness between the sorted parameters in the grid via a smoothness loss [S1]. This loss penalizes large differences between adjacent grid cells, exploiting the local homogeneity of natural scenes [S1].
    $$ \mathcal{L}_{smooth} = \sum_{i,j} \| \mathbf{p}_{i,j} - \mathbf{p}_{neighbor(i,j)} \|^2 $$
    where $\mathbf{p}_{i,j}$ is the parameter vector at grid cell $(i,j)$ [S1].
4.  **Finalization:** The final grid contains the optimized Gaussian parameters. The mapping from grid indices to original Gaussian attributes is stored [S2].

**Parameters:**
*   Grid dimensions $H, W$: Not given in the sources.
*   Learning rate $\eta(t)$: Not given in the sources.
*   Neighborhood radius: Not given in the sources.
*   Storage reduction factor: 17x to 42x for complex scenes [S1].

**Edge Cases and Pitfalls:**
*   Encoding requires a computationally expensive optimization to determine element order [S2].
*   The method relies on the assumption of local homogeneity; scenes with high-frequency, non-local variations may not compress as effectively [S1].

## Operating characteristics
*   **Time Complexity:** Encoding is computationally expensive due to the optimization process required to determine the element order [S2]. Rendering time is not significantly increased compared to standard 3DGS, as the uncompressed structure is used during rendering [S1].
*   **Memory Complexity:** Storage size is reduced by a factor of 17x to 42x for complex scenes [S1].
*   **Strengths:** Maintains fast rendering and high quality while drastically reducing storage [S1]. Exploits perceptual redundancies effectively [S1].
*   **Limitations:** High encoding complexity [S2].
*   **When to use:** When storage size is a critical constraint (e.g., resource-constrained devices) and encoding time is not a bottleneck [S1].
*   **When not to use:** When real-time encoding is required or when the scene lacks local homogeneity [S1, S2].

## Background
Self-Organizing Gaussian Grids was introduced by Wieland Morgenstern, Florian Barthel, Anna Hilsmann, and Peter Eisert from Fraunhofer Heinrich Hertz Institute and Humboldt University of Berlin [S1]. The method is based on the concept of Self-Organizing Maps (SOM), an unsupervised learning model that projects high-dimensional data onto a lower-dimensional grid, preserving topological relationships between data points through competitive learning [S2]. It was proposed to address the high storage requirements of 3D Gaussian Splatting, which hinders practical deployment on resource-constrained devices [S1]. The method was published in arXiv:2312.13299v2 on May 2, 2024 [S1].
