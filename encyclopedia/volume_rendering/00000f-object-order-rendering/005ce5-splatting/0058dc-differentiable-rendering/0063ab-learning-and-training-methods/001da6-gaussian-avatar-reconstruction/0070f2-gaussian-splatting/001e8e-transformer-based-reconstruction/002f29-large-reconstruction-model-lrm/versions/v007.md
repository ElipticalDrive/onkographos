# Large Reconstruction Model (LRM)

## Overview
Large Reconstruction Model (LRM) is a feedforward neural network that performs single-image or multi-view to 3D reconstruction by predicting a triplane neural representation in a single transformer forward pass [S1, unofficial][S2]. It solves the problem of per-scene optimization latency by learning 3D priors from large-scale datasets, enabling real-time reconstruction [S1, unofficial][S2]. It sets itself apart from its siblings by outputting a continuous triplane field rather than discrete primitives (like [GS-LRM](1483-gs-lrm.md)) or meshes directly, serving as the foundational architecture for subsequent variants [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A single image $I$ or a viewset $V = \{I_i\}_{i=1}^N$ with corresponding camera parameters $\{\pi_i\}_{i=1}^N$ [S2].
*   **Output:** A triplane neural representation $\theta$ [S2]. This representation is subsequently rendered to produce novel view images $\hat{I}$ [S2].

**Data Structures:**
The core data structure is the **triplane**, a 3D representation composed of three 2D feature planes oriented along the XY, YZ, and XZ axes [S2]. The model $\Phi$ outputs parameters $\theta$ defining this triplane [S2].

**Algorithm Steps:**
1.  **Feature Extraction:** Extract a pixel-wise feature map $\mathbf{v} = \psi(I_i)$ from each input image $I_i$ using a vision encoder $\psi$ [S2].
2.  **Lifting (Splatter):** Lift the 2D feature maps into an initial 3D representation $\tilde{\theta}$ using a "Splatter" layer [S2]. The Splatter layer projects the source view features into a new triplane, taking previous transformer block outputs as prior shape encoding [S2].
3.  **Transformer Processing:** Input $\tilde{\theta}$ into the large-scale model $\Phi$ to output the final 3D representations $\theta = \Phi_\theta(\tilde{\theta})$ [S2].
    *   The model consists of a series of transformer blocks [S2].
    *   The Splatter layer is inserted every 3 transformer blocks (resulting in 5 blocks total in the described configuration) [S2].
4.  **Rendering:** Output novel view images $\hat{I} = R(\theta, \pi)$ from $\theta$ using a differentiable Renderer $R$ [S2].
5.  **Training:** Train the model by minimizing a loss $L$ between the rendered novel view image $\hat{I}$ and the corresponding ground truth image $I$ [S2].

**Pseudocode:**
```python
def LRM_forward(input_images, camera_params):
    # 1. Extract features
    features = []
    for img in input_images:
        v = VisionEncoder(img) # psi(I_i)
        features.append(v)
    
    # 2. Initial Lifting (Splatter)
    # Lifts 2D features into a triplane representation
    theta_tilde = Splatter(features, camera_params)
    
    # 3. Transformer Blocks with Interleaved Splatter
    # Total 5 blocks, Splatter inserted every 3 blocks
    theta = theta_tilde
    for i in range(5):
        theta = TransformerBlock(theta)
        if (i + 1) % 3 == 0:
            # Insert Splatter layer using previous output as prior
            theta = Splatter(features, theta)
            
    # 4. Final Output
    return theta

def LRM_render(triplane_params, camera_params):
    # Render novel views from the triplane
    return Renderer(triplane_params, camera_params)
```

**Parameters and Training:**
*   **Dataset:** Trained on Objaverse and Objaverse-XL [S1, unofficial].
*   **Loss:** The model is trained using image-level losses [S2].
*   **Optimization:** The integration of the Lightplane Renderer allows for LPIPS optimization without the added complexity of deferred backpropagation used in earlier implementations [S2].

**Edge Cases and Pitfalls:**
*   **Memory Efficiency:** The memory efficiency of the Renderer is critical for enabling high-resolution differentiable rendering and backpropagation of image-level losses [S2].
*   **Unbounded Scenes:** For background representation, ray-point coordinates may need contraction to represent unbounded scenes [S2].

## Subtopics

### [Large Gaussian Reconstruction Model (GRM)](5961-large-gaussian-reconstruction-model-grm.md)
A variant that replaces the triplane output with Gaussian primitives, supporting both single and multi-view inputs.

## Operating characteristics
*   **Latency:** Real-time reconstruction on a single GPU [S1, unofficial].
*   **Accuracy:** Outperforms baseline ViewFormer and overfitting baselines (Voxel, NeRF) in amortized 3D reconstruction tasks [S2].
*   **Scalability:** Highly scalable components allow for large-scale 3D reconstruction and generation [S2].
*   **Limitations:** The original LRM required deferred backpropagation for certain losses, which added complexity [S2].

## Background
LRM was introduced by Adobe in 2023 and published at ICLR 2024 [S1, unofficial][S3, unofficial]. It represents a shift from per-scene optimization to feedforward prediction, leveraging large-scale datasets like Objaverse [S1, unofficial]. It serves as the parent architecture for several subsequent methods, including InstantMesh, MeshLRM, and GS-LRM [S1, unofficial].
