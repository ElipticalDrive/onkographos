# Gaussian Splatting

Also called: 3D Gaussian Splatting (3DGS), 3D GS

## Overview
Gaussian Splatting is a real-time novel view synthesis method that represents a scene as an explicit collection of learnable 3D Gaussian ellipsoids, rendered via differentiable volume splatting [S1, S6][S12, unofficial]. It solves the computational bottleneck of implicit neural radiance fields (NeRFs) by replacing ray marching with a tile-based rasterization pipeline, enabling interactive frame rates while maintaining high visual fidelity [S1, S5][S19, unofficial]. Unlike NeRFs, which query dense volumes along rays, Gaussian Splatting projects 3D Gaussians into 2D screen-space splats and composites them via alpha blending, avoiding costly queries in empty space [S1][S19, unofficial]. It sets itself apart from its siblings in the Gaussian Avatar family by using a general-purpose explicit representation initialized from Structure-from-Motion (SfM) point clouds, rather than anchoring primitives to parametric meshes like SMPL or FLAME [S1][S12, S36, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of posed input images $\{I_i\}$ and a sparse colored point cloud obtained via Structure-from-Motion (SfM) (e.g., COLMAP) [S1][S12, S36, unofficial].
*   **Outputs:** A set of $N$ 3D Gaussian primitives $\mathcal{G} = \{g_i\}_{i=1}^N$, where each $g_i$ is defined by parameters optimized to minimize the difference between rendered and ground-truth images [S1, S23].

**Data Structures:**
Each Gaussian $g_i$ is defined by the following attributes [S1, S6, S23][S25, unofficial]:
1.  **Position (Mean):** $\boldsymbol{\mu}_i \in \mathbb{R}^3$, the center of the Gaussian in world coordinates.
2.  **Covariance:** $\boldsymbol{\Sigma}_i \in \mathbb{R}^{3 \times 3}$, a symmetric positive-definite matrix defining shape and orientation. To ensure positive semi-definiteness during optimization, $\boldsymbol{\Sigma}_i$ is parameterized by a rotation quaternion $\mathbf{q}_i \in \mathbb{R}^4$ and a scale vector $\mathbf{s}_i \in \mathbb{R}^3$ [S6][S25, unofficial]:
    $$ \boldsymbol{\Sigma}_i = \mathbf{R}(\mathbf{q}_i) \mathbf{S}(\mathbf{s}_i) \mathbf{S}(\mathbf{s}_i)^\top \mathbf{R}(\mathbf{q}_i)^\top $$
    where $\mathbf{R}$ is the rotation matrix derived from $\mathbf{q}_i$ and $\mathbf{S} = \text{diag}(\mathbf{s}_i)$ [S6][S25, unofficial].
3.  **Opacity:** $\alpha_i \in [0, 1]$, a scalar representing the peak transparency of the primitive [S1, S6].
4.  **Color:** Represented by spherical harmonics (SH) coefficients $\mathbf{c}_i \in \mathbb{R}^{3 \times (k+1)^2}$, allowing for view-dependent appearance [S1, S6][S12, unofficial]. Typically, band 3 (48 coefficients per splat for RGB) is used [S8, unofficial].

**Numbered Steps:**

1.  **Initialization:** Initialize $N$ Gaussians using the SfM point cloud. Set $\boldsymbol{\mu}_i$ to the 3D point coordinates, $\alpha_i$ to a small constant (e.g., 0.1), and $\mathbf{c}_i$ by averaging pixel colors from visible images or initializing randomly [S1, S15][S36, unofficial]. Initialize $\mathbf{q}_i$ and $\mathbf{s}_i$ to represent isotropic spheres with small scale [S19, unofficial].

2.  **Frustum Culling:** Determine which Gaussians lie outside the camera's view frustum and exclude them from rendering [S6].

3.  **3D-to-2D Projection (Splatting):** Project each 3D Gaussian to the 2D image plane.
    *   Transform the 3D mean to camera coordinates: $\boldsymbol{\mu}_c = \mathbf{W} \boldsymbol{\mu}_i$, where $\mathbf{W}$ is the world-to-camera transformation matrix [S6][S22, unofficial].
    *   Approximate the perspective projection $\phi_{\mathbf{K}}$ using a first-order Taylor expansion around $\boldsymbol{\mu}_c$ with Jacobian $\mathbf{J} \in \mathbb{R}^{2 \times 3}$ [S1, S15]:
        $$ \phi_{\mathbf{K}}(\mathbf{x}) \approx \phi_{\mathbf{K}}(\boldsymbol{\mu}_c) + \mathbf{J}(\mathbf{x} - \boldsymbol{\mu}_c) $$
    *   Compute the 2D mean $\tilde{\boldsymbol{\mu}}_i$ and covariance $\tilde{\boldsymbol{\Sigma}}_i$ [S1, S15]:
        $$ \tilde{\boldsymbol{\mu}}_i = \phi_{\mathbf{K}}(\boldsymbol{\mu}_c) $$
        $$ \tilde{\boldsymbol{\Sigma}}_i = \mathbf{J} \mathbf{W} \boldsymbol{\Sigma}_i \mathbf{W}^\top \mathbf{J}^\top $$
        Note: $\mathbf{W}$ in the covariance formula refers to the rotational component of the viewing transformation [S22, unofficial]. The opacity and color are preserved: $\tilde{\alpha}_i = \alpha_i$, $\tilde{\mathbf{c}}_i = \mathbf{c}_i$ [S1].

4.  **Tile-Based Assignment:** Divide the image into non-overlapping tiles (typically $16 \times 16$ pixels) [S19, unofficial][S23]. Assign each projected 2D Gaussian to the tiles it intersects using an axis-aligned bounding box (AABB) test [S30].

5.  **Depth Sorting:** Sort the Gaussians within each tile by depth (distance from camera) to determine the rendering order [S6, S16, S30]. This is often implemented using a GPU-optimized radix sort on a combined key of tile ID and depth [S6].

6.  **Alpha Compositing (Rasterization):** For each pixel $\mathbf{x}$ in a tile, accumulate color from the sorted Gaussians using front-to-back alpha blending [S1, S16]:
    $$ C(\mathbf{x}) = \sum_{i \in \mathcal{N}} c_i \alpha'_i \prod_{j=1}^{i-1} (1 - \alpha'_j) $$
    where $\mathcal{N}$ is the set of overlapping Gaussians, $c_i$ is the view-dependent color evaluated from SH coefficients at the viewing direction, and $\alpha'_i$ is the effective opacity at pixel $\mathbf{x}$ [S3, unofficial][S6]:
    $$ \alpha'_i = \alpha_i \exp\left(-\frac{1}{2} (\mathbf{x} - \tilde{\boldsymbol{\mu}}_i)^\top \tilde{\boldsymbol{\Sigma}}_i^{-1} (\mathbf{x} - \tilde{\boldsymbol{\mu}}_i)\right) $$
    The term $\exp(\dots)$ is the value of the 2D Gaussian kernel $\mathcal{G}_i^{2D}(\mathbf{x})$ [S7][S14, unofficial].

7.  **Optimization (Training Loop):**
    *   Render the image and compute loss $\mathcal{L}$ against the ground truth image $I_{gt}$ [S1, S6]:
        $$ \mathcal{L} = (1 - \lambda) \mathcal{L}_{L1} + \lambda \mathcal{L}_{MS-SSIM} $$
        where $\mathcal{L}_{L1}$ is the pixel-wise L1 distance and $\mathcal{L}_{MS-SSIM}$ is the perceptual structural similarity loss [S6][S13, unofficial].
    *   Backpropagate gradients to update $\boldsymbol{\mu}_i, \mathbf{q}_i, \mathbf{s}_i, \alpha_i, \mathbf{c}_i$ [S1, S6].
    *   **Adaptive Density Control:** Periodically (e.g., every 100 iterations) adjust the number of Gaussians [S1][S19, unofficial]:
        *   **Clone:** Duplicate small Gaussians with large position gradients (under-reconstructed regions).
        *   **Split:** Replace large Gaussians with large position gradients with two smaller Gaussians sampled from the original.
        *   **Prune:** Remove Gaussians with opacity below a threshold $\tau$ or those that are excessively large in screen space [S1][S19, unofficial].
        *   **Opacity Reset:** Periodically reset opacities to a small value to prune redundancies [S19, unofficial].

**Pseudocode:**

```python
def render_gaussian_splatting(gaussians, camera_pose, image_width, image_height, tile_size=16):
    """
    Renders a scene represented by 3D Gaussians using tile-based rasterization.
    
    Args:
        gaussians: List of Gaussian objects with attributes:
            - mu: (3,) mean position in world space
            - q: (4,) rotation quaternion
            - s: (3,) scale vector
            - alpha: (1,) opacity
            - sh_coeffs: (3, (k+1)^2) spherical harmonic coefficients
        camera_pose: (4, 4) world-to-camera transformation matrix W
        image_width, image_height: int
        tile_size: int (default 16)
        
    Returns:
        image: (H, W, 3) rendered RGB image
    """
    # 1. Frustum Culling (Simplified: assume all are in frustum for core logic)
    # In practice, cull Gaussians outside the camera frustum [S6]
    
    # 2. Projection to 2D
    projected_gaussians = []
    for g in gaussians:
        # Compute 3D covariance from q and s
        R = quaternion_to_rotation_matrix(g.q)
        S = diag(g.s)
        Sigma_3d = R @ S @ S.T @ R.T
        
        # Transform mean to camera space
        mu_cam = camera_pose[:3, :3] @ g.mu + camera_pose[:3, 3]
        
        # Compute Jacobian J of perspective projection at mu_cam
        # J depends on camera intrinsics K and mu_cam
        J = compute_projection_jacobian(mu_cam, camera_intrinsics)
        
        # Project covariance: Sigma_2d = J * W * Sigma_3d * W.T * J.T
        # Note: W in formula is rotational part of camera_pose
        W_rot = camera_pose[:3, :3]
        Sigma_2d = J @ W_rot @ Sigma_3d @ W_rot.T @ J.T
        
        # Project mean
        mu_2d = project_point(mu_cam, camera_intrinsics)
        
        projected_gaussians.append({
            'mu_2d': mu_2d,
            'Sigma_2d': Sigma_2d,
            'alpha': g.alpha,
            'sh_coeffs': g.sh_coeffs,
            'mu_cam_z': mu_cam[2] # Depth for sorting
        })
        
    # 3. Tile Assignment and Sorting
    # Initialize tile lists
    num_tiles_x = (image_width + tile_size - 1) // tile_size
    num_tiles_y = (image_height + tile_size - 1) // tile_size
    tiles = [[[] for _ in range(num_tiles_x)] for _ in range(num_tiles_y)]
    
    for pg in projected_gaussians:
        # Determine bounding box in pixel space
        # Approximate extent using 3 standard deviations of Sigma_2d
        std_devs = 3.0
        # Eigenvalues of Sigma_2d give squared extents
        eigenvalues = np.linalg.eigvalsh(pg['Sigma_2d'])
        extent_x = std_devs * np.sqrt(eigenvalues[0])
        extent_y = std_devs * np.sqrt(eigenvalues[1])
        
        min_x = int(pg['mu_2d'][0] - extent_x)
        max_x = int(pg['mu_2d'][0] + extent_x)
        min_y = int(pg['mu_2d'][1] - extent_y)
        max_y = int(pg['mu_2d'][1] + extent_y)
        
        # Clip to image bounds
        min_x = max(0, min_x)
        max_x = min(image_width, max_x)
        min_y = max(0, min_y)
        max_y = min(image_height, max_y)
        
        # Assign to tiles
        tile_min_x = min_x // tile_size
        tile_max_x = max_x // tile_size
        tile_min_y = min_y // tile_size
        tile_max_y = max_y // tile_size
        
        for ty in range(tile_min_y, tile_max_y + 1):
            for tx in range(tile_min_x, tile_max_x + 1):
                if 0 <= ty < num_tiles_y and 0 <= tx < num_tiles_x:
                    tiles[ty][tx].append(pg)
                    
    # Sort each tile's Gaussians by depth (z-coordinate in camera space)
    for ty in range(num_tiles_y):
        for tx in range(num_tiles_x):
            tiles[ty][tx].sort(key=lambda g: g['mu_cam_z'])
            
    # 4. Alpha Compositing
    image = np.zeros((image_height, image_width, 3), dtype=np.float32)
    
    for ty in range(num_tiles_y):
        for tx in range(num_tiles_x):
            tile_gaussians = tiles[ty][tx]
            if not tile_gaussians:
                continue
                
            # Define pixel range for this tile
            y_start = ty * tile_size
            x_start = tx * tile_size
            y_end = min(y_start + tile_size, image_height)
            x_end = min(x_start + tile_size, image_width)
            
            # Precompute conic matrix inverse for speed (optional optimization)
            # For each Gaussian, compute conic = Sigma_2d^{-1}
            for pg in tile_gaussians:
                pg['conic'] = np.linalg.inv(pg['Sigma_2d'])
                
            # Iterate over pixels in tile
            for y in range(y_start, y_end):
                for x in range(x_start, x_end):
                    transmittance = 1.0
                    color = np.zeros(3)
                    
                    for pg in tile_gaussians:
                        # Compute distance vector from pixel to Gaussian center
                        dx = x - pg['mu_2d'][0]
                        dy = y - pg['mu_2d'][1]
                        
                        # Compute 2D Gaussian value: exp(-0.5 * d^T * Sigma^{-1} * d)
                        # Using conic matrix
                        power = -0.5 * (pg['conic'][0,0]*dx*dx + pg['conic'][1,1]*dy*dy + 2*pg['conic'][0,1]*dx*dy)
                        
                        # Clamp power to avoid numerical issues
                        power = max(power, -2.0) # [G] Heuristic to prevent exp overflow/underflow artifacts
                        gaussian_val = np.exp(power)
                        
                        # Effective opacity
                        alpha_prime = pg['alpha'] * gaussian_val
                        
                        # View-dependent color from SH
                        # Note: SH evaluation depends on viewing direction, which is constant for the pixel
                        view_dir = compute_view_direction(x, y, camera_intrinsics)
                        c_i = evaluate_sh(pg['sh_coeffs'], view_dir)
                        
                        # Accumulate
                        weight = alpha_prime * transmittance
                        color += weight * c_i
                        transmittance *= (1.0 - alpha_prime)
                        
                        # Early termination if transmittance is very low
                        if transmittance < 1e-4:
                            break
                            
                    image[y, x] = color
                    
    return image
```

## Operating characteristics
*   **Time Complexity:** Rendering is $O(N \cdot T)$ where $N$ is the number of Gaussians and $T$ is the average number of overlapping Gaussians per tile, but effectively linear in image resolution due to tile-based culling and sorting [S1, S6]. Training involves iterative optimization, which is slower than inference but converges in minutes to hours depending on scene complexity [S1][S19, unofficial].
*   **Memory Complexity:** $O(N)$, storing position, covariance (via q, s), opacity, and SH coefficients for each Gaussian [S6]. Typical scenes require hundreds of thousands to millions of Gaussians, consuming several hundred MBs to GBs of VRAM [S5, S6].
*   **Performance:** Enables real-time rendering (60+ FPS) on modern GPUs for scenes with up to a few million Gaussians [S1, S5].
*   **Strengths:** Real-time rendering, high visual fidelity, explicit representation allows for easy editing and integration with graphics pipelines [S1, S5, S6].
*   **Limitations:** Large memory footprint compared to implicit methods; sorting bottleneck for very high counts; approximations in projection and alpha blending can cause artifacts like popping or transparency errors [S2, S5].
*   **When to use:** Novel view synthesis, real-time visualization, interactive applications where speed is critical.
*   **When not to use:** Scenes requiring exact volumetric accuracy (e.g., medical imaging where density integration is crucial) or extremely sparse input with no SfM data [S2][S19, unofficial].

## Background
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1][S12, unofficial]. It builds upon earlier work in volume splatting, specifically Elliptical Weighted Average (EWA) splatting [S2][S4, unofficial], and point-based rendering methods [S2]. The method was developed to address the computational inefficiencies of Neural Radiance Fields (NeRFs), which rely on ray marching and MLP queries [S1][S19, unofficial]. By using explicit 3D Gaussians and a differentiable rasterization pipeline, 3DGS achieved a breakthrough in real-time novel view synthesis [S1, S5]. It has since become a dominant paradigm in 3D reconstruction and rendering, spawning numerous variants and applications [S5, S6].
