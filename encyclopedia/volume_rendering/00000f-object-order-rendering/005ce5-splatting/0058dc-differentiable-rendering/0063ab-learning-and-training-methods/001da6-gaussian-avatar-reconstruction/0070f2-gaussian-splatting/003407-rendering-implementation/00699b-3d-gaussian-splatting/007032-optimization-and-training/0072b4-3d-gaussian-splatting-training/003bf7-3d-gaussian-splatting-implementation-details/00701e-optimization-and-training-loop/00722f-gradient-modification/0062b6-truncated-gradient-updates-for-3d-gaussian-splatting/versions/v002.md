# Truncated Gradient Updates for 3D Gaussian Splatting

Also called: TruncGradGS

## Overview
Truncated Gradient Updates is a gradient modification technique that applies truncated gradients to 'dead' Gaussians (those with low opacity) to enable long-range movement and convergence, addressing vanishing gradients in dynamic scenes or poor initialization [S1]. It sets itself apart from standard 3D Gaussian Splatting by introducing a piecewise surrogate gradient function that activates only when a Gaussian's contribution falls below a threshold, allowing primitives to be pulled toward distant pixels they currently miss [S1]. Unlike [Bézier-boundary gradient approximation](13137-b-zier-boundary-gradient-approximation.md), which approximates gradients at boundaries, this method explicitly handles the "dead" state where rasterization yields zero gradient.

## How it works

### Inputs and Outputs
**Inputs:**
*   Loss function $L$ and its gradients with respect to Gaussian parameters.
*   Gaussian parameters: mean $\mu$, opacity $\sigma$, alpha $\alpha$ (derived from $\sigma$ and density), and covariance.
*   Pixel center $p$ in 2D image space.
*   Mahalanobis distance coefficients $a, b, c$ derived from the Gaussian's 2D covariance projection [S1].
*   Pruning threshold $\tau_{pruning}$ [S1].
*   Slope parameter $m$ controlling the decay of the truncated gradient [S1].
*   Tile-coverage radius threshold for dead Gaussians [S1].

**Outputs:**
*   Modified gradients for the Gaussian mean $\mu$ (and opacity $\sigma$ in specific cases) to be used in the optimizer step [S1].

### Data Structures
The method operates on the standard 3D Gaussian Splatting primitive structure. Key fields relevant to this method include:
*   `mean`: 3D vector $(\mu_x, \mu_y, \mu_z)$.
*   `opacity`: Scalar $\sigma$.
*   `alpha`: Scalar $\alpha$ (often $\alpha = 1 - e^{-\sigma \cdot \text{density}}$ or similar, but the method treats $\alpha$ as the effective alpha contribution) [S1].
*   `covariance`: 3x3 matrix, projected to 2D for Mahalanobis calculation [S1].
*   `is_dead`: Boolean flag, true if $\sigma < \tau_{pruning}$ [S1].

### Numbered Steps

1.  **Identify Dead Gaussians:** Determine if a Gaussian is "dead" by checking if its opacity $\sigma_i$ is below the pruning threshold $\tau_{pruning}$ [S1]. The truncated gradient is applied **only** to these Gaussians to prevent divergence in well-fitted primitives [S1].

2.  **Calculate Mahalanobis Distance:** For each pixel $p$ that the Gaussian *does not* contribute to (filtered out by the rasterizer), calculate the squared Mahalanobis distance $r_s$ between the Gaussian mean $\mu$ and the pixel center $p$ [S1]:
    $$ r_s = \|\mu - p\|_2^2 $$
    The threshold condition involves the quadratic form:
    $$ K = a(\mu_x - p_x)^2 + 2b(\mu_x - p_x)(\mu_y - p_y) + c(\mu_y - p_y)^2 $$
    where $a, b, c$ are coefficients from the inverse of the projected 2D covariance matrix (Eq. 8 in source) [S1].

3.  **Check Alpha Gradient Sign:** Compute the gradient of the loss with respect to alpha, $\frac{\partial L}{\partial \alpha_i}$ [S1].
    *   If $\frac{\partial L}{\partial \alpha_i} \ge 0$, do **not** apply the truncated gradient. Applying it when positive would cause a "long-range push," making Gaussians repel each other [S1].
    *   If $\frac{\partial L}{\partial \alpha_i} < 0$, proceed to determine the update path [S1].

4.  **Determine Gradient Update Path:** Based on the product of opacity $\sigma$ and alpha $\alpha$ relative to $1/255$ and the Mahalanobis distance, select one of three paths [S1]:
    *   **Normal Path:** If $\sigma\alpha \ge 1/255$ (high-pass filter), the Gaussian receives normal gradients. This case is handled by the standard backward pass; the truncated gradient logic is bypassed [S1].
    *   **Truncated Path:** If $\sigma\alpha < 1/255$ (low density or low opacity) AND the Mahalanobis distance is above the cut-off threshold, the Gaussian receives truncated gradients [S1].
        *   If the low contribution is due to low opacity $\sigma$, compute the gradient specifically for opacity $\sigma$ [S1].
        *   The cut-off point $x$ is the solution to $G(x) = \tau$, where $G(x)$ is the gradient function [S1].
    *   **Skip Path:** If $\sigma\alpha < 1/255$ AND the Mahalanobis distance is below the threshold, the Gaussian receives **no** gradients [S1].

5.  **Compute Truncated Gradient:** For Gaussians on the Truncated Path, the gradient is derived from a linear surrogate function with slope $m$ [S1].
    *   The slope $m$ influences the range of action: a lower $m$ yields a near-constant long-range gradient approximating the cut-off gradient, while a higher $m$ yields a sharp decay [S1].
    *   The cut-off gradient is defined as $G'(x)$, where $x$ is the solution to $G(x) = \tau$ [S1].
    *   The full derivation for the solution $r_s$ is provided in the source's supplementary material, but the implementation uses the condition $d(p) > \tau$ to trigger the truncated gradient [S1].

6.  **Interleaved Optimization Strategy:** Alternate between optimization steps using the truncated gradient and normal optimization steps with Adaptive Density Control (ADC) turned on [S1]. This prevents perturbations to the accumulated viewspace gradient from affecting the ADC decisions [S1].

7.  **Delay Pruning:** Delay the pruning of primitives until the end of training. This allows dead Gaussians to receive long-range gradients and converge to distant pixels before being pruned [S1].

8.  **Expand Tile-Coverage Radius:** For each dead Gaussian whose radius is below a threshold, expand its tile-coverage radius [S1]. This addresses the tile-based culling of the rasterizer, enabling long-distance pixel error contributions using the truncated gradient field [S1].

9.  **Dynamic Scene Optimization (Optional):** For dynamic methods, create viewpoint-dependent motion masks via frame-difference and image processing on input videos. Ignore contributions of static pixels to reduce computation [S1].

### Parameters
*   **Slope parameter $m$:** Influences the range of action of the truncated gradient in the image plane. A lower $m$ yields a near-constant long-range gradient approximating the cut-off gradient; a higher $m$ yields a sharp decay from the cut-off gradient [S1].
*   **Pruning threshold $\tau_{pruning}$:** Opacity threshold below which a Gaussian is considered "dead" and eligible for truncated gradients [S1].
*   **Tile-coverage radius threshold:** Radius below which a dead Gaussian's tile coverage is expanded [S1].

### Edge Cases and Pitfalls
*   **Model Divergence:** Accumulated truncated gradients may surpass the true gradient, especially for "very bad fits" (no normal gradients) or "good fits" (true gradient near zero) [S1]. This is prevented by applying the truncated gradient **only** for dead Gaussians ($\sigma_i < \tau_{pruning}$) [S1].
*   **Repulsion:** Applying the truncated gradient when $\frac{\partial L}{\partial \alpha_i} \ge 0$ causes a "long-range push," making Gaussians repel each other [S1].
*   **Performance Overhead:** Without careful implementation, the method can be 1–10× slower to train than the baseline [S1]. This is mitigated by applying radius expansion and truncated gradient computation only for dead Gaussians and using motion masks for dynamic scenes [S1].
*   **Tile Culling:** Dead Gaussians may be culled by the rasterizer before they can receive gradients. Expanding their tile-coverage radius addresses this [S1].

## Operating characteristics

**Time and Memory Complexity:**
*   The method adds computational overhead during training, specifically in the backward pass for dead Gaussians.
*   Training performance is 1–10× slower than the baseline, depending on the scene and primitive count [S1].
*   Inference speed is unaffected [S1].
*   Memory complexity is not explicitly stated, but the method requires storing additional flags (e.g., `is_dead`) and potentially expanded tile coverage data [S1].

**Measured Performance:**
*   **Static Scene (Mip-NeRF360, Random Init):**
    *   PSNR: 25.16 (vs 24.74 baseline)
    *   SSIM: 0.8511 (vs 0.8351 baseline)
    *   LPIPS: 0.1974 (vs 0.2106 baseline)
    *   #GS: 0.799M (vs 1.126M baseline) [S1]
*   **Dynamic Scene (Neural 3D Video):**
    *   PSNR: 31.70 (vs 30.22 baseline)
    *   SSIM: 0.9493 (vs 0.9443 baseline)
    *   LPIPS: 0.1339 (vs 0.1360 baseline)
    *   #GS: 1.733M (vs 2.806M baseline) [S1]

**Scaling:**
*   The method scales with the number of primitives, but the overhead is limited to dead Gaussians [S1].
*   For dynamic scenes, the use of motion masks helps scale by ignoring static pixels [S1].

**Strengths and Limitations:**
*   **Strengths:** Improves reconstruction quality for poorly initialized or dynamic scenes; reduces the number of Gaussians needed; plug-and-play compatibility with 3DGS, 2DGS, 4DGS, CEM-4DGS, and 4DScaffold [S1].
*   **Limitations:** Slower training time; requires careful tuning of parameters like $m$ and $\tau_{pruning}$; risk of divergence if applied to non-dead Gaussians [S1].

**When to Use:**
*   Use when dealing with poor initialization, dynamic scenes with large spatio-temporal divergence, or when standard 3DGS fails to converge due to vanishing gradients for distant pixels [S1].

**When Not to Use:**
*   Avoid if training time is a critical constraint and the scene is well-initialized with standard 3DGS performance [S1].
*   Do not apply to all Gaussians, as it degrades performance and causes divergence [S1].

## Background

**Origin:**
*   The method was introduced by T. Morales, N.-Q. Le-Pham, R. Atkins & B.-S. Hua in the paper "TruncGradGS: Improved 3D Gaussian Splatting via Truncated Gradient Updates" [S1].
*   Published in the Proceedings of Eurographics - The European Association for Computer Graphics, 2026 [S1].

**History and Development:**
*   The method addresses limitations in standard 3D Gaussian Splatting, particularly in dynamic scenes and poor initialization scenarios where Gaussians fail to receive gradients from distant pixels [S1].
*   It builds on the concept of gradient modification, specifically targeting the "dead" state of Gaussians [S1].

**Usage:**
*   Used as a plug-and-play module on top of 3DGS, 2DGS, 4DGS, CEM-4DGS, and 4DScaffold for both static and dynamic scene reconstruction [S1].
