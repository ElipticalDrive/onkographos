# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, GSGEN Implementation Details, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific hyperparameters, data structures, and optimization schedules required to implement the 3D Gaussian Splatting (3DGS) training loop and rendering pipeline. It addresses the problem of translating the theoretical differentiable rendering formulation into a stable, high-performance software implementation. It sets itself apart from general optimization methods by providing concrete values for densification thresholds, loss weighting, and hardware-specific kernel configurations (e.g., half-precision fetches, GEMM reformulation) that are critical for reproducibility [S1, S2][S9, unofficial][S16].

## How it works

### Inputs and Outputs
**Inputs:**
*   A set of $N_{cam}$ calibrated images with known camera poses $C_i$ and intrinsics.
*   An initial sparse point cloud from Structure-from-Motion (SfM) with $N_{SfM}$ points [S4].
*   Optimization hyperparameters (learning rate, iteration budget, densification intervals) [S1][S9, unofficial].

**Outputs:**
*   A set of $N$ 3D Gaussian primitives $\mathcal{G} = \{g_1, ..., g_N\}$, where each $g_j$ is parameterized by position $\mu_j$, covariance $\Sigma_j$ (or scale $s_j$ and rotation $q_j$), opacity $\alpha_j$, and spherical harmonic coefficients $\mathbf{c}_j$ [S5, S6].

### Data Structures
The implementation relies on the `gsplat` library or custom CUDA kernels [S2, S3]. Key data layouts include:

1.  **Gaussian Attributes:** Stored in SoA (Structure of Arrays) format for efficient vectorized memory access.
    *   `positions`: Float32, $(N, 3)$ [S2].
    *   `scales`: Float32, $(N, 3)$ [S2].
    *   `rotations`: Quaternions, Float32, $(N, 4)$ [S2].
    *   `opacities`: Float32, $(N, 1)$ [S2].
    *   `sh_coeffs`: Float32, $(N, K \cdot 3)$, where $K$ is the number of SH bands. For SH Degree 1, $K=4$, resulting in 12 coefficients per Gaussian [S3].
    *   `viewdirs`: Float32, $(N, 3)$, used for view-dependent SH evaluation [S2].

2.  **Tile/Screen Layout:**
    *   The 2D screen is divided into tiles, typically $16 \times 16$ pixels [S16].
    *   Each tile maintains a list of intersecting Gaussians, sorted by depth [S16].

3.  **Error/Gradient Maps:**
    *   Per-pixel error maps and age maps are maintained to guide sparse sampling or densification [S13, S15].

### Training Loop and Optimization Steps
The training process follows a stochastic gradient descent loop [S9, unofficial].

1.  **Initialization:**
    *   Initialize Gaussians from the SfM point cloud.
    *   Calculate scene extent $e_{scene}$. If using the corrected method, compute $e'_{scene}$ based on SfM points to avoid camera-position bias [S4].
    *   Set SH Degree to 1 for initial stability [S3].

2.  **Iteration Loop (for $I$ iterations, typically 30,000 [S9, unofficial]):**
    *   **Step 1: Random View Selection.** Randomly select one training image and its camera pose [S3][S9, unofficial].
    *   **Step 2: Forward Rendering.**
        *   Project 3D Gaussians to 2D screen space.
        *   Sort Gaussians by depth within each tile [S16].
        *   Rasterize using alpha blending. For half-precision implementations, fetch feature vectors in FP16 to reduce register pressure [S2].
        *   Compute rendered image $\hat{I}$.
    *   **Step 3: Loss Computation.**
        *   Compute per-image error between $\hat{I}$ and ground truth $I_{gt}$ [S9, unofficial].
        *   Loss $\mathcal{L} = (1 - \lambda)\mathcal{L}_1 + \lambda\mathcal{L}_{SSIM}$, with $\lambda \approx 0.2$ [S9, unofficial].
        *   Apply automatic scaling factor to loss values to improve half-precision training stability [S2].
    *   **Step 4: Backward Pass.**
        *   Compute gradients $\frac{\partial \mathcal{L}}{\partial \theta}$ for all Gaussian parameters $\theta$ [S2].
    *   **Step 5: Optimizer Update.**
        *   Update parameters using Adam optimizer with learning rate $1 \times 10^{-3}$ [S3].

3.  **Densification and Pruning (Adaptive Density Control):**
    *   **Splitting:** Every 500 iterations, split Gaussians where the view-space position gradient exceeds $T_{pos} = 0.02$ [S1].
    *   **Cloning:** Clone Gaussians based on compactness criteria every 1000 iterations [S1].
    *   **Pruning:** Every 200 iterations, remove Gaussians with opacity $\alpha < \alpha_{min} = 0.05$ or excessively large world-space/view-space radius [S1].

### Formulas

**Corrected Scene Extent [S4]:**
To avoid bias from clustered cameras, the scene extent $e'_{scene}$ is calculated as:
$$
\bar{C} = \frac{1}{N_{cam}} \sum_{i=1}^{N_{cam}} C_i
$$
$$
e'_{scene} = \frac{1}{N_{SfM}} \sum_{i=1}^{N_{SfM}} \|\bar{C} - p_i\|_2
$$
where $\bar{C}$ is the average camera position, $N_{cam}$ is the number of cameras, $N_{SfM}$ is the number of SfM points, and $p_i$ is the $i$-th SfM point.

**Multi-Scale Constraint [S7]:**
For large-scale scenes, a position-aware scale factor $\gamma(\mu)$ is applied:
$$
\gamma(\mu) = 
\begin{cases} 
1 & \text{if } \|\mu - c\|^2 < 2r \\
\frac{\|\mu - c\|^2}{r} - 1 & \text{if } \|\mu - c\|^2 \ge 2r
\end{cases}
$$
where $r$ is the scene radius and $c$ is the camera center. Cloning occurs if $\max(s) < g \cdot \gamma(\mu)$, splitting if $\max(s) \ge g \cdot \gamma(\mu)$, and elimination if $\max(s) > b \cdot \gamma(\mu)$, with $g$ and $b$ as threshold parameters.

**Resolution Guided Primitive Scheduler [S13]:**
The primitive budget $P_{fin}^{(i)}$ at step $i$ is updated as:
$$
P_{fin}^{(i)} = \max(P_{fin}^{(i-1)}, \gamma \cdot P_{fin}^{(i-1)} + \eta \cdot P_{add})
$$
where $P_{add}$ is the number of densified primitives, $\gamma = 0.98$ (momentum decay), and $\eta = 1$ (force scaling). $P_{fin}^{(0)} = 5 \cdot P_{init}$.

### Pseudocode

```python
def train_3dgs(images, poses, sfm_points, num_iterations=30000):
    # Initialization
    gaussians = initialize_from_sfm(sfm_points)
    optimizer = Adam(gaussians.parameters(), lr=1e-3)
    
    # Hyperparameters
    lambda_ssim = 0.2
    alpha_min = 0.05
    t_pos = 0.02
    
    for i in range(num_iterations):
        # 1. Random View Selection
        idx = random_choice(len(images))
        image = images[idx]
        pose = poses[idx]
        
        # 2. Forward Rendering
        # Project Gaussians, sort by depth, rasterize
        rendered_image = rasterize(gaussians, pose)
        
        # 3. Loss Computation
        l1_loss = l1_loss(rendered_image, image)
        ssim_loss = ssim_loss(rendered_image, image)
        loss = (1 - lambda_ssim) * l1_loss + lambda_ssim * ssim_loss
        
        # Apply scaling for half-precision stability if using FP16
        loss = scale_loss_for_precision(loss)
        
        # 4. Backward Pass
        optimizer.zero_grad()
        loss.backward()
        
        # 5. Optimizer Update
        optimizer.step()
        
        # 6. Adaptive Density Control
        if i % 500 == 0:
            # Split Gaussians with high position gradient
            split_gaussians(gaussians, threshold=t_pos)
            
        if i % 1000 == 0:
            # Clone based on compactness
            clone_gaussians(gaussians)
            
        if i % 200 == 0:
            # Prune low opacity Gaussians
            prune_gaussians(gaussians, alpha_min=alpha_min)
            
    return gaussians
```

### Edge Cases and Pitfalls
*   **Scene Extent Bias:** Using the default scene extent formula based on camera positions can lead to incorrect splitting/pruning if cameras are clustered (e.g., orbiting a small object) [S4]. Use the corrected SfM-based extent [S4].
*   **Half-Precision Stability:** Training in FP16 requires an automatic scaling factor for loss values to prevent gradient underflow/overflow [S2].
*   **Uniform Blur Degeneration:** In defocus blurring methods, if the predicted scale offset $\delta s_j$ is constant for all Gaussians, the method degrades to a uniform Gaussian blur, failing to model spatially varying blurriness [S5].
*   **Late-Stage Growth:** Excessive primitive growth at the end of optimization leads to poor convergence. Mitigated by concave-up scheduling functions [S13].

## Operating characteristics

**Time and Memory Complexity:**
*   Rendering is $O(N \cdot T)$ where $N$ is the number of Gaussians and $T$ is the number of tiles, but optimized via spatial partitioning and sorting [S16].
*   Memory usage is dominated by storing Gaussian attributes (position, scale, rotation, opacity, SH coefficients) for millions of primitives, often exceeding 1GB [12943-data-compression-and-storage-optimization.md].

**Measured Performance:**
*   GEMM-GS achieves an average 1.42× speedup over vanilla 3DGS and an additional 1.47× when combined with other acceleration methods [S16].
*   LS-Gaussian achieves a 5.41× speedup over edge GPU baselines on Jetson AGX Orin, rendering one frame in every 6 fully [S8].

**Strengths and Limitations:**
*   **Strengths:** Real-time rendering speeds, high fidelity, explicit representation allows for easy editing and compression [S16, S8].
*   **Limitations:** High memory bandwidth requirements, sensitivity to initialization (scene extent bias), and potential for floating artifacts in large-scale scenes without proper partitioning [S4, S7].

**When to Use:**
*   Use when real-time novel view synthesis is required and hardware supports modern GPU features (Tensor Cores, half-precision).
*   Avoid or modify (e.g., Corrected Scene-Extent) when camera distribution is biased or clustered [S4].

## Background

3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1]. It represents scenes as a set of 3D Gaussians and uses differentiable rasterization for training. The method has since evolved with various optimization techniques, including densification schedules [S1], half-precision implementations [S2], and hardware-specific accelerations like GEMM-GS [S16]. It is widely used in computer vision for novel view synthesis, SLAM, and scene representation [S1][S10, unofficial].
