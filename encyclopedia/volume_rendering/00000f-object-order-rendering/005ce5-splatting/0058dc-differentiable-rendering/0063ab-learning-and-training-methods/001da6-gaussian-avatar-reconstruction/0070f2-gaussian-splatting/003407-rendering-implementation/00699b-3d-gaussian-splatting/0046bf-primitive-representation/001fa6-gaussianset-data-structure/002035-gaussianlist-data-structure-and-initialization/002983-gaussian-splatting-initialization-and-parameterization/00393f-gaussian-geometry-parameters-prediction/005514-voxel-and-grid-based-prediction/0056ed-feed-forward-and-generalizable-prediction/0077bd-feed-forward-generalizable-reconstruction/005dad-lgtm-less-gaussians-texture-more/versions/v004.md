# LGTM (Less Gaussians, Texture More)

Also called: Feed-Forward Prediction of Textured Gaussians, Feed-Forward Textured Splatting

## Overview
LGTM is a feed-forward framework that predicts compact 2D Gaussian primitives coupled with per-primitive texture maps to enable high-fidelity 4K novel view synthesis without per-scene optimization [S1, unofficial]. It solves the quadratic growth in primitive count inherent in pixel-aligned feed-forward methods, which makes high-resolution synthesis intractable due to memory and compute limits [S1, unofficial]. Unlike standard 3DGS which couples appearance and geometry within each primitive, LGTM decouples them, allowing a compact set of geometric primitives to represent rich texture regions via per-primitive textures [S1, unofficial].

## How it works
**Inputs and Outputs:**
The network $f$ takes a set of input images $\{I^v\}_{v=1}^N$ and their low-resolution counterparts $\{I^v_{low}\}_{v=1}^N$ as input [S1, unofficial]. It outputs a set of textured 2D Gaussians:
$$ f : (I^v, I^v_{low}) \rightarrow \{\mu_i, s_i, r_i, c_i, T^i_c, T^i_\alpha\} $$
where $\mu_i$ is the mean, $s_i$ and $r_i$ define the scale and rotation (covariance), $c_i$ are the spherical harmonic (SH) coefficients, $T^i_c$ is the color texture map, and $T^i_\alpha$ is the alpha texture map [S1, unofficial].

**Data Structures:**
*   **Primitive Grid:** The primitive network predicts a grid of $h \times w$ 2DGS primitives, where $h \times w$ corresponds to the resolution of the low-resolution input $I^v_{low}$ [S1, unofficial].
*   **Per-primitive Texture Maps:** Each primitive $i$ has two texture maps:
    *   Color texture: $T^i_c \in \mathbb{R}^{T \times T \times 3}$
    *   Alpha texture: $T^i_\alpha \in \mathbb{R}^{T \times T}$
    *   $T$ is the texture resolution, a tunable parameter trading off primitive size and texture size [S1, unofficial].
    *   $T^i_c$ is zero-initialized [S1, unofficial].

**Architecture:**
The architecture consists of two submodules:
1.  **Primitive Network ($f_{prim}$):** Processes low-resolution images $I^v_{low}$ to predict compact geometric primitives ($\mu, s, r, c$) and base opacity $o_i$. It uses a Vision Transformer (ViT) encoder-decoder to produce a grid of primitives [S1, unofficial]. It also outputs feature maps $F^{v}_{prim}$ from the ViT decoder, which are shared with the texture network [S1, unofficial].
2.  **Texture Network ($f_{texture}$):** Processes high-resolution images $I^v$ and the geometric features $F^{v}_{prim}$ to predict per-primitive texture maps $T^i_\alpha, T^i_c$ [S1, unofficial]. It extracts features from three sources:
    *   $F^{v}_{patch}$: High-resolution features from $I^v$ via image patchification and convolutions [S1, unofficial].
    *   $F^{v}_{proj}$: Projective features derived from mapping source image pixels back to primitive local coordinates [S1, unofficial].
    *   $F^{v}_{prim}$: Geometric features from the primitive network [S1, unofficial].
    These features are aggregated to predict the final texture maps [S1, unofficial].

**Rendering Formulas:**
For a ray-splat intersection point $u$ on primitive $i$, the alpha and color are redefined using the texture maps [S1, unofficial]:
$$ a_i(u) = o_i \cdot T^i_\alpha[u] $$
$$ \hat{c}_i(u, d_i) = T^i_c[u] + SH(c_i, d_i) $$
where $d_i$ is the view direction, $o_i$ is the base opacity, and $T[u]$ denotes bilinear sampling from the texture map at local coordinate $u$ [S1, unofficial]. The alpha texture replaces the standard Gaussian falloff $G(u)$, and the color texture adds high-frequency detail to the SH base color [S1, unofficial]. The final pixel color $C$ is computed by alpha-blending contributions from all primitives sorted by depth [S1, unofficial]:
$$ C = \sum_i a_i(u_i) \hat{c}_i(d_i) \prod_{j=1}^{i-1} (1 - a_j(u_j)) $$

**Projective Feature Computation:**
To compute projective features $F^{v}_{proj}$, a projective prior texture $T^{i, proj}_c$ is computed using the inverse transformation $M^{-1}_{i,v}$ that maps primitive local coordinates $u$ to source image pixel coordinates $x$ [S1, unofficial]:
$$ T^{i, proj}_c[u] = I^v[x] = I^v[M^{-1}_{i,v}(u)] $$
Features $F^{v}_{proj}$ are then extracted from $T^{i, proj}_c[u]$ [S1, unofficial].

**Training Strategy:**
LGTM uses a staged training strategy supervised by standard photometric losses (MSE + LPIPS) [S1, unofficial]:
1.  **Stage 1:** Pre-train the primitive network $f_{prim}$ in isolation. It takes low-resolution inputs $I^v_{low}$ and predicts primitives, but renders and supervises them at full resolution $H \times W$ (high-resolution supervision) to prevent holes and ensure anti-aliasing [S1, unofficial].
2.  **Stage 2:** Jointly train $f_{prim}$ and $f_{texture}$. The parameters of $f_{prim}$ are frozen or trained with a reduced learning rate (0.1×) to maintain geometric stability [S1, unofficial].

**Pseudocode:**

```python
def lgtm_forward(input_images, low_res_images, camera_poses):
    """
    Forward pass of the LGTM network.
    
    Args:
        input_images: List of high-resolution RGB images I^v.
        low_res_images: List of low-resolution RGB images I^v_low.
        camera_poses: Camera poses P (optional, depending on baseline).
        
    Returns:
        primitives: List of Gaussian primitives (mu, s, r, c, o).
        textures: List of per-primitive texture maps (T_c, T_alpha).
    """
    # Stage 1: Primitive Network
    # f_prim takes low-res images and predicts geometric primitives
    primitives, prim_features = f_prim(low_res_images)
    
    # Stage 2: Texture Network
    # f_texture takes high-res images and prim_features to predict textures
    textures = f_texture(input_images, prim_features)
    
    return primitives, textures

def render_lgtm(primitives, textures, camera_poses, image_resolution):
    """
    Render the scene using textured Gaussian splatting.
    
    Args:
        primitives: List of Gaussian primitives.
        textures: List of per-primitive texture maps.
        camera_poses: Camera poses.
        image_resolution: Target resolution (H, W).
        
    Returns:
        rendered_image: Rendered RGB image.
    """
    # Initialize output image
    image = zeros(image_resolution)
    
    # For each pixel, find intersecting primitives
    for y in range(image_resolution[0]):
        for x in range(image_resolution[1]):
            ray = get_ray(camera_poses, x, y)
            intersections = find_ray_splat_intersections(ray, primitives)
            
            # Sort intersections by depth
            intersections.sort(key=lambda p: p.depth)
            
            accumulated_alpha = 0.0
            accumulated_color = zeros(3)
            
            for prim, u in intersections:
                # Retrieve texture values using bilinear sampling
                # u is the local coordinate on the primitive plane
                alpha_tex = textures[prim.id].alpha[u]
                color_tex = textures[prim.id].color[u]
                
                # Compute alpha and color
                # o is base opacity from primitive
                a = prim.opacity * alpha_tex
                c_sh = spherical_harmonics(prim.sh_coeffs, ray.direction)
                c = color_tex + c_sh
                
                # Alpha blending
                weight = a * (1.0 - accumulated_alpha)
                accumulated_color += weight * c
                accumulated_alpha += weight
                
                if accumulated_alpha > 0.99: # Early ray termination
                    break
            
            image[y, x] = accumulated_color
            
    return image

def train_lgtm():
    """
    Training loop for LGTM.
    """
    # Stage 1: Pre-train primitive network
    for epoch in range(num_epochs_stage1):
        low_res_images = get_low_res_batch()
        high_res_gt = get_high_res_gt_batch()
        
        primitives, prim_features = f_prim(low_res_images)
        rendered = render_lgtm(primitives, default_textures, camera_poses, high_res_gt.shape)
        
        loss = mse_loss(rendered, high_res_gt) + lpips_loss(rendered, high_res_gt)
        loss.backward()
        optimizer_prim.step()
        
    # Stage 2: Joint training
    for epoch in range(num_epochs_stage2):
        input_images = get_high_res_batch()
        low_res_images = get_low_res_batch()
        high_res_gt = get_high_res_gt_batch()
        
        # Freeze or reduce LR for prim network
        primitives, prim_features = f_prim(low_res_images)
        textures = f_texture(input_images, prim_features)
        
        rendered = render_lgtm(primitives, textures, camera_poses, high_res_gt.shape)
        
        loss = mse_loss(rendered, high_res_gt) + lpips_loss(rendered, high_res_gt)
        loss.backward()
        optimizer_joint.step()
```

**Edge Cases and Pitfalls:**
*   **Memory Constraints:** Standard feed-forward methods fail to train at 2K resolution or higher due to memory constraints (e.g., NoPoSplat requires >61 GB for 1024x576 primitives) [S1, unofficial]. LGTM mitigates this by decoupling geometry and appearance [S1, unofficial].
*   **Holes in Rendering:** Without high-resolution supervision in Stage 1, predicted Gaussians may result in areas with holes as they are not anti-aliased [S1, unofficial].
*   **Geometric Stability:** In Stage 2, the primitive network must be trained with a reduced learning rate (0.1×) or frozen to maintain geometric stability while the texture network learns [S1, unofficial].

## Operating characteristics
*   **Memory Usage:** LGTM trains successfully at 2K and 4K resolutions using under 30 GB of memory, whereas prior methods like NoPoSplat fail at these resolutions due to out-of-memory errors [S1, unofficial].
*   **Scalability:** At inference, a 64× pixel increase adds only modest memory and time overhead [S1, unofficial].
*   **Primitive Count:** LGTM uses significantly fewer Gaussian primitives than prior feed-forward methods by decoupling geometry from appearance [S1, unofficial].
*   **Strengths:** Enables high-fidelity 4K novel view synthesis in a feed-forward manner without per-scene optimization [S1, unofficial].
*   **Limitations:** Requires a staged training strategy and careful tuning of the texture resolution parameter $T$ [S1, unofficial].

## Background
LGTM was published as a conference paper at ICLR 2026 [S1, unofficial]. It addresses the limitations of existing feed-forward 3D Gaussian Splatting methods, which suffer from quadratic growth in primitive count as resolution increases, and textured Gaussian methods that require per-scene optimization [S1, unofficial]. It builds on the principles of feed-forward generalizable reconstruction [Parent].
