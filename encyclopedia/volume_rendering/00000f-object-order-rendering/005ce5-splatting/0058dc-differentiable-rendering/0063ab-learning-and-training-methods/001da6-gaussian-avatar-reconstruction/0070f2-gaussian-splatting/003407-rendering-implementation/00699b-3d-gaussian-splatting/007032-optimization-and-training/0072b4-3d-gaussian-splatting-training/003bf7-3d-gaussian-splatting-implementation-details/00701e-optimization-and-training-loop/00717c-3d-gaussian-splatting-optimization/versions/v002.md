# 3D Gaussian Splatting Optimization

Also called: 3DGS Training Procedure

## Overview
This method defines the stochastic gradient descent training procedure for 3D Gaussian Splatting, optimizing the position, covariance, opacity, and spherical harmonics coefficients of a set of 3D Gaussians to minimize photometric error against input images [S1, unofficial]. It distinguishes itself from other differentiable rendering methods by combining anisotropic covariance optimization with a specific densification strategy (splitting and cloning) and a staged introduction of spherical harmonics bands to handle angular visibility gaps [S1, unofficial].

## How it works
The optimization minimizes a composite loss function $\mathcal{L}$ between the rendered image $\hat{I}$ and the ground-truth image $I_{gt}$ [S1, unofficial]. The loss is defined as:
$$ \mathcal{L} = (1 - \lambda) \mathcal{L}_{L1} + \lambda \mathcal{L}_{D-SSIM} $$
where $\mathcal{L}_{L1}$ is the L1 loss, $\mathcal{L}_{D-SSIM}$ is the differentiable Structural Similarity index loss, and $\lambda = 0.2$ [S1, unofficial].

### Inputs and Outputs
*   **Inputs:** A set of training images $I_{gt}$ with known camera poses, and an initial set of 3D Gaussians $\mathcal{G}$.
*   **Outputs:** Optimized Gaussian parameters $\mathcal{G}^*$ (positions $\mathbf{p}$, covariances $\Sigma$, opacities $\alpha$, SH coefficients $\mathbf{c}$).

### Data Structures
The implementation uses Python/PyTorch with custom CUDA kernels for rasterization (extended from Kopanas et al. 2021) and NVIDIA CUB sorting routines for Radix sort [S1, unofficial]. The Gaussian parameters are stored in tensors compatible with PyTorch's automatic differentiation engine.

### Initialization
For synthetic bounded scenes (e.g., Blender dataset), initialization begins with 100,000 uniformly random Gaussians inside a volume enclosing the scene bounds [S1, unofficial]. These are automatically pruned to 6,000–10,000 meaningful Gaussians during early optimization [S1, unofficial]. For real-world scenes, initialization typically relies on Structure-from-Motion (SfM) points, though specific initialization counts for real scenes are not detailed in the primary source beyond the synthetic case [S1, unofficial].

### Optimization Steps
The training loop follows these steps:

1.  **Warm-up Resolution:** Start optimization at an image resolution 4 times smaller than the target resolution [S1, unofficial]. Upsample the resolution twice: once after 250 iterations and again after 500 iterations [S1, unofficial].
2.  **Spherical Harmonics Staging:** Initially, optimize only the zero-order (diffuse) component of the Spherical Harmonics (SH) to prevent incorrect color values in captures with missing angular regions [S1, unofficial]. Introduce one additional SH band every 1,000 iterations until all 4 bands are represented [S1, unofficial].
3.  **Rendering:** Project the 3D Gaussians to 2D screen space and alpha-blend them using a differentiable rasterizer to produce $\hat{I}$ [S1, unofficial].
4.  **Loss Computation:** Compute $\mathcal{L}$ using the formula above [S1, unofficial].
5.  **Backpropagation:** Compute gradients $\nabla \mathcal{L}$ with respect to all Gaussian parameters using automatic differentiation [S1, unofficial].
6.  **Update:** Update parameters using the Adam optimizer with $\beta_1 = 0.9$ and $\beta_2 = 0.99$ [S1, unofficial].
7.  **Densification/Pruning:** Periodically evaluate gradient magnitudes and opacity thresholds to split high-gradient Gaussians or prune low-opacity ones [S1, unofficial].

### Pseudocode
```python
def optimize_3dgs(training_images, initial_gaussians, target_resolution, total_iterations=30000):
    """
    Optimizes 3D Gaussians using the 3D Gaussian Splatting training procedure.
    """
    # Initialize optimizer with Adam (beta1=0.9, beta2=0.99)
    optimizer = Adam(initial_gaussians.parameters(), lr=initial_lr)
    
    # Warm-up resolution is 4x smaller
    current_resolution = target_resolution / 4
    
    for iteration in range(1, total_iterations + 1):
        # 1. Resolution Upsampling
        if iteration == 250 or iteration == 500:
            current_resolution = current_resolution * 2
            
        # 2. Sample Training View
        image, camera_pose = sample_training_view(training_images)
        
        # 3. Render
        # Project Gaussians to 2D and alpha-blend
        rendered_image = render_gaussians(initial_gaussians, camera_pose, current_resolution)
        
        # 4. Compute Loss
        # L_img = (1 - 0.2) * L1 + 0.2 * D-SSIM
        loss = compute_loss(rendered_image, image, lambda_weight=0.2)
        
        # 5. Backpropagation
        loss.backward()
        
        # 6. Update Parameters
        optimizer.step()
        optimizer.zero_grad()
        
        # 7. Spherical Harmonics Band Introduction
        # Start with zero-order only. Add one band every 1000 iterations.
        if iteration % 1000 == 0 and iteration > 0:
            activate_next_sh_band(initial_gaussians)
            
        # 8. Densification and Pruning
        # This step is typically performed periodically, not every iteration.
        # The exact frequency is not specified in the provided notes, 
        # but standard 3DGS implementations perform this every 100 iterations.
        if iteration % 100 == 0:
            densify_and_prune(initial_gaussians, gradient_threshold=0.0002, opacity_threshold=0.005)
            
    return initial_gaussians
```

### Edge Cases and Pitfalls
*   **Angular Missing Regions:** In captures with missing angular regions (e.g., corners, inside-out), optimizing all SH bands initially causes incorrect zero-order (diffuse) color values. This is mitigated by the staged SH introduction [S1, unofficial].
*   **Gradient Limiting:** Limiting gradient computation to only the front-most $N$ points (e.g., $N=10$) causes unstable optimization and severe quality degradation (11dB PSNR drop in the Truck scene) [S1, unofficial].
*   **Popping Artifacts:** Large Gaussians created during optimization can cause popping artifacts, partly due to trivial rejection via guard bands in the rasterizer and depth order switches [S1, unofficial].

## Operating characteristics
*   **Training Time:** For synthetic scenes, convergence to high quality occurs within 7,000 iterations (~8 minutes) [S1, unofficial]. For real-world scenes like Mip-NeRF360, training takes 35–45 minutes on a single A6000 GPU (equivalent to 12 hours on a 4-GPU A100 node for Mip-NeRF360, which takes 48 hours single-GPU equivalent) [S1, unofficial]. Tanks & Temples scenes take ~7 minutes [S1, unofficial].
*   **Rendering Speed:** Trained synthetic scenes render at 180–300 FPS [S1, unofficial]. Mip-NeRF360 renders at 10s/frame [S1, unofficial].
*   **Model Size:** For synthetic scenes, the final model size after 30,000 iterations is 200,000–500,000 Gaussians [S1, unofficial]. Compared to Zhang et al. [2022], 3DGS uses ~1/4 the point count, resulting in a 3.8 MB model size vs 9 MB [S1, unofficial].
*   **Quality:** Achieves comparable quality to InstantNGP/Plenoxels in 5–10 minutes, surpassing them with additional time. Matches or slightly exceeds Mip-NeRF360 quality after full convergence [S1, unofficial].
*   **Strengths:** Anisotropic covariance significantly improves surface alignment and rendering quality compared to isotropic models [S1, unofficial]. Cloning small Gaussians aids convergence for thin structures; splitting big Gaussians aids background reconstruction [S1, unofficial].
*   **Limitations:** Artifacts appear in poorly observed regions. Elongated or "splotchy" Gaussians may form. Popping artifacts can occur in regions with view-dependent appearance [S1, unofficial].

## Background
3D Gaussian Splatting was introduced by Kerbl et al. [2023] as a real-time radiance field rendering method [S1, unofficial]. The rasterization kernels are extended versions of methods by Kopanas et al. [2021], and the sorting uses routines from Merrill and Grimshaw [2010] [S1, unofficial]. The method was evaluated on 13 real scenes (Mip-NeRF360, Tanks&Temples, Hedman et al.) and the synthetic Blender dataset [S1, unofficial]. Hardware used was primarily A6000 GPU, except for Mip-NeRF360 which was trained on a 4-GPU A100 node [S1, unofficial].
