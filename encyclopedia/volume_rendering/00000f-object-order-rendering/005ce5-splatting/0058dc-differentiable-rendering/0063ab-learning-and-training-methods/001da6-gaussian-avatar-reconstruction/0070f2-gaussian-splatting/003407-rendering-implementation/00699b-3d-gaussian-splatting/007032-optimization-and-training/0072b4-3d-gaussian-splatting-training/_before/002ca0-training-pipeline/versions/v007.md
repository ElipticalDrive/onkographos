# Training Pipeline

Also called: Full Training Procedure, Iterative optimization loop, Main Training Loop

## Overview
The Training Pipeline is the iterative optimization loop for 3D Gaussian Splatting that samples camera views, rasterizes the current set of 3D Gaussians, computes a loss against ground truth images, and updates Gaussian parameters via backpropagation [S1, S2, unofficial]. It differs from sibling methods by defining the high-level orchestration of the training state, whereas siblings like [MaskGaussian Gradient Computation](4254-maskgaussian-gradient-computation.md) focus on specific gradient masking strategies and [Parallelization for Backpropagation](5989-parallelization-for-backpropagation.md) focuses on the computational distribution of the backward pass.

## How it works
**Inputs and Outputs:**
*   **Inputs:** A sparse point cloud (initializing Gaussian positions), extra features (initial colors, SH coefficients, covariances), and a sequence of camera poses with corresponding ground truth images.
*   **Outputs:** An optimized set of 3D Gaussians with updated positions, covariances, opacities, colors, and SH coefficients.

**Data Structures:**
The core state is `WeightToTrain`, which contains the mutable parameters of the Gaussians:
*   `sparsePointCloud`: Array of 3D positions $(x, y, z)$.
*   `pointCloudExtraFeatures`: Concatenated attributes including base color, spherical harmonic (SH) coefficients, opacity $\alpha$, and covariance matrix parameters (rotation quaternion $q$ and scale vector $s$) [S1, unofficial].

**Algorithm Steps:**
1.  **View Sampling:** Select a random camera pose and its corresponding ground truth image from the training set [S1, S2, unofficial].
2.  **Hierarchy Cutting (Optional):** If using a hierarchical structure (e.g., Level-of-Detail), cut the hierarchy based on the camera distance to identify the active subset of Gaussians (the "cut set") [S2, unofficial].
3.  **Rasterization:** Pass the active Gaussians and camera pose to the differentiable rasterizer. The rasterizer projects 3D Gaussians to 2D ellipses, sorts them by depth, and performs alpha blending to produce the rendered image $\mathbf{I}_r$ [S1, S2, unofficial].
4.  **Loss Computation:** Compare the rendered image $\mathbf{I}_r$ with the ground truth image $\mathbf{I}_{gt}$ using a composite loss function $\mathcal{L}$, typically combining L1 loss and Structural Similarity (SSIM) [S1, unofficial][S3].
5.  **Backpropagation:** Compute gradients of $\mathcal{L}$ with respect to the Gaussian parameters. Gradients flow through the alpha blending chain to update position, covariance, opacity, and color [S1, S2, unofficial].
6.  **Parameter Update:** Apply the gradients to the `WeightToTrain` state using an optimizer (e.g., Adam) [S1, unofficial].
7.  **Adaptive Control (Periodic):** Every $N$ iterations, perform densification (cloning/splitting) and pruning based on gradient magnitudes and opacity thresholds to manage Gaussian count [S1, unofficial][S3].

**Formulas:**
The total loss $\mathcal{C}_{\text{total}}$ is defined as:
$$
\mathcal{C}_{\text{total}} = \mathcal{L}_1 (\mathbf{I}_r, \mathbf{I}_{gt}) + \alpha_{\text{SSIM}} \mathcal{L}_{\text{SSIM}} (\mathbf{I}_r, \mathbf{I}_{gt})
$$
where $\alpha_{\text{SSIM}}$ is the weight for the SSIM term [S1, unofficial][S3].

In variants like FaCT-GS, a Total Variation (TV) loss is added:
$$
\mathcal{C}_{\text{total}} = \mathcal{L}_1 (\mathbf{I}_r, \mathbf{I}_{gt}) + \alpha_{\text{SSIM}} \mathcal{L}_{\text{SSIM}} (\mathbf{I}_r, \mathbf{I}_{gt}) + \alpha_{\text{TV}} \mathcal{L}_{\text{TV}} (\mathbf{V}_{32^3})
$$
where $\mathbf{V}_{32^3}$ is a randomly sampled voxelized volume section of size $32^3$ [S3].

**Parameters:**
*   $\alpha_{\text{SSIM}}$: SSIM loss weight. Typical value: 0.2 [S1, unofficial][S3].
*   $\alpha_{\text{TV}}$: TV loss weight (FaCT-GS only). Value not given in sources.
*   Voxelization sampling size: Increased from $8^3$ to $32^3$ in FaCT-GS [S3].

**Edge Cases and Pitfalls:**
*   **Gradient Diffusion:** In hierarchical methods, updating only the cut set may leave deeper hierarchy nodes unupdated in early iterations. This is mitigated by ensuring diverse view coverage over time [S2, unofficial].
*   **Memory:** Large scenes require caching or out-of-core techniques to manage the Gaussian list [S2, unofficial].

**Pseudocode:**
```python
def training_pipeline(sparse_point_cloud, extra_features, camera_poses, gt_images):
    # Initialize trainable weights
    weights = WeightToTrain(sparse_point_cloud, extra_features)
    
    for iteration in range(max_iterations):
        # 1. Sample view
        idx = random_index(len(camera_poses))
        camera = camera_poses[idx]
        gt_img = gt_images[idx]
        
        # 2. Rasterize
        # If using hierarchy, cut set is determined here
        rendered_img = rasterize(weights, camera)
        
        # 3. Compute Loss
        l1_loss = compute_l1(rendered_img, gt_img)
        ssim_loss = compute_ssim(rendered_img, gt_img)
        total_loss = l1_loss + alpha_ssim * ssim_loss
        
        # Optional: Add TV loss if using FaCT-GS variant
        if use_fact_gs:
            voxels = voxelize_random_section(weights, size=32**3)
            tv_loss = compute_total_variation(voxels)
            total_loss += alpha_tv * tv_loss
            
        # 4. Backpropagate
        gradients = backward_pass(total_loss, weights)
        
        # 5. Update Weights
        optimizer.step(weights, gradients)
        
        # 6. Periodic Adaptive Control (Densification/Pruning)
        if iteration % densification_interval == 0:
            weights = adaptive_control(weights, gradients)
            
    return weights
```

## Subtopics

### [Mini-Splatting Pipeline](9235-mini-splatting-pipeline.md)
The Mini-Splatting Pipeline is a training strategy that explicitly manages the total number of Gaussians through periodic densification, simplification, and depth-based reinitialization phases. It distinguishes itself from standard 3D Gaussian Splatting by enforcing a constrained Gaussian count via a manually controlled sampling ratio.

### [Validation Metric Computation & Logging](10760-validation-metric-computation-logging.md)
This method computes quantitative validation metrics (primarily PSNR) and saves visual examples by rendering novel views from the optimized model and comparing them against ground truth images. It is distinct from the training loop as it operates in evaluation mode (`is_train=False`) with gradient tracking disabled, ensuring that the optimization state is not updated during metric calculation.

### FaCT-GS Optimization Loop
FaCT-GS extends the standard loop by adding a Total Variation (TV) regularization prior on a randomly sampled voxelized volume section [S3]. It uses a larger voxelization sampling size ($32^3$) compared to prior works ($8^3$) [S3]. The loss function includes $\mathcal{L}_{TV}$ weighted by $\alpha_{TV}$ [S3].

### Cut-Set Gradient Update
In hierarchical training (e.g., LoD of Gaussians), this variant updates only the parameters of the "cut set" of Gaussians intersecting the current training view [S2, unofficial]. Gradients propagate to Gaussians in the middle of the hierarchy, diffusing across the entire structure over many iterations with diverse views [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of active Gaussians and pixels per iteration. The backward pass is the primary bottleneck [S3].
*   **Memory Complexity:** Linear with respect to the number of Gaussians. Hierarchical methods reduce memory pressure by only loading active subsets [S2, unofficial].
*   **Strengths:** Differentiable rasterization allows end-to-end optimization of 3D structure from 2D images. Parallelization across pixels and Gaussians enables real-time rendering during training [S2, unofficial].
*   **Limitations:** High memory usage for large scenes; requires careful tuning of densification parameters to avoid explosion of Gaussian count [S1, unofficial].
*   **When to use:** Standard 3D Gaussian Splatting reconstruction.
*   **When not to use:** When memory is extremely constrained (use hierarchical variants like [Grendel-GS](7349-grendel-gs.md) or [A LoD of Gaussians](6233-optimization-and-parallelization.md)).

## Background
The training pipeline originates from the 3D Gaussian Splatting method by Kerbl et al. [2023], which introduced differentiable rasterization for 3D Gaussians [S2, unofficial]. Subsequent works have extended this pipeline to handle larger scenes (hierarchical cutting) and specific domains like CT reconstruction (FaCT-GS) [S2, unofficial][S3].
