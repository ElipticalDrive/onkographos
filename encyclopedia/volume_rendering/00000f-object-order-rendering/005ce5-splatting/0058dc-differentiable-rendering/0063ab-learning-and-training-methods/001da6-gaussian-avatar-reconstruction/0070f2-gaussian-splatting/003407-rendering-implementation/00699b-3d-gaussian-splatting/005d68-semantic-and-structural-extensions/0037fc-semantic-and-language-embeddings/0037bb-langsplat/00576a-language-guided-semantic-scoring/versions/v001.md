# Language-Guided Semantic Scoring

Also called: Semantic Scoring via CLIP

## Overview
Language-Guided Semantic Scoring computes per-Gaussian semantic probabilities by comparing learned visual features against text embeddings from a vision-language model (VLM) such as CLIP [S1]. It enables open-vocabulary semantic segmentation and editing in 3D Gaussian Splatting by rendering feature maps that are compared against text embeddings [S1]. Unlike methods that align primitives directly in image-embedding space to preserve richer latent semantics [S2], this approach typically operates in a text-embedding space using inner products followed by softmax normalization [S1].

## How it works
**Inputs:**
- A set of $N$ 3D Gaussians, each with an associated semantic feature vector $f_j \in \mathbb{R}^d$ (where $d$ is the feature dimension, typically 512 for CLIP ViT-B/32 [S1]).
- A set of $C$ text categories or labels $\{l_1, \dots, l_C\}$ [S1].

**Outputs:**
- A semantic score matrix $S \in \mathbb{R}^{N \times C}$, where $S_{j,c}$ represents the probability that Gaussian $j$ belongs to category $c$ [S1].

**Data Structures:**
- **Gaussian Semantic Features:** Stored as a matrix $F \in \mathbb{R}^{N \times d}$. Each row $f_j$ corresponds to the semantic feature of the $j$-th Gaussian. These features are typically extracted during training or inference using a teacher encoder (e.g., CLIP image encoder) [S1].
- **Text Embeddings:** Stored as a matrix $T \in \mathbb{R}^{C \times d}$. Each row $t_i$ is the text embedding for category $i$ [S1].

**Steps:**
1. **Text Encoding:** Encode each of the $C$ text categories using the CLIP ViT-B/32 text encoder to obtain text feature vectors $t_i \in \mathbb{R}^{512}$ [S1].
2. **Inner Product Calculation:** Compute the dot product between each Gaussian's semantic feature $f_j$ and each text embedding $t_i$. This results in a raw score matrix $P \in \mathbb{R}^{N \times C}$ where $P_{j,i} = f_j^\top t_i$ [S1].
3. **Softmax Normalization:** Apply a softmax function along the category dimension (columns) to normalize the scores into probabilities [S1].

**Formula:**
The semantic score $S_{j,i}$ for Gaussian $j$ and category $i$ is calculated as:
$$ S_{j,i} = \frac{\exp(f_j^\top t_i)}{\sum_{k=1}^{C} \exp(f_j^\top t_k)} $$
where $f_j$ is the semantic feature of the $j$-th Gaussian, $t_i$ is the text embedding for the $i$-th category, and $C$ is the total number of categories [S1].

**Parameters:**
- **Temperature:** Not explicitly defined in the primary source [S1]. Standard implementations may use a temperature scaling factor $\tau$ in the exponent, i.e., $\exp(f_j^\top t_i / \tau)$, but the source describes a direct inner product followed by softmax [S1].
- **Threshold ($t_h$):** Used for hard selection during editing. If $S_{j,i} \ge t_h$, the Gaussian is selected [S1]. The specific value is not given in the sources.

**Edge Cases and Pitfalls:**
- **Precision:** The inner product and softmax operations are sensitive to the magnitude of the embeddings. Ensuring that $f_j$ and $t_i$ are normalized (e.g., L2 normalized) before the dot product can stabilize training and inference [G].
- **Category Mismatch:** If the text encoder is not aligned with the visual encoder used for $f_j$, scores may be unreliable. The source assumes a consistent CLIP model [S1].
- **Degenerate Input:** If a Gaussian has zero or near-zero semantic features, the softmax output will be uniform across categories, providing no semantic guidance [G].

**Pseudocode:**
```python
import torch
import torch.nn.functional as F

def compute_semantic_scores(gaussian_features: torch.Tensor, text_embeddings: torch.Tensor) -> torch.Tensor:
    """
    Compute semantic scores for 3D Gaussians based on text embeddings.
    
    Args:
        gaussian_features: Tensor of shape (N, d), where N is the number of Gaussians 
                           and d is the feature dimension (e.g., 512).
        text_embeddings: Tensor of shape (C, d), where C is the number of categories.
        
    Returns:
        scores: Tensor of shape (N, C) containing semantic probabilities.
    """
    # Step 1: Compute inner products between Gaussian features and text embeddings
    # Resulting shape: (N, C)
    raw_scores = torch.matmul(gaussian_features, text_embeddings.T)
    
    # Step 2: Apply softmax along the category dimension (dim=1)
    # This normalizes the scores so that they sum to 1 for each Gaussian
    scores = F.softmax(raw_scores, dim=1)
    
    return scores

def select_gaussians(scores: torch.Tensor, category_index: int, threshold: float) -> torch.Tensor:
    """
    Select Gaussians for a specific category based on a threshold.
    
    Args:
        scores: Tensor of shape (N, C).
        category_index: Index of the category to select (0 to C-1).
        threshold: Minimum score required for selection.
        
    Returns:
        mask: Boolean tensor of shape (N,) indicating selected Gaussians.
    """
    # Extract the column for the specified category
    category_scores = scores[:, category_index]
    
    # Apply binary thresholding
    mask = category_scores >= threshold
    
    return mask
```

## Subtopics

### Gaussian Language Feature Labeling
A variant that assigns semantic labels to 3D Gaussian primitives based on user text queries by computing cosine similarity rather than inner product with softmax [S2]. It represents the scene as $N$ Gaussian primitives $G_j \in \mathbb{R}^{59}$ (encoding position, covariance, color, opacity, etc.) [S2]. For each primitive $G_j$, a language embedding $E^G_j \in \mathbb{R}^d$ is computed, either via per-scene processing or a learned encoder [S2]. User queries $c_i$ are mapped to embeddings $E^T_i$ using a frozen text encoder (e.g., CLIP) [S2]. The label for $G_j$ is the index $i$ that maximizes cosine similarity: $\text{label}(G_j) = \arg \max_i \cos(E^G_j, E^T_i)$ [S2]. This method avoids information loss inherent in textual descriptions by aligning in image-embedding space [S2].

## Operating characteristics
- **Time Complexity:** $O(N \cdot C \cdot d)$ for computing the score matrix, where $N$ is the number of Gaussians, $C$ is the number of categories, and $d$ is the feature dimension [S1]. This is efficient enough for real-time rendering if $C$ is small or fixed [S1].
- **Memory Complexity:** $O(N \cdot d + C \cdot d)$ to store Gaussian features and text embeddings [S1].
- **Performance:** The performance is limited by the capability of the teacher encoders used to generate the feature maps [S1]. Using CLIP ViT-B/32 provides a balance between speed and semantic richness [S1].
- **Strengths:** Enables open-vocabulary editing and segmentation without retraining the 3DGS model for each new category [S1]. Supports both hard and soft selection for editing operations [S1].
- **Limitations:** Relies on the quality of the pre-trained CLIP model [S1]. May not capture fine-grained details as well as methods that align in image-embedding space [S2].

## Background
The method was introduced in "Feature 3DGS: Supercharging 3D Gaussian Splatting to Enable Distilled Feature Fields" [S1]. It builds on the idea of using teacher encoders to distill semantic information into 3D Gaussian primitives [S1]. The approach leverages the strong zero-shot capabilities of CLIP to enable semantic understanding in 3D scenes [S1].
