# Gaussian Geometry Parameters Prediction

Also called: EVolSplat, Efficient Volume-based Gaussian Splatting, GRM, Gaussian MLP Heads, Gaussian Representation Model

## Overview
Gaussian Geometry Parameters Prediction is a feed-forward method that predicts the geometric attributes (position, opacity, covariance) of 3D Gaussians from a global volumetric feature representation, rather than regressing them per-pixel from 2D image features [S2]. It solves the problem of ghosting artifacts and multi-view inconsistencies inherent in pixel-aligned Gaussian prediction methods by accumulating depth information into a unified 3D volume and refining Gaussian positions via learned offsets [S2]. Unlike standard initialization methods that use static point clouds, this approach iteratively refines geometry during the prediction phase to align Gaussians with the underlying scene structure [S2].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of $N$ sparse input images $\{I_n\}_{n=1}^N$ with known camera poses (intrinsic matrices $K_n$, extrinsic matrices $T_n = [R_n | t_n]$) and optional monocular depth estimates $\{D_n\}_{n=1}^N$ [S2].
*   **Outputs:** A set of 3D Gaussians $\mathcal{G} = \{(\mu_i, \alpha_i, \Sigma_i, c_i)\}_{i=1}^{N_p}$, where $\mu_i$ is the center, $\alpha_i$ is the opacity, $\Sigma_i$ is the covariance matrix, and $c_i$ is the view-dependent color [S2].

**Data Structures:**
1.  **Global Point Cloud ($P$):** A set of 3D points in world coordinates, $P \in \mathbb{R}^{N_p \times 3}$, constructed by unprojecting RGB-D data from all input views [S2].
2.  **Feature Volume ($F$):** A sparse 3D tensor $F \in \mathbb{R}^{H \times W \times D \times C}$ extracted by a sparse 3D CNN, aligned with the world coordinate system [S2].
3.  **MLP Heads:** Three independent Multi-Layer Perceptrons:
    *   $\mathcal{D}_{pos}$: Predicts position offset $\Delta \mu_i$.
    *   $\mathcal{D}_{opa}$: Predicts opacity $\alpha_i$.
    *   $\mathcal{D}_{cov}$: Predicts covariance matrix $\Sigma_i$ [S2].

**Numbered Steps:**

1.  **Depth Estimation and Filtering:**
    *   Predict metric depth maps $\{D_n\}$ for each input image $\{I_n\}$ using an off-the-shelf estimator (e.g., Metric3D, Unidepth) [S2].
    *   Apply a depth consistency check to remove inconsistent depth values [S2].
    *   Unproject the RGB images and depth maps into 3D space using $K_n$ and $T_n$ to form a raw point cloud:
        $$ P_{raw} = \bigcup_{n=1}^N \pi^{-1}(I_n, D_n, T_n, K_n) $$
        where $\pi^{-1}$ denotes pixel unprojection [S2].
    *   Apply a **uniform filter** to $P_{raw}$ to delete duplicate primitives while preserving scene structure [S2].
    *   Apply a **statistical filter** to remove floating artifacts (noise) from the filtered points, resulting in the clean global point cloud $P$ [S2].

2.  **Feature Volume Extraction:**
    *   Construct a sparse tensor from the points in $P$.
    *   Pass the sparse tensor through a sparse 3D CNN (e.g., sparse U-Net) to extract the neural feature volume $F$ [S2].

3.  **Initialization:**
    *   Initialize the Gaussian centers $\mu^{init}_i$ using the points in $P$: $\mu^{init}_i = p_i \in P$ for $i=1 \dots N_p$ [S2].

4.  **Geometry Parameters Prediction (Iterative Refinement):**
    *   For each Gaussian $i$, maintain a previous position offset $\Delta \mu^{prev}_i$ (initialized to 0 for the first iteration or inference) [S2].
    *   Query the feature volume $F$ at the refined position $\mu^{init}_i + \Delta \mu^{prev}_i$ using trilinear interpolation to obtain the feature vector $f_i$:
        $$ f_i = F(\mu^{init}_i + \Delta \mu^{prev}_i) $$
    *   Decode the geometry attributes using the MLP heads:
        $$ \alpha_i = \mathcal{D}_{opa}(f_i) $$
        $$ \Sigma_i = \mathcal{D}_{cov}(f_i) $$
        $$ \Delta \mu_i = \text{Tanh}(\mathcal{D}_{pos}(f_i)) \cdot v_{\text{size}} $$
        where $v_{\text{size}}$ is the voxel size used to scale the offset [S2].
    *   Update the Gaussian center:
        $$ \mu_i = \mu^{init}_i + \Delta \mu_i $$
    *   **Training:** Track $\Delta \mu_i$ from the current iteration as $\Delta \mu^{prev}_i$ for the next iteration. The network learns to gradually move Gaussians to correct locations [S2].
    *   **Inference:** Initialize $\Delta \mu^{prev}_i = 0$. Recursively execute the query and update steps (Eq. 4 and 6 in [S2]) twice to obtain a converged $\Delta \mu_i$. Use the converged point to query $\alpha_i$ and $\Sigma_i$ [S2].

5.  **Color Prediction:**
    *   Project the 3D Gaussians to the nearest $K$ reference views to retrieve 2D context, including color windows $\{c_k\}_{k=1}^K$ and visibility maps [S2].
    *   Decode the Gaussian color $c_i$ using the retrieved 2D context (Image-Based Rendering technique) [S2].

6.  **Background Handling (Optional/Hybrid):**
    *   Model distant views and the sky with a generalizable hemisphere Gaussian model where geometry is fixed and color is predicted similarly to the foreground [S2].
    *   Compose foreground and background to reconstruct the full image [S2].

**Pseudocode:**

```python
def predict_gaussian_geometry(input_images, camera_poses, depth_estimator, sparse_3d_cnn, 
                              d_pos, d_opa, d_cov, voxel_size, num_inference_iters=2):
    """
    Predicts 3D Gaussian geometry parameters from input images.
    
    Args:
        input_images: List of N RGB images.
        camera_poses: List of N camera poses (K, R, t).
        depth_estimator: Function to predict depth maps.
        sparse_3d_cnn: Sparse 3D CNN to extract feature volume.
        d_pos, d_opa, d_cov: MLP heads for position, opacity, covariance.
        voxel_size: Scaling factor for position offset.
        num_inference_iters: Number of recursive updates during inference.
        
    Returns:
        gaussians: List of Gaussian objects with mu, alpha, sigma, color.
    """
    # 1. Depth Estimation and Point Cloud Construction
    depth_maps = [depth_estimator(img) for img in input_images]
    raw_points = []
    for img, depth, (K, R, t) in zip(input_images, depth_maps, camera_poses):
        # Unproject RGB-D to 3D world coordinates
        points_3d = unproject_rgb_depth(img, depth, K, R, t)
        raw_points.append(points_3d)
    
    # Concatenate all points
    P_raw = concatenate(raw_points)
    
    # 2. Filtering
    # Uniform filter to remove duplicates
    P_filtered = uniform_filter(P_raw)
    # Statistical filter to remove floaters
    P_clean = statistical_filter(P_filtered)
    
    # 3. Feature Volume Extraction
    # Construct sparse tensor from P_clean
    sparse_tensor = create_sparse_tensor(P_clean)
    # Extract feature volume F
    F = sparse_3d_cnn(sparse_tensor)
    
    # 4. Initialization
    # Initialize Gaussian centers from clean point cloud
    mu_init = P_clean
    N_p = len(mu_init)
    
    # Initialize previous offsets to 0
    delta_mu_prev = np.zeros_like(mu_init)
    
    # 5. Geometry Prediction
    gaussians = []
    
    for i in range(N_p):
        # Determine query position
        if is_training():
            # During training, use previous iteration's offset
            query_pos = mu_init[i] + delta_mu_prev[i]
        else:
            # During inference, iterate to converge
            query_pos = mu_init[i] + delta_mu_prev[i]
            for _ in range(num_inference_iters):
                # Query feature at current query_pos
                f_i = trilinear_interpolate(F, query_pos)
                # Predict new offset
                delta_mu_i = tanh(d_pos(f_i)) * voxel_size
                # Update query position for next iteration
                query_pos = mu_init[i] + delta_mu_i
            # Final converged position
            mu_i = query_pos
            
        # Query feature at final position
        f_i = trilinear_interpolate(F, query_pos)
        
        # Decode attributes
        alpha_i = d_opa(f_i)
        sigma_i = d_cov(f_i)
        
        # If training, update delta_mu_prev for next iteration
        if is_training():
            delta_mu_prev[i] = tanh(d_pos(f_i)) * voxel_size
            
        # 6. Color Prediction (Simplified)
        # Retrieve 2D context from nearest K views
        color_window, visibility = retrieve_2d_context(mu_i, camera_poses, input_images)
        color_i = decode_color(color_window, visibility)
        
        gaussians.append(Gaussian(mu=mu_i, alpha=alpha_i, sigma=sigma_i, color=color_i))
        
    return gaussians
```

**Parameters:**
*   $N$: Number of input images [S2].
*   $v_{\text{size}}$: Voxel size used to scale the position offset output of the Tanh activation [S2].
*   $K$: Number of nearest reference views used for retrieving 2D context [S2].

**Edge Cases and Pitfalls:**
*   **Ghosting Artifacts:** Pixel-aligned methods generate redundant and inconsistent primitives in overlapping regions. This method addresses this by using a global volume and filtering duplicates [S2].
*   **Depth Noise:** Monocular depth predictions contain noise and floating artifacts. This method handles this by applying a statistical filter to remove floaters after uniform filtering [S2].
*   **Recursive Convergence:** The position offset $\Delta \mu_i$ depends on the feature queried at the updated position. During inference, this requires iterative updates. The sources state that executing the recursion twice is sufficient to obtain a converged $\Delta \mu_i$ [S2].

## Subtopics

### [Textured-GS](9436-textured-gs.md)
Textured-GS enhances the textural representation of individual 3D Gaussians by modeling spatially defined color and opacity variations across the Gaussian ellipsoidal surface using Spherical Harmonics (SH), without increasing the number of Gaussians or adding extra parameters beyond the existing SH framework. Unlike standard 3D Gaussian Splatting (3DGS) where each Gaussian retains a fixed opacity and shows a single color when viewed from a specific direction, Textured-GS enables color variation across the Gaussian ellipsoidal surface and opacity variations, allowing for deviations from the standard ellipsoidal shape such as 'unidirectional Gaussians' that are opaque on one side and transparent on the other. It differs from Gaussian Geometry Parameters Prediction by using the surface intersection vector for SH evaluation instead of the viewing vector, allowing spatial variation of color/opacity within a single Gaussian.

### [3D Skew-Normal Splatting](10045-3d-skew-normal-splatting.md)
3D Skew-Normal Splatting (SNS) replaces the standard symmetric 3D Gaussian kernel with the Azzalini Skew-Normal distribution to model asymmetric structures, such as sharp boundaries and one-sided surfaces, while preserving analytical tractability under affine transformations. It sets apart from standard Gaussian Splatting and its symmetric variants (e.g., Textured-GS, Oriented Gaussian Splatting) by introducing a learnable skewness parameter that allows continuous interpolation between symmetric Gaussians and half-ellipsoids, enabling a single primitive to represent complex geometries that would otherwise require multiple overlapping kernels.

### [Deformable 3D Gaussian Splatting](10060-deformable-3d-gaussian-splatting.md)
Deformable 3D Gaussian Splatting is a method for dynamic scene reconstruction that learns 3D Gaussians in a canonical (static) space and models spatial-temporal deformation using an implicit deformation field implemented as a Multi-Layer Perceptron (MLP). It differs from static 3D Gaussian Splatting by introducing time-dependent offsets to Gaussian attributes, and from other dynamic variants like Mesh-Embedded Gaussian Splatting by relying on an implicit MLP rather than explicit mesh constraints or voxel grids.

### [Fourier Splatting Primitive](11094-fourier-splatting-primitive.md)
The Fourier Splatting primitive is a planar surfel for radiance field rendering that replaces the fixed Gaussian or elliptical falloff with a boundary defined by a Fourier series, allowing the representation of arbitrary closed shapes. Unlike 3D Gaussian Splatting (3DGS) or 2D Gaussian Splatting (2DGS), which are limited to fixed elliptical or disc shapes, this primitive enables higher fidelity representation of complex geometry and fine-grained details. Its key differentiator is inherent scalability: the level of detail (LoD) is controlled by truncating Fourier coefficients at runtime, allowing a single trained model to be rendered at varying complexities without retraining or post-hoc compression.

### [Conditional Slicing Mechanism](11455-conditional-slicing-mechanism.md)
The Conditional Slicing Mechanism conditions a 7-dimensional Gaussian (defined over spatial, temporal, and angular dimensions) on observed time $t$ and view direction $d$ to yield a conditional 3D Gaussian governing the spatial component. This operation "slices" the full 7D distribution to integrate temporal dynamics and view-dependent effects into the traditional 3D rendering pipeline without introducing additional temporal dependencies in the spherical harmonics. It sets itself apart from static Gaussian Splatting variants by explicitly modeling the joint distribution of space, time, and view, allowing the spatial mean and covariance to shift based on the current rendering context.

### [Structure-Aware 3D Gaussian Splatting (SAGS)](11908-structure-aware-3d-gaussian-splatting-sags.md)
Structure-Aware 3D Gaussian Splatting (SAGS) is a novel-view synthesis method that implicitly encodes scene geometry using a local-global graph representation to facilitate learning complex scenes and enforce meaningful point displacements that preserve structure, thereby reducing floating-point artifacts and storage requirements. Unlike standard 3D Gaussian Splatting which optimizes each Gaussian independently, SAGS leverages inter- and intra-connectivity between 3D point positions via Graph Neural Networks (GNNs) to predict Gaussian attributes, outperforming 3D-GS and Scaffold-GS in capturing high-frequency details while significantly reducing memory footprint.

### [Mesh-embedded representation](12559-mesh-embedded-representation.md)
Mesh-embedded representation anchors 3D Gaussians to a canonical triangle mesh $\mathcal{M}$ to disentangle motion from appearance. It solves the problem of coherent, editable deformation in 3D Gaussian Splatting (3DGS) by parameterizing Gaussian positions via barycentric coordinates and normal displacement on mesh faces, allowing explicit motion control through mesh editing or skeletal animation. It sets itself apart from nearest alternatives like GaMeS by explicitly controlling Gaussian rotation and translation directly via the mesh geometry rather than relying on implicit MLP-based linear blend skinning (LBS) fields, ensuring compatibility with standard animation techniques.

### [AnySplat Pipeline](12847-anysplat-pipeline.md)
AnySplat is a feed-forward neural network that predicts a set of 3D Gaussians directly from uncalibrated input images, enabling novel-view synthesis without iterative optimization. It differs from inverse methods by using a transformer-based encoder-decoder architecture to predict Gaussian parameters, depth, and camera poses in a single forward pass, bypassing the need for per-scene optimization.

### [Inverse Gaussian Splattling](13193-inverse-gaussian-splattling.md)
Inverse Gaussian Splattling is a method for initializing 3D Gaussian primitives by back-projecting optimized 2D Gaussian kernels from image space into world space. It solves the problem of generating high-quality initial geometric parameters (position, rotation, scale) for new 3D Gaussians from 2D renderings, specifically handling foreground-background ambiguity in boundary regions. It differs from standard initialization by using Weighted Principal Component Analysis (WPCA) on clustered 3D points derived from depth maps, followed by a scaling calibration step to align the projected 3D covariance with the original 2D target.

### [Occupancy-Opacity Factorization](13440-occupancy-opacity-factorization.md)
Occupancy-Opacity Factorization decouples a Gaussian primitive's geometric presence from its optical properties by splitting the single standard opacity parameter into two learnable attributes: geometric occupancy ($\sigma$) and optical opacity ($\alpha$). This solves the problem where a single opacity parameter cannot simultaneously model a surface that is geometrically solid (for sharp reflections) yet optically clear (for light transmission). It sets itself apart from siblings like Textured-GS and Oriented Gaussian Splatting by explicitly modeling the probabilistic interaction of rays with the Gaussian substance, enabling deferred shading for high-frequency reflection modeling.

### [QuickSplat](15256-quicksplat.md)
QuickSplat is a method for fast 3D surface reconstruction of large indoor scenes from multi-view images that combines three learned data prior networks (initializer, densifier, optimizer) in an iterative densification-optimization loop to accelerate convergence and improve geometry in under-observed regions. It differs from standard 3D Gaussian Splatting (3DGS) and its variants like 2DGS or SuGaR by replacing heuristic-based densification and gradient descent with learned networks that jointly predict new Gaussians and update vectors, thereby removing heuristics and handling textureless regions better. Unlike methods relying solely on photometric errors, QuickSplat leverages learned geometry priors to reconstruct flat wall structures and object details in large-scale indoor environments.

### [FineSplat](15257-finesplat.md)
FineSplat is a feed-forward 3D Gaussian Splatting (3DGS) framework that predicts a set of 3D Gaussians from $N$ context views (with or without known poses) using a two-stage dual-grouping strategy to balance local detail preservation with global multi-view reasoning. It distinguishes itself from sibling methods like YoNoSplat and ZipSplat by employing high-resolution 4x4 patch tokens and a dual-grouping strategy (view-wise and 3D spatial locality) to preserve fine-grained visual information while avoiding the prohibitive costs of global multi-view attention.

### [CAG-GS Semantic Mapping and Gaussian Generation](15260-cag-gs-semantic-mapping-and-gaussian-generation.md)
CAG-GS generates implicit 3D Gaussians from semantic anchors by encoding spatial positions into high-dimensional semantic vectors via a multi-resolution hash grid, which are then fused with anchor features to predict Gaussian attributes. It distinguishes itself from standard 3D Gaussian Splatting by incorporating semantic guidance and geometric consistency constraints (normal and flattening losses) to improve global consistency in large-scale scenes, utilizing a coarse-to-fine training strategy.

### [HO-Gaussian](15368-ho-gaussian.md)
HO-Gaussian is a point-free representation method for multi-camera urban scenes that combines a grid-based volume with the 3D Gaussian Splatting (3DGS) pipeline to eliminate dependency on Structure-from-Motion (SfM) point initialization. It solves the problem of rendering low-texture, sky, and distant areas in large-scale urban environments where standard 3DGS fails due to sparse or outlier-prone SfM data. Unlike standard 3DGS, which relies on well-initialized point clouds, HO-Gaussian learns Gaussian positions directly from a grid volume, using Gaussian Directional Encoding to replace spherical harmonics for view-dependent color, and neural warping to ensure consistency across multiple camera viewpoints.

### [Geometry and orientation extension](15381-geometry-and-orientation-extension.md)

### [Voxel and Grid-Based Prediction](15382-voxel-and-grid-based-prediction.md)
Voxel and Grid-Based Prediction is a neural rendering method that combines voxel-based density representation with Multi-Plane Image (MPI) depth layers to perform efficient volume rendering. It solves the problem of slow convergence and poor surface quality in implicit neural representations by using explicit grid-based features alongside approximate Signed Distance Function (SDF) supervision. Unlike its sibling Voxel and Grid-Based Prediction, which typically predicts Gaussian parameters or raw densities, DirectMPIGO explicitly predicts an SDF value via a feature grid to enable robust surface extraction and regularization. It is significantly faster than implicit-only methods like NeuralRGB-D but requires larger memory footprints due to the explicit grid storage.

### GSGEN
A method introducing 3D SDS loss based on Point-E to mitigate the multi-face or Janus problem in text-to-3D generation [S1]. Point-E is adopted to initialize the point cloud as the initial geometry for optimization, and appearance is refined using only the 2D image prior [S1].

### BrightDreamer
A method predicting the deviation of a set of fixed anchor points to determine the centers of Gaussians [S1]. The deviation of a set of fixed anchor points is predicted, and the centers of Gaussians are determined from these deviations [S1].

### NeRF-Guided 3D Gaussian Splatting
Uses a pretrained NeRF as a teacher to guide feature distillation, improving alignment between geometry and semantics [S3, unofficial].

### Defocus Blur Modeling
Models optical defocus by adjusting the scale $s$ of 3D Gaussians based on their distance from the camera's focal plane [S4]. During training, use larger scale values $\bar{s}_j$ to rasterize blurred images. During testing, use smaller scale values $s_j$ to render sharp details [S4]. The scale $s$ controls dispersion; larger $s$ models out-of-focus points, smaller $s$ models in-focus points [S4]. Unlike a naive Gaussian kernel that blurs the entire image uniformly, this method selectively enlarges covariances only for Gaussians corresponding to blurred regions [S4].

### GauS (Gaussian Splatting Surface Reconstruction)
A render-then-fuse approach for high-fidelity mesh reconstruction from 3DGS inputs without fine-tuning. It uses volumetric fusion to convert 3D Gaussians into textured triangle meshes. It is a plug-and-play module compatible with various GS-based methods [S5, unofficial]. Unlike NeRF-based re-training or further fine-tuning required for explicit surface modeling in other methods, GauS converts optimized Gaussians directly into textured meshes serving as a versatile plug-and-play solution [S5, unofficial].

### Hybrid Scene Representation (Foreground/Background)
A scene representation comprising Gaussian foreground models and background models. The background models support diverse backends like environment maps, textured meshes, and neural representations. Specifically, sky background is built using spherical environment maps composed of Gaussians to reduce artifacts in unbounded outdoor scenes [S5, unofficial].

### Barycentric Splat Parameterization
A method to constrain 2D Gaussian Splat centers to lie on triangular mesh faces using barycentric coordinates, allowing splats to move freely on the face while preserving per-splat attributes [S6]. For each mesh face with vertices $v_1, v_2, v_3$, compute the splat center $m$ using the barycentric coordinates $u, w$:
$$ m = u \cdot v_1 + w \cdot v_2 + (1 - u - w) \cdot v_3 $$
where $m$ is the 2DGS mean (center), $v_1, v_2, v_3$ are the vertices of the triangular mesh face, and $u, w \in [0, 1]$ with $u + w \le 1$ are the barycentric coordinates [S6].

### In-Plane Rotation for Splats
A parameterization for the orientation of Gaussian Splats on the face plane using an in-plane rotation parameter $R_{2d}$, transformed into world space [S6].
$$ R = R_s \cdot R_{2d} $$
where $R$ is the final rotation matrix used for rasterization, $R_s$ is the rotation matrix of the triangle faces, and $R_{2d}$ is the in-plane rotation parameter [S6].

## Operating characteristics
*   **Time Complexity:** Feed-forward inference is significantly faster than iterative optimization-based 3DGS. The method involves a single pass through a sparse 3D CNN and MLP heads, with minimal recursive updates (2 iterations) during inference [S2].
*   **Memory Complexity:** Requires storage for the global feature volume $F$ and the set of Gaussians. The sparse 3D CNN and feature volume size depend on the scene scale and resolution $H \times W \times D$ [S2].
*   **Measured Performance:** EVolSplat achieves real-time rendering by feed-forward prediction of Gaussian primitives [S2]. It improves global consistency and reduces ghosting artifacts compared to pixel-aligned methods like MVSplat, Flash3D, and DrivingForward [S2].
*   **Strengths:** Handles urban scenes with large camera movements and small parallax; reduces ghosting artifacts; efficient feed-forward prediction; handles background/sky with hemisphere model [S2].
*   **Limitations:** Relies on monocular depth estimators which may contain noise; requires calibrated camera poses for unprojection; downsampling initial primitives may lose high-frequency appearance details (mitigated by IBR-based color prediction) [S2].
*   **When to use:** Urban view synthesis, autonomous driving applications, large-scale scenes with sparse input views [S2].
*   **When not to use:** Small-scale scenes with high overlap where per-pixel methods might suffice; scenes where high-frequency texture details are critical and cannot be recovered by IBR [S2].

## Background
Gaussian Geometry Parameters Prediction, specifically as implemented in EVolSplat, was introduced by Sheng Miao, Jiaxin Huang, Dongfeng Bai, Xu Yan, Hongyu Zhou, Yue Wang, Bingbing Liu, Andreas Geiger, and Yiyi Liao from Zhejiang University, Huawei Noah’s Ark Lab, and University of Tübingen [S2]. The paper "EVolSplat: Efficient Volume-based Gaussian Splatting for Urban View Synthesis" was published in CVPR 2025 (arXiv:2503.20168v1, March 26, 2025) [S2]. It addresses the limitations of existing feed-forward 3DGS methods that suffer from multi-view inconsistencies and duplicated content by predicting 3D Gaussians across multiple frames within a unified volume using a 3D convolutional network [S2].
