# Frequency Regularization

Also called: Amplitude and Phase Discrepancy Regularization, Improved Optimization via Regularization

## Overview
Frequency Regularization (FR) is a training-time constraint for 3D Gaussian Splatting that minimizes the spectral discrepancy between rendered and ground-truth images to alleviate over-reconstruction and improve Gaussian densification [S2]. Unlike standard pixel-wise losses (e.g., L1) which provide small gradients in over-reconstructed regions, FR increases pixel gradients in these areas by explicitly disentangling frequency components, thereby enabling adaptive densification [S2]. It sets itself apart from spatial/depth-based siblings by operating in the Fourier domain to penalize high-frequency noise and structural mismatches rather than geometric alignment [S2].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Rendered image $\hat{I} \in \mathbb{R}^{H \times W \times C}$, Ground-truth image $I \in \mathbb{R}^{H \times W \times C}$, and hyperparameter $\lambda$ (weight for the regularization term).
*   **Outputs:** Regularization loss $\mathcal{L}_{FR}$, which is added to the total loss.

**Data Structures:**
*   Complex frequency matrices $F$ and $\hat{F}$ of size $H \times W$ (per channel, or combined via magnitude/phase aggregation).
*   Amplitude matrices $|F|$ and $|\hat{F}|$.
*   Phase matrices $\angle F$ and $\angle \hat{F}$.

**Steps:**
1.  **Fourier Transform:** Compute the 2D Discrete Fourier Transform (DFT) for the ground-truth image $I$ and rendered image $\hat{I}$ to obtain complex frequency values $F(u, v)$ and $\hat{F}(u, v)$.
    $$ F(u, v) = \sum_{x=0}^{H-1} \sum_{y=0}^{W-1} I(x, y) \cdot e^{-i2\pi(\frac{u}{H}x + \frac{v}{W}y)} $$
    where $(x, y)$ are spatial coordinates, $(u, v)$ are frequency coordinates, $H$ is height, and $W$ is width [S2].
2.  **Amplitude Calculation:** Compute the amplitude for each frequency component:
    $$ |F(u, v)| = \sqrt{\text{Re}(u, v)^2 + \text{Im}(u, v)^2} $$
    where $\text{Re}$ and $\text{Im}$ are the real and imaginary parts of $F(u, v)$ [S2].
3.  **Phase Calculation:** Compute the phase for each frequency component:
    $$ \angle F(u, v) = \arctan\left(\frac{\text{Im}(u, v)}{\text{Re}(u, v)}\right) $$
    [S2].
4.  **Discrepancy Calculation:** Compute the total amplitude discrepancy $d_a$ and total phase discrepancy $d_p$ using the Euclidean metric over all frequency components:
    $$ d_a = \sqrt{\frac{1}{HW} \sum_{x=0}^{H-1} \sum_{y=0}^{W-1} (|F(u, v)| - |\hat{F}(u, v)|)^2} $$
    $$ d_p = \sqrt{\frac{1}{HW} \sum_{x=0}^{H-1} \sum_{y=0}^{W-1} (\angle F(u, v) - \angle \hat{F}(u, v))^2} $$
    [S2].
5.  **Loss Computation:** The frequency regularization loss is typically a weighted sum of these discrepancies (often combined with a weighting factor $\lambda$). Note: The source [S2] defines $d_a$ and $d_p$ as the discrepancies but does not explicitly provide the final scalar loss formula $\mathcal{L}_{FR} = \lambda(d_a + d_p)$ or similar, though it implies their use in the optimization [S2].

**Parameters:**
*   **Optimizer:** Adam [S2].
*   **Framework:** PyTorch [S2].
*   **Rasterization:** Custom CUDA kernels from 3D-GS [S2].
*   **Typical Values:** Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Over-reconstruction Bias:** Naively adopting amplitude and phase discrepancies without distinguishing between low and high frequencies can bias the splatting towards undesirable artifacts and restrict Gaussian densification [S2]. This is addressed in variants like FreGS via frequency annealing [S2].
*   **Gradient Vanishing:** In well-reconstructed regions, standard L1 loss yields small gradients, preventing densification. FR mitigates this by maintaining higher gradients in over-reconstructed regions [S2].

**Pseudocode:**
```python
import torch
import torch.fft

def frequency_regularization_loss(rendered_image: torch.Tensor, ground_truth: torch.Tensor) -> torch.Tensor:
    """
    Computes the amplitude and phase discrepancy loss between rendered and ground truth images.
    
    Args:
        rendered_image: Tensor of shape (H, W, C) or (C, H, W). Assuming (H, W, C) for spatial indexing.
        ground_truth: Tensor of shape (H, W, C).
        
    Returns:
        Scalar tensor representing the frequency regularization loss.
    """
    # Ensure inputs are float32 for FFT stability
    I = ground_truth.float()
    I_hat = rendered_image.float()
    
    # Move to CPU if necessary for FFT, or use torch.fft on GPU
    # Note: torch.fft.fft2 expects complex input or returns complex output.
    # We compute DFT for each channel and aggregate.
    
    H, W, C = I.shape
    
    total_amplitude_diff = 0.0
    total_phase_diff = 0.0
    
    for c in range(C):
        # Extract single channel
        img_gt = I[:, :, c]
        img_hat = I_hat[:, :, c]
        
        # 2D Discrete Fourier Transform
        # torch.fft.fft2 returns complex tensor of shape (H, W)
        F = torch.fft.fft2(img_gt)
        F_hat = torch.fft.fft2(img_hat)
        
        # Compute Amplitude
        amp_gt = torch.abs(F)
        amp_hat = torch.abs(F_hat)
        
        # Compute Phase
        phase_gt = torch.angle(F)
        phase_hat = torch.angle(F_hat)
        
        # Compute Discrepancies
        # d_a for this channel
        amp_diff_sq = torch.pow(amp_gt - amp_hat, 2)
        d_a_channel = torch.sqrt(torch.mean(amp_diff_sq))
        
        # d_p for this channel
        phase_diff_sq = torch.pow(phase_gt - phase_hat, 2)
        d_p_channel = torch.sqrt(torch.mean(phase_diff_sq))
        
        total_amplitude_diff += d_a_channel
        total_phase_diff += d_p_channel
        
    # Average over channels
    avg_d_a = total_amplitude_diff / C
    avg_d_p = total_phase_diff / C
    
    # Return combined loss. Source [S2] defines d_a and d_p separately.
    # A common implementation would sum them.
    return avg_d_a + avg_d_p
```

## Subtopics

### DWTGS
DWTGS is a variant designed for sparse-view 3D Gaussian Splatting. It rethinks frequency regularization by applying a Discrete Wavelet Transform (DWT) on the rendered image instead of the Fourier Transform. It penalizes the loss in the wavelet domain to encourage sharper edges [S4, unofficial].

## Operating characteristics
*   **Time Complexity:** The 2D DFT is $O(HW \log(HW))$ per image. This adds computational overhead to each training step compared to standard L1 loss.
*   **Memory Complexity:** Requires storing complex frequency matrices of size $H \times W$ for both rendered and ground-truth images.
*   **Performance:** FR significantly increases pixel gradients in over-reconstruction regions, enabling better adaptive densification than L1 loss [S2]. It alleviates over-reconstruction and improves the quality of Gaussian densification [S2].
*   **Strengths:** Explicitly disentangles frequency components, addressing high-frequency noise and transient artifacts [S2].
*   **Limitations:** Naive application can bias splatting towards artifacts; requires careful annealing (low-to-high frequency) for optimal results [S2].
*   **When to use:** When over-reconstruction is prevalent or when standard densification fails to capture high-frequency details.
*   **When not to use:** When computational resources are extremely limited, or when the scene is very low-frequency and wavelet/Fourier overhead is unjustified.

## Background
Frequency Regularization was introduced to address convergence speed, visual artifacts, and improper Gaussians in 3D Gaussian Splatting optimization [S1]. The specific formulation using amplitude and phase discrepancy (FreGS) was proposed in 2024 [S2]. It is part of a broader trend of improving 3DGS optimization through additional regularization, alongside geometry-aware approaches [S1].
