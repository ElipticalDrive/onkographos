# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific implementation parameters, training loops, and optimization strategies required to reproduce 3D Gaussian Splatting (3DGS) and its immediate variants. It covers the core training loop, hyperparameter settings, and specific algorithmic modifications such as corrected scene extent calculation, selective defocus blurring, and internal rendering constraints. It sets itself apart from general [Optimization and Parallelization](6233-optimization-and-parallelization.md) by providing concrete values for learning rates, loss weights, and data structure layouts used in standard and modified implementations.

## How it works

### Inputs and Outputs
*   **Inputs:** A set of $N_{cam}$ calibrated images with known camera poses $C_i$, and an initial sparse point cloud from Structure-from-Motion (SfM) with $N_{SfM}$ points.
*   **Outputs:** A set of 3D Gaussian primitives $\mathcal{G}$, each parameterized by mean position $\mu$, covariance matrix $\Sigma$ (or scale/rotation), opacity $\alpha$, spherical harmonics coefficients $c_l^m$, and potentially auxiliary attributes (normals, BRDF, semantic codes).

### Data Structures
The Gaussian set $\mathcal{G}$ is typically stored in a flat array or structure-of-arrays (SoA) layout for efficient GPU access. Each Gaussian $j$ contains:
*   $\mu_j \in \mathbb{R}^3$: Position.
*   $\sigma_j \in \mathbb{R}^3$: Scale (log-space).
*   $q_j \in \mathbb{R}^4$: Rotation (quaternion).
*   $\alpha_j \in \mathbb{R}$: Opacity.
*   $c_{j, l, m} \in \mathbb{R}$: SH coefficients (typically degree 1, i.e., 9 coefficients per RGB channel).
*   [G] Additional attributes depending on the variant (e.g., normal vectors, semantic IDs).

### Training Loop
The standard training process follows a stochastic gradient descent loop [S10, unofficial]:

1.  **Random View Selection:** Randomly select one input image $I_{target}$ and its corresponding camera pose $T_{CW}$ from the training set [S2][S10, unofficial].
2.  **Rendering:** Render the current set of Gaussians $\mathcal{G}$ from $T_{CW}$ using the differentiable rasterizer to produce image $I_{render}$ [S10, unofficial].
3.  **Loss Computation:** Compute the loss $\mathcal{L}$ between $I_{render}$ and $I_{target}$ [S10, unofficial].
4.  **Optimization:** Compute gradients $\nabla_{\mathcal{G}} \mathcal{L}$ and update Gaussian parameters using the Adam optimizer [S2][S10, unofficial].
5.  **Densification/Pruning:** Periodically (e.g., every 100 iterations), apply densification (cloning/splitting) and pruning based on gradient magnitudes and opacity thresholds [S3, S7].
6.  **Repeat:** Iterate for a fixed budget (typically 30,000 iterations) [S10, unofficial].

### Loss Function
The total loss is a weighted combination of L1 loss and D-SSIM [S10, unofficial]:
$$ \mathcal{L} = (1 - \lambda) \mathcal{L}_1 + \lambda \mathcal{L}_{SSIM} $$
Typical value for $\lambda$ is 0.2 [S10, unofficial][S12].

### Optimizer Settings
*   **Optimizer:** Adam [S2].
*   **Learning Rate:** $1 \times 10^{-3}$ for position, scale, rotation, opacity, and SH coefficients [S2].
*   **Iteration Budget:** Typically 30,000 iterations [S10, unofficial].

### Corrected Scene Extent
The default 3DGS scene extent $e_{\text{scene}}$ is biased by camera distribution [S3]. It is calculated as:
$$ e_{\text{scene}} = 1.1 \cdot \max_{i=1}^{N_{\text{cam}}} \|\bar{C} - C_i\|_2 $$
where $\bar{C} = \frac{1}{N_{\text{cam}}} \sum_{i=1}^{N_{\text{cam}}} C_i$ [S3].
To avoid bias from clustered cameras (e.g., orbiting a small object), use the corrected scene extent based on SfM points [S3]:
$$ e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2 $$
where $p_i$ are the SfM points [S3].

### Selective Defocus Blurring
To handle spatially varying blur, predict a per-Gaussian scale offset $\delta s_j$ using a compact MLP [S4]:
1.  Predict $\delta s_j$ for each Gaussian $j$.
2.  Add $\delta s_j$ to the base scale to transform the covariance $\Sigma_j$.
3.  Project the transformed covariance to 2D space to act as a pixel-wise blur kernel during rasterization [S4].
*   **Pitfall:** If $\delta s_j$ is constant for all Gaussians, it degrades to a uniform Gaussian blur [S4].

### Multi-Scale Constraint
For large-scale scenes, apply position-aware adaptive control [S7]:
Define $\gamma(\mu)$ based on distance from camera center $c$ and scene radius $r$:
$$ \gamma(\mu) = \begin{cases} 1 & \text{if } \|\mu - c\|^2 < 2r \\ \|\mu - c\|^2 / r - 1 & \text{if } \|\mu - c\|^2 \ge 2r \end{cases} $$
*   **Cloning:** If $\max(s) < g \cdot \gamma(\mu)$, clone the Gaussian.
*   **Splitting:** If $\max(s) \ge g \cdot \gamma(\mu)$, split the Gaussian.
*   **Elimination:** If $\max(s) > b \cdot \gamma(\mu)$, eliminate the Gaussian.
Here, $g$ and $b$ are scale threshold parameters [S7].

### LS-Gaussian Viewpoint Transformation
For sparse rendering of consecutive frames, transform the viewpoint between frames rather than rendering each separately [S8]:
*   **Method:** Leverage inter-frame continuity to transform Gaussians.
*   **Pitfall:** Rendering quality degrades as the number of consecutively transformed frames increases due to accumulated interpolation errors [S8].
*   **Usage:** Render only one frame in every 6 frames fully, transforming the rest [S8].

### GS-IR (Internal Rendering)
For internal volumetric structure reconstruction (e.g., medical imaging), use cross-sectional supervision [S9]:
1.  Define virtual slicing planes within the volume.
2.  Use a binary mask to select Gaussians whose centers lie within the plane thickness.
3.  Render the selected subset using the standard rasterizer.
4.  Optimize against ground-truth cross-sections (trilinear resampling).
5.  Apply distance-aware soft weighting to attenuate opacity based on distance from the plane [S9].

### Sensitivity-Aware Vector Clustering (Compression)
Compress Gaussians by grouping colors and shape parameters into codebooks [S12]:
1.  Calculate sensitivity $S(p)$ for each parameter $p$:
    $$ S(p) = \frac{\sum_{i=1}^K \frac{1}{P_i} \sum_{j=1}^{P_i} \left| \frac{\partial E_i}{\partial p} \right|}{\sum_{i=1}^K E_i} $$
    where $E_i$ is the sum of RGB components for image $i$, and $P_i$ is the number of pixels [S12].
2.  Compute codebooks $C$ using k-Means with a similarity measure between vectors and centroids [S12].
3.  Fine-tune parameters using quantization-aware training with Min-Max Quantization [S12].
4.  Compress Gaussians and codebooks using DEFLATE after ordering by Z-order (Morton order) [S12].

### Relightable 3D Gaussians
Enhance Gaussians with normal vectors $n$, BRDF parameters, and incident lighting [S13]:
1.  Assign $n$, BRDF, and incident light to each Gaussian.
2.  Apply physically based rendering (PBR) to get PBR color, then alpha-composite [S13].
3.  Split incident light into global environment map and indirect incident light field [S13].
4.  Introduce regularizations: depth distribution constraints, smoothness priors, and lighting regularization [S13].
5.  Use BVH-based ray tracing for visibility pre-computation [S13].

### Normal Estimation via Back-propagation
Optimize normal attributes $n$ from random initialization via back-propagation [S13]:
*   **Normal Consistency Loss:** $\mathcal{L}_n = \|\mathcal{N} - \tilde{\mathcal{N}}\|_2$, where $\mathcal{N}$ is the estimated normal and $\tilde{\mathcal{N}}$ is the target normal derived from depth distribution [S13].

### DiffGS Framework
Optimize Gaussians to exact locations using a functional Gaussian splatting diffusion approach [S14]:
*   **Truncation Function:** $\lambda$ is introduced when modeling GauPF (Gaussian Probability Function) [S14].
*   **Projection Function:** $\tau(x) = e^{-x}$ (Exponent) or linear projection [S14].
*   **Performance:** 50K Gaussians: PSNR 28.61, SSIM 0.9787, LPIPS 0.0251; 100K: PSNR 30.35, SSIM 0.9838, LPIPS 0.0151; 350K: PSNR 34.01, SSIM 0.9879, LPIPS 0.0149 [S14].

### Opacity Offset Table for DSA
Construct an opacity offset table to model changes in digital subtraction angiography [S15].

### Model-based Depth Estimation for Volume Parameter Update
Use depth values $z$ extracted from the scene to update medium parameters ($B_\infty, B_b$) [S6]:
$$ z = \frac{\sum_{i=1}^M d_i \alpha_i T_i}{\sum_{i=1}^M \alpha_i T_i} $$
where $d_i$ is the depth of Gaussian $i$, $\alpha_i$ is opacity, and $T_i$ is transmittance [S6].

### Camera Localisation for Convergence Basin
Localize camera pose by minimizing photometric error against ground-truth color image [S11, unofficial]:
1.  Fix $G_{init}$ during optimization.
2.  Initialize $T_{CW}$ at one of the test view's positions.
3.  Optimize for 1000 iterations.
4.  Success if estimated pose converges to within 1cm of target view [S11, unofficial].
$$ \mathbf{T}_{CW}^{est} = \underset{\mathbf{T}_{CW}}{\arg \min} \left\| I(\mathcal{G}_{init}, \mathbf{T}_{CW}) - \bar{I}_{target} \right\|_1 $$

## Subtopics

### [Sorting and Rendering Pipeline Optimization](12180-sorting-and-rendering-pipeline-optimization.md)
Addresses computational bottlenecks in 3DGS rendering, specifically targeting memory bandwidth limits in the front-end (sorting and attribute fetching) and compute throughput limits in the rasterization stage. It sets itself apart from generic optimization by explicitly mapping software strategies to hardware constraints (e.g., using the Roofline model) or by replacing standard sorting with hardware-friendly, comparison-free logic and sorting-free approximations.

### [LangSplat Training Procedure](12438-langsplat-training-procedure.md)
Optimizes 3D Gaussian Splatting scenes to incorporate semantic language features alongside photometric rendering. It extends the standard differentiable rendering pipeline by computing a loss against ground-truth language embeddings (e.g., CLIP features) when enabled, allowing the scene to support semantic queries. It is distinguished from standard 3D Gaussian Splatting training by the conditional inclusion of language feature loss and the consequent disabling of densification and pruning operations during language-aware training.

### [DeSplat](12925-desplat.md)
Decomposes the 3D Gaussian Splatting scene representation into two distinct sets of Gaussian primitives: static scene Gaussians ($G_s$) and per-view distractor Gaussians ($G_d$). It solves the problem of transient occluders (e.g., pedestrians, vehicles) corrupting the static 3D reconstruction by separating them from the permanent scene geometry without relying on external semantic segmentation models or pre-trained neural networks. Unlike sibling methods that use foundation models for detection or complex neural appearance encoders for separation, DeSplat relies solely on volume rendering and photometric loss, allowing independent rendering of static elements and transient components while maintaining the speed of standard Gaussian splatting.

### [360 Gaussian Splatting](12929-360-gaussian-splatting.md)
Generates high-quality 3D spatial representations from 360-degree camera images by combining OpenSfM for sparse point cloud generation and Gaussian Splatting for dense Gaussian conversion. It solves the problem that standard Gaussian Splatting assumes perspective cameras and cannot directly process equirectangular images from 360-degree cameras, a limitation that previously forced users to crop or split images. It sets itself apart from standard implementations by modifying the differentiable rasterization module to support spherical rendering and using OpenSfM, which natively supports equirectangular inputs, unlike Colmap.

### [Data Compression and Storage Optimization](12943-data-compression-and-storage-optimization.md)
Addresses the excessive memory footprint and storage overhead of 3D Gaussian Splatting (3DGS), which often exceeds 1 GB for large scenes due to per-Gaussian attributes. The methods reduce storage requirements by compressing numerical representations, clustering parameters into codebooks, or replacing explicit attributes with neural fields. They distinguish themselves from sibling methods like [Sorting and Rendering Pipeline Optimization](12180-sorting-and-rendering-pipeline-optimization.md) by focusing on data representation density rather than rendering throughput, and from [Gaussian Representation and Truncation](12855-gaussian-representation-and-truncation.md) by employing structural compression (clustering/quantization) rather than geometric pruning alone.

### [Bézier-boundary gradient approximation](13137-b-zier-boundary-gradient-approximation.md)
Approximates the gradients of a discontinuous indicator function $g(\cdot)$ with respect to Bézier curve control point coordinates, enabling backpropagation in Gaussian Splatting despite the function being piecewise constant and non-differentiable. It sets itself apart from standard Gaussian Splatting, which relies on differentiable rendering, by explicitly handling the non-differentiable segments of discontinuity-aware rendering through geometric boundary analysis.

### [Discontinuity-aware Gaussian Splatting](13138-discontinuity-aware-gaussian-splatting.md)
Enables 3D Gaussian Splatting to represent and render sharp boundaries and discontinuities, addressing a key limitation of the original method which assumes smooth, continuous alpha blending. It distinguishes itself from standard Gaussian Splatting by introducing a "pre-scissoring" step that segments projected Gaussians along boundaries defined by cubic Bézier curves, combined with a Bézier-boundary gradient approximation strategy to maintain differentiability during optimization.

### [SOGS (Second-Order Anchor for Advanced 3D Gaussian Splatting)](13171-sogs-second-order-anchor-for-advanced-3d-gaussian-splatting.md)
An anchor-based 3D Gaussian Splatting technique that introduces second-order statistics to achieve superior rendering quality while simultaneously reducing anchor feature dimensions and overall model size. It distinguishes itself from standard anchor methods like Scaffold-GS by using covariance-based feature augmentation to capture co-variation patterns across feature dimensions, allowing for smaller feature vectors without sacrificing detail.

### [TraGraph-GS](14454-tragraph-gs.md)
A high-quality rendering method for arbitrary large-scale scenes that employs graph-based adaptive spatial partitioning, regularization constraints, and adaptive region selection. It addresses the limitations of standard 3D Gaussian Splatting (3DGS) in handling vast scales and textureless regions by decoupling the scene into manageable local regions and a coarse global representation. Unlike methods that rely on fixed spatial grids or simple clustering, TraGraph-GS constructs a camera connectivity graph to ensure balanced, connected subgraphs, and uses a progressive rendering strategy for novel viewpoints to eliminate boundary artifacts.

### [Explicit 4D Gaussian Splatting](14584-explicit-4d-gaussian-splatting.md)
Achieves memory efficiency and rendering capacity by separating Gaussians into static and dynamic categories and explicitly sampling positions and rotations at sparse timestamps. It differs from implicit trajectory-based methods by storing explicit keyframe data for dynamic Gaussians and using interpolation to reconstruct continuous motion, thereby avoiding the memory overhead of multiple primitives for occluded objects.

### [Color and Appearance Modeling](14740-color-and-appearance-modeling.md)
Addresses the limitations of standard view-dependent radiance representation (typically Spherical Harmonics) when handling complex lighting, transient objects, or unstructured data. It solves the problem where static Gaussian attributes cannot capture appearance variations caused by changing illumination, camera ISP processing, or dynamic occluders. It sets itself apart from sibling methods by offering diverse strategies: post-processing image transformations ([DAVIGS](12021-davigs.md)), neural field substitution ([Compact View-dependent Color](12904-compact-view-dependent-color.md)), factorized illumination ([3iGS](13977-3igs-factorised-tensorial-illumination-for-3d-gaussian-splat.md)), and image-conditioned modulation ([SWAG](14315-swag-splatting-in-the-wild-images-with-appearance-conditione.md)), rather than relying solely on optimizing SH coefficients ([Spherical Harmonics Optimization](14206-spherical-harmonics-optimization.md)).

### GS-IR (Gaussian Splatting for Internal Rendering)
An inverse rendering approach based on 3D Gaussian Splatting (3DGS) that leverages forward mapping volume rendering to achieve photorealistic novel view synthesis and relighting results, estimating scene geometry, surface material, and environment illumination from multi-view images captured under unknown lighting conditions. Unlike NeRF-based inverse rendering methods that use implicit neural representations and ray tracing (backward mapping) which suffer from low expressive power and high computational complexity, GS-IR uses 3D Gaussians and forward mapping splatting for real-time rendering efficiency.

### [Physics and Optical Modeling](15148-physics-and-optical-modeling.md)
Extends the standard 3D Gaussian Splatting (3DGS) image formation pipeline to account for physical light transport phenomena, specifically volumetric attenuation and scattering. It solves the problem of inaccurate rendering in non-vacuum media (such as underwater environments) or the need for geometrically consistent surface extraction by reformulating the discrete alpha-blending rasterization into a continuous volumetric integration framework. It distinguishes itself from standard 3DGS by introducing learnable medium parameters (attenuation and backscatter coefficients) or by deriving continuous attenuation fields from Gaussian densities to ensure unbiased surface extraction, thereby addressing color distortion and depth inconsistency issues inherent in the base method.

### [Scene Representation and Geometry Constraints](15421-scene-representation-and-geometry-constraints.md)
Defines the fundamental data structures and geometric constraints used to represent scenes in 3D Gaussian Splatting (3DGS) and its variants. It addresses the problem of defining learnable primitives and ensuring their geometric consistency, particularly when integrating explicit mesh structures. It differs from sibling methods by focusing on the core mathematical definition of the Gaussian primitives and the constraints applied to their physical parameters, whereas siblings like [Sorting and Rendering Pipeline Optimization](12180-sorting-and-rendering-pipeline-optimization.md) focus on rendering efficiency, and [Mesh Extraction and Representation](14095-mesh-extraction-and-representation.md) focuses on post-processing or surface alignment strategies.

### [FAST-Splat](15436-fast-splat.md)
A semantic Gaussian Splatting method that directly augments each Gaussian primitive with specific semantic codes and uses a hash-table for disambiguation, avoiding neural fields for semantic distillation to enable fast training, rendering, and ambiguity-free object localization. It distinguishes itself from sibling methods like [LangSplat Training Procedure](12438-langsplat-training-procedure.md) and [Feature-3DGS](12925-desplat.md) by employing a single-phase, neural-free training procedure that jointly optimizes geometric, visual, and semantic attributes, thereby preserving the explicit representation's speed benefits while resolving semantic ambiguity in open-vocabulary queries.

### [Perceptual Wrapper](15438-perceptual-wrapper.md)
A plug-and-play 2D module that enhances the rendered outputs of existing 3D Gaussian Splatting (3DGS) representations by synthesizing high-frequency texture details in a content- and view-dependent manner. It addresses the limitation of standard 3DGS in rendering sharp textures, particularly under memory-constrained or rate-distortion-optimized (RDO) pipelines where blurriness is exacerbated. Unlike methods that modify the 3D primitive densification or loss functions directly (e.g., Perceptual-GS), PW operates as a post-processing synthesis network in the image domain, conditioned on pseudo-random Gaussian noise and Plücker embeddings, and is trained using Wasserstein Distortion (WD) loss.

### [Monte Carlo Specular Energy Aggregator](15439-monte-carlo-specular-energy-aggregator.md)
Compresses high-order (third-order) Spherical Harmonics (SH) radiance energy into a compact lower-order (first-order) subspace without pre-training or distillation, thereby preserving specular features while reducing memory overhead. It solves the inefficiency of high-order SH for sharp specular lobes by extracting directional moments of the specular residual via Monte Carlo projection, replacing the teacher-student distillation process used in methods like Mobile-GS. Unlike Mobile-GS, which requires costly distillation from a high-order teacher model, MC-SEA compresses energy directly, improving training efficiency and enabling real-time rendering on mobile hardware.

### [Gaussian Deformation Field (GauFRe)](15458-gaussian-deformation-field-gaufre.md)
Augments 3D Gaussian Splatting with a time-conditioned forward-warping deformation field to enable real-time novel view synthesis of dynamic scenes. Unlike NeRF-based methods that use backward warps to query canonical space from spatio-temporal coordinates, GauFRe stores Gaussians in a canonical space and uses a neural field to output deformed attributes for each time step $t$. It distinguishes itself from sibling methods by explicitly separating static and deformable Gaussian sets to prevent capacity waste and noise in static regions, and by modeling non-rigid scaling deformations in addition to rigid motion.

## Operating characteristics
*   **Time Complexity:** Rendering is $O(N \cdot P)$ where $N$ is the number of Gaussians and $P$ is the number of pixels, but optimized via tile-based rasterization and sorting. Training time is dominated by the number of iterations (typically 30,000) and the cost of densification operations [S10, unofficial].
*   **Memory Complexity:** $O(N)$ for storing Gaussian attributes. Large scenes can exceed 1 GB [S1].
*   **Performance:** Real-time rendering is achievable on modern GPUs with optimized CUDA kernels (e.g., gsplat) [S2, S8].
*   **Strengths:** High-quality novel view synthesis, real-time rendering, explicit representation.
*   **Limitations:** Sensitive to camera distribution for scene extent, struggles with transparent objects and complex lighting without extensions, memory intensive for large scenes.
*   **When to use:** When high-quality novel view synthesis and real-time rendering are required, and camera poses are known.
*   **When not to use:** When memory is extremely constrained without compression, or when dealing with highly dynamic scenes without temporal extensions.

## Background
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1]. It represents scenes as a set of 3D Gaussians optimized via differentiable rasterization. The method has since been extended to handle various challenges such as defocus blur [S4], sparse views [S5], large-scale scenes [S7], internal rendering [S9], and relighting [S13]. The implementation details provided here are based on the original gsplat library and subsequent modifications [S1, S2][S10, unofficial].
