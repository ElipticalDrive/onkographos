# On-the-Fly GS Progressive Training

Also called: On-the-Fly Gaussian Splatting

## Overview
On-the-Fly GS Progressive Training is a method for optimizing a 3D Gaussian Splatting (3DGS) field from a continuous stream of incoming images, enabling near real-time reconstruction without requiring the full dataset upfront [S1]. It solves the problem of catastrophic forgetting and overfitting in incremental learning by decoupling the training into initialization, progressive updates, and final global optimization phases [S1]. Unlike static training methods, it dynamically allocates computational resources (iterations and learning rates) based on hierarchical image overlap weights and balances Gaussian density via a load-balancing loss [S1].

## How it works

### Inputs and Outputs
**Inputs:**
*   A sequence of incoming RGB images $I_{new}$.
*   An existing 3DGS field $\mathcal{G}$ (set of Gaussians with position $\mathbf{p}$, covariance $\Sigma$, opacity $\alpha$, and spherical harmonics coefficients).
*   A sparse point cloud $\mathcal{P}$ from On-the-Fly SfM.
*   Camera poses for existing and new images.

**Outputs:**
*   Updated 3DGS field $\mathcal{G}'$ optimized for the new image and its context.

### Data Structures
*   **3DGS Field:** A list of Gaussian primitives. Each Gaussian stores position, scale, rotation (quaternion), opacity, and SH coefficients.
*   **Sparse Point Cloud:** A list of 3D points $\mathbf{p}_k$ with associated feature descriptors.
*   **Search Tree:** A spatial index (e.g., KD-Tree or Octree) built on $\mathcal{P}$ to query nearest neighbors efficiently.
*   **Image Overlap Graph:** Implicitly maintained via feature matches $M_{i,j}$ between image $i$ and image $j$.

### Parameters
*   $N_0$: Number of initial images for Phase 1. Typical value: 30 [S1].
*   $T_{init}$: Initial training iterations for Phase 1. Typical value: 2,000 [S1].
*   $T_I$: Total training iterations per new image in Phase 2. Typical value: 200 [S1].
*   $N_m$: Number of top-weighted images for local optimization. Typical value: 10 [S1].
*   $T_a$: Threshold iterations for learning rate saturation. Typical value: 200 [S1].
*   $\eta^0$: Initial learning rate. Typical value: $1.6 \times 10^{-4}$ [S1].
*   $\eta^f$: Final learning rate. Typical value: $1.6 \times 10^{-6}$ [S1].
*   $\lambda_1$: Weight for L1 Loss. Typical value: 0.47 [S1].
*   $\lambda_{ssim}$: Weight for SSIM Loss. Typical value: 0.12 [S1].
*   $\lambda_{load}$: Weight for Load-Balancing Loss. Typical value: 0.41 [S1].

### Steps

#### Phase 1: Initial 3DGS Training
1.  Acquire the first $N_0$ images.
2.  Run On-the-Fly SfM to estimate poses and generate the initial sparse point cloud $\mathcal{P}_0$.
3.  Initialize the 3DGS field $\mathcal{G}$ using the points in $\mathcal{P}_0$.
4.  Perform $T_{init}$ iterations of standard 3DGS optimization on these $N_0$ images to prevent overfitting to the small initial set [S1].

#### Phase 2: Progressive 3DGS Training
For each newly acquired image $n$:

1.  **Pose and Point Cloud Update:**
    *   Estimate the pose of image $n$ using On-the-Fly SfM.
    *   Perform local Bundle Adjustment (BA) to optimize the pose of image $n$ and its connected neighbors.
    *   Update the sparse point cloud $\mathcal{P}$ with new points from image $n$.

2.  **Gaussian Initialization:**
    *   Construct a search tree for the current sparse point cloud $\mathcal{P}$.
    *   Query points from image $n$ against the search tree.
    *   Identify points $\mathbf{p}_{new}$ where the distance to the nearest existing point in $\mathcal{P}$ exceeds a predefined threshold.
    *   Initialize new Gaussians from $\mathbf{p}_{new}$ and append them to $\mathcal{G}$ [S1].

3.  **Hierarchical Image Weighting:**
    *   Calculate weights $\omega$ for images based on their overlap with the new image $n$.
    *   **Layer 1 (New Image):** $\omega_{11} = 1$.
    *   **Layer 2 (Direct Overlap):** For images $i$ with direct overlap ($M_{i,n} > 0$):
        $$ \omega_{2i} = M_{i,n} $$
        where $M_{i,n}$ is the number of matched feature points between image $i$ and image $n$ [S1].
    *   **Layer $k$ (Indirect Overlap, $k \ge 3$):** For images in layer $k$, let $N_{k-1}$ be the number of images in layer $k-1$. The weight $\omega_{ki}$ for image $i$ in layer $k$ is:
        $$ \omega_{ki} = \frac{\sum_{j=1}^{N_{k-1}} \omega_{j}^{(k-1)} \times M_{j,ki}^{(k-1)}}{N_{k-1}} $$
        where $\omega_{j}^{(k-1)}$ is the weight of image $j$ in layer $k-1$, and $M_{j,ki}^{(k-1)}$ is the match count between image $j$ (from layer $k-1$) and image $i$ (from layer $k$) [S1].

4.  **Training Iteration Allocation:**
    *   Select the top $N_m$ images with the highest weights as key training targets.
    *   For each key image $i$ with weight $\omega_i$, calculate its allocated iterations $T_{im}$:
        $$ T_{im} = \frac{1 - e^{-\omega_i}}{\sum_{j=1}^{N_m} (1 - e^{-\omega_j})} \times T_I $$
    *   Distribute the remaining $T_I / 2$ iterations evenly among the other registered images (Semi-Global optimization). The local optimization uses the other $T_I / 2$ iterations distributed according to $T_{im}$ [S1].

5.  **Adaptive Learning Rate Update:**
    *   For each image $j$ being trained, calculate the progress $t_i$:
        $$ t_i = \begin{cases} 1 & \text{if } T_j > T_a \\ T_j / T_a & \text{if } T_j \le T_a \end{cases} $$
    *   Calculate the base learning rate $\eta_j^c$:
        $$ \eta_j^c = (\eta_j^0)^{1-t_i} \times (\eta_j^f)^{t_i} $$
    *   Adjust for overlapping images. Let $I$ be the set of images overlapping with $j$ ($M_{i,j} > 0$) and $N_I$ be the count. The final learning rate $\eta_j$ is:
        $$ \eta_j = \frac{\eta_j^c + \sum_{i \in I} M_{i,j} \times \eta_i^c}{N_I + 1} $$
        [S1].

6.  **Loss Calculation and Optimization:**
    *   **Load-Balancing-Loss:** For the current image, let $G_p$ be the number of Gaussians associated with pixel $p$.
        $$ L_{load} = \text{std}(G_p), \quad p \in \text{image} $$
    *   **Total Loss:**
        $$ L_{total} = \lambda_1 L_1 + \lambda_{ssim} L_{ssim} + \lambda_{load} L_{load} $$
    *   Perform gradient accumulation. To accelerate training, use **Splatting-based Parallelism**: accumulate gradients per Gaussian rather than per pixel to eliminate thread contention and serialized atomic operations [S1].
    *   Update Gaussian parameters using the computed gradients and learning rates [S1].

#### Phase 3: Final Optimization
1.  After all images are acquired, perform global Bundle Adjustment (BA) on all estimated poses [S1].
2.  Apply rapid additional optimization to the final 3DGS field to improve overall rendering quality [S1].

### Pseudocode

```python
def on_the_fly_gs_training(image_stream, initial_params):
    """
    Main loop for On-the-Fly GS Progressive Training.
    """
    # Phase 1: Initialization
    initial_images = image_stream.take(initial_params['N0'])
    poses, sparse_cloud = on_the_fly_sfm(initial_images)
    gaussians = initialize_gaussians(sparse_cloud)
    
    # Initial training with strict iteration limit
    optimize_3dgs(gaussians, initial_images, iterations=initial_params['T_init'])
    
    # Phase 2: Progressive Training
    for new_image in image_stream:
        # 1. Update Pose and Cloud
        new_pose, updated_cloud = on_the_fly_sfm_update(new_image, poses, sparse_cloud)
        poses.append(new_pose)
        sparse_cloud = updated_cloud
        
        # 2. Initialize New Gaussians
        search_tree = build_search_tree(sparse_cloud)
        new_points = query_new_points(new_image.depth_points, search_tree, threshold=initial_params['threshold'])
        new_gaussians = initialize_gaussians(new_points)
        gaussians.extend(new_gaussians)
        
        # 3. Calculate Image Weights
        weights = calculate_hierarchical_weights(new_image, poses, sparse_cloud, initial_params['N0'])
        
        # 4. Allocate Iterations
        top_images = get_top_n_images_by_weight(weights, initial_params['Nm'])
        iteration_allocation = allocate_iterations(top_images, weights, initial_params['TI'])
        
        # 5. Optimize
        optimize_progressive(gaussians, poses, sparse_cloud, 
                             iteration_allocation, initial_params)

    # Phase 3: Final Optimization
    poses = global_bundle_adjustment(poses, sparse_cloud)
    optimize_3dgs(gaussians, all_images, iterations=initial_params['final_opt_iters'])
    return gaussians

    """

    weights = {}
    weights[new_image.id] = 1.0  # Layer 1

    for img in direct_overlap_images:
        M_in = count_feature_matches(new_image, img)

    # This part is complex to implement without a full overlap graph structure.
    # For the purpose of this article, we assume a function exists that computes

    indirect_images = get_indirect_overlap_images(new_image, poses, sparse_cloud)

def optimize_progressive(gaussians, poses, sparse_cloud, iteration_allocation, params):
    """
    Performs local and semi-global optimization with adaptive learning rates.
    """
    total_iters = params['TI']
    local_iters = total_iters // 2
    semi_global_iters = total_iters // 2
    
    # Local Optimization
    for img_id, img_iters in iteration_allocation.items():
        if img_iters > 0:
            # Adaptive Learning Rate
            eta = calculate_adaptive_lr(img_id, img_iters, params)
            
            # Load Balancing Loss
            # L_load = std(G_p)
            # This requires counting Gaussians per pixel during splatting
            
            # Gradient Accumulation (Splatting-based)
            gradients = compute_gradients_splatting_based(gaussians, img_id, poses)
            update_gaussians(gaussians, gradients, eta)
            
    # Semi-Global Optimization
    # Distribute remaining iterations evenly among other images
    other_images = get_other_images(iteration_allocation)
    if other_images:
        per_img_iters = semi_global_iters // len(other_images)
        for img_id in other_images:
            if per_img_iters > 0:
                eta = calculate_adaptive_lr(img_id, per_img_iters, params)
                gradients = compute_gradients_splatting_based(gaussians, img_id, poses)
                update_gaussians(gaussians, gradients, eta)

def calculate_adaptive_lr(img_id, T_j, params):
    """
    Calculates the learning rate for image j based on training progress.
    """
    eta_0 = params['eta_0']
    eta_f = params['eta_f']
    T_a = params['T_a']
    
    if T_j > T_a:
        t_i = 1.0
    else:
        t_i = T_j / T_a
        
    eta_c = (eta_0 ** (1 - t_i)) * (eta_f ** t_i)
    
    # Adjust for overlapping images
    overlapping_imgs = get_overlapping_images(img_id)
    sum_overlap_eta = 0
    N_I = len(overlapping_imgs)
    
    for i in overlapping_imgs:
        M_ij = count_feature_matches(img_id, i)
        # Recursive call or pre-computed eta_i^c
        # In practice, eta_i^c should be calculated similarly
        eta_i_c = calculate_adaptive_lr(i, get_iters(i), params) 
        sum_overlap_eta += M_ij * eta_i_c
        
    eta_j = (eta_c + sum_overlap_eta) / (N_I + 1)
    return eta_j
```

### Edge Cases and Pitfalls
*   **Threshold Selection:** The distance threshold for identifying new points in the sparse cloud must be carefully chosen. Too low, and existing points are re-initialized, causing instability. Too high, and new geometry is missed [S1].
*   **Overfitting in Phase 1:** Training too long on the initial $N_0$ images can lead to overfitting, degrading generalization for subsequent images. The strict iteration limit ($T_{init}$) mitigates this [S1].
*   **Gradient Contention:** Using per-pixel gradient accumulation can lead to thread contention on GPUs. Splatting-based parallelism (per-Gaussian accumulation) is required for performance [S1].
*   **Learning Rate Inconsistency:** If learning rates are not adapted per-image, regions with fewer training iterations may have lower quality. The adaptive learning rate formula addresses this [S1].

## Operating characteristics

### Time and Memory Complexity
*   **Time Complexity:** Per new image, the method performs $T_I$ iterations of optimization. The complexity is dominated by the splatting and gradient computation, which is linear in the number of Gaussians and pixels. The hierarchical weighting and search tree queries add logarithmic overhead relative to the number of points/images [S1].
*   **Memory Complexity:** The memory usage scales with the number of Gaussians in the 3DGS field. The load-balancing loss helps control the total number of Gaussians, preventing excessive memory consumption [S1].

### Measured Performance
*   Evaluated on RGB datasets including 3DGS, Mip-NeRF 360, On-the-Fly SfM, and Replica [S1].
*   Compared against off-line solutions (Adr-Gaussian, Taming-3DGS) and SLAM-based methods (GS-SLAM, RTG-SLAM) [S1].
*   The method achieves near real-time optimization speeds, significantly faster than full re-optimization [S1].

### Strengths and Limitations
*   **Strengths:**
    *   Enables incremental, real-time 3DGS reconstruction.
    *   Prevents catastrophic forgetting through hierarchical weighting and semi-global optimization.
    *   Reduces Gaussian count and accelerates training via load-balancing loss and splatting-based parallelism [S1].
*   **Limitations:**
    *   Requires a robust On-the-Fly SfM backend for pose estimation and sparse cloud generation [S1].
    *   Performance depends on the quality of feature matches for overlap calculation [S1].

### When to Use
*   Use when images arrive sequentially and real-time or near real-time reconstruction is required.
*   Use when the full dataset is not available at the start of training [S1].

### When Not to Use
*   Use standard 3DGS optimization if the full dataset is available and offline training is acceptable, as it may achieve higher final quality with global optimization [S1].

## Background

### Origin
The method was introduced in the paper "Gaussian On-the-Fly Splatting: A Progressive Framework for Robust Near Real-Time 3DGS Optimization" [S1].

### History and Development
The method builds upon the original 3D Gaussian Splatting technique and integrates concepts from On-the-Fly SfM. It addresses the limitations of static 3DGS training in dynamic or incremental scenarios by introducing a progressive framework that updates the Gaussian field as new images arrive [S1].
