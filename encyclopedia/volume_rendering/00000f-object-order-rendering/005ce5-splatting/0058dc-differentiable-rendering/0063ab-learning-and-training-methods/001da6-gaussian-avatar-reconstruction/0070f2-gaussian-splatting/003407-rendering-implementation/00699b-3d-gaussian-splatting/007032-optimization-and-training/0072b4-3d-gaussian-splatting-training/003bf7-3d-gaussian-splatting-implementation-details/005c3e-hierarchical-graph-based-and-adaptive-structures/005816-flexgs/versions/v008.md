# FlexGS

Also called: Flexible 3D Gaussian Splatting, Elastic Inference for 3DGS

## Overview
FlexGS is an elastic inference method for 3D Gaussian Splatting (3DGS) that enables a single trained model to adapt to varying computational constraints at inference time by selecting and transforming a subset of Gaussians based on a desired model size ratio, without requiring additional fine-tuning [S1]. It solves the problem that standard 3DGS models are too memory-intensive for devices with restricted resources (e.g., smartphones, VR headsets) and that previous compression methods require costly retraining or separate model generation for each target hardware configuration [S1]. Unlike post-hoc compression methods that use fixed heuristics to retain Top-K Gaussians and require separate runs for each ratio, FlexGS jointly trains a learnable module to adaptively select points based on attributes and the desired ratio during training [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A pre-trained 3DGS model consisting of $N$ Gaussians, where each Gaussian $i$ is defined by position $X_i \in \mathbb{R}^3$, scaling vector $s_i \in \mathbb{R}^3$, rotation quaternion $q_i \in \mathbb{R}^3$, opacity $\alpha_i \in \mathbb{R}$, and color coefficients $SH_i$ [S1]. A target ratio $e \in (0, 1]$ representing the desired percentage of remaining Gaussians [S1].
*   **Output:** A subset of selected Gaussians with transformed attributes, ready for rendering, such that the number of active Gaussians is approximately $eN$ [S1].

**Data Structures:**
The core data structure remains the set of 3D Gaussians. Each Gaussian $G_i$ is defined by:
*   Mean position $X_i \in \mathbb{R}^3$ [S1].
*   Covariance matrix $\Sigma_i \in \mathbb{R}^{3 \times 3}$, decomposed into a scaling matrix $S_i$ and rotation matrix $R_i$ derived from vector $s_i$ and quaternion $q_i$ respectively: $\Sigma_i = R_i S_i S_i^\top R_i^\top$ [S1].
*   Opacity $\alpha_i \in \mathbb{R}$ [S1].
*   Color $c_i$ defined by spherical harmonics coefficients $SH_i \in \mathbb{R}^{(d+1)}$, where $d$ is the SH degree [S1].

**Algorithm Steps:**
1.  **Gaussian Selection:** For a given target ratio $e$, a learnable Gaussian selector predicts a binary scaler $\lambda_i$ for each Gaussian $i \in \{1, \dots, N\}$. $\lambda_i = 1$ if the Gaussian is selected, and $\lambda_i = 0$ otherwise. The selection must satisfy the constraint $\sum_{i=1}^N \lambda_i = eN$ [S1].
2.  **Gaussian Transformation:** For the selected Gaussians ($\lambda_i = 1$), a ratio-dependent Gaussian transformation field displaces their attributes (position, scale, rotation) to compensate for missing details caused by the reduction in the number of Gaussians [S1].
3.  **Rendering:** The transformed and selected Gaussians are rendered using standard differentiable splatting. The color $C$ of a pixel is computed by blending $N$ ordered points overlapping the pixel:
    $$ C = \sum_{i \in N} c_i \alpha_i \prod_{j=1}^{i-1} (1 - \alpha_j) $$
    where $c_i$ and $\alpha_i$ are the color and opacity of the $i$-th Gaussian [S1].

**Pseudocode:**
```python
def flexgs_inference(gaussians, target_ratio_e):
    """
    Perform elastic inference on a set of 3D Gaussians.
    
    Args:
        gaussians: List of N Gaussian objects. Each has attributes:
                   X (pos), s (scale), q (rotation), alpha (opacity), SH (color coeffs).
        target_ratio_e: Float in (0, 1], the desired fraction of Gaussians to keep.
        
    Returns:
        transformed_gaussians: List of selected and transformed Gaussian objects.
    """
    N = len(gaussians)
    
    # Step 1: Adaptive Gaussian Selection
    # The selector predicts binary scalers lambda_i based on Gaussian attributes and target_ratio_e.
    # Constraint: sum(lambda_i) == e * N.
    # Implementation note: The source describes a "learnable module" trained jointly.
    # At inference, this module outputs the selection mask.
    # We assume a function `selector_predict` encapsulates the learned logic.
    lambda_mask = selector_predict(gaussians, target_ratio_e)
    
    # Verify constraint (for robustness, though training ensures it)
    # assert sum(lambda_mask) == target_ratio_e * N
    
    selected_indices = [i for i, l in enumerate(lambda_mask) if l == 1]
    selected_gaussians = [gaussians[i] for i in selected_indices]
    
    # Step 2: Ratio-Dependent Gaussian Transformation
    # Displace selected Gaussians to compensate for missing details.
    # This module takes the selected Gaussians and the target ratio as input.
    transformed_gaussians = transformation_field(selected_gaussians, target_ratio_e)
    
    return transformed_gaussians

def render_splat(transformed_gaussians, camera):
    """
    Render the transformed Gaussians using differentiable splatting.
    """
    # Project 3D Gaussians to 2D covariance in camera coordinates
    # Sigma_prime = J * W * Sigma * W^T * J^T
    # where W is viewing transform, J is Jacobian of affine approximation
    projected_gaussians = []
    for g in transformed_gaussians:
        # Compute 2D covariance Sigma'
        # Note: Sigma = R * S * S^T * R^T
        # R and S are derived from g.q and g.s
        sigma_3d = compute_covariance(g.s, g.q)
        sigma_2d = project_covariance(sigma_3d, camera)
        
        # Compute 2D mean position
        pos_2d = project_position(g.X, camera)
        
        # Evaluate color c from SH coefficients and view direction
        color = evaluate_sh(g.SH, camera.view_direction, pos_2d)
        
        projected_gaussians.append({
            'pos_2d': pos_2d,
            'cov_2d': sigma_2d,
            'alpha': g.alpha,
            'color': color
        })
    
    # Sort by depth for alpha blending
    projected_gaussians.sort(key=lambda g: g['pos_2d'].z)
    
    # Render pixels
    # For each pixel, sum contributions from overlapping Gaussians
    # C = sum(c_i * alpha_i * product(1 - alpha_j)) for j < i
    # This is handled by the rasterizer backend
    return rasterize(projected_gaussians)
```

**Parameters:**
*   $e$: Target ratio of Gaussians to retain. Typical values depend on hardware constraints, ranging from 1.0 (full model) down to 0.01 (1% of Gaussians) [S1].
*   $N$: Total number of Gaussians in the pre-trained model [S1].

**Edge Cases and Pitfalls:**
*   **Extreme Compression:** Fixed heuristic selection rules may fail to generalize in extreme cases, such as when selecting only 1% of Gaussians, because importance scores must be frequently re-computed as Gaussian attributes evolve during training [S1]. FlexGS addresses this by joint training, but extreme ratios may still result in visual degradation if the transformation field cannot fully compensate [S1].
*   **Discrete Optimization:** The binary nature of $\lambda_i$ makes traditional gradient descent ineffective. The method uses a learnable module (likely involving Gumbel-Softmax or similar relaxation during training, as implied by "Adaptive Selection via Gumbel-Softmax" in the source text snippet) to enable differentiable selection during training [S1].

## Operating characteristics
*   **Time Complexity:** Inference time is proportional to the number of selected Gaussians $eN$. The selection and transformation modules add negligible overhead compared to the rendering cost [S1].
*   **Memory Complexity:** Memory usage is reduced by a factor of $e$ compared to the full 3DGS model, as only $eN$ Gaussians are stored and rendered [S1].
*   **Measured Performance:** Experiments on ZipNeRF, MipNeRF, and Tanks&Temples scenes demonstrate substantial rendering performance improvements without additional fine-tuning [S1].
*   **Strengths:** Single model deployment across diverse hardware; no retraining required for different ratios; adaptive selection based on learned importance rather than fixed heuristics [S1].
*   **Limitations:** Performance at very low ratios (e.g., 1%) may be limited by the capacity of the transformation field to compensate for missing details [S1].
*   **When to use:** When deploying 3DGS on devices with varying computational constraints (smartphones, VR headsets) and a single model instance is preferred over maintaining multiple pruned models [S1].
*   **When not to use:** When maximum possible quality at very low memory budgets is required and the transformation field cannot adequately compensate for the loss of Gaussians [S1].

## Background
FlexGS was introduced by Hengyu Liu, Yuehao Wang, Chenxin Li, Ruisi Cai, Kevin Wang, Wuyang Li, Pavlo Molchanov, Peihao Wang, and Zhangyang Wang from The Chinese University of Hong Kong, University of Texas at Austin, and Nvidia [S1]. It was published in CVPR 2025 (arXiv:2506.04174v1, June 4, 2025) [S1]. The work addresses the widespread adoption challenges of 3DGS, specifically its high memory overhead (millions of primitives with position, scaling, rotation, opacity, and color attributes) which limits use on devices with restricted computational resources [S1]. Previous approaches focused on pruning less important Gaussians but required fine-tuning and lacked adaptability for specific memory needs [S1]. FlexGS proposes an "elastic inference" framework that trains once and deploys everywhere [S1].
