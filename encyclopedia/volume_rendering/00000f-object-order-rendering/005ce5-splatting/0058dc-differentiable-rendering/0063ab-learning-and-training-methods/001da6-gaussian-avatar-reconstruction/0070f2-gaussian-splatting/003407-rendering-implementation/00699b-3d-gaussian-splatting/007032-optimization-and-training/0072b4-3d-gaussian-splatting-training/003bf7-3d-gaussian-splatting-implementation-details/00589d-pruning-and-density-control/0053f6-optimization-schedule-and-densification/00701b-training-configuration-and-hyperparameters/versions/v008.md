# Training Configuration and Hyperparameters

Also called: Decoder Training Setup, Hyperparameter Tuning, Training Configuration for Gaussian Splatting Decoder

## Overview
This article defines the specific hyperparameters, optimization schedules, and training protocols required to stabilize and accelerate the convergence of 3D Gaussian Splatting (3DGS) decoders. While the parent method [Optimization Schedule and Densification](15107-optimization-schedule-and-densification.md) handles the dynamic growth of primitives, this configuration ensures that the underlying geometric and photometric parameters converge correctly. It distinguishes itself from sibling methods like [Error-Driven 2D Gaussian Training](13985-error-driven-2d-gaussian-training.md) by focusing on the global training setup (learning rates, iteration counts, loss weights) rather than local densification criteria.

## How it works
The training process involves optimizing the Gaussian parameters ($\mathbf{p}_i, \mathbf{s}_i, \mathbf{q}_i, \alpha_i, \mathbf{c}_i$) using gradient descent. The specific configuration depends on the target application (e.g., generative decoding, downstream classification, or photometric stereo).

### Inputs and Outputs
*   **Inputs:** Input images (or point clouds), camera poses, and initial Gaussian distribution (often derived from Structure-from-Motion or random initialization).
*   **Outputs:** Optimized Gaussian primitives and their attributes.

### Data Structures
The implementation relies on the standard 3DGS primitive representation defined in the parent article. Additionally, specific variants may require:
*   **Grouped Gaussians:** For downstream tasks, Gaussians are grouped (e.g., 64 groups of 32) to facilitate feature aggregation [S3, unofficial].
*   **Voxel Grids:** For voxel-aligned methods, a voxel grid with a defined size (e.g., 0.002m) is used to constrain Gaussian placement [S1, unofficial].

### Optimization Steps and Parameters
The following steps and parameters are derived from the most common and effective configurations found in the literature.

1.  **Initialization:**
    *   **Standard 3DGS:** Initialize Gaussians from SfM points.
    *   **Synthetic/Implicit:** Initialize implicit functions as a sphere and randomize Gaussian positions [S6].
    *   **Sparse Initialization:** For methods sensitive to initialization (e.g., RAIN-GS), initialize Gaussians sparsely with large variance from SfM points [S4, unofficial].

2.  **Loss Function Definition:**
    The total loss $L$ is typically a weighted sum of photometric and geometric terms.
    *   **Standard Photometric:** $L = L_{rgb} + \lambda_1 L_{depth} + \lambda_2 L_{normal} + \dots$ [S1, unofficial][S7].
    *   **Photometric Stereo:** $L = L_c + L_n$, where $L_c$ is L1 photometric loss and $L_n$ is normal regularization derived from depth gradients [S5].
    *   **Lambertian Model:** In photometric stereo, intensity is modeled as $I(x,y) \propto l^T \cdot n(x,y)$, where $l$ is light direction and $n$ is surface normal [S5].

3.  **Optimizer Configuration:**
    *   **Optimizer:** Adam or AdamW [S2][S3, unofficial].
    *   **Learning Rate:**
        *   Standard Decoder: $0.0009$ [S2].
        *   Downstream Classification (ModelNet): $10^{-3}$ [S3, unofficial].
        *   Downstream Segmentation (ShapeNet-Part): $10^{-4}$ [S3, unofficial].
    *   **Weight Decay:** $0.05$ (for AdamW in classification tasks) [S3, unofficial].
    *   **Warm-up:** 5 warm-up epochs for probing tasks [S3, unofficial].

4.  **Training Schedule:**
    *   **Iteration Count:**
        *   Standard Decoder: 500,000 iterations [S2].
        *   Downstream Tasks: 300 epochs [S3, unofficial].
        *   Test-Time Optimization (TTO): 20 iterations selected for balance [S1, unofficial].
    *   **Batch Size:**
        *   Standard Decoder: Not specified in [S2], but implied by single-image rendering.
        *   Classification: Total batch size 256 [S3, unofficial].
        *   Segmentation: Batch size 16 [S3, unofficial].
    *   **Camera Sampling:**
        *   **360° Scenes (e.g., PanoHead):** Sample random cameras all around the head [S2].
        *   **Frontal Scenes (e.g., EG3D):** Sample mainly frontal views with small vertical/horizontal rotations [S2].

5.  **Hyperparameter Tuning (VoxelTTO Example):**
    *   **Voxel Size:** Evaluated at 0.0015, 0.002, 0.003, 0.005m. Optimal: 0.002m [S1, unofficial].
    *   **Splits per Voxel:** Evaluated at 1, 2, 4. Optimal: 2 splits [S1, unofficial].
    *   **Depth Loss:** Removing $L_{depth}$ slightly reduces geometric accuracy [S1, unofficial].

### Pseudocode: Standard Decoder Training Loop
```python
# Standard training loop for 3DGS decoder
# Based on [S2] and [S1, unofficial]

def train_decoder(dataset, iterations=500000, lr=0.0009, optimizer_type="Adam"):
    # 1. Initialization
    # Initialize Gaussians from SfM points or random distribution
    gaussians = initialize_gaussians(dataset.initial_points)
    
    # 2. Optimizer Setup
    optimizer = create_optimizer(gaussians.parameters(), lr=lr, type=optimizer_type)
    
    # 3. Training Loop
    for step in range(1, iterations + 1):
        # Sample a random camera pose and image from the dataset
        # For 360 deg scenes (PanoHead): random full sphere
        # For frontal scenes (EG3D): random frontal with small rotations
        camera, target_image = dataset.sample_random_view()
        
        # Render the scene using the current Gaussian parameters
        rendered_image, depth_map, normal_map = render_gaussians(gaussians, camera)
        
        # Calculate Loss
        # L_rgb: L1 or LPIPS between rendered and target image
        # L_depth: Depth consistency loss (optional, [S1, unofficial])
        # L_normal: Normal regularization (optional, [S5])
        loss = calculate_loss(rendered_image, target_image, depth_map, normal_map)
        
        # Backpropagate and update
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        
        # 4. Densification and Pruning
        # Triggered periodically based on parent method [15107-optimization-schedule-and-densification.md]
        if step % densification_interval == 0:
            gaussians = densify_and_prune(gaussians, camera, target_image)
            
    return gaussians
```

### Edge Cases and Pitfalls
*   **Simultaneous Optimization:** Optimizing geometry and high-dimensional semantics simultaneously from initialization causes unstable gradients, chaotic densification, and poor spatial convergence [S8].
*   **Sparse Views:** Standard densification degrades under sparse views because color overfits. Geometrically enhanced supervision or selective updates are required [S7].
*   **Initialization Sensitivity:** Poor initialization can lead to 2D Gaussian projections smaller than a pixel. Sparse initialization with large variance helps mitigate this [S4, unofficial].

## Subtopics

### [Adaptive Gaussian Refinement Strategy](16570-adaptive-gaussian-refinement-strategy.md)
The Adaptive Gaussian Refinement Strategy is a densification and pruning mechanism for 3D Gaussian Splatting that dynamically adjusts the number and size of Gaussians during training based on 2D gradient magnitude and screen-space size. It solves the problem of fixed Gaussian counts by growing Gaussians in regions with high reconstruction error and pruning those that are redundant or overly large. It differs from standard densification by explicitly tracking screen-space radii to enable screen-aware splitting and pruning, and by using a reset-based accumulation of gradient statistics to avoid bias from early training steps.

### [Spectrum and Edge-based Gaussian Splat Count Estimation](19432-spectrum-and-edge-based-gaussian-splat-count-estimation.md)
This method determines the expected number of 3D Gaussian splats per semantic group by analyzing image spectral complexity and edge energy to control geometric detail. It differs from naive frequency magnitude statistics by using a high-pass threshold strategy (implemented via Canny edge detection) to isolate high-frequency signals, which directly dictate Gaussian refinement. This approach outperforms naive mean magnitude because it suppresses dominant low-frequency noise and targets the high-frequency geometric details that require denser Gaussian representation.

### [Densification and Splitting](20677-densification-and-splitting.md)
Densification and splitting is the primary mechanism in 3D Gaussian Splatting (3DGS) for adapting the primitive population to scene complexity during optimization. It addresses the problem of insufficient geometric detail by subdividing existing Gaussians into smaller, more numerous primitives in regions where the current representation fails to reconstruct the input images accurately. Unlike static initialization methods, this dynamic process allows the model to grow its capacity iteratively, balancing reconstruction fidelity against computational cost. It sets itself apart from sibling methods like [Gaussian Pruning and Removal](21353-gaussian-pruning-and-removal.md) by focusing on constructive growth rather than destructive culling, although the two are often paired in a complete density control loop.

### [LiDAR-Guided Structural Initialization](20693-lidar-guided-structural-initialization.md)
LiDAR-Guided Structural Initialization is a method for initializing the geometric structure and density priors of a sparse voxel grid for driving scene reconstruction, specifically within the DrivingVoxels framework. It solves the problem of initializing a volumetric representation that is both sparse enough for efficiency and geometrically plausible enough to guide optimization, by using LiDAR point clouds to define voxel subdivision and density values. It differs from sibling methods like [Adaptive Gaussian Refinement Strategy](16570-adaptive-gaussian-refinement-strategy.md) by operating on a voxel grid rather than Gaussian splats, and from [Gaussian Pruning](18664-gaussian-pruning.md) by focusing on initial structural creation rather than post-training cleanup.

### [Gaussian Pruning and Removal](21353-gaussian-pruning-and-removal.md)
Gaussian Pruning and Removal is a family of optimization techniques in 3D Gaussian Splatting (3DGS) that reduces the number of Gaussian primitives by eliminating redundant or low-contribution splats. It solves the problem of excessive memory consumption and computational overhead caused by the densification process, which generates many auxiliary Gaussians with low geometric meaning. Unlike densification control which limits freedom, these methods are applied post-densification or during optimization to guarantee real-time rendering for large-scale scenes with nearly identical rendering quality while significantly reducing Gaussian count and storage.

### Standard Downstream Protocols
A standardized training and evaluation pipeline for classification and part segmentation tasks using Gaussian inputs [S3, unofficial].
*   **ModelNet10/40:** Uses 1,024 Gaussians, 64 groups of 32, and all 14 attributes. Full fine-tuning, linear probing, and three-layer MLP probing run for 300 epochs with AdamW, learning rate $10^{-3}$, weight decay 0.05, 5 warm-up epochs, and total batch size 256. Frozen probing updates only the classifier [S3, unofficial].
*   **ShapeNet-Part:** Uses 2,048 Gaussians, 128 groups of 32, batch size 16, learning rate $10^{-4}$, and 300 epochs [S3, unofficial].

### RAIN-GS
A method that initializes Gaussians sparsely with large variance from the SfM point cloud and progressively applies low-pass filtering to avoid 2D Gaussian projections smaller than a pixel, addressing sensitivity to initialization [S4, unofficial].

### Photometric Stereo with Gaussian Splatting
A calibrated photometric stereo method that reconstructs 3D normal maps from multiple images with different lighting by optimizing Gaussian Splatting parameters using inverse rendering and a Lambertian reflectance model [S5].
*   **Lighting Model:** Uses the Lambertian model $I(x,y) \propto l^T \cdot n(x,y)$ to calculate self-occlusions (shadows) by analyzing if surfaces are aligned with the light direction [S5].
*   **Loss Function:** Minimizes $L = L_c + L_n$, where $L_c$ is the L1 photometric loss and $L_n$ is a normal regularization term ensuring Gaussians align with the true object surface, calculated via the gradient of the depth map [S5].

### 3DGSR Initialization and Adaptive Control
*   **Initialization:** For synthetic data, initializes the implicit function as a sphere and randomly initializes Gaussian positions. For real-world scenes, adopts SFM points as initialized Gaussian positions [S6].
*   **Control:** Increases the number of 3D Gaussian primitives during training following the adaptive control strategy in 3DGS [S6].
*   **Implementation:** Implemented with CUDA and tinycudann, customizing normal and depth maps CUDA rendering kernels [S6].

### Selective Gaussian Update
A strategy to selectively update Gaussian primitive positions using rendered geometric cues (depth/normal) instead of continuous densification, which degrades under sparse views [S7].
*   **Warping:** Warps an image patch from a source view to a target view using the Gaussian primitive's position $\mathbf{p}$ and orientation $\mathbf{R}$ along with camera pose [S7].
*   **Evaluation:** Computes NCC for Gaussian primitive warping (NCCG) and for warping using rendered pixel-wise depth and normals (NCCR) [S7].
*   **Update:** If NCCR > NCCG, reprojects the rendered depth into a 3D point and updates the position of the corresponding Gaussian primitive. Updates occur every 100 training steps [S7].
*   **Formula:** $NCC(x, y) = \frac{\sum_{l=1}^{n} (x_l - \bar{x})(y_l - \bar{y})}{\sqrt{\sum_{l=1}^{n} (x_l - \bar{x})^2 \sum_{l=1}^{n} (y_l - \bar{y})^2}}$ [S7].

### Phased Optimization Schedule
A training strategy that separates geometric and semantic optimization into phases to prevent unstable gradients and chaotic densification caused by simultaneous optimization [S8].
*   **Phase 1:** Set semantic learning rate to zero. Optimize only spatial geometry and photometric appearance using visual loss functions.
*   **Phase 2:** Wait for geometric structure to stabilize and Gaussian primitives to settle into approximate spatial locations. Gradually warm up the semantic learning rate to activate semantic embedding optimization [S8].
*   **Pitfall:** Simultaneous optimization of geometry and semantics from initialization causes unstable gradients, chaotic densification, poor spatial convergence, and failure to localize semantic concepts [S8].

## Operating characteristics
*   **Time Complexity:** Training time scales with the number of iterations (e.g., 500k for decoders [S2]) and the number of Gaussians. Test-Time Optimization (TTO) adds negligible overhead (2.304s for 10 images vs 2.293s without TTO) [S1, unofficial].
*   **Memory Complexity:** Memory usage is dominated by the number of Gaussians. Pruning methods significantly reduce storage [S1, unofficial]. Downstream protocols use fixed counts (1K-4K) [S3, unofficial].
*   **Performance:** Standard decoders achieve high frame rates with efficient renderers (e.g., SIBR viewer) [S2]. Voxel-aligned methods balance performance and computation with optimal voxel size of 0.002m [S1, unofficial].
*   **Strengths:** High-fidelity reconstruction, real-time rendering capability, flexible initialization.
*   **Limitations:** Sensitive to initialization (addressed by RAIN-GS [S4, unofficial]), degrades under sparse views without geometric supervision (addressed by Selective Update [S7]), unstable with simultaneous semantic optimization (addressed by Phased Schedule [S8]).

## Background
3D Gaussian Splatting was introduced by Müller et al. in 2023 [Müller 2021] as a real-time explicit scene representation. Subsequent work has focused on optimizing training configurations for specific domains:
*   **Generative Decoding:** PanoHead and EG3D decoders use 500k iterations with specific camera sampling strategies [S2].
*   **Downstream Tasks:** Gaussian-JEPA and Gaussian-MAE use standardized protocols for classification and segmentation [S3, unofficial].
*   **Photometric Stereo:** Inverse rendering approaches use Lambertian models to reconstruct normals [S5].
*   **Semantic Alignment:** Phased optimization schedules prevent instability in vision-language models [S8].
