# LinPrim Differentiable Rendering Pipeline

Also called: LinPrim Rendering, LinPrim rasterizer, Linear Primitive Rendering, Linear Primitives for Differentiable Volumetric Rendering, Octahedron Rendering

## Overview
LinPrim is a differentiable rendering method that replaces the Gaussian primitives of 3D Gaussian Splatting with convex polyhedra, specifically octahedra, to enable explicit geometric representation [S1]. It solves the problem of approximating complex scene geometry by using bounded, triangular primitives that allow for exact ray-intersection calculations, thereby distributing gradients directly onto geometric features rather than kernel parameters [S1]. Unlike its sibling [3D Gaussian Splatting](3D-Gaussian-Splatting.md) which relies on soft Gaussian kernels, LinPrim uses hard-edged convex shapes, offering a trade-off between geometric fidelity and the complexity of intersection-based rasterization [S1].

## How it works
The method employs a two-stage rendering process: per-primitive preprocessing followed by per-pixel rasterization [S1]. This structure enables efficient parallelization of primitive construction and sorting before the final compositing stage [S1].

### Inputs and Outputs
*   **Inputs:**
    *   Scene primitives defined by position, distances (defining shape), rotation, and Spherical Harmonic (SH) coefficients [S1].
    *   Camera pose (view matrix) and intrinsic parameters [S1].
*   **Outputs:**
    *   A 2D image with accumulated color and opacity [S1].

### Data Structures
Each primitive stores the following features [S1]:
1.  **Position:** 3D center coordinate.
2.  **Shape:** Distances from the center to the vertices. For octahedra, symmetry is enforced such that opposite vertices share the same distance, reducing complexity [S1].
3.  **Rotation:** Orientation in space [S1].
4.  **Color:** 48 SH coefficients (floats) to capture view-dependent appearance [S1]. This accounts for the majority of memory per primitive [S1].

### Numbered Steps

1.  **Preprocessing (Per-Primitive):**
    1.  Construct the primitive geometry from position, distances, and rotation [S1].
    2.  Transform the primitive into the camera's coordinate system using the camera pose [S1].
    3.  Calculate view-dependent color based on the viewing direction using the stored SH coefficients [S1].
    4.  Project the primitive into the 3D affine ray space approximation (EWA Splatting) [S1]. This approximation is valid because small primitives keep the error negligible [S1].
    5.  Compute the projected bounding box in screen space to determine visibility [S1].
    6.  Store the $L_1$-slab parameters of the projected octahedron for the rasterization stage [S2, unofficial].

2.  **Global Sorting and Tiling:**
    1.  Tile the screen into regions (e.g., $16 \times 16$ tiles) [S1].
    2.  Assign primitives to tiles based on their projected bounding boxes [S1].
    3.  Sort the primitives within each tile in approximate front-to-back order [S1].

3.  **Rasterization (Per-Pixel):**
    1.  For each pixel in a tile, reconstruct the pixel ray using the $+0.5$ pixel-center convention [S2, unofficial].
    2.  Determine if the ray intersects the convex primitive. Since primitives are convex, the ray intersects either twice or not at all [S1].
    3.  Use the Möller-Trumbore intersection algorithm (MTIA) to find the intersection points [S1]. This algorithm is fully differentiable [S1].
    4.  If two intersections exist, calculate the opacity based on the distance between the entry and exit points [S1].
    5.  **Normalization:** To handle scale ambiguity, normalize the intersection distances. Determine the smallest distance $d$ among all primitives and scale all distance measurements accordingly [S1].
    6.  Compute the density $\sigma$ using the normalized distances and the primitive's target opacity $\alpha$:
        $$ \sigma(\alpha) = -\frac{\log(1 - 0.99 \cdot \alpha)}{2 \cdot \min(d_x, d_y, d_z)} $$
        where $d_x, d_y, d_z$ are the normalized distances [S1].
    7.  Compute the Beer-Lambert opacity from the ray’s entry and exit depths through the octahedron [S2, unofficial].

4.  **Compositing:**
    1.  Aggregate color contributions of all visible primitives via alpha blending in front-to-back order [S1].
    2.  Stop blending once the cumulative opacity reaches a threshold of $0.999$ [S1].

def linprim_render(primitives, camera, tile_size=16):
    H, W = camera['height'], camera['width']
    tiles = [(y, x) for y in range(0, H, tile_size) for x in range(0, W, tile_size)]
    tile_prims = {t: [] for t in tiles}
    
    # 1. Preprocessing
    for p in primitives:
        # Transform to camera space
        p_cam = transform_to_camera(p, camera['view_matrix'])
        
        # Project to 3D affine ray space (EWA approximation)
        # Compute bounding box in screen space
        bbox = compute_3d_bbox(p_cam)
        
        # Assign to tiles
        for t in tiles:
            if intersects_bbox(bbox, t, tile_size):
                # Store L1-slab parameters for rasterization
                slab_params = compute_slab_params(p_cam)
                tile_prims[t].append({
                    'slab_params': slab_params,
                    'depth': p_cam['z'],
                    'sh_coeffs': p['sh_coeffs'],
                    'target_alpha': p['alpha']
                })
    
    # 2. Sorting
    for t in tiles:
        tile_prims[t].sort(key=lambda x: x['depth'])
        
    # 3. Find global minimum distance for normalization [S1]
    min_d_global = float('inf')
    for t in tiles:
        for prim in tile_prims[t]:
            # Estimate distance from slab params or geometry
            d = estimate_primitive_distance(prim['slab_params'])
            if d < min_d_global:
                min_d_global = d
                
    # 4. Rasterization and Compositing
    image = zeros((H, W, 3))
    for t in tiles:
        prims = tile_prims[t]
        for y in range(t[0], min(t[0] + tile_size, H)):
            for x in range(t[1], min(t[1] + tile_size, W)):
                acc_color = zeros(3)
                T = 1.0
                
                # Reconstruct pixel ray [S2, unofficial]
                ray = reconstruct_pixel_ray(x, y, camera)
                
                for prim in prims:
                    # Check intersection with octahedron [S1]
                    hits = mtia_intersect(ray, prim['slab_params'])
                    
                    if len(hits) == 2:
                        d_entry, d_exit = hits[0], hits[1]
                        d_path = d_exit - d_entry
                        
                        # Normalize distance [S1]
                        # Scale relative to smallest primitive distance
                        d_normalized = d_path / min_d_global
                        
                        # Calculate density [S1]
                        # min(d_x, d_y, d_z) is approximated by d_normalized in this context
                        sigma = -log(1.0 - 0.99 * prim['target_alpha']) / (2.0 * d_normalized)
                        
                        # Beer-Lambert opacity [S2, unofficial]
                        alpha = 1.0 - exp(-sigma * d_path)
                        
                        # Evaluate color from SH [S1]
                        color = evaluate_sh(prim['sh_coeffs'], ray.direction)
                        
                        weight = alpha * T
                        acc_color += color * weight
                        T *= (1.0 - alpha)
                        
                        if T < 1e-4: # Threshold 0.999 opacity means T < 0.001
                            break
                image[y, x] = acc_color
    return image

### Parameters
*   **SH Degree:** 48 coefficients (typically degree 3) are stored per primitive [S1].
*   **Opacity Threshold:** Blending stops when cumulative opacity reaches $0.999$ [S1].
*   **Tile Size:** Typically $16 \times 16$ pixels, consistent with 3DGS [S1].

### Edge Cases and Pitfalls
*   **Scale Ambiguity:** Without normalization, the appearance of primitives varies across different scene sizes. This is handled by scaling intersection distances relative to the smallest primitive distance $d$ in the scene [S1].
*   **Approximation Error:** The 3D affine ray space approximation error grows with distance from the center points. However, for small primitives required for high-fidelity reconstruction, this error remains negligible [S1].
*   **Convexity:** The method relies on primitives being convex. If a primitive is non-convex, the ray may intersect more than twice, breaking the simple opacity calculation [S1].

## Operating characteristics
*   **Time Complexity:** Dominated by the sorting step $O(N \log N)$ and the rasterization step $O(P \cdot N_{prim})$, where $P$ is pixels and $N_{prim}$ is primitives per pixel. The use of tiling and early termination (threshold 0.999) optimizes this [S1].
*   **Memory Complexity:** High memory usage per primitive due to 48 SH coefficients (floats) [S1].
*   **Performance:** Capable of real-time rendering speeds comparable to 3DGS, while providing explicit geometric representation [S1].
*   **Strengths:** Differentiable through exact ray-triangle intersections; bounded geometry allows for intuitive scene modification; high-fidelity reconstruction of fine geometry [S1].
*   **Limitations:** Scale ambiguity requires global normalization; approximation errors from EWA splatting projection; convexity constraint limits primitive types (though tetrahedra are also supported) [S1].

## Background
LinPrim was introduced in the paper "LinPrim: Linear Primitives for Differentiable Volumetric Rendering" [S1]. It builds upon the 3D Gaussian Splatting pipeline but replaces Gaussian kernels with transparent octahedron and tetrahedron primitives [S1]. The method was developed to provide a more intuitive and geometrically explicit representation for differentiable rendering, allowing gradients to be backpropagated through intersection calculations to geometric features [S1]. It is also referenced in the XPR renderer documentation as an example of a point-based primitive that uses $L_1$-slab parameters and ray-intersection based evaluation [S2, unofficial].
