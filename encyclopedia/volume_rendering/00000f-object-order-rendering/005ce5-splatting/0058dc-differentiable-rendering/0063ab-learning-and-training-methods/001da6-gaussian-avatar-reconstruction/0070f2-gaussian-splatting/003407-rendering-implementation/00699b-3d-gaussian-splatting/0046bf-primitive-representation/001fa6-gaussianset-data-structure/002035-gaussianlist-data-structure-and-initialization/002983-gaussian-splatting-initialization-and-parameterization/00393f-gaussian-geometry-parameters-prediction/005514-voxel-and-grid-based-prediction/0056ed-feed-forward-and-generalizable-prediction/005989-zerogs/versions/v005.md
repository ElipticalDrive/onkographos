# ZeroGS

Also called: ZeroGS: Training 3D Gaussian Splatting from Unposed Images

## Overview
ZeroGS is a pipeline for training 3D Gaussian Splatting (3DGS) from hundreds of unposed and unordered images without requiring Structure-from-Motion (SfM) tools like COLMAP [S1, unofficial]. It leverages a pretrained foundation model (Spann3R) as a neural scene representation to predict dense 3D Gaussians and pointmaps, followed by an incremental registration process that refines camera poses and optimizes the scene using a rendering loss [S1, unofficial]. It differs from its siblings by regressing points in a global coordinate frame without aligning dense pairwise pointmaps, allowing it to handle hundreds of images on consumer hardware [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $N$ unposed, unordered RGB images $\{I_1, \dots, I_N\}$. One image is selected as the seed image $I_{seed}$ [S1, unofficial].
*   **Output:** A set of 3D Gaussians $\mathcal{G}$ and camera poses $\{P_1, \dots, P_N\}$ for all registered images [S1, unofficial].

**Data Structures:**
*   **Training Buffer:** A set of registered images and their associated poses and 3D Gaussians. Initially contains only the seed image [S1, unofficial].
*   **3D Gaussian $G_k$:** Defined by mean position $\mu_k$, scale $s_k$, rotation $r_k$ (quaternion), opacity $\alpha_k$, and color coefficients $c_k$ [S1, unofficial].
*   **Pointmap $X_{i,j}$:** A dense map of 3D points for image $j$ expressed in the coordinate frame of camera $i$ [S1, unofficial].

**Network Architecture (Spann3R):**
The method uses Spann3R, a variant of DUSt3R, which uses a Vision Transformer (ViT) $V$ as a shared encoder and transformer decoders [S1, unofficial].
1.  **Encoding:** For an image pair $(I_i, I_j)$, features are extracted:
    $$ f_{ie}, f_{je} = V(I_i, I_j) $$
2.  **Decoding:** Reference and target decoder features are computed:
    $$ f_{id} = D_{ref}(f_{ie}, f_{je}), \quad f_{jd} = D_{tgt}(f_{je}, f_{ie}) $$
    where $D_{ref}$ and $D_{tgt}$ are reference and target transformer decoders [S1, unofficial].
3.  **Projection:** Pointmaps are generated via projection heads $H_{ref}$ and $H_{tgt}$:
    $$ X_{i,i}, X_{j,i} = H_{ref}(f_{id}), H_{tgt}(f_{jd}) $$
    Spann3R extends this by using a spatial feature memory to predict pointmaps $X_{i,g}, X_{j,g}$ in a global coordinate frame relative to a seed image, avoiding the need for global alignment of pairwise pointmaps [S1, unofficial].

**Algorithm Steps:**
1.  **Seed Initialization:** Initialize the pipeline with the pretrained Spann3R model and the single seed image $I_{seed}$ [S1, unofficial].
2.  **Batch Registration:**
    *   Select a batch of unregistered images.
    *   Use Spann3R to predict 3D Gaussians $G_k$ and pointmaps $X_k$ for pairs consisting of registered images (from the buffer) and unregistered images [S1, unofficial].
    *   Compute coarse camera poses for unregistered images using RANSAC and a Perspective-n-Point (PnP) solver on the 2D-3D correspondences from the predicted pointmaps [S1, unofficial].
3.  **Pose Refinement:**
    *   Refine the coarse camera poses by minimizing a point-to-camera ray consistency loss. This loss minimizes the distance between the predicted 3D points and the camera centers across multiple views [S1, unofficial].
4.  **Rendering and Optimization:**
    *   Rasterize the 3D Gaussians using the refined camera poses to render images [S1, unofficial].
    *   Compute an RGB loss (e.g., L1 or SSIM) between rendered and ground truth images.
    *   Back-propagate gradients to update the network parameters and Gaussian attributes [S1, unofficial].
5.  **Buffer Update:**
    *   At the end of each training epoch, register new images into the training buffer using the refined poses [S1, unofficial].
6.  **Iteration:**
    *   Repeat steps 2-5 until all images are registered or no more images can be registered [S1, unofficial].

**Parameters:**
*   **Hardware:** Runs on a 24GB consumer-level GPU for hundreds of images [S1, unofficial].
*   **Batch Size:** Images are registered in batches rather than individually [S1, unofficial].

**Pitfalls:**
*   **Memory Limits:** Aligning dense pairwise pointmaps to a global frame (as done in DUSt3R post-processing) is time-consuming and can exceed GPU memory limits for large scenes [S1, unofficial]. ZeroGS avoids this by regressing in a global frame directly via Spann3R [S1, unofficial].
*   **Textureless Areas:** 3DGS may struggle to identify Gaussians in textureless areas; however, the dense pointmap prediction helps mitigate this [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Incremental registration scales with the number of images. Batch registration reduces overhead compared to individual registration [S1, unofficial].
*   **Memory Complexity:** Optimized to run on 24GB GPUs, handling hundreds of images by avoiding global alignment of dense pointmaps [S1, unofficial].
*   **Strengths:** Does not require COLMAP or initial poses; handles unordered/unposed images; renders higher quality images than 3DGS with COLMAP poses on standard datasets [S1, unofficial].
*   **Limitations:** Relies on the accuracy of the pretrained foundation model (Spann3R/DUSt3R); finetuning is challenging due to the lack of ground-truth 3D points in unseen scenes [S1, unofficial].
*   **When to use:** When camera poses are unavailable and the scene is large/unordered.
*   **When not to use:** When high-precision COLMAP poses are already available, or when GPU memory is severely constrained (<24GB) for very large scenes.

## Background
ZeroGS was proposed to address the limitation of traditional SfM pipelines that require posed images or extensive preprocessing [S1, unofficial]. It builds on the principles of DUSt3R and Spann3R, which use transformer-based architectures for 3D reconstruction from image pairs [S1, unofficial]. Unlike ACE0, which uses sparse pointmaps and CNNs, ZeroGS uses dense pointmaps and transformers [S1, unofficial]. It differs from InstantSplat and Splatt3R by regressing points in a global coordinate frame without aligning dense pointmaps, followed by incremental registration [S1, unofficial]. Evaluated on LLFF, MipNeRF360, and Tanks-and-Temples datasets, it demonstrates robust performance without pose priors [S1, unofficial].
