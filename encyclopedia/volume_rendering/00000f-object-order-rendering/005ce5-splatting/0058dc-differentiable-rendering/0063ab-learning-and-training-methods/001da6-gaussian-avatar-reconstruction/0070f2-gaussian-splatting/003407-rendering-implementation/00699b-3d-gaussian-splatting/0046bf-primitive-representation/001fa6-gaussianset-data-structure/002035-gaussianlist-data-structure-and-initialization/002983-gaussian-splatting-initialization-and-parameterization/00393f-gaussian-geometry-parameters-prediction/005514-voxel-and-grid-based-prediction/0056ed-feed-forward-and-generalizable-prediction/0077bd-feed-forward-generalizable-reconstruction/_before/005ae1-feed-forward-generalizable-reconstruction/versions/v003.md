# Feed-forward Generalizable Reconstruction

Also called: Feed-forward 3D Gaussian Splatting, Generalizable Gaussian Splatting

## Overview
Feed-forward generalizable reconstruction maps input images directly to a 3D Gaussian Splatting (3DGS) representation without per-scene optimization [Parent]. It solves the latency bottleneck of traditional 3DGS by leveraging learned priors from large-scale datasets to predict Gaussian parameters in a single forward pass [Parent]. Unlike sibling methods that may rely on specific input constraints (e.g., calibrated poses or stereo pairs), this family encompasses diverse architectures ranging from uncalibrated stereo inputs to sparse multi-view setups, distinguished by their specific strategies for feature aggregation, spatial grouping, and primitive prediction .

## Shared principles
All methods in this family share the core objective of mapping input image features to a set of 3D Gaussian parameters $\mathcal{G} = \{\mu, \Sigma, \alpha, c\}$ without per-scene gradient descent [Parent].

1.  **Input Representation:** Inputs are typically one or more RGB images $I \in \mathbb{R}^{H \times W \times 3}$. Some methods require known camera poses $P$, while others (e.g., [Splatt3R](16423-splatt3r.md), [ZeroGS](16425-zerogs.md)) predict poses or operate on uncalibrated inputs.
2.  **Feature Encoding:** A shared encoder (e.g., Vision Transformer, CNN) extracts multi-scale features from the input images. Cross-attention or cost volumes are often used to aggregate multi-view information.
3.  **Primitive Prediction:** A decoder head predicts Gaussian attributes. These attributes are usually:
    *   **Mean ($\mu$):** 3D position.
    *   **Covariance ($\Sigma$):** Defined by scale $s$ and rotation $r$ (quaternion or 6D).
    *   **Opacity ($\alpha$):** Scalar.
    *   **Color ($c$):** Spherical Harmonics (SH) coefficients or constant RGB.
4.  **Differentiable Rendering:** The predicted Gaussians are rendered into target views using differentiable rasterization to compute reconstruction losses (e.g., L1, SSIM, LPIPS) for training the network.
5.  **Generalization:** The network is trained on a large dataset of scenes to learn priors about geometry and appearance, allowing inference on unseen scenes.

## Subtopics

### [AnySplat Pipeline](12847-anysplat-pipeline.md)
Operates on uncalibrated input views, simultaneously predicting Gaussian parameters, depth maps, and camera poses. It distinguishes itself by integrating a Differentiable Voxelization module to stabilize rendering and enable robust geometry supervision via pseudo-geometry priors from a pretrained VGGT model.

### [FineSplat](15257-finesplat.md)
Uses a two-stage dual-grouping strategy to balance local detail preservation with global multi-view reasoning. It employs high-resolution 4x4 patch tokens and serialized attention for 3D spatial grouping to avoid the cost of global multi-view attention.

### [SparSplat](15813-sparsplat.md)
Maps sparse input images to 2D Gaussian Splatting (2DGS) parameters. It differs by using 2D planar primitives instead of 3D volumetric primitives, ensuring multi-view depth consistency required for coherent TSDF mesh fusion.

### [Splatt3R](16423-splatt3r.md)
Predicts 3D Gaussian Splat parameters directly from a pair of uncalibrated RGB images using a parallel "Gaussian head" on top of the MASt3R foundation model. It employs a loss masking strategy to enable robust extrapolation to viewpoints outside the input frustums.

### [GlobalSplat](16571-globalsplat.md)
Aligns multi-view inputs into a fixed set of global latent scene tokens before decoding explicit 3D geometry. It uses an iterative, disentangled dual-branch architecture and a coarse-to-fine capacity curriculum to achieve a superior quality-efficiency trade-off.

### [Generalizable Pixel-Wise 3D Gaussian Splatting](17059-generalizable-pixel-wise-3d-gaussian-splatting.md)
Designed for real-time novel view synthesis of humans from sparse camera views. It performs source-view computation once and renders novel views instantly, allowing concurrent rendering of multiple views.

## Background
The family originates from the need to accelerate 3D Gaussian Splatting, which traditionally requires per-scene optimization [Parent]. Early works adapted generalizable depth estimation and stereo matching techniques to predict Gaussian primitives directly . The integration of foundation models like MASt3R and VGGT has further enabled uncalibrated input handling . Recent developments focus on efficient token-based representations and 2DGS variants for surface reconstruction .
