# RLSplat

Also called: Resource-Linear Budget Control for Feed-forward 3D Gaussian Splatting

## Overview
RLSplat is a resource-linear, budget-controllable feed-forward 3D Gaussian Splatting (FF3DGS) framework that generates exactly $B$ Gaussians for a given scene, ensuring that inference latency and peak memory scale linearly with the requested budget [S1, unofficial]. Unlike prior budget-controllable methods that predict a dense set of candidates and prune them (resulting in nearly constant inference cost regardless of the target budget), RLSplat uses a learned allocation policy to distribute the budget across local scene regions and a resource-linear decoder to refine the Gaussians [S1, unofficial]. It solves the problem of adapting FF3DGS to strict resource constraints (e.g., in AR/VR or robotics) where both output size and computational cost must be strictly bounded [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** $V$ uncalibrated context images $\{I_i\}_{i=1}^V$, and a target Gaussian budget $B$ (integer).
*   **Outputs:** A set of $B$ 3D Gaussians $\mathcal{G} = \{g_b\}_{b=1}^B$ and camera parameters $\{P_i\}_{i=1}^V$. Each Gaussian $g_b$ consists of a 3D center, opacity, scale, rotation, and color coefficients [S1, unofficial].

**Data Structures:**
1.  **Anchor Tokens ($\mathcal{A}$):** A set of $N$ tokens $\{a_n\}_{n=1}^N$ extracted from the geometry backbone, each representing a local 3D region.
2.  **Allocation Vector ($\mathbf{k}$):** A discrete vector $\mathbf{k} \in \mathbb{Z}_{\ge 0}^N$ where $k_n$ is the number of Gaussians assigned to anchor $n$, such that $\sum_{n=1}^N k_n = B$.
3.  **Gaussian Tokens:** $B$ tokens generated by spawning $k_n$ tokens per anchor $n$.
4.  **Hierarchical Neighbor Search Structure:** Used to find the $K_{gs}$ nearest Gaussian neighbors for each token efficiently.

**Parameters:**
*   $B$: Target Gaussian budget. Typical values: 2K, 8K, 64K [S1, unofficial].
*   $K_{gs}$: Number of nearest Gaussian neighbors for local refinement. Default ablation value: 16. Can be changed at inference without retraining [S1, unofficial].
*   $K_{anc}$: Number of anchor neighbors used in hierarchical search. Fixed value in ablations: 16 [S1, unofficial].
*   $C$: Number of rollouts (candidate allocations) drawn per training step for GSPO. Not given in the sources.

**Algorithm Steps:**

1.  **Geometry Encoding:** The geometry backbone encodes the input images $\{I_i\}$ into $N$ anchor tokens $\{a_n\}_{n=1}^N$ and predicts camera parameters $\{P_i\}$ [S1, unofficial].
2.  **Gaussian Allocation:** The allocation policy $\pi_\psi$ predicts a discrete allocation vector $\mathbf{k}$ based on anchor features. The policy ensures $\sum k_n = B$. This is trained using Group Sequence Policy Optimization (GSPO) [S1, unofficial].
3.  **Token Spawning:** For each anchor $n$, $k_n$ Gaussian tokens are spawned. The total number of Gaussian tokens is exactly $B$ [S1, unofficial].
4.  **Resource-Linear Decoding:**
    *   **Initialization:** Each Gaussian token is initialized with an initial state (center, scale, rotation, opacity, color) predicted from its token and anchor context [S1, unofficial].
    *   **Hierarchical Neighbor Search:** For each Gaussian token, the $K_{gs}$ nearest Gaussian tokens are identified using a hierarchical neighbor search over the anchor tokens and their spawned Gaussians [S1, unofficial].
    *   **Local Refinement:** Each Gaussian token attends to its $K_{gs}$ nearest neighbors via local cross-attention to refine its attributes [S1, unofficial].
5.  **Rendering:** The final set of $B$ Gaussians is rendered into target views using differentiable rasterization [S1, unofficial].

**Pseudocode:**

```python
def rl_splat_forward(images, budget_B, K_gs=16, K_anc=16):
    """
    Forward pass of RLSplat.
    
    Args:
        images: List of V uncalibrated RGB images.
        budget_B: Integer, total number of Gaussians to generate.
        K_gs: Integer, number of Gaussian neighbors for refinement.
        K_anc: Integer, number of anchor neighbors for search.
        
    Returns:
        gaussians: List of B 3D Gaussian objects.
        cameras: List of V camera parameters.
    """
    # Step 1: Geometry Encoding
    # Encodes images into N anchor tokens and predicts camera poses
    anchor_tokens, cameras = geometry_backbone(images)
    N = len(anchor_tokens)
    
    # Step 2: Gaussian Allocation
    # Predicts discrete allocation k such that sum(k) == budget_B
    # Uses policy pi_psi trained with GSPO
    allocation_k = gaussian_allocation_policy(anchor_tokens, budget_B)
    
    # Validate allocation sum
    assert sum(allocation_k) == budget_B
    
    # Step 3: Token Spawning
    # Spawn k_n Gaussian tokens for each anchor n
    gaussian_tokens = []
    for n in range(N):
        k_n = allocation_k[n]
        # Spawn k_n tokens associated with anchor n
        tokens_for_anchor = spawn_tokens(anchor_tokens[n], k_n)
        gaussian_tokens.extend(tokens_for_anchor)
        
    # Step 4: Resource-Linear Decoding
    # Initialize Gaussian attributes from tokens
    gaussians = initialize_gaussians(gaussian_tokens)
    
    # Hierarchical Neighbor Search
    # Find K_gs nearest Gaussian neighbors for each Gaussian
    # Uses K_anc anchor neighbors as a coarse search space
    neighbor_indices = hierarchical_neighbor_search(
        gaussians, 
        anchor_tokens, 
        K_gs=K_gs, 
        K_anc=K_anc
    )
    
    # Local Refinement via Cross-Attention
    # Each Gaussian attends to its K_gs neighbors
    refined_gaussians = local_cross_attention_refinement(
        gaussians, 
        neighbor_indices
    )
    
    return refined_gaussians, cameras

def gaussian_allocation_policy(anchor_tokens, budget_B):
    """
    Predicts discrete allocation vector k.
    Trained with GSPO.
    """
    # Compute allocation probabilities p from anchor features
    p = compute_allocation_probs(anchor_tokens)
    
    # Sample discrete allocation k from Multinomial distribution
    # with budget_B trials and probabilities p
    # Gradients are stopped during sampling for RL
    k = sample_multinomial(budget_B, p)
    
    return k

def hierarchical_neighbor_search(gaussians, anchor_tokens, K_gs, K_anc):
    """
    Efficiently finds K_gs nearest Gaussian neighbors.
    Uses hierarchical search over anchors (K_anc) to find candidate Gaussians.
    """
    # 1. For each Gaussian, find K_anc nearest anchor tokens
    # This reduces the search space from B to K_anc * (avg Gaussians per anchor)
    anchor_neighbors = find_k_nearest_anchors(gaussians, anchor_tokens, K_anc)
    
    # 2. Collect candidate Gaussian tokens from these anchor neighbors
    candidate_gaussians = collect_gaussians_from_anchors(anchor_neighbors)
    
    # 3. Find K_gs nearest neighbors among candidates
    # Exact distance computation in 3D space
    neighbor_indices = find_k_nearest_gaussians(gaussians, candidate_gaussians, K_gs)
    
    return neighbor_indices

def local_cross_attention_refinement(gaussians, neighbor_indices):
    """
    Refines Gaussian attributes using local cross-attention.
    """
    refined_gaussians = []
    for i, g in enumerate(gaussians):
        # Get attributes of neighbor Gaussians
        neighbor_attrs = get_neighbor_attributes(gaussians, neighbor_indices[i])
        
        # Cross-attention: Query from g, Key/Value from neighbors
        refined_attr = cross_attention(query=g.attributes, keys=neighbor_attrs)
        
        # Update Gaussian attributes
        g.attributes = refined_attr
        refined_gaussians.append(g)
        
    return refined_gaussians
```

**Edge Cases and Pitfalls:**
*   **Allocation Sum Constraint:** The allocation policy must strictly satisfy $\sum k_n = B$. Failure to do so breaks the resource-linear guarantee [S1, unofficial].
*   **Projection Loss:** Removing the projection loss causes training to fail entirely, as it ties anchor Gaussians to their image regions [S1, unofficial].
*   **Voronoi Loss:** Removing the Voronoi loss causes a significant PSNR drop (2.51 dB) because Gaussians leave their anchor's cell, and the hierarchical search retrieves incorrect neighbors [S1, unofficial].
*   **Local Refinement:** Removing the local refinement module lowers PSNR by 0.96 dB, as Gaussians cannot be made consistent with neighbors [S1, unofficial].
*   **Precision:** Hierarchical neighbor search is 27× faster than exact search but may introduce approximation errors in neighbor identification [S1, unofficial].

## Subtopics

### Gaussian Allocation Policy
A reinforcement learning-based policy that distributes the Gaussian budget $B$ across anchors based on local scene significance (e.g., texture complexity). It concentrates capacity where fine geometric details require it. Choose this when resource efficiency and adaptive detail allocation are critical. [Link](16746-feed-forward-generalizable-reconstruction.md)

### Resource-Linear Decoder
A decoding module that refines Gaussians via local cross-attention with a hierarchical neighbor search, ensuring $O(B \cdot K_{gs})$ complexity. Choose this when inference latency and memory must scale linearly with the output size. [Link](16746-feed-forward-generalizable-reconstruction.md)

## Operating characteristics
*   **Time Complexity:** Decoding cost is $O(B \cdot K_{gs})$, scaling linearly with the Gaussian budget $B$. This contrasts with global self-attention which costs $O(B^2)$ [S1, unofficial].
*   **Memory Complexity:** Peak memory scales linearly with $B$ [S1, unofficial].
*   **Measured Performance:**
    *   On ACID dataset ($B=8,192$, 8 views): PSNR 22.84 dB, SSIM 0.643, LPIPS 0.353 [S1, unofficial].
    *   On RE10K ($B=8,192$): Full-view PSNR 26.51 dB, compared to 23.42 dB for F4 Splat and 21.82 dB for EcoSplat [S1, unofficial].
    *   At $B=2,048$: Achieves higher PSNR than F4 Splat while using 9.6× less peak memory and running 4.1× faster [S1, unofficial].
*   **Scaling:** Inference latency and peak memory decrease linearly as $B$ is reduced [S1, unofficial].
*   **Strengths:** Resource-linear cost, adaptive allocation to high-frequency structures, high quality at low budgets.
*   **Limitations:** Requires training with GSPO, which may be complex to implement. Hierarchical search introduces approximation errors.
*   **When to Use:** Applications with strict resource budgets (AR/VR, robotics) where both output size and inference cost must be controlled.
*   **When Not to Use:** When maximum possible quality is required regardless of resource cost (use full 3DGS or non-budget-controllable FF3DGS).

## Background
RLSplat was proposed by Bae, Park, and Kim from KAIST in 2026 [S1, unofficial]. It addresses the limitations of prior budget-controllable FF3DGS methods like EcoSplat and F4 Splat, which predict dense sets of Gaussians and prune them, resulting in nearly constant inference latency and memory regardless of the target budget [S1, unofficial]. RLSplat introduces a resource-linear approach by formulating Gaussian generation as an allocation problem and using a resource-linear decoder with hierarchical neighbor search [S1, unofficial].
