# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, GSGEN Implementation Details, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific hyperparameters, optimization schedules, and hardware-aware implementation strategies required to train 3D Gaussian Splatting (3DGS) models effectively. It addresses the problem of balancing reconstruction fidelity with computational efficiency by defining precise thresholds for densification (splitting/cloning) and pruning, as well as numerical stability techniques for half-precision training. It sets itself apart from general optimization theory by providing concrete, reproducible configuration values (e.g., gradient thresholds, opacity cutoffs) and low-level kernel optimizations (e.g., register pressure reduction) that enable real-time rendering and stable convergence.

## How it works
The training process involves initializing Gaussians from Structure-from-Motion (SfM) points and iteratively optimizing their attributes (position, scale, rotation, opacity, and spherical harmonic coefficients) using differentiable rasterization. The implementation relies on specific schedules for modifying the Gaussian set and hardware-specific optimizations for the rasterization kernels.

### Inputs and Outputs
*   **Inputs:** Sparse SfM point cloud (position, covariance), camera poses, training images.
*   **Outputs:** Optimized set of 3D Gaussians $\{G_i\}$, where each $G_i$ is defined by position $\mu_i$, scale $s_i$, rotation $q_i$, opacity $\alpha_i$, and SH coefficients $c_{i,lm}$.

### Data Structures
*   **Gaussian Attributes:** Stored in contiguous arrays for GPU access.
    *   Position: 3 floats ($x, y, z$).
    *   Scale: 3 floats (log-space or linear).
    *   Rotation: 4 floats (quaternion, normalized).
    *   Opacity: 1 float.
    *   SH Coefficients: $3 \times (L+1)^2$ floats, where $L$ is the SH degree.
*   **Scene Extent:** Calculated to bound the initialization and densification logic. Default 3DGS uses camera positions, but corrected implementations use SfM points to avoid bias [S4].

### Numbered Steps

1.  **Initialization:**
    *   Initialize Gaussians at SfM points.
    *   Calculate scene extent $e_{\text{scene}}$. If using corrected extent [S4]:
        $$ \bar{C} = \frac{1}{N_{\text{cam}}} \sum_{i=1}^{N_{\text{cam}}} C_i $$
        $$ e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2 $$
        where $C_i$ are camera positions and $p_i$ are SfM points [S4].
    *   Set initial scale based on the distance to nearest neighbors in the SfM cloud [S4].

2.  **Training Loop (per iteration):**
    *   Randomly select a single image from the training set as supervision [S3].
    *   **Rasterization:** Project 3D Gaussians to 2D. Use half-precision memory fetches for feature vectors during forward and backward passes to reduce register pressure [S2].
    *   **Loss Computation:** Compute photometric loss (e.g., L1 + SSIM) between rendered and ground-truth image. Apply an automatic scaling factor to loss values to improve half-precision training stability [S2].
    *   **Backpropagation:** Compute gradients $\frac{\partial \mathcal{L}}{\partial \theta}$ for all Gaussian parameters.

3.  **Densification (Adaptive Density Control):**
    *   **Splitting:** Every 500 iterations, split Gaussians based on view-space position gradient. If gradient $> T_{\text{pos}}$, split into two [S1].
        *   Threshold $T_{\text{pos}} = 0.02$ [S1].
    *   **Cloning/Compactness:** Every 1000 iterations, perform compactness-based densification [S1].
    *   **Multi-Scale Constraint (Optional):** For large scenes, apply position-aware adaptive control [S7]:
        $$ \gamma(\mu) = \begin{cases} 1 & \text{if } \|\mu - c\|^2 < 2r \\ \|\mu - c\|^2 / r - 1 & \text{if } \|\mu - c\|^2 \ge 2r \end{cases} $$
        *   Clone if $\max(s) < g \cdot \gamma(\mu)$ [S7].
        *   Split if $\max(s) \ge g \cdot \gamma(\mu)$ [S7].
        *   Eliminate if $\max(s) > b \cdot \gamma(\mu)$ [S7].
        *   Parameters: $r$ (scene radius), $c$ (camera center), $g$ (clone threshold), $b$ (elimination threshold) [S7].

4.  **Pruning:**
    *   Every 200 iterations, remove Gaussians with opacity $\alpha < \alpha_{\text{min}}$ or excessively large world-space/view-space radius [S1].
    *   Threshold $\alpha_{\text{min}} = 0.05$ [S1].

5.  **Optimizer Update:**
    *   Use Adam optimizer with learning rate $1 \times 10^{-3}$ [S3].

### Pseudocode

```python
# Configuration
T_pos = 0.02
alpha_min = 0.05
split_interval = 500
clone_interval = 1000
prune_interval = 200
lr = 1e-3

# Initialization
gaussians = initialize_from_sfm(sfm_points)
scene_extent = calculate_corrected_extent(sfm_points, camera_poses) # [S4]

for iteration in range(max_iterations):
    # 1. Sample Image
    image = random_sample(training_images)
    
    # 2. Forward Pass (Rasterization)
    # Use half-precision fetches for features to reduce register pressure [S2]
    rendered_image = rasterize(gaussians, camera_pose, image.resolution)
    
    # 3. Loss Computation
    loss = compute_loss(rendered_image, image)
    loss = scale_loss_for_fp16_stability(loss) # [S2]
    
    # 4. Backward Pass
    gradients = compute_gradients(loss, gaussians)
    
    # 5. Optimizer Step
    optimizer.step(gaussians, gradients, lr)
    
    # 6. Densification and Pruning
    if iteration % split_interval == 0:
        # Split Gaussians with high view-space position gradient [S1]
        split_gaussians(gaussians, gradients, threshold=T_pos)
        
    if iteration % clone_interval == 0:
        # Compactness-based densification [S1]
        clone_gaussians(gaussians)
        
    if iteration % prune_interval == 0:
        # Remove low opacity and oversized Gaussians [S1]
        prune_gaussians(gaussians, alpha_threshold=alpha_min)
```

### Parameters
*   **Optimizer:** Adam [S3].
*   **Learning Rate:** $1 \times 10^{-3}$ [S3].
*   **SH Degree:** 1 (for simplicity/efficiency) [S3].
*   **Split Threshold ($T_{\text{pos}}$):** 0.02 [S1].
*   **Opacity Cutoff ($\alpha_{\text{min}}$):** 0.05 [S1].
*   **DiffGS Parameters:** Truncation function $\lambda$ for Gaussian Probability Function; Projection function $\tau(x) = e^{-x}$ or linear [S10].
*   **Resolution Guided Primitive Scheduler:** Power factor starts at 2, decreases to 1; $\gamma = 0.98$; $\eta = 1$ [S12].

### Edge Cases and Pitfalls
*   **Scene Extent Bias:** Default extent calculation based on camera positions fails if cameras are clustered (e.g., orbiting a small object in a large environment), leading to incorrect splitting/pruning. Use SfM-based extent correction [S4].
*   **Half-Precision Stability:** Loss values must be scaled automatically to prevent overflow/underflow during half-precision training [S2].
*   **Blur Modeling:** Predicting a constant scale offset $\delta s_j$ for all Gaussians degrades to a uniform Gaussian blur, failing to model spatially varying blurriness [S5].
*   **Primitive Growth:** Excessive primitive growth at the end of optimization leads to poor convergence. Mitigated by concave-up scheduling [S12].
*   **Uncertainty Regularity:** Fisher Information uncertainty calculation assumes volume rendering meets regularity conditions (partial derivative exists, integral differentiability, support independence) [S14].

### Minor Variants
#### Corrected Scene-Extent
A method to calculate scene extent based on the SfM point cloud rather than camera positions to avoid bias from camera distribution (e.g., orbiting a small object in a large environment) [S4]. The corrected extent is $e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2$, where $\bar{C}$ is the average camera position and $p_i$ are SfM points [S4]. The default 3DGS extent $e_{\text{scene}} = 1.1 \cdot \max_{i} \|\bar{C} - C_i\|_2$ causes bias if cameras are clustered [S4].

#### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ to selectively enlarge covariances, creating pixel-wise variable blur kernels that match spatially varying scene blurriness [S5]. A compact MLP predicts $\delta s_j$ for each Gaussian, which is added to the base scale before projection [S5]. If $\delta s_j$ is constant, it degrades to uniform blur [S5].

#### Denoise-GS
A self-supervised denoising method for sparse-view 3DGS that combines Noise2Void (N2V) with differentiable 3DGS [S6]. Round 1: Train UNet with N2V, process denoised images through InstantSplat for initialization/training. Round 2: Fine-tune UNet with composite loss (low-frequency + perceptual), render again [S6]. Unlike supervised methods, it requires no paired clean data [S6].

#### Multi-Scale Constraint
Applies different scales to Gaussians based on viewer distance using position-aware point adaptive control [S7]. Uses $\gamma(\mu)$ to scale thresholds for cloning ($\max(s) < g \cdot \gamma(\mu)$), splitting ($\max(s) \ge g \cdot \gamma(\mu)$), and elimination ($\max(s) > b \cdot \gamma(\mu)$) [S7].

#### LS-Gaussian Viewpoint Transformation
Leverages inter-frame continuity by transforming the viewpoint between consecutive frames instead of rendering each frame separately [S8]. Operates at the tile/Gaussian level to enable sparse rendering (e.g., one full render every 6 frames) [S8]. Quality degrades with accumulated interpolation errors [S8].

#### Camera Localisation for Convergence Basin
Localizes camera pose by minimizing photometric error against ground-truth color image, fixing $G_{init}$ during optimization [S9, unofficial]. Initializes $T_{CW}$ at a test view position and optimizes for 1000 iterations [S9, unofficial]. Success if pose converges within 1cm [S9, unofficial].

#### DiffGS Framework
Applies optimization during Gaussian extraction to optimize Gaussians to exact locations [S10]. Uses truncation function $\lambda$ for Gaussian Probability Function and projection function $\tau(x) = e^{-x}$ or linear [S10]. Achieves PSNR 34.01 with 350K Gaussians [S10].

#### Opacity Offset Table for DSA
Constructs an opacity offset table to model changes in digital subtraction angiography [S11].

#### Resolution Guided Primitive Scheduler
Schedules primitive growth using $P_{fin}^{(i)} = \max(P_{fin}^{(i-1)}, \gamma \cdot P_{fin}^{(i-1)} + \eta \cdot P_{add})$ [S12]. Power factor starts at 2, decreases to 1; $\gamma=0.98, \eta=1$ [S12]. Mitigates poor convergence from excessive end-stage growth [S12].

#### Conditional Splat Approximation
Approximates the influence range of a 3D Gaussian on a slice using a 2D ellipse splat scaled by the marginal factor, closely matching true iso-probability contours [S13, unofficial].

#### 3DGS Uncertainty Calculation via Fisher Information
Computes uncertainty $\bar{C}_{V;G} = -\log p_f(\pi|V; G)$ based on negative log-likelihood [S14]. Assumes volume rendering meets regularity conditions (partial derivative exists, integral differentiability, support independence) [S14].

## Operating characteristics
*   **Time Complexity:** Training time is dominated by the iterative densification and rasterization steps. The use of half-precision arithmetic and optimized CUDA kernels (e.g., in `gsplat`) significantly reduces register pressure and memory bandwidth usage, enabling real-time rendering during training [S2].
*   **Memory Complexity:** Memory usage scales with the number of Gaussians. Pruning and compactness-based densification control the upper bound of primitives [S1].
*   **Measured Performance:** With 350K Gaussians, DiffGS achieves PSNR 34.01, SSIM 0.9879, LPIPS 0.0149 [S10]. LS-Gaussian achieves 5.41× speedup over edge GPU baseline on Jetson AGX Orin [S8].
*   **Strengths:** Real-time rendering capability, high fidelity, explicit representation allows for easy manipulation and compression.
*   **Limitations:** Sensitive to initialization and hyperparameters (e.g., scene extent, gradient thresholds). Struggles with transparent objects and thin structures without modifications (e.g., 3D-DoG, Gaussian Frosting).
*   **When to use:** When real-time novel view synthesis is required and high-fidelity reconstruction from multi-view images is needed.
*   **When not to use:** For scenes with extreme transparency or complex participating media without specific extensions (e.g., Inverse and Internal Rendering).

## Background
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 as a real-time explicit radiance field representation [S1, S2, S3]. It builds on the concept of splatting 3D Gaussians to 2D for differentiable rendering. Subsequent work has focused on optimizing the training process, including densification schedules [S1, S12], hardware acceleration [S2, S8], and handling specific challenges like blur [S5], noise [S6], and large-scale scenes [S7]. The implementation details provided here synthesize best practices from various extensions and optimizations to the original method.
