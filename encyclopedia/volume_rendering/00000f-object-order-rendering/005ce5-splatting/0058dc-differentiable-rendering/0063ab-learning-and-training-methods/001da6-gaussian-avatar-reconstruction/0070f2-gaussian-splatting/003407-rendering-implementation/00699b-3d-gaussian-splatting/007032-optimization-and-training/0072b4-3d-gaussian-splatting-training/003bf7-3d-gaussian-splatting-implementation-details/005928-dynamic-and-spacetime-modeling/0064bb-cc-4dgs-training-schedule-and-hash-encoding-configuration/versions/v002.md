# CC-4DGS Training Schedule and Hash Encoding Configuration

Also called: CC-4DGS implementation details, Canonical Deformation Field (CDF) with Compression (CCA) setup

## Overview
CC-4DGS is a training and encoding configuration for dynamic Gaussian splatting that replaces learnable XOR-based hash tables with modulation-based universal hash functions, dense hash encoding, and lightweight neural decoders, combined with a three-stage optimization schedule and dynamic-score gating [S1]. It sets itself apart from siblings like [SpacetimeGaussians](15898-spacetimegaussians-training-pipeline.md) and [Swift4D](16313-spacetime-gaussian-feature-splatting.md) by eliminating large vertex embedding tables to drastically reduce storage, achieving ~30 MB model sizes with minimal quality loss while maintaining real-time rendering speeds [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Multi-view video sequences (e.g., N3DV or Technicolor datasets), initial COLMAP point cloud, time $t$.
*   **Outputs:** Optimized Gaussian parameters (position, rotation, scale, opacity, color), deformation field parameters, dynamic scores $d$, and compressed feature representations.

**Data Structures:**
1.  **Multi-resolution Hash Grids:** A set of $L$ grids (typically $L=4$ or $5$). Unlike standard 3DGS which uses XOR-based hash tables storing learnable embeddings, CC-4DGS stores no such learnable hash tables [S1].
2.  **Hash Function Parameters:**
    *   Bucket size $m$: An integer parameter determining the hash table width. Must be sufficiently large to limit collisions [S1].
    *   Prime $P$: An integer parameter used alongside $m$ in the hash function [S1].
3.  **Lightweight Neural Decoders:** One decoder per grid level. These map hash-encoded integers to continuous feature vectors [S1].
4.  **Per-Gaussian Dynamic Score:** A scalar value $d$ learned for each Gaussian to indicate its motion activity [S1].
5.  **Threshold $\zeta$:** A scalar threshold for $d$. Deformation is applied only if $d > \zeta$ [S1].

**Algorithm Steps:**
The training follows a strict three-stage schedule [S1]:

1.  **Stage 1: Coarse Initialization (5K iterations)**
    *   Establish the initial canonical point cloud using COLMAP.
    *   Optimize base Gaussian parameters (position, rotation, scale, opacity, color) without deformation.
    *   This stage stabilizes the static geometry [S1].

2.  **Stage 2: Dynamic Score Fitting (3K iterations)**
    *   Optimize the per-Gaussian dynamic score $d$ for each Gaussian.
    *   The deformation field is not yet fully optimized; the focus is on identifying which Gaussians are dynamic [S1].

3.  **Stage 3: Main Optimization (20K iterations)**
    *   Jointly optimize the deformation field and the full Gaussian set (positions, rotations, scales, etc.).
    *   Total iterations per scene: 28K (5K + 3K + 20K) [S1].
    *   **Dynamic Score Gating:** During rendering and optimization, deformation is applied only to Gaussians where the learned dynamic score $d$ exceeds the threshold $\zeta$. If $d \le \zeta$, the Gaussian is treated as static, avoiding unnecessary deformation computation [S1].

**Hash Encoding and Feature Retrieval:**
Instead of storing learnable embeddings in XOR-based hash tables, CC-4DGS uses modulation-based universal hash functions with dense hash encoding [S1].
1.  For a given spatial coordinate $\mathbf{x}$ and time $t$, compute the hash index for each grid level $l$:
    $$ h_l = (\text{hash}(\mathbf{x}, t) + \text{offset}_l) \mod m $$
    Where $\text{hash}$ is a universal hash function, $m$ is the bucket size, and $\text{offset}_l$ is a level-specific offset [S1].
2.  The hash index $h_l$ is passed to the lightweight neural decoder for level $l$.
3.  The decoder outputs a continuous feature vector $\mathbf{f}_l$ [S1].
4.  Features from all $L$ levels are aggregated (e.g., summed or concatenated) to form the final feature representation for the deformation field or color [S1].

**Parameters:**
*   **Bucket size $m$:** Must be sufficiently large. Preliminary tests showed that smaller $m$ values noticeably degrade PSNR [S1]. Exact value not specified in sources, but "sufficiently large" is required [S1].
*   **Prime $P$:** Used in the hash function to limit collisions [S1]. Exact value not specified [S1].
*   **Number of grids:** Restricted to 4 or 5 due to GPU memory constraints [S1].
*   **Threshold $\zeta$:** Scalar threshold for dynamic score $d$. Value not specified in sources [S1].

**Pseudocode:**
```python
# CC-4DGS Training and Rendering Configuration

# Hyperparameters
NUM_GRIDS = 5  # Restricted to 4 or 5 due to GPU memory [S1]
BUCKET_SIZE = m  # Must be sufficiently large to limit collisions [S1]
PRIME_P = P  # Used in hash function [S1]
THRESHOLD_ZETA = zeta  # Dynamic score threshold [S1]
STAGE1_ITERS = 5000  # Coarse initialization [S1]
STAGE2_ITERS = 3000  # Dynamic score fitting [S1]
STAGE3_ITERS = 20000  # Main optimization [S1]

# Data Structures
# hash_grids: List of NUM_GRIDS lightweight neural decoders
# gaussians: List of Gaussian objects with attributes:
#   - pos: (x, y, z)
#   - rot: quaternion
#   - scale: (sx, sy, sz)
#   - opacity: scalar
#   - color: features
#   - dynamic_score: scalar d
# deformation_field: Neural network taking (pos, time, features) -> offset

def hash_function(x, t, level_idx, m, P):
    """
    Modulation-based universal hash function.
    Returns an integer hash index.
    """
    # Implementation detail: Uses dense hash encoding with prime P and bucket size m [S1]
    # Exact hash formula not provided in sources, but uses universal hash properties [S1]
    # Placeholder for specific universal hash implementation
    hash_val = (hash(x, t) + level_idx) % m
    return hash_val

def get_feature(hash_index, decoder):
    """
    Maps hash-encoded integer to continuous feature via lightweight neural decoder [S1].
    """
    return decoder(hash_index)

def train_stage1(gaussians, images, time_frames):
    """
    Stage 1: Coarse initialization (5K iterations) [S1].
    Establish initial canonical point cloud and base Gaussian parameters.
    """
    for i in range(STAGE1_ITERS):
        # Optimize base Gaussian parameters (pos, rot, scale, opacity, color)
        # No deformation applied yet
        loss = compute_rendering_loss(gaussians, images, time_frames)
        optimize(gaussians, loss)

def train_stage2(gaussians, images, time_frames):
    """
    Stage 2: Dynamic score fitting (3K iterations) [S1].
    Fit the per-Gaussian dynamic score d.
    """
    for i in range(STAGE2_ITERS):
        # Optimize dynamic_score d for each Gaussian
        # Deformation field parameters are fixed or lightly updated
        loss = compute_rendering_loss(gaussians, images, time_frames)
        optimize(gaussians.dynamic_score, loss)

def train_stage3(gaussians, images, time_frames):
    """
    Stage 3: Main optimization (20K iterations) [S1].
    Jointly optimize deformation field and Gaussian set.
    """
    for i in range(STAGE3_ITERS):
        for gaussian in gaussians:
            # Dynamic score gating: only apply deformation if d > zeta [S1]
            if gaussian.dynamic_score > THRESHOLD_ZETA:
                # Get features from hash grids
                features = []
                for l in range(NUM_GRIDS):
                    h = hash_function(gaussian.pos, time, l, BUCKET_SIZE, PRIME_P)
                    f = get_feature(h, hash_grids[l])
                    features.append(f)
                # Aggregate features (e.g., sum)
                aggregated_feature = sum(features)
                # Compute deformation offset
                offset = deformation_field(gaussian.pos, time, aggregated_feature)
                # Apply offset to Gaussian parameters
                gaussian.pos += offset.dx
                gaussian.rot += offset.dr
                gaussian.scale += offset.ds
            else:
                # Static Gaussian: no deformation
                pass
        
        loss = compute_rendering_loss(gaussians, images, time_frames)
        optimize(gaussians, deformation_field, loss)

def render(gaussians, camera, time):
    """
    Render using differentiable rasterization [S1].
    Apply dynamic score gating during rendering as well.
    """
    projected_gaussians = []
    for gaussian in gaussians:
        if gaussian.dynamic_score > THRESHOLD_ZETA:
            # Apply deformation
            features = []
            for l in range(NUM_GRIDS):
                h = hash_function(gaussian.pos, time, l, BUCKET_SIZE, PRIME_P)
                f = get_feature(h, hash_grids[l])
                features.append(f)
            aggregated_feature = sum(features)
            offset = deformation_field(gaussian.pos, time, aggregated_feature)
            # Update Gaussian for rendering
            render_pos = gaussian.pos + offset.dx
            render_rot = gaussian.rot + offset.dr
            render_scale = gaussian.scale + offset.ds
        else:
            render_pos = gaussian.pos
            render_rot = gaussian.rot
            render_scale = gaussian.scale
        
        # Project to 2D using covariance transformation [S1]
        projected = project_gaussian(render_pos, render_rot, render_scale, camera)
        projected_gaussians.append(projected)
    
    # Alpha blending [S1]
    image = alpha_blend(projected_gaussians)
    return image
```

## Operating characteristics
*   **Storage:** Significantly reduced compared to hash-table-based methods. The CDF component alone reduces model size to a few tens of megabytes. Combined with CCA, total storage is ~30 MB (N3DV) or ~32 MB (Technicolor) [S1]. This is smaller than the lightweight baseline 4DGS [S1].
*   **Rendering Speed:** Maintains real-time performance. On Technicolor dataset, achieves 64.7 FPS (CDF) and 64.6 FPS (CDF+CCA) on a single NVIDIA RTX 4090 [S1]. Slightly slower than Swift4D's 64.7 FPS due to decoder computation, but comparable [S1].
*   **Reconstruction Quality:**
    *   N3DV: PSNR in the low 32 dB range, SSIM ~0.94 [S1].
    *   Technicolor: PSNR 33.29 dB (CDF), 33.30 dB (CDF+CCA); SSIM 0.912 [S1].
*   **Complexity:** The use of lightweight neural decoders adds computational overhead compared to direct table lookups, but the dynamic-score gating reduces the number of Gaussians requiring deformation computation [S1].
*   **Limitations:** The bucket size $m$ and prime $P$ must be carefully chosen; smaller $m$ noticeably degrades PSNR [S1]. The number of grids is limited to 4-5 due to GPU memory constraints [S1].

## Background
CC-4DGS was introduced in the paper "CC-4DGS: Computational Deformation and Point-Cloud Compression for Storage-Efficient Dynamic Gaussian Splatting" [S1]. It addresses the high storage costs of dynamic Gaussian splatting methods that rely on large learnable hash tables (e.g., Swift4D) [S1]. The method builds on the 3D Gaussian Splatting representation [S1] and incorporates ideas from Swift4D, such as the dynamic-score strategy [S1]. It was evaluated on the N3DV and Technicolor Light Field datasets [S1].
