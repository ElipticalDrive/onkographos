# Parameter Initialization

Also called: Emission, Roughness, and Specular Initialization, Median Texture Initialization for Diffuse Color

## Overview
This method initializes the physical material parameters and lighting environment for inverse rendering pipelines that use differentiable rendering to optimize for geometry, albedo, and illumination [S1, S2]. It addresses the problem of gradient-based optimizers diverging or getting stuck in poor local minima due to ill-conditioned initial states, such as extreme exposure mismatches or view-dependent artifacts contaminating diffuse color estimates [S1, S2]. It sets apart from sibling methods by explicitly decoupling view-independent diffuse properties from view-dependent specular effects using median filtering and by enforcing a neutral baseline for emission and roughness to stabilize the BRDF optimization [S1, S2].

## How it works
The method initializes four distinct components: the geometric shape (via SDF), the diffuse albedo, the specular BRDF parameters, and the environment lighting. It also includes a preprocessing step for input image normalization.

**Inputs:**
*   A set of $N$ reference images $\{I_1, \dots, I_N\}$ capturing the object from various viewpoints.
*   A 3D bounding box enclosing the object.
*   A mesh or point cloud representing the initial geometry (optional, depending on the specific pipeline variant).

**Outputs:**
*   Initialized SDF weights $\Theta$.
*   Initialized diffuse albedo function $a(x; \Phi)$.
*   Initialized specular BRDF parameters: lobe sharpness $\lambda$ and specular albedo $\mu$.
*   Initialized environment map lobes.
*   Scaled input images.

**Data Structures:**
*   **SDF Network:** A multi-layer perceptron (MLP) mapping 3D coordinates to signed distance values. Weights $\Theta$ are initialized using the method from [12] to ensure the initial zero-level set forms a rough sphere [S1].
*   **Albedo Network:** An MLP mapping 3D coordinates to diffuse albedo values.
*   **Environment Map:** Represented as a set of lobes distributed on the unit sphere.

**Steps:**

1.  **Input Image Normalization:**
    To handle varying exposure across captures, scale all input images by a constant factor such that the median intensity of all scaled images is $0.5$ [S1]. This ensures consistent lighting assumptions during training [S1].

2.  **Diffuse Albedo Initialization:**
    Initialize the diffuse albedo network $a(x; \Phi)$ such that the predicted albedo is approximately $0.5$ for all locations inside the object's bounding box [S1].
    *   *Alternative/Refined Approach for Spatially-Varying Color:* If spatially varying diffuse color is required, build a median texture [S2].
        1.  Iterate over all available reference pictures.
        2.  Project each view into texture space.
        3.  Use an online median estimator to accumulate color values per texel [S2]. This avoids memory issues with tens of thousands of views and suppresses view-dependent effects like specular reflections, which would bias a mean estimator [S2].

3.  **Specular BRDF Initialization:**
    Initialize the specular lobe sharpness $\lambda$ by drawing randomly from the interval $[95, 125]$ [S1]. Initialize the specular albedo $\mu$ by drawing randomly from the interval $[0.18, 0.26]$ [S1]. These values provide a neutral starting point for the specular component [S2].

4.  **Environment Map Initialization:**
    Initialize the environment map lobes to distribute uniformly on the unit sphere using a spherical Fibonacci lattice [S1, S2]. Assign monochrome colors to these lobes [S1]. Scale the amplitude of the randomly initialized lobes such that the initial rendered pixel intensity output by the rendering pipeline is approximately $0.5$ [S1].

5.  **Other Material Parameters:**
    Initialize emission to $0$, roughness to $0.5$, and specular to $0.5$ [S2]. These neutral constant values guide optimization toward a good minimum [S2].

**Formulas and Parameters:**
*   **Median Intensity Scaling:** Let $M$ be the median intensity of all pixels across all input images. Scale each image $I_i$ by $k = 0.5 / M$.
*   **Albedo Target:** $a(x; \Phi) \approx 0.5$ for $x \in \text{Bounding Box}$ [S1].
*   **Environment Map Amplitude:** Scale lobes $L_j$ such that $\text{Render}(L) \approx 0.5$ [S1].
*   **Specular Sharpness:** $\lambda \sim \text{Uniform}(95, 125)$ [S1].
*   **Specular Albedo:** $\mu \sim \text{Uniform}(0.18, 0.26)$ [S1].

**Edge Cases and Pitfalls:**
*   **Environment Map Brightness:** If the initial environment map is too bright or too dark, the diffuse albedo MLP may get stuck, predicting all zeros or ones during training [S1]. The amplitude scaling step (Step 4) is critical to prevent this [S1].
*   **View-Dependent Artifacts:** Using a mean filter for diffuse color initialization can incorporate specular highlights, leading to incorrect diffuse estimates [S2]. The median estimator is preferred to suppress these effects [S2].

def initialize_parameters(images, bounding_box, num_lobs):
    """
    Initializes parameters for inverse rendering.
    
    Args:
        images: List of numpy arrays representing reference images.

    median_intensity = np.median(all_pixels)
    
    # Scale images so median intensity is 0.5
    scale_factor = 0.5 / median_intensity
    scaled_images = [img * scale_factor for img in images]
    
    # Step 2: Initialize Diffuse Albedo
    # Option A: Constant albedo ~0.5
    # Option B: Spatially varying via median texture
    # Here we assume Option B for spatially varying color
    # Note: In practice, this requires texture space projection logic
    # which is omitted for brevity as it depends on specific UV mapping.
    # The key is using an online median estimator.
    diffuse_albedo_init = 0.5 # Placeholder for constant case
    
    # Step 3: Initialize Specular BRDF
    lambda_sharpness = np.random.uniform(95, 125)
    mu_specular_albedo = np.random.uniform(0.18, 0.26)
    
    # Step 4: Initialize Environment Map
    # Generate uniform distribution on unit sphere using spherical Fibonacci lattice
    # Formula for spherical Fibonacci lattice points:
    # theta = arccos(1 - 2*(i + 0.5)/N)
    # phi = pi * (1 + sqrt(5)) * (i + 0.5)
    indices = np.arange(num_lobs)
    theta = np.arccos(1 - 2 * (indices + 0.5) / num_lobs)
    phi = np.pi * (1 + np.sqrt(5)) * (indices + 0.5)
    
    # Convert to Cartesian coordinates for lobe centers
    x = np.sin(theta) * np.cos(phi)
    y = np.sin(theta) * np.sin(phi)
    z = np.cos(theta)
    lobe_centers = np.stack([x, y, z], axis=-1)
    
    # Initialize monochrome colors (e.g., white)
    lobe_colors = np.ones((num_lobs, 3))
    
    # Scale amplitudes so initial render intensity is ~0.5
    # This requires a forward pass through the renderer to estimate intensity
    # and then scaling the lobes.
    # Placeholder for the scaling factor calculation
    initial_render_intensity = estimate_render_intensity(lobe_centers, lobe_colors)
    amplitude_scale = 0.5 / initial_render_intensity
    lobe_colors *= amplitude_scale
    
    # Step 5: Initialize other parameters
    emission = 0.0
    roughness = 0.5
    specular = 0.5
    
    # SDF weights initialization (method from [12] to form a rough sphere)
    # This is implementation-specific to the SDF network architecture
    sdf_weights = initialize_sdf_weights_rough_sphere()
    
    return {
        'scaled_images': scaled_images,
        'diffuse_albedo_init': diffuse_albedo_init,
        'lambda': lambda_sharpness,
        'mu': mu_specular_albedo,

        'lobe_colors': lobe_colors,

## Operating characteristics
*   **Time Complexity:** The median texture construction is $O(N \cdot V)$ where $N$ is the number of views and $V$ is the number of texels, but the online estimator allows for $O(1)$ memory per texel update [S2]. The environment map initialization is $O(L)$ where $L$ is the number of lobes [S1].
*   **Memory Complexity:** The online median estimator avoids storing all projected views, keeping memory usage low even for tens of thousands of views [S2].
*   **Strengths:** Prevents optimization from getting stuck in degenerate solutions (all-zero or all-one albedo) [S1]. Suppresses view-dependent artifacts in diffuse color estimation [S2].
*   **Limitations:** Relies on the assumption that the median intensity of input images is a good proxy for neutral lighting [S1]. The spherical Fibonacci lattice is an approximation of uniform distribution [S1].
*   **When to use:** When training inverse rendering models with Spherical Gaussians or similar BRDF representations where environment map and material parameters are optimized jointly [S1, S2].
*   **When not to use:** If the input images have extreme exposure variations that cannot be normalized by a single global scale factor [S1].
