# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific implementation parameters, optimization schedules, and algorithmic variants required to train and render 3D Gaussian Splatting (3DGS) scenes effectively. It addresses the core training loop, hardware-aware rasterization configurations, and specific methodological adjustments for scene extent, densification, and noise handling. It sets itself apart from generic optimization articles by providing concrete hyperparameters, data structure layouts, and step-by-step procedures for specific variants like selective defocus blurring and internal rendering.

## How it works

### Inputs and Outputs
**Inputs:**
*   A set of $N_{cam}$ input images with known camera poses $C_i$ and intrinsics.
*   An initial sparse point cloud from Structure-from-Motion (SfM) with $N_{SfM}$ points.
*   Training hyperparameters: learning rate, iteration budget, loss weights, and densification thresholds.

**Outputs:**
*   A set of $N$ 3D Gaussians, each parameterized by:
    *   Position $\mu \in \mathbb{R}^3$.
    *   Covariance $\Sigma \in \mathbb{R}^{3 \times 3}$ (often stored as rotation quaternion $q \in \mathbb{R}^4$ and scale $s \in \mathbb{R}^3$).
    *   Opacity $\alpha \in [0, 1]$.
    *   Spherical Harmonics (SH) coefficients for view-dependent color.
*   Rendered images for novel viewpoints.

### Data Structures
The Gaussian scene is typically stored in a flat array or a structure-of-arrays (SoA) layout for efficient GPU access.
*   **Position:** `float3` (32-bit float, 12 bytes).
*   **Rotation:** `float4` (quaternion, 16 bytes).
*   **Scale:** `float3` (32-bit float, 12 bytes).
*   **Opacity:** `float` (32-bit float, 4 bytes).
*   **SH Coefficients:** Variable size depending on degree $D$. For degree 1, 9 coefficients per RGB channel, stored as `float` arrays.
*   **Indices/Sorting:** An integer array mapping Gaussian IDs to their sorted order for rasterization.

### Training Loop
The training process follows a stochastic gradient descent loop [S10, unofficial].

1.  **Random View Selection:** Randomly select one input image from the training set [S2][S10, unofficial].
2.  **Rendering:** Render the current set of Gaussians from the known camera pose of the selected image using a differentiable rasterizer (e.g., `gsplat`) [S2][S10, unofficial].
    *   Gaussians are sorted front-to-back based on depth along the view ray.
    *   Alpha blending is performed per pixel: $C = \sum_{i \in \text{sorted}} c_i \alpha_i \prod_{j < i} (1 - \alpha_j)$.
3.  **Loss Computation:** Compare the rendered image against the ground-truth photo pixel-by-pixel [S10, unofficial].
    *   The total loss $\mathcal{L}$ is a weighted sum of L1 loss and D-SSIM:
        $$ \mathcal{L} = (1 - \lambda) \mathcal{L}_1 + \lambda \mathcal{L}_{SSIM} $$
    *   Typical value for $\lambda$ is 0.2 [S10, unofficial][S12].
4.  **Backpropagation:** Compute gradients of $\mathcal{L}$ with respect to all Gaussian parameters (position, rotation, scale, opacity, SH coefficients) [S10, unofficial].
5.  **Optimization Step:** Update parameters using the Adam optimizer with a learning rate of $1 \times 10^{-3}$ [S2].
6.  **Densification/Pruning (Periodic):** Every $k$ iterations (e.g., 100), perform densification (splitting/cloning) and pruning based on gradient magnitudes and opacity thresholds [S3, S13].
7.  **Repeat:** Repeat for a fixed iteration budget, typically 30,000 iterations [S10, unofficial].

### Implementation Specifics

#### Half-Precision Rasterization
To reduce register pressure and memory bandwidth, the rasterization kernels (forward and backward) use half-precision (FP16) memory fetches for feature vectors [S1].
*   **Stability:** An automatic scaling factor is applied to loss values to improve training stability in half-precision [S1].
*   **MLP Evaluation:** If using auxiliary networks (e.g., for defocus blur), they are trained and evaluated in FP16 using JIT-compiled cooperative vector MLPs (e.g., via `tiny-cuda-nn`) [S1].

#### Scene Extent Calculation
The default 3DGS scene extent $e_{\text{scene}}$ is proportional to the distance of the furthest camera from the average camera position:
$$ e_{\text{scene}} = 1.1 \cdot \max_{i=1}^{N_{\text{cam}}} \|\bar{C} - C_i\|_2 $$
$$ \bar{C} = \frac{1}{N_{\text{cam}}} \sum_{i=1}^{N_{\text{cam}}} C_i $$
This can cause bias if cameras are clustered (e.g., orbiting a small object) [S3]. A corrected scene extent $e'_{\text{scene}}$ based on the SfM point cloud is recommended:
$$ e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2 $$
where $p_i$ are the SfM points [S3].

#### Densification Criteria
Standard densification uses the accumulated positional gradient. Additional criteria include:
*   **Normal Gradient:** Densify Gaussians whose normal gradient exceeds a threshold $T_n$ (typical value $2 \times 10^{-9}$) to improve normal recovery in thin regions [S13].
*   **Multi-Scale Constraint:** For large scenes, apply position-aware adaptive control. Let $\gamma(\mu)$ be a scale factor based on distance from camera center $c$ and scene radius $r$:
    $$ \gamma(\mu) = \begin{cases} 1 & \text{if } \|\mu - c\|^2 < 2r \\ \|\mu - c\|^2 / r - 1 & \text{if } \|\mu - c\|^2 \ge 2r \end{cases} $$
    *   Clone if $\max(s) < g \cdot \gamma(\mu)$.
    *   Split if $\max(s) \ge g \cdot \gamma(\mu)$.
    *   Eliminate if $\max(s) > b \cdot \gamma(\mu)$, where $g$ and $b$ are scale threshold parameters [S7].

### Edge Cases and Pitfalls
*   **Scene Extent Bias:** Using camera-based extent for clustered cameras leads to incorrect splitting/pruning [S3].
*   **Defocus Blurring:** Predicting a constant scale offset $\delta s_j$ for all Gaussians degrades to a uniform Gaussian blur, failing to model spatially varying blurriness [S4].
*   **Interpolation Error:** In sparse rendering via viewpoint transformation, rendering quality degrades as the number of consecutively transformed frames increases due to accumulated interpolation errors [S8].
*   **Half-Precision Instability:** Training in FP16 requires loss scaling to prevent gradient underflow/overflow [S1].

### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ to selectively enlarge covariances, creating pixel-wise variable blur kernels that match spatially varying scene blurriness. It sets itself apart from naive Gaussian blur (uniform) or learnable single-kernel blur (average) by allowing spatially varying blur shapes and magnitudes. Use this for scenes with depth-dependent defocus. Link: [Selective Defocus Blurring](12180-selective-defocus-blurring.md).

### Denoise-GS
A self-supervised denoising method for sparse-view 3DGS that combines unsupervised image denoising (Noise2Void) with differentiable 3DGS. It sets itself apart from supervised methods by requiring no paired clean data, making it robust to non-Gaussian and time-varying noise in sparse viewpoints. Use this when training data is noisy and sparse. Link: [Denoise-GS](12180-denoise-gs.md).

### Model-based depth estimation for volume parameter update
Uses depth values extracted from the current scene estimate to update medium-parameter estimates (attenuation and backscatter) in volumetric rendering [S6]. The depth $z$ is computed as a weighted average of Gaussian depths: $z = \frac{\sum_{i=1}^M d_i \alpha_i T_i}{\sum_{i=1}^M \alpha_i T_i}$. Use this for underwater or volumetric scenes. ### Multi-Scale Constraint

### LS-Gaussian Viewpoint Transformation
Leverages inter-frame continuity to transform viewpoints between consecutive frames, enabling sparse rendering where only one frame in every 6 is fully rendered [S8]. It sets itself apart from naive pixel warping by operating at the tile/Gaussian level to reduce preprocessing and sorting costs. ## Operating characteristics

### Time and Memory Complexity
*   **Training Time:** Typically runs for 30,000 iterations [S10, unofficial]. Each iteration involves rendering and backpropagation, which is $O(N \cdot P)$ where $N$ is the number of Gaussians and $P$ is the number of pixels, but optimized via tile-based rasterization.
*   **Memory:** Scales linearly with the number of Gaussians. Each Gaussian stores position, rotation, scale, opacity, and SH coefficients. For large scenes, this can exceed 1 GB [S1].
*   **Rasterization:** The `gsplat` library uses half-precision fetches to reduce register pressure [S1].

### Measured Performance
*   **Hardware:** Tested on NVIDIA GPUs and edge platforms like Jetson AGX Orin [S8].
*   **Speedup:** LS-Gaussian achieves up to 17.3× speedup with a custom accelerator on Jetson AGX Orin [S8].
*   **Quality:** GS-IR improves PSNR by up to 21.52 dB and SSIM by up to 0.54 on medical datasets [S9].

### Strengths and Limitations
*   **Strengths:** Real-time rendering, high-quality novel view synthesis, differentiable optimization.
*   **Limitations:** High memory usage for large scenes, sensitivity to camera distribution for scene extent, degradation in sparse view scenarios without denoising [S5].

### When to Use
*   Use standard 3DGS for general novel view synthesis with dense input views.
*   Use variants like Denoise-GS for sparse/noisy views.
*   Use GS-IR for internal volume reconstruction.
*   Use LS-Gaussian for real-time video sequences on edge devices.

## Background

3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1][S10, unofficial]. It represents scenes as a set of 3D Gaussians optimized via differentiable rasterization. The method has since been extended to handle various scenarios including defocus blur [S4], sparse views [S5], large-scale scenes [S7], and internal volumes [S9]. The implementation details provided here are based on the `gsplat` library and various research extensions.
