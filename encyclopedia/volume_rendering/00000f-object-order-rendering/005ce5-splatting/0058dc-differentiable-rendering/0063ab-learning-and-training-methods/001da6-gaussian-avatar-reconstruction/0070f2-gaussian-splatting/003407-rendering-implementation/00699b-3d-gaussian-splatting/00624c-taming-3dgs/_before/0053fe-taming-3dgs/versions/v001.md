# Taming 3DGS

Also called: Budget-constrained 3DGS, Explicit Gaussian Cap

## Overview
Taming 3DGS is a resource-efficiency method for 3D Gaussian Splatting that imposes an explicit cap on the total number of Gaussians to enable high-quality rendering on consumer-grade GPUs [S1, S2, unofficial]. It steers the densification process to spend a fixed budget where it helps most, trading peak quality for faster training and smaller model size [S2, unofficial]. Unlike standard 3DGS which allows unbounded growth, this approach formulates optimization as a mixed-integer problem to maintain a constant Gaussian count [S1, unofficial].

## How it works
**Inputs:** A set of 3D Gaussians $\{G_i\}$ with attributes (position, covariance, opacity, SH coefficients), a target maximum count $N_{max}$, and a training schedule or importance metric.
**Outputs:** A pruned and densified set of Gaussians $\{G'_i\}$ where $|\{G'_i\}| \le N_{max}$.

**Data Structures:**
*   **Gaussian List:** Array of size $N_{max}$. Each element contains position $\mathbf{p}$, rotation $\mathbf{q}$, scale $\mathbf{s}$, opacity $\alpha$, and SH coefficients.
*   **Importance Score:** A scalar value per Gaussian, derived from gradient magnitude or contribution to loss.

**Steps:**
1.  **Initialize:** Start with the standard 3DGS initialization. Set current count $N = N_{init}$.
2.  **Iterative Optimization Loop:**
    a. Perform standard differentiable rasterization and backpropagation to compute gradients.
    b. **Prune:** Identify the least important Gaussians based on opacity and/or gradient contribution. Remove them if $N > N_{max}$ or if they fall below a threshold [S1, unofficial].
    c. **Densify:** Identify the most important Gaussians (high gradient/importance). Split or clone these to increase local density [S1, unofficial].
    d. **Budget Enforcement:** If $N > N_{max}$, prune again. If $N < N_{max}$, densify more. The goal is to keep $N$ close to $N_{max}$ [S1, unofficial].
3.  **Schedule/Policy:** Use either a predictable schedule (fixed pruning/densification intervals) or adaptive importance guidance to decide when to apply steps 2b and 2c [S1, unofficial].

**Pseudocode:**
```python
def taming_3dgs_step(gaussians, N_max, importance_scores):
    # Prune least important if over budget
    if len(gaussians) > N_max:
        sorted_indices = argsort(importance_scores)
        prune_count = len(gaussians) - N_max
        for i in range(prune_count):
            gaussians.pop(sorted_indices[i])
        importance_scores = importance_scores[sorted_indices[prune_count:]]
    
    # Densify most important if under budget or to improve quality
    # Note: Exact splitting logic is inherited from standard 3DGS
    # [G] Standard 3DGS splits Gaussians with high gradient magnitude
    # and clones those with low opacity but high gradient.
    # Here, we prioritize splitting those with highest importance scores.
    if len(gaussians) < N_max:
        top_indices = argsort(importance_scores, reverse=True)[:N_max - len(gaussians)]
        for idx in top_indices:
            split_gaussian(gaussians[idx])
            update_importance_scores(gaussians)
            
    return gaussians
```

**Edge Cases:**
*   **Precision:** Ensure importance scores are stable across iterations to avoid oscillation between pruning and densifying [S1, unofficial].
*   **Boundaries:** $N_{max}$ must be chosen carefully; too low causes quality loss, too high defeats the purpose [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Training time is reduced due to fewer Gaussians to rasterize and backpropagate through [S2, unofficial].
*   **Memory Complexity:** Memory usage is bounded by $O(N_{max})$, significantly lower than unconstrained 3DGS [S2, unofficial].
*   **Performance:** Enables high-quality rendering on consumer-grade GPUs [S1, unofficial].
*   **Strengths:** Faster training, smaller model size, predictable resource usage [S2, unofficial].
*   **Limitations:** Slight quality loss compared to unconstrained 3DGS [S1, S2, unofficial].
*   **When to use:** When hardware resources are limited or training time is a constraint [S2, unofficial].
*   **When not to use:** When peak visual fidelity is required regardless of cost [S2, unofficial].

## Background
Taming 3DGS was introduced to address the resource intensity of standard 3D Gaussian Splatting [S1, unofficial]. It explores a spectrum of trade-offs from predictable schedules to adaptive importance guidance [S1, unofficial]. The method is part of a broader trend of optimizing 3DGS for efficiency, alongside works like LightGaussian and RTGS [S1, unofficial].
