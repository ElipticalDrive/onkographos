# CoherentRaster

Also called: Coherent Rasterization for Light Field Displays, Cross-view Coherent Attribute Reuse, View-coherent Remapping

## Overview
CoherentRaster is a real-time 3D Gaussian Splatting (3DGS) rendering framework optimized for Light Field Displays (LFDs) [S1]. It solves the computational bottleneck of dense multi-view synthesis by leveraging subpixel-level rasterization to eliminate redundant computations across adjacent viewpoints and resolve uncoalesced memory access patterns inherent to subpixel rendering [S1]. Unlike Subpixel-3DGS, which suffers from redundant cross-view computation and irregular memory access, or MPI-based frameworks, which scale poorly with resolution due to depth plane traversal, CoherentRaster achieves real-time performance on high-resolution scenes by exploiting view coherence [S1].

## How it works
CoherentRaster operates on a set of $N$ 3D Gaussians $\{G_i\}_{i=1}^N$ . The method consists of two primary optimization strategies: Cross-view Coherent Attribute Reuse and View-coherent Remapping.

### Inputs and Outputs
*   **Inputs:**
    *   Set of $N$ 3D Gaussians $\{G_i\}$, each defined by mean $\mu_i$, covariance $\Sigma_i$, opacity $\alpha_i$, and spherical harmonics coefficients for color .
    *   A cluster of $|V|$ viewpoints $\mathcal{V} = \{V_1, V_2, \dots, V_{|V|}\}$ representing adjacent views in the light field [S1].
    *   Target resolution for each view (e.g., 2K or 4K) [S1].
*   **Outputs:**
    *   A set of rendered images, one for each viewpoint in $\mathcal{V}$, with high-fidelity color and alpha values [S1].

### Data Structures
*   **Gaussian Attributes:** Standard 3DGS attributes stored in global memory .
*   **View Cluster:** A batch of $|V|$ camera matrices and projection parameters [S1].
*   **Tile Grid:** The image plane is divided into non-overlapping tiles (typically $16 \times 16$ pixels) to localize processing .

### Steps
1.  **Cluster Formation:** Group adjacent viewpoints into clusters of size $|V|$. The optimal cluster size is determined to be $|V|=8$ to balance efficiency and quality [S1].
2.  **Cross-view Coherent Attribute Reuse:**
    *   For each Gaussian $G_i$, compute its 2D projection parameters (mean $\mu_{2D}$, covariance $\Sigma_{2D}$) for the first viewpoint $V_1$ in the cluster [S1].
    *   Exploit the local consistency between adjacent views. Instead of fully recomputing projection attributes for all $|V|$ views, reuse attributes from $V_1$ and apply small corrections or direct reuse for neighboring views $V_j$ ($j > 1$) within the cluster [S1]. This eliminates redundant computation for Gaussians that project similarly across adjacent views [S1].
3.  **View-coherent Remapping:**
    *   Subpixel-level rasterization generates non-contiguous memory accesses when mapping screen pixels to Gaussian contributions [S1].
    *   Apply a remapping strategy to reorder or pack the Gaussian contributions and pixel indices such that memory accesses become coalesced across the threads processing the view cluster [S1]. This resolves the uncoalesced memory access issue inherent to subpixel rasterization [S1].
4.  **Rasterization and Blending:**
    *   For each tile in each view of the cluster:
        *   Identify contributing Gaussians using culling (frustum and tile overlap) .
        *   Sort contributing Gaussians by view-space depth (front-to-back) .
        *   Perform alpha blending to compute final color and opacity for each pixel .
    *   Use the remapped data structures to ensure coalesced global memory writes [S1].
5.  **Output Assembly:** Combine the rendered tiles for all views in the cluster to form the final light field output [S1].

### Parameters
*   **Cluster Size ($|V|$):** The number of viewpoints processed together. $|V|=8$ is recommended as it achieves the best performance across datasets [S1]. Increasing $|V|$ improves speed but may reduce fidelity [S1].

### Edge Cases and Pitfalls
*   **High-Frequency Specular Effects:** The Cross-view Coherent Attribute Reuse strategy relies on local consistency within view clusters. Scenes with high-frequency specular effects may exhibit visual artifacts because the assumption of attribute coherence breaks down [S1].
*   **Dynamic Scenes:** The current framework is restricted to static scenes and does not support dynamic content [S1].
*   **Cluster Size Trade-off:** Increasing the cluster size $|V|$ improves rendering speed but may reduce high-fidelity rendering quality [S1].

## Operating characteristics
*   **Time Complexity:** The method reduces redundant computation by reusing attributes across adjacent views, leading to significant speedups compared to full-frame 3DGS. On the Synthetic Blender dataset at 2K resolution, it achieves 88 FPS, compared to 34 FPS without reuse and 67 FPS without remapping [S1].
*   **Memory Complexity:** The View-coherent Remapping step optimizes memory access patterns, reducing latency from uncoalesced accesses [S1].
*   **Measured Performance:**
    *   **Synthetic Blender 2K:** 88 FPS (Full), 34 FPS (w/o Reuse), 67 FPS (w/o Remap) [S1].
    *   **Synthetic Blender 4K:** 56 FPS (Full), 22 FPS (w/o Reuse), 41 FPS (w/o Remap) [S1].
    *   **Mip-NeRF 360 2K:** 30 FPS (Full), 12 FPS (w/o Reuse), 21 FPS (w/o Remap) [S1].
    *   **Mip-NeRF 360 4K:** 16 FPS (Full), 6.4 FPS (w/o Reuse), 11 FPS (w/o Remap) [S1].
*   **Quality:** CoherentRaster achieves higher PSNR than MPI-based frameworks (e.g., 20.84/21.28 dB on Synthetic Blender at 2K/4K for MPI) by avoiding discretization artifacts from limited depth planes [S1].
*   **Strengths:** Real-time rendering on high-resolution LFDs (beyond 2K for real-world scenes); eliminates redundant multi-view computation; resolves uncoalesced memory access [S1].
*   **Limitations:** Restricted to static scenes; potential artifacts in scenes with high-frequency specular effects due to view coherence assumptions [S1].

## Background
CoherentRaster was introduced as a real-time 3DGS-based light field rendering framework for Light Field Displays (LFDs) [S1]. It addresses the limitations of previous methods like Subpixel-3DGS (redundant computation, uncoalesced memory) and MPI-based frameworks (poor scaling, discretization artifacts) [S1]. The method was developed to enable real-time rendering for high-resolution multi-view displays, a task previously unattainable with standard 3DGS pipelines due to computational redundancy [S1].
