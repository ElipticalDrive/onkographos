# 3D Skew-Normal Splatting

Also called: Skew-Normal Splatting

## Overview
3D Skew-Normal Splatting (SNS) replaces the standard symmetric 3D Gaussian kernel with the Azzalini Skew-Normal distribution to model asymmetric structures, such as sharp boundaries and one-sided surfaces, while preserving analytical tractability under affine transformations [S1, unofficial]. It sets apart from standard Gaussian Splatting and its symmetric variants (e.g., [Textured-GS](9436-textured-gs.md), [Oriented Gaussian Splatting](9621-oriented-gaussian-splatting.md)) by introducing a learnable skewness parameter that allows continuous interpolation between symmetric Gaussians and half-ellipsoids, enabling a single primitive to represent complex geometries that would otherwise require multiple overlapping kernels [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** $N$ 3D Skew-Normal primitives defined by location $\mu$, scale matrix $\Omega$, skew latent variable $k$, color coefficients $c$, and signed opacity $o$; camera parameters including view matrix $W$ and projection matrix $P$ [S1, unofficial].
*   **Output:** Rendered pixel colors $C(u)$ for each pixel $u$ [S1, unofficial].

**Data Structures:**
Each primitive $i$ stores:
*   $\mu_i \in \mathbb{R}^3$: Location parameter [S1, unofficial].
*   $R_i \in \mathbb{R}^{3 \times 3}$: Rotation matrix (orthonormal) [S1, unofficial].
*   $S_i \in \mathbb{R}^3$: Scale vector (positive) [S1, unofficial].
*   $\Omega_i = R_i S_i S_i^\top R_i^\top \in \mathbb{R}^{3 \times 3}$: Scale matrix [S1, unofficial].
*   $x_i \in \mathbb{R}$: Raw scalar for skew magnitude [S1, unofficial].
*   $v_i \in \mathbb{R}^3$: Raw vector for skew direction [S1, unofficial].
*   $c_i$: Color coefficients (e.g., spherical harmonics) [S1, unofficial].
*   $o_i \in [-1, 1]$: Signed opacity [S1, unofficial].

**Derived Parameters:**
*   Skew magnitude: $m_k = \frac{8}{1 + \exp(-x/6)}$ [S1, unofficial].
*   Skew direction: $d_k = \frac{v}{\|v\|_2 + \epsilon}$ [S1, unofficial].
*   Latent skew vector: $k = m_k d_k$ [S1, unofficial].
*   Slant parameter: $\alpha = \omega R S^{-1} k$, where $\omega = (\Omega \odot I_3)^{1/2}$ [S1, unofficial].

**Numbered Steps:**

1.  **Parameter Initialization:** Initialize $\mu, R, S, c, o$ as in standard 3DGS [G]. Initialize $x$ and $v$ to small random values or zeros to start with symmetric Gaussians [G].
2.  **Compute Skew Vector:** Calculate $m_k$ from $x$ and $d_k$ from $v$. Compute $k = m_k d_k$ [S1, unofficial].
3.  **Compute Slant:** Calculate $\omega = \sqrt{\text{diag}(\Omega)}$. Compute $\alpha = \omega R S^{-1} k$ [S1, unofficial].
4.  **Project to 2D:** Compute affine transformation matrix $A = JW$, where $J$ is the Jacobian of the projection and $W$ is the view matrix [S1, unofficial]. Compute 2D center $\mu^{2D} = A \mu$ [S1, unofficial]. Compute 2D covariance $\Omega^{2D} = A \Omega A^\top$ [S1, unofficial]. Compute 2D skew parameter $m^{2D} = \frac{(\Omega^{2D})^{-1} A R S k}{\sqrt{1 + k^\top k} - (A R S k)^\top (\Omega^{2D})^{-1} A R S k}$ [S1, unofficial].
5.  **Bounding Box Correction:** Compute the offset to the true spatial mean $\Delta = \sqrt{\frac{2}{\pi}} \cdot \frac{A R S k}{\sqrt{1 + k^\top k}}$ [S1, unofficial]. Set bounding box center $\mu_{bbox} = \mu^{2D} + \Delta$ [S1, unofficial]. Use $\mu_{bbox}$ and $\Omega^{2D}$ to determine tile intersection for rasterization [G].
6.  **Rasterization:** For each pixel $u$ covered by the primitive's bounding box, compute the 2D Skew-Normal density $SN^{2D}(u) = G_2(u - \mu^{2D}; \Omega^{2D}) \Phi \left( (m^{2D})^\top (u - \mu^{2D}) \right)$, where $G_2$ is the 2D Gaussian PDF and $\Phi$ is the standard normal CDF [S1, unofficial]. Compute spatial influence $a_i(u) = o_i SN^{2D}(u)$ [S1, unofficial].
7.  **Color Aggregation:** Sort primitives by depth [G]. Aggregate color using front-to-back alpha blending with signed opacity: $C(u) = \sum_{i \in \mathcal{N}} c_i o_i SN_i^{2D}(u) \prod_{j=1}^{i-1} (1 - o_j SN_j^{2D}(u))$ [S1, unofficial].

**Pseudocode:**

```python
import torch
import torch.nn.functional as F

def compute_skew_params(x, v, eps=1e-8):
    """Compute skew magnitude and direction from raw learnable parameters."""
    m_k = 8.0 / (1.0 + torch.exp(-x / 6.0))
    d_k = v / (torch.norm(v, dim=1, keepdim=True) + eps)
    k = m_k.unsqueeze(1) * d_k
    return k

def compute_slant(R, S, k, Omega):
    """Compute slant parameter alpha."""
    omega = torch.sqrt(torch.diagonal(Omega, dim1=1, dim2=2))
    S_inv = 1.0 / (S + eps)
    R_scaled = R * S_inv.unsqueeze(1)
    R_sk = torch.bmm(R_scaled, k.unsqueeze(2)).squeeze(2)
    alpha = omega * R_sk
    return alpha

def project_skew_to_2d(A, mu, Omega, R, S, k):
    """Project 3D Skew-Normal to 2D image plane."""
    mu_2d = torch.bmm(A, mu.unsqueeze(2)).squeeze(2)
    Omega_2d = torch.bmm(torch.bmm(A, Omega), A.transpose(1, 2))
    ARSk = torch.bmm(torch.bmm(A, R), (S.unsqueeze(1) * k).unsqueeze(2)).squeeze(2)
    Omega_2d_inv = torch.inverse(Omega_2d)
    k_norm_sq = torch.sum(k**2, dim=1, keepdim=True)
    denom = torch.sqrt(1.0 + k_norm_sq) - (ARSk.transpose(1, 0) @ Omega_2d_inv @ ARSk.unsqueeze(2)).squeeze(2)
    m_2d = (Omega_2d_inv @ ARSk.unsqueeze(2)).squeeze(2) / denom
    return mu_2d, Omega_2d, m_2d

def render_sns(primitives, cameras, image_size):
    """Main rendering loop."""
    mu, R, S, x, v, c, o = primitives['mu'], primitives['R'], primitives['S'], primitives['x'], primitives['v'], primitives['c'], primitives['o']
    k = compute_skew_params(x, v)
    A = cameras['J'] @ cameras['W']
    mu_2d, Omega_2d, m_2d = project_skew_to_2d(A, mu, R, S, k)
    k_norm = torch.sqrt(1.0 + torch.sum(k**2, dim=1, keepdim=True))
    ARSk = torch.bmm(torch.bmm(A, R), (S.unsqueeze(1) * k).unsqueeze(2)).squeeze(2)
    delta = torch.sqrt(torch.tensor(2.0 / torch.pi)) * ARSk / k_norm
    mu_bbox = mu_2d + delta
```

**Parameters:**
*   Skew magnitude raw parameter $x \in \mathbb{R}$: Maps to $m_k \in [0, 8]$ via sigmoid-like function [S1, unofficial].
*   Skew direction raw vector $v \in \mathbb{R}^3$: Normalized to unit length [S1, unofficial].
*   Signed opacity $o_i \in [-1, 1]$: Allows subtractive density [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Unbounded Tails:** If skewness is unbounded, primitives may intersect excessive tiles, degrading rasterization performance and violating local affine approximation assumptions [S1, unofficial]. The bounded parameterization prevents this [S1, unofficial].
*   **Parameter Coupling:** Strong coupling between scale, rotation, and skewness causes optimization instability. The decoupled parameterization $\alpha = \omega R S^{-1} k$ and factorization of $k$ into $m_k, d_k$ resolves this [S1, unofficial].
*   **Mean vs. Location:** The location parameter $\mu$ does not coincide with the spatial mean. Using $\mu$ for bounding boxes leads to inaccurate localization. The corrected center $\mu_{bbox}$ must be used [S1, unofficial].

## Subtopics

### [2D Skew-Normal Parameter Projection](10052-2d-skew-normal-parameter-projection.md)
Computes the parameters of a 2D Skew-Normal distribution (SN2D) resulting from the linear projection of a 3D Skew-Normal kernel (SN3) onto the image plane. It sets apart from standard Gaussian splatting by preserving the asymmetry (skewness) of the 3D primitive during projection, allowing the 2D kernel to model one-sided surfaces and sharp boundaries that symmetric Gaussians cannot.

### Skew-Normal Mean Correction
Addresses the fact that the location parameter $\mu$ of a Skew-Normal distribution is not its spatial mean. It derives a corrected operational center $\mu_{bbox}$ to ensure accurate bounding-box localization for rasterization. The mean is given by $\mathbb{E}[X] = \mu + \sqrt{\frac{2}{\pi}} \cdot \frac{R S k}{\sqrt{1+k^\top k}}$ [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Comparable to standard 3DGS and SSS, with minor overhead from computing the Skew-Normal CDF $\Phi$ and the additional skew parameters [S1, unofficial].
*   **Memory Complexity:** Slightly higher than 3DGS due to storage of skew parameters ($x, v$ or $k$) per primitive [S1, unofficial].
*   **Measured Performance:** On Mip-NeRF360, SNS achieves 30.17 PSNR, 0.895 SSIM, 0.144 LPIPS, outperforming SSS (29.90 PSNR) and 3DGS (28.69 PSNR) [S1, unofficial]. On the drjohnson scene, SNS completes 30,000 iterations in 38m 4s (29.89 dB PSNR), comparable to SSS (38m 7s, 29.66 dB PSNR) [S1, unofficial].
*   **Strengths:** Continuous shape interpolation between symmetric and asymmetric primitives; better modeling of sharp edges and flat surfaces; bounded skewness ensures stable rasterization [S1, unofficial].
*   **Limitations:** Optimization requires a two-phase strategy (joint then block coordinate descent) to handle parameter coupling; slightly more complex gradient computation due to the skew term [S1, unofficial].
*   **When to use:** Scenes with sharp boundaries, one-sided structures, or asymmetric details that symmetric Gaussians struggle to represent efficiently [S1, unofficial].
*   **When not to use:** Scenes with purely symmetric, smooth geometry where the added complexity and parameters do not yield significant quality improvements [G].

## Background
3D Skew-Normal Splatting was introduced in the paper "3D Skew-Normal Splatting" (arXiv:2605.15010) [S1, unofficial]. It builds on the Azzalini Skew-Normal distribution, which has been used in statistics for decades, and adapts it to the differentiable rendering framework of 3D Gaussian Splatting. The method addresses limitations of symmetric kernels in representing complex geometries by introducing a learnable skewness parameter while maintaining analytical tractability [S1, unofficial].
