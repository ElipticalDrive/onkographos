# Multi-stage Training with Pose Prediction

Also called: FineSplat training phases, Training and Inference Protocol, Two-stage Training with Pose-free Inference

## Overview
Multi-stage training with pose prediction addresses the instability of end-to-end optimization in feed-forward 3D Gaussian Splatting by decoupling geometry reconstruction from pose estimation and refinement [S1, S2, unofficial]. It enables robust pose-free novel view synthesis by first learning a stable scene representation with ground-truth or weakly supervised cameras, then progressively unfreezing the pose estimator for fine-tuning [S1, S2, unofficial]. This approach distinguishes itself from single-stage training by isolating the error sources of camera prediction from Gaussian attribute optimization, a strategy also explored in [Free-View Training (FVT)](15162-free-view-training-fvt.md) but implemented here through distinct architectural freezing and loss weighting protocols.

## How it works
The method implements a sequential training protocol across three distinct phases. The specific implementation details vary between the FineSplat [S1, unofficial] and InfiniSplat v2 [S2, unofficial] architectures, though both follow the freeze-unfreeze paradigm.

### Inputs and Outputs
*   **Inputs:** A set of input views $\mathcal{I}_{in} = \{I_1, \dots, I_V\}$ with associated intrinsics and poses (during Stage I/II) or uncalibrated images (during End-to-end). Ground-truth target views $\mathcal{I}_{tgt}$ are used for supervision.
*   **Outputs:** A set of 3D Gaussians $\mathcal{G}$ and, in pose-free settings, predicted camera poses for target views.

### Data Structures
The method operates on the standard 3D Gaussian primitive set $\mathcal{G}$ defined in [Progressive and Multi-stage Training](9966-progressive-and-multi-stage-training.md).
*   **FineSplat [S1, unofficial]:** Uses a patch-aligned Gaussian decoder. Tokens are processed in steps $i=0 \dots T$.
*   **InfiniSplat v2 [S2, unofficial]:** Uses a geometry branch (reconstructor) and an attribute branch (refiner). The spatial KNN graph is fixed after Stage I to allow reuse across steps.

### Training Phases

#### Phase 1: Initial Geometry and Pose Learning
**FineSplat [S1, unofficial]:**
1.  Train a pixel-aligned Gaussian prediction network for 120,000 iterations.
2.  Replace the pixel-aligned decoder with a patch-aligned Gaussian decoder.
3.  Fine-tune the model for an additional 80,000 iterations on 8 GPUs.
4.  Supervise predicted poses and intrinsics using camera losses [S1, unofficial].

**InfiniSplat v2 [S2, unofficial]:**
1.  Initialize both the geometry branch (reconstructor) and attribute branch (refiner).
2.  Input RGB images and Ground-Truth (GT) pose conditions.
3.  Supervise input and sampled target renderings using equally weighted masked L1 and LPIPS losses.
4.  Update only the attribute branch’s last $K$ Transformer blocks and the Gaussian decoder. The geometry branch remains frozen or is trained minimally depending on the specific variant, but the primary update is on attributes [S2, unofficial].

#### Phase 2: Pose-Free Refinement with Ground-Truth Cameras
This phase freezes the pose estimation capabilities of Stage 1 to allow the Gaussian attributes to learn correction without being confounded by pose errors [S1, unofficial].

**FineSplat [S1, unofficial]:**
1.  Freeze Stage 1 parameters.
2.  Train Stage 2 using ground-truth camera poses and intrinsics.
3.  The model learns to correct Gaussian attributes independently of pose errors.
4.  Supervise the output at every step $T=4$.
5.  The training loss is averaged over all steps:
    $$ L = \frac{1}{T} \sum_{i=1}^{T} \left( \mathcal{L}_2(\hat{I}^{(i)}, I) + \lambda \mathcal{L}_{perc}(\hat{I}^{(i)}, I) \right) $$
    where $\hat{I}^{(i)}$ is the rendered image after step $i$, $I$ is the ground truth, $\mathcal{L}_2$ is mean squared error, $\mathcal{L}_{perc}$ is VGG-19 perceptual loss, and $\lambda = 0.2$ [S1, unofficial].
6.  Tokens are detached between steps so each step learns to improve the state it receives [S1, unofficial].
7.  Train for 20,000 iterations on 4 GPUs [S1, unofficial].

**InfiniSplat v2 [S2, unofficial]:**
1.  Freeze the reconstructor (geometry branch).
2.  Train the feature projection and refiner (attribute branch).
3.  Input-view losses provide feedback to the refiner.
4.  Input and disjoint target views supervise the updated scene attributes [S2, unofficial].

#### Phase 3: End-to-End Fine-Tuning (Pose-Free)
All parameters are unfrozen to enable full pose-free inference.

**FineSplat [S1, unofficial]:**
1.  Unfreeze all parameters, including the camera pose estimator and Gaussian head.
2.  Fine-tune the full model in a fully pose-free setting where both context and target cameras are predicted.
3.  No camera loss is used in this phase.
4.  Supervise the Stage-1 Gaussians.
5.  The loss is averaged over steps $i=0 \dots T$:
    $$ L = \frac{1}{T+1} \sum_{i=0}^{T} \left( \mathcal{L}_2(\hat{I}^{(i)}, I) + \lambda \mathcal{L}_{perc}(\hat{I}^{(i)}, I) \right) $$
6.  Fine-tune for 10,000 iterations on 8 GPUs [S1, unofficial].

**InfiniSplat v2 [S2, unofficial]:**
1.  The model supports pose-free inference using the geometry branch’s predicted cameras.
2.  Translations are normalized by $s_{norm}$ (scene scale normalization) [S2, unofficial].
3.  The refiner updates scene attributes while network weights remain fixed during inference [S2, unofficial].

### Optimization Parameters
*   **Optimizer:** AdamW [S1, S2, unofficial].
*   **Hyperparameters:** $\beta_1 = 0.9$, $\beta_2 = 0.95$, weight decay $0.05$ (applied to multi-dimensional parameters only), gradient clipping max norm $1.0$ [S1, unofficial].
*   **Precision:** bfloat16 mixed precision [S1, unofficial].
*   **Learning Rates:**
    *   **FineSplat Stage 1:** $2 \times 10^{-5}$, no warm-up, cosine decay to zero [S1, unofficial].
    *   **FineSplat Stage 2:** $1 \times 10^{-4}$, 200-iteration linear warm-up, constant until 80% of training, cosine decay to zero over remaining 20% [S1, unofficial].
    *   **FineSplat End-to-End:** $2 \times 10^{-5}$ for all parameters, 200-iteration linear warm-up, cosine decay to zero [S1, unofficial].
    *   **InfiniSplat v2:** Specific LR schedules not detailed in the provided notes, but uses masked L1 and LPIPS losses [S2, unofficial].

### Scene Scale Normalization
Feed-forward methods predict geometry in a world frame with undefined origin, orientation, and scale [S1, unofficial].
*   **YoNoSplat convention (used by FineSplat [S1, unofficial]):** Origin is placed at the first context camera. All translations are divided by the maximum pairwise distance between context camera centers [S1, unofficial].
*   **ZipSplat convention:** Scale is derived from estimated depth [S1, unofficial].
*   **InfiniSplat v2 [S2, unofficial]:** Translations are normalized by $s_{norm}$, derived from predicted depths or context camera statistics [S2, unofficial].

### Edge Cases and Pitfalls
*   **Pose Error Confounding:** Training pose and attributes simultaneously in early stages can lead to instability. Freezing pose in Stage 2 mitigates this [S1, unofficial].
*   **Token Dependency:** In iterative refinement (FineSplat), failing to detach tokens between steps causes error accumulation across steps [S1, unofficial].
*   **Cheirality:** In variants like RLSplat, Gaussians must be prevented from landing behind the camera using a cheirality penalty in the projection loss [S3, unofficial].

## Subtopics

### RLSplat Training
RLSplat employs a two-stage training process focused on resource-linear budget control [S3, unofficial].
*   **Stage 1 (Base Training):** The geometry backbone and decoder are trained with random Gaussian allocations for 40,000 steps. The Gaussian budget is sampled from $[2048, 16384V]$ where $V$ is the number of input views. This exposes the decoder to diverse allocations [S3, unofficial].
*   **Stage 2 (Policy Training):** A policy head is added, initialized to uniform probabilities. The entire model is fine-tuned for 5,000 steps with the policy loss $L_{policy} = -J_{policy}$. Budgets are sampled with a skew toward the lower end of the range [S3, unofficial].
*   **Losses:** Total loss combines reconstruction loss $L_{recon}$ (MSE + LPIPS), camera loss $L_{cam}$ (translation, rotation, FOV), projection loss $L_{proj}$ (with cheirality penalty), locality regularizers ($L_{vor}, L_{offset}$), and policy loss [S3, unofficial].
*   **Parameters:** $K_{anc} = K_{gs} = 16$ [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** Multi-stage training significantly increases total training time compared to single-stage methods due to sequential phases. FineSplat requires 120K + 80K + 20K + 10K = 230K iterations [S1, unofficial]. InfiniSplat v2 stages are not explicitly timed in the notes but involve similar sequential dependencies [S2, unofficial].
*   **Memory Complexity:** Memory usage is dominated by the Gaussian set $\mathcal{G}$ and the intermediate tokens/features during the iterative refinement steps. FineSplat detaches tokens between steps to manage gradient memory [S1, unofficial]. InfiniSplat v2 reuses the spatial KNN graph to save memory [S2, unofficial].
*   **Performance:** Multi-stage training with pose prediction yields higher PSNR and SSIM in pose-free novel view synthesis compared to end-to-end training, particularly at lower Gaussian budgets [S3, unofficial]. FineSplat achieves detailed splats with local groups [S1, unofficial]. InfiniSplat v2 improves feed-forward 3DGS from any views [S2, unofficial].
*   **Strengths:** Robustness to pose initialization errors; stable convergence; high-quality texture and geometry details.
*   **Limitations:** Complex training pipeline; requires careful tuning of learning rates and freezing schedules; sensitive to scene scale normalization conventions [S1, S2, unofficial].
*   **When to use:** When high-fidelity novel view synthesis is required and computational resources allow for multi-stage optimization. When pose-free inference is needed without explicit camera calibration [S1, S2, unofficial].
*   **When not to use:** For real-time applications requiring single-pass inference without pre-training; when training data lacks sufficient overlap for reliable pose estimation [S1, unofficial].

## Background
The method originates from the need to stabilize feed-forward 3D Gaussian Splatting, which suffers from instability when predicting both geometry and camera poses simultaneously [S1, S2, unofficial]. FineSplat [S1, unofficial] introduced the three-phase protocol (Stage 1: pixel/patch-aligned, Stage 2: GT pose refinement, Stage 3: end-to-end pose-free) to decouple these errors. InfiniSplat v2 [S2, unofficial] adapted this into a two-branch architecture (geometry reconstructor and attribute refiner) with pose-free inference capabilities. RLSplat [S3, unofficial] extended the multi-stage concept to include policy-based Gaussian allocation for budget control. These methods build on the foundational 3D Gaussian Splatting [Parent] and densification strategies [Densification Strategy](6234-densification-strategy.md).
