# Score-based Densification

Also called: Budget-constrained Optimization, Guided Densification

## Overview
Score-based Densification is a constructive training strategy for 3D Gaussian Splatting that controls model size by adding new primitives only where they improve reconstruction quality, adhering to a strict user-defined budget without requiring pruning [S1]. Unlike standard Gaussian Splatting which relies on heuristic splitting and subsequent culling, this method uses a scoring function to guide densification, ensuring the final model size is predictable and fixed [S1]. It distinguishes itself from siblings like [Gaussian Insertion and Pruning](10074-gaussian-insertion-and-pruning.md) by eliminating the need for destructive culling operations during training, thereby avoiding optimization instability and hardware constraint violations [S1].

## How it works
**Inputs:**
*   Current set of 3D Gaussians $\mathcal{G}$.
*   A set of sampled training views.
*   A target model size (budget) $N_{target}$.
*   Current iteration count $t$.

**Outputs:**
*   Updated set of 3D Gaussians $\mathcal{G}'$ with increased count towards $N_{target}$.

**Data Structures:**
*   **Gaussian Properties:** Position $\mathbf{p}$, Covariance $\mathbf{\Sigma}$ (or rotation $\mathbf{R}$ and scale $\mathbf{s}$), Opacity $\alpha$, Spherical Harmonics coefficients $\mathbf{c}$, and Color $C$.
*   **Score Buffer:** A scalar value $S_g$ stored per Gaussian, aggregating gradient magnitude, saliency, and primitive properties.

**Steps:**

1.  **Sample Views and Compute Saliency:**
    Sample a batch of training views. For each view, render the current scene and compute the per-pixel loss (e.g., L1 or SSIM) relative to the ground truth. Convert these per-pixel errors into a saliency map $M_{saliency}$, identifying regions where the reconstruction is poor or visually important [S1].

2.  **Compute Per-Gaussian Score ($S_g$):**
    For each Gaussian $g \in \mathcal{G}$, compute a score $S_g$ using a scoring function $F$ that combines multiple signals [S1]:
    $$ S_g = F(\nabla_g, M_{saliency}, P_g) $$
    Where:
    *   $\nabla_g$ is the accumulated gradient magnitude of the loss with respect to the Gaussian's parameters (position, opacity, etc.) across the sampled views.
    *   $M_{saliency}$ is the average saliency value of the pixels splatted by the Gaussian.
    *   $P_g$ represents primitive properties (e.g., current size, opacity) to prevent densification of already well-reconstructed or redundant primitives [S1].
    *   *Note:* The exact formulation of $F$ is not specified in the sources, but it is described as a combination of loss-relevant components collected per Gaussian [S1].

3.  **Select Top-Scoring Gaussians:**
    Rank all Gaussians by $S_g$ in descending order. Select the top $k$ Gaussians to act as seeds for densification. The number $k$ is determined by the desired growth rate at the current iteration [S1].

4.  **Densify New Gaussians:**
    For each selected seed Gaussian $g_{seed}$, spawn new Gaussians in its vicinity. The sources state that densification occurs "in the vicinity" of top-scoring Gaussians [S1].
    *   *Initialization:* New Gaussians are typically initialized with the position and orientation of the parent, with slightly perturbed positions and scales [G].
    *   *Budget Constraint:* The total number of Gaussians must not exceed $N_{target}$. The growth curve is fitted to mimic standard 3DGS behavior but constrained to hit $N_{target}$ exactly at the end of training [S1].

5.  **Update Optimization State:**
    Continue training with the expanded set $\mathcal{G}'$. Since no pruning is performed, the optimization trajectory is purely constructive [S1].

**Parameters:**
*   **Target Size ($N_{target}$):** The exact number of Gaussians desired at the end of training. Not given in the sources as a specific value, but user-defined.
*   **Growth Curve:** A function mapping iteration to the number of added Gaussians. It is fitted to ensure the model size reaches $N_{target}$ at the final iteration [S1].

**Edge Cases and Pitfalls:**
*   **Budget Violation:** If the growth curve is not carefully fitted, the model may exceed $N_{target}$ or fail to reach it. The method avoids "unnecessary peaks in optimization" that could violate hardware constraints, which is a key advantage over pruning-based methods [S1].
*   **Redundancy:** Without pruning, there is a risk of redundant Gaussians if the scoring function does not adequately penalize already well-reconstructed primitives. The scoring function $F$ must account for primitive properties $P_g$ to mitigate this [S1].

## Subtopics

### [Perceptual-GS](9175-perceptual-gs.md)
Perceptual-GS replaces the standard gradient-threshold densification heuristic with a scene-adaptive perceptual signal to improve detail in visually salient areas. It distinguishes itself from sibling methods like Pixel-GS by utilizing a learned vision-transformer head to compute a local perceptual error map, rather than relying solely on raw pixel or gradient magnitudes.

### [Pixel-GS](9189-pixel-gs.md)
Pixel-GS is a densification strategy for 3D Gaussian Splatting that modifies the gradient-based splitting signal to account for the spatial footprint of each Gaussian primitive. It addresses the baseline's tendency to under-densify regions by scaling the positional gradient by the number of pixels a Gaussian influences and applying a depth-dependent scaling factor to suppress floaters. It recovers detail the baseline misses without simply carpeting the scene in more blobs.

### Late Densification
Late Densification is a minor variant that enables densification back between iterations 20K to 20.5K for every 100 iterations to help the model recover loss from pruning of false-positive Gaussians [S2].

### Fixed-Budget Optimisation
Fixed-Budget Optimisation is an approach where the user specifies a maximum budget, and the optimisation is constrained not to surpass that value [S3]. It learns a fractional assignment of cost to each panel, starting from a uniform assignment, and rescales the area of the panel such that the cost equals its assigned fraction of the total detector cost [S3]. This mode ensures the user meets their budget exactly and requires no balancing coefficients between performance and cost in the loss function [S3].

## Operating characteristics
*   **Time Complexity:** The method avoids the computational overhead of pruning and culling operations required by standard 3DGS, potentially reducing training time peaks [S1]. However, it requires computing saliency maps and per-Gaussian scores for every densification step [S1].
*   **Memory Complexity:** Memory usage is strictly bounded by the target budget $N_{target}$, preventing the unpredictable memory spikes associated with uncontrolled Gaussian growth [S1].
*   **Performance:** The method achieves high-quality reconstruction at a fixed budget, comparable to or better than standard 3DGS with pruning [S1].
*   **Strengths:** Predictable model size, no need for pruning, avoids optimization instability, suitable for downstream tasks requiring fixed-size inputs [S1].
*   **Limitations:** Requires careful tuning of the growth curve and scoring function parameters. The exact formulation of the scoring function $F$ is not provided in the sources, making implementation dependent on heuristic choices [S1].

## Background
Score-based Densification was introduced in "Taming 3DGS: High-Quality Radiance Fields with Limited Resources" [S1]. It addresses the challenges of training 3D Gaussian Splatting on a budget, specifically the unpredictable storage demands and fluctuating training times of the original method [S1]. The work acknowledges concurrent work by Bulò et al. [2024] on revising densification in 3D Gaussian Splatting [S1]. The method is part of a broader effort to make 3DGS more practical for downstream tasks by controlling model size and training duration [S1].
