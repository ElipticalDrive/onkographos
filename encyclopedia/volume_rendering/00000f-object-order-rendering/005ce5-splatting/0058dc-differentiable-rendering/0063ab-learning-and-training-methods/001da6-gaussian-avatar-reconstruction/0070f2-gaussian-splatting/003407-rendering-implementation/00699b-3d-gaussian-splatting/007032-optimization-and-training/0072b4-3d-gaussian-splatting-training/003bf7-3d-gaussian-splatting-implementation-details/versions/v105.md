# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, GSGEN Implementation Details, Gaussian Splatting Training Configuration, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the computational pipeline, optimization schedules, and specific hyperparameters required to implement the 3D Gaussian Splatting (3DGS) training and rendering loop. It addresses the problem of efficiently managing millions of anisotropic Gaussian primitives on GPU hardware, covering data structures, kernel-level optimizations (such as half-precision fetches), and the iterative densification/pruning schedules that maintain reconstruction quality. It sets itself apart from [3D Gaussian Splatting Training](3761-3d-gaussian-splatting-training.md) by providing the low-level implementation specifics—such as exact iteration intervals, threshold values, and memory management techniques—that are necessary to realize the high-level training strategy.

## How it works

### Inputs and Outputs
**Inputs:**
- A set of $N$ input images $\{I_i\}$ with known camera poses (extrinsics $C_i$ and intrinsics $K_i$).
- An initial point cloud $\mathcal{P}_0$ derived from Structure-from-Motion (SfM) (e.g., COLMAP).
- Optimization hyperparameters (learning rates, iteration counts, thresholds).

**Outputs:**
- A trained set of 3D Gaussian primitives $\mathcal{G} = \{\mu_j, \Sigma_j, \alpha_j, c_j, \mathbf{S}_j\}_{j=1}^M$, where $\mu$ is position, $\Sigma$ is covariance, $\alpha$ is opacity, $c$ is spherical harmonic (SH) coefficients, and $\mathbf{S}$ is scale.
- Rendered novel views.

### Data Structures
The implementation relies on specific GPU memory layouts to minimize bandwidth and register pressure [S2].

1.  **Gaussian Attributes:**
    -   **Position ($\mu$):** 3 floats (FP32 or FP16 depending on implementation).
    -   **Rotation ($R$):** 4 floats (quaternion).
    -   **Scale ($s$):** 3 floats.
    -   **Opacity ($\alpha$):** 1 float.
    -   **SH Coefficients ($c$):** $3 \times (D+1)^2$ floats, where $D$ is the SH degree. Typically $D=1$ (7 coefficients per channel, 21 floats total) [S3].
    -   **Layout:** Attributes are stored in Structure-of-Arrays (SoA) or Array-of-Structures (AoS) formats optimized for coalesced memory access during rasterization.

2.  **Rasterization State:**
    -   **Tile Map:** A 2D grid mapping pixels to tile IDs (typically $16 \times 16$ or $32 \times 32$ pixels per tile).
    -   **Gaussian List:** A sorted list of Gaussians per tile, ordered by depth.
    -   **Depth Buffer:** Per-pixel depth for alpha blending.

3.  **Optimization State:**
    -   **Optimizer States:** Adam optimizer states (mean and variance estimates) for each parameter group, typically stored in FP16 or BF16 to save memory [S2].

### Numbered Steps

1.  **Initialization:**
    -   Initialize Gaussians from the SfM point cloud $\mathcal{P}_0$.
    -   Set initial covariance $\Sigma_j$ based on the distance to nearest neighbors in $\mathcal{P}_0$.
    -   Initialize SH coefficients to zero (or DC color only for lightweight passes) [S15].

2.  **Forward Pass (Rasterization):**
    -   **Projection:** For each Gaussian, compute the 2D covariance matrix $\Sigma'$ in screen space using the Jacobian of the projection matrix and the 3D-to-2D transformation [Parent].
    -   **Culling:** Discard Gaussians whose 2D bounding box does not intersect any tile.
    -   **Sorting:** Sort visible Gaussians per tile by depth (front-to-back).
    -   **Splatting:** For each pixel in a tile, iterate through the sorted Gaussians. Compute the 2D Gaussian value $G(x,y)$ and accumulate color $C$ and opacity $\alpha$ using alpha blending:
        $$ C = \sum_{i \in \text{sorted}} c_i \alpha_i \prod_{j < i} (1 - \alpha_j) $$
        $$ \alpha = \sum_{i \in \text{sorted}} \alpha_i \prod_{j < i} (1 - \alpha_j) $$
    -   **Half-Precision Fetch:** During rasterization, feature vectors (SH coefficients) are fetched in half-precision (FP16) to reduce register pressure and memory bandwidth usage [S2].

3.  **Loss Computation:**
    -   Compute the photometric loss $\mathcal{L}$ between the rendered image $\hat{I}$ and the ground truth image $I$:
        $$ \mathcal{L} = (1 - \lambda) \mathcal{L}_1(\hat{I}, I) + \lambda \mathcal{L}_{\text{SSIM}}(\hat{I}, I) $$
        where $\lambda$ is a weighting factor (typically 0.2) [S6].

4.  **Backward Pass:**
    -   Compute gradients $\nabla \mathcal{L}$ with respect to all Gaussian parameters ($\mu, R, s, \alpha, c$).
    -   **Gradient Stability:** Apply an automatic scaling factor to loss values to improve stability during half-precision training [S2].

5.  **Optimization Step:**
    -   Update parameters using the Adam optimizer with a learning rate of $1 \times 10^{-3}$ [S3].

6.  **Densification and Pruning (Iterative):**
    -   **Splitting:** Every 500 iterations, split Gaussians with high view-space position gradients.
        -   Condition: Gradient magnitude $> T_{pos} = 0.02$ [S1].
        -   Action: Clone the Gaussian, scale down the clone, and adjust opacity.
    -   **Cloning/Compactness:** Every 1000 iterations, perform compactness-based densification to add Gaussians in under-represented regions [S1].
    -   **Pruning:** Every 200 iterations, remove Gaussians with low opacity.
        -   Condition: Opacity $\alpha < \alpha_{min} = 0.05$ [S1].
        -   Condition: Remove Gaussians with excessively large world-space or view-space radii to prevent "floaters" [S1].

### Pseudocode

```python
def train_3dgs(images, poses, initial_points, num_iterations=30000):
    # Initialize Gaussians from SfM points
    gaussians = GaussianSet.from_points(initial_points)
    
    # Optimizer setup
    optimizer = Adam(gaussians.parameters(), lr=1e-3)
    
    for iteration in range(1, num_iterations + 1):
        # 1. Sample a random image
        idx = random.randint(0, len(images) - 1)
        image = images[idx]
        pose = poses[idx]
        
        # 2. Forward Pass: Rasterize
        # Use half-precision fetches for SH coefficients to save memory [S2]
        rendered_image, depth_buffer = rasterize(gaussians, pose, image.shape)
        
        # 3. Compute Loss
        # Apply automatic scaling for half-precision stability [S2]
        loss = compute_loss(rendered_image, image)
        
        # 4. Backward Pass
        loss.backward()
        
        # 5. Optimizer Step
        optimizer.step()
        optimizer.zero_grad()
        
        # 6. Densification and Pruning
        if iteration % 500 == 0:
            # Split Gaussians with high position gradients [S1]
            split_gaussians(gaussians, threshold=0.02)
            
        if iteration % 1000 == 0:
            # Compactness-based densification [S1]
            densify_gaussians(gaussians)
            
        if iteration % 200 == 0:
            # Prune low opacity and large radius Gaussians [S1]
            prune_gaussians(gaussians, alpha_min=0.05)
            
    return gaussians
```

### Parameters and Typical Values
-   **Learning Rate:** $1 \times 10^{-3}$ [S3].
-   **SH Degree:** 1 (7 coefficients per channel) [S3].
-   **Split Threshold ($T_{pos}$):** 0.02 [S1].
-   **Opacity Threshold ($\alpha_{min}$):** 0.05 [S1].
-   **Loss Weight ($\lambda$):** 0.2 [S6].
-   **Half-Precision:** Enabled for feature vectors and optimizer states [S2].

### Edge Cases and Pitfalls
-   **Half-Precision Instability:** Training in FP16 can lead to gradient overflow/underflow. Mitigation involves automatic loss scaling [S2].
-   **Large Radius Floaters:** Gaussians with excessively large scales can cause visual artifacts. Pruning based on view-space radius is critical [S1].
-   **Sparse View Ambiguity:** In sparse-view scenarios, standard initialization may fail. Techniques like 3DGS Self-Initialization (training a lightweight model to generate additional points) can compensate [S15].
-   **Motion Blur:** Standard 3DGS assumes sharp images. For blurred inputs, per-Gaussian scale offsets ($\delta s_j$) can be predicted to model defocus blur [S4].

## Subtopics

### [DeSplat](12925-desplat.md)
DeSplat is a method for distractor-free novel view synthesis that decomposes the 3D Gaussian Splatting (3DGS) scene representation into two distinct sets of Gaussian primitives: static scene Gaussians ($G_s$) and per-view distractor Gaussians ($G_d$). It solves the problem of transient occluders (e.g., pedestrians, vehicles) corrupting the static 3D reconstruction by separating them from the permanent scene geometry without relying on external semantic segmentation models or pre-trained neural networks. Unlike sibling methods that use foundation models for detection or complex neural appearance encoders for separation, DeSplat relies solely on volume rendering and photometric loss, allowing independent rendering of static elements and transient components while maintaining the speed of standard Gaussian splatting.

### [360 Gaussian Splatting](12929-360-gaussian-splatting.md)
360 Gaussian Splatting is a method for generating high-quality 3D spatial representations from 360-degree camera images by combining OpenSfM for sparse point cloud generation and Gaussian Splatting for dense Gaussian conversion. It solves the problem that standard Gaussian Splatting assumes perspective cameras and cannot directly process equirectangular images from 360-degree cameras, a limitation that previously forced users to crop or split images. It sets itself apart from standard implementations by modifying the differentiable rasterization module to support spherical rendering and using OpenSfM, which natively supports equirectangular inputs, unlike Colmap.

### [Scene Representation and Geometry Constraints](15421-scene-representation-and-geometry-constraints.md)
This family defines the fundamental geometric and appearance primitives of 3D Gaussian Splatting (3DGS) and the mechanisms for their optimization, truncation, and structural refinement. It addresses the problem of representing complex scenes with high-fidelity geometry and appearance using a set of anisotropic 3D Gaussians, while managing computational cost through truncation and densification strategies. It sets itself apart from sibling methods like [Discontinuity-aware Gaussian Splatting](13138-discontinuity-aware-gaussian-splatting.md) by focusing on the core primitive definition and training dynamics rather than post-hoc discontinuity handling, and from [Appearance and Physical Modeling](15766-appearance-and-physical-modeling.md) by prioritizing the structural integrity and density of the Gaussian set itself over complex physical light transport models.

### [Perceptual Wrapper](15438-perceptual-wrapper.md)
The Perceptual Wrapper (PW) is a plug-and-play 2D module that enhances the rendered outputs of existing 3D Gaussian Splatting (3DGS) representations by synthesizing high-frequency texture details in a content- and view-dependent manner. It addresses the limitation of standard 3DGS in rendering sharp textures, particularly under memory-constrained or rate-distortion-optimized (RDO) pipelines where blurriness is exacerbated. Unlike methods that modify the 3D primitive densification or loss functions directly (e.g., Perceptual-GS), PW operates as a post-processing synthesis network in the image domain, conditioned on pseudo-random Gaussian noise and Plücker embeddings, and is trained using Wasserstein Distortion (WD) loss.

### [Inverse and Internal Rendering](15764-inverse-and-internal-rendering.md)
Inverse and Internal Rendering extends 3D Gaussian Splatting (3DGS) to handle scenarios where standard surface-based supervision is insufficient or unavailable, specifically targeting internal volumetric structures, unknown lighting conditions, and global illumination effects. It solves the problem that conventional 3DGS optimizes only camera-visible surfaces, leaving occluded interiors empty, and relies on known camera poses and direct lighting. This family sets itself apart from standard 3DGS by introducing plane-based cross-sectional supervision for internal reconstruction, pose-free conditional splatting for sliced data [15745-inner-3d-gaussian-splatting.md], and analytical gradient propagation through global illumination solvers for material and lighting optimization [23297-gradient-calculation-for-global-illumination.md].

### [Gaussian Frosting](15863-gaussian-frosting.md)
Gaussian Frosting is a mesh-based radiance field representation that augments a base triangle mesh with an adaptive layer of 3D Gaussians, termed the "Frosting," to capture fine volumetric details such as hair or grass while maintaining the editability of a surface mesh. It solves the inefficiency of unconstrained densification in fuzzy areas and the loss of volumetric quality in surface-only methods by allowing users to specify a fixed Gaussian budget ($N$) and adapting the layer thickness locally to material properties. Unlike SuGaR, which flattens Gaussians onto the mesh surface, Frosting preserves rendering quality for complex materials by maintaining a variable-thickness layer.

### [Semantic and Language Integration](15930-semantic-and-language-integration.md)
Semantic and Language Integration extends 3D Gaussian Splatting by associating high-dimensional semantic or language embeddings with Gaussian primitives, enabling open-vocabulary querying, zero-shot segmentation, and semantic-aware scene editing. It differs from standard 3DGS by optimizing a joint loss that includes a feature reconstruction or classification term alongside photometric loss, and it differs from NeRF-based semantic methods by leveraging explicit point-based rasterization to achieve real-time rendering speeds (e.g., 115.0 fps) compared to the slow ray-marching of implicit fields.

### [3D Difference-of-Gaussians (3D-DoG)](16198-3d-difference-of-gaussians-3d-dog.md)
3D Difference-of-Gaussians (3D-DoG) is a volumetric primitive variant designed to enhance the representation of fine geometric details and edges in compact 3D Gaussian Splatting models. It solves the limitation of standard smooth Gaussian kernels, which struggle to capture high-frequency details when the number of primitives is aggressively reduced. Unlike standard 3D Gaussians that only contribute positive density, the 3D-DoG models both positive and negative spatial responses, allowing it to implement color subtraction in $\alpha$-blending to sharpen boundaries. It is distinct from sibling optimization techniques like [DeSplat](12925-desplat.md) or [TurboGS](15697-turbogs.md) by introducing a specific mathematical primitive structure rather than altering the rendering pipeline or training schedule directly.

### [Pruning and Density Control](16215-pruning-and-density-control.md)
Pruning and Density Control manages the dynamic population of 3D Gaussian primitives during training to balance rendering quality, memory efficiency, and convergence stability. It solves the problem of inefficient spatial coverage, overfitting, and redundant primitive accumulation by adaptively growing, splitting, or removing Gaussians based on optimization progress and reconstruction metrics. It sets itself apart from static initialization or uniform densification by employing adaptive schedules and importance-based criteria that synchronize primitive density with rendering resolution and learning progress, ensuring high-frequency details are fitted only after low-frequency structures are established [Parent].

### [QuantumGS](16253-quantumgs.md)
QuantumGS is a hybrid quantum-classical framework that integrates Variational Quantum Circuits (VQCs) into the 3D Gaussian Splatting pipeline to capture high-frequency view-dependent effects, such as sharp reflections and transparency, which classical Multi-Layer Perceptrons (MLPs) struggle to model efficiently in low-parameter regimes. It distinguishes itself from standard view-dependent splatting by mapping viewing directions directly onto the Bloch sphere, leveraging the natural geometry of qubits to represent 3D directional data and achieving higher expressivity through quantum entanglement.

### [Dynamic and Spacetime Modeling](16342-dynamic-and-spacetime-modeling.md)
Dynamic and Spacetime Modeling extends static 3D Gaussian Splatting to represent and render time-varying scenes by introducing temporal dependencies into Gaussian parameters or via deformation fields. It solves the problem of high-fidelity, real-time rendering of dynamic content where static representations fail to capture motion. Unlike static methods, these approaches decouple geometry from appearance over time, using either learned deformation fields in a canonical space or explicit polynomial motion models , distinguishing them from entangled methods that condition the radiance field directly on time.

### [Closed-Form Triangle Splatting (CF-Splat)](16773-closed-form-triangle-splatting-cf-splat.md)
Closed-Form Triangle Splatting (CF-Splat) is a method for efficient scene appearance estimation over a known mesh geometry using calibrated camera views. It formulates rendered pixel colors as a linear function of per-vertex spherical harmonic (SH) coefficients, allowing the global appearance to be solved via a single linear least-squares (LLS) problem rather than iterative nonlinear optimization. Unlike [3D Gaussian Splatting Implementation Details](9128-3d-gaussian-splatting-implementation-details.md), which relies on gradient-based optimization of millions of coupled Gaussian parameters, CF-Splat eliminates iterative updates, thereby avoiding local minima, reducing computation time by 27.5×–378.0×, and lowering peak GPU memory usage.

### [Softmax-GS](16854-softmax-gs.md)
Softmax-GS is a unified rendering and optimization method for 3D Gaussian Splatting that resolves view-inconsistency (popping artifacts) and diffuse boundaries by enforcing a softmax-based competition among overlapping Gaussians. Unlike standard 3D Gaussian Splatting, which assumes non-overlapping primitives, Softmax-GS relaxes this assumption to allow a continuous spectrum of visual behaviors from smooth color blending to sharp, winner-take-all boundaries. It differs from [DeSplat](12925-desplat.md) and [StopThePop](12925-desplat.md) by directly modeling overlap via softmax weights rather than re-sorting or stochastic mixing, and from [EVER](12925-desplat.md) by maintaining near-real-time rendering speeds while providing controllable boundary sharpness.

### [Student’s t-Primitive Representation](17072-student-s-t-primitive-representation.md)
Student’s t-Primitive Representation replaces standard Gaussian kernels with heavy-tailed Student’s t-distribution primitives to improve robustness against outliers and sparse-view ambiguity in volumetric reconstruction. It differs from sibling methods like [DeSplat](12925-desplat.md) or [360 Gaussian Splatting](12929-360-gaussian-splatting.md) by explicitly modeling tail heaviness via the degrees of freedom parameter $\nu_i$, allowing the representation to handle sparse-view artifacts and outlier contamination more effectively than fixed-variance Gaussian splats.

### [Hierarchical, Graph-Based, and Adaptive Structures](17106-hierarchical-graph-based-and-adaptive-structures.md)
This family of methods extends standard 3D Gaussian Splatting (3DGS) by introducing structural organization—such as graphs, trees, grids, or hierarchical levels—to address limitations in scalability, memory efficiency, geometric consistency, and view-dependent aliasing. While standard 3DGS treats primitives as an unstructured flat list, these methods enforce spatial or semantic relationships to enable large-scale rendering, dynamic budget adaptation, and robust deformation. They differ from flat 3DGS by explicitly modeling connectivity or hierarchy, and from sibling methods like [Pruning and Density Control](16215-pruning-and-density-control.md) by using learned or structural constraints rather than simple heuristic removal.

### [Variable Basis Mapping (VBM)](17312-variable-basis-mapping-vbm.md)
Variable Basis Mapping (VBM) is a framework that transforms volumetric fields into 3D Gaussian Splatting (3DGS) representations through wavelet-domain analysis, enabling real-time volumetric visualization by avoiding the prohibitively high computational costs of direct volume rendering. Unlike iVR-GS, which uses randomly initialized Gaussians, or VEG, which uses heuristic density-based spheres, VBM establishes a direct, mathematical bridge using wavelet analysis to exploit structural and statistical information.

### [Human Gaussian Splatting](17349-human-gaussian-splatting.md)
Human Gaussian Splats (HUGS) is a neural rendering framework that represents an animatable human avatar and a static scene using 3D Gaussians, trained on 50–100 frames of monocular video to enable novel view and novel pose synthesis at 60 FPS. It sets itself apart from implicit neural field methods by allowing test-time rendering without evaluating triplane/MLPs for new poses, and from static 3DGS by disentangling the human and scene to allow human transfer to other scenes.

### [Uncertainty and Probabilistic Modeling](17380-uncertainty-and-probabilistic-modeling.md)
Uncertainty and Probabilistic Modeling in 3D Gaussian Splatting (3DGS) addresses the lack of confidence metrics in standard deterministic rendering by estimating the reliability of predicted colors, depths, and geometric parameters. It differs from sibling methods like [DeSplat](12925-desplat.md) or [360 Gaussian Splatting](12929-360-gaussian-splatting.md) by explicitly modeling parameter distributions or post-hoc error statistics rather than just refining geometry or appearance. It enables active view selection, robust reconstruction under sparse or asynchronous data, and detection of out-of-distribution regions.

### [SCION](17424-scion.md)
SCION is a hierarchical compositional scene representation that replaces the millions of independent Gaussians used in standard 3D Gaussian Splatting (3DGS) with a compact vocabulary of reusable local primitives and lightweight world-space instances. It solves the redundancy and lack of structural manipulation handles in standard 3DGS by discovering and encoding repetitive structures end-to-end from multi-view captures. Unlike prior codebook methods that share parameters across distinct splats or require manual instance selection, SCION builds shared primitives and recovers structure automatically, enabling compact storage (e.g., 1.2 MB) and instance-level editing without retraining.

### [On-the-Fly GS](17509-on-the-fly-gs.md)
On-the-Fly GS is a progressive framework for near real-time 3D Gaussian Splatting (3DGS) field optimization that enables robust online training during discrete image acquisition. It addresses the limitation of standard 3DGS, which requires offline training after full Structure-from-Motion (SfM) processing. Unlike SLAM-based methods such as GS-SLAM or RTG-SLAM that require spatial and temporal continuity and often depth priors, On-the-Fly GS handles discrete images captured in an arbitrary manner without spatiotemporal continuity, relying only on a certain degree of overlap with previously registered images.

### [View-Dependent and Appearance Modeling](17617-view-dependent-and-appearance-modeling.md)
This family extends 3D Gaussian Splatting to model complex, view-dependent lighting effects such as specular highlights and anisotropic reflections, which standard isotropic spherical Gaussians cannot capture accurately [G]. ### [Optimization and Training Loop](17791-optimization-and-training-loop.md)
The Optimization and Training Loop is the iterative process that minimizes the photometric error between rendered images and ground-truth input photos by adjusting the parameters of a set of 3D Gaussians. It differs from sibling methods like [TurboGS](15697-turbogs.md) or [Distributed 3DGS Training Loop with Adaptive Workload Division](18650-distributed-3dgs-training-loop-with-adaptive-workload-divisi.md) by relying on the standard stochastic gradient descent with a fixed iteration budget and explicit densification/pruning heuristics, rather than adaptive workload division or accelerated rendering pipelines.

### [BAD-Gaussians](18036-bad-gaussians.md)
BAD-Gaussians recovers a sharp 3D scene representation by jointly learning camera motion trajectories and 3D Gaussian parameters from a sequence of motion-blurred images, inaccurate poses, and sparse point clouds. It solves the problem of reconstructing high-quality geometry and appearance from blurry inputs where standard 3D Gaussian Splatting fails due to unmodeled motion blur. It sets itself apart from sibling methods like [DeSplat](12925-desplat.md) and [360 Gaussian Splatting](12929-360-gaussian-splatting.md) by explicitly modeling the physical motion blur formation process via virtual camera poses and optimizing the camera trajectory (start and end poses) alongside the Gaussians, rather than assuming static sharp inputs or using different blur kernels.

### [LiteTex-GS](18111-litetex-gs.md)
LiteTex-GS is a fast and lightweight texturing framework for 3D Gaussian Splatting that decouples geometry from appearance by assigning independent local RGB texture maps to each Gaussian primitive. It solves the computational overhead of high-resolution texturing by initializing compact low-resolution maps and progressively allocating higher resolution only to primitives with significant reconstruction errors, using a global-to-local capacity allocation strategy. Unlike prior methods that statically allocate texture resolution, LiteTex-GS uses a frequency-aware scheduler to coordinate image supervision, texture-cap release, and primitive densification, while employing a contribution- and area-aware pruning strategy to eliminate low-utility Gaussians.

### [Virtual Camera Optimization for Mirror Reflections](18121-virtual-camera-optimization-for-mirror-reflections.md)
Virtual Camera Optimization for Mirror Reflections (GSIM) is a method for rendering physically accurate mirror reflections in 3D Gaussian Splatting (3D-GS) by modeling reflections as images captured by virtual cameras positioned symmetrically to the real camera across the mirror plane. ### [ParetoGS Continuous-Budget Decoding](18388-paretogs-continuous-budget-decoding.md)
ParetoGS Continuous-Budget Decoding is a runtime procedure that returns parameters for exactly $K$ Gaussians at any valid integer budget by interpolating between nested adapted anchors using a compressed residual atlas and calibrated exponents. It differs from static compression methods like [Data Compression and Storage Optimization](12943-data-compression-and-storage-optimization.md) by enabling smooth, continuous trade-offs between quality and performance without retraining, and from discrete pruning methods like [Pruning and Density Control](16215-pruning-and-density-control.md) by preserving the full geometric fidelity of the original model through residual interpolation rather than hard selection.

### [TruncGradGS](18675-truncgradgs.md)

### [EfficientGS](18681-efficientgs.md)
EfficientGS is an optimized adaptation of 3D Gaussian Splatting (3DGS) designed for efficient large-scale, high-resolution scene representation. ### [Variational 3D Gaussians](18706-variational-3d-gaussians.md)
Variational 3D Gaussians encode a scene as a set of $N$ semantic 3D Gaussians where uncertainty is modeled by storing parameters for a normal distribution of spherical harmonic coefficients rather than explicit feature vectors. ### [EnvMap-GS](18915-envmap-gs.md)
EnvMap-GS is a two-stage Gaussian Splatting framework designed to reconstruct outdoor "inside-out" captures where a camera moves within a restricted navigation area while looking outward at a distant environment. ### [Heat Kernel Textures (HKTex)](19427-heat-kernel-textures-hktex.md)

### [BoundedGS](20068-boundedgs.md)
BoundedGS is a memory-efficient training and rendering method for 3D Gaussian Splatting (3DGS) that bounds GPU memory usage during high-resolution training by separating rasterization and projection backward passes. ### [Connectivity-based Visibility for 3D Gaussian Splatting](20071-connectivity-based-visibility-for-3d-gaussian-splatting.md)

HybridGS is a method for novel view synthesis in scenes containing transient objects (e.g., moving people, vehicles) by decoupling the scene representation into static and transient components. GS2Mesh is a post-processing method that extracts a smooth, triangulated 3D mesh from a trained 3D Gaussian Splatting (3DGS) representation by leveraging a pre-trained stereo-matching model. Local-GS is a warp-coherent rendering paradigm that restructures alpha computation and reorganizes work around SIMT (Single Instruction, Multiple Threads) execution boundaries to reduce warp divergence and redundant computation in 3D Gaussian Splatting. Unlike methods that focus on macroscopic scene culling or geometric simplification, Local-GS is a pure kernel-level optimization that shifts focus to microscopic GPU execution boundaries, mitigating intra-block computational overhead. It achieves this through three stages: tile-hoisted parameterization, warp-level culling, and warp-coherent blending. It is orthogonal to existing culling, pruning, and compression methods, providing additional performance gains when combined with them.

Adaptive Spherical Harmonics Band Adjustment is a memory optimization technique for 3D Gaussian Splatting that assigns a variable number of spherical harmonics (SH) bands (0 to 3) to each primitive based on its view-dependent appearance complexity. It addresses the wasteful memory utilization of the standard fixed 3-band SH representation, where 76% of the primitive storage is dedicated to SH coefficients, by disabling higher-order bands for primitives that can be adequately represented by a single RGB color or fewer bands. Unlike [DeSplat](12925-desplat.md) which focuses on spatial redundancy, this method specifically targets the attribute storage overhead of view-dependent shading.

Codebook Quantization is a post-processing compression technique for 3D Gaussian Splatting that reduces memory footprint by replacing high-precision floating-point attributes with indices into a fixed-size codebook. It specifically targets attributes with low sensitivity to precision errors—opacity, scale, rotation, and spherical harmonics (SH) coefficients—while preserving the full precision of primitive positions to prevent visual degradation. Unlike methods that alter the rendering pipeline or training loop, this approach operates as a final storage optimization, achieving an average memory reduction of 96.3% (approximately 27x) with minimal quality loss.

Camera and Projection Models define the geometric transformation from 3D scene coordinates to 2D image coordinates, serving as the foundation for differentiable rendering in Gaussian Splatting. ### Minor Variants
#### Selective Defocus Blurring
Selective Defocus Blurring predicts a per-Gaussian scale offset $\delta s_j$ using a compact MLP to selectively enlarge covariances, creating pixel-wise variable blur kernels that match spatially varying scene blurriness [S4]. The offset is added to the base scale to transform the covariance, which is then projected to 2D space and used as a blur kernel during rasterization [S4]. If $\delta s_j$ is predicted as a constant for all Gaussians, it degrades to a uniform Gaussian blur over the entire image [S4]. This method enables spatially varying blur shapes and magnitudes, unlike naive Gaussian blur which applies a single kernel to the whole image or learnable Gaussian kernels which optimize a single mean/variance for average blurriness [S4].

#### Denoise-GS
Denoise-GS is a self-supervised denoising method for sparse-view 3D Gaussian Splatting that combines unsupervised image denoising with explicitly differentiable 3DGS to address suboptimal reconstruction performance in sparse view and noisy scenes [S5]. The process involves two rounds: Round 1 trains a UNet using Noise2Void (N2V) for denoising, processes denoised images through InstantSplat to initialize/train/render 3DGS, and groups/filter rendered results by viewpoint [S5]. Round 2 fine-tunes the UNet using a composite loss balancing low-frequency and perceptual detail consistency, then renders again on selected viewpoints [S5]. Unlike supervised methods that rely on annotated datasets, Denoise-GS uses unsupervised N2V, which requires no paired clean data and is robust to uncertain noise patterns in sparse viewpoint scenarios [S5].

#### Multi-Scale Constraint
Multi-Scale Constraint uses position-aware point adaptive control to apply different scales to Gaussians based on viewer distance, improving rendering of distant objects [S6]. It defines a scaling factor $\gamma(\mu)$ based on the distance of the Gaussian center $\mu$ from the camera center $c$ relative to the scene radius $r$: $\gamma(\mu) = 1$ if $\|\mu - c\|^2 < 2r$, and $\gamma(\mu) = \|\mu - c\|^2 / r - 1$ if $\|\mu - c\|^2 \ge 2r$ [S6]. Cloning is performed if $\max(s) < g \cdot \gamma(\mu)$, splitting if $\max(s) \ge g \cdot \gamma(\mu)$, and elimination if $\max(s) > b \cdot \gamma(\mu)$, where $g$ and $b$ are scale threshold parameters [S6].

#### LS-Gaussian Viewpoint Transformation
LS-Gaussian Viewpoint Transformation leverages inter-frame continuity for efficient sparse rendering by transforming the viewpoint between consecutive frames, rather than rendering each frame separately [S7]. It operates at the tile/Gaussian level to enable sparse rendering, unlike naive pixel warping which fails to reduce preprocessing and sorting costs because projected Gaussians are assigned to workloads at the tile level [S7]. Rendering quality degrades noticeably as the number of consecutively transformed frames increases due to the accumulation of interpolation errors [S7]. It is used in LS-Gaussian to enable sparse rendering where only one frame in every 6 frames is fully rendered, as demonstrated on Jetson AGX Orin [S7].

#### Opacity Offset Table for DSA
Opacity Offset Table for DSA constructs an opacity offset table to model changes in digital subtraction angiography [S8].

#### GAINS (Gaussian-based Inverse Rendering from Sparse multi-view captures)
GAINS is a two-stage inverse rendering framework that leverages foundation model priors to stabilize geometry and material estimation from sparse multi-view RGB captures [S9]. Stage I optimizes geometry using monocular depth, normal, and diffusion priors. Stage II jointly optimizes material parameters and lighting using segmentation, intrinsic image decomposition (IID), and diffusion priors to minimize re-rendering loss [S9]. It uses 2DGS instead of 3DGS because 2DGS provides more accurate geometry reconstruction, which is essential for accurate material property estimation [S9]. The number of input views $N$ typically ranges from 4 to 32 [S9].

#### SAGS (Adaptive Gaussian Splatting)
SAGS utilizes an adaptive 2D low-pass filter at inferencing time based on rendering resolution and camera distance to handle aliasing [S10, unofficial].

#### GraphiGS
GraphiGS is a variant of the GraphiXS framework where the component distribution $\delta_\theta$ is modeled as a 3D Gaussian primitive, providing compact spatial support and exponential density decay [S11]. The distribution is defined as $\delta_{GS}(x; \mu, \Sigma) = \exp(-\frac{1}{2} (x - \mu)^T \Sigma^{-1} (x - \mu))$, where $\mu \in \mathbb{R}^3$ is the mean vector and $\Sigma \in \mathbb{R}^{3 \times 3}$ is the covariance matrix [S11]. GraphiGS uses Gaussian primitives which provide compact spatial support but may be limited in capturing broader uncertainty regions compared to heavy-tailed distributions [S11].

#### Gaussian Grid Layout
Gaussian Grid Layout converts a list of millions of 3D Gaussians into a 2D square grid structure to enable image-based compression [S12]. It determines the largest square grid size ($N \times N$) that can be completely filled with the current number of Gaussians and discards Gaussians with the lowest opacity values that do not fit [S12]. Removing up to 30% of Gaussians (ordered by lowest opacity) does not meaningfully alter the scene's PSNR, whereas removing Gaussians with small scaling affects quality considerably more [S12]. Unlike standard 3DGS which stores Gaussians in an unordered list or .ply file, this method organizes them into a 2D grid to leverage spatial coherence for compression [S12].

#### Local 3DGS for Relative Pose Estimation
Local 3DGS for Relative Pose Estimation estimates the relative camera pose between two adjacent frames by optimizing a rigid SE-3 transformation applied to a pre-trained set of 3D Gaussians, rather than optimizing camera parameters directly [S13]. Given a pre-trained 3D Gaussian set $G_t^*$ and the next frame $I_{t+1}$, it optimizes the transformation $T_t$ to minimize the photometric loss between the rendered image of the transformed Gaussians and the next frame [S13]. During optimization, all attributes of the pre-trained 3D Gaussian $G_t^*$ are frozen to separate camera movement from Gaussian deformation/densification [S13]. The transformation $T$ is represented by a quaternion rotation $q \in so(3)$ and a translation vector $t \in \mathbb{R}^3$ [S13]. The pose optimization step typically requires 5-10 seconds to complete [S13].

#### AM-GS Implementation Configuration
AM-GS holds the inherited object Gaussians, optimizer, loss, and direction-conditioned asymptotic-color head fixed so that only the spatial water representation and query change [S14, unofficial]. It uses a fixed lattice size $N=8$, coverage normalization, and geometric camera-ray distance for query [S14, unofficial]. It uses 2,048 water Gaussians and 12,288 RGB transport parameters [S14, unofficial]. Eighteen analytic-renderer unit tests covering diagonal rays, finite segments, anisotropic bases, culling, and transformed cameras agree with independent float64 integration within $2.90 \times 10^{-6}$ [S14, unofficial].

#### 3DGS Self-Initialization
3DGS Self-Initialization generates additional Gaussian centers by training a lightweight 3DGS model and reusing its primitive centers as a point cloud to compensate for regions with insufficient image features [S15]. It trains a lightweight first-pass 3DGS $G^{(0)}$ on downsampled images, seeded by the SfM points $P_0$, using SH degree 0 (DC color only) for economy [S15]. Training stops when densification plateaus or a small step budget is reached [S15]. It forms a colored point set $P_1$ by taking the primitive center $X_n = \mu_n$ and DC color $C_n = c_n$ for each Gaussian primitive $g_n$ [S15].

#### Mesh-adsorbed Gaussian Representation (MaGS)
Mesh-adsorbed Gaussian Representation (MaGS) is a hybrid 3D representation composed of a triangular mesh and 3D Gaussians, where Gaussians are constrained to roam near the mesh surface, combining rendering flexibility with structured mesh properties [S16, unofficial]. During reconstruction, it uses RGD-Net to model relative displacement between the mesh and Gaussians to enhance rendering fidelity under mesh constraints [S16, unofficial]. Unlike conventional anchored/fixed mesh-Gaussian methods that rigidly bind Gaussians to the mesh, MaGS allows relative displacement via RGD-Net, bypassing the trade-off between rendering accuracy and deformation rationality [S16, unofficial].

#### Dynamic Neural Motion Factorization
Dynamic Neural Motion Factorization is a motion factorization framework for real-time rendering of dynamic scenes, using a small MLP queried only by time to allow training convergence in half an hour and rendering speed of more than 120 FPS [S17]. The number of motion trajectories $B$ is the most important hyperparameter that decides in what detail the scene will be modeled [S17]. On the N3DV dataset (resolution 1280x1080), DynMF achieves 135 FPS with 40 mins training time, compared to DyNeRF (0.015 FPS, 1344 hours) and 4DGS (114 FPS, 1 hour) [S17]. DynMF uses a learned basis (small MLP) which is more expressive and smooth than Fourier Series for decoding details of complicated scenes [S17].

#### Intersection Depth
Intersection Depth is the depth of the intersection between the Gaussian and the ray emitted from the camera center, calculated by flattening the Gaussian ellipsoid into a planar shape [S18]. It applies scale regularization loss $L_s$ to squeeze the 3D Gaussian ellipsoids into highly flat shapes by constraining the minimum component of the scaling factor $s$ towards zero [S18]. The depth is calculated as $d(n, p) = r_z \cdot (n \cdot p) / (n \cdot r)$, where $r_z$ is the z-value of the ray direction $r$, $n$ is the normal, and $p$ is the position [S18].

## Operating characteristics

### Time and Memory Complexity
-   **Time Complexity:** The rasterization step is $O(N \cdot T)$, where $N$ is the number of Gaussians and $T$ is the number of tiles. Sorting and blending add overhead proportional to the number of visible Gaussians per tile.
-   **Memory Complexity:** Storage is $O(N \cdot D)$, where $D$ is the dimensionality of the Gaussian attributes (position, scale, rotation, opacity, SH coefficients). Half-precision storage reduces this by approximately 50% [S2].

### Measured Performance
-   **Hardware:** Optimized for modern GPUs (NVIDIA RTX series) using CUDA kernels [S2].
-   **Resolution:** Supports high-resolution rendering (e.g., 1080p, 4K) with real-time frame rates (60+ FPS) on standard hardware [S17].
-   **Scaling:** Performance scales linearly with the number of Gaussians, but pruning and culling mitigate this in sparse regions [S1].

### Strengths and Limitations
-   **Strengths:** Real-time rendering speeds, high visual fidelity, differentiable optimization [S1].
-   **Limitations:** High memory usage for large scenes, potential for "floaters" in sparse regions, sensitivity to initialization [S1, S15].

### When to Use and When Not to Use
-   **Use:** For high-quality novel view synthesis, real-time rendering applications, and scenes with complex geometry and appearance [S1].
-   **Do Not Use:** For scenes with extreme transparency or subsurface scattering where standard alpha blending is insufficient, or for applications with strict memory constraints where compression techniques are required [S1].

## Background

### Origin
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1]. It builds on the concept of Gaussian splatting for radiance fields, adapting it for real-time differentiable rendering.

### History and Development
The method has since been extended to handle dynamic scenes, sparse views, and various optimization techniques [S1, S3, S15]. It has become a popular alternative to NeRFs for real-time rendering applications.

### Where it is Used
