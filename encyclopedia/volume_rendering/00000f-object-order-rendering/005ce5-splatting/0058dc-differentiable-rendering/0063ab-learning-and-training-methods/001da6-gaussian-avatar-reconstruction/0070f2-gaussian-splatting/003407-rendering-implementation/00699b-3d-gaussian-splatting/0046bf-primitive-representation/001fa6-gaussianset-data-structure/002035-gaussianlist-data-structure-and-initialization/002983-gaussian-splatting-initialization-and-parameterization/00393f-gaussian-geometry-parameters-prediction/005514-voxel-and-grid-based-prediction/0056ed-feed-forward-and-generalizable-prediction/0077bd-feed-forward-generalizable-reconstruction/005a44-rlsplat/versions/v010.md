# RLSplat

Also called: Resource-Linear Budget Control for Feed-forward 3D Gaussian Splatting

## Overview
RLSplat is a resource-linear, budget-controllable feed-forward 3D Gaussian Splatting (FF3DGS) framework that ensures inference latency, peak memory, and representation size scale linearly with the requested Gaussian budget $B$ [S1, unofficial]. Unlike prior budget-controllable methods (e.g., EcoSplat, F4 Splat) that predict a dense set of candidates and prune them—resulting in nearly constant inference costs regardless of $B$—RLSplat learns a Gaussian allocation policy to distribute exactly $B$ Gaussians across scene anchors and refines them using a resource-linear decoder with local cross-attention [S1, unofficial]. It is designed for applications with strict resource constraints, such as AR/VR and robotics, where adjustable rendering quality is required without retraining [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Inputs:** A set of $V$ uncalibrated context images $\{I_i\}_{i=1}^V$ and a target integer Gaussian budget $B$.
- **Outputs:** A set of $B$ 3D Gaussians $\mathcal{G} = \{g_b\}_{b=1}^B$ and the context camera parameters $\{P_i\}_{i=1}^V$. Each Gaussian $g_b$ consists of a 3D center, opacity, scale, rotation, and color coefficients [S1, unofficial].

**Data Structures:**
1.  **Anchor Tokens:** The geometry backbone encodes context images into $N$ anchor tokens $\{a_n\}_{n=1}^N$, each representing a local 3D region [S1, unofficial].
2.  **Allocation Vector:** A discrete vector $\mathbf{k} \in \mathbb{Z}_{\ge 0}^N$ where $k_n$ is the number of Gaussians assigned to anchor $n$, such that $\sum_{n=1}^N k_n = B$ [S1, unofficial].
3.  **Gaussian Tokens:** Each anchor $n$ spawns $k_n$ Gaussian tokens. The total number of Gaussian tokens is exactly $B$ [S1, unofficial].

**Parameters:**
-   $B$: Target Gaussian budget. Typical evaluation values are 2K (2,048) and 64K [S1, unofficial]. On the ACID dataset (8 views), $B=8,192$ (1,024 per view) is used [S1, unofficial]. On RE10K, $B=8,192$ is standard [S1, unofficial].
-   $K_{gs}$: Number of nearest Gaussian neighbors each token attends to during refinement. Default ablation value is 16. This can be changed at inference without retraining [S1, unofficial].
-   $K_{anc}$: Number of anchor neighbors used in the hierarchical neighbor search. Fixed value in ablations is 16 [S1, unofficial].
-   $C$: Number of rollouts (candidate allocations) drawn per training step for the Group Sequence Policy Optimization (GSPO) [S1, unofficial].

**Algorithm Steps:**

1.  **Encoding:** The geometry backbone encodes the input images $\{I_i\}$ into $N$ anchor tokens $\{a_n\}$ and predicts camera parameters $\{P_i\}$ [S1, unofficial].
2.  **Allocation Policy:** The policy $\pi_\psi$ assesses the local significance of each anchor (based on image features like texture complexity) and predicts a discrete allocation $\mathbf{k}$ such that $\sum k_n = B$. This policy is trained using GSPO [S1, unofficial].
3.  **Spawning:** Each anchor $n$ spawns $k_n$ Gaussian tokens. The total number of Gaussian tokens is exactly $B$ [S1, unofficial].
4.  **Resource-Linear Decoding:**
    -   **Initialization:** The decoder instantiates initial Gaussian states (center, scale, rotation, opacity, color) from the Gaussian tokens [S1, unofficial].
    -   **Hierarchical Neighbor Search:** For each Gaussian token, find its $K_{gs}$ nearest Gaussian neighbors. This is done efficiently via a hierarchical neighbor search over anchor tokens (using $K_{anc}$ anchor neighbors) to identify candidate Gaussian neighborhoods [S1, unofficial].
    -   **Local Refinement:** Each Gaussian token refines its state through local cross-attention with its $K_{gs}$ nearest Gaussian neighbors [S1, unofficial]. This step ensures consistency among neighboring Gaussians [S1, unofficial].
5.  **Output:** The final set of $B$ Gaussians $\mathcal{G}$ is returned [S1, unofficial].

**Training (GSPO):**
To optimize the non-differentiable allocation policy $\pi_\psi$:
1.  Draw $C$ candidate allocations $\mathbf{k}^{(c)} \sim \pi_{\text{old}} = \text{Mult}(B, \text{sg}(p))$ for $c \in \{1, \dots, C\}$, where $p$ is the policy's probability distribution and $\text{sg}(\cdot)$ stops gradients [S1, unofficial].
2.  For each rollout $c$, generate the Gaussian representation $\mathcal{G}^{(c)}$ and render an image $\hat{I}^{(c)}$ at novel target views [S1, unofficial].
3.  Compute the reconstruction loss $\mathcal{L}_{\text{recon}}$ between $\hat{I}^{(c)}$ and ground-truth images $I$ without gradient tracking [S1, unofficial].
4.  Use $\mathcal{L}_{\text{recon}}$ as the reward signal to update the policy via reinforcement learning [S1, unofficial].
5.  Additional losses include an offset loss $\mathcal{L}_{\text{offset}}$ (for position refinement), a Voronoi loss $\mathcal{L}_{\text{vor}}$ (to keep Gaussians near their anchor cells), and a projection loss $\mathcal{L}_{\text{proj}}$ (to tie anchors to image regions). Removing $\mathcal{L}_{\text{proj}}$ causes training failure [S1, unofficial].

## Operating characteristics
-   **Time Complexity:** The decoding cost is $O(B \cdot K_{gs})$, scaling linearly with the Gaussian budget $B$, compared to global self-attention which costs $O(B^2)$ [S1, unofficial]. The hierarchical neighbor search further reduces the constant factor [S1, unofficial].
-   **Memory Complexity:** Peak memory scales linearly with $B$ [S1, unofficial].
-   **Performance:** At a budget of 2K Gaussians, RLSplat achieves higher PSNR than F4 Splat while using 9.6× less peak memory and running 4.1× faster [S1, unofficial]. On the ACID dataset ($B=8,192$), RLSplat achieves PSNR 22.84 dB, SSIM 0.643, LPIPS 0.353 [S1, unofficial]. On RE10K ($B=8,192$), RLSplat achieves full-view PSNR 26.51 dB, compared to 23.42 dB for F4 Splat and 21.82 dB for EcoSplat [S1, unofficial].
-   **Strengths:** Linear scaling of inference cost with budget; better allocation of Gaussians to high-frequency structures; no need for retraining to change $B$ (except for $K_{gs}$ which can be changed at inference) [S1, unofficial].
-   **Limitations:** Requires training of the allocation policy and decoder; hierarchical neighbor search adds complexity to implementation [S1, unofficial].
-   **When to use:** Applications requiring limited resource budgets, such as AR/VR, robotics, and digital content creation, where adjustable rendering quality is needed [S1, unofficial].

## Background
RLSplat was proposed by Bae, Park, and Kim from KAIST [S1, unofficial]. It addresses the limitations of prior budget-controllable FF3DGS methods like EcoSplat and F4 Splat, which predict dense sets of Gaussians and then prune them, resulting in nearly constant inference latency and memory regardless of the budget [S1, unofficial]. RLSplat introduces a resource-linear approach by learning a Gaussian allocation policy and using a resource-linear decoder with local cross-attention [S1, unofficial]. The method uses Group Sequence Policy Optimization (GSPO) for training the allocation policy [S1, unofficial].
