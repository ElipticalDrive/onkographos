# Fine-tuning

Also called: 3DGS Fine-tuning, Gaussian Splatting Fine-tuning

## Overview
Fine-tuning in 3D Gaussian Splatting (3DGS) refers to the phase of optimization that follows an initial initialization or pre-training step, where the geometry and color attributes of the Gaussian primitives are refined to achieve high-fidelity reconstruction [S1]. It solves the problem of initializing a sparse or redundant set of Gaussians by allowing the model to converge from a coarse approximation to a detailed representation, often leveraging pretrained priors to accelerate convergence [S1]. It sets itself apart from standard training by explicitly enabling growing and pruning operations during the optimization process to reduce memory consumption while maintaining fidelity, and it serves as the foundation for more specialized variants like stylization or inverse rendering [S1].

## How it works
The fine-tuning process typically begins with a set of 3D Gaussian primitives $\mathcal{G}$ initialized via a direct feed-forward process or from a standard SfM point cloud, where both geometry (position, scale, rotation) and color (spherical harmonic coefficients) are generated [S1]. The optimization then proceeds by minimizing a loss function, commonly the L1 color reconstruction loss combined with SSIM, using an optimizer such as Adam [S1, S2].

### Inputs and Outputs
*   **Inputs:** Initial set of 3D Gaussians $\mathcal{G}_0$ (with means $\mu$, covariances $\Sigma$, opacities $\alpha$, and SH coefficients $\mathbf{c}$), input images $I_{gt}$, and camera poses $P$.
*   **Outputs:** Optimized set of 3D Gaussians $\mathcal{G}_{final}$ with refined attributes.

### Data Structures
The Gaussian primitives are stored in a contiguous buffer or sparse structure (e.g., using `torchsparse` or `gsplat`) to allow efficient rasterization [S1]. Each Gaussian $g_k$ contains:
*   $\mu_k \in \mathbb{R}^3$: Mean position.
*   $s_k \in \mathbb{R}^3$: Scale vector.
*   $q_k \in \mathbb{R}^4$: Rotation quaternion.
*   $\alpha_k \in \mathbb{R}$: Opacity.
*   $\mathbf{c}_k \in \mathbb{R}^{C \times K}$: Spherical Harmonic coefficients (where $C$ is channels and $K$ is degree).

### Steps
1.  **Initialization:** Predict or extract an initial set of 3D Gaussian primitives. In some variants (e.g., EVolSplat), this is done via a direct feed-forward process where geometry and color are generated simultaneously [S1].
2.  **Optimization Loop:** For each iteration $t$:
    a. Render the scene using differentiable rasterization to produce image $I_{pred}$ [S1].
    b. Compute the loss $L = \mathcal{L}_{color} + \lambda_{ssim} \mathcal{L}_{SSIM}$ [S1].
    c. Compute gradients $\frac{\partial L}{\partial \theta}$ for all parameters $\theta$ (geometry and color) [S1].
    d. Update parameters using Adam optimizer with learning rate $\eta$ [S1, S2].
3.  **Densification and Pruning:** Periodically (e.g., every $N$ iterations), evaluate metrics to modify the set $\mathcal{G}$:
    a. **Growing:** Split or clone Gaussians in regions with high gradient magnitude or error [S1, Parent].
    b. **Pruning:** Remove Gaussians with low opacity $\alpha_k < \alpha_{min}$ or excessive scale [S1, Parent].
    c. This step reduces the number of redundant Gaussians, lowering memory consumption [S1].
4.  **Convergence:** Continue until the loss stabilizes or a maximum iteration count is reached [S1].

### Formulas
*   **Loss Function (Standard):**
    $$ L = \mathcal{L}_{L1}(I_{pred}, I_{gt}) + \lambda_{ssim} \mathcal{L}_{SSIM}(I_{pred}, I_{gt}) $$
    where $\mathcal{L}_{L1}$ is the L1 norm and $\mathcal{L}_{SSIM}$ is the Structural Similarity Index [S1].
*   **Adam Update:**
    $$ \theta_{t+1} = \theta_t - \eta \frac{\hat{m}_t}{\sqrt{\hat{v}_t} + \epsilon} $$
    where $\hat{m}_t$ and $\hat{v}_t$ are bias-corrected first and second moment estimates [S1, S2].

### Parameters
*   **Learning Rate ($\eta$):** Typically $1 \times 10^{-3}$ for Adam [S1].
*   **Optimizer:** Adam [S1, S2].
*   **Densification Interval:** Not explicitly given in [S1], but standard 3DGS uses 100 iterations [Parent].
*   **Opacity Threshold ($\alpha_{min}$):** Not explicitly given in [S1], but standard 3DGS uses $0.005$ [Parent].

### Edge Cases and Pitfalls
*   **Redundancy:** Initial feed-forward Gaussians may be redundant; fine-tuning must aggressively prune them to avoid memory bloat [S1].
*   **Overfitting:** Without proper regularization or pruning, the model may overfit to input views, especially in sparse input scenarios [Parent, S1].
*   **Precision:** Using 3D sparse convolution libraries (e.g., `torchsparse`) helps manage memory but requires careful handling of sparse tensor formats [S1].

## Subtopics

### Two-stage Optimization
A fine-tuning variant used in inverse rendering (e.g., GS-IR) that separates geometric/appearance optimization from material decomposition [S2]. It solves the problem of jointly optimizing complex material properties by decoupling them into two stages. It sets itself apart by fixing geometry and appearance in the second stage to focus solely on material parameters [S2].
*   **Stage 1 (Initial):** Minimize color reconstruction loss $L_c$ and normal loss $L_n$ to optimize geometry $T$ and appearance $A$ for 30,000 iterations [S2].
*   **Stage 2 (Decomposition):** Fix $T$ and $A$, then minimize decomposition loss $L_d$ to optimize material $M$ for 10,000 iterations [S2].
*   **Parameters:** Adam optimizer, single NVIDIA V100 GPU, smoothing weights $\lambda_{n-TV}=5.0$, $\lambda_M=1.0$, $\lambda_E=0.01$ [S2].

### StylizedGS
A fine-tuning method for controllable 3D stylization that performs color matching with a style image and uses a 3DGS filter to remove artifacts [S3]. It solves the problem of applying artistic styles to 3D scenes while maintaining geometric consistency. It sets itself apart by employing a nearest neighbor feature match loss and a depth preservation loss for optimization [S3].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of Gaussians and iterations, but densification adds overhead proportional to the number of splits/clones [Parent].
*   **Memory Complexity:** Proportional to the number of active Gaussians; fine-tuning with pruning reduces this compared to raw initialization [S1].
*   **Performance:** Fine-tuning with pretrained priors accelerates convergence compared to training from scratch [S1].
*   **Strengths:** High fidelity, memory efficiency via pruning, flexibility for various tasks (stylization, inverse rendering) [S1, S2, S3].
*   **Limitations:** Requires careful tuning of densification and pruning thresholds; may overfit to input views if not regularized [Parent, S1].
*   **When to use:** When high-fidelity reconstruction is needed from sparse or noisy inputs, or when adapting a pretrained model to a specific scene [S1].
*   **When not to use:** When real-time inference speed is critical and memory is extremely constrained without pruning, or when the input data is insufficient for reliable initialization [S1].

## Background
Fine-tuning in 3D Gaussian Splatting emerged as a refinement of the original 3DGS method to address issues of redundancy and convergence speed. The concept of using pretrained priors and feed-forward initialization for fine-tuning was introduced in EVolSplat [S1]. Variants like GS-IR [S2] and StylizedGS [S3] extended this to inverse rendering and stylization, respectively. The method builds on the densification and pruning strategies of the original 3DGS [Parent].
