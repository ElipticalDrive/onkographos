# Mini-Splatting-C

Also called: Ours+PP, Post-processed Compact 3D Gaussian

## Overview
Mini-Splatting-C is a storage-compression variant of the Mini-Splatting representation designed for scenarios requiring minimal model size [S1, S2]. It addresses the problem of high storage overhead in 3D Gaussian Splatting by applying post-processing compression techniques to the attributes of a pre-trained Mini-Splatting model [S1, S2]. Unlike its sibling [Hybrid Compression Framework](15040-hybrid-compression-framework.md) which may involve different architectural decouplings, or [Prune2TargetSize](15817-prune2targetsize.md) which focuses on iterative pruning targets, Mini-Splatting-C relies on the optimized and simplified Gaussian representation of Mini-Splatting combined with standard lossless/lossy coding techniques [S1, S2]. It sets itself apart by achieving significantly smaller file sizes (e.g., 0.04x of standard 3DGS) while maintaining competitive rendering quality, primarily through transform coding and quantization of non-position attributes [S1, S2].

## How it works
**Inputs and Outputs:**
*   **Input:** A pre-trained Mini-Splatting model consisting of 3D Gaussian parameters: centers ($\mathbf{c}$), scales ($\mathbf{s}$), rotations ($\mathbf{q}$), opacities ($\alpha$), spherical harmonic (SH) coefficients ($\mathbf{c}_{SH}$), and potentially hash grid parameters if using a neural field variant [S1, S2].
*   **Output:** A compressed binary file containing the encoded attributes [S1, S2].

**Data Structures and Layout:**
The method does not alter the logical structure of the Gaussian attributes but changes their storage precision and encoding.
1.  **Centers:** Stored as `float32` (32-bit floating point) [S1].
2.  **Other Attributes (Scales, SH, Opacity, Hash Parameters):** Processed via transform coding and quantization [S1, S2].
3.  **Encoding:** The result is compressed using standard zip compression [S1] or specific entropy coding like Huffman encoding [S2].

**Steps:**
1.  **Train Pre-trained Model:** Obtain a trained Mini-Splatting model [S1].
2.  **Store Centers:** Encode Gaussian centers as `float32` values [S1].
3.  **Transform Coding:** Apply transform coding to non-center attributes (scales, SH coefficients) [S1]. Note: [S2] specifies applying 8-bit min-max quantization to opacity and hash grid parameters instead of or in addition to transform coding for those specific attributes.
4.  **Pruning (Optional/Variant):** In the "Ours+PP" variant, prune hash grid parameters with values below a threshold (e.g., 0.1) [S2].
5.  **Quantization:** Apply 8-bit min-max quantization to opacity and hash grid parameters [S2].
6.  **Entropy Coding:** Apply Huffman encoding to the quantized opacity, hash parameters, and Residual Vector Quantization (R-VQ) indices [S2].
7.  **Final Compression:** Apply standard zip compression to the resulting bitstream [S1].

**Formulas and Parameters:**
*   **Min-Max Quantization:** For an attribute value $x$ with min $x_{min}$ and max $x_{max}$, the quantized value $q$ is:
    $$ q = \text{clip}\left( \text{round}\left( \frac{x - x_{min}}{x_{max} - x_{min}} \times 255 \right), 0, 255 \right) $$
    [S2]
*   **Pruning Threshold:** Hash grid parameters $h$ are removed if $|h| < 0.1$ [S2].
*   **Precision:** Centers are `float32`; Opacity/Hash are `uint8` (8-bit) [S1, S2].

def min_max_quantize(values, bits=8):
    """Quantize float array to uint8 using min-max scaling."""
    min_val = np.min(values)
    max_val = np.max(values)
    if max_val == min_val:
        return np.zeros_like(values, dtype=np.uint8)
    normalized = (values - min_val) / (max_val - min_val)
    quantized = np.clip(np.round(normalized * (2**bits - 1)), 0, 2**bits - 1)
    return quantized.astype(np.uint8)

## Subtopics

### [Feed-Forward 3DGS Compression](19101-feed-forward-3dgs-compression.md)
Feed-Forward 3DGS Compression (FCGS) is a post-training compression method that reduces the storage size of 3D Gaussian Splatting (3DGS) models generated by feed-forward reconstruction networks without requiring retraining or optimization. Unlike Mini-Splatting-C which is based on the Mini-Splatting architecture, FCGS applies a learned entropy model directly to the existing Gaussian attributes, enabling zero-shot generalization to scenes where ground-truth geometry is unavailable. It sets itself apart by handling the irregular data structures of feed-forward outputs (e.g., from LGM or MVSplat) where traditional mesh-based or optimization-based codecs fail due to the lack of a consistent reference.

### MesonGS
MesonGS employs universal Gaussian pruning by evaluating the importance of Gaussians through forward propagation, considering both view-dependent and view-independent features [S3]. It transforms rotation quaternions into Euler angles to reduce storage requirements and applies region adaptive hierarchical transform (RAHT) to reduce entropy in key attributes [S3]. Block quantization is performed on attribute channels by dividing them into multiple blocks and performing quantization for each block individually, using vector quantization for compressing less important attributes [S3]. Geometry is compressed using an octree, and all elements are packed with the LZ77 codec [S3]. A finetune scheme is implemented post-training to restore quality [S3].

### Model Compression (Post-processing)
This variant refers to a post-processing compression pipeline applied to the HyRF representation to reduce model size while maintaining rendering quality, compatible with existing 3DGS compression approaches [S4]. It stores point positions as half-precision tensors, applies residual vector quantization (R-VQ) and Huffman encoding to explicit Gaussian properties, and employs Huffman encoding with 8-bit min-max quantization for the hash table [S4]. It outperforms five state-of-the-art 3DGS compression methods in both model size and rendering quality, maintaining superior visual fidelity even after aggressive compression where conventional methods sacrifice quality for storage efficiency [S4].

## Operating characteristics
*   **Storage Size:** Mini-Splatting-C (Ours+PP) achieves 2.67 MB storage on the NeRF-Synthetic dataset, which is 0.04x the size of standard 3DGS [S2]. The base Mini-Splatting model (Ours) is 5.55 MB (0.08x) [S2].
*   **Rendering Quality:** On NeRF-Synthetic, Ours+PP achieves 32.88 PSNR, a slight drop from the base Ours' 33.33 PSNR [S2].
*   **Performance:** Rendering speed is 545 FPS on the tested hardware, which is 1.52x faster than the base Ours (359 FPS) [S2].
*   **Training Time:** The post-processing step adds minimal overhead; Ours+PP training time is 8m 04s vs 6m 14s for Ours [S2].
*   **Strengths:** Extremely low storage footprint; fast rendering due to reduced data size; compatible with standard compression tools (zip, Huffman) [S1, S2].
*   **Limitations:** Slight reduction in PSNR compared to uncompressed Mini-Splatting; relies on the quality of the pre-trained Mini-Splatting model [S1, S2].
*   **When to Use:** When storage bandwidth or disk space is the primary constraint, and a slight quality trade-off is acceptable [S1].
*   **When Not to Use:** When maximum possible visual fidelity is required without any compression artifacts [S1].

## Background
Mini-Splatting-C was introduced as part of the Mini-Splatting framework, which aims to represent scenes with a constrained number of Gaussians [S1]. The "C" variant specifically targets storage compression scenarios [S1]. It builds on the Mini-Splatting representation, which itself is a variant of 3D Gaussian Splatting [S1]. The post-processing techniques (transform coding, quantization) are adapted from general image/video compression standards [S1, S2]. The method demonstrates superior performance compared to other methods primarily tailored for storage compression applied to standard 3DGS [S1].
