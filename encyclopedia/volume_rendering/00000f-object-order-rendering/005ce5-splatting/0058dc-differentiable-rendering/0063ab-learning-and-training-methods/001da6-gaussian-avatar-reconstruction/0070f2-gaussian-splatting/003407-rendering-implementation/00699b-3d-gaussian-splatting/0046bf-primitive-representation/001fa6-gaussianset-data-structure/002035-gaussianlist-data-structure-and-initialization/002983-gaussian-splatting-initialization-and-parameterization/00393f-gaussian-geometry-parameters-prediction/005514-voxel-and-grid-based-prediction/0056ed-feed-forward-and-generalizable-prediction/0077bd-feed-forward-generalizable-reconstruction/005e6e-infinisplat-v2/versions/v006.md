# InfiniSplat v2

Also called: InfiniSplat

## Overview
InfiniSplat v2 is a feed-forward Gaussian reconstruction method for arbitrary input views that decouples geometry and attribute prediction, uses ground-truth (GT) camera poses for alignment during training, and employs large-angle target view supervision to improve rendering quality under large viewpoint changes [S1, unofficial]. It differs from its parent [Feed-forward Generalizable Reconstruction](23266-feed-forward-generalizable-reconstruction.md) and siblings like [AnySplat Pipeline](12847-anysplat-pipeline.md) and [Splatt3R](16423-splatt3r.md) by freezing the geometry branch to prevent geometric degradation caused by joint optimization, and by using GT poses to avoid pose errors that misguide the network under large-angle supervision [S1, unofficial].

## How it works
**Inputs and Outputs:**
The method takes $N$ input RGB images $I_C = \{I_i\}_{i \in C}$ and optional pose conditions $Q_C$ (camera intrinsics and poses). In the pose-free setting, $Q_C = \emptyset$ [S1, unofficial]. The output is a Gaussian scene $G = \{(\mu_m, \xi_m)\}_{m=1}^M$, where $\mu_m \in \mathbb{R}^3$ is the center and $\xi_m = (\alpha_m, s_m, q_m, c_m)$ contains opacity, three-axis scale, rotation, and zeroth-order spherical-harmonic (SH) color [S1, unofficial]. The renderer produces image $I_b$ from scene $G$ and camera $\Pi = (K, P)$ [S1, unofficial].

**Data Structures:**
The scene is represented as a set of $M$ Gaussians. Each Gaussian $m$ has attributes $\xi_m$. The geometry branch outputs predicted cameras $\hat{\Pi}_C$ and depths $\hat{C}$ via frozen network $\Phi_{geo}$. The attribute branch outputs features $F_C$ via trainable network $\Phi_{attr}$ [S1, unofficial].

**Parameters:**
- Voxel merging side length: 0.004 in scale-normalized reconstruction frame [S1, unofficial].
- Opacity pruning threshold $\tau_\alpha$: 0.01 [S1, unofficial].
- `gsplat` `eps2d`: $10^{-2}$ [S1, unofficial].
- Mask thresholds: $\tau_{abs} = 0.03$, $\tau_{rel} = 0.01$ [S1, unofficial].
- Stage I learning rates: $10^{-6}$ for last ten attribute-backbone Transformer blocks, $2 \times 10^{-4}$ for Gaussian head [S1, unofficial].
- Stage I training steps: 25,000 steps, 2,000 steps linear warmup, cosine decay to 0.1 times peaks [S1, unofficial].
- Stage II learning rate: $2 \times 10^{-4}$, cosine decay to 0.1 times initial value, 5,000 steps [S1, unofficial].
- AdamW parameters: $\beta = (0.9, 0.95)$, global batch size 16, global L2 gradient clipping at 1.0 [S1, unofficial].

**Steps:**

1.  **Dual-Branch Initialization:** Initialize both geometry and attribute branches from the same pretrained DA3 weights (DA3NESTED-GIANT-LARGE1.1) [S1, unofficial]. The geometry branch $\Phi_{geo}$ is frozen; the attribute branch $\Phi_{attr}$ has only its last $K$ Transformer blocks fine-tuned [S1, unofficial].
2.  **Geometry Prediction:** Compute predicted depths $\hat{C}$ and cameras $\hat{\Pi}_C$ using $\Phi_{geo}(I_C; Q_C)$ [S1, unofficial].
3.  **Attribute Feature Extraction:** Compute multi-layer patch features $F_C$ using $\Phi_{attr}(I_C; Q_C)$ [S1, unofficial].
4.  **Scale Alignment:**
    - Express predicted and GT poses relative to their respective reference cameras (first input view in sorted order) [S1, unofficial].
    - Normalize predicted depths and translations by $s_{norm} > 0$ [S1, unofficial].
    - Fit an Umeyama similarity transform from the GT trajectory to the normalized predicted trajectory using only input-camera center correspondences, retaining its scale $s_C$ [S1, unofficial].
    - Apply scale to translations: $t^\star_v = s_C t^\star_v$, while rotations remain unchanged: $R^\star_v = R^\star_v$ [S1, unofficial].
5.  **Gaussian Center Construction:** Construct Gaussian centers from normalized predicted $z$-depth, GT intrinsics, and scale-aligned GT poses [S1, unofficial].
6.  **Attribute Prediction (Stage I):** Use a DPT decoder to map $F_C$ to per-pixel attributes $\xi$. Perform voxel merging with side length 0.004. Prune Gaussians with opacity $\alpha_m < \tau_\alpha = 0.01$ [S1, unofficial].
7.  **Stage I Rendering:** Render initial scene $G_0$ into input and target views $v \in V = C \cup T$: $I_{bv} = R(G_0; \Pi^\star_v)$ [S1, unofficial].
8.  **Visibility Mask Construction:** Construct visibility masks $M_v$. A target pixel is retained if it has finite GT depth $> 10^{-6}$, passes validity mask, and satisfies $|z_{proj} - d_{src}| \le \max(\tau_{abs}, \tau_{rel} d_{src})$ where $z_{proj}$ is point depth in input camera, $d_{src}$ is sampled depth, $\tau_{abs}=0.03$, $\tau_{rel}=0.01$ [S1, unofficial].
9.  **Stage I Loss:** Compute LPIPS spatial distance map $d_v = \text{LPIPS}_{\text{spatial}}(M_v \odot \hat{I}_v, M_v \odot I_v)$, with invalid regions zeroed before normalization. Aggregate losses $L_1$ and $L_{\text{LPIPS}}$ over valid pixels [S1, unofficial].
10. **Stage II Feature Projection:** Project DPT features to 8 channels by learnable $1 \times 1$ conv, merge using Gaussian voxel groups/weights, and reuse. Initialize 16-dim hidden state [S1, unofficial].
11. **Stage II Refinement (Iterative):**
    - Concatenate image features, current attributes, gradient feedback, neighbor distances, and hidden states. Project to 64 dims [S1, unofficial].
    - Process by four KNN Transformer blocks. Each block contains single-head attention over eight neighbors, LayerNorm, MLP, and residual connections. Output is concatenated with original input, and MLP predicts attribute and hidden-state increments [S1, unofficial].
    - **Feedback Loss:** $\ell_{fb} = 0.8 L_1 + 0.2 L_{\text{DSSIM}}$, where $L_{\text{DSSIM}} = (1 - \text{SSIM})/2$ computed over valid regions [S1, unofficial].
    - **Gradient Handling:** Gradients w.r.t Gaussian attributes are normalized and detached before entering shared updater. Gaussian centers, counts, and correspondence remain fixed [S1, unofficial].
    - **Attribute Updates:**
        - Scales: $s_{\text{new}} = s_{\text{old}} \exp(\Delta \log s)$ without residual clipping [S1, unofficial].
        - Opacity-logit, local rotation-vector, and RGB-logit increments use elementwise $a \tanh(\text{raw})$ with $a=0.1, 0.25, 1.0$ respectively [S1, unofficial].
        - Hidden-state increments use $0.1 \tanh(\text{raw})$ [S1, unofficial].
        - Logit inputs clamped to $[10^{-6}, 1-10^{-6}]$ [S1, unofficial].
    - **Surrogate Loss:** Let $x_k$ collect updated parameters. Rendering gradients computed on independent leaf copies $z_k = \text{sg}(x_k)$ to form $r_k = \text{sg}(\nabla_z L_{\text{render}}(z_k))$. Proxy loss $L_{k\text{proxy}} = \text{sg}(L_{\text{render}}(z_k)) + \langle x_k - \text{sg}(x_k), r_k \rangle$ [S1, unofficial].
    - **Multi-step Objective:** $L_{II} = \sum_{k=1}^{K_r} 0.9^{K_r-k} L_{k\text{render}} + 0.1 L_{\text{opacity}}$ [S1, unofficial].
    - **Opacity Regularization:** $L_{\text{opacity}} = \frac{1}{M} \sum_{m=1}^M [\text{logit}_\epsilon(\alpha_{m, K_r}) - \text{logit}_\epsilon(\alpha_{m, 0})]^2$, where $\epsilon=10^{-6}$ [S1, unofficial].
    - **Chunked Execution:** Global KNN graph reused. After stable sorting along longest voxel-coordinate axis, core sets of at most 200,000 points are expanded with four-hop neighborhoods. Chunks exceeding 300,000 points are recursively bisected by point count along core sets' longest axes, with neighborhoods recomputed. Only core-point outputs retained; training uses gradient checkpointing [S1, unofficial].
    - **Sampling:** Sample $K_r$ uniformly from $\{1, 2, 3\}$ updates during training, using three updates at inference [S1, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
The method uses chunked execution to manage memory. Core sets of at most 200,000 points are expanded with four-hop neighborhoods. Chunks exceeding 300,000 points are recursively bisected. Training uses gradient checkpointing [S1, unofficial].

**Measured Performance:**
In the pose-conditioned setting, mean LPIPS and DISTS decrease by 25.8% and 32.9%, respectively, compared with the strongest evaluated baselines across six datasets [S1, unofficial].

**Strengths and Limitations:**
- **Strengths:** Decoupling geometry and attribute prediction prevents geometric degradation. Using GT poses avoids pose errors under large-angle supervision. Large-angle target view supervision improves rendering quality under large viewpoint changes. Opacity learned with only image reconstruction supervision suppresses geometrically inconsistent points (outliers) [S1, unofficial].
- **Limitations:** Jointly optimizing geometry and Gaussian attributes leads to geometric degradation and flying-point artifacts in prior methods [S1, unofficial]. Using predicted camera poses during training introduces pose errors that misguide the network under large-angle supervision [S1, unofficial].

**When to Use:**
Use InfiniSplat v2 when high-quality novel view rendering under large viewpoint changes is required, especially in pose-conditioned or pose-free settings where ground-truth poses are available for training alignment [S1, unofficial].

## Background
InfiniSplat v2 was introduced by Lin et al. in 2025/2026 as an improvement over DA3-GS and InfiniSplat [S1, unofficial]. It builds on Depth Anything 3 (DA3) and addresses limitations in Gaussian attribute learning by freezing the geometry branch, using GT camera poses for alignment, and adopting large-angle target view supervision [S1, unofficial].
