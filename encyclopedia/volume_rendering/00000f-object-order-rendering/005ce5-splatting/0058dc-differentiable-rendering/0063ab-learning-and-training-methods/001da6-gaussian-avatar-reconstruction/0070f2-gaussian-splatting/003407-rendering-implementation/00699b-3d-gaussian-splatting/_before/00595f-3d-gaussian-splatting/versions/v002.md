# 3D Gaussian Splatting

Also called: 3DGS

## Overview
3D Gaussian Splatting (3DGS) is a novel view synthesis method that represents a scene as a set of anisotropic 3D Gaussians, combining the volumetric representation of Neural Radiance Fields (NeRF) with the rendering speed of point-based techniques [S1, unofficial]. It solves the high computational cost and slow training times of continuous MLP-based NeRFs by enabling real-time rendering (>30fps) and short training times (minutes) through projected alpha blending [S1, unofficial]. Unlike NeRF, which uses ray marching and continuous density fields, 3DGS uses explicit Gaussian primitives and tile-based sorting, allowing it to handle millions of primitives without real-time performance loss [S1, unofficial].

## How it works
**Inputs:** A set of images of a scene from various angles, along with camera parameters (intrinsics like focal length, and extrinsics like position/orientation) estimated via Structure-from-Motion (SfM) [S1, unofficial]. Optionally, a sparse SfM point cloud is used for initial Gaussian placement [S1, unofficial].

**Outputs:** A rendered image for a given camera pose, and a set of optimized 3D Gaussian parameters [S1, unofficial].

**Data Structures:**
The scene is represented as a list of $N$ Gaussians. Each Gaussian $i$ has the following parameters:
*   **Position:** $\mu_i \in \mathbb{R}^3$ [S1, unofficial].
*   **Shape:** Defined by a scale $s_i \in \mathbb{R}^3$ and a rotation $q_i \in \mathbb{R}^4$ (quaternion), totaling 7 dimensions [S1, unofficial]. These define the covariance matrix $\Sigma_i$ [S1, unofficial].
*   **Opacity:** $\alpha_i \in \mathbb{R}$ [S1, unofficial].
*   **Color:** Spherical Harmonics (SH) coefficients $c_i$. For 4 bands and RGB, this is approximately 48 dimensions [S1, unofficial].
*   **Total Parameters:** Typically 30-60 parameters per Gaussian [S1, unofficial].

**Rendering Steps:**
1.  **Projection:** Project each 3D Gaussian onto the 2D image plane using the camera parameters [S1, unofficial].
2.  **Sorting:** Sort Gaussians by depth (Z-sort) per tile (e.g., 16x16 pixels) using Radix sort [S1, unofficial].
3.  **Rasterization/Blending:** For each pixel, iterate through the sorted Gaussians covering that pixel. Perform alpha blending from front to back to compute the final color [S1, unofficial].
4.  **Color Evaluation:** Evaluate the SH coefficients based on the view direction to determine the view-dependent color for each Gaussian [S1, unofficial].

**Training Steps:**
1.  **Initialization:** Place Gaussians using the sparse SfM point cloud to stabilize convergence [S1, unofficial].
2.  **Rendering:** Render the current scene estimate [S1, unofficial].
3.  **Loss Calculation:** Compute the loss between the rendered image and the ground truth image using a combination of L1 loss and D-SSIM [S1, unofficial].
4.  **Optimization:** Compute gradients (e.g., using Adam) and update Gaussian parameters (position, rotation, scale, opacity, color) in a batch [S1, unofficial].
5.  **Adaptive Density Control:** Iteratively adjust the number of Gaussians:
    *   **Clone:** Duplicate Gaussians in regions with high error to capture fine details [S1, unofficial].
    *   **Split:** Divide large Gaussians into smaller ones for higher precision [S1, unofficial].
    *   **Prune:** Delete Gaussians with low opacity or those that are not contributing to the image [S1, unofficial].
6.  **Repeat:** Steps 2-5 are repeated for thousands to tens of thousands of iterations [S1, unofficial].

**Pseudocode:**

```python
import math

def render_gaussians(gaussians, camera, image_width, image_height, tile_size=16):
    """
    Renders an image from a set of 3D Gaussians.
    
    Args:
        gaussians: List of Gaussian objects with attributes:
                   - mu: (3,) position
                   - scale: (3,) scale
                   - rot: (4,) quaternion
                   - alpha: float opacity
                   - sh_coeffs: (num_bands * 3,) SH coefficients
        camera: Camera object with attributes:
                - K: (3,3) intrinsic matrix
                - R: (3,3) rotation matrix
                - T: (3,) translation vector
        image_width, image_height: int
        tile_size: int, size of tiles for sorting (default 16)
        
    Returns:
        image: (image_height, image_width, 3) rendered RGB image
    """
    # Initialize output image
    image = np.zeros((image_height, image_width, 3))
    
    # 1. Project Gaussians to 2D
    projected_gaussians = []
    for g in gaussians:
        # Transform Gaussian center to camera space
        center_cam = camera.R @ g.mu + camera.T
        
        # Compute 2D covariance matrix in screen space
        # J is the Jacobian of the projection, W is the view rotation
        # Sigma_2d = J * W * Sigma_3d * W^T * J^T
        # Sigma_3d is derived from scale and rot
        # This step involves matrix operations to get 2D covariance (2x2)
        cov_2d = compute_2d_covariance(g, camera)
        
        # Project center to pixel coordinates
        uv = project_to_pixel(center_cam, camera.K)
        
        # Check if Gaussian is within image bounds (with some margin)
        if is_within_bounds(uv, image_width, image_height, cov_2d):
            projected_gaussians.append({
                'uv': uv,
                'cov_2d': cov_2d,
                'alpha': g.alpha,
                'sh_coeffs': g.sh_coeffs,
                'depth': center_cam[2] # Z-depth
            })
            
    # 2. Sort Gaussians by depth per tile
    # Create tiles
    num_tiles_x = math.ceil(image_width / tile_size)
    num_tiles_y = math.ceil(image_height / tile_size)
    
    # Initialize tile lists
    tiles = [[[] for _ in range(num_tiles_x)] for _ in range(num_tiles_y)]
    
    for pg in projected_gaussians:
        tx = int(pg['uv'][0] / tile_size)
        ty = int(pg['uv'][1] / tile_size)
        if 0 <= tx < num_tiles_x and 0 <= ty < num_tiles_y:
            tiles[ty][tx].append(pg)
            
    # Sort each tile by depth (Radix sort is efficient for this)
    for ty in range(num_tiles_y):
        for tx in range(num_tiles_x):
            tiles[ty][tx].sort(key=lambda x: x['depth'])
            
    # 3. Alpha blending per pixel
    for ty in range(num_tiles_y):
        for tx in range(num_tiles_x):
            tile_gaussians = tiles[ty][tx]
            
            # Determine pixel range for this tile
            y_start = ty * tile_size
            y_end = min((ty + 1) * tile_size, image_height)
            x_start = tx * tile_size
            x_end = min((tx + 1) * tile_size, image_width)
            
            for y in range(y_start, y_end):
                for x in range(x_start, x_end):
                    # Initialize accumulated color and opacity
                    acc_color = np.zeros(3)
                    acc_alpha = 0.0
                    
                    for pg in tile_gaussians:
                        # Check if pixel (x,y) is covered by this Gaussian
                        # Compute Mahalanobis distance
                        dist_sq = mahalanobis_distance((x, y), pg['uv'], pg['cov_2d'])
                        
                        # Compute alpha contribution
                        # alpha_g = exp(-0.5 * dist_sq)
                        alpha_g = math.exp(-0.5 * dist_sq)
                        
                        # Apply Gaussian's opacity
                        alpha_g *= pg['alpha']
                        
                        if alpha_g < 1e-5: # Skip negligible contributions
                            continue
                            
                        # Evaluate SH color for view direction
                        # View direction is from camera center to pixel
                        view_dir = compute_view_direction(x, y, camera)
                        color = evaluate_sh(pg['sh_coeffs'], view_dir)
                        
                        # Alpha blending
                        # C = C_prev * (1 - alpha_g) + color * alpha_g
                        # A = A_prev + alpha_g * (1 - A_prev)
                        weight = alpha_g * (1.0 - acc_alpha)
                        acc_color += color * weight
                        acc_alpha += weight
                        
                        if acc_alpha > 0.99: # Early exit if fully opaque
                            break
                            
                    # Write to image
                    image[y, x] = acc_color
                    
    return image

    """
    Clones, splits, and prunes Gaussians based on error and size.
    """
    # Prune: Remove Gaussians with low opacity
    gaussians = [g for g in gaussians if g.alpha > 0.005]
```

**Parameters:**
*   **Number of Gaussians:** Tens of thousands to millions for complex outdoor scenes [S1, unofficial].
*   **SH Bands:** Typically 4 bands for RGB, resulting in ~48 color parameters per Gaussian [S1, unofficial].
*   **Tile Size:** Commonly 16x16 pixels for sorting [S1, unofficial].
*   **Learning Rate:** Typically uses Adam optimizer [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Initialization:** Random initialization leads to unstable convergence. Using a sparse SfM point cloud for initial placement is recommended [S1, unofficial].
*   **Memory Usage:** Complex scenes require millions of Gaussians, increasing memory usage. Tile-based parallel sorting and software rasterization are used to handle this [S1, unofficial].
*   **Generalization:** The method is scene-specific and does not generalize to unknown scenes without re-training [S1, unofficial].
*   **Artifacts:** Artifacts may appear in out-of-domain views (unobserved regions) [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Training time is several minutes to tens of minutes for high quality, comparable to InstantNGP speed [S1, unofficial].
*   **Memory Complexity:** Memory usage scales with the number of Gaussians. Complex scenes can require millions of Gaussians, leading to high memory consumption [S1, unofficial].
*   **Rendering Performance:** Real-time rendering (>30fps) at 1080p resolution with millions of Gaussians is achievable [S1, unofficial].
*   **Strengths:** Real-time rendering, short training times, high quality comparable to Mip-NeRF360 [S1, unofficial].
*   **Limitations:** Scene-specific (no generalization), high memory usage for complex scenes, artifacts in unobserved regions [S1, unofficial].
*   **When to use:** When real-time rendering and fast training are required for a specific scene.
*   **When not to use:** When generalization to unknown scenes is needed, or when memory is extremely constrained.

## Background
3D Gaussian Splatting was introduced as a novel approach to novel view synthesis, combining the volumetric representation of NeRF with the speed of point-based rendering [S1, unofficial]. It addresses the limitations of NeRF, such as slow training and rendering, by using explicit 3D Gaussians and efficient rasterization techniques [S1, unofficial]. The method has gained significant attention for its ability to achieve high-quality results with real-time performance [S1, unofficial].
