# 3D Gaussian Splatting with Transformer-based Parameterization

Also called: GS-LRM

## Overview
This method enables feed-forward 3D Gaussian Splatting (3DGS) reconstruction by replacing iterative optimization with a transformer-based decoder that directly predicts Gaussian parameters from input images [S1]. It solves the computational bottleneck of training-based reconstruction by tokenizing multi-view inputs and regressing scene attributes in a single forward pass [S1]. Unlike iterative optimization methods, it offers immediate inference but may suffer from lower fidelity in complex scenes compared to optimized baselines [S1].

## How it works
**Inputs:** A set of $N$ input images (typically $N=2$ to $4$) and their corresponding camera parameters (extrinsics and intrinsics) [S1].
**Outputs:** A set of 3D Gaussians defined by position, covariance (scale/rotation), opacity, and spherical harmonic coefficients for color [S1].

**Data Structures:**
1.  **Image Tokens:** Each input image is processed into a sequence of visual tokens.
2.  **Camera Tokens:** Camera parameters are encoded into token embeddings.
3.  **Scene Tokens:** The concatenated sequence of image and camera tokens is processed by a transformer encoder to produce output scene tokens [S1].
4.  **Gaussian Parameters:** A decoder maps each scene token to a set of Gaussian attributes [S1].

**Steps:**
1.  **Tokenization:** Concatenate the visual tokens from the input images with the camera parameter tokens [S1].
2.  **Transformer Encoding:** Pass the concatenated token sequence through a transformer block [S1]. The output is a set of scene tokens representing the global scene context [S1].
3.  **Decoding:** Decode the scene tokens into Gaussian parameters. The specific decoding mechanism maps tokens to Gaussian attributes (position, scale, rotation, opacity, color) [S1].
4.  **Rendering:** Render the predicted Gaussians using standard differentiable rasterization [S1].

**Formulas:**
Let $I_i$ be the $i$-th input image and $C_i$ be its camera parameters.
The input sequence $T$ is formed by concatenating image tokens $V_i$ and camera tokens $K_i$:
$$ T = [V_1, K_1, V_2, K_2, \dots, V_N, K_N] $$
The transformer encoder $E$ processes $T$:
$$ T_{out} = E(T) $$
The decoder $D$ maps each token $t_j \in T_{out}$ to a set of Gaussians $G_j$:
$$ G_j = D(t_j) $$
The final rendered image is computed by rasterizing the union of all $G_j$ [S1].

**Parameters:**
-   Number of input images: Typically 2 to 4 [S1].
-   Transformer depth/width: Not given in the sources.

**Edge Cases and Pitfalls:**
-   **Scale Ambiguity:** If camera intrinsics are not properly encoded, scale ambiguity may occur [S1].
-   **View Overlap:** Performance degrades with minimal view overlap [S1].

## Operating characteristics
-   **Time Complexity:** $O(1)$ inference time relative to optimization steps, as it is a feed-forward method [S1].
-   **Memory Complexity:** Depends on the transformer size and number of Gaussians [S1].
-   **Strengths:** Fast inference, no training required per scene [S1].
-   **Limitations:** May produce lower quality than optimized methods, sensitive to camera pose accuracy [S1].

## Background
This method is part of the family of feed-forward 3D Gaussian Splatting approaches, building on earlier work like MVSplat and NoPoSplat [S1]. It was introduced to address the limitations of iterative optimization by providing a direct mapping from images to Gaussians [S1].
