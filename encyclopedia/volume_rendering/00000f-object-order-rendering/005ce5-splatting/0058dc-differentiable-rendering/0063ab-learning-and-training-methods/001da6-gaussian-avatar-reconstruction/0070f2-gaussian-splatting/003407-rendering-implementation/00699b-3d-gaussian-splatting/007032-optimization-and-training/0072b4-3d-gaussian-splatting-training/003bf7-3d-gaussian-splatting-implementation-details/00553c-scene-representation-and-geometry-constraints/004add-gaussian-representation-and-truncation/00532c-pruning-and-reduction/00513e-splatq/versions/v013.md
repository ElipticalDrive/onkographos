# SplatQ

Also called: SplatQ: Post-training Gaussian pruning via QUBO

## Overview
SplatQ is a post-training pruning framework for 3D Gaussian Splatting (3DGS) that addresses spatial quality imbalance and ignores joint deletion effects inherent in global Top-K selection methods [S1, unofficial]. It partitions Gaussians into size-limited blocks based on spatial and appearance similarity, allocates retention quotas to balance regional budgets, and uses a Quadratic Unconstrained Binary Optimization (QUBO) model to jointly select Gaussians within each block under a fixed global count [S1, unofficial].

## How it works
**Inputs and outputs:**
- Input: A pretrained 3DGS model with $N$ Gaussians $\mathcal{G} = \{G_i\}_{i=1}^N$ and a target retention count $K$.
- Output: A pruned set of $K$ Gaussians with optimized attributes.

**Data structures:**
- Gaussian $G_i$: Center $\mu_i$, scale $s_i$, rotation quaternion $r_i$, zeroth-order SH coefficients $c_i$, higher-order SH coefficients $h_i$, opacity $o_i$ [S1, unofficial].
- Blocks $\mathcal{C}_b$: A partition of $\mathcal{G}$ into disjoint sets, each with size $|\mathcal{C}_b| \le M$ [S1, unofficial].
- Response Matrix $R_b$: For block $b$, a matrix estimating individual deletion effects and pairwise interactions, derived from sampled pixel responses [S1, unofficial].
- Retention Quota $K_b$: The number of Gaussians to retain in block $b$, such that $\sum_b K_b = K$ [S1, unofficial].

**Steps:**

1. **Partitioning:** Divide the $N$ Gaussians into blocks $\mathcal{C}_b$ of at most $M$ members using spatial proximity and appearance similarity. This is implemented via a 3D grid and Morton ordering to efficiently group related Gaussians without quadratic pairwise comparisons [S1, unofficial].

2. **Opacity Response Modeling:** For each block $\mathcal{C}_b$, compute the response matrix $R_b$. This involves sampling pixels from multiple views and estimating how individual Gaussian deletions and pairwise interactions affect rendered colors [S1, unofficial].

3. **Budget Allocation:** Assign a retention quota $K_b$ to each block $b$. Initial quotas are derived from importance estimates, then smoothed to prevent budget concentration in high-scoring regions, ensuring $\sum_b K_b = K$ [S1, unofficial].

4. **Quadratic Selection:** For each block $\mathcal{C}_b$, formulate a QUBO objective function incorporating individual responses, pairwise interactions from $R_b$, and penalties for deviating from quota $K_b$. Solve the QUBO using Simulated Annealing (SA) or a Coherent Ising Machine (CIM) to determine which $K_b$ Gaussians to retain [S1, unofficial].

5. **Fine-tuning:** Fine-tune the attributes ($\mu_i, s_i, r_i, c_i, h_i, o_i$) of the retained Gaussians without changing their count to recover rendering quality [S1, unofficial].

    final_model = fine_tune(retained_gaussians, num_views)

def partition_by_morton(G, M):
    """
    Partition Gaussians into blocks of size <= M using Morton ordering.
    """
    # Assign Morton codes based on spatial position (mu)
    morton_codes = [compute_morton_code(g.mu) for g in G]
    
    # Sort Gaussians by Morton code
    sorted_indices = sorted(range(len(G)), key=lambda i: morton_codes[i])
    sorted_G = [G[i] for i in sorted_indices]
    
    # Divide into blocks of size M
    blocks = []
    for i in range(0, len(sorted_G), M):
        blocks.append(sorted_G[i:i+M])
        
    return blocks

**Parameters:**
- $N$: Total number of Gaussians in the pretrained 3DGS model [S1, unofficial].
- $K$: Exact number of Gaussians to retain after pruning [S1, unofficial].
- $M$: Maximum size (number of members) of each block $\mathcal{C}_b$ [S1, unofficial].
- $K_b$: Retention quota assigned to block $b$ [S1, unofficial].
- $R_b$: Response matrix for block $b$ [S1, unofficial].

**Edge cases and pitfalls:**
- Global ranking can lead to spatial quality imbalance where the limited budget concentrates in regions with consistently higher scores, leaving other regions with insufficient representational capacity [S1, unofficial].
- Independent scoring fails to capture joint rendering effects because multiple Gaussians may jointly support the same pixel or make overlapping contributions, meaning degradation from removing multiple Gaussians is not strictly additive [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Partitioning is efficient using Morton ordering, avoiding quadratic pairwise comparisons [S1, unofficial]. QUBO solving is NP-hard, but block size $M$ limits the problem size, making it tractable with SA or CIM [S1, unofficial].
- **Memory Complexity:** Depends on block size $M$ and number of blocks. Response matrices $R_b$ are $M \times M$, so memory is proportional to $N \times M$ if all blocks are processed simultaneously, or less if processed sequentially [S1, unofficial].
- **Strengths:** Ensures balanced reconstruction quality across scene regions by controlling regional budgets [S1, unofficial]. Captures joint deletion effects via quadratic objective, avoiding redundant retention of overlapping Gaussians [S1, unofficial].
- **Limitations:** Requires solving QUBO for each block, which can be computationally intensive depending on $M$ and the solver used [S1, unofficial]. Fine-tuning adds additional training time [S1, unofficial].
- **When to use:** When balanced quality across the entire scene is critical and global Top-K methods lead to spatial imbalance [S1, unofficial].
- **When not to use:** When computational resources for QUBO solving are limited or when scene quality is not uniformly important [S1, unofficial].

## Background
SplatQ was proposed by Hongbin Ye et al. in "SplatQ: Interaction-Aware Pruning of 3D Gaussian Splatting via Quadratic Selection" (arXiv:2610.13503, 2026) [S1, unofficial]. It addresses limitations of existing 3DGS pruning methods that rely on global Top-K selection based on independent importance scores, which lack regional budget control and ignore joint deletion effects [S1, unofficial].
