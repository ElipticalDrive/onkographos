# Fine-tuning

Also called: 3DGS Fine-tuning, Fine-tuning Strategy, Gaussian Splatting Fine-tuning

## Overview
Fine-tuning in the context of 3D Gaussian Splatting (3DGS) refers to the phase of training optimization where a pre-initialized or pre-trained representation is refined to achieve high-fidelity novel view synthesis. It addresses the problem of adapting generic or sparse initial priors to specific scene details by optimizing geometry, color, and opacity attributes, often while enabling dynamic densification (growing/pruning) [S2]. It sets itself apart from initial training by leveraging existing weights or structures to accelerate convergence and improve quality, distinguishing it from naive end-to-end training which starts from scratch [S5].

## How it works
The fine-tuning process varies depending on the initialization source (e.g., feed-forward prediction, pre-trained generative models, or sparse SfM points), but generally involves optimizing the parameters of the 3D Gaussian primitives $\mathcal{G}$ using gradient-based optimization.

### Inputs and Outputs
*   **Inputs:** A set of initial 3D Gaussian primitives $\mathcal{G}_{init}$ (with means $\mu$, covariances $\Sigma$, opacities $\alpha$, and spherical harmonic coefficients $\mathbf{c}$), a set of training images with known camera poses, and a pre-trained model or backbone (if applicable) [S2, S6].
*   **Outputs:** Optimized Gaussian parameters $\mathcal{G}_{final}$ that minimize the rendering loss against the training images [S2].

### Data Structures
The core data structure is the set of Gaussians $\mathcal{G} = \{g_1, \dots, g_N\}$. Each Gaussian $g_k$ is defined by:
*   Mean position $\mu_k \in \mathbb{R}^3$
*   Covariance matrix $\Sigma_k$ (parameterized by scale $s_k \in \mathbb{R}^3$ and rotation $q_k \in \mathbb{R}^4$)
*   Opacity $\alpha_k \in [0, 1]$
*   Spherical Harmonic coefficients $\mathbf{c}_k$ [Parent]

During fine-tuning, these parameters are stored in contiguous buffers for efficient rasterization. If densification (splitting/cloning) is enabled, the buffer size $N$ is dynamic [S2].

### Steps
1.  **Initialization:**
    *   If using a feed-forward predictor (e.g., EVolSplat), predict initial $\mathcal{G}_{init}$ via a direct feed-forward process generating geometry and color attributes [S2].
    *   If using a pre-trained generator (e.g., Gaussian Splatting Decoder), create a copy of the pre-trained 3D generator (backbone) and the decoder [S6].
    *   If using standard 3DGS, initialize from Structure-from-Motion (SfM) points [Parent].

2.  **Optimization Loop:**
    *   For each training iteration $t$:
        *   Render the current $\mathcal{G}_t$ to generate predicted color $\hat{C}$ and depth $\hat{D}$ for the training views [S3, S6].
        *   Compute the loss $\mathcal{L}$ between rendered outputs and ground truth images $C, D$. Common losses include L1 loss ($\mathcal{L}_1$) and Structural Similarity (SSIM) [S3, S6].
            $$ \mathcal{L} = \lambda_{color} \|\hat{C} - C\|_1 + \lambda_{SSIM} \text{SSIM}(\hat{C}, C) + \lambda_{depth} \|\hat{D} - D\|_1 $$
        *   Backpropagate gradients to update the Gaussian parameters $\mathcal{G}$ and, if applicable, the backbone/decoder weights [S2, S6].
        *   Use an optimizer such as Adam with a learning rate typically around $1 \times 10^{-3}$ [S2, S5].

3.  **Densification and Pruning (Conditional):**
    *   If the fine-tuning strategy enables growing and pruning (e.g., EVolSplat, HO-Gaussian), evaluate metrics periodically (e.g., every $N$ iterations) [S2, S4].
    *   **Gradient-based:** Compute accumulated 2D positional gradients $\tau_k$. Split or clone Gaussians with high gradients [Parent].
    *   **Rendering-based:** Identify holes where rendered opacity $O(x,y) < \tau_{opa}$ or high error where $E_{color}(x,y) > \tau_{color}$ or normalized depth error $E_{depth}(x,y)/D(x,y) > \tau_{depth}$ [S3]. Add new Gaussians to these regions [S3].
    *   **Pruning:** Remove Gaussians with low opacity $\alpha_k < \alpha_{min}$ to reduce redundancy [S2].

4.  **Backbone Fine-tuning (Specific to Generative Priors):**
    *   When using a pre-trained 3D generator, optimize the weights of the generator copy alongside the decoder to adapt tri-plane features to Gaussian Splatting attributes (scale/rotation), which influence adjacent regions unlike NeRF's local density [S6].

### Pseudocode
```python
def fine_tune_3dgs(initial_gaussians, training_data, pre_trained_backbone=None, 
                   enable_densification=True, iterations=10000, lr=1e-3):
    """
    Fine-tune 3D Gaussian Splatting representation.
    
    Args:
        initial_gaussians: Set of 3D Gaussians G_init.
        training_data: List of (image, depth, camera_pose) tuples.
        pre_trained_backbone: Optional pre-trained 3D generator network.
        enable_densification: Boolean flag for dynamic densification.
        iterations: Number of optimization steps.
        lr: Learning rate for Adam optimizer.
        
    Returns:
        Optimized set of 3D Gaussians.
    """
    # Initialize optimizer
    # If using backbone, optimize backbone weights + decoder + gaussians
    # Else, optimize only gaussians
    optimizer = Adam(params=initial_gaussians.parameters(), lr=lr)
    
    # If pre-trained backbone is provided, copy it and include in optimization
    if pre_trained_backbone is not None:
        backbone_copy = copy(pre_trained_backbone)
        optimizer.add_param_group({'params': backbone_copy.parameters()})
        
    for step in range(iterations):
        # Sample a batch of training views
        batch = sample_batch(training_data)
        
        # Forward pass: Render current Gaussians
        rendered_color, rendered_depth = render(initial_gaussians, batch.poses)
        
        # Compute Loss
        # Standard 3DGS uses L1 + SSIM
        loss_color = L1_loss(rendered_color, batch.images)
        loss_ssim = SSIM_loss(rendered_color, batch.images)
        loss_depth = L1_loss(rendered_depth, batch.depths) if batch.has_depth else 0
        
        total_loss = loss_color + loss_ssim + loss_depth
        
        # Backward pass
        optimizer.zero_grad()
        total_loss.backward()
        optimizer.step()
        
        # Densification Step (if enabled)
        if enable_densification and step % refine_every == 0:
            # 1. Compute gradients for each Gaussian
            gradients = compute_gradient_magnitude(initial_gaussians)
            
            # 2. Identify Gaussians to split/clone (high gradient)
            split_candidates = [g for g in initial_gaussians if g.gradient > threshold_grad]
            
            # 3. Identify regions for densification (holes/high error)
            # Render to check opacity and error
            test_render = render(initial_gaussians, batch.poses)
            hole_mask = test_render.opacity < threshold_opacity
            error_mask = abs(test_render.color - batch.images) > threshold_color
            
            # 4. Add new Gaussians in hole/error regions
            new_gaussians = create_gaussians_from_error(test_render, hole_mask, error_mask)
            
            # 5. Split/Clone high-gradient Gaussians
            densified_gaussians = split_and_clone(split_candidates, initial_gaussians)
            
            # 6. Merge and Prune
            initial_gaussians = merge(initial_gaussians, new_gaussians, densified_gaussians)
            initial_gaussians = prune_low_opacity(initial_gaussians, threshold_opacity)
            
    return initial_gaussians
```

### Parameters
*   **Learning Rate:** $1 \times 10^{-3}$ is common for fine-tuning [S2, S5].
*   **Iterations:** Naive fine-tuning may use 10,000 steps [S5]. Fine-tuning for EVolSplat uses Adam with $1 \times 10^{-3}$ [S2].
*   **Refinement Interval (`refineEvery`):** Typically 100 iterations [Parent].
*   **Opacity Threshold ($\tau_{opa}$):** Predefined threshold for hole detection [S3].
*   **Depth Error Threshold ($\tau_{depth}$):** Predefined threshold for normalized depth error [S3].
*   **Color Error Threshold ($\tau_{color}$):** Predefined threshold for color error [S3].

### Edge Cases and Pitfalls
*   **Forgetting:** In continuous mapping or incremental fine-tuning, Gaussians may overfit to the latest frame, degrading quality for previous frames. Regularization terms (e.g., SSIM, extra L1 on previous frames) are needed to alleviate this [S3].
*   **Redundancy:** Feed-forward initialization may produce redundant Gaussians. Fine-tuning must include pruning to reduce memory consumption while maintaining fidelity [S2].
*   **Scale Compensation:** When checking depth error, divide by rendered depth $D(x,y)$ to compensate for varying scales [S3].

## Subtopics

### [Exponentially Ascending Gradient Threshold](9684-exponentially-ascending-gradient-threshold.md)
A densification control mechanism that uses an exponentially ascending gradient threshold to regulate splitting and cloning. It allows aggressive densification when few Gaussians exist and restricts it as the scene becomes dense, solving the trade-off between early-stage convergence speed and late-stage overfitting.

### [SplatFormer Training Objective & Refinement](11745-splatformer-training-objective-refinement.md)
A learning-based, feed-forward 3D neural module that refines initial 3DGS representations to enable robust novel view synthesis from out-of-distribution (OOD) camera angles. It applies a point transformer network to predict attribute residuals, addressing the bias of standard 3DGS optimization which overfits to input views.

### [MCMC-based 3DGS / SGLD for 3DGS](11917-mcmc-based-3dgs-sgld-for-3dgs.md)
Reforms 3DGS by treating Gaussians as MCMC samples from an underlying probability distribution. It converts updates into Stochastic Gradient Langevin Dynamics (SGLD) by introducing noise, removing the need for manual densification heuristics like cloning and splitting.

### [Deblurring 3D Gaussian Splatting](12318-deblurring-3d-gaussian-splatting.md)
A real-time deblurring framework that reconstructs sharp 3D scenes from blurry inputs by manipulating covariance matrices and means using a small MLP. It uses differentiable rasterization for real-time inference (>800 FPS) and handles defocus and motion blur.

### [Supplementary Point Addition for Sparse Point Clouds](12323-supplementary-point-addition-for-sparse-point-clouds.md)
A densification technique that explicitly injects synthetic points into empty or sparse regions after a fixed number of iterations. It compensates for poor SfM extraction in far-end scenes with large depth of field, preventing distant objects from being ignored.

### [Augmented Radiance Field](13218-augmented-radiance-field.md)
A post-enhancement framework that improves 3DGS by adding Gaussian kernels with view-dependent opacity to explicitly model specular components. It solves the problem of standard SH failing to decouple diffuse and specular radiance, avoiding memory issues of high-order SH.

### [Frequency Regularization for Densification](13484-frequency-regularization-for-densification.md)
Addresses over-reconstruction by minimizing the discrepancy between the frequency spectrum of the rendered image and the ground truth in Fourier space. This increases pixel gradients in over-reconstruction regions, enabling coarse-to-fine densification guided by progressive frequency annealing.

### [Error-Guided Redistribution](14037-error-guided-redistribution.md)
A family of strategies that dynamically adjusts the spatial distribution of Gaussians based on rendering errors or gradient magnitudes. It targets regions with persistent coarse-scale errors or "hard" gradients, either by reallocating a fixed budget or growing defective primitives.

### CoherentGS
A regularized optimization method for sparse novel view synthesis that introduces structural coherency by constraining Gaussian movement in 2D image space. It solves instability and "needle-like" artifacts in sparse views (3-4 images) by enforcing single-view and multi-view consistency [S1].

### [Pruning and Sparsity Control](14431-pruning-and-sparsity-control.md)
Methods that reduce the number of active Gaussians to lower memory and storage while maintaining quality. They actively eliminate redundant primitives throughout optimization using explicit geometric or volume-based criteria, rather than relying solely on opacity thresholds.

### [Rendering-Free Pruning via Hessian Importance](14447-rendering-free-pruning-via-hessian-importance.md)
A post-processing framework that identifies and removes unimportant Gaussians without forward rendering passes. It uses an analytically approximated Hessian field to estimate quality degradation, achieving a 3,000× reduction in computational complexity.

### [GoF-based Dynamic 3DGS Video Construction](14770-gof-based-dynamic-3dgs-video-construction.md)
Constructs dynamic 3DGS video by temporally segmenting input sequences into Groups of Frames (GoFs) and independently training deformation fields within each segment. It solves motion drift and geometric inconsistencies in long-range temporal dependencies.

### [Two-stage Optimization](14857-two-stage-optimization.md)
A training protocol that decouples geometric and appearance optimization from material and lighting decomposition. It prevents entanglement of physical properties during early training by introducing normal gradient-based densification and PBR-specific loss terms.

### [TIP-Editor](14859-tip-editor.md)
A method for editing existing 3DGS scenes using text and image prompts. It combines stepwise 2D personalization with score distillation sampling (SDS), integrating LoRA for reference alignment and a dedicated localization loss.

### StylizedGS
A controllable 3D stylization method that performs color matching with a reference style image while using a 3DGS filter to remove artifacts. It optimizes for nearest neighbor feature matching and depth preservation [S1].

### [SGD (Street View Synthesis with Gaussian Splatting and Diffusion Prior)](15522-sgd-street-view-synthesis-with-gaussian-splatting-and-diffus.md)
Enhances 3DGS for street scenes by fine-tuning a Stable Diffusion model on driving data and using it to regularize 3DGS training at unseen viewpoints. It addresses sparse-view reconstruction by using adjacent frames and LiDAR depth.

### Gaussian Densification via Rendering Loss
A strategy to add new 3D Gaussians by identifying unobserved regions (holes) and regions with high rendering error. It uses opacity, color, and depth thresholds to guide densification, projecting corresponding depths directly for depth images [S3].

### Point Densification
A process in original 3DGS that adaptively controls the number of Gaussian points through clone and split operations. In HO-Gaussian, this is performed at regular intervals to provide new positions to populate problematic regions [S4].

### Naive Fine-tuning
A generator fine-tuning method identical to model rewriting except freely optimizing all weights of the generator. It is typically optimized over 10,000 steps with a learning rate of $10^{-3}$ [S5].

### Backbone Fine-tuning
Optimizing the weights of a pre-trained 3D generator (backbone) alongside the decoder to adapt tri-plane features for Gaussian Splatting attributes. This is necessary because Gaussian splats have scale and rotation influencing adjacent regions, unlike NeRF's local color/density [S6].

## Operating characteristics
*   **Time Complexity:** Fine-tuning is generally faster than training from scratch due to warm-starting from pre-trained weights or initial predictions [S2]. However, the inclusion of densification operations (splitting/cloning) adds overhead proportional to the number of Gaussians and the frequency of densification steps [Parent].
*   **Memory Complexity:** Memory usage scales with the number of Gaussians $N$. Fine-tuning with pruning can reduce $N$ compared to initial feed-forward predictions, lowering memory consumption [S2].
*   **Performance:** Fine-tuning enables photorealism on par with or surpassing other methods, leveraging powerful pretrained weights to accelerate convergence [S2].
*   **Strengths:** Accelerates training, improves quality, allows adaptation to specific scenes, and can handle sparse or blurry inputs with specialized variants [S2, S3, S5].
*   **Limitations:** May suffer from "forgetting" in incremental settings [S3]. Requires careful tuning of densification thresholds to avoid overfitting or artifacts [S1].

## Background
Fine-tuning in deep learning generally involves transferring knowledge from a pre-trained model to a new task by adjusting weights [S1]. In the context of 3D Gaussian Splatting, fine-tuning has emerged as a critical step for high-fidelity reconstruction, especially when using pre-trained generative models or feed-forward predictors [S2, S6]. The concept of adaptive densification (splitting/cloning) was introduced in the original 3DGS paper [Parent], and subsequent works have refined this process through various strategies like rendering-guided densification [S3], frequency regularization [S1], and MCMC-based approaches [S1].
