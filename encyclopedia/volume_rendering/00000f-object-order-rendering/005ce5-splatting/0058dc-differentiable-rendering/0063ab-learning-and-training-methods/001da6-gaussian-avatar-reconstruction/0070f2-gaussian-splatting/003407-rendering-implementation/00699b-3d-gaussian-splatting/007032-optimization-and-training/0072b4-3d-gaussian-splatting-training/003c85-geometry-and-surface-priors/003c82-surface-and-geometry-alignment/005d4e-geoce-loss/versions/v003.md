# GeoCE Loss

Also called: Geometric Contrastive Loss

## Overview
GeoCE (Geometric Contrastive Embedding) is a geometric supervision method used in 3D Gaussian Splatting training to ensure that learned scene tokens cluster by physical surface rather than by viewpoint [S1, unofficial]. It solves the problem where feature-space similarity does not guarantee geometric consistency, by explicitly aligning token cosine similarities with 3D proximity [S1, unofficial]. Unlike sibling methods that enforce hard constraints on Gaussian positions or normals, GeoCE shapes the latent token space using a soft contrastive target derived from unprojected patch depths, allowing multiple patches observing the same surface to share high similarity weights [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Inputs:**
    *   A set of $N$ geometry tokens $\{\mathbf{g}_i\}_{i=1}^N$, where each token $\mathbf{g}_i$ corresponds to an image patch observed from a specific camera view [S1, unofficial].
    *   Ground-truth camera poses and intrinsics for the training views [S1, unofficial].
    *   Depth maps for the training views (precomputed, e.g., by DA3-Giant) [S1, unofficial].
*   **Outputs:**
    *   A scalar loss value $\mathcal{L}_{\mathrm{geo}}$ that penalizes discrepancies between token similarity and 3D proximity [S1, unofficial].

**Data Structures**
*   **Tokens:** $\mathbf{g}_i \in \mathbb{R}^d$, $\ell_2$-normalized [S1, unofficial].
*   **Anchors:** A subset of tokens sampled as anchors. The method samples 2048 tokens per scene as anchors during training [S1, unofficial].
*   **3D Points:** For each anchor $i$, a 3D point $\mathbf{p}_i$ is computed by unprojecting the median-depth pixel of its associated patch using the ground-truth camera [S1, unofficial].
*   **Bandwidths:** A scalar $\sigma_i$ for each anchor, derived from local patch texture [S1, unofficial].

**Parameters**
*   $\tau = 0.1$: Temperature parameter for the softmax [S1, unofficial].
*   $\lambda_{\mathrm{geo}} = 0.05$: Weight for the GeoCE loss in the total objective [S1, unofficial].
*   $K = 2048$: Number of anchor tokens sampled per scene [S1, unofficial].
*   Grid size: $4 \times 4$ pixels for depth averaging [S1, unofficial].

**Algorithm Steps**
1.  **Anchor Sampling:** Randomly sample $K$ tokens from the current batch of scene tokens to serve as anchors [S1, unofficial].
2.  **3D Unprojection:** For each anchor $i$, identify its associated image patch and compute the median depth $d_i$ of its valid pixels [S1, unofficial]. Unproject the patch center using the ground-truth camera to obtain the 3D anchor point $\mathbf{p}_i$ [S1, unofficial].
3.  **Validity Check:** Exclude anchors whose patches have valid depth on fewer than half of their pixels [S1, unofficial].
4.  **Bandwidth Calculation:**
    *   Compute the base bandwidth $\sigma$ as the scene-wise median 3D distance between adjacent patch points [S1, unofficial].
    *   For each anchor $i$, compute the mean image-gradient energy of its patch to rank texture complexity [S1, unofficial].
    *   Calculate the per-token bandwidth $\sigma_i$ by log-interpolating between $\sigma$ (for the flattest patch) and $0.4\sigma$ (for the most textured patch), based on the patch's rank in gradient energy [S1, unofficial].
5.  **Target Weight Computation:**
    *   For each pair of anchors $(i, j)$ with $i \neq j$, compute the soft target weight $w_{ij}$ based on their 3D Euclidean distance:
        $$ w_{ij} \propto \exp \left( -\frac{\|\mathbf{p}_i - \mathbf{p}_j\|^2}{2\sigma_i \sigma_j} \right) $$
    *   The weight $w_{ij}$ is proportional to the exponential of negative squared 3D distance, scaled by per-token bandwidths [S1, unofficial]. Patches with high 3D proximity receive high weights [S1, unofficial].
    *   Normalize $w_{ij}$ such that $\sum_{j \neq i} w_{ij} = 1$ for each $i$ [S1, unofficial].
6.  **Loss Computation:**
    *   Compute the cosine similarity between all pairs of anchor tokens: $s_{ij} = \mathbf{g}_i^\top \mathbf{g}_j$ (assuming $\ell_2$-normalized tokens) [S1, unofficial].
    *   Calculate the GeoCE loss using cross-entropy between the target distribution $w_{ij}$ and the predicted similarity distribution:
        $$ \mathcal{L}_{\mathrm{geo}} = -\sum_{i} \sum_{j \neq i} w_{ij} \log \frac{\exp(\mathbf{g}_i^\top \mathbf{g}_j / \tau)}{\sum_{k \neq i} \exp(\mathbf{g}_i^\top \mathbf{g}_k / \tau)} $$
    *   This loss pushes the token cosine similarities to match the soft target distribution weighted by 3D proximity [S1, unofficial].

**Pseudocode**
```python
import math

def geoce_loss(geometry_tokens, anchor_indices, cameras, depth_maps, sigma_base, tau=0.1):
    """
    Computes the GeoCE loss for a batch of scene tokens.
    
    Args:
        geometry_tokens: List of vectors (each a list of floats), L2-normalized.
        anchor_indices: List of K indices into geometry_tokens to use as anchors.
        cameras: Dict mapping view_id to {'K': intrinsics, 'T': pose}.
        depth_maps: Dict mapping view_id to 2D list of depths.
        sigma_base: Base bandwidth (scene-wise median 3D distance).
        tau: Temperature parameter.
        
    Returns:
        Scalar loss value.
    """
    valid_indices = []
    anchor_points = []
    anchor_grad_energies = []

    for idx in anchor_indices:
        # [G] Mapping from token index to (view_id, patch_bbox) is external to the loss function.
        view_id, patch_bbox = get_token_view_and_patch(idx)
        
        depth_map = depth_maps[view_id]
        # Extract depths over a 4x4 pixel grid inside the patch
        patch_depths = extract_patch_depths(depth_map, patch_bbox, grid_size=4)
        
        # Check validity: at least half pixels must have valid depth
        if count_valid_depth(patch_depths) < 0.5 * len(patch_depths):
            continue
            
        # Compute median depth
        valid_depths = [d for d in patch_depths if d > 0]
        if not valid_depths:
            continue
        median_depth = sorted(valid_depths)[len(valid_depths) // 2]
        
        # Unproject to 3D
        p_i = unproject_pixel(view_id, patch_bbox['center'], median_depth, cameras[view_id])
        
        # Compute gradient energy for bandwidth interpolation
        grad_energy = compute_mean_gradient_energy(view_id, patch_bbox)
        
        valid_indices.append(idx)
        anchor_points.append(p_i)
        anchor_grad_energies.append(grad_energy)
        
    if len(valid_indices) < 2:
        return 0.0
        
    K_valid = len(valid_indices)
    anchor_tokens = [geometry_tokens[i] for i in valid_indices]
    
    # Step 4: Calculate per-token bandwidths
    # Rank patches by gradient energy
    sorted_indices = sorted(range(K_valid), key=lambda k: anchor_grad_energies[k])
    min_sigma = 0.4 * sigma_base
    max_sigma = sigma_base
    
    sigmas = []
    for rank, idx in enumerate(sorted_indices):
        t = rank / (K_valid - 1)
        # Log-interpolation: log(sigma_i) = (1-t)*log(max_sigma) + t*log(min_sigma)
        log_sigma = (1 - t) * math.log(max_sigma) + t * math.log(min_sigma)
        sigmas.append(math.exp(log_sigma))
        
    # Step 5: Compute target weights
    # Pairwise distances
    dists = [[math.sqrt(sum((a - b) ** 2 for a, b in zip(p1, p2))) for p2 in anchor_points] for p1 in anchor_points]
    # Weights w_ij proportional to exp(-dist^2 / (2 * sigma_i * sigma_j))
    weights = [[0.0] * K_valid for _ in range(K_valid)]
    for i in range(K_valid):
        for j in range(K_valid):
            if i != j:
                weights[i][j] = math.exp(-(dists[i][j] ** 2) / (2 * sigmas[i] * sigmas[j]))
                
    # Normalize weights for each row i
    for i in range(K_valid):
        row_sum = sum(weights[i])
        for j in range(K_valid):
            weights[i][j] /= (row_sum + 1e-8)
            
    # Step 6: Compute loss
    # Cosine similarities (tokens are L2-normalized)
    similarities = [[dot_product(a, b) for b in anchor_tokens] for a in anchor_tokens]
    
    # Softmax over j != i
    log_probs = [[0.0] * K_valid for _ in range(K_valid)]
    for i in range(K_valid):
        exp_sims = [math.exp(similarities[i][j] / tau) if j != i else 0.0 for j in range(K_valid)]
        sum_exp = sum(exp_sims) + 1e-8
        for j in range(K_valid):
            log_probs[i][j] = math.log(exp_sims[j] / sum_exp + 1e-8)
            
    # Cross-entropy: - sum_i sum_j w_ij log(p_j|i)
    loss = 0.0
    for i in range(K_valid):
        for j in range(K_valid):
            loss -= weights[i][j] * log_probs[i][j]
            
    return loss

def dot_product(a, b):
    return sum(x * y for x, y in zip(a, b))

def get_token_view_and_patch(token_idx):
    # [G] External mapping from token index to (view_id, patch_bbox) is required by the training loop.
    return 0, {'center': [0.0, 0.0], 'size': [16, 16]}

def extract_patch_depths(depth_map, patch_bbox, grid_size=4):
    # [G] Standard grid sampling over the patch bounding box.
    depths = []
    for dy in range(grid_size):
        for dx in range(grid_size):
            y = int(patch_bbox['center'][1] + (dy - grid_size/2) * patch_bbox['size'][1] / grid_size)
            x = int(patch_bbox['center'][0] + (dx - grid_size/2) * patch_bbox['size'][0] / grid_size)
            depths.append(depth_map[y][x])
    return depths

def count_valid_depth(depths):
    return sum(1 for d in depths if d > 0)

def unproject_pixel(view_id, center, depth, camera):
    # [G] Standard pinhole camera unprojection to camera space.
    K = camera['K']
    nx = (center[0] - K[0][2]) / K[0][0]
    ny = (center[1] - K[1][2]) / K[1][1]
    x = nx * depth
    y = ny * depth
    z = depth
    return [x, y, z]
```

**Edge Cases and Pitfalls**
*   **Invalid Depth:** Patches with insufficient valid depth are excluded [S1, unofficial].
*   **Precision:** Median depth computation should handle outliers in depth maps [S1, unofficial].
*   **Bandwidth Scaling:** The bandwidth $\sigma_i$ scales with local patch spacing [S1, unofficial]. Incorrect scaling can lead to overly local or overly global similarity targets [S1, unofficial].

### [Cone Loss](17337-cone-loss.md)
The Cone Loss is a geometric regularization term used in ZipSplat to ground 3D Gaussian tokens to their specific source image patches, preventing decoded Gaussians from drifting arbitrarily in 3D space.

## Operating characteristics
*   **Time Complexity:** Time complexity is not given in the sources [S1, unofficial].
*   **Memory Complexity:** Memory complexity is not given in the sources [S1, unofficial].
*   **Performance:** GeoCE enables the formation of compact, surface-aligned Gaussian clusters, improving reconstruction quality (PSNR) while reducing the number of required Gaussians [S1, unofficial].
*   **Strengths:** Explicitly enforces geometric consistency in the latent space, preventing viewpoint-based clustering artifacts [S1, unofficial].
*   **Limitations:** Requires accurate depth maps (or depth estimation) for the training views [S1, unofficial].

## Background
GeoCE was introduced in the ZipSplat paper (2026) as part of a framework for few-shot 3D Gaussian Splatting [S1, unofficial]. It addresses the limitation of previous methods where clustering in feature space did not guarantee geometric coherence [S1, unofficial].
