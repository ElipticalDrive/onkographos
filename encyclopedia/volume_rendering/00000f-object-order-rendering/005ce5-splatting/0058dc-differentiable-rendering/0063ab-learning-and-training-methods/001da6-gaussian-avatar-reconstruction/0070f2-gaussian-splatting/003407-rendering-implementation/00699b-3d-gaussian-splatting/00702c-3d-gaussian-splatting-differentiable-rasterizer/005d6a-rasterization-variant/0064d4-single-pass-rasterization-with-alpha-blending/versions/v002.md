# Single-Pass Rasterization with Alpha-Blending

Also called: Single-Pass Anti-Aliased Rasterization, Unified Rasterization

## Overview
This method provides a unified rendering pipeline that rasterizes both 3D Gaussians and triangle meshes in a single pass using alpha-blending, ensuring correct spatial occlusion and color blending without dropping rendering rates [S1]. It distinguishes itself from standard Gaussian Splatting by integrating triangle fragments into the depth-sorted accumulation loop while applying Multi-Sample Anti-Aliasing (MSAA) logic to triangles to prevent color overflow artifacts when Gaussians are present between depth-adjacent triangles [S1].

## How it works
**Inputs and Outputs**
*   **Inputs:** A set of 3D Gaussians (mean $\boldsymbol{\mu}$, covariance $\boldsymbol{\Sigma}$, opacity $\alpha$, color $\mathbf{c}$), a triangle mesh (vertices, faces, per-face opacity $\alpha$, color $\mathbf{c}$), camera parameters (intrinsic/extrinsic matrices), and the number of sub-pixels $M$ for MSAA.
*   **Outputs:** Final pixel color $\mathbf{C}_{pixel}$ and potentially transmittance/coverage masks.

**Data Structures**
The method operates on fragments sorted by depth. For each pixel, fragments (both Gaussian and triangle) are processed in depth order.
*   **Gaussian Fragment:** Contains $\alpha_i$, $\mathbf{c}_i$. Coverage is implicit via the EWA-filtered alpha value.
*   **Triangle Fragment:** Contains $\alpha_i$, $\mathbf{c}_i$. Requires explicit coverage calculation $O_i$ using sub-pixel sampling.

**Numbered Steps**
1.  **Projection and Sorting:** Project 3D Gaussians and triangle vertices to screen space. Sort all resulting fragments (Gaussian splats and triangle faces) by depth $z$ for each pixel [S1].
2.  **Initialize Transmittance:** Set initial transmittance $T_{in} = 1.0$ for the pixel [S1].
3.  **Process Gaussian Fragments:** For each Gaussian fragment $i$ in depth order:
    *   Compute transmittance $T_i = \prod_{j=1}^{i-1} (1 - \alpha_j)$, with $T_1 = T_{in}$ [S1].
    *   Accumulate Gaussian color contribution: $\mathbf{C}_{gs} += T_i \alpha_i \mathbf{c}_i$ [S1].
    *   Update pixel-level transmittance for subsequent fragments: $T_{current} = T_i (1 - \alpha_i)$ [S1].
4.  **Process Triangle Fragments:** For each triangle fragment $i$ in depth order:
    *   **Sub-pixel Coverage Calculation:** Determine if the triangle covers each of the $M$ sub-pixels. Let $o_{ji} \in \{0, 1\}$ be the geometric coverage of fragment $i$ at sub-pixel $j$ [S1].
    *   **Sub-pixel Transmittance:** Compute sub-pixel transmittance $t_{ji}$ accounting for previous fragments at that specific sub-pixel:
        $$ t_{ji} = \prod_{k=1}^{i-1} (1 - o_{jk} \alpha_k) $$
        with $t_{j1} = 1.0$ [S1].
    *   **Pixel Coverage:** Compute the effective coverage $O_i$ for the triangle at the pixel level by averaging sub-pixel coverages weighted by their transmittance:
        $$ O_i = \frac{1}{M} \sum_{j=1}^{M} o_{ji} t_{ji} $$
        [S1].
    *   **Triangle Color Accumulation:** Treat depth-adjacent triangles as a single entity to avoid color overflow. Accumulate triangle color using the initial transmittance $T_{in}$ (or the transmittance state before the current group of adjacent triangles, but the source specifies $T_{in}$ in Eq 9 for the group logic, while noting $T_i$ is updated for subsequent blending):
        $$ \mathbf{C}_{tris} += T_{in} O_i \alpha_i \mathbf{c}_i $$
        [S1].
    *   **Update Pixel Transmittance:** Update the pixel-level transmittance $T_i$ for subsequent blending using the effective coverage $O_i$:
        $$ T_i = \prod_{k=1}^{i-1} (1 - O_k \alpha_k) $$
        [S1].
5.  **Final Color Calculation:** Combine the accumulated triangle color, the accumulated Gaussian color, and the background:
    $$ \mathbf{C}_{pixel} = \mathbf{C}_{tris} + \mathbf{C}_{gs} + T_{bg} \mathbf{C}_{bg} $$
    where $T_{bg} = T_N (1 - \alpha_{bg})$, $T_N$ is the final transmittance after all fragments, $\mathbf{C}_{bg}$ is the background color, and $\alpha_{bg}$ is the background opacity [S1].

**Parameters**
*   $M$: Number of sub-pixels for MSAA. Typical value: 4 [S1].

**Pitfalls**
*   **Color Overflow:** If all triangles overlapping a pixel are treated as a single entity without considering Gaussians between them, the transmittance for deeper triangles does not account for decay from intervening Gaussians. This results in excessive brightness (white artifacts) [S1]. The solution is to treat only depth-adjacent triangles as a single entity for the $\mathbf{C}_{tris}$ calculation [S1].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of fragments per pixel. The sub-pixel coverage calculation adds a constant factor of $M$ (typically 4) to triangle processing.
*   **Memory Complexity:** Requires storing depth-sorted fragments per pixel. Sub-pixel coverage requires $M$ bits or flags per fragment per pixel.
*   **Strengths:** Unified handling of meshes and Gaussians; correct occlusion; anti-aliased triangles via MSAA integration.
*   **Limitations:** Complexity in managing depth-adjacent triangle groups to prevent artifacts; potential performance overhead from sub-pixel sampling if not optimized.

## Background
This method was proposed in "UniMGS: Unifying Mesh and 3D Gaussian Splatting with Single-Pass Rasterization and Proxy-Based Deformation" to address the need for unified rendering of 3D Gaussian Splatting (3DGS) and mesh-based representations in dynamic scenes [S1]. It departs from proxy-based deformation strategies that are sensitive to mesh topology by using a Gaussian-centric strategy and a single-pass rasterization pipeline [S1].
