# Compact 3D Gaussian Representation (C3DGS)
Also called: Compact 3D Gaussian Representation for Radiance Field, Compact3DGS

## Overview
Compact 3D Gaussian Representation (C3DGS) is a framework that reduces the storage footprint and rendering latency of 3D Gaussian Splatting by eliminating redundant primitives and compressing their attributes via spatial sharing [S1, S2]. Unlike standard 3DGS, which stores high-precision per-Gaussian attributes, C3DGS exploits spatial redundancy by replacing per-primitive color data with a shared hash-based neural field and quantizing geometric attributes into a small codebook [S1]. This approach achieves over 25× storage compression and up to 40% faster rendering while maintaining or improving reconstruction quality [S1].

## How it works
C3DGS operates on the set of $N$ 3D Gaussians $\{G_i\}_{i=1}^N$ defined in [Rendering Implementation and Acceleration](21069-rendering-implementation-and-acceleration.md). The method consists of two parallel optimization streams: a pruning stream that reduces the count $N$, and a compression stream that reduces the attribute size per remaining Gaussian.

### Inputs and Outputs
**Inputs:**
*   Initial set of $N$ Gaussians $\{G_i\}$ with attributes: position $\mathbf{p}_i$, scale $\mathbf{s}_i$, rotation $\mathbf{r}_i$ (quaternion), opacity $\alpha_i$, and spherical harmonics coefficients $\mathbf{c}_i$ (view-dependent color).
*   Training images and camera poses.
*   Hyperparameters: codebook size $K$, hash grid resolution/depth (Instant-NGP settings), pruning threshold $\tau$.

**Outputs:**
*   Pruned set of $N'$ Gaussians ($N' \le N$).
*   Shared Hash Grid $\mathcal{H}$ for color.
*   Codebook $\mathcal{C}$ of size $K$ for geometry.
*   Per-Gaussian indices: $idx^{color}_i$ (grid coordinate/hash key) and $idx^{geo}_i \in [0, K-1]$.

### Data Structures

1.  **Gaussian State (per primitive $i$):**
    *   $\mathbf{p}_i \in \mathbb{R}^3$: Position.
    *   $\mathbf{r}_i \in \mathbb{R}^4$: Rotation (unit quaternion).
    *   $\alpha_i \in [0, 1]$: Opacity.
    *   $idx^{geo}_i \in \{0, \dots, K-1\}$: Index into the geometric codebook.
    *   $hash\_key_i$: Key for querying the color grid.

2.  **Geometric Codebook $\mathcal{C}$:**
    *   Size: $K$ entries.
    *   Layout: Array of vectors. Each entry $j$ stores a representative scale $\mathbf{s}_j \in \mathbb{R}^3$ and rotation $\mathbf{r}_j \in \mathbb{R}^4$.
    *   Total storage: $K \times (\text{size of scale} + \text{size of rotation})$.

3.  **Color Hash Grid $\mathcal{H}$:**
    *   Based on Instant-NGP [S1].
    *   Layout: Multi-resolution hash table mapping spatial coordinates to feature vectors.
    *   Query: Given a 3D position $\mathbf{p}_i$ and view direction $\mathbf{v}$, $\mathcal{H}$ returns the color $\mathbf{c}_i$.

### Numbered Steps

1.  **Initialization:** Initialize Gaussians using standard 3DGS densification. Initialize Codebook $\mathcal{C}$ with random or k-means clustered scale/rotation vectors. Initialize Hash Grid $\mathcal{H}$ with zero features. Initialize learnable binary masks $m_i \in \{0, 1\}$ for each Gaussian.

2.  **Volume-Based Masking (Pruning):**
    *   During training, compute a contribution score for each Gaussian based on its opacity $\alpha_i$ and scale (volume).
    *   Update masks $m_i$ via gradient descent to minimize a loss term that penalizes non-zero masks for Gaussians with low contribution [S1, S2].
    *   Gaussians with $m_i \approx 0$ are effectively pruned (zeroed out) during rendering. This reduces $N$ iteratively [S2].

3.  **Geometric Attribute Compression (Codebook):**
    *   Instead of storing $\mathbf{s}_i$ and $\mathbf{r}_i$ directly, store only the index $idx^{geo}_i$.
    *   The actual scale and rotation are retrieved as $\mathbf{s}_i = \mathcal{C}[idx^{geo}_i].\mathbf{s}$ and $\mathbf{r}_i = \mathcal{C}[idx^{geo}_i].\mathbf{r}$.
    *   During training, optimize both the Codebook entries $\mathcal{C}$ and the indices $idx^{geo}_i$ (via straight-through estimator or soft assignment) to minimize reconstruction error [S1].
    *   This exploits the observation that most Gaussians share similar geometric patterns [S1].

4.  **Color Attribute Compression (Hash Grid):**
    *   Replace per-Gaussian spherical harmonics coefficients with a query to the Hash Grid $\mathcal{H}$.
    *   For a Gaussian at $\mathbf{p}_i$ viewed from direction $\mathbf{v}$, compute color $\mathbf{c}_i = \text{Query}(\mathcal{H}, \mathbf{p}_i, \mathbf{v})$.
    *   The Hash Grid is shared across all Gaussians, exploiting spatial redundancy where neighboring Gaussians have similar colors [S1].
    *   Instant-NGP is used for $\mathcal{H}$ due to its compactness and fast lookup speed [S1].

5.  **Rendering:**
    *   For each pixel, project the surviving Gaussians ($m_i > \epsilon$).
    *   Retrieve geometry from $\mathcal{C}$ using $idx^{geo}_i$.
    *   Retrieve color from $\mathcal{H}$ using $\mathbf{p}_i$ and $\mathbf{v}$.
    *   Perform alpha blending as in standard 3DGS.

6.  **Post-Processing (Optional):**
    *   Apply quantization to the Codebook indices and Hash Grid features.
    *   Apply entropy coding to the final bitstream for further compression [S2].

### Parameters and Edge Cases
*   **Codebook Size $K$:** Must be small to ensure compression. Typical values are not explicitly given in sources, but "quite small" is noted [S1].
*   **Hash Grid Resolution:** Uses Instant-NGP settings [S1].
*   **Pruning Threshold:** Determined by the learned mask values [S2].
*   **Edge Cases:**
    *   **Sparse Regions:** The hash grid may have holes in sparse areas. The sources do not specify interpolation fallbacks, relying on the grid's inherent continuity [S1].
    *   **Index Optimization:** Optimizing discrete indices $idx^{geo}_i$ requires care. Sources mention "codebook-based approach" but do not detail the straight-through estimator specifics [S1]. [G] Standard practice involves using a soft assignment during training and hard assignment during inference.

## Subtopics

### [Optimized Minimal 3D Gaussian Splatting (OMG)](13978-optimized-minimal-3d-gaussian-splatting-omg.md)
OMG retains per-Gaussian geometry to handle sparsity better than C3DGS, using a neural field only for appearance. Choose OMG when scene geometry is highly sparse or irregular, as C3DGS's shared codebook may struggle with unique local geometries.

## Operating characteristics
*   **Storage:** Achieves >25× compression compared to standard 3DGS [S1]. On the Deep Blending dataset, storage efficiency is enhanced by over 28× [S1]. General datasets show ~15× reduction [S1].
*   **Speed:** Rendering speed increases by nearly 40% on Deep Blending [S1]. General speedup is attributed to reduced $N$ and faster attribute lookup [S1].
*   **Quality:** Maintains or improves PSNR compared to 3DGS [S1].
*   **Limitations:** Relies on spatial redundancy; may struggle with highly unique or sparse geometric features where codebook quantization introduces artifacts [S1]. The hash grid requires careful tuning to avoid aliasing in sparse regions [S1].

## Background
C3DGS was proposed in 2024 [S1]. It addresses the scalability issues of 3DGS in unbounded scenes with large numbers of SfM points [S2]. The method builds on the observation that 3DGS produces redundant Gaussians and that spatial redundancy in color and geometry can be exploited [S1]. It uses Instant-NGP for the color field [S1].
