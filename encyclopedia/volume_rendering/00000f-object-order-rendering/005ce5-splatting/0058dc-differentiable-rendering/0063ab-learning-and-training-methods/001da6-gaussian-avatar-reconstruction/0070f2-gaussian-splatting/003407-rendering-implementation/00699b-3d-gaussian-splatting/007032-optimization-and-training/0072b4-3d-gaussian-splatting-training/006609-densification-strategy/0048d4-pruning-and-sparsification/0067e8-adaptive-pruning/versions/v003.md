# Adaptive Pruning

Also called: Triangle Pruning based on Volume Rendering Weight

## Overview
Adaptive Pruning is a sparsification technique used in triangle-based volume rendering to reduce floaters and prevent overfitting by removing primitives that contribute minimally to the final image [S1]. It distinguishes itself from sibling methods by evaluating the maximum volume rendering blending weight ($T \cdot o$) across all training views, rather than relying solely on opacity thresholds or gradient magnitudes [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** The set of 3D triangles (splats), their current opacities, the current training step, and the pruning threshold $\tau_{prune}$.
*   **Output:** A filtered set of triangles with reduced count, and re-initialized optimizers.

**Data Structures:**
*   **Triangles:** Defined by vertices, normals, and an opacity scalar $o$.
*   **Blending Weight:** For each triangle, the maximum value of $T \cdot o$ observed during rasterization across all training views, where $T$ is transmittance and $o$ is opacity [S1].
*   **Render Count:** The number of distinct training views in which a triangle was rendered with more than one pixel of coverage [S1].

**Parameters:**
*   $\tau_{prune}$: A user-defined threshold for the maximum volume rendering blending weight. Triangles with a maximum weight below this value are pruned [S1].
*   **Frequency:** Pruning executes every 200 training steps [S2, unofficial].

**Algorithm Steps:**
1.  **Check Pruning Condition:** Pruning is executed if the current training step $s$ satisfies $s > 0$, $s \pmod{200} == 0$, and $\tau_{prune} > 0$ [S2, unofficial].
2.  **Calculate Blending Weights:** During rasterization, for each triangle, compute the volume rendering blending weight $w = T \cdot o$ for every pixel it covers in every training view [S1].
3.  **Determine Maximum Weight:** For each triangle, identify the maximum blending weight $w_{max}$ observed across all training views [S1].
4.  **Count Render Occurrences:** For each triangle, count the number of training views in which it was rendered with coverage of more than one pixel [S1].
5.  **Identify Alive Splats:** A triangle is considered "alive" (kept) if it satisfies both conditions:
    *   $w_{max} > \tau_{prune}$ [S1].
    *   The render count is at least 2 [S1].
    *   *Note:* Some implementations also check if the sigmoid of the opacity parameter exceeds a threshold, but the primary criterion in the source literature is the blending weight [S2, unofficial].
6.  **Filter Buffers:** Create a boolean mask `alive` based on the criteria above. Filter all triangle buffers (vertices, normals, colors, opacities) using this mask to remove pruned triangles [S2, unofficial].
7.  **Re-initialize Optimizers:** After pruning, re-initialize the optimizers and learning rate schedulers for the remaining triangles to ensure stable training dynamics [S2, unofficial].

**Pseudocode:**
```python
def adaptive_pruning(triangles, training_views, step, tau_prune):
    """
    Prunes triangles based on maximum volume rendering blending weight.
    
    Args:
        triangles: List of triangle objects with attributes:
                   - opacities: tensor of opacity values
                   - vertices: tensor of vertex positions
                   - normals: tensor of normal vectors
                   - colors: tensor of color values
        training_views: List of training view data (camera poses, images).
        step: Current training step integer.
        tau_prune: Float threshold for pruning.
        
    Returns:
        filtered_triangles: List of kept triangle objects.
        new_optimizer: Re-initialized optimizer.
    """
    # Step 1: Check if pruning should occur
    if step <= 0 or step % 200 != 0 or tau_prune <= 0:
        return triangles, None

    alive_mask = []
    
    # Step 2-4: Calculate max blending weight and render count for each triangle
    for tri in triangles:
        max_weight = 0.0
        render_count = 0
        
        # Iterate over all training views to calculate blending weights
        for view in training_views:
            # Rasterize triangle to view
            # This step assumes a rasterization function that returns pixel coverage
            # and the transmittance T for each covered pixel.
            # [G] Implementation detail: Rasterization must compute T = exp(-sum(alpha))
            # where alpha is the alpha contribution of the triangle.
            # The blending weight for a pixel is T * o.
            
            covered_pixels = rasterize_triangle(tri, view)
            
            if len(covered_pixels) > 1:
                render_count += 1
            
            # Calculate max blending weight for this view
            view_max_weight = 0.0
            for pixel in covered_pixels:
                # T is transmittance, o is opacity
                # [G] T is typically computed as exp(-sigma * d) or similar in splatting
                # The exact formula for T depends on the specific volume rendering integrator.
                # Here we assume the rasterizer provides T and the pixel is covered.
                weight = pixel.transmittance * tri.opacity
                if weight > view_max_weight:
                    view_max_weight = weight
            
            if view_max_weight > max_weight:
                max_weight = view_max_weight
        
        # Step 5: Determine if triangle is alive
        # Condition 1: Max weight > threshold
        # Condition 2: Rendered in at least 2 views with >1 pixel coverage
        is_alive = (max_weight > tau_prune) and (render_count >= 2)
        alive_mask.append(is_alive)

    # Step 6: Filter buffers
    filtered_triangles = []
    for i, tri in enumerate(triangles):
        if alive_mask[i]:
            filtered_triangles.append(tri)

    # Step 7: Re-initialize optimizers
    # [G] The specific optimizer re-initialization depends on the framework (e.g., Adam).
    # Typically, this involves creating a new optimizer instance with the filtered parameters.
    new_optimizer = reinitialize_optimizer(filtered_triangles)

    return filtered_triangles, new_optimizer
```

**Edge Cases and Pitfalls:**
*   **Precision:** The transmittance $T$ can be very small, leading to numerical underflow in $T \cdot o$. Ensure stable computation of $T$ [S1].
*   **Boundaries:** Triangles on the boundary of the scene might have low coverage in some views but high weight in others. The multi-view requirement helps mitigate this [S1].
*   **Degenerate Input:** If a triangle has zero opacity, its blending weight is zero, and it will be pruned if $\tau_{prune} > 0$ [S1].

## Operating characteristics
*   **Time Complexity:** Pruning requires iterating over all triangles and all training views to calculate blending weights, making it $O(N \cdot V)$ per pruning step, where $N$ is the number of triangles and $V$ is the number of training views [S1].
*   **Memory Complexity:** Filtering buffers reduces memory usage proportional to the number of pruned triangles [S2, unofficial].
*   **Performance:** Reduces floaters and overfitting, leading to cleaner renderings [S1].
*   **Strengths:** Effective at removing noise and artifacts that do not contribute significantly to the image [S1].
*   **Limitations:** Requires multiple training views to be effective; triangles that are only visible in one view may be incorrectly pruned if they are not overfitted [S1].
*   **When to Use:** When floaters or overfitting are observed in the rendered output [S1].
*   **When Not to Use:** When the scene has sparse views or when triangles are intentionally sparse and meaningful [S1].

## Background
Adaptive Pruning was introduced in the context of Triangle Splatting for Real-Time Radiance Field Rendering [S1]. It is analogous to the pruning routines in 3D Gaussian Splatting [S1]. The method is designed to reduce the representation power of the model by removing triangles that explain small amounts of data within a single view [S1].
