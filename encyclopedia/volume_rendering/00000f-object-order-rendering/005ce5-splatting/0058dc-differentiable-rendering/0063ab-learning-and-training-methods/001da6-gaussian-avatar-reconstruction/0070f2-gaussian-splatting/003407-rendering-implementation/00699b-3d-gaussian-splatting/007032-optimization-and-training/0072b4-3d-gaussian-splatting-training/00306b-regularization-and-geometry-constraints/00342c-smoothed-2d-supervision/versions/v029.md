# Smoothed 2D Supervision

Also called: Adaptive Gaussian blur strategy, Progressive Gaussian Blurring

## Overview
Smoothed 2D Supervision is a regularization technique that enhances the robustness of joint optimization by smoothing the 2D supervision signal [S1][S2, unofficial]. It addresses the instability in camera alignment and the overfitting to high-frequency noise by blurring 2D training images with a parallel set of scheduled 2D Gaussian kernels [S2, unofficial]. Unlike [Frequency Regularization](6130-frequency-regularization.md) which operates in the Fourier domain, this method applies spatial-domain smoothing to the target images [S3]. It sets itself apart from [Hard and Soft Depth Regularization](9178-hard-and-soft-depth-regularization.md) by constraining the photometric signal's spectrum rather than geometric proxies [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Ground-truth 2D training images $I_{gt}$, current iteration $t$, total iterations $T_{max}$, initial kernel size $K_{init}$, initial standard deviation $\sigma_{init}$, decay interval $k_b$, and downsampling scale $s$ (if applicable).
*   **Output:** Smoothed supervision images $I_{smooth}$ used in the photometric loss $\mathcal{L}_{photo}$.

**Data Structures:**
*   **Kernel Parameters:** A tuple $(\sigma_t, K_t)$ representing the standard deviation and kernel size at iteration $t$.
*   **Image Buffer:** A 2D array or tensor of the same resolution as $I_{gt}$, potentially pre-allocated for performance.

**Steps:**
1.  **Initialize Parameters:** Set initial kernel size $K_0 = K_{init}$ (e.g., $9 \times 9$) and initial standard deviation $\sigma_0 = \sigma_{init}$ (e.g., $2.4$) [S4].
2.  **Schedule Decay:** For each training iteration $t$:
    *   Calculate the current kernel size $K_t$. If $t < T_{max}$, reduce the kernel size or $\sigma$ based on the schedule. Specifically, reduce the blur every $k_b$ iterations (e.g., $k_b = 100$) until iteration 19500 [S4].
    *   If downsampling is active, adjust the kernel size by the downsampling scale $s$ at the current stage to account for the resolution change [S4].
    *   Lower the blurring kernel size before densifying Gaussians to introduce extra signal on the gradient of erroneous Gaussians as the noise level reduces [S4].
3.  **Apply Gaussian Blur:** Convolve the ground-truth image $I_{gt}$ with a 2D Gaussian kernel $G(\sigma_t)$ to produce $I_{smooth}$:
    $$ I_{smooth} = I_{gt} * G(\sigma_t) $$
    where $G(\sigma_t)$ is defined as:
    $$ G(x, y) = \frac{1}{2\pi\sigma_t^2} e^{-\frac{x^2 + y^2}{2\sigma_t^2}} $$
    The kernel size $K_t$ is chosen to cover the significant support of the Gaussian (e.g., $K_t \approx 2 \lceil 3\sigma_t \rceil + 1$) [S4].
4.  **Compute Loss:** Calculate the photometric loss $\mathcal{L}_{photo}$ between the rendered image $I_{render}$ and the smoothed image $I_{smooth}$ [S2, unofficial].
5.  **Update:** Backpropagate the loss to update Gaussian parameters and camera poses [S1].

**Pseudocode:**
```python
def compute_smoothed_supervision(gt_image, iteration, total_iterations, 
                                 init_sigma=2.4, init_kernel_size=9, 
                                 decay_interval=100, decay_end_iter=19500,
                                 downsampling_scale=1.0):
    """
    Computes the smoothed supervision image for the current iteration.
    
    Args:
        gt_image: 2D array or tensor of the ground-truth image.
        iteration: Current training iteration number.
        total_iterations: Total number of training iterations.
        init_sigma: Initial standard deviation of the Gaussian kernel.
        init_kernel_size: Initial kernel size (e.g., 9 for 9x9).
        decay_interval: Number of iterations between kernel size reductions.
        decay_end_iter: Iteration after which blur is reduced to 0 or minimal.
        downsampling_scale: Scale factor if image is downsampled.
        
    Returns:
        smoothed_image: The blurred ground-truth image.
    """
    # 1. Determine current sigma and kernel size based on schedule
    # The schedule reduces blur progressively. 
    # Note: Exact decay function (linear/exponential) is not specified in sources.
    # We assume a linear decay of sigma or kernel size until decay_end_iter.
    
    if iteration < decay_end_iter:
        # Calculate progress factor (0 to 1)
        progress = iteration / decay_end_iter
        
        # Linear decay of sigma from init_sigma to a small value (e.g., 0.1 or 0)
        # Source [S2, unofficial] mentions exponential reduction to 0 at 10k iterations in one context,
        # but [S4] specifies reduction every 100 iterations until 19500.
        # We follow the iterative reduction described in [S4].
        
        # Number of decay steps
        steps = iteration // decay_interval
        
        # Reduce sigma linearly or in steps. 
        # A common implementation for "progressive" blur is linear decay.
        current_sigma = init_sigma * (1 - progress)
        
        # Kernel size should cover ~3-4 sigmas. 
        # Adjust for downsampling if applicable.
        base_kernel_size = int(2 * 3 * current_sigma) + 1
        # Ensure kernel size is at least 1 and odd
        base_kernel_size = max(1, base_kernel_size if base_kernel_size % 2 == 1 else base_kernel_size + 1)
        
        # If downsampling is active, scale the kernel size
        current_kernel_size = int(base_kernel_size * downsampling_scale)
        current_kernel_size = max(1, current_kernel_size if current_kernel_size % 2 == 1 else current_kernel_size + 1)
        
    else:
        # After decay_end_iter, blur is minimal or zero
        current_sigma = 0.0
        current_kernel_size = 1
        
    # 2. Apply Gaussian Blur
    if current_sigma > 0:
        # Create 2D Gaussian kernel
        # Kernel size is current_kernel_size x current_kernel_size
        kernel = create_2d_gaussian_kernel(current_kernel_size, current_sigma)
        
        # Convolve gt_image with kernel
        # Using standard convolution with 'same' padding to preserve resolution
        smoothed_image = convolve_2d(gt_image, kernel)
    else:
        smoothed_image = gt_image
        
    return smoothed_image

def create_2d_gaussian_kernel(size, sigma):
    """
    Creates a 2D Gaussian kernel.
    """
    # Generate 1D Gaussian
    x = np.arange(size) - size // 2
    kernel_1d = np.exp(-x**2 / (2 * sigma**2))
    kernel_1d /= kernel_1d.sum()
    
    # Create 2D kernel by outer product (separable)
    kernel_2d = np.outer(kernel_1d, kernel_1d)
    
    return kernel_2d

def convolve_2d(image, kernel):
    """
    Performs 2D convolution with 'same' padding.
    """
    # Implementation depends on the framework (e.g., torch.nn.functional.conv2d)
    # Here we assume a generic implementation
    # Pad image to handle boundaries
    pad_size = kernel.shape[0] // 2
    padded_image = np.pad(image, pad_size, mode='reflect')
    
    # Perform convolution
    # This is a simplified representation; actual implementation uses efficient libraries
    smoothed = np.zeros_like(image)
    h, w = image.shape
    kh, kw = kernel.shape
    
    for i in range(h):
        for j in range(w):
            smoothed[i, j] = np.sum(padded_image[i:i+kh, j:j+kw] * kernel)
            
    return smoothed
```

**Parameters:**
*   $K_{init}$: Initial kernel size, typically $9 \times 9$ [S4].
*   $\sigma_{init}$: Initial standard deviation, typically $2.4$ [S4].
*   $k_b$: Decay interval, typically $100$ iterations [S4].
*   $T_{decay}$: Iteration to stop significant blurring, typically $19500$ [S4].

**Edge Cases and Pitfalls:**
*   **Boundary Effects:** Gaussian convolution can introduce artifacts at image boundaries. Use 'reflect' or 'replicate' padding [G].
*   **Downsampling Mismatch:** If downsampling is used, the kernel size must be scaled by the downsampling factor to maintain the correct spatial frequency suppression [S4].
*   **Over-smoothing:** If the decay is too slow, high-frequency details may be lost, leading to blurry reconstructions. If too fast, the optimization may not converge stably [S2, unofficial].

## Subtopics

### [Randomly Scaled Kernel Parameter](7875-randomly-scaled-kernel-parameter.md)
Randomly Scaled Kernel Parameter is a regularization technique used during joint optimization to mitigate weak and noisy gradient signals. It addresses the insufficiency of using a single-size kernel for diverse real-world scene structures, where a fixed kernel may be overly aggressive in some contexts and overly gentle in others. By randomly scaling the kernel size, it allows combinations of different-sized kernels to guide the optimization, resulting in a more robust training schedule.

### [Multiscale Pre-convolved Representation](10911-multiscale-pre-convolved-representation.md)
A regularization technique for neural illumination fields that stabilizes the decomposition of object materials from environmental illumination by enforcing consistency with pre-computed, roughness-adapted background reflections. It addresses the ambiguity where diffuse object color is incorrectly absorbed into the estimated environment map, a problem inherent to high-dimensional neural illumination representations. Unlike methods that ignore the background or treat it as static, this method explicitly models the relationship between rough refractive surfaces and the convolved background, allowing for realistic specular reflections even when roughness exceeds the kernel scale. The technique builds on [Smoothed 2D Supervision](7213-smoothed-2d-supervision.md) by applying discrete Gaussian blur kernels to the background to stabilize convergence.

### [Soft Rasterization](13687-soft-rasterization.md)
Soft rasterization is a differentiable rendering technique that mitigates the discontinuities inherent in standard rasterization by blending facet contributions for pixels near primitive edges. It solves the problem of sparse and vanishing gradients caused by the non-uniformity of bilinear interpolation operands, which typically have similar values except at object boundaries. Unlike standard hard rasterization, it yields slightly distorted images but allows backpropagating more useful gradients, thereby stabilizing optimization and preventing gradient vanishing at edges.

### Platonic GAN (pGAN)
A learning-based method for 2D supervision per class of reconstructed objects, used here to pre-train a network for per-frame supervision of rising smoke [S5]. It improves depth artifacts but lacks temporal constraints, leading to incoherent solutions if not integrated with temporal self-supervision [S5].

## Operating characteristics
*   **Time Complexity:** The additional cost is the convolution of the ground-truth image with a Gaussian kernel. This is $O(N \cdot K^2)$ per image per iteration, where $N$ is the number of pixels and $K$ is the kernel size. Since the kernel size is small (e.g., $9 \times 9$) and the operation is performed on the target images (not the scene representation), the overhead is minimal [S4].
*   **Memory Complexity:** Requires storing the smoothed images, which is $O(N)$ per image. This is negligible compared to the scene representation [S4].
*   **Performance:** On DTU 3-view, it achieves 19.72 PSNR, improving over the baseline of 19.54 [S3]. It reduces training iterations to 50k compared to 200k for previous methods, reducing training time to 25% [S1].
*   **Strengths:** Stabilizes camera alignment, restricts the spectrum of the learned 3D scene, and mitigates noisy gradients [S2, unofficial]. It is experimentally proven crucial for successful pose refinement [S1].
*   **Limitations:** It is a handcrafted strategy and cannot fully align frequency relationships compared to adaptive methods like [FreGS](9212-fregs.md) or [Cross-scale geometric adaptation](10796-cross-scale-geometric-adaptation.md) [S3].
*   **When to Use:** When joint optimization of camera poses and scene representation is unstable, or when high-frequency noise leads to poor convergence [S1][S2, unofficial].
*   **When Not to Use:** When adaptive frequency alignment is available and preferred, or when computational resources are extremely limited and even the small convolution overhead is prohibitive [S3].

## Background
Smoothed 2D Supervision was introduced as part of techniques to improve the robustness of joint optimization of camera poses and decomposed low-rank tensorial radiance fields [S1][S2, unofficial]. It was inspired by the analysis of spectral control and the observation that blurring 2D training images helps stabilize optimization [S2, unofficial]. The method was further refined in the context of Gaussian Splatting with "Tricks" to balance efficiency and quality [S4]. It is used in novel view synthesis and pose refinement tasks [S1].
