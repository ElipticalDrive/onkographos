# Rendering Implementation

Also called: 3D Gaussian Splatting Rasterization Pipeline, 3DGS Rendering

## Overview
Rendering Implementation defines the computational pipeline that transforms a set of 3D Gaussian primitives into a 2D image. It solves the problem of efficiently evaluating the volume rendering equation for explicit, particle-based scene representations by leveraging hardware-accelerated rasterization . It sets itself apart from its siblings by providing the foundational mechanisms—specifically the projection from 3D covariance to 2D screen-space conics and the alpha compositing logic—that enable both the high-performance GPU rasterization of [3D Gaussian Splatting](2812-3d-gaussian-splatting.md) and the display-only CPU-sorted instancing of [3D Gaussian Splatting Rendering (CPU-Sorted, Instanced)](2058-3d-gaussian-splatting-rendering-cpu-sorted-instanced.md).

## Shared principles
All rendering implementations for 3D Gaussians share the following mathematical and procedural core:

1.  **Parameter Activation**: Raw training parameters are transformed into geometric primitives:
    *   Rotation $q$ is normalized: $q_{norm} = q / \|q\|$ [Parent].
    *   Scale $s$ is exponentiated to ensure positivity: $s_{eff} = \exp(s)$ [Parent].
    *   Opacity $\alpha$ is sigmoided: $\alpha_{eff} = \sigma(\alpha)$ [Parent].
    *   The 3D covariance matrix is constructed as $\boldsymbol{\Sigma}_{3D} = \mathbf{R} \mathbf{S} \mathbf{S}^T \mathbf{R}^T$, where $\mathbf{R}$ is the rotation matrix derived from $q_{norm}$ and $\mathbf{S} = \text{diag}(s_{eff})$ [Parent].

2.  **Camera Space Transformation**:
    *   The mean position is transformed to camera space: $\boldsymbol{\mu}' = \mathbf{V} \boldsymbol{\mu}$ [Parent].
    *   The covariance is transformed using the upper-left $3 \times 3$ submatrix of the view matrix $\mathbf{V}$:
        $$ \boldsymbol{\Sigma}' = \mathbf{V}_{1:3, 1:3} \boldsymbol{\Sigma}_{3D} \mathbf{V}_{1:3, 1:3}^T $$
        [Parent].

3.  **Screen-Space Projection**:
    *   The Jacobian $\mathbf{J}$ of the projective projection at $\boldsymbol{\mu}'$ is computed:
        $$ \mathbf{J} = \begin{pmatrix} \frac{f_x}{\mu'_z} & 0 & -\frac{f_x \mu'_x}{\mu'_z^2} \\ 0 & \frac{f_y}{\mu'_z} & -\frac{f_y \mu'_y}{\mu'_z^2} \end{pmatrix} $$
        [Parent].
    *   The 2D screen-space covariance is:
        $$ \boldsymbol{\Sigma}_{2D} = \mathbf{J} \boldsymbol{\Sigma}' \mathbf{J}^T $$
        [Parent].
    *   The 2D mean is:
        $$ \boldsymbol{\mu}_{2D} = \begin{pmatrix} \frac{f_x \mu'_x}{\mu'_z} + c_x \\ \frac{f_y \mu'_y}{\mu'_z} + c_y \end{pmatrix} $$
        [Parent].

4.  **Alpha Compositing**:
    *   Gaussians are sorted by depth (camera-space $z$) [Parent].
    *   For each pixel, color $C$ and transmittance $T$ are accumulated:
        $$ C \leftarrow C + T \cdot \alpha_{pixel} \cdot \mathbf{c} $$
        $$ T \leftarrow T \cdot (1 - \alpha_{pixel}) $$
        [Parent].
    *   Early termination occurs when $T$ drops below a threshold (e.g., 0.05) [Parent].

## Subtopics

### [3D Gaussian Splatting Rendering (CPU-Sorted, Instanced)](2058-3d-gaussian-splatting-rendering-cpu-sorted-instanced.md)
A display-only technique that projects Gaussians to 2D quads, sorts them by depth on the CPU, and renders them via hardware-instanced drawing with standard alpha blending. It avoids GPU tile-based complexity by relying on CPU sorting.

### [3D Gaussian Splatting](2812-3d-gaussian-splatting.md)
The primary real-time rendering method using GPU-based global depth sorting and tile-based rasterization. It computes 2D conics for efficient pixel-wise alpha evaluation and supports view-dependent color via spherical harmonics.

## Background
The rendering pipeline originates from the 3D Gaussian Splatting (3DGS) framework, which introduced explicit Gaussian primitives to replace volumetric ray marching for real-time novel view synthesis . The method was developed to overcome the computational cost of NeRFs while maintaining high visual fidelity . The specific projection and rasterization techniques described here are standard implementations of the 3DGS rendering equation .
