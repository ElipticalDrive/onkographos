# GlobalSplat

Also called: GlobalSplat: Efficient Feed-Forward 3D Gaussian Splatting via Global Scene Tokens

## Overview
GlobalSplat is a feed-forward 3D Gaussian Splatting framework that aligns multi-view inputs into a fixed set of global latent scene tokens before decoding explicit 3D geometry, preventing representation bloat and ensuring global consistency [S1]. Unlike sibling methods that form primitives in dense view-aligned spaces and align them globally afterward, GlobalSplat aggregates multi-view inputs into a fixed number of latent tokens (2048) regardless of input view count, then decodes these tokens into a strict, view-invariant budget of Gaussians (16K) [S1]. This approach achieves competitive novel-view synthesis quality with significantly lower GPU memory usage, smaller disk footprint, and faster inference times compared to dense baselines [S1].

## How it works
GlobalSplat operates in four main phases: scene normalization and feature extraction, iterative latent token refinement via a dual-branch encoder, coarse-to-fine decoding of Gaussian candidates, and differentiable rendering with specific training objectives.

### Inputs and Outputs
**Inputs:**
*   A set of $C$ input images $\mathcal{I} = \{I_i\}_{i=1}^C$ with corresponding camera poses $T_i$ (rotation $R_i$, translation $t_i$) and intrinsics $K_i$.
*   Target image $I_t$ and camera $\pi_t$ for training loss computation.

**Outputs:**
*   A fixed set of $N = 16,384$ 3D Gaussians, each defined by mean $\mu$, scale $s$, rotation $r$, opacity $\alpha$, and spherical harmonic coefficients $c$.

### Data Structures
**Latent Tokens:**
*   A set of $M=2048$ learnable latent scene tokens $l_j \in \mathbb{R}^{512}$ for $j=1 \dots M$.
*   Learnable register tokens (dimension not explicitly specified, used for global context) [S1].

**Gaussian Candidates:**
*   For each latent token $p$, the decoder predicts $K_s=16$ candidates.
*   Geometry attributes per token $p$:
    *   Means: $\mathbf{X}_p \in \mathbb{R}^{16 \times 3}$
    *   Scales: $\mathbf{S}_p \in \mathbb{R}^{16 \times 3}$
    *   Rotations: $\mathbf{R}_p \in \mathbb{R}^{16 \times 6}$ (6D parameterization)
    *   Opacity Logits: $\mathbf{O}_p \in \mathbb{R}^{16 \times 1}$
    *   Importance Scores: $\boldsymbol{\ell}_p \in \mathbb{R}^{16 \times 1}$
*   Appearance attributes per token $p$:
    *   SH Coefficients: $\mathbf{C}_p \in \mathbb{R}^{16 \times (3 D_{\mathrm{SH}})}$, where $D_{\mathrm{SH}} = 16$ for SH degree 3 [S1].

**Input Patches:**
*   Patchified RGB tokens $u_{i,p}^{\mathrm{rgb}}$ and camera tokens $u_{i,p}^{\mathrm{cam}}$ for each view $i$ and patch $p$.

### Parameters
*   **Latent Tokens ($M$):** 2048 [S1].
*   **Latent Dimension ($d$):** 512 [S1].
*   **Encoder Blocks ($B$):** 4 [S1].
*   **Self-Attention Depth ($L$):** 2 blocks per branch [S1].
*   **Candidates per Token ($K_s$):** 16 [S1].
*   **SH Degree:** 3 ($D_{\mathrm{SH}} = 16$) [S1].
*   **Final Capacity ($G$):** 8 Gaussians per token (Stage $s=3$) [S1].
*   **Total Gaussians ($N$):** $2048 \times 8 = 16,384$ [S1].
*   **Input Resolution:** 256x256 [S1].
*   **Patch Size:** 8x8 [S1].
*   **Gaussian Initialization:**
    *   Means: Fixed forward offset of 1.5 [S1].
    *   Scales: Log-space offset from -2 [S1].
    *   Opacity: Logit-space offset from -5 [S1].
    *   Rotations: Residual offsets from static rotation [S1].

### Steps

1.  **Scene Normalization:**
    *   Compute the canonical frame origin: $\bar{o} = \frac{1}{C} \sum_{i=1}^C o_i$ [S1].
    *   Compute axes by averaging camera viewing directions and re-orthonormalizing to form $T_{\text{avg}}$ [S1].
    *   Transform all cameras: $\hat{T}_i = T_{\text{avg}}^{-1} T_i$ [S1].
    *   Compute scene scale: $s = \max_{a,b} \|\hat{o}_a - \hat{o}_b\|_2$ [S1].
    *   Normalize translations: $\tilde{o}_i = \frac{\hat{o}_i}{s}$ [S1].

2.  **Input Feature Extraction:**
    *   Preprocess images: Resize to height 256, round width to multiple of 8, centered square crop, resize to 256x256 [S1].
    *   Extract patchified RGB features $u_{i,p}^{\mathrm{rgb}}$ [S1].
    *   Compute dense Plücker-ray features $r_{i,p}$ and patchify [S1].
    *   Map rays: $\hat{r}_{i,p} = W_{\mathrm{ray}} r_{i,p}$ [S1].
    *   Encode camera context: $e_i = W_{\mathrm{proj}}([\mathrm{MLP}_{K}(\phi(\kappa_i)); \mathrm{PE}(o_i)])$ [S1].
    *   Form camera token: $u_{i,p}^{\mathrm{cam}} = \hat{r}_{i,p} + e_i$ [S1].
    *   Concatenate: $u_{i,p} = [u_{i,p}^{\mathrm{cam}} ; u_{i,p}^{\mathrm{rgb}}]$ [S1].

3.  **Latent Token Refinement (Dual-Branch Encoder):**
    *   Initialize latent tokens $l_j$ and register tokens [S1].
    *   For each encoder block $b \in \{1 \dots B\}$:
        *   Project latent tokens to streams: $f_{\text{geo}}^{(0)}, f_{\text{app}}^{(0)} = \mathrm{Proj}_{\text{geo}}(l), \mathrm{Proj}_{\text{app}}(l)$ [S1].
        *   For each branch $i \in \{\text{geo}, \text{app}\}$:
            *   Cross-attention with input patches: $f_i^{\text{cross}} = \mathrm{CrossAtt}_i(x, f_i^{(j)})$ [S1].
            *   Self-attention blocks ($L=2$): $f_i^{(j+1)} = \mathrm{SelfAtt}_i(f_i^{\text{cross}})$ [S1].
        *   Fuse streams: $l_{\text{geo}}^{(j+1)}, l_{\text{app}}^{(j+1)} = \mathrm{MLP}(\mathrm{Concat}(f_{\text{geo}}^{(j)}, f_{\text{app}}^{(j)}))$ [S1].
    *   Final latent tokens: $l_{\text{geo}}^{(B)}, l_{\text{app}}^{(B)}$ [S1].

4.  **Gaussian Candidate Prediction:**
    *   Decode geometry: $G_{\text{geo}} = \mathrm{Proj}_{\text{geo}}^{\text{dec}}(l_{\text{geo}}^{(B)})$ [S1].
    *   Decode appearance: $G_{\text{app}} = \mathrm{Proj}_{\text{app}}^{\text{dec}}(l_{\text{app}}^{(B)})$ [S1].
    *   For each latent token $p$, predict 16 candidates for $\mathbf{X}_p, \mathbf{S}_p, \mathbf{R}_p, \mathbf{O}_p, \boldsymbol{\ell}_p, \mathbf{C}_p$ [S1].

5.  **Coarse-to-Fine Merging (Inference/Training):**
    *   Determine stage $s$ (final model uses $s=3$, so $G=8$) [S1].
    *   Partition 16 candidates into $G$ groups of size $b_s = 16/G$ [S1].
    *   For each group $g$ and candidate $i$:
        *   Compute weight: $w_{p,g,i} = \frac{\exp(\ell_{p,g,i}/\tau)}{\sum_{j=1}^{b_s}\exp(\ell_{p,g,j}/\tau)}$ [S1].
        *   Merge attributes: $\bar{\mathbf{z}}_{p,g} = \sum_{i=1}^{b_s} w_{p,g,i} \mathbf{z}_{p,g,i}$ [S1].
    *   Convert predicted parameters to final Gaussian attributes:
        *   $\mu = \bar{\mathbf{X}} + \text{offset}$
        *   $s = \exp(\bar{\mathbf{S}} - 2)$
        *   $\alpha = \sigma(\bar{\mathbf{O}} - 5)$
        *   $r = \text{Normalize6D}(\bar{\mathbf{R}} + \text{static\_rot})$
        *   $c = \bar{\mathbf{C}}$ [S1].

6.  **Differentiable Rendering:**
    *   Project Gaussians to 2D.
    *   Render image $\hat{I}_t$ using alpha blending: $C = \sum_{i=1}^{M} c_i \alpha'_i \prod_{j=1}^{i-1} (1 - \alpha'_j)$ [S1].

import torch
import torch.nn as nn
import torch.nn.functional as F

class GlobalSplat:
    def __init__(self, num_tokens=2048, token_dim=512, num_candidates=16, final_stage=3):
        self.M = num_tokens
        self.d = token_dim
        self.K_s = num_candidates
        self.final_stage = final_stage
        self.G = 2 ** final_stage  # 8
        self.b_s = 16 // self.G    # 2
        
        # Learnable tokens
        self.latent_tokens = nn.Parameter(torch.randn(self.M, self.d))
        self.register_tokens = nn.Parameter(torch.randn(self.M, self.d)) # Placeholder for register tokens
        
        # Encoder components
        self.encoder_blocks = nn.ModuleList([
            DualBranchEncoderBlock(token_dim) for _ in range(4)
        ])
        
        # Decoder components
        self.geo_decoder_proj = nn.Linear(token_dim, 16 * (3 + 3 + 6 + 1 + 1)) # X, S, R, O, l
        self.app_decoder_proj = nn.Linear(token_dim, 16 * (3 * 16)) # C (SH degree 3)
        
        # Projection layers for streams
        self.proj_geo = nn.Linear(token_dim, token_dim)
        self.proj_app = nn.Linear(token_dim, token_dim)
        
        # Mixer MLP
        self.mixer_mlp = nn.Sequential(
            nn.Linear(token_dim * 2, token_dim),
            nn.ReLU(),
            nn.Linear(token_dim, token_dim)
        )

    def normalize_scene(self, poses, intrinsics):
        """
        Normalize camera poses to canonical frame.
        poses: (C, 4, 4) or (C, 3, 4)
        """
        # Extract centers
        centers = poses[:, :3, 3] # (C, 3)
        
        # Canonical origin
        o_avg = centers.mean(dim=0) # (3,)
        
        # Average viewing direction (simplified, assuming z-axis is view direction in local frame)
        # In practice, average rotation matrices or viewing vectors
        # Re-orthonormalize to get T_avg
        # T_avg_inv = ... (Implementation detail omitted, assume function exists)
        T_avg_inv = self.compute_average_pose_inv(poses)
        
        # Transform poses
        T_hat = T_avg_inv @ poses # (C, 4, 4)
        o_hat = T_hat[:, :3, 3]
        
        # Scale normalization
        max_dist = 0.0
        for i in range(len(o_hat)):
            for j in range(i + 1, len(o_hat)):
                dist = torch.norm(o_hat[i] - o_hat[j])
                if dist > max_dist:
                    max_dist = dist
        s = max_dist
        
        o_tilde = o_hat / s
        return o_tilde, T_hat

    def extract_features(self, images, poses, intrinsics):
        """
        images: (C, 3, 256, 256)
        """
        # Patchify images
        # Assuming ViT or similar encoder produces tokens
        # u_rgb: (C, 2048, 512) for 256x256 image with 8x8 patches (32x32=1024 patches? No, 256/8=32, 32*32=1024)
        # Note: Source says 2048 latent scene tokens, but input patches might differ.
        # Source says "process 8x8 image patches to produce 2048 latent scene tokens" via encoder rounds.
        # Let's assume view encoder produces patch tokens.
        
        # Placeholder for View Encoder
        u_rgb = self.view_encoder(images) # (C, N_patches, 512)
        
        # Plücker rays and camera codes
        # r_i,p: (C, N_patches, 6)
        r_patches = self.compute_plucker_rays(poses, intrinsics, images.shape)
        
        # Map rays
        W_ray = nn.Linear(6, 256)
        r_hat = W_ray(r_patches) # (C, N_patches, 256)
        
        # Camera code
        # e_i: (C, 256)
        e_cam = self.encode_camera(poses, intrinsics)
        
        # Broadcast e_cam to patches
        u_cam = r_hat + e_cam.unsqueeze(1) # (C, N_patches, 256)
        
        # Concatenate
        # u_rgb is 512, u_cam is 256 -> 768?
        # Source says input embedding uses 512 for RGB and 256 for ray.
        # Concatenation: [u_cam; u_rgb] -> (C, N_patches, 768)
        u_input = torch.cat([u_cam, u_rgb], dim=-1)
        
        return u_input

    def encode(self, u_input):
        """
        u_input: (C, N_patches, 768)
        """
        # Initialize latent tokens
        l = self.latent_tokens.clone() # (M, 512)
        
        for block in self.encoder_blocks:
            # Project to streams
            f_geo = self.proj_geo(l)
            f_app = self.proj_app(l)
            
            # Cross Attention
            # x = u_input
            f_geo_cross = block.cross_att_geo(x=u_input, q=f_geo)
            f_app_cross = block.cross_att_app(x=u_input, q=f_app)
            
            # Self Attention (L=2)
            f_geo = block.self_att_geo(f_geo_cross)
            f_app = block.self_att_app(f_app_cross)
            
            # Fuse
            fused = torch.cat([f_geo, f_app], dim=-1)
            l = self.mixer_mlp(fused)
            
        return l

    def decode(self, l_geo, l_app):
        """
        l_geo, l_app: (M, 512)
        """
        # Predict candidates
        geo_params = self.geo_decoder_proj(l_geo) # (M, 16 * 14)
        app_params = self.app_decoder_proj(l_app) # (M, 16 * 48)
        
        # Reshape
        # X: (M, 16, 3), S: (M, 16, 3), R: (M, 16, 6), O: (M, 16, 1), l: (M, 16, 1)
        # C: (M, 16, 48)
        
        geo_flat = geo_params.view(-1, 16, 14)
        X = geo_flat[:, :, :3]
        S = geo_flat[:, :, 3:6]
        R = geo_flat[:, :, 6:12]
        O = geo_flat[:, :, 12:13]
        l_scores = geo_flat[:, :, 13:14]
        
        C = app_params.view(-1, 16, 48)
        
        return X, S, R, O, l_scores, C

    def merge_candidates(self, X, S, R, O, l_scores, C, stage=None):
        """
        Merge 16 candidates into G Gaussians per token.
        """
        if stage is None:
            stage = self.final_stage
            
        G = 2 ** stage
        b_s = 16 // G
        
        # Partition into groups
        # X: (M, 16, 3) -> (M, G, b_s, 3)
        X = X.view(-1, G, b_s, 3)
        S = S.view(-1, G, b_s, 3)
        R = R.view(-1, G, b_s, 6)
        O = O.view(-1, G, b_s, 1)
        l_scores = l_scores.view(-1, G, b_s, 1)
        C = C.view(-1, G, b_s, 48)
        
        # Compute weights
        # l_scores: (M, G, b_s, 1)
        weights = F.softmax(l_scores / 0.1, dim=2) # Temperature tau=0.1 assumed
        
        # Merge
        X_merged = (weights * X).sum(dim=2) # (M, G, 3)
        S_merged = (weights * S).sum(dim=2)
        R_merged = (weights * R).sum(dim=2)
        O_merged = (weights * O).sum(dim=2)
        C_merged = (weights * C).sum(dim=2)
        
        return X_merged, S_merged, R_merged, O_merged, C_merged

    def forward(self, images, poses, intrinsics, target_image=None, target_pose=None):
        # 1. Normalize
        o_tilde, T_hat = self.normalize_scene(poses, intrinsics)
        
        # 2. Features
        u_input = self.extract_features(images, poses, intrinsics)
        
        # 3. Encode
        l = self.encode(u_input)
        
        # Split into geo/app (assuming split happens after encoder or within)
        # Source says dual branch encoder produces l_geo and l_app
        # Assuming l is split or projected
        l_geo = l[:, :self.d//2]
        l_app = l[:, self.d//2:]
        
        # 4. Decode
        X, S, R, O, l_scores, C = self.decode(l_geo, l_app)
        
        # 5. Merge
        X_m, S_m, R_m, O_m, C_m = self.merge_candidates(X, S, R, O, l_scores, C)
        
        # 6. Convert to Gaussians
        # Means
        mu = X_m + 1.5 # Offset
        # Scales
        sigma = torch.exp(S_m - 2)
        # Opacity
        alpha = torch.sigmoid(O_m - 5)
        # Rotations (6D to matrix)
        rot = self.normalize_6d(R_m)
        # Colors
        colors = C_m
        
        # Render if target provided
        if target_image is not None:
            rendered = self.render_gaussians(mu, sigma, rot, alpha, colors, target_pose)
            loss = self.compute_loss(rendered, target_image)
            return rendered, loss
        else:
            return self.render_gaussians(mu, sigma, rot, alpha, colors, poses[0]) # Render first view or default

    def compute_loss(self, rendered, target):
        # L_ren
        l2 = torch.mean((rendered - target) ** 2)

        # L_con (placeholder)
        l_con = 0.0
        # L_reg (placeholder)
        l_reg = 0.0
        
        return l2 + l_perc + l_con + l_reg

### Edge Cases and Pitfalls
*   **Scale Ambiguity:** Monocular or sparse-view reconstruction suffers from scale ambiguity. GlobalSplat handles this by normalizing the scene to a canonical coordinate system where camera translations are scaled to lie within $[-1, 1]^3$ [S1].
*   **Representation Bloat:** Without the coarse-to-fine curriculum, the model might produce too many Gaussians. The curriculum starts with $G=1$ and increments to $G=8$, preventing bloat [S1].
*   **Gradient Conflicts:** The dual-branch architecture disentangles geometry and appearance to prevent texture from masking poor structural predictions [S1].
*   **Precision:** Rotations are predicted as 6D residuals from a static rotation to ensure valid rotation matrices [S1].

## Operating characteristics
*   **Time Complexity:** Inference is a single forward pass, taking <78 ms on RealEstate10K with 24 views [S1].
*   **Memory Complexity:** Peak GPU memory is 1.79 GB for 24 views on RealEstate10K [S1]. Disk size is ~4 MB for 16K Gaussians [S1].
*   **Performance:** On RealEstate10K with 24 views, GlobalSplat achieves 28.5 PSNR with 16K Gaussians [S1]. With 12 views, GlobalSplat16K achieves 28.57 PSNR, 0.885 SSIM, 0.138 LPIPS [S1].
*   **Strengths:** Compact representation (16K Gaussians), fast inference, low memory usage, global consistency [S1].
*   **Limitations:** Fixed number of Gaussians may limit detail in very complex scenes compared to adaptive methods [S1].

## Background
GlobalSplat was introduced by R. Itkin et al. in 2025 [S1]. It addresses the limitation of current feed-forward 3DGS pipelines where primitives are formed in dense view-aligned spaces, leading to representation bloat and fragile global consistency [S1]. It builds on the principles of feed-forward 3DGS but introduces a global latent scene token approach [S1].
