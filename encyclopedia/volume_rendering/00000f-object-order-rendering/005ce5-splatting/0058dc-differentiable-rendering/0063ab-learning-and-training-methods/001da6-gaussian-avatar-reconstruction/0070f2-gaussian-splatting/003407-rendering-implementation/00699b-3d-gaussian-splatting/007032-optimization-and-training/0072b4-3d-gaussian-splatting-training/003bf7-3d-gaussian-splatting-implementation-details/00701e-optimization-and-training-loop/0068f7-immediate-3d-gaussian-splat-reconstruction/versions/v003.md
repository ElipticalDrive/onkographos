# Immediate 3D Gaussian Splat Reconstruction

Also called: Immediate 3D Gaussian Splat Reconstruction Pipeline, Incremental 3D Gaussian Splatting Reconstruction, Incremental 3DGS with Loop Closure, Main Pipeline for Immediate 3D Gaussian Splat Reconstruction, Real-time 3DGS Reconstruction, Streaming 3D Gaussian Splatting Pipeline, Two-Level Matching 3DGS

## Overview
Immediate 3D Gaussian Splat Reconstruction is a streaming pipeline that processes an unordered sequence of RGB images to produce a real-time 3D Gaussian Splatting (3DGS) model [S1]. It solves the problem of incremental reconstruction from unordered inputs by maintaining global consistency through loop closure and a covisibility graph, while optimizing Gaussian primitives in real-time [S1]. Unlike batch reconstruction methods, it interleaves matching, pose estimation, and Gaussian placement with a fixed local optimization window, keeping the delay between capture and processing start below the time to handle two keyframes (<0.8 s) [S1]. It distinguishes itself from other training loops by its explicit handling of disjoint sequences via shelving and its linear-scaling fast bundle adjustment, which restricts landmark observations to covisibility-based subsets rather than all keyframes in the window [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A stream of unordered RGB images $\{I_1, I_2, \dots\}$ [S1].
*   **Output:** A 3DGS reconstruction consisting of optimized Gaussian primitives and camera poses [S1].

**Data Structures:**
1.  **Registered Keyframes ($M$):** A set of camera poses and images that have been successfully integrated into the global map [S1].
2.  **Covisibility Graph ($G_{graph}$):** A triple $(M, E, W)$ representing the set of registered keyframes, edges $E$ between them, and edge weights $W$ [S1].
3.  **Active Gaussian Primitives ($G_{prims}$):** The set of 3D Gaussians currently in the scene [S1].
4.  **Gaussian Hierarchy ($H$):** A structure managing the spatial organization of Gaussians [S1].
5.  **Shelf ($Shelf$):** A buffer for unmatched frames that fail initial registration [S1].

**Parameters:**
*   $N=20$: The fixed number of keyframes selected for local bundle adjustment [S1].
*   $\tau_{lc} = 5$: The threshold for the minimum graph distance (hops) between clusters to trigger loop closure [S1].
*   $\tau_v$: The threshold for the minimum number of valid matching pairs required to trigger loop closure [S1].
*   Welding Window ($W$): Defined as the union of the top $N/2$ keyframes from cluster $C1$ and the top $N/2$ keyframes from cluster $C2$ [S1].

**Pitfalls:**
*   **Variable Name Collision:** The source pseudocode uses $G$ for both the covisibility graph and active Gaussian primitives. Implementers must distinguish them (e.g., $G_{graph}$ vs $G_{prims}$) to avoid overwriting [S1].
*   **Accumulated Drift:** Without loop closure, accumulated drift causes Gaussians to be optimized incorrectly, introducing spiky artifacts and superimposition [S1].
*   **Memory Constraints:** While this method is efficient, related feed-forward methods like AnySplat run out of memory on high-end hardware (H100) for large scenes due to VRAM limitations and image size constraints (448x448) [S1].

**Algorithm:**

```python
def main_pipeline(image_stream):
    # 1. Initialize data structures
    M = set()                  # Registered keyframes
    G_graph = (set(), set(), set()) # Covisibility graph (M, E, W)
    G_prims = set()            # Active Gaussian primitives
    H = set()                  # Gaussian hierarchy
    Shelf = set()              # Shelved unmatched frames

    # 2. Bootstrap the reconstruction
    # Process the first 8 well-connected keyframes to initialize the map
    bootstrap_keyframes = get_first_8_well_connected_images(image_stream)
    for I_q in bootstrap_keyframes:
        process_image(I_q, M, G_graph, G_prims, H, Shelf)

    # 3. Iterate over remaining incoming images
    for I_q in image_stream:
        process_image(I_q, M, G_graph, G_prims, H, Shelf)

def process_image(I_q, M, G_graph, G_prims, H, Shelf):
    # 4. Two-Level Matching
    # Extract MixVPR and XFeat features for four rotations (0, 90, 180, 270 degrees)
    # Use MixVPR to detect orientation, then select corresponding XFeat features
    V, K_prime = TwoLevelMatching(I_q, M)

    # 5. Handle unmatched frames
    if not V:
        Shelf.add(I_q)
        return

    # 6. Update Covisibility Graph
    UpdateGraph(G_graph, I_q, V)

    # 7. Loop Detection
    loop, C1, C2 = LoopDetection(I_q, K_prime, G_graph)

    # 8. Local Bundle Adjustment
    # Select N=20 keyframes for optimization
    S = SelectKeyframes({I_q}, G_graph, N=20)
    LocalBA(S, G_prims)

    # 9. Loop Closure Handling
    if loop:
        # Welding BA aligns the disjoint clusters
        WeldingBA(C1, C2, G_graph)
        # Propagate corrections through the graph
        BackbonePropagation(G_graph, C1, C2, G_prims)

    # 10. Place New Gaussians
    PlaceGaussians(I_q, G_graph)

    # 11. Update State
    M.add(I_q)
    UpdateHierarchy(G_graph, H, I_q)
    OptimizeGaussians(M, G_graph)

    # 12. Retry Shelved Frames
    RetryShelved(Shelf, M, G_graph)

def TwoLevelMatching(I_q, M):
    # Extract features for 4 rotations
    features_0 = ExtractFeatures(I_q, rot=0)
    features_90 = ExtractFeatures(I_q, rot=90)
    features_180 = ExtractFeatures(I_q, rot=180)
    features_270 = ExtractFeatures(I_q, rot=270)
    
    # Detect orientation using MixVPR
    orientation = MixVPR_Detect(I_q, M)
    
    # Select correct feature set based on orientation
    selected_features = features_0 if orientation == 0 else \
                        features_90 if orientation == 90 else \
                        features_180 if orientation == 180 else features_270
                        
    # Match using XFeat
    V, K_prime = XFeat_Match(selected_features, M)
    return V, K_prime

def LoopDetection(I_q, K_prime, G_graph):
    # Identify disjoint clusters in the visual neighborhood
    C1, C2 = FindClusters(I_q, K_prime, G_graph)
    
    # Calculate graph distance between clusters
    d_G = min_shortest_path_hops(C1, C2, G_graph)
    
    # Check loop closure conditions
    if d_G > 5 and min(len(C1), len(C2)) > tau_v:
        return True, C1, C2
    return False, None, None

def WeldingBA(C1, C2, G_graph):
    # Select anchor keyframes based on connectivity
    I_a1 = argmax_{I in C1} connectivity(I, W)
    I_a2 = argmax_{I in C2} connectivity(I, W)
    
    # Compute rigid transform between optimized and initial poses
    T_delta = T_a_opt * inverse(T_a_init)
    
    # Estimate scale change from landmark depth variations
    s_delta = EstimateScaleChange(C1, C2)
    
    # Compose similarity transform
    S_delta = Sim3(T_delta, s_delta)
    
    # Optimize poses in the welding window
    LocalBA(W, G_prims)

def BackbonePropagation(G_graph, C1, C2, G_prims):
    # Build backbone path using Dijkstra's algorithm
    B = Dijkstra(I_a1, I_a2, G_graph)
    
    # Interpolate transformation along backbone
    for I_b in B:
        alpha = distance(I_b, I_a2) / distance(I_a1, I_a2)
        # Interpolate rotation using 6D representation
        # Interpolate scale linearly: s_delta,b = s_delta ^ alpha
        S_delta_b = InterpSim3(S_delta, alpha)
        
        # Apply to keyframes not in welding window
        for I_i not in W:
            I_b_star = argmin_{I_b in B} distance(I_i, I_b)
            T_i_new = S_delta_b_star * T_i_old
            
    # Update Gaussians based on new poses
    UpdateGaussians(G_prims)

def LocalBA(S, G_prims):
    # Fast BA: Restrict landmark observations to covisibility-based subset
    # This scales linearly with N, unlike quadratic scaling in previous methods
    OptimizePosesAndGaussians(S, G_prims)
```

## Operating characteristics
*   **Time Complexity:** The method scales linearly with the number of keyframes in the local window by restricting landmark observations to a covisibility-based subset, avoiding the quadratic growth of previous fast BA solutions [S1]. The delay between capture and processing start is kept below 0.8 seconds [S1].
*   **Memory Complexity:** Efficient enough to run on standard GPUs, unlike feed-forward methods like AnySplat which require excessive VRAM for large scenes [S1].
*   **Measured Performance:**
    *   **MipNeRF360:** PSNR 26.29, SSIM 0.839, LPIPS 0.241 in 0:01:17 [S1].
    *   **TUM:** PSNR 24.51, SSIM 0.861, LPIPS 0.174 in 0:01:36 [S1].
    *   **StaticHikes:** PSNR 23.78, SSIM 0.760, LPIPS 0.242 in 0:01:49 [S1] [S1].
*   **Strengths:** Real-time incremental reconstruction, robust to rotation via two-level matching, handles disjoint sequences via shelving, and corrects drift via loop closure.
*   **Limitations:** Requires a bootstrap phase of 8 keyframes; performance depends on the quality of feature matching; shelved frames may delay full reconstruction if matching is poor.
*   **When to use:** Immediate/incremental 3D reconstruction from unordered image collections, specifically targeting pose-free methods and large-scale scenes [S1].

## Background
The method was introduced by Andreas Meuleman, Linus Franke, Boris Zhestiankin, Camille Montemagni, and George Drettakis in the paper "Immediate 3D Gaussian Splat Reconstruction of Unordered Input with Global Consistency" [S1]. It addresses the limitations of previous fast bundle adjustment solutions which did not scale well beyond small windows ($N=5$) due to quadratic growth in observations [S1]. The work builds on differentiable rendering techniques  and integrates loop closure mechanisms similar to those in SLAM systems but adapted for Gaussian Splatting.
