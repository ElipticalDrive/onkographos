# Parameter and Coordinate Initialization

## Overview
Parameter and Coordinate Initialization establishes the initial values for learnable attributes of 3D Gaussian primitives, including view-dependent color coefficients, material properties, and spatial sampling coordinates. It solves the problem of optimization instability and poor convergence in differentiable rendering pipelines by providing physically plausible or geometrically consistent starting points for non-convex inverse problems. It differs from sibling methods like [Angle-pose Cuboid Uniform Initialization (ACUI)](4503-angle-pose-cuboid-uniform-initialization-acui.md) and [DreamGaussian](5998-dreamgaussian.md) by focusing on the specific tensor initialization of Gaussian parameters (SH coefficients, SDF weights, sampling coordinates) rather than the spatial distribution of the Gaussian centers themselves.
## Shared principles
The family shares the principle of deterministic or statistically constrained initialization to reduce the search space for gradient-based optimizers. Key shared mechanisms include:
1.  **Normalization:** Input data (e.g., RGB values, image intensities) is normalized to a standard range (e.g., $[0, 1]$) or median intensity (e.g., $0.5$) to ensure stable gradient magnitudes [S1][S2, unofficial].
2.  **Zero-Initialization of Higher-Order Terms:** For frequency-domain representations like Spherical Harmonics, only the DC (zeroth-order) term is initialized from data, while higher-order coefficients are set to zero, assuming view-independent color as the prior [S1].
3.  **Physical Priors:** Material parameters (roughness, albedo) are initialized to neutral or physically plausible values (e.g., roughness $0.5$, emission $0$) to prevent immediate divergence in inverse rendering [S1][S2, unofficial].
4.  **Coordinate Transformation:** Spatial coordinates are transformed into feature sampling spaces using linear projections constrained to preserve local similarity (e.g., row sums equal to 1) [S1].
## Subtopics

### [Spherical Harmonics Initialization](3163-spherical-harmonics-initialization.md)
Initializes view-dependent color coefficients by mapping input RGB colors into the zeroth-order spherical harmonic term. It differs from [Spherical Harmonics Evaluation](3848-spherical-harmonics-evaluation.md) by preparing the parameter tensor for optimization rather than computing colors during rendering, and from [Splat Initialization from Normalized Coordinates](3595-splat-initialization-from-normalized-coordinates.md) by relying on external RGB data rather than deriving color from spatial coordinates. Choose this when initializing standard 3D Gaussian Splatting with view-dependent shading.

### [Parameter Initialization](16048-parameter-initialization.md)
Defines the deterministic initialization of material parameters (emission, roughness, specular albedo, diffuse color) and geometric priors (SDF, environment map) for differentiable rendering pipelines, specifically those utilizing spherical Gaussian basis functions or texture-space sampling. It solves the problem of optimization instability caused by poor initial guesses in non-convex inverse rendering problems, such as MLPs getting stuck in local minima or incorrect exposure handling. It is distinct from sibling methods like Spherical Harmonics Initialization by focusing on physical material properties and spatially-varying diffuse textures via median filtering rather than frequency-domain coefficients. Choose this for inverse rendering tasks requiring physical material recovery.

### GS-W Sampling Coordinate Initialization
Initializes K learnable sampling coordinates per Gaussian point to enable adaptive feature sampling on K feature maps [S1]. Assign each Gaussian point $i$ $K$ sampling coordinates $(sc1_i, sc2_i, \dots, scK_i) \in \mathbb{R}^{K \times 2}$ [S1]. Randomly generate $K$ matrices $(M^1, M^2, \dots, M^K) \in \mathbb{R}^{K \times 2 \times 3}$ [S1]. Constrain each matrix such that the sum of its rows equals 1 [S1]. Multiply each matrix $M^k$ with the Gaussian point's 3D position $X_i \in \mathbb{R}^3$ to compute the initial sampling coordinates [S1]. The formula is:
$$
(sc_1^1, sc_2^2, \dots, sc_k^K)_{init} = (M^1 X_i, M^2 X_i, \dots, M^K X_i)
$$
The number of feature maps $K$ is typically set to 3 to balance efficiency and effectiveness [S1].

### Gaussian Point Splatting Parameterization
A method to calculate point size and transparency for volume rendering based on projected voxel size and Gaussian texture coverage [S2, unofficial]. The point size is calculated as:
$$
mPointSize = mGauspara \times m\_projectedVoxelSize
$$
The transparency is calculated as:
$$
mTransParency = 20.2f / \_znum
$$
$mGauspara$ is the Gaussian texture coverage ratio, with a typical value of 2.0 [S2, unofficial]. $m\_projectedVoxelSize$ is the calculated projected size of a voxel on screen, dependent on window width and field of view [S2, unofficial]. $\_znum$ is the number of depth slices or z-resolution, used to calculate transparency [S2, unofficial].

## Background
The need for robust initialization in 3D Gaussian Splatting arose with the introduction of the method by Kerbl et al. [2023], which relies on gradient-based optimization of Gaussian parameters. Subsequent works extended this to handle view-dependent effects via Spherical Harmonics [S1], inverse rendering via SDFs and material parameters [S1][S2, unofficial], and feature-based rendering via sampling coordinates [S1]. The specific normalization constants and parameter ranges (e.g., SH DC scaling, roughness values) were derived empirically to ensure stable convergence in differentiable rendering pipelines.
