# Support Guard

Also called: Coordinate box clamp, Per-primitive clamp, node-local guard

## Overview
The Support Guard is a fault-mitigation technique for 3D Gaussian Splatting (3DGS) that prevents catastrophic rendering errors caused by Single-Event Upsets (SEUs), such as bit flips in memory, by clamping primitive parameters to the valid range observed during training [S1, unofficial]. It solves the problem of "frame-spanning corruption," where a single bit flip in a scale parameter can exponentially inflate a primitive into a translucent sheet covering most of the screen [S1, unofficial]. Unlike activation range supervision used in CNNs, which clamps neuron outputs to statistical distributions, the Support Guard clamps geometric and appearance parameters to the bounded parameter space of the optimized scene, providing a geometric correctness argument [S1, unofficial]. It is distinct from its siblings in that it requires zero additional memory overhead and operates as a pure per-primitive clamp, making it suitable for deployment on spaceborne, robotic, and clustered hardware where reliability is critical [S1, unofficial].

## How it works
The method operates by enforcing a hard boundary on every parameter of every Gaussian primitive before rendering. It ensures that no primitive can exceed the physical or appearance bounds established by the trained model, thereby neutralizing the exponential impact of bit flips in logarithmic scale or opacity fields [S1, unofficial].

### Inputs and Outputs
*   **Input:** A set of $N$ 3D Gaussian primitives, each defined by parameters $\mathbf{p}_i$ (position, rotation, scale, opacity, color). The parameters are stored in floating-point format (typically fp32).
*   **Input:** The per-field support box $B_f$, defined as the per-component minimum and maximum values observed over all primitives in the clean, trained model for each parameter field $f$ [S1, unofficial].
*   **Output:** A set of guarded primitives $\mathbf{p}'_i$ where every component lies within its respective support box $B_f$ [S1, unofficial].

### Data Structures
*   **Support Box ($B_f$):** For each parameter field $f$ (e.g., scale $x, y, z$; opacity; color channels), $B_f$ is a pair of scalars $[\ell_f, h_f]$ representing the global minimum and maximum of that field across the entire scene [S1, unofficial].
    *   $\ell_f = \min_{i} (\mathbf{p}_i[f])$
    *   $h_f = \max_{i} (\mathbf{p}_i[f])$
    *   These values are static and derived from the trained checkpoint [S1, unofficial].

### Algorithm
The guard is applied per-primitive. For each primitive $i$ and each parameter field $f$:

1.  Retrieve the current value $x$ of the parameter.
2.  Check if $x$ lies within the support box $[\ell_f, h_f]$.
3.  If $x < \ell_f$, clamp $x$ to $\ell_f$.
4.  If $x > h_f$, clamp $x$ to $h_f$.
5.  If $\ell_f \le x \le h_f$, leave $x$ unchanged.

This process is repeated for all components of all primitives. In a distributed sort-first rendering architecture, this guard is applied node-locally on each node before it renders its assigned tile, ensuring that out-of-range primitives are contained before compositing [S1, unofficial].

### Pseudocode
```python
def apply_support_guard(primitives, support_boxes):
    """
    Clamps all primitive parameters to their trained support boxes.
    
    Args:
        primitives: List of primitive objects, each having attributes 
                    corresponding to parameter fields (e.g., scale_x, opacity).
        support_boxes: Dictionary mapping parameter field names to tuples 
                       (min_val, max_val).
    
    Returns:
        primitives: The same list of primitives, modified in-place.
    """
    for primitive in primitives:
        for field_name, (min_val, max_val) in support_boxes.items():
            # Get current value of the field
            current_val = getattr(primitive, field_name)
            
            # Clamp to support box
            if current_val < min_val:
                setattr(primitive, field_name, min_val)
            elif current_val > max_val:
                setattr(primitive, field_name, max_val)
            # Else: value is within bounds, leave unchanged
    return primitives
```

### Formulas and Definitions
*   **Support Box $B_f$:** The coordinate box for field $f$ is defined as $B_f = [\ell_f, h_f]$, where $\ell_f$ and $h_f$ are the empirical min and max of field $f$ over the clean trained model [S1, unofficial].
*   **Clamping Function:** For a parameter $x$ and box $B_f = [\ell_f, h_f]$, the guarded value $x'$ is:
    $$
    x' = \begin{cases} 
    \ell_f & \text{if } x < \ell_f \\
    x & \text{if } \ell_f \le x \le h_f \\
    h_f & \text{if } x > h_f 
    \end{cases}
    $$
*   **Scale Explosion Mitigation:** A sign flip in the logarithmic scale $\theta$ (where $s = \exp(\theta)$) can change $\theta \approx -3$ to $\theta \approx +3$, causing $s \to s \cdot e^6$. The guard clamps $\theta$ back into $B_{\theta}$, preventing this exponential explosion [S1, unofficial].

### Parameters
*   **Support Box Bounds ($\ell_f, h_f$):** Determined from the trained model. Not given in the sources for specific scenes, but must be computed once during model loading [S1, unofficial].
*   **Cost:** 76 µs per frame, or 0.07× a single-view render time [S1, unofficial].
*   **Memory Overhead:** None (1× memory relative to unguarded) [S1, unofficial].

### Edge Cases and Pitfalls
*   **Catastrophic Upsets:** Without the guard, a single scale sign-bit upset can inflate one primitive into a translucent sheet spanning most of the frame, causing catastrophic corruption [S1, unofficial].
*   **Residual Errors:** The guard neutralizes 90.4% of catastrophic upsets. The remaining 9.6% are "in-support" mantissa-level residuals that are bounded by Lemma 1 in the source and are perceptually invisible [S1, unofficial].
*   **Distributed Rendering:** In a distributed renderer, the spatial extent of a corrupted primitive equals the number of screen tiles (and thus compositing nodes) that a single upset contaminates. The node-local guard contains this corruption to the node where it occurs, preventing broadcast into the composite [S1, unofficial].
*   **Clean Model Invariance:** The guard leaves a clean model unchanged by construction, as all clean parameters lie within $B_f$ by definition [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The guard parallelizes trivially across primitives. The measured cost is 76 µs per frame, which is approximately 0.07× a single-view render time [S1, unofficial].
*   **Memory Complexity:** Zero additional memory overhead. It operates on the existing primitive data structures [S1, unofficial].
*   **Effectiveness:** Neutralizes 90.4% of catastrophic upsets. Under accumulated dose (up to 20,000 simultaneous upsets), the guarded renderer maintains a mean global PSNR close to clean, whereas the unguarded renderer degrades to 10.6 dB [S1, unofficial].
*   **Worst-Case Footprint:** In a test of 768,000 guarded single-bit upsets, the worst observed corruption footprint was 11.68% of the frame, with 470 residual catastrophic events [S1, unofficial].
*   **Comparison to Alternatives:**
    *   **Full Duplication:** Requires 3× memory and voting. Eliminates catastrophes but at high memory cost [S1, unofficial].
    *   **ECC Sign+Exp:** Requires ~1.3× memory and parity. Eliminates catastrophes but at higher memory cost [S1, unofficial].
    *   **Selective Clamp:** Clamps only scale and opacity. Cheaper than full guard but similarly effective, as scale and opacity carry most catastrophic mass [S1, unofficial].
*   **When to Use:** Deploy on hardware susceptible to SEUs (spaceborne, robotic, clustered) where memory bandwidth and capacity are constrained, and where catastrophic frame-spanning errors are unacceptable [S1, unofficial].
*   **When Not to Use:** If memory is abundant and computational cost is less critical than absolute fault correction, full duplication or ECC may be preferred for zero catastrophe rate [S1, unofficial].

## Background
The Support Guard was introduced in the paper "Single-Event Upsets in 3D Gaussian Splatting Rendering: Bit-Level Criticality, Spatial Extent, and a Parallel Support Guard" [S1, unofficial]. The work was motivated by the need to deploy real-time radiance-field rendering on hardware exposed to radiation, such as spaceborne and robotic platforms [S1, unofficial]. The authors identified that 3DGS primitives, being explicit and interpretable, are susceptible to bit-level criticality, particularly in the logarithmic scale parameters where sign flips cause exponential scale explosions [S1, unofficial]. The Support Guard was developed as a lightweight, geometrically grounded mitigation strategy that exploits the compact, bounded nature of trained 3DGS parameter spaces [S1, unofficial]. It was validated against a fault grid of 768,000 single-bit upsets and proven to make frame-covering corruption impossible under any single-bit upset (Theorems 1 and 2) [S1, unofficial].
