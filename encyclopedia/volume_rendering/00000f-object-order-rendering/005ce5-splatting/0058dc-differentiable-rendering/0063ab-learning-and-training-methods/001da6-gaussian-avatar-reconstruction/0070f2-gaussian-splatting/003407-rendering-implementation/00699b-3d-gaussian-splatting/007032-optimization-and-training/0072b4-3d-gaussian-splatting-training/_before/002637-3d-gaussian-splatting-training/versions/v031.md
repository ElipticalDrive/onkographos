# 3D Gaussian Splatting Training

Also called: 3DGS Learning, G Splats

## Overview
3D Gaussian Splatting Training is the iterative optimization process that adjusts the parameters of a set of 3D Gaussian primitives to minimize the photometric difference between rendered images and ground truth views [S2][S6, unofficial]. It solves the problem of reconstructing a high-fidelity 3D scene from a sparse set of 2D images by optimizing position, rotation, scale, opacity, and appearance (spherical harmonics) [S5, S6, unofficial]. Unlike implicit neural radiance fields (NeRFs) which require per-scene network convergence, 3DGS training directly optimizes explicit geometric primitives, offering significantly faster training times and real-time rendering capabilities [S2][S5, unofficial]. It sets itself apart from static initialization methods by actively modifying the primitive set (densification and pruning) during optimization to balance reconstruction fidelity against computational cost [S2][S6, unofficial].

## How it works
**Inputs and Outputs**
*   **Inputs:** A set of $N$ input images (or video frames) with known camera poses (rotation $R_{cw}$, translation $t_{cw}$, intrinsic matrix $K$) [S6, unofficial]. Initial 3D Gaussian parameters derived from Structure from Motion (SfM) point clouds [S2][S6, unofficial].
*   **Outputs:** Optimized 3D Gaussian parameters (positions $\mathbf{p}$, rotations $q$, scales $\mathbf{s}$, opacities $\alpha$, spherical harmonic coefficients $h$) stored in a format such as PLY [S4, S6, unofficial].

**Data Structures**
Each Gaussian primitive $i$ is defined by:
*   Position $\mathbf{p}_i \in \mathbb{R}^3$
*   Rotation $q_i \in \mathbb{R}^4$ (unit quaternion)
*   Scale $\mathbf{s}_i \in \mathbb{R}^3$
*   Opacity $\alpha_i \in [0, 1]$
*   Appearance parameters $h_i$ (Spherical Harmonic coefficients) [Parent]

**Formulas**
The optimization minimizes a loss function $\mathcal{L}$ between the rendered image $\gamma$ and ground truth $\gamma_{gt}$ [S6, unofficial]:
$$
\mathcal{L} = (1 - \lambda) \mathcal{L}_1 + \lambda \mathcal{L}_{D-SSIM}
$$
where $\lambda$ is the SSIM weight (default 0.2) [S4, S6, unofficial].

The rotation matrix $R$ from unit quaternion $q = (q_r, q_i, q_j, q_k)$ is:
$$
R(q) = 2 \begin{bmatrix} \frac{1}{2} - (q_j^2 + q_k^2) & q_i q_j - q_r q_k & q_i q_k + q_r q_j \\ q_i q_j + q_r q_k & \frac{1}{2} - (q_i^2 + q_k^2) & q_j q_k - q_r q_i \\ q_i q_k - q_r q_j & q_j q_k + q_r q_i & \frac{1}{2} - (q_i^2 + q_j^2) \end{bmatrix}
$$
[S2][S6, unofficial]

The pixel color $\gamma_j$ is computed via alpha blending of $N$ projected Gaussians sorted by depth:
$$
\gamma_j = \sum_{i \in N} \alpha'_{ij} c_i \tau_{ij}, \quad \tau_{ij} = \prod_{k=1}^{i-1} (1 - \alpha'_{kj})
$$
[S6, unofficial]

**Parameters**
*   `numIters`: Total optimization steps. Default: 30,000 [S3, S4, unofficial].
*   `sh_degree`: Spherical harmonic degree. Default: 3 [S4, unofficial].
*   `sh_degree_interval`: Steps between increasing SH degree. Default: 1,000 [S4, unofficial].
*   `densifyFrom`: Step after which densification begins. Default: 500 [S3, unofficial].
*   `densifyUntil`: Step after which densification stops. Default: $\min(15000, \text{numIters} / 2)$ [S3, unofficial].
*   `refineEvery`: Steps between densification/pruning operations. Default: 500 [S3, unofficial].
*   `densify_grad_thresh`: Gradient threshold for densification. Default: 0.0002 [S4, unofficial].
*   `densify_size_thresh`: Size threshold for densification. Default: 0.01 [S4, unofficial].
*   `split_screen_size`: Screen size threshold for splitting. Default: 0.05 [S4, unofficial].
*   `stop_screen_size_at`: Step at which screen-size splitting stops. Default: 4,000 [S4, unofficial].
*   `maxGaussians`: Maximum number of Gaussians. Default: 5,000,000 [S3, unofficial].
*   `downScaleFactor`: Initial image downscale. Default: 1.0 [S4, unofficial].
*   `numDownscales`: Number of resolution scales. Default: 0-2 [S3, S4, unofficial].
*   `resolutionSchedule`: Steps between doubling resolution. Default: 3,000 [S3, unofficial].
*   `bg_color`: Background color [R, G, B]. Default: [0.613, 0.010, 0.398] (magenta) [S4, unofficial].

**Steps**
1.  **Initialization:** Initialize positions $\mathbf{p}$ from SfM point clouds in normalized bounds $[-1, 1]$. Initialize scales $\mathbf{s}$ between 0 and 1. Initialize rotations $q$ as unit quaternions. Initialize opacities $\alpha$ and colors $c$ (or SH coefficients $h$) [S2][S6, unofficial].
2.  **Camera Sampling:** Select a training camera $V$ and ground truth image $\hat{I}$ using a shuffled round-robin iterator [S2][S4, unofficial].
3.  **Rendering:** Rasterize the Gaussians using camera $V$ to obtain rendered image $I$. This involves projecting 3D Gaussians to 2D screen space, sorting by depth, and alpha blending [Parent, S2].
4.  **Loss Computation:** Compute loss $\mathcal{L}$ between $I$ and $\hat{I}$ using L1 and D-SSIM [S2][S6, unofficial].
5.  **Backpropagation:** Compute gradients for all parameters ($\mathbf{p}, q, \mathbf{s}, h, \alpha$) using the chain rule [S6, unofficial].
    *   Jacobian for rotation $q_i$: $\frac{\partial \mathcal{L}}{\partial q_i} = \sum_j \frac{\partial \mathcal{L}}{\partial \gamma_j} \frac{\partial \gamma_j}{\partial \sigma'_i} \frac{\partial \sigma'_i}{\partial \sigma_i} \frac{\partial \sigma_i}{\partial q_i}$ [S6, unofficial]
    *   Jacobian for scale $s_i$: $\frac{\partial \mathcal{L}}{\partial s_i} = \sum_j \frac{\partial \mathcal{L}}{\partial \gamma_j} \frac{\partial \gamma_j}{\partial \sigma'_i} \frac{\partial \sigma'_i}{\partial \sigma_i} \frac{\partial \sigma_i}{\partial s_i}$ [S6, unofficial]
    *   Jacobian for SH $h_i$: $\frac{\partial \mathcal{L}}{\partial h_i} = \sum_j \frac{\partial \mathcal{L}}{\partial \gamma_j} \frac{\partial \gamma_j}{\partial c_i} \frac{\partial c_i}{\partial h_i}$ [S6, unofficial]
    *   Jacobian for opacity $\alpha_i$: $\frac{\partial \mathcal{L}}{\partial \alpha_i} = \sum_j \frac{\partial \mathcal{L}}{\partial \gamma_j} \frac{\partial \gamma_j}{\partial \alpha'_{ij}} \frac{\partial \alpha'_{ij}}{\partial \alpha_i}$ [S6, unofficial]
    *   Jacobian for position $\mathbf{p}_{w,i}$ involves three terms for depth sorting, color, and covariance changes [S6, unofficial].
6.  **Optimizer Step:** Update parameters using the Adam optimizer [S2][S6, unofficial].
7.  **Adaptive Density Control:** If the current step is a refinement iteration (e.g., every 100 or 500 steps):
    *   **Pruning:** If $\alpha_i < \epsilon$ or the Gaussian is too large, prune it [S2].
    *   **Densification:** If positional gradient $\nabla_{\mathbf{p}} \mathcal{L} > \tau_p$:
        *   **Over-reconstruction:** If covariance norm $\|\mathbf{S}\| > \tau_S$, split the Gaussian [S2].
        *   **Under-reconstruction:** Else, clone the Gaussian [S2].
8.  **Resolution Schedule:** Increase image resolution according to `resolutionSchedule` [S3, S4, unofficial].
9.  **SH Degree Schedule:** Increase SH degree according to `sh_degree_interval` [S4, unofficial].

**Pseudocode**
```python
def train_3dgs(cameras, gt_images, initial_gaussians, config):
    # Initialize parameters
    gaussians = initial_gaussians
    optimizer = Adam(gaussians.parameters(), lr=config.init_lr)
    
    # Camera iterator
    cam_indices = list(range(len(cameras)))
    shuffle(cam_indices)
    cam_iter = Iterator(cam_indices)
    
    step = 1
    while step <= config.numIters:
        # 1. Sample Camera
        cam_idx = cam_iter.next()
        if cam_iter.is_end():
            shuffle(cam_indices)
            cam_iter.reset()
        
        cam = cameras[cam_idx]
        gt_img = gt_images[cam_idx]
        
        # 2. Render
        # Apply downscale factor based on step and resolution_schedule
        downscale = get_downscale_factor(step, config)
        rendered_img = render(gaussians, cam, downscale)
        
        # 3. Compute Loss
        loss = compute_loss(rendered_img, gt_img, config.ssim_weight)
        
        # 4. Backpropagate
        loss.backward()
        
        # 5. Optimizer Step
        optimizer.step()
        optimizer.zero_grad()
        
        # 6. Adaptive Density Control
        if step % config.refineEvery == 0:
            densify_and_prune(gaussians, config)
            
        # 7. Update Schedulers
        update_sh_degree(step, config)
        update_resolution(step, config)
        
        step += 1
        
    return gaussians

def densify_and_prune(gaussians, config):
    # Pruning
    for g in gaussians:
        if g.opacity < config.opacity_threshold or is_too_large(g):
            prune(g)
            
    # Densification
    if config.densifyFrom <= step <= config.densifyUntil:
        for g in gaussians:
            if g.gradient_norm > config.densify_grad_thresh:
                if g.covariance_norm > config.densify_size_thresh:
                    split(g)
                else:
                    clone(g)
```

### HUGS
HUGS creates a coarse-to-fine deformation module using linear blend skinning and local learning-based refinement for animating virtual human avatars [S1]. It utilizes a tri-plane representation to factorize the canonical space, reconstructing the person and scene from monocular video (50-100 frames) within 30 minutes, achieving 20 FPS rendering [S1].

### Wolf et al. Stereo Method
Trains a 3DGS to render stereo-calibrated novel views, applies stereo depth estimation on the rendered views, and fuses the estimated dense depth maps using a Truncated Signed Distance Function (TSDF) to form a triangular mesh [S1].

### Pseudo Ground Truth Acquisition for Gaussians
A labeling pipeline that generates Gaussian-specific pseudo ground truth labels from original point cloud labels, accounting for the densification and pruning processes of 3D-GS optimization [S8, unofficial].

### Cross-View Pruning Mechanism
A mechanism comprising a Cross-View Consistency Loss and adaptive pruning to reduce Gaussian redundancy. It selects adjacent view pairs with SSIM > 0.6, computes a consistency loss to penalize residual discrepancies, and prunes Gaussians based on depth/distance consistency conditions [S9].

### Structure-View Co-learning
A module combining structural and view-dependent gradients for robust joint optimization. The loss is defined as $\mathcal{L} = \lambda (\lambda_V \mathcal{L}_V + \lambda_S \mathcal{L}_S)$, where $\mathcal{L}_V$ is view gradient loss and $\mathcal{L}_S$ is structure gradient loss [S9].

### Single-view Mini-batch Strategy
A training data sampling strategy where data is organized per viewpoint. A mini-batch consists of data from only a single viewpoint, organizing datasets $D = \{D_i\}$ for $N$ viewpoints and sampling $B_{3DGS}$ from count=1 viewpoint [S10, unofficial].

## Operating characteristics
*   **Time Complexity:** Training time is significantly faster than NeRFs, often completing in under an hour for complex scenes [S5, unofficial]. The C++ implementation with Metal backend achieves training in ~90 seconds on an M4 Max [S4, unofficial].
*   **Memory Complexity:** Memory usage scales with the number of Gaussians. Default max is 5,000,000 [S3, unofficial]. Sinc splatting variants consume less memory than standard Gaussians [S7].
*   **Performance:** Achieves comparable image quality to NeRFs with real-time rendering speeds [S2]. On the Replica dataset, SGS-SLAM achieves PSNR 34.15, SSIM 0.97, and LPIPS 0.096 [S1].
*   **Hardware:** Supports CUDA, MPS, and CPU. CPU execution is ~100x slower than GPU [S3, S4, unofficial].
*   **Strengths:** Fast training, real-time rendering, high fidelity.
*   **Limitations:** Sensitive to initialization; prone to "floaters" in unconstrained settings without regularization [S2][S6, unofficial].

## Background
3D Gaussian Splatting was introduced as a method for real-time radiance field rendering [9]. The original method initializes positions using sparse point clouds from SfM tools like COLMAP [21, S2]. It differs from NeRFs by using explicit Gaussian primitives instead of implicit neural networks, enabling faster training and rendering [S2][S5, unofficial]. The training process relies on adaptive density control to manage the number and size of Gaussians [S2].
