# Compact 3D Gaussian Representation (C3DGS)

## Overview
Compact 3D Gaussian Representation (C3DGS) is a method for reducing the memory footprint and storage requirements of 3D Gaussian Splatting (3DGS) by exploiting spatial redundancy in scene attributes [S1]. It solves the problem of excessive storage (often >1GB for real-world scenes) caused by storing unique per-Gaussian attributes for view-dependent color and covariance [S1]. Unlike standard 3DGS, which treats each Gaussian as an independent primitive, C3DGS replaces per-Gaussian color storage with a shared hash-based neural field and replaces per-Gaussian geometric parameters with a discrete codebook, achieving over 25× compression while maintaining or improving reconstruction quality [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $N$ 3D Gaussians $\{G_i\}$ optimized via standard 3DGS training, where each $G_i$ has position $\mu_i$, scale $\hat{s}_i$, rotation $r_i$ (quaternion), opacity $o_i$, and spherical harmonic (SH) coefficients $c_i$ [S1].
*   **Output:** A compact representation consisting of:
    1.  A reduced set of active Gaussians (via masking).
    2.  A hash-based grid neural field for color attributes.
    3.  A geometry codebook storing scale/rotation patterns.
    4.  Indices mapping each Gaussian to its respective color and geometry entries.

**Data Structures:**
1.  **Mask Vector:** A learnable binary mask $m \in \{0, 1\}^N$ indicating whether Gaussian $i$ is active.
2.  **Hash Grid:** A multi-resolution hash table (Instant NGP style) mapping 3D positions to color feature vectors.
3.  **Geometry Codebook:** A fixed-size table $C_{geo} \in \mathbb{R}^{K \times D_{geo}}$ containing learned scale and rotation patterns, where $K$ is the codebook size and $D_{geo}$ is the dimensionality of the geometry vector.
4.  **Indices:**
    *   $idx_{color}(i)$: Index into the hash grid (computed from position).
    *   $idx_{geo}(i) \in \{0, \dots, K-1\}$: Index into the geometry codebook for Gaussian $i$.

**Steps:**

1.  **Volume-Based Masking (Gaussian Reduction):**
    During training, introduce a learnable mask $m_i$ for each Gaussian. The loss function includes a regularization term that penalizes non-zero masks for Gaussians that contribute minimally to the rendering error. This identifies and removes redundant Gaussians, reducing $N$ [S1].
    *   *Pitfall:* Aggressive masking may remove fine details; the mask must be learned jointly with other parameters to ensure minimal impact on performance [S1].

2.  **Color Compression via Hash Grid:**
    Instead of storing SH coefficients $c_i$ for each Gaussian, query a hash-based neural field using the Gaussian's 3D position $\mu_i$ to retrieve its color features.
    *   The hash grid maps $\mu_i$ to a set of feature vectors.
    *   These features are processed (e.g., via an MLP or direct lookup) to determine the view-dependent color.
    *   This exploits spatial redundancy: neighboring Gaussians with similar positions share color features from the grid [S1].
    *   *Parameter:* The hash grid uses the Instant NGP representation for compactness and fast processing [S1].

3.  **Geometry Compression via Codebook:**
    Since most Gaussians exhibit similar geometry (scale and rotation) with limited variation, replace the continuous parameters $\hat{s}_i$ and $r_i$ with discrete indices.
    *   Initialize a codebook $C_{geo}$ of size $K$.
    *   During training, assign each Gaussian $i$ to the closest entry in $C_{geo}$ based on its current scale and rotation.
    *   Store only the index $idx_{geo}(i)$ for each Gaussian.
    *   The actual scale and rotation are reconstructed by looking up $C_{geo}[idx_{geo}(i)]$ during rendering or gradient computation [S1].
    *   *Note:* The codebook size $K$ is kept small to minimize spatial and computational overhead [S1].

4.  **Rendering:**
    For each pixel, project the active Gaussians (where $m_i=1$).
    *   Retrieve color from the hash grid using $\mu_i$.
    *   Retrieve scale/rotation from $C_{geo}$ using $idx_{geo}(i)$.
    *   Perform standard Gaussian splatting with these attributes [S1].

**Pseudocode:**

```python
# Initialization
N = number_of_gaussians
K = codebook_size_for_geometry
hash_grid = HashGrid() # Instant NGP structure
codebook_geo = RandomInit(K, D_geo) # D_geo = dim(scale) + dim(rotation)
mask = LearnableMask(N) # Initialized to 1.0

# Training Step
def compute_loss(rendered_image, target_image, gaussians):
    # 1. Apply Mask
    active_gaussians = [g for g, m in zip(gaussians, mask) if m > 0.5]
    
    # 2. Compress Geometry
    # Find closest codebook entry for each active Gaussian
    indices_geo = []
    for g in active_gaussians:
        # Compute distance between g.scale/rotation and all entries in codebook_geo
        # Assign index of minimum distance
        idx = argmin([dist(g.scale, g.rot, codebook_geo[k]) for k in range(K)])
        indices_geo.append(idx)
    
    # 3. Compress Color
    # Colors are retrieved from hash grid during rendering, no explicit storage here
    
    # 4. Render
    # Use active_gaussians, indices_geo, and hash_grid to render
    rendered = render(active_gaussians, indices_geo, hash_grid)
    
    # 5. Loss Calculation
    reconstruction_loss = mse(rendered, target_image)
    
    # 6. Mask Regularization
    # Penalize non-zero masks to encourage sparsity
    mask_loss = sum(mask) 
    
    return reconstruction_loss + lambda_mask * mask_loss

# Rendering Step
def render(active_gaussians, indices_geo, hash_grid):
    for g, idx in zip(active_gaussians, indices_geo):
        # Retrieve geometry from codebook
        scale, rot = codebook_geo[idx]
        
        # Retrieve color from hash grid
        color = hash_grid.query(g.position)
        
        # Splat using scale, rot, color, opacity, position
        splat_pixel(g.position, scale, rot, color, g.opacity)
```

**Parameters:**
*   **Codebook Size ($K$):** Not given in the sources. Must be small to minimize overhead [S1].
*   **Hash Grid Type:** Hash-based grid representation (Instant NGP) [S1].
*   **Masking Weight ($\lambda_{mask}$):** Not given in the sources. Controls the trade-off between Gaussian count and reconstruction quality [S1].

**Edge Cases and Pitfalls:**
*   **Precision:** The sources mention post-processing quantization and entropy coding can achieve over 25× compression, implying the base method may use standard floating-point for grid features and codebook entries [S1].
*   **Boundaries:** The hash grid must handle out-of-bounds queries gracefully, though Instant NGP typically handles this via wrapping or clamping [S1].
*   **Degenerate Input:** If the scene has high geometric diversity, a small codebook $K$ may lead to quantization errors in scale/rotation [S1].

## Subtopics

### [Optimized Minimal 3D Gaussian Splatting (OMG)](13978-optimized-minimal-3d-gaussian-splatting-omg.md)
OMG extends C3DGS by retaining per-Gaussian parameterization for geometry to handle sparsity, while using a small neural field and Sub-Vector Quantization (SVQ) for appearance features. It addresses C3DGS's weakness in sparse settings where neighboring Gaussians are far apart, achieving >300× compression.

## Operating characteristics
*   **Storage Efficiency:** Achieves over 25× compression compared to standard 3DGS across various datasets [S1]. On the Deep Blending dataset, it achieves over 28× enhancement in storage efficiency [S1].
*   **Rendering Speed:** Nearly 40% increase in rendering speed on the Deep Blending dataset due to reduced number of Gaussians and efficient attribute lookup [S1]. Generally shows enhanced rendering speed across datasets [S1].
*   **Reconstruction Quality:** Outperforms 3DGS in PSNR on the Deep Blending dataset [S1]. Maintains high-quality reconstruction on other datasets [S1].
*   **Training Speed:** Fast training speed is claimed, though specific metrics are not given [S1].
*   **Strengths:** Significant reduction in memory and storage; real-time rendering capability; high visual fidelity.
*   **Limitations:** Relies on spatial redundancy; may struggle with highly sparse or geometrically diverse scenes without extensions like OMG [S1].
*   **When to Use:** When storage and memory are critical constraints, and the scene exhibits spatial redundancy in color and geometry.
*   **When Not to Use:** For scenes with high geometric diversity where codebook quantization errors are unacceptable, or where extreme sparsity exists.

## Background
C3DGS was proposed to address the critical large memory and storage issue in 3D Gaussian Splatting (3DGS), which often requires >1GB for real-world scenes [S1]. It builds on the observation that standard 3DGS densification produces redundant Gaussians and does not exploit spatial redundancy in attributes [S1]. The method uses Instant NGP for the hash grid [S1]. It was evaluated on real and synthetic scenes, including the Deep Blending dataset [S1].
