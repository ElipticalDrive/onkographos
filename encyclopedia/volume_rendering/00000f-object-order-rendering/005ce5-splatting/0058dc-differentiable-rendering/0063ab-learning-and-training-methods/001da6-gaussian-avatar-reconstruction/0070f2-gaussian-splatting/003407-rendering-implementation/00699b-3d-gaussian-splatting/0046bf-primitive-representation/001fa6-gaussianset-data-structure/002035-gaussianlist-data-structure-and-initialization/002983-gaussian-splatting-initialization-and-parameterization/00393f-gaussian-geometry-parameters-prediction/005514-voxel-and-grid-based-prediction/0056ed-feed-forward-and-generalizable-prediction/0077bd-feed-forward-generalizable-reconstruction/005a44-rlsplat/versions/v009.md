# RLSplat

Also called: Resource-Linear Budget Control for Feed-forward 3D Gaussian Splatting

## Overview
RLSplat is a resource-linear, budget-controllable feed-forward 3D Gaussian Splatting (FF3DGS) framework that generates exactly $B$ Gaussians from uncalibrated input images, ensuring that inference latency and peak memory scale linearly with the requested Gaussian budget $B$ [S1, unofficial]. Unlike prior budget-controllable methods (e.g., EcoSplat, F4 Splat) that predict a dense set of candidates and prune them—resulting in nearly constant inference costs regardless of the target budget—RLSplat uses a learned allocation policy to distribute $B$ Gaussians across local scene regions and a resource-linear decoder that refines them via local cross-attention [S1, unofficial]. This approach allows the representation size, inference latency, and peak memory to decrease linearly as $B$ is reduced, making it suitable for applications with strict resource constraints such as AR/VR and robotics [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of $V$ uncalibrated context images $\{I_i\}_{i=1}^V$ and a target Gaussian budget $B \in \mathbb{Z}_{>0}$ [S1, unofficial].
*   **Outputs:** A set of $B$ 3D Gaussians $\mathcal{G} = \{g_b\}_{b=1}^B$ and the context camera parameters $\{P_i\}_{i=1}^V$ [S1, unofficial]. Each Gaussian $g_b$ consists of a 3D center, opacity, scale, rotation, and color coefficients [S1, unofficial].

**Data Structures:**
1.  **Anchor Tokens:** The geometry backbone encodes the input images into $N$ anchor tokens $\{a_n\}_{n=1}^N$, each representing a local 3D region of the scene [S1, unofficial].
2.  **Allocation Vector:** A discrete allocation vector $k \in \mathbb{Z}_{\ge 0}^N$ where $k_n$ is the number of Gaussians assigned to anchor $n$, satisfying $\sum_{n=1}^N k_n = B$ [S1, unofficial].
3.  **Gaussian Tokens:** Each anchor $n$ spawns $k_n$ Gaussian tokens. The total number of Gaussian tokens is exactly $B$ [S1, unofficial].
4.  **Hierarchical Neighbor Search:** Used to find the $K_{gs}$ nearest Gaussian tokens for each token efficiently [S1, unofficial].

**Parameters:**
*   $B$: The target Gaussian budget. Typical evaluation values include 2K (2,048) and 64K [S1, unofficial]. On the ACID dataset (8 views), $B=8,192$ (1,024 per view) is used [S1, unofficial]. On RE10K, $B=8,000$ is used [S1, unofficial].
*   $K_{gs}$: The number of nearest Gaussian neighbors each token attends to during refinement. Default ablation value is 16 [S1, unofficial]. This can be changed at inference without retraining [S1, unofficial].
*   $K_{anc}$: The number of anchor neighbors used in the hierarchical neighbor search. Fixed value in ablations is 16 [S1, unofficial].
*   $C$: The number of rollouts (candidate allocations) drawn per training step for the Group Sequence Policy Optimization (GSPO) [S1, unofficial].

**Algorithm Steps:**

1.  **Geometry Encoding:** Given $V$ uncalibrated images $\{I_i\}$, a geometry backbone encodes them into $N$ anchor tokens $\{a_n\}_{n=1}^N$ and predicts camera parameters $\{P_i\}_{i=1}^V$ [S1, unofficial].
2.  **Gaussian Allocation:** A Gaussian allocation policy $\pi_\psi$ assesses the local significance of each anchor (based on image features like texture complexity) to predict a discrete allocation $k \in \mathbb{Z}_{\ge 0}^N$ such that $\sum_{n=1}^N k_n = B$ [S1, unofficial]. This policy is trained using Group Sequence Policy Optimization (GSPO) [S1, unofficial].
3.  **Token Spawning:** Each anchor $n$ spawns $k_n$ Gaussian tokens. The total number of Gaussian tokens is exactly $B$ [S1, unofficial].
4.  **Resource-Linear Decoding:**
    *   **Initialization:** The decoder instantiates initial Gaussian states (center, scale, rotation, opacity, color) from the spawned Gaussian tokens [S1, unofficial].
    *   **Hierarchical Neighbor Search:** For each Gaussian token, the $K_{gs}$ nearest Gaussian tokens are found using a hierarchical neighbor search over the anchor tokens (using $K_{anc}$ anchor neighbors) [S1, unofficial].
    *   **Local Refinement:** Each Gaussian token is refined through local cross-attention with its $K_{gs}$ nearest Gaussian neighbors [S1, unofficial]. This step ensures consistency among neighbors and refines the initial predictions [S1, unofficial].
5.  **Output:** The final set of $B$ Gaussians $\mathcal{G}$ and camera parameters $\{P_i\}$ are returned [S1, unofficial].

**Training (GSPO):**
To optimize the policy $\pi_\psi$, Group Sequence Policy Optimization (GSPO) is used [S1, unofficial]. At each training step:
1.  Draw $C$ rollouts (candidate allocations) $k^{(c)} \sim \pi_{old} = \text{Mult}(B, \text{sg}(p))$ for $c \in \{1, \dots, C\}$, where $\text{sg}(\cdot)$ stops gradients [S1, unofficial].
2.  For each rollout $c$, generate the 3DGS representation $\mathcal{G}^{(c)}$ using the allocation $k^{(c)}$ and the decoder [S1, unofficial].
3.  Render an image $\hat{I}^{(c)}$ from $\mathcal{G}^{(c)}$ at novel target views [S1, unofficial].
4.  Compute the reconstruction loss $\mathcal{L}_{recon}$ against the ground-truth image $I$ without gradient tracking [S1, unofficial].
5.  Use $\mathcal{L}_{recon}$ as the reward signal to update the policy [S1, unofficial].
Additional losses include an offset loss $\mathcal{L}_{offset}$ and a Voronoi loss $\mathcal{L}_{vor}$ for local refinement stability, and a projection loss $\mathcal{L}_{proj}$ to tie anchors to image regions [S1, unofficial]. Removing $\mathcal{L}_{proj}$ causes training to fail [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The decoding cost is $O(B \cdot K_{gs})$, scaling linearly with the Gaussian budget $B$, compared to global self-attention which costs $O(B^2)$ [S1, unofficial]. The hierarchical neighbor search is significantly faster than exact search; for example, at 65,536 Gaussians, hierarchical search is 27× faster (8.1 ms vs. 219.6 ms) [S1, unofficial].
*   **Memory Complexity:** Peak memory scales linearly with the Gaussian budget $B$ [S1, unofficial]. At a budget of 2K Gaussians, RLSplat uses 9.6× less peak memory than F4 Splat [S1, unofficial].
*   **Inference Latency:** Inference latency scales linearly with $B$ [S1, unofficial]. At 2K Gaussians, RLSplat runs 4.1× faster than F4 Splat [S1, unofficial].
*   **Strengths:**
    *   Resource-linear scaling: Both representation size and inference cost decrease linearly as $B$ is reduced [S1, unofficial].
    *   High quality at low budgets: At 2K Gaussians, RLSplat achieves higher PSNR than F4 Splat [S1, unofficial].
    *   Adaptive allocation: Concentrates Gaussians on high-frequency structures (e.g., thin stair balusters) while using fewer on smooth areas, leading to better local and full-view PSNR [S1, unofficial].
*   **Limitations:**
    *   Requires training with GSPO, which involves non-differentiable discrete allocations [S1, unofficial].
    *   Performance depends on the quality of the geometry backbone and the learned allocation policy [S1, unofficial].
*   **When to use:** Applications requiring limited resource budgets, such as AR/VR, robotics, and digital content creation, where inference latency and memory are critical [S1, unofficial].
*   **When not to use:** When maximum possible reconstruction quality is required regardless of resource constraints, as dense methods may outperform RLSplat at very high budgets [S1, unofficial].

## Background
RLSplat was proposed by Bae, Park, and Kim from KAIST [S1, unofficial]. It addresses the limitation of prior budget-controllable FF3DGS methods (EcoSplat, F4 Splat) which predict a dense set of Gaussians and then prune or select, resulting in nearly constant inference latency and peak memory regardless of the target budget [S1, unofficial]. RLSplat introduces a resource-linear framework where the number of Gaussians, inference latency, and peak memory all decrease linearly as the budget $B$ is reduced [S1, unofficial]. It formulates Gaussian generation as an allocation problem and learns a Gaussian allocation policy via reinforcement learning (GSPO) [S1, unofficial]. The method uses a resource-linear decoder that refines Gaussians through local cross-attention with a hierarchical neighbor search [S1, unofficial].
