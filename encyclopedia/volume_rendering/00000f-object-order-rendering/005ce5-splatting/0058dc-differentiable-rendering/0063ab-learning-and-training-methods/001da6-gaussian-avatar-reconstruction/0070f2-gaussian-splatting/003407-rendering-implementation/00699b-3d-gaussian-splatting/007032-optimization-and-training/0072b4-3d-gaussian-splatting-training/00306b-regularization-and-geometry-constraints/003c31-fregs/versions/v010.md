# FreGS

Also called: Frequency-aware regularization for 3DGS, Progressive frequency regularization

## Overview
FreGS addresses the over-reconstruction problem in 3D Gaussian Splatting, where the model generates "floaters" (Gaussians in empty space) and high-frequency artifacts due to overfitting during optimization [S2]. It distinguishes itself from geometric constraints by operating in the frequency domain, regularizing the spectral discrepancies between rendered and ground-truth images to suppress noise while preserving structural integrity [S1, unofficial][S2].

## How it works
FreGS integrates a frequency-aware regularization term into the training pipeline. It operates by comparing the frequency content of the rendered image against the ground truth, penalizing high-frequency residuals that indicate artifacts rather than detail.

**Inputs and Outputs:**
- **Inputs:** Rendered image $I_{render}$, Ground-truth image $I_{gt}$, current Gaussian primitives parameters.
- **Outputs:** Regularization loss $\mathcal{L}_{freq}$, updated gradients for Gaussian parameters.

**Data Structures:**
- **Frequency Domain Representation:** The images are transformed into the frequency domain using the 2D Fast Fourier Transform (FFT). Let $F(I)$ denote the FFT of image $I$.
- **Magnitude Spectrum:** The magnitude of the frequency components is computed as $|F(I)|$.

**Numbered Steps:**
1. **Rendering:** Render the current view using the current set of 3D Gaussians to obtain $I_{render}$.
2. **Frequency Transformation:** Compute the 2D FFT of both the rendered image and the ground-truth image:
   $$ F_{render} = \text{FFT2}(I_{render}) $$
   $$ F_{gt} = \text{FFT2}(I_{gt}) $$
3. **Magnitude Calculation:** Compute the magnitude spectra for both images:
   $$ M_{render} = |F_{render}| $$
   $$ M_{gt} = |F_{gt}| $$
4. **Frequency Discrepancy Calculation:** Compute the difference between the magnitude spectra. This highlights frequency bands where the model has over-reconstructed (high error in high frequencies) or under-reconstructed.
   $$ \Delta M = M_{render} - M_{gt} $$
5. **Regularization Loss:** The frequency regularization loss $\mathcal{L}_{freq}$ is typically defined as the L1 or L2 norm of the frequency discrepancy, potentially weighted by frequency to emphasize high-frequency artifacts. A common formulation is:
   $$ \mathcal{L}_{freq} = \| \Delta M \|_1 $$
   Or, if focusing on high-frequency suppression:
   $$ \mathcal{L}_{freq} = \sum_{u,v} w(u,v) | |F_{render}(u,v)| - |F_{gt}(u,v)| | $$
   where $w(u,v)$ is a weight function that increases with frequency $(u,v)$ to penalize high-frequency noise more heavily.
6. **Backpropagation:** Compute gradients of $\mathcal{L}_{freq}$ with respect to the Gaussian parameters (position, scale, rotation, opacity, color) and update them using an optimizer (e.g., Adam).

**Parameters:**
- **$\lambda_{freq}$:** Weighting factor for the frequency regularization term in the total loss. Typical values are small (e.g., $10^{-3}$ to $10^{-2}$) to avoid overpowering the photometric loss.
- **Frequency Weighting:** The specific form of $w(u,v)$ is not explicitly detailed in the provided sources, but the method implies a focus on high-frequency components [S1, unofficial][S2].

**Edge Cases and Pitfalls:**
- **FFT Boundary Effects:** Zero-padding or windowing may be required to handle image boundaries, though standard FFT implementations handle this implicitly.
- **Gradient Oscillations:** High-frequency regularization can introduce noisy gradients. The sources mention that gradient updates for scaling and rotation can oscillate, suggesting that careful learning rate tuning or gradient rescaling may be necessary [S1, unofficial].

**Pseudocode:**
```python
def compute_freq_regularization_loss(rendered_image, gt_image, lambda_freq=1e-3):
    """
    Computes the frequency regularization loss for FreGS.
    
    Args:
        rendered_image: Tensor of shape (H, W, 3), rendered image.
        gt_image: Tensor of shape (H, W, 3), ground-truth image.
        lambda_freq: Weight for the frequency regularization term.
        
    Returns:
        loss: Scalar tensor, the total loss including frequency regularization.
    """
    # Step 1: Compute FFT of rendered and ground-truth images
    # Assuming images are in range [0, 1] and shape (H, W, C)
    # FFT2 is applied to each channel or the whole image depending on implementation
    F_render = torch.fft.fft2(rendered_image)
    F_gt = torch.fft.fft2(gt_image)
    
    # Step 2: Compute magnitude spectra
    M_render = torch.abs(F_render)
    M_gt = torch.abs(F_gt)
    
    # Step 3: Compute frequency discrepancy
    # Using L1 norm of the difference in magnitude spectra
    freq_diff = torch.abs(M_render - M_gt)
    
    # Step 4: Compute regularization loss
    # The sources do not specify a frequency weighting function w(u,v)
    # We assume a simple L1 norm over all frequencies as a baseline
    loss_freq = torch.mean(freq_diff)
    
    # Step 5: Combine with photometric loss (assumed to be computed elsewhere)
    # For the purpose of this function, we return the frequency loss component
    # The total loss would be L_photometric + lambda_freq * L_freq
    return lambda_freq * loss_freq
```

## Operating characteristics
- **Time Complexity:** The FFT operation is $O(N \log N)$ where $N$ is the number of pixels. This adds a moderate overhead to each training step compared to standard L1/L2 photometric loss.
- **Memory Complexity:** Requires storing the frequency domain representations of the images, which is $O(N)$ memory.
- **Performance:** FreGS reduces over-reconstruction and high-frequency artifacts, leading to cleaner geometry and fewer floaters [S2]. It may slightly increase training time due to the FFT computation.
- **Strengths:** Effective at suppressing noise and artifacts in the frequency domain, which are hard to detect with spatial losses alone.
- **Limitations:** May require careful tuning of the regularization weight $\lambda_{freq}$ to balance detail preservation and artifact suppression.

## Background
FreGS was introduced to address the issue of over-reconstruction in 3D Gaussian Splatting, a common problem where the model generates unnecessary Gaussians in empty space [S2]. The method leverages the fact that photometric loss alone is insufficient for recovering high-quality geometry, often leading to blurred surfaces or floaters . By regularizing frequency discrepancies, FreGS targets the spectral domain, providing a complementary constraint to spatial losses [S1, unofficial][S2].
