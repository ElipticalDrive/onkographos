# 3DGS Initialization Policy

Also called: Initialization Policy, OTS Initialization

## Overview
The 3DGS Initialization Policy defines the strategy for seeding the initial set of 3D Gaussians before the optimization process begins, addressing the problem of sparse or inaccurate starting geometry which can lead to reconstruction artifacts. It sets apart from sibling methods like [Density Control and Densification](5337-density-control-and-densification.md) by focusing on the pre-optimization state rather than dynamic adaptation during training, and differs from [GauFRe](7994-gaufre.md) by relying on explicit geometric seeding (often from SfM) rather than neural field inversion for the primary initialization phase.

## How it works
**Inputs and Outputs:**
- **Input:** A sparse point cloud (typically from Structure-from-Motion, SfM) or a defined scene volume; the total number of Gaussians $N$ to initialize.
- **Output:** A set of $N$ 3D Gaussians, each defined by a mean position $\boldsymbol{\mu}$, a covariance matrix $\boldsymbol{\Sigma}$ (or scale/rotation parameters), and an opacity $\alpha$.

**Data Structures:**
Each Gaussian $i$ is stored with:
- $\boldsymbol{\mu}_i \in \mathbb{R}^3$: Position.
- $\mathbf{q}_i \in \mathbb{R}^4$: Unit quaternion for rotation.
- $\mathbf{s}_i \in \mathbb{R}^3$: Scale vector.
- $\alpha_i \in [0, 1]$: Opacity.
- $\mathbf{c}_i$: Color coefficients (SH coefficients).

**Steps:**
1. **Position Seeding:**
   - For standard 3DGS on synthetic data (e.g., Nerf-Synthetic): Initialize $N$ Gaussians with random positions uniformly distributed within a unit cube centered at the scene origin [S1].
   - For real-world scenes: Use the sparse SfM point cloud as the initial positions. If the SfM cloud is sparse, variants like [DART (Distance-Aware Replication on Tangent-planes)](12512-dart-distance-aware-replication-on-tangent-planes.md) may be used to enrich the cloud by generating samples on local tangent planes before this step [S1].

2. **Opacity Initialization:**
   - Set all Gaussians to a uniform initial opacity $\alpha_0$. This is often referred to as the "OTS weight" [S1].
   - The value of $\alpha_0$ is derived from a power function of the total number of Gaussians $N$:
     $$ \alpha_0 = 2 \cdot N^p $$
     where the exponent $p$ depends on the rendering method:
     - $p = 0.35$ for standard 3DGS [S1].
     - $p = 0.55$ for OTS-based (Order-Independent Transparency) methods [S1].
   - Note: Since opacity must be in $[0, 1]$, this value is typically clamped or used as a scaling factor for the initial alpha values in the optimization [S1].

3. **Scale and Rotation Initialization:**
   - **Standard 3DGS:** Scales are often initialized based on the average distance to the $k$-nearest neighbors in the SfM cloud or randomly within a small range. Rotations are initialized to identity or random [G].
   - **OTS/Advanced Methods:** Scales may be initialized to match the local density or feature size.

4. **Color Initialization:**
   - Colors are typically initialized from the RGB values of the corresponding SfM points or averaged from the training images [G].

**Parameters:**
- $N$: Total number of Gaussians. Typical values: 4k, 12k, 36k, 100k, 500k, 1M [S1].
- $p$: Exponent for opacity scaling (0.35 for 3DGS, 0.55 for OTS) [S1].

**Edge Cases and Pitfalls:**
- **Sparse SfM:** If the initial SfM point cloud is too sparse, especially in low-texture regions or scene peripheries, the reconstruction quality will be poor. This is mitigated by pre-processing steps like DART [S1].
- **Incorrect Geometry:** Starting with incorrect geometry (e.g., from a poor inversion or noisy SfM) can cause artifacts such as "second ears" or fuzzy surfaces during finetuning [S3].
- **Opacity Value:** Using an incorrect exponent $p$ can lead to over- or under-saturated initial opacities, affecting convergence [S1].

**Pseudocode:**
```python
def initialize_gaussians(N, scene_type="synthetic", sfm_cloud=None):
    """
    Initialize N 3D Gaussians based on the 3DGS Initialization Policy.
    
    Args:
        N (int): Total number of Gaussians.
        scene_type (str): 'synthetic' or 'real_world'.
        sfm_cloud (list): List of (position, color) tuples from SfM.
        
    Returns:
        list: List of Gaussian objects with initialized parameters.
    """
    gaussians = []
    
    # Determine opacity exponent based on method (assuming standard 3DGS here)
    # For OTS-based methods, use p=0.55
    p = 0.35 
    
    # Calculate initial opacity value
    # Note: In practice, this might be clamped or used as a base for alpha
    initial_opacity_val = 2 * (N ** p)
    
    for i in range(N):
        g = Gaussian()
        
        # Step 1: Position Seeding
        if scene_type == "synthetic":
            # Random position in unit cube around origin
            g.mu = np.random.uniform(-1, 1, 3)
        elif scene_type == "real_world" and sfm_cloud is not None:
            # Use SfM point if available, otherwise random in bounding box
            if i < len(sfm_cloud):
                g.mu = sfm_cloud[i].position
            else:
                # Fallback: random in bounding box of SfM cloud
                g.mu = np.random.uniform(
                    sfm_cloud[0].position.min(), 
                    sfm_cloud[0].position.max(), 
                    3
                )
        else:
            # Fallback for no SfM
            g.mu = np.random.uniform(-1, 1, 3)
            
        # Step 2: Opacity Initialization
        # Uniform opacity for all Gaussians
        g.alpha = initial_opacity_val
        
        # Step 3: Scale and Rotation Initialization
        # Identity rotation
        g.q = np.array([1, 0, 0, 0])
        # Small random scale or based on neighbor distance [G]
        g.s = np.random.uniform(0.01, 0.1, 3)
        
        # Step 4: Color Initialization
        if scene_type == "real_world" and sfm_cloud is not None and i < len(sfm_cloud):
            g.c = sfm_cloud[i].color
        else:
            g.c = np.array([0.5, 0.5, 0.5])
            
        gaussians.append(g)
        
    return gaussians
```

## Subtopics

### [Gaussian Pruning (Monocular)](10098-gaussian-pruning-monocular.md)
Gaussian Pruning (Monocular) is a preprocessing step for 3D Gaussian Splatting initialization in monocular SLAM that filters out unreliable initial Gaussian centers based on multi-view consistency checks. It prevents incorrect initial geometry from degrading camera tracking performance by ensuring only Gaussians with valid, consistent observations in the training views are retained. Unlike sibling methods that focus on replication or allocation density, this method focuses on quality control of the initial point cloud.

### [DART (Distance-Aware Replication on Tangent-planes)](12512-dart-distance-aware-replication-on-tangent-planes.md)
DART is a pre-processing initialization policy for 3D Gaussian Splatting that enriches a sparse Structure-from-Motion (SfM) point cloud by generating additional samples on local tangent planes. It solves the problem of sparse seeding in scene peripheries and low-texture regions, which typically leads to poor reconstruction quality in those areas. Unlike dynamic densification methods that spawn primitives during training based on view-space gradients, DART acts once before optimization using only the initial SfM geometry, making it independent of the backbone’s densification dynamics. Its distinguishing feature is distance-aware replication: the radius of the tangent disk grows with the point’s distance from the scene center, providing wider spread where the SfM cloud is naturally sparser.

### [Gaussian Allocation Policy](16605-gaussian-allocation-policy.md)
The Gaussian Allocation Policy (GAP) is a reinforcement learning method that determines how to distribute a fixed budget of 3D Gaussians among learned anchor tokens to maximize rendering fidelity. It differs from heuristic initialization methods by treating allocation as a discrete optimization problem solved via Group Sequence Policy Optimization (GSPO), allowing the policy to learn complex geometric dependencies between anchors and required Gaussian density.

### Geometric Correction via Neural Gaussians
A strategy to maximize overlap between cells and emitted neural Gaussians by dynamically aligning cell geometry with Gaussian properties [S2]. It involves: 1. Dynamically defining the cell's quaternion as a weighted average of the quaternions associated with its emitted Gaussians [S2]. 2. Periodically updating cell centers using the formula $\mathbf{x}_n = \frac{\sum_{k=1}^K \boldsymbol{\mu}_{n,k}}{K}$, where $\mathbf{x}_n$ is the cell center, $K$ is the number of Gaussians in the cell, and $\boldsymbol{\mu}_{n,k}$ is the mean of the k-th Gaussian in cell n [S2]. 3. Learning the three-dimensional covariances and positions of first-layer cells in accordance with the updates to the second-layer Gaussians, leveraging the differentiability of cell scales [S2].

### Inversion Initialization
An initialization strategy that starts optimization from an inversion result to prevent geometric artifacts [S3]. Incorrect geometry initialization at the start of finetuning causes artifacts like a second ear, an unrealistic forehead, and a fuzzy surface [S3]. Starting from the inversion result mitigates these artifacts [S3].

## Operating characteristics
- **Time Complexity:** Initialization is $O(N)$, where $N$ is the number of Gaussians. The power function calculation is $O(1)$ per Gaussian.
- **Memory Complexity:** $O(N)$ to store the initial Gaussian parameters.
- **Performance:** Proper initialization significantly reduces the number of training steps required to converge and improves final reconstruction quality, especially in sparse regions [S1].
- **Strengths:** Simple to implement; provides a stable starting point for optimization.
- **Limitations:** Relies heavily on the quality of the initial SfM cloud or random seeding; may require additional preprocessing (like DART) for complex scenes [S1].

## Background
The 3DGS Initialization Policy originates from the original 3D Gaussian Splatting paper and subsequent works like "Does 3D Gaussian Splatting Need Accurate Volumetric Rendering?" [S1]. It was developed to address the challenges of initializing 3D Gaussians for novel view synthesis, particularly in balancing the trade-off between initialization speed and reconstruction accuracy. The policy has been extended to handle different rendering techniques (like OTS) and various scene types (synthetic vs. real-world) [S1].
