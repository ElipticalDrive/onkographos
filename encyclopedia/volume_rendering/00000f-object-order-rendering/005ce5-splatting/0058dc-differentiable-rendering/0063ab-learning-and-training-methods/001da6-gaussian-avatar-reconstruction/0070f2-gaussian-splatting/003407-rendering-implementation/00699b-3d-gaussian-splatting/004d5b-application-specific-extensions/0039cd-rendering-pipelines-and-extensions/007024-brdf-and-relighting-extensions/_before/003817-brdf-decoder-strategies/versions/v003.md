# BRDF Decoder Strategies

Also called: Physical and Neural BRDF Decoding

## Overview
BRDF Decoder Strategies define how 3D Gaussian Splatting primitives encode and reconstruct material properties (such as albedo, roughness, and metalness) or direct light reflection weights during optimization. While standard 3DGS renders color directly, these strategies decouple geometry and appearance to enable physically-based rendering (PBR) and relighting [S1, S2, unofficial]. They differ from sibling methods by focusing specifically on the *decoding* mechanism—whether through explicit physical parameter regression or implicit neural mapping—rather than the rasterization or sorting pipeline itself.

## How it works
The method operates in two distinct modes depending on the availability of ground-truth physical attributes in the training dataset.

### Inputs and Outputs
*   **Inputs:** 3D Gaussian primitives (position, covariance, opacity) and camera/light parameters. Optional: Ground-truth physical maps (albedo, roughness, normal) if available.
*   **Outputs:** Per-pixel color, or decomposed PBR parameters (base color, metalness, roughness, indirect illumination).

### Data Structures
The Gaussian attributes are extended to store BRDF parameters.
*   **Physical Mode:** Stores scalar fields for albedo ($\rho$), roughness ($\alpha$), and metalness ($m$). These are typically clamped or scaled to valid ranges [S2, unofficial].
*   **Neural Mode:** Stores latent vectors or uses MLPs to map view/light directions to reflection weights.

### Steps

1.  **Attribute Regression (Physical Mode):**
    If physical attributes are available, use multiple Multi-Layer Perceptrons (MLPs) to regress physical attributes from the Gaussian features [S1, unofficial].
    *   **Albedo:** Clamped to $[0, 1]$ [S2, unofficial].
    *   **Metalness:** Clamped to $[0, 1]$ [S2, unofficial].
    *   **Roughness:** Scaled and shifted to lie between $0.09$ and $1$ to prevent exceedingly strong specular reflectance [S2, unofficial].

2.  **BRDF Evaluation (Physical Mode):**
    Calculate the BRDF value using a simplified Disney principle-based model [S1, unofficial].
    *   **Normal Distribution Function (NDF):** Calculated using Neilf's formula [S1, unofficial].
    *   **Fresnel Term:** Calculated using Neilf's formula [S1, unofficial].
    *   **Geometry Term:** Calculated using Neilf's formula [S1, unofficial].
    *   The final BRDF value is the product of these terms [S1, unofficial].

3.  **Direct Reflection Weight Regression (Neural Mode):**
    If physical attributes are lacking, use MLPs or LSTMs to directly analyze the energy distribution of incident light and reflection [S1, unofficial].
    *   The BRDF is represented as a light reflection weight [S1, unofficial].
    *   This acts as a degenerated form of light reflection weight without physical constraints [S1, unofficial].

4.  **Highlight Preservation (Neural Mode):**
    Direct training of reflection weights may lead to a loss of highlight information [S1, unofficial]. To mitigate this:
    *   Apply a brightening operation to training images [S1, unofficial].
    *   Multiply pixels with gray values surpassing a threshold by a brightness coefficient [S1, unofficial].

### Pseudocode

```python
def decode_brdf(gaussian_features, view_dir, light_dir, has_physical_gt):
    """
    Decodes BRDF parameters or reflection weights from Gaussian features.
    
    Args:
        gaussian_features: Tensor of shape (N, D) containing learned features.
        view_dir: View direction vector.
        light_dir: Light direction vector.
        has_physical_gt: Boolean, True if physical attributes (albedo, roughness) are available.
        
    Returns:
        brdf_value: Float or Tensor representing the BRDF value or reflection weight.
        physical_params: Dict of physical parameters (if physical mode).
    """
    if has_physical_gt:
        # Physical Mode: Regress physical attributes using MLPs
        albedo = clamp(mlp_albedo(gaussian_features), 0.0, 1.0)
        metalness = clamp(mlp_metalness(gaussian_features), 0.0, 1.0)
        roughness = scale_and_shift(mlp_roughness(gaussian_features), min=0.09, max=1.0)
        
        physical_params = {
            'albedo': albedo,
            'metalness': metalness,
            'roughness': roughness
        }
        
        # Calculate BRDF terms using Neilf's formula
        ndf = neilf_ndf(roughness, view_dir, light_dir)
        fresnel = neilf_fresnel(metalness, albedo, view_dir, light_dir)
        geometry = neilf_geometry(roughness, view_dir, light_dir)
        
        brdf_value = ndf * fresnel * geometry
        return brdf_value, physical_params
    
    else:
        # Neural Mode: Direct regression of reflection weight
        # Use MLP or LSTM to analyze energy distribution
        reflection_weight = mlp_reflection(gaussian_features, view_dir, light_dir)
        
        # Note: No physical constraints are applied here.
        # Highlight loss mitigation is handled in the training loop via image brightening,
        # not in the decoder function itself.
        return reflection_weight, None
```

### Parameters and Edge Cases
*   **Roughness Bounds:** Must be scaled to $[0.09, 1]$ to avoid numerical instability from extremely sharp specular highlights [S2, unofficial].
*   **Highlight Loss:** In neural mode, without physical constraints, highlights may vanish. This is mitigated by pre-processing training images (brightening high-gray-value pixels) [S1, unofficial].
*   **Degenerate Cases:** Imperfect surface meshes and large gradients in HDR space during PBR training can cause dramatic position shifts in vertices, impairing visibility [S2, unofficial].

## Subtopics

### [BRDF-SMAE](12538-brdf-smae.md)
BRDF-SMAE is a method for spatially varying BRDF decomposition in neural volumes, where a single BRDF embedding is stored at each point to enable spatially varying material representation. It differs from standard neural volume rendering by explicitly encoding material properties via an auto-encoder structure rather than implicit color or density fields, allowing for disentangled material analysis. It builds on [BRDF Decoder Strategies](8147-brdf-decoder-strategies.md).

### Deferred Rendering Pipeline for Phys3DGS
A rendering pipeline used to train PBR parameters, involving multiple importance sampling for light rays and post-processing denoising [S2, unofficial].
*   **Light Sampling:** Uses Fibonacci sampling for random incoming light sampling during training. For relighting, adopts NVDiffrecMC’s multiple importance sampling by casting an equal amount of light importance rays and GGX importance rays [S2, unofficial].
*   **Denoising:** Applies a non-parametric bilateral denoiser to the PBR result to cope with low samples per point (spp), enabling real-time rendering [S2, unofficial].
*   **Performance:** Uses 64 spp for real-time rendering with denoiser, compared to 1,024 spp for voxel grid-based methods [S2, unofficial].

## Operating characteristics
*   **Complexity:** Training time increases significantly when adding PBR parameters. Stage 2 (PBR training) takes up to 10 minutes for 10k steps on a single NVIDIA RTX 4090 [S2, unofficial].
*   **Memory:** Storing additional physical attributes (albedo, roughness, metalness) increases the memory footprint per Gaussian compared to standard color-only splatting.
*   **Strengths:** Enables physically-based relighting and material analysis. The deferred pipeline with denoising allows real-time rendering with significantly fewer samples (64 spp) than traditional voxel-based methods (1,024 spp) [S2, unofficial].
*   **Limitations:** Direct neural decoding without physical constraints risks losing highlight information [S1, unofficial]. PBR training in HDR space can cause geometric instability (vertex shifts) if the underlying mesh is imperfect [S2, unofficial].

## Background
BRDF decoding strategies emerged as extensions to 3D Gaussian Splatting to support inverse rendering and relighting. Early approaches used neural networks to directly map directions to reflection weights [S1, unofficial]. Later, physically-based methods like Phys3DGS introduced deferred rendering pipelines with multiple importance sampling to improve relighting quality while maintaining real-time performance [S2, unofficial].
