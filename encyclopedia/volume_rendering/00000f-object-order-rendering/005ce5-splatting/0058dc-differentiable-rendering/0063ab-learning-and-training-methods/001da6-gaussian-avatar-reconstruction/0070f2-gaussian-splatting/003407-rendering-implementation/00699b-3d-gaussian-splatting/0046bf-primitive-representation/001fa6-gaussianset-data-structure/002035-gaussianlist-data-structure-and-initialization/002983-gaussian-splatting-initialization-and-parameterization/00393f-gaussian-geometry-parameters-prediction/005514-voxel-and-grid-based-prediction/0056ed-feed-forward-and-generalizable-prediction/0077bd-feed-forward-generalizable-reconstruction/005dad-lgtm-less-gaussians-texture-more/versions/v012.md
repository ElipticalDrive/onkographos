# LGTM (Less Gaussians, Texture More)
Also called: Feed-Forward Prediction of Textured Gaussians, Feed-Forward Textured Splatting

## Overview
LGTM is a feed-forward framework that predicts compact 2D Gaussian primitives coupled with per-primitive texture maps, decoupling geometric complexity from rendering resolution to enable high-fidelity 4K novel view synthesis without per-scene optimization [S1, unofficial]. It solves the problem where existing feed-forward 3DGS methods exhibit quadratic growth in primitive count as resolution increases, making high-resolution synthesis intractable due to memory and compute limits [S1, unofficial]. Unlike standard 3DGS which couples appearance and geometry within each primitive, LGTM allows a compact set of geometric primitives to represent rich texture regions via per-primitive textures [S1, unofficial].

## How it works
**Inputs and Outputs:**
The network $f$ takes a set of input images $\{I^v\}_{v=1}^N$ and their low-resolution counterparts $\{I^v_{low}\}_{v=1}^N$ [S1, unofficial]. It predicts a set of textured 2D Gaussians:
$$ f : (I^v, I^v_{low}) \rightarrow \{\mu_i, s_i, r_i, c_i, T^i_c, T^i_\alpha\} $$
where $\mu_i$ is the center, $s_i$ is the scale, $r_i$ is the rotation, $c_i$ is the spherical harmonic (SH) coefficients, $T^i_c$ is the color texture map, and $T^i_\alpha$ is the alpha texture map for primitive $i$ [S1, unofficial].

**Data Structures:**
*   **Primitive Grid:** The primitive network predicts a grid of size $h \times w$ corresponding to the low-resolution input dimensions [S1, unofficial].
*   **Per-primitive Texture Maps:** Each primitive $i$ has two texture maps:
    *   Color texture: $T^i_c \in \mathbb{R}^{T \times T \times 3}$
    *   Alpha texture: $T^i_\alpha \in \mathbb{R}^{T \times T}$
    *   $T$ is the texture resolution, a tunable parameter trading off primitive size and texture size [S1, unofficial].
    *   $T^i_c$ is zero-initialized [S1, unofficial].

**Architecture:**
The architecture consists of two submodules [S1, unofficial]:
1.  **Primitive Network ($f_{prim}$):** Processes low-resolution images to predict compact geometric primitives ($\mu, s, r, c$) and base opacity $o_i$. It uses a ViT encoder-decoder. The input is $I^v_{low} \in \mathbb{R}^{h \times w \times 3}$. It outputs primitive features $F^{v}_{prim}$ from the ViT decoder, which are shared with the texture network [S1, unofficial].
2.  **Texture Network ($f_{texture}$):** Processes high-resolution images to predict detailed per-primitive texture maps. It extracts high-resolution features via image patchification and projective mapping, then fuses them with geometric features from the primitive network [S1, unofficial].

**Steps:**

1.  **Primitive Prediction:**
    The primitive network $f_{prim}$ takes the low-resolution image $I^v_{low}$ and predicts the primitive grid parameters $\{\mu_i, s_i, r_i, o_i, c_i\}$ and feature maps $F^{v}_{prim}$ [S1, unofficial].

2.  **Texture Feature Extraction:**
    The texture network $f_{texture}$ computes three feature sets for each primitive $i$ [S1, unofficial]:
    *   **Patch Features ($F^{v}_{patch}$):** Computed from the high-resolution image $I^v$ via patchification and convolutional layers to encode local features.
    *   **Projective Features ($F^{v}_{proj}$):** Extracted from projective prior textures. For each primitive $i$, compute a projective prior texture $T^{i,c,proj}$ using the inverse transformation $M_{i,v}^{-1}$ that maps primitive local coordinates $u$ to source image pixel coordinates $x$:
        $$ T^{i,c,proj}[u] = I^v[x] = I^v[M_{i,v}^{-1}(u)] $$
        Then extract features $F^{v}_{proj}$ from $T^{i,c,proj}[u]$ [S1, unofficial].
    *   **Primitive Features ($F^{v}_{prim}$):** Reused from the primitive network's ViT decoder [S1, unofficial].

3.  **Texture Map Prediction:**
    Aggregate $F^{v}_{prim}$, $F^{v}_{patch}$, and $F^{v}_{proj}$ to predict the per-primitive texture maps $T^i_\alpha$ and $T^i_c$ [S1, unofficial].

4.  **Rendering:**
    For a ray-splat intersection point $u$ on primitive $i$, retrieve color and alpha values from the texture maps using bilinear sampling, denoted by $T[u]$ [S1, unofficial]. The alpha and color are redefined as [S1, unofficial]:
    $$ a_i(u) = o_i \cdot T^i_\alpha[u] $$
    $$ \hat{c}_i(u, d_i) = T^i_c[u] + SH(c_i, d_i) $$
    where $d_i$ is the view direction, $o_i$ is the base opacity, and $SH(c_i, d_i)$ is the spherical harmonic evaluation [S1, unofficial]. The alpha texture replaces the Gaussian falloff, and the color texture adds detail to the SH base color [S1, unofficial].

5.  **Compositing:**
    Compute the final pixel color $C$ by alpha-blending contributions from all primitives sorted by depth [S1, unofficial]:
    $$ C = \sum_i a_i(u_i) \hat{c}_i(d_i) \prod_{j=1}^{i-1} (1 - a_j(u_j)) $$
    [S1, unofficial]

**Training Strategy:**
LGTM uses a staged training strategy [S1, unofficial]:
1.  **Stage 1:** Pre-train the primitive network $f_{prim}$ to predict 2DGS parameters using low-resolution inputs with high-resolution supervision. This establishes a robust geometric foundation [S1, unofficial].
2.  **Stage 2:** Jointly train $f_{prim}$ and $f_{texture}$. Freeze or reduce the learning rate of $f_{prim}$ by 0.1x to maintain geometric stability. The color texture $T^i_c$ is zero-initialized [S1, unofficial].
3.  **Loss:** Standard photometric losses (MSE + LPIPS) are used for supervision in both stages [S1, unofficial].

**Pseudocode:**

```python
def lgtm_forward(input_images, low_res_images, camera_params):
    """
    Forward pass of LGTM.
    input_images: List of high-res images I^v
    low_res_images: List of low-res images I^v_low
    camera_params: Camera parameters for view v
    Returns: Predicted textured Gaussians and rendered image
    """
    # Stage 1: Primitive Network
    # f_prim takes low-res image and predicts primitives and features
    primitives, prim_features = f_prim(low_res_images)
    # primitives contains mu, s, r, c, o for each primitive i
    
    # Stage 2: Texture Network
    # f_texture takes high-res image and prim_features
    # Compute patch features from high-res image
    patch_features = compute_patch_features(input_images)
    
    # Compute projective features
    # Map primitive local coordinates to image pixels using inverse homography
    projective_prior = compute_projective_prior(primitives, input_images, camera_params)
    proj_features = extract_features(projective_prior)
    
    # Aggregate features and predict texture maps
    texture_maps = f_texture(prim_features, patch_features, proj_features)
    # texture_maps contains T_c and T_alpha for each primitive
    
    return primitives, texture_maps

def render_textured_gaussians(primitives, texture_maps, camera_params):
    """
    Render scene using textured 2D Gaussians.
    primitives: List of primitive parameters (mu, s, r, c, o)
    texture_maps: List of texture maps (T_c, T_alpha)
    camera_params: Camera parameters
    Returns: Rendered image
    """
    # Initialize output image
    image = zeros_like(target_resolution)
    
    # Sort primitives by depth
    sorted_primitives = sort_by_depth(primitives, camera_params)
    
    for primitive in sorted_primitives:
        # Find ray-splat intersection u for each pixel
        # This involves computing the homography M_{i,v} and its inverse
        # to get local coordinates u from pixel coordinates x
        u = compute_local_coordinates(primitive, camera_params)
        
        # Sample alpha and color from texture maps using bilinear sampling
        # T[u] denotes bilinear sampling of texture T at local coordinate u
        alpha = primitive.o * texture_maps.alpha[u]
        color = texture_maps.color[u] + spherical_harmonic(primitive.c, primitive.view_direction)
        
        # Alpha blend into image
        # Note: Standard 2DGS rasterization handles the blending order and accumulation
        # Here we show the per-primitive contribution logic
        image = alpha_blend(image, color, alpha)
        
    return image

def compute_projective_prior(primitives, high_res_image, camera_params):
    """
    Compute projective prior texture for each primitive.
    Maps primitive local coordinates back to source image pixels.
    """
    projective_prior = []
    for primitive in primitives:
        # Get inverse homography M^{-1} for this primitive and view
        inv_homography = get_inverse_homography(primitive, camera_params)
        
        # For each local coordinate u in the primitive's texture grid:
        # x = M^{-1}(u)
        # T_proj[u] = high_res_image[x]
        # This is done efficiently via rasterization-like operations
        prior = sample_image_at_inverse_homography(high_res_image, inv_homography)
        projective_prior.append(prior)
    return projective_prior
```

**Edge Cases and Pitfalls:**
*   **Memory Constraints:** Standard feed-forward methods fail to train at 2K or higher resolutions due to memory constraints (OOM). LGTM trains successfully at 2K and 4K using under 30 GB of memory [S1, unofficial].
*   **Holes in Rendering:** Without high-resolution supervision, predicted Gaussians may result in areas with holes as they are not anti-aliased. High-resolution supervision forces the network to learn proper coverage [S1, unofficial].
*   **Geometric Stability:** In Stage 2, the learning rate of the primitive network must be reduced (0.1x) to prevent destabilizing the geometric foundation established in Stage 1 [S1, unofficial].

## Operating characteristics
*   **Time and Memory Complexity:** LGTM scales efficiently at inference; a 64x pixel increase adds only modest memory and time overhead [S1, unofficial]. It uses significantly fewer Gaussian primitives than prior feed-forward methods [S1, unofficial].
*   **Measured Performance:** LGTM trains successfully at 2K and 4K resolutions using under 30 GB of memory, whereas NoPoSplat fails to train at 2K or higher due to memory constraints (OOM) [S1, unofficial].
*   **Strengths:** Enables high-fidelity 4K novel view synthesis without per-scene optimization; decouples geometry and appearance; versatile input baselines (monocular, posed/unposed two-view, multi-view) [S1, unofficial].
*   **Limitations:** Requires a dual-network architecture; relies on high-resolution supervision during training to avoid holes [S1, unofficial].
*   **When to use:** When high-resolution (4K) novel view synthesis is required without per-scene optimization, and computational resources are limited (under 30 GB VRAM) [S1, unofficial].
*   **When not to use:** When per-scene optimization is acceptable and lower resolution is sufficient, or when memory is extremely constrained (<30 GB) and 4K is not required [S1, unofficial].

## Background
LGTM was published as a conference paper at ICLR 2026 by Yixing Lao, Xuyang Bai, Xiaoyang Wu, Nuoyuan Yan, Zixin Luo, Jean-Daniel Nahmias, Yanghai Tsin, Shiwei Li, and Hengshuang Zhao from HKU and Apple [S1, unofficial]. It addresses the resolution scalability bottleneck of feed-forward methods and the per-scene optimization requirement of existing textured Gaussian techniques [S1, unofficial]. It is applicable to monocular (Flash3D), posed two-view (DepthSplat), unposed two-view (NoPoSplat), and multi-view (VGGT) input baselines [S1, unofficial].
