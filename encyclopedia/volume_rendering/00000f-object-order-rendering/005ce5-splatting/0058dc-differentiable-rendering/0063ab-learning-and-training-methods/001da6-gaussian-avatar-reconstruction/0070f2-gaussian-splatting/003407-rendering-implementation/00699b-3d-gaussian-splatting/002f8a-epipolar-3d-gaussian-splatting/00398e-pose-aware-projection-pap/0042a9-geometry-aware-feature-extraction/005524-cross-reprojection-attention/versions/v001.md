# Cross-Reprojection Attention

Also called: CRA Module, Cross-Reprojection Attention (CRA) Module

## Overview
Cross-Reprojection Attention (CRA) is a two-stage attention mechanism that approximates dense semantic connections in 3D space by reprojecting query rays to source views and aggregating features, solving the insufficiency of single-point feature extraction for semantic prediction [S1]. It replaces dense multi-view attention to reduce computational cost and GPU memory usage while maintaining comparable semantic segmentation performance [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A query ray $r(z)$ defined by two points $p_i, p_j$ in the query view; camera poses $(R, t)$ for $m$ source views; camera calibration matrix $K$; $N$ sample points $\{z_k\}_{k=1}^N$ along the ray; feature dimension $C$; number of attention heads $H$.
*   **Outputs:** A refined semantic ray feature $s$ and rendered semantic logits $\hat{S}(r)$.

**Data Structures:**
*   **3D Contextual Space ($M$):** A tensor of shape $\mathbb{R}^{m \times N \times C}$. It is structured as $M = [F_1, \dots, F_m]^T$, where $F_i \in \mathbb{R}^{N \times C}$ contains the features extracted from the $i$-th source view along the reprojected ray.
*   **Attention Projections:** Query ($Q$), Key ($K$), and Value ($V$) matrices of shape $\mathbb{R}^{N \times d_k}$, where $d_k = C/H$.

**Numbered Steps:**

1.  **Ray Warping and Feature Extraction:**
    For each source view $j \in \{1, \dots, m\}$ with pose $(R_j, t_j)$:
    a. Define the query ray in the query view coordinate system:
       $$r(z) = p_i + z \frac{p_j - p_i}{\|p_j - p_i\|}, \quad z \in \mathbb{R}$$
    b. Reproject the ray to the source view plane using the warping function $w$:
       $$r^*(z) = w(r(z), R_j, t_j) = K \pi(R_j \cdot r(z) + t_j)$$
       where $\pi(u) = [u_x/u_z, u_y/u_z]$ is the perspective projection function [S1].
    c. Extract features $F_j(r^*(z))$ at the $N$ sampled points along $r^*(z)$ using a shared U-Net-based CNN (e.g., ResUnet) [S1]. This yields $F_j \in \mathbb{R}^{N \times C}$.
    d. Assemble $M = [F_1, \dots, F_m]^T \in \mathbb{R}^{m \times N \times C}$ [S1].

2.  **Intra-View Radial Attention:**
    Refine the contextual space $M$ to $M'$ by processing each view $F_i$ independently. For each $i \in \{1, \dots, m\}$:
    a. Compute projections:
       $$Q_R = F_i W_q, \quad K_R = F_i W_k, \quad V_R = F_i W_v$$
       where $W_q, W_k, W_v, W_o \in \mathbb{R}^{C \times C}$ are learnable projection matrices [S1].
    b. Compute attention heads for $h = 1, \dots, H$:
       $$A^{(h)} = \text{softmax}\left(\frac{Q_R^{(h)} (K_R^{(h)})^T}{\sqrt{d_k}}\right) V_R^{(h)}$$
       where $d_k = C/H$ [S1].
    c. Concatenate heads and project:
       $$F'_i = \text{Concat}(A^{(1)}, \dots, A^{(H)}) W_o$$
    d. Update $M'$ such that $M' = [F'_1, \dots, F'_m]^T$ [S1].

3.  **Cross-View Sparse Attention:**
    Decompose $M'$ across views to form semantic rays. For each sample point $k \in \{1, \dots, N\}$:
    a. Extract the cross-view feature vector:
       $$F'_{r^*(k)} = [F'_1(r^*(z_k)), \dots, F'_m(r^*(z_k))]^T \in \mathbb{R}^{m \times C}$$
    b. Compute view weights $w \in \mathbb{R}^m$ using a Semantic-aware Weight Network (or fixed uniform weights if not trained) subject to constraints:
       $$w \in \mathcal{C}(\tau) := \left\{ w : 0 < w_i < \frac{\tau}{m}, \sum_{i=1}^m w_i = 1 \right\}$$
       where $\tau > 0$ is a hyperparameter bounding deviation from uniform distribution [S1].
    c. Construct the semantic ray feature $s(z_k)$:
       $$s(z_k) = \sum_{i=1}^m w_i F'_i(r^*(z_k))$$

4.  **Semantic Field Rendering:**
    Render the final semantic logits $\hat{S}(r)$ using volume rendering along the query ray:
    $$\hat{S}(r) = \sum_{k=1}^N T(z_k) \{1 - \exp(-\sigma(z_k)\delta_k)\} s(z_k)$$
    where:
    *   $\sigma(z_k)$ is the predicted density from a Geometry-aware Network [S1].
    *   $\delta_k = z_{k+1} - z_k$ is the interval between sampled points [S1].
    *   $T(z_k) = \exp\left(-\sum_{k'=1}^{k-1} \sigma(z_{k'})\delta_{k'}\right)$ is the accumulated transmittance [S1].

**Pseudocode:**

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

def cross_reprojection_attention(
    query_points_i: torch.Tensor,  # (3,)
    query_points_j: torch.Tensor,  # (3,)
    source_poses: list,            # List of (R, t) tuples, length m
    K: torch.Tensor,               # (3, 3) camera calibration
    num_samples: int = 64,         # N
    feature_dim: int = 256,        # C
    num_heads: int = 8,            # H
    tau: float = 1.0,              # Hyperparameter for weight constraint
    geometry_network: nn.Module,   # Predicts sigma
    cnn_extractor: nn.Module       # Shared U-Net/CNN for feature extraction
) -> torch.Tensor:
    """
    Implements Cross-Reprojection Attention.
    Returns: semantic_logits (C_semantic,)
    """
    m = len(source_poses)
    
    # 1. Ray Definition
    direction = (query_points_j - query_points_i) / torch.norm(query_points_j - query_points_i)
    # Sample z values along the ray. 
    # Note: The paper defines r(z) = pi + z * dir. 
    # We need to sample z values. Standard NeRF sampling or uniform sampling in a range.
    # Assuming z is normalized or sampled in a specific interval [z_min, z_max].
    # For implementation completeness, we assume z_samples is provided or generated.
    # Here we generate linearly spaced z for demonstration, though actual implementation 
    # depends on the specific ray sampling strategy (e.g., stratified sampling).
    z_samples = torch.linspace(0.0, 1.0, num_samples) # Placeholder for actual z range
    
    # 2. Build 3D Contextual Space M
    # M shape: (m, N, C)
    M = torch.zeros(m, num_samples, feature_dim, device=query_points_i.device)
    
    for i, (R, t) in enumerate(source_poses):
        # Ray warping: r*(z) = K * pi(R * r(z) + t)
        # r(z) = query_points_i + z * direction
        # We need to warp the entire ray to the source view.
        # r_world = R * (query_points_i + z * direction) + t
        # This requires broadcasting z_samples.
        
        # Expand direction and points to match z_samples
        dir_exp = direction.unsqueeze(0).expand(num_samples, -1) # (N, 3)
        pi_exp = query_points_i.unsqueeze(0).expand(num_samples, -1) # (N, 3)
        
        # Ray in world space for source view i
        # r(z) in query view is relative to query camera. 
        # The paper says: r*(z) = w(r(z), R, t). 
        # Usually, r(z) is in the query camera frame. 
        # To reproject to source view, we transform r(z) to world, then to source camera.
        # However, the formula w(r(z), R, t) = K * pi(R * r(z) + t) implies 
        # r(z) is treated as a direction/point in a coordinate system where R, t map to source.
        # Standard reprojection: 
        # 1. Transform ray from Query Camera to World: P_w = R_q * P_q + t_q (if points are in query cam)
        #    But here R, t are likely the pose of the source view relative to the query view or world.
        #    Let's assume R, t transform from Query View to Source View directly or via World.
        #    The formula K * pi(R * r(z) + t) suggests R, t are the extrinsics of the source camera 
        #    expressed in the coordinate system of r(z).
        
        # Let's follow the formula strictly:
        # r(z) is a vector/point. 
        # transformed_r = R @ r(z) + t
        # projected_r = K @ transformed_r
        # pixel_r = projected_r[:2] / projected_r[2]
        
        # r(z) shape: (N, 3)
        r_z = pi_exp + z_samples.unsqueeze(1) * dir_exp # (N, 3)
        
        # Apply R and t. R is (3,3), t is (3,)
        # R @ r(z)^T + t
        r_transformed = torch.einsum('ij,nj->ni', R, r_z) + t # (N, 3)
        
        # Project
        r_proj = torch.einsum('ij,nj->ni', K, r_transformed) # (N, 3)
        r_pixel = r_proj[:, :2] / (r_proj[:, 2:] + 1e-6) # (N, 2)
        
        # Extract features using CNN
        # Assuming r_pixel is normalized to [-1, 1] or [0, 1] for grid_sample
        # grid_sample expects normalized coordinates.
        # We assume cnn_extractor takes a batch of images and coordinates.
        # For this pseudocode, we assume cnn_extractor(r_pixel, source_image_i) returns (N, C)
        # In practice, this involves grid sampling from the source view image.
        F_i = cnn_extractor(r_pixel, source_images[i]) # (N, C)
        
        M[i] = F_i

    # 3. Intra-View Radial Attention
    # Refine M to M_prime
    M_prime = torch.zeros_like(M)
    
    # Attention projections
    W_q = nn.Parameter(torch.randn(feature_dim, feature_dim))
    W_k = nn.Parameter(torch.randn(feature_dim, feature_dim))
    W_v = nn.Parameter(torch.randn(feature_dim, feature_dim))
    W_o = nn.Parameter(torch.randn(feature_dim, feature_dim))
    
    for i in range(m):
        F_i = M[i] # (N, C)
        
        Q = torch.einsum('nc,cd->nd', F_i, W_q) # (N, C)
        K_att = torch.einsum('nc,cd->nd', F_i, W_k) # (N, C)
        V = torch.einsum('nc,cd->nd', F_i, W_v) # (N, C)
        
        # Split into heads
        # Q, K, V shape (N, C) -> (N, H, dk)
        dk = feature_dim // num_heads
        Q_heads = Q.view(num_samples, num_heads, dk).transpose(0, 1) # (H, N, dk)
        K_heads = K_att.view(num_samples, num_heads, dk).transpose(0, 1) # (H, N, dk)
        V_heads = V.view(num_samples, num_heads, dk).transpose(0, 1) # (H, N, dk)
        
        # Attention
        # Scores: (H, N, dk) @ (H, dk, N) -> (H, N, N)
        scores = torch.matmul(Q_heads, K_heads.transpose(1, 2)) / (dk ** 0.5)
        attn_weights = F.softmax(scores, dim=-1) # (H, N, N)
        
        # Output
        out_heads = torch.matmul(attn_weights, V_heads) # (H, N, dk)
        
        # Concat and project
        out = out_heads.transpose(0, 1).contiguous().view(num_samples, feature_dim) # (N, C)
        F_i_prime = torch.einsum('nc,cd->nd', out, W_o) # (N, C)
        
        M_prime[i] = F_i_prime

    # 4. Cross-View Sparse Attention & Semantic Ray Construction
    # For each sample point k, aggregate across views
    # Weights w are computed per ray or globally? 
    # The paper says "assign distinct weights to different source views". 
    # It implies a single weight vector w for the entire ray aggregation.
    
    # Compute weights w
    # Constraint: sum(w) = 1, 0 < w_i < tau/m
    # If tau=1, w is uniform 1/m.
    # If tau > 1, weights can deviate.
    # Implementation: Softmax with temperature or constrained optimization.
    # Simple approach: learnable logits, then project to simplex with constraint.
    
    # Placeholder for Semantic-aware Weight Network output
    # Let's assume we have raw scores s_w of shape (m,)
    # We need to enforce 0 < w_i < tau/m and sum(w)=1.
    
    # For simplicity in pseudocode, we use a constrained projection.
    # If tau=1, w = [1/m, ..., 1/m]
    if tau == 1.0:
        w = torch.ones(m, device=M_prime.device) / m
    else:
        # Learnable weights or fixed heuristic. 
        # The paper mentions a "Semantic-aware Weight Network".
        # We assume it outputs raw scores.
        # Here we use a placeholder for the network output.
        raw_scores = torch.randn(m, device=M_prime.device) # Placeholder
        # Apply softmax to get base distribution
        w_base = F.softmax(raw_scores, dim=0)
        
        # Project to constraint set C(tau)
        # This is a non-trivial projection. 
        # A simple approximation for tau > 1:
        # w_i = clamp(w_base, min=epsilon, max=tau/m)
        # Then renormalize.
        # Note: The constraint is strict. 
        # For implementation, one might use a projected gradient step or a specific layer.
        # We will use a simplified projection for the pseudocode.
        
        min_val = 1e-6
        max_val = tau / m
        
        # Clip
        w_clipped = torch.clamp(w_base, min=min_val, max=max_val)
        
        # Renormalize to sum to 1
        w = w_clipped / w_clipped.sum()

    # Aggregate features for each sample point
    # M_prime shape: (m, N, C)
    # w shape: (m,)
    # s(z_k) = sum_i w_i * M_prime[i, k, :]
    
    # s shape: (N, C)
    s = torch.einsum('i,nci->nc', w, M_prime) # (N, C)

    # 5. Semantic Field Rendering
    # Predict density sigma
    # s is used for semantic features, sigma is predicted by geometry network
    # The geometry network likely takes the ray or the features as input.
    # Assuming geometry_network takes the ray points or features.
    # Let's assume it takes the aggregated features s or the raw ray points.
    # The paper says "sigma is predicted by a Geometry-aware Network".
    # Usually, this is a MLP taking position and/or features.
    
    # Placeholder for sigma prediction
    # sigma shape: (N,)
    sigma = geometry_network(s) # (N,)
    
    # Compute intervals
    # z_samples needs to be actual depth values, not 0..1
    # Assuming z_samples are depths
    deltas = torch.diff(z_samples, dim=0) # (N-1,)
    # Pad the last delta or assume uniform
    deltas = torch.cat([deltas, deltas[-1]]) # (N,)
    
    # Compute transmittance
    # T(z_k) = exp(- sum_{k'=1}^{k-1} sigma(z_{k'}) * delta_{k'})
    # alpha_k = 1 - exp(-sigma_k * delta_k)
    
    alphas = 1.0 - torch.exp(-sigma * deltas) # (N,)
    
    # Accumulated transmittance
    # T_0 = 1
    # T_k = T_{k-1} * (1 - alpha_{k-1})
    # Using cumprod
    # (1 - alpha) is transmittance between k-1 and k
    T_prev = 1.0 - alphas[:-1] # (N-1,)
    T = torch.cat([torch.tensor([1.0], device=sigma.device), torch.cumprod(T_prev, dim=0)]) # (N,)
    
    # Render
    # S_hat = sum T_k * alpha_k * s_k
    weights_render = T * alphas # (N,)
    semantic_logits = torch.einsum('n,nc->c', weights_render, s) # (C,)
    
    return semantic_logits
```

**Parameters:**
*   $\tau$: Hyperparameter for weight distribution deviation bound. Constraint: $0 < w_i < \tau/m$. Keeps semantic consistency instead of bias across views. $\tau=1$ corresponds to mean aggregation [S1].
*   $d_k$: Dimension of each attention head. Calculated as $d_k = C/H$, where $C$ is feature dimension and $H$ is number of heads [S1].

**Edge Cases and Pitfalls:**
*   **Precision:** The projection function $\pi(u)$ involves division by $u_z$. Ensure $u_z$ is not zero (ray parallel to image plane) to avoid division by zero. Add a small epsilon [S1].
*   **Boundaries:** The reprojection $r^*(z)$ may fall outside the image boundaries of source views. The CNN extractor should handle out-of-bounds coordinates (e.g., via padding or clamping) [S1].
*   **Degenerate Input:** If source views are too close or too far, the reprojection may be inaccurate. The method assumes known camera poses $(R, t)$ and calibration $K$ [S1].

## Operating characteristics
*   **Time and Memory Complexity:** CRA improves performance by 47.3% in FLOPs and 76.5% in GPU memory compared to dense attention [S1].
*   **Measured Performance:** On real data (ScanNet), with an input of $1024 \times 64 \times 8 \times 32$, the full CRA module achieves 76.30% mIoU and 91.08% Total Accuracy with 5.40 GFLOPs, compared to 10.25 GFLOPs for Dense Attention [S1].
*   **Strengths:** Captures dense and global contextual information with computational efficiency; avoids heavy computational costs of dense attention [S1].
*   **Limitations:** Relies on accurate camera poses and calibration; performance depends on the quality of the shared CNN feature extractor [S1].
*   **When to use:** When generalizable semantic rendering is required with limited computational resources (GPU memory/FLOPs) [S1].
*   **When not to use:** When extremely high precision in view-dependent effects is needed and computational budget is unlimited (dense attention might be slightly better, though CRA is comparable) [S1].

*   **Origin:** Proposed in the S-Ray method [S1].
