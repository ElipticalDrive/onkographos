# MCMC Densification
Also called: Markov Chain Monte Carlo, SGLD Densification, Stochastic Gradient Langevin Dynamic (SGLD) Densification

## Overview
MCMC Densification is a Bayesian optimization strategy that reformulates Gaussian Splatting densification as a Stochastic Gradient Langevin Dynamic (SGLD) update rule [S2, unofficial]. Unlike standard adaptive density control which clones and splits individual Gaussians based on gradient magnitude, MCMC densification samples a fixed number of Gaussians from a learned probability distribution [S1]. It distinguishes itself by adding a noise term to the position of the Gaussians to incorporate exploration during training, while re-spawning Gaussians that drop below an opacity threshold randomly at Gaussians with high opacity [S1]. This approach reduces reliance on the initial point cloud, allows for specifying the number of Gaussians prior to optimization, and improves rendering quality in regions with few initial primitives [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** The current set of 3D Gaussians $\mathcal{G}$, each defined by mean position $\mu$, covariance $\Sigma$, opacity $\alpha$, and spherical harmonics coefficients. The current camera views $\mathcal{I}$ and the reconstruction loss $\mathcal{L}_{\text{total}}$.
*   **Output:** Updated set of Gaussians $\mathcal{G}'$ with modified parameters and potentially re-localized centers.

**Data Structures:**
The Gaussian set $\mathcal{G}$ is stored as a list or array of objects. Each Gaussian $g_i \in \mathcal{G}$ contains:
*   $\mu_i \in \mathbb{R}^3$: Center location.
*   $\Sigma_i \in \mathbb{R}^{3 \times 3}$: Covariance matrix (often parameterized via rotation $R$ and scale $S$).
*   $\alpha_i \in [0, 1]$: Opacity.
*   Other attributes (color, SH coefficients) as required by the renderer.

**Parameters:**
*   $\lambda_{\text{lr}}$: Learning rate hyperparameter for the gradient descent step [S2, unofficial].
*   $\lambda_{\text{noise}}$: Noise scale hyperparameter applied to the center locations $\mu$ of Gaussians [S2, unofficial].
*   $\epsilon$: Noise term drawn from a standard normal distribution [S2, unofficial].
*   Opacity threshold: A value below which a Gaussian is considered for re-spawning [S1].

**Steps:**
1.  **Gradient Computation:** Compute the gradient of the total loss with respect to the Gaussian parameters $\mathcal{G}$ using stochastic gradient descent over a batch of images $\mathcal{I}$ [S2, unofficial].
    $$ \nabla_{\mathcal{G}} \mathbf{E}_{\mathcal{I}} [\mathcal{L}_{\text{total}} (\mathcal{G}; \mathcal{I})] $$
2.  **SGLD Update:** Update the Gaussian parameters by combining the gradient descent step with a noise term [S2, unofficial]:
    $$ \mathcal{G} \leftarrow \mathcal{G} - \lambda_{\text{lr}} \cdot \nabla_{\mathcal{G}} \mathbf{E}_{\mathcal{I}} [\mathcal{L}_{\text{total}} (\mathcal{G}; \mathcal{I})] + \lambda_{\text{noise}} \cdot \epsilon $$
    The noise $\epsilon$ is applied specifically to the center locations $\mu$ of the Gaussians to encourage exploration of the parameter space [S2, unofficial].
3.  **Re-spawning (Pruning and Spawning):** Identify Gaussians whose opacity $\alpha_i$ drops below a predefined threshold. These Gaussians are removed from the scene. To maintain the target number of Gaussians or sample from the learned distribution, new Gaussians are spawned randomly at the locations of Gaussians that currently have high opacity [S1]. This re-localization scheme preserves the sample probability [S3, unofficial].
4.  **Iteration:** Repeat steps 1-3 for the training duration.

**Pseudocode:**
```python
def mcmc_densification_step(Gaussians, Images, lambda_lr, lambda_noise, opacity_threshold):
    """
    Performs one step of MCMC densification.
    
    Args:
        Gaussians: List of Gaussian objects with attributes .mu, .alpha, etc.
        Images: Batch of reference images for loss computation.
        lambda_lr: Learning rate.
        lambda_noise: Noise scale.
        opacity_threshold: Threshold for pruning/re-spawning.
        
    Returns:
        Updated Gaussians list.
    """
    # 1. Compute gradients
    loss = compute_reconstruction_loss(Gaussians, Images)
    gradients = compute_gradients(loss, Gaussians)
    
    # 2. SGLD Update
    for g in Gaussians:
        # Gradient descent step
        g.mu = g.mu - lambda_lr * gradients[g].mu
        # Add noise to center location for exploration
        noise = sample_normal_distribution(size=3)
        g.mu = g.mu + lambda_noise * noise
        # Update other parameters (covariance, opacity, SH) via gradient descent
        # Note: Noise is typically only applied to mu in SGLD formulation for 3DGS
        update_other_params(g, gradients[g])
        
    # 3. Re-spawning based on opacity
    pruned_gaussians = []
    high_opacity_gaussians = []
    
    for g in Gaussians:
        if g.alpha < opacity_threshold:
            pruned_gaussians.append(g)
        else:
            high_opacity_gaussians.append(g)
            
    # Remove pruned Gaussians
    Gaussians = [g for g in Gaussians if g.alpha >= opacity_threshold]
    
    # Re-spawn new Gaussians at locations of high opacity Gaussians
    # The number of new Gaussians equals the number of pruned ones to maintain count
    # or to sample from the distribution.
    num_to_spawn = len(pruned_gaussians)
    for _ in range(num_to_spawn):
        # Select a parent Gaussian randomly from high opacity ones
        parent = random.choice(high_opacity_gaussians)
        # Create new Gaussian with similar properties but potentially perturbed
        new_g = Gaussian()
        new_g.mu = parent.mu + sample_normal_distribution(size=3) * small_scale
        new_g.alpha = parent.alpha # Or initialize with small opacity
        new_g.covariance = parent.covariance
        new_g.color = parent.color
        Gaussians.append(new_g)
        
    return Gaussians
```

**Edge Cases and Pitfalls:**
*   **Precision:** The noise injection can lead to instability if $\lambda_{\text{noise}}$ is too large, causing Gaussians to diverge from the scene geometry.
*   **Boundaries:** Re-spawning at high-opacity Gaussians may cluster Gaussians in already well-represented areas if not balanced with the exploration noise.
*   **Degenerate Input:** If the initial point cloud is sparse, the MCMC approach may take longer to converge to a dense representation compared to splitting methods, as it relies on random exploration.

## Subtopics

### [HYDRA Densification](11088-hydra-densification.md)
HYDRA is a densification strategy for 3D Gaussian Splatting that decomposes complex, multi-lobed primitives into simpler constituents within the MCMC framework. It solves the problem of undersampled regions by subdividing primitives with high positional gradients while preserving the target distribution $P(g_{\text{new}}) \approx P(g_{\text{old}})$. It distinguishes itself from standard splitting by using a learned decomposition for large primitives, enabling generalizable planar primitives to operate effectively within MCMC.

### Fast MCMC Densification
An optimized implementation of the MCMC densification approach from 3DGS-MCMC [39], which treats 3D Gaussians as MCMC samples and uses SGLD updates [S3, unofficial]. It fuses the noise injection step into a single CUDA kernel to reduce training time bottleneck [S3, unofficial]. On the Mip-NeRF360 dataset, the optimized version achieves 28.00 PSNR, 6m17s training time, and 7.2GiB VRAM, compared to the original 27.83 PSNR, 27m22s training time, and 8.9GiB VRAM [S3, unofficial]. The target number of Gaussians for the nine Mip-NeRF360 scenes (alphabetical order) are: 6131954, 1244819, 1222956, 3636448, 5834784, 1852335, 1593376, 4961797, 3783761 [S3, unofficial]. The optimized version is significantly faster and uses less VRAM than the original implementation [39], while achieving similar or slightly better quality [S3, unofficial].

### Dynamic LoD Hierarchy Densification
A novel hierarchy densification strategy that allows Gaussian Level-of-Detail (LoD) hierarchies to evolve continuously during optimization, supporting stable refinement and restructuring without post-training hierarchy construction [S4, unofficial]. It maintains the hierarchy throughout training as Gaussian parameters and spatial distribution evolve dynamically [S4, unofficial]. Unlike methods that construct the hierarchy post-training, this method evolves the hierarchy continuously during optimization [S4, unofficial].

## Operating characteristics
*   **Time Complexity:** The SGLD update is $O(N)$ per iteration where $N$ is the number of Gaussians. The re-spawning step is also $O(N)$ if implemented efficiently. The optimized CUDA kernel implementation reduces constant factors significantly [S3, unofficial].
*   **Memory Complexity:** $O(N)$ to store Gaussian parameters. The optimized version uses less VRAM (7.2GiB vs 8.9GiB on Mip-NeRF360) due to fused kernels [S3, unofficial].
*   **Measured Performance:** On Mip-NeRF360, Fast MCMC Densification achieves 28.00 PSNR in 6m17s with 7.2GiB VRAM, outperforming the original 3DGS-MCMC (27.83 PSNR, 27m22s, 8.9GiB VRAM) [S3, unofficial].
*   **Strengths:** Reduces reliance on initial point cloud quality; allows pre-specifying the number of Gaussians; improves quality in undersampled regions [S1].
*   **Limitations:** May require careful tuning of $\lambda_{\text{noise}}$ and opacity threshold; convergence can be slower in very sparse initial configurations compared to aggressive splitting [S1].
*   **When to use:** When the initial point cloud is sparse or noisy, or when a fixed number of Gaussians is desired. Also useful for large-scale scenes where dynamic hierarchy evolution is needed [S4, unofficial].
*   **When not to use:** When rapid convergence is critical and the initial point cloud is dense and well-distributed.

## Background
MCMC Densification was introduced by Kheradmand et al. (2024) as an alternative Bayesian perspective to the densification strategy in Gaussian Splatting [S2, unofficial]. It reformulates the densification process as a Stochastic Gradient Langevin Dynamic (SGLD) update rule [S2, unofficial]. This approach was motivated by the advantages of reducing reliance on the initial point cloud, allowing specification of the number of Gaussians prior to optimization, and leading to improved rendering quality [S3, unofficial]. The method has been further optimized for performance in frameworks like Faster-GS [S3, unofficial] and integrated into hierarchical rendering strategies [S4, unofficial].
