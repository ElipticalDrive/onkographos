# Self-Organizing Gaussian Grids

Also called: Self-Organizing Gaussians

## Overview
Self-Organizing Gaussian Grids is a compact 3D scene representation that organizes the high-dimensional parameters of 3D Gaussian Splatting (3DGS) into a 2D grid with local homogeneity to drastically reduce storage size without compromising visual quality [S1]. It differs from fixed-ordering methods like [Z-order curves](17106-hierarchical-graph-based-and-adaptive-structures.md) or [Tri-planes](17106-hierarchical-graph-based-and-adaptive-structures.md) by learning a scene-specific topological mapping via unsupervised competitive learning, rather than imposing a static spatial traversal [S2].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of optimized 3D Gaussian primitives $\{G_i\}$ from a standard 3DGS training run, where each Gaussian $i$ has parameters: position $\mathbf{p}_i \in \mathbb{R}^3$, scale $\mathbf{s}_i \in \mathbb{R}^3$, rotation quaternion $\mathbf{q}_i \in \mathbb{R}^4$, opacity $\alpha_i \in \mathbb{R}$, and spherical harmonics coefficients for color $\mathbf{c}_i \in \mathbb{R}^D$ [S1].
*   **Output:** A 2D grid representation where Gaussians are mapped to grid cells, enabling efficient compression using standard image codecs [S1, S2].

**Data Structures:**
The method organizes attributes into multiple data layers that share a consistent 2D layout [S2].
1.  **Grid Dimensions:** The grid size $W \times H$ is determined by the number of Gaussians $N$. Typically, $W \approx H \approx \sqrt{N}$ [S1, S2].
2.  **Cell Content:** Each cell $(u, v)$ in the grid stores the index of the Gaussian mapped to that position, or a null value if empty. Alternatively, the grid stores the parameters directly if the grid resolution matches the Gaussian count exactly (one Gaussian per cell) [S1].
3.  **Parameter Layers:** Separate 2D grids are created for each attribute type (e.g., one grid for positions, one for colors, one for opacities) [S2]. These grids preserve the topological relationship: Gaussians that are similar in high-dimensional parameter space are placed in neighboring cells [S2].

**Algorithm Steps:**
The core process relies on Self-Organizing Maps (SOM), an unsupervised learning model [S2].

1.  **Initialization:**
    *   Flatten all Gaussian parameters into a single high-dimensional vector $\mathbf{x}_i$ for each Gaussian $i$. This vector typically concatenates normalized position, scale, rotation, opacity, and color coefficients [S1, S2].
    *   Initialize a 2D grid of weight vectors $\mathbf{m}_{u,v}$ of size $W \times H$, where each $\mathbf{m}_{u,v}$ has the same dimensionality as $\mathbf{x}_i$. Initialize $\mathbf{m}_{u,v}$ randomly or by sampling from the input data [S2].

2.  **Competitive Learning (SOM Training):**
    *   For each input vector $\mathbf{x}_i$:
        *   Find the Best Matching Unit (BMU) $(u^*, v^*)$ in the grid:
            $$ (u^*, v^*) = \arg \min_{u,v} \| \mathbf{x}_i - \mathbf{m}_{u,v} \|_2 $$
        *   Update the BMU and its neighbors to become more like $\mathbf{x}_i$:
            $$ \mathbf{m}_{u,v}(t+1) = \mathbf{m}_{u,v}(t) + \eta(t) \cdot h_{u^*,v^*,u,v}(t) \cdot (\mathbf{x}_i - \mathbf{m}_{u,v}(t)) $$
            Where:
            *   $\eta(t)$ is the learning rate at iteration $t$, decaying over time.
            *   $h_{u^*,v^*,u,v}(t)$ is the neighborhood function, typically a Gaussian kernel:
                $$ h_{u^*,v^*,u,v}(t) = \exp\left(-\frac{\| (u,v) - (u^*,v^*) \|^2}{2\sigma(t)^2}\right) $$
            *   $\sigma(t)$ is the neighborhood radius, decaying over time [S2].

3.  **Mapping:**
    *   After training converges, map each Gaussian $i$ to the grid cell $(u_i, v_i)$ corresponding to its BMU [S2].
    *   Construct the 2D grids for each attribute layer. If multiple Gaussians map to the same cell, they may be averaged, or the grid resolution is increased to ensure a 1:1 mapping (one Gaussian per cell) [S1, S2].

4.  **Smoothness Enforcement (Optional/Integrated):**
    *   During the optimization phase, a smoothness loss can be enforced between neighboring parameters in the grid to further enhance compressibility [S1]. This loss penalizes differences between adjacent cells in the 2D grid:
        $$ \mathcal{L}_{smooth} = \sum_{u,v} \| \mathbf{P}_{u,v} - \mathbf{P}_{u+1,v} \|^2 + \| \mathbf{P}_{u,v} - \mathbf{P}_{u,v+1} \|^2 $$
        Where $\mathbf{P}_{u,v}$ is the parameter vector at grid cell $(u,v)$ [S1].

5.  **Compression:**
    *   The resulting 2D grids are treated as images and compressed using standard codecs (e.g., JPEG, WebP, or PNG) [S2].

**Pseudocode:**

```python
import numpy as np

def train_som(input_vectors, grid_shape, iterations=1000):
    """
    Trains a Self-Organizing Map to organize high-dimensional Gaussian parameters.
    
    Args:
        input_vectors: np.array of shape (N, D), where N is number of Gaussians, D is dimensionality.
        grid_shape: tuple (W, H), dimensions of the 2D grid.
        iterations: int, number of training steps.
        
    Returns:
        grid_weights: np.array of shape (W, H, D), the learned weight vectors.
        mappings: np.array of shape (N,), mapping each Gaussian to a grid cell index.
    """
    N, D = input_vectors.shape
    W, H = grid_shape
    
    # Initialize grid weights randomly from input data
    grid_weights = np.random.choice(input_vectors, size=(W * H, D))
    grid_weights = grid_weights.reshape(W, H, D)
    
    # Learning rate and neighborhood radius schedules
    eta_init = 0.05
    sigma_init = max(W, H) / 2.0
    
    for t in range(iterations):
        # Decay parameters
        eta = eta_init * (1 - t / iterations)
        sigma = sigma_init * (1 - t / iterations)
        
        # Shuffle input vectors for stochastic training
        indices = np.random.permutation(N)
        
        for idx in indices:
            x = input_vectors[idx]
            
            # Find Best Matching Unit (BMU)
            # Flatten grid for distance calculation
            grid_flat = grid_weights.reshape(-1, D)
            distances = np.linalg.norm(grid_flat - x, axis=1)
            bmu_idx = np.argmin(distances)
            bmu_pos = np.unravel_index(bmu_idx, (W, H))
            
            # Update neighbors
            for u in range(W):
                for v in range(H):
                    dist = np.sqrt((u - bmu_pos[0])**2 + (v - bmu_pos[1])**2)
                    # Neighborhood function (Gaussian)
                    h = np.exp(-(dist**2) / (2 * sigma**2))
                    
                    # Update weight
                    grid_weights[u, v, :] += eta * h * (x - grid_weights[u, v, :])
    
    # Map each input vector to its BMU
    grid_flat = grid_weights.reshape(-1, D)
    distances = np.linalg.norm(input_vectors[:, np.newaxis, :] - grid_flat[np.newaxis, :, :], axis=2)
    bmu_indices = np.argmin(distances, axis=1)
    mappings = np.unravel_index(bmu_indices, (W, H))
    
    return grid_weights, mappings

def compress_gaussians(gaussians, grid_shape):

    """
```

**Parameters:**
*   **Grid Dimensions ($W \times H$):** Typically chosen such that $W \times H \ge N$ to avoid collisions, or exactly $N$ for 1:1 mapping. Common values are $\sqrt{N} \times \sqrt{N}$ [S1, S2].
*   **Learning Rate ($\eta$):** Initial value around 0.05, decaying linearly or exponentially [S2].
*   **Neighborhood Radius ($\sigma$):** Initial value $\max(W, H)/2$, decaying linearly [S2].
*   **Iterations:** 1000–5000 steps are typical for convergence [S2].

**Pitfalls:**
*   **Encoding Complexity:** The SOM training process is computationally expensive and requires optimization to determine the element order, unlike fixed-ordering methods [S2].
*   **Parameter Normalization:** High-dimensional vectors must be normalized appropriately before SOM training to prevent attributes with larger magnitudes (e.g., position) from dominating the distance metric over attributes with smaller magnitudes (e.g., opacity) [S2].
*   **Collision Handling:** If $W \times H < N$, multiple Gaussians map to the same cell, requiring averaging or loss of detail [S1].

## Operating characteristics
*   **Storage Reduction:** Achieves a reduction factor of 17x to 42x in size for complex scenes compared to standard 3DGS [S1].
*   **Rendering Performance:** Maintains fast rendering speeds comparable to standard 3DGS because the uncompressed Gaussians use the same structure as standard 3DGS during rasterization [S1]. The decoding overhead is minimal as the 2D grids are decompressed into standard Gaussian lists [S2].
*   **Training Time:** No increase in training time for the initial 3DGS model; the compression step is post-processing [S1]. However, the encoding (SOM training) adds a significant computational cost during the compression phase [S2].
*   **Strengths:** Drastic storage reduction; seamless integration with established 3DGS renderers; exploits perceptual redundancies [S1].
*   **Limitations:** High encoding complexity; requires scene-specific optimization; not suitable for dynamic scenes where Gaussians change frequently during training [S2].

## Background
*   **Origin:** Introduced by Wieland Morgenstern, Florian Barthel, Anna Hilsmann, and Peter Eisert from Fraunhofer Heinrich Hertz Institute and Humboldt University of Berlin [S1].
*   **Publication:** arXiv:2312.13299v2, published May 2, 2024 [S1].
*   **History:** The method builds on the concept of Self-Organizing Maps (SOMs) [25] (Kohonen maps), an unsupervised learning model that projects high-dimensional data onto a lower-dimensional grid while preserving topological relationships [S2]. It was developed specifically for 3DGS compression to address the high storage requirements of 3DGS models, which can take up to several hundred megabytes [S1].
