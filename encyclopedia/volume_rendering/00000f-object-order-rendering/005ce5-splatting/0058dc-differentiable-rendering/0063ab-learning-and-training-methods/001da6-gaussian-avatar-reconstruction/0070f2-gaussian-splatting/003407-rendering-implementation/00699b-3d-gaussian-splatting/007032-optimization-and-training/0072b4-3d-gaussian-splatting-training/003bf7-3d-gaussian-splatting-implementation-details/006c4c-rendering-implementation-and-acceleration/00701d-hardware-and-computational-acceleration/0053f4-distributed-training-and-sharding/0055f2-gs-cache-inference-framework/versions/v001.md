# GS-Cache Inference Framework

Also called: GS-Cache

## Overview
GS-Cache is a holistic rendering framework designed to support real-time rendering of large-scale 3D Gaussian Splatting (3DGS) models at the city level, achieving >72 FPS at binocular 2K resolution by using a cache-centric de-redundancy pipeline and elastic parallel scheduling [S1, unofficial]. It specifically targets 'Structured Gaussian derivation methods' (like Scaffold-GS and Octree-GS) which use anchors to derive neural Gaussians, addressing the bottleneck of the 'Gaussian Derivation Stage' (decoding anchor features) which dominates computation time [S1, unofficial]. Unlike native 3DGS or unstructured methods, GS-Cache optimizes the inter-frame redundancy in the derivation stage while maintaining full rasterization quality, as slight perspective changes significantly affect occlusion in the rasterization stage [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Camera pose sequence, structured 3DGS model parameters (anchors, MLP weights for derivation), previous frame cache state.
*   **Output:** Rendered image frames at target resolution (e.g., binocular 2K).

**Data Structures:**
*   **Anchor Set ($X$):** The total set of anchors for decoding in the current frame.
*   **Cache:** Stores derived Gaussian parameters (position, scale, rotation, color, opacity) for anchors. The cache maps anchor indices to cached Gaussian parameters.
*   **Cache Index Mapping:** A translation mechanism from anchor indices to cache indices.
*   **Heuristic Function ($H$):** Guides the dynamic cache depth scheduling.

**Numbered Steps:**
1.  **Camera Input Processing:** The current camera input is used to compute anchor indices. These indices filter the anchors to be decoded and locate corresponding anchors in the cache [S1, unofficial].
2.  **Index Mapping:** Anchor indices are translated to cache indices using index mapping [S1, unofficial].
3.  **Anchor Filtering and Cache Lookup:** The system checks if the required Gaussian parameters for the filtered anchors are present in the cache.
4.  **Selective Decoding:**
    *   If an anchor's parameters are in the cache, they are reused from the previous frames.
    *   If an anchor's parameters are not in the cache, they are decoded simultaneously using the AnchorDecoder (typically an MLP) [S1, unofficial].
    *   This step removes inter-frame redundancy in the derivation stage [S1, unofficial].
5.  **Cache Scheduling and Update:** The cache scheduler performs scheduling based on the filtered anchors, loading necessary model parameters for the decoding stage. Results of previous decoding computations are updated in the cache [S1, unofficial].
6.  **Dynamic Cache Depth Scheduling:** A dynamic cache depth scheduling strategy adjusts the depth of reuse and cached parameters according to the intensity of decoding calculations in the current frame. This uses a heuristic function $H$ to determine the expected reuse depth [S1, unofficial].
7.  **Gaussian Rasterization:** The derived or cached Gaussian parameters are passed to the rasterizer. This stage is not accelerated by caching to maintain visual quality, as slight perspective changes significantly affect occlusion [S1, unofficial].
8.  **Cache Flushing:** To avoid rendering errors from maintaining Gaussian appearance parameters in the cache for too long (e.g., on trajectories around a centered target), the cache is flushed in time, triggering cache re-filling and inter-frame reusing [S1, unofficial].

**Formulas:**
The expected reuse depth is determined by the heuristic function $H$ applied to the update rate:
$$ \text{depth} = H\left(\frac{|X_k'|}{|X|}\right) $$
Where:
*   $\text{depth}$ is the expected reuse depth [S1, unofficial].
*   $H$ is the guiding function of the heuristic strategy [S1, unofficial].
*   $|X_k'|$ is the number of newly decoded anchors from the previous $k$ frames [S1, unofficial].
*   $|X|$ is the total anchor set for decoding in the current frame [S1, unofficial].

**Parameters:**
*   $k$: The number of previous frames from which newly decoded anchors ($X_k'$) are considered for the update rate calculation [S1, unofficial].
*   $H$: The guiding function of the heuristic cache reuse depth scheduling strategy [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Cache Staleness:** Maintaining Gaussian appearance parameters in the cache for too long can cause significant rendering errors, especially on trajectories around a centered target. The cache must be flushed in time [S1, unofficial].
*   **Rasterization Quality:** The rasterization stage cannot be accelerated by caching because slight perspective changes significantly affect occlusion. Ignoring this would degrade visual quality [S1, unofficial].
*   **Dynamic Depth Adjustment:** Static cache reuse depth can cause rapid changes in scene appearance upon flushing. The dynamic strategy suppresses this [S1, unofficial].

## Subtopics

### Structured Gaussian Derivation Methods
Methods like Scaffold-GS and Octree-GS that use anchors to derive neural Gaussians. GS-Cache is specifically designed for these methods [S1, unofficial].

### Gaussian Derivation Stage
The computationally intensive stage of decoding anchor features into neural Gaussian parameters. This is the primary bottleneck GS-Cache addresses [S1, unofficial].

### Gaussian Rasterization Stage
The stage of splatting 3D neural Gaussians to 2D and rasterizing them into an image. This stage is not cached by GS-Cache to maintain quality [S1, unofficial].

## Operating characteristics
*   **Performance:** GS-Cache achieves an average frame rate exceeding 72 FPS at binocular 2K resolution for large-scale city-level scenes [S1, unofficial].
*   **Scalability:** The framework is designed for large-scale 3DGS models, addressing the challenges of real-time photo-realistic rendering, particularly on VR applications [S1, unofficial].
*   **Strengths:**
    *   Significantly enhances rendering efficiency through cache-centric de-redundancy [S1, unofficial].
    *   Supports elastic parallel rendering [S1, unofficial].
    *   Maintains rendering quality without significant decrease or fluctuation due to cached results [S1, unofficial].
*   **Limitations:**
    *   Specifically targets structured Gaussian derivation methods; not directly applicable to native 3DGS or unstructured methods [S1, unofficial].
    *   The rasterization stage cannot be accelerated by caching, limiting overall speedup potential [S1, unofficial].
*   **When to Use:** Real-time rendering of large-scale 3DGS models, especially in VR applications requiring binocular 2K resolution [S1, unofficial].
*   **When Not to Use:** When using native 3DGS or unstructured methods where anchor-based derivation is not present [S1, unofficial].

## Background
GS-Cache was introduced in the paper "A GS-Cache Inference Framework for Large-Scale Gaussian Splatting Models" [S1, unofficial]. It addresses the challenges associated with real-time photo-realistic rendering of large-scale 3DGS models, particularly for VR applications. The framework was developed to support elastic parallel rendering and to optimize the Gaussian derivation rendering pipeline patterns [S1, unofficial].
