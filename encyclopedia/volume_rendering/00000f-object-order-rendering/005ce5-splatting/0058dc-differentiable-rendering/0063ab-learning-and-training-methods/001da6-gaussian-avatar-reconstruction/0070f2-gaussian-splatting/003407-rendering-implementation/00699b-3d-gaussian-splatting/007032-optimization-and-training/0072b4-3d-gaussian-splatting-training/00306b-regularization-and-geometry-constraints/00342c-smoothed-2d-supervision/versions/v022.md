# Smoothed 2D Supervision

Also called: Adaptive Gaussian blur strategy, Progressive Gaussian Blurring

## Overview
Smoothed 2D Supervision is a regularization technique that enhances the robustness of joint optimization by smoothing the 2D supervision signal [S1][S2, unofficial]. It addresses the instability in camera alignment and the overfitting to high-frequency noise during the early stages of training [S2, unofficial][S3]. Unlike methods that modify the 3D primitives directly, this approach modifies the target image used for gradient computation [S2, unofficial]. It sets itself apart from [Frequency Regularization](6130-frequency-regularization.md) by applying explicit spatial blurring to the supervision signal rather than adjusting positional encoding frequencies, and from [Hard and Soft Depth Regularization](9178-hard-and-soft-depth-regularization.md) by operating in the 2D image domain rather than enforcing geometric depth constraints [S2, unofficial][S3].

## How it works
**Inputs and Outputs:**
- Input: A set of 2D training images $I_{raw}$ and a current optimization iteration $t$.
- Output: A smoothed supervision image $I_{smooth}$ used for computing the rendering loss.

**Data Structures:**
- The supervision signal is a 2D image tensor with dimensions $H \times W \times C$ (Height, Width, Channels).
- The blur kernel is a 2D Gaussian kernel $K$ defined by its standard deviation $\sigma$ and size $S \times S$.

**Parameters:**
- Initial kernel size: $9 \times 9$ [S4].
- Initial standard deviation: $\sigma_0 = 2.4$ [S4].
- Schedule interval: $k_b = 100$ iterations [S4].
- End of blurring: Iteration 19,500 [S4].
- Downsampling scale factor: $s$ (applied if downsampling is active) [S4].

**Steps:**
1. **Initialize Kernel:** Set the Gaussian kernel size to $9 \times 9$ and standard deviation $\sigma = 2.4$ [S4].
2. **Iterative Schedule:** For each optimization iteration $t$:
   a. If $t \le 19,500$:
      i. Calculate the current $\sigma_t$. The sources indicate a gradual reduction of the blur [S3, S4]. Specifically, [S4] states the kernel size is lowered every $k_b=100$ iterations. [S2, unofficial] mentions an exponential reduction to 0 at 10k iterations in a related context, but [S4] provides the specific schedule for Trick-GS: reduce kernel size every 100 iterations until 19,500. [S3] describes it as "progressively reducing the standard variance." We follow the explicit step-wise reduction in [S4] for implementation clarity, noting the variance reduction described in [S3].
      ii. If downsampling is active, adjust the kernel size by the downsampling scale $s$ [S4].
      iii. Convolve the raw training image $I_{raw}$ with the current Gaussian kernel $K(\sigma_t)$ to produce $I_{smooth}$ [S2, unofficial][S4].
   b. If $t > 19,500$:
      i. Set $I_{smooth} = I_{raw}$ (no blur) [S4].
3. **Loss Computation:** Compute the rendering loss (e.g., L1 or LPIPS) between the rendered image $I_{render}$ and the smoothed supervision image $I_{smooth}$ [S2, unofficial][S3].

**Formula:**
The smoothed supervision image $I_{smooth}(x, y)$ is computed as:
$$ I_{smooth}(x, y) = \sum_{i=-k}^{k} \sum_{j=-k}^{k} I_{raw}(x-i, y-j) \cdot K(i, j; \sigma_t) $$
where $K(i, j; \sigma_t) = \frac{1}{2\pi\sigma_t^2} e^{-\frac{i^2+j^2}{2\sigma_t^2}}$ is the 2D Gaussian kernel, and $k = \lfloor S/2 \rfloor$.

**Edge Cases and Pitfalls:**
- **Boundary Conditions:** When convolving near image borders, padding (e.g., reflection or replication) must be used to avoid artifacts [G].
- **Precision:** Ensure $\sigma$ does not become negative or zero before the final iteration if the schedule is continuous; however, [S4] specifies a discrete reduction, so $\sigma$ remains positive until the final step where blur is disabled [S4].
- **Downsampling Interaction:** If the image is downsampled, the kernel size must be scaled accordingly to maintain the effective blur radius in the original image space [S4].

**Pseudocode:**
```python
def get_smoothed_supervision(raw_image, iteration, initial_sigma=2.4, kernel_size=9, schedule_interval=100, end_iteration=19500, downsampling_scale=1.0):
    """
    Computes the smoothed 2D supervision image based on the current iteration.
    
    Args:
        raw_image: The original training image tensor.
        iteration: Current optimization iteration number.
        initial_sigma: Initial standard deviation of the Gaussian kernel.
        kernel_size: Initial kernel size (S x S).
        schedule_interval: Number of iterations between kernel size reductions.
        end_iteration: Iteration after which blurring is disabled.
        downsampling_scale: Scale factor if image downsampling is active.
        
    Returns:
        smoothed_image: The blurred supervision image.
    """
    if iteration > end_iteration:
        return raw_image
    
    # Calculate current kernel parameters
    # The number of reductions performed so far
    steps = iteration // schedule_interval
    
    # Reduce kernel size linearly or based on schedule
    # Note: [S4] says "lower the blurring kernel size... every k_b iterations"
    # We assume a linear reduction of the kernel size or sigma. 
    # [S3] says "progressively reduce the standard variance".
    # [S4] gives specific start/end points. We implement a linear decay of sigma 
    # from initial_sigma to 0 over the end_iteration, or step-wise as per [S4].
    # Given [S4] specifies "lower the kernel size", we adjust the kernel dimensions.
    
    current_kernel_size = kernel_size
    current_sigma = initial_sigma
    
    # Apply schedule: reduce kernel size every schedule_interval iterations
    # Assuming a linear reduction of kernel size to 1 (or minimal) by end_iteration
    if end_iteration > 0:
        progress = iteration / end_iteration
        # Linear interpolation of sigma from initial_sigma to 0
        current_sigma = initial_sigma * (1 - progress)
        
        # Adjust kernel size based on sigma or steps
        # A 9x9 kernel at sigma=2.4. As sigma decreases, kernel can shrink.
        # We keep kernel size fixed at 9x9 but adjust sigma, or shrink kernel.
        # [S4] explicitly says "lower the blurring kernel size".
        # Let's reduce kernel size linearly to 3x3 (minimum for Gaussian)
        min_kernel = 3
        current_kernel_size = int(kernel_size - (kernel_size - min_kernel) * progress)
        if current_kernel_size % 2 == 0:
            current_kernel_size += 1 # Ensure odd size
        if current_kernel_size < min_kernel:
            current_kernel_size = min_kernel
            
    # Adjust for downsampling
    # [S4]: "lower the kernel size by the scale of downsampling"
    # This likely means the effective kernel in the downsampled space is smaller,
    # or the kernel in original space is scaled. We apply the blur in the 
    # resolution of the raw_image. If raw_image is downsampled, we blur the 
    # downsampled image with a scaled kernel.
    # Assuming raw_image is already downsampled if downsampling is active.
    # The note says "initial hyperparameter choice is based on original image resolutions".
    # So if we are working on downsampled images, we must scale the kernel.
    if downsampling_scale > 1.0:
        # Scale down the kernel size and sigma for the lower resolution
        current_kernel_size = max(min_kernel, int(current_kernel_size / downsampling_scale))
        if current_kernel_size % 2 == 0:
            current_kernel_size += 1
        current_sigma = current_sigma / downsampling_scale

    # Apply Gaussian Blur
    smoothed_image = apply_gaussian_blur(raw_image, current_sigma, current_kernel_size)
    
    return smoothed_image

def apply_gaussian_blur(image, sigma, kernel_size):
    """
    Applies a 2D Gaussian blur to an image.
    """
    # Create Gaussian kernel
    k = kernel_size // 2
    y, x = np.ogrid[-k:k+1, -k:k+1]
    kernel = np.exp(-(x**2 + y**2) / (2 * sigma**2))
    kernel = kernel / np.sum(kernel)
    
    # Convolve image with kernel
    # Assuming image is a numpy array or tensor
    # Use standard convolution with appropriate padding
    smoothed = convolve2d(image, kernel, mode='same', boundary='fill', fillvalue=0)
    return smoothed
```

## Subtopics

### [Randomly Scaled Kernel Parameter](7875-randomly-scaled-kernel-parameter.md)
Randomly Scaled Kernel Parameter is a regularization technique used during joint optimization to mitigate weak and noisy gradient signals. It addresses the insufficiency of using a single-size kernel for diverse real-world scene structures, where a fixed kernel may be overly aggressive in some contexts and overly gentle in others. By randomly scaling the kernel size, it allows combinations of different-sized kernels to guide the optimization, resulting in a more robust training schedule.

### [Multiscale Pre-convolved Representation](10911-multiscale-pre-convolved-representation.md)
A regularization technique for neural illumination fields that stabilizes the decomposition of object materials from environmental illumination by enforcing consistency with pre-computed, roughness-adapted background reflections. It addresses the ambiguity where diffuse object color is incorrectly absorbed into the estimated environment map, a problem inherent to high-dimensional neural illumination representations. Unlike methods that ignore the background or treat it as static, this method explicitly models the relationship between rough refractive surfaces and the convolved background, allowing for realistic specular reflections even when roughness exceeds the kernel scale. The technique builds on [Smoothed 2D Supervision](7213-smoothed-2d-supervision.md) by applying discrete Gaussian blur kernels to the background to stabilize convergence.

### [Soft Rasterization](13687-soft-rasterization.md)
Soft rasterization is a differentiable rendering technique that mitigates the discontinuities inherent in standard rasterization by blending facet contributions for pixels near primitive edges. It solves the problem of sparse and vanishing gradients caused by the non-uniformity of bilinear interpolation operands, which typically have similar values except at object boundaries. Unlike standard hard rasterization, it yields slightly distorted images but allows backpropagating more useful gradients, thereby stabilizing optimization and preventing gradient vanishing at edges.

### Platonic GAN (pGAN)
Platonic GAN (pGAN) is a learning-based method for 2D supervision per class of reconstructed objects, used here to pre-train a network for per-frame supervision of rising smoke [S5]. It provides a target for supervision where explicit geometric or photometric constraints are difficult to define, such as in fluid dynamics [S5].

## Operating characteristics
**Time and Memory Complexity:**
- The method adds a convolution operation per iteration. The complexity is $O(H \cdot W \cdot K^2)$ per image, where $K$ is the kernel size [S1]. Since the kernel is small (max 9x9), this is negligible compared to the rendering cost [S1].
- Memory overhead is minimal, storing only the blurred image [S1].

**Measured Performance:**
- On DTU 3-view, Smoothed 2D Supervision achieves 19.72 PSNR, improving over the Baseline of 19.54 PSNR [S3].
- It reduces training iterations required for successful pose refinement, with some methods requiring only 50k iterations compared to 200k for previous methods [S1].

**Strengths and Limitations:**
- **Strengths:** Stabilizes camera alignment, restricts the spectrum of the learned 3D scene, and improves robustness in joint optimization [S2, unofficial][S3]. It is experimentally proven crucial for successful pose refinement [S1].
- **Limitations:** It is handcrafted and cannot fully align frequency relationships between positional encoding and pixel supervision as effectively as adaptive methods [S3].

**When to Use:**
- Use when optimizing camera poses jointly with scene representation to prevent divergence [S1][S2, unofficial].
- Use when training data is noisy or contains high-frequency artifacts that hinder convergence [S2, unofficial].

**When Not to Use:**
- When high-frequency detail preservation is critical from the start, as blurring removes high frequencies [S2, unofficial].
- When an adaptive frequency alignment method is available and computationally feasible [S3].

## Background
Smoothed 2D Supervision was introduced as part of techniques to improve the robustness of joint optimization in radiance fields and Gaussian Splatting [S1][S2, unofficial]. It draws inspiration from spectral analysis of rendering losses, where blurring the supervision signal helps stabilize gradients [S2, unofficial]. It has been used in methods such as Trick-GS [S4] and Few-shot NeRF [S3]. The technique is often combined with other regularization methods like Randomly Scaled Kernel Parameter [S1] and Edge Guided Loss [S2, unofficial].
