# Edge-guided Splitting Strategy


## Overview
The Edge-guided Splitting Strategy (ESS) is a densification method for 3D Gaussian Splatting that refines primitives by splitting large Gaussians located in high-frequency edge regions to capture fine details [S1]. It addresses the loss of high-frequency detail caused by enlarged primitives, particularly when used alongside Random Dropout Regularization (RDR) [S1].

## How it works
**Inputs and Outputs**
*   **Input:** A set of 3D Gaussian primitives $\mathcal{G}$ (each with mean $\mu$, covariance $\Sigma$, scaling $s$, opacity $\alpha$, and spherical harmonic features $f$), a set of $M$ training viewpoints, and an edge detection function [S1, G].
*   **Output:** An updated set of primitives where large Gaussians with high edge scores are split into smaller primitives [S1].

**Data Structures**
*   **Gaussian Primitive $i$:** Stores scalar size $S_i$ (derived from scaling factors), opacity $\alpha_i$, and position [S1].
*   **Edge Map $E(I)$:** A pixel-wise probability map ranging from $0$ to $1$, generated by an edge detection method on input view $I$ [S1].
*   **Binary Mask $\mathcal{M}^i(p)$:** Indicates whether pixel $p$ is covered by primitive $i$ [S1].

**Parameters**
*   $\mathcal{S}_{thr}$: Size threshold for splitting. Value not given in the sources [S1].
*   $\mathcal{E}_{thr}$: Edge threshold for splitting. Value not given in the sources [S1].
*   $M$: Number of viewpoints used for edge score accumulation [S1].

**Steps**
1.  **Edge Map Generation:** For each input view $I$, compute the pixel-wise edge probability map $E(I)$ using an edge detection method [S1].
2.  **Single-View Edge Score Calculation:** For each Gaussian primitive $i$ and each viewpoint $k$, calculate the single-view edge score $\mathcal{E}_{i,k}'$ by aggregating the edge probabilities of covered pixels, weighted by the primitive's alpha-blending contribution [S1]:
    $$ \mathcal{E}_{i,k}' = \alpha_i \prod_{j=1}^{i-1}(1-\alpha_j) \cdot \sum_{p} E(I_k) \mathcal{M}_k^i(p) $$
    where $\mathcal{M}_k^i(p)$ is the binary mask for pixel $p$ covered by primitive $i$ in view $k$, and the term $\alpha_i \prod_{j=1}^{i-1}(1-\alpha_j)$ represents the standard alpha-blending weight $w_i$ [S1].
3.  **Accumulate Edge Score:** Compute the final edge score $\mathcal{E}_i$ for primitive $i$ by summing the single-view scores across all $M$ viewpoints, normalized by the number of pixels covered by the primitive in each view [S1]:
    $$ \mathcal{E}_i = \sum_{k=1}^M \frac{\mathcal{E}_{i,k}'}{\sum_{p} \mathcal{M}_k^i(p)} $$
4.  **Splitting Mask Determination:** Identify primitives to split using the mask $\mathcal{M}_{edge}$, which selects primitives satisfying both a size condition and an edge score condition [S1]:
    $$ \mathcal{M}_{edge} = \{ S_i \geq \mathcal{S}_{thr} \} \cap \{ \mathcal{E}_i \geq \mathcal{E}_{thr} \} $$
    where $S_i$ is the size of the $i$-th primitive [S1].
5.  **Splitting:** Split all Gaussian primitives $i$ where $\mathcal{M}_{edge}$ is true into smaller primitives [S1].

**Pseudocode**
```python
def compute_edge_scores(primitives, views, edge_maps, cameras):
    """Computes the final edge score E_i for each primitive across M views."""
    M = len(views)
    final_scores = {}
    for i, prim in enumerate(primitives):
        total_score = 0.0
        for k in range(M):
            cam = cameras[k]
            emap = edge_maps[k]
            # [G] Standard 3DGS projection to find covered pixels
            covered_pixels = get_covered_pixels(prim, cam)
            pixel_count = len(covered_pixels)
            if pixel_count == 0:
                continue
            # [G] Standard alpha blending weight computation
            w_i = compute_alpha_weight(prim, cam)
            edge_sum = sum(emap[p] for p in covered_pixels)
            e_prime = w_i * edge_sum
            total_score += e_prime / pixel_count
        final_scores[prim.id] = total_score
    return final_scores

def get_covered_pixels(prim, cam):
    # [G] Projects 3D Gaussian covariance to 2D screen space, computes bounding box,
    # and returns list of pixel indices where coverage > 0.
    return []

def compute_alpha_weight(prim, cam):

    # the rasterization order of primitives in the current view.
    return prim.alpha

def apply_edge_guided_splitting(primitives, edge_scores, s_thr, e_thr):
    """Splits primitives that are large and have high edge scores."""
    to_split = []
    for prim in primitives:
        size = get_primitive_size(prim)
        score = edge_scores[prim.id]
        if size >= s_thr and score >= e_thr:
            to_split.append(prim)

    # and redistribute opacity/features.
    new_primitives = []
    for prim in to_split:
        new_primitives.extend(split_primitive(prim))
    remaining = [p for p in primitives if p not in to_split]
    return remaining + new_primitives
```

**Edge Cases and Pitfalls**
*   **Division by Zero:** The normalization in step 3 divides by the number of pixels covered by the primitive. If a primitive covers zero pixels in a view, its contribution to that view is skipped or treated as zero [G].
*   **Threshold Selection:** The values for $\mathcal{S}_{thr}$ and $\mathcal{E}_{thr}$ are not specified in the sources [S1].
*   **Edge Detection Dependency:** The quality of ESS depends on the edge detection method used to generate $E(I)$ [S1].

## Operating characteristics
*   **Time Complexity:** Not given in the sources [S1].
*   **Memory Complexity:** No significant additional memory beyond storing edge maps and scores [G].
*   **Strengths:** Effectively captures high-frequency details in edge regions, improving performance on sparse-view benchmarks (LLFF, DTU, Blender) [S1]. Compatible with diverse 3DGS-based methods [S1].
*   **Limitations:** Relies on the quality of edge detection [S1].
*   **When to Use:** When high-frequency detail recovery is critical, especially in sparse-view settings or when using regularization techniques like RDR that may enlarge primitives [S1].

## Background
The Edge-guided Splitting Strategy (ESS) was introduced in the DropoutGS paper by Xu et al. in 2025 [S1]. It was developed to remedy the loss of high-frequency details caused by enlarged primitives, which can occur during optimization or when using Random Dropout Regularization (RDR) to alleviate overfitting [S1]. DropoutGS combines RDR and ESS to improve generalization performance in sparse-view novel view synthesis [S1].
