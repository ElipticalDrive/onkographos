# BlitzGS


## Overview
BlitzGS is a distributed 3D Gaussian Splatting framework that accelerates city-scale training by reducing the active Gaussian workload at system, model, and view levels [S1, unofficial]. Unlike spatial block partitioning, which incurs cross-block visibility waste and imbalanced shards, BlitzGS shards Gaussians across GPUs by index parity and couples this with importance-based pruning and distance-based Level-of-Detail filtering [S1, unofficial]. It achieves nearly an order-of-magnitude training speedup over baselines like Momen.GS and CityGS-X while maintaining high reconstruction quality [S1, unofficial].

## How it works
**Inputs:** A set of calibrated images, an initial set of 3D Gaussians $\mathcal{G}$, and $M$ GPUs [G].
**Outputs:** Optimized 3D Gaussian parameters (position, scale, rotation, opacity, spherical harmonic coefficients) and rendered novel views [G].

**Data Structures:**
*   **Global Gaussian Set $\mathcal{G}$:** Partitioned into shards $\mathcal{G}^{(m)}$ for each GPU $m \in \{0, \dots, M-1\}$ [S1, unofficial].
*   **Sharding Strategy:** Gaussians are assigned to GPU $m$ based on index parity (even/odd indices), ensuring balanced distribution without spatial locality constraints [S1, unofficial].
*   **Tile Ownership:** The image plane is divided into tiles, with each tile assigned to a specific GPU [S1, unofficial].

**Algorithm Steps:**

1.  **System-Level Sharding and Distribution:**
    *   Partition $\mathcal{G}$ into shards $\mathcal{G}^{(m)}$ by index parity so each GPU holds $\approx |\mathcal{G}|/M$ Gaussians [S1, unofficial].
    *   Each GPU projects its local shard to 2D screen space [S1, unofficial].
    *   Perform a single cross-GPU all-to-all exchange to route projected Gaussians to the GPUs owning the tiles they cover [S1, unofficial].

2.  **Model-Level Population Control:**
    *   Execute importance-scoring passes to prune redundant Gaussians and emit per-(Gaussian, camera) importance signals [S1, unofficial].
    *   Use a lightweight spawn gate to withhold candidates predicted not to survive before they spawn [S1, unofficial].
    *   Apply the importance signal to reweight density control gradients during optimization [S1, unofficial].

3.  **View-Level Filtering:**
    *   Apply a distance-based LOD gate to drop Gaussians too fine for the current camera distance [S1, unofficial].
    *   Apply an importance-based mask to skip Gaussians with negligible cross-view contribution, trimming the active set [S1, unofficial].

4.  **Rasterization and Optimization:**
    *   Each GPU composites pixels for its assigned tiles using the filtered Gaussians [S1, unofficial].
    *   Compute loss and backpropagate gradients [G].
    *   Update Gaussian parameters using the locally maintained optimizer state [S1, unofficial].

**Pseudocode:**

```python
def blitzgs_training(images, initial_gaussians, num_gpus, num_iterations):
    # 1. Initialization: Shard by index parity
    shards = [initial_gaussians[i::num_gpus] for i in range(num_gpus)]
    optimizer_states = [Optimizer(shard) for shard in shards]

    for iteration in range(num_iterations):
        # 2. System-Level: Projection and Communication
        projected_gaussians = [project_2d(shard, images[iteration].camera) for shard in shards]
        received_gaussians = all_to_all_exchange(projected_gaussians)

        # 3. Model-Level: Population Control
        importance_scores = compute_importance(received_gaussians, optimizer_states)
        active_gaussians = prune_by_importance(received_gaussians, importance_scores)

        candidates = densification_candidates(active_gaussians)
        surviving_candidates = spawn_gate(candidates, importance_scores)
        active_gaussians = merge(active_gaussians, surviving_candidates)

        # 4. View-Level: Filtering
        filtered_gaussians = apply_lod_gate(active_gaussians, images[iteration].camera)
        final_gaussians = apply_importance_mask(filtered_gaussians, importance_scores)

        # 5. Rasterization
        rendered_images = [rasterize_tiles(final_gaussians, images[iteration].camera, m) for m in range(num_gpus)]

        # 6. Optimization
        loss = compute_loss(rendered_images, images[iteration].ground_truth)
        gradients = backward(loss)
        reweighted_gradients = reweight_gradients(gradients, importance_scores)

        for m in range(num_gpus):
            update_optimizer(optimizer_states[m], reweighted_gradients[m])
            shards[m] = optimizer_states[m].get_parameters()

    return shards

# Helper definitions
def project_2d(shard, camera): return [g.project(camera) for g in shard]
def all_to_all_exchange(projected): return distribute_by_tile(projected)
def compute_importance(gaussians, states): return [g.importance_signal(states) for g in gaussians]
def prune_by_importance(gaussians, scores): return [g for g, s in zip(gaussians, scores) if s > 0.0]
def densification_candidates(active): return generate_new_primitives(active)
def spawn_gate(candidates, scores): return [c for c, s in zip(candidates, scores) if s > 0.0]
def merge(active, candidates): return active + candidates
def apply_lod_gate(gaussians, camera): return [g for g in gaussians if g.scale > 0.0]
def apply_importance_mask(gaussians, scores): return [g for g, s in zip(gaussians, scores) if s > 0.0]
def compute_loss(rendered, ground_truth): return sum((r - gt)**2 for r, gt in zip(rendered, ground_truth))
def backward(loss): return compute_gradients(loss)
def reweight_gradients(grads, scores): return [g * s for g, s in zip(grads, scores)]
def update_optimizer(state, grads): state.step(grads)
def distribute_by_tile(projected): return all_gather(projected)
def generate_new_primitives(active): return create_candidates(active)
def create_candidates(active): return active.copy()
def all_gather(projected): return projected
```

**Parameters:**
*   **Hardware:** 4x NVIDIA A6000 GPUs [S1, unofficial].
*   **Sharding:** Index parity (even/odd) [S1, unofficial].
*   **LOD Threshold:** Not given in the sources.
*   **Importance Threshold:** Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Imbalanced Shards:** Spatial block partitioning leads to imbalanced shards due to varying scene density; index parity sharding avoids this [S1, unofficial].
*   **Cross-Block Visibility:** Spatial partitioning causes visibility waste at boundaries; index parity sharding eliminates the need for a final merge step [S1, unofficial].
*   **Precision:** Not given in the sources.

## Operating characteristics
*   **Time Complexity:** Training time is significantly reduced. On the Rubble scene, BlitzGS takes 39 minutes compared to 5 hours 3 minutes for Momen.GS and 4 hours 45 minutes for CityGS-X [S1, unofficial].
*   **Memory Complexity:** By pruning redundant Gaussians and gating spawns, the peak population of Gaussians is limited, reducing memory usage per GPU [S1, unofficial].
*   **Performance:** Achieves scene-average PSNR of 24.66 dB on Residence and 33.79 dB on Rubble [S1, unofficial].
*   **Strengths:** Near order-of-magnitude speedup on city-scale scenes; avoids cross-block redundancy; balanced load distribution [S1, unofficial].
*   **Limitations:** Requires a single cross-GPU all-to-all exchange per render step to route projected Gaussians to tile owners; effectiveness depends on the accuracy of the importance scoring and spawn gating [S1, unofficial].
*   **When to use:** Large-scale, city-scale 3DGS training where speed is critical and high-quality reconstruction is required [S1, unofficial].

## Background
BlitzGS was introduced by Zhongtao Wang, Huishan Au, Yisong Chen, Meng Gai, Yilong Li, Fei Zhu, Mai Su, Haojie Jin, and Guoping Wang in the paper "BlitzGS: City-Scale Gaussian Splatting at Lightning Speed" [S1, unofficial]. The work addresses the high computational cost of city-scale 3DGS training, which involves preprocessing, communication, and rasterization of overly dense primitive sets [S1, unofficial]. It builds on insights from prior work on distributed 3DGS [S1, unofficial].
