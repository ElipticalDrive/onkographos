# LinPrim Differentiable Rendering Pipeline

Also called: LinPrim Rendering, LinPrim rasterizer, Linear Primitive Rendering, Linear Primitives for Differentiable Volumetric Rendering, Octahedron Rendering

## Overview
LinPrim is a differentiable rendering pipeline that replaces the Gaussian primitives of 3D Gaussian Splatting with convex polyhedra, specifically octahedra, to enable explicit geometric representation [S1]. It solves the problem of approximating complex scene geometry with bounded, triangular surfaces while maintaining real-time performance and full differentiability for gradient-based optimization [S1]. Unlike its sibling [3D Gaussian Splatting](3d-gaussian-splatting.md) which uses implicit Gaussian kernels, LinPrim uses explicit ray-triangle intersections to determine opacity, allowing gradients to be backpropagated directly onto the geometric features of the polyhedra [S1].

## How it works
The pipeline follows a two-stage process: per-primitive preprocessing followed by per-pixel rasterization [S1]. This structure allows efficient parallelization of primitive construction and sorting before the final compositing stage [S1].

### Inputs and Outputs
*   **Inputs:**
    *   Scene primitives defined by position, rotation, and distance parameters [S1].
    *   Camera pose (view matrix) and intrinsic parameters [S1].
    *   Spherical Harmonic (SH) coefficients for view-dependent color [S1].
*   **Outputs:**
    *   A 2D image with accumulated color and opacity [S1].

### Data Structures
Each primitive stores the following features [S1]:
1.  **Position:** 3D center coordinates.
2.  **Rotation:** Orientation of the primitive.
3.  **Distances:** Parameters defining the shape. For octahedra, symmetry is enforced by choosing a single distance to describe opposing corners, reducing complexity [S1].
4.  **SH Coefficients:** 48 floats (Spherical Harmonics) to capture complex reflectance under varying illumination and view angles [S1]. This accounts for the majority of memory per primitive [S1].

### Steps

1.  **Preprocessing:**
    *   Construct the primitive geometry from position, distances, and rotation [S1].
    *   Transform the primitive into the camera's coordinate system using the camera pose [S1].
    *   Calculate view-dependent color based on the viewing direction using the stored SH coefficients [S1].
    *   Project the primitive into the 3D affine ray space approximation (EWA Splatting) [S1]. This approximation is valid because small primitives keep the error negligible [S1].
    *   Compute the projected bounding box in screen space to determine visibility [S1].

2.  **Global Sorting and Tiling:**
    *   Tile the screen into regions (e.g., $16 \times 16$ tiles) [S1].
    *   Sort primitives within each tile according to an approximate front-to-back order [S1].

3.  **Rasterization:**
    *   For each pixel, cast a ray from the camera origin through the pixel center [S2, unofficial].
    *   Determine if the ray intersects the convex primitive. Since primitives are convex, the ray intersects either twice or not at all [S1].
    *   Use the Möller-Trumbore Intersection Algorithm (MTIA) to find the intersection points [S1]. This algorithm is fully differentiable [S1].
    *   If two intersections exist, calculate the distance between them [S1].

4.  **Opacity Calculation and Normalization:**
    *   The reconstruction is scale-ambiguous. To ensure consistent appearance across different scene sizes, normalize the intersection distances [S1].
    *   Determine the smallest distance $d$ among all primitives in the scene [S1].
    *   Scale all distance measurements relative to $d$ [S1].
    *   Calculate the density $\sigma$ based on the primitive's opacity $\alpha$ and the normalized distances $d_x, d_y, d_z$ (derived from the intersection path) [S1]:
        $$
        \sigma(\alpha) = -\frac{\log(1 - 0.99 \cdot \alpha)}{2 \cdot \min(d_x, d_y, d_z)}
        $$
    *   Note: The sources describe optimizing for opacity $\alpha$ rather than unnormalized density directly, as this improves interpretability without performance loss [S1].

5.  **Compositing:**
    *   Aggregate color contributions of all visible primitives in front-to-back order using alpha blending [S1].
    *   Stop blending for a pixel once the cumulative opacity reaches a threshold of 0.999 [S1].

### Pseudocode

```python
def linprim_render(primitives, camera, scene_min_dist):
    """
    Renders the scene using LinPrim primitives.
    
    Args:
        primitives: List of primitive objects.
        camera: Camera object with view_matrix, width, height.
        scene_min_dist: The smallest distance d of primitives in the scene (precomputed).
        
    Returns:
        Image tensor of shape (H, W, 3).
    """
    H, W = camera.height, camera.width
    tiles = get_tiles(H, W, tile_size=16)
    tile_prims = {t: [] for t in tiles}
    
    # 1. Preprocessing
    for p in primitives:
        # Transform to camera space
        p_cam = transform_to_camera(p, camera.view_matrix)
        
        # Calculate view-dependent color
        color = evaluate_sh_color(p.sh_coeffs, p_cam.view_direction)
        
        # Project to 3D affine ray space and compute bounding box
        # Note: LinPrim stores L1-slab parameters for the projected octahedron [S2, unofficial]
        # For implementation, we approximate the bounding box of the transformed octahedron
        bbox = compute_octahedron_bbox(p_cam)
        
        # Assign to tiles
        for t in tiles:
            if intersects_bbox(bbox, t):
                tile_prims[t].append({
                    'data': p_cam,
                    'color': color,
                    'opacity': p.opacity,
                    'bbox': bbox
                })
    
    # 2. Sort and Rasterize
    image = zeros((H, W, 3))
    
    for t in tiles:
        prims = tile_prims[t]
        # Sort by depth (approximate front-to-back)
        prims.sort(key=lambda x: x['data'].z)
        
        for y in range(t.y, min(t.y + 16, H)):
            for x in range(t.x, min(t.x + 16, W)):
                acc_color = zeros(3)
                T = 1.0
                
                # Reconstruct pixel ray
                ray = reconstruct_pixel_ray(x, y, camera)
                
                for prim in prims:
                    # Ray-Triangle Intersection (Möller-Trumbore)
                    # The primitive is an octahedron, composed of triangles
                    intersections = []
                    for triangle in prim['data'].triangles:
                        hit, t_val = moller_trumbore(ray, triangle)
                        if hit:
                            intersections.append(t_val)
                    
                    # Convex primitive: 0 or 2 intersections
                    if len(intersections) == 2:
                        t1, t2 = sorted(intersections)
                        path_length = t2 - t1
                        
                        # Normalize distance
                        # Scale by scene_min_dist to handle scale ambiguity [S1]
                        normalized_dist = path_length / scene_min_dist
                        
                        # Calculate opacity contribution
                        # Using the density formula derived from alpha [S1]
                        # alpha is the target opacity of the primitive
                        # We compute the transmittance based on path length and density
                        
                        # Inverse of the density formula to get effective alpha for this path segment
                        # sigma = -log(1 - 0.99 * alpha) / (2 * min_dist_norm)
                        # Transmittance T_seg = exp(-sigma * path_length)
                        # However, the source defines sigma(alpha) directly. 
                        # We interpret this as: the primitive has a base opacity alpha.
                        # The contribution is modulated by the path length through the volume.
                        
                        # Let's use the Beer-Lambert law with the calculated density
                        alpha_val = prim['opacity']
                        sigma = -log(1 - 0.99 * alpha_val) / (2 * normalized_dist)
                        
                        # Opacity of this specific ray segment
                        seg_alpha = 1.0 - exp(-sigma * path_length)
                        
                        weight = seg_alpha * T
                        acc_color += prim['color'] * weight
                        T *= (1.0 - seg_alpha)
                        
                        if T < 1e-4:
                            break
                
                image[y, x] = acc_color
                
    return image

def transform_to_camera(p, view_matrix):
    # Transform position
    pos_world = p.position
    pos_cam = view_matrix[:3, :3] @ pos_world + view_matrix[:3, 3]
    
    # Transform orientation (rotation matrix)
    rot_cam = view_matrix[:3, :3] @ p.rotation
    
    # Construct octahedron vertices from center, rotation, and distances
    # Symmetry: opposite vertices share distance [S1]
    vertices = build_octahedron(pos_cam, rot_cam, p.distances)
    
    return {
        'pos': pos_cam,
        'view_direction': -pos_cam, # Simplified
        'z': pos_cam[2],
        'triangles': get_triangles(vertices),
        'rotation': rot_cam
    }

def moller_trumbore(ray_origin, ray_dir, triangle):
    # Standard MTIA implementation [S1]
    v0, v1, v2 = triangle
    e1 = v1 - v0
    e2 = v2 - v0
    h = cross(ray_dir, e2)
    a = dot(e1, h)
    if abs(a) < 1e-8:
        return False, 0.0
    f = 1.0 / a
    s = ray_origin - v0
    u = f * dot(s, h)
    if u < 0.0 or u > 1.0:
        return False, 0.0
    q = cross(s, e1)
    v = f * dot(ray_dir, q)
    if v < 0.0 or u + v > 1.0:
        return False, 0.0
    t = f * dot(e2, q)
    if t > 1e-8:
        return True, t
    return False, 0.0

def evaluate_sh_color(sh_coeffs, view_dir):
```

### Edge Cases and Pitfalls
*   **Scale Ambiguity:** Without normalizing intersection distances relative to the smallest primitive distance $d$, the appearance of primitives varies across different scene sizes [S1].
*   **Approximation Error:** The 3D affine ray space approximation error grows with distance from the center points, but remains negligible for the small primitives used in high-fidelity reconstructions [S1].
*   **Convexity:** The method relies on primitives being convex, ensuring exactly two intersections or none [S1].

## Operating characteristics
*   **Time Complexity:** Real-time performance is achieved due to the two-stage parallelization and early termination in compositing (threshold 0.999) [S1]. Sorting is required per tile [S1].
*   **Memory Complexity:** High memory usage per primitive due to 48 SH coefficients (floats) [S1]. Reducing SH degree or primitive count is necessary for memory-constrained scenes [S1].
*   **Strengths:** Explicit geometric representation, fully differentiable via MTIA, real-time speeds, high-fidelity reconstruction [S1].
*   **Limitations:** Scale ambiguity requires global normalization; approximation error in ray space for large primitives [S1].

## Background
LinPrim was introduced in the paper "LinPrim: Linear Primitives for Differentiable Volumetric Rendering" [S1]. It builds upon the 3D Gaussian Splatting pipeline [S1] but replaces Gaussian kernels with transparent octahedron and tetrahedron primitives [S1]. The method was developed to provide an intuitive, modifiable scene representation with bounded, triangular geometry, expanding the applicability of differentiable rendering pipelines [S1]. It is also referenced in the XPR renderer documentation as a method that replaces Gaussian primitives with octahedra [S2, unofficial].
