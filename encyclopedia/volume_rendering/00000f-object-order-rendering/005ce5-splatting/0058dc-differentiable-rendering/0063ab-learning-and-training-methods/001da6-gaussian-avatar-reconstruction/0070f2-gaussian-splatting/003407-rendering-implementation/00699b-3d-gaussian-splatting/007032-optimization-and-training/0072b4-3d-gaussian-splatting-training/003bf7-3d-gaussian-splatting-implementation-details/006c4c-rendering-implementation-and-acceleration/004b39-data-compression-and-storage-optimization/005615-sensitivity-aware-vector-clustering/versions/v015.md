# Sensitivity-Aware Vector Clustering

Also called: Niedemayr et al. compression, Niedermayr, Sensitivity-Aware Scene Compression, Sensitivity-Aware Vector Clustering for 3DGS Compression, Sensitivity-aware k-Means

## Overview
Sensitivity-Aware Vector Clustering is a compression scheme for 3D Gaussian Splatting that reduces storage requirements by grouping spherical harmonic (SH) coefficients and Gaussian shape parameters (scale and rotation) into compact codebooks using sensitivity-aware vector quantization [S1, S2]. It distinguishes itself from standard post-training quantization by deriving a sensitivity measure for each parameter to guide the clustering process, prioritizing the preservation of parameters that significantly affect image quality [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of optimized 3D Gaussians, each defined by position, opacity, scale, rotation, and SH coefficients for color. A set of training images with known camera parameters.
*   **Output:** Two codebooks (one for SH coefficients, one for shape parameters) and a list of Gaussians where each Gaussian stores two indices (pointing to the respective codebooks) instead of the raw attributes, plus compressed data using entropy encoding.

**Data Structures:**
1.  **Codebook Entry (Shape):** Stores 4 scalar values for a quaternion (rotation) and 3 scalar values for scaling [S1].
2.  **Codebook Entry (Color):** Stores the SH coefficient vector.
3.  **Gaussian Record:** Stores position, opacity, and two 32-bit unsigned integer indices pointing to the SH codebook and Shape codebook [S1].

**Parameters:**
*   $K$: Codebook size. Typical value: 4096 [S1].
*   $\lambda_d$: Decay factor for the moving average in batched clustering. Typical value: 0.8 [S1].
*   $\beta_c$: Sensitivity threshold for SH coefficients. Gaussians with sensitivity $> \beta_c$ are excluded from clustering and added directly to the codebook. Typical value: $6 \times 10^{-7}$ [S1].
*   $\beta_g$: Sensitivity threshold for Gaussian shape parameters. Typical value: $3 \times 10^{-6}$ [S1].
*   Batch size for color features: $2^{18}$ [S1].
*   Batch size for Gaussian parameters: $2^{20}$ [S1].
*   Optimization steps for quantization-aware fine-tuning: 5000 [S1].

**Sensitivity Calculation:**
The sensitivity $S(p)$ of a parameter $p$ is calculated to measure its contribution to the training images [S1, S2].
$$ S(p) = \frac{\sum_{i=1}^{N} \frac{\partial E_i}{\partial p_i}}{\sum_{i=1}^{N} P_i} $$
Where:
*   $N$ is the number of training images.
*   $E_i$ is the total image energy (sum of RGB components) for image $i$.
*   $P_i$ is the number of pixels in image $i$.
*   The gradient $\frac{\partial E_i}{\partial p_i}$ is computed via a single backward pass over each training image [S1].

For a vector $x$ (representing a set of parameters like SH coefficients or shape features), the sensitivity is defined as the maximum sensitivity over its components $d$:
$$ S(x) = \max_d S(x_d) $$
where $S(x_d)$ is the sensitivity of component $d$ [S1].

**Clustering Algorithm (Sensitivity-Aware k-Means):**
The method uses k-Means clustering with a weighted distance metric.

1.  **Initialization:** Initialize codebook centroids randomly with a uniform distribution within the minimum and maximum values of each parameter [S1].
2.  **Pre-filtering:** Identify vectors (SH coefficients or shape parameters) with sensitivity higher than the threshold ($\beta_c$ for SH, $\beta_g$ for shape). These high-sensitivity vectors are not clustered but are added directly to the codebook [S1].
3.  **Assignment:** For each remaining vector $x$, calculate the weighted distance to all centroids $c_k$:
    $$ D(x, c_k) = S(x) \|x - c_k\|_2^2 $$
    Assign $x$ to the centroid $c_k$ with the minimum distance [S1]. Let $A(k)$ be the set of vectors assigned to centroid $c_k$.
4.  **Update:** Update the centroid $c_k$ using the weighted average:
    $$ c_k = \frac{1}{\sum_{x_i \in A(k)} S(x_i)} \sum_{x_i \in A(k)} S(x_i) x_i $$
5.  **Batched Strategy:** To improve performance, a random subset of vectors is picked in each update step. Centroids are updated using a moving average with decay factor $\lambda_d$ [S1].
6.  **Normalization Guard:** Due to floating-point errors, clustering normalized covariance matrices can lead to non-unit scaling vectors. After each update step, re-normalize each codebook vector by dividing it through the trace of the covariance metric [S1].
7.  **Decomposition:** After clustering, decompose each codebook entry (covariance matrix) into rotation (quaternion) and scale parameters using eigenvalue decomposition. This is required for quantization-aware training [S1].

**Quantization-Aware Fine-Tuning:**
To recover information lost during clustering, parameters are fine-tuned on the training set using quantization-aware training with Min-Max Quantization [S2].
*   **Forward Pass:** Simulate quantization considering a certain number of bits and the moving average of each parameter's min/max values [S2].
*   **Backward Pass:** Ignore the simulated quantization and calculate the gradient for the parameter without quantization [S2].

**Entropy Encoding:**
The set of Gaussians and codebooks are compressed using DEFLATE (LZ77 + Huffman coding) [S1, S2]. Gaussians are ordered by their positions along a Z-order curve (Morton order) to exploit spatial coherence and improve run-length encoding efficiency [S1, S2].

def calculate_sensitivity(gradient_sum, pixel_counts):
    """
    Calculate sensitivity S(p) for a parameter p.
    gradient_sum: Sum of gradients dE/dp over all training images.
    pixel_counts: Sum of pixels P_i over all training images.
    """
    return gradient_sum / pixel_counts

    Perform sensitivity-aware k-Means clustering.
    vectors: Array of shape (N, D) containing the parameters to cluster.

## Operating characteristics
*   **Compression Ratio:** Achieves up to 31× compression on real-world scenes with minimal visual degradation [S1].
*   **Rendering Performance:** Enables real-time rendering on lightweight GPUs, up to 4× higher framerates than optimized GPU compute pipelines [S1].
*   **Memory:** Significantly reduces memory consumption, suitable for network streaming and low-power devices [S1].
*   **Strengths:** Preserves visual quality by prioritizing sensitive parameters; efficient rendering via hardware rasterization [S1].
*   **Limitations:** Requires a sensitivity calculation phase (backward pass over training images); clustering is iterative and may require fine-tuning [S1].
*   **When to use:** When storage/bandwidth is constrained and real-time rendering on limited hardware is required [S1].
*   **When not to use:** When maximum possible visual fidelity is required without any compression artifacts, or when training data is not available for sensitivity calculation.

## Background
*   **Origin:** Proposed by Niedemayr et al. in "Compressed 3D Gaussian Splatting for Accelerated Novel View Synthesis" (CVPR 2024) [S1].
*   **History:** Builds on previous work on volumetric radiance field compression and deep network weight quantization [S1]. It addresses the high storage requirements of 3D Gaussian Splatting, particularly for SH coefficients and Gaussian shape parameters [S1].
*   **Usage:** Used for compressed 3D Gaussian splat representations to enable novel view synthesis on low-end devices and web browsers via WebGPU [S1].
