# 3D Gaussian Splatting Self-Shadowing (T_light)

Also called: 光源视角自阴影 (T_light)

## Overview
Calculates the self-shadowing transmittance $T_{light}$ for each Gaussian primitive along a directional sun direction, representing the 'front occlusion transmittance' to model self-shadowing effects in volume rendering [S1, unofficial]. It differs from standard splatting by performing a separate rasterization pass from a virtual sun camera to accumulate occlusion, rather than relying on depth sorting from the main camera view [S1, unofficial]. It sets itself apart from sibling methods like [Light Space Rasterization for T_light](4489-light-space-rasterization-for-t-light.md) by using a specific energy-weighted mean accumulation strategy and strict gradient handling during the light pass [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** 3D Gaussian primitives (mean $\boldsymbol{\mu}$, covariance $\boldsymbol{\Sigma}$, opacity $o$, color $\mathbf{c}$), sun direction vector, sun camera parameters (position, orientation, FOV).
*   **Outputs:** Per-Gaussian self-shadowing transmittance $T_{light}$ (stored in `record_front_tau` channel).

**Data Structures:**
*   **Gaussian Buffer:** Standard 3D Gaussian attributes.
*   **Light Pass Buffer:** Contains the `record_front_tau` channel for each Gaussian, storing the accumulated front transmittance weighted by energy.

**Steps:**
1.  **Sun Camera Setup:** Construct a distant narrow FOV perspective camera to simulate a directional sun light source. The distance and FOV are chosen to ensure parallax error is less than 2% and to avoid modifying the EWA Jacobian [S1, unofficial].
2.  **Rasterization Pass:** Perform a CUDA rasterization pass from the sun camera's perspective.
    *   Traverse Gaussians in depth order relative to the sun camera.
    *   For each Gaussian, compute its contribution to the accumulated front transmittance.
    *   Record the accumulated front transmittance $\tau$ weighted by $\tau \times \text{weight}$ (energy-weighted mean over the entire sun-facing footprint, not just a center point sample) into the `record_front_tau` channel [S1, unofficial].
3.  **Gradient Handling:** Enable full continuous gradients by default. This includes gradients for $\tau$, weights, normalization, weak density backup transmittance, and projection position/scale/rotation. However, treat sun camera framing, sorting, coverage, and threshold branches as constants (no gradients) to prevent incorrect gradient propagation [S1, unofficial].
4.  **Covariance Handling:** Do not expand the projection covariance by $0.3I$ during this light pass, and do not apply amplitude compensation. Keep the sampling expansion from the main camera pass as is [S1, unofficial].
5.  **Deeply Buried Gaussians:** Handle deeply buried Gaussians (where early termination causes $wsum=0$) by explicitly mapping them to full shadow to prevent inversion artifacts [S1, unofficial].

**Parameters:**
*   **Fallback Mode:** Use the old $128^3$ voxel cache path if the `--tlight_voxel` flag is passed. This is compatible with models trained before rasterization. The viewer's `--tlight auto` reads `cfg_args` to automatically match the mode [S1, unofficial].

        near_plane=sun_camera.near_plane,
        far_plane=sun_camera.far_plane

    # 2. Project Gaussians to Sun Camera Space
    projected_gaussians = []
    for g in gaussians:

        # Note: Do NOT expand covariance by 0.3I or apply amplitude compensation
        proj_mean = project_point(g.mean, sun_cam)
        proj_cov = project_covariance(g.covariance, sun_cam)
        
        # Check if Gaussian is visible in sun camera view

                'opacity': g.opacity,

            })
    
    # 3. Sort Gaussians by depth (front-to-back) relative to sun camera
    projected_gaussians.sort(key=lambda x: x['proj_mean'].z)
    
    # 4. Rasterization Pass
    # Initialize transmittance buffer
    t_light_buffer = {g['id']: 1.0 for g in gaussians} # Initial transmittance = 1.0 (fully lit)
    
    for pg in projected_gaussians:
        # Compute 2D ellipse coverage in screen space
        coverage = compute_ellipse_coverage(pg['proj_mean'], pg['proj_cov'])
        
        if coverage == 0:
            continue

        # Update transmittance: T_new = T_old * (1 - alpha)

        new_t = current_t * (1 - alpha)

        t_light_buffer[pg['id']] = new_t * pg['weight'] # Note: This might be an intermediate value
        
        # Actually, the final T_light should be the accumulated transmittance
        # Let's refine: T_light is the transmittance *through* the scene from the sun's perspective
        # So for each Gaussian, we accumulate occlusion.
        # The final T_light for a Gaussian is the product of (1-alpha) for all Gaussians in front of it.
        
    # Re-evaluating based on "record its accumulated front transmittance tau weighted by tau * weight"
    # This suggests the buffer stores the accumulated tau, and we multiply by weight for some reason?
    # Or perhaps the 'weight' is used to scale the contribution to the final T_light?

    # Reset buffer
    t_light_buffer = {g['id']: 1.0 for g in gaussians}
    
    for pg in projected_gaussians:
        alpha = compute_gaussian_alpha(pg['proj_mean'], pg['proj_cov'], pg['opacity'])
        current_t = t_light_buffer[pg['id']]
        
        # Update transmittance

**Edge Cases and Pitfalls:**
*   **Deeply Buried Gaussians:** If early termination causes $wsum=0$, explicitly map to full shadow to prevent inversion artifacts [S1, unofficial].
*   **Gradient Propagation:** Sun camera framing, sorting, coverage, and threshold branches must be treated as constants to prevent incorrect gradient propagation [S1, unofficial].
*   **Covariance Expansion:** Do not expand the projection covariance by $0.3I$ during the light pass [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ for $N$ Gaussians, plus sorting overhead $O(N \log N)$ per light pass.
*   **Memory Complexity:** $O(N)$ for storing $T_{light}$ per Gaussian.
*   **Performance:** Depends on the number of Gaussians and the resolution of the sun camera's rasterization pass.
*   **Strengths:** Accurately models self-shadowing in volume rendering.
*   **Limitations:** Requires an additional rasterization pass. Parallax error must be managed by camera setup.

## Background
Originated in the context of 4D Gaussian Splatting for volume clouds, specifically for rendering realistic lighting and shadowing effects [S1, unofficial]. The method was developed to address the lack of self-shadowing in standard 3D Gaussian Splatting rendering pipelines.
