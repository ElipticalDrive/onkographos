# 3D Gaussian Splatting Training Loop

Also called: 3DGS Optimization, Render-Compare-Correct Loop

## Overview
The 3D Gaussian Splatting (3DGS) training loop is an iterative optimization process that minimizes the difference between rendered images and ground-truth photographs by adjusting the parameters of a set of 3D Gaussians [S2, unofficial]. It distinguishes itself from random search or Monte Carlo methods by using gradient descent to compute the exact downhill direction for the error surface, allowing millions of parameters to be corrected simultaneously and purposefully [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of training images with known camera poses (typically recovered via Structure-from-Motion), and an initial set of 3D Gaussians (often initialized from a sparse point cloud or model vertices) [S1][S2, unofficial].
*   **Outputs:** Optimized Gaussian parameters (position, covariance, opacity, spherical harmonics coefficients) and potentially a densified/pruned set of Gaussians [S1][S2, unofficial].

**Data Structures:**
The core data structure is a list of $N$ Gaussians. Each Gaussian $i$ is defined by:
*   Mean position $\mu_i \in \mathbb{R}^3$
*   Covariance matrix $\Sigma_i \in \mathbb{R}^{3 \times 3}$ (often parameterized by a rotation matrix $R_i$ and a scaling vector $s_i$ such that $\Sigma_i = R_i S_i S_i^T R_i^T$)
*   Opacity $\alpha_i \in [0, 1]$
*   Spherical Harmonics (SH) coefficients $c_{i, l, m}$ for color representation, where $l$ is the degree and $m$ is the order [S1][S2, unofficial].

**Numbered Steps:**
1.  **Initialization:** Initialize the Gaussian centers at vertex positions of a template model (e.g., SMPL) and import skinning weights if applicable [S1]. Alternatively, initialize from a sparse SfM point cloud [S2, unofficial].
2.  **Sampling:** Randomly select one training image (and its corresponding camera pose) from the dataset [S1][S2, unofficial].
3.  **Transformation:** Transform the canonical Gaussians to the observation space using the camera pose and, if applicable, body pose transformations [S1].
4.  **Rendering:** Render the image by projecting the 3D Gaussians to 2D and alpha-blending them using the differentiable Gaussian rasterizer [S1][S2, unofficial].
5.  **Loss Computation:** Compute the per-image error by comparing the rendered image to the ground-truth photo pixel-by-pixel [S2, unofficial]. The total loss $\mathcal{L}$ is defined as:
    $$ \mathcal{L} = (1 - \lambda) \mathcal{L}_{L1} + \lambda \mathcal{L}_{D-SSIM} $$
    where $\mathcal{L}_{L1}$ is the L1 loss (average absolute difference between corresponding pixel colors) and $\mathcal{L}_{D-SSIM}$ is the differentiable Structural Similarity index loss [S1][S2, unofficial]. The weight $\lambda$ is typically around 0.2 [S1][S2, unofficial].
6.  **Backpropagation:** Compute gradients $\nabla \mathcal{L}$ with respect to all Gaussian parameters (position, covariance, opacity, SH coefficients) using the differentiable renderer [S1][S2, unofficial].
7.  **Update:** Adjust the parameters using the Adam optimizer [S1].
8.  **Densification/Pruning:** Periodically (e.g., every $k$ iterations), incrementally densify and prune the set of Gaussians following 3D-GS heuristics based on gradient magnitudes and opacity thresholds [S1].
9.  **Repeat:** Repeat steps 2-8 for a fixed number of iterations [S2, unofficial].

**Pseudocode:**
```python
def train_3dgs(gaussians, training_images, camera_poses, num_iterations=30000):
    """
    Optimizes 3D Gaussian parameters to match training images.
    
    Args:
        gaussians: List of Gaussian objects with attributes:
            - position: (N, 3) tensor
            - rotation: (N, 4) quaternion tensor
            - scale: (N, 3) tensor
            - opacity: (N, 1) tensor
            - sh_coeffs: (N, num_sh_bases, 3) tensor
        training_images: List of ground-truth images (H, W, 3)
        camera_poses: List of camera pose matrices (4, 4)
        num_iterations: Total training steps
        
    Returns:
        Optimized gaussians
    """
    optimizer = Adam(gaussians.parameters(), lr=1e-4, betas=(0.9, 0.99))
    
    for iteration in range(num_iterations):
        # 1. Sampling
        idx = random.randint(0, len(training_images) - 1)
        gt_image = training_images[idx]
        camera_pose = camera_poses[idx]
        
        # 2. Transformation (if applicable, e.g., for avatars)
        # transformed_gaussians = transform_to_observation_space(gaussians, camera_pose)
        transformed_gaussians = gaussians # Simplified for static scenes
        
        # 3. Rendering
        rendered_image = render_gaussians(transformed_gaussians, camera_pose)
        
        # 4. Loss Computation
        l1_loss = l1_loss_function(rendered_image, gt_image)
        ssim_loss = d_ssim_loss_function(rendered_image, gt_image)
        lambda_val = 0.2
        loss = (1 - lambda_val) * l1_loss + lambda_val * ssim_loss
        
        # 5. Backpropagation
        optimizer.zero_grad()
        loss.backward()
        
        # 6. Update
        optimizer.step()
        
        # 7. Densification/Pruning (every k iterations)
        if iteration % 1000 == 0: # Example interval
            gaussians = densify_and_prune(gaussians, threshold=0.01)
            
    return gaussians
```

**Parameters:**
*   **Optimizer:** Adam with $\beta_1 = 0.9$ and $\beta_2 = 0.99$ [S1].
*   **Iteration Budget:** Typically 30,000 iterations [S2, unofficial].
*   **Loss Weight ($\lambda$):** Approximately 0.2 [S1][S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Overfitting:** Training on all views simultaneously can lead to overfitting; random sampling per iteration mitigates this [S2, unofficial].
*   **Stopping Criterion:** There is rarely a clean loss threshold for "done"; training stops after a fixed iteration budget due to diminishing returns [S2, unofficial].
*   **Generalization:** For animatable avatars, regularization losses (e.g., perceptual loss) are important to guide the model to generalize to novel poses [S1].

## Operating characteristics
*   **Time Complexity:** Each iteration involves rendering $N$ Gaussians, which is $O(N)$ for rasterization, and backpropagation, which is also $O(N)$ in terms of gradient computation per Gaussian. The total time is proportional to the number of iterations (typically 30,000) and the number of Gaussians [S2, unofficial].
*   **Memory Complexity:** Memory usage is dominated by storing the Gaussian parameters ($O(N)$) and intermediate rendering buffers. The number of Gaussians can grow significantly during densification [S1].
*   **Strengths:** Efficient gradient-based optimization allows for high-quality reconstruction from sparse inputs. The differentiable rasterizer enables end-to-end training [S2, unofficial].
*   **Limitations:** The fixed iteration budget may lead to under-training or over-training depending on scene complexity. Densification heuristics can introduce artifacts if not tuned correctly [S1].
*   **When to Use:** Suitable for reconstructing static scenes or animatable avatars from multi-view images where high-fidelity rendering is required [S1][S2, unofficial].

## Background
The 3D Gaussian Splatting training loop was introduced in the context of 3D Gaussian Splatting for novel view synthesis [S2, unofficial]. The method builds on the differentiable rendering pipeline of 3D-GS [S1]. Variations, such as Human Gaussian Splatting, adapt the loop for animatable avatars by incorporating SMPL model initialization and body pose transformations [S1].
