# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, GSGEN Implementation Details, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific hyperparameters, data structures, and optimization strategies required to implement the 3D Gaussian Splatting (3DGS) training pipeline, focusing on the densification, pruning, and gradient computation mechanics. It addresses the problem of balancing reconstruction fidelity with computational efficiency by defining the exact thresholds for adaptive density control and the numerical stability measures for half-precision training. It sets itself apart from general overviews by providing the concrete implementation values (e.g., learning rates, opacity thresholds, iteration intervals) and low-level kernel behaviors (e.g., half-precision fetches, gradient flags) necessary for a functional codebase.

## How it works

### Inputs and Outputs
*   **Inputs**: A set of $N$ training images with known camera poses (intrinsics $K$, extrinsics $R, t$), an initial point cloud (typically from Structure-from-Motion, SfM), and hyperparameters for optimization.
*   **Outputs**: A set of optimized 3D Gaussian primitives $\mathcal{G} = \{\mu_i, \Sigma_i, \alpha_i, c_i\}$, where $\mu_i$ is position, $\Sigma_i$ is covariance, $\alpha_i$ is opacity, and $c_i$ are spherical harmonic (SH) coefficients.

### Data Structures
Each Gaussian primitive $i$ stores the following attributes in memory:
1.  **Position** $\mu_i \in \mathbb{R}^3$: 32-bit float (FP32) or 16-bit float (FP16) depending on precision settings.
2.  **Rotation** $q_i \in \mathbb{R}^4$: Unit quaternion, normalized after updates.
3.  **Scale** $s_i \in \mathbb{R}^3$: Log-space scaling factors to ensure positivity.
4.  **Opacity** $\alpha_i \in \mathbb{R}$: Sigmoid-activated value in $[0, 1]$.
5.  **Color** $c_i \in \mathbb{R}^{3 \times (k+1)^2}$: SH coefficients for view-dependent color, where $k$ is the SH degree.
6.  **Gradient Flags** (Optional): A vector $\nabla \in \mathbb{R}^{11+k_c}$ storing historical gradient trends for robustness against pseudo-view noise [S14].

### Numbered Steps

1.  **Initialization**:
    *   Initialize Gaussians from the SfM point cloud.
    *   Set initial opacity $\alpha$ to a low value (e.g., 0.1) to allow gradual growth [S14].
    *   Compute scene extent $e_{\text{scene}}$. The default is $1.1 \cdot \max_i \|\bar{C} - C_i\|_2$, but a corrected extent using SfM points is recommended to avoid bias from clustered cameras: $e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2$ [S4].

2.  **Rasterization (Forward Pass)**:
    *   Project 3D Gaussians to 2D screen space using the camera projection matrix.
    *   Sort Gaussians by depth for each tile.
    *   Perform alpha blending to compute pixel color $\mathbf{c}(\mathbf{x})$ and depth [6233-optimization-and-parallelization].
    *   *Implementation Note*: Use half-precision (FP16) memory fetches for feature vectors during rasterization to reduce register pressure [S2].

3.  **Loss Computation**:
    *   Compute the loss $\mathcal{L}$ between the rendered image $\hat{I}$ and the ground-truth image $I$.
    *   Standard loss: $\mathcal{L} = \lambda \cdot \text{MSE}(I, \hat{I}) + (1 - \lambda) \cdot \text{SSIM}(I, \hat{I})$ [S13, unofficial].
    *   Apply an automatic scaling factor to loss values to improve half-precision training stability [S2].

4.  **Backpropagation**:
    *   Compute gradients $\frac{\partial \mathcal{L}}{\partial \theta}$ for all Gaussian parameters.
    *   *Gradient Flag Optimization*: If using S2Gaussian, compute cosine similarity between current gradient $g_{ic}$ and stored flag gradient $\nabla(g_i)$. If similarity $\le 0$, scale gradient by $\epsilon = 0.1$ and update flag: $g_{ic}^{new} = \epsilon g_{ic}$, $\nabla(g_i) = (1-\epsilon)\nabla(g_i) + \epsilon g_{ic}$ [S14].

5.  **Optimizer Update**:
    *   Update parameters using Adam optimizer with learning rate $1 \times 10^{-3}$ [S3].
    *   Accumulate gradients over steps if using distributed training [6233-optimization-and-parallelization].

6.  **Adaptive Density Control (Densification)**:
    *   Every 100 iterations, reset accumulated gradients.
    *   Every 1000 iterations, perform densification:
        *   **Split**: For Gaussians with position gradient magnitude $> T_{pos} = 0.02$ (view-space), split into two. One copy retains original position/scale; the other is perturbed [S1].
        *   **Clone**: For Gaussians with high opacity but low gradient magnitude, clone without perturbation to increase density in flat regions [S1].
    *   *Multi-Scale Constraint*: For large scenes, apply position-aware control. If $\max(s) < g \cdot \gamma(\mu)$, clone; if $\max(s) \ge g \cdot \gamma(\mu)$, split; if $\max(s) > b \cdot \gamma(\mu)$, eliminate. Here $\gamma(\mu) = 1$ if $\|\mu - c\|^2 < 2r$, else $\|\mu - c\|^2/r - 1$ [S7].

7.  **Pruning**:
    *   Every 200 iterations, remove Gaussians with opacity $\alpha < \alpha_{min} = 0.05$ or excessively large world-space/view-space radius [S1].

### Pseudocode

```python
def train_3dgs(images, poses, initial_points, num_iterations=30000):
    # 1. Initialization
    gaussians = initialize_gaussians(initial_points)
    optimizer = Adam(gaussians.parameters(), lr=1e-3)
    
    # 2. Training Loop
    for step in range(num_iterations):
        # Randomly select a single image from a random scene as supervision
        image, pose = random_sample(images, poses)
        
        # Forward: Rasterize
        rendered_image = rasterize(gaussians, pose, half_precision=True)
        
        # Loss: MSE + SSIM
        loss = compute_loss(rendered_image, image)
        
        # Backward: Compute Gradients
        loss.backward()
        
        # Optional: Gradient Flag Optimization (S2Gaussian)
        if use_gradient_flags:
            apply_gradient_flags(gaussians, epsilon=0.1)
            
        # Optimizer Step
        optimizer.step()
        optimizer.zero_grad()
        
        # Adaptive Density Control
        if step % 100 == 0:
            reset_gradients(gaussians)
            
        if step % 1000 == 0:
            densify_gaussians(gaussians, threshold_pos=0.02)
            
        if step % 200 == 0:
            prune_gaussians(gaussians, alpha_min=0.05)
            
    return gaussians

def densify_gaussians(gaussians, threshold_pos):
    for g in gaussians:
        grad_mag = g.position_gradient.magnitude()
        if grad_mag > threshold_pos:
            split_gaussian(g)
        elif g.opacity > threshold_opacity and grad_mag < threshold_pos:
            clone_gaussian(g)
```

### Parameters and Typical Values
*   **Learning Rate**: $1 \times 10^{-3}$ [S3].
*   **SH Degree**: 1 (for color) [S3].
*   **Split Threshold ($T_{pos}$)**: 0.02 (view-space position gradient) [S1].
*   **Opacity Threshold ($\alpha_{min}$)**: 0.05 [S1].
*   **Densification Interval**: Every 1000 iterations [S1].
*   **Pruning Interval**: Every 200 iterations [S1].
*   **Stable Diffusion Guidance Scale**: 100 (if using text-to-3D priors) [S1].
*   **Checkpoint**: `runwayml/stable-diffusion-v1-5` (for text-to-3D) [S1].

### Edge Cases and Pitfalls
*   **Scene Extent Bias**: Using camera positions to define scene extent can lead to incorrect splitting/pruning if cameras are clustered (e.g., orbiting a small object). Use SfM point cloud-based extent calculation [S4].
*   **Half-Precision Stability**: FP16 training can suffer from gradient overflow/underflow. Apply automatic loss scaling [S2].
*   **Gradient Confusion**: Pseudo-views or noisy data can cause gradient perturbations. Use gradient flags to mitigate [S14].
*   **Uniform Blurring**: In selective defocus blurring, if the MLP predicts a constant offset $\delta s_j$ for all Gaussians, it degrades to a uniform blur. Ensure the MLP predicts spatially varying offsets [S5].

## Subtopics

### Corrected Scene-Extent
A method to calculate scene extent based on the SfM point cloud rather than camera positions to avoid bias from camera distribution (e.g., orbiting a small object in a large environment) [S4]. It sets itself apart from standard 3DGS by replacing the max-camera-distance formula with an average distance to SfM points, ensuring the scene volume is correctly represented for densification [S4].

### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ to selectively enlarge covariances, creating pixel-wise variable blur kernels that match spatially varying scene blurriness [S5]. It sets itself apart from naive Gaussian blur by allowing different blur shapes and magnitudes per pixel, enabling effective deblurring of defocus artifacts [S5].

### Denoise-GS
A self-supervised denoising method for sparse-view 3D Gaussian Splatting that combines unsupervised image denoising (Noise2Void) with explicitly differentiable 3DGS [S6]. It sets itself apart from supervised methods by requiring no paired clean data, making it robust to non-Gaussian and time-varying noise in sparse view scenarios [S6].

### Multi-Scale Constraint
A technique using position-aware point adaptive control to apply different scales to Gaussians based on viewer distance, improving rendering of distant objects [S7]. It sets itself apart from standard densification by dynamically adjusting cloning/splitting thresholds based on the Gaussian's distance from the camera center [S7].

### LS-Gaussian Viewpoint Transformation
An algorithm that leverages inter-frame continuity for efficient sparse rendering by transforming the viewpoint between consecutive frames, rather than rendering each frame separately [S8]. It sets itself apart from naive pixel warping by operating at the tile/Gaussian level to reduce preprocessing and sorting costs, enabling sparse rendering where only one frame in every 6 frames is fully rendered [S8].

### Camera Localisation for Convergence Basin
Localizes camera pose by minimizing only the photometric error against the ground-truth colour image of the target view, fixing the initial Gaussians during optimization [S9, unofficial]. It sets itself apart from joint optimization methods by decoupling pose estimation from geometry optimization, ensuring convergence to the correct basin [S9, unofficial].

### DiffGS Framework
Applies an optimization process during Gaussian extraction to optimize Gaussians to exact locations, using a truncation function $\lambda$ and projection function $\tau$ (e.g., $e^{-x}$) [S10]. It sets itself apart by achieving high PSNR/SSIM with fewer Gaussians (e.g., 50K-350K) compared to standard 3DGS [S10].

### Opacity Offset Table for DSA
Constructs an opacity offset table to model changes in digital subtraction angiography [S11]. It sets itself apart by explicitly handling temporal opacity changes in medical imaging contexts [S11].

### Conditional Splat Approximation
Approximates the influence range of a 3D Gaussian on a slice by using a 2D ellipse splat scaled by the marginal factor, which closely matches the true iso-probability contours [S12, unofficial]. It sets itself apart by providing an accurate and efficient approximation for slice-based rendering or tomographic reconstruction [S12, unofficial].

### PyGS Optimization
Uses a combined MSE and SSIM loss, along with density control strategies adapted from 3DGS, while preserving the multi-scale structure [S13, unofficial]. It sets itself apart by routinely reassessing and reassigning the levels of Gaussians based on their scales to preserve multi-scale characteristics [S13, unofficial].

### Gradient Flag Optimization
Augments Gaussian primitives with a flag gradient attribute to mitigate gradient confusion and perturbations caused by imperfect supervision from pseudo-views [S14]. It sets itself apart by storing historical gradient trends and scaling down updates with negative cosine similarity [S14].

### GAINS (Gaussian-based Inverse Rendering from Sparse multi-view captures)
A two-stage inverse rendering framework that leverages foundation model priors to stabilize geometry and material estimation from sparse multi-view RGB captures [S15]. It sets itself apart by using 2DGS for more accurate geometry reconstruction, which is essential for accurate material property estimation [S15].

### View-Dependent Gaussian Splatting (VDGS)
Produces more faithful view-dependent effects by modeling 3DGS to represent 3D shapes and predicting attributes like view-dependent color and opacity with a NeRF-like neural network instead of spherical harmonic coefficients [S16, unofficial]. It sets itself apart from standard 3DGS by replacing SH coefficients with a neural network for view-dependent attributes [S16, unofficial].

### SAGS (Adaptive Gaussian Splatting)
Utilizes an adaptive 2D low-pass filter at inferencing time based on rendering resolution and camera distance to handle aliasing [S16, unofficial]. It sets itself apart by dynamically adjusting the filter based on scene geometry and camera parameters [S16, unofficial].

### Frequency Gaussian Splatting
Applies frequency-domain regularization to the rendered 2D image to encourage recovery of high-frequency detail, resolving blurring issues [S16, unofficial]. It sets itself apart by operating in the frequency domain to explicitly target high-frequency loss [S16, unofficial].

### Sparse Adaptive Scalable Compact Gaussian Splatting
A compression method that utilizes vector clustering to encode color and geometric attributes [S16, unofficial]. It sets itself apart by reducing storage size through clustering-based encoding [S16, unofficial].

## Operating characteristics

*   **Time Complexity**: $O(N \cdot M)$ per iteration, where $N$ is the number of Gaussians and $M$ is the number of pixels/tiles. Densification adds $O(N)$ overhead every 1000 iterations.
*   **Memory Complexity**: $O(N \cdot C)$, where $C$ is the size of Gaussian attributes (position, rotation, scale, opacity, SH coefficients). Standard 3DGS can exceed 1GB for real-world datasets [12927-compact-3d-gaussian-representation-c3dgs.md].
*   **Measured Performance**: On a single RTX 3090 GPU, standard 3DGS training takes several hours to tens of thousands of iterations. LS-Gaussian achieves 5.41× speedup over edge GPU baselines and up to 17.3× with custom accelerators [S8].
*   **Scaling**: Scales well with GPU parallelism due to tile-based rasterization. Distributed training is possible via gradient synchronization [6233-optimization-and-parallelization].
*   **Strengths**: Real-time rendering speeds, high-quality novel view synthesis, explicit representation allows for easy editing.
*   **Limitations**: High memory usage for large scenes, sensitive to initialization, prone to artifacts in sparse-view scenarios without denoising [S6].
*   **When to Use**: When real-time rendering and high fidelity are required, and sufficient GPU memory is available.
*   **When Not to Use**: When memory is severely constrained (consider compression methods [12943-data-compression-and-storage-optimization.md]) or when sparse-view robustness is critical without additional denoising [S6].

## Background

3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1, S2]. It revolutionized neural rendering by replacing implicit neural fields with explicit 3D Gaussian primitives, enabling real-time differentiable rasterization. The method builds on the concept of splatting, where 3D primitives are projected and blended in 2D space. The training optimization and implementation details described here are based on the original paper and subsequent refinements for stability, efficiency, and robustness [S1, S2, S3, S4, S5, S6, S7, S8][S9, unofficial][S10, S11][S12, S13, unofficial][S14, S15][S16, unofficial].
