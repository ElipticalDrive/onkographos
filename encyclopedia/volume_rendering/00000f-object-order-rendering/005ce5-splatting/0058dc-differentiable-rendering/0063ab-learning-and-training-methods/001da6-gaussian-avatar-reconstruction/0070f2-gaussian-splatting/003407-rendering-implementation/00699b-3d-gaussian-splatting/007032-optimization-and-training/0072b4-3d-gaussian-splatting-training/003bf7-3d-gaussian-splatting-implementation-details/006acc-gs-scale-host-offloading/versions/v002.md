# GS-Scale Host Offloading

Also called: host offloading, hybrid training

## Overview
**GS-Scale** is a training framework for 3D Gaussian Splatting that reduces GPU memory usage by storing all Gaussian parameters and optimizer states in host (CPU) memory, transferring only a necessary subset to the GPU on demand for each forward and backward pass [S1, unofficial]. It sets itself apart from GPU-Only training by preventing Out-of-Memory (OOM) errors on large scenes, and from naive host offloading by achieving significantly faster training speeds through system-level optimizations [S1, unofficial].

## How it works
**Inputs:** 3D Gaussian parameters (position, scale, rotation, SH coefficients, opacity) and optimizer states stored in host memory; camera poses and image data [S1, unofficial][G].
**Outputs:** Rendered images and gradients for optimization [S1, unofficial][G].

**Data Structures:**
*   **Host Memory:** Stores the full set of $N$ Gaussians and their optimizer states [S1, unofficial]. Each Gaussian $i$ contains position $\mathbf{p}_i \in \mathbb{R}^3$, scale $\mathbf{s}_i \in \mathbb{R}^3$, rotation $\mathbf{q}_i \in \mathbb{R}^4$, SH coefficients $\mathbf{c}_i \in \mathbb{R}^{3 \times K}$, and opacity $\alpha_i \in \mathbb{R}$ [G]. Optimizer states (e.g., Adam momentum and variance) are stored identically to the parameters [G].
*   **Device Memory (GPU):** Contains only the subset of Gaussians currently being processed for a specific view or split [S1, unofficial].

**Algorithm Steps:**
1.  Store all Gaussian parameters and optimizer states in host memory [S1, unofficial].
2.  For each forward/backward pass, transfer only the necessary subset of Gaussians to the GPU [S1, unofficial].
3.  If split mode is enabled, check if the current image's Gaussian count exceeds `split_threshold * total_gaussians` [S1, unofficial].
4.  If the threshold is exceeded, split the image processing into smaller batches to further reduce peak GPU memory usage [S1, unofficial].

**Parameters:**
*   `split_threshold`: A float controlling the split mode threshold. Default value is 0.3. If an image consumes more Gaussians than `split_threshold * total_gaussians`, the image is split to reduce GPU memory [S1, unofficial].

**Pseudocode:**
```python
def train():
    # 1. Store all parameters and optimizer states in host memory [S1, unofficial]
    host_params = load_gaussian_parameters()  # [G] standard 3DGS initialization
    host_optimizer_states = create_optimizer_buffers(host_params)  # [G] standard optimizer setup
    total_gaussians = len(host_params)
    split_threshold = 0.3
    split_mode_enabled = True  # [G]

    for camera, image_gt in training_data:
        # 2. Identify subset of Gaussians for current view [S1, unofficial]
        relevant_indices = select_visible_gaussians(camera, host_params)  # [G] standard frustum/distance culling
        num_relevant = len(relevant_indices)

        # 3. Check split mode condition [S1, unofficial]
        if split_mode_enabled and num_relevant > split_threshold * total_gaussians:
            # 4. Split processing to reduce GPU memory [S1, unofficial]
            chunk_size = max(1, num_relevant // 2)
            indices_chunks = [relevant_indices[i:i + chunk_size] for i in range(0, num_relevant, chunk_size)]
            for chunk in indices_chunks:
                process_chunk(chunk, camera, image_gt, host_params, host_optimizer_states)
        else:
            process_chunk(relevant_indices, camera, image_gt, host_params, host_optimizer_states)

def process_chunk(indices, camera, image_gt, host_params, host_optimizer_states):
    # Transfer subset to GPU [S1, unofficial]
    device_params = host_params[indices]
    device_optimizer_states = host_optimizer_states[indices]

    # Forward pass: rasterize and render [S1, unofficial]
    rendered_image = rasterize_3d_gaussians(device_params, camera)  # [G] standard differentiable rasterizer

    # Compute loss and gradients [S1, unofficial]
    loss = compute_mse_loss(rendered_image, image_gt)  # [G] standard loss function
    gradients = compute_gradients(loss, device_params)  # [G] standard autograd/backprop

    # Transfer gradients back to host and update [S1, unofficial]
    update_optimizer_states(host_optimizer_states[indices], gradients)  # [G] standard optimizer step
    update_params(host_params[indices], gradients)  # [G] standard parameter update
```

**Edge Cases and Pitfalls:**
*   Out-of-Memory (OOM) errors can occur if GPU memory demand is too high; this is handled by the host offloading mechanism and optionally by split mode [S1, unofficial].
*   Setting `split_threshold` too low further reduces memory but may slow down training due to increased chunking overhead [S1, unofficial].

## Operating characteristics
*   **Memory Reduction:** Reduces GPU memory usage by 3.3-5.6x compared to GPU-Only systems, enabling training on consumer-grade GPUs [S1, unofficial].
*   **Performance:** Slower than GPU-Only training for small scenes due to data transfer overhead, but significantly faster than naive host offloading [S1, unofficial].
*   **Scalability:** Enables training on large-scale scenes that would otherwise cause OOM errors on standard GPUs [S1, unofficial].
*   **Split Mode:** Further reduces memory usage at the cost of potential speed reduction if `split_threshold` is set low [S1, unofficial].

## Background
GS-Scale was introduced by SNU-ARC as a solution to the memory bottlenecks in large-scale 3D Gaussian Splatting training [S1, unofficial]. It builds on the principles of host offloading but incorporates system-level optimizations to mitigate the performance penalties typically associated with CPU-GPU data transfers [S1, unofficial].
