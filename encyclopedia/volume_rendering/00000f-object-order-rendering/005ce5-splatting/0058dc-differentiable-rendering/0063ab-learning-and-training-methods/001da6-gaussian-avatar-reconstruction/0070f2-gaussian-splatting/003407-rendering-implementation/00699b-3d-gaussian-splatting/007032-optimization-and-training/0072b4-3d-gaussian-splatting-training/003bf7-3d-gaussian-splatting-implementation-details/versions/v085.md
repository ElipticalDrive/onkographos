# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, GSGEN Implementation Details, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific algorithmic steps, data structures, and hyperparameters required to implement the core 3D Gaussian Splatting (3DGS) training pipeline, including densification, pruning, and differentiable rasterization. It serves as the implementation reference for the parent method [Optimization and Parallelization](6233-optimization-and-parallelization.md), providing the concrete logic for adaptive density control and gradient accumulation that enables the method to solve the inverse problem of radiance field reconstruction from multi-view images. It sets itself apart from sibling methods by focusing on the baseline configuration and low-level kernel behaviors (e.g., half-precision fetches, specific threshold schedules) rather than high-level architectural modifications or specialized loss functions.

## How it works

### Inputs and Outputs
*   **Inputs:** A set of $N$ training images with known camera poses (extrinsics $C_i$ and intrinsics $K_i$), an initial point cloud (typically from Structure-from-Motion, SfM), and hyperparameters for optimization.
*   **Outputs:** A set of 3D Gaussian primitives $\mathcal{G} = \{\mu_j, \Sigma_j, \alpha_j, c_j\}_{j=1}^M$, where $\mu_j$ is position, $\Sigma_j$ is covariance, $\alpha_j$ is opacity, and $c_j$ are spherical harmonic (SH) coefficients for view-dependent color.

### Data Structures
The Gaussian primitives are stored in a flat array or structure-of-arrays (SoA) layout for efficient GPU access. Each Gaussian $j$ contains:
*   **Position ($\mu_j$):** 3 floats ($x, y, z$).
*   **Covariance ($\Sigma_j$):** Stored as a 6-vector quaternion ($q_x, q_y, q_z, q_w$) and 3-vector scale ($s_x, s_y, s_z$) to ensure positive-definiteness and efficient updates. The covariance matrix is reconstructed as $\Sigma = R S S^T R^T$, where $R$ is the rotation matrix derived from $q$ and $S$ is the diagonal scale matrix.
*   **Opacity ($\alpha_j$):** 1 float.
*   **Color ($c_j$):** $k_c$ SH coefficients. For SH degree 1, this is 12 floats (4 per RGB channel). For SH degree 3, this is 45 floats.
*   **Accumulated Gradients:** 3 floats for position gradient magnitude (used for densification decisions).

### Numbered Steps

1.  **Initialization:** Initialize Gaussians from the SfM point cloud. Set initial scales to a small value (e.g., $0.01$) and opacity to a low value (e.g., $0.1$). [S3]
2.  **Random View Selection:** For each training iteration, randomly select a single image from the training set to supervise the optimization. [S3]
3.  **Differentiable Rasterization:**
    *   Project 3D Gaussians to 2D screen space using the camera projection matrix.
    *   Compute the 2D covariance matrix $\Sigma_{2D}$ and screen-space bounding box.
    *   Sort Gaussians by depth within each tile.
    *   Perform alpha-blending to render the color $\hat{C}$ and opacity $\hat{\alpha}$ for each pixel.
    *   *Implementation Note:* Use half-precision (FP16) memory fetches for feature vectors during rasterization to reduce register pressure and improve throughput. [S2]
4.  **Loss Computation:** Compute the photometric loss $\mathcal{L}$ between the rendered image $\hat{C}$ and the ground-truth image $C$. The loss is typically a combination of L1 loss and Structural Similarity (SSIM):
    $$ \mathcal{L} = (1 - \lambda) \mathcal{L}_{L1} + \lambda \mathcal{L}_{SSIM} $$
    where $\lambda$ is a hyperparameter (typically $0.2$). [S13, unofficial]
    *   *Stability:* Apply an automatic scaling factor to loss values to improve half-precision training stability. [S2]
5.  **Backpropagation:** Compute gradients $\frac{\partial \mathcal{L}}{\partial \theta}$ for all Gaussian parameters $\theta$ ($\mu, q, s, \alpha, c$) using the chain rule through the differentiable rasterizer. [6233-optimization-and-parallelization]
6.  **Optimizer Update:** Update Gaussian parameters using the Adam optimizer with a learning rate of $1 \times 10^{-3}$ for positions/scales/rotations and $2.5 \times 10^{-5}$ for colors (SH coefficients). [S3]
7.  **Adaptive Density Control (Densification):**
    *   **Splitting:** Every 500 iterations, split Gaussians whose accumulated view-space position gradient exceeds a threshold $T_{pos} = 0.02$. Splitting involves creating two new Gaussians from the parent, one with half the opacity and scaled position. [S1]
    *   **Cloning:** Clone Gaussians with large gradients but small scales to increase density in under-represented areas.
    *   **Pruning:** Every 200 iterations, remove Gaussians with opacity $\alpha < \alpha_{min} = 0.05$ or those with excessively large world-space or view-space radii. [S1]
    *   **Compactness Check:** Perform compactness-based densification every 1000 iterations to ensure uniform distribution. [S1]
8.  **Scene Extent Correction (Optional but Recommended):** Calculate the scene extent $e'_{\text{scene}}$ based on the SfM point cloud rather than camera positions to avoid bias from camera distribution (e.g., orbiting a small object). [S4]
    $$ e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2 $$
    where $\bar{C}$ is the average camera position and $p_i$ are SfM points. [S4]

### Pseudocode

```python
def train_3dgs(training_images, initial_points, num_iterations):
    # Initialize Gaussians from SfM points
    gaussians = GaussianSet(initial_points)
    
    # Optimizer setup
    optimizer = Adam(gaussians.parameters(), lr=1e-3)
    
    for step in range(num_iterations):
        # 1. Random View Selection
        image_idx = random.choice(range(len(training_images)))
        gt_image, camera_pose = training_images[image_idx]
        
        # 2. Forward Pass: Rasterization
        # Use half-precision fetches for features
        rendered_image = rasterize(gaussians, camera_pose, half_precision=True)
        
        # 3. Loss Computation
        # Apply automatic scaling for FP16 stability
        loss = compute_loss(rendered_image, gt_image, scale_factor=auto_scale())
        
        # 4. Backward Pass
        loss.backward()
        
        # 5. Optimizer Step
        optimizer.step()
        optimizer.zero_grad()
        
        # 6. Adaptive Density Control
        if step % 500 == 0:
            # Split Gaussians with high position gradient
            gaussians.split(threshold=0.02)
            
        if step % 200 == 0:
            # Prune low opacity and oversized Gaussians
            gaussians.prune(alpha_min=0.05)
            
        if step % 1000 == 0:
            # Compactness-based densification
            gaussians.compact_densify()
            
    return gaussians
```

### Parameters
*   **Learning Rate:** $1 \times 10^{-3}$ for geometric parameters, $2.5 \times 10^{-5}$ for SH coefficients. [S3]
*   **Split Threshold ($T_{pos}$):** $0.02$ (view-space position gradient). [S1]
*   **Opacity Threshold ($\alpha_{min}$):** $0.05$. [S1]
*   **SH Degree:** 1 (typically used for real-time applications; degree 3 for higher quality). [S3]
*   **Loss Weight ($\lambda$):** $0.2$ (balance between L1 and SSIM). [S13, unofficial]

### Edge Cases and Pitfalls
*   **Scene Extent Bias:** Using camera positions to define scene extent can lead to incorrect splitting/pruning if cameras are clustered (e.g., orbiting a small object in a large environment). Use SfM point cloud for extent calculation. [S4]
*   **Half-Precision Instability:** Training in FP16 can lead to gradient overflow/underflow. Apply automatic loss scaling. [S2]
*   **Gradient Confusion:** In sparse-view scenarios, pseudo-views can cause gradient perturbations. Use gradient flag optimization to mitigate this. [S14]

## Subtopics

### Corrected Scene-Extent
A method to calculate scene extent based on the SfM point cloud rather than camera positions to avoid bias from camera distribution (e.g., orbiting a small object in a large environment). It solves the problem where default 3DGS scene extent ($e_{\text{scene}}$) is proportional to the distance of the furthest camera from the average camera position, causing bias if cameras are clustered. [S4]

### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ to selectively enlarge covariances, creating pixel-wise variable blur kernels that match spatially varying scene blurriness. It sets itself apart from standard Gaussian Splatting by allowing spatially varying blur shapes and magnitudes, unlike naive Gaussian blur which applies a single kernel to the whole image. [S5]

### Denoise-GS
A self-supervised denoising method for sparse-view 3D Gaussian Splatting that combines unsupervised image denoising (Noise2Void) with explicitly differentiable 3DGS. It solves the problem of suboptimal reconstruction in sparse view and noisy scenes by using unsupervised N2V, which requires no paired clean data and is robust to uncertain noise patterns. [S6]

### Multi-Scale Constraint
A technique using position-aware point adaptive control to apply different scales to Gaussians based on viewer distance, improving rendering of distant objects. It sets itself apart by dynamically adjusting cloning and splitting thresholds based on the distance of the Gaussian from the camera center. [S7]

### LS-Gaussian Viewpoint Transformation
An algorithm that leverages inter-frame continuity for efficient sparse rendering by transforming the viewpoint between consecutive frames, rather than rendering each frame separately. It sets itself apart from naive pixel warping by operating at the tile/Gaussian level to enable sparse rendering, reducing preprocessing and sorting costs. [S8]

### Camera Localisation for Convergence Basin
Localizes camera pose by minimizing only the photometric error against the ground-truth colour image of the target view, fixing the initial Gaussians during optimization. It solves the problem of initializing camera poses for novel view synthesis by finding the estimated pose $T_{CW}^{est}$ that minimizes the L1 norm between rendered and target images. [S9, unofficial]

### DiffGS Framework
Applies an optimization process during Gaussian extraction to optimize Gaussians to exact locations using a Gaussian Probability Function (GauPF) with a truncation function $\lambda$ and projection function $\tau$. It sets itself apart by providing a functional formulation for Gaussian splatting that improves rendering quality with fewer Gaussians. [S10]

### Opacity Offset Table for DSA
Constructs an opacity offset table to model changes in digital subtraction angiography. It sets itself apart by explicitly modeling temporal changes in opacity for medical imaging applications. [S11]

### Conditional Splat Approximation
Approximates the influence range of a 3D Gaussian on a slice by using a 2D ellipse splat scaled by the marginal factor, which closely matches the true iso-probability contours. It sets itself apart by providing an accurate and efficient approximation for slice-based rendering or tomographic reconstruction. [S12, unofficial]

### PyGS Optimization
The optimization process using a combined MSE and SSIM loss, along with density control strategies adapted from 3DGS, while preserving the multi-scale structure. It sets itself apart by routinely reassessing and reassigning the levels of Gaussians based on their scales to preserve multi-scale characteristics. [S13, unofficial]

### Gradient Flag Optimization
Augments Gaussian primitives with a flag gradient attribute to mitigate gradient confusion and perturbations caused by imperfect supervision from pseudo-views. It sets itself apart by scaling down gradients with negative cosine similarity to the stored flag gradient, preserving update trends. [S14]

### GAINS (Gaussian-based Inverse Rendering from Sparse multi-view captures)
A two-stage inverse rendering framework that leverages foundation model priors to stabilize geometry and material estimation from sparse multi-view RGB captures. It sets itself apart by using 2DGS for more accurate geometry reconstruction, which is essential for accurate material property estimation. [S15]

### View-Dependent Gaussian Splatting (VDGS)
Produces more faithful view-dependent effects by modeling 3DGS to represent 3D shapes and predicting attributes like view-dependent color and opacity with a NeRF-like neural network instead of spherical harmonic coefficients. It sets itself apart by replacing SH coefficients with a neural network for view-dependent attributes. [S16, unofficial]

### SAGS (Adaptive Gaussian Splatting)
Utilizes an adaptive 2D low-pass filter at inferencing time based on rendering resolution and camera distance to handle aliasing. It sets itself apart by dynamically adjusting the filter based on rendering conditions. [S16, unofficial]

### Frequency Gaussian Splatting
Applies frequency-domain regularization to the rendered 2D image to encourage recovery of high-frequency detail, resolving blurring issues. It sets itself apart by operating in the frequency domain to enhance high-frequency details. [S16, unofficial]

### Sparse Adaptive Scalable Compact Gaussian Splatting
A compression method that utilizes vector clustering to encode color and geometric attributes. It sets itself apart by focusing on compression through vector clustering. [S16, unofficial]

## Operating characteristics

*   **Time Complexity:** The rasterization step is $O(N \cdot M)$ where $N$ is the number of pixels and $M$ is the number of Gaussians, but optimized to $O(N \cdot K)$ where $K$ is the average number of Gaussians per pixel (typically small). Densification adds $O(M)$ overhead every few hundred iterations.
*   **Memory Complexity:** $O(M \cdot D)$ where $D$ is the dimensionality of Gaussian attributes (position, scale, rotation, opacity, SH coefficients). For SH degree 1, $D \approx 20$. Memory usage scales linearly with the number of Gaussians.
*   **Measured Performance:** On standard datasets (e.g., Mip-NeRF 360), 3DGS achieves real-time rendering speeds (60+ FPS) on modern GPUs (e.g., RTX 3090) for scenes with millions of Gaussians. [S8]
*   **Scaling:** Scales well with GPU parallelism due to the tile-based rasterization approach. Distributed training is possible but requires careful synchronization of gradients and Gaussian states. [6233-optimization-and-parallelization]
*   **Strengths:** Real-time rendering, high visual quality, explicit representation allows for easy editing and compression.
*   **Limitations:** High memory usage for large scenes, sensitive to initialization, can produce "floaters" in unobserved regions.
*   **When to Use:** Real-time novel view synthesis, interactive applications, scenes with complex geometry and appearance.
*   **When Not to Use:** Scenes with extreme dynamic range or highly reflective surfaces without additional modifications (e.g., Spec-Gaussian), scenes with very sparse views without denoising or regularization.

## Background

3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1]. It builds on the idea of explicit radiance field representations, using 3D Gaussians as primitives for efficient differentiable rendering. The method was developed to address the limitations of NeRFs, which are slow to render and require iterative optimization for each new scene. 3DGS enables real-time rendering by leveraging a tile-based differentiable rasterizer and adaptive density control. It has become a standard baseline for novel view synthesis and 3D reconstruction. [S1, S2]
