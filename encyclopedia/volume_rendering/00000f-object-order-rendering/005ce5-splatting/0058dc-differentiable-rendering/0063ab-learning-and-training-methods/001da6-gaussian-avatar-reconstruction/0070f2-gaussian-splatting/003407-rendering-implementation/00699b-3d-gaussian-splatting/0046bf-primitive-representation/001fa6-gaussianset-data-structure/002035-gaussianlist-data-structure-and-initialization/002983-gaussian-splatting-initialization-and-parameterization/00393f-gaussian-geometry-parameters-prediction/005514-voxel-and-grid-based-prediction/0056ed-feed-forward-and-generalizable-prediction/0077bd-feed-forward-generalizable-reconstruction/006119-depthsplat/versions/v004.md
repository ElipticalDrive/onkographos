# DepthSplat


## Overview
DepthSplat is a feed-forward method for 3D Gaussian splatting reconstruction that connects Gaussian splatting with multi-view depth estimation by leveraging pre-trained monocular depth features to augment multi-view feature matching [S1]. It solves the problem of robust depth prediction in challenging scenarios (occlusions, low-texture areas, non-Lambertian surfaces) where standard multi-view stereo fails, and scale ambiguities where monocular estimation fails [S1]. Unlike siblings that refine coarse depth with monocular features (e.g., [TranSplat](link)) or discard explicit feature matching for data-driven priors (e.g., [GS-LRM](link)), DepthSplat combines cost volumes and monocular features early in the pipeline, enabling robust multi-view consistency and cheaper training [S1].

## How it works
**Inputs:** $N$ input images $\{I_i\}_{i=1}^N$ with corresponding projection matrices $\{P_i\}_{i=1}^N$, where $I_i \in \mathbb{R}^{H \times W \times 3}$ and $P_i \in \mathbb{R}^{3 \times 4}$ (computed from intrinsic and extrinsic matrices) [S1].

**Outputs:** A set of 3D Gaussians $\mathcal{G} = \{\mu_j, \alpha_j, \Sigma_j, c_j\}$ for each pixel $j$ in the reference views, where $\mu_j$ is the 3D position, $\alpha_j$ is opacity, $\Sigma_j$ is covariance, and $c_j$ is color [S1].

**Data Structures:**
*   **Monocular Features:** Extracted per-view using a Vision Transformer (ViT).
*   **Cost Volume:** $C_i \in \mathbb{R}^{\frac{H}{s} \times \frac{W}{s} \times D}$ for each view $i$, where $s$ is the downsampling factor and $D$ is the number of depth candidates [S1].
*   **Depth Map:** $D_i \in \mathbb{R}^{H \times W}$, dense per-pixel depth prediction [S1].

**Parameters:**
*   **Downsampling factor ($s$):** Controlled by the number of stride-2 $3 \times 3$ convolutions in feature extraction. $s=4$ if two convolutions are used; $s=8$ if three are used [S1].
*   **Depth candidates ($D$):** Uniformly sampled from near/far depth ranges [S1].
*   **Multi-View Transformer:** Contains six stacked self- and cross-attention layers [S1].
*   **Neighbor Selection:** For $N > 2$ views, the top-2 nearest neighboring views are selected based on camera distance to the reference view [S1].

**Steps:**
1.  **Monocular Feature Extraction:** For each input image $I_i$, extract per-view features $F_i$ using a pre-trained monocular depth model (ViT-based) [S1].
2.  **Depth Candidate Sampling:** For each view $i$, uniformly sample $D$ depth candidates $\{d_m\}_{m=1}^D$ from the near and far depth ranges [S1].
3.  **Feature Warping:** For each view $i$ and each neighboring view $j$, warp the features $F_j$ to view $i$ using the camera projection matrix $P_i$ and each depth candidate $d_m$. This yields warped features $\{F_{j \to i}^m\}_{m=1}^D$ corresponding to $F_i$ [S1].
4.  **Cost Volume Construction:** Measure feature correlations between $F_i$ and the warped features $\{F_{j \to i}^m\}$ using the dot-product operation. Stack these correlations to form the cost volume $C_i \in \mathbb{R}^{\frac{H}{s} \times \frac{W}{s} \times D}$ for image $i$ [S1].
    *   If $N > 2$, select the top-2 nearest neighboring views for each reference view $i$. Compute correlations only for these views. Combine the correlation values from the selected views by averaging [S1].
5.  **Feature Concatenation:** Concatenate the multi-view cost volumes $C_i$ with the extracted monocular features $F_i$ [S1].
6.  **Depth Regression:** Perform depth regression using a 2D U-Net architecture followed by a softmax layer to predict the dense per-pixel depth map $D_i$ [S1].
7.  **Gaussian Unprojection:** Unproject the predicted depth maps $D_i$ to 3D space using the camera parameters $P_i$ to obtain the Gaussian centers $\mu_j$ [S1].
8.  **Parameter Prediction:** Predict the remaining Gaussian parameters (opacity $\alpha_j$, covariance $\Sigma_j$, color $c_j$) using an additional lightweight network/head in parallel with the depth regression [S1].
9.  **Rendering:** Render novel views using the splatting operation with the predicted 3D Gaussians [S1].

**Pseudocode:**

```python
def depth_splat(input_images, projection_matrices):
    """
    input_images: List of N images, shape (H, W, 3)
    projection_matrices: List of N matrices, shape (3, 4)
    """
    N = len(input_images)
    monocular_features = []
    cost_volumes = []
    
    # Step 1: Monocular Feature Extraction
    for i in range(N):
        # Extract features using pre-trained monocular depth model (ViT)
        F_i = extract_monocular_features(input_images[i])
        monocular_features.append(F_i)
        
    # Step 2-4: Cost Volume Construction
    for i in range(N):
        # Step 2: Sample depth candidates
        depth_candidates = sample_depth_candidates(near_far_ranges)
        D = len(depth_candidates)
        
        # Determine neighbors
        if N > 2:
            # Select top-2 nearest neighboring views based on camera distance
            neighbor_indices = get_top_k_neighbors(i, projection_matrices, k=2)
        else:
            # For N=2, use the other view
            neighbor_indices = [j for j in range(N) if j != i]
            
        correlations = []
        for j in neighbor_indices:
            F_j = monocular_features[j]
            warped_features = []
            
            # Step 3: Feature Warping
            for d_m in depth_candidates:
                # Warp F_j to view i using P_i and d_m
                F_warped = warp_features(F_j, projection_matrices[i], d_m)
                warped_features.append(F_warped)
            
            # Step 4: Correlation via dot-product
            # F_i is downsampled to (H/s, W/s) for correlation
            F_i_down = downsample(F_i, s)
            corr = dot_product_correlation(F_i_down, warped_features)
            correlations.append(corr)
            
        # Combine correlations by averaging if multiple neighbors
        if len(correlations) > 1:
            C_i = average_correlations(correlations)
        else:
            C_i = correlations[0]
            
        cost_volumes.append(C_i)
        
    # Step 5-6: Depth Regression
    depth_maps = []
    for i in range(N):
        # Concatenate cost volume with monocular features
        # Note: Dimensions must be aligned (e.g., upsampling monocular features)
        combined_input = concatenate(cost_volumes[i], monocular_features[i])
        
        # 2D U-Net followed by softmax
        D_i = depth_regression_net(combined_input)
        depth_maps.append(D_i)
        
    # Step 7: Unprojection to 3D Gaussians
    gaussian_centers = []
    for i in range(N):
        # Unproject depth map D_i using P_i
        mu_j = unproject_depth(depth_maps[i], projection_matrices[i])
        gaussian_centers.append(mu_j)
        
    # Step 8: Predict remaining parameters
    # Parallel head for alpha, Sigma, c
    gaussian_params = predict_gaussian_params(monocular_features, depth_maps)
    
    # Step 9: Rendering (for training loss calculation)
    # Render novel views using splatting
    rendered_views = splat_render(gaussian_centers, gaussian_params)
    
    return gaussian_centers, gaussian_params, rendered_views
```

**Edge Cases and Pitfalls:**
*   **Occlusions/Low-Texture/Non-Lambertian:** Multi-view depth estimation fails in these areas. DepthSplat mitigates this by augmenting multi-view cost volumes with monocular features [S1].
*   **Scale Ambiguity:** Monocular depth estimation suffers from scale ambiguities across views. DepthSplat maintains multi-view consistency by using monocular features only as an augmentation to multi-view matching, not as the primary depth source [S1].
*   **Error Propagation:** Unlike methods that refine coarse depth with monocular features (e.g., TranSplat), DepthSplat combines cost volume and monocular features early to avoid error propagation from coarse stages [S1].

## Subtopics

### [Gaussian Graph Network](18863-gaussian-graph-network.md)
A feed-forward method that generates efficient and generalizable 3D Gaussian representations by modeling relations between Gaussian groups from different views using a Gaussian Graph structure. It solves artifacts and excessive memory costs from simply combining pixel-aligned Gaussians. Unlike DepthSplat which focuses on robust depth prediction via feature matching, GGN focuses on inter-view Gaussian relations. Choose GGN when inter-view consistency of Gaussian primitives is critical beyond depth accuracy.

## Operating characteristics
*   **Time Complexity:** Reconstruction speed is 0.6 seconds for feed-forward reconstruction from 12 input views at 512x960 resolution [S1].
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:** State-of-the-art performance on ScanNet, RealEstate10K, and DL3DV datasets [S1].
*   **Scaling:** Computation scales efficiently to larger numbers of input views by selecting only the top-2 nearest neighbors for cost volume construction [S1].
*   **Strengths:** Robust to occlusions, low-texture, and non-Lambertian surfaces; maintains multi-view consistency; cheaper to train (4 GPUs vs 64 A100s for GS-LRM) [S1].
*   **Limitations:** Relies on pre-trained monocular depth features; multi-view transformer adds computational overhead compared to pure CNN-based methods [S1].
*   **When to use:** When robust feed-forward 3D Gaussian reconstruction from multi-view images is needed, especially in challenging scenes with low texture or reflections.
*   **When not to use:** When per-scene optimization is acceptable and higher quality is prioritized over speed; when computational resources are extremely limited and pre-trained models cannot be used.

## Background
DepthSplat was introduced to connect Gaussian splatting and depth estimation, studying their interactions [S1]. It was developed to overcome the individual limitations of multi-view stereo (failure in occlusions/low-texture) and monocular depth estimation (scale ambiguity) [S1]. The method was trained on TartanAir, ScanNet, RealEstate10K, and DL3DV datasets [S1]. It also demonstrates that Gaussian splatting can serve as an unsupervised pre-training objective for learning powerful depth models from large-scale multi-view posed datasets [S1].
