# RLSplat

Also called: Resource-Linear Budget Control for Feed-forward 3D Gaussian Splatting

## Overview
RLSplat is a resource-linear, budget-controllable feed-forward 3D Gaussian Splatting (FF3DGS) framework that generates exactly $B$ Gaussians for a given scene, ensuring that inference latency and peak memory scale linearly with the budget $B$ [S1, unofficial]. Unlike prior budget-controllable methods (e.g., EcoSplat, F4 Splat) that predict a dense set of candidates and prune them—resulting in nearly constant inference costs regardless of the target budget—RLSplat uses a learned allocation policy to distribute exactly $B$ Gaussians across local scene regions from the start [S1, unofficial]. It solves the problem of rigid resource usage in FF3DGS, enabling adaptation to diverse deployment constraints (e.g., AR/VR, robotics) without retraining [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** $V$ uncalibrated context images $\{I_i\}_{i=1}^V$ and a target Gaussian budget $B \in \mathbb{Z}_{>0}$ [S1, unofficial].
*   **Outputs:** A set of $B$ 3D Gaussians $\mathcal{G} = \{g_b\}_{b=1}^B$ and camera parameters $\{P_i\}_{i=1}^V$ for the context views [S1, unofficial]. Each Gaussian $g_b$ consists of a 3D center, opacity, scale, rotation, and color coefficients [S1, unofficial].

**Data Structures:**
1.  **Anchor Tokens ($\mathbf{a}$):** A set of $N$ tokens $\{\mathbf{a}_n\}_{n=1}^N$ extracted from the geometry backbone, each representing a local 3D region [S1, unofficial].
2.  **Allocation Vector ($\mathbf{k}$):** A discrete vector $\mathbf{k} \in \mathbb{Z}_{\ge 0}^N$ where $k_n$ is the number of Gaussians assigned to anchor $n$, such that $\sum_{n=1}^N k_n = B$ [S1, unofficial].
3.  **Gaussian Tokens:** $B$ tokens generated by spawning $k_n$ tokens per anchor [S1, unofficial].

**Parameters:**
*   $B$: Target Gaussian budget. Typical values: 2K (2,048), 8K, 64K [S1, unofficial].
*   $K_{gs}$: Number of nearest Gaussian neighbors for local refinement. Default ablation value: 16 [S1, unofficial].
*   $K_{anc}$: Number of anchor neighbors in hierarchical search. Fixed value in ablations: 16 [S1, unofficial].
*   $C$: Number of rollouts (candidate allocations) per training step for GSPO [S1, unofficial].

**Algorithm:**

1.  **Geometry Encoding:** The geometry backbone encodes the input images $\{I_i\}$ into $N$ anchor tokens $\{\mathbf{a}_n\}$ and predicts camera parameters $\{P_i\}$ [S1, unofficial].
2.  **Gaussian Allocation:** The allocation policy $\pi_\psi$ predicts a discrete allocation vector $\mathbf{k}$ based on anchor features. The policy is optimized using Group Sequence Policy Optimization (GSPO) [S1, unofficial].
    *   During training, $C$ candidate allocations $\mathbf{k}^{(c)}$ are sampled from the policy: $\mathbf{k}^{(c)} \sim \text{Mult}(B, \text{sg}(\mathbf{p}))$, where $\mathbf{p}$ are the policy logits and $\text{sg}(\cdot)$ stops gradients [S1, unofficial].
    *   The constraint $\sum k_n = B$ is strictly enforced [S1, unofficial].
3.  **Token Spawning:** For each anchor $n$, $k_n$ Gaussian tokens are spawned [S1, unofficial]. The total number of Gaussian tokens is exactly $B$ [S1, unofficial].
4.  **Resource-Linear Decoding:**
    *   **Initialization:** Each Gaussian token is assigned an initial state (center, scale, rotation, opacity, color) [S1, unofficial].
    *   **Hierarchical Neighbor Search:** For each Gaussian token, the $K_{gs}$ nearest Gaussian neighbors are identified using a hierarchical neighbor search over the anchor tokens (using $K_{anc}$ anchor neighbors) [S1, unofficial].
    *   **Local Refinement:** Each Gaussian token attends only to its $K_{gs}$ nearest neighbors via local cross-attention to refine its attributes [S1, unofficial]. This step ensures computational cost is $O(B \cdot K_{gs})$ rather than $O(B^2)$ [S1, unofficial].
5.  **Rendering:** The final set of $B$ Gaussians is rendered to target views using differentiable rasterization [Parent].

**Edge Cases and Pitfalls:**
*   **Training Failure:** Removing the projection loss causes training to fail entirely, as it ties anchor Gaussians to the image region they were encoded from [S1, unofficial].
*   **Neighbor Search Accuracy:** Removing the Voronoi loss causes a significant PSNR drop (2.51 dB) because Gaussians leave their anchor's cell, and the hierarchical search no longer retrieves their true neighbors [S1, unofficial].
*   **Local Refinement:** Removing the local refinement module lowers PSNR by 0.96 dB, as Gaussians cannot be made consistent with neighbors [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Decoding cost is $O(B \cdot K_{gs})$, scaling linearly with the Gaussian budget $B$ [S1, unofficial]. This contrasts with global self-attention, which costs $O(B^2)$ [S1, unofficial].
*   **Memory Complexity:** Peak memory scales linearly with $B$ [S1, unofficial].
*   **Performance:**
    *   At $B=2K$, RLSplat achieves higher PSNR than F4 Splat while using 9.6× less peak memory and running 4.1× faster [S1, unofficial].
    *   On ACID ($B=8,192$): PSNR 22.84 dB, SSIM 0.643, LPIPS 0.353 [S1, unofficial].
    *   On RE10K ($B=8K$): Full-view PSNR 26.51 dB, compared to 23.42 dB for F4 Splat and 21.82 dB for EcoSplat [S1, unofficial].
*   **Strengths:**
    *   True resource-linearity: Latency and memory decrease as $B$ decreases.
    *   Adaptive allocation: Concentrates Gaussians on high-frequency structures (e.g., thin balusters) and spares smooth regions, leading to better local and full-view PSNR [S1, unofficial].
    *   No retraining required to change $B$ or $K_{gs}$ at inference [S1, unofficial].
*   **Limitations:**
    *   Requires reinforcement learning (GSPO) for training the allocation policy, which may be complex to implement [S1, unofficial].
    *   Performance depends on the accuracy of the hierarchical neighbor search [S1, unofficial].
*   **When to Use:** Applications requiring limited resource budgets, such as AR/VR, robotics, and digital content creation, where inference latency and memory must be strictly controlled [S1, unofficial].

## Background
RLSplat was proposed by Bae, Park, and Kim from KAIST [S1, unofficial]. It addresses the limitations of prior budget-controllable FF3DGS methods like EcoSplat and F4 Splat, which predict dense sets of Gaussians and prune them, resulting in constant inference costs [S1, unofficial]. The method was published as a preprint in 2026 [S1, unofficial].
