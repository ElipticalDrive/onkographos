# Real-time 4DGS

Also called: RealTime4DGS

## Overview
Real-time 4DGS is a rendering method that achieves interactive frame rates by fusing a static background with a small, fast-updating set of dynamic foreground Gaussians [S1, unofficial]. It distinguishes itself from general 4D Gaussian Splatting by treating the time dimension equally with spatial dimensions, utilizing a 4D scaling matrix and isotropic rotations to represent 4D rotation, and conditioning the marginal distribution on time [S2, unofficial].

## How it works
**Inputs:** A set of 4D Gaussians representing the scene, where each Gaussian is defined in 4D space-time.
**Outputs:** A rendered image frame for a specific timestamp $t$.

**Data Structures:**
The method utilizes a specialized renderer structure that separates Gaussians into two sets:
1.  **Static Background Gaussians:** Stored in a standard 3D Gaussian Splatting (3D-GS) tile-based rasterization structure. These do not change over time.
2.  **Dynamic Foreground Gaussians:** A smaller set of Gaussians that are updated frequently. These are treated as 4D primitives.

**Method Steps:**
1.  **Reformulation:** The method reformulates 3D-GS into 4D-GS. Each Gaussian is represented with a 4D scaling matrix and a pair of isotropic rotations to define 4D rotation [S2, unofficial].
2.  **Time Conditioning:** The 4D Gaussians are conditioned on time $t$ multiplied by the marginal distribution to render the dynamic scene [S2, unofficial].
3.  **Sampling:** At the current rendering timestamp $t$, the 4D Gaussians are sampled into 3D Gaussians. This projection allows the use of the existing efficient tile-based rasterizer designed for static 3D-GS [S2, unofficial].
4.  **Rendering:** The sampled 3D Gaussians (both from the static background and the projected dynamic foreground) are rasterized using the tile-based approach to produce the final image.

**Pseudocode:**
```python
def render_realtime_4dgs(static_gaussians, dynamic_4d_gaussians, timestamp):
    # Step 1: Sample dynamic 4D Gaussians into 3D Gaussians at the current timestamp
    # This involves projecting the 4D primitive (defined by 4D scaling and rotation)
    # onto the 3D spatial slice at time 'timestamp'.
    dynamic_3d_gaussians = sample_4d_to_3d(dynamic_4d_gaussians, timestamp)
    
    # Step 2: Combine static and dynamic sets
    all_gaussians = static_gaussians + dynamic_3d_gaussians
    
    # Step 3: Rasterize using the tile-based rasterizer
    # The rasterizer handles depth sorting, alpha blending, and tile culling
    image = tile_based_rasterize(all_gaussians)
    
    return image
```

**Parameters:**
*   **Timestamp:** The specific time instance for which the frame is rendered.
*   **Update Frequency:** The rate at which dynamic foreground Gaussians are updated. The method relies on this set being "small" and "fast-updating" to maintain interactivity [S1, unofficial].

**Edge Cases:**
*   **Precision:** The conversion from 4D rotation (isotropic pairs) to 3D spatial representation at a specific timestamp must handle numerical stability to avoid artifacts in dynamic regions [S2, unofficial].
*   **Boundary:** The separation between static and dynamic Gaussians must be robust; misclassification leads to either performance loss (if static is treated as dynamic) or visual artifacts (if dynamic is treated as static).

## Operating characteristics
*   **Time Complexity:** Interactive frame rates are achieved by limiting the expensive 4D-to-3D sampling and update operations to a small set of dynamic foreground Gaussians, while leveraging the highly optimized tile-based rasterizer for the bulk of the scene (static background) [S1, unofficial].
*   **Memory Complexity:** Reduced compared to full 4D Gaussian storage for the entire scene, as static parts are stored in efficient 3D structures and only dynamic parts require 4D parameterization and frequent updates [S1, unofficial].
*   **Strengths:** High rendering speed (interactive); effective separation of static and dynamic content; leverages mature 3D-GS rasterization infrastructure.
*   **Limitations:** Relies on the assumption that a significant portion of the scene is static or can be effectively modeled as such; performance depends on the size of the dynamic foreground set.
*   **When to use:** Real-time applications requiring dynamic scenes with a dominant static background.
*   **When not to use:** Fully dynamic scenes with no static background, or scenes where the dynamic component is too large to be considered a "small" set.

## Background
Real-time 4DGS is cited as the first method to reformulate 3D-GS into 4D-GS by treating time and space dimensions equally [S2, unofficial]. It was developed to address the computational bottleneck of rendering dynamic scenes in Gaussian Splatting by introducing a specialized renderer that fuses static and dynamic components [S1, unofficial].
