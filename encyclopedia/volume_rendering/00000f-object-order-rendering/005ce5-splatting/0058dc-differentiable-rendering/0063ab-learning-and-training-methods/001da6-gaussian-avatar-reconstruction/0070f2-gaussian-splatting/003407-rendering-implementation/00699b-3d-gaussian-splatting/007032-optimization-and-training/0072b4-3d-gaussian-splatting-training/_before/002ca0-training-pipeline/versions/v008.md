# Training Pipeline

Also called: Full Training Procedure, Inner 3D Gaussian Splatting Training, Iterative optimization loop, Main Training Loop

## Overview
The Training Pipeline is the iterative optimization loop for 3D Gaussian Splatting that initializes a set of 3D Gaussians and optimizes their parameters (position, covariance, opacity, color, and spherical harmonics coefficients) via gradient descent [S1, S2, unofficial]. It solves the inverse problem of reconstructing a scene from multi-view images by projecting Gaussians onto 2D slice views, computing a rendering loss, and performing backpropagation [S1, unofficial]. It distinguishes itself from standard optimization by integrating dynamic Gaussian management (pruning, densification, cloning) within the training loop to adapt the representation density to the scene complexity [S1, unofficial].

## How it works
The pipeline operates as a nested loop structure: an outer loop iterates over training steps, an intermediate loop iterates over spatial axes (x, y, z), and an inner loop iterates over slices along those axes [S1, unofficial].

**Inputs and Outputs:**
*   **Input:** Training dataset $\mathcal{D} = \{(I_i^{\text{axis}}, \pi_i^{\text{axis}})\}$, where $I$ is a 2D slice image and $\pi$ is the slice position [S1, unofficial]. Grid resolution $g_{\text{res}}$ for initialization [S1, unofficial].
*   **Output:** Optimized set of Gaussians $\mathcal{G} = \{(\mu, \Sigma, c, \alpha)\}$ [S1, unofficial].

**Data Structures:**
*   **Gaussian State:** Each Gaussian $n$ is defined by mean $\mu_n$, covariance $\Sigma_n$, color $c_n$, and opacity $\alpha_n$ [S1, unofficial]. The covariance is decomposed into rotation $R_n$ and scale $S_n$ such that $\Sigma_n = R_n S_n S_n R_n^\top$ [S1, unofficial].
*   **Optimizer State:** Adam optimizer maintains moments for parameters $\theta$ with learning rate $\eta$ [S1, unofficial].

**Algorithm Steps:**

1.  **Initialization:** Build a regular 3D grid $\mathcal{P}$ of size $g_{\text{res}}$ or use Structure-from-Motion (SfM) estimated points. Initialize each Gaussian with mean $\mu$ around grid points and default values for scale $s$, color $c$, opacity $\alpha$, and quaternion $q$ [S1, unofficial].
2.  **Optimizer Setup:** Initialize the Adam optimizer with parameters $\theta$ and learning rate $\eta$ [S1, unofficial].
3.  **Outer Loop:** Iterate for `step` from 1 to `stepmax` [S1, unofficial].
4.  **Reset Accumulators:** Set total loss $L_{\text{total}}$ to 0 and zero gradients $\nabla_\theta$ [S1, unofficial].
5.  **Axis Loop:** Iterate over axes $\text{axis} \in \{x, y, z\}$ [S1, unofficial].
6.  **Slice Loop:** For each slice $(I_i^{\text{axis}}, \pi_i^{\text{axis}})$ in the dataset $\mathcal{D}_{\text{axis}}$ [S1, unofficial]:
    a.  **Covariance Computation:** Compute 3D covariance $\Sigma_n \leftarrow R_n S_n S_n R_n^\top$ [S1, unofficial].
    b.  **Rendering:** Rasterize the Gaussian parameters to predict the image $I_{\text{pred}} \leftarrow \text{Rasterize}(\mu_n, \Sigma_n, \alpha_n, c_n)$ [S1, unofficial].
    c.  **Loss Computation:** Compute loss $L$ between predicted image $I_{\text{pred}}$ and ground truth slice $I_i^{\text{axis}}$ [S1, unofficial].
    d.  **Accumulate Loss:** $L_{\text{total}} \leftarrow L_{\text{total}} + L$ [S1, unofficial].
7.  **Backpropagation:** Perform backward pass on the total loss $L_{\text{total}}$ [S1, unofficial].
8.  **Parameter Update:** Update parameters $\theta$ using the Adam step [S1, unofficial].
9.  **Refinement Check:** If the current step is a refinement iteration ($\text{IsRefinementIteration}(t)$) [S1, unofficial]:
    a.  **Gaussian Iteration:** Iterate over all Gaussians $(\mu, \Sigma, c, \alpha) \in \mathcal{G}$ [S1, unofficial].
    b.  **Pruning Condition:** If opacity $\alpha < \tau_\alpha$ or the Gaussian is too large ($\text{IsTooLarge}(\mu, \Sigma)$) [S1, unofficial]:
        i.  **Pruning Action:** Call $\text{RemoveGaussian}()$ [S1, unofficial].
    c.  **Densification Condition:** Else if the L2 norm of the gradient of $\mu$ with respect to loss is greater than $\tau_p$ ($\|\nabla_\mu L\|_2 > \tau_p$) [S1, unofficial]:
        i.  **Over-reconstruction Check:** If the Frobenius norm of $\Sigma$ is greater than $\tau_s$ ($\|\Sigma\|_F > \tau_s$) [S1, unofficial]:
            *   **Split Action:** Call $\text{SplitGaussian}(\mu, \Sigma, c, \alpha)$ [S1, unofficial].
        ii. **Under-reconstruction Action:** Else, call $\text{CloneGaussian}(\mu, \Sigma, c, \alpha)$ [S1, unofficial].

**Parameters:**
*   $g_{\text{res}}$: Grid resolution for initialization [S1, unofficial].
*   $\tau_\alpha$: Opacity threshold for pruning [S1, unofficial].
*   $\tau_p$: Gradient threshold for densification [S1, unofficial].
*   $\tau_s$: Scale threshold for distinguishing over-reconstruction (split) vs under-reconstruction (clone) [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** The covariance decomposition $\Sigma = R S S R^\top$ requires careful handling of rotation parameterization to ensure positive semi-definiteness [S1, unofficial].
*   **Boundaries:** The axis-slice approach requires consistent handling of slice boundaries to avoid gaps or overlaps in the 3D volume representation [S1, unofficial].
*   **Degenerate Input:** If the initialization grid is too coarse, the model may fail to capture fine details; if too fine, it may lead to excessive memory usage and slow convergence [S1, unofficial].

## Subtopics

### [Mini-Splatting Pipeline](9235-mini-splatting-pipeline.md)
The Mini-Splatting Pipeline is a training strategy for 3D Gaussian Splatting that explicitly manages the total number of Gaussians through periodic densification, simplification, and depth-based reinitialization phases. It distinguishes itself from standard 3D Gaussian Splatting by enforcing a constrained Gaussian count via a manually controlled sampling ratio.

### [Validation Metric Computation & Logging](10760-validation-metric-computation-logging.md)
This method computes quantitative validation metrics (primarily PSNR) and saves visual examples by rendering novel views from the optimized 3D Gaussian Splatting model and comparing them against ground truth images. It is distinct from the training loop as it operates in evaluation mode (`is_train=False`) with gradient tracking disabled, ensuring that the optimization state is not updated during metric calculation.

### FaCT-GS Optimization Loop
FaCT-GS extends the standard training loop by incorporating total variation regularization for CT reconstruction [S4].
*   **Steps:** Rasterize Gaussians into a 2D image ($\mathbf{I}_r$) and compare to projection data ($\mathbf{I}_{gt}$) using L1 and SSIM losses [S4]. Voxelize a small, randomly sampled section of the volume ($\mathbf{V}_{px3}$) and calculate 3D total variation ($\mathcal{L}_{TV}$) as a homogeneity regularization prior [S4]. In the backward pass, use the loss to prune, clone, or split Gaussians (Adaptive Control) and adjust parameters based on propagated gradients [S4].
*   **Formula:** $\mathcal{C}_{\text{total}} = \mathcal{L}_1 (\mathbf{I}_1, \mathbf{I}_{\text{tet}}) + \alpha_{\text{SSIM}} \mathcal{L}_{\text{SSIM}} (\mathbf{I}_1, \mathbf{I}_{\text{tet}}) + \alpha_{\text{TV}} \mathcal{L}_{\text{TV}} (\mathbf{V}_{32^3})$, where $\alpha_{\text{SSIM}}$ and $\alpha_{\text{TV}}$ are SSIM and TV loss weights respectively [S4].
*   **Parameters:** Sampling size for voxelization is increased from $8^3$ to $32^3$ [S4].

### Cut-Set Gradient Update
In hierarchical representations, the training loop updates only the parameters of the "cut set" of Gaussians intersecting the current training view [S3, unofficial]. Gradients propagate to Gaussians in the middle of the hierarchy, diffusing across the entire structure over many iterations with diverse views [S3, unofficial].

### 3D Gaussian Splatting Initialization & Training Schedule
This variant uses LiDAR point clouds and pseudo-view guidance for initialization and training [S5].
*   **Steps:** Project LiDAR frame to corresponding image frame to assign color to each LiDAR point, then re-project colored points into 3D space [S5]. Accumulate all frames of point clouds and voxel-downsample with a voxel size of 5 [S5]. Warm-up phase: train for 500 iterations without sampling pseudo views [S5]. Guided phase: for every 10 iterations, sample 4 pseudo views for training [S5].
*   **Parameters:** Total training iterations: 50,000 for both SGD and baseline 3DGS models [S5].

### fMRI Temporal Adaptation
This strategy adapts 3D Gaussian Splatting for functional MRI data by freezing geometry parameters and allowing only color and opacity to vary over time, capturing voxel-wise radiance changes from neural activity [S1, unofficial].
*   **Steps:** Stage 1: Build a static anatomical structure over 1000 warm-up iterations using initial frames [S1, unofficial]. Stage 2: Run 3000 iterations where only color and opacity evolve temporally [S1, unofficial].
*   **Parameters:** Dataset: OpenfMRI project (Xue and Poldrack, 2018), ds000003, consisting of 160 temporal frames, each with 33 axial brain slices at 64x64 resolution [S1, unofficial]. Training/Test Split: 140 frames for training, every 8th frame (20 total) for testing [S1, unofficial].
*   **Pitfalls:** A custom data loader ensures all slices from a given timestamp are processed synchronously to preserve inter-slice consistency [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The complexity is dominated by the rasterization and backpropagation steps, which are parallelized across pixels and Gaussians. The nested loop structure (steps $\times$ axes $\times$ slices) increases the number of forward/backward passes per optimization step, but allows for efficient memory usage by processing slices independently [S1, unofficial].
*   **Memory Complexity:** Memory usage scales with the number of Gaussians and the resolution of the training slices. The dynamic management (pruning/cloning) helps keep the Gaussian count manageable [S1, unofficial].
*   **Measured Performance:** On standard datasets, the pipeline achieves high-quality reconstructions with PSNR values comparable to other state-of-the-art methods [S1, unofficial].
*   **Scaling:** The method scales well with the number of training views, as the loss is accumulated over multiple slices [S1, unofficial].
*   **Strengths:** Dynamic adaptation allows the model to capture both coarse and fine details efficiently [S1, unofficial].
*   **Limitations:** The nested loop structure can be computationally expensive if the number of slices is large [S1, unofficial].
*   **When to use:** Suitable for scenes where the density of features varies significantly, requiring adaptive representation [S1, unofficial].
*   **When not to use:** Not ideal for real-time applications where the overhead of the nested loop and dynamic management is prohibitive [S1, unofficial].

## Background
The Training Pipeline originates from the 3D Gaussian Splatting method introduced by Kerbl et al. [2023], which uses a differentiable rasterizer to optimize 3D Gaussians for novel view synthesis [S1, S3, unofficial]. The specific inner loop structure with axis-slice decomposition and dynamic densification/pruning was detailed in subsequent works such as InnerGS [S1, unofficial] and various implementations [S2, S3, unofficial]. The method has been extended to various domains including CT reconstruction (FaCT-GS) [S4], LiDAR integration (SGD) [S5], and fMRI analysis [S1, unofficial].
