# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, GSGEN Implementation Details, Gaussian Splatting Training Configuration, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific implementation parameters, optimization strategies, and variant algorithms used to train and render 3D Gaussian Splatting (3DGS) scenes. It covers the core training loop mechanics, including densification schedules, gradient thresholds, and half-precision rasterization techniques, as well as specialized variants for handling defocus blur, sparse views, and large-scale scenes. It sets itself apart from general [Optimization and Parallelization](6233-optimization-and-parallelization.md) by providing concrete hyperparameters, code-level logic for density control, and specific architectural choices for differentiable rendering kernels.

## How it works

### Core Training and Densification
The standard training pipeline optimizes Gaussian parameters (position $\mathbf{p}$, covariance $\mathbf{\Sigma}$, opacity $\alpha$, and spherical harmonic coefficients $\mathbf{c}$) using stochastic gradient descent. The optimization is guided by a photometric loss combining Mean Squared Error (MSE) and Structural Similarity Index Measure (SSIM) [S13, unofficial]:

$$
\mathcal{L} = \lambda \cdot \text{MSE}(\mathbf{C}, \hat{\mathbf{C}}) + (1 - \lambda) \cdot \text{SSIM}(\mathbf{C}, \hat{\mathbf{C}})
$$

where $\mathbf{C}$ is the ground-truth color, $\hat{\mathbf{C}}$ is the rendered color, and $\lambda$ is a hyperparameter balancing the terms [S13, unofficial].

**Densification Schedule:**
To adapt the Gaussian distribution to the scene complexity, densification (splitting and cloning) and pruning are performed periodically [S1].

1.  **Splitting:** Every 500 iterations, Gaussians are split based on their view-space position gradient. If the accumulated gradient exceeds a threshold $T_{\text{pos}} = 0.02$, the Gaussian is split into two [S1].
2.  **Cloning/Compactness:** Every 1000 iterations, a compactness-based densification step is performed to add new Gaussians in under-represented regions [S1].
3.  **Pruning:** Every 200 iterations, Gaussians with opacity $\alpha < \alpha_{\text{min}} = 0.05$ or excessively large world-space/view-space radius are removed [S1].

**Gradient Threshold Schedule:**
To control the number of split Gaussians, an exponentially ascending gradient threshold is used. This ensures that densification is aggressive in early stages and stabilizes as training progresses, preventing overfitting to noise [S4].

### Half-Precision Rasterization Implementation
To accelerate training and reduce memory bandwidth, the rasterization kernels (forward and backward passes) can be implemented using half-precision (FP16) arithmetic [S2].

**Data Structures:**
*   **Gaussian Attributes:** Stored in contiguous memory. Feature vectors (e.g., SH coefficients) are fetched using half-precision memory accesses to reduce register pressure [S2].
*   **MLP Evaluation:** If view-dependent features are predicted via a Multilayer Perceptron (MLP), they are trained and evaluated using tiny-cuda-nn's JIT-compiled cooperative vector MLPs in FP16 [S2].

**Stability Measures:**
*   **Loss Scaling:** An automatic scaling factor is applied to loss values to prevent gradient underflow during backpropagation in half-precision [S2].

### Optimizer Configuration
*   **Optimizer:** Adam [S3].
*   **Learning Rate:** $1 \times 10^{-3}$ [S3].
*   **Spherical Harmonics (SH) Degree:** Typically set to 1 for standard implementations, balancing view-dependent detail and computational cost [S3].

### Pseudocode: Standard Training Loop

```python
# Initialization
gaussians = initialize_from_sfm(sfm_points)
optimizer = Adam(gaussians.parameters(), lr=1e-3)
iteration = 0
max_iterations = 30000

while iteration < max_iterations:
    # 1. Sample a random training image
    image_id = random_choice(training_images)
    gt_color = get_gt_color(image_id)
    camera_pose = get_camera_pose(image_id)
    
    # 2. Forward Pass: Differentiable Rasterization
    # Projects 3D Gaussians to 2D, sorts by depth, and alpha-blends
    rendered_color = rasterize(gaussians, camera_pose)
    
    # 3. Loss Computation
    # Combined MSE and SSIM loss
    mse_loss = mean_squared_error(gt_color, rendered_color)
    ssim_loss = 1 - structural_similarity(gt_color, rendered_color)
    loss = 0.8 * mse_loss + 0.2 * ssim_loss # Typical lambda=0.8
    
    # 4. Backward Pass
    optimizer.zero_grad()
    loss.backward()
    
    # 5. Optimizer Step
    optimizer.step()
    
    # 6. Densification and Pruning
    if iteration % 500 == 0:
        # Split Gaussians with high view-space position gradient
        split_gaussians(gaussians, threshold=0.02)
        
    if iteration % 1000 == 0:
        # Compactness-based densification
        densify_gaussians(gaussians)
        
    if iteration % 200 == 0:
        # Prune low-opacity and oversized Gaussians
        prune_gaussians(gaussians, alpha_min=0.05)
        
    iteration += 1
```

## Subtopics

### Corrected Scene-Extent
A method to calculate scene extent based on the Structure-from-Motion (SfM) point cloud rather than camera positions to avoid bias from camera distribution (e.g., orbiting a small object in a large environment) [S4]. The default 3DGS scene extent $e_{\text{scene}}$ is proportional to the distance of the furthest camera from the average camera position, causing bias if cameras are clustered [S4]. The corrected extent $e'_{\text{scene}}$ is calculated as:

$$
e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2
$$

where $N_{\text{SfM}}$ is the number of SfM points, $\bar{C}$ is the averaged camera position, and $p_i$ is the $i$-th SfM point [S4].

### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ to selectively enlarge covariances, creating pixel-wise variable blur kernels that match spatially varying scene blurriness [S5]. A compact MLP predicts $\delta s_j$ for each Gaussian $j$. The offset is added to the base scale to transform the covariance, which is then projected to 2D space and used as a pixel-wise blur kernel during rasterization [S5]. If $\delta s_j$ is predicted as a constant for all Gaussians, it degrades to a uniform Gaussian blur [S5].

### Denoise-GS
A self-supervised denoising method for sparse-view 3D Gaussian Splatting that combines unsupervised image denoising with explicitly differentiable 3DGS [S6]. It uses Noise2Void (N2V) to train a UNet for denoising without paired clean data, which is crucial for sparse viewpoints where only one image per view exists [S6]. The process involves two rounds: Round 1 trains the UNet and initializes 3DGS via InstantSplat; Round 2 fine-tunes the UNet with a composite loss balancing low-frequency consistency and perceptual detail consistency, then renders final denoised views [S6].

### Multi-Scale Constraint
A technique using position-aware point adaptive control to apply different scales to Gaussians based on viewer distance, improving rendering of distant objects [S7]. A scaling factor $\gamma(\mu)$ is computed based on the distance of the Gaussian center $\mu$ from the camera center $c$ and scene radius $r$:

$$
\gamma(\mu) = 
\begin{cases} 
1 & \text{if } \|\mu - c\|^2 < 2r \\
\|\mu - c\|^2 / r - 1 & \text{if } \|\mu - c\|^2 \ge 2r 
\end{cases}
$$

Cloning is performed if $\max(s) < g \cdot \gamma(\mu)$, splitting if $\max(s) \ge g \cdot \gamma(\mu)$, and elimination if $\max(s) > b \cdot \gamma(\mu)$, where $g$ and $b$ are scale threshold parameters [S7].

### LS-Gaussian Viewpoint Transformation
An algorithm that leverages inter-frame continuity for efficient sparse rendering by transforming the viewpoint between consecutive frames, rather than rendering each frame separately [S8]. It operates at the tile/Gaussian level to enable sparse rendering, where only one frame in every 6 frames is fully rendered, as demonstrated on Jetson AGX Orin [S8]. Rendering quality degrades noticeably as the number of consecutively transformed frames increases due to the accumulation of interpolation errors [S8].

### Camera Localisation for Convergence Basin
Localizes camera pose by minimizing only the photometric error against the ground-truth colour image of the target view, fixing the initial Gaussians $G_{\text{init}}$ during optimization [S9, unofficial]. The estimated pose $T_{CW}^{\text{est}}$ is found by:

$$
\mathbf{T}_{CW}^{\text{est}} = \underset{\mathbf{T}_{CW}}{\arg \min} \left\| I(\mathcal{G}_{\text{init}}, \mathbf{T}_{CW}) - \bar{I}_{\text{target}} \right\|_1
$$

Localization is successful if the estimated pose converges to within 1cm of the target view within 1000 iterations [S9, unofficial].

### DiffGS Framework
Applies an optimization process during Gaussian extraction to optimize Gaussians to exact locations using a Gaussian Probability Function (GauPF) with a truncation function $\lambda$ and a projection function $\tau$ (either exponential or linear) [S10]. With 50K Gaussians, it achieves PSNR 28.61, SSIM 0.9787, and LPIPS 0.0251; with 100K Gaussians, PSNR 30.35, SSIM 0.9838, and LPIPS 0.0151; and with 350K Gaussians, PSNR 34.01, SSIM 0.9879, and LPIPS 0.0149 [S10].

### Conditional Splat Approximation
Approximates the influence range of a 3D Gaussian on a slice by using a 2D ellipse splat scaled by the marginal factor, which closely matches the true iso-probability contours [S12, unofficial]. Qualitative validation shows that the conditional splat approximation closely overlaps with the true 3D Gaussian iso-probability contours, providing an accurate and efficient approximation of the original 3D Gaussian’s influence range [S12, unofficial].

### PyGS Optimization
The optimization process using a combined MSE and SSIM loss, along with density control strategies adapted from 3DGS, while preserving the multi-scale structure [S13, unofficial]. Splitting and cloning strategies from 3DGS are applied, with newly split/cloned Gaussians remaining in their original level and cluster. Levels are routinely reassessed and reassigned based on scales to preserve multi-scale characteristics [S13, unofficial].

### GAINS (Gaussian-based Inverse Rendering from Sparse multi-view captures)
A two-stage inverse rendering framework that leverages foundation model priors to stabilize geometry and material estimation from sparse multi-view RGB captures (typically 4–32 views) [S14]. Stage I optimizes geometry using monocular depth, normal, and diffusion priors. Stage II jointly optimizes material parameters and lighting using segmentation, intrinsic image decomposition (IID), and diffusion priors to minimize re-rendering loss [S14]. It uses 2DGS instead of 3DGS because 2DGS provides more accurate geometry reconstruction, which is essential for accurate material property estimation [S14].

### SAGS (Adaptive Gaussian Splatting)
Utilizes an adaptive 2D low-pass filter at inferencing time based on rendering resolution and camera distance to handle aliasing [S15, unofficial].

### Frequency Gaussian Splatting
Applies frequency-domain regularization to the rendered 2D image to encourage recovery of high-frequency detail, resolving blurring issues [S15, unofficial].

### Neural Illumination Enhancement
A neural module applied only to non-Lambertian regions to model view-dependent highlights and handle non-Lambertian effects that vanilla 3DGS struggles with [S16, unofficial]. A lightweight MLP predicts a view-dependent color residual $I_n$. Spatial positions are encoded using HashGrid, reflection directions using Spherical Harmonics (SH), and other features (view direction, surface normals, Fresnel term, roughness) are used directly. The final image is $I = I_g + I_n$, where $I_g$ is the explicit Gaussian image [S16, unofficial].

### GraphiGS
A variant of the GraphiXS framework where the component distribution $\delta_\theta$ is modeled as a 3D Gaussian primitive, providing compact spatial support and exponential density decay [S17]. The distribution is defined as:

$$
\delta_{\text{GS}}(\mathbf{x}; \boldsymbol{\mu}, \mathbf{\Sigma}) = \exp\left(-\frac{1}{2} (\mathbf{x} - \boldsymbol{\mu})^\top \mathbf{\Sigma}^{-1} (\mathbf{x} - \boldsymbol{\mu})\right)
$$

where $\boldsymbol{\mu}$ is the mean vector ($\mathbb{R}^3$) and $\mathbf{\Sigma}$ is the covariance matrix ($\mathbb{R}^{3 \times 3}$) [S17].

### Direct Gaussian Primitive Regularization
Aligns 2D Gaussian primitives (orientation $\mathbf{R}$, scale $\mathbf{S}$, position $\mathbf{p}$) with latent scene surfaces using multi-view consistency on sampled points [S18]. $K$ points are sampled from the standard Gaussian distribution on each disk-shaped primitive, projected to source and target views, and MVS features are queried. The point position loss $L_{df}$ is computed via cosine similarity, and the normal loss $L_{dn}$ supervises the normal vector $\mathbf{R}[\dots, 2]$ using rendered normal $\mathbf{n}$:

$$
L_{dr} = L_{df} + L_{dn}
$$

A pitfall is that the last scale value of 2D Gaussian primitives is zero, making it difficult to optimize the normal vector $\mathbf{R}[\dots, 2]$ in the last dimension [S18].

### SLS-mlp
A robust masking method using an MLP to predict distractor masks, compared against SLS-agg (agglomerative clustering) and RobustFilter [S19]. A lightweight MLP (roughly 30K parameters, two nonlinear activations) is trained simultaneously with the 3DGS model to group semantically associated pixels. It adapts better to subtle transients like shadows compared to a small CNN of similar size, but is marginally slower than the clustering-based SLS-agg [S19].

### SLS-agg
A robust masking method using agglomerative clustering to remove distractors [S19]. It performs agglomerative clustering on semantic features extracted from the scene. Performance improves with more clusters, plateauing for $C \ge 100$ clusters. It is faster than SLS-mlp because it does not require further training [S19].

### Geometrically Enhanced Supervision
Incorporates off-the-shelf Multi-View Stereo (MVS) features into Gaussian primitives to prevent geometric degradation under sparse views, where color alone overfits [S18]. MVS features $f_{ij}$ and RGB color $c_{ij}$ are sampled into each Gaussian primitive at the projected 3D point $p_{ij}$ using the projection function $\pi(\cdot)$. The values of $f_{ij}$ and $c_{ij}$ are fixed during optimization to enforce learning specifically for geometry. Simultaneous learning of appearance (color) and feature with geometry causes geometric degradation under sparse views [S18].

### Uncertainty-based Pruning
Reduces the number of splats while maintaining reconstruction quality, based on epistemic uncertainty computation per primitive [S19]. Epistemic uncertainty is computed per primitive and thresholded to remove lesser utilized Gaussians. If the uncertainty threshold is set too aggressively, the method may remove parts of the scene that are rarely viewed in the training data [S19].

## Operating characteristics

*   **Time Complexity:** The training time is dominated by the differentiable rasterization and the periodic densification steps. Half-precision rasterization [S2] significantly reduces memory bandwidth usage and accelerates the forward/backward passes.
*   **Memory Complexity:** Memory usage scales with the number of Gaussians. Pruning [S1] and compression methods [12943-data-compression-and-storage-optimization.md] are critical for managing memory in large scenes.
*   **Performance:** Standard 3DGS achieves high-fidelity rendering at real-time speeds on modern GPUs. Variants like LS-Gaussian [S8] can achieve significant speedups (e.g., 5.41× on Jetson AGX Orin) by leveraging sparse rendering and viewpoint transformation.
*   **Strengths:** High visual fidelity, real-time rendering, explicit representation allows for easy editing and compression.
*   **Limitations:** Sensitive to initialization and camera distribution (addressed by Corrected Scene-Extent [S4]). Struggles with non-Lambertian effects without augmentation (e.g., NIE [S16, unofficial]). Requires careful tuning of densification thresholds to avoid floaters or over-smoothing.

## Background

3D Gaussian Splatting was introduced by Kerbl et al. in 2023 as a real-time explicit scene representation method [S1]. It builds on the principles of differentiable rendering and splatting, adapting them for 3D Gaussians. The method has since been extended with various optimization and training techniques to improve efficiency, robustness, and applicability to diverse scenarios such as sparse views, dynamic scenes, and inverse rendering.
