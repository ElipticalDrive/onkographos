# Compact View-dependent Color

Also called: Grid-based Neural Field for Color

## Overview
Compact View-dependent Color replaces the storage of per-Gaussian Spherical Harmonics (SH) coefficients with a shared grid-based neural field to predict view-dependent color, significantly reducing memory usage from 48 parameters per Gaussian to a compact global representation [S1]. Unlike [Spherical Harmonics Optimization](14206-spherical-harmonics-optimization.md) which retains SH bases, this method maps spatial position and view direction to color via a hash grid and MLP, offering a parameter-efficient alternative for [Gaussian Splatting](../3d-gaussian-splatting.md) rendering [S1, S3].

## How it works
**Inputs and Outputs:**
*   **Input:** 3D position $p_n \in \mathbb{R}^3$ of the $n$-th Gaussian, view direction $d \in \mathbb{R}^3$, and 0-degree SH coefficients (RGB channels, view-independent) [S1].
*   **Output:** View-dependent color $c_n(d) \in \mathbb{R}^3$ [S1].

**Data Structures:**
1.  **Hash Grid:** A sparse hash table mapping quantized 3D coordinates to feature vectors. The grid is shared across all Gaussians [S1, S3].
2.  **Tiny MLP:** A small multi-layer perceptron with parameters $\theta$ that takes the concatenated hash grid feature and view direction as input [S1].

**Steps:**
1.  **Contraction:** Map the unbounded position $p_n$ to a bounded range $[-1, 1]^3$ using the contraction function from mip-NeRF 360 [S1].
    $$
    \text{contract}(p_n) = 
    \begin{cases} 
    p_n & \text{if } \|p_n\| \le 1 \\
    \frac{p_n}{\|p_n\|} (2 - \|p_n\|) & \text{if } \|p_n\| > 1 
    \end{cases}
    $$
    where $\|p_n\|$ is the Euclidean norm [S1].
2.  **Hash Encoding:** Query the hash grid using the contracted position $\text{contract}(p_n)$ to retrieve a feature vector $f_{pos}$ [S1, S3].
3.  **Color Prediction:** Concatenate $f_{pos}$ with the view direction $d$ and pass through the MLP $f(\cdot; \theta)$ to predict the color [S1, S3].
    $$
    c_n(d) = f(\text{contract}(p_n), d; \theta)
    $$
4.  **Base Color Integration:** The method uses 0-degree SH components (RGB) as a base color input or residual, converting them to RGB colors to slightly increase performance compared to representing RGB directly [S1].

**Pseudocode:**
```python
def contract(p: Vector3) -> Vector3:
    """
    Contracts unbounded position p to bounded range [-1, 1]^3.
    Based on mip-NeRF 360 contraction [S1].
    """
    norm = magnitude(p)
    if norm <= 1.0:
        return p
    else:
        return (p / norm) * (2.0 - norm)

def get_view_dependent_color(p: Vector3, d: Vector3, hash_grid: HashGrid, mlp: MLP) -> Vector3:
    """
    Computes view-dependent color for a Gaussian at position p with view direction d.
    Uses a shared hash grid and tiny MLP [S1, S3].
    """
    # Step 1: Contract position to bounded space
    p_contracted = contract(p)
    
    # Step 2: Query hash grid for positional features
    # The hash grid maps quantized coordinates to feature vectors
    feature_pos = hash_grid.query(p_contracted)
    
    # Step 3: Combine with view direction
    # Concatenate positional features and view direction
    input_vector = concatenate(feature_pos, d)
    
    # Step 4: Predict color via MLP
    # f(theta) is the tiny MLP with parameters theta
    color = mlp.forward(input_vector)
    
    return color
```

**Parameters:**
*   **Hash Grid Resolution:** Not given in the sources.
*   **MLP Architecture:** Described as "tiny" [S1]. Specific layer sizes and activation functions are not given in the sources.
*   **SH Degree:** 0-degree (RGB only) is used for the base color component [S1].

**Edge Cases and Pitfalls:**
*   **Unbounded Space:** The contraction function is necessary because the hash grid operates on a bounded domain; without it, positions outside $[-1, 1]^3$ would not be handled correctly [S1].
*   **Precision:** The contraction function involves division by norm, requiring care for $p_n \approx 0$ [G].

## Subtopics

### Gaussian Directional Encoding
A strategy to reduce disk space explosion from high-order SH by using view-dependent color $c_\theta$ from a grid-based neural network, using only 0-degree SH during training [S2]. The model representation is $\{( N (x_{encoding}^{(i)}, \Sigma_i ), \alpha_i , c_i )\}_{i=1}^n$, where $c_i$ is obtained from MLPs $f$ [S2].

### Hash-Grid and MLP Color Representation
A method to eliminate storing attributes for each Gaussian by using a hash-grid and MLP to predict view-dependent color based on position and view direction [S3]. Positions are input into the hash-grid, and the resultant feature along with the view-direction are provided to the MLP to retrieve the color [S3].

## Operating characteristics
*   **Memory Complexity:** Reduces per-Gaussian memory from 48 parameters (for SH degree 3) to a shared grid and MLP, significantly lowering total scene memory [S1].
*   **Time Complexity:** Rendering requires a hash grid query and MLP forward pass per Gaussian, which is generally faster than evaluating SH basis functions [S1].
*   **Performance:** On Mip-NeRF 360, the method achieved PSNR 29.91 with training time 17m 51s and 254 fps, compared to 3DGS baseline PSNR 29.87, 19m 22s, and 154 fps (tested on NVIDIA A6000/A100) [S1].
*   **Strengths:** Parameter efficiency, reduced disk space, and faster training/inference compared to high-order SH [S1, S2].
*   **Limitations:** Relies on the capacity of the hash grid and MLP to capture complex view-dependent effects; may struggle with highly specular or complex lighting compared to high-degree SH [S1, S2].

## Background
Originated in "Compact 3D Gaussian Representation for Radiance Field" (CVPR 2024) [S1], motivated by the parameter inefficiency of storing 48 SH coefficients per Gaussian in standard 3DGS [S1]. It builds on the contraction function from mip-NeRF 360 [S1] and hash grid techniques from neural radiance fields [S1, S3]. Variants like HO-Gaussian apply this to urban scenes to handle lighting variations [S2].
