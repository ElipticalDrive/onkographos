# Optimization and Training


## Overview
Optimization and Training is the iterative procedure that adjusts the parameters of a collection of 3D Gaussian primitives to minimize the distortion between rendered views and ground-truth images [S2]. It solves the problem of reconstructing high-fidelity, view-dependent 3D scenes from 2D image collections without relying on neural network weights [S6]. It sets itself apart from its siblings by using adaptive density control to dynamically adjust the number of Gaussians during training, balancing reconstruction fidelity against computational cost [S2].

## How it works
**Inputs and outputs:** Input consists of an initial set of $N$ 3D Gaussian primitives, camera poses, and ground-truth images. Output is the optimized set of Gaussian parameters after convergence.

**Data structures:** Each Gaussian $i$ stores a mean position $\mu_i \in \mathbb{R}^3$, a covariance matrix $\Sigma_i \in \mathbb{R}^{3 \times 3}$ (parameterized by a rotation quaternion and a scale vector), color coefficients $c_i$ represented as spherical harmonics, and an opacity scalar $\alpha_i \in [0, 1]$ [S2]. The full collection is denoted $\mathbf{G}$ [S2].

**Numbered steps:**
1. Initialize Gaussians from a Structure-from-Motion (SfM) point cloud or uniformly sample them inside a bounding volume [S1].
2. Render 2D images by projecting the 3D Gaussians to screen space, sorting them by depth, and alpha-blending them in front-to-back order [S2].
3. Compute a distortion loss $D(\bx, \bhx)$ between the rendered image $\bhx$ and the ground-truth image $\bx$ using L1, multi-scale structural similarity, and LPIPS metrics [S2].
4. Backpropagate the pixel error through the differentiable rasterizer and 2D projection to compute gradients for every parameter of every Gaussian touching the pixel [S3, unofficial].
5. Update all parameters using the Adam optimizer, which adapts per-parameter step sizes based on recent gradients and uses different base learning rates for position, opacity, and color [S3, unofficial].
6. Apply adaptive densification: inspect view-space positional gradients to identify under-reconstructed regions (requiring cloning) and over-reconstructed regions (requiring splitting), and prune Gaussians with low opacity [S2].
7. Progressively introduce spherical harmonic bands to stabilize optimization: optimize only the zero-order component initially, then introduce one band every 1000 iterations until all 4 bands are active [S1].

**Formulas:**
The optimization minimizes:
$$\min_{\mathbf{G}} \gamma D(\bx, \bhx)$$
where $\mathbf{G}$ is the collection of Gaussian parameters, $D(\cdot)$ denotes the multi-scale structural similarity distortion computed on the rendered 2D image, and $\gamma$ is a scalar weighting factor [S2].

**Parameters:**
- $\gamma$: Scalar weighting factor for the distortion loss. It varies across datasets to align Gaussian counts across methods, as adaptive densification relies on gradient magnitude [S2].
- Warm-up resolution: 4$\times$ smaller than the target resolution to stabilize early optimization [S1].
- Warm-up upsampling: Occurs twice, after iteration 250 and iteration 500 [S1].
- SH band interval: 1000 iterations between introducing each new spherical harmonic band [S1].
- Gradient limit: The method allows an unlimited number of splats to receive gradients, unlike variants that limit this to $N=10$ points [S1].

**Edge cases and pitfalls:**
- Angular missing regions (e.g., corner captures or inside-out setups) cause completely incorrect zero-order SH components (base/diffuse color) [S1].
- Popping artifacts occur due to trivial guard-band culling in the rasterizer and simple visibility algorithms that cause sudden depth or blending order switches [S1].
- Unseen or poorly observed regions produce artifacts and elongated, "splotchy" Gaussians [S1].
- Limiting gradients to the $N=10$ front-most points causes unstable optimization and an 11 dB PSNR drop on benchmark scenes [S1].

**Pseudocode:**
```python
def optimize_gaussians(gaussians, cameras, gt_images, target_res, iterations=30000):
    optimizer = Adam(gaussians.parameters(), lr=base_lr)
    sh_band_count = 0
    
    for step in range(iterations):
        cam = random.choice(cameras)
        
        # Warm-up resolution schedule
        if step < 250:
            render_res = target_res // 4
        elif step < 500:
            render_res = target_res // 2
        else:
            render_res = target_res
            
        # Differentiable rendering
        rendered = render(gaussians, cam, render_res)
        
        # Loss computation
        loss = distortion_loss(rendered, gt_images[cam.id])
        
        # Optimization step
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        
        # Progressive SH band introduction
        if step > 0 and step % 1000 == 0:
            sh_band_count += 1
            gaussians.activate_sh_band(sh_band_count)
            
        # Adaptive densification (periodic)
        if step % densify_interval == 0:
            apply_adaptive_densification(gaussians, step)
            
    return gaussians
```

## Subtopics

### [3DGS Initialization Policy](1398-3dgs-initialization-policy.md)
Defines the protocol for seeding the initial set of $N$ 3D Gaussian primitives before optimization begins, ensuring a stable starting point for gradient-based training. It distinguishes itself from dynamic densification strategies by establishing the initial geometric and opacity distribution statically, often using a power-law scaling for opacity to match specific rendering assumptions. Choose it when a robust, reproducible starting configuration is required before iterative refinement.

### [Optical Flow Loss for 3D Gaussian Reconstruction](3303-optical-flow-loss-for-3d-gaussian-reconstruction.md)
Improves 3D shape reconstruction of static objects from video sequences by incorporating an optical flow loss term into the optimization objective. It leverages the temporal prior inherent in video data to resolve concavity/convexity ambiguities that are present when relying solely on silhouette and color loss terms. Choose it when reconstructing from user-captured video with long-term lighting changes or autoexposure variations.

### [3D Gaussian Splatting Training](3761-3d-gaussian-splatting-training.md)
The iterative optimization process that adjusts the parameters of a set of 3D Gaussian primitives to minimize the difference between rendered images and ground truth views. It solves the problem of reconstructing high-fidelity, view-dependent 3D scenes from sparse or dense 2D image collections without relying on neural network weights. It sets itself apart from its siblings by using adaptive density control (splitting, cloning, pruning) to dynamically adjust the number of Gaussians during training. Choose it as the standard baseline for static scene reconstruction.

### [Density Control and Densification](5337-density-control-and-densification.md)
A training-time mechanism for 3D Gaussian Splatting that dynamically adjusts the number, position, and scale of Gaussian primitives to match scene complexity. It solves the limitation of standard gradient descent, which can only move or scale existing Gaussians but cannot create new ones in empty regions or cleanly remove useless ones. Choose it when scene detail requires adaptive representation density beyond the initial initialization.

### [GauFRe](7994-gaufre.md)
A method for real-time dynamic novel view synthesis that represents dynamic scenes using deformable 3D Gaussian primitives. It solves the problem of reconstructing non-rigid motion from monocular video by employing a forward-warping deformation field, which explicitly models the temporal evolution of scene geometry. Choose it when handling dynamic scenes with explicit primitive-based rendering efficiency.

### [RadSplat](8059-radsplat.md)
A method for initializing 3D Gaussian Splatting representations by leveraging the robust geometric priors of a trained Neural Radiance Field (NeRF). It solves the problem of poor initialization quality and topological inconsistencies inherent in raw Structure-from-Motion point clouds. Choose it when bypassing extensive per-scene gradient descent loops for initialization is desired.

### [Differentiable Pose Estimation](12756-differentiable-pose-estimation.md)
Optimizes camera poses by backpropagating photometric loss gradients through a 3D Gaussian Splatting renderer. It solves the problem of recovering accurate camera extrinsics when initial poses are noisy or unknown, specifically enabling applications like motion deblurring. Choose it when batch optimization of poses for a static scene or trajectory is required.

### [SLAM and Tracking](22161-slam-and-tracking.md)
Handles simultaneous localization and mapping by incrementally tracking camera poses and updating the Gaussian representation in real time. It distinguishes itself from batch optimization methods by focusing on online, incremental reconstruction. Choose it for real-time mapping and tracking applications.

## Operating characteristics
**Time and memory complexity:** Training converges in 35–45 minutes on a single GPU, compared to 48 hours for Mip-NeRF360 [S1]. Rendering achieves 180–300 FPS on synthetic bounded scenes [S1]. Final models require 200–500K Gaussians per scene after 30K iterations [S1]. Model compactness reaches 3.8 MB, using approximately one-fourth of the point count of Zhang et al. [2022] while breaking even with their PSNR in 2–4 minutes [S1].

**Measured performance and scaling:** Evaluated on an NVIDIA A6000 GPU [S1]. The method scales efficiently due to stochastic gradient descent (random camera selection per step) and fast CUDA-based rasterization with NVIDIA CUB sorting routines [S1][S3, unofficial].

**Strengths and limitations:** Strengths include rapid convergence, real-time rendering speeds, and highly compact scene representations compared to explicit point-based or implicit neural methods [S1]. Limitations include artifacts in unobserved regions, popping artifacts from guard-band culling and depth-order switches, and the tendency to create elongated or "splotchy" Gaussians in poorly covered areas [S1].

**When to use it and when not:** Use it for high-fidelity, real-time novel view synthesis from image collections where training time and rendering speed are critical. Avoid it when capture geometry has severe angular gaps, as SH optimization will fail, or when strict memory caps require fixed primitive counts without adaptive densification.

## Background
The optimization and training procedure for 3D Gaussian Splatting was introduced alongside the original 3DGS method [S1]. It was implemented in Python using the PyTorch framework with custom CUDA kernels for rasterization and NVIDIA CUB sorting routines for fast Radix sort [S1]. An interactive viewer was built using the open-source SIBR framework for evaluation [S1]. The approach has since been extended to address initialization quality, frequency detail recovery, dynamic scene deformation, and text-to-3D generation pipelines [S4, unofficial][S5, S6].
