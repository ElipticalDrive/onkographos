# Rendering and Lighting Pipelines


## Overview
This family encompasses methods that extend the standard 3D Gaussian Splatting rasterization pipeline to support advanced rendering features such as order-independent transparency, explicit geometric primitives, volumetric lighting, inverse rendering, and physical relighting. While standard 3DGS renders opaque or simple transparent splats via front-to-back blending, these extensions introduce mechanisms for complex light transport, geometric fidelity, and material decomposition.

## Shared principles
All methods in this family share the core mechanism of projecting 3D primitives into 2D screen space and accumulating color based on depth order or spatial locality [G].

1. **Projection:** Primitives are transformed from world space to camera space [G]. The 3D covariance matrix $\Sigma$ is transformed using the view matrix $W$ and the Jacobian $J$ of the perspective projection approximation: $\Sigma_c = J W \Sigma W^T J^T$ [G]. The 2D covariance $\Sigma_{2D}$ is extracted as the upper-left $2\times2$ block [G].
2. **Rasterization:** Primitives are assigned to screen tiles [G]. Visibility is determined by bounding boxes or projected extents [G].
3. **Compositing:** Color is accumulated using front-to-back alpha blending or order-independent techniques [G]. The final intensity for a pixel is $I_f = \sum_{i=1}^N c_i \tilde{\sigma}_i \tilde{\mathcal{G}}_i(\mathbf{p}) \prod_{j=1}^{i-1} (1 - \tilde{\sigma}_j \tilde{\mathcal{G}}_j(\mathbf{p}))$, where $c_i$ is color, $\tilde{\sigma}_i$ is opacity or density, and $\tilde{\mathcal{G}}_i(\mathbf{p})$ is the 2D Gaussian value at pixel $\mathbf{p}$ [G].
4. **Sorting:** Most methods require sorting primitives by depth within tiles to ensure correct front-to-back compositing, although some variants use spatial hashing or cell-level sorting to approximate this or enable order-independent transparency [G].

## Subtopics

### [Duplex-GS](1988-duplex-gs.md)
Duplex-GS is a dual-hierarchy rendering framework for real-time order-independent Gaussian Splatting that combines alpha-blending with a reformulated Weighted-Sum Rendering (WSR) strategy. It solves the transparency artifacts and lack of early termination inherent in vanilla Order-Independent Transparency (OIT) methods, while reducing the sorting overhead of standard alpha-blending. Unlike Sort-free Gaussian Splatting which uses linear depth decay, Duplex-GS uses ellipsoidal cell proxies to establish a coarse spatial order, enabling physically grounded transmittance decay and early termination.

### [LinPrim Differentiable Rendering Pipeline](2195-linprim-differentiable-rendering-pipeline.md)
LinPrim is a differentiable rendering method that replaces the Gaussian primitives of 3D Gaussian Splatting with convex polyhedra, specifically octahedra, to enable explicit geometric representation. It solves the problem of approximating complex scene geometry by using bounded, triangular primitives that allow for exact ray-intersection calculations, thereby distributing gradients directly onto geometric features rather than kernel parameters. Unlike its sibling [3D Gaussian Splatting](3D-Gaussian-Splatting.md) which relies on soft Gaussian kernels, LinPrim uses hard-edged convex shapes, offering a trade-off between geometric fidelity and the complexity of intersection-based rasterization.

### [GsplatVolumeLighting](2203-gsplatvolumelighting.md)
GsplatVolumeLighting is a volume lighting and occlusion technique for 3D Gaussian Splatting that ray-marches through a 3D density texture to compute transmittance for shadow and volume occlusion, combined with per-light attenuation and diffuse shading. It extends the standard 3D Gaussian Splatting rendering pipeline by adding a secondary pass that evaluates volumetric shadows and ambient/direct lighting contributions for each splat, allowing splats to cast and receive shadows from volumetric objects. Unlike standard 3DGS which assumes unoccluded lighting or simple environment maps, this method integrates a 3D density field to modulate light transport, enabling realistic indoor or complex outdoor scenes where splats interact with volumetric geometry.

### [NeILF Rendering and Loss Calculation](2920-neilf-rendering-and-loss-calculation.md)
NeILF Rendering and Loss Calculation is a differentiable rendering pipeline that extends 3D Gaussian Splatting by decomposing features into diffuse, specular, and ambient components using a Blinn-Phong model. It enables inverse rendering by providing specific loss functions for depth, normals, and color sparsity, allowing for the optimization of lighting parameters and material properties alongside geometry. Unlike standard Gaussian Splatting which renders a single composite color, this method separates the rendering equation to facilitate physically-based constraints during training.

### [4DGS-Volume-Cloud Two-Stage Relighting](4101-4dgs-volume-cloud-two-stage-relighting.md)
This method enables real-time, dynamic relighting of volumetric clouds by decoupling physical geometry from environmental illumination using a two-stage training pipeline. Unlike standard Gaussian Splatting which learns appearance directly, this approach parameterizes Gaussians with physical participating medium properties (extinction, albedo, scattering) and uses a global environment network to compute sky inscattering, allowing arbitrary sun direction changes without retraining the geometry. It builds on [3D Gaussian Splatting](3D-Gaussian-Splatting.md) and [Rendering and Lighting Pipelines](4135-rendering-and-lighting-pipelines.md).

## Background
Originating from the 3D Gaussian Splatting framework [17], these pipelines address limitations in transparency handling, geometric representation, and lighting flexibility. Duplex-GS and LinPrim focus on rendering fidelity and differentiability, while GsplatVolumeLighting, NeILF, and 4DGS-Volume-Cloud extend the lighting model to support volumetric effects and physical relighting.
