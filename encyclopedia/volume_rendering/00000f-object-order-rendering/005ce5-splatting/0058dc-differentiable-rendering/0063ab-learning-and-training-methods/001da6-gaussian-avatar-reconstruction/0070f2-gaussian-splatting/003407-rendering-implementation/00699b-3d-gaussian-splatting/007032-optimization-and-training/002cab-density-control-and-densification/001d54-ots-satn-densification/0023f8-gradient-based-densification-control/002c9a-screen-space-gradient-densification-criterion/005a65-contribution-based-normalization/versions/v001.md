# Contribution-Based Normalization

Also called: Average Contribution Normalization

## Overview
Contribution-Based Normalization is a densification criterion for 3D Gaussian Splatting that normalizes the accumulated photometric gradient by the Gaussian's average rendering contribution across views, rather than the raw number of visible views [S1, unofficial]. Unlike the standard 3DGS approach, which divides by the view count $M$ (including occluded views where the Gaussian contributes zero), this method uses contribution-weighted visibility to prevent occluded primitives from artificially depressing the gradient score and stalling densification in complex scenes [S1, unofficial]. It builds on [Screen-Space Gradient Densification Criterion](5303-screen-space-gradient-densification-criterion.md) by refining how the gradient signal is scaled.

## How it works
**Inputs and Outputs:**
*   **Input:** For a specific Gaussian $i$, the accumulated gradient magnitude $\sum_v \|g_{i,v}\|$ and the sum of average blending weights $\sum_v \bar{w}_{i,v}$ across all training views $v$ in which the Gaussian is rendered.
*   **Output:** A scalar densification score $\gamma_i$. If $\gamma_i$ exceeds a fixed threshold, the Gaussian is split or cloned.

**Data Structures:**
*   `accumulated_gradient`: Scalar, sum of $\|g_{i,v}\|$ over all views $v$.
*   `accumulated_contribution`: Scalar, sum of $\bar{w}_{i,v}$ over all views $v$.
*   `N_i`: Integer, count of views where Gaussian $i$ is rendered (visible in frustum and not fully occluded).

**Steps:**
1.  Initialize `accumulated_gradient` = 0 and `accumulated_contribution` = 0.
2.  For each training view $v$:
    a. Render the Gaussian and compute the photometric loss gradient $g_{i,v}$ with respect to the projected 2D center.
    b. Compute the blending weight $w_{i,p}$ for each pixel $p$ covered by the Gaussian.
    c. Compute the average contribution $\bar{w}_{i,v}$ for view $v$. The source defines this as the mean of the blending weights over the pixels where the Gaussian is active. [S1, unofficial]
    d. Add $\|g_{i,v}\|$ to `accumulated_gradient`.
    e. Add $\bar{w}_{i,v}$ to `accumulated_contribution`.
3.  Compute the score $\gamma_i$ using the formula below.
4.  Compare $\gamma_i$ to the threshold.

**Formula:**
$$
\gamma_i = \frac{\sum_v \|g_{i,v}\|}{1 + \sum_v \bar{w}_{i,v}}
$$

Where:
*   $\|g_{i,v}\|$ is the magnitude of the gradient of the photometric loss w.r.t. the projected 2D screen-space center of the Gaussian in view $v$.
*   $\bar{w}_{i,v}$ is the average blending weight of Gaussian $i$ in view $v$.
*   The denominator includes a smoothing constant $1$ to prevent division by zero. [S1, unofficial]

**Parameters:**
*   Threshold: A fixed value (e.g., 0.0003 in cited experiments) [S1, unofficial].
*   Smoothing constant: 1.

**Edge Cases and Pitfalls:**
*   **Occlusion:** If a Gaussian is occluded in a view, it contributes 0 to the weight sum but also 0 to the gradient sum. Standard normalization by view count $M$ would divide by $M$, penalizing the Gaussian for being occluded. This method only divides by the sum of actual contributions, ignoring occluded views in the denominator's scale. [S1, unofficial]
*   **Precision:** Ensure $\bar{w}_{i,v}$ is computed correctly as an average over pixels, not a sum, to match the derivation in the source. [S1, unofficial]

**Pseudocode:**
```python
def compute_contribution_normalization_score(gaussian_i, training_views):
    """
    Computes the contribution-based normalization score for a Gaussian.
    
    Args:
        gaussian_i: The Gaussian primitive being evaluated.
        training_views: List of training camera views.
        
    Returns:
        gamma_i: The densification score.
    """
    accumulated_gradient = 0.0
    accumulated_contribution = 0.0
    
    for view in training_views:
        # Render Gaussian and compute gradient w.r.t. 2D center
        # This step assumes access to the differentiable renderer
        gradient_vector = compute_gradient_wrt_2d_center(gaussian_i, view)
        gradient_magnitude = norm(gradient_vector)
        
        # Compute blending weights for all pixels covered by the Gaussian
        # w_i_p is the weight of Gaussian i at pixel p in this view
        weights = compute_blending_weights(gaussian_i, view)
        
        # Average contribution is the mean of weights over active pixels
        if len(weights) > 0:
            avg_weight = sum(weights) / len(weights)
        else:
            avg_weight = 0.0
            
        accumulated_gradient += gradient_magnitude
        accumulated_contribution += avg_weight
        
    # Formula: Gradient Sum / (1 + Contribution Sum)
    gamma_i = accumulated_gradient / (1.0 + accumulated_contribution)
    
    return gamma_i
```

## Subtopics

### Per-view Normalizer
A variant that divides both the gradient sum and the weight sum by the number of rendered views $N_i$ before combining them [S1, unofficial].
**Formula:**
$$
\gamma_i^{\text{per-view}} = \frac{\sum_v \|g_{i,v}\|/N_i}{1 + \sum_v \bar{w}_{i,v}/N_i}
$$
**Comparison:** Produces reconstruction quality similar to the baseline contribution normalizer but requires approximately 1.4× more Gaussians to reach the same operating point, indicating lower efficiency [S1, unofficial].

### Sum-alloc Normalizer
A variant that replaces the per-view mean weight $\bar{w}_{i,v}$ with the per-view total weight $W_{i,v} = \sum_p w_{i,p}$ in the denominator [S1, unofficial].
**Formula:**
$$
\gamma_i^{\text{sum-alloc}} = \frac{\sum_v \|g_{i,v}\|}{1 + \sum_v W_{i,v}}
$$
**Comparison:** Places the denominator on a different scale than the baseline, requiring a separate threshold sweep for calibration. It is less natural than the average contribution because it scales with pixel count rather than normalized visibility [S1, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
*   Requires tracking two additional accumulators per Gaussian per view (gradient magnitude and average weight).
*   No significant change in asymptotic complexity compared to standard 3DGS densification, but slightly higher constant factor due to weight averaging.

**Measured Performance:**
*   On occlusion-heavy scenes (Zip-NeRF), it outperforms the baseline StopThePop method on all image-quality metrics, reducing LPIPS by up to 12% [S1, unofficial].
*   Gaussian count remains bounded under extended training schedules (e.g., 100k iterations), whereas other criteria (like PixelGS) may diverge and reach millions of Gaussians (e.g., 7.4M) [S1, unofficial].

**Strengths and Limitations:**
*   **Strength:** Robust to occlusion; prevents stalling of densification in occluded regions.
*   **Limitation:** Requires accurate computation of average blending weights, which may be sensitive to rasterization artifacts if not handled carefully.

**When to Use:**
*   Use in scenes with significant self-occlusion or complex geometry where standard view-count normalization fails to densify occluded areas.
*   Avoid if computational budget is extremely tight and occlusion is minimal, as the baseline may suffice.

## Background
Originated in the paper "Counting Contributions, Not Views: Occlusion-Aware Densification for 3D Gaussian Splatting" [S1, unofficial]. The method addresses a flaw in 3DGS where normalizing by view count penalizes Gaussians that are frequently occluded, even if they have high gradient signals when visible. It consolidates improvements from prior methods like StopThePop and GOF into a stronger baseline for occlusion-aware training.
