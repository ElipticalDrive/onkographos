# 3D Gaussian Splatting Training Loop

Also called: Render-Compare-Correct Loop

## Overview
The 3D Gaussian Splatting (3DGS) training loop is an iterative optimization process that minimizes the photometric error between rendered images and ground-truth input photos by adjusting the parameters of a set of 3D Gaussians [S2, unofficial][S1]. It differs from sibling methods like [TurboGS](15697-turbogs.md) or [Distributed 3DGS Training Loop](18650-distributed-3dgs-training-loop-with-adaptive-workload-divisi.md) by relying on the standard stochastic gradient descent with a fixed iteration budget and explicit densification/pruning heuristics, rather than adaptive workload division or accelerated rendering pipelines [S2, unofficial][S1].

## How it works
The loop operates on a per-image basis, randomly sampling training views to prevent overfitting to camera order [S2, unofficial].

**Inputs:**
- Set of training images $\{I_k\}$ with known camera poses $\{C_k\}$ recovered by Structure-from-Motion (SfM) [S2, unofficial].
- Initial set of Gaussians $\mathcal{G} = \{g_i\}_{i=1}^N$. For standard scenes, this is often a sparse point cloud; for avatars, it may be initialized using SMPL vertex positions and skinning weights [S1].

**Outputs:**
- Optimized Gaussian parameters $\mathcal{G}$ (positions, covariances, opacities, SH coefficients) and any auxiliary parameters (e.g., MLP weights for avatar deformation) [S1].

**Data Structures:**
- Gaussian $g_i$ contains:
  - Position $\mathbf{p}_i \in \mathbb{R}^3$
  - Covariance $\Sigma_i$, parameterized by rotation quaternion $\mathbf{q}_i \in \mathbb{R}^4$ and scale vector $\mathbf{s}_i \in \mathbb{R}^3$ [S2, unofficial].
  - Opacity $\alpha_i \in [0, 1]$
  - Spherical Harmonics (SH) coefficients $\mathbf{c}_{i, l}$ for view-dependent color [S2, unofficial].

**Numbered Steps:**
1. **Sample View:** Randomly select one training image $I_{gt}$ and its corresponding camera pose $C$ from the dataset [S2, unofficial].
2. **Transform:** Transform canonical Gaussians to the observation space defined by $C$. If using avatar models, apply deformation (e.g., via SMPL skinning) to positions and orientations [S1].
3. **Render:** Use the differentiable Gaussian rasterizer to render the image $\hat{I}$ from the current Gaussian set $\mathcal{G}$ and pose $C$ [S1].
4. **Compare:** Compute the per-image loss $\mathcal{L}_{img}$ by comparing $\hat{I}$ and $I_{gt}$ pixel-by-pixel [S2, unofficial].
5. **Correct:** Compute gradients $\nabla_{\mathcal{G}} \mathcal{L}_{img}$ and update Gaussian parameters using the Adam optimizer [S1][S2, unofficial].
6. **Densify/Prune:** Periodically (e.g., every $N$ iterations), apply densification heuristics (splitting/cloning Gaussians based on gradient magnitude or screen-space size) and pruning (removing low-opacity Gaussians) to adapt the representation density [S1].
7. **Repeat:** Continue until the fixed iteration budget is reached [S2, unofficial].

**Loss Function:**
The total loss is a weighted sum of L1 loss and differentiable Structural Similarity (D-SSIM) [S2, unofficial][S1]:
$$ \mathcal{L}_{img} = (1 - \lambda) \mathcal{L}_{L1} + \lambda \mathcal{L}_{D-SSIM} $$
where $\lambda \approx 0.2$ [S2, unofficial][S1]. $\mathcal{L}_{L1}$ is the average absolute difference between pixel colors. $\mathcal{L}_{D-SSIM}$ measures local structure, contrast, and texture [S2, unofficial]. For avatar reconstruction, additional regularization losses (e.g., perceptual LPIPS) may be added [S1].

**Parameters:**
- Optimizer: Adam with $\beta_1 = 0.9$, $\beta_2 = 0.99$ [S1][S2, unofficial].
- Iteration Budget: Typically 30,000 iterations for standard scenes [S2, unofficial]. Specific schedules may vary (e.g., ~6,000 for primitive training) [S2, unofficial].
- Stopping Criterion: Fixed iteration count, not a loss threshold, as the loss curve creeps down with diminishing returns [S2, unofficial].

**Pseudocode:**
```python
def train_3dgs(training_images, initial_gaussians, num_iterations=30000):
    # Initialize optimizer with Adam (beta1=0.9, beta2=0.99)
    optimizer = Adam(initial_gaussians.parameters(), lr=1e-4)
    
    for iteration in range(num_iterations):
        # 1. Sample a random training view
        idx = random_choice(len(training_images))
        gt_image, camera_pose = training_images[idx]
        
        # 2. Transform Gaussians to observation space
        # For avatars: apply deformation based on body pose if available
        transformed_gaussians = transform_gaussians(initial_gaussians, camera_pose)
        
        # 3. Render the image
        rendered_image = gaussian_rasterize(transformed_gaussians, camera_pose)
        
        # 4. Compute Loss
        # L1 Loss
        l1_loss = mean_absolute_error(rendered_image, gt_image)
        # D-SSIM Loss
        dssim_loss = compute_dssim(rendered_image, gt_image)
        # Combined Loss (lambda = 0.2)
        loss = 0.8 * l1_loss + 0.2 * dssim_loss
        
        # Optional: Add regularization losses (e.g., LPIPS for avatars)
        # loss += lambda_lpips * compute_lpips(rendered_image, gt_image)
        
        # 5. Backpropagate and Update
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        
        # 6. Densify and Prune (every N iterations)
        if iteration % densify_interval == 0:
            initial_gaussians = densify_and_prune(initial_gaussians, gt_image, camera_pose)
            
    return initial_gaussians
```

**Edge Cases and Pitfalls:**
- **Precision:** Gradient computation relies on the differentiability of the rasterizer; numerical instability can occur with extremely small or large covariances [G].
- **Boundaries:** Background pixels should be handled explicitly (e.g., setting background to black in ground truth) to avoid artifacts [S1].
- **Degenerate Input:** If SfM poses are inaccurate, rendering will fail to align with ground truth, leading to poor convergence [S2, unofficial].

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of Gaussians $N$ and the number of pixels $P$ per iteration ($O(N \cdot P)$) [G]. Total time scales with the iteration budget (typically 30,000) [S2, unofficial].
- **Memory Complexity:** $O(N)$ to store Gaussian parameters and gradients [G].
- **Performance:** Training time varies by hardware but is generally faster than neural radiance field (NeRF) training due to the explicit representation and fast rasterization [S2, unofficial].
- **Strengths:** Simultaneous correction of millions of parameters via gradient descent, avoiding the inefficiency of random search [S2, unofficial].
- **Limitations:** Fixed iteration budget may lead to overfitting or underfitting if not tuned for the scene; densification heuristics can introduce artifacts if not carefully controlled [S1][S2, unofficial].

## Background
The 3D Gaussian Splatting training loop was introduced in the original 3DGS paper [S1] and popularized by subsequent implementations and tutorials [S2, unofficial]. It builds on the differentiable rendering framework established by 3DGS, enabling end-to-end optimization of explicit 3D primitives. The method has been adapted for various domains, including animatable avatars (Human Gaussian Splatting) [S1] and large-scale scenes.
