# Parallel Grid Sorting Algorithm

Also called: 3DGS densification sorting, self-organizing grid sorting

## Overview
The Parallel Grid Sorting Algorithm is a post-densification optimization step that reorders 3D Gaussian primitives into 2D attribute grids to maximize spatial locality and compressibility [S1]. Unlike sibling methods that focus on geometric refinement or probabilistic sampling, this method specifically targets the data layout for efficient storage and transmission by minimizing the variance of absolute differences between neighboring grid elements [S1]. It is distinct from standard rasterization sorting as it operates on the entire attribute set (position, color, opacity, scale, rotation) simultaneously to prepare the data for subsequent compression codecs [S1].

## How it works
The algorithm executes after every densification step (e.g., every 100 iterations) to reorder the set of $N$ Gaussians $\mathcal{G}$ into a 2D grid structure $\mathcal{G}_{grid}$ [S1].

**Inputs and Outputs:**
*   **Input:** A set of $N$ 3D Gaussians $\mathcal{G} = \{g_1, \dots, g_N\}$, where each $g_k$ has attributes: mean position $\mu_k \in \mathbb{R}^3$, opacity $\alpha_k \in \mathbb{R}$, scaling $s_k \in \mathbb{R}^3$, rotation $q_k \in \mathbb{R}^4$, and spherical harmonic coefficients $\mathbf{c}_k$.
*   **Output:** A 2D grid of dimensions $W \times H$ (where $W \times H \ge N$) containing the reordered Gaussians, such that spatially and attribute-similar Gaussians are adjacent in the grid [S1].

**Data Structures:**
The algorithm maintains separate 2D grids for each attribute channel. For a grid of side length $L$, the layout is a contiguous array of size $L \times L \times C$, where $C$ is the number of channels (e.g., 3 for position RGB, 1 for opacity, etc.) [S1]. The grid is initialized with the current Gaussian positions.

**Parameters:**
*   **Break Threshold ($\tau$):** A relative L2 reduction threshold controlling convergence. Default: $10^{-4}$ [S1].
*   **Sorting Weights ($w$):** A vector of multipliers for each attribute type (position, color/SH DC, opacity, scaling, rotation) to guide sorting priority. Position, color, and scale typically have higher weights as they impact PSNR more significantly [S1].

**Algorithm Steps:**
1.  **Initialization:** Map the $N$ Gaussians to a 2D grid of size $L \times L$ (where $L = \lceil \sqrt{N} \rceil$). Initialize the grid with the current Gaussian attributes.
2.  **Iteration Loop:**
    a.  **Compute Current Cost:** Calculate the total L2 distance cost $E_{curr}$ of the current grid configuration. The cost is defined as the sum of squared differences between neighboring grid cells, weighted by the sorting weights $w$.
    b.  **Generate Permutation:** Apply a parallel sorting heuristic (e.g., row/column swaps, block moves) to generate a candidate permutation of the grid indices. The heuristic prioritizes moves that reduce the weighted L2 distance [S1].
    c.  **Evaluate Candidate:** Compute the cost $E_{next}$ for the permuted grid.
    d.  **Update:** If $E_{next} < E_{curr}$, accept the permutation and update the grid. Otherwise, reject it.
    e.  **Convergence Check:** Compute the relative reduction in L2 distance: $\Delta = \frac{|E_{curr} - E_{next}|}{E_{curr}}$. If $\Delta < \tau$, stop sorting for the current configuration. If not, continue to the next permutation or level [S1].
3.  **Finalization:** Once convergence is reached or the maximum iterations are exceeded, the grid is finalized for compression.

**Pseudocode:**
```python
def parallel_grid_sorting(gaussians, weights, threshold=1e-4, max_iterations=10000):
    """
    Reorders 3D Gaussians into a 2D grid for compression.
    
    Args:
        gaussians: List of Gaussian objects with attributes (pos, color, opacity, scale, rot).
        weights: Dict mapping attribute names to sorting weights.
        threshold: Relative L2 reduction threshold for convergence.
        max_iterations: Maximum number of sorting iterations.
        
    Returns:
        grid: 2D array of Gaussians, reordered.
    """
    N = len(gaussians)
    L = int(ceil(sqrt(N)))
    # Initialize grid with current Gaussians, padding with None if N < L*L
    grid = initialize_grid(gaussians, L)
    
    current_cost = compute_weighted_l2_cost(grid, weights)
    
    for iteration in range(max_iterations):
        # Generate a candidate permutation using parallel heuristics
        # This involves swapping rows, columns, or blocks to improve locality
        candidate_grid = apply_parallel_heuristic(grid, weights)
        
        next_cost = compute_weighted_l2_cost(candidate_grid, weights)
        
        # Check for improvement
        if next_cost < current_cost:
            # Accept the move
            relative_reduction = abs(current_cost - next_cost) / current_cost
            
            if relative_reduction < threshold:
                # Convergence reached
                break
            
            grid = candidate_grid
            current_cost = next_cost
        else:
            # No improvement, try different heuristic or break if stuck
            # In practice, multiple heuristics are tried per iteration
            pass
            
    return grid

def compute_weighted_l2_cost(grid, weights):
    """
    Computes the sum of squared differences between neighboring cells,
    weighted by attribute importance.
    """
    total_cost = 0.0
    L = grid.shape[0]
    
    # Iterate over all cells and their neighbors (right and down to avoid double counting)
    for y in range(L):
        for x in range(L):
            current_g = grid[y, x]
            if current_g is None: continue
            
            # Right neighbor
            if x + 1 < L:
                right_g = grid[y, x + 1]
                if right_g is not None:
                    total_cost += compute_attribute_diff(current_g, right_g, weights)
            
            # Down neighbor
            if y + 1 < L:
                down_g = grid[y + 1, x]
                if down_g is not None:
                    total_cost += compute_attribute_diff(current_g, down_g, weights)
                    
    return total_cost

def compute_attribute_diff(g1, g2, weights):
    """
    Computes weighted L2 distance between two Gaussians' attributes.
    """
    diff = 0.0
    # Position (3 channels)
    diff += weights['position'] * np.sum((g1.pos - g2.pos)**2)
    # Color/SH DC (3 channels)
    diff += weights['color'] * np.sum((g1.color - g2.color)**2)
    # Opacity (1 channel)
    diff += weights['opacity'] * (g1.opacity - g2.opacity)**2
    # Scale (3 channels)
    diff += weights['scale'] * np.sum((g1.scale - g2.scale)**2)
    # Rotation (4 channels, quaternion)
    diff += weights['rotation'] * np.sum((g1.rot - g2.rot)**2)
    return diff
```

**Edge Cases and Pitfalls:**
*   **Grid Size:** The grid side length $L$ must be sufficient to hold all Gaussians. For the largest tested scene (Garden), $N=4.37M$ requires $L=2091$ [S1].
*   **Smoothing Regularization:** Applying sorting and compression only after vanilla 3DGS training (without smoothing regularization) drastically reduces visual quality [S1]. The smoothing regularization influences the training process to make attributes more amenable to sorting [S1].
*   **Convergence:** The break threshold $\tau$ controls the trade-off between sorting quality and runtime. A lower $\tau$ yields better compression but increases runtime [S1].

## Operating characteristics
*   **Time Complexity:** The algorithm is iterative and depends on the number of Gaussians $N$ and the grid size $L \approx \sqrt{N}$. Each iteration involves computing the cost $O(N)$ and applying heuristics. The total runtime depends on the convergence speed, which is influenced by $\tau$ [S1].
*   **Memory Complexity:** $O(N)$ to store the grid and attributes. The grid is $L \times L \times C$, where $C$ is the number of attribute channels [S1].
*   **Measured Performance:**
    *   On an Nvidia RTX 4090, sorting a random $512 \times 512 \times 3$ grid takes 5.7 seconds after 8015 reorders, achieving a Variance of Absolute Differences (VAD) of 4.02 [S1].
    *   On an AMD Ryzen Threadripper PRO 5955WX CPU, the FLAS algorithm takes 131 seconds for the same grid, achieving a VAD of 3.53 [S1].
    *   The largest tested scene (Garden, 4.37M Gaussians, $L=2091$) sorts in well below one minute [S1].
*   **Strengths:** High parallelism leads to significantly reduced runtime compared to CPU-based state-of-the-art methods like FLAS, while maintaining comparable sorting quality (VAD 4.02 vs 3.53) [S1].
*   **Limitations:** Requires smoothing regularization during training to maintain visual quality; otherwise, compression degrades rendering [S1].

## Background
The Parallel Grid Sorting Algorithm was introduced in the context of compact 3D scene representation via self-organizing Gaussian grids [S1]. It addresses the need for efficient storage and transmission of 3D Gaussian Splatting models by leveraging spatial locality in attribute space. The method builds on the observation that sorting Gaussians based on their attributes (position, color, scale, etc.) can significantly improve compression ratios [S1].
