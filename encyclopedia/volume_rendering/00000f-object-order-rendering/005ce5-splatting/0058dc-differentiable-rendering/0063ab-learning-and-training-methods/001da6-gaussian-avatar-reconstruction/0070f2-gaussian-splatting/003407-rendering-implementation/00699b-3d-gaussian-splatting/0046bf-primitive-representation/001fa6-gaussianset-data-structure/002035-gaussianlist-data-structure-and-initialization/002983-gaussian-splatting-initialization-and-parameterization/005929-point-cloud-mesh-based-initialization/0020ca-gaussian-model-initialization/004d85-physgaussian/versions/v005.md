# PhysGaussian

Also called: 3D Gaussian MPM Simulation, MPM over Gaussians

## Overview
PhysGaussian is a physical simulation pipeline that treats reconstructed 3D Gaussian primitives as Material Point Method (MPM) particles to model the deformation and motion of soft tissue structures [S1]. It couples 3D Gaussian Splatting (3DGS) with continuum mechanics, allowing a single representation to serve for both high-fidelity rendering and physics-based simulation of dynamics such as deformation, fracture, and fluid-like behavior [S2, S3, unofficial]. Unlike standard 3DGS which relies on geometric deformation or linear transformations, PhysGaussian assigns physical properties to each Gaussian, enabling the simulation of materials like cloth, jelly, sand, and snow within a unified framework [S3, unofficial].

## How it works
PhysGaussian integrates the static 3D Gaussian representation with a continuum mechanics solver. The method proceeds by initializing Gaussians from a reconstruction, mapping them to MPM particles, and evolving their state through physical simulation steps.

### Inputs and Outputs
**Inputs:**
*   A set of static 3D Gaussians $\mathcal{G} = \{g_i\}_{i=1}^N$ reconstructed from sparse-view projections (e.g., CT data) [S1].
*   Material parameters: Young's modulus ($E$), Poisson's ratio ($\nu$), and density ($\rho$) [S1].
*   Simulation environment settings (e.g., gravity, boundary conditions) [S1].

**Outputs:**
*   Deformed 3D Gaussian parameters (position, covariance, opacity) suitable for differentiable rendering [S1].
*   Visualizations of deformation and motion [S1].

### Data Structures
The core data structure is the Gaussian, which is augmented with physical state variables required by the MPM solver. Each Gaussian $g_i$ stores:
1.  **Geometric State:** Position $\mathbf{x}_i$, covariance matrix $\mathbf{\Sigma}_i$ (or rotation/scale), opacity $\alpha_i$, and spherical harmonics coefficients for color [S1][S2, unofficial].
2.  **Physical State:** Mass $m_i$, velocity $\mathbf{v}_i$, and deformation gradient $\mathbf{F}_i$ [S1][S3, unofficial].

The Gaussians are treated as particles in the MPM grid. The particle distribution is voxelized to compute macroscopic motion and deformation fields [S1].

### Parameters
Typical values for a simplified "jelly" material model mimicking soft tissue are:
*   Young's modulus ($E$): $2 \times 10^6$ [S1].
*   Poisson's ratio ($\nu$): $0.4$ [S1].
*   Density ($\rho$): $200$ [S1].

### Steps
1.  **Reconstruction:** Reconstruct the target object (e.g., a coronary artery) from sparse-view projections to obtain a static set of 3D Gaussians [S1].
2.  **Particle Initialization:** Treat each Gaussian $g_i$ as an MPM particle. Initialize physical properties:
    *   Assign mass $m_i$ based on the Gaussian's volume and density $\rho$ [S1][S3, unofficial].
    *   Initialize velocity $\mathbf{v}_i = \mathbf{0}$ and deformation gradient $\mathbf{F}_i = \mathbf{I}$ (identity) [S1][S3, unofficial].
3.  **Voxelization:** Map the particle positions to a background grid for the MPM solver. This allows the computation of overall motion and deformation fields [S1].
4.  **Force Application:** Apply external forces. In demonstrations, a transient impulsive force is applied in a zero-gravity environment to isolate the force effects [S1].
5.  **Simulation Step:** Run the MPM simulation loop:
    *   Transfer particle momentum and position to the grid.
    *   Solve the grid equations using the constitutive model (e.g., neo-Hookean for soft tissue) [S1][S3, unofficial].
    *   Transfer updated grid velocities back to particles.
    *   Update particle positions and deformation gradients [S1][S3, unofficial].
6.  **Rendering:** Use the updated Gaussian parameters (positions and covariances derived from deformation) to render the scene using standard 3DGS rasterization [S1][S3, unofficial].

### Pseudocode
```python
def phys_gaussian_simulation(gaussians, material_params, num_frames):
    """
    Simulate deformation of 3D Gaussians using MPM.
    
    Args:
        gaussians: List of Gaussian objects with pos, cov, opacity, etc.
        material_params: Dict with 'E' (Young's modulus), 'nu' (Poisson's ratio), 'rho' (density).
        num_frames: Number of simulation steps.
    """
    # 1. Initialize Physical State
    for g in gaussians:
        # Estimate volume from covariance determinant
        volume = sqrt(det(g.cov))
        g.mass = material_params['rho'] * volume
        g.velocity = Vector3(0, 0, 0)
        g.deformation_gradient = Matrix3.identity()
        
    # 2. Setup MPM Grid
    grid = MPMGrid(gaussians)
    
    # 3. Simulation Loop
    for frame in range(num_frames):
        # Apply external forces (e.g., transient impulse)
        apply_external_forces(gaussians, frame)
        
        # MPM Step: Particle-to-Grid
        grid.transfer_particles_to_grid(gaussians)
        
        # MPM Step: Grid Solve
        # Solve momentum equation with constitutive model (e.g., Neo-Hookean)
        grid.solve(material_params)
        
        # MPM Step: Grid-to-Particle
        gaussians = grid.transfer_grid_to_particles(gaussians)
        
        # Update Gaussian Geometry from Particle State
        for g in gaussians:
            # Update position
            g.pos += g.velocity * dt
            
            # Update covariance based on deformation gradient F
            # Sigma_new = F * Sigma_old * F^T
            g.cov = g.deformation_gradient @ g.cov @ g.deformation_gradient.transpose()
            
            # Normalize covariance to maintain stability if needed [G]
            
    return gaussians
```

### Edge Cases and Pitfalls
*   **Precision:** The simulation requires consistent units for mass, density, and modulus to avoid numerical instability in the MPM solver [S1].
*   **Boundaries:** Zero-gravity environments are used in demonstrations to isolate force effects; gravity must be explicitly handled if added [S1].
*   **Degenerate Input:** The method assumes a valid initial reconstruction. Poor reconstruction quality (e.g., missing regions) will lead to inaccurate physical behavior [S1].

## Subtopics

### [GASP](16066-gasp.md)
GASP is a pipeline that integrates 3D Gaussian Splatting with black-box physics engines by converting flat Gaussian components into triangle faces, simulating the vertices using the Material Point Method (MPM), and reconstructing Gaussians from the deformed triangles. It solves the problem of simulating deformable objects in Gaussian representations without requiring modifications to the physics engine or complex mesh extraction strategies like marching cubes. Unlike PhysGaussian, which approximates deformation via first-order linear transformations and requires adjustments to the physics engine, GASP operates directly on the geometry of flat Gaussians using the GaMeS parameterization, ensuring stable simulations and avoiding artifacts associated with treating points as discrete entities.

### [MPM Simulation Framework](18583-mpm-simulation-framework.md)
The MPM Simulation Framework is a physics-based simulation method used within the PhysGaussian pipeline to model the large-deformation behavior of materials such as cloth, jelly, sand, and snow. It serves as the physical prior for soft-body control, allowing shape changes to be computed via physical simulation rather than purely geometric deformation . It is distinguished from its siblings, such as [GASP](16066-gasp.md), by its support for a wide variety of constitutive and plasticity models within a unified continuum mechanics framework.

## Operating characteristics
*   **Time Complexity:** The simulation cost scales with the number of particles (Gaussians) and the grid resolution. Performance on an RTX 3090 GPU with >50,000 particles over 100 frames is approximately 250 ms per frame [S1].
*   **Memory Complexity:** Peak GPU memory usage is reported at 18 GB for the aforementioned configuration [S1].
*   **Strengths:** Provides a single representation for both rendering and simulation, enabling real-time visualization of physical dynamics [S3, unofficial]. Suitable for clinical applications like surgical planning and stent deployment prediction [S1].
*   **Limitations:** Requires a pre-reconstructed 3D Gaussian model. The physical simulation adds computational overhead compared to static rendering. The simplified material models may not capture all complex tissue behaviors accurately [S1].
*   **When to use:** When physical interaction and deformation of soft tissues or materials need to be visualized alongside high-fidelity rendering, particularly in medical or robotics simulation contexts [S1][S3, unofficial].
*   **When not to use:** For static scene rendering where physics is irrelevant, or for scenes with extremely high particle counts where the 250 ms/frame performance becomes a bottleneck.

## Background
PhysGaussian was introduced in CVPR'24 [S3, unofficial]. It builds upon the 3D Gaussian Splatting framework by integrating the Material Point Method (MPM), a continuum mechanics technique widely used for simulating large deformations in materials like sand, snow, and soft tissues [S1][S3, unofficial]. The method was developed to address the need for physically plausible simulations in computer graphics and medical imaging, allowing for applications such as surgical planning, stent deployment prediction, and catheterization vessel compression analysis [S1].
