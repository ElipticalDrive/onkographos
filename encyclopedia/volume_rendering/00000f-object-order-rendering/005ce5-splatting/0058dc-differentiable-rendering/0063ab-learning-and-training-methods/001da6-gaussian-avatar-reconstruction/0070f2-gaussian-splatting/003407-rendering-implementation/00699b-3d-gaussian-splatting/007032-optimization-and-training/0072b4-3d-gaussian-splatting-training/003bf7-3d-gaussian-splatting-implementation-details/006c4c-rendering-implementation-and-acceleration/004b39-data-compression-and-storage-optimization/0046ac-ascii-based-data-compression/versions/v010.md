# ASCII-Based Data Compression
Also called: Anywhere Compression, Base 94 Floating-Point Compression, Base 95 Integer Compression

## Overview
This method reduces the bit-width of scene parameters during 3D Gaussian Splatting training by encoding numerical values as ASCII characters, thereby improving data transmission speed over network or inter-process boundaries [S1, unofficial]. It distinguishes itself from sibling methods like [Sensitivity-Aware Vector Clustering](12167-sensitivity-aware-vector-clustering.md) and [Compact 3D Gaussian Representation (C3DGS)](12927-compact-3d-gaussian-representation-c3dgs.md) by focusing on transmission efficiency via character-based encoding rather than geometric simplification or vector quantization.

## How it works
**Inputs and Outputs:**
- Input: Numerical scene parameters (integers, floating-point numbers, and color matrix values) to be transmitted.
- Output: ASCII strings representing the compressed parameters.

**Data Structures:**
- **Integer Encoding Map:** A mapping of integers $[0, 95]$ to ASCII characters in the range `chr(32)` to `chr(126)`.
- **Floating-Point Encoding Map:** A mapping of integer components $[0, 94]$ to ASCII characters in the range `chr(32)` to `chr(125)`. The character `chr(126)` serves as a delimiter between the integer and fractional parts.
- **Color Matrix Optimization:** Each color value is restricted to one decimal place within the range $[0.0, 2.0]$, resulting in 21 discrete alternative values.

**Steps:**

1.  **Integer Compression:**
    For an integer $n$ where $0 \le n \le 95$:
    - Map $n$ to the corresponding ASCII character $c$ using the range `chr(32)` to `chr(126)`.
    - Output the string containing $c$.

2.  **Floating-Point Compression:**
    For a floating-point number $f$:
    - Extract the integer part $I$ and the fractional part.
    - Map $I$ (where $0 \le I \le 94$) to an ASCII character $c_I$ using the range `chr(32)` to `chr(125)`.
    - Determine the number of decimal places $d$ required for the fractional part.
    - Concatenate $c_I$, the delimiter `chr(126)`, and the string representation of $d$.
    - Output the resulting ASCII string.

3.  **Color Matrix Optimization:**
    - Round each color matrix item to one decimal place, restricting values to the range $[0.0, 2.0]$.
    - This reduces the possible values to 21 distinct options per item.
    - Apply ASCII compression to these rounded values to reduce data size significantly.

4.  **Decoding Integer:**
    - Convert the ASCII string directly back to the decimal integer number using the inverse mapping of Step 1.

5.  **Decoding Floating-Point:**
    - Split the ASCII string into two parts: the integer part $I$ (decoded from the first character) and the decimal places $d$ (decoded from the part after the delimiter).
    - Calculate the final floating-point value $f$ using the formula:
      $$ f = I \times 10^{-d} $$

**Parameters:**
- Integer base: 95.
- Floating-point integer component base: 94.
- Color precision: 1 decimal place.
- Color range: $[0.0, 2.0]$.

**Edge Cases and Pitfalls:**
- **Color Matrix Traversal:** Compressing the entire color matrix into ASCII strings is computationally expensive due to the time required for matrix traversal. Using internal functions like `torch.where` and `torch.index_select` can replace explicit loops but may still not be fast enough for full replacement [S1, unofficial].
- **Line Break Characters:** Using line break characters in ASCII strings adds an extra operator during writing and decoding, which should be avoided [S1, unofficial].
- **Performance Gain:** The method provides approximately 6% or less improvement in training speed [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Encoding and decoding are linear with respect to the number of parameters. However, matrix traversal for color compression is a bottleneck, potentially negating transmission gains if not optimized [S1, unofficial].
- **Memory Complexity:** Reduces the number of bits required to represent parameters, leading to smaller data payloads during transmission.
- **Performance:** Gains about 6% or less in training speed [S1, unofficial].
- **Strengths:** Simple implementation; effective for reducing transmission overhead for integers and small-range floats.
- **Limitations:** Limited applicability to color matrices due to traversal costs; minimal overall speedup; not suitable for high-precision requirements beyond one decimal place for colors.

## Background
This method was introduced in the context of improving the training speed of 3D Gaussian Splatting models. It is part of a broader effort to optimize various dimensions of the model, including compression, to enhance scientific and practical references for related research [S1, unofficial].
