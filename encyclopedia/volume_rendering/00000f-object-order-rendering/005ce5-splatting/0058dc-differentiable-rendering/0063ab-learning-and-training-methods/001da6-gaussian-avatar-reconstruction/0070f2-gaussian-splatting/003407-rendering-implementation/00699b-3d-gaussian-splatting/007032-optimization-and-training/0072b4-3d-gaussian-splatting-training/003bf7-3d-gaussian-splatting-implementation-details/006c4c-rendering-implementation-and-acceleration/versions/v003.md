# Rendering Implementation and Acceleration

Also called: 3D Gaussian Splatting Rendering Pipeline, 3DGS Rasterization, Gaussian Splatting Acceleration

## Overview
Rendering Implementation and Acceleration defines the computational pipeline for projecting 3D Gaussian primitives onto a 2D image plane and accumulating their contributions via alpha blending. It solves the problem of efficiently rendering millions of anisotropic Gaussians in real-time by leveraging modern GPU architectures through tiling, sorting, and culling. It sets itself apart from sibling methods by focusing on **execution efficiency** and **data representation**: [Data Compression and Storage Optimization](12943-data-compression-and-storage-optimization.md) reduces storage footprint, [Hardware and Computational Acceleration](16214-hardware-and-computational-acceleration.md) optimizes kernel execution, and [Occupancy Region Derivation & ϵ-Intersection Criterion](19020-occupancy-region-derivation-intersection-criterion.md) provides robust geometric intersection tests.

## Shared principles
All methods in this family operate on the set of $N$ 3D Gaussians $\{G_i\}_{i=1}^N$ defined in [Rendering Implementation and Acceleration](21069-rendering-implementation-and-acceleration.md). The core rendering operation involves projecting these 3D primitives to 2D screen space and performing alpha blending. Acceleration relies on the following shared mechanisms:

1.  **Tiling:** Dividing the image plane into non-overlapping tiles (commonly $16 \times 16$ pixels) to localize Gaussian processing and enable coalesced memory accesses [S2, unofficial].
2.  **Sorting:** Sorting Gaussians within each tile by view-space depth (front-to-back) to enable correct alpha blending [S2, unofficial].
3.  **Culling:** Discarding Gaussians that do not overlap with the camera frustum or specific tiles to reduce enumeration overhead [S2, unofficial].
4.  **Memory Hierarchy Management:** Exploiting the distinction between global memory (VRAM), shared memory (on-chip), and host memory (CPU RAM) to minimize data movement.

## Subtopics

### [Data Compression and Storage Optimization](12943-data-compression-and-storage-optimization.md)
This family of methods reduces the storage footprint and transmission overhead of 3D Gaussian Splatting (3DGS) models by compressing geometric attributes (position, scale, rotation), opacity, and view-dependent color (spherical harmonic coefficients). Unlike [Hardware and Computational Acceleration](16214-hardware-and-computational-acceleration.md) which focuses on rendering speed, or [Occupancy Region Derivation & ϵ-Intersection Criterion](19020-occupancy-region-derivation-intersection-criterion.md) which focuses on culling, these methods focus on data representation efficiency. They set themselves apart from [Gaussian Piling](19322-gaussian-piling.md) and [Parallel Differentiable Rasterization](19784-parallel-differentiable-rasterization.md) by altering the data structures themselves rather than the rendering pipeline execution.

### [Hardware and Computational Acceleration](16214-hardware-and-computational-acceleration.md)
Hardware and Computational Acceleration encompasses methods that optimize the execution of 3D Gaussian Splatting (3DGS) on modern graphics hardware, addressing bottlenecks in memory bandwidth, arithmetic intensity, and parallelism. It solves the problem of high computational cost and memory exhaustion when rendering or training scenes with millions of primitives. Unlike sibling methods that focus on data compression [Data Compression and Storage Optimization](12943-data-compression-and-storage-optimization.md) or spatial partitioning [Occupancy Region Derivation & ϵ-Intersection Criterion](19020-occupancy-region-derivation-intersection-criterion.md), this family focuses on **execution efficiency**: restructuring kernels to better utilize GPU architectures (e.g., Tensor Cores, shared memory) and managing data movement between CPU and GPU memory hierarchies.

### [Occupancy Region Derivation & ϵ-Intersection Criterion](19020-occupancy-region-derivation-intersection-criterion.md)
This method defines a robust geometric intersection test for 3D Gaussian primitives by approximating their density support with an elliptic occupancy region $\Omega_i$. It solves the problem of determining whether two splats $G_i$ and $G_j$ overlap in screen space without relying on strict binary boundary checks, which are sensitive to numerical precision and degenerate cases. It differs from standard bounding-box culling by using a shape-aware, normal-wise offset metric $\delta_{ij}$ combined with an $\epsilon$-tolerance, allowing for robust handling of near-misses and surface-aligned primitives.

### [Gaussian Piling](19322-gaussian-piling.md)
Gaussian Piling is a slice-based volumetric rendering method that unifies 3D Gaussian Splatting with an imaging system-aware focus model to compressively represent internal volumetric structures. Unlike standard 3D Gaussian Splatting which discards internal volumetric information and produces incoherent 3D structures with floating artifacts for slice-based modalities, Gaussian Piling models the finite focal zone to preserve high-frequency internal volumetric detail. It achieves this by re-parameterizing Gaussians to account for axial resolution, modulating opacity based on distance from the focal plane, and using additive rasterization to enforce 3D-to-2D consistency.

### [Parallel Differentiable Rasterization](19784-parallel-differentiable-rasterization.md)
Parallel Differentiable Rasterization is a rendering method that jointly generates High Dynamic Range (HDR) and Low Dynamic Range (LDR) images from a set of 3D Gaussian primitives using two parallel rasterization pipelines, $F_{HDR}$ and $F_{LDR}$. It differs from standard differentiable rasterization by decoupling the color representation into independent HDR and LDR streams that share the same geometric projection and alpha-blending logic, allowing for simultaneous optimization of high-intensity and standard-range views.

#### Conditional Splat Approximation
- **Definition**: A technique to approximate the influence range of a 3D Gaussian on a slice by using a 2D ellipse splat scaled by the marginal factor, which closely matches the true iso-probability contours [S1, unofficial].
- **Validation**: Qualitative validation shows that the conditional splat approximation (dashed red contours) closely overlaps with the true 3D Gaussian iso-probability contours (solid blue contours) [S1, unofficial].
- **Comparison**: The conditional splat provides an accurate and efficient approximation of the original 3D Gaussian’s influence range [S1, unofficial].

#### Conservative Region Pre-Culling
- **Definition**: A pre-rasterization optimization that skips spatially contiguous blocks of Gaussians before projection and preprocessing, reducing enumeration, sorting, and downstream rasterization overhead [S2, unofficial].
- **Steps**:
    1. At export time, reorder the Gaussian model by Morton code and cut it into fixed-size contiguous memory blocks [S2, unofficial].
    2. For each block, precompute an axis-aligned bounding box that contains the full $\tau_0$-support of every Gaussian it holds, inflated by a safety factor [S2, unofficial].
    3. Pass surviving blocks to the rasterizer as contiguous ranges; Gaussians in rejected blocks are never read, incurring zero cost in projection, prefix scan, or duplication [S2, unofficial].
- **Parameters**: $\tau_0$: The finite-support radius used by the backbone's Gaussian culling predicate [S2, unofficial].
- **Layout**: Gaussians are stored in contiguous memory blocks ordered by Morton code. Each block has a precomputed AABB. Rejected blocks are passed to the rasterizer as contiguous ranges to be skipped [S2, unofficial].
- **Pitfalls**: Conservative culling may skip visible Gaussians if their support extends beyond the inflated block box. Handled by inflating the box with a safety factor to guarantee bit-exactness [S2, unofficial].
- **Performance**: Evaluated across 52 runs; images produced are bit-identical to the unmodified backbone [S2, unofficial].

#### GaussianPile Forward Rendering
- **Definition**: A forward rendering process for slice-based volumetric reconstruction that converts 3D Gaussian primitives into 2D images by convolving the Gaussian with a reversed sensitivity map (PSF) along the axial direction, resulting in a 'focus Gaussian' that accounts for depth-of-field effects [S3, unofficial].
- **Steps**:
    1. Represent each primitive as an anisotropic 3D Gaussian with parameters $G = (\boldsymbol{\mu}, \mathbf{s}, \mathbf{q}, \alpha)$, where $\boldsymbol{\mu}$ is position, $\mathbf{s}$ is scale, $\mathbf{q}$ is orientation quaternion, and $\alpha$ is opacity [S3, unofficial].
    2. Convert scale $\mathbf{s}$ and orientation $\mathbf{q}$ into a 3D covariance matrix $\boldsymbol{\Sigma}$ in world coordinates: $\mathbf{S} = \text{diag}(\text{mod} \cdot \mathbf{s})$, $\mathbf{R} = \text{quatToMatrix}(\mathbf{q})$, $\boldsymbol{\Sigma} = \mathbf{R}\mathbf{S}\mathbf{S}^\top\mathbf{R}^\top$ [S3, unofficial].
    3. Extract the 2D components from the focus Gaussian: $\boldsymbol{\Sigma}_{2d}$ is the top-left 2x2 block of $\boldsymbol{\Sigma}_e$, and $\boldsymbol{\mu}_{2d} = [\mu_e[0], \mu_e[1]]^\top$ [S3, unofficial].

#### GES Implementation and Rendering Pipeline
- **Parameters**: $\delta$: Depth offset in Eq. (2) and (3). Set $\delta = \sum_{k=1}^D s^k$ for each Gaussian, where $D$ is dimension of scaling and $s^k$ is the $k$-th axis length of scaling $\mathbf{s}$. This allows $\delta$ to vary adaptively to geometric granularity [S4].
- **Layout**:
    - **Optimization renderer**: Pytorch framework, per-pixel rendering (GPU thread per pixel querying surfels and Gaussians) [S4].
    - **Post-optimization renderer**: OpenGL, per-primitive rendering (GPU thread per fragment of primitives querying covered pixels). Uses 4x MSAA instead of 4x supersampling. Two rendering passes: 1. Depth testing/writing enabled, blending disabled. Geometry shader generates surfels from points, renders surfel color map and depth map. Multisampling textures resolved. Depth map modified by offset $\delta$ via post-processing shader. 2. Depth testing and additive blending enabled, depth writing disabled. Geometry shader generates 3D Gaussians from points, splats 3D Gaussians to obtain $\mathbf{C}$ and $\mathbf{D}$. Final image computed using Eq. (5) via post-processing shader [S4].
- **Pitfalls**: Depth offset $\delta$ impact: If too large, 3D Gaussians occluded by surface leak out. If too small, 3D Gaussians close to surface are wrongly truncated [S4].

## Background
The rendering pipeline for 3D Gaussian Splatting was introduced by Kerbl et al. in "A 3D Gaussian Splatting for Real-Time Radiance Field Rendering" (2023) [G]. It established the standard tile-based rasterization approach that subsequent acceleration and optimization methods build upon. The method has become the de facto standard for real-time neural rendering, with extensive research focusing on its implementation details, acceleration techniques, and extensions for specific modalities like volumetric data and HDR imaging.
