# Multi-View Consistency Scoring for Densification

Also called: gaussian pruning and densification score

## Overview
This method computes per-Gaussian scores based on multi-view photometric consistency to guide both densification (importance) and pruning in 3D Gaussian Splatting [S1, unofficial]. It differs from standard gradient-based densification by aggregating L1 reconstruction errors across multiple camera views, identifying Gaussians that consistently fail to reconstruct the scene geometry or appearance [S1, unofficial]. It builds on [Multi-view Consistency and Scoring](15793-multi-view-consistency-and-scoring.md).

## How it works
**Inputs:**
- `camlist`: List of viewpoint camera objects.
- `gaussians`: Current Gaussian representation (positions, covariances, opacities, SH coefficients).
- `pipe`: Rendering pipeline configuration.
- `bg`: Background color/tensor.
- `args`: Configuration object containing `loss_thresh` (threshold for high-error classification).
- `DENSIFY`: Boolean flag. If `True`, compute importance score for densification; if `False`, compute only pruning score.

**Outputs:**
- `importance_score`: Per-Gaussian integer counts (floor-averaged) of views marking the Gaussian as high-error. Only returned if `DENSIFY` is `True`.
- `pruning_score`: Normalized per-Gaussian score in $[0, 1]$, where higher values indicate worse multi-view consistency.

**Data Structures:**
- `full_metric_counts`: Tensor of shape $(N)$, initialized to `None`. Accumulates the count of views where the Gaussian contributed to high L1 loss.
- `full_metric_score`: Tensor of shape $(N)$, initialized to `None`. Accumulates the weighted photometric loss.
- `metric_map`: Binary tensor of shape $(H, W)$, where $1$ indicates pixel L1 loss $>$ `args.loss_thresh`, else $0$.

**Steps:**
1. Initialize `full_metric_counts = None` and `full_metric_score = None`.
2. For each `view` in `camlist`:
   a. Retrieve `my_viewpoint_cam = camlist[view]`.
   b. Render the image: `render_image = render_fastgs(my_viewpoint_cam, gaussians, pipe, bg, args.mult)["render"]`.
   c. Compute photometric loss: `photometric_loss = compute_photometric_loss(my_viewpoint_cam, render_image)`.
   d. Retrieve ground truth: `gt_image = my_viewpoint_cam.original_image.cuda()`.
   e. Compute normalized L1 loss: `l1_loss_norm = get_loss(render_image, gt_image)`.
   f. Create binary mask: `metric_map = (l1_loss_norm > args.loss_thresh).int()`.
   g. Render with metric accumulation: `render_pkg = render_fastgs(my_viewpoint_cam, gaussians, pipe, bg, args.mult, get_flag=True, metric_map=metric_map)`.
   h. Extract accumulated counts: `accum_loss_counts = render_pkg["accum_metric_counts"]`.
   i. Update accumulators:
      - If `full_metric_counts` is `None`, set `full_metric_counts = accum_loss_counts.clone()`. Else, `full_metric_counts += accum_loss_counts`.
      - If `full_metric_score` is `None`, set `full_metric_score = photometric_loss * accum_loss_counts.clone()`. Else, `full_metric_score += photometric_loss * accum_loss_counts`.
3. Compute pruning score:
   $$ \text{pruning\_score} = \frac{\text{full\_metric\_score} - \min(\text{full\_metric\_score})}{\max(\text{full\_metric\_score}) - \min(\text{full\_metric\_score})} $$
   [G] Handle division by zero if $\max - \min = 0$ by setting score to $0$.
4. If `DENSIFY` is `True`:
   $$ \text{importance\_score} = \lfloor \text{full\_metric\_counts} / |\text{camlist}| \rfloor $$
   Else, `importance_score = None`.
5. Return `importance_score` and `pruning_score`.

**Parameters:**
- `args.loss_thresh`: Threshold for L1 loss to classify a pixel as "high error". Not given in the sources.
- `args.mult`: Multiplier for rendering scale/resolution. Not given in the sources.

**Edge Cases:**
- If `full_metric_score` has zero variance (all values equal), the denominator in the pruning score formula is zero. [G] In this case, set `pruning_score` to a constant (e.g., 0 or 0.5) to avoid NaN.
- `accum_loss_counts` may be sparse; ensure tensor operations handle zeros correctly.

**Pseudocode:**
```python
def compute_gaussian_score_fastgs(camlist, gaussians, pipe, bg, args, DENSIFY=True):
    full_metric_counts = None
    full_metric_score = None
    
    for view in camlist:
        my_viewpoint_cam = camlist[view]
        
        # Render image
        render_pkg = render_fastgs(my_viewpoint_cam, gaussians, pipe, bg, args.mult)
        render_image = render_pkg["render"]
        
        # Compute photometric loss (scalar or per-pixel? Note says scalar * counts)
        photometric_loss = compute_photometric_loss(my_viewpoint_cam, render_image)
        
        gt_image = my_viewpoint_cam.original_image.cuda()
        
        # Compute L1 loss
        l1_loss_norm = get_loss(render_image, gt_image)
        
        # Create metric map
        metric_map = (l1_loss_norm > args.loss_thresh).int()
        
        # Render with metric accumulation
        render_pkg_metric = render_fastgs(
            my_viewpoint_cam, gaussians, pipe, bg, args.mult, 
            get_flag=True, metric_map=metric_map
        )
        accum_loss_counts = render_pkg_metric["accum_metric_counts"]
        
        # Update accumulators
        if full_metric_counts is None:
            full_metric_counts = accum_loss_counts.clone()
        else:
            full_metric_counts += accum_loss_counts
            
        if full_metric_score is None:
            full_metric_score = photometric_loss * accum_loss_counts.clone()
        else:
            full_metric_score += photometric_loss * accum_loss_counts
            
    # Compute pruning score
    min_score = torch.min(full_metric_score)
    max_score = torch.max(full_metric_score)
    denom = max_score - min_score
    
    if denom == 0:
        pruning_score = torch.zeros_like(full_metric_score)
    else:
        pruning_score = (full_metric_score - min_score) / denom
        
    importance_score = None
    if DENSIFY:
        importance_score = torch.floor_divide(full_metric_counts, len(camlist))
        
    return importance_score, pruning_score
```

## Subtopics

### [Cross-ray Densification](15775-cross-ray-densification.md)
Cross-ray Densification is a strategy that selectively increases 3D Gaussian density in multi-view overlapped regions to enhance multi-view consistency during optimization. It is divided into Multi-view Augmented Densification (MVAD), which adapts the densification threshold based on camera geometry, and Cross-ray Densification, which uses ray tracing to identify 3D regions contributing significantly to multiple views. Unlike standard densification which relies solely on 2D gradient magnitude, this method leverages multi-view photometric loss and ray intersection geometry to target complex, texture-dense areas that are consistently observed across different camera perspectives.

## Operating characteristics
- **Time Complexity:** $O(V \cdot N \cdot H \cdot W)$, where $V$ is the number of views, $N$ is the number of Gaussians, and $H \times W$ is the image resolution. Each view requires a forward render and a metric-aware render.
- **Memory Complexity:** $O(N)$ for storing `full_metric_counts` and `full_metric_score`.
- **Strengths:** Targets Gaussians that are consistently wrong across views, reducing artifacts in texture-dense or geometrically complex regions.
- **Limitations:** Requires multiple renders per optimization step, increasing training time. Sensitive to the `loss_thresh` parameter.
- **When to use:** When standard gradient-based densification fails to resolve multi-view inconsistencies or artifacts in complex geometry.
- **When not to use:** When computational resources are limited or for simple scenes with high consistency.

## Background
This method is part of the FastGS (Fast Gaussian Splatting) optimization pipeline [S1, unofficial]. It was introduced to improve the quality of 3D Gaussian Splatting by leveraging multi-view consistency for densification and pruning decisions.
