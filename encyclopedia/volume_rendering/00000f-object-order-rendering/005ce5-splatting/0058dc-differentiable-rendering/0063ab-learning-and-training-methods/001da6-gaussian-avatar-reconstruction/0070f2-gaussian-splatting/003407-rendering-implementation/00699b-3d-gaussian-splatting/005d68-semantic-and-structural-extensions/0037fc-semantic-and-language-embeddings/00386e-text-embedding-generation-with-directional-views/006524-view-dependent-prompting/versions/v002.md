# View-Dependent Prompting

Also called: Directional View Suffixing

## Overview
View-Dependent Prompting augments a base text prompt with a directional suffix derived from the prior camera's position relative to the reconstruction camera to guide diffusion-based 3D generation [S1, unofficial][S2]. It differs from sibling methods like [TexGS-VolVis Representation and Optimization](11105-texgs-volvis-representation-and-optimization.md) and [Multimodal Object Embedding](21344-multimodal-object-embedding.md) by explicitly conditioning the text embedding on discrete viewing angles rather than relying solely on volumetric or geometric consistency [S1, unofficial][S2].

## How it works
**Inputs and Outputs:**
*   **Input:** Base text prompt $P$, sampled camera azimuth $\theta_{cam}$, and camera elevation $\phi_{cam}$.
*   **Output:** Augmented text prompt $P'$ containing a view-dependent suffix.

**Data Structures:**
*   **Prompt Suffixes:** A set of discrete strings: "front view", "side view", "overhead view", "bottom view" [S2].

**Steps:**
1.  **Determine Suffix:** Based on $\theta_{cam}$ and $\phi_{cam}$, select a suffix $S$ according to the rules below [S2]:
    *   If $\phi_{cam} > 60^\circ$: $S = \text{"overhead view"}$ [S2].
    *   If $\phi_{cam} < 0^\circ$: $S = \text{"bottom view"}$ [S2].
    *   If $|\theta_{cam}| \le 30^\circ$: $S = \text{"front view"}$ [S2].
    *   If $30^\circ \le |\theta_{cam}| \le 90^\circ$: $S = \text{"side view"}$ [S2].
    *   If $90^\circ < |\theta_{cam}| \le 180^\circ$: $S = \text{"bottom view"}$ [S2].
2.  **Augment Prompt:** Append $S$ to the base prompt $P$ to form $P'$ [S2].

**Pseudocode:**
```python
def get_view_dependent_suffix(theta_cam, phi_cam):
    if phi_cam > 60.0:
        return "overhead view"
    if phi_cam < 0.0:
        return "bottom view"
    abs_theta = abs(theta_cam)
    if abs_theta <= 30.0:
        return "front view"
    if abs_theta <= 90.0:
        return "side view"
    return "bottom view"
```

**Parameters:**
*   **Elevation Thresholds:** $60^\circ$ (overhead), $0^\circ$ (bottom) [S2].
*   **Azimuthal Bands:** $\pm 30^\circ$ (front), $\pm 30^\circ-90^\circ$ (side), $\pm 90^\circ-180^\circ$ (bottom) [S2].

**Edge Cases and Pitfalls:**
*   **Disagreement:** [S1, unofficial] suggests interpolating embeddings based on the quadrant of $\theta_{cam}$, but explicitly states that taking the closest embedding worked better [S1, unofficial]. [S2] uses the discrete suffix rules above [S2]. Implementers should follow the discrete suffix selection for [S2] or the closest-embedding retrieval for [S1, unofficial] [S1, unofficial][S2].
*   **Ambiguity:** The term "bottom view" is used for both low elevation ($\phi_{cam} < 0^\circ$) and high azimuth ($90^\circ < |\theta_{cam}| \le 180^\circ$) in [S2] [S2].

## Operating characteristics
Time complexity is not given in the sources. Memory complexity is not given in the sources. Strengths include improved geometric coherence by providing explicit directional context to the diffusion model [S1, unofficial][S2]. Limitations include potential abrupt changes in the text embedding as the camera moves across boundaries [S1, unofficial]. Use this method when generating 3D content from text prompts where consistent directional lighting and geometry across views are required [S1, unofficial][S2]. Avoid this method when continuous view-dependent variations are preferred over discrete categorical descriptions [S1, unofficial].

## Background
Originated in text-to-3D diffusion methods to mitigate view inconsistency [S1, unofficial][S2]. [S1, unofficial] (DreamFusion) explored interpolation but found nearest-neighbor embedding selection effective [S1, unofficial]. [S2] (RealFusion) formalized the discrete suffix approach based on camera quadrants [S2].
