# AnySplat Pipeline

Also called: Feed-forward 3D Gaussian Splatting from Unconstrained Views

## Overview
AnySplat is a feed-forward, generalizable reconstruction method that predicts a set of 3D Gaussians directly from uncalibrated input images without per-scene optimization [S1, unofficial]. It solves the problem of requiring known camera poses and per-scene training by jointly predicting Gaussian parameters, depth maps, and camera poses using a transformer-based encoder-decoder architecture [S1, unofficial]. Unlike sibling methods that may rely on fixed grids or specific calibration assumptions, AnySplat operates on unconstrained views and uses a differentiable voxelization module to handle the transition from pixel-wise predictions to a renderable 3D primitive set [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A batch of $K$ uncalibrated RGB images $I \in \mathbb{R}^{1 \times K \times 3 \times 448 \times 448}$ [S1, unofficial]. The images are normalized to $[-1, 1]$ before processing [S1, unofficial].
*   **Outputs:** A set of 3D Gaussians $\mathcal{G}$ (defined by mean $\mu$, scale $s$, rotation $r$, opacity $\alpha$, and color $c$) and predicted camera poses (extrinsic $E$ and intrinsic $K$) [S1, unofficial].

**Data Structures:**
The method predicts pixel-wise 3D Gaussians which are then aggregated. The core data structure is the set of Gaussians $\mathcal{G}$, where each Gaussian is defined by:
*   $\mu \in \mathbb{R}^3$: 3D position.
*   $s \in \mathbb{R}^3$: Scale (vector).
*   $r \in \mathbb{R}^4$: Rotation (quaternion).
*   $\alpha \in \mathbb{R}$: Opacity.
*   $c \in \mathbb{R}^3$: Color (RGB).

**Steps:**
1.  **Feature Encoding:** Input images are processed by a transformer-based geometry encoder to extract multi-scale features [S1, unofficial].
2.  **Parameter Prediction:** Three decoder heads ($F_G, F_D, F_C$) predict:
    *   $F_G$: Gaussian parameters ($\mu, \sigma, r, s, c$) [S1, unofficial]. Note: $\sigma$ likely refers to scale or covariance components.
    *   $F_D$: Depth map $D$.
    *   $F_C$: Camera poses $p$ (extrinsic and intrinsic matrices) [S1, unofficial].
3.  **Gaussian Construction:** The predicted parameters are used to construct a set of pixel-wise 3D Gaussians [S1, unofficial].
4.  **Differentiable Voxelization:** The pixel-wise Gaussians are voxelized into "pre-voxel 3D Gaussians" using a Differentiable Voxelization module [S1, unofficial]. This step aggregates and regularizes the primitives for efficient rendering.
5.  **Rendering:** Multi-view images and depth maps are rendered from the voxelized Gaussians using differentiable rasterization [S1, unofficial].
6.  **Loss Computation:**
    *   **RGB Loss:** Rendered images are compared against ground truth images using an RGB loss (e.g., L1 or LPIPS) [S1, unofficial].
    *   **Geometry Loss:** Rendered depth maps, decoded depth $D$, and predicted poses $p$ are used to compute geometry losses [S1, unofficial].
    *   **Pseudo-Geometry Supervision:** Geometries are supervised by pseudo-geometry priors obtained from a pretrained VGGT model [S1, unofficial].
7.  **Training:** The network is trained end-to-end to minimize these losses [S1, unofficial].

**Pseudocode:**
```python
import torch

def anysplat_pipeline(images):
    """
    images: torch.Tensor of shape [1, K, 3, 448, 448], values in [-1, 1]
    """
    # 1. Encode and Decode
    # model.inference handles the encoder and decoder heads F_G, F_D, F_C
    # Returns: gaussians (set of 3D Gaussians), pred_context_pose (dict with extrinsic/intrinsic)
    gaussians, pred_context_pose = model.inference(images)
    
    # 2. Extract Poses
    pred_all_extrinsic = pred_context_pose['extrinsic']
    pred_all_intrinsic = pred_context_pose['intrinsic']
    
    # 3. Render and Compute Losses (during training)
    # Rendered images and depth maps are generated from gaussians
    rendered_images, rendered_depths = render(gaussians, pred_all_extrinsic, pred_all_intrinsic)
    
    # RGB Loss
    rgb_loss = compute_rgb_loss(rendered_images, ground_truth_images)
    
    # Geometry Loss
    # Uses rendered depth, decoded depth D (from F_D), and poses p
    geometry_loss = compute_geometry_loss(rendered_depths, decoded_depth_D, pred_context_pose)
    
    # Pseudo-Geometry Loss
    # Supervised by pretrained VGGT priors
    pseudo_geometry_loss = compute_pseudo_geometry_loss(gaussians, vggt_priors)
    
    total_loss = rgb_loss + geometry_loss + pseudo_geometry_loss
    
    return gaussians, pred_context_pose, total_loss
```

**Parameters:**
*   Input resolution: $448 \times 448$ [S1, unofficial].
*   Number of views $K$: Variable, but typically small for unconstrained inputs [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Uncalibrated Inputs:** The method must handle varying camera intrinsics and extrinsics, relying on the network to predict them [S1, unofficial].
*   **Voxelization Artifacts:** The differentiable voxelization step may introduce artifacts if the voxel grid resolution is not chosen appropriately [S1, unofficial].
*   **Pseudo-Geometry Dependency:** The quality of geometry supervision depends on the accuracy of the pretrained VGGT model [S1, unofficial].

## Subtopics

### [SubSplat](13524-subsplat.md)
SubSplat is a method for high-resolution novel-view synthesis that resolves the trade-off between network computational cost and rendering fidelity in pixel-aligned 3D Gaussian Splatting. It solves the problem of insufficient Gaussian density and artifacts when using low-resolution backbone inputs by introducing a Sub-pixel Gaussian Reparameterizer (SPGR). Unlike prior methods limited by fixed grids or image-space upsamplers, SubSplat subdivides each grid-anchored primary Gaussian into multiple fine-grained sub-pixel primitives, restoring structural density directly from low-resolution features while maintaining stable network latency.

### [Deformable Radial Kernel (DRK)](13699-deformable-radial-kernel-drk.md)
Deformable Radial Kernel (DRK) Splatting is a 3D scene representation method that replaces the fixed radial symmetry of Gaussian primitives with a flexible planar kernel defined by multiple radial basis functions. It solves the overparameterization and geometric fidelity limitations of Gaussian Splatting by allowing adaptive stretching, rotation, and sharp boundary control, enabling high-fidelity rendering with significantly fewer primitives. Unlike standard 2D Gaussian Splatting, which relies on smooth, elliptical distributions, DRK supports straight edges and sharp corners through L1/L2 norm blending and piecewise edge sharpening.

## Operating characteristics
*   **Time Complexity:** Inference is feed-forward, making it significantly faster than per-scene optimization methods like original 3D Gaussian Splatting. The complexity is dominated by the transformer encoder and decoder heads [S1, unofficial].
*   **Memory Complexity:** Memory usage depends on the number of predicted Gaussians and the voxel grid resolution. The differentiable voxelization step may require additional memory for intermediate voxel structures [S1, unofficial].
*   **Performance:** The method achieves high-quality novel-view synthesis and geometry reconstruction on unconstrained views [S1, unofficial].
*   **Strengths:** No per-scene optimization required; handles uncalibrated inputs; joint prediction of geometry and appearance.
*   **Limitations:** Relies on the quality of the pretrained VGGT model for geometry supervision; performance may degrade on scenes significantly different from the training distribution [S1, unofficial].
*   **When to Use:** When fast reconstruction from unconstrained views is needed and per-scene optimization is not feasible.
*   **When Not to Use:** When high-precision per-scene optimization is required or when input images are highly calibrated and static.

## Background
AnySplat was introduced by InternRobotics as a feed-forward generalizable reconstruction method [S1, unofficial]. It builds on the principles of 3D Gaussian Splatting and feed-forward neural radiance fields, extending them to handle uncalibrated inputs and joint pose prediction [S1, unofficial]. The method leverages a pretrained VGGT model for pseudo-geometry supervision, enabling effective training without ground-truth 3D geometry [S1, unofficial].
