# Human Gaussian Splatting

Also called: HuGS

## Overview
Human Gaussian Splatting (HuGS) is an animatable human model that represents the body as a set of 3D Gaussian primitives in a canonical space, deformed via forward skinning and local non-rigid refinement to render novel views in real-time [S1]. It solves the problem of real-time rendering of clothed human avatars from multi-view videos, addressing the degradation in quality and speed associated with previous NeRF/SDF approaches that rely on backward skinning [S1]. HuGS distinguishes itself by applying Linear Blend Skinning (LBS) directly to explicit Gaussian primitives in canonical space, enabling real-time performance (≈ 80 fps) while achieving higher visual quality than state-of-the-art methods on the THuman4 dataset [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Multi-view video data captured by $N$ calibrated cameras over $T$ timesteps [S1]. Pre-computed or assumed SMPL/SMPL-X parameters: body shape $\beta$ and body pose $\theta_t$ (3D rotation of each body joint $j$) at timestep $t$ [S1]. Foreground segmentation masks [S1].
*   **Outputs:** Rendered images of the human avatar at novel poses and views [S1].

**Data Structures:**
Each Gaussian primitive $i$ stores the following learnable parameters in canonical space [S1]:
*   Position: $\mathbf{p}_c = (p_x, p_y, p_z)$
*   Orientation: Quaternion $\mathbf{q}_c$
*   Scale: $\mathbf{s} = (s_x, s_y, s_z)$
*   Color: $\mathbf{c} = (c_r, c_g, c_b)$
*   Opacity: Scalar $o$
*   Skinning weights: Vector $\mathbf{w} = (w_1, w_j, \dots, w_J)$, where $J$ is the number of body joints [S1].
*   Latent code: $\mathbf{l}$, encoding non-rigid motion [S1].

Scale and opacity are consistent across novel views and poses [S1].

**Deformation Pipeline:**
The deformation from canonical space to posed space occurs in two stages: forward skinning and local non-rigid refinement [S1].

1.  **Compute Joint Transformations:** Given the body pose $\theta_t$, compute the rigid transformation $\mathbf{M}_j \in SE(3)$ for each body joint $j$ using the kinematic tree [S1].
2.  **Compute Skinning Transformation:** Calculate the Gaussian's skinning transformation $\mathbf{T}_t$ by weight-averaging joint transformations [S1]:
    $$ \mathbf{T}_t = \sum_{j=1}^{J} w_j \mathbf{M}_j $$
    where $w_j$ are the skinning weights and $\mathbf{M}_j$ are the joint transformations [S1].
3.  **Apply Linear Blend Skinning (LBS):** Transform the canonical position and orientation to posed space ($\mathbf{p}_{lbs}, \mathbf{q}_{lbs}$) using $\mathbf{T}_t = [\mathbf{R}_t | \mathbf{t}_t]$ [S1]:
    $$ \mathbf{p}_{lbs} = \mathbf{T}_t \mathbf{p}_c $$
    $$ \mathbf{q}_{lbs} = \mathbf{R}_t \circ \mathbf{q}_c $$
    where $\circ$ denotes quaternion multiplication [S1].
4.  **Local Non-Rigid Refinement:** Compute a local pose vector $\boldsymbol{\theta}^l_t$ using attention-weighting to prevent overfitting and capture local deformations (e.g., from garments) [S1]:
    $$ \boldsymbol{\theta}^l_t = (W \cdot \mathbf{w}) \odot \boldsymbol{\theta}_t $$
    where $W$ is an explicit attention map based on the kinematic tree, $\mathbf{w}$ are the skinning weights, and $\odot$ is element-wise multiplication [S1].
5.  **MLP Refinement:** Pass $\boldsymbol{\theta}^l_t$ and the latent code $\mathbf{l}$ into a pose-dependent MLP. The MLP outputs per-Gaussian residuals for translation, rotation, and lightness changes to refine the position ($\mathbf{p}_{obs}$), orientation ($\mathbf{q}_{obs}$), and color [S1].
6.  **Rendering:** Render the deformed Gaussians using a differentiable Gaussian rasterizer [S1].

**Pseudocode:**
```python
def human_gaussian_splatting_render(gaussians, pose_theta_t, joint_transforms_M, attention_map_W, mlp_refinement, camera_params):
    """
    Render a frame for Human Gaussian Splatting.
    
    Args:
        gaussians: List of Gaussian primitives. Each has attributes:
                   p_c (pos), q_c (quat), s (scale), c (color), o (opacity),
                   w (skinning weights vector), l (latent code).
        pose_theta_t: Body pose at timestep t, rotations for each joint.
        joint_transforms_M: List of SE(3) transformations for each joint j in canonical space.
        attention_map_W: Attention map based on kinematic tree.
        mlp_refinement: Pose-dependent MLP for non-rigid refinement.
        camera_params: Camera view and projection matrices.
        
    Returns:
        Rendered image.
    """
    J = len(joint_transforms_M)
    rendered_image = None
    
    for g in gaussians:
        # 1. Compute Skinning Transformation T_t
        # T_t = sum(w_j * M_j)
        T_t = Identity_SE3()
        for j in range(J):
            # w is a vector, w_j is the scalar weight for joint j
            w_j = g.w[j]
            M_j = joint_transforms_M[j]
            # Add weighted transformation to T_t
            # Note: In standard LBS, transformations are applied to points.
            # Here T_t is the composite transformation matrix.
            # Implementation detail: T_t is typically constructed as a weighted sum of matrices
            # if using linear blend, or accumulated. The source defines T_t = sum(w_j M_j).
            # We assume matrix addition is valid for the SE(3) representation in this context
            # or that M_j are 4x4 matrices and w_j are scalars.
            T_t += w_j * M_j
            
        # Extract Rotation R_t and Translation t_t from T_t
        R_t, t_t = decompose_SE3(T_t)
        
        # 2. Apply LBS
        # p_lbs = T_t * p_c
        p_lbs = T_t @ g.p_c # Assuming homogeneous coordinates for p_c
        
        # q_lbs = R_t o q_c
        q_lbs = quaternion_multiply(R_t, g.q_c)
        
        # 3. Local Non-Rigid Refinement
        # Compute local pose vector
        # theta_lt = (W . w) o theta_t
        # W is attention map, w is skinning weights.
        # Element-wise multiplication of attention map and weights, then with pose.
        # Note: theta_t is a vector of joint rotations.
        # The source says: theta_lt = (W . w) o theta_t
        # W . w implies element-wise multiplication of the attention map and weights.
        # Then element-wise multiplication with theta_t.
        
        # Construct local pose input for MLP
        # W is likely a matrix or vector aligning with joints.
        # Assuming W and w are aligned with the J joints.
        local_weights = attention_map_W * g.w # Element-wise
        theta_lt = local_weights * pose_theta_t # Element-wise
        
        # 4. MLP Refinement
        # Input: theta_lt, latent code l
        # Output: residuals for pos, rot, color
        residuals = mlp_refinement(theta_lt, g.l)
        
        # Apply residuals
        p_obs = p_lbs + residuals.translation
        q_obs = quaternion_multiply(residuals.rotation, q_lbs)
        c_obs = g.c + residuals.lightness_change
        
        # 5. Rasterize
        # Project p_obs, q_obs, s, c_obs, o to screen space
        screen_coords, depth, alpha = project_gaussian(p_obs, q_obs, g.s, c_obs, g.o, camera_params)
        
        # Accumulate into image
        rendered_image = accumulate_pixel(rendered_image, screen_coords, alpha, c_obs)
        
    return rendered_image
```

**Parameters:**
*   $N$: Number of calibrated cameras [S1].
*   $T$: Number of timesteps in the multi-view videos [S1].
*   $\beta$: Body shape parameters from SMPL/SMPL-X [S1].
*   $\theta_t$: Body pose at timestep $t$, expressed as 3D rotation of each body joint $j$ [S1].

**Edge Cases and Pitfalls:**
*   **Overfitting:** Using the global pose vector $\theta_t$ directly as input to the refinement MLP can represent too much information for local primitives, leading to spurious correlations and overfitting [S1]. The attention-weighting scheme mitigates this [S1].
*   **Backward Skinning:** Previous NeRF/SDF approaches require backward skinning formulations which are slower and harder to generalize [S1]. HuGS avoids this by using forward skinning on explicit primitives [S1].

## Operating characteristics
*   **Performance:** Renders at approximately 80 fps at 512 × 512 resolution [S1].
*   **Quality:** Achieves a 1.5 dB PSNR improvement over the state-of-the-art on the THuman4 dataset [S1].
*   **Strengths:** Real-time rendering capability; handles clothed avatars with non-rigid deformations; end-to-end training from multi-view observations [S1].
*   **Limitations:** Requires pre-computed or assumed SMPL/SMPL-X parameters [S1]. Relies on multi-view video data [S1].

## Background
Human Gaussian Splatting (HuGS) was proposed to address the limitations of neural representations like NeRF and SDF, which are difficult to render in real-time and degrade in quality when animated with poses different from training observations [S1]. It builds on the efficiency of 3D Gaussian Splatting [16] by adding pose-dependent movement parameters (skinning weights and latent codes) to the canonical Gaussian representation [S1]. The method was evaluated on the THuman4 dataset [S1].
