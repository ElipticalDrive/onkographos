# Scene Flow Prior

Also called: Flow MLP for motion estimation

## Overview
Scene Flow Prior enhances the temporal consistency of 4D spatio-temporal representations by incorporating a flow Multi-Layer Perceptron (MLP) for motion estimation [S1]. It maps spatio-temporal coordinates from $\mathbb{R}^4$ to motion fields in $\mathbb{R}^3$, predicting displacement only between adjacent frames to avoid the difficulty of establishing long-term correspondences in deformable scenes [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Spatio-temporal coordinates $(\mathbf{x}, t)$ where $\mathbf{x} \in \mathbb{R}^3$ and $t$ is the time index; LiDAR point clouds $S_i$ for frame $i$ [S1].
*   **Outputs:** Predicted scene flow displacement $\Delta \mathbf{x}$; transformed point cloud $\mathbf{x}'$ [S1].

**Data Structures:**
*   **Flow MLP:** A Multi-Layer Perceptron that processes position-encoded inputs [S1].
*   **Positional Encoding:** $\gamma(\mathbf{x}, t)$ applies element-wise sine and cosine functions across $L$ frequency bands to the concatenated coordinate and time vector [S1].
*   **Point Clouds:** Sets of 3D points $S$ and $\hat{S}$ representing two adjacent frames, each containing $K$ points [S1].

**Parameters:**
*   $L$: Number of frequency bands in positional encoding [S1].
*   $K$: Number of points in each point cloud set [S1].
*   $n$: Total number of frames in the sequence [S1].

**Steps:**
1.  **Positional Encoding:** Encode the input coordinate $\mathbf{x}$ and time $t$ using $\gamma(\mathbf{x}, t)$ [S1].
2.  **Flow Prediction:** Feed the encoded coordinates into the flow MLP to predict the displacement vector $\Delta \mathbf{x}$:
    $$ \Delta \mathbf{x} = \mathrm{MLP}_\mathrm{flow}(\gamma(\mathbf{x}, t)) $$
3.  **Motion Application:** Compute the transformed coordinate $\mathbf{x}'$:
    $$ \mathbf{x}' = \mathbf{x} + \Delta \mathbf{x} $$
4.  **Geometric Loss Calculation:** Supervise the motion prediction by calculating the Chamfer Distance (CD) between the predicted transformed point cloud and the ground truth point cloud of the adjacent frame [S1]. The flow loss $\mathcal{L}_\mathrm{flow}$ sums the CD over forward and backward adjacent frames:
    $$ \mathcal{L}_\mathrm{flow} = \sum_{j \in \{-1, 1\}} \mathrm{CD}(S_i + \mathrm{MLP}_\mathrm{flow}(S_i), S_{i+j}) $$
    where $i \in (0, n-1)$ [S1].
5.  **Chamfer Distance Definition:** The Chamfer Distance between two point cloud sets $S$ and $\hat{S}$ is defined as:
    $$ \mathrm{CD} = \frac{1}{K} \sum_{\hat{p}_i \in \hat{S}} \min_{p_i \in S} \|\hat{p}_i - p_i\|_2^2 + \frac{1}{K} \sum_{p_i \in S} \min_{\hat{p}_i \in \hat{S}} \|p_i - \hat{p}_i\|_2^2 $$
    where $S$ and $\hat{S}$ are two frames of point clouds [S1].

**Pseudocode:**
```python
import numpy as np

def positional_encoding(coords, L):
    """Applies positional encoding to coordinates.
    coords: (N, D) array
    L: int, number of frequency bands
    Returns: (N, 2 * D * L) encoded vector
    """
    frequencies = 2.0 ** np.arange(L)
    encoded = []
    for freq in frequencies:
        encoded.append(np.sin(coords * freq))
        encoded.append(np.cos(coords * freq))
    return np.concatenate(encoded, axis=1)

def mlp_forward(x, weights):
    """Standard MLP forward pass.
    x: (N, D_in)
    weights: list of (W, b) tuples
    Returns: (N, D_out)
    """
    for W, b in weights:
        x = x @ W + b
        x = np.maximum(0, x) # ReLU activation [G]
    return x

def chamfer_distance(S, S_hat):
    """Computes Chamfer Distance between two point clouds.
    S: (K, 3), S_hat: (K, 3)
    Returns: float
    """
    K = S.shape[0]
    # Pairwise squared Euclidean distances
    dists = np.sum((S[:, np.newaxis, :] - S_hat[np.newaxis, :, :]) ** 2, axis=2)
    # Minimum distances for each point in S_hat to S
    min_S_hat_to_S = np.min(dists, axis=1)
    # Minimum distances for each point in S to S_hat
    min_S_to_S_hat = np.min(dists, axis=0)
    cd = (1.0 / K) * np.sum(min_S_hat_to_S) + (1.0 / K) * np.sum(min_S_to_S_hat)
    return cd

def compute_flow_loss(S_i, S_adj, flow_mlp_weights, L, t_i):
    """Computes flow loss for a frame and its adjacent frame.
    S_i: (K, 3) point cloud of frame i
    S_adj: (K, 3) point cloud of frame i+j
    flow_mlp_weights: weights for the flow MLP
    L: positional encoding bands
    t_i: time index of S_i
    Returns: float, CD value
    """
    # Concatenate coordinates and time for encoding
    coords_with_time = np.concatenate([S_i, np.full((S_i.shape[0], 1), t_i)], axis=1)
    encoded = positional_encoding(coords_with_time, L)
    # Predict displacement
    delta_x = mlp_forward(encoded, flow_mlp_weights)
    # Transform point cloud
    S_i_transformed = S_i + delta_x
    # Compute Chamfer Distance
    return chamfer_distance(S_i_transformed, S_adj)

def total_flow_loss(S_all, flow_mlp_weights, L):
    """Computes total flow loss over all frames.
    S_all: list of (K, 3) arrays for frames 0 to n-1
    Returns: float, total L_flow
    """
    n = len(S_all)
    total_loss = 0.0
    for i in range(n):
        for j in [-1, 1]:
            target_idx = i + j
            if 0 <= target_idx < n: # Boundary guard [G]
                total_loss += compute_flow_loss(S_all[i], S_all[target_idx], flow_mlp_weights, L, t_i=i)
    return total_loss
```

**Edge Cases and Pitfalls:**
*   **Long-term Correspondences:** The method explicitly avoids long-term correspondences to canonical space because vehicle motion range may span a long distance in autonomous driving scenarios, making such correspondences hard to establish [S1].
*   **Precision:** The Chamfer Distance uses squared Euclidean norms, which penalize large errors quadratically [G].
*   **Boundary Conditions:** The index $i$ ranges over valid frame indices where adjacent frames exist, and the summation over $j \in \{-1, 1\}$ naturally skips out-of-bounds targets [S1].

## Operating characteristics
*   **Time Complexity:** Not given in the sources. [S1]
*   **Memory Complexity:** Not given in the sources. [S1]
*   **Strengths:** Enhances temporal consistency by leveraging explicit geometric constraints from LiDAR point clouds and imposes a motion prior that helps in dynamic scenes [S1].
*   **Limitations:** Relies on the availability of LiDAR point clouds, and predicting motion only between adjacent frames may require proper aggregation to maintain consistency over long sequences [S1].
*   **When to Use:** Suitable for dynamic scene reconstruction in autonomous driving scenarios where LiDAR data is available and temporal consistency is critical [S1].

## Background
The Scene Flow Prior method is part of the LiDAR4D framework, introduced in the paper "LiDAR4D: Dynamic Neural Fields for Novel Space-Time View LiDAR Synthesis" [S1]. It was developed to address the challenges of reconstructing dynamic scenes from LiDAR data, specifically focusing on temporal consistency and geometric accuracy [S1]. The method builds on the idea of using flow MLPs for motion estimation, as seen in prior works cited in the source [S1].
