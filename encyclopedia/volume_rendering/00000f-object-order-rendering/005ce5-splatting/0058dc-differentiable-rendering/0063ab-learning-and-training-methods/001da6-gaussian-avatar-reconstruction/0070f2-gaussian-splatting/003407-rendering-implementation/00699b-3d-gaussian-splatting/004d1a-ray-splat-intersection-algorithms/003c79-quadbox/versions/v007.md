# QuadBox


## Overview
QuadBox is a Gaussian-tile intersection method that uses four axis-aligned bounding boxes (AABBs) to tightly encapsulate projected 2D Gaussians, reducing tile over-approximation and redundant computations in the rasterizer preprocess stage [S1]. It sets itself apart from its siblings by replacing the single conservative AABB (used in standard 3DGS) and the single adaptive AABB (used in AdR-Gaussian) with four symmetrically positioned, adaptively stretched sub-boxes that better fit the anisotropic shape of the ellipse [S1]. This tight fit suppresses empty tile coverage along the minor axis, while the accompanying QPass algorithm ensures deterministic, cache-friendly tile traversal with minimal per-tile overhead [S1].

## How it works
**Inputs:**
*   Set of 3D Gaussians $\{\mathcal{G}_i\}_{i=1}^N$, each defined by mean $\boldsymbol{\mu}_i$, 3D covariance $\boldsymbol{\Sigma}_i$, opacity $o_i$, and color $\mathbf{c}_i$ [S1].
*   Camera parameters for affine projection to screen space [S1].
*   Image resolution and tile size (typically $16 \times 16$ pixels) [S1].
*   Opacity threshold $\alpha_{\min}$ (typically $1/255$) [S1].

**Outputs:**
*   A list of tile-Gaussian pairs, where each Gaussian is assigned to the specific tiles it intersects, ready for the sort and render stages [S1].

**Data Structures:**
*   **QuadBox:** A structure containing four AABBs. Each AABB is defined by minimum and maximum integer tile coordinates $(t_{x,min}, t_{y,min})$ and $(t_{x,max}, t_{y,max})$.
*   **Inverse Covariance Matrix ($\Lambda$):** A $2 \times 2$ symmetric matrix $\Lambda = (\boldsymbol{\Sigma}^{2D})^{-1} = \begin{bmatrix} a & b \\ b & c \end{bmatrix}$, derived from the projected 2D covariance [S1].

**Steps:**

1.  **Initialization and Filtering:**
    *   Project each 3D Gaussian to 2D screen space using the affine transformation [S1].
    *   Compute the splatted opacity $\alpha_i$ at the Gaussian center.
    *   Filter out Gaussians where $\alpha_i < \alpha_{\min}$ to ensure numerical stability [S1].

2.  **Compute Inverse Covariance and Threshold:**
    *   Calculate $\Lambda = (\boldsymbol{\Sigma}^{2D})^{-1}$ with entries $a, b, c$ [S1].
    *   Compute the threshold $\gamma$ from the confidence inequality:
        $$ 2 \ln\left(\frac{\theta_i}{\alpha_{\min}}\right) \leq (u - \boldsymbol{\mu}_i^{2D})(\boldsymbol{\Sigma}_i^{2D})^{-1}(u - \boldsymbol{\mu}_i^{2D})^\top $$
        where $\theta_i$ is the opacity and $u$ is the pixel coordinate [S1]. In the context of the ellipse equation $F(x_d, y_d) \leq 0$, $\gamma$ is the constant term derived from this inequality [S1].

3.  **DualBox Extraction (Major Axis Alignment):**
    *   Identify the major axis of the ellipse defined by $\Lambda$ [S1].
    *   Extract the two quadrants of the adaptive AABB (AdR-AABB) that are aligned with the major axis [S1]. This suppresses empty tile coverage along the minor axis [S1].

4.  **Adaptive Stretching (QuadBox Construction):**
    *   Compute the stretching factor $f$ using the purely algebraic closed form:
        $$ f = \sqrt{1 - \frac{b^2}{ac}} $$
        This factor depends only on $a, b, c$ and is independent of $\gamma$ and center translation [S1]. Note that $0 < f \leq 1$ [S1].
    *   Compute the maximal extents $x_{\max}$ and $y_{\max}$ along the coordinate axes:
        $$ x_{\max} = \sqrt{\frac{\gamma c}{ac - b^2}}, \quad y_{\max} = \sqrt{\frac{\gamma a}{ac - b^2}} $$
        [S1]
    *   Construct four sub-boxes symmetrically positioned around the Gaussian center. The dimensions of these sub-boxes are adaptively stretched by $f$ to tightly enclose the elliptical projection [S1].

5.  **QPass Tile Traversal:**
    *   **Step 1:** Compute the global tile range using simple integer divisions based on the QuadBox bounds [S1].
    *   **Step 2:** Scan along the shorter axis. For each scanline, aggregate the active tile interval using fast min/max tests over the intersecting sub-boxes [S1].
    *   **Step 3:** Perform tile intersection checks using simple integer comparisons for each tile in the aggregated range. This ensures each tile is visited exactly once [S1].

**Pseudocode:**

```python
import math

def compute_stretching_factor(a, b, c):
    """
    Computes the stretching factor f = sqrt(1 - b^2 / (a*c)).
    Inputs: a, b, c are entries of Lambda = (Sigma_2D)^-1.
    Returns: f, where 0 < f <= 1.
    """
    # Guard against division by zero or negative determinant
    det = a * c - b * b
    if det <= 0:
        return 1.0 # Fallback for degenerate cases, though Lambda is positive definite
    
    val = 1.0 - (b * b) / (a * c)
    # Clamp to [0, 1] for numerical stability
    val = max(0.0, min(1.0, val))
    return math.sqrt(val)

def compute_max_extents(gamma, a, b, c):
    """
    Computes x_max and y_max extents of the ellipse.
    Inputs: gamma is the threshold, a, b, c are entries of Lambda.
    Returns: (x_max, y_max)
    """
    det = a * c - b * b
    if det <= 0:
        return 0.0, 0.0
        
    x_max = math.sqrt((gamma * c) / det)
    y_max = math.sqrt((gamma * a) / det)
    return x_max, y_max

def quadbox_preprocess(gaussian, alpha_min, tile_size):
    """
    Preprocesses a single Gaussian to determine intersecting tiles.
    gaussian: object with .mu_2d, .sigma_2d, .opacity
    alpha_min: float, threshold (e.g., 1/255)
    tile_size: int, size of a tile in pixels (e.g., 16)
    """
    # 1. Initialization
    # Project to 2D and compute opacity at center (omitted as per standard 3DGS pipeline)
    # Filter low opacity Gaussians
    if gaussian.opacity < alpha_min:
        return []

    # 2. Compute Lambda and Gamma
    # Lambda = (Sigma_2D)^-1
    # For 2x2 matrix [[s11, s12], [s21, s22]], inverse is 1/det * [[s22, -s12], [-s21, s11]]
    s11, s12, s21, s22 = gaussian.sigma_2d
    det_sigma = s11 * s22 - s12 * s21
    if det_sigma <= 0:
        return []
    
    a = s22 / det_sigma
    b = -s12 / det_sigma
    c = s11 / det_sigma
    
    # Gamma derivation from confidence inequality:
    # 2 * ln(theta / alpha_min) <= (u - mu)^T * Lambda * (u - mu)
    # The ellipse equation is ax^2 + 2bxy + cy^2 <= gamma
    # Here gamma corresponds to 2 * ln(theta / alpha_min)
    gamma = 2.0 * math.log(gaussian.opacity / alpha_min)
    
    if gamma <= 0:
        return []

    # 3. DualBox and QuadBox Construction
    # Compute stretching factor
    f = compute_stretching_factor(a, b, c)
    
    # Compute max extents
    x_max, y_max = compute_max_extents(gamma, a, b, c)
    
    # The QuadBox consists of 4 sub-boxes.
    # The exact construction of the 4 sub-boxes from x_max, y_max and f
    # involves splitting the bounding region along the major axis and stretching.
    # For implementation, we approximate the bounding box of the 4 sub-boxes
    # or compute the integer tile bounds for each sub-box.
    
    # Center in pixel coordinates
    cx, cy = gaussian.mu_2d
    
    # Convert extents to tile coordinates
    # Note: The paper describes deriving tile-aligned boxes.
    # We compute the bounding box of the ellipse and then refine with f.
    # A simplified implementation of the "four AABBs" logic:
    # The paper states the boxes are symmetrically positioned around the center.
    # We calculate the integer tile range for the overall extent first.
    
    # Global tile range calculation (QPass Step 1)
    # Bounds in pixels
    x_min_px = cx - x_max
    x_max_px = cx + x_max
    y_min_px = cy - y_max
    y_max_px = cy + y_max
    
    # Convert to tile indices
    t_x_min = math.floor(x_min_px / tile_size)
    t_x_max = math.ceil(x_max_px / tile_size)
    t_y_min = math.floor(y_min_px / tile_size)
    t_y_max = math.ceil(y_max_px / tile_size)
    
    # QPass Algorithm
    # Step 2: Scan along shorter axis
    # Determine which axis is shorter in terms of tile count
    if (t_x_max - t_x_min) < (t_y_max - t_y_min):
        # Scan along Y (rows)
        tiles = []
        for ty in range(t_y_min, t_y_max + 1):
            # Aggregate active tile interval for this row
            # This requires checking intersection of the 4 sub-boxes with the row ty
            # For simplicity, we assume the aggregated interval is [t_x_min, t_x_max]
            # refined by the sub-box intersections.
            # In a full implementation, one would compute the intersection of the 
            # ellipse with the horizontal line at ty, then map to tiles.
            # The paper uses fast min/max tests over intersecting sub-boxes.
            
            # Placeholder for precise sub-box interval aggregation
            # interval_min, interval_max = aggregate_subbox_interval(ty, cx, cy, x_max, y_max, f, tile_size)
            interval_min = t_x_min
            interval_max = t_x_max
            
            for tx in range(interval_min, interval_max + 1):
                tiles.append((tx, ty))
    else:
        # Scan along X (columns)
        tiles = []
        for tx in range(t_x_min, t_x_max + 1):
            # Aggregate active tile interval for this column
            # interval_min, interval_max = aggregate_subbox_interval(tx, cx, cy, x_max, y_max, f, tile_size)
            interval_min = t_y_min
            interval_max = t_y_max
            
            for ty in range(interval_min, interval_max + 1):
                tiles.append((tx, ty))
                
    return tiles
```

**Edge Cases and Pitfalls:**
*   **Numerical Stability:** Gaussians with very low opacity can cause instability. This is handled by filtering Gaussians with opacity $\alpha < \alpha_{\min}$ [S1].
*   **Computational Overhead:** Excessive use of square roots ($\sqrt{}$) and division operations inflates computational overhead. The method uses a purely algebraic closed form for $f$ to avoid these operations where possible [S1].
*   **Degenerate Input:** If the determinant of the covariance matrix is zero or negative, the inverse is undefined. The pseudocode includes guards for this [G].

## Operating characteristics
*   **Time Complexity:** The preprocessing step involves computing the inverse covariance and bounding box extents, which is $O(1)$ per Gaussian. The QPass traversal is $O(T)$ where $T$ is the number of tiles visited, which is significantly reduced compared to standard 3DGS due to tighter bounding boxes.
*   **Memory Complexity:** $O(N)$ to store the Gaussian primitives and their associated QuadBox data structures.
*   **Measured Performance:** QuadBox achieves an average over 1.8× speedup compared to standard 3DGS on Mip-NeRF 360, Tanks & Temples, and Deep Blending datasets [S1]. It outperforms AdR-Gaussian's AABB algorithm by 1.85× [S1].
*   **Strengths:** Tighter fit reduces redundant tile checks and warp divergence. The QPass algorithm is branch-free and cache-friendly [S1].
*   **Limitations:** The method requires computing the inverse covariance matrix and deriving the stretching factor, which adds some preprocessing overhead compared to the simplest AABB methods, though this is mitigated by the algebraic closed form [S1].
*   **When to use:** When rendering speed is critical and the scene contains many anisotropic Gaussians. It is particularly effective when the standard AABB over-approximation leads to significant redundant computations [S1].

## Background
QuadBox was introduced in the paper "QuadBox: Accelerating 3D Gaussian Splatting with Geometry-Aware Boxes" [S1]. It addresses the inefficiency of conservative bounding boxes in 3D Gaussian Splatting rasterization pipelines [S1]. The method builds on the concept of adaptive bounding boxes (AdR-Gaussian) but improves upon them by using four sub-boxes to better capture the anisotropic shape of the Gaussian projection [S1].
