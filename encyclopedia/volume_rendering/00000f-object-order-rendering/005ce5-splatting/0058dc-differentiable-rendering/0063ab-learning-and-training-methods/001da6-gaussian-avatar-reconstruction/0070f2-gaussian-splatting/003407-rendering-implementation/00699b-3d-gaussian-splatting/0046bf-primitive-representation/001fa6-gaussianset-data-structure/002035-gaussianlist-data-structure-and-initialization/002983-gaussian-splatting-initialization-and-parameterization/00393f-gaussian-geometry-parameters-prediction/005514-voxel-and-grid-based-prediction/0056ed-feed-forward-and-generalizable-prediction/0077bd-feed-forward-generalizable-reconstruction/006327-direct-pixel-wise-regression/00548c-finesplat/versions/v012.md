# FineSplat

Also called: Detailed Splats, Fine Patches, Local Groups

## Overview
FineSplat is a feed-forward 3D Gaussian Splatting framework that predicts a set of 3D Gaussian primitives from $N$ context views (with or without known poses) using a two-stage dual-grouping strategy [S1, unofficial]. It balances local detail preservation with global multi-view reasoning by dividing input views into fine-grained $4 \times 4$ patches and employing view-wise token grouping in Stage 1, followed by 3D spatial grouping in Stage 2 [S1, unofficial]. Unlike sibling methods that use coarser patches (e.g., $14 \times 14$) or global attention, FineSplat avoids the prohibitive cost of global multi-view attention while maintaining fine-grained visual information through serialized attention in 3D space [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** $N$ context views $I \in \mathbb{R}^{N \times H \times W \times 3}$, optionally with known camera poses. Images are normalized and resized to a fixed resolution for encoding [S1, unofficial].
*   **Output:** A set of 3D Gaussian primitives defined by mean position $\mu_i$, scale $s_i$, rotation $r_i$, opacity $\alpha_i$, and color $c_i$ [S1, unofficial].

**Data Structures:**
*   **Tokens:** $z \in \mathbb{R}^{M \times d}$, where $M = N \cdot (H/p) \cdot (W/p)$ is the number of fine-grained tokens, $p$ is the patch size, and $d$ is the token dimension [S1, unofficial].
*   **Gaussians:** Each token predicts $K$ Gaussian primitives. In FineSplat, $K=4$ per $4 \times 4$ token, corresponding to four non-overlapping $2 \times 2$ sub-patches [S1, unofficial].

**Parameters:**
*   $p$: Patch size. Default is $4 \times 4$ [S1, unofficial].
*   $T$: Number of iterative refinement steps in Stage 2. Default is 4 [S1, unofficial].
*   $s$: Sub-patch stride. Default is 2 (for $4 \times 4$ tokens divided into $2 \times 2$ sub-patches) [S1, unofficial].
*   $N$: Number of input context views. Training samples $N \in \{6, 12, 24, 32\}$ [S1, unofficial].
*   $S$: Size of groups for serialized attention in 3D spatial grouping [S1, unofficial].

**Algorithm:**

1.  **Scene Normalization:** To handle scale ambiguity in feed-forward reconstruction, normalize scene scale using context camera poses. Express poses in the mean context camera frame and rescale translations so all context camera centers lie within $[-1, 1]^3$ [S1, unofficial].

2.  **Stage 1: View-Wise Token Grouping:**
    *   Extract multi-scale features $F^l$ for $l \in \{1, 2, 3\}$ (finest to coarsest) from input images using a shared encoder [S1, unofficial].
    *   Fuse features into $M$ fine-grained tokens $z^{(0)}$ using Equation (1) [S1, unofficial]:
        $$ z^{(0)} = \text{fuse}\left(\text{up}\left(\text{fuse}\left(\text{up}(F^3) + F^2\right)\right)\right) + F^1 $$
        where $\text{up}(\cdot)$ is bilinear upsampling and $\text{fuse}(\cdot)$ is a convolutional fusion block [S1, unofficial].
    *   Encode tokens using view-wise token grouping based on the Multi-View Pyramid (MVP) architecture. This performs fine-grained attention within small view groups and exchanges information across all views via coarser global tokens [S1, unofficial].

3.  **Stage 2: 3D Spatial Token Grouping (Iterative Refinement for $t = 1 \dots T$):**
    *   **Gaussian Prediction:** Decode tokens $z^{(t-1)}$ into an initial set of Gaussians using a lightweight Gaussian head $\mathcal{D}$ (linear decoder). For each token, predict 4 Gaussians, one for each $2 \times 2$ sub-patch [S1, unofficial].
    *   **Patch-Aligned Sub-Pixel Gaussian Reconstruction:**
        *   For a sub-patch with center $(u_c, v_c)$, learn a 2D image-space offset $\Delta = (\Delta_x, \Delta_y)$ [S1, unofficial].
        *   Bound the offset to keep Gaussians within their sub-patch:
            $$ \delta_x = 2s \tanh(\Delta_x), \quad \delta_y = 2s \tanh(\Delta_y) $$
            where $s=2$ is the sub-patch stride, ensuring $\delta_x, \delta_y \in [-s/2, s/2]$ [S1, unofficial].
        *   Compute displaced coordinate $(u, v) = (u_c, v_c) + \delta$ [S1, unofficial].
        *   Unproject $(u, v)$ using predicted camera intrinsics to get a direction vector. Transform and normalize this direction using camera-to-world rotation, using camera translation as the ray origin to determine $\mu_i$ [S1, unofficial].
    *   **Error Feature Computation:**
        *   Render the predicted Gaussians into every context view $n$ to get rendered images $\hat{I}_n$ [S1, unofficial].
        *   Compute signed pixel error map $E_n = \hat{I}_n - I_n$ [S1, unofficial].
        *   Compute feature-level difference $\Delta \phi_n = \phi(\hat{I}_n) - \phi(I_n)$ using a pretrained ResNet-18 encoder $\phi(\cdot)$ [S1, unofficial].
        *   Combine with finest-scale features $F_n^1$ from Stage 1 via linear embeddings $E_{\text{err}}$ and $E_{\text{feat}}$ to form error feature map $F_n^{\text{err}}$ [S1, unofficial]:
            $$ F_n^{\text{err}} = [E_{\text{err}}(E_n, \Delta \phi_n); E_{\text{feat}}(F_n^1)] \in \mathbb{R}^{(H/p) \times (W/p) \times d_e} $$
            where $[\cdot; \cdot]$ represents feature concatenation [S1, unofficial].
    *   **Error Aggregation:**
        *   For each token, gather two error signals:
            1.  $e_{\text{self}}$: Self error feature from the patch where the token is predicted.
            2.  $e_{\text{agg}}$: Aggregated error feature averaged over all context views where the token is visible (projected onto error feature maps and filtered by frustum/occlusion) [S1, unofficial].
    *   **3D Spatial Grouping:**
        *   Lift tokens to 3D space using their predicted Gaussian centers [S1, unofficial].
        *   Order tokens along a space-filling curve and partition them into groups of $S$ consecutive points [S1, unofficial].
        *   Apply serialized self-attention within each 3D group to exchange error signals with neighbors [S1, unofficial].
        *   Use four attention blocks in Stage 2, each using a different space-filling curve, so each token meets a different set of neighbors [S1, unofficial].
        *   Update tokens:
            $$ \Delta z_j^{(t)} = \text{Linear}(\text{SerialAttn}(h_j^{(t)})) $$
            $$ z_j^{(t)} = z_j^{(t-1)} + \Delta z_j^{(t)} $$
            where $h_j^{(t)}$ is the concatenated feature of token $j$ including error signals [S1, unofficial].
    *   Repeat steps 3.1–3.5 for $T$ steps. FineSplat uses $T=4$ [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** FineSplat is efficient due to its dual-grouping strategy. Stage 1 uses local view-wise attention, and Stage 2 uses serialized attention in 3D, avoiding global multi-view attention costs [S1, unofficial]. It is faster than explicit k-nearest-neighbor search for 3D grouping [S1, unofficial].
*   **Memory Complexity:** Depends on the number of tokens $M$ and Gaussians. FineSplat uses a small primitive budget (e.g., 62K Gaussians for 6 views on DL3DV) [S1, unofficial].
*   **Performance:**
    *   DL3DV (6 views): 27.325 PSNR, 0.871 SSIM, 0.115 LPIPS with 62K Gaussians [S1, unofficial].
    *   RE10K (6 views): 27.394 PSNR, 0.886 SSIM, 0.116 LPIPS with 75K Gaussians [S1, unofficial].
    *   Mip-NeRF 360 (128 views): 23.463 PSNR, 0.706 SSIM, 0.214 LPIPS with 1.6M Gaussians [S1, unofficial].
*   **Strengths:** High quality with fine-grained details, efficient reconstruction time, strong generalization to unseen datasets (zero-shot) [S1, unofficial].
*   **Limitations:** Quality may degrade if Stage 1 alone is used for large scenes with many views due to blind spots between view groups [S1, unofficial]. No depth supervision is used, relying on pose normalization for scale [S1, unofficial].
*   **When to use:** Novel view synthesis where high fidelity and efficiency are required, especially with a small number of context views [S1, unofficial].
*   **When not to use:** If depth supervision is available and preferred, or if global multi-view attention is feasible and necessary for very large scenes [S1, unofficial].

## Background
FineSplat was introduced in 2026 [S1, unofficial]. It is trained on the DL3DV dataset and evaluated on DL3DV, RealEstate10K, and Mip-NeRF 360 [S1, unofficial]. The method addresses the trade-off between fine-grained multi-view reasoning and computational cost in feed-forward 3D Gaussian Splatting [S1, unofficial].
