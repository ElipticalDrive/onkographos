# 3D Gaussian Splatting Optimization

Also called: 3DGS Gradient Update, 3DGS Training Step, Adam Optimization for Gaussians, Backpropagation and Optimization

## Overview
3D Gaussian Splatting Optimization is the iterative training process that minimizes the difference between rendered images and ground-truth observations by adjusting the parameters of a set of 3D Gaussians. It solves the problem of learning scene geometry and appearance from multi-view images by treating the Gaussian parameters as differentiable variables. Unlike sibling methods that focus on rasterization speed or specific rendering artifacts, this method focuses on the gradient computation and parameter update logic, specifically leveraging Stochastic Gradient Descent (SGD) with the Adam optimizer to converge on a high-fidelity scene representation [S1, unofficial].

## How it works
The optimization loop operates on a per-step basis, processing a single randomly selected camera view to provide stochastic gradient descent [S1, unofficial].

**Inputs:**
- A set of $N$ 3D Gaussians, each defined by position $\mathbf{x} \in \mathbb{R}^3$, covariance matrix $\Sigma \in \mathbb{R}^{3 \times 3}$ (or quaternion $\mathbf{q}$ and scale $\mathbf{s}$), opacity $\alpha \in [0, 1]$, and spherical harmonic coefficients for color $\mathbf{c}$.
- A target image $I_{target}$ and its corresponding camera pose and intrinsics.
- The current rendered image $I_{render}$ (computed by the [3D Gaussian Splatting Differentiable Rasterizer](2813-3d-gaussian-splatting-differentiable-rasterizer.md)).

**Outputs:**
- Updated Gaussian parameters ($\mathbf{x}, \Sigma, \alpha, \mathbf{c}$) for the next iteration.

**Data Structures:**
- **Gaussian Parameters:** Stored in contiguous arrays or structures of arrays (SoA) for GPU efficiency.
    - Position: 3 floats.
    - Rotation: 4 floats (quaternion).
    - Scale: 3 floats.
    - Opacity: 1 float.
    - Color: $K \times 3$ floats (where $K$ is the number of SH bands).
- **Optimizer State (Adam):** For each parameter type, maintain running averages of first moment ($m$) and second moment ($v$) of gradients.

**Numbered Steps:**

1. **Render:** Compute the rendered image $I_{render}$ using the differentiable rasterizer. This involves projecting 3D Gaussians to 2D, sorting them by depth, and alpha compositing colors [S1, unofficial].
2. **Compute Loss:** Calculate the pixel-wise error between $I_{render}$ and $I_{target}$. Common losses include L1 loss and D-SSIM (Differential Structural Similarity) [S1, unofficial]. Let $L$ be the scalar loss value.
3. **Backpropagation:** Propagate the error backward through the differentiable path.
    - Start with the gradient of the loss with respect to the pixel colors: $\frac{\partial L}{\partial I_{render}}$.
    - Propagate through the alpha compositing equation to get gradients for the 2D Gaussian colors and opacities.
    - Propagate through the 2D projection and covariance transformation to get gradients for the 3D Gaussian parameters (position, scale, rotation, opacity, and SH coefficients) [S1, unofficial].
    - The chain rule is applied to every parameter of every Gaussian that contributed to the rendered pixels.
4. **Update Parameters:** Use the Adam optimizer to update the parameters.
    - Adam maintains exponential moving averages of the gradients ($m_t$) and squared gradients ($v_t$).
    - Bias-corrected estimates are computed.
    - Parameters are updated using an adaptive per-parameter learning rate. Different parameter types (e.g., position vs. opacity) use different base learning rates because the magnitude of change required for position (spatial) differs from opacity (intensity) [S1, unofficial].

**Pseudocode:**

```python
def optimize_step(gaussians, camera, target_image, optimizer_state):
    # 1. Render the current scene
    # Returns rendered image and intermediate buffers for backprop
    rendered_image, render_buffers = rasterize(gaussians, camera)
    
    # 2. Compute Loss
    # L1 loss between rendered and target
    loss = l1_loss(rendered_image, target_image)
    
    # 3. Backpropagation
    # Compute gradient of loss w.r.t rendered image
    grad_rendered = gradient_l1_loss(rendered_image, target_image)
    
    # Backprop through rasterizer to get gradients for Gaussian parameters
    # This function implements the chain rule through alpha compositing and projection
    grad_params = differentiable_rasterizer_backward(render_buffers, grad_rendered)
    
    # 4. Update Parameters using Adam
    for param_type in ['position', 'rotation', 'scale', 'opacity', 'color']:
        param = gaussians[param_type]
        grad = grad_params[param_type]
        
        # Get base learning rate for this parameter type
        base_lr = get_base_learning_rate(param_type)
        
        # Update Adam state and apply step
        # Adam update rule:
        # m_t = beta1 * m_{t-1} + (1 - beta1) * grad
        # v_t = beta2 * v_{t-1} + (1 - beta2) * grad^2
        # m_hat = m_t / (1 - beta1^t)
        # v_hat = v_t / (1 - beta2^t)
        # param = param - lr * m_hat / (sqrt(v_hat) + epsilon)
        
        gaussians[param_type] = adam_update(
            param, 
            grad, 
            optimizer_state[param_type], 
            base_lr
        )
        
    return loss
```

**Edge Cases and Pitfalls:**
- **Precision:** Gradients for position and scale can vary significantly in magnitude. Using a single learning rate for all parameters leads to poor convergence. Separate base learning rates are required [S1, unofficial].
- **Stochasticity:** Using a single camera per step introduces noise. This is intentional for SGD but requires careful learning rate scheduling [S1, unofficial].
- **Degenerate Gaussians:** If a Gaussian becomes too small or too large, gradients may become unstable. This is often handled by densification/culling strategies (see Subtopics) rather than the optimizer itself.

## Subtopics

### SplaTAM
SplaTAM is an RGB-D Simultaneous Localization and Mapping (SLAM) method that represents the scene as a 3D Gaussian Splatting (3DGS) model [S2]. It solves the problem of online mapping and tracking by jointly optimizing camera poses and Gaussian parameters using depth and photometric constraints [S2]. It is distinguished from sibling methods like Gaussian-SLAM and Gaussian Splatting SLAM by its use of view-independent colors and a specific densification mask strategy to prevent duplicate Gaussian creation [S1, unofficial].

### [Gaussian-SLAM](9195-gaussian-slam.md)
Gaussian-SLAM is a keyframe-based Simultaneous Localization and Mapping (SLAM) method that constructs a scene representation using 3D Gaussians and employs sub-map fusion to manage global consistency. It distinguishes itself from sibling methods like SplaTAM, which relies on depth-assisted ICP for tracking, by utilizing a specific scale regularization loss to enforce isotropic Gaussians, thereby stabilizing the joint optimization of camera poses and map geometry.

### [Gaussian Splatting SLAM](10078-gaussian-splatting-slam.md)
Gaussian Splatting SLAM is a simultaneous localization and mapping method that jointly optimizes camera poses and a 3D Gaussian scene representation from monocular or RGB-D video streams. It distinguishes itself from siblings like [SplaTAM](9193-splatam.md) and [Gaussian-SLAM](9195-gaussian-slam.md) by explicitly enforcing isotropic scale regularization to stabilize localization and mapping, and by utilizing a covisibility-based keyframing strategy for efficient map management.

### [Differentiable Pose Estimation](12756-differentiable-pose-estimation.md)
Differentiable pose estimation optimizes camera poses by back-propagating photometric loss gradients through a 3D Gaussian Splatting (3DGS) renderer. It solves the problem of recovering accurate camera motion, particularly in scenarios involving motion blur, by treating pose as a differentiable variable within the rendering pipeline. It sets itself apart from sibling methods like SplaTAM and Gaussian-SLAM by explicitly decoupling the pose optimization from the scene geometry update in specific implementations (e.g., Deblur-GS), utilizing a simplified gradient derivation that ignores covariance and color terms to ensure stability during short optimization steps.

### GS-SLAM
GS-SLAM is a SLAM method that proposes an adaptive 3D Gaussian expanding strategy to add new 3D Gaussians into the training stage and delete unreliable ones with captured depths and rendered opacity values [S2]. On the Replica dataset, GS-SLAM achieves PSNR 31.56, SSIM 0.97, and LPIPS 0.094 [S2].

## Operating characteristics
- **Time Complexity:** Each optimization step is dominated by the forward rasterization and backward pass, which is $O(N \cdot P)$ where $N$ is the number of Gaussians and $P$ is the number of pixels. The Adam update is $O(N)$.
- **Memory Complexity:** Requires storing gradients and optimizer states for all Gaussian parameters. For $N$ Gaussians with $K$ SH bands, memory is $O(N \cdot (3 + 4 + 3 + 1 + 3K))$.
- **Performance:** Converges in tens of thousands of steps. The stochastic nature (single camera per step) allows for parallel gradient computation on GPU, enabling fast training times compared to full-batch methods [S1, unofficial].
- **Strengths:** High-quality novel view synthesis; differentiable nature allows for joint optimization of geometry and appearance.
- **Limitations:** Requires careful tuning of learning rates for different parameter types; prone to overfitting if not regularized; densification strategies are critical for long-term stability [S1, unofficial].

## Background
The method originates from the 3D Gaussian Splatting paper by Kerbl et al. (2023), which introduced the differentiable rasterization pipeline that makes this optimization possible [S1, unofficial]. The use of Adam optimizer and stochastic gradient descent is standard in deep learning but adapted here for explicit geometric primitives. Subsequent works like SplaTAM, Gaussian-SLAM, and GS-SLAM have extended this optimization framework to SLAM tasks, introducing additional constraints and densification strategies [S2].
