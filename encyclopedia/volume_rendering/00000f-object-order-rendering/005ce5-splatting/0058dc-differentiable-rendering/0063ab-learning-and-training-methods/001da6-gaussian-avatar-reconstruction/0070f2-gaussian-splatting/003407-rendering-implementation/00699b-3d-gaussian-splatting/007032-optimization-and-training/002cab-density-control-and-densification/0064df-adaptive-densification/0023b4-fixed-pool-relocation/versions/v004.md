# Fixed-Pool Relocation

Also called: Component Recycling, Dynamic Operations, Relocating low opacity components to high opacity component

## Overview
Fixed-Pool Relocation redistributes a fixed budget of splats every 50 iterations to improve coverage by moving low-importance components to areas of high reconstruction error without increasing the total component count [S1, unofficial]. It identifies splats with low importance scores and relocates them to local maxima of the positive reconstruction residual $(V - \hat{V})_+$, reinitializing them to explore new geometry [S1, unofficial]. Unlike [Adaptive Densification](3034-adaptive-densification.md), which increases the component count via cloning and splitting, Fixed-Pool Relocation maintains a constant budget by recycling existing components [S1, unofficial].

## How it works
**Inputs:**
- Current splat pool with positions $\mu$, covariances/scales $\sigma$, opacities $O$, and Adam optimizer states ($m, v$) [S1, unofficial].
- View volume $V$ and reconstructed volume $\hat{V}$ [S1, unofficial].
- Configuration parameters: relocation interval (50 iterations), max relocations (64), cooldown (≥1 step), culling fraction (0.1% to 5%) [S1, unofficial].

**Outputs:**
- Updated splat pool with relocated positions, reinitialized scales, zeroed optimizer states, and periodic Morton reordering [S1, unofficial].

**Data Structures:**
- **Splat Pool:** List of splats. Each splat stores `mu` (3D position), `sigma` (isotropic scale in voxels), `opacity` (scalar), `adam_m` and `adam_v` (Adam moments), and `last_relocated_iter` (iteration index for cooldown) [S1, unofficial].
- **Residual Volume:** 3D grid storing the positive reconstruction residual $(V - \hat{V})_+$ [S1, unofficial].

**Steps:**

1. **Identify Candidates:** Compute an importance score $a_k$ for each splat $k$, proportional to amplitude times approximate volume ($L_{k,ii}$) [S1, unofficial]. Sort splats by this score and select the bottom 1% that sit at low residual [S1, unofficial]. Limit the selection to at most 64 splats per step, ensuring at most one splat is selected per detected residual peak [S1, unofficial].
2. **Find Relocation Targets:** Compute the positive reconstruction residual $R = (V - \hat{V})_+$ [S1, unofficial]. Find local maxima of $R$ using non-maximum suppression over the volume [S1, unofficial].
3. **Relocate and Reinitialize:** For each selected splat $k$: move its position $\mu_k$ to a local residual maximum [S1, unofficial]. Reinitialize the scale isotropically to $\sigma = 0.5$ voxels [S1, unofficial]. Zero the Adam first- and second-moment estimates ($m = 0, v = 0$) [S1, unofficial]. Update `last_relocated_iter` to the current iteration [S1, unofficial].
4. **Opacity Preservation (Component Recycling):** When relocating $N$ new components to the location of an old component ($\mu_{new} = \mu_{old}$), preserve the total distribution by adjusting opacity [S2]. The new opacity $O_{new}$ is calculated from the old opacity $O_{old}$ using $(1 - O_{new})^N = (1 - O_{old})$, or $O_{new} = 1 - (1 - O_{old})^{1/N}$ [S2].
5. **Cooldown:** Enforce a cooldown period of at least 1 relocation step to prevent the same splat from being relocated again before it adapts [S1, unofficial].
6. **Cache Reordering:** Every 1,000 iterations, reorder splats along a Morton (Z-order) curve to improve GPU cache locality [S1, unofficial].
7. **Conservative Culling (Post-Fitting):** After fitting completes, perform a single pass of conservative culling to remove splats accounting for the lowest fraction of cumulative amplitude [S1, unofficial]. The default retention is 99.9% (removing 0.1%), though 5% removal is used in some Python API defaults [S1, unofficial].

**Pseudocode:**

```python
def fixed_pool_relocation(splats, residual_volume, current_iter, config):
    # config: relocation_interval=50, max_relocations=64, cooldown=1, culling_fraction=0.001
    if current_iter % config['relocation_interval'] != 0:
        return splats

    # Step 1: Identify candidates (bottom 1% by importance, at most 64)
    # Importance score a_k proportional to amplitude times approximate volume (L_k,ii) [S1, unofficial]
    scores = [s.amplitude * s.volume for s in splats]
    sorted_indices = sorted(range(len(scores)), key=lambda i: scores[i])
    num_candidates = max(1, int(len(splats) * 0.01))
    candidates = sorted_indices[:num_candidates]

    # Limit to max_relocations (one per detected residual peak) [S1, unofficial]
    candidates = candidates[:config['max_relocations']]

    # Filter by cooldown [S1, unofficial]
    valid_candidates = [i for i in candidates if current_iter - splats[i].last_relocated_iter >= config['cooldown']]

    # Step 2: Find relocation targets via non-maximum suppression on positive residual [S1, unofficial]
    # Compute positive residual R = (V - V_hat)_+
    positive_residual = [max(0, v - vh) for v, vh in zip(residual_volume.V, residual_volume.V_hat)]
    peaks = non_maximum_suppression(positive_residual, threshold=0.0)

    # Assign peaks to candidates
    assignments = list(zip(valid_candidates, peaks[:len(valid_candidates)]))

    for splat_idx, peak_pos in assignments:
        splat = splats[splat_idx]

        # Step 3: Relocate position to peak [S1, unofficial]
        splat.mu = peak_pos

        # Reinitialize isotropically at sigma = 0.5 voxels [S1, unofficial]
        splat.sigma = 0.5

        # Zero Adam first- and second-moment estimates [S1, unofficial]
        splat.adam_m = [0.0, 0.0, 0.0]
        splat.adam_v = [0.0, 0.0, 0.0]

        # Update cooldown timestamp [S1, unofficial]
        splat.last_relocated_iter = current_iter

    # Step 6: Cache reordering every 1000 iterations [S1, unofficial]
    if current_iter % 1000 == 0:
        splats = morton_sort(splats)

    return splats

def non_maximum_suppression(values, threshold):
    peaks = []
    for i in range(1, len(values) - 1):
        if values[i] > values[i-1] and values[i] > values[i+1] and values[i] > threshold:
            peaks.append(i)
    return peaks

def morton_sort(points):
    # Reorder points along a Morton (Z-order) curve for GPU cache locality [S1, unofficial]
    return sorted(points, key=lambda p: morton_encode(p.mu))

def morton_encode(point):
    # Standard 3D Morton (Z-order) encoding
    x, y, z = point
    x = (x | (x << 16)) & 0x0000FFFF0000FFFF
    x = (x | (x << 8)) & 0x00FF00FF00FF00FF
    x = (x | (x << 4)) & 0x0F0F0F0F0F0F0F0F
    x = (x | (x << 2)) & 0x3333333333333333
    x = (x | (x << 1)) & 0x5555555555555555
    y = (y | (y << 16)) & 0x0000FFFF0000FFFF
    y = (y | (y << 8)) & 0x00FF00FF00FF00FF
    y = (y | (y << 4)) & 0x0F0F0F0F0F0F0F0F
    y = (y | (y << 2)) & 0x3333333333333333
    y = (y | (y << 1)) & 0x5555555555555555
    z = (z | (z << 16)) & 0x0000FFFF0000FFFF
    z = (z | (z << 8)) & 0x00FF00FF00FF00FF
    z = (z | (z << 4)) & 0x0F0F0F0F0F0F0F0F
    z = (z | (z << 2)) & 0x3333333333333333
    z = (z | (z << 1)) & 0x5555555555555555
    return x | (y << 1) | (z << 2)
```

## Subtopics

### Primitive Relocation (Densification)
A variant where relocation is used to densify rather than just redistribute. When a primitive with opacity $o$, circumradius $R$, and sharpness $\sigma$ is replaced by $N$ co-located copies, the new opacity is computed as $o_{\text{new}} = 1 - (1 - o)^{1/N}$ [S3]. For $N=2$ (standard densification), one child is placed at the sampled position, and the other is offset in the primitive's tangent plane by $\eta \epsilon$, where $\epsilon \sim \mathcal{N}(0, I)$ and $\eta$ is a noise scale [S3]. The scale (circumradius) is corrected to maintain the rendered image using the denominator $D = \sum_{i=1}^{N}\sum_{k=0}^{i-1} \binom{i-1}{k}(-1)^k \frac{o_{\text{new}}^{k+1}}{(\sigma(k+1)+1)(\sigma(k+1)+2)}$ and the formula $R_{\text{new}} = R \sqrt{\frac{o}{(\sigma+1)(\sigma+2) \cdot D}}$ [S3]. This variant is chosen when the goal is to increase density in under-reconstructed regions while strictly preserving the visual output of the parent primitive before splitting [S3].

## Operating characteristics
- **Time and Memory Complexity:** Not given in the sources [G]. The method runs every 50 iterations with a maximum of 64 relocations per step [S1, unofficial]. Morton reordering occurs every 1,000 iterations [S1, unofficial].
- **Performance:** Maintains a fixed memory footprint, unlike densification methods that grow $N$ [S1, unofficial]. The 50-iteration interval balances responsiveness with computational overhead [S1, unofficial].
- **Strengths:** Prevents unbounded growth of Gaussian count. Effective for filling holes in sparse reconstructions without adding memory pressure [S1, unofficial].
- **Limitations:** The fixed budget may limit detail in very complex scenes compared to unbounded densification [S1, unofficial].
- **When to use:** Memory-constrained applications, microscopy data (Luxar), or when a strict upper bound on primitive count is required [S1, unofficial].
- **When not to use:** Scenes requiring extremely high detail that exceeds the fixed budget's capacity [S1, unofficial].

## Background
Fixed-Pool Relocation is described in the Luxar framework for microscopy and scientific data visualization [S1, unofficial]. The mechanism is also referred to as Dynamic Operations in that context [S1, unofficial]. The opacity preservation rule for component recycling appears in 3D Student Splatting [S2]. The scale correction variant for primitive relocation is detailed in Fourier Splatting [S3]. The method addresses the problem of inefficient coverage in sparse initializations or regions with high reconstruction error, without the memory overhead of traditional densification [S1, unofficial].
