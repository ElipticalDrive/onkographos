# AnySplat Pipeline

Also called: Feed-forward 3D Gaussian Splatting from Unconstrained Views

## Overview
AnySplat is a feed-forward generalizable reconstruction method that predicts a set of 3D Gaussians directly from uncalibrated input images without per-scene optimization [S1, unofficial]. It differs from sibling methods by explicitly predicting camera poses and depth maps alongside Gaussian parameters, using pseudo-geometry priors from a pretrained VGGT model for supervision, and employing a differentiable voxelization module to handle the transition from pixel-wise predictions to a renderable primitive set [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A batch of $K$ uncalibrated RGB images $I \in \mathbb{R}^{1 \times K \times 3 \times 448 \times 448}$ [S1, unofficial].
*   **Outputs:** A set of 3D Gaussians $\mathcal{G}$ and predicted camera poses (extrinsic $E$ and intrinsic $K$) [S1, unofficial].

**Data Structures:**
The model outputs a list of Gaussian parameters. Each Gaussian is defined by:
*   Mean $\mu \in \mathbb{R}^3$
*   Scale $s \in \mathbb{R}^3$
*   Rotation $r$ (quaternion or 6D representation, implied by $\sigma$)
*   Color $c$ (Spherical Harmonics coefficients or RGB)
*   Opacity $\alpha$

**Steps:**
1.  **Feature Encoding:** Input images are processed by a transformer-based geometry encoder to extract multi-scale features [S1, unofficial].
2.  **Parameter Prediction:** Three decoder heads ($F_G, F_D, F_C$) predict:
    *   $F_G$: Gaussian parameters $(\mu, \sigma, r, s, c)$ [S1, unofficial].
    *   $F_D$: Depth map $D$ [S1, unofficial].
    *   $F_C$: Camera poses $p$ [S1, unofficial].
3.  **Gaussian Construction:** Pixel-wise 3D Gaussians are constructed from the predicted parameters [S1, unofficial].
4.  **Differentiable Voxelization:** The pixel-wise Gaussians are voxelized into pre-voxel 3D Gaussians using a Differentiable Voxelization module [S1, unofficial]. This step aggregates and filters primitives to create a stable representation for rendering.
5.  **Rendering:** Multi-view images and depth maps are rendered from the voxelized Gaussians using differentiable rasterization [S1, unofficial].
6.  **Loss Computation:**
    *   **RGB Loss:** Rendered images are compared against ground truth images using an L1 or similar pixel-wise loss [S1, unofficial].
    *   **Geometry Loss:** Rendered depth maps, decoded depth $D$, and predicted poses $p$ are used to compute geometry losses [S1, unofficial].
    *   **Pseudo-Geometry Supervision:** Geometries are supervised by pseudo-geometry priors obtained from a pretrained VGGT model [S1, unofficial].

## Subtopics

### [SubSplat](13524-subsplat.md)
SubSplat is a method for high-resolution novel-view synthesis that resolves the trade-off between network computational cost and rendering fidelity in pixel-aligned 3D Gaussian Splatting. It solves the problem of insufficient Gaussian density and artifacts when using low-resolution backbone inputs by introducing a Sub-pixel Gaussian Reparameterizer (SPGR). Unlike prior methods limited by fixed grids or image-space upsamplers, SubSplat subdivides each grid-anchored primary Gaussian into multiple fine-grained sub-pixel primitives, restoring structural density directly from low-resolution features while maintaining stable network latency.

### [Deformable Radial Kernel (DRK)](13699-deformable-radial-kernel-drk.md)
Deformable Radial Kernel (DRK) Splatting is a 3D scene representation method that replaces the fixed radial symmetry of Gaussian primitives with a flexible planar kernel defined by multiple radial basis functions. It solves the overparameterization and geometric fidelity limitations of Gaussian Splatting by allowing adaptive stretching, rotation, and sharp boundary control, enabling high-fidelity rendering with significantly fewer primitives. Unlike standard 2D Gaussian Splatting, which relies on smooth, elliptical distributions, DRK supports straight edges and sharp corners through L1/L2 norm blending and piecewise edge sharpening.

## Operating characteristics
*   **Time Complexity:** Inference is feed-forward, making it significantly faster than per-scene optimization methods like original 3D Gaussian Splatting. Training time depends on the dataset size and the complexity of the VGGT prior computation.
*   **Memory Complexity:** Memory usage is dominated by the number of predicted Gaussians and the voxel grid resolution. The differentiable voxelization module adds some overhead but helps manage memory by filtering primitives.
*   **Performance:** Achieves high-fidelity novel-view synthesis on unconstrained views. Performance is limited by the accuracy of the predicted camera poses and depth maps, especially in textureless or repetitive regions.
*   **Strengths:** No per-scene optimization required; handles uncalibrated inputs; leverages strong geometric priors from VGGT.
*   **Limitations:** Relies on the quality of the pretrained VGGT model; may struggle with extreme view angles or occlusions not covered by the training data.

## Background
AnySplat was introduced by InternRobotics as a feed-forward generalizable reconstruction method [S1, unofficial]. It builds on the principles of 3D Gaussian Splatting and extends them to handle unconstrained views by predicting camera poses and depth maps. The method uses pseudo-geometry priors from a pretrained VGGT model to supervise the geometry, enabling robust reconstruction without per-scene optimization.
