# 3D Gaussian Splatting Training Loop

Also called: Render-Compare-Correct Loop

## Overview
The 3D Gaussian Splatting (3DGS) training loop is an iterative optimization process that minimizes the photometric difference between rendered images and ground-truth training views by adjusting the parameters of a set of 3D Gaussians. It distinguishes itself from blind search methods by using stochastic gradient descent to compute precise update directions for millions of parameters simultaneously, leveraging a differentiable rasterizer to propagate errors back to the 3D primitives [S2, unofficial].

## How it works
**Inputs:** A set of training images with known camera poses (typically recovered via Structure-from-Motion), and an initial set of 3D Gaussians $\mathcal{G} = \{g_i\}_{i=1}^N$.
**Outputs:** Optimized Gaussian parameters (position, covariance, opacity, spherical harmonics coefficients) and a final scene representation.

**Data Structures:**
Each Gaussian $i$ is defined by:
*   Position $\mathbf{p}_i \in \mathbb{R}^3$
*   Covariance $\Sigma_i$, parameterized by rotation quaternion $\mathbf{q}_i \in \mathbb{R}^4$ and scale vector $\mathbf{s}_i \in \mathbb{R}^3$.
*   Opacity $\alpha_i \in [0, 1]$.
*   Spherical Harmonics (SH) coefficients $\mathbf{c}_{i, l}$ for view-dependent color.

**Numbered Steps:**
1.  **Sampling:** Randomly select one training image and its corresponding camera pose from the dataset [S2, unofficial][S1].
2.  **Rendering:** Transform the 3D Gaussians from canonical space to the observation space (camera space) and render a 2D image $\hat{I}$ using the differentiable Gaussian rasterizer [S1][S2, unofficial].
3.  **Loss Computation:** Compute the per-image loss $\mathcal{L}$ between the rendered image $\hat{I}$ and the ground-truth image $I_{gt}$ [S2, unofficial][S1].
4.  **Backpropagation:** Compute gradients $\nabla \mathcal{L}$ with respect to all Gaussian parameters using automatic differentiation through the rasterizer [S2, unofficial][S1].
5.  **Update:** Update the Gaussian parameters using the Adam optimizer [S1][S2, unofficial].
6.  **Densification/Pruning:** Periodically (every $k$ iterations), evaluate gradient magnitudes and opacity thresholds to split high-gradient Gaussians or prune low-opacity ones, adapting the density of the representation [S1][S2, unofficial].

**Formulas:**
The total loss $\mathcal{L}$ is a weighted sum of the L1 loss and the differentiable Structural Similarity (D-SSIM) loss [S2, unofficial][S1]:
$$ \mathcal{L}_{img} = (1 - \lambda) \mathcal{L}_{L1} + \lambda \mathcal{L}_{D-SSIM} $$
where $\mathcal{L}_{L1}$ is the average absolute difference between corresponding pixel colors, and $\mathcal{L}_{D-SSIM}$ measures local structure, contrast, and texture [S2, unofficial]. The weight $\lambda$ is typically 0.2 [S2, unofficial][S1].

**Parameters:**
*   **Optimizer:** Adam with $\beta_1 = 0.9$ and $\beta_2 = 0.99$ [S1][S2, unofficial].
*   **Iteration Budget:** Training typically runs for a fixed number of iterations, commonly around 30,000 [S2, unofficial].
*   **Loss Weight:** $\lambda \approx 0.2$ [S2, unofficial][S1].

**Edge Cases and Pitfalls:**
*   **Stopping Criterion:** The process does not stop at a specific loss threshold because the loss curve continues to creep down with diminishing returns. A fixed iteration budget is used instead [S2, unofficial].
*   **Initialization:** For specific applications like human avatars, Gaussians may be initialized using SMPL model vertex positions and skinning weights [S1].
*   **Evaluation:** To judge generalization, hold-out views not seen during training should be rendered and compared against real photos using metrics like PSNR, SSIM, and LPIPS [S2, unofficial][S1].

**Pseudocode:**
```python
def train_3dgs(Gaussians, TrainingData, Iterations=30000, Lambda=0.2):
    # Initialize optimizer with Adam (beta1=0.9, beta2=0.99)
    optimizer = Adam(Gaussians.parameters(), lr=initial_lr)
    
    for step in range(Iterations):
        # 1. Sampling
        image, camera_pose = TrainingData.random_sample()
        
        # 2. Rendering
        # Transform Gaussians to observation space and rasterize
        rendered_image = DifferentiableRasterizer(Gaussians, camera_pose)
        
        # 3. Loss Computation
        # Compute L1 and D-SSIM losses
        l1_loss = L1Loss(rendered_image, image)
        ssim_loss = DSSIMLoss(rendered_image, image)
        loss = (1 - Lambda) * l1_loss + Lambda * ssim_loss
        
        # 4. Backpropagation
        optimizer.zero_grad()
        loss.backward()
        
        # 5. Update
        optimizer.step()
        
        # 6. Densification/Pruning (Periodic)
        if step % densification_interval == 0:
            Gaussians.densify_and_prune()
            
    return Gaussians
```

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of Gaussians and pixels per iteration. The fixed iteration budget (e.g., 30,000) makes total time predictable but potentially long for high-resolution scenes [S2, unofficial].
*   **Memory Complexity:** Proportional to the number of Gaussians $N$ and the resolution of the SH coefficients. Densification increases memory usage over time [S1].
*   **Strengths:** Efficient gradient-based optimization allows for simultaneous correction of millions of parameters, avoiding the inefficiency of random search [S2, unofficial].
*   **Limitations:** The loss curve has diminishing returns, requiring a fixed iteration budget rather than a convergence threshold [S2, unofficial].

## Background
The method originates from the 3D Gaussian Splatting framework, which introduced differentiable rasterization for 3D Gaussians. The training loop conceptually follows a "Render, Compare, Correct" cycle, leveraging stochastic gradient descent to optimize the scene representation from multi-view images [S2, unofficial]. It builds on earlier work in differentiable rendering and Gaussian splatting [S1].
