# Speedy-Splat Rendering Pipeline

Also called: Speedy-Splat

## Overview
The Speedy-Splat rendering pipeline is a CUDA-based optimization for 3D Gaussian Splatting that replaces coarse bounding box culling with precise geometric intersection tests and a parallel tile-sorting architecture to reduce redundant pixel computations [S1]. It distinguishes itself from standard rasterization by explicitly addressing the overestimation of Gaussian extents and model overparameterization, ensuring that only Gaussians with significant contribution to specific tiles are processed during the pixel-wise compositing stage [S1].

## How it works
The pipeline operates on a tile-based rasterization model, dividing the image into fixed-size tiles (typically $16 \times 16$ pixels) [S1]. The method consists of a preprocessing phase to identify and sort relevant Gaussians, followed by a pixel-parallel rendering kernel.

### Inputs and Outputs
*   **Inputs:**
    *   Set of 3D Gaussians $\mathcal{G}$, each defined by 3D mean $\mu_i$, 3D covariance $\Sigma_i$, opacity $\sigma_i$, and spherical harmonic coefficients for color $c_i$.
    *   Camera parameters (view and projection matrices).
    *   Image resolution and tile dimensions.
*   **Outputs:**
    *   Final image color buffer $C(p)$ for each pixel $p$.

### Data Structures
1.  **Key Array:** Stores pairs of `(tile_index, depth)` for every Gaussian-tile intersection. The size of this array equals the total number of intersecting Gaussian-tile pairs.
2.  **Value Array:** Stores the Gaussian index corresponding to each key.
3.  **Tile Ranges:** An array indicating the start and end indices in the sorted Key/Value arrays for each tile.

### Numbered Steps

1.  **Precise Tile Intersection (duplicateWithKeys):**
    For each Gaussian $G_i$, compute its projected 2D mean $\mu_{i_{2D}}$ and covariance $\Sigma_{i_{2D}}$ [S1]. Unlike standard methods that use an Axis-Aligned Bounding Box (AABB) derived from the maximum eigenvalue, Speedy-Splat performs precise intersection tests to determine which tiles the Gaussian actually covers [S1]. For each intersecting tile $t$, generate a key consisting of the tile index and the Gaussian's depth $z_i$ [S1].

2.  **Inclusive Sum (InclusiveSum):**
    Compute the prefix sum of the number of intersecting tiles per Gaussian to allocate the exact size for the Key and Value arrays [S1].

3.  **Sorting (RadixSort):**
    Sort the Key array using a CUDA Radix Sort primitive. The sorting order is primarily by tile index, and secondarily by Gaussian depth (ascending) [S1]. This ensures that for any given tile, the Gaussians are ordered from front to back.

4.  **Tile Range Identification (identifyTileRanges):**
    Process the sorted Key array to determine the contiguous range of indices in the Key/Value arrays that correspond to each tile [S1]. This allows the render kernel to quickly locate the relevant Gaussians for a specific tile.

5.  **Pixel Rendering (Render Kernel):**
    The render kernel is parallelized across pixels. For each pixel $p$:
    a. Identify the tile $t$ containing $p$.
    b. Retrieve the range of Gaussians for tile $t$ from the sorted arrays.
    c. Iterate through the Gaussians in depth order.
    d. Compute the projected 2D Gaussian value $g_i$ at pixel $p$:
       $$ g_i = e^q $$
       $$ q = -\frac{1}{2}(p - \mu_{i_{2D}})\Sigma_{i_{2D}}^{-1}(p - \mu_{i_{2D}})^T $$
       where $p$ is the pixel coordinate, $\mu_{i_{2D}}$ is the 2D mean, and $\Sigma_{i_{2D}}^{-1}$ is the inverse 2D covariance [S1].
    e. Compute the alpha value $\alpha_i(p)$:
       $$ \alpha_i(p) = \sigma_i g_i(p) $$
       where $\sigma_i$ is the Gaussian opacity [S1].
    f. **Thresholding:** If $\alpha_i > 255$, include the Gaussian in the compositing. Note: The source specifies a threshold of 255, implying a fixed-point or scaled integer representation of alpha, or a specific implementation detail where alpha is compared against an integer threshold [S1].
    g. **Compositing:** Accumulate the color using front-to-back blending:
       $$ C(p) = \sum_{i \in \mathcal{N}} c_i \alpha_i(p) \prod_{j=1}^{i-1} (1 - \alpha_j(p)) $$
       where $\mathcal{N}$ is the set of Gaussians in the tile that passed the threshold, sorted by depth [S1].

```python
# Preprocessing Phase
def preprocess_gaussians(gaussians, camera, image_dims):
    # 1. Precise Intersection
    keys = []
    values = []
    for i, g in enumerate(gaussians):
        # Project 3D Gaussian to 2D
        mu_2d, Sigma_2d = project_2d(g.mu_3d, g.Sigma_3d, camera)
        depth = g.mu_3d.z # Or appropriate depth metric
        
        # Find intersecting tiles using precise geometry
        intersecting_tiles = find_precise_intersecting_tiles(mu_2d, Sigma_2d, image_dims)
        
        for tile_idx in intersecting_tiles:
            keys.append((tile_idx, depth))
            values.append(i)
            
    # 2. Inclusive Sum to determine array sizes
    tile_counts = count_tiles_per_gaussian(gaussians)
    offsets = inclusive_sum(tile_counts)
    
    # 3. Radix Sort
    # Sort keys by tile_idx (primary) and depth (secondary)
    sorted_indices = radix_sort(keys)
    sorted_keys = [keys[i] for i in sorted_indices]
    sorted_values = [values[i] for i in sorted_indices]
    
    # 4. Identify Tile Ranges
    tile_ranges = compute_ranges(sorted_keys)
    
    return sorted_keys, sorted_values, tile_ranges

# Rendering Phase
def render_pixel(p, sorted_keys, sorted_values, tile_ranges, gaussians):
    tile_idx = get_tile_index(p, image_dims)
    start, end = tile_ranges[tile_idx]
    
    accumulated_alpha = 0.0
    final_color = (0.0, 0.0, 0.0)
    
    # Iterate through Gaussians in this tile, sorted by depth
    for k in range(start, end):
        g_idx = sorted_values[k]
        g = gaussians[g_idx]
        
        # Compute 2D Gaussian value at pixel p
        mu_2d, Sigma_2d_inv = get_projected_params(g, camera)
        q = -0.5 * dot((p - mu_2d), Sigma_2d_inv * (p - mu_2d).T)
        g_val = exp(q)
        
        # Compute alpha
        alpha = g.opacity * g_val
        
        # Threshold check (Source specifies > 255, assuming scaled int or specific impl)
        # In standard float [0,1], this condition would never be met.
        # Assuming the source implies a scaled integer representation or a typo for a small epsilon.
        # However, we must follow the source literally.
        if alpha > 255: 
            # Compositing
            color = g.color
            final_color += color * alpha * (1.0 - accumulated_alpha)
            accumulated_alpha += alpha * (1.0 - accumulated_alpha)
            
            # Early exit if fully opaque
            if accumulated_alpha >= 1.0:
                break
                
    return final_color
```

### Parameters and Edge Cases
*   **Alpha Threshold:** The source explicitly states the condition $\alpha_i > 255$ [S1]. In standard floating-point implementations where $\alpha \in [0, 1]$, this condition is impossible. This suggests either a fixed-point representation (e.g., 8-bit integer alpha where 255 is max) or a specific implementation detail not fully elaborated in the provided text [S1]. Implementers should verify the data type of $\alpha$ in the source code context.
*   **Precision:** The precise intersection test avoids false positives from AABB culling, reducing the number of Gaussians processed per pixel [S1].
*   **Degenerate Input:** If a Gaussian has a singular 2D covariance matrix, the inverse $\Sigma_{i_{2D}}^{-1}$ is undefined. Standard regularization or clamping of eigenvalues is required [G].

## Operating characteristics
*   **Time Complexity:** The sorting step dominates the preprocessing phase with $O(N \log N)$ complexity, where $N$ is the number of Gaussian-tile intersections. The rendering phase is $O(P \cdot K)$, where $P$ is the number of pixels and $K$ is the average number of Gaussians per tile after culling.
*   **Memory Complexity:** Requires storage for the Key and Value arrays, proportional to the number of intersections. This is typically larger than the number of Gaussians but smaller than the naive $P \times G$ matrix.
*   **Performance:** Speedy-Splat achieves significant speedups by reducing the number of Gaussians processed per pixel through precise culling and efficient parallel sorting [S1].
*   **Strengths:** Reduces overestimation of Gaussian extents; handles overparameterized models efficiently.
*   **Limitations:** The sorting step adds overhead; the alpha threshold condition ($>255$) requires careful implementation regarding data types.

## Background
Speedy-Splat was introduced in the paper "Speedy-Splat: Fast 3D Gaussian Splatting with Sparse Pixels and Sparse Primitives" [S1]. The method addresses inefficiencies in the standard 3D Gaussian Splatting pipeline, specifically the overestimation of Gaussian extents and the computational cost associated with overparameterized models [S1]. It builds on the tile-based rasterization model common in modern GPU architectures.
