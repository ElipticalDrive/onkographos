# AnySplat Pipeline

Also called: Feed-forward 3D Gaussian Splatting from Unconstrained Views

## Overview
AnySplat is a feed-forward, generalizable reconstruction method that predicts 3D Gaussian primitives directly from uncalibrated input images without iterative optimization [S1, unofficial]. It solves the problem of requiring calibrated camera poses and per-scene tuning by using a transformer-based encoder-decoder to jointly predict geometry, appearance, and camera parameters [S1, unofficial]. Unlike sibling methods that may rely on fixed grids or specific calibration constraints, AnySplat handles unconstrained views by predicting pixel-wise Gaussians and voxelizing them for stable rendering [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A tensor of $K$ uncalibrated images with shape $[1, K, 3, 448, 448]$ (batch, views, channels, height, width) [S1, unofficial].
*   **Outputs:** A set of 3D Gaussians (defined by mean $\mu$, covariance $\sigma$, rotation $r$, scale $s$, and color $c$) and predicted camera poses $p$ [S1, unofficial].

**Data Structures:**
The method constructs a set of pixel-wise 3D Gaussians. Each Gaussian is defined by:
*   $\mu \in \mathbb{R}^3$: Mean position.
*   $\sigma \in \mathbb{R}^3$: Standard deviation (related to covariance).
*   $r \in \mathbb{R}^4$: Rotation quaternion.
*   $s \in \mathbb{R}^3$: Scale factors.
*   $c \in \mathbb{R}^3$: Color (RGB).

These pixel-wise Gaussians are processed by a **Differentiable Voxelization** module to produce "pre-voxel 3D Gaussians" [S1, unofficial]. This step aggregates and regularizes the dense pixel-wise predictions into a voxel-based representation suitable for efficient rendering.

**Algorithm Steps:**
1.  **Encoding:** Pass the input image tensor through a transformer-based geometry encoder [S1, unofficial].
2.  **Decoding:** Three decoder heads ($F_G, F_D, F_C$) process the encoded features:
    *   $F_G$ predicts Gaussian parameters $(\mu, \sigma, r, s, c)$ [S1, unofficial].
    *   $F_D$ predicts a depth map $D$ [S1, unofficial].
    *   $F_C$ predicts camera poses $p$ [S1, unofficial].
3.  **Construction:** Construct a set of pixel-wise 3D Gaussians using the predicted parameters [S1, unofficial].
4.  **Voxelization:** Apply the Differentiable Voxelization module to convert pixel-wise Gaussians into pre-voxel 3D Gaussians [S1, unofficial].
5.  **Rendering:** Render multi-view images and depth maps from the voxelized Gaussians using standard differentiable splatting [S1, unofficial].
6.  **Loss Computation:**
    *   **RGB Loss:** Compare rendered images against ground truth images [S1, unofficial].
    *   **Geometry Loss:** Compute losses using rendered depth maps, decoded depth $D$, and predicted poses $p$ [S1, unofficial].
    *   **Pseudo-Geometry Prior:** Supervise geometries using priors from a pretrained VGGT model [S1, unofficial].
7.  **Optimization:** Update model weights to minimize the combined loss [S1, unofficial].

**Pseudocode:**
```python
import torch

def inference_step(model, image_paths, device):
    """
    Runs the AnySplat inference pipeline.
    :param model: The trained AnySplat model.
    :param image_paths: List of paths to input images.
    :param device: Torch device.
    :return: Gaussians and predicted camera poses.
    """
    # Load and preprocess images
    images = []
    for path in image_paths:
        img = load_and_process_image(path) # Assumes normalization to [-1, 1]
        images.append(img)
    
    # Stack images: [1, K, 3, 448, 448]
    images_tensor = torch.stack(images, dim=0).unsqueeze(0).to(device)
    
    # Run inference
    # Input normalization: (images + 1) * 0.5 converts from [-1, 1] to [0, 1]
    gaussians, pred_context_pose = model.inference((images_tensor + 1) * 0.5)
    
    return gaussians, pred_context_pose

def training_step(model, images, gt_images, gt_depths, vggt_priors, optimizer):
    """
    Single training step for AnySplat.
    """
    optimizer.zero_grad()
    
    # Forward pass
    gaussians, pred_context_pose = model.inference((images + 1) * 0.5)
    
    # Extract predictions
    pred_depth = pred_context_pose.get('depth', None) # F_D output
    pred_poses = pred_context_pose['extrinsic']        # F_C output
    pred_intrinsics = pred_context_pose['intrinsic']   # F_C output
    
    # Render
    rendered_images = render_gaussians(gaussians, pred_poses, pred_intrinsics)
    rendered_depths = render_depth(gaussians, pred_poses, pred_intrinsics)
    
    # Compute Losses
    # 1. RGB Loss
    rgb_loss = compute_rgb_loss(rendered_images, gt_images)
    
    # 2. Geometry Losses
    # Supervise rendered depth, decoded depth D, and poses p
    geometry_loss = compute_geometry_loss(
        rendered_depths, 
        pred_depth, 
        pred_poses, 
        gt_depths, 
        vggt_priors
    )
    
    total_loss = rgb_loss + geometry_loss
    total_loss.backward()
    optimizer.step()
    
    return total_loss.item()
```

**Parameters:**
*   Input resolution: $448 \times 448$ pixels [S1, unofficial].
*   Number of views $K$: Variable, depending on input set [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Uncalibrated Inputs:** The method assumes no prior camera calibration is provided; it predicts poses jointly [S1, unofficial].
*   **VGGT Dependency:** The quality of geometry supervision relies on the pretrained VGGT model for pseudo-geometry priors [S1, unofficial].
*   **Voxelization Artifacts:** The Differentiable Voxelization step is critical for stabilizing the dense pixel-wise Gaussians; improper voxel size may lead to loss of detail or artifacts [S1, unofficial].

## Subtopics

### [SubSplat](13524-subsplat.md)
SubSplat is a method for high-resolution novel-view synthesis that resolves the trade-off between network computational cost and rendering fidelity in pixel-aligned 3D Gaussian Splatting. It solves the problem of insufficient Gaussian density and artifacts when using low-resolution backbone inputs by introducing a Sub-pixel Gaussian Reparameterizer (SPGR). Unlike prior methods limited by fixed grids or image-space upsamplers, SubSplat subdivides each grid-anchored primary Gaussian into multiple fine-grained sub-pixel primitives, restoring structural density directly from low-resolution features while maintaining stable network latency.

### [Deformable Radial Kernel (DRK)](13699-deformable-radial-kernel-drk.md)
Deformable Radial Kernel (DRK) Splatting is a 3D scene representation method that replaces the fixed radial symmetry of Gaussian primitives with a flexible planar kernel defined by multiple radial basis functions. It solves the overparameterization and geometric fidelity limitations of Gaussian Splatting by allowing adaptive stretching, rotation, and sharp boundary control, enabling high-fidelity rendering with significantly fewer primitives. Unlike standard 2D Gaussian Splatting, which relies on smooth, elliptical distributions, DRK supports straight edges and sharp corners through L1/L2 norm blending and piecewise edge sharpening.

## Operating characteristics
*   **Time Complexity:** Feed-forward inference is fast as it avoids per-scene optimization. Training time depends on the transformer encoder-decoder size and the number of views [S1, unofficial].
*   **Memory Complexity:** Memory usage is dominated by the transformer model and the voxelized Gaussian representation. The voxelization step helps manage memory compared to storing all pixel-wise Gaussians [S1, unofficial].
*   **Performance:** Achieves high-fidelity novel-view synthesis from unconstrained views without calibration [S1, unofficial].
*   **Strengths:** No need for camera calibration; generalizable across scenes; fast inference [S1, unofficial].
*   **Limitations:** Relies on pretrained VGGT for geometry priors; performance may degrade in extreme unconstrained scenarios where VGGT priors are weak [S1, unofficial].
*   **When to use:** When camera poses are unknown or uncalibrated, and fast generalizable reconstruction is needed [S1, unofficial].
*   **When not to use:** When high-precision calibrated reconstruction is required, or when per-scene optimization is acceptable for higher fidelity [S1, unofficial].

AnySplat was introduced by InternRobotics as a feed-forward approach to 3D Gaussian Splatting that handles unconstrained views [S1, unofficial]. It builds on the principles of differentiable rendering and transformer-based geometry estimation [S1, unofficial]. The method integrates a differentiable voxelization module to stabilize the prediction of 3D Gaussians from image features [S1, unofficial].
