# Adaptive Pruning

Also called: Triangle Pruning based on Volume Rendering Weight

## Overview
Adaptive Pruning is a sparsification technique used in triangle-based splatting methods to reduce floaters and prevent overfitting by removing primitives that contribute negligibly to the rendered image [S1]. Unlike Gaussian Splatting methods that rely on opacity thresholds or gradient magnitudes, this method operates on the volume rendering blending weight ($T \cdot o$) of individual triangles [S1]. It is specifically designed to eliminate triangles that explain only small amounts of data within a single view, thereby improving the generalization of the radiance field representation [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of 3D triangle primitives $\mathcal{T} = \{t_1, \dots, M\}$ and a set of training views with known camera poses [S1].
*   **Output:** A filtered subset of triangles $\mathcal{T}' \subset \mathcal{T}$ with updated buffers [G].

**Data Structures:**
*   **Triangle Buffers:** Arrays storing vertex positions, normals, opacities, and colors for all active triangles [G].
*   **Weight Accumulator:** A buffer of size $M$ storing the maximum volume rendering weight observed for each triangle across all training views [S1].
*   **Render Count:** A buffer of size $M$ storing the number of views in which a triangle was rendered with more than one pixel of coverage [S1].

**Parameters:**
*   $\tau_{\text{prune}}$: User-defined threshold for the maximum volume rendering blending weight [S1].
*   `prune_interval`: Frequency of pruning execution, set to 200 steps [S2, unofficial].
*   `min_views`: Minimum number of views a triangle must be rendered in, set to 2 [S1].
*   `min_pixels`: Minimum pixel coverage required per view, set to 1 [S1].

**Steps:**
1.  **Weight Accumulation:** During rasterization for each training view, calculate the volume rendering blending weight for each triangle as $W = T \cdot o$, where $T$ is transmittance and $o$ is opacity [S1].
2.  **Update Max Weight:** For each triangle $t_i$, update its maximum observed weight: $W_{\max}(t_i) = \max(W_{\max}(t_i), W(t_i))$ [S1].
3.  **Update Render Count:** Increment a counter for each triangle that is rendered with more than one pixel of coverage in the current view [S1].
4.  **Pruning Execution:** Execute pruning every 200 steps if `step > 0`, `step % 200 == 0`, and `prune_threshold > 0` [S2, unofficial].
5.  **Filtering Criteria:** A triangle $t_i$ is pruned if it meets **any** of the following conditions: $W_{\max}(t_i) < \tau_{\text{prune}}$ or the number of views in which it was rendered with $>1$ pixel coverage is less than `min_views` [S1].
6.  **Buffer Compaction:** Create a boolean mask `alive` where `alive[i]` is true if $t_i$ is not pruned. Filter all triangle buffers using this mask to maintain contiguous memory [S2, unofficial].
7.  **Optimizer Reset:** Re-initialize the optimizers and learning rate scheduler to account for the change in the number of parameters [S2, unofficial].

**Pseudocode:**
```python
def adaptive_pruning(triangles, tau_prune, step, prune_interval=200, min_views=2, min_pixels=1):
    """
    Prunes triangles based on volume rendering weight and view coverage.
    """
    # Step 4: Check pruning condition
    if step <= 0 or step % prune_interval != 0 or tau_prune <= 0:
        return triangles

    # Step 5: Determine alive mask based on evidence [S1]
    # Prune if max weight < threshold OR rendered in < min_views with > min_pixels coverage
    alive_mask = (triangles.W_max >= tau_prune) & (triangles.view_counts >= min_views)

    # Step 6: Filter buffers if any triangles are removed
    if alive_mask.sum() < len(triangles):
        for key in triangles.buffers:
            triangles.buffers[key] = triangles.buffers[key][alive_mask]
        triangles.W_max = triangles.W_max[alive_mask]
        triangles.view_counts = triangles.view_counts[alive_mask]

    # Step 7: Re-initialize optimizers and learning rate scheduler [S2, unofficial]
    # Standard implementation: create new optimizer instance with updated parameter list
    # and reset scheduler state to match new parameter count
    triangles.optimizer = type(triangles.optimizer)(triangles.parameters(), lr=triangles.initial_lr)
    triangles.scheduler = type(triangles.scheduler)(triangles.optimizer)

    return triangles
```

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Strengths:** Effectively removes "floaters" (artifacts that appear in only one view) and reduces overfitting to training data [S1]. It is simpler than gradient-based densification as it relies on direct rendering contribution [S1].
*   **Limitations:** Requires tracking per-triangle statistics across all views, which adds memory overhead. The threshold $\tau_{\text{prune}}$ is user-defined and may require tuning [S1].
*   **When to use:** When using triangle-based splatting (e.g., Convex Splatting) and observing artifacts from overfitted primitives [S1].
*   **When not to use:** Not given in the sources.

## Background
Adaptive Pruning was introduced in the context of Triangle Splatting for Real-Time Radiance Field Rendering [S1]. It draws inspiration from the densification and pruning routines used in 3D Gaussian Splatting (3DGS) but adapts them to the triangle primitive representation [S1]. The method addresses the issue where the support of the window function can be significantly larger than the triangle, leading to potential overfitting if not managed [S1].
