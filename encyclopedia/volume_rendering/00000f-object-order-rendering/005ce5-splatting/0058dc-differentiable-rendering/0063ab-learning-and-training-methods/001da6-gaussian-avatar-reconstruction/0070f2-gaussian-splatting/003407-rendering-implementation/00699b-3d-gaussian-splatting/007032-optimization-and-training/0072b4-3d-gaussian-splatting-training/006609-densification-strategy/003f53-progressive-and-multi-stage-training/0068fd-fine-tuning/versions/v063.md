# Fine-tuning

Also called: 3DGS Fine-tuning, Fine-tuning Strategy, Gaussian Splatting Fine-tuning, Per-scene optimization

## Overview
Fine-tuning in the context of 3D Gaussian Splatting (3DGS) refers to a per-scene optimization process that refines an initial Gaussian representation to achieve high-fidelity reconstruction or adaptation to specific constraints. It typically follows an initialization phase (such as SfM point cloud generation or a feed-forward prediction) and involves optimizing geometry and color attributes using rendering losses [S1, S3]. It sets itself apart from static initialization methods by allowing dynamic densification (growing/pruning) and continuous parameter updates to converge to a local optimum that minimizes image-space error [S3].

## How it works
The fine-tuning process generally follows a two-phase structure: initialization followed by iterative optimization. The specific implementation varies depending on whether the method adapts a generative prior, handles multi-modal volumes, or performs style transfer.

### Inputs and Outputs
*   **Inputs:**
    *   Initial set of 3D Gaussians $\mathcal{G}_0 = \{g_1, \dots, g_N\}$ with initial means $\mu$, covariances $\Sigma$, opacities $\alpha$, and spherical harmonic (SH) coefficients $c$. These are derived from SfM points, a feed-forward network, or a generative model [S1, S3].
    *   A set of training images $I_{train}$ with known camera poses $P$.
    *   (Optional) A latent vector or point cloud encoding if using a generative prior [S1].
*   **Outputs:**
    *   Optimized set of 3D Gaussians $\mathcal{G}_{final}$ with refined attributes.
    *   (Optional) Multiple Gaussian sets $\{G_h\}$ for different visual modes in volumetric data [S4, unofficial].

### Data Structures
The core data structure is the set of 3D Gaussians. Each Gaussian $g_i$ is defined by:
*   Mean position $\mu_i \in \mathbb{R}^3$.
*   Covariance matrix $\Sigma_i \in \mathbb{R}^{3 \times 3}$, typically parameterized by a rotation matrix $R_i$ (quaternion) and a scaling vector $s_i \in \mathbb{R}^3$ such that $\Sigma_i = R_i S_i S_i^T R_i^T$ where $S_i = \text{diag}(s_i)$ [S3].
*   Opacity $\alpha_i \in [0, 1]$.
*   Spherical Harmonic coefficients $c_{i, l, m}$ for view-dependent color [S3].

### Numbered Steps

#### Standard Per-Scene Optimization (Vanilla 3DGS Fine-tuning)
1.  **Initialization:** Obtain an initial set of Gaussians. This may involve generating primitives via a feed-forward process where geometry and color are predicted, or using SfM points [S3].
2.  **Enable Densification:** Activate growing (cloning/splitting) and pruning mechanisms during the fine-tuning loop to manage the number of primitives [S3].
3.  **Optimization Loop:**
    *   Sample a batch of training views.
    *   Render the scene using differentiable rasterization to produce predicted images $\hat{I}$.
    *   Compute the loss $\mathcal{L}$ between $\hat{I}$ and ground truth $I$. The loss typically includes an L1 term and a D-SSIM term:
        $$ \mathcal{L} = (1 - \lambda) \mathcal{L}_1 + \lambda \mathcal{L}_{\text{D-SSIM}} $$
        where $\lambda$ is a weighting factor (typically 0.2) [S3].
    *   Backpropagate the loss to update $\mu, \Sigma, \alpha, c$.
    *   Apply densification heuristics (e.g., splitting Gaussians with high position gradients or low opacity) at specified intervals [S3].
4.  **Convergence:** Repeat until the loss converges or a maximum number of iterations is reached.

#### Generative Prior Fine-tuning (GPN)
1.  **Point Cloud Encoding:** Encode the input point cloud $X$ into a latent vector $z$ using a PointNet-like encoder $\epsilon$ [S1].
2.  **NeRF Conditioning:** Condition a NeRF network $\Phi_\phi$ on $z$ to generate an implicit scene representation [S1].
3.  **Voxelization:** Obtain a voxel representation of the object using volume density samples along rays [S1].
4.  **Mesh Reconstruction:** Reconstruct a mesh using the marching cubes method on the voxel grid [S1].
5.  **Color Prediction:** Predict the color for all vertices from the rendered nearest novel view using predefined novel camera poses [S1].
6.  **Per-Scene Optimization:** Treat the reconstructed mesh as a single-scene NeRF. Optimize the mesh geometry and color using the rendering loss $\mathcal{L}_{color}$ supervised by scanned color frames [S1].

#### Image-space Gaussian Fine-tuning (Multi-modal Volumes)
1.  **Transfer Function Selection:** Select a series of transfer functions $\{TF_h\}$, where each $TF_h$ is non-zero only within specific value intervals of the physical field $F$ and zero elsewhere [S4, unofficial].
2.  **Radiance Field Generation:** Generate radiance fields $RF_h = TF_h(F)$ for each mode $h$ [S4, unofficial].
3.  **Supervision Data Generation:** Render 64 images through volumetric integration for each radiance field $RF_h$ to provide supervision data [S4, unofficial].
4.  **Fine-tuning:** Compute the image-space loss (as defined in [26]) and backpropagate to update the Gaussian set $G_h$ for each mode [S4, unofficial].
5.  **Post-processing:** Concatenate or separately render the Gaussians $G_h$ for global and local visibility [S4, unofficial].

#### Style Transfer Fine-tuning (Ada-GS)
1.  **Stylized Input Generation:** Generate 2D stylized views of the scene using a style transfer algorithm (e.g., AdaIN) [S5].
2.  **Direct Training:** Train vanilla 3DGS directly on these 2D stylized images as ground truth supervision [S5].
    *   *Note:* This requires training from scratch for every new style image, limiting practical usability [S5].

### Parameters
*   **Learning Rate:** Typically $1 \times 10^{-3}$ for Adam optimizer [S3].
*   **Loss Weighting:** $\lambda$ for D-SSIM is typically 0.2 [S3].
*   **Transfer Functions:** In multi-modal volume fine-tuning, 5 transfer functions are typically selected per volume [S4, unofficial].

### Edge Cases and Pitfalls
*   **Overfitting to Input Views:** Standard 3DGS optimization can overfit to input views, leading to artifacts in novel views. Fine-tuning with regularization or priors helps mitigate this [S1, S3].
*   **Style Consistency:** In style transfer, training on 2D stylized images independently can lead to multi-view inconsistencies. Methods like Ada-GS preserve details but lack consistency compared to methods that optimize 3D structure directly [S5].
*   **Redundancy:** Initial feed-forward Gaussians may be redundant. Fine-tuning should include pruning to reduce memory consumption while maintaining fidelity [S3].

## Subtopics

### Image-space Gaussian Fine-tuning
A fine-tuning process for volumetric data that accounts for different visual modes by generating multiple radiance fields using different transfer functions. It optimizes separate Gaussian sets against rendered images for each mode, allowing for global and local visibility control [S4, unofficial].

### Ada-GS
A baseline method for 3D Gaussian Splatting in Style that trains vanilla 3DGS directly on 2D stylized images. It preserves better details than GS-Ada but requires training from scratch for every new style image, limiting its practical usability [S5].

## Operating characteristics
*   **Time Complexity:** Fine-tuning is iterative and depends on the number of training views and iterations. Vanilla 3DGS fine-tuning typically takes several hours to converge on standard scenes [S3]. Generative fine-tuning (GPN) involves additional mesh reconstruction and NeRF optimization steps, increasing complexity [S1].
*   **Memory Complexity:** Depends on the number of Gaussians. Fine-tuning with densification can increase the number of primitives, requiring more memory. Pruning mechanisms help mitigate this [S3].
*   **Strengths:** Achieves high photorealism and can leverage pretrained priors for faster convergence [S3]. Allows for per-scene adaptation to specific constraints or styles [S1, S5].
*   **Limitations:** Can be computationally expensive. Style transfer via 2D supervision may lack multi-view consistency [S5]. Generative methods may introduce artifacts if the prior is mismatched [S1].
*   **When to Use:** When high-fidelity reconstruction is required for a specific scene, or when adapting a general model to a specific domain (e.g., style transfer, volumetric visualization) [S1, S3, S5].

## Background
Fine-tuning in 3D Gaussian Splatting evolved from the need to refine initial sparse reconstructions into dense, high-quality representations. Early methods relied on static SfM points, but fine-tuning allowed for dynamic densification and optimization [S3]. The concept of per-scene optimization was adapted from NeRF methods, where a global model is fine-tuned on a specific scene to improve quality [S1]. Multi-modal fine-tuning was introduced to handle complex volumetric data with varying visual modes [S4, unofficial]. Style transfer methods explored the application of fine-tuning to artistic domains, highlighting the trade-offs between 2D and 3D supervision [S5].
