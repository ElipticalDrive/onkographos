# Compact 3D Gaussian Representation (C3DGS)

## Overview
Compact 3D Gaussian Representation (C3DGS) is a method for reducing the memory footprint and storage requirements of 3D Gaussian Splatting (3DGS) by eliminating redundant primitives and compressing attributes via spatial sharing [S1]. It addresses the excessive storage costs of standard 3DGS, which often exceed 1 GB for large scenes, by introducing a volume-based masking strategy to prune non-essential Gaussians and using a hash-based neural field for colors and a codebook for geometry [S1]. Unlike 3DGS, which stores unique per-Gaussian attributes, C3DGS exploits spatial redundancy to achieve over 25× compression while maintaining or improving reconstruction quality [S1].

## How it works
**Inputs:** Initial set of 3D Gaussians $\{G_i\}$ from a 3DGS training pipeline, including position $\mathbf{p}_i$, scale $\mathbf{s}_i$, rotation $\mathbf{q}_i$, opacity $\alpha_i$, and spherical harmonic (SH) coefficients $\mathbf{c}_i$.
**Outputs:** A compact representation consisting of:
1. A subset of active Gaussians with pruned attributes.
2. A hash-based grid neural field $\mathcal{F}_{grid}$ for view-dependent color.
3. A geometry codebook $\mathcal{C}_{geo}$ and per-Gaussian indices $k_i$.

**Data Structures:**
1. **Active Gaussian List:** Stores $\mathbf{p}_i$, $\alpha_i$, and indices $k_i$ for active Gaussians.
2. **Hash Grid ($\mathcal{F}_{grid}$):** A multi-resolution hash table (Instant NGP style) mapping 3D coordinates to feature vectors. The feature vector is processed by a small MLP to output SH coefficients.
3. **Geometry Codebook ($\mathcal{C}_{geo}$):** A fixed-size table of prototype scale/rotation vectors. Each entry stores a scale vector $\mathbf{s}_k$ and rotation quaternion $\mathbf{q}_k$.

**Steps:**
1. **Volume-Based Masking (Pruning):**
   During training, a learnable mask $m_i \in \{0, 1\}$ is associated with each Gaussian $G_i$. The mask is optimized to identify and remove Gaussians that have minimal impact on the rendering loss. This reduces the total number of Gaussians $N$ without sacrificing performance, directly lowering computational complexity which is linear in $N$ [S1].

2. **Color Compression via Hash Grid:**
   Instead of storing SH coefficients $\mathbf{c}_i$ for each Gaussian, the view-dependent color is computed by querying the hash grid $\mathcal{F}_{grid}$ at the Gaussian's position $\mathbf{p}_i$.
   - Let $\mathcal{H}(\mathbf{p}_i)$ be the hash lookup for position $\mathbf{p}_i$.
   - The color feature $\mathbf{f}_i$ is extracted from the grid.
   - An MLP $\mathcal{M}$ maps $\mathbf{f}_i$ to SH coefficients: $\mathbf{c}_i = \mathcal{M}(\mathbf{f}_i)$.
   - This replaces $O(N)$ storage for colors with the fixed size of the hash grid [S1].

3. **Geometry Compression via Codebook:**
   Scale $\mathbf{s}_i$ and rotation $\mathbf{q}_i$ are quantized to indices in a codebook $\mathcal{C}_{geo}$.
   - For each Gaussian, find the codebook entry $k_i$ that minimizes the reconstruction error of $\mathbf{s}_i$ and $\mathbf{q}_i$.
   - Store only the index $k_i$ (e.g., 8-16 bits) instead of the full float vectors.
   - The actual scale and rotation are retrieved as $\mathbf{s}_i = \mathcal{C}_{geo}[k_i].\mathbf{s}$ and $\mathbf{q}_i = \mathcal{C}_{geo}[k_i].\mathbf{q}$ [S1].

4. **Training Optimization:**
   The total loss includes the standard rendering loss plus regularization terms for the mask $m_i$ and codebook quantization error. The hash grid and codebook are updated via backpropagation [S1].

**Parameters:**
- **Hash Grid Resolution:** Uses Instant NGP multi-resolution hash grid. Specific resolution levels are not given in the sources [S1].
- **Codebook Size:** Not given in the sources [S1].
- **Masking Rate:** The target reduction in Gaussian count is learned, not fixed [S1].

**Edge Cases and Pitfalls:**
- **Sparse Regions:** The hash grid may struggle in sparse regions where neighboring Gaussians are far apart, as spatial coherence is lower. This is a known limitation addressed by variants like OMG [S1].
- **Quantization Error:** Codebook quantization introduces approximation errors in geometry. The codebook size must be large enough to capture geometric diversity but small enough to save space [S1].

## Operating characteristics
- **Storage:** Achieves >25× compression compared to standard 3DGS [S1]. On the Deep Blending dataset, storage efficiency is enhanced by over 28× [S1]. General datasets show ~15× reduction [S1].
- **Speed:** Rendering speed increases by nearly 40% on Deep Blending due to fewer Gaussians and efficient grid lookups [S1].
- **Quality:** Maintains or improves PSNR over 3DGS [S1].
- **Complexity:** Spatial complexity is reduced from $O(N)$ for attributes to $O(1)$ for color (grid size) and $O(N)$ for indices [S1]. Computational complexity is linear in the number of *active* Gaussians [S1].

## Background
C3DGS was proposed to address the critical memory and storage issues in 3D Gaussian Splatting, which often require >1 GB for large scenes [S1]. It builds on the observation that standard densification produces redundant Gaussians and that spatial redundancy in color and geometry can be exploited [S1]. The method uses Instant NGP for the hash grid [S1].
