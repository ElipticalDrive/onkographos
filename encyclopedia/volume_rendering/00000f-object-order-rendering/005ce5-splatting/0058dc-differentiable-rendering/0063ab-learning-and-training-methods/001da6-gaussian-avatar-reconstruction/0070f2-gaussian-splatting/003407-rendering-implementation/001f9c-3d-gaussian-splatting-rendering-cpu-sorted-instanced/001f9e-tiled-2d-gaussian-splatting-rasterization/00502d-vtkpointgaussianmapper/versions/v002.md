# vtkPointGaussianMapper

Also called: PointGaussianMapper, vtkOpenGLPointGaussianMapper

## Overview
`vtkPointGaussianMapper` renders point clouds as simple points or anisotropic 3D Gaussian splats without requiring `verts` cells, supporting per-point scale, rotation, opacity, and emissive properties [S1, unofficial]. Unlike sibling methods that rely on GPU-parallel tile-based rasterization or transmittance culling, it operates in object-order using standard OpenGL blending and a vertex shader for EWA projection [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   Input: A `vtkPolyData` object containing point positions [S1, unofficial]. If `verts` cells are present, only points referenced by these cells are drawn; otherwise, all points are drawn [S1, unofficial].
*   Output: A rendered image of points or Gaussian splats [S1, unofficial].

**Data Structures:**
*   **Position Array:** Float positions [S1, unofficial]. If no shift/scale is applied to the VBO, these are uploaded directly [S1, unofficial].
*   **Color Array:** RGBA byte colors [S1, unofficial].
*   **Per-Point Attributes:** Arrays for scale, rotation, and opacity [S1, unofficial]. These are shared between simple-point and splat modes [S1, unofficial].
*   **Buffers:** Per-point buffers are uploaded only when their source data changes [S1, unofficial]. Arrays that do not cover every drawn point are staged [S1, unofficial].

**Parameters:**
*   `scaleFactor`: Scalar multiplier for splat size [S1, unofficial]. A value of 0 disables splatting and renders simple points [S1, unofficial].
*   `anisotropic`: Boolean flag enabling anisotropic 3D Gaussian splats [S1, unofficial].
*   `rotationArray`: Name of the array containing rotation data for anisotropic splats [S1, unofficial].
*   `lowpassMatrix`: Matrix used for low-pass filtering in anisotropic splatting calculation [S1, unofficial].
*   `emissive`: Boolean flag [S1, unofficial]. When true, splats add their coverage to the alpha channel for correct compositing over transparent backgrounds [S1, unofficial].
*   `scaleArray`, `scaleArrayComponent`, `scaleFunction`, `scaleTableSize`: Controls for scale mapping [S1, unofficial].
*   `opacityArray`, `opacityArrayComponent`, `scalarOpacityFunction`, `opacityTableSize`: Controls for opacity mapping [S1, unofficial].
*   `splatShaderCode`: Custom shader code for splat rendering [S1, unofficial].
*   `boundScale`: Bound scale parameter [S1, unofficial].

**Steps:**
1.  **Input Validation:** Check if `polyData` contains `verts` cells [S1, unofficial]. If yes, identify the subset of points referenced by these cells [S1, unofficial]. If no, use all points [S1, unofficial].
2.  **Buffer Management:** Identify compatible arrays: float positions without shift/scale, RGBA byte colors, and float scale/rotation/opacity arrays [S1, unofficial]. Upload compatible arrays directly to GPU buffers without staging copies [S1, unofficial]. For arrays that do not cover every drawn point or require staging, use staging buffers [S1, unofficial]. Re-upload buffers only if their source data has changed [S1, unofficial].
3.  **Rendering Mode Selection:** If `scaleFactor` is 0, render as simple points [S1, unofficial]. If `scaleFactor` is non-zero, render as Gaussian splats [S1, unofficial].
4.  **Simple Point Rendering:** Use `gl.POINTS` primitive type [S1, unofficial]. Submit one vertex per point [S1, unofficial].
5.  **Gaussian Splat Rendering:** Use a four-vertex triangle strip instance per point [S1, unofficial]. The vertex shader projects each 3D Gaussian to a screen-space ellipse using EWA (Elliptical Weighted Average) projection [S1, unofficial]. The shader places the four corners of the triangle strip around the projected Gaussian center [S1, unofficial]. Splat sizes do not apply VBO shift and scale, ensuring data far from the origin retains its splat size [S1, unofficial]. Every splat maintains one consistent winding order to ensure face culling treats rotated splats consistently [S1, unofficial].
6.  **Blending:** If `emissive` is true, add splat coverage to the alpha channel [S1, unofficial]. If `emissive` is false and using default Gaussian falloff, render with translucent geometry so faded corners do not hide objects behind them [S1, unofficial]. Apply opacity array regardless of scalar colors [S1, unofficial]. If opacity is below 1, render translucent [S1, unofficial].
7.  **Selection:** Hardware selection returns point IDs for simple points and `verts` cells for splats [S1, unofficial].

**Pseudocode:**
```python
def render_point_gaussian_mapper(poly_data, scaleFactor, anisotropic, rotationArray, lowpassMatrix, emissive):
    # 1. Determine points to render
    if poly_data.has_verts_cells():
        points_to_render = [p for p in poly_data.points if p in poly_data.verts_cells]
    else:
        points_to_render = poly_data.points

    # 2. Buffer Management
    position_array = poly_data.get_positions()
    color_array = poly_data.get_colors() # RGBA bytes
    scale_array = poly_data.get_array('scale')
    opacity_array = poly_data.get_array('opacity')
    rotation_array = poly_data.get_array(rotationArray) if anisotropic else None

    # Upload compatible arrays directly; others staged
    def upload_buffer(arr, name):
        if arr is not None and is_compatible_array(arr):
            gpu_buffer = allocate_gpu_memory(arr)
        else:
            staging_memory = allocate_cpu_memory()
            copy_to_staging(staging_memory, arr)
            gpu_buffer = upload_staged(staging_memory)
        bind_buffer(name, gpu_buffer)

    upload_buffer(position_array, 'position')
    upload_buffer(color_array, 'color')
    upload_buffer(scale_array, 'scale')
    upload_buffer(opacity_array, 'opacity')
    if rotation_array is not None:
        upload_buffer(rotation_array, 'rotation')

    # 3. Render
    if scaleFactor == 0:
        # Simple Points
        draw_arrays(primitive_type=POINTS, count=len(points_to_render))
    else:
        # Gaussian Splats
        for point in points_to_render:
            scale = get_scale(point, scale_array)
            opacity = get_opacity(point, opacity_array)
            rotation = get_rotation(point, rotation_array) if anisotropic else identity_matrix()

            # EWA Projection
            screen_center, screen_covariance = ewa_project(point.position, rotation, scale, camera_matrix)

            # Generate 4 corners of triangle strip
            corners = generate_splat_corners(screen_center, screen_covariance)

            # Set attributes and draw
            for corner in corners:
                set_vertex_position(corner)
                set_color(color_array[point.index])
                set_opacity(opacity)
                set_emissive(emissive)
                draw_arrays(primitive_type=TRIANGLE_STRIP, count=4)
```

**Edge Cases and Pitfalls:**
*   **View Culling:** Splats centered outside the view are drawn if their projection reaches into the view [S1, unofficial]. The projection is linearized no further than 30% beyond the view bounds [S1, unofficial].
*   **Winding Order:** Every splat maintains one winding order to ensure face culling treats rotated splats consistently [S1, unofficial].
*   **Splat Size Scaling:** Splat sizes do not apply VBO shift and scale, ensuring data far from the origin retains its splat size [S1, unofficial].
*   **Opacity Application:** The opacity array applies regardless of scalar colors [S1, unofficial]. If opacity is below 1, the property is rendered translucent [S1, unofficial].
*   **Non-emissive Rendering:** Non-emissive splats with default Gaussian falloff render with translucent geometry, allowing faded corners to not hide objects behind them [S1, unofficial].
*   **Scalar Colors:** Scalar colors are always per-point and never switch to texture coloring, even if `interpolateScalarsBeforeMapping` is set [S1, unofficial].
*   **Cell Scalars:** Cell scalars only color points that are drawn by `verts` cells [S1, unofficial].
*   **Composite Datasets:** Composite datasets are not supported because `vtk.js` mappers require `polydata` input [S1, unofficial].

## Subtopics

### vtkPointSpriteMapper
A subclass of `vtkPointGaussianMapper` designed for dense point clouds, defaulting to opaque simple points [S1, unofficial]. It adds controls for point size multiplier (e.g., for device pixel ratio), round points (which also select as discs), point sizes in model units that follow camera distance, and a draw limit for progressive loading (showing a prefix of points without uploading them again) [S1, unofficial]. The OpenGL mapper uses an extension point to determine the number of points each draw submission submits [S1, unofficial].

**Strengths and Limitations:**
*   **Strengths:** Renders point clouds without requiring `verts` cells; supports anisotropic 3D Gaussian splats; efficient buffer management by sharing buffers between simple-point and splat modes; correct compositing for emissive splats; consistent winding order for face culling [S1, unofficial].
*   **Limitations:** Does not support composite datasets; scalar colors are always per-point; non-emissive splats with default Gaussian falloff render with translucent geometry (which may differ from VTK's opaque geometry behavior); splats centered outside the view but projecting into the view are drawn (linearized up to 30% beyond view bounds) [S1, unofficial].

**When to Use:**
Use when rendering point clouds as simple points or Gaussian splats in `vtk.js` without needing complex cell structures, especially for dense point clouds where `vtkPointSpriteMapper` is preferred [S1, unofficial].

**When Not to Use:**
Do not use for composite datasets or when texture-based scalar coloring is required [S1, unofficial].

## Background
`vtkPointGaussianMapper` was added to `vtk.js` by PaulHax in a pull request (PR #42) in September 2026, porting VTK's `vtkPointGaussianMapper` with its API and defaults [S1, unofficial]. It addresses the lack of a counterpart in `vtk.js` for rendering point clouds as Gaussian splats or showing 3D Gaussian splatting data (scale and rotation per point) without requiring `verts` cells [S1, unofficial]. `vtkPointSpriteMapper` was added in the same PR as a subclass for dense point clouds [S1, unofficial].
