# DepthSplat
## Overview
DepthSplat is a feed-forward method for 3D Gaussian splatting reconstruction that integrates pre-trained monocular depth features into a multi-view cost volume framework [S1]. It solves the problem of robust depth estimation in challenging scenes (occlusions, low-texture, non-Lambertian surfaces) where standard multi-view stereo fails, and scale ambiguities where monocular estimation fails [S1]. Unlike TranSplat, which refines coarse depth with monocular features (prone to error propagation), DepthSplat combines cost volumes and monocular features early in the pipeline [S1]. Unlike GS-LRM, it relies on explicit feature matching rather than pure data-driven priors, reducing training compute requirements significantly [S1].
## How it works
**Inputs:** $N$ input images $\{I_i\}_{i=1}^N$ with resolution $H \times W$, and corresponding camera projection matrices $\{P_i\}_{i=1}^N$ (derived from intrinsic and extrinsic parameters) [S1].

**Outputs:** A set of 3D Gaussians $\mathcal{G} = \{\mu_j, \alpha_j, \Sigma_j, c_j\}$ for each pixel $j$ in the reference views, where $\mu_j$ is the mean (3D position), $\alpha_j$ is opacity, $\Sigma_j$ is covariance, and $c_j$ is color [S1].

**Data Structures:**
*   **Monocular Features:** Extracted per-view using a Vision Transformer (ViT) [S1]. Dimensions: $N \times C \times \frac{H}{s} \times \frac{W}{s}$, where $C$ is feature dimension and $s$ is downsampling factor [S1].
*   **Cost Volume:** For each view $i$, a 3D tensor $C_i \in \mathbb{R}^{\frac{H}{s} \times \frac{W}{s} \times D}$, where $D$ is the number of depth candidates [S1].
*   **Depth Map:** Predicted per-view dense depth $D_i \in \mathbb{R}^{H \times W}$ [S1].

**Parameters:**
*   **Downsampling factor ($s$):** Controlled by stride-2 $3 \times 3$ convolutions [S1]. $s=4$ with two convolutions; $s=8$ with three [S1].
*   **Depth candidates ($D$):** Uniformly sampled from near/far depth ranges [S1].
*   **Multi-view Transformer:** Contains six stacked self- and cross-attention layers [S1].
*   **Neighbor Selection:** For $N > 2$, top-2 nearest neighboring views are selected based on camera distance to the reference view [S1].

**Steps:**
1.  **Monocular Feature Extraction:** For each input image $I_i$, extract features $F_i$ using a pre-trained monocular depth model (ViT-based) [S1].
2.  **Cost Volume Construction (Multi-View Branch):**
    a. For each reference view $i$, uniformly sample $D$ depth candidates $\{d_m\}_{m=1}^D$ from the near/far ranges [S1].
    b. For each neighbor view $j$ (all views if $N \le 2$; top-2 nearest if $N > 2$), warp the features $F_j$ to view $i$ using $P_i$ and each depth candidate $d_m$ to obtain warped features $F_{j \to i}^m$ [S1].
    c. Compute feature correlations using the dot-product between $F_i$ and $F_{j \to i}^m$ [S1].
    d. If $N > 2$, average the correlation values from the two selected neighbor views [S1].
    e. Stack correlations for all $d_m$ to form cost volume $C_i \in \mathbb{R}^{\frac{H}{s} \times \frac{W}{s} \times D}$ [S1].
3.  **Feature Concatenation:** Concatenate the multi-view cost volumes $C_i$ with the extracted monocular features $F_i$ [S1].
4.  **Depth Regression:** Pass the concatenated features through a 2D U-Net architecture followed by a softmax layer to predict dense per-pixel depth $D_i$ [S1].
5.  **Gaussian Center Unprojection:** Unproject the predicted depth maps $D_i$ to 3D space using camera parameters $P_i$ to obtain Gaussian centers $\mu_j$ [S1].
6.  **Remaining Parameter Prediction:** Predict opacity $\alpha_j$, covariance $\Sigma_j$, and color $c_j$ using an additional lightweight network/head operating in parallel with the depth regression [S1].
7.  **Rendering:** Render novel views using the splatting operation with the predicted 3D Gaussians [S1].

**Pseudocode:**
```python
import torch
import torch.nn.functional as F

def DepthSplatForward(images, projection_matrices, near, far, D, s):
    """
    Forward pass for DepthSplat.
    images: (N, 3, H, W)
    projection_matrices: (N, 3, 4)
    near, far: float, depth range bounds
    D: int, number of depth candidates
    s: int, downsampling factor
    Returns: gaussian_centers (N, H, W, 3), gaussian_params (N, 4, H_ds, W_ds)
    """
    N, _, H, W = images.shape
    H_ds, W_ds = H // s, W // s

    # Step 1: Monocular Feature Extraction
    # Pre-trained ViT encoder extracts features
    mono_features = MonocularEncoder(images)  # (N, C, H_ds, W_ds)

    # Step 2: Cost Volume Construction
    cost_volumes = []
    # Select neighbors: all if N<=2, else top-2 by camera distance
    neighbors = SelectNeighbors(projection_matrices, N)

    for i in range(N):
        F_i = mono_features[i]  # (C, H_ds, W_ds)
        C_i = torch.zeros((H_ds, W_ds, D), device=images.device)
        depth_candidates = torch.linspace(near, far, D, device=images.device)  # (D,)

        for j in neighbors[i]:
            F_j = mono_features[j]  # (C, H_ds, W_ds)
            # Warp F_j to view i using plane-sweep stereo
            warped = WarpFeatures(F_j, projection_matrices[i], projection_matrices[j], depth_candidates)
            # warped shape: (D, C, H_ds, W_ds)

            # Dot-product correlation
            F_i_flat = F_i.view(-1, H_ds * W_ds)  # (C, H_ds*W_ds)
            warped_flat = warped.view(D, -1, H_ds * W_ds)  # (D, C, H_ds*W_ds)
            corr = torch.bmm(warped_flat, F_i_flat.unsqueeze(-1)).squeeze(-1)  # (D, H_ds*W_ds)
            corr = corr.view(D, W_ds, H_ds).permute(1, 2, 0)  # (H_ds, W_ds, D)

            C_i = C_i + corr

        if len(neighbors[i]) > 1:
            C_i = C_i / len(neighbors[i])
        cost_volumes.append(C_i)

    # Step 3: Feature Concatenation
    cost_volumes_tensor = torch.stack(cost_volumes, dim=0).permute(0, 3, 1, 2)  # (N, D, H_ds, W_ds)
    combined = torch.cat([cost_volumes_tensor, mono_features], dim=1)  # (N, D+C, H_ds, W_ds)

    # Step 4: Depth Regression
    depth_logits = DepthUNet(combined)  # (N, D, H_ds, W_ds)
    depth_probs = F.softmax(depth_logits, dim=1)
    depth_map_ds = torch.sum(depth_probs * depth_candidates.view(1, -1, 1, 1), dim=1)  # (N, H_ds, W_ds)
    depth_map = F.interpolate(depth_map_ds.unsqueeze(1), size=(H, W), mode='bilinear', align_corners=False).squeeze(1)  # (N, H, W)

    # Step 5: Gaussian Center Unprojection
    gaussian_centers = []
    for i in range(N):
        centers = UnprojectDepth(depth_map[i], projection_matrices[i], H, W)  # (H, W, 3)
        gaussian_centers.append(centers)

    # Step 6: Remaining Parameter Prediction
    gaussian_params = GaussianHead(mono_features)  # (N, 4, H_ds, W_ds) -> alpha, scale(3), color(3)

    return gaussian_centers, gaussian_params

def SelectNeighbors(projection_matrices, N):
    """Select top-2 nearest neighbors based on camera distance."""
    # Extract camera centers from projection matrices (last column of P)
    centers = projection_matrices[:, :, 3]  # (N, 3)
    dists = torch.cdist(centers, centers)  # (N, N)
    neighbors = []
    for i in range(N):
        sorted_idx = torch.argsort(dists[i])
        # Exclude self (index 0) and take top-2
        neighbors.append(sorted_idx[1:3].tolist())
    return neighbors

def WarpFeatures(F_j, P_ref, P_src, depth_candidates):
    """Warp source features to reference view using depth candidates."""
    C, H, W = F_j.shape
    D = len(depth_candidates)
    # Create reference pixel grid
    y, x = torch.meshgrid(torch.arange(H), torch.arange(W), indexing='ij')
    coords_ref = torch.stack([x, y, torch.ones_like(x)], dim=-1).float()  # (H, W, 3)
    coords_ref = coords_ref.view(1, 1, -1, 3).expand(N if 'N' in locals() else 1, 1, -1, 3)
    
    # Back-project to 3D using P_ref and depth
    # X_3d = P_ref^{-1} * [x, y, 1]^T * d_m
    # Project to source view using P_src
    # u_src, v_src = P_src * X_3d
    # Sample F_j at (u_src, v_src)
    # Standard plane-sweep warping implementation using grid_sample
    # For brevity, using standard coordinate transformation math
    warped = torch.zeros((D, C, H, W), device=F_j.device)
    for m in range(D):
        d = depth_candidates[m]
        # Back-project reference pixels to 3D
        pts_ref = coords_ref[0, 0].transpose(0, 1).unsqueeze(0)  # (1, 3, H*W)
        pts_3d = torch.inverse(P_ref) @ torch.cat([pts_ref, torch.ones(1, 1, H*W, device=pts_ref.device)], dim=1)
        pts_3d = pts_3d * d
        # Project to source view
        pts_src = P_src @ pts_3d
        u = pts_src[0] / pts_src[2]
        v = pts_src[1] / pts_src[2]
        # Normalize to [-1, 1] for grid_sample
        u_norm = 2 * u / W - 1
        v_norm = 2 * v / H - 1
        grid = torch.stack([u_norm, v_norm], dim=-1).view(1, H, W, 2)
        warped[m] = F.grid_sample(F_j.unsqueeze(0), grid, align_corners=True).squeeze(0)
    return warped

def UnprojectDepth(depth_map, P, H, W):
    """Unproject depth map to 3D points."""
    y, x = torch.meshgrid(torch.arange(H), torch.arange(W), indexing='ij')
    coords = torch.stack([x.float(), y.float(), torch.ones_like(x)], dim=-1)  # (H, W, 3)
    pts_2d = coords.view(1, 1, -1, 3).transpose(1, 2)  # (1, H*W, 3)
    pts_3d = torch.inverse(P) @ torch.cat([pts_2d, torch.ones(1, H*W, 1, device=coords.device)], dim=2)
    pts_3d = pts_3d * depth_map.view(1, H*W, 1, 1)
    return pts_3d[0].transpose(0, 1).view(H, W, 3)

class MonocularEncoder(torch.nn.Module):
    def __init__(self): pass
    def forward(self, x): return x  # Pre-trained ViT backbone [S1]

class DepthUNet(torch.nn.Module):
    def __init__(self, in_ch, out_ch): pass
    def forward(self, x): return x  # 2D U-Net architecture [S1]

class GaussianHead(torch.nn.Module):
    def __init__(self, in_ch, out_ch): pass
    def forward(self, x): return x  # Lightweight parallel head [S1]
```
## Subtopics

### [Gaussian Graph Network](18863-gaussian-graph-network.md)
A feed-forward method that generates efficient and generalizable 3D Gaussian representations from multi-view images by modeling relations between Gaussian groups from different views using a Gaussian Graph structure, enabling message passing and aggregation at the Gaussian level. Unlike previous methods that simply combine pixel-aligned Gaussians from multiple views without modeling relations, GGN explicitly models these relations via Gaussian Graphs, allowing each Gaussian to benefit from its connected Gaussian groups through feature fusion. This approach mitigates artifacts and extra memory costs associated with naive combination, enabling the model to benefit from increased input views rather than suffering performance degradation. Choose it when explicit Gaussian-level relation modeling is needed to handle multi-view consistency and reduce artifacts. [Gaussian Graph Network](18863-gaussian-graph-network.md)

## Operating characteristics
*   **Time Complexity:** The method is feed-forward, offering fast reconstruction [S1]. Reconstruction speed is 0.6 seconds for 12 input views at 512x960 resolution [S1].
*   **Memory Complexity:** Depends on the number of depth candidates $D$ and the cost volume size $\frac{H}{s} \times \frac{W}{s} \times D$ [S1]. The multi-view transformer scales with the number of views, but neighbor selection limits this to top-2 neighbors for $N > 2$ [S1].
*   **Training Compute:** Significantly cheaper than data-heavy methods like GS-LRM [S1]. Trained in 2 days with 4 GPUs, compared to 64 A100s for GS-LRM [S1].
*   **Strengths:** Robust to occlusions, low-textured areas, and non-Lambertian surfaces by augmenting multi-view matching with monocular features [S1]. Maintains multi-view consistency while leveraging monocular priors [S1].
*   **Limitations:** Multi-view depth estimation still fails in extreme occlusions or textureless regions without monocular augmentation [S1]. Monocular features alone suffer from scale ambiguity, which is mitigated but not eliminated by the multi-view constraint [S1].
*   **When to Use:** Large-scale scene reconstruction from multiple views where robustness to challenging textures is required, and computational resources for training are limited [S1].
*   **When Not to Use:** Single-image reconstruction (monocular depth alone is insufficient) or scenarios where per-scene optimization is acceptable and higher fidelity is needed [S1].
## Background
DepthSplat was introduced to connect Gaussian splatting and depth estimation, studying their interactions [S1]. It addresses the limitations of traditional multi-view stereo (failure in occlusions/low-texture) and monocular depth estimation (scale ambiguity) [S1]. The method was trained on TartanAir, ScanNet, RealEstate10K, and DL3DV datasets [S1]. It demonstrates that Gaussian splatting can serve as an unsupervised pre-training objective for learning powerful depth models from large-scale multi-view posed datasets [S1].
