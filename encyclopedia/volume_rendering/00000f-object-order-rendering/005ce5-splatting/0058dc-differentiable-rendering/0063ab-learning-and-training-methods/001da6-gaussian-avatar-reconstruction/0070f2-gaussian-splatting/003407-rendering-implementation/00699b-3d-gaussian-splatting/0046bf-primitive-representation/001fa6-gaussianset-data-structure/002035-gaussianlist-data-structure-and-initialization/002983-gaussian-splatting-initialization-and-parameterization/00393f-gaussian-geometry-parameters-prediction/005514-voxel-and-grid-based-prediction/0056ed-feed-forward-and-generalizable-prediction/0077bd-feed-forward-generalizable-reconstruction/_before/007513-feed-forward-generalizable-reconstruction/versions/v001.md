# Feed-forward Generalizable Reconstruction

Also called: Feed-forward 3D Gaussian Splatting, FF3DGS, Generalizable Gaussian Splatting

## Overview
Feed-forward generalizable reconstruction methods map input images directly to a set of 3D Gaussian parameters $\mathcal{G} = \{\mu, \Sigma, \alpha, c\}$ without per-scene gradient descent [Parent]. This solves the latency and compute bottlenecks of iterative optimization-based 3D Gaussian Splatting (3DGS), enabling instant reconstruction from arbitrary image sets . Unlike traditional 3DGS which requires iterative optimization per scene, these methods generalize across scenes using pretrained geometry encoders .

## Shared principles
All methods in this family share the core objective of mapping input image features to a set of 3D Gaussian parameters $\mathcal{G} = \{\mu, \Sigma, \alpha, c\}$ without per-scene gradient descent [Parent].

1.  **Input Representation:** Inputs are typically one or more RGB images $I \in \mathbb{R}^{H \times W \times 3}$. Some methods require known camera poses $P$, while others (e.g., [Splatt3R](16423-splatt3r.md), [ZeroGS](16425-zerogs.md)) predict poses or operate on uncalibrated inputs [Parent].
2.  **Feature Encoding:** A shared encoder (e.g., Vision Transformer, CNN) extracts multi-scale features from the input images. Cross-attention or cost volumes are often used to aggregate multi-view information [Parent].
3.  **Primitive Prediction:** A decoder head predicts Gaussian attributes. These attributes are usually:
    *   **Mean ($\mu$):** 3D position.
    *   **Covariance ($\Sigma$):** Defined by scale $s$ and rotation $r$ (quaternion or 6D).
    *   **Opacity ($\alpha$):** Scalar.
    *   **Color ($c$):** Spherical Harmonics (SH) coefficients or constant RGB [Parent].
4.  **Differentiable Rendering:** The predicted Gaussians are rendered into target views using differentiable rasterization to compute reconstruction losses (e.g., L1, SSIM, LPIPS) for training the network [Parent].
5.  **Generalization:** The network is trained on a large dataset of scenes to learn priors about geometry and appearance, allowing inference on unseen scenes [Parent].

## Subtopics

### [AnySplat Pipeline](12847-anysplat-pipeline.md)
The AnySplat Pipeline is a feed-forward, transformer-based method for reconstructing 3D Gaussian Splatting representations from uncalibrated, unconstrained multi-view images. It solves the problem of requiring known camera poses and calibrated intrinsics by jointly predicting Gaussian parameters, depth maps, and camera poses in a single forward pass. Unlike traditional 3D Gaussian Splatting which requires iterative optimization per scene, AnySplat generalizes across scenes using a pretrained geometry encoder, enabling instant reconstruction from arbitrary image sets.

### [Splatt3R](16423-splatt3r.md)
Splatt3R is a feed-forward, pose-free method that predicts 3D Gaussian Splat primitives directly from a stereo pair of uncalibrated images, without requiring camera intrinsics, extrinsics, or depth maps. Unlike existing generalizable 3D-GS methods that are limited to interpolating viewpoints between input images, Splatt3R supports extrapolation to wider baselines by employing a novel loss masking strategy to prevent training on unseen or obscured geometry. It builds on the MASt3R foundation model, extending its point-cloud prediction capability with a dedicated Gaussian head for appearance and covariance attributes.

### [RLSplat](16575-rlsplat.md)
RLSplat is a resource-linear, budget-controllable feed-forward 3D Gaussian Splatting (FF3DGS) framework that ensures inference latency, peak memory, and representation size all decrease linearly as the target Gaussian budget $B$ is reduced. Unlike prior budget-controllable methods that predict a dense set of Gaussians and subsequently prune or select a subset—resulting in nearly constant inference costs regardless of the budget—RLSplat learns a Gaussian allocation policy to distribute exactly $B$ Gaussians across local scene regions from the start. It then refines these Gaussians using a resource-linear decoder based on local cross-attention, making it suitable for applications with strict resource constraints such as AR/VR and robotics.

### [LGTM (Less Gaussians, Texture More)](17426-lgtm-less-gaussians-texture-more.md)
LGTM is a feed-forward framework that predicts compact 2D Gaussian primitives coupled with per-primitive texture maps, decoupling geometric complexity from rendering resolution to enable high-fidelity 4K novel view synthesis without per-scene optimization. It solves the problem where existing feed-forward 3D Gaussian Splatting methods suffer from quadratic growth in primitive count as resolution increases, making high-resolution synthesis intractable due to memory and compute limits. Unlike standard 3DGS which couples appearance and geometry within each primitive, LGTM decouples them, allowing a compact set of geometric primitives to represent rich texture regions via per-primitive textures.

### [InfiniSplat v2](17642-infinisplat-v2.md)
InfiniSplat v2 is a feed-forward Gaussian reconstruction method for arbitrary input views that decouples geometry and attribute prediction, uses ground-truth (GT) camera poses for alignment during training, and employs large-angle target view supervision to improve rendering quality under large viewpoint changes. It differs from its parent [Feed-forward Generalizable Reconstruction](23168-feed-forward-generalizable-reconstruction.md) and siblings like [DA3-GS](12847-anysplat-pipeline.md) by freezing the geometry branch to prevent geometric degradation caused by joint optimization, and by using GT poses to avoid pose errors that misguide the network under large-angle supervision.

### [DepthSplat](18278-depthsplat.md)
DepthSplat is a feed-forward method that reconstructs 3D Gaussian splatting representations from multi-view images by integrating pre-trained monocular depth features into a multi-view cost volume framework. It solves the problem of robust depth estimation in challenging scenes (occlusions, low-texture, non-Lambertian surfaces) where standard multi-view stereo fails, and scale ambiguity where monocular estimation fails. Unlike TranSplat, which uses monocular features to refine coarse depth (vulnerable to error propagation), DepthSplat combines cost volumes and monocular features early in the pipeline. Unlike GS-LRM, which discards explicit feature matching for data-driven priors, DepthSplat uses explicit feature matching and is significantly cheaper to train (4 GPUs vs 64 A100s).

### [VG2GT](18425-vg2gt.md)
VG2GT is a feed-forward, non-pixel-aligned 3D Gaussian Splatting (3DGS) reconstruction framework that directly regresses geometrically accurate Gaussian scenes and camera parameters from an arbitrary number of unposed and uncalibrated images. It distinguishes itself from sibling methods like [AnySplat Pipeline](12847-anysplat-pipeline.md) by avoiding the intermediate step of regressing pixel-aligned primitives; instead, it decodes Gaussian primitives directly from structured voxel features, thereby eliminating the uneven distributions and cross-view inconsistencies inherent to pixel-aligned formulations.

### [WildSplat](19321-wildsplat.md)
WildSplat is a feedforward 3D Gaussian Splatting framework designed for appearance-conditioned novel-view synthesis from sparse, unposed, in-the-wild images. It solves the problem of inconsistent photometric conditions (varying lighting, weather, or season) that typically cause existing feedforward methods to fail by entangling geometry with appearance. Unlike optimization-based methods or prior feedforward approaches that assume photometric consistency, WildSplat explicitly decouples geometry from appearance using a dual-branch architecture, allowing it to reconstruct invariant 3D structure while conditioning the rendering appearance on a specific reference image.

### [StereoGaussians](19766-stereogaussians.md)
StereoGaussians is a feed-forward method that predicts a metric 3D Gaussian Splatting (3DGS) representation from a single calibrated stereo pair, enabling nearby-view extrapolation without per-scene optimization. It differs from its siblings by freezing a pretrained stereo encoder to extract geometric anchors and features, while a trainable predictor maps these to Gaussian attributes on an expanded image canvas with a dedicated back layer for disoccluded content. Unlike [AnySplat Pipeline](12847-anysplat-pipeline.md) or [Splatt3R](16423-splatt3r.md) which may use different feature aggregation or multi-view inputs, StereoGaussians relies on a single stereo pair and explicit depth anchoring.

## Background
The family originates from the need to overcome the iterative optimization bottleneck of original 3D Gaussian Splatting [Parent]. Early generalizable methods adapted multi-view stereo (MVS) cost volumes and depth estimation networks to predict Gaussian parameters directly . Subsequent developments introduced foundation models (e.g., MASt3R, DINO) to provide robust geometric priors without explicit camera calibration . Recent trends focus on resource efficiency (RLSplat), high-resolution synthesis via texture decoupling (LGTM), and handling uncalibrated/in-the-wild inputs (AnySplat, WildSplat) .
