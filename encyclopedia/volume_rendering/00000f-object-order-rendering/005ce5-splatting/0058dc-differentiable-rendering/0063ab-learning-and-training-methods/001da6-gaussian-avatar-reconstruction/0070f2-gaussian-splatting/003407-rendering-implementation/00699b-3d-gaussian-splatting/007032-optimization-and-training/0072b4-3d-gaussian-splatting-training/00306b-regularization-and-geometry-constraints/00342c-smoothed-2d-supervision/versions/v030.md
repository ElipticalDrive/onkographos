# Smoothed 2D Supervision

Also called: Adaptive Gaussian blur strategy, Progressive Gaussian Blurring

## Overview
Smoothed 2D Supervision is a regularization technique that enhances the robustness of joint optimization (e.g., camera pose and scene geometry) by blurring 2D training images with a scheduled set of 2D Gaussian kernels [S1][S2, unofficial]. It stabilizes camera alignment by producing smoothed image gradients and restricts the spectrum of the learned 3D scene to prevent high-frequency noise from dominating early training [S2, unofficial]. Unlike raw pixel supervision, which can lead to unstable gradients in the presence of noise or misalignment, this method provides a coarse-to-fine supervision signal [S3]. It is distinct from frequency-based methods like [Frequency Regularization](6130-frequency-regularization.md) because it operates directly in the spatial domain on the rendered images rather than in the Fourier domain [S3].

## How it works
**Inputs and Outputs:**
*   **Input:** Ground truth 2D training images $I_{gt}$, current rendered images $I_{render}$, current iteration $t$, and hyperparameters for the blur schedule.
*   **Output:** Smoothed ground truth images $I_{gt}^{smooth}$ and smoothed rendered images $I_{render}^{smooth}$ used for loss computation.

**Data Structures:**
*   **Blur Kernel:** A 2D Gaussian kernel $K_{\sigma}$ defined by standard deviation $\sigma$. The kernel size is typically odd, e.g., $9 \times 9$ [S4].
*   **Schedule Parameters:**
    *   $\sigma_{start}$: Initial standard deviation (e.g., 2.4) [S4].
    *   $k_b$: Iteration interval for reducing blur (e.g., 100 iterations) [S4].
    *   $T_{end}$: Iteration at which blur is fully removed (e.g., 19500) [S4].
    *   $S_{down}$: Downsampling scale factor if multi-resolution training is used [S4].

**Numbered Steps:**
1.  **Initialize Schedule:** Set initial standard deviation $\sigma = \sigma_{start}$ [S4].
2.  **Apply Blur:** For each training iteration $t$:
    a. If $t < T_{end}$ and $t \pmod{k_b} == 0$, reduce $\sigma$. The reduction strategy is typically exponential or linear decay towards 0 [S2, unofficial][S4].
    b. If downsampling is active, adjust $\sigma$ by the downsampling scale: $\sigma_{effective} = \sigma / S_{down}$ [S4].
    c. Convolve $I_{gt}$ with $K_{\sigma}$ to get $I_{gt}^{smooth}$ [S2, unofficial].
    d. Convolve $I_{render}$ with $K_{\sigma}$ to get $I_{render}^{smooth}$ [S2, unofficial].
3.  **Compute Loss:** Calculate the photometric loss (e.g., L1 or SSIM) between $I_{gt}^{smooth}$ and $I_{render}^{smooth}$ [S2, unofficial].
4.  **Backpropagate:** Use the smoothed loss to update Gaussian parameters and camera poses [S2, unofficial].

**Pseudocode:**
```python
def compute_smoothed_loss(I_gt, I_render, t, sigma_start, k_b, t_end, s_down):
    # Determine current sigma based on schedule
    if t < t_end:
        # Linear or exponential decay from sigma_start to 0 over t_end iterations
        # Example linear decay:
        sigma = sigma_start * (1 - t / t_end)
        
        # Adjust for downsampling if applicable
        sigma = sigma / s_down
    else:
        sigma = 0.0
        
    # Create Gaussian kernel with sigma
    # Kernel size is typically 9x9 for sigma=2.4, adjust as needed
    kernel = create_gaussian_kernel(sigma, size=9)
    
    # Convolve images
    I_gt_smooth = convolve_2d(I_gt, kernel)
    I_render_smooth = convolve_2d(I_render, kernel)
    
    # Compute loss (e.g., L1)
    loss = l1_loss(I_gt_smooth, I_render_smooth)
    
    return loss
```

**Parameters with Typical Values:**
*   $\sigma_{start} = 2.4$ [S4].
*   $k_b = 100$ iterations [S4].
*   $T_{end} = 19500$ iterations [S4].
*   Kernel size: $9 \times 9$ [S4].

**Edge Cases and Pitfalls:**
*   **Downsampling:** When downsampling and blurring are activated together, the kernel size must be lowered by the scale of downsampling at the current stage, as the initial hyperparameter choice is based on original image resolutions [S4].
*   **Densification:** Lower the blurring kernel size before densifying Gaussians to introduce extra signal on the gradient of erroneous Gaussians as the noise level reduces [S4].
*   **Precision:** Ensure the convolution operation is differentiable and efficient, as it is applied every iteration [S2, unofficial].

## Subtopics

### [Randomly Scaled Kernel Parameter](7875-randomly-scaled-kernel-parameter.md)
A regularization technique used during joint optimization to mitigate weak and noisy gradient signals. It addresses the insufficiency of using a single-size kernel for diverse real-world scene structures, where a fixed kernel may be overly aggressive in some contexts and overly gentle in others. By randomly scaling the kernel size, it allows combinations of different-sized kernels to guide the optimization, resulting in a more robust training schedule.

### [Multiscale Pre-convolved Representation](10911-multiscale-pre-convolved-representation.md)
A regularization technique for neural illumination fields that stabilizes the decomposition of object materials from environmental illumination by enforcing consistency with pre-computed, roughness-adapted background reflections. It addresses the ambiguity where diffuse object color is incorrectly absorbed into the estimated environment map, a problem inherent to high-dimensional neural illumination representations. Unlike methods that ignore the background or treat it as static, this method explicitly models the relationship between rough refractive surfaces and the convolved background, allowing for realistic specular reflections even when roughness exceeds the kernel scale. The technique builds on [Smoothed 2D Supervision](7213-smoothed-2d-supervision.md) by applying discrete Gaussian blur kernels to the background to stabilize convergence.

### [Soft Rasterization](13687-soft-rasterization.md)
Soft rasterization is a differentiable rendering technique that mitigates the discontinuities inherent in standard rasterization by blending facet contributions for pixels near primitive edges. It solves the problem of sparse and vanishing gradients caused by the non-uniformity of bilinear interpolation operands, which typically have similar values except at object boundaries. Unlike standard hard rasterization, it yields slightly distorted images but allows backpropagating more useful gradients, thereby stabilizing optimization and preventing gradient vanishing at edges.

### Platonic GAN (pGAN)
A learning-based method for 2D supervision per class of reconstructed objects, used here to pre-train a network for per-frame supervision of rising smoke [S5]. It was used to pre-train a network for per-frame supervision of the rising smoke case of a single-view evaluation, yielding improvements in terms of depth artifacts [S5]. However, due to the lack of constraints over time, the solutions are incoherent and do not align with the input sequence, leading to an FID of more than 180 [S5].

## Operating characteristics
*   **Time Complexity:** Adds convolution overhead to each training iteration. The cost is proportional to the number of pixels and the kernel size [S2, unofficial].
*   **Memory Complexity:** Requires storing the blurred images or recomputing them on the fly. Minimal additional memory if computed on the fly [S2, unofficial].
*   **Measured Performance:** Achieves 19.72 PSNR on DTU 3-view, improving over the Baseline (19.54) [S3]. In Trick-GS, it contributes to efficient training with fewer iterations (e.g., 50k vs 200k) [S1].
*   **Strengths:** Stabilizes camera alignment, reduces noise sensitivity, and allows for faster convergence by focusing on low-frequency structures first [S2, unofficial][S4].
*   **Limitations:** Handcrafted schedule may not fully align frequency relationships compared to adaptive methods [S3]. Requires careful tuning of the schedule parameters [S4].
*   **When to Use:** Crucial for successful pose refinement in joint optimization scenarios [S1]. Useful when training data is noisy or camera poses are uncertain [S2, unofficial].
*   **When Not to Use:** When high-frequency details are critical from the start and the scene is well-aligned [S3].

## Background
Smoothed 2D Supervision was introduced as part of techniques to improve the robustness of joint optimization of camera pose and decomposed low-rank tensorial radiance fields [S1][S2, unofficial]. It was inspired by the analysis of spectral control in radiance fields [S2, unofficial]. The method has been adopted in various Gaussian Splatting variants, such as Trick-GS, to enhance training stability and efficiency [S4]. It is also referenced in the context of adaptive rendering loss regularization [S3] and neural illumination fields [S1].
