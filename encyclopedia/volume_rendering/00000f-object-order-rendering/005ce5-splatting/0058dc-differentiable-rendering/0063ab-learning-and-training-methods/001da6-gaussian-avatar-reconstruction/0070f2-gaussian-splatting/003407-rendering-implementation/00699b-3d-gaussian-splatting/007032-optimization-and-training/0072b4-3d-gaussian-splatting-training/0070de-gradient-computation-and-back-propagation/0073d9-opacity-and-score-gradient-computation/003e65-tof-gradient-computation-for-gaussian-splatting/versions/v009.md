# ToF Gradient Computation for Gaussian Splatting

Also called: Opacity gradient for ToF image formation, Recursive gradient for quad pixels

## Overview
This method computes the gradient of the loss function $L$ with respect to the opacity parameter $\alpha_k$ of the $k$-th Gaussian in Time-of-Flight (ToF) image formation models, specifically for phasor or quad pixel signals. It extends the standard 3D Gaussian Splatting (3DGS) color rendering gradient by introducing squared transmittance terms in the recursive accumulation, addressing the non-linear interaction of opacity in ToF signal integration. It solves the problem of back-propagating errors through the ToF forward rendering equation, which differs from the linear alpha-blending used in standard RGB rendering.

## How it works
**Inputs and Outputs:**
*   **Input:** The loss function $L$, the rendered ToF signal $\mathbf{q}(\mathbf{x})$ (e.g., quad pixels) at pixel $\mathbf{x}$, the opacity $\alpha_k$, the quad contribution $\mathbf{q}_k$ of the $k$-th Gaussian, the transmittance $T_k$, and the accumulated quad signal $\text{acc}_k^q$ from subsequent Gaussians.
*   **Output:** The gradient $\frac{\partial L}{\partial \alpha_k}$.

**Data Structures:**
*   $\mathbf{q}_k$: A vector representing the quad pixel contribution of the $k$-th Gaussian. For standard quad pixels, this typically contains 4 components (e.g., phase shifts or intensity samples).
*   $\text{acc}_k^q$: An accumulator variable of the same dimension as $\mathbf{q}_k$, storing the aggregated contribution of Gaussians $k+1$ to $N$.
*   $T_k$: Scalar transmittance up to Gaussian $k$.
*   $\alpha_k$: Scalar opacity of Gaussian $k$.

**Numbered Steps:**
1.  **Compute the Accumulator ($\text{acc}_k^q$):**
    Iterate backwards from the last Gaussian $N$ to the first. For each Gaussian $k$, compute the accumulated quad signal using the recursive formula:
    $$
    \text{acc}_k^q = \begin{cases} \alpha_{k+1} \mathbf{q}_{k+1} + (1 - \alpha_{k+1})^2 \text{acc}_{k+1}^q, & k < N \\ 0, & k = N \end{cases}
    $$
    Here, $\text{acc}_N^q = 0$. The term $(1 - \alpha_{k+1})^2$ reflects the squared transmittance effect inherent in ToF signal formation compared to the linear $(1 - \alpha_{k+1})$ in standard color rendering.

2.  **Compute the Signal Gradient ($\frac{\partial \mathbf{q}(\mathbf{x})}{\partial \alpha_k}$):**
    Using the pre-computed $\text{acc}_k^q$ and the current Gaussian's parameters, calculate the gradient of the quad signal with respect to opacity:
    $$
    \frac{\partial \mathbf{q}(\mathbf{x})}{\partial \alpha_k} = T_k^2 \left( \mathbf{q}_k + 2(\alpha_k - 1)\text{acc}_k^q \right)
    $$
    Note that $T_k^2$ appears due to the derivative of the squared transmittance terms in the forward model.

3.  **Compute the Loss Gradient ($\frac{\partial L}{\partial \alpha_k}$):**
    Apply the chain rule to combine the loss gradient with respect to the signal and the signal gradient with respect to opacity:
    $$
    \frac{\partial L}{\partial \alpha_k} = \frac{\partial L}{\partial \mathbf{q}(\mathbf{x})} \cdot \frac{\partial \mathbf{q}(\mathbf{x})}{\partial \alpha_k}
    $$
    Where $\frac{\partial L}{\partial \mathbf{q}(\mathbf{x})}$ is the upstream gradient provided by the loss function (e.g., MSE between predicted and target quad pixels).

**Pseudocode:**
```python
def compute_tof_opacity_gradient(loss_grad_signal, gaussians_sorted_by_depth):
    """
    Computes the gradient of the loss with respect to opacity for ToF quad pixels.
    
    Args:
        loss_grad_signal: Gradient of Loss L w.r.t. the rendered quad signal q(x). Shape: (4,) or (B, 4).
        gaussians_sorted_by_depth: List of Gaussian objects sorted from back (N) to front (1).
                                   Each object has attributes: alpha, q (quad contribution), T (transmittance).
    
    Returns:
        opacities_grad: List of gradients dL/d_alpha_k for each Gaussian.
    """
    N = len(gaussians_sorted_by_depth)
    opacities_grad = [None] * N
    
    # Initialize accumulator for the last Gaussian
    acc_q = 0.0
    
    # Iterate from back (N-1) to front (0)
    for k in range(N - 1, -1, -1):
        g = gaussians_sorted_by_depth[k]
        alpha_k = g.alpha
        q_k = g.q
        T_k = g.T
        
        # Step 1: Compute the gradient of the signal w.r.t opacity for this Gaussian
        # Formula: d_q/d_alpha_k = T_k^2 * (q_k + 2 * (alpha_k - 1) * acc_q)
        # Note: acc_q here holds acc_{k+1}^q from the previous iteration (or 0 for k=N)
        
        term_inside = q_k + 2.0 * (alpha_k - 1.0) * acc_q
        grad_signal_wrt_alpha = (T_k ** 2) * term_inside
        
        # Step 2: Chain rule to get loss gradient w.r.t opacity
        # loss_grad_signal is dL/d_q(x)
        grad_loss_wrt_alpha = loss_grad_signal * grad_signal_wrt_alpha
        
        opacities_grad[k] = grad_loss_wrt_alpha
        
        # Step 3: Update accumulator for the next iteration (k-1)
        # Formula: acc_k^q = alpha_{k+1} * q_{k+1} + (1 - alpha_{k+1})^2 * acc_{k+1}^q
        # In the loop, 'g' is currently k. We need to compute acc_k^q to be used for k-1.
        # However, the loop structure above computes grad for k using acc_{k+1}.
        # We must update acc_q to be acc_k^q for the next iteration (which will be k-1).
        
        if k < N - 1:
            # We are at Gaussian k. We need to compute acc_k^q using Gaussian k+1's data?
            # Wait, the definition is: acc_k^q depends on alpha_{k+1}, q_{k+1}, acc_{k+1}^q.
            # In the backward pass, when we are at step k, we have just computed grad for k.
            # We need to prepare acc_k^q for step k-1.
            # But acc_k^q requires data from k+1.
            # Let's re-read the definition carefully.
            # acc_k^q = alpha_{k+1} * q_{k+1} + (1 - alpha_{k+1})^2 * acc_{k+1}^q
            # This means acc_k^q is the accumulation starting from k+1.
            # So, when we are at index k, we need acc_{k+1}^q (which is 'acc_q' variable).
            # After computing grad for k, we need to compute acc_k^q to pass to k-1.
            # But acc_k^q depends on k+1.
            # Let's trace:
            # k=N-1 (last): acc_N^q = 0. Compute grad for N-1. Then compute acc_{N-1}^q?
            # No, acc_{N-1}^q is needed for k=N-2.
            # acc_{N-1}^q = alpha_N * q_N + (1-alpha_N)^2 * acc_N^q.
            # But we don't have N in the list if we iterate 0..N-1.
            # The list is sorted back-to-front. Index 0 is back (N), Index N-1 is front (1).
            # Let's assume gaussians_sorted_by_depth[0] is the back-most (k=1 in math notation if 1-based, or k=N in 0-based back-to-front).
            # Let's stick to the math notation: k=1 is front, k=N is back.
            # Sorted list: [G_N, G_{N-1}, ..., G_1].
            # Loop k from 0 to N-1 in code corresponds to math k from N down to 1.
            
            # Let's restart the loop logic to be precise.
            pass

    # Corrected Pseudocode Logic:
    # List: [G_N, G_{N-1}, ..., G_1]
    # acc_q starts as 0 (representing acc_{N+1}^q = 0)
    
    acc_q = 0.0
    opacities_grad = []
    
    for g in gaussians_sorted_by_depth: # Iterates G_N, then G_{N-1}, ...
        alpha_k = g.alpha
        q_k = g.q
        T_k = g.T
        
        # Compute grad for current Gaussian k
        # acc_q currently holds acc_{k+1}^q
        grad_signal_wrt_alpha = (T_k ** 2) * (q_k + 2.0 * (alpha_k - 1.0) * acc_q)
        grad_loss_wrt_alpha = loss_grad_signal * grad_signal_wrt_alpha
        opacities_grad.append(grad_loss_wrt_alpha)
        
        # Update acc_q to be acc_k^q for the next Gaussian (which is k-1)
        # acc_k^q = alpha_{k+1} * q_{k+1} + (1 - alpha_{k+1})^2 * acc_{k+1}^q
        # Wait, the formula for acc_k^q uses k+1.
        # If we are at G_k, the next Gaussian in the list is G_{k-1} (closer to camera).
        # The previous Gaussian in the list was G_{k+1} (further from camera).
        # We need to store G_{k+1}'s data to compute acc_k^q?
        # No, acc_k^q is the accumulation of contributions from k+1 to N.
        # So acc_k^q depends on G_{k+1} and acc_{k+1}^q.
        # In the loop, when we process G_k, we have already processed G_{k+1} (it was the previous iteration).
        # But we didn't save G_{k+1}'s alpha and q.
        
        # Alternative: Compute acc_k^q using the CURRENT Gaussian's data?
        # No, acc_k^q aggregates LATER Gaussians.
        # Let's look at the base case: acc_N^q = 0.
        # acc_{N-1}^q = alpha_N * q_N + (1-alpha_N)^2 * acc_N^q.
        # So to compute acc_{N-1}^q, we need G_N's alpha and q.
        # In the loop, when we are at G_{N-1} (index 1), we need G_N's data.
        # We can store the previous Gaussian's data.
        
        # Let's rewrite the loop to carry forward the "next" Gaussian's data.
        pass

    # Final Corrected Pseudocode:
    acc_q = 0.0
    opacities_grad = []
    prev_g = None # To store G_{k+1}
    
    for g in gaussians_sorted_by_depth: # G_N, G_{N-1}, ...
        alpha_k = g.alpha
        q_k = g.q
        T_k = g.T
        
        # Compute grad for current Gaussian k
        # acc_q holds acc_{k+1}^q
        grad_signal_wrt_alpha = (T_k ** 2) * (q_k + 2.0 * (alpha_k - 1.0) * acc_q)
        grad_loss_wrt_alpha = loss_grad_signal * grad_signal_wrt_alpha
        opacities_grad.append(grad_loss_wrt_alpha)
        
        # Prepare acc_k^q for the next iteration (which will be k-1)
        # acc_k^q = alpha_{k+1} * q_{k+1} + (1 - alpha_{k+1})^2 * acc_{k+1}^q
        # Here, 'prev_g' is G_{k+1}
        if prev_g is not None:
            alpha_next = prev_g.alpha
            q_next = prev_g.q
            acc_q = alpha_next * q_next + ((1.0 - alpha_next) ** 2) * acc_q
        else:
            # For the last Gaussian in the list (G_N), acc_N^q is 0.
            # But we need to compute acc_{N-1}^q for the next step.
            # acc_{N-1}^q = alpha_N * q_N + (1-alpha_N)^2 * acc_N^q
            # So we use G_N's data.
            alpha_next = g.alpha
            q_next = g.q
            acc_q = alpha_next * q_next + ((1.0 - alpha_next) ** 2) * 0.0
            
        prev_g = g
        
    return opacities_grad
```

**Parameters:**
*   $T_k$: Transmittance up to the $k$-th Gaussian. Typical values: $[0, 1]$.
*   $\alpha_k$: Opacity of the $k$-th Gaussian. Typical values: $[0, 1]$.
*   $\mathbf{q}_k$: Quad contribution. Dimension depends on the ToF sensor model (e.g., 4 for quad pixels).

**Edge Cases and Pitfalls:**
*   **Precision:** The squared terms $(1-\alpha)^2$ and $T^2$ can lead to vanishing gradients if $\alpha$ is close to 1 or $T$ is close to 0. [S1]
*   **Recursion Order:** The accumulator $\text{acc}_k^q$ must be computed in reverse depth order (back to front) to ensure $\text{acc}_{k+1}^q$ is available when computing the gradient for $k$. [S1]
*   **Standard vs. ToF:** Using the standard 3DGS gradient formula $\frac{\partial \mathbf{c}(\mathbf{x})}{\partial \alpha_k} = T_k(\mathbf{c}_k - \alpha \mathbf{c}_k)$ for ToF signals will result in incorrect gradients. The ToF model requires the squared transmittance and the specific accumulator update. [S1]

## Operating characteristics
*   **Time Complexity:** $O(N)$ per pixel, where $N$ is the number of Gaussians, due to the single backward pass for accumulation and gradient computation.
*   **Memory Complexity:** $O(N)$ to store the gradients and intermediate accumulator values if not computed on the fly.
*   **Strengths:** Provides accurate gradients for ToF-specific loss functions, enabling end-to-end training of Gaussian Splatting for depth/ToF data.
*   **Limitations:** More complex than standard RGB gradient computation; requires careful implementation of the recursive accumulator.
*   **When to use:** When training 3D Gaussian Splatting models using Time-of-Flight data (phasor or quad pixels).
*   **When not to use:** For standard RGB rendering, use the standard 3DGS opacity gradient.

## Background
This method originates from the paper "Time of the Flight of the Gaussians: Optimizing Depth Indirectly in Dynamic Radiance Fields" [S1], published in CVPR 2025. It extends the original 3D Gaussian Splatting rendering pipeline [13] to handle ToF image formation models, which involve non-linear interactions between opacity and signal accumulation. The key insight is that the derivative of the ToF signal with respect to opacity involves squared transmittance terms, necessitating a modified recursive accumulation scheme.
