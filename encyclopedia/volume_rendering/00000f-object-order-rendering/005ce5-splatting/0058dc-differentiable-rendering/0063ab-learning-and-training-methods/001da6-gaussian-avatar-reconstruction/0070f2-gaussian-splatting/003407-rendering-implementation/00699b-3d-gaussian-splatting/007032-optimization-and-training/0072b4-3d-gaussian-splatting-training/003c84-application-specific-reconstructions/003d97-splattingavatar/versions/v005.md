# SplattingAvatar

Also called: Realistic Real-Time Human Avatars with Mesh-Embedded Gaussian Splatting

## Overview
SplattingAvatar is a method for reconstructing animatable human head avatars from monocular video by embedding 3D Gaussians directly onto a driving mesh (FLAME) in tangent space [S2, unofficial]. It solves the noise and instability issues associated with nearest-triangle sampling in canonical space, enabling high-fidelity rendering of complex geometries like eyes and hair while maintaining real-time performance [S2, unofficial]. Unlike methods that focus on accurate geometry reconstruction, SplattingAvatar prioritizes photometric quality and rendering efficiency [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Monocular video of a human head; pre-fitted FLAME mesh parameters (pose, expression) [S2, unofficial].
*   **Output:** A set of 3D Gaussians embedded on the mesh, optimized for photorealistic rendering and real-time animation [S2, unofficial].

**Data Structures:**
*   **Gaussian Attributes:** Each Gaussian retains standard 3DGS attributes: mean $\mu$, covariance $\Sigma$, opacity $\alpha$, and spherical harmonics $\mathbf{c}$ [S2, unofficial].
*   **Mesh Embedding:** Gaussians are initialized per mesh triangle in tangent space [S2, unofficial].
*   **Unity Implementation:** One quad primitive per Gaussian is drawn in the rendering engine [S2, unofficial].

**Optimization Steps:**
1.  **Initialization:** Initialize one Gaussian per mesh triangle in the tangent space of the FLAME mesh [S2, unofficial].
2.  **Training Loop:** Run optimization for 30,000 iterations [S2, unofficial].
    *   **Iteration 0–599:** Standard 3DGS optimization without densification/pruning [S2, unofficial].
    *   **Iteration 600–15,000:** Perform densify, prune, and opacity reset every 100 iterations [S2, unofficial].
        *   **Densify:** Clone and split Gaussians based on gradient magnitude (standard 3DGS criteria) [S2, unofficial].
        *   **Prune:** Remove Gaussians with low opacity [S2, unofficial].
        *   **Opacity Reset:** Every 3,000 iterations, reset the opacity of all Gaussians to zero to remove redundant Gaussians [S2, unofficial].
    *   **Iteration 15,001–30,000:** Continue standard optimization without densification/pruning/reset [S2, unofficial].
3.  **Walking on Triangle:** After densifying and pruning, enforce that Gaussians remain within their corresponding mesh triangle boundaries [S2, unofficial]. This prevents Gaussians from sticking or piling up on triangle boundaries [S2, unofficial].
4.  **Motion Control:** Use trainable embeddings ported to compute shaders for motion control, allowing the avatar to be animated in real-time [S2, unofficial].

**Parameters:**
*   $\lambda_l$ (L1 loss weight): 0.01 [S2, unofficial].
*   $\lambda_s$ (SSIM loss weight): 1.0 [S2, unofficial].
*   $T_s$ (Scale threshold): 10.0 [S2, unofficial].
*   $T_r$ (Rotation threshold): 0.008 [S2, unofficial].
*   Total iterations: 30,000 [S2, unofficial].
*   Densify/Prune interval: Every 100 iterations [S2, unofficial].
*   Opacity reset interval: Every 3,000 iterations [S2, unofficial].
*   Densify/Prune/Reset stop iteration: 15,000 [S2, unofficial].

**Pseudocode:**
```python
# SplattingAvatar Training Loop
def train_splatting_avatar(video_frames, flame_mesh, num_iterations=30000):
    # Initialize Gaussians in tangent space of FLAME mesh
    gaussians = initialize_gaussians_per_triangle(flame_mesh)
    
    for iteration in range(1, num_iterations + 1):
        # Get current pose and expression from video
        pose, expression = get_pose_expression(video_frames[iteration])
        
        # Render current frame using 3DGS splatting
        rendered_image = render_gaussians(gaussians, pose, expression)
        
        # Compute loss
        loss = compute_loss(rendered_image, video_frames[iteration])
        loss_l1 = 0.01 * l1_loss(rendered_image, video_frames[iteration])
        loss_ssim = 1.0 * ssim_loss(rendered_image, video_frames[iteration])
        total_loss = loss_l1 + loss_ssim
        
        # Backpropagate and update Gaussians
        update_gaussians(gaussians, total_loss)
        
        # Densify, Prune, and Opacity Reset
        if iteration >= 600 and iteration <= 15000:
            if iteration % 100 == 0:
                # Standard 3DGS densification
                gaussians = densify_gaussians(gaussians, threshold=10.0, rotation_threshold=0.008)
                gaussians = prune_gaussians(gaussians)
                
                # Opacity reset every 3000 iterations
                if iteration % 3000 == 0:
                    gaussians.opacity = 0.0
                
                # Enforce Gaussians stay within mesh triangles
                gaussians = walking_on_triangle(gaussians, flame_mesh)
    
    return gaussians

def walking_on_triangle(gaussians, mesh):
    # Project Gaussian centers to mesh surface
    # Ensure they remain within the bounds of their assigned triangle
    for gaussian in gaussians:
        triangle = get_triangle_for_gaussian(gaussian)
        gaussian.center = project_to_triangle(gaussian.center, triangle)
        # Clip UV values to prevent moving beyond triangle boundaries
        gaussian.uv = clip_uv(gaussian.uv, triangle.uv_bounds)
    return gaussians
```

**Edge Cases and Pitfalls:**
*   **Nearest-Triangle Sampling:** Using nearest-triangle sampling for deformation from posed space to canonical space (as in INSTA) causes unstable sampling in canonical space and strong noise in complex geometries like the eye region [S2, unofficial]. SplattingAvatar avoids this by using embeddings-based motion control [S2, unofficial].
*   **Disabling Walking on Triangle:** Disabling the 'walking on triangle' mechanism and clipping UV values causes Gaussians to stick and pile up on the boundaries of mesh triangles, leading to performance drops in PSNR, SSIM, and LPIPS metrics [S2, unofficial].

## Operating characteristics
*   **Performance:** Renders over 300 FPS on an NVIDIA RTX 3090 GPU [S2, unofficial].
*   **Quality:** On head avatar dataset, achieves PSNR 28.19, SSIM 0.931, LPIPS 0.063 with FLAME; PSNR 28.86, SSIM 0.931, LPIPS 0.060 with NHA [S2, unofficial].
*   **Comparison:** Compared to FLARE, SplattingAvatar does not focus on accurate geometry and materials reconstruction but offers significant improvement in photometric quality and rendering efficiency [S2, unofficial].
*   **Ablation:** Disabling 'walking on triangle' reduces PSNR from 30.04 to 29.91 (bala) and 33.01 to 32.48 (male-3-casual) [S2, unofficial].
*   **Strengths:** Real-time rendering, high photometric quality, robust handling of complex geometries (eyes, hair) [S2, unofficial].
*   **Limitations:** Does not reconstruct accurate geometry or materials compared to methods like FLARE [S2, unofficial].

## Background
SplattingAvatar was introduced in the paper "SplattingAvatar: Realistic Real-Time Human Avatars with Mesh-Embedded Gaussian Splatting" [S2, unofficial]. It builds on the principles of 3D Gaussian Splatting Training and extends them to head avatars by embedding Gaussians in mesh tangent space [S2, unofficial]. The method addresses limitations of previous approaches like INSTA, which suffered from noise due to nearest-triangle sampling [S2, unofficial].
