# Feed-forward Generalizable Reconstruction

Also called: Feed-forward 3D Gaussian Splatting, FF3DGS, Generalizable Gaussian Splatting

## Overview
Feed-forward generalizable reconstruction maps input images directly to a set of 3D Gaussian parameters $\mathcal{G} = \{\mu, \Sigma, \alpha, c\}$ without per-scene gradient descent [Parent]. It solves the latency bottleneck of traditional 3D Gaussian Splatting, which requires minutes of optimization per scene, by learning a global prior from large datasets to enable real-time inference on unseen scenes [Parent]. It distinguishes itself from iterative methods by replacing optimization with a single forward pass of a neural network, and from implicit methods by producing explicit, rasterizable primitives that support high-fidelity novel view synthesis and mesh extraction [Parent].

## Shared principles
All methods in this family share the core objective of mapping input image features to a set of 3D Gaussian parameters $\mathcal{G} = \{\mu, \Sigma, \alpha, c\}$ without per-scene gradient descent [Parent].

1.  **Input Representation:** Inputs are typically one or more RGB images $I \in \mathbb{R}^{H \times W \times 3}$. Some methods require known camera poses $P$, while others (e.g., [Splatt3R](16423-splatt3r.md), [ZeroGS](16425-zerogs.md)) predict poses or operate on uncalibrated inputs [Parent].
2.  **Feature Encoding:** A shared encoder (e.g., Vision Transformer, CNN) extracts multi-scale features from the input images. Cross-attention or cost volumes are often used to aggregate multi-view information [Parent].
3.  **Primitive Prediction:** A decoder head predicts Gaussian attributes. These attributes are usually:
    *   **Mean ($\mu$):** 3D position.
    *   **Covariance ($\Sigma$):** Defined by scale $s$ and rotation $r$ (quaternion or 6D).
    *   **Opacity ($\alpha$):** Scalar.
    *   **Color ($c$):** Spherical Harmonics (SH) coefficients or constant RGB [Parent].
4.  **Differentiable Rendering:** The predicted Gaussians are rendered into target views using differentiable rasterization to compute reconstruction losses (e.g., L1, SSIM, LPIPS) for training the network [Parent].
5.  **Generalization:** The network is trained on a large dataset of scenes to learn priors about geometry and appearance, allowing inference on unseen scenes [Parent].

## Subtopics

### [AnySplat Pipeline](12847-anysplat-pipeline.md)
The AnySplat Pipeline is a feed-forward method for generalizable 3D Gaussian Splatting that operates on uncalibrated input views, simultaneously predicting Gaussian parameters, depth maps, and camera poses without per-scene optimization. It distinguishes itself from sibling methods like [Splatt3R](16423-splatt3r.md) and [ZeroGS](16425-zerogs.md) by explicitly integrating a Differentiable Voxelization module to convert pixel-wise Gaussians into a voxelized representation, which stabilizes rendering and enables robust geometry supervision via pseudo-geometry priors from a pretrained VGGT model. See [AnySplat Pipeline](12847-anysplat-pipeline.md).

### [FineSplat](15257-finesplat.md)
FineSplat is a feed-forward 3D Gaussian Splatting framework that predicts a set of 3D Gaussians from $N$ context views using a two-stage dual-grouping strategy to balance local detail preservation with global multi-view reasoning. It distinguishes itself from sibling methods like [YoNoSplat](16425-yonosplat.md) and [ZipSplat](16425-zipsplat.md) by employing high-resolution 4x4 patch tokens instead of coarser 14x14 patches, combined with serialized attention for 3D spatial grouping to avoid the prohibitive cost of global multi-view attention. See [FineSplat](15257-finesplat.md).

### [SparSplat](15813-sparsplat.md)
SparSplat is a generalizable, feed-forward model that maps a sparse set of input images to 2D Gaussian Splatting (2DGS) parameters in a single forward pass to perform both 3D shape reconstruction and novel view synthesis. It differs from its sibling [MVSGaussian](16571-mvsgaussian.md) by using 2D planar primitives instead of 3D volumetric primitives, which ensures multi-view depth consistency required for coherent TSDF mesh fusion. Unlike prior generalizable methods designed primarily for novel view synthesis, SparSplat is explicitly optimized for feed-forward surface reconstruction, offering inference speeds nearly two orders of magnitude faster than implicit volume rendering methods. See [SparSplat](15813-sparsplat.md).

### [Splatt3R](16423-splatt3r.md)
Splatt3R is a feed-forward model that predicts 3D Gaussian Splat parameters directly from a pair of uncalibrated RGB images, without requiring camera intrinsics, extrinsics, or depth maps. It solves the problem of generalizable novel view synthesis by extending the MASt3R foundation model with a parallel "Gaussian head" to predict geometry offsets, covariances, opacities, and colors. Unlike sibling methods that restrict supervision to viewpoints interpolated between input stereo views, Splatt3R employs a loss masking strategy to enable robust extrapolation to viewpoints outside the input frustums. See [Splatt3R](16423-splatt3r.md).

### [GlobalSplat](16571-globalsplat.md)
GlobalSplat is a feed-forward framework for 3D Gaussian Splatting that aligns multi-view inputs into a fixed set of global latent scene tokens before decoding explicit 3D geometry, preventing representation bloat and ensuring global consistency. Unlike sibling methods such as [C3G](12847-anysplat-pipeline.md) which rely on full self-attention and single-Gaussian decoding, GlobalSplat uses an iterative, disentangled dual-branch architecture and a coarse-to-fine capacity curriculum to achieve a superior quality-efficiency trade-off in large-context settings. See [GlobalSplat](16571-globalsplat.md).

### [Generalizable Pixel-Wise 3D Gaussian Splatting](17059-generalizable-pixel-wise-3d-gaussian-splatting.md)
Generalizable Pixel-Wise 3D Gaussian Splatting (GPS-Gaussian) is a feed-forward method for real-time novel view synthesis of humans from sparse camera views. It solves the problem of per-subject optimization latency in 3D Gaussian Splatting by directly regressing Gaussian parameters from source images without fine-tuning. Unlike sibling methods that recompute view-correlated modules for every target viewpoint, GPS-Gaussian performs source-view computation once and renders novel views instantly, allowing concurrent rendering of multiple views. See [Generalizable Pixel-Wise 3D Gaussian Splatting](17059-generalizable-pixel-wise-3d-gaussian-splatting.md).

### [LGTM (Less Gaussians, Texture More)](17426-lgtm-less-gaussians-texture-more.md)
LGTM is a feed-forward framework that predicts compact 2D Gaussian primitives coupled with per-primitive texture maps to enable high-fidelity 4K novel view synthesis without per-scene optimization. It solves the quadratic growth in primitive count inherent in pixel-aligned feed-forward 3DGS methods, which makes high-resolution synthesis intractable due to memory and compute limits. Unlike standard 3DGS which couples appearance and geometry within each primitive, LGTM decouples them, allowing a compact set of geometric primitives to represent rich texture regions via per-primitive textures. See [LGTM (Less Gaussians, Texture More)](17426-lgtm-less-gaussians-texture-more.md).

### [InfiniSplat v2](17642-infinisplat-v2.md)
InfiniSplat v2 is a feed-forward Gaussian reconstruction method for arbitrary input views that decouples geometry and attribute prediction, uses ground-truth (GT) camera poses for alignment during training, and employs large-angle target view supervision to improve rendering quality under large viewpoint changes. It differs from its siblings by freezing the geometry branch to prevent geometric degradation caused by joint optimization, and by using GT poses for alignment to avoid pose errors that misguide the network under large-angle supervision. See [InfiniSplat v2](17642-infinisplat-v2.md).

### [CodecSplat](18143-codecsplat.md)
CodecSplat is a compression framework for feed-forward 3D Gaussian Splatting (FF3DGS) that encodes an intermediate 2D Gaussian-generation feature into an entropy-coded scene bitstream, avoiding the inefficient compression of irregular 3D Gaussian primitives. Unlike existing 3DGS compression methods that compress Gaussian primitives after a structured-to-irregular transformation, CodecSplat places the coding bottleneck before 2D-to-3D Gaussian construction, allowing compression to exploit the structured intermediate feature representation. See [CodecSplat](18143-codecsplat.md).

### [DepthSplat](18278-depthsplat.md)
DepthSplat is a feed-forward method for 3D Gaussian splatting reconstruction that integrates pre-trained monocular depth features into a multi-view cost volume framework. It solves the problem of robust depth estimation in challenging scenes (occlusions, low-texture, non-Lambertian surfaces) where standard multi-view stereo fails, and scale ambiguities where monocular estimation fails. Unlike TranSplat, which refines coarse depth with monocular features (prone to error propagation), DepthSplat combines cost volumes and monocular features early in the pipeline. Unlike GS-LRM, it relies on explicit feature matching rather than pure data-driven priors, reducing training compute requirements significantly. See [DepthSplat](18278-depthsplat.md).

### [VG2GT](18425-vg2gt.md)
VG2GT is a feed-forward, non-pixel-aligned 3D Gaussian Splatting (3DGS) reconstruction framework that directly regresses geometrically accurate Gaussian scenes and camera parameters from an arbitrary number of unposed and uncalibrated images. It solves the problem of uneven Gaussian distributions and cross-view inconsistencies inherent in pixel-aligned methods by introducing a multi-scale differentiable voxel module that aggregates point-cloud features into a structured representation. Unlike siblings such as [AnySplat](16422-anysplat.md) which first regress pixel-aligned primitives and then aggregate them, VG2GT directly decodes Gaussian primitives from structured voxel features, avoiding the intermediate pixel-aligned representation. See [VG2GT](18425-vg2gt.md).

### Sliding Window Large-scale Reconstruction
Uses sliding windows to process the sequence and construct a unified large-scale Gaussian scene [S2, unofficial]. Successfully applied to a KITTI street sequence containing over 1,000 frames [S2, unofficial].

## Background
Feed-forward generalizable reconstruction emerged as a response to the computational cost of per-scene optimization in 3D Gaussian Splatting. Early work like SplatterImage [105] demonstrated single-view reconstruction using a U-Net to translate input images into Gaussian attributes, which could be extended to multi-view via warping [S1, unofficial]. Subsequent methods integrated multi-view stereo (MVS) principles, such as cost volumes (e.g., MVSplat [104]), and foundation models (e.g., MASt3R, VGGT) to improve geometric consistency and generalization to uncalibrated inputs [S1, unofficial]. The field has expanded to include specialized approaches for dynamic scenes (DrivingGaussian [108], HUGS [109], StreetGaussians [111]), large-scale reconstruction (WorldMirror 2.0 [S2, unofficial]), and compression (CodecSplat) [S1, unofficial].
