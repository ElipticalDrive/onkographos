# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, GSGEN Implementation Details, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific hyperparameters, data structures, and optimization schedules required to implement the 3D Gaussian Splatting (3DGS) training loop. It defines the densification criteria, pruning thresholds, and loss weighting that distinguish a functional 3DGS implementation from a generic differentiable renderer. It sets itself apart from [Sorting and Rendering Pipeline Optimization](12180-sorting-and-rendering-pipeline-optimization.md) by focusing on the geometric evolution of the primitive set rather than the computational throughput of the rasterizer, and from [Data Compression and Storage Optimization](12943-data-compression-and-storage-optimization.md) by prioritizing reconstruction fidelity over storage efficiency.

## How it works

### Inputs and Outputs
**Inputs:**
*   A set of $N$ training images with known camera poses (extrinsics $C_i$ and intrinsics).
*   An initial point cloud (typically from Structure-from-Motion, SfM) used to initialize the 3D Gaussians [S4].
*   Optimization hyperparameters: learning rates, iteration budget, densification intervals, and thresholds [S9, unofficial].

**Outputs:**
*   A final set of $M$ 3D Gaussians, each defined by position $\mathbf{x}$, covariance $\Sigma$ (parameterized as scale $\mathbf{s}$ and rotation $\mathbf{q}$), opacity $\alpha$, and spherical harmonic coefficients $\mathbf{c}$ [S1][S9, unofficial].

### Data Structures
The Gaussian population is stored in a flat array or structure-of-arrays (SoA) layout to facilitate efficient memory access during rasterization [S2]. Each Gaussian $j$ contains:
*   **Position:** $\mathbf{x}_j \in \mathbb{R}^3$
*   **Rotation:** $\mathbf{q}_j \in \mathbb{R}^4$ (unit quaternion)
*   **Scale:** $\mathbf{s}_j \in \mathbb{R}^3$ (log-space or linear)
*   **Opacity:** $\alpha_j \in \mathbb{R}$
*   **Color:** $\mathbf{c}_j$ (Spherical Harmonic coefficients, typically degree 1 or 3) [S3]

During training, auxiliary arrays track per-Gaussian metrics:
*   **Position Gradient Accumulator:** $\mathbf{g}_j \in \mathbb{R}^3$, accumulated over the densification interval [S1].
*   **Opacity:** Used for pruning [S1].

### Scene Extent Calculation
The scene extent $e_{\text{scene}}$ determines the initial scale of Gaussians and the thresholds for splitting/pruning. The default 3DGS implementation calculates extent based on camera positions:
$$ e_{\text{scene}} = 1.1 \cdot \max_{i=1}^{N_{\text{cam}}} \|\bar{C} - C_i\|_2 $$
where $\bar{C} = \frac{1}{N_{\text{cam}}} \sum_{i=1}^{N_{\text{cam}}} C_i$ is the average camera position [S4].

**Pitfall:** This default formulation is biased if cameras are clustered (e.g., orbiting a small object in a large environment), leading to an underestimated scene extent and incorrect densification [S4].

**Corrected Scene Extent:** To avoid this bias, the scene extent can be calculated based on the SfM point cloud:
$$ e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2 $$
where $N_{\text{SfM}}$ is the number of SfM points and $p_i$ is the $i$-th SfM point [S4].

### Training Loop
The training process follows a stochastic gradient descent loop [S9, unofficial]:

1.  **Sample View:** Randomly select one training image and its camera pose [S9, unofficial].
2.  **Render:** Project the current set of 3D Gaussians to 2D and rasterize the image using alpha blending [S9, unofficial].
3.  **Compute Loss:** Calculate the loss $\mathcal{L}$ between the rendered image and the ground-truth image [S9, unofficial].
4.  **Backpropagate:** Compute gradients $\nabla \mathcal{L}$ with respect to all Gaussian parameters [S9, unofficial].
5.  **Update:** Update Gaussian parameters using an optimizer (e.g., Adam) [S3].
6.  **Densification/Pruning:** Periodically modify the Gaussian set based on gradient metrics and opacity [S1].

### Loss Function
The total loss is a weighted combination of L1 loss and D-SSIM (Differential Structural Similarity) [S9, unofficial]:
$$ \mathcal{L} = (1 - \lambda) \mathcal{L}_1 + \lambda \mathcal{L}_{\text{SSIM}} $$
Typical value for $\lambda$ is 0.2 [S9, unofficial].

### Optimization Schedule and Densification
Densification is performed periodically to increase Gaussian density in under-reconstructed regions [S1][S9, unofficial].

**Splitting:**
*   **Interval:** Every 100 iterations [S1].
*   **Criterion:** Gaussians with accumulated view-space position gradient magnitude exceeding a threshold $T_{\text{pos}}$ are split.
*   **Threshold:** $T_{\text{pos}} = 0.02$ [S1].
*   **Method:** The Gaussian is cloned, and the clone's position is perturbed. The original is retained [S1].

**Cloning:**
*   **Criterion:** Gaussians with high opacity but low gradient magnitude are cloned to increase density without splitting [S1].

**Pruning:**
*   **Interval:** Every 200 iterations [S1].
*   **Criterion:** Gaussians with opacity $\alpha < \alpha_{\text{min}}$ are removed.
*   **Threshold:** $\alpha_{\text{min}} = 0.05$ [S1].
*   **Additional Criterion:** Gaussians with excessively large world-space or view-space radius are also removed [S1].

**Compactness-based Densification:**
*   **Interval:** Every 1000 iterations [S1].
*   **Method:** Adjusts the distribution of Gaussians to improve compactness [S1].

### Implementation Parameters
*   **Optimizer:** Adam [S3].
*   **Learning Rate:** $1 \times 10^{-3}$ for position, scale, rotation, and opacity; $1.6 \times 10^{-6}$ for spherical harmonic coefficients [S3][S9, unofficial].
*   **Iteration Budget:** Typically 30,000 iterations [S9, unofficial].
*   **Spherical Harmonic Degree:** 1 (default) or 3 [S3].
*   **Half-Precision:** Use FP16 for feature vectors during rasterization to reduce register pressure [S2]. Apply an automatic scaling factor to loss values to improve half-precision training stability [S2].

### Pseudocode

```python
def train_3dgs(training_images, initial_gaussians, num_iterations=30000):
    """
    Main training loop for 3D Gaussian Splatting.
    
    Args:
        training_images: List of (image, camera_pose) tuples.
        initial_gaussians: List of Gaussian objects initialized from SfM.
        num_iterations: Total number of training steps.
        
    Returns:
        final_gaussians: The optimized set of 3D Gaussians.
    """
    gaussians = initial_gaussians
    optimizer = Adam(gaussians.parameters(), lr=1e-3)
    
    # Accumulators for densification
    grad_accumulators = {g.id: torch.zeros(3) for g in gaussians}
    
    for iteration in range(1, num_iterations + 1):
        # 1. Sample a random view
        image, camera_pose = random.choice(training_images)
        
        # 2. Render the view
        rendered_image = rasterize(gaussians, camera_pose)
        
        # 3. Compute Loss
        # L = 0.8 * L1 + 0.2 * SSIM
        loss = compute_loss(rendered_image, image, lambda_ss=0.2)
        
        # 4. Backpropagate
        optimizer.zero_grad()
        loss.backward()
        
        # 5. Update parameters
        optimizer.step()
        
        # 6. Accumulate gradients for densification
        for g in gaussians:
            if g.requires_grad:
                grad_accumulators[g.id] += g.position.grad.norm(dim=1)
        
        # 7. Periodic Densification and Pruning
        if iteration % 100 == 0:
            densify(gaussians, grad_accumulators, threshold=0.02)
            
        if iteration % 200 == 0:
            prune(gaussians, alpha_min=0.05)
            
        if iteration % 1000 == 0:
            compactify(gaussians)
            
        # Reset accumulators after densification
        if iteration % 100 == 0:
            for g in gaussians:
                grad_accumulators[g.id] = torch.zeros(3)
                
    return gaussians

def densify(gaussians, grad_accumulators, threshold):
    """
    Split and clone Gaussians based on gradient magnitude.
    """
    new_gaussians = []
    for g in gaussians:
        grad_mag = grad_accumulators[g.id]
        if grad_mag > threshold:
            # Split: Clone and perturb
            clone = g.clone()
            clone.position += perturb(g.position)
            new_gaussians.append(clone)
            # Keep original
            new_gaussians.append(g)
        else:
            new_gaussians.append(g)
    return new_gaussians

def prune(gaussians, alpha_min):
    """
    Remove Gaussians with low opacity.
    """
    return [g for g in gaussians if g.opacity >= alpha_min]
```

### Corrected Scene-Extent
A method to calculate scene extent based on the SfM point cloud rather than camera positions to avoid bias from camera distribution (e.g., orbiting a small object in a large environment) [S4]. The corrected extent is $e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2$ [S4]. The default extent $e_{\text{scene}} = 1.1 \cdot \max_{i=1}^{N_{\text{cam}}} \|\bar{C} - C_i\|_2$ can lead to incorrect splitting/pruning if cameras are clustered [S4].

### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ to selectively enlarge covariances, creating pixel-wise variable blur kernels that match spatially varying scene blurriness [S5]. If $\delta s_j$ is predicted as a constant, it degrades to a uniform Gaussian blur [S5].

### Denoise-GS
A self-supervised denoising method for sparse-view 3DGS that combines unsupervised image denoising (Noise2Void) with differentiable 3DGS [S6]. It uses a two-round process: Round 1 trains a UNet for denoising and initializes 3DGS; Round 2 fine-tunes the UNet and renders denoised views [S6].

### Multi-Scale Constraint
Applies different scales to Gaussians based on viewer distance to improve rendering of distant objects [S7]. Uses a position-aware point adaptive control where cloning and splitting thresholds are modulated by $\gamma(\mu)$, a function of the Gaussian's distance from the camera center [S7].

### LS-Gaussian Viewpoint Transformation
Leverages inter-frame continuity for efficient sparse rendering by transforming the viewpoint between consecutive frames, rather than rendering each frame separately [S8]. Rendering quality degrades as the number of consecutively transformed frames increases due to accumulated interpolation errors [S8].

### 3D Gaussian Splatting Training Loop
Per-image error compares one render against one photo. Scene-wide error is the loss averaged across all training views [S9, unofficial]. Training typically runs for a fixed number of iterations (e.g., 30,000) rather than stopping at a specific loss threshold [S9, unofficial]. The loss is a blend of L1 and D-SSIM, weighted with $\lambda \approx 0.2$ [S9, unofficial].

### Camera Localisation for Convergence Basin
Localizes camera pose by minimizing photometric error against the ground-truth colour image of the target view, fixing the initial Gaussians $G_{init}$ during optimization [S10, unofficial].

### DiffGS Framework
Applies an optimization process during Gaussian extraction to optimize Gaussians to exact locations [S11]. Uses a truncation function $\lambda$ and projection function $\tau$ (e.g., $\tau(x) = e^{-x}$) [S11].

### Opacity Offset Table for DSA
Constructs an opacity offset table to model changes in digital subtraction angiography [S12].

### Resolution Guided Primitive Scheduler
Uses a concave-up scheduling function to control primitive growth, mitigating poor convergence at the end of optimization [S13]. The primitive budget is updated as $P_{fin}^{(i)} = \max(P_{fin}^{(i-1)}, \gamma \cdot P_{fin}^{(i-1)} + \eta \cdot P_{add})$ [S13].

### Conditional Splat Approximation
Approximates the influence range of a 3D Gaussian on a slice by using a 2D ellipse splat scaled by the marginal factor, closely matching true iso-probability contours [S14, unofficial].

### Deformation-Aware Pruning
Identifies and removes redundant Gaussians by gauging their impact on deformation, distinguishing between stable and deformed Gaussians [S15].

### GEMM-GS
Reformulates the blending process into a GEMM-compatible form to leverage Tensor Cores on GPUs [S16]. Achieves a 1.42× speedup over vanilla 3DGS and an additional 1.47× speedup when combined with existing acceleration approaches [S16].

## Operating characteristics
*   **Time Complexity:** The training time is dominated by the rasterization and backpropagation steps, which are $O(N \cdot M)$ where $N$ is the number of pixels and $M$ is the number of Gaussians per pixel [S1][S9, unofficial]. The densification and pruning steps add overhead but are performed periodically [S1].
*   **Memory Complexity:** Memory usage scales with the number of Gaussians $M$, which can grow to millions for complex scenes [S1][S9, unofficial]. Each Gaussian requires storage for position, rotation, scale, opacity, and SH coefficients [S2].
*   **Measured Performance:** On a standard GPU, vanilla 3DGS can render at real-time speeds (e.g., 100+ FPS) for moderate scene sizes [S16]. GEMM-GS achieves a 1.42× speedup over vanilla implementation [S16].
*   **Strengths:** High-quality novel view synthesis, real-time rendering, and explicit scene representation [S1][S9, unofficial].
*   **Limitations:** High memory usage for large scenes, potential for floating artifacts in sparse regions, and sensitivity to initialization [S1, S4, S7].
*   **When to Use:** When high-fidelity novel view synthesis is required and computational resources are sufficient to handle the memory footprint [S9, unofficial].
*   **When Not to Use:** When memory is severely constrained or when real-time rendering on low-power devices is required without acceleration techniques [S8, S16].

## Background
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1]. It represents a scene as a set of 3D Gaussians and uses differentiable rasterization to optimize their parameters from multi-view images [S1]. The method has since been extended in various directions, including semantic rendering [S12], dynamic scenes [S15], and large-scale environments [S7].
