# Neural Radiance Field (NeRF) Representation

Also called: Instant Neural Graphics Primitives (INGP), Photon Field Networks, Photon Fields

## Overview
Neural Radiance Field (NeRF) representation refers to two distinct but related approaches for 3D scene modeling: the original implicit neural field formulation and the explicit 3D Gaussian Splatting (3DGS) representation. The original NeRF [S1] implicitly represents a 6-dimensional illumination volume using a neural network to map position, view direction, and phase function coefficients to radiance, solving the problem of high-quality novel view synthesis by replacing expensive volumetric integration with constant-time network inference [S1]. In contrast, 3D Gaussian Splatting [S2, unofficial] explicitly represents a scene as millions of tiny colored semi-transparent 3D Gaussian blobs, rendering them via differentiable rasterization to achieve real-time performance, thereby avoiding neural network evaluation during rendering [S2, unofficial]. While NeRF offers compact memory usage, Gaussian Splatting provides significantly faster training and rendering speeds at the cost of higher memory consumption [S2, unofficial].

## How it works
The implementation details differ fundamentally between the implicit NeRF (Photon Field) approach and the explicit Gaussian Splatting approach. Both are described below.

### Implicit NeRF (Photon Field Networks)
This method represents indirect global illumination as a neural field.

**Inputs and Outputs:**
*   **Input:** Sample position $x \in [0,1]^3$, view direction $\vec{\omega}$ in normalized spherical coordinates, and a phase function coefficient $g \in [-1,1]$ [S1].
*   **Output:** Predicted log-encoded indirect radiance $L_i'(x, \vec{\omega})$, which is decoded to RGB values [S1].

**Data Structures:**
*   **Hashgrid Encoding:** Used for positions (3D) and directions (2D). Configuration: 16 grid levels, 8 features per level, 2x scaling factor between levels, hash table size $2^{19}$ [S1]. The phase coefficient $g$ is left unencoded [S1].
*   **Neural Network:** A 5-layer perceptron with 64 neurons per layer, ReLU activations between hidden layers, and no output activation [S1].
*   **Photon Map:** A collection of photons generated via multi-phase photon tracing, stored on the GPU with a kd-tree for fast spatial queries [S1].

**Parameters:**
*   **Phase Coefficients ($G$):** Discrete set of coefficients for photon assignment. The set $G = \{-0.75, 0.0, 0.75\}$ is used as a compromise between tracing speed and field quality [S1].
*   **Precision ($\psi$):** Maximum desired floating point precision in digits beyond zero. Typical values are 4 to 6 [S1].
*   **KNN Parameters:** Number of neighbors $K=1024$ and a maximum query radius $r$ for radiance estimation [S1].
*   **Batch Size:** $2^{16}$ samples per training batch [S1].

**Steps:**
1.  **Photon Tracing:** Generate a photon map by tracing photons from random light sources. For each photon, pick a phase coefficient $g$ randomly from $G$. Trace the photon through the volume using delta tracking. Store photons after their first interaction with the medium (bounces $\ge 1$) [S1].
    ```python
    # Pseudocode for Photon Tracing (Algorithm 1 from [S1])
    n_photons = 0
    photonmap = []
    while n_photons < max_n_photons:
        bounces = 0
        throughput = 1.0
        photon = generate_from_random_light_source()
        photon.g = random_pick_from(G) # G = {-0.75, 0.0, 0.75}
        while bounces < max_bounces:
            # Compute sample distance via delta tracking
            if no_interaction_via_delta_tracking():
                break # Photon left the volume
            photon.position = interaction_location
            photon.direction = PHASE_FUNCTION(photon.g, photon.direction)
            sample = VOLUME(photon.position)
            albedo = TRANSFER_FUNCTION(sample)
            throughput = throughput * albedo.alpha * albedo.rgb
            photon.intensity = light.intensity * throughput
            if bounces >= 1:
                photonmap.append(photon)
                n_photons += 1
            bounces += 1
            if russian_roulette_termination():
                break
    ```
2.  **Data Sampling:** Construct a kd-tree on the GPU from the photon map. Generate training batches of size $2^{16}$. Each batch contains uniformly sampled grid coordinates $x \in [0,1]$, random uniform directions $\vec{\omega}$, and phase coefficients $g$ randomly selected from $G$ [S1].
3.  **Ground Truth Radiance Estimation:** For each sample $(x, g, \vec{\omega})$, perform a phase-specific k-nearest-neighbor (KNN) range query on the photon map. Only consider photons with the matching phase coefficient $g$. Use $K=1024$ neighbors and a maximum query radius $r$. Compute the radiance using the KNN adaptive radius estimator:
    $$
    L_i(x, \vec{\omega}) \approx \sum_{n=1}^K p_g(x, \vec{\omega}, \vec{\omega}_n) \frac{\Phi_n}{4\pi r^3}
    $$
    where $r$ is the distance to the farthest photon, $\Phi_n$ is the photon intensity, and $p_g$ is the Henyey-Greenstein phase function determined by $g$ [S1].
4.  **Target Encoding:** Encode the ground truth radiance $L_i$ logarithmically to normalize it to $[0,1]$. Using precision parameter $\psi$ (typically 4-6):
    $$
    L_i'(x, \vec{\omega}) = \begin{cases} -\frac{\log_{10}(L_i(x, \vec{\omega}))}{\psi} & \text{if } L_i(x, \vec{\omega}) > \frac{1}{10^{\psi}} \\ 1 & \text{otherwise} \end{cases}
    $$
    If $L_i < 10^{-\psi}$, clamp to 1 (which maps to 0 in the inverse transformation) [S1].
5.  **Network Training:** Pass the batch of encoded inputs $[(x, g, \vec{\omega}), L_i']$ to the 5-layer MLP. The network predicts $L_i'$. Regenerate a new batch for every training step [S1].
6.  **Decoding:** To obtain the final RGB indirect radiance values, apply the inverse logarithmic transformation to the network output $L_i'$:
    $$
    L_i(x, \vec{\omega}) = 10^{-L_i'(x, \vec{\omega})} \cdot \Psi
    $$
    where $\Psi$ is the scaling factor related to $\psi$ (Note: The source formula [S1] Eq. 7 uses $\Psi$ as a multiplier, likely representing the dynamic range or a constant derived from the encoding bounds, though exact value is not specified beyond the context of restoring radiance) [S1].

**Edge Cases and Pitfalls:**
*   **Precision:** Values below the precision threshold $\psi$ are clamped, potentially losing detail in very dark regions [S1].
*   **Query Radius:** The maximum query radius $r$ must be chosen carefully to limit the number of queried photons; it is provided by a custom training schedule [S1].

### Explicit NeRF (3D Gaussian Splatting)
This method represents the scene as a set of 3D Gaussians.

**Inputs and Outputs:**
*   **Input:** Camera pose $\mathbf{T}$, viewing direction $\vec{\omega}$, and a set of 3D Gaussians $\mathcal{G}$.
*   **Output:** Rendered image $C(\mathbf{r})$ [S2, unofficial].

**Data Structures:**
*   **Gaussian ($g_i$):** Each Gaussian stores approximately 59 learnable numbers [S2, unofficial]:
    *   Position: Center in 3D space ($\mu_i$).
    *   Shape: Scale and rotation, defining the covariance matrix $\Sigma_i$. The covariance is constructed as $R S S^T R^T$ to ensure positive semi-definiteness, where $R$ is the rotation matrix and $S$ is the scaling vector [S2, unofficial].
    *   Opacity: Transparency ($\alpha_i$).
    *   Color: Stored as spherical harmonic coefficients for view-dependent color ($\mathbf{c}_i$) [S2, unofficial].

**Steps:**
1.  **Initialization:** Start with photos and camera poses from Structure from Motion (e.g., COLMAP) to generate a sparse cloud of 3D points. Each point becomes the starting position of one Gaussian [S2, unofficial].
2.  **Projection:** Project every 3D Gaussian onto the camera image. A projected 3D Gaussian results in a 2D Gaussian (soft ellipse) on the screen. The 2D covariance is computed using the camera transformation and a local linear approximation of the projection [S2, unofficial].
3.  **Tiling:** Divide the screen into small tiles of 16x16 pixels. Assign each Gaussian to the tiles it overlaps [S2, unofficial].
4.  **Sorting:** Within each tile, sort the Gaussians by depth from front to back using a very fast GPU sort [S2, unofficial].
5.  **Rasterization/Blending:** For each pixel, blend the colors of the sorted Gaussians front-to-back using alpha compositing:
    $$
    C(\mathbf{r}) = \sum_{i \in \mathcal{N}} T_i \alpha_i \mathbf{c}_i(\vec{\omega})
    $$
    where $\mathcal{N}$ is the set of Gaussians in the tile, $\alpha_i$ is the opacity, and $T_i = \prod_{j=1}^{i-1} (1 - \alpha_j)$ is the accumulated transmittance [S2, unofficial].
6.  **Training Loss:** Compare the rendered image with the real training photo using an L1 loss combined with a structural similarity (SSIM) term [S2, unofficial].
7.  **Optimization:** Backpropagate the error to update each Gaussian's position, shape, opacity, and color directly via gradient descent [S2, unofficial].
8.  **Adaptive Density Control:**
    *   **Cloning:** In regions that are under-reconstructed with missing details, clone small Gaussians [S2, unofficial].
    *   **Splitting:** Where a single Gaussian is too large and covers too much detail, split it into two smaller ones [S2, unofficial].
    *   **Pruning:** Prune away Gaussians that become almost transparent [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Artifacts:** Can produce floating artifacts and needle-like Gaussians in regions seen by few cameras [S2, unofficial].
*   **Aliasing:** Zooming in or out can cause aliasing [S2, unofficial].
*   **Mesh Extraction:** The blobs do not directly give a clean surface or mesh [S2, unofficial].

## Subtopics

### [Scene NeRF](12484-scene-nerf.md)
Isolates static background by training exclusively on background pixels, excluding dynamic foreground. Uses an emptiness regularizer. Choose when dynamic objects must be removed from the scene representation.

### [NeRF-OSR](14477-nerf-osr.md)
Decomposes scene into geometry, albedo, and lighting for outdoor relighting. Provides explicit intrinsic decomposition. Choose when physical relighting and albedo editing are required.

### [Explicit Volumetric Rendering with Multiple View Aggregation](15335-explicit-volumetric-rendering-with-multiple-view-aggregation.md)
Models scene as an explicit RGB$\alpha$ volume to amortize rendering across views. Enables real-time rendering and structural losses. Choose when real-time rendering and SSIM training are needed.

### [Dynamic Neural Radiance Fields](16398-dynamic-neural-radiance-fields.md)
Reconstructs 4D avatars from monocular video by conditioning on expressions/pose. Provides 3D consistency and view-dependent effects. Choose when modeling temporal dynamics and expression editing is required.
#### SLAIM
A SLAM method that introduces a coarse-to-fine tracking pipeline and improves photometric bundle adjustment for NeRF-based mapping. Maintains NeRF’s original volume density formulation while introducing a KL regularization over the ray termination distribution. Addresses the challenge of high-frequency renderings in NeRF hindering image alignment [S3].
#### SNI-SLAM
A dense NeRF-based RGB-D SLAM system for accurate real-time 3D semantic mapping. Introduces a hierarchical semantic encoding and cross-attention mechanism to enable mutual reinforcement between appearance, geometry, and semantics modalities. Proposes a novel one-way decoder design to enhance inter-modal information flow without reverse interference [S3].
#### KN-SLAM
A NeRF-based SLAM method that integrates local feature correspondences for coarse pose initialization and joint optimization. Uses global image features and local matches for explicit loop detection. Performs pose graph optimization and global refinement of the neural map to ensure consistency [S3].

## Operating characteristics
*   **Implicit NeRF (Photon Fields):**
    *   **Time Complexity:** Training requires generating photon maps and training a neural network. Rendering is constant-time network inference, scaling slower than baseline volumetric methods [S1].
    *   **Memory Complexity:** Compact, as the scene is stored in a neural network [S1].
    *   **Strengths:** High-quality global illumination, efficient rendering after training, handles heterogeneous media [S1].
    *   **Limitations:** Requires complex photon tracing for training, indirect radiance only [S1].
*   **Explicit NeRF (3D Gaussian Splatting):**
    *   **Time Complexity:** Training time drops from many hours (NeRF) to tens of minutes. Rendering jumps from seconds per image to >100 FPS [S2, unofficial].
    *   **Memory Complexity:** Increases from a few megabytes (NeRF) to hundreds of megabytes (Gaussian Splatting) [S2, unofficial].
    *   **Strengths:** Real-time rendering, fast training, differentiable rasterization [S2, unofficial].
    *   **Limitations:** High memory usage, floating artifacts, aliasing, no clean mesh extraction [S2, unofficial].
    *   **Usage:** Virtual reality, film, robotics, mapping, digital humans, ecommerce, cultural heritage [S2, unofficial].

## Background
*   **Implicit NeRF (Photon Fields):** Introduced in "Photon Field Networks for Dynamic Real-Time Volumetric Global Illumination" [S1]. It replaces expensive sampling steps in scientific volume rendering with neural network inference to represent 6-dimensional illumination volumes [S1].
*   **Explicit NeRF (3D Gaussian Splatting):** Introduced by Kerbal and colleagues at SIGGRAPH 2023 [S2, unofficial]. It represents scenes explicitly as millions of 3D Gaussians, enabling real-time rendering without neural network evaluation [S2, unofficial].
