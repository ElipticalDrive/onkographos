# Codebook Quantization

Also called: Clustering-based Codebook, K-means Codebook Quantization, Post-processing Quantization, Quantization via Codebooks

## Overview
Codebook Quantization is a post-processing compression technique for 3D Gaussian Splatting that reduces memory footprint by replacing high-precision floating-point attributes with indices into a fixed-size codebook [S1]. It specifically targets attributes with low sensitivity to precision errors—opacity, scale, rotation, and spherical harmonics (SH) coefficients—while preserving the full precision of primitive positions to prevent visual degradation [S1]. Unlike methods that alter the rendering pipeline or training loop, this approach operates as a final storage optimization, achieving an average memory reduction of 96.3% (approximately 27x) with minimal quality loss [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** The fully trained 3D Gaussian Splatting representation, including primitive positions, scales, rotations (quaternions), opacities, and SH coefficients.
*   **Output:** A compressed representation where non-position attributes are stored as 1-byte indices referencing codebooks, and remaining floating-point values (positions, codebook entries) are stored as 16-bit half-floats [S1].

**Data Structures:**
The method replaces dense arrays of 32-bit floats for specific attributes with:
1.  **Codebooks:** A list of 256 entries (vectors of floats) for each attribute group.
2.  **Indices:** A 1-byte integer per component per primitive, pointing to the closest entry in the corresponding codebook.

**Attributes and Codebook Allocation:**
Codebooks are created for the following attribute groups [S1]:
*   Opacity (scalar).
*   Scale (3 components: x, y, z).
*   Rotation (1 real part, 3 imaginary parts).
*   Base color (3 components: R, G, B).
*   SH coefficients (15 groups, each with 3 color components).

**Numbered Steps:**
1.  **Identify Attributes:** Select attributes for quantization: opacity, scale, rotation, and SH coefficients. Exclude primitive positions [S1].
2.  **Cluster Attributes:** For each attribute group, apply K-means clustering to the training data to generate a codebook of size $K=256$ [S1].
    *   For vector attributes (e.g., scale), maintain one shared codebook but treat the three scalar components separately. This results in one index per component [S1].
3.  **Quantize:** Replace the original float value of each primitive's attribute with the index of the closest entry in the corresponding codebook [S1].
4.  **Quantize Remaining Floats:** Apply 16-bit half-float quantization to all remaining uncompressed floating-point values, specifically primitive positions and the codebook entries themselves [S1].

**Formulas:**
Let $N$ be the number of Gaussians.

*   **Scale Storage Cost:**
    Original cost: $3N \times 4$ bytes.
    Quantized cost: $3N + 4 \times 256$ bytes.
    (Where $3N$ is the storage for indices, and $4 \times 256$ is the storage for the codebook entries, assuming 4 bytes per float entry in the codebook before half-float conversion, or effectively negligible overhead for large $N$) [S1].

*   **Total Attribute Memory Reduction:**
    Original cost for quantized attributes: $56N \times 4$ bytes.
    Quantized cost: $56N + 20 \times 256 \times 4$ bytes.
    (The term $56N$ represents the total number of indices required for opacity, scale, rotation, base color, and SH coefficients. The term $20 \times 256 \times 4$ represents the overhead of the 20 distinct codebooks) [S1].

*   **Overall Memory Reduction:**
    Average reduction: 96.3% [S1].

**Parameters:**
*   **Codebook Size:** 256 entries [S1].
*   **Index Size:** 1 byte [S1].
*   **Remaining Float Precision:** 16-bit half-float [S1].

**Edge Cases and Pitfalls:**
*   **Position Accuracy:** Reducing the accuracy of primitive positions leads to significant degradation in visual quality. Therefore, positions are strictly excluded from codebook quantization [S1].
*   **Precision Sensitivity:** Attributes like opacity and SH coefficients are chosen because they do not require high dynamic range or high precision. Using codebooks for attributes requiring high fidelity is not recommended [S1].

**Pseudocode:**
```python
import numpy as np
from sklearn.cluster import KMeans

def codebook_quantization(gaussians, codebook_size=256):
    """
    Compress 3D Gaussian Splatting attributes using codebook quantization.
    
    Args:
        gaussians: Object containing attributes:
            - positions: (N, 3) float32
            - opacities: (N, 1) float32
            - scales: (N, 3) float32
            - rotations: (N, 4) float32 (quaternion w, x, y, z)
            - sh_coeffs: (N, 15, 3) float32 (SH groups, RGB)
            - base_colors: (N, 3) float32 (if not included in SH)
            
    Returns:
        compressed_gaussians: Dictionary with quantized indices and codebooks
    """
    N = gaussians.positions.shape[0]
    compressed = {}
    
    # Step 1: Define attribute groups to quantize
    # Note: Positions are excluded [S1]
    attribute_groups = {
        'opacity': gaussians.opacities.flatten(),
        'scale_x': gaussians.scales[:, 0],
        'scale_y': gaussians.scales[:, 1],
        'scale_z': gaussians.scales[:, 2],
        'rot_real': gaussians.rotations[:, 0],
        'rot_imag_x': gaussians.rotations[:, 1],
        'rot_imag_y': gaussians.rotations[:, 2],
        'rot_imag_z': gaussians.rotations[:, 3],
        'base_r': gaussians.base_colors[:, 0],
        'base_g': gaussians.base_colors[:, 1],
        'base_b': gaussians.base_colors[:, 2],
    }
    
    # Add SH coefficients as separate groups
    # 15 groups * 3 components = 45 groups
    for group_idx in range(15):
        for comp_idx in range(3):
            attr_name = f'sh_g{group_idx}_c{comp_idx}'
            attribute_groups[attr_name] = gaussians.sh_coeffs[:, group_idx, comp_idx]
            
    compressed['codebooks'] = {}
    compressed['indices'] = {}
    
    # Step 2 & 3: Create codebooks and quantize
    for attr_name, values in attribute_groups.items():
        # Reshape for KMeans (n_samples, n_features)
        # Since we treat components separately, each is 1D
        values_reshaped = values.reshape(-1, 1)
        
        # K-means clustering to create codebook
        kmeans = KMeans(n_clusters=codebook_size, random_state=42, n_init=10)
        kmeans.fit(values_reshaped)
        
        # Store codebook entries
        compressed['codebooks'][attr_name] = kmeans.cluster_centers_.flatten()
        
        # Store indices (1-byte integers)
        # Map each value to its closest cluster center index
        indices = kmeans.predict(values_reshaped)
        compressed['indices'][attr_name] = indices.astype(np.uint8)
        
    # Step 4: Quantize remaining floats (positions and codebook entries) to half-float
    # Positions are stored as half-floats
    compressed['positions'] = gaussians.positions.astype(np.float16)
    
    # Codebook entries are also stored as half-floats
    for attr_name in compressed['codebooks']:
        compressed['codebooks'][attr_name] = compressed['codebooks'][attr_name].astype(np.float16)
        
    return compressed
```

## Operating characteristics
*   **Time Complexity:** The method is a post-processing step, so it does not affect rendering time. The compression time depends on the K-means clustering complexity, which is generally linear with respect to the number of primitives $N$ and the number of clusters $K$ [S1].
*   **Memory Complexity:** Reduces memory usage by approximately 96.3% (27x reduction) compared to the original 3DGS file size [S1]. The memory overhead for codebooks is constant ($20 \times 256 \times 4$ bytes) and negligible for large $N$ [S1].
*   **Strengths:** Significant reduction in storage and transmission requirements without altering the rendering algorithm or requiring changes to the GPU kernel [S1].
*   **Limitations:** Requires a post-processing step after training. Cannot be applied dynamically during training. Quality degradation is minimal but non-zero (average 0.21 dB PSNR drop) [S1].
*   **When to use:** When storage or bandwidth is a bottleneck and slight quality loss is acceptable.
*   **When not to use:** When maximum visual fidelity is required, or when positions need to be compressed (which causes significant degradation) [S1].

## Background
Codebook Quantization was introduced in the paper "Reducing the Memory Footprint of 3D Gaussian Splatting" [S1]. It builds on the observation that many primitive attributes in 3D Gaussian Splatting do not require high dynamic range or precision. The method was developed to address the large memory footprint of 3DGS, which can be prohibitive for large scenes. It is used as a final compression stage in optimized 3DGS pipelines.
