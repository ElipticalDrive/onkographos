# Progressive Partitioning for Large-Scale 3DGS

Also called: Progressive Data Partitioning, Progressive Partitioning

## Overview
Progressive Partitioning is a data distribution strategy for training 3D Gaussian Splatting on large-scale scenes by dividing the environment into spatially-disjoint cells, each containing a subset of training cameras and 3D Gaussians [S1, S2]. It solves the memory and time bottlenecks of global optimization by enabling parallel, lower-memory training per cell [S2]. It distinguishes itself from naive spatial splitting by using an airspace-aware visibility criterion to ensure sufficient supervision of the volume above the surface, preventing floaters and under-supervision [S2].

## How it works
**Inputs:**
- Point cloud $P$ (initially empty or sparse) [S2].
- Set of training views $V$ [S2].
- Scene dimensions defining the ground plane [S2].
- Grid dimensions $m \times n$ (number of cells along two axes) [S2].
- Visibility threshold $T_h$ (typically 25%) [S2].
- Boundary expansion ratio $\alpha$ (typically 0.2 or 20%) [S2].

**Outputs:**
- A set of $m \times n$ cells [S2].
- For each cell $j$: a subset of cameras $V_j$ and a subset of points $P_j$ [S2].

**Data Structures:**
- **Cell $j$**: Defined by a rectangular region on the ground plane with height $h_j$ and width $w_j$ [S2].
- **Point Cloud $P_j$**: List of 3D Gaussian parameters (position, covariance, opacity, spherical harmonics) associated with cell $j$ [S2].
- **Camera Set $V_j$**: List of camera poses and intrinsics assigned to cell $j$ [S2].

**Parameters:**
- $T_h$: Visibility threshold. Typical value: 25% [S2].
- $\alpha$: Boundary expansion factor. Typical value: 0.2 [S2].
- $m, n$: Grid dimensions. Example: $m=4, n=2$ for 8 cells [S2].

**Steps:**

1. **Camera-Position-Based Region Division**
   Partition the ground plane into a grid of $m \times n$ cells [S2].
   - Divide the ground plane into $m$ sections along one axis, such that each section contains approximately $|V|/m$ views based on camera positions [S2].
   - Subdivide each section into $n$ segments along the other axis, such that each segment contains approximately $|V|/(m \times n)$ views [S2].
   - Let the $j$-th cell be bounded by a rectangle of size $h_j \times w_j$ [S2].

2. **Position-Based Data Selection (Boundary Expansion)**
   Expand the boundaries of each cell to include context from neighboring areas [S2].
   - Calculate expanded dimensions:
     $$ h'_j = h_j + \alpha h_j $$
     $$ w'_j = w_j + \alpha w_j $$
   - Assign training views $V$ to $V_j$ if the camera position falls within the expanded boundaries of cell $j$ [S2].
   - Assign points $P$ to $P_j$ if the point position falls within the expanded boundaries of cell $j$ [S2].

3. **Visibility-Based Camera Selection**
   Refine the camera set $V_j$ for each cell to ensure adequate supervision of the airspace [S2].
   - For each camera $C_i$ not yet selected for cell $j$:
     - Calculate the projected area of the cell's volume in the image plane of $C_i$ [S2].
     - **Airspace-Aware Calculation**: Construct an axis-aligned bounding box (AABB) for the points currently in $P_j$ (or the cell's spatial extent) [S2].
     - Project this AABB onto the image plane to get area $\Omega_{ij}$ [S2].
     - Calculate visibility:
       $$ \text{Visibility} = \frac{\Omega_{ij}}{\Omega_i} $$
       where $\Omega_i$ is the total pixel area of image $I_i$ [S2].
     - If $\text{Visibility} > T_h$, add $C_i$ to $V_j$ [S2].
   - **Pitfall Avoidance**: Do not use only the convex hull of surface points ($\Omega_{\text{surf}, ij}$) for $\Omega_{ij}$, as this is airspace-agnostic and leads to under-supervision of the volume above the surface and floaters [S2]. Use the AABB of the cell's point cloud extent to capture the full volume [S2].

4. **Coverage-Based Point Selection**
   Initialize $P_j$ with points that are well-constrained by the selected cameras [S2].
   - Identify points in the global point cloud $P$ that are covered by **all** views in $V_j$ [S2].
   - Add these points to $P_j$ [S2].
   - This provides better initialization for optimization, reducing depth ambiguity and preventing the creation of floaters for objects outside the cell [S2].

5. **Optimization and Cleanup**
   - Optimize the 3D Gaussians in $P_j$ using only cameras in $V_j$ [S2].
   - After optimization, remove any 3D Gaussians generated outside the cell's boundaries to prevent artifacts (floaters) in adjacent cells [S2].

**Pseudocode:**

```python
def progressive_partitioning(point_cloud, views, m, n, threshold=0.25, expansion=0.2):
    # Step 1: Camera-Position-Based Region Division
    # Sort views by x-coordinate, split into m groups
    sorted_views_x = sorted(views, key=lambda v: v['position'][0])
    chunk_size_x = len(sorted_views_x) // m
    x_groups = [sorted_views_x[i:i+chunk_size_x] for i in range(0, len(sorted_views_x), chunk_size_x)]
    while len(x_groups) < m:
        x_groups.append(x_groups[-1])

    cells = []
    for group in x_groups:
        sorted_views_y = sorted(group, key=lambda v: v['position'][1])
        chunk_size_y = len(sorted_views_y) // n
        y_groups = [sorted_views_y[i:i+chunk_size_y] for i in range(0, len(sorted_views_y), chunk_size_y)]
        while len(y_groups) < n:
            y_groups.append(y_groups[-1])
        for y_chunk in y_groups:
            xs = [v['position'][0] for v in y_chunk]
            ys = [v['position'][1] for v in y_chunk]
            cells.append({
                'bounds': (min(xs), min(ys), max(xs), max(ys)),
                'h': max(ys) - min(ys),
                'w': max(xs) - min(xs)
            })

    cell_data = []
    for j, cell in enumerate(cells):
        h, w = cell['h'], cell['w']
        h_exp, w_exp = h * (1 + expansion), w * (1 + expansion)
        x_min, y_min, x_max, y_max = cell['bounds']
        # Center expansion around original bounds
        dx = (w_exp - w) / 2
        dy = (h_exp - h) / 2
        x_min_e, y_min_e = x_min - dx, y_min - dy
        x_max_e, y_max_e = x_max + dx, y_max + dy

        V_j = [v for v in views if x_min_e <= v['position'][0] <= x_max_e and y_min_e <= v['position'][1] <= y_max_e]
        P_j = [p for p in point_cloud if x_min_e <= p[0] <= x_max_e and y_min_e <= p[1] <= y_max_e]
        cell_data.append({'V': V_j, 'P': P_j, 'bounds': cell['bounds'], 'h': h, 'w': w})

    # Step 3: Visibility-Based Camera Selection
    for data in cell_data:
        V_j = data['V']
        P_j = data['P']
        x_min, y_min, x_max, y_max = data['bounds']
        remaining = [v for v in views if v not in V_j]
        for v in remaining:
            # Compute AABB of P_j or fallback to cell bounds
            if P_j:
                xs = [p[0] for p in P_j]
                ys = [p[1] for p in P_j]
                zs = [p[2] for p in P_j]
                aabb = (min(xs), min(ys), min(zs), max(xs), max(ys), max(zs))
            else:
                # Fallback to cell bounds extended vertically [G]
                aabb = (x_min, y_min, 0, x_max, y_max, 10)

            # Project AABB corners to image plane
            corners = []
            for dx in [0, 1]:
                for dy in [0, 1]:
                    for dz in [0, 1]:
                        p = (aabb[0] + dx*(aabb[3]-aabb[0]),
                             aabb[1] + dy*(aabb[4]-aabb[1]),
                             aabb[2] + dz*(aabb[5]-aabb[2]))
                        corners.append(project_3d_to_2d(p, v))

            # Compute bounding box area in pixels
            if corners:
                us = [c[0] for c in corners]
                vs = [c[1] for c in corners]
                proj_area = max(0, max(us) - min(us)) * max(0, max(vs) - min(vs))
            else:
                proj_area = 0

            image_area = v['image_width'] * v['image_height']
            visibility = proj_area / image_area if image_area > 0 else 0
            if visibility > threshold:
                V_j.append(v)
        data['V'] = V_j

    # Step 4: Coverage-Based Point Selection
    for data in cell_data:
        V_j = data['V']
        P_j = data['P']
        new_points = []
        for p in point_cloud:
            if all(is_visible_in_view(p, v) for v in V_j):
                new_points.append(p)
        data['P'].extend(new_points)

    return cell_data

def project_3d_to_2d(point, view):
    # Standard perspective projection [G]
    p_cam = [
        view['world_to_cam'][0][0]*point[0] + view['world_to_cam'][0][1]*point[1] + view['world_to_cam'][0][2]*point[2] + view['world_to_cam'][0][3],
        view['world_to_cam'][1][0]*point[0] + view['world_to_cam'][1][1]*point[1] + view['world_to_cam'][1][2]*point[2] + view['world_to_cam'][1][3],
        view['world_to_cam'][2][0]*point[0] + view['world_to_cam'][2][1]*point[1] + view['world_to_cam'][2][2]*point[2] + view['world_to_cam'][2][3]
    ]
    if p_cam[2] <= 0: return (0, 0) # Behind camera
    u = view['intrinsics'][0][0] * (p_cam[0] / p_cam[2]) + view['intrinsics'][0][2]
    v = view['intrinsics'][1][0] * (p_cam[1] / p_cam[2]) + view['intrinsics'][1][2]
    return (u, v)

def is_visible_in_view(point, view):
    u, v = project_3d_to_2d(point, view)
    return 0 <= u < view['image_width'] and 0 <= v < view['image_height']
```

## Operating characteristics
- **Time Complexity**: Training time is reduced because each cell is optimized independently and in parallel, requiring less training time than global optimization [S2].
- **Memory Complexity**: Memory usage per cell is lower, as each cell only stores a subset of Gaussians and cameras. This allows training on hardware with limited VRAM [S2].
- **Performance**: In experiments with 8 cells, visibility threshold of 25%, and 60,000 iterations per cell, the method achieved high-fidelity reconstruction on large-scale scenes [S2].
- **Strengths**: Enables large-scale reconstruction on consumer hardware; reduces floaters and airspace artifacts through airspace-aware visibility; provides better initialization via coverage-based point selection.
- **Limitations**: Requires careful tuning of grid dimensions ($m, n$) and visibility threshold ($T_h$); may introduce seams at cell boundaries if not handled by merging techniques (like those in VastGaussian) [S2].

## Background
Progressive Partitioning was introduced by Lin et al. in the VastGaussian paper (CVPR 2024) as a strategy to adapt 3D Gaussian Splatting for large-scale scenes [S1, S2]. It addresses the limitations of global optimization, such as high memory consumption and long training times, by partitioning the scene into manageable cells [S1, S2]. The method builds on the idea of distributed learning and feature encoding for large scenes [S1].
