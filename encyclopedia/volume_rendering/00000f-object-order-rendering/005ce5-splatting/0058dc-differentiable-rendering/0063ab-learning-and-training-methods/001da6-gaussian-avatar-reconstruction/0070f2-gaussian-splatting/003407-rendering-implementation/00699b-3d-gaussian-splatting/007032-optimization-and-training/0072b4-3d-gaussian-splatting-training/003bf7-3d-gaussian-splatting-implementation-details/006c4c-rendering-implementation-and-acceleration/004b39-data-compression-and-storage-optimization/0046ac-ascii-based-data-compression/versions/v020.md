# ASCII-Based Data Compression
Also called: Anywhere Compression, Base 94 Floating-Point Compression, Base 95 Integer Compression

## Overview
This method accelerates data transmission during the training of 3D Gaussian Splatting models by compressing numerical attributes into ASCII strings [S1, unofficial]. It solves the bottleneck of transmitting large volumes of floating-point and integer data between processing units or across networks by reducing the byte count per value [S1, unofficial]. It is distinguished from sibling methods like [Sensitivity-Aware Vector Clustering](12167-sensitivity-aware-vector-clustering.md) and [Compact 3D Gaussian Representation (C3DGS)](12927-compact-3d-gaussian-representation-c3dgs.md) by its focus on transmission speed via character-level encoding rather than geometric quantization or structural simplification [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Continuous numerical attributes (position, scale, rotation, opacity, SH coefficients) and discrete indices.
*   **Output:** ASCII strings representing the compressed data.

**Data Structures:**
The method operates on standard numerical types but maps them to a character set. No complex binary structures are used; the output is a sequence of ASCII characters.

**Steps:**

1.  **Integer Compression (Base 95):**
    *   Map integers in the range $[0, 95]$ to a single ASCII character.
    *   The character set is ASCII codes 32 to 126 inclusive.
    *   Encoding: $char = \text{chr}(32 + \text{value})$.
    *   Decoding: $\text{value} = \text{ord}(char) - 32$.

2.  **Floating-Point Compression (Base 94):**
    *   Split the floating-point number $f$ into an integer part $I$ and a fractional part represented by decimal places $d$.
    *   The integer part $I$ must be in the range $[0, 94]$.
    *   Map $I$ to an ASCII character using codes 32 to 125.
    *   Use ASCII character 126 (`~`) as a delimiter between the integer part and the decimal places.
    *   The decimal places $d$ are encoded as a string of digits.
    *   Encoding: $string = \text{chr}(32 + I) + \text{chr}(126) + \text{str}(d)$.
    *   Decoding:
        1.  Split the string at the delimiter `~` (ASCII 126).
        2.  Let the left part be $S_I$ and the right part be $S_d$.
        3.  Calculate $I = \text{ord}(S_I) - 32$.
        4.  Calculate $d = \text{int}(S_d)$.
        5.  Reconstruct value: $f = I \times 10^{-d}$.

3.  **Color Matrix Optimization:**
    *   The output color matrix items are restricted to the range $[0.0, 2.0]$ with only one decimal place.
    *   This results in 21 possible values ($0.0, 0.1, \dots, 2.0$).
    *   These values are compressed using the ASCII compression algorithm described above to significantly reduce data size [S1, unofficial].

**Parameters:**
*   **Integer Base:** 95 (ASCII 32-126).
*   **Floating-Point Integer Base:** 94 (ASCII 32-125).
*   **Delimiter:** ASCII 126 (`~`).
*   **Color Precision:** 1 decimal place.

**Pitfalls and Edge Cases:**
*   **Matrix Traversal Speed:** Compressing large color matrices into ASCII strings is computationally expensive due to the traversal time required [S1, unofficial]. Using internal functions like `torch.where` and `torch.index_select` can replace explicit `for` loops to improve speed, but this is often not fast enough to fully replace standard transmission methods [S1, unofficial].
*   **Line Breaks:** Using line break characters in ASCII strings adds extra operators during writing and decoding, which should be avoided [S1, unofficial].
*   **Range Constraints:** The floating-point compression assumes the integer component is within $[0, 94]$. Values outside this range require scaling or are not supported by this specific encoding scheme [S1, unofficial].

**Pseudocode:**

def compress_integer(value):
    """
    Compress an integer in range [0, 95] to a single ASCII character.
    """
    if not (0 <= value <= 95):
        raise ValueError("Integer value out of range [0, 95]")
    return chr(32 + value)

def decompress_integer(char):
    """
    Decompress a single ASCII character to an integer.
    """
    code = ord(char)
    if not (32 <= code <= 126):
        raise ValueError("Invalid ASCII character for integer compression")
    return code - 32

def compress_float(value):

    # "decimal places d" usually means the count of digits.

def decompress_float(s):
    """
    Decompress an ASCII string to a floating-point number.
    """
    delimiter = chr(126)
    if delimiter not in s:
        raise ValueError("Missing delimiter")
    
    parts = s.split(delimiter, 1)
    char_I = parts[0]
    str_d = parts[1]
    
    I = ord(char_I) - 32
    d = int(str_d)
    
    f = I * (10 ** -d)
    return f

## Operating characteristics
*   **Training Speed Improvement:** Gains approximately 6% or less improvement in training speed [S1, unofficial].
*   **Complexity:** The compression/decompression is $O(1)$ per number, but matrix traversal is $O(N)$ where $N$ is the number of elements.
*   **Strengths:** Reduces data size for transmission, particularly for color matrices with limited precision [S1, unofficial].
*   **Limitations:** Not fast enough to fully replace standard transmission for large color matrices due to traversal overhead [S1, unofficial]. Restricted to small integer components for floating-point numbers [S1, unofficial].
*   **When to Use:** When transmission speed is a bottleneck and data can be normalized to fit the constraints (integer part $\le 94$, color values $[0.0, 2.0]$ with 1 decimal place) [S1, unofficial].

## Background
This method was proposed in the context of improving 3D Gaussian Splatting training speed [S1, unofficial]. It is part of the "Anywhere" compression technique described in the paper "I3DGS: Improve 3D Gaussian Splatting from Multiple Dimensions" [S1, unofficial]. The authors identified data transmission as a critical bottleneck and explored ASCII-based encoding as a solution [S1, unofficial].
