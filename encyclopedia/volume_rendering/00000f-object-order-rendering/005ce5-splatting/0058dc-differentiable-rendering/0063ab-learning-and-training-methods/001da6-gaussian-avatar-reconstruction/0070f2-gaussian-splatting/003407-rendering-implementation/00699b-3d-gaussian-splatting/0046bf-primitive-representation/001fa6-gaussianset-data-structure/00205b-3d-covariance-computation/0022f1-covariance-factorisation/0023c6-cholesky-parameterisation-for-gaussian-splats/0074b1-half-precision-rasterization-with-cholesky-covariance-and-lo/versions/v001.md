# Half-Precision Rasterization with Cholesky Covariance and Local Coordinates

Also called: FP16 Rasterization with Cholesky and Local Coordinates

## Overview
This method optimizes the rasterization stage of 3D Gaussian Splatting by executing the entire pipeline in half-precision (fp16) to maximize memory bandwidth and load/store throughput [S1, unofficial]. It specifically addresses numerical instability in fp16 by replacing conic covariance representations with Cholesky factors and using local coordinates to prevent overflow [S1, unofficial]. It builds on [Cholesky Parameterisation for Gaussian Splats](3120-cholesky-parameterisation-for-gaussian-splats.md) to ensure positive-definiteness and avoids the arithmetic speedup benefits (negligible on commodity GPUs) in favor of memory efficiency [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of 3D Gaussians $\mathcal{S}$, each defined by a mean $\mathbf{t}$, a $3 \times 3$ covariance matrix $\Sigma_{3D}$ (parameterized via Cholesky), and spherical harmonic (SH) coefficients. Camera parameters (view/projection matrices).
*   **Output:** A rendered image with alpha compositing.

**Data Structures:**
*   **Gaussian Attributes:** Stored in fp16. The inverse covariance $\Sigma^{-1}$ is stored as its lower triangular Cholesky factor $L$ such that $\Sigma^{-1} = LL^\top$. For 2D screen-space, this requires 3 elements ($l_0, l_1, l_2$) [S1, unofficial].
*   **SH Compression:** Coefficients are packed into 32 bytes using YCoCg-R color-space conversion, square-root gamma quantization (6 bits luma, 4 bits chroma), and per-basis percentile scaling [S1, unofficial]. This reduces bandwidth from 192 bytes (fp32) to 32 bytes [S1, unofficial].
*   **Coordinates:** Positions are stored relative to the macro-tile center rather than absolute screen-space coordinates [S1, unofficial].

**Steps:**
1.  **Global Projection and SH Evaluation:** A single kernel processes each Gaussian end-to-end. Each thread handles one Gaussian:
    *   Transform $\mathbf{t}$ to camera space.
    *   Project to screen space to get 2D mean $\boldsymbol{\mu}$.
    *   Compute the 2D screen-space covariance $\Sigma_{2D}$ via Jacobian projection of $\Sigma_{3D}$ [S1, unofficial].
    *   Compute the Cholesky decomposition of the inverse covariance $\Sigma_{2D}^{-1} = LL^\top$ [S1, unofficial].
    *   Compute the view direction inline.
    *   Evaluate degree-3 spherical harmonics for color [S1, unofficial].
2.  **Tile Rasterization:**
    *   Gaussians are assigned to macro-tiles.
    *   Within a tile, positions are treated as relative to the macro-tile center to keep intermediate products within fp16 range [S1, unofficial].
    *   For each pixel $(x, y)$ in the tile, compute the offset $(dx, dy) = \mathbf{p} - \boldsymbol{\mu}$, where $\mathbf{p}$ is the pixel position relative to the tile center [S1, unofficial].
3.  **Mahalanobis Distance Calculation:**
    *   Compute $q$ using the Cholesky factors to avoid cancellation:
        $$ q = (l_0 \cdot dx + l_1 \cdot dy)^2 + (l_2 \cdot dy)^2 $$
    *   Here, $l_0, l_1, l_2$ are elements of $L$, and $(dx, dy)$ are the local offsets [S1, unofficial].
4.  **Alpha Compositing:**
    *   Use front-to-back blending. The scheduling buffer decouples variable-rate mask compaction from fixed-rate blending [S1, unofficial].
5.  **Decoding (SH):**
    *   Use a pure fp16 SIMD pipeline with byte-permute instructions for bitfield extraction, avoiding integer-to-float conversions [S1, unofficial].

**Pseudocode:**
```python
def rasterize_tile(tile_center, gaussians, camera):
    """
    Rasterize a single tile using half-precision arithmetic.
    tile_center: (x, y) macro-tile center in screen space.
    gaussians: List of Gaussian objects with attributes in fp16.
    camera: Camera parameters for projection.
    """
    # Shared memory / local storage for tile
    tile_width = 16  # Example tile size
    tile_height = 16
    image = zeros((tile_height, tile_width, 3), dtype=fp16)
    alpha = zeros((tile_height, tile_width), dtype=fp16)

    # Sort gaussians by depth within tile (simplified)
    tile_gaussians = filter_gaussians_in_tile(gaussians, tile_center)
    tile_gaussians.sort(key=lambda g: g.depth)

    for g in tile_gaussians:
        # 1. Project Gaussian
        mu_cam = camera.project(g.mean_3d)
        # 2. Compute 2D Covariance and Cholesky Factor
        # J is Jacobian of projection at mu_cam
        Sigma_2d = J @ g.Sigma_3d @ J.T
        # Inverse Cholesky: Sigma_inv = L @ L.T
        L = cholesky_lower(Sigma_2d.inv())
        
        # 3. Evaluate SH Color (compressed decode)
        color = decode_sh_color(g.sh_coeffs, g.view_dir)

        # 4. Rasterize Gaussian to Tile Pixels
        for dy in range(tile_height):
            for dx in range(tile_width):
                # Local coordinates relative to tile center
                pixel_abs = (tile_center.x + dx, tile_center.y + dy)
                local_offset = (pixel_abs.x - tile_center.x, pixel_abs.y - tile_center.y)
                
                # Offset from Gaussian center (also local)
                dx_rel = local_offset.x - (mu_cam.x - tile_center.x)
                dy_rel = local_offset.y - (mu_cam.y - tile_center.y)
                
                # Mahalanobis distance in fp16
                # q = (l0*dx + l1*dy)^2 + (l2*dy)^2
                term1 = fp16_mul(L.l0, fp16_add(fp16_mul(L.l0, dx_rel), fp16_mul(L.l1, dy_rel)))
                term2 = fp16_mul(L.l2, dy_rel)
                q = fp16_add(fp16_mul(term1, term1), fp16_mul(fp16_mul(term2, term2), term2)) # Note: term2 squared
                
                # Actually: q = (l0*dx + l1*dy)^2 + (l2*dy)^2
                inner = fp16_add(fp16_mul(L.l0, dx_rel), fp16_mul(L.l1, dy_rel))
                q = fp16_add(fp16_mul(inner, inner), fp16_mul(fp16_mul(L.l2, dy_rel), L.l2))
                
                alpha_val = fp16_exp(-0.5 * q) * g.opacity
                
                # Front-to-back blending
                # alpha_out = alpha_in + alpha_g * (1 - alpha_in)
                # color_out = (color_in * alpha_in + color_g * alpha_g * (1 - alpha_in)) / alpha_out
                # Simplified accumulation for single pass
                current_alpha = alpha[dy, dx]
                new_alpha = fp16_add(current_alpha, fp16_mul(alpha_val, fp16_sub(1.0, current_alpha)))
                
                if new_alpha > 0:
                    blended_color = fp16_add(
                        fp16_mul(color, alpha_val),
                        fp16_mul(fp16_sub(1.0, alpha_val), fp16_mul(image[dy, dx], current_alpha))
                    )
                    blended_color = fp16_div(blended_color, new_alpha)
                    
                    image[dy, dx] = blended_color
                    alpha[dy, dx] = new_alpha

    return image
```
*Note: The pseudocode above is a conceptual representation. The actual implementation uses a single kernel where each thread processes one Gaussian end-to-end, and a scheduling buffer decouples masking from blending [S1, unofficial].*

**Parameters:**
*   **SH Compression:** 32-byte packed representation [S1, unofficial].
*   **Tile Size:** Not given in the sources.
*   **Batch Size:** Drain batch $B_d = 64$ [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Cancellation Hazard:** Storing $\Sigma^{-1}$ as conic coefficients $(A, B, C)$ leads to catastrophic cancellation in fp16 due to mixed-sign cross terms. Using Cholesky factors eliminates this [S1, unofficial].
*   **Overflow Hazard:** Absolute screen-space coordinates can cause $l_k \cdot dx$ to overflow fp16 range. Using local coordinates relative to the macro-tile center prevents this [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Halves the footprint in DRAM and on-chip local storage compared to fp32, doubling effective load/store throughput [S1, unofficial].
*   **Performance:** On commodity GPUs, packed half and single precision share math throughput, so the benefit is memory-bound, not compute-bound [S1, unofficial].
*   **Quality:** HiGS reaches 67.0 dB PSNR without SH compression and 55.6 dB with 32-byte SH compression, with no observable image-quality loss compared to the gsplat baseline [S1, unofficial].
*   **Strengths:** Reduced memory bandwidth, increased resident Gaussian count per processing unit, exact compositing algorithm.
*   **Limitations:** Requires careful handling of fp16 precision hazards (addressed by Cholesky and local coords).

## Background
This method is part of the HiGS (Hierarchical Rendering Architecture for Real-Time 3D Gaussian Splatting) pipeline, targeting NVIDIA Blackwell GPUs [S1, unofficial]. It addresses the memory bandwidth bottleneck in real-time 3D Gaussian Splatting by optimizing the numerical representation and rasterization pipeline for half-precision hardware [S1, unofficial].
