# Stochastic Depth Rendering

Also called: Depth from Stochastic Solids, Depth-Rendering via Stochastic Theory, Median Depth via Stochastic Solids, Stochastic Solid Depth Rendering, Volumetric Depth Formulation

## Overview
Stochastic Depth Rendering is a method for computing depth maps from 3D Gaussian primitives by modeling them as continuous stochastic solids [S1, unofficial]. It solves the problem of noisy, inconsistent depth estimates in standard Gaussian Splatting by defining depth as the median transmittance crossing ($T=0.5$) rather than an opacity-weighted average [S1, unofficial]. Unlike alpha-averaged expected depth, which blurs silhouettes and suffers from view-dependent floater bias, this approach provides sharper boundary transitions and superior multi-view consistency [S1, unofficial]. It builds on [Continuous Stochastic Solids Volume Rendering](18428-continuous-stochastic-solids-volume-rendering.md) by applying the stochastic solid attenuation model specifically to depth estimation.

## How it works

### Inputs and Outputs
*   **Inputs:** A set of $N$ 3D Gaussian primitives $\{G_i\}$, each defined by position, covariance, opacity, and color; a camera ray $r$ defined by origin $o$ and direction $d$.
*   **Outputs:** A scalar median depth value $t_{med}$ for the ray.

### Data Structures
The method operates on the parameters of the Gaussian primitives projected onto the ray. For each Gaussian $i$, the following values are computed along the ray parameter $t$:
*   $t_i^*$: The location of the Gaussian's maximum density along the ray (the center of the Gaussian projected onto the ray axis).
*   $v_i(t)$: The continuous attenuation profile (vacancy) of the $i$-th Gaussian at distance $t$. This is derived from the Gaussian's covariance and position [S1, unofficial].

### Algorithm Steps

1.  **Compute Individual Transmittance:** For a given ray parameter $t$, calculate the transmittance $T_i(t)$ for each Gaussian $i$ using the stochastic solid attenuation function [S1, unofficial]:
    $$
    T_i(t) = \begin{cases} 
    v_i(t), & t \leq t_i^* \\
    \frac{v_i(t_i^*)^2}{v_i(t)}, & t > t_i^*
    \end{cases}
    $$
    Here, $v_i(t)$ represents the probability that the ray has not been "absorbed" or blocked by the Gaussian up to point $t$. The term $v_i(t_i^*)^2/v_i(t)$ for $t > t_i^*$ ensures the attenuation profile is symmetric and continuous at the peak $t_i^*$ [S1, unofficial].

2.  **Compute Overall Transmittance:** Assuming statistical independence of ray intersections with different Gaussians, compute the total transmittance $T(t)$ as the product of individual transmittances [S1, unofficial]:
    $$
    T(t) = \prod_{i=1}^{N} T_i(t)
    $$
    The product is taken over all Gaussians intersecting the ray.

3.  **Find Median Depth:** The median depth $t_{med}$ is defined as the inverse transmittance at 0.5 [S1, unofficial]:
    $$
    t_{med} = T^{-1}(0.5)
    $$
    Since $T(t)$ is monotonically decreasing along the ray (as transmittance decreases with distance), a binary search is used to find $t_{med}$ such that $T(t_{med}) = 0.5$.
    *   **Binary Search:** Initialize an interval $[t_{min}, t_{max}]$ covering the scene depth. Iteratively narrow the interval by evaluating $T(t_{mid})$ and updating bounds until convergence.
    *   **Gradient Computation:** During backpropagation, the iterative search is bypassed. The gradient of the median depth with respect to Gaussian parameters $\theta$ is computed using the implicit function theorem [S1, unofficial]:
        $$
        \frac{\partial t_{med}}{\partial \theta} = -\frac{\frac{\partial T(t_{med}; \theta)}{\partial \theta}}{\frac{\partial T(t; \theta)}{\partial t} \Big|_{t=t_{med}}}
        $$
        This allows gradients to be distributed to all contributing Gaussians along the ray [S1, unofficial].

                   - center: 3D position

                   - opacity: scalar
        ray_origin: 3D vector
        ray_direction: 3D vector (normalized)

        t_med: Scalar median depth
    """

    # v_i(t) is derived from the Gaussian's Mahalanobis distance along the ray.
    # Let sigma_i be the standard deviation of the Gaussian along the ray direction.
    # v_i(t) ~ exp(-0.5 * ((t - t_i*) / sigma_i)^2)
    
    ray_gaussians = []
    for g in gaussians:
        # Project Gaussian center onto ray
        t_center = dot(g.center - ray_origin, ray_direction)
        
        # Compute variance along ray direction
        # sigma_sq = ray_direction^T * cov * ray_direction
        sigma_sq = dot(ray_direction, dot(g.cov, ray_direction))
        sigma = sqrt(sigma_sq)
        
        # Store parameters for this Gaussian
        ray_gaussians.append({
            't_star': t_center,
            'sigma': sigma,
            'opacity': g.opacity # Note: Opacity scaling is implicit in v_i(t) definition in source
        })
    
    # Define the transmittance function T(t)
    def T(t):
        transmittance = 1.0
        for rg in ray_gaussians:
            t_star = rg['t_star']
            sigma = rg['sigma']
            
            # Compute v_i(t)
            # v_i(t) = exp(-0.5 * ((t - t_star) / sigma)^2)
            exponent = -0.5 * ((t - t_star) / sigma) ** 2
            v_t = exp(exponent)
            
            # Compute T_i(t) based on stochastic solid formula
            if t <= t_star:
                T_i = v_t
            else:
                # v_i(t_star) is the peak value
                v_star = exp(-0.5 * ((t_star - t_star) / sigma) ** 2) # = 1.0 if normalized, but generally exp(0)=1
                # Note: The source formula uses v_i(t_star)^2 / v_i(t).
                # If v_i(t) is a normalized Gaussian PDF/CDF component, 
                # the source implies a specific attenuation profile.
                # Assuming v_i(t) is the raw Gaussian value:
                T_i = (v_star ** 2) / v_t
            
            transmittance *= T_i
        return transmittance

    # Binary search for T(t) = 0.5
    t_min = 0.0

        if t_val > 0.5:
            t_min = t_mid
        else:
            t_max = t_mid
            
    return (t_min + t_max) / 2.0

### Parameters
*   **Binary Search Tolerance:** Not specified in the sources. Typical values for depth precision in graphics are $10^{-4}$ to $10^{-6}$ world units.

### Edge Cases and Pitfalls
*   **Jagged Artifacts:** Previous discrete transmittance updates cause the 0.5 crossing to snap to a single Gaussian, leading to jagged artifacts where neighboring pixels select different Gaussians [S1, unofficial]. The stochastic-solid formulation models attenuation continuously, yielding a smooth transmittance function and reducing staircasing [S1, unofficial].
*   **Precision:** The binary search relies on the monotonicity of transmittance. If the ray does not intersect any Gaussians, $T(t)=1$ everywhere, and no solution exists. Guard against empty intersections.
*   **Runtime:** The method is computationally more expensive than standard rasterization due to the binary search and the evaluation of the product of transmittances for all Gaussians along the ray [S1, unofficial].

## Operating characteristics

*   **Time Complexity:** $O(N \cdot K)$ per pixel, where $N$ is the number of Gaussians intersecting the ray and $K$ is the number of binary search iterations. This is higher than standard alpha-blending ($O(N)$) [S1, unofficial].
*   **Memory Complexity:** $O(N)$ to store Gaussian parameters and intermediate transmittance values during the search.
*   **Measured Performance:** In experiments on Tanks & Temples, the method was faster than GeoSVR (15 vs. 53 min) and PGSR (25 vs. 30 min) for the same number of iterations due to efficient multi-view regularization implementation [S1, unofficial]. However, it is slower than the fastest baselines due to the binary search cost [S1, unofficial].
*   **Strengths:**
    *   Produces cleaner, smoother, and more multi-view consistent depth maps than alpha-averaged expected depth [S1, unofficial].
    *   Sharper boundary transitions compared to alpha-weighted compositing [S1, unofficial].
    *   More robust to outliers (floaters) than expected depth [S1, unofficial].
    *   Outperforms PGSR and RaDe-GS in multi-view consistency and floater suppression [S1, unofficial].
*   **Limitations:**
    *   Higher runtime than standard rasterization methods [S1, unofficial].
    *   Requires careful initialization of the binary search interval.
*   **When to Use:** When geometric accuracy, multi-view consistency, and sharp depth boundaries are critical, such as in Gaussian Avatar Reconstruction or high-fidelity shape reconstruction.
*   **When Not to Use:** When real-time performance is the primary constraint and geometric consistency is less important than raw rendering speed.

## Background

*   **Origin:** Introduced in "Geometry-Grounded Gaussian Splatting" by Ramazzina et al. (2026) [S1, unofficial].
*   **History:** The method addresses limitations in prior Gaussian Splatting depth rendering, such as view-dependent depth planes [Yu et al. 2024c; Zhang et al. 2024] and opacity-weighted ray averaging [Chen et al. 2024], which suffer from blurred silhouettes and floater bias [S1, unofficial]. It builds on the concept of treating Gaussians as stochastic solids to align volume rendering with rasterization-based rendering [S1, unofficial].
*   **Usage:** Used in Gaussian Avatar Reconstruction and geometric regularization tasks to improve cross-view consistency and reduce reprojection error [S1, unofficial].
