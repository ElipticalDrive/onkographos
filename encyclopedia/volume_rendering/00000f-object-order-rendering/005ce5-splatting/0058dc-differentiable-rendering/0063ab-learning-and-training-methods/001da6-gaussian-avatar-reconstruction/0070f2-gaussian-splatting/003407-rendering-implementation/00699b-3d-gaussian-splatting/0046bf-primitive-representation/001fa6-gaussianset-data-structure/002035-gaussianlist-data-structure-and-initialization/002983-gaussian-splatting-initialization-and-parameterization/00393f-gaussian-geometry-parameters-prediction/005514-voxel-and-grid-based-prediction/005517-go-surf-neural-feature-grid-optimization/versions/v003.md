# GO-Surf Neural Feature Grid Optimization


## Overview
GO-Surf is a differentiable volume rendering method that optimizes a multi-resolution neural feature grid to reconstruct high-fidelity 3D surfaces from RGB-D observations [S1]. It solves the problem of fast, dense surface reconstruction by combining explicit grid-based feature storage with implicit SDF decoding, significantly reducing optimization time compared to fully implicit MLP-based methods like NeuralRGB-D [S1]. It sets itself apart by using a multi-resolution grid to store geometry and color features, allowing for faster convergence and higher detail capture, albeit at the cost of higher memory usage [S1].

## How it works

### Inputs and Outputs
**Inputs:**
*   A set of images with corresponding depth maps $D[u, v]$ and camera poses parameterized by translation vector $t \in \mathbb{R}^3$ and Lie Algebra $\nu \in \mathfrak{so}(3)$ [S1].
*   A 3D bounding box defining the scene volume [S1].

**Outputs:**
*   Optimized multi-resolution feature grids (geometry and color) [S1].
*   Optimized geometry and color decoder MLPs [S1].
*   Optimized camera poses [S1].
*   Rendered color and depth images [S1].

### Data Structures
**Multi-Resolution Feature Grids:** The method uses a set of 3D grids with different voxel sizes [S1]. Geometry grids have 4 levels with voxel sizes 3cm, 6cm, 24cm, and 96cm [S1]. Feature dimension per level $h_g$ is 4, yielding a final geometry feature vector dimension of 16 [S1]. Color grids have 4 levels with the same voxel sizes [S1]. Feature dimension per level $h_c$ is 6 [S1]. Trilinear interpolation is used to query features from these grids [S1].

**Decoders:** Both geometry and color decoders are lightweight MLPs with 2 hidden layers and 32 neurons each [S1]. The geometry decoder takes the concatenated 16D geometry feature vector as input and outputs the SDF value $\phi(x)$ [S1]. The color decoder takes the concatenated 6D color feature vector and viewing direction $d$ as input and outputs the RGB color $c$ [S1].

**Sampling:** Points $x_i$ along a ray are sampled using importance sampling [S1]. The process starts with $N_c = 96$ coarse samples [S1]. It iteratively adds 12 samples each time for 3 steps based on weights computed from previously sampled points [S1]. It concludes with $N_f = 36$ fine samples [S1].

### Parameters
*   Loss weights: $\lambda_{\text{rgb}} = 10.0$, $\lambda_{\text{depth}} = 1.0$, $\lambda_{\text{sdf}} = 10.0$, $\lambda_{\text{fs}} = 1.0$, $\lambda_{\text{eik}} = 1.0$, $\lambda_{\text{smooth}} = 1.0$ [S1].
*   Truncation threshold $t = 16\text{cm}$ [S1].
*   Free space loss exponential penalty $\alpha = 5$ [S1].
*   Smoothness perturbation length $\delta_s$ is between 1mm and 4mm [S1].
*   Sigmoid smoothness parameter $s$ is learnable [S1].
*   Optimizer is ADAM with learning rates $1 \times 10^{-3}$ for MLP decoders, $1 \times 10^{-2}$ for feature grids, and $5 \times 10^{-4}$ for camera poses [S1].
*   Batch size $M = 6144$ rays per batch [S1].
*   Optimization iterations: 10,000 [S1].

class GeometryDecoder(nn.Module):

        super().__init__()
        self.fc1 = nn.Linear(16, 32)
        self.fc2 = nn.Linear(32, 32)
        self.fc3 = nn.Linear(32, 1)
    def forward(self, x):
        x = F.relu(self.fc1(x))
        x = F.relu(self.fc2(x))
        return self.fc3(x).squeeze(-1)

class ColorDecoder(nn.Module):

        super().__init__()
        self.fc1 = nn.Linear(6, 32)
        self.fc2 = nn.Linear(32, 32)
        self.fc3 = nn.Linear(32, 3)
    def forward(self, x, d):
        x = F.relu(self.fc1(x))
        x = F.relu(self.fc2(x))
        return self.fc3(x)

class GOSurf:

        self.voxel_sizes = voxel_sizes
        self.num_cameras = num_cameras
        # [G] Grid dimensions calculated from scene_bounds and voxel_sizes
        self.geo_features = [nn.Parameter(torch.rand(10, 10, 10, 4)) for _ in range(4)]
        self.color_features = [nn.Parameter(torch.rand(10, 10, 10, 6)) for _ in range(4)]
        self.geo_decoder = GeometryDecoder()
        self.color_decoder = ColorDecoder()
        self.camera_poses_t = [nn.Parameter(torch.zeros(3)) for _ in range(num_cameras)]
        self.camera_poses_nu = [nn.Parameter(torch.zeros(3)) for _ in range(num_cameras)]
        self.s = nn.Parameter(torch.tensor(1.0))
        self.t = 0.16
        self.alpha = 5
        self.delta_s = 0.002
        self.Nc = 96
        self.Nf = 36
        self.M = 6144
        self.lambda_rgb = 10.0
        self.lambda_depth = 1.0
        self.lambda_sdf = 10.0

    def render(self, rays_o, rays_d):
        points, depths, weights = self.sample_points(rays_o, rays_d)
        sdf = self.query_sdf(points)
        colors = self.query_color(points, rays_d)
        sigma_s = 1.0 / (1.0 + torch.exp(-self.s * sdf))
        sigma_s_next = torch.roll(sigma_s, -1)
        sigma_s_next[-1] = 0.0
        alpha = torch.clamp((sigma_s - sigma_s_next) / sigma_s, min=0.0)

        l_rgb = torch.mean(torch.abs(gt_color - pred_color))
        valid_mask = gt_depth > 0
        l_depth = torch.mean(torch.abs(gt_depth[valid_mask] - pred_depth[valid_mask]))

        # b(x) = D[u, v] - d
        ray_depths_at_points = torch.sum(points * rays_d, dim=-1)
        b_values = gt_depth[pixel_indices] - ray_depths_at_points

        near_surface_mask = torch.abs(gt_depth[pixel_indices] - ray_depths_at_points) <= self.t
        l_sdf = torch.mean(torch.abs(self.query_sdf(points[near_surface_mask]) - b_values[near_surface_mask]))

        far_surface_mask = ~near_surface_mask
        term1 = torch.exp(-self.alpha * self.query_sdf(points[far_surface_mask])) - 1
        term2 = self.query_sdf(points[far_surface_mask]) - b_values[far_surface_mask]
        l_fs = torch.mean(torch.clamp(torch.stack([torch.zeros_like(term1), term1, term2], dim=-1), min=0).max(dim=-1).values)

        grad_phi = torch.autograd.grad(self.query_sdf(points[far_surface_mask]), points[far_surface_mask],
                                       grad_outputs=torch.ones_like(self.query_sdf(points[far_surface_mask])),
                                       create_graph=True)[0]
        l_eik = torch.mean((1.0 - torch.norm(grad_phi, dim=-1))**2)

        eps = torch.randn_like(points[near_surface_mask]) * self.delta_s
        points_perturbed = points[near_surface_mask] + eps
        grad_phi_perturbed = torch.autograd.grad(self.query_sdf(points_perturbed), points_perturbed,
                                                 grad_outputs=torch.ones_like(self.query_sdf(points_perturbed)),
                                                 create_graph=True)[0]
        grad_phi_near = torch.autograd.grad(self.query_sdf(points[near_surface_mask]), points[near_surface_mask],
                                            grad_outputs=torch.ones_like(self.query_sdf(points[near_surface_mask])),
                                            create_graph=True)[0]
        l_smooth = torch.mean((grad_phi_near - grad_phi_perturbed)**2)

        loss = (self.lambda_rgb * l_rgb + self.lambda_depth * l_depth +
                self.lambda_sdf * l_sdf + self.lambda_fs * l_fs +
                self.lambda_eik * l_eik + self.lambda_smooth * l_smooth)
        return loss

### Edge Cases and Pitfalls
*   **Second-Order Derivatives:** Computing the Eikonal and smoothness losses requires the Hessian of the SDF. Standard PyTorch autograd does not support double back-propagation through the standard grid sampler for trilinear interpolation. A custom CUDA kernel must be implemented for the second backward pass [S1].
*   **Initialization:** Poor initialization can lead to local minima. Initializing the SDF to a sphere centered at the volume origin with radius half the smallest dimension helps convergence [S1].
*   **Depth Noise:** RGB-D sensors often have noisy depth or missing values (e.g., glass). The SDF regularization and RGB loss help mitigate these artifacts [S1].

## Operating characteristics

**Time Complexity:**
*   Optimization takes 15 to 45 minutes depending on scene size [S1].
*   Significantly faster than NeuralRGB-D (15-25 hours) [S1].

**Memory Complexity:**
*   Model size scales with scene resolution [S1].
*   Example: 268 MB for 8.8x9.1x3.4m scene (66.5M params) [S1].
*   41 MB for synthetic scene (10.1M params) [S1].
*   Larger memory footprint than implicit MLP methods [S1].

**Strengths:**
*   Fast optimization [S1].
*   High-fidelity surface reconstruction [S1].
*   Good hole-filling ability [S1].
*   Captures thin structures [S1].

**Limitations:**
*   High memory usage [S1].
*   Requires custom CUDA kernel for training [S1].

**When to Use:**
*   When fast reconstruction is required [S1].
*   When high-fidelity surface is needed [S1].
*   When memory is not a constraint [S1].

**When Not to Use:**
*   When memory is very limited [S1].
*   When implicit representation is preferred for scalability [S1].

## Background

GO-Surf was introduced in the paper "GO-Surf: Neural Feature Grid Optimization for Fast, High-Fidelity RGB-D Surface Reconstruction" [S1]. It builds on the idea of using neural feature grids for scene representation, combining the speed of explicit grids with the flexibility of implicit decoding [S1]. It is an improvement over NeuralRGB-D, which uses a single MLP for the entire scene, resulting in slower optimization [S1]. GO-Surf uses a multi-resolution grid to store features, allowing for faster convergence and better detail capture [S1].
