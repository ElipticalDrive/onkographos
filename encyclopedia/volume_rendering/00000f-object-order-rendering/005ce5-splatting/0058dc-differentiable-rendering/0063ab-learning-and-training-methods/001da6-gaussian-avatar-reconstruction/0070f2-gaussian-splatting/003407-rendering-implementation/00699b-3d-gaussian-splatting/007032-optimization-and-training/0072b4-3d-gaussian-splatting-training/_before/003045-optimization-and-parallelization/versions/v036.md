# Optimization and Parallelization

Also called: Distributed Training, Per-Splat Backpropagation, Mask Gradient Computation

## Overview
This family encompasses methods that accelerate the training of 3D Gaussian Splatting (3DGS) and enable its application to large-scale scenes by optimizing the computational efficiency of the differentiable rasterization pipeline. It addresses the bottlenecks of memory bandwidth, atomic contention in gradient accumulation, and single-GPU memory limits. It is distinguished from standard optimization by restructuring the data flow: [MaskGaussian Gradient Computation](4254-maskgaussian-gradient-computation.md) explicitly derives gradients for probabilistic masks, [Parallelization for Backpropagation](5989-parallelization-for-backpropagation.md) replaces per-pixel atomic updates with per-splat accumulation, and [Grendel-GS](7349-grendel-gs.md) distributes the Gaussian primitive list across multiple GPUs.

## Shared principles
The methods in this family share the following foundational mechanisms:

1.  **Differentiable Rasterization Core**: All methods rely on the differentiable alpha-blending rasterizer. The forward pass computes pixel color $\mathbf{c}(\mathbf{x})$ via depth-sorted alpha blending, and the backward pass computes gradients $\frac{\partial \mathcal{L}}{\partial \theta}$ with respect to Gaussian parameters $\theta$ [6233-optimization-and-parallelization].
2.  **Gradient Accumulation**: Gradients are accumulated over multiple training steps or views before an optimizer update. In distributed settings, gradients or intermediate rendering states are synchronized across devices [6233-optimization-and-parallelization].
3.  **Adaptive Representation**: Many optimization variants modify the Gaussian representation or its distribution to improve efficiency or fidelity, requiring corresponding adjustments to the gradient computation or data flow [6233-optimization-and-parallelization].
4.  **Hardware Acceleration**: Methods leverage GPU parallelism, often using CUDA kernels, Tensor Cores (via GEMM reformulation), or half-precision arithmetic to accelerate the rasterization and gradient computation [6233-optimization-and-parallelization].

## Subtopics

### [MaskGaussian Gradient Computation](4254-maskgaussian-gradient-computation.md)
A method for computing the gradient of the loss with respect to probabilistic masks $\mathcal{M}_i$ applied to 3D Gaussians. It solves the problem of backpropagating gradients through a masked alpha-blending process where the mask modulates the opacity of each Gaussian. It is distinguished from standard 3DGS backpropagation by explicitly accounting for the gradient contribution of the mask on both the foreground Gaussian color accumulation and the background transmittance path.

### [Training Pipeline](5325-training-pipeline.md)
The iterative optimization loop for 3D Gaussian Splatting that initializes a set of 3D Gaussians and optimizes their parameters (position, covariance, opacity, color, and spherical harmonics coefficients) via gradient descent. It solves the inverse problem of reconstructing a scene from multi-view images by projecting Gaussians onto 2D slice views, computing a rendering loss, and performing backpropagation. It distinguishes itself from standard optimization by integrating dynamic Gaussian management (pruning, densification, cloning) within the training loop to adapt the representation density to the scene complexity.

### [Parallelization for Backpropagation](5989-parallelization-for-backpropagation.md)
A training optimization that replaces the standard per-pixel backward pass with a per-splat (per-Gaussian) approach to accelerate gradient computation. While the standard method computes gradients by iterating over pixels and accumulating contributions from visible Gaussians using atomic operations, this method iterates over Gaussians and updates the gradients of the pixels they cover. This shift addresses the performance bottleneck of atomic contention in the per-pixel approach, where splats contributing to arbitrary numbers of pixels require frequent global memory synchronization. It yields a 4–5× reduction in training time while maintaining numerical equivalence to the original backpropagation.

### [Grendel-GS](7349-grendel-gs.md)
A distributed optimization framework for 3D Gaussian Splatting (3DGS) that partitions the Gaussian primitive list across multiple GPUs to overcome single-device memory limits. Unlike [TideGS](7350-tidegs.md), which streams data from disk on a single machine, Grendel-GS distributes the parameter table across a GPU cluster, enabling training on scenes with billions of primitives by leveraging inter-GPU communication. It builds on the differentiable rasterization core defined in [Optimization and Training Efficiency](9264-optimization-and-training-efficiency.md) but modifies the data flow to support multi-GPU parallelism.

### [3D Gaussian Splatting Implementation Details](9128-3d-gaussian-splatting-implementation-details.md)
Details the specific hyperparameters, data structures, and optimization strategies required to implement the 3D Gaussian Splatting (3DGS) training pipeline, focusing on the densification, pruning, and gradient computation mechanics. It addresses the problem of balancing reconstruction fidelity with computational efficiency by defining the exact thresholds for adaptive density control and the numerical stability measures for half-precision training. It sets itself apart from general overviews by providing the concrete implementation values (e.g., learning rates, opacity thresholds, iteration intervals) and low-level kernel behaviors (e.g., half-precision fetches, gradient flags) necessary for a functional codebase.

## Background
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 . The initial implementation relied on a per-pixel backward pass with atomic operations for gradient accumulation, which became a bottleneck for high-resolution scenes. Subsequent works such as [Parallelization for Backpropagation](5989-parallelization-for-backpropagation.md) and [Grendel-GS](7349-grendel-gs.md) emerged to address scalability and efficiency, leveraging hardware-specific optimizations and distributed computing architectures. The integration of adaptive density control, as detailed in [3D Gaussian Splatting Implementation Details](9128-3d-gaussian-splatting-implementation-details.md), has become a standard component of the training pipeline to maintain representation quality during optimization.
