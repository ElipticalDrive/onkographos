# 3D Gaussian Splatting Training

Also called: 3DGS Learning, G Splats

## Overview
3D Gaussian Splatting Training is the iterative optimization process that adjusts the parameters of a set of 3D Gaussian primitives to minimize the difference between rendered images and ground truth views [S2][S6, unofficial]. It solves the problem of reconstructing a photorealistic 3D scene from a sparse set of 2D images by optimizing position, rotation, scale, opacity, and appearance (spherical harmonics) [S5, S6, unofficial]. Unlike implicit neural radiance fields (NeRFs) which require per-pixel neural network evaluation, 3DGS training optimizes explicit geometric primitives, offering significantly faster training and real-time rendering speeds while achieving comparable image quality [S2][S5, unofficial]. It sets itself apart from its siblings by using a differentiable rasterization pipeline with adaptive density control (splitting, cloning, pruning) rather than continuous field sampling or probabilistic MCMC moves [S2].

## How it works
**Inputs and Outputs**
*   **Inputs:** A set of $N$ input images (or video frames) with known camera poses (rotation $R_{cw}$, translation $t_{cw}$, intrinsic matrix $K$) [S6, unofficial]. Initial 3D Gaussian parameters are derived from Structure from Motion (SfM) point clouds (e.g., COLMAP) [S2][S6, unofficial].
*   **Outputs:** A set of optimized 3D Gaussians defined by position $\mathbf{p}_i$, rotation $q_i$, scale $\mathbf{s}_i$, opacity $\alpha_i$, and spherical harmonic coefficients $h_i$, stored typically in a PLY file [S4, S6, unofficial].

**Data Structures**
Each Gaussian $i$ maintains:
*   $\mathbf{p}_i \in \mathbb{R}^3$: Center position.
*   $q_i \in \mathbb{R}^4$: Unit quaternion for rotation.
*   $\mathbf{s}_i \in \mathbb{R}^3$: Scale (standard deviation) for each axis.
*   $\alpha_i \in [0, 1]$: Opacity.
*   $h_i$: Spherical Harmonic coefficients for view-dependent color.
*   $\mathbf{c}_i$: View-independent color (or derived from $h_i$) [S6, unofficial].

**Initialization**
1.  **Position:** Initialize $\mathbf{p}_i$ using sparse 3D points from SfM (e.g., COLMAP) [S2][S6, unofficial].
2.  **Rotation:** Initialize $q_i$ as a unit quaternion (e.g., identity or random) [S2].
3.  **Scale:** Initialize $\mathbf{s}_i$ with values between 0 and 1 [S2].
4.  **Opacity:** Initialize $\alpha_i$ as a constant (often low, e.g., 0.1 or derived from SfM confidence) [S6, unofficial].
5.  **Color:** Initialize $h_i$ or $\mathbf{c}_i$ from the average color of the input images at the corresponding 3D point [S6, unofficial].

**Optimization Loop**
The training minimizes a loss function $\mathcal{L}$ between the rendered image $\gamma$ and ground truth $\gamma_{gt}$ using the Adam optimizer [S2][S6, unofficial]. The loss is a combination of L1 loss and D-SSIM loss:
$$
\mathcal{L} = (1 - \lambda) \mathcal{L}_1 + \lambda \mathcal{L}_{D-SSIM}
$$
where $\lambda$ is typically 0.2 [S6, S4, unofficial].

**Rendering Step (Forward Pass)**
For a selected camera view:
1.  **Projection:** Project 3D Gaussians to 2D screen space. The covariance matrix $\Sigma$ is transformed using the Jacobian of the affine approximation of the projection [S6, unofficial].
2.  **Sorting:** Sort Gaussians by depth for each pixel to handle occlusion [S2].
3.  **Rasterization:** Compute pixel color $\gamma_j$ via alpha blending:
    $$
    \gamma_j = \sum_{i \in N} \alpha'_{ij} c_i \tau_{ij}, \quad \tau_{ij} = \prod_{k=1}^{i-1} (1 - \alpha'_{kj})
    $$
    where $\alpha'_{ij}$ is the effective opacity, $c_i$ is the color, and $\tau_{ij}$ is the transmittance [S6, unofficial].

**Backpropagation (Gradient Computation)**
Gradients are computed using the chain rule for each parameter [S6, unofficial]:
*   **Rotation ($q_i$):**
    $$
    \frac{\partial \mathcal{L}}{\partial q_i} = \sum_j \frac{\partial \mathcal{L}}{\partial \gamma_j} \frac{\partial \gamma_j}{\partial \sigma'_i} \frac{\partial \sigma'_i}{\partial \sigma_i} \frac{\partial \sigma_i}{\partial q_i}
    $$
*   **Scale ($s_i$):**
    $$
    \frac{\partial \mathcal{L}}{\partial s_i} = \sum_j \frac{\partial \mathcal{L}}{\partial \gamma_j} \frac{\partial \gamma_j}{\partial \sigma'_i} \frac{\partial \sigma'_i}{\partial \sigma_i} \frac{\partial \sigma_i}{\partial s_i}
    $$
*   **Spherical Harmonics ($h_i$):**
    $$
    \frac{\partial \mathcal{L}}{\partial h_i} = \sum_j \frac{\partial \mathcal{L}}{\partial \gamma_j} \frac{\partial \gamma_j}{\partial c_i} \frac{\partial c_i}{\partial h_i}
    $$
*   **Opacity ($\alpha_i$):**
    $$
    \frac{\partial \mathcal{L}}{\partial \alpha_i} = \sum_j \frac{\partial \mathcal{L}}{\partial \gamma_j} \frac{\partial \gamma_j}{\partial \alpha'_{ij}} \frac{\partial \alpha'_{ij}}{\partial \alpha_i}
    $$
*   **Position ($\mathbf{p}_{w,i}$):**
    $$
    \begin{aligned}
    \frac{\partial \mathcal{L}}{\partial \mathbf{p}_{w,i}} &= \sum_j \frac{\partial \mathcal{L}}{\partial \gamma_j} \frac{\partial \gamma_j}{\partial \alpha'_{ij}} \frac{\partial \alpha'_{ij}}{\partial u_i} \frac{\partial u_i}{\partial \mathbf{p}_{c,i}} \frac{\partial \mathbf{p}_{c,i}}{\partial \mathbf{p}_{w,i}} \\
    &+ \sum_j \frac{\partial \mathcal{L}}{\partial \gamma_j} \frac{\partial \gamma_j}{\partial c_i} \frac{\partial c_i}{\partial \mathbf{p}_{w,i}} \\
    &+ \sum_j \frac{\partial \mathcal{L}}{\partial \gamma_j} \frac{\partial \gamma_j}{\partial \alpha'_{ij}} \frac{\partial \alpha'_{ij}}{\partial \sigma'_i} \frac{\partial \sigma'_i}{\partial \mathbf{p}_{c,i}} \frac{\partial \mathbf{p}_{c,i}}{\partial \mathbf{p}_{w,i}}
    \end{aligned}
    $$
    where $\mathbf{p}_c$ is the camera-space position, $u_i$ is the screen-space center, and $\sigma'$ is the 2D covariance [S6, unofficial].

**Adaptive Density Control**
Periodically (e.g., every 100-500 steps), the number of Gaussians is adjusted based on gradients and opacity [S2]:
1.  **Pruning:** If $\alpha_i < \epsilon$ (e.g., 0.005) or the Gaussian is too large, remove it [S2].
2.  **Densification:** If the positional gradient magnitude $\|\nabla_{\mathbf{p}} \mathcal{L}\| > \tau_p$ (e.g., 0.0002):
    *   **Split:** If the scale $\|\mathbf{s}_i\| > \tau_s$ (e.g., 0.01), split the Gaussian into two smaller ones [S2].
    *   **Clone:** If the scale is small, clone the Gaussian to increase density [S2].

**Pseudocode**
```python
def train_3dgs(input_images, camera_poses, num_iterations=30000):
    # 1. Initialization
    gaussians = initialize_from_sfm(input_images, camera_poses)
    optimizer = Adam(gaussians.parameters(), lr=1e-4)
    
    # 2. Training Loop
    for step in range(1, num_iterations + 1):
        # Camera Selection
        cam = select_camera(camera_poses, step)
        gt_image = get_ground_truth(input_images, cam, step)
        
        # Forward Pass: Rendering
        rendered_image = rasterize(gaussians, cam)
        
        # Loss Computation
        loss = compute_loss(rendered_image, gt_image)
        
        # Backward Pass
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        
        # Adaptive Density Control (every refine_every steps)
        if step % refine_every == 0:
            update_gaussian_density(gaussians, step)
            
        # Scheduler Updates
        update_learning_rate(optimizer, step)
        
    return gaussians

def update_gaussian_density(gaussians, step):
    for g in gaussians:
        # Pruning
        if g.opacity < opacity_threshold or g.scale > scale_threshold:
            remove_gaussian(g)
        # Densification
        elif gradient_norm(g.position) > gradient_threshold:
            if g.scale > split_scale_threshold:
                split_gaussian(g)
            else:
                clone_gaussian(g)
```

### HUGS
HUGS (Human Gaussian Splatting) creates a coarse-to-fine deformation module using linear blend skinning and local learning-based refinement to animate virtual human avatars [S1]. It utilizes a tri-plane representation to factorize the canonical space, allowing reconstruction from monocular video (50-100 frames) within 30 minutes [S1]. It achieves state-of-the-art human neural rendering performance at 20 FPS [S1].

### Wolf et al. Stereo Method
This method trains a 3DGS to render stereo-calibrated novel views, then applies stereo depth estimation on the rendered views [S1]. The estimated dense depth maps are fused using a Truncated Signed Distance Function (TSDF) to form a triangular mesh [S1].

### Pseudo Ground Truth Acquisition for Gaussians
A labeling pipeline that generates Gaussian-specific pseudo ground truth labels from original point cloud labels, accounting for the densification and pruning processes of 3D-GS optimization [S8, unofficial].

### Cross-View Pruning Mechanism
A mechanism comprising a Cross-View Consistency Loss and adaptive pruning to reduce Gaussian redundancy and ensure geometric validity [S9]. It selects adjacent view pairs with SSIM > 0.6, computes a Cross-View Consistent Loss ($L_{CVC}$) to penalize residual discrepancies, and prunes Gaussians based on depth consistency conditions ($d^i_p < 0.01 \land d^j_p < 0.5 \lor d^i_p > 3\sigma$) [S9].

### Structure-View Co-learning
A module combining structural and view-dependent gradients for robust joint optimization of Gaussian positions and appearance [S9]. The loss is defined as $\mathcal{L} = \lambda (\lambda_V \mathcal{L}_V + \lambda_S \mathcal{L}_S)$, where $\mathcal{L}_V$ is view gradient loss and $\mathcal{L}_S$ is structure gradient loss [S9].

### Single-view Mini-batch Strategy
A training data sampling strategy where data is organized per viewpoint, and a mini-batch consists of data from only a single viewpoint [S10, unofficial]. For each viewpoint $i$, the dataset $D_i$ is collected, and a mini-batch $B_{3DGS}$ is sampled from $D = \{D_i\}$ with count=1 [S10, unofficial].

## Operating characteristics
*   **Time Complexity:** Training time scales with the number of iterations (typically 30,000) and the number of Gaussians [S3, S4, unofficial]. It is significantly faster than NeRF training [S2][S5, unofficial].
*   **Memory Complexity:** Memory usage scales with the number of Gaussians. The default maximum is 5,000,000 Gaussians, but this can be unlimited [S3, unofficial].
*   **Performance:** On the Replica dataset, SGS-SLAM achieves PSNR 34.15, SSIM 0.97, and LPIPS 0.096 [S1].
*   **Hardware:** GPU acceleration (CUDA/Metal) is recommended; CPU execution is ~100x slower [S3, S4, unofficial].
*   **Strengths:** Real-time rendering, fast training, high fidelity [S2][S5, unofficial].
*   **Limitations:** Can produce "floaters" in empty space; sensitive to initialization; large memory footprint for high-resolution scenes [S2].

## Background
3D Gaussian Splatting was introduced by Kerbl et al. [9] (cited in [S2][S6, unofficial]). It initializes positions using sparse point clouds from SfM tools like COLMAP [S2][S6, unofficial]. The method has been widely adopted for real-time rendering and 3D reconstruction, with various extensions for SLAM, dynamic scenes, and compression [S1].
