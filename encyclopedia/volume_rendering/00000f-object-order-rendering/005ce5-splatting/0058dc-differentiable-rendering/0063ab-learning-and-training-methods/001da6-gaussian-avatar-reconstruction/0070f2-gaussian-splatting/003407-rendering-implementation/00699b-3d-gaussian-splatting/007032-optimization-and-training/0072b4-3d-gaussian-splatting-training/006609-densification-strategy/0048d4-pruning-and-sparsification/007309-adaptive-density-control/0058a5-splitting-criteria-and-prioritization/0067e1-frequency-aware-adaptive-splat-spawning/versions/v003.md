# Frequency-Aware Adaptive Splat Spawning

Also called: Adaptive Frequency-Aware Cell Division, adaptive strategy, frequency-aware spawning

## Overview
Frequency-Aware Adaptive Splat Spawning is a densification strategy for 3D Gaussian Splatting that generates new splats in regions of high-frequency image content or low opacity ("holes") by scoring pixels based on frequency gaps and alpha gaps, then sampling new splats from the nearest existing cloud points [S1, unofficial]. It differs from sibling methods like [Multi-View Density Control Criterion](5663-multi-view-density-control-criterion.md) by relying on single-view frequency analysis and alpha transparency rather than multi-view consistency or complexity metrics, and from [Complexity-Aware Adaptive Density Control](16126-complexity-aware-adaptive-density-control.md) by using explicit frequency domain gaps rather than structural complexity scores.

## How it works
**Inputs and Outputs:**
- **Inputs:** Rendered color image ($C_{pred}$), rendered alpha map ($\alpha_{pred}$), current Gaussian splat attributes (means, scales, rotations, colors), camera extrinsics ($R, t$) and intrinsics ($K$), current training step ($step$), target splat count ($target\_splats$).
- **Outputs:** Updated set of Gaussian splats with new splats added via splitting existing ones.

**Data Structures:**
- **Splat Attributes:** Each splat $G_i$ has:
  - `means`: 3D position $(x, y, z)$ [G: float32, shape (3,)].
  - `scales`: Log-scale vector $(\log s_x, \log s_y, \log s_z)$ [G: float32, shape (3,)].
  - `quats`: Rotation quaternion $(w, x, y, z)$ [G: float32, shape (4,)].
  - `colors`: RGB color [G: float32, shape (3,)].
- **Camera Parameters:**
  - $K$: $3 \times 3$ intrinsic matrix $\begin{bmatrix} f_x & 0 & c_x \\ 0 & f_y & c_y \\ 0 & 0 & 1 \end{bmatrix}$.
  - $R$: $3 \times 3$ rotation matrix from world to camera.
  - $t$: $3 \times 1$ translation vector from world to camera.

**Numbered Steps:**

1.  **Frequency Gap Computation:** Compute the frequency gap map $F_{gap}$ from the predicted color image $C_{pred}$ and the ground truth or reference pixels $P$. The exact implementation of `_compute_freq_gap` is not detailed in the source, but it measures high-frequency discrepancies [S1, unofficial].
2.  **Alpha Gap Computation:** Compute the alpha gap map $A_{gap}$ using the ReLU function on the difference between 0.5 and the predicted alpha:
    $$ A_{gap} = \text{ReLU}(0.5 - \alpha_{pred}) $$
    This highlights regions where opacity is below 0.5 [S1, unofficial].
3.  **Score Calculation:** For each valid splat projected to pixel coordinates $(u, v)$, initialize a score $S(G_i) = 0$. If the splat projects to a valid pixel within bounds and has depth $z > 0.1$, add the frequency gap at that pixel to the score. Then, boost the score by adding $2.0 \times A_{gap}(u, v)$:
    $$ S(G_i) = F_{gap}(u, v) + 2.0 \cdot A_{gap}(u, v) $$
    [S1, unofficial].
4.  **Candidate Selection:** Flatten the scores of all valid splats. If the sum of scores is near zero, terminate. Otherwise, compute probabilities $p_i$ for each splat:
    $$ p_i = \frac{S(G_i)}{\sum_j S(G_j)} $$
    Determine the number of splats to spawn $N_{spawn}$:
    $$ N_{spawn} = \min(N_{spawn\_budget}, \sum_{i} \mathbb{I}(S(G_i) > 0), N_{cloud}) $$
    where $N_{cloud}$ is the number of valid cloud points [S1, unofficial]. Sample $N_{spawn}$ pixel indices using multinomial distribution without replacement:
    $$ \text{pixel\_idx} \sim \text{Multinomial}(p, N_{spawn}, \text{replacement}=False) $$
    [S1, unofficial].
5.  **Pixel to World Ray Conversion:** Convert sampled pixel indices to coordinates $(p_x, p_y)$:
    $$ p_y = \left\lfloor \frac{\text{pixel\_idx}}{W} \right\rfloor, \quad p_x = \text{pixel\_idx} \pmod W $$
    Unproject to camera-space ray directions $d_{cam}$:
    $$ d_{cam} = \begin{bmatrix} \frac{p_x - c_x}{f_x} \\ \frac{p_y - c_y}{f_y} \\ 1 \end{bmatrix} $$
    Compute camera position in world space $C_{world} = -R^T t$. Transform ray directions to world space $d_{world}$ and normalize:
    $$ d_{world} = \text{normalize}(R^T d_{cam}) $$
    [S1, unofficial].
6.  **Nearest Neighbor Search:** Project existing cloud points to camera space $P_{cam} = P_{world} R^T + t$. Filter points with depth $z > 0.1$. Project valid points to 2D UV coordinates:
    $$ u = \frac{x_{cam}}{z_{cam}} f_x + c_x, \quad v = \frac{y_{cam}}{z_{cam}} f_y + c_y $$
    Build a 2D KD-tree from valid $(u, v)$ points. For each spawn pixel $(p_x, p_y)$, find the nearest neighbor in the 2D projection space to identify the parent splat index [S1, unofficial].
7.  **Splitting Execution:** If $step > 100$, $step \% 50 == 0$, current splat count $< target\_splats$, and $step < 0.85 \times iterations$, proceed to split [S1, unofficial].
    - Calculate number of splats to split $N_{split} = \min(\lfloor N_{current}/10 \rfloor, target\_splats - N_{current}, 5000)$.
    - Select top $N_{split}$ splats by score $S(G_i)$ using `torch.topk`.
    - For each selected parent splat:
        - Find the longest axis $a_{long} = \arg\max_k (\text{scales}_k)$.
        - Compute world-space direction $d_{axis}$ of the longest axis from the rotation matrix $R_{splat}$:
          $$ d_{axis} = R_{splat}[:, a_{long}] $$
        - Compute offset distance $d_{off}$:
          $$ d_{off} = \exp(\text{scales}_{a_{long}}) \cdot 0.5 $$
        - Compute offset vector $v_{off} = d_{axis} \cdot d_{off}$.
        - Create two children:
          - Parent mean: $m_{parent} = m_{orig} + v_{off}$
          - Child mean: $m_{child} = m_{orig} - v_{off}$
        - Halve the scale of the longest axis in log space by subtracting $\ln(2) \approx 0.693$:
          $$ \text{scales}_{new, a_{long}} = \text{scales}_{orig, a_{long}} - 0.693 $$
          Apply this new scale to both children.
        - Clone other attributes (quats, colors) from the parent.
        - Concatenate parent and child data to update the splat list [S1, unofficial].

**Parameters:**
- $target\_splats$: Target number of splats. If $\le 0$, defaults to 500,000 [S1, unofficial].
- Splitting frequency: Every 50 steps during the first 85% of training [S1, unofficial].
- Minimum step: 100 [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Zero Score Sum:** If the sum of scores is near zero, no splats are spawned [S1, unofficial].
- **Depth Filtering:** Cloud points with depth $\le 0.1$ are filtered out to avoid noise or camera-internal artifacts [S1, unofficial].
- **Precision:** Log-space scale manipulation requires careful handling of negative values if scales are not strictly positive in log space, though standard 3DGS assumes positive scales [G].

## Operating characteristics
- **Time Complexity:** Dominated by the KD-tree construction and nearest neighbor search, which is $O(N \log N)$ for $N$ cloud points, and the sorting/topk operation $O(N \log K)$ [S1, unofficial].
- **Memory Complexity:** Requires storing the 2D KD-tree of projected cloud points, adding $O(N)$ memory overhead [S1, unofficial].
- **Strengths:** Targets high-frequency details and transparency holes directly, potentially leading to faster convergence in complex regions [S1, unofficial].
- **Limitations:** Relies on single-view frequency analysis, which may be less robust than multi-view methods in occluded areas. The fixed frequency of splitting (every 50 steps) may not adapt dynamically to training progress as effectively as step-dependent thresholds [S1, unofficial].

## Background
Frequency-Aware Adaptive Splat Spawning is an adaptation of densification strategies for 3D Gaussian Splatting, specifically implemented in the `dust3r-3dgs` repository [S1, unofficial]. It builds on the principles of adaptive density control by incorporating frequency domain information to guide splat placement, aiming to improve reconstruction quality in high-frequency regions [S1, unofficial].
