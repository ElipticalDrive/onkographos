# Feed-forward Generalizable Reconstruction

Also called: Feed-forward 3D Gaussian Splatting, FF3DGS, Generalizable 3DGS

## Overview
Feed-forward generalizable reconstruction maps input images directly to a 3D Gaussian Splatting (3DGS) representation without per-scene optimization, enabling instant novel view synthesis on unseen scenes [Parent]. Unlike traditional 3DGS which requires iterative gradient descent for each new scene, these methods use a learned neural network to predict Gaussian parameters ($\mu, \Sigma, \alpha, c$) in a single forward pass [Parent]. This family is distinguished from sibling methods like [Triplane-LRM](16746-feed-forward-generalizable-reconstruction.md) by its explicit prediction of explicit Gaussian primitives rather than latent field representations, and from optimization-based methods by its inference speed and lack of per-scene tuning [Parent].

## Shared principles
All methods in this family share the core objective of mapping input image features to a set of 3D Gaussian parameters $\mathcal{G} = \{\mu, \Sigma, \alpha, c\}$ without per-scene gradient descent [Parent].

1.  **Input Representation:** Inputs are typically one or more RGB images $I \in \mathbb{R}^{H \times W \times 3}$. Some methods require known camera poses $P$, while others (e.g., [Splatt3R](16423-splatt3r.md), [ZeroGS](16425-zerogs.md)) predict poses or operate on uncalibrated inputs [Parent].
2.  **Feature Encoding:** A shared encoder (e.g., Vision Transformer, CNN) extracts multi-scale features from the input images. Cross-attention or cost volumes are often used to aggregate multi-view information [Parent].
3.  **Primitive Prediction:** A decoder head predicts Gaussian attributes. These attributes are usually:
    *   **Mean ($\mu$):** 3D position.
    *   **Covariance ($\Sigma$):** Defined by scale $s$ and rotation $r$ (quaternion or 6D).
    *   **Opacity ($\alpha$):** Scalar.
    *   **Color ($c$):** Spherical Harmonics (SH) coefficients or constant RGB [Parent].
4.  **Differentiable Rendering:** The predicted Gaussians are rendered into target views using differentiable rasterization to compute reconstruction losses (e.g., L1, SSIM, LPIPS) for training the network [Parent].
5.  **Generalization:** The network is trained on a large dataset of scenes to learn priors about geometry and appearance, allowing inference on unseen scenes [Parent].

## Subtopics

### [AnySplat Pipeline](12847-anysplat-pipeline.md)
The AnySplat Pipeline is a feed-forward method for generalizable 3D Gaussian Splatting that operates on uncalibrated input views, simultaneously predicting Gaussian parameters, depth maps, and camera poses without per-scene optimization. It distinguishes itself from sibling methods like [Splatt3R](16423-splatt3r.md) and [ZeroGS](16425-zerogs.md) by explicitly integrating a Differentiable Voxelization module to convert pixel-wise Gaussians into a voxelized representation, which stabilizes rendering and enables robust geometry supervision via pseudo-geometry priors from a pretrained VGGT model.

### [Splatt3R](16423-splatt3r.md)
Splatt3R is a feed-forward model that predicts 3D Gaussian Splat parameters directly from a pair of uncalibrated RGB images, without requiring camera intrinsics, extrinsics, or depth maps. It solves the problem of generalizable novel view synthesis by extending the MASt3R foundation model with a parallel "Gaussian head" to predict geometry offsets, covariances, opacities, and colors. Unlike sibling methods that restrict supervision to viewpoints interpolated between input stereo views, Splatt3R employs a loss masking strategy to enable robust extrapolation to viewpoints outside the input frustums.

### [RLSplat](16575-rlsplat.md)
RLSplat is a resource-linear, budget-controllable feed-forward 3D Gaussian Splatting (FF3DGS) framework that generates exactly $B$ Gaussians for a given scene, ensuring that inference latency and peak memory scale linearly with the requested budget. Unlike prior budget-controllable methods (e.g., EcoSplat, F4 Splat) that predict a dense set of candidates and prune them—resulting in nearly constant inference costs regardless of the target budget—RLSplat uses a learned Gaussian allocation policy to distribute exactly $B$ Gaussians across local scene regions from the start. This approach allows the representation size, inference latency, and peak memory to decrease linearly as the Gaussian budget $B$ is reduced, while maintaining or exceeding the reconstruction quality of denser baselines at lower resource costs.

### [LGTM (Less Gaussians, Texture More)](17426-lgtm-less-gaussians-texture-more.md)
LGTM is a feed-forward framework that predicts compact 2D Gaussian primitives coupled with per-primitive texture maps to enable high-fidelity 4K novel view synthesis without per-scene optimization. It solves the quadratic growth in primitive count inherent in pixel-aligned feed-forward 3DGS methods, which makes high-resolution synthesis intractable due to memory and compute limits. Unlike standard 3DGS which couples appearance and geometry within each primitive, LGTM decouples them, allowing a compact set of geometric primitives to represent rich texture regions via per-primitive textures.

### [InfiniSplat v2](17642-infinisplat-v2.md)
InfiniSplat v2 is a feed-forward Gaussian reconstruction method for arbitrary input views that decouples geometry and attribute prediction, uses ground-truth (GT) camera poses for alignment during training, and employs large-angle target view supervision to improve rendering quality under large viewpoint changes. It differs from its siblings by freezing the geometry branch to prevent geometric degradation caused by joint optimization, and by using GT poses for alignment to avoid pose errors that misguide the network under large-angle supervision.

### [DepthSplat](18278-depthsplat.md)
DepthSplat is a feed-forward method for 3D Gaussian splatting reconstruction that integrates pre-trained monocular depth features into a multi-view cost volume framework. It solves the problem of robust depth estimation in challenging scenes (occlusions, low-texture, non-Lambertian surfaces) where standard multi-view stereo fails, and scale ambiguities where monocular estimation fails. Unlike TranSplat, which refines coarse depth with monocular features (prone to error propagation), DepthSplat combines cost volumes and monocular features early in the pipeline. Unlike GS-LRM, it relies on explicit feature matching rather than pure data-driven priors, reducing training compute requirements significantly.

### [VG2GT](18425-vg2gt.md)
VG2GT is a feed-forward, non-pixel-aligned 3D Gaussian Splatting (3DGS) reconstruction framework that directly regresses geometrically accurate Gaussian scenes and camera parameters from an arbitrary number of unposed and uncalibrated images. It solves the problem of uneven Gaussian distributions and cross-view inconsistencies inherent in pixel-aligned methods by introducing a multi-scale differentiable voxel module that aggregates point-cloud features into a structured representation. Unlike siblings such as [AnySplat](16422-anysplat.md) which first regress pixel-aligned primitives and then aggregate them, VG2GT directly decodes Gaussian primitives from structured voxel features, avoiding the intermediate pixel-aligned representation.

### [Direct Pixel-Wise Regression](18786-direct-pixel-wise-regression.md)
Direct Pixel-Wise Regression is a feed-forward method that predicts a set of 3D Gaussian primitives directly from input image patches, establishing a one-to-one correspondence between 2D pixels and 3D Gaussians. It differs from sibling methods like [Triplane-LRM](16746-feed-forward-generalizable-reconstruction.md) by avoiding fixed-resolution latent representations (e.g., triplanes), thereby enabling pixel-aligned prediction of per-Gaussian colors and scaling Gaussian count with input resolution to capture high-frequency details.

### [WildSplat](19321-wildsplat.md)
WildSplat is a feedforward 3D Gaussian Splatting framework designed for appearance-conditioned novel-view synthesis from sparse, unposed, in-the-wild images. It solves the problem of inconsistent photometric conditions (varying lighting, weather, or time of day) by explicitly decoupling geometry from appearance, allowing the reconstruction of 3D structure independent of the target image's illumination. Unlike optimization-based methods that require precomputed poses and dense inputs, or existing feedforward methods that assume photometric consistency, WildSplat operates in a single forward pass on unposed inputs while preventing target appearance conditioning from altering the underlying geometric structure.

### [StereoGaussians](19766-stereogaussians.md)
StereoGaussians is a feed-forward method that predicts a metric 3D Gaussian Splatting (3DGS) representation from a single calibrated stereo pair, enabling nearby-view extrapolation without per-scene optimization. It differs from its siblings by explicitly transferring frozen stereo features into Gaussian attribute prediction and using a two-layer Gaussian structure with an expanded image canvas to handle disoccluded content and outside-field-of-view regions. Unlike methods that synthesize images directly (e.g., [LVSM](16425-lvsm.md)) or refine inverse depth through a composer (e.g., [SHARP](16422-sharp.md)), StereoGaussians fixes the front-layer stereo depth and bounds image-plane offsets to provide a structural prior for geometry.

### [Latent Space Representation](19901-latent-space-representation.md)
Latent Space Representation methods map input images to a compact, structured latent code (tokens, features, or distributions) which is subsequently decoded into explicit 3D Gaussian primitives, enabling generalizable reconstruction without per-scene optimization [Parent]. Unlike sibling methods that predict Gaussians directly from pixel-wise features or cost volumes, this family explicitly models the scene as a set of learnable latent entities (e.g., tokens or entropy-coded features) to enforce global consistency, reduce representation bloat, or handle ambiguity .

### Sliding Window Large-scale Reconstruction
Use sliding windows to process the sequence and construct a unified large-scale Gaussian scene [S2, unofficial]. Successfully applied to a KITTI street sequence containing over 1,000 frames [S2, unofficial].

## Background
The concept of feed-forward generalizable reconstruction for 3D Gaussians emerged as an alternative to the computationally expensive per-scene optimization of original 3DGS [S1, unofficial]. Early approaches like SplatterImage utilized U-Net architectures to translate single-view images into Gaussian attributes, which could be extended to multi-view inputs via warping [S1, unofficial]. Subsequent works integrated multi-view stereo principles, such as cost volumes (MVSplat) or foundation models (MASt3R, VGGT), to improve geometric consistency and generalization to unseen scenes [S1, unofficial]. The field has since expanded to include resource-linear methods, texture-decoupled primitives, and pose-free pipelines, addressing limitations in memory, resolution, and input requirements [S1, S2, unofficial].
