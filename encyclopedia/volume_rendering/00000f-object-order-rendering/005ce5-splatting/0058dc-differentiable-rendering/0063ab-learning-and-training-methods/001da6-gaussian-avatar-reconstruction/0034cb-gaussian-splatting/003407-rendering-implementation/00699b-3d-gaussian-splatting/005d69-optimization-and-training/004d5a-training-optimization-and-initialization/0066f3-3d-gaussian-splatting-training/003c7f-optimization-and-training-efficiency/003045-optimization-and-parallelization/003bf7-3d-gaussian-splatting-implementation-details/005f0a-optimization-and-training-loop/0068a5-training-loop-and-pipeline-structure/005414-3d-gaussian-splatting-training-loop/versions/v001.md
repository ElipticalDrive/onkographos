# 3D Gaussian Splatting Training Loop

Also called: 3DGS Optimization, Render-Compare-Correct Loop

## Overview
The 3D Gaussian Splatting (3DGS) training loop is an iterative optimization process that minimizes the difference between rendered images and ground-truth photographs by adjusting the parameters of a set of 3D Gaussians [S2, unofficial]. It solves the inverse problem of reconstructing a radiance field from sparse or dense multi-view images by using differentiable rendering to compute gradients for every Gaussian parameter simultaneously [S2, unofficial]. Unlike blind search methods, it uses gradient descent to purposefully correct millions of parameters in the direction that reduces pixel-wise error [S2, unofficial].

## How it works
**Inputs:** A set of $N$ training images with known camera poses (intrinsic and extrinsic parameters) recovered via Structure-from-Motion (SfM) [S2, unofficial]. A set of 3D Gaussians, each defined by position, covariance (or scale/rotation), opacity, and spherical harmonics coefficients for color [S1][S2, unofficial].

**Outputs:** Optimized Gaussian parameters (position, covariance, opacity, SH coefficients) and potentially an MLP for dynamic scenes [S1].

**Data Structures:**
*   **Gaussian Attributes:** Stored in contiguous arrays or GPU buffers. Each Gaussian $i$ has:
    *   $\mathbf{p}_i \in \mathbb{R}^3$: Center position.
    *   $\mathbf{R}_i \in SO(3)$: Rotation matrix (or quaternion).
    *   $\mathbf{s}_i \in \mathbb{R}^3$: Scale vector.
    *   $\alpha_i \in [0, 1]$: Opacity.
    *   $\mathbf{c}_i \in \mathbb{R}^{K \times 3}$: Spherical Harmonics coefficients (color).
*   **Camera Pose:** $\mathbf{T}_{cam} \in SE(3)$ and intrinsics $\mathbf{K}$ for the selected view.
*   **Ground Truth Image:** $\mathbf{I}_{gt} \in \mathbb{R}^{H \times W \times 3}$.

**Parameters:**
*   Optimizer: Adam [S1].
*   Learning rate: Not given in the sources.
*   Adam hyperparameters: $\beta_1 = 0.9$, $\beta_2 = 0.99$ [S1].
*   Loss weighting: $\lambda \approx 0.2$ for D-SSIM term [S2, unofficial].
*   Iteration budget: Typically 30,000 iterations [S2, unofficial].

**Steps:**
1.  **Initialization:** Initialize Gaussian centers at SfM point cloud positions or, in specific applications like human avatars, at SMPL model vertex positions with imported skinning weights [S1][S2, unofficial].
2.  **Sample View:** Randomly select one training image $j$ from the set of $N$ images [S2, unofficial].
3.  **Transform:** Transform canonical Gaussian parameters to the observation space defined by the camera pose of image $j$ [S1]. For dynamic scenes, this may involve an MLP predicting deformations [S1].
4.  **Render:** Use the differentiable Gaussian rasterizer to render an image $\mathbf{I}_{pred}$ from the transformed Gaussians using the camera pose [S1][S2, unofficial].
5.  **Compare:** Compute the per-image loss $\mathcal{L}_{per}$ between $\mathbf{I}_{pred}$ and the ground truth $\mathbf{I}_{gt}$ [S2, unofficial].
6.  **Correct:** Compute gradients $\nabla \mathcal{L}_{per}$ with respect to all Gaussian parameters using backpropagation through the rasterizer [S2, unofficial]. Update parameters using the Adam optimizer [S1].
7.  **Densify/Prune (Optional/Periodic):** Incrementally densify and prune Gaussians based on heuristics (e.g., gradient magnitude, opacity thresholds) to manage density and detail [S1]. *Note: The specific densification schedule is detailed in sibling article [15107-optimization-schedule-and-densification.md].*
8.  **Repeat:** Repeat steps 2-7 for the iteration budget (e.g., 30,000 times) [S2, unofficial].

**Loss Function:**
The total loss $\mathcal{L}$ for a single iteration is a weighted sum of L1 loss and D-SSIM loss [S2, unofficial]:
$$ \mathcal{L} = (1 - \lambda) \mathcal{L}_{L1} + \lambda \mathcal{L}_{D-SSIM} $$
where $\lambda \approx 0.2$ [S2, unofficial].
*   $\mathcal{L}_{L1}$: The mean absolute difference between corresponding pixel colors in $\mathbf{I}_{pred}$ and $\mathbf{I}_{gt}$ [S2, unofficial].
*   $\mathcal{L}_{D-SSIM}$: The differentiable Structural Similarity index, measuring local structure, contrast, and texture [S2, unofficial].

**Pseudocode:**
```python
def train_3dgs(gaussians, images, camera_poses, num_iterations=30000, lambda_ss=0.2):
    # Initialize optimizer with Adam (beta1=0.9, beta2=0.99)
    optimizer = Adam(gaussians.parameters(), lr=initial_lr)
    
    for iteration in range(num_iterations):
        # 1. Sample a random training view
        view_idx = random.randint(0, len(images) - 1)
        image_gt = images[view_idx]
        pose = camera_poses[view_idx]
        
        # 2. Transform Gaussians to observation space
        # For static scenes, this is a rigid transformation.
        # For dynamic scenes (e.g., HumanGS), an MLP may deform canonical Gaussians.
        gaussians_obs = transform_to_observation_space(gaussians, pose)
        
        # 3. Render the image
        # Uses differentiable Gaussian rasterizer
        image_pred = rasterize(gaussians_obs, pose)
        
        # 4. Compute Loss
        # L1 Loss: Mean absolute error
        loss_l1 = mean_absolute_error(image_pred, image_gt)
        
        # D-SSIM Loss: Differentiable Structural Similarity
        loss_dssim = compute_dssim(image_pred, image_gt)
        
        # Combined Loss
        loss = (1 - lambda_ss) * loss_l1 + lambda_ss * loss_dssim
        
        # 5. Backpropagate and Update
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        
        # 6. Periodic Densification/Pruning
        # (Details in sibling article [15107-optimization-schedule-and-densification.md])
        if iteration % densify_interval == 0:
            densify_and_prune(gaussians, optimizer)
            
    return gaussians
```

**Edge Cases and Pitfalls:**
*   **Overfitting:** Training on all views simultaneously can lead to overfitting to the specific order or distribution of training images. Random sampling mitigates this [S2, unofficial].
*   **Stopping Criterion:** There is no clean loss threshold for "done." Training stops after a fixed iteration budget (e.g., 30,000) because the loss curve exhibits diminishing returns [S2, unofficial].
*   **Evaluation:** Per-image loss is used for optimization, but scene-wide progress is monitored by averaging loss across all views. Generalization should be evaluated on held-out novel views [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Each iteration involves rendering $O(G)$ Gaussians to $O(H \times W)$ pixels, where $G$ is the number of Gaussians and $H, W$ are image dimensions. The rasterization is linear in the number of Gaussians and pixels [S1]. Backpropagation is similarly efficient due to the differentiable rasterizer [S2, unofficial].
*   **Memory Complexity:** $O(G)$ to store Gaussian parameters. The number of Gaussians $G$ can grow significantly during densification, potentially reaching millions [S1][S2, unofficial].
*   **Performance:** Training typically runs for ~30,000 iterations [S2, unofficial]. The method is significantly faster than neural radiance field (NeRF) optimization because it avoids volumetric sampling and uses a fast rasterizer [S2, unofficial].
*   **Strengths:** Simultaneous optimization of millions of parameters; differentiable rendering provides clear gradients; fast convergence compared to iterative volume rendering methods [S2, unofficial].
*   **Limitations:** Requires a fixed iteration budget; densification heuristics can be sensitive to hyperparameters; prone to overfitting if not regularized or if training views are insufficient [S1][S2, unofficial].

## Background
The 3D Gaussian Splatting training loop was introduced in the original 3D Gaussian Splatting paper [S1][S2, unofficial]. It builds on the differentiable rasterization of 3D Gaussians, allowing for end-to-end optimization of scene representation from images [S1]. The method was initially developed for static scene reconstruction but has been extended to dynamic scenes (e.g., Human Gaussian Splatting) and other domains [S1]. The use of Adam optimizer and the specific loss combination (L1 + D-SSIM) are standard practices in differentiable rendering [S1][S2, unofficial].
