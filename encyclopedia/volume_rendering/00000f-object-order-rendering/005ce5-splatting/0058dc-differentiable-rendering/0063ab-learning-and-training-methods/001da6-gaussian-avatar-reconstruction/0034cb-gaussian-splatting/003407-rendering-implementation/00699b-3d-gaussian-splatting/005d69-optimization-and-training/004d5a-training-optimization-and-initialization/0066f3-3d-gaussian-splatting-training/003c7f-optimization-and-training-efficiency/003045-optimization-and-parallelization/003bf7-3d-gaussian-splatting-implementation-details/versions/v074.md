# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, GSGEN Implementation Details, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific hyperparameters, data structures, and optimization schedules required to implement the 3D Gaussian Splatting (3DGS) training pipeline, including densification, pruning, and hardware-aware rasterization. It addresses the practical gap between the theoretical differentiable rendering formulation and a working implementation, focusing on stability in half-precision arithmetic and adaptive density control. It builds on [Optimization and Parallelization](6233-optimization-and-parallelization.md) by specifying the concrete thresholds and iteration counts for the shared gradient accumulation and adaptive representation mechanisms.

## How it works
### Inputs and Outputs
*   **Inputs**: Sparse Structure-from-Motion (SfM) point cloud (position, covariance, color), camera poses, and training images.
*   **Outputs**: A set of optimized 3D Gaussians $\mathcal{G} = \{\mathbf{p}_i, \mathbf{R}_i, \mathbf{s}_i, \alpha_i, \mathbf{c}_i\}$, where $\mathbf{p}$ is position, $\mathbf{R}$ is rotation, $\mathbf{s}$ is scale, $\alpha$ is opacity, and $\mathbf{c}$ is spherical harmonic coefficients.

### Data Structures
The Gaussian representation is stored in a flat array or structure-of-arrays (SoA) layout for efficient GPU access.
*   **Position**: $\mathbf{p} \in \mathbb{R}^3$ (float32).
*   **Rotation**: $\mathbf{q} \in \mathbb{R}^4$ (quaternion, float32), normalized after every update.
*   **Scale**: $\mathbf{s} \in \mathbb{R}^3$ (float32), representing log-scale for unconstrained optimization.
*   **Opacity**: $\alpha \in \mathbb{R}$ (float32), sigmoid-activated.
*   **Color**: $\mathbf{c} \in \mathbb{R}^{3 \times (N_{SH}+1)^2}$ (float32), where $N_{SH}$ is the SH degree.
*   **Gradients**: Accumulated per-parameter buffers, typically float32 or float16 depending on mixed precision settings.

### Training Loop and Optimization Steps
The training process minimizes a loss $\mathcal{L} = (1-\lambda)\mathcal{L}_{L1} + \lambda\mathcal{L}_{SSIM}$ using the Adam optimizer.

1.  **Initialization**: Initialize Gaussians from the SfM point cloud. Compute scene extent $e_{scene}$ to bound the initial splitting/pruning logic.
2.  **Rasterization**: For each training image, project Gaussians to 2D, sort by depth, and render via alpha blending.
3.  **Loss Computation**: Compute $\mathcal{L}$ between rendered and ground-truth images.
4.  **Backpropagation**: Compute gradients $\frac{\partial \mathcal{L}}{\partial \theta}$ for all Gaussian parameters.
5.  **Optimizer Step**: Update parameters using Adam.
6.  **Adaptive Density Control (Densification/Pruning)**:
    *   **Splitting**: Every 100 iterations (standard) or 500 iterations (GSGEN [S1]), split Gaussians with high positional gradients.
    *   **Cloning**: Clone Gaussians with high view-space opacity gradients but low positional gradients.
    *   **Pruning**: Every 100 iterations (standard) or 200 iterations (GSGEN [S1]), remove Gaussians with opacity $\alpha < \alpha_{min}$ or excessive radius.

### Formulas and Parameters

**Scene Extent Calculation**
The default scene extent $e_{scene}$ biases optimization if cameras are clustered. A corrected extent $e'_{scene}$ uses SfM points [S4]:
$$ \bar{C} = \frac{1}{N_{cam}} \sum_{i=1}^{N_{cam}} C_i $$
$$ e'_{scene} = \frac{1}{N_{SfM}} \sum_{i=1}^{N_{SfM}} \|\bar{C} - p_i\|_2 $$
where $C_i$ are camera positions, $p_i$ are SfM points, and $N_{cam}, N_{SfM}$ are their counts.

**Densification Thresholds**
*   **Position Gradient Split**: Split if view-space position gradient $> T_{pos}$. Standard $T_{pos}$ is not explicitly defined in the base paper but GSGEN uses $T_{pos} = 0.02$ [S1].
*   **Opacity Gradient Clone**: Clone if view-space opacity gradient $> T_{op}$ and position gradient $< T_{pos}$.
*   **Pruning Threshold**: Remove if $\alpha < \alpha_{min}$. Standard $\alpha_{min} = 0.005$ [G]; GSGEN uses $\alpha_{min} = 0.05$ [S1].

**Half-Precision Stability**
To stabilize FP16 training, an automatic scaling factor is applied to loss values [S2]. Feature vectors are fetched in half-precision to reduce register pressure [S2].

### Pseudocode

```python
def train_3dgs(sfm_points, images, num_iterations=30000):
    # Initialize Gaussians from SfM
    gaussians = init_gaussians(sfm_points)
    
    # Optimizer setup
    optimizer = Adam(gaussians.parameters(), lr=1e-3)
    
    # Hyperparameters
    alpha_min = 0.005  # Standard pruning threshold [G]
    t_pos = 0.02       # GSGEN position gradient threshold [S1]
    split_interval = 100 # Standard densification interval [G]
    prune_interval = 100 # Standard pruning interval [G]
    
    for step in range(num_iterations):
        # 1. Sample a random training image
        image, camera_pose = sample_random_view(images)
        
        # 2. Forward pass: Rasterize
        # Custom CUDA kernel for differentiable alpha blending
        rendered_image = rasterize(gaussians, camera_pose)
        
        # 3. Compute Loss
        # Apply scaling factor for FP16 stability if using half-precision [S2]
        loss = compute_loss(rendered_image, image)
        
        # 4. Backward pass
        loss.backward()
        
        # 5. Optimizer step
        optimizer.step()
        optimizer.zero_grad()
        
        # 6. Adaptive Density Control
        if step % split_interval == 0:
            densify(gaussians, t_pos)
        if step % prune_interval == 0:
            prune(gaussians, alpha_min)
            
    return gaussians

def densify(gaussians, t_pos):
    for g in gaussians:
        if g.pos_gradient > t_pos:
            split_gaussian(g)
        elif g.opacity_gradient > threshold and g.pos_gradient < t_pos:
            clone_gaussian(g)

def prune(gaussians, alpha_min):
    for g in gaussians:
        if g.opacity < alpha_min or g.radius > max_radius:
            remove_gaussian(g)
```

### Edge Cases and Pitfalls
*   **Scene Extent Bias**: Using camera-based extent $e_{scene}$ for scenes with clustered cameras (e.g., orbiting a small object) leads to incorrect splitting/pruning [S4]. Use SfM-based extent [S4].
*   **Half-Precision Instability**: Direct FP16 training can cause NaNs. Use loss scaling and half-precision memory fetches for features [S2].
*   **Gradient Accumulation**: Ensure gradients are accumulated correctly across multiple views if using batched training [6233-optimization-and-parallelization].

## Subtopics

### Corrected Scene-Extent
A method to calculate scene extent based on the SfM point cloud rather than camera positions to avoid bias from camera distribution (e.g., orbiting a small object in a large environment) [S4]. It sets itself apart from the default 3DGS implementation by using $e'_{scene} = \frac{1}{N_{SfM}} \sum_{i=1}^{N_{SfM}} \|\bar{C} - p_i\|_2$ [S4]. Choose this when camera positions are not uniformly distributed around the scene volume.

### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ to selectively enlarge covariances, creating pixel-wise variable blur kernels that match spatially varying scene blurriness [S5]. It sets itself apart from naive Gaussian blur by allowing spatially varying blur shapes and magnitudes, enabling effective deblurring of defocus blur [S5]. Choose this for scenes with depth-dependent blur.

### Denoise-GS
A self-supervised denoising method for sparse-view 3D Gaussian Splatting that combines unsupervised image denoising (Noise2Void) with differentiable 3DGS [S6]. It sets itself apart from supervised methods by requiring no paired clean data, making it robust to non-Gaussian noise in sparse viewpoints [S6]. Choose this for sparse-view or noisy input data.

### Multi-Scale Constraint
A technique using position-aware point adaptive control to apply different scales to Gaussians based on viewer distance, improving rendering of distant objects [S7]. It sets itself apart from standard densification by using a distance-dependent threshold $\gamma(\mu)$ for cloning and splitting [S7]. Choose this for large-scale scenes with significant depth variation.

### LS-Gaussian Viewpoint Transformation
An algorithm that leverages inter-frame continuity for efficient sparse rendering by transforming the viewpoint between consecutive frames, rather than rendering each frame separately [S8]. It sets itself apart from naive pixel warping by operating at the tile/Gaussian level to reduce preprocessing and sorting costs [S8]. Choose this for real-time rendering of continuous camera trajectories.

### Camera Localisation for Convergence Basin
Localizes camera pose by minimizing photometric error against a ground-truth image while fixing the Gaussian initialization [S9, unofficial]. It sets itself apart from joint optimization by decoupling pose estimation from geometry refinement [S9, unofficial]. Choose this for SLAM or pose estimation tasks.

### DiffGS Framework
Applies an optimization process during Gaussian extraction to optimize Gaussians to exact locations using a Gaussian Probability Function (GauPF) [S10]. It sets itself apart from standard splatting by modeling Gaussians as probability functions with truncation and projection functions [S10]. Choose this for high-fidelity reconstruction with fewer Gaussians.

### Opacity Offset Table for DSA
Constructs an opacity offset table to model changes in digital subtraction angiography [S11]. It sets itself apart by explicitly modeling temporal opacity changes for medical imaging [S11]. Choose this for dynamic medical volume rendering.

### Conditional Splat Approximation
Approximates the influence range of a 3D Gaussian on a slice by using a 2D ellipse splat scaled by the marginal factor [S12, unofficial]. It sets itself apart by providing an accurate and efficient approximation of 3D Gaussian iso-probability contours for slice-based rendering [S12, unofficial]. Choose this for tomographic reconstruction or slice-based visualization.

### 3DGS Uncertainty Calculation via Fisher Information
Computes an uncertainty attribute for 3D Gaussians based on the negative log-likelihood of the rendered pixel value, interpreted as Fisher information [S13]. It sets itself apart by providing a per-Gaussian uncertainty metric derived from the Hessian of the log-likelihood [S13]. Choose this for uncertainty-aware rendering or active view selection.

## Operating characteristics
*   **Time Complexity**: $O(N \cdot M)$ per iteration, where $N$ is the number of Gaussians and $M$ is the number of pixels. Sorting dominates the cost.
*   **Memory Complexity**: $O(N)$ for storing Gaussian parameters. High memory usage for large scenes due to millions of primitives.
*   **Performance**: Real-time rendering (30-100+ FPS) on modern GPUs for scenes with $<10^6$ Gaussians [6233-optimization-and-parallelization].
*   **Strengths**: High visual fidelity, fast training, real-time rendering.
*   **Limitations**: High memory usage, sensitivity to initialization, potential for artifacts in dynamic scenes.
*   **When to use**: Static scene reconstruction, novel view synthesis, text-to-3D generation.
*   **When not to use**: Scenes with extreme dynamic content, very large-scale outdoor scenes without spatial partitioning.

## Background
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [6233-optimization-and-parallelization]. It revolutionized radiance field rendering by using explicit 3D Gaussians as primitives, enabling real-time differentiable rendering. The method has since been extended with various optimization techniques, densification strategies, and hardware accelerations.
