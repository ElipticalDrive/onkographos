# 3D Gaussian Splatting

Also called: 3D Gaussian Splatting Pipeline, 3DGS Rendering, 3DGS Rasterization, 3D Gaussian Splatting Rasterization, 3D Gaussian Splatting Rendering Pipeline, Standard 3D Gaussian Splatting Rendering, Kerbl et al. pipeline, Original 3DGS

## Overview
3D Gaussian Splatting is a novel view synthesis and 3D reconstruction method where the scene is represented by anisotropic 3D Gaussians parameterized by positions, covariances, colors, and opacities [S1]. It solves the problem of real-time, high-fidelity rendering by projecting these 3D primitives into 2D ellipses and rasterizing them using a tile-based, differentiable software rasterizer [S6, unofficial]. Unlike volumetric ray-marching methods like NeRF, it uses discrete, point-based splatting, and unlike standard OpenGL rasterization, it computes analytic gradients for the non-linear projection and compositing operations, enabling end-to-end differentiable training [S6, unofficial][S10]. It sets itself apart from its siblings by establishing the baseline tile-based rasterization pipeline that subsequent variants (e.g., [3D Gaussian Splatting Differentiable Rasterizer](2813-3d-gaussian-splatting-differentiable-rasterizer.md)) optimize or extend.

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $N$ 3D Gaussian primitives, each defined by a mean position $\boldsymbol{\mu} \in \mathbb{R}^3$, a rotation quaternion $\mathbf{q} \in \mathbb{R}^4$, a scale vector $\mathbf{s} \in \mathbb{R}^3$, a base opacity $\alpha_{raw} \in \mathbb{R}$, and spherical harmonics coefficients $\mathbf{c} \in \mathbb{R}^{3 \times K}$ (where $K$ depends on the SH degree). Camera parameters (intrinsics $f_x, f_y, c_x, c_y$ and extrinsics $V$) and image dimensions $(W, H)$ are also required.
*   **Output:** An RGB image $\mathbf{I} \in \mathbb{R}^{H \times W \times 3}$, and optionally depth, normal, or alpha masks.

**Data Structures:**
The primitive data is typically stored in Structure-of-Arrays (SoA) or Array-of-Structures (AoS) format for GPU memory coalescing. A common layout includes:
*   `xyz`: `float32[N, 3]`
*   `rot`: `float32[N, 4]` (quaternions)
*   `scale`: `float32[N, 3]`
*   `opacity`: `float32[N, 1]`
*   `sh`: `float32[N, SH_dim]` (e.g., $N \times 48$ for degree 3) [S12, unofficial].

**Steps:**

1.  **Activation and Covariance Construction:**
    Raw parameters are transformed to ensure valid ranges and positive definiteness [S6, unofficial]:
    *   Normalize rotation: $\mathbf{q}_{norm} = \mathbf{q} / \|\mathbf{q}\|$ [S6, unofficial].
    *   Exponentiate scales: $\mathbf{s}_{eff} = \exp(\mathbf{s})$ [S6, unofficial].
    *   Sigmoid opacity: $\alpha_{eff} = \sigma(\alpha_{raw})$ [S6, unofficial].
    *   Construct the 3D covariance matrix $\boldsymbol{\Sigma}_{3D}$ from the rotation matrix $\mathbf{R}$ (derived from $\mathbf{q}_{norm}$) and scaling matrix $\mathbf{S} = \text{diag}(\mathbf{s}_{eff})$:
        $$ \boldsymbol{\Sigma}_{3D} = \mathbf{R} \mathbf{S} \mathbf{S}^T \mathbf{R}^T $$
        [S6, unofficial].

2.  **Camera Space Transformation:**
    Transform means and covariances to camera space using the view matrix $\mathbf{V}$ [S6, unofficial]:
    *   Mean: $\boldsymbol{\mu}' = \mathbf{V} \boldsymbol{\mu}$ (homogeneous coordinates implied).
    *   Covariance: $\boldsymbol{\Sigma}' = \mathbf{V}_{1:3, 1:3} \boldsymbol{\Sigma}_{3D} \mathbf{V}_{1:3, 1:3}^T$ [S6, unofficial].

3.  **Projection to Screen Space:**
    Project to 2D using a first-order Taylor approximation (Jacobian) of the perspective projection [S10]:
    *   Compute the Jacobian $\mathbf{J}$ at $\boldsymbol{\mu}' = (X, Y, Z)^T$:
        $$ \mathbf{J} = \begin{pmatrix} \frac{f_x}{Z} & 0 & -\frac{f_x X}{Z^2} \\ 0 & \frac{f_y}{Z} & -\frac{f_y Y}{Z^2} \end{pmatrix} $$
        [S6, unofficial][S10]. Note: $\mathbf{J}$ contains identically zero terms, allowing hardware optimization [S10].
    *   Compute the 2D screen-space covariance:
        $$ \boldsymbol{\Sigma}_{2D} = \mathbf{J} \boldsymbol{\Sigma}' \mathbf{J}^T $$
        [S6, unofficial].
    *   Compute the 2D mean:
        $$ \boldsymbol{\mu}_{2D} = \begin{pmatrix} \frac{f_x X}{Z} + c_x \\ \frac{f_y Y}{Z} + c_y \end{pmatrix} $$
        [S6, unofficial].

4.  **Culling and Sorting:**
    *   **Culling:** Discard Gaussians where $\mu'_z < z_{near}$ (typically 0.01) or outside the view frustum [S10].
    *   **Sorting:** Sort the remaining Gaussians by camera-space depth $\mu'_z$ to approximate front-to-back order. This avoids prohibitively slow per-pixel sorting [S6, unofficial].

5.  **Tile Assignment and Rasterization:**
    *   Divide the image into tiles (e.g., $16 \times 16$ pixels) [S10].
    *   Assign each Gaussian to the tiles it intersects. The radius for intersection testing is typically $3\sigma$ (bounding box size multiplier 3.0) [S12, unofficial].
    *   For each tile, iterate over assigned Gaussians. For each pixel $(u, v)$ covered by a Gaussian, compute the alpha contribution:
        $$ \alpha_{pixel} = \alpha_{eff} \cdot \exp\left(-\frac{1}{2} (\mathbf{x} - \boldsymbol{\mu}_{2D})^T \boldsymbol{\Sigma}_{2D}^{-1} (\mathbf{x} - \boldsymbol{\mu}_{2D})\right) $$
        where $\mathbf{x} = (u, v)^T$ [S6, unofficial].
    *   Compute the view-dependent color $\mathbf{c}_i$ using spherical harmonics evaluated at the viewing direction $\mathbf{d} = \text{normalize}(\boldsymbol{\mu}' - \mathbf{cam\_pos})$ [S11, unofficial].

6.  **Alpha Compositing:**
    Accumulate color and transmittance for each pixel in depth order [S10]:
    *   Initialize $C_{acc} = 0$, $T = 1$.
    *   For each Gaussian $i$ in sorted order:
        $$ C_{acc} \leftarrow C_{acc} + T \cdot \alpha_{pixel} \cdot \mathbf{c}_i $$
        $$ T \leftarrow T \cdot (1 - \alpha_{pixel}) $$
    *   **Early Termination:** Stop processing Gaussians for a pixel when $T < \tau$ (threshold, e.g., 0.0001) [S10].

**Pseudocode:**

```python
import numpy as np

def render_3dgs(gaussians, camera, width, height, tile_size=16, tau=0.0001):
    """
    Render a scene using 3D Gaussian Splatting.
    
    Args:
        gaussians: Dict with keys 'xyz' (N,3), 'rot' (N,4), 'scale' (N,3), 
                   'opacity' (N,1), 'sh' (N, SH_dim).
        camera: Dict with 'K' (3,3), 'W2C' (4,4).
        width, height: Image dimensions.
        tile_size: Size of rasterization tiles.
        tau: Early termination threshold.
        
    Returns:
        image: (H, W, 3) RGB image.
    """
    N = gaussians['xyz'].shape[0]
    
    # 1. Activation
    q = gaussians['rot'] / np.linalg.norm(gaussians['rot'], axis=1, keepdims=True)
    s = np.exp(gaussians['scale'])
    alpha_raw = gaussians['opacity']
    alpha_eff = 1.0 / (1.0 + np.exp(-alpha_raw))
    
    # 2. Covariance Construction
    # Construct rotation matrix R from quaternion q
    R = quaternion_to_rotation_matrix(q) # Helper defined below
    S_diag = np.diag(s, axis1=-2, axis2=-1) # Shape (N, 3, 3)
    # Sigma_3D = R S S^T R^T
    # Efficiently: Sigma_3D = R @ diag(s^2) @ R^T
    S_sq = np.square(s)
    Sigma_3D = np.einsum('nij,njk,nlk->nil', R, np.diag(S_sq, axis1=-2, axis2=-1), R) # Simplified einsum for diag
    
    # 3. Camera Space Transformation
    # Extract 3x3 rotation part of W2C
    V_rot = camera['W2C'][:3, :3]
    V_trans = camera['W2C'][:3, 3]
    
    # Transform means: mu' = V * mu + t
    mu_cam = np.einsum('ij,nj->ni', V_rot, gaussians['xyz']) + V_trans
    
    # Transform covariances: Sigma' = V_rot Sigma_3D V_rot^T
    Sigma_cam = np.einsum('ij,njk,lk->nil', V_rot, Sigma_3D, V_rot)
    
    # 4. Projection to Screen Space
    fx, fy = camera['K'][0, 0], camera['K'][1, 1]
    cx, cy = camera['K'][0, 2], camera['K'][1, 2]
    
    X, Y, Z = mu_cam[:, 0], mu_cam[:, 1], mu_cam[:, 2]
    
    # Jacobian J
    # J = [[fx/Z, 0, -fx*X/Z^2], [0, fy/Z, -fy*Y/Z^2]]
    # We need Sigma_2D = J Sigma' J^T
    # Since J is 2x3 and Sigma' is 3x3, result is 2x2
    
    # Compute terms for J
    inv_Z = 1.0 / Z
    inv_Z_sq = inv_Z * inv_Z
    
    # J components
    J00 = fx * inv_Z
    J02 = -fx * X * inv_Z_sq
    J11 = fy * inv_Z
    J12 = -fy * Y * inv_Z_sq
    
    # Sigma_2D calculation
    # Sigma_2D[0,0] = J00^2 * Sigma'[0,0] + 2*J00*J02*Sigma'[0,2] + J02^2 * Sigma'[2,2]
    # ... (full expansion required for correctness)
    # Using matrix multiplication for clarity
    J = np.zeros((N, 2, 3))
    J[:, 0, 0] = J00
    J[:, 0, 2] = J02
    J[:, 1, 1] = J11
    J[:, 1, 2] = J12
    
    Sigma_2D = np.einsum('nij,njk,nlk->nil', J, Sigma_cam, J)
    
    # 2D Means
    mu_2d_x = fx * X * inv_Z + cx
    mu_2d_y = fy * Y * inv_Z + cy
    mu_2d = np.stack([mu_2d_x, mu_2d_y], axis=1) # (N, 2)
    
    # 5. Culling
    near_plane = 0.01
    valid_mask = Z > near_plane
    valid_indices = np.where(valid_mask)[0]
    
    if len(valid_indices) == 0:
        return np.zeros((height, width, 3))
        
    xyz_valid = gaussians['xyz'][valid_indices]
    alpha_eff_valid = alpha_eff[valid_indices]
    Sigma_2D_valid = Sigma_2D[valid_indices]
    mu_2d_valid = mu_2d[valid_indices]
    Z_valid = Z[valid_indices]
    
    # 6. Sorting
    sort_idx = np.argsort(Z_valid)
    xyz_valid = xyz_valid[sort_idx]
    alpha_eff_valid = alpha_eff_valid[sort_idx]
    Sigma_2D_valid = Sigma_2D_valid[sort_idx]
    mu_2d_valid = mu_2d_valid[sort_idx]
    Z_valid = Z_valid[sort_idx]
    
    # 7. Tile Rasterization
    # Initialize output buffers
    image = np.zeros((height, width, 3))
    transmittance = np.ones((height, width))
    
    # Precompute inverse 2D covariances (conics)
    # Sigma_2D is 2x2. Inverse is 1/det * [[d, -b], [-c, a]]
    # Store as (a, b, d) for conic representation
    det = Sigma_2D_valid[:, 0, 0] * Sigma_2D_valid[:, 1, 1] - Sigma_2D_valid[:, 0, 1] * Sigma_2D_valid[:, 1, 0]
    # Guard against singular matrices
    det = np.maximum(det, 1e-6)
    conics = np.zeros((len(valid_indices), 3))
    conics[:, 0] = Sigma_2D_valid[:, 1, 1] / det
    conics[:, 1] = -Sigma_2D_valid[:, 0, 1] / det
    conics[:, 2] = Sigma_2D_valid[:, 0, 0] / det
    
    # Compute bounding boxes for tiles
    # Radius is approx 3 sigma. Use sqrt of diagonal elements for axis-aligned bbox
    # More precise: use conic to find intersection, but bbox is faster for culling
    # Simplified: use 3 * sqrt(diag)
    sigma_x = np.sqrt(np.maximum(Sigma_2D_valid[:, 0, 0], 1e-6))
    sigma_y = np.sqrt(np.maximum(Sigma_2D_valid[:, 1, 1], 1e-6))
    radius_x = 3.0 * sigma_x
    radius_y = 3.0 * sigma_y
    
    # Assign to tiles and rasterize
    # For implementation completeness, we iterate pixels if N is small, 
    # but standard is tile-based. Here we simulate the core blending logic.
    
    # To make this self-contained and valid Python without external libs, 
    # we perform a simplified per-pixel check for Gaussians that cover it.
    # In production, this is done via tile intersection lists.
    
    # Create a list of (u_min, u_max, v_min, v_max, gauss_idx)
    tiles = []
    for i in range(len(valid_indices)):
        u_min = int(np.floor(mu_2d_valid[i, 0] - radius_x[i]))
        u_max = int(np.ceil(mu_2d_valid[i, 0] + radius_x[i]))
        v_min = int(np.floor(mu_2d_valid[i, 1] - radius_y[i]))
        v_max = int(np.ceil(mu_2d_valid[i, 1] + radius_y[i]))
        
        u_min = max(0, u_min)
        u_max = min(width, u_max)
        v_min = max(0, v_min)
        v_max = min(height, v_max)
        
        if u_min < u_max and v_min < v_max:
            tiles.append((u_min, u_max, v_min, v_max, i))
            
    # Sort tiles by gauss_idx to process gaussians in depth order per pixel? 
    # No, standard is: for each tile, process gaussians assigned to it.
    # For simplicity in this pure Python ref, we iterate gaussians and update pixels.
    # This is O(N * Pixels) worst case, but correct for reference.
    
    for i in range(len(valid_indices)):
        u_c, v_c = mu_2d_valid[i]
        c = conics[i] # (a, b, d)
        alpha = alpha_eff_valid[i]
        
        # Get color from SH (simplified to base color if SH not fully implemented in helper)
        # Assuming 'sh' contains base color in first 3 coeffs for degree 0
        color = gaussians['sh'][valid_indices[i], :3] 
        
        u_min, u_max, v_min, v_max, _ = tiles[i] # Re-fetch from list if needed, but i is index in valid
        
        # Actually, let's just iterate the valid gaussians and their bounding boxes
        # Re-construct bbox for current i
        # (Already computed in loop above, but let's re-access or store)
        # For this pseudocode, we assume we have the bbox for i
        
        # Iterate pixels in bbox
        for v in range(v_min, v_max):
            for u in range(u_min, u_max):
                # Check if pixel is within transmittance threshold
                if transmittance[v, u] < tau:
                    continue
                
                # Compute alpha at pixel (u, v)
                # x = [u - u_c, v - v_c]
                dx = u - u_c
                dy = v - v_c
                
                # Quadratic form: x^T Sigma^{-1} x = a*dx^2 + 2*b*dx*dy + d*dy^2
                # conics stores a, b, d where Sigma_inv = [[a, b], [b, d]]
                # Note: conics[1] is the off-diagonal element. The quadratic form is:
                # a*dx*dx + 2*b*dx*dy + d*dy*dy
                exponent = -(0.5 * (c[0]*dx*dx + 2*c[1]*dx*dy + c[2]*dy*dy))
                
                # Clamp exponent to avoid overflow
                exponent = np.clip(exponent, -100, 0)
                
                alpha_pixel = alpha * np.exp(exponent)
                
                # Blend
                T_prev = transmittance[v, u]
                contribution = T_prev * alpha_pixel * color
                image[v, u] += contribution
                transmittance[v, u] *= (1 - alpha_pixel)
                
    return image

def quaternion_to_rotation_matrix(q):
    """Convert quaternion (w, x, y, z) to 3x3 rotation matrix."""
    # q is (N, 4). Assume w is first component or last? Standard is often w,x,y,z or x,y,z,w.
    # Kerbl uses w,x,y,z.
    w, x, y, z = q[:, 0], q[:, 1], q[:, 2], q[:, 3]
    
    R = np.zeros((q.shape[0], 3, 3))
    
    R[:, 0, 0] = 1 - 2*(y*y + z*z)
    R[:, 0, 1] = 2*(x*y - w*z)
    R[:, 0, 2] = 2*(x*z + w*y)
    
    R[:, 1, 0] = 2*(x*y + w*z)
    R[:, 1, 1] = 1 - 2*(x*x + z*z)
    R[:, 1, 2] = 2*(y*z - w*x)
    
    R[:, 2, 0] = 2*(x*z - w*y)
    R[:, 2, 1] = 2*(y*z + w*x)
    R[:, 2, 2] = 1 - 2*(x*x + y*y)
    
    return R
```

**Parameters:**
*   **Tile Size:** Typically $16 \times 16$ pixels [S10].
*   **Near Plane:** 0.01 [S12, unofficial].
*   **Far Plane:** 100.0 or larger (e.g., $10^{10}$) [S12, unofficial][S11, unofficial].
*   **SH Degree:** 3 (coefficients $\hat{c} \in \mathbb{R}^{3 \times 16}$) [S6, unofficial].
*   **Bounding Box Multiplier:** 3.0 (representing $3\sigma$ extent) [S12, unofficial].
*   **Opacity Learning Rate:** 0.025 (halved from 0.05 in later implementations) [S6, unofficial].
*   **Training Iterations:** 30,000 [S6, unofficial].

**Edge Cases and Pitfalls:**
*   **Singular Covariance:** The 2D covariance matrix $\boldsymbol{\Sigma}_{2D}$ may become singular (non-invertible) if a Gaussian is viewed edge-on or has zero scale. The inverse is required for the conic representation. A small epsilon (e.g., $10^{-6}$) should be added to the determinant before inversion [S12, unofficial][S16].
*   **Jacobian Approximation:** The projection is projective, not affine. Gaussians are closed under affine transformations but not projective ones, leading to approximation errors when using the local affine approximation (Jacobian) [S16].
*   **Sorting Bottleneck:** Sorting millions of Gaussians is a primary bottleneck. Efficient implementations use CUB device radix sort (CUDA) [S14, unofficial].
*   **Memory Usage:** High VRAM usage (4GB to view, 12GB to train) and large disk size (1GB+ for a scene) due to unbounded Gaussian count [S14, unofficial].

### Fisheye Camera Adaptation (Equidistant Projection)
Adapts the rasterization projection for fisheye cameras using the equidistant projection model [S16]. For a pixel $(u, v)$, the 2D coordinate vector $\mathbf{x}_{2D}$ is computed using intrinsic parameters $c_x, c_y, f_x, f_y$ and the angle $\theta = \sqrt{\frac{(u-c_x)^2}{f_x^2} + \frac{(v-c_y)^2}{f_y^2}}$:
$$ \mathbf{x}_{2D} = \varphi_p \left( \begin{array}{c} (u-c_x) \sin(\theta) \\ f_x \theta \\ (v-c_y) \sin(\theta) \\ f_y \theta \\ \cos(\theta) \end{array} \right) $$
[S16].

### Temporal Marginal Probability Filtering
Pre-rasterization culling step that removes 4D Gaussians with negligible temporal support $p_i(t)$ at the current frame timestamp $t$, stabilizing rendering speed across video length [S19, unofficial]. Unlike methods where Gaussian count scales with video length, this keeps active Gaussians constant [S19, unofficial].

### t-distribution truncation for splatting
Replaces the fixed three-sigma rule with a $\nu$-dependent critical value interpolation to handle fat-tailed Student's t-distributions [S20]. Using a fixed threshold on fat-tailed distributions causes excessive truncation or leakage; interpolation resolves this [S20].

### Don't Splat your Gaussians
Introduces volumetric ray-traced primitives with closed-form transmittance for efficient media rendering, addressing violations of physical absorption-emission models [S21, unofficial].

### 3D Gaussian Splatting for X-ray Projection Rasterization
Leverages 3DGS to rasterize X-ray projections by modeling attenuation using the Beer-Lambert law, treating the volume as 3D Gaussians with density and isotropic absorption [S22, unofficial]. The exponential transmittance model is $T(t) = \exp\left(-\int_{t_0}^t \sigma(\mathbf{r}(s)) ds\right)$ [S22, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot T)$ where $N$ is the number of Gaussians and $T$ is the number of tiles/pixels covered. Sorting is $O(N \log N)$ [S14, unofficial].
*   **Memory Complexity:** $O(N)$ for storing Gaussian parameters. High VRAM usage (4GB to view, 12GB to train) due to unbounded growth [S14, unofficial].
*   **Measured Performance:** Real-time rendering (e.g., 129 FPS at Full HD on desktop GPUs) [S10].
*   **Scaling:** Scales well with desktop GPUs but faces memory/bandwidth limits on mobile/AR-VR edge devices [S10].
*   **Strengths:** Real-time rendering, high visual fidelity, differentiable training [S1][S6, unofficial].
*   **Limitations:** High memory usage, large disk size, approximation errors in projection [S14, unofficial][S16].
*   **When to use:** Static scene novel view synthesis, real-time rendering on desktop GPUs.
*   **When not to use:** Resource-constrained devices (mobile/AR-VR) without optimization, scenes requiring complex light transport (shadows/reflections) without extensions.

## Background
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1][S6, unofficial]. It represents a breakthrough in static scene rendering by using explicit 3D Gaussian primitives instead of neural fields, enabling real-time rates with high fidelity [S7]. The method builds on earlier point-based rendering and neural radiance field concepts, offering a differentiable rasterization pipeline that allows for adaptive density control during training [S6, unofficial]. It is widely used as a baseline for AR/VR and desktop GPU rendering [S10].
