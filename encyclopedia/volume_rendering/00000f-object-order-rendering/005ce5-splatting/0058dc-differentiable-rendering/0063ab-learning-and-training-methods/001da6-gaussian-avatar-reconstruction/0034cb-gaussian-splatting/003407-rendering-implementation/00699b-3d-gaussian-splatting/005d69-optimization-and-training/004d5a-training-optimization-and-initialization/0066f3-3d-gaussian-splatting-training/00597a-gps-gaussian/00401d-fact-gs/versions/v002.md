# FaCT-GS
## Overview
FaCT-GS is a framework for fast and flexible Computed Tomography (CT) reconstruction that optimizes the voxelization and rasterization pipelines of 3D Gaussian Splatting [S1]. It solves the problem of slow convergence and high computational cost in Gaussian-based tomographic reconstruction by removing view-dependent occlusion logic, coalescing data structures, and enabling rapid fitting to pre-existing volumes for warm-starting [S1]. It is distinguished from standard 3D Gaussian Splatting by its removal of depth-sorting overhead and its specific adaptation to CT geometry [S1].
## How it works
### Inputs and Outputs
**Inputs:**
*   A set of $N$ X-ray projection images (views) [S1].
*   Camera parameters for each view (pinhole or cone-beam geometry) [S1].
*   Optional: A pre-existing volumetric prior (e.g., from FDK reconstruction) for initialization [S1].

**Outputs:**
*   A set of $M$ 3D Gaussians $\{G_i\}_{i=1}^M$ representing the 3D volume [S1].
*   Each Gaussian $i$ is defined by a center $\mathbf{p}_i$, a covariance matrix $\boldsymbol{\Sigma}_i$, an opacity/weight $G_i$, and other attributes [S1].

### Data Structures
To reduce memory traffic, parameters are coalesced into compact `float4` structs [S1]:
1.  **Voxelizer Struct:** Combines position and radius [S1].
2.  **Rasterizer Struct:** Combines the projected conic (inverse covariance) $\hat{\boldsymbol{\Sigma}}_i^{-1}$ and the integration factor $\mu_i$ [S1].

### Rendering Formula
The projection of a 3D Gaussian onto the 2D detector plane yields a 2D Gaussian [S1]. The intensity $I(\hat{\mathbf{x}})$ at a pixel coordinate $\hat{\mathbf{x}}$ on the detector plane is computed as [S1]:

$$
I(\hat{\mathbf{x}}) = \sum_{i=1}^M G_i^2 \left( \hat{\mathbf{x}} \mid \mu_i \rho_i, \hat{\mathbf{p}}_i, \hat{\boldsymbol{\Sigma}}_i \right)
$$

Where:
*   $M$ is the number of Gaussians [S1].
*   $G_i$ is the Gaussian weight [S1].
*   $\mu_i$ is an integration factor [S1].
*   $\rho_i$ is a scaling factor [S1].
*   $\hat{\mathbf{p}}_i$ is the projected center of the $i$-th Gaussian [S1].
*   $\hat{\boldsymbol{\Sigma}}_i$ is the projected covariance matrix of the $i$-th Gaussian [S1].
*   The term $G_i^2 (\dots)$ represents the 2D Gaussian function evaluated at $\hat{\mathbf{x}}$ with the specified parameters [S1].

### Algorithm Steps
1.  **Initialization:** Initialize the set of 3D Gaussians via gradient-based initialization from an FDK reconstruction or by fitting Gaussians to a pre-existing volumetric prior [S1].
2.  **Voxelization:** Discretize the 3D space into a regular grid and accumulate Gaussian contributions within each voxel to produce a dense volumetric representation [S1]. This avoids mapping Gaussians to a 2D plane but incurs cubic growth in grid elements [S1].
3.  **Projection:** For each view, project the 3D Gaussians onto the 2D detector plane, transforming the 3D covariance $\boldsymbol{\Sigma}_i$ into $\hat{\boldsymbol{\Sigma}}_i$ and the center $\mathbf{p}_i$ into $\hat{\mathbf{p}}_i$ [S1].
4.  **Culling:** For each pixel, identify contributing Gaussians by accumulating contributions only for Gaussians satisfying $|\hat{\mathbf{x}} - \hat{\mathbf{p}}_i| < 3\lambda_{\text{MAX}}(\hat{\boldsymbol{\Sigma}}_i)$, where $\lambda_{\text{MAX}}$ is the largest eigenvalue of the projected covariance $\hat{\boldsymbol{\Sigma}}_i$ [S1].
5.  **Rasterization:** Compute the intensity contribution of each culling-passed Gaussian using the rendering formula [S1]. Unlike standard 3D Gaussian Splatting, do not sort Gaussians by depth or accumulate in a specific order, as the integration order along the ray does not affect the measured signal in CT [S1]. Use the coalesced `float4` structs for memory-efficient access to conics and $\mu$ values [S1].
6.  **Optimization Loop:** Compare the rendered projections with the acquired X-ray images, compute the loss, and update the Gaussian parameters (centers, covariances, weights, etc.) via gradient descent [S1].

### Pseudocode
```python
import math

def mat_mul_2x2(A, B):
    return [[A[0][0]*B[0][0] + A[0][1]*B[1][0], A[0][0]*B[0][1] + A[0][1]*B[1][1]],
            [A[1][0]*B[0][0] + A[1][1]*B[1][0], A[1][0]*B[0][1] + A[1][1]*B[1][1]]]

def mat_inv_2x2(M):
    det = M[0][0] * M[1][1] - M[0][1] * M[1][0]
    return [[M[1][1] / det, -M[0][1] / det], [-M[1][0] / det, M[0][0] / det]]

def mat_det_2x2(M):
    return M[0][0] * M[1][1] - M[0][1] * M[1][0]

def project_3d_to_2d(center_3d, cov_3d, R, t, fx, fy, cx, cy):
    p_cam = [R[0][0]*center_3d[0] + R[0][1]*center_3d[1] + R[0][2]*center_3d[2] + t[0],
             R[1][0]*center_3d[0] + R[1][1]*center_3d[1] + R[1][2]*center_3d[2] + t[1],
             R[2][0]*center_3d[0] + R[2][1]*center_3d[1] + R[2][2]*center_3d[2] + t[2]]
    if p_cam[2] <= 0: return None, None
    p_2d = [(p_cam[0] * fx / p_cam[2]) + cx, (p_cam[1] * fy / p_cam[2]) + cy]
    J = [[fx / p_cam[2], 0, -(p_cam[0] * fx) / (p_cam[2]**2)],
         [0, fy / p_cam[2], -(p_cam[1] * fy) / (p_cam[2]**2)]]
    cov_3d_2 = [row[:2] for row in cov_3d]
    cov_2d = mat_mul_2x2(J, mat_mul_2x2(cov_3d_2, [[row[0] for row in J] for _ in range(2)]))
    return p_2d, cov_2d

def evaluate_2d_gaussian(x, y, mu, rho, p_2d, cov_2d):
    diff_x = x - p_2d[0]
    diff_y = y - p_2d[1]
    inv_cov = mat_inv_2x2(cov_2d)
    exponent = -0.5 * (diff_x * inv_cov[0][0] * diff_x + diff_x * inv_cov[0][1] * diff_y +
                       diff_y * inv_cov[1][0] * diff_x + diff_y * inv_cov[1][1] * diff_y)
    norm_const = 1.0 / (2.0 * math.pi * math.sqrt(mat_det_2x2(cov_2d)))
    return (mu * rho) * norm_const * math.exp(exponent)

def render_fact_gs(projections, gaussians, camera_params):
    rendered_images = []
    for view_idx, target in enumerate(projections):
        h, w = target.shape
        image = [[0.0] * w for _ in range(h)]
        R, t, fx, fy, cx, cy = camera_params[view_idx]
        for g in gaussians:
            p_2d, cov_2d = project_3d_to_2d(g.center, g.cov, R, t, fx, fy, cx, cy)
            if p_2d is None: continue
            tr = cov_2d[0][0] + cov_2d[1][1]
            det = mat_det_2x2(cov_2d)
            disc = math.sqrt(max(0, tr**2 - 4 * det))
            lambda_max = (tr + disc) / 2.0
            radius = 3.0 * lambda_max
            min_x = max(0, int(p_2d[0] - radius))
            max_x = min(w, int(p_2d[0] + radius) + 1)
            min_y = max(0, int(p_2d[1] - radius))
            max_y = min(h, int(p_2d[1] + radius) + 1)
            for y in range(min_y, max_y):
                for x in range(min_x, max_x):
                    dist = math.sqrt((x - p_2d[0])**2 + (y - p_2d[1])**2)
                    if dist < radius:
                        pdf = evaluate_2d_gaussian(x, y, g.mu, g.rho, p_2d, cov_2d)
                        image[y][x] += (g.weight ** 2) * pdf
        rendered_images.append(image)
    return rendered_images
```

### Parameters
*   **Culling Threshold:** $3\lambda_{\text{MAX}}$ [S1].
*   **Execution Time:** Approximately 2 minutes per scan on 75 projections of $512^2$ size; competitive results after 45 seconds [S1].
*   **Scalability:** Generates high-quality reconstructions in about 1 minute for 1k projections and 4 minutes for 2k projections [S1].

### Edge Cases and Pitfalls
*   **Occlusion Logic:** Standard 3D Gaussian Splatting accumulates splat contributions in a specific order to model view-dependent occlusion [S1]. In CT, integration order along the ray has no effect on the measured signal [S1]. Removing this ordering logic is critical to avoid unnecessary overhead [S1].
*   **Memory Traffic:** Failure to coalesce function parameters into compact `float4` structs (combining position/radius in voxelizer, conics/$\mu$ in rasterizer) leads to higher memory traffic and reduced performance [S1].
*   **Voxelization Cost:** Voxelization is computationally expensive due to the cubic growth in the number of grid elements [S1]. Care must be taken with grid resolution [S1].

## Operating characteristics
*   **Time Complexity:** Significantly faster than State of the Art GS CT reconstruction [S1]. Over 4x faster on standard $512^2$ projections and over 13x faster on 2k projections [S1].
*   **Memory Complexity:** Reduced by coalescing parameters into `float4` structs [S1]. Voxelization incurs cubic growth in grid elements [S1].
*   **Scalability:** Scales well with projection and output volume size [S1].
*   **Strengths:** Fast execution, flexible initialization (including warm-starting from pre-existing volumes), and compression properties comparable to 2D JPEG stacks [S1].
*   **Limitations:** Voxelization can be computationally expensive for high-resolution grids [S1].
*   **When to use:** Sparse-view tomography, fast CT reconstruction, scenarios requiring warm-starting from prior volumes [S1].
*   **When not to use:** Standard 3D rendering with view-dependent occlusion is required [S1].

## Background
FaCT-GS was introduced to address the limitations of Gaussian Splatting-based CT reconstruction, specifically the slow convergence and high computational cost [S1]. It builds on the observation that projecting a 3D Gaussian yields a 2D Gaussian, allowing for simplified rendering equations [S1]. The method was developed to enable rapid fitting of Gaussians to pre-existing volumes, serving as a prior for warm-starting or as a compressed representation [S1]. It is related to R2-Gaussian, which also highlighted the irrelevance of integration order in CT, but FaCT-GS fully removes the ordering logic from the pipeline [S1].
