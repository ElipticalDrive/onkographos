# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, GSGEN Implementation Details, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific implementation parameters, optimization strategies, and variant algorithms required to train and render 3D Gaussian Splatting (3DGS) scenes effectively. It addresses the gap between the theoretical differentiable rasterization core [6233-optimization-and-parallelization] and practical deployment, covering densification schedules, precision handling, and specialized variants for specific constraints such as sparse views, large-scale scenes, and inverse rendering. It sets itself apart from general optimization theory by providing concrete hyperparameters, data layouts, and algorithmic steps for specific implementations like `gsplat`, Denoise-GS, and LS-Gaussian.

## How it works

### Inputs and Outputs
*   **Inputs**: Structure-from-Motion (SfM) point cloud (positions, colors), camera poses (extrinsics $C_i$ and intrinsics $K_i$), and training images.
*   **Outputs**: A set of 3D Gaussian primitives parameterized by position $\mu$, covariance $\Sigma$ (or scale $s$ and rotation $R$), opacity $\alpha$, and spherical harmonic (SH) coefficients $c_{lm}$.

### Data Structures and Layouts
The Gaussian representation is stored as a flat list or structured array. Common layouts include:
*   **Position**: 3 floats ($x, y, z$).
*   **Scale**: 3 floats (log-scale or direct).
*   **Rotation**: 4 floats (quaternion $w, x, y, z$).
*   **Opacity**: 1 float.
*   **Color**: $N_{SH} \times 3$ floats, where $N_{SH} = (d+1)^2$ for degree $d$.
*   **Quantized Layout (e.g., [S16, unofficial])**: Position (FP16), Scales (FP16), Opacity (INT8), SH coefficients (INT8 or codebook-based).

### Training Optimization and Initialization

#### Standard Densification Schedule
The standard 3DGS training loop uses adaptive density control to split and clone Gaussians based on positional gradients [S1, S4].

1.  **Initialization**: Initialize Gaussians from the SfM point cloud.
2.  **Iteration Loop**:
    *   Render a random training image using differentiable rasterization.
    *   Compute loss $\mathcal{L}$ (typically $\mathcal{L}_{L1} + \mathcal{L}_{SSIM}$) and backpropagate to get positional gradients $\nabla_{\mu}$.
    *   **Densification Check**: Every $K_{dens}$ iterations:
        *   **Split**: If accumulated gradient magnitude $> T_{split}$ and scale is small, split the Gaussian into two.
        *   **Clone**: If accumulated gradient magnitude $> T_{clone}$ and scale is large, clone the Gaussian.
        *   **Pruning**: Remove Gaussians with opacity $< \alpha_{min}$ or excessive radius.
3.  **Optimizer Update**: Update parameters using Adam.

**Parameters**:
*   $T_{split}$: Gradient threshold for splitting. Default varies; [S1] uses a view-space position gradient threshold $T_{pos} = 0.02$.
*   $T_{clone}$: Gradient threshold for cloning.
*   $\alpha_{min}$: Opacity threshold for pruning. Default $0.05$ [S1].
*   $K_{dens}$: Interval for densification. Default 100 iterations [S1, S4]. [S1] performs compactness-based densification every 1000 iterations.
*   Pruning Interval: Every 200 iterations [S1].

#### Corrected Scene Extent
The default scene extent $e_{scene}$ in 3DGS is calculated based on camera positions, which biases optimization if cameras are clustered (e.g., orbiting a small object) [S4]. A corrected extent $e'_{scene}$ uses the SfM point cloud:

$$ \bar{C} = \frac{1}{N_{\text{cam}}} \sum_{i=1}^{N_{\text{cam}}} C_i $$

$$ e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2 $$

where $N_{\text{cam}}$ is the number of cameras, $C_i$ is the $i$-th camera position, $N_{\text{SfM}}$ is the number of SfM points, and $p_i$ is the $i$-th SfM point [S4].

#### Half-Precision Rasterization
To reduce register pressure and memory bandwidth, implementations like `gsplat` use half-precision (FP16) for feature vectors during rasterization [S2].
*   **Forward/Backward Kernels**: Use tiny-cuda-nn's JIT-compiled cooperative vector MLPs trained in FP16 [S2].
*   **Stability**: Apply an automatic scaling factor to loss values to improve half-precision training stability [S2].

#### Optimizer Configuration
*   **Optimizer**: Adam [S3].
*   **Learning Rate**: $1 \times 10^{-3}$ for position/rotation/scale, often with different rates for SH coefficients [S3].
*   **Supervision**: Randomly select a single image from a random scene as supervision for each iteration [S3].

### Variant Algorithms

#### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ to model spatially varying blur [S5].
1.  Predict $\delta s_j$ for each Gaussian $j$ using a compact MLP.
2.  Add offset to base scale to transform covariance.
3.  Project transformed covariance to 2D space.
4.  Use as pixel-wise blur kernel during rasterization.
*   **Pitfall**: If $\delta s_j$ is constant, it degrades to uniform Gaussian blur [S5].

#### Denoise-GS (Sparse/Noisy Views)
A two-round self-supervised denoising method [S6].
1.  **Round 1**: Train a UNet using Noise2Void (N2V) for denoising. Process denoised images through InstantSplat to initialize/train/render 3DGS.
2.  **Filtering**: Group and filter rendered results by viewpoint for stability.
3.  **Round 2**: Fine-tune UNet using composite loss (low-frequency + perceptual detail). Render again on selected viewpoints.

#### Multi-Scale Constraint
Applies position-aware adaptive control for large-scale scenes [S7].
*   **Gamma Function**:
    $$ \gamma(\mu) = \begin{cases} 1 & \text{if } \|\mu - c\|^2 < 2r \\ \|\mu - c\|^2 / r - 1 & \text{if } \|\mu - c\|^2 \ge 2r \end{cases} $$
    where $r$ is scene radius, $c$ is camera center.
*   **Operations**:
    *   Clone if $\max(s) < g \cdot \gamma(\mu)$.
    *   Split if $\max(s) \ge g \cdot \gamma(\mu)$.
    *   Eliminate if $\max(s) > b \cdot \gamma(\mu)$.
    *   $g, b$ are scale threshold parameters.

#### LS-Gaussian Viewpoint Transformation
Leverages inter-frame continuity for sparse rendering [S8].
*   Transforms viewpoint between consecutive frames instead of rendering each separately.
*   **Pitfall**: Quality degrades with accumulated interpolation errors over many transformed frames.
*   **Usage**: Fully render 1 frame every 6 frames on edge devices like Jetson AGX Orin.

#### Camera Localisation for Convergence Basin
Localizes camera pose by minimizing photometric error against ground truth [S9, unofficial].
1.  Fix $G_{init}$.
2.  Initialize $T_{CW}$ at test view position.
3.  Optimize for 1000 iterations.
4.  Success if pose converges within 1cm of target.
    $$ \mathbf{T}_{CW}^{est} = \underset{\mathbf{T}_{CW}}{\arg \min} \left\| I(\mathcal{G}_{init}, \mathbf{T}_{CW}) - \bar{I}_{target} \right\|_1 $$

#### DiffGS Framework
Optimizes Gaussians to exact locations using a Gaussian Probability Function (GauPF) [S10].
*   **Parameters**: Truncation function $\lambda$, Projection function $\tau(x) = e^{-x}$ or linear.
*   **Performance**: 50K Gaussians: PSNR 28.61, SSIM 0.9787, LPIPS 0.0251. 100K: PSNR 30.35, SSIM 0.9838, LPIPS 0.0151. 350K: PSNR 34.01, SSIM 0.9879, LPIPS 0.0149.

#### Conditional Splat Approximation
Approximates 3D Gaussian influence on a slice using a 2D ellipse splat scaled by marginal factor [S12, unofficial]. Qualitative validation shows close overlap with true iso-probability contours.

#### PyGS Optimization
Uses combined MSE and SSIM loss with multi-scale structure [S13, unofficial].
*   **Loss**: $\mathcal{L} = \lambda \cdot \text{MSE}(C, \hat{C}) + (1 - \lambda) \cdot \text{SSIM}(C, \hat{C})$.
*   **Strategy**: Split/cloned Gaussians remain in original level/cluster. Routinely reassess levels based on scales.

#### GAINS (Inverse Rendering)
Two-stage inverse rendering from sparse views (4-32) [S14].
*   **Stage I**: Optimize geometry using monocular depth, normal, and diffusion priors.
*   **Stage II**: Jointly optimize material and lighting using segmentation, IID, and diffusion priors.
*   **Note**: Uses 2DGS for better geometry reconstruction.

#### GraphiGS
Models component distribution $\delta_\theta$ as a 3D Gaussian primitive [S18].
$$ \delta_{GS}(x; \mu, \Sigma) = \exp\left(-\frac{1}{2} (x - \mu)^T \Sigma^{-1} (x - \mu)\right) $$
*   $\mu \in \mathbb{R}^3$, $\Sigma \in \mathbb{R}^{3 \times 3}$.
*   Provides compact spatial support but may be limited in capturing broader uncertainty regions compared to heavy-tailed distributions.

#### Opacity Offset Table for DSA
Constructs an opacity offset table to model changes in digital subtraction angiography [S11].

#### SAGS, FreGS, SASCGS
*   **SAGS**: Adaptive 2D low-pass filter at inference based on resolution/distance [S15, unofficial].
*   **FreGS**: Frequency-domain regularization to recover high-frequency detail [S15, unofficial].
*   **SASCGS**: Vector clustering to encode color/geometry attributes [S15, unofficial].

#### 3DGS Quantization Compression
Reduces storage by quantizing attributes [S16, unofficial].
*   **Layout**: Position (FP16), Scales (FP16), Opacity (INT8), SH (INT8/codebook).
*   **Result**: ~10x smaller size without significant quality loss.

#### Neural Illumination Enhancement (NIE)
Applies a neural module only to non-Lambertian regions to model view-dependent highlights and global illumination caching [S17, unofficial].

## Operating characteristics

### Time and Memory Complexity
*   **Memory**: Standard 3DGS scales linearly with the number of Gaussians $N$. Each Gaussian stores position (12B), scale (12B), rotation (16B), opacity (4B), and SH coefficients ($12 \times (d+1)^2$ B). For $N=10^6$ and degree 3, this exceeds 1GB [12927-compact-3d-gaussian-representation-c3dgs.md].
*   **Time**: Rasterization is $O(N \cdot P)$ where $P$ is pixels, but optimized via tile-based sorting and culling. Training time is dominated by densification steps and backpropagation.

### Measured Performance
*   **Half-Precision**: Using FP16 for feature vectors reduces register pressure and improves throughput [S2].
*   **Compression**: Quantization (INT8 for opacity/SH) achieves ~10x size reduction with minimal quality loss [S16, unofficial].
*   **Acceleration**: LS-Gaussian achieves 5.41x speedup on Jetson AGX Orin via sparse rendering [S8].

### Strengths and Limitations
*   **Strengths**: Real-time rendering, high fidelity, explicit representation allows easy editing.
*   **Limitations**: High memory usage for large scenes, sensitivity to initialization, potential for "floaters" in unobserved regions.

### When to Use
*   Use standard implementation for general novel view synthesis with dense views.
*   Use variants like Denoise-GS for sparse/noisy views, or CLM for memory-constrained hardware.

## Background

### Origin
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1, S2]. It builds on the concept of differentiable rasterization of 3D Gaussians, adapting techniques from point-based rendering and neural radiance fields.

### History and Development
Since its introduction, numerous variants have been developed to address specific limitations, including compression [S16, unofficial], inverse rendering [S14], dynamic scenes [S1, S11], and large-scale environments [S7][S13, unofficial]. The `gsplat` library [S3] and other implementations have standardized the CUDA kernel approach for efficiency [S2].
