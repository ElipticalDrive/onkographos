# Mesh Extraction via Poisson Reconstruction

Also called: Poisson Mesh Extraction, Poisson Surface Reconstruction

## Overview
This method extracts a textured triangular mesh from an optimized 3D Gaussian Splatting (3DGS) scene by converting rendered 2D depth and normal maps into a 3D oriented point cloud, which is then processed by a Poisson surface reconstruction algorithm [S1][S2, unofficial]. It differs from direct meshing approaches like Gaussian Opacity Fields (GOF) [3692-gaussian-opacity-fields-gof-mesh-extraction.md] or distance-based methods [7411-distance-based-gaussian-splatting.md] by relying on post-processing rendered geometric cues rather than modifying the core Gaussian representation or optimizing a signed distance field [S1][S2, unofficial].

## How it works
**Inputs:** Optimized 3D Gaussian scene $\mathcal{G} = \{G_i\}_{i=1}^M$; camera poses and intrinsics for training views.
**Outputs:** Textured triangular mesh.

**Data Structures:**
*   **Gaussian Primitive $G_i$:** Contains 3D position $\mathbf{p}_i$, 3D covariance matrix $\mathbf{\Sigma}_i$ (or rotation $\mathbf{R}_i$ and scale $\mathbf{s}_i$), spherical harmonic coefficients for color, and opacity $\alpha_i$.
*   **Rendered Depth Map $D$:** 2D array where each pixel stores the median depth of splats covering that pixel.
*   **Rendered Normal Map $N$:** 2D array where each pixel stores the surface normal vector.
*   **Oriented Point Cloud $P$:** List of points $\{(\mathbf{x}_k, \mathbf{n}_k, \mathbf{c}_k)\}$, where $\mathbf{x}_k$ is 3D position, $\mathbf{n}_k$ is normal, and $\mathbf{c}_k$ is color.

**Steps:**

1.  **Render Depth and Normal Maps:**
    For each training view $v$:
    a. Project all Gaussians to 2D screen space. The projected 2D covariance $\mathbf{\hat{\Sigma}}_i$ is computed using the Jacobian $J$ of the affine approximation of the projection and the rotation part $W$ of the extrinsic matrix:
    $$ \mathbf{\hat{\Sigma}}_i = J W \mathbf{\Sigma}_i W^T J^T $$
    [4971-radiative-and-tomographic-gaussians.md]
    b. Render the depth map $D_v$ by accumulating splats and storing the **median** depth value for each pixel [S2, unofficial].
    c. Render or derive the normal map $N_v$. Sources indicate deriving normals from the depth map or using pre-trained models (e.g., Omnidata) to provide monocular normal cues [S1][S2, unofficial].

2.  **Back-Projection to 3D:**
    For each pixel $(u, v)$ in the depth map $D_v$ with depth $d$ and normal $\mathbf{n}_{uv}$:
    a. Convert pixel coordinates and depth to 3D world coordinates $\mathbf{x}$ using the camera projection matrix inverse.
    b. Assign the color $\mathbf{c}_{uv}$ from the rendered RGB image.
    c. Transform the normal $\mathbf{n}_{uv}$ from camera space to world space.
    d. Add $(\mathbf{x}, \mathbf{n}, \mathbf{c})$ to the oriented point cloud $P$.

3.  **Poisson Surface Reconstruction:**
    Input the oriented point cloud $P$ into the Poisson reconstruction algorithm [S1][S2, unofficial].
    a. The algorithm solves for a scalar function $f$ such that $\nabla f \approx \mathbf{n}$ in a least-squares sense.
    b. The mesh is extracted as the zero-level set of $f$.
    c. **Parameters:**
        *   Depth level (octree depth): 9 [S1].
        *   Target number of points: 2 million [S1].

**Edge Cases and Pitfalls:**
*   **Median Depth:** Using mean depth can cause artifacts in transparent or multi-layered regions; median is preferred for geometric accuracy [S2, unofficial].
*   **Normal Consistency:** Inconsistent normals from different views can lead to holes or artifacts in the reconstructed mesh. Regularization during training (e.g., depth and normal priors) helps align Gaussian positions [S1].
*   **Initialization:** Using 1M back-projected sensor depth points for initialization improves geometric accuracy compared to sparse COLMAP SfM initialization [S1].

## Subtopics

### Screened Poisson Equation Framework
A framework introduced by Mechrez et al. [78] that effectively preserves structural fidelity while achieving stylization [S3]. It modifies the standard Poisson equation to include a screening term, allowing for better handling of stylized content while maintaining the underlying geometric structure [S3].

## Operating characteristics
*   **Time Complexity:** Dominated by the rendering of depth/normal maps ($O(M \cdot N_{views} \cdot N_{pixels})$) and the Poisson reconstruction ($O(N_{points})$).
*   **Memory Complexity:** Requires storing the point cloud ($O(N_{points})$) and intermediate render buffers.
*   **Performance:** On a single NVIDIA GeForce RTX 4090 GPU, mesh extraction is efficient post-training [S2, unofficial].
*   **Strengths:** Produces high-quality, watertight meshes with texture; leverages existing 3DGS rendering pipeline [S1][S2, unofficial].
*   **Limitations:** Relies on the quality of rendered depth/normal maps; may struggle with highly transparent or thin structures if not regularized [S1].

## Background
Originating from the broader field of surface reconstruction from point clouds, Poisson surface reconstruction was introduced by Kazhdan et al. [18]. In the context of 3DGS, it is used as a post-processing step to extract meshes from optimized Gaussian scenes [S1][S2, unofficial]. The method benefits from the dense and well-distributed Gaussian points achieved through regularization strategies [S1].
