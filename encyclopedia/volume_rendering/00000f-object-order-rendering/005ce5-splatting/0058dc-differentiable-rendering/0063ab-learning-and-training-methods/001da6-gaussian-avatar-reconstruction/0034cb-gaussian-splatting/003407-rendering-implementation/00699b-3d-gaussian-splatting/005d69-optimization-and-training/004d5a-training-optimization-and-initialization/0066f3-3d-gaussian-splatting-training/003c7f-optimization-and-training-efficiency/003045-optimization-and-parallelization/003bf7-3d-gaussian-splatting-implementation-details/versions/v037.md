# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific implementation strategies, hyperparameters, and optimization variants required to train and render 3D Gaussian Splatting (3DGS) effectively in diverse scenarios. While the parent article [Optimization and Parallelization](6233-optimization-and-parallelization.md) covers the general differentiable rasterization pipeline, this article provides the concrete parameters for solvers, memory management techniques (such as half-precision fetches), and specialized variants for handling scene extent bias, defocus blur, sparse/noisy views, underwater environments, and hardware acceleration. It serves as the practical reference for implementing the core algorithm and its notable extensions.

## How it works

### Core Training Configuration
The standard training process relies on a differentiable rasterizer that renders images from a set of 3D Gaussians. The core optimization mechanism involves computing the gradient of a loss function $\mathcal{L}$ with respect to the Gaussian parameters (position, covariance, opacity, color, SH coefficients) [S2].

**Inputs and Outputs:**
*   **Input:** A set of posed images $\{I_k\}_{k=1}^K$ and an initial point cloud (e.g., from SfM).
*   **Output:** A set of 3D Gaussians $\Theta$ parameterized by mean $\mu$, covariance $\Sigma$, opacity $\alpha$, spherical harmonics coefficients $\mathbf{c}$, and scale $\mathbf{s}$.

**Data Structures:**
*   **Gaussian List:** A dynamic array of Gaussian primitives. Each Gaussian stores:
    *   Position $\mu \in \mathbb{R}^3$
    *   Rotation $q \in \mathbb{R}^4$ (quaternion)
    *   Scale $\mathbf{s} \in \mathbb{R}^3$
    *   Opacity $\alpha \in [0, 1]$
    *   Color coefficients $\mathbf{c}$ (Spherical Harmonics)
*   **Volume Grid (Optional):** For large-scale or specific implementations (e.g., EVolSplat), a 3D sparse voxel grid is used to partition the scene [S2].
    *   **Dimensions:** Defined by bounding box and voxel size. Example: Height 12.8m, Width 32m, Length 64m with voxel size 0.1m results in a $128 \times 320 \times 640$ volume [S2].

**Optimization Steps:**
1.  **Initialization:** Initialize Gaussians from SfM points. Apply **Corrected Scene-Extent** to avoid bias from camera distribution [S3].
2.  **Iteration Loop:**
    a.  **Random Selection:** Randomly select a single image from the training set as supervision for the current iteration [S2].
    b.  **Rasterization:** Render the selected image using the current Gaussian set $\Theta$. This involves projecting 3D Gaussians to 2D, sorting them by depth, and alpha-blending [S2].
    c.  **Loss Computation:** Compute the loss $\mathcal{L}$ between the rendered image $I^r$ and the ground truth $I^{gt}$. The standard loss is:
        $$ \mathcal{L} = \sum_{k=1}^K (1 - \lambda_1) \| I_k^{gt} - I_k^r(\Theta) \|_{\ell_1} + \lambda_1 L_{D-SSIM}(I_k^{gt}, I_k^r(\Theta)) $$
        where $\lambda_1 \in [0,1]$ is a user-defined weight [S6].
    d.  **Backpropagation:** Compute gradients $\nabla_\Theta \mathcal{L}$ using the differentiable rasterizer.
    e.  **Parameter Update:** Update $\Theta$ using an optimizer (typically Adam) [S2].
    f.  **Densification/Pruning:** Based on gradient thresholds and scale constraints, clone, split, or prune Gaussians [S3, S7].

**Pseudocode for Standard Training Loop:**

```python
# Initialization
G = InitializeFromSfM(points)
optimizer = Adam(params=G.parameters(), lr=1e-3) # [S2]
SH_degree = 1 # [S2]

for t in range(num_iterations):
    # 1. Random Image Selection [S2]
    image_idx = random.choice(range(K))
    gt_image = images[image_idx]
    
    # 2. Forward Pass: Rasterization
    # Uses gsplat library with custom CUDA kernels [S1]
    # Half-precision memory fetches for feature vectors to reduce register pressure [S1]
    rendered_image = rasterize(G, camera_poses[image_idx], SH_degree)
    
    # 3. Loss Computation
    # Automatic scaling factor applied to loss for FP16 stability [S1]
    loss = compute_loss(rendered_image, gt_image)
    
    # 4. Backward Pass
    optimizer.zero_grad()
    loss.backward()
    
    # 5. Optimization Step
    optimizer.step()
    
    # 6. Densification and Pruning (Conditional)
    # Apply Corrected Scene Extent [S3] and Multi-Scale Constraints [S7]
    G = densify_and_prune(G, gradients=optimizer.param_groups[0]['grads'], t=t)
```

**Parameters:**
*   **Optimizer:** Adam [S2].
*   **Learning Rate:** $1 \times 10^{-3}$ [S2].
*   **SH Degree:** 1 (for simplicity and performance) [S2].
*   **Loss Weights:** $\lambda_1$ for SSIM term [S6].

### Variant: Corrected Scene-Extent
Standard 3DGS calculates scene extent $e_{\text{scene}}$ based on camera positions, which biases densification if cameras are clustered (e.g., orbiting a small object) [S3]. The corrected extent $e'_{\text{scene}}$ uses the SfM point cloud [S3].

**Formula:**
$$ \bar{C} = \frac{1}{N_{\text{cam}}} \sum_{i=1}^{N_{\text{cam}}} C_i $$
$$ e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2 $$
where $\bar{C}$ is the average camera position, $N_{\text{cam}}$ is the number of cameras, $N_{\text{SfM}}$ is the number of SfM points, and $p_i$ is the i-th SfM point [S3].

### Variant: Selective Defocus Blurring
To handle spatially varying blur, a compact MLP predicts a per-Gaussian scale offset $\delta s_j$ [S4].

**Steps:**
1.  Predict $\delta s_j$ for each Gaussian $j$ using the MLP.
2.  Add $\delta s_j$ to the base scale to transform the covariance $\Sigma_j$.
3.  Project the transformed covariance to 2D space.
4.  Use the transformed 2D covariance as a pixel-wise blur kernel during rasterization [S4].

**Pitfall:** If $\delta s_j$ is constant for all Gaussians, the method degrades to a uniform Gaussian blur, failing to model spatially varying blurriness [S4].

### Variant: Denoise-GS (Sparse/Noisy Views)
A self-supervised method combining Noise2Void (N2V) with 3DGS to handle sparse views and non-Gaussian noise [S5].

**Steps:**
1.  **Round 1:** Train a UNet using Noise2Void (N2V) on noisy input images. N2V requires no paired clean data, making it suitable for sparse viewpoints where only one image per view exists [S5].
2.  **Round 1:** Process denoised images through InstantSplat to initialize and train 3DGS.
3.  **Round 1:** Group and filter rendered results by viewpoint to ensure representativeness.
4.  **Round 2:** Fine-tune the UNet using a composite loss balancing low-frequency consistency and perceptual detail consistency.
5.  **Round 2:** Render again on selected viewpoints to generate denoised views [S5].

### Variant: Underwater 3D Gaussian Splatting (Gaussian Splashing)
Adapts 3DGS for underwater scenes by learning direct attenuation $B_d$, infinite backscatter $B_\infty$, and backscatter coefficient $B_b$ [S6].

**Rendering Formula:**
$$ C^{uw} = \sum_{i=1}^M c_i \alpha_i T_i e^{-B_d z} + B_\infty (1 - e^{-B_b z}) $$
where $T_i = \prod_{j=0}^{i-1} (1 - \alpha_j)$ is the transmittance, and $z$ is the depth [S6].

**Backscatter Estimation Steps:**
1.  Divide the depth map (from current scene estimate) into 10 evenly-spaced clusters from $\min(z)$ to $\max(z)$ [S6].
2.  Within each cluster, identify pixels in the ground-truth image whose RGB triplets are below the bottom 1st percentile. These serve as an overestimate of backscatter $B_s$ [S6].
3.  Use nonlinear least squares fitting on pairs $(B_s, z)$ to estimate $B_\infty$ and $B_b$ [S6].
4.  Re-estimate $B_\infty$ and $B_b$ every 500 optimization steps [S6].

**Depth Extraction:**
$$ z = \frac{\sum_{i=1}^M d_i \alpha_i T_i}{\sum_{i=1}^M \alpha_i T_i} $$
where $d_i$ is the depth of Gaussian $i$ [S6].

**Pitfall:** The camera sensor must have a linear response to light. In-camera processed .jpg images or gamma-corrected images cannot be used unless non-linearities are reversed [S6].

**Parameter Bounds:** $B_\infty \in [0, 1]$, $B_b \in [0, 5]$ [S6].

### Variant: Multi-Scale Constraint
Improves rendering of distant objects by applying different scales to Gaussians based on viewer distance [S7].

**Formula:**
$$ \gamma(\mu) = \begin{cases} 1 & \text{if } \|\mu - c\|^2 < 2r \\ \frac{\|\mu - c\|^2}{r} - 1 & \text{if } \|\mu - c\|^2 \ge 2r \end{cases} $$
where $r$ is the scene radius and $c$ is the center of cameras [S7].

**Steps:**
1.  If $\max(s) < g \cdot \gamma(\mu)$, perform cloning operation on the Gaussian ellipsoid.
2.  If $\max(s) \ge g \cdot \gamma(\mu)$, execute splitting procedure.
3.  Eliminate Gaussian ellipsoids where $\max(s) > b \cdot \gamma(\mu)$.
where $g$ and $b$ are scale threshold parameters [S7].

### Variant: QuickSplat Optimization
Uses learned networks for initialization, densification, and parameter updates to accelerate surface reconstruction [S8].

**Pseudocode:**
```python
G0 = fI(P) # Initialize Gaussians from SfM points P using initializer network fI
for t = 0 to T - 1:
    grad_accum = 0
    for all images:
        L = rendering_loss(image)
        delta_G = gradient(L)
        grad_accum += delta_G
    
    # Generate new Gaussians using densifier network fD
    G_new = fD(Gt, grad_accum, t)
    G_t_plus_1 = Gt union G_new
    
    # Update parameters using optimizer network fO
    delta_G_update = fO(G_t_plus_1, grad_accum, t)
    Gt_plus_1 = G_t_plus_1 + delta_G_update
```

### Variant: LS-Gaussian (Sparse Rendering & Accelerator)
Optimizes for real-time rendering on edge devices (e.g., Jetson AGX Orin) by leveraging inter-frame continuity [S9].

**Algorithm:**
1.  **Viewpoint Transformation:** Instead of rendering each frame separately, transform the viewpoint between consecutive frames. Only one frame in every 6 frames is fully rendered [S9].
2.  **Workload Prediction:** Predict the workload for each tile based on viewpoint transformation to enable balanced parallel computation [S9].
3.  **Accelerator Architecture:** Co-design a hardware architecture with a streaming pipeline that allows continuous processing across hardware modules without global synchronization [S9].

**Pitfall:** Rendering quality degrades noticeably as the number of consecutively transformed frames increases due to the accumulation of interpolation errors [S9].

## Subtopics

### [Continuous Attenuation Model for 3D Gaussian Splatting](9624-continuous-attenuation-model-for-3d-gaussian-splatting.md)
Reformulates rasterization into a volumetric ray-marching framework by mapping Gaussians to a continuous attenuation field $\sigma(\mathbf{x}, \mathbf{w})$. This ensures transmittance isosurfaces remain unbiased and ellipsoidal, preventing surface erosion and multi-view inconsistency seen in prior approximations like GGGS [9624-continuous-attenuation-model-for-3d-gaussian-splatting.md].

### [Sorting and Rendering Pipeline Optimization](12180-sorting-and-rendering-pipeline-optimization.md)
Addresses computational bottlenecks in sorting and attribute fetching. It maps software strategies to hardware constraints (e.g., Roofline model) or replaces standard sorting with hardware-friendly, comparison-free logic and sorting-free approximations [12180-sorting-and-rendering-pipeline-optimization.md].

### [LangSplat Training Procedure](12438-langsplat-training-procedure.md)
Extends the standard pipeline to incorporate semantic language features (e.g., CLIP) alongside photometric rendering. It disables densification and pruning during language-aware training to maintain semantic consistency [12438-langsplat-training-procedure.md].

### [Gaussian Representation and Truncation](12855-gaussian-representation-and-truncation.md)
Modifies the definition, spatial extent, or lifecycle of 3D Gaussians. Includes alternative kernel shapes, opacity-independent culling, and voxel-based constraints to improve fidelity and efficiency [12855-gaussian-representation-and-truncation.md].

### [DeSplat](12925-desplat.md)
Decomposes the scene into static scene Gaussians ($G_s$) and per-view distractor Gaussians ($G_d$) to handle transient occluders (e.g., pedestrians) without external semantic models [12925-desplat.md].

### [360 Gaussian Splatting](12929-360-gaussian-splatting.md)
Modifies the differentiable rasterizer to support spherical rendering and uses OpenSfM (which supports equirectangular inputs) to process 360-degree camera images directly [12929-360-gaussian-splatting.md].

### [Data Compression and Storage Optimization](12943-data-compression-and-storage-optimization.md)
Reduces the memory footprint of 3DGS by compressing numerical representations, clustering parameters into codebooks, or replacing explicit attributes with neural fields [12943-data-compression-and-storage-optimization.md].

### [Bézier-boundary gradient approximation](13137-b-zier-boundary-gradient-approximation.md)
Approximates gradients of discontinuous indicator functions with respect to Bézier curve control points, enabling backpropagation in discontinuity-aware rendering [13137-b-zier-boundary-gradient-approximation.md].

### [Discontinuity-aware Gaussian Splatting](13138-discontinuity-aware-gaussian-splatting.md)
Introduces "pre-scissoring" to segment projected Gaussians along boundaries defined by cubic Bézier curves, allowing the representation of sharp boundaries and discontinuities [13138-discontinuity-aware-gaussian-splatting.md].

### [SOGS (Second-Order Anchor for Advanced 3D Gaussian Splatting)](13171-sogs-second-order-anchor-for-advanced-3d-gaussian-splatting.md)
Uses covariance-based feature augmentation to capture co-variation patterns, allowing for smaller feature vectors and reduced model size compared to standard anchor methods [13171-sogs-second-order-anchor-for-advanced-3d-gaussian-splatting.md].

### [Underwater 3D Gaussian Splatting with Backscatter Loss](13980-underwater-3d-gaussian-splatting-with-backscatter-loss.md)
Adapts 3DGS for underwater environments by learning direct attenuation and backscatter parameters, using an alternating optimization strategy to refine depth and medium parameters simultaneously [13980-underwater-3d-gaussian-splatting-with-backscatter-loss.md].

### [Error-Driven 2D Gaussian Training](13985-error-driven-2d-gaussian-training.md)
Performs densification in 2D image space using a differentiable rasterizer, then back-projects to 3D to initialize new 3D Gaussians, improving specular radiance reconstruction [13985-error-driven-2d-gaussian-training.md].

### [Mesh Extraction and Representation](14095-mesh-extraction-and-representation.md)
Converts the volumetric 3DGS representation into explicit triangular meshes or point clouds for compatibility with standard 3D graphics pipelines [14095-mesh-extraction-and-representation.md].

### [TraGraph-GS](14454-tragraph-gs.md)
Employs graph-based adaptive spatial partitioning and regularization constraints to handle large-scale scenes and textureless regions, decoupling the scene into local regions and a coarse global representation [14454-tragraph-gs.md].

### [Explicit 4D Gaussian Splatting](14584-explicit-4d-gaussian-splatting.md)
Achieves memory efficiency in dynamic scenes by separating Gaussians into static and dynamic categories and explicitly sampling positions/rotations at sparse timestamps [14584-explicit-4d-gaussian-splatting.md].

### [Color and Appearance Modeling](14740-color-and-appearance-modeling.md)
Extends the radiance representation to handle complex lighting and view-dependent effects by decoupling geometry from lighting or using image-specific conditions [14740-color-and-appearance-modeling.md].

### [GS-IR](14852-gs-ir.md)
An inverse rendering approach using forward mapping volume rendering to estimate scene geometry, surface material, and environment illumination from multi-view images under unknown lighting [14852-gs-ir.md].

## Operating characteristics

**Time and Memory Complexity:**
*   **Memory:** Standard 3DGS can exceed 1 GB for large scenes due to per-Gaussian attributes [12943-data-compression-and-storage-optimization.md]. Implementations like EVolSplat use sparse voxel grids (e.g., $128 \times 320 \times 640$) to manage memory [S2].
*   **Time:** Rendering is real-time on modern GPUs. LS-Gaussian achieves up to 17.3× speedup on edge devices like Jetson AGX Orin compared to edge GPU baselines [S9].

**Measured Performance:**
*   EVolSplat achieves 83.81 FPS on Waymo dataset with 10.41 GB memory [S2].
*   LS-Gaussian achieves 1.04ms/frame on Jetson AGX Orin, compared to 49.06ms/frame for standard 3DGS [S9].

**Strengths and Limitations:**
*   **Strengths:** Real-time rendering, high fidelity, differentiable optimization.
*   **Limitations:** High memory usage for large scenes, sensitivity to camera distribution (addressed by Corrected Scene-Extent), difficulty with transparent/discontinuous boundaries (addressed by DisC-GS), and degradation in sparse/noisy views (addressed by Denoise-GS).

**When to Use:**
*   Use standard 3DGS for dense-view, well-lit scenes.
*   Use Corrected Scene-Extent for scenes with clustered cameras.
*   Use Denoise-GS for sparse-view or noisy inputs.
*   Use Underwater 3DGS for aquatic environments.
*   Use LS-Gaussian for real-time edge deployment.

## Background

3D Gaussian Splatting was introduced as a real-time explicit scene representation method [S1, S2]. It builds on the principles of differentiable volume rendering and inverse rendering [Parent]. The method has been extended to handle various challenges including scene extent bias [S3], defocus blur [S4], sparse views [S5], underwater environments [S6], and hardware acceleration [S9].
