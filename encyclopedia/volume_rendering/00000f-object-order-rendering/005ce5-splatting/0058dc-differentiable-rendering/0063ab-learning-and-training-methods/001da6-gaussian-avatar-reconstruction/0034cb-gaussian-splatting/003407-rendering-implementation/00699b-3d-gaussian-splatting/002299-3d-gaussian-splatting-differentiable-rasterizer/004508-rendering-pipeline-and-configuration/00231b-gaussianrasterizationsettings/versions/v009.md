# GaussianRasterizationSettings

Also called: 4D Gaussian Splatting Rasterization, GaussianRasterizationSettings configuration, GaussianRasterizer

## Overview
`GaussianRasterizationSettings` is a configuration container (typically a `NamedTuple` or struct) that encapsulates the camera parameters, rendering constraints, and mode flags required to invoke the differentiable 3D Gaussian splatting rasterizer. It solves the problem of translating high-level scene and camera state into the specific numerical formats expected by the CUDA backend, ensuring mutual exclusivity of input representations (e.g., spherical harmonics vs. precomputed colors) and device consistency [S1, S2, S3, unofficial]. It differs from the rasterizer itself by handling the setup of state and memory layout rather than the pixel-wise projection and blending logic [S1, unofficial].

## How it works
The settings object serves as the bridge between the Python-level scene representation and the C++/CUDA rasterization kernel (`_C.rasterize_gaussians`). It validates inputs, normalizes `None` values to empty tensors, and structures arguments for the forward and backward passes.

### Inputs and Outputs
*   **Inputs**: Camera matrices (`viewmatrix`, `projmatrix`), field of view (`tanfovx`, `tanfovy`), image dimensions (`image_height`, `image_width`), background color (`bg`), and mode flags (`sh_degree`, `rot_4d`, `debug`, etc.).
*   **Outputs**: The settings object itself is passed to the rasterizer. The rasterizer returns rendered tensors (color, depth, flow, etc.) and buffers for the backward pass.

### Data Structures
The layout varies slightly between implementations (3D GS vs. 4D GS vs. variants), but generally includes:

**Standard 3D GS Layout [S1, S3, unofficial]:**
*   `image_height`: `int`
*   `image_width`: `int`
*   `tanfovx`: `float` (Tangent of half horizontal FOV)
*   `tanfovy`: `float` (Tangent of half vertical FOV)
*   `cx`: `float` (Principal point x, optional in some variants)
*   `cy`: `float` (Principal point y, optional in some variants)
*   `bg`: `torch.Tensor` (Background color, shape `(3,)` or `(4,)`)
*   `scale_modifier`: `float` (Multiplicative scalar for Gaussian scales)
*   `viewmatrix`: `torch.Tensor` (4x4 view matrix)
*   `projmatrix`: `torch.Tensor` (4x4 projection matrix)
*   `sh_degree`: `int` (Degree of spherical harmonics)
*   `campos`: `torch.Tensor` (Camera position)
*   `prefiltered`: `bool`
*   `debug`: `bool`
*   `backward_geometry`: `bool` (Enable geometry gradients [S1, unofficial])
*   `computer_pseudo_normal`: `bool` (Enable pseudo-normal computation [S1, unofficial])

**4D GS Layout [S2, unofficial]:**
*   Includes all 3D GS fields plus:
*   `sh_degree_t`: `int` (Time-varying SH degree)
*   `timestamp`: `float`
*   `time_duration`: `float`
*   `rot_4d`: `bool` (Enable 4D rotation/velocity)
*   `gaussian_dim`: `int`
*   `force_sh_3d`: `bool`

**FastGS Layout [S3, unofficial]:**
*   Includes `mult`: `float`, `get_flag`: `bool`, `metric_map`: `torch.Tensor`.

### Numbered Steps

1.  **Initialization**: Create the settings object with camera parameters.
    *   Compute `tanfovx = math.tan(camera.FoVx * 0.5)` and `tanfovy = math.tan(camera.FoVy * 0.5)` [S1, unofficial].
    *   Extract principal points `cx = intrinsic[0, 2]`, `cy = intrinsic[1, 2]` if supported [S1, unofficial].
2.  **Input Normalization (Guard)**: Before invoking the rasterizer, ensure all optional input tensors that are `None` are converted to empty `torch.Tensor` objects to prevent CUDA crashes [Parent, S2].
    *   If `shs` is `None`, set `shs = torch.Tensor([])`.
    *   If `colors_precomp` is `None`, set `colors_precomp = torch.Tensor([])`.
    *   If `flow_2d` is `None`, set `flow_2d = torch.Tensor([])`.
    *   If `ts` is `None`, set `ts = torch.Tensor([])`.
    *   If `scales` is `None`, set `scales = torch.Tensor([])`.
    *   If `scales_t` is `None`, set `scales_t = torch.Tensor([])`.
    *   If `rotations` is `None`, set `rotations = torch.Tensor([])`.
    *   If `rotations_r` is `None`, set `rotations_r = torch.Tensor([])`.
    *   If `cov3D_precomp` is `None`, set `cov3D_precomp = torch.Tensor([])` [S2, unofficial].
3.  **Validation (Mutual Exclusivity)**:
    *   Check color input: Exactly one of `shs` or `colors_precomp` must be provided. If neither or both are provided, raise `Exception 'Please provide excatly one of either SHs or precomputed colors!'` [S2, unofficial].
    *   Check geometry input: Either (`scales` and `rotations`) OR `cov3D_precomp` must be provided, but not both. If the condition is violated, raise `Exception 'Please provide exactly one of either scale/rotation pair or precomputed 3D covariance!'` [S2, unofficial].
    *   Check 4D constraints: If `rot_4d` is `True` and `cov3D_precomp` is `None`, then `rotations_r`, `scales_t`, and `ts` must all be non-None. Otherwise, raise `Exception 'Please provide exactly rotations_r and scales_t and ts if rot_4d and cov3D_precomp is None!'` [S2, unofficial].
4.  **Argument Restructuring (Forward)**: Construct the `args` tuple in the exact order expected by `_C.rasterize_gaussians`:
    `args = (raster_settings.bg, means3D, colors_precomp, flow_2d, opacities, ts, scales, scales_t, rotations, rotations_r, raster_settings.scale_modifier, cov3Ds_precomp, prefilter_var, raster_settings.viewmatrix, raster_settings.projmatrix, raster_settings.tanfovx, raster_settings.tanfovy, raster_settings.image_height, raster_settings.image_width, sh, raster_settings.sh_degree, raster_settings.sh_degree_t, raster_settings.campos, raster_settings.timestamp, raster_settings.time_duration, raster_settings.rot_4d, raster_settings.gaussian_dim, raster_settings.force_sh_3d, raster_settings.prefiltered, raster_settings.debug)` [S2, unofficial].
5.  **Execution (Forward)**:
    *   If `raster_settings.debug` is `True`, deep-copy `args` to CPU (`cpu_args`) for potential snapshotting [S2, S6, unofficial].
    *   Call `num_rendered, color, flow, depth, T, radii, geomBuffer, binningBuffer, imgBuffer, covs_com, out_means3D = _C.rasterize_gaussians(*args)` [S2, unofficial].
    *   If an exception occurs and debug is on, save `cpu_args` to `'snapshot_fw.dump'` and re-raise [S2, unofficial].
6.  **Context Saving**: Save tensors for the backward pass: `raster_settings`, `num_rendered`, `prefilter_var`, `colors_precomp`, `means3D`, `out_means3D`, `scales`, `rotations`, `cov3Ds_precomp`, `radii`, `sh`, `flow_2d`, `opacities`, `ts`, `scales_t`, `rotations_r`, `geomBuffer`, `binningBuffer`, `imgBuffer` [S2, unofficial].
7.  **Return (Forward)**: Return `(color, radii, depth, 1-T, flow, covs_com)` [S2, unofficial].

### Backward Pass Steps
1.  **Argument Restructuring (Backward)**: Construct `args` tuple for `_C.rasterize_gaussians_backward`:
    `args = (raster_settings.bg, means3D, out_means3D, radii, colors_precomp, flow_2d, opacities, ts, scales, scales_t, rotations, rotations_r, raster_settings.scale_modifier, cov3Ds_precomp, prefilter_var, raster_settings.viewmatrix, raster_settings.projmatrix, raster_settings.tanfovx, raster_settings.tanfovy, grad_out_color, grad_depth, grad_alpha, grad_flow, sh, raster_settings.sh_degree, raster_settings.sh_degree_t, raster_settings.campos, raster_settings.timestamp, raster_settings.time_duration, raster_settings.rot_4d, raster_settings.gaussian_dim, raster_settings.force_sh_3d, geomBuffer, num_rendered, binningBuffer, imgBuffer, raster_settings.debug)` [S2, unofficial].
2.  **Execution (Backward)**:
    *   If debug, copy `args` to CPU [S2, unofficial].
    *   Call `grad_means2D, grad_colors_precomp, grad_opacities, grad_means3D, grad_cov3Ds_precomp, grad_sh, grad_flows, grad_ts, grad_scales, grad_scales_t, grad_rotations, grad_rotations_r = _C.rasterize_gaussians_backward(*args)` [S2, unofficial].
3.  **Return (Backward)**: Return `(grad_means3D, grad_means2D, grad_sh, grad_colors_precomp, grad_flows, grad_opacities, grad_ts, grad_scales, grad_scales_t, grad_rotations, grad_rotations_r, grad_cov3Ds_precomp, None, None)` [S2, unofficial].

### Parameters with Typical Values
*   `scale_modifier`: Default `1.0` [S1, unofficial].
*   `tanfovx`, `tanfovy`: Computed from camera FOV [S1, unofficial].
*   `sh_degree`: Typically 0-3, increased during training [S2, unofficial].
*   `debug`: `False` during training, `True` for debugging [S2, unofficial].

### Edge Cases and Pitfalls
*   **None Handling**: Passing `None` directly to the CUDA kernel causes crashes; must be converted to `torch.Tensor([])` [Parent, S2].
*   **Mutual Exclusivity**: Providing both SH and precomputed colors, or both scale/rotation and precomputed covariance, raises an exception [S2, unofficial].
*   **4D Consistency**: If `rot_4d` is enabled, specific time-dependent parameters (`ts`, `scales_t`, `rotations_r`) must be provided [S2, unofficial].
*   **Debug Snapshots**: In debug mode, arguments are copied to CPU, which may impact performance [S2, S6, unofficial].

## Subtopics

### 3D Half-Gaussian Rasterization
A variant that splits a 3D Gaussian kernel into two halves using a plane through its center, allowing distinct opacity values ($\alpha_1, \alpha_2$) for each half to better represent sharp edges and planar surfaces [S4]. It uses three unused normal parameters in the 3D-GS kernel to store the splitting plane normal $\mathbf{n}$ [S4].

### Restricting Gaussian Kernel Support
Techniques to reduce Gaussian footprints and superfluous ray-Gaussian intersections using a generalized kernel exponent and adaptive alpha clamping [S5]. The generalized kernel is $\exp \left[ -\frac{1}{2n_{\text{expo}}} ((x - \mu)^T \Sigma^{-1} (x - \mu))^{n_{\text{expo}}} \right]$ [S5]. 3DGRT uses $4.5 n_{\text{expo}}$ in the denominator, while GRay uses $1 2^{n_{\text{expo}}}$ for less sensitive initialization [S5].

## Operating characteristics
*   **Time Complexity**: Linear in the number of Gaussians $N$ and pixels $P$, dominated by the sorting and blending steps in the CUDA kernel.
*   **Memory Complexity**: Linear in $N$ for storing Gaussian parameters and buffers (`geomBuffer`, `binningBuffer`, `imgBuffer`) [S2, unofficial].
*   **Performance**: Real-time rendering on modern GPUs (e.g., RTX 4090) for typical scene sizes [S5].
*   **Strengths**: Differentiable, fast, supports dynamic scenes (4D GS) [S2, unofficial].
*   **Limitations**: Sensitive to input validation errors (None handling, mutual exclusivity) [S2, unofficial]. Debug mode incurs CPU copy overhead [S2, unofficial].

## Background
Originated from the 3D Gaussian Splatting paper [Parent] and extended to 4D Gaussian Splatting for dynamic scenes by Yang et al. (ICLR 2024) [S2, unofficial]. The `GaussianRasterizationSettings` structure is part of the `diff_gaussian_rasterization` CUDA extension [S2, S6, unofficial].
