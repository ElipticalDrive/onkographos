# Quaternion-Scale Covariance Parameterization

Also called: 3D Gaussian Splatting Parameterization, Covariance Matrix Construction, Covariance Parameterization via Quaternion and Scale, Ellipsoid Parameterization, QS Covariance, Quaternion and Scale Parameterization, Quaternion-Scale Covariance

## Overview
This method parameterizes the 3D Gaussian covariance matrix $\Sigma$ using a unit quaternion $q$ and a 3D scale vector $s$ to ensure the matrix remains positive semi-definite during optimization [S1][S2, unofficial]. It solves the problem that directly optimizing the entries of $\Sigma$ can result in non-positive semi-definite matrices, violating physical interpretation and causing numerical instability [S1]. Unlike siblings such as [Cholesky Parameterisation for Gaussian Splats](3120-cholesky-parameterisation-for-gaussian-splats.md), which uses a triangular factorization, this approach explicitly decouples rotation and scale, allowing for efficient gradient derivation and intuitive ellipsoid parameterization [S2, unofficial].

## How it works
**Inputs and Outputs**
*   **Inputs:** A unit quaternion $q = [w, x, y, z]^T$ representing rotation, and a 3D scale vector $s = [s_x, s_y, s_z]^T$ representing anisotropic scaling.
*   **Outputs:** The covariance matrix $\Sigma$ or its inverse $\Sigma^{-1}$, used in the Gaussian density function.

**Data Structures**
*   **Quaternion ($q$):** A 4-element vector $[w, x, y, z]$. Must be normalized to unit length ($||q||=1$) to represent a valid rotation [S1].
*   **Scale Vector ($s$):** A 3-element vector $[s_x, s_y, s_z]$. These values are typically positive, representing the semi-axis lengths of the ellipsoid [S1][S2, unofficial].

**Construction Steps**
1.  **Construct Rotation Matrix ($R$):** Convert the quaternion $q$ into a $3 \times 3$ rotation matrix $R$. The standard conversion from quaternion components $w, x, y, z$ to $R$ is:
    $$
    R = \begin{bmatrix}
    1 - 2(y^2 + z^2) & 2(xy - wz) & 2(xz + wy) \\
    2(xy + wz) & 1 - 2(x^2 + z^2) & 2(yz - wx) \\
    2(xz - wy) & 2(yz + wx) & 1 - 2(x^2 + y^2)
    \end{bmatrix}
    $$
    [S1][S2, unofficial]. Note: Some implementations may use a different convention for quaternion-to-matrix conversion (e.g., row-major vs column-major), but the resulting $R$ must be orthogonal with determinant +1.

2.  **Construct Scale Matrix ($S$):** Create a $3 \times 3$ diagonal matrix from the scale vector $s$:
    $$
    S = \text{diag}(s_x, s_y, s_z) = \begin{bmatrix}
    s_x & 0 & 0 \\
    0 & s_y & 0 \\
    0 & 0 & s_z
    \end{bmatrix}
    $$
    [S1][S2, unofficial].

3.  **Compute Covariance Matrix ($\Sigma$):** The covariance matrix is reconstructed as:
    $$
    \Sigma = R S S^T R^T
    $$
    Since $S$ is diagonal, $S S^T = S^2 = \text{diag}(s_x^2, s_y^2, s_z^2)$. Thus:
    $$
    \Sigma = R \begin{bmatrix}
    s_x^2 & 0 & 0 \\
    0 & s_y^2 & 0 \\
    0 & 0 & s_z^2
    \end{bmatrix} R^T
    $$
    [S1]. This ensures $\Sigma$ is symmetric and positive semi-definite by construction.

4.  **Compute Inverse Covariance ($\Sigma^{-1}$):** For rendering, the inverse is often required. Using the property $(ABC)^{-1} = C^{-1} B^{-1} A^{-1}$:
    $$
    \Sigma^{-1} = (R S S^T R^T)^{-1} = R (S S^T)^{-1} R^T = R S^{-2} R^T
    $$
    where $S^{-2} = \text{diag}(1/s_x^2, 1/s_y^2, 1/s_z^2)$ [S2, unofficial].

**Gradients**
Instead of relying on automatic differentiation through the complex graph $q, s \rightarrow \Sigma \rightarrow \Sigma^{-1} \rightarrow \alpha$ (where $\alpha$ is opacity/density), gradients for $q$ and $s$ are derived analytically to avoid computational cost and potential numerical errors [S1].

**Pseudocode**
```python
import numpy as np

def quaternion_to_rotation_matrix(q):
    """
    Converts a unit quaternion [w, x, y, z] to a 3x3 rotation matrix R.
    q: array-like of shape (4,)
    Returns: R, shape (3, 3)
    """
    w, x, y, z = q[0], q[1], q[2], q[3]
    
    # Precompute terms to avoid redundant calculations
    xx, yy, zz = x*x, y*y, z*z
    xy, xz, yz = x*y, x*z, y*z
    wx, wy, wz = w*x, w*y, w*z
    
    R = np.array([
        [1 - 2*(yy + zz), 2*(xy - wz),     2*(xz + wy)],
        [2*(xy + wz),     1 - 2*(xx + zz), 2*(yz - wx)],
        [2*(xz - wy),     2*(yz + wx),     1 - 2*(xx + yy)]
    ])
    return R

def compute_covariance(q, s):
    """
    Computes the covariance matrix Sigma from quaternion q and scale vector s.
    q: array-like of shape (4,), unit quaternion
    s: array-like of shape (3,), scale factors
    Returns: Sigma, shape (3, 3)
    """
    # Ensure q is normalized [G]
    q = q / np.linalg.norm(q)
    
    R = quaternion_to_rotation_matrix(q)
    
    # S is diagonal matrix of scales
    S = np.diag(s)
    
    # Sigma = R * S * S^T * R^T
    # Since S is diagonal, S * S^T = S^2
    S_squared = np.diag(s**2)
    
    Sigma = R @ S_squared @ R.T
    return Sigma

def compute_inverse_covariance(q, s):
    """
    Computes the inverse covariance matrix Sigma_inv from quaternion q and scale vector s.
    q: array-like of shape (4,), unit quaternion
    s: array-like of shape (3,), scale factors (must be non-zero)
    Returns: Sigma_inv, shape (3, 3)
    """
    # Ensure q is normalized [G]
    q = q / np.linalg.norm(q)
    
    R = quaternion_to_rotation_matrix(q)
    
    # Sigma_inv = R * S^{-2} * R^T
    # S^{-2} is diagonal with 1/s_i^2
    # Guard against division by zero [G]
    s_sq_inv = 1.0 / (s**2 + 1e-8)
    S_inv_squared = np.diag(s_sq_inv)
    
    Sigma_inv = R @ S_inv_squared @ R.T
    return Sigma_inv
```

**Parameters**
*   **Learning Rate:** Applied to $q$ and $s$ during optimization. Typical values are not specified in the sources, but $s$ often requires careful clamping or regularization to prevent collapse or explosion [S1].
*   **Clamping:** Scale values $s$ are often clamped to a minimum positive value to prevent numerical instability in $\Sigma^{-1}$ [G].

**Edge Cases and Pitfalls**
*   **Non-Positive Semi-Definite Matrix:** Directly optimizing $\Sigma$ entries can lead to invalid matrices. This parameterization guarantees validity [S1].
*   **Quaternion Normalization:** The quaternion must remain unit length. Optimization steps must include renormalization or a projection step [S1].
*   **Scale Zero/Negative:** If any scale component $s_i$ is zero, $\Sigma^{-1}$ becomes singular. If negative, the physical interpretation of the ellipsoid axis is ambiguous (though mathematically $s^2$ is positive). Scales are typically constrained to be positive [S2, unofficial].
*   **Notation Confusion:** In probability theory, $\Sigma$ often denotes standard deviation, while $\Sigma^2$ denotes variance. In this context, $\Sigma$ is the covariance matrix (variance), and $s$ represents the standard deviation-like scale factors. Confusion here leads to errors in constructing $S$ (using $s$ vs $s^2$) [S2, unofficial].

## Subtopics

### Cholesky Parameterisation for Gaussian Splats
Uses a lower triangular Cholesky factor of the covariance matrix. It guarantees positive definiteness without explicit rotation/scale decomposition. Choose when computational efficiency of matrix inversion is critical and rotation interpretation is less important. See [Cholesky Parameterisation for Gaussian Splats](3120-cholesky-parameterisation-for-gaussian-splats.md).

## Operating characteristics
*   **Time Complexity:** Constructing $R$ from $q$ is $O(1)$. Matrix multiplications for $\Sigma$ and $\Sigma^{-1}$ are $O(1)$ for fixed $3 \times 3$ size. Analytical gradient derivation is $O(1)$.
*   **Memory Complexity:** Stores 4 floats for $q$ and 3 floats for $s$, totaling 7 floats per Gaussian, compared to 6 floats for the upper triangular $\Sigma$ or 9 for full $\Sigma$. This is slightly more memory than the minimal 6-float representation but provides explicit semantic meaning [S1].
*   **Strengths:** Guarantees positive semi-definiteness; intuitive interpretation as an ellipsoid; efficient gradient computation via analytical derivatives; avoids complex automatic differentiation graphs [S1][S2, unofficial].
*   **Limitations:** Requires careful handling of quaternion normalization; scale parameters may need regularization to prevent degenerate Gaussians [S1].
*   **When to Use:** Standard for 3D Gaussian Splatting optimization where physical interpretability and stability are prioritized.
*   **When Not to Use:** If memory is extremely constrained and semantic meaning is irrelevant, Cholesky parameterization might be preferred for its compactness [S2, unofficial].

## Background
Originated in the context of 3D Gaussian Splatting for novel view synthesis [S1]. The method draws from computer graphics traditions of parameterizing ellipsoids with scale and rotation, as well as probability theory's generalization of Gaussian PDFs using covariance matrices [S2, unofficial]. It was introduced to address the instability of direct covariance optimization in differentiable rendering pipelines [S1].
