# On-the-Fly GS Progressive Training

Also called: On-the-Fly Gaussian Splatting

## Overview
On-the-Fly GS Progressive Training is a method for optimizing 3D Gaussian Splatting (3DGS) fields in a continuous, incremental manner as new images are acquired, enabling near real-time reconstruction without retraining from scratch. It solves the problem of catastrophic forgetting and overfitting in sequential SLAM-based 3DGS by structuring training into three phases: initial sparse training, progressive fly-in updates with hierarchical weighting, and final global optimization. It distinguishes itself from standard 3DGS by dynamically allocating training iterations and learning rates based on image overlap hierarchies and introducing a load-balancing loss to prevent Gaussian accumulation hotspots, while utilizing splatting-based parallelism for gradient accumulation to accelerate convergence.

## How it works

### Inputs and Outputs
**Inputs:**
- A sequence of RGB images arriving sequentially.
- Camera poses and sparse point clouds estimated by an On-the-Fly SfM module (e.g., [On-the-Fly SfM](link)).
- Hyperparameters: $N_0=30$ (initial images), $T_{init}=2000$ (initial iterations), $T_I=200$ (iterations per new image), $N_m=10$ (key images), $T_a=200$ (satisfactory quality threshold), $\eta^0=1.6\times10^{-4}$, $\eta^f=1.6\times10^{-6}$, $\lambda_1=0.47$, $\lambda_{ssim}=0.12$, $\lambda_{load}=0.41$.

**Outputs:**
- A fully optimized 3D Gaussian field (positions, covariances, opacities, spherical harmonics coefficients) representing the scene.

### Data Structures
- **Sparse Point Cloud:** A set of 3D points $\{P_k\}$ with associated feature descriptors, maintained and refined by the SfM backend.
- **Search Tree:** A spatial index (e.g., KD-Tree) built over the existing sparse point cloud to facilitate nearest-neighbor queries for new points.
- **3DGS Field:** The standard 3DGS representation containing $G$ Gaussians, each defined by mean $\mu$, covariance $\Sigma$, opacity $\alpha$, and spherical harmonics coefficients $\mathbf{c}$.
- **Image Overlap Matrix:** A matrix $M$ where $M_{i,j}$ stores the number of matched feature points between image $i$ and image $j$.

### Algorithm Steps

#### Phase 1: Initial 3DGS Training
1.  Acquire the first $N_0$ images.
2.  Run On-the-Fly SfM to estimate poses and generate a sparse point cloud for these $N_0$ images.
3.  Initialize the 3DGS field using the standard 3DGS densification and optimization pipeline.
4.  Perform $T_{init}$ training iterations on these $N_0$ images. This limited iteration count prevents overfitting to the initial sparse subset [S1].

#### Phase 2: Progressive 3DGS Training (Per New Image)
For each newly acquired image $n$:

1.  **Pose and Cloud Update:**
    -   Estimate the pose of image $n$ using On-the-Fly SfM.
    -   Perform local Bundle Adjustment (BA) to optimize the pose of image $n$ and its connected neighbors.
    -   Refine the global sparse point cloud.

2.  **Gaussian Initialization:**
    -   Construct a search tree over the current sparse point cloud.
    -   Query the 3D points from image $n$ against this tree.
    -   Identify points $P_{new}$ where the distance to the nearest existing point in the cloud exceeds a predefined threshold.
    -   Initialize new Gaussians for each $P_{new}$ and append them to the 3DGS field [S1].

3.  **Hierarchical Image Weighting:**
    -   Assign weight $\omega_{11} = 1$ to the new image $n$.
    -   Identify images with direct overlap ($M_{i,n} > 0$). For each such image $i$ in layer 2, calculate weight:
        $$ \omega_{2i} = M_{i,n} $$
    -   For images with indirect overlap (layer $k \ge 3$), calculate weights recursively based on the previous layer $k-1$:
        $$ \omega_{ki} = \frac{\sum_{j=1}^{N_{k-1}} \omega_{j}^{(k-1)} \times M_{j,ki}^{(k-1)}}{N_{k-1}} $$
        where $N_{k-1}$ is the number of images in layer $k-1$, $\omega_{j}^{(k-1)}$ is the weight of image $j$ in layer $k-1$, and $M_{j,ki}^{(k-1)}$ is the match count between image $j$ (from layer $k-1$) and image $i$ (in layer $k$) [S1].

4.  **Training Iteration Allocation:**
    -   Select the top $N_m$ images with the highest weights as key training targets.
    -   Distribute the total $T_I$ iterations between Local and Semi-Global optimization (each gets $T_I/2$ iterations).
    -   **Local Optimization:** For each key image $i$ (with weight $\omega_i$), calculate its specific iteration count $T_{im}$:
        $$ T_{im} = \frac{1 - e^{-\omega_i}}{\sum_{j=1}^{N_m} (1 - e^{-\omega_j})} \times T_I $$
        Train the 3DGS field on these key images for their allocated $T_{im}$ iterations.
    -   **Semi-Global Optimization:** Distribute the remaining $T_I/2$ iterations evenly among all other registered images to prevent forgetting [S1].

5.  **Adaptive Learning Rate Update:**
    -   For each image $j$ trained for $T_j$ iterations, calculate the base learning rate $\eta_j^c$:
        $$ t_i = \min\left(1, \frac{T_j}{T_a}\right) $$
        $$ \eta_j^c = (\eta_j^0)^{1-t_i} \times (\eta_j^f)^{t_i} $$
    -   Adjust for overlapping images. Let $I$ be the set of images overlapping with $j$ ($M_{i,j} > 0$) and $N_I = |I|$. The final learning rate $\eta_j$ is:
        $$ \eta_j = \frac{\eta_j^c + \sum_{i \in I} M_{i,j} \times \eta_i^c}{N_I + 1} $$
        This ensures images with high overlap and satisfactory quality (high $T_j$) have lower learning rates, while others adapt dynamically [S1].

6.  **Loss Function and Optimization:**
    -   Calculate the Load-Balancing-Loss $L_{load}$ for the current image. Let $G_p$ be the number of Gaussians associated with pixel $p$.
        $$ L_{load} = \text{std}(G_p), \quad p \in \text{image} $$
    -   Compute total loss:
        $$ L_{total} = \lambda_1 L_1 + \lambda_{ssim} L_{ssim} + \lambda_{load} L_{load} $$
    -   Perform gradient descent using the adaptive learning rates. Use **Splatting-based Parallelism**: accumulate gradients per Gaussian rather than per pixel to eliminate thread contention and atomic operation serialization [S1].

#### Phase 3: Final Optimization
1.  After all images are acquired, perform global Bundle Adjustment on all estimated poses.
2.  Apply rapid additional optimization to the entire 3DGS field to improve overall rendering quality [S1].

### Edge Cases and Pitfalls
-   **Threshold Selection:** The distance threshold for classifying new points must be small enough to avoid duplicate Gaussians but large enough to handle SfM noise. Not given in the sources.
-   **Memory Growth:** Progressive training accumulates Gaussians. The Load-Balancing-Loss helps mitigate abnormal accumulation, but total Gaussian count will grow linearly with image count. Pruning strategies (e.g., [Pruning and Sparsity Control](14431-pruning-and-sparsity-control.md)) may be needed for very large scenes, though not part of the core On-the-Fly GS method.
-   **SfM Failure:** If On-the-Fly SfM fails to estimate a pose or matches features poorly, the overlap matrix $M$ will be inaccurate, leading to incorrect weighting and potential training instability.

## Operating characteristics

-   **Time Complexity:** Training time per new image is constant $O(T_I \cdot G)$, where $G$ is the number of Gaussians. The total training time scales linearly with the number of images, unlike offline 3DGS which scales super-linearly or requires full re-optimization.
-   **Memory Complexity:** $O(G)$, where $G$ grows with the number of images. The search tree adds $O(P)$ overhead for $P$ sparse points.
-   **Performance:** Achieves near real-time optimization. On RTX 4090, it processes images sequentially with minimal delay. The splatting-based parallelism significantly reduces training time compared to per-pixel gradient accumulation [S1].
-   **Strengths:** Robust to incremental input; prevents catastrophic forgetting via hierarchical weighting; reduces Gaussian count via load-balancing loss; fast convergence due to adaptive learning rates.
-   **Limitations:** Requires a reliable On-the-Fly SfM backend; quality depends on the initial $N_0$ images; may require final global BA for best results.

## Background

On-the-Fly GS was introduced in 2025 by the authors of "Gaussian On-the-Fly Splatting: A Progressive Framework for Robust Near Real-Time 3DGS Optimization" [S1]. It builds upon the original 3DGS method [3] and addresses the limitations of offline training when applied to streaming data from SLAM systems. It integrates concepts from Taming 3DGS [7] regarding gradient accumulation parallelism and adapts them for progressive training.
