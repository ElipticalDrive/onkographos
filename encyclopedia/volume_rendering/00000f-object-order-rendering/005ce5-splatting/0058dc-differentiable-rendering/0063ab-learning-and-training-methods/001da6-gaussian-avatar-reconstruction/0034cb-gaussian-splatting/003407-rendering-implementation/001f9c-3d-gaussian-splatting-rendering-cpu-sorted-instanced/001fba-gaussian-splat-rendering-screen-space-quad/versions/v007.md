# Gaussian Splat Rendering (Screen-Space Quad)

Also called: Gaussian Splat Rendering Pipeline, RenderGaussianSplats, Splatv Render Program, VideoRenderProgram, WebGL Instanced Gaussian Splat Rendering

## Overview
Gaussian Splat Rendering (Screen-Space Quad) is a display-only rendering technique that projects 3D Gaussian distributions into 2D screen-space quads and renders them using instanced drawing with standard alpha blending [S2, S3, unofficial]. It solves the problem of visualizing large-scale, photorealistic 3D scenes reconstructed via Gaussian Splatting by treating each splat as a billboard-like primitive [S1, unofficial]. It sets itself apart from its siblings by defining the fundamental geometry generation and quad-drawing mechanism without specifying the sorting implementation or advanced shading extensions [S2, unofficial]. Unlike [Tiled 2D Gaussian Splatting Rasterization](2061-tiled-2d-gaussian-splatting-rasterization.md), which rasterizes tiles, this method relies on CPU-side depth sorting to resolve the non-commutative nature of alpha blending [S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A list of 3D Gaussian splats (position, scale, rotation, color, opacity), a view matrix ($V$), a projection matrix ($P$), and screen resolution parameters.
*   **Outputs:** A 2D framebuffer image with composited splat colors and alphas.

**Data Structures:**
*   **Splat Data:** Stored in textures or buffers. For WebGL implementations, a `splat texture` is created with `gl.RGBA32UI` internal format, sized to the render data dimensions [S3, unofficial].
*   **Order Buffer:** A buffer (`_OrderBuffer`) containing depth-sorted splat indices, used to map instance IDs to splat indices [S2, unofficial].
*   **View Data:** Per-splat view-space data (position, axes, color) loaded from `_SplatViewData` [S2, unofficial].
*   **Vertex Buffer:** Contains quad coordinates, typically `[-2, -2, 2, -2, 2, 2, -2, 2]` representing a unit quad [S3, unofficial].
*   **Index Buffer:** Contains depth-sorted splat indices (Uint32Array) [S3, unofficial].

**Numbered Steps:**

1.  **Initialization:** Initialize scene, camera, and render data. Create vertex and index buffers. Bind splat textures. Send initial sort data (positions, dummy transforms) to a background worker for sorting [S3, unofficial].
2.  **Per-Frame Update:** On each render frame, update camera parameters and send the view-projection matrix ($VP$) to the sorting worker [S3, unofficial].
3.  **Vertex Shader Execution (Instanced):**
    a.  Map the instance ID to the splat index using the order buffer: `instID = _OrderBuffer[instanceID]` [S2, unofficial].
    b.  Load view-space data for the splat: `view = _SplatViewData[instID]` [S2, unofficial].
    c.  **Camera Culling:** Check if the splat center is behind the camera in clip space ($w \le 0$). If so, output a NaN vertex (e.g., `asfloat(0x7fc00000)`) to discard the primitive [S2, unofficial].
    d.  **Frustum Culling:** Calculate clip-space position. If the splat is outside the frustum border (defined as $1 + \text{half-edge length}$), discard the primitive [S1, unofficial].
    e.  **Quad Generation:** Calculate the screen-space delta for the quad corners based on the splat's view-space axes and screen resolution. Apply this delta to the clip-space position [S2, unofficial].
    f.  **Selection (Optional):** If selection bits are enabled, check the selection bit for the splat. If selected, modify the output alpha to mark it (e.g., negative alpha) [S2, unofficial].
4.  **Fragment Shader Execution:**
    a.  **Gaussian Evaluation:** Calculate the Gaussian falloff based on the fragment's distance from the quad center: `power = -dot(pos, pos)`, `alpha = exp(power)` [S2, unofficial].
    b.  **Alpha Modulation:** If not selected, saturate alpha: `alpha = saturate(alpha * color.a)` [S2, unofficial]. If selected, apply magenta outline logic based on alpha thresholds [S2, unofficial].
    c.  **Discard:** Discard the fragment if `alpha < 1.0/255.0` [S2, unofficial].
    d.  **Output:** Output the final color and alpha: `res = half4(color.rgb * alpha, alpha)` [S2, unofficial].
5.  **Blending:** Use pre-multiplied alpha blending: `gl.blendFuncSeparate(gl.ONE_MINUS_DST_ALPHA, gl.ONE, gl.ONE_MINUS_DST_ALPHA, gl.ONE)` [S3, unofficial].
6.  **Drawing:** Call `gl.drawArraysInstanced(gl.TRIANGLE_FAN, 0, 4, vertexCount)` [S3, unofficial].

**Formulas:**
*   **Voxel Offset (View Space):** $voxelOffset = splatSize \times (scale/gridLength) \times \sqrt{2}$ [S1, unofficial].
*   **Frustum Culling Border:** $voxelFrustumCullingBorder = 1 + voxelHalfEdgeLengthClipSpace$, where $voxelHalfEdgeLengthClipSpace$ is the distance in clip space between the center and the right edge midpoint [S1, unofficial].
*   **Gaussian Falloff:** $alpha = \exp(-\mathbf{d}^T \mathbf{d})$, where $\mathbf{d}$ is the normalized position within the quad [S2, unofficial].

**Parameters:**
*   `_ScreenParams.xy`: Screen resolution in pixels, used to normalize screen-space deltas [S2, unofficial].
*   `splatCount`: Number of splats to render, coerced to `0..splatCloud.count`. Defaults to full count. Used for LOD/reveal [S4, unofficial].
*   `u_focal`: Camera focal lengths ($f_x, f_y$) [S3, unofficial].
*   `u_viewport`: Canvas dimensions [S3, unofficial].

**Edge Cases and Pitfalls:**
*   **Behind Camera:** Splats with clip-space $w \le 0$ must be discarded to prevent artifacts. This is handled by outputting a NaN vertex [S2, unofficial].
*   **Precision:** Color data may be stored as half-floats and must be decompressed to 32-bit floats for accurate blending [S2, unofficial].
*   **Multiple Objects:** Some implementations (e.g., Splatv) do not support multiple splat objects in the same scene [S3, unofficial].
*   **Worker Dependency:** The sorting worker must be initialized before rendering; otherwise, rendering fails [S3, unofficial].

**Pseudocode:**

```python
# Vertex Shader Logic (Conceptual)
def vertex_shader(instance_id):
    # Map instance to splat index via order buffer
    splat_index = order_buffer[instance_id]
    
    # Load view data
    view_data = splat_view_data[splat_index]
    
    # Transform to clip space
    center_clip = projection_matrix * view_data.position_view_space
    center_clip /= center_clip.w
    
    # Check if behind camera
    if center_clip.w <= 0:
        return NaN_VERTEX
    
    # Frustum Culling
    half_edge_length = calculate_half_edge_length(center_clip, view_data)
    frustum_border = 1.0 + half_edge_length
    if is_outside_frustum(center_clip, frustum_border):
        return DISCARD
    
    # Calculate Quad Corners
    quad_pos = get_quad_corner_index(instance_id) # e.g., 0..3
    delta_screen = (quad_pos.x * view_data.axis1 + quad_pos.y * view_data.axis2) * 2.0 / screen_resolution
    final_vertex = center_clip + delta_screen * center_clip.w
    
    # Output
    return final_vertex, view_data.color, view_data.alpha

# Fragment Shader Logic (Conceptual)
def fragment_shader(pos_local, color, alpha):
    # Gaussian Falloff
    power = -dot(pos_local, pos_local)
    gaussian_alpha = exp(power)
    
    # Modulate with splat alpha
    final_alpha = saturate(gaussian_alpha * alpha)
    
    # Discard low alpha
    if final_alpha < 1.0 / 255.0:
        return DISCARD
    
    # Output
    return color * final_alpha, final_alpha

# Render Loop
def render_frame():
    update_camera()
    send_view_projection_to_worker()
    wait_for_sort_completion()
    
    set_blend_function(ONE_MINUS_DST_ALPHA, ONE)
    bind_splat_textures()
    bind_index_buffer()
    
    draw_arrays_instanced(TRIANGLE_FAN, 0, 4, splat_count)
```

## Subtopics

### [WebGL Gaussian Splatting](2084-webgl-gaussian-splatting.md)
WebGL Gaussian Splatting is a real-time rendering technique for 3D Gaussian Splatting (3DGS) implemented in web browsers using WebGL 1.0 and the Three.js library. It solves the problem of displaying large-scale, photorealistic 3D scenes reconstructed via Gaussian Splatting on client-side hardware without requiring neural network inference or server-side ray tracing. It sets itself apart from its siblings by utilizing a CPU-side depth sorting algorithm (often offloaded to a Web Worker) to resolve the non-commutative nature of alpha blending, whereas the parent [Gaussian Splat Rendering (Screen-Space Quad)](2075-gaussian-splat-rendering-screen-space-quad.md) describes the general projection and quad-drawing mechanism without specifying the sorting implementation. Unlike [Animated 3D Gaussian Splatting (Splatv rendering)](7758-animated-3d-gaussian-splatting-splatv-rendering.md), this method typically omits spherical harmonics to reduce file size and memory footprint for web delivery.

### [Gaussian Splat Fragment Shader](3258-gaussian-splat-fragment-shader.md)
The Gaussian Splat Fragment Shader evaluates the 2D Gaussian probability density function (PDF) at each fragment of a screen-space quad to determine splat coverage and modulate fragment color. It composites the new splat over the existing framebuffer color using pre-multiplied alpha blending. It is distinguished from its parent [Gaussian Splat Rendering (Screen-Space Quad)](2075-gaussian-splat-rendering-screen-space-quad.md) by performing the per-pixel alpha evaluation and blending logic directly in the fragment shader, handling transparency via alpha cutoffs and discarding fragments behind the camera or with negligible alpha.

### [Gaussian Splat Shader Property Configuration](3596-gaussian-splat-shader-property-configuration.md)
This method configures the GPU render pass by populating a material property block (or uniform buffer) with splat count, spherical harmonic (SH) degree, brightness, scale, antialiasing settings, transform matrices, and optional skinning or volume lighting data. It solves the problem of efficiently passing per-renderer and global state to the fragment shader without causing state overwrites in multi-camera setups or shader compilation errors when optional features (like skinning) are disabled. It differs from standard mesh rendering by explicitly handling the decoupling of jittered projections and ensuring valid sampled resources even for unused features.

### [Animated 3D Gaussian Splatting (Splatv rendering)](7758-animated-3d-gaussian-splatting-splatv-rendering.md)
Animated 3D Gaussian Splatting (Splatv rendering) is a GPU-accelerated rendering method for time-varying 3D Gaussian splats that computes time-dependent position, rotation, and scale deltas from packed texture data to enable smooth animation without per-frame CPU updates. It differs from static 3D Gaussian Splatting by evaluating polynomial motion deltas and applying temporal opacity decay in the vertex and fragment shaders, building on the screen-space quad rendering of [Gaussian Splat Rendering (Screen-Space Quad)](2075-gaussian-splat-rendering-screen-space-quad.md).

### Debug Splat Point Rendering
Renders small quads at the center of each splat for debugging, optionally displaying the splat index as color [S2, unofficial]. In the vertex shader, it loads splat data, transforms the center to world and clip space, and applies a small offset in screen space based on `_SplatSize` and `_ScreenParams.xy` [S2, unofficial]. If `_DisplayIndex` is true, the splat index is encoded into the RGB color channels (R: `frac(index / count * 100)`, G: `frac(index / count * 10)`, B: `index / count`) [S2, unofficial].

### Anisotropic 3D Gaussian Splatting Rendering
A rendering method for Gaussian splats that computes anisotropic covariance matrices to handle perspective distortion and view-dependent scaling, improving edge crispness and reducing haze compared to isotropic approximations [S5, unofficial]. In the vertex shader, it computes the 3D covariance matrix $\Sigma_3 = R \cdot S^2 \cdot R^T$, transforms it to view space, and applies a perspective Jacobian $J$ to obtain a 2D covariance $\Sigma_2$ [S5, unofficial]. A low-pass filter (adding $0.3 \text{ px}^2$) is applied to $\Sigma_2$ to prevent aliasing. Eigenvalues $\lambda_1, \lambda_2$ and eigenvectors are computed to determine quad corners as $\text{centre} \pm 3\sqrt{\lambda} \cdot v$, clamped to screen bounds [S5, unofficial]. The fragment shader evaluates the Gaussian kernel $\exp(-\frac{1}{2} \mathbf{d}^T \Sigma_2^{-1} \mathbf{d})$ using interpolated quad coordinates [S5, unofficial]. This requires a third RGBA16F texture for rotation (quaternion xyzw) or repacked scale/position data [S5, unofficial].

### Isotropic Gaussian Splatting Rendering
A rendering technique for 3D Gaussian Splatting where each splat is rendered as an isotropic billboard (circle) using the maximum of the three axis scales, ignoring the rotation for the shape geometry [S5, unofficial]. This results in a hazy, over-bright appearance, identified as the 'P1 isotropic artefact' [S5, unofficial]. Per-splat data is stored in two RGBA16F textures, fetched by instance ID in the vertex shader [S5, unofficial]. Splats are rendered as hardware-instanced camera-facing quads with premultiplied-alpha blending, `depthWrite:false`, and `depthCulling:true` [S5, unofficial]. Instances are batched in groups of at most 65535 per draw call [S5, unofficial]. Sorting complexity is $O(n \log n)$ performed on the CPU [S5, unofficial].

### Anisotropic Gaussian Splatting Projection
A rendering technique that projects 3D Gaussian ellipses onto the screen space by computing a 2x2 covariance matrix, allowing for accurate anisotropic rendering of splats as ellipses rather than circles [S5, unofficial]. It adds a rotation texture or packs a quaternion and scales into a third RGBA16F texture [S5, unofficial]. It computes the 3D covariance matrix $\Sigma = R \cdot S \cdot S^T \cdot R^T$, projects it to screen space using the view Jacobian to obtain a 2x2 covariance matrix, eigen-decomposes it to find major and minor axes, and places quad corners on these axes [S5, unofficial]. This differs from isotropic rendering by using the full covariance matrix, reducing overdraw and providing a sharper image [S5, unofficial].

### Gaussian Splat Vertex Shader
A vertex shader for rendering Gaussian splats as quads [S6, unofficial]. It takes `SplatCount` (uint32), `DebugMode` (uint32: 0=off, 1=cluster colors), and `EnableNanite` (uint32: 1=Nanite enabled) as parameters [S6, unofficial]. It uses `ViewDataBuffer` (StructuredBuffer<FGaussianSplatViewData>) and `SortKeysBuffer` (StructuredBuffer<uint>) as input buffers [S6, unofficial].

## Operating characteristics
*   **Time Complexity:** Sorting is $O(n \log n)$ on the CPU [S5, unofficial]. Rendering is $O(n)$ for instanced drawing.
*   **Memory Complexity:** Requires storage for splat data (textures/buffers), order buffer, and view data. For 233k splats, re-sorting involves ~5.6 MB of texture re-upload [S5, unofficial].
*   **Performance:** Fill rate and overdraw are dominant factors. Anisotropic rendering reduces overdraw compared to isotropic max-axis discs [S5, unofficial]. CPU sorting is feasible up to ~300–500k splats; beyond that, LOD/pruning is needed [S5, unofficial].
*   **Strengths:** Simple implementation, leverages standard graphics APIs, good quality with anisotropic projection.
*   **Limitations:** CPU sorting bottleneck at high splat counts, isotropic approximation causes visual artifacts (haze), requires careful culling to avoid artifacts from behind-camera splats.
*   **When to Use:** Real-time visualization of static or slowly changing 3DGS scenes on desktop/mobile/web where CPU sorting is acceptable.
*   **When Not to Use:** Extremely high splat counts (>500k) without LOD, or when GPU-based sorting is required for performance.

## Background
Gaussian Splat Rendering (Screen-Space Quad) is based on the 3D Gaussian Splatting technique introduced by Kerbl et al. in 2023 [S1, S2, S3, unofficial]. It adapts the mathematical representation of 3D Gaussians into a rasterization-friendly format by projecting them into 2D screen-space quads. The method has been implemented in various contexts, including Unity (aras-p/UnityGaussianSplatting) [S2, unofficial], WebGL (gsplat.js) [S3, unofficial], and SceneView [S4, S5, unofficial]. The screen-space quad approach is a common implementation strategy for visualizing Gaussian splats in real-time renderers.
