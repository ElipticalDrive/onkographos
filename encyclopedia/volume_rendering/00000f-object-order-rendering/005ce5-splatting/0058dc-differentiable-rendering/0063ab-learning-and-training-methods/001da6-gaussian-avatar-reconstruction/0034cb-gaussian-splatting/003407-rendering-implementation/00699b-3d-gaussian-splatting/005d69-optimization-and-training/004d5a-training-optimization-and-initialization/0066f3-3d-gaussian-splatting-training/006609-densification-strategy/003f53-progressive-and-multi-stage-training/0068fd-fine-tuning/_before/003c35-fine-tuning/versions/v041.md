# Fine-tuning
Also called: 3DGS Fine-tuning, Gaussian Splatting Fine-tuning

## Overview
Fine-tuning in 3D Gaussian Splatting (3DGS) refers to the optimization phase where initial Gaussian primitives are refined to achieve high-fidelity reconstruction, often leveraging pretrained priors or specific loss functions to accelerate convergence and improve quality [S1]. It distinguishes itself from standard training by explicitly enabling the growing and pruning of primitives during the optimization process to reduce redundancy and memory consumption while maintaining photorealism [S1]. Unlike static initialization methods, fine-tuning dynamically adjusts the Gaussian population based on rendering errors or specific task requirements (e.g., inverse rendering, stylization) [S1, S2, S3].

## How it works
The fine-tuning process generally follows a two-phase structure: initialization via a feed-forward prediction or sparse point cloud, followed by differentiable optimization of geometry and color attributes [S1]. The core mechanism involves minimizing a loss function (typically L1 color loss, SSIM, or specialized losses for inverse rendering/stylization) while periodically densifying or pruning Gaussians based on rendering metrics [S1, S4].

### Inputs and Outputs
*   **Inputs:** Initial set of 3D Gaussians $\mathcal{G}_{init}$ (from SfM, feed-forward network, or synthetic points), input images/depths, camera poses.
*   **Outputs:** Optimized set of 3D Gaussians $\mathcal{G}_{final}$ with refined means $\mu$, covariances $\Sigma$, opacities $\alpha$, and spherical harmonic coefficients $\mathbf{c}$.

### Data Structures
The Gaussian set $\mathcal{G}$ is stored as a contiguous array or sparse structure. Each Gaussian $g_k$ contains:
*   $\mu_k \in \mathbb{R}^3$: Mean position.
*   $s_k \in \mathbb{R}^3$: Scale (vector).
*   $q_k \in \mathbb{R}^4$: Rotation (quaternion).
*   $\alpha_k \in \mathbb{R}$: Opacity.
*   $\mathbf{c}_k$: Spherical Harmonic coefficients.

### Steps
1.  **Initialization:** Generate initial Gaussians. This can be done via a direct feed-forward process predicting geometry and color [S1], or from a sparse point cloud [S4].
2.  **Optimization Loop:**
    *   Render the scene using differentiable rasterization.
    *   Compute loss $\mathcal{L}$ based on the specific variant (e.g., L1+SSIM for standard [S4], decomposition loss for inverse rendering [S2], feature match loss for stylization [S3]).
    *   Backpropagate to update Gaussian parameters using an optimizer (typically Adam) [S1, S2].
3.  **Densification/Pruning (Conditional):**
    *   Evaluate rendering metrics (opacity, depth error, color error) [S4].
    *   If metrics indicate holes or high error, split or clone Gaussians [S4].
    *   If Gaussians are redundant or have low opacity, prune them [S1].
4.  **Regularization (Optional):** Apply smoothing terms (e.g., Total Variation) to prevent overfitting or "forgetting" in continuous mapping scenarios [S2, S4].

### Formulas
*   **Opacity Rendering:** The accumulated opacity $O$ at a pixel is calculated as [S4]:
    $$ O = \sum_{i \in N} \alpha_i \prod_{j=1}^{i-1} (1 - \alpha_j) $$
    where $N$ are the 2D Gaussians overlapping the pixel, sorted by depth, and $\alpha_i$ is the alpha value of the $i$-th Gaussian.

*   **Rendering-Guided Densification Thresholds:** New Gaussians are added if [S4]:
    $$ O(x, y) < \tau_{opa} \quad \text{or} \quad E_{color}(x, y) > \tau_{color} \quad \text{or} \quad \frac{E_{depth}(x, y)}{D(x, y)} > \tau_{depth} $$
    where $E_{color} = |\hat{C} - C|$, $E_{depth} = |\hat{D} - D|$, and $D(x,y)$ is the rendered depth used to normalize the depth error.

*   **Inverse Rendering Loss (GS-IR):** The total loss in the decomposition stage is [S2]:
    $$ \mathcal{L}_d = \mathcal{L}_{shade} + \lambda_M \text{TV}_{mat} + \lambda_E \text{TV}_{light} $$
    where $\mathcal{L}_{shade}$ is the shading error, $\text{TV}_{mat}$ is the total variation of the material map, and $\text{TV}_{light}$ is the total variation of the light map.

### Parameters
*   **Learning Rate:** $1 \times 10^{-3}$ for Adam optimizer [S1].
*   **Iterations:** 30,000 for initial stage, 10,000 for decomposition stage in GS-IR [S2].
*   **Smoothing Weights (GS-IR):** $\lambda_{n-TV} = 5.0$, $\lambda_M = 1.0$, $\lambda_E = 0.01$ [S2].
*   **Thresholds (Rendering-Guided):** $\tau_{opa}, \tau_{color}, \tau_{depth}$ are predefined thresholds for opacity and error [S4].

### Edge Cases and Pitfalls
*   **Forgetting:** In continuous mapping (SLAM), parameters may overfit to the latest frame, degrading quality for previous frames. Regularization (SSIM, TV loss) is required to mitigate this [S4].
*   **Redundancy:** Feed-forward initialization may produce redundant Gaussians. Pruning is essential to reduce memory consumption [S1].
*   **Scale Sensitivity:** Depth error thresholds must be normalized by rendered depth to handle varying scene scales [S4].

    """
    Generic fine-tuning loop for 3D Gaussian Splatting.
    """
    gaussians = initial_gaussians
    optimizer = Adam(gaussians.parameters(), lr=config.lr)
    
    for iteration in range(config.total_iterations):
        # 1. Render
        rendered_color, rendered_depth, rendered_opacity = render(gaussians, poses)
        
        # 2. Compute Loss
        # Standard L1 + SSIM loss [S4]
        loss_color = L1(rendered_color, images.color)
        loss_ssim = SSIM(rendered_color, images.color)
        loss = loss_color + config.lambda_ssim * loss_ssim
        
        # Specialized losses can be added here (e.g., GS-IR [S2], StylizedGS [S3])
        
        # 3. Backpropagate
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        
        # 4. Densification/Pruning (if enabled)
        if iteration % config.densify_interval == 0:
            # Identify regions needing densification [S4]
            opacity_holes = rendered_opacity < config.threshold_opacity
            color_errors = abs(rendered_color - images.color) > config.threshold_color
            depth_errors = abs(rendered_depth - images.depth) / rendered_depth > config.threshold_depth
            
            densify_mask = opacity_holes | color_errors | depth_errors
            
            if config.enable_densification:
                densify_gaussians(gaussians, densify_mask, images.depth)
            
            if config.enable_pruning:
                prune_gaussians(gaussians, config.min_opacity)
                
    return gaussians

## Subtopics

### Two-stage Optimization
A fine-tuning strategy used in inverse rendering (e.g., GS-IR) that separates geometric/appearance optimization from material decomposition [S2]. Stage 1 minimizes color and normal loss for 30,000 iterations to optimize geometry and appearance. Stage 2 fixes geometry and appearance to minimize decomposition loss for 10,000 iterations to optimize material properties [S2]. It is chosen when decoupling material properties from geometry is required for physically based rendering [S2].

### StylizedGS
A fine-tuning method for controllable 3D stylization that performs color matching with a style image and uses a 3DGS filter to remove artifacts [S3]. It employs a nearest neighbor feature match loss and a depth preservation loss for optimization [S3]. It is chosen when artistic style transfer is required while preserving 3D geometry [S3].

### Gaussian Densification via Rendering Loss
A fine-tuning densification strategy that adds new Gaussians to unobserved regions (holes) or regions with high rendering error [S4]. It uses opacity, color, and depth thresholds to identify regions for densification [S4]. It is chosen for SLAM or continuous mapping tasks where maintaining map completeness and accuracy is critical [S4].

## Operating characteristics
*   **Time Complexity:** Depends on the number of Gaussians $N$ and views $V$. Rendering is $O(N)$ per pixel, optimization is dominated by backpropagation. Fine-tuning with densification increases $N$ over time, potentially slowing down later iterations [S1, S4].
*   **Memory Complexity:** $O(N)$, where $N$ is the number of Gaussians. Fine-tuning with pruning can reduce $N$ compared to feed-forward initialization [S1].
*   **Performance:** Fine-tuning with pretrained priors (e.g., EVolSplat) accelerates convergence and reduces memory consumption compared to training from scratch [S1]. Rendering-guided densification improves map quality in SLAM [S4].
*   **Strengths:** High fidelity, flexibility to incorporate various losses (stylization, inverse rendering), ability to handle sparse inputs via densification [S1, S3, S4].
*   **Limitations:** Requires careful tuning of thresholds and learning rates. Prone to "forgetting" in continuous mapping without regularization [S4].

## Background
Fine-tuning in 3DGS emerged as a refinement of the original 3DGS method to address limitations in initialization, redundancy, and specific task requirements. EVolSplat introduced fine-tuning with feed-forward initialization to accelerate convergence and reduce memory [S1]. GS-IR applied fine-tuning to inverse rendering, separating geometry and material optimization [S2]. StylizedGS adapted fine-tuning for artistic style transfer [S3]. Rendering-guided densification was proposed for SLAM to handle unobserved regions and view-dependent errors [S4].
