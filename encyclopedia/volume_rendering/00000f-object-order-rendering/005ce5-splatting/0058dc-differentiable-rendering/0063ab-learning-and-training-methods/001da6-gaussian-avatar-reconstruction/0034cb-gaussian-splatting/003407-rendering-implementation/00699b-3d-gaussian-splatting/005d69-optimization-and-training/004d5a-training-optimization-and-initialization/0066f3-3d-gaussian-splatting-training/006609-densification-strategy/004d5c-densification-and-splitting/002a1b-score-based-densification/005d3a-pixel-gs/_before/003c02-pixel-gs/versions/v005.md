# Pixel-GS

Also called: AbsGS / Pixel-GS Densification, Better densification triggers, Pixel-GS Densification, Pixel-based densification, Projected area gradient scaling

## Overview
Pixel-GS is a densification strategy for 3D Gaussian Splatting that modifies the gradient-based splitting signal to account for the spatial footprint of each Gaussian primitive. It addresses the baseline's tendency to under-densify regions by scaling the positional gradient by the number of pixels a Gaussian influences and applying a depth-dependent scaling factor to suppress floaters [S1][S2, S3, unofficial]. It yields state-of-the-art rendering quality compared to standard 3DGS, though it typically results in a higher number of Gaussian primitives [S1].

## How it works
Pixel-GS operates within the densification loop of 3D Gaussian Splatting training. It replaces the standard densification trigger (average magnitude of positional gradient) with a pixel-weighted, depth-aware metric [S3, unofficial].

**Inputs and Outputs:**
- Input: Current set of 3D Gaussians $\mathcal{G}$, camera poses $\{C_i\}$, input images $\{I_i\}$, and accumulated gradients $\nabla_{\mathbf{p}}$ for each Gaussian's position $\mathbf{p}$.
- Output: A subset of Gaussians selected for splitting (cloning + perturbation) based on the modified score.

**Data Structures:**
- Each Gaussian $g_j$ maintains:
  - Position $\mathbf{p}_j \in \mathbb{R}^3$
  - Covariance $\Sigma_j$ (or scale/rotation parameters)
  - Opacity $\alpha_j$
  - Accumulated positional gradient magnitude $G_j$ (reset periodically or maintained continuously)
  - Pixel coverage count $N_{pix, j}$ (number of pixels influenced by $g_j$ across all views)

**Steps:**
1. **Render and Backpropagate:** Render the scene from all training viewpoints. Compute the photometric loss $\mathcal{L}$ and backpropagate to obtain positional gradients $\nabla_{\mathbf{p}_j}$ for each Gaussian $g_j$.
2. **Accumulate Pixel Influence:** For each Gaussian $g_j$, count the number of pixels $N_{pix, j}$ it contributes to in the rendered images across all viewpoints. This is typically derived from the alpha-blending accumulation weights or the rasterization footprint [S1][S2, unofficial].
3. **Compute Depth-Aware Gradient Score:** Calculate the densification score $S_j$ for each Gaussian. The score scales the absolute positional gradient by the pixel coverage and applies a distance-dependent factor to suppress floaters in the background [S1][S2, S3, unofficial].
   $$ S_j = \left( \sum_{v \in \text{views}} |\nabla_{\mathbf{p}_j^{(v)}}| \right) \cdot N_{pix, j} \cdot f(d_j) $$
   Where:
   - $|\nabla_{\mathbf{p}_j^{(v)}}|$ is the magnitude of the positional gradient for Gaussian $j$ in view $v$. Note: Pixel-GS sums absolute gradients across views rather than averaging [S3, unofficial].
   - $N_{pix, j}$ is the total number of pixels influenced by $g_j$ across all views [S1].
   - $d_j$ is the depth (distance to camera) of Gaussian $j$.
   - $f(d_j)$ is a depth-dependent scaling factor. While the exact function is not specified in the sources, it is designed to suppress densification in distant regions to prevent floaters [S1]. [G] A common implementation uses an inverse depth or exponential decay, e.g., $f(d_j) = 1/d_j$ or $e^{-d_j}$, to reduce the score for far-away Gaussians.
4. **Select for Splitting:** Compare $S_j$ against a threshold or select the top-$k$ Gaussians with the highest scores. These Gaussians are candidates for splitting.
5. **Split:** For each selected Gaussian $g_j$:
   - Clone $g_j$ to create two new Gaussians.
   - Perturb the position of the clone slightly (e.g., along the normal or random direction).
   - Adjust the scale and opacity of the parent and child to maintain coverage [G] (standard 3DGS splitting procedure).

**Parameters:**
- Threshold for splitting: Not given in the sources. [G] Typically a percentile-based threshold (e.g., top 10% of gradients) or a fixed count.
- Depth scaling factor $f(d_j)$: Not given in the sources. [G] Inverse depth is a common heuristic.

**Edge Cases and Pitfalls:**
- **Precision:** Summing gradients across views can lead to large values for Gaussians visible in many views. Normalization may be required if scores are compared across different training steps.
- **Boundaries:** Gaussians at the edge of the scene may have lower $N_{pix, j}$ due to partial visibility, potentially leading to under-densification at boundaries.
- **Degenerate Input:** If a Gaussian has zero gradient, it will not be split, which is correct behavior.

## Operating characteristics
- **Time Complexity:** The additional cost is proportional to the number of Gaussians and views, as pixel coverage must be tracked and gradients summed. This is negligible compared to the rendering and backpropagation steps.
- **Memory Complexity:** Requires storing $N_{pix, j}$ and accumulated gradients for each Gaussian. This is $O(N)$ where $N$ is the number of Gaussians.
- **Measured Performance:** Yields state-of-the-art rendering quality compared to standard 3DGS [S1]. However, it typically results in a higher number of Gaussian primitives [S1].
- **Strengths:** Recovers detail that the baseline misses by weighting gradients by pixel coverage [S3, unofficial]. Suppresses floaters via depth scaling [S1].
- **Limitations:** Higher number of Gaussians increases memory usage and potentially rendering time if not optimized.
- **When to use:** When high reconstruction quality is prioritized over model size and rendering speed.
- **When not to use:** When memory or rendering speed is constrained, or when the scene is simple and the baseline is sufficient.

## Background
Pixel-GS was introduced as part of the evolution of 3D Gaussian Splatting densification strategies. It differs from the original baseline by changing the densification signal from the average magnitude of the positional gradient to a sum of absolute gradients weighted by pixel coverage [S3, unofficial]. It is related to AbsGS, which also uses absolute gradients but without the pixel coverage weighting [S2, unofficial]. The method is cited in recent surveys of 3D Gaussian Splatting advancements [S1].
