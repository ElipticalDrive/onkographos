# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific implementation parameters, data structures, and optimization strategies required to train and render 3D Gaussian Splatting (3DGS) scenes efficiently. It addresses the core problem of translating the mathematical formulation of differentiable volume rendering into high-performance code, focusing on memory management, precision handling, and training loop stability. It sets itself apart from sibling articles by providing concrete implementation values (e.g., SH degree, loss weights, iteration counts) and addressing specific pitfalls like optimization instability and hardware-specific bottlenecks, rather than describing the general algorithmic flow [S1, S5, S14, unofficial].

## How it works

### Inputs and Outputs
**Inputs:**
*   A set of $N$ training images with known camera poses (intrinsics $K$, extrinsics $R, t$) [S1, unofficial][S3].
*   An initial sparse point cloud (typically from Structure-from-Motion) to initialize Gaussian means [S1, unofficial][S3].
*   Hyperparameters: Learning rate, iteration budget, loss weights, and densification thresholds [S1, S14, unofficial].

**Outputs:**
*   A set of $K$ 3D Gaussians $G_K = \{G_k | k = 1, ..., K\}$, each defined by learnable parameters [S3].
*   Rendered novel views and semantic/feature maps if applicable [S1, unofficial][S3].

### Data Structures
Each Gaussian $G_k$ stores the following attributes [S3]:
*   **Position ($p_k$):** $\mathbb{R}^3$ (3D coordinates).
*   **Opacity ($\alpha_k$):** Scalar in $[0, 1]$.
*   **Rotation ($q_k$):** $\mathbb{R}^4$ (Quaternion) or $\mathbb{R}^9$ (Rotation matrix).
*   **Scaling ($s_k$):** $\mathbb{R}^3$ (Scale factors along principal axes).
*   **Spherical Harmonics (SH):** $\mathbb{R}^{3 \times 16}$ for SH degree 1, representing view-dependent color coefficients [S3].
*   **Semantic Code ($\beta$):** $\mathbb{R}^3$ (Optional, for semantic methods like FAST-Splat) [S1, unofficial].

**Rasterization Data:**
*   **Tile-based Sorting:** Gaussians are sorted per tile (e.g., $16 \times 16$ pixels) based on depth [S3].
*   **Feature Vectors:** During rasterization, feature vectors (color, SH, semantic) are fetched. Half-precision (FP16) memory fetches are used to reduce register pressure [S2].

### Numbered Steps

1.  **Initialization:** Initialize Gaussian means, covariances (from scaling/rotation), opacities, and SH parameters from the SfM point cloud [S1, unofficial][S3].
2.  **Training Loop (Per Iteration):**
    a.  Randomly select one training image (camera pose $\tau_i$, intrinsics $\kappa$) [S3][S14, unofficial].
    b.  **Forward Pass (Rasterization):**
        i.  Project 3D Gaussians to 2D screen space using camera parameters [S3].
        ii. Sort Gaussians by depth within each tile [S3].
        iii. Render color $C$ via alpha blending:
        $$ C(x) = \sum_{k \in \text{tile}} \alpha_k c_k G_k^{2D}(x) \prod_{t=1}^{k-1} (1 - \alpha_t G_t^{2D}(x)) $$
        where $G_k^{2D}$ is the projected 2D Gaussian distribution [S3].
    c.  **Loss Computation:**
        i.  Compute photometric loss $\mathcal{L}_{gs}$:
        $$ \mathcal{L}_{gs} = (1 - \lambda) \sum_{I \in D} \| I - \hat{I} \|_1 + \lambda \mathcal{L}_{D-SSIM} $$
        where $\lambda \approx 0.2$ [S1, S14, unofficial].
        ii. If semantic training is active, compute cross-entropy loss $\mathcal{L}_{ce}$ and total loss $\mathcal{L}_{sgs} = \mathcal{L}_{gs} + \mathcal{L}_{ce}$ [S1, unofficial].
        iii. If perceptual wrapper is active, compute Wasserstein Distortion loss $\mathcal{L}_{WD}$ [S5, unofficial].
    d.  **Backward Pass:** Compute gradients of $\mathcal{L}$ with respect to Gaussian parameters [S14, unofficial].
    e.  **Optimization Step:** Update parameters using Adam optimizer (learning rate $1 \times 10^{-3}$) [S6][S14, unofficial].
    f.  **Densification/Pruning:** Periodically (e.g., every 100 iterations) adjust Gaussian count based on gradient magnitude and opacity thresholds [S14, unofficial].

### Formulas
*   **Alpha Blending:** See Step 2.b.iii [S3].
*   **Normal Consistency (for Relightable GS):** $\mathcal{L}_n = \| \mathcal{N} - \tilde{\mathcal{N}} \|_2$, where $\mathcal{N}$ is rendered normal and $\tilde{\mathcal{N}}$ is pseudo-normal from depth [S4].
*   **Plücker Embedding (for Perceptual Wrapper):** $P(x, y) = (d, o \times d)$, where $d = \frac{R K^{-1}[x,y,1]^T}{\|R K^{-1}[x,y, 1]^T\|}$ [S5, unofficial].
*   **Scene Extent Correction:** $e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \| \bar{C} - p_i \|_2$, where $\bar{C} = \frac{1}{N_{\text{cam}}} \sum_{i=1}^{N_{\text{cam}}} C_i$ [S7].

### Parameters
*   **SH Degree:** 1 (commonly used for balance of quality/speed) [S6].
*   **Learning Rate:** $1 \times 10^{-3}$ [S6].
*   **Loss Weight ($\lambda$):** 0.2 [S1, unofficial][S16].
*   **Normal Gradient Threshold ($T_n$):** $2 \times 10^{-9}$ [S4].
*   **Training Iterations:** 30,000 (standard) [S14, unofficial]; 15,000 for Stage 1 in Perceptual Wrapper [S5, unofficial].
*   **Volume Dimensions (for Urban Scenes):** $128 \times 320 \times 640$ (voxel size 0.1m) [S6].

### Edge Cases and Pitfalls
*   **Optimization Instability:** Directly optimizing with Wasserstein Distortion (WD) loss from the start can destabilize training if densification/pruning are still active. Solution: Use a two-stage approach where Stage 1 (15,000 iterations) optimizes only 3DGS geometry, and Stage 2 activates the perceptual wrapper [S5, unofficial].
*   **Scene Extent Bias:** Default scene extent calculation based on furthest camera can bias splitting/pruning if cameras are clustered (e.g., orbiting a small object). Solution: Calculate extent based on SfM points [S7].
*   **Uniform Blur Degeneration:** If per-Gaussian scale offsets ($\delta s_j$) are predicted as constant, the method degrades to uniform Gaussian blur. Ensure the MLP predicts variable offsets [S8].
*   **Interpolation Error Accumulation:** In sparse rendering via viewpoint transformation, quality degrades as the number of transformed frames increases. Limit the number of consecutive transformed frames [S12].

### Pseudocode

```python
def train_3dgs(training_images, initial_points, num_iterations=30000):
    # Initialize Gaussians from SfM points
    gaussians = initialize_gaussians(initial_points)
    
    # Optimizer setup
    optimizer = Adam(gaussians.parameters(), lr=1e-3)
    
    for iteration in range(num_iterations):
        # 1. Select random image
        image_idx = random_choice(len(training_images))
        image = training_images[image_idx]
        camera_pose = image.pose
        intrinsics = image.intrinsics
        
        # 2. Forward Pass: Rasterization
        # Project Gaussians to 2D
        projected_gaussians = project_gaussians(gaussians, camera_pose, intrinsics)
        
        # Sort by depth within tiles
        sorted_gaussians = sort_gaussians_by_depth(projected_gaussians)
        
        # Render image via alpha blending
        rendered_image = alpha_blend(sorted_gaussians)
        
        # 3. Loss Computation
        # Photometric Loss
        l1_loss = l1_loss(rendered_image, image.gt_image)
        ssim_loss = d_ssim_loss(rendered_image, image.gt_image)
        lambda_param = 0.2
        loss = (1 - lambda_param) * l1_loss + lambda_param * ssim_loss
        
        # Optional: Semantic Loss (if enabled)
        if semantic_training_enabled:
            semantic_map = render_semantic_map(sorted_gaussians)
            ce_loss = cross_entropy_loss(semantic_map, image.gt_semantics)
            loss = loss + ce_loss
            
        # Optional: Perceptual Wrapper (if enabled and iteration > 15000)
        if perceptual_wrapper_enabled and iteration > 15000:
            # Compute Plücker embeddings
            plucker_embeddings = compute_plucker_embeddings(intrinsics, camera_pose)
            # Generate noise pyramid
            noise_pyramid = generate_noise_pyramid(image.resolution)
            # Synthesis network forward pass
            residual = synthesis_network(rendered_image, noise_pyramid, plucker_embeddings)
            final_image = rendered_image + residual
            wd_loss = wasserstein_distortion_loss(final_image, image.gt_image)
            loss = wd_loss + regularization_loss
            
        # 4. Backward Pass
        optimizer.zero_grad()
        loss.backward()
        
        # 5. Optimization Step
        optimizer.step()
        
        # 6. Densification/Pruning (every 100 iterations)
        if iteration % 100 == 0:
            densify_and_prune(gaussians, optimizer)
            
    return gaussians
```

### [LangSplat Training Procedure](12438-langsplat-training-procedure.md)
Optimizes 3DGS scenes to incorporate semantic language features alongside photometric rendering. It distinguishes itself by conditionally including language feature loss and disabling densification/pruning during language-aware training [12438-langsplat-training-procedure.md].

### [DeSplat](12925-desplat.md)
Decomposes the 3DGS scene into static and per-view distractor Gaussians to solve transient occluder corruption. It sets itself apart by relying solely on volume rendering and photometric loss without external semantic models [12925-desplat.md].

### [360 Gaussian Splatting](12929-360-gaussian-splatting.md)
Generates 3D representations from 360-degree images by modifying the rasterizer for spherical rendering and using OpenSfM. It sets itself apart from standard implementations that assume perspective cameras [12929-360-gaussian-splatting.md].

### [Data Compression and Storage Optimization](12943-data-compression-and-storage-optimization.md)
Reduces the memory footprint of 3DGS by compressing numerical representations, clustering parameters, or using neural fields. It distinguishes itself by focusing on data density rather than rendering throughput [12943-data-compression-and-storage-optimization.md].

### [Bézier-boundary gradient approximation](13137-b-zier-boundary-gradient-approximation.md)
Approximates gradients of discontinuous indicator functions with respect to Bézier curve control points, enabling backpropagation in discontinuity-aware rendering [13137-b-zier-boundary-gradient-approximation.md].

### [Discontinuity-aware Gaussian Splatting](13138-discontinuity-aware-gaussian-splatting.md)
Enables 3DGS to represent sharp boundaries by introducing "pre-scissoring" along Bézier curves and using Bézier-boundary gradient approximation [13138-discontinuity-aware-gaussian-splatting.md].

### [SOGS (Second-Order Anchor for Advanced 3D Gaussian Splatting)](13171-sogs-second-order-anchor-for-advanced-3d-gaussian-splatting.md)
Uses covariance-based feature augmentation to capture co-variation patterns, allowing smaller feature vectors without sacrificing detail [13171-sogs-second-order-anchor-for-advanced-3d-gaussian-splatting.md].

### [TraGraph-GS](14454-tragraph-gs.md)
Employs graph-based adaptive spatial partitioning and regularization constraints for large-scale scenes. It sets itself apart by constructing a camera connectivity graph for balanced subgraphs [14454-tragraph-gs.md].

### [Explicit 4D Gaussian Splatting](14584-explicit-4d-gaussian-splatting.md)
Achieves memory efficiency in dynamic scenes by separating Gaussians into static and dynamic categories and explicitly sampling positions/rotations at sparse timestamps [14584-explicit-4d-gaussian-splatting.md].

### [Color and Appearance Modeling](14740-color-and-appearance-modeling.md)
Addresses limitations of fixed SH representation by introducing dynamic mechanisms to modulate radiance/opacity based on spatial position, viewing direction, or image context [14740-color-and-appearance-modeling.md].

### GS-IR (Gaussian Splatting for Internal Rendering)
An inverse rendering approach using forward mapping volume rendering to estimate geometry, material, and illumination. It sets itself apart from NeRF-based methods by using 3D Gaussians for real-time efficiency [14852-gs-ir.md].

### Corrected Scene-Extent
Calculates scene extent based on SfM points rather than camera positions to avoid bias from camera distribution [S7].

### Selective Defocus Blurring
Predicts per-Gaussian scale offsets to create pixel-wise variable blur kernels matching spatially varying scene blurriness [S8].

A self-supervised denoising method for sparse-view 3DGS combining unsupervised image denoising (Noise2Void) with differentiable 3DGS [S9].

### Model-based depth estimation for volume parameter update

### Multi-Scale Constraint
Applies different scales to Gaussians based on viewer distance using position-aware point adaptive control [S11].

### LS-Gaussian Viewpoint Transformation
Leverages inter-frame continuity by transforming the viewpoint between consecutive frames for efficient sparse rendering [S12].

### LS-Gaussian Accelerator Architecture
A hardware architecture co-designed with LS-Gaussian to support workload-aware mapping and streaming pipelines [S12].

### GS-IR (Gaussian Splatting for Internal Rendering)
A plane-based internal rendering framework that replaces exterior-view supervision with cross-sectional supervision sampled from a volume [S13].

### 3D Gaussian Splatting Training Loop
Per-image error comparison against ground truth, using gradient descent for optimization over tens of thousands of iterations [S14, unofficial].

### Camera Localisation for Convergence Basin
Localizes camera pose by minimizing photometric error against ground-truth color image, fixing the initial Gaussian set [S15, unofficial].

### Sensitivity-Aware Vector Clustering for 3DGS Compression
Groups Gaussian colors and shape parameters into codebooks using sensitivity-aware vector clustering and quantization-aware training [S16].

### Relightable 3D Gaussians
Enhances vanilla 3D Gaussians with normal vectors, BRDF parameters, and incident lighting for photo-realistic relighting [S4].

## Operating characteristics

**Time and Memory Complexity:**
*   Training time is significantly reduced by single-phase optimization and neural-free semantic distillation (6x-8x faster than prior work) [S1, unofficial].
*   Rendering speed is improved by 18x-51x compared to prior semantic GSplat methods [S1, unofficial].
*   GPU memory usage is approximately 6x smaller than prior work due to explicit representation and efficient data structures [S1, unofficial].
*   Standard training runs for ~30,000 iterations [S14, unofficial].

**Measured Performance:**
*   On the 3D-OVS dataset 'Bed' scene, FAST-Splat achieved SSIM: 0.971, PSNR: 34.24, and used 1.02GB GPU memory [S1, unofficial].
*   On the Mip-NeRF 360 dataset, the Perceptual Wrapper (PW) method achieved a 6x reduction in bit-rate at equivalent perceptual quality [S5, unofficial].
*   GS-IR achieved PSNR improvement of up to 21.52 dB and SSIM improvement of up to 0.54 on KiTS23 CT and IXI MRI datasets [S13].

**Scaling:**
*   Large-scale scenes require divide-and-conquer training and Level-of-Detail (LoD) strategies (e.g., CityGaussian) [S3].
*   Distributed training and sharding are necessary for very large scenes [15108-distributed-training-and-sharding.md].

**Strengths and Limitations:**
*   **Strengths:** Real-time rendering, high visual fidelity, efficient memory usage compared to neural fields [S1, unofficial].
*   **Limitations:** Struggles with thin structures (addressed by normal gradient densification) [S4], transient occluders (addressed by DeSplat) [12925-desplat.md], and complex lighting (addressed by Relightable GS) [S4].

**When to Use:**
*   Use for real-time novel view synthesis, semantic segmentation, and inverse rendering tasks where speed and quality are critical [S1, unofficial][S4, S13].

**When Not to Use:**
*   Avoid for scenes with significant non-vacuum media effects without physics-based extensions [15148-physics-and-optical-modeling.md].
*   Avoid for sparse-view scenarios without denoising pre-processing [S9].

## Background

**Origin:**
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [12]. It represents scenes as a set of 3D Gaussians and uses differentiable rasterization for training.

**History and Development:**
Subsequent work has focused on improving training efficiency (FAST-Splat [S1, unofficial]), large-scale rendering (CityGaussian [S3]), semantic grounding (LangSplat [12438-langsplat-training-procedure.md]), and inverse rendering (GS-IR [S13]).

**Usage:**
Used in robotics, virtual reality, and 3D reconstruction pipelines [S1, unofficial][S12].
