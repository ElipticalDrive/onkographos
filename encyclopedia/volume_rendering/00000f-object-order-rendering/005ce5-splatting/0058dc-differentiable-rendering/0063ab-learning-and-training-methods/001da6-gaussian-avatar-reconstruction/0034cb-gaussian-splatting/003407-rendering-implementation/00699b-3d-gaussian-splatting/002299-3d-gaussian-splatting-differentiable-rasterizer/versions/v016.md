# 3D Gaussian Splatting Differentiable Rasterizer

Also called: 3D Gaussian Rasterization and Rendering, 3DGS Renderer, 3DGS rasterization pipeline, Differentiable Gaussian Rasterization, differentiable splatting

## Overview
The 3D Gaussian Splatting Differentiable Rasterizer is a screen-space rendering engine that projects a set of 3D Gaussian primitives into 2D ellipses and alpha-composites them to produce an RGB image, while simultaneously computing exact gradients for all Gaussian parameters (position, scale, rotation, opacity, color) with respect to the rendered pixels [S3][S12, unofficial]. Unlike volumetric ray-marching methods such as NeRF, which integrate density along rays, this method performs discrete splatting and alpha blending in image space, enabling real-time rendering speeds and efficient gradient-based optimization of scene representations [S2, S7]. It sets itself apart from its siblings by providing a fully differentiable, tiled CUDA-based (or CPU-based) pipeline that handles frustum culling, depth sorting, and basis function evaluation in a single coherent pass, serving as the core differentiable link between 3D scene parameters and 2D image loss [S9, S12, unofficial].

## How it works
### Inputs and Outputs
**Inputs:**
*   **Gaussian Parameters:** A set of $N$ 3D Gaussians. Each Gaussian $i$ is defined by:
    *   Mean position $\boldsymbol{\mu}_i \in \mathbb{R}^3$ [S3].
    *   Covariance $\boldsymbol{\Sigma}_i \in \mathbb{R}^{3 \times 3}$, typically decomposed into a scaling vector $\mathbf{s}_i \in \mathbb{R}^3$ and a rotation quaternion $\mathbf{q}_i \in \mathbb{R}^4$ (or rotation matrix $\mathbf{R}_i \in SO(3)$) [S3].
    *   Opacity $o_i \in \mathbb{R}$ [S3].
    *   Color representation: Either pre-computed RGB colors $\mathbf{c}_i \in \mathbb{R}^3$ or Spherical Harmonics (SH) coefficients $\mathbf{c}_{i, \text{SH}}$ [S3][S4, unofficial].
*   **Camera Parameters:**
    *   View matrix $\mathbf{V} \in \mathbb{R}^{4 \times 4}$ (world-to-camera transformation) [S9, unofficial].
    *   Projection matrix $\mathbf{P} \in \mathbb{R}^{4 \times 4}$ (camera intrinsics and perspective projection) [S9, unofficial].
    *   Image dimensions: width $W$, height $H$ [S9, unofficial].
    *   Field of view tangents: $\tan(\text{FOV}_x/2)$, $\tan(\text{FOV}_y/2)$ [S8, unofficial].
    *   Principal point $(c_x, c_y)$ [S8, unofficial].
    *   Background color tensor $\mathbf{b} \in \mathbb{R}^3$ [S9, unofficial].
*   **Settings:**
    *   `scale_modifier`: Scalar multiplier for Gaussian scales (default 1.0) [S8, unofficial].
    *   `prefiltered`: Boolean flag indicating if colors are pre-filtered (typically False) [S8, unofficial].
    *   `backward_geometry`: Boolean flag for geometry gradient computation [S6, unofficial].

**Outputs:**
*   **Rendered Image:** $\hat{\mathbf{C}} \in \mathbb{R}^{H \times W \times 3}$ [S3].
*   **Rendered Opacity/Transmittance:** $\hat{\mathbf{A}} \in \mathbb{R}^{H \times W}$ or transmittance buffer $\mathbf{T}$ [S5, unofficial].
*   **Gradients:** $\frac{\partial \mathcal{L}}{\partial \boldsymbol{\mu}_i}$, $\frac{\partial \mathcal{L}}{\partial \mathbf{s}_i}$, $\frac{\partial \mathcal{L}}{\partial \mathbf{q}_i}$, $\frac{\partial \mathcal{L}}{\partial o_i}$, $\frac{\partial \mathcal{L}}{\partial \mathbf{c}_i}$ [S12, unofficial].

### Data Structures
The rasterizer typically operates on tiled grids to optimize memory access.
*   **Gaussian Attributes:** Stored in contiguous tensors on the GPU (CUDA) or CPU.
    *   `means3D`: Shape $(N, 3)$, dtype float32 [S11, unofficial].
    *   `opacities`: Shape $(N,)$, dtype float32 [S11, unofficial].
    *   `scales`: Shape $(N, 3)$, dtype float32 [S11, unofficial].
    *   `rotations`: Shape $(N, 4)$, dtype float32 (quaternions) [S11, unofficial].
    *   `colors_precomp` or `shs`: Shape $(N, 3)$ or $(N, K, 3)$ where $K$ is SH bands [S6, unofficial].
*   **Intermediate Buffers:**
    *   `means2D`: Shape $(N, 2)$, screen-space coordinates [S9, unofficial].
    *   `cov2D`: Shape $(N, 3)$, upper-triangular 2D covariance matrix elements (or $2 \times 2$ matrix) [S5, unofficial].
    *   `conics`: Shape $(N, 3)$, inverse of the 2D covariance matrix (conic coefficients) [S5, unofficial].
    *   `radii`: Shape $(N,)$, integer radius of the bounding box for each Gaussian [S6, unofficial].
    *   `depths`: Shape $(N,)$, z-depth of each Gaussian in camera space [S5, unofficial].
*   **Tile/Sort Buffers:**
    *   `geomBuffer`: Stores tile IDs and Gaussian indices for sorting [S6, unofficial].
    *   `binningBuffer`: Stores sorted Gaussian indices per tile [S6, unofficial].
    *   `imgBuffer`: Stores per-pixel linked lists or pointers to contributing Gaussians [S6, unofficial].
*   **Context (for Backpropagation):**
    *   `saved_data`: Stores `px2gid` (pixel-to-gaussian ID map, int64_t), `imgWidth`, `imgHeight`, `errorMap`, `edgeMap`, `densificationInfo`, `xyAbsGrad` [S5, unofficial].
    *   `save_for_backward`: Stores input tensors `xys`, `conics`, `colors`, `opacity`, `background`, `cov2d`, `camDepths`, `finalTs` [S5, unofficial].

### Numbered Steps

1.  **Projection to Camera Space:**
    Transform 3D means $\boldsymbol{\mu}_i$ from world space to camera space using the view matrix $\mathbf{V}$:
    $$ \boldsymbol{\mu}_{i, \text{cam}} = \mathbf{V} \begin{bmatrix} \boldsymbol{\mu}_i \\ 1 \end{bmatrix} $$
    [S10, unofficial]

2.  **Covariance Transformation:**
    Compute the 3D covariance matrix $\boldsymbol{\Sigma}_{i, \text{cam}}$ in camera space. If decomposed into scale $\mathbf{s}_i$ and rotation $\mathbf{q}_i$:
    $$ \mathbf{R}_i = \text{QuaternionToMatrix}(\mathbf{q}_i) $$
    $$ \mathbf{S}_i = \text{Diag}(\exp(\mathbf{s}_i)) \quad \text{(or similar scaling function)} $$
    $$ \boldsymbol{\Sigma}_{i, \text{cam}} = \mathbf{J} \mathbf{R}_i \mathbf{S}_i \mathbf{S}_i^\top \mathbf{R}_i^\top \mathbf{J}^\top $$
    where $\mathbf{J}$ is the Jacobian of the perspective projection [S11, S12, unofficial]. The Jacobian $\mathbf{J}$ for perspective projection at depth $z$ is:
    $$ \mathbf{J} = \begin{bmatrix} \frac{f_x}{z} & 0 & -\frac{f_x x}{z^2} \\ 0 & \frac{f_y}{z} & -\frac{f_y y}{z^2} \end{bmatrix} $$
    [S11, unofficial]

3.  **Projection to 2D Screen Space:**
    Project the 3D covariance $\boldsymbol{\Sigma}_{i, \text{cam}}$ to 2D screen space $\boldsymbol{\Sigma}_{i, \text{2D}}$ using the upper-left $2 \times 2$ block of the projection matrix $\mathbf{P}$ and the Jacobian $\mathbf{J}$:
    $$ \boldsymbol{\Sigma}_{i, \text{2D}} = \mathbf{J} \boldsymbol{\Sigma}_{i, \text{cam}} \mathbf{J}^\top $$
    [S12, unofficial]
    Compute the 2D mean $\boldsymbol{\mu}_{i, \text{2D}}$ by projecting $\boldsymbol{\mu}_{i, \text{cam}}$:
    $$ \boldsymbol{\mu}_{i, \text{2D}} = \begin{bmatrix} \frac{f_x \cdot x_{\text{cam}}}{z_{\text{cam}}} + c_x \\ \frac{f_y \cdot y_{\text{cam}}}{z_{\text{cam}}} + c_y \end{bmatrix} $$
    [S10, unofficial]

4.  **Bounding Box and Culling:**
    Compute the axis-aligned bounding box (AABB) for each Gaussian in screen space, typically based on $3\sigma$ (99.7% coverage) of the 2D covariance eigenvalues [S11, unofficial]. Frustum cull Gaussians that do not intersect the image plane or have zero radius [S9, unofficial].

5.  **Tiling and Sorting:**
    Divide the image into tiles (e.g., $16 \times 16$ pixels) [S11, unofficial]. For each tile, identify overlapping Gaussians. Sort the Gaussians within each tile by depth (front-to-back) to ensure correct alpha compositing order [S3][S11, unofficial].

6.  **2D Gaussian Evaluation (Splatting):**
    For each pixel $(x, y)$ in a tile, and for each contributing Gaussian $i$ (sorted front-to-back):
    *   Compute the displacement vector $\mathbf{d} = [x - \mu_{i,x}, y - \mu_{i,y}]^\top$ [S10, unofficial].
    *   Compute the inverse 2D covariance (conic) $\mathbf{C}_i^{-1} = \boldsymbol{\Sigma}_{i, \text{2D}}^{-1}$ [S10, unofficial].
    *   Calculate the exponent (power) of the 2D Gaussian:
        $$ \text{power} = -\frac{1}{2} \mathbf{d}^\top \mathbf{C}_i^{-1} \mathbf{d} $$
        [S10, unofficial]
    *   Compute the blending coefficient (alpha) $\alpha_i$:
        $$ \alpha_i = o_i \cdot \exp(\text{power}) $$
        [S3]
        *Note: Some implementations clamp $\alpha_i$ to a maximum value (e.g., 0.99) to prevent numerical instability [S10, unofficial].*

7.  **Alpha Compositing:**
    Initialize transmittance $T = 1.0$ and accumulated color $\hat{\mathbf{C}} = \mathbf{b}$ (background) [S10, unofficial].
    For each Gaussian $i$ in front-to-back order:
    $$ \hat{\mathbf{C}} = \hat{\mathbf{C}} + \mathbf{c}_i \cdot \alpha_i \cdot T $$
    $$ T = T \cdot (1 - \alpha_i) $$
    [S3][S10, unofficial]
    where $\mathbf{c}_i$ is the color of the Gaussian at the viewing direction (evaluated from SH coefficients if applicable) [S4, unofficial].

8.  **Backpropagation (Gradient Computation):**
    Compute gradients of the loss $\mathcal{L}$ with respect to the output image $\hat{\mathbf{C}}$. Propagate these gradients back through the alpha compositing loop to compute $\frac{\partial \mathcal{L}}{\partial \alpha_i}$ and $\frac{\partial \mathcal{L}}{\partial \mathbf{c}_i}$ [S12, unofficial].
    *   **Gradient w.r.t. 2D Mean:** Use the chain rule through the exponent.
    *   **Gradient w.r.t. 2D Covariance:** Compute $\frac{\partial \text{power}}{\partial \boldsymbol{\Sigma}_{i, \text{2D}}}$ [S10, unofficial].
    *   **Gradient w.r.t. 3D Parameters:** Propagate gradients from 2D space to 3D space using the Jacobians of the projection and covariance transformation steps. This requires the analytic derivatives of the projection matrix and the rotation/scaling decomposition [S12, unofficial].
    *   **Gradient w.r.t. Opacity:** $\frac{\partial \mathcal{L}}{\partial o_i} = \frac{\partial \mathcal{L}}{\partial \alpha_i} \cdot \exp(\text{power})$ [S3].
    *   **Gradient w.r.t. Color:** $\frac{\partial \mathcal{L}}{\partial \mathbf{c}_i} = \alpha_i \cdot T \cdot \frac{\partial \mathcal{L}}{\partial \hat{\mathbf{C}}}$ [S3].

### Parameters
*   **$\theta$ (Adjustment Factor):** A small value (e.g., 0.05) added to ensure normalization occurs for interior splats, preventing division by zero or undefined gradients at boundaries [S1].
*   **$\sigma$ (Variance):** The variance setting for the Gaussian kernel, often set to 0.5 for normalization purposes [S1].
*   **`scale_modifier`:** A scalar multiplier (default 1.0) applied to Gaussian scales during rasterization [S8, unofficial].
*   **`tanfovx`, `tanfovy`:** Tangents of half the horizontal and vertical field of view, derived from camera intrinsics [S9, unofficial].
*   **`sh_degree`:** The degree of Spherical Harmonics used for color representation (e.g., 3) [S9, unofficial].
*   **`prefiltered`:** Boolean flag (default False) indicating if colors are pre-filtered [S9, unofficial].
*   **`antialiasing`:** Boolean flag (default False) for antialiasing [S9, unofficial].

### Edge Cases and Pitfalls
*   **Undefined Alpha Gradient:** If the alpha channel is not used in the loss function, `v_outAlpha` may be undefined during autograd. It must be initialized to `zeros_like(finalTs)` before backward computation [S5, unofficial].
*   **Frustum Culling:** Gaussians that are frustum culled or have a radius of 0 are invisible and excluded from gradient updates/splitting criteria. The `screenspace_points` tensor retains gradients only for visible Gaussians [S9, unofficial].
*   **Normalization at Boundaries:** Derivatives of splat weights do not account for resampling and need to be normalized by accumulated weights to match the forward pass. The adjustment factor $\theta$ ensures normalization always occurs for interior splats [S1].
*   **Memory Constraints:** Iterating over all Gaussians in a Python loop is slow and memory-intensive for large $N$. The implementation should use CUDA kernels for real-time performance [S10, unofficial].
*   **Singular Covariance:** The 2D covariance matrix must be positive definite. Clamping or adding a small epsilon to the diagonal may be necessary to prevent inversion errors [S12, unofficial].

## Subtopics

### [Gaussian Splat Rasterization (Vertex Shader)](3253-gaussian-splat-rasterization-vertex-shader.md)
This method implements the vertex shader stage of a GPU-based rasterizer for 3D Gaussian Splatting, transforming 3D Gaussian primitives into 2D screen-space ellipses for instanced rendering. It differs from fragment-based or compute-shader approaches by performing all geometric projection, covariance transformation, and ellipse basis computation within the vertex shader, passing only the final vertex positions and attributes to the rasterizer. It builds on [3D Gaussian Splatting Differentiable Rasterizer](2813-3d-gaussian-splatting-differentiable-rasterizer.md) by handling the specific data unpacking and frustum culling required for efficient vertex-driven splatting.

### [Opacity Rendering with SH Colors](7480-opacity-rendering-with-sh-colors.md)
This method performs a rendering pass that uses the model's actual opacity values and precomputes colors from Spherical Harmonics (SH) in Python before rasterization, allowing the rasterizer to use precomputed colors. It differs from rasterizers with built-in SH evaluation by deferring directional color computation to the Python host layer rather than evaluating SH inside the GPU kernel. The source code initializes the color tensor to ones, indicating that actual SH evaluation is expected to be performed externally or as a simplification in the provided snippet.

### [3D Gaussian Unscented Transform (3DGUT)](9154-3d-gaussian-unscented-transform-3dgut.md)
3D Gaussian Unscented Transform (3DGUT) is a rasterization-based rendering technique for 3D Gaussian particles that replaces the standard Elliptical Weighted Average (EWA) splatting formulation with the Unscented Transform (UT). It approximates 3D Gaussian particles using a set of sigma points to enable exact projection under arbitrary nonlinear camera projections, such as those with distortion or rolling shutter effects, while retaining the efficiency of rasterization. Unlike its sibling [3D Gaussian Splatting Differentiable Rasterizer](2813-3d-gaussian-splatting-differentiable-rasterizer.md), which relies on linearization via Jacobians, 3DGUT avoids Jacobian derivation and approximation errors by approximating the particle itself. This alignment with ray-tracing formulations also supports secondary rays for phenomena like reflections and refraction.

### [RoofGS Quadratic Form Expansion and Coefficient Folding](10258-roofgs-quadratic-form-expansion-and-coefficient-folding.md)
RoofGS Quadratic Form Expansion and Coefficient Folding is a rasterization optimization that expands the Gaussian quadratic form to separate pixel-dependent terms from Gaussian-dependent terms, allowing pixel coordinates to be hoisted out of the primitive loop and reducing instruction overhead in the innermost rendering loop. It sets itself apart from standard 3D Gaussian Splatting rasterization by pre-computing and folding opacity and scaling factors into the quadratic coefficients, enabling a streamlined FMA (Fused Multiply-Add) sequence for exponent evaluation.

### [Transmittance of Gaussian Splatting](10263-transmittance-of-gaussian-splatting.md)
This method establishes that the image formation model of Gaussian Splatting (alpha-blending) is equivalent to a ray-marching volumetric rendering model under assumptions of statistical independence and non-overlapping Gaussian primitives. It defines a continuous transmittance function and a view-dependent attenuation coefficient that yield the same color output as the standard discrete alpha-compositing rasterizer.

### [Rendering Pipeline and Configuration](11406-rendering-pipeline-and-configuration.md)
The Rendering Pipeline and Configuration family manages the translation of high-level scene state (3D Gaussians, camera matrices) into the specific numerical formats and validation checks required by the underlying CUDA rasterization backend. It solves the problem of undefined behavior, CUDA kernel crashes, and incorrect gradient flow caused by inconsistent tensor states, mismatched devices, or ambiguous input representations (e.g., providing both precomputed colors and Spherical Harmonics coefficients). It sets itself apart from the actual rasterization logic by focusing strictly on pre-computation checks, data normalization, and camera parameter extraction rather than the pixel-wise projection and blending operations.

### [Differentiable Backpropagation Mechanisms](11407-differentiable-backpropagation-mechanisms.md)
This family defines the mathematical and algorithmic mechanisms for computing gradients of the rendering loss with respect to 3D Gaussian parameters (position, scale, rotation, opacity, color) during the training of Gaussian Splatting models [G]. It solves the problem of enabling end-to-end optimization of scene representations by providing differentiable paths from the final pixel color to the underlying 3D attributes [G]. It differs from standard rasterization by explicitly deriving chain-rule gradients for alpha compositing and basis function evaluations, and from non-differentiable methods by supporting arbitrary gradient estimation strategies including per-splat parallelization and stochastic estimation [G].

### [Multi-view Mini-batch Rasterization](13386-multi-view-mini-batch-rasterization.md)
Multi-view mini-batch rasterization is a training strategy that renders multiple viewpoints simultaneously within a single mini-batch to reduce gradient variance and improve convergence speed. It modifies the standard 3D Gaussian Splatting (3DGS) rasterizer pipeline by introducing view-specific frustum culling and a composite sorting ID, allowing the rasterizer to process multiple camera views in parallel while significantly reducing memory consumption compared to naive multi-view rendering. Unlike single-view training, this method increases performance metrics (PSNR/SSIM) but introduces higher memory overhead and preprocessing time.

### [Rasterization Variant](17388-rasterization-variant.md)
This family defines the specific algorithmic variations of the differentiable rasterization pipeline used to render 3D Gaussians, extending the standard alpha-compositing logic of [3D Gaussian Splatting Differentiable Rasterizer](2813-3d-gaussian-splatting-differentiable-rasterizer.md). It addresses specialized requirements such as dynamic pruning gradients, X-ray physics, hybrid sigma fallbacks, and importance scoring, which the base rasterizer does not natively support.

### [Camera Pose Gradient Computation](18044-camera-pose-gradient-computation.md)
This method computes the gradient of the rendering loss $\mathcal{L}$ with respect to virtual camera poses $\mathbf{T}_i$ to enable the joint optimization of 3D Gaussian parameters and camera trajectories. It differs from standard differentiable rasterization by explicitly deriving the analytical Jacobian of the Gaussian mean transformation with respect to the camera pose, allowing gradients to flow from the image loss back to the pose parameters (rotation and translation). This is distinct from the parent method [3D Gaussian Splatting Differentiable Rasterizer](2813-3d-gaussian-splatting-differentiable-rasterizer.md), which primarily focuses on gradients with respect to Gaussian attributes, by extending the backpropagation path to include the extrinsic camera parameters.

### Gaussian Rasterization Kernel Fusion
This variant skips the concatenation of the two SH coefficient buffers (view-independent and view-dependent bands) and passes these buffers separately to the rasterization backend, fusing the concatenation into the rasterization kernel [S13, unofficial]. It also fuses the activation functions for the scales, rotations, and opacities of the Gaussians into the rasterizer to avoid PyTorch-related overhead [S13, unofficial]. Additionally, it fuses the gradient computations required for the added benefits during training [S13, unofficial].

### Isotropic Loss
This is a regularization term applied during RGB-D optimization to prevent Gaussians from over-stretching along the viewing axis, particularly in textureless regions [S14, unofficial]. Standard rasterisation does not account for elongation along the viewing axis, causing Gaussians to over-stretch without isotropic regularisation [S14, unofficial]. On TUM RGB-D, ATE RMSE changes from 1.43 cm (w/o $E_{iso}$) to 1.47 cm (Ours). On Replica RGB-D, Ours achieves 2.25 cm average ATE RMSE [S14, unofficial]. On TUM RGB-D, isotropic regularisation yields only marginal performance difference. On Replica RGB-D, it significantly improves camera tracking [S14, unofficial].

### Gaussian Normal Estimation
This method derives per-pixel normal estimates directly from the geometry of Gaussians during backpropagation, where adjustments to scale and rotation parameters update normal estimates without additional learnable parameters [S3]. Normals are transformed into camera space using the current camera transform and alpha-composited according to the rendering equation to provide a single per-pixel normal estimate: $\hat{\boldsymbol{N}} = \sum_{i \in N} \hat{\boldsymbol{n}}_i \alpha_i T_i$ [S3]. Incorrect normal orientation is handled by flipping the direction of normals at the beginning of training if the dot product between the current camera viewing direction and the Gaussian normal is negative [S3].

### Normal Prediction from Gaussians
This method approximates the normal direction of a Gaussian using the axis with the minimum scaling coefficient, assuming Gaussians become flat, disc-like during optimization [S3]. The geometric normal for Gaussian $i$ is $\hat{\boldsymbol{n}}_i = R \cdot \text{OneHot}(\arg\min(s_1, s_2, s_3))$, where $R \in SO(3)$ is the rotation matrix from quaternion $q$, and $s \in \mathbb{R}^3$ are scaling coefficients [S3]. The rotation matrix $R$ from quaternion $q=(w,x,y,z)^\top$ is:
$$ R = \begin{bmatrix} 1 - 2(y^2+z^2) & 2(xy-wz) & 2(xz+wy) \\ 2(xy+wz) & 1 - 2(x^2+z^2) & 2(yz-wx) \\ 2(xz-wy) & 2(yz+wx) & 1 - 2(x^2+y^2) \end{bmatrix} $$
[S3]

### Parallel N-Dimensional Gaussian Rasterization
This is a point-based alpha-blending technique for rasterizing feature maps alongside RGB, maintaining matching sizes for both to mitigate inconsistent spatial resolution inherent in tile-based rasterization. Dimensions are flexible to adapt to various foundational models [S15]. It rasterizes features using ParallelRasterizer with inputs X, C, Σ, A, F, V to produce rendered feature map Fs [S15]. If refinement step, it iterates over Gaussians (x, q, c, α, f): if opacity α < ε or Gaussian is too large, remove it [S15]. Learning rate for feature rendering optimization uses Adam optimizer [S15]. Learning rate for the Speed-up Module feature decoder network uses Adam optimizer [S15]. Image resolution strategy: render at 4 times lower resolution and upsample twice after 250 and 500 iterations [S15]. Standard exponential decay scheduling used similar to reference [11] [S15].

### Simplified Gaussian Rasterization
This method rasterizes Gaussians to compute accumulated weights and max counts without full color/SH evaluation [S16, unofficial]. It packs args (omits `flag_max_count`, includes `culling`), calls `_C.rasterize_gaussians_simp(*args)`, and returns `color, radii, accum_weights_ptr, accum_weights_count, accum_max_count` [S16, unofficial].

### Depth-aware Gaussian Rasterization
This method rasterizes Gaussians while computing depth, discriminants, and group indices for depth-based rendering [S16, unofficial]. It packs args (omits `flag_max_count`, includes `culling`), calls `_C.rasterize_gaussians_depth(*args)`, and returns dict with keys: `render, out_pts, rendered_depth, discriminants, gidx, accum_alpha` [S16, unofficial].

## Operating characteristics
*   **Time Complexity:** The rasterization step is $O(N \cdot T)$ where $N$ is the number of Gaussians and $T$ is the number of tiles, but effectively $O(P)$ where $P$ is the number of pixels, as each pixel only processes a small constant number of overlapping Gaussians. The sorting step is $O(N \log N)$ or $O(N)$ with bucket sort [S11, unofficial].
*   **Memory Complexity:** $O(N)$ for storing Gaussian parameters and intermediate buffers. The tile-based approach reduces memory pressure by processing small regions of the image at a time [S6, unofficial].
*   **Measured Performance:** The CUDA implementation achieves real-time rendering speeds (e.g., 1080p at 60+ FPS) on consumer-grade GPUs [S10, unofficial]. The Python/PyTorch loop implementation is interpreter-bound and slow, suitable only for pedagogical purposes [S10, unofficial].
*   **Scaling:** Scales well with the number of Gaussians due to the tiled and parallelized nature of the CUDA kernels. Memory usage is the primary bottleneck for very large scenes [S10, unofficial].
*   **Strengths:** Real-time rendering, differentiable, efficient gradient computation, high-quality novel view synthesis [S3][S12, unofficial].
*   **Limitations:** Memory-intensive for very large scenes, requires careful tuning of hyperparameters (e.g., $\theta$, scale modifier), and may suffer from artifacts in textureless regions without regularization [S10, S14, unofficial].
*   **When to Use:** Real-time rendering, training 3D Gaussian Splatting models, novel view synthesis [S3][S10, unofficial].
*   **When Not to Use:** Scenes with extreme occlusion where volumetric methods might be more robust, or when hardware does not support CUDA/GPU acceleration [S10, unofficial].

## Background
The 3D Gaussian Splatting Differentiable Rasterizer was introduced as part of the 3D Gaussian Splatting (3DGS) method by Kerbl et al. in 2023 [S3][S11, unofficial]. It was developed to address the slow rendering speeds of neural radiance fields (NeRF) by using explicit 3D Gaussian primitives and a fast, differentiable rasterization pipeline [S2, S7]. The method builds on earlier work in differentiable rendering and splatting, such as EWA splatting [S12, unofficial], and has become a standard technique for real-time 3D scene reconstruction and rendering [S3][S11, unofficial]. It is widely used in computer vision and graphics research for tasks such as novel view synthesis, SLAM, and 3D editing [S3][S14, unofficial].
