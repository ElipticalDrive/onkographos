# TraGraph-GS

Also called: Trajectory Graph-based Gaussian Splatting

## Overview
TraGraph-GS is a high-quality rendering method for arbitrary large-scale scenes that employs graph-based adaptive spatial partitioning, regularization constraints, and adaptive region selection [S1]. It addresses the challenges of memory overflow and rendering artifacts in large-scale 3D Gaussian Splatting by decoupling scene training into connected local regions and using a progressive rendering strategy for novel viewpoints [S1]. Unlike sibling methods that may rely on fixed grids or simple hierarchical trees, TraGraph-GS constructs a camera connectivity graph to ensure spatial coherence and balanced node distribution during partitioning [S1].

## How it works

### Inputs and Outputs
**Inputs:** A set of disordered scene photographs (images) and their associated camera poses.
**Outputs:** A set of 3D Gaussian primitives $\{G_i\}$ for each segmented region, a coarse global Gaussian representation, and rendered images for novel viewpoints.

### Data Structures
1.  **Camera Connectivity Graph:** $G = (V, E, w)$, where $V = \{v_1, ..., v_n\}$ are vertices (images), $E$ are edges, and $w: E \to \mathbb{R}$ are weights representing feature matching counts between image pairs [S1].
2.  **Local Gaussians:** A set of Gaussians $\{G_j\}$ trained independently for each segmented region $P_k$. Each Gaussian $G_j$ is defined by mean position $\mathbf{X}_j$, covariance $\Sigma_j$ (parameterized by rotation $\mathbf{R}_j$ and scaling $\mathbf{S}_j$), opacity $\alpha_j$, and color $\mathbf{c}_j$ [S1].
3.  **Global Gaussians:** A coarse set of Gaussians $\{G^g_m\}$ trained on downsampled data, avoiding densification [S1].

### Algorithm Steps

#### 1. Graph-Based Adaptive Spatial Partitioning
1.  **Construct Graph:** Build $G(V, E, w)$ from input images. Edge weights $w_{ij}$ are determined by the count of feature matches between image $i$ and image $j$ [S1].
2.  **BFS-Based Segmentation:** Divide $G$ into $k$ regions $\{P_1, ..., P_k\}$ ensuring connectivity and balanced node distribution [S1]:
    *   Initialize unassigned nodes $U = V$ [S1].
    *   Identify node $n$ with the highest degree in $U$ as the seed node [S1].
    *   Perform Breadth-First Search (BFS) from the seed, adding nodes to the current region until it contains $|V|/k$ nodes [S1].
    *   For remaining unassigned nodes, calculate a score $s_i$ relative to existing regions and assign them to maintain balance [S1].
3.  **Local Training:** Train local 3D Gaussians independently for each region $P_k$ [S1].

#### 2. Regularization Constraints
Apply constraints during local training to enhance texture and geometry [S1].

*   **Multi-View Constraint:**
    *   Render depth and normal maps for each image using alpha blending of local Gaussians [S1].
    *   For a pixel $p$ in a reference view, establish a spatial plane $(d, \mathbf{n})$ where $\mathbf{n}$ is the rendered normal and $d$ is the distance from the camera origin [S1].
    *   Use homography warping to project $p$ to corresponding pixel $p'$ in a neighborhood view [S1].
    *   Compute Normalized Cross Correlation (NCC) between patches at $p$ and $p'$ [S1].
    *   Add to loss:
        $$ L_{mv} = \sum_{p \in P_i} (1 - \text{NCC}(p, p')) $$
        [S1]

*   **Multi-Scale Constraint:**
    *   Define position-aware adaptive control $\gamma(\boldsymbol{\mu})$ based on Gaussian mean $\boldsymbol{\mu}$, camera center $\mathbf{c}$, and scene radius $r$ [S1]:
        $$
        \gamma(\boldsymbol{\mu}) =
        \begin{cases}
        1 & \text{if } \|\boldsymbol{\mu} - \mathbf{c}\|_2 < 2r \\
        \|\boldsymbol{\mu} - \mathbf{c}\|_2 / r - 1 & \text{if } \|\boldsymbol{\mu} - \mathbf{c}\|_2 \ge 2r
        \end{cases}
        $$
        [S1]
    *   **Cloning:** If directional gradient exceeds threshold AND $\max(\mathbf{s}) < g \cdot \gamma(\boldsymbol{\mu})$, clone the Gaussian [S1].
    *   **Splitting:** If directional gradient exceeds threshold AND $\max(\mathbf{s}) \ge g \cdot \gamma(\boldsymbol{\mu})$, split the Gaussian [S1].
    *   **Pruning:** Eliminate Gaussians where opacity $\alpha$ is below a threshold [S1].

*   **Total Loss:**
    $$ L = (1 - \lambda)L_1 + \lambda L_{SSIM} + L_{mv} $$
    where $L_1$ and $L_{SSIM}$ are standard image reconstruction losses [S1].

#### 3. Adaptive Region Selection for Novel Viewpoints
1.  **Global Training:** Train a coarse global Gaussian representation by downsampling point clouds and images, explicitly avoiding the densification process to prevent memory overflow [S1].
2.  **Matching Score Calculation:** Render the novel viewpoint using local Gaussians and global Gaussians separately. Calculate matching score $S$ for each local-global pair:
    $$ S = (1 - \lambda)L_1 + \lambda L_{SSIM} $$
    Higher scores indicate higher likelihood of visibility [S1].
3.  **Sorting:** Sort local Gaussians in descending order of matching scores: $G_1, G_2, ..., G_k$ [S1].
4.  **Progressive Rendering:** Compute pixel color $C$ using a progressive strategy based on an overlapped opacity threshold $\beta$ [S1]:
    *   Calculate projection opacity $o_i(p)$ for each sorted Gaussian $i$:
        $$ o_i(p) = \alpha_i \prod_{j=1}^{i-1} (1 - \alpha_j) $$
        [S1]
    *   Determine weight $w_i$ for Gaussian $i$ at pixel $p$:
        $$
        w_i =
        \begin{cases}
        o_i(p) & \text{if } \sum_{j=1}^{i-1} o_j(p) < \beta \\
        0 & \text{if } \sum_{j=1}^{i-1} o_j(p) \ge \beta
        \end{cases}
        $$
        [S1]
    *   Compute final color:
        $$ C(p) = \sum_{i=1}^{k} w_i c_i(p) $$
        [S1]

### Parameters
*   $k$: Number of segmented regions.
*   $\lambda$: Weight for SSIM loss (typical value not specified in sources, standard 3DGS uses 0.2).
*   $r$: Scene radius.
*   $\mathbf{c}$: Center of cameras.
*   $g$: Scaling factor for cloning threshold.
*   $\beta$: Overlapped opacity threshold for progressive rendering.

### Edge Cases and Pitfalls
*   **Memory Overflow:** Avoiding densification in global training is critical for large scenes [S1].
*   **Boundary Artifacts:** The progressive rendering strategy specifically addresses floating artifacts at region boundaries caused by Gaussian overlap or improper pruning [S1].
*   **Textureless Regions:** Multi-view constraints are essential for geometry reconstruction in these areas [S1].

## Operating characteristics

### Time and Memory Complexity
*   **Memory:** Reduced compared to monolithic 3DGS due to independent local training and coarse global representation. The BFS segmentation ensures balanced node distribution, preventing memory overflow from uneven region sizes [S1].
*   **Time:** Parallel training of local Gaussians accelerates the training phase. Novel viewpoint rendering involves sorting and progressive evaluation, which may add overhead compared to standard splatting but ensures quality [S1].

### Measured Performance
*   Evaluated on large-scale aerial (Mill-19, UrbanScene3D) and ground-level (SmallCity, Campus, Road, General) datasets [S1].
*   Handles scenes with thousands of images (e.g., 3,019 images in Sci-Art) [S1].

### Strengths and Limitations
*   **Strengths:** High-quality rendering for arbitrary large-scale scenes; handles varying distances via multi-scale constraints; avoids boundary artifacts [S1].
*   **Limitations:** Requires feature matching for graph construction; performance depends on the quality of the connectivity graph [S1].

### When to Use
*   Use for large-scale scenes where standard 3DGS fails due to memory constraints or boundary artifacts.
*   Use when high fidelity in textureless regions is required.

### When Not to Use
*   Not necessary for small-scale scenes where standard 3DGS performs well.
*   Not suitable if real-time performance is critical and the overhead of graph construction and progressive rendering is unacceptable.

## Background
TraGraph-GS was proposed to address the limitations of existing methods for large-scale scene rendering, such as VastGaussian, which used progressive partitioning but neglected structural information of feature correspondences [S1]. The method was published in IEEE Transactions on Pattern Analysis and Machine Intelligence in 2026 [S1].
