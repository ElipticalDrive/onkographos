# 3D Gaussian Splatting to Point Cloud

Also called: 3DGS to Point Cloud Conversion, 3DGS-to-PC, Gaussian Splatting Point Cloud Generation, Gaussian Splatting to Dense Point Clouds

## Overview
This method converts a trained 3D Gaussian Splatting (3DGS) scene representation into a dense, standard point cloud (PLY format) that visually approximates the original radiance field, enabling compatibility with general 3D software that does not support Gaussian primitives [S1, unofficial]. It distinguishes itself from sibling methods like [SuGaR Mesh Extraction](12580-sugar-mesh-extraction.md) by focusing on direct probabilistic sampling from the Gaussian distributions rather than optimizing a separate mesh or point set via differentiable rendering losses, although it optionally uses rendering to refine colors and visibility [S1, unofficial].

## How it works
The method transforms learnable Gaussian parameters into a set of discrete 3D points by sampling from their probability density functions, applying visibility and geometric constraints, and optionally re-rendering colors for high-fidelity appearance.

### Inputs and Outputs
**Inputs:**
*   **Gaussian Scene:** A PLY or SPLAT file containing $N$ Gaussians. Each Gaussian $i$ has:
    *   Position $\mu_i \in \mathbb{R}^3$
    *   Rotation $q_i \in \mathbb{R}^4$ (unit quaternion)
    *   Scale $s_i \in \mathbb{R}^3$
    *   Opacity $\omega_i \in [0, 1]$
    *   Spherical Harmonic (SH) coefficients $c_i$ (typically degree 3, 48 coefficients)
*   **Camera Transforms:** A file (COLMAP or Transform format) containing camera poses ($c2w$ matrices) and intrinsics (focal lengths, image dimensions) required for visibility estimation and color rendering [S1, unofficial].
*   **Settings:** Configuration parameters controlling sampling density, culling, and rendering quality (see Parameters).

**Outputs:**
*   **Point Cloud Data:** A PLY file containing points $\mathbf{p}$, colors $\mathbf{C}$, and optionally normals $\mathbf{n}$.
*   **Mesh (Optional):** A PLY mesh generated via Poisson surface reconstruction if `generate_mesh` is enabled.

### Data Structures
The implementation uses the following structures [S1, unofficial]:

**GaussPointCloudSettings:**

*   `num_points`: `int` (Default: 10,000,000)
*   `exact_num_points`: `bool` (Default: False)
*   `prioritise_visible_gaussians`: `bool` (Default: True)
*   `mahalanobis_distance_std`: `float` (Default: 2.0)
*   `camera_skip_rate`: `int` (Default: 0)
*   `render_colours`: `bool` (Default: True)
*   `min_opacity`: `float` (Default: 0.0)
*   `bounding_box_min`: `list[float]` (Default: None)
*   `bounding_box_max`: `list[float]` (Default: None)
*   `calculate_normals`: `bool` (Default: True)
*   `cull_large_percentage`: `float` (Default: 0.0)
*   `remove_unrendered_gaussians`: `bool` (Default: True)
*   `colour_resolution`: `int` (Mapped from `colour_quality`)
*   `max_sh_degree`: `int` (Default: 3)
*   `visibility_threshold`: `float` (Default: 0.05)
*   `surface_distance_std`: `float` (Default: None/Disabled)
*   `generate_mesh`: `bool` (Default: False)
*   `quiet`: `bool` (Default: False)
*   `device`: `str` (Default: 'cuda')

**PointCloudData:**
*   `points`: `torch.Tensor` of shape $(P, 3)$
*   `colours`: `torch.Tensor` of shape $(P, 3)$
*   `normals`: `torch.Tensor` of shape $(P, 3)$

### Parameters
*   `num_points`: Total target point count. Default: 10,000,000 [S1, unofficial].
*   `exact_num_points`: If True, forces the output to match `num_points` exactly (slower). Default: False [S1, unofficial].
*   `visibility_threshold`: Minimum accumulated contribution a Gaussian must have across rendered views to be included. Default: 0.05 [S1, unofficial].
*   `mahalanobis_distance_std`: Maximum Mahalanobis distance from the Gaussian center for sampled points. Default: 2.0 [S1, unofficial].
*   `colour_quality`: Quality preset for color rendering. Maps to resolution: `tiny`=180, `low`=360, `medium`=720, `high`=1280, `ultra`=1920, `original`=None. Default: `high` [S1, unofficial].
*   `surface_distance_std`: Culls Gaussians further than X standard deviations from predicted surfaces. Default: Disabled [S1, unofficial].
*   `cull_gaussian_sizes`: Percentage of largest Gaussians to remove. Default: 0.0 [S1, unofficial].
*   `min_opacity`: Minimum opacity threshold for inclusion. Default: 0.0 [S1, unofficial].
*   `camera_skip_rate`: Number of cameras to skip during visibility rendering. Default: 0 [S1, unofficial].
*   `generate_mesh`: Flag to enable mesh generation. Default: False [S1, unofficial].
*   `poisson_depth`: Depth for Poisson reconstruction. Default: 10 [S1, unofficial].
*   `laplacian_iterations`: Iterations for Laplacian mesh smoothing. Default: 10 [S1, unofficial].

### Algorithm Steps

1.  **Load and Validate Gaussians:**
    Load Gaussian parameters from the input file. Validate covariance matrices $\Sigma_i$ for positive semi-definiteness. If invalid (due to floating-point errors), clamp scales or cull the Gaussian [S1, unofficial].

2.  **Filter Gaussians:**
    Apply culling criteria to the set of $N$ Gaussians:
    *   **Opacity:** Remove if $\omega_i < \text{min\_opacity}$.
    *   **Bounding Box:** Remove if $\mu_i$ is outside `[bounding_box_min, bounding_box_max]`.
    *   **Size:** Remove the top `cull_gaussian_sizes`% of Gaussians ranked by surface area. Surface area $A_i$ is approximated from eigenvalues $\lambda_{i,1}, \lambda_{i,2}, \lambda_{i,3}$ of $\Sigma_i$:
        $$ a = \sqrt{\lambda_{i,1}}, \quad b = \sqrt{\lambda_{i,2}}, \quad c = \sqrt{\lambda_{i,3}} $$
        $$ A_i \approx 4\pi \left( \frac{a^p b^p + a^p c^p + b^p c^p}{3} \right)^{1/p}, \quad p=1.6075 $$
    *   **Visibility (Optional):** If `prioritise_visible_gaussians` is True, render the scene from all camera views to compute total contribution per Gaussian. Remove Gaussians with total contribution $< \text{visibility\_threshold}$ [S1, unofficial].

3.  **Calculate Point Allocation:**
    Determine the number of points $k_i$ to sample from each remaining Gaussian $i$.
    *   Calculate magnitude $M_i$ based on surface area $A_i$ and contribution $C_i$ (opacity if visibility not used, or rendered contribution if used):
        $$ M_i = \sqrt{A_i} \cdot C_i $$
    *   If `exact_num_points` is False, sample attempts are limited. If True, more attempts are made to hit the target count precisely [S1, unofficial].

4.  **Sample Points:**
    For each Gaussian $i$:
    *   Construct the 3D covariance $\Sigma_i = R_i S_i S_i^T R_i^T$.
    *   Sample points $\mathbf{p}$ from the multivariate normal distribution $\mathcal{N}(\mu_i, \Sigma_i)$.
    *   Reject samples where the Mahalanobis distance $d_M > \text{mahalanobis\_distance\_std}$:
        $$ d_M = \sqrt{(\mathbf{p} - \mu_i)^T \Sigma_i^{-1} (\mathbf{p} - \mu_i)} $$
    *   Add valid points to the global point cloud. If `generate_mesh` is True, a separate subset of points is generated specifically from "surface" Gaussians (identified by a predicted surface standard deviation threshold), capped at half the total requested points, with a fixed average of 25 points per surface Gaussian [S1, unofficial].

5.  **Render Colors (Optional):**
    If `render_colours` is True:
    *   Initialize a Gaussian renderer (CUDA or Python) with the loaded Gaussians and camera parameters.
    *   Iterate through camera views (skipping `camera_skip_rate` cameras if specified).
    *   Render the scene to obtain per-pixel colors and depths.
    *   Assign the rendered color to the corresponding points in the point cloud. If `no_render_colours` is True, points retain their original SH-derived colors or default values [S1, unofficial].

6.  **Calculate Normals (Optional):**
    If `calculate_normals` is True, compute normals for each point. For points sampled from a Gaussian, the normal can be derived from the gradient of the Gaussian density or by averaging the normals of the parent Gaussian's principal axes weighted by the sample's position relative to the mean [S1, unofficial].

7.  **Post-Processing and Output:**
    *   If `clean_pointcloud` is True, remove outliers using Open3D's statistical outlier removal.
    *   If `generate_mesh` is True, perform Poisson surface reconstruction on the surface point subset using `poisson_depth` and apply `laplacian_iterations` of smoothing.
    *   Save the final point cloud (and mesh) to PLY format [S1, unofficial].

def compute_covariance_from_params(scale, rot):
    """Sigma = R S S^T R^T"""
    S = torch.diag(scale)
    R = quaternion_to_matrix(rot)
    return R @ S @ S.T @ R.T

def sample_from_gaussian(mean, cov):
    """Sample from N(mean, cov)"""
    return torch.distributions.MultivariateNormal(mean, cov).sample()

def mahalanobis_distance(point, mean, cov):
    diff = point - mean
    # Solve cov @ x = diff for x, then sqrt(diff^T @ x)
    # Or use cholesky
    L = torch.linalg.cholesky(cov)
    diff_inv = torch.linalg.solve_triangular(L, diff, upper=False)
    return torch.norm(diff_inv)

## Operating characteristics
*   **Time Complexity:** Dominated by the visibility rendering step if `prioritise_visible_gaussians` is True, which is $O(N \cdot C \cdot R)$ where $N$ is Gaussians, $C$ is cameras, and $R$ is resolution. Sampling is $O(P)$ where $P$ is the number of output points.
*   **Memory Complexity:** $O(N + P)$. The Gaussian parameters are stored in memory, and the output point cloud scales with `num_points`.
*   **Performance:** Rendering colors at `high` quality (1280px) can be slow for large scenes. Using `cuda` renderer is significantly faster than `python`. Culling large Gaussians and using `camera_skip_rate` can reduce processing time.
*   **Strengths:** Produces high-quality, dense point clouds that closely mimic the original 3DGS appearance. Flexible culling and sampling options allow for noise reduction and mesh optimization.
*   **Limitations:** Requires camera poses for visibility-based culling and color rendering. The resulting point cloud is not a true geometric representation but a visual approximation. Mesh generation quality depends on the density and distribution of surface Gaussians.
*   **When to use:** When a standard point cloud format is needed for visualization or processing in software that doesn't support 3DGS.
*   **When not to use:** When precise geometric accuracy is required, or when the scene is too large for the visibility rendering step to be feasible.

## Background
3D Gaussian Splatting (3DGS) was introduced by Kerbl et al. in 2023 as a real-time radiance field representation. The conversion to point clouds is a practical utility developed by the community (e.g., Lewis-Stuart) to bridge the gap between specialized 3DGS viewers and general 3D tools. The method leverages the probabilistic nature of Gaussians to sample points, effectively discretizing the continuous field.
