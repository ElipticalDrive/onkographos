# Training Configuration and Hyperparameters

Also called: Decoder Training Setup, Training Configuration for Gaussian Splatting Decoder

## Overview
This article defines the specific hyperparameters, optimization schedules, and data sampling strategies required to train 3D Gaussian Splatting decoders, particularly in the context of 3D-aware generative models and downstream 3D classification tasks. It addresses the problem of configuring the Adam optimizer, learning rates, and camera sampling distributions to achieve convergence in explicit 3D space rendering. It differs from its parent, [Optimization Schedule and Densification](15107-optimization-schedule-and-densification.md), by focusing on the global training loop parameters (iterations, LR, batch size) rather than the dynamic primitive management (splitting, cloning, pruning) that occurs within the loop.

## How it works
### Inputs and Outputs
**Inputs:**
- Pre-trained GAN encoder weights (e.g., EG3D, PanoHead) [S1].
- Dataset (e.g., FFHQ, LPFF, FFHQ-H) [S1].
- Target task (Novel View Synthesis, Classification, Part Segmentation) [S1][S2, unofficial].

**Outputs:**
- Optimized Gaussian parameters (position $\mathbf{p}$, covariance $\mathbf{\Sigma}$, opacity $\alpha$, spherical harmonics coefficients $\mathbf{c}$) [S1].
- Trained decoder weights [S1].

### Data Structures
The training state maintains the standard 3DGS Gaussian attributes. For downstream protocols, Gaussians are grouped for processing:
- **Grouping:** Gaussians are organized into groups of fixed size (e.g., 32) [S2, unofficial].
- **Attributes:** All 14 attributes (position, rotation, scale, opacity, SH coefficients) are updated during full fine-tuning [S2, unofficial].

### Steps
1. **Initialization:** Initialize Gaussians from the pre-trained GAN's latent space or point cloud [S1][S2, unofficial].
2. **Camera Sampling:**
   - For full 360° scenes (e.g., PanoHead): Sample random cameras uniformly around the head [S1].
   - For frontal-focused scenes (e.g., EG3D): Sample mainly frontal views with small vertical and horizontal rotations [S1].
3. **Rendering:** Render the scene using the current Gaussian set [S1].
4. **Loss Computation:** Compute loss using weights $\lambda = (0.2, 0.5, 1.0, 1.0, 0.2)$ for the respective loss terms (e.g., LPIPS, MSE, ID similarity) [S1].
5. **Optimization Step:** Update Gaussian parameters and decoder weights using the Adam optimizer [S1][S2, unofficial].
6. **Iteration:** Repeat for the specified number of iterations or epochs [S1][S2, unofficial].

### Formulas
The loss function for decoder training is a weighted sum:
$$
\mathcal{L} = \lambda_1 \mathcal{L}_1 + \lambda_2 \mathcal{L}_2 + \lambda_3 \mathcal{L}_3 + \lambda_4 \mathcal{L}_4 + \lambda_5 \mathcal{L}_5
$$
Where $\lambda = (0.2, 0.5, 1.0, 1.0, 0.2)$ [S1].

For downstream classification/segmentation, the optimization uses standard cross-entropy or segmentation loss with the classifier head [S2, unofficial].

### Parameters
**Decoder Training (Generative):**
- **Iterations:** 500,000 [S1].
- **Optimizer:** Adam [S1].
- **Learning Rate:** 0.0009 [S1].
- **Loss Weights:** $\lambda = (0.2, 0.5, 1.0, 1.0, 0.2)$ [S1].

**Standard Downstream Protocols (Classification/Segmentation):**
- **Optimizer:** AdamW [S2, unofficial].
- **ModelNet10/40:**
  - **Gaussians:** 1,024 [S2, unofficial].
  - **Groups:** 64 groups of 32 Gaussians [S2, unofficial].
  - **Attributes:** All 14 [S2, unofficial].
  - **Epochs:** 300 [S2, unofficial].
  - **Learning Rate:** $10^{-3}$ [S2, unofficial].
  - **Weight Decay:** 0.05 [S2, unofficial].
  - **Warm-up:** 5 epochs [S2, unofficial].
  - **Batch Size:** 256 [S2, unofficial].
- **ShapeNet-Part:**
  - **Gaussians:** 2,048 [S2, unofficial].
  - **Groups:** 128 groups of 32 Gaussians [S2, unofficial].
  - **Epochs:** 300 [S2, unofficial].
  - **Learning Rate:** $10^{-4}$ [S2, unofficial].
  - **Batch Size:** 16 [S2, unofficial].

### Edge Cases and Pitfalls
- **Run-to-run Variance:** ModelNet fine-tuning exhibits appreciable run-to-run variation, particularly on ModelNet40 [S2, unofficial]. Results should be interpreted with caution regarding small cross-environment differences [S2, unofficial].
- **Protocol Matching:** Ensure that pre-training and transfer protocols match (e.g., 1K-to-4K protocol) to avoid unfair comparisons [S2, unofficial].

## Subtopics

### Standard Downstream Protocols
A standardized training and evaluation pipeline for classification and part segmentation tasks using Gaussian inputs [S2, unofficial]. It differs from generative decoder training by using fixed Gaussian counts (1K/2K) and epoch-based training rather than iteration-based training. It is chosen when evaluating the geometric fidelity of Gaussians for downstream 3D vision tasks [S2, unofficial].

### StopThePop Framework Integration
A framework that integrates occlusion-aware densification with StopThePop's per-pixel depth ordering to remove popping artifacts and keep occlusion boundaries intact [S3, unofficial]. It differs from standard training by modifying the densification statistics accumulation to be occlusion-aware [S3, unofficial]. It is chosen for large-scale scenes with heavy occlusion where standard view-count normalizers diverge [S3, unofficial].

## Operating characteristics
- **Time Complexity:** Training for 500,000 iterations is computationally expensive [S1]. Downstream protocols use fewer epochs (300) but may require careful tuning due to variance [S2, unofficial].
- **Memory Complexity:** Depends on the number of Gaussians (1K-2K for downstream, variable for generative) [S1][S2, unofficial].
- **Strengths:** High-quality 3D reconstruction for generative models [S1]; standardized evaluation for 3D classification [S2, unofficial].
- **Limitations:** High variance in ModelNet results [S2, unofficial]; requires careful camera sampling strategy for generative models [S1].

## Background
Originated from the application of 3D Gaussian Splatting to 3D-aware generative adversarial networks (GANs) [S1] and subsequent adaptations for 3D point cloud classification and segmentation [S2, unofficial]. The StopThePop integration addresses occlusion issues in large-scale scenes [S3, unofficial].
