# FineSplat

Also called: Detailed Splats, Fine Patches, Local Groups

## Overview
FineSplat is a feed-forward 3D Gaussian Splatting framework that predicts a set of 3D Gaussians from $N$ context views using a two-stage dual-grouping strategy to balance local detail preservation with global multi-view reasoning [S1, unofficial]. It replaces the iterative optimization loop of standard 3DGS with a neural network that maps input images to Gaussian parameters, building on the shared principles of feed-forward prediction [15832-feed-forward-and-generalizable-prediction.md]. FineSplat distinguishes itself by using high-resolution 4x4 patch tokens and a dual-grouping mechanism—view-wise grouping in Stage 1 and 3D spatial grouping in Stage 2—to preserve fine-grained visual information while avoiding the prohibitive costs of global multi-view attention [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of $N$ context images $\{I_n\}_{n=1}^N$ with known or predicted camera poses (intrinsics and extrinsics).
*   **Outputs:** A set of 3D Gaussian primitives $\Theta = \{\mu_k, s_k, r_k, \alpha_k, c_k\}_{k=1}^K$, where $K$ is the total number of Gaussians.

**Data Structures:**
*   **Tokens:** Fine-grained tokens $z \in \mathbb{R}^{M \times d}$, where $M = N \cdot (H/p) \cdot (W/p)$ is the number of tokens, $H, W$ are image dimensions, $p=4$ is the patch size, and $d$ is the feature dimension.
*   **Gaussians:** Each token predicts $K_{token}=4$ Gaussian primitives. A Gaussian is defined by mean $\mu \in \mathbb{R}^3$, scale $s \in \mathbb{R}^3$, rotation $r \in \mathbb{R}^4$ (quaternion), opacity $\alpha \in [0,1]$, and spherical harmonic coefficients $c$.

**Parameters:**
*   $p$: Patch size, fixed at 4x4 pixels [S1, unofficial].
*   $T$: Number of iterative refinement steps in Stage 2, fixed at 4 [S1, unofficial].
*   $s$: Sub-patch stride, fixed at 2 [S1, unofficial].
*   $N$: Number of context views. Training samples $N \in \{6, 12, 24, 32\}$ [S1, unofficial].
*   $S$: Size of groups for serialized attention in Stage 2 (number of consecutive points along the space-filling curve). Not given in the sources.

**Algorithm:**

1.  **Scene Normalization:** To handle scale ambiguity, transform all camera poses into the mean context camera frame. Rescale translations so that all context camera centers lie within $[-1, 1]^3$ [S1, unofficial]. Apply the same transformation to target poses.

2.  **Stage 1: View-Wise Token Grouping:**
    *   Extract multi-scale features $F^l$ for $l \in \{1, 2, 3\}$ (finest to coarsest) from the input images using a backbone.
    *   Fuse features into initial fine-grained tokens $z^{(0)}$ using Equation (1) [S1, unofficial]:
        $$ z^{(0)} = \text{fuse}\left(\text{up}\left(\text{fuse}\left(\text{up}(F^3) + F^2\right)\right)\right) + F^1 $$
        where $\text{up}(\cdot)$ is bilinear upsampling and $\text{fuse}(\cdot)$ is a convolutional fusion block.
    *   Encode tokens using view-wise attention. Group tokens by view and apply attention within small view groups, exchanging information across all views via coarser global tokens (Multi-View Pyramid architecture) [S1, unofficial].

3.  **Stage 2: 3D Spatial Token Grouping (Iterative Refinement for $t = 1 \dots T$):**
    *   **Decode:** Map current tokens $z^{(t-1)}$ to an initial set of Gaussians using a lightweight linear Gaussian head $\mathcal{D}$.
    *   **Patch-Aligned Sub-Pixel Gaussian Reconstruction:** For each token, predict 4 Gaussians, one for each non-overlapping 2x2 sub-patch of the 4x4 token.
        *   Learn a 2D image-space offset $\Delta = (\Delta_x, \Delta_y)$.
        *   Compute bounded offsets: $\delta_x = 2s \tanh(\Delta_x)$, $\delta_y = 2s \tanh(\Delta_y)$, where $s=2$. This ensures $\delta_x, \delta_y \in [-s/2, s/2]$ [S1, unofficial].
        *   For a sub-patch with center $(u_c, v_c)$, compute displaced coordinate $(u, v) = (u_c, v_c) + (\delta_x, \delta_y)$.
        *   Unproject $(u, v)$ using camera intrinsics to get a ray direction. Transform and normalize the direction using camera-to-world rotation, using camera translation as the ray origin. Set $\mu$ along this ray.
    *   **Render:** Render the predicted Gaussians into all $N$ context views to obtain rendered images $\{\hat{I}_n\}$.
    *   **Compute Error Features:** For each view $n$:
        *   Compute signed pixel error map: $E_n = \hat{I}_n - I_n$ [S1, unofficial].
        *   Compute feature-level difference: $\Delta\phi_n = \phi(\hat{I}_n) - \phi(I_n)$, where $\phi(\cdot)$ is a pretrained ResNet-18 encoder [S1, unofficial].
        *   Combine with finest-scale features $F_n^1$ from Stage 1 via linear embeddings $E_{err}$ and $E_{feat}$:
            $$ F_n^{err} = [E_{err}(E_n, \Delta\phi_n); E_{feat}(F_n^1)] \in \mathbb{R}^{(H/p) \times (W/p) \times d_e} $$
            where $[\cdot; \cdot]$ denotes concatenation [S1, unofficial].
    *   **Gather Errors:** For each token, compute two error signals:
        *   $e_{self}$: Error feature from the patch where the token was predicted.
        *   $e_{agg}$: Aggregated error feature averaged over all context views where the token is visible (projected onto error feature maps and masked by visibility/occlusion) [S1, unofficial].
    *   **3D Spatial Grouping:**
        *   Lift tokens to 3D space using their current Gaussian means.
        *   Order tokens along a space-filling curve.
        *   Partition tokens into groups of $S$ consecutive points.
        *   Apply serialized self-attention within each group to exchange error signals with 3D neighbors. Use four attention blocks, each using a different space-filling curve, so each token meets a different set of neighbors [S1, unofficial].
        *   Update tokens: $\Delta z_j = \text{Linear}(\text{SerialAttn}(h_j^{(i)}))$, $z_j^{(i+1)} = z_j^{(i)} + \Delta z_j$ [S1, unofficial].
    *   **Repeat:** Go to Decode with updated tokens.

4.  **Final Output:** After $T=4$ steps, decode the final tokens into the final set of Gaussians.

## Operating characteristics
*   **Time Complexity:** Faster than global attention methods. Stage 1 uses local view-wise attention; Stage 2 uses serialized attention with space-filling curves, which scales favorably with token count compared to k-NN search [S1, unofficial].
*   **Memory Complexity:** Depends on the number of tokens $M$ and views $N$. Fine-grained 4x4 patches increase token count compared to 14x14 patches (e.g., YoNoSplat, ZipSplat), but the dual-grouping strategy keeps memory manageable [S1, unofficial].
*   **Measured Performance:**
    *   **DL3DV (6 views):** 27.325 PSNR, 0.871 SSIM, 0.115 LPIPS using 62K Gaussians [S1, unofficial].
    *   **RE10K (6 views):** 27.394 PSNR, 0.886 SSIM, 0.116 LPIPS using 75K Gaussians [S1, unofficial].
    *   **Mip-NeRF 360 (128 views):** 23.463 PSNR, 0.706 SSIM, 0.214 LPIPS using 1.6M Gaussians [S1, unofficial].
*   **Strengths:** High quality with small primitive budget; efficient reconstruction time; handles fine-grained details better than coarser patch methods; robust to varying view counts.
*   **Limitations:** Performance degrades if view groups in Stage 1 do not cover the scene well (mitigated by Stage 2); scale ambiguity requires pose normalization; no depth supervision used, which may limit geometric accuracy in some scenarios [S1, unofficial].
*   **When to use:** Novel view synthesis where high fidelity and efficiency are required, and camera poses are known or accurately predicted.
*   **When not to use:** Scenes with extreme scale variations without proper normalization; applications requiring explicit depth maps without additional supervision.

## Background
FineSplat was introduced in 2026 by Xu et al. [S1, unofficial]. It addresses the trade-off between fine-grained detail and computational cost in feed-forward 3D Gaussian Splatting. Previous methods like YoNoSplat and ZipSplat used larger 14x14 patches and global or coarser interactions, which limited detail preservation. FineSplat uses 4x4 patches and a dual-grouping strategy to achieve finer detail while maintaining efficiency. It is trained on the DL3DV dataset and evaluated on DL3DV, RealEstate10K, and Mip-NeRF 360 [S1, unofficial].
