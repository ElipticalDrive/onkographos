# SparSplat

Also called: Generalizable 2D Gaussian Splatting, SparSplat Model, SparSplat: Fast Multi-View Reconstruction with Generalizable 2D Gaussian Splatting

## Overview
SparSplat is a generalizable, feed-forward model that maps a set of sparse input images (typically 3) to planar surface elements, represented as 2D Gaussian Splatting (2DGS) parameters, in a single forward pass to perform 3D shape reconstruction and novel view synthesis [S1, unofficial]. It differs from its sibling [AnySplat Pipeline](12847-anysplat-pipeline.md) and [Splatt3R](16423-splatt3r.md) by explicitly optimizing for surface consistency via 2D primitives rather than 3D volume primitives, enabling coherent TSDF mesh extraction [S1, unofficial]. Unlike [FineSplat](15257-finesplat.md) and [HFGaussian](16422-hfgaussian.md) which focus on high-fidelity rendering or specific optimization strategies, SparSplat is designed for immediate feed-forward inference from sparse views without per-scene optimization [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of $N$ color images $\{I_i\}_{i=1}^N$ (where $N=3$ in the standard configuration) with dimensions $H \times W \times 3$, and their corresponding camera poses $P_i$ (rotation and translation).
*   **Outputs:** For a target view $P_t$, a pixel-aligned 2DGS parameter map $O_t \in \mathbb{R}^{H \times W \times (2+4+3+1+3)}$ containing scale $s$, quaternion rotation $q$, centroid $p$, opacity $\alpha$, and color $c$. Additionally, an explicit 3D triangle mesh $S$ can be extracted via TSDF fusion of the rendered depths.

**Data Structures:**
The core data structure is the parameter map $O_t$. The channel layout is fixed as follows:
1.  **Scale ($s$):** 2 channels (representing the planar dimensions in the local frame).
2.  **Rotation ($q$):** 4 channels (quaternion components).
3.  **Centroid ($p$):** 3 channels (3D position, derived from depth unprojection).
4.  **Opacity ($\alpha$):** 1 channel.
5.  **Color ($c$):** 3 channels (RGB).

**Algorithm Steps:**
The model $\Phi$ predicts $O_t$ through the following pipeline:

1.  **Feature Encoding:**
    *   Encode each input image $I_i$ using a Feature Pyramid Network (FPN) to obtain 2D feature maps $f_i$ [S1, unofficial].
    *   Extract monocular semantic features from DINOv2 for each $I_i$ [S1, unofficial].
    *   Extract pairwise dense correspondence features from MASt3R for all pairs of input images [S1, unofficial].

2.  **Feature Warping:**
    *   For the target view $P_t$, warp the feature maps $f_i$ from each source view $P_i$ to the target view using homography based on the relative poses $P_t / P_i$. This yields warped features $f_{t,i}$ [S1, unofficial].

3.  **Cost Volume Construction and Depth Estimation (DeepMVS Branch):**
    *   Merge the warped features $f_{t,i}$ into a 3D cost volume.
    *   Process the cost volume with a 3D convolutional network to produce a probability volume.
    *   Integrate the probability volume to predict a coarse depth map.
    *   Refine the depth using a fine stage.
    *   *Note:* During depth estimation, 64 depth planes are sampled for the coarse stage and 8 depth planes for the fine stage [S1, unofficial].

4.  **Gaussian Attribute Prediction (Pixel-Aligned Branch):**
    *   Pool the warped features $f_{t,i}$ into a single target feature map $f_t$ [S1, unofficial].
    *   Pass $f_t$ through a 2D convolutional network followed by a Multi-Layer Perceptron (MLP).
    *   The network predicts the Gaussian primitive attributes $\{s, q, \alpha, c\}$ for each pixel [S1, unofficial].

5.  **Centroid Assembly:**
    *   Unproject the predicted depth map from the DeepMVS branch using the camera intrinsics $K$ of the target view $P_t$ to obtain the 3D positions $p$.
    *   Combine $p$ with $\{s, q, \alpha, c\}$ to form the final parameter map $O_t$ [S1, unofficial].

6.  **Rendering and Mesh Extraction:**
    *   **Novel View Synthesis:** Render the scene using perspective-accurate 2D Gaussian Splatting rasterization [S1, unofficial].
    *   **Mesh Extraction:** Render depth maps for all training views $P_i$ using the predicted splat maps $O_i = \Phi(P_i | I_1, \dots, I_N)$. Perform Truncated Signed Distance Function (TSDF) fusion on these depth maps to generate the explicit mesh $S$. The TSDF voxel size is set to 1.5 [S1, unofficial].

**Parameters and Training:**
*   **Resolution:** $640 \times 512$ [S1, unofficial].
*   **Source Views ($N$):** 3 [S1, unofficial].
*   **Optimizer:** Adam [S1, unofficial].
*   **Learning Rate:** $5 \times 10^{-4}$ [S1, unofficial].
*   **Steps:** 300,000 [S1, unofficial].
*   **Hardware:** Single RTX A6000 GPU [S1, unofficial].
*   **Loss Weights:** $\lambda_s = 0.1$, $\lambda_p = 0.05$, $\lambda_\alpha = 0.05$, $\lambda_\beta = 0.05$, $\lambda_\gamma = 0.05$, $\lambda_1 = 0.5$, $\lambda_2 = 1$ [S1, unofficial].
*   **Depth Planes:** 64 for coarse stage, 8 for fine stage [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **3DGS vs 2DGS:** Using 3D Gaussian Splatting (3DGS) instead of 2DGS leads to depth inconsistencies across views. This causes TSDF fusion to produce incorrect, warped, or disconnected surfaces [S1, unofficial].
*   **Feature Selection:** Using only image features or DINOv2 features yields inferior results compared to MASt3R. MASt3R provides an 11.11% boost in Chamfer Distance over image-only features, while DINOv2 provides only a 0.85% boost [S1, unofficial].
*   **Depth Loss:** The depth loss $L_{depth}$ is critical. Without it, the mean Chamfer Distance is 4.37; with it, it drops to 1.04 (a 71.8% improvement) [S1, unofficial].

## Operating characteristics
*   **Inference Speed:** SparSplat is approximately 2 orders of magnitude faster than prior state-of-the-art feed-forward sparse-view reconstruction methods based on implicit volume rendering. On an RTX A6000, inference takes 0.8s (reproduced 0.88s), compared to 66s for UfoRecon, 32s for GeoTransfer, and 31s for VolRecon [S1, unofficial].
*   **Accuracy (NVS):** On the DTU test set, SparSplat achieves PSNR 28.33, SSIM 0.938, and LPIPS 0.073, outperforming MVSGaussian (PSNR 28.21, SSIM 0.963, LPIPS 0.076) and other implicit methods like SparseNeuS [S1, unofficial].
*   **Accuracy (Reconstruction):** On the DTU sparse 3D reconstruction benchmark, SparSplat achieves a mean Chamfer Distance of 1.04, setting a new state-of-the-art for generalizable methods [S1, unofficial].
*   **Strengths:** Fast inference, coherent surface reconstruction via TSDF, superior novel view synthesis in low-overlap regions compared to MVSGaussian [S1, unofficial].
*   **Limitations:** Performance relies on the quality of foundation model features (MASt3R/DINOv2). Generalization to very challenging outdoor scenes (BlendedMVS) is promising but requires robust feature extraction [S1, unofficial].
*   **When to use:** When fast, generalizable 3D reconstruction and novel view synthesis from sparse views (3 images) is required, and explicit mesh output is desired.
*   **When not to use:** When per-scene optimization is acceptable and higher fidelity is needed (e.g., standard 3DGS), or when dense input views are available and real-time inference is not critical.

## Background
SparSplat was proposed by Shubhendu Jena et al. in 2025 [S1, unofficial]. It builds upon the MVSGaussian framework [48] but replaces 3D primitives with 2D Gaussian Splatting (2DGS) to improve geometric consistency for surface reconstruction. It incorporates features from foundation models DINOv2 [59] and MASt3R [41] to enhance generalizability. The method addresses the limitations of prior generalizable GS methods which were primarily designed for novel view synthesis and failed to produce coherent meshes via TSDF fusion [S1, unofficial]. It is evaluated on the DTU, BlendedMVS, and Tanks and Temples datasets [S1, unofficial].
