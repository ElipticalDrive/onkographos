# 3DGS Parameter Tuning and Sensitivity Analysis

Also called: 3DGS Hyperparameter Optimization

## Overview
This method defines a systematic procedure for optimizing the hyperparameters of 3D Gaussian Splatting (3DGS) to maximize rendering quality metrics (PSNR, SSIM, LPIPS) while maintaining computational efficiency. It addresses the sensitivity of the 3DGS densification strategy to specific thresholds and learning rates, which are often treated as fixed or heuristic values in standard implementations. Unlike the base 3DGS method, which uses default gradient thresholds, this approach treats resolution, density control, gradient magnitude thresholds, and scaling learning rates as tunable variables, ranking them by impact to identify the most critical parameters for fine-tuning [S1].

## How it works
The method consists of two phases: parameter sensitivity analysis to rank importance, and final configuration selection based on empirical testing on a target dataset.

### Inputs and Outputs
**Inputs:**
- A dataset of input images (e.g., $N$ photos).
- A baseline 3DGS implementation with default hyperparameters.
- A set of candidate hyperparameters to test.

**Outputs:**
- A ranked list of hyperparameters by sensitivity.
- An optimal configuration tuple $(\text{Resolution}, \tau, p, \text{Scaling\_lr})$.

### Data Structures
The method relies on standard 3DGS data structures but focuses on the following scalar hyperparameters:
- $\tau$ (tau): Float. Threshold for average magnitude of spatial position gradients.
- $p$: Float. Hyperparameter controlling Gaussian kernel density level (cloning/cropping condition).
- $\text{Scaling\_lr}$: Float. Learning rate for Gaussian scale updates.
- $\text{Resolution}$: Integer or string (e.g., "0.8k"). Rendered image resolution.

### Steps

1. **Baseline Evaluation**: Run the 3DGS algorithm with default or initial hyperparameters on the target dataset. Record baseline metrics: $PSNR_{base}$, $SSIM_{base}$, $LPIPS_{base}$, and training time $T_{base}$.

2. **Parameter Sweep**: For each hyperparameter $h \in \{\text{Resolution}, \tau, p, \text{Scaling\_lr}\}$:
   - Iterate through a predefined set of candidate values $V_h$.
   - For each value $v \in V_h$:
     - Run the 3DGS training with $h=v$ and other parameters fixed at their current best or default values.
     - Record metrics $PSNR_v, SSIM_v, LPIPS_v$.

3. **Sensitivity Calculation**: Compute the delta for each parameter relative to the baseline (or a reference configuration) to determine impact magnitude.
   - $\Delta PSNR = PSNR_v - PSNR_{ref}$
   - $\Delta SSIM = SSIM_v - SSIM_{ref}$
   - $\Delta LPIPS = LPIPS_v - LPIPS_{ref}$
   - Rank parameters by the magnitude of these deltas. The source identifies the ranking order as: Resolution > $p$ > $\tau$ > Scaling\_lr [S1].

4. **Optimal Value Selection**: Select the value $v^*$ for each parameter that yields the best combined metric performance (highest PSNR/SSIM, lowest LPIPS) without significant increase in training time.
   - If multiple values yield similar metrics, prefer the one with lower training time or simpler implementation [S1].

5. **Final Configuration Validation**: Run the algorithm with the selected optimal values for all parameters simultaneously. Compare final metrics against the baseline to confirm improvement.

### Formulas and Definitions

**Gradient Threshold ($\tau$):**
$\tau$ controls the gradient-based adaptation during training. It is compared against the average magnitude of spatial position gradients.
- Tested values: $\{0.0001, 0.0002, 0.0003, 0.0004\}$ [S1].
- Optimal value: $0.0003$ [S1].

**Density Control Parameter ($p$):**
$p$ acts as the condition for cloning or cropping Gaussians during the densification step.
- Condition: When the maximum scaling of a Gaussian kernel in a certain direction exceeds a threshold governed by $p$, the kernel is cropped; otherwise, it is cloned to increase density [S1].
- Tested values: $\{0.0005, 0.001, 0.002, 0.01, 0.1\}$ [S1].
- Optimal value: $0.001$ [S1].

**Scaling Learning Rate ($\text{Scaling\_lr}$):**
Controls how quickly Gaussian kernel scales are updated.
- Tested values: $\{0.004, 0.005, 0.006, 0.008\}$ [S1].
- Optimal value: $0.005$ [S1].

**Resolution:**
The output image resolution.
- Tested values: $\{0.3k, 0.5k, 0.8k, 1.2k, 1.5k, 1.6k, 2k\}$ [S1].
- Optimal value: $0.8k$ [S1].

### Pseudocode

```python
def tune_3dgs_parameters(dataset, baseline_config):
    """
    Performs sensitivity analysis and parameter tuning for 3DGS.
    
    Args:
        dataset: Object containing input images and metadata.
        baseline_config: Dictionary with initial hyperparameters.
        
    Returns:
        optimal_config: Dictionary with tuned hyperparameters.
        metrics: Dictionary with final performance metrics.
    """
    
    # 1. Evaluate Baseline
    baseline_metrics = run_3dgs(dataset, baseline_config)
    psnr_base = baseline_metrics['PSNR']
    ssim_base = baseline_metrics['SSIM']
    lpips_base = baseline_metrics['LPIPS']
    
    # 2. Define Candidate Values
    candidates = {
        'tau': [0.0001, 0.0002, 0.0003, 0.0004],
        'p': [0.0005, 0.001, 0.002, 0.01, 0.1],
        'scaling_lr': [0.004, 0.005, 0.006, 0.008],
        'resolution': ['0.3k', '0.5k', '0.8k', '1.2k', '1.5k', '1.6k', '2k']
    }
    
    # 3. Sensitivity Analysis
    sensitivity_results = {}
    
    for param, values in candidates.items():
        param_deltas = []
        for val in values:
            # Create config with current param varied, others fixed to baseline or previous best
            config = baseline_config.copy()
            config[param] = val
            
            # Run training
            metrics = run_3dgs(dataset, config)
            
            # Calculate deltas relative to baseline
            delta_psnr = metrics['PSNR'] - psnr_base
            delta_ssim = metrics['SSIM'] - ssim_base
            delta_lpips = metrics['LPIPS'] - lpips_base
            
            param_deltas.append({
                'value': val,
                'delta_psnr': delta_psnr,
                'delta_ssim': delta_ssim,
                'delta_lpips': delta_lpips,
                'metrics': metrics
            })
        
        sensitivity_results[param] = param_deltas
        
    # 4. Rank Parameters
    # Based on source [S1], ranking is: Resolution > p > tau > Scaling_lr
    # This ranking is derived from the magnitude of impact on metrics.
    ranked_params = ['resolution', 'p', 'tau', 'scaling_lr']
    
    # 5. Select Optimal Values
    optimal_config = baseline_config.copy()
    
    # Select best value for each parameter based on combined metric performance
    # Note: In practice, one might optimize sequentially or jointly. 
    # The source implies independent testing followed by combination.
    
    # For 'tau': Optimal is 0.0003 (highest PSNR/SSIM, lowest LPIPS)
    optimal_config['tau'] = 0.0003
    
    # For 'p': Optimal is 0.001 (best LPIPS/PSNR with comparable time)
    optimal_config['p'] = 0.001
    
    # For 'scaling_lr': Optimal is 0.005 (best performance, aligns with original)
    optimal_config['scaling_lr'] = 0.005
    
    # For 'resolution': Optimal is 0.8k (best trade-off)
    optimal_config['resolution'] = '0.8k'
    
    # 6. Final Validation
    final_metrics = run_3dgs(dataset, optimal_config)
    
    return optimal_config, final_metrics

def run_3dgs(dataset, config):
    """
    Wrapper for the 3DGS training and evaluation pipeline.
    """
```

### Edge Cases and Pitfalls
- **Training Time Variance**: Some parameter combinations (e.g., high $p$ or high resolution) may significantly increase training time. The source notes that $p=0.1$ resulted in longer training times and worse metrics, so extreme values should be avoided [S1].
- **Metric Trade-offs**: While PSNR and SSIM may improve, LPIPS might not change significantly for certain parameters (e.g., Scaling\_lr). Implementers should monitor all three metrics [S1].
- **Dataset Dependency**: The optimal values are derived from a specific self-collected indoor dataset (66 photos). Results may vary for different scene types or dataset sizes [S1].

## Operating characteristics
- **Time Complexity**: The tuning process itself requires multiple training runs (one per candidate value per parameter). For the tested parameters, each training run took approximately 10 minutes on the tested hardware [S1]. The total tuning time is proportional to the number of candidates tested.
- **Memory Complexity**: No additional memory overhead compared to standard 3DGS, as the method only changes scalar hyperparameters [S1].
- **Performance**: On the tested dataset (66 photos, 7000 iterations), the tuned configuration (Resolution=0.8k, $\tau$=0.0003, $p$=0.001) achieved:
  - PSNR: 23.694 (increase of 4.3% from baseline 22.708) [S1].
  - SSIM: 0.798 (increase of 0.2% from baseline 0.796) [S1].
  - LPIPS: 0.36 (unchanged from baseline) [S1].
  - Training time: 10 minutes [S1].
- **Strengths**: Improves image sharpness and structural preservation, particularly on ceilings and corners [S1].
- **Limitations**: Sensitivity analysis was performed on a single dataset type (indoor). Generalizability to other scenes is not guaranteed [S1].

## Background
This method originates from a 2025 study published in *ISPRS International Journal of Geo-Information* [S1]. The study focused on optimizing 3DGS for indoor scene generation and rendering. It identified that standard hyperparameters are not optimal for all scenarios and proposed a systematic sensitivity analysis to determine the best settings for specific datasets. The work builds on the original 3DGS algorithm [G] by introducing a structured approach to hyperparameter tuning.
