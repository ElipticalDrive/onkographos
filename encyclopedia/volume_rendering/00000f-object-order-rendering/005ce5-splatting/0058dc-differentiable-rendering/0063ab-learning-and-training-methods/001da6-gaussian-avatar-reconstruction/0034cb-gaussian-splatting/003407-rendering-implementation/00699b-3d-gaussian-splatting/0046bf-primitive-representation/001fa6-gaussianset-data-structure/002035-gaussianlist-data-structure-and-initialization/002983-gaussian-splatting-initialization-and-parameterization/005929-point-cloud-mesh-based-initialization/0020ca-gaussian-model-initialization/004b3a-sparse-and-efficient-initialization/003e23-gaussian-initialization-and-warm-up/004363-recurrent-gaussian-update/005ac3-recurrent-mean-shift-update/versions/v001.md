# Recurrent Mean-Shift Update

Also called: Holistic separability update, Mean-shift update

## Overview
The Recurrent Mean-Shift Update is a regularization step applied to the descriptor parameters of 3D Gaussians to enforce holistic separability across the entire scene [S1]. It addresses the problem where local segmentation losses only distinguish descriptors within individual image views, failing to ensure that descriptors for the same 3D plane instance remain consistent across different camera viewpoints [S1]. By applying a mean-shift operation based on the von Mises-Fisher distribution, it pulls similar descriptors together and pushes dissimilar ones apart globally, improving plane instance segmentation [S1]. It differs from standard differentiable updates by operating on the statistical distribution of descriptors rather than individual pixel-wise gradients.

## How it works
**Inputs and Outputs:**
- Input: $\mathbf{Z}$, a matrix of shape $(N, D)$ containing the $D$-dimensional descriptor vectors for $N$ Gaussians.
- Output: Updated $\mathbf{Z}$ with enhanced separability.

**Data Structures:**
- $\mathbf{Z}$: Matrix where each row $\mathbf{z}_i$ is the descriptor for the $i$-th Gaussian.
- $\mathbf{K}$: Kernel matrix of shape $(N, N)$.
- $\mathbf{D}$: Diagonal matrix of shape $(N, N)$.
- $\mathbf{I}$: Identity matrix of shape $(N, N)$.

**Parameters:**
- $\eta$ (eta): Update rate (learning rate for this step). Typical values are not specified in the sources [S1].
- $\gamma$ (gamma): Kernel bandwidth controlling the smoothness of the kernel density estimation. Typical values are not specified in the sources [S1].
- $N_{steps}$: Number of mean-shift steps to perform per update cycle. Not given in the sources.
- $N_{iter}$: Frequency of applying the update (every $N$ iterations of the main optimization loop). Not given in the sources.

**Formulas:**
The update rule is defined as [S1]:
$$ \mathbf{Z} \leftarrow \mathbf{Z} \cdot (\eta \cdot \mathbf{K} \cdot \mathbf{D}^{-1} + (1-\eta) \cdot \mathbf{I}) $$

Where:
1.  $\mathbf{K}$ is the von Mises-Fisher (vMF) kernel matrix:
    $$ \mathbf{K} = e^{\gamma \cdot \mathbf{Z}^T \cdot \mathbf{Z}} $$
    Here, $\mathbf{Z}^T \cdot \mathbf{Z}$ computes the dot products between all pairs of descriptor vectors. The exponential is applied element-wise.
2.  $\mathbf{D}$ is a diagonal matrix where the diagonal elements are the row sums of $\mathbf{K}$:
    $$ \mathbf{D} = \text{diag}(\mathbf{K}^T \cdot \mathbf{1}) $$
    where $\mathbf{1}$ is a column vector of ones. Effectively, $D_{ii} = \sum_{j} K_{ji}$. Since $\mathbf{K}$ is symmetric (dot product is symmetric), $\mathbf{K}^T = \mathbf{K}$, so $D_{ii} = \sum_{j} K_{ij}$.
3.  $\mathbf{I}$ is the identity matrix.

**Steps:**
1.  Compute the pairwise dot product matrix $\mathbf{S} = \mathbf{Z}^T \cdot \mathbf{Z}$.
2.  Compute the kernel matrix $\mathbf{K} = \exp(\gamma \cdot \mathbf{S})$ (element-wise exponential).
3.  Compute the normalization vector $\mathbf{v} = \mathbf{K} \cdot \mathbf{1}$ (sum of rows of $\mathbf{K}$).
4.  Construct the diagonal matrix $\mathbf{D}$ from $\mathbf{v}$.
5.  Compute the update matrix $\mathbf{M} = \eta \cdot \mathbf{K} \cdot \mathbf{D}^{-1} + (1-\eta) \cdot \mathbf{I}$.
    - Note: $\mathbf{D}^{-1}$ is simply the reciprocal of the diagonal elements.
6.  Update the descriptors: $\mathbf{Z}_{new} = \mathbf{Z} \cdot \mathbf{M}$.
7.  Repeat steps 1-6 for a few steps (as specified by implementation details) every $N$ optimization iterations [S1].

**Pseudocode:**
```python
import numpy as np

def recurrent_mean_shift_update(Z, eta, gamma, num_steps):
    """
    Applies the recurrent mean-shift update to Gaussian descriptors Z.
    
    Args:
        Z: numpy array of shape (N, D), descriptor matrix.
        eta: float, update rate.
        gamma: float, kernel bandwidth.
        num_steps: int, number of mean-shift iterations to perform.
        
    Returns:
        Z: Updated descriptor matrix.
    """
    N = Z.shape[0]
    
    for _ in range(num_steps):
        # 1. Compute pairwise dot products: Z^T @ Z is (D, N) @ (N, D) -> (D, D)? 
        # Wait, formula says K = exp(gamma * Z^T * Z). 
        # If Z is (N, D), Z^T is (D, N). Z^T @ Z is (D, D). 
        # But K is used in Z @ K. Z is (N, D). K must be (D, D) or (N, N)?
        # Let's re-read carefully: "K = e^(gamma * Z^T * Z) is vMF distribution of z on sphere"
        # Usually vMF kernel depends on dot product between samples. 
        # If Z rows are samples, dot products are Z @ Z.T -> (N, N).
        # The text says: K = e^(gamma * Z^T * Z). 
        # If Z is (N, D), Z^T is (D, N). Z^T @ Z is (D, D).
        # Then Z @ K would be (N, D) @ (D, D) = (N, D). This matches dimensions.
        # However, standard mean shift on descriptors usually implies similarity between Gaussians (N x N).
        # Let's check D = diag(K^T * I). If K is (D, D), D is (D, D).
        # Then Z @ K @ D^-1 is (N, D) @ (D, D) @ (D, D) = (N, D).
        # This interpretation (K is DxD) seems mathematically consistent with the matrix multiplication order Z @ K.
        # BUT, "separability of descriptors for all 3D plane instances" usually implies clustering N items.
        # Let's look at the source text again: "K = e^(gamma * Z^T * Z)".
        # If Z is (N, D), Z^T @ Z is (D, D). This is the Gram matrix of the columns (features).
        # This computes similarity between features, not between Gaussians.
        # However, the next line says D = diag(K^T * I).
        # And the update is Z <- Z * (eta * K * D^-1 + ...).
        # If K is (D, D), this updates each feature dimension based on other feature dimensions.
        # This effectively decorrelates or separates features.
        # Let's stick to the literal formula provided: K = exp(gamma * Z^T @ Z).
        
        # Compute S = Z^T @ Z (D, D)
        S = Z.T @ Z
        
        # Compute K = exp(gamma * S) (D, D)
        K = np.exp(gamma * S)
        
        # Compute D_diag = sum of rows of K (since K is symmetric, row sum == col sum)
        # D = diag(K^T * I) -> K^T is K. K * I is K. diag(K) is diagonal elements?
        # Wait. "D = diag(K^T * I)". 
        # If I is identity, K^T * I = K. diag(K) extracts diagonal elements of K.
        # But earlier I thought D was row sums. 
        # Let's re-read: "D = diag(K^T * I)". 
        # In matrix notation, diag(M) usually returns a diagonal matrix with M's diagonal.
        # Or it returns a vector. The text says "D is the diagonal matrix".
        # If D is a diagonal matrix, D^-1 is element-wise inverse of diagonal.
        # If D = diag(K), then D_ii = K_ii.
        # K_ii = exp(gamma * (Z^T @ Z)_ii) = exp(gamma * ||z_i||^2) if Z columns were samples?
        # No, Z is (N, D). Z^T @ Z is (D, D). (Z^T @ Z)_jj = sum_i Z_ij^2 = ||col_j||^2.
        # So D_ii = exp(gamma * ||feature_i||^2).
        
        # Let's check the alternative interpretation: K is (N, N).
        # If K is (N, N), then Z @ K is (N, D) @ (N, N) -> Dimension mismatch.
        # Unless Z is (D, N). But Z is usually (N, D).
        # The formula is Z <- Z * (eta * K * D^-1 + ...).
        # If Z is (N, D), K must be (D, D) for Z @ K to work.
        # Therefore, K is (D, D).
        
        # So:
        # 1. K = exp(gamma * Z^T @ Z)  [Shape: D x D]
        # 2. D_mat = diag(diag(K))      [Shape: D x D]
        # 3. Update = eta * K @ D_mat^-1 + (1-eta) * I_D [Shape: D x D]
        # 4. Z_new = Z @ Update          [Shape: N x D]
        
        # Extract diagonal of K
        D_diag = np.diag(K)
        
        # Create diagonal matrix D
        D_mat = np.diag(D_diag)
        
        # Inverse of D (element-wise inverse of diagonal)
        D_inv_diag = 1.0 / D_diag
        D_inv_mat = np.diag(D_inv_diag)
        
        # Compute Update Matrix M
        # Identity matrix of size D
        I_D = np.eye(D)
        
        M = eta * (K @ D_inv_mat) + (1 - eta) * I_D
        
        # Update Z
        Z = Z @ M
        
    return Z
```

**Edge Cases and Pitfalls:**
- **Large N:** The number of Gaussians can be very large. While the derived pseudocode computes a $D \times D$ matrix (where $D$ is descriptor dimension, typically small, e.g., 16-64), the source notes that an "efficient way" is used because the number of Gaussians is large [S1]. The provided formula operates on the descriptor space ($D$), not the Gaussian count ($N$), making it $O(N \cdot D^2)$ per step, which is efficient with respect to $N$. If the source intended $K$ to be $N \times N$, the complexity would be $O(N^2)$, which is prohibitive. The literal formula $Z^T Z$ yields $D \times D$. We follow the literal formula [S1].
- **Precision:** Division by zero in $D^{-1}$ if any diagonal element of $K$ is zero. Since $K_{ii} = \exp(\gamma \cdot ||\mathbf{z}_i||^2)$, it is always positive, so this is safe.
- **Boundaries:** The update is applied every $N$ iterations, not every step, to stabilize optimization [S1].

## Subtopics

### Holistic Separability of Gaussian Descriptors
This is the specific application of the Recurrent Mean-Shift Update to improve the separability of descriptors for all 3D plane instances across the entire scene [S1]. It uses the von Mises-Fisher distribution to model the descriptors on the sphere [S1]. It is chosen when plane instance segmentation quality is critical and local view-based losses are insufficient to disambiguate planes seen from different viewpoints [S1]. It sets itself apart by enforcing global consistency rather than local discriminative power [S1].

## Operating characteristics
- **Time Complexity:** The core update involves computing $Z^T Z$ ($O(N D^2)$), exponentiation ($O(D^2)$), and matrix multiplication $Z @ M$ ($O(N D^2)$). Since $D$ (descriptor dimension) is small and fixed, the complexity is linear with respect to the number of Gaussians $N$.
- **Memory Complexity:** $O(N D)$ to store $Z$, and $O(D^2)$ for the kernel matrix $K$.
- **Measured Performance:** Ablation studies show that encouraging holistic separability provides effective performance improvement on plane segmentation [S1]. Specific metrics (e.g., mIoU) are not provided in the source text for this specific component in isolation, but the full method (Planar Gaussian Splatting) achieves competitive results on ScanNetv2 and Replica [S1].
- **Strengths:** Improves segmentation accuracy by resolving ambiguities between planes that are not jointly visible in any single view [S1].
- **Limitations:** Requires tuning of $\eta$ and $\gamma$ [S1]. Computationally efficient with respect to $N$ due to the descriptor-space formulation, but adds an extra optimization step every $N$ iterations [S1].
- **When to use:** When performing 3D plane instance segmentation using Gaussian Splatting and local losses are insufficient for global consistency.
- **When not to use:** When computational budget is extremely tight and segmentation accuracy is secondary, or when descriptors are not used for plane segmentation.

## Background
The method originates from Planar Gaussian Splatting (PGS) [S1]. It builds on the concept of using 3D Gaussians to represent 3D planes and introduces a recurrent mean-shift update [18] (cited in S1) to maintain holistic separability of descriptors [S1]. The approach was developed to address the ambiguity in merging local geometries into 3D planes by learning discriminative descriptors without explicit 2D/3D plane annotations [S1].
