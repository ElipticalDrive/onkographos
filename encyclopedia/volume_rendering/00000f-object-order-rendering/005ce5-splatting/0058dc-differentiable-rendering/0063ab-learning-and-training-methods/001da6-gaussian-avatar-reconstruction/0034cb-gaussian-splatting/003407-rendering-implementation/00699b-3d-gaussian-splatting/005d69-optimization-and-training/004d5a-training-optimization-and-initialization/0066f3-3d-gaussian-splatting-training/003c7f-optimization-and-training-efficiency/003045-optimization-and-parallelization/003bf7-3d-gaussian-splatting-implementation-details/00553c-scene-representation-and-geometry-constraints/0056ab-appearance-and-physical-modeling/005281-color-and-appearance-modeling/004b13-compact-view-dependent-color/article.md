# Compact View-dependent Color
Also called: Grid-based Neural Field for Color

## Overview
Compact View-dependent Color replaces the per-Gaussian Spherical Harmonics (SH) coefficients with a shared grid-based neural field to represent view-dependent color, significantly reducing the parameter count from 48 coefficients per Gaussian to a compact neural representation [S1, S2]. Unlike sibling methods that use post-processing transformations [DAVIGS](12021-davigs.md), factorized illumination [3iGS](13977-3igs-factorised-tensorial-illumination-for-3d-gaussian-splat.md), or image-conditioned modulation [SWAG](14315-swag-splatting-in-the-wild-images-with-appearance-conditione.md), this method substitutes the directional encoding entirely with a spatial-hash-based MLP, addressing the disk space explosion caused by high-order SH storage [S2].

## How it works
**Inputs and Outputs:**
*   **Input:** 3D position $\mathbf{p}_n \in \mathbb{R}^3$ and view direction $\mathbf{d} \in \mathbb{R}^3$ for a specific Gaussian $n$.
*   **Output:** View-dependent color $\mathbf{c}_n(\mathbf{d}) \in \mathbb{R}^3$.
*   **Implicit Input:** The shared neural field parameters $\theta$ (hash grid and MLP weights).

**Data Structures:**
1.  **Hash Grid:** A sparse hash table mapping 3D coordinates to feature vectors. Positions are first contracted to a bounded range before hashing [S1].
2.  **Tiny MLP:** A small multi-layer perceptron that takes the concatenated hash grid features and view direction to predict RGB color [S1].
3.  **Gaussian Attributes:** Each Gaussian $i$ stores:
    *   $\mathbf{x}_{\text{encoding}}^{(i)}$: The contracted 3D position.
    *   $\boldsymbol{\Sigma}_i$: The covariance matrix (for density/opacity calculation).
    *   $\alpha_i$: The base opacity.
    *   $\mathbf{c}_i$: The view-dependent color, obtained from the neural field $f$ [S2].
    *   *Note:* The Gaussian no longer stores SH coefficients [S1].

**Numbered Steps:**
1.  **Contraction:** Map the unbounded 3D position $\mathbf{p}_n$ to a bounded range $[-1, 1]^3$ using the contraction function from mip-NeRF 360 [S1]:
    $$
    \text{contract}(\mathbf{p}_n) = 
    \begin{cases} 
    \mathbf{p}_n & \text{if } \|\mathbf{p}_n\| \le 1 \\
    \frac{\mathbf{p}_n}{\|\mathbf{p}_n\|} (2 - \|\mathbf{p}_n\|) & \text{if } \|\mathbf{p}_n\| > 1
    \end{cases}
    $$
    Let $\mathbf{p}'_n = \text{contract}(\mathbf{p}_n)$ [S1].

2.  **Hash Encoding:** Query the hash grid using $\mathbf{p}'_n$ to retrieve a feature vector $\mathbf{f}_{\text{pos}}$ [S1].

3.  **Color Prediction:** Concatenate $\mathbf{f}_{\text{pos}}$ with the view direction $\mathbf{d}$ and pass through the tiny MLP $f(\cdot; \theta)$ to compute the color [S1]:
    $$
    \mathbf{c}_n(\mathbf{d}) = f(\mathbf{p}'_n, \mathbf{d}; \theta)
    $$
    [S1, S2].

4.  **Base Color Initialization (Optional/Implementation Detail):** The sources note that 0-degree SH components (constant color) are used and converted to RGB, which may serve as an initialization or a residual component, though the primary view-dependent term is generated by the MLP [S1].

**Parameters:**
*   **Hash Grid Resolution/Size:** Not given in the sources.
*   **MLP Architecture:** Described as "tiny" [S1]. Specific layer sizes and activation functions are not given in the sources.
*   **Contraction Function:** Standard mip-NeRF 360 contraction [S1].

**Edge Cases and Pitfalls:**
*   **Unbounded Space:** The contraction function is critical to handle unbounded scenes; without it, hash grid queries for distant points would be invalid or require infinite grid size [S1].
*   **Precision:** The contraction maps large coordinates to the unit sphere boundary, potentially losing fine-grained positional detail for very distant points [S1].

**Pseudocode:**
> **Unverified code.** The code below did not pass a test run against a reference implementation, or no test fits it, so it may contain errors.

```python
def contract(p):
    """
    Contracts unbounded 3D position p to bounded range [-1, 1]^3.
    Based on mip-NeRF 360 contraction.
    """
    norm = np.linalg.norm(p)
    if norm <= 1.0:
        return p
    else:
        return (p / norm) * (2.0 - norm)

def get_view_dependent_color(gaussian_index, view_direction, hash_grid, mlp):
    """
    Computes view-dependent color for a Gaussian using a grid-based neural field.
    
    Args:
        gaussian_index: Index of the Gaussian in the scene.
        view_direction: 3D view direction vector d (normalized).
        hash_grid: Hash grid data structure mapping positions to features.
        mlp: Tiny MLP function f(theta) taking features and direction.
        
    Returns:
        color: RGB color vector.
    """
    # 1. Retrieve position from Gaussian attributes
    # Note: The Gaussian stores the original position or the contracted position.
    # The source implies we contract the position before hashing.
    raw_position = gaussians[gaussian_index].position 
    
    # 2. Contract position
    contracted_pos = contract(raw_position)
    
    # 3. Query Hash Grid
    # Implementation detail: Hash grid lookup depends on specific hash function
    # and feature dimension. We assume a generic query function.
    pos_features = hash_grid.query(contracted_pos)
    
    # 4. Compute Color via MLP
    # Concatenate position features and view direction
    input_vector = np.concatenate([pos_features, view_direction])
    
    # Pass through the tiny MLP
    color = mlp.forward(input_vector)
    
    return color
```

## Subtopics

### DAVIGS
Applies a learned affine transformation to the rendered image based on 3D position and view embedding. Choose when you want to preserve per-Gaussian SH but correct global color shifts. [DAVIGS](12021-davigs.md)

### 3iGS (Factorised Tensorial Illumination)
Separates scene lighting (tensor grid) from material properties (BRDF features). Choose when modeling specular effects and complex lighting is required. [3iGS](13977-3igs-factorised-tensorial-illumination-for-3d-gaussian-splat.md)

### Spherical Harmonics Optimization
Optimizes the SH coefficients directly or reduces their degree. Choose when you need standard view-dependent shading without neural network overhead. [Spherical Harmonics Optimization](14206-spherical-harmonics-optimization.md)

### SWAG
Uses an MLP and per-image embeddings to modulate color and opacity. Choose when handling transient objects or appearance synthesis across different images. [SWAG](14315-swag-splatting-in-the-wild-images-with-appearance-conditione.md)

## Operating characteristics
*   **Time Complexity:** Rendering time depends on the hash grid lookup and MLP inference per Gaussian. The MLP is described as "tiny," suggesting low per-Gaussian overhead compared to evaluating high-order SH [S1].
*   **Memory Complexity:** Significantly reduces memory usage compared to base 3DGS. Base 3DGS uses 48 parameters (SH degree 3) per Gaussian for color. This method replaces those 48 parameters with a shared grid and MLP, storing only the base attributes (position, covariance, opacity) and the shared network weights [S1, S2].
*   **Measured Performance:** On Mip-NeRF 360, the method achieved PSNR 29.91 with training time 17m 51s and 254 fps, compared to 3DGS PSNR 29.87, 19m 22s, and 154 fps [S1].
*   **Strengths:** Reduces disk space explosion from high-order SH; improves training speed and rendering FPS; handles unbounded scenes via contraction [S1, S2].
*   **Limitations:** Relies on a neural network for color, which may introduce slight inference overhead compared to simple SH evaluation (though mitigated by "tiny" MLP); requires careful tuning of hash grid and MLP [S1].
*   **When to use:** When disk space is a constraint, or when high-order SH causes overfitting or slow training.
*   **When not to use:** When maximum rendering speed is critical and SH evaluation is faster than MLP inference on the target hardware; when precise control over per-Gaussian directional shading is needed without shared field assumptions.

## Background
The method was introduced in "Compact 3D Gaussian Representation for Radiance Field" (CVPR 2024) by the authors of [S1], motivated by the parameter inefficiency of storing 48 SH coefficients per Gaussian in standard 3D Gaussian Splatting [S1]. It draws inspiration from mip-NeRF 360's contraction function for handling unbounded spaces [S1]. A similar approach is also discussed in "HO-Gaussian: Hybrid Optimization of 3D Gaussian Splatting for Urban Scenes" (2024), which highlights the reduction in disk space and the use of 0-degree SH for base color [S2].
