# Mesh-Embedded Gaussian Initialization and Deformation

Also called: Gaussian Embedding, Triangle Embedding

## Overview
This method anchors 3D Gaussians to a canonical triangle mesh $\mathcal{M}$ using barycentric coordinates and normal displacement, enabling deformation tracking through mesh topology rather than direct vertex positions [S1, unofficial]. It differs from sibling methods like [Mesh-Embedded Gaussian Splatting](9553-mesh-embedded-gaussian-splatting.md) by explicitly parameterizing the Gaussian position via a displacement $d$ along the interpolated normal, allowing Gaussians to represent off-surface geometry (e.g., hair) or fit tightly to the surface [S1, unofficial]. It builds on [Mesh-embedded representation](12559-mesh-embedded-representation.md) by defining the specific initialization and deformation rules for the embedding parameters.

## How it works
**Inputs:** Canonical triangle mesh $\mathcal{M}$ with vertices $V$, per-vertex normals $n$, and optionally per-vertex quaternions $q$. Number of Gaussians $N$ (typically 10,000).
**Outputs:** Set of $N$ Gaussians, each defined by embedding parameters $E_i = \{k, u, v, d\}$ and invariant parameters $\{\bar{q}, \bar{s}, o, c\}$.

**Data Structures:**
Each Gaussian $i$ stores:
*   $k \in \mathbb{Z}$: Triangle index.
*   $u, v \in \mathbb{R}$: Barycentric coordinates ($u \ge 0, v \ge 0, u+v \le 1$).
*   $d \in \mathbb{R}$: Normal displacement.
*   $\bar{q} \in \mathbb{R}^4$: Canonical rotation quaternion.
*   $\bar{s} \in \mathbb{R}^3$: Canonical scale vector.
*   $o \in \mathbb{R}$: Opacity.
*   $c$: Color (Spherical Harmonics disabled for simplicity [S1, unofficial]).

**Canonical Position and Normal:**
The canonical position $\mu_{cano}$ and normal $n_{cano}$ are computed via Phong interpolation [S1, unofficial]:
$$
\mu_{cano} = \mathcal{V}(k, u, v) = u V_1 + v V_2 + (1 - u - v) V_3
$$
$$
n_{cano} = \mathcal{N}(k, u, v) = u n_1 + v n_2 + (1 - u - v) n_3
$$
where $V_1, V_2, V_3$ are the vertices of triangle $k$, and $n_1, n_2, n_3$ are the per-vertex normals [S1, unofficial].

**Deformation:**
For a posed frame, the posed position $\mu_{pose}$ is obtained by applying mesh deformation to the canonical position and adding normal displacement:
$$
\mu_{pose} = \text{Deform}(\mu_{cano} + d \cdot n_{cano})
$$
where $\text{Deform}(\cdot)$ applies skeletal or blend-shape animation to the mesh vertices [S1, unofficial].

**Rotation:**
The posed rotation $q_{pose}$ is interpolated from per-vertex quaternions using barycentric weights and combined with the canonical rotation [S1, unofficial]:
$$
q_{pose} = \delta q * \bar{q}
$$
where $\delta q = u q_1 + v q_2 + (1 - u - v) q_3$ is the interpolated rotation from the mesh vertices, and $*$ denotes quaternion multiplication. The per-vertex quaternions $q_V$ are calculated by area-weighted average from surrounding neighbor triangles [S1, unofficial].

**Scale:**
The posed scale $s_{pose}$ is derived from the area change of the embedded triangle relative to the canonical state [S1, unofficial]:
$$
s_{pose} = \left( \frac{A_{pose}}{A_{cano}} \right) \bar{s}
$$
where $A_{pose}$ and $A_{cano}$ are the areas of the triangle in the posed and canonical states, respectively.

**Initialization Steps:**
1.  Randomly select $N$ pairs of triangle indices $k$ and barycentric coordinates $(u, v)$ on the canonical mesh.
2.  Initialize all displacements $d$ to zero.
3.  Initialize invariant parameters $\bar{q}, \bar{s}, o, c$ according to standard Gaussian Splatting initialization or specific scene requirements.
4.  Compute per-vertex quaternions $q_V$ for the mesh using area-weighted averaging of neighbor triangles [S1, unofficial].

**Pseudocode:**
```python
def initialize_mesh_embedded_gaussians(mesh, num_gaussians=10000):
    """
    Initialize Gaussians embedded on a canonical mesh.
    mesh: Object containing vertices V, normals n, triangles T, and method to get posed vertices/normals.
    """
    gaussians = []
    
    # Precompute per-vertex quaternions for the canonical mesh
    # This requires area-weighted average from surrounding neighbor triangles [S1, unofficial]
    per_vertex_quaternions = compute_per_vertex_quaternions(mesh)
    
    for i in range(num_gaussians):
        # Step 1: Randomly select triangle and barycentric coordinates
        k = random_triangle_index(mesh)
        u, v = random_barycentric_coordinates()
        d = 0.0  # Initialize displacement to zero
        
        # Step 2: Compute canonical position and normal
        V1, V2, V3 = mesh.vertices[k]
        n1, n2, n3 = mesh.normals[k]
        
        mu_cano = u * V1 + v * V2 + (1 - u - v) * V3
        n_cano = u * n1 + v * n2 + (1 - u - v) * n3
        
        # Step 3: Initialize invariant parameters
        # q_bar, s_bar, o, c are initialized here (details depend on specific implementation)
        q_bar = random_rotation_quaternion()
        s_bar = random_scale_vector()
        o = random_opacity()
        c = random_color()
        
        gaussians.append({
            'k': k, 'u': u, 'v': v, 'd': d,
            'q_bar': q_bar, 's_bar': s_bar, 'o': o, 'c': c
        })
        
    return gaussians

def get_posed_gaussian(g, mesh, per_vertex_quaternions):
    """
    Compute the posed position, rotation, and scale for a Gaussian.
    """
    k, u, v, d = g['k'], g['u'], g['v'], g['d']
    q_bar, s_bar = g['q_bar'], g['s_bar']
    
    # Get canonical vertices and normals
    V1, V2, V3 = mesh.vertices[k]
    n1, n2, n3 = mesh.normals[k]
    
    # Compute canonical position and normal
    mu_cano = u * V1 + v * V2 + (1 - u - v) * V3
    n_cano = u * n1 + v * n2 + (1 - u - v) * n3
    
    # Apply normal displacement
    mu_displaced = mu_cano + d * n_cano
    
    # Apply mesh deformation to get posed position
    # Note: Deform() applies skeletal/blend-shape animation to the mesh vertices
    mu_pose = mesh.deform(mu_displaced)
    
    # Compute posed rotation
    # Interpolate per-vertex quaternions
    q1, q2, q3 = per_vertex_quaternions[k]
    delta_q = u * q1 + v * q2 + (1 - u - v) * q3
    q_pose = quaternion_multiply(delta_q, q_bar)
    
    # Compute posed scale based on area change
    # A_cano is area of triangle in canonical space
    # A_pose is area of triangle in posed space
    A_cano = triangle_area(V1, V2, V3)
    V1_p, V2_p, V3_p = mesh.deform(V1), mesh.deform(V2), mesh.deform(V3)
    A_pose = triangle_area(V1_p, V2_p, V3_p)
    
    s_pose = (A_pose / A_cano) * s_bar
    
    return mu_pose, q_pose, s_pose, g['o'], g['c']
```

**Cross-Triangle Handling:**
Barycentric coordinates are only differentiable within a single triangle. If an optimization step moves the embedding point across a triangle boundary, the embedding must be re-expressed in the neighboring triangle to maintain differentiability [S1, unofficial]. Failure to handle this causes Gaussians to stick to boundaries and pile up [S1, unofficial]. This is addressed by the [Walking on Triangle](9700-walking-on-triangle.md) constraint mechanism.

## Subtopics

### [Walking on Triangle](9700-walking-on-triangle.md)
A constraint mechanism that binds 3D Gaussians to the surface of a triangle mesh, ensuring they remain within the boundaries of their corresponding triangles during optimization and deformation. It solves the problem of Gaussians drifting off-mesh or piling up at triangle edges when the underlying mesh is manipulated, animated, or deformed. Unlike methods that rely heavily on precise mesh accuracy, it defines a local triangle space to ensure robust results even with inaccurate meshes.

## Operating characteristics
**Time and Memory Complexity:**
Initialization is $O(N)$ where $N$ is the number of Gaussians. Deformation computation per frame is $O(N)$, involving barycentric interpolation and mesh deformation. Memory complexity is $O(N)$ for storing Gaussian parameters and $O(V)$ for mesh data, where $V$ is the number of vertices.

**Measured Performance:**
Specific performance metrics are not given in the sources. The method is designed for real-time or near-real-time rendering of dynamic avatars, as indicated by its application in [SplattingAvatar] [S1, unofficial].

**Strengths and Limitations:**
*   **Strengths:** Efficiently tracks deformation through mesh topology. Allows Gaussians to represent off-surface geometry via displacement $d$. Simple initialization.
*   **Limitations:** Requires a valid triangle mesh. Differentiability issues at triangle boundaries if not handled (see [Walking on Triangle](9700-walking-on-triangle.md)). Color representation is simplified (no spherical harmonics) in the base implementation [S1, unofficial].

**When to Use:**
Use when rendering dynamic avatars or deformable objects where the underlying geometry is well-represented by a triangle mesh and deformation is driven by skeletal or blend-shape animation.

**When Not to Use:**
Not suitable for static scenes without a mesh or scenes with complex, non-mesh-based geometry.

## Background
This method is part of the [SplattingAvatar] framework [S1, unofficial]. It builds on the principles of [Mesh-embedded representation](12559-mesh-embedded-representation.md) and [Gaussian Splatting](https://arxiv.org/abs/2308.04079) [S1, unofficial]. The use of Phong interpolation for position and normal is standard in computer graphics [S1, unofficial]. The area-weighted average for per-vertex quaternions is a technique to ensure smooth rotation interpolation across the mesh surface [S1, unofficial].
