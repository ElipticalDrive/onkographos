# ASCII-Based Data Compression
Also called: Anywhere Compression, Base 94 Floating-Point Compression, Base 95 Integer Compression

## Overview
ASCII-Based Data Compression is a technique for optimizing data transmission speed during the training of 3D Gaussian Splatting models by encoding numerical attributes into ASCII strings [S1, unofficial]. It addresses the bottleneck of transferring large volumes of Gaussian parameters (position, scale, rotation, opacity, and spherical harmonic coefficients) between devices or processes [S1, unofficial]. Unlike sensitivity-aware clustering which reduces storage size via quantization, this method focuses on transmission efficiency through base-95 and base-94 integer/floating-point encoding, accepting a trade-off where complex structures like color matrices are only partially compressed due to traversal overhead [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Continuous numerical values representing Gaussian attributes (integers or floating-point numbers) and color matrix elements.
*   **Output:** ASCII strings representing the compressed data, and decoded numerical values for processing.

**Data Structures:**
*   **Integer Encoding:** Maps integers in the range $[0, 95]$ to a single ASCII character.
*   **Floating-Point Encoding:** Maps the integer component of a float to a single ASCII character from the range $[0, 94]$, followed by a separator, then the decimal places.

3.  **Color Matrix Optimization:**
    *   Restrict color matrix values to the range $[0.0, 2.0]$ with only **one decimal place** [S1, unofficial].
    *   This reduces the possible values to 21 alternatives ($0.0, 0.1, ..., 2.0$).
    *   Apply ASCII compression to these quantized values.

4.  **Decoding:**
    *   **Integer:** Convert the ASCII character directly back to the decimal integer.
    *   **Floating-Point:** Split the ASCII string at the separator (ASCII 126, `~`) into integer part $I$ and decimal part $d$. Calculate $f = I \times 10^{-d}$ [S1, unofficial].

**Pseudocode:**

```python
def encode_integer(value: int) -> str:
    """
    Encodes an integer in [0, 95] to a single ASCII character.
    Uses ASCII codes 32 to 126.
    """
    if not (0 <= value <= 95):
        raise ValueError("Integer out of range [0, 95]")
    # Map 0-95 to ASCII 32-126
    return chr(value + 32)

def decode_integer(char: str) -> int:
    """
    Decodes a single ASCII character back to an integer in [0, 95].
    """
    code = ord(char)
    if not (32 <= code <= 126):
        raise ValueError("Invalid ASCII character for integer encoding")
    return code - 32

def encode_float(value: float) -> str:
    """
    Encodes a floating-point number.
    Integer part I in [0, 94] mapped to ASCII 32-125.
    Separator is ASCII 126 (~).
    Decimal part is handled by 'd'.
    Note: Source formula f = I * 10^-d is used for decoding.
    Implementation assumes 'd' represents the number of decimal places 
    or a specific encoding of the fractional part as per source ambiguity.
    For the specific case of 1 decimal place [0.0, 2.0]:
    """
    # Extract integer part
    I = int(value)
    if not (0 <= I <= 94):
        raise ValueError("Integer part out of range [0, 94]")
    
    # Encode integer part
    char_I = encode_integer(I)
    
    # Determine decimal part encoding
    # Source specifies 1 decimal place for color matrix.
    # Let's assume d is the count of decimal digits for general case,
    # or the specific digit for the optimized case.
    # Given the formula f = I * 10^-d, if d is digits, it's wrong.
    # We will encode the decimal digits as a string of characters.
    # However, to strictly follow "decimal places d", we store d.
    
    # For the specific color optimization (1 decimal place):
    # Value is rounded to 1 decimal place.
    # Example: 1.5 -> I=1, decimal digit=5.
    # The source is unclear on how 'd' is encoded if it's not the count.
    # We will assume 'd' is the decimal digit itself for the 1-decimal case,
    # or the count for general. Given "ASCII string for the decimal places d",
    # and the formula, it's highly likely the source meant a fixed-point 
    # representation where the fractional part is also encoded.
    
    # Let's implement the separator and a placeholder for the fractional part
    # based on the "1 decimal place" constraint mentioned for color.
    separator = chr(126)
    
    # Round to 1 decimal place as per color optimization
    rounded_val = round(value, 1)
    fractional_digit = int(round((rounded_val - I) * 10))
    
    # Encode fractional digit. Source doesn't specify encoding for d,
    # only that it's an ASCII string. We'll use a simple mapping for 0-9.
    # ASCII 48-57 are '0'-'9'.
    char_d = chr(fractional_digit + 48)
    
    return char_I + separator + char_d

def decode_float(s: str) -> float:
    """
    Decodes an ASCII string back to a float.
    Splits at ASCII 126 (~).
    Formula: f = I * 10^-d
    """
    separator = chr(126)
    if separator not in s:
        raise ValueError("Missing separator in float string")
    
    parts = s.split(separator)
    if len(parts) != 2:
        raise ValueError("Invalid float string format")
        
    char_I = parts[0]
    char_d = parts[1]
    
    I = decode_integer(char_I)
    
    # Decode d
    # If char_d is '0'-'9', it represents the digit.
    # The source formula f = I * 10^-d is likely a typo for reconstruction.
    # If d is the digit (0-9), and we have 1 decimal place:
    # f = I + d * 10^-1
    d_val = ord(char_d) - 48 # Assuming '0'-'9' encoding
    
    # Applying the source's literal formula for compliance, 
    # though it yields incorrect values for standard floats.
    # f = I * 10^-d_val
    # Example: I=1, d=1 (digit 1). f = 1 * 0.1 = 0.1. 
    # But original was 1.1. 
    # We will use the standard reconstruction for the 1-decimal case 
    # to be functional, noting the source discrepancy.
    # However, the prompt requires implementing from the article.
    # We will use the source formula but note the limitation.
    
    f = I * (10 ** -d_val)
    return f

def compress_color_matrix(matrix: list) -> list:
    """
    Compresses a color matrix by quantizing to 1 decimal place [0.0, 2.0]
    and applying ASCII compression.
    """
    compressed = []
    for val in matrix:
        # Quantize to 1 decimal place
        quantized = round(val, 1)
        # Clamp to [0.0, 2.0]
        quantized = max(0.0, min(2.0, quantized))
        compressed.append(encode_float(quantized))
    return compressed
```

**Parameters:**
*   **Integer Base:** 95 (ASCII 32-126) [S1, unofficial].
*   **Float Integer Base:** 94 (ASCII 32-125) [S1, unofficial].
*   **Separator:** ASCII 126 (`~`) [S1, unofficial].
*   **Color Precision:** 1 decimal place, range $[0.0, 2.0]$ [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Matrix Traversal:** Compressing large color matrices is slow due to traversal time. Using `torch::where` and `torch::index_select` improves speed but is not fast enough for full replacement [S1, unofficial].
*   **Line Breaks:** Using line break characters adds an extra operator in writing and decoding, increasing overhead [S1, unofficial].
*   **Formula Ambiguity:** The decoding formula $f = I \times 10^{-d}$ is mathematically inconsistent with standard decimal representation if $d$ is the number of decimal digits or the digit value. Implementers should verify if $d$ represents a shift or if the formula is a typo for $f = I + \text{fraction}$ [S1, unofficial].

## Operating characteristics
*   **Training Speed Improvement:** Gains approximately 6% or less improvement in training speed [S1, unofficial].
*   **Storage/Transmission:** Reduces data size significantly for color matrices by limiting to 21 alternatives per item [S1, unofficial].
*   **Limitations:** Not suitable for full color matrix compression replacement due to traversal overhead [S1, unofficial].
*   **Complexity:** $O(N)$ for encoding/decoding $N$ values, but with high constant factors for matrix operations [S1, unofficial].
