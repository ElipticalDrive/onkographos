# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific implementation parameters, optimization schedules, and algorithmic variants required to train and render 3D Gaussian Splatting (3DGS) scenes effectively. It addresses the gap between the theoretical differentiable rasterization framework and practical execution, covering training loops, densification controls, and specialized handling for defocus, noise, and internal volumes. It sets itself apart from generic optimization articles by providing concrete hyperparameters, specific CUDA-level optimizations (such as half-precision fetches), and distinct variant algorithms for handling non-standard scene conditions like sparse views or internal structures.

## How it works

### 3D Gaussian Splatting Training Loop
The core training process is an iterative loop that optimizes Gaussian parameters to minimize the difference between rendered images and ground-truth photographs [S10, unofficial].

**Inputs:**
- Set of $N$ training images with known camera poses.
- Initial set of 3D Gaussians (typically derived from Structure-from-Motion points).
- Loss weights $\lambda$ (typically 0.2 for SSIM, 0.8 for L1) [S10, unofficial].
- Iteration budget (typically 30,000 iterations) [S10, unofficial].

**Outputs:**
- Optimized set of 3D Gaussians with positions, covariances, opacities, colors, and SH coefficients.

**Steps:**
1. **Random Selection:** Randomly select one input photo from the training set for the current iteration [S10, unofficial].
2. **Rendering:** Render the current set of Gaussians from the known camera pose of the selected photo using the differentiable rasterizer [S10, unofficial].
3. **Loss Computation:** Compare the rendered image against the original photo pixel-by-pixel. The total loss $\mathcal{L}$ is a weighted sum of L1 loss and D-SSIM:
   $$ \mathcal{L} = (1 - \lambda) \mathcal{L}_{L1} + \lambda \mathcal{L}_{SSIM} $$
   where $\lambda \approx 0.2$ [S10, unofficial].
4. **Gradient Update:** Compute gradients of $\mathcal{L}$ with respect to all Gaussian parameters (position, covariance, opacity, color, SH coefficients) and update them using an optimizer (typically Adam with learning rate $1 \times 10^{-3}$) [S2][S10, unofficial].
5. **Iteration:** Repeat steps 1–4 for the specified iteration budget (e.g., 30,000 iterations) [S10, unofficial].

**Pitfalls:**
- Training does not stop at a specific loss threshold but rather at a fixed iteration budget, as the loss curve continues to creep down with diminishing returns [S10, unofficial].
- Using all views simultaneously is computationally prohibitive; stochastic selection is required [S10, unofficial].

### Optimization and Parallelization Details
To achieve real-time performance and stability, specific implementation choices are made in the rasterization and optimization kernels [S1].

**Half-Precision Rasterization:**
- Feature vectors are fetched using half-precision (FP16) memory accesses during both forward and backward passes of the rasterization kernels. This reduces register pressure and memory bandwidth usage [S1].
- An automatic scaling factor is applied to loss values to improve training stability in half-precision [S1].

**Neural Network Integration:**
- If auxiliary networks (e.g., for color refinement) are used, they are implemented using JIT-compiled cooperative vector MLPs (e.g., via `tiny-cuda-nn`) and trained/evaluated in FP16 [S1].
- The Gaussian Rasterization Library `gsplat` is commonly used, often based on the 3DGUT formulation [S1][S2].

### Densification and Scene Extent Control
The number of Gaussians is controlled through densification (splitting/cloning) and pruning, which depend critically on the calculated scene extent [S3].

**Corrected Scene Extent:**
The default scene extent $e_{\text{scene}}$ is proportional to the distance of the furthest camera from the average camera position:
$$ e_{\text{scene}} = 1.1 \cdot \max_{i=1}^{N_{\text{cam}}} \|\bar{C} - C_i\|_2 $$
where $\bar{C} = \frac{1}{N_{\text{cam}}} \sum_{i=1}^{N_{\text{cam}}} C_i$ [S3].

**Pitfall:** If cameras are clustered (e.g., orbiting a small object in a large environment), $e_{\text{scene}}$ becomes artificially small, leading to incorrect splitting/pruning of Gaussians that are appropriately sized for the actual scene volume [S3].

**Correction:** Use the Structure-from-Motion (SfM) point cloud to calculate the scene extent:
$$ e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2 $$
where $N_{\text{SfM}}$ is the number of SfM points and $p_i$ is the $i$-th SfM point [S3].

**Gradient Threshold Schedule:**
To control the number of split/cloned Gaussians, an exponentially ascending gradient threshold is applied during the densification interval. This ensures that the number of densified Gaussians corresponds to an exponential schedule, preventing explosion or stagnation [S3].

### Multi-Scale Constraint for Large Scenes
For large-scale scenes with varying distances, a position-aware point adaptive control adjusts Gaussian scales based on viewer distance [S7].

**Formula:**
Define a scaling factor $\gamma(\mu)$ based on the distance of the Gaussian center $\mu$ from the camera center $c$ and the scene radius $r$:
$$ \gamma(\mu) = \begin{cases} 1 & \text{if } \|\mu - c\|^2 < 2r \\ \frac{\|\mu - c\|^2}{r} - 1 & \text{if } \|\mu - c\|^2 \ge 2r \end{cases} $$

**Operations:**
- **Cloning:** If $\max(s) < g \cdot \gamma(\mu)$, perform cloning on the Gaussian ellipsoid.
- **Splitting:** If $\max(s) \ge g \cdot \gamma(\mu)$, execute the splitting procedure.
- **Elimination:** Eliminate Gaussian ellipsoids where $\max(s) > b \cdot \gamma(\mu)$.

Here, $g$ and $b$ are scale threshold parameters [S7]. This approach uses larger Gaussians for distant objects and smaller ones for nearby regions, improving rendering quality across scales [S7].

### Model-Based Depth Estimation for Volume Parameter Update
In volumetric rendering scenarios (e.g., underwater), depth values extracted from the 3DGS scene are used to update medium parameters [S6].

**Depth Extraction:**
Depth $z$ is computed at each pixel during rendering as a weighted average of Gaussian depths:
$$ z = \frac{\sum_{i=1}^M d_i \alpha_i T_i}{\sum_{i=1}^M \alpha_i T_i} $$
where $d_i$ is the depth of Gaussian $i$, $\alpha_i$ is opacity, and $T_i$ is transmittance [S6]. These depth values are then used to update medium-parameter estimates ($B_\infty, B_b$) via optimization [S6].

## Subtopics

### [Sorting and Rendering Pipeline Optimization](12180-sorting-and-rendering-pipeline-optimization.md)
This family addresses computational bottlenecks in 3DGS rendering, specifically targeting memory bandwidth limits in the front-end (sorting and attribute fetching) and compute throughput limits in the rasterization stage. It sets itself apart from generic optimization by explicitly mapping software strategies to hardware constraints (e.g., using the Roofline model) or by replacing standard sorting with hardware-friendly, comparison-free logic and sorting-free approximations.

### [LangSplat Training Procedure](12438-langsplat-training-procedure.md)
LangSplat Training Procedure is a method for optimizing 3D Gaussian Splatting scenes to incorporate semantic language features alongside photometric rendering. It extends the standard differentiable rendering pipeline by computing a loss against ground-truth language embeddings (e.g., CLIP features) when enabled, allowing the scene to support semantic queries. It is distinguished from standard 3D Gaussian Splatting training by the conditional inclusion of language feature loss and the consequent disabling of densification and pruning operations during language-aware training.

### [Gaussian Representation and Truncation](12855-gaussian-representation-and-truncation.md)
This article defines the fundamental data structures, mathematical representation, and rendering pipeline for 3D Gaussian Splatting (3DGS) primitives, which serve as the basis for the methods in this family. It solves the problem of how to represent a continuous radiance field using discrete, differentiable volumetric primitives that can be efficiently rasterized. It sets apart from sibling methods by providing the standard, unmodified Gaussian kernel and truncation logic; siblings like Inverse Multiquadric Splatting or Opacity-Independent Gaussian Truncation modify these core definitions to address specific artifacts or efficiency issues.

### [DeSplat](12925-desplat.md)
DeSplat is a method for distractor-free novel view synthesis that decomposes the 3D Gaussian Splatting (3DGS) scene representation into two distinct sets of Gaussian primitives: static scene Gaussians ($G_s$) and per-view distractor Gaussians ($G_d$). It solves the problem of transient occluders (e.g., pedestrians, vehicles) corrupting the static 3D reconstruction by separating them from the permanent scene geometry without relying on external semantic segmentation models or pre-trained neural networks. Unlike sibling methods that use foundation models for detection or complex neural appearance encoders for separation, DeSplat relies solely on volume rendering and photometric loss, allowing independent rendering of static elements and transient components while maintaining the speed of standard Gaussian splatting.

### [360 Gaussian Splatting](12929-360-gaussian-splatting.md)
360 Gaussian Splatting is a method for generating high-quality 3D spatial representations from 360-degree camera images by combining OpenSfM for sparse point cloud generation and Gaussian Splatting for dense Gaussian conversion. It solves the problem that standard Gaussian Splatting assumes perspective cameras and cannot directly process equirectangular images from 360-degree cameras, a limitation that previously forced users to crop or split images. It sets itself apart from standard implementations by modifying the differentiable rasterization module to support spherical rendering and using OpenSfM, which natively supports equirectangular inputs, unlike Colmap.

### [Data Compression and Storage Optimization](12943-data-compression-and-storage-optimization.md)
This family of methods addresses the excessive memory footprint and storage overhead of 3D Gaussian Splatting (3DGS), which often exceeds 1 GB for large scenes due to per-Gaussian attributes. The methods reduce storage requirements by compressing numerical representations, clustering parameters into codebooks, or replacing explicit attributes with neural fields. They distinguish themselves from sibling methods like Sorting and Rendering Pipeline Optimization by focusing on data representation density rather than rendering throughput, and from Gaussian Representation and Truncation by employing structural compression (clustering/quantization) rather than geometric pruning alone.

### [Bézier-boundary gradient approximation](13137-b-zier-boundary-gradient-approximation.md)
This method approximates the gradients of a discontinuous indicator function $g(\cdot)$ with respect to Bézier curve control point coordinates, enabling backpropagation in Gaussian Splatting despite the function being piecewise constant and non-differentiable. It sets itself apart from standard Gaussian Splatting, which relies on differentiable rendering, by explicitly handling the non-differentiable segments of discontinuity-aware rendering through geometric boundary analysis.

### [Discontinuity-aware Gaussian Splatting](13138-discontinuity-aware-gaussian-splatting.md)
Discontinuity-aware Gaussian Splatting (DisC-GS) is a framework that enables 3D Gaussian Splatting to represent and render sharp boundaries and discontinuities, addressing a key limitation of the original method which assumes smooth, continuous alpha blending. It distinguishes itself from standard Gaussian Splatting by introducing a "pre-scissoring" step that segments projected Gaussians along boundaries defined by cubic Bézier curves, combined with a Bézier-boundary gradient approximation strategy to maintain differentiability during optimization.

### [SOGS (Second-Order Anchor for Advanced 3D Gaussian Splatting)](13171-sogs-second-order-anchor-for-advanced-3d-gaussian-splatting.md)
SOGS is an anchor-based 3D Gaussian Splatting technique that introduces second-order statistics to achieve superior rendering quality while simultaneously reducing anchor feature dimensions and overall model size. It distinguishes itself from standard anchor methods like Scaffold-GS by using covariance-based feature augmentation to capture co-variation patterns across feature dimensions, allowing for smaller feature vectors without sacrificing detail.

### [Mesh Extraction and Representation](14095-mesh-extraction-and-representation.md)
This family of methods converts the continuous, volumetric representation of 3D Gaussian Splatting (3DGS) into explicit geometric structures, primarily triangular meshes or discrete point clouds, to enable compatibility with standard 3D graphics pipelines, editing tools, and animation frameworks. Unlike standard 3DGS rendering which rasterizes splats directly, these methods extract surface geometry either by regularizing Gaussians to align with scene surfaces during training (SuGaR Mesh Extraction) or by sampling discrete points from the Gaussian distributions post-training (3D Gaussian Splatting to Point Cloud).

### [TraGraph-GS](14454-tragraph-gs.md)
TraGraph-GS is a high-quality rendering method for arbitrary large-scale scenes that employs graph-based adaptive spatial partitioning, regularization constraints, and adaptive region selection. It addresses the limitations of standard 3D Gaussian Splatting (3DGS) in handling vast scales and textureless regions by decoupling the scene into manageable local regions and a coarse global representation. Unlike methods that rely on fixed spatial grids or simple clustering, TraGraph-GS constructs a camera connectivity graph to ensure balanced, connected subgraphs, and uses a progressive rendering strategy for novel viewpoints to eliminate boundary artifacts.

### [Explicit 4D Gaussian Splatting](14584-explicit-4d-gaussian-splatting.md)
Explicit 4D Gaussian Splatting (Ex4DGS) is a method for dynamic scene rendering that achieves memory efficiency and rendering capacity by separating Gaussians into static and dynamic categories and explicitly sampling positions and rotations at sparse timestamps. It differs from implicit trajectory-based methods by storing explicit keyframe data for dynamic Gaussians and using interpolation to reconstruct continuous motion, thereby avoiding the memory overhead of multiple primitives for occluded objects.

### [Color and Appearance Modeling](14740-color-and-appearance-modeling.md)
Color and Appearance Modeling in 3D Gaussian Splatting addresses the limitations of the base method's fixed Spherical Harmonics (SH) representation, which struggles with complex lighting, transient objects, and high-frequency view-dependent effects. It solves the problem of color distortion and floaters by introducing dynamic mechanisms to modulate Gaussian radiance or opacity based on spatial position, viewing direction, or image context. It sets itself apart from siblings by either decoupling global appearance from local geometry (DAVIGS), factorizing illumination and material properties (3iGS), or conditioning rendering on per-image embeddings to handle wild images (SWAG), rather than relying solely on the static SH coefficients of base 3DGS.

### GS-IR (Gaussian Splatting for Internal Rendering)
GS-IR is an inverse rendering approach based on 3D Gaussian Splatting (3DGS) that leverages forward mapping volume rendering to achieve photorealistic novel view synthesis and relighting results, estimating scene geometry, surface material, and environment illumination from multi-view images captured under unknown lighting conditions. Unlike NeRF-based inverse rendering methods that use implicit neural representations and ray tracing (backward mapping) which suffer from low expressive power and high computational complexity, GS-IR uses 3D Gaussians and forward mapping splatting for real-time rendering efficiency.

### [Physics and Optical Modeling](15148-physics-and-optical-modeling.md)
Physics and Optical Modeling extends the standard 3D Gaussian Splatting (3DGS) image formation pipeline to account for physical light transport phenomena, specifically volumetric attenuation and scattering. It solves the problem of inaccurate rendering in non-vacuum media (such as underwater environments) or the need for geometrically consistent surface extraction by reformulating the discrete alpha-blending rasterization into a continuous volumetric integration framework. It distinguishes itself from standard 3DGS by introducing learnable medium parameters (attenuation and backscatter coefficients) or by deriving continuous attenuation fields from Gaussian densities to ensure unbiased surface extraction, thereby addressing color distortion and depth inconsistency issues inherent in the base method.

### Corrected Scene-Extent
A method to calculate scene extent based on the SfM point cloud rather than camera positions to avoid bias from camera distribution (e.g., orbiting a small object in a large environment). The corrected scene extent $e'_{\text{scene}}$ is calculated as $e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2$, where $N_{\text{SfM}}$ is the number of SfM points, $\bar{C}$ is the averaged camera position, and $p_i$ is the $i$-th SfM point. The default method, which uses camera positions, can lead to incorrect splitting/pruning if cameras are clustered [S3].

### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ to selectively enlarge covariances, creating pixel-wise variable blur kernels that match spatially varying scene blurriness. A compact MLP predicts $\delta s_j$ for each Gaussian $j$, which is added to the base scale to transform the covariance. The transformed covariance is projected to 2D space and used as a pixel-wise blur kernel during rasterization. If $\delta s_j$ is predicted as a constant for all Gaussians, it degrades to a uniform Gaussian blur over the entire image [S4].

### Denoise-GS
A self-supervised denoising method for sparse-view 3D Gaussian Splatting that combines unsupervised image denoising with explicitly differentiable 3DGS to address suboptimal reconstruction performance in sparse view and noisy scenes. The process involves two rounds: Round 1 trains a UNet using Noise2Void (N2V) for denoising, processes denoised images through InstantSplat to initialize/train 3DGS, and filters rendered results. Round 2 fine-tunes the UNet using a composite loss balancing low-frequency and perceptual detail consistency, then renders again on selected viewpoints [S5]. Unlike supervised methods, it requires no paired clean data, and unlike N2N, it requires no paired noisy images [S5].

### LS-Gaussian Viewpoint Transformation
An algorithm that leverages inter-frame continuity for efficient sparse rendering by transforming the viewpoint between consecutive frames, rather than rendering each frame separately. It operates at the tile/Gaussian level to enable sparse rendering, unlike naive pixel warping which fails to reduce preprocessing and sorting costs. Rendering quality degrades noticeably as the number of consecutively transformed frames increases due to the accumulation of interpolation errors. It is used in LS-Gaussian to enable sparse rendering where only one frame in every 6 frames is fully rendered [S8].

### LS-Gaussian Accelerator Architecture
A hardware architecture co-designed with the LS-Gaussian algorithm to support workload-aware mapping, featuring a streaming pipeline that allows continuous processing across hardware modules without requiring global synchronization. The accelerator predicts the workload for each tile based on viewpoint transformation to enable more balanced parallel computation. Unlike naive assignment of tiles to rendering blocks which fails to achieve balanced load distribution, this architecture uses workload prediction to mitigate inter-block idling and intra-block bubbles [S8].

### GS-IR (Gaussian Splatting for Internal Rendering)
GS-IR is a plane-based internal rendering framework that replaces exterior-view supervision with cross-sectional supervision sampled from a volume to reconstruct internal volumetric structure. Virtual cameras define slicing planes within the volume. A binary mask selects the Gaussian subset whose centers lie within the plane thickness. The selected Gaussian subset is rendered using the original Gaussian rasterizer. Optimization is performed against ground-truth cross-sections generated through trilinear resampling. Distance-aware soft weighting is applied to continuously attenuate Gaussian opacity as the distance from the Gaussian to the plane increases. This method improves PSNR by up to 21.52 dB and SSIM by up to 0.54 on medical datasets, focusing optimization gradients on interior Gaussians to supervise occluded internal regions [S9].

## Operating characteristics

**Time and Memory Complexity:**
- Training complexity is dominated by the number of Gaussians $N$ and the number of pixels $P$. The rasterization step is approximately $O(N)$ per pixel, but with spatial partitioning and culling, it is often closer to $O(P)$ in practice.
- Memory usage scales linearly with the number of Gaussians. Each Gaussian stores position (3 floats), covariance (6 floats), opacity (1 float), SH coefficients (variable, e.g., 45 floats for degree 2), and color (3 floats).
- Half-precision rasterization reduces memory bandwidth requirements and register pressure, improving throughput on modern GPUs [S1].

**Measured Performance:**
- Standard 3DGS training on scenes like Mip-NeRF360 typically runs for 30,000 iterations [S10, unofficial].
- LS-Gaussian achieves a 5.41× speedup over edge GPU baselines and up to 17.3× with a custom accelerator, enabling real-time rendering on resource-constrained devices like Jetson AGX Orin [S8].
- GS-IR improves PSNR by up to 21.52 dB and SSIM by up to 0.54 on KiTS23 CT and IXI MRI datasets [S9].

**Scaling:**
- Large-scale scenes require spatial partitioning (e.g., grids, trees) to manage Gaussian culling and sorting efficiently [S7].
- Distributed training and sharding are necessary for scenes exceeding single-GPU memory [S15108].

**Strengths and Limitations:**
- **Strengths:** Real-time rendering, high visual fidelity, explicit representation allows for easy editing and integration with other graphics pipelines.
- **Limitations:** High memory footprint for large scenes, potential for "floaters" in textureless regions, sensitivity to initialization and densification parameters.

**When to Use:**
- Use when real-time novel view synthesis is required.
- Use when explicit scene representation is needed for downstream tasks (e.g., mesh extraction, AR/VR).
- Use variants like Denoise-GS for sparse/noisy views, or GS-IR for internal volume reconstruction.

**When Not to Use:**
- Avoid if memory is extremely constrained and compression techniques are insufficient.
- Avoid if the scene has extreme dynamic range or complex light transport that standard alpha blending cannot capture (consider Physics and Optical Modeling variants).

## Background

3D Gaussian Splatting was introduced by Kerbl et al. in 2023 as a real-time explicit scene representation method [S10, unofficial]. It builds on the idea of using differentiable volumetric primitives (Gaussians) that can be rasterized efficiently. The method gained popularity due to its ability to achieve high-quality novel view synthesis at interactive frame rates. Subsequent research has focused on optimizing the training process, reducing memory footprint, and extending the method to handle special cases like defocus blur, noise, and internal volumes [S1-S9]. The implementation details described here reflect the community's best practices and specific optimizations developed in various papers and repositories [S1-S10].
