# SH Coefficient Interleaving

Also called: SH Data Layout Interleaving, SH Interleaving

## Overview
SH Coefficient Interleaving is a data layout strategy for 3D Gaussian Splatting that packs spherical harmonic (SH) coefficients into a single contiguous array by grouping coefficients by channel rather than by degree. It solves the problem of efficient memory access during rendering by ensuring that all color channels for a specific SH degree are stored adjacently, which aligns with how SH values are evaluated and applied to RGB output. It differs from non-interleaved layouts (which store all coefficients for one channel before moving to the next) by optimizing for vectorized processing of the RGB triplet during the final color computation step.

## How it works
**Inputs:**
- `sh_dc`: A 3-component vector (RGB) representing the zeroth-degree (DC) spherical harmonic coefficients.
- `sh_rest`: A 1D array of floating-point numbers containing the higher-order SH coefficients. The total number of coefficients per channel is `coeffs_per_channel`. The total size of `sh_rest` is `3 * coeffs_per_channel`.
- `channels`: The number of color channels, typically 3 (RGB).

**Outputs:**
- `result`: A 1D array containing the interleaved SH data. The total size is `3 + (3 * coeffs_per_channel)`.

**Data Structure:**
The output array is structured as follows:
1. The first 3 elements are `sh_dc.x`, `sh_dc.y`, `sh_dc.z`.
2. The remaining elements are filled by iterating through the SH degrees (indices `i` from `0` to `coeffs_per_channel - 1`). For each degree `i`, the coefficients for all 3 channels are appended in order: `sh_rest[0 * coeffs_per_channel + i]`, `sh_rest[1 * coeffs_per_channel + i]`, `sh_rest[2 * coeffs_per_channel + i]`.

**Algorithm:**
1. Initialize an empty list `result`.
2. Append `sh_dc.x` to `result`.
3. Append `sh_dc.y` to `result`.
4. Append `sh_dc.z` to `result`.
5. Let `coeffs_per_channel` be the number of higher-order coefficients per channel.
6. For `i` from `0` to `coeffs_per_channel - 1`:
    a. For `j` from `0` to `2` (representing R, G, B):
        i. Calculate the index in the source array: `index = j * coeffs_per_channel + i`.
        ii. Append `sh_rest[index]` to `result`.

**Pseudocode:**
```python
def interleave_sh_coefficients(sh_dc, sh_rest, coeffs_per_channel):
    """
    Interleaves SH DC and rest coefficients into a single array.
    
    Args:
        sh_dc: List or array of 3 floats [R, G, B] for DC coefficients.
        sh_rest: List or array of floats containing higher-order SH coefficients.
                 Layout is assumed to be [R_coeffs..., G_coeffs..., B_coeffs...].
        coeffs_per_channel: Integer, number of higher-order coefficients per channel.
    
    Returns:
        List of floats with interleaved layout.
    """
    result = []
    
    # Append DC coefficients
    result.append(sh_dc[0])
    result.append(sh_dc[1])
    result.append(sh_dc[2])
    
    # Interleave rest coefficients
    # sh_rest is organized as [R0, R1, ..., Rn, G0, G1, ..., Gn, B0, B1, ..., Bn]
    # We want to output: R0, G0, B0, R1, G1, B1, ...
    
    for i in range(coeffs_per_channel):
        for j in range(3):  # 0 for R, 1 for G, 2 for B
            index = j * coeffs_per_channel + i
            result.append(sh_rest[index])
            
    return result
```

**Parameters:**
- `coeffs_per_channel`: Determined by the maximum SH degree used. For degree 1, `coeffs_per_channel = 3`. For degree 2, `coeffs_per_channel = 8`. Not given in the sources for other degrees, but standard SH theory applies.

**Edge Cases and Pitfalls:**
- **Precision:** The source code in [S1, unofficial] implies the use of standard floating-point types (likely `f32` or `f16` depending on the asset format). Precision loss can occur if converting to lower precision formats like Norm11 or Norm6 without proper quantization [S1, unofficial].
- **Boundary Conditions:** Ensure `sh_rest` has exactly `3 * coeffs_per_channel` elements. Accessing `sh_rest[index]` where `index >= len(sh_rest)` will cause an out-of-bounds error.
- **Degenerate Input:** If `coeffs_per_channel` is 0, only the DC coefficients are written.

## Operating characteristics
**Time Complexity:** $O(N)$, where $N$ is the total number of SH coefficients. The operation involves a single pass through the `sh_rest` array with constant-time appends.
**Memory Complexity:** $O(N)$ for the output array. The input and output arrays are of similar size, so no significant memory overhead is incurred beyond the output buffer.
**Performance:** This layout is optimized for rendering performance. By interleaving RGB coefficients for each SH degree, the GPU can load a single SH degree's contribution for all three color channels in a single memory transaction or vector load, reducing memory bandwidth pressure during the color evaluation phase.
**Strengths:** Efficient memory access patterns for RGB rendering; compact storage.
**Limitations:** Requires careful indexing logic during data preparation. Not optimal for algorithms that process one color channel independently across all degrees.

## Background
SH Coefficient Interleaving is a specific data layout technique used in modern 3D Gaussian Splatting engines, such as Brush, to optimize the storage and retrieval of spherical harmonic coefficients for view-dependent coloring. It builds on the general principles of spherical harmonic representation in graphics [S1, unofficial].
