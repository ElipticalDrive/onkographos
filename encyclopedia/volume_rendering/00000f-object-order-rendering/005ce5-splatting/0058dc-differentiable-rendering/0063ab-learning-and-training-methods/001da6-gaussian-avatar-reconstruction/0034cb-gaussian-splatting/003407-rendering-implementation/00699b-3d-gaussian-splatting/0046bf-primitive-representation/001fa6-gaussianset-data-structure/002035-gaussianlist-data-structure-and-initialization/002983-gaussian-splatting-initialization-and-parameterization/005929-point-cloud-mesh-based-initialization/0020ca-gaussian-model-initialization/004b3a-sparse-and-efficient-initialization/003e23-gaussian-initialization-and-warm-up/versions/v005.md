# Gaussian Initialization and Warm-up

Also called: Random initialization, Warm-up stage

## Overview
Gaussian Initialization and Warm-up establishes the initial state of 3D Gaussian primitives and optimizes them in a static phase before introducing complex dynamics or densification. It solves the problem of poor convergence and incorrect placement caused by high initial opacity/reflectivity and the lack of a stable starting configuration [S1, S3]. It sets itself apart from [Dense Initialization (DI)](10026-dense-initialization-di.md) by starting with a sparse, random set rather than a dense coverage, and from [Recurrent Gaussian Update](10974-recurrent-gaussian-update.md) by relying on gradient-based optimization rather than a feed-forward network [S1, S1].

## How it works
**Inputs:** Camera poses, raw image data (e.g., C-ToF quartets or RGB), scene bounds (near/far planes).
**Outputs:** Initialized set of 3D Gaussians (means, covariances, colors, opacities, scales) and optimized parameters after the warm-up phase.

**Data Structures:**
*   **Gaussian Set:** A list of $N$ Gaussians. Each Gaussian $i$ has:
    *   Mean $\mu_i \in \mathbb{R}^3$: Position.
    *   Covariance $\Sigma_i \in \mathbb{R}^{3 \times 3}$: Shape/Orientation.
    *   Color $c_i$: Spherical Harmonic coefficients.
    *   Opacity $\alpha_i \in [0, 1]$.
    *   Scale $s_i \in \mathbb{R}^3$.

**Steps:**

1.  **Random Placement:** Initialize Gaussian means $\mu_i$ randomly within the camera frustum, bounded by the near and far planes [S1].
2.  **Reflectivity/Opacity Bias:** Initialize the initial reflectivity (or opacity $\alpha_i$) to a low value, typically between $0.01$ and $0.1$ [S1].
    *   *Rationale:* High initial reflectivity (e.g., 0.5) causes Gaussians in low-reflectivity regions to be incorrectly placed far from the camera due to inverse-square falloff assumptions, leading to multiple opacity peaks and interference from closer splats [S1]. Low initial reflectivity allows Gaussians to be placed more correctly, closer to the true scene depth [S1].
3.  **Coordinate Rescaling (Optional/Contextual):** If using an MLP for deformation or color prediction, rescale input coordinates to the unambiguous depth range to ensure most values lie within $[0, 1]$ [S1].
4.  **Warm-up Phase:** Run an initial optimization stage for a fixed number of iterations (typically 2,000) assuming the scene is static [S1]. This places Gaussians into useful positions before introducing dynamics or densification [S1].
5.  **Background Perturbation (For Low-Reflectivity Areas):** In sensitive low-reflectivity regions, randomly change the background signal (uniformly between $-1$ and $1$) at each optimization iteration [S1].
    *   *Rationale:* A low background contribution can cause Gaussians to fail to place on surfaces because the background already reproduces the signal, resulting in only low-contributing Gaussians [S1].

**Pseudocode:**

```python
def initialize_gaussians_and_warmup(cameras, scene_bounds, num_gaussians, warmup_iters=2000):
    """
    Initialize 3D Gaussians and run a static warm-up phase.
    """
    gaussians = []
    
    # Step 1: Random Placement within Frustum
    for i in range(num_gaussians):
        gaussian = Gaussian()
        # Sample position within near/far planes of the camera frustum
        gaussian.mean = sample_random_point_in_frustum(cameras, scene_bounds.near, scene_bounds.far)
        
        # Step 2: Low Reflectivity/Opacity Bias
        # Initialize opacity/reflectivity to low value to prevent incorrect placement
        gaussian.opacity = random.uniform(0.01, 0.1)
        
        # Initialize other attributes (scales, colors) to defaults or small random values
        gaussian.scale = [1.0, 1.0, 1.0]
        gaussian.color = [0.0, 0.0, 0.0] # Or SH coefficients initialized to 0
        
        gaussians.append(gaussian)
    
    # Step 4: Warm-up Phase
    for iteration in range(warmup_iters):
        # Step 5: Background Perturbation (if applicable to scene type)
        # Randomize background signal to prevent Gaussians from ignoring surfaces
        if use_background_perturbation:
            background_signal = random.uniform(-1, 1)
        else:
            background_signal = 0.0
            
        # Render current Gaussians
        rendered_images = []
        for camera in cameras:
            rendered = render_gaussians(gaussians, camera, background_signal)
            rendered_images.append(rendered)
            
        # Compute Loss (e.g., L2, SSIM)
        loss = compute_loss(rendered_images, ground_truth_images)
        
        # Backpropagate and update Gaussian parameters
        # Note: During warm-up, positions are optimized, but densification is disabled
        update_gaussians(gaussians, loss)
        
    return gaussians
```

## Subtopics

### [Dense Initialization (DI)](10026-dense-initialization-di.md)
Dense Initialization (DI) generates millions of small Gaussians to densely cover all visible surfaces at the outset, rather than starting with a sparse set and progressively refining it. It solves the problem of slow convergence and the computational overhead of iterative densification stages used in standard 3D Gaussian Splatting. DI sets itself apart from its sibling, Recurrent Gaussian Update, by eliminating the need for densification entirely through high-density matching, which also benefits ray tracing performance by reducing the workload of irrelevant primitives.

### [Recurrent Gaussian Update](10974-recurrent-gaussian-update.md)
Recurrent Gaussian Update is a gradient-free, feed-forward refinement method that iteratively corrects initial 3D Gaussian predictions by predicting incremental updates to Gaussian parameters and hidden states based on rendering errors from input views. It solves the problem of inaccurate initial reconstructions in single-step feed-forward models by establishing a feedback loop that progressively refines the Gaussian set without requiring backpropagation or gradient computation. Unlike standard differentiable optimization which relies on iterative gradient descent, this method uses a learned recurrent network to map rendering errors directly to parameter updates, enabling convergence in a fixed number of iterations (typically 4) rather than thousands.

### [Structure-Aware Initialization](13704-structure-aware-initialization.md)
Structure-Aware Initialization is a strategy that adapts primitive placement and scale to local image complexity using local variance. It solves the problem of inefficient coverage in radiance-field optimization by ensuring dense, fine-grained primitives in complex regions and sparse, coarse coverage in smooth areas. Unlike Dense Initialization, which distributes primitives uniformly, this method accelerates convergence and improves final fidelity, particularly when using high primitive counts.

### [Cluster-level Weighting](17081-cluster-level-weighting.md)
Cluster-level Weighting is a method for adaptively determining the contribution of multi-scale Gaussians in a Pyramidal Gaussian hierarchy during rendering. It solves the problem of balancing detail and performance by assigning unique weight sets to spatial clusters of Gaussians rather than individual splats, thereby incorporating positional context without the computational cost of per-Gaussian weight networks. It differs from sibling methods like Dense Initialization or Structure-Aware Initialization by focusing on the *rendering-time* adaptive weighting of an existing hierarchical structure, rather than the *initialization* of the Gaussian parameters themselves.

### Low-Reflectivity Bias
This variant specifically addresses the initialization of reflectivity/opacity to prevent incorrect placement in low-reflectivity regions.
*   **Step:** Initialize Gaussian reflectivity to a low value (0.01 to 0.1) [S1].
*   **Pitfall:** High initial reflectivity (e.g., 0.5) causes Gaussians in low-reflectivity regions to be incorrectly placed far away due to inverse-square falloff, leading to multiple opacity peaks and interference from closer splats [S1].
*   **Comparison:** Combining occupancy and low-reflectivity biases is effective for both low and high reflectivity regions. Using only occupancy bias harms low-reflectivity regions [S1].

### APMGSRN Initialization
This variant applies to Adaptively Placed Multi-Grid Scene Representation Networks.
*   **Step:** Initialize transformation matrices to cover a near global domain with small random shears, rotations, and translations. Diagonals sampled from $N(1, 0.05)$. Remaining entries in the first three rows sampled from $N(0, 0.05)$ [S2].
*   **Step:** Initialize feature grids from $U(-0.0001, 0.0001)$, encouraging near-zero initial guesses with small randomness [S2].
*   **Step:** Initialize decoder network weights following Glorot and Bengio [S2].
*   **Pitfall:** Initialization ensures each entry in the transformation matrix is non-zero so it may contribute to the final output, guaranteeing gradients can be used to update each entry [S2].

### Fine-tuning/Recoloring with Initialization
This variant applies to compressed or voxelized Gaussian representations.
*   **Definition:** A constrained retraining process that fixes Gaussian means after voxelization and fine-tunes the remaining attributes (covariance $\Sigma$, SH coefficients $C$, opacity $\alpha$) to minimize training loss [S3].
*   **Step:** Initialize the DC colors $C_i^{(dc)}$, high-frequency SH coefficients $C_i^{(ac)}$, and opacities $\alpha_i$ of the voxelized Gaussian means by averaging the attributes within each voxel [S3].
*   **Step:** Initialize the covariance $\Sigma$ of the voxelized Gaussian mean by the largest volume Gaussian in the voxel [S3].
*   **Step:** Perform fine-tuning iterations to restore rendering fidelity. The proposed initialization requires approximately 8K iterations to approach ground-truth PSNR [S3].
*   **Pitfall:** Initializing attributes to zero takes more iterations and often results in sub-optimal rendering quality because Gaussian splitting and merging are disabled during retraining [S3].
*   **Number:** Fine-tuning without initialization requires 30K iterations and fails to recover ground-truth PSNR at higher rates, whereas the proposed initialization requires ~8K iterations [S3].

### Appearance-aware Rendering with Color Correction
This variant applies to Pyramidal Gaussian Splatting (PyGS) to handle lighting variations.
*   **Definition:** A mechanism to handle lighting variations across images by applying a per-cluster color correction $\Delta c_i$ based on camera appearance embedding and cluster embedding, before final alpha blending [S4, unofficial].
*   **Step:** Compute color correction $\Delta c_i$ for the $i$-th Gaussian (belonging to cluster $k_i$) viewed from camera $n$: $\Delta c_i = F_\phi (\text{Concat}(E_c[k_i], E_{app}[n]))$ [S4, unofficial].
*   **Step:** Render the image by sorting Gaussians by depth. For each pixel, blend the adjusted colors $(c_i + \Delta c_i)$ weighted by the cluster-level weight $w_{k_i,n}[l_i]$ and opacity $\alpha_i$, using the standard alpha blending equation [S4, unofficial].
*   **Formula:**
    $$ \hat{C} = \sum_{i=1}^{N} \frac{(c_i + \Delta c_i) \cdot w_{k_i,n}[l_i] \cdot \alpha_i}{\prod_{j=1}^{i-1} (1 - w_{k_j,n}[l_j] \cdot \alpha_j)} $$
    where $c_i$ is spherical harmonic color, $\Delta c_i$ is color correction, $w$ is cluster-level weight, $\alpha$ is opacity [S4, unofficial].
*   **Layout:** Appearance Embedding $E_{app}$: A learnable tensor of size $R^{N_{cam} \times D}$, where $N_{cam}$ is the total count of cameras. $E_{app}[n]$ is the embedding for the $n$-th camera [S4, unofficial].

## Operating characteristics
*   **Time Complexity:** The warm-up phase typically requires a fixed number of iterations (e.g., 2,000) [S1]. Fine-tuning with proper initialization can reduce required iterations from 30K to ~8K [S3].
*   **Memory Complexity:** Depends on the number of initialized Gaussians. Random initialization uses minimal memory initially, while Dense Initialization requires significant memory for millions of primitives [S1].
*   **Strengths:** Prevents early optimization failures, ensures correct placement in low-reflectivity regions, and accelerates convergence [S1, S3].
*   **Limitations:** Requires careful tuning of initial reflectivity/opacity values [S1]. Random initialization may lead to sub-optimal local minima if not combined with biasing strategies [S1].
*   **When to use:** When starting with a sparse set of Gaussians, especially in dynamic scenes or low-reflectivity environments [S1]. When compressing voxelized Gaussians [S3].

## Background
The concept of initializing Gaussians with low opacity/reflectivity and running a static warm-up phase originates from dynamic radiance field optimization, specifically in the context of Time of Flight (ToF) cameras [S1]. The specific initialization schemes for multi-grid representations (APMGSRN) were introduced to ensure gradient flow in large-scale data visualization [S2]. Fine-tuning initialization for voxelized Gaussians was proposed to improve compression efficiency [S3]. Appearance-aware color correction was introduced in Pyramidal Gaussian Splatting (PyGS) to handle lighting variations [S4, unofficial].
