# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, GSGEN Implementation Details, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific hyperparameters, data structures, and optimization schedules required to implement the 3D Gaussian Splatting (3DGS) training pipeline. It addresses the problem of configuring the differentiable rasterizer and densification logic to balance rendering fidelity with computational efficiency. It sets itself apart from sibling methods by providing concrete numerical thresholds, iteration intervals, and precision settings (e.g., FP16 rasterization) rather than high-level architectural descriptions.

## How it works
The implementation relies on a differentiable rasterization core that computes pixel colors via depth-sorted alpha blending and computes gradients with respect to Gaussian parameters [6233-optimization-and-parallelization]. The following details specify the training loop, densification schedule, and hardware-specific optimizations.

### Inputs and Outputs
*   **Inputs**: A set of input images with known camera poses, an initial point cloud (typically from Structure-from-Motion, SfM), and hyperparameters for optimization.
*   **Outputs**: A set of 3D Gaussians defined by position $\mathbf{p}$, covariance $\Sigma$ (or scale $\mathbf{s}$ and rotation $\mathbf{q}$), opacity $\alpha$, and spherical harmonic coefficients $\mathbf{c}_{lm}$ for each view direction.

### Data Structures
The Gaussian representation is stored in a flat array or structure-of-arrays (SoA) format on the GPU to facilitate parallel access during rasterization.
*   **Position**: 3 floats ($x, y, z$).
*   **Scale**: 3 floats (log-scale representation is often used for stability).
*   **Rotation**: 4 floats (unit quaternion).
*   **Opacity**: 1 float.
*   **Color**: $N_{SH} \times 3$ floats, where $N_{SH}$ is the number of spherical harmonic coefficients. For SH degree 1, this is 12 floats.
*   **Gradients**: Accumulated gradients for position, scale, rotation, opacity, and color, updated via Adam optimizer.

### Optimization Schedule and Parameters
The training process involves iterative optimization with periodic densification (splitting/cloning) and pruning.

1.  **Optimizer**: Adam optimizer is used with a learning rate of $1 \times 10^{-3}$ [S3].
2.  **Spherical Harmonics (SH)**: Degree 1 is commonly used for simplicity and performance [S3].
3.  **Densification (Splitting/Cloning)**:
    *   Gaussians are split based on the view-space position gradient every 500 iterations [S1].
    *   The threshold for splitting is $T_{pos} = 0.02$ [S1, S4].
    *   Compactness-based densification is performed every 1000 iterations [S1].
4.  **Pruning**:
    *   Gaussians with opacity $\alpha < \alpha_{min} = 0.05$ are removed every 200 iterations [S1].
    *   Gaussians with excessively large world-space or view-space radius are also removed every 200 iterations [S1].
5.  **Loss Scaling**: An automatic scaling factor is applied to loss values to improve stability during half-precision (FP16) training [S2].

### Scene Extent Calculation
The default 3DGS implementation calculates scene extent $e_{\text{scene}}$ based on camera positions, which can be biased if cameras are clustered (e.g., orbiting a small object in a large environment) [S4].

$$e_{\text{scene}} = 1.1 \cdot \max_{i=1}^{N_{\text{cam}}} \|\bar{C} - C_i\|_2 \quad (9)$$

$$\bar{C} = \frac{1}{N_{\text{cam}}} \sum_{i=1}^{N_{\text{cam}}} C_i \quad (10)$$

To correct this bias, a corrected scene extent $e'_{\text{scene}}$ can be calculated using the SfM point cloud:

$$e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2 \quad (11)$$

where $N_{\text{SfM}}$ is the number of SfM points, $\bar{C}$ is the average camera position, and $p_i$ is the $i$-th SfM point [S4].

### Half-Precision Rasterization
To reduce register pressure and memory bandwidth, half-precision (FP16) arithmetic is used for feature vectors during rasterization [S2].
*   **Forward/Backward Kernels**: Memory fetches for feature vectors are performed in half-precision [S2].
*   **MLP Evaluation**: Neural networks (e.g., for view-dependent appearance) are trained and evaluated in FP16 using JIT-compiled cooperative vector MLPs (e.g., via tiny-cuda-nn) [S2].

### Pseudocode: Training Loop with Densification

```python
# Initialization
gaussians = initialize_from_sfm(point_cloud)
optimizer = Adam(gaussians.parameters(), lr=1e-3)
iteration = 0
max_iterations = 30000 # Example value

while iteration < max_iterations:
    # 1. Randomly select a training image
    image, camera_pose = random_sample_training_data()
    
    # 2. Forward Pass: Rasterize Gaussians
    # Uses half-precision for feature vectors to reduce register pressure [S2]
    rendered_image = rasterize(gaussians, camera_pose, precision='fp16')
    
    # 3. Compute Loss
    # Apply automatic scaling factor for FP16 stability [S2]
    loss = compute_loss(rendered_image, image)
    
    # 4. Backward Pass
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
    
    # 5. Densification and Pruning Schedule
    if iteration % 500 == 0:
        # Split Gaussians based on view-space position gradient
        # Threshold T_pos = 0.02 [S1]
        split_gaussians(gaussians, threshold=0.02)
        
    if iteration % 1000 == 0:
        # Compactness-based densification [S1]
        compactness_densify(gaussians)
        
    if iteration % 200 == 0:
        # Prune Gaussians with low opacity or excessive size [S1]
        prune_gaussians(gaussians, alpha_min=0.05)
        
    iteration += 1
```

### Corrected Scene-Extent
A method to calculate scene extent based on the SfM point cloud rather than camera positions to avoid bias from camera distribution (e.g., orbiting a small object in a large environment) [S4]. The default extent $e_{\text{scene}}$ is proportional to the distance of the furthest camera from the average camera position, causing bias if cameras are clustered [S4]. The corrected extent is $e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2$, where $N_{\text{SfM}}$ is the number of SfM points, $\bar{C}$ is the averaged camera position, and $p_i$ is the $i$-th SfM point [S4].

### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ to selectively enlarge covariances, creating pixel-wise variable blur kernels that match spatially varying scene blurriness [S5]. A compact MLP predicts $\delta s_j$ for each Gaussian $j$, which is added to the base scale to transform the covariance. The transformed covariance is projected to 2D space and used as a pixel-wise blur kernel during rasterization [S5]. If $\delta s_j$ is predicted as a constant, it degrades to a uniform Gaussian blur [S5]. Unlike naive Gaussian blur which applies a single kernel to the whole image, this method enables spatially varying blur shapes and magnitudes [S5].

### Denoise-GS
A self-supervised denoising method for sparse-view 3D Gaussian Splatting that combines unsupervised image denoising with explicitly differentiable 3DGS [S6]. Round 1: Train a UNet using Noise2Void (N2V) for denoising, process denoised images through InstantSplat to initialize/train/render 3DGS, and group/filter rendered results by viewpoint [S6]. Round 2: Fine-tune the UNet using a composite loss balancing low-frequency and perceptual detail consistency, then render again on selected viewpoints [S6]. Unlike supervised methods, it uses unsupervised N2V, which requires no paired clean data and is robust to uncertain noise patterns in sparse viewpoint scenarios [S6].

### Multi-Scale Constraint
A technique using position-aware point adaptive control to apply different scales to Gaussians based on viewer distance, improving rendering of distant objects [S7]. The scale factor is $\gamma(\mu) = 1$ if $\|\mu - c\|^2 < 2r$, and $\gamma(\mu) = \|\mu - c\|^2 / r - 1$ if $\|\mu - c\|^2 \ge 2r$, where $r$ is the scene radius and $c$ is the center of cameras [S7]. If $\max(s) < g \cdot \gamma(\mu)$, cloning is performed; if $\max(s) \ge g \cdot \gamma(\mu)$, splitting is executed; if $\max(s) > b \cdot \gamma(\mu)$, the Gaussian is eliminated, where $g$ and $b$ are scale threshold parameters [S7].

### LS-Gaussian Viewpoint Transformation
An algorithm that leverages inter-frame continuity for efficient sparse rendering by transforming the viewpoint between consecutive frames, rather than rendering each frame separately [S8]. Unlike naive pixel warping which fails to reduce preprocessing and sorting costs because projected Gaussians are assigned to workloads at the tile level, this method operates at the tile/Gaussian level to enable sparse rendering [S8]. Rendering quality degrades noticeably as the number of consecutively transformed frames increases due to the accumulation of interpolation errors [S8]. It is used in LS-Gaussian to enable sparse rendering where only one frame in every 6 frames is fully rendered, as demonstrated on Jetson AGX Orin [S8].

### Camera Localisation for Convergence Basin
Localizes camera pose by minimizing only the photometric error against the ground-truth colour image of the target view, fixing $G_{init}$ during optimization [S9, unofficial]. Initialize $T_{CW}$ at one of the test view's positions and perform optimization for 1000 iterations [S9, unofficial]. Localisation is successful if the estimated pose converges to within 1cm of the target view within the 1000 iterations [S9, unofficial]. The estimated pose $T_{CW}^{est}$ is found by $\mathbf{T}_{CW}^{est} = \underset{\mathbf{T}_{CW}}{\arg \min} \left\| I(\mathcal{G}_{init}, \mathbf{T}_{CW}) - \bar{I}_{target} \right\|_1$ [S9, unofficial].

### DiffGS Framework
Applies an optimization process during Gaussian extraction to optimize Gaussians to exact locations [S10]. A truncation function $\lambda$ is introduced when modeling GauPF (Gaussian Probability Function), and a projection function $\tau$ is implemented either as $\tau(x) = e^{-x}$ (Exponent) or as a linear projection [S10]. With 50K Gaussians, it achieves PSNR 28.61, SSIM 0.9787, LPIPS 0.0251; with 100K Gaussians, PSNR 30.35, SSIM 0.9838, LPIPS 0.0151; with 350K Gaussians, PSNR 34.01, SSIM 0.9879, LPIPS 0.0149 [S10].

### Opacity Offset Table for DSA
A method that constructs an opacity offset table to model changes in digital subtraction angiography [S11].

### Conditional Splat Approximation
A technique to approximate the influence range of a 3D Gaussian on a slice by using a 2D ellipse splat scaled by the marginal factor, which closely matches the true iso-probability contours [S12, unofficial]. Qualitative validation shows that the conditional splat approximation (dashed red contours) closely overlaps with the true 3D Gaussian iso-probability contours (solid blue contours) [S12, unofficial]. The conditional splat provides an accurate and efficient approximation of the original 3D Gaussian’s influence range [S12, unofficial].

### 3DGS Uncertainty Calculation via Fisher Information
Computes an uncertainty attribute for 3D Gaussians based on the negative log-likelihood of the rendered pixel value, interpreted as Fisher information [S13]. The uncertainty value $\bar{C}_{V;G}$ is computed as $\bar{C}_{V;G} = -\log p_f(\pi|V; G)$, where $p_f$ is the probability density function of the rendered pixel $\pi$ given view $V$ and Gaussian parameters $G$ [S13]. The derivation assumes volume rendering of 3D Gaussians meets regularity conditions: partial derivative exists almost everywhere, integral differentiability, and support independence from $G$ [S13].

## Operating characteristics
*   **Time Complexity**: The rasterization step is $O(N \cdot M)$ where $N$ is the number of Gaussians and $M$ is the number of pixels, but optimized via tile-based processing and early sorting. Densification adds overhead proportional to the number of Gaussians being split/cloned.
*   **Memory Complexity**: $O(N \cdot D)$ where $D$ is the dimensionality of Gaussian attributes (position, scale, rotation, opacity, SH coefficients). High-resolution scenes with millions of Gaussians can exceed 1GB of memory [12927-compact-3d-gaussian-representation-c3dgs.md].
*   **Performance**: Half-precision rasterization reduces register pressure and improves throughput [S2]. The method achieves real-time rendering speeds on modern GPUs.
*   **Strengths**: High-quality novel view synthesis, real-time rendering, explicit representation allows for easy editing and compression.
*   **Limitations**: High memory consumption for large scenes, sensitivity to initialization and densification parameters, potential for artifacts in textureless regions or with sparse inputs.
*   **When to use**: Real-time novel view synthesis, high-fidelity 3D reconstruction from multi-view images.
*   **When not to use**: Resource-constrained environments without GPU acceleration, scenes requiring explicit surface geometry without post-processing.

## Background
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 as a real-time explicit 3D representation [S1, S2, S3]. It builds on the concept of Gaussian splatting for volume rendering, adapting it for differentiable optimization. The method has since been extended with various optimizations for densification, compression, and hardware acceleration [S4, S5, S6, S7, S8][S9, unofficial][S10, S11][S12, unofficial][S13].
