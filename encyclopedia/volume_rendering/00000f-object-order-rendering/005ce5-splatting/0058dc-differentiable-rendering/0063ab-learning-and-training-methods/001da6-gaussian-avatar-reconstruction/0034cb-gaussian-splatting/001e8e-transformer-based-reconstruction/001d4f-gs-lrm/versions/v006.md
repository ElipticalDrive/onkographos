# GS-LRM


## Overview
GS-LRM is a feed-forward transformer-based method that predicts 3D Gaussian Splatting (3DGS) parameters directly from a small set of input images [S1, unofficial]. It tokenizes two to four images and their camera parameters, concatenates them, and passes them through a transformer block whose output tokens are decoded into Gaussian parameters [S1, unofficial]. It distinguishes itself from sibling methods like [Large Reconstruction Model (LRM)](5959-large-reconstruction-model-lrm.md) by specifically targeting Gaussian parameter prediction rather than mesh or NeRF fields [S1, unofficial].

## How it works
**Inputs:** A set of two to four input images and their corresponding camera parameters (intrinsics and extrinsics) [S1, unofficial].
**Outputs:** A set of 3D Gaussian parameters: mean position $\mu$, covariance $\Sigma$ (or rotation $R$ and scale $S$), color $c$, and opacity $\alpha$ [S1, unofficial].

**Data Structures:**
1. **Image Tokens:** Each input image is encoded into a sequence of feature tokens using a vision backbone (e.g., ViT) [S1, unofficial].
2. **Camera Tokens:** Camera parameters are encoded into token embeddings [S1, unofficial].
3. **Concatenated Sequence:** Image tokens and camera tokens are concatenated into a single sequence [S1, unofficial].

**Steps:**
1. **Tokenization:** Encode the two to four input images into image feature tokens [S1, unofficial]. Encode the corresponding camera parameters into camera tokens [S1, unofficial].
2. **Concatenation:** Concatenate the image tokens and camera tokens into a single sequence [S1, unofficial].
3. **Transformer Processing:** Pass the concatenated sequence through a transformer block (encoder/decoder) to model spatial and geometric relationships [S1, unofficial].
4. **Decoding:** Decode the output tokens from the transformer into the final set of 3D Gaussian parameters ($\mu, \Sigma, c, \alpha$) [S1, unofficial].

**Training Objective:** The network is trained end-to-end using photometric losses (e.g., LPIPS, SSIM) between the rendered output and ground truth images [S1, unofficial].

**Edge Cases:**
*   **Camera Pose Accuracy:** The method requires known camera poses [S1, unofficial].

## Subtopics

### Large 4D Gaussian Model (L4GM)
L4GM is a feed-forward 4D large reconstruction model that outputs per-frame 3DGS from a single-view video in one ~1s forward pass [S2, unofficial]. It upsamples to higher fps for temporal smoothness via temporal self-attention [S2, unofficial]. It is built on LGM and trained on a new Objaverse-derived multiview-video dataset containing 44K objects, 12M videos, and 300M frames [S2, unofficial]. It is marked as a 2026 SOTA update [S2, unofficial]. It sets itself apart by handling temporal consistency directly in a feed-forward pass rather than requiring multi-view rigs [S2, unofficial]. Choose it when reconstructing dynamic scenes from single-view video [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Feed-forward inference [S1, unofficial].
*   **Measured Performance:** L4GM is noted as a 2026 SOTA update for 4D reconstruction [S2, unofficial].
*   **Strengths:** Fast feed-forward generation of 3DGS from sparse views [S1, unofficial].
*   **Limitations:** Requires known camera poses [S1, unofficial].
*   **When to use:** Sparse-view reconstruction with known camera poses [S1, unofficial].

## Background
GS-LRM was introduced as part of the evolution of feed-forward 3D reconstruction models, building upon earlier methods like PixelSplat and MVSplat [S1, unofficial]. It is cited in a tutorial on Gaussian Splatting variants [S1, unofficial]. L4GM, a variant, is marked as a 2026 SOTA update [S2, unofficial].
