# Adaptive Bounding Box Computation

Also called: Tsplat bounding box

## Overview
Computes a tight, axis-aligned bounding box (AABB) for a 2D Gaussian splat based on a specific opacity threshold, replacing the loose circular bounding box used in original 3D Gaussian Splatting (3DGS) [S1, unofficial][S2]. This method significantly reduces false-positive tile intersections and the resulting number of duplicated splat fragments during rasterization [S1, unofficial][S2]. It serves as the core geometric culling step in differentiable rendering pipelines that utilize Gaussian Avatar Reconstruction, enabling efficient depth-sorted rasterization by emitting sorted keys only for relevant tiles [S1, unofficial].

## How it works
**Inputs:**
- `sx`, `sy`: Screen-space center coordinates of the 2D Gaussian splat (float).
- `cov2d_00`, `cov2d_11`: Diagonal elements of the projected 2D covariance matrix $\Sigma$ (float). Note: This method assumes the covariance is diagonal or that these are the effective variances along the screen axes after rotation handling in the parent step.
- `opacity`: The scalar opacity of the splat (float).
- `alpha_threshold`: The minimum opacity threshold $\tau$ for a pixel to be considered visible (float).
- `max_k2`: The maximum allowed squared Mahalanobis distance to prevent overflow or excessive box sizes (float).
- `w_i`, `h_i`: Framebuffer width and height in pixels (uint).

**Outputs:**
- A bounding box defined by integer coordinates $(x_0, y_0, x_1, y_1)$, or `None` if the splat is effectively invisible or has negligible size.

**Data Structures:**
- No complex data structures. The output is typically a tuple or struct containing the four integer coordinates.

**Steps:**
1. **Opacity Check:** If `opacity` $\le$ `alpha_threshold`, return `None`. The splat cannot contribute any pixel above the threshold.
2. **Compute Squared Mahalanobis Distance Limit ($k^2$):**
   Calculate the squared distance in the normalized space corresponding to the opacity threshold:
   $$ k^2 = \min\left(2.0 \cdot \ln\left(\frac{\text{opacity}}{\text{alpha\_threshold}}\right), \text{max\_k2}\right) $$
   If $k^2 \le 0.0$, return `None`. This occurs if the opacity is too low relative to the threshold.
3. **Compute Half-Widths:**
   Calculate the half-extents of the bounding box along the x and y axes:
   $$ rx_f = \sqrt{k^2 \cdot \text{cov2d}_{00}} $$
   $$ ry_f = \sqrt{k^2 \cdot \text{cov2d}_{11}} $$
   If $rx_f$ or $ry_f$ is not finite or is less than $1.0$, return `None`. This ensures the bounding box covers at least one pixel and avoids numerical instability.
4. **Compute Integer Bounding Box:**
   Determine the pixel coordinates of the bounding box corners:
   $$ x_0 = \lfloor sx - rx_f \rfloor $$
   $$ y_0 = \lfloor sy - ry_f \rfloor $$
   $$ x_1 = \lceil sx + rx_f \rceil $$
   $$ y_1 = \lceil sy + ry_f \rceil $$
5. **Clip to Framebuffer:**
   Clamp the coordinates to the valid framebuffer range:
   $$ x_0 = \max(0, x_0) $$
   $$ y_0 = \max(0, y_0) $$
   $$ x_1 = \min(w_i - 1, x_1) $$
   $$ y_1 = \min(h_i - 1, y_1) $$
6. **Validity Check:**
   If $x_0 > x_1$ or $y_0 > y_1$, return `None`. The bounding box is empty or invalid.
7. **Return:**
   Return the tuple $(x_0, y_0, x_1, y_1)$.

**Pseudocode:**
```python
def compute_adaptive_bounding_box(sx, sy, cov2d_00, cov2d_11, opacity, alpha_threshold, max_k2, w_i, h_i):
    # Step 1: Opacity Check
    if opacity <= alpha_threshold:
        return None

    # Step 2: Compute k^2
    # Note: ln is natural logarithm
    ratio = opacity / alpha_threshold
    if ratio <= 1.0:
        return None
    
    k2 = 2.0 * math.log(ratio)
    if k2 > max_k2:
        k2 = max_k2
    
    if k2 <= 0.0:
        return None

    # Step 3: Compute half-widths
    rx_f = math.sqrt(k2 * cov2d_00)
    ry_f = math.sqrt(k2 * cov2d_11)

    # Check for finite and minimum size
    if not math.isfinite(rx_f) or rx_f < 1.0:
        return None
    if not math.isfinite(ry_f) or ry_f < 1.0:
        return None

    # Step 4: Compute integer bounding box
    x0 = math.floor(sx - rx_f)
    y0 = math.floor(sy - ry_f)
    x1 = math.ceil(sx + rx_f)
    y1 = math.ceil(sy + ry_f)

    # Step 5: Clip to framebuffer
    x0 = max(0, x0)
    y0 = max(0, y0)
    x1 = min(w_i - 1, x1)
    y1 = min(h_i - 1, y1)

    # Step 6: Validity Check
    if x0 > x1 or y0 > y1:
        return None

    # Step 7: Return
    return (x0, y0, x1, y1)
```

**Parameters:**
- `max_k2`: Not given in the sources. A typical value might be derived from the maximum reasonable spread of a Gaussian splat, but no specific value is provided.
- `alpha_threshold`: Not given in the sources. Typically a small value like $1/255$ or similar, depending on the rendering pipeline's opacity cutoff.

**Edge Cases and Pitfalls:**
- **Precision:** The calculation of $k^2$ involves logarithms and square roots. Ensure floating-point precision is sufficient to avoid negative values under the square root due to numerical noise, although the check $k^2 \le 0.0$ handles this.
- **Boundaries:** The clipping step ensures the bounding box stays within the framebuffer. If the splat is entirely outside the framebuffer, the clipping will result in an invalid box ($x_0 > x_1$), which is correctly handled.
- **Degenerate Input:** If `cov2d_00` or `cov2d_11` is zero or negative (which should not happen if the covariance is positive definite, as ensured by the parent method), the half-widths will be zero or NaN. The check for $< 1.0$ and `isfinite` handles this.

## Subtopics

### [Opacity-Sensitive Elliptical Bounding Box](2100-opacity-sensitive-elliptical-bounding-box.md)
The Opacity-Sensitive Elliptical Bounding Box is a method for determining which image tiles a 2D Gaussian splat intersects by computing a tight, non-square axis-aligned bounding box (AABB) around the ellipse defined by the splat's covariance at a specific opacity threshold. Unlike the original 3D Gaussian Splatting (3DGS) approach, which uses a circular bounding box or a loose AABB around the ellipse's bounding circle, this method significantly reduces false-positive tile intersections and the resulting number of duplicated splat fragments. It serves as the core geometric culling step in differentiable rendering pipelines that utilize Gaussian Avatar Reconstruction, enabling efficient depth-sorted rasterization by emitting sorted keys only for relevant tiles.

### [Tight Ellipse AABB Derivation](2826-tight-ellipse-aabb-derivation.md)
This method computes the tight axis-aligned bounding box (AABB) of a projected 2D Gaussian ellipse in constant time. It replaces the loose circular bounding box used in original 3D Gaussian Splatting to determine tile intersections, significantly reducing false-positive splat duplications during rasterization.

### [Opacity-aware Non-Square Bounding Box](6079-opacity-aware-non-square-bounding-box.md)
This method computes a tight, axis-aligned rectangular bounding box for a 2D Gaussian splat based on its projected opacity and covariance, replacing the original 3D Gaussian Splatting (3DGS) approach which uses a square bounding box derived from a fixed confidence radius. It reduces false positives in per-tile splat lists by accounting for the Gaussian's actual opacity and the non-square nature of its projected shape.

### Non-Square Bounding Boxes
Allowing the axis-aligned bounding box of a projected 2D Gaussian to have different width and height dimensions, rather than forcing a square shape [S2]. On the Bicycle scene at native resolution with 16x16 tiles, non-square boxes reduced duplicated Gaussians from 55,648,264 (square) to 18,466,556 [S2].

## Operating characteristics
**Time Complexity:** $O(1)$ per splat. The computation involves a constant number of arithmetic operations, logarithms, and square roots.
**Memory Complexity:** $O(1)$ per splat. No additional memory is allocated for the bounding box computation itself.
**Measured Performance:** On the Bicycle scene at native resolution, the combination of opacity-aware bounding boxes and other improvements decreased render time by a factor of 3.77 and GPU memory usage by a factor of 2.11 [S2]. The reduction in duplicated Gaussians from 55,648,264 (square) to 18,466,556 (non-square) on the same scene highlights the efficiency gain in rasterization [S2].
**Strengths:** Significantly reduces false-positive tile intersections, leading to fewer splat duplications and lower memory bandwidth usage during rasterization. It is computationally inexpensive.
**Limitations:** Requires the covariance matrix to be diagonal or pre-rotated to the screen space axes. If the covariance is not diagonal, the computed box may be loose or incorrect.
**When to use:** Use when efficient culling of Gaussian splats is required, especially in scenes with high splat density or varying opacity. It is particularly effective when combined with opacity thresholds.
**When not to use:** Do not use if the covariance matrix is not available or if the splat's shape is not well-approximated by an ellipse in screen space.

## Background
The method originates from the Tsplat project, an unofficial implementation of Gaussian Splatting [S1, unofficial]. It was developed to address the inefficiencies of the original 3D Gaussian Splatting paper's circular bounding box approach [S1, unofficial][S2]. The approach is also discussed in the context of fast 3D Gaussian Splatting rendering improvements [S2]. The original 3D Gaussian Splatting paper by Kerbl et al. is acknowledged as the foundation [S1, unofficial].
