# ASCII-Based Data Compression
Also called: Anywhere Compression, Base 94 Floating-Point Compression, Base 95 Integer Compression

## Overview
ASCII-Based Data Compression is a method for optimizing data transmission speed during the training of 3D Gaussian Splatting models by encoding numerical attributes into compact ASCII strings [S1, unofficial]. It improves training throughput by reducing the volume of data transferred between processes, achieving approximately 6% or less improvement in training speed [S1, unofficial]. It differs from sibling methods like [Sensitivity-Aware Vector Clustering](12167-sensitivity-aware-vector-clustering.md) by focusing on transmission efficiency via character encoding rather than reducing the number of primitives or quantizing attribute vectors into codebooks.

## How it works
**Inputs and Outputs:**
*   **Input:** Continuous numerical values (integers or floating-point numbers) representing Gaussian attributes (e.g., color matrix entries).
*   **Output:** A string of ASCII characters representing the compressed value, and the decoded numerical value for rendering/computation.

**Data Structures:**
*   **Integer Representation:** A single ASCII character mapping to an integer in the range $[0, 95]$.
*   **Floating-Point Representation:** A string composed of an integer part, a separator, and a decimal part.
*   **Color Matrix Optimization:** Each entry in the output color matrix is restricted to one decimal place within the range $[0.0, 2.0]$.

**Encoding Steps:**
1.  **Integer Compression (Base 95):**
    *   Map an integer $n$ where $0 \le n \le 95$ to a single ASCII character.
    *   The character set used is ASCII codes 32 to 126 inclusive.
    *   Formula: $char = \text{chr}(n + 32)$ [S1, unofficial].
2.  **Floating-Point Compression (Base 94):**
    *   Decompose the floating-point number into an integer component $I$ and a decimal place count $d$.
    *   The integer component $I$ must be in the range $[0, 94]$.
    *   Map $I$ to an ASCII character using codes 32 to 125 inclusive.
    *   Formula: $char\_int = \text{chr}(I + 32)$ [S1, unofficial].
    *   Use the ASCII character 126 (`~`) as a separator between the integer part and the decimal part.
    *   The resulting string is $char\_int + \text{chr}(126) + \text{str}(d)$, where $d$ represents the decimal places. Note: The source describes $d$ as "decimal places," implying the magnitude of the fractional part or the number of digits, but the decoding formula clarifies the reconstruction [S1, unofficial].
3.  **Color Matrix Optimization:**
    *   Quantize each color matrix item to one decimal place.
    *   Restrict values to the range $[0.0, 2.0]$.
    *   This results in 21 discrete alternative numbers ($0.0, 0.1, \dots, 2.0$).
    *   Apply ASCII compression to these quantized values to reduce data size significantly [S1, unofficial].

**Decoding Steps:**
1.  **Decoding Integer:**
    *   Convert the single ASCII character directly back to the decimal integer.
    *   Formula: $n = \text{ord}(char) - 32$ [S1, unofficial].
2.  **Decoding Floating-Point:**
    *   Split the ASCII string at the separator character (ASCII 126).
    *   Let the first part be the ASCII string for the integer part $I_{str}$ and the second part be the ASCII string for the decimal places $d_{str}$.
    *   Decode $I$ from $I_{str}$: $I = \text{ord}(I_{str}) - 32$.
    *   The final floating-point value $f$ is calculated as:
        $$ f = I \times 10^{-d} $$
        where $d$ is the integer value derived from $d_{str}$ [S1, unofficial].

**Parameters:**
*   **Integer Base:** 95.
*   **Floating-Point Integer Base:** 94.
*   **Color Precision:** 1 decimal place.
*   **Color Range:** $[0.0, 2.0]$.

**Edge Cases and Pitfalls:**
*   **Matrix Traversal Speed:** Compressing large color matrices into ASCII strings is difficult because traversing a large matrix takes significant processing time. Using internal functions like `torch::where` and `torch::index_select` helps but is not fast enough for full replacement [S1, unofficial].
*   **Line Break Characters:** Using line break characters in ASCII strings adds an extra operator in writing and decoding, which should be avoided [S1, unofficial].
*   **Performance Limit:** The method gains about 6% or less improvement in training speed [S1, unofficial].

**Pseudocode:**

```python
def encode_integer(n):
    """
    Encode an integer in range [0, 95] to a single ASCII character.
    """
    if not (0 <= n <= 95):
        raise ValueError("Integer out of range [0, 95]")
    return chr(n + 32)

def decode_integer(char):
    """
    Decode a single ASCII character back to an integer.
    """
    return ord(char) - 32

def encode_float(f_val):
    """
    Encode a floating-point number.
    Assumes f_val is non-negative and can be represented as I * 10^-d.
    I is in [0, 94].
    """
    # Determine decimal places d and integer part I
    # Note: The source implies a specific decomposition. 
    # For a value like 12.34, if I=12, d=2, then 12 * 10^-2 = 0.12 != 12.34.
    # The source formula is f = I * 10^-d. 
    # This implies I is the significant digits and d is the scale.
    # Example: 12.34 -> I=1234, d=2? No, I must be <= 94.
    # The source likely implies a specific normalization or that I is the integer part 
    # and d is the number of decimal digits, but the formula f = I * 10^-d 
    # suggests I is the mantissa. 
    # Given the constraint I <= 94, this method is likely for small numbers 
    # or a specific subset of attributes.
    # We implement the decoding logic in reverse as described.
    
    # To encode, we need to find I and d such that f_val = I * 10^-d
    # and 0 <= I <= 94.
    # This is only possible if f_val is small or d is negative (not supported by ASCII digits).
    # Assuming the source implies I is the integer part of the number 
    # and d is the number of decimal places, but the formula is explicit.
    # We will follow the source's decoding formula strictly.
    
    # Heuristic for encoding based on source description:
    # Split float into integer part and decimal string.
    # However, the source says "integer component of the floating-point number".
    # Let's assume I is the integer part of the float, and d is the number of decimal digits.
    # But f = I * 10^-d would be wrong for 12.34 (12 * 10^-2 = 0.12).
    # The source might mean f = I + d * 10^-k? No, it says f = I * 10^-d.
    # This suggests I is the significant digits.
    # Given the ambiguity and the constraint I <= 94, this method is likely for 
    # normalized values or specific attributes.
    
    # Implementation based on strict source formula f = I * 10^-d:
    # We need to find I and d.
    # If f_val = 0.12, I=12, d=2. 12 * 10^-2 = 0.12. Correct.
    # If f_val = 1.2, I=12, d=1. 12 * 10^-1 = 1.2. Correct.
    # If f_val = 12, I=12, d=0. 12 * 10^0 = 12. Correct.
    # If f_val = 0.012, I=12, d=3. Correct.
    # So I is the integer formed by the significant digits, and d is the number of decimal places.
    
    # Extract significant digits
    # Convert to string to handle decimal places
    s = f"{f_val:.10f}".rstrip('0').rstrip('.')
    if '.' in s:
        int_part, dec_part = s.split('.')
        # Combine to get significant digits
        significant_str = int_part + dec_part
        d = len(dec_part)
    else:
        significant_str = s
        d = 0
        
    I = int(significant_str)
    
    if not (0 <= I <= 94):
        raise ValueError(f"Integer component I={I} out of range [0, 94]")
        
    char_int = encode_integer(I)
    separator = chr(126)
    char_d = str(d) # d is small, can be stored as string digit
    
    return char_int + separator + char_d

def decode_float(s):
    """
    Decode an ASCII string back to a floating-point number.
    """
    # Find separator
    sep_idx = s.find(chr(126))
    if sep_idx == -1:
        raise ValueError("Missing separator")
        
    char_int = s[:sep_idx]
    d_str = s[sep_idx+1:]
    
    I = decode_integer(char_int)
    d = int(d_str)
    
    f = I * (10 ** -d)
    return f

def optimize_color_matrix(color_matrix):
    """
    Quantize color matrix to 1 decimal place in range [0.0, 2.0].
    """
    # Clip to range
    clipped = torch.clamp(color_matrix, 0.0, 2.0)
    # Round to 1 decimal place
    quantized = torch.round(clipped * 10) / 10
    return quantized
```

## Operating characteristics
*   **Time Complexity:** Encoding/decoding is $O(1)$ per number, but matrix traversal for compression is $O(N)$ where $N$ is the number of elements. The source notes that matrix traversal is a bottleneck and internal PyTorch functions (`torch::where`, `torch::index_select`) are not fast enough for full replacement [S1, unofficial].
*   **Memory Complexity:** Reduces the size of transmitted data. The color matrix is reduced by quantizing to 21 discrete values and encoding them as ASCII [S1, unofficial].
*   **Measured Performance:** Gains about 6% or less improvement in training speed [S1, unofficial].
*   **Strengths:** Simple implementation; improves data transmission speed; reduces color matrix data size significantly.
*   **Limitations:** Limited speedup (6%); difficult to compress large color matrices efficiently due to traversal overhead; not suitable for full replacement of data transmission; line break characters add overhead.
*   **When to Use:** When data transmission is a bottleneck in training and attributes can be quantized to small integer ranges or simple decimal representations.
*   **When Not to Use:** When higher compression ratios are needed; when matrix traversal speed is critical and optimized kernels are not available; when precision loss from quantization is unacceptable.

## Background
The method was introduced in "I3DGS: Improve 3D Gaussian Splatting from Multiple Dimensions" by F. Author et al. in 2024 [S1, unofficial]. It is part of an effort to improve the training speed of 3D Gaussian Splatting models by exploring various dimensions including compression, learning, and structure design. The method is specifically designed to address the impact of data transmission on training speed.
