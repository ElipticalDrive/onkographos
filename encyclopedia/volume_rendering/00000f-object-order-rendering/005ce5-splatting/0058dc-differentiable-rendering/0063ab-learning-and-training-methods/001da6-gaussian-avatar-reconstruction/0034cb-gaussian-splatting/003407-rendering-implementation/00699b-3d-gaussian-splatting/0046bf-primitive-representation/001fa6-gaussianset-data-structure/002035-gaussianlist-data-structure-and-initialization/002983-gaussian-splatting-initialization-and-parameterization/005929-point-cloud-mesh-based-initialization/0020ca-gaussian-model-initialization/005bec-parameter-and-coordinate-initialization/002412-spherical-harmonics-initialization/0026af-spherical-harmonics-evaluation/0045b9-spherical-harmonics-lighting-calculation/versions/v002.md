# Spherical Harmonics Lighting Calculation

Also called: SH Evaluation with Lighting, SH Lighting

## Overview
This method computes the RGB color contribution of a 3D Gaussian splat by evaluating real spherical harmonics against a viewing direction vector [S1]. It represents view-dependent lighting effects compactly within the Gaussian representation [S1]. It differs from [Spherical Harmonics Evaluation](3848-spherical-harmonics-evaluation.md) by explicitly defining the lighting calculation pipeline, including the Condon–Shortley phase conventions, the mandatory 0.5 bias for numeric stability, and the exact polynomial expansions for degrees 0 through 3 [S1].

## How it works
**Inputs:**
- $SH_{l,m}$: The spherical harmonic coefficients for the Gaussian, stored as RGB vectors [S1]. For each degree $l$, there are $2l+1$ coefficients (orders $m = -l \dots l$), each containing values for the red, green, and blue channels [S1].
- $\mathbf{v} = (x, y, z)$: The normalized viewing direction vector [S1].

**Outputs:**
- $\mathbf{C}_{final}$: The resulting RGB color vector [S1].

**Data Structures:**
The coefficients are stored such that for degree $n$, the total number of RGB coefficients is $SH_n \times 3 = SH_{total}$, where $SH_n$ is the count of SH basis functions for that degree [S1]. This yields 3 coefficients for Degree 0, 9 for Degree 1, 15 for Degree 2, and 21 for Degree 3 [S1].

**Step-by-Step Calculation:**

1. **Normalize Direction:** Ensure the direction vector $\mathbf{v}$ is a unit vector [S1]. In 3D Gaussian Splatting, direction vectors are normalized, so $r = \sqrt{x^2 + y^2 + z^2} = 1$ when evaluating spherical harmonics [S1].
2. **Compute Degree 0 (Diffuse):** Calculate the zeroth-order contribution [S1].
   $$Color_{SH_0} = SH_{0,0} \cdot 0.2820947917738781$$
   Where $SH_{0,0}$ is the vector of 3 RGB coefficients for the zeroth-order real spherical harmonic [S1].
3. **Compute Degree 1 (First Order):**
   $$Color_{SH_1} = SH_{1,-1} \cdot y \cdot -0.4886025119029199 + SH_{1,0} \cdot z \cdot 0.4886025119029199 + SH_{1,1} \cdot x \cdot -0.4886025119029199$$
   Where $SH_{1,m}$ are the RGB coefficient vectors for orders $-1, 0, 1$ [S1].
4. **Compute Degree 2 (Second Order):**
   $$Color_{SH_2} = SH_{2,-2} \cdot xy \cdot 1.092548430592079 + SH_{2,-1} \cdot yz \cdot -1.092548430592079 + SH_{2,0} \cdot (2z^2 - x^2 - y^2) \cdot 0.3153915652525200 + SH_{2,1} \cdot xz \cdot -1.092548430592079 + SH_{2,2} \cdot (x^2 - y^2) \cdot 0.5462742152960395$$
5. **Compute Degree 3 (Third Order):**
   $$Color_{SH_3} = SH_{3,-3} \cdot y(3x^2 - y^2) \cdot -0.5900435899266435 + SH_{3,-2} \cdot xyz \cdot 2.890611442640554 + SH_{3,-1} \cdot y(4z^2 - x^2 - y^2) \cdot -0.4570457994644657 + SH_{3,0} \cdot z(2z^2 - 3x^2 - 3y^2) \cdot 0.3731763325901154 + SH_{3,1} \cdot x(4z^2 - x^2 - y^2) \cdot -0.4570457994644657 + SH_{3,2} \cdot z(x^2 - y^2) \cdot 1.445305721320277 + SH_{3,3} \cdot x(x^2 - 3y^2) \cdot -0.5900435899266435$$
6. **Sum and Bias:** Sum the contributions from all available degrees and apply the 0.5 bias [S1].
   $$Color_{final} = Color_{SH_0} + Color_{SH_1} + Color_{SH_2} + Color_{SH_3} + 0.5$$
   The 0.5 bias is applied to keep the spherical harmonics within the [0, 1] range during training and rendering, ensuring numeric stability and allowing coefficients to remain in a valid range for unsigned normalized color buffers [S1].

**Pseudocode:**
```python
def spherical_harmonics_lighting(sh_coeffs, direction_x, direction_y, direction_z):
    """
    Computes the RGB color of a Gaussian using Spherical Harmonics.
    
    Args:
        sh_coeffs: A dictionary mapping (l, m) tuples to lists of 3 floats [R, G, B].
        direction_x, direction_y, direction_z: Components of the normalized viewing direction vector.
        
    Returns:
        List of 3 floats representing the final RGB color.
    """
    # Constants from [S1]
    C0 = 0.2820947917738781
    C1 = 0.4886025119029199
    C2_2m2 = 1.092548430592079
    C2_2m1 = -1.092548430592079
    C2_20 = 0.3153915652525200
    C2_21 = -1.092548430592079
    C2_22 = 0.5462742152960395
    C3_3m3 = -0.5900435899266435
    C3_3m2 = 2.890611442640554
    C3_3m1 = -0.4570457994644657
    C3_30 = 0.3731763325901154
    C3_31 = -0.4570457994644657
    C3_32 = 1.445305721320277
    C3_33 = -0.5900435899266435
    
    color = [0.0, 0.0, 0.0]
    
    # Degree 0
    if (0, 0) in sh_coeffs:
        coeff = sh_coeffs[(0, 0)]
        color[0] += coeff[0] * C0
        color[1] += coeff[1] * C0
        color[2] += coeff[2] * C0
        
    # Degree 1
    if (1, -1) in sh_coeffs and (1, 0) in sh_coeffs and (1, 1) in sh_coeffs:
        c_m1 = sh_coeffs[(1, -1)]
        c_0 = sh_coeffs[(1, 0)]
        c_1 = sh_coeffs[(1, 1)]
        color[0] += c_m1[0] * direction_y * -C1 + c_0[0] * direction_z * C1 + c_1[0] * direction_x * -C1
        color[1] += c_m1[1] * direction_y * -C1 + c_0[1] * direction_z * C1 + c_1[1] * direction_x * -C1
        color[2] += c_m1[2] * direction_y * -C1 + c_0[2] * direction_z * C1 + c_1[2] * direction_x * -C1
        
    # Degree 2
    if all((2, m) in sh_coeffs for m in [-2, -1, 0, 1, 2]):
        xy = direction_x * direction_y
        yz = direction_y * direction_z
        xz = direction_x * direction_z
        term_20 = 2 * direction_z**2 - direction_x**2 - direction_y**2
        term_22 = direction_x**2 - direction_y**2
        
        c_m2 = sh_coeffs[(2, -2)]
        c_m1 = sh_coeffs[(2, -1)]
        c_0 = sh_coeffs[(2, 0)]
        c_1 = sh_coeffs[(2, 1)]
        c_2 = sh_coeffs[(2, 2)]
        
        color[0] += c_m2[0] * xy * C2_2m2 + c_m1[0] * yz * C2_2m1 + c_0[0] * term_20 * C2_20 + c_1[0] * xz * C2_21 + c_2[0] * term_22 * C2_22
        color[1] += c_m2[1] * xy * C2_2m2 + c_m1[1] * yz * C2_2m1 + c_0[1] * term_20 * C2_20 + c_1[1] * xz * C2_21 + c_2[1] * term_22 * C2_22
        color[2] += c_m2[2] * xy * C2_2m2 + c_m1[2] * yz * C2_2m1 + c_0[2] * term_20 * C2_20 + c_1[2] * xz * C2_21 + c_2[2] * term_22 * C2_22
        
    # Degree 3
    if all((3, m) in sh_coeffs for m in [-3, -2, -1, 0, 1, 2, 3]):
        term_3m3 = direction_y * (3 * direction_x**2 - direction_y**2)
        term_3m2 = direction_x * direction_y * direction_z
        term_3m1 = direction_y * (4 * direction_z**2 - direction_x**2 - direction_y**2)
        term_30 = direction_z * (2 * direction_z**2 - 3 * direction_x**2 - 3 * direction_y**2)
        term_31 = direction_x * (4 * direction_z**2 - direction_x**2 - direction_y**2)
        term_32 = direction_z * (direction_x**2 - direction_y**2)
        term_33 = direction_x * (direction_x**2 - 3 * direction_y**2)
        
        c_m3 = sh_coeffs[(3, -3)]
        c_m2 = sh_coeffs[(3, -2)]
        c_m1 = sh_coeffs[(3, -1)]
        c_0 = sh_coeffs[(3, 0)]
        c_1 = sh_coeffs[(3, 1)]
        c_2 = sh_coeffs[(3, 2)]
        c_3 = sh_coeffs[(3, 3)]
        
        color[0] += c_m3[0] * term_3m3 * C3_3m3 + c_m2[0] * term_3m2 * C3_3m2 + c_m1[0] * term_3m1 * C3_3m1 + c_0[0] * term_30 * C3_30 + c_1[0] * term_31 * C3_31 + c_2[0] * term_32 * C3_32 + c_3[0] * term_33 * C3_33
        color[1] += c_m3[1] * term_3m3 * C3_3m3 + c_m2[1] * term_3m2 * C3_3m2 + c_m1[1] * term_3m1 * C3_3m1 + c_0[1] * term_30 * C3_30 + c_1[1] * term_31 * C3_31 + c_2[1] * term_32 * C3_32 + c_3[1] * term_33 * C3_33
        color[2] += c_m3[2] * term_3m3 * C3_3m3 + c_m2[2] * term_3m2 * C3_3m2 + c_m1[2] * term_3m1 * C3_3m1 + c_0[2] * term_30 * C3_30 + c_1[2] * term_31 * C3_31 + c_2[2] * term_32 * C3_32 + c_3[2] * term_33 * C3_33
        
    # Apply bias
    color[0] += 0.5
    color[1] += 0.5
    color[2] += 0.5
    
    return color
```

**Parameters:**
- $r$: Magnitude of the direction vector. In 3D Gaussian Splatting, this is always 1 due to normalization [S1].
- $SH_{l,m}$: RGB coefficients for degree $l$ and order $m$ [S1].
- $x, y, z$: Components of the direction vector [S1].

**Pitfalls:**
- **Partial Definitions:** Higher order spherical harmonics are optional, but if used, lower order spherical harmonics MUST also be provided. Each order MUST be fully defined; partial definitions (e.g., providing $SH_{2,0}$ but not $SH_{2,-2}$) are not allowed [S1].
- **Clamping:** If using unsigned normalized color buffers, values less than 0 or greater than 1 are clamped automatically. The 0.5 bias helps keep values within [0, 1] [S1].
- **Condon–Shortley Phase:** Odd values for order ($m$) are negated. This is handled by the negative signs in the constants provided above [S1].

## Operating characteristics
- **Time Complexity:** Not given in the sources.
- **Memory Complexity:** Not given in the sources. Degree 0 requires 9 floats (3 RGB $\times$ 3 coefficients), Degree 1 adds 27, Degree 2 adds 45, Degree 3 adds 63, totaling 144 floats per Gaussian for full degree 3 [S1].
- **Strengths:** Compact representation of view-dependent effects. Causes less range clamping than passing color and alpha values separately [S1].
- **Limitations:** Limited angular resolution with low degrees. Higher degrees increase memory and compute cost.
- **When to use:** When view-dependent lighting (specular, anisotropy) is important and memory/compute budget allows for higher SH degrees.
- **When not to use:** When only diffuse lighting is needed (use Degree 0 only). When memory is extremely constrained.

## Background
This method is defined in the KHR_gaussian_splatting extension for glTF, which standardizes the storage and rendering of 3D Gaussian Splatting assets [S1]. It builds on the mathematical foundations of spherical harmonics used in computer graphics for lighting approximation. The specific constants and biasing strategy are tailored for the 3D Gaussian Splatting pipeline to ensure compatibility with standard graphics APIs and color buffers [S1].
