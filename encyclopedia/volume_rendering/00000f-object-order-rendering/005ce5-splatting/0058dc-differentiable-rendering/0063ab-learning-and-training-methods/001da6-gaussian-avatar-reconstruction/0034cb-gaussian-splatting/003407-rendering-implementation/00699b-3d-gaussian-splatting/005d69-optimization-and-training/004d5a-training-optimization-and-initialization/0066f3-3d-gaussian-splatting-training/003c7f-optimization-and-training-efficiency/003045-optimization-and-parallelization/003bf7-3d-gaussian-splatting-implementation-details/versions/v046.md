# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific implementation parameters, optimization schedules, and variant algorithms required to train and render 3D Gaussian Splatting (3DGS) scenes effectively. It addresses the core training loop, hardware-aware rasterization optimizations, and specific methodological variants for handling scene extent, defocus blur, noise, and large-scale constraints. It sets itself apart from generic optimization guides by providing concrete hyperparameters, formulaic definitions for adaptive controls, and specific CUDA-level implementation strategies (e.g., half-precision fetches) derived from the `gsplat` library and related research.

## How it works

### Core Training Loop
The training process is an iterative optimization loop that minimizes the difference between rendered images and ground-truth photographs [S9, unofficial].

1.  **Initialization**: The scene is initialized using a sparse point cloud from Structure-from-Motion (SfM) [S9, unofficial].
2.  **Iteration**:
    *   **Selection**: Randomly select a single input photo and its corresponding camera pose from the training set [S2][S9, unofficial].
    *   **Rendering**: Render the current set of 3D Gaussians from the selected camera pose using a differentiable rasterizer (e.g., `gsplat`) [S2][S9, unofficial].
    *   **Loss Computation**: Compute the error between the rendered image and the ground-truth photo [S9, unofficial]. The total loss $\mathcal{L}$ is a weighted combination of L1 loss and D-SSIM:
        $$ \mathcal{L} = (1 - \lambda)\mathcal{L}_1 + \lambda\mathcal{L}_{SSIM} $$
        where $\lambda \approx 0.2$ [S9, unofficial].
    *   **Optimization**: Compute gradients of $\mathcal{L}$ with respect to Gaussian parameters (position, covariance, opacity, color, SH coefficients) and update them using the Adam optimizer [S2][S9, unofficial].
3.  **Termination**: Training typically runs for a fixed iteration budget, commonly around 30,000 iterations [S9, unofficial].

### Rasterization and Kernel Implementation
To achieve real-time performance, the implementation relies on custom CUDA kernels, often within the `gsplat` library [S1, S2].

*   **Half-Precision Fetches**: To reduce register pressure during rasterization, feature vectors are fetched using half-precision (FP16) memory accesses for both forward and backward passes [S1].
*   **Neural Network Integration**: If neural components (e.g., for color or deformation) are used, they are implemented using JIT-compiled cooperative vector MLPs (e.g., via `tiny-cuda-nn`) trained and evaluated in FP16 [S1].
*   **Loss Scaling**: An automatic scaling factor is applied to loss values to improve stability during half-precision training [S1].

### Optimization Parameters
*   **Optimizer**: Adam [S2].
*   **Learning Rate**: $1 \times 10^{-3}$ [S2].
*   **Spherical Harmonics (SH) Degree**: 1 [S2].

### Pseudocode: Standard Training Iteration

```python
def training_iteration(gaussians, camera_poses, gt_images, optimizer, lambda_ssim=0.2):
    """
    Performs one iteration of 3D Gaussian Splatting training.
    
    Args:
        gaussians: Current set of 3D Gaussian primitives.
        camera_poses: List of camera poses (extrinsics/intrinsics).
        gt_images: List of ground-truth images.
        optimizer: Adam optimizer instance.
        lambda_ssim: Weight for SSIM loss term.
        
    Returns:
        None (updates gaussians in place via optimizer).
    """
    # 1. Randomly select one image and its pose
    idx = random_integer(0, len(camera_poses) - 1)
    pose = camera_poses[idx]
    gt_image = gt_images[idx]
    
    # 2. Render the scene from the selected pose
    # Uses differentiable rasterizer (e.g., gsplat)
    rendered_image = render_gaussians(gaussians, pose)
    
    # 3. Compute Loss
    # L1 Loss: Mean absolute difference
    l1_loss = mean_absolute_error(rendered_image, gt_image)
    
    # D-SSIM Loss: Structural Similarity index based loss
    ssim_loss = 1.0 - structural_similarity_index(rendered_image, gt_image)
    
    # Combined Loss
    total_loss = (1.0 - lambda_ssim) * l1_loss + lambda_ssim * ssim_loss
    
    # 4. Backpropagation and Update
    optimizer.zero_grad()
    total_loss.backward()
    optimizer.step()
    
    # Note: Densification (splitting/cloning) and pruning are typically
    # performed periodically (e.g., every 100 iterations) based on gradient
    # thresholds and opacity, not in every single iteration.
```

## Subtopics

### Corrected Scene-Extent
A method to calculate scene extent based on the SfM point cloud rather than camera positions to avoid bias from camera distribution [S3].
*   **Definition**: The default 3DGS scene extent $e_{\text{scene}}$ is proportional to the distance of the furthest camera from the average camera position, causing bias if cameras are clustered (e.g., orbiting a small object) [S3].
*   **Formula**: The corrected scene extent $e'_{\text{scene}}$ is calculated as:
    $$ e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2 $$
    where $N_{\text{SfM}}$ is the number of SfM points, $\bar{C}$ is the averaged camera position, and $p_i$ is the i-th SfM point [S3].
*   **Pitfall**: Using the default extent leads to incorrect splitting/pruning in large outdoor scenes captured with clustered cameras [S3].

### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ to selectively enlarge covariances, creating pixel-wise variable blur kernels that match spatially varying scene blurriness [S4].
*   **Step**: Predict $\delta s_j$ for each Gaussian $j$ using a compact MLP. Add offset to base scale to transform covariance. Project transformed covariance to 2D space. Use as pixel-wise blur kernel during rasterization [S4].
*   **Pitfall**: If $\delta s_j$ is predicted as a constant for all Gaussians, it degrades to a uniform Gaussian blur over the entire image [S4].
*   **Comparison**: Unlike naive Gaussian blur which applies a single kernel to the whole image, this method enables spatially varying blur shapes and magnitudes [S4].

### Denoise-GS
A self-supervised denoising method for sparse-view 3D Gaussian Splatting that combines unsupervised image denoising with explicitly differentiable 3DGS [S5].
*   **Step**:
    1.  Train a UNet using Noise2Void (N2V) for denoising on input images [S5].
    2.  Process denoised images through InstantSplat to initialize, train, and render 3DGS [S5].
    3.  Group and filter rendered results by viewpoint to ensure representativeness [S5].
    4.  Fine-tune the UNet using a composite loss balancing low-frequency and perceptual detail consistency [S5].
    5.  Render again on selected viewpoints to generate denoised views [S5].
*   **Comparison**: Unlike supervised methods requiring annotated data, Denoise-GS uses unsupervised N2V, which requires no paired clean data and is robust to uncertain noise patterns in sparse viewpoint scenarios [S5].

### Multi-Scale Constraint
A technique using position-aware point adaptive control to apply different scales to Gaussians based on viewer distance, improving rendering of distant objects [S6].
*   **Formula**: The scale factor $\gamma(\mu)$ is defined as:
    $$ \gamma(\mu) = \begin{cases} 1 & \text{if } \|\mu - c\|^2 < 2r \\ \|\mu - c\|^2 / r - 1 & \text{if } \|\mu - c\|^2 \ge 2r \end{cases} $$
    where $r$ is the scene radius and $c$ is the center of cameras [S6].
*   **Step**:
    *   If $\max(s) < g \cdot \gamma(\mu)$, perform cloning.
    *   If $\max(s) \ge g \cdot \gamma(\mu)$, execute splitting.
    *   Eliminate Gaussians where $\max(s) > b \cdot \gamma(\mu)$ [S6].
*   **Parameters**: $g$ is the scale threshold for cloning, $b$ is the scale threshold for elimination [S6].

### LS-Gaussian Viewpoint Transformation
An algorithm that leverages inter-frame continuity for efficient sparse rendering by transforming the viewpoint between consecutive frames, rather than rendering each frame separately [S7].
*   **Usage**: Used in LS-Gaussian to enable sparse rendering where only one frame in every 6 frames is fully rendered, as demonstrated on Jetson AGX Orin [S7].
*   **Pitfall**: Rendering quality degrades noticeably as the number of consecutively transformed frames increases due to the accumulation of interpolation errors [S7].
*   **Comparison**: Unlike naive pixel warping which fails to reduce preprocessing and sorting costs because projected Gaussians are assigned to workloads at the tile level, this method operates at the tile/Gaussian level to enable sparse rendering [S7].

### GS-IR (Gaussian Splatting for Internal Rendering)
GS-IR is a plane-based internal rendering framework that replaces exterior-view supervision with cross-sectional supervision sampled from a volume to reconstruct internal volumetric structure [S8].
*   **Step**:
    1.  Virtual cameras define slicing planes within the volume [S8].
    2.  A binary mask selects the Gaussian subset whose centers lie within the plane thickness [S8].
    3.  The selected Gaussian subset is rendered using the original Gaussian rasterizer [S8].
    4.  Optimization is performed against ground-truth cross-sections generated through trilinear resampling [S8].
    5.  Distance-aware soft weighting is applied to continuously attenuate Gaussian opacity as the distance from the Gaussian to the plane increases [S8].
*   **Parameter**: Plane thickness defines the spatial extent for Gaussian selection [S8].
*   **Comparison**: Unlike conventional 3DGS which constrains camera-visible surfaces, GS-IR focuses optimization gradients on interior Gaussians to supervise occluded internal regions [S8].
*   **Performance**: PSNR improvement of up to 21.52 dB and SSIM improvement of up to 0.54 on KiTS23 CT and IXI MRI datasets [S8].

### 3D Gaussian Splatting Training Loop
Per-image error compares one render against one photo. Scene-wide error is the loss averaged across all training views, used to monitor overall progress [S9, unofficial].
*   **Comparison**: Unlike random search or Monte Carlo methods which try changes blindly, this method uses gradient descent to compute the actual downhill direction for the error surface, allowing millions of parameters to be corrected simultaneously and purposefully [S9, unofficial].

### Camera Localisation for Convergence Basin
Localizes camera pose by minimizing only the photometric error against the ground-truth colour image of the target view, fixing the initial Gaussian set $G_{init}$ during optimization [S10, unofficial].
*   **Step**:
    1.  Initialize $T_{CW}$ at one of the test view's positions [S10, unofficial].
    2.  Perform optimization for 1000 iterations [S10, unofficial].
    3.  Localisation is successful if the estimated pose converges to within 1cm of the target view within the 1000 iterations [S10, unofficial].
*   **Formula**: Find estimated pose $T_{CW}^{est}$ by:
    $$ \mathbf{T}_{CW}^{est} = \underset{\mathbf{T}_{CW}}{\arg \min} \left\| I(\mathcal{G}_{init}, \mathbf{T}_{CW}) - \bar{I}_{target} \right\|_1 $$
    where $I$ is the rendered image, $\mathcal{G}_{init}$ is the initial Gaussian set, and $\bar{I}_{target}$ is the target image [S10, unofficial].

### Relightable 3D Gaussians
A differentiable point-based rendering framework that enhances vanilla 3D Gaussians by associating extra properties (normal vectors, BRDF parameters, and incident lighting) to achieve photo-realistic relighting and BRDF decomposition from multi-view images [S11].
*   **Step**:
    1.  Assign a normal vector $n$, BRDF values, and incident light information to each 3D Gaussian point to model per-point light reflectance [S11].
    2.  Apply physically based rendering (PBR) to get a PBR color for each 3D Gaussian point, which is then alpha-composited to obtain the rendered color for the corresponding image pixel [S11].
    3.  Split the incident light into a global environment map and an indirect incident light field for robust material and lighting estimation [S11].
    4.  Introduce proper regularizations to enhance geometry and mitigate material-lighting ambiguity, including constraints on depth distribution, smoothness priors, and a lighting regularization [S11].

### DiffGS Framework
Applies an optimization process during Gaussian extraction to optimize Gaussians to exact locations [S12].
*   **Parameter**: Truncation function $\lambda$ is introduced when modeling GauPF (Gaussian Probability Function) [S12]. Projection function $\tau$ is implemented either as $\tau(x) = e^{-x}$ (Exponent) or as a linear projection [S12].
*   **Performance**:
    *   50K Gaussians: PSNR 28.61, SSIM 0.9787, LPIPS 0.0251 [S12].
    *   100K Gaussians: PSNR 30.35, SSIM 0.9838, LPIPS 0.0151 [S12].
    *   350K Gaussians: PSNR 34.01, SSIM 0.9879, LPIPS 0.0149 [S12].

### Opacity Offset Table for DSA
A method that constructs an opacity offset table to model changes in digital subtraction angiography [S13].

## Operating characteristics

### Time and Memory Complexity
*   **Rendering**: The rasterization process is $O(N \cdot P)$ where $N$ is the number of Gaussians and $P$ is the number of pixels, but optimized via tile-based sorting and culling to be effectively linear in practice for sparse scenes [S1, S2].
*   **Training**: Memory usage scales with the number of Gaussians and the resolution of the training images. Half-precision fetches reduce register pressure and memory bandwidth requirements [S1].
*   **Large Scenes**: For large-scale scenes (e.g., Waymo Zero-shot Volume Range: 50m x 20m x 128m), memory management becomes critical. Implementations like EVolSplat use sparse 3D convolution (e.g., `torchsparse`) with volume dimensions such as $128 \times 320 \times 640$ (voxel size 0.1m) to manage memory efficiently [S2].

### Measured Performance
*   **Hardware**: LS-Gaussian achieves a 5.41× speedup over edge GPU baselines on Jetson AGX Orin, and up to 17.3× with a customized accelerator, by leveraging sparse rendering [S7].
*   **Quality**: GS-IR improves PSNR by up to 21.52 dB and SSIM by up to 0.54 on medical imaging datasets (KiTS23 CT, IXI MRI) compared to standard 3DGS [S8].

### Strengths and Limitations
*   **Strengths**: Real-time rendering speeds, high visual fidelity, and efficient memory usage through half-precision optimizations and sparse representations [S1, S2].
*   **Limitations**: Standard 3DGS assumes smooth, continuous alpha blending, which can struggle with sharp boundaries and discontinuities [S1, S7]. Performance degrades in sparse-view or noisy scenarios without additional denoising steps (e.g., Denoise-GS) [S5].

## Background

### Origin
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 as a real-time explicit 3D scene representation method [S1][S9, unofficial]. It differs from NeRFs by using explicit Gaussian primitives instead of implicit neural fields.

### Development
The method has evolved to include various optimizations for training efficiency, rendering speed, and handling specific scene types (e.g., internal volumes, dynamic scenes, large-scale urban environments). Key developments include the `gsplat` library for efficient CUDA-based rasterization [S1, S2], and variants addressing specific challenges like defocus blur [S4], noise [S5], and large-scale constraints [S6].

### Usage
3DGS is widely used in computer vision and graphics for novel view synthesis, 3D reconstruction, and augmented reality applications. It is particularly valued for its ability to render high-quality images in real-time on consumer hardware [S1, S7].
