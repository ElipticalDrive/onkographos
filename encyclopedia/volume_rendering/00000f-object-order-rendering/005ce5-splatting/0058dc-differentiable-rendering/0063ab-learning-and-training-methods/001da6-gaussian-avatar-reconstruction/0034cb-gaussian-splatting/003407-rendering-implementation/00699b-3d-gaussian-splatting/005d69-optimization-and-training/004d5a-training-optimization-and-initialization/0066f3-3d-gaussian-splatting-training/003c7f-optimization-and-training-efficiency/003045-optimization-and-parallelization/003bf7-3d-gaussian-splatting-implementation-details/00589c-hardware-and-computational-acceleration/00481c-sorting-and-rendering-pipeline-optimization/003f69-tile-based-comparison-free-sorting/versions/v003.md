# Tile-Based Comparison-Free Sorting

Also called: Comparison-Free Depth Sorting, Tile-Local Sorting

## Overview
Tile-Based Comparison-Free Sorting restricts depth sorting operations to individual tiles to avoid global synchronization, reduce hardware complexity, and achieve fixed latency per output [S1]. Unlike global radix sort, which incurs high memory traffic and variable latency due to histograms and prefix sums, this method provides deterministic O(N) cycles suitable for low-power hardware accelerators [S1]. It serves as the sorting mechanism for 3D Gaussian Splatting, ensuring Gaussians are ordered front-to-back for correct alpha compositing within each tile [S1].

## How it works
**Inputs and Outputs**
*   **Input:** A list of $N$ Gaussian points per tile, each with a projected depth value [S1].
*   **Output:** The Gaussian points sorted front-to-back (increasing depth) within each tile [S1].
*   **Sorting Key:** $\langle \text{tile-id}, \text{depth} \rangle$ [S1].

**Data Structures**
*   **Element Vector Table (EVT):** A bit vector of size $N$ tracking unsorted elements [S1].
*   **Depth Values:** $n$-bit representations of depth, processed from the most significant bit [S1].

**Algorithm Steps**
The algorithm identifies the Largest Element (LE) iteratively $N$ times, marking each as sorted in the EVT until all elements are ordered [S1].

1.  **Initialization:** Initialize the EVT with all bits set to `1` to indicate all elements are unsorted [S1].
2.  **Concurrent Phase:** $k$ parallel clusters process partitions of the $N$ $n$-bit elements starting from the most significant bit [S1]. The clusters filter out smaller values through bitwise AND operations and multiplexer-based selection in cascaded blocks [S1].
3.  **Sequential Phase:** The outputs from the $k$ clusters pass to a linear array of $k$ cascaded blocks to further refine the selection and identify the single Largest Element (LE) [S1].
4.  **Data Conflict Resolution:** Duplicate depth values may cause multiple bits to be selected as "largest" [S1]. To resolve conflicts, the algorithm computes a unique identifier using bitwise operations: $FO_{NEW} = Fo \& (\sim Fo + 1)$, where $Fo$ is the output mask [S1]. This isolates a single element from the conflict set [S1].
5.  **Iteration:** The identified LE is removed from the EVT by setting its bit to `0` [S1]. The process repeats $N$ times until the EVT contains all `0`s, signaling completion [S1].

**Pseudocode**
```python
def tile_based_comparison_free_sort(depths, n_bits, k_clusters):
    """
    Sorts Gaussian depths within a tile using comparison-free logic.
    depths: List of n-bit depth values.
    n_bits: Number of bits per depth value.
    k_clusters: Number of parallel processing clusters.
    """
    N = len(depths)
    evt = [1] * N  # Element Vector Table: 1 = unsorted, 0 = sorted
    sorted_depths = []

    for _ in range(N):
        # Concurrent Phase: Filter candidates starting from MSB
        candidates = [i for i in range(N) if evt[i] == 1]
        for bit_pos in range(n_bits - 1, -1, -1):
            if len(candidates) <= 1:
                break
            # Extract bit at current position for all candidates
            bits = [(depths[i] >> bit_pos) & 1 for i in candidates]
            # Retain only candidates with the maximum bit value
            max_bit = max(bits)
            candidates = [candidates[j] for j, b in enumerate(bits) if b == max_bit]

        # Data Conflict Resolution: Isolate LSB of the candidate mask
        if len(candidates) > 1:
            candidate_mask = sum(1 << i for i in candidates)
            # FO_NEW = Fo & (~Fo + 1) isolates the least significant set bit
            resolved_mask = candidate_mask & (~candidate_mask + 1)
            selected_idx = resolved_mask.bit_length() - 1
        else:
            selected_idx = candidates[0]

        # Iteration: Mark selected element as sorted
        evt[selected_idx] = 0
        sorted_depths.append(depths[selected_idx])

    return sorted_depths
```

**Edge Cases and Pitfalls**
*   **Duplicate Depths:** The algorithm must handle duplicate depth values to prevent multiple EVT bits from being selected as largest [S1]. The bitwise resolution formula ensures deterministic single-element selection per cycle [S1].
*   **Sign Bit:** Near-plane culling excludes points with depth $< 0$, making the sign bit always 0 [S1]. The algorithm skips sign bit operations to reduce unnecessary computations [S1].
*   **Variable N:** The number of Gaussians per tile varies across scenes and views [S1]. The fixed-latency comparison-free logic handles this variability without pipeline stalls [S1].

## Subtopics

### Parallel Comparison-Free Sorting
A tile-based, comparison-free sorting algorithm for Gaussian points that uses an Element Vector Table (EVT) to identify the largest element (LE) in O(N) deterministic cycles, avoiding the high memory overhead of radix sort [S1]. It is chosen when hardware resources are constrained and deterministic latency is required, as opposed to global sorting methods [S1].

## Operating characteristics
*   **Time Complexity:** O(N) deterministic cycles per tile, where N is the number of Gaussians in the tile [S1].
*   **Memory Complexity:** Low hardware complexity compared to radix sort, which requires histograms, prefix sums, and scatters [S1]. The EVT requires O(N) bits [S1].
*   **Performance:** Achieves full-HD rendering at 129 FPS, with 3× higher throughput and 5.98× smaller area compared to prior 3DGS accelerators [S1].
*   **Strengths:** Fixed per-output latency, no global synchronization, low hardware complexity, suitable for low-power AR/VR hardware [S1].
*   **Limitations:** Requires near-plane culling to skip sign bit logic; performance depends on the number of Gaussians per tile, which can vary significantly [S1].
