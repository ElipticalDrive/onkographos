# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific algorithmic choices, hyperparameters, and optimization strategies required to implement the 3D Gaussian Splatting (3DGS) training pipeline, focusing on stability, efficiency, and handling of specific scene conditions. It addresses the problem of configuring the differentiable rasterizer and optimizer to converge on high-fidelity radiance fields, distinguishing itself from general optimization schedules by providing concrete parameter values, data structure layouts, and custom kernel logic for forward/backward passes. It builds on [Optimization and Parallelization](6233-optimization-and-parallelization.md).

## How it works

### Inputs and Outputs
*   **Inputs**: Sparse Structure-from-Motion (SfM) point cloud, camera poses, and multi-view images.
*   **Outputs**: A set of 3D Gaussian primitives parameterized by position $\mathbf{p}$, covariance $\mathbf{\Sigma}$ (or rotation $\mathbf{R}$ and scale $\mathbf{s}$), opacity $\alpha$, and Spherical Harmonics (SH) coefficients $\mathbf{c}$.

### Data Structures
The core data structure is a list of Gaussians. Each Gaussian $i$ stores:
*   **Position**: $\mathbf{p}_i \in \mathbb{R}^3$
*   **Rotation**: $\mathbf{q}_i \in \mathbb{R}^4$ (unit quaternion) or $\mathbf{R}_i \in \mathbb{R}^{3 \times 3}$
*   **Scale**: $\mathbf{s}_i \in \mathbb{R}^3$
*   **Opacity**: $\alpha_i \in [0, 1]$
*   **Color**: SH coefficients $\mathbf{c}_i$ up to degree $D$. For $D=1$, this requires $3 \times (1+3) = 12$ coefficients per RGB channel, or 36 floats total.

### Parameters
*   **Optimizer**: Adam [S2].
*   **Learning Rate**: $1 \times 10^{-3}$ [S2].
*   **SH Degree**: 1 (default for simplicity and speed) [S2].
*   **Rasterization Library**: `gsplat` [S1, S2].
*   **Sparse Convolution**: `torchsparse` [S2].
*   **Loss Scaling**: An automatic scaling factor is applied to loss values to improve half-precision (FP16) training stability [S1].

### Steps

1.  **Initialization**: Initialize Gaussians from the SfM point cloud. Calculate scene extent.
    *   *Pitfall*: The default scene extent $e_{\text{scene}}$ is proportional to the distance of the furthest camera from the average camera position [S3]. This biases optimization if cameras are clustered (e.g., orbiting a small object), leading to incorrect splitting/pruning [S3].
    *   *Correction*: Use the corrected scene extent based on the SfM point cloud [S3]:
        $$ \bar{C} = \frac{1}{N_{\text{cam}}} \sum_{i=1}^{N_{\text{cam}}} C_i $$
        $$ e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2 $$
        where $N_{\text{cam}}$ is the number of camera views, $C_i$ is the $i$-th camera position, $N_{\text{SfM}}$ is the number of SfM points, and $p_i$ is the $i$-th SfM point [S3].

2.  **Iteration Loop**:
    *   Randomly select a single image from a random scene as supervision for each iteration [S2].
    *   **Forward Pass**:
        *   Project 3D Gaussians to 2D screen space.
        *   Use half-precision memory fetches on feature vectors during rasterization for both forward and backward kernels to reduce register pressure [S1].
        *   Render image using alpha blending.
    *   **Loss Computation**:
        *   Compute loss $\mathcal{L}$ between rendered image $I^r$ and ground truth $I^{gt}$ using L1 and D-SSIM [S6]:
            $$ L = \sum_{k=1}^K (1 - \lambda_1) \| I_k^{gt} - I_k^r(\Theta) \|_{\ell_1} + \lambda_1 L_{D-SSIM}(I_k^{gt}, I_k^r(\Theta)) $$
            where $K$ is the number of images and $\lambda_1 \in [0,1]$ is user-defined [S6].
    *   **Backward Pass**:
        *   Compute gradients $\nabla_\Theta \mathcal{L}$ with respect to Gaussian parameters.
        *   Use tiny-cuda-nn's JIT-compiled cooperative vector MLPs, trained and evaluated in half precision (FP16) if neural appearance models are used [S1].
    *   **Optimization Step**:
        *   Update parameters using Adam optimizer [S2].
    *   **Densification/Pruning**:
        *   Apply densification based on gradient thresholds and scale constraints (see Subtopics for specific variants like Multi-Scale Constraint).

### Edge Cases and Pitfalls
*   **Half-Precision Stability**: FP16 training can suffer from overflow/underflow. Apply an automatic scaling factor to loss values [S1].
*   **Scene Extent Bias**: Using camera-based extent for clustered cameras causes poor reconstruction. Use SfM-based extent [S3].
*   **Linear Response**: Camera sensors must have a linear response to light. In-camera processed .jpg images or gamma-corrected images cannot be used unless non-linearities are reversed [S6].

### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ to selectively enlarge covariances, creating pixel-wise variable blur kernels that match spatially varying scene blurriness [S4]. It sets itself apart from naive Gaussian blur (uniform) or learnable single-kernel approaches by allowing spatially varying blur shapes and magnitudes [S4]. Choose this when training on images with defocus blur or motion blur [S4]. Pitfall: If $\delta s_j$ is predicted as a constant for all Gaussians, it degrades to a uniform Gaussian blur [S4].

### Denoise-GS
A self-supervised denoising method for sparse-view 3D Gaussian Splatting that combines unsupervised image denoising with explicitly differentiable 3DGS [S5]. It sets itself apart from supervised methods (requiring clean annotations) and Noise2Noise (requiring paired noisy images) by using Noise2Void (N2V), which requires no paired data [S5]. Choose this for sparse-view or noisy scenes [S5]. Steps: 1. Train UNet with N2V. 2. Process denoised images through InstantSplat to initialize/train 3DGS. 3. Filter rendered results. 4. Fine-tune UNet with composite loss. 5. Render final views [S5].

### Backscatter Estimation and Optimization
Estimates underwater backscatter parameters ($B_\infty, B_b$) and direct attenuation ($B_d$) to correct color distortion [S6]. It sets itself apart from standard 3DGS by incorporating ocean optics models [S6]. Choose this for underwater scenes [S6]. Steps: 1. Divide depth map into 10 clusters. 2. Identify pixels with RGB below 1st percentile as backscatter overestimate $B_s$. 3. Fit $B_\infty, B_b$ via nonlinear least squares on $(B_s, z)$ pairs. 4. Re-estimate every 500 steps [S6]. Pitfall: Requires linear camera response [S6].

### Multi-Scale Constraint
Applies different scales to Gaussians based on viewer distance to improve rendering of distant objects [S7]. It sets itself apart from standard densification by using a position-aware adaptive control $\gamma(\mu)$ [S7]. Choose this for large-scale scenes with varying distances [S7]. Formula: $\gamma(\mu) = 1$ if $\|\mu - c\|^2 < 2r$; $\gamma(\mu) = \|\mu - c\|^2 / r - 1$ if $\|\mu - c\|^2 \ge 2r$. Cloning if $\max(s) < g \cdot \gamma(\mu)$, splitting if $\max(s) \ge g \cdot \gamma(\mu)$, elimination if $\max(s) > b \cdot \gamma(\mu)$ [S7].

### LS-Gaussian Viewpoint Transformation
Leverages inter-frame continuity for efficient sparse rendering by transforming the viewpoint between consecutive frames [S8]. It sets itself apart from naive pixel warping by operating at the tile/Gaussian level to reduce preprocessing and sorting costs [S8]. Choose this for real-time rendering on edge devices (e.g., Jetson AGX Orin) where only one frame in every 6 is fully rendered [S8]. Pitfall: Quality degrades with accumulated interpolation errors over many transformed frames [S8].

### LS-Gaussian Accelerator Architecture
A hardware architecture co-designed with LS-Gaussian to support workload-aware mapping [S8]. It sets itself apart from naive tile assignment by predicting workload per tile to mitigate inter-block idling and intra-block bubbles [S8]. Choose this for custom hardware implementations of 3DGS [S8].

### GS-IR (Gaussian Splatting for Internal Rendering)
A plane-based internal rendering framework that replaces exterior-view supervision with cross-sectional supervision sampled from a volume [S9]. It sets itself apart from conventional 3DGS by focusing optimization gradients on interior Gaussians to supervise occluded internal regions [S9]. Choose this for medical imaging (CT/MRI) internal view synthesis [S9]. Steps: 1. Define slicing planes with virtual cameras. 2. Select Gaussians within plane thickness via binary mask. 3. Render subset. 4. Optimize against ground-truth cross-sections. 5. Apply distance-aware soft weighting to attenuate opacity [S9].

## Operating characteristics

*   **Time Complexity**: Rendering is $O(N \cdot P)$ where $N$ is the number of Gaussians and $P$ is the number of pixels, but optimized via tiling and sorting. Training time depends on the number of iterations and densification steps.
*   **Memory Complexity**: $O(N \cdot D)$ where $D$ is the dimensionality of SH coefficients. Large scenes (e.g., Waymo) can require significant memory (e.g., 10-26 GB) [S2].
*   **Performance**: On NVIDIA V100, generalizable methods like EVolSplat achieve ~81-83 FPS [S2]. LS-Gaussian achieves up to 17.3x speedup on custom accelerators [S8].
*   **Strengths**: Real-time rendering, high fidelity, explicit representation.
*   **Limitations**: High memory usage for large scenes, sensitivity to initialization and scene extent, artifacts in sparse views or underwater environments without modifications.
*   **When to use**: Real-time novel view synthesis, high-quality 3D reconstruction from multi-view images.
*   **When not to use**: Scenes with extreme transparency or subsurface scattering without modifications, underwater scenes without backscatter modeling, internal volume reconstruction without GS-IR.

## Background

3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1, S2, S6, S9]. It represents scenes as a set of differentiable 3D Gaussians optimized via gradient descent. The method gained popularity for its real-time rendering capabilities and high visual quality compared to NeRFs. Subsequent works have extended it to handle defocus blur [S4], underwater scenes [S6], sparse views [S5], internal volumes [S9], and large-scale scenes [S7, S8].
