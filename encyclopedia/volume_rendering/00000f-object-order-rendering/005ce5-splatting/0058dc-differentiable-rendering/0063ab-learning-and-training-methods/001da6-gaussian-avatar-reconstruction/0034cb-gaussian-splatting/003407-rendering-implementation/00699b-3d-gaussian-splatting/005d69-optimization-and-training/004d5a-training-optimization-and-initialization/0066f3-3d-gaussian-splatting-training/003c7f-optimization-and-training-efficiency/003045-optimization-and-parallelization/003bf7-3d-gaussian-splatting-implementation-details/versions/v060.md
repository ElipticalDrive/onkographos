# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, GSGEN Implementation Details, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific hyperparameters, optimization schedules, data structures, and hardware-accelerated kernel implementations required to train and render 3D Gaussian Splatting (3DGS) scenes. It addresses the practical engineering challenges of differentiable volume rendering, including half-precision stability, adaptive densification thresholds, and memory-efficient rasterization pipelines. It sets itself apart from theoretical descriptions by providing exact numerical thresholds, iteration schedules, and CUDA-level optimization strategies necessary for a working implementation.

## How it works

### Inputs and Outputs
*   **Inputs**: A set of $N$ images with known camera poses (intrinsic and extrinsic parameters), initialized from Structure-from-Motion (SfM) [S9, unofficial].
*   **Outputs**: A set of $M$ 3D Gaussian primitives, each parameterized by position $\mu$, covariance $\Sigma$ (encoded as scale $s$ and rotation $q$), opacity $\alpha$, and spherical harmonic coefficients for color $c_{SH}$ [S1][S9, unofficial].

### Data Structures
The Gaussian representation is stored in a flat array or structure-of-arrays (SoA) layout for efficient GPU access [S2, S16]:
*   **Position**: 3 floats ($x, y, z$).
*   **Rotation**: 4 floats (quaternion $w, x, y, z$).
*   **Scale**: 3 floats ($s_x, s_y, s_z$).
*   **Opacity**: 1 float.
*   **Color**: $K \times 3$ floats, where $K$ is the number of spherical harmonic (SH) coefficients. For SH degree 1, $K=4$, resulting in 12 floats [S3].
*   **Features**: Additional feature vectors (e.g., for semantic or language tasks) are appended, often fetched in half-precision to reduce register pressure [S2].

### Training Loop and Optimization
The training process is a stochastic gradient descent loop [S9, unofficial]:

1.  **Random View Selection**: Randomly select one input image and its corresponding camera pose from the training set [S9, unofficial].
2.  **Differentiable Rasterization**: Render the current Gaussian set from the selected camera pose using the differentiable alpha-blending rasterizer [6233-optimization-and-parallelization].
3.  **Loss Computation**: Compute the loss $\mathcal{L}$ between the rendered image and the ground-truth image. The loss is a weighted combination of L1 loss and D-SSIM [S9, unofficial]:
    $$ \mathcal{L} = (1 - \lambda) \mathcal{L}_1 + \lambda \mathcal{L}_{\text{SSIM}} $$
    where $\lambda \approx 0.2$ [S9, unofficial].
4.  **Gradient Computation**: Compute gradients $\frac{\partial \mathcal{L}}{\partial \theta}$ with respect to all Gaussian parameters $\theta$ (position, scale, rotation, opacity, SH coefficients) via backpropagation through the rasterizer [6233-optimization-and-parallelization].
5.  **Optimizer Update**: Update parameters using the Adam optimizer with a learning rate of $1 \times 10^{-3}$ [S3].
6.  **Iteration**: Repeat for a fixed budget of iterations, typically 30,000 [S9, unofficial].

### Adaptive Densification and Pruning
To maintain reconstruction fidelity, the Gaussian population is dynamically adjusted [S1, S4]:

1.  **Gradient Monitoring**: Accumulate view-space position gradients for each Gaussian over a window of iterations [S1].
2.  **Splitting**: Every 500 iterations, split Gaussians whose accumulated position gradient exceeds a threshold $T_{\text{pos}} = 0.02$ [S1]. Splitting involves cloning the Gaussian and perturbing its position and scale [S1].
3.  **Cloning**: Gaussians with high opacity but low gradient may be cloned to increase density in under-reconstructed areas [S1].
4.  **Pruning**: Every 200 iterations, remove Gaussians with opacity $\alpha < \alpha_{\text{min}} = 0.05$ or those with excessively large world-space or view-space radii [S1].
5.  **Compactness Check**: Perform compactness-based densification every 1000 iterations to ensure spatial distribution [S1].

### Scene Extent Correction
The default 3DGS scene extent $e_{\text{scene}}$ is calculated based on camera positions, which can be biased if cameras are clustered [S4]:
$$ e_{\text{scene}} = 1.1 \cdot \max_{i=1}^{N_{\text{cam}}} \|\bar{C} - C_i\|_2 $$
where $\bar{C}$ is the average camera position [S4]. This bias leads to incorrect splitting/pruning in scenes like orbiting small objects [S4]. A corrected scene extent $e'_{\text{scene}}$ is used instead, based on the SfM point cloud [S4]:
$$ e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2 $$
where $N_{\text{SfM}}$ is the number of SfM points and $p_i$ are their positions [S4].

### Half-Precision Rasterization
To improve performance and reduce memory bandwidth, the rasterization kernels use half-precision (FP16) arithmetic [S2]:
*   Feature vectors are fetched in half-precision during both forward and backward passes [S2].
*   The loss values are scaled automatically to maintain stability during half-precision training [S2].
*   Custom CUDA kernels are implemented using tiny-cuda-nn's JIT-compiled cooperative vector MLPs, trained and evaluated in FP16 [S2].

### GEMM-GS Acceleration
For further acceleration, the blending process can be reformulated into a General Matrix Multiplication (GEMM) compatible form [S16]:
1.  **Preprocessing**: Project 3D Gaussians to 2D, compute depth $d$ and RGB color $c$ [S16].
2.  **Duplication**: Duplicate Gaussians for each tile they overlap, assigning a tile index [S16].
3.  **Sorting**: Sort Gaussians by depth within each tile using radix sort [S16].
4.  **Blending**: Implement the alpha-blending equation as a GEMM operation [S16]:
    $$ C_j = \sum_{i=1}^{N} T_i \alpha_{i,j} c_i $$
    where $T_i = \prod_{k=1}^{i-1} (1 - \alpha_{k,j})$ [S16].
5.  **Kernel Design**: Use a three-stage double-buffered pipeline with asynchronous memory copy to overlap computation and memory access [S16]. A 16x16 tile is assigned to a thread block of 256 threads [S16].

### Pseudocode

```python
def train_3dgs(images, camera_poses, initial_gaussians, num_iterations=30000):
    """
    Main training loop for 3D Gaussian Splatting.
    
    Args:
        images: List of training images.
        camera_poses: List of camera poses corresponding to images.
        initial_gaussians: Initial set of 3D Gaussians from SfM.
        num_iterations: Total number of training steps.
        
    Returns:
        Trained set of 3D Gaussians.
    """
    gaussians = initial_gaussians
    optimizer = Adam(gaussians.parameters(), lr=1e-3)
    
    for step in range(num_iterations):
        # 1. Random View Selection
        idx = random.randint(0, len(images) - 1)
        image = images[idx]
        pose = camera_poses[idx]
        
        # 2. Differentiable Rasterization
        # Render using half-precision kernels if enabled
        rendered_image = rasterize(gaussians, pose, half_precision=True)
        
        # 3. Loss Computation
        # L = 0.8 * L1 + 0.2 * D-SSIM
        loss = compute_loss(rendered_image, image, lambda_ss=0.2)
        
        # 4. Gradient Computation and Update
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        
        # 5. Adaptive Densification and Pruning
        if step % 500 == 0:
            # Split Gaussians with high position gradient
            split_gaussians(gaussians, threshold=0.02)
            
        if step % 200 == 0:
            # Prune low opacity Gaussians
            prune_gaussians(gaussians, alpha_min=0.05)
            
        if step % 1000 == 0:
            # Compactness-based densification
            densify_gaussians(gaussians)
            
    return gaussians

def rasterize(gaussians, camera_pose, half_precision=False):
    """
    Differentiable rasterization of 3D Gaussians.
    
    Args:
        gaussians: List of 3D Gaussian primitives.
        camera_pose: Camera intrinsic and extrinsic parameters.
        half_precision: Whether to use FP16 for feature fetching.
        
    Returns:
        Rendered image.
    """
    # Project Gaussians to 2D
    projected_gaussians = project(gaussians, camera_pose)
    
    # Divide screen into tiles (e.g., 16x16)
    tiles = create_tiles(projected_gaussians)
    
    # For each tile, sort and blend Gaussians
    image = zeros_like(target_image)
    for tile in tiles:
        tile_gaussians = get_gaussians_for_tile(tile)
        sorted_gaussians = sort_by_depth(tile_gaussians)
        
        # Alpha blending
        for gaussian in sorted_gaussians:
            # Fetch features in half-precision if enabled
            color = fetch_color(gaussian, half_precision)
            alpha = gaussian.opacity
            # Compute contribution to pixels in tile
            update_pixels(tile, gaussian, color, alpha)
            
    return image

def compute_loss(rendered, ground_truth, lambda_ss=0.2):
    """
    Compute combined L1 and D-SSIM loss.
    
    Args:
        rendered: Rendered image.
        ground_truth: Ground truth image.
        lambda_ss: Weight for SSIM term.
        
    Returns:
        Scalar loss value.
    """
    l1_loss = mean_absolute_error(rendered, ground_truth)
    ssim_loss = 1 - structural_similarity(rendered, ground_truth)
    return (1 - lambda_ss) * l1_loss + lambda_ss * ssim_loss
```

### Edge Cases and Pitfalls
*   **Precision**: Half-precision training requires loss scaling to prevent underflow [S2].
*   **Boundaries**: The default scene extent calculation is biased by camera distribution; use the corrected extent based on SfM points [S4].
*   **Degenerate Input**: If cameras are clustered (e.g., orbiting a small object), the default scene extent will be too small, leading to incorrect densification [S4].

## Subtopics

### [Sorting and Rendering Pipeline Optimization](12180-sorting-and-rendering-pipeline-optimization.md)
This family addresses the computational bottlenecks in 3D Gaussian Splatting (3DGS) rendering, specifically targeting memory bandwidth limits in the front-end (sorting and attribute fetching) and compute throughput limits in the rasterization stage. It sets itself apart from generic optimization by explicitly mapping software strategies to hardware constraints (e.g., using the Roofline model) or by replacing standard sorting with hardware-friendly, comparison-free logic and sorting-free approximations.

### [LangSplat Training Procedure](12438-langsplat-training-procedure.md)
LangSplat Training Procedure is a method for optimizing 3D Gaussian Splatting scenes to incorporate semantic language features alongside photometric rendering. It extends the standard differentiable rendering pipeline by computing a loss against ground-truth language embeddings (e.g., CLIP features) when enabled, allowing the scene to support semantic queries. It is distinguished from standard 3D Gaussian Splatting training by the conditional inclusion of language feature loss and the consequent disabling of densification and pruning operations during language-aware training.

### [DeSplat](12925-desplat.md)
DeSplat is a method for distractor-free novel view synthesis that decomposes the 3D Gaussian Splatting (3DGS) scene representation into two distinct sets of Gaussian primitives: static scene Gaussians ($G_s$) and per-view distractor Gaussians ($G_d$). It solves the problem of transient occluders (e.g., pedestrians, vehicles) corrupting the static 3D reconstruction by separating them from the permanent scene geometry without relying on external semantic segmentation models or pre-trained neural networks. Unlike sibling methods that use foundation models for detection or complex neural appearance encoders for separation, DeSplat relies solely on volume rendering and photometric loss, allowing independent rendering of static elements and transient components while maintaining the speed of standard Gaussian splatting.

### [360 Gaussian Splatting](12929-360-gaussian-splatting.md)
360 Gaussian Splatting is a method for generating high-quality 3D spatial representations from 360-degree camera images by combining OpenSfM for sparse point cloud generation and Gaussian Splatting for dense Gaussian conversion. It solves the problem that standard Gaussian Splatting assumes perspective cameras and cannot directly process equirectangular images from 360-degree cameras, a limitation that previously forced users to crop or split images. It sets itself apart from standard implementations by modifying the differentiable rasterization module to support spherical rendering and using OpenSfM, which natively supports equirectangular inputs, unlike Colmap.

### [Data Compression and Storage Optimization](12943-data-compression-and-storage-optimization.md)
This family of methods reduces the memory footprint and storage size of 3D Gaussian Splatting (3DGS) scenes, which often exceed 1GB for real-world datasets [12927-compact-3d-gaussian-representation-c3dgs.md]. The primary problem addressed is the high bandwidth and storage cost of storing unique attributes (position, scale, rotation, opacity, and high-order spherical harmonic coefficients) for millions of primitives [12927-compact-3d-gaussian-representation-c3dgs.md]. These methods distinguish themselves from rendering optimizations by focusing on data representation, quantization, and structural redundancy removal rather than pipeline acceleration [11820-ascii-based-data-compression.md].

### [Bézier-boundary gradient approximation](13137-b-zier-boundary-gradient-approximation.md)
This method approximates the gradients of a discontinuous indicator function $g(\cdot)$ with respect to Bézier curve control point coordinates, enabling backpropagation in Gaussian Splatting despite the function being piecewise constant and non-differentiable. It sets itself apart from standard Gaussian Splatting, which relies on differentiable rendering, by explicitly handling the non-differentiable segments of discontinuity-aware rendering through geometric boundary analysis.

### [Discontinuity-aware Gaussian Splatting](13138-discontinuity-aware-gaussian-splatting.md)
Discontinuity-aware Gaussian Splatting (DisC-GS) is a framework that enables 3D Gaussian Splatting to represent and render sharp boundaries and discontinuities, addressing a key limitation of the original method which assumes smooth, continuous alpha blending. It distinguishes itself from standard Gaussian Splatting by introducing a "pre-scissoring" step that segments projected Gaussians along boundaries defined by cubic Bézier curves, combined with a Bézier-boundary gradient approximation strategy to maintain differentiability during optimization.

### [SOGS (Second-Order Anchor for Advanced 3D Gaussian Splatting)](13171-sogs-second-order-anchor-for-advanced-3d-gaussian-splatting.md)
SOGS is an anchor-based 3D Gaussian Splatting technique that introduces second-order statistics to achieve superior rendering quality while simultaneously reducing anchor feature dimensions and overall model size. It distinguishes itself from standard anchor methods like Scaffold-GS by using covariance-based feature augmentation to capture co-variation patterns across feature dimensions, allowing for smaller feature vectors without sacrificing detail.

### [TraGraph-GS](14454-tragraph-gs.md)
TraGraph-GS is a high-quality rendering method for arbitrary large-scale scenes that employs graph-based adaptive spatial partitioning, regularization constraints, and adaptive region selection. It addresses the limitations of standard 3D Gaussian Splatting (3DGS) in handling vast scales and textureless regions by decoupling the scene into manageable local regions and a coarse global representation. Unlike methods that rely on fixed spatial grids or simple clustering, TraGraph-GS constructs a camera connectivity graph to ensure balanced, connected subgraphs, and uses a progressive rendering strategy for novel viewpoints to eliminate boundary artifacts.

### [Optimization Schedule and Densification](15107-optimization-schedule-and-densification.md)
This family defines the temporal schedule and geometric criteria for modifying the set of 3D Gaussian primitives during training, specifically addressing when and how to split, clone, or prune Gaussians to balance reconstruction fidelity with computational efficiency. It sets itself apart from static initialization methods by dynamically adapting the primitive count and distribution based on optimization gradients and rendering errors, building on [3D Gaussian Splatting Implementation Details](9128-3d-gaussian-splatting-implementation-details.md).

### [Distributed Training and Sharding](15108-distributed-training-and-sharding.md)
Distributed training and sharding address the memory and compute bottlenecks of training 3D Gaussian Splatting (3DGS) on large-scale scenes by distributing the Gaussian population and rendering workload across multiple GPUs. Unlike spatial block partitioning, which suffers from boundary redundancy and imbalanced shards, this family primarily utilizes index-parity sharding to distribute a global Gaussian model evenly across devices, minimizing communication overhead and eliminating cross-block visibility waste.

### [Scene Representation and Geometry Constraints](15421-scene-representation-and-geometry-constraints.md)
This family of methods enhances the standard 3D Gaussian Splatting (3DGS) representation by integrating explicit geometric constraints and refining the spatial definition of Gaussian primitives to improve surface fidelity, training stability, and physical accuracy. Unlike standard 3DGS, which relies on opaque, soft volumetric splats, these methods enforce surface alignment, constrain scale distributions via mesh priors, or model volumetric attenuation in participating media. They set themselves apart from sibling methods like [Sorting and Rendering Pipeline Optimization](12180-sorting-and-rendering-pipeline-optimization.md) by focusing on the semantic and physical correctness of the scene representation rather than rendering speed or compression.

### [FAST-Splat](15436-fast-splat.md)
FAST-Splat is a semantic Gaussian Splatting method that directly augments each Gaussian primitive with specific semantic codes and uses a hash-table for disambiguation, avoiding neural fields for semantic distillation to enable fast training, rendering, and ambiguity-free object localization. It distinguishes itself from sibling methods like [LangSplat Training Procedure](12438-langsplat-training-procedure.md) and [Feature-3DGS](12925-desplat.md) by employing a single-phase, neural-free training procedure that jointly optimizes geometric, visual, and semantic attributes, thereby preserving the explicit representation's speed benefits while resolving semantic ambiguity in open-vocabulary queries.

### [Perceptual Wrapper](15438-perceptual-wrapper.md)
The Perceptual Wrapper (PW) is a plug-and-play 2D module that enhances the rendered outputs of existing 3D Gaussian Splatting (3DGS) representations by synthesizing high-frequency texture details in a content- and view-dependent manner. It addresses the limitation of standard 3DGS in rendering sharp textures, particularly under memory-constrained or rate-distortion-optimized (RDO) pipelines where blurriness is exacerbated. Unlike methods that modify the 3D primitive densification or loss functions directly (e.g., Perceptual-GS), PW operates as a post-processing synthesis network in the image domain, conditioned on pseudo-random Gaussian noise and Plücker embeddings, and is trained using Wasserstein Distortion (WD) loss.

### TurboGS
TurboGS is an error-guided training framework for 3D Gaussian Splatting (3DGS) that accelerates optimization by dynamically focusing computation on perceptually informative pixels, addressing redundant computation in well-reconstructed regions and loss of fine details [S1]. It differs from standard 3DGS by replacing dense per-pixel rasterization and supervision with a sparse, error-guided sampling strategy that adaptively reallocates computation from easy regions to challenging ones [S1].

### [Error-Guided Sparse Pixel Sampling](15708-error-guided-sparse-pixel-sampling.md)
Error-Guided Sparse Pixel Sampling (Err-SPS) is a training optimization strategy for 3D Gaussian Splatting that restricts loss evaluation and gradient computation to a sparse subset of pixels per tile, guided by persistent error and age maps. It solves the problem of redundant gradient computation in well-reconstructed regions by reallocating computation to perceptually informative pixels. Unlike sibling methods that optimize rendering pipelines or data compression, Err-SPS specifically accelerates the optimization phase by sparsifying the pixel-level supervision signal.

### [DashGaussian](15742-dashgaussian.md)
DashGaussian is a scheduling scheme for 3D Gaussian Splatting (3DGS) optimization that accelerates training by progressively fitting Gaussians to higher frequency components and synchronizing primitive growth with rendering resolution. It reformulates optimization as a frequency component fitting task, cooperatively allocating rendering resolution and primitive count to strip redundant complexity. Unlike vanilla 3DGS or methods with concave-down growth curves, DashGaussian produces a concave-up primitive growth curve spanning the entire optimization process, yielding fewer primitives and faster convergence while preserving or improving rendering quality.

### [Frequency Guided Resolution Scheduler](15751-frequency-guided-resolution-scheduler.md)
A strategy to schedule rendering resolution throughout optimization by distributing steps based on frequency energy, reducing optimization complexity. It sets itself apart from naive multi-resolution training by calculating a switch point based on the ratio of low-frequency energy to total energy, ensuring that high-resolution optimization only begins after the model has sufficiently captured the scene's low-frequency structure.

### [Inverse and Internal Rendering](15764-inverse-and-internal-rendering.md)
Inverse and Internal Rendering extends 3D Gaussian Splatting beyond surface reconstruction to estimate physical scene properties (lighting, material) from unknown illumination [14852-gs-ir.md] and to reconstruct internal volumetric structures from sparse, pose-free data [15745-inner-3d-gaussian-splatting.md]. Unlike standard 3DGS which optimizes for camera-visible surfaces, this family addresses occluded interiors and implicit volumetric density, solving the failure of projection-based methods on non-surface data and the lack of native normal/material attributes in standard splatting.

### [Neural SDF Inference via Gaussian Pulling](15776-neural-sdf-inference-via-gaussian-pulling.md)
Neural SDF Inference via Gaussian Pulling (often referred to as GS-Pull) is a method for reconstructing continuous 3D geometry from multi-view RGB images by jointly optimizing a set of 3D Gaussians and a neural Signed Distance Function (SDF). It solves the problem of inferring accurate surface geometry from 3D Gaussian Splatting (3DGS), which typically suffers from discrete, sparse, and off-surface Gaussian distributions that do not naturally represent continuous surfaces. Unlike standard 3DGS which renders color directly, or methods that add separate volume rendering branches, this approach dynamically aligns Gaussians to the SDF's zero-level set via a differentiable "pulling" operation and constrains them to be thin disks tangent to the surface, enabling robust surface extraction using marching cubes.

### [Multi-View Regulated Gaussian Splatting](15783-multi-view-regulated-gaussian-splatting.md)
Multi-View Regulated Gaussian Splatting (MVGS) is a training optimization strategy for 3D Gaussian Splatting that imposes multi-view coherent (MVC) constraints throughout the optimization process to enhance multi-view consistency and ensure smoother gradient updates. It addresses the unstable gradients and suboptimal rendering quality caused by the single-view optimization paradigms typical in existing Gaussian-based methods. Unlike single-view training where only partial Gaussians are updated and gradients may conflict with physical restrictions, MVGS jointly updates 3D Gaussians observed by multiple views, leading to stable gradients and better performance.

### [Gaussian Frosting](15863-gaussian-frosting.md)
Gaussian Frosting is a mesh-based radiance field representation that augments a base triangle mesh with an adaptive layer of 3D Gaussians, termed the "Frosting," to capture fine volumetric details such as hair or grass while maintaining the editability of a surface mesh. It solves the inefficiency of unconstrained densification in fuzzy areas and the loss of volumetric quality in surface-only methods by allowing users to specify a fixed Gaussian budget ($N$) and adapting the layer thickness locally to material properties. Unlike SuGaR, which flattens Gaussians onto the mesh surface, Frosting preserves rendering quality for complex materials by maintaining a variable-thickness layer.

### FisherRF
FisherRF is a method for active view selection and uncertainty quantification in Radiance Fields that directly quantifies observed information on model parameters using Fisher Information, selecting candidate views by maximizing Expected Information Gain (EIG) [S1]. It sets itself apart from sibling methods like [SOGS](13171-sogs-second-order-anchor-for-advanced-3d-gaussian-splatting.md) or [Gaussian Frosting](15863-gaussian-frosting.md) by focusing on the *selection* of new training views rather than just optimizing existing parameters, leveraging the sparsity of the Hessian to achieve real-time evaluation speeds (70 fps) [S1].

### [SpacetimeGaussians Training Pipeline](15898-spacetimegaussians-training-pipeline.md)
The SpacetimeGaussians training pipeline is a specific optimization schedule and implementation strategy for training dynamic 3D Gaussian splats, extending the static [3D Gaussian Splatting](9128-3d-gaussian-splatting-implementation-details.md) method to handle temporal variations. It solves the problem of real-time dynamic view synthesis by integrating motion parameters into the Gaussian attributes and applying a structured densification, pruning, and freezing schedule to stabilize training. It is distinguished from its siblings by its explicit handling of time-dependent Gaussians, specific regularization terms for motion gradients, and a multi-channel rendering pipeline that supports both full and lite configurations.

### [Feature 3D Gaussian Splatting](15902-feature-3d-gaussian-splatting.md)
Feature 3D Gaussian Splatting is a feature field distillation technique based on the 3D Gaussian Splatting framework that enables the rendering of arbitrary-dimensional semantic features by learning a semantic feature vector at each 3D Gaussian, in addition to color information, guided by 2D foundation models. Unlike NeRF-based methods that use two distinct branches of MLPs to output color and feature separately, Feature 3DGS uses explicit point-based 3D representation with parallel rasterization, achieving up to 2.7× faster distillation and rendering.

## Operating characteristics

### Time and Memory Complexity
*   **Time**: The training time is dominated by the differentiable rasterization and gradient computation, which scales linearly with the number of Gaussians and pixels [S9, unofficial]. The GEMM-GS acceleration provides a 1.42× speedup over vanilla 3DGS [S16].
*   **Memory**: Memory usage scales with the number of Gaussians and their attributes. For SH degree 1, each Gaussian requires 3 (pos) + 4 (rot) + 3 (scale) + 1 (opacity) + 12 (color) = 23 floats. For millions of Gaussians, this can exceed 1GB [12927-compact-3d-gaussian-representation-c3dgs.md].

### Measured Performance
*   **Hardware**: Tested on GPUs with Tensor Cores (e.g., NVIDIA A100, RTX 4090) [S16].
*   **Resolution**: Performance is measured at various resolutions, with 16x16 tiles being a common block size for parallelization [S16].
*   **Scene**: Tested on standard datasets like Mip-NeRF 360 and Tanks & Temples [S4, S16].

### Scaling
*   **Large Scenes**: Methods like TraGraph-GS and Distributed Training address scalability to large scenes by partitioning the scene or sharding the Gaussian population [S7, S15108-distributed-training-and-sharding.md].
*   **High Resolution**: Frequency-guided resolution schedulers and error-guided sparse sampling help manage the computational cost of high-resolution rendering [S15751-frequency-guided-resolution-scheduler.md, S15708-error-guided-sparse-pixel-sampling.md].

### Strengths and Limitations
*   **Strengths**: Real-time rendering, high fidelity, explicit representation [S9, unofficial].
*   **Limitations**: High memory usage, sensitivity to initialization, potential for artifacts in sparse-view scenarios [S6, S12927-compact-3d-gaussian-representation-c3dgs.md].

### When to Use
*   Use when real-time rendering and high visual fidelity are required.
*   Use when the scene can be captured with sufficient overlap and lighting consistency.

### When Not to Use
*   Avoid for scenes with extreme sparsity of views without additional denoising or regularization [S6].
*   Avoid for scenes with significant transient occluders unless using methods like DeSplat [S1].

## Background

### Origin
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1]. It represents a scene as a set of 3D Gaussians and uses differentiable rasterization for training and rendering.

### History and Development
Since its introduction, numerous methods have been developed to improve its efficiency, fidelity, and applicability, including acceleration techniques (GEMM-GS), densification schedules (DashGaussian), and extensions to dynamic scenes (SpacetimeGaussians) [S16, S13, S15898-spacetimegaussians-training-pipeline.md].

### Where it is Used
3DGS is used in computer vision, graphics, and robotics for novel view synthesis, 3D reconstruction, and augmented reality [S9, unofficial][S15].
