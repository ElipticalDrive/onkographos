# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, GSGEN Implementation Details, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific hyperparameters, optimization schedules, and engineering configurations required to implement the 3D Gaussian Splatting (3DGS) training pipeline. It addresses the problem of translating the theoretical differentiable rendering framework into a stable, convergent optimization process. It sets itself apart from general optimization theory by providing concrete thresholds for densification, pruning, and loss weighting, as well as hardware-specific implementation strategies like half-precision rasterization.

## How it works
The training process optimizes a set of 3D Gaussians $\mathcal{G}$ to minimize the difference between rendered images and ground-truth photographs. The core loop involves rendering, loss computation, gradient propagation, and adaptive densification/pruning.

### Inputs and Outputs
*   **Inputs:** A set of $N$ calibrated images with known camera poses $\{C_i\}$, an initial point cloud (e.g., from SfM), and hyperparameters for optimization.
*   **Outputs:** A final set of optimized 3D Gaussians $\mathcal{G}_{final}$, each defined by position $\mathbf{t}$, rotation $\mathbf{q}$, scale $\mathbf{s}$, opacity $\alpha$, and spherical harmonic coefficients $\mathbf{c}$.

### Data Structures
The Gaussian set $\mathcal{G}$ is typically stored in a flat array or structure-of-arrays (SoA) format for efficient GPU access. Each Gaussian $j$ contains:
*   $\mathbf{t}_j \in \mathbb{R}^3$: World-space position.
*   $\mathbf{q}_j \in \mathbb{R}^4$: Unit quaternion for rotation.
*   $\mathbf{s}_j \in \mathbb{R}^3$: Scale vector (often exponentiated during storage to ensure positivity).
*   $\alpha_j \in [0, 1]$: Opacity.
*   $\mathbf{c}_j$: Spherical Harmonic coefficients (dimension depends on degree $D$).

### Training Loop Steps
1.  **Initialization:** Initialize Gaussians from the SfM point cloud. Set initial scales based on the local point density or a fixed value. [S4]
2.  **Random View Selection:** For each iteration, randomly select one training image and its corresponding camera pose. [S3]
3.  **Rasterization:** Render the selected view using the differentiable rasterizer. This involves projecting 3D Gaussians to 2D, sorting them by depth, and alpha-blending. [S9, unofficial]
4.  **Loss Computation:** Compute the loss $\mathcal{L}$ between the rendered image and the ground-truth image. The standard loss is a weighted combination of L1 loss and D-SSIM:
    $$ \mathcal{L} = (1 - \lambda)\mathcal{L}_1 + \lambda\mathcal{L}_{\text{SSIM}} $$
    where $\lambda \approx 0.2$. [S9, unofficial]
5.  **Backpropagation:** Compute gradients $\nabla_{\mathcal{G}} \mathcal{L}$ with respect to all Gaussian parameters. [S9, unofficial]
6.  **Optimization Step:** Update Gaussian parameters using an optimizer (typically Adam). [S3]
7.  **Densification (Periodic):** Every $K_{split}$ iterations, split or clone Gaussians based on gradient magnitude and opacity. [S1]
8.  **Pruning (Periodic):** Every $K_{prune}$ iterations, remove Gaussians with low opacity or excessive size. [S1]

### Densification and Pruning Parameters
*   **Splitting:** Split Gaussians if the view-space position gradient exceeds a threshold $T_{pos}$. [S1]
    *   $T_{pos} = 0.02$. [S1]
    *   Frequency: Every 500 iterations. [S1]
*   **Compactness Densification:** Perform compactness-based densification to ensure complete geometry. [S1]
    *   Frequency: Every 1000 iterations. [S1]
*   **Pruning:** Remove Gaussians if:
    *   Opacity $\alpha < \alpha_{min}$. [S1]
        *   $\alpha_{min} = 0.05$. [S1]
    *   World-space or view-space radius is excessively large. [S1]
    *   Frequency: Every 200 iterations. [S1]

### Optimization Configuration
*   **Optimizer:** Adam. [S3]
*   **Learning Rate:** $1 \times 10^{-3}$. [S3]
*   **Iteration Budget:** Training typically runs for a fixed number of iterations, commonly around 30,000. [S9, unofficial]
*   **Spherical Harmonics (SH) Degree:** Often set to 1 for simplicity or computational efficiency. [S3]

### Engineering Implementation Details
*   **Library:** The `gsplat` library is commonly used for the rasterization pipeline. [S3]
*   **Half-Precision:** Use half-precision (FP16) memory fetches on feature vectors during rasterization for both forward and backward kernels to reduce register pressure. [S2]
*   **MLP Training:** Use JIT-compiled cooperative vector MLPs (e.g., via `tiny-cuda-nn`) trained and evaluated in FP16. [S2]
*   **Loss Scaling:** Apply an automatic scaling factor to loss values to improve half-precision training stability. [S2]

### Pseudocode
```python
def train_3dgs(images, poses, initial_gaussians, num_iterations=30000):
    gaussians = initial_gaussians
    optimizer = Adam(gaussians.parameters(), lr=1e-3)
    
    for iteration in range(1, num_iterations + 1):
        # 1. Random View Selection
        idx = random.randint(0, len(images) - 1)
        image = images[idx]
        pose = poses[idx]
        
        # 2. Rasterization
        rendered_image = rasterize(gaussians, pose)
        
        # 3. Loss Computation
        loss = compute_loss(rendered_image, image, lambda_ss=0.2)
        
        # 4. Backpropagation and Optimization
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        
        # 5. Densification (Every 500 iterations)
        if iteration % 500 == 0:
            gaussians = densify(gaussians, threshold=0.02)
            
        # 6. Compactness Densification (Every 1000 iterations)
        if iteration % 1000 == 0:
            gaussians = compactness_densify(gaussians)
            
        # 7. Pruning (Every 200 iterations)
        if iteration % 200 == 0:
            gaussians = prune(gaussians, alpha_min=0.05)
            
    return gaussians
```

## Subtopics

### Corrected Scene-Extent
A method to calculate scene extent based on the SfM point cloud rather than camera positions to avoid bias from camera distribution (e.g., orbiting a small object in a large environment) [S4]. The default 3DGS scene extent $e_{\text{scene}}$ is proportional to the distance of the furthest camera from the average camera position, causing bias if cameras are clustered [S4]. The corrected scene extent is:
$$ e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2 $$
where $N_{\text{SfM}}$ is the number of SfM points, $\bar{C}$ is the averaged camera position, and $p_i$ is the i-th SfM point [S4].

### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ to selectively enlarge covariances, creating pixel-wise variable blur kernels that match spatially varying scene blurriness [S5]. A naive Gaussian blur applies a single kernel to the whole image, while this method predicts per-Gaussian offsets, enabling spatially varying blur shapes and magnitudes [S5]. If $\delta s_j$ is predicted as a constant for all Gaussians, it degrades to a uniform Gaussian blur over the entire image [S5].

### Denoise-GS
A self-supervised denoising method for sparse-view 3D Gaussian Splatting that combines unsupervised image denoising with explicitly differentiable 3DGS [S6]. It uses Noise2Void (N2V) in two rounds: Round 1 trains a UNet for denoising, processes denoised images through InstantSplat to initialize/train 3DGS, and filters rendered results. Round 2 fine-tunes the UNet with a composite loss and renders again [S6]. Unlike supervised methods, it requires no paired clean data and is robust to uncertain noise patterns [S6].

### Multi-Scale Constraint
A technique using position-aware point adaptive control to apply different scales to Gaussians based on viewer distance, improving rendering of distant objects [S7]. It uses a scale factor $\gamma(\mu)$ based on distance from camera center $c$ and scene radius $r$:
$$ \gamma(\mu) = \begin{cases} 1 & \text{if } \|\mu - c\|^2 < 2r \\ \|\mu - c\|^2 / r - 1 & \text{if } \|\mu - c\|^2 \ge 2r \end{cases} $$
Cloning occurs if $\max(s) < g \cdot \gamma(\mu)$, splitting if $\max(s) \ge g \cdot \gamma(\mu)$, and elimination if $\max(s) > b \cdot \gamma(\mu)$, where $g$ and $b$ are scale threshold parameters [S7].

### LS-Gaussian Viewpoint Transformation
An algorithm that leverages inter-frame continuity for efficient sparse rendering by transforming the viewpoint between consecutive frames, rather than rendering each frame separately [S8]. It operates at the tile/Gaussian level to enable sparse rendering, unlike naive pixel warping which fails to reduce preprocessing costs [S8]. Rendering quality degrades noticeably as the number of consecutively transformed frames increases due to the accumulation of interpolation errors [S8]. It is used in LS-Gaussian to enable sparse rendering where only one frame in every 6 frames is fully rendered [S8].

### 3D Gaussian Splatting Training Loop
Per-image error compares one render against one photo. Scene-wide error is the loss averaged across all training views, used to monitor overall progress [S9, unofficial]. The loop consists of: 1. Pick one input photo randomly. 2. Render the current set of Gaussians from the known camera pose. 3. Compare the render against the original photo pixel-by-pixel to compute an error metric. 4. Use the error to compute gradients and nudge every Gaussian's parameters to reduce the error. 5. Repeat for tens of thousands of iterations [S9, unofficial]. Unlike random search, this method uses gradient descent to compute the actual downhill direction for the error surface [S9, unofficial].

### Camera Localisation for Convergence Basin
Localize camera pose by minimizing only the photometric error against the ground-truth colour image of the target view. Fix $G_{init}$ during optimization. Initialize $T_{CW}$ at one of the test view's positions. Perform optimization for 1000 iterations. Localisation is successful if the estimated pose converges to within 1cm of the target view within the 1000 iterations [S10, unofficial]. The estimated pose $T_{CW}^{est}$ is found by:
$$ \mathbf{T}_{CW}^{est} = \underset{\mathbf{T}_{CW}}{\arg \min} \left\| I(\mathcal{G}_{init}, \mathbf{T}_{CW}) - \bar{I}_{target} \right\|_1 $$
[S10, unofficial].

### DiffGS Framework
Applies an optimization process during Gaussian extraction to optimize Gaussians to exact locations [S11]. It introduces a truncation function $\lambda$ when modeling GauPF (Gaussian Probability Function) and a projection function $\tau$ implemented as $\tau(x) = e^{-x}$ or linear [S11]. With 50K Gaussians, it achieves PSNR 28.61, SSIM 0.9787, LPIPS 0.0251. With 100K Gaussians, PSNR 30.35, SSIM 0.9838, LPIPS 0.0151. With 350K Gaussians, PSNR 34.01, SSIM 0.9879, LPIPS 0.0149 [S11].

### Opacity Offset Table for DSA
A method that constructs an opacity offset table to model changes in digital subtraction angiography [S12].

### Resolution Guided Primitive Scheduler
Uses a formula to control primitive growth:
$$ P_{fin}^{(i)} = \max(P_{fin}^{(i-1)}, \gamma \cdot P_{fin}^{(i-1)} + \eta \cdot P_{add}) $$
where $P_{add}$ is the number of primitives densified in step $i$, and $P_{fin}^{(0)}$ is initialized as $5 \cdot P_{init}$ [S13]. The power factor starts at 2 and decreases to 1. Hyperparameter $\gamma$ (momentum decay) defaults to 0.98, and $\eta$ (force scaling) defaults to 1 [S13]. Too much primitive growth at the end of optimization results in poor convergence, mitigated by the concave-up scheduling function [S13].

### Conditional Splat Approximation
A technique to approximate the influence range of a 3D Gaussian on a slice by using a 2D ellipse splat scaled by the marginal factor, which closely matches the true iso-probability contours [S14, unofficial]. Qualitative validation shows that the conditional splat approximation closely overlaps with the true 3D Gaussian iso-probability contours [S14, unofficial].

### Deformation-Aware Pruning
A pruning technique that identifies and removes redundant Gaussians by gauging their impact on deformation, distinguishing between stable and deformed Gaussians [S15].

## Operating characteristics
*   **Time Complexity:** The training time is dominated by the rasterization and backpropagation steps, which scale with the number of Gaussians and image resolution. The fixed iteration budget (e.g., 30,000) provides a predictable training duration [S9, unofficial].
*   **Memory Complexity:** Memory usage scales linearly with the number of Gaussians. Half-precision rasterization reduces register pressure and memory bandwidth requirements [S2].
*   **Performance:** The use of `gsplat` and custom CUDA kernels enables real-time rendering during training [S3]. Half-precision training improves stability and speed [S2].
*   **Strengths:** The method is efficient, scalable, and produces high-quality results. The adaptive densification and pruning strategies ensure that the Gaussian representation is optimized for the scene complexity [S1].
*   **Limitations:** The method is sensitive to hyperparameters such as $T_{pos}$, $\alpha_{min}$, and the iteration budget. Incorrect scene extent calculation can lead to poor densification and pruning [S4].

## Background
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 as a real-time explicit 3D representation. The implementation details described here are based on the original paper and subsequent refinements and variations [S1, S3][S9, unofficial]. The method has been widely adopted and extended in various domains, including text-to-3D generation [S1], large-scale scene rendering [S7], and dynamic scene reconstruction [S15].
