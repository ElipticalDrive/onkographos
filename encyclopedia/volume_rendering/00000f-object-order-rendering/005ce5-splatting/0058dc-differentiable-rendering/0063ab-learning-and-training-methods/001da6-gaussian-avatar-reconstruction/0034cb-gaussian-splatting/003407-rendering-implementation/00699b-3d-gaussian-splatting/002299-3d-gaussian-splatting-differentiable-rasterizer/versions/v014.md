# 3D Gaussian Splatting Differentiable Rasterizer

Also called: 3D Gaussian Rasterization and Rendering, 3DGS Renderer, 3DGS rasterization pipeline, Differentiable Gaussian Rasterization, differentiable splatting

## Overview
The 3D Gaussian Splatting Differentiable Rasterizer is a screen-space rendering method that projects a set of 3D Gaussian primitives into 2D ellipses and alpha-composites them to produce an RGB image, while simultaneously computing exact gradients for all Gaussian parameters (position, scale, rotation, opacity, color) with respect to the pixel loss [S3][S12, unofficial]. It differs from volumetric ray-marching methods like NeRF by using discrete, point-based alpha blending in image space, which allows for real-time rendering speeds and efficient gradient propagation without the need for expensive ray sampling [S7][S10, unofficial]. Unlike standard OpenGL rasterizers, it is fully differentiable with respect to camera parameters and Gaussian attributes, enabling end-to-end optimization of the scene representation [S11, S12, unofficial].

## How it works
**Inputs and Outputs**
*   **Inputs:**
    *   `means3D`: Tensor of shape $(N, 3)$ containing 3D positions [S11, unofficial].
    *   `cov3D_precomp` (or `scales` $(N, 3)$ and `rotations` $(N, 4)$): 3D covariance matrices or their decomposition [S11, unofficial].
    *   `opacities`: Tensor of shape $(N,)$ containing scalar opacity values [S11, unofficial].
    *   `colors`: Tensor of shape $(N, 3)$ for view-independent color or $(N, C)$ for Spherical Harmonics (SH) coefficients [S9, S11, unofficial].
    *   `camera_params`: View matrix $V \in \mathbb{R}^{4 \times 4}$, Projection matrix $P \in \mathbb{R}^{4 \times 4}$ (or intrinsics $K$ and camera position), image dimensions $(H, W)$, and field of view tangents `tanfovx`, `tanfovy` [S6, S9, unofficial].
    *   `background`: Tensor of shape $(3)$ for the background color [S9, unofficial].
*   **Outputs:**
    *   `rendered_image`: Tensor of shape $(H, W, 3)$ [S9, unofficial].
    *   `rendered_opacity`: Tensor of shape $(H, W)$ [S9, unofficial].
    *   `radii`: Tensor of shape $(N)$ indicating the radius of each Gaussian in pixels (used for culling) [S9, unofficial].
    *   Gradients for all input tensors with respect to the loss [S5, S12, unofficial].

**Data Structures**
The rasterizer typically operates on a tiled basis (e.g., $16 \times 16$ tiles) to optimize memory access and sorting [S11, unofficial].
*   `GaussianRasterizationSettings`: A configuration struct containing `image_height`, `image_width`, `tanfovx`, `tanfovy`, `cx`, `cy`, `bg`, `scale_modifier`, `viewmatrix`, `projmatrix`, `sh_degree`, `campos`, `prefiltered`, `backward_geometry`, `computer_pseudo_normal`, and `debug` flags [S6, S9, unofficial].
*   `geomBuffer`, `binningBuffer`, `imgBuffer`: Intermediate buffers used in the CUDA implementation to store Gaussian indices, tile assignments, and pixel contributions [S6, unofficial].
*   `ctx->saved_data`: In the CPU/PyTorch autograd context, this stores `px2gid` (pixel-to-Gaussian ID map, cast to `int64_t`), `imgWidth`, `imgHeight`, `errorMap`, `edgeMap`, `densificationInfo`, `xyAbsGrad`, and the input tensors `xys`, `conics`, `colors`, `opacity`, `background`, `cov2d`, `camDepths`, `finalTs` for backward pass reconstruction [S5, unofficial].

**Steps**

1.  **Projection:** Project each 3D Gaussian from world space to camera space, then to screen space.
    *   Transform mean $\mu$ to camera space: $\mu_{cam} = V \mu$.
    *   Project to 2D screen coordinates $(x, y)$ using the projection matrix $P$ or intrinsic parameters:
        $$ x = \frac{P_{00} \mu_{cam,x} + P_{01} \mu_{cam,y} + P_{02} \mu_{cam,z} + P_{03}}{P_{20} \mu_{cam,x} + P_{21} \mu_{cam,y} + P_{22} \mu_{cam,z} + P_{23}} $$
        $$ y = \frac{P_{10} \mu_{cam,x} + P_{11} \mu_{cam,y} + P_{12} \mu_{cam,z} + P_{13}}{P_{20} \mu_{cam,x} + P_{21} \mu_{cam,y} + P_{22} \mu_{cam,z} + P_{23}} $$
        [S10, S11, unofficial].
    *   Compute the 2D covariance matrix $\Sigma_{2D}$ in screen space. This involves the Jacobian $J$ of the projection transformation and the 3D covariance $\Sigma_{3D}$:
        $$ \Sigma_{2D} = J W \Sigma_{3D} W^T J^T $$
        where $W$ is the view rotation matrix and $J$ is the $2 \times 3$ Jacobian of the perspective projection [S11, S12, unofficial].
    *   Apply a scale modifier if specified [S9, unofficial].

2.  **Bounding Box and Culling:**
    *   Compute the axis-aligned bounding box (AABB) for each 2D Gaussian, typically covering the $3\sigma$ ellipse (99% percentile) [S11, unofficial].
    *   Frustum cull Gaussians that do not intersect the image plane or have zero radius [S9, unofficial].
    *   Bin visible Gaussians into $16 \times 16$ tiles based on their AABB intersection [S11, unofficial].

3.  **Sorting:**
    *   Sort Gaussians within each tile by their depth ($z$-coordinate in camera space) in front-to-back order [S3][S11, unofficial].

4.  **Rasterization (Alpha Compositing):**
    *   For each pixel $(u, v)$ in the image:
        *   Initialize transmittance $T = 1.0$ and accumulated color $C = \text{background}$ [S10, unofficial].
        *   Iterate through the sorted list of Gaussians $i$ overlapping the pixel:
            *   Compute the displacement vector $d$ from the pixel center to the Gaussian mean $\mu_{2D}$: $d = [u - \mu_{2D,x}, v - \mu_{2D,y}]^T$ [S10, unofficial].
            *   Compute the exponent for the 2D Gaussian density:
                $$ \text{power} = -0.5 \cdot d^T \Sigma_{2D}^{-1} d = -0.5 (d_x^2 \Sigma_{2D,00}^{-1} + d_y^2 \Sigma_{2D,11}^{-1} + 2 d_x d_y \Sigma_{2D,01}^{-1}) $$
                [S10, unofficial].
            *   Compute the opacity contribution $\alpha_i$:
                $$ \alpha_i = o_i \cdot \exp(\text{power}) $$
                Clamp $\alpha_i$ to a maximum value (e.g., 0.99) to prevent numerical instability [S10, unofficial].
            *   Update transmittance and color:
                $$ C = C + c_i \cdot \alpha_i \cdot T $$
                $$ T = T \cdot (1 - \alpha_i) $$
                where $c_i$ is the color of the $i$-th Gaussian (evaluated from SH if applicable) [S3][S10, unofficial].
            *   If $T < \epsilon$ (e.g., $10^{-4}$), break the loop early [S11, unofficial].
        *   Store $C$ as the final pixel color and $1 - T$ as the final opacity [S5, unofficial].

5.  **Backpropagation:**
    *   Compute gradients of the loss with respect to the output image.
    *   Propagate gradients back through the alpha compositing loop to compute gradients for $\alpha_i$ and $c_i$ [S12, unofficial].
    *   Compute gradients for the 2D means ($\mu_{2D}$) and covariance ($\Sigma_{2D}$) using the chain rule on the Gaussian density function [S10, unofficial].
    *   Propagate gradients from screen space to 3D space using the Jacobian $J$ and the projection transformation [S11, unofficial].
    *   Compute gradients for 3D means, scales, rotations, opacities, and SH coefficients [S5, S12, unofficial].

**Pseudocode**

```python
import torch
import math

def rasterize_gaussians(means3D, cov3D_precomp, opacities, colors, shs, 
                        viewmatrix, projmatrix, tanfovx, tanfovy, 
                        bg, scale_modifier, image_height, image_width, sh_degree):
    """
    Simplified differentiable rasterization of 3D Gaussians.
    Note: This is a conceptual implementation. Production versions use CUDA kernels.
    """
    N = means3D.shape[0]
    H, W = image_height, image_width
    
    # 1. Project 3D Gaussians to 2D
    # Transform means to camera space
    means_cam = torch.matmul(viewmatrix[:3, :3], means3D.t()).t() + viewmatrix[:3, 3]
    
    # Project to screen space (simplified perspective projection)
    # Assuming standard pinhole camera for simplicity; real impl uses full projmatrix
    z = means_cam[:, 2]
    x = means_cam[:, 0] / z
    y = means_cam[:, 1] / z
    
    # Convert to pixel coordinates
    # cx, cy are principal points, fx, fy are focal lengths derived from tanfovx/fov
    # For brevity, assuming identity intrinsics scaled by tanfovx/fov
    means2D = torch.zeros(N, 2, device=means3D.device)
    means2D[:, 0] = x * (W / 2) / tanfovx + W / 2
    means2D[:, 1] = y * (H / 2) / tanfovy + H / 2
    
    # 2. Compute 2D Covariance
    # Jacobian of projection J
    # J = d(x,y)/d(X,Y,Z)
    # For perspective: dx/dX = 1/Z, dx/dZ = -X/Z^2
    J = torch.zeros(N, 2, 3, device=means3D.device)
    J[:, 0, 0] = 1.0 / z
    J[:, 0, 2] = -means_cam[:, 0] / (z * z)
    J[:, 1, 1] = 1.0 / z
    J[:, 1, 2] = -means_cam[:, 1] / (z * z)
    
    # Transform 3D covariance to camera space
    # cov3D_precomp is (N, 3, 3)
    cov_cam = torch.matmul(viewmatrix[:3, :3], torch.matmul(cov3D_precomp, viewmatrix[:3, :3].t()))
    
    # Project to 2D: Sigma_2D = J * cov_cam * J^T
    cov2D = torch.matmul(J, torch.matmul(cov_cam, J.transpose(1, 2)))
    
    # 3. Sort by depth
    # Sort indices by z descending (back-to-front for alpha compositing logic, 
    # but rasterizer usually iterates front-to-back)
    sorted_indices = torch.argsort(z, descending=True)
    
    # 4. Rasterize
    out_img = bg.unsqueeze(0).unsqueeze(0).expand(H, W, 3).contiguous()
    out_alpha = torch.zeros(H, W, device=bg.device)
    
    # Initialize transmittance buffer
    T = torch.ones(H, W, device=bg.device)
    
    # Iterate over Gaussians (in a real CUDA kernel, this is tiled and parallelized)
    for idx in sorted_indices:
        mu = means2D[idx]
        cov = cov2D[idx]
        opac = opacities[idx]
        
        # Compute inverse covariance
        det = cov[0, 0] * cov[1, 1] - cov[0, 1] * cov[1, 1] # Bug in source? Should be cov[0,1]*cov[1,0]
        # Correct inverse for 2x2 symmetric matrix
        inv_det = 1.0 / (cov[0, 0] * cov[1, 1] - cov[0, 1] * cov[1, 1]) # Note: cov[0,1]==cov[1,0]
        inv_cov = torch.zeros(2, 2, device=bg.device)
        inv_cov[0, 0] = cov[1, 1] * inv_det
        inv_cov[1, 1] = cov[0, 0] * inv_det
        inv_cov[0, 1] = -cov[0, 1] * inv_det
        inv_cov[1, 0] = -cov[1, 0] * inv_det
        
        # Get color (simplified: no SH)
        color = colors[idx]
        
        # Compute bounding box for this Gaussian to limit pixel iteration
        # Approximate radius as 3*sqrt(max_eigenvalue)
        # For simplicity, iterate all pixels (inefficient, but correct for pseudocode)
        # In practice, only iterate pixels within the AABB
        
        # Create grid of pixel coordinates
        y_coords, x_coords = torch.meshgrid(torch.arange(H, device=bg.device), 
                                            torch.arange(W, device=bg.device), 
                                            indexing='ij')
        pixel_centers = torch.stack([x_coords.float(), y_coords.float()], dim=-1)
        
        # Displacement vector
        d = pixel_centers - mu # (H, W, 2)
        
        # Power = -0.5 * d^T * inv_cov * d
        # d^T * inv_cov
        d_inv = torch.einsum('hwk,kj->hwj', d, inv_cov)
        power = -0.5 * torch.einsum('hwk,hwk->hw', d_inv, d)
        
        # Alpha
        alpha = torch.clamp(opac * torch.exp(power), max=0.99)
        
        # Update image
        # out_img = out_img + color * alpha * T
        # T = T * (1 - alpha)
        
        # Vectorized update
        contribution = color.unsqueeze(-1).unsqueeze(-1) * alpha.unsqueeze(-1) * T.unsqueeze(-1)
        out_img = out_img + contribution
        T = T * (1 - alpha)
        
        # Accumulate opacity for output
        # out_alpha = 1 - T_final
        # We can compute this at the end or incrementally
        
    out_alpha = 1.0 - T
    return out_img, out_alpha
```

**Parameters**
*   `tanfovx`, `tanfovy`: Tangents of half the horizontal and vertical field of view. Derived from camera intrinsics [S9, unofficial].
*   `scale_modifier`: Scalar multiplier for Gaussian scales. Default 1.0 [S8, S9, unofficial].
*   `sh_degree`: Degree of Spherical Harmonics for color representation. Commonly 3 [S9, unofficial].
*   `prefiltered`: Boolean flag. If False, SH coefficients are not pre-filtered [S9, unofficial].
*   `lambda_dssim`: Weight for SSIM term in loss. Value not specified [S6, unofficial].
*   `lambda_opacity`: Weight for opacity mask loss. Enabled if > 0 [S6, unofficial].
*   `lambda_normal_render_depth`: Weight for normal consistency loss. Typical value 0.01 [S6, unofficial].

**Edge Cases and Pitfalls**
*   **Undefined Alpha Gradient:** If the alpha channel is not used in the loss function, `v_outAlpha` may be undefined during autograd. It must be initialized to `zeros_like(finalTs)` before backward computation [S5, unofficial].
*   **Culled Gaussians:** Gaussians that are frustum culled or have a radius of 0 are invisible and excluded from gradient updates. The `screenspace_points` tensor retains gradients only for visible Gaussians [S9, unofficial].
*   **Normalization at Boundaries:** The adjustment factor $\theta = 0.05$ ensures normalization occurs even if weights sum < 1 at boundaries, preventing derivative mismatches [S1].
*   **Memory Constraints:** Iterating over all Gaussians in a Python loop is slow and memory-intensive for large $N$. CUDA kernels are required for real-time performance [S10, unofficial].

## Subtopics

### [Gaussian Splat Rasterization (Vertex Shader)](3253-gaussian-splat-rasterization-vertex-shader.md)
This method implements the vertex shader stage of a GPU-based rasterizer for 3D Gaussian Splatting, transforming 3D Gaussian primitives into 2D screen-space ellipses for instanced rendering. It differs from fragment-based or compute-shader approaches by performing all geometric projection, covariance transformation, and ellipse basis computation within the vertex shader, passing only the final vertex positions and attributes to the rasterizer. It builds on [3D Gaussian Splatting Differentiable Rasterizer](2813-3d-gaussian-splatting-differentiable-rasterizer.md) by handling the specific data unpacking and frustum culling required for efficient vertex-driven splatting.

### [Opacity Rendering with SH Colors](7480-opacity-rendering-with-sh-colors.md)
This method performs a rendering pass that uses the model's actual opacity values and precomputes colors from Spherical Harmonics (SH) in Python before rasterization, allowing the rasterizer to use precomputed colors. It differs from rasterizers with built-in SH evaluation by deferring directional color computation to the Python host layer rather than evaluating SH inside the GPU kernel. The source code initializes the color tensor to ones, indicating that actual SH evaluation is expected to be performed externally or as a simplification in the provided snippet.

### [3D Gaussian Unscented Transform (3DGUT)](9154-3d-gaussian-unscented-transform-3dgut.md)
3D Gaussian Unscented Transform (3DGUT) is a rasterization-based rendering technique for 3D Gaussian particles that replaces the standard Elliptical Weighted Average (EWA) splatting formulation with the Unscented Transform (UT). It approximates 3D Gaussian particles using a set of sigma points to enable exact projection under arbitrary nonlinear camera projections, such as those with distortion or rolling shutter effects, while retaining the efficiency of rasterization. Unlike its sibling [3D Gaussian Splatting Differentiable Rasterizer](2813-3d-gaussian-splatting-differentiable-rasterizer.md), which relies on linearization via Jacobians, 3DGUT avoids Jacobian derivation and approximation errors by approximating the particle itself. This alignment with ray-tracing formulations also supports secondary rays for phenomena like reflections and refraction.

### [RoofGS Quadratic Form Expansion and Coefficient Folding](10258-roofgs-quadratic-form-expansion-and-coefficient-folding.md)
RoofGS Quadratic Form Expansion and Coefficient Folding is a rasterization optimization that expands the Gaussian quadratic form to separate pixel-dependent terms from Gaussian-dependent terms, allowing pixel coordinates to be hoisted out of the primitive loop and reducing instruction overhead in the innermost rendering loop. It sets itself apart from standard 3D Gaussian Splatting rasterization by pre-computing and folding opacity and scaling factors into the quadratic coefficients, enabling a streamlined FMA (Fused Multiply-Add) sequence for exponent evaluation.

### [Transmittance of Gaussian Splatting](10263-transmittance-of-gaussian-splatting.md)
This method establishes that the image formation model of Gaussian Splatting (alpha-blending) is equivalent to a ray-marching volumetric rendering model under assumptions of statistical independence and non-overlapping Gaussian primitives. It defines a continuous transmittance function and a view-dependent attenuation coefficient that yield the same color output as the standard discrete alpha-compositing rasterizer.

### [Rendering Pipeline and Configuration](11406-rendering-pipeline-and-configuration.md)
The Rendering Pipeline and Configuration family manages the data preparation, validation, and orchestration required to execute the differentiable 3D Gaussian Splatting rasterization kernel. It solves the problem of translating high-level scene representations (Gaussian parameters, camera matrices) into the specific tensor layouts and validation states required by the underlying CUDA backend. It sets itself apart from the rasterization kernel itself by handling the "plumbing": normalizing inputs, enforcing mutual exclusivity between parametric and precomputed representations, and configuring the `GaussianRasterizationSettings` that bridge the scene and the kernel [Parent].

### [Differentiable Backpropagation Mechanisms](11407-differentiable-backpropagation-mechanisms.md)
This family defines the mathematical and algorithmic mechanisms for computing gradients of the rendering loss with respect to 3D Gaussian parameters (position, scale, rotation, opacity, color) during the training of Gaussian Splatting models [G]. It solves the problem of enabling end-to-end optimization of scene representations by providing differentiable paths from the final pixel color to the underlying 3D attributes [G]. It differs from standard rasterization by explicitly deriving chain-rule gradients for alpha compositing and basis function evaluations, and from non-differentiable methods by supporting arbitrary gradient estimation strategies including per-splat parallelization and stochastic estimation [G].

### [Multi-view Mini-batch Rasterization](13386-multi-view-mini-batch-rasterization.md)
Multi-view mini-batch rasterization is a training strategy that renders multiple viewpoints simultaneously within a single mini-batch to reduce gradient variance and improve convergence speed. It modifies the standard 3D Gaussian Splatting (3DGS) rasterizer pipeline by introducing view-specific frustum culling and a composite sorting ID, allowing the rasterizer to process multiple camera views in parallel while significantly reducing memory consumption compared to naive multi-view rendering. Unlike single-view training, this method increases performance metrics (PSNR/SSIM) but introduces higher memory overhead and preprocessing time.

### [Rasterization Variant](17388-rasterization-variant.md)
This family defines the specific algorithmic variations of the differentiable rasterization pipeline used to render 3D Gaussians, extending the standard alpha-compositing logic of [3D Gaussian Splatting Differentiable Rasterizer](2813-3d-gaussian-splatting-differentiable-rasterizer.md). It addresses specialized requirements such as dynamic pruning gradients, X-ray physics, hybrid sigma fallbacks, and importance scoring, which the base rasterizer does not natively support.

### Gaussian Rasterization Kernel Fusion
This variant skips the concatenation of the two SH coefficient buffers (view-independent and view-dependent bands) and passes these buffers separately to the rasterization backend, fusing the concatenation into the rasterization kernel [S13, unofficial]. It also fuses the activation functions for the scales, rotations, and opacities of the Gaussians into the rasterizer to avoid PyTorch-related overhead, and fuses the gradient computations required for the added benefits during training [S13, unofficial].

### Isotropic Loss
A regularisation term applied during RGB-D optimization to prevent Gaussians from over-stretching along the viewing axis, particularly in textureless regions [S14, unofficial]. Standard rasterisation does not account for elongation along the viewing axis, causing Gaussians to over-stretch without isotropic regularisation [S14, unofficial]. On TUM RGB-D, ATE RMSE changes from 1.43 cm (w/o $E_{iso}$) to 1.47 cm (Ours). On Replica RGB-D, Ours achieves 2.25 cm average ATE RMSE. On TUM RGB-D, isotropic regularisation yields only marginal performance difference. On Replica RGB-D, it significantly improves camera tracking [S14, unofficial].

### Gaussian Normal Estimation
Deriving per-pixel normal estimates directly from the geometry of Gaussians during backpropagation, where adjustments to scale and rotation parameters update normal estimates without additional learnable parameters [S3]. Normals are transformed into camera space using the current camera transform and alpha-composited according to the rendering equation to provide a single per-pixel normal estimate: $\hat{\boldsymbol{N}} = \sum_{i \in N} \hat{\boldsymbol{n}}_i \alpha_i T_i$ [S3]. Incorrect normal orientation is handled by flipping the direction of normals at the beginning of training if the dot product between the current camera viewing direction and the Gaussian normal is negative [S3].

### Normal Prediction from Gaussians
Approximating the normal direction of a Gaussian using the axis with the minimum scaling coefficient, assuming Gaussians become flat, disc-like during optimization [S3]. Geometric normal for Gaussian $i$: $\hat{\boldsymbol{n}}_i = R \cdot \text{OneHot}(\arg\min(s_1, s_2, s_3))$, where $R \in SO(3)$ is the rotation matrix from quaternion $q$, and $s \in \mathbb{R}^3$ are scaling coefficients [S3].

### Parallel N-Dimensional Gaussian Rasterization
A point-based alpha-blending technique for rasterizing feature maps alongside RGB, maintaining matching sizes for both to mitigate inconsistent spatial resolution inherent in tile-based rasterization. Dimensions are flexible to adapt to various foundational models [S15]. Rasterize features using ParallelRasterizer with inputs X, C, Σ, A, F, V to produce rendered feature map Fs [S15]. If refinement step, iterate over Gaussians (x, q, c, α, f): if opacity α < ε or Gaussian is too large, remove it [S15].

### Simplified Gaussian Rasterization
Rasterizes Gaussians to compute accumulated weights and max counts without full color/SH evaluation [S16, unofficial]. Pack args (omits `flag_max_count`, includes `culling`), call `_C.rasterize_gaussians_simp(*args)`, return `color, radii, accum_weights_ptr, accum_weights_count, accum_max_count` [S16, unofficial].

### Depth-aware Gaussian Rasterization
Rasterizes Gaussians while computing depth, discriminants, and group indices for depth-based rendering [S16, unofficial]. Pack args (omits `flag_max_count`, includes `culling`), call `_C.rasterize_gaussians_depth(*args)`, return dict with keys: render, out_pts, rendered_depth, discriminants, gidx, accum_alpha [S16, unofficial].

## Operating characteristics
*   **Time Complexity:** The rasterization step is $O(N \cdot P)$ in a naive implementation, where $N$ is the number of Gaussians and $P$ is the number of pixels. However, with tiling and culling, the effective complexity is closer to $O(N + H \cdot W)$, as each pixel only processes overlapping Gaussians [S10, S11, unofficial].
*   **Memory Complexity:** $O(N + H \cdot W)$ for storing Gaussian parameters and intermediate buffers (transmittance, accumulated color) [S10, unofficial].
*   **Measured Performance:** The CUDA-based implementation achieves real-time rendering speeds (e.g., >100 FPS for 1080p) on modern GPUs, significantly faster than NeRF-based methods [S10, S12, unofficial].
*   **Strengths:** Real-time rendering, efficient gradient computation, high-quality novel view synthesis, explicit scene representation [S3][S10, unofficial].
*   **Limitations:** Memory-intensive for very large scenes (requires chunking or LOD), sensitive to initialization, may produce artifacts in textureless regions without regularization [S10, S14, unofficial].
*   **When to Use:** Real-time novel view synthesis, training of 3D Gaussian scenes from images, applications requiring differentiable rendering [S3][S10, unofficial].
*   **When Not to Use:** Scenes with extremely high geometric complexity requiring implicit representations, applications where memory is severely constrained without chunking support [S10, unofficial].

## Background
The 3D Gaussian Splatting Differentiable Rasterizer was introduced by Kerbl et al. in 2023 in the paper "3D Gaussian Splatting for Real-Time Radiance Field Rendering" [S11, unofficial]. It builds on the concept of Gaussian splatting from computer graphics [S1] and adapts it for differentiable neural rendering. The method was developed to address the slow rendering speeds of NeRF-based methods while maintaining high visual quality [S7][S10, unofficial]. It has since become a standard technique for 3D scene reconstruction and novel view synthesis [S3][S11, unofficial].
