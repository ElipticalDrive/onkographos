# Octree-GS / Scaffold-GS


## Overview
Scaffold-GS anchors scene content to a sparse voxel grid, using the grid as a scaffold to allocate Gaussians only in occupied regions, which naturally adapts to view distance and improves memory efficiency [S1, S3, unofficial]. Octree-GS builds an octree over the scene, associating each node with a merged Gaussian that summarizes the radiance and opacity of its children, enabling real-time rendering of massive datasets [S1, S3, unofficial]. Scaffold-GS uses anchor points to predict "neural" Gaussians on the fly via a small MLP, achieving approximately 5$\times$ less memory usage than vanilla 3DGS at the same quality [S2, S3, unofficial].

## How it works
**Inputs:** Sparse voxel grid (anchor positions), initial Gaussian parameters (or neural decoder weights), camera poses [G].
**Outputs:** Rendered image, optimized anchor/Gaussian parameters [G].

**Data Structures:**
1. **Anchor Grid:** A sparse voxel grid where each cell contains an "anchor." The anchor stores latent parameters or serves as an index for a neural decoder [G].
2. **Neural Decoder (Scaffold-GS):** A small Multi-Layer Perceptron (MLP) that takes anchor coordinates as input and outputs Gaussian parameters (position, covariance, opacity, spherical harmonics coefficients) [S2, S3, unofficial].
3. **Octree Nodes (Octree-GS):** Each node in the octree contains a merged Gaussian representing its children, allowing for hierarchical culling and LoD selection [S1, S3, unofficial].

**Steps:**
1. **Voxelization:** Input SfM points or scene bounds are voxelized to create the anchor grid [S4].
2. **Anchor Initialization:** Gaussians are initialized at anchor positions. In Scaffold-GS, the MLP is initialized to predict these Gaussians [S2, unofficial][S4].
3. **Neural Prediction (Scaffold-GS):** During rendering or training, the MLP decodes the anchor position into full Gaussian parameters [S2, S3, unofficial]. This reduces storage overhead by avoiding explicit parameter storage for every primitive [S3, unofficial].
4. **Hierarchical Aggregation (Octree-GS):** Gaussians are grouped into octree nodes. Each node stores a summary Gaussian. Rendering selects the appropriate LoD based on view distance [S1, S3, unofficial].
5. **Optimization:** Standard 3DGS densification and pruning strategies are applied to the anchors or the decoded Gaussians [G]. Scaffold-GS uses a volume regularization loss $L_{\text{vol}} = \sum_{i=1}^{N} \text{Prod}(s_i)$ to control Gaussian size, where $N$ is the number of Gaussians and $s_i$ represents the scale of the $i$-th Gaussian [S4].
6. **Rendering:** Gaussians are splatted. For Scaffold-GS, parameters are decoded on the fly [S2, S3, unofficial]. For Octree-GS, hierarchical culling is performed [S1, S3, unofficial].

**Parameters:**
* **Voxel Size:** 0.001 for anchor grid variants (Anchor-2D-GS, Anchor-3D-GS) [S4]. Intermediate levels may use 0.02 [S4].
* **Training Iterations:** 40k for small-scale scenes, 100k for large-scale scenes [S4].
* **Loss Weights:** L1=0.8, SSIM=0.2 for 3D-GS; Distortion=0.01, Normal=0.05 for 2D-GS; Volume regularization weight applied in Scaffold-GS [S4].

**Edge Cases:**
* **Precision:** Quantization of parameters (e.g., positions to 16-bit half, opacity to 8 bits) is often used in conjunction with these methods for compression [S3, unofficial].
* **Boundaries:** Anchor-based methods reduce redundancy at scene boundaries by not allocating Gaussians in empty space [S4].

## Subtopics

### Context-GS
A method that adopts context-aware approaches that explicitly model hierarchical relationships among anchors to enhance representational capacity, building on anchor-based representation [S1, unofficial].

### Anchor-2D-GS / Anchor-3D-GS
Modified versions of 2D-GS and 3D-GS that employ an anchor grid structure to organize Gaussian primitives more efficiently, reducing redundancy and storage overhead [S4]. They use a voxel size of 0.001 for the anchor grid [S4]. These variants achieve competitive rendering quality with fewer file storage than original methods, demonstrating that the anchor design organizes primitives more efficiently [S4].

## Operating characteristics
* **Memory:** Scaffold-GS uses approximately 5$\times$ less memory than vanilla 3DGS at the same quality [S2, unofficial]. Both methods provide large size reduction [S3, unofficial].
* **Performance:** Enables real-time rendering of very large datasets by naturally adapting to view distance and selecting relevant LoD [S1, S3, unofficial].
* **Strengths:** Efficient memory usage, natural LoD adaptation, better generalization to extrapolated views [S3, unofficial].
* **Limitations:** Requires neural decoding overhead for Scaffold-GS or complex tree traversal for Octree-GS [G].
* **Usage:** Used in CityGaussian for huge scenes [S2, unofficial].

## Background
These methods originated to handle large-scale scenes and avoid rendering millions of far-away, sub-pixel Gaussians [S1, S3, unofficial]. Scaffold-GS and Octree-GS address the memory and rendering bottlenecks of flat Gaussian lists by introducing hierarchical structures [S1, S3, unofficial]. Scaffold-GS is notably used in CityGaussian for massive urban scenes [S2, unofficial]. Context-GS and the Anchor-variants extend these concepts by adding context modeling and adapting to 2D/3D Gaussian representations [S1, unofficial][S4].
