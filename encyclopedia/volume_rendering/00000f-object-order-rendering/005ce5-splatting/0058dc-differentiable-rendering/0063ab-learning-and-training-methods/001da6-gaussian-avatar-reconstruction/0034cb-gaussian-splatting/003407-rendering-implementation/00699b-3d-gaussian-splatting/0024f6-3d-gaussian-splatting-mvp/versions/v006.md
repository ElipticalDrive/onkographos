# 3D Gaussian Splatting MVP

Also called: 3DGS MVP, pure PyTorch 3DGS

## Overview
3D Gaussian Splatting MVP is a self-contained, pure-PyTorch implementation of the core 3D Gaussian Splatting rendering algorithm, designed as a teaching reference rather than a production renderer [S1, unofficial]. It solves the problem of understanding the mathematical foundations of 3DGS by implementing the forward rasterization pipeline without custom CUDA kernels, relying entirely on standard PyTorch operations [S1, unofficial]. It sets itself apart from production implementations like [3D Gaussian Splatting Rendering (Software)](2805-3d-gaussian-splatting-rendering-software.md) by using explicit Python loops for rasterization and omitting optimizations such as tile-based sorting, spherical harmonics, and adaptive density control [S1, unofficial].

## How it works
The method implements the forward pass of 3D Gaussian Splatting, transforming a set of 3D Gaussians into a 2D image via camera projection and alpha compositing.

**Inputs and Outputs**
*   **Inputs:** A list of $N$ 3D Gaussians, each defined by mean position, scale, rotation, opacity, and color; camera parameters (intrinsics and extrinsics); image dimensions $(H, W)$.
*   **Outputs:** A rendered RGB image of size $(H, W, 3)$ and optionally depth/transmittance buffers.

**Data Structures**
Each Gaussian $i$ is parameterized by the following fields [S1, unofficial]:
*   `mean`: 3D vector $(x, y, z)$ in world space.
*   `scale`: 3D vector $(s_x, s_y, s_z)$ stored in log-space to ensure positivity.
*   `rotation`: Unit quaternion $(w, x, y, z)$.
*   `opacity`: Scalar $\alpha \in [0, 1]$.
*   `color`: 3D vector $(r, g, b)$.

The covariance matrix $\Sigma$ is constructed implicitly from scale and rotation to ensure it is symmetric positive semi-definite (PSD) [S1, unofficial]:
$$ \Sigma = R S S^T R^T $$
where $R$ is the rotation matrix derived from the unit quaternion, and $S = \text{diag}(e^{s_x}, e^{s_y}, e^{s_z})$ is the scale matrix [S1, unofficial].

**Algorithm Steps**
The rasterizer processes Gaussians in a loop for readability, rather than vectorizing over all pixels and Gaussians simultaneously [S1, unofficial].

1.  **World-to-Camera Transformation:** Transform the mean $\mu_i$ of each Gaussian from world space to camera space using the view matrix $W$ [S1, unofficial].
2.  **Covariance Transformation:** Transform the 3D covariance matrix $\Sigma_i$ into the camera frame:
    $$ \Sigma_{cam} = W \Sigma_i W^T $$
3.  **2D Projection (EWA):** Project the 3D covariance to the 2D image plane using the Jacobian $J$ of the perspective projection transformation [S1, unofficial]:
    $$ \Sigma_{2d} = J \Sigma_{cam} J^T $$
    A small isotropic dilation (blur) is added to $\Sigma_{2d}$ for numerical stability [S1, unofficial].
4.  **Screen-Space Bounds:** Compute the bounding box for each Gaussian in screen space based on $\Sigma_{2d}$ to determine which pixels to update.
5.  **Depth Sorting:** Sort the Gaussians overlapping each pixel by their depth $z$ in camera space. The implementation uses `argsort`, which is non-differentiable across order changes; gradients flow through the values given the fixed ordering [S1, unofficial].
6.  **Alpha Compositing:** Perform per-pixel front-to-back alpha compositing using the volume-rendering equation [S1, unofficial]:
    $$ C = \sum_{i=1}^{N} c_i \alpha_i \prod_{j=1}^{i-1} (1 - \alpha_j) $$
    where $c_i$ is the color, $\alpha_i$ is the opacity, and the product term represents the accumulated transmittance $T_i$. The opacity $\alpha_i$ for each pixel is computed from the 2D Gaussian weight at that pixel location [S1, unofficial].

def quaternion_to_rotation_matrix(q):
    """Convert unit quaternion (w, x, y, z) to 3x3 rotation matrix."""
    w, x, y, z = q[:, 0], q[:, 1], q[:, 2], q[:, 3]
    N = q.shape[0]
    R = torch.zeros(N, 3, 3, device=q.device)
    
    R[:, 0, 0] = 1 - 2 * (y**2 + z**2)
    R[:, 0, 1] = 2 * (x*y - w*z)
    R[:, 0, 2] = 2 * (x*z + w*y)
    
    R[:, 1, 0] = 2 * (x*y + w*z)
    R[:, 1, 1] = 1 - 2 * (x**2 + z**2)
    R[:, 1, 2] = 2 * (y*z - w*x)
    
    R[:, 2, 0] = 2 * (x*z - w*y)
    R[:, 2, 1] = 2 * (y*z + w*x)
    R[:, 2, 2] = 1 - 2 * (x**2 + y**2)
    
    return R

**Parameters**
*   **Camera Model:** Pinhole camera with `look_at` function using OpenCV/COLMAP convention [S1, unofficial].
*   **Optimization:** Adam optimizer with L1 + MSE loss for 600 iterations [S1, unofficial].
*   **Performance:** End-to-end run takes ~30 seconds on CPU for a 64x64 image [S1, unofficial].

**Edge Cases and Pitfalls**
*   **Depth Sort:** The `argsort` operation used for depth sorting is non-differentiable across order changes. Gradients flow through the values given the ordering, which is accepted for the fit-from-scratch demo [S1, unofficial].
*   **Precision:** A small isotropic dilation is added to the 2D covariance for stability to prevent numerical issues during inversion or exponentiation [S1, unofficial].
*   **Simplifications:** The MVP intentionally skips tile-based CUDA rasterization, spherical harmonics for view-dependent color, adaptive density control, real-world captures, and SSIM losses [S1, unofficial].

## Subtopics

### [3D Gaussian Splatting with Gaussian Unpooling](6133-3d-gaussian-splatting-with-gaussian-unpooling.md)
FSGS is a method for reconstructing 3D scenes from sparse-view inputs, addressing the challenge of insufficient initialization data for standard 3D Gaussian Splatting. It distinguishes itself from dense-view baselines by using Gaussian unpooling to expand a sparse set of Structure-from-Motion (SfM) points into a denser set of Gaussians, enabling faithful geometry reconstruction where standard methods fail due to lack of initial coverage.

### [Relightable 3DGS](7851-relightable-3dgs.md)
Relightable 3DGS extends standard 3D Gaussian Splatting by embedding physically-based material properties into each Gaussian, enabling deferred shading and realistic rendering of complex appearances such as reflections, transparency, and glossy surfaces. Unlike standard rasterization which approximates view-dependent colors via spherical harmonics and fails to represent specular reflections or global illumination, this method decomposes outgoing radiance into a BRDF integration that respects material parameters. It sets itself apart from its siblings by treating alpha-blending as a smoothing filter to stabilize optimization while allowing for physically accurate lighting interactions.

### PRoGS
PRoGS is a post-training technique for 3D Gaussian Splatting that approximates each Gaussian's contribution to the final scene to construct a prioritization order, enabling progressive rendering or streaming by dynamically selecting splats to display or transmit [S1, unofficial]. Unlike existing web-viewers that require full scene retrieval before rendering, PRoGS loads a representative subset early, significantly reducing time-to-first-paint while maintaining perceptual quality [S1, unofficial]. It is designed for on-device rendering applications constrained by memory and streaming applications requiring minimal bandwidth [S1, unofficial].

### [3D Gaussian Splatting Rendering Pipeline (RViz Plugin)](10297-3d-gaussian-splatting-rendering-pipeline-rviz-plugin.md)
This article describes the OpenGL-based rendering pipeline for visualizing 3D Gaussian Splatting data within the ROS RViz environment. It solves the problem of efficiently rendering millions of 2D-projected Gaussian splats as a single instanced draw call, handling depth sorting and view-dependent shading. It differs from pure software implementations by leveraging GPU-based sorting and texture buffer objects (TBOs) for data storage, and from other RViz plugins by supporting both exact back-to-front sorting and Order-Independent Transparency (WBOIT) approximations.

### [CPU-based Gaussian Splatting Thumbnailer with JIT Optimization](14069-cpu-based-gaussian-splatting-thumbnailer-with-jit-optimizati.md)
This method provides a lightweight, CPU-only pipeline for generating rapid visual thumbnails from 3D Gaussian Splatting datasets, prioritizing responsiveness and portability over high-fidelity rendering. It distinguishes itself from standard GPU-accelerated splatting by omitting rotation parameters, approximating Gaussians as spheres, and leveraging Python's Numba JIT compiler to achieve near-real-time performance on constrained hardware.

### 3D Gaussian Splatting with Vector Clustering and Entropy Encoding
A method that utilizes vector clustering to encode color and geometric attributes into two codebooks, using a sensitivity-aware KMeans method [S2]. For disk data storage, SASCGS utilizes the entropy encoding method DEFLATE, which combines the LZ77 algorithm and Huffman coding, to compress the data [S2]. On the MipNeRF360 dataset, SASCGS achieves SSIM 0.801, PSNR 26.98, LPIPS 0.238, and a size of 28.80 MB [S2].

### Vol3DGS
Enforces that alpha blending exactly satisfies the front-to-back absorption-emission model by deriving discrete compositing as an unbiased Monte Carlo estimator of the continuous integral [S3, unofficial]. It introduces a continuous density field along the ray to resolve artifacts in scenes with semi-transparent objects [S3, unofficial]. Volumetric alpha computation is defined as $\alpha_i = 1 - \exp(-\int G_i(x) dx)$, accumulating density along the ray in accordance with the volume rendering equation [S3, unofficial].

### HiFi4G
This successfully preserves spatial-temporal consistency in a more compact manner [S2]. It combines 3DGS with the non-rigid tracking offered by its dual-graph mechanism for high-fidelity rendering [S2].

### 3D Gaussian Splatting with Mesh UV Parameterization
This enables real-time and high-quality animated humans [S2]. It projects the 3D Gaussian learning into a 2D texture space using mesh UV parameterization to capture the appearance [S2].

### Modified Alpha-Blending
A modified alpha-blending function designed to perform image rendering over re-sketched Gaussian lines and Gaussian triangles [S4, unofficial]. It renders the re-sketched primitives using the modified alpha-blending function in a similar manner as original Gaussian ellipses [S4, unofficial].

### Depth Generation via Linear Interpolation
A method to compute accurate depth $\hat{D}$ for a pixel by treating it as a linear interpolation of distances from 3D Gaussians to the image plane, avoiding the floating problem and disc aliasing associated with peak selection in forward mapping splatting [S5]. For each pixel, it renders the view using 3D Gaussians to obtain $T_i$, $\alpha_i$, $d_i$, and $n_i$ for all contributing Gaussians $i$ [S5]. The depth is calculated as $\hat{D} = \sum_{i=1}^{N} \hat{w}_i d_i$, where $\hat{w}_i = \frac{T_i \alpha_i}{\sum_{i=1}^{N} T_i \alpha_i}$, $d_i$ is the distance from the i-th Gaussian to the image plane, $T_i$ is accumulated transmittance, and $\alpha_i$ is opacity [S5].

## Operating characteristics
*   **Time Complexity:** The MVP implementation uses a Python loop over Gaussians and pixels, resulting in $O(N \cdot H \cdot W)$ complexity in the worst case (where $N$ is the number of Gaussians and $H, W$ are image dimensions), though bounding boxes reduce the effective constant. This is significantly slower than the tile-based CUDA rasterizer used in production [S1, unofficial].
*   **Memory Complexity:** $O(N + H \cdot W)$ for storing Gaussian parameters and intermediate buffers (T, image) [S1, unofficial].
*   **Measured Performance:** End-to-end run takes ~30 seconds on CPU for a 64x64 image [S1, unofficial].
*   **Strengths:** High readability, no custom CUDA kernels required, suitable for educational purposes and debugging the mathematical foundations of 3DGS [S1, unofficial].
*   **Limitations:** Slow performance on CPU, lacks optimizations like tile-based sorting, spherical harmonics, and adaptive density control, making it unsuitable for real-time or large-scale applications [S1, unofficial].
*   **When to use:** For learning, teaching, or debugging the 3DGS algorithm.
*   **When not to use:** For production rendering, real-time applications, or large-scale scene reconstruction.

## Background
3D Gaussian Splatting MVP was introduced as a self-contained Jupyter notebook implementation of the core 3D Gaussian Splatting algorithm (Kerbl et al., SIGGRAPH 2023) in pure PyTorch [S1, unofficial]. It was created to serve as a teaching reference, allowing users to "grind on the math" without the complexity of custom CUDA kernels [S1, unofficial]. The implementation includes a pinhole camera model, Gaussian parameterization, forward rasterization, and a simple optimization loop for fitting Gaussians to training images [S1, unofficial].
