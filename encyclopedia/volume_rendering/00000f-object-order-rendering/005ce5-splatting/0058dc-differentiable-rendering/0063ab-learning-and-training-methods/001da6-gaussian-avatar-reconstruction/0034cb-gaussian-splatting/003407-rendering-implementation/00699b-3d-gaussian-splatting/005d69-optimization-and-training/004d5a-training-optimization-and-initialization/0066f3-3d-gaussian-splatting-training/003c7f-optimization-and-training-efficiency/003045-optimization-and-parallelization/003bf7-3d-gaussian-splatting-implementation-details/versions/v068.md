# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, GSGEN Implementation Details, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific hyperparameters, data structures, and optimization schedules required to implement the 3D Gaussian Splatting (3DGS) training pipeline, including densification, pruning, and hardware-accelerated rasterization. It serves as the operational reference for the differentiable rasterization core described in [Optimization and Parallelization](6233-optimization-and-parallelization.md), providing the concrete values for gradient thresholds, iteration intervals, and memory management strategies that distinguish a functional implementation from the theoretical framework.

## How it works

### Inputs and Outputs
*   **Inputs:** A set of $N$ 3D Gaussians $\mathcal{G}$, each parameterized by position $\mu \in \mathbb{R}^3$, covariance $\Sigma \in \mathbb{R}^{3 \times 3}$ (or rotation $q \in \mathbb{R}^4$ and scale $s \in \mathbb{R}^3$), opacity $\alpha \in [0, 1]$, and spherical harmonic coefficients $\mathbf{c}_{lm}$. A set of training images with known camera poses $C_i$.
*   **Outputs:** Optimized Gaussian parameters $\mathcal{G}'$ and rendered images $\mathbf{I}_{rendered}$ minimizing the loss $\mathcal{L}$ against ground truth $\mathbf{I}_{gt}$.

### Data Structures
The implementation relies on the `gsplat` library [S3] or custom CUDA kernels [S2]. Key structures include:
1.  **Gaussian Attributes:** Stored in contiguous GPU memory. For half-precision rasterization, feature vectors are fetched in FP16 to reduce register pressure [S2].
2.  **Gradient Accumulators:** Per-Gaussian buffers for accumulated view-space position gradients $\nabla_{\mu}$ and opacity gradients $\nabla_{\alpha}$ [S1].
3.  **Scene Extent:** Calculated to guide densification. The default 3DGS extent $e_{\text{scene}}$ is biased by camera distribution [S4]. A corrected extent $e'_{\text{scene}}$ is computed using Structure-from-Motion (SfM) points:
    $$ \bar{C} = \frac{1}{N_{\text{cam}}} \sum_{i=1}^{N_{\text{cam}}} C_i $$
    $$ e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2 $$
    where $N_{\text{SfM}}$ is the number of SfM points and $p_i$ are their positions [S4].

### Training Schedule and Densification
The training loop iterates over random views. For each iteration:
1.  **Forward Pass:** Render the image using differentiable alpha blending [6233-optimization-and-parallelization].
2.  **Loss Computation:** Compute $\mathcal{L} = \mathcal{L}_{L1} + \lambda \mathcal{L}_{SSIM}$ [S7]. In text-to-3D generation, SDS guidance is applied with scale 100 [S1].
3.  **Backward Pass:** Compute gradients $\frac{\partial \mathcal{L}}{\partial \theta}$ [6233-optimization-and-parallelization].
4.  **Optimizer Update:** Update parameters using Adam with learning rate $1 \times 10^{-3}$ [S3].

**Densification Steps (Every 100–1000 iterations):**
1.  **Splitting:** Every 500 iterations, split Gaussians where the view-space position gradient exceeds threshold $T_{\text{pos}} = 0.02$ [S1].
2.  **Cloning/Compactness:** Every 1000 iterations, perform compactness-based densification [S1].
3.  **Pruning:** Every 200 iterations, remove Gaussians with opacity $\alpha < \alpha_{\min} = 0.05$ or excessive world-space/view-space radius [S1].

### Half-Precision Optimization
To improve training stability and reduce memory bandwidth:
1.  Use half-precision (FP16) memory fetches for feature vectors during rasterization forward and backward passes [S2].
2.  Apply an automatic scaling factor to loss values to prevent gradient underflow/overflow in FP16 [S2].
3.  Use JIT-compiled cooperative vector MLPs (e.g., via `tiny-cuda-nn`) trained in FP16 [S2].

### Edge Cases and Pitfalls
*   **Scene Extent Bias:** Using camera positions to define scene extent causes incorrect splitting/pruning if cameras are clustered (e.g., orbiting a small object in a large environment) [S4]. Use SfM-based extent [S4].
*   **Uniform Blur:** Predicting a constant scale offset $\delta s_j$ for all Gaussians in defocus blurring methods degrades to a uniform Gaussian blur, failing to model spatially varying blurriness [S5].
*   **Interpolation Error Accumulation:** In sparse rendering via viewpoint transformation, rendering quality degrades as the number of consecutively transformed frames increases due to accumulated interpolation errors [S8].
*   **Late-Stage Growth:** Excessive primitive growth at the end of optimization leads to poor convergence. Mitigated by concave-up scheduling functions [S12].

### Pseudocode
```python
def train_3dgs(gaussians, images, camera_poses, config):
    """
    Main training loop for 3D Gaussian Splatting.
    """
    optimizer = Adam(gaussians.parameters(), lr=config.lr)
    
    # Initialize scene extent using SfM points to avoid camera bias [S4]
    scene_extent = compute_sfm_scene_extent(gaussians.init_points, camera_poses)
    
    for step in range(config.max_iterations):
        # 1. Random View Selection [S3]
        view_idx = random.choice(len(images))
        image = images[view_idx]
        pose = camera_poses[view_idx]
        
        # 2. Forward Pass (Half-Precision Rasterization [S2])
        rendered_image = rasterize_forward(gaussians, pose, half_precision=True)
        
        # 3. Loss Computation
        # Apply loss scaling for FP16 stability [S2]
        loss = compute_loss(rendered_image, image) * config.loss_scale
        
        # 4. Backward Pass
        optimizer.zero_grad()
        loss.backward()
        
        # 5. Optimizer Step
        optimizer.step()
        
        # 6. Densification and Pruning Schedule
        if step % 100 == 0:
            # Pruning: Remove low opacity and large Gaussians [S1]
            prune_gaussians(gaussians, alpha_min=0.05, radius_threshold=compute_radius(scene_extent))
            
        if step % 500 == 0:
            # Splitting: Based on view-space position gradient [S1]
            split_gaussians(gaussians, threshold=0.02)
            
        if step % 1000 == 0:
            # Compactness-based densification [S1]
            clone_gaussians(gaussians, metric='compactness')
            
        # 7. Adaptive Resolution/Primitive Scheduling (Optional [S12])
        update_primitive_budget(gaussians, step, momentum_decay=0.98, force_scale=1.0)
```

### Corrected Scene-Extent
A method to calculate scene extent based on the SfM point cloud rather than camera positions to avoid bias from camera distribution (e.g., orbiting a small object in a large environment) [S4]. The corrected extent is $e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2$ [S4]. The default extent $e_{\text{scene}} = 1.1 \cdot \max_{i} \|\bar{C} - C_i\|_2$ causes incorrect splitting/pruning if cameras are clustered [S4].

### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ to selectively enlarge covariances, creating pixel-wise variable blur kernels [S5]. A compact MLP predicts $\delta s_j$ for each Gaussian, which is added to the base scale before projection [S5]. If $\delta s_j$ is constant, it degrades to uniform blur [S5].

### Denoise-GS
A self-supervised denoising method for sparse-view 3DGS combining Noise2Void (N2V) with differentiable rendering [S6]. Round 1: Train UNet with N2V, process denoised images through InstantSplat for initialization. Round 2: Fine-tune UNet with composite loss, render on selected viewpoints [S6]. Unlike supervised methods, it requires no paired clean data [S6].

### Multi-Scale Constraint
Applies different scales to Gaussians based on viewer distance using position-aware point adaptive control [S7]. The scale factor is $\gamma(\mu) = 1$ if $\|\mu - c\|^2 < 2r$, else $\|\mu - c\|^2 / r - 1$ [S7]. Cloning occurs if $\max(s) < g \cdot \gamma(\mu)$, splitting if $\max(s) \ge g \cdot \gamma(\mu)$, and elimination if $\max(s) > b \cdot \gamma(\mu)$ [S7].

### LS-Gaussian Viewpoint Transformation
Leverages inter-frame continuity by transforming the viewpoint between consecutive frames rather than rendering each separately [S8]. This enables sparse rendering (e.g., one full render every 6 frames) [S8]. Quality degrades with accumulated interpolation errors [S8].

### Camera Localisation for Convergence Basin
Localizes camera pose by minimizing photometric error against ground truth while fixing $G_{init}$ [S9, unofficial]. The pose $T_{CW}^{est}$ is found by $\arg \min \| I(\mathcal{G}_{init}, T_{CW}) - \bar{I}_{target} \|_1$ [S9, unofficial]. Success is defined as convergence within 1cm in 1000 iterations [S9, unofficial].

### DiffGS Framework
Applies optimization during Gaussian extraction to optimize Gaussians to exact locations [S10]. Uses a truncation function $\lambda$ and projection function $\tau$ (e.g., $\tau(x) = e^{-x}$) [S10]. Achieves PSNR 34.01 with 350K Gaussians [S10].

### Opacity Offset Table for DSA
Constructs an opacity offset table to model changes in digital subtraction angiography [S11].

### Resolution Guided Primitive Scheduler
Updates primitive budget $P_{fin}^{(i)} = \max(P_{fin}^{(i-1)}, \gamma \cdot P_{fin}^{(i-1)} + \eta \cdot P_{add})$ [S12]. Power factor starts at 2 and decreases to 1 to suppress early growth [S12]. Default $\gamma=0.98, \eta=1.0$ [S12].

### Conditional Splat Approximation
Approximates the influence range of a 3D Gaussian on a slice using a 2D ellipse splat scaled by the marginal factor [S13, unofficial]. Closely matches true iso-probability contours [S13, unofficial].

### 3DGS Uncertainty Calculation via Fisher Information
Computes uncertainty $\bar{C}_{V;G} = -\log p_f(\pi|V; G)$ based on negative log-likelihood [S14]. Assumes regularity conditions: partial derivative exists almost everywhere, integral differentiability, and support independence from $G$ [S14].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot M)$ per pixel, where $N$ is the number of Gaussians and $M$ is the number of tiles. Densification adds $O(N)$ overhead every 100–1000 iterations [S1].
*   **Memory Complexity:** $O(N \cdot D)$, where $D$ is the dimensionality of Gaussian attributes (position, scale, rotation, opacity, SH coefficients) [12927-compact-3d-gaussian-representation-c3dgs.md]. Half-precision fetches reduce register pressure [S2].
*   **Performance:** Real-time rendering (80+ FPS) on consumer GPUs (e.g., RTX 4090) for moderate scene sizes [S3]. LS-Gaussian achieves 5.41× speedup on Jetson AGX Orin via sparse rendering [S8].
*   **Strengths:** High fidelity, real-time rendering, explicit representation allows easy densification/pruning [S1].
*   **Limitations:** High memory usage for large scenes [12927-compact-3d-gaussian-representation-c3dgs.md]. Bias in scene extent calculation if not corrected [S4]. Degradation in sparse rendering with viewpoint transformation [S8].

## Background
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1, S3]. It represents scenes as a set of differentiable 3D Gaussians, optimized via gradient descent to minimize rendering error. The method builds on differentiable rasterization techniques and has become a standard for real-time novel view synthesis. Subsequent implementations have focused on optimization efficiency, hardware acceleration, and handling specific challenges like defocus blur [S5], sparse views [S6], and large-scale scenes [S7].
