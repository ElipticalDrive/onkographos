# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, GSGEN Implementation Details, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific implementation parameters, optimization strategies, and variant algorithms required to realize the 3D Gaussian Splatting (3DGS) training and rendering pipeline. It addresses the gap between the theoretical differentiable rasterization core and practical execution, covering densification schedules, precision handling, and specialized variants for scene extent correction, defocus modeling, and sparse-view denoising. It sets itself apart from general optimization articles by providing concrete thresholds, data structures, and algorithmic steps for specific implementation challenges such as camera-localization convergence, multi-scale constraints, and uncertainty quantification.

## How it works

### Inputs and Outputs
*   **Inputs**: Sparse Structure-from-Motion (SfM) point cloud, camera poses, training images, and hyperparameters (learning rate, thresholds, iteration counts).
*   **Outputs**: Optimized set of 3D Gaussians (position, scale, rotation, opacity, spherical harmonic coefficients) and rendered novel views.

### Data Structures
The core representation is a list of Gaussian primitives. Each Gaussian $i$ is parameterized by:
*   **Position**: $\mathbf{p}_i \in \mathbb{R}^3$
*   **Scale**: $\mathbf{s}_i \in \mathbb{R}^3$ (log-space for optimization)
*   **Rotation**: $\mathbf{q}_i \in \mathbb{R}^4$ (unit quaternion)
*   **Opacity**: $\alpha_i \in [0, 1]$
*   **Color**: Spherical Harmonic (SH) coefficients $\mathbf{c}_i$ up to degree $D$.

For half-precision rasterization, feature vectors are fetched using half-precision memory accesses to reduce register pressure [S2].

### Training Loop and Optimization Steps
The training process iteratively minimizes the difference between rendered images and ground truth.

1.  **Initialization**: Initialize Gaussians from the SfM point cloud. Calculate scene extent.
    *   *Standard Extent*: $e_{\text{scene}} = 1.1 \cdot \max_{i=1}^{N_{\text{cam}}} \|\bar{C} - C_i\|_2$, where $\bar{C} = \frac{1}{N_{\text{cam}}} \sum_{i=1}^{N_{\text{cam}}} C_i$ [S4].
    *   *Corrected Extent*: To avoid bias from clustered cameras, use $e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2$, where $p_i$ are SfM points [S4].
2.  **Random View Selection**: For each iteration, randomly select a single image from a random scene as supervision [S3].
3.  **Differentiable Rasterization**: Render the selected image using the current Gaussian set. Use half-precision arithmetic for feature vectors to improve stability and speed [S2]. Apply an automatic scaling factor to loss values to stabilize half-precision training [S2].
4.  **Loss Computation**: Compute loss $\mathcal{L}$ using a combination of Mean Squared Error (MSE) and Structural Similarity Index Measure (SSIM):
    $$ \mathcal{L} = \lambda \cdot \text{MSE}(C, \hat{C}) + (1 - \lambda) \cdot \text{SSIM}(C, \hat{C}) $$
    where $C$ is ground truth, $\hat{C}$ is rendered color, and $\lambda$ is a hyperparameter [S15, unofficial].
5.  **Gradient Accumulation**: Accumulate gradients with respect to Gaussian parameters $\theta$ [6233-optimization-and-parallelization].
6.  **Optimizer Update**: Update parameters using Adam optimizer with learning rate $1 \times 10^{-3}$ [S3].
7.  **Densification and Pruning**:
    *   **Splitting**: Every 500 iterations, split Gaussians where the view-space position gradient exceeds $T_{\text{pos}} = 0.02$ [S1].
    *   **Cloning/Compactness**: Every 1000 iterations, perform compactness-based densification [S1].
    *   **Pruning**: Every 200 iterations, remove Gaussians with opacity $\alpha < \alpha_{\text{min}} = 0.05$ or excessively large world-space/view-space radius [S1].

### Variant: Camera Localization for Convergence Basin
For SLAM or localization tasks, the camera pose $T_{CW}$ is optimized against a fixed initial Gaussian set $G_{init}$ [S9, unofficial].
1.  Initialize $T_{CW}$ at a test view's position.
2.  Minimize photometric error for 1000 iterations:
    $$ \mathbf{T}_{CW}^{est} = \underset{\mathbf{T}_{CW}}{\arg \min} \left\| I(\mathcal{G}_{init}, \mathbf{T}_{CW}) - \bar{I}_{target} \right\|_1 $$
3.  Localization is successful if the estimated pose converges to within 1cm of the target view [S9, unofficial].

### Variant: DiffGS Framework
DiffGS optimizes Gaussians to exact locations using a Gaussian Probability Function (GauPF) [S10].
1.  Apply optimization during Gaussian extraction.
2.  Use a truncation function $\lambda$ and projection function $\tau(x)$ (either $e^{-x}$ or linear) [S10].
3.  Performance metrics for varying Gaussian counts:
    *   50K Gaussians: PSNR 28.61, SSIM 0.9787, LPIPS 0.0251.
    *   100K Gaussians: PSNR 30.35, SSIM 0.9838, LPIPS 0.0151.
    *   350K Gaussians: PSNR 34.01, SSIM 0.9879, LPIPS 0.0149 [S10].

### Variant: Multi-Scale Constraint
For large-scale scenes, apply position-aware point adaptive control [S7].
1.  Compute distance factor $\gamma(\mu)$:
    $$ \gamma(\mu) = \begin{cases} 1 & \text{if } \|\mu - c\|^2 < 2r \\ \|\mu - c\|^2 / r - 1 & \text{if } \|\mu - c\|^2 \ge 2r \end{cases} $$
    where $r$ is scene radius and $c$ is camera center [S7].
2.  If $\max(s) < g \cdot \gamma(\mu)$, clone the Gaussian.
3.  If $\max(s) \ge g \cdot \gamma(\mu)$, split the Gaussian.
4.  If $\max(s) > b \cdot \gamma(\mu)$, eliminate the Gaussian.
    Here $g$ and $b$ are scale threshold parameters [S7].

### Variant: LS-Gaussian Viewpoint Transformation
For sparse rendering in continuous video, transform viewpoints between consecutive frames rather than rendering each separately [S8].
1.  Leverage inter-frame continuity.
2.  Render only one frame in every 6 frames fully, transforming the rest [S8].
3.  *Pitfall*: Quality degrades as accumulated interpolation errors increase with more transformed frames [S8].

### Variant: Neural Illumination Enhancement (NIE)
To handle non-Lambertian effects, predict a view-dependent color residual $I_n$ using an MLP [S14, unofficial].
1.  Inputs: Spatial position (HashGrid encoded), reflection direction (SH encoded), and material features (view direction, normals, Fresnel, roughness) [S14, unofficial].
2.  Final image: $I = I_g + I_n$, where $I_g$ is the explicit Gaussian render [S14, unofficial].
3.  Update procedure: Use path-traced renderings with albedo-shading decomposition to update 3DGS efficiently [S14, unofficial].

### Variant: Tangent Plane Constrained Gaussian Splatting
Constrain Gaussians to a 2D tangent plane for accurate normal map estimation [S16].
1.  Define point $P$ on the 2D plane with coordinates $(u, v)$:
    $$ P(u, v) = p_k + s_u t_u u + s_v t_v v = H(u, v, 1, 1)^T $$
    where $H = [p_k, t_u, t_v, t_w]$ is the transformation matrix [S16].
2.  Render normals using the same splatting logic as color [S16].

### Variant: 3DGS Uncertainty Calculation
Compute uncertainty $\bar{C}_{V;G}$ based on Fisher Information [S13].
1.  Formula: $\bar{C}_{V;G} = -\log p_f(\pi|V; G)$, where $p_f$ is the PDF of rendered pixel $\pi$ [S13].
2.  Implementation: Compute the dot product of the gradient with itself: $\nabla_G \pi(V; G)^T \nabla_G \pi(V; G)$ [S13].
3.  *Pitfall*: Assumes regularity conditions: partial derivative exists almost everywhere, integral differentiability, and support independence from $G$ [S13].

### Variant: Conditional Splat Approximation
Approximate the influence range of a 3D Gaussian on a slice using a 2D ellipse splat scaled by the marginal factor [S12, unofficial].
1.  This provides an accurate approximation of true 3D Gaussian iso-probability contours [S12, unofficial].

### Variant: Opacity Offset Table for DSA
Construct an opacity offset table to model changes in digital subtraction angiography [S11].

### Variant: Graphical X Splatting (GraphiXS)
A probabilistic framework treating learnable parameters and camera poses as random variables inferred via Maximum a Posteriori (MAP) [S17].
1.  Formulate as a generative process with stochasticity.
2.  Treat camera pose and frame time as samples of random variables [S17].
3.  The 'X' allows instantiation with primitives other than Gaussians, such as Student’s-t [S17].

## Subtopics

### Corrected Scene-Extent
A method to calculate scene extent based on the SfM point cloud rather than camera positions to avoid bias from camera distribution (e.g., orbiting a small object in a large environment) [S4]. It sets itself apart by using $e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2$ instead of the default camera-based extent, preventing incorrect splitting/pruning when cameras are clustered [S4].

### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ to selectively enlarge covariances, creating pixel-wise variable blur kernels that match spatially varying scene blurriness [S5]. It sets itself apart from naive Gaussian blur by allowing spatially varying blur shapes and magnitudes, enabling effective deblurring [S5].

### Denoise-GS
A self-supervised denoising method for sparse-view 3D Gaussian Splatting that combines unsupervised image denoising (Noise2Void) with explicitly differentiable 3DGS [S6]. It sets itself apart from supervised methods by requiring no paired clean data, making it robust to non-Gaussian noise in sparse view scenarios [S6].

### Multi-Scale Constraint
A technique using position-aware point adaptive control to apply different scales to Gaussians based on viewer distance, improving rendering of distant objects [S7]. It sets itself apart by dynamically adjusting cloning, splitting, and elimination thresholds based on the distance factor $\gamma(\mu)$ [S7].

### LS-Gaussian Viewpoint Transformation
An algorithm that leverages inter-frame continuity for efficient sparse rendering by transforming the viewpoint between consecutive frames [S8]. It sets itself apart from naive pixel warping by operating at the tile/Gaussian level to reduce preprocessing and sorting costs, enabling sparse rendering where only one frame in every 6 is fully rendered [S8].

### DiffGS Framework
Applies an optimization process during Gaussian extraction to optimize Gaussians to exact locations using a Gaussian Probability Function (GauPF) [S10]. It sets itself apart by using truncation and projection functions to refine Gaussian positions, achieving high PSNR/SSIM with fewer Gaussians [S10].

### Opacity Offset Table for DSA
Constructs an opacity offset table to model changes in digital subtraction angiography [S11].

### Conditional Splat Approximation
Approximates the influence range of a 3D Gaussian on a slice by using a 2D ellipse splat scaled by the marginal factor [S12, unofficial]. It sets itself apart by providing an accurate and efficient approximation of true 3D Gaussian iso-probability contours [S12, unofficial].

### 3DGS Uncertainty Calculation via Fisher Information
Computes an uncertainty attribute for 3D Gaussians based on the negative log-likelihood of the rendered pixel value, interpreted as Fisher information [S13]. It sets itself apart by providing a differentiable uncertainty metric derived from gradient norms [S13].

### Neural Illumination Enhancement
A module that complements explicit 3DGS representation by predicting a view-dependent color residual using a lightweight MLP to handle non-Lambertian effects [S14, unofficial]. It sets itself apart by combining explicit splatting with neural residuals for highlights [S14, unofficial].

### 3DGS Update Procedure with Albedo-Shading Decomposition
A procedure to efficiently capture global illumination by updating 3D Gaussians using path-traced renderings, combined with albedo-shading decomposition [S14, unofficial].

### PyGS Optimization
The optimization process using a combined MSE and SSIM loss, along with density control strategies adapted from 3DGS, while preserving the multi-scale structure [S15, unofficial]. It sets itself apart by routinely reassessing and reassigning levels of Gaussians to preserve multi-scale characteristics [S15, unofficial].

### Tangent Plane Constrained Gaussian Splatting
An extension of 3D Gaussian Splatting where Gaussians are constrained to a 2D tangent plane to resolve the conflict between volumetric Gaussians and surface representation, enabling accurate normal map estimation [S16].

### Graphical X Splatting (GraphiXS)
A probabilistic framework that incorporates data uncertainty into Gaussian Splatting by treating learnable parameters as latent variables and camera poses/times as random variables, inferred via Maximum a Posteriori (MAP) [S17]. It sets itself apart by being a general framework that can upgrade existing methods with different primitives and handle asynchronous data [S17].

## Operating characteristics

*   **Time Complexity**: Dominated by the rasterization step, which is $O(N \cdot R)$ where $N$ is the number of Gaussians and $R$ is the resolution, but optimized via tile-based sorting and early stopping. Densification adds overhead every few hundred iterations.
*   **Memory Complexity**: $O(N \cdot D)$ where $D$ is the number of SH coefficients. Half-precision rasterization reduces register pressure and memory bandwidth usage [S2].
*   **Performance**: Standard 3DGS achieves real-time rendering on modern GPUs. Variants like LS-Gaussian achieve up to 17.3× speedup on edge devices like Jetson AGX Orin by using sparse rendering [S8].
*   **Strengths**: Real-time rendering, high fidelity, explicit representation allows for easy editing and compression.
*   **Limitations**: High memory usage for large scenes, sensitivity to initialization (addressed by Corrected Scene-Extent), and potential for popping artifacts (addressed by Softmax-GS or DeSplat).
*   **When to use**: Real-time novel view synthesis, interactive applications, scenes with complex geometry and view-dependent effects.
*   **When not to use**: Scenes with extreme occlusion or non-surface data (use Inverse and Internal Rendering), or when strict geometric surface extraction is required without post-processing (use Tangent Plane Constrained or Neural SDF Inference).

## Background

3D Gaussian Splatting was introduced by Kerbl et al. in 2023 as a real-time explicit scene representation method [S1, S2, S3, S4, S5, S6, S7, S8][S9, unofficial][S10, S11][S12, unofficial][S13][S14, S15, unofficial][S16, S17]. It builds on the differentiable rasterization core shared by its siblings [6233-optimization-and-parallelization]. The method has since been extended with various optimization and implementation details to address specific challenges such as sparse views, defocus, large-scale scenes, and geometric fidelity.
