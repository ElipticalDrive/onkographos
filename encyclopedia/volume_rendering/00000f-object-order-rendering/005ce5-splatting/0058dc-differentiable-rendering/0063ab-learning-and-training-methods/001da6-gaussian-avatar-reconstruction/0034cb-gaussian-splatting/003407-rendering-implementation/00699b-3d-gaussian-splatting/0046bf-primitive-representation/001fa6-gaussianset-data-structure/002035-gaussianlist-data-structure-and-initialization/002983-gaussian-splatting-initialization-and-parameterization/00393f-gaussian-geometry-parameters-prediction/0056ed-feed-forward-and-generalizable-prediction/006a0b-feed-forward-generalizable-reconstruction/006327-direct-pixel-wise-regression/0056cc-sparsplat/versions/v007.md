# SparSplat

Also called: Generalizable 2D Gaussian Splatting, SparSplat Model, SparSplat: Fast Multi-View Reconstruction with Generalizable 2D Gaussian Splatting

## Overview
SparSplat is a generalizable, feed-forward model that maps a set of sparse input images to 2D Gaussian Splatting (2DGS) parameters in a single forward pass to perform both 3D shape reconstruction and novel view synthesis [S1, unofficial]. It differs from its sibling [MVSGaussian](12847-anysplat-pipeline.md) by using 2D primitives instead of 3D Gaussians, which ensures multi-view depth consistency required for coherent TSDF mesh fusion, a task prior generalizable GS methods failed to support [S1, unofficial]. Unlike implicit methods such as [SparseNeuS](15257-finesplat.md) or [UfoRecon](12847-anysplat-pipeline.md), SparSplat offers superior novel view synthesis capabilities alongside reconstruction, with inference speeds nearly two orders of magnitude faster [S1, unofficial].

## How it works
**Inputs:** A set of $N$ RGB images $\{I_i\}_{i=1}^N$ where $I_i \in \mathbb{R}^{H \times W \times 3}$, and their associated camera poses $P_i$ (intrinsics and extrinsics). The model is trained with $N=3$ and image resolution $640 \times 512$ [S1, unofficial].

**Outputs:** For a given target view $P_t$, the model $\Phi$ predicts a pixel-aligned 2DGS Gaussian parameter map $O_t = \{s, q, p, \alpha, c\} \in \mathbb{R}^{H \times W \times (2+4+3+1+3)}$, where $s$ is scale (2D), $q$ is rotation (quaternion, 4D), $p$ is centroid position (3D), $\alpha$ is opacity (1D), and $c$ is color (3D) [S1, unofficial]. Additionally, an explicit 3D triangle mesh $S$ can be extracted via TSDF fusion of the splatted depths [S1, unofficial].

**Data Structures:**
The core data structure is the parameter map $O_t$. Each pixel $(u,v)$ in the target view holds a vector of 13 floats:
1.  Scale $s \in \mathbb{R}^2$
2.  Rotation $q \in \mathbb{R}^4$ (normalized quaternion)
3.  Position $p \in \mathbb{R}^3$
4.  Opacity $\alpha \in \mathbb{R}^1$
5.  Color $c \in \mathbb{R}^3$

**Algorithm Steps:**
The prediction pipeline $\Phi$ follows the architecture of [MVSGaussian](12847-anysplat-pipeline.md) [S1, unofficial], enhanced with foundation model features:

1.  **Feature Extraction:**
    *   Extract monocular 2D semantic features from each input image $I_i$ using DINOv2 [S1, unofficial].
    *   Extract pairwise dense correspondence features from input images using MASt3R [S1, unofficial].
    *   An FPN network predicts a 2D feature map $f_i$ for each input image $I_i$ [S1, unofficial].

2.  **Feature Warping:**
    *   Warp the feature maps $f_i$ to the target view coordinate system using homography based on relative poses $P_t / P_i$, resulting in warped features $f_{t,i}$ [S1, unofficial].

3.  **Cost Volume and Depth Prediction (DeepMVS Branch):**
    *   Merge warped features $f_{t,i}$ into a cost volume.
    *   Process the cost volume into a probability volume using a 3D convolutional network.
    *   Sample depth planes: 64 planes for the coarse stage and 8 planes for the fine stage [S1, unofficial].
    *   Produce a depth prediction $D_{pred}$ [S1, unofficial].

4.  **Gaussian Attribute Prediction (Pixel-Aligned Branch):**
    *   Pool the warped features $f_{t,i}$ into a target feature map $f_t$ [S1, unofficial].
    *   Pass $f_t$ through a 2D convolutional network and an MLP to predict attributes $\{s, q, \alpha, c\}$ [S1, unofficial].

5.  **Position Unprojection:**
    *   Compute the 3D position attribute $p$ by unprojecting the predicted depth $D_{pred}$ using the camera intrinsics $K$ of the target view [S1, unofficial].
    *   Combine all attributes to form the final map $O_t = \{s, q, p, \alpha, c\}$ [S1, unofficial].

6.  **Rendering and Mesh Extraction (Inference):**
    *   **Novel View Synthesis:** Render the scene using perspective-accurate 2D Gaussian Splatting rasterization [S1, unofficial].
    *   **3D Reconstruction:** Render depth maps for all training views $P_i$ using the predicted splat maps $O_i = \Phi(P_i | I_1, ..., I_N)$. Perform TSDF fusion on these $N$ mean splatted depths to extract the mesh $S$. The TSDF voxel size is set to 1.5 [S1, unofficial].

        fpn_feats = self.fpn(images) # Shape: (N, C_f, H, W)

        # Assume target pose is the first pose or specified separately.

        target_pose = poses[0]
        source_poses = poses
        
        warped_feats = []
        for i in range(N):

            # Homography warping

            warped_feats.append(w_feat)

        fine_depths = get_depth_planes(self.num_fine_depth_planes)
        all_depths = torch.cat([coarse_depths, fine_depths], dim=0)
        
        # Weighted sum to get expected depth
        depth_map = weighted_depth_sum(prob_volume, all_depths) # (H, W)
        
        # 4. Gaussian Attribute Branch
        # Pool warped features into target feature map
        target_feat = self.pool_features(warped_feats) # (C_target, H, W)
        
        # Predict s, q, alpha, c
        attr_map = self.attr_net(target_feat) # (H, W, 2+4+1+3) = (H, W, 10)

        # s (2), q (4), alpha (1), c (3) from attr_map
        # p (3) from unprojected depth
        s = attr_map[..., :2]

        alpha = attr_map[..., 6:7]
        c = attr_map[..., 7:10]
        
        # Unproject depth to 3D position p
        # Requires camera intrinsics K (assumed known or part of poses)
        K = get_intrinsics()
        p = unproject_depth(depth_map, K, target_pose) # (H, W, 3)

**Parameters and Losses:**
*   **Training Resolution:** $640 \times 512$ [S1, unofficial].
*   **Optimizer:** Adam, initial learning rate $5 \times 10^{-4}$ [S1, unofficial].
*   **Training Steps:** 300k steps on a single RTX A6000 GPU [S1, unofficial].
*   **Loss Weights:** $\lambda_s = 0.1$, $\lambda_p = 0.05$, $\lambda_\alpha = 0.05$, $\lambda_\beta = 0.05$, $\lambda_\gamma = 0.05$, $\lambda_1 = 0.5$, $\lambda_2 = 1$ [S1, unofficial].
*   **Depth Loss:** A depth loss $L_{depth}$ is applied, guiding the mean 2DGS splatted depth with ground truth depth supervision. This improves mean Chamfer distance by 71.8% (from 4.37 to 1.04) [S1, unofficial].

**Edge Cases and Pitfalls:**
*   Using 3DGS instead of 2DGS causes depth inconsistencies across views, leading to TSDF producing incorrect fusions with warped/disconnected surfaces [S1, unofficial].
*   Prior SOTA generalizable GS methods fail to give coherent reconstructions on TSDF fusion of rendered depth maps [S1, unofficial].

## Operating characteristics
*   **Speed:** Inference time is approximately 0.8s (reproduced 0.88s) on an RTX A6000 GPU [S1, unofficial]. This is nearly two orders of magnitude faster than prior state-of-the-art feed-forward sparse view reconstruction methods based on volume rendering of implicit representations (e.g., 66s for UfoRecon, 32s for GeoTransfer) [S1, unofficial].
*   **Accuracy (NVS):** On the DTU test set, SparSplat achieves PSNR 28.33, SSIM 0.938, and LPIPS 0.073 [S1, unofficial]. It outperforms MVSGaussian in novel-view synthesis, exhibiting sharper results in regions with low input view overlap [S1, unofficial].
*   **Accuracy (Reconstruction):** On the DTU sparse 3D reconstruction benchmark, SparSplat achieves a mean Chamfer distance of 1.04 [S1, unofficial].
*   **Generalization:** Demonstrates strong generalization on BlendedMVS and Tanks and Temples datasets without fine-tuning [S1, unofficial].
*   **Strengths:** Dual advantage of superior reconstruction and novel-view synthesis; fast inference; benefits from foundation model features (MASt3R, DINOv2) [S1, unofficial].
*   **Limitations:** Relies on the quality of foundation model features; TSDF fusion requires careful parameter tuning (voxel size 1.5) [S1, unofficial].

## Background
SparSplat was proposed by Shubhendu Jena et al. in 2025 [S1, unofficial]. It builds upon the MVSGaussian framework [48] but replaces 3D Gaussians with 2D Gaussians to improve geometric consistency for surface reconstruction. It incorporates features from DINOv2 [59] and MASt3R [41] to enhance generalizability from sparse views. The method is designed for applications in robotics, autonomous systems, and AR/VR where fast, sparse-view 3D reconstruction is required [S1, unofficial].
