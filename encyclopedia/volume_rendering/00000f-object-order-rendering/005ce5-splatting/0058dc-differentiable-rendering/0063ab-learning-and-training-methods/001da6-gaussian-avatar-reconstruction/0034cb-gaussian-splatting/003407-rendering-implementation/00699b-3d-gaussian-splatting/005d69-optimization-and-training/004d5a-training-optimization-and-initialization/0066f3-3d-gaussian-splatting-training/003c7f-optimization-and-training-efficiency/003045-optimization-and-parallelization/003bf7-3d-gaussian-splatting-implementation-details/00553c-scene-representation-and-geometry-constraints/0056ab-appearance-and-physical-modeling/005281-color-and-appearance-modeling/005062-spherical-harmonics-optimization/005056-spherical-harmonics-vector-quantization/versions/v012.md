# Spherical Harmonics Vector Quantization

Also called: SH clustering, SH palette

## Overview
Spherical Harmonics Vector Quantization (SH VQ) is a compression technique for 3D Gaussian Splatting that replaces the continuous per-splat SH coefficients with discrete indices pointing to a shared, finite palette of distinct SH vectors [S1, unofficial]. This method significantly reduces the memory footprint of the scene representation by trading minor lighting artifacts for substantial storage savings, making it suitable for constrained environments such as real-time web or mobile rendering [S1, unofficial]. Unlike dimensionality reduction methods that lower the SH degree, SH VQ retains the full high-frequency detail capacity of the original SH basis but approximates the specific coefficients using a limited set of prototypes [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A set of $N$ Gaussian splats, each defined by a vector of SH coefficients $\mathbf{c}_i$. The coefficients exclude the zeroth-order term (treated as base color), resulting in a 45-dimensional vector per splat (15 dimensions per RGB channel) [S1, unofficial].
*   **Output:** A palette of $K$ SH vectors and an index map assigning each splat to its closest palette entry.

**Data Structures**
1.  **Palette:** An array of $K$ vectors, where each vector has 45 components. Stored as FP16 (16-bit floating point) [S1, unofficial].
2.  **Index Map:** An array of $N$ integers, where each integer is 16 bits wide, storing the index into the Palette array [S1, unofficial].

**Parameters**
*   **Palette Size ($K$):** Typically between 4,000 and 16,000 items [S1, unofficial].
*   **Coefficient Dimension:** 45 floats per splat (excluding the DC term) [S1, unofficial].
*   **Index Bit Depth:** 16 bits per splat [S1, unofficial].

**Algorithm Steps**
1.  **Collection:** Gather all $N$ SH coefficient vectors from the scene. Let the dataset be $\mathcal{D} = \{ \mathbf{v}_1, \mathbf{v}_2, \dots, \mathbf{v}_N \}$, where each $\mathbf{v}_i \in \mathbb{R}^{45}$ [S1, unofficial].
2.  **Clustering:** Perform vector quantization on $\mathcal{D}$ to find $K$ cluster centers (the palette). The source recommends a custom mini-batch k-means implementation over standard libraries like scikit-learn or Faiss for speed and quality in this specific high-dimensional context [S1, unofficial].
    *   Let the resulting palette be $\mathcal{P} = \{ \mathbf{p}_1, \mathbf{p}_2, \dots, \mathbf{p}_K \}$ [S1, unofficial].
3.  **Assignment:** For each splat $i$, find the index $j$ of the palette item $\mathbf{p}_j$ that minimizes the Euclidean distance to $\mathbf{v}_i$:
    $$ j_i = \arg \min_{j \in \{1, \dots, K\}} \| \mathbf{v}_i - \mathbf{p}_j \|_2 $$
4.  **Storage:** Store the palette $\mathcal{P}$ and the index array $\mathbf{J} = [j_1, j_2, \dots, j_N]$ [S1, unofficial].

**Pseudocode**
```python
import numpy as np

def spherical_harmonics_vector_quantization(sh_data: np.ndarray, k: int) -> tuple:
    """
    Compress SH coefficients using vector quantization.
    
    Args:
        sh_data: Array of shape (N, 45) containing SH coefficients for N splats.
                 Excludes the 0th-order color term.
        k: Number of palette entries (e.g., 4000 or 16000).
        
    Returns:
        palette: Array of shape (k, 45) containing the cluster centers.
        indices: Array of shape (N,) containing indices into the palette.
    """
    # Step 1: Initialize centroids randomly from the data
    # [G] Standard k-means initialization; source notes custom mini-batch k-means is used
    # for performance, but the logical structure follows k-means.
    n_splats, dim = sh_data.shape
    centroid_indices = np.random.choice(n_splats, k, replace=False)
    centroids = sh_data[centroid_indices].copy()
    
    # Step 2: Mini-batch K-Means Iteration
    # [G] Source specifies a custom implementation for speed. 
    # The following represents the logical convergence steps.
    for iteration in range(100): # [G] Max iterations not specified; typical k-means default
        # Sample a mini-batch
        batch_size = 1024 # [G] Not specified; typical batch size
        batch_indices = np.random.choice(n_splats, batch_size, replace=False)
        batch_data = sh_data[batch_indices]
        
        # Assign batch data to nearest centroid
        # Calculate distances: (batch_size, k)
        # dist = ||x - c||^2 = ||x||^2 + ||c||^2 - 2*x.c
        batch_sq_norms = np.sum(batch_data**2, axis=1, keepdims=True)
        centroid_sq_norms = np.sum(centroids**2, axis=1, keepdims=True).T
        cross_term = batch_data @ centroids.T
        distances = batch_sq_norms + centroid_sq_norms - 2 * cross_term
        
        batch_assignments = np.argmin(distances, axis=1)
        
        # Update centroids based on batch assignments
        for j in range(k):
            members = batch_data[batch_assignments == j]
            if len(members) > 0:
                centroids[j] = np.mean(members, axis=0)
                
    # Step 3: Final Assignment for all splats
    # Calculate distances for all splats to all centroids
    all_sq_norms = np.sum(sh_data**2, axis=1, keepdims=True)
    all_centroid_sq_norms = np.sum(centroids**2, axis=1, keepdims=True).T
    all_cross_term = sh_data @ centroids.T
    all_distances = all_sq_norms + all_centroid_sq_norms - 2 * all_cross_term
    
    indices = np.argmin(all_distances, axis=1)
    
    # Convert palette to FP16 for storage as per source
    palette = centroids.astype(np.float16)
    
    return palette, indices
```

**Edge Cases and Pitfalls**
*   **Curse of Dimensionality:** Clustering millions of splats in 45 dimensions is computationally expensive and slow [S1, unofficial].
*   **Library Choice:** Standard libraries like scikit-learn are too slow for this scale. Faiss is faster but introduces external dependencies; a custom implementation is preferred for performance and dependency management [S1, unofficial].
*   **Index Width:** The index is stored as 16 bits regardless of whether the palette size $K$ exceeds $2^{16}$ (which it does not in the cited range of 4k-16k) [S1, unofficial].

## Operating characteristics
**Time and Memory Complexity**
*   **Memory:** The palette size is small ($K \times 45 \times 2$ bytes for FP16). For $K=16,000$, the palette is ~1.44 MB [S1, unofficial]. The index map is $N \times 2$ bytes. For the 'bike' scene ($N=6.1$ million), the index map is ~12 MB [S1, unofficial].
*   **Time:** Clustering is the bottleneck. The source reports that a custom mini-batch k-means implementation is ~3x faster than Faiss and significantly faster than scikit-learn [S1, unofficial].

**Measured Performance**
*   **Bike Scene (6.1M splats):**
    *   **Low Preset (16k palette):** Total data size 98 MB (Pos) / 41 MB (Rot) / 93 MB (Col); PSNR 35.17 / 35.32 / 35.00 [S1, unofficial].
    *   **Very Low Preset (4k palette):** Total data size 79 MB (Pos) / 33 MB (Rot) / 75 MB (Col); PSNR 32.27 / 30.19 / 31.10 [S1, unofficial].
*   **Comparison:** Compared to uncompressed SH (1.1 GB for SH data alone) or FP16 SH (350 MB), SH VQ reduces SH-related storage to ~13 MB total (palette + indices) [S1, unofficial].

**Strengths and Limitations**
*   **Strengths:** Drastic reduction in memory footprint; retains "shininess" effects better than low-degree SH; usable quality at "Very Low" presets where other compression methods fail [S1, unofficial].
*   **Limitations:** Introduces lighting artifacts due to quantization; clustering time is high due to dimensionality [S1, unofficial].

## Background
This method was developed and documented by Aras Pranckevičius for his Unity-based Gaussian Splatting implementation [S1, unofficial]. It draws on general vector quantization and k-means clustering techniques applied to the specific domain of 3D Gaussian Splatting SH coefficients [S1, unofficial].
