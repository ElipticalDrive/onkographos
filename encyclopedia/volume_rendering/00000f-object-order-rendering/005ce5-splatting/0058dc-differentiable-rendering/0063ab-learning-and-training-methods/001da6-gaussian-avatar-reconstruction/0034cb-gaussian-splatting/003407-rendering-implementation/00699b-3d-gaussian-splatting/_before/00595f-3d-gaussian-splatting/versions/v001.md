# 3D Gaussian Splatting

Also called: 3DGS

## Overview
3D Gaussian Splatting (3DGS) is a novel view synthesis method that represents a scene as a set of anisotropic 3D Gaussians, combining the volumetric representation of Neural Radiance Fields (NeRF) with the rendering speed of point-based techniques [S1, unofficial]. It solves the high computational cost and slow training times of continuous NeRFs by enabling real-time rendering (30fps+) and short training durations through projected alpha blending rather than ray marching [S1, unofficial]. Unlike NeRF, which uses continuous MLPs for density/radiance and ray marching (high cost, slow), 3D Gaussian Splatting uses projected Gaussians and alpha blending (fast, real-time) [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of multi-view photographs of a scene, camera parameters (intrinsic: focal length; extrinsic: position/orientation) estimated via Structure-from-Motion (SfM), and optionally a sparse SfM point cloud for initialization [S1, unofficial].
*   **Outputs:** A rendered image for a novel view, and a set of optimized 3D Gaussian parameters [S1, unofficial].

**Data Structures:**
The scene is represented by a list of $N$ 3D Gaussians. Each Gaussian $i$ stores:
*   **Position:** $\mu_i \in \mathbb{R}^3$ [S1, unofficial].
*   **Shape:** Defined by a scale $s_i \in \mathbb{R}^3$ and a rotation quaternion $q_i \in \mathbb{R}^4$ (or rotation matrix) [S1, unofficial]. These define the covariance matrix $\Sigma_i$ [S1, unofficial].
*   **Opacity:** $\alpha_i \in \mathbb{R}$ [S1, unofficial].
*   **Color:** Spherical Harmonics (SH) coefficients $c_{i,lm}$ for each RGB channel, allowing view-dependent color [S1, unofficial]. For 4 bands of SH, this is ~48 dimensions [S1, unofficial].
*   **Total Parameters:** Typically 30-60 parameters per Gaussian [S1, unofficial].

**Numbered Steps:**

1.  **Initialization:** Initialize Gaussian positions using a sparse SfM point cloud to stabilize convergence. Random initialization is discouraged as it leads to unstable convergence [S1, unofficial].
2.  **Projection:** For each Gaussian, compute its projection onto the image plane using the camera's intrinsic and extrinsic parameters. This involves transforming the 3D covariance matrix $\Sigma$ into screen space [S1, unofficial].
3.  **Sorting:** Sort Gaussians by depth (Z-sort) per tile (e.g., 16x16 tiles) using Radix sort to ensure correct front-to-back rendering order [S1, unofficial].
4.  **Rasterization (Splatting):** For each pixel in a tile, iterate through the sorted Gaussians that overlap the pixel.
5.  **Alpha Blending:** Compute the contribution of each Gaussian to the pixel color using alpha blending. The final color $C$ and opacity $\alpha$ for a pixel are computed as:
    $$ C = \sum_{i \in N} c_i \alpha_i \prod_{j=1}^{i-1} (1 - \alpha_j) $$
    where $c_i$ is the color of Gaussian $i$ evaluated at the view direction, and $\alpha_i$ is its opacity [S1, unofficial].
6.  **Color Evaluation:** Evaluate the SH coefficients based on the view direction to determine $c_i$ [S1, unofficial].
7.  **Loss Computation:** Compute the loss between the estimated image and the ground truth photograph using a combination of L1 loss and D-SSIM [S1, unofficial].
    $$ \mathcal{L} = (1 - \lambda) \mathcal{L}_{L1} + \lambda \mathcal{L}_{D-SSIM} $$
    where $\lambda$ is a weighting factor [S1, unofficial].
8.  **Gradient Update:** Compute gradients (e.g., using Adam) and update Gaussian parameters (position, rotation, scale, opacity, color) in batch [S1, unofficial].
9.  **Adaptive Density Control:** Iteratively adjust the Gaussian count:
    *   **Clone:** Duplicate Gaussians in areas with high gradient/error to capture fine details [S1, unofficial].
    *   **Split:** Divide large Gaussians into smaller ones for precision [S1, unofficial].
    *   **Prune:** Delete Gaussians with low opacity or those that do not contribute significantly to the image [S1, unofficial].
10. **Iteration:** Repeat steps 2-9 for thousands to tens of thousands of iterations until convergence [S1, unofficial].

**Pseudocode:**

```python
def render(gaussians, camera_params, image_width, image_height):
    """
    Renders an image from a set of 3D Gaussians.
    gaussians: List of Gaussian objects with attributes:
        - pos: (3,) position
        - scale: (3,) scale
        - rot: (4,) quaternion
        - opacity: (1,) scalar
        - sh_coeffs: (num_bands * 3,) spherical harmonics coefficients
    camera_params: Object with intrinsic (K) and extrinsic (R, t) matrices.
    """
    # 1. Project Gaussians to 2D
    projected_gaussians = []
    for g in gaussians:
        # Compute 3D covariance Sigma from scale and rot
        R = quaternion_to_rotation_matrix(g.rot)
        S = scale_to_matrix(g.scale)
        Sigma_3D = R @ S @ S.T @ R.T
        
        # Transform to camera space
        Sigma_cam = camera_params.R @ Sigma_3D @ camera_params.R.T
        
        # Project to 2D screen space (Jacobian approximation)
        # This involves camera intrinsics K and depth
        Sigma_2D = project_covariance(Sigma_cam, camera_params.K, g.pos)
        
        projected_gaussians.append({
            'pos_2d': project_point(g.pos, camera_params),
            'cov_2d': Sigma_2D,
            'opacity': g.opacity,
            'sh_coeffs': g.sh_coeffs,
            'depth': g.pos.z # Assuming camera space Z
        })
    
    # 2. Sort Gaussians by depth (Z-sort) per tile
    # Tiles are typically 16x16 pixels
    tiles = create_tiles(image_width, image_height, tile_size=16)
    sorted_gaussians_per_tile = {}
    for tile in tiles:
        # Filter Gaussians overlapping this tile
        tile_gaussians = [g for g in projected_gaussians if overlaps_tile(g, tile)]
        # Radix sort by depth
        tile_gaussians.sort(key=lambda g: g['depth'])
        sorted_gaussians_per_tile[tile] = tile_gaussians
    
    # 3. Rasterize and Alpha Blend
    image = np.zeros((image_height, image_width, 3))
    for tile in tiles:
        tile_gaussians = sorted_gaussians_per_tile[tile]
        for y in range(tile.y, tile.y + tile_size):
            for x in range(tile.x, tile.x + tile_size):
                accumulated_color = np.zeros(3)
                accumulated_alpha = 0.0
                
                for g in tile_gaussians:
                    # Evaluate 2D Gaussian at (x, y)
                    # Mahalanobis distance using Sigma_2D
                    dist_sq = mahalanobis_distance((x, y), g['pos_2d'], g['cov_2d'])
                    
                    # Gaussian weight
                    weight = exp(-0.5 * dist_sq)
                    
                    # View-dependent color from SH
                    view_dir = get_view_direction(x, y, camera_params)
                    color = evaluate_sh(g['sh_coeffs'], view_dir)
                    
                    alpha = g['opacity'] * weight
                    
                    # Alpha blending
                    # C_new = C_old + c * alpha * (1 - accumulated_alpha)
                    # alpha_new = alpha_old + alpha * (1 - accumulated_alpha)
                    
                    accumulated_color += color * alpha * (1 - accumulated_alpha)
                    accumulated_alpha += alpha * (1 - accumulated_alpha)
                    
                    if accumulated_alpha > 0.99: # Early exit optimization
                        break
                
                image[y, x] = accumulated_color
                
    return image

def train_step(gaussians, camera_params, gt_image, lr_scheduler):
    """
    Performs one training step.
    """
    # Forward pass
    pred_image = render(gaussians, camera_params, gt_image.shape[0], gt_image.shape[1])
    
    # Loss computation
    l1_loss = l1_loss(pred_image, gt_image)
    ssim_loss = d_ssim_loss(pred_image, gt_image)
    loss = (1 - 0.2) * l1_loss + 0.2 * ssim_loss # Typical lambda=0.2
    
    # Backward pass
    gradients = compute_gradients(loss, gaussians)
    
    # Update parameters
    update_gaussians(gaussians, gradients, lr_scheduler.current_lr)
    
    # Adaptive Density Control
    gaussians = adaptive_density_control(gaussians, gradients)
    
    return loss
```

**Parameters:**
*   **Number of Gaussians:** Tens of thousands to millions for complex outdoor scenes [S1, unofficial].
*   **SH Bands:** Typically 4 bands for RGB, resulting in ~48 color parameters per Gaussian [S1, unofficial].
*   **Tile Size:** 16x16 pixels is common for sorting [S1, unofficial].
*   **Optimizer:** Adam [S1, unofficial].
*   **Loss Weights:** L1 and D-SSIM combination [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Initialization:** Random initialization leads to unstable convergence. Sparse SfM point cloud initialization is recommended [S1, unofficial].
*   **Memory Usage:** Complex scenes require millions of Gaussians, increasing memory usage. However, tile-based parallel sorting and software rasterization allow handling this without real-time performance loss [S1, unofficial].
*   **Generalization:** The method is scene-specific and does not generalize to unknown scenes without re-training [S1, unofficial].
*   **Artifacts:** Artifacts may appear in out-of-domain views (unobserved regions) [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Training time is several minutes to tens of minutes for high quality, comparable to InstantNGP speed but with Mip-NeRF360 class quality [S1, unofficial].
*   **Memory Complexity:** Memory usage scales with the number of Gaussians. For complex scenes, this can be millions of Gaussians, leading to significant memory consumption, but manageable with efficient data structures [S1, unofficial].
*   **Rendering Performance:** Real-time (>30fps) at 1080p resolution with millions of Gaussians [S1, unofficial].
*   **Strengths:** Real-time rendering, short training times, high visual quality comparable to NeRF [S1, unofficial].
*   **Limitations:** Scene-specific (no generalization), potential artifacts in unobserved regions, high memory usage for complex scenes [S1, unofficial].
*   **When to use:** When real-time novel view synthesis is required for a known scene with high visual fidelity [S1, unofficial].
*   **When not to use:** For unknown scenes or when generalization to new scenes is required without re-training [S1, unofficial].

## Background
3D Gaussian Splatting was introduced as a novel approach to novel view synthesis, building on the success of NeRF while addressing its computational limitations [S1, unofficial]. It combines the volumetric representation of NeRF with the speed of point-based rendering [S1, unofficial]. The method was developed to provide real-time rendering capabilities without sacrificing the high quality achieved by NeRF-based methods [S1, unofficial]. It is widely used in computer graphics and vision for applications requiring fast and high-quality 3D scene reconstruction and rendering [S1, unofficial].
