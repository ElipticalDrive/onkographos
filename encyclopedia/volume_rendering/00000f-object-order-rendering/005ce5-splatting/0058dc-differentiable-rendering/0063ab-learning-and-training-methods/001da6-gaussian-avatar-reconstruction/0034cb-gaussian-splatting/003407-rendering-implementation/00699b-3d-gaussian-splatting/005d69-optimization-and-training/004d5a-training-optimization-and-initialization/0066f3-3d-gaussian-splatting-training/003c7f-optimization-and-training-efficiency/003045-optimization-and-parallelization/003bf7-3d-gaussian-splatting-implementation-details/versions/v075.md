# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, GSGEN Implementation Details, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific hyperparameters, data structures, and optimization schedules required to implement the 3D Gaussian Splatting (3DGS) training pipeline, including densification, pruning, and hardware-aware rasterization. It serves as the operational reference for the parent method [Optimization and Parallelization](6233-optimization-and-parallelization.md), translating high-level differentiable rendering principles into concrete code-level decisions. It distinguishes itself from sibling methods like [MaskGaussian Gradient Computation](4254-maskgaussian-gradient-computation.md) or [Parallelization for Backpropagation](5989-parallelization-for-backpropagation.md) by focusing on the *configuration* of the standard 3DGS algorithm rather than novel architectural changes or distributed communication protocols.

## How it works

### Inputs and Outputs
*   **Inputs:** A set of $N$ training images with known camera poses (extrinsics $C_i$ and intrinsics), and an initial point cloud (typically from Structure-from-Motion, SfM) providing initial Gaussian positions.
*   **Outputs:** A set of optimized 3D Gaussian primitives $\mathcal{G} = \{G_j\}_{j=1}^{M}$, where each $G_j$ is defined by position $\mu_j$, covariance $\Sigma_j$ (or scale $s_j$ and rotation $q_j$), opacity $\alpha_j$, and spherical harmonic coefficients $\mathbf{c}_j$ for view-dependent color.

### Data Structures
The implementation relies on the `gsplat` library [S3] or custom CUDA kernels [S2]. Key data layouts include:
1.  **Gaussian Attributes:** Stored in contiguous arrays (SoA - Structure of Arrays) for efficient vectorized access.
    *   `positions`: $M \times 3$ float32.
    *   `scales`: $M \times 3$ float32 (log-space scale).
    *   `rotations`: $M \times 4$ float32 (quaternions).
    *   `opacities`: $M \times 1$ float32.
    *   `sh_coeffs`: $M \times K \times 3$ float32, where $K$ is the number of SH bands. For SH Degree 1, $K=4$ [S3].
2.  **Rasterization State:**
    *   Tile-based assignment: Gaussians are mapped to image tiles.
    *   Depth sorting: Per-tile list of Gaussian indices sorted by depth.
    *   Accumulators: Per-pixel color and opacity buffers.

### Training Loop and Optimization Schedule
The training process minimizes a loss $\mathcal{L}$ between rendered images and ground truth, typically using the Adam optimizer [S3].

**Parameters:**
*   Optimizer: Adam [S3].
*   Learning Rate: $1 \times 10^{-3}$ [S3].
*   SH Degree: 1 [S3].
*   Loss Weights: $\lambda_{SDS} = 0.1$, $\lambda_{3D} = 0.01$ (for text-to-3D); $\lambda_r = 0.2$, $\lambda_e = 0.1$ (for volume-based) [S1, S3].

**Step-by-Step Procedure:**

1.  **Initialization:** Initialize Gaussians from SfM points. Set initial scales based on the neighborhood density [S4].
2.  **Iteration Loop:**
    a.  **Random View Selection:** Randomly select a single image from the training set as supervision [S3].
    b.  **Differentiable Rasterization:** Render the image using the current Gaussian set $\mathcal{G}$ and camera pose. This involves projecting 3D Gaussians to 2D ellipses, sorting them by depth, and alpha-blending [6233-optimization-and-parallelization].
    c.  **Loss Computation:** Compute $\mathcal{L}$ (e.g., L1 + SSIM) between rendered and ground truth images.
    d.  **Backpropagation:** Compute gradients $\frac{\partial \mathcal{L}}{\partial \theta}$ for all Gaussian parameters $\theta$ [6233-optimization-and-parallelization].
    e.  **Optimizer Step:** Update $\mathcal{G}$ using Adam.
    f.  **Densification (Every 100-500 iterations):**
        *   **Splitting:** Split Gaussians with high view-space position gradients. Threshold $T_{pos} = 0.02$ [S1]. Interval: every 500 iterations [S1].
        *   **Cloning:** Clone Gaussians with high scale but low gradient to fill gaps. Interval: every 1000 iterations (compactness-based) [S1].
    g.  **Pruning (Every 200 iterations):**
        *   Remove Gaussians with opacity $\alpha < \alpha_{min} = 0.05$ [S1].
        *   Remove Gaussians with excessively large world-space or view-space radius [S1].
    h.  **Regularization:** Apply automatic scaling factor to loss values to improve half-precision training stability [S2].

### Pseudocode

```python
# Configuration
LR = 1e-3
ALPHA_MIN = 0.05
T_POS = 0.02
DENSIFY_INTERVAL_SPLIT = 500
DENSIFY_INTERVAL_CLONE = 1000
PRUNE_INTERVAL = 200
SH_DEGREE = 1

# Initialization
gaussians = initialize_from_sfm(points)
optimizer = Adam(gaussians.parameters(), lr=LR)

for iteration in range(MAX_ITERATIONS):
    # 1. Sample View
    image_idx = random.choice(training_images)
    gt_image = training_images[image_idx].color
    camera_pose = training_images[image_idx].pose
    
    # 2. Forward Pass (Rasterization)
    # Uses gsplat or custom CUDA kernels [S2, S3]
    rendered_image = rasterize(gaussians, camera_pose, SH_DEGREE)
    
    # 3. Loss Computation
    # L = L1 + SSIM (standard) or SDS/3D loss for text-to-3D [S1, S3]
    loss = compute_loss(rendered_image, gt_image)
    
    # Apply scaling for half-precision stability if using FP16 [S2]
    loss = loss * loss_scaling_factor
    
    # 4. Backward Pass
    optimizer.zero_grad()
    loss.backward()
    
    # 5. Optimizer Step
    optimizer.step()
    
    # 6. Densification and Pruning
    if iteration % DENSIFY_INTERVAL_SPLIT == 0:
        # Split Gaussians with high position gradient
        split_gaussians(gaussians, threshold=T_POS)
        
    if iteration % DENSIFY_INTERVAL_CLONE == 0:
        # Clone Gaussians for compactness
        clone_gaussians(gaussians)
        
    if iteration % PRUNE_INTERVAL == 0:
        # Prune low opacity and large radius Gaussians
        prune_gaussians(gaussians, alpha_min=ALPHA_MIN)
```

### Edge Cases and Pitfalls
*   **Scene Extent Bias:** Default 3DGS calculates scene extent based on the furthest camera distance from the average camera position. If cameras are clustered (e.g., orbiting a small object in a large environment), this leads to an underestimated scene extent, causing incorrect splitting/pruning [S4]. **Fix:** Use the corrected scene extent $e'_{\text{scene}}$ based on the SfM point cloud:
    $$ e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2 $$
    where $\bar{C}$ is the average camera position and $p_i$ are SfM points [S4].
*   **Half-Precision Instability:** Training in FP16 can lead to gradient underflow/overflow. **Fix:** Use automatic loss scaling [S2].
*   **Register Pressure:** High-dimensional feature vectors can cause register spilling in CUDA kernels. **Fix:** Use half-precision memory fetches for feature vectors during rasterization [S2].

## Subtopics

### Corrected Scene-Extent
A method to calculate scene extent based on the SfM point cloud rather than camera positions to avoid bias from camera distribution (e.g., orbiting a small object in a large environment) [S4]. It sets itself apart from standard 3DGS by decoupling densification thresholds from camera-centric metrics, ensuring consistent Gaussian sizing across diverse capture setups [S4].

### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ to selectively enlarge covariances, creating pixel-wise variable blur kernels that match spatially varying scene blurriness [S5]. It distinguishes itself from naive Gaussian blur (which applies a single kernel to the whole image) by allowing spatially varying blur shapes and magnitudes, enabling effective deblurring of defocus artifacts [S5].

### Denoise-GS
A self-supervised denoising method for sparse-view 3D Gaussian Splatting that combines unsupervised image denoising (Noise2Void) with explicitly differentiable 3DGS [S6]. It solves the problem of suboptimal reconstruction in noisy, sparse-view scenarios by using a two-round process: initial denoising and training, followed by fine-tuning the denoiser with a composite loss based on rendered views [S6]. Unlike supervised methods, it requires no paired clean data [S6].

### Multi-Scale Constraint
A technique using position-aware point adaptive control to apply different scales to Gaussians based on viewer distance, improving rendering of distant objects [S7]. It sets itself apart from standard densification by using a distance-dependent scaling factor $\gamma(\mu)$ to adjust cloning and splitting thresholds, preventing distant objects from becoming overly fragmented [S7].

### LS-Gaussian Viewpoint Transformation
An algorithm that leverages inter-frame continuity for efficient sparse rendering by transforming the viewpoint between consecutive frames, rather than rendering each frame separately [S8]. It distinguishes itself from naive pixel warping by operating at the tile/Gaussian level, enabling sparse rendering (e.g., one full render every 6 frames) on resource-constrained edge platforms like Jetson AGX Orin [S8].

### Camera Localisation for Convergence Basin
A method to localize camera pose by minimizing only the photometric error against the ground-truth colour image of the target view, fixing the initial Gaussian set $G_{init}$ during optimization [S9, unofficial]. It sets itself apart by providing a robust initialization for SLAM tasks, ensuring convergence within 1cm of the target view within 1000 iterations [S9, unofficial].

### DiffGS Framework
Applies an optimization process during Gaussian extraction to optimize Gaussians to exact locations, using a truncation function $\lambda$ and projection function $\tau$ (e.g., exponential or linear) [S10]. It distinguishes itself by achieving high fidelity with fewer Gaussians (e.g., 350K Gaussians yielding PSNR 34.01) compared to standard 3DGS [S10].

### Opacity Offset Table for DSA
A method that constructs an opacity offset table to model changes in digital subtraction angiography [S11]. It sets itself apart by adapting the opacity attribute to handle dynamic contrast changes in medical imaging [S11].

### Conditional Splat Approximation
A technique to approximate the influence range of a 3D Gaussian on a slice by using a 2D ellipse splat scaled by the marginal factor, which closely matches the true iso-probability contours [S12, unofficial]. It distinguishes itself by providing an accurate and efficient approximation for slice-based rendering or tomographic reconstruction [S12, unofficial].

### 3DGS Uncertainty Calculation via Fisher Information
Computes an uncertainty attribute for 3D Gaussians based on the negative log-likelihood of the rendered pixel value, interpreted as Fisher information [S13]. It sets itself apart by providing a differentiable uncertainty metric $\bar{C}_{V;G} = -\log p_f(\pi|V; G)$, which can be used to guide refinement or sampling strategies [S13].

## Operating characteristics

*   **Time Complexity:** $O(N \cdot M)$ per iteration, where $N$ is the number of pixels/tiles and $M$ is the number of Gaussians. Sorting and rasterization are linear in the number of active Gaussians per tile.
*   **Memory Complexity:** $O(M \cdot D)$, where $D$ is the dimensionality of Gaussian attributes (position, scale, rotation, opacity, SH coefficients). For SH Degree 1, $D \approx 3 + 3 + 4 + 1 + 12 = 23$ floats per Gaussian.
*   **Measured Performance:** On NVIDIA V100, EVolSplat achieves 83.81 FPS with 10.41 GB memory on Waymo dataset [S3]. LS-Gaussian achieves 5.41× speedup over edge GPU baseline on Jetson AGX Orin [S8].
*   **Strengths:** Real-time rendering speeds (100+ FPS on modern GPUs), high visual fidelity, explicit representation allows for easy editing and compression.
*   **Limitations:** High memory usage for large scenes, sensitivity to initialization (SfM quality), and potential for "floaters" in textureless regions.
*   **When to Use:** Real-time novel view synthesis, interactive applications, scenarios requiring high visual fidelity.
*   **When Not to Use:** Memory-constrained embedded systems without acceleration, scenes with extreme dynamic range or complex lighting not captured by SH.

## Background

3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1, S2, S3]. It revolutionized radiance field representation by using explicit 3D Gaussians instead of implicit neural fields, enabling real-time differentiable rendering. The method builds on the parent principles of differentiable rasterization [6233-optimization-and-parallelization]. Subsequent work has focused on optimizing the training process, handling specific artifacts (blur, noise), and adapting the representation for various domains (medical, large-scale, dynamic) [S1-S13].
