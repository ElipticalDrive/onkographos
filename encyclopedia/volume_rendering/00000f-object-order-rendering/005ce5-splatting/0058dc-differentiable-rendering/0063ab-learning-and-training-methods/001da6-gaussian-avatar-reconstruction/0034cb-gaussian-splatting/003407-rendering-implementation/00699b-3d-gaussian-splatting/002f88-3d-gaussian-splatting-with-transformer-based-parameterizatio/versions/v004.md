# 3D Gaussian Splatting with Transformer-based Parameterization

Also called: GS-LRM, Transformer-based 3D Gaussian Splatting, Feed-forward 3D Gaussian Splatting

## Overview
This method enables real-time novel view synthesis by replacing the iterative optimization of standard 3D Gaussian Splatting with a feed-forward neural network that predicts Gaussian parameters directly from input images [S1]. It solves the problem of slow training times and view-dependent artifacts inherent in pixel-aligned optimization by using a transformer to aggregate multi-view features into a shared representation [S1]. Unlike its parent method, which relies on differentiable rendering to optimize scene parameters, this approach uses a transformer block to decode tokens directly into Gaussian attributes, enabling immediate inference [S1].

## How it works
The method operates as a feed-forward network that takes a small set of input views and outputs a set of 3D Gaussians suitable for rasterization.

**Inputs and Outputs:**
*   **Input:** A sequence of $N$ input images (typically $N=2$ to $4$) and their corresponding camera parameters (extrinsics and intrinsics) [S1].
*   **Output:** A set of 3D Gaussian primitives, each defined by position, covariance (scale and rotation), opacity, and spherical harmonic coefficients for color [S1].

**Data Structures:**
The core data structure is a sequence of tokens processed by the transformer. Each token represents a spatial location or feature vector derived from the input images and camera poses [S1]. The output of the transformer is a sequence of tokens that are decoded into the Gaussian parameters [S1].

**Steps:**
1.  **Tokenization:** The input images and camera parameters are tokenized. This involves extracting features from the images and encoding the camera poses [S1].
2.  **Concatenation:** The image tokens and camera parameter tokens are concatenated into a single sequence [S1].
3.  **Transformer Processing:** The concatenated sequence is passed through a transformer block. The transformer attends to the multi-view information to resolve ambiguities and align features across views [S1].
4.  **Decoding:** The output tokens from the transformer are decoded into the final Gaussian parameters (position, scale, rotation, opacity, color) [S1].

**Formulas:**
The specific mathematical formulation for the tokenization and decoding layers is not provided in the sources [S1]. The general process is described as:
$$ \text{Gaussians} = \text{Decode}(\text{Transformer}(\text{Concat}(\text{Images}, \text{Cameras}))) $$
where $\text{Concat}$ combines the feature representations of the input images and camera parameters, and $\text{Decode}$ maps the transformer output to Gaussian attributes [S1].

**Parameters:**
*   **Number of Input Views:** Typically 2 to 4 images [S1].
*   **Transformer Architecture:** Not specified in detail, but described as a "transformer block" [S1].

**Edge Cases and Pitfalls:**
*   **Scale Ambiguity:** In scenarios with minimal view overlap, scale ambiguity can occur. This is addressed in related methods like NoPoSplat by using a canonical coordinate system and intrinsics token embeddings, but the base method's handling is not explicitly detailed [S1].
*   **Floaters:** Pixel-aligned methods are prone to alignment errors such as floaters. This method aims to mitigate this by aggregating multi-view features, though the extent of reduction is not quantified [S1].

## Subtopics

### [VolSplat](7674-volsplat.md)
VolSplat is a multi-view feed-forward framework for 3D Gaussian Splatting that replaces the standard pixel-aligned Gaussian prediction with a voxel-aligned prediction strategy. It solves the problems of view-biased density distributions and alignment errors (such as floaters) inherent in pixel-aligned methods by aggregating multi-view features into a shared 3D voxel grid before regressing Gaussian parameters. Unlike its parent method, which uses a transformer to decode tokens directly into Gaussian parameters, VolSplat explicitly constructs a 3D voxel feature grid via depth unprojection and refines it with a sparse 3D decoder to enable adaptive density control based on volumetric scene complexity.

### Sequential Gaussian Attribute Decoding
A decoder architecture that estimates 3D Gaussian Splatting attributes (color, opacity, rotation, scale, position offset) sequentially rather than in parallel, using prior attribute information to reduce degrees of freedom and create dependencies between attributes [S2]. It differs from parallel decoders (e.g., HUGS) which compute all attributes at once. Sequential decoding reduces high degrees of freedom for each decoder, allowing for easier specialization [S2]. The process involves:
1.  Forwarding tri-plane features to the first decoder to estimate color [S2].
2.  Feeding the estimated color and tri-plane features to the next decoder to estimate opacity [S2].
3.  Iteratively decoding remaining attributes in the order: rotation, then scale, then position offset, feeding all preceding attributes and tri-plane features into each subsequent decoder [S2].
The last decoder receives all preceding attributes along with the tri-plane features [S2]. The intuition is that, for instance, the scale decoder benefits from information about the color or rotation to decide the Gaussian size [S2].
*   **Parameters:** Hidden layers: 3 layers, 128 neurons each, GELU activation [S2]. Output layer activation: None for all attributes except scale, which uses inverted Softplus to prevent excessive GPU memory usage [S2].

## Operating characteristics
*   **Time Complexity:** Not given in the sources. However, as a feed-forward method, it is significantly faster to train than iterative optimization methods like standard 3D Gaussian Splatting [S1].
*   **Memory Complexity:** Not given in the sources. The inverted Softplus activation in sequential decoding is used to avoid excessive GPU memory usage during rasterization [S2].
*   **Performance:** Achieves superior novel view synthesis quality, especially in scenarios with minimal view overlap, when compared to pixel-aligned methods [S1].
*   **Strengths:** Real-time inference after training; reduces view-biased artifacts; handles multi-view consistency via transformer attention [S1].
*   **Limitations:** Requires known camera poses (unless using variants like NoPoSplat) [S1]; performance depends on the quality of the transformer's feature aggregation [S1].

## Background
The method originates from the need to accelerate the training process of 3D Gaussian Splatting, which traditionally relies on iterative optimization [S1]. It builds upon earlier feed-forward methods like MVSplat and PixelSplat, which combined multi-view feature extraction through transformers and cost volumes [S1]. GS-LRM specifically tokenizes images and camera parameters to predict Gaussians directly [S1]. The sequential decoding approach was introduced to improve the efficiency and specialization of Gaussian attribute prediction in generative models [S2].
