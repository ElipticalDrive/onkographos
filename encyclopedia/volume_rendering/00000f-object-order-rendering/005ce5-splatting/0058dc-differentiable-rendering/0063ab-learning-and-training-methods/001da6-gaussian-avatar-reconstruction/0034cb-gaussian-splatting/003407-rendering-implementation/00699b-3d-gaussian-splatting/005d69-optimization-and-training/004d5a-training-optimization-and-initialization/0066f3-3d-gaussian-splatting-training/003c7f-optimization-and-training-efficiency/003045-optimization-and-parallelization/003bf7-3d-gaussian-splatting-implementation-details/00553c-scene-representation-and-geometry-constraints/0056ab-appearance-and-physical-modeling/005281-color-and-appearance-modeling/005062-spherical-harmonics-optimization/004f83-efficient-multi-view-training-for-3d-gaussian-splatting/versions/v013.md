# Efficient Multi-View Training for 3D Gaussian Splatting

Also called: Multi-View Mini-Batch Training for 3DGS, Thread-Efficient Partial Rendering for Multi-View 3DGS

## Overview
This method enables stable optimization of 3D Gaussian Splatting (3DGS) by training on multiple views per iteration, addressing the high variance of gradients inherent in standard single-view training. It overcomes the rasterization overhead and adaptive density control (ADC) incompatibilities of naive multi-view rendering through thread-efficient partial rendering and 3D-space loss computation. Unlike standard 3DGS which processes one image per iteration to avoid tile-based rasterizer idle threads, this approach allows gathering individual pixels from multiple images, resulting in smaller mini-batch gradient variance and more stable convergence [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of $N$ training images with corresponding camera poses; 3D Gaussian primitives defined by mean $\boldsymbol{\mu}$, covariance $\boldsymbol{\Sigma}$ (derived from scale $S$ and rotation $R$), opacity $o$, and spherical harmonic coefficients $\mathbf{c}$.
*   **Outputs:** Updated Gaussian parameters $\boldsymbol{\mu}, \boldsymbol{\Sigma}, o, \mathbf{c}$ and optimized scene representation.

**Data Structures:**
The rasterizer uses a tile-based architecture. The image is split into tiles. A single thread block is allocated to a single tile. Threads within a block cooperate to preprocess Gaussians and render pixels. A thread is freed only when all peer threads in the same block have completed their work [S1, unofficial].

**Rendering Equation:**
The rendered color $\hat{C}(p)$ for pixel $p$ is computed via alpha-blending of sorted 2D projected Gaussians $\{G_j\}_{j=1}^M$:
$$ \hat{C}(p) = \sum_{i=1}^{M} c_i T_i o_i G_i(p) $$
where:
*   $T_i = \prod_{k=1}^{i-1} (1 - o_k G_k(p))$ is the transmittance.
*   $G_i(p) = \exp\left(-\frac{1}{2}(p - \boldsymbol{\mu}'_i)^T (\boldsymbol{\Sigma}'_i)^{-1} (p - \boldsymbol{\mu}'_i)\right)$ is the 2D Gaussian density.
*   $\boldsymbol{\mu}'$ and $\boldsymbol{\Sigma}'$ are the projected 2D mean and covariance derived from the 3D parameters.
*   $c_i$ is the view-dependent color (radiance) and $o_i$ is the opacity [S1, unofficial].

**Variance Estimation:**
The variance of the mini-batch gradients $\nabla \bar{\phi}_k$ is estimated to compare single-view and multi-view stability. The variance of vectors $x$ is defined as $V(x) := E[\|x - \mu\|_2^2]$ where $E[x] = \mu$. The variance for a mini-batch $B_k$ sampled from set $S$ is estimated via Monte Carlo sampling:
$$ V_{B_k \in S} (\nabla \bar{\phi}_k) = E[\|\nabla \bar{\phi}_k - P(w_t)\|_2^2] $$
where $P(w_t)$ is the projection of the gradient at weights $w_t$ [S1, unofficial].

**Algorithm Steps:**
1.  **Mini-batch Selection:** Randomly sample $K$ mini-batches from the dataset $D$ (consisting of $R = N \times M$ rays/pixels) to estimate gradient variance [S1, unofficial].
2.  **Thread-Efficient Partial Rendering:**
    *   Instead of rendering full images for multiple views (which causes idle threads in the tile-based rasterizer), select specific pixels from multiple images to form a mini-batch.
    *   Map these pixels to their respective tiles.
    *   Execute the rasterizer such that threads are not blocked waiting for peers in other tiles or views, mitigating the overhead of naive multi-view rendering [S1, unofficial].
3.  **Forward Pass:** Compute $\hat{C}(p)$ for the selected pixels using the standard 3DGS rasterization pipeline [S1, unofficial].
4.  **Loss Computation:** Compute the loss using a D-SSIM metric adapted for 3D space. Standard D-SSIM assumes single-view planes; this method computes the loss directly in 3D space to ensure compatibility with multi-view pixel sampling [S1, unofficial].
5.  **Backward Pass:** Compute gradients $\nabla \bar{\phi}_k$ for the selected pixels.
6.  **Parameter Update:** Update weights $w$ using the learning rate $\eta_t$:
    $$ w_{t+1} = w_t - \eta_t \nabla \bar{\phi}_k (w_t) $$
    where $\nabla \bar{\phi}_k (w_t) = \frac{1}{|B_k|} \sum_{i \in B_k} \nabla \phi_i (w_t)$ [S1, unofficial].
7.  **Adaptive Density Control (ADC) Adjustment:**
    *   Standard ADC assumes all 2D positional gradients reside within a single image plane.
    *   In multi-view training, gradients come from different image planes. Arithmetic between these vectors in different spaces is invalid for standard ADC.
    *   The method requires a modified densification strategy that operates in 3D space or aggregates gradients appropriately before densification decisions, avoiding suboptimal densification caused by mixing vectors from different spaces [S1, unofficial].

**Pseudocode:**
```python
def train_step(model, dataset, batch_size, num_views, learning_rate):
    # 1. Sample pixels from multiple views
    # Instead of picking one full image, pick pixels from 'num_views' images
    selected_pixels = []
    for v in range(num_views):
        view_idx = random.choice(dataset.views)
        # Select a subset of pixels from this view
        pixels = random.sample(dataset.views[view_idx].pixels, batch_size // num_views)
        selected_pixels.extend(pixels)
    
    # 2. Thread-Efficient Partial Rendering
    # Render only the selected pixels across the selected views
    # The rasterizer must handle partial tile updates to avoid idle threads
    rendered_colors = partial_rasterize(model, selected_pixels)
    
    # 3. Compute Loss in 3D Space
    # Use a 3D-compatible D-SSIM loss instead of standard 2D D-SSIM
    ground_truth = get_ground_truth(selected_pixels)
    loss = compute_3d_dssim_loss(rendered_colors, ground_truth)
    
    # 4. Backpropagation
    gradients = compute_gradients(loss, model)
    
    # 5. Update Parameters
    model.update_parameters(gradients, learning_rate)
    
    # 6. Adaptive Density Control (3D-aware)
    # Aggregate positional gradients in 3D space before densification
    # to avoid arithmetic between vectors in different image planes
    update_density_control_3d(model, gradients)
```

**Parameters:**
*   $\eta_t$: Learning rate. Typical values are not specified in the source, but standard 3DGS values apply [S1, unofficial].
*   $K$: Number of sampled mini-batches for variance estimation [S1, unofficial].
*   $N$: Number of training images [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Idle Threads:** Naive multi-view rendering (rendering full images) causes significant overhead because the tile-based rasterizer allocates one block per tile. If some views finish earlier, threads become idle [S1, unofficial].
*   **ADC Incompatibility:** Standard ADC fails in multi-view training because it assumes gradients are in a single plane. Performing arithmetic on gradients from different image planes leads to suboptimal densification [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The method reduces the overhead of multi-view rendering compared to naive approaches by using thread-efficient partial rendering. However, it is generally more expensive per iteration than single-view training due to the complexity of managing multiple views and 3D-space loss computation.
*   **Memory Complexity:** Requires storing gradients and intermediate states for multiple views simultaneously.
*   **Performance:** Multi-view mini-batch training results in smaller variance of mini-batch gradients compared to single-view training, leading to more stable optimization [S1, unofficial].
*   **Strengths:** More stable optimization; lower gradient variance; better utilization of parallel hardware through thread-efficient rendering.
*   **Limitations:** Requires modified ADC and loss functions; more complex implementation than standard single-view 3DGS.
*   **When to use:** When training stability is prioritized over raw iteration speed; when hardware allows for efficient partial rendering.
*   **When not to use:** When strict single-view ADC compatibility is required without modification; when hardware rasterizer does not support efficient partial rendering.

## Background
3D Gaussian Splatting (3DGS) has emerged as a preferred choice for inverse rendering due to its superior rendering speed compared to Neural Radiance Fields (NeRF) [S1, unofficial]. Standard 3DGS uses single-view mini-batch training (one image per iteration) because its rasterization pipeline makes gathering individual pixels from multiple images difficult, requiring rendering every pixel of all images in a single iteration which incurs considerable overhead [S1, unofficial]. In contrast, NeRF implicitly benefits from multi-view learning. The method was proposed by Minhyuk Choi, Injae Kim, and Hyunwoo J. Kim from Korea University and KAIST, published in June 2025 [S1, unofficial].
