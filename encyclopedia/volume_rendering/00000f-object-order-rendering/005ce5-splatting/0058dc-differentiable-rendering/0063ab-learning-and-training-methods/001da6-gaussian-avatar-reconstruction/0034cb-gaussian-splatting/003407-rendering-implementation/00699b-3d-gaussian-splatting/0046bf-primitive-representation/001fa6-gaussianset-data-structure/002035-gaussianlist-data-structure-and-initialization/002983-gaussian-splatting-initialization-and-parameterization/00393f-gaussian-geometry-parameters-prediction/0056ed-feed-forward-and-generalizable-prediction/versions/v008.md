# Feed-forward and Generalizable Prediction

Also called: Feed-forward 3D Gaussian Splatting, Generalizable Gaussian Splatting

## Overview
Feed-forward and Generalizable Prediction refers to methods that estimate 3D Gaussian Splatting parameters directly from a set of input images in a single forward pass, eliminating the iterative per-scene optimization required by standard 3D Gaussian Splatting [S1]. This family solves the problem of slow reconstruction and the dependency on Structure-from-Motion (SfM) preprocessing by leveraging learned priors from large-scale datasets [S1]. What sets this approach apart from iterative inverse rendering is the shift from optimization-based recovery to regression-based prediction, enabling real-time or near-real-time novel view synthesis and reconstruction [S1].

## Shared principles
The core mechanism of this family involves a neural network that takes one or more input images as input and outputs a set of 3D Gaussian primitives $\mathcal{G} = \{\mu_k, \Sigma_k, c_k, \alpha_k\}_{k=1}^K$ [S1]. The network is trained end-to-end on large-scale multi-view datasets to generalize across scenes [S1].

Key shared components include:
1.  **Feature Extraction:** A backbone network (often Vision Transformers or CNNs) extracts multi-scale features from input images [S1].
2.  **Multi-View Fusion:** Features from multiple views are aggregated to establish dense correspondences and depth information. This is often achieved via cost volumes, attention mechanisms, or foundation model features (e.g., MASt3R, DINOv2) [S1].
3.  **Parameter Regression:** A decoder head predicts Gaussian attributes (position, scale, rotation, opacity, color) for each pixel or token [S1].
4.  **Differentiable Rendering:** The predicted Gaussians are rendered using differentiable rasterization to compute photometric losses (e.g., L1, SSIM, LPIPS) for training [S1].

Mathematically, the prediction function is defined as:
$$ \mathcal{G} = \Phi(\{I_i\}_{i=1}^N; \theta) $$
where $\Phi$ is the feed-forward network with parameters $\theta$, and $\{I_i\}$ are the input images [S1].

## Subtopics

### [AnySplat Pipeline](12847-anysplat-pipeline.md)
AnySplat is a feed-forward method that predicts scene geometry and appearance directly from uncalibrated input images, eliminating the need for Structure-from-Motion (SfM) preprocessing. It differs from sibling methods like Splatt3R and ZeroGS by explicitly predicting camera poses and depth maps alongside Gaussian parameters through a unified transformer-based architecture, enabling end-to-end differentiable training with geometry supervision.

### [FineSplat](15257-finesplat.md)
FineSplat is a feed-forward 3D Gaussian Splatting framework that predicts a set of 3D Gaussians from $N$ context views using a two-stage dual-grouping strategy to balance local detail preservation with global multi-view reasoning. It builds on [Feed-forward and Generalizable Prediction](15832-feed-forward-and-generalizable-prediction.md) by employing high-resolution 4x4 patch tokens and a dual-grouping mechanism (view-wise and 3D spatial locality) to preserve fine-grained visual information while avoiding the computational costs of global multi-view attention. Unlike sibling methods such as [YoNoSplat](12847-anysplat-pipeline.md) and [ZipSplat](16425-zerogs.md) which use coarser 14x14 patches and global or broader interactions, FineSplat restricts attention scope in Stage 1 and uses serialized attention in Stage 2 to connect tokens across view groups once lifted to 3D.

### [SparSplat](15813-sparsplat.md)
SparSplat is a generalizable, feed-forward model that maps a set of sparse input images to 2D Gaussian Splatting (2DGS) parameters in a single forward pass to perform both 3D shape reconstruction and novel view synthesis. It differs from its sibling [MVSGaussian](12847-anysplat-pipeline.md) by using 2D primitives instead of 3D Gaussians, which ensures multi-view depth consistency required for coherent TSDF mesh fusion, a task prior generalizable GS methods failed to support. Unlike implicit methods such as [SparseNeuS](15257-finesplat.md) or [UfoRecon](12847-anysplat-pipeline.md), SparSplat offers superior novel view synthesis capabilities alongside reconstruction, with inference speeds nearly two orders of magnitude faster.

### [HFGaussian](16422-hfgaussian.md)
HFGaussian is a generalizable, human-centric 3D Gaussian Splatting framework that estimates 3D human avatars with integrated biomechanical features (3D skeleton, 3D keypoints, dense pose) and 3D pose in real time from sparse input images, without per-subject fine-tuning. It sets itself apart from sibling methods like [AnySplat Pipeline](12847-anysplat-pipeline.md) and [FineSplat](15257-finesplat.md) by explicitly predicting continuous surface embeddings and pose parameters alongside photometric data using a "feature splatting" mechanism, rather than relying on parametric body models (e.g., SMPL) or direct parameterization of Gaussians with features.

### [Splatt3R](16423-splatt3r.md)
Splatt3R is a feed-forward model that predicts 3D Gaussian Splat parameters directly from a pair of uncalibrated natural images, without requiring camera intrinsics, extrinsics, or depth information. It solves the problem of pose-free novel view synthesis by extending the MASt3R foundation model with a parallel "Gaussian head" to output geometry and appearance attributes for each pixel. Unlike sibling methods that typically supervise only interpolated viewpoints between input views, Splatt3R is designed to extrapolate to viewpoints beyond the stereo baseline using a novel loss masking strategy.

### [ZeroGS](16425-zerogs.md)
ZeroGS is a pipeline for training 3D Gaussian Splatting (3DGS) from hundreds of unposed and unordered images without requiring Structure-from-Motion (SfM) tools like COLMAP. It differs from its siblings by using a pretrained foundation model (Spann3R) to predict dense 3D Gaussians and pointmaps directly from image pairs, followed by an incremental registration process that refines camera poses via a point-to-camera ray consistency loss and optimizes the scene using a rendering loss rather than reprojection error.

#### Deformation Field MLP
- [S2] An MLP network $F_\theta$ that maps 3D Gaussian coordinates and time to deviations in position, rotation, and scaling.
- [S2] Input: 3D Gaussian coordinate $x$ and time $t$. Process: Pass through eight fully connected layers with ReLU activations and 256-dimensional hidden layers to output a 256-dimensional feature vector. Concatenate the feature vector and the input in the fourth layer. Output: Pass the feature vector through three additional fully connected layers (without activation) to separately output offsets $\delta x, \delta r, \delta s$ for position, rotation, and scaling.
- [S2] Hidden layer dimension: 256.
- [S2] Number of initial fully connected layers: 8.
- [S2] Number of output layers: 3 (one for each offset).
- [S2] Activation function: ReLU for hidden layers, none for output layers.
- [S2] Additional storage compared to 3D Gaussians: 2MB.
- [S2] Does not use grid/plane-based structures because dynamic scenes have higher rank than static scenes, and explicit point-based rendering exacerbates this rank.

## Background
The concept of feed-forward 3D reconstruction has evolved from early neural radiance fields (NeRF) and multi-view stereo (MVS) networks to the more recent 3D Gaussian Splatting paradigm. Traditional 3DGS requires per-scene optimization, which is computationally expensive and requires known camera poses [S1]. The introduction of generalizable MVS networks (e.g., MVSNet, Cascade MVSNet) demonstrated that depth could be predicted directly from images [S1]. More recently, foundation models like MASt3R and DUSt3R provided dense 3D correspondences without explicit camera calibration [S1]. These advances enabled the development of feed-forward Gaussian Splatting methods that bypass SfM and iterative optimization, allowing for real-time reconstruction and novel view synthesis [S1].
