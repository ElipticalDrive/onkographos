# Gaussian Splatting Initialization and Parameterization

Also called: 3D Gaussian Splatting Initialization, COLMAP Initialization, SfM Initialization, Sparse Point Cloud Initialization, Sparse SfM Initialization, Starter Gaussians, Structure from Motion (SfM) Initialization

## Overview
Gaussian Splatting Initialization and Parameterization is the process of converting a sparse 3D point cloud (typically from Structure from Motion) into a set of learnable 3D Gaussian primitives to begin the differentiable rendering optimization [S2, S8, unofficial]. It solves the problem of providing geometrically accurate starting positions, orientations, and scales for the Gaussians, which is superior to random initialization for achieving high-quality novel view synthesis [S7, S8, unofficial]. It sets itself apart from random initialization by leveraging multi-view consistency to anchor the Gaussians to real scene geometry, avoiding the slow convergence and background artifacts associated with unstructured starting points [S7, S8, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of 2D images and their corresponding camera poses (extrinsics and intrinsics), or a pre-computed sparse 3D point cloud with colors (e.g., from COLMAP) [S2, S8, unofficial].
*   **Output:** A set of $N$ 3D Gaussians, each defined by learnable parameters: position $\mathbf{x}$, scale $\mathbf{s}$, rotation quaternion $\mathbf{q}$, opacity $\alpha$, and spherical harmonics coefficients $\mathbf{c}$ [S6, S8, unofficial].

**Data Structures:**
The Gaussians are stored as PyTorch `nn.Parameter` tensors on the GPU [S6, unofficial]:
*   `_xyz`: Shape $(N, 3)$, float32. Stores the mean position of each Gaussian.
*   `_scaling`: Shape $(N, 3)$, float32. Stores the log-scale values (pre-activation) for the x, y, z axes.
*   `_rotation`: Shape $(N, 4)$, float32. Stores quaternions in $[w, x, y, z]$ format.
*   `_features_dc`: Shape $(N, 1, 3)$, float32. Stores the DC component of the spherical harmonics (base color).
*   `_features_rest`: Shape $(N, D, 3)$, float32. Stores higher-order SH coefficients (initialized to zero).
*   `_opacity`: Shape $(N, 1)$, float32. Stores the logit of the opacity.

**Numbered Steps:**

1.  **Acquire Sparse Point Cloud:** Run Structure from Motion (SfM) on the input images to estimate camera poses and reconstruct a sparse 3D point cloud with associated colors [S2, S7, unofficial]. Let $N$ be the number of points.
    *   *Note:* Using Multi-View Stereo (MVS) dense clouds is discouraged for standard initialization as it wastes time and bakes in MVS errors as starting bias [S8, unofficial].

2.  **Initialize Positions:** Copy the 3D coordinates from the SfM point cloud directly to the `_xyz` tensor [S1, S8, unofficial].

3.  **Initialize Colors (SH):**
    *   Normalize the RGB color of each SfM point to the range $[-0.5, 0.5]$ [S1, unofficial].
    *   Compute the DC component $f_{dc}$ by dividing the normalized RGB by the SH basis constant $C_0 = 0.28209479177387814$ [S1, S6, unofficial].
    *   Store $f_{dc}$ in `_features_dc`.
    *   Initialize `_features_rest` to zeros [S1, S8, unofficial].

4.  **Initialize Scales:**
    *   Compute the distance to the $k$-nearest neighbors (typically $k=50$) for each point using a KD-tree [S1, S4, unofficial].
    *   Calculate the mean distance $d_{mean}$ [S4, unofficial].
    *   Compute the log-scale pre-activation: $\mathbf{s}_{pre} = \log(\sqrt{d_{mean}})$ [S1, S6, unofficial].
    *   *Alternative (Fixed Base):* Some implementations use a fixed base distance $d_{base} = 0.1$. Compute $dist2 = \max(0.1, \min(d_{mean}, \infty))$ (clamped min $10^{-7}$), then $\mathbf{s}_{pre} = \log(\sqrt{dist2})$ repeated for x, y, z [S6, unofficial].
    *   Store $\mathbf{s}_{pre}$ in `_scaling` [S6, unofficial].

5.  **Initialize Rotations:**
    *   *Standard:* Initialize all quaternions to identity $[1, 0, 0, 0]$ [S4, S6, S8, unofficial].
    *   *Normal-Aligned (Optional):* If surface normals are available (e.g., from depth maps), compute the quaternion that aligns the local z-axis with the estimated surface normal [S3, unofficial].

6.  **Initialize Opacity:**
    *   Initialize the opacity logit to a value that yields a sigmoid output close to but less than 1.0, or a low value to allow gradual learning.
    *   *Method A:* Set pre-activation opacity to 8.0, yielding $\sigma(8.0) \approx 0.9997$ [S4, unofficial].
    *   *Method B:* Set target opacity to 0.1, compute logit: $\alpha_{pre} = \log(0.1 / 0.9)$ [S1, unofficial].
    *   *Method C:* Clamp initial value 0.5 to range $[10^{-4}, 0.99]$, then apply logit function [S6, unofficial].
    *   Store $\alpha_{pre}$ in `_opacity` [S6, unofficial].

7.  **Construct Covariance (Runtime):**
    *   The covariance matrix $\Sigma$ is not stored directly but reconstructed from scale and rotation to ensure positive semi-definiteness [S8, unofficial].
    *   Create diagonal scaling matrix $S = \text{diag}(\exp(\mathbf{s}_{pre}))$ [S6, unofficial].
    *   Convert quaternion $\mathbf{q}$ to rotation matrix $R$ [S6, unofficial].
    *   Compute $\Sigma = R S S^T R^T$ [S6, S8, unofficial].

**Formulas:**

*   **SH Basis Constant:**
    $$ C_0 = \frac{1}{\sqrt{4\pi}} \approx 0.28209479177387814 $$

*   **Covariance Matrix:**
    $$ \Sigma = R S S^T R^T $$
    Where $R$ is the rotation matrix derived from the quaternion, and $S$ is the diagonal scaling matrix with entries $\exp(s_i)$ [S6, unofficial].

*   **2D Projection Covariance:**
    To render, the 3D covariance is projected to 2D screen space:
    $$ \Sigma' = J W \Sigma W^T J^T $$
    Where $W$ is the world-to-camera rotation matrix, and $J$ is the Jacobian of the perspective projection [S6, unofficial].
    The Jacobian $J$ (size $N \times 2 \times 3$) for a camera with focal length $f$ and depth $z$ (clamped with $10^{-7}$ to prevent division by zero) is:
    $$ J_{i,0,0} = \frac{f}{z_i}, \quad J_{i,0,2} = -\frac{f x_i}{z_i^2} $$
    $$ J_{i,1,1} = \frac{f}{z_i}, \quad J_{i,1,2} = -\frac{f y_i}{z_i^2} $$
    Numerical stability bias of $0.3$ is added to the diagonal elements of $\Sigma'$ [S6, unofficial].

**Parameters:**
*   **Learning Rates (Adam):**
    *   Means: $0.00016$ (decays exponentially to $0.0000016$) [S1, unofficial].
    *   Scales: $0.005$ [S1, unofficial].
    *   Quaternions: $0.001$ [S1, unofficial].
    *   Features DC: $0.0025$ [S1, unofficial].
    *   Features Rest: $0.000125$ [S1, unofficial].
    *   Opacity: $0.05$ [S1, unofficial].
*   **Max Scale:** Clamped to $10.0$ after exponential transformation to prevent excessively large Gaussians [S6, unofficial].
*   **Quaternion Normalization:** Quaternions are normalized to unit length before rotation matrix conversion [S6, unofficial].

**Pseudocode:**

```python
import torch
import numpy as np

def initialize_gaussians_from_sfm(points_xyz, points_rgb, num_neighbors=50):
    """
    Initialize 3D Gaussian parameters from a sparse SfM point cloud.
    
    Args:
        points_xyz: Tensor of shape (N, 3) containing 3D coordinates.
        points_rgb: Tensor of shape (N, 3) containing RGB colors (0-255).
        num_neighbors: Number of nearest neighbors for scale estimation.
        
    Returns:
        Dictionary of initialized nn.Parameter tensors.
    """
    N = points_xyz.shape[0]
    device = points_xyz.device
    
    # 1. Positions
    _xyz = torch.nn.Parameter(points_xyz.clone().to(device), requires_grad=True)
    
    # 2. Colors (SH DC component)
    # Normalize RGB to [-0.5, 0.5]
    rgb_norm = (points_rgb.float() / 255.0) - 0.5
    # Divide by C0
    C0 = 0.28209479177387814
    features_dc = torch.nn.Parameter(rgb_norm / C0, requires_grad=True) # Shape (N, 1, 3)
    features_dc = features_dc.unsqueeze(1)
    
    # Initialize rest to zeros
    features_rest = torch.nn.Parameter(torch.zeros(N, 15, 3).to(device), requires_grad=True) # Assuming degree 3
    
    # 3. Scales
    # Compute KNN distances (simplified using KDTree logic conceptually)
    # In practice, use a library like scipy.spatial.KDTree or torch_cluster
    # dists: Tensor of shape (N,)
    dists = compute_knn_mean_distance(points_xyz, k=num_neighbors)
    
    # Log scale
    # Clamp to avoid log(0)
    dists = torch.clamp(dists, min=1e-7)
    scaling_pre = torch.log(torch.sqrt(dists)).unsqueeze(1).repeat(1, 3) # Shape (N, 3)
    _scaling = torch.nn.Parameter(scaling_pre, requires_grad=True)
    
    # 4. Rotations (Identity)
    quats = torch.zeros(N, 4, device=device)
    quats[:, 0] = 1.0 # w=1, x=y=z=0
    _rotation = torch.nn.Parameter(quats, requires_grad=True)
    
    # 5. Opacity (Logit of 0.1)
    target_opacity = 0.1
    opacity_pre = torch.log(torch.tensor(target_opacity / (1 - target_opacity)))
    _opacity = torch.nn.Parameter(opacity_pre.unsqueeze(1), requires_grad=True) # Shape (N, 1)
    
    return {
        '_xyz': _xyz,
        '_features_dc': features_dc,
        '_features_rest': features_rest,
        '_scaling': _scaling,
        '_rotation': _rotation,
        '_opacity': _opacity
    }

def compute_knn_mean_distance(points, k=50):

def quaternion_to_rotation_matrix(quaternions):
    """
    Convert quaternions [w, x, y, z] to rotation matrices.
    """
    # Normalize quaternions
    quaternions = torch.nn.functional.normalize(quaternions, dim=1)
    w, x, y, z = quaternions[:, 0], quaternions[:, 1], quaternions[:, 2], quaternions[:, 3]
    
    R = torch.zeros(quaternions.shape[0], 3, 3, device=quaternions.device)
    
    R[:, 0, 0] = 1 - 2 * (y**2 + z**2)
    R[:, 0, 1] = 2 * (x*y - w*z)
    R[:, 0, 2] = 2 * (x*z + w*y)
    
    R[:, 1, 0] = 2 * (x*y + w*z)
    R[:, 1, 1] = 1 - 2 * (x**2 + z**2)
    R[:, 1, 2] = 2 * (y*z - w*x)
    
    R[:, 2, 0] = 2 * (x*z - w*y)
    R[:, 2, 1] = 2 * (y*z + w*x)
    R[:, 2, 2] = 1 - 2 * (x**2 + y**2)
    
    return R

def compute_covariance(scaling_pre, rotation_matrix):
    """
    Compute 3D covariance matrix Sigma = R S S^T R^T.
    """
    # S is diagonal matrix of exp(scaling_pre)
    scales = torch.exp(scaling_pre) # (N, 3)
    S = torch.zeros(scales.shape[0], 3, 3, device=scales.device)
    S[:, 0, 0] = scales[:, 0]
    S[:, 1, 1] = scales[:, 1]
    S[:, 2, 2] = scales[:, 2]
    
    # Sigma = R @ S @ S^T @ R^T
    # Since S is diagonal, S @ S^T is diag(s^2)
    SS_T = S @ S.T
    
    Sigma = rotation_matrix @ SS_T @ rotation_matrix.transpose(1, 2)
    return Sigma
```

## Subtopics

### [Random Large-Variance Initialization](6129-random-large-variance-initialization.md)
Random Large-Variance Initialization (RAIN-GS) relaxes the strict Structure-from-Motion (SfM) point cloud assumption required by standard 3D Gaussian Splatting by introducing sparse, large-variance random initialization. Unlike standard methods that rely solely on dense SfM points, this approach allows optimization to proceed even when SfM data is sparse or absent, serving as a fallback or complementary initialization strategy.

### [Temporal Point Cloud Initialization via Chamfer Distance Minimization](6954-temporal-point-cloud-initialization-via-chamfer-distance-min.md)
This method reduces training time for dynamic video scenes by initializing the point cloud of the current frame using the learned model from the previous frame, leveraging temporal correlation between nearby frames. It sets itself apart from static initialization methods by explicitly optimizing geometric alignment between consecutive frames via Chamfer distance minimization before refining radiance parameters.

### [Gaussian Geometry Parameters Prediction](8442-gaussian-geometry-parameters-prediction.md)
Gaussian Geometry Parameters Prediction refers to methods that infer the spatial attributes (position, covariance, and opacity) of 3D Gaussian primitives directly from input data, rather than optimizing them via iterative gradient descent per scene. It solves the latency bottleneck of standard 3D Gaussian Splatting (3DGS) [Parent](2313-gaussian-splatting-initialization-and-parameterization.md) by enabling feed-forward reconstruction. Unlike sibling initialization methods that rely on static heuristics or single-frame depth [6129-random-large-variance-initialization.md], these methods leverage learned neural volumes or multi-view consistency to predict geometry that is globally consistent and robust to noise.

### [Background Hemisphere Initialization](8446-background-hemisphere-initialization.md)
Background Hemisphere Initialization is a technique for handling unbounded scenes in 3D Gaussian Splatting by modeling the distant background (sky) as a separate, fixed-radius hemisphere of Gaussians. It solves the problem of "cloud-like" artifacts and occlusion errors that occur when foreground Gaussians attempt to model distant sky regions, which degrades novel view synthesis quality. It sets itself apart from standard background models by explicitly disentangling the sky from the foreground geometry, often using a hemisphere to avoid occluding the ground plane.

### [ReSplat Initialization](10957-resplat-initialization.md)
ReSplat Initialization predicts an initial set of 3D Gaussians from a sparse point cloud by aggregating local and global 3D context to compensate for information loss incurred by downsampling the input point cloud by 16x. Unlike naive prediction methods that directly map point features to Gaussian parameters, this method uses a transformer-based encoder to enrich features with neighborhood context before decoding. It sets the stage for the subsequent Recurrent Gaussian Update by providing a structured initial state $\mathcal{G}^0$.

### [Point Cloud/Mesh-based Initialization](16343-point-cloud-mesh-based-initialization.md)
This family of methods initializes 3D Gaussian Splatting (3DGS) primitives using pre-existing 3D geometry (point clouds or meshes) rather than relying solely on sparse Structure-from-Motion (SfM) outputs. It solves the problem of initializing high-quality radiance fields when multi-view images are unavailable or when the user possesses dense, surface-aligned volumetric data (e.g., MPEG plenoptic point clouds or meshes). It differs from [Random Large-Variance Initialization](6129-random-large-variance-initialization.md) by anchoring Gaussians to observed geometry, and from [Gaussian Model Initialization](2349-gaussian-model-initialization.md) by supporting dense mesh inputs and optional fixed-position constraints.

### Neural Point Cloud Initialization from COLMAP
A method to initialize the neural point cloud and their features for Point-NeRF using an external point cloud reconstruction (specifically COLMAP) [S9]. It solves the problem of how to provide initial positions, variances, and feature vectors for the neural points [S9]. The variance parameter $\gamma_i$ for each point $p_i$ is initialized to 0.3 [S9]. To acquire the feature vector $f_i$ for a point $p_i$, all views where the point is occluded are ruled out, and the view where the camera is closest to the point is selected. The point is then unprojected onto the feature maps extracted by the Image Feature Extraction 2D CNN (Gf) from the selected closest view to obtain $f_i$ [S9].

### Binary Gaussian Hierarchy Construction
The hierarchy is a binary tree [S10, unofficial]. Leaf nodes contain the full set of optimized Gaussian properties (base color, SH coefficients, position, covariance). Internal nodes store merged approximations of their two child nodes [S10, unofficial].

### Single Ellipsoid Initialization
Initializes a single ellipsoid from a set of 3D points using Principal Component Analysis (PCA) to determine orientation, center, and radii [S11]. The minimum allowed radius $r_{\min}$ is typically 0.005 to avoid numerical problems [S11]. A scaling factor $\alpha$ (typically 3) is used to ensure points are mostly covered [S11].

### MVS-guided Initialization
Aggregates filtered multiview depth maps from an MVS method into a unified 3D point cloud [S12]. An initial optimization phase prunes noisy Gaussians by freezing updates for Gaussian centers and optimizing all other parameters for $N_{prun}$ iterations, removing Gaussians with opacity $\alpha_k < \tau$ [S12]. After pruning, all parameters are unfrozen for standard optimization with Adaptive Density Control [S12].

### Feature Initialization
Initializes the base feature $f_{base}$ and directional feature $f_{dir}$ with the RGB color values of the corresponding SfM points [S13]. The temporal feature $f_{time}$ is initialized as a zero vector [S13].

## Operating characteristics
*   **Time Complexity:** Initialization is dominated by the SfM step, which is $O(N^2)$ or worse depending on the number of images and matches, but typically fast for moderate scene sizes (e.g., 6 minutes for COLMAP on a standard scene) [S5, unofficial]. The Gaussian parameter initialization itself is $O(N)$ [S4, unofficial].
*   **Memory Complexity:** $O(N)$ for storing the Gaussian parameters [S6, unofficial].
*   **Performance:** SfM initialization yields significantly higher PSNR (e.g., 26.05 vs 20.42 on Average-30K) compared to random initialization [S7, unofficial]. Random initialization is faster to start but degrades background quality and converges slower [S7, S8, unofficial].
*   **Strengths:** Provides geometrically accurate starting points, improving overall reconstruction quality and convergence speed [S7, S8, unofficial]. Avoids the "baking in" of MVS errors by using sparse points [S8, unofficial].
*   **Limitations:** Requires multi-view images and successful SfM reconstruction. Fails if image coverage is too thin or if there are no matching features [S8, unofficial].
*   **When to Use:** When multi-view images are available and high-quality novel view synthesis is required [S2, S7, unofficial].
*   **When Not to Use:** When only a single image is available, or when calibrated 3D cameras are already known (e.g., synthetic datasets) and random initialization is sufficient [S2, S7, unofficial].

## Background
Originated with the introduction of 3D Gaussian Splatting (3DGS) by Kerbl et al. in 2023 [S7, S8, unofficial]. The method builds on established Computer Vision techniques, specifically Structure from Motion (SfM), which has been used for over 20 years to reconstruct 3D geometry from 2D images [S2, unofficial]. COLMAP is the goto implementation for SfM [S2, S8, unofficial]. The specific parameterization (splitting covariance into scale and rotation) ensures the covariance matrix remains positive semi-definite during optimization [S8, unofficial].
