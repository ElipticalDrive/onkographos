# Gradient-based Pruning

Also called: Gradient Magnitude Pruning

## Overview
Gradient-based Pruning removes 3D Gaussians that contribute minimally to the optimization process by evaluating the magnitude of gradients associated with each Gaussian during training [S1]. It distinguishes itself from opacity-based methods by targeting Gaussians that are structurally redundant or poorly aligned with scene geometry, rather than those that are simply transparent [S1]. This method is a core component of several efficient 3D Gaussian Splatting variants, including EfficientGS, GDGS, Trimming the Fat, and ELMGS [S1].

## How it works
**Inputs and Outputs**
*   **Input:** The set of 3D Gaussians $\mathcal{G}$, their current parameters (position, covariance, opacity, spherical harmonics coefficients), and the accumulated gradient information from the most recent training iterations.
*   **Output:** A pruned subset of Gaussians $\mathcal{G}' \subset \mathcal{G}$ with low gradient magnitudes removed.

**Data Structures**
*   **Gradient Accumulator:** A vector or scalar value stored per Gaussian, tracking the cumulative gradient magnitude. In EfficientGS, this is specifically a cumulative gradient sum [S1].
*   **Threshold:** A scalar value determining the cutoff for removal. The sources do not specify a fixed universal threshold, noting that implementations like Trimming the Fat and ELMGS remove a fixed percentage (75%) [S1].

**Steps**
1.  **Gradient Calculation:** During the standard backpropagation step of training, compute the gradient of the loss function with respect to the parameters of each Gaussian.
    *   Standard implementations use positional gradients [S1].
    *   Kim et al. [30] extend this by incorporating Spherical Harmonics (SH) gradients alongside positional gradients to refine the pruning process [S1].
2.  **Magnitude Aggregation:** Calculate the magnitude of the gradients for each Gaussian.
    *   EfficientGS utilizes cumulative gradient sum analysis to aggregate these values over time [S1].
    *   GDGS models scene gradients to reduce Gaussian density [S1].
3.  **Pruning Decision:** Compare the calculated gradient magnitude against a threshold or rank order the Gaussians.
    *   If the magnitude is below the threshold (or in the lowest percentile), the Gaussian is marked for removal.
    *   Specific implementations like Trimming the Fat [25] and ELMGS [18] remove 75% of Gaussians based on this criterion [S1].
4.  **Removal:** Delete the marked Gaussians from the scene representation.

**Pseudocode**
```python
def gradient_based_pruning(gaussians, cumulative_gradients, pruning_ratio=0.75):
    """
    Prunes Gaussians with low cumulative gradient magnitudes.
    
    Args:
        gaussians: List of Gaussian objects with attributes:
                   - id: Unique identifier
                   - pos_grad_norm: Norm of positional gradient
                   - sh_grad_norm: Norm of SH gradient (optional, if using Kim et al. extension)
        cumulative_gradients: Dictionary mapping Gaussian id to accumulated gradient magnitude.
        pruning_ratio: Fraction of Gaussians to remove (e.g., 0.75 for Trimming the Fat/ELMGS).
        
    Returns:
        List of Gaussian objects that are kept.
    """
    # Step 1: Aggregate gradient magnitude for each Gaussian
    # Note: In standard implementations, this is done during backprop.
    # Here we assume cumulative_gradients is pre-populated.
    
    # If SH gradients are used (Kim et al. [30]), combine them.
    # For standard gradient-based pruning, only positional gradients are used [S1].
    
    # Step 2: Rank Gaussians by cumulative gradient magnitude
    # Sort in ascending order (lowest gradient first)
    sorted_gaussians = sorted(gaussians, key=lambda g: cumulative_gradients.get(g.id, 0))
    
    # Step 3: Determine number of Gaussians to remove
    num_to_remove = int(len(sorted_gaussians) * pruning_ratio)
    
    # Step 4: Remove the bottom N Gaussians
    # The sources state Trimming the Fat and ELMGS remove 75% [S1]
    # EfficientGS uses cumulative sum analysis to halt densification and prune [S1]
    
    pruned_gaussians = sorted_gaussians[num_to_remove:]
    
    return pruned_gaussians
```

**Edge Cases and Pitfalls**
*   **Precision:** Accumulating gradients over many iterations may lead to numerical overflow or underflow if not normalized. EfficientGS uses cumulative sum analysis, implying careful handling of these values [S1].
*   **Degenerate Input:** Gaussians with zero gradient (e.g., those in static, unobserved regions) will be pruned. This is intended behavior but may remove valid geometry if the scene is not fully observed during training.
*   **Threshold Selection:** The sources do not specify a fixed gradient value threshold, but rather a percentage-based removal (75%) for specific methods [S1]. Implementers must choose between a fixed percentage or a dynamic threshold based on the gradient distribution.

## Subtopics

## Operating characteristics
*   **Time Complexity:** $O(N)$ per pruning step, where $N$ is the number of Gaussians, as it requires iterating through all Gaussians to compute or aggregate gradients and then sorting or filtering them [S1].
*   **Memory Complexity:** $O(N)$ to store cumulative gradient values for each Gaussian [S1].
*   **Measured Performance:** Trimming the Fat [25] and ELMGS [18] achieve high visual quality while removing 75% of Gaussians [S1]. GDGS enhances compactness by modeling scene gradients [S1].
*   **Strengths:** Effectively removes redundant and floaters Gaussians that have low impact on the final image [S1]. It complements opacity-based pruning by targeting structural redundancy rather than transparency [S1].
*   **Limitations:** Requires access to gradient information, which is only available during training. It may be less effective for Gaussians that are important for fine details but have small gradients due to smoothness [S1].
*   **When to Use:** When computational efficiency is critical and the training process allows for gradient accumulation. It is particularly useful in conjunction with densification strategies to prevent over-density [S1].

## Background
Gradient-based Pruning originated as a method to improve the efficiency of 3D Gaussian Splatting by removing Gaussians that contribute minimally to scene reconstruction [S1]. It is employed by several notable works:
*   **EfficientGS [27]:** Uses cumulative gradient sum analysis to halt unnecessary densification and prune redundant Gaussians [S1].
*   **GDGS [91]:** Reduces Gaussian density by modeling scene gradients [S1].
*   **Trimming the Fat [25] and ELMGS [18]:** Apply gradient-based pruning to remove 75% of Gaussians while maintaining high visual quality [S1].
*   **Kim et al. [30]:** Extended the approach by incorporating SH gradients alongside positional gradients [S1].
