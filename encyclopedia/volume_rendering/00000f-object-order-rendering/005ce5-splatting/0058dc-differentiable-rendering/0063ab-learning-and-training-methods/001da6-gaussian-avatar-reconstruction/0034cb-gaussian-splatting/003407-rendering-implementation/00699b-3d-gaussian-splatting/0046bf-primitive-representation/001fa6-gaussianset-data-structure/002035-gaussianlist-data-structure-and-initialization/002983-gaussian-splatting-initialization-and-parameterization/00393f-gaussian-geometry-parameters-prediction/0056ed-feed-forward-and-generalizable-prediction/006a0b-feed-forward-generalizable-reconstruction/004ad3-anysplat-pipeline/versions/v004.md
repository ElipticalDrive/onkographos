# AnySplat Pipeline

Also called: Feed-forward 3D Gaussian Splatting from Unconstrained Views

## Overview
AnySplat is a feed-forward method that predicts a complete 3D Gaussian Splatting (3DGS) representation directly from a set of uncalibrated input images, eliminating the need for iterative optimization or known camera poses [S1, unofficial]. It differs from sibling methods like [FineSplat](15257-finesplat.md) and [SparSplat](15813-sparsplat.md) by explicitly predicting camera poses and depth maps alongside Gaussian parameters, using a differentiable voxelization module to resolve density artifacts common in low-resolution feature backbones [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A batch of $K$ uncalibrated images $I \in \mathbb{R}^{1 \times K \times 3 \times 448 \times 448}$ [S1, unofficial].
*   **Outputs:** A set of 3D Gaussians (defined by mean $\mu$, scale $s$, rotation $r$, opacity $\alpha$, and color $c$) and predicted camera poses (extrinsic $E$ and intrinsic $K$) [S1, unofficial].

**Data Structures:**
The Gaussian parameters are predicted per-pixel from the feature map. The mean $\mu$ is derived from the predicted depth $D$ and camera intrinsics. The covariance is parameterized by scale $s$ and rotation $r$. Color $c$ is represented as spherical harmonics coefficients.

**Steps:**
1.  **Feature Encoding:** Input images are processed by a transformer-based geometry encoder to extract multi-view features [S1, unofficial].
2.  **Parameter Prediction:** Three decoder heads ($F_G, F_D, F_C$) predict:
    *   $F_G$: Gaussian parameters ($\mu, \sigma, r, s, c$) [S1, unofficial].
    *   $F_D$: Per-pixel depth map $D$ [S1, unofficial].
    *   $F_C$: Camera poses $p$ (extrinsic and intrinsic matrices) [S1, unofficial].
3.  **Gaussian Construction:** Pixel-wise 3D Gaussians are constructed using the predicted depth $D$ and camera intrinsics to determine $\mu$, and the predicted $s, r, c$ [S1, unofficial].
4.  **Differentiable Voxelization:** The pixel-wise Gaussians are voxelized into "pre-voxel" 3D Gaussians using a Differentiable Voxelization module to aggregate density and reduce artifacts [S1, unofficial].
5.  **Rendering:** Multi-view images and depth maps are rendered from the voxelized Gaussians using differentiable rasterization [S1, unofficial].
6.  **Loss Computation:**
    *   **RGB Loss:** Between rendered images and ground truth images.
    *   **Geometry Loss:** Between rendered depth, decoded depth $D$, and predicted poses $p$, supervised by pseudo-geometry priors from a pretrained VGGT model [S1, unofficial].
7.  **Optimization:** The network weights are updated via backpropagation through the rendering and voxelization steps [S1, unofficial].

**Pseudocode:**
```python
import torch

def anysplat_pipeline(images):
    """
    images: torch.Tensor of shape [1, K, 3, 448, 448]
    Returns: gaussians (list of parameters), pred_context_pose (dict)
    """
    # 1. Normalize input to [-1, 1] range if not already, 
    # but the inference call expects [0, 1] based on (images+1)*0.5 in source.
    # Source code shows: model.inference((images+1)*0.5)
    # Assuming images are in [-1, 1] from preprocessing, this maps to [0, 1].
    normalized_images = (images + 1.0) * 0.5
    
    # 2. Run the model inference
    # The model contains the encoder and three decoder heads F_G, F_D, F_C
    gaussians, pred_context_pose = model.inference(normalized_images)
    
    # 3. Extract predicted poses
    pred_all_extrinsic = pred_context_pose['extrinsic']
    pred_all_intrinsic = pred_context_pose['intrinsic']
    
    return gaussians, pred_all_extrinsic, pred_all_intrinsic
```

**Parameters:**
*   Input resolution: $448 \times 448$ [S1, unofficial].
*   Number of views $K$: Variable, typically small (e.g., 3-5) for feed-forward inference [S1, unofficial].
*   Backbone: Transformer-based geometry encoder [S1, unofficial].
*   Priors: Pretrained VGGT for pseudo-geometry supervision [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Uncalibrated Input:** The method handles unknown camera poses by predicting them, but accuracy depends on the quality of the VGGT priors and the encoder's ability to infer geometry from uncalibrated views [S1, unofficial].
*   **Voxelization Artifacts:** Without the differentiable voxelization module, pixel-wise Gaussians may suffer from insufficient density and artifacts, especially at low resolutions [S1, unofficial].

## Subtopics

### [SubSplat](13524-subsplat.md)
SubSplat is a method for high-resolution novel-view synthesis that resolves the trade-off between network computational cost and rendering fidelity in pixel-aligned 3D Gaussian Splatting. It solves the problem of insufficient Gaussian density and artifacts when using low-resolution backbone inputs by introducing a Sub-pixel Gaussian Reparameterizer (SPGR). Unlike prior methods limited by fixed grids or image-space upsamplers, SubSplat subdivides each grid-anchored primary Gaussian into multiple fine-grained sub-pixel primitives, restoring structural density directly from low-resolution features while maintaining stable network latency.

### [Deformable Radial Kernel (DRK)](13699-deformable-radial-kernel-drk.md)
Deformable Radial Kernel (DRK) Splatting is a 3D scene representation method that replaces the fixed radial symmetry of Gaussian primitives with a flexible planar kernel defined by multiple radial basis functions. It solves the overparameterization and geometric fidelity limitations of Gaussian Splatting by allowing adaptive stretching, rotation, and sharp boundary control, enabling high-fidelity rendering with significantly fewer primitives. Unlike standard 2D Gaussian Splatting, which relies on smooth, elliptical distributions, DRK supports straight edges and sharp corners through L1/L2 norm blending and piecewise edge sharpening.

## Operating characteristics
*   **Time Complexity:** Inference is feed-forward, making it significantly faster than iterative optimization-based methods like original 3DGS. Training time depends on the backbone size and the number of views, but is generally faster than per-scene optimization.
*   **Memory Complexity:** Memory usage is dominated by the transformer encoder and the Gaussian representation. The voxelization step adds overhead but reduces the number of primitives needed for high fidelity compared to pure pixel-wise approaches.
*   **Strengths:** Handles uncalibrated images; no iterative optimization required; robust to varying numbers of input views.
*   **Limitations:** Performance is bounded by the accuracy of the predicted camera poses and depth maps; relies on external priors (VGGT) for geometry supervision.
*   **Hardware:** Requires GPU with CUDA support (tested on CUDA 12.1) [S1, unofficial].

## Background
AnySplat was introduced by InternRobotics as a feed-forward approach to 3D Gaussian Splatting that removes the dependency on calibrated camera poses [S1, unofficial]. It builds on the principles of differentiable rendering and multi-view fusion, extending them to predict both scene geometry and camera parameters simultaneously.
