# Mesh Extraction and Representation

Also called: Triangle Soup

## Overview
This family of methods converts the volumetric, implicit representation of 3D Gaussian Splatting (3DGS) into explicit geometric structures, primarily triangular meshes or point clouds, to enable compatibility with standard 3D graphics pipelines, editing tools, and animation systems. Unlike standard 3DGS, which renders via alpha-composited splats, these methods extract a discrete surface or point set that approximates the scene geometry. [SuGaR Mesh Extraction](12580-sugar-mesh-extraction.md) achieves this by regularizing Gaussians to align with the surface during training, while [3D Gaussian Splatting to Point Cloud](14068-3d-gaussian-splatting-to-point-cloud.md) samples points from the Gaussian distribution post-training.

## Shared principles
All methods in this family operate on a set of $N$ 3D Gaussian primitives. Each primitive $i$ is defined by learnable parameters describing its geometry, appearance, and position.

**Data Structure:**
Each Gaussian $g_i$ is represented by the following attributes [S1]:
*   **Position ($\mu_i$):** A 3D vector $\mathbb{R}^3$ representing the centroid in world space.
*   **Rotation ($q_i$):** A unit quaternion $\mathbb{R}^4$ representing orientation.
*   **Scale ($s_i$):** A 3D vector $\mathbb{R}^3$ representing anisotropic scaling factors along principal axes.
*   **Opacity ($\omega_i$):** A scalar $\mathbb{R} \in [0, 1]$ representing maximum opacity.
*   **Color ($c_i$):** Represented by Spherical Harmonic (SH) coefficients (typically degree 3, 48 coefficients for RGB) for view-dependent appearance.

**Covariance Matrix:**
The spatial spread is defined by a 3D covariance matrix $\Sigma_i$, constructed from scale and rotation:
$$ \Sigma_i = R_i S_i S_i^T R_i^T $$
where $S_i = \text{diag}(s_i)$ is the scaling matrix and $R_i$ is the rotation matrix derived from $q_i$ [S1].

**Projection to 2D:**
During rendering, the 3D covariance $\Sigma_i$ is projected to the 2D image plane using the Jacobian $J$ of the affine approximation of the projective transformation:
$$ \Sigma' = J \Sigma_i J^T $$
The relevant part for rasterization is the top-left $2 \times 2$ submatrix $\Sigma'_{2 \times 2}$ [S1].

**Spatial Response (Kernel Function):**
The contribution of a Gaussian to a pixel at screen coordinates $x$ is determined by:
$$ R(x) = \exp\left(-\frac{1}{2} (x - \mu')^T (\Sigma'_{2 \times 2})^{-1} (x - \mu')\right) $$
where $\mu'$ is the projected 2D mean [S1].

**Alpha Compositing:**
The final opacity $\alpha$ contributed by a Gaussian is:
$$ \alpha = \omega_i \cdot R(x) $$
The pixel color is computed via alpha blending with primitives sorted back-to-front:
$$ C_{pixel} = \sum_i T_i \alpha_i C_i, \quad T_i = \prod_{j < i} (1 - \alpha_j) $$
where $C_i$ is evaluated using SH coefficients based on view direction [S1].

**Truncation:**
To optimize speed, fragments are discarded if $\alpha < \tau_\alpha$ (typically $1/255$), limiting rendering to a region of approximately $3.33\sigma$ [S1].

**Density Estimation for Mesh Extraction:**
The scene density $\sigma(\mathbf{x})$ is the superposition of Gaussian contributions:
$$ \sigma(\mathbf{x}) = \sum_{i=1}^{N} \alpha_i \exp\left(-\frac{1}{2} (\mathbf{x} - \mathbf{p}_i)^T \Sigma_i^{-1} (\mathbf{x} - \mathbf{p}_i)\right) $$
where $\alpha_i$ is opacity, $\mathbf{p}_i$ is the mean, and $\Sigma_i$ is the covariance [S1].

## Subtopics

### [SuGaR Mesh Extraction](12580-sugar-mesh-extraction.md)
SuGaR extracts a surface mesh by regularizing Gaussians to align with the true scene surface during optimization. It differs from standard 3DGS by enforcing surface alignment, enabling the use of traditional mesh-processing tools. Unlike methods that rely on complex dual-stage generation, SuGaR employs a regularization term to align Gaussians with the scene surface and uses Poisson reconstruction for efficient mesh extraction.

### [3D Gaussian Splatting to Point Cloud](14068-3d-gaussian-splatting-to-point-cloud.md)
This method converts a trained 3DGS scene into a dense, high-quality point cloud that approximates the original volumetric representation, enabling compatibility with standard 3D software that lacks native 3DGS support. It distinguishes itself from sibling methods like [SuGaR Mesh Extraction](12580-sugar-mesh-extraction.md) by focusing on faithful point cloud generation from the original optimized Gaussians rather than learning a new explicit representation, optionally incorporating rendered camera views to weight contributions and filter surface proximity.

### Triangle Soup (Mesh-based Gaussian Splatting)
#### definition
- [S1] A representation that connects Gaussian splats to a mesh structure, enabling real-time editing and animation by directly manipulating mesh vertices.
#### step
- [S1] Train GS with flat Gaussians. Construct an initial Triangle Soup. Adjust the Triangle Soup during training. For mesh-based input, fit a pre-existing mesh (e.g., FLAME) to the data.
#### parameter
- [S1] Number of Gaussians per face: 100 (used in facial reconstruction experiments).
- [S1] GPU hardware: Tesla V100-SXM2-32GB (used for NeRF-Synthetic dataset experiments).
#### pitfall
- [S1] Artifacts appear with significant changes on meshes with large faces. Handled by dividing large faces into smaller ones using subdivision.
- [S1] How to change Gaussian components when mesh faces are split is not apparent.
#### comparison
- [S1] Differs from vanilla GS by automatically recalculating Gaussian parameters (covariance, rotation) when vertices are moved, avoiding holes and blurriness.
#### usage
- [S1] Used in the GaMeS model for 3D face reconstruction, object editing, and animation.

## Background
The need for explicit mesh extraction from 3D Gaussian Splatting arises from the desire to integrate neural radiance fields and Gaussian splats into traditional computer graphics pipelines that rely on polygonal meshes for editing, animation, and physics simulation. Standard 3DGS provides a high-quality volumetric representation but lacks a discrete surface. SuGaR [S1] introduced surface-aligned regularization to facilitate Poisson reconstruction. Triangle Soup, as implemented in the GaMeS model [S1], extends this by binding Gaussians to a mesh topology for direct manipulation.
