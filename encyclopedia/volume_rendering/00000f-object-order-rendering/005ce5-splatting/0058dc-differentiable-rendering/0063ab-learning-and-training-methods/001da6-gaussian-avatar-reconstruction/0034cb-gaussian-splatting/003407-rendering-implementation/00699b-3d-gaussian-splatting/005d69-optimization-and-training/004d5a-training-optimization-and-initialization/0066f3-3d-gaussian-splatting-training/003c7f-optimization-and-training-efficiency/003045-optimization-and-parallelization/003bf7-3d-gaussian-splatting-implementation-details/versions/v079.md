# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, GSGEN Implementation Details, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific hyperparameters, data structures, and optimization schedules required to implement the standard 3D Gaussian Splatting (3DGS) training pipeline, along with key implementation variants for stability, denoising, and large-scale rendering. It solves the problem of translating the theoretical differentiable rasterization framework into a working, efficient CUDA-based training loop. It sets itself apart from sibling methods by providing the concrete numerical thresholds (e.g., opacity cutoffs, gradient thresholds) and software engineering choices (e.g., half-precision fetches, specific libraries) that enable real-time performance and convergence [S1, S2, S3].

## How it works
The implementation relies on a differentiable rasterization core that projects 3D Gaussians to 2D screen space, sorts them by depth, and alpha-blends them to produce pixel colors [6233-optimization-and-parallelization]. The training loop minimizes a loss function (typically $\mathcal{L} = (1-\lambda)\mathcal{L}_{L1} + \lambda\mathcal{L}_{SSIM}$) using gradient descent.

### Inputs and Outputs
*   **Inputs:** A set of $N$ 3D Gaussians, each defined by position $\mathbf{\mu} \in \mathbb{R}^3$, covariance $\mathbf{\Sigma} \in \mathbb{R}^{3 \times 3}$ (or scale $\mathbf{s} \in \mathbb{R}^3$ and rotation $\mathbf{q} \in \mathbb{R}^4$), opacity $\alpha \in [0,1]$, and spherical harmonic (SH) coefficients for view-dependent color. A set of training images with known camera poses.
*   **Outputs:** Optimized Gaussian parameters and a rendered image matching the training view.

### Data Structures
*   **Gaussian Attributes:** Stored in contiguous arrays (SoA) for GPU access: `positions` ($N \times 3$), `scales` ($N \times 3$), `quaternions` ($N \times 4$), `opacities` ($N$), `sh_coeffs` ($N \times K \times 3$, where $K$ is the number of SH bands).
*   **Tile/Screen Space:** Images are divided into tiles (e.g., $16 \times 16$ pixels). For each tile, a list of contributing Gaussians is generated, sorted by depth.
*   **Gradients:** Accumulated per-Gaussian gradients for position, scale, rotation, opacity, and SH coefficients.

### Training Steps and Parameters
The standard training procedure involves initialization, iterative optimization, and adaptive densification/pruning.

1.  **Initialization:** Initialize Gaussians from a Structure-from-Motion (SfM) point cloud.
    *   *Corrected Scene Extent:* To avoid bias from camera distribution (e.g., orbiting a small object), calculate scene extent $e'_{\text{scene}}$ using SfM points rather than camera positions [S4]:
        $$ \bar{C} = \frac{1}{N_{\text{cam}}} \sum_{i=1}^{N_{\text{cam}}} C_i $$
        $$ e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2 $$
        where $\bar{C}$ is the average camera position, $N_{\text{cam}}$ is the number of cameras, $N_{\text{SfM}}$ is the number of SfM points, and $p_i$ are SfM points [S4].
2.  **Optimization Loop:**
    *   Randomly select a training image [S3].
    *   **Rasterization:** Project Gaussians to 2D. Use half-precision memory fetches on feature vectors during rasterization (forward and backward) to reduce register pressure [S2].
    *   **Loss Computation:** Compute $\mathcal{L}_{L1}$ and $\mathcal{L}_{SSIM}$. Apply an automatic scaling factor to loss values to improve half-precision training stability [S2].
    *   **Backpropagation:** Compute gradients $\frac{\partial \mathcal{L}}{\partial \theta}$ for all Gaussian parameters [6233-optimization-and-parallelization].
    *   **Optimizer Update:** Use Adam optimizer with learning rate $1 \times 10^{-3}$ [S3].
3.  **Adaptive Densification (Every 100-500 iterations):**
    *   **Splitting:** Split Gaussians if the view-space position gradient exceeds a threshold. Standard threshold $T_{\text{pos}} = 0.02$ every 500 iterations [S1].
    *   **Cloning:** Clone Gaussians with high opacity but low gradient magnitude to fill gaps.
    *   **Compactness Densification:** Perform compactness-based densification every 1000 iterations to ensure complete geometry [S1].
    *   **Pruning:** Remove Gaussians with opacity $\alpha < \alpha_{\text{min}} = 0.05$ and excessively large world-space or view-space radius every 200 iterations [S1].

### Pseudocode
```python
# Standard 3DGS Training Loop Implementation
# Assumes gsplat library for rasterization [S3]

def train_3dgs(gaussians, training_images, num_iterations=30000):
    optimizer = Adam(gaussians.parameters(), lr=1e-3)
    
    for iteration in range(1, num_iterations + 1):
        # 1. Sample a random training image
        image, camera_pose = random_sample(training_images)
        
        # 2. Forward Pass: Rasterize
        # Use half-precision fetches for features [S2]
        rendered_image = gsplat_rasterize(
            gaussians.positions,
            gaussians.scales,
            gaussians.quaternions,
            gaussians.opacities,
            gaussians.sh_coeffs,
            camera_pose,
            image.resolution
        )
        
        # 3. Compute Loss
        # Apply automatic scaling factor for FP16 stability [S2]
        loss = compute_loss(rendered_image, image.gt)
        
        # 4. Backward Pass
        optimizer.zero_grad()
        loss.backward()
        
        # 5. Optimizer Step
        optimizer.step()
        
        # 6. Adaptive Densification & Pruning
        if iteration % 100 == 0:
            # Compute view-space position gradients
            gradients = compute_view_space_position_gradients(gaussians)
            
            # Splitting: Threshold T_pos = 0.02 [S1]
            split_candidates = gaussians[gradients > 0.02]
            gaussians = split_gaussians(gaussians, split_candidates)
            
            # Pruning: Opacity < 0.05 [S1]
            gaussians = prune_gaussians(gaussians, alpha_min=0.05)
            
        if iteration % 1000 == 0:
            # Compactness-based densification [S1]
            gaussians = compactness_densify(gaussians)
            
        if iteration % 500 == 0:
            # Additional split check [S1]
            split_candidates = gaussians[gradients > 0.02]
            gaussians = split_gaussians(gaussians, split_candidates)

    return gaussians
```

### Edge Cases and Pitfalls
*   **Scene Extent Bias:** Using camera positions to define scene extent can lead to incorrect splitting/pruning if cameras are clustered (e.g., orbiting a small object in a large environment) [S4]. Use the corrected SfM-based extent [S4].
*   **Half-Precision Stability:** Training in FP16 requires loss scaling to prevent gradient underflow [S2].
*   **Overfitting in Sparse Views:** Standard 3DGS overfits to limited views. Use techniques like DropGaussian (randomly removing Gaussians during training) or Denoise-GS (self-supervised denoising) [S6, S16856-dropgaussian.md].

### Corrected Scene-Extent
A method to calculate scene extent based on the SfM point cloud rather than camera positions to avoid bias from camera distribution (e.g., orbiting a small object in a large environment) [S4]. The corrected extent $e'_{\text{scene}}$ is computed as $\frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2$, where $\bar{C}$ is the average camera position and $p_i$ are SfM points [S4]. The default 3DGS extent $e_{\text{scene}} = 1.1 \cdot \max_{i} \|\bar{C} - C_i\|_2$ can lead to incorrect splitting/pruning if cameras are clustered [S4].

### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ using a compact MLP to selectively enlarge covariances, creating pixel-wise variable blur kernels [S5]. The transformed covariance is projected to 2D space and used as a blur kernel during rasterization [S5]. If $\delta s_j$ is constant, it degrades to uniform Gaussian blur [S5]. This allows spatially varying blur shapes, unlike naive or learnable single-kernel approaches [S5].

### Denoise-GS
A self-supervised denoising method for sparse-view 3DGS combining unsupervised image denoising (Noise2Void) with differentiable 3DGS [S6]. Round 1: Train UNet with N2V, process denoised images through InstantSplat to initialize/train 3DGS, and filter rendered results [S6]. Round 2: Fine-tune UNet with composite loss (low-frequency and perceptual consistency) and render again [S6]. Unlike supervised methods, it requires no paired clean data and is robust to non-Gaussian noise [S6].

### Multi-Scale Constraint
Applies different scales to Gaussians based on viewer distance to improve distant object rendering [S7]. Uses a position-aware factor $\gamma(\mu)$: $\gamma(\mu) = 1$ if $\|\mu - c\|^2 < 2r$, else $\|\mu - c\|^2 / r - 1$, where $r$ is scene radius and $c$ is camera center [S7]. Cloning occurs if $\max(s) < g \cdot \gamma(\mu)$, splitting if $\max(s) \ge g \cdot \gamma(\mu)$, and elimination if $\max(s) > b \cdot \gamma(\mu)$, with $g$ and $b$ as threshold parameters [S7].

### LS-Gaussian Viewpoint Transformation
Leverages inter-frame continuity to transform viewpoints between consecutive frames for sparse rendering, rather than rendering each frame separately [S8]. Operates at the tile/Gaussian level to reduce preprocessing and sorting costs [S8]. Rendering quality degrades as the number of consecutively transformed frames increases due to interpolation error accumulation [S8]. Used in LS-Gaussian to fully render only one frame in every 6 frames [S8].

### Camera Localisation for Convergence Basin
Localizes camera pose by minimizing photometric error against ground-truth color, fixing $G_{init}$ during optimization [S9, unofficial]. Initialize $T_{CW}$ at a test view's position and optimize for 1000 iterations [S9, unofficial]. Success if estimated pose converges to within 1cm of the target view [S9, unofficial]. Pose is found by $\mathbf{T}_{CW}^{est} = \underset{\mathbf{T}_{CW}}{\arg \min} \left\| I(\mathcal{G}_{init}, \mathbf{T}_{CW}) - \bar{I}_{target} \right\|_1$ [S9, unofficial].

### DiffGS Framework
Applies optimization during Gaussian extraction to optimize Gaussians to exact locations [S10]. Uses a truncation function $\lambda$ for GauPF and a projection function $\tau$ (e.g., $\tau(x) = e^{-x}$) [S10]. Performance: 50K Gaussians (PSNR 28.61, SSIM 0.9787, LPIPS 0.0251), 100K (PSNR 30.35, SSIM 0.9838, LPIPS 0.0151), 350K (PSNR 34.01, SSIM 0.9879, LPIPS 0.0149) [S10].

### Opacity Offset Table for DSA
Constructs an opacity offset table to model changes in digital subtraction angiography [S11].

### Conditional Splat Approximation
Approximates the influence range of a 3D Gaussian on a slice using a 2D ellipse splat scaled by the marginal factor [S12, unofficial]. Qualitative validation shows close overlap with true 3D Gaussian iso-probability contours [S12, unofficial]. Provides an accurate and efficient approximation of the original 3D Gaussian’s influence range [S12, unofficial].

### 3DGS Uncertainty Calculation via Fisher Information
Computes an uncertainty attribute based on the negative log-likelihood of the rendered pixel value, interpreted as Fisher information [S13]. Uncertainty $\bar{C}_{V;G} = -\log p_f(\pi|V; G)$, where $p_f$ is the probability density function of the rendered pixel $\pi$ given view $V$ and Gaussian parameters $G$ [S13]. Computed as the dot product of the gradient with itself [S13]. Assumes volume rendering meets regularity conditions: partial derivative exists almost everywhere, integral differentiability, and support independence from $G$ [S13].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot T)$ per iteration, where $N$ is the number of Gaussians and $T$ is the number of tiles. Sorting dominates the cost.
*   **Memory Complexity:** $O(N \cdot K)$, where $K$ is the number of SH coefficients.
*   **Performance:** Real-time rendering (30-100+ FPS) on modern GPUs [S8, S16214-hardware-and-computational-acceleration.md]. Training time varies by scene size but typically takes minutes to hours [S3].
*   **Strengths:** High visual fidelity, real-time rendering, explicit representation.
*   **Limitations:** High memory usage for large scenes, potential for floating artifacts in large-scale scenes without partitioning [S7], sensitivity to initialization and densification parameters [S4].
*   **When to Use:** Real-time novel view synthesis, high-quality 3D reconstruction from multi-view images.
*   **When Not to Use:** Scenes with extreme dynamic range or complex lighting requiring implicit volume rendering, or when memory is severely constrained without compression [S12943-data-compression-and-storage-optimization.md].

## Background
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1, S2, S3]. It builds on the idea of using explicit 3D primitives for radiance field representation, enabling differentiable rasterization. The method has since been extended to handle dynamic scenes, large-scale environments, and various applications like SLAM and text-to-3D generation [S1, S3, S16342-dynamic-and-spacetime-modeling.md].
