# Background Hemisphere Initialization

Also called: Background Hemisphere Initialization and Optimization, Hemisphere Background Model

## Overview
Background Hemisphere Initialization is a technique for handling unbounded scenes in 3D Gaussian Splatting by modeling the distant background as a separate, fixed-radius hemisphere of Gaussians [S1]. It solves the problem of representing distant regions (hundreds of meters away) that would otherwise require foreground Gaussians to extend to infinity, which degrades novel view synthesis quality [S1]. It sets itself apart from standard background models by explicitly disentangling the sky from the foreground geometry using a moving hemisphere that maintains a fixed relative distance to the target camera [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** $K$ reference images with known camera poses, and the midpoint of the foreground volume [S1].
*   **Output:** A set of background Gaussian primitives $\mathcal{G}_{bg}$ with defined positions, colors, scales, fixed rotations, and fixed opacities [S1].

**Data Structures:**
The background is represented as a set of $N_{bg}$ 3D Gaussians [S1]. Each Gaussian $i$ has:
*   Position $\boldsymbol{\mu}_i$: Located on the surface of a hemisphere [S1].
*   Color $\mathbf{c}_{bg}$: Regressed from projected 2D colors [S1].
*   Scale $\mathbf{s}_{bg}$: Initial scale from KNN plus a learned residual [S1].
*   Rotation $\mathbf{q}_{bg}$: Fixed unit quaternion $[1, 0, 0, 0]$ [S1].
*   Opacity $\alpha_{bg}$: Fixed value $1.0$ [S1].

**Steps:**
1.  **Hemisphere Placement:** Center a hemisphere at the midpoint of the foreground volume [S1]. Set a fixed radius $r_{bg} = 100$ meters [S1]. The hemisphere moves with the vehicle/camera such that the relative distance to the target camera remains fixed [S1].
2.  **Point Sampling:** Uniformly sample points over the hemisphere surface [S1].
3.  **Color Projection:** Project the sampled background points onto $K$ reference images to retrieve their 2D colors $\{\mathbf{c}_k\}_{k=1}^K$ [S1].
4.  **Scale Initialization:** Initialize the base Gaussian scales $\mathbf{s}_{bg}^{init}$ using the K-Nearest Neighbors (KNN) algorithm on the projected points [S1].
5.  **Parameter Regression:** Use a lightweight two-layer MLP $\mathcal{M}_{bg}$ to regress the color $\mathbf{c}_{bg}$ and the scale residual $\Delta \mathbf{s}_{bg}$ from the projected colors $\{\mathbf{c}_k\}_{k=1}^K$ [S1].
6.  **Final Parameter Assembly:** Compute the final scale by adding the residual to the initial scale [S1]. Set rotation to $[1, 0, 0, 0]$ and opacity to $1$ [S1].

**Formulas:**
The final scale $\mathbf{s}_{bg}$ is computed as:
$$ \mathbf{s}_{bg} = \Delta \mathbf{s}_{bg} + \mathbf{s}_{bg}^{init} $$
where the residual is:
$$ \Delta \mathbf{s}_{bg} = \mathcal{M}_{bg}(\{\mathbf{c}_k\}_{k=1}^K) $$
The color is directly regressed:
$$ \mathbf{c}_{bg} = \mathcal{M}_{bg}(\{\mathbf{c}_k\}_{k=1}^K) $$
Note: $\mathcal{M}_{bg}$ outputs both color and scale residuals [S1].

**Parameters:**
*   $r_{bg}$: Fixed radius of the background hemisphere. Value: $100$ meters [S1].
*   $K$: Number of reference images used for color projection [S1].

**Edge Cases and Pitfalls:**
*   **Occlusion:** Projecting points to reference images may retrieve inaccurate color information if the line of sight is occluded by foreground objects [S1].
*   **Fixed Parameters:** Rotation and opacity are explicitly set and not optimized through the network [S1].

            'color': c_bg[i],

## Subtopics

### Generalizable Background Model
A variant where the hemisphere model is designed to be generalizable across scenes [S1]. It uniformly samples points over a hemisphere with fixed radius $r_{bg}$ that moves along with the camera motion [S1]. It employs a lightweight two-layer MLP $\mathcal{M}_{bg}$ to learn color $\mathbf{c}_{bg}$ and scale $\mathbf{s}_{bg}$ from projected colors $\{\mathbf{c}_k\}_{k=1}^K$ [S1]. The formula is $\mathbf{c}_{bg}, \mathbf{s}_{bg} = \mathcal{M}_{bg}(\{\mathbf{c}_k\}_{k=1}^K)$ [S1]. Rotation and opacity remain fixed parameters [S1].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Strengths:** Efficiently handles distant backgrounds without requiring foreground Gaussians to extend to infinity, reducing artifacts [S1]. Keeps background rendering efficient via standard 3DGS rasterization [S1].
*   **Limitations:** Assumes the background is distant and static relative to the camera motion [S1]. Fixed opacity and rotation limit flexibility for complex sky conditions [S1].
*   **When to use:** Urban view synthesis or autonomous driving scenarios where the background (sky, distant buildings) is hundreds of meters away and relatively stable [S1].

## Background
Originated in **EVolSplat: Efficient Volume-based Gaussian Splatting for Urban View Synthesis** (2025) [S1]. It addresses the limitations of standard 3D Gaussian Splatting in unbounded urban environments, where foreground Gaussians struggle to represent distant sky regions [S1]. The method was developed to enable efficient reconstruction of full urban scenes by separating foreground and background representations [S1].
