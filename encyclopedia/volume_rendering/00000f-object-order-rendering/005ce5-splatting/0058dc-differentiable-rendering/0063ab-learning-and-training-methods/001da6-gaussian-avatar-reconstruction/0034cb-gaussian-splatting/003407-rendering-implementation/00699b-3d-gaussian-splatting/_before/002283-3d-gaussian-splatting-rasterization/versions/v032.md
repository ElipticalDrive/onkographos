# 3D Gaussian Splatting Rasterization

Also called: 3D Gaussian Splatting (3DGS), 3DGS Rasterization, Differentiable Gaussian Rasterization, TrimGS, gsplat.rasterization

## Overview
3D Gaussian Splatting Rasterization is a screen-space rendering method that projects a set of 3D Gaussian primitives into 2D ellipses and alpha-composites them to produce an RGB image [S3, unofficial]. It solves the problem of real-time, high-fidelity rendering of scenes represented by discrete, point-based splats, distinguishing itself from volumetric ray-marching methods like NeRF by using explicit geometric primitives and from standard OpenGL rasterization by computing analytic gradients for the non-linear projection and compositing operations [S6, unofficial][S10]. It builds on [Rendering Implementation](7155-rendering-implementation.md) by implementing the specific forward and backward passes required for optimization.

## How it works
**Inputs and Outputs:**
*   **Inputs:**
    *   `means`: 3D positions, shape $[N, 3]$ [S2, unofficial].
    *   `quats`: Rotation quaternions (w, x, y, z), shape $[N, 4]$ [S2, unofficial].
    *   `scales`: Log-scales, shape $[N, 3]$ [S2, unofficial].
    *   `opacities`: Log-opacities, shape $[N]$ [S2, unofficial].
    *   `colors`: Spherical Harmonics (SH) coefficients or direct RGB, shape $[N, D]$ or $[N, K, 3]$ [S2, unofficial].
    *   `viewmats`: Camera view matrices, shape $[C, 4, 4]$ [S2, unofficial].
    *   `Ks`: Camera intrinsic matrices, shape $[C, 3, 3]$ [S2, unofficial].
    *   `width`, `height`: Image dimensions [S2, unofficial].
    *   `tile_size`: Integer, default 16 [S2, unofficial].
    *   `near_plane`, `far_plane`: Floats, defaults 0.01, 1e10 [S2, unofficial].
    *   `render_mode`: String, e.g., "RGB", "D", "ED" [S2, unofficial].
    *   `rasterize_mode`: String, "classic" or "antialiased" [S2, unofficial].
    *   `camera_model`: String, "pinhole", "ortho", or "fisheye" [S2, unofficial].
    *   `sh_degree`: Integer or None [S2, unofficial].
*   **Outputs:**
    *   `render_colors`: Shape $[C, H, W, D]$ [S2, unofficial].
    *   `render_alphas`: Shape $[C, H, W, 1]$ [S2, unofficial].

**Data Structures:**
*   **Gaussian Attributes:** Stored in contiguous arrays or tensors. For GPU TBOs, per-splat data is packed into 32-byte blocks: `center.xyz` (float bits), covariance upper-triangle (packed half-floats), and DC color/alpha (unorm 8-bit) [S8, unofficial].
*   **Tile Intersection:** Tiles are computed as $tile\_width = \lceil width / tile\_size \rceil$, $tile\_height = \lceil height / tile\_size \rceil$ [S2, unofficial]. Intersection IDs and offsets map Gaussians to tiles for efficient rasterization [S2, unofficial].

**Steps:**

1.  **Activation and Covariance Construction:**
    *   Normalize quaternions: $q_{norm} = q / \|q\|$ [Parent].
    *   Exponentiate scales: $s_{eff} = \exp(s)$ [Parent].
    *   Construct 3D covariance: $\Sigma_{3D} = R S S^T R^T$ [Parent].
    *   Sigmoid opacities: $\alpha_{eff} = \sigma(\alpha)$ [Parent].

2.  **Camera Space Transformation:**
    *   Transform means: $\mu' = V \mu$ [Parent].
    *   Transform covariance: $\Sigma' = V_{1:3, 1:3} \Sigma_{3D} V_{1:3, 1:3}^T$ [Parent].

3.  **Projection to Screen Space:**
    *   Compute Jacobian $J$ at $\mu'$ [Parent].
    *   Compute 2D covariance: $\Sigma_{2D} = J \Sigma' J^T$ [Parent].
    *   Compute 2D mean: $\mu_{2D} = (f_x \mu'_x / \mu'_z + c_x, f_y \mu'_y / \mu'_z + c_y)$ [Parent].
    *   *Antialiased Mode:* Compute compensation factors based on the ratio of the projected area to the pixel area [S2, unofficial].

4.  **Culling and Sorting:**
    *   Filter Gaussians behind the near plane ($\mu'_z < z_{near}$) [Parent].
    *   Compute bounding radii for each Gaussian in screen space [S2, unofficial].
    *   Determine tile intersections: `isect_tiles(means2d, radii, depths, ...)` [S2, unofficial].
    *   Sort Gaussians by depth within each tile or globally using radix sort [S4, unofficial].

5.  **SH Evaluation (if `sh_degree` is not None):**
    *   Compute view directions: $dirs = \mu - campos$ [S2, unofficial].
    *   Evaluate SH: $c(d) = \sum_{\ell=0}^{N} \sum_{m=-\ell}^{\ell} \beta_{\ell m} Y_{\ell m}(d)$ [S1].
    *   Clamp colors: $c = \max(c + 0.5, 0.0)$ [S2, unofficial].

6.  **Rasterization and Compositing:**
    *   For each pixel, iterate over Gaussians in sorted order [S4, unofficial].
    *   Compute alpha contribution: $\alpha_{pixel} = \alpha_{eff} \cdot \exp\left(-\frac{1}{2} \mathbf{x}^T \Sigma_{2D}^{-1} \mathbf{x}\right)$ [Parent].
    *   *Antialiased:* Multiply $\alpha_{pixel}$ by compensation factor [S2, unofficial].
    *   Update transmittance: $T \leftarrow T \cdot (1 - \alpha_{pixel})$ [Parent].
    *   Accumulate color: $C_{acc} \leftarrow C_{acc} + T \cdot \alpha_{pixel} \cdot c$ [Parent].
    *   Early termination if $T < \tau$ [Parent].

**Pseudocode:**

```python
def rasterize_gaussians(means, quats, scales, opacities, colors, viewmats, Ks, width, height, tile_size=16, near_plane=0.01, far_plane=1e10, sh_degree=None, render_mode="RGB", rasterize_mode="classic", camera_model="pinhole"):
    """
    Renders 3D Gaussians to 2D images.
    Returns: render_colors, render_alphas
    """
    C = viewmats.shape[0] # Number of cameras
    N = means.shape[0]    # Number of Gaussians
    
    # 1. Activation
    q_norm = quats / norm(quats, axis=1, keepdims=True)
    s_eff = exp(scales)
    alpha_eff = sigmoid(opacities)
    
    # 2. Covariance Construction
    R = quat_to_rotmat(q_norm)
    S = diag(s_eff)
    cov_3d = R @ S @ S.T @ R.T # Shape [N, 3, 3]
    
    # 3. Camera Space & Projection
    # Transform means to camera space
    means_cam = einsum("cij,nj->cni", viewmats[:,:3,:3], means) + viewmats[:,:3,3][:, None, :]
    
    # Transform covariance to camera space
    V_3x3 = viewmats[:,:3,:3]
    cov_cam = einsum("cij,njk,cik->cni", V_3x3, cov_3d, V_3x3)
    
    # Project to 2D
    # Compute Jacobian J based on camera intrinsics Ks and means_cam
    # J depends on fx, fy, cx, cy and means_cam.z
    J = compute_jacobian(Ks, means_cam)
    
    # 2D Covariance: Sigma_2D = J * Sigma_cam * J^T
    cov_2d = einsum("cij,njk,cik->cni", J, cov_cam, J)
    
    # 2D Means
    means_2d = project_means(Ks, means_cam)
    
    # 4. Culling and Sorting
    # Filter by near plane
    valid_mask = means_cam[:,:,2] >= near_plane
    
    # Compute radii and tile intersections
    radii = compute_radii(cov_2d)
    tiles_per_gauss, isect_ids, flatten_ids = isect_tiles(means_2d, radii, means_cam[:,:,2], tile_size, width, height)
    
    # Sort Gaussians by depth within tiles
    sorted_indices = sort_by_depth(means_cam, tiles_per_gauss, isect_ids)
    
    # 5. SH Evaluation (if applicable)
    if sh_degree is not None:
        dirs = means[None, :, :] - viewmats[:,:3,3][:, None, :]
        dirs = dirs / norm(dirs, axis=2, keepdims=True)
        colors = evaluate_sh(sh_degree, dirs, colors)
        colors = max(colors + 0.5, 0.0)
    
    # 6. Rasterization
    # Initialize output buffers
    render_colors = zeros((C, height, width, 3))
    render_alphas = zeros((C, height, width, 1))
    
    # Broadcast opacities and colors to [C, N, ...]
    opacities_cn = broadcast(opacities, (C, N))
    colors_cn = broadcast(colors, (C, N, 3))
    
    # Apply antialiased compensation if needed
    if rasterize_mode == "antialiased":
        compensations = compute_compensations(cov_2d)
        opacities_cn = opacities_cn * compensations
        
    # Iterate over tiles and Gaussians
    for c in range(C):
        for tile_y in range(ceil(height/tile_size)):
            for tile_x in range(ceil(width/tile_size)):
                # Get Gaussians intersecting this tile
                gaussians_in_tile = get_gaussians_for_tile(tile_x, tile_y, isect_ids, flatten_ids)
                
                # Iterate front-to-back
                for g in gaussians_in_tile:
                    # Compute alpha at pixel offsets
                    # x is offset from means_2d[c, g]
                    alpha_pixel = opacities_cn[c, g] * exp(-0.5 * quadratic_form(x, cov_2d[c, g]))
                    
                    # Composite
                    # T is current transmittance for this pixel
                    # C_acc is current accumulated color
                    T = 1.0 - alpha_pixel
                    C_acc = C_acc + T * alpha_pixel * colors_cn[c, g]
                    T_new = T * (1 - alpha_pixel) # Wait, standard alpha compositing:
                    # Correct logic:
                    # weight = alpha_pixel * T_current
                    # C_acc += weight * color
                    # T_next = T_current * (1 - alpha_pixel)
                    
                    # Early termination if T is very small
                    if T_new < 1e-4:
                        break
                        
    # Composite background
    # Where alpha is 0, use background color
    render_colors = render_colors + (1.0 - render_alphas) * background_color
    
    return render_colors, render_alphas
```

## Subtopics

### [3D Gaussian Splatting Differentiable Rasterizer](2813-3d-gaussian-splatting-differentiable-rasterizer.md)
The 3D Gaussian Splatting Differentiable Rasterizer is a screen-space rendering method that projects a set of 3D Gaussian primitives into 2D ellipses and alpha-composites them to produce an RGB image, while providing exact gradients for all Gaussian parameters (position, scale, rotation, opacity, color) and camera poses. It differs from volumetric ray-marching methods like NeRF by using discrete, point-based splatting and from standard OpenGL rasterization by computing analytic gradients for the non-linear projection and compositing operations, enabling end-to-end differentiable training. It builds on [3D Gaussian Splatting Rasterization](2812-3d-gaussian-splatting-rasterization.md) by implementing the specific forward and backward passes required for optimization.

### [Ghost Ellipsoids for Chunked Training](3559-ghost-ellipsoids-for-chunked-training.md)
Ghost Ellipsoids for Chunked Training resolves boundary artifacts in chunked volume training by including ellipsoids from neighboring chunks in the loss computation without updating their parameters, providing boundary context without requiring a global volume or merged model. Unlike chunk-based 3DGS methods that resolve boundary inconsistencies by merging chunks into a global coarse model or through post-training stages, this method requires boundary support during training itself without access to a global volume.

### [2D Gaussian Splatting Rasterization](4815-2d-gaussian-splatting-rasterization.md)
2D Gaussian Splatting Rasterization renders a scene represented by 2D Gaussian primitives (surfels) into RGB, alpha, and normal maps using a custom rasterizer. It differs from standard 3D Gaussian Splatting by operating on surfels projected into screen space, accumulating color and geometric attributes via front-to-back alpha compositing [Parent]. It serves as the Tier-1 NumPy reference implementation for 2D Gaussian Splatting, performing ray-surfel intersection per pixel using the projection matrix.

### [AdR-Gaussian](8365-adr-gaussian.md)
AdR-Gaussian is a rendering acceleration method for 3D Gaussian Splatting that optimizes the rasterization pipeline by moving serial culling operations to a parallel preprocessing stage and balancing computational loads across pixel threads. It achieves significant speedups without reducing the total number of Gaussians, thereby avoiding the quality degradation associated with pruning-based acceleration methods.

### [Projection Geometry and Coordinate Systems](9313-projection-geometry-and-coordinate-systems.md)
This article defines the mathematical framework for transforming 3D Gaussian primitives from world space into the 2D image plane for rasterization in 3D Gaussian Splatting. It solves the problem of accurately projecting 3D ellipsoids onto a 2D sensor plane while preserving geometric fidelity and enabling differentiable rendering. It sets apart from standard perspective projection by supporting optimal tangent-plane projections [3293-optimal-gaussian-splatting.md] and specialized geometries such as cone-beam X-ray scanning [3458-3d-gaussian-splatting-rasterization-cone-beam-scanner-space.md].

### [Point-Based Ray Tracing for Visibility](10934-point-based-ray-tracing-for-visibility.md)
Point-Based Ray Tracing for Visibility serves as a sparse visibility oracle that evaluates transmittance along sampled light directions using a bounding volume hierarchy (BVH) of Gaussian proxies, enabling evaluation from any point in space in any direction. Unlike the camera-tied rasterizer, it decouples visibility estimation from screen-space projection, allowing it to act as a drop-in companion to standard 3D Gaussian Splatting (3DGS) by reusing the same EWA-splatting formulation for consistent blending without requiring training mismatch.

### [Primitive Representation](11838-primitive-representation.md)
Primitive Representation defines the geometric and photometric data structures used to approximate a 3D scene in Gaussian Splatting methods [G]. It solves the problem of representing continuous geometry and appearance with discrete, differentiable primitives that can be efficiently rasterized [G]. It sets itself apart from parent methods by explicitly defining the kernel shape (e.g., isotropic, half-space, or hybrid Bézier) and the associated attribute storage (e.g., opacity, normals, control points) that determine how light interacts with the primitive during rendering [G].

### [Shading and Lighting Models](11924-shading-and-lighting-models.md)
Shading and Lighting Models extend the standard 3D Gaussian Splatting rasterization pipeline to support physically based rendering (PBR), self-occlusion, and anti-aliased forward shading. While standard splatting assumes a fixed, uniform lighting environment and simple alpha blending, this family introduces mechanisms for deferred shading pipelines, light-space rasterization for shadows, and analytic integration approximations for multiscale fidelity. It differs from sibling methods like [Analytic-Splatting Forward Shading](3459-analytic-splatting-forward-shading.md) by focusing on material attributes and light interaction rather than just pixel-area integration, and from [Transparency and Blending Models](9274-transparency-and-blending-models.md) by explicitly handling light source geometry and PBR material buffers.

### [Reflective Gaussian Splatting](12321-reflective-gaussian-splatting.md)
Reflective Gaussian Splatting (Ref-Gaussian) is a framework for the real-time, high-quality rendering of reflective objects with inter-reflection effects, addressing the limitations of standard 3D Gaussian Splatting in modeling complex surfaces and multi-view inconsistencies. It distinguishes itself from sibling methods like [3D Gaussian Splatting Rasterization](2812-3d-gaussian-splatting-rasterization.md) by utilizing 2D Gaussian primitives for view-consistent geometry and employing physically based deferred rendering with split-sum approximation to stabilize optimization and enable efficient inter-reflection modeling without heavy Monte Carlo sampling.

### [Ray-Splat Intersection Algorithms](13401-ray-splat-intersection-algorithms.md)
Ray-splat intersection algorithms compute the contribution of 3D Gaussians to a pixel by analytically evaluating the Gaussian density along the viewing ray, rather than projecting the 3D Gaussian onto the 2D image plane. This approach solves the problem of numerical instability and geometric inaccuracy that arises when splats become degenerate or when perspective-correct depth estimation is required [3403-perspective-correct-3d-gaussian-splatting-via-pl-cker-coordi.md][5992-gaussian-opacity-fields-gof.md]. Unlike standard rasterization which approximates the 3D Gaussian as a 2D ellipse, these methods treat the Gaussian as a volumetric primitive, enabling accurate depth extraction and surface reconstruction [5992-gaussian-opacity-fields-gof.md].

### [Rasterization Pipeline Optimization](15109-rasterization-pipeline-optimization.md)
Rasterization Pipeline Optimization refers to techniques that accelerate the rendering of 3D Gaussians by improving the efficiency of the rasterization stage, addressing the bottleneck of processing non-intersecting pixels and managing memory bandwidth. It sets itself apart from sibling methods by focusing on the computational pipeline (sorting, hardware acceleration, and culling) rather than the primitive representation or shading models.

### Temporal Marginal Probability Filtering
Pre-rasterization culling step that removes 4D Gaussians with negligible temporal support at the current frame timestamp, stabilizing rendering speed across video length [S6, unofficial]. Compute the marginal probability $p_i(t)$ for each 4D Gaussian $i$ at the current frame's timestamp $t$. Discard Gaussians with negligible $p_i(t)$ before executing standard frustum culling. Unlike methods where Gaussian count scales with video length, this filtering keeps active Gaussians constant, making the approach friendly to long videos in terms of rendering speed [S6, unofficial].

### t-distribution truncation for splatting
A projection truncation technique that replaces the fixed three-sigma rule used in vanilla 3DGS with a $\nu$-dependent critical value interpolation to handle fat-tailed Student's t-distributions [S7]. For t-distributions with thin tails (high $\nu$), apply the standard three-sigma rule directly. For fat-tailed distributions (low $\nu$), obtain critical values for different $\nu$ degrees from reference [9] and interpolate between them to compute the appropriate truncation threshold. Using a fixed three-sigma threshold on fat-tailed t-distributions causes excessive truncation or leakage. Interpolation across $\nu$ degrees resolves this [S7].

### Progressive Normal Propagation
Uses progressive propagation along normals to fill texture-less regions [S5, unofficial].

### Splat TBO Upload & Layout
Packs per-splat data (center, covariance, DC color/alpha, optional SH) into Texture Buffer Objects (TBOs) for GPU consumption [S8, unofficial]. Iterate over splats. For each splat, copy center.xyz as raw float bits to d[0..2]. Pack covariance upper-triangle to d[3..5] using packHalf2x16: d[3]=covA[0],covA[1]; d[4]=covA[2],covB[0]; d[5]=covB[1],covB[2]. Pack DC color/alpha to d[6] using packDCColor. Set d[7]=0. Create GL_TEXTURE_BUFFER buffer with GL_RGBA32UI format. Bind to tbo_tex_. For non-DC SH coefficients, pack each coefficient's RGB into RGBA16F texels (B=0), layout is [splat0_c1, splat0_c2, …, splat1_c1, splat1_c2, …]. Create SH TBO with GL_RGBA16F format. Memory: 32 B/splat for base TBO + 8 B × sh_coeffs_per_splat_ × splat_count_ for SH TBO. sh_coeffs_per_splat_ = (active_sh_degree_ + 1)^2 - 1 (excludes DC) [S8, unofficial].

### 3D Gaussian Splatting for X-ray Projection Rasterization
A rendering technique that leverages 3D Gaussian Splatting (3DGS) to rasterize X-ray projections by modeling X-ray attenuation using the Beer-Lambert law, treating the volume as a collection of 3D Gaussians with density and isotropic absorption [S9, unofficial]. The exponential transmittance model $T(t)$ is defined as $T(t) = \exp\left(-\int_{t_0}^t \sigma(\mathbf{r}(s)) ds\right)$, where $\mathbf{r}(t) = \mathbf{o} + t\mathbf{d}$ represents a 3D point along a ray with origin $\mathbf{o}$ and direction $\mathbf{d}$, and $\sigma(\mathbf{p})$ denotes the density at point $\mathbf{p}$ [S9, unofficial]. Color attributes are optional and can be excluded from the rendering model, accounting solely for isotropic absorption [S9, unofficial].

### Ray-Gaussian Intersection
Project the 3D Gaussian's covariance and center onto the camera ray to convert the 3D influence into a 1D Gaussian function along that specific ray [S10].

## Operating characteristics
*   **Time Complexity:** Dominated by sorting $N$ Gaussians, typically $O(N \log N)$ or $O(N)$ with radix sort [S4, unofficial]. Rasterization is $O(P \cdot K)$ where $P$ is pixels and $K$ is average splats per pixel.
*   **Memory Complexity:** $O(N)$ for Gaussian attributes. High VRAM usage: 4GB to view, 12GB to train [S4, unofficial]. Large disk size: 1GB+ for a scene [S4, unofficial].
*   **Performance:** Real-time rendering rates (30+ FPS) on modern GPUs [S1]. The primary bottleneck is sorting millions of gaussians, which is done efficiently in the original implementation using CUB device radix sort, a highly optimized sort only available in CUDA [S4, unofficial].
*   **Strengths:** High-quality, photorealistic scenes; fast, real-time rasterization; relatively fast to train [S4, unofficial].
*   **Limitations:** High VRAM usage; large disk size; incompatible with existing rendering pipelines (Vulkan, DirectX, WebGPU) without adaptation; static (for now) [S4, unofficial].
*   **When to use:** Real-time visualization of learned radiance fields; training differentiable scene representations.
*   **When not to use:** When strict compatibility with legacy graphics APIs is required without custom shaders; when memory is severely constrained.

## Background
3D Gaussian Splatting was introduced in "3D Gaussian Splatting for Real-Time Radiance Field Rendering" [S4, unofficial]. It represents a breakthrough in static scene rendering by representing scenes as collections of 3D Gaussian primitives, enabling real-time rendering rates while maintaining high visual fidelity [S1]. The method is analogous to triangle rasterization but uses Gaussians instead of triangles [S4, unofficial]. It is typically initialized using Structure from Motion (SfM) methods like COLMAP to estimate a point cloud, which is then converted to Gaussians [S4, unofficial]. Training uses Stochastic Gradient Descent with automated densification and pruning [S4, unofficial].
