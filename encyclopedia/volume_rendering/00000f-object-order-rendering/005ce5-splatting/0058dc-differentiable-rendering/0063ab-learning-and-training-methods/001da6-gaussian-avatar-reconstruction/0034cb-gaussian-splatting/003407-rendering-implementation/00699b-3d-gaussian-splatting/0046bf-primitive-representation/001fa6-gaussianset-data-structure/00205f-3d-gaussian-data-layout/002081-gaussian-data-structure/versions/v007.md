# Gaussian Data Structure

Also called: GaussianList

## Overview
The Gaussian Data Structure defines the memory layout and field organization for 3D Gaussian primitives in differentiable volume rendering, specifically within the 3D Gaussian Splatting (3DGS) framework. It solves the problem of efficiently storing and accessing high-dimensional geometric and appearance attributes (position, scale, rotation, opacity, spherical harmonics, and covariance) on the GPU for rasterization and gradient-based optimization. It sets itself apart from its parent [3D Gaussian Data Layout](2242-3d-gaussian-data-layout.md) by specifying the concrete container types (e.g., `GaussianList` as a flat array structure) and from its sibling [Gaussian Data Packing](3257-gaussian-data-packing.md) by focusing on the logical attribute grouping rather than low-level bit-packing or compression.

## How it works
The method organizes Gaussian primitives into contiguous GPU buffers to enable batched processing during splatting and densification. The primary container is the `GaussianList` structure, which aggregates per-attribute arrays.

### Inputs and Outputs
- **Input**: A set of $N$ Gaussian primitives, each defined by position, scale, rotation, opacity, and appearance coefficients.
- **Output**: A `GaussianList` instance containing aligned arrays of these attributes, ready for GPU kernel execution.

### Data Structures
The core structure is `GaussianList`, which stores attributes in separate, contiguous arrays (Structure of Arrays, SoA) to maximize memory bandwidth during rendering. The fields are [S1, unofficial]:

1.  **`positions`**: `Matrix4xX<f32>` (or `Vector3<f32>[N]`). Stores the 3D center $(x, y, z)$ of each Gaussian. The source uses a 4xN matrix notation, implying 4 rows for potentially homogeneous coordinates or padding, but typically 3 floats are used for position.
2.  **`scales`**: `Matrix3xX<f32>` (or `Vector3<f32>[N]`). Stores the 3D scale $(s_x, s_y, s_z)$ for each Gaussian.
3.  **`opacities`**: `DVector<f32>` (or `f32[N]`). Stores the scalar opacity $\alpha_i$ for each Gaussian.
4.  **`rotations`**: `Matrix4xX<f32>` (or `Quaternion<f32>[N]`). Stores the 4D quaternion $(w, x, y, z)$ representing the rotation of each Gaussian.
5.  **`sh`**: `Matrix48xX<f32>` (or `f32[N][48]`). Stores the Spherical Harmonics coefficients. The layout is a flat array of size 48, corresponding to the maximum for degree 3. The layout order is $C_{0,R}, C_{0,B}, C_{0,G}, C_{1,R}, C_{1,B}, C_{1,G}, \dots$ [S1, unofficial].
6.  **`num_gaussians`**: `usize`. The current count of active Gaussians $N$.
7.  **`cov3d`**: `Matrix3xX<f32>` (or `Matrix3<f32>[N]`). Stores the precomputed 3D covariance matrix $\Sigma_{3D}$ for each Gaussian. This is derived from scale and rotation to avoid recomputation during rendering [S1, unofficial].

The individual primitive struct `Gaussian` (used during construction or loading) contains [S1, unofficial]:
-   `position`: `Vector3<f32>`
-   `scale`: `Vector3<f32>`
-   `opacity`: `f32`
-   `rotation`: `Quaternion<f32>`
-   `sh`: `SVector<f32, 48>`
-   `cov3d`: `Matrix3<f32>`

### Steps
1.  **Initialization**: Allocate arrays for `positions`, `scales`, `opacities`, `rotations`, `sh`, and `cov3d` with capacity $N_{max}$. Initialize `num_gaussians` to 0.
2.  **Loading/Creation**: For each new Gaussian primitive $i$:
    a. Set `positions[i]` to the 3D center.
    b. Set `scales[i]` to the 3D scale.
    c. Set `opacities[i]` to the initial opacity.
    d. Set `rotations[i]` to the initial quaternion.
    e. Set `sh[i]` to the initial Spherical Harmonics coefficients.
    f. Compute the 3D covariance $\Sigma_{3D}$ from `scales[i]` and `rotations[i]` and store in `cov3d[i]`.
    g. Increment `num_gaussians`.
3.  **Covariance Precomputation**: The 3D covariance $\Sigma_{3D}$ is computed as $\Sigma_{3D} = R S S^T R^T$, where $R$ is the rotation matrix derived from the quaternion and $S$ is the diagonal scale matrix. This is stored in `cov3d` to allow efficient projection to 2D during rendering [S1, unofficial].
4.  **Buffer Management**: Ensure arrays are contiguous in GPU memory. If `num_gaussians` exceeds capacity, resize arrays (see [Dynamic Buffer Management](3753-dynamic-buffer-management.md)).

### Formulas
-   **3D Covariance Construction**:
    $$ \Sigma_{3D} = R S S^T R^T $$
    Where $R$ is the rotation matrix from the quaternion and $S = \text{diag}(s_x, s_y, s_z)$ [S1, unofficial].
-   **Spherical Harmonics Layout**:
    The SH coefficients are stored in a flat array of size 48. The index for coefficient $k$ (band $b$, component $c$) is determined by the specific ordering $C_{0,R}, C_{0,B}, C_{0,G}, C_{1,R}, \dots$ [S1, unofficial].

### Parameters
-   **SH Degree**: Max degree 3, resulting in 48 coefficients per Gaussian [S1, unofficial].
-   **Data Type**: `f32` (32-bit float) for all geometric and appearance attributes [S1, unofficial].

### Edge Cases and Pitfalls
-   **Precision**: Using `f32` for covariance and rotation may lead to precision issues in large-scale scenes or when Gaussians are very small. [G] Normalization of quaternions should be performed after optimization steps to prevent drift.
-   **Boundary**: The `sh` array is fixed at 48 elements. If lower-degree SH is used, the remaining coefficients should be zero-initialized to maintain the flat array layout [S1, unofficial].
-   **Degenerate Input**: If a scale component is zero or negative, the covariance becomes singular or invalid. [G] Scales should be clamped to a minimum positive value (e.g., $10^{-4}$) during optimization.

### Pseudocode
```python
import numpy as np

class GaussianList:
    def __init__(self, max_capacity: int):
        self.num_gaussians = 0
        self.max_capacity = max_capacity
        # SoA layout: separate arrays for each attribute
        self.positions = np.zeros((max_capacity, 3), dtype=np.float32)
        self.scales = np.zeros((max_capacity, 3), dtype=np.float32)
        self.opacities = np.zeros(max_capacity, dtype=np.float32)
        self.rotations = np.zeros((max_capacity, 4), dtype=np.float32) # w, x, y, z
        self.sh = np.zeros((max_capacity, 48), dtype=np.float32)
        self.cov3d = np.zeros((max_capacity, 3, 3), dtype=np.float32)

    def add_gaussian(self, position: np.ndarray, scale: np.ndarray, 
                     opacity: float, rotation: np.ndarray, sh: np.ndarray):
        if self.num_gaussians >= self.max_capacity:
            raise ValueError("GaussianList capacity exceeded")
        
        idx = self.num_gaussians
        self.positions[idx] = position
        self.scales[idx] = scale
        self.opacities[idx] = opacity
        self.rotations[idx] = rotation
        self.sh[idx] = sh
        
        # Compute 3D covariance
        self.cov3d[idx] = self._compute_cov3d(scale, rotation)
        
        self.num_gaussians += 1

    def _compute_cov3d(self, scale: np.ndarray, rotation: np.ndarray) -> np.ndarray:
        # Construct rotation matrix from quaternion (w, x, y, z)
        w, x, y, z = rotation
        R = np.array([
            [1 - 2*(y**2 + z**2), 2*(x*y - w*z), 2*(x*z + w*y)],
            [2*(x*y + w*z), 1 - 2*(x**2 + z**2), 2*(y*z - w*x)],
            [2*(x*z - w*y), 2*(y*z + w*x), 1 - 2*(x**2 + y**2)]
        ])
        # Construct scale matrix
        S = np.diag(scale)
        # Covariance = R * S * S^T * R^T
        return R @ (S @ S.T) @ R.T

    def get_cov3d(self, index: int) -> np.ndarray:
        return self.cov3d[index]
```

## Subtopics

### [GSPull](2773-gspull.md)
GSPull is a technique that leverages neural Signed Distance Functions (SDFs) or Unsigned Distance Functions (UDFs) to recover detailed mesh structures from 3D Gaussian Splatting representations. It addresses the limitation of standard 3DGS, which produces volumetric splats rather than explicit surfaces, by integrating distance-field supervision to refine geometry. Unlike methods that directly pull Gaussians to the zero-level set, GSPull uses dense queries around the zero-level set as strong geometric cues to refine the surface conservatively and gradually, preventing error accumulation from ambiguous pulling directions.

### [Composite Error Map and Densification/Pruning Scoring](3396-composite-error-map-and-densification-pruning-scoring.md)
A density control mechanism for 3D Gaussian Splatting that uses a frequency-aware mask and photometric loss to compute densification and pruning scores for Gaussian primitives, reducing redundancy and improving fidelity compared to vanilla 3DGS. It sets itself apart from visibility-based siblings like [Efficient Pruning Score](3598-efficient-pruning-score.md) by weighting counts with photometric loss rather than relying solely on projected footprint visibility, and from [Fisher Sensitivity Score](9664-fisher-sensitivity-score.md) by using a composite error mask rather than a Hessian approximation.

### [Dynamic Buffer Management](3753-dynamic-buffer-management.md)
Dynamic Buffer Management handles the resizing of GPU buffers that store 3D Gaussian splat data during training or streaming, ensuring the allocated capacity matches the active Gaussian count. It solves the problem of buffer overflow when densification adds new Gaussians or buffer under-utilization when pruning removes them [G]. It is distinguished from sibling methods like [GSPull](2773-gspull.md) (which handles data retrieval) and [Composite Error Map and Densification/Pruning Scoring](3396-composite-error-map-and-densification-pruning-scoring.md) (which determines *which* Gaussians to add/remove) by focusing on the *memory infrastructure* required to hold the changing set of active entities [G].

### [GS-W Network Architecture](5927-gs-w-network-architecture.md)
The GS-W Network Architecture is the component of the Gaussian in the Wild (GS-W) method responsible for predicting per-Gaussian appearance attributes and visibility from a set of reference images. It solves the problem of adapting 3D Gaussian Splatting to unconstrained image collections by replacing static color attributes with learnable features that are dynamically sampled based on camera viewpoint. It sets itself apart from standard 3DGS by introducing a U-Net encoder-decoder structure to extract image features and a fusion network to combine these with intrinsic Gaussian attributes, enabling view-dependent appearance modeling without explicit spherical harmonics.

### [VastGaussian](6000-vastgaussian.md)
VastGaussian is a large-scale 3D Gaussian Splatting method that partitions a scene into spatially-disjoint regions to enable independent training and decoupled appearance handling for varying lighting conditions, merging results at render time with feathered overlap. It distinguishes itself from standard 3DGS by solving the scalability and lighting inconsistency problems in city-scale reconstruction through a divide-and-conquer strategy that isolates local geometry and appearance.

### [Data Layout and Storage](6235-data-layout-and-storage.md)
Data Layout and Storage defines the memory organization, serialization, and runtime management of 3D Gaussian Splat attributes (position, scale, rotation, opacity, and spherical harmonics) to enable efficient GPU rendering and optimization [G]. It solves the problem of translating high-level splat representations into contiguous, cache-friendly structures suitable for batched processing, while supporting dynamic scene growth and cross-platform data transfer [G]. It is distinguished from sibling methods by focusing on the raw memory layout and buffer management infrastructure rather than the rendering algorithm itself ([GSPull](2773-gspull.md)), error-based densification ([Composite Error Map and Densification/Pruning Scoring](3396-composite-error-map-and-densification-pruning-scoring.md)), or specific network architectures ([GS-W Network Architecture](5927-gs-w-network-architecture.md)).

### [SLAM and Tracking](6236-slam-and-tracking.md)
SLAM and Tracking in the context of 3D Gaussian Splatting (3DGS) refers to the simultaneous estimation of camera poses and the optimization of the Gaussian scene representation from a stream of images or video. It solves the problem of building a consistent, real-time 3D model while tracking the camera's trajectory in dynamic or static environments. What sets this family apart from standard offline 3DGS reconstruction is the online, incremental nature of the optimization, requiring efficient keyframe management, robust tracking against dynamic objects, and real-time rendering feedback for pose correction.

### [Spherical Harmonics Representation](10084-spherical-harmonics-representation.md)
Spherical Harmonics (SH) is a mathematical basis used in 3D Gaussian Splatting to represent the view-dependent color of each Gaussian primitive. It solves the problem of modeling directional lighting and material properties that vary with the camera viewing angle, which a single static RGB value cannot capture. Unlike static color representations, SH allows for an analytical Jacobian that propagates gradients from the SH coefficients to camera poses during optimization, enabling joint optimization of geometry and appearance.

### [7D Gaussian Splatting](11462-7d-gaussian-splatting.md)
7D Gaussian Splatting (7DGS) is a unified framework for the real-time rendering of dynamic scenes with complex view-dependent effects, representing scene elements as seven-dimensional Gaussians spanning spatial position (3D), time (1D), and viewing direction (3D). It solves the problem of simultaneously modeling spatial geometry, temporal dynamics, and view-dependent appearance (such as scattering and anisotropic reflections) in dynamic scenes, a challenge that prior methods like 4DGS and 6DGS addressed in isolation. Unlike its siblings, 7DGS jointly models all three dimensions in a single coherent framework, using a conditional slicing mechanism to transform 7D Gaussians into time- and view-conditioned 3D Gaussians compatible with existing 3DGS rendering pipelines.

### [Deformation and Dynamic Modeling](11474-deformation-and-dynamic-modeling.md)
Deformation and Dynamic Modeling extends static 3D Gaussian Splatting to handle non-rigid motion and temporal changes by associating time-dependent deformation fields with Gaussian primitives. It solves the problem of rendering dynamic scenes (e.g., humans, vehicles, fluid) in real-time by decomposing the scene into a static canonical representation and a time-varying deformation mechanism. It distinguishes itself from sibling methods like [Sparse-Controlled 3D Gaussian Splatting](6145-sparse-controlled-3d-gaussian-splatting.md) by its reliance on dense per-Gaussian prediction networks rather than sparse control points, and from [4D Gaussian Splatting](https://arxiv.org/abs/2404.03414) by its use of standard MLP architectures instead of HexPlane/k-Plane decoders.

### [Deformable Radial Kernel (DRK) Parametrization](13703-deformable-radial-kernel-drk-parametrization.md)
Deformable Radial Kernel (DRK) parametrization defines the unconstrained learnable parameters for the attributes of 3D Gaussian kernels, ensuring they remain within valid physical ranges through specific activation functions. It distinguishes itself from standard 3D Gaussian Splatting by introducing a specialized three-step activation for basis angles $\theta_k$ to maintain angular separation and monotonicity, and by providing configurable density control thresholds for sparse training scenarios.

### Learnable Scale Modulation for Primitive Compactness
A technique that introduces a learnable per-Gaussian scalar factor to reparameterize effective Gaussian scales, providing an optimization pathway for adapting primitive extent while retaining existing tile-culling rules [S2, unofficial]. It initializes a learnable scalar $\beta_i \in \mathbb{R}$ to zero for each Gaussian primitive and optimizes $\beta_i$ jointly with other Gaussian attributes using the Adam optimizer [S2, unofficial]. The effective covariance is scaled by $\gamma_i^2$, where $\gamma_i = \text{sigmoid}(\beta_i)$, changing the overall extent while keeping anisotropic axis ratios governed by the base scales [S2, unofficial]. The gradient is computed as $\frac{\partial \gamma_i}{\partial \beta_i} = 2 \cdot \text{sigmoid}(\beta_i) \cdot (1 - \text{sigmoid}(\beta_i))$ [S2, unofficial]. This method reduces the average Gaussian count and improves reconstruction quality (PSNR/SSIM) compared to vanilla 3DGS [S2, unofficial].

### Direct-Unrestricted (DU) Variant
DU replaces the structured parameterization $V_{pq} \text{diag}(\Lambda) V_{qq}$ with a free matrix $M \in \mathbb{R}^{3 \times C}$, removing spatial normalization and bounded coupling [S3, unofficial]. The matrix learning rate is set to $5 \times 10^{-6}$, scaled by the median primitive size [S3, unofficial]. Unrestricted direct coordinates alone do not explain quality gains; structured parameterization performs better [S3, unofficial].

### DisC-GS 3D Extension
DisC-GS stores control points of Bézier curves directly in 3D spatial coordinates using attribute $c_{\text{curve}}^{3D} \in \mathbb{R}^{4M \times 3}$ instead of 2D subspace $c_{\text{curve}} \in \mathbb{R}^{4M \times 2}$ [S4]. During rendering, the equation used to acquire $c_{\text{curve}}^{3D}$ from $c_{\text{curve}}$ is omitted, as $c_{\text{curve}}^{3D}$ is introduced as a direct attribute [S4].

### GaussianEditor (Local)
A method tailored for local editing on 3DGS [S5]. It extracts the region of interest (RoI) from text instructions, aligns the text RoI with 3D Gaussians through the image space, and delicately edits within the identified 3D Gaussian RoI [S5].

### Gaussian Grouping
A method enhancing 3DGS by incorporating identity encodings for 3D objects, enabling grouping based on identity, object removal, inpainting, and recomposition [S5]. Compared with DFF, Gaussian Grouping can remove the object with greatly reduced artifacts without leaving a blurry background [S5].

## Operating characteristics
-   **Time Complexity**: Loading and initialization is $O(N)$ for $N$ Gaussians. Rendering is $O(N)$ per pixel, but optimized via tile-based rasterization.
-   **Memory Complexity**: $O(N \cdot D)$, where $D$ is the dimensionality of attributes (position, scale, rotation, opacity, SH, covariance). For degree 3 SH, $D \approx 48 + 3 + 3 + 4 + 1 + 9 = 68$ floats per Gaussian.
-   **Performance**: The SoA layout enables efficient vectorized access on GPUs. Precomputing `cov3d` reduces per-pixel computation during splatting.
-   **Strengths**: High rendering fidelity, real-time performance, differentiable optimization.
-   **Limitations**: High memory usage for large scenes with many Gaussians. Densification can lead to unbounded growth without pruning.
-   **When to use**: Real-time novel view synthesis, high-fidelity reconstruction from images.
-   **When not to use**: Memory-constrained environments, scenes requiring explicit mesh representation without post-processing.

## Background
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1, unofficial]. The Gaussian Data Structure is a fundamental component of this framework, enabling efficient storage and manipulation of Gaussian primitives. The structure has been extended and modified in various subsequent works to address scalability, dynamic scenes, and editing capabilities.
