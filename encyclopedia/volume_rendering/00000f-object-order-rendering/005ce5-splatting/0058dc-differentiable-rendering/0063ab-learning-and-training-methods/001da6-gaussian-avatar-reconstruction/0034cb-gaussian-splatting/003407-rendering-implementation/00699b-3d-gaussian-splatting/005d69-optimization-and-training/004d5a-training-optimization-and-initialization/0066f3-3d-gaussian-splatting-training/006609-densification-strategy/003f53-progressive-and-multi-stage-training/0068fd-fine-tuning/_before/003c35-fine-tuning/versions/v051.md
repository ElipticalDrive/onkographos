# Fine-tuning

Also called: 3DGS Fine-tuning, Fine-tuning Strategy, Gaussian Splatting Fine-tuning

## Overview
Fine-tuning in the context of 3D Gaussian Splatting (3DGS) refers to the phase of optimization where a pre-initialized or pre-trained set of 3D Gaussian primitives is refined to match specific target data, often leveraging pretrained weights or adapting to new domains [S2, S6]. It solves the problem of initializing a sparse or suboptimal representation by allowing the model to adapt its geometry, color, and opacity attributes through gradient-based optimization, frequently enabling densification and pruning operations to correct initialization errors [S2]. It sets itself apart from initial training by typically starting from a structured prior (e.g., a feed-forward prediction or a pre-trained neural generator) rather than raw point clouds, and by focusing on adapting existing parameters rather than solely discovering new geometry [S2, S6].

## How it works
The fine-tuning process generally follows a two-step protocol: initialization via a feed-forward or pre-trained model, followed by differentiable optimization of the Gaussian parameters [S2].

**Inputs and Outputs:**
*   **Input:** A set of initial 3D Gaussian primitives $\mathcal{G}_{init}$ (generated by a feed-forward network or pre-trained backbone), target images/depths, and camera poses.
*   **Output:** Refined Gaussian primitives $\mathcal{G}_{final}$ with optimized means $\mu$, covariances $\Sigma$ (scale $s$, rotation $q$), opacities $\alpha$, and spherical harmonic coefficients $\mathbf{c}$.

**Data Structures:**
The Gaussian set $\mathcal{G}$ is stored as a contiguous array or list of structures. Each element $g_k$ contains:
*   $\mu_k \in \mathbb{R}^3$: Mean position.
*   $s_k \in \mathbb{R}^3$: Scale (log-space for optimization).
*   $q_k \in \mathbb{R}^4$: Rotation (quaternion).
*   $\alpha_k \in \mathbb{R}$: Opacity (sigmoid output).
*   $\mathbf{c}_k$: Spherical Harmonic coefficients (typically degree 3, 48 floats).

**Numbered Steps:**
1.  **Initialization:** Predict initial 3D Gaussian primitives using a feed-forward process or load a pre-trained backbone. Both geometry and color attributes are generated [S2]. If using a pre-trained 3D generator (e.g., for GANs), create a copy of the pre-trained weights to adapt tri-plane features to Gaussian attributes [S6].
2.  **Optimization Setup:** Initialize the optimizer (e.g., Adam) with a learning rate (e.g., $1 \times 10^{-3}$) [S2, S5].
3.  **Differentiable Rendering:** Render the current Gaussian set to 2D images using volumetric integration or alpha blending. The color $\mathbf{C}$ at pixel $(x,y)$ is computed as:
    $$ \mathbf{C} = \sum_{i \in N} \mathbf{c}_i \alpha_i \prod_{j=1}^{i-1} (1 - \alpha_j) $$
    where $N$ are the 2D Gaussians overlapping the pixel, $\mathbf{c}_i$ is the color, and $\alpha_i$ is the opacity [S4].
4.  **Loss Computation:** Compute the loss between rendered images and target images. Common losses include L1 color loss, SSIM, and depth loss [S3, S6].
5.  **Backpropagation:** Backpropagate the loss to update the Gaussian parameters $\mu, s, q, \alpha, \mathbf{c}$ [S2].
6.  **Densification and Pruning (Optional):** Enable growing and pruning of 3D primitives during fine-tuning to remove redundant initial Gaussians and add new ones in high-error regions [S2]. This may involve:
    *   **Cloning/Splitting:** Based on gradient magnitude or rendering error [S3, S4].
    *   **Pruning:** Removing Gaussians with low opacity [S2].
7.  **Iteration:** Repeat steps 3-6 for a specified number of iterations (e.g., 10,000 steps for naive fine-tuning) [S5].

**Parameters:**
*   **Learning Rate:** $1 \times 10^{-3}$ is common for fine-tuning [S2, S5].
*   **Iterations:** 10,000 steps for naive fine-tuning [S5].
*   **Transfer Functions:** In multi-mode volumes, 5 transfer functions are typically selected to generate separate radiance fields for fine-tuning [S7, unofficial].

**Edge Cases and Pitfalls:**
*   **Overfitting:** In continuous mapping or SLAM, fine-tuning can lead to "forgetting" previous frames if not regularized [S3].
*   **Redundancy:** Initial feed-forward Gaussians may be redundant; fine-tuning must effectively prune them to reduce memory consumption [S2].
*   **Scale Compensation:** When using depth error for densification, depth error must be normalized by rendered depth to compensate for scale variations [S3].

**Pseudocode:**
```python
def fine_tune_gaussians(initial_gaussians, target_images, target_depths, camera_poses, num_iterations=10000, lr=1e-3):
    """
    Fine-tune 3D Gaussian Splatting from an initial set.
    
    Args:
        initial_gaussians: List of Gaussian primitives (mu, s, q, alpha, c)
        target_images: List of target RGB images
        target_depths: List of target depth images
        camera_poses: List of camera pose matrices
        num_iterations: Number of optimization steps
        lr: Learning rate
        
    Returns:
        Refined Gaussian primitives
    """
    # Initialize optimizer with initial parameters
    optimizer = Adam(initial_gaussians.parameters(), lr=lr)
    
    for i in range(num_iterations):
        # Sample a random view or iterate through all views
        view_idx = random.randint(0, len(target_images) - 1)
        target_img = target_images[view_idx]
        target_depth = target_depths[view_idx]
        pose = camera_poses[view_idx]
        
        # Render current Gaussians
        rendered_img, rendered_depth = render_gaussians(initial_gaussians, pose)
        
        # Compute Loss
        # L1 Color Loss
        loss_color = L1(rendered_img, target_img)
        # Depth Loss (normalized)
        depth_error = abs(rendered_depth - target_depth)
        # Normalize by rendered depth to compensate for scale
        normalized_depth_error = depth_error / (rendered_depth + 1e-6)
        loss_depth = L1(normalized_depth_error, zeros_like(normalized_depth_error)) # Target is 0 error
        
        # SSIM Loss (optional but common)
        loss_ssim = 1 - SSIM(rendered_img, target_img)
        
        # Total Loss
        loss = loss_color + 0.5 * loss_depth + 0.2 * loss_ssim
        
        # Backpropagation
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        
        # Optional: Densification/Pruning every N steps
        if i % 100 == 0:
            initial_gaussians = densify_and_prune(initial_gaussians, rendered_img, target_img)
            
    return initial_gaussians

def densify_and_prune(gaussians, rendered_img, target_img):
    """
    Simplified densification and pruning logic.
    """
    # Prune low opacity Gaussians
    gaussians = [g for g in gaussians if g.alpha > 0.005]
    
    # Densify high error regions (simplified)
    error = abs(rendered_img - target_img)
    high_error_pixels = error > threshold
    # Add new Gaussians in high error regions
    new_gaussians = create_gaussians_from_error_map(high_error_pixels)
    gaussians.extend(new_gaussians)
    
    return gaussians
```

## Subtopics

### [Exponentially Ascending Gradient Threshold](9684-exponentially-ascending-gradient-threshold.md)
A densification control mechanism that uses an exponentially ascending gradient threshold to regulate splitting and cloning during training. It solves the trade-off between early-stage convergence speed and late-stage overfitting by allowing aggressive densification when few Gaussians exist and restricting it as the scene becomes dense. It sets itself apart from static threshold methods by dynamically adjusting the sensitivity of densification decisions based on the normalized training progress.

### [SplatFormer Training Objective & Refinement](11745-splatformer-training-objective-refinement.md)
SplatFormer is a learning-based, feed-forward 3D neural module that refines initial 3D Gaussian Splatting (3DGS) representations to enable robust novel view synthesis from out-of-distribution (OOD) camera angles. It addresses the bias of standard 3DGS optimization, which overfits to input views and fails to generalize to unseen high-elevation perspectives, by applying a point transformer network that predicts attribute residuals. Unlike 2D image restoration methods that suffer from multi-view inconsistencies, SplatFormer operates directly on 3D primitives, ensuring geometric consistency while recovering details lost in OOD views.

### [MCMC-based 3DGS / SGLD for 3DGS](11917-mcmc-based-3dgs-sgld-for-3dgs.md)
This method reformulates 3D Gaussian Splatting (3DGS) by treating the set of 3D Gaussians as random samples drawn from an underlying probability distribution describing the scene, specifically as Markov Chain Monte Carlo (MCMC) samples. It converts conventional 3DGS updates into Stochastic Gradient Langevin Dynamics (SGLD) updates by introducing a noise term to promote sample exploration, thereby removing the need for manual densification heuristics like cloning, splitting, and opacity resetting. Unlike sibling methods that rely on complex gradient thresholds or hard constraints, this approach relies on probabilistic state transitions and regularization to manage Gaussian population.

### [Deblurring 3D Gaussian Splatting](12318-deblurring-3d-gaussian-splatting.md)
Deblurring 3D Gaussian Splatting is a real-time deblurring framework that reconstructs sharp 3D scenes from blurry input images by manipulating the covariance matrices and means of 3D Gaussians using a small Multi-Layer Perceptron (MLP) during training. Unlike volumetric rendering-based methods like Deblur-NeRF which require seconds per image, this method uses differentiable rasterization to achieve real-time inference speeds (>800 FPS) while handling both defocus and camera motion blur. It addresses the sparse point clouds caused by blurry inputs through K-nearest-neighbor interpolation and depth-based pruning.

### [Supplementary Point Addition for Sparse Point Clouds](12323-supplementary-point-addition-for-sparse-point-clouds.md)
Supplementary Point Addition is a densification technique designed to compensate for the sparsity of 3D Gaussians at the far end of scenes with large depth of field, where Structure-from-Motion (SfM) extraction is poor due to defocus blur. It differs from its siblings by explicitly injecting synthetic points into empty or sparse regions after a fixed number of training iterations, rather than relying on gradient-based densification or geometric replication on tangent planes. This method ensures that distant objects are represented by initial Gaussians, preventing them from being ignored during the adaptive density control phase.

### [Augmented Radiance Field](13218-augmented-radiance-field.md)
Augmented Radiance Field is a post-enhancement framework that improves 3D Gaussian Splatting (3DGS) scenes by adding Gaussian kernels with view-dependent opacity to explicitly model specular components. It solves the problem that standard spherical harmonics (SH) cannot decouple diffuse and specular radiance, leading to poor reconstruction of sharp highlights and material artifacts. Unlike standard 3DGS which assigns SH coefficients to every primitive, this method uses distinct primitives for diffuse and specular components, avoiding the memory and stability issues of high-order SH.

### [Frequency Regularization for Densification](13484-frequency-regularization-for-densification.md)
Frequency Regularization for Densification (FreGS) addresses the over-reconstruction issue in 3D Gaussian Splatting, where high-variance image regions are covered by a few large Gaussians, leading to blur and artifacts. Unlike standard 3D-GS which relies solely on pixel-wise L1 loss in the spatial domain, FreGS minimizes the discrepancy between the frequency spectrum of the rendered image and the ground truth in the Fourier space. This approach significantly increases pixel gradients within over-reconstruction regions, enabling a coarse-to-fine densification process guided by progressive frequency annealing.

### [Error-Guided Redistribution](14037-error-guided-redistribution.md)
Error-Guided Redistribution is a family of training optimization strategies for 3D Gaussian Splatting (3DGS) that addresses reconstruction artifacts and detail loss by dynamically adjusting the spatial distribution of Gaussian primitives based on rendering errors or gradient magnitudes. Unlike standard densification which adds primitives globally or based on simple gradient thresholds, these methods specifically target regions with persistent coarse-scale errors or "hard" gradients, either by reallocating a fixed budget of Gaussians, growing defective primitives, or controlling density via online sparse statistics.

### CoherentGS
CoherentGS is a regularized optimization method for sparse novel view synthesis (NVS) that introduces structural coherency to explicit 3D Gaussian representations by constraining Gaussian movement in 2D image space [S1]. It solves the instability and "needle-like" artifacts common in standard 3D Gaussian Splatting (3DGS) when trained on extremely sparse input views (e.g., 3–4 images) by enforcing single-view and multi-view consistency, thereby preventing overfitting and allowing for the identification of occluded regions suitable for inpainting [S1]. Unlike NeRF-based sparse methods that rely on implicit MLPs and produce blurry occluded regions, CoherentGS maintains an explicit representation that can be cleanly segmented for diffusion-based inpainting [S1].

### [Pruning and Sparsity Control](14431-pruning-and-sparsity-control.md)
Pruning and Sparsity Control methods reduce the number of active 3D Gaussians in a radiance field to lower memory consumption and storage requirements while maintaining rendering quality. Unlike standard 3DGS which relies on opacity thresholds and stops densifying mid-training, these methods actively eliminate redundant primitives throughout the optimization process [12710-gaussian-volume-mask.md]. They are distinguished from sibling methods like [Exponentially Ascending Gradient Threshold](9684-exponentially-ascending-gradient-threshold.md) by using explicit geometric or volume-based criteria rather than gradient magnitude alone [14019-visibility-based-pruning-for-3d-gaussian-splatting.md].

### [Rendering-Free Pruning via Hessian Importance](14447-rendering-free-pruning-via-hessian-importance.md)
Rendering-Free Pruning via Hessian Importance (REFINE) is a post-processing framework for 3D Gaussian Splatting (3DGS) that identifies and removes unimportant Gaussian primitives without performing forward rendering passes. It quantifies primitive importance using an analytically approximated Hessian field, which estimates the image-space quality degradation caused by removing a primitive based on parameter-space gradients. Unlike rendering-based methods such as PUP [14431-pruning-and-sparsity-control.md] or LightGaussian, REFINE bypasses rasterization entirely, relying on closed-form algebraic operations to achieve a 3,000× reduction in computational complexity and a ~20× speedup in device latency.

### [GoF-based Dynamic 3DGS Video Construction](14770-gof-based-dynamic-3dgs-video-construction.md)
This method constructs dynamic 3D Gaussian Splatting (3DGS) video by temporally segmenting input sequences into Groups of Frames (GoFs) and independently training Gaussian deformation fields within each segment. It solves the problem of motion drift and geometric inconsistencies that occur when modeling long-range temporal dependencies with a single global deformation field. By limiting the motion degree within short segments, it prevents the deformation field from struggling to adapt to complex, long-sequence dynamics. It sets itself apart from global optimization approaches by decoupling static and dynamic components via weighted MLP parameters and separating foreground/background content to reduce training complexity.

### [Two-stage Optimization](14857-two-stage-optimization.md)
Two-stage optimization is a training protocol for inverse rendering with 3D Gaussians that decouples geometric and appearance optimization from material and lighting decomposition. It solves the problem of jointly recovering geometry, material properties (albedo, roughness), and lighting from static multi-view images by preventing the entanglement of these distinct physical properties during early training. It sets itself apart from vanilla 3DGS by introducing normal gradient-based densification and PBR-specific loss terms, while differing from neural relightable methods by maintaining a discrete point-based representation.

### [TIP-Editor](14859-tip-editor.md)
TIP-Editor is a method for editing existing 3D Gaussian Splatting (3DGS) scenes using intuitive text and image prompts. It solves the problem of achieving accurate local editing while maintaining multi-view consistency, which is often compromised in text-guided 3D editing. It distinguishes itself from sibling methods like [GaussCtrl](14877-gaussctrl.md) by employing a stepwise 2D personalization strategy with LoRA-based reference image alignment and localization loss, rather than relying on depth-conditioned ControlNet for geometric consistency.

### StylizedGS
StylizedGS is a controllable 3D stylization method for 3D Gaussian Splatting (3DGS) models that performs color matching with a reference style image while utilizing a 3DGS filter to remove artifacts [S1]. It distinguishes itself from other stylization approaches by explicitly optimizing for nearest neighbor feature matching and depth preservation, ensuring the stylized output retains the geometric structure of the original scene while adopting the artistic appearance of the style image [S1].

### [SGD (Street View Synthesis with Gaussian Splatting and Diffusion Prior)](15522-sgd-street-view-synthesis-with-gaussian-splatting-and-diffus.md)
SGD is a novel view synthesis method for street scenes that enhances 3D Gaussian Splatting (3DGS) by fine-tuning a Stable Diffusion model on driving data and using it to regularize 3DGS training at unseen viewpoints, addressing the sparse-view reconstruction problem. It differs from prior sparse-view NVS methods that rely on object-centric multi-view datasets and relative camera poses; instead, it uses adjacent frames and LiDAR depth for direct fine-tuning on driving data, overcoming the domain gap.

### [Equivalent Distribution Reorganization](16968-equivalent-distribution-reorganization.md)
Equivalent Distribution Reorganization (ReorgGS) is a post-training reorganization method for converged 3D Gaussian Splatting (3DGS) models that addresses "parameterization degeneration," a failure mode where high-opacity floaters attenuate gradients to true surfaces and redundant overlapping clusters create strongly coupled parameter blocks. Unlike standard opacity reset, which only rescales opacity on the old overlap graph, ReorgGS rebuilds centers, covariances, and the visibility structure by resampling from the empirical distribution, thereby changing the graph itself. It preserves the original scene support asymptotically while reducing parameter coupling and opacity barriers, delivering up to 0.5 dB higher training PSNR and a 12.8% rendering speedup in representative settings.

### [S2Gaussian](17154-s2gaussian.md)
S2Gaussian is a two-stage framework for reconstructing high-quality 3D scenes from sparse and low-resolution input views, addressing the joint challenge of deficient perspectives and clarity. Unlike methods that treat sparsity and low resolution as isolated problems, S2Gaussian handles this hybrid scenario by initializing high-resolution Gaussians from a densified low-resolution representation and refining them using super-resolved supervision. It sets itself apart from its parent [Fine-tuning](9138-fine-tuning.md) by introducing a specific "Gaussian Shuffle Split" densification strategy and a "Blur-Free Inconsistency Modeling" scheme to mitigate multi-view artifacts.

### [On-the-Fly GS Progressive Training](17502-on-the-fly-gs-progressive-training.md)
On-the-Fly GS Progressive Training is a method for optimizing 3D Gaussian Splatting (3DGS) fields in a continuous, incremental manner as new images are acquired, enabling near real-time reconstruction without retraining from scratch. It solves the problem of catastrophic forgetting and overfitting in sequential SLAM-based 3DGS by structuring training into three phases: initial sparse training, progressive fly-in updates with hierarchical weighting, and final global optimization. It distinguishes itself from standard 3DGS by dynamically allocating training iterations and learning rates based on image overlap hierarchies and introducing a load-balancing loss to prevent Gaussian accumulation hotspots, while utilizing splatting-based parallelism for gradient accumulation to accelerate convergence.

### [FreeFix](17532-freefix.md)
FreeFix is a fine-tuning-free method to improve the rendering quality of extrapolated views in 3D Gaussian Splatting (3DGS) by leveraging pretrained 2D image diffusion models (IDMs). It solves the problem of artifacts in rendered RGBs and inconsistency across frames that arise when using Video Diffusion Models (VDMs) or naive 2D IDMs, avoiding the computational burden of temporal attention and the loss of per-pixel guidance due to 3D VAE down-sampling. It sets itself apart from siblings like [ViewExtrapolator](11917-mcmc-based-3dgs-sgld-for-3dgs.md) or [Difix3D+](11917-mcmc-based-3dgs-sgld-for-3dgs.md) by using a 2D–3D interleaved refinement strategy with per-pixel confidence masks derived from Fisher information, rather than relying on rendered opacity or warp masks which fail to identify artifact regions.

### Gaussian Densification via Rendering Loss
A strategy to add new 3D Gaussians to the map by identifying unobserved regions (holes) and regions with high rendering error, using opacity, color, and depth thresholds [S3]. It identifies holes where rendered opacity $O(x,y) < \tau_{opa}$ and high error regions where $E_{color}(x,y) > \tau_{color}$ or $E_{depth}(x,y)/D(x,y) > \tau_{depth}$ [S3]. For depth images, corresponding depths are projected directly [S3].

### Point Densification
A process in original 3DGS that adaptively controls the number of Gaussian points through clone and split operations to convert a sparse set into a denser one [S4]. In HO-Gaussian, point densification is performed at regular intervals to provide new positions to the Gaussian pipeline, populating problematic regions [S4].

### Naive Fine-tuning
Naive generator fine-tuning method identical to model rewriting except freely optimizing all weights of the generator [S5]. It optimizes over 10,000 steps with a learning rate of $10^{-3}$ [S5].

### Backbone Fine-tuning
Optimizing the weights of the pre-trained 3D generator (backbone) alongside the decoder to adapt tri-plane features for Gaussian Splatting attributes, which have scale and rotation influencing adjacent regions unlike NeRF's local color/density [S6]. It creates a copy of the pre-trained 3D generator and optimizes its weights during the training process [S6].

### Image-space Gaussian Fine-tuning
A fine-tuning process to account for different visual modes in the volume by generating multiple radiance fields using different transfer functions and optimizing the Gaussian set against rendered images [S7, unofficial]. It selects a series of transfer functions $\{TF_h\}$, generates radiance fields $RF_h = TF_h(F)$, renders 64 images for supervision, and backpropagates to update the Gaussian set $G_h$ [S7, unofficial]. In practice, 5 transfer functions are selected for each volume [S7, unofficial].

## Operating characteristics
*   **Time Complexity:** Fine-tuning typically requires thousands of iterations (e.g., 10,000 steps) [S5]. The cost per iteration is dominated by differentiable rasterization, which is $O(N)$ where $N$ is the number of Gaussians, but with a small constant due to spatial coherence [S2].
*   **Memory Complexity:** Memory usage scales with the number of Gaussians. Fine-tuning with densification can increase the number of Gaussians significantly, while pruning can reduce it [S2]. Pre-trained models may require additional memory for the backbone network [S6].
*   **Measured Performance:** Fine-tuning can achieve photorealism on par with or surpassing other methods, leveraging powerful pretrained weights [S2]. It accelerates network training and enables faster convergence compared to other test-time optimization methods [S2].
*   **Scaling:** Fine-tuning scales well with the number of views and resolution, but densification can lead to quadratic complexity in naive implementations if not managed with spatial hashing or bounding volumes [S3].
*   **Strengths:** Leverages pretrained priors for faster convergence and better generalization [S2]. Allows for adaptive refinement of geometry and appearance [S6].
*   **Limitations:** Can overfit to input views if not regularized [S3]. Requires careful tuning of learning rates and densification thresholds [S5].
*   **When to use:** When starting from a pre-trained model or when initial SfM points are sparse or noisy [S2, S4].
*   **When not to use:** When real-time training is required, or when the scene is very large and memory is constrained [S2].

## Background
Fine-tuning in 3D Gaussian Splatting is derived from transfer learning techniques in deep learning, where lower layers are fixed and higher layers are adapted to a specific task [S1]. In the context of 3DGS, it was introduced to address the limitations of random initialization and sparse SfM points, allowing for more robust and high-fidelity reconstructions [S2, S4]. The method has been extended to various domains, including SLAM [S3], urban scenes [S4], and generative modeling [S6].
