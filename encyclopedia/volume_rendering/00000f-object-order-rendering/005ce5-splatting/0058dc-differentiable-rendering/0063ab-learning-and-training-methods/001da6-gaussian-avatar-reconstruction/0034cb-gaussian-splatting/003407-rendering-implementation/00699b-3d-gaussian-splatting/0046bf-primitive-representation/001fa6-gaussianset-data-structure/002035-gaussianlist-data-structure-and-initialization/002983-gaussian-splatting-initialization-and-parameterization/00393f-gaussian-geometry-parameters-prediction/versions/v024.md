# Gaussian Geometry Parameters Prediction

Also called: EVolSplat, Efficient Volume-based Gaussian Splatting, GRM, Gaussian MLP Heads, Gaussian Representation Model

## Overview
Gaussian Geometry Parameters Prediction is a method for initializing and refining the geometric attributes (position, opacity, and covariance) of 3D Gaussian primitives in a feed-forward manner, typically using a global volumetric representation rather than per-pixel alignment [S2]. It solves the problem of ghosting artifacts and multi-view inconsistencies inherent in existing feed-forward methods that predict per-pixel aligned Gaussians using local cost volumes or epipolar transformers [S2]. By accumulating depth information in 3D space and refining it via a sparse 3D convolutional network, this approach improves global consistency and reduces redundant primitives in overlapping regions [S2].

## How it works
The method predicts Gaussian geometry parameters by initializing a global point cloud from monocular depth estimates, encoding it into a latent feature volume, and decoding geometric attributes via MLP heads.

**Inputs:**
- A set of $N$ sparse input images $\{I_n\}_{n=1}^N$ with known camera poses.
- Calibrated intrinsic matrices $\{K_n\}_{n=1}^N$ and extrinsic matrices $\{T_n = R_n | t_n\}_{n=1}^N$.
- (Optional) Pre-trained metric depth estimators to provide depth maps $\{D_n\}_{n=1}^N$.

**Outputs:**
- A set of 3D Gaussians $\mathcal{G} = \{(\mu_i, \alpha_i, \Sigma_i, c_i)\}_{i=1}^{N_p}$, where $\mu_i$ is the mean position, $\alpha_i$ is the opacity, $\Sigma_i$ is the covariance matrix, and $c_i$ is the view-dependent color.

**Data Structures:**
- **Global Point Cloud ($\mathcal{P}$):** A set of 3D points in world coordinates, $\mathcal{P} \in \mathbb{R}^{N_p \times 3}$.
- **Feature Volume ($\mathcal{F}$):** A sparse 3D tensor $H \times W \times D \times C$ representing the latent neural volume, aligned with the world coordinate system.
- **MLP Heads:** Three independent Multi-Layer Perceptrons:
  - $\mathcal{D}_{pos}$: Predicts position offsets.
  - $\mathcal{D}_{opa}$: Predicts opacity.
  - $\mathcal{D}_{cov}$: Predicts covariance parameters.

**Steps:**

1.  **Depth Estimation and Point Cloud Construction:**
    For each input image $I_n$, predict a metric depth map $D_n$ using an off-the-shelf depth estimator. Unproject the RGB images into 3D space using the intrinsic and extrinsic matrices to construct the global scene point cloud $\mathcal{P}$:
    $$ \mathcal{P} = \bigcup_{n=1}^N \pi^{-1}(I_n, D_n, T_n, K_n) $$
    where $\pi^{-1}$ denotes pixel unprojection [S2].

2.  **Filtering:**
    Apply a uniform filter to $\mathcal{P}$ to delete duplicate primitives while preserving scene structure. Apply a statistical filter to remove floating artifacts (floaters) from the processed primitives [S2].

3.  **Feature Volume Extraction:**
    Construct a sparse tensor from the filtered points $\mathcal{P}$ and feed it into a sparse 3D CNN (e.g., sparse U-Net) to extract the feature volume $\mathcal{F}$ [S2].

4.  **Initialization:**
    Initialize the Gaussian centers $\mu^{init}_i$ using the scene point cloud $\mathcal{P}$, such that $\mu^{init}_i = p_i \in \mathcal{P}$ for each point $p_i$ [S2].

5.  **Geometry Parameters Prediction (Training):**
    For each initialized Gaussian $i$:
    a. Query the feature volume $\mathcal{F}$ at the current estimated position $\mu^{init}_i + \Delta \mu^{prev}_i$ using trilinear interpolation to obtain the feature vector $\mathbf{f}_i$:
    $$ \mathbf{f}_i = \mathcal{F}(\mu^{init}_i + \Delta \mu^{prev}_i) $$
    b. Decode opacity $\alpha_i$ and covariance $\Sigma_i$ using the MLP heads:
    $$ \alpha_i = \mathcal{D}_{opa}(\mathbf{f}_i), \quad \Sigma_i = \mathcal{D}_{cov}(\mathbf{f}_i) $$
    c. Decode the position offset $\Delta \mu_i$ using the position MLP head, applying a Tanh activation and scaling by the voxel size $v_{size}$:
    $$ \Delta \mu_i = \text{Tanh}(\mathcal{D}_{pos}(\mathbf{f}_i)) \cdot v_{size} $$
    d. Update the Gaussian mean:
    $$ \mu_i = \mu^{init}_i + \Delta \mu_i $$
    e. Track $\Delta \mu_i$ from the current iteration as $\Delta \mu^{prev}_i$ for the next iteration [S2].

6.  **Inference:**
    Initialize $\Delta \mu^{prev}_i = 0$. Recursively execute the update rules (querying $\mathbf{f}_i$, predicting $\Delta \mu_i$, and updating $\mu_i$) twice to obtain a converged $\Delta \mu_i$. Use the converged point to query $\alpha_i$ and $\Sigma_i$ [S2].

7.  **Color Prediction (Optional Context):**
    Project the 3D Gaussians to the nearest $K$ reference views to retrieve 2D context (color windows $\{c_k\}$ and visibility maps). Decode the Gaussian color $c_i$ using this 2D context [S2].

**Parameters:**
- $N$: Number of input images [S2].
- $N_p$: Number of points in the global point cloud [S2].
- $K$: Number of nearest reference views for color retrieval [S2].
- $v_{size}$: Voxel size used to scale the position offset output [S2].

**Edge Cases and Pitfalls:**
- **Ghosting Artifacts:** Pixel-aligned methods generate redundant and inconsistent primitives in overlapping regions. This method addresses this by using a global volume and filtering duplicates [S2].
- **Depth Noise:** Monocular depth predictions contain noise and floating artifacts. Statistical filtering is required to remove floaters after uniform filtering [S2].
- **Convergence:** The recursive formulation of $\Delta \mu_i$ relies on convergence. Empirically, two iterations are sufficient during inference [S2].

## Subtopics

### BrightDreamer
BrightDreamer predicts the deviation of a set of fixed anchor points to determine the centers of Gaussians, rather than predicting point clouds directly from images [S1].

### Defocus Blur Modeling
This variant models optical defocus by adjusting the scale $s$ of 3D Gaussians based on their distance from the camera's focal plane. During training, larger scale values $\bar{s}_j$ are used to rasterize blurred images, while smaller scale values $s_j$ are used during testing to render sharp details. Unlike naive Gaussian kernels that blur the entire image uniformly, this method selectively enlarges covariances only for Gaussians corresponding to blurred regions [S3].

### GaMeS Parametrization
GaMeS parametrizes Gaussian components into flat triangle-face meshes, allowing GS to be visualized and manipulated as a triangle soup [S4, unofficial].
- **Forward Mapping:** Given a Gaussian $N(m, R, S)$ with $R=[r_1, r_2, r_3]$ and $S=\text{diag}(\epsilon, s_2, s_3)$, the triangle vertices are $v_1 = m$, $v_2 = m + s_2 r_2$, and $v_3 = m + s_3 r_3$.
- **Inverse Mapping:** Given a triangle $V=[v_1, v_2, v_3]$, the Gaussian is recovered as $N(\hat{m}, \hat{R}, \hat{S})$ using:
  $$ \hat{m} = v_1 $$
  $$ \hat{r}_1 = \frac{(v_2 - v_1) \times (v_3 - v_1)}{\|(v_2 - v_1) \times (v_3 - v_1)\|} $$
  $$ \hat{r}_2 = \frac{v_2 - v_1}{\|v_2 - v_1\|} $$
  $$ \hat{r}_3 = \text{orth}(v_3 - v_1; \hat{r}_1, \hat{r}_2) $$
  $$ \hat{s}_1 = \epsilon, \quad \hat{s}_2 = \|v_2 - v_1\|, \quad \hat{s}_3 = \langle v_3 - v_1, \hat{r}_3 \rangle $$
  The covariance matrix is recovered as $\hat{\Sigma} = \hat{R}\hat{S}\hat{S}^T\hat{R}^T$ [S4, unofficial].
- **Mesh Embedding:** For mesh-bound Gaussians, means are assigned to mesh faces via learnable barycentric coordinates, ensuring they remain bound under deformation. Orientation is defined by the face normal and two in-plane directions derived from the vertices [S4, unofficial].

## Operating characteristics
- **Time Complexity:** Feed-forward prediction allows for real-time rendering without iterative per-scene optimization, significantly faster than standard 3DGS optimization [S2].
- **Memory Complexity:** Uses a global volumetric representation ($\mathcal{F}$) which may require more memory than local cost volumes but reduces redundancy compared to per-pixel methods [S2].
- **Strengths:** Improves global consistency, reduces ghosting artifacts in overlapping regions, and handles foreground/background separation effectively (e.g., via hemisphere models for sky) [S2].
- **Limitations:** Relies on the quality of off-the-shelf depth estimators; noisy depth can lead to inaccurate initializations if filtering is insufficient [S2].
- **When to use:** Urban scene reconstruction, autonomous driving applications, and scenarios requiring fast, feed-forward novel view synthesis with sparse input views [S2].
- **When not to use:** Small-scale scenes with high overlap where local methods might be more efficient, or when high-fidelity per-pixel alignment is critical without global refinement [S2].

## Background
The method originates from EVolSplat (Efficient Volume-based Gaussian Splatting for Urban View Synthesis), introduced by Sheng Miao et al. in 2025 [S2]. It addresses the limitations of existing feed-forward 3DGS methods like MVSplat, Flash3D, and DrivingForward, which predict per-pixel aligned Gaussians using local cost volumes or epipolar transformers. These methods often suffer from multi-view inconsistencies and duplicated content when accumulating Gaussians from multiple local volumes in global coordinates [S2]. EVolSplat predicts 3D Gaussians across multiple frames within a unified volume using a 3D convolutional network, handling foreground and background separately [S2]. The concept of predicting Gaussian parameters via MLP heads from a feature volume is also related to GRM (Gaussian Representation Model) and other feed-forward generation models [S1].
