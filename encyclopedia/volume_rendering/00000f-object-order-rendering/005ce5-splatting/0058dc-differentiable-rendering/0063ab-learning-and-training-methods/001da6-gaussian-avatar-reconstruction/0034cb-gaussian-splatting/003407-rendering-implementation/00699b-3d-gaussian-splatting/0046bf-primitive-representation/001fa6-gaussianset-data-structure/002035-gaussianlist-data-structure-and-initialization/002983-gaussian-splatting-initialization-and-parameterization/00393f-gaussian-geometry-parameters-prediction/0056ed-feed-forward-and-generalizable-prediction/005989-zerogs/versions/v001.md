# ZeroGS

Also called: ZeroGS: Training 3D Gaussian Splatting from Unposed Images

## Overview
ZeroGS is a pipeline for training 3D Gaussian Splatting (3DGS) from hundreds of unposed and unordered images without requiring Structure-from-Motion (SfM) tools like COLMAP [S1, unofficial]. It differs from its siblings by using a pretrained foundation model (Spann3R) to predict dense 3D Gaussians and pointmaps directly from image pairs, followed by an incremental registration process that refines camera poses via a point-to-camera ray consistency loss and optimizes the scene using a rendering loss rather than reprojection error [S1, unofficial].

## How it works
**Inputs:** A set of $N$ unposed and unordered RGB images $\{I_i\}_{i=1}^N$.
**Outputs:** A set of 3D Gaussians $\mathcal{G}$ and refined camera poses $\{P_i\}_{i=1}^N$.

**Data Structures:**
*   **Training Buffer:** A collection of registered images and their associated poses and 3D Gaussians.
*   **Spatial Feature Memory:** Used by the Spann3R backbone to store fused features for global coordinate regression [S1, unofficial].
*   **3D Gaussians ($G_k$):** Predicted primitives with parameters $\Theta = \{\mu, \sigma, r, s, c, \alpha\}$ [S1, unofficial].
*   **Pointmaps ($X_k$):** Dense depth maps where each pixel contains the 3D coordinate of the corresponding point in the reference camera's frame [S1, unofficial].

**Parameters:**
*   **Batch Size:** Image pairs are processed in batches.
*   **GPU Memory:** Designed to run on 24GB consumer-level GPUs for hundreds of images [S1, unofficial].
*   **Seed Image:** One initial image is selected to fix the global coordinate frame [S1, unofficial].

**Steps:**

1.  **Initialization:** Initialize the pipeline with a pretrained Spann3R model and a single seed image $I_{seed}$ [S1, unofficial]. Add $I_{seed}$ to the training buffer with its pose fixed as the global origin.

2.  **Feature Extraction and Prediction:** For a batch of image pairs $(I_i, I_j)$, where at least one image is in the training buffer:
    *   Encode images using a Vision Transformer (ViT) shared encoder $V$:
        $$f_{ie}, f_{je} = V(I_i, I_j)$$
    *   Decode features using reference and target transformer decoders $D_{ref}$ and $D_{tgt}$:
        $$f_{id} = D_{ref}(f_{ie}, f_{je}), \quad f_{jd} = D_{tgt}(f_{je}, f_{ie})$$
    *   Project decoder features to pointmaps using projection heads $H_{ref}$ and $H_{tgt}$:
        $$X_{i,i}, X_{j,i} = H_{ref}(f_{id}), H_{tgt}(f_{jd})$$
        Here, $X_{i,j}$ is the pointmap of image $j$ in camera $i$'s coordinate frame [S1, unofficial].
    *   Predict 3D Gaussians $G_k$ alongside the pointmaps using the Spann3R architecture [S1, unofficial].

3.  **Coarse Pose Estimation:**
    *   Extract 2D-3D correspondences from the predicted pointmaps.
    *   Compute coarse camera poses using RANSAC and a Perspective-n-Point (PnP) solver [S1, unofficial].

4.  **Pose Refinement:**
    *   Refine the coarse camera poses by minimizing a point-to-camera ray consistency loss. This loss minimizes the distance between the predicted 3D points and the camera centers across multiple views [S1, unofficial].

5.  **Rendering and Loss Computation:**
    *   Rasterize the 3D Gaussians using the refined camera poses to render images.
    *   Compute an RGB reconstruction loss (e.g., L1 or LPIPS) between rendered and ground truth images [S1, unofficial].

6.  **Back-Propagation and Update:**
    *   Back-propagate gradients through the differentiable rasterization and the network to update the model parameters [S1, unofficial].
    *   At the end of each training epoch, update the training buffer by registering new images. This involves:
        *   Finding unregistered images that have sufficient overlap with registered images.
        *   Using RANSAC and PnP to register them.
        *   Adding them to the buffer [S1, unofficial].

7.  **Iteration:**
    *   Repeat steps 2-6 until all images are registered or no more images can be registered [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Memory Limits:** Aligning dense pointmaps to a global frame for >2 images (as done in DUSt3R post-processing) is time-consuming and can exceed GPU memory limits [S1, unofficial]. ZeroGS avoids this by regressing points in the global coordinate frame of a seed image without aligning dense pointmaps globally [S1, unofficial].
*   **Textureless Areas:** 3DGS may struggle to identify Gaussians in textureless areas. The use of dense pointmaps and rendering loss helps mitigate this compared to sparse SfM [S1, unofficial].
*   **Gauge Freedom:** Unlike incremental SfM which fixes poses of an image pair, ZeroGS fixes the pose of a single seed image [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Depends on the number of images and the convergence of the incremental registration. The use of transformers for feature extraction is computationally intensive but allows for parallel processing of image pairs [S1, unofficial].
*   **Memory Complexity:** Optimized to run on 24GB consumer GPUs for hundreds of images by avoiding global alignment of dense pointmaps [S1, unofficial].
*   **Strengths:** Handles unposed and unordered images; does not require COLMAP; renders higher quality images than 3DGS with COLMAP poses on standard datasets [S1, unofficial].
*   **Limitations:** Relies on the accuracy of the pretrained foundation model (Spann3R/DUSt3R); performance may degrade in scenes with significant textureless regions or dynamic content [S1, unofficial].

## Background
ZeroGS was proposed by researchers from Alibaba Group (indicated by the project page `aibluefisher.github.io/ZeroGS`) and published on arXiv in November 2024 [S1, unofficial]. It builds on the principles of differentiable volume rendering and 3D Gaussian Splatting, addressing the limitation of previous methods that required accurate pose priors or could only handle simple scenes [S1, unofficial]. It differs from ACE0 by predicting dense pointmaps and 3D Gaussians using transformers instead of sparse points and CNNs [S1, unofficial]. It differs from InstantSplat and Splatt3R by regressing points in the global coordinate frame of a seed image without aligning dense pointmaps, followed by incremental registration [S1, unofficial].
