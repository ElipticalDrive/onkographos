# RLSplat

Also called: Resource-Linear Budget Control for Feed-forward 3D Gaussian Splatting

## Overview
RLSplat is a resource-linear, budget-controllable feed-forward 3D Gaussian Splatting (FF3DGS) framework that generates exactly $B$ Gaussians for a given target budget, ensuring that inference latency and peak memory scale linearly with $B$ [S1, unofficial]. Unlike prior budget-controllable methods (e.g., EcoSplat, F4 Splat) that predict a dense set of candidates and prune them—resulting in nearly constant inference cost regardless of the budget—RLSplat uses a learned allocation policy to distribute $B$ Gaussians across local scene regions and a resource-linear decoder that refines them via local cross-attention [S1, unofficial]. This approach allows the representation size, latency, and memory to decrease linearly as the Gaussian budget is reduced, making it suitable for applications with strict resource constraints such as AR/VR and robotics [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of $V$ uncalibrated context images $\{I_i\}_{i=1}^V$ and a target Gaussian budget $B \in \mathbb{Z}_{\ge 0}$ [S1, unofficial].
*   **Outputs:** A set of $B$ 3D Gaussians $\mathcal{G} = \{g_b\}_{b=1}^B$ and the camera parameters $\{P_i\}_{i=1}^V$ for the context images [S1, unofficial]. Each Gaussian $g_b$ consists of a 3D center, opacity, scale, rotation, and color coefficients [S1, unofficial].

**Data Structures:**
1.  **Anchor Tokens:** The geometry backbone encodes the input images into $N$ anchor tokens $\{a_n\}_{n=1}^N$. Each anchor represents a local 3D region of the scene [S1, unofficial].
2.  **Allocation Vector:** A discrete allocation vector $\mathbf{k} \in \mathbb{Z}_{\ge 0}^N$ where $k_n$ is the number of Gaussians assigned to anchor $n$, such that $\sum_{n=1}^N k_n = B$ [S1, unofficial].
3.  **Gaussian Tokens:** Each anchor $n$ spawns $k_n$ Gaussian tokens. The total number of Gaussian tokens is exactly $B$ [S1, unofficial].
4.  **Hierarchical Neighbor Search:** Used to find the $K_{gs}$ nearest Gaussian neighbors for each token efficiently [S1, unofficial].

**Algorithm Steps:**

1.  **Geometry Encoding:**
    The geometry backbone (e.g., a Vision Transformer-based encoder) processes the $V$ input images $\{I_i\}$ to extract multi-scale features and predict camera parameters $\{P_i\}$ [S1, unofficial]. The images are encoded into $N$ anchor tokens $\{a_n\}_{n=1}^N$ [S1, unofficial].

2.  **Gaussian Allocation:**
    A Gaussian allocation policy $\pi_\psi$ assesses the local significance of each anchor (based on image features such as texture complexity) and predicts a discrete allocation $\mathbf{k} = [k_1, \dots, k_N]$ [S1, unofficial].
    *   The policy is trained using Group Sequence Policy Optimization (GSPO) [S1, unofficial].
    *   During training, $C$ rollouts (candidate allocations) are drawn from the policy: $\mathbf{k}^{(c)} \sim \text{Mult}(B, \text{sg}(\mathbf{p}))$, where $\mathbf{p}$ are the predicted probabilities and $\text{sg}(\cdot)$ stops gradients [S1, unofficial].
    *   The constraint $\sum_{n=1}^N k_n = B$ is strictly enforced [S1, unofficial].

3.  **Token Spawning:**
    For each anchor $n$, $k_n$ Gaussian tokens are spawned. These tokens serve as the initial representation for the Gaussians associated with that anchor [S1, unofficial].

4.  **Resource-Linear Decoding and Refinement:**
    The $B$ Gaussian tokens are decoded into the final set of $B$ Gaussians $\mathcal{G}$ [S1, unofficial].
    *   **Initialization:** Each token predicts an initial state (center, scale, rotation, opacity, color) for its associated Gaussian [S1, unofficial].
    *   **Local Refinement:** To ensure consistency and accuracy, each Gaussian token attends only to its $K_{gs}$ nearest Gaussian neighbors [S1, unofficial].
    *   **Neighbor Search:** The $K_{gs}$ neighbors are found using a hierarchical neighbor search. This search operates over the anchor tokens first (using $K_{anc}$ anchor neighbors) and then refines the search among the Gaussian tokens [S1, unofficial].
    *   **Cross-Attention:** A local cross-attention mechanism refines the Gaussian parameters based on the information from its neighbors [S1, unofficial].
    *   **Losses:** The refinement process is guided by losses including a projection loss (tying anchors to image regions), an offset loss, and a Voronoi loss (regularizing the spatial distribution) [S1, unofficial]. Removing the projection loss causes training to fail [S1, unofficial].

**Pseudocode:**

```python
def RLSplat(context_images: List[Image], budget: int) -> Tuple[List[Gaussian], List[Camera]]:
    """
    RLSplat: Resource-Linear Budget Control for Feed-forward 3D Gaussian Splatting.
    
    Args:
        context_images: List of V uncalibrated context images.
        budget: Target number of Gaussians B.
        
    Returns:
        Gaussians: List of B 3D Gaussians.
        Cameras: List of V camera parameters.
    """
    # 1. Geometry Encoding
    # Encode images into N anchor tokens and predict camera parameters
    # Backbone: e.g., DINOv2 or similar Vision Transformer
    anchor_tokens, cameras = geometry_backbone(context_images)
    N = len(anchor_tokens)
    
    # 2. Gaussian Allocation
    # Predict allocation vector k such that sum(k) == budget
    # Policy: pi_psi, trained with GSPO
    # Inference: Sample from policy or use argmax/straight-through estimator
    allocation_probs = gaussian_allocation_policy(anchor_tokens)
    # Sample discrete allocation k from multinomial distribution with straight-through gradient
    # k ~ Mult(budget, sg(allocation_probs))
    # Note: In inference, this is typically a single sample or deterministic selection
    # ensuring sum(k) == budget.
    k = sample_allocation(allocation_probs, budget)
    
    # 3. Token Spawning
    # Spawn k_n Gaussian tokens for each anchor n
    gaussian_tokens = []
    for n in range(N):
        for _ in range(k[n]):
            # Each token inherits features from anchor n
            token = create_gaussian_token(anchor_tokens[n])
            gaussian_tokens.append(token)
            
    # Total number of tokens is exactly budget
    assert len(gaussian_tokens) == budget
    
    # 4. Resource-Linear Decoding
    # Initialize Gaussian parameters from tokens
    gaussians = initialize_gaussians(gaussian_tokens)
    
    # Hierarchical Neighbor Search
    # Find Kgs nearest Gaussian neighbors for each token
    # First find Kanc anchor neighbors, then refine within those anchors
    Kanc = 16  # Fixed ablation value
    Kgs = 16   # Variable parameter, default ablation value
    
    # Build hierarchical structure for efficient neighbor search
    # This step is O(B * Kgs) instead of O(B^2)
    neighbor_indices = hierarchical_neighbor_search(gaussians, Kanc, Kgs)
    
    # Local Cross-Attention Refinement
    # Each Gaussian attends to its Kgs neighbors
    refined_gaussians = local_cross_attention(gaussians, neighbor_indices)
    
    return refined_gaussians, cameras

def sample_allocation(probs: List[float], budget: int) -> List[int]:
    """
    Sample a discrete allocation vector k from probabilities such that sum(k) == budget.
    Uses multinomial sampling with straight-through estimator during training.
    For inference, this may use a deterministic or stochastic method.
    """
    # Implementation detail: Use multinomial distribution
    # k ~ Mult(budget, probs)
    # This ensures sum(k) == budget by definition of the multinomial distribution
    k = np.random.multinomial(budget, probs)
    return k.tolist()
```

**Parameters:**
*   $B$: Target Gaussian budget. Typical values: 2K (2,048), 8K (8,192), 64K [S1, unofficial].
*   $K_{gs}$: Number of nearest Gaussian neighbors for local cross-attention. Default ablation value: 16. Can be changed at inference without retraining [S1, unofficial].
*   $K_{anc}$: Number of anchor neighbors in hierarchical search. Fixed value in ablations: 16 [S1, unofficial].
*   $C$: Number of rollouts (candidate allocations) per training step for GSPO [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Training Failure:** Removing the projection loss causes training to fail entirely, as it ties the anchor's Gaussians to the image region [S1, unofficial].
*   **Neighbor Search Accuracy:** Removing the Voronoi loss causes a significant drop in performance (2.51 dB) because Gaussians leave their anchor's cell, and the hierarchical search no longer retrieves their true neighbors [S1, unofficial].
*   **Budget Scaling:** The method's efficiency relies on $K_{gs}$ being small relative to $B$. If $K_{gs}$ is too large, the linear scaling advantage diminishes [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The decoding cost is $O(B \cdot K_{gs})$, scaling linearly with the Gaussian budget $B$. This contrasts with global self-attention which costs $O(B^2)$ [S1, unofficial].
*   **Memory Complexity:** Peak memory scales linearly with $B$ [S1, unofficial].
*   **Performance:**
    *   At a budget of 2K Gaussians, RLSplat achieves higher PSNR than F4 Splat while using 9.6× less peak memory and running 4.1× faster [S1, unofficial].
    *   On the ACID dataset (8 views, $B=8,192$), RLSplat achieves PSNR 22.84 dB, SSIM 0.643, LPIPS 0.353 [S1, unofficial].
    *   On the RE10K dataset ($B=8,192$), RLSplat achieves full-view PSNR 26.51 dB, compared to 23.42 dB for F4 Splat and 21.82 dB for EcoSplat [S1, unofficial].
*   **Strengths:**
    *   Linear scaling of inference cost and memory with budget.
    *   Better allocation of Gaussians to high-frequency structures (e.g., thin stair balusters) compared to uniform or pruning-based methods [S1, unofficial].
    *   High quality at low budgets (e.g., 2K) [S1, unofficial].
*   **Limitations:**
    *   Requires training with GSPO, which involves non-differentiable discrete allocations [S1, unofficial].
    *   Performance depends on the accuracy of the hierarchical neighbor search [S1, unofficial].
*   **When to Use:** Applications requiring limited resource budgets, such as AR/VR, robotics, and digital content creation, where inference latency and memory are critical constraints [S1, unofficial].

## Background
RLSplat was proposed by Bae, Park, and Kim from KAIST [S1, unofficial]. It addresses the limitations of prior budget-controllable FF3DGS methods like EcoSplat and F4 Splat, which predict dense sets of Gaussians and then prune them, resulting in nearly constant inference latency and memory regardless of the target budget [S1, unofficial]. RLSplat introduces a resource-linear approach by learning a Gaussian allocation policy and using a resource-linear decoder with local cross-attention [S1, unofficial].
