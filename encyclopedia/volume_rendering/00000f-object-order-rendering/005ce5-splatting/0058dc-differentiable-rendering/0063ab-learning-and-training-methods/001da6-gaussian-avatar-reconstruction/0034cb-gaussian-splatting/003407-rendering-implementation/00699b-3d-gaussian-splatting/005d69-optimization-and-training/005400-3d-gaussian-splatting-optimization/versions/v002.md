# 3D Gaussian Splatting Optimization

Also called: Original 3DGS Loss

## Overview
3D Gaussian Splatting Optimization is the training procedure that adjusts the parameters of 3D Gaussian primitives to minimize the difference between rendered images and ground truth observations [S1]. It solves the problem of fitting a differentiable radiance field to 2D image data by using gradient-based optimization to update geometry, color, and opacity, while dynamically controlling the number of primitives via adaptive densification [S1]. It is distinguished from sibling methods like [CoR-GS](1486-cor-gs.md) and [EffGS](3365-effgs.md) by its reliance on a specific distortion loss formulation and a fixed set of base hyperparameters where the scalar weighting factor $\gamma$ is tuned to align Gaussian counts across datasets, rather than modifying the underlying optimization framework [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of $N$ training images with known camera poses, each represented by a ground truth pixel color $x$. The initial scene representation is a collection of 3D Gaussians $\mathcal{G} = \{G_i\}_{i=1}^M$, where each Gaussian $G_i$ is defined by parameters $\mu_i$ (center), $\Sigma_i$ (covariance), $c_i$ (color), and $\alpha_i$ (opacity) [S1].
*   **Outputs:** Optimized Gaussian parameters $\mathcal{G}$ that minimize the distortion loss, along with a dynamically adjusted set of Gaussians resulting from densification and pruning steps [S1].

**Data Structures:**
The optimization operates on the collection of Gaussian parameters $\mathcal{G}$. Each Gaussian $G_i$ stores:
*   $\mu_i \in \mathbb{R}^3$: 3D position.
*   $\Sigma_i \in \mathbb{R}^{3 \times 3}$: Covariance matrix (often parameterized via a rotation matrix $R$ and scaling vector $S$ such that $\Sigma = RSS^T R^T$).
*   $c_i \in \mathbb{R}^3$: Spherical Harmonics coefficients or RGB color.
*   $\alpha_i \in [0, 1]$: Opacity scalar.
*   Additional metadata for densification tracking (e.g., accumulated gradient norms) is maintained per Gaussian [S1].

**Algorithm Steps:**
1.  **Random Camera Selection:** Select a single training image (camera pose) randomly for the current optimization step [S2, unofficial]. This provides stochastic flavoring to the gradient descent [S2, unofficial].
2.  **Differentiable Rendering:** Render the selected view by projecting all 3D Gaussians to 2D ellipses, sorting them by depth, and alpha-blending them to produce the predicted image $\hat{x}$ [S1].
3.  **Loss Computation:** Compute the distortion loss $D(x, \hat{x})$ between the ground truth image $x$ and the rendered image $\hat{x}$ [S1]. The total loss is $\mathcal{L} = \gamma D(x, \hat{x})$, where $\gamma$ is a scalar weighting factor [S1].
4.  **Backpropagation:** Propagate the pixel error backward through the differentiable rendering pipeline (alpha compositing and 2D projection) to compute gradients for every parameter of every Gaussian that contributed to the pixel values [S2, unofficial].
5.  **Parameter Update:** Use the Adam optimizer to update the Gaussian parameters. Adam adapts the per-parameter step size based on recent gradients, with different base learning rates for different parameter types (e.g., position vs. opacity) [S2, unofficial].
6.  **Adaptive Densification:** Evaluate gradient magnitudes to decide on topology changes:
    *   **Densification:** Introduce new Gaussian primitives in regions with high gradient magnitudes [S1].
    *   **Pruning:** Remove Gaussians with low opacity [S1].
    *   These decisions are driven by the gradients from the distortion loss, meaning the optimization objective influences the evolution of the scene representation [S1].

**Formulas:**
The optimization objective is:
$$ \min_{\mathcal{G}} \gamma \, D(x, \hat{x}) $$
where $\mathcal{G}$ is the collection of Gaussian parameters, $D(\cdot)$ is the distortion computed on the rendered 2D image space, and $\gamma$ is a scalar weighting factor [S1].

**Parameters:**
*   $\gamma$: Scalar weighting factor for the distortion loss. It varies across datasets to align Gaussian counts across methods, as adaptive densification relies on gradient magnitude [S1].
*   Optimizer: Adam, which maintains running averages of gradients and squared gradients to adapt step sizes [S2, unofficial].
*   Base Learning Rates: Different for position, covariance, color, and opacity [S2, unofficial].

**Pseudocode:**
```python
def optimize_3dgs(training_images, initial_gaussians, gamma, num_steps):
    """
    Optimizes 3D Gaussian Splatting parameters.
    
    Args:
        training_images: List of tuples (image_tensor, camera_pose).
        initial_gaussians: List of Gaussian objects with parameters (mu, Sigma, c, alpha).
        gamma: Scalar weighting factor for the distortion loss.
        num_steps: Total number of optimization steps.
        
    Returns:
        Optimized list of Gaussians.
    """
    gaussians = initial_gaussians
    optimizer = Adam(gaussians.parameters(), lr_config={"position": 1e-4, "opacity": 1e-5, ...}) # [G] Typical LR values; exact values not given in sources.
    
    for step in range(num_steps):
        # 1. Random Camera Selection
        img, pose = random.choice(training_images)
        
        # 2. Differentiable Rendering
        # Project Gaussians to 2D, sort by depth, alpha-blend
        rendered_img = render(gaussians, pose)
        
        # 3. Loss Computation
        # D is distortion (e.g., L1 + SSIM + LPIPS as per [S1] context, though specific D is not detailed beyond "distortion")
        distortion = compute_distortion(img, rendered_img)
        loss = gamma * distortion
        
        # 4. Backpropagation
        loss.backward()
        
        # 5. Parameter Update
        optimizer.step()
        optimizer.zero_grad()
        
        # 6. Adaptive Densification
        # Evaluate gradient magnitudes per Gaussian
        grad_norms = compute_gradient_norms(gaussians)
        
        # Densification: Add new Gaussians where gradient is high
        new_gaussians = densify(gaussians, grad_norms, threshold_high) # [G] Thresholds not given in sources.
        gaussians.extend(new_gaussians)
        
        # Pruning: Remove Gaussians with low opacity
        gaussians = prune(gaussians, threshold_opacity_low) # [G] Threshold not given in sources.
        
    return gaussians
```

## Subtopics

### [SplaTAM](9193-splatam.md)
SplaTAM is an RGB-D Simultaneous Localization and Mapping (SLAM) method that represents the world as a collection of 3D Gaussians. It solves the problem of online tracking and mapping by using depth and photometric Iterative Closest Point (ICP) for pose estimation and densification. It is distinguished from sibling methods like Gaussian-SLAM and Gaussian Splatting SLAM by its specific use of view-independent colors and a densification mask to prevent duplicate Gaussian creation.

### [Gaussian-SLAM](9195-gaussian-slam.md)
Gaussian-SLAM is a keyframe-based Simultaneous Localization and Mapping (SLAM) method that utilizes 3D Gaussian Splatting for dense scene representation. It solves the problem of real-time, photorealistic mapping and localization by fusing sub-maps derived from keyframes, addressing the drift and consistency issues common in online streaming approaches. It distinguishes itself from sibling methods like SplaTAM (which uses online densification and depth/photometric ICP) and MonoGS (which is monocular) by employing a sub-map fusion strategy to maintain global consistency.

### [Gaussian Splatting SLAM](10078-gaussian-splatting-slam.md)
Gaussian Splatting SLAM is a simultaneous localization and mapping (SLAM) method that reconstructs a scene as a collection of 3D Gaussians while estimating camera poses, building on [3D Gaussian Splatting Optimization](15143-3d-gaussian-splatting-optimization.md). It differs from siblings like [SplaTAM](9193-splatam.md) and [Gaussian-SLAM](9195-gaussian-slam.md) by explicitly minimizing a combined photometric and geometric residual for both tracking and mapping, and by applying isotropic scale regularization to stabilize localization.

### [Differentiable Pose Estimation](12756-differentiable-pose-estimation.md)
Differentiable Pose Estimation optimizes camera poses by backpropagating photometric loss gradients through a 3D Gaussian Splatting (3DGS) renderer. It solves the problem of recovering accurate camera extrinsics when initial poses are noisy or unknown, specifically enabling applications like motion deblurring where camera motion during exposure must be modeled. It distinguishes itself from SLAM-based siblings like [SplaTAM](9193-splatam.md) and [Gaussian-SLAM](9195-gaussian-slam.md) by focusing on batch optimization of poses for a static scene (or trajectory) rather than incremental online tracking, often leveraging the equivalence between camera transformation and Gaussian position transformation to simplify gradient computation.

### GS-SLAM
GS-SLAM is a SLAM method that proposes an adaptive 3D Gaussian expanding strategy to add new 3D Gaussians into the training stage and delete unreliable ones with captured depths and rendered opacity values [S3]. On the Replica dataset, GS-SLAM achieves PSNR 31.56, SSIM 0.97, and LPIPS 0.094 [S3].

## Operating characteristics
*   **Time Complexity:** Each optimization step involves rendering all Gaussians for a single camera view and backpropagating gradients. The complexity is linear with respect to the number of Gaussians $M$ and the number of pixels $P$ in the view, i.e., $O(M \cdot P)$ per step [S1][S2, unofficial].
*   **Memory Complexity:** Memory usage is dominated by storing the parameters of all Gaussians ($O(M)$) and intermediate rendering buffers ($O(P)$) [S1].
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** The method scales to large scenes by managing the number of Gaussians via adaptive densification and pruning [S1]. The scalar weighting factor $\gamma$ is tuned to align Gaussian counts across datasets, ensuring fair comparison under similar representation budgets [S1].
*   **Strengths:** Real-time rendering capabilities due to the efficient rasterization of 2D splats; high-fidelity reconstruction via differentiable optimization [S1].
*   **Limitations:** The number of Gaussians can grow large, requiring careful densification control; performance depends on the initial SfM points [S1].
*   **When to use:** When real-time novel view synthesis and high-quality reconstruction from sparse or dense image collections are required [S1].
*   **When not:** When memory constraints are extremely tight and cannot accommodate the Gaussian count, or when the scene is highly dynamic without extensions like [Dynamic 3D Gaussian Splatting](5703-dynamic-3d-gaussian-splatting.md) [S1].

## Background
3D Gaussian Splatting Optimization was introduced in the original 3D Gaussian Splatting paper [S1]. It builds on the concept of representing scenes as differentiable 3D Gaussian primitives, allowing for gradient-based optimization using standard distortion losses [S1]. The method has since been extended to various applications, including SLAM [S3], compression [S1], and dynamic scenes [S1].
