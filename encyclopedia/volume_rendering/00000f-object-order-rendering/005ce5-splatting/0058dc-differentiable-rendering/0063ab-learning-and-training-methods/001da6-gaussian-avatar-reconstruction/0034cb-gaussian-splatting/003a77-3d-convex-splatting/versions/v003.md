# 3D Convex Splatting

Also called: Smooth Convex Splatting

## Overview
3D Convex Splatting is a neural rendering method that replaces standard 3D Gaussian primitives with smooth convex shapes to represent scenes [S1, unofficial]. It solves the limitation of Gaussians in accurately modeling flat surfaces and sharp edges, offering greater geometric flexibility and requiring fewer primitives for equivalent fidelity [S1, unofficial]. Unlike its parent [Gaussian Splatting](946-gaussian-splatting.md), which relies on elliptical distributions, this method introduces non-elliptical convex boundaries to better approximate complex geometry [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of scene parameters defining smooth convex shapes (positions, orientations, scales, and opacity/color attributes).
*   **Output:** A rendered 2D image via volume splatting.

**Data Structures:**
The specific internal data layout for the smooth convex shapes is not given in the sources. The method relies on a representation that supports efficient projection and rasterization, distinct from the covariance matrices used in Gaussian Splatting.

**Steps:**
1.  **Primitive Definition:** Define smooth convex shapes in 3D space. These shapes are characterized by their convex boundaries, which differ from the elliptical boundaries of Gaussians [S1, unofficial].
2.  **Projection:** Project the 3D convex shapes onto the 2D image plane. The sources do not provide the explicit mathematical formula for this projection, but it implies a differentiable transformation suitable for gradient-based optimization [S1, unofficial].
3.  **Rasterization:** Render the projected shapes using an efficient CUDA rasterizer [S1, unofficial]. This step computes the contribution of each convex primitive to the final pixel color and opacity, handling overlaps via alpha compositing.
4.  **Optimization:** Optimize the parameters of the convex shapes (position, shape, color, opacity) through end-to-end differentiable rendering to minimize the difference between the rendered image and ground truth [S1, unofficial].

**Parameters:**
*   **Rasterizer:** An efficient CUDA-based rasterizer is used to ensure performance [S1, unofficial].
*   **Primitive Count:** The method aims to use fewer primitives than Gaussian Splatting for similar visual quality [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Sharp Edges:** Standard Gaussians struggle with sharp edges; convex shapes are specifically designed to mitigate this [S1, unofficial].
*   **Flat Surfaces:** Convex shapes offer better representation for flat surfaces compared to the bell-curve falloff of Gaussians [S1, unofficial].

## Subtopics

### [Compositional Splatting Strategy](13273-compositional-splatting-strategy.md)
A rendering strategy for non-elliptical primitives (lines, triangles) that decomposes them into vertices and re-sketches the shape. It is chosen when mixed-primitive frameworks are needed for sharp edges.

### [Base Splat Model Generation](15146-base-splat-model-generation.md)
Generates initial elliptical surface patches from point clouds via local PCA. It is chosen for initializing splat models from sparse data, differing from convex shapes by using elliptical primitives.

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** The method reduces memory usage compared to Gaussian Splatting by requiring fewer primitives to represent the scene [S1, unofficial].
*   **Performance:** Coupled with an efficient CUDA rasterizer, it improves fidelity while reducing memory overhead [S1, unofficial].
*   **Strengths:** Greater flexibility than Gaussians; more accurate representation of flat surfaces and sharp edges; fewer primitives required.
*   **Limitations:** Not given in the sources.
*   **When to use:** When accurate representation of sharp edges and flat surfaces is critical, and memory efficiency is a concern.
*   **When not to use:** When compatibility with standard Gaussian-based pipelines is required, or when the scene geometry is well-approximated by ellipsoids.

## Background
3D Convex Splatting was introduced as part of a broader effort to bridge neural rendering and classical computer graphics [S1, unofficial]. It is the first work to move beyond Gaussian primitives by introducing smooth convex shapes [S1, unofficial]. The method is followed by Triangle Splatting and MeshSplatting in the same lineage of enhancing visual quality and integration with graphics pipelines [S1, unofficial].
