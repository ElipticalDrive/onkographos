# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, GSGEN Implementation Details, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific hyperparameters, data structures, and optimization schedules required to implement the 3D Gaussian Splatting (3DGS) training pipeline. It addresses the practical configuration of densification, pruning, and gradient thresholds, which are critical for balancing reconstruction fidelity against memory constraints. It sets itself apart from general optimization theory by providing concrete values for thresholds (e.g., $T_{pos} = 0.02$) and iteration intervals, serving as the primary reference for reproducing standard 3DGS results.

## How it works
The implementation relies on a differentiable rasterization core [6233-optimization-and-parallelization] combined with an iterative optimization loop that adjusts Gaussian parameters (position, scale, rotation, opacity, and spherical harmonic coefficients) to minimize photometric loss.

### Inputs and Outputs
*   **Inputs:** A set of $N$ calibrated images with known camera poses, an initial point cloud (typically from Structure-from-Motion, SfM), and hyperparameters for optimization.
*   **Outputs:** A set of 3D Gaussians $\mathcal{G} = \{\mathbf{p}_i, \mathbf{s}_i, \mathbf{q}_i, \alpha_i, \mathbf{c}_i\}$ representing the scene, where $\mathbf{p}$ is position, $\mathbf{s}$ is scale, $\mathbf{q}$ is rotation (quaternion), $\alpha$ is opacity, and $\mathbf{c}$ is color (SH coefficients).

### Data Structures
The Gaussian representation is stored in a flat array or structure-of-arrays (SoA) format for efficient GPU access. Each Gaussian $i$ contains:
*   **Position:** $\mathbf{p}_i \in \mathbb{R}^3$
*   **Scale:** $\mathbf{s}_i \in \mathbb{R}^3$ (log-space storage is common to ensure positivity)
*   **Rotation:** $\mathbf{q}_i \in \mathbb{R}^4$ (unit quaternion)
*   **Opacity:** $\alpha_i \in [0, 1]$
*   **Color:** $\mathbf{c}_i$ represented by Spherical Harmonic (SH) coefficients. For SH degree $D=1$, this requires $3 \times (D+1)^2 = 12$ coefficients per Gaussian.

### Optimization Steps
The training process follows a fixed schedule of densification and pruning operations interspersed with gradient descent updates.

1.  **Initialization:** Initialize Gaussians from the SfM point cloud. The scene extent $e_{scene}$ determines the initial scale and splitting bounds.
2.  **Iteration Loop:** For each iteration $t$:
    a.  **Random View Sampling:** Randomly select a single image from the training set as supervision [S3].
    b.  **Rasterization:** Render the selected image using the differentiable alpha-blending rasterizer [6233-optimization-and-parallelization].
    c.  **Loss Computation:** Compute the loss $\mathcal{L}$ (typically a combination of L1 and SSIM) between the rendered image and the ground truth.
    d.  **Backpropagation:** Compute gradients $\frac{\partial \mathcal{L}}{\partial \theta}$ for all Gaussian parameters $\theta$ [6233-optimization-and-parallelization].
    e.  **Optimizer Update:** Update parameters using Adam with learning rate $\eta = 1 \times 10^{-3}$ [S3].
    f.  **Densification (Every 100-500 iterations):**
        *   **Splitting:** Split Gaussians where the view-space position gradient exceeds a threshold $T_{pos}$. Standard value: $T_{pos} = 0.02$ [S1]. Interval: Every 500 iterations [S1].
        *   **Cloning:** Clone Gaussians with high opacity but low gradient magnitude to fill gaps.
        *   **Compactness:** Perform compactness-based densification every 1000 iterations to improve geometric completeness [S1].
    g.  **Pruning (Every 200 iterations):**
        *   Remove Gaussians with opacity $\alpha_i < \alpha_{min} = 0.05$ [S1].
        *   Remove Gaussians with excessively large world-space or view-space radius [S1].

### Formulas and Parameters
*   **Adam Optimizer:** $\mathbf{m}_t = \beta_1 \mathbf{m}_{t-1} + (1-\beta_1)\mathbf{g}_t$, $\mathbf{v}_t = \beta_2 \mathbf{v}_{t-1} + (1-\beta_2)\mathbf{g}_t^2$, $\hat{\mathbf{m}}_t = \mathbf{m}_t / (1-\beta_1^t)$, $\hat{\mathbf{v}}_t = \mathbf{v}_t / (1-\beta_2^t)$, $\theta_{t+1} = \theta_t - \eta \hat{\mathbf{m}}_t / (\sqrt{\hat{\mathbf{v}}_t} + \epsilon)$ [S3].
*   **Scene Extent (Default):** $e_{\text{scene}} = 1.1 \cdot \max_{i=1}^{N_{\text{cam}}} \|\bar{C} - C_i\|_2$, where $\bar{C} = \frac{1}{N_{\text{cam}}} \sum_{i=1}^{N_{\text{cam}}} C_i$ [S4].
*   **SH Degree:** Typically set to $D=1$ for simplicity and speed [S3].

### Pseudocode
```python
# Initialization
gaussians = initialize_from_sfm(point_cloud)
optimizer = Adam(gaussians.parameters(), lr=1e-3)
iteration = 0

while iteration < max_iterations:
    # 1. Sample View
    target_image, target_pose = random_sample(training_data)
    
    # 2. Forward Pass (Rasterization)
    rendered_image = rasterize(gaussians, target_pose)
    
    # 3. Loss Computation
    loss = compute_loss(rendered_image, target_image)
    
    # 4. Backward Pass
    loss.backward()
    
    # 5. Optimizer Step
    optimizer.step()
    optimizer.zero_grad()
    
    # 6. Densification and Pruning Schedule
    if iteration % 500 == 0:
        # Split Gaussians based on position gradient
        split_gaussians(gaussians, threshold=0.02)
        
    if iteration % 1000 == 0:
        # Compactness-based densification
        compactness_densify(gaussians)
        
    if iteration % 200 == 0:
        # Prune low opacity and large radius Gaussians
        prune_gaussians(gaussians, alpha_min=0.05)
        
    iteration += 1
```

### Edge Cases and Pitfalls
*   **Scene Extent Bias:** The default scene extent calculation depends on camera positions. If cameras are clustered (e.g., orbiting a small object in a large environment), the extent is underestimated, leading to incorrect splitting/pruning [S4]. Use corrected scene extent based on SfM points: $e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2$ [S4].
*   **Half-Precision Stability:** Training in FP16 requires an automatic scaling factor for loss values to prevent gradient underflow [S2].
*   **Register Pressure:** Use half-precision memory fetches for feature vectors during rasterization to reduce register pressure on GPU [S2].

### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ to selectively enlarge covariances, creating pixel-wise variable blur kernels that match spatially varying scene blurriness [S5]. It sets itself apart from standard Gaussian Splatting by modeling defocus blur explicitly through covariance transformation rather than post-processing [S5]. Choose this for scenes with significant depth-of-field effects [S5].

### Denoise-GS
A self-supervised denoising method for sparse-view 3D Gaussian Splatting that combines unsupervised image denoising (Noise2Void) with differentiable 3DGS [S6]. It sets itself apart from supervised denoising by requiring no paired clean data, making it robust to non-Gaussian noise in sparse viewpoints [S6]. Choose this for sparse-view or noisy input scenarios [S6].

### Multi-Scale Constraint
A technique using position-aware point adaptive control to apply different scales to Gaussians based on viewer distance, improving rendering of distant objects [S7]. It sets itself apart from standard densification by using a distance-dependent threshold $\gamma(\mu)$ for cloning and splitting [S7]. Choose this for large-scale scenes with significant depth variation [S7].

### LS-Gaussian Viewpoint Transformation
An algorithm that leverages inter-frame continuity for efficient sparse rendering by transforming the viewpoint between consecutive frames, rather than rendering each frame separately [S8]. It sets itself apart from naive pixel warping by operating at the tile/Gaussian level to reduce preprocessing and sorting costs [S8]. Choose this for real-time rendering on resource-constrained edge devices like Jetson AGX Orin [S8].

### Camera Localisation for Convergence Basin
Localizes camera pose by minimizing photometric error against ground-truth color image while fixing initial Gaussians $G_{init}$ [S9, unofficial]. It sets itself apart from joint optimization by decoupling pose estimation from scene reconstruction for faster convergence [S9, unofficial]. Choose this for SLAM applications where initial pose estimates are poor [S9, unofficial].

### DiffGS Framework
Applies an optimization process during Gaussian extraction to optimize Gaussians to exact locations using a Gaussian Probability Function (GauPF) [S10]. It sets itself apart from standard 3DGS by using a truncation function $\lambda$ and projection function $\tau$ to refine Gaussian positions [S10]. Choose this for high-fidelity reconstruction where precise Gaussian placement is critical [S10].

### Opacity Offset Table for DSA

### Conditional Splat Approximation
Approximates the influence range of a 3D Gaussian on a slice by using a 2D ellipse splat scaled by the marginal factor [S12, unofficial]. It sets itself apart from exact 3D Gaussian projection by providing an efficient approximation for slice-based rendering or tomographic reconstruction [S12, unofficial]. Choose this for applications requiring fast slice-wise processing [S12, unofficial].

### 3DGS Uncertainty Calculation via Fisher Information
Computes an uncertainty attribute for 3D Gaussians based on the negative log-likelihood of the rendered pixel value, interpreted as Fisher information [S13]. It sets itself apart from standard 3DGS by providing an explicit uncertainty metric derived from the Hessian of the log-likelihood [S13]. ## Operating characteristics
*   **Time Complexity:** $O(N \cdot M)$ per iteration, where $N$ is the number of Gaussians and $M$ is the number of pixels. Densification adds overhead proportional to the number of split/clone operations.
*   **Memory Complexity:** $O(N \cdot D)$, where $D$ is the number of SH coefficients. For $D=1$, each Gaussian uses $\approx 12 \times 4 + 3 \times 4 + 3 \times 4 + 4 \times 4 + 4 \times 4 \approx 100$ bytes (assuming FP32).
*   **Measured Performance:** On NVIDIA V100, generalizable methods like EVolSplat achieve ~80 FPS with 10.41 GB memory [S3]. Standard 3DGS training can take several hours for high-resolution scenes.
*   **Strengths:** Real-time rendering, high fidelity, explicit representation.
*   **Limitations:** High memory usage for large scenes, sensitive to initialization and hyperparameters.
*   **When to use:** Real-time novel view synthesis, high-quality 3D reconstruction.
*   **When not to use:** Resource-constrained environments without optimization, scenes with extreme dynamic range or transparency without extensions.

## Background
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1, S2, S3]. It revolutionized radiance field optimization by replacing neural networks with explicit 3D Gaussians, enabling real-time rendering. The implementation details described here are based on the original paper and subsequent refinements for stability and efficiency [S1, S2, S3].
