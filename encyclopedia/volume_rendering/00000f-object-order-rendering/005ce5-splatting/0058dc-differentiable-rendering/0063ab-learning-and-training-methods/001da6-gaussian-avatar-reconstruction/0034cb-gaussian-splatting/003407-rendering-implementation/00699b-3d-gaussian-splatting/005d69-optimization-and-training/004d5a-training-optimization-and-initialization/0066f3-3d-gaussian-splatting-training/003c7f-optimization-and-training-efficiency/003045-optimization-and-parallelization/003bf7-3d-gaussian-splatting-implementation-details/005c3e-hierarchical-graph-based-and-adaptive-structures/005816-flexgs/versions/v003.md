# FlexGS

Also called: Flexible 3D Gaussian Splatting, Elastic 3DGS

## Overview
FlexGS is an elastic inference method for 3D Gaussian Splatting (3DGS) that enables a single trained model to adapt to varying computational constraints at inference time by selecting and transforming a subset of Gaussians based on a desired model size ratio, without requiring additional fine-tuning [S1]. It solves the problem that standard 3DGS models are too memory-intensive for devices with restricted resources (e.g., smartphones, VR headsets) and that previous compression methods require costly separate fine-tuning or re-training for each target compression ratio [S1]. Unlike post-hoc compression methods that use fixed heuristics to retain Top-K Gaussians based on importance scores and require separate runs for each ratio, FlexGS jointly trains a learnable module to adaptively select points based on attributes and the desired ratio during training [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A pre-trained 3DGS model consisting of $N$ Gaussians, where each Gaussian $i$ is defined by position $\mathbf{X}_i$, scaling vector $\mathbf{s}_i$, rotation quaternion $\mathbf{q}_i$, opacity $\alpha_i$, and spherical harmonics coefficients $\mathbf{SH}_i$ [S1]. A target ratio $e \in (0, 1]$ representing the desired percentage of remaining Gaussians [S1].
*   **Output:** A subset of $K = eN$ Gaussians, transformed by a displacement field, ready for rendering [S1].

**Data Structures:**
The core data structure is the set of $N$ Gaussians. Each Gaussian $i$ is characterized by:
*   Position $\mathbf{X} \in \mathbb{R}^3$ [S1].
*   Scaling vector $\mathbf{s} \in \mathbb{R}^3$ [S1].
*   Rotation vector (quaternion) $\mathbf{q} \in \mathbb{R}^3$ (Note: The source specifies $\mathbb{R}^3$ for the rotation vector, though quaternions are typically $\mathbb{R}^4$; the source text explicitly states $\mathbf{q} \in \mathbb{R}^3$) [S1].
*   Opacity $\alpha \in \mathbb{R}$ [S1].
*   Color $\mathbf{c}$ defined by spherical harmonics coefficients $\mathbf{SH} \in \mathbb{R}^{(d+1)}$ where $d$ is the SH degree [S1].

The covariance matrix $\Sigma$ is decomposed into a scaling matrix $\mathbf{S}$ and a rotation matrix $\mathbf{R}$ derived from $\mathbf{s}$ and $\mathbf{q}$:
$$ \Sigma = \mathbf{R}\mathbf{S}\mathbf{S}^\top \mathbf{R}^\top $$
The Gaussian function is defined as:
$$ G(\mathbf{X}) = e^{-\frac{1}{2} \mathbf{X} \Sigma^{-1} \mathbf{X}} $$
[ S1 ]

**Numbered Steps:**
1.  **Initialization:** Start with a fully trained 3DGS model containing $N$ Gaussians [S1].
2.  **Gaussian Selection:** For a given target ratio $e$, the method predicts a binary scaler $\lambda_i$ for each Gaussian $i$, where $\lambda_i = 1$ if selected and $\lambda_i = 0$ if not [S1]. The selection must satisfy the constraint:
    $$ \sum_{i=1}^{N} \lambda_i = eN $$
    [ S1 ]
    The selection is performed by a learnable Gaussian selector module that takes Gaussian attributes and the ratio $e$ as input [S1].
3.  **Gaussian Transformation:** For the selected Gaussians ($\lambda_i = 1$), a ratio-dependent Gaussian transformation field displaces them to compensate for missing details caused by the reduction in the number of Gaussians [S1].
4.  **Rendering:** Render the transformed subset using the standard differentiable splatting equation for pixel color $C$:
    $$ C = \sum_{i \in N} c_i \alpha_i \prod_{j=1}^{i-1} (1 - \alpha_j) $$
    where the product term represents the accumulated transparency of preceding Gaussians [S1].

**Parameters:**
*   $e$: Target ratio. Typical values are not specified in the sources, but the method supports arbitrary ratios [S1].
*   $N$: Total number of Gaussians in the original model [S1].
*   $K$: Number of selected Gaussians, $K = eN$ [S1].

**Edge Cases and Pitfalls:**
*   Fixed heuristic selection rules may fail to generalize in extreme cases, such as when selecting only 1% of Gaussians, because importance scores must be frequently re-computed as Gaussian attributes evolve during training [S1]. FlexGS addresses this by jointly training the selector [S1].
*   The discrete nature of the selection variable $\lambda_i$ makes traditional gradient descent ineffective; the method uses Gumbel-Softmax to handle this during training [S1].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** The method reduces memory usage at inference time by storing only $K = eN$ Gaussians instead of $N$ [S1]. The training phase requires storing the full model plus the parameters for the selector and transformation modules [S1].
*   **Measured Performance:** Comprehensive experiments on ZipNeRF, MipNeRF, and Tanks&Temples scenes demonstrate the effectiveness of the approach [S1]. Specific metrics (FPS, PSNR, SSIM) are not provided in the notes.
*   **Scaling:** The method allows dynamic compression at any ratio without re-training, adaptively balancing quality and computational costs for diverse deployment scenarios [S1].
*   **Strengths:** Eliminates the need for separate fine-tuning for each ratio; enables deployment on devices with restricted computational resources; adapts to arbitrary remaining ratios [S1].
*   **Limitations:** Requires a learnable module to be trained jointly with the 3DGS model; performance at extreme compression ratios (e.g., 1%) may be challenging without careful training [S1].

## Background
FlexGS was introduced by Hengyu Liu, Yuehao Wang, Chenxin Li, Ruisi Cai, Kevin Wang, Wuyang Li, Pavlo Molchanov, Peihao Wang, and Zhangyang Wang from The Chinese University of Hong Kong, University of Texas at Austin, and Nvidia [S1]. The paper "FlexGS: Train Once, Deploy Everywhere with Many-in-One Flexible 3D Gaussian Splatting" was published in CVPR 2025 (arXiv:2506.04174v1, June 4, 2025) [S1]. It addresses the limitations of standard 3DGS, which demands significant GPU memory, limiting its use on devices with restricted computational resources [S1]. Previous approaches focused on pruning less important Gaussians but often required a fine-tuning stage and lacked adaptability for specific memory needs of different devices [S1].
