# FAST-Splat

Also called: Fast, Ambiguity-Free Semantic Transfer in Gaussian Splatting

## Overview
FAST-Splat is a semantic Gaussian Splatting method that directly augments each Gaussian primitive with specific semantic codes and uses a hash-table for disambiguation, avoiding neural fields for semantic distillation to enable fast training, rendering, and ambiguity-free object localization [S1, unofficial]. It solves the limitations of prior semantic GSplat methods, which suffer from slow training/rendering speeds, high memory usage, and ambiguous semantic object localization when users query with semantically similar but distinct objects [S1, unofficial]. Unlike siblings like LangSplat and Feature 3D Gaussian Splatting, FAST-Splat employs a single-phase, neural-free training procedure that jointly optimizes geometric, visual, and semantic attributes, preserving the explicit representation benefits of 3D Gaussian Splatting [S1, unofficial].

## How it works
FAST-Splat builds on [Semantic and Language Integration](15930-semantic-and-language-integration.md) by implementing a specific neural-free, single-phase training procedure. It augments the standard 3D Gaussian parameter set with a semantic attribute $\beta_i$ and uses an affine transformation to map these attributes to a semantic dictionary (hash-table) for classification and open-vocabulary querying.

### Inputs and Outputs
**Inputs:**
*   A dataset of RGB images $\mathcal{D}$ with known camera poses.
*   (Optional) Closed-set object detector (e.g., YOLO, DETR) for initial object lists.
*   Open-set object detector (e.g., GroundingDINO) and segmentation model (e.g., SAM-2) for dense semantic maps.
*   Pre-trained text encoder (e.g., CLIP, BERT) for open-vocabulary queries.

**Outputs:**
*   Optimized Gaussian parameters: means $\mu_i$, covariances $\Sigma_i$ (or rotation $q_i$ and scale $s_i$), opacities $\alpha_i$, spherical harmonic coefficients $c_i$, and semantic codes $\beta_i$.
*   Affine transformation matrix $W$.
*   Hash-table (dictionary) of identified object classes and their text embeddings.

### Data Structures
1.  **Gaussian Primitive $i$:**
    *   $\mu_i \in \mathbb{R}^3$: Mean position.
    *   $q_i \in \mathbb{R}^4$: Unit quaternion for rotation.
    *   $s_i \in \mathbb{R}^3$: Scale vector.
    *   $\alpha_i \in \mathbb{R}$: Opacity.
    *   $c_i$: Spherical Harmonic coefficients for color.
    *   $\beta_i \in \mathbb{R}^3$: Semantic code associated with the ellipsoid's semantic identity [S1, unofficial].
2.  **Affine Transformation $W$:**
    *   $W \in \mathbb{R}^{N \times 3}$: Maps the 3D semantic code $\beta_i$ to an $N$-dimensional space, where $N$ is the size of the dictionary [S1, unofficial].
3.  **Hash-Table (Dictionary):**
    *   A collection of identified object classes.
    *   Each entry $d$ has a pre-computed text embedding $\theta_d$ from the text encoder [S1, unofficial].

### Numbered Steps

1.  **Initialization:** Initialize the Gaussian Splatting model (means, covariances, opacities, SH parameters) from a sparse point cloud obtained via structure-from-motion [S1, unofficial]. Initialize semantic codes $\beta_i$ (e.g., randomly or zero-initialized) and the affine matrix $W$ [S1, unofficial].
2.  **Semantic Map Generation (Pre-processing):**
    *   Feed images into an open-set object detector to generate object lists and bounding boxes [S1, unofficial].
    *   Generate dense semantic maps using SAM-2, passing each object class and its bounding box [S1, unofficial].
    *   Maintain a dictionary (hash-table) of identified objects. Augment object classes with an "undetected" class label [S1, unofficial].
3.  **Text Embedding Pre-computation:**
    *   For each entry $d$ in the dictionary, compute the text embedding $\theta_d$ using a pre-trained text encoder (e.g., CLIP) without fine-tuning [S1, unofficial].
4.  **Joint Optimization (Single-Phase Training):**
    *   Simultaneously optimize all attributes ($\mu_i, q_i, s_i, \alpha_i, c_i, \beta_i$) and the affine transformation $W$ in a single phase using gradient descent with the Adam optimizer [S1, unofficial].
    *   For each image $I \in \mathcal{D}$:
        a. **Rendering:** Render a semantic feature map using differentiable tile-based rasterization for the given camera pose. For each pixel $p$, the rendered semantic feature $F_{I,p}$ is computed by accumulating the transformed semantic codes of visible Gaussians:
           $$ F_{I,p} = \sum_{i \in \mathcal{N}_p} \text{softmax}(W \beta_i) \alpha_i T_i $$
           where $\mathcal{N}_p$ are the Gaussians covering pixel $p$, $\alpha_i$ is opacity, $T_i$ is transmittance, and $\text{softmax}$ is applied to the $N$-dimensional vector $W \beta_i$ to define a probability distribution over the dictionary entries [S1, unofficial]. Note: The standard color rendering equation is also computed: $C_{I,p} = \sum_{i \in \mathcal{N}_p} c_i \alpha_i T_i$.
        b. **Loss Calculation:** Compute the total loss $L_{sgs}$:
           $$ L_{sgs} = L_{gs} + L_{ce} $$
           where $L_{gs}$ is the Gaussian Splatting photometric loss:
           $$ L_{gs} = (1 - \lambda) \sum_{I \in \mathcal{D}} \| I - \hat{I} \|_1 + \lambda L_{D-SSIM} $$
           and $L_{ce}$ is the multi-class cross-entropy loss for semantics:
           $$ L_{ce} = - \sum_{I \in \mathcal{D}} \sum_{p \in \mathcal{T}_I} \gamma_p \sum_{c} y_{p,c} \log \left( \frac{\exp(F_{I,p,c})}{\sum_{j=1}^{N} \exp(F_{I,p,j})} \right) $$
           Here, $\lambda \in [0, 1]$ balances L1 and D-SSIM losses [S1, unofficial]. $\mathcal{T}_I$ is the set of pixel indices in image $I$. $y_{p,c}$ is the ground truth one-hot label for pixel $p$ and class $c$. $\gamma_p$ is a weight for pixel $p$; pixels with the "undetected" class label are assigned a lower weight to serve as a regularization term for stability [S1, unofficial].
        c. **Update:** Update parameters using the Adam optimizer [S1, unofficial].
5.  **Open-Vocabulary Querying (Runtime):**
    *   Given a user's natural-language prompt, compute the query text embedding $\theta_q$ using the pre-trained text encoder [S1, unofficial].
    *   Compute the relevancy score for each dictionary entry $d$ using pairwise softmax between cosine-similarity values of $\theta_d$ and $\theta_q$ (positive) plus canonical negative embeddings [S1, unofficial].
    *   Designate entries exceeding a relevancy score threshold as similar to the query.
    *   Map these entries to pixels in the rendered feature map using the softmax probability distribution.
    *   Assign a label to each pixel by taking the maximum probability value (or using conformal prediction) [S1, unofficial].
    *   **Disambiguation:** If the query is ambiguous (e.g., "tea" but the object is a "coffee machine"), the system identifies the semantically similar object via the hash-table and provides the precise semantic label (e.g., "coffee machine") to disambiguate the identity [S1, unofficial].

import torch.nn.functional as F

class FASTSplat:
    def __init__(self, num_classes, hidden_dim=3):
        """
        Initialize FAST-Splat model.
        :param num_classes: N, size of the semantic dictionary.
        :param hidden_dim: Dimension of semantic code beta (default 3).
        """
        self.num_classes = num_classes
        self.hidden_dim = hidden_dim
        
        # Affine transformation W: maps beta (R^3) to class logits (R^N)
        self.W = nn.Linear(hidden_dim, num_classes)
        
        # Dictionary of text embeddings (pre-computed, frozen)
        self.dictionary_embeddings = None 
        
        # Text encoder (pre-trained, frozen)
        self.text_encoder = None # Placeholder for CLIP/BERT

    def set_dictionary_embeddings(self, dictionary, text_encoder):
        """
        Pre-compute text embeddings for the dictionary.
        :param dictionary: List of object class strings.
        :param text_encoder: Pre-trained text encoder model.
        """
        self.text_encoder = text_encoder
        self.dictionary_embeddings = []
        for class_name in dictionary:
            # Compute embedding without fine-tuning
            emb = text_encoder.encode(class_name)
            self.dictionary_embeddings.append(emb)
        self.dictionary_embeddings = torch.tensor(self.dictionary_embeddings)

    def compute_relevancy_score(self, query_text):
        """
        Compute relevancy scores for open-vocabulary queries.
        :param query_text: User's natural language prompt.
        :return: Tensor of relevancy scores for each dictionary entry.
        """
        query_emb = self.text_encoder.encode(query_text)
        query_emb = torch.tensor(query_emb)
        
        # Cosine similarity between query and dictionary embeddings
        cos_sim = F.cosine_similarity(query_emb.unsqueeze(0), self.dictionary_embeddings.unsqueeze(1), dim=2)
        
        # Pairwise softmax with canonical negative embeddings (simplified)
        # Note: Exact negative embedding strategy from [S1, unofficial] is not fully specified in pseudocode form.
        # We assume a standard softmax over the cosine similarities for relevancy.

        :param gaussians: List of Gaussian primitives with attributes.

            for g in visible_gaussians:
                # Transform semantic code beta to class probabilities
                logits = self.W(g.beta)
                probs = F.softmax(logits, dim=0)
                
                # Alpha blending
                alpha = g.alpha * T
                F_p = F_p * (1 - alpha) + probs * alpha
                T = T * (1 - alpha)
            F_map[p] = F_p

        Compute joint loss L_sgs = L_gs + L_ce.
        :param gt_image: Ground truth RGB image.
        :param gt_semantic_map: Ground truth semantic map (one-hot).
        :param rendered_image: Rendered RGB image.
        :param rendered_semantic_map: Rendered semantic feature map (probabilities).
        :param lambda_weight: Weight for D-SSIM loss.
        :param undetected_class_idx: Index of the undetected class label.
        :return: Total loss scalar.
        """
        # L_gs: Photometric loss
        l1_loss = torch.mean(torch.abs(gt_image - rendered_image))
        d_ssim_loss = compute_d_ssim(gt_image, rendered_image)
        l_gs = (1 - lambda_weight) * l1_loss + lambda_weight * d_ssim_loss
        
        # L_ce: Semantic cross-entropy loss
        # Flatten maps for loss computation
        gt_flat = gt_semantic_map.view(-1, self.num_classes)
        pred_flat = rendered_semantic_map.view(-1, self.num_classes)
        
        # Weights gamma_p: lower weight for undetected class
        # Assuming gt_flat has 1.0 for detected classes, 0.0 for undetected
        # We need to mask or weight pixels with undetected class
        is_undetected = (gt_flat[:, undetected_class_idx] > 0.5)
        weights = torch.ones_like(gt_flat[:, 0])
        weights[is_undetected] = 0.1 # Lower weight for undetected pixels [S1, unofficial]

        # Note: F.cross_entropy expects raw logits, but we have probabilities from softmax in rendering.
        # We must either re-compute logits or use NLLLoss with log-probs.
        log_probs = F.log_softmax(rendered_semantic_map, dim=-1)
        l_ce = F.nll_loss(log_probs, torch.argmax(gt_flat, dim=1), weight=weights, reduction='mean')

### Parameters
*   $\lambda \in [0, 1]$: Weighting parameter balancing the L1-loss term and the D-SSIM loss term in the Gaussian Splatting loss [S1, unofficial].
*   $\beta_i \in \mathbb{R}^3$: Semantic parameter for each ellipsoid, trained simultaneously with other attributes [S1, unofficial].
*   $W \in \mathbb{R}^{N \times 3}$: Affine transformation matrix mapping $\beta_i$ to $N$-dimensional space [S1, unofficial].
*   Relevancy Score Threshold: Threshold for determining if a dictionary entry is similar to the query [S1, unofficial].

### Edge Cases and Pitfalls
*   **Ambiguity:** Users may query with semantically similar but distinct objects (e.g., "tea" vs. "coffee machine"). FAST-Splat resolves this by providing the precise semantic label of the localized object, unlike methods that only localize [S1, unofficial].
*   **Undetected Pixels:** Pixels not segmented during pre-processing are assigned an "undetected" class label. These pixels are assigned lower weights in the cross-entropy loss to ensure training stability [S1, unofficial].
*   **Bag-of-Words Limitation:** Vision-language models like CLIP use bag-of-words approaches, which can contribute to ambiguity. FAST-Splat mitigates this via the hash-table and specific semantic codes [S1, unofficial].

## Operating characteristics
*   **Training Speed:** 6x to 8x faster than prior work (e.g., LangSplat, Feature-3DGS) [S1, unofficial].
*   **Rendering Speed:** 18x to 51x faster than prior work [S1, unofficial].
*   **GPU Memory Usage:** Approximately 6x smaller than prior work [S1, unofficial].
*   **Performance Metrics (3D-OVS Dataset):**
    *   **Bed Scene:** mIoU 0.933 (vs. LangSplat 0.925, F-3DGS 0.643); Localization Accuracy 0.998 (vs. LangSplat 0.992, F-3DGS 0.961); Training Time 13.96 mins (vs. LangSplat 79.23, F-3DGS 107.25) [S1, unofficial].
    *   **Covered-Desk Scene:** mIoU 0.913 (vs. LangSplat 0.779, F-3DGS 0.678); Localization Accuracy 0.995 (vs. LangSplat 0.978, F-3DGS 0.895); Training Time 13.96 mins (vs. LangSplat 112.06, F-3DGS 112.06) [S1, unofficial].
*   **Strengths:** Fast training and rendering, low memory usage, ambiguity-free semantic localization, single-phase training.
*   **Limitations:** Relies on pre-trained text encoders and open-set detectors for semantic map generation; performance depends on the quality of the initial point cloud and detector outputs.

## Background
FAST-Splat was introduced by Ola Shorinwa, Jiankai Sun, and Mac Schwager from Stanford University. The paper "FAST-Splat: Fast, Ambiguity-Free Semantics Transfer in Gaussian Splatting" was published on arXiv in November 2024 (v2 in March 2025) [S1, unofficial]. It addresses the limitations of existing semantic Gaussian Splatting methods, which are slow, memory-intensive, and ambiguous. FAST-Splat builds on the explicit representation of 3D Gaussian Splatting to achieve faster training and rendering while enabling open-vocabulary queries and precise semantic disambiguation.
