# Gaussian Data Structure

Also called: GaussianList

## Overview
The Gaussian Data Structure (also known as GaussianList) is the primary in-memory container for 3D Gaussian Splatting primitives, organizing per-Gaussian attributes into column-major arrays to facilitate efficient GPU rendering and optimization [S1, unofficial]. It solves the problem of managing a dynamic, large-scale set of heterogeneous geometric primitives by providing a flat, contiguous memory layout that supports batched processing, while explicitly storing precomputed 3D covariance matrices to accelerate the projection step [S1, unofficial]. It sets itself apart from its parent [3D Gaussian Data Layout](2242-3d-gaussian-data-layout.md) by defining the specific container type (a list of arrays rather than a struct-of-arrays or array-of-structs) and from its sibling [Gaussian Data Packing](3257-gaussian-data-packing.md) by focusing on the logical attribute organization rather than low-level bit-packing or serialization [S1, unofficial].

## How it works
### Inputs and Outputs
- **Input**: A set of $N$ 3D Gaussian primitives, each defined by position, scale, rotation, opacity, and spherical harmonics (SH) coefficients.
- **Output**: A `GaussianList` data structure containing column-major matrices for all attributes, enabling efficient iteration during rasterization and gradient computation.

### Data Structures
The `GaussianList` struct consists of the following fields [S1, unofficial]:

1.  **`positions`**: `Matrix4xN<f32>`
    -   Layout: $4 \times N$ matrix.
    -   Rows: $x, y, z$ coordinates in the first three rows; the fourth row is typically padding or homogeneous coordinate (1.0).
    -   Memory: Contiguous column-major storage.
2.  **`scales`**: `Matrix3xN<f32>`
    -   Layout: $3 \times N$ matrix.
    -   Rows: Scale factors along the local $x, y, z$ axes.
3.  **`opacities`**: `DVector<f32>`
    -   Layout: 1D vector of size $N$.
    -   Values: Scalar opacity $\alpha_i \in [0, 1]$.
4.  **`rotations`**: `Matrix4xN<f32>`
    -   Layout: $4 \times N$ matrix.
    -   Rows: Quaternion components $(w, x, y, z)$ for each Gaussian.
5.  **`sh`**: `Matrix48xN<f32>`
    -   Layout: $48 \times N$ matrix.
    -   Content: Spherical Harmonics coefficients.
    -   Detail: Stored in a flat array of size 48 (maximum for degree 3). The layout interleaves channels per degree: $C_{0,R}, C_{0,B}, C_{0,G}, C_{1,R}, C_{1,B}, C_{1,G}, \dots$ [S1, unofficial].
6.  **`num_gaussians`**: `usize`
    -   The current number of active Gaussians $N$.
7.  **`cov3d`**: `Matrix3xN<f32>`
    -   Layout: $3 \times N$ matrix.
    -   Content: Precomputed $3 \times 3$ covariance matrices for each Gaussian, flattened into columns. This avoids recomputing the covariance from scale and rotation during every render pass [S1, unofficial].

### Numbered Steps
1.  **Initialization**: Allocate memory for the `GaussianList` with a capacity $C \ge N$. Initialize `num_gaussians` to $N$.
2.  **Attribute Population**:
    -   For each Gaussian $i \in [0, N-1]$:
        -   Extract position $\mathbf{p}_i$, scale $\mathbf{s}_i$, rotation $\mathbf{q}_i$, opacity $\alpha_i$, and SH coefficients $\mathbf{c}_i$.
        -   Compute the 3D covariance matrix $\Sigma_i$ using the rotation matrix $\mathbf{R}_i$ derived from $\mathbf{q}_i$ and the diagonal scale matrix $\mathbf{S}_i = \text{diag}(\mathbf{s}_i)$:
            $$ \Sigma_i = \mathbf{R}_i \mathbf{S}_i \mathbf{S}_i^T \mathbf{R}_i^T $$
        -   Store $\mathbf{p}_i$ in `positions[:, i]`.
        -   Store $\mathbf{s}_i$ in `scales[:, i]`.
        -   Store $\alpha_i$ in `opacities[i]`.
        -   Store $\mathbf{q}_i$ in `rotations[:, i]`.
        -   Store $\mathbf{c}_i$ in `sh[:, i]`.
        -   Store $\Sigma_i$ (flattened column-wise) in `cov3d[:, i]`.
3.  **Rendering Preparation**: The structure is passed to the rasterization pipeline. The `cov3d` matrix allows the projection step to compute the 2D covariance $\tilde{\Sigma}_i$ efficiently using the Jacobian of the projection and the camera rotation [S1, unofficial].

### Formulas
-   **Covariance Construction** (Implicit in `cov3d` generation):
    $$ \Sigma_i = \mathbf{R}_i \mathbf{S}_i \mathbf{S}_i^T \mathbf{R}_i^T $$
    Where $\mathbf{R}_i$ is the rotation matrix from quaternion $\mathbf{q}_i$, and $\mathbf{S}_i = \text{diag}(s_{i,x}, s_{i,y}, s_{i,z})$.
-   **SH Coefficient Layout**:
    For degree $L=3$, the 48 coefficients are stored as:
    $$ [C_{0,R}, C_{0,B}, C_{0,G}, C_{1,R}, C_{1,B}, C_{1,G}, \dots, C_{3,R}, C_{3,B}, C_{3,G}] $$
    Repeated for each Gaussian column [S1, unofficial].

### Parameters
-   **SH Degree**: Typically up to degree 3, resulting in 48 coefficients per Gaussian [S1, unofficial].
-   **Data Type**: `f32` (32-bit float) for all attributes [S1, unofficial].

### Edge Cases and Pitfalls
-   **Precision**: Floating-point errors in quaternion normalization can lead to invalid rotation matrices if not clamped or renormalized before covariance computation [G].
-   **Boundary**: If $N$ exceeds the allocated capacity, the buffer must be resized (see [Dynamic Buffer Management](3753-dynamic-buffer-management.md)) [G].
-   **Degenerate Input**: Scales of zero or near-zero can cause numerical instability in covariance inversion during projection. A small epsilon floor (e.g., $10^{-6}$) should be applied to scales before constructing $\mathbf{S}_i$ [G].

## Subtopics

### [GSPull](2773-gspull.md)
GSPull is a technique that leverages neural Signed Distance Functions (SDFs) or Unsigned Distance Functions (UDFs) to recover detailed mesh structures from 3D Gaussian Splatting representations. It addresses the limitation of standard 3DGS, which produces volumetric splats rather than explicit surfaces, by integrating distance-field supervision to refine geometry. Unlike methods that directly pull Gaussians to the zero-level set, GSPull uses dense queries around the zero-level set as strong geometric cues to refine the surface conservatively and gradually, preventing error accumulation from ambiguous pulling directions.

### [Composite Error Map and Densification/Pruning Scoring](3396-composite-error-map-and-densification-pruning-scoring.md)
A density control mechanism that uses a frequency-aware mask and photometric loss to compute densification and pruning scores for Gaussian primitives, reducing redundancy and improving fidelity compared to vanilla 3DGS. It sets itself apart from its siblings by integrating a frequency-aware mask into the error computation to filter noise, and by weighting pruning scores with image-level photometric loss rather than raw pixel counts, whereas [Efficient Pruning Score](3598-efficient-pruning-score.md) focuses on second-order sensitivity and [Fisher Sensitivity Score](9664-fisher-sensitivity-score.md) uses Hessian approximations.

### [Dynamic Buffer Management](3753-dynamic-buffer-management.md)
Dynamic Buffer Management handles the resizing of GPU buffers that store 3D Gaussian splat data during training or streaming, ensuring the allocated capacity matches the active Gaussian count. It solves the problem of buffer overflow when densification adds new Gaussians or buffer under-utilization when pruning removes them [G]. It is distinguished from sibling methods like [GSPull](2773-gspull.md) (which handles data retrieval) and [Composite Error Map and Densification/Pruning Scoring](3396-composite-error-map-and-densification-pruning-scoring.md) (which determines *which* Gaussians to add/remove) by focusing on the *memory infrastructure* required to hold the changing set of active entities [G].

### [GS-W Network Architecture](5927-gs-w-network-architecture.md)
The GS-W Network Architecture is the component of the Gaussian in the Wild (GS-W) method responsible for predicting per-Gaussian appearance attributes and visibility from a set of reference images. It solves the problem of adapting 3D Gaussian Splatting to unconstrained image collections by replacing static color attributes with learnable features that are dynamically sampled based on camera viewpoint. It sets itself apart from standard 3DGS by introducing a U-Net encoder-decoder structure to extract image features and a fusion network to combine these with intrinsic Gaussian attributes, enabling view-dependent appearance modeling without explicit spherical harmonics.

### [VastGaussian](6000-vastgaussian.md)
VastGaussian is a large-scale 3D Gaussian Splatting method that partitions a scene into spatially-disjoint regions to enable independent training and decoupled appearance handling for varying lighting conditions, merging results at render time with feathered overlap. It distinguishes itself from standard 3DGS by solving the scalability and lighting inconsistency problems in city-scale reconstruction through a divide-and-conquer strategy that isolates local geometry and appearance.

### [Data Layout and Storage](6235-data-layout-and-storage.md)
Data Layout and Storage defines the memory organization, serialization, and runtime management of 3D Gaussian Splat attributes (position, scale, rotation, opacity, and spherical harmonics) to enable efficient GPU rendering and optimization [G]. It solves the problem of translating high-level splat representations into contiguous, cache-friendly structures suitable for batched processing, while supporting dynamic scene growth and cross-platform data transfer [G]. It is distinguished from sibling methods by focusing on the raw memory layout and buffer management infrastructure rather than the rendering algorithm itself ([GSPull](2773-gspull.md)), error-based densification ([Composite Error Map and Densification/Pruning Scoring](3396-composite-error-map-and-densification-pruning-scoring.md)), or specific network architectures ([GS-W Network Architecture](5927-gs-w-network-architecture.md)).

### [SLAM and Tracking](6236-slam-and-tracking.md)
SLAM and Tracking in the context of 3D Gaussian Splatting (3DGS) enables simultaneous localization and mapping by jointly optimizing camera poses and Gaussian parameters from a stream of incoming images. It solves the problem of reconstructing dynamic or large-scale scenes in real-time or near-real-time, where traditional batch optimization is infeasible. What sets it apart from offline 3DGS is the use of a sliding window of keyframes and incremental updates, allowing the system to maintain a consistent map while tracking camera motion without re-optimizing the entire history.

### [Spherical Harmonics Representation](10084-spherical-harmonics-representation.md)
Spherical Harmonics (SH) is a mathematical basis used in 3D Gaussian Splatting to represent the view-dependent color of each Gaussian primitive. It solves the problem of modeling directional lighting and material properties that vary with the camera viewing angle, which a single static RGB value cannot capture. Unlike static color representations, SH allows for an analytical Jacobian that propagates gradients from the SH coefficients to camera poses during optimization, enabling joint optimization of geometry and appearance.

### [7D Gaussian Splatting](11462-7d-gaussian-splatting.md)
7D Gaussian Splatting (7DGS) is a unified framework for the real-time rendering of dynamic scenes with complex view-dependent effects, representing scene elements as seven-dimensional Gaussians spanning spatial position (3D), time (1D), and viewing direction (3D). It solves the problem of simultaneously modeling spatial geometry, temporal dynamics, and view-dependent appearance (such as scattering and anisotropic reflections) in dynamic scenes, a challenge that prior methods like 4DGS and 6DGS addressed in isolation. Unlike its siblings, 7DGS jointly models all three dimensions in a single coherent framework, using a conditional slicing mechanism to transform 7D Gaussians into time- and view-conditioned 3D Gaussians compatible with existing 3DGS rendering pipelines.

### [Deformation and Dynamic Modeling](11474-deformation-and-dynamic-modeling.md)
Deformation and Dynamic Modeling extends static 3D Gaussian Splatting to represent and render time-varying scenes by predicting time-dependent deformation deltas for canonical Gaussian parameters. It solves the problem of reconstructing moving objects (e.g., people, fluids) from multi-view video or casual capture, enabling real-time rendering of dynamic content. It sets itself apart from static methods by introducing a temporal dimension $t$ that modulates the geometry (position, rotation, scale) of the Gaussian set, distinguishing it from sibling methods like [Sparse-Controlled 3D Gaussian Splatting](6145-sparse-controlled-3d-gaussian-splatting.md) which use sparse control points, or [Deformable Radial Kernel](13703-deformable-radial-kernel-drk-parametrization.md) which modifies the kernel shape.

### [Deformable Radial Kernel (DRK) Parametrization](13703-deformable-radial-kernel-drk-parametrization.md)
Deformable Radial Kernel (DRK) parametrization defines the unconstrained learnable parameters for the attributes of 3D Gaussian kernels, ensuring they remain within valid physical ranges through specific activation functions. It distinguishes itself from standard 3D Gaussian Splatting by introducing a specialized three-step activation for basis angles $\theta_k$ to maintain angular separation and monotonicity, and by providing configurable density control thresholds for sparse training scenarios.

### [Gaussian Grouping](14893-gaussian-grouping.md)
Gaussian Grouping is a method that enhances 3D Gaussian Splatting (3DGS) by incorporating identity encodings for 3D objects, enabling the system to group splats based on their semantic identity. It solves the problem of precise object-level manipulation in 3D scenes, specifically enabling object removal, inpainting, and recomposition. Compared to sibling methods like DFF, Gaussian Grouping removes objects with greatly reduced artifacts and avoids leaving a blurry background.

### Learnable Scale Modulation for Primitive Compactness
A technique that introduces a learnable per-Gaussian scalar factor to reparameterize effective Gaussian scales, providing an optimization pathway for adapting primitive extent while retaining existing tile-culling rules [S2, unofficial]. It initializes a learnable scalar $\beta_i \in \mathbb{R}$ to zero for each Gaussian primitive and optimizes $\beta_i$ jointly with other Gaussian attributes using the Adam optimizer [S2, unofficial]. The effective covariance is scaled by $\gamma_i^2$, where $\gamma_i = \text{sigmoid}(\beta_i)$, changing the overall extent while keeping anisotropic axis ratios governed by the base scales [S2, unofficial]. The gradient is computed as $\frac{\partial \gamma_i}{\partial \beta_i} = 2 \cdot \text{sigmoid}(\beta_i) \cdot (1 - \text{sigmoid}(\beta_i))$ [S2, unofficial]. The projected 2D covariance is $\tilde{\Sigma}_i^{2D} = \gamma_i^2 \cdot \Pi_i \Sigma_i \Pi_i^T$ [S2, unofficial].

### Direct-Unrestricted (DU) Variant
DU replaces $V_{pq} \text{diag}(\Lambda)V_{qq}$ with a free matrix $M \in \mathbb{R}^{3 \times C}$, removing spatial normalization and bounded coupling [S3, unofficial]. The matrix learning rate is set to $5 \times 10^{-6}$, scaled by the median primitive size [S3, unofficial]. Unrestricted direct coordinates alone do not explain quality gains; structured parameterization performs better [S3, unofficial].

### DisC-GS 3D Extension
DisC-GS stores control points of Bézier curves directly in 3D spatial coordinates using attribute $c_{\text{curve}}^{3D} \in \mathbb{R}^{4M \times 3}$ instead of 2D subspace $c_{\text{curve}} \in \mathbb{R}^{4M \times 2}$ [S4]. During rendering, the equation used to acquire $c_{\text{curve}}^{3D}$ from $c_{\text{curve}}$ is omitted, as $c_{\text{curve}}^{3D}$ is introduced as a direct attribute [S4].

### GaussianEditor (Local)
A method tailored for local editing on 3DGS [S5]. It extracts the region of interest (RoI) from text instructions, aligns the text RoI with 3D Gaussians through the image space, and delicately edits within the identified 3D Gaussian RoI [S5].

## Operating characteristics
-   **Time Complexity**: $O(N)$ for initialization and attribute population, where $N$ is the number of Gaussians. Rendering complexity depends on the rasterization algorithm but is linear in the number of splats per tile.
-   **Memory Complexity**: $O(N)$ for storage. Specifically, $4N$ floats for positions, $3N$ for scales, $N$ for opacities, $4N$ for rotations, $48N$ for SH coefficients, and $3N$ (or $9N$ if full covariance is stored) for `cov3d` [S1, unofficial].
-   **Measured Performance**: Not given in the sources.
-   **Scaling**: Scales linearly with the number of Gaussians. Performance is limited by memory bandwidth due to the large SH coefficient storage [S1, unofficial].
-   **Strengths**: Efficient GPU access patterns due to column-major layout; precomputed covariance accelerates projection.
-   **Limitations**: High memory footprint due to SH coefficients; dynamic resizing requires careful buffer management.
-   **When to use**: Standard 3DGS rendering and optimization.
-   **When not to use**: Memory-constrained environments where SH degree can be reduced or omitted.

## Background
The Gaussian Data Structure is the foundational data container for 3D Gaussian Splatting, introduced by Kerbl et al. in 2023 [S1, unofficial]. It has been widely adopted in subsequent works for its efficiency in handling large-scale scenes. The structure has evolved to include precomputed covariances and optimized SH storage to improve rendering speed [S1, unofficial].
