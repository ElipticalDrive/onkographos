# Feed-forward and Generalizable Prediction

Also called: Zero-shot Gaussian Splatting, Pose-free Gaussian Splatting, Foundation Model-based Gaussian Prediction

## Overview
Feed-forward and generalizable prediction methods for 3D Gaussian Splatting (3DGS) replace the iterative, per-scene optimization of standard 3DGS with a single forward pass of a neural network to predict Gaussian parameters directly from input images [S2, unofficial][S3]. This approach solves the problem of slow reconstruction and the dependency on accurate camera poses (typically obtained via Structure-from-Motion) by leveraging pretrained foundation models for geometry and appearance [S1, S2, unofficial]. Unlike inverse methods that optimize a scene representation for a specific set of views, these models generalize across scenes, enabling novel view synthesis and 3D reconstruction from uncalibrated, unordered, or sparse image sets without fine-tuning [S1, unofficial][S3].

## How it works
The core methodology involves a neural network that takes one or more input images as input and outputs a set of 3D Gaussian primitives (position, rotation, scale, opacity, color, and potentially other features) in a single inference step [S2, unofficial][S3]. The specific implementation varies by variant, but generally follows these patterns:

### Inputs and Outputs
*   **Inputs:** One or more RGB images ($I$). Inputs may be uncalibrated (unknown intrinsics/extrinsics) or calibrated [S2, unofficial][S3].
*   **Outputs:** A set of 3D Gaussians $G = \{ \mu_i, \Sigma_i, \alpha_i, c_i, \dots \}$, where $\mu_i$ is the mean position, $\Sigma_i$ is the covariance matrix, $\alpha_i$ is opacity, and $c_i$ is color [S2, unofficial][S3]. Some variants also output additional features (e.g., human biomechanical features) [S3].

### Data Structures
The output is typically a set of Gaussian primitives. Each Gaussian is defined by:
*   **Position ($\mu$):** 3D vector in world or camera coordinates [S2, unofficial][S3].
*   **Covariance ($\Sigma$):** $3 \times 3$ symmetric positive semi-definite matrix, reparameterized as $\Sigma = R(q) S(s) S(s)^T R(q)^T$, where $q \in \mathbb{R}^4$ is a rotation quaternion and $s \in \mathbb{R}^3$ is a scale vector [S2, unofficial][S3].
*   **Opacity ($\alpha$):** Scalar in $[0, 1]$ [S2, unofficial][S3].
*   **Color ($c$):** Can be view-independent (constant RGB) or view-dependent (Spherical Harmonics coefficients) [S2, unofficial][S5].
*   **Additional Features:** Some methods predict feature vectors $f$ for specific applications (e.g., human pose) [S3].

### Numbered Steps (General Pipeline)
1.  **Image Encoding:** Input images are encoded using a shared backbone, often a Vision Transformer (ViT) or a foundation model like MASt3R, DUSt3R, or Spann3R [S1, S2, unofficial][S3].
2.  **Feature Extraction:** The backbone extracts dense feature maps or pointmaps. Foundation models like MASt3R predict 3D point locations and confidence maps in a reference camera frame [S2, unofficial].
3.  **Gaussian Parameter Prediction:** A parallel "Gaussian head" (e.g., DPT architecture or convolutional heads) predicts Gaussian attributes from the encoded features [S2, unofficial][S3].
    *   For each pixel or point, offsets $\Delta$ are predicted to refine the position: $\mu = x + \Delta$ [S2, unofficial].
    *   Rotations $q$, scales $s$, opacities $\alpha$, and colors $c$ are predicted [S2, unofficial][S3].
    *   Activation functions are applied: normalization for quaternions, exponential for scales/offsets, and sigmoid for opacities [S2, unofficial].
4.  **Scene Construction:** The predicted parameters form the set of 3D Gaussians. In some methods, the final set is the union of primitives predicted from multiple input images [S2, unofficial].
5.  **Rendering (Optional for Training):** The predicted Gaussians are rasterized using differentiable splatting to render novel views [S2, unofficial][S3].
6.  **Loss Calculation (Training):** The rendered images are compared to ground truth images using losses such as MSE, LPIPS, SSIM, and photometric/depth losses [S2, unofficial][S3].

### Formulas
*   **Gaussian Position:** $\mu = x + \Delta$, where $x$ is the point predicted by the foundation model and $\Delta$ is the offset predicted by the Gaussian head [S2, unofficial].
*   **Covariance Matrix:** $\Sigma = R(q) S(s) S(s)^T R(q)^T$ [S2, unofficial][S3].
*   **2D Covariance Projection:** $\Sigma' = J W \Sigma W^T J^T$, where $W$ is the view transformation matrix and $J$ is the Jacobian of the affine approximation of the projective transform [S3].
*   **Rendering (Alpha Blending):** $C = \sum_{i \in N} c_i \alpha'_i \prod_{j=1}^{i-1} (1 - \alpha'_j)$, where $c_i$ is color, $\alpha'_i$ is the effective opacity, and $N$ is the set of splatted Gaussians [S3].
*   **Loss Function (Splatt3R):** $L = \lambda_{MSE} L_{MSE}(M \odot \hat{I}, M \odot I) + \lambda_{LPIPS} L_{LPIPS}(M \odot \hat{I}, M \odot I)$, where $M$ is a loss mask [S2, unofficial].
*   **Loss Function (HFGaussian):** $L = L_{image} + L_{depth} + L_{pose} + L_{feature}$, where $L_{image} = \beta L_{mae} + \gamma L_{ssim}$ [S3].

### Parameters
*   **Input Resolution:** Typically 512 × 512 pixels [S2, unofficial][S3].
*   **Training Dataset:** ScanNet++ for general scenes [S2, unofficial]; Human datasets for HFGaussian [S3].
*   **Hyperparameters:** Overlap thresholds $\phi$ and $\psi$ control context/target image selection (e.g., Close: 0.9, 0.9; Very Wide: 0.3, 0.3) [S2, unofficial].
*   **Learning Rate:** $2 \times 10^{-4}$ [S3].
*   **Batch Size:** 4 [S3].

### Edge Cases and Pitfalls
*   **Loss Masking:** Supervising rendering loss for pixels not visible in context views (obscured or outside frustums) is counterproductive. A loss masking strategy based on frustum culling and covisibility testing is critical for strong performance, especially on extrapolated viewpoints [S2, unofficial].
*   **Blurry Details:** Disabling perceptual losses (LPIPS) causes blurry renderings, while disabling geometric losses (L1/SSIM) creates edge artifacts [S5].
*   **View-Dependent Artifacts:** In human-centric models, eyes may appear uncanny if trained on view-dependent data (subjects looking at camera) without spherical harmonics [S5].
*   **Memory Limits:** Processing large numbers of images with dense pointmaps can exceed GPU memory limits if not managed incrementally [S1, unofficial].

## Subtopics

### [AnySplat Pipeline](12847-anysplat-pipeline.md)
AnySplat is a feed-forward neural network that predicts a set of 3D Gaussians directly from uncalibrated input images, enabling novel-view synthesis without iterative optimization. It differs from inverse methods by using a transformer-based encoder-decoder architecture to predict Gaussian parameters, depth, and camera poses in a single forward pass, bypassing the need for per-scene optimization.

### [FineSplat](15257-finesplat.md)
FineSplat is a feed-forward 3D Gaussian Splatting (3DGS) framework that predicts a set of 3D Gaussians from $N$ context views (with or without known poses) using a two-stage dual-grouping strategy to balance local detail preservation with global multi-view reasoning. It distinguishes itself from sibling methods like [YoNoSplat](9436-textured-gs.md) and [ZipSplat](12847-anysplat-pipeline.md) by employing high-resolution 4x4 patch tokens and a dual-grouping strategy (view-wise and 3D spatial locality) to preserve fine-grained visual information while avoiding the prohibitive costs of global multi-view attention.

### [SparSplat](15813-sparsplat.md)
SparSplat is a generalizable, feed-forward model that maps a set of sparse input images (typically 3) and their camera poses to a pixel-aligned map of 2D Gaussian Splatting (2DGS) parameters in a single forward pass. It solves the joint problem of fast multi-view 3D shape reconstruction and novel view synthesis (NVS) from sparse views, leveraging deep features from foundation models like DINOv2 and MASt3R. It differs from its sibling [MVSGaussian](8985-gsgen.md) by using 2DGS primitives instead of 3D Gaussians, which ensures consistent depth across views and enables coherent TSDF mesh extraction, whereas prior generalizable GS methods are primarily optimized for NVS and fail to produce coherent surface reconstructions.

### [AnySplat Pipeline](12847-anysplat-pipeline.md)
A 3D-aware image synthesis generator that predicts color and density values on a sparse voxel grid, conditioned on camera pose. It uses a mapping network with 2 layers and 64 channels, with a channel base of 4000. It conditions the generator on a 12-dimensional camera pose vector (rotation matrix and translation vector) and outputs spherical harmonics coefficients (degree 0) for color. The density output is multiplied by a factor of 30 to facilitate sharp surfaces.

## Operating characteristics
*   **Time Complexity:** Inference is $O(1)$ with respect to scene complexity, as it is a single forward pass, unlike iterative optimization which scales with the number of optimization steps [S2, unofficial][S3].
*   **Memory Complexity:** Depends on the network architecture and input resolution. Runs on consumer-level GPUs (e.g., 24GB) for hundreds of images when using incremental pipelines [S1, unofficial].
*   **Performance:** Splatt3R achieves 4 FPS inference at 512 × 512 resolution [S2, unofficial]. HFGaussian achieves 25 FPS rendering [S3].
*   **Strengths:** Fast reconstruction, no need for camera poses or depth, generalizes to unseen scenes, real-time rendering [S2, unofficial][S3].
*   **Limitations:** Quality may be lower than iteratively optimized 3DGS, especially in textureless regions or with sparse inputs. Requires large training datasets for generalization [S2, unofficial][S3].
*   **When to Use:** When fast reconstruction from uncalibrated images is needed, or when camera poses are unavailable.
*   **When Not to Use:** When maximum possible visual fidelity is required and computational time is not a constraint.

## Background
Feed-forward Gaussian Splatting emerged from the need to accelerate the reconstruction process of 3DGS, which traditionally requires iterative optimization and accurate camera poses [S2, unofficial]. Early methods like Splatt3R extended foundation models like MASt3R to predict Gaussian attributes directly [S2, unofficial]. Subsequent works like ZeroGS introduced incremental pipelines to handle unordered images [S1, unofficial], while HFGaussian specialized the approach for human avatars with integrated biomechanical features [S3]. The field continues to evolve with variants focusing on sparse views, 2DGS, and specific applications like human modeling [S1, unofficial][S3].
