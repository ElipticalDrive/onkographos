# Tight Quad Rasterization with Eigenvalue Decomposition

Also called: Eigenvalue-based Tight Quad Rasterization

## Overview
This method renders 3D Gaussian splats by projecting their anisotropic covariance into screen space and emitting a non-axis-aligned quad per splat to the GPU's fixed-function rasterizer. It solves the problem of overdraw and inefficient clipping inherent in axis-aligned bounding boxes by computing a tight, rotated bounding quad that incorporates the splat's alpha threshold. It differs from software-based CUDA rasterization [S1] by leveraging hardware clipping and interpolation, achieving significant speedups on mobile hardware by discarding large, distant Gaussians early.

## How it works
**Inputs:** 3D Gaussian parameters (mean $\mathbf{\mu}$, 3D covariance $\Sigma$, opacity $\alpha$, color $C$); camera projection matrix $P$; clipping thresholds $\tau_\lambda$ (max eigenvalue) and $\lambda_{dist}$ (distance).
**Outputs:** Rasterized image with blended Gaussians.

**Data Structures:**
*   **Gaussian:** Struct containing $\mathbf{\mu} \in \mathbb{R}^3$, $\Sigma \in \mathbb{R}^{3 \times 3}$ (symmetric positive definite), $\alpha \in \mathbb{R}$, $C \in \mathbb{R}^3$.
*   **Quad Vertices:** 4 vertices in screen space $(x, y)$ with associated attributes (color, opacity).

**Steps:**
1.  **Cull Negative Opacity:** If $\alpha < 0$, discard the Gaussian [S1].
2.  **Project Covariance:** Compute the 2D screen-space covariance $\Sigma_{2D}$. This involves projecting the 3D covariance $\Sigma$ using the camera's Jacobian $J$ and projection matrix $P$. Let $W$ be the depth scaling factor. The standard EWA splatting approach is used [S1].
3.  **Eigen Decomposition:** Decompose $\Sigma_{2D}$ to find eigenvalues $\lambda_1, \lambda_2$ and eigenvectors $\mathbf{v}_1, \mathbf{v}_2$. These represent the scale and rotation of the Gaussian in screen space [S1].
4.  **Compute Tight Quad Bounds:**
    *   Determine the extent of the Gaussian based on $\lambda_1, \lambda_2$ and the alpha threshold.
    *   Calculate the rotation angle $\theta$ from $\mathbf{v}_1$.
    *   Compute the width $w$ and height $h$ of the bounding box aligned with the eigenvectors. The calculation incorporates the splat alpha value to ensure the quad tightly fits the visible portion of the splat [S1].
    *   Construct the 4 vertices of the non-axis-aligned quad centered at the projected mean $\mathbf{\mu}_{2D}$, rotated by $\theta$, with dimensions $w \times h$.
5.  **Clipping Check:**
    *   Check if the maximum eigenvalue $\max(\lambda_1, \lambda_2) > \tau_\lambda$. If so, discard the Gaussian [S1].
    *   (Optional for mobile) Check distance threshold $\lambda_{dist}$. If the Gaussian is too distant, discard it [S1].
6.  **Rasterization:** Emit the quad to the fragment shader. The hardware rasterizer handles clipping against the view frustum and tile boundaries.
7.  **Blending:** In the fragment shader, evaluate the 2D Gaussian density at each fragment inside the quad and blend using the pre-multiplied alpha [S1].

**Pseudocode:**
```python
def render_tight_quad(gaussian, camera, tau_lambda):
    # Step 1: Cull negative opacity
    if gaussian.alpha < 0:
        return []

    # Step 2: Project covariance to 2D
    # J is the Jacobian of the projection at gaussian.mean
    # Sigma_2D = J * Sigma_3D * J^T
    sigma_2d = project_covariance(gaussian.sigma_3d, camera)

    # Step 3: Eigen decomposition
    eigenvalues, eigenvectors = eigen_decompose(sigma_2d)
    lambda_1, lambda_2 = eigenvalues
    v_1, v_2 = eigenvectors

    # Step 4: Compute tight quad
    # Determine scale factors based on alpha threshold and eigenvalues
    # This part incorporates alpha into the bound rectangle calculation [S1]
    scale_1 = compute_scale(lambda_1, gaussian.alpha)
    scale_2 = compute_scale(lambda_2, gaussian.alpha)

    # Calculate quad dimensions
    width = 2 * scale_1
    height = 2 * scale_2

    # Calculate rotation angle from eigenvector
    angle = atan2(v_1.y, v_1.x)

    # Project mean to screen space
    mean_2d = project_point(gaussian.mean, camera)

    # Generate 4 vertices of the rotated quad
    vertices = generate_rotated_quad(mean_2d, width, height, angle)

    # Step 5: Clipping check
    if max(lambda_1, lambda_2) > tau_lambda:
        return []

    # Step 6: Return vertices for rasterization
    return vertices
```

**Parameters:**
*   $\tau_\lambda$: Clipping threshold for maximum eigenvalue. Typical value: Not given in the sources.
*   $\lambda_{dist}$: Distance threshold for culling distant Gaussians. Typical value: Not given in the sources.

**Edge Cases:**
*   **Degenerate Covariance:** If $\Sigma_{2D}$ is singular (eigenvalues are zero), the quad collapses. Handle by skipping or using a minimal fallback quad [G].
*   **Large Eigenvalues:** Gaussians with large splats but means outside the view frustum are discarded by the $\tau_\lambda$ check, preventing unnecessary processing [S1].

## Subtopics

## Operating characteristics
*   **Time Complexity:** $O(N)$ for $N$ Gaussians, with constant-time projection and decomposition per Gaussian.
*   **Memory Complexity:** $O(1)$ per Gaussian for vertex generation.
*   **Performance:** Achieves 5-10x speedup over original software CUDA rasterizer for high pixel-to-point ratios on mobile hardware [S1].
*   **Strengths:** Reduces overdraw; leverages fixed-function hardware for clipping and interpolation; efficient culling of large, distant Gaussians.
*   **Limitations:** Requires GPU support for non-axis-aligned quad rasterization; eigen decomposition can be computationally expensive if not optimized [S1].

## Background
This method is part of the Shape-Shifting Splats approach for real-time context translation in VR [S1]. It builds on the standard 3D Gaussian Splatting rasterization pipeline but optimizes it for mobile and VR contexts by using tight, rotated quads instead of axis-aligned boxes. It references EWA Splatting [60] for the projection foundation and GSplat [54] for the tight fit concept.
