# HFGaussian

Also called: Human Feature Gaussian

## Overview
HFGaussian is a generalizable, human-centric 3D Gaussian splatting framework that estimates photorealistic novel views and integrated biomechanical features (3D skeleton, 3D keypoints, and dense pose) from sparse input images in real time, without per-subject optimization [S1]. It distinguishes itself from sibling methods by explicitly predicting continuous surface embeddings and 3D pose alongside geometry, using a "feature splatting" mechanism that decouples human feature representation from the standard Gaussian opacity and scaling parameters, which are ill-suited for high-frequency biomechanical data [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** Two sparse source views, $I_l$ and $I_r$ (RGB images of size $H \times W$), representing the left and right nearest neighbors to the target view [S1].
*   **Outputs:**
    *   Rendered novel view image $C$ [S1].
    *   3D pose (19 keypoints) [S1].
    *   Human feature map (Continuous Surface Embeddings) [S1].
    *   Set of 3D Gaussians $\mathcal{G} = \{X, c, r, s, \alpha, f\}$, where $X$ is position, $c$ is color, $r$ is rotation, $s$ is scaling, $\alpha$ is opacity, and $f$ is the human feature vector [S1].

**Data Structures:**
The scene is represented as a set of 3D Gaussians. Each Gaussian $i$ is defined by:
*   $X_i \in \mathbb{R}^3$: 3D position.
*   $c_i \in \mathbb{R}^3$: RGB color.
*   $r_i \in \mathbb{R}^4$: Rotation (quaternion).
*   $s_i \in \mathbb{R}^3$: Scaling.
*   $\alpha_i \in \mathbb{R}$: Opacity.
*   $f_i \in \mathbb{R}^k$: Human feature vector (dimension $k$ depends on the embedding space, e.g., DensePose) [S1].

**Step-by-Step Method:**

1.  **Image Encoding:**
    Feed $I_l$ and $I_r$ into a shared image encoder $\epsilon_{img}$ (typically a Vision Transformer or CNN) to generate multiscale image features $f^l_s$ and $f^r_s$, where $s$ denotes the feature scale [S1].

2.  **Cost Volume and Depth Estimation:**
    *   Generate a cost volume $C$ by correlating the feature maps $f^l_s$ and $f^r_s$ of the two source views [S1].
    *   Apply an iterative update mechanism on $C$ to estimate depth maps $D_l$ and $D_r$ corresponding to $I_l$ and $I_r$ [S1].

3.  **Gaussian Feature Generation:**
    *   Encode the depth maps $D_l, D_r$ using a depth encoder $\epsilon_{depth}$ [S1].
    *   Combine the encoded depth features with the image features $f_{img}$ via concatenation ($\oplus$) [S1].
    *   Pass the combined features through a U-Net-like decoder $\epsilon_{params}$ to generate a pixel-wise Gaussian feature map $\Gamma$ [S1]:
        $$ \Gamma = \epsilon_{params}(\epsilon_{img}(I) \oplus \epsilon_{depth}(I)) $$
        [S1]

4.  **Gaussian Parameter Prediction:**
    Use four separate convolutional prediction heads on $\Gamma$ to estimate parameter maps for each foreground pixel coordinate $x$:
    *   Rotation map $M_r$: $r(x) = M_r(\Gamma(x))$ [S1].
    *   Scaling map $M_s$: $s(x) = M_s(\Gamma(x))$ [S1].
    *   Opacity map $M_\alpha$: $\alpha(x) = M_\alpha(\Gamma(x))$ [S1].
    *   Human Feature map $M_f$: $f(x) = M_f(\Gamma(x))$, where $M_f = \text{Sigmoid}(h_f(\Gamma(x)))$ and $h_f$ is the feature head [S1].

5.  **Position and Color Mapping:**
    *   **Position ($X$):** Map 2D pixel coordinates $x$ to 3D space using the predicted depth maps and known camera parameters via a mapping function $M_p$: $X = M_p(x, D, K)$ [S1].
    *   **Color ($c$):** Directly sample RGB color values from the source images $I_l, I_r$ using a mapping function $M_c$: $c = M_c(x, I)$ [S1].

6.  **Pose Regression (Optional/Parallel Branch):**
    *   Generate point clouds $P_l, P_r$ from depth maps $D_l, D_r$ and camera parameters [S1].
    *   Extract human point clouds using 2D masks [S1].
    *   Combine point clouds into a single context and randomly sample 2048 points to form point cloud $P_c$ [S1].
    *   Input $P_c$ into a pose regression network (based on DGCNN and PointNet) to estimate 3D pose keypoints [S1].

7.  **Feature Splatting (Rendering Human Features):**
    To render the human feature map, use alpha composition similar to color rendering:
    $$ f_p = \sum_{i \in N} f_i \alpha'_i \prod_{j=1}^{i-1} (1 - \alpha'_j) $$
    where $f_i$ is the Gaussian feature, $\alpha'_i$ is the effective alpha (opacity $\alpha_i$ multiplied by the 2D Gaussian value), and $N$ is the set of splatted Gaussians [S1].
    *   Decode the blended feature vector $f_p$ using an MLP with two linear layers (ReLU activation) followed by a final sigmoid layer to render continuous surface embeddings [S1].

8.  **Differentiable Rendering (Color):**
    *   Project 3D Gaussians into 2D space. Calculate the 2D covariance matrix $\Sigma'$ using the view transformation matrix $W$ and the Jacobian $J$ of the affine approximation of the projective transform:
        $$ \Sigma' = J W \Sigma W^T J^T $$
        where $\Sigma$ is the 3D covariance matrix derived from $r$ and $s$ [S1].
    *   Render final pixel colors $C$ using alpha blending:
        $$ C = \sum_{i \in N} c_i \alpha'_i \prod_{j=1}^{i-1} (1 - \alpha'_j) $$
        where $c_i$ is the learned color and $\alpha'_i$ is the resulting alpha [S1].

**Training:**
The model is trained in two stages:
1.  **Depth Estimation:** Train the depth estimator module on both source views for 40,000 iterations [S1].
2.  **Joint Training:** Jointly train the Gaussian parameter estimator, feature estimator MLP, and 3D pose estimator for 100,000 iterations [S1].

**Loss Function:**
The total loss is:
$$ \mathcal{L} = \mathcal{L}_{image} + \mathcal{L}_{depth} + \mathcal{L}_{pose} + \mathcal{L}_{feature} $$
*   $\mathcal{L}_{image} = \beta \mathcal{L}_{MAE} + \gamma \mathcal{L}_{SSIM}$, with $\beta=1.6, \gamma=0.4$ [S1].
*   $\mathcal{L}_{depth} = \sum_{t=1}^{T} \mu^{T-t} \|d_{gt} - d_t\|_1$, with $\mu=0.9$ [S1].
*   $\mathcal{L}_{pose}$: L2 loss between ground truth and estimated 3D keypoints [S1].
*   $\mathcal{L}_{feature}$: L1 loss between ground truth and predicted human features (continuous surface embeddings) [S1].

**Parameters:**
*   Learning rate: $2 \times 10^{-4}$ [S1].
*   Weight decay: $1 \times 10^{-5}$ [S1].
*   Batch size: 4 [S1].
*   Dataset resolution: $512 \times 512$ [S1].
*   Source views: 8 images rendered in a circle at 45-degree intervals [S1].
*   Target views: 3 random viewpoints [S1].
*   Keypoints: 19 (nose, neck, shoulders, elbows, wrists, pelvis, hips, knees, ankles, eyes, ears) [S1].

## Operating characteristics
*   **Speed:** Renders at 25 FPS [S1].
*   **Performance:** Achieves a PSNR of 32.43 on the THuman2.0 test set, closely matching GPS-Gaussian's 32.55 [S1].
*   **Strengths:** Real-time estimation of biomechanical features (dense pose, 3D skeleton) and 3D pose simultaneously with novel view synthesis; generalizes to unseen data without fine-tuning [S1].
*   **Limitations:** Relies on the quality of the initial depth estimation; performance is constrained by the capacity of the feature splatting MLP [S1].
*   **When to use:** Applications requiring real-time 3D human avatars with integrated biomechanical data, such as AR/VR, entertainment, and medical domains [S1].
*   **When not to use:** Scenes without human subjects or where high-fidelity non-human geometry is the primary focus [S1].

## Background
HFGaussian was introduced by Arnab Dey, Cheng-You Lu, Andrew I. Comport, Jean Martinet, Srinath Sridhar, and Chin-Teng Lin in November 2024 [S1]. It builds on GPS-Gaussian, using it as a backbone to generalize to unseen human data [S1]. The method addresses the limitation of previous Gaussian splatting approaches for humans that either rely on parametric body models (SMPL/STAR) or fail to incorporate biomechanical features [S1]. It is implemented using PyTorch and the AdamW optimizer [S1].
