# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, GSGEN Implementation Details, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific hyperparameters, data structures, and optimization schedules required to implement the 3D Gaussian Splatting (3DGS) training pipeline. It addresses the problem of translating the theoretical differentiable rendering formulation into a stable, efficient software implementation. It sets itself apart from sibling methods by providing the concrete "recipe" for the base training loop, including densification schedules, loss weighting, and hardware-specific optimizations like half-precision rasterization, rather than proposing new architectural variants or acceleration kernels.

## How it works

### Inputs and Outputs
**Inputs:**
*   A set of $N_{cam}$ calibrated images with known camera poses $C_i$ and intrinsics.
*   An initial sparse point cloud from Structure-from-Motion (SfM) with $N_{SfM}$ points [S4].
*   Optimization hyperparameters: learning rate, iteration budget, densification intervals, and loss weights [S9, unofficial].

**Outputs:**
*   A set of $N$ 3D Gaussian primitives $\mathcal{G} = \{g_1, ..., g_N\}$, where each $g_j$ is parameterized by position $\mu_j$, covariance $\Sigma_j$ (or scale $s_j$ and rotation $q_j$), opacity $\alpha_j$, and spherical harmonic coefficients $\mathbf{c}_j$ [S5, S6].

### Data Structures
The implementation typically relies on a flat array of Gaussian attributes for efficient GPU access.
*   **Position:** 3 floats ($x, y, z$).
*   **Rotation:** 4 floats (quaternion $w, x, y, z$).
*   **Scale:** 3 floats ($\log(s_x), \log(s_y), \log(s_z)$) to ensure positivity [S6].
*   **Opacity:** 1 float.
*   **Features:** $K$ floats for spherical harmonics (SH) coefficients. For SH degree 1, this is $3 \times (2 \cdot 1 + 1) = 9$ floats per color channel (RGB) [S3].
*   **Gradients:** Accumulated gradients for each parameter field, updated via Adam optimizer [S9, unofficial].

### Training Loop and Optimization
The core training process is a stochastic gradient descent loop [S9, unofficial].

1.  **Initialization:** Initialize Gaussians from the SfM point cloud. The scene extent $e_{scene}$ determines the initial scale and splitting thresholds.
    *   *Pitfall:* The default 3DGS extent calculation $e_{\text{scene}} = 1.1 \cdot \max_{i} \|\bar{C} - C_i\|_2$ is biased if cameras are clustered (e.g., orbiting a small object in a large environment) [S4].
    *   *Correction:* Use the corrected scene extent based on SfM points:
        $$ e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2 $$
        where $\bar{C} = \frac{1}{N_{\text{cam}}} \sum_{i=1}^{N_{\text{cam}}} C_i$ [S4].

2.  **Iteration:**
    1.  Randomly select one training image $I_{target}$ and its camera pose $T_{CW}$ [S9, unofficial].
    2.  **Render:** Project all Gaussians to 2D, sort by depth, and alpha-blend to produce the rendered image $I_{render}$ [S16].
    3.  **Loss:** Compute the loss $\mathcal{L}$ between $I_{render}$ and $I_{target}$:
        $$ \mathcal{L} = (1 - \lambda) \mathcal{L}_1 + \lambda \mathcal{L}_{D-SSIM} $$
        where $\lambda \approx 0.2$ [S9, unofficial].
    4.  **Backprop:** Compute gradients $\frac{\partial \mathcal{L}}{\partial \theta}$ for all Gaussian parameters $\theta$ [S1].
    5.  **Update:** Apply Adam optimizer with learning rate $1 \times 10^{-3}$ [S3].

3.  **Densification and Pruning:**
    *   **Splitting:** Every 500 iterations, split Gaussians with high view-space position gradients. Threshold $T_{pos} = 0.02$ [S1].
    *   **Cloning:** Clone Gaussians with high scale but low gradient to increase density in flat regions [S1].
    *   **Pruning:** Every 200 iterations, remove Gaussians with opacity $\alpha < \alpha_{min} = 0.05$ or excessive radius [S1].
    *   **Compactness:** Perform compactness-based densification every 1000 iterations [S1].

4.  **Termination:** Training typically runs for a fixed budget of 30,000 iterations [S9, unofficial].

### Pseudocode
```python
def train_3dgs(images, poses, sfm_points, num_iterations=30000):
    # 1. Initialization
    gaussians = initialize_from_sfm(sfm_points)
    optimizer = Adam(gaussians.parameters(), lr=1e-3)
    
    # Corrected scene extent calculation
    C_avg = mean([pose.position for pose in poses])
    e_scene = mean([norm(C_avg - p) for p in sfm_points])
    
    for step in range(num_iterations):
        # 2. Sample View
        idx = random_choice(len(images))
        target_image = images[idx]
        camera_pose = poses[idx]
        
        # 3. Render
        rendered_image = render(gaussians, camera_pose)
        
        # 4. Compute Loss
        # L = 0.8 * L1 + 0.2 * D-SSIM
        loss = 0.8 * l1_loss(rendered_image, target_image) + \
               0.2 * d_ssim_loss(rendered_image, target_image)
        
        # 5. Backprop and Update
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        
        # 6. Densification and Pruning
        if step % 500 == 0:
            split_gaussians(gaussians, threshold=0.02)
        if step % 200 == 0:
            prune_gaussians(gaussians, alpha_min=0.05)
        if step % 1000 == 0:
            compactness_densify(gaussians)
            
    return gaussians
```

### Parameters and Edge Cases
*   **Half-Precision:** Use FP16 for feature vector fetches during rasterization to reduce register pressure [S2]. Apply an automatic scaling factor to loss values to stabilize half-precision training [S2].
*   **Library:** Implementation often uses `gsplat` for rasterization and `tiny-cuda-nn` for MLPs if extensions are used [S2, S3].
*   **Sparse Convolution:** If using volume-based extensions, `torchsparse` is used with voxel sizes (e.g., 0.1m) [S3].

## Subtopics

### Corrected Scene-Extent
A method to calculate scene extent based on the SfM point cloud rather than camera positions to avoid bias from camera distribution (e.g., orbiting a small object in a large environment) [S4]. It sets itself apart by replacing the default max-camera-distance metric with an average SfM-point distance [S4].

### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ to selectively enlarge covariances, creating pixel-wise variable blur kernels that match spatially varying scene blurriness [S5]. It distinguishes itself from naive Gaussian blur by allowing spatially varying blur shapes and magnitudes via a compact MLP [S5].

### Denoise-GS
A self-supervised denoising method for sparse-view 3DGS that combines Noise2Void (N2V) with 3DGS training [S6]. It solves the problem of suboptimal reconstruction in noisy, sparse-view scenarios by using unsupervised denoising (N2V) which requires no paired clean data, unlike supervised methods or Noise2Noise [S6].

### Multi-Scale Constraint
Applies different scales to Gaussians based on viewer distance to improve rendering of distant objects [S7]. It uses a position-aware adaptive control where cloning/splitting thresholds are modulated by $\gamma(\mu)$, a function of the Gaussian's distance from the camera center relative to the scene radius [S7].

### LS-Gaussian Viewpoint Transformation
Leverages inter-frame continuity for efficient sparse rendering by transforming the viewpoint between consecutive frames [S8]. It sets itself apart from naive pixel warping by operating at the tile/Gaussian level to reduce preprocessing and sorting costs, enabling sparse rendering (e.g., 1 in 6 frames fully rendered) [S8].

### 3D Gaussian Splatting Training Loop
Defines the per-image error computation and the stochastic gradient descent loop [S9, unofficial]. It emphasizes that training runs for a fixed iteration budget (e.g., 30,000) rather than a loss threshold, and uses a blend of L1 and D-SSIM losses [S9, unofficial].

### Camera Localisation for Convergence Basin
Localizes camera pose by minimizing photometric error against a ground-truth image while fixing the initial Gaussian set $G_{init}$ [S10, unofficial]. It is used to find the convergence basin for novel views by optimizing $T_{CW}$ for 1000 iterations [S10, unofficial].

### DiffGS Framework
Applies an optimization process during Gaussian extraction to optimize Gaussians to exact locations using a Gaussian Probability Function (GauPF) [S11]. It introduces a truncation function $\lambda$ and projection function $\tau$ (e.g., exponential or linear) to improve reconstruction quality with fewer Gaussians [S11].

### Opacity Offset Table for DSA
Constructs an opacity offset table to model changes in digital subtraction angiography [S12]. It is a specific application variant for medical imaging [S12].

### Resolution Guided Primitive Scheduler
Schedules primitive growth using a concave-up function to suppress early growth and encourage mid-stage growth, mitigating poor convergence at the end of optimization [S13]. It uses a momentum-based budget update rule $P_{fin}^{(i)} = \max(P_{fin}^{(i-1)}, \gamma \cdot P_{fin}^{(i-1)} + \eta \cdot P_{add})$ [S13].

### Conditional Splat Approximation
Approximates the influence range of a 3D Gaussian on a slice using a 2D ellipse splat scaled by a marginal factor [S14, unofficial]. It provides an accurate and efficient approximation of the true 3D Gaussian iso-probability contours [S14, unofficial].

### Deformation-Aware Pruning
Identifies and removes redundant Gaussians by gauging their impact on deformation, distinguishing between stable and deformed Gaussians [S15]. It is used in 4D Gaussian Splatting for surgical scene reconstruction [S15].

### GEMM-GS
An acceleration approach that reformulates the 3DGS blending process into a GEMM-compatible form to leverage Tensor Cores [S16]. It uses a three-stage double-buffered CUDA kernel pipeline, achieving a 1.42× speedup over vanilla 3DGS [S16].

## Operating characteristics

*   **Time Complexity:** The training loop is dominated by the rasterization and sorting steps, which are $O(N \cdot T)$ per iteration, where $N$ is the number of Gaussians and $T$ is the number of tiles. With densification, $N$ grows over time, typically reaching millions [S16].
*   **Memory Complexity:** Memory usage scales linearly with the number of Gaussians $N$. Each Gaussian stores position, rotation, scale, opacity, and SH coefficients. For SH degree 1, this is significant [S3].
*   **Performance:** Vanilla 3DGS training takes approximately 30,000 iterations. Accelerations like GEMM-GS provide a 1.42× speedup [S16]. Half-precision rasterization reduces register pressure and improves throughput [S2].
*   **Strengths:** High-fidelity rendering, explicit representation, and relatively fast training compared to neural radiance fields [S9, unofficial].
*   **Limitations:** High memory consumption for large scenes, potential for "floaters" if pruning is insufficient, and sensitivity to initialization and scene extent calculation [S4].
*   **When to use:** When high-quality novel view synthesis is required and computational resources allow for GPU-based training.
*   **When not to use:** When memory is extremely constrained without compression, or when real-time training on CPU is required.

## Background

3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1]. It represents scenes as a set of 3D Gaussians and uses differentiable rasterization for training. The method builds on earlier work in radiance field optimization and differentiable rendering [S1]. The implementation details described here are based on the original paper and subsequent community implementations (e.g., `gsplat`) [S2, S3].
