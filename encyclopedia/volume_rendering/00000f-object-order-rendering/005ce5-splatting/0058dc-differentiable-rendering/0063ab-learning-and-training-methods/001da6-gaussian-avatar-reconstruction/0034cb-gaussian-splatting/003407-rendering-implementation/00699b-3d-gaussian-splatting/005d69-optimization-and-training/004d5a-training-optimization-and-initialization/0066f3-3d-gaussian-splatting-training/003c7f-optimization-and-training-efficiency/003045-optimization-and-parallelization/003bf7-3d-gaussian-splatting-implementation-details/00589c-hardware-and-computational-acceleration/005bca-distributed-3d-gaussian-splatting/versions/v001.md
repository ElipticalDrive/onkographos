# Distributed 3D Gaussian Splatting

Also called: Distributed 3D Gaussian Splatting for Scientific Visualization, Distributed 3D-GS, Multi-GPU 3D-GS

## Overview
Distributed 3D Gaussian Splatting is a multi-GPU extension of the 3D Gaussian Splatting (3D-GS) pipeline designed for scientific visualization, enabling the scalable processing of large datasets that exceed the memory capacity of a single GPU [S1]. Unlike standard 3D-GS which operates on a single device, this method distributes the optimization of Gaussian primitives across multiple GPUs using a data-parallel approach adapted from Grendel-GS, allowing for high-resolution reconstruction of complex scientific isosurfaces [S1]. It sets itself apart by bypassing image-based reconstruction in favor of direct initialization from volume data, specifically targeting the memory bottlenecks encountered when handling millions of Gaussians in HPC environments [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** Scientific volume data (e.g., VTK, HDF5), number of GPUs ($N_{GPU}$), target image resolution ($R \times R$), number of synthetic camera views ($N_{views}$).
*   **Output:** Optimized set of 3D Gaussian primitives (position, covariance, opacity, spherical harmonics coefficients) distributed across $N_{GPU}$ devices, and rendered images matching the synthetic views.

**Data Structures:**
The global state consists of a point cloud and associated Gaussian parameters. This global state is sharded across $N_{GPU}$ workers.
*   **Global Point Cloud:** A set of $N$ points $\{p_i\}_{i=1}^N$ extracted from the isosurface.
*   **Gaussian Parameters per Shard:** Each GPU $k$ holds a subset of Gaussians $G_k$. For each Gaussian $j \in G_k$:
    *   Position: $\mathbf{\mu}_j \in \mathbb{R}^3$
    *   Covariance: $\mathbf{\Sigma}_j \in \mathbb{R}^{3 \times 3}$ (or rotation $\mathbf{R}_j$ and scale $\mathbf{s}_j$)
    *   Opacity: $\alpha_j \in [0, 1]$
    *   Color: Spherical Harmonics coefficients $\mathbf{c}_j$
*   **Training Data:** A set of $N_{views}$ synthetic camera poses and corresponding target images.

**Numbered Steps:**

1.  **Initialization:** Extract an isosurface point cloud directly from the scientific volume data using a tool such as ParaView [S1]. This point cloud serves as the initial positions for the Gaussian primitives, bypassing the need for Structure-from-Motion (SfM) or image-based reconstruction [S1].
2.  **Data Sharding:** Distribute the global point cloud and Gaussian parameters across the $N_{GPU}$ workers. Each GPU $k$ is assigned a shard of the Gaussians $G_k$ such that $\bigcup_k G_k$ constitutes the full set [S1].
3.  **View Generation:** Generate a set of synthetic camera views in a structured orbit around the volume [S1]. The number of views is set to 448 to support the complexity of scientific data, an increase from the 250 views used in prior work [S1].
4.  **Training Loop (Per Step):**
    a. **Data Distribution:** Distribute the training data (camera poses and target images) across the workers [S1]. Each worker processes a subset of the views.
    b. **Forward Pass:** Each GPU renders the splatted image for its assigned views using its local shard of Gaussians. The rendering follows the standard 3D-GS differentiable rasterization pipeline [S1].
    c. **Loss Computation:** Compute the reconstruction loss (e.g., L1 loss + SSIM loss) between the rendered image and the target image for the assigned views [S1].
    d. **Gradient Computation:** Compute gradients of the loss with respect to the local Gaussian parameters ($\mathbf{\mu}, \mathbf{\Sigma}, \alpha, \mathbf{c}$) [S1].
    e. **Gradient Synchronization:** Synchronize gradients across all GPUs using a fused all-reduce scheme [S1]. This ensures that the optimization updates are consistent across the distributed shards.
    f. **Parameter Update:** Apply the optimizer (e.g., Adam) to update the local Gaussian parameters using the synchronized gradients [S1].
5.  **Iteration:** Repeat Step 4 for the desired number of training iterations.

**Pseudocode:**

```python
import torch
import torch.distributed as dist
import torch.multiprocessing as mp

def init_process(rank, world_size, volume_data, num_views, resolution):
    # Initialize distributed process group
    dist.init_process_group("nccl", rank=rank, world_size=world_size)
    
    # 1. Initialization: Extract isosurface point cloud (simulated here)
    # In practice, this uses ParaView to extract points from volume_data
    global_points = extract_isosurface_points(volume_data)
    
    # 2. Data Sharding: Shard the Gaussians
    # Each GPU gets a subset of the initial points
    local_points = shard_data(global_points, rank, world_size)
    
    # Initialize Gaussian parameters for local shard
    # mu: position, cov: covariance, alpha: opacity, sh: spherical harmonics
    local_gaussians = initialize_gaussians(local_points)
    
    # 3. View Generation: Generate synthetic camera views
    # 448 views are used for scientific data complexity
    cameras = generate_structured_orbit_views(num_views=448)
    
    # 4. Training Loop
    for step in range(num_iterations):
        # a. Data Distribution: Assign subset of cameras to this GPU
        local_cameras = cameras[rank::world_size]
        
        # b. Forward Pass: Render images
        rendered_images = []
        for cam in local_cameras:
            # Standard 3D-GS rasterization
            img = splat_render(local_gaussians, cam, resolution)
            rendered_images.append(img)
        
        # c. Loss Computation
        # Target images are assumed to be generated or loaded
        target_images = get_target_images(local_cameras)
        loss = compute_loss(rendered_images, target_images)
        
        # d. Gradient Computation
        loss.backward()
        
        # e. Gradient Synchronization: Fused All-Reduce
        # Synchronize gradients for all parameters across all GPUs
        synchronize_gradients(local_gaussians)
        
        # f. Parameter Update
        optimizer.step(local_gaussians)
        optimizer.zero_grad()

def synchronize_gradients(gaussians):
    # Gather gradients from all ranks and average them
    # This is a fused all-reduce operation
    for param in gaussians.parameters():
        dist.all_reduce(param.grad, op=dist.ReduceOp.SUM)
        param.grad /= world_size

def main():
    world_size = 4 # Number of GPUs
    mp.spawn(init_process, args=(world_size, volume_data, 448, 2048), nprocs=world_size, join=True)

if __name__ == "__main__":
    main()
```

**Parameters:**
*   **Number of synthetic camera views:** 448 [S1].
*   **Image resolutions:** 512x512, 1024x1024, 2048x2048 [S1].
*   **Hardware:** NVIDIA A100 GPUs [S1].

**Edge Cases and Pitfalls:**
*   **Memory Limits:** A single A100 GPU supports up to approximately 11.2M Gaussians [S1]. Datasets larger than this (e.g., Miranda with ~18M Gaussians) are infeasible on a single GPU and will fail due to out-of-memory errors [S1].
*   **Scalability:** While multi-GPU training reduces time, communication overhead from the all-reduce scheme can impact efficiency if the number of GPUs is very large or the network is slow [S1].

## Operating characteristics
*   **Time Complexity:** Training time decreases with the number of GPUs. For the Kingsnake dataset (4M Gaussians) at 2048x2048 resolution, training time drops from 48.00 minutes on 1 GPU to 8.50 minutes on 4 GPUs, a 5.6x speedup [S1].
*   **Memory Complexity:** Memory usage per GPU is reduced by sharding the Gaussians. A single GPU only stores its shard of the Gaussian parameters and the gradients for that shard [S1].
*   **Measured Performance:**
    *   **Kingsnake (4M Gaussians, 110.3 MB):** 4 GPUs, 2048x2048 resolution: PSNR 29.32, SSIM 0.97, LPIPS 0.03 [S1].
    *   **Miranda (18M Gaussians, 491 MB):** 4 GPUs, 2048x2048 resolution: PSNR 36.37, SSIM 0.99, LPIPS 0.011 [S1].
*   **Strengths:** Enables training on datasets that exceed single-GPU memory limits; significant speedup for large datasets; integrates with HPC workflows [S1].
*   **Limitations:** Requires multi-GPU infrastructure; communication overhead; limited to scientific visualization use cases in the current implementation [S1].
*   **When to use:** When the number of Gaussians exceeds ~11M (for A100) or when training time on a single GPU is prohibitive for large scientific datasets [S1].
*   **When not to use:** For small datasets that fit on a single GPU, where the overhead of distributed training may not be justified [S1].

## Background
*   **Origin:** The method was presented in "Toward Distributed 3D Gaussian Splatting for High-Resolution Isosurface Visualization" by Mateevitsi et al. (2025) [S1].
*   **History:** It builds on previous work by Sewell et al. [4] which demonstrated high-fidelity isosurface reconstruction using Gaussian primitives, and adapts the distributed training design from Grendel-GS [6] to the 3D-GS pipeline [S1].
*   **Usage:** Designed for scientific visualization, specifically for post hoc and in situ visualization of complex simulations on HPC systems [S1].
