# Appearance Feature Initialization and Training Schedule

Also called: Appearance feature initialization, Training schedule with appearance features

## Overview
This method defines a staged training protocol for 3D Gaussian Splatting that introduces appearance features after an initial period of geometry optimization, followed by simplification and quantization. It solves the problem of premature optimization of appearance parameters by decoupling them from the initial scale and rotation learning phases. Unlike standard Gaussian Splatting which optimizes all parameters simultaneously, this approach introduces static and view-dependent appearance features at iteration 15K, simplifies the primitive count at 20K, and applies Sub-Vector Quantization (SVQ) in the final 1K iterations [S1].

## How it works
**Inputs and Outputs:**
- Input: Initial 3D Gaussian primitives (position, covariance/scale, rotation, opacity, and initial SH coefficients).
- Output: Optimized Gaussian primitives with quantized appearance features.

**Data Structures:**
The Gaussian primitive stores appearance features as a vector of dimension $D=3$ [S1]. The training schedule manages the state of these features and the primitive set through specific iteration milestones.

**Parameters:**
- Total iterations: 30,000 [S1].
- Appearance introduction iteration: 15,000 [S1].
- Simplification iteration: 20,000 [S1].
- SVQ start iteration: 29,000 [S1].
- Local distinctiveness factor ($\lambda$): 2 [S1].
- Appearance feature dimension ($D$): 3 [S1].

**Steps:**

1. **Initial Training (Iterations 0–14,999):**
   Train scale and rotation parameters from the initial training iteration. Do not optimize appearance features. The spherical harmonics (SH) coefficients are updated, specifically the DC term, which serves as the basis for later initialization [S1].

2. **Appearance Feature Introduction (Iteration 15,000):**
   Introduce appearance features. Initialize static appearance features using the spherical harmonics DC coefficients trained up to iteration 15,000. Initialize view-dependent appearance features as zero vectors [S1].

3. **Simplification (Iteration 20,000):**
   Run the simplification process incorporating local distinctiveness (LD) scoring with factor $\lambda=2$ [S1]. This step reduces the number of Gaussians while preserving visual fidelity.

4. **Sub-Vector Quantization (Iterations 29,000–30,000):**
   Apply SVQ to per-Gaussian features using fixed K-means indices and optimized codebooks. K-means clustering is performed once to assign indices, which remain fixed. Only the codebooks are optimized for the remaining 1,000 iterations [S1].
   - Scale: length 1, 26 codes for each sub-vector.
   - Rotation: length 2, 29 codes for each sub-vector.
   - Appearance features: length 2, 210 codes for each sub-vector [S1].

**Pseudocode:**

```python
def train_gaussian_avatar(total_iterations=30000, appearance_start=15000, simplification_iter=20000, svq_start=29000):
    # Initialize Gaussians with position, scale, rotation, opacity, SH coefficients
    gaussians = initialize_gaussians()
    
    # Pre-compute K-means for SVQ if needed, but indices are fixed later
    # Note: K-means is performed once before SVQ optimization
    
    for iter in range(total_iterations):
        # 1. Initial Training: Optimize scale and rotation only
        if iter < appearance_start:
            optimize_scale_rotation(gaussians)
            update_sh_dc(gaussians) # SH DC coefficients are tracked for later initialization
            
        # 2. Appearance Feature Introduction
        elif iter == appearance_start:
            # Initialize static appearance features from trained SH DC coefficients
            gaussians.static_appearance = gaussians.sh_dc_coefficients
            # Initialize view-dependent appearance features as zero vectors
            gaussians.view_dependent_appearance = zeros_like(gaussians.position)
            
        # 3. Simplification
        elif iter == simplification_iter:
            # Simplify primitives using Local Distinctiveness scoring with lambda=2
            gaussians = simplify_gaussians(gaussians, lambda_factor=2)
            
        # 4. SVQ Optimization
        elif iter >= svq_start:
            # Apply SVQ with fixed indices and optimized codebooks
            # Scale: length 1, 26 codes
            # Rotation: length 2, 29 codes
            # Appearance: length 2, 210 codes
            optimize_svq_codebooks(gaussians, fixed_indices=True)
            
        # Standard rendering and loss computation for all iterations
        render_image(gaussians)
        compute_loss()
        update_gradients(gaussians)
```

**Edge Cases and Pitfalls:**
- Precision: The SVQ step uses fixed K-means indices. If the initial K-means clustering is poor, the final quantization may be suboptimal [S1].
- Boundaries: The transition at iteration 15,000 requires that SH DC coefficients are fully trained up to that point to provide a meaningful initialization for static appearance features [S1].

## Subtopics

## Operating characteristics
- **Time Complexity:** The training runs for 30,000 iterations [S1]. The simplification step at 20,000 iterations adds computational overhead for LD scoring. The SVQ step in the last 1,000 iterations involves optimizing codebooks but uses fixed indices, reducing the search space [S1].
- **Memory Complexity:** The introduction of appearance features increases the memory footprint per Gaussian. The SVQ step reduces memory usage by quantizing features, with specific codebook sizes: 26 codes for scale, 29 for rotation, and 210 for appearance features [S1].
- **Performance:** Experiments were conducted on an NVIDIA RTX 4090 using the Mini-Splatting framework [S1]. The method aims to improve training efficiency and final quality through staged optimization and quantization [S1].
- **Strengths:** Decoupling appearance from geometry/rotation optimization may lead to more stable convergence. SVQ reduces memory and potentially speeds up rendering.
- **Limitations:** The fixed K-means indices in SVQ may not adapt to later training dynamics. The method requires careful tuning of iteration milestones.

## Background
This method is part of the "Optimized Minimal 3D Gaussian Splatting" framework, implemented within the Mini-Splatting library [S1]. It builds on the standard 3D Gaussian Splatting rendering pipeline but introduces a specific training schedule to handle appearance features and quantization efficiently [S1]. The approach is designed to optimize the trade-off between training time, memory usage, and rendering quality.
