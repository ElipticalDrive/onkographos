# DashGaussian

Also called: Computational resource allocation for 3DGS

## Overview
DashGaussian is a scheduling scheme for 3D Gaussian Splatting (3DGS) optimization that accelerates training by reformulating the process as a progressive fitting of higher-frequency components [S1]. It cooperatively allocates rendering resolution and primitive count to strip redundant complexity, distinguishing itself from vanilla 3DGS and other schedulers by producing a concave-up primitive growth curve that spans the entire optimization process [S1]. Unlike methods that peak in primitive count at half-iteration or use concave-down curves, DashGaussian synchronizes primitive growth with dynamic resolution scaling to reduce per-iteration elapsed time without sacrificing rendering fidelity [S1].

## How it works
### Inputs and Outputs
**Inputs:**
*   Training views (images).
*   Initial 3D Gaussian primitives (position, covariance, opacity, color).
*   Optimization hyperparameters (learning rate, densification intervals, thresholds).
*   Target optimization time (e.g., 200 seconds) [S1].

**Outputs:**
*   Optimized 3D Gaussian primitives.
*   Accelerated training time with preserved or improved PSNR/SSIM [S1].

### Data Structures
The method operates on the standard 3DGS primitive structure. No new complex data structures are introduced, but the method tracks:
*   **Iteration Index ($i$):** Current optimization step.
*   **Resolution Factor ($r(i)$):** A continuous scalar modulated to integer values for downsampling [S1].
*   **Primitive Budget ($P_{max}$):** Estimated maximum number of primitives via momentum-based budgeting [S1].

### Formulas
The rendering equation remains the standard volume rendering integral discretized over Gaussian primitives [S1]:

$$
C(u) = \sum_{i=1}^P T_i(u) \cdot w_i(u) \cdot c_i
$$

Where:
*   $C(u)$ is the pixel color at coordinate $u$.
*   $P$ is the total number of active primitives.
*   $T_i(u) = \prod_{j=1}^{i-1} (1 - w_j(u))$ is the transmittance.
*   $w_i(u) = o_i G_{i2D}(u)$ is the weight, with $o_i$ being opacity and $G_{i2D}(u)$ being the 2D Gaussian splatted to the image plane.
*   $c_i$ is the color coefficient of the $i$-th primitive [S1].

**Resolution Scheduling:**
The method formulates optimization as fitting frequency components. Increasing resolution is equivalent to fitting higher frequencies [S1]. The resolution factor $r(i)$ is defined as a continuous scalar and modulated in practice:

$$
r_{mod}(i) = \lfloor r(i) \rfloor
$$

This modulation encourages primitives to grow relatively faster to optimize each primitive more sufficiently [S1].

**Primitive Growth:**
The primitive scheduler produces a concave-up growth curve. The growth is coupled with the rendering resolution via a numerical constraint to balance computing redundancy and fitting quality [S1].

**Momentum-Based Budgeting:**
To estimate the maximum number of primitives ($P_{max}$) adaptively without dataset priors, a momentum-based method is used [S1]. The exact update rule is not provided in the source text, but it replaces static dataset priors [S1].

### Pseudocode

```python
def dash_gaussian_optimization(training_views, initial_primitives, target_time=200.0):
    """
    DashGaussian optimization loop.
    """
    # Initialize primitives
    primitives = initial_primitives
    iteration = 0
    max_iterations = estimate_max_iterations(target_time) # [G] Placeholder for time estimation logic
    
    # Momentum variables for primitive budgeting [S1]
    momentum_buffer = 0.0
    momentum_decay = 0.9 # [G] Typical momentum decay, not specified in source
    
    # Pre-compute frequency components of training views if necessary [S1]
    # Note: Source implies dynamic resolution handles this implicitly
    
    while iteration < max_iterations:
        # 1. Determine current resolution factor
        # r(i) is a continuous scalar; modulate to integer for downsampling
        r_continuous = compute_resolution_factor(iteration, max_iterations)
        r_mod = floor(r_continuous)
        
        # 2. Downsample training views for this iteration
        # Apply anti-aliasing low-pass filter before downsampling to avoid 3D aliasing [S1]
        current_views = apply_low_pass_filter(training_views)
        current_views = downsample(current_views, factor=r_mod)
        
        # 3. Forward pass and Loss computation
        rendered_images = render_primitives(primitives, current_views, r_mod)
        loss = compute_loss(rendered_images, current_views)
        
        # 4. Backward pass and Gradient update
        gradients = compute_gradients(loss, primitives)
        update_primitives(primitives, gradients)
        
        # 5. Primitive Scheduling (Densification/Pruning)
        # The primitive growth follows a concave-up curve synchronized with resolution [S1]
        
        # Estimate primitive budget using momentum-based method [S1]
        # Note: Exact formula not provided in source; using generic momentum update [G]
        current_primitive_count = len(primitives)
        momentum_buffer = momentum_decay * momentum_buffer + (1 - momentum_decay) * current_primitive_count
        estimated_max_primitives = momentum_buffer / (1 - momentum_decay)
        
        # Apply densification criteria (Split/Clone) if count < estimated_max_primitives
        # and other standard 3DGS criteria (gradient magnitude, opacity) are met [S1, Parent]
        if iteration % densification_interval == 0:
            primitives = densify_primitives(primitives, gradients, estimated_max_primitives)
            
        # Prune low-opacity primitives [S1, Parent]
        primitives = prune_primitives(primitives, opacity_threshold)
        
        iteration += 1
        
    return primitives
```

### Parameters
*   **Target Optimization Time:** 200 seconds is cited as a target when applied to the Taming-3DGS backbone [S1].
*   **Resolution Modulation:** Uses floor function $\lfloor r(i) \rfloor$ to encourage faster primitive growth [S1].
*   **Anti-aliasing:** Low-pass filter applied before downsampling [S1].

### Edge Cases and Pitfalls
*   **3D Aliasing:** Simply reducing resolution in training causes 3D aliasing, sacrificing rendering fidelity at the original resolution [S1].
*   **Artifact Introduction:** Anti-aliasing downsampling must apply a low-pass filter before downsampling to avoid disturbing recoverable low-frequency components and introducing artifacts [S1].
*   **Primitive Count:** The method yields fewer primitives than vanilla 3DGS while preserving quality [S1].

## Operating characteristics
*   **Time Complexity:** Significantly reduced per-iteration elapsed time for forward rendering, gradient back-propagation, and primitive optimizing [S1].
*   **Memory Complexity:** Uses fewer Gaussian primitives than vanilla 3DGS [S1].
*   **Measured Performance:**
    *   Average acceleration rate across tested backbones: 45.7% [S1].
    *   Optimization time reduction for Taming-3DGS backbone: 41.3% [S1].
    *   Achieves optimization within 200 seconds on consumer-grade GPUs for models with millions of primitives [S1].
*   **Scaling:** Scene-adaptive; schedules resolution and primitive growth based on scene frequency information [S1].
*   **Strengths:** Plug-and-play integration with existing backbones (Mip-Splatting, Revising-3DGS, Taming-3DGS); preserves or improves rendering quality (PSNR/SSIM) while reducing time [S1].
*   **Limitations:** Requires careful tuning of the resolution factor modulation; relies on the assumption that frequency fitting correlates with optimization progress [S1].

## Background
DashGaussian was proposed by Youyu Chen, Junjun Jiang, Kui Jiang, et al. from Harbin Institute of Technology and Huawei Noah’s Ark Lab [S1]. It was published in CVPR 2025 (arXiv:2503.18402v2, March 26, 2025) [S1]. The work addresses the high computational cost of 3D Gaussian Splatting optimization by treating it as a resource allocation problem, building on the observation that increasing resolution during optimization is equivalent to fitting higher frequency components [S1]. It integrates with various 3DGS backbones to provide a general acceleration paradigm [S1].
