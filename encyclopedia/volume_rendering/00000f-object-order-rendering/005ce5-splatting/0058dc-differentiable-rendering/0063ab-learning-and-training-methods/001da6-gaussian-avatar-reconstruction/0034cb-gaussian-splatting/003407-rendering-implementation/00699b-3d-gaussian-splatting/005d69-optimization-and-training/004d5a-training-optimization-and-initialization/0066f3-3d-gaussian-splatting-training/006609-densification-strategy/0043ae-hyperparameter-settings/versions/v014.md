# Hyperparameter Settings

Also called: Optimizer and Regularization Settings, Optimizer settings, Phys3DGS Hyperparameter Settings, Training Hyperparameters

## Overview
Hyperparameter Settings define the numerical configuration for the optimization of 3D Gaussian primitives, including learning rates, optimizer hyperparameters, and regularization strengths. This method solves the problem of stable convergence and high-fidelity reconstruction by preventing gradient overflow and material-lighting ambiguity. It differs from sibling methods like [Adaptive Density Control](9188-adaptive-density-control.md) by focusing on the numerical stability of the optimizer rather than the structural management of the Gaussian set, and from [Progressive and Multi-stage Training](9966-progressive-and-multi-stage-training.md) by providing the static or dynamic values used within each training stage.

## How it works
**Inputs:**
*   Gaussian parameters: Position $\mu$, Scale $s$, Rotation $q$, Opacity $\alpha$, Spherical Harmonic coefficients $\mathbf{c}$, and potentially material parameters (Base Color, Metallic, Roughness) or MLP weights.
*   Ground truth images and camera poses.
*   Loss function components (e.g., L1, D-SSIM, smoothness regularizers).

**Outputs:**
*   Optimized Gaussian parameters.
*   Stable training trajectory without gradient overflow.

**Data Structures:**
*   **Optimizer State:** Adam state variables (first and second moment estimates) for each parameter group.
*   **Learning Rate Schedule:** Map of parameter names to initial learning rates and decay schedules.
*   **Regularization Weights:** Scalars $\lambda$ for each loss term.

**Parameters and Values:**
1.  **Optimizer:** Adam [S1][S2, unofficial].
    *   $\beta_1 = 0.9$
    *   $\beta_2 = 0.999$
    *   $\epsilon = 10^{-15}$ [S1][S2, unofficial]
2.  **Learning Rates (LR):** [S2, unofficial]
    *   Position: $1.6 \times 10^{-4}$
    *   Color SH: $2.5 \times 10^{-3}$
    *   Scale: $5 \times 10^{-3}$
    *   Opacity: $5 \times 10^{-2}$
    *   Base Color: $1 \times 10^{-2}$
    *   Metallic: $1 \times 10^{-2}$
    *   Roughness: $1 \times 10^{-2}$
    *   Normal Rotation: $1 \times 10^{-3}$
    *   Direct Light SH (deg=0): $2.5 \times 10^{-3}$
    *   Direct Light SH (deg>0): $1 \times 10^{-4}$
    *   Indirect Light SH (deg=0): $2.5 \times 10^{-4}$
    *   Indirect Light SH (deg>0): $1 \times 10^{-3}$
    *   Visibility SH: $0.1$
3.  **Regularization Strengths:** [S2, unofficial]
    *   $\lambda_{smooth}$ (Base Color): $0.06$
    *   $\lambda_{smooth}$ (Roughness): $0.02$
    *   $\lambda_{smooth}$ (Metallic): $0.02$
    *   $\lambda_o$ (Opacity regularizer): $1.0$
    *   $\lambda_{sc}$ (Scale regularizer): $1.0$
    *   $\lambda_{sr}$ (Rotation regularizer): $1.0$
4.  **Reflectivity (Phys3DGS):** [S1]
    *   Initialization: $0.1$
    *   Learning Rate $\gamma_r$: $0.00016$
5.  **MLP Learning Rate (Phys3DGS):** [S1]
    *   Initial $\gamma_{MLP}$: $0.0008$
    *   Decay: Exponential to $1.6 \times 10^{-6}$ over 60,000 iterations.
6.  **Loss Weights (ToRF):** [S1]
    *   $\alpha$ (Depth loss weight): $5$ (or $1$ for synthetic scenes)
    *   $\beta$ (Color loss weight): $0.0008$

**Steps:**
1.  **Initialization:** Initialize Gaussian parameters. For deformable models, initialize deformation offsets $\delta x_k$ from a normal distribution with $\sigma = 10^{-5}$ [S1]. Initialize reflectivity to $0.1$ [S1].
2.  **Gradient Computation:** Compute gradients of the total loss $L$ with respect to all learnable parameters.
3.  **Update:** Apply Adam optimizer updates using the specific learning rates defined above.
4.  **Regularization Application:** Apply smoothness and other regularizers with weights $\lambda$. High weights ($\lambda=1.0$) are used for opacity, scale, and rotation regularizers to prevent instability [S2, unofficial].
5.  **Schedule Decay:** If using MLPs, decay the MLP learning rate exponentially according to the schedule [S1].

**Pseudocode:**
```python
def update_gaussians(gaussians, optimizer, lr_config, reg_config, loss_fn, gt_image, camera):
    """
    Performs one optimization step for 3D Gaussian Splatting with specific hyperparameters.
    """
    # 1. Forward pass
    rendered_image = render(gaussians, camera)
    
    # 2. Compute Loss
    # Example: L1 loss for color, potentially weighted
    color_loss = loss_fn(rendered_image, gt_image)
    
    # Regularization losses
    smoothness_loss = compute_smoothness(gaussians, reg_config.lambda_smooth)
    opacity_reg = compute_opacity_reg(gaussians)
    scale_reg = compute_scale_reg(gaussians)
    rotation_reg = compute_rotation_reg(gaussians)
    
    total_loss = (color_loss + 
                  reg_config.lambda_smooth_base * smoothness_loss.base_color +
                  reg_config.lambda_smooth_rough * smoothness_loss.roughness +
                  reg_config.lambda_smooth_metal * smoothness_loss.metallic +
                  reg_config.lambda_o * opacity_reg +
                  reg_config.lambda_sc * scale_reg +
                  reg_config.lambda_sr * rotation_reg)
    
    # 3. Backward pass
    optimizer.zero_grad()
    total_loss.backward()
    
    # 4. Update parameters with specific learning rates
    # Note: In practice, optimizer.param_groups are set up with these LRs beforehand
    optimizer.step()
    
    return total_loss

# Configuration setup
lr_config = {
    'position': 1.6e-4,
    'color_sh': 2.5e-3,
    'scale': 5e-3,
    'opacity': 5e-2,
    'base_color': 1e-2,
    'metallic': 1e-2,
    'roughness': 1e-2,
    'normal_rotation': 1e-3,
    'direct_light_sh_deg0': 2.5e-3,
    'direct_light_sh_deg_gt0': 1e-4,
    'indirect_light_sh_deg0': 2.5e-4,
    'indirect_light_sh_deg_gt0': 1e-3,
    'visibility_sh': 0.1
}

reg_config = {
    'lambda_smooth_base': 0.06,
    'lambda_smooth_rough': 0.02,
    'lambda_smooth_metal': 0.02,
    'lambda_o': 1.0,
    'lambda_sc': 1.0,
    'lambda_sr': 1.0
}

optimizer = Adam(params=gaussians.parameters(), lr=lr_config, beta1=0.9, beta2=0.999, eps=1e-15)
```

**Edge Cases and Pitfalls:**
*   **Gradient Overflow:** If a single Gaussian behaves abnormally (e.g., driven to the opposite side of the surface, extremely large scale, or extreme opacity), it causes instability. Erroneous Gaussians interfere with visibility, occluding global illumination. The optimizer then compensates by increasing local intensity or decreasing opacity to extreme values, leading to gradient overflow in SH coefficients or opacity values [S2, unofficial].
*   **Mitigation:** Use high regularization weights ($\lambda=1.0$) for opacity, scale, and rotation to constrain these parameters and prevent such outliers [S2, unofficial].

## Subtopics

### [Conditional 3DGS Optimization and Rendering](11459-conditional-3dgs-optimization-and-rendering.md)
Conditional 3DGS Optimization and Rendering extends 3D Gaussian Splatting to handle dynamic scenes by incorporating temporal and directional dependencies into the Gaussian parameters. It solves the problem of representing time-varying geometry and appearance by conditioning the Gaussian covariance and opacity on time $t$ and view direction $d$. It differs from static 3DGS by using a conditional covariance matrix to drive densification and splitting, and from other dynamic variants by integrating these cues directly into the standard 3DGS rasterization pipeline with minimal architectural changes.

### [Blended Error Densification and Splitting](13892-blended-error-densification-and-splitting.md)
Blended Error Densification and Splitting is a strategy for growing Gaussian primitives in 3D Gaussian Splatting that uses an auxiliary per-pixel error metric to drive densification decisions, rather than relying on positional gradient magnitudes. It solves the limitation of gradient-based methods, which are sensitive to error changes but blind to absolute error values in high-frequency areas, by redistributing per-pixel errors to primitives proportional to their rendering contribution. This method is distinct from sibling strategies like [Conditional 3DGS Optimization and Rendering](11459-conditional-3dgs-optimization-and-rendering.md) by explicitly utilizing accumulated L1 error norms as probability weights for splitting.

### [Sparse Matching Integration](14995-sparse-matching-integration.md)
Sparse Matching Integration addresses the under-constrained geometry problem in few-shot neural rendering by integrating precise correspondences from a sparse matching network into the 3D Gaussian Splatting (3DGS) initialization and optimization pipeline. Unlike dense matcher-based methods that introduce blurriness in high-frequency areas due to accuracy limitations, this approach yields precise correspondences that, when combined with frequency regularization, enable better reconstruction of fine details. It serves as a densification and initialization strategy that enhances the base 3DGS architecture's performance in sparse-view scenarios.

### [Adaptive Gaussian Selector](16104-adaptive-gaussian-selector.md)
The Adaptive Gaussian Selector is a learnable module within the FlexGS framework that adaptively selects a subset of 3D Gaussians during training based on their attributes and a desired elastic ratio $e$, using a differentiable mask to enable gradient-based optimization. It sets itself apart from non-differentiable thresholding or hard masking by allowing gradients to flow through the selection decision via the Straight-Through Estimator (STE) applied to Gumbel-Softmax outputs, unlike sibling methods that rely on fixed heuristics or non-differentiable hard thresholds.

### GaMeS
GaMeS is a method simplifying mesh generation by utilizing initial mesh or estimating it in a single-stage training process, introducing a pseudo-mesh of unconnected triangle faces with Gaussian components positioned on these faces to ensure proper alignment [S3]. It realizes deformation by modifying pseudo-mesh positions, with these alterations automatically propagating to the Gaussian mesh, enabling real-time animation and scene editing [S3]. However, it exhibits artifacts when dealing with significant deformations in meshes with large faces, leading to inaccuracies [S3].

### View Selection for Optimization
View Selection for Optimization involves selecting specific views for the adaptation optimization to prevent overfitting to known training views and maintain novel-view performance [S4]. It avoids using training views (+train) as they focus on known-view fitting, and instead uses test views or synthetic views sampled from the estimated camera trajectory (+syn.) [S4]. Using 50 synthetic views on the bicycle scene resulted in Zoom-out PSNR of 29.72 and Zoom-in PSNR of 30.05, compared to 30.84 and 24.23 with test views [S4].

## Operating characteristics
*   **Time Complexity:** The optimization step is dominated by the forward and backward passes of the differentiable rasterizer, which is $O(N \cdot V)$ where $N$ is the number of Gaussians and $V$ is the number of pixels. The Adam optimizer update is $O(N)$.
*   **Memory Complexity:** $O(N)$ for storing Gaussian parameters and optimizer states.
*   **Strengths:** The specific learning rate configuration prevents gradient explosion, particularly for opacity and scale, which are prone to instability. The high regularization weights ensure robust convergence in inverse rendering tasks [S2, unofficial].
*   **Limitations:** The hyperparameters are sensitive to the scene and task. For example, the depth loss weight $\alpha$ must be adjusted for synthetic vs. real scenes [S1]. The method does not inherently handle dynamic scenes without additional conditional mechanisms [S1].
*   **When to use:** Use these settings as a baseline for stable 3DGS training, especially for inverse rendering (Phys3DGS) or depth-aware optimization (ToRF). Adjust learning rates if convergence is slow or unstable.

## Background
The hyperparameter settings described here originate from specific implementations of 3D Gaussian Splatting for advanced tasks. The Adam optimizer settings ($\beta=(0.9, 0.999), \epsilon=10^{-15}$) are standard in deep learning but specifically cited in [S1] and [S2, unofficial]. The detailed learning rate configuration for Phys3DGS [S2, unofficial] addresses the material-lighting ambiguity in inverse rendering. The ToRF method [S1] introduces specific weights for depth and color loss to optimize depth indirectly. GaMeS [S3] and View Selection [S4] represent adaptations for mesh-based deformation and anti-aliasing, respectively.
