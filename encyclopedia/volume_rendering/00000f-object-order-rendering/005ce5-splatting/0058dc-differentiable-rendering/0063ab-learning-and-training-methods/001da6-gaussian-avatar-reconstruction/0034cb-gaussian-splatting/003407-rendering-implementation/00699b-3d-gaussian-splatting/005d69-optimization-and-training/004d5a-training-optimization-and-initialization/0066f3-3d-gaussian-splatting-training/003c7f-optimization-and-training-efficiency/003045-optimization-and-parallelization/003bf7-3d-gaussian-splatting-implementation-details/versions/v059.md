# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, GSGEN Implementation Details, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific algorithmic steps, hyperparameters, and data structures required to implement the training and optimization of 3D Gaussian Splatting (3DGS). It addresses the problem of converting a sparse Structure-from-Motion (SfM) point cloud into a high-fidelity, differentiable radiance field representation. It sets itself apart from generic volume rendering by its reliance on explicit, anisotropic 3D Gaussian primitives and a specific densification/pruning schedule driven by view-space position gradients [S1, S4]. Unlike [MaskGaussian Gradient Computation](4254-maskgaussian-gradient-computation.md) which focuses on gradient sparsity, or [Training Pipeline](5325-training-pipeline.md) which outlines the high-level workflow, this article provides the low-level implementation constants and logic for the core optimization loop.

## How it works

### Inputs and Outputs
**Inputs:**
*   A set of $N_{cam}$ calibrated images with known camera poses $C_i$ and intrinsics.
*   A sparse 3D point cloud generated by SfM (e.g., COLMAP), with $N_{SfM}$ points.
*   Target resolution (width, height).

**Outputs:**
*   A set of $N$ 3D Gaussians, each defined by parameters $\theta = \{\mu, \Sigma, \mathbf{c}, \alpha\}$, where $\mu$ is position, $\Sigma$ is covariance, $\mathbf{c}$ is color (SH coefficients), and $\alpha$ is opacity.

### Data Structures
Each Gaussian $j$ stores:
*   **Position:** $\mu_j \in \mathbb{R}^3$ (float32).
*   **Covariance:** $\Sigma_j \in \mathbb{R}^{3 \times 3}$, parameterized by a scale vector $s_j \in \mathbb{R}^3$ and rotation quaternion $q_j \in \mathbb{R}^4$. $\Sigma_j = R_j S_j S_j^T R_j^T$ [S5].
*   **Opacity:** $\alpha_j \in \mathbb{R}$ (float32, range [0, 1]).
*   **Color:** Spherical Harmonic (SH) coefficients. Default degree $D=1$ (9 coefficients per RGB channel) [S3]. Stored as $\mathbf{c}_j \in \mathbb{R}^{9 \times 3}$ (float32).
*   **Gradient Accumulation:** $\nabla \mu_j, \nabla \alpha_j$ (float32) for densification logic [S1].

### Initialization
1.  **Scene Extent Calculation:** Calculate the corrected scene extent $e'_{\text{scene}}$ to avoid bias from camera distribution [S4]:
    $$ \bar{C} = \frac{1}{N_{\text{cam}}} \sum_{i=1}^{N_{\text{cam}}} C_i $$
    $$ e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2 $$
    where $p_i$ are SfM points. The default 3DGS extent $e_{\text{scene}} = 1.1 \cdot \max_i \|\bar{C} - C_i\|_2$ is replaced to prevent incorrect splitting in clustered camera setups [S4].
2.  **Gaussian Creation:** Initialize one Gaussian per SfM point.
    *   Position $\mu_j = p_j$.
    *   Opacity $\alpha_j$ initialized to a small value (e.g., 0.1) or learned [G].
    *   Scale $s_j$ initialized proportional to $e'_{\text{scene}}$ [S4].
    *   Rotation $q_j$ initialized to identity.
    *   SH coefficients $\mathbf{c}_j$ initialized to 0 for $D>0$, and RGB color from the image at the nearest pixel [G].

### Training Loop
The training loop runs for a fixed iteration budget, typically 30,000 iterations [S9, unofficial].

1.  **Random View Selection:** Randomly select one training image $I_{target}$ and its camera pose $T_{CW}$ [S9, unofficial].
2.  **Differentiable Rasterization:**
    *   Project all Gaussians to 2D screen space.
    *   Compute 2D covariance $\Sigma_{2D}$ using the Jacobian of the affine approximation of the projection [S5].
    *   Sort Gaussians by depth for each tile.
    *   Render pixel color $\mathbf{C}_{render}$ using alpha blending:
        $$ \mathbf{C}_{render} = \sum_{i \in \text{sorted}} \mathbf{c}_i \alpha_i T_i, \quad T_i = \prod_{k < i} (1 - \alpha_k) $$
    *   [G] Use half-precision (FP16) for feature vector fetches during rasterization to reduce register pressure [S2].
3.  **Loss Computation:**
    *   Compute per-pixel loss between $\mathbf{C}_{render}$ and $I_{target}$.
    *   Total Loss $\mathcal{L} = (1 - \lambda) \mathcal{L}_1 + \lambda \mathcal{L}_{SSIM}$, with $\lambda \approx 0.2$ [S9, unofficial].
    *   [G] Apply an automatic scaling factor to loss values to improve half-precision training stability [S2].
4.  **Backpropagation:**
    *   Compute gradients $\frac{\partial \mathcal{L}}{\partial \theta}$ via the differentiable rasterizer [6233-optimization-and-parallelization].
    *   Accumulate positional gradients $\nabla \mu_j$ for densification logic [S1].
5.  **Optimizer Update:**
    *   Update parameters using Adam optimizer with learning rate $1 \times 10^{-3}$ [S3].
6.  **Densification and Pruning (Periodic):**
    *   **Splitting:** Every 500 iterations, split Gaussians where the view-space position gradient magnitude exceeds $T_{pos} = 0.02$ [S1].
    *   **Cloning:** Clone Gaussians with high opacity but low gradient magnitude to prevent over-convergence [G].
    *   **Pruning:** Every 200 iterations, remove Gaussians with opacity $\alpha < \alpha_{min} = 0.05$ or with excessively large world-space/view-space radius [S1].
    *   **Compactness:** Perform compactness-based densification every 1000 iterations [S1].

### Pseudocode

```python
def train_3dgs(images, poses, sfm_points, num_iterations=30000):
    # 1. Initialization
    gaussians = []
    for p in sfm_points:
        g = Gaussian()
        g.mu = p.position
        g.alpha = 0.1
        g.scale = compute_initial_scale(p, sfm_points, poses) # Based on e'_scene
        g.rot = IdentityQuaternion()
        g.sh_coeffs = compute_initial_sh(p, images, poses)
        gaussians.append(g)
        
    optimizer = Adam(gaussians.parameters(), lr=1e-3)
    
    # 2. Training Loop
    for i in range(num_iterations):
        # Random view selection
        idx = random.randint(0, len(images) - 1)
        target_img = images[idx]
        cam_pose = poses[idx]
        
        # Rasterization
        rendered_img, render_info = rasterize(gaussians, cam_pose)
        
        # Loss computation
        l1_loss = l1_loss(rendered_img, target_img)
        ssim_loss = ssim_loss(rendered_img, target_img)
        loss = 0.8 * l1_loss + 0.2 * ssim_loss
        
        # Backpropagation
        loss.backward()
        
        # Optimizer step
        optimizer.step()
        optimizer.zero_grad()
        
        # Periodic Densification and Pruning
        if i % 100 == 0:
            prune_gaussians(gaussians, alpha_min=0.05)
            
        if i % 500 == 0:
            densify_gaussians(gaussians, grad_threshold=0.02)
            
        if i % 1000 == 0:
            compactness_densify(gaussians)
            
    return gaussians

def compute_initial_scale(points, sfm_points, poses):
    # Corrected scene extent calculation [S4]
    avg_cam = mean([p.position for p in poses])
    e_scene = mean([norm(avg_cam - p.position) for p in sfm_points])
    # Scale proportional to scene extent [G]
    return e_scene * 0.1 

def prune_gaussians(gaussians, alpha_min=0.05):
    to_remove = []
    for g in gaussians:
        if g.alpha < alpha_min:
            to_remove.append(g)
        elif is_too_large(g):
            to_remove.append(g)
    gaussians = [g for g in gaussians if g not in to_remove]

def densify_gaussians(gaussians, grad_threshold=0.02):
    for g in gaussians:
        if norm(g.grad_mu) > grad_threshold:
            split_gaussian(g)
        elif g.alpha > 0.8 and norm(g.grad_mu) < 0.01:
            clone_gaussian(g)
```

### Corrected Scene-Extent
A method to calculate scene extent based on the SfM point cloud rather than camera positions to avoid bias from camera distribution (e.g., orbiting a small object in a large environment) [S4]. The default 3DGS scene extent is proportional to the distance of the furthest camera from the average camera position, causing bias if cameras are clustered, leading to incorrect splitting/pruning [S4]. The corrected extent is $e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2$, where $\bar{C}$ is the average camera position and $p_i$ are SfM points [S4].

### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ to selectively enlarge covariances, creating pixel-wise variable blur kernels that match spatially varying scene blurriness [S5]. It predicts $\delta s_j$ for each Gaussian using a compact MLP, adds the offset to the base scale, and uses the transformed covariance as a blur kernel during rasterization [S5]. If $\delta s_j$ is constant, it degrades to uniform Gaussian blur [S5].

### Denoise-GS
A self-supervised denoising method for sparse-view 3DGS that combines unsupervised image denoising with differentiable 3DGS [S6]. Round 1: Train a UNet using Noise2Void (N2V) for denoising, process denoised images through InstantSplat to initialize/train 3DGS, and filter rendered results [S6]. Round 2: Fine-tune the UNet with a composite loss and render again [S6]. Unlike supervised methods, it requires no paired clean data, and unlike N2N, it requires no paired noisy images, making it suitable for sparse viewpoints [S6].

### Multi-Scale Constraint
A technique using position-aware point adaptive control to apply different scales to Gaussians based on viewer distance, improving rendering of distant objects [S7]. It uses a scaling factor $\gamma(\mu)$ based on distance from camera center $c$ and scene radius $r$: $\gamma(\mu) = 1$ if $\|\mu - c\|^2 < 2r$, else $\|\mu - c\|^2 / r - 1$ [S7]. Cloning occurs if $\max(s) < g \cdot \gamma(\mu)$, splitting if $\max(s) \ge g \cdot \gamma(\mu)$, and elimination if $\max(s) > b \cdot \gamma(\mu)$ [S7].

### LS-Gaussian Viewpoint Transformation
An algorithm that leverages inter-frame continuity for efficient sparse rendering by transforming the viewpoint between consecutive frames, rather than rendering each frame separately [S8]. It operates at the tile/Gaussian level to enable sparse rendering, unlike naive pixel warping [S8]. Rendering quality degrades as the number of consecutively transformed frames increases due to interpolation error accumulation [S8]. Used in LS-Gaussian to fully render only one frame in every 6 frames [S8].

### 3D Gaussian Splatting Training Loop
Per-image error compares one render against one photo; scene-wide error is the loss averaged across all training views [S9, unofficial]. The loop: 1. Pick one input photo randomly. 2. Render from known pose. 3. Compute error (L1 + D-SSIM, $\lambda \approx 0.2$). 4. Compute gradients and update Gaussians. 5. Repeat for ~30,000 iterations [S9, unofficial]. Unlike random search, it uses gradient descent to compute the actual downhill direction for the error surface [S9, unofficial].

### Camera Localisation for Convergence Basin
Localizes camera pose by minimizing photometric error against the ground-truth color image of the target view, fixing $G_{init}$ during optimization [S10, unofficial]. Initialize $T_{CW}$ at a test view's position and optimize for 1000 iterations. Success if estimated pose converges to within 1cm of the target view [S10, unofficial]. The pose is found by $\mathbf{T}_{CW}^{est} = \underset{\mathbf{T}_{CW}}{\arg \min} \left\| I(\mathcal{G}_{init}, \mathbf{T}_{CW}) - \bar{I}_{target} \right\|_1$ [S10, unofficial].

### DiffGS Framework
Applies an optimization process during Gaussian extraction to optimize Gaussians to exact locations [S11]. Uses a truncation function $\lambda$ when modeling GauPF and a projection function $\tau$ (e.g., $\tau(x) = e^{-x}$ or linear) [S11]. With 50K Gaussians: PSNR 28.61, SSIM 0.9787, LPIPS 0.0251; with 100K: PSNR 30.35, SSIM 0.9838, LPIPS 0.0151; with 350K: PSNR 34.01, SSIM 0.9879, LPIPS 0.0149 [S11].

### Opacity Offset Table for DSA
Constructs an opacity offset table to model changes in digital subtraction angiography [S12].

### Resolution Guided Primitive Scheduler
Updates the primitive budget $P_{fin}^{(i)} = \max(P_{fin}^{(i-1)}, \gamma \cdot P_{fin}^{(i-1)} + \eta \cdot P_{add})$, where $P_{add}$ is the number of primitives densified in step $i$, and $P_{fin}^{(0)} = 5 \cdot P_{init}$ [S13]. The power factor starts at 2 and decreases to 1 to suppress early growth and encourage mid-stage growth. $\gamma = 0.98$, $\eta = 1$ [S13]. Too much growth at the end results in poor convergence, mitigated by the concave-up scheduling function [S13].

### Conditional Splat Approximation
Approximates the influence range of a 3D Gaussian on a slice by using a 2D ellipse splat scaled by the marginal factor, closely matching true iso-probability contours [S14, unofficial]. Qualitative validation shows the conditional splat (dashed red) closely overlaps with true 3D Gaussian contours (solid blue) [S14, unofficial].

### Deformation-Aware Pruning
Identifies and removes redundant Gaussians by gauging their impact on deformation, distinguishing between stable and deformed Gaussians [S15].

### GEMM-GS
An acceleration approach utilizing Tensor Cores by reformulating the blending process into a GEMM-compatible form [S16]. Transforms blending to GEMM-style, develops a CUDA kernel with a three-stage double-buffered pipeline and asynchronous memory copy [S16]. Tile size 16x16 pixels, thread block size 256 threads [S16]. Achieves 1.42× speedup over vanilla 3DGS and an additional 1.47× speedup when combined with existing acceleration methods [S16].

## Operating characteristics
*   **Time Complexity:** The training loop is dominated by the rasterization and sorting steps, which are $O(N \cdot T)$ per iteration, where $N$ is the number of Gaussians and $T$ is the number of tiles [S16]. The total time is proportional to the number of iterations (typically 30,000) [S9, unofficial].
*   **Memory Complexity:** Memory usage scales linearly with the number of Gaussians $N$. Each Gaussian stores position (12 bytes), scale (12 bytes), rotation (16 bytes), opacity (4 bytes), and SH coefficients (108 bytes for D=1) [G]. Total memory $\approx N \times 152$ bytes.
*   **Measured Performance:** GEMM-GS achieves an average 1.42× speedup over vanilla 3DGS implementation [S16]. LS-Gaussian achieves 5.41× speedup over edge GPU baseline on Jetson AGX Orin [S8].
*   **Strengths:** High rendering quality, real-time rendering speeds, explicit representation allows for easy editing and compression.
*   **Limitations:** High memory consumption for large scenes, sensitive to initialization and hyperparameters (e.g., scene extent, gradient thresholds), prone to artifacts in sparse-view or noisy scenarios without additional denoising [S6].
*   **When to use:** When high-fidelity novel view synthesis is required from a dense set of input images.
*   **When not to use:** When memory is severely constrained, or when dealing with sparse views without additional denoising/regularization [S6].

## Background
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1]. It represents scenes as a set of 3D Gaussians, optimizing their parameters via differentiable rasterization. The method builds on the principles of differentiable volume rendering [6233-optimization-and-parallelization] but uses explicit primitives instead of neural fields. It has since been extended to handle dynamic scenes [15898-spacetimegaussians-training-pipeline.md], semantic features [15902-feature-3d-gaussian-splatting.md], and large-scale environments [14454-tragraph-gs.md].
