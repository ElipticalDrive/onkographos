# eval3d

Also called: ray-based 3D gaussian evaluation

## Overview
eval3d is a rendering evaluation method for 3D Gaussian particles that computes the Gaussian response along the pixel's view ray rather than using the projected 2D footprint [S1, unofficial]. It solves the visual degradation (washed-out, hazy appearance) that occurs when scenes trained with the 3D Gaussian Unscented Transform (3DGUT) are rendered using standard EWA splatting [S1, unofficial]. It is distinct from its parent [3D Gaussian Unscented Transform (3DGUT)](9154-3d-gaussian-unscented-transform-3dgut.md) in that it implements the specific ray-based evaluation metric required by 3DGUT-trained data, whereas 3DGUT provides the training and projection framework [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of 3D Gaussians (position, covariance, opacity, color) and camera parameters.
*   **Output:** A rendered image where Gaussian contributions are evaluated via ray intersection/response.

**Data Structures:**
*   **Per-splat cache:** An extra texture storing ray terms.
    *   **Size:** 16 bytes per splat [S1, unofficial].
    *   **Content:** Specific ray terms required for the fragment shader evaluation (exact fields not specified in sources) [S1, unofficial].

**Steps:**
1.  **Projector Stage:** For each Gaussian splat, compute the necessary ray terms and write them to the per-splat cache texture (16 bytes per splat) [S1, unofficial].
2.  **Fragment Stage:**
    *   Interpolate the cached ray terms linearly across the splat's quad [S1, unofficial].
    *   Evaluate the Gaussian response exactly using the interpolated terms and the pixel's view ray [S1, unofficial].
3.  **Fallbacks and Exceptions:**
    *   **Picking/Selection:** Continue to use the existing EWA footprint for picking, rings, and selection operations, not the eval3d evaluation [S1, unofficial].
    *   **Orthographic Views:** Fall back to standard EWA evaluation [S1, unofficial].

**Parameters:**
*   **Toggle:** A per-layer "3D Evaluation" toggle in the UI [S1, unofficial].
    *   **Default:** Off [S1, unofficial].
    *   **Persistence:** Saved in the document [S1, unofficial].
    *   **Scope:** Per-layer, as the training method depends on how the scene was trained and PLY files do not mark 3DGUT scenes [S1, unofficial].

**Pitfalls:**
*   **Incomplete Projection:** The implementation of eval3d does not include the full Unscented Transform (UT) projection logic from 3DGUT [S1, unofficial].
*   **Quad Bounds:** For undistorted pinhole views, the UT only affects the quad bounds, which still originate from the EWA footprint [S1, unofficial].

**Pseudocode:**
```python
# Pseudocode for eval3d rendering pipeline
# Note: Specific 16-byte cache layout is not defined in sources [S1, unofficial]

def render_eval3d(gaussians, camera, layer_config):
    """
    Renders 3D Gaussians using ray-based evaluation if enabled.
    """
    if not layer_config.eval3d_enabled:
        # Fallback to standard EWA splatting
        return render_ewa(gaussians, camera)

    # Step 1: Projector writes ray terms to cache
    # Each splat gets 16 bytes in the cache texture
    cache_texture = allocate_cache(len(gaussians), 16)
    for i, gaussian in enumerate(gaussians):
        # Compute ray terms specific to the view ray and gaussian
        # Exact formula for these 16 bytes is not provided in sources [S1, unofficial]
        ray_terms = compute_ray_terms(gaussian, camera)
        cache_texture.write(i, ray_terms)

    # Step 2: Fragment shader evaluation
    # For each pixel covered by a splat's quad:
    # 1. Interpolate ray terms linearly across the quad
    # 2. Evaluate Gaussian response exactly using view ray
    for pixel in pixels_covered_by_quads:
        interpolated_terms = interpolate_linearly(cache_texture, pixel.uv)
        response = evaluate_ray_response(interpolated_terms, camera.view_ray_at(pixel))
        accumulate_color(pixel, response)

    return image
```

## Subtopics

### 3D Gaussian Unscented Transform (3DGUT)
The parent method that defines the training and projection framework using sigma points. Choose 3DGUT when rendering scenes trained with UT to handle nonlinear camera projections. [Link](9154-3d-gaussian-unscented-transform-3dgut.md)

## Operating characteristics
*   **Performance:** On a 6M-gaussian 3DGUT-trained scene at 960x540 resolution, eval3d achieved a PSNR of 38.2 dB and a mean absolute error of 1.1 (0-255) compared to gsplat's 3DGUT rasterizer [S1, unofficial].
*   **Comparison:** Stock EWA (toggle off) on the same scene achieved 33.0 dB PSNR and 3.0 mean absolute error [S1, unofficial].
*   **Strengths:** Correctly renders scenes trained with 3DGUT, avoiding the washed-out/hazy artifacts of EWA [S1, unofficial].
*   **Limitations:** Does not implement the full UT projection; relies on EWA footprint for quad bounds in undistorted pinhole views [S1, unofficial]. Requires manual toggle per layer as PLY files do not indicate training method [S1, unofficial].

## Background
eval3d was proposed as a contribution to the SuperSplat viewer to support scenes trained with NVIDIA's 3dgrut or gsplat with `with_ut`/`with_eval3d` [S1, unofficial]. The method addresses the discrepancy between the training objective (ray-based evaluation) and the default rendering engine (EWA splatting) [S1, unofficial]. The implementation was developed by husuninder and proposed via a GitHub issue in October 2026 [S1, unofficial].
