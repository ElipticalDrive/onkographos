# 3D Gaussian Splatting with Feature Vectors

Also called: Feature-3DGS, LangSplat, Semantic 3DGS

## Overview
This method extends standard 3D Gaussian Splatting by attaching a high-dimensional feature vector $\mathbf{f}_i \in \mathbb{R}^D$ to each Gaussian primitive $i$, enabling the rendering of semantic or language embeddings alongside color. It solves the problem of real-time open-vocabulary semantic segmentation and scene understanding by distilling 2D vision-model features into a 3D representation. Unlike sibling methods that may rely on directional views or specific pre-trained encoders like LSeg, this approach generalizes the alpha-blending accumulation to arbitrary feature spaces, allowing the resulting 2D feature map to be decoded by segmentation heads or compared against text embeddings via cosine similarity [S1, S2, unofficial].

## How it works
**Inputs:**
*   A set of $N$ 3D Gaussians, each defined by mean $\boldsymbol{\mu}_i$, covariance $\boldsymbol{\Sigma}_i$ (or rotation $\mathbf{R}_i$ and scale $\mathbf{s}_i$), opacity $\alpha_i$, and a feature vector $\mathbf{f}_i$.
*   Camera parameters (view and projection matrices).
*   Feature dimension $D$ (e.g., 512 for CLIP ViT-L/14).

**Outputs:**
*   A 2D feature map $\mathbf{F} \in \mathbb{R}^{H \times W \times D}$, where $H, W$ are image dimensions.

**Data Structures:**
*   **Gaussian Primitive:** Contains fields for position, scale, rotation, opacity, spherical harmonics coefficients (for color), and the feature vector $\mathbf{f}_i$. The feature vector is stored as a dense array of size $D$.
*   **Rendered Feature Map:** Accumulated in a buffer of size $H \times W \times D$.

**Algorithm:**
The rendering process projects each 3D Gaussian to 2D, computes its screen-space covariance, and sorts them front-to-back. For each pixel $p$, the feature value is accumulated using differentiable alpha-blending.

1.  **Projection:** For each Gaussian $i$, compute the 2D mean $\mathbf{t}_i$ and covariance $\mathbf{T}_i$ in screen space using the Jacobian of the projection transformation [S1, unofficial].
2.  **Sorting:** Sort all Gaussians overlapping with the view frustum by their depth $z_i$ relative to the camera, resulting in an ordered list $\mathcal{O}_p$ for each pixel $p$.
3.  **Rasterization:** For each pixel $p$ in the image:
    *   Initialize accumulated transmittance $T = 1.0$ and accumulated feature $\mathbf{F}(p) = \mathbf{0}$.
    *   Iterate through Gaussians $i \in \mathcal{O}_p$ in front-to-back order:
        *   Compute the 2D Gaussian density at pixel $p$:
            $$
            \sigma_i(p) = \exp\left(-\frac{1}{2} (\mathbf{x}_p - \mathbf{t}_i)^T \mathbf{T}_i^{-1} (\mathbf{x}_p - \mathbf{t}_i)\right)
            $$
            where $\mathbf{x}_p$ is the pixel coordinate.
        *   Compute the alpha weight:
            $$
            \alpha_i(p) = \min(1, \sigma_i(p) \cdot \alpha_i)
            $$
        *   Update the accumulated feature and transmittance:
            $$
            \mathbf{F}(p) \leftarrow \mathbf{F}(p) + \mathbf{f}_i \cdot \alpha_i(p) \cdot T
            $$
            $$
            T \leftarrow T \cdot (1 - \alpha_i(p))
            $$
        *   If $T < \epsilon$ (e.g., $10^{-5}$), break the loop for this pixel [G].
4.  **Post-processing:** The resulting $\mathbf{F}(p)$ is a weighted average of the feature vectors, normalized by the total alpha if necessary for downstream tasks [G].

**Pseudocode:**
```python
def render_feature_map(gaussians, camera, image_height, image_width, feature_dim):
    """
    Renders a 2D feature map from 3D Gaussians.
    
    Args:
        gaussians: List of Gaussian objects with attributes:
                   - mean: (3,)
                   - scale: (3,)
                   - rotation: (4,) quaternion
                   - opacity: (1,)
                   - features: (feature_dim,)
        camera: Camera object with view and projection matrices.
        image_height: int
        image_width: int
        feature_dim: int
        
    Returns:
        feature_map: (image_height, image_width, feature_dim)
    """
    feature_map = torch.zeros((image_height, image_width, feature_dim), device=gaussians[0].features.device)
    
    # 1. Project Gaussians to 2D
    # This step computes screen-space means and covariances for all Gaussians
    # that overlap with the view frustum.
    projected_gaussians = project_gaussians(gaussians, camera)
    
    # 2. Sort Gaussians by depth for each pixel
    # In practice, this is often done via a tile-based approach or sorting
    # the entire list by depth if N is manageable, or using a depth buffer.
    # Here we assume a sorted list per pixel is available or computed.
    # For simplicity, we assume a global sort by depth z, which is an approximation
    # but common in rasterizers where depth sorting is handled per-tile.
    sorted_gaussians = sorted(projected_gaussians, key=lambda g: g.depth)
    
    # 3. Rasterize
    for pixel_y in range(image_height):
        for pixel_x in range(image_width):
            accumulated_feature = torch.zeros(feature_dim, device=gaussians[0].features.device)
            transmittance = 1.0
            
            for gaussian in sorted_gaussians:
                # Check if Gaussian overlaps with this pixel
                if not gaussian.overlaps(pixel_x, pixel_y):
                    continue
                
                # Compute 2D Gaussian value at pixel
                # delta = [pixel_x - gaussian.mean_x, pixel_y - gaussian.mean_y]
                # sigma = exp(-0.5 * delta.T @ gaussian.cov_inv @ delta)
                sigma = compute_2d_gaussian_value(gaussian, pixel_x, pixel_y)
                
                alpha = min(1.0, sigma * gaussian.opacity)
                
                if alpha < 1e-5:
                    continue
                
                # Accumulate feature
                accumulated_feature += gaussian.features * alpha * transmittance
                transmittance *= (1.0 - alpha)
                
                if transmittance < 1e-5:
                    break
            
            feature_map[pixel_y, pixel_x] = accumulated_feature
            
    return feature_map
```

**Parameters:**
*   **Feature Dimension $D$:** Typically 512 (CLIP ViT-L/14) or 768 (CLIP ViT-B/16). Not given in the sources for other dimensions.
*   **Threshold $\epsilon$:** $10^{-5}$ for transmittance cutoff [G].

**Edge Cases and Pitfalls:**
*   **Precision:** Accumulating high-dimensional vectors can lead to precision issues if not handled carefully. Using float32 is standard.
*   **Boundaries:** Gaussians partially outside the image frame must be clipped or ignored to avoid out-of-bounds memory access.
*   **Degenerate Input:** If a Gaussian has zero opacity or zero scale, it should be skipped during rasterization.

## Subtopics

### Scale-Aware Semantic Feature Gating
A mechanism to modulate rendered semantic features based on scale, using learned or fixed gate vectors derived from sampled scales [S2, unofficial]. It maps the distribution of sampled scales to a Gaussian distribution using `self.q_trans(sampled_scales)`. If `scale_aware_dim <= 0` or `scale_aware_dim >= 32`, gates are computed by passing sampled scales through `self.scale_gate`: `gates = self.scale_gate(sampled_scales.unsqueeze(-1))`. Otherwise, scales are discretized to integers: `int_sampled_scales = ((1 - sampled_scales.squeeze()) * scale_aware_dim).long()`, and pre-computed gates are looked up: `gates = self.fixed_scale_gate[int_sampled_scales].detach()`. The rendered features are repeated for each sampled scale: `feature_with_scale = rendered_features.unsqueeze(0).repeat([sampled_scales.shape[0], 1, 1, 1])`, and multiplied by the gate vectors: `feature_with_scale = feature_with_scale * gates.unsqueeze(-1).unsqueeze(-1)` [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot H \cdot W)$ in the worst case if every Gaussian overlaps every pixel, but typically $O(N)$ with efficient rasterization (tile-based) where $N$ is the number of Gaussians and $H \cdot W$ is the image resolution. The feature accumulation adds a factor of $D$ to the memory bandwidth requirement.
*   **Memory Complexity:** $O(N \cdot D)$ to store the feature vectors for all Gaussians, plus $O(H \cdot W \cdot D)$ for the output feature map.
*   **Performance:** Real-time performance is achievable on modern GPUs due to the efficiency of the Gaussian rasterizer. The feature dimension $D$ significantly impacts memory bandwidth.
*   **Strengths:** Enables open-vocabulary segmentation and language-guided editing without retraining the 3DGS representation.
*   **Limitations:** Requires a pre-trained vision-language model (e.g., CLIP) for feature extraction. The quality of the semantic map depends on the alignment between 2D features and 3D geometry.

## Background
The method was pioneered by Feature-3DGS [102] and LangSplat [103], which demonstrated that the speed of the 3DGS rasterizer makes it an ideal platform for distilling 2D vision-model features into a 3D representation [S1, unofficial]. Language Embedded 3D Gaussians [104] expanded this to full scene understanding, encoding object-level embeddings for phrase grounding. Subsequent works like SplatTalk [105] and 3D Vision-Language GS [106] further extended these capabilities [S1, unofficial].
