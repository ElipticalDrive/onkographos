# Mipmap-GS

Also called: Mipmap-Gaussian Splatting

## Overview
Mipmap-GS is a test-time adaptation method that deforms pre-trained 3D Gaussians into scale-adaptive primitives to eliminate aliasing artifacts (zoom-in spikes and zoom-out thickness) caused by fixed Gaussian distributions at varying zoom factors [S1]. Unlike methods that apply post-processing filters or hierarchical level-of-detail selection, Mipmap-GS self-adjusts primitive properties and distribution by optimizing against scale-specific mipmap-like pseudo ground-truth generated on novel views [S1].

## How it works
**Inputs and Outputs**
*   **Input:** A set of single-scale trained base 3D Gaussians $G = \{G_k\}_{k=1}^K$, where each Gaussian $G_k$ is defined by position, covariance (shape/size), opacity, and spherical harmonics coefficients (color) [S1]. A target zoom factor $N$ [S1].
*   **Output:** A set of optimized, scale-adaptive Gaussians $G^{opt} = \{G^{opt}_k\}_{k=1}^K$ [S1].

**Data Structures**
The data structure for a Gaussian $G_k$ remains identical to the standard 3D Gaussian Splatting representation [S1]. It consists of:
*   Position: $\mathbf{\mu}_k \in \mathbb{R}^3$
*   Covariance: $\mathbf{\Sigma}_k$ (or its rotation/scale decomposition)
*   Opacity: $\alpha_k \in [0, 1]$
*   Color: Spherical Harmonics coefficients $\mathbf{c}_k$

**Algorithm Steps**
The method operates as a plug-in module during inference. The optimization loop proceeds as follows [S1]:

1.  **Initialize:** Set current Gaussians $G^{(0)} = G$ (the base Gaussians) [S1].
2.  **Iterate:** For iteration $i$ from $0$ to $S$ (where $S=1000$) [S1]:
    a.  **Select View:** Randomly select a viewpoint $v_j$ from the set of novel views $V$ [S1].
    b.  **Render Base:** Render the current Gaussians $G^{(i)}$ at the basic scale ($\times 1$) to produce the base image $\hat{x}_j$ [S1].
    c.  **Construct Pseudo-GT:** Apply the mipmap resizing function $r(\cdot)$ to $\hat{x}_j$ to generate the scale-specific pseudo ground-truth $r(\hat{x}_j)$ [S1].
        *   For **zoom-in** (upsampling): Use a super-resolution method, such as SwinIR, to upsample $\hat{x}_j$ by a factor of $N$ [S1].
        *   For **zoom-out** (downsampling): Use bilinear interpolation to downsample $\hat{x}_j$ by a factor of $1/N$ [S1].
    d.  **Render Optimized:** Render the current Gaussians $G^{(i)}$ at the *new* target scale (effectively rendering at the resolution of $r(\hat{x}_j)$) to produce the image $x_j$ [S1].
    e.  **Compute Loss:** Calculate the scale-aware guidance loss $L(x_j, r(\hat{x}_j))$ [S1].
    f.  **Update:** Update the Gaussians using gradient descent:
        $$ G^{(i+1)} = G^{(i)} - \beta \nabla L(x_j, r(\hat{x}_j)) $$
        where $\beta$ is the learning rate [S1].
    g.  **Pruning:** If $i \pmod{100} == 0$, perform densification or pruning to maintain compactness [S1].
3.  **Return:** The final optimized Gaussians $G^{opt} = G^{(S+1)}$ [S1].

**Formulas**
The core optimization objective minimizes the L2 loss between the rendered image at the target scale and the pseudo ground-truth [S1]:

$$ L(x, r(\hat{x})) = \| x - r(\hat{x}) \|_2^2 $$

where:
*   $x$ is the rendered image from the deformed Gaussians at the target scale.
*   $r(\hat{x})$ is the mipmap-like pseudo ground-truth derived from the base rendering $\hat{x}$ [S1].

The update rule for the Gaussian parameters is [S1]:

$$ G^{opt} = G - \beta \nabla L(x, r(\hat{x})) $$

**Parameters**
*   **Optimization Iterations ($S$):** 1,000 iterations [S1].
*   **Zoom Factor ($N$):** An integer scaling factor. For zoom-in, the image is upsampled by $\times N$. For zoom-out, it is downsampled by $\times 1/N$ [S1].
*   **Learning Rate ($\beta$):** Not explicitly specified in the source, but standard 3DGS learning rates are implied [S1].
*   **Resizing Function ($r$):**
    *   Zoom-in: SwinIR (super-resolution) [S1].
    *   Zoom-out: Bilinear interpolation [S1].

**Edge Cases and Pitfalls**
*   **Zoom-in Spikes:** Caused by varying shrinkage bias during accumulation when sampling rates change. The fixed Gaussian field samples signals differently at higher resolutions, leading to confusion during accumulation [S1].
*   **Zoom-out Thickness:** Caused by constant dilation. The 2D dilation operation in standard 3DGS amplifies tiny Gaussians to ensure coverage. At zoom-out, this constant dilation leads to excessively wide coverage and thick structures, as Gaussians that should not contribute to a pixel are included due to inherited dilation [S1].
*   **Precision:** The method relies on the accuracy of the super-resolution model (SwinIR) for zoom-in. Degradation in the pseudo-GT quality directly impacts the optimization target [S1].

**Pseudocode**

```python
def mipmap_gs_optimize(base_gaussians, viewpoints, zoom_factor, iterations=1000, learning_rate=0.01):
    """
    Deforms base 3D Gaussians to be adaptive for a specific zoom scale.
    
    Args:
        base_gaussians: List of Gaussian primitives (position, cov, opacity, SH).
        viewpoints: List of camera poses for novel view synthesis.
        zoom_factor: Integer N. >1 for zoom-in, <1 for zoom-out (e.g., 0.5).
        iterations: Number of optimization steps (default 1000).
        learning_rate: Step size for gradient descent.
        
    Returns:
        optimized_gaussians: Deformed Gaussian primitives.
    """
    current_gaussians = copy.deepcopy(base_gaussians)
    
    # Determine resizing function based on zoom direction
    if zoom_factor > 1:
        # Zoom-in: Upsample using super-resolution
        resize_func = swinir_upsample # SwinIR model
        scale = zoom_factor
    else:
        # Zoom-out: Downsample using bilinear interpolation
        resize_func = bilinear_downsample
        scale = 1.0 / zoom_factor # Factor to downsample by
        
    for i in range(iterations):
        # 1. Select random viewpoint
        view = random.choice(viewpoints)
        
        # 2. Render base Gaussians at basic scale (x1)
        # This produces the base image without scale adaptation
        image_base = render_gaussians(current_gaussians, view, resolution=original_resolution)
        
        # 3. Construct mipmap-like pseudo-GT
        # Apply resizing function to create target scale reference
        pseudo_gt = resize_func(image_base, scale_factor=scale)
        
        # 4. Render current (deforming) Gaussians at the new target scale
        # The renderer must account for the new pixel footprint/resolution
        image_target = render_gaussians(current_gaussians, view, resolution=target_resolution)
        
        # 5. Compute L2 Loss
        loss = l2_loss(image_target, pseudo_gt)
        
        # 6. Optimize Gaussians
        gradients = compute_gradients(loss, current_gaussians)
        current_gaussians = update_gaussians(current_gaussians, gradients, learning_rate)
        
        # 7. Active Pruning every 100 iterations
        if i % 100 == 0:
            current_gaussians = prune_and_densify(current_gaussians)
            
    return current_gaussians
```

## Operating characteristics
*   **Time Complexity:** The method adds an optimization phase to the inference pipeline. It requires 1,000 iterations of rendering and gradient updates per view adaptation [S1]. This is significantly faster than training from scratch, requiring only 3% of the iterations of full training [S1].
*   **Memory Complexity:** Memory usage is comparable to standard 3DGS, as it does not store hierarchical structures or multiple LODs. Active pruning during optimization can reduce the final Gaussian count, particularly for zoom-out scenarios [S1].
*   **Performance:** On the NeRF Synthetic dataset, Mipmap-GS outperforms standard 3DGS by an average of 9.25 dB PSNR for zoom-in and 10.40 dB PSNR for zoom-out [S1].
    *   At $\times 1/2$ zoom-out on NeRF Synthetic: SSIM 0.971, PSNR 32.71, LPIPS 0.026 (vs. 3DGS: 0.951, 27.14, 0.031) [S1].
    *   At $\times 1/2$ zoom-out on Mip-NeRF 360: SSIM 0.854, PSNR 28.57 (vs. 3DGS: 0.774, 26.66) [S1].
*   **Strengths:**
    *   Plug-in module compatible with any 3DGS model (e.g., Scaffold-GS) [S1].
    *   Preserves finer details compared to filtering methods (like Mip-Splatting) by deforming the Gaussians themselves rather than suppressing high-frequency components [S1].
    *   Solves aliasing essentially by informing the new sampling rate to the Gaussians [S1].
*   **Limitations:**
    *   Requires test-time optimization, adding latency before rendering.
    *   Performance depends on the quality of the super-resolution model (SwinIR) for zoom-in [S1].
    *   Not given in the sources: Specific hardware acceleration details for the SwinIR component or the gradient computation over the Gaussian parameters.

## Background
Mipmap-GS was proposed to address the severe aliasing and blurriness in 3D Gaussian Splatting when zooming in or out [S1]. Standard 3DGS suffers from mismatched pixel coverage due to constant dilation and fixed Gaussian distributions [S1]. Previous methods like Mip-Splatting used heuristic 2D/3D smoothing filters, which suppress high-frequency components [S1]. Octree-GS used hierarchical Level-of-Detail (LoD), but selection was sensitive to hyper-parameters [S1]. Mipmap-GS introduces a unified optimization method that makes Gaussians adaptive for arbitrary scales by self-adjusting primitive properties and distribution using scale-specific mipmap-like pseudo ground-truth [S1]. It is described as a plug-in module applicable to any 3DGS models [S1].
