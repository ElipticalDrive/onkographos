# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, GSGEN Implementation Details, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific hyperparameters, data structures, and optimization strategies required to implement the 3D Gaussian Splatting (3DGS) training and rendering pipeline. It addresses the practical challenges of differentiable rasterization, including half-precision stability, adaptive density control, and scene extent calculation. The method sets itself apart from theoretical descriptions by providing concrete thresholds (e.g., opacity limits, gradient thresholds) and implementation-specific configurations (e.g., CUDA kernel optimizations, library choices) necessary for a functional, high-fidelity reconstruction.

## How it works

### Inputs and Outputs
**Inputs:**
*   Sparse Structure-from-Motion (SfM) point cloud (positions, colors).
*   Camera poses (extrinsics $C_i$) and intrinsics (focal length, principal point).
*   Training images (RGB).
*   Hyperparameters: Learning rate, densification intervals, thresholds ($T_{pos}$, $\alpha_{min}$), loss weights.

**Outputs:**
*   A set of 3D Gaussians $\mathcal{G} = \{\mu_j, \Sigma_j, R_j, s_j, q_j, \sigma_j, c_j\}$, where $\mu$ is position, $\Sigma$ is covariance, $R$ is rotation, $s$ is scale, $q$ is quaternion, $\sigma$ is opacity, and $c$ is spherical harmonic (SH) coefficients.
*   Rendered novel view images.

### Data Structures
The Gaussian representation is stored in flat arrays for GPU access. Each Gaussian $j$ contains:
*   **Position:** $\mu_j \in \mathbb{R}^3$ (float32).
*   **Rotation:** $q_j \in \mathbb{R}^4$ (unit quaternion, float32).
*   **Scale:** $s_j \in \mathbb{R}^3$ (log-space scale factors, float32).
*   **Opacity:** $\sigma_j \in \mathbb{R}$ (sigmoid output, float32).
*   **Color:** $c_j \in \mathbb{R}^{3 \times (D+1)^2}$, where $D$ is the SH degree. For $D=1$, this is $3 \times 4 = 12$ floats.
*   **Covariance:** $\Sigma_j$ is derived from $s_j$ and $R_j$ as $\Sigma = R S S^T R^T$, where $S = \text{diag}(s)$.

**Optimization State:**
*   **Optimizer:** Adam [S3].
*   **Learning Rate:** $1 \times 10^{-3}$ for position, rotation, scale, opacity; $1.6 \times 10^{-3}$ for SH coefficients [S3].
*   **Gradient Accumulation:** Gradients are accumulated over iterations before optimizer step [6233-optimization-and-parallelization].

### Numbered Steps

1.  **Initialization:**
    *   Initialize Gaussians from the SfM point cloud.
    *   Set initial opacity $\sigma$ to a low value (e.g., 0.1) to allow densification.
    *   Set initial scale based on the average distance to nearest neighbors in the SfM cloud.
    *   [G] Initialize SH coefficients to zero for $D>0$ to ensure neutral initial color.

2.  **Differentiable Rasterization (Forward Pass):**
    *   For each training image, project 3D Gaussians to 2D screen space.
    *   Compute 2D covariance $\Sigma_{2D}$ using the Jacobian of the projection transformation [6233-optimization-and-parallelization].
    *   Sort Gaussians by depth for each tile/pixel.
    *   Alpha-blend colors: $C = \sum_i c_i \alpha_i \prod_{j<i} (1-\alpha_j)$.
    *   [S2] Use half-precision (FP16) memory fetches for feature vectors during rasterization to reduce register pressure.
    *   [S2] Apply an automatic scaling factor to loss values to improve half-precision training stability.

3.  **Loss Computation:**
    *   Compute photometric loss $\mathcal{L}$ between rendered image $\hat{I}$ and ground truth $I$.
    *   Common loss: $\mathcal{L} = \lambda_{\text{L1}} \mathcal{L}_{\text{L1}} + \lambda_{\text{SSIM}} \mathcal{L}_{\text{SSIM}}$ [S13, unofficial].
    *   [S1] For text-to-3D generation, use SDS (Score Distillation Sampling) loss with guidance scale 100 [S1].

4.  **Backpropagation:**
    *   Compute gradients $\frac{\partial \mathcal{L}}{\partial \theta}$ for all Gaussian parameters $\theta$ [6233-optimization-and-parallelization].
    *   [S2] Implement custom CUDA kernels for forward and backward logic to ensure efficient gradient flow.

5.  **Optimizer Update:**
    *   Update Gaussian parameters using Adam optimizer [S3].

6.  **Adaptive Density Control (Densification & Pruning):**
    *   **Densification:** Every 100 iterations (standard) or 500/1000 iterations (specific variants) [S1, S3]:
        *   Compute accumulated positional gradients for each Gaussian.
        *   **Split:** If gradient > $T_{pos}$ and scale < threshold, split into two Gaussians.
        *   **Clone:** If gradient > $T_{pos}$ and scale > threshold, clone.
        *   [S1] Split Gaussians by view-space position gradient every 500 iterations with threshold $T_{pos} = 0.02$.
        *   [S1] Perform compactness-based densification every 1000 iterations.
    *   **Pruning:** Every 100-200 iterations [S1, S3]:
        *   Remove Gaussians with opacity $\sigma < \alpha_{min}$.
        *   Remove Gaussians with excessively large world-space or view-space radius.
        *   [S1] Remove Gaussians with opacity $< \alpha_{min} = 0.05$ and excessively large world-space or view-space radius every 200 iterations.

7.  **Scene Extent Correction (Optional but Recommended):**
    *   Calculate corrected scene extent $e'_{\text{scene}}$ based on SfM points rather than camera positions to avoid bias [S4].
    *   Formula: $e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2$ [S4].
    *   Where $\bar{C} = \frac{1}{N_{\text{cam}}} \sum_{i=1}^{N_{\text{cam}}} C_i$ [S4].

### Formulas

**Scene Extent (Corrected):**
$$ e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2 $$
$$ \bar{C} = \frac{1}{N_{\text{cam}}} \sum_{i=1}^{N_{\text{cam}}} C_i $$
[S4]

**Multi-Scale Constraint (for large scenes):**
$$ \gamma(\mu) = \begin{cases} 1 & \text{if } \|\mu - c\|^2 < 2r \\ \|\mu - c\|^2 / r - 1 & \text{if } \|\mu - c\|^2 \ge 2r \end{cases} $$
[S7]
Where $r$ is scene radius, $c$ is camera center. Cloning if $\max(s) < g \cdot \gamma(\mu)$, splitting if $\max(s) \ge g \cdot \gamma(\mu)$, elimination if $\max(s) > b \cdot \gamma(\mu)$ [S7].

**Loss Function (PyGS):**
$$ \mathcal{L} = \lambda \cdot \text{MSE}(C, \hat{C}) + (1 - \lambda) \cdot \text{SSIM}(C, \hat{C}) $$
[S13, unofficial]

**Camera Localization (for SLAM):**
$$ \mathbf{T}_{CW}^{est} = \underset{\mathbf{T}_{CW}}{\arg \min} \left\| I(\mathcal{G}_{init}, \mathbf{T}_{CW}) - \bar{I}_{target} \right\|_1 $$
[S9, unofficial]

### Parameters and Typical Values
*   **$T_{pos}$ (Gradient Threshold):** 0.02 [S1].
*   **$\alpha_{min}$ (Min Opacity):** 0.05 [S1].
*   **Densification Interval:** 100 iterations [S3], 500/1000 iterations [S1].
*   **Pruning Interval:** 100-200 iterations [S1, S3].
*   **SH Degree:** 1 [S3].
*   **Optimizer:** Adam [S3].
*   **Learning Rate:** $1 \times 10^{-3}$ [S3].
*   **Guidance Scale (Text-to-3D):** 100 [S1].
*   **Volume Dimensions (Urban):** Height 12.8m, Width 32m, Length 64m; Voxel size 0.1m ($128 \times 320 \times 640$) [S3].

### Edge Cases and Pitfalls
*   **Scene Extent Bias:** Default 3DGS scene extent is proportional to the furthest camera distance. If cameras are clustered (e.g., orbiting a small object in a large environment), the extent is underestimated, leading to incorrect splitting/pruning [S4]. Use corrected extent [S4].
*   **Half-Precision Stability:** FP16 training can suffer from gradient overflow/underflow. Apply automatic loss scaling [S2].
*   **Uniform Blur:** If using Selective Defocus Blurring, predicting a constant $\delta s_j$ for all Gaussians degrades to a uniform Gaussian blur, failing to model spatially varying blurriness [S5].
*   **Accumulation Error in Sparse Rendering:** In LS-Gaussian, rendering quality degrades as the number of consecutively transformed frames increases due to interpolation error accumulation [S8].
*   **Naive Pixel Warping:** Naive pixel warping fails to reduce preprocessing/sorting costs because projected Gaussians are assigned to workloads at the tile level. LS-Gaussian operates at the tile/Gaussian level [S8].

### Pseudocode

```python
def train_3dgs(sfm_points, camera_poses, images, hyperparams):
    """
    Main training loop for 3D Gaussian Splatting.
    """
    # 1. Initialization
    gaussians = initialize_gaussians_from_sfm(sfm_points)
    optimizer = Adam(gaussians.parameters(), lr=hyperparams.lr)
    
    # 2. Correct Scene Extent (Optional but recommended)
    N_cam = len(camera_poses)
    C_avg = sum(C_i.position for C_i in camera_poses) / N_cam
    N_sfm = len(sfm_points)
    scene_extent = sum(dist(C_avg, p) for p in sfm_points) / N_sfm
    
    for iteration in range(hyperparams.max_iterations):
        # 3. Select Training Image
        image_idx = random.choice(range(len(images)))
        image = images[image_idx]
        camera_pose = camera_poses[image_idx]
        
        # 4. Forward Pass (Differentiable Rasterization)
        # Use half-precision for feature vectors [S2]
        rendered_image = rasterize(gaussians, camera_pose, hyperparams.sh_degree)
        
        # 5. Loss Computation
        loss = compute_loss(rendered_image, image, hyperparams.loss_weights)
        
        # 6. Backward Pass
        optimizer.zero_grad()
        loss.backward()
        
        # 7. Optimizer Step
        optimizer.step()
        
        # 8. Adaptive Density Control
        if iteration % hyperparams.densify_interval == 0:
            # Compute accumulated gradients
            gradients = compute_gradient_accumulation(gaussians)
            
            # Densification
            for g in gaussians:
                if gradients[g] > hyperparams.T_pos:
                    if g.scale < hyperparams.scale_threshold:
                        split_gaussian(g)
                    else:
                        clone_gaussian(g)
            
            # Compactness-based densification (if applicable) [S1]
            if iteration % 1000 == 0:
                perform_compactness_densification(gaussians)
                
        if iteration % hyperparams.prune_interval == 0:
            # Pruning
            gaussians = [g for g in gaussians 
                         if g.opacity >= hyperparams.alpha_min 
                         and g.radius < hyperparams.max_radius]
                         
    return gaussians
```

## Operating characteristics

**Time Complexity:**
*   Training: $O(N \cdot I \cdot P)$, where $N$ is number of Gaussians, $I$ is iterations, $P$ is pixels. Densification adds overhead every $K$ iterations.
*   Rendering: $O(N \cdot T)$, where $T$ is tiles. Sorting is $O(N \log N)$ per tile.

**Memory Complexity:**
*   Storage: $O(N \cdot D)$, where $D$ is attribute size (position, scale, rotation, opacity, SH). For $D=1$, 12 floats per Gaussian.
*   GPU Memory: Dominated by Gaussian attributes and optimizer state. Can exceed 1GB for real-world scenes [12927-compact-3d-gaussian-representation-c3dgs.md].

**Measured Performance:**
*   Standard 3DGS achieves real-time rendering (30-100+ FPS) on modern GPUs for scenes with $10^5-10^6$ Gaussians [6233-optimization-and-parallelization].
*   CF-Splat reduces computation time by 27.5×–378.0× compared to iterative optimization [16773-closed-form-triangle-splatting-cf-splat.md].
*   LS-Gaussian achieves 5.41× speedup over edge GPU baseline, up to 17.3× with custom accelerator [S8].

**Strengths:**
*   Real-time rendering speed.
*   High-fidelity novel view synthesis.
*   Explicit representation allows easy editing and compression.

**Limitations:**
*   High memory usage for large scenes.
*   Sensitive to initialization and hyperparameters (e.g., scene extent).
*   Struggles with transparent/refractive objects without extensions.

**When to Use:**
*   Real-time novel view synthesis.
*   Interactive 3D editing.
*   Scenes with complex geometry and appearance.

**When Not to Use:**
*   Scenes with extreme transparency/refraction (without extensions).
*   Memory-constrained environments without compression/offloading.
*   Applications requiring explicit surface meshes (without extensions).

## Background

**Origin:**
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [6233-optimization-and-parallelization]. It builds on the concept of splatting (rasterizing 3D primitives to 2D) and differentiable rendering.

**History and Development:**
*   Early work used point clouds and neural networks for view synthesis.
*   3DGS replaced neural fields with explicit Gaussian primitives, enabling faster training and rendering.
*   Subsequent variants addressed limitations: compression [12943-data-compression-and-storage-optimization.md], dynamic scenes [16342-dynamic-and-spacetime-modeling.md], inverse rendering [15764-inverse-and-internal-rendering.md], etc.

**Usage:**
*   Used in computer vision, graphics, and AR/VR for novel view synthesis, 3D editing, and scene reconstruction.
*   Integrated into libraries like `gsplat` [S3] and `tiny-cuda-nn` [S2].
