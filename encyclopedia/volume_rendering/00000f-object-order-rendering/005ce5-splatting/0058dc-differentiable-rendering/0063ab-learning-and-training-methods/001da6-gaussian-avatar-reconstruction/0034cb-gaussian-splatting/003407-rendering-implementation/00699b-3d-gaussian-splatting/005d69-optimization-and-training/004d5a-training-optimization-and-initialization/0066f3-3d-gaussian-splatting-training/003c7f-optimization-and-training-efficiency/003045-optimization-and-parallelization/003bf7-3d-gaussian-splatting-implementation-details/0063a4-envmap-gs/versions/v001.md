# EnvMap-GS

Also called: two-stage outdoor Gaussian reconstruction with background-to-environment map baking

## Overview
EnvMap-GS is a two-stage Gaussian Splatting framework designed to reconstruct outdoor "inside-out" captures where a camera moves within a restricted navigation area while looking outward at a distant environment [S1]. It explicitly separates foreground and background regions to eliminate "floaters" (large, erroneous Gaussians in the far field) caused by incorrect initialization and limited view ranges [S1]. Unlike standard 3D Gaussian Splatting, which struggles with far-field reconstruction, EnvMap-GS constrains background primitives to a spherical shell and allows the background to be baked into an environment map for faster rendering [S1].

## How it works
**Inputs:** A sequence of images or video frames captured in a restricted area; a metric monocular depth estimation model (e.g., Video Depth Anything) [S1].
**Outputs:** A set of foreground Gaussians, a set of background Gaussians, and optionally an inpainted environment map [S1].

**Data Structures:**
*   **Camera Poses:** $4 \times 4$ transformation matrices from COLMAP [S1].
*   **Sparse Point Cloud:** 3D points from Structure-from-Motion (SfM) [S1].
*   **Dense Metric Depth Maps:** Per-image depth maps from MMDE [S1].
*   **Distance-from-Center (DFC) Maps:** Image-aligned maps storing the Euclidean distance of unprojected 3D points to the scene center $O$ [S1].
*   **Gaussian Primitives:** Defined by mean $\mu$, covariance $\Sigma$ (or rotation $R$ and scale $S$), opacity $\alpha$, and spherical harmonics coefficients $c_{lm}$ [S1, G].

**Parameters:**
*   $O$: World system center, placed at the barycenter of camera positions [S1].
*   $R_i$: Inner radius threshold for foreground-background segmentation [S1].
*   $R_o$: Outer radius of the background spherical shell [S1].

**Steps:**

1.  **Pre-processing:** Run Structure-from-Motion (COLMAP) on input images to obtain camera poses and a 3D sparse point cloud [S1]. Set the world center $O$ to the barycenter of the camera positions [S1].
2.  **Depth Estimation:** Estimate dense metric depth maps for each input image using a metric monocular depth estimation (MMDE) method, such as Video Depth Anything [S1].
3.  **Distance Map Creation:** For each image, unproject every pixel's depth value into 3D space using the corresponding camera pose. Compute the Euclidean distance of each resulting 3D point to the center $O$. Store these distances in image-aligned Distance-from-Center (DFC) maps [S1].
4.  **Segmentation:** Determine the threshold $R_i$. Estimate the histogram of distances in the DFC maps with a binning interval of 10 meters. Set $R_i$ to the distance value corresponding to the first bin where the point count is less than 2.5% of the total reconstructed points [S1]. Classify points with distance $< R_i$ as foreground and points with distance $\ge R_i$ as background [S1].
5.  **Stage 1 Initialization (Background):** Create a geodesic sphere point cloud. Initialize background Gaussians within a spherical shell defined by inner radius $R_i$ and outer radius $R_o$ [S1].
6.  **Stage 1 Optimization:** Optimize the background Gaussians using a loss function combining:
    *   A background-only photometric term [S1].
    *   A shell constraint loss $L_{shell}$, constraining Gaussians to remain inside the shell $[R_i, R_o]$ [S1].
    *   A planarity loss $L_{planarity}$, aligning Gaussians with local tangential planes [S1].
7.  **Stage 1 Pruning:** Apply a modified pruning strategy that preserves large, stable Gaussians necessary for representing distant scenery [S1].
8.  **Stage 2 Initialization (Foreground):** Initialize foreground Gaussians from the filtered SfM sparse point cloud, containing only the foreground points identified in Step 4 [S1].
9.  **Stage 2 Optimization:** Add and refine foreground Gaussians using the standard 3D Gaussian Splatting rendering loss. The background set remains fixed during this stage but contributes to the final image formation [S1].
10. **Environment Map Conversion (Optional):** Render the background Gaussians to an object-free environment map. Inpaint the map to fill missing parts. This map can replace the Gaussian-based background for faster rendering [S1].

**Pseudocode:**

```python
def envmap_gs_pipeline(images, mmde_model):
    # Step 1: Pre-processing
    camera_poses, sparse_cloud = run_colmap(images)
    O = barycenter(camera_poses)
    
    # Step 2: Depth Estimation
    depth_maps = [mmde_model.predict(img) for img in images]
    
    # Step 3: Distance Map Creation
    dfc_maps = []
    for img_idx, (img, pose, depth_map) in enumerate(zip(images, camera_poses, depth_maps)):
        # Unproject depth to 3D points
        points_3d = unproject_depth(depth_map, pose)
        # Compute distance to center O
        distances = compute_distances(points_3d, O)
        dfc_maps.append(distances)
        
    # Step 4: Segmentation
    # Estimate histogram with 10m bins
    all_distances = [d for dm in dfc_maps for d in dm.flatten()]
    histogram = compute_histogram(all_distances, bin_size=10.0)
    total_points = len(all_distances)
    
    # Find first bin with count < 2.5% of total
    Ri = 0
    for bin_center, count in histogram:
        if count < 0.025 * total_points:
            Ri = bin_center
            break
            
    # Classify SfM points
    foreground_points = [p for p in sparse_cloud if distance(p, O) < Ri]
    background_points = [p for p in sparse_cloud if distance(p, p, O) >= Ri]
    
    # Step 5: Stage 1 Initialization
    # Create geodesic sphere point cloud for background initialization
    geodesic_sphere = create_geodesic_sphere(O, Ri, Ro)
    background_gaussians = initialize_gaussians(geodesic_sphere, shell_range=(Ri, Ro))
    
    # Step 6: Stage 1 Optimization
    # Optimize background Gaussians
    for epoch in range(num_epochs_stage1):
        # Render background only
        bg_image = render_gaussians(background_gaussians, camera_poses)
        # Compute losses
        photometric_loss = compute_photometric_loss(bg_image, background_images)
        shell_loss = compute_shell_constraint_loss(background_gaussians, Ri, Ro)
        planarity_loss = compute_planarity_loss(background_gaussians)
        total_loss = photometric_loss + shell_loss + planarity_loss
        # Update Gaussians via gradient descent
        background_gaussians = optimize(background_gaussians, total_loss)
        
    # Step 7: Stage 1 Pruning
    background_gaussians = prune_gaussians(background_gaussians, preserve_large=True)
    
    # Step 8: Stage 2 Initialization
    foreground_gaussians = initialize_gaussians(foreground_points)
    
    # Step 9: Stage 2 Optimization
    for epoch in range(num_epochs_stage2):
        # Render full scene (fixed background + optimized foreground)
        full_image = render_gaussians(background_gaussians + foreground_gaussians, camera_poses)
        # Standard GS loss
        loss = compute_rendering_loss(full_image, images)
        # Update only foreground Gaussians
        foreground_gaussians = optimize(foreground_gaussians, loss)
        
    # Step 10: Environment Map Conversion (Optional)
    env_map = render_gaussians(background_gaussians, spherical_camera_poses)
    env_map = inpaint(env_map)
    
    return foreground_gaussians, background_gaussians, env_map
```

**Edge Cases and Pitfalls:**
*   **Threshold Sensitivity:** While the heuristic for $R_i$ works for most scenes, it is scene-dependent. Changing $R_i$ within reasonable ranges does not significantly affect novel view synthesis metrics [S1].
*   **Metric Scale:** MMDE methods are independent of the SfM reconstruction, so global metric scale alignment is not required [S1].
*   **Floaters:** Standard GS fails in the far field due to densification choices and limited view ranges. EnvMap-GS addresses this by constraining background Gaussians to a shell [S1].

## Subtopics

### Environment Map Baking
Converting the optimized background Gaussians into a 2D environment map to accelerate rendering. This replaces the Gaussian-based background with a static texture, reducing computational load during novel view synthesis [S1].

### Geodesic Sphere Initialization
Using a geodesic sphere point cloud to initialize background Gaussians ensures uniform coverage of the spherical shell, avoiding clustering artifacts common in random initialization [S1].

## Operating characteristics
*   **Time Complexity:** Two-stage optimization increases training time compared to single-stage GS. Stage 1 optimizes background Gaussians with additional geometric losses; Stage 2 optimizes foreground Gaussians with standard loss [S1].
*   **Memory Complexity:** Requires storage for foreground and background Gaussians separately, plus DFC maps and depth maps during preprocessing [S1].
*   **Performance:** Reduces background artifacts and improves perceptual quality of novel view renderings compared to state-of-the-art baselines, specifically removing floaters in the navigation region [S1].
*   **Strengths:** Effective for outdoor "inside-out" captures; eliminates far-field floaters; enables faster rendering via environment map baking [S1].
*   **Limitations:** Requires metric depth estimation; assumes a restricted navigation area; background is constrained to a spherical shell, which may not fit all outdoor scenes perfectly [S1].

## Background
EnvMap-GS was introduced to address the challenges of reconstructing outdoor environments from "inside-out" captures, where a camera moves within a restricted area but looks outward [S1]. Standard 3D Gaussian Splatting suffers from "floaters" in the far field due to incorrect initialization and densification choices, as well as limited view ranges [S1]. The method builds on 3D Gaussian Splatting [7] and extends it with geometric constraints and a two-stage optimization process [S1]. It is particularly relevant for real-time applications requiring high-fidelity novel view synthesis of large outdoor scenes [S1].
