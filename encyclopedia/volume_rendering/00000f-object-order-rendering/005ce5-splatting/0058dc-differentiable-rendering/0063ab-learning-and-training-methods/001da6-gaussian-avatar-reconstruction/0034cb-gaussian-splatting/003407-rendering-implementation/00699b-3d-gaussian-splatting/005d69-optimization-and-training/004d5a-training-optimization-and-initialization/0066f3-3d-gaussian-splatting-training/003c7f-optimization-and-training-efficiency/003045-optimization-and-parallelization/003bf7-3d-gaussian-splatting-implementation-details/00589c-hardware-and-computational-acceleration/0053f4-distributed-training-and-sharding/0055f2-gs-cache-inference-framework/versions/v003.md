# GS-Cache Inference Framework

Also called: GS-Cache

## Overview
GS-Cache is a holistic rendering framework designed to support real-time rendering of large-scale 3D Gaussian Splatting (3DGS) models at the city level, achieving >72 FPS at binocular 2K resolution [S1, unofficial]. It addresses the computational bottleneck of the "Gaussian Derivation Stage" in structured Gaussian methods (e.g., Scaffold-GS, Octree-GS) by employing a cache-centric de-redundancy pipeline [S1, unofficial]. Unlike native 3DGS or unstructured methods, GS-Cache specifically targets structured representations where anchors derive neural Gaussians, optimizing inter-frame redundancy in parameter decoding while maintaining rasterization quality [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Camera pose sequence, structured 3DGS model (anchors and MLP weights), previous frame cache state.
*   **Output:** Rendered image frames.

**Data Structures:**
*   **Cache:** Stores derived Gaussian parameters (position, covariance, opacity, spherical harmonics coefficients) for anchors. The cache is indexed by anchor indices mapped from camera inputs.
*   **Anchor Set ($X$):** The total set of anchors requiring decoding in the current frame.
*   **Newly Decoded Anchors ($X_k'$):** The subset of anchors from the previous $k$ frames that were newly decoded (not found in cache) and are now candidates for reuse.

**Steps:**
1.  **Anchor Indexing:** Compute anchor indices from the current camera input. These indices filter which anchors need decoding and locate existing anchors in the cache [S1, unofficial].
2.  **Index Mapping:** Translate anchor indices to cache indices [S1, unofficial].
3.  **Cache Scheduling:** The cache scheduler loads necessary model parameters for the decoding stage based on filtered anchors. It updates the cache with results from previous decoding computations [S1, unofficial].
4.  **Dynamic Depth Scheduling:** Calculate the expected reuse depth using the heuristic function $H$ and the update rate [S1, unofficial]:
    $$ \text{depth} = H\left(\frac{|X_k'|}{|X|}\right) $$
    where $|X_k'|$ is the number of newly decoded anchors from the previous $k$ frames, and $|X|$ is the total anchor set for decoding in the current frame. The function $H$ adjusts the depth of reuse and cached parameters according to the intensity of decoding calculations [S1, unofficial].
5.  **Anchor Decoding (Derivation Stage):**
    *   For anchors found in the cache and within the reuse depth limit, reuse the stored Gaussian parameters.
    *   For anchors not in the cache or exceeding the reuse depth, decode anchor features into neural Gaussian parameters using the MLP [S1, unofficial].
    *   This step removes inter-frame redundancy in the derivation stage [S1, unofficial].
6.  **Gaussian Rasterization:** Splat the derived 3D neural Gaussians into 2D and rasterize them into the image. This stage is **not** cached because slight perspective changes significantly affect occlusion and visual perception, requiring full recomputation to maintain quality [S1, unofficial].
7.  **Cache Flush:** To prevent rendering errors from maintaining Gaussian appearance parameters in the cache for too long (e.g., around centered targets), the cache is flushed when necessary, triggering re-filling and inter-frame reusing [S1, unofficial].

**Parameters:**
*   $k$: The number of previous frames considered for the update rate calculation. Typical value: Not given in the sources.
*   $H$: The guiding function of the heuristic cache reuse depth scheduling strategy. Definition: Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Cache Staleness:** If cached parameters are maintained for too long, significant rendering errors can occur, particularly around centered targets or during rapid viewpoint changes [S1, unofficial].
*   **Quality vs. Speed:** The cache optimization is restricted to the derivation stage. The rasterization stage cannot be cached to avoid visual artifacts from occlusion changes [S1, unofficial].
*   **Dynamic Scheduling:** A static cache reuse depth can cause rapid changes in scene appearance upon cache flushing. The dynamic strategy suppresses this [S1, unofficial].

## Operating characteristics
*   **Performance:** Achieves an average frame rate exceeding 72 FPS at binocular 2K resolution for large-scale city-level scenes [S1, unofficial].
*   **Complexity:** Reduces computational load in the Gaussian Derivation Stage by reusing cached parameters. The rasterization stage remains computationally intensive as it is not cached [S1, unofficial].
*   **Strengths:** Enables real-time rendering of large-scale 3DGS models on VR applications by addressing the bottleneck of structured Gaussian derivation methods [S1, unofficial].
*   **Limitations:** Only applicable to structured Gaussian derivation methods (e.g., Scaffold-GS, Octree-GS) that use anchors to derive neural Gaussians. Not suitable for unstructured 3DGS or methods without a distinct derivation stage [S1, unofficial].
*   **When to use:** When rendering large-scale, structured 3DGS models in real-time, especially in VR or binocular stereo applications where inter-frame redundancy is high.
*   **When not to use:** For unstructured 3DGS, small-scale scenes, or when the derivation stage is not the primary bottleneck.

## Background
GS-Cache was introduced in the paper "A GS-Cache Inference Framework for Large-Scale Gaussian Splatting Models" [S1, unofficial]. It was developed to address the challenges of real-time photo-realistic rendering of large-scale 3DGS models, particularly for VR applications requiring binocular stereo rendering. The framework builds on the observation that structured Gaussian derivation methods suffer from significant computational bottlenecks in the anchor decoding stage, which can be optimized through cache-centric de-redundancy [S1, unofficial].
