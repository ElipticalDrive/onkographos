# Gaussian-to-Intersect Mapping and Sorting

Also called: Gaussian rasterization preprocessing, Gaussian to Intersects Mapping, Tile-Based Gaussian Visibility Culling and Sorting, tile-key sorting

## Overview
This method is a CUDA-based preprocessing pipeline that culls invisible Gaussians, maps 3D Gaussian projections to tile-based intersection IDs, and sorts them for depth-ordered rendering [S1, S2, unofficial]. It generates key-value pairs for all Gaussian-tile overlaps to enable efficient tile-based rasterization [S1, S2, unofficial]. Unlike differentiable rendering steps, this mapping and sorting process is not differentiable to any input [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:**
    *   `num_points`: Number of Gaussians [S2, unofficial].
    *   `xys`: Tensor of shape `(batch, 2)` containing x,y locations of 2D Gaussian projections [S2, unofficial].
    *   `depths`: Tensor of shape `(batch, 1)` containing z depth of Gaussians [S2, unofficial].
    *   `radii`: Tensor of radii for each Gaussian [S1, S2, unofficial].
    *   `cov2d`: Tensor of shape `(batch, 3)` containing the upper triangular 2D covariance values [S2, unofficial].
    *   `tile_bounds`: Tuple of `(tile_width, tile_height, num_tiles)` or `(tiles.x, tiles.y, 1)` [S2, unofficial].
    *   `block_size`: Integer block size for CUDA kernel [S2, unofficial].
*   **Outputs:**
    *   `isect_ids_sorted`: Tensor of shape `(cum_tiles_hit, 1)` containing unique IDs for each Gaussian in the form `(tile | depth id)` [S2, unofficial].
    *   `gaussian_ids_sorted`: Tensor of shape `(cum_tiles_hit, 1)` mapping `isect_ids` back to `cum_tiles_hit` [S2, unofficial].
    *   `tile_bins`: Tensor of shape `(num_intersects, 2)` where each row represents the range of Gaussian IDs hit per tile [S2, unofficial].
    *   `conic`: Conic parameters derived from `cov2d` [S2, unofficial].
    *   `radii`: Computed radii [S2, unofficial].

**Data Structures:**
*   `GeometryState`: Contains allocated buffers for rasterization geometry [S1, unofficial].
    *   `depths`: float, size P
    *   `clamped`: float, size P*3
    *   `internal_radii`: uint32_t, size P
    *   `means2D`: float, size P
    *   `cov3D`: float, size P*6
    *   `conic_opacity`: float, size P
    *   `rgb`: float, size P*3
    *   `tiles_touched`: uint32_t, size P
*   `gaussian_keys_unsorted`: uint64_t array of size L. Each element packs tile ID in the upper 32 bits and depth in the lower 32 bits [S1, unofficial].
*   `gaussian_values_unsorted`: uint32_t array of size L. Stores the original Gaussian index corresponding to each key [S1, unofficial].
*   `ranges`: uint2 array of size equal to the number of tiles. Each element stores the start (x) and end (y) indices in the sorted key/value arrays for that tile [S1, unofficial].
*   `cum_tiles_hit`: Tensor resulting from the cumulative sum of `num_tiles_hit` (number of intersected tiles per Gaussian) along dimension 0 with dtype int32 [S2, unofficial]. The total number of intersects is the last element of this tensor [S2, unofficial].

**Steps:**

1.  **Frustum Culling:** Launch the `checkFrustum` kernel with P threads (P = total number of Gaussians) [S1, unofficial]. Each thread `idx` tests Gaussian `idx` against the view frustum using `in_frustum`, writing the boolean result to `present[idx]` [S1, unofficial].
2.  **Covariance and Radius Computation:** Call `compute_cov2d_bounds` with `cov2d` (contiguous, shape batch x 3 upper triangular 2D covariance values) [S2, unofficial]. Asserts input shape ends in 3 and number of points > 0 [S2, unofficial]. Returns `conic` parameters and `radii` [S2, unofficial].
3.  **Key/Value Generation:** Launch the `duplicateWithKeys` kernel with P threads [S1, unofficial]. For each Gaussian with `radii[idx] > 0`, compute its bounding tile rectangle `(rect_min, rect_max)` using `getRect` [S1, unofficial]. For each tile `(x, y)` in the rectangle, compute `key = (y * grid.x + x) << 32 | depth`, and store the key and Gaussian index `idx` in `gaussian_keys_unsorted` and `gaussian_values_unsorted` at offset `off` [S1, unofficial]. Invisible Gaussians (`radii <= 0`) must be skipped to avoid emitting invalid or zero-sized tile overlaps [S1, unofficial].
4.  **Cumulative Sum:** Calculate `cum_tiles_hit` by taking the cumulative sum of `num_tiles_hit` (number of intersected tiles per Gaussian) along dimension 0 with dtype int32 [S2, unofficial].
5.  **Sorting:** Sort `gaussian_keys_unsorted` and `gaussian_values_unsorted` together [S1, unofficial]. Sorting by the composite key yields Gaussian IDs first sorted by tile ID, then by depth [S1, unofficial].
6.  **Tile Range Identification:** Launch the `identifyTileRanges` kernel with L threads (L = total key/value pairs) [S1, unofficial]. For each index `idx`, read `currtile = key >> 32` [S1, unofficial].
    *   If `idx == 0`, set `ranges[currtile].x = 0` [S1, unofficial].
    *   If `currtile != prevtile`, set `ranges[prevtile].y = idx` and `ranges[currtile].x = idx` [S1, unofficial].
    *   If `idx == L - 1`, set `ranges[currtile].y = L` [S1, unofficial].
    *   Tile range boundaries must correctly handle the first and last elements of the sorted list to ensure all tiles have valid start/end indices [S1, unofficial].
7.  **Intersection ID Mapping:** Call the CUDA kernel `map_gaussian_to_intersects` with inputs `num_points`, `num_intersects`, `xys` (contiguous), `depths` (contiguous), `radii` (contiguous), `cum_tiles_hit` (contiguous), `tile_bounds`, and `block_size` [S2, unofficial]. This returns `isect_ids` (unique IDs in form tile | depth id) and `gaussian_ids` (mapping back to cum_tiles_hit) [S2, unofficial].
8.  **Sorting Intersection IDs:** Sort `isect_ids` using `torch.sort` to get `isect_ids_sorted` and `sorted_indices` [S2, unofficial].
9.  **Sorting Gaussian IDs:** Reorder `gaussian_ids` using `torch.gather` with dimension 0 and `sorted_indices` to produce `gaussian_ids_sorted` [S2, unofficial].
10. **Tile Bin Computation:** Call `get_tile_bin_edges` with `num_intersects`, `isect_ids_sorted` (contiguous), and `tile_bounds` [S2, unofficial]. This returns `tile_bins`, a tensor where `tile_bins[tile_idx]` returns the range (lower, upper) of Gaussian IDs that hit `tile_idx` [S2, unofficial]. Expects intersection IDs to be sorted by increasing tile ID [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Dominated by sorting, which is $O(N \log N)$ where $N$ is the number of Gaussian-tile intersections [S1, S2, unofficial].
*   **Memory Complexity:** Requires storage for `gaussian_keys_unsorted`, `gaussian_values_unsorted`, `ranges`, `isect_ids`, and `gaussian_ids` [S1, S2, unofficial].
*   **Strengths:** Efficiently culls invisible Gaussians and sorts them for fast tile-based rendering [S1, S2, unofficial].
*   **Limitations:** Not differentiable, so gradients must be handled separately or these steps excluded from the differentiable graph [S2, unofficial].
*   **When to use:** When rendering 3D Gaussians using a tile-based rasterizer [S1, S2, unofficial].
*   **When not to use:** When differentiability is required for the mapping and sorting steps [S2, unofficial].

This method is part of the 3D Gaussian Splatting rendering pipeline, specifically for CPU-sorted, instanced rendering [S1, S2, unofficial]. It builds on [Gaussian Rasterization Key Generation](5133-gaussian-rasterization-key-generation.md) [S1, S2, unofficial].
