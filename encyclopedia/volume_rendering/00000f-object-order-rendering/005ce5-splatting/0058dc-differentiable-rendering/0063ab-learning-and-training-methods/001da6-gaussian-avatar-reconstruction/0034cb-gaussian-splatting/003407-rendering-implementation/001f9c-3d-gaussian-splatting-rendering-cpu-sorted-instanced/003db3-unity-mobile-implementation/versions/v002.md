# Unity Mobile Implementation

Also called: SplattingAvatar Unity Renderer

## Overview
This method implements a display-only renderer for trained 3D Gaussian Splatting scenes within the Unity engine, optimized for mobile compatibility [S1, unofficial]. It solves the problem of rendering high-fidelity Gaussian avatars on constrained hardware by relying exclusively on a warped canonical mesh for rigging and using a standard front-to-back alpha blending pipeline [S1, unofficial]. It sets itself apart from its siblings by prioritizing maximum compatibility with existing game engine workflows (Mixamo rigging) and mobile stability over the raw performance optimizations found in tiled or sort-free variants [S1, unofficial].

## How it works
The implementation follows a specific export and rendering pipeline designed for Unity's compute shader architecture [S1, unofficial].

**Inputs and Outputs:**
*   **Inputs:** A canonical mesh (`.obj`), Gaussian data (`.ply`), embedding description (`.json`), and a rigged mesh (`.fbx`) [S1, unofficial].
*   **Outputs:** A rendered video frame with photorealistic details, achieving steady 30 FPS on iPhone 13 [S1, unofficial].

**Data Structures:**
*   **Gaussians:** Stored in a `.ply` file [S1, unofficial]. Each Gaussian is defined by its 3D position, covariance matrix, spherical harmonics coefficients (for color), and opacity [G].
*   **Rigging:** The canonical mesh is exported to Mixamo for autorigging [S1, unofficial]. The resulting `.fbx` file maintains triangle order to ensure correct deformation [S1, unofficial].
*   **Embedding:** Described in a `.json` file, linking the geometric structure to the Gaussian attributes [S1, unofficial].

**Rendering Steps:**
1.  **Rigging and Export:**
    *   Export the canonical mesh as `.obj` to Mixamo for autorigging [S1, unofficial].
    *   Export one `.ply` file containing the Gaussians [S1, unofficial].
    *   Export one `.json` file describing the embedding [S1, unofficial].
    *   Export the rigged mesh as `.fbx` from Mixamo to Unity [S1, unofficial].
    *   Note: The `.fbx` file can be rigged by other software as long as the triangle order is maintained [S1, unofficial].

2.  **Sorting:**
    *   Sort all Gaussians by the z-axis in camera coordinates from near to far [S1, unofficial].

3.  **Primitive Generation:**
    *   Based on the calculated 2D covariance $\Sigma'$, draw one front-parallel quad primitive for every visible Gaussian centered at its position [S1, unofficial].
    *   This one-primitive-one-Gaussian strategy is important for the game engine to properly handle the occlusion of other regular objects [S1, unofficial].

4.  **Fragment Shader:**
    *   For every pixel to draw, emit color with alpha pre-multiplication [S1, unofficial].
    *   Set the blend function to `(ONE, ONE_MINUS_SRC_ALPHA)` [S1, unofficial].

**Pseudocode:**
```python

    # 1. Sorting: Sort all Gaussians by z-axis in camera coordinates from near to far
    sorted_gaussians = sorted(gaussians, key=lambda g: g.position @ camera.view_matrix[2])
    
    for gaussian in sorted_gaussians:
        # 2. Primitive Setup: Calculate 2D covariance Sigma' in screen space
        # Standard 3DGS projection: transform 3D covariance by view/projection matrices [G]
```

## Subtopics

### Unity Sentis Implementation for Gaussian Splats
This variant uses the Unity Sentis framework to predict Gaussian splats from anchors and control encodings at runtime [S2]. It builds model graphs and loads MLP weights at runtime, translating each MLP via Sentis to run as a custom compute shader [S2]. Anchor features and positions are uploaded at initialization and pinned in GPU memory to avoid CPU-GPU readbacks [S2]. Computed 3D Gaussians are accessed in compute buffers and passed to the standard 3DGS renderer [S2]. Appearance can be changed at runtime by invoking MLPs with a different encoding $\Psi(x)$ without reallocating GPU memory, as the number of predicted Gaussians remains constant [S2]. MLPs are loaded at initialization and serialized from `.onnx` to `.sentis` models [S2]. To avoid unnecessary rendering, Gaussians with negative opacity are culled [S2]. The quad should fit the respective Gaussian tightly to avoid overdraw and achieve smooth rendering, decomposing eigenvalues of anisotropic 3D Gaussians into rotation and scale components [S2].

## Operating characteristics
*   **Performance:** Achieves over 300 FPS on a modern GPU and a steady 30 FPS on an iPhone 13 [S1, unofficial].

## Background
This implementation is part of the SplattingAvatar project, which focuses on creating photorealistic avatars using 3D Gaussian Splatting [S1, unofficial]. The method was developed to demonstrate the effectiveness of Gaussian Splatting for head and full-body avatars, comparing favorably with state-of-the-art methods in terms of PSNR, SSIM, and LPIPS [S1, unofficial].
