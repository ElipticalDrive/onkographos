# Tiled 2D Gaussian Splatting Rasterization

Also called: 3D Gaussian Rasterization (Forward Pass), 3D Gaussian Splatting Forward Rendering Pipeline, 3DGS Rasterization, CUDA Gaussian Rasterizer, CudaRasterizer::Rasterizer::forward, Gaussian Rasterization (GPU), Tile-based Gaussian Rasterization, Tiled Rendering of 3DGS

## Overview
Tiled 2D Gaussian Splatting Rasterization is a GPU-parallel, tile-based rendering method for 3D Gaussian Splatting (3DGS) that partitions the image plane into macro-tiles to manage memory and processing load, assigning Gaussians to tiles based on their projected axis-aligned bounding boxes [S1, S6, unofficial]. It solves the performance bottleneck of per-pixel sorting by using a global radix sort to bin splats by tile and sort them by depth simultaneously, enabling real-time performance for millions of splats [S2, S6, unofficial]. It sets itself apart from its parent [3D Gaussian Splatting Rendering (CPU-Sorted, Instanced)](2058-3d-gaussian-splatting-rendering-cpu-sorted-instanced.md) by performing the sorting and rasterization entirely on the GPU, and from siblings like [Gaussian Splat Rendering (Screen-Space Quad)](2075-gaussian-splat-rendering-screen-space-quad.md) by using iterative alpha-blending within thread blocks rather than standard hardware blending [S1, S6, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** 3D Gaussian parameters (means $\mathbf{x}$, scales $\mathbf{s}$, rotations $\mathbf{q}$, opacities $\alpha_{logit}$, spherical harmonics coefficients $\mathbf{c}_{SH}$), camera parameters (view matrix $\mathbf{V}$, projection matrix $\mathbf{P}$, image width $W$, height $H$, focal lengths $f_x, f_y$), and background color tensor $\mathbf{bg}$ [S1, S4, S6, unofficial].
*   **Outputs:** Rendered color image $\mathbf{C}$, accumulated alpha $\mathbf{A}$, and auxiliary buffers (radii, depths, ranges) [S4, S6, unofficial].

**Data Structures:**
The method uses three primary state structures allocated on the GPU [S4, S5, unofficial]:
1.  **GeometryState:** Holds per-Gaussian data.
    *   `depths`: `float*`, size $P$ (number of Gaussians).
    *   `means2D`: `float2*`, size $P$.
    *   `conic_opacity`: `float4*`, size $P$ (stores conic matrix components $a,b,c$ and opacity).
    *   `rgb`: `float*`, size $P \times 3$ (precomputed SH colors).
    *   `tiles_touched`: `uint32_t*`, size $P$.
    *   `point_offsets`: `uint32_t*`, size $P$ (prefix sum of tiles touched).
2.  **BinningState:** Holds sorting buffers.
    *   `point_list_keys`: `uint64_t*`, size $P$ (encoded tile ID and Gaussian index).
    *   `point_list`: `uint32_t*`, size $P$ (Gaussian indices).
3.  **ImageState:** Holds per-pixel/tile accumulation data.
    *   `accum_alpha`: `float*`, size $W \times H$.
    *   `ranges`: `uint2*`, size $N_{tiles}$ (start/end indices in sorted list for each tile).

**Steps:**

1.  **Preprocessing and Projection:**
    For each Gaussian $i$:
    a. Transform mean $\mathbf{x}_i$ to camera space: $\mathbf{x}_i' = \mathbf{V} \mathbf{x}_i$ [S6, unofficial].
    b. Rotate covariance $\Sigma_i$ to camera space using rotation derived from $\mathbf{q}_i$ [S6, unofficial].
    c. Project to 2D screen space to get mean $\mathbf{m}_i = (u_i, v_i)$ and 2D covariance $\Sigma_{2D}$ [S4, S6, unofficial].
    d. Compute the inverse 2D covariance (conic matrix) $\mathbf{C} = \Sigma_{2D}^{-1} = \begin{bmatrix} a & b \\ b & c \end{bmatrix}$ [S6, unofficial].
    e. Compute the 2D opacity: $\alpha_i = \sigma(\alpha_{logit, i}) \exp(-\frac{1}{2} (\mathbf{p} - \mathbf{m}_i)^T \mathbf{C} (\mathbf{p} - \mathbf{m}_i))$ evaluated at the center, or simply use the sigmoid of the logit for the splat's base opacity [S7, unofficial].
    f. Compute the axis-aligned bounding box (AABB) for the Gaussian in screen space. The radius $r$ is typically $3\sigma$ (where $\sigma$ is derived from the largest eigenvalue of $\Sigma_{2D}$) [S6, unofficial].
    g. Identify all tiles $(t_u, t_v)$ that intersect the AABB. Generate a 64-bit key for each intersection: `key = (tile_id << 32) | gaussian_index`. Store the Gaussian index in the value list [S4, S5, unofficial].

2.  **Binning and Sorting:**
    a. Collect all generated keys and values into unsorted arrays [S4, unofficial].
    b. Perform a device-side radix sort on the keys to group Gaussians by tile ID, and sort the corresponding values (Gaussian indices) by depth within each tile [S1, S4, S5, unofficial]. The sort key encodes the tile ID in the upper bits and depth in the lower bits to ensure correct ordering [S4, unofficial].
    c. Scan the sorted keys to compute `ranges` in `ImageState`, storing the start and end indices in the sorted list for each tile [S4, S5, unofficial].

3.  **Tile-Based Rasterization:**
    a. Launch a CUDA kernel where each thread block is assigned to one tile [S1, unofficial].
    b. Each thread $i$ in the block corresponds to a pixel $(u, v)$ within the tile [S2, unofficial].
    c. The block cooperatively fetches the sorted Gaussians for that tile from global memory into shared memory `Shmem` [S2, unofficial].
    d. For each pixel, iterate through the sorted Gaussians. Compute the squared Mahalanobis distance:
       $$dist\_sq = a \cdot (u - u_i)^2 + 2 \cdot b \cdot (u - u_i)(v - v_i) + c \cdot (v - v_i)^2$$
       Compute the Gaussian contribution:
       $$G_i(u,v) = \exp(-\frac{1}{2} dist\_sq)$$
       Update the pixel color and alpha using iterative alpha blending:
       $$C_{out} = C_{in} + c_i \alpha_i G_i \prod_{j=1}^{i-1} (1 - \alpha_j G_j)$$
       $$\alpha_{out} = \alpha_{in} + \alpha_i G_i \prod_{j=1}^{i-1} (1 - \alpha_j G_j)$$
       [S1, S7, unofficial].
    e. **Early Termination:** If the accumulated transmittance $(1 - \alpha_{out})$ drops below a threshold (e.g., 0.01), stop processing further Gaussians for that pixel [S1, unofficial].
    f. After processing all Gaussians, add the background color:
       $$C_{final} = C_{out} + \mathbf{bg} (1 - \alpha_{out})$$
       [S6, unofficial].

**Pseudocode:**

```python
import torch
import math

def tiled_gaussian_rasterization(
    means2D: torch.Tensor,      # [P, 2]
    conics: torch.Tensor,       # [P, 3] (a, b, c)
    opacities: torch.Tensor,    # [P]
    colors: torch.Tensor,       # [P, 3]
    tile_ranges: torch.Tensor,  # [N_tiles, 2] (start, end)
    tile_size: int = 32,
    width: int,
    height: int,
    bg_color: torch.Tensor      # [3]
):
    """
    Simulates the tiled rasterization kernel logic.
    Note: This is a Python simulation for clarity; the actual method uses CUDA.
    """
    H, W = height, width
    N_tiles_u = math.ceil(W / tile_size)
    N_tiles_v = math.ceil(H / tile_size)
    
    out_color = torch.zeros((3, H, W), dtype=torch.float32)
    out_alpha = torch.zeros((H, W), dtype=torch.float32)
    
    for tile_v in range(N_tiles_v):
        for tile_u in range(N_tiles_u):
            tile_idx = tile_v * N_tiles_u + tile_u
            start_idx = tile_ranges[tile_idx, 0].item()
            end_idx = tile_ranges[tile_idx, 1].item()
            
            if start_idx == end_idx:
                continue
                
            # Extract Gaussians for this tile
            tile_gaussians = slice(start_idx, end_idx)
            g_means = means2D[tile_gaussians]
            g_conics = conics[tile_gaussians]
            g_opacities = opacities[tile_gaussians]
            g_colors = colors[tile_gaussians]
            
            # Pixel bounds for this tile
            u_start = tile_u * tile_size
            v_start = tile_v * tile_size
            u_end = min(u_start + tile_size, W)
            v_end = min(v_start + tile_size, H)
            
            for u_pix in range(u_start, u_end):
                for v_pix in range(v_start, v_end):
                    # Initialize pixel accumulators
                    acc_color = torch.zeros(3)
                    acc_alpha = 0.0
                    transmittance = 1.0
                    
                    # Iterate over sorted Gaussians
                    for k in range(len(g_means)):
                        # Early termination check
                        if transmittance < 0.01:
                            break
                            
                        mean = g_means[k]
                        conic = g_conics[k]
                        opacity = g_opacities[k]
                        color = g_colors[k]
                        
                        a, b, c = conic
                        
                        du = u_pix - mean[0]
                        dv = v_pix - mean[1]
                        
                        # Mahalanobis distance
                        dist_sq = a * du**2 + 2 * b * du * dv + c * dv**2
                        
                        # Gaussian value
                        g_val = torch.exp(-0.5 * dist_sq)
                        
                        # Effective opacity
                        alpha = opacity * g_val
                        
                        # Alpha blending
                        contribution = alpha * transmittance
                        acc_color += color * contribution
                        acc_alpha += contribution
                        transmittance *= (1.0 - alpha)
                    
                    # Add background
                    final_color = acc_color + bg_color * transmittance
                    
                    out_color[:, v_pix, u_pix] = final_color
                    out_alpha[v_pix, u_pix] = acc_alpha
                    
    return out_color, out_alpha
```

**Parameters:**
*   `tile_size`: Default 32x32 pixels [S6, unofficial].
*   `sigma_multiplier`: Multiplier for Gaussian extent, typically 3.0 [S6, unofficial].
*   `visible_gaussian_threshold`: Threshold for culling invisible Gaussians [S4, unofficial].

**Edge Cases and Pitfalls:**
*   If the scene has non-RGB channels (`NUM_CHANNELS != 3`) and `colors_precomp` is not provided, the method throws a runtime error [S4, S5, unofficial].
*   Invisible Gaussians (tiles_touched == 0) must be skipped during key generation to avoid invalid memory writes [S5, unofficial].
*   Rasterization is restricted to pinhole cameras and cannot compute arbitrary light paths [S8].

## Subtopics

### [Non-Tiled 2D Gaussian Splatting with Transmittance Culling](2067-non-tiled-2d-gaussian-splatting-with-transmittance-culling.md)
A rasterization method that iterates over Gaussians rather than tiles, using axis-aligned bounding boxes to limit pixel iteration and transmittance-based early ray termination for performance optimization. It produces visually identical results to tiled rasterization in most cases but is significantly faster due to early stopping and better culling.

### [Gaussian Splat Projection and Sorting](3369-gaussian-splat-projection-and-sorting.md)
A GPU compute shader pass that projects 3D Gaussian splats into 2D screen space, culls invisible splats, computes view-dependent lighting, and prepares data for tile-based sorting. It differs from its parent [Tiled 2D Gaussian Splatting Rasterization](2061-tiled-2d-gaussian-splatting-rasterization.md) by handling the geometric projection, visibility culling, and sorting key generation, whereas the parent handles the actual pixel-level rasterization within tiles [G].

### [Spirula Renderer](6909-spirula-renderer.md)
The Spirula Renderer is a GPU-accelerated Gaussian Splatting renderer implemented as a native Vulkan bridge (`librosplat_spirula.so`) called via Python's `ctypes`. It handles tile sorting, Gaussian rasterization, and rendering to Vulkan textures. It explicitly excludes CUDA, PyTorch, `gsplat`, or OpenGL renderer paths. It builds on [Tiled 2D Gaussian Splatting Rasterization](2061-tiled-2d-gaussian-splatting-rasterization.md) by performing the tile sorting and rasterization internally during the render call.

### [Depth Rendering with Constant Opacity](7462-depth-rendering-with-constant-opacity.md)
Depth Rendering with Constant Opacity is a specialized rendering pass for 3D Gaussian Splatting that produces clean depth maps by forcing all Gaussians to have uniform opacity and color. Unlike standard alpha-blending which weights depth by Gaussian opacity and transmittance, this method ensures that depth accumulation is driven purely by geometric distance and rasterization order, eliminating shading artifacts and opacity-induced depth bias.

### [Tile-based Rasterization with Radix Sort](7921-tile-based-rasterization-with-radix-sort.md)
Tile-based Rasterization with Radix Sort is a GPU-parallel rendering method for 3D Gaussian Splatting that divides the image into tiles to manage memory and processing load, assigning Gaussians to tiles based on their projected axis-aligned bounding boxes [Parent](2061-tiled-2d-gaussian-splatting-rasterization.md). It solves the performance bottleneck of per-pixel sorting by using a single global radix sort to bin splats by tile and sort them by depth simultaneously.

### [Gaussian Splatting Rendering with Camera Pose Override](7971-gaussian-splatting-rendering-with-camera-pose-override.md)
This method modifies the standard 3D Gaussian Splatting rasterization pipeline to inject a custom world-to-camera transformation matrix (`camera_pose`) during rendering. It transforms the Gaussian 3D means and rotations into the new camera frame while keeping the primitives fixed in their original world-space coordinates.

### [Load Balancing for Pixel-parallel Splatting](8373-load-balancing-for-pixel-parallel-splatting.md)
A strategy to address uneven computational load across pixel threads in Gaussian rasterization by reducing the number of Gaussians rendered for heavy-load pixels and increasing it for light-load pixels. Uneven load across GPU threads leads to lower rendering efficiency due to thread waiting.

### [Half-cosine Squared Splatting](9915-half-cosine-squared-splatting.md)
Half-cosine Squared Splatting is a radial basis function (RBF) technique for 3D Gaussian Splatting that replaces the standard Gaussian decay with a half-cosine squared function. It solves the problem of slow convergence and high memory usage in standard splatting by providing higher opacity values per primitive, allowing fewer primitives to achieve the same accumulated opacity.

### [HSPT Cut and Gaussian Loading Optimization](10300-hspt-cut-and-gaussian-loading-optimization.md)
This method optimizes the HSPT cut and Gaussian loading by storing SPT properties in a continuous GPU buffer and transferring Gaussians via a single copy operation, reorganizing them on the GPU into a Structure of Arrays (SoA) layout. It reduces PCIe bus traffic and kernel launch overhead inherent in hierarchical 3D Gaussian Splatting rendering.

### [DP-GES Rendering](12576-dp-ges-rendering.md)
DP-GES is a sort-free rendering method that combines 2D surfels with semi-transparent boundaries and 3D Gaussians to achieve high-fidelity novel view synthesis, eliminating aliasing and popping artifacts while enabling correct transmittance modulation. It sets itself apart from its parent [Tiled 2D Gaussian Splatting Rasterization](2061-tiled-2d-gaussian-splatting-rasterization.md) and sibling [Non-Tiled 2D Gaussian Splatting with Transmittance Culling](2067-non-tiled-2d-gaussian-splatting-with-transmittance-culling.md) by introducing a two-stage pipeline: Stage 1 uses z-buffer-based depth peeling to extract the nearest three layers of depth, color, and opacity from surfels, and Stage 2 splats 3D Gaussians without sorting, modulating their weights by the transmittance from the peeled surfel layers.

### [Per-fragment Voxel-Cell Mask Injection](12613-per-fragment-voxel-cell-mask-injection.md)
Per-fragment Voxel-Cell Mask Injection is a technique for carving cube-shaped holes in 3D Gaussian Splatting scenes by injecting a Signed Distance Field (SDF) evaluation into the fragment shader at runtime. It solves the visual artifacts caused by deleting whole splats (the "H2" baseline) by operating at the fragment level, producing clean, sharp cube edges without forking the underlying renderer.

### [Thread-efficient Partial Rendering](13363-thread-efficient-partial-rendering.md)
Thread-efficient partial rendering is a GPU rasterization optimization for 3D Gaussian Splatting (3DGS) designed to reduce the computational overhead of multi-view training. It solves the problem of low GPU utilization caused by naive binary masking in tiled rendering, where idle threads wait for active threads to finish.

### [3D Gaussian Splatting Rasterization (GPU)](13469-3d-gaussian-splatting-rasterization-gpu.md)
A GPU-parallel rasterization method for 3D Gaussian Splatting that implements the forward and backward passes of the rendering pipeline using a CUDA backend. It projects 3D Gaussians to 2D, composites colors and depths via alpha blending, and computes exact gradients for all Gaussian parameters (means, opacities, scales, rotations, spherical harmonics, and direct colors).

### [vtkPointGaussianMapper](14148-vtkpointgaussianmapper.md)
`vtkPointGaussianMapper` renders point clouds as simple points or anisotropic 3D Gaussian splats without requiring vertex cells, supporting per-point scale, rotation, opacity, and emissive properties. It differs from its parent [Tiled 2D Gaussian Splatting Rasterization](2061-tiled-2d-gaussian-splatting-rasterization.md) by operating in object-order on the CPU-side data structure and projecting Gaussians via a vertex shader rather than GPU-parallel tile-based rasterization, and from [Non-Tiled 2D Gaussian Splatting with Transmittance Culling](2067-non-tiled-2d-gaussian-splatting-with-transmittance-culling.md) by lacking transmittance culling and relying on standard OpenGL blending.

### [Feature 3DGS Rendering](15900-feature-3dgs-rendering.md)
Feature 3DGS is a method for rendering high-dimensional semantic feature maps alongside RGB images using 3D Gaussians, enabling the distillation of knowledge from 2D foundation models (such as SAM or LSeg) into an explicit 3D scene representation. It sets itself apart from NeRF-based feature field methods by using an explicit representation that avoids interference between the radiance and feature fields, allowing for equal-weighted joint optimization without the sensitivity to hyperparameters required by implicit neural networks.

### [3D Gaussian Splatting (glTF KHR_gaussian_splatting)](16403-3d-gaussian-splatting-gltf-khr-gaussian-splatting.md)
A rendering method treating 3D Gaussian splats as point primitives, defined by position, rotation, scale, opacity, and spherical harmonics for diffuse/specular color, stored in glTF mesh primitives.

### Mobile-GS
A memory-centric rendering design for smartphones that loads only the Gaussians visible in the current view frustum from flash storage, uses a quantized integer representation for positions and colors, and performs the blending in a lower-precision shader [S1, unofficial].

### 4D Gaussian Splatting Motion Evaluation
A technique for rendering time-varying 3D captures (volumetric video) by storing static per-splat attributes and per-splat motion coefficients in extra textures, evaluated in the vertex shader from a time uniform, avoiding per-frame CPU sorting and texture uploads [S9, unofficial].

### AABB Culling for Gaussian Splatting
A culling technique that uses an axis-aligned bounding box of the projected Gaussian ellipse to reduce ineffective rendering expenses, specifically addressing the inability of bounding circles to cull low-opacity pairs in the minor axis direction [S10].

### Tight Quad Rasterization with Eigenvalue Decomposition
Represents each 3D Gaussian as a quad in Gaussian rasterization. Decomposes eigenvalues of anisotropic 3D Gaussians into rotation and scale components (2D Eigenvalues in screenspace). Computes a non-axis-aligned quad and incorporates splat alpha value into the bound rectangle calculation for tighter fits [S11].

### Adaptive Region Selection
A rendering strategy for novel viewpoints that prioritizes local Gaussians with higher contributions to avoid floating artifacts and holes [S12]. It trains a coarse global Gaussian representation by downsampling point clouds and images and avoiding densification, then renders novel viewpoints using local and global Gaussians separately, calculating a matching score $S = (1 - \lambda)L1 + \lambda \cdot LSSIM$ to sort local Gaussians [S12].

## Operating characteristics
*   **Time Complexity:** $O(N \log N)$ for sorting $N$ Gaussians, followed by $O(P \cdot K)$ for rasterization where $P$ is the number of pixels and $K$ is the average number of Gaussians per tile [S1, unofficial][S8].
*   **Memory Complexity:** $O(N)$ for storing Gaussian data and sorting buffers [S4, unofficial].
*   **Performance:** Enables real-time rendering (60+ FPS) for scenes with millions of Gaussians on modern GPUs [S1, unofficial].
*   **Strengths:** High performance due to tile-based parallelism and early termination; differentiable for training [S1, S3, unofficial].
*   **Limitations:** Restricted to pinhole cameras; linear scaling with Gaussian count regardless of size (wasted computation for small Gaussians) [S8].
*   **When to use:** Real-time rendering and training of 3DGS scenes.
*   **When not to use:** Scenes requiring complex light transport or non-pinhole cameras [S8].

## Background
Tiled 2D Gaussian Splatting Rasterization was introduced as part of the 3D Gaussian Splatting framework by Kerbl et al. in 2023 [S1, unofficial]. It was developed to address the computational bottleneck of rendering millions of Gaussian primitives in real-time. The method leverages GPU parallelism and tile-based memory management to achieve high throughput. It is widely used in 3DGS training pipelines and real-time viewers [S1, S5, unofficial].
