# Parallelization for Backpropagation
Also called: Per-splat Backpropagation

## Overview
Parallelization for Backpropagation is a training optimization for 3D Gaussian Splatting that restructures the backward pass from a per-pixel to a per-splat execution model to address training speed bottlenecks [S1]. It differs from standard pixel-parallel backpropagation by computing gradients for all pixels affected by a single Gaussian simultaneously, thereby reducing global memory synchronization overhead and atomic contention [S1].

## How it works
The method replaces the standard backward pass, where each pixel thread computes gradients for contributing Gaussians and accumulates them via atomics, with a strategy where each thread (or warp) processes a fixed set of Gaussians [S1].

**Inputs:**
- Gradient of the loss with respect to pixel colors, $\frac{\partial \mathcal{L}}{\partial \mathbf{c}_p}$, for all pixels $p$.
- Forward pass state: Gaussian parameters $\theta_i$ (position, covariance, opacity, spherical harmonics), screen-space bounding boxes, and depth-sorted order.

**Outputs:**
- Accumulated gradients $\frac{\partial \mathcal{L}}{\partial \theta_i}$ for all Gaussians $i$.

**Data Structures:**
- **Gaussian Buckets:** Gaussians are grouped into fixed-size buckets of 32 (one GPU warp) [S1].
- **Gradient Accumulators:** Per-Gaussian gradient buffers, initialized to zero. Unlike the pixel-parallel approach which requires atomic adds to global memory, this approach allows for local accumulation within the warp or shared memory before writing back [S1].

**Steps:**
1. **Bucket Assignment:** Assign each Gaussian to a bucket of 32 Gaussians. This ensures that each warp processes a contiguous block of Gaussians [S1].
2. **Pixel Lookup:** For each Gaussian in the bucket, identify the set of pixels $P_i$ it contributes to. This information is typically derived from the forward pass's screen-space bounding box and depth sorting [S1].
3. **Gradient Computation:** For each Gaussian $i$ in the bucket, iterate over its contributing pixels $p \in P_i$. Compute the local gradient contribution $\Delta \theta_{i,p} = \frac{\partial \mathcal{L}}{\partial \mathbf{c}_p} \frac{\partial \mathbf{c}_p}{\partial \theta_i}$ [S1].
4. **Local Accumulation:** Sum the contributions $\sum_{p \in P_i} \Delta \theta_{i,p}$ locally within the warp or thread [S1]. This avoids frequent atomic operations on global memory.
5. **Global Write:** Write the accumulated gradient $\frac{\partial \mathcal{L}}{\partial \theta_i}$ to the global gradient buffer for Gaussian $i$ [S1].

**Formulas:**
The total gradient for Gaussian $i$ is:
$$ \frac{\partial \mathcal{L}}{\partial \theta_i} = \sum_{p \in P_i} \frac{\partial \mathcal{L}}{\partial \mathbf{c}_p} \frac{\partial \mathbf{c}_p}{\partial \theta_i} $$
where $\frac{\partial \mathbf{c}_p}{\partial \theta_i}$ is the derivative of the alpha-blended color at pixel $p$ with respect to Gaussian $i$'s parameters, computed using the chain rule through the differentiable rasterizer [S1].

**Parameters:**
- **Bucket Size:** 32 Gaussians (one warp) [S1].

**Edge Cases:**
- **Empty Buckets:** If a bucket contains fewer than 32 Gaussians (e.g., at the end of the list), the remaining threads in the warp should be masked out to prevent invalid memory access [G].
- **Precision:** The method claims numerical equivalence to the standard approach, implying no loss in gradient accuracy [S1].

## Subtopics

### [Per-Gaussian Backward Pass](9590-per-gaussian-backward-pass.md)
A specific implementation of this strategy that parallelizes gradient computation over Gaussians rather than pixels to reduce atomic contention. It uses fixed-size buckets of 32 Gaussians to reduce warp stalls and false sharing.

## Operating characteristics
- **Time Complexity:** Reduces training time by 4–5× compared to standard 3DGS backpropagation in budgeted settings [S1].
- **Memory Complexity:** Lower memory requirements due to reduced atomic contention and potentially more efficient cache usage [S1].
- **Strengths:** Significant speedup in training; reduces global memory synchronization overhead [S1].
- **Limitations:** Requires careful management of warp-level parallelism and bucket assignment [S1].
- **When to use:** When training speed is a primary bottleneck and the scene contains many Gaussians contributing to multiple pixels [S1].

## Background
The method was introduced in "Taming 3DGS: High-Quality Radiance Fields with Limited Resources" (2024) as part of a broader effort to optimize the 3D Gaussian Splatting training pipeline [S1]. It addresses the observation that the standard per-pixel backpropagation approach suffers from performance obstacles due to atomic contention when splats contribute to arbitrary numbers of pixels [S1].
