# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, GSGEN Implementation Details, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific hyperparameters, data structures, and optimization schedules required to implement the 3D Gaussian Splatting (3DGS) training pipeline, focusing on the densification, pruning, and rendering configurations that distinguish a functional implementation from the theoretical formulation. It addresses the practical challenges of half-precision stability, gradient threshold scheduling, and scene extent calculation, which are critical for preventing artifacts such as floating geometry or incorrect splitting. While the parent article [Optimization and Parallelization](6233-optimization-and-parallelization.md) covers the general differentiable rasterization core, this article provides the concrete values and algorithmic steps for the adaptive representation updates.

## How it works

### Inputs and Outputs
*   **Inputs**: Initial 3D point cloud from Structure-from-Motion (SfM), camera poses, and training images.
*   **Outputs**: A set of optimized 3D Gaussians $\mathcal{G} = \{\mathbf{p}_i, \mathbf{s}_i, \mathbf{q}_i, \alpha_i, \mathbf{c}_i\}$, where $\mathbf{p}$ is position, $\mathbf{s}$ is scale, $\mathbf{q}$ is rotation (quaternion), $\alpha$ is opacity, and $\mathbf{c}$ is spherical harmonic (SH) coefficients.

### Data Structures
The implementation typically utilizes a flat array or structure-of-arrays (SoA) layout for GPU memory efficiency.
*   **Position**: 3 floats ($x, y, z$).
*   **Scale**: 3 floats (log-space scaling factors for anisotropy).
*   **Rotation**: 4 floats (unit quaternion).
*   **Opacity**: 1 float.
*   **SH Coefficients**: $3 \times (D+1)^2$ floats, where $D$ is the SH degree. For $D=1$, this is 12 floats per color channel.
*   **Gradients**: Accumulated gradients for position and other trainable parameters, updated via Adam optimizer.

### Parameters and Typical Values
*   **Optimizer**: Adam [S3].
*   **Learning Rate**: $1 \times 10^{-3}$ for positions, scales, rotations, and opacities; $1.6 \times 10^{-3}$ for SH coefficients [S3][S9, unofficial].
*   **SH Degree**: 1 (often used for simplicity and speed) [S3].
*   **Opacity Threshold ($\alpha_{min}$)**: 0.05 [S1].
*   **Position Gradient Threshold ($T_{pos}$)**: 0.02 [S1].
*   **Densification Interval**: Split every 500 iterations; Compactness-based densification every 1000 iterations [S1].
*   **Pruning Interval**: Every 200 iterations [S1].
*   **Half-Precision**: FP16 used for feature vectors and MLPs to reduce register pressure [S2].

### Numbered Steps

1.  **Initialization**:
    *   Initialize Gaussians from SfM points.
    *   Calculate **Scene Extent**. The default 3DGS extent $e_{\text{scene}}$ is biased by camera distribution. Use the corrected extent based on SfM points to avoid incorrect splitting in large environments with clustered cameras [S4]:
        $$ \bar{C} = \frac{1}{N_{\text{cam}}} \sum_{i=1}^{N_{\text{cam}}} C_i $$
        $$ e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2 $$
        where $\bar{C}$ is the average camera position, $N_{\text{cam}}$ is the number of cameras, $N_{\text{SfM}}$ is the number of SfM points, and $p_i$ are the SfM points [S4].

2.  **Training Loop (per iteration)**:
    *   Randomly select a single image from the training set as supervision [S3].
    *   **Forward Pass**: Render the image using differentiable alpha blending. Use half-precision memory fetches for feature vectors to reduce register pressure [S2].
    *   **Loss Calculation**: Compute photometric loss (L1 + SSIM). Apply an automatic scaling factor to loss values to improve half-precision training stability [S2].
    *   **Backward Pass**: Compute gradients $\frac{\partial \mathcal{L}}{\partial \theta}$ for all Gaussian parameters.
    *   **Optimizer Step**: Update parameters using Adam.

3.  **Densification (Every 500 iterations)**:
    *   Compute the accumulated view-space position gradient for each Gaussian.
    *   **Split**: If the gradient magnitude exceeds $T_{pos} = 0.02$, split the Gaussian into two. The new Gaussians inherit the original parameters but are perturbed by small random noise in position and scale [S1].
    *   **Clone**: (Standard 3DGS) If gradient is high but scale is small, clone instead of split to avoid thin artifacts.

4.  **Compactness Densification (Every 1000 iterations)**:
    *   Perform compactness-based densification to ensure complete geometry coverage [S1]. This typically involves checking the density of Gaussians in space and adding new ones where gaps are detected, often guided by the gradient magnitude or depth consistency.

5.  **Pruning (Every 200 iterations)**:
    *   Remove Gaussians with opacity $\alpha < \alpha_{min} = 0.05$ [S1].
    *   Remove Gaussians with excessively large world-space or view-space radius, which often indicate floating artifacts or noise [S1].

6.  **Half-Precision Stability**:
    *   When using FP16 for MLPs (e.g., for view-dependent appearance), apply an automatic scaling factor to the loss to prevent gradient underflow/overflow [S2].

### Pseudocode

```python
def train_3dgs(gaussians, images, cameras, num_iterations=30000):
    # Initialization
    scene_extent = calculate_corrected_scene_extent(gaussians.positions, cameras.poses)
    optimizer = Adam(gaussians.parameters(), lr=1e-3)
    
    for step in range(num_iterations):
        # 1. Sample Image
        img_idx = random_choice(len(images))
        image = images[img_idx]
        camera = cameras[img_idx]
        
        # 2. Forward Pass (Half-Precision Rasterization)
        # Use gsplat or custom CUDA kernel with FP16 fetches
        rendered_color = rasterize_forward(gaussians, camera, precision='fp16')
        
        # 3. Loss Calculation
        # Apply scaling factor for FP16 stability
        loss = compute_loss(rendered_color, image) * loss_scaling_factor
        loss = loss.mean()
        
        # 4. Backward Pass
        optimizer.zero_grad()
        loss.backward()
        
        # 5. Optimizer Step
        optimizer.step()
        
        # 6. Densification and Pruning
        if step % 500 == 0:
            # Split based on position gradient
            gradients = gaussians.get_position_gradients()
            split_mask = gradients > 0.02 # T_pos
            gaussians.split(split_mask)
            
        if step % 1000 == 0:
            # Compactness-based densification
            gaussians.compactness_densify(scene_extent)
            
        if step % 200 == 0:
            # Pruning
            opacity = gaussians.opacity
            prune_mask = opacity < 0.05 # alpha_min
            gaussians.prune(prune_mask)
            
        if step % 1000 == 0:
            print(f"Step {step}: Gaussians count = {len(gaussians)}")
```

### Edge Cases and Pitfalls
*   **Scene Extent Bias**: Using the default extent calculation (based on furthest camera) in scenes with clustered cameras (e.g., orbiting a small object in a large room) leads to an underestimated extent, causing Gaussians to be split or pruned incorrectly [S4]. Use the SfM-based corrected extent [S4].
*   **Half-Precision Instability**: Training with FP16 can lead to NaN gradients if loss scaling is not applied [S2].
*   **Floating Artifacts**: Excessively large Gaussians that are not pruned can cause visual artifacts. Regular pruning based on radius and opacity is essential [S1].
*   **Gradient Threshold Tuning**: A fixed $T_{pos}$ may not be optimal for all scenes. Adaptive threshold schedules can improve convergence [S4].

## Subtopics

### Corrected Scene-Extent
A method to calculate scene extent based on the SfM point cloud rather than camera positions to avoid bias from camera distribution (e.g., orbiting a small object in a large environment) [S4]. It sets itself apart from standard 3DGS by replacing the camera-centric extent formula with a point-cloud-centric one, ensuring that the densification thresholds are appropriate for the actual scene volume rather than the camera capture pattern [S4].

### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ to selectively enlarge covariances, creating pixel-wise variable blur kernels that match spatially varying scene blurriness [S5]. It sets itself apart from naive Gaussian blur by allowing spatially varying blur shapes and magnitudes, enabling effective deblurring of defocus blur without blurring sharp regions [S5].

### Denoise-GS
A self-supervised denoising method for sparse-view 3D Gaussian Splatting that combines unsupervised image denoising (Noise2Void) with explicitly differentiable 3DGS [S6]. It sets itself apart from supervised methods by requiring no paired clean data, making it robust to non-Gaussian and time-varying noise in sparse viewpoint scenarios [S6].

### Multi-Scale Constraint
A technique using position-aware point adaptive control to apply different scales to Gaussians based on viewer distance, improving rendering of distant objects [S7]. It sets itself apart from standard densification by dynamically adjusting cloning and splitting thresholds based on the Gaussian's distance from the camera center, using larger Gaussians for distant objects and smaller ones for nearby regions [S7].

### LS-Gaussian Viewpoint Transformation
An algorithm that leverages inter-frame continuity for efficient sparse rendering by transforming the viewpoint between consecutive frames, rather than rendering each frame separately [S8]. It sets itself apart from naive pixel warping by operating at the tile/Gaussian level to enable sparse rendering, reducing preprocessing and sorting costs [S8].

### Camera Localisation for Convergence Basin
Localizes camera pose by minimizing only the photometric error against the ground-truth colour image of the target view, fixing the initial Gaussians during optimization [S9, unofficial]. It sets itself apart from joint optimization methods by decoupling pose estimation from geometry refinement, ensuring convergence to the correct local minimum [S9, unofficial].

### DiffGS Framework
Applies an optimization process during Gaussian extraction to optimize Gaussians to exact locations, using a truncation function $\lambda$ and projection function $\tau$ [S10]. It sets itself apart from standard 3DGS by explicitly modeling the Gaussian Probability Function (GauPF) to achieve higher fidelity with fewer Gaussians [S10].

### Opacity Offset Table for DSA
Constructs an opacity offset table to model changes in digital subtraction angiography [S11]. It sets itself apart from standard opacity handling by explicitly modeling temporal changes in opacity for medical imaging applications [S11].

### Conditional Splat Approximation
Approximates the influence range of a 3D Gaussian on a slice by using a 2D ellipse splat scaled by the marginal factor, which closely matches the true iso-probability contours [S12, unofficial]. It sets itself apart from exact 3D Gaussian slicing by providing an accurate and efficient approximation for slice-based rendering or tomographic reconstruction [S12, unofficial].

### 3DGS Uncertainty Calculation via Fisher Information
Computes an uncertainty attribute for 3D Gaussians based on the negative log-likelihood of the rendered pixel value, interpreted as Fisher information [S13]. It sets itself apart from standard 3DGS by providing an explicit uncertainty measure that can guide refinement and sampling, assuming regularity conditions for volume rendering [S13].

## Operating characteristics

*   **Time Complexity**: The forward pass is $O(N \cdot M)$ where $N$ is the number of Gaussians and $M$ is the number of pixels, but optimized via tile-based rasterization to be effectively linear in practice. The backward pass is similar. Densification adds $O(N)$ overhead every 500-1000 iterations.
*   **Memory Complexity**: $O(N \cdot D)$ where $D$ is the number of SH coefficients. For $D=1$, each Gaussian requires ~30-40 bytes. Millions of Gaussians can require several GBs of VRAM.
*   **Measured Performance**: On an NVIDIA RTX 4090, 3DGS can render at >100 FPS for scenes with ~1-2 million Gaussians [S3]. Training typically takes 10-20 minutes for standard datasets like Mip-NeRF 360.
*   **Strengths**: Real-time rendering, high visual fidelity, explicit representation allows for easy editing and compression.
*   **Limitations**: High memory usage for large scenes, potential for floating artifacts if densification/pruning is not tuned, sensitivity to initialization.
*   **When to use**: Real-time novel view synthesis, interactive applications, scenes with complex geometry and view-dependent effects.
*   **When not to use**: Scenes with extreme occlusions or non-Lambertian surfaces that cannot be well-represented by Gaussians, or when memory is severely constrained.

## Background

3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1, S2]. It revolutionized novel view synthesis by combining the efficiency of explicit primitives with the quality of neural radiance fields. The method relies on differentiable rasterization of 3D Gaussians, allowing for end-to-end optimization of the scene representation. The implementation details described here are based on the original paper and subsequent optimizations for stability, efficiency, and specific use cases like text-to-3D generation and sparse-view reconstruction.
