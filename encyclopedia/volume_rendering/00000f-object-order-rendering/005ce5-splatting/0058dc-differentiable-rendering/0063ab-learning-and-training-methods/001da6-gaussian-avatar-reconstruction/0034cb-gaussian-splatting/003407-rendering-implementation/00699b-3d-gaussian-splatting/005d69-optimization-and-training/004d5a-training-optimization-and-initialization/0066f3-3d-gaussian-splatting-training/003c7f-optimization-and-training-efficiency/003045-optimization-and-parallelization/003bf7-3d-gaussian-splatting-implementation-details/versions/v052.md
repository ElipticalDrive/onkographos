# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, GSGEN Implementation Details, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific hyperparameters, optimization schedules, and software engineering choices required to implement the 3D Gaussian Splatting (3DGS) training pipeline. It addresses the problem of translating the theoretical differentiable rendering formulation into a stable, efficient, and high-fidelity optimization process. It sets itself apart from sibling articles by focusing on the concrete numerical values, iteration schedules, and data structure layouts (e.g., half-precision fetches, specific loss weights) rather than the general mathematical derivation of gradients or the high-level training loop structure.

## How it works
The training process optimizes a set of 3D Gaussians $\mathcal{G}$ to minimize the difference between rendered images and ground-truth training views. The implementation relies on a differentiable rasterizer (typically `gsplat`) and an optimizer (typically Adam).

### Inputs and Outputs
*   **Inputs:** A set of $N$ training images with known camera poses (extrinsics $C_i$ and intrinsics), initialized from Structure-from-Motion (SfM) points.
*   **Outputs:** A final set of 3D Gaussians $\mathcal{G}_{final}$, each defined by position $\mu$, covariance $\Sigma$ (or scale $s$ and rotation $q$), opacity $\alpha$, and spherical harmonic coefficients $c_{l,m}$ for color.

### Data Structures and Layout
The Gaussian primitives are stored in a flat array or list. Each Gaussian $j$ contains:
*   **Position:** $\mu_j \in \mathbb{R}^3$ (float32 or float16).
*   **Rotation:** $q_j \in \mathbb{R}^4$ (unit quaternion, float32 or float16).
*   **Scale:** $s_j \in \mathbb{R}^3$ (log-space or raw, float32 or float16).
*   **Opacity:** $\alpha_j \in [0, 1]$ (float32 or float16).
*   **Color:** Spherical Harmonic coefficients $c_{j, l, m}$ for degree $L$. For $L=1$, this is $3 \times (L+1)^2 = 12$ floats per Gaussian.

**Precision:** To reduce register pressure and memory bandwidth, feature vectors (including SH coefficients) are often fetched and processed in half-precision (FP16) during rasterization, both in forward and backward passes [S2]. An automatic scaling factor is applied to loss values to improve half-precision training stability [S2].

### Optimization Loop
The training loop iterates for a fixed budget, commonly 30,000 iterations [S9, unofficial].

1.  **Sampling:** Randomly select one training image (and its camera pose) from the dataset [S3][S9, unofficial].
2.  **Rasterization:** Render the image from the selected camera pose using the current set of Gaussians. This involves projecting 3D Gaussians to 2D ellipses, sorting them by depth, and alpha-blending [S9, unofficial].
3.  **Loss Computation:** Compute the loss $\mathcal{L}$ between the rendered image and the ground-truth image. The standard loss is a weighted combination of L1 loss and D-SSIM:
    $$ \mathcal{L} = (1 - \lambda) \mathcal{L}_1 + \lambda \mathcal{L}_{\text{SSIM}} $$
    where $\lambda \approx 0.2$ [S9, unofficial].
4.  **Backpropagation:** Compute gradients $\nabla \mathcal{L}$ with respect to all Gaussian parameters ($\mu, s, q, \alpha, c$) [S9, unofficial].
5.  **Optimization Step:** Update parameters using the Adam optimizer with a learning rate of $1 \times 10^{-3}$ [S3][S9, unofficial].
6.  **Densification and Pruning:** Periodically modify the set of Gaussians based on gradient statistics and opacity (see Densification Schedule below) [S1, S4].

### Densification and Pruning Schedule
Densification is performed to increase Gaussian density in under-reconstructed regions. Pruning removes redundant Gaussians.

**Densification Steps:**
1.  **Gradient Tracking:** Accumulate the view-space position gradient for each Gaussian over iterations [S1].
2.  **Splitting:** Every 500 iterations, split Gaussians whose accumulated view-space position gradient exceeds a threshold $T_{\text{pos}} = 0.02$ [S1].
3.  **Cloning/Compactness:** Every 1000 iterations, perform compactness-based densification (cloning) to fill gaps [S1].

**Pruning Steps:**
1.  **Opacity Check:** Every 200 iterations, remove Gaussians with opacity $\alpha < \alpha_{\text{min}} = 0.05$ [S1].
2.  **Size Check:** Remove Gaussians with excessively large world-space or view-space radius [S1].

### Scene Extent Calculation
The default 3DGS implementation calculates scene extent $e_{\text{scene}}$ based on camera positions, which can be biased if cameras are clustered (e.g., orbiting a small object) [S4]. A corrected scene extent $e'_{\text{scene}}$ should be used, based on the SfM point cloud:

$$ \bar{C} = \frac{1}{N_{\text{cam}}} \sum_{i=1}^{N_{\text{cam}}} C_i $$

$$ e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2 $$

where $N_{\text{cam}}$ is the number of camera views, $C_i$ is the position of the $i$-th camera, $N_{\text{SfM}}$ is the number of SfM points, and $p_i$ is the $i$-th SfM point [S4].

### Pseudocode

```python
# Initialization
gaussians = initialize_from_sfm(sfm_points)
optimizer = Adam(gaussians.parameters(), lr=1e-3)
iteration = 0
max_iterations = 30000
T_pos = 0.02
alpha_min = 0.05
lambda_ss = 0.2

# Precompute corrected scene extent if available
if use_corrected_extent:
    C_avg = mean(camera_positions)
    e_scene = mean(distance(C_avg, p) for p in sfm_points)
else:
    e_scene = default_extent_calculation(camera_positions)

while iteration < max_iterations:
    # 1. Sample a random training view
    view_idx = random_choice(training_views)
    image_gt, camera_pose = training_views[view_idx]
    
    # 2. Rasterize
    # Uses half-precision fetches for features [S2]
    image_pred = rasterize(gaussians, camera_pose)
    
    # 3. Compute Loss
    loss_l1 = l1_loss(image_pred, image_gt)
    loss_ssim = ssim_loss(image_pred, image_gt)
    loss = (1 - lambda_ss) * loss_l1 + lambda_ss * loss_ssim
    
    # 4. Backpropagate
    optimizer.zero_grad()
    loss.backward()
    
    # 5. Optimizer Step
    optimizer.step()
    
    # 6. Densification and Pruning
    if iteration % 500 == 0:
        # Split Gaussians with high position gradient
        split_gaussians(gaussians, threshold=T_pos)
        
    if iteration % 1000 == 0:
        # Compactness-based cloning
        clone_gaussians(gaussians)
        
    if iteration % 200 == 0:
        # Prune low opacity and large radius Gaussians
        prune_gaussians(gaussians, alpha_min=alpha_min)
        
    iteration += 1
```

## Operating characteristics
*   **Time Complexity:** The training loop is dominated by the rasterization and backpropagation steps, which are $O(N \cdot M)$ where $N$ is the number of Gaussians and $M$ is the number of pixels/tiles. Densification adds overhead every 500-1000 iterations.
*   **Memory Complexity:** Memory usage scales linearly with the number of Gaussians. Each Gaussian stores position, rotation, scale, opacity, and SH coefficients. Half-precision fetches reduce memory bandwidth requirements [S2].
*   **Performance:** Standard 3DGS training takes approximately 30,000 iterations. With the default settings, it achieves high PSNR and SSIM on standard datasets like Mip-NeRF 360 and Tanks & Temples [S1, S2, S3].
*   **Strengths:** High-quality novel view synthesis, real-time rendering after training, explicit representation allows for easy manipulation.
*   **Limitations:** Training can be slow for large scenes due to the large number of Gaussians. Densification and pruning schedules require careful tuning to avoid overfitting or underfitting. The default scene extent calculation can be biased [S4].
*   **When to use:** When high-fidelity novel view synthesis is required, and training time is acceptable.
*   **When not to use:** When real-time training is required, or when the scene is extremely large and memory is constrained (consider compression methods [12943-data-compression-and-storage-optimization.md]).

## Background
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1, S2, S3]. It represents a scene as a set of 3D Gaussians and uses differentiable rasterization to optimize their parameters. The method has since been extended in various ways, including text-to-3D generation [S1], neural harmonic textures [S2], and urban view synthesis [S3]. The implementation details described here are based on the original paper and subsequent refinements in the community [S1, S2, S3, S4, S5, S6, S7, S8][S9, S10, unofficial][S11, S12, S13][S14, unofficial][S15].
