# Fine-tuning

Also called: 3DGS Fine-tuning, Fine-tuning Strategy, Gaussian Splatting Fine-tuning

## Overview
Fine-tuning in 3D Gaussian Splatting (3DGS) refers to the phase of training where an initial set of Gaussian primitives is optimized to minimize rendering loss, often leveraging pretrained weights or specific initialization strategies to accelerate convergence and improve fidelity [S2]. It solves the problem of slow convergence and suboptimal initialization from sparse Structure-from-Motion (SfM) points by allowing the model to adaptively densify, split, and prune primitives during the optimization process [S2]. Unlike static initialization methods, fine-tuning enables the dynamic adjustment of the Gaussian population, ensuring that the representation density matches the scene complexity [S2]. It sets itself apart from basic training by explicitly integrating densification operations (growing and pruning) and potentially leveraging pretrained priors to reduce the number of redundant primitives while maintaining high visual quality [S2].

## How it works
The fine-tuning process begins with an initialization of 3D Gaussian primitives, which may be generated via a direct feed-forward process using pretrained weights or derived from sparse SfM points [S2]. The core mechanism involves iterative optimization of geometry (position, scale, rotation) and color attributes (opacity, spherical harmonic coefficients) using gradient descent, while periodically applying densification and pruning operations to manage the primitive count [S2].

**Inputs and Outputs:**
*   **Inputs:** Initial set of 3D Gaussians $\mathcal{G}_0$, camera poses, input images (RGB/Depth), and optimization hyperparameters (learning rate, densification interval).
*   **Outputs:** Optimized set of 3D Gaussians $\mathcal{G}_{final}$ with refined attributes.

**Data Structures:**
Each Gaussian $g_k$ is defined by:
*   Mean position $\mu_k \in \mathbb{R}^3$
*   Covariance matrix $\Sigma_k$ (parameterized by scale $s_k$ and rotation $q_k$)
*   Opacity $\alpha_k \in [0, 1]$
*   Spherical Harmonic coefficients $\mathbf{c}_k$

**Numbered Steps:**
1.  **Initialization:** Generate an initial set of 3D Gaussian primitives. If using a feed-forward approach, a neural network predicts geometry and color attributes directly [S2]. If using SfM, initialize Gaussians at point cloud locations [S2, Parent].
2.  **Optimization Loop:** For each iteration $t$:
    a. Render the scene from available camera views using differentiable rasterization [S2].
    b. Compute the loss $\mathcal{L}$ between rendered images and ground truth images (e.g., L1 loss, SSIM) [S2, S3].
    c. Compute gradients of the loss with respect to Gaussian attributes [S2].
    d. Update Gaussian attributes using an optimizer (e.g., Adam) [S2].
3.  **Densification and Pruning (Periodic):** Every $N$ iterations (e.g., `refineEvery` = 100), evaluate metrics to determine if densification or pruning is needed [Parent, S2]:
    a. **Gradient Evaluation:** Compute the accumulated 2D positional gradient $\tau_k$ for each Gaussian [Parent].
    b. **Opacity Check:** Identify Gaussians with $\alpha_k < \alpha_{\min}$ for pruning [Parent].
    c. **Scale Check:** Identify Gaussians with excessive scale for splitting or pruning [Parent].
    d. **Rendering-Guided Densification (Optional):** In some variants, identify regions with high rendering error or low opacity (holes) and add new Gaussians [S3].
    e. **Split/Clone:** Replace high-gradient Gaussians with children (split) or exact copies (clone) [Parent].
    f. **Prune:** Remove low-opacity or insignificant Gaussians [Parent, S2].
4.  **Final Output:** Return the optimized set of Gaussians [S2].

**Formulas:**
*   **Rendering Loss:** $\mathcal{L} = \lambda_{color} \|\hat{C} - C\|_1 + \lambda_{SSIM} \text{SSIM}(\hat{C}, C) + \lambda_{depth} \|\hat{D} - D\|_1$ [S3].
*   **Opacity Rendering:** $O(x,y) = \sum_{i \in N} \alpha_i \prod_{j=1}^{i-1} (1 - \alpha_j)$, where $N$ are 2D Gaussians overlapping the pixel [S3].
*   **Depth Error Normalization:** $E_{depth}(x,y)/D(x,y) > \tau_{depth}$ [S3].

**Parameters:**
*   Learning rate: $1 \times 10^{-3}$ (Adam optimizer) [S2].
*   Densification interval: Typically 100 iterations [Parent].
*   Opacity threshold $\tau_{opa}$: Predefined threshold for hole detection [S3].
*   Depth threshold $\tau_{depth}$: Predefined threshold for depth error [S3].

**Edge Cases and Pitfalls:**
*   **Overfitting:** In continuous mapping, Gaussians may overfit to the latest frame, causing "forgetting" of previous frames [S3]. Regularization terms (e.g., SSIM) can alleviate this [S3].
*   **Sparse Initialization:** SfM points may have holes in sky, distant, or low-texture areas, leading to blank regions [S4]. Fine-tuning with densification helps fill these gaps [S4].
*   **Redundancy:** Initial feed-forward Gaussians may be redundant, requiring significant pruning during fine-tuning to reduce memory consumption [S2].

**Pseudocode:**
```python
def fine_tune_3dgs(initial_gaussians, images, poses, hyperparams):
    """
    Fine-tune 3D Gaussian Splatting with optional densification.
    
    Args:
        initial_gaussians: List of Gaussian primitives with initial attributes.
        images: List of input images (RGB/Depth).
        poses: List of camera poses.
        hyperparams: Dictionary containing learning_rate, refine_every, etc.
        
    Returns:
        Optimized list of Gaussian primitives.
    """
    gaussians = initial_gaussians
    optimizer = Adam(gaussians.parameters(), lr=hyperparams['learning_rate'])
    
    for iteration in range(hyperparams['total_iterations']):
        # 1. Render and Compute Loss
        rendered_images = []
        for image, pose in zip(images, poses):
            rendered = render_gaussians(gaussians, pose)
            rendered_images.append(rendered)
            
        loss = compute_loss(rendered_images, images)
        
        # 2. Backpropagate and Update
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        
        # 3. Periodic Densification and Pruning
        if iteration % hyperparams['refine_every'] == 0:
            gaussians = densify_and_prune(gaussians, images, poses, hyperparams)
            
    return gaussians

def densify_and_prune(gaussians, images, poses, hyperparams):

    Perform densification and pruning based on gradients and rendering error.
    """

            new_gaussians.extend(children)
        else:
            new_gaussians.append(g)
```

## Subtopics

### [Exponentially Ascending Gradient Threshold](9684-exponentially-ascending-gradient-threshold.md)
A densification control mechanism for 3D Gaussian Splatting that uses an exponentially ascending gradient threshold to regulate the splitting and cloning of Gaussians during training. It solves the trade-off between early-stage convergence speed and late-stage overfitting by allowing aggressive densification when few Gaussians exist and restricting it as the scene becomes dense. It sets itself apart from static threshold methods by dynamically adjusting the sensitivity of densification decisions based on the normalized training progress.

### [SplatFormer Training Objective & Refinement](11745-splatformer-training-objective-refinement.md)
SplatFormer is a learning-based, feed-forward 3D neural module that refines initial 3D Gaussian Splatting (3DGS) representations to enable robust novel view synthesis from out-of-distribution (OOD) camera angles. It addresses the bias of standard 3DGS optimization, which overfits to input views and fails to generalize to unseen high-elevation perspectives, by applying a point transformer network that predicts attribute residuals. Unlike 2D image restoration methods that suffer from multi-view inconsistencies, SplatFormer operates directly on 3D primitives, ensuring geometric consistency while recovering details lost in OOD views.

### [MCMC-based 3DGS / SGLD for 3DGS](11917-mcmc-based-3dgs-sgld-for-3dgs.md)
This method reformulates 3D Gaussian Splatting (3DGS) by treating the set of 3D Gaussians as random samples drawn from an underlying probability distribution describing the scene, specifically as Markov Chain Monte Carlo (MCMC) samples. It converts conventional 3DGS updates into Stochastic Gradient Langevin Dynamics (SGLD) updates by introducing a noise term to promote sample exploration, thereby removing the need for manual densification heuristics like cloning, splitting, and opacity resetting. Unlike sibling methods that rely on complex gradient thresholds or hard constraints, this approach relies on probabilistic state transitions and regularization to manage Gaussian population.

### [Deblurring 3D Gaussian Splatting](12318-deblurring-3d-gaussian-splatting.md)
Deblurring 3D Gaussian Splatting is a real-time deblurring framework that reconstructs sharp 3D scenes from blurry input images by manipulating the covariance matrices and means of 3D Gaussians using a small Multi-Layer Perceptron (MLP) during training. Unlike volumetric rendering-based methods like Deblur-NeRF which require seconds per image, this method uses differentiable rasterization to achieve real-time inference speeds (>800 FPS) while handling both defocus and camera motion blur. It addresses the sparse point clouds caused by blurry inputs through K-nearest-neighbor interpolation and depth-based pruning.

### [Supplementary Point Addition for Sparse Point Clouds](12323-supplementary-point-addition-for-sparse-point-clouds.md)
Supplementary Point Addition is a densification technique designed to compensate for the sparsity of 3D Gaussians at the far end of scenes with large depth of field, where Structure-from-Motion (SfM) extraction is poor due to defocus blur. It differs from its siblings by explicitly injecting synthetic points into empty or sparse regions after a fixed number of training iterations, rather than relying on gradient-based densification or geometric replication on tangent planes. This method ensures that distant objects are represented by initial Gaussians, preventing them from being ignored during the adaptive density control phase.

### [Augmented Radiance Field](13218-augmented-radiance-field.md)
Augmented Radiance Field is a post-enhancement framework that improves 3D Gaussian Splatting (3DGS) scenes by adding Gaussian kernels with view-dependent opacity to explicitly model specular components. It solves the problem that standard spherical harmonics (SH) cannot decouple diffuse and specular radiance, leading to poor reconstruction of sharp highlights and material artifacts. Unlike standard 3DGS which assigns SH coefficients to every primitive, this method uses distinct primitives for diffuse and specular components, avoiding the memory and stability issues of high-order SH.

### [Frequency Regularization for Densification](13484-frequency-regularization-for-densification.md)
Frequency Regularization for Densification (FreGS) addresses the over-reconstruction issue in 3D Gaussian Splatting, where high-variance image regions are covered by a few large Gaussians, leading to blur and artifacts. Unlike standard 3D-GS which relies solely on pixel-wise L1 loss in the spatial domain, FreGS minimizes the discrepancy between the frequency spectrum of the rendered image and the ground truth in the Fourier space. This approach significantly increases pixel gradients within over-reconstruction regions, enabling a coarse-to-fine densification process guided by progressive frequency annealing.

### [Error-Guided Redistribution](14037-error-guided-redistribution.md)
Error-Guided Redistribution is a family of training optimization methods for 3D Gaussian Splatting (3DGS) that refine Gaussian allocation based on reconstruction quality metrics. It addresses artifacts caused by suboptimal primitive placement or size by either identifying defective Gaussians for targeted densification or reallocating a fixed budget of primitives toward high-error regions. It differs from standard densification by using explicit error signals (positional gradients or SSIM) rather than averaged gradient magnitudes, and from simple pruning by actively moving primitives to improve fidelity rather than just removing them.

### CoherentGS
CoherentGS is a regularized optimization approach for sparse novel view synthesis that introduces coherency to an explicit 3D Gaussian representation by constraining Gaussian movement in 2D image space, initialized with monocular depth estimates [S1]. It addresses the instability and "needle-like" artifacts of standard 3D Gaussian Splatting (3DGS) when trained on extremely sparse inputs (e.g., 3–4 images) by enforcing single-view and multi-view constraints, preventing overfitting and allowing for the identification of occluded regions suitable for inpainting [S1]. Unlike NeRF-based sparse methods that rely on implicit MLP coherency and produce blurry occluded regions, CoherentGS constrains explicit Gaussians in 2D image space, enabling sharper details and structured hallucination via diffusion models [S1].

### [Pruning and Sparsity Control](14431-pruning-and-sparsity-control.md)
Pruning and Sparsity Control methods reduce the number of active 3D Gaussians in a radiance field to lower memory consumption and storage requirements while maintaining rendering quality. Unlike standard 3DGS which relies on opacity thresholds and stops densifying mid-training, these methods actively eliminate redundant primitives throughout the optimization process [12710-gaussian-volume-mask.md]. They are distinguished from sibling methods like [Exponentially Ascending Gradient Threshold](9684-exponentially-ascending-gradient-threshold.md) by using explicit geometric or volume-based criteria rather than gradient magnitude alone [14019-visibility-based-pruning-for-3d-gaussian-splatting.md].

### [Rendering-Free Pruning via Hessian Importance](14447-rendering-free-pruning-via-hessian-importance.md)
Rendering-Free Pruning via Hessian Importance (REFINE) is a post-processing framework for 3D Gaussian Splatting (3DGS) that identifies and removes unimportant Gaussian primitives without performing forward rendering passes. It quantifies primitive importance using an analytically approximated Hessian field, which estimates the image-space quality degradation caused by removing a primitive based on parameter-space gradients. Unlike rendering-based methods such as PUP [14431-pruning-and-sparsity-control.md] or LightGaussian, REFINE bypasses rasterization entirely, relying on closed-form algebraic operations to achieve a 3,000× reduction in computational complexity and a ~20× speedup in device latency.

### [GoF-based Dynamic 3DGS Video Construction](14770-gof-based-dynamic-3dgs-video-construction.md)
This method constructs dynamic 3D Gaussian Splatting (3DGS) video by temporally segmenting input sequences into Groups of Frames (GoFs) and independently training Gaussian deformation fields within each segment. It solves the problem of motion drift and geometric inconsistencies that occur when modeling long-range temporal dependencies with a single global deformation field. By limiting the motion degree within short segments, it prevents the deformation field from struggling to adapt to complex, long-sequence dynamics. It sets itself apart from global optimization approaches by decoupling static and dynamic components via weighted MLP parameters and separating foreground/background content to reduce training complexity.

### [Two-stage Optimization](14857-two-stage-optimization.md)
Two-stage optimization is a training protocol for inverse rendering with 3D Gaussians that decouples geometric and appearance optimization from material and lighting decomposition. It solves the problem of jointly recovering geometry, material properties (albedo, roughness), and lighting from static multi-view images by preventing the entanglement of these distinct physical properties during early training. It sets itself apart from vanilla 3DGS by introducing normal gradient-based densification and PBR-specific loss terms, while differing from neural relightable methods by maintaining a discrete point-based representation.

### [TIP-Editor](14859-tip-editor.md)
TIP-Editor is a method for editing existing 3D Gaussian Splatting (3DGS) scenes using intuitive text and image prompts. It solves the problem of local, high-fidelity modification by combining a stepwise 2D personalization strategy with score distillation sampling (SDS). It is distinguished from sibling methods by its specific integration of LoRA for reference image alignment and a dedicated localization loss for scene adaptation, rather than relying solely on attention maps or ControlNet depth conditioning.

### StylizedGS
StylizedGS is a controllable 3D stylization method for 3D Gaussian Splatting (3DGS) models that performs color matching with a reference style image while utilizing a 3DGS filter to remove artifacts [S1]. It distinguishes itself from other stylization approaches by explicitly optimizing for nearest neighbor feature matching and depth preservation, ensuring the stylized output retains the geometric structure of the original scene while adopting the artistic appearance of the style image [S1].

### [SGD (Street View Synthesis with Gaussian Splatting and Diffusion Prior)](15522-sgd-street-view-synthesis-with-gaussian-splatting-and-diffus.md)
SGD is a novel view synthesis method for street scenes that enhances 3D Gaussian Splatting (3DGS) by fine-tuning a Stable Diffusion model on driving data and using it to regularize 3DGS training at unseen viewpoints, addressing the sparse-view reconstruction problem. It differs from prior sparse-view NVS methods that rely on object-centric multi-view datasets and relative camera poses; instead, it uses adjacent frames and LiDAR depth for direct fine-tuning on driving data, overcoming the domain gap.

### Gaussian Densification via Rendering Loss
A strategy to add new 3D Gaussians to the map by identifying unobserved regions (holes) and regions with high rendering error, using opacity, color, and depth thresholds [S3]. It solves the problem of incomplete reconstruction in SLAM systems by actively densifying areas that are not well-represented by the current Gaussian set [S3]. It sets itself apart from gradient-based densification by directly using rendering metrics (opacity and error) to guide densification [S3].

### Point Densification
A process in original 3DGS that adaptively controls the number of Gaussian points through clone and split operations to convert a sparse set into a denser one [S4]. It solves the problem of insufficient representation in complex or large-scale scenes by dynamically adjusting the density of Gaussians based on optimization progress [S4]. It sets itself apart from static initialization methods by allowing the Gaussian population to grow and shrink during training [S4].

## Operating characteristics
*   **Time Complexity:** The fine-tuning process is iterative, with each iteration involving rendering and gradient computation. The complexity is proportional to the number of Gaussians $N$ and the number of pixels $P$ in the rendered images, typically $O(N \cdot P)$ per iteration [S2, S3]. The total time depends on the number of iterations and the frequency of densification operations [S2].
*   **Memory Complexity:** Memory usage is dominated by the storage of Gaussian attributes ($\mu, \Sigma, \alpha, \mathbf{c}$) and intermediate rendering buffers. The number of Gaussians can vary significantly during fine-tuning, with initial feed-forward methods potentially requiring more memory initially due to redundancy, which is reduced through pruning [S2].
*   **Measured Performance:** Fine-tuning with pretrained weights (e.g., EVolSplat) can accelerate convergence and achieve photorealism comparable to or surpassing other methods [S2]. Rendering-guided densification (e.g., in SLAM) improves map quality and reduces forgetting [S3].
*   **Scaling:** The method scales with the complexity of the scene, as densification operations increase the number of Gaussians in detailed regions [S4]. However, pruning helps control the overall number of primitives [S2].
*   **Strengths:** Accelerates convergence, improves fidelity, handles sparse initialization, and reduces redundancy through pruning [S2].
*   **Limitations:** Can suffer from overfitting in continuous mapping scenarios [S3]. Requires careful tuning of hyperparameters (e.g., thresholds, learning rate) [S2, S3].
*   **When to use:** When starting from sparse SfM points or pretrained weights, and when high fidelity and fast convergence are required [S2].
*   **When not to use:** When computational resources are extremely limited and densification/pruning overhead is prohibitive [S2].

## Background
Fine-tuning in the context of 3D Gaussian Splatting has evolved from general deep learning transfer learning strategies, where lower layers are fixed and higher layers are optimized [S1]. In 3DGS, it specifically refers to the optimization phase where initial Gaussian primitives are refined to minimize rendering loss, often incorporating densification and pruning operations [S2]. The concept of densification and pruning was introduced in the original 3DGS paper to handle sparse initialization and adapt to scene complexity [Parent, S4]. Subsequent works have extended this by integrating rendering-guided densification for SLAM [S3], feed-forward initialization with fine-tuning [S2], and various regularization techniques to prevent overfitting [S3].
