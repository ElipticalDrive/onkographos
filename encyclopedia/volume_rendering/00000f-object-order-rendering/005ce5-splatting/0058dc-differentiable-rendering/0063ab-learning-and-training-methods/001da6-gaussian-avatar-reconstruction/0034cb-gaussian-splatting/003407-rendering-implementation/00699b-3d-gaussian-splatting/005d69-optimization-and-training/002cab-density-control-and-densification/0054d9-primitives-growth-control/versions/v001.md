# Primitives Growth Control

Also called: Budget control, Growth control

## Overview
Primitives Growth Control is a constraint mechanism applied during the densification phase of 3D Gaussian Splatting to prevent unbounded exponential growth of Gaussian primitives, which can lead to out-of-memory errors [S1]. It operates by enforcing a global maximum primitive count ($N_{max}$) and limiting the number of new primitives spawned in each densification step to a fixed fraction of the existing population [S1]. It differs from sibling methods like [Adaptive Densification](3034-adaptive-densification.md) by actively capping the density rather than relying solely on gradient thresholds and opacity pruning to naturally stabilize the count.

## How it works
**Inputs and Outputs:**
*   **Input:** Current set of Gaussians $\mathcal{G}$, current count $N = |\mathcal{G}|$, densification candidates $\mathcal{C} \subseteq \mathcal{G}$ (Gaussians meeting gradient/size criteria from the parent method), maximum budget $N_{max}$, growth fraction $\phi$.
*   **Output:** Updated set of Gaussians $\mathcal{G}'$ with controlled growth.

**Data Structures:**
*   $\mathcal{G}$: List of Gaussian primitives.
*   $\mathcal{C}$: List of candidate primitives eligible for cloning or splitting.
*   $N_{max}$: Integer scalar, the hard cap on total primitives.
*   $\phi$: Float scalar, the growth fraction (e.g., 0.05).

**Parameters:**
*   $\phi$: Growth fraction. Typical value: $0.05$ (5%) [S1].
*   $N_{max}$: Maximum primitives budget. Set to the median number of primitives generated by the baseline method (e.g., standard 3DGS) for comparable experiments [S1].

**Steps:**
1.  **Calculate Budget:** Determine the maximum number of new primitives allowed in this step:
    $$ N_{new}^{max} = \lfloor \phi \cdot N \rfloor $$
    [S1]

2.  **Check Global Limit:** If the current count $N$ is already at or above $N_{max}$, skip densification entirely for this step [S1].
    [G] *Note: If $N \ge N_{max}$, no new primitives are added. Existing primitives may still be pruned if they fail opacity checks, but no growth occurs.*

3.  **Score Candidates:** Assign a densification score to each candidate $G_i \in \mathcal{C}$. The score is typically the accumulated view-space positional gradient magnitude $|\nabla_{\mathbf{p}} \mathcal{L}|_i$ or a derived metric indicating reconstruction error [S1, 3034-adaptive-densification.md].

4.  **Select Top-K:** If $|\mathcal{C}| > N_{new}^{max}$, select only the $N_{new}^{max}$ candidates with the highest densification scores. Let this subset be $\mathcal{C}_{selected}$ [S1].
    [G] *If $|\mathcal{C}| \le N_{new}^{max}$, then $\mathcal{C}_{selected} = \mathcal{C}$.*

5.  **Spawn Primitives:** For each $G_i \in \mathcal{C}_{selected}$, perform the standard cloning or splitting operation defined in the parent [Density Control and Densification](5337-density-control-and-densification.md).
    *   **Cloning:** Create $G_{clone}$ at $\mathbf{p}_i$ with scale $\mathbf{s}_i$ and $\alpha_{clone} = \alpha_i / 2$.
    *   **Splitting:** Remove $G_i$. Create two new Gaussians with positions sampled from $\mathcal{N}(\mathbf{p}_i, \mathbf{S}_i)$, scales reduced by factor $1.2^{-1}$, and opacities halved.

6.  **Update Count:** Add the new primitives to $\mathcal{G}$.

**Pseudocode:**
```python
def primitives_growth_control(G, candidates, N_max, phi):
    """
    G: List of Gaussian primitives
    candidates: List of primitives eligible for densification
    N_max: Maximum allowed total primitives
    phi: Growth fraction (e.g., 0.05)
    """
    N = len(G)
    
    # Step 2: Check global limit
    if N >= N_max:
        return G  # No growth allowed
    
    # Step 1: Calculate budget
    budget = int(phi * N)
    
    # Step 4: Select top-K candidates
    if len(candidates) > budget:
        # Sort candidates by densification score (e.g., gradient magnitude) descending
        # Assume candidates have a 'score' attribute
        candidates.sort(key=lambda g: g.score, reverse=True)
        selected = candidates[:budget]
    else:
        selected = candidates
        
    # Step 5: Spawn primitives
    new_primitives = []
    for g in selected:
        # Perform cloning or splitting as defined in parent method
        # Here we assume a generic 'densify' function that returns new primitives
        # Cloning returns 1 primitive, Splitting returns 2 (and removes original)
        spawned = densify_primitive(g) 
        new_primitives.extend(spawned)
        
    # Remove original candidates that were split (if splitting was used)
    # Note: Cloning keeps the original. Splitting removes it.
    # This logic depends on the specific densification variant.
    # For simplicity, we assume 'densify_primitive' handles the removal/creation
    # and returns only the NEW primitives.
    
    # Step 6: Update
    G.extend(new_primitives)
    return G
```

## Subtopics

### [DashGaussian Primitive Growth Control](15744-dashgaussian-primitive-growth-control.md)
A variant that combines threshold-based selection with top-k selection to prevent primitive explosion while maintaining reconstruction quality.

## Operating characteristics
*   **Time Complexity:** $O(N \log N)$ or $O(N)$ depending on sorting implementation for selecting top-K candidates, where $N$ is the number of candidates. The growth limit check is $O(1)$.
*   **Memory Complexity:** Prevents memory overflow by capping $N$. The memory usage is bounded by $N_{max} \times \text{size\_per\_primitive}$.
*   **Strengths:** Guarantees memory safety; prevents "primitive explosion" in complex scenes; allows densification to remain active for longer training periods (e.g., 27k iterations vs 15k in standard 3DGS) without crashing [S1].
*   **Limitations:** May suppress densification in regions that would otherwise benefit from higher density if the budget is reached early; requires careful tuning of $N_{max}$ relative to scene complexity.
*   **When to use:** When training on high-resolution scenes or long-duration training schedules where standard adaptive densification leads to excessive memory usage.

## Background
Primitives Growth Control was introduced in "Revising Densification in Gaussian Splatting" [S1]. The authors observed that the standard Adaptive Densification Control (ADC) module could lead to unpredictable growth, eventually causing out-of-memory issues. They proposed a global limit and a fixed-fraction growth mechanism to stabilize the number of primitives. The method was evaluated on the Mip-NeRF 360 dataset, demonstrating stable primitive counts over extended training periods (27k iterations) compared to the baseline 3DGS (15k iterations) [S1].
