# Gaussian Splat Fragment Shader

Also called: 2D Gaussian Splat Fragment Evaluation, FGaussianSplatPS, Gaussian Alpha Cutoff, Gaussian Splat Pixel Shader, Over Operator, Pre-multiplied Alpha Blending, Splat Fragment Shader, splat.frag

## Overview
The Gaussian Splat Fragment Shader evaluates the 2D Gaussian probability density function (PDF) at each fragment of a screen-space quad to determine splat coverage and modulate fragment color [S1, S3, unofficial]. It composites the new splat over the existing framebuffer color using pre-multiplied alpha blending [S1, unofficial]. It is distinguished from its parent [Gaussian Splat Rendering (Screen-Space Quad)](2075-gaussian-splat-rendering-screen-space-quad.md) by performing the per-pixel alpha evaluation and blending logic directly in the fragment shader, handling transparency via alpha cutoffs and discarding fragments behind the camera or with negligible alpha [S1, S3, unofficial].

## How it works
**Inputs and Outputs:**
The shader receives vertex attributes passed from the vertex stage: `vColor` (a `vec4` containing RGBA color) and `vPosition` (a `vec2` containing the 2D position relative to the splat center in screen space) [S3, unofficial]. The output is `fragColor` (a `vec4`) written to the framebuffer [S3, unofficial]. The framebuffer pixel format is 32-bit BGRA packed as a `u32` [S1, unofficial].

**Data Structures and Layout:**
The framebuffer stores pixels as a `u32` integer [S1, unofficial]. The bit layout is: bits 0-7 for Blue (B), bits 8-15 for Green (G), bits 16-23 for Red (R), and bits 24-31 for Alpha (A) [S1, unofficial].

**Parameters:**
- `alpha_cutoff`: `f32 = 1.0/255.0`. Minimum alpha threshold to discard fragments [S1, unofficial].
- `whitePoint`: `f32 = 0.9`. Used for tone mapping [S3, unofficial].

**Steps:**
1. **Compute Squared Distance:** Calculate the squared distance $A$ from the splat center using the dot product of `vPosition` [S3, unofficial].
   $$ A = -\text{dot}(\mathbf{vPosition}, \mathbf{vPosition}) $$
   The standard 2D Gaussian PDF is $\alpha(u, v) = \alpha_0 \exp\left(-\frac{1}{2}(u^2 + v^2)\right)$ [S1, unofficial]. The implementation in [S3, unofficial] omits the 0.5 factor in $A$ and applies `exp(A)` directly, implying `vPosition` is scaled or the variance is normalized to 1 [S3, unofficial].

2. **Evaluate Gaussian Alpha:** Compute the Gaussian falloff using the distance value [S3, unofficial].
   $$ \text{gaussian} = \exp(A) $$
   $$ \text{edgeSmoothness} = \text{smoothstep}(-4.0, -3.5, A) $$
   $$ \alpha_{\text{new}} = \text{gaussian} \times \mathbf{vColor}.a \times \text{edgeSmoothness} $$
   [S3, unofficial]

3. **Alpha Cutoff:** Discard fragments where the computed alpha falls below the threshold [S1, unofficial]. The implementation in [S3, unofficial] uses a distance-based check `if A < -4.0` as a proxy for the alpha cutoff [S3, unofficial].

4. **Modulate Color:** Multiply the RGB channels by the computed alpha to produce pre-multiplied color output [S1, unofficial].
   $$ \mathbf{C}_{\text{premult}} = \alpha_{\text{new}} \times \mathbf{vColor}.rgb $$
   [S1, S3, unofficial]

5. **Post-Processing:** Apply implementation-specific color adjustments before blending [S3, unofficial].
   - **Saturation Adjustment:** Compute luminance $L = \text{dot}(\mathbf{C}_{\text{premult}}, \text{vec3}(0.2126, 0.7152, 0.0722))$, then $\mathbf{C}_{\text{sat}} = \text{mix}(\text{vec3}(L), \mathbf{C}_{\text{premult}}, 1.2)$ [S3, unofficial].
   - **White Point (Tone Mapping):** Apply $\mathbf{C}_{\text{tone}} = \mathbf{C}_{\text{sat}} \times \frac{1.0 + \mathbf{C}_{\text{sat}} / (\text{whitePoint} \times \text{whitePoint})}{1.0 + \mathbf{C}_{\text{sat}}}$ with $\text{whitePoint} = 0.9$ [S3, unofficial].
   - **Sharpening:** Apply $\mathbf{C}_{\text{final}} = \mathbf{C}_{\text{tone}}^{\text{vec3}(1.0 / 1.05)}$ [S3, unofficial].

6. **Read Existing Framebuffer:** Unpack the existing framebuffer pixel from BGRA `u32` format into a `vec4` of normalized floats [S1, unofficial].
   $$ \mathbf{C}_{\text{old}} = \text{vec4}\left( \frac{(\text{old\_color\_u32} \gg 16) \& 0xFF}{255.0}, \frac{(\text{old\_color\_u32} \gg 8) \& 0xFF}{255.0}, \frac{\text{old\_color\_u32} \& 0xFF}{255.0}, \frac{(\text{old\_color\_u32} \gg 24) \& 0xFF}{255.0} \right) $$
   [S1, unofficial]

7. **Composite (Over Operator):** Blend the new fragment over the old pixel using the over operator formula [S1, unofficial].
   $$ \mathbf{C}_{\text{out}} = (1 - \alpha_{\text{new}}) \mathbf{C}_{\text{old}}.rgb + \alpha_{\text{new}} \mathbf{C}_{\text{final}}.rgb $$
   [S1, unofficial]

8. **Quantize and Pack:** Quantize the blended RGB channels back to 8-bit integers and pack them into a `u32` BGRA pixel, discarding the alpha channel [S1, unofficial].
   $$ R = \lfloor \mathbf{C}_{\text{out}}.r \times 255.0 \rfloor, \quad G = \lfloor \mathbf{C}_{\text{out}}.g \times 255.0 \rfloor, \quad B = \lfloor \mathbf{C}_{\text{out}}.b \times 255.0 \rfloor $$
   $$ \text{output\_u32} = (R \ll 16) \mid (G \ll 8) \mid B $$
   [S1, unofficial]

**Pseudocode:**
```python
import math

def smoothstep(edge0: float, edge1: float, x: float) -> float:
    t = max(0.0, min(1.0, (x - edge0) / (edge1 - edge0)))
    return t * t * (3.0 - 2.0 * t)

def gaussian_splat_fragment_shader(
    vColor: tuple, 
    vPosition: tuple, 
    old_color_u32: int, 
    alpha_cutoff: float = 1.0/255.0, 
    whitePoint: float = 0.9
) -> int:
    # 1. Compute squared distance
    A = - (vPosition[0]**2 + vPosition[1]**2)

    # 2. Evaluate Gaussian Alpha
    edgeSmoothness = smoothstep(-4.0, -3.5, A)
    gaussian = math.exp(A)
    alpha_new = gaussian * vColor[3] * edgeSmoothness

    # 3. Alpha Cutoff
    if A < -4.0 or alpha_new < alpha_cutoff:
        return 0  # Discard / transparent

    # 4. Modulate Color
    color_premult = (vColor[0] * alpha_new, vColor[1] * alpha_new, vColor[2] * alpha_new)

    # 5. Post-Processing
    luminance = color_premult[0]*0.2126 + color_premult[1]*0.7152 + color_premult[2]*0.0722
    color_sat = (
        luminance + 1.2 * (color_premult[0] - luminance),
        luminance + 1.2 * (color_premult[1] - luminance),
        luminance + 1.2 * (color_premult[2] - luminance)
    )
    color_tone = tuple(c * (1.0 + c / (whitePoint * whitePoint)) / (1.0 + c) for c in color_sat)
    color_final = tuple(c ** (1.0 / 1.05) for c in color_tone)

    # 6. Read Existing Framebuffer
    old_r = ((old_color_u32 >> 16) & 0xFF) / 255.0
    old_g = ((old_color_u32 >> 8) & 0xFF) / 255.0
    old_b = (old_color_u32 & 0xFF) / 255.0
    old_a = ((old_color_u32 >> 24) & 0xFF) / 255.0

    # 7. Composite
    blended_r = (1.0 - alpha_new) * old_r + alpha_new * color_final[0]
    blended_g = (1.0 - alpha_new) * old_g + alpha_new * color_final[1]
    blended_b = (1.0 - alpha_new) * old_b + alpha_new * color_final[2]

    # 8. Quantize and Pack
    r = int(blended_r * 255.0)
    g = int(blended_g * 255.0)
    b = int(blended_b * 255.0)
    output_u32 = (r << 16) | (g << 8) | b
    return output_u32
```

## Subtopics

### [Oriented Ellipse Splatting](7934-oriented-ellipse-splatting.md)
Renders each Gaussian splat as an oriented ellipse in screen space, derived from its 3D rotation and 3-axis scale projected to a 2D covariance matrix, replacing the previous method of drawing round blobs sized by the largest axis. This approach improves visual fidelity by eliminating the "hazy" appearance of isotropic billboards and reduces overdraw, resulting in crisp edges and equal or better frame times. It differs from its parent [Gaussian Splat Fragment Shader](3258-gaussian-splat-fragment-shader.md) by explicitly computing the bounding quad from the covariance eigenvectors and evaluating the Gaussian kernel over the full anisotropic shape rather than a circular disc.

## Operating characteristics
- **Time Complexity:** $O(1)$ per fragment [S1, S3, unofficial].
- **Memory Complexity:** $O(1)$ per fragment [S1, S3, unofficial].
- **Measured Performance:** Not given in the sources.
- **Scaling:** Performance scales linearly with the number of fragments covered by splats [S1, S3, unofficial]. The alpha cutoff and distance checks help cull non-contributing fragments early [S1, S3, unofficial].
- **Strengths:** Simple to implement, efficient per-pixel evaluation, handles transparency via blending [S1, S3, unofficial].
- **Limitations:** Not given in the sources.
- **When to use:** When rendering 3D Gaussian splats as screen-space quads with a pre-sorted order buffer [S1, S3, unofficial].
- **When not to use:** When high-fidelity anisotropic edges are required (use [Oriented Ellipse Splatting](7934-oriented-ellipse-splatting.md)) [S1, unofficial].

## Background
The Gaussian Splat Fragment Shader is part of the rendering implementation for 3D Gaussian Splatting, a technique for novel view synthesis using 3D Gaussians [S1, S2, S3, unofficial]. The method of evaluating 2D Gaussians in the fragment shader is a standard approach in GPU-based splatting [S1, S3, unofficial]. The specific implementation details, such as the use of `smoothstep` for edge smoothing and tone mapping, are derived from unofficial implementations and plugins [S1, S2, S3, unofficial]. The parent method [Gaussian Splat Rendering (Screen-Space Quad)](2075-gaussian-splat-rendering-screen-space-quad.md) builds on this by handling the sorting and projection [S2, unofficial].
