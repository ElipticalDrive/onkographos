# Perspective-Correct 3D Gaussian Splatting via Plücker Coordinates

Also called: Hybrid 3D Gaussian Splatting intersection, Inversion-free splat evaluation, Matrix inversion-free ray-splat intersection, Perspective-Correct Ray-Splat Intersection, Plücker coordinate ray-splat intersection

## Overview
This method provides a numerically stable, matrix-inversion-free approach for evaluating 3D Gaussian splats along viewing rays in screen space, ensuring perspective correctness even for degenerate Gaussians [S1]. Unlike standard 3D Gaussian Splatting [Parent](13401-ray-splat-intersection-algorithms.md) which may suffer from numerical instabilities or approximations, this method extends Weyrich et al.'s optimization to full 3D non-degenerate Gaussians using Plücker coordinates to compute the squared Mahalanobis distance $\rho^2$ directly [S1]. It is distinguished from [3D Gaussian Ray Tracing](8101-3d-gaussian-ray-tracing.md) by its rasterization-based tile approach and from [QuadBox](9231-quadbox.md) by its explicit handling of 3D ellipsoids without reducing them to 2D projections [S1].

## How it works
**Inputs and Outputs**
*   **Inputs**: Per-Gaussian attributes (position $\boldsymbol{\mu}$, scale $s$, rotation $q$), Model-View matrix $\mathbf{M}$, Projection matrix $\mathbf{P}$, Viewport transform $\mathbf{V}$, Pixel coordinates $(x_s, y_s)$, and hyperparameter $\tau_\alpha$.
*   **Outputs**: The squared distance $\rho^2$ from the ray to the Gaussian center in normalized space, used to compute the Gaussian value $G(\mathbf{x})$ and opacity $\alpha$.

**Data Structures**
*   **Transformation Matrix $\mathbf{T}'$**: A $4 \times 4$ matrix mapping normalized splat space (where the ellipsoid is a unit sphere) to screen space.
*   **Plücker Coordinates**: A 6-dimensional representation of the ray in splat space, consisting of direction $\mathbf{d}$ and moment $\mathbf{m}$.
*   **Bounding Box**: A $3 \times 2$ array of screen-space coordinates $[b_1, t_1] \times [b_2, t_2] \times [b_3, t_3]$.

**Numbered Steps**

1.  **Compute Screen-Space Transformation $\mathbf{T}'$**:
    Construct the transformation from normalized splat space to screen space. Let $\mathbf{T}$ be the transformation from normalized splat space to world space. The full transformation $\mathbf{T}'$ is derived from the model-view matrix $\mathbf{M}$, projection matrix $\mathbf{P}$, and viewport transform $\mathbf{V}$.
    $$ \mathbf{T}' = \mathbf{V} \mathbf{P} \mathbf{M} \mathbf{T} $$
    [G: In practice, $\mathbf{T}$ is constructed from the Gaussian's scale and rotation parameters such that it maps the unit sphere to the Gaussian's ellipsoid in world space.]

2.  **Compute Tight 3D Axis-Aligned Bounding Box (AABB)**:
    Calculate the screen-space bounding box $[b_i, t_i]$ for $i \in \{1, 2, 3\}$ (corresponding to x, y, z) using the rows of $\mathbf{T}'$. Let $\mathbf{T}'_i$ be the $i$-th row of $\mathbf{T}'$. Let $\mathbf{c}$ be the center of the unit sphere in normalized splat space (typically $\mathbf{0}$). Let $\mathbf{r}$ be the radius vector of the unit sphere (typically $\mathbf{1}$).
    
    The bottom and top bounds are computed as:
    $$ b_i = \langle \mathbf{T}'_i, \mathbf{c} - \mathbf{r} \rangle - \|\mathbf{T}'_i \odot \mathbf{r}\|_1 $$
    $$ t_i = \langle \mathbf{T}'_i, \mathbf{c} + \mathbf{r} \rangle + \|\mathbf{T}'_i \odot \mathbf{r}\|_1 $$
    [Note: The source [S1] references formulas (4)-(9) involving component-wise multiplication $\odot$ and dot products. The specific formulation for the tight bounding box of an ellipsoid transformed by $\mathbf{T}'$ relies on the support function. For a unit sphere, the extent in direction $\mathbf{u}$ is $\|\mathbf{T}'^T \mathbf{u}\|$. However, the source explicitly states the use of Weyrich et al.'s optimization extended to non-degenerate Gaussians. A precise implementation requires the exact vector algebra defined in Weyrich et al. [WHA*07] applied to $\mathbf{T}'$. The source notes that this is a closed-form solution without matrix inversion.]
    
    Additionally, compute an individual cutoff value for the bounding box based on opacity $\alpha$ and $\tau_\alpha$. If $\alpha < 1$, shrink the box to exclude regions where the Gaussian value is below a threshold defined by $\tau_\alpha$.

3.  **Represent Viewing Ray as Planes**:
    For a pixel at screen coordinates $(x_s, y_s)$, define two perpendicular planes in screen space:
    $$ \pi_x = (1, 0, 0, -x_s)^\top $$
    $$ \pi_y = (0, 1, 0, -y_s)^\top $$
    These planes are represented as homogeneous vectors $\mathbf{p} = (a, b, c, d)^\top$ such that $\mathbf{p}^\top \mathbf{x} = 0$ for points $\mathbf{x}$ on the plane.

4.  **Transform Planes to Splat Space**:
    Transform $\pi_x$ and $\pi_y$ into the normalized splat space using the inverse-transposed mapping of the transformation matrix. Let $\mathbf{W} = (\mathbf{V} \mathbf{P} \mathbf{M} \mathbf{T})^{-1}$. To avoid explicit matrix inversion, use the property that plane transforms use the inverse-transpose:
    $$ \pi_{sx} = (\mathbf{W}^{-1})^\top \pi_x = (\mathbf{V} \mathbf{P} \mathbf{M} \mathbf{T})^\top \pi_x $$
    $$ \pi_{sy} = (\mathbf{W}^{-1})^\top \pi_y = (\mathbf{V} \mathbf{P} \mathbf{M} \mathbf{T})^\top \pi_y $$
    [G: In code, this is a matrix-vector multiplication. Let $\mathbf{M}_{total} = \mathbf{V} \mathbf{P} \mathbf{M} \mathbf{T}$. Then $\pi_{sx} = \mathbf{M}_{total}^\top \pi_x$.]

5.  **Compute Dual Plücker Coordinates**:
    The viewing ray in splat space is the intersection of planes $\pi_{sx}$ and $\pi_{sy}$. Let the coefficients of the planes be:
    $$ \pi_{sx} = (a_1 : a_2 : a_3 : a_0) $$
    $$ \pi_{sy} = (b_1 : b_2 : b_3 : b_0) $$
    The dual Plücker coordinates $\mathcal{L}_s^*$ of the line are computed from the coefficients:
    $$ \mathcal{L}_s^* = ( \mathbf{m} \mid \mathbf{d} ) $$
    Where the moment $\mathbf{m}$ and direction $\mathbf{d}$ components are derived from the cross products of the plane coefficients. Specifically, for two planes $\mathbf{p}_1=(\mathbf{n}_1, d_1)$ and $\mathbf{p}_2=(\mathbf{n}_2, d_2)$:
    $$ \mathbf{d} = \mathbf{n}_1 \times \mathbf{n}_2 $$
    $$ \mathbf{m} = d_2 \mathbf{n}_1 - d_1 \mathbf{n}_2 $$
    [S1: Eq. (11) and (12) define the dual Plücker coordinates from the plane coefficients.]

6.  **Compute Squared Distance $\rho^2$**:
    The squared distance from the ray to the origin (which corresponds to the Gaussian center in normalized space) is given by:
    $$ \rho^2 = \frac{\|\mathbf{m}\|^2}{\|\mathbf{d}\|^2} $$
    [S1: Eq. (15).]
    
    **Edge Cases and Pitfalls**:
    *   **Degenerate Splats**: If one or more principal axes of the Gaussian vanish, the ellipsoid becomes degenerate (2D or 1D). This method remains numerically stable because it avoids matrix inversions [S1].
    *   **Ray Miss**: If $\|\mathbf{d}\| \approx 0$, the denominator vanishes. This indicates the ray does not intersect the splat's effective volume (or is parallel to the normal of the planes in a way that yields no unique line in the context of the bounding box). This case is detected and handled by skipping the splat [S1].

**Pseudocode**

```python
import numpy as np

def compute_gaussian_ray_intersection(gaussian, M, P, V, x_s, y_s, tau_alpha):
    """
    Compute the squared distance rho^2 for a 3D Gaussian splat along a viewing ray.
    
    Args:
        gaussian: Object with attributes .position (mu), .scale (s), .rotation (q).
        M: 4x4 Model-View matrix.
        P: 4x4 Projection matrix.
        V: 4x4 Viewport transform.
        x_s, y_s: Pixel screen coordinates.
        tau_alpha: Hyperparameter for opacity cutoff.
        
    Returns:
        rho_sq: Squared Mahalanobis distance.
        alpha: Computed opacity (optional, depends on rho_sq).
    """
    
    # 1. Construct Transformation T' from normalized splat space to screen space
    # T maps unit sphere to Gaussian ellipsoid in world space
    # Construct T from scale and rotation
    s = gaussian.scale
    q = gaussian.rotation
    
    # Rotation matrix from quaternion q
    R = quaternion_to_rotation_matrix(q)
    
    # Scale matrix
    S = np.diag(np.concatenate([s, [1.0]]))
    
    # Translation matrix from position mu
    T_trans = np.eye(4)
    T_trans[:3, 3] = gaussian.position
    
    # T = T_trans * R * S (Order depends on convention; usually scale/rot then trans)
    # Normalized splat space -> World space
    T = np.eye(4)
    T[:3, :3] = R @ np.diag(s)
    T[:3, 3] = gaussian.position
    
    # Total transformation T' = V * P * M * T
    T_prime = V @ P @ M @ T
    
    # 2. Compute Bounding Box (Simplified for ray intersection context, 
    # though bounding box is primarily for culling)
    # Using Weyrich et al. optimization extended to 3D
    # Rows of T_prime
    T_prime_rows = [T_prime[i, :] for i in range(3)] # Rows 0, 1, 2 for x, y, z
    
    # Center and radius in normalized space (unit sphere)
    c = np.array([0.0, 0.0, 0.0, 1.0])
    r = np.array([1.0, 1.0, 1.0, 1.0]) # Extent
    
    # Calculate bounds b_i, t_i
    # Note: Exact formula from source involves component-wise multiplication and dot products
    # b_i = <T'_i, c - r> - ||T'_i o r||_1
    # t_i = <T'_i, c + r> + ||T'_i o r||_1
    # This is used for culling, not strictly for rho^2 calculation but part of the method
    
    # 3. Represent Ray as Planes in Screen Space
    # pi_x = (1, 0, 0, -x_s)
    # pi_y = (0, 1, 0, -y_s)
    pi_x = np.array([1.0, 0.0, 0.0, -x_s])
    pi_y = np.array([0.0, 1.0, 0.0, -y_s])
    
    # 4. Transform Planes to Splat Space using Inverse-Transpose of T'
    # Since we want to transform planes from screen to splat space, we use (T')^-T
    # However, source says: "transform ... by (VPMT)^-1 ... requires inverse-transposed mapping"
    # And "sidestepping inversion" by using M_total^T
    # Let M_total = V @ P @ M @ T = T_prime
    # Plane transform p' = M^T p
    M_total_T = T_prime.T
    
    pi_sx = M_total_T @ pi_x
    pi_sy = M_total_T @ pi_y
    
    # 5. Compute Dual Plücker Coordinates from Intersection of Planes
    # pi_sx = (a1, a2, a3, a0)
    # pi_sy = (b1, b2, b3, b0)
    a = pi_sx[:3]
    a0 = pi_sx[3]
    b = pi_sy[:3]
    b0 = pi_sy[3]
    
    # Direction d = a x b
    d = np.cross(a, b)
    
    # Moment m = b0 * a - a0 * b
    m = b0 * a - a0 * b
    
    # 6. Compute Squared Distance rho^2
    d_norm_sq = np.dot(d, d)
    
    # Handle degenerate case / ray miss
    if d_norm_sq < 1e-9:
        return None, None # Ray misses splat or is degenerate
        
    m_norm_sq = np.dot(m, m)
    rho_sq = m_norm_sq / d_norm_sq
    
    # Compute Alpha from Gaussian density G(x) = exp(-0.5 * rho_sq)
    # Note: In 3DGS, the exponent is often -0.5 * rho^2
    alpha = np.exp(-0.5 * rho_sq)
    
    # Apply opacity cutoff if necessary
    if alpha < tau_alpha:
        return None, None
        
    return rho_sq, alpha

def quaternion_to_rotation_matrix(q):
    """Convert quaternion [w, x, y, z] to 3x3 rotation matrix."""
    w, x, y, z = q
    n = np.sqrt(w**2 + x**2 + y**2 + z**2)
    w, x, y, z = w/n, x/n, y/n, z/n
    
    xx, yy, zz = x*x, y*y, z*z
    xy, xz, yz = x*y, x*z, y*z
    wx, wy, wz = w*x, w*y, w*z
    
    R = np.array([
        [1 - 2*(yy + zz),     2*(xy - wz),       2*(xz + wy)],
        [2*(xy + wz),         1 - 2*(xx + zz),   2*(yz - wx)],
        [2*(xz - wy),         2*(yz + wx),       1 - 2*(xx + yy)]
    ])
    return R
```

## Operating characteristics
*   **Time Complexity**: The method incurs reduced setup costs per Gaussian compared to methods requiring matrix inversion but has slightly higher costs per pixel due to the Plücker coordinate calculations [S1]. This trade-off is desirable when primitives cover few pixels [S1].
*   **Memory Complexity**: Requires storing the transformation matrix $\mathbf{T}'$ and Plücker coordinates temporarily. No large auxiliary data structures like sparse voxel grids are required for the intersection step itself.
*   **Numerical Stability**: Highly stable. It avoids matrix inversions entirely, remaining robust even for degenerate splats where one or more principal axes vanish [S1].
*   **Strengths**: Perspective-correct rendering; handles degenerate 3D Gaussians; no matrix inversion; closed-form bounding box computation.
*   **Limitations**: Slightly higher per-pixel computational cost compared to approximate methods. Relies on correct construction of the transformation matrix $\mathbf{T}'$ from scale and rotation.
*   **When to Use**: When perspective correctness is critical and degenerate Gaussians are expected during training or rendering. Preferred over [3D Gaussian Ray Tracing](8101-3d-gaussian-ray-tracing.md) for rasterization pipelines where tile-based rendering is used.

## Background
This method was introduced in *Efficient Perspective‐Correct 3D Gaussian Splatting Using Hybrid Transparency* [S1]. It extends the work of Weyrich et al. [WHA*07] and Sigg et al. [SWBG06], which provided perspectively accurate rendering for 2D Gaussian splats, to non-degenerate 3D Gaussians. The approach addresses the numerical instabilities found in standard 3D Gaussian Splatting [KKLD23] (Eq. 1) and concurrent works like [YSG24] and [MLMP*24] which may suffer from matrix inversion issues. It is also more general than Huang et al. [HYC*24], which only supports 2D (degenerate) Gaussians.
