# Surface Normal Rendering via External Channel

Also called: External Channel Normal Rendering, PyTorch3D Normal Rendering for Gaussians

## Overview
This method enables the rendering of surface normals from 3D Gaussian Splatting representations by treating normals as an additional attribute in an external channel, since Gaussian ellipsoids natively represent volume rather than surface geometry [S1, unofficial]. It provides the rendering mechanism for normals, whereas sibling methods like [Normal Field Supervision via Rendering and Depth Derivatives](9627-normal-field-supervision-via-rendering-and-depth-derivatives.md) focus on loss supervision [G].

## How it works
**Inputs:**
*   A set of Gaussian ellipsoids $\{G_i\}$, where each $G_i$ is defined by a mean $\mu_i$, a covariance matrix $\Sigma_i$ (or rotation $R_i$ and scale $S_i$), and a base color $C_i$ [G].
*   For each Gaussian, a surface normal vector $n_i \in \mathbb{R}^3$ with $\|n_i\|=1$ [S1, unofficial].
*   Camera parameters (view and projection matrices) [G].

**Outputs:**
*   A rendered normal map $N_{img}(u,v) \in \mathbb{R}^3$ per pixel $(u,v)$ [S1, unofficial].
*   Optionally, a rendered color map with lighting applied [S1, unofficial].

**Data Structures:**
*   **Gaussian Attributes:** Each Gaussian $i$ stores a 3D vector attribute $A_i$ for the normal [S1, unofficial]. In the implementation described in [S1, unofficial], this normal vector is encoded as an RGB color value for the vertex/Gaussian. Specifically, the normal components $(n_x, n_y, n_z)$ are mapped to the red, green, and blue channels respectively [S1, unofficial]. Since normals range from $[-1, 1]$, they are typically mapped to $[0, 1]$ for storage in standard image formats or tensors if not using signed float textures [G].
*   **Render Buffer:** An image buffer of size $H \times W \times 3$ to accumulate the interpolated normal values [G].

**Steps:**
1.  **Normal Computation (Initialization):** If the Gaussians are derived from a mesh (e.g., from The Stanford 3D Scanning Repository), compute the surface normal $n_i$ for each vertex or Gaussian center using a library such as PyTorch3D [S1, unofficial].
2.  **Attribute Assignment:** Assign the computed normal $n_i$ to the Gaussian $i$'s external channel. In the specific implementation cited, this is done by setting the Gaussian's "RGB" attribute to the normal vector components [S1, unofficial].
3.  **Rendering (Alpha Blending):** Render the Gaussians using the standard volume rendering equation for the external channel. For a pixel $p$, the rendered normal $N_p$ is the alpha-blended average of the normals of all overlapping Gaussians sorted by depth:
    $$ N_p = \sum_{i \in \text{sorted}} \alpha_i n_i \prod_{j < i} (1 - \alpha_j) $$
    where $\alpha_i$ is the opacity of Gaussian $i$ at pixel $p$ [G]. Note: The source [S1, unofficial] describes interpolating the RGB value (normals) into images, implying standard alpha compositing of the normal vectors.
4.  **Lighting Integration (Optional):** To apply lighting, first render the surface normals into an image-like map as described in Step 3. Then, use a diffuse lighting function (e.g., `PyTorch3D.renderer.lighting`) to compute the brightness under a point light source using the rendered normals and a predefined light position [S1, unofficial].

**Pseudocode:**
```python
import torch

def composite_normals(sorted_indices, opacities, mapped_normals):
    """Alpha-blend normals for a single pixel given sorted Gaussians."""
    if len(sorted_indices) == 0:
        return torch.zeros(3)
    alpha = opacities[0]
    color = mapped_normals[0]
    for i in range(1, len(sorted_indices)):
        alpha_i = opacities[i]
        color = color * (1 - alpha_i) + mapped_normals[i] * alpha_i
        alpha = alpha * (1 - alpha_i)
    return color

def render_normals_with_lighting(gaussians, camera, light_position):
    """
    Render surface normals from Gaussians and apply diffuse lighting.
    """
    means_3d = torch.stack([g.mean for g in gaussians])
    covariances = torch.stack([g.covariance for g in gaussians])
    normals = torch.stack([g.normal for g in gaussians])
    
    # Map normals from [-1, 1] to [0, 1]
    normals_mapped = (normals + 1.0) / 2.0 
    
    # Project Gaussians to screen space and sort by depth per pixel.
    # This step is handled by the differentiable volume renderer's rasterization pass.
    # For each pixel, we obtain sorted Gaussian indices, their opacities, and mapped normals.
    # We assume `rasterize_gaussians` returns these lists per pixel.
    pixel_data = rasterize_gaussians(means_3d, covariances, normals_mapped, camera)
    
    normal_map = torch.zeros(H, W, 3)
    for y in range(H):
        for x in range(W):
            indices, opacities, mapped_n = pixel_data[y, x]
            normal_map[y, x] = composite_normals(indices, opacities, mapped_n)
            
    # Convert normal map back to [-1, 1] range
    normals_unmapped = normal_map * 2.0 - 1.0
    
    # Normalize normals for lighting
    normals_unmapped = torch.nn.functional.normalize(normals_unmapped, dim=-1)
    
    # Compute diffuse lighting
    # Approximate surface points from depth or assume flat surface at z=0
    # Light direction from surface to light
    light_dir = light_position - normal_map
    light_dir = torch.nn.functional.normalize(light_dir, dim=-1)
    diffuse = torch.clamp(torch.sum(normals_unmapped * light_dir, dim=-1, keepdim=True), min=0.0)
    lit_color = diffuse * torch.ones_like(normals_unmapped)
    
    return normal_map, lit_color
```

**Edge Cases and Pitfalls:**
*   **Boundary Fuzziness:** The rendered normals may have slightly fuzzier boundaries compared to a mesh renderer because Gaussians are volumetric [S1, unofficial].
*   **Coordinate Systems:** Ensure consistent coordinate systems between the mesh normal computation (PyTorch3D) and the rendering pipeline [G].

## Subtopics

### [Learnable Normals Parameterization](9615-learnable-normals-parameterization.md)
A parameterization for learnable surface normals of Gaussians that uses a sign scalar and a direction vector to stabilize optimization and allow normal flipping without rotation. It solves the instability inherent in naive vector parameterization, where flipping a normal requires a 180-degree rotation that causes convergence to inaccurate local minima. It sets itself apart from sibling methods like [Normal Field Supervision via Rendering and Depth Derivatives](9627-normal-field-supervision-via-rendering-and-depth-derivatives.md) by explicitly modifying the Gaussian's internal attribute representation rather than relying on external gradient supervision.

### [Normal Field Supervision via Rendering and Depth Derivatives](9627-normal-field-supervision-via-rendering-and-depth-derivatives.md)
This method supervises the learnable surface normal field of a 3D Gaussian Splatting representation by enforcing geometric consistency between the rendered normal maps and the spatial derivatives of the rendered depth map. While [Surface Normal Rendering via External Channel](2099-surface-normal-rendering-via-external-channel.md) provides the mechanism to render normals as an external attribute, this method provides the loss signal. It differs from sibling methods like [Learnable Normals Parameterization](9615-learnable-normals-parameterization.md) by relying on self-supervision from the scene's own depth geometry rather than external pseudo-normal targets or lighting priors.

### Rendering Normal Field with Gaussians
This variant focuses on approximating the integral of the normal field along the ray by attributing a single value $N_i$ per Gaussian [S2]. For a vector field $V$, it selects $V_i$ proportional to the integral of the i-th term of the sum multiplied by the normalized density of the Gaussian [S2]. Due to symmetry around $n_i$, $V_i \propto n_i$, and thus the normalized vector field $N_i \sim n_i$ [S2]. This allows rendering plane normals $n_i$ with Gaussian splatting to estimate the average normal field value [S2]. The integral is defined as:
$$ V_i \propto \int_{\mathbb{R}^3} G_i(x) \cdot \mathbf{1}_{n_i^T(x-\mu_i) \geq 0} \nabla \log(1 - G_i(x)) dx $$
[S2]

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of Gaussians $N$ and pixels $P$, similar to standard Gaussian Splatting rendering $O(N \cdot P)$ or $O(N + P)$ depending on implementation details like spatial hashing [G].
*   **Memory Complexity:** $O(N)$ to store the additional normal attribute per Gaussian [G].
*   **Performance:** Rendering quality improves significantly with the number of Gaussians [S1, unofficial]. However, VoGE renderer gives slightly fuzzier boundaries compared to mesh renderers [S1, unofficial].
*   **Strengths:** Enables lighting integration and normal-based supervision for Gaussian Splatting, which natively lacks surface information [S1, unofficial].
*   **Limitations:** Normals are an approximation derived from the volumetric representation; boundaries are fuzzier than explicit mesh rendering [S1, unofficial].

## Background
This method was introduced in the context of VoGE (Volume Gaussian Ellipsoids), a differentiable volume renderer using Gaussian ellipsoids for analysis-by-synthesis [S1, unofficial]. It was developed to bridge the gap between volumetric Gaussian representations and surface-based analysis tasks like lighting and normal supervision. The approach leverages PyTorch3D for normal computation and lighting [S1, unofficial].
