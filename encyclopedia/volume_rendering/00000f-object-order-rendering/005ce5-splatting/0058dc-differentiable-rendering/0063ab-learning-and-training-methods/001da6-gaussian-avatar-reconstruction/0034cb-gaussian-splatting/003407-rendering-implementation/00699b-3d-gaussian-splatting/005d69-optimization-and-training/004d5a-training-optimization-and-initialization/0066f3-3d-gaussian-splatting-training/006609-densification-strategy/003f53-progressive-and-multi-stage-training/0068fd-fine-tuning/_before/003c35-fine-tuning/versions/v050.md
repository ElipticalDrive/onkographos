# Fine-tuning

Also called: 3DGS Fine-tuning, Fine-tuning Strategy, Gaussian Splatting Fine-tuning

## Overview
Fine-tuning in the context of 3D Gaussian Splatting (3DGS) refers to the phase of training optimization where a pre-initialized or pre-trained representation is refined to achieve high-fidelity novel view synthesis. It solves the problem of adapting generic or sparse initial Gaussian primitives to specific scene details by optimizing geometry, color, and opacity attributes, often while enabling dynamic densification (growing/pruning) [S2]. It sets itself apart from initial training by leveraging prior knowledge (e.g., from ImageNet or a feed-forward predictor) to accelerate convergence and improve quality, distinguishing it from sibling methods like [Hybrid Coarse-to-Fine Strategy](7173-hybrid-coarse-to-fine-strategy.md) which may use different initialization or loss structures, and [Training Objective and Densification](7448-training-objective-and-densification.md) which focuses on the core densification mechanics rather than the transfer learning aspect [S2, S5].

## How it works
The fine-tuning process generally begins with an initial set of 3D Gaussian primitives $\mathcal{G}$, which may be generated via a feed-forward network or derived from Structure-from-Motion (SfM) points. The core mechanism involves optimizing the parameters of these Gaussians ($\mu_k, \Sigma_k, \alpha_k, \mathbf{c}_k$) using gradient descent, often with specific strategies to handle the unique properties of Gaussian splats compared to neural radiance fields (NeRFs) [S2, S6].

### Inputs and Outputs
*   **Inputs:** Pre-trained model weights (e.g., from a 3D generator or ImageNet), initial Gaussian primitives (geometry and color), input images/poses, and optimization hyperparameters (learning rate, iterations).
*   **Outputs:** Optimized Gaussian primitives with refined attributes suitable for rendering.

### Data Structures
The data structure remains the standard 3DGS primitive set:
*   $\mu_k \in \mathbb{R}^3$: Mean position.
*   $\Sigma_k \in \mathbb{R}^{3 \times 3}$: Covariance matrix, parameterized by scale $s_k \in \mathbb{R}^3$ and rotation $q_k \in \mathbb{R}^4$ (quaternion).
*   $\alpha_k \in [0, 1]$: Opacity.
*   $\mathbf{c}_k$: Spherical Harmonic (SH) coefficients.

### Steps
1.  **Initialization:** Generate or load initial Gaussian primitives. In feed-forward fine-tuning (e.g., EVolSplat), a network predicts initial $\mu, \Sigma, \alpha, \mathbf{c}$ directly from input views [S2]. In backbone fine-tuning, a pre-trained 3D generator (e.g., tri-plane based) is copied [S6].
2.  **Optimization Loop:**
    *   Render images from current Gaussians using differentiable rasterization.
    *   Compute loss (typically L1 + SSIM, possibly with entropy or regularization terms) [S2, S6].
    *   Backpropagate gradients to update Gaussian attributes and/or backbone weights [S2, S6].
3.  **Densification/Pruning (Optional but Common):** Enable growing and pruning of primitives during fine-tuning to reduce redundancy and fill gaps. This involves:
    *   **Cloning/Splitting:** Based on gradient magnitude or rendering error [S2, S4].
    *   **Pruning:** Removing low-opacity Gaussians [S2].
4.  **Convergence:** Iterate until the desired PSNR/SSIM is reached or a fixed iteration count is met.

### Formulas
*   **Rendering:** Color $\mathbf{C}$ is computed via alpha compositing:
    $$ \mathbf{C} = \sum_{i \in N} \mathbf{c}_i \alpha_i \prod_{j=1}^{i-1} (1 - \alpha_j) $$
    where $N$ are the 2D Gaussians overlapping the pixel [S3, S4].
*   **Opacity Rendering:**
    $$ O = \sum_{i \in N} \alpha_i \prod_{j=1}^{i-1} (1 - \alpha_j) $$
    [S3]
*   **Loss Function (Standard):**
    $$ \mathcal{L} = \lambda_{color} \mathcal{L}_1(\hat{C}, C) + \lambda_{SSIM} \mathcal{L}_{SSIM}(\hat{C}, C) $$
    [S6]
*   **Loss Function (SLAM/Regularized):**
    $$ \mathcal{L}_{mapping} = \lambda_{color} |\hat{C} - C| + \lambda_{depth} |\hat{D} - D| + \lambda_{SSIM} SSIM(\hat{C}, C) $$
    [S3]

### Parameters
*   **Learning Rate:** $1 \times 10^{-3}$ is common for fine-tuning [S2, S5].
*   **Iterations:** Naive fine-tuning may run for 10,000 steps [S5]. EVolSplat uses Adam optimizer with LR $1 \times 10^{-3}$ [S2].
*   **Thresholds (for densification):**
    *   Opacity threshold $\tau_{opa}$: Regions with $O(x,y) < \tau_{opa}$ are densified [S3].
    *   Depth error threshold $\tau_{depth}$: Regions with $E_{depth}(x,y)/D(x,y) > \tau_{depth}$ are densified [S3].
    *   Color error threshold $\tau_{color}$: Regions with $E_{color}(x,y) > \tau_{color}$ are densified [S3].

### Pseudocode
```python
def fine_tune_3dgs(initial_gaussians, images, poses, config):
    """
    Fine-tune 3D Gaussian Splatting from initial primitives.
    
    Args:
        initial_gaussians: List of Gaussian primitives (mu, sigma, alpha, c)
        images: List of input images
        poses: List of camera poses
        config: Dictionary with learning_rate, iterations, thresholds, etc.
        
    Returns:
        Optimized list of Gaussian primitives
    """
    gaussians = copy(initial_gaussians)
    optimizer = Adam(gaussians.parameters(), lr=config.learning_rate)
    
    for step in range(config.iterations):
        # 1. Sample a random image/pose pair
        idx = random_index(len(images))
        image = images[idx]
        pose = poses[idx]
        
        # 2. Render the image
        rendered_color, rendered_depth, rendered_opacity = render(gaussians, pose)
        
        # 3. Compute Loss
        loss_color = L1_loss(rendered_color, image.color)
        loss_ssim = SSIM_loss(rendered_color, image.color)
        loss = config.lambda_color * loss_color + config.lambda_ssim * loss_ssim
        
        # Optional: Add depth loss if depth is available
        if image.has_depth:
            loss_depth = L1_loss(rendered_depth, image.depth)
            loss += config.lambda_depth * loss_depth
            
        # Optional: Add regularization (e.g., entropy)
        if config.use_entropy:
            loss_entropy = Entropy_loss(gaussians.opacity)
            loss += config.lambda_entropy * loss_entropy
            
        # 4. Backpropagate and Update
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        
        # 5. Densification/Pruning (if enabled)
        if step % config.refine_every == 0 and config.enable_densification:
            gaussians = densify_and_prune(gaussians, rendered_opacity, rendered_color, image.color, config)
            
    return gaussians

def densify_and_prune(gaussians, rendered_opacity, rendered_color, gt_color, config):
    """
    Perform densification and pruning based on rendering metrics.
    """
    new_gaussians = []
    
    for g in gaussians:
        # Pruning: Remove low opacity Gaussians
        if g.opacity < config.opacity_threshold:
            continue
            
        # Densification: Check for holes or high error
        # Note: This is a simplified per-Gaussian check; in practice, 
        # error is often computed per-pixel and mapped back to Gaussians.
        
        # Check for holes (low opacity contribution)
        # In a full implementation, we would check the rendered opacity map
        # and identify Gaussians contributing to low-opacity regions.
        
        # Check for high error
        # Compute error at pixels covered by this Gaussian
        error = compute_error(g, rendered_color, gt_color)
        
        if error > config.error_threshold:
            # Split or Clone
            children = split_gaussian(g)
            new_gaussians.extend(children)
        else:
            new_gaussians.append(g)
            
    return new_gaussians
```

### Edge Cases and Pitfalls
*   **Overfitting:** In continuous mapping (SLAM), Gaussians may overfit to the latest frame, causing "forgetting" of previous frames. Regularization terms (e.g., SSIM, entropy) are needed to alleviate this [S3].
*   **Sparse Initialization:** If initial SfM points are sparse (e.g., sky, distant areas), standard densification may fail to populate these regions. Hybrid approaches or supplementary point addition may be required [S4, S12323-supplementary-point-addition-for-sparse-point-clouds.md].
*   **Parameter Coupling:** High-opacity floaters can attenuate gradients to true surfaces. Post-training reorganization (ReorgGS) can help by resampling from the empirical distribution [S16968-equivalent-distribution-reorganization.md].

## Subtopics

### [Exponentially Ascending Gradient Threshold](9684-exponentially-ascending-gradient-threshold.md)
A densification control mechanism that uses an exponentially ascending gradient threshold to regulate splitting and cloning. It allows aggressive densification when few Gaussians exist and restricts it as the scene becomes dense, solving the trade-off between early-stage convergence speed and late-stage overfitting.

### [SplatFormer Training Objective & Refinement](11745-splatformer-training-objective-refinement.md)
A learning-based, feed-forward 3D neural module that refines initial 3DGS representations to enable robust novel view synthesis from out-of-distribution (OOD) camera angles. It applies a point transformer network to predict attribute residuals, addressing the bias of standard 3DGS optimization which overfits to input views.

### [MCMC-based 3DGS / SGLD for 3DGS](11917-mcmc-based-3dgs-sgld-for-3dgs.md)
Reforms 3DGS by treating Gaussians as MCMC samples from an underlying probability distribution. It converts updates into Stochastic Gradient Langevin Dynamics (SGLD) by adding noise, removing the need for manual densification heuristics like cloning and splitting.

### [Deblurring 3D Gaussian Splatting](12318-deblurring-3d-gaussian-splatting.md)
A real-time deblurring framework that reconstructs sharp 3D scenes from blurry input images by manipulating covariance matrices and means using a small MLP. It handles defocus and camera motion blur, addressing sparse point clouds caused by blurry inputs.

### [Supplementary Point Addition for Sparse Point Clouds](12323-supplementary-point-addition-for-sparse-point-clouds.md)
A densification technique that explicitly injects synthetic points into empty or sparse regions after a fixed number of training iterations. It compensates for the sparsity of 3D Gaussians at the far end of scenes with large depth of field, where SfM extraction is poor.

### [Augmented Radiance Field](13218-augmented-radiance-field.md)
A post-enhancement framework that improves 3DGS by adding Gaussian kernels with view-dependent opacity to explicitly model specular components. It solves the problem that standard SH cannot decouple diffuse and specular radiance, leading to poor reconstruction of sharp highlights.

### [Frequency Regularization for Densification](13484-frequency-regularization-for-densification.md)
Addresses over-reconstruction by minimizing the discrepancy between the frequency spectrum of the rendered image and the ground truth in Fourier space. This increases pixel gradients within over-reconstruction regions, enabling coarse-to-fine densification.

### [Error-Guided Redistribution](14037-error-guided-redistribution.md)
A family of strategies that dynamically adjusts the spatial distribution of Gaussian primitives based on rendering errors or gradient magnitudes. It targets regions with persistent coarse-scale errors or "hard" gradients, either by reallocating a fixed budget or growing defective primitives.

### CoherentGS
A regularized optimization method for sparse novel view synthesis that introduces structural coherency by constraining Gaussian movement in 2D image space. It solves instability and "needle-like" artifacts in standard 3DGS when trained on extremely sparse input views [S1].

### [Pruning and Sparsity Control](14431-pruning-and-sparsity-control.md)
Methods that reduce the number of active 3D Gaussians to lower memory consumption and storage requirements while maintaining rendering quality. They actively eliminate redundant primitives throughout the optimization process using explicit geometric or volume-based criteria.

### [Rendering-Free Pruning via Hessian Importance](14447-rendering-free-pruning-via-hessian-importance.md)
A post-processing framework that identifies and removes unimportant Gaussian primitives without performing forward rendering passes. It quantifies primitive importance using an analytically approximated Hessian field, achieving significant speedups in device latency.

### [GoF-based Dynamic 3DGS Video Construction](14770-gof-based-dynamic-3dgs-video-construction.md)
Constructs dynamic 3DGS video by temporally segmenting input sequences into Groups of Frames (GoFs) and independently training Gaussian deformation fields within each segment. It solves motion drift and geometric inconsistencies in long-range temporal dependencies.

### [Two-stage Optimization](14857-two-stage-optimization.md)
A training protocol that decouples geometric and appearance optimization from material and lighting decomposition. It prevents the entanglement of distinct physical properties during early training by introducing normal gradient-based densification and PBR-specific loss terms.

### [TIP-Editor](14859-tip-editor.md)
A method for editing existing 3DGS scenes using intuitive text and image prompts. It combines a stepwise 2D personalization strategy with score distillation sampling (SDS), integrating LoRA for reference image alignment and a dedicated localization loss.

### StylizedGS
A controllable 3D stylization method that performs color matching with a reference style image while utilizing a 3DGS filter to remove artifacts. It optimizes for nearest neighbor feature matching and depth preservation [S1].

### [SGD (Street View Synthesis with Gaussian Splatting and Diffusion Prior)](15522-sgd-street-view-synthesis-with-gaussian-splatting-and-diffus.md)
Enhances 3DGS by fine-tuning a Stable Diffusion model on driving data and using it to regularize 3DGS training at unseen viewpoints. It addresses the sparse-view reconstruction problem for street scenes.

### [Equivalent Distribution Reorganization](16968-equivalent-distribution-reorganization.md)
A post-training reorganization method that addresses "parameterization degeneration" by rebuilding centers, covariances, and visibility structure through resampling from the empirical distribution. It reduces parameter coupling and opacity barriers.

### [S2Gaussian](17154-s2gaussian.md)
A two-stage framework for reconstructing high-quality 3D scenes from sparse and low-resolution input views. It initializes high-resolution Gaussians from a densified low-resolution representation and refines them using super-resolved supervision, introducing a "Gaussian Shuffle Split" strategy.

### Gaussian Densification via Rendering Loss
A strategy to add new 3D Gaussians to the map by identifying unobserved regions (holes) and regions with high rendering error. It uses opacity, color, and depth thresholds to guide densification, particularly useful in SLAM contexts [S3].

### Point Densification
A process in original 3DGS that adaptively controls the number of Gaussian points through clone and split operations. In hybrid optimization (e.g., HO-Gaussian), it is performed at regular intervals to populate problematic regions [S4].

### Naive Fine-tuning
A method identical to model rewriting except it freely optimizes all weights of the generator. It is typically optimized over 10,000 steps with a learning rate of $10^{-3}$ [S5].

### Backbone Fine-tuning
Optimizing the weights of a pre-trained 3D generator (backbone) alongside the decoder to adapt tri-plane features for Gaussian Splatting attributes. This is necessary because Gaussian splats have scale and rotation that influence adjacent regions, unlike NeRF's local color/density [S6].

## Operating characteristics
*   **Time Complexity:** Fine-tuning typically requires fewer iterations than training from scratch due to pre-trained priors, but densification operations add overhead. Naive fine-tuning may run for 10,000 steps [S5].
*   **Memory Complexity:** Depends on the number of Gaussians. Fine-tuning with densification/pruning can manage memory by removing redundant primitives [S2].
*   **Performance:** Fine-tuning with pre-trained priors accelerates convergence and improves photorealism [S2].
*   **Strengths:** Faster convergence, better generalization to OOD views (with SplatFormer), ability to handle sparse/blurry inputs (with Deblurring/Supplementary Point Addition).
*   **Limitations:** May overfit to input views if not regularized [S3]. Requires careful tuning of densification thresholds [S3].

## Background
Fine-tuning in 3DGS is derived from transfer learning principles in deep learning, where lower layers are fixed and higher layers are adapted [S1]. In the context of 3DGS, it involves adapting pre-trained models or initial Gaussian sets to specific scenes. The concept is closely related to the original 3DGS paper's densification strategy [S4] and has been extended to various domains such as SLAM [S3], urban scenes [S4], and generative models [S6].
