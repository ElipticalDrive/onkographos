# Feed-forward and Generalizable Prediction

Also called: Feed-forward 3D Gaussian Splatting, Generalizable 3DGS, Zero-shot 3D Reconstruction

## Overview
Feed-forward and Generalizable Prediction refers to a family of methods that predict a complete 3D Gaussian Splatting (3DGS) scene representation directly from one or more input images in a single neural network forward pass, eliminating the need for per-scene gradient-based optimization [S1, Parent]. Unlike traditional 3D Gaussian Splatting which requires iterative optimization to fit a specific scene, these methods learn priors from large-scale datasets to generalize to unseen scenes [Parent]. They distinguish themselves from sibling methods by their specific architectural choices for handling multi-view consistency, pose estimation, and primitive types (2D vs 3D), as detailed in the subtopics.

## Shared principles
The core mechanism of this family is the replacement of the iterative optimization loop with a learned mapping function $f_\theta: \mathcal{I} \rightarrow \mathcal{G}$, where $\mathcal{I}$ is the set of input images (and optionally poses) and $\mathcal{G}$ is the set of 3D Gaussian parameters $\{\mu, \Sigma, \alpha, c\}$ [Parent].

1.  **Input Representation:** Inputs are typically one or more RGB images $I \in \mathbb{R}^{H \times W \times 3}$. Some methods require known camera poses $P$, while others predict poses or operate on uncalibrated inputs [Parent].
2.  **Feature Encoding:** A shared encoder (e.g., Vision Transformer, CNN) extracts multi-scale features from the input images. Cross-attention or cost volumes are often used to aggregate multi-view information [Parent].
3.  **Primitive Prediction:** A decoder head predicts Gaussian attributes. These attributes are usually:
    *   **Mean ($\mu$):** 3D position.
    *   **Covariance ($\Sigma$):** Defined by scale $s$ and rotation $r$ (quaternion or 6D).
    *   **Opacity ($\alpha$):** Scalar.
    *   **Color ($c$):** Spherical Harmonics (SH) coefficients or constant RGB [Parent].
4.  **Differentiable Rendering:** The predicted Gaussians are rendered into target views using differentiable rasterization to compute reconstruction losses (e.g., L1, SSIM, LPIPS) for training the network [Parent].
5.  **Generalization:** The network is trained on a large dataset of scenes to learn priors about geometry and appearance, allowing inference on unseen scenes [Parent].

## Subtopics

### [FineSplat](15257-finesplat.md)
FineSplat is a feed-forward 3D Gaussian Splatting framework that predicts a set of 3D Gaussians from $N$ context views using a two-stage dual-grouping strategy to balance local detail preservation with global multi-view reasoning. It distinguishes itself from sibling methods like [HFGaussian](16422-hfgaussian.md) and [ZipSplat](16425-zerogs.md) by employing high-resolution $4 \times 4$ patch tokens and a serialized 3D spatial grouping mechanism, which avoids the prohibitive cost of global multi-view attention while preserving fine-grained visual information.

### [HFGaussian](16422-hfgaussian.md)
HFGaussian is a generalizable, feed-forward framework for real-time 3D human avatar reconstruction that simultaneously estimates novel views, 3D pose, and biomechanical features (such as dense pose and 3D keypoints) from sparse input images. Unlike sibling methods that rely on parametric body models (e.g., SMPL) or fail to integrate structural biomechanics, HFGaussian uses Gaussian splatting to represent the human subject and its associated features directly. It builds on [Feed-forward and Generalizable Prediction](15832-feed-forward-and-generalizable-prediction.md) by introducing a "feature splatting" mechanism that decouples human feature learning from the geometric Gaussian parameters, allowing different frequencies of features to be rendered efficiently without per-subject optimization.

### [ZeroGS](16425-zerogs.md)
ZeroGS is a pipeline for training 3D Gaussian Splatting (3DGS) from hundreds of unposed and unordered images without requiring Structure-from-Motion (SfM) tools like COLMAP. It differs from its siblings by leveraging a pretrained foundation model (Spann3R) as a neural scene representation and employing an incremental training buffer to progressively register images and refine poses. Unlike [ACE0](16422-ace0.md), which predicts sparse points using CNNs, ZeroGS predicts dense pointmaps and 3D Gaussians using transformers and optimizes the scene via rendering loss rather than reprojection error.

### [Shape Completion Training](16514-shape-completion-training.md)
Shape Completion Training is a feed-forward method that predicts all 14 3D Gaussian attributes from partial, incomplete inputs without requiring target coordinates or per-scene optimization. It distinguishes itself from sibling methods by employing a fixed 2×2 folding grid to expand a small set of coarse primitives into a dense Gaussian set, enabling robust reconstruction of missing geometry in occluded or sparse scenes.

### [RLSplat](16575-rlsplat.md)
RLSplat is a resource-linear, budget-controllable feed-forward 3D Gaussian Splatting (FF3DGS) framework that generates exactly $B$ Gaussians for a given scene, ensuring that inference latency and peak memory scale linearly with the requested budget. Unlike prior budget-controllable methods (e.g., EcoSplat, F4 Splat) that predict a dense set of candidates and prune them—resulting in nearly constant inference costs regardless of the target budget—RLSplat uses a learned Gaussian allocation policy to distribute exactly $B$ Gaussians across local scene regions from the start. This approach allows the representation size, inference latency, and peak memory to decrease linearly as the Gaussian budget $B$ is reduced, while maintaining or exceeding the reconstruction quality of denser baselines at lower resource costs.

### [Feed-forward Generalizable Reconstruction](16746-feed-forward-generalizable-reconstruction.md)

#### 3D-aware Image Synthesis via Sparse Voxel Grids
- [S1] A 3D-aware image synthesis generator that predicts color and density values on a sparse voxel grid, conditioned on camera pose.
- [S1] Use a mapping network with 2 layers and 64 channels.
- [S1] Set the channel base to 4000 (reduced from StyleGAN2's 32768) to account for higher parameter count in 3D convolutions.
- [S1] Implement skip connections that add an upsampled version of the output grid of the previous layer to the input of the next layer.
- [S1] Condition the generator on a camera pose represented by a rotation matrix and a translation vector, yielding a 12-dimensional input vector.
- [S1] Output coefficients of spherical harmonics for color; use degree 0 (single coefficient per color channel).
- [S1] Multiply the network's density output by a factor of 30 to facilitate generating high density values for sharp surfaces.
- [S1] Channel base: 4000.
- [S1] Density multiplier: 30.
- [S1] Mapping network layers: 2.
- [S1] Mapping network channels: 64.
- [S1] Spherical harmonics degree: 0.

#### Deformation Field MLP
- [S2] An MLP network $F_\theta$ that maps 3D Gaussian coordinates and time to deviations in position, rotation, and scaling.
- [S2] Input: 3D Gaussian coordinate $x$ and time $t$. Process: Pass through eight fully connected layers with ReLU activations and 256-dimensional hidden layers to output a 256-dimensional feature vector. Concatenate the feature vector and the input in the fourth layer. Output: Pass the feature vector through three additional fully connected layers (without activation) to separately output offsets $\delta x, \delta r, \delta s$ for position, rotation, and scaling.
- [S2] Hidden layer dimension: 256.
- [S2] Number of initial fully connected layers: 8.
- [S2] Number of output layers: 3 (one for each offset).
- [S2] Activation function: ReLU for hidden layers, none for output layers.
- [S2] Additional storage compared to 3D Gaussians: 2MB.
- [S2] Does not use grid/plane-based structures because dynamic scenes have higher rank than static scenes, and explicit point-based rendering exacerbates this rank.

#### RnD-Avatar
- [S3] A 3DGS-based human avatar modeling framework that reconstructs animatable and relightable human avatars from monocular video by decomposing geometry and appearance attributes and using dynamic skinning weights for pose-variant deformation.
- [S3] Encode Gaussian attributes using the Gaussian Attributes Encoder $D_G$, which consists of two sub-encoders $D_g$ and $D_a$. Both are multi-layer perceptrons (MLPs) that take the Gaussian position $x$ as input and output the corresponding geometric and appearance attributes, respectively.
- [S3] Articulate the human avatar by applying Linear Blend Skinning (LBS) transformations using the dynamic skinning weights $W_{\Theta_t}$ to deform the 3D Gaussians from canonical space to posed space.
- [S3] Optimize the RnD-Avatar through a Physically-Based Rendering (PBR) process to optimize geometric attributes (position and normal) and appearance attributes (albedo, roughness, and visibility).
- [S3] Render photorealistic images given an environmental light by performing a PBR process on the optimized avatar.

## Background
The concept of feed-forward 3D Gaussian Splatting emerged as a solution to the computational bottleneck of traditional 3DGS, which requires per-scene optimization that can take minutes to hours. Early works like [Splatt3R](16423-splatt3r.md) and [ZipSplat](16425-zerogs.md) demonstrated that generalizable reconstruction was possible by leveraging large-scale datasets and transformer-based architectures. The field has since expanded to include specialized applications such as human avatar reconstruction ([HFGaussian](16422-hfgaussian.md), [RnD-Avatar](16746-feed-forward-generalizable-reconstruction.md)), resource-constrained inference ([RLSplat](16575-rlsplat.md)), and unposed image reconstruction ([ZeroGS](16425-zerogs.md)).
