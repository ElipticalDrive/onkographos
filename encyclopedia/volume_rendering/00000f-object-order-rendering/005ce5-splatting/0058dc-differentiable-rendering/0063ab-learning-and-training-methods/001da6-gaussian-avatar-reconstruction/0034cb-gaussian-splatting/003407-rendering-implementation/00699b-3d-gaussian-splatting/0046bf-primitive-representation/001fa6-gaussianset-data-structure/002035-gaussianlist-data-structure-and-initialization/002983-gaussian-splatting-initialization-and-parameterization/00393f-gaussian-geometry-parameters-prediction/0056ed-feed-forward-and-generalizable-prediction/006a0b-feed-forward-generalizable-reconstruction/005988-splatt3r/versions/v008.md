# Splatt3R

Also called: Splatt3R: Zero-Shot Gaussian Splatting from Uncalibrated Image Pairs

## Overview
Splatt3R is a feed-forward model that takes two uncalibrated images as input and outputs 3D Gaussian parameters for geometry and appearance, without requiring camera intrinsics, extrinsics, or depth [S1, unofficial]. It predicts 3D Gaussians from uncalibrated image pairs for novel view synthesis, avoiding per-scene optimization [S1, unofficial]. Unlike existing generalizable 3D-GS methods that only supervise novel viewpoints between input stereo views, Splatt3R supervises extrapolated viewpoints beyond the stereo baseline using a loss masking strategy [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Two uncalibrated natural images $I_1, I_2 \in \mathbb{R}^{H \times W \times 3}$ (typically $512 \times 512$ pixels) [S1, unofficial].
*   **Output:** A set of 3D Gaussian primitives representing the scene, parameterized by mean position $\mu$, covariance $\Sigma$ (via rotation $q$ and scale $s$), opacity $\alpha$, and color $S$ [S1, unofficial].

**Data Structures:**
The model predicts per-pixel Gaussian attributes. For each pixel in the input images, the following parameters are predicted:
*   **Offsets:** $\Delta \in \mathbb{R}^3$
*   **Rotations:** $q \in \mathbb{R}^4$ (normalized quaternion)
*   **Scales:** $s \in \mathbb{R}^3$
*   **Opacities:** $\alpha \in \mathbb{R}$
*   **Spherical Harmonics:** $S \in \mathbb{R}^{3 \times d}$ (or constant color $S \in \mathbb{R}^3$) [S1, unofficial].

**Numbered Steps:**

1.  **Encoding:** Encode the two input images $I_1, I_2$ using a shared Vision Transformer (ViT) encoder and cross-attention transformers. This backbone is based on MASt3R and is frozen during training [S1, unofficial].
2.  **Point Cloud Prediction:** Predict 3D point locations $\hat{X}_1, \hat{X}_2$ and confidence maps $C_1, C_2$ in the coordinate frame of the first image using the frozen MASt3R backbone [S1, unofficial].
3.  **Gaussian Parameter Prediction:** Predict Gaussian parameters using a parallel 'Gaussian head' (DPT architecture) that outputs offsets $\Delta$, rotations $q$, scales $s$, opacities $\alpha$, and spherical harmonics $S$ for each pixel [S1, unofficial].
    *   The mean position $\mu$ of each Gaussian is calculated as the sum of the predicted 3D point $x$ and the offset $\Delta$:
        $$ \mu = x + \Delta $$
    *   The covariance matrix is reparameterized using a rotation quaternion $q \in \mathbb{R}^4$ and scale $s \in \mathbb{R}^3$ to ensure positive semi-definiteness:
        $$ \Sigma = R(q) S(s) S(s)^T R(q)^T $$
    *   Activation functions are applied: normalization for quaternions, exponential for scales and offsets, and sigmoid for opacities [S1, unofficial].
4.  **Primitive Construction:** Construct the final set of Gaussian primitives as the union of primitives predicted from both input images. The predicted covariances and spherical harmonics are considered to be in the first image's camera frame [S1, unofficial].
5.  **Rendering:** Render the novel view using standard differentiable 3D Gaussian Splatting rasterization [S1, unofficial].
6.  **Loss Masking (Training Only):** Calculate a loss mask $M$ to prevent updates from unseen parts of the scene.
    *   Unproject target image points and reproject them onto context images.
    *   Check if the rendered depth matches ground truth depth and if the pixel is inside the frustum.
    *   Pixels are valid if they are inside the frustum of at least one view, have reprojected depth matching ground truth, and have valid depth in the dataset [S1, unofficial].
7.  **Loss Calculation:** Calculate the total loss $L$ as a weighted sum of masked MSE and LPIPS losses:
    $$ L = \lambda_{MSE} L_{MSE}(M \odot \hat{I}, M \odot I) + \lambda_{LPIPS} L_{LPIPS}(M \odot \hat{I}, M \odot I) $$
    where $\hat{I}$ is the rendered image and $I$ is the ground truth target image [S1, unofficial].

**Training Procedure:**
Training is performed in two stages:
1.  **Geometry Loss:** Optimize the 3D point cloud’s geometry loss using the MASt3R backbone (which is pre-trained).
2.  **Novel View Synthesis:** Optimize the novel view synthesis objective by training only the Gaussian head [S1, unofficial].

**Parameters:**
*   **Input Resolution:** $512 \times 512$ pixels [S1, unofficial].
*   **Color Parameterization:** Constant, view-independent color $S \in \mathbb{R}^3$ is used in experiments, with ablation for view-dependent spherical harmonics [S1, unofficial].
*   **Overlap Thresholds:** Hyperparameters $\phi$ and $\psi$ control overlap thresholds during context image selection.
    *   Close: $\phi=0.9, \psi=0.9$
    *   Medium: $\phi=0.7, \psi=0.7$
    *   Wide: $\phi=0.5, \psi=0.5$
    *   Very Wide: $\phi=0.3, \psi=0.3$ [S1, unofficial].
*   **Dataset:** ScanNet++ [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Supervising Unseen Pixels:** Supervising rendering loss for pixels not visible in context views (obscured or outside frustums) is counterproductive and can be destructive to the model’s performance. This is addressed by the loss masking strategy [S1, unofficial].
*   **Local Minima:** Original 3D-GS uses iterative optimization which can get stuck in local minima. Splatt3R avoids this by using a pre-trained foundation model (MASt3R) and direct supervision of positions [S1, unofficial].
*   **Uncalibrated Input:** Unlike pixelSplat which uses camera intrinsics $K$ to compute location $\mu = K^{-1}ud + \Delta$, Splatt3R directly supervises positions using ground-truth point clouds from uncalibrated images [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Inference is a single forward pass, achieving 4 FPS at $512 \times 512$ resolution [S1, unofficial].
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:** On ScanNet++ test scenes, Splatt3R achieves PSNR 19.66, SSIM 0.757, LPIPS 0.234 for Close view overlap ($\phi=0.9, \psi=0.9$) [S1, unofficial].
*   **Scaling:** The method is designed for generalization to uncalibrated, in-the-wild images [S1, unofficial].
*   **Strengths:** Pose-free, feed-forward, handles uncalibrated images, supports extrapolation beyond stereo baseline.
*   **Limitations:** Performance degrades with wider baselines (lower overlap). Relies on the quality of the MASt3R backbone.
*   **When to use:** When camera parameters are unknown and per-scene optimization is too slow.
*   **When not to use:** When high precision is required for very wide baselines or when camera intrinsics are known and can be leveraged for better accuracy.

## Background
Splatt3R was introduced in 2024 by Brandon, Zheng, Iro, and Victor from the University of Oxford [S1, unofficial]. It builds on the MASt3R architecture, extending it to predict 3D Gaussian Splats for novel view synthesis. The method was trained on the ScanNet++ dataset [S1, unofficial]. It addresses the limitation of existing generalizable 3D-GS methods that only supervise novel viewpoints between input stereo views, by introducing a loss masking strategy to support extrapolation [S1, unofficial].
