# Adaptive SH Regularization

Also called: Directional support-aware SH regularization

## Overview
Adaptive SH Regularization is a technique for stabilizing spherical harmonic (SH) coefficient estimation in sparse or unevenly observed scenes by suppressing higher-order SH components that lack sufficient directional support [S1, unofficial]. It prevents overfitting to input views and improves generalization to unseen viewpoints, distinguishing itself from methods that rely on iterative optimization or fixed SH complexity [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A set of $N$ Gaussians, each with mean $\boldsymbol{\mu}_i$, covariance $\boldsymbol{\Sigma}_i$, opacity $\alpha_i$, and initial SH coefficients $\mathbf{c}_i$. A set of $K$ observed camera views with poses $\{\mathbf{P}_k\}_{k=1}^K$.
*   **Output:** Regularized SH coefficients $\hat{\mathbf{c}}_i$ for each Gaussian.

**Data Structures**
*   **SH Coefficients:** Stored as a vector of size $(L+1)^2$ for degree $L$.
*   **Directional Support Metric:** A scalar value per Gaussian per SH band, derived from the viewing directions relative to the Gaussian's orientation.

**Steps**
1.  **Evaluate Directional Support:** For each Gaussian $i$ and each SH band $l$, calculate a support metric based on the distribution of viewing directions from the $K$ input cameras relative to the Gaussian's local frame.
2.  **Apply Support Criterion:** Compare the support metric against a threshold (implicitly defined in the source's equation 25) [S1, unofficial].
    *   If the support is **insufficient** (weakly supported), apply strong regularization to the non-DC components ($l > 0$) of that band.
    *   If the support is **sufficient** (well-supported), apply weak regularization or none, preserving the directional detail.
3.  **Preserve DC Component:** The zeroth-order (DC, $l=0$) component is always preserved regardless of support, as it represents the average color [S1, unofficial].
4.  **Solve Regularized System:** Incorporate the adaptive regularization weights into the linear least squares (LLS) system used to estimate or refine the SH coefficients. This improves the conditioning of the system, allowing faster convergence [S1, unofficial].

**Formulas**
*   **Regularization Weight:** The regularization strength $\lambda_{i,l}$ for Gaussian $i$ and band $l$ is determined by the support criterion.
    *   If support $< \text{threshold}$: $\lambda_{i,l}$ is large for $l > 0$.
    *   If support $\ge \text{threshold}$: $\lambda_{i,l}$ is small for $l > 0$.
    *   For $l=0$: $\lambda_{i,0} \approx 0$.
*   **LLS System:** The system solved is of the form $(\mathbf{A}^\top \mathbf{A} + \mathbf{\Lambda}) \mathbf{c} = \mathbf{A}^\top \mathbf{b}$, where $\mathbf{\Lambda}$ is a diagonal matrix containing the adaptive regularization weights $\lambda_{i,l}$ [S1, unofficial].

**Parameters**
*   **Support Threshold:** Implicitly defined in equation (25) of the source [S1, unofficial]. Not given in the sources.
*   **SH Degree ($L$):** Typically 3 or higher, depending on scene complexity.

**Edge Cases and Pitfalls**
*   **Overfitting:** Without regularization, unconstrained SH coefficients lacking sufficient directional constraints overfit input views and generalize poorly to unseen viewpoints, producing noisy colors [S1, unofficial].
*   **Convergence Failure:** Unregularized systems may fail to converge within a reasonable iteration count (e.g., $T_{max}=300$) due to poor conditioning [S1, unofficial].
*   **Degenerate Input:** In scenes with very few views ($K$ small), many Gaussians will have insufficient support, leading to heavy suppression of non-DC components and potentially oversmoothed appearance [S1, unofficial].

**Pseudocode**
```python
def adaptive_sh_regularization(gaussians, camera_poses, sh_degree, support_threshold):
    """
    Applies adaptive SH regularization based on directional support.
    
    Args:
        gaussians: List of Gaussian objects with attributes:
            - mu: mean position
            - cov: covariance matrix
            - sh_coeffs: array of shape (num_bands,)
            - view_dirs: list of viewing directions from input cameras
        camera_poses: List of camera pose matrices
        sh_degree: Integer, degree of spherical harmonics
        support_threshold: Float, threshold for directional support metric
        
    Returns:
        Regularized SH coefficients for each Gaussian
    """
    num_bands = (sh_degree + 1) ** 2
    regularized_coeffs = []
    
    for g in gaussians:
        coeffs = g.sh_coeffs.copy()
        regularization_weights = np.zeros(num_bands)
        
        # Calculate directional support for each band
        for l in range(sh_degree + 1):
            # Determine number of bands for this degree
            num_l_bands = 2 * l + 1
            start_idx = l * l
            end_idx = start_idx + num_l_bands
            
            # Evaluate support metric for this band group
            # Note: Exact formula for support metric is implicit in source eq (25)
            # [G] Assuming a metric based on the spread of viewing directions
            # relative to the Gaussian's orientation.
            support_metric = evaluate_directional_support(g, camera_poses, l)
            
            # Apply regularization based on support
            if support_metric < support_threshold:
                # Weakly supported: strong regularization for non-DC
                if l > 0:
                    regularization_weights[start_idx:end_idx] = 1.0 # Strong weight
                else:
                    # DC component preserved
                    regularization_weights[start_idx:end_idx] = 0.0
            else:
                # Well-supported: weak or no regularization
                regularization_weights[start_idx:end_idx] = 0.0 # Weak weight
        
        # Solve regularized LLS system
        # [G] Assuming a function that solves (A^T A + Lambda) c = A^T b
        # where Lambda is diagonal with regularization_weights
        regularized_coeffs.append(solve_regularized_lls(g, regularization_weights))
        
    return regularized_coeffs

def evaluate_directional_support(gaussian, camera_poses, l):

    Evaluates the directional support for a specific SH degree l.
    [G] Placeholder for the implicit support metric from source eq (25).
    Typically involves projecting camera directions onto the Gaussian's
    local coordinate system and measuring the angular coverage.
    """
    # [G] Simplified implementation: measure the variance of viewing directions
    # projected onto the Gaussian's principal axes.
    # This is a heuristic; the exact metric is not provided in the sources.
    view_dirs = get_viewing_directions(gaussian, camera_poses)
    if len(view_dirs) == 0:
        return 0.0
    
    # Project directions onto the Gaussian's local frame
    local_dirs = project_to_local_frame(view_dirs, gaussian.cov)
    
    # Calculate support metric (e.g., angular spread)
    # [G] Using standard deviation of angles as a proxy for support
    angles = np.arccos(np.clip(np.dot(local_dirs, local_dirs[0]), -1.0, 1.0))
    support = np.std(angles)
    
    return support
```

## Operating characteristics
*   **Time Complexity:** Solving the global LLS system scales with the number of observations, but remains more efficient than iterative optimization of large parameter sets [S1, unofficial].
*   **Memory Complexity:** No significant additional memory overhead compared to standard SH storage, as regularization weights are computed on-the-fly or stored per-band.
*   **Measured Performance:** On the C3VD c t1 b scene with $K=7$ views and $L=3$, adaptive regularization improves test-view PSNR from 33.66 to 34.69 [S1, unofficial].
*   **Convergence:** With regularization, the PCG residual decreases rapidly; without it, the system fails to converge within $T_{max}=300$ iterations [S1, unofficial].
*   **Strengths:** Improves conditioning of the appearance estimation problem, reduces unstable view-dependent appearance, and yields more stable fidelity gains as the number of views increases [S1, unofficial].
*   **Limitations:** Requires careful tuning of the support threshold; may oversmooth appearance in regions with very sparse observations [S1, unofficial].
*   **When to Use:** Sparse or unevenly observed scenes, scenes with limited input views, or when stable generalization to unseen viewpoints is critical [S1, unofficial].
*   **When Not to Use:** Dense, uniformly observed scenes where standard SH optimization converges well and high-frequency detail is preserved [S1, unofficial].

## Background
Adaptive SH Regularization was introduced in the context of CF-Splat (Closed-Form Triangle Splatting with Mesh Priors) [S1, unofficial]. It addresses the challenge of overfitting in SH-based appearance modeling when directional support is insufficient. The method builds on the principle that SH coefficients should be constrained based on the available viewing directions, rather than being optimized unconstrained [S1, unofficial].
