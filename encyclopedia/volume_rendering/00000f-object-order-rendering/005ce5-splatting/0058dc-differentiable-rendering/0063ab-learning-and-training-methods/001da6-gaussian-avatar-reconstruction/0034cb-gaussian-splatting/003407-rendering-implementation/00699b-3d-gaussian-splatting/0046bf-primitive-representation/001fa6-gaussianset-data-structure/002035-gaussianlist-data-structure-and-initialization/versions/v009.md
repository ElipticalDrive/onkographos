# GaussianList Data Structure and Initialization

Also called: GaussianList

## Overview
The GaussianList is a contiguous, column-major data structure that stores the attributes of a set of 3D Gaussians to enable batch processing during differentiable volume rendering [S1, unofficial]. It solves the problem of efficiently managing and computing with large sets of Gaussian primitives by organizing means, scales, rotations, opacities, and spherical harmonics (SH) coefficients into matrices aligned for SIMD-friendly operations [S1, unofficial]. It differs from its parent, [GaussianSet Data Structure](2074-gaussianset-data-structure.md), by explicitly defining the memory layout (column-major matrices) and the initialization pipeline that populates this layout from an input vector of Gaussian objects [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A vector of Gaussian objects, each containing position (3D), scale (3D), opacity (scalar), rotation (quaternion), and spherical harmonics coefficients.
*   **Output:** A `GaussianList` struct instance with populated matrices and pre-computed 3D covariance matrices.

**Data Structures:**
The `GaussianList` struct stores attributes in column-major matrices for batch processing [S1, unofficial]. The fields are:
*   `positions`: `na::Matrix4xX<f32>` (4 rows $\times$ $N$ columns). Stores 3D positions as homogeneous coordinates $(x, y, z, 1.0)$ [S1, unofficial].
*   `scales`: `na::Matrix3xX<f32>` (3 rows $\times$ $N$ columns). Stores scale components $(s_x, s_y, s_z)$ [S1, unofficial].
*   `opacities`: `na::DVector<f32>` (1D vector of size $N$). Stores opacity values [S1, unofficial].
*   `rotations`: `na::Matrix4xX<f32>` (4 rows $\times$ $N$ columns). Stores quaternion components $(w, x, y, z)$ [S1, unofficial].
*   `sh`: `Matrix48xX<f32>` (48 rows $\times$ $N$ columns). Stores SH coefficients [S1, unofficial].
*   `num_gaussians`: `usize`. The total number of Gaussians $N$ [S1, unofficial].
*   `cov3d`: `na::Matrix3xX<f32>` (3 rows $\times$ $N$ columns). Pre-allocated zeros, filled with computed 3D covariance matrices [S1, unofficial].

**Spherical Harmonics Layout:**
The SH coefficients are stored in the columns of the `sh` matrix. Within a column, the layout corresponds to RGB channels for each SH degree/order: $C_{0,R}, C_{0,B}, C_{0,G}, C_{1,R}, C_{1,B}, C_{1,G}, \dots$ [S1, unofficial].

**Initialization Steps:**
1.  Set `num_gaussians` $N$ to the length of the input vector of Gaussian objects [S1, unofficial].
2.  Construct the `positions` matrix: Iterate over all $N$ Gaussians. For each Gaussian $i$, clone its position components $(x_i, y_i, z_i)$ and append $1.0$ to form the $i$-th column: $[x_i, y_i, z_i, 1.0]^T$ [S1, unofficial].
3.  Construct the `scales` matrix: Iterate over all $N$ Gaussians. Clone the scale components $(s_{x,i}, s_{y,i}, s_{z,i})$ into the $i$-th column [S1, unofficial].
4.  Construct the `opacities` vector: Clone opacity values $\alpha_i$ into the $i$-th element of the vector [S1, unofficial].
5.  Construct the `rotations` matrix: Iterate over all $N$ Gaussians. Clone quaternion components $(w_i, x_i, y_i, z_i)$ into the $i$-th column [S1, unofficial].
6.  Construct the `sh` matrix: Clone spherical harmonics coefficients into the $i$-th column according to the defined layout [S1, unofficial].
7.  Initialize `cov3d` with zeros of size $3 \times N$ [S1, unofficial].
8.  Call `compute_cov3d()` to calculate covariance matrices for all Gaussians [S1, unofficial].

**Covariance Computation (`compute_cov3d`):**
For each Gaussian $i$ from $0$ to $N-1$:
1.  Extract the rotation quaternion $q_i$ from the `rotations` matrix column $i$ [S1, unofficial].
2.  Convert $q_i$ to a `UnitQuaternion`, then to a $3 \times 3$ rotation matrix $R_i$ [S1, unofficial].
3.  Create a diagonal scale matrix $S_i = \text{diag}(s_{x,i}^2, s_{y,i}^2, s_{z,i}^2)$ [S1, unofficial].
4.  Compute the covariance matrix $\Sigma_i = R_i S_i R_i^T$ [S1, unofficial].
5.  Copy the resulting $3 \times 3$ matrix $\Sigma_i$ into the `cov3d` buffer at offset $i \times 3$ (column-major) [S1, unofficial].

**Centering Positions (Optional Pre-processing):**
If centering is required before initialization or as a separate step:
1.  Initialize `avg_pos` as a zero $3$-vector [S1, unofficial].
2.  Iterate over all $N$ Gaussians, adding each position $(x_i, y_i, z_i)$ to `avg_pos` [S1, unofficial].
3.  Divide `avg_pos` by $N$ to get the mean position $\mu$ [S1, unofficial].
4.  Iterate over all $N$ Gaussians again, subtracting $\mu$ from each position [S1, unofficial].

def initialize_gaussian_list(gaussians: List[Gaussian]) -> GaussianList:
    """
    Initialize a GaussianList from a vector of Gaussian objects.
    gaussians: List of objects with attributes: position (Vec3), scale (Vec3), 
               opacity (float), rotation (Quaternion), sh (List[float]).
    """
    N = len(gaussians)
    
    # Initialize matrices with zeros
    # positions: 4xN, scales: 3xN, rotations: 4xN, sh: 48xN, cov3d: 3xN
    positions = [[0.0] * N for _ in range(4)]
    scales = [[0.0] * N for _ in range(3)]
    opacities = [0.0] * N
    rotations = [[0.0] * N for _ in range(4)]
    sh = [[0.0] * N for _ in range(48)]
    cov3d = [[0.0] * N for _ in range(3)]
    
    for i in range(N):
        g = gaussians[i]
        
        # 1. Positions (homogeneous)
        positions[0][i] = g.position.x
        positions[1][i] = g.position.y
        positions[2][i] = g.position.z
        positions[3][i] = 1.0
        
        # 2. Scales
        scales[0][i] = g.scale.x
        scales[1][i] = g.scale.y
        scales[2][i] = g.scale.z
        
        # 3. Opacities
        opacities[i] = g.opacity
        
        # 4. Rotations (quaternion w, x, y, z)
        rotations[0][i] = g.rotation.w
        rotations[1][i] = g.rotation.x
        rotations[2][i] = g.rotation.y
        rotations[3][i] = g.rotation.z
        
        # 5. SH Coefficients
        # Layout: C0_R, C0_B, C0_G, C1_R, ...
        # Assuming g.sh is a flat list of coefficients
        for k in range(48):
            sh[k][i] = g.sh[k]
            
    # 6. Compute Covariances
    compute_cov3d(positions, scales, rotations, cov3d, N)
    
    return GaussianList(
        positions=positions,
        scales=scales,
        opacities=opacities,
        rotations=rotations,
        sh=sh,
        num_gaussians=N,
        cov3d=cov3d
    )

        # Convert quaternion to rotation matrix R
        # R = I + 2w * [v]x + 2 * [v]x^2
        # where v = (x, y, z)
        # Standard conversion:
        R = [
            [1 - 2*(y*y + z*z), 2*(x*y - w*z), 2*(x*z + w*y)],
            [2*(x*y + w*z), 1 - 2*(x*x + z*z), 2*(y*z - w*x)],
            [2*(x*z - w*y), 2*(y*z + w*x), 1 - 2*(x*x + y*y)]

def project_cov3d_to_screen(cov3d, positions, view_matrix, focal_x, focal_y, tan_fovx, tan_fovy, N):
    """
    Project 3D covariance to 2D screen space.
    """
    cov2d_list = []
    for i in range(N):
        # Get position
        pos_w = [positions[0][i], positions[1][i], positions[3][i], 1.0] # Assuming positions[2] is z? 
        # [S1, unofficial] says positions is 4xN, components x,y,z,1.0.
        # So positions[0]=x, [1]=y, [2]=z, [3]=1.0.
        pos_w = [positions[0][i], positions[1][i], positions[2][i], 1.0]
        
        # Transform to camera space: pos_cam = viewmatrix * pos_w
        pos_cam = mat_mul_vec(view_matrix, pos_w)
        
        # Get focal length and tangent of FOV
        # tan_fovx, tan_fovy are precomputed
        
        # Compute tangent of Gaussian center
        # txtz = pos_cam.x / pos_cam.z
        # tytz = pos_cam.y / pos_cam.z
        if pos_cam[3] == 0: # Handle division by zero
            txtz = 0.0
            tytz = 0.0
        else:
            txtz = pos_cam[0] / pos_cam[3]
            tytz = pos_cam[1] / pos_cam[3]
            
        # Clamp tangents
        limit_x = 1.3 * tan_fovx
        limit_y = 1.3 * tan_fovy
        
        t_x = clamp(txtz, -limit_x, limit_x) * pos_cam[3]
        t_y = clamp(tytz, -limit_y, limit_y) * pos_cam[3]
        t_z = pos_cam[3]
        
        # Compute Jacobian J (3x3)
        # J depends on focal_x, focal_y, t_x, t_y, t_z
        # Standard projection Jacobian:
        # J = [ fx/z, 0,   -fx*x/z^2 ]
        #     [ 0,   fy/z, -fy*y/z^2 ]
        #     [ 0,    0,   -1         ]
        # But [S1, unofficial] uses t.x, t.y, t.z.
        # Let's use the standard form with pos_cam
        z = pos_cam[3]
        if z == 0:
            z = 1e-6 # Guard
        
        J = [
            [focal_x / z, 0, -focal_x * pos_cam[0] / (z * z)],
            [0, focal_y / z, -focal_y * pos_cam[1] / (z * z)],
            [0, 0, -1]
        ]
        
        # Compute W as transpose of top-left 3x3 of view matrix
        # W = view_matrix[0:3, 0:3].T
        W = [
            [view_matrix[0][0], view_matrix[1][0], view_matrix[2][0]],
            [view_matrix[0][1], view_matrix[1][1], view_matrix[2][1]],
            [view_matrix[0][2], view_matrix[1][2], view_matrix[2][2]]
        ]
        
        # T = W * J
        T = mat_mul(W, J)
        
        # Get cov3d for this Gaussian
        # Assuming cov3d is 9xN or we extract the 3x3 block
        # Let's assume we have a function get_cov3d_block(i) that returns 3x3 matrix
        cov3d_i = get_cov3d_block(cov3d, i)
        
        # cov = T^T * cov3d^T * T
        # Note: [S1, unofficial] says T.transpose() * cov3d.transpose() * T
        # This is equivalent to (T * cov3d * T^T)^T if cov3d is symmetric?
        # Actually, the projection formula is usually T * cov3d * T^T.
        # [S1, unofficial] says T^T * cov3d^T * T.
        # If cov3d is symmetric, cov3d^T = cov3d.
        # So T^T * cov3d * T.
        # This is different from T * cov3d * T^T.
        # Let's follow [S1, unofficial] exactly.
        cov = mat_mul(mat_mul(transpose(T), transpose(cov3d_i)), T)
        
        # Extract top-left 2x2 submatrix as cov2d
        cov2d = [
            [cov[0][0], cov[0][1]],
            [cov[1][0], cov[1][1]]
        ]
        
        # Apply low-pass filter: add 0.3 to diagonal
        cov2d[0][0] += 0.3
        cov2d[1][1] += 0.3
        
        cov2d_list.append(cov2d)
        
    return cov2d_list

**Edge Cases and Pitfalls:**
*   **Division by Zero:** In `project_cov3d_to_screen`, if `pos_cam.z` is zero, division by zero occurs. A guard value (e.g., $10^{-6}$) should be used [G].
*   **Covariance Storage Ambiguity:** The source [S1, unofficial] states `cov3d` is $3 \times N$ but requires storing $3 \times 3$ matrices. This is a contradiction. Implementers should likely use a $9 \times N$ matrix or a flattened array of size $9N$ [G].
*   **FOV Clamping:** The FOV clamping limit is $1.3 \times \tan(\text{FOV})$ [S1, unofficial].

## Subtopics

### [LinPrim Population Control](2295-linprim-population-control.md)
LinPrim Population Control manages the density of linear primitives (octahedra and tetrahedra) during differentiable volume rendering optimization by pruning, cloning, and splitting primitives to adapt to scene complexity. It differs from standard 3D Gaussian Splatting by redefining primitive size metrics to accommodate non-spherical kernels and adjusting sampling distributions to respect the anisotropic geometry of linear primitives.

### [Gaussian Splatting Initialization and Parameterization](2313-gaussian-splatting-initialization-and-parameterization.md)
This method creates the initial set of 3D Gaussian primitives for training, typically by converting a sparse Structure-from-Motion (SfM) point cloud into learnable Gaussian parameters. It solves the problem of providing a geometrically plausible starting state for differentiable rendering, avoiding the poor reconstruction quality and slow convergence associated with purely random initialization. Unlike siblings that use random large-variance distributions [6129-random-large-variance-initialization.md] or dense MVS clouds, this method relies on sparse SfM points to anchor the geometry, allowing the optimizer to create detail during training rather than requiring a dense starting geometry.

### [Octree-GS / Scaffold-GS](6142-octree-gs-scaffold-gs.md)
Octree-GS and Scaffold-GS are hierarchical level-of-detail (LoD) methods that anchor scene content to a sparse voxel grid, using the grid as a scaffold to allocate Gaussians only in occupied regions. This approach naturally adapts to view distance and improves memory efficiency compared to flat Gaussian lists. Scaffold-GS specifically uses anchor points to predict "neural" Gaussians on the fly via a small MLP, achieving approximately 5x less memory usage than vanilla 3DGS at the same quality. Octree-GS builds an explicit octree over the scene, associating each node with a merged Gaussian that summarizes the radiance and opacity of its children, enabling massive scene rendering.

### [Random Gaussian Generation](14047-random-gaussian-generation.md)
Random Gaussian Generation is the initialization procedure for creating a set of 3D Gaussians from scratch, typically to serve as the starting point for differentiable rendering optimization in methods like 3D Gaussian Splatting. It generates a fixed number of Gaussian primitives with random positions (implicitly at the origin before transformation), scales, orientations, opacities, and spherical harmonics coefficients. It differs from [LinPrim Population Control](2295-linprim-population-control.md) which manages the density of existing Gaussians during training, and from [Gaussian Splatting Initialization and Parameterization](2313-gaussian-splatting-initialization-and-parameterization.md) which may use structured or data-driven initialization strategies. This method provides a uniform, uninformative prior over the parameter space.

### GaussianHair
GaussianHair is a strand-aware hair method using strand + GS representation [S2, unofficial].

### Appearance Modeling
Appearance Modeling uses per-image and per-Gaussian embeddings optimized via an MLP to model view-dependent appearance, illumination, and weather effects [S3]. The learning rate for the appearance MLP is 0.0005, for per-image embeddings $\mathbf{e}_j$ is 0.001, and for per-Gaussian embeddings $\mathbf{z}_i$ is 0.005 [S3]. Per-image embedding $\mathbf{e}_j \in \mathbb{R}^{32}$ and per-Gaussian embedding $\mathbf{z}_i \in \mathbb{R}^{24}$, initialized using Fourier frequencies with 4 components [S3].

## Operating characteristics
**Time and Memory Complexity:**
*   **Memory:** $O(N)$ where $N$ is the number of Gaussians. The storage is dominated by the `sh` matrix (48 floats per Gaussian) and `positions`, `scales`, `rotations` (11 floats per Gaussian). Total $\approx 59N$ floats [S1, unofficial].
*   **Time:** Initialization is $O(N)$ for copying attributes and computing covariances [S1, unofficial].

**Measured Performance:**
Not given in the sources.

**Scaling:**
Not given in the sources.

**Strengths and Limitations:**
*   **Strengths:** Column-major layout enables efficient batch processing and SIMD operations [S1, unofficial].
*   **Limitations:** The ambiguity in `cov3d` storage size ($3 \times N$ vs $9 \times N$) may cause implementation errors [S1, unofficial].

**When to Use:**
Use when implementing a standard 3D Gaussian Splatting renderer that requires efficient batch processing of Gaussian attributes [S1, unofficial].

## Background
The GaussianList data structure is part of the implementation of 3D Gaussian Splatting, specifically as described in the `thomasantony/splat` repository [S1, unofficial]. It is designed to store and manage the attributes of 3D Gaussians for differentiable rendering [S1, unofficial].
