# Ground Truth Downsampling

Also called: Anti-alias Ground Truth Downsampling

## Overview
Ground Truth Downsampling is a supervision strategy used during the low-resolution (LR) optimization stage of 3D Gaussian Splatting (specifically within the DashGaussian framework) to prevent optimization misguidance caused by aliased ground truth images. It differs from standard upsampling or fixed-resolution training by explicitly downscaling the target images using an anti-aliasing filter before computing the loss against the rendered low-resolution output. This ensures that the Gaussians are optimized to match the frequency content appropriate for the target resolution, rather than attempting to fit high-frequency noise present in the original high-resolution ground truth.

## How it works
**Inputs and Outputs:**
- **Input:** High-resolution ground truth image $I_{HR}$, rendered low-resolution image $I_{LR}$ from the current Gaussian scene representation.
- **Output:** Downsampled ground truth image $I_{LR}^{GT}$ used for loss computation.

**Data Structures:**
- $I_{HR}$: Tensor of shape $(H, W, C)$, typically 3-channel RGB.
- $I_{LR}$: Tensor of shape $(h, w, C)$, where $h = H/s$ and $w = W/s$ for some scale factor $s$.
- $I_{LR}^{GT}$: Tensor of shape $(h, w, C)$.

**Steps:**
1. **Resolution Selection:** Determine the target low resolution $(h, w)$ for the current optimization stage. This is often part of a resolution scheduler that gradually increases resolution during training.
2. **Anti-Aliased Downsampling:** Apply PyTorch's official anti-alias downsampling algorithm to $I_{HR}$ to produce $I_{LR}^{GT}$. This step involves a low-pass filter to remove frequencies above the Nyquist limit of the target resolution before subsampling.
3. **Loss Computation:** Compute the reconstruction loss (e.g., L1 or L2, or SSIM) between the rendered image $I_{LR}$ and the downsampled ground truth $I_{LR}^{GT}$.
   $$ \mathcal{L} = \| I_{LR} - I_{LR}^{GT} \| $$
4. **Optimization Step:** Update the Gaussian parameters (position, scale, rotation, opacity, color) using the gradient of the loss with respect to the rendered image.

**Pseudocode:**
```python
import torch
import torch.nn.functional as F

def ground_truth_downsampling(gt_hr, render_lr, scale_factor):
    """
    Downsamples high-resolution ground truth to match the resolution of the low-resolution rendering.
    
    Args:
        gt_hr (torch.Tensor): High-resolution ground truth image, shape (H, W, C) or (B, H, W, C).
        render_lr (torch.Tensor): Rendered low-resolution image, shape (h, w, C) or (B, h, w, C).
        scale_factor (int): Integer factor by which to downsample (H/h = W/w = scale_factor).
        
    Returns:
        torch.Tensor: Downsampled ground truth image, shape (h, w, C).
    """
    # Ensure input is in the correct format for PyTorch's anti-alias downsampling
    # PyTorch's F.interpolate with antialias=True expects channels first (B, C, H, W)
    # or (C, H, W) if batch dimension is absent.
    
    # Check if batch dimension exists
    if gt_hr.dim() == 3:
        gt_hr = gt_hr.unsqueeze(0) # Add batch dim
        needs_unsqueeze = True
    else:
        needs_unsqueeze = False
        
    # Apply anti-alias downsampling
    # Note: PyTorch's F.interpolate with antialias=True uses a Gaussian filter
    # to low-pass filter the image before downsampling.
    gt_lr = F.interpolate(
        gt_hr, 
        size=(render_lr.shape[-2], render_lr.shape[-1]), 
        mode='bilinear', 
        align_corners=False, 
        antialias=True
    )
    
    if needs_unsqueeze:
        gt_lr = gt_lr.squeeze(0)
        
    return gt_lr

def compute_loss(render_lr, gt_lr):
    """
    Computes the reconstruction loss between rendered and downsampled ground truth.
    """
    # Example: L1 Loss
    loss = torch.mean(torch.abs(render_lr - gt_lr))
    return loss
```

**Parameters:**
- **Anti-aliasing Filter:** PyTorch's official implementation is used. The specific kernel is not explicitly detailed in the source but is part of the `antialias=True` flag in `F.interpolate`. [S1]
- **Scale Factor:** Determined by the resolution scheduler. Not given in the sources.

**Edge Cases and Pitfalls:**
- **Precision:** Ensure that the ground truth images are normalized consistently with the rendered images (e.g., [0, 1] or [-1, 1]) before downsampling. [G]
- **Boundary Conditions:** The anti-aliasing filter may introduce slight blurring at the edges. This is generally desirable for anti-aliasing but should be noted if edge fidelity is critical. [G]
- **Degenerate Input:** If the ground truth image is already at the target low resolution, the downsampling step should be skipped or identity-mapped. [G]

## Subtopics

## Operating characteristics
- **Time Complexity:** The downsampling operation is $O(H \cdot W)$, which is negligible compared to the rendering and optimization steps. [S1]
- **Memory Complexity:** Requires storing the intermediate downsampled ground truth tensor, which is $O(h \cdot w \cdot C)$. [S1]
- **Measured Performance:** In the DashGaussian framework, this method contributes to a 5dB PSNR improvement over baseline 3DGS on zoom-out tasks. [S1]
- **Strengths:** Prevents high-frequency aliasing artifacts in the optimization process, leading to more stable convergence at low resolutions. [S1]
- **Limitations:** Relies on the quality of the anti-aliasing filter provided by the deep learning framework. [S1]
- **When to Use:** During the low-resolution optimization stages of 3D Gaussian Splatting training, particularly when using a multi-resolution schedule. [S1]
- **When Not to Use:** When training at a single high resolution where anti-aliasing of the ground truth is not necessary for the target output resolution. [S1]

## Background
Ground Truth Downsampling was introduced as part of the DashGaussian method, which aims to optimize 3D Gaussian Splatting in 200 seconds. The method addresses the issue of aliased supervision hindering optimization when training at low resolutions. It is a key component of the DashGaussian framework, which also includes modifications to learning rate schedules, resolution schedulers, primitive growth schedules, and densification operations.
