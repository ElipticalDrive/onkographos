# 3D Gaussian Ray Tracing

Also called: 3DGRT, BVH Ray Tracing for 3D Gaussians, Point-based Ray Tracing on 3D Gaussians, Ray-Splat Intersection via BVH, Splat BVH Traversal

## Overview
3D Gaussian Ray Tracing is a rendering method that replaces the tile-based rasterization of standard 3D Gaussian Splatting with hardware-accelerated ray tracing to correctly handle semi-transparent Gaussians and complex lighting [S1, unofficial][S4]. Unlike rasterization, which evaluates all Gaussians overlapping a screen tile for every pixel (linear scaling in dense scenes), this method uses a Bounding Volume Hierarchy (BVH) to traverse only the Gaussians intersected by each ray, enabling logarithmic scaling and correct volumetric transparency [S1, unofficial][S4]. It solves the problem of implausible transparency effects and the violation of physical absorption-emission models inherent in standard alpha-blending splatting [S1, unofficial].

## How it works
The method renders 3D Gaussians by treating them as semi-transparent volumetric primitives. It constructs a spatial acceleration structure (BVH) to efficiently query which Gaussians intersect a given ray, then computes the accumulated color and transmittance along the ray path.

### Inputs and Outputs
*   **Inputs:** A set of $N$ 3D Gaussians, each defined by mean $\boldsymbol{\mu}$, covariance $\boldsymbol{\Sigma}$, opacity $\alpha$, and color/appearance. Camera ray origins $\boldsymbol{r_o}$ and directions $\boldsymbol{r_d}$.
*   **Outputs:** A 2D image buffer with accumulated color and opacity per pixel.

### Data Structures
The implementation relies on two primary textures for BVH storage and Gaussian data, optimized for GPU texture sampling [S3, unofficial]:

1.  **Triangle Texture (`tTriangleTexture`)**:
    *   **Type:** `highp usampler2D`
    *   **Size:** $2048 \times 2048$ texels (`TRI_TEXTURE_SIZE`).
    *   **Layout:** Each Gaussian (splat) occupies two consecutive texels (`id*2` and `id*2+1`).
        *   `vd0.x, y, z`: Position $\boldsymbol{pos}$ (decoded via `uintBitsToFloat`).
        *   `vd0.w, vd1.x`: First axis vector $\boldsymbol{au}$ components (decoded via `unpackHalf2x16`).
        *   `vd1.y`: Second component of $\boldsymbol{au}$.
        *   `vd1.z, w`: RGBA color (`z`=RGB, `w`=Alpha).

2.  **AABB Texture (`tAABBTexture`)**:
    *   **Type:** `highp usampler2D`
    *   **Size:** $4096 \times 4096$ texels (`AABB_TEXTURE_SIZE`).
    *   **Layout:** Each BVH node is stored as one `uvec4`.
        *   `x`: Node ID. Negative for inner nodes, positive for leaf splat IDs.
        *   `y`: Min/Max X of AABB (decoded via `unpackHalf2x16`).
        *   `z`: Min/Max Y of AABB.
        *   `w`: Min/Max Z of AABB.

### Algorithm Steps

1.  **BVH Construction**:
    Construct a binary radix tree from the 3D Gaussians. Leaf nodes represent tight bounding boxes of individual Gaussians. Internal nodes denote the bounding box of their two children. This structure is stored in `tAABBTexture` [S2].

2.  **Ray Traversal**:
    For each pixel, cast a ray $\boldsymbol{r}(t) = \boldsymbol{r_o} + t\boldsymbol{r_d}$. Traverse the BVH recursively from the root:
    *   Perform Axis-Aligned Bounding Box (AABB) intersection tests between the ray and the bounding volumes of child nodes [S2][S3, unofficial].
    *   **AABB Intersection Logic**: Compute near/far $t$ values for x, y, z axes. Let $t_{min}$ and $t_{max}$ be the intersection intervals for each axis.
        $$ t_0 = \max(\max(t_{min}.x, t_{min}.y), t_{min}.z) $$
        $$ t_1 = \min(\min(t_{max}.x, t_{max}.y), t_{max}.z) $$
        The ray intersects the box if $\max(t_0, 0.0) \le t_1$ [S3, unofficial].
    *   If the node is an inner node (ID < 0), push children to the traversal stack. Sort children such that the closer child (by $t_0$) is processed first for closest-hit, or the farther child (by $t_1$) for any-hit [S3, unofficial].
    *   If the node is a leaf (ID $\ge$ 0), fetch the Gaussian data from `tTriangleTexture` and perform a Splat Intersection test [S3, unofficial].

3.  **Splat Intersection**:
    For a leaf Gaussian with position $\boldsymbol{pos}$ and axes $\boldsymbol{au}$ (and implied orthogonal axis), solve for the intersection parameters $u, v, t$ in the local coordinate system:
    $$ [\boldsymbol{au}, \boldsymbol{av}, \boldsymbol{r_d}] \cdot [u, v, -t]^T = \boldsymbol{r_o} - \boldsymbol{pos} $$
    Let the solution vector be $\boldsymbol{uvt} = [u, v, t]$. The hit is valid if $t > 0$ and $u^2 + v^2 < 1.0$ (inside the unit circle in local space) [S3, unofficial].

4.  **Mode Selection**:
    The traversal supports two modes [S3, unofficial]:
    *   **Closest-Hit (`USE_ANYHIT=0`)**: Finds the nearest splat. Used for single-bounce or opaque-like rendering.
    *   **Any-Hit (`USE_ANYHIT=1`)**: Collects all splats intersected by the ray. Used for correct alpha blending of semi-transparent layers.

5.  **Radiance Accumulation**:
    *   **Closest-Hit Mode**: Loop up to 8 bounces.
        *   Intersect ray. If hit, accumulate color:
            $$ \text{cumColor} += T \cdot \text{hitOpacity} \cdot \text{hitColor} $$
        *   Update transmittance:
            $$ T *= 1.0 - \text{hitOpacity} $$
        *   Shift ray origin: $\boldsymbol{r_o} \leftarrow \boldsymbol{r_o} + (t + 10^{-6})\boldsymbol{r_d}$.
        *   Break if $T < 0.05$ [S3, unofficial].
    *   **Any-Hit Mode**:
        *   Collect all hits into a sorted array `intersects[N_INT]` (max size 32) using insertion sort by depth $d$ [S3, unofficial].
        *   If the array is full (`intersectPtr >= N_INT`), return early [S3, unofficial].
        *   Sort collected intersections by depth.
        *   Loop through sorted hits:
            $$ \text{cumColor} += T \cdot \text{rgba}.w \cdot \text{rgba}.xyz $$
            $$ T *= 1.0 - \text{rgba}.w $$

6.  **Alternative Volumetric Approach (S2)**:
    Some implementations approximate the Gaussian contribution as a point sample at an "equivalent intersection point" $\boldsymbol{r_x}$ [S2]:
    $$ \boldsymbol{r_x} = \boldsymbol{r_o} + t_j\boldsymbol{r_d} $$
    $$ t_j = \frac{(\boldsymbol{\mu} - \boldsymbol{r_o})^T \boldsymbol{\Sigma} \boldsymbol{r_d}}{\boldsymbol{r_d}^T \boldsymbol{\Sigma} \boldsymbol{r_d}} $$
    The contribution is approximated as $\alpha_j$ at $\boldsymbol{r_x}$. Transmittance is attenuated progressively:
    $$ T_i = (1 - \alpha_{i-1})T_{i-1}, \quad \text{for } i = 1, \ldots, j-1 \text{ with } T_1 = 1 $$
    Early termination occurs if transmittance drops below a threshold $T_{min}$ [S2].

### Parameters
*   **N_INT**: Maximum number of splat intersections stored in any-hit mode. Value: 32 [S3, unofficial].
*   **INFINITY**: Large float value for no-hit. Value: 1048576.0 [S3, unofficial].
*   **Tmin**: Threshold for early termination of ray tracing if transmittance drops below this value [S2].
*   **Batch Size**: Fixed-size groups of $N$ Gaussians for evaluation to avoid register spilling [S4].

### Edge Cases and Pitfalls
*   **Precision**: BVH traversal uses float for stack pointers and IDs. Inner nodes have negative IDs, leaves have positive. The check `id < 0.0` distinguishes them. Floating point comparison `currentStackData.t0 >= t` is used for pruning [S3, unofficial].
*   **Complexity**: Online visibility querying is computationally expensive. For static scenes, visibility is often pre-computed in a separate stage [S2].
*   **Register Spilling**: Large batches of Gaussians can cause register spilling in shaders. Batching evaluation into fixed-size groups mitigates this [S4].

## Subtopics

### [GRay](10042-gray.md)
A fast ray-tracing method for 3D Gaussian Splatting (3DGS) designed to close the performance gap between ray tracing and rasterization by leveraging the algorithmic advantage of ray tracing: it evaluates only intersected Gaussians, allowing logarithmic scaling in dense scenes with tiny Gaussians. Unlike 3DGS rasterization which operates on tiles and evaluates all Gaussians overlapping a tile for every pixel (linear scaling), GRay uses a Bounding Volume Hierarchy (BVH) to select and evaluate exactly the set of Gaussians intersecting each pixel. It builds on [3D Gaussian Ray Tracing](8101-3d-gaussian-ray-tracing.md), [EPBRR](8102-epbrr.md), and [EDGS](8103-edgs.md).

## Operating characteristics
*   **Time Complexity**: Logarithmic scaling with respect to the number of Gaussians in dense scenes, as only intersected Gaussians are evaluated via BVH traversal [S1, unofficial]. This contrasts with the linear scaling of rasterization in dense regions.
*   **Memory Complexity**: Requires storage for the BVH structure (AABB texture) and Gaussian data (Triangle texture). The BVH construction is done in-place or via parallel radix tree algorithms [S2].
*   **Performance**: On tested hardware, 3DGRT optimizes about 9× slower than a recent version of 3DGS rasterization [S4]. However, it provides physically plausible transparency and shadow effects that rasterization struggles with [S1, unofficial][S2].
*   **Strengths**: Correct handling of semi-transparent objects, volumetric accuracy, support for complex lighting (shadows, reflections) via ray tracing [S1, unofficial][S2].
*   **Limitations**: Slower than rasterization, computational complexity of online visibility querying for dynamic scenes [S2], precision issues in BVH traversal [S3, unofficial].
*   **When to use**: Scenes requiring high-fidelity transparency, shadows, or complex lighting interactions with 3D Gaussians [S1, unofficial][S2].
*   **When not to use**: Real-time applications where rasterization speed is critical and transparency artifacts are acceptable [S4].

## Background
3D Gaussian Ray Tracing was first studied as a hardware-accelerated alternative to rasterization for rendering 3D Gaussians by Moenne-Loccoz et al. [2024] using OptiX [S4]. It addresses the limitations of standard 3D Gaussian Splatting, which violates physical absorption-emission models for heterogeneous transparent media [S1, unofficial]. Subsequent work, such as Relightable 3D Gaussians, introduced point-based ray tracing for realistic point cloud relighting with BRDF decomposition [S2]. More recently, methods like GRay have optimized this approach to close the performance gap with rasterization [S1, unofficial].
