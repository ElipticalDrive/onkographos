# Edge-guided Splitting Strategy


## Overview
The Edge-guided Splitting Strategy (ESS) is a densification method for 3D Gaussian Splatting (3DGS) that refines primitives by splitting large Gaussians located in high-frequency edge regions to capture fine details [S1]. It addresses the weakness of enlarged primitives, which lose high-frequency detail, particularly when used in conjunction with Random Dropout Regularization (RDR) [S1]. Unlike standard splitting based solely on position gradient magnitude, ESS explicitly guides splitting toward geometric edges, making it distinct from sibling methods like Blended Error Densification which rely on rendering error [13892-blended-error-densification-and-splitting.md].

## How it works
**Inputs and Outputs**
*   **Input:** A set of 3D Gaussian primitives $\mathcal{G}$, each defined by mean position $\mu$, covariance $\Sigma$, scaling $s$, opacity $\alpha$, and spherical harmonic features $f$; a set of $M$ training viewpoints; and an edge detection function.
*   **Output:** An updated set of primitives where large Gaussians with high edge scores are split into smaller primitives.

**Data Structures**
*   **Gaussian Primitive $i$:** Contains scalar size $S_i$ (derived from scaling factors), opacity $\alpha_i$, and position.
*   **Edge Map $E(I)$:** A pixel-wise probability map ranging from 0 to 1, generated by an edge detection method on input view $I$ [S1].
*   **Binary Mask $\mathcal{M}^i(p)$:** Indicates if pixel $p$ is covered by primitive $i$ [S1].

**Parameters**
*   $\mathcal{S}_{thr}$: Size threshold for splitting. Value not given in the sources.
*   $\mathcal{E}_{thr}$: Edge threshold for splitting. Value not given in the sources.
*   $M$: Number of viewpoints used for edge score accumulation.

**Steps**
1.  **Edge Map Generation:** For each input view $I$, compute the pixel-wise edge probability map $E(I)$ using an edge detection method [S1].
2.  **Single-View Edge Score Calculation:** For each Gaussian primitive $i$ and each viewpoint $k$, calculate the single-view edge score $\mathcal{E}_{i,k}'$ by aggregating the edge probabilities of covered pixels, weighted by the primitive's contribution to the pixel [S1]:
    $$ \mathcal{E}_{i,k}' = \alpha_i \prod_{j=1}^{i-1}(1-\alpha_j) \cdot \sum_{p} E(I_k) \mathcal{M}_k^i(p) $$
    where $\mathcal{M}_k^i(p)$ is the binary mask for pixel $p$ covered by primitive $i$ in view $k$, and the term $\alpha_i \prod_{j=1}^{i-1}(1-\alpha_j)$ represents the alpha-blending weight $w_i$ of the primitive [S1].
3.  **Accumulate Edge Score:** Compute the final edge score $\mathcal{E}_i$ for primitive $i$ by summing the single-view scores across all $M$ viewpoints, normalized by the number of pixels covered by the primitive in each view [S1]:
    $$ \mathcal{E}_i = \sum_{k=1}^M \frac{\mathcal{E}_{i,k}'}{\sum_{p} \mathcal{M}_k^i(p)} $$
4.  **Splitting Mask Determination:** Identify primitives to split using the mask $\mathcal{M}_{edge}$, which selects primitives satisfying both a size condition and an edge score condition [S1]:
    $$ \mathcal{M}_{edge} = \{ S_i \geq \mathcal{S}_{thr} \} \cap \{ \mathcal{E}_i \geq \mathcal{E}_{thr} \} $$
    where $S_i$ is the size of the $i$-th primitive [S1].
5.  **Splitting:** Split all Gaussian primitives $i$ where $\mathcal{M}_{edge}$ is true into smaller primitives [S1].

**Pseudocode**
```python
def compute_edge_score(primitive, view_index, edge_map, camera):
    """
    Computes the single-view edge score E_i' for a primitive.
    """
    # Project primitive to view to get coverage mask M^i(p)
    # This involves projecting the 3D Gaussian to 2D and determining
    # which pixels it covers.
    coverage_mask = project_and_mask(primitive, camera)
    
    # Calculate alpha blending weight w_i
    # Note: In standard 3DGS, w_i depends on the order of primitives.
    # For simplicity in this isolated function, we assume w_i is precomputed
    # or approximated by alpha_i if order is not strictly enforced in this step.
    # The source formula uses alpha_i * product(1-alpha_j).
    # [G] Assuming w_i is available or computed via standard 3DGS rasterization order.
    weight = primitive.alpha * compute_preceding_alpha_product(primitive, camera)
    
    # Sum edge probabilities for covered pixels
    # E(I) is the edge map for the current view
    edge_sum = sum(edge_map[p] for p in coverage_mask)
    
    return weight * edge_sum

def accumulate_edge_scores(primitives, views, edge_maps, cameras):
    """
    Computes the final edge score E_i for each primitive across M views.
    """
    M = len(views)
    final_scores = {}
    
    for i, primitive in enumerate(primitives):
        total_score = 0.0
        for k in range(M):
            view = views[k]
            edge_map = edge_maps[k]
            camera = cameras[k]
            
            # Compute single-view score
            e_prime = compute_edge_score(primitive, k, edge_map, camera)
            
            # Compute number of pixels covered by primitive in this view
            coverage_mask = project_and_mask(primitive, camera)
            pixel_count = len(coverage_mask)
            
            # Avoid division by zero
            if pixel_count > 0:
                total_score += e_prime / pixel_count
            else:
                total_score += 0.0
                
        final_scores[primitive.id] = total_score
        
    return final_scores

def apply_edge_guided_splitting(primitives, edge_scores, s_thr, e_thr):
    """
    Splits primitives that are large and have high edge scores.
    """
    to_split = []
    
    for primitive in primitives:
        size = get_primitive_size(primitive) # Derived from scaling factors
        score = edge_scores[primitive.id]
        
        if size >= s_thr and score >= e_thr:
            to_split.append(primitive)
            
    # Split the selected primitives into smaller ones
    # [G] The specific splitting logic (e.g., copying, perturbing mean, halving scale)
    # is not detailed in the source, but standard 3DGS splitting is assumed.
    new_primitives = []
    for primitive in to_split:
        new_primitives.extend(split_primitive(primitive))
        
    # Remove old primitives and add new ones
    remaining = [p for p in primitives if p not in to_split]
    return remaining + new_primitives
```

**Edge Cases and Pitfalls**
*   **Division by Zero:** The normalization in the edge score accumulation divides by the number of pixels covered by the primitive. If a primitive covers zero pixels in a view, the contribution is zero [S1].
*   **Threshold Selection:** The values for $\mathcal{S}_{thr}$ and $\mathcal{E}_{thr}$ are not specified in the sources. Improper selection may lead to over-splitting (noise) or under-splitting (loss of detail) [S1].
*   **Edge Detection Dependency:** The quality of ESS depends on the edge detection method used to generate $E(I)$ [S1].

## Operating characteristics
*   **Time Complexity:** Adds overhead for edge map generation and edge score calculation per primitive per view. The splitting step is proportional to the number of primitives meeting the threshold.
*   **Memory Complexity:** No significant additional memory beyond storing edge maps and scores.
*   **Strengths:** Effectively captures high-frequency details in edge regions, improving performance on sparse-view benchmarks (LLFF, DTU, Blender) [S1]. Compatible with diverse 3DGS-based methods [S1].
*   **Limitations:** Relies on the quality of edge detection. Does not address overfitting directly (requires RDR for that) [S1].
*   **When to Use:** When high-frequency detail recovery is critical, especially in sparse-view settings or when using regularization techniques like RDR that may enlarge primitives [S1].

## Background
The Edge-guided Splitting Strategy (ESS) was introduced in the DropoutGS paper by Xu et al. in 2025 [S1]. It was developed to remedy the loss of high-frequency details caused by Random Dropout Regularization (RDR), which alleviates overfitting but leads to enlarged primitives [S1]. DropoutGS combines RDR and ESS to improve generalization performance in sparse-view novel view synthesis [S1].
