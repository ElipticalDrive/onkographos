# 2D-Lift-3D Scene Segmentation

Also called: 2D-Lift-3D Segmentation for Partial Scene Editing, PSE with 2D-lift-3D segmentation

## Overview
2D-Lift-3D Scene Segmentation is a training-free method for segmenting 3D Gaussian primitives by lifting 2D segmentation masks from a reference view into 3D space. It solves the problem of isolating specific objects or parts within a volumetric scene represented by 3D Gaussian Splatting (3DGS) to enable partial scene editing (PSE) [S1]. Unlike methods that require learnable feature vectors or explicit surface reconstruction, this approach relies on multi-view label voting to assign semantic labels to Gaussians based on 2D foundation model outputs [S1]. It is distinguished from [Gaussian Opacity Fields (GOF) Mesh Extraction](3692-gaussian-opacity-fields-gof-mesh-extraction.md) by its focus on semantic grouping for editing rather than geometric mesh extraction, and from [Distance-based Gaussian Splatting](7411-distance-based-gaussian-splatting.md) by its reliance on external 2D priors rather than implicit distance fields.

## How it works
**Inputs:**
*   A trained 3D Gaussian Splatting model $\mathcal{G} = \{G_i\}_{i=1}^M$, where each primitive $G_i$ has mean $\mathbf{p}_i$, covariance $\mathbf{\Sigma}_i$, opacity $\alpha_i$, and color attributes [Parent].
*   A set of $N$ training views with known camera poses.
*   A reference view image $I_{ref}$ rendered from $\mathcal{G}$.
*   User-specified point prompts on $I_{ref}$.

**Outputs:**
*   A label assignment $L_i \in \{0, 1, \dots, K\}$ for each Gaussian $G_i$, where $K$ is the number of segmented parts.

**Data Structures:**
*   **Gaussian List:** Array of $M$ primitives. Each primitive stores its 3D position $\mathbf{p}_i$, projected 2D covariance $\mathbf{\hat{\Sigma}}_i$, opacity $\alpha_i$, and a label attribute $L_i$ initialized to $-1$ (unassigned).
*   **Label Vote Counter:** An array of size $M$ initialized to zero, storing the number of views supporting a specific label for each Gaussian.

**Steps:**

1.  **Render Reference View:** Render the image $I_{ref}$ from the chosen reference camera pose using standard differentiable rasterization of $\mathcal{G}$ [S1].
2.  **Generate 2D Mask:** Use the Segment Anything Model (SAM) with user-specified point prompts on $I_{ref}$ to generate a binary segmentation mask $M_{ref}$ [S1].
3.  **Generate Multi-View 2D Masks:** For each training view $v \in \{1, \dots, N\}$:
    a. Render the image $I_v$ from the camera pose of view $v$.
    b. Project the 2D mask $M_{ref}$ from the reference view to the current view $v$. This requires the inverse projection matrix and camera extrinsics to map the 2D coordinates of the mask pixels to the 2D coordinates of view $v$ [S1].
    c. Generate a 2D mask $M_v$ for view $v$ using SAM with point prompts derived from the projected locations of $M_{ref}$, or by directly using the projected mask if geometric consistency is assumed [S1]. *Note: The source describes generating masks for corresponding parts across all training views using SAM, implying either direct prompting or propagation.*
4.  **Label Propagation (Per View):** For each view $v$ and its mask $M_v$:
    a. Iterate through all Gaussians $G_i$.
    b. Project $G_i$ to 2D screen space to obtain center $\mathbf{c}_i$ and covariance $\mathbf{\hat{\Sigma}}_i$ [Parent].
    c. Check if the center $\mathbf{c}_i$ falls within the foreground region of $M_v$.
    d. If yes, assign a temporary label $l_{i,v}$ corresponding to the segment in $M_v$ to Gaussian $G_i$.
5.  **Multi-View Label Voting:**
    a. Initialize $Vote_i = 0$ and $FinalLabel_i = -1$ for all $i$.
    b. For each Gaussian $G_i$, count the number of views $v$ where $G_i$ was assigned a valid label $l_{i,v}$.
    c. Determine the dominant label. If a label $l$ appears in more than a threshold number of views (or consistently across views), assign $L_i = l$.
    d. If no consistent label is found, $G_i$ remains unassigned or is assigned to background [S1].
6.  **Segmentation Result:** The set of Gaussians $\{G_i | L_i = k\}$ forms the $k$-th segmented part of the scene [S1].

**Pseudocode:**

```python
def lift_2d_to_3d_segmentation(gaussians, training_views, reference_view_idx, point_prompts):
    """
    gaussians: List of Gaussian primitives with attributes p, sigma, alpha, color.
    training_views: List of camera objects (extrinsics, intrinsics) for N views.
    reference_view_idx: Index of the reference view in training_views.
    point_prompts: List of (x, y) coordinates on the reference view image.
    """
    N = len(training_views)
    M = len(gaussians)
    
    # Initialize label storage
    # label_votes[i] is a dictionary mapping label_id -> count
    label_votes = [{} for _ in range(M)]
    
    # Step 1: Render Reference View
    ref_view = training_views[reference_view_idx]
    ref_image = render_gaussians(gaussians, ref_view)
    
    # Step 2: Generate 2D Mask on Reference View using SAM
    # SAM takes image and point prompts
    ref_mask = sam_segment(ref_image, point_prompts)
    
    # Step 3 & 4: Process all training views
    for v_idx, view in enumerate(training_views):
        # Render current view
        view_image = render_gaussians(gaussians, view)
        
        # Generate 2D mask for this view
        # Method: Project reference mask points to current view and prompt SAM,
        # or use SAM directly if the view shows the same object clearly.
        # The source implies generating masks for corresponding parts across all views.
        # We assume we have a way to get a mask M_v for the target object in view v.
        # If using projection:
        projected_points = project_points_to_view(point_prompts, ref_view, view)
        view_mask = sam_segment(view_image, projected_points)
        
        # Label Propagation
        for i in range(M):
            G = gaussians[i]
            
            # Project Gaussian to 2D
            center_2d, cov_2d = project_gaussian_2d(G, view)
            
            # Check if Gaussian center is inside the mask
            # Simple point-in-polygon or pixel check
            if is_inside_mask(center_2d, view_mask):
                # Determine which segment in view_mask this corresponds to.
                # If view_mask is binary (foreground/background), label is 1.
                # If multi-class, identify the class at center_2d.
                label_id = get_label_at_pixel(view_mask, center_2d)
                
                if label_id is not None:
                    if label_id not in label_votes[i]:
                        label_votes[i][label_id] = 0
                    label_votes[i][label_id] += 1

    # Step 5: Multi-View Label Voting
    final_labels = [-1] * M
    for i in range(M):
        votes = label_votes[i]
        if not votes:
            continue
        
        # Find label with max votes
        best_label = max(votes, key=votes.get)
        max_count = votes[best_label]
        
        # Thresholding: require consistent voting across views
        # Not given in sources exactly, but implied by "multi-view label voting technique"
        if max_count > 0: 
            final_labels[i] = best_label
            
    return final_labels
```

**Parameters:**
*   **Point Prompts:** User-defined 2D coordinates on the reference view. Accuracy is critical; vague prompts lead to errors [S1].
*   **SAM Model:** Segment Anything Model, used for 2D mask generation [S1].

**Edge Cases and Pitfalls:**
*   **Inefficiency:** The method cannot immediately generate a perfect 3D segmentation from a single 2D mask. It may require multiple rounds of segmentation with adjusted prompts for complex scenes, which is inefficient [S1].
*   **Occlusion:** If the object is occluded in many training views, the voting count may be low, leading to incomplete segmentation.
*   **Label Consistency:** Different views might assign different semantic labels to the same object if SAM interprets context differently. The voting mechanism mitigates this but requires a consistent labeling scheme.

## Subtopics

### [SA3D](14892-sa3d.md)
SA3D is a method for 3D object segmentation within 3D Gaussian Splatting that leverages the Segment Anything Model (SAM) to generate initial 2D masks from text or point prompts in a single view. It distinguishes itself by alternating between mask inverse rendering and cross-view self-prompting to iteratively refine the 3D mask until complete object segmentation is achieved, avoiding the need for manual multi-view annotation. It is chosen when interactive refinement is preferred over batch multi-view voting. See [SA3D](14892-sa3d.md).

### Fine-Level Affinity-Based Segmentation
This variant refines coarse segmentation by learning affinity features from 2D masks generated by SAM, enabling fine-grained structure distinction [S2]. It lifts 2D masks to a 3D affinity field to subdivide coarse-level color-based segmentation results [S2]. It is chosen when color-based segmentation is insufficient to distinguish fine-grained structures within components that share similar colors [S2].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot M)$ for label propagation, where $N$ is the number of training views and $M$ is the number of Gaussians. SAM inference is $O(N)$ for mask generation.
*   **Memory Complexity:** $O(M)$ to store label votes and final labels. No additional learnable parameters are required (training-free) [S1].
*   **Performance:** Enables real-time partial scene editing (PSE) after segmentation [S1]. Rendering time for the base scene is unaffected by the segmentation step, which is a post-processing or pre-processing step.
*   **Strengths:** Training-free; leverages powerful 2D foundation models (SAM); allows flexible partial editing of color, opacity, and lighting [S1].
*   **Limitations:** Inefficient for scenes requiring multiple rounds of segmentation; dependent on the quality of SAM prompts; may struggle with highly occluded or ambiguous objects [S1].
*   **When to use:** When rapid, interactive segmentation of specific parts of a 3DGS scene is needed for editing, and training a new model is not feasible.
*   **When not to use:** When high-precision, automatic segmentation without user prompts is required, or when the scene has significant occlusion that breaks multi-view consistency.

## Background
The method originates from the need for partial scene editing in volume visualization using 3D Gaussian Splatting. It was introduced in **TexGS-VolVis** (2025) by the authors of [S1], building on prior work in 2D-lift-3D segmentation [5, 8, 25, 35]. It addresses the limitation of previous methods like StyleRF-VolVis, which could not apply distinct edits to different parts of a basic scene [S1]. The approach is inspired by SAGD [25] for its training-free nature. It is used in scientific visualization (VolVis) to decompose scenes into parts for independent editing of color, opacity, and lighting [S1].
