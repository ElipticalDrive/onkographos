# Multi-View Density Control Criterion

Also called: Absolute-gradient split proxy, FastGS criterion, Multi-view Adaptive Density Control (ADC)

## Overview
The Multi-View Density Control Criterion is a densification strategy for 3D Gaussian Splatting designed to resolve invalid vector arithmetic that occurs when applying standard Adaptive Density Control (ADC) to multi-view training scenarios [S1, unofficial]. It replaces the summation of 2D positional gradient vectors with a metric based on the sum of squared norms, ensuring that error metrics remain valid across multiple image planes [S1, unofficial]. It yields higher reconstruction quality with fewer primitives compared to standard positional-gradient rules [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $N$ viewpoints; for each viewpoint, a set of pixels covering the Gaussian; the loss function $L$ and its gradients $\nabla_{\pi} L$ at each pixel $\pi$.
*   **Output:** A scalar error metric $E_1(G)$ for each Gaussian $G$, used to determine if the Gaussian should be split or cloned.

**Data Structures:**
*   **Gradients:** For each pixel $\pi$ covering a Gaussian, the 2D positional gradient $\nabla_{\pi} L$ is a 2D vector $(\frac{\partial L}{\partial u}, \frac{\partial L}{\partial v})$ in the image plane coordinate system of the specific viewpoint [S1, unofficial].

**Method:**
1.  **Identify Coverage:** For a given Gaussian $G$, identify all pixels $\pi$ across all $N$ viewpoints that project onto the Gaussian's footprint. Let $V_{\pi}$ be the viewpoint index for pixel $\pi$.
2.  **Compute Norms:** For each pixel $\pi$, compute the squared Euclidean norm of its positional gradient: $\|\nabla_{\pi} L\|^2 = (\frac{\partial L}{\partial u})^2 + (\frac{\partial L}{\partial v})^2$.
3.  **Aggregate:** Sum these squared norms across all pixels covering the Gaussian.

**Formula:**
The error metric $E_1(G)$ is defined as:
$$ E_1(G) = \sum_{k=1}^{N} \sum_{\pi: V_{\pi}=k} \|\nabla_{\pi} L\|^2 $$
where:
*   $N$ is the total number of viewpoints.
*   $k$ iterates over each viewpoint.
*   $\pi$ iterates over all pixels belonging to viewpoint $k$ that cover the Gaussian.
*   $\nabla_{\pi} L$ is the 2D positional gradient of the loss with respect to the pixel coordinates $(u, v)$ at pixel $\pi$ [S1, unofficial].

**Parameters:**
*   **Thresholds:** The resulting $E_1(G)$ is compared against splitting and cloning thresholds defined in the parent [Splitting Criteria and Prioritization](16226-splitting-criteria-and-prioritization.md). Specific threshold values are not provided in the sources for this specific criterion, but it is applied during the teacher training phase [S2, unofficial].

**Pitfalls and Edge Cases:**
*   **Invalid Vector Addition:** Standard ADC sums 2D positional gradients directly: $E_{old}(G) = \sum \nabla_{\pi} L$. In multi-view training, a Gaussian is projected onto multiple image planes. The 2D gradient vectors from different viewpoints exist in different coordinate spaces. Adding them directly is mathematically invalid and can result in cancellation (e.g., zero vectors) even if the underlying 3D gradients are identical and large [S1, unofficial].
*   **Precision:** The use of squared norms avoids cancellation errors inherent in vector addition across different spaces [S1, unofficial].

**Pseudocode:**
```python
def compute_multiview_density_error(gaussian, viewpoints, gradients):
    """
    Computes the Multi-View Density Control Criterion error for a single Gaussian.
    
    Args:
        gaussian: Object representing the 3D Gaussian.
        viewpoints: List of viewpoint indices [0, ..., N-1].
        gradients: Dictionary mapping (viewpoint_idx, pixel_idx) to 2D gradient vector (du, dv).
                   Only entries for pixels covering the Gaussian are included.
    
    Returns:
        float: The sum of squared norms of the positional gradients.
    """
    total_error = 0.0
    
    # Iterate over all viewpoints
    for v_idx in viewpoints:
        # Iterate over all pixels in this viewpoint that cover the Gaussian
        # In implementation, this is typically done by iterating over the 
        # list of pixels known to cover the Gaussian, filtered by viewpoint.
        for p_idx in get_pixels_covering_gaussian(gaussian, v_idx):
            # Retrieve the 2D positional gradient for this pixel
            grad = gradients[(v_idx, p_idx)]
            
            # Compute squared Euclidean norm: du^2 + dv^2
            squared_norm = grad[0]**2 + grad[1]**2
            
            # Accumulate
            total_error += squared_norm
            
    return total_error
```

## Subtopics

### DS Threshold (DSTH)
A hyperparameter threshold that controls the densification constraints of Gaussians. Increasing the DSTH imposes stricter constraints, which reduces the number of Gaussians (NGS), rendering quality, and training time [S3, unofficial]. The default value is 30. For the playroom scene in the DeepBlending dataset, it is set to 60; other scenes use 30 [S3, unofficial]. Lowering the threshold (e.g., sub 20) increases the number of Gaussians and training time but may improve quality metrics like PSNR and SSIM [S3, unofficial].

## Operating characteristics
*   **Performance:** The multi-view criterion yields an average improvement of 0.67 dB in PSNR and 0.028 in LPIPS compared to standard methods, while using 28% fewer primitives at the same time [S2, unofficial].
*   **Primitive Count:** On the "garden" scene, the standard positional-gradient rule produces 240,075 primitives, whereas the multi-view criterion produces 148,658 primitives [S2, unofficial].
*   **Quality Metrics:** On the "garden" scene, the multi-view criterion achieves a PSNR of 27.06 (vs 26.83 for standard) and an LPIPS of 0.1247 (vs 0.1303 for standard) [S2, unofficial].
*   **Usage:** It is applied during the teacher training phase to control primitive count and distribution [S2, unofficial].
*   **Strengths:** Resolves the invalid arithmetic issue in multi-view training, leading to more accurate densification decisions and fewer redundant primitives.
*   **Limitations:** Requires computing squared norms and summing them, which may have slightly different computational characteristics than simple vector addition, though the sources do not specify the exact overhead.

## Background
The method was proposed to address the incompatibility of standard 3D Gaussian Splatting's densification strategy with efficient multi-view training frameworks [S1, unofficial]. Standard ADC, which relies on summing 2D positional gradients, fails in multi-view settings because gradients from different image planes cannot be meaningfully added [S1, unofficial]. The Multi-View Density Control Criterion was introduced as a space-independent error metric to fix this [S1, unofficial]. It is cited in works related to efficient multi-view training for 3DGS [S1, unofficial] and ultrafast spatial texture-atlas splatting [S2, unofficial].
