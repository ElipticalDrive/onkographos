# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, GSGEN Implementation Details, Gaussian Splatting Training Configuration, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific implementation parameters, optimization strategies, and variant algorithms used to train and render 3D Gaussian Splatting (3DGS) scenes. It addresses the practical challenges of differentiable rasterization, including half-precision arithmetic stability, adaptive density control thresholds, and handling of transient distractors or defocus blur. While the parent method [Optimization and Parallelization](6233-optimization-and-parallelization.md) provides the foundational differentiable rasterization core, this article specifies the hyperparameters, data structures, and variant logic required for robust implementation.

## How it works

### Inputs and Outputs
*   **Inputs**: Sparse Structure-from-Motion (SfM) point cloud (positions, colors), camera poses (extrinsics $C_i$ and intrinsics $K_i$), and ground-truth images.
*   **Outputs**: Optimized set of 3D Gaussians $\mathcal{G} = \{\mu_j, \Sigma_j, \alpha_j, c_j\}$, where $\mu_j$ is position, $\Sigma_j$ is covariance, $\alpha_j$ is opacity, and $c_j$ are spherical harmonic (SH) coefficients for color.

### Data Structures
The Gaussian representation is stored in a flat array or structure-of-arrays (SoA) layout for efficient GPU access [S2].
*   **Position**: $\mathbb{R}^3$ (float32 or float16).
*   **Covariance**: Stored as a $3 \times 3$ rotation matrix $R$ and scaling vector $s$. The covariance is $\Sigma = R S S^T R^T$, where $S = \text{diag}(s)$ [S5].
*   **Opacity**: $\mathbb{R}$ (sigmoid output).
*   **Color**: SH coefficients. Default degree is 1 (9 coefficients per RGB channel) [S3].
*   **Gradients**: Accumulated per-iteration gradients for position and scale to drive densification [S1].

### Training Optimization and Initialization

#### Standard 3DGS Training Loop
The training process iterates over random views, rendering them via differentiable rasterization and computing loss against ground truth [S3].

1.  **Initialization**: Initialize Gaussians from SfM points. Set initial covariance based on local neighborhood distance [S4].
2.  **Optimization**: Use Adam optimizer with learning rate $1 \times 10^{-3}$ [S3].
3.  **Loss Function**: Combine Mean Squared Error (MSE) and Structural Similarity Index (SSIM):
    $$ \mathcal{L} = \lambda \cdot \text{MSE}(C, \hat{C}) + (1 - \lambda) \cdot \text{SSIM}(C, \hat{C}) $$
    where $\lambda$ balances the terms, $C$ is ground-truth color, and $\hat{C}$ is rendered color [S13, unofficial].
4.  **Densification**: Every 100–500 iterations, split or clone Gaussians based on gradient magnitude [S1].
5.  **Pruning**: Every 200 iterations, remove Gaussians with opacity $\alpha < \alpha_{\min}$ (typically 0.05) or excessive radius [S1].

#### Half-Precision Implementation (gsplat)
To reduce register pressure and memory bandwidth, the `gsplat` library implements the rasterization in half-precision (FP16) [S2].
*   **Memory Fetches**: Feature vectors are fetched in half-precision during both forward and backward passes [S2].
*   **Stability**: An automatic scaling factor is applied to loss values to prevent gradient underflow/overflow during backpropagation [S2].
*   **MLP Evaluation**: If using neural components (e.g., for view-dependent color), they are evaluated using tiny-cuda-nn's JIT-compiled cooperative vector MLPs in FP16 [S2].

#### Adaptive Density Control and Scene Extent
Standard 3DGS uses camera positions to estimate scene extent, which biases densification if cameras are clustered (e.g., orbiting a small object) [S4].

**Corrected Scene Extent**:
Calculate the average camera position $\bar{C}$:
$$ \bar{C} = \frac{1}{N_{\text{cam}}} \sum_{i=1}^{N_{\text{cam}}} C_i $$
Calculate the corrected scene extent $e'_{\text{scene}}$ using SfM points $p_i$:
$$ e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2 $$
This prevents incorrect splitting/pruning in large environments with clustered cameras [S4].

**Gradient Threshold Schedule**:
Split Gaussians based on view-space position gradient threshold $T_{\text{pos}}$.
*   Standard threshold: $T_{\text{pos}} = 0.02$ [S1].
*   Exponential schedule: The threshold can be scaled exponentially over densification intervals to control the number of created Gaussians [S4].

### Variant Algorithms

#### Selective Defocus Blurring
To handle defocus blur in training images, predict a per-Gaussian scale offset $\delta s_j$ using a compact MLP [S5].
1.  Predict $\delta s_j$ for each Gaussian $j$.
2.  Add offset to base scale to transform covariance.
3.  Project transformed covariance to 2D space to act as a pixel-wise blur kernel.
*   **Pitfall**: If $\delta s_j$ is constant, it degrades to a uniform Gaussian blur [S5].

#### Denoise-GS
For sparse-view and noisy scenes, use a two-round self-supervised denoising pipeline [S6]:
1.  **Round 1**: Train a UNet using Noise2Void (N2V) for denoising. Process denoised images through InstantSplat to initialize 3DGS.
2.  **Round 2**: Fine-tune the UNet using a composite loss (low-frequency consistency + perceptual detail). Render again on selected viewpoints.
*   **Comparison**: N2V requires no paired data, unlike Noise2Noise (N2N), making it suitable for sparse views where only one image per viewpoint exists [S6].

#### Multi-Scale Constraint
For large-scale scenes, apply position-aware point adaptive control [S7]:
1.  Compute distance factor $\gamma(\mu)$:
    $$ \gamma(\mu) = \begin{cases} 1 & \text{if } \|\mu - c\|^2 < 2r \\ \|\mu - c\|^2 / r - 1 & \text{if } \|\mu - c\|^2 \ge 2r \end{cases} $$
    where $r$ is scene radius and $c$ is camera center.
2.  If $\max(s) < g \cdot \gamma(\mu)$, clone the Gaussian.
3.  If $\max(s) \ge g \cdot \gamma(\mu)$, split the Gaussian.
4.  If $\max(s) > b \cdot \gamma(\mu)$, eliminate the Gaussian.
*   **Parameters**: $g$ (clone threshold), $b$ (elimination threshold) [S7].

#### LS-Gaussian Viewpoint Transformation
For real-time streaming, leverage inter-frame continuity by transforming viewpoints between consecutive frames rather than rendering each frame separately [S8].
*   **Usage**: Fully render one frame every 6 frames; transform Gaussians for intermediate frames.
*   **Pitfall**: Rendering quality degrades as the number of consecutively transformed frames increases due to accumulated interpolation errors [S8].

#### Camera Localisation for Convergence Basin
To initialize camera poses for SLAM, minimize photometric error against ground-truth color [S9, unofficial]:
1.  Fix $G_{\text{init}}$.
2.  Initialize $T_{CW}$ at a test view's position.
3.  Optimize for 1000 iterations.
4.  Success if pose converges within 1cm of target view.
$$ \mathbf{T}_{CW}^{est} = \underset{\mathbf{T}_{CW}}{\arg \min} \left\| I(\mathcal{G}_{\text{init}}, \mathbf{T}_{CW}) - \bar{I}_{\text{target}} \right\|_1 $$

#### DiffGS Framework
Optimize Gaussians to exact locations using a Gaussian Probability Function (GauPF) with a truncation function $\lambda$ and projection function $\tau$ (e.g., $\tau(x) = e^{-x}$) [S10].
*   **Performance**: 50K Gaussians: PSNR 28.61, SSIM 0.9787, LPIPS 0.0251. 100K Gaussians: PSNR 30.35, SSIM 0.9838, LPIPS 0.0151. 350K Gaussians: PSNR 34.01, SSIM 0.9879, LPIPS 0.0149 [S10].

#### Conditional Splat Approximation
Approximate the influence range of a 3D Gaussian on a slice using a 2D ellipse splat scaled by the marginal factor. This closely matches true iso-probability contours [S12, unofficial].

#### PyGS Optimization
For multi-scale scenes, use a combined MSE and SSIM loss [S13, unofficial]:
1.  Apply splitting/cloning from 3DGS.
2.  Routinely reassess and reassign levels of Gaussians based on scales to preserve multi-scale characteristics.

#### GAINS (Inverse Rendering)
A two-stage framework for sparse multi-view captures [S14]:
1.  **Stage I**: Optimize geometry using monocular depth, normal, and diffusion priors.
2.  **Stage II**: Jointly optimize material parameters and lighting using segmentation, intrinsic image decomposition (IID), and diffusion priors.
*   **Note**: Uses 2DGS for more accurate geometry reconstruction [S14].

#### Neural Illumination Enhancement (NIE)
Model non-Lambertian effects by adding a neural residual $I_n$ to the explicit Gaussian image $I_g$ [S16, unofficial]:
1.  Input spatial position, reflection direction, and material features (view direction, normals, Fresnel, roughness) into an MLP.
2.  Encode spatial positions with HashGrid and reflection directions with SH.
3.  Compute final image: $I = I_g + I_n$.

#### GraphiGS
Model component distribution $\delta_\theta$ as a 3D Gaussian primitive for compact spatial support [S17]:
$$ \delta_{\text{GS}}(x; \mu, \Sigma) = \exp\left(-\frac{1}{2} (x - \mu)^T \Sigma^{-1} (x - \mu)\right) $$

#### Direct Gaussian Primitive Regularization
Align 2D Gaussian primitives with latent scene surfaces using multi-view consistency [S18]:
1.  Sample points $Z$ from standard Gaussian on each primitive.
2.  Project to source/target views to get 2D positions $q_{\text{src}}, q_{\text{tar}}$.
3.  Query MVS features $F_{\text{src}}, F_{\text{tar}}$.
4.  Compute point position loss $L_{df}$ via cosine similarity and normal loss $L_{dn}$ using rendered normal $n$.
5.  Combine: $L_{dr} = L_{df} + L_{dn}$.
*   **Pitfall**: The last scale value of 2D Gaussian primitives is zero, making normal optimization difficult [S18].

#### Geometrically Enhanced Supervision
Prevent geometric degradation under sparse views by fixing MVS features $f_{ij}$ and RGB colors $c_{ij}$ during optimization [S18]:
1.  Extract MVS features from CLMVSNet FPN.
2.  Sample features into Gaussians at projected 3D points.
3.  Fix values to enforce geometric learning.
*   **Pitfall**: Simultaneous learning of appearance and feature causes degradation [S18].

#### SpotLessSplats (SLS)
Remove transient distractors using robust masking [S19]:
*   **SLS-mlp**: Train a lightweight MLP (30K params, 2 nonlinear activations) to predict distractor masks. Adapts better to subtle transients like shadows than CNNs.
*   **SLS-agg**: Use agglomerative clustering on semantic features. Faster than MLP, performance plateaus at $C \ge 100$ clusters.
*   **Uncertainty-based Pruning**: Compute epistemic uncertainty per primitive and threshold to remove lesser-used Gaussians. Aggressive thresholds may remove rarely viewed scene parts [S19].

## Operating characteristics

*   **Time Complexity**: Rendering is $O(N \cdot M)$ where $N$ is the number of Gaussians and $M$ is the number of pixels, but optimized via tile-based rasterization to be effectively linear in practice [6233-optimization-and-parallelization]. Training time is dominated by the iterative densification and backpropagation steps.
*   **Memory Complexity**: $O(N)$ per Gaussian. Standard 3DGS scenes can exceed 1GB for real-world datasets [12943-data-compression-and-storage-optimization.md]. Half-precision implementations reduce memory bandwidth requirements [S2].
*   **Performance**: Real-time rendering (60+ FPS) is achievable on modern GPUs with optimized CUDA kernels [6233-optimization-and-parallelization]. Training can take several hours to days depending on scene complexity and densification steps [S3].
*   **Strengths**: High-fidelity novel view synthesis, real-time rendering speeds, explicit representation allows for easy editing and compression [12943-data-compression-and-storage-optimization.md].
*   **Limitations**: Sensitive to initialization, prone to "floaters" in unobserved regions, and requires significant memory for large scenes [15421-scene-representation-and-geometry-constraints.md].

## Background

3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1]. It revolutionized neural rendering by replacing implicit neural fields with explicit 3D Gaussian primitives, enabling real-time differentiable rasterization. The method builds on earlier work in splatting and neural rendering, addressing the computational bottlenecks of NeRF-based methods [6233-optimization-and-parallelization]. Subsequent research has focused on optimization efficiency, compression, and handling dynamic scenes and complex lighting [S1-S19].
