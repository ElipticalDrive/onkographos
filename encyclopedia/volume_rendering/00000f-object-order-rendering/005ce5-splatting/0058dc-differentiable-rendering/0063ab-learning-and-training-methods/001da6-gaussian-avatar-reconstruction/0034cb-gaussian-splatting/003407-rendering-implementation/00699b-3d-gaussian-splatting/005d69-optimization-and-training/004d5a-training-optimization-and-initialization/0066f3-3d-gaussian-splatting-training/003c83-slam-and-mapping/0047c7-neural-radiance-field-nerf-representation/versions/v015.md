# Neural Radiance Field (NeRF) Representation

Also called: Instant Neural Graphics Primitives (INGP), Photon Field Networks, Photon Fields

## Overview
Neural Radiance Field (NeRF) representation refers to a family of methods that use neural networks to implicitly encode 3D scenes for novel view synthesis or real-time rendering. This article covers two distinct but related implementations found in the source material: **Photon Field Networks** (an implicit method for global illumination in volumetric media) and **3D Gaussian Splatting** (an explicit method using differentiable rasterization of Gaussian blobs). While standard NeRF methods [S1] map spatial coordinates and view directions to color and density via a Multi-Layer Perceptron (MLP), 3D Gaussian Splatting [S2, unofficial] abandons the implicit field evaluation for real-time performance, storing the scene explicitly as millions of 3D Gaussians. Photon Fields specifically target indirect global illumination in heterogeneous media, whereas Gaussian Splatting focuses on high-fidelity, real-time rendering of general scenes.

## How it works

### 1. Photon Field Networks (Implicit Volumetric Global Illumination)
This method represents the scene as a neural network that approximates the indirect in-scattered radiance (global illumination) for volumetric media.

**Inputs and Outputs:**
*   **Input:** Sample position $x \in [0,1]^3$, view direction $\vec{\omega}$ (normalized spherical coordinates), and a phase function coefficient $g \in [-1,1]$ determining scattering behavior (backward to forward).
*   **Output:** Predicted log-encoded indirect radiance $L_i'(x, \vec{\omega})$, which is decoded to RGB indirect radiance.

**Data Structures:**
*   **Hashgrid Encoding:** Positions ($x$) and directions ($\vec{\omega}$) are encoded using a hashgrid with 16 levels, 8 features per level, a 2x scaling factor between levels, and a hash table size of $2^{19}$. The phase coefficient $g$ is left unencoded.
*   **Network:** A 5-layer Multi-Layer Perceptron (MLP) with 64 neurons per layer, ReLU activations in hidden layers, and no output activation.
*   **Photon Map:** A GPU-based kd-tree constructed from generated photons to enable fast spatial queries.

**Numbered Steps:**

1.  **Photon Tracing (Training Data Generation):**
    Generate training data by tracing photons from random light sources into the volume using delta tracking. Only photons past their first interaction are stored. Each photon is assigned a phase coefficient $g$ randomly selected from a discrete set $G$.
    *   *Note:* The set $G = \{-0.75, 0.0, 0.75\}$ is used as a compromise between speed and quality [S1].
    *   *Algorithm:* See Pseudocode below.

2.  **Radiance Estimation (Ground Truth Creation):**
    For each training sample $(x, g, \vec{\omega})$, compute the ground truth indirect radiance $L_i(x, \vec{\omega})$ using a phase-specific k-nearest-neighbor (KNN) query on the photon map.
    *   Query $K=1024$ neighbors with a maximum radius $r$.
    *   Compute radiance using the KNN adaptive radius estimator:
        $$ L_i(x, \vec{\omega}) \approx \sum_{n=1}^K p_g(x, \vec{\omega}, \vec{\omega}_n) \frac{\Phi_n}{4\pi r^3} $$
        where $\Phi_n$ is the photon intensity, $\vec{\omega}_n$ is the photon direction, and $p_g$ is the Henyey-Greenstein phase function determined by $g$ [S1].

3.  **Target Encoding:**
    Normalize the ground truth radiance values for network training by applying a logarithmic transformation. This maps values to $[0,1]$ and handles high dynamic range.
    *   Let $\psi$ be the maximum desired floating-point precision in digits beyond zero (typically 4–6) [S1].
    *   Compute encoded target $L_i'$:
        $$ L_i'(x, \vec{\omega}) = \begin{cases} -\frac{\log_{10}(L_i(x, \vec{\omega}))}{\psi} & \text{if } L_i(x, \vec{\omega}) > 10^{-\psi} \\ 1 & \text{otherwise} \end{cases} $$
    *   Values below the threshold are clamped to 1 (which maps to 0 in the inverse) [S1].

4.  **Network Training:**
    Train the 5-layer MLP to predict $L_i'$ given the encoded inputs $(x, g, \vec{\omega})$.
    *   Batches of size $2^{16}$ are generated per step, containing uniformly sampled grid coordinates, random directions, and random phase coefficients [S1].
    *   A single loss term is used (specific loss function details not provided in sources) [S1].

5.  **Decoding (Inference):**
    To render, decode the network output $L_i'$ back to physical radiance $L_i$:
    $$ L_i(x, \vec{\omega}) = 10^{-L_i'(x, \vec{\omega})} \cdot \Psi $$
    where $\Psi$ is the precision parameter (implicitly $10^\psi$ or similar scaling factor depending on implementation, though the source formula uses $\Psi$ directly) [S1].

**Pseudocode: Multi-Phase Photon Tracing**
```python
# Algorithm 1: Multi-phase photon tracing in heterogeneous media [S1]
# G is the set of discrete phase coefficients, e.g., {-0.75, 0.0, 0.75}

def generate_photon_map(max_n_photons, max_bounces, G):
    photonmap = []
    n_photons = 0
    
    while n_photons < max_n_photons:
        bounces = 0
        throughput = 1.0
        photon = generate_photon_from_random_light_source()
        photon.g = random_choice(G)
        
        while bounces < max_bounces:
            # Compute sample distance via delta tracking
            interaction_found = delta_tracking(photon.position, photon.direction, photon.g)
            
            if not interaction_found:
                break # Photon left the volume
                
            photon.position = interaction_location
            photon.direction = apply_phase_function(photon.g, photon.direction)
            
            # Sample volume properties at interaction point
            sample = volume_sample(photon.position)
            albedo = transfer_function(sample)
            
            # Update throughput
            throughput = throughput * albedo.alpha * albedo.rgb
            photon.intensity = light_intensity * throughput
            
            # Store photon if it's not the first bounce (indirect light only)
            if bounces >= 1:
                photonmap.append(photon)
                n_photons += 1
                
            # Russian roulette termination
            if russian_roulette_termination(throughput):
                break
                
            bounces += 1
            
    return photonmap
```

### 2. 3D Gaussian Splatting (Explicit Differentiable Rendering)
This method represents the scene explicitly as a set of 3D Gaussians, rendered via differentiable rasterization.

**Inputs and Outputs:**
*   **Input:** A set of images with known camera poses (from Structure from Motion, e.g., COLMAP).
*   **Output:** A set of 3D Gaussians $\mathcal{G}$, each defined by learnable parameters.

**Data Structures:**
*   **Gaussian Parameters:** Each Gaussian stores approximately 59 learnable numbers [S2, unofficial]:
    *   **Position:** Center in 3D space ($\mu \in \mathbb{R}^3$).
    *   **Covariance:** Defined by scale ($S$) and rotation ($R$). The covariance matrix is $\Sigma = R S S^T R^T$ to ensure positive semi-definiteness [S2, unofficial].
    *   **Opacity:** Transparency ($\alpha$).
    *   **Color:** Stored as spherical harmonic coefficients ($c$) for view-dependent color [S2, unofficial].

**Numbered Steps:**

1.  **Initialization:**
    Start with photos and camera poses from Structure from Motion (SfM). Generate a sparse cloud of 3D points; each point becomes the initial position of one Gaussian [S2, unofficial].

2.  **Projection:**
    For a given camera pose, project every 3D Gaussian onto the camera image. A projected 3D Gaussian results in a 2D Gaussian (soft ellipse) on the screen. The 2D covariance is computed using the camera transformation and a local linear approximation of the projection [S2, unofficial].

3.  **Tiling:**
    Divide the screen into small tiles of 16x16 pixels. Assign each Gaussian to the tiles it overlaps [S2, unofficial].

4.  **Sorting:**
    Within each tile, sort the Gaussians by depth from front to back using a fast GPU sort [S2, unofficial].

5.  **Rasterization/Blending:**
    For each pixel, blend the colors of the sorted Gaussians front-to-back using alpha compositing:
    $$ C = \sum_{i \in N} c_i \alpha_i \prod_{j=1}^{i-1} (1 - \alpha_j) $$
    where $N$ is the set of Gaussians covering the pixel, $c_i$ is the color, and $\alpha_i$ is the opacity [S2, unofficial].

6.  **Training Loss:**
    Compare the rendered image with the real training photo using an L1 loss combined with a Structural Similarity (SSIM) term [S2, unofficial].

7.  **Optimization:**
    Because the rasterizer is differentiable, backpropagate the error to update each Gaussian's position, shape (scale/rotation), opacity, and color directly via gradient descent [S2, unofficial].

8.  **Adaptive Density Control:**
    *   **Cloning:** In regions that are under-reconstructed with missing details, clone small Gaussians [S2, unofficial].
    *   **Splitting:** Where a single Gaussian is too large and covers too much detail, split it into two smaller ones [S2, unofficial].
    *   **Pruning:** Prune away Gaussians that become almost transparent [S2, unofficial].

**Pitfalls:**
*   Floating artifacts and needle-like Gaussians in regions seen by few cameras [S2, unofficial].
*   Aliasing when zooming in or out [S2, unofficial].
*   Inability to directly extract a clean surface or mesh [S2, unofficial].

## Subtopics

### [Scene NeRF](12484-scene-nerf.md)
Scene NeRF is a method for isolating and rendering the static background of a scene by training a Neural Radiance Field (NeRF) exclusively on pixels identified as background via human segmentation masks. It differs from standard NeRF by explicitly excluding dynamic foreground elements (e.g., humans) from the training data and employing an emptiness regularizer to prevent artifacts in empty space. [Scene NeRF](12484-scene-nerf.md)

### [NeRF-OSR](14477-nerf-osr.md)
NeRF-OSR is a neural radiance field approach for outdoor scene relighting that learns a neural representation of scene geometry, diffuse albedo, and illumination-dependent shadows from a set of images capturing the same site from different viewpoints and at different times, enabling simultaneous editing of both the scene’s lighting and viewpoint. Unlike standard NeRF which learns a Lambertian model under fixed lighting, NeRF-OSR decomposes the scene into spatial occupancy, illumination, shadowing, and diffuse albedo reflectance, trained in a self-supervised manner from outdoor data captured from various viewpoints and at different illuminations. It sets itself apart from siblings like [Scene NeRF](12484-scene-nerf.md) by providing explicit intrinsic decomposition (albedo, geometry, lighting) rather than just view-dependent appearance, allowing for physical relighting and albedo editing. [NeRF-OSR](14477-nerf-osr.md)

### [Explicit Volumetric Rendering with Multiple View Aggregation](15335-explicit-volumetric-rendering-with-multiple-view-aggregation.md)
This method models scene geometry and appearance as an explicit RGBα volume to amortize rendering across multiple views, solving the computational inefficiency of NeRF-like methods where per-ray sampling is independent and not reusable across different viewing angles. Unlike its siblings [Scene NeRF](12484-scene-nerf.md), [NeRF-OSR](14477-nerf-osr.md), and [Dynamic Neural Radiance Fields](15318-dynamic-neural-radiance-fields.md), which typically rely on implicit field evaluations or sparse ray sampling, this approach generates a dense volumetric representation that enables real-time rendering and the use of structural losses like SSIM during training. [Explicit Volumetric Rendering with Multiple View Aggregation](15335-explicit-volumetric-rendering-with-multiple-view-aggregation.md)

### [Dynamic Neural Radiance Fields](16398-dynamic-neural-radiance-fields.md)
Dynamic Neural Radiance Fields (Dynamic NeRF) is a method for modeling the appearance and dynamics of a human face using an implicit volumetric representation. It combines a neural scene representation network with a low-dimensional morphable model to handle facial dynamics, allowing novel viewpoint and expression synthesis from monocular input. Unlike static NeRF methods, this approach handles dynamically changing surfaces by conditioning the neural network on morphable model expression parameters and a per-frame latent code. It differs from other volumetric approaches by requiring only a single view from a fixed camera (e.g., webcam) instead of an expensive calibrated multi-view rig. [Dynamic Neural Radiance Fields](16398-dynamic-neural-radiance-fields.md)

### SLAIM
SLAIM is a SLAM method that introduces a coarse-to-fine tracking pipeline and improves photometric bundle adjustment for NeRF-based mapping [S3]. It maintains NeRF’s original volume density formulation while introducing a KL regularization over the ray termination distribution [S3]. It addresses the challenge of high-frequency renderings in NeRF hindering image alignment [S3].

### SNI-SLAM
SNI-SLAM is a dense NeRF-based RGB-D SLAM system for accurate real-time 3D semantic mapping [S3]. It introduces a hierarchical semantic encoding and cross-attention mechanism to enable mutual reinforcement between appearance, geometry, and semantics modalities [S3]. It proposes a novel one-way decoder design to enhance inter-modal information flow without reverse interference [S3].

### KN-SLAM
KN-SLAM is a NeRF-based SLAM method that integrates local feature correspondences for coarse pose initialization and joint optimization [S3]. It uses global image features and local matches for explicit loop detection [S3]. It performs pose graph optimization and global refinement of the neural map to ensure consistency [S3].

## Operating characteristics

**Photon Field Networks:**
*   **Time Complexity:** Training involves generating photon maps (costly, but done offline/pre-computation) and training a small 5-layer MLP. Inference is constant-time neural network evaluation, scaling slower than baseline global illumination methods [S1].
*   **Memory Complexity:** Depends on the hashgrid size ($2^{19}$ entries) and the MLP parameters. The photon map is stored on the GPU [S1].
*   **Strengths:** Efficiently approximates indirect global illumination in heterogeneous media without expensive path tracing during rendering [S1].
*   **Limitations:** Requires pre-computation of photon maps; limited to volumetric/global illumination aspects (does not handle direct lighting or surface reflection implicitly in the same field) [S1].

**3D Gaussian Splatting:**
*   **Time Complexity:** Rendering is extremely fast (>100 FPS) as it avoids neural network evaluation per ray, relying instead on rasterization [S2, unofficial]. Training time is significantly reduced compared to NeRF (tens of minutes vs. many hours) [S2, unofficial].
*   **Memory Complexity:** High. Memory usage increases from a few megabytes (NeRF) to hundreds of megabytes (Gaussian Splatting) due to storing millions of Gaussian parameters [S2, unofficial].
*   **Strengths:** Real-time rendering, fast training, high visual fidelity [S2, unofficial].
*   **Limitations:** High memory footprint, floating artifacts in sparse regions, aliasing at zoom extremes, no direct mesh extraction [S2, unofficial].

## Background

**Photon Field Networks:**
Introduced in a paper published in IEEE Transactions on Visualization and Computer Graphics (2023) [S1]. The method replaces expensive sampling steps for global illumination in scientific volume rendering with a constant-time neural network inference [S1].

**3D Gaussian Splatting:**
Introduced by Kerbl and colleagues at SIGGRAPH 2023 [S2, unofficial]. It was developed to address the computational inefficiency of NeRF-like methods, which require per-ray neural network evaluations. By representing the scene explicitly as 3D Gaussians, it enables real-time rendering. It is used in virtual reality games, film, robotics, mapping, digital humans, ecommerce, and cultural heritage [S2, unofficial].
