# First-order Spherical Harmonics Distillation

Also called: Mobile-GS SH Distillation, SH Knowledge Distillation, SH Order Reduction via Distillation, SH degree reduction, Spherical Harmonics degree reduction

## Overview
First-order Spherical Harmonics Distillation reduces the spherical harmonics (SH) degree of Gaussian elements from the standard third-order to first-order to decrease parameter count and computation cost, thereby enabling real-time rendering on mobile devices [S1][S2, unofficial]. It differs from direct degree reduction by using a distillation strategy where a student model with first-order SH approximates the directional radiance of a pretrained third-order teacher model, preserving rendering quality better than naive projection [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A pretrained teacher 3D Gaussian Splatting model using third-order SH (16 coefficients per color channel, $3 \times 16$ total) and a set of training views.
*   **Output:** A student 3D Gaussian Splatting model using first-order SH (4 coefficients per color channel, $3 \times 4$ total) with optimized parameters.

**Data Structures:**
The Gaussian attributes are stored per element $i$. The key change is the SH coefficient vector $\mathbf{c}_i$:
*   **Teacher:** $\mathbf{c}_i^{tea} \in \mathbb{R}^{48}$ (3 channels $\times$ 16 coefficients).
*   **Student:** $\mathbf{c}_i \in \mathbb{R}^{12}$ (3 channels $\times$ 4 coefficients).
Other attributes (position $\boldsymbol{\mu}$, covariance $\boldsymbol{\Sigma}$, opacity $\alpha$, scale, rotation) remain unchanged or are jointly optimized during distillation.

**Numbered Steps:**
1.  **Initialize Student:** Initialize a student Gaussian field with the same geometry (positions, covariances, opacities) as the teacher, but with first-order SH coefficients initialized to zero or randomly.
2.  **Render Teacher:** For each training view, render the pixel colors $\mathbf{C}_p^{tea}$ and depth maps $\mathbf{D}^{tea}$ using the teacher model.
3.  **Render Student:** For the same views, render the pixel colors $\mathbf{C}_p$ and depth maps $\hat{\mathbf{D}}_p$ using the student model.
4.  **Compute Distillation Loss:** Calculate the color distillation loss $\mathcal{L}_{\text{distill}}$ between teacher and student pixel colors.
5.  **Compute Depth Distillation Loss:** Calculate the scale-invariant depth distillation loss $\mathcal{L}_{\text{depth}}$ between teacher and student depth maps.
6.  **Optimize:** Update student parameters (primarily SH coefficients, potentially geometry) to minimize the combined loss.

**Formulas:**
The total loss is a combination of color and depth distillation losses.

Color Distillation Loss [S2, unofficial]:
$$ \mathcal{L}_{\text{distill}} = \frac{1}{|P|} \sum_{p \in P} \|\mathbf{C}_p^{tea} - \mathbf{C}_p\|_2^2 $$
where $P$ is the set of pixels, $\mathbf{C}_p^{tea}$ is the rendered pixel color from the teacher, and $\mathbf{C}_p$ is the rendered pixel color from the student.

Scale-Invariant Depth Distillation Loss [S2, unofficial]:
$$ \mathcal{L}_{\text{depth}}(\mathbf{D}, \mathbf{D}^{tea}) = \frac{1}{|P|} \sum_{p \in P} \left( \log(\hat{\mathbf{D}}_p) - \log(\hat{\mathbf{D}}_p^{tea}) \right)^2 - \frac{1}{|P|^2} \left( \sum_{p \in P} \left( \log(\hat{\mathbf{D}}_p) - \log(\hat{\mathbf{D}}_p^{tea}) \right) \right)^2 $$
where $\hat{\mathbf{D}}_p^{tea} = \mathbf{D}^{tea} + \epsilon$ and $\epsilon = 10^{-8}$ for training stability. The second term is a mean subtraction to enforce scale invariance.

**Parameters:**
*   Target SH degree: 1 (first-order) [S1][S2, unofficial].
*   Epsilon for depth stability: $\epsilon = 10^{-8}$ [S2, unofficial].

**Pseudocode:**
```python
def first_order_sh_distillation(teacher_model, student_model, training_views, lr=1e-3, epsilon=1e-8):
    """
    Distill third-order SH teacher to first-order SH student.
    """
    optimizer = torch.optim.Adam(student_model.parameters(), lr=lr)
    
    for view in training_views:
        # 1. Render Teacher
        with torch.no_grad():
            teacher_output = teacher_model.render(view)
            C_tea = teacher_output['color']  # Shape: (H, W, 3)
            D_tea = teacher_output['depth']  # Shape: (H, W, 1)
            
        # 2. Render Student
        student_output = student_model.render(view)
        C_stu = student_output['color']
        D_stu = student_output['depth']
        
        # 3. Compute Color Distillation Loss
        loss_color = torch.mean((C_tea - C_stu) ** 2)
        
        # 4. Compute Depth Distillation Loss
        # Add epsilon for stability
        D_tea_safe = D_tea + epsilon
        
        # Log difference
        log_diff = torch.log(D_stu) - torch.log(D_tea_safe)
        
        # Scale-invariant term: mean of log differences squared minus square of mean
        mean_log_diff = torch.mean(log_diff)
        loss_depth = torch.mean(log_diff ** 2) - mean_log_diff ** 2
        
        # 5. Combine Losses
        # Note: Weights are not specified in sources; assume equal or tuned
        loss = loss_color + loss_depth
        
        # 6. Backpropagate
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        
    return student_model
```

**Edge Cases and Pitfalls:**
*   **Depth Reliability:** The teacher's depth may not be perfectly reliable, hence the use of scale-invariant loss rather than strict L1/L2 [S2, unofficial].
*   **Precision:** Using $\log$ requires positive depth values; adding $\epsilon$ prevents numerical instability [S2, unofficial].
*   **Degenerate Input:** If the teacher model is poorly trained, distillation may propagate errors.

## Operating characteristics
*   **Time Complexity:** Rendering complexity is reduced due to fewer SH coefficients. Third-order SH requires 16 coefficients per channel; first-order requires 4. This results in a 4x reduction in SH computation per Gaussian.
*   **Memory Complexity:** Parameter count is reduced by 61% when going from degree 3 to 1 [S1].
*   **Measured Performance:**
    *   Degree 3→2: -36% parameters, -35% computation, -0.17 dB PSNR [S1].
    *   Degree 2→1: -25% parameters, -17% computation, -0.31 dB PSNR [S1].
    *   Degree 3→1: -61% parameters, -52% computation, -0.48 dB PSNR [S1].
*   **Strengths:** Significant reduction in storage and computation, enabling mobile deployment [S2, unofficial].
*   **Limitations:** Quality drop compared to third-order SH, though less than naive reduction due to distillation [S2, unofficial].
*   **When to use:** When deploying 3DGS on resource-constrained devices (mobile, embedded) [S2, unofficial].
*   **When not to use:** When maximum rendering quality is required and resources are abundant.

## Background
*   **Origin:** Introduced in Mobile-GS (2026) as part of a suite of compression techniques for mobile 3DGS [S2, unofficial][S1].
*   **History:** Builds on the observation that third-order SH is computationally expensive and storage-heavy [S2, unofficial]. Previous work like LightGaussian used second-order distillation [S2, unofficial].
*   **Usage:** Used in Mobile-GS for real-time Gaussian Splatting on mobile devices [S2, unofficial].
