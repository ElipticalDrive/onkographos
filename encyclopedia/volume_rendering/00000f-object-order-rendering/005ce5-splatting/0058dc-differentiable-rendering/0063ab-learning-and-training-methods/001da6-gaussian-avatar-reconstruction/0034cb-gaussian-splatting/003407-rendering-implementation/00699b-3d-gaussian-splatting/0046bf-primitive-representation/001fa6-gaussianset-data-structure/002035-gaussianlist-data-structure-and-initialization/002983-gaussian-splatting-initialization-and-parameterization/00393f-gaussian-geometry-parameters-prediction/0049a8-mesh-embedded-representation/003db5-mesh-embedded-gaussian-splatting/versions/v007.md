# Mesh-Embedded Gaussian Splatting

Also called: Gaussian Mesh Splatting, Gaussian-Mesh association

## Overview
Mesh-Embedded Gaussian Splatting is a hybrid 3D representation that parameterizes 3D Gaussians relative to an explicit canonical triangle mesh $\mathcal{M}$ [S1][S2, unofficial]. It solves the problem of coherent motion transfer and structural control in 3D Gaussian Splatting (3DGS) by disentangling low-frequency motion (handled by the mesh) from high-frequency appearance and geometry (handled by the Gaussians) [S2, unofficial]. Unlike sibling methods that rely on implicit MLP-based linear blend skinning (LBS) fields for deformation, this method controls Gaussian rotation and translation directly via mesh attributes, enabling compatibility with skeletal animation, blend shapes, and mesh editing [S2, unofficial]. It sets itself apart from [Mesh-Embedded Gaussian Initialization and Deformation](9559-mesh-embedded-gaussian-initialization-and-deformation.md) by utilizing a reconstructed explicit mesh for initialization and employing specific face-split and normal-guidance strategies for large deformations [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A canonical triangle mesh $\mathcal{M}$ with vertices $V$, per-vertex normals $n$, and faces $F$; monocular video frames of the subject in various poses; initial Gaussian parameters.
*   **Output:** A set of 3D Gaussians defined by embeddings on the mesh, capable of real-time rendering under mesh deformation.

**Data Structures:**
Each Gaussian $i$ is defined by an embedding tuple $E_i = \{k, u, v, d\}$ and pose-invariant appearance parameters:
*   $k \in F$: Index of the triangle in the canonical mesh.
*   $(u, v)$: Barycentric coordinates within triangle $k$, constrained by $u \ge 0, v \ge 0, u+v \le 1$.
*   $d$: Normal displacement scalar along the interpolated surface normal.
*   Pose-invariant parameters: Canonical rotation $\bar{q}$, canonical scale $\bar{s}$, opacity $\alpha$, and color coefficients $c$ (SH coefficients).

**Canonical State Computation:**
The canonical mean $\mu_{cano}$ and normal $n_{cano}$ are computed via Phong interpolation on the canonical mesh [S2, Parent, unofficial]:
$$
\mu_{cano} = \mathcal{V}(k, u, v) = u V_1 + v V_2 + (1 - u - v) V_3
$$
$$
n_{cano} = \mathcal{N}(k, u, v) = u n_1 + v n_2 + (1 - u - v) n_3
$$
where $V_j$ and $n_j$ are the vertices and per-vertex normals of triangle $k$ [Parent].

**Posed State Computation:**
When the mesh is deformed by a function $\text{Deform}(\cdot)$ (e.g., skeletal animation), the posed state is derived as follows [Parent, S2]:

1.  **Position:** The displaced canonical position is deformed:
    $$
    \mu_{pose} = \text{Deform}(\mu_{cano} + d \cdot n_{cano})
    $$
2.  **Rotation:** The posed rotation $q_{pose}$ combines the canonical rotation $\bar{q}$ with a pose-dependent delta rotation $\delta q$ interpolated from per-vertex quaternions $q_1, q_2, q_3$:
    $$
    q_{pose} = \delta q * \bar{q}, \quad \delta q = u q_1 + v q_2 + (1 - u - v) q_3
    $$
    where $*$ denotes quaternion multiplication [Parent].
3.  **Scale:** The posed scale $s_{pose}$ scales the canonical scale $\bar{s}$ by the ratio of the triangle's area in the posed state ($A_{pose}$) to the canonical state ($A_{cano}$):
    $$
    s_{pose} = \left( \frac{A_{pose}}{A_{cano}} \right) \bar{s}
    $$

**Optimization and Initialization:**
During training, Gaussian parameters and embedding parameters are updated simultaneously [S2, unofficial]. The method adapts the clone and split scheme of 3DGS to suit the mesh-embedded representation [S2, unofficial].

**Cross-Triangle Handling (Lifted Optimization):**
Barycentric coordinates are differentiable only within a single triangle. If optimization updates move an embedding point across a boundary ($u < 0$, $v < 0$, or $u+v > 1$), the embedding must be re-expressed in the neighboring triangle to maintain differentiability [Parent, S2]. Failure to handle this causes Gaussians to stick to boundaries and pile up [Parent]. The method employs "lifted optimization" where embedding points "walk" on the triangle mesh, re-expressing the barycentric update in the neighboring triangle as if the Gaussian is walking on the mesh [S2, unofficial].

**Pseudocode:**
```python
def compute_posed_gaussian(gaussian, mesh, pose_transform):
    """
    Computes the posed position, rotation, and scale for a single Gaussian.
    
    Args:
        gaussian: Dict containing embedding {k, u, v, d} and canonical params {q_bar, s_bar}.
        mesh: Object providing vertices V, normals n, and quaternions q for face k.
        pose_transform: Function that deforms a point and returns the deformed triangle geometry.
        
    Returns:
        posed_mu, posed_q, posed_s
    """
    # 1. Retrieve canonical mesh attributes for triangle k
    k = gaussian['embedding']['k']
    u = gaussian['embedding']['u']
    v = gaussian['embedding']['v']
    d = gaussian['embedding']['d']
    
    V1, V2, V3 = mesh.get_vertices(k)
    n1, n2, n3 = mesh.get_normals(k)
    q1, q2, q3 = mesh.get_quaternions(k)
    
    # 2. Compute canonical position and normal (Phong interpolation)
    mu_cano = u * V1 + v * V2 + (1 - u - v) * V3
    n_cano = u * n1 + v * n2 + (1 - u - v) * n3
    
    # 3. Compute posed position
    # Apply displacement along normal, then deform
    displaced_pos = mu_cano + d * n_cano
    posed_mu = pose_transform(deform_point=displaced_pos, face_index=k)
    
    # 4. Compute posed rotation
    # Interpolate per-vertex quaternions
    delta_q = u * q1 + v * q2 + (1 - u - v) * q3
    # Combine with canonical rotation
    posed_q = quaternion_multiply(delta_q, gaussian['canonical_q'])
    
    # 5. Compute posed scale
    # Calculate area of triangle in posed state
    # Note: pose_transform should return the deformed vertices to compute area
    V1_p, V2_p, V3_p = pose_transform(deform_vertices=[V1, V2, V3], face_index=k)
    A_pose = triangle_area(V1_p, V2_p, V3_p)
    A_cano = triangle_area(V1, V2, V3)
    
    # Scale canonical scale by area ratio
    posed_s = (A_pose / A_cano) * gaussian['canonical_s']
    
    return posed_mu, posed_q, posed_s

def handle_cross_triangle_update(embedding, gradient, mesh):
    """
    Handles the case where a gradient update moves the embedding outside its current triangle.
    Re-expresses the embedding in the neighboring triangle.
    """
    k = embedding['k']
    u = embedding['u']
    v = embedding['v']
    
    # Check boundaries
    if u < 0 or v < 0 or (u + v) > 1:
        # Find neighboring triangle across the violated edge
        neighbor_k = mesh.get_neighbor(k, u, v)
        
        # Convert barycentric coordinates (u, v) in triangle k to 
        # barycentric coordinates (u', v') in neighbor_k.
        # This requires the specific adjacency topology of the mesh.
        u_new, v_new = convert_barycentric_to_neighbor(u, v, k, neighbor_k, mesh)
        
        # Update embedding
        embedding['k'] = neighbor_k
        embedding['u'] = u_new
        embedding['v'] = v_new
        
        # Note: The gradient must also be transformed to the new coordinate system
        # to ensure correct backpropagation.
        return True
    return False
```

## Subtopics

### [GaussianMesh](11812-gaussianmesh.md)
Defines 3D Gaussians over an explicit triangle mesh for large-scale, interactive deformations driven by mesh editing. It uses joint refinement where GS rendering guides adaptive splitting and mesh constraints regularize Gaussian shapes. It sets itself apart by utilizing a reconstructed explicit mesh from calibrated images and employing face-split/normal-guidance strategies without relying on implicit MLP-based skinning.

## Operating characteristics
*   **Performance:** Achieves over 300 FPS on an NVIDIA RTX 3090 GPU and 30 FPS on an iPhone 13 [S2, unofficial].
*   **Strengths:** Explicit motion control allows compatibility with various animation techniques (skeletal animation, blend shapes, mesh editing) [S2, unofficial]. The mesh handles low-frequency motion efficiently, while Gaussians capture high-frequency details [S2, unofficial].
*   **Limitations:** Relies on accurate semantic labels or mesh proxies for initialization [S1]. Cross-triangle updates require careful handling to maintain differentiability and prevent Gaussians from sticking to boundaries [Parent].
*   **Usage:** Ported to Unity for real-time rendering [S2, unofficial].

## Background
The method was introduced in **SplattingAvatar** by Zhijing Shao et al. (2024) [S2, unofficial]. It builds on the principles of mesh-embedded representations [Parent] and adapts 3D Gaussian Splatting [23] to explicit mesh geometry. The approach is inspired by Phong shading [38] and lifted optimization [40, 41] to handle the differentiability constraints of barycentric coordinates. It addresses the limitations of MLP-based linear blend skinning fields by providing explicit mesh-driven control over Gaussian parameters [S2, unofficial].
