# Compact 3D Gaussian Representation (C3DGS)

## Overview
Compact 3D Gaussian Representation (C3DGS) is a method for optimizing the storage and rendering efficiency of 3D Gaussian Splatting (3DGS) by reducing the number of Gaussian primitives and compressing their attributes [S1]. It addresses the high memory and storage requirements of standard 3DGS, which often exceed 1GB for large scenes, by exploiting spatial redundancy in color and geometry [S1]. Unlike 3DGS, which stores unique per-Gaussian attributes, C3DGS uses a grid-based neural field for view-dependent colors and a codebook for geometric parameters, achieving over 25x storage reduction and faster rendering speeds [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of 3D Gaussians $\{G_i\}$ generated from standard 3DGS training (positions, scales, rotations, opacities, and spherical harmonic coefficients for color).
*   **Output:** A compact representation consisting of:
    1.  A subset of active Gaussians identified by a learnable mask.
    2.  A hash-based grid neural field for color attributes.
    3.  A codebook for geometric attributes (scale and rotation).
    4.  Indices mapping each Gaussian to its respective grid entry and codebook entry.

**Data Structures:**
1.  **Gaussian Mask:** A learnable scalar parameter $\alpha_i \in [0, 1]$ for each Gaussian $i$. If $\alpha_i$ drops below a threshold (e.g., 0.5 or via hard pruning during training), the Gaussian is deactivated [S1].
2.  **Hash Grid:** Based on Instant NGP [S1]. Stores feature vectors for color prediction. Let $H$ be the hash grid.
3.  **Codebook:** A fixed-size table $C \in \mathbb{R}^{K \times D}$, where $K$ is the number of entries and $D$ is the dimensionality of the geometric vector (scale and rotation combined) [S1].
4.  **Indices:**
    *   $idx^{color}_i$: Index into the hash grid features for Gaussian $i$.
    *   $idx^{geo}_i$: Index into the codebook $C$ for Gaussian $i$.

**Steps:**

1.  **Volume-Based Masking (Pruning):**
    During training, introduce a learnable mask $\alpha_i$ for each Gaussian. The loss function includes a regularization term that encourages $\alpha_i$ to approach 0 for non-essential Gaussians. Gaussians with $\alpha_i < \tau$ (threshold) are removed from the rendering pipeline and storage [S1]. This reduces the total count $N$ of Gaussians.

2.  **Color Compression via Hash Grid:**
    Instead of storing spherical harmonic coefficients for each Gaussian, query the hash grid $H$ at the Gaussian's position $p_i$ to retrieve a feature vector $f_i$. A small MLP (or linear layer) maps $f_i$ and the view direction $v$ to the final color $c_i$ [S1].
    $$ c_i = \text{MLP}(H(p_i), v) $$
    The hash grid is shared across all Gaussians, exploiting spatial redundancy in color [S1].

3.  **Geometry Compression via Codebook:**
    Geometric attributes (scale $s_i$ and rotation $q_i$) are quantized. Instead of storing $s_i$ and $q_i$ directly, each Gaussian is assigned an index $idx^{geo}_i$ pointing to an entry in the codebook $C$. The actual geometry is retrieved as:
    $$ \text{Geo}_i = C[idx^{geo}_i] $$
    The codebook is learned during training to capture common geometric patterns [S1].

4.  **Training Optimization:**
    The total loss is the standard 3DGS photometric loss plus a mask regularization term. The hash grid and codebook are updated via backpropagation. The indices $idx^{color}_i$ and $idx^{geo}_i$ are treated as discrete variables; in practice, they may be optimized via straight-through estimator or by fixing them after an initial clustering phase [S1, G].

**Pseudocode:**

```python
# Initialization
# N: number of initial Gaussians
# K: codebook size for geometry
# H: Hash grid instance (Instant NGP style)
# C: Codebook tensor [K, D_geo]
# alpha: Learnable mask parameters [N] initialized to 1.0
# idx_geo: Integer indices [N] initialized to random integers in [0, K)

def forward_pass(Gaussians, Camera):
    # 1. Apply Mask
    active_mask = alpha > 0.5  # Thresholding for rendering
    active_indices = where(active_mask)
    
    # 2. Retrieve Compressed Attributes
    # Color: Query hash grid
    # pos: Positions of active Gaussians
    # view_dirs: View directions for active Gaussians
    features = H.query(pos) 
    colors = MLP(features, view_dirs)
    
    # Geometry: Lookup codebook
    scales_rotations = C[idx_geo[active_indices]]
    
    # 3. Render using standard 3DGS splatting
    # with the retrieved colors, scales, rotations, and opacities
    image = splat_render(Gaussians[active_indices], colors, scales_rotations, Camera)
    return image

def update_step(image, target_image, Gaussians):
    # Standard 3DGS loss
    loss = photometric_loss(image, target_image)
    
    # Mask regularization: encourage sparsity
    mask_loss = sum(alpha) 
    total_loss = loss + lambda_mask * mask_loss
    
    # Backpropagate to update:
    # - Hash grid H
    # - Codebook C
    # - Learnable masks alpha
    # - Indices idx_geo (via straight-through or similar discrete optimization)
    # - Standard 3DGS parameters (position, opacity)
    gradient_descent(total_loss)
```

**Parameters:**
*   **Hash Grid Type:** Hash-based grid representation (Instant NGP) [S1].
*   **Codebook Size:** Not given in the sources.
*   **Mask Threshold:** Not given in the sources (implied to be a hyperparameter, e.g., 0.5) [S1].

**Edge Cases and Pitfalls:**
*   **Precision:** The hash grid and codebook introduce approximation errors. Care must be taken to ensure the grid resolution and codebook size are sufficient to maintain visual fidelity [S1].
*   **Degenerate Input:** If too many Gaussians are pruned, scene detail may be lost. The mask regularization parameter $\lambda_{mask}$ must be tuned to balance compression and quality [S1].

## Subtopics

### [Optimized Minimal 3D Gaussian Splatting (OMG)](13978-optimized-minimal-3d-gaussian-splatting-omg.md)
OMG extends C3DGS by retaining per-Gaussian parameterization for geometry to handle sparsity, while using a small neural field and Sub-Vector Quantization (SVQ) for appearance features. It addresses C3DGS's weakness in sparse settings where neighboring Gaussians are far apart, achieving >300x compression.

## Operating characteristics
*   **Time Complexity:** Rendering speed is linearly proportional to the number of active Gaussians. Since C3DGS reduces the number of Gaussians, rendering speed increases [S1].
*   **Memory Complexity:** Storage is reduced by over 25x compared to 3DGS [S1]. The hash grid and codebook have fixed, small memory footprints compared to per-Gaussian attribute storage [S1].
*   **Measured Performance:**
    *   On the Deep Blending dataset: Over 28x storage efficiency enhancement, nearly 40% increase in rendering speed, and outperforms 3DGS in PSNR [S1].
    *   General datasets: Consistently shows about 15x reduced storage and enhanced rendering speed [S1].
    *   With post-processing (quantization and entropy coding): Achieves over 25x compression [S1].
*   **Strengths:** Significant storage reduction, faster rendering, high-quality reconstruction.
*   **Limitations:** Relies on spatial redundancy; may struggle in highly sparse regions where neighbors do not share similar attributes (addressed by OMG) [S1].

## Background
C3DGS was proposed to address the critical memory and storage issues in 3D Gaussian Splatting, which often require >1GB for large real-world scenes [S1]. It builds on the observation that standard 3DGS densification produces redundant Gaussians and that spatial redundancy is underutilized in per-Gaussian attribute storage [S1]. The method uses Instant NGP for the hash grid, leveraging its compactness and speed [S1].
