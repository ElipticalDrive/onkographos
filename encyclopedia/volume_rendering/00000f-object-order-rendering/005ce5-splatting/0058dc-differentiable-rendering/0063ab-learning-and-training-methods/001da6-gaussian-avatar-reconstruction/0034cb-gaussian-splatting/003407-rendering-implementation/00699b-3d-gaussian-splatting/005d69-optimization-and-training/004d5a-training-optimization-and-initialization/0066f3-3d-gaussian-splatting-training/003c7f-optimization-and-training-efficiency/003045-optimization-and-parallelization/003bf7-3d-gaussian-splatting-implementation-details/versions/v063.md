# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, GSGEN Implementation Details, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific algorithmic steps, hyperparameters, and data structures required to implement the training and rendering pipeline of 3D Gaussian Splatting (3DGS). It addresses the core problem of optimizing a set of anisotropic 3D Gaussians to reconstruct a scene from multi-view images by defining the exact densification schedule, pruning criteria, and loss functions. It sets itself apart from generic volume rendering by its explicit, discrete primitive management (splitting/cloning/pruning) driven by view-space gradients and opacity, rather than continuous field optimization [S1][S9, unofficial].

## How it works

### Inputs and Outputs
**Inputs:**
*   A set of $N_{cam}$ calibrated images with known camera poses $C_i$ and intrinsics.
*   An initial sparse point cloud from Structure-from-Motion (SfM) with $N_{SfM}$ points [S4].
*   Optimization hyperparameters (learning rate, iteration budget, thresholds) [S1][S9, unofficial].

**Outputs:**
*   A final set of $N$ 3D Gaussians, each parameterized by mean $\mu$, covariance $\Sigma$ (or scale $s$ and rotation $q$), opacity $\alpha$, and spherical harmonic coefficients $c_{lm}$ [S1][S9, unofficial].

### Data Structures
The Gaussian representation is stored in a flat array or structure-of-arrays (SoA) layout for efficient GPU access [S2, S16]:
*   **Position:** $\mathbb{R}^3$ (float32 or float16) [S2].
*   **Rotation:** $\mathbb{R}^4$ (normalized quaternion) [S1].
*   **Scale:** $\mathbb{R}^3$ (log-space for optimization stability) [S1].
*   **Opacity:** $\mathbb{R}^1$ (sigmoid output) [S1].
*   **Features:** $\mathbb{R}^{3 \times (L+1)^2}$ for SH degree $L$ [S1]. Typically $L=1$ is used for real-time rendering [S3].
*   **Gradients:** Accumulated view-space position gradients $\nabla_{\mu}$ for densification decisions [S1].

### Training Loop and Optimization
The training process is a stochastic gradient descent loop [S9, unofficial].

1.  **Initialization:** Initialize Gaussians from the SfM point cloud. The scene extent $e_{scene}$ determines the initial scale. Default 3DGS uses camera positions, but this is biased if cameras are clustered [S4]. A corrected extent $e'_{scene}$ is recommended:
    $$ \bar{C} = \frac{1}{N_{cam}} \sum_{i=1}^{N_{cam}} C_i $$
    $$ e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2 $$
    where $p_i$ are SfM points [S4].

2.  **Iteration:**
    a.  **Random View Selection:** Randomly select one training image $I_{target}$ and its camera pose $T_{CW}$ [S9, unofficial].
    b.  **Rendering:** Project the current Gaussians to 2D. Sort by depth. Perform alpha blending to render the image $I_{render}$ [S1, S16].
    c.  **Loss Computation:** Compute the loss $\mathcal{L}$ between $I_{render}$ and $I_{target}$:
        $$ \mathcal{L} = (1 - \lambda) \mathcal{L}_1 + \lambda \mathcal{L}_{D-SSIM} $$
        where $\lambda \approx 0.2$ [S9, unofficial].
    d.  **Backpropagation:** Compute gradients $\frac{\partial \mathcal{L}}{\partial \theta}$ for all Gaussian parameters $\theta$ [S1].
    e.  **Optimizer Update:** Update parameters using Adam with learning rate $1 \times 10^{-3}$ [S3].

3.  **Densification and Pruning:** Periodically modify the Gaussian set [S1]:
    *   **Splitting:** Every 500 iterations, split Gaussians where the view-space position gradient magnitude exceeds $T_{pos} = 0.02$ [S1].
    *   **Cloning:** Clone Gaussians with high opacity and small scale to fill gaps [S1].
    *   **Pruning:** Every 200 iterations, remove Gaussians with opacity $\alpha < \alpha_{min} = 0.05$ or excessive radius [S1].
    *   **Compactness:** Perform compactness-based densification every 1000 iterations [S1].

4.  **Termination:** Stop after a fixed iteration budget, typically 30,000 iterations [S9, unofficial].

### Rendering Pipeline (Forward Pass)
1.  **Preprocessing:** Project 3D Gaussians to 2D ellipses. Compute depth $d$ and RGB color $c$ [S16].
2.  **Tiling:** Divide the screen into tiles (e.g., $16 \times 16$ pixels) [S16].
3.  **Sorting:** Sort Gaussians contributing to each tile by depth [S16].
4.  **Blending:** For each pixel, accumulate color using alpha blending:
    $$ C_j = \sum_{i=1}^{N} T_i \alpha_i c_i, \quad T_i = \prod_{k=1}^{i-1} (1 - \alpha_k) $$
    where $C_j$ is the pixel color, $\alpha_i$ is opacity, and $c_i$ is color [S16].

### Pseudocode

```python
def train_3dgs(images, poses, initial_points, num_iterations=30000):
    # Initialize Gaussians from SfM points
    gaussians = [Gaussian(p) for p in initial_points]
    
    # Optimizer setup
    optimizer = Adam(gaussians.parameters(), lr=1e-3)
    
    for i in range(num_iterations):
        # 1. Random View Selection
        idx = random.randint(0, len(images) - 1)
        target_image = images[idx]
        camera_pose = poses[idx]
        
        # 2. Rendering
        rendered_image = render(gaussians, camera_pose)
        
        # 3. Loss Computation
        loss = compute_loss(rendered_image, target_image)
        
        # 4. Backpropagation and Update
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        
        # 5. Densification and Pruning
        if i % 500 == 0:
            densify(gaussians, threshold=0.02)
        if i % 200 == 0:
            prune(gaussians, min_opacity=0.05)
            
    return gaussians

def densify(gaussians, threshold):
    for g in gaussians:
        if g.position_gradient > threshold:
            split_gaussian(g)
        elif g.opacity > 0.8 and g.scale < threshold:
            clone_gaussian(g)

def prune(gaussians, min_opacity):
    gaussians = [g for g in gaussians if g.opacity >= min_opacity]
```

### Edge Cases and Pitfalls
*   **Scene Extent Bias:** Using camera positions for scene extent estimation can lead to incorrect splitting/pruning if cameras are clustered (e.g., orbiting a small object) [S4]. Use SfM points instead [S4].
*   **Half-Precision Stability:** Training in FP16 requires automatic loss scaling to prevent gradient underflow [S2].
*   **Gradient Accumulation:** Gradients must be accumulated over iterations for densification decisions to be stable [S1].

### Corrected Scene-Extent
A method to calculate scene extent based on the SfM point cloud rather than camera positions to avoid bias from camera distribution (e.g., orbiting a small object in a large environment) [S4]. The corrected scene extent is calculated as $e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2$, where $\bar{C}$ is the averaged camera position and $p_i$ are SfM points [S4]. The default method, which uses camera positions, can lead to incorrect splitting/pruning if cameras are clustered [S4].

### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ to selectively enlarge covariances, creating pixel-wise variable blur kernels that match spatially varying scene blurriness [S5]. A compact MLP predicts $\delta s_j$ for each Gaussian, which is added to the base scale to transform the covariance [S5]. If $\delta s_j$ is constant, it degrades to a uniform Gaussian blur [S5].

### Denoise-GS
A self-supervised denoising method for sparse-view 3DGS that combines unsupervised image denoising (Noise2Void) with 3DGS [S6]. It uses two rounds: Round 1 trains a UNet with N2V, initializes 3DGS with InstantSplat, and filters rendered results. Round 2 fine-tunes the UNet with a composite loss and renders again [S6]. Unlike supervised methods, it requires no paired clean data [S6].

### Multi-Scale Constraint
Applies different scales to Gaussians based on viewer distance to improve rendering of distant objects [S7]. It uses a position-aware control function $\gamma(\mu)$ to adjust cloning and splitting thresholds based on the distance from the camera center [S7].

### LS-Gaussian Viewpoint Transformation
Leverages inter-frame continuity to transform viewpoints between consecutive frames for efficient sparse rendering [S8]. It operates at the tile/Gaussian level to reduce preprocessing and sorting costs [S8]. Rendering quality degrades as the number of consecutively transformed frames increases due to interpolation error accumulation [S8].

### 3D Gaussian Splatting Training Loop
The core loop involves picking a random photo, rendering from its known pose, comparing the render to the photo to compute an error metric (L1 + D-SSIM), and using gradients to nudge Gaussian parameters [S9, unofficial]. Training typically runs for a fixed budget of ~30,000 iterations [S9, unofficial].

### Camera Localisation for Convergence Basin
Localizes camera pose by minimizing photometric error against a target view while fixing the initial Gaussian set $G_{init}$ [S10, unofficial]. The estimated pose $T_{CW}^{est}$ is found by minimizing $\| I(\mathcal{G}_{init}, \mathbf{T}_{CW}) - \bar{I}_{target} \|_1$ [S10, unofficial].

### DiffGS Framework
Applies an optimization process during Gaussian extraction to optimize Gaussians to exact locations using a Gaussian Probability Function (GauPF) with a truncation function $\lambda$ and projection function $\tau$ [S11].

### Opacity Offset Table for DSA
Constructs an opacity offset table to model changes in digital subtraction angiography [S12].

### Resolution Guided Primitive Scheduler
Uses a concave-up scheduling function to control primitive growth, mitigating poor convergence from excessive growth at the end of optimization [S13]. The primitive budget is updated as $P_{fin}^{(i)} = \max(P_{fin}^{(i-1)}, \gamma \cdot P_{fin}^{(i-1)} + \eta \cdot P_{add})$ [S13].

### Conditional Splat Approximation
Approximates the influence range of a 3D Gaussian on a slice using a 2D ellipse splat scaled by the marginal factor, closely matching true iso-probability contours [S14, unofficial].

### Deformation-Aware Pruning
Identifies and removes redundant Gaussians by gauging their impact on deformation, distinguishing between stable and deformed Gaussians [S15].

### GEMM-GS
Reformulates the blending process into a GEMM-compatible form to leverage Tensor Cores [S16]. It uses a three-stage double-buffered CUDA kernel pipeline [S16]. It achieves a 1.42× speedup over vanilla 3DGS [S16].

### 3DGS Uncertainty Calculation via Fisher Information
Computes an uncertainty attribute for 3D Gaussians based on the negative log-likelihood of the rendered pixel value, interpreted as Fisher information [S17]. The uncertainty is $\bar{C}_{V;G} = -\log p_f(\pi|V; G)$ [S17].

### Spatio-spectral Pruning Score
Incorporates spectral information into the importance ranking of Gaussian primitives to enable stable pruning [S18, unofficial]. The score is $\tilde{U}_i^* = \lambda_s \frac{(\nabla g_i I_G)^2}{\|\tilde{U}_s\|^2} + \lambda_f \frac{(\nabla g_i \text{FFT}(I_G))^2}{\|\tilde{U}_f\|^2}$ [S18, unofficial].

## Operating characteristics

### Time and Memory Complexity
*   **Time:** The dominant cost is the sorting and rasterization step, which is $O(N \log N)$ or $O(N)$ depending on the sorting algorithm, where $N$ is the number of Gaussians [S16]. Training time is typically fixed at ~30,000 iterations [S9, unofficial].
*   **Memory:** Memory usage is proportional to the number of Gaussians and their feature dimensions. Each Gaussian stores position, rotation, scale, opacity, and SH coefficients [S1].

### Measured Performance
*   **GEMM-GS:** Achieves a 1.42× speedup over vanilla 3DGS and an additional 1.47× speedup when combined with other acceleration methods [S16].
*   **LS-Gaussian:** Achieves a 5.41× speedup over edge GPU baselines on Jetson AGX Orin [S8].

### Strengths and Limitations
*   **Strengths:** Real-time rendering speeds, high-quality novel view synthesis, explicit representation allows for easy editing [S1][S9, unofficial].
*   **Limitations:** High memory usage for large scenes, sensitivity to initialization and hyperparameters, potential for artifacts in sparse view scenarios [S6, S13].

### When to Use
*   Use for real-time novel view synthesis and interactive applications [S1][S9, unofficial].
*   Use when high-fidelity reconstruction is required from multi-view images [S1].

### When Not to Use
*   Avoid for scenes with extreme sparsity of views without additional denoising or regularization [S6].
*   Avoid for applications requiring strict surface geometry without additional constraints [S15421-scene-representation-and-geometry-constraints.md].

## Background

### Origin
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1]. It builds on the idea of representing scenes as a set of anisotropic 3D Gaussians and using differentiable rasterization for optimization [S1].

### History and Development
Since its introduction, numerous variants have been developed to address limitations such as memory usage, training speed, and handling of dynamic scenes [S1, S6, S15]. Methods like GEMM-GS and LS-Gaussian have focused on hardware acceleration [S8, S16], while others like DeSplat and Denoise-GS have addressed specific scene conditions [S5, S6].

### Where it is Used
3DGS is used in computer vision, graphics, and robotics for tasks such as novel view synthesis, 3D reconstruction, and augmented reality [S1, S8].
