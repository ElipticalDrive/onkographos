# Appearance Embedding

Also called: Image-specific Embedding

## Overview
Appearance Embedding associates each training image with a unique learnable vector to model appearance variations such as lighting changes and shadows [S1, unofficial]. It sets itself apart from standard Gaussian Splatting by decoupling appearance from the static 3D geometry, allowing the radiance field to adapt to per-image illumination conditions without altering the underlying Gaussian parameters [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A set of training images $\{I_i\}$, their corresponding camera poses, and the 3D Gaussian parameters (position, covariance, opacity, base color/features).
- Output: A rendered image where the final color accounts for the specific appearance embedding of the viewing image.

**Data Structures:**
- **Appearance Embedding Vector ($e_i$):** A learnable parameter vector for each training image $i$.
  - **Size:** Dimension $D=8$ [S1, unofficial].
  - **Type:** Float32 (standard for neural embeddings).
  - **Layout:** A 1D array of size 8.

**Parameters:**
- **Embedding Dimension:** 8 [S1, unofficial].

**Steps:**
1. **Initialization:** Initialize the appearance embedding vector $e_i$ for each training image $i$ with small random values (e.g., from a normal distribution with mean 0 and small variance) [G].
2. **Rendering:** For a training image $i$, retrieve its specific embedding $e_i$. Combine $e_i$ with the base Gaussian features (or replace them, depending on the variant) to compute the final color contribution during volume rendering.
3. **Optimization:** Update $e_i$ via gradient descent alongside other Gaussian parameters to minimize the photometric loss between the rendered image and the ground truth image $I_i$ [S1, unofficial].
4. **Validation Handling:** During validation, the appearance embeddings for unseen validation images are unknown. Calculate the mean of the appearance embeddings from all training images:
   $$ \bar{e} = \frac{1}{N} \sum_{i=1}^{N} e_i $$
   where $N$ is the number of training images. Use $\bar{e}$ as the appearance embedding for all validation images to ensure consistent appearance representation [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Validation Consistency:** Using the mean embedding for validation prevents the model from relying on specific training-image artifacts but may result in slightly less accurate appearance for validation views compared to training views [S1, unofficial].
- **Dimensionality:** The dimension is fixed at 8. Increasing this may capture more complex lighting but increases memory and compute cost [S1, unofficial].

## Subtopics

### Feature Embedding for Illumination
A technique to handle intense illumination changes, such as those found in indoor scenes with multiple light sources, by replacing spherical harmonics with a feature embedding $f$ and a trainable per-image embedding $e$ [S2]. It retains the opacity parameter $\alpha$ consistent with standard 2D Gaussian Splatting [S2]. This variant is chosen when standard spherical harmonics fail to represent high-frequency lighting variations [S2].

## Operating characteristics
- **Time Complexity:** Adds negligible overhead to the rendering pipeline, as the embedding lookup is $O(1)$ per image. Optimization adds gradient updates for $N$ embedding vectors.
- **Memory Complexity:** $O(N \times D)$, where $N$ is the number of training images and $D=8$ is the embedding dimension [S1, unofficial]. For 1,200 images, this is $1,200 \times 8 \times 4$ bytes $\approx 38.4$ KB, which is negligible.
- **Strengths:** Effectively models appearance changes like shadows and lighting variations without requiring explicit light source modeling [S1, unofficial].
- **Limitations:** Requires storing one embedding per training image. Validation performance relies on the mean embedding, which may not perfectly match the lighting of specific validation views [S1, unofficial].
- **When to use:** When scenes exhibit significant appearance variations across training images (e.g., outdoor scenes with changing weather or indoor scenes with multiple light sources) [S1, unofficial][S2].

## Background
Originating from the SCALAR-NeRF method, this approach follows the strategy of NeRF-W to associate each image with an appearance embedding [S1, unofficial]. It has been adopted in various 3D Gaussian Splatting variants to handle appearance changes [S1, unofficial][S2].
