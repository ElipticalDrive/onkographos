# Image-Based Localization (Floc)

Also called: Heatmap Generation, Target Localization, RNR-Map-based localization

## Overview
Image-Based Localization (Floc) determines an agent's position within a Renderable Neural Radiance Map (RNR-Map) using a single query image, bypassing the computationally expensive rendering step required by traditional inverse volume rendering methods. Unlike sibling methods that rely on differentiable rendering to match observed pixels with rendered views, Floc operates directly on the latent codes embedded in the RNR-Map, outputting a spatial heatmap and a predicted orientation to identify the most probable location and viewing angle.

## How it works
**Inputs and Outputs**
*   **Input:** A target query image $I_{trg}$ and the global RNR-Map $m$.
*   **Output:** A heatmap $E \in \mathbb{R}^{U \times V}$ representing the probability distribution of the target location $(u_{trg}, v_{trg})$ across the map grid, and a predicted orientation $\hat{a}_{trg}$.

**Data Structures**
*   **RNR-Map ($m$):** A 2D grid map where each cell $(u,v)$ contains a latent code vector $c_{u,v}$ derived from the encoder. The map also stores occupancy counts $n(u,v)$ [S1].
*   **Local Map ($m_{trg}$):** A temporary grid representation of the query image, generated by the registration function $F_{reg}$ using a hypothetical origin pose $p_0 = (0,0,0)$ [S1].
*   **Processed Maps ($m'_k, m'_q$):** Feature maps extracted from $m$ and $m_{trg}$ by CNNs $F_k$ and $F_q$ [S1].

**Numbered Steps**
1.  **Local Map Generation:** Transform the target image $I_{trg}$ into a local map $m_{trg}$ using the registration encoder $F_{reg}(I_{trg}, p_0; \theta_{enc})$, where $p_0$ is the fixed origin pose $(0,0,0)$ [S1].
2.  **Feature Extraction:** Process the global RNR-Map $m$ through convolutional network $F_k$ to obtain $m'_k$. Simultaneously, process the local map $m_{trg}$ through convolutional network $F_q$ to obtain $m'_q$ [S1].
3.  **Orientation Rotation:** Generate $R$ rotated versions of the query feature map $m'_q$. For each rotation index $r \in \{1, \dots, R\}$, apply rotation $Rot_r$ corresponding to angle $\theta_r = 360^\circ \times \frac{r-1}{R}$ to produce $(m'_q)_r$ [S1].
4.  **Cross-Correlation:** Perform cross-correlation (denoted as $\mathrm{Conv}$) between the global feature map $m'_k$ and each rotated query feature map $(m'_q)_r$. This acts as a sliding window filter to find spatial matches [S1].
5.  **Heatmap and Orientation Prediction:** Forward the outputs of the cross-correlation operations into a final CNN $F_E$. $F_E$ produces the heatmap $E$ and the orientation prediction $\hat{a}_{trg}$ [S1].

**Formulas**
The localization function $F_{loc}$ is defined as [S1]:
$$ F_{loc}(m, m_{trg}; \theta_{loc}) = F_E\left(\mathrm{Conv}\left(F_k(m), \{F_q(m_{trg})_r\}_{r=1}^R\right)\right) $$
where $\{F_q(m_{trg})_r\}_{r=1}^R$ are the $R$ rotated versions of the processed target map [S1].

The training loss minimizes the error between the predicted outputs and ground truth [S1]:
$$ \mathrm{Loss}(\theta_{loc}) = D_{KL}(E_{gt}, \hat{E}) + CE(a_{trg}, \hat{a}_{trg}) $$
where $D_{KL}$ is the Kullback-Leibler divergence between the ground truth heatmap $E_{gt}$ and predicted heatmap $\hat{E}$, and $CE$ is the cross-entropy loss for the orientation $a_{trg}$, which is discretized into 18 bins [S1].

**Parameters**
*   **$R$ (Rotations):** The number of discrete orientation angles to search. The source specifies 18 bins for orientation classification [S1].
*   **$p_0$:** The initial pose used for encoding the query image, fixed at $(0,0,0)$ [S1].

**Edge Cases and Pitfalls**
*   **Unknown Position:** The method assumes the agent does not know the target location, necessitating the use of the origin pose $p_0$ for the initial encoding of $I_{trg}$ [S1].
*   **Orientation Ambiguity:** Visual similarity can cause confusion between visually similar places; the rotation search and orientation head mitigate this but require sufficient training data [S1].

```python
def floc_localization(global_map_m, target_image_I_trg, R=18):
    # Step 1: Transform target image to local map using origin pose p0=(0,0,0)
    # F_reg is the registration encoder from RNR-Map Construction
    local_map_m_trg = F_reg(I_trg, p0=(0,0,0))
    
    # Step 2: Process global and local maps through CNNs
    # F_k and F_q are feature extraction networks
    m_prime_k = F_k(global_map_m)
    m_prime_q = F_q(local_map_m_trg)
    
    # Step 3: Rotate query map into R different angles
    rotated_queries = []
    for r in range(1, R + 1):
        # Angle calculation: 360 * (r-1) / R
        angle = 360.0 * (r - 1) / R
        # Rot_r represents the rotation operation
        rotated_m_prime_q = Rot_r(m_prime_q, angle)
        rotated_queries.append(rotated_m_prime_q)
        
    # Step 4: Cross-correlation (Conv) between global map and each rotated query
    # Conv denotes cross-correlation
    conv_outputs = []
    for q_rot in rotated_queries:
        # Conv(m_prime_k, q_rot) slides q_rot over m_prime_k
        output = Conv(m_prime_k, q_rot)
        conv_outputs.append(output)
        
    # Step 5: Forward to CNN F_E to produce heatmap and orientation
    # F_E takes the list of conv_outputs (or concatenated features)
    heatmap_E, orientation_pred = F_E(conv_outputs)
    
    return heatmap_E, orientation_pred
```

## Operating characteristics
*   **Speed:** The localization framework operates at 56.8 Hz [S1]. This is significantly faster than rendering-based optimization methods (e.g., camera tracking at 5 Hz) because it eliminates the rendering step [S1].
*   **Accuracy:** In curved scenarios of the NRNS dataset, the navigation framework utilizing this localization achieves a 65.7% success rate, an improvement of 18.6% over the state-of-the-art (55.4%) [S1].
*   **Strengths:** Direct utilization of latent codes allows for fast, real-time localization without rendering. It is robust under odometry and actuation noises [S1].
*   **Limitations:** It relies on the quality of the latent codes embedded in the RNR-Map. If the RNR-Map is poorly constructed or lacks visual information, localization accuracy degrades. It is less precise than rendering-based camera tracking for fine-level localization [S1].

## Background
*   **Origin:** The method was introduced in the paper "Renderable Neural Radiance Map for Visual Navigation" [S1].
*   **Context:** It addresses the challenge of visual navigation by explicitly embedding 3D visual information into a 2D grid form (RNR-Map) and leveraging the implicit visual information of latent codes for reasoning about the environment [S1].
*   **Development:** The work was supported by the Institute of Information & Communications Technology Planning & Evaluation (IITP) [S1]. It is presented as the first method combining explicit grid embedding, renderability, and fast latent-code-based localization for navigation [S1].
