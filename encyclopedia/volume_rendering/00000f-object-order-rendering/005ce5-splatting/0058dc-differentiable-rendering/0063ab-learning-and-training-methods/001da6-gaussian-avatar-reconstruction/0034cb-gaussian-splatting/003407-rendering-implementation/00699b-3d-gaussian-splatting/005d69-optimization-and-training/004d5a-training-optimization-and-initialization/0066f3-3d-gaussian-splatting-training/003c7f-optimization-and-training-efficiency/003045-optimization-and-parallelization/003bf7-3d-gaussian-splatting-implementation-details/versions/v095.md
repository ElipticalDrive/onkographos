# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, GSGEN Implementation Details, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific implementation parameters, optimization strategies, and variant algorithms used to train and render 3D Gaussian Splatting (3DGS) scenes. It addresses the practical challenges of differentiable rasterization, including half-precision stability, adaptive density control, and handling of specific scene properties like defocus blur or sparse views. It sets itself apart from general optimization theory by providing concrete thresholds, data structures, and algorithmic steps for variants such as DeSplat, Denoise-GS, and LS-Gaussian.

## How it works

### Inputs and Outputs
*   **Inputs:** Sparse Structure-from-Motion (SfM) point cloud, camera poses, and input images.
*   **Outputs:** A set of 3D Gaussian primitives parameterized by mean $\mu$, covariance $\Sigma$ (or scale $s$ and rotation $q$), opacity $\alpha$, and spherical harmonic coefficients for color $c$.

### Data Structures
*   **Gaussian Attributes:** Each Gaussian stores position ($\mathbb{R}^3$), rotation ($\mathbb{R}^4$, quaternion), scale ($\mathbb{R}^3$), opacity ($\mathbb{R}^1$), and SH coefficients ($\mathbb{R}^{3 \times (d+1)^2}$).
*   **Rasterization Buffer:** Tile-based accumulation buffer for color and depth.
*   **Gradient Storage:** Accumulated positional gradients for densification decisions.

### Training Optimization and Initialization

#### Standard 3DGS Training Loop
The core training process involves iterative densification and pruning of Gaussians based on view-space position gradients and opacity [S1, S3].

1.  **Initialization:** Initialize Gaussians from the SfM point cloud.
2.  **Rasterization:** Render the scene using differentiable alpha blending.
3.  **Loss Computation:** Compute loss between rendered and ground-truth images.
4.  **Backpropagation:** Compute gradients with respect to Gaussian parameters.
5.  **Densification (Every 100–500 iterations):**
    *   **Splitting:** Split Gaussians with high view-space position gradients. Threshold $T_{pos} = 0.02$ [S1].
    *   **Cloning:** Clone Gaussians with high opacity but low gradient to increase density in complex areas.
6.  **Pruning (Every 200 iterations):**
    *   Remove Gaussians with opacity $\alpha < \alpha_{min} = 0.05$ [S1].
    *   Remove Gaussians with excessively large world-space or view-space radius.
7.  **Compactness Densification:** Perform compactness-based densification every 1000 iterations [S1].

#### Half-Precision Implementation
To reduce register pressure and memory bandwidth, the `gsplat` library implements half-precision (FP16) memory fetches on feature vectors during rasterization for both forward and backward kernels [S2].
*   **Stability:** An automatic scaling factor is applied to loss values to improve half-precision training stability [S2].
*   **MLP Evaluation:** Compact MLPs (e.g., for view-dependent effects) are trained and evaluated in half precision using tiny-cuda-nn's JIT-compiled cooperative vector MLPs [S2].

#### Optimizer Settings
*   **Optimizer:** Adam [S3].
*   **Learning Rate:** $1 \times 10^{-3}$ [S3].
*   **SH Degree:** 1 [S3].

### Variant Algorithms

#### Corrected Scene-Extent
Standard 3DGS calculates scene extent $e_{\text{scene}}$ based on camera positions, which biases optimization if cameras are clustered (e.g., orbiting a small object) [S4]. The corrected extent uses the SfM point cloud:
$$ \bar{C} = \frac{1}{N_{\text{cam}}} \sum_{i=1}^{N_{\text{cam}}} C_i $$
$$ e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2 $$
where $N_{\text{SfM}}$ is the number of SfM points, $\bar{C}$ is the average camera position, and $p_i$ are SfM points [S4].

#### Selective Defocus Blurring
To handle spatially varying blur, a compact MLP predicts a per-Gaussian scale offset $\delta s_j$ [S5].
1.  Predict $\delta s_j$ for each Gaussian $j$.
2.  Add offset to base scale to transform covariance.
3.  Project transformed covariance to 2D space.
4.  Use as pixel-wise blur kernel during rasterization.
*   **Pitfall:** If $\delta s_j$ is constant, it degrades to uniform Gaussian blur [S5].

#### Denoise-GS
A self-supervised method for sparse-view/noisy scenes using Noise2Void (N2V) [S6].
1.  **Round 1:** Train UNet with N2V. Process denoised images through InstantSplat to initialize/train/render 3DGS.
2.  **Filtering:** Group and filter rendered results by viewpoint for stability.
3.  **Round 2:** Fine-tune UNet with composite loss (low-frequency + perceptual detail). Render again on selected viewpoints.

#### Multi-Scale Constraint
Applies position-aware adaptive control for large-scale scenes [S7].
$$ \gamma(\mu) = \begin{cases} 1 & \|\mu - c\|^2 < 2r \\ \|\mu - c\|^2 / r - 1 & \|\mu - c\|^2 \ge 2r \end{cases} $$
where $r$ is scene radius, $c$ is camera center.
*   If $\max(s) < g \cdot \gamma(\mu)$, clone.
*   If $\max(s) \ge g \cdot \gamma(\mu)$, split.
*   If $\max(s) > b \cdot \gamma(\mu)$, eliminate.
Parameters $g$ and $b$ are scale thresholds [S7].

#### LS-Gaussian Viewpoint Transformation
Leverages inter-frame continuity for sparse rendering [S8].
*   Transforms viewpoint between consecutive frames instead of rendering each separately.
*   **Pitfall:** Quality degrades with accumulated interpolation errors over many transformed frames [S8].
*   **Usage:** Renders one frame fully every 6 frames on edge devices like Jetson AGX Orin [S8].

#### Camera Localisation for Convergence Basin
Localizes camera pose by minimizing photometric error against ground-truth color, fixing $G_{init}$ [S9, unofficial].
$$ \mathbf{T}_{CW}^{est} = \underset{\mathbf{T}_{CW}}{\arg \min} \left\| I(\mathcal{G}_{init}, \mathbf{T}_{CW}) - \bar{I}_{target} \right\|_1 $$
Optimization runs for 1000 iterations; success if pose converges within 1cm [S9, unofficial].

#### DiffGS Framework
Optimizes Gaussians to exact locations using a Gaussian Probability Function (GauPF) with truncation function $\lambda$ and projection function $\tau$ (e.g., $\tau(x) = e^{-x}$) [S10].
*   **Performance:** 50K Gaussians: PSNR 28.61, SSIM 0.9787, LPIPS 0.0251. 100K: PSNR 30.35, SSIM 0.9838, LPIPS 0.0151. 350K: PSNR 34.01, SSIM 0.9879, LPIPS 0.0149 [S10].

#### Conditional Splat Approximation
Approximates 3D Gaussian influence on a slice using a 2D ellipse splat scaled by marginal factor, closely matching true iso-probability contours [S12, unofficial].

#### PyGS Optimization
Uses combined MSE and SSIM loss for multi-scale Pyramidal 3DGS [S13, unofficial].
$$ L = \lambda \cdot \text{MSE}(C, \hat{C}) + (1 - \lambda) \cdot \text{SSIM}(C, \hat{C}) $$
*   Newly split/cloned Gaussians remain in original level/cluster.
*   Routinely reassess levels based on scales to preserve multi-scale balance [S13, unofficial].

#### GAINS (Inverse Rendering)
Two-stage inverse rendering from sparse views (4–32) using 2DGS for geometry [S14].
*   **Stage I:** Optimize geometry using monocular depth, normal, and diffusion priors.
*   **Stage II:** Jointly optimize material/lighting using segmentation, intrinsic image decomposition, and diffusion priors.

#### Neural Illumination Enhancement (NIE)
Models non-Lambertian effects via a lightweight MLP predicting view-dependent color residual $I_n$ [S16, unofficial].
*   **Inputs:** Spatial position (HashGrid), reflection direction (SH), view direction, normals, Fresnel, roughness.
*   **Output:** $I = I_g + I_n$, where $I_g$ is explicit 3DGS render [S16, unofficial].

#### GraphiGS
Models component distribution $\delta_\theta$ as a 3D Gaussian primitive for uncertainty [S17].
$$ \delta_{GS}(x; \mu, \Sigma) = \exp(-\frac{1}{2} (x - \mu)^T \Sigma^{-1} (x - \mu)) $$
Provides compact spatial support but may be limited in capturing broader uncertainty regions compared to heavy-tailed distributions [S17].

#### Opacity Offset Table for DSA
Constructs an opacity offset table to model changes in digital subtraction angiography [S11].

#### SAGS & Frequency GS
*   **SAGS:** Adaptive 2D low-pass filter at inference based on resolution/distance to handle aliasing [S15, unofficial].
*   **Frequency GS:** Frequency-domain regularization on rendered image to recover high-frequency detail [S15, unofficial].

## Operating characteristics

*   **Time Complexity:** Rendering is $O(N \cdot T)$ where $N$ is the number of Gaussians and $T$ is the number of tiles/pixels. Training involves iterative densification, increasing $N$ over time.
*   **Memory Complexity:** $O(N \cdot D)$ where $D$ is the dimensionality of Gaussian attributes (position, scale, rotation, opacity, SH coefficients).
*   **Performance:** Real-time rendering (60+ FPS) is achievable on modern GPUs for scenes with millions of Gaussians [S8][S13, unofficial].
*   **Strengths:** High fidelity, real-time rendering speed, explicit representation allows easy editing.
*   **Limitations:** High memory usage for large scenes, sensitive to initialization, potential for "floaters" in unobserved regions.
*   **Hardware:** Heavily optimized for CUDA GPUs using half-precision arithmetic and tile-based rasterization [S2].

## Background

3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1]. It represents scenes as a set of differentiable 3D Gaussians, enabling high-quality novel view synthesis at interactive frame rates. The method builds on earlier work in neural rendering and splatting, addressing the computational bottlenecks of NeRFs. It has since spawned numerous variants for compression, dynamic scenes, and specific applications like inverse rendering and sparse-view reconstruction.
