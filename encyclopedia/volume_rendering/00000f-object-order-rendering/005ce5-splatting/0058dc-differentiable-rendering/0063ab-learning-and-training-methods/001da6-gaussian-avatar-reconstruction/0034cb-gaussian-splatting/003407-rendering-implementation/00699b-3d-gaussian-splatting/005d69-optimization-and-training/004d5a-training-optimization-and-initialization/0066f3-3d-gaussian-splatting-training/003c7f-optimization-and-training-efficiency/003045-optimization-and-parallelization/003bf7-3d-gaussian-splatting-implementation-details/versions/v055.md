# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, GSGEN Implementation Details, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific hyperparameters, optimization schedules, and data structures required to implement the 3D Gaussian Splatting (3DGS) training loop and rendering pipeline. It addresses the problem of translating the theoretical differentiable rendering formulation into a stable, efficient software implementation. It sets itself apart from sibling articles by providing concrete numerical thresholds, iteration schedules, and memory management strategies (such as half-precision handling and GEMM reformulation) rather than high-level architectural descriptions.

## How it works

### Inputs and Outputs
*   **Inputs:** A set of $N$ images with known camera poses (from SfM), an initial point cloud (SfM points), and hyperparameters for the optimization schedule.
*   **Outputs:** A set of $M$ 3D Gaussians, each parameterized by mean $\mu$, covariance $\Sigma$ (or scale $s$ and rotation $q$), opacity $\alpha$, spherical harmonic coefficients $c$, and potentially additional features (e.g., semantic codes, language embeddings).

### Data Structures
The implementation typically maintains the following structures in GPU memory:
1.  **Gaussian Attributes:** A flat array or structure-of-arrays (SoA) containing:
    *   Position: $\mathbb{R}^3$ (float32 or float16).
    *   Rotation: $\mathbb{R}^4$ (quaternion, normalized).
    *   Scale: $\mathbb{R}^3$ (log-space or exponential).
    *   Opacity: $\mathbb{R}^1$ (sigmoid output).
    *   SH Coefficients: $\mathbb{R}^{3 \times (D+1)^2}$ for degree $D$.
2.  **Gradients:** Parallel arrays for $\nabla_\mu, \nabla_\Sigma, \nabla_\alpha, \nabla_c$.
3.  **Tile/Screen Buffers:** For rasterization, buffers storing accumulated color $C_j$ and transmittance $T_i$ per tile.

### Training Loop and Optimization Schedule
The core training process is a stochastic gradient descent loop [S9, unofficial].

1.  **Initialization:** Initialize Gaussians from the SfM point cloud. Compute scene extent $e_{\text{scene}}$.
    *   *Pitfall:* The default scene extent calculation $e_{\text{scene}} = 1.1 \cdot \max_{i} \|\bar{C} - C_i\|_2$ is biased if cameras are clustered (e.g., orbiting a small object) [S4]. Use the corrected extent based on SfM points:
        $$e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2$$
        where $\bar{C} = \frac{1}{N_{\text{cam}}} \sum C_i$ [S4].
2.  **Iteration:**
    *   Randomly select one training image $I_{target}$ and its camera pose [S9, unofficial].
    *   **Render:** Project Gaussians to 2D, sort by depth, and rasterize using alpha blending to produce $I_{render}$ [S16].
    *   **Loss:** Compute $\mathcal{L} = (1 - \lambda)\mathcal{L}_1 + \lambda\mathcal{L}_{SSIM}$ with $\lambda \approx 0.2$ [S9, unofficial].
    *   **Backprop:** Compute gradients w.r.t. Gaussian parameters [S9, unofficial].
    *   **Optimize:** Update parameters using Adam optimizer with learning rate $1 \times 10^{-3}$ [S3].
3.  **Densification (Splitting/Cloning):**
    *   Triggered every 500 iterations [S1].
    *   Split Gaussians where the view-space position gradient exceeds $T_{pos} = 0.02$ [S1].
    *   *Advanced Schedule:* Use an exponentially ascending gradient threshold or a concave-up growth curve (DashGaussian) to control primitive count [S13].
    *   *Multi-Scale Constraint:* For large scenes, apply position-aware scaling $\gamma(\mu)$:
        $$\gamma(\mu) = \begin{cases} 1 & \|\mu - c\|^2 < 2r \\ \|\mu - c\|^2 / r - 1 & \|\mu - c\|^2 \ge 2r \end{cases}$$
        Clone if $\max(s) < g \cdot \gamma(\mu)$, split if $\max(s) \ge g \cdot \gamma(\mu)$, and eliminate if $\max(s) > b \cdot \gamma(\mu)$ [S7].
4.  **Pruning:**
    *   Triggered every 200 iterations [S1].
    *   Remove Gaussians with opacity $\alpha < \alpha_{min} = 0.05$ or excessive radius [S1].
    *   *Deformation-Aware:* Identify redundant Gaussians based on deformation scores in dynamic scenes [S15].
5.  **Termination:** Run for a fixed budget, typically 30,000 iterations [S9, unofficial].

### Rendering Pipeline (Rasterization)
1.  **Preprocessing:** Project 3D Gaussians to 2D ellipses. Compute depth $d$ and RGB color $c$ [S16].
2.  **Tile Assignment:** Divide screen into tiles (e.g., $16 \times 16$ pixels) [S16]. Assign Gaussians to overlapping tiles.
3.  **Sorting:** Sort Gaussians per tile by depth $d$ using radix sort [S16].
4.  **Blending:**
    *   Standard: Iterate through sorted Gaussians, accumulating $C_j = \sum T_i \alpha_i c_i$ [S16].
    *   *GEMM-GS:* Reformulate blending into General Matrix Multiplication (GEMM) to leverage Tensor Cores. Use a three-stage double-buffered CUDA pipeline with asynchronous memory copy [S16].
    *   *Half-Precision:* Use FP16 memory fetches for feature vectors to reduce register pressure [S2]. Apply automatic scaling to loss values for stability [S2].

### Pseudocode: Training Step

```python
def train_step(gaussians, camera, target_image, iteration):
    # 1. Render
    # Project Gaussians to 2D, sort by depth, rasterize
    rendered_image = rasterize(gaussians, camera)
    
    # 2. Compute Loss
    # L = 0.8 * L1 + 0.2 * SSIM
    loss = compute_loss(rendered_image, target_image)
    
    # 3. Backpropagation
    loss.backward()
    
    # 4. Optimization Step
    optimizer.step()
    optimizer.zero_grad()
    
    # 5. Densification (Every 500 iters)
    if iteration % 500 == 0:
        gradients = get_position_gradients(gaussians)
        for g in gaussians:
            if gradients[g] > 0.02: # T_pos
                split_gaussian(g)
                
    # 6. Pruning (Every 200 iters)
    if iteration % 200 == 0:
        for g in gaussians:
            if g.opacity < 0.05: # alpha_min
                remove_gaussian(g)
                
    return loss
```

## Subtopics

### Corrected Scene-Extent
A method to calculate scene extent based on the SfM point cloud rather than camera positions to avoid bias from camera distribution (e.g., orbiting a small object in a large environment). It sets itself apart by replacing the max-camera-distance metric with the mean distance of SfM points from the average camera position. Choose this when camera poses are clustered or non-representative of the full scene volume. Link: [Corrected Scene-Extent](12944-corrected-scene-extent.md).

### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ to selectively enlarge covariances, creating pixel-wise variable blur kernels that match spatially varying scene blurriness. It sets itself apart from uniform Gaussian blur by allowing spatially varying blur shapes and magnitudes via a compact MLP. Choose this for scenes with defocus blur or motion blur. Link: [Selective Defocus Blurring](12945-selective-defocus-blurring.md).

### Denoise-GS
A self-supervised denoising method for sparse-view 3DGS that combines unsupervised image denoising (Noise2Void) with differentiable 3DGS. It sets itself apart from supervised methods by requiring no paired clean data, making it robust to non-Gaussian noise in sparse viewpoints. Choose this for sparse-view or noisy input data. Link: [Denoise-GS](12946-denoise-gs.md).

### Multi-Scale Constraint
A technique using position-aware point adaptive control to apply different scales to Gaussians based on viewer distance, improving rendering of distant objects. It sets itself apart by dynamically adjusting cloning/splitting thresholds based on distance from the camera center. Choose this for large-scale scenes with significant depth variation. Link: [Multi-Scale Constraint](12947-multi-scale-constraint.md).

### LS-Gaussian Viewpoint Transformation
An algorithm that leverages inter-frame continuity for efficient sparse rendering by transforming the viewpoint between consecutive frames. It sets itself apart from naive pixel warping by operating at the tile/Gaussian level to reduce preprocessing and sorting costs. Choose this for high-frame-rate video rendering on edge devices. Link: [LS-Gaussian Viewpoint Transformation](12948-ls-gaussian-viewpoint-transformation.md).

### 3D Gaussian Splatting Training Loop
Defines the per-image error computation and the stochastic gradient descent loop. It sets itself apart by emphasizing the fixed iteration budget (30,000) and the specific loss weighting (0.8 L1 + 0.2 SSIM). Choose this as the baseline training procedure. Link: [3D Gaussian Splatting Training Loop](12949-3d-gaussian-splatting-training-loop.md).

### Camera Localisation for Convergence Basin
Localizes camera pose by minimizing photometric error against a ground-truth image, fixing the Gaussian initialization. It sets itself apart by using the 3DGS renderer as a differentiable projection model for pose estimation. Choose this for SLAM or pose refinement tasks. Link: [Camera Localisation for Convergence Basin](12950-camera-localisation-for-convergence-basin.md).

### DiffGS Framework
Applies an optimization process during Gaussian extraction to optimize Gaussians to exact locations using a Gaussian Probability Function (GauPF). It sets itself apart by introducing truncation and projection functions to refine Gaussian placement. Choose this for high-fidelity reconstruction with fewer Gaussians. Link: [DiffGS Framework](12951-diffgs-framework.md).

### Opacity Offset Table for DSA
Constructs an opacity offset table to model changes in digital subtraction angiography. It sets itself apart by explicitly modeling temporal opacity changes for medical imaging. Choose this for dynamic medical volume rendering. Link: [Opacity Offset Table for DSA](12952-opacity-offset-table-for-dsa.md).

### Resolution Guided Primitive Scheduler
Schedules primitive growth using a momentum-based budgeting formula $P_{fin}^{(i)} = \max(P_{fin}^{(i-1)}, \gamma \cdot P_{fin}^{(i-1)} + \eta \cdot P_{add})$. It sets itself apart by using a concave-up scheduling function to suppress early growth and encourage mid-stage growth, mitigating poor convergence at the end. Choose this for faster training convergence. Link: [Resolution Guided Primitive Scheduler](12953-resolution-guided-primitive-scheduler.md).

### Conditional Splat Approximation
Approximates the influence range of a 3D Gaussian on a slice using a 2D ellipse splat scaled by the marginal factor. It sets itself apart by providing an accurate and efficient approximation of 3D Gaussian iso-probability contours for slice-based rendering. Choose this for tomographic or slice-based applications. Link: [Conditional Splat Approximation](12954-conditional-splat-approximation.md).

### Deformation-Aware Pruning
Identifies and removes redundant Gaussians by gauging their impact on deformation, distinguishing between stable and deformed Gaussians. It sets itself apart by incorporating deformation scores into the pruning criteria. Choose this for dynamic 4D scene reconstruction. Link: [Deformation-Aware Pruning](12955-deformation-aware-pruning.md).

### GEMM-GS
An acceleration approach that reformulates the blending process into a GEMM-compatible form to utilize Tensor Cores. It sets itself apart by achieving a 1.42× speedup over vanilla 3DGS and being orthogonal to other acceleration methods. Choose this for high-performance rendering on modern GPUs. Link: [GEMM-GS](12956-gemm-gs.md).

## Operating characteristics

*   **Time Complexity:** Rendering is $O(N \cdot T)$ where $N$ is the number of Gaussians and $T$ is the number of tiles, dominated by sorting and blending [S16]. Training time is proportional to the number of iterations (typically 30,000) [S9, unofficial].
*   **Memory Complexity:** $O(N \cdot D)$ where $D$ is the dimensionality of SH coefficients. Large scenes can exceed 1GB [12927-compact-3d-gaussian-representation-c3dgs.md].
*   **Performance:** GEMM-GS achieves 1.42× speedup over vanilla implementation [S16]. LS-Gaussian achieves 5.41× speedup on Jetson AGX Orin [S8].
*   **Strengths:** Real-time rendering, high visual fidelity, explicit representation.
*   **Limitations:** High memory usage, sensitivity to initialization, potential for artifacts in sparse views [S6].
*   **When to use:** Novel view synthesis, real-time visualization, AR/VR.
*   **When not to use:** Scenes with extreme occlusion or transient objects without distractor separation [S1], or when memory is severely constrained without compression [12943-data-compression-and-storage-optimization.md].

## Background
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1]. It represents scenes as a set of 3D Gaussians optimized via differentiable rasterization. The method builds on earlier work in radiance fields and splatting, offering a trade-off between the quality of NeRFs and the speed of mesh-based rendering. The implementation details described here are derived from the original paper and subsequent optimizations for efficiency and robustness [S1, S2, S3][S9, unofficial].
