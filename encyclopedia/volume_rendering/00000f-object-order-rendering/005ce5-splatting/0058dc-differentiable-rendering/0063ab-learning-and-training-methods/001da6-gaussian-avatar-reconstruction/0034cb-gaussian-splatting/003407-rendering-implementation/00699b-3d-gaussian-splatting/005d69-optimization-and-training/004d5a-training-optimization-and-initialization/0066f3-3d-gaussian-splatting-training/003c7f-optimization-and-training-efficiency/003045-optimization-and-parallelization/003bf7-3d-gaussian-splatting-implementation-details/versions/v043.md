# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific implementation parameters, optimization schedules, and algorithmic variants required to train and render 3D Gaussian Splatting (3DGS) scenes effectively. It addresses the gap between the theoretical differentiable rendering formulation and practical execution, covering training loops, densification heuristics, memory management, and specialized variants for handling blur, noise, and internal structures. It sets itself apart from generic optimization articles by providing concrete hyperparameters, code-level logic for densification thresholds, and specific handling of edge cases like camera bias and sparse views.

## How it works

### Inputs and Outputs
*   **Inputs:** A set of $N$ input images with known camera poses (extrinsics $T_{CW}$ and intrinsics), initialized 3D Gaussians (typically from Structure-from-Motion, SfM), and a loss function $\mathcal{L}$ (typically a weighted sum of L1 and D-SSIM).
*   **Outputs:** Optimized Gaussian parameters: position $\mu$, covariance $\Sigma$ (parameterized as scale $s$ and rotation $q$), opacity $\alpha$, spherical harmonic coefficients $c_l^m$, and potentially auxiliary attributes (normals, BRDF, semantic codes).

### Data Structures
The core data structure is a list of $M$ Gaussians. Each Gaussian $i$ stores:
*   $\mu_i \in \mathbb{R}^3$: Center position.
*   $s_i \in \mathbb{R}^3$: Scale (non-negative).
*   $q_i \in \mathbb{R}^4$: Rotation (unit quaternion).
*   $\alpha_i \in \mathbb{R}$: Opacity.
*   $c_{i, l, m} \in \mathbb{R}$: SH coefficients for degree $l$.
*   Optional: Normal vector $n_i$, BRDF parameters, semantic codes.

During rasterization, Gaussians are projected to 2D. The 2D covariance $\Sigma'$ is computed as $\Sigma' = J W \Sigma W^T J^T$, where $W$ is the view matrix and $J$ is the Jacobian of the affine approximation of the projection.

### Training Loop
The standard training loop follows a stochastic gradient descent approach [S10, unofficial]:

1.  **Random Selection:** Randomly select one input image $I_{target}$ and its camera pose $T_{CW}$ from the training set [S2][S10, unofficial].
2.  **Rendering:** Render the current set of Gaussians from $T_{CW}$ to produce image $I_{render}$ using the differentiable rasterizer [S10, unofficial].
3.  **Loss Computation:** Compute the loss $\mathcal{L}$ between $I_{render}$ and $I_{target}$. The standard loss is:
    $$ \mathcal{L} = (1 - \lambda) \mathcal{L}_1 + \lambda \mathcal{L}_{SSIM} $$
    where $\lambda \approx 0.2$ [S10, unofficial].
4.  **Backpropagation:** Compute gradients $\nabla \mathcal{L}$ with respect to all Gaussian parameters [S10, unofficial].
5.  **Optimization Step:** Update parameters using an optimizer (typically Adam with learning rate $1 \times 10^{-3}$) [S2].
6.  **Densification/Pruning:** Periodically (e.g., every 100 iterations), apply densification and pruning heuristics based on gradient magnitudes and Gaussian sizes [S3, S13].
7.  **Repeat:** Iterate for a fixed budget (typically 30,000 iterations) [S10, unofficial].

### Densification and Pruning Heuristics
Densification controls the number of Gaussians to balance detail and performance.

**Gradient Threshold Schedule:**
To control splitting, an exponentially ascending gradient threshold is used [S3]. Let $t$ be the current iteration. The threshold $T(t)$ increases over time to prevent excessive splitting in early stages [S3].

**Cloning vs. Splitting:**
*   **Cloning:** If the accumulated positional gradient of a Gaussian splat exceeds a threshold, and the Gaussian is small, it is cloned.
*   **Splitting:** If the gradient exceeds the threshold and the Gaussian is large, it is split into two smaller Gaussians.
*   **Pruning:** Gaussians with low opacity or excessive size are removed [S3].

**Multi-Scale Constraint:**
For large-scale scenes, a position-aware adaptive control adjusts thresholds based on viewer distance [S7]:
$$ \gamma(\mu) = \begin{cases} 1 & \text{if } \|\mu - c\|^2 < 2r \\ \frac{\|\mu - c\|^2}{r} - 1 & \text{if } \|\mu - c\|^2 \ge 2r \end{cases} $$
where $r$ is the scene radius and $c$ is the camera center [S7].
*   Clone if $\max(s) < g \cdot \gamma(\mu)$.
*   Split if $\max(s) \ge g \cdot \gamma(\mu)$.
*   Eliminate if $\max(s) > b \cdot \gamma(\mu)$, where $g$ and $b$ are scale threshold parameters [S7].

**Normal Gradient Densification:**
To improve normal recovery in thin regions, an additional criterion densifies Gaussians whose normal gradient exceeds a threshold $T_n$ (typically $2 \times 10^{-9}$) [S13].

### Scene Extent Calculation
The default 3DGS scene extent $e_{\text{scene}}$ is proportional to the distance of the furthest camera from the average camera position:
$$ e_{\text{scene}} = 1.1 \cdot \max_{i=1}^{N_{\text{cam}}} \|\bar{C} - C_i\|_2 $$
$$ \bar{C} = \frac{1}{N_{\text{cam}}} \sum_{i=1}^{N_{\text{cam}}} C_i $$
This can cause bias if cameras are clustered (e.g., orbiting a small object) [S3]. A corrected scene extent $e'_{\text{scene}}$ uses the SfM point cloud:
$$ e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2 $$
where $p_i$ are SfM points [S3].

### Optimization and Parallelization
*   **Half-Precision:** Use half-precision (FP16) memory fetches for feature vectors during rasterization to reduce register pressure [S1]. Use tiny-cuda-nn's JIT-compiled cooperative vector MLPs in FP16 [S1]. Apply an automatic scaling factor to loss values to improve half-precision stability [S1].
*   **Library:** The `gsplat` library is commonly used for the differentiable rasterization [S2].
*   **Sparse Convolution:** For volume-based methods, `torchsparse` is used [S2].

### Pseudocode: Training Loop

```python
def train_3dgs(images, poses, initial_gaussians, num_iterations=30000, lambda_ssim=0.2):
    """
    Standard 3DGS training loop.
    """
    gaussians = initial_gaussians
    optimizer = Adam(gaussians.parameters(), lr=1e-3)
    
    for iteration in range(num_iterations):
        # 1. Randomly select one image and pose
        idx = random.randint(0, len(images) - 1)
        target_image = images[idx]
        camera_pose = poses[idx]
        
        # 2. Render
        rendered_image = rasterize(gaussians, camera_pose)
        
        # 3. Compute Loss
        l1_loss = L1(rendered_image, target_image)
        ssim_loss = D_SSIM(rendered_image, target_image)
        loss = (1 - lambda_ssim) * l1_loss + lambda_ssim * ssim_loss
        
        # 4. Backpropagate
        loss.backward()
        
        # 5. Optimizer Step
        optimizer.step()
        optimizer.zero_grad()
        
        # 6. Densification/Pruning (every 100 iterations)
        if iteration % 100 == 0:
            densify_and_prune(gaussians, iteration)
            
        # 7. Update learning rate schedule if necessary
        update_learning_rates(optimizer, iteration)

def densify_and_prune(gaussians, iteration):
    """
    Apply densification and pruning heuristics.
    """
    # Calculate gradients
    gradients = calculate_gradient_magnitudes(gaussians)
    
    # Get scene extent (corrected or default)
    scene_extent = calculate_scene_extent(gaussians)
    
    # Thresholds based on iteration
    grad_threshold = get_gradient_threshold(iteration, scene_extent)
    opacity_threshold = get_opacity_threshold(iteration)
    
    for gaussian in gaussians:
        # Pruning
        if gaussian.opacity < opacity_threshold or gaussian.size > max_size:
            remove_gaussian(gaussian)
            continue
            
        # Densification
        if gradients[gaussian.id] > grad_threshold:
            if gaussian.size < clone_threshold:
                clone_gaussian(gaussian)
            else:
                split_gaussian(gaussian)
```

## Subtopics

### Corrected Scene-Extent
A method to calculate scene extent based on the SfM point cloud rather than camera positions to avoid bias from camera distribution (e.g., orbiting a small object in a large environment). It sets itself apart from the default 3DGS extent calculation by using the spatial distribution of reconstructed points, ensuring the scene volume is accurately represented regardless of camera clustering. Choose this when camera poses are not uniformly distributed around the scene. [Corrected Scene-Extent](12180-sorting-and-rendering-pipeline-optimization.md) is not the correct link; this is a specific variant of scene extent calculation.

### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ to selectively enlarge covariances, creating pixel-wise variable blur kernels that match spatially varying scene blurriness [S4]. It sets itself apart from naive Gaussian blur (which applies a single kernel to the whole image) and learnable Gaussian kernels (which optimize a single mean/variance) by allowing spatially varying blur shapes and magnitudes [S4]. Choose this when training on images with defocus blur or motion blur [S4]. Pitfall: If $\delta s_j$ is predicted as a constant, it degrades to a uniform Gaussian blur [S4].

### Denoise-GS
A self-supervised denoising method for sparse-view 3D Gaussian Splatting that combines unsupervised image denoising (Noise2Void) with 3DGS [S5]. It sets itself apart from supervised methods by requiring no paired clean data, making it robust to non-Gaussian and time-varying noise in sparse view scenarios [S5]. Choose this when training data is sparse and noisy [S5].

### Model-based depth estimation for volume parameter update
During optimization, depth values $z$ are extracted from the current scene estimate using $z = \frac{\sum_{i=1}^M d_i \alpha_i T_i}{\sum_{i=1}^M \alpha_i T_i}$ and used to update medium-parameter estimates ($B_\infty, B_b$) for volumetric rendering [S6]. This is used in physics-based extensions like underwater rendering [S6].

### Multi-Scale Constraint
A technique using position-aware point adaptive control to apply different scales to Gaussians based on viewer distance, improving rendering of distant objects [S7]. It sets itself apart from standard densification by scaling thresholds by $\gamma(\mu)$, which depends on the distance from the camera center [S7]. Choose this for large-scale scenes with varying distances [S7].

### LS-Gaussian Viewpoint Transformation
An algorithm that leverages inter-frame continuity for efficient sparse rendering by transforming the viewpoint between consecutive frames, rather than rendering each frame separately [S8]. It sets itself apart from naive pixel warping by operating at the tile/Gaussian level to reduce preprocessing and sorting costs [S8]. Pitfall: Rendering quality degrades as the number of consecutively transformed frames increases due to interpolation error accumulation [S8]. Usage: Used in LS-Gaussian to enable sparse rendering where only one frame in every 6 frames is fully rendered [S8].

### LS-Gaussian Accelerator Architecture
A hardware architecture co-designed with the LS-Gaussian algorithm to support workload-aware mapping, featuring a streaming pipeline that allows continuous processing across hardware modules without requiring global synchronization [S8]. It sets itself apart from naive tile assignment by predicting workload for each tile to mitigate inter-block idling and intra-block bubbles [S8].

### GS-IR (Gaussian Splatting for Internal Rendering)
A plane-based internal rendering framework that replaces exterior-view supervision with cross-sectional supervision sampled from a volume to reconstruct internal volumetric structure [S9]. It sets itself apart from conventional 3DGS by focusing optimization gradients on interior Gaussians to supervise occluded internal regions [S9]. Usage: Applied to 3DGS, 2DGS, and Mip-Splatting without modifying their rasterizers [S9].

### 3D Gaussian Splatting Training Loop
The core training process involves picking one input photo, rendering the current set of Gaussians, comparing the render against the original photo pixel-by-pixel to compute an error metric (L1 + D-SSIM), and using the error to compute gradients and nudge every Gaussian's parameters [S10, unofficial]. It sets itself apart from random search or Monte Carlo methods by using gradient descent to compute the actual downhill direction for the error surface, allowing millions of parameters to be corrected simultaneously and purposefully [S10, unofficial].

### Camera Localisation for Convergence Basin
Localize camera pose by minimizing only the photometric error against the ground-truth colour image of the target view, fixing the initial Gaussians $G_{init}$ during optimization [S11, unofficial]. The estimated pose $T_{CW}^{est}$ is found by $\mathbf{T}_{CW}^{est} = \underset{\mathbf{T}_{CW}}{\arg \min} \left\| I(\mathcal{G}_{init}, \mathbf{T}_{CW}) - \bar{I}_{target} \right\|_1$ [S11, unofficial].

### Sensitivity-Aware Vector Clustering for 3DGS Compression
A compression method that groups Gaussian colors and shape parameters into codebooks using sensitivity-aware vector clustering and quantization-aware training [S12]. It sets itself apart from simple quantization by using sensitivity $S(p)$ to guide clustering, where $S(p)$ is calculated by evaluating the change in image quality to changes of a parameter $p$ [S12].

### Relightable 3D Gaussians
A differentiable point-based rendering framework that enhances vanilla 3D Gaussians by associating extra properties (normal vectors, BRDF parameters, and incident lighting) to achieve photo-realistic relighting and BRDF decomposition from multi-view images [S13]. It sets itself apart from standard 3DGS by modeling per-point light reflectance using physically based rendering (PBR) [S13].

### Normal Gradient Based Densification
A densification criterion to improve normal recovery in thin regions by introducing an additional densification criterion on the gradient of normals, beyond the vanilla 3DGS gradient of view space points [S13]. It sets itself apart by densifying Gaussians whose normal gradient exceeds a threshold $T_n$ (typically $2 \times 10^{-9}$) [S13].

### Normal Estimation via Back-propagation
A method to solve for the normal attribute $n$ for each 3D Gaussian by optimizing it from an initial random vector via back-propagation, perceiving the depth of all Gaussians along a ray as a distribution [S13]. It sets itself apart by estimating the normal for each pixel by estimating the expectation of the depth distribution along the ray [S13].

## Operating characteristics

*   **Time Complexity:** The training loop is $O(N \cdot M)$ per iteration, where $N$ is the number of pixels and $M$ is the number of Gaussians. The rasterization step is typically $O(M \log M)$ due to sorting, but can be optimized to $O(M)$ with bucket sorting [S1].
*   **Memory Complexity:** $O(M)$ to store Gaussian parameters. For large scenes, memory management techniques like out-of-core processing or sharding may be required [S15108-distributed-training-and-sharding.md].
*   **Measured Performance:** On a Jetson AGX Orin, LS-Gaussian achieves 5.41x speedup over edge GPU baseline and up to 17.3x speedup with a customized accelerator, achieving real-time rendering at 90 FPS [S8].
*   **Strengths:** Real-time rendering, high-quality novel view synthesis, explicit scene representation.
*   **Limitations:** High memory usage for large scenes, sensitivity to camera distribution for scene extent, difficulty in representing thin structures without normal gradient densification.
*   **When to use:** When real-time rendering is required, and high-quality novel view synthesis is needed.
*   **When not to use:** When memory is severely constrained and compression techniques are not sufficient, or when the scene has extreme occlusions that are not handled by internal rendering methods.

## Background

3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1][S10, unofficial]. It represents scenes as a set of 3D Gaussians optimized via differentiable rasterization. The method has since been extended to handle various scenarios including blur [S4], noise [S5], internal structures [S9], and large-scale scenes [S7]. The `gsplat` library [S2] and `tiny-cuda-nn` [S1] are key implementation tools.
