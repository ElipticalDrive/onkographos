# Atomized Proliferation

Also called: Atom Gaussian Densification

## Overview
Atomized Proliferation is a training optimization strategy for 3D Gaussian Splatting that enhances geometric precision by constraining Gaussians representing fine details into "Atom Gaussians" (isotropic spheroids with uniform size) and prioritizing their proliferation to align with scene geometry [S1, unofficial]. Unlike standard 3D Gaussian Splatting, which struggles to stabilize densification and often produces noisy meshes or blurry artifacts, Atomized Proliferation uses a warm-up strategy that aggressively densifies initially, then merges large smooth surfaces, leading to a declining and stabilizing trend in Gaussian count [S1, unofficial]. It builds on [Gaussian Representation and Truncation](12855-gaussian-representation-and-truncation.md) by introducing specific constraints on scale isotropy and a geometry-guided proliferation schedule.

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of $N$ 3D Gaussians (defined by position $\mu$, covariance $\Sigma$, color $c$, opacity $\alpha$), input Structure-from-Motion (SfM) points, and hyperparameters: Clone Threshold $\tau_c$, Split Threshold $\tau_s$, Prune Threshold $\varepsilon$, Atom Scale $S$, Atomized Proliferation Duration $t_a$, and Warm-Up Duration $t_w$.
*   **Outputs:** An optimized set of Gaussians where fine details are represented by isotropic Atom Gaussians and smooth surfaces are merged into larger primitives.

**Data Structures and Parameters:**
*   **Atom Scale ($S$):** Defined as the $i$-th percentile of ordered distances from input SfM points, denoted $S = P_i(d)$. Typically, $i=1$ (first percentile) is used for general scenes, but $i=10$ may be used for object-centered datasets like DTU [S1, unofficial].
*   **Atom Gaussian:** A Gaussian designated as an Atom Gaussian has its scale fixed to an isotropic value $s = \sqrt[3]{S}$ (where $s_1=s_2=s_3$) and is no longer optimized via backpropagation for scale [S1, unofficial].
*   **Hyperparameters:**
    *   $\tau_c = 0.002$ (Clone Threshold) [S1, unofficial].
    *   $\tau_s = 0.002$ (Base Split Threshold) [S1, unofficial].
    *   $\varepsilon = 0.005$ (Prune Threshold, opacity cutoff); for DTU dataset, $\varepsilon = 0.5$ [S1, unofficial].
    *   $t_a = 7000$ (Atomized Proliferation Duration) [S1, unofficial].
    *   $t_w = 7000$ (Warm-Up Duration) [S1, unofficial].

**Algorithm Steps:**
The algorithm iterates through all Gaussians in the set $(M, S, C, A)$ representing mean, covariance, color, and opacity [S1, unofficial]. For each Gaussian $g_i$ at iteration $i$:

1.  **Pruning:** If the opacity $\alpha < \varepsilon$ OR the covariance $\Sigma$ is excessively large (determined by a helper function `IsTooLarge`), the Gaussian is pruned [S1, unofficial].
2.  **Cloning:** If the loss gradient with respect to the pixel $\nabla_p L \ge \tau_c$, the Gaussian is cloned to bridge geometry gaps [S1, unofficial].
3.  **Splitting:** If $\nabla_p L \ge \min\left(\frac{i}{t_w}\tau_s, \tau_s\right)$ AND the maximum norm of the covariance $\|\Sigma\|_{\max} > S$, the Gaussian is split. This condition applies during the warm-up phase ($i < t_w$) using a linearly increasing threshold to enhance the probability of division into smaller Atom Gaussians [S1, unofficial].
4.  **Atomization:** If the minimum norm of the covariance $\|\Sigma\|_{\min} \le S$ AND the current iteration $i < t_a$, the Gaussian is designated as an Atom Gaussian. Its scale is set to $s = \sqrt[3]{S}$ and fixed. Subsequent scale updates follow a geometric progression $S_n = S_{n-1} \cdot r^{n-1}$, where $r = \sqrt[t_a]{p}$ and $p$ is the final proportion to the initial $S$, ensuring the atom scale decreases over iterations to refine fine details [S1, unofficial].

**Pseudocode:**
```python
def atomized_proliferation(gaussians, sfm_points, tau_c, tau_s, epsilon, ta, tw):
    # Calculate Atom Scale S from SfM points
    distances = compute_ordered_distances(sfm_points)
    S = percentile(distances, i=1) # Default i=1, use i=10 for DTU
    
    for i in range(total_iterations):
        for g in gaussians:
            # 1. Pruning
            if g.opacity < epsilon or is_too_large(g.covariance):
                remove_gaussian(g)
                continue
            
            # 2. Cloning
            if g.loss_gradient >= tau_c:
                clone_gaussian(g)
                
            # 3. Splitting
            # Dynamic threshold during warm-up phase
            if i < tw:
                split_threshold = min((i / tw) * tau_s, tau_s)
            else:
                split_threshold = tau_s
                
            if g.loss_gradient >= split_threshold and max_norm(g.covariance) > S:
                split_gaussian(g)
                
            # 4. Atomization
            if min_norm(g.covariance) <= S and i < ta:
                atomize_gaussian(g, S)
```

**Edge Cases and Pitfalls:**
*   **Dataset Specifics:** For object-centered datasets like DTU, the Prune Threshold $\varepsilon$ should be increased to 0.5, and the Atom Scale $S$ should be calculated using the 10th percentile ($P_{10}$) of SfM distances [S1, unofficial].
*   **Scale Learning Rate:** When working with object-centered datasets lacking extensive backgrounds, the scale learning rate $\eta_s$ should be set to 0 to maximize geometric accuracy [S1, unofficial].
*   **Warm-up Phase:** The linear warm-up of the split threshold is critical during the initial phase ($i < t_w$) to ensure aggressive densification into Atom Gaussians before merging begins [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The method adds overhead for calculating SfM distances and checking covariance norms, but the aggressive pruning and merging of smooth surfaces reduce the final Gaussian count compared to standard 3DGS. On the Mip-NeRF360 dataset, AtomGS achieves an average training time of 0.28 hours compared to 0.40 hours for standard 3DGS [S1, unofficial].
*   **Memory Complexity:** The final model size is reduced. On Mip-NeRF360, AtomGS results in a model size of 749MB compared to 869MB for standard 3DGS [S1, unofficial].
*   **Strengths:** Enhances geometric precision, reduces noisy meshes and blurry artifacts, and stabilizes Gaussian proliferation with a declining trend in count [S1, unofficial].
*   **Limitations:** Requires input SfM points to calculate Atom Scale. The geometric progression for Atom Gaussian scales is a simplified model of detail refinement [S1, unofficial].

## Background
Atomized Proliferation was proposed in the paper "AtomGS: Atomizing Gaussian Splatting for High-Fidelity Radiance Field" by Liu, Xu, Hu, Chen, and Feng [S1, unofficial]. It addresses issues in standard 3D Gaussian Splatting where Gaussians may not adhere to underlying geometric structures, leading to noisy meshes and slower convergence. The method introduces a two-part approach: Atomized Proliferation for fine details and geometry-guided optimization for smooth surfaces [S1, unofficial].
