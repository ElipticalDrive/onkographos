# Inner 3D Gaussian Splatting

Also called: Inner Gaussian Splatting, InnerGS

## Overview
Inner 3D Gaussian Splatting (InnerGS) is a framework for direct volumetric inference that models continuous volumetric density using 3D Gaussians to reconstruct internal structures from sparse, pose-free sliced data [S1, unofficial]. It solves the problem of reconstructing internal volumes where camera poses are unavailable and standard projection-based rendering fails because learned Gaussians concentrate on surfaces, leaving the interior empty [S1, unofficial]. It sets itself apart from standard 3D Gaussian Splatting by eliminating the need for camera parameters (view/projection matrices) and using a slice-based rendering pipeline with Conditional Splatting, which adapts the bounding box per slice based on conditional Gaussians, unlike sibling methods like 3D Ellipsoid Projection that compute a cube and project identical bounding boxes across slices [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Sparse, pose-free sliced data (2D slices at various depths). No camera poses or projection matrices are required.
*   **Outputs:** A 3D Gaussian representation of the internal volume, enabling reconstruction of smooth and detailed internal structures. The final output is a rendered image $I(u, v, t)$ for a specific slice at depth $t$.

**Data Structures:**
The scene is represented as a cloud of 3D Gaussians. Each Gaussian $i$ is defined by:
*   **Position:** $\mu = (\mu_x, \mu_y, \mu_z) \in \mathbb{R}^3$, defining the center.
*   **Covariance:** $\Sigma \in \mathbb{R}^{3 \times 3}$, decomposed into scaling $S$ and rotation $R$: $\Sigma = RSS^\top R^\top$.
    *   $S$ is a diagonal matrix with scale factors $s_x, s_y, s_z$.
    *   $R$ is derived from a unit quaternion $q$ encoding rotation.
*   **Opacity:** $\alpha_i \in [0, 1]$.
*   **Color:** $c_i$, modeled using Spherical Harmonics (SH) coefficients to capture view-dependent variations.

**Method Steps:**
1.  **Conditional Splatting:** For each depth slice $t$, compute conditional 2D Gaussian splats. This determines the 2D Gaussian center and influence radii in the image plane for that specific slice [S1, unofficial]. This step adapts the bounding box per slice based on these conditional Gaussians [S1, unofficial].
2.  **3D Gaussian Formulation:** Combine the conditional 2D Gaussians with a marginal 1D Gaussian along the depth axis to formulate the complete 3D Gaussian Splatting (3DGS) density [S1, unofficial]. This allows the representation to capture continuous volumetric information between slices.
3.  **Rendering:** Perform tile-based rasterization using the formulated 3DGS density. The final color of a pixel at coordinates $(u, v)$ on a slice at depth $t$ is computed using front-to-back alpha compositing [S1, unofficial]:
    $$
    I(u, v, t) = \sum_{i=1}^{N} p_i(u, v, t)\alpha_i c_i \prod_{j=1}^{i-1} (1 - p_j(u, v, t)\alpha_j)
    $$
    where $N$ is the total number of Gaussians, $p_i(u, v, t)$ is the density of the $i$-th splat at pixel $(u, v)$ for slice $t$, $\alpha_i$ is opacity, and $c_i$ is color. Pixel coordinates satisfy $u \in [0, W - 1]$ and $v \in [0, H - 1]$ for an image of width $W$ and height $H$ [S1, unofficial].

**Pseudocode:**
```python
def inner_gs_render(slices, gaussians, depth_t):
    """
    Renders a single slice at depth t using InnerGS.
    
    Args:
        slices: List of 2D slices (pose-free data).
        gaussians: List of 3D Gaussian objects, each with:
                   - mu: (mu_x, mu_y, mu_z)
                   - S: diagonal scale factors (sx, sy, sz)
                   - q: unit quaternion for rotation R
                   - alpha: opacity
                   - sh_coeffs: Spherical Harmonics coefficients for color
        depth_t: The current depth slice index/coordinate.
        
    Returns:
        Image I(u, v) for the slice at depth_t.
    """
    W, H = get_image_dimensions(slices)
    image = zeros((H, W, 3))
    
    # Step 1 & 2: Formulate 3DGS density for the current slice
    # This involves computing conditional 2D splats and combining with marginal 1D Gaussian
    # The result is a set of effective 2D Gaussians projected onto the image plane for slice t
    effective_2d_gaussians = []
    
    for g in gaussians:
        # Compute conditional 2D Gaussian center and influence radii for slice t
        # This adapts the bounding box per slice based on conditional Gaussians
        # [G] Implementation detail: Project 3D Gaussian to 2D plane at depth t
        # without camera matrices, using the marginal 1D Gaussian along depth.
        center_2d, cov_2d = compute_conditional_splat(g.mu, g.S, g.q, depth_t)
        
        # Combine with marginal 1D Gaussian to get density p_i(u, v, t)
        # [G] The density p_i is derived from the 2D Gaussian covariance and the 
        # marginal depth distribution.
        density_func = lambda u, v: gaussian_density(u, v, center_2d, cov_2d)
        
        # Get color from SH coefficients
        color = evaluate_sh(g.sh_coeffs, view_direction) # [G] View direction assumed or fixed for slice
        
        effective_2d_gaussians.append({
            'density': density_func,
            'alpha': g.alpha,
            'color': color
        })
    
    # Step 3: Tile-based rasterization (front-to-back compositing)
    # Sort Gaussians by depth or density contribution if necessary
    # Standard 3DGS sorts by depth; here, since it's a slice, sorting might be implicit
    # or based on the marginal 1D Gaussian contribution.
    
    for v in range(H):
        for u in range(W):
            accumulated_color = zeros(3)
            accumulated_alpha = 0.0
            
            for g in effective_2d_gaussians:
                p = g['density'](u, v)
                alpha = g['alpha']
                color = g['color']
                
                # Contribution: p * alpha * color
                # Transmittance: product of (1 - p_j * alpha_j) for previous j
                
                # Note: The formula uses p_i(u,v,t) * alpha_i. 
                # In standard 3DGS, p_i is the 2D density. Here p_i(u,v,t) is the 
                # density at pixel (u,v) for slice t.
                
                weight = p * alpha
                transmittance = 1.0 - accumulated_alpha
                
                accumulated_color += weight * color * transmittance
                accumulated_alpha += weight * transmittance
                
                # Early exit if fully opaque
                if accumulated_alpha >= 1.0 - 1e-5:
                    break
            
            image[v, u] = accumulated_color
            
    return image
```

**Parameters:**
*   **Pixel Coordinates:** $u \in [0, W - 1]$, $v \in [0, H - 1]$ [S1, unofficial].
*   **Position Vector:** $\mu = (\mu_x, \mu_y, \mu_z)$ [S1, unofficial].
*   **Covariance Decomposition:** $\Sigma = RSS^\top R^\top$, where $S = \text{diag}(s_x, s_y, s_z)$ and $R$ from unit quaternion $q$ [S1, unofficial].
*   **Opacity:** $\alpha$ [S1, unofficial].
*   **Color:** Spherical Harmonics (SH) coefficients [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Surface Concentration:** Standard 3DGS projection-based mechanisms fail for internal volumetric structures because learned Gaussians concentrate on the object's surface, leaving the interior volume empty [S1, unofficial]. InnerGS addresses this by modeling continuous volumetric density.
*   **Missing Camera Poses:** Standard 3DGS relies on camera parameters (view/projection matrices) which are absent in sliced data. InnerGS eliminates this need [S1, unofficial].
*   **Sparse Slices:** Applying original 3DGS to sparse slices fails to capture continuous volumetric information between slices. InnerGS uses marginal 1D Gaussians to bridge this gap [S1, unofficial].

## Background
Inner 3D Gaussian Splatting (InnerGS) was proposed to address the limitations of Neural Radiance Fields (NeRF) and standard 3D Gaussian Splatting in modeling internal scenes. NeRF requires heavy multi-layer perceptrons, making it costly to train and slow to render [S1, unofficial]. Standard 3DGS, while fast, is projection-based and relies on camera parameters, making it unsuitable for internal volumetric structures from pose-free data [S1, unofficial]. InnerGS was introduced as a novel method specifically designed for modeling internal scenes, employing 3D Gaussian density instead of traditional projection-based 2D Gaussian rendering [S1, unofficial]. It was presented in the paper "InnerGS: Internal Scenes Reconstruction and Segmentation via Factorized 3D Gaussian Splatting" [S1, unofficial].
