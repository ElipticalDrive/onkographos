# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, GSGEN Implementation Details, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific implementation parameters, optimization strategies, and variant algorithms used to train and render 3D Gaussian Splatting (3DGS) scenes. It addresses the practical challenges of differentiable rasterization, including half-precision stability, adaptive density control, and handling of specific scene properties like defocus blur or sparse views. It sets itself apart from general optimization theory by providing concrete thresholds, library choices (e.g., `gsplat`, `torchsparse`), and specific algorithmic modifications for variants like DeSplat, Denoise-GS, and LS-Gaussian.

## How it works

### Inputs and Outputs
*   **Inputs**: Initial 3D point cloud from Structure-from-Motion (SfM), camera poses, input images, and hyperparameters (learning rate, densification intervals, thresholds).
*   **Outputs**: Optimized set of 3D Gaussians (position $\mu$, covariance $\Sigma$ or scale $s$ and rotation $R$, opacity $\alpha$, spherical harmonic coefficients $c_{lm}$).

### Data Structures
*   **Gaussian Attributes**: Stored in contiguous arrays or structures of arrays (SoA) for cache efficiency during rasterization. Fields typically include:
    *   Position: $\mathbb{R}^3$
    *   Scale: $\mathbb{R}^3$ (log-space for optimization)
    *   Rotation: $\mathbb{R}^4$ (quaternion)
    *   Opacity: $\mathbb{R}$ (sigmoid output)
    *   SH Coefficients: $\mathbb{R}^{3 \times (L+1)^2}$ for degree $L$.
*   **Scene Extent**: Used for normalization and densification thresholds. Default 3DGS calculates extent based on camera positions, but variants use corrected methods [S4].

### Training Loop and Optimization Steps

1.  **Initialization**:
    *   Initialize Gaussians from SfM points.
    *   Set initial opacity low (e.g., 0.1) to allow gradual growth [S1][S15, unofficial].
    *   For large-scale scenes, define volume dimensions. Example: Height 12.8m, Width 32m, Length 64m, with voxel size 0.1m, resulting in a volume dimension of $128 \times 320 \times 640$ [S3].

2.  **Forward Pass (Rasterization)**:
    *   Project 3D Gaussians to 2D screen space using camera intrinsics and extrinsics.
    *   Sort Gaussians by depth for each tile/pixel.
    *   Alpha-blend colors using spherical harmonics for view-dependent appearance.
    *   **Half-Precision**: Use half-precision (FP16) memory fetches on feature vectors during rasterization for both forward and backward kernels to reduce register pressure [S2]. Apply an automatic scaling factor to loss values to improve half-precision training stability [S2].

3.  **Loss Computation**:
    *   Compute photometric loss between rendered image $\hat{C}$ and ground truth $C$.
    *   Common loss function:
        $$ \mathcal{L} = \lambda \cdot \text{MSE}(C, \hat{C}) + (1 - \lambda) \cdot \text{SSIM}(C, \hat{C}) $$
        where $\lambda$ balances the terms [S13, unofficial].
    *   For specific variants, additional losses may apply (e.g., perceptual loss in Denoise-GS [S6], frequency regularization in FreGS [S15, unofficial]).

4.  **Backward Pass**:
    *   Compute gradients $\frac{\partial \mathcal{L}}{\partial \theta}$ with respect to Gaussian parameters.
    *   Accumulate gradients.

5.  **Optimizer Update**:
    *   Use Adam optimizer with learning rate $1 \times 10^{-3}$ [S3].
    *   Update parameters.

6.  **Adaptive Density Control (Densification)**:
    *   Performed periodically (e.g., every 100–1000 iterations).
    *   **Splitting**: Split Gaussians with high positional gradient magnitude. Threshold $T_{pos} = 0.02$ for view-space position gradient every 500 iterations [S1].
    *   **Cloning**: Clone Gaussians with high scale but low gradient to increase density in flat regions.
    *   **Pruning**: Remove Gaussians with opacity $\alpha < \alpha_{min} = 0.05$ and excessively large world-space or view-space radius every 200 iterations [S1].
    *   **Corrected Scene Extent**: To avoid bias from camera distribution, calculate scene extent $e'_{\text{scene}}$ based on SfM points:
        $$ e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2 $$
        where $\bar{C} = \frac{1}{N_{\text{cam}}} \sum_{i=1}^{N_{\text{cam}}} C_i$ is the average camera position [S4].

### Pseudocode: Standard Training Loop with Densification

```python
# Initialization
gaussians = initialize_from_sfm(points)
optimizer = Adam(gaussians.parameters(), lr=1e-3)
iteration = 0

while iteration < max_iterations:
    # 1. Select random view
    view = random.choice(training_views)
    
    # 2. Forward Pass
    rendered_image = rasterize(gaussians, view.camera)
    
    # 3. Loss Computation
    loss = compute_loss(rendered_image, view.gt_image)
    
    # 4. Backward Pass
    optimizer.zero_grad()
    loss.backward()
    
    # 5. Optimizer Step
    optimizer.step()
    
    # 6. Densification (every 100 iterations)
    if iteration % 100 == 0:
        # Compute gradients for densification
        compute_gradient_accumulation(gaussians)
        
        # Splitting
        high_grad_mask = gaussians.position_gradient > T_pos
        gaussians = split_gaussians(gaussians, high_grad_mask)
        
        # Cloning
        high_scale_low_grad_mask = (gaussians.scale > threshold_scale) & (gaussians.position_gradient < threshold_grad)
        gaussians = clone_gaussians(gaussians, high_scale_low_grad_mask)
        
        # Pruning
        low_opacity_mask = gaussians.opacity < alpha_min
        gaussians = prune_gaussians(gaussians, low_opacity_mask)
        
    iteration += 1
```

### Edge Cases and Pitfalls
*   **Scene Extent Bias**: Default 3DGS scene extent calculation based on camera positions can be biased if cameras are clustered (e.g., orbiting a small object), leading to incorrect splitting/pruning [S4]. Use corrected scene extent [S4].
*   **Half-Precision Stability**: FP16 training can suffer from overflow/underflow. Apply loss scaling [S2].
*   **Defocus Blur**: Standard 3DGS assumes sharp images. For blurred images, predict per-Gaussian scale offsets $\delta s_j$ to enlarge covariances, creating pixel-wise variable blur kernels [S5]. If $\delta s_j$ is constant, it degrades to uniform blur [S5].
*   **Sparse Views**: Standard 3DGS struggles with sparse views. Use self-supervised denoising (e.g., Noise2Void) before initialization [S6].
*   **Aliasing**: Use adaptive 2D low-pass filters based on rendering resolution and camera distance [S15, unofficial].

## Subtopics

### Corrected Scene-Extent
A method to calculate scene extent based on the SfM point cloud rather than camera positions to avoid bias from camera distribution (e.g., orbiting a small object in a large environment). It sets itself apart from standard 3DGS by using $e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2$. Choose it when camera positions are not representative of the full scene volume. [Corrected Scene-Extent](12926-corrected-scene-extent.md)

### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ to selectively enlarge covariances, creating pixel-wise variable blur kernels that match spatially varying scene blurriness. It sets itself apart from naive Gaussian blur by allowing spatially varying blur shapes and magnitudes. Choose it for scenes with defocus blur. [Selective Defocus Blurring](12927-selective-defocus-blurring.md)

### Denoise-GS
A self-supervised denoising method for sparse-view 3D Gaussian Splatting that combines unsupervised image denoising (Noise2Void) with 3DGS. It sets itself apart from supervised methods by requiring no paired clean data and being robust to non-Gaussian noise. Choose it for sparse and noisy scenes. [Denoise-GS](12928-denoise-gs.md)

### Multi-Scale Constraint
A technique using position-aware point adaptive control to apply different scales to Gaussians based on viewer distance, improving rendering of distant objects. It sets itself apart from standard 3DGS by using a distance-dependent scaling factor $\gamma(\mu)$. Choose it for large-scale scenes with varying distances. [Multi-Scale Constraint](12929-multi-scale-constraint.md)

### LS-Gaussian Viewpoint Transformation
An algorithm that leverages inter-frame continuity for efficient sparse rendering by transforming the viewpoint between consecutive frames, rather than rendering each frame separately. It sets itself apart from naive pixel warping by operating at the tile/Gaussian level. Choose it for real-time rendering of continuous camera trajectories. [LS-Gaussian Viewpoint Transformation](12930-ls-gaussian-viewpoint-transformation.md)

### Camera Localisation for Convergence Basin
Localizes camera pose by minimizing photometric error against ground-truth color image, fixing initial Gaussians during optimization. It sets itself apart by using a fixed Gaussian set for pose estimation. Choose it for camera re-localization tasks. [Camera Localisation for Convergence Basin](12931-camera-localisation-for-convergence-basin.md)

### DiffGS Framework
Applies an optimization process during Gaussian extraction to optimize Gaussians to exact locations, using a truncation function $\lambda$ and projection function $\tau$. It sets itself apart by modeling Gaussian Probability Function (GauPF). Choose it for high-fidelity reconstruction. [DiffGS Framework](12932-diffgs-framework.md)

### Opacity Offset Table for DSA
Constructs an opacity offset table to model changes in digital subtraction angiography. It sets itself apart by handling dynamic opacity changes. Choose it for medical imaging applications. [Opacity Offset Table for DSA](12933-opacity-offset-table-for-dsa.md)

### Conditional Splat Approximation
Approximates the influence range of a 3D Gaussian on a slice by using a 2D ellipse splat scaled by the marginal factor. It sets itself apart by providing an accurate and efficient approximation of 3D Gaussian iso-probability contours. Choose it for slice-based rendering or tomographic reconstruction. [Conditional Splat Approximation](12934-conditional-splat-approximation.md)

### PyGS Optimization
Uses a combined MSE and SSIM loss, along with density control strategies adapted from 3DGS, while preserving the multi-scale structure. It sets itself apart by retaining newly split/cloned Gaussians in their original level and cluster. Choose it for large-scale scene representation. [PyGS Optimization](12935-pygs-optimization.md)

### GAINS (Gaussian-based Inverse Rendering from Sparse multi-view captures)
A two-stage inverse rendering framework that leverages foundation model priors to stabilize geometry and material estimation from sparse multi-view RGB captures [S14]. It sets itself apart by using 2DGS for more accurate geometry reconstruction [S14]. Choose it for inverse rendering from sparse views [S14]. [GAINS](12936-gains.md)

### SAGS (Adaptive Gaussian Splatting)
Utilizes an adaptive 2D low-pass filter at inferencing time based on rendering resolution and camera distance to handle aliasing [S15, unofficial]. It sets itself apart from standard 3DGS by dynamically adjusting filtering [S15, unofficial]. Choose it for aliasing-free rendering [S15, unofficial]. [SAGS](12937-sags.md)

### Frequency Gaussian Splatting
Applies frequency-domain regularization to the rendered 2D image to encourage recovery of high-frequency detail, resolving blurring issues. It sets itself apart by operating in the frequency domain. Choose it for scenes with high-frequency details. [Frequency Gaussian Splatting](12938-frequency-gaussian-splatting.md)

### Neural Illumination Enhancement
A neural module applied only to non-Lambertian regions to model view-dependent highlights and handle non-Lambertian effects that vanilla 3DGS struggles with. It sets itself apart by using a lightweight MLP to predict a view-dependent color residual. Choose it for scenes with specular highlights. [Neural Illumination Enhancement](12939-neural-illumination-enhancement.md)

### GraphiGS
A variant of the GraphiXS framework where the component distribution is modeled as a 3D Gaussian primitive, providing compact spatial support and exponential density decay. It sets itself apart by using Gaussian primitives for uncertainty modeling. Choose it for 4D Gaussian Splatting under uncertainty. [GraphiGS](12940-graphigs.md)

### TRIPS
Attaches a neural feature to Gaussians and renders pyramid-like image feature planes according to the projected Gaussian’s size, similar to ADOP, to resolve blurring issues. It sets itself apart by using neural features for detail recovery. Choose it for high-fidelity rendering. [TRIPS](12941-trips.md)

## Operating characteristics

### Time and Memory Complexity
*   **Time**: Rasterization is $O(N)$ where $N$ is the number of Gaussians, but sorting adds overhead. Training time is dominated by the number of iterations and densification steps.
*   **Memory**: Scales linearly with the number of Gaussians. Each Gaussian stores position, scale, rotation, opacity, and SH coefficients. Half-precision can reduce memory usage by half [S2].

### Measured Performance
*   **Hardware**: Performance varies by GPU. LS-Gaussian achieves 5.41× speedup over edge GPU baseline on Jetson AGX Orin [S8].
*   **Resolution**: Performance degrades with higher resolution due to increased rasterization cost. Adaptive methods like SAGS help mitigate aliasing at different resolutions [S15, unofficial].
*   **Scene**: Large-scale scenes require hierarchical or multi-scale approaches (e.g., PyGS [S13, unofficial], Multi-Scale Constraint [S7]) to maintain efficiency.

### Scaling
*   **Gaussian Count**: Densification increases Gaussian count, improving fidelity but increasing memory and compute. Pruning removes redundant Gaussians [S1].
*   **Resolution**: Higher resolution requires more Gaussians to maintain detail. Frequency-guided schedulers can optimize this [15751-frequency-guided-resolution-scheduler.md].

### Strengths and Limitations
*   **Strengths**: Real-time rendering, high fidelity, explicit representation.
*   **Limitations**: Sensitive to initialization, struggles with sparse views and noise without variants, high memory usage for large scenes.

### When to Use and When Not
*   **Use**: Real-time rendering, high-fidelity reconstruction, scenes with sufficient views.
*   **Not Use**: Sparse views without denoising variants, scenes with extreme defocus without selective blurring variants, memory-constrained environments without compression variants.

## Background

### Origin
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1, S2]. It builds on the idea of differentiable rasterization of 3D Gaussians.

### History and Development
Since its introduction, many variants have been developed to address specific limitations, such as sparse views (Denoise-GS [S6]), defocus blur (Selective Defocus Blurring [S5]), and large-scale scenes (PyGS [S13, unofficial], Multi-Scale Constraint [S7]).

### Where it is Used
3DGS is used in computer graphics, robotics, and augmented reality for real-time rendering and reconstruction.
