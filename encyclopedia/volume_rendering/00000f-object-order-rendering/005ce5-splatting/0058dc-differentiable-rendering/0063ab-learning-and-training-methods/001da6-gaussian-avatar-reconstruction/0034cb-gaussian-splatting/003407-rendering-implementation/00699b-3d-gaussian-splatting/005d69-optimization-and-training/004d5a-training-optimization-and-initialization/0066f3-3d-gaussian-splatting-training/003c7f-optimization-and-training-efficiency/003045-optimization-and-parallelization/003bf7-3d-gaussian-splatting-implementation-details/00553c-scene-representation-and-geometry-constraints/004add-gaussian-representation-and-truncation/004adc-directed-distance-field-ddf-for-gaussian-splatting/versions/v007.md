# Directed Distance Field (DDF) for Gaussian Splatting

Also called: Directed Distance Function, ray-query oracle

## Overview
The Directed Distance Field (DDF) is a neural implicit representation that serves as a constant-time, constant-memory ray oracle for 3D Gaussian Splatting (3DGS) scenes [S1, unofficial]. It maps a ray origin and direction to the distance to the first surface and a visibility probability, enabling efficient computation of secondary rays for shadows, ambient occlusion, and global illumination without requiring a mesh or iterative sphere tracing [S1, unofficial]. Unlike Gaussian rasterization, which only answers camera-view queries, or BVH-based Gaussian tracing, which scales with scene size, the DDF provides flat latency and memory usage regardless of the number of Gaussians [S1, unofficial].

## How it works
The DDF is trained to approximate the geometric structure of a 3DGS scene by learning from distance supervision derived from the Gaussians or a neural surface. It replaces the need for explicit geometry traversal with a single forward pass through a compact neural network.

### Inputs and Outputs
*   **Input:** A ray defined by origin $\mathbf{x} \in \mathbb{R}^3$ and unit direction $\mathbf{d} \in S^2$.
*   **Output:** A tuple $(t, \xi)$, where $t \in \mathbb{R}^+$ is the distance to the first surface along $\mathbf{d}$, and $\xi \in [0, 1]$ is the visibility value (probability that the ray hits the scene) [S1, unofficial]. The hit point is $\mathbf{x} + t\mathbf{d}$ when $\xi$ is high [S1, unofficial].

### Data Structures
The DDF is implemented as a neural field with a fixed memory footprint of approximately 52 MB, independent of the scene size (number of Gaussians) [S1, unofficial].

1.  **Multiresolution Hash Grid (Point Encoding):**
    *   Encodes the 3D point $\mathbf{x}$.
    *   **Levels:** 16.
    *   **Features per level:** 2.
    *   **Entries per level:** $2^{19}$ (524,288).
    *   **Base resolution:** 16.
    *   **Growth factor:** 1.5.
    *   **Bounding Box:** A box bounding the normalized object [S1, unofficial].
    *   **Parameter Count:** $\approx 13$ million parameters [S1, unofficial].

2.  **Sinusoidal Encoding (Direction Encoding):**
    *   Encodes the direction $\mathbf{d}$.
    *   **Bands:** 4 sinusoidal bands [S1, unofficial].

3.  **Multi-Layer Perceptron (MLP):**
    *   **Architecture:** Two layers.
    *   **Width:** 64 neurons per layer.
    *   **Input:** Concatenated features from the hash grid and direction encoding.
    *   **Output:** Two scalars: distance $t$ and visibility $\xi$.
    *   **Parameter Count:** $\approx 8,000$ parameters [S1, unofficial].

### Training Procedure
The network is trained using a combination of distance and visibility targets derived from the 3DGS scene and/or a neural surface.

1.  **Data Generation:**
    *   **Primary Rays:** Sample rays from the camera frustum. Targets are obtained by rendering depth from the 3DGS scene [S1, unofficial].
    *   **Secondary Rays:** Sample rays anchored on the surface pointing in various directions. Targets are obtained by sphere tracing a neural surface (e.g., NeuS) fit to the same images, providing "clean" distance supervision [S1, unofficial].
    *   **Self-Consistency Samples:** For a ray hitting at distance $t$, sample a point shifted forward by distance $s$ along the ray. The target distance for this shifted point is $t - s$. This accounts for 30% of the training batch [S1, unofficial].

2.  **Loss Function:**
    The total loss $L$ is a weighted sum of clamped L1 loss on distance and Binary Cross-Entropy (BCE) on visibility:
    $$ L = \text{ClampedL1}(t_{pred}, t_{target}) + 0.3 \cdot \text{BCE}(\xi_{pred}, \xi_{target}) $$
    The L1 term is clamped to a maximum value (box scale) to prevent far-away surfaces from dominating the gradient [S1, unofficial].

3.  **Optimization:**
    *   **Optimizer:** Adam.
    *   **Batch Size:** 16,384 rays.
    *   **Learning Rate:** $3 \times 10^{-3}$, decayed by cosine schedule to 5% of initial value.
    *   **Steps:** 30,000 [S1, unofficial].

        """

                            # Standard positional encoding uses sin/cos. 
                            # Let's assume standard PE: 4 bands -> 8 dims.
        input_dim = hash_out_dim + 8
        
        self.mlp = nn.Sequential(
            nn.Linear(input_dim, mlp_width),
            nn.ReLU(),
            nn.Linear(mlp_width, mlp_width),
            nn.ReLU(),
            nn.Linear(mlp_width, 2) # Output: t, xi
        )

    def forward(self, x, d):
        """
        Query the DDF.
        
        Args:
            x: Ray origins, shape (N, 3).
            d: Ray directions, shape (N, 3).
            
        Returns:
            t: Distances, shape (N,).
            xi: Visibility probabilities, shape (N,).
        """
        # Encode point x
        x_features = self.hash_grid(x) # Shape (N, 32)
        
        # Encode direction d
        d_features = self.dir_encoding(d) # Shape (N, 8)
        
        # Join features
        combined = torch.cat([x_features, d_features], dim=-1) # Shape (N, 40)
        
        # MLP forward pass
        output = self.mlp(combined) # Shape (N, 2)
        
        t = output[:, 0]
        xi = torch.sigmoid(output[:, 1]) # Ensure xi is in [0, 1]
        
        return t, xi

    def compute_loss(self, t_pred, xi_pred, t_target, xi_target):
        """
        Compute the training loss.
        
        Args:
            t_pred: Predicted distances.
            xi_pred: Predicted visibility.
            t_target: Target distances.
            xi_target: Target visibility.
            
        Returns:
            loss: Scalar loss value.
        """
        # Clamped L1 loss on distance
        # Clamp to box scale. Assume box_scale is a hyperparameter.
        box_scale = 1.0 # Normalized object box scale
        l1_loss = torch.nn.functional.l1_loss(t_pred, t_target, reduction='none')
        l1_loss = torch.clamp(l1_loss, max=box_scale)
        l1_loss = l1_loss.mean()
        
        # BCE loss on visibility
        bce_loss = torch.nn.functional.binary_cross_entropy(xi_pred, xi_target)
        
        # Weighted sum
        loss = l1_loss + 0.3 * bce_loss
        return loss

        # Let's stick to the literal interpretation: 4 bands. 
        # If it's just sin, it's 4 dims. If it's sin/cos, it's 8.

        encoded = torch.cat([torch.sin(scaled_d), torch.cos(scaled_d)], dim=-1)
        # Shape: (N, 3, 8)
        # Flatten last two dims
        encoded = encoded.view(d.shape[0], -1)
        return encoded

### Querying (Inference)
1.  **Primary Ray:** Evaluate $f(\mathbf{x}, \mathbf{d})$ at the camera origin $\mathbf{x}$ and view direction $\mathbf{d}$ to get $t$ and $\xi$.
2.  **Shadow Ray:** Offset the surface point $\mathbf{p} = \mathbf{x} + t\mathbf{d}$ slightly along its normal $\mathbf{n}$. Evaluate $f(\mathbf{p} + \epsilon\mathbf{n}, \mathbf{d}_{light})$ toward the light source. If the returned distance $t_{shadow} < \text{distance to light}$, the point is in shadow [S1, unofficial].
3.  **Ambient Occlusion (AO):** Evaluate $f$ along a set of directions $\{\mathbf{d}_i\}$ over the hemisphere centered at the surface normal. Average the hit flags $\xi_i$. This requires a constant number of evaluations per ray [S1, unofficial].
4.  **Precision:** Inference uses reduced precision and a compiled forward pass (e.g., via `tinycudann`) to maximize speed [S1, unofficial].

### Edge Cases and Pitfalls
*   **Thin Features:** Supervising solely on 3DGS-rendered depth blurs thin parts (e.g., mug handles, animal legs) because soft Gaussians average narrow structures. Clean distance supervision (from sphere-traced neural surfaces or ray-casted meshes) is required to recover these features [S1, unofficial].
*   **Compact Objects:** For compact objects where Gaussian depth already captures geometry well, clean distance supervision may not help and can hurt if the neural surface point cloud is noisy, causing the reconstructed surface to "fatten" [S1, unofficial].
*   **Background Rays:** Learning directly from images (volume-rendering color loss) is ineffective because most sampled rays land on the background, providing a weak gradient signal for the distance output [S1, unofficial].
*   **Step-by-Step Tracing:** Supervising sequential ray-marching steps from images is unstable due to sequential gradient issues [S1, unofficial].
*   **Ray Origin Distribution:** The oracle is accurate primarily for ray origins on or near the surface. Rays starting far from the surface (e.g., on a ground plane below an object) may report false occlusion. Training with volumetric origins would extend coverage [S1, unofficial].
*   **Ambient Occlusion Quality:** AO quality (21.3 dB) is lower than shadow quality (30.3 dB) because averaging many rays accumulates small per-ray errors [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per ray query. The DDF requires a single forward pass regardless of the number of Gaussians $N$ [S1, unofficial].
*   **Memory Complexity:** $O(1)$ with respect to scene size. The DDF memory is fixed at ~52 MB [S1, unofficial].
*   **Performance:**
    *   **Speed:** 26 to 72 times faster than sphere tracing an equivalent Signed Distance Field (SDF) [S1, unofficial].
    *   **Scaling:** Unlike BVH-over-Gaussians, DDF latency is flat. BVH latency rises by ~9x from 5K to 1M Gaussians [S1, unofficial].
    *   **Comparison to BVH:** On small scenes (< few thousand Gaussians), RT-core BVH is faster per ray. At real scene scales (hundreds of thousands to millions of Gaussians), DDF becomes competitive or faster, especially with CUDA-fused kernels (0.005 µs vs 0.009 µs per ray at 1M Gaussians) [S1, unofficial].
    *   **Comparison to Rasterization:** For sparse queries (1K-10K rays), DDF is 600+ times faster than re-rasterizing. At full frame (1M rays), DDF ties rasterization (4.81 ms vs 4.45 ms) due to frame buffer write bounds [S1, unofficial].
*   **Quality:**
    *   **Shadows:** Reproduces reference ray-traced shadows at 30.3 dB [S1, unofficial].
    *   **Ambient Occlusion:** Reproduces reference AO at 21.3 dB [S1, unofficial].
    *   **Geometry:** Chamfer distance improves from 0.082 to 0.065 (21% drop) with clean distance supervision [S1, unofficial].
*   **Strengths:** Constant time and memory, no mesh required, no RT-core hardware dependency, supports arbitrary ray queries.
*   **Limitations:** AO quality is limited by error accumulation; accuracy degrades for ray origins far from the training surface distribution; mesh-free pipeline inherits smoothing errors from the source neural surface [S1, unofficial].

## Background
The Directed Distance Field for Gaussian Splatting was introduced to address the limitation of 3DGS rasterization, which cannot trace secondary rays for global illumination [S1, unofficial]. It builds on the multiresolution hash grid encoding technique from [8] (tinycudann) [S1, unofficial]. The method was developed to provide a mesh-free, scalable oracle for global illumination in differentiable rendering pipelines [S1, unofficial].
