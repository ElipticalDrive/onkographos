# 3D Gaussian Splatting Implementation Details

Also called: 3DGS CUDA kernel implementation, GS Implementation Parameters, GSGEN Implementation Details, Gaussian Splatting Training Configuration, Implementation Details, gsplat implementation details, half-precision rasterization implementation

## Overview
This article details the specific hyperparameters, optimization schedules, and data structures required to implement the training and rendering pipeline of 3D Gaussian Splatting (3DGS). It addresses the problem of translating the theoretical differentiable rasterization into a stable, efficient software implementation. It sets itself apart from sibling articles by providing concrete numerical thresholds, iteration schedules, and memory management strategies (such as half-precision handling) rather than high-level architectural descriptions.

## How it works
The implementation relies on a differentiable rasterizer that renders images from a set of 3D Gaussians. The core optimization mechanism involves computing the gradient of a loss function $\mathcal{L}$ with respect to the Gaussian parameters (position, covariance, opacity, color, SH coefficients) and any auxiliary parameters.

### Inputs and Outputs
*   **Inputs:** A set of $N$ 3D Gaussians, each defined by position $\mathbf{p}$, covariance $\mathbf{\Sigma}$ (or scale $\mathbf{s}$ and rotation $\mathbf{q}$), opacity $\alpha$, spherical harmonic coefficients $\mathbf{c}$, and view-dependent color. A set of training images with known camera poses.
*   **Outputs:** Rendered images, gradients for Gaussian parameters, and the final optimized scene representation.

### Data Structures
The Gaussian population is stored in a flat array or structure-of-arrays (SoA) format to optimize memory access during rasterization.
*   **Position:** 3 floats ($x, y, z$).
*   **Rotation:** 4 floats (quaternion $w, x, y, z$).
*   **Scale:** 3 floats ($\log(s_x), \log(s_y), \log(s_z)$) to ensure positivity.
*   **Opacity:** 1 float.
*   **Color:** $C \times K$ floats, where $C$ is the number of color channels (3) and $K$ is the number of SH bands squared (e.g., $9$ for degree 1).
*   **Covariance:** In some implementations (e.g., gsplat), the covariance is computed on-the-fly from scale and rotation to save memory, or stored as a 6-float symmetric matrix [S2].

### Training Loop
The training process is an iterative loop that minimizes the difference between rendered images and ground truth.

1.  **Initialization:** Initialize Gaussians from a Structure-from-Motion (SfM) point cloud. Calculate scene extent $e_{\text{scene}}$ to determine initial Gaussian scales [S4].
2.  **Iteration:**
    a.  **Sample View:** Randomly select one training image and its camera pose [S9, unofficial].
    b.  **Rasterize:** Project 3D Gaussians to 2D screen space. Sort Gaussians by depth for each tile/pixel. Compute alpha-blended color using the differentiable rasterizer [S2].
    c.  **Loss Computation:** Compute the loss $\mathcal{L}$ between the rendered image and the ground truth image. The standard loss is a weighted sum of L1 loss and D-SSIM:
        $$ \mathcal{L} = (1 - \lambda) \mathcal{L}_1 + \lambda \mathcal{L}_{\text{SSIM}} $$
        where $\lambda \approx 0.2$ [S9, unofficial].
    d.  **Backpropagation:** Compute gradients $\frac{\partial \mathcal{L}}{\partial \theta}$ for all Gaussian parameters $\theta$ using automatic differentiation or custom CUDA kernels [S2].
    e.  **Optimization Step:** Update parameters using the Adam optimizer with a learning rate of $1 \times 10^{-3}$ [S3].
3.  **Densification and Pruning:** Periodically modify the Gaussian set to improve reconstruction quality (see Densification Schedule below).

### Densification Schedule
Densification controls the number of Gaussians to balance detail and performance.

1.  **Splitting:** Every 500 iterations, split Gaussians with high view-space position gradients.
    *   Threshold: $T_{\text{pos}} = 0.02$ [S1].
    *   Condition: If accumulated gradient magnitude $> T_{\text{pos}}$, split the Gaussian into two.
2.  **Cloning:** (Often combined with splitting or handled via compactness) Every 1000 iterations, perform compactness-based densification [S1].
3.  **Pruning:** Every 200 iterations, remove Gaussians that are insignificant.
    *   Condition: Opacity $\alpha < \alpha_{\text{min}} = 0.05$ [S1].
    *   Condition: World-space or view-space radius is excessively large [S1].

### Scene Extent Calculation
The default 3DGS scene extent $e_{\text{scene}}$ is proportional to the distance of the furthest camera from the average camera position, which can be biased if cameras are clustered [S4]. A corrected scene extent $e'_{\text{scene}}$ based on the SfM point cloud is recommended:

$$ \bar{C} = \frac{1}{N_{\text{cam}}} \sum_{i=1}^{N_{\text{cam}}} C_i $$

$$ e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2 $$

where $N_{\text{cam}}$ is the number of camera views, $C_i$ is the position of the $i$-th camera, $N_{\text{SfM}}$ is the number of SfM points, and $p_i$ is the $i$-th SfM point [S4].

### Half-Precision Optimization
To reduce memory bandwidth and register pressure, feature vectors can be fetched and processed in half-precision (FP16) during rasterization [S2].
*   **Stability:** An automatic scaling factor is applied to loss values to improve half-precision training stability [S2].
*   **MLP Evaluation:** If auxiliary networks (e.g., for color or scale prediction) are used, they are trained and evaluated in FP16 using JIT-compiled cooperative vector MLPs (e.g., via tiny-cuda-nn) [S2].

### Pseudocode

```python
def train_3dgs(gaussians, images, camera_poses, num_iterations=30000):
    """
    Main training loop for 3D Gaussian Splatting.
    """
    optimizer = Adam(gaussians.parameters(), lr=1e-3)
    
    for iteration in range(1, num_iterations + 1):
        # 1. Sample a random view
        idx = random.randint(0, len(images) - 1)
        image = images[idx]
        camera_pose = camera_poses[idx]
        
        # 2. Render the scene
        # Projects Gaussians, sorts them, and alpha-blends
        rendered_image = rasterize(gaussians, camera_pose)
        
        # 3. Compute Loss
        # L = 0.8 * L1 + 0.2 * SSIM
        loss = compute_loss(rendered_image, image)
        
        # 4. Backpropagate
        loss.backward()
        
        # 5. Update parameters
        optimizer.step()
        optimizer.zero_grad()
        
        # 6. Densification and Pruning
        if iteration % 500 == 0:
            split_gaussians(gaussians, threshold=0.02)
        
        if iteration % 1000 == 0:
            compactness_densification(gaussians)
            
        if iteration % 200 == 0:
            prune_gaussians(gaussians, alpha_min=0.05)
            
    return gaussians
```

## Subtopics

### Corrected Scene-Extent
A method to calculate scene extent based on the SfM point cloud rather than camera positions to avoid bias from camera distribution (e.g., orbiting a small object in a large environment) [S4]. It sets itself apart from the default 3DGS implementation by using the formula $e'_{\text{scene}} = \frac{1}{N_{\text{SfM}}} \sum_{i=1}^{N_{\text{SfM}}} \|\bar{C} - p_i\|_2$ [S4]. Choose this when camera positions are clustered or do not represent the full scene volume.

### Selective Defocus Blurring
Predicts a per-Gaussian scale offset $\delta s_j$ to selectively enlarge covariances, creating pixel-wise variable blur kernels that match spatially varying scene blurriness [S5]. It sets itself apart from naive Gaussian blur by allowing spatially varying blur shapes and magnitudes [S5]. Use this when training on images with defocus blur.

### Denoise-GS
A self-supervised denoising method for sparse-view 3D Gaussian Splatting that combines unsupervised image denoising (Noise2Void) with 3DGS [S6]. It sets itself apart from supervised methods by requiring no paired clean data, making it robust to non-Gaussian noise in sparse views [S6]. Use this for sparse-view or noisy scene reconstruction.

### Multi-Scale Constraint
A technique using position-aware point adaptive control to apply different scales to Gaussians based on viewer distance, improving rendering of distant objects [S7]. It sets itself apart from standard densification by dynamically adjusting thresholds based on distance $\gamma(\mu)$ [S7]. Use this for large-scale scenes with varying distances.

### LS-Gaussian Viewpoint Transformation
An algorithm that leverages inter-frame continuity for efficient sparse rendering by transforming the viewpoint between consecutive frames, rather than rendering each frame separately [S8]. It sets itself apart from naive pixel warping by operating at the tile/Gaussian level to reduce preprocessing and sorting costs [S8]. Use this for high-frame-rate video rendering on resource-constrained devices.

### 3D Gaussian Splatting Training Loop
The core iterative process of picking a photo, rendering, comparing, and correcting Gaussians [S9, unofficial]. It sets itself apart from random search by using gradient descent to compute the actual downhill direction for the error surface [S9, unofficial]. This is the standard training paradigm.

### Camera Localisation for Convergence Basin
Localizes camera pose by minimizing photometric error against the ground-truth colour image of the target view, fixing the initial Gaussians $G_{init}$ during optimization [S10, unofficial]. It sets itself apart by using the 3DGS renderer as a differentiable model for pose estimation [S10, unofficial]. Use this for camera re-localization tasks.

### Relightable 3D Gaussians
A framework that enhances vanilla 3D Gaussians by associating extra properties (normal vectors, BRDF parameters, and incident lighting) to achieve photo-realistic relighting [S11]. It sets itself apart from standard 3DGS by incorporating physically based rendering (PBR) and ray tracing for visibility [S11]. Use this when relighting or material decomposition is required.

### DiffGS Framework
Applies an optimization process during Gaussian extraction to optimize Gaussians to exact locations, using a truncation function $\lambda$ and projection function $\tau$ [S12]. It sets itself apart by focusing on functional Gaussian splatting diffusion [S12]. Use this for diffusion-based Gaussian generation.

### Opacity Offset Table for DSA
Constructs an opacity offset table to model changes in digital subtraction angiography [S13]. It sets itself apart by addressing specific medical imaging artifacts [S13]. Use this for medical volume rendering applications.

### Resolution Guided Primitive Scheduler
Schedules primitive growth using a concave-up function $P_{fin}^{(i)} = \max(P_{fin}^{(i-1)}, \gamma \cdot P_{fin}^{(i-1)} + \eta \cdot P_{add})$ to suppress early growth and encourage mid-stage growth [S14]. It sets itself apart from linear growth schedules by adapting to resolution changes [S14]. Use this to accelerate training and reduce final primitive count.

### Conditional Splat Approximation
Approximates the influence range of a 3D Gaussian on a slice by using a 2D ellipse splat scaled by the marginal factor [S15, unofficial]. It sets itself apart by providing an accurate and efficient approximation of the original 3D Gaussian’s influence range [S15, unofficial]. Use this for slice-based rendering or tomographic reconstruction.

## Operating characteristics
*   **Time Complexity:** The training loop runs for a fixed number of iterations, commonly around 30,000 [S9, unofficial]. Each iteration involves rasterization, which is $O(N)$ for $N$ Gaussians, but optimized via tiling and sorting.
*   **Memory Complexity:** Memory usage scales with the number of Gaussians. Each Gaussian stores position, rotation, scale, opacity, and SH coefficients. Half-precision fetches reduce register pressure [S2].
*   **Performance:** Standard 3DGS achieves real-time rendering on modern GPUs. Training time depends on scene size and iteration count.
*   **Strengths:** High-quality novel view synthesis, real-time rendering, explicit representation.
*   **Limitations:** Sensitive to initialization, requires careful densification/pruning tuning, can suffer from artifacts in sparse views or dynamic scenes without extensions.

## Background
3D Gaussian Splatting was introduced by Kerbl et al. in 2023 [S1]. It represents scenes as a set of 3D Gaussians and uses a differentiable rasterizer to render them. The method has since been extended with various optimizations and variants, as detailed in the subtopics.
