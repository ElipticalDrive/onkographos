# GaussianList Data Structure and Initialization

Also called: GaussianList

## Overview
The GaussianList is a contiguous, column-major data structure used to store a batch of 3D Gaussian primitives for efficient differentiable volume rendering. It solves the problem of organizing per-Gaussian attributes (position, scale, rotation, opacity, and spherical harmonics coefficients) into a format optimized for SIMD-style batch processing and GPU memory coalescing. It differs from sparse representations like [GaussianSet Data Structure](2074-gaussianset-data-structure.md) by prioritizing linear memory layout and fixed-size buffers over dynamic resizing or hierarchical indexing, making it suitable for the initial population and iterative optimization phases of 3D Gaussian Splatting [S1, unofficial].

## How it works

### Inputs and Outputs
*   **Input**: A vector of Gaussian objects, each containing position, scale, rotation (quaternion), opacity, and spherical harmonics coefficients.
*   **Output**: A `GaussianList` instance with populated matrices and pre-computed 3D covariance matrices.

### Data Structures
The `GaussianList` struct stores attributes in column-major matrices where each column $i$ corresponds to the $i$-th Gaussian. The layout is as follows [S1, unofficial]:

*   `positions`: `na::Matrix4xX<f32>` (4 rows $\times$ $N$ columns). Stores 4D homogeneous coordinates $(x, y, z, 1.0)$.
*   `scales`: `na::Matrix3xX<f32>` (3 rows $\times$ $N$ columns). Stores scale factors $(s_x, s_y, s_z)$.
*   `opacities`: `na::DVector<f32>` (1D vector of size $N$). Stores opacity values $\alpha_i$.
*   `rotations`: `na::Matrix4xX<f32>` (4 rows $\times$ $N$ columns). Stores quaternion components $(w, x, y, z)$ or similar ordering.
*   `sh`: `Matrix48xX<f32>` (48 rows $\times$ $N$ columns). Stores spherical harmonics coefficients. The layout within a column is interleaved by RGB channel for each degree/order: $C_{0,R}, C_{0,B}, C_{0,G}, C_{1,R}, C_{1,B}, C_{1,G}, \dots$ [S1, unofficial].
*   `num_gaussians`: `usize`. The total count $N$.
*   `cov3d`: `na::Matrix3xX<f32>` (3 rows $\times$ $N$ columns). Pre-allocated buffer storing the flattened 3D covariance matrices. Each Gaussian's $3 \times 3$ covariance is stored in columns $3i$ to $3i+2$ of this matrix.

### Initialization Steps
The initialization process transforms a list of Gaussian objects into the `GaussianList` structure [S1, unofficial]:

1.  **Count**: Set `num_gaussians` $N$ to the length of the input vector.
2.  **Positions**: Iterate over all $N$ gaussians. For each Gaussian $i$, clone its 3D position $(x_i, y_i, z_i)$ and append $1.0$ to form the 4th row. Store in `positions` column $i$.
3.  **Scales**: Clone the scale components $(s_{x,i}, s_{y,i}, s_{z,i})$ into `scales` column $i$.
4.  **Opacities**: Clone the opacity value $\alpha_i$ into `opacities` index $i$.
5.  **Rotations**: Clone the quaternion components into `rotations` column $i$.
6.  **Spherical Harmonics**: Clone the SH coefficients into `sh` column $i$ according to the interleaved RGB layout.
7.  **Covariance Buffer**: Initialize `cov3d` with zeros of size $3 \times N$.
8.  **Compute Covariances**: Call `compute_cov3d()` to calculate the 3D covariance matrices for all Gaussians.

### Covariance Computation (`compute_cov3d`)
For each Gaussian $i$, the 3D covariance matrix $\Sigma_{3D}$ is computed from its rotation and scale [S1, unofficial]:

1.  Extract the rotation quaternion $q_i$ from `rotations` column $i$.
2.  Convert $q_i$ to a unit quaternion, then to a $3 \times 3$ rotation matrix $R_i$.
3.  Construct a diagonal scale matrix $S_i = \text{diag}(s_{x,i}^2, s_{y,i}^2, s_{z,i}^2)$. Note that the source squares the scale components.
4.  Compute the covariance: $\Sigma_{3D, i} = R_i S_i R_i^T$.
5.  Copy the elements of $\Sigma_{3D, i}$ into `cov3d` at offset $i \times 3$ (column-major flattening).

### Centering (Optional Pre-processing)
Before initialization or during optimization, Gaussian positions may be centered [S1, unofficial]:

1.  Initialize `avg_pos` as a zero $3$-vector.
2.  Sum all positions: $\text{avg\_pos} = \sum_{i=0}^{N-1} \mathbf{p}_i$.
3.  Normalize: $\text{avg\_pos} = \text{avg\_pos} / N$.
4.  Subtract `avg_pos` from each position $\mathbf{p}_i$.

### Projecting 3D Covariance to 2D Screen Space (`project_cov3d_to_screen`)
To render, the 3D covariance $\Sigma_{3D}$ is projected to 2D screen space $\Sigma_{2D}$ [S1, unofficial]:

1.  **Camera Space Position**: Let $\mathbf{p}_w$ be the 4D homogeneous position. Transform to camera space: $\mathbf{p}_{cam} = \mathbf{V} \mathbf{p}_w$, where $\mathbf{V}$ is the view matrix. Let $\mathbf{p}_{cam} = (x_c, y_c, z_c, 1)^T$.
2.  **Tangent Calculation**: Compute tangents of the center: $t_{xz} = x_c / z_c$, $t_{yz} = y_c / z_c$.
3.  **Clamping**: Clamp tangents to FOV limits. Let $f_x, f_y$ be focal lengths and $\text{htanfov}_{xy}$ be the tangent of the FOV.
    *   $t_x = \text{clamp}(t_{xz}, -1.3 \cdot \text{htanfov}_x, 1.3 \cdot \text{htanfov}_x) \cdot z_c$
    *   $t_y = \text{clamp}(t_{yz}, -1.3 \cdot \text{htanfov}_y, 1.3 \cdot \text{htanfov}_y) \cdot z_c$
    *   The constant $1.3$ is the FOV Clamping Limit [S1, unofficial].
4.  **Jacobian Matrix $J$**: Construct the $3 \times 3$ Jacobian of the perspective projection. Using $t_x, t_y, t_z = z_c$:
    $$
    J = \begin{bmatrix}
    f_x / t_z & 0 & -f_x t_x / t_z^2 \\
    0 & f_y / t_z & -f_y t_y / t_z^2 \\
    0 & 0 & 0
    \end{bmatrix}
    $$
    *(Note: The exact derivation of $J$ depends on the specific projection model, but the source implies a standard perspective projection Jacobian structure involving focal lengths and tangent coordinates.)*
5.  **View Matrix Transpose $W$**: Extract the top-left $3 \times 3$ submatrix of the view matrix $\mathbf{V}$ and transpose it: $W = \mathbf{V}_{3 \times 3}^T$.
6.  **Transformation Matrix $T$**: Compute $T = W J$.
7.  **2D Covariance**: Compute $\Sigma_{2D} = T^T \Sigma_{3D} T$.
8.  **Extract 2D Submatrix**: Take the top-left $2 \times 2$ submatrix of $\Sigma_{2D}$.
9.  **Low-Pass Filter**: Add $0.3$ to the diagonal elements of the $2 \times 2$ matrix to ensure the Gaussian is at least one pixel wide/high [S1, unofficial].

### Evaluating Color
Color is evaluated using Spherical Harmonics (SH) [S1, unofficial]:
1.  Pass the SH coefficients column for index $i$, the SH dimension, and the viewing direction $\mathbf{d}$ to `eval_spherical_harmonics`.
2.  Return the resulting RGB color vector and the Gaussian's opacity.

### Pseudocode

```python
import numpy as np

def initialize_gaussian_list(gaussians: list) -> dict:
    """
    Initialize a GaussianList from a list of Gaussian objects.
    gaussians: list of objects with attributes: position (3,), scale (3,), 
               rotation (4,), opacity (float), sh_coeffs (48,)
    """
    N = len(gaussians)
    
    # Initialize matrices (Column-major: shape (rows, N))
    positions = np.zeros((4, N), dtype=np.float32)
    scales = np.zeros((3, N), dtype=np.float32)
    opacities = np.zeros(N, dtype=np.float32)
    rotations = np.zeros((4, N), dtype=np.float32)
    sh = np.zeros((48, N), dtype=np.float32)
    cov3d = np.zeros((3, N), dtype=np.float32) # Flattened 3x3 matrices stored column-wise
    
    for i, g in enumerate(gaussians):
        # 1. Positions
        positions[:3, i] = g.position
        positions[3, i] = 1.0
        
        # 2. Scales
        scales[:, i] = g.scale
        
        # 3. Opacities
        opacities[i] = g.opacity
        
        # 4. Rotations
        rotations[:, i] = g.rotation
        
        # 5. Spherical Harmonics (Interleaved RGB)
        # Layout: C0_R, C0_B, C0_G, C1_R, ...
        sh[:, i] = g.sh_coeffs
        
        # 6. Compute 3D Covariance
        cov3d[:, i] = compute_cov3d(g.rotation, g.scale)
        
    return {
        "positions": positions,
        "scales": scales,
        "opacities": opacities,
        "rotations": rotations,
        "sh": sh,
        "num_gaussians": N,
        "cov3d": cov3d
    }

def compute_cov3d(rotation: np.ndarray, scale: np.ndarray) -> np.ndarray:
    """
    Compute 3D covariance matrix from rotation quaternion and scale.
    rotation: (4,) quaternion
    scale: (3,) scale factors
    Returns: flattened 3x3 covariance matrix (9,)
    """
    # Convert quaternion to rotation matrix R (3x3)
    R = quaternion_to_rotation_matrix(rotation)
    
    # Scale matrix S (diagonal)
    S = np.diag(scale**2)
    
    # Covariance Sigma = R * S * R^T
    cov = R @ S @ R.T
    
    return cov.flatten()

def project_cov3d_to_screen(cov3d_col: np.ndarray, position_4d: np.ndarray, 
                            view_matrix: np.ndarray, focal_x: float, 
                            focal_y: float, tan_fov_x: float, tan_fov_y: float) -> np.ndarray:
    """
    Project 3D covariance to 2D screen space.
    cov3d_col: (9,) flattened 3x3 covariance matrix
    position_4d: (4,) homogeneous position
    view_matrix: (4,4) view matrix
    """
    cov3d = cov3d_col.reshape(3, 3)
    
    # Transform position to camera space
    pos_cam = view_matrix @ position_4d
    x_c, y_c, z_c = pos_cam[:3]
    
    # Tangents
    t_xz = x_c / z_c
    t_yz = y_c / z_c
    
    # Clamping
    limit_x = 1.3 * tan_fov_x
    limit_y = 1.3 * tan_fov_y
    
    t_x = np.clip(t_xz, -limit_x, limit_x) * z_c
    t_y = np.clip(t_yz, -limit_y, limit_y) * z_c
    
    # Jacobian J (3x3)
    # Standard perspective projection Jacobian approximation
    J = np.array([
        [focal_x / z_c, 0, -focal_x * t_x / (z_c**2)],
        [0, focal_y / z_c, -focal_y * t_y / (z_c**2)],
        [0, 0, 0]
    ])
    
    # W: Transpose of top-left 3x3 of view matrix
    W = view_matrix[:3, :3].T
    
    # T = W * J
    T = W @ J
    
    # Sigma_2D = T^T * Sigma_3D * T
    cov2d = T.T @ cov3d @ T
    
    # Extract top-left 2x2
    cov2d_2x2 = cov2d[:2, :2]
    
    # Low-pass filter
    cov2d_2x2[0, 0] += 0.3
    cov2d_2x2[1, 1] += 0.3
    
    return cov2d_2x2
```

## Subtopics

### [LinPrim Population Control](2295-linprim-population-control.md)
LinPrim Population Control manages the density of linear primitives (octahedra and tetrahedra) during differentiable volume rendering optimization by pruning, cloning, and splitting primitives to adapt to scene complexity. It differs from standard 3D Gaussian Splatting by redefining primitive size metrics to accommodate non-spherical kernels and adjusting sampling distributions to respect the anisotropic geometry of linear primitives.

### [Gaussian Splatting Initialization and Parameterization](2313-gaussian-splatting-initialization-and-parameterization.md)
Gaussian Splatting Initialization and Parameterization establishes the initial state of the 3D Gaussian primitives ($\mathcal{G}$) from a sparse Structure-from-Motion (SfM) point cloud, providing geometrically accurate starting positions, colors, and covariances. Unlike random initialization, which lacks normal information and accurate geometry, SfM initialization leverages multi-view matching to produce a sparse cloud that serves as a superior prior for the differentiable renderer, significantly improving reconstruction quality and convergence speed. It sets itself apart from dense MVS initialization by avoiding the baking of MVS errors and redundant geometry, relying instead on the optimizer to create detail during training.

### [Octree-GS / Scaffold-GS](6142-octree-gs-scaffold-gs.md)
Octree-GS and Scaffold-GS are hierarchical level-of-detail (LoD) methods that anchor scene content to a sparse voxel grid, using the grid as a scaffold to allocate Gaussians only in occupied regions. This approach naturally adapts to view distance and improves memory efficiency compared to flat Gaussian lists. Scaffold-GS specifically uses anchor points to predict "neural" Gaussians on the fly via a small MLP, achieving approximately 5x less memory usage than vanilla 3DGS at the same quality. Octree-GS builds an explicit octree over the scene, associating each node with a merged Gaussian that summarizes the radiance and opacity of its children, enabling massive scene rendering.

### [Random Gaussian Generation](14047-random-gaussian-generation.md)
Random Gaussian Generation is the initialization procedure for creating a set of 3D Gaussians from scratch, typically to serve as the starting point for differentiable rendering optimization in methods like 3D Gaussian Splatting. It generates a fixed number of Gaussian primitives with random positions (implicitly at the origin before transformation), scales, orientations, opacities, and spherical harmonics coefficients. It differs from [LinPrim Population Control](2295-linprim-population-control.md) which manages the density of existing Gaussians during training, and from [Gaussian Splatting Initialization and Parameterization](2313-gaussian-splatting-initialization-and-parameterization.md) which may use structured or data-driven initialization strategies. This method provides a uniform, uninformative prior over the parameter space.

### GaussianHair
GaussianHair is a strand-aware hair method using a combined strand + GS representation [S2, unofficial].

### Appearance Modeling
Appearance Modeling uses per-image and per-Gaussian embeddings optimized via an MLP to model view-dependent appearance, illumination, and weather effects [S3].
*   **Parameters**:
    *   Learning rate for the appearance MLP: $0.0005$ [S3].
    *   Learning rate for per-image embeddings $\mathbf{e}_j$: $0.001$ [S3].
    *   Learning rate for per-Gaussian embeddings $\mathbf{z}_i$: $0.005$ [S3].
*   **Layout**:
    *   Per-image embedding $\mathbf{e}_j \in \mathbb{R}^{d_e}$ with dimension $d_e = 32$ [S3].
    *   Per-Gaussian embedding $\mathbf{z}_i \in \mathbb{R}^{d_z}$ with dimension $d_z = 24$, initialized using Fourier frequencies with 4 components [S3].

## Operating characteristics
*   **Time Complexity**: Initialization is $O(N)$ where $N$ is the number of Gaussians. Covariance computation is $O(N)$ (constant factor per Gaussian). Projection is $O(N)$ per camera view.
*   **Memory Complexity**: $O(N)$ for the contiguous arrays. The column-major layout ensures cache-friendly access during batched rendering operations.
*   **Strengths**: High performance due to SIMD-friendly memory layout; simple to implement; supports efficient batched operations.
*   **Limitations**: Fixed-size buffers require pre-allocation or resizing; does not inherently support hierarchical culling or adaptive resolution like Octree-GS.
*   **When to use**: Standard 3D Gaussian Splatting training and rendering where scene complexity is moderate and memory bandwidth is a bottleneck.
*   **When not to use**: Extremely large-scale scenes requiring hierarchical LOD (use Octree-GS) or dynamic scenes with significant structural changes requiring sparse updates (use GaussianSet).

## Background
The GaussianList data structure originates from the implementation of 3D Gaussian Splatting, specifically as seen in the `thomasantony/splat` repository [S1, unofficial]. It represents a practical engineering choice for storing Gaussian attributes in a format suitable for GPU computation and differentiable rendering pipelines. The structure has been adopted and adapted in various open-source implementations and variants of 3DGS.
