# TraGraph-GS

Also called: Trajectory Graph-based Gaussian Splatting

## Overview
TraGraph-GS is a high-quality rendering method for arbitrary large-scale scenes that employs graph-based adaptive spatial partitioning and regularization constraints to handle textureless regions and varying viewing distances [S1]. It distinguishes itself from standard 3D Gaussian Splatting by decoupling training into local regions via a camera connectivity graph and using a progressive rendering strategy with a coarse global representation to eliminate boundary artifacts during novel view synthesis [S1].

## How it works

### Inputs and Outputs
**Inputs:** A set of disordered scene photographs (images) and their corresponding camera poses.
**Outputs:** A set of 3D Gaussians (local and global) and a rendering pipeline capable of generating novel viewpoints.

### Data Structures

**Camera Connectivity Graph $G$**
*   **Vertices $V$**: Set of input images $\{v_1, v_2, ..., v_n\}$.
*   **Edges $E$**: Set of pairs $\{(v_i, v_j) | v_i, v_j \in V\}$ representing co-visibility.
*   **Weights $w$**: Function $w: E \rightarrow \mathbb{R}$ assigning a weight to each edge based on the count of feature matches between image pairs. Higher weights indicate larger co-visible regions [S1].

**Local Regions $\{P_i\}_{i=1}^k$**
*   Partition of vertices $V$ into $k$ connected subgraphs.
*   Each region $P_i$ contains a subset of vertices and the edges connecting them within the subset.

**Gaussian Representation**
*   **Local Gaussians**: Trained independently for each region $P_i$.
*   **Global Gaussians**: A coarse representation trained on downsampled data to capture overall scene structure.

### Algorithm Steps

1.  **Construct Camera Connectivity Graph**:
    *   For every pair of input images, compute the number of feature matches.
    *   Create graph $G=(V, E, w)$ where edge weights $w_{ij}$ equal the feature match count [S1].

2.  **BFS-Based Graph Segmentation**:
    *   Initialize unassigned nodes $U = V$.
    *   Identify the node $n$ with the highest degree in $U$ as the seed node.
    *   Perform Breadth-First Search (BFS) from the seed node, adding nodes to the current region until the region size reaches $|V|/k$.
    *   For remaining unassigned nodes, calculate a score $s_i$ relative to existing regions and assign them to maintain balanced node distribution and connectivity [S1].

3.  **Local Training with Regularization**:
    *   Train local 3D Gaussians independently for each region $P_i$ in parallel to optimize GPU memory [S1].
    *   **Multi-View Constraint**: To improve geometry in textureless regions, render depth and normal maps for each image. For a pixel $p$ in a reference view, establish a spatial plane $(d, n)$ where $n$ is the rendered normal and $d$ is the distance from the camera origin. Use homography warping to project $p$ to a corresponding pixel $p'$ in a neighborhood view. Compute the Normalized Cross Correlation (NCC) between patches at $p$ and $p'$. The multi-view loss is:
        $$ L_{mv} = \sum_{p \in P_i} (1 - \text{NCC}(p, p')) $$
    *   **Multi-Scale Constraint**: Apply position-aware point adaptive control. Define a scale factor $\gamma(\mu)$ based on the distance of Gaussian mean $\mu$ from the camera center $c$ and scene radius $r$:
        $$ \gamma(\mu) = \begin{cases} 1 & \text{if } \|\mu - c\|_2 < 2r \\ \|\mu - c\|_2 / r - 1 & \text{if } \|\mu - c\|_2 \ge 2r \end{cases} $$
    *   **Densification Protocol**: If the directional gradient exceeds a threshold:
        *   If $\max(s) < g \cdot \gamma(\mu)$, perform cloning.
        *   Otherwise, perform splitting.
        *   Prune Gaussians where opacity falls below a threshold [S1].
    *   **Total Loss**:
        $$ L = (1 - \lambda)L_1 + \lambda L_{SSIM} + L_{mv} $$
        where $L_1$ and $L_{SSIM}$ are standard reconstruction losses [S1].

4.  **Global Coarse Training**:
    *   Downsample point clouds and images.
    *   Train a global Gaussian representation without densification to prevent excessive memory consumption [S1].

5.  **Progressive Rendering for Novel Viewpoints**:
    *   Render the novel viewpoint separately using local Gaussians and global Gaussians.
    *   Calculate a matching score $S$ for each local-global Gaussian pair:
        $$ S = (1 - \lambda)L_1 + \lambda L_{SSIM} $$
        Higher scores indicate higher visibility likelihood [S1].
    *   Sort local Gaussians in descending order of $S$: $G_1, G_2, ..., G_k$.
    *   Compute projection opacity $o_i(p)$ for each pixel $p$:
        $$ o_i(p) = \sum_{i=1}^{N} \alpha_i \prod_{j=1}^{i-1} (1 - \alpha_j) $$
    *   Compute final pixel color $c(p)$ using progressive weights $w_i$:
        $$ c(p) = \sum_{i=1}^{k} w_i c_i(p) $$
        where $c_i(p)$ is the color rendered by local Gaussian $G_i$, and weights $w_i$ are defined by an overlap threshold $\beta$:
        $$ w_i = \begin{cases} o_i(p) & \text{if } \sum_{j=1}^{i-1} o_j(p) < \beta \\ 0 & \text{if } \sum_{j=1}^{i-1} o_j(p) \ge \beta \end{cases} $$
        This prioritizes local Gaussians with higher contributions and refines regions with lower contributions [S1].

### Parameters
*   $k$: Number of segmented regions.
*   $\lambda$: Weight for SSIM loss (typical value not specified in source, standard 3DGS uses 0.2).
*   $r$: Scene radius.
*   $c$: Center of cameras.
*   $g$: Scaling factor for densification threshold.
*   $\beta$: Overlapped opacity threshold for progressive rendering.

### Edge Cases and Pitfalls
*   **Memory Overflow**: Naive partitioning can lead to unbalanced node distribution. The BFS method ensures balanced distribution to mitigate this [S1].
*   **Boundary Artifacts**: Combining local Gaussians naively causes floating artifacts or holes. The progressive rendering strategy with global supplementation resolves this [S1].
*   **Textureless Regions**: Standard 3DGS struggles with geometry here. The multi-view constraint using NCC addresses this [S1].

## Operating characteristics

### Time and Memory Complexity
*   **Memory**: Parallel training of local Gaussians reduces peak GPU memory usage compared to training a single global model. Global training uses downsampled data to further limit memory [S1].
*   **Time**: Graph construction and segmentation add preprocessing overhead. However, parallel local training accelerates convergence. Progressive rendering adds computational cost per pixel during novel view synthesis compared to standard splatting [S1].

### Measured Performance
*   Evaluated on large-scale aerial (Mill-19, UrbanScene3D) and ground-level (SmallCity, Campus, Road, General) datasets with thousands of images [S1].
*   Maintains real-time performance across vastly different scales [S1].

### Strengths and Limitations
*   **Strengths**: Handles large-scale scenes with varying distances; improves texture and geometry in textureless regions; eliminates boundary artifacts in novel views [S1].
*   **Limitations**: Requires feature matching for graph construction; relies on specific densification protocols for multi-scale handling [S1].

## Background

### Origin
TraGraph-GS was proposed to address the limitations of existing methods in rendering arbitrary large-scale scenes, specifically tackling issues with boundary artifacts and textureless regions [S1].

### History and Development
The method builds upon 3D Gaussian Splatting [11] and addresses issues found in prior large-scale methods like VastGaussian [14] and others [2, 1] by introducing a trajectory graph-based partitioning and progressive rendering strategy [S1].

### Usage
Used for high-quality rendering of large-scale scenes, including aerial imagery and ground-level urban environments [S1].
