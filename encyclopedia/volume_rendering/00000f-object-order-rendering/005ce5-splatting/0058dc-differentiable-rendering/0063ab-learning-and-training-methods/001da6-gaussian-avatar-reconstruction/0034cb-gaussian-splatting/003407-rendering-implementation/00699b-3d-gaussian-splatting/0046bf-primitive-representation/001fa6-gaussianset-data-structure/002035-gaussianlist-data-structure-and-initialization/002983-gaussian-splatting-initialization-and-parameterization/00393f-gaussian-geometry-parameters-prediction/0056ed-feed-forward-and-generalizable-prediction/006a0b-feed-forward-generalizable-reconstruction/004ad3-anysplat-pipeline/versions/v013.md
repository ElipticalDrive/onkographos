# AnySplat Pipeline

Also called: Feed-forward 3D Gaussian Splatting from Unconstrained Views

## Overview
AnySplat is a feed-forward method for novel-view synthesis that predicts a full set of 3D Gaussian primitives directly from uncalibrated input images, eliminating the need for camera poses or depth maps during inference [S1, unofficial]. It differs from sibling methods like [Splatt3R](16423-splatt3r.md) and [ZeroGS](16425-zerogs.md) by explicitly predicting camera poses and depth alongside Gaussian parameters in a single forward pass, using a differentiable voxelization module to stabilize the rendering of pixel-wise Gaussians [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A tensor of $K$ uncalibrated RGB images $I \in \mathbb{R}^{1 \times K \times 3 \times 448 \times 448}$, normalized to $[-1, 1]$ before processing [S1, unofficial].
*   **Outputs:** A set of 3D Gaussians defined by mean $\mu$, scale $s$, rotation $r$, opacity $\alpha$, and color $c$; predicted camera poses (extrinsic $E$ and intrinsic $K$); and a predicted depth map $D$ [S1, unofficial].

**Data Structures:**
The Gaussian parameters are predicted per-pixel in the input image space. Each pixel $i$ corresponds to a 3D Gaussian primitive. The parameters are:
*   $\mu_i \in \mathbb{R}^3$: 3D mean position.
*   $s_i \in \mathbb{R}^3$: Scale (log-space or exponential activation).
*   $r_i \in \mathbb{R}^4$: Rotation quaternion (normalized).
*   $\alpha_i \in [0, 1]$: Opacity (sigmoid activation).
*   $c_i$: Color coefficients (Spherical Harmonics or RGB).

**Steps:**
1.  **Feature Encoding:** Input images are processed by a transformer-based geometry encoder to extract multi-scale features [S1, unofficial].
2.  **Parameter Regression:** Three decoder heads ($F_G, F_D, F_C$) predict:
    *   $F_G$: Gaussian parameters $(\mu, \sigma, r, s, c)$ [S1, unofficial].
    *   $F_D$: Depth map $D$ [S1, unofficial].
    *   $F_C$: Camera poses $p$ (extrinsic and intrinsic matrices) [S1, unofficial].
3.  **Gaussian Construction:** Pixel-wise 3D Gaussians are constructed using the predicted parameters and the camera projection matrices derived from $p$ [S1, unofficial].
4.  **Differentiable Voxelization:** The pixel-wise Gaussians are voxelized into "pre-voxel" 3D Gaussians using a Differentiable Voxelization module. This step aggregates overlapping Gaussians and handles spatial coherence [S1, unofficial].
5.  **Rendering:** Multi-view images and depth maps are rendered from the voxelized Gaussians using differentiable rasterization [S1, unofficial].
6.  **Loss Computation:**
    *   **RGB Loss:** Difference between rendered images and ground truth [S1, unofficial].
    *   **Geometry Loss:** Computed from rendered depth maps, decoded depth $D$, and predicted poses $p$ [S1, unofficial].
    *   **Pseudo-Geometry Prior:** Supervision from a pretrained VGGT model [S1, unofficial].

**Pseudocode:**
```python
def inference(images):
    """
    images: torch.Tensor of shape [1, K, 3, 448, 448], normalized to [-1, 1]
    Returns: gaussians (list of Gaussian parameters), pred_context_pose (dict with extrinsic/intrinsic)
    """
    # 1. Feature Encoding
    features = geometry_encoder(images)
    
    # 2. Parameter Regression
    gaussian_params = F_G(features)  # Predicts mu, sigma, r, s, c
    depth_map = F_D(features)        # Predicts depth D
    camera_poses = F_C(features)     # Predicts extrinsic and intrinsic matrices
    
    # 3. Gaussian Construction
    # Construct pixel-wise 3D Gaussians using camera_poses and gaussian_params
    pixel_gaussians = construct_pixel_gaussians(gaussian_params, camera_poses)
    
    # 4. Differentiable Voxelization
    voxelized_gaussians = differentiable_voxelization(pixel_gaussians)
    
    # 5. Rendering
    rendered_images = render_images(voxelized_gaussians, camera_poses)
    rendered_depth = render_depth(voxelized_gaussians, camera_poses)
    
    return voxelized_gaussians, camera_poses
```

**Edge Cases and Pitfalls:**
*   **Uncalibrated Inputs:** The method must handle arbitrary camera poses and intrinsics, requiring robust pose prediction [S1, unofficial].
*   **Voxelization Artifacts:** Improper voxelization can lead to artifacts or loss of detail; the differentiable voxelization module is critical for stability [S1, unofficial].
*   **Depth Ambiguity:** Predicting depth from monocular images is inherently ambiguous; pseudo-geometry priors from VGGT help mitigate this [S1, unofficial].

## Subtopics

### [SubSplat](13524-subsplat.md)
SubSplat is a method for high-resolution novel-view synthesis that resolves the trade-off between network computational cost and rendering fidelity in pixel-aligned 3D Gaussian Splatting. It solves the problem of insufficient Gaussian density and artifacts when using low-resolution backbone inputs by introducing a Sub-pixel Gaussian Reparameterizer (SPGR). Unlike prior methods limited by fixed grids or image-space upsamplers, SubSplat subdivides each grid-anchored primary Gaussian into multiple fine-grained sub-pixel primitives, restoring structural density directly from low-resolution features while maintaining stable network latency.

### [Deformable Radial Kernel (DRK)](13699-deformable-radial-kernel-drk.md)
Deformable Radial Kernel (DRK) Splatting is a 3D scene representation method that replaces the fixed radial symmetry of Gaussian primitives with a flexible planar kernel defined by multiple radial basis functions. It solves the overparameterization and geometric fidelity limitations of Gaussian Splatting by allowing adaptive stretching, rotation, and sharp boundary control, enabling high-fidelity rendering with significantly fewer primitives. Unlike standard 2D Gaussian Splatting, which relies on smooth, elliptical distributions, DRK supports straight edges and sharp corners through L1/L2 norm blending and piecewise edge sharpening.

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of input views and pixels, as it is a feed-forward method. Inference time is dominated by the transformer encoder and decoder heads [S1, unofficial].
*   **Memory Complexity:** Proportional to the number of Gaussians, which is equal to the number of input pixels ($H \times W \times K$). Voxelization may add overhead [S1, unofficial].
*   **Performance:** Not given in the sources.
*   **Strengths:** Handles uncalibrated inputs; end-to-end differentiable; no need for explicit camera calibration or depth estimation pipelines [S1, unofficial].
*   **Limitations:** Relies on the accuracy of the predicted poses and depth; quality depends on the pretrained VGGT priors [S1, unofficial].
*   **When to use:** Novel-view synthesis from uncalibrated image sets where camera parameters are unknown [S1, unofficial].
*   **When not to use:** When high-precision camera poses are available and can be used directly; when real-time performance is critical and the overhead of the transformer is prohibitive [S1, unofficial].

## Background
AnySplat was introduced by InternRobotics as a feed-forward approach to 3D Gaussian Splatting that operates on unconstrained views [S1, unofficial]. It builds on the principles of differentiable rendering and Gaussian Splatting, extending them to handle the lack of camera calibration by jointly predicting geometry and appearance [S1, unofficial].
