# Tiled 2D Gaussian Splatting Rasterization

Also called: 3D Gaussian Rasterization (Forward Pass), 3D Gaussian Splatting Forward Rendering Pipeline, 3DGS Rasterization, CUDA Gaussian Rasterizer, CudaRasterizer::Rasterizer::forward, Gaussian Rasterization (GPU), Tile-based Gaussian Rasterization, Tiled Rendering of 3DGS

## Overview
Tiled 2D Gaussian Splatting Rasterization is a highly optimized, differentiable GPU rendering method for 3D Gaussian Splatting (3DGS) that partitions the image plane into macro-tiles to manage memory and processing load [S1, S2, S6, unofficial]. It solves the performance bottleneck of per-pixel sorting and redundant Gaussian evaluation by binning projected Gaussians into tiles, sorting them by depth, and using CUDA thread blocks to cooperatively accumulate pixel colors via iterative alpha-blending [S1, S2, S4, S5, unofficial]. Unlike its sibling [Gaussian Splat Rendering (Screen-Space Quad)](2075-gaussian-splat-rendering-screen-space-quad.md) which relies on standard graphics pipeline blending, or [Depth-First Splat Sorting](2850-depth-first-splat-sorting.md) which sorts globally, this method ensures each tile is processed by one GPU thread block walking a single sorted list, enabling real-time performance for millions of splats [S2, S4, unofficial][S8].

## How it works
**Inputs and Outputs:**
*   **Inputs:** 3D Gaussian parameters (means $\mathbf{x}$, covariances $\Sigma$, opacities $\alpha$, spherical harmonics coefficients $\mathbf{c}$), camera parameters (view matrix $V$, projection matrix $P$, focal lengths $f_x, f_y$, image dimensions $W, H$), and background color tensor $\mathbf{b}$ [S1, S4, S6, unofficial].
*   **Outputs:** Rendered color image $\mathbf{C}$, accumulated alpha $\mathbf{A}$, and optionally depth $\mathbf{D}$ [S4, S6, unofficial].

**Data Structures:**
The method relies on three primary state buffers allocated on the GPU [S4, S5, unofficial]:
1.  **GeometryState:** Per-Gaussian buffers.
    *   `depths`: `float*`, size $P$ (number of Gaussians).
    *   `means2D`: `float2*`, size $P$.
    *   `conic_opacity`: `float4*`, size $P$ (stores inverse 2D covariance components $a, b, c$ and opacity).
    *   `rgb`: `float*`, size $P \times 3$ (precomputed or SH-evaluated colors).
    *   `tiles_touched`: `uint32_t*`, size $P$.
    *   `point_offsets`: `uint32_t*`, size $P$ (prefix sum of tile contributions).
2.  **BinningState:** Sorting buffers.
    *   `point_list_keys`: `uint64_t*`, size $P$ (encoded tile ID and depth).
    *   `point_list`: `uint32_t*`, size $P$ (Gaussian indices).
3.  **ImageState:** Per-pixel/tile buffers.
    *   `accum_alpha`: `float*`, size $W \times H$.
    *   `ranges`: `uint2*`, size $N_{tiles}$ (start/end indices for each tile in the sorted list).

**Numbered Steps:**

1.  **Preprocessing and Projection:**
    For each Gaussian $i$:
    *   Transform mean $\mathbf{x}_i$ to camera space: $\mathbf{x}'_i = V \mathbf{x}_i$ [S6, unofficial].
    *   Rotate covariance $\Sigma_i$ to camera space: $\Sigma'_i = R \Sigma_i R^T$ [S6, unofficial].
    *   Project to 2D screen space using the Jacobian of the perspective projection to compute the 2D covariance $\Sigma_{2D}$ [S4, S6, unofficial].
    *   Approximate $\Sigma_{2D}$ and compute its inverse (conics) $\mathbf{K} = \Sigma_{2D}^{-1} = \begin{bmatrix} a & b \\ b & c \end{bmatrix}$ [S6, unofficial].
    *   Compute the 2D bounding box radius $r = \lceil \sigma_{multiplier} \sqrt{\lambda_{max}} \rceil$, where $\lambda_{max}$ is the largest eigenvalue of $\Sigma_{2D}$ and $\sigma_{multiplier}$ is typically 3.0 [S1, S6, unofficial].
    *   Evaluate Spherical Harmonics to get color $\mathbf{c}_i$ if not precomputed [S4, S6, unofficial].
    *   Apply sigmoid to opacity logit to get $\alpha_i$ [S7, unofficial].

2.  **Frustum Culling and Tile Binning:**
    *   Discard Gaussians outside the camera frustum (near/far planes and image bounds) [S1, S6, unofficial].
    *   For each surviving Gaussian, determine which tiles it overlaps. A tile $(u, v)$ is assigned if the Gaussian's bounding box intersects the tile [S1, S6, unofficial].
    *   Generate sorting keys: For each tile overlap, create a 64-bit key encoding the tile ID (high bits) and the Gaussian's view-space depth (low bits) [S4, S5, unofficial]. Duplicate the Gaussian index for each tile it touches.

3.  **Sorting:**
    *   Use a device-side radix sort (e.g., `cub::DeviceRadixSort`) to sort the keys and corresponding Gaussian indices [S4, S5, unofficial]. This groups Gaussians by tile and sorts them by depth within each tile [S2, S4, unofficial].
    *   Identify tile ranges: Scan the sorted keys to find the start and end indices in the sorted list for each tile, storing these in `ImageState.ranges` [S4, S5, unofficial].

4.  **Tiled Rasterization (Forward Pass):**
    *   Launch a CUDA kernel where each thread block $(T_x, T_y)$ is assigned to one image tile of size $BLOCK\_X \times BLOCK\_Y$ (typically 16x16 or 32x32) [S1, S6, unofficial].
    *   Threads within a block cooperatively fetch Gaussians from the sorted list for their assigned tile [S1, S2, unofficial].
    *   For each pixel $(u, v)$ in the tile, iterate through the sorted Gaussians $i$:
        *   Compute squared Mahalanobis distance: $dist\_sq = a \cdot du^2 + 2 \cdot b \cdot du \cdot dv + c \cdot dv^2$, where $du = u - u_{mean}$ and $dv = v - v_{mean}$ [S6, unofficial].
        *   Compute pixel opacity: $\alpha_i(P) = \alpha_i \cdot \exp(-0.5 \cdot dist\_sq)$ [S7, unofficial].
        *   Update accumulated color and alpha using iterative alpha blending:
            $$C(P) = \sum_{i=1}^N \mathbf{c}_i \alpha_i(P) \prod_{j=1}^{i-1} (1 - \alpha_j(P))$$
            $$A(P) = \sum_{i=1}^N \alpha_i(P) \prod_{j=1}^{i-1} (1 - \alpha_j(P))$$
        *   **Early Termination:** If accumulated transmittance $\prod (1 - \alpha_j)$ drops below a threshold (e.g., 0.01) or accumulated alpha exceeds 0.99, stop processing further Gaussians for that pixel [S1, S6, unofficial].
    *   After processing all Gaussians, add the background color: $\mathbf{C}_{final}(P) = \mathbf{C}_{accumulated}(P) + \mathbf{b} \cdot (1 - A(P))$ [S6, unofficial].

**Pseudocode:**

```python
import torch
import math

def tiled_gaussian_rasterization(
    means2D: torch.Tensor,      # [P, 2]
    conics: torch.Tensor,       # [P, 3] (a, b, c)
    opacities: torch.Tensor,    # [P]
    colors: torch.Tensor,       # [P, 3]
    depths: torch.Tensor,       # [P]
    tile_ranges: torch.Tensor,  # [N_tiles, 2] (start, end indices in sorted list)
    sorted_gaussian_indices: torch.Tensor, # [P_sorted]
    width: int,
    height: int,
    tile_size: int = 16
):
    """
    Simulates the tiled rasterization kernel logic.
    Note: This is a simplified Python representation of the CUDA logic.
    """
    N_tiles_x = math.ceil(width / tile_size)
    N_tiles_y = math.ceil(height / tile_size)
    out_color = torch.zeros(3, height, width)
    out_alpha = torch.zeros(height, width)
    
    # Background color (black)
    bg = torch.tensor([0.0, 0.0, 0.0])

    for tile_u in range(N_tiles_x):
        for tile_v in range(N_tiles_y):
            # Pixel bounds for this tile
            u_start = tile_u * tile_size
            v_start = tile_v * tile_size
            u_end = min(u_start + tile_size, width)
            v_end = min(v_start + tile_size, height)
            
            # Get range of Gaussians for this tile from sorted list
            range_idx = tile_u * N_tiles_y + tile_v
            start_idx = tile_ranges[range_idx, 0]
            end_idx = tile_ranges[range_idx, 1]
            
            # Extract Gaussians for this tile
            if start_idx >= end_idx:
                continue
                
            tile_gaussian_indices = sorted_gaussian_indices[start_idx:end_idx]
            
            # Fetch properties for these Gaussians
            g_indices = tile_gaussian_indices
            g_means = means2D[g_indices]
            g_conics = conics[g_indices]
            g_opacities = opacities[g_indices]
            g_colors = colors[g_indices]
            
            # Rasterize pixels in this tile
            for u_pix in range(u_start, u_end):
                for v_pix in range(v_start, v_end):
                    accumulated_color = torch.zeros(3)
                    accumulated_alpha = 0.0
                    transmittance = 1.0
                    
                    # Iterate Gaussians back-to-front (sorted by depth)
                    for k in range(len(g_indices)):
                        idx = g_indices[k]
                        mean = g_means[k]
                        conic = g_conics[k]
                        alpha_g = g_opacities[k]
                        color_g = g_colors[k]
                        
                        du = u_pix - mean[0]
                        dv = v_pix - mean[1]
                        
                        # Mahalanobis distance
                        a, b, c = conic
                        dist_sq = a * du**2 + 2 * b * du * dv + c * dv**2
                        
                        # Pixel opacity
                        pixel_alpha = alpha_g * math.exp(-0.5 * dist_sq)
                        
                        if pixel_alpha < 1e-4:
                            continue
                            
                        # Alpha blending
                        accumulated_color += color_g * pixel_alpha * transmittance
                        accumulated_alpha += pixel_alpha * transmittance
                        transmittance *= (1.0 - pixel_alpha)
                        
                        # Early termination
                        if transmittance < 0.01:
                            break
                    
                    # Add background
                    final_color = accumulated_color + bg * (1.0 - accumulated_alpha)
                    out_color[:, v_pix, u_pix] = final_color
                    out_alpha[v_pix, u_pix] = accumulated_alpha
                    
    return out_color, out_alpha
```

**Parameters:**
*   `tile_size`: Default 16x16 or 32x32 pixels [S1, S6, unofficial].
*   `sigma_multiplier`: Multiplier for Gaussian extent, typically 3.0 [S6, unofficial].
*   `visible_gaussian_threshold`: Opacity threshold for culling, often 0.01 [S4, unofficial].

**Edge Cases and Pitfalls:**
*   **Non-RGB Channels:** If the scene uses non-RGB channels (NUM_CHANNELS != 3) and precomputed colors are not provided, the rasterizer throws a runtime error [S4, S5, unofficial].
*   **Invisible Gaussians:** Gaussians with `tiles_touched == 0` must be skipped during key generation to avoid invalid memory writes [S5, unofficial].
*   **Precision:** The method is restricted to pinhole cameras and cannot compute arbitrary light paths (e.g., reflections) [S8].
*   **Wasted Computation:** Rasterization evaluates all Gaussians overlapping a tile for every pixel, leading to wasted computation for small Gaussians [S8].

## Operating characteristics
*   **Time Complexity:** $O(N \log N)$ for sorting $N$ Gaussians, followed by $O(P \cdot T)$ for rasterization where $P$ is pixels and $T$ is average Gaussians per tile. Early termination reduces effective $T$ [S1, S4, unofficial].
*   **Memory Complexity:** $O(N)$ for Gaussian buffers and $O(W \cdot H)$ for image buffers [S4, S5, unofficial].
*   **Performance:** Achieves real-time rendering (100+ FPS) for scenes with millions of Gaussians on modern GPUs [S1, unofficial].
*   **Strengths:** Differentiable, highly optimized for GPU parallelism, supports real-time training and rendering [S1, S3, unofficial].
*   **Limitations:** Restricted to pinhole cameras, linear scaling with Gaussian count regardless of size, potential wasted computation for small splats [S8].

## Background
Originated with the 3D Gaussian Splatting paper [S1, unofficial], this method was developed to enable real-time differentiable rendering of 3D scenes represented by Gaussian primitives. It builds on earlier splatting techniques but introduces tile-based binning and sorting to handle the large number of primitives efficiently [S1, S4, unofficial]. It is widely used in 3DGS training pipelines and novel view synthesis applications [S1, S5, unofficial].
