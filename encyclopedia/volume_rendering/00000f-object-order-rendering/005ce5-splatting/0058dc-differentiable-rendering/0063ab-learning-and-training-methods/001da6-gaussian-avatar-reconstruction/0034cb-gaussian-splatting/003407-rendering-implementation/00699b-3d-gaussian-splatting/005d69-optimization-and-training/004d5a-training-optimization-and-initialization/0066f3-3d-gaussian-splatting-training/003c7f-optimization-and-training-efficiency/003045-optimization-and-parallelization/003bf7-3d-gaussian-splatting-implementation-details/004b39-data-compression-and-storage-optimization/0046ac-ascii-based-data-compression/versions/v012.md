# ASCII-Based Data Compression

Also called: Anywhere Compression, Base 94 Floating-Point Compression, Base 95 Integer Compression

## Overview
This method reduces the storage footprint and improves data transmission speed during the training of 3D Gaussian Splatting by encoding numerical attributes into compact ASCII strings [S1, unofficial]. It distinguishes itself from sibling methods like [Sensitivity-Aware Vector Clustering](12167-sensitivity-aware-vector-clustering.md) and [Compact 3D Gaussian Representation (C3DGS)](12927-compact-3d-gaussian-representation-c3dgs.md) by using character-based base-N encoding rather than vector quantization or neural field prediction, specifically targeting the overhead of transmitting Gaussian parameters between devices or processes [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: Numerical values (integers or floating-point numbers) representing Gaussian attributes (e.g., position, scale, rotation, SH coefficients).
- Output: A string of ASCII characters representing the compressed value.

**Data Structures:**
- The compressed data is stored as a sequence of ASCII characters.
- Integer values are mapped to a single character.
- Floating-point values are mapped to a sequence of characters: one for the integer part, a delimiter, and one or more for the fractional part.

**Steps:**

1.  **Integer Compression (Base 95):**
    - Select ASCII characters with codes 32 to 126 (inclusive). This provides 95 distinct characters.
    - Map the integer value $v$ (where $0 \le v \le 95$) to the corresponding ASCII character.
    - *Note:* The source states the range is $[0, 95]$, which implies a base-96 interpretation if 96 values are covered, but explicitly calls it "base 95". Given characters 32-126, there are $126 - 32 + 1 = 95$ characters. The range $[0, 95]$ contains 96 integers. This is a contradiction in the source. We assume the standard base-95 interpretation: values $0 \dots 94$ are encoded. If the source insists on $[0, 95]$, it may imply a different mapping or a typo. We will follow the explicit character range: 95 characters for values $0 \dots 94$. [S1, unofficial]

2.  **Floating-Point Compression (Base 94):**
    - Select ASCII characters with codes 32 to 125 (inclusive) for the integer part. This provides 94 distinct characters.
    - Select ASCII character 126 (`~`) as the delimiter between the integer and fractional parts.
    - Encode the integer component $I$ of the floating-point number using the Base 94 mapping (values $0 \dots 93$).
    - Encode the fractional part. The source describes splitting the string into integer part $I$ and decimal places $d$.
    - The final value is reconstructed as $f = I \times 10^{-d}$.
    - *Interpretation:* This formula suggests that $d$ is not the fractional digits themselves, but the *number of decimal places* or a scaling factor. However, the text says "ASCII string for the decimal places d". If $d$ is a single character representing the decimal places count, the precision is very low. A more likely interpretation for "decimal places" in this context is that the fractional part is also encoded, but the formula $f = I \times 10^{-d}$ is explicitly given. We will use the explicit formula. [S1, unofficial]

3.  **Color Matrix Optimization:**
    - The color matrix values are constrained to the range $[0.0, 2.0]$.
    - Each value is rounded to one decimal place.
    - This results in 21 possible values ($0.0, 0.1, \dots, 2.0$).
    - These values are compressed using the ASCII compression algorithm.
    - This significantly reduces the data size for color attributes. [S1, unofficial]

4.  **Decoding:**
    - **Integer:** Convert the ASCII character back to its decimal integer value using the Base 95 mapping.
    - **Floating-Point:**
        - Split the ASCII string at the delimiter (ASCII 126).
        - Decode the integer part $I$ from the first segment.
        - Decode the decimal places $d$ from the second segment.
        - Calculate $f = I \times 10^{-d}$. [S1, unofficial]

**Parameters:**
- Integer Base: 95 (Characters 32-126).
- Floating-Point Integer Base: 94 (Characters 32-125).
- Delimiter: ASCII 126 (`~`).
- Color Precision: 1 decimal place.

**Edge Cases and Pitfalls:**
- **Matrix Traversal:** Compressing large color matrices is slow because traversing the matrix takes significant processing time. Using internal functions like `torch.where` and `torch.index_select` helps but is not fast enough for full replacement. [S1, unofficial]
- **Line Breaks:** Using line break characters in ASCII strings adds an extra operator in writing and decoding, which should be avoided. [S1, unofficial]
- **Range Mismatch:** The source claims Base 95 encoding for range $[0, 95]$, but 95 characters can only encode 95 distinct values ($0 \dots 94$). This discrepancy should be noted. [S1, unofficial]

def encode_integer(value):
    """
    Encode an integer value (0-94) to a single ASCII character.
    Note: Source claims range [0, 95] for Base 95, but 95 chars cover 0-94.
    We assume 0-94 for safety with 95 characters.
    """
    if value < 0 or value >= INT_BASE:
        raise ValueError(f"Integer value {value} out of range [0, {INT_BASE-1}]")
    return chr(INT_ASCII_START + value)

def decode_integer(char):
    """
    Decode a single ASCII character to an integer.
    """
    code = ord(char)
    if code < INT_ASCII_START or code > INT_ASCII_END:
        raise ValueError(f"Invalid integer ASCII character: {char}")
    return code - INT_ASCII_START

def decode_float(s):
    """
    Decode an ASCII string to a floating-point number.
    """
    parts = s.split(chr(DELIMITER_CHAR))
    if len(parts) != 2:
        raise ValueError("Invalid float string format")
    
    int_char = parts[0]
    d_char = parts[1]
    
    I = decode_integer(int_char)
    d = decode_integer(d_char)
    
    return I * (10 ** (-d))

def encode_color_matrix(matrix):
    """
    Compress a color matrix by rounding to 1 decimal place and encoding.

    # Round to 1 decimal place
    rounded_matrix = np.round(matrix, 1)

    indices = (rounded_matrix * 10).astype(int)

            raise ValueError(f"Color index {idx} out of range")
        compressed_chars.append(chr(INT_ASCII_START + idx))
        
    return "".join(compressed_chars)

## Operating characteristics
- **Training Speed Improvement:** The method gains about 6% or less improvement in training speed [S1, unofficial].
- **Storage Reduction:** Significant reduction in data size for color matrices due to reduced precision and ASCII encoding [S1, unofficial].
- **Limitations:**
    - Compressing large color matrices is slow due to traversal overhead. Internal PyTorch functions help but are not sufficient for full replacement [S1, unofficial].
    - The method is not suitable for all attributes, as only a few parts of the model can be optimized by this algorithm [S1, unofficial].
    - The formula for floating-point decoding is ambiguous and potentially incorrect as stated in the source [S1, unofficial].

## Background
This method was proposed in the paper "I3DGS: Improve 3D Gaussian Splatting from Multiple Dimensions" [S1, unofficial]. The research focuses on improving the training speed of 3D Gaussian Splatting by exploring various dimensions including color, learning, structure design, and compression. The ASCII-based compression is one of the proposed methods to reduce data transmission overhead during training.
