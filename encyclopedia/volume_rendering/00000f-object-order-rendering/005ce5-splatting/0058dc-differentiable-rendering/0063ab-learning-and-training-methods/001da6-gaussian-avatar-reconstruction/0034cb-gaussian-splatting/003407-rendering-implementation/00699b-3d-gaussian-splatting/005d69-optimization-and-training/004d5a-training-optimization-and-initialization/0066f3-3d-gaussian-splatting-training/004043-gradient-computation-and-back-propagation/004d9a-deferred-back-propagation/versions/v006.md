# Deferred Back-propagation

Also called: Deferred Gradient Computation, Patch-wise Gradient Accumulation

## Overview
Deferred back-propagation is a memory-efficient auto-differentiation technique that enables the optimization of radiance fields using full-resolution image losses, such as VGG-based style losses, despite limited GPU memory [S1]. Unlike sparse pixel sampling, which is insufficient for CNN-based losses requiring global context, this method decouples the forward render from the backward pass, allowing the memory footprint to scale with a small patch rather than the full image resolution [S1].

## How it works
The method solves the problem where standard differentiable volume rendering is too memory-intensive for full-resolution CNN losses because pixel color is composited from many samples [S1]. It operates by deferring the gradient computation from the full-resolution render to a patch-wise re-render [S1].

**Inputs:**
- A differentiable radiance field representation (e.g., 3D Gaussians).
- Camera parameters for the target viewpoint.
- A loss function $L$ defined on full-resolution images (e.g., NNFM or Gram matrix) [S1].
- Patch size $P \times P$ (small enough to fit in GPU memory with auto-differentiation enabled) [S1].

**Outputs:**
- Accumulated gradients for scene parameters (position, scale, rotation, color, opacity) [S1].

**Data Structures:**
- `cached_grads`: A 2D tensor of shape $(H, W, C)$ storing the gradient of the loss with respect to the rendered pixel colors $\frac{\partial L}{\partial \mathbf{C}}$. This is computed once and reused [S1].
- `param_grads`: Accumulator buffers for each scene parameter, initialized to zero [S1].

**Steps:**
1. **Full-Resolution Forward Pass (No Gradients):**
   Render the full-resolution image $\mathbf{C}_{full}$ from the target viewpoint with auto-differentiation disabled. This step consumes memory proportional to the output image size but not the intermediate computation graph [S1].

2. **Loss and Gradient Caching:**
   Compute the image loss $L(\mathbf{C}_{full})$ using the full-resolution image. Compute the gradient of the loss with respect to the pixel colors:
   $$
   \mathbf{G}_{cached} = \frac{\partial L}{\partial \mathbf{C}_{full}}
   $$
   Store $\mathbf{G}_{cached}$ in memory. This tensor has the same dimensions as the image [S1].

3. **Patch-wise Back-Propagation:**
   Iterate over all non-overlapping (or overlapping, depending on implementation, but typically non-overlapping for simplicity) patches $\mathcal{P}_i$ covering the image domain. For each patch:
   
   a. **Local Forward Pass (With Gradients):**
      Re-render only the pixels within patch $\mathcal{P}_i$ with auto-differentiation enabled. This generates a small computation graph [S1].
   
   b. **Local Gradient Computation:**
      Extract the cached gradient values corresponding to the pixels in $\mathcal{P}_i$ from $\mathbf{G}_{cached}$. Let this subset be $\mathbf{G}_{patch}$.
   
   c. **Back-Propagation:**
      Perform the backward pass for this patch using $\mathbf{G}_{patch}$ as the upstream gradient. Apply the chain rule to compute gradients for all scene parameters that influence the pixels in $\mathcal{P}_i$:
      $$
      \frac{\partial L}{\partial \theta} \leftarrow \frac{\partial L}{\partial \mathbf{C}_{patch}} \frac{\partial \mathbf{C}_{patch}}{\partial \theta}
      $$
      Accumulate these gradients into `param_grads` [S1].

4. **Optimization Step:**
   Use the accumulated `param_grads` to update the scene parameters [S1].

**Pseudocode:**
```python
def deferred_backprop(radiance_field, camera, loss_fn, patch_size):
    # Step 1: Render full-res image without gradients
    with torch.no_grad():
        C_full = radiance_field.render(camera)  # Shape: (H, W, C)
    
    # Step 2: Compute loss and cached gradients
    loss = loss_fn(C_full)
    # Compute gradient of loss w.r.t. pixel colors
    # Note: In practice, this requires a temporary backward pass or manual derivation
    # of the loss function's gradient.
    cached_grads = torch.autograd.grad(loss, C_full, retain_graph=True)[0]
    
    # Initialize parameter gradients
    param_grads = {p: torch.zeros_like(p) for p in radiance_field.parameters()}
    
    # Step 3: Patch-wise back-propagation
    H, W, C = C_full.shape
    for y in range(0, H, patch_size):
        for x in range(0, W, patch_size):
            y_end = min(y + patch_size, H)
            x_end = min(x + patch_size, W)
            
            # Define patch coordinates
            patch_coords = (slice(y, y_end), slice(x, x_end), slice(None))
            
            # Step 3a: Re-render patch with gradients enabled
            # The renderer must support rendering a subset of pixels or rays
            C_patch = radiance_field.render(camera, patch_coords)
            
            # Step 3b: Get cached gradients for this patch
            G_patch = cached_grads[patch_coords]
            
            # Step 3c: Back-propagate
            # Compute gradients for parameters affecting this patch
            grads = torch.autograd.grad(
                C_patch, 
                radiance_field.parameters(), 
                grad_outputs=G_patch, 
                retain_graph=True
            )
            
            # Accumulate gradients
            for p, g in zip(radiance_field.parameters(), grads):
                if g is not None:
                    param_grads[p] += g
    
    return param_grads
```

**Edge Cases and Pitfalls:**
- **Memory:** The method assumes the patch size is small enough to fit the full computation graph (including intermediate samples for alpha-compositing) in GPU memory [S1].
- **Loss Type:** This method is specifically designed for losses that require full-resolution inputs (e.g., VGG, Gram matrix). It is overkill for per-pixel losses like L1/L2, where sparse sampling is more efficient [S1].
- **Gradient Consistency:** The cached gradients must be computed correctly with respect to the *full* image, even though the backward pass is performed on patches. The chain rule ensures that the contribution of each patch to the total loss gradient is correctly isolated [S1].

## Operating characteristics
- **Time Complexity:** $O(N \cdot P)$, where $N$ is the number of pixels and $P$ is the patch size. The forward pass is done once, and the backward pass is done $N/P$ times. This is slower than a single full-resolution backward pass but avoids the memory crash.
- **Memory Complexity:** $O(H \cdot W + P^2 \cdot S)$, where $H, W$ are image dimensions, and $S$ is the number of samples per ray. The dominant term is the cached gradient image $O(H \cdot W)$, which is smaller than the full computation graph of a differentiable full-res render [S1].
- **Strengths:** Enables the use of sophisticated CNN-based losses (style, perceptual) on high-resolution images for radiance fields [S1].
- **Limitations:** Requires two forward passes per iteration (one non-differentiable, one differentiable per patch). Not suitable for real-time training if patch re-rendering is slow [S1].

## Background
Deferred back-propagation was introduced in the context of "Artistic Radiance Fields" (ARF) for 3D scene stylization [S1]. The authors noted that volumetric radiance field rendering consumes significant memory, often forcing training to regress on sparsely sampled pixels, which is insufficient for computing VGG features used in style losses [S1]. The method was developed to allow optimization on high-resolution images by accumulating cached gradients in a patch-wise fashion [S1].
