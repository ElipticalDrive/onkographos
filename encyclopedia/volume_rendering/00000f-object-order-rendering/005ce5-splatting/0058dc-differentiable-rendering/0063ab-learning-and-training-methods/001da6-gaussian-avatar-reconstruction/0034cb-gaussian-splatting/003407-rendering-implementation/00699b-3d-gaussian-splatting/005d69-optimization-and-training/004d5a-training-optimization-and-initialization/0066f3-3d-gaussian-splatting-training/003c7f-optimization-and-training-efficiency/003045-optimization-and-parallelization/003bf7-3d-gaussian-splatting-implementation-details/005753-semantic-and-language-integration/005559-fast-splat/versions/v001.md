# FAST-Splat

Also called: Fast, Ambiguity-Free Semantic Transfer in Gaussian Splatting

## Overview
FAST-Splat is a semantic Gaussian Splatting method that directly augments each Gaussian primitive with specific semantic codes and uses a hash-table for disambiguation, avoiding neural fields for semantic distillation to enable fast training, rendering, and ambiguity-free object localization [S1, unofficial]. It distinguishes itself from sibling methods like [LangSplat Training Procedure](12438-langsplat-training-procedure.md) and [Feature-3DGS](12925-desplat.md) by employing a single-phase, neural-free training procedure that jointly optimizes geometric, visual, and semantic attributes, thereby preserving the explicit representation's speed benefits while resolving semantic ambiguity in open-vocabulary queries [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A dataset of RGB images $\mathcal{D}$; optional closed-set object detector (e.g., YOLO, DETR) for initialization; open-set object detector (e.g., GroundingDINO); segmentation model (SAM-2); pre-trained text encoder (e.g., CLIP, BERT).
*   **Outputs:** Optimized Gaussian Splatting parameters (means, covariances, opacities, SH coefficients, semantic codes $\beta$, affine matrix $W$); a hash-table of identified object classes; a system capable of rendering semantic feature maps and providing disambiguated labels for natural language queries.

**Data Structures:**
*   **Gaussian Attributes:** Each ellipsoid $i$ stores:
    *   Mean position $\mu_i \in \mathbb{R}^3$.
    *   Covariance matrix $\Sigma_i$ (or rotation/scale representation).
    *   Opacity $\alpha_i$.
    *   Spherical Harmonic coefficients for color.
    *   Semantic code $\beta_i \in \mathbb{R}^3$.
*   **Hash-Table (Dictionary):** A mapping of object class indices $c \in \{1, \dots, N\}$ to semantic labels and pre-computed text embeddings $\theta_d$. $N$ is the size of the dictionary.
*   **Affine Transformation:** A learnable matrix $W$ used to map $\beta$ to the dictionary space.

**Numbered Steps:**

1.  **Initialization:** Initialize the Gaussian Splatting model (means, covariances, opacities, SH parameters) from a sparse point cloud obtained via structure-from-motion [S1, unofficial]. Initialize semantic codes $\beta_i$ and affine matrix $W$.

2.  **Semantic Dictionary Construction:**
    *   Feed each image $I \in \mathcal{D}$ into an object detector (closed-set or open-set) to generate object lists and bounding boxes [S1, unofficial].
    *   Generate dense semantic maps using SAM-2, passing each object class and its bounding box [S1, unofficial].
    *   Maintain a dictionary (hash-table) of identified objects. Augment object classes with an "undetected" class label to handle pixels not segmented during preprocessing [S1, unofficial].

3.  **Single-Phase Joint Optimization:**
    *   Simultaneously optimize all attributes (geometric, visual, semantic $\beta$, and affine $W$) in a single phase using gradient descent with the Adam optimizer [S1, unofficial].
    *   **Visual Loss:** Compute the standard Gaussian Splatting loss $L_{gs}$:
        $$ L_{gs} = (1 - \lambda) \sum_{I \in \mathcal{D}} \| I - \hat{I} \| + \lambda L_{D-SSIM} $$
        where $\lambda \in [0, 1]$ balances the L1-loss and differentiable structural similarity (D-SSIM) loss, $I$ is the ground-truth image, and $\hat{I}$ is the rendered image [S1, unofficial].
    *   **Semantic Loss:** Compute the cross-entropy loss $L_{ce}$ to align rendered semantic features with the dictionary:
        $$ L_{ce} = - \sum_{I \in \mathcal{D}} \sum_{p \in \mathcal{T}_I} \gamma_p \log \left( \frac{\exp(F_{I,p,c})}{\sum_{j=1}^{N} \exp(F_{I,p,j})} \right) $$
        where $\mathcal{T}_I$ is the set of pixel indices in image $I$, $c$ is the true class of pixel $p$, $\gamma_p$ is the pixel weight (lower for undetected classes), and $F_{I,p}$ is the semantic feature vector for pixel $p$ in image $I$ [S1, unofficial].
    *   **Total Loss:**
        $$ L_{sgs} = L_{gs} + L_{ce} $$
    *   **Semantic Feature Prediction:** For each ellipsoid, apply the affine transformation $W$ to $\beta$ to map it to an $N$-dimensional space, then apply softmax to define a probability distribution over the dictionary entries [S1, unofficial]. Render a semantic feature map using differentiable tile-based rasterization, transforming each pixel's semantic feature to this probability distribution [S1, unofficial].

4.  **Open-Vocabulary Query Processing (Runtime):**
    *   Pre-compute text embeddings $\theta_d$ for each dictionary entry using a pre-trained text encoder (e.g., CLIP) without fine-tuning [S1, unofficial].
    *   Given a user query, compute the text embedding $\theta_q$ using the same pre-trained encoder [S1, unofficial].
    *   Compute a relevancy score for each dictionary entry as the pairwise softmax between cosine-similarity values of $\theta_d$ and $\theta_q$ (positive) plus canonical negative embeddings [S1, unofficial].
    *   Designate entries exceeding a relevancy score threshold as similar to the query [S1, unofficial].
    *   Map these entries to pixels in the rendered feature map using the softmax probability distribution. Assign a label to each pixel by taking the maximum probability value (or using conformal prediction) [S1, unofficial]. This provides a clarifying semantic label to disambiguate the identity of localized objects (e.g., identifying a "coffee machine" when queried for "tea") [S1, unofficial].

**Parameters:**
*   $\lambda \in [0, 1]$: Weighting parameter balancing L1-loss and D-SSIM loss. Typical value: 0.2 [S1, unofficial].
*   $\beta \in \mathbb{R}^3$: Semantic parameter for each ellipsoid. Dimension 3 is used to enable rasterization compatibility, though not strictly limited to it [S1, unofficial].
*   Relevancy Score Threshold: Threshold for determining if a dictionary entry is similar to the query. Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Ambiguity:** Users may query with semantically similar but distinct objects (e.g., "tea" vs. "coffee machine"). FAST-Splat resolves this by providing the precise semantic label of the localized object, unlike methods that only localize [S1, unofficial].
*   **Undetected Pixels:** Pixels not segmented by SAM-2 are assigned an "undetected" class label with lower weights in the loss function to ensure stability [S1, unofficial].
*   **Precision:** The method relies on the accuracy of the open-set detector and SAM-2 for dictionary construction. Errors here propagate to the semantic codes [S1, unofficial].

## Operating characteristics
*   **Training Speed:** 6x to 8x faster than prior work (e.g., LangSplat, Feature-3DGS) [S1, unofficial].
*   **Rendering Speed:** 18x to 51x faster than prior work [S1, unofficial].
*   **GPU Memory:** Approximately 6x smaller than prior work [S1, unofficial].
*   **Performance Metrics (3D-OVS Dataset):**
    *   **Bed Scene:** SSIM: 0.971, PSNR: 34.24, GPU: 1.02GB, mIoU: 0.933, Localization Accuracy: 0.998, Training Time: 13.96 mins [S1, unofficial].
    *   **Covered-Desk Scene:** mIoU: 0.913, Localization Accuracy: 0.995, Training Time: 13.96 mins [S1, unofficial].
*   **Strengths:** Fast training and rendering due to neural-free, single-phase optimization; ambiguity-free semantic localization; low memory usage.
*   **Limitations:** Relies on external detectors (YOLO, GroundingDINO, SAM-2) for dictionary construction; performance depends on the quality of these detectors; open-vocabulary query performance depends on the pre-trained text encoder (e.g., CLIP) [S1, unofficial].

## Background
FAST-Splat was introduced by Ola Shorinwa, Jiankai Sun, and Mac Schwager from Stanford University in the paper "FAST-Splat: Fast, Ambiguity-Free Semantics Transfer in Gaussian Splatting" (arXiv:2411.13753v2, March 12, 2025) [S1, unofficial]. It addresses limitations of existing semantic Gaussian Splatting methods, such as slow training/rendering, high memory usage, and ambiguous object localization, by leveraging the explicit nature of Gaussian primitives to avoid neural fields [S1, unofficial].
