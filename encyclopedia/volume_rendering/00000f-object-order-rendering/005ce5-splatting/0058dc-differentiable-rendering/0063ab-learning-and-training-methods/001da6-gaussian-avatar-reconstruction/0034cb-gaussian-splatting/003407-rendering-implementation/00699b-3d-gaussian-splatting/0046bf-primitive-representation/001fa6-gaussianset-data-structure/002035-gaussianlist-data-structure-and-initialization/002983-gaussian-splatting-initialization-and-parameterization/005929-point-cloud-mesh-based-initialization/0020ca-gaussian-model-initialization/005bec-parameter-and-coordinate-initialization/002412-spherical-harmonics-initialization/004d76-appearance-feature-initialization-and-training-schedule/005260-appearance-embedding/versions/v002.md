# Appearance Embedding

Also called: Image-specific Embedding, NeRF in the Wild, WildConvexes, WildGaussians

## Overview
Appearance Embedding is a technique for modeling appearance variations, such as lighting changes and shadows, by associating each training image with a unique learnable embedding vector [S1, S2, unofficial]. It solves the problem of inconsistent color prediction in scenes with varying illumination by incorporating these embeddings as an extra input when computing the color of a point or primitive [S2, unofficial]. Unlike vanilla methods that assume static lighting, this approach optimizes per-image lighting conditions jointly with scene parameters [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of training images with known poses; for each image $i$, a unique embedding vector $e_i$ is learned.
*   **Output:** A rendered image where color is conditioned on the specific image's appearance embedding.

**Data Structures:**
*   **Appearance Embedding:** A learnable vector $e_i \in \mathbb{R}^d$.
    *   **Dimension ($d$):** 8 [S1, unofficial].
    *   **Initialization:** Not specified in sources [G]. Typically random or zero-initialized in similar contexts, but exact initialization is not given.

**Steps:**
1.  **Initialization:** Create a unique embedding vector $e_i$ for each training image $i$.
2.  **Optimization:** During training, optimize the scene parameters (e.g., Gaussian attributes, positions) jointly with the appearance embeddings $\{e_i\}$ [S2, unofficial].
3.  **Color Computation:** When rendering a pixel for image $i$, compute the color $C$ using the scene's geometric/radiance representation and the specific embedding $e_i$ as an additional input [S2, unofficial]. The exact functional form $C = f(\dots, e_i)$ depends on the underlying renderer (e.g., MLP, Gaussian attributes), but the embedding is always incorporated as an extra input [S2, unofficial].
4.  **Validation Handling:** For validation images, the specific appearance embedding is unknown. Calculate the mean of the appearance embeddings from all training images:
    $$ \bar{e} = \frac{1}{N} \sum_{i=1}^{N} e_i $$
    where $N$ is the number of training images. Use $\bar{e}$ as the appearance embedding for all validation images to ensure consistent representation [S1, unofficial].

**Parameters:**
*   **Embedding Dimension:** 8 [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Validation:** Using the mean embedding is a heuristic to handle unknown lighting conditions during validation [S1, unofficial].
*   **Precision:** Not specified [G].

## Subtopics

### Feature Embedding for Illumination
A variant that replaces spherical harmonics with a feature embedding $f$ and a trainable per-image embedding $e$ to handle intense illumination changes, such as multiple light sources in indoor scenes [S3]. It retains the opacity parameter $\alpha$ consistent with standard 2D Gaussian Splatting [S3]. This approach is used when spherical harmonics are insufficient for modeling complex lighting [S3].

## Operating characteristics
*   **Time Complexity:** Adds overhead to training due to the optimization of additional parameters (one vector per image). Inference time may increase slightly if the embedding is concatenated with other features.
*   **Memory Complexity:** Increases memory usage by $N \times d$ bytes, where $N$ is the number of training images and $d=8$ is the embedding dimension [S1, unofficial]. This is negligible compared to scene geometry/radiance storage.
*   **Performance:** Improves robustness to lighting variations and can mitigate floater artifacts in geometry-critical tasks [S2, unofficial]. Originally designed to improve robustness to lighting [S2, unofficial].
*   **Strengths:** Handles dynamic lighting, shadows, and appearance changes effectively [S1, S2, unofficial].
*   **Limitations:** Requires per-image optimization; validation requires a heuristic (mean embedding) [S1, unofficial].
*   **When to use:** Scenes with varying illumination, shadows, or appearance changes across images [S1, S2, unofficial].
*   **When not to use:** Static lighting scenes where vanilla methods suffice, or when memory is extremely constrained (though impact is small).

## Background
Appearance embeddings were originally introduced in "NeRF in the Wild" [S2, unofficial] to address lighting variations in space-based scenarios and other uncontrolled environments [S2, unofficial]. The concept has been extended to various rendering frameworks, including K-Planes (WildGaussians) and Convex Splatting (WildConvexes) [S2, unofficial]. It is commonly used in large-scale scene reconstruction where lighting consistency is challenging [S1, unofficial].
