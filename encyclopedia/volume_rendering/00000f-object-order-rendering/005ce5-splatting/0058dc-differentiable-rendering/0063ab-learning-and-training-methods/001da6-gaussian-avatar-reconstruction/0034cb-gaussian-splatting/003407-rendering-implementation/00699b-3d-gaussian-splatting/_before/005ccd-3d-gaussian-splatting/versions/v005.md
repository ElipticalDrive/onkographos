# 3D Gaussian Splatting
Also called: 3D Gaussian Splats, 3DGS, Tetrahedron Splatting, dGS Conditional Slicing, direct Gaussian Splatting conditional slicing

## Overview
3D Gaussian Splatting (3DGS) is a particle-based discretization method for representing 3D scenes using ellipsoids (3D Gaussians) that are projected into 2D screen-space Gaussians and rendered via alpha blending, enabling real-time differentiable rendering [S2, S5, unofficial]. It solves the problem of high-fidelity, real-time renderable scene reconstruction from multiple calibrated images by replacing implicit neural fields with explicit, learnable Gaussian distributions [S2, S5, unofficial]. Unlike NeRF, which uses an MLP to represent a continuous function requiring expensive ray marching to integrate density along a ray, 3DGS uses explicit particle positions, allowing direct contribution sampling without extensive ray marching [S2, unofficial]. It sets itself apart from siblings like [Neural Radiance Fields](4972-neural-radiance-fields.md) by using explicit, analytically tractable basis functions that can be efficiently rasterized, and from [Hierarchical Grid Optimization](1414-hierarchical-grid-optimization.md) by avoiding the discretization of space into voxels in favor of continuous, learnable Gaussian distributions [G].

## How it works
**Inputs:** A set of $N$ calibrated images with known camera poses (extrinsics $E_i$ and intrinsics $K_i$) and a bounding volume containing the scene [S5, unofficial].
**Outputs:** A trained set of $M$ 3D Gaussian primitives, each defined by a mean position $\mu$, a covariance matrix $\Sigma$ (parameterized by rotation $R$ and scale $S$), an opacity $\alpha$, and spherical harmonics (SH) coefficients $c_{lm}$ for view-dependent color [S2, S5, unofficial].

**Data Structures:**
The scene is stored in a `GaussianSet` [S1], which organizes the parameters into fixed-layout tensors for batch processing. Each Gaussian $i$ has the following attributes:
*   $\mu_i \in \mathbb{R}^3$: Mean position [S2, unofficial].
*   $R_i \in SO(3)$: Rotation matrix (stored as a quaternion $q_i \in \mathbb{R}^4$) [S2, unofficial].
*   $S_i \in \mathbb{R}^3$: Scale vector (log-scale for optimization stability) [S2, S5, unofficial].
*   $\alpha_i \in [0, 1]$: Opacity [S2, unofficial].
*   $c_{i, lm} \in \mathbb{R}^3$: SH coefficients for $L$ bands (typically $L=3$ or $4$), representing view-dependent color [S2, S5, unofficial].

The covariance matrix $\Sigma_i$ in 3D space is constructed as:
$$ \Sigma_i = R_i S_i S_i^T R_i^T $$
where $S_i$ is a diagonal matrix with entries $S_i$ [G].

**Rendering Pipeline (Forward Pass):**
1.  **Sorting:** Gaussians are sorted by their depth along the ray to ensure correct alpha-blending order. This is typically done by projecting the 3D mean $\mu_i$ to 2D and sorting by the projected depth $z_i$ [S2, unofficial].
2.  **Projection:** The 3D covariance $\Sigma_i$ is projected to 2D using the Jacobian of the perspective projection. Let $J$ be the Jacobian of the affine approximation of the projection matrix at $\mu_i$. The 2D covariance $\Sigma'_i$ is:
    $$ \Sigma'_i = J W \Sigma_i W^T J^T $$
    where $W$ is the view matrix. The resulting $2 \times 2$ matrix is decomposed into a mean $\mu'_i$ and covariance $\Sigma'_i$ in screen space [G].
3.  **Rasterization:** For each pixel, the contribution of each Gaussian is computed. The 2D Gaussian density at pixel $u$ is:
    $$ G_i(u) = \exp\left(-\frac{1}{2} (u - \mu'_i)^T (\Sigma'_i)^{-1} (u - \mu'_i)\right) $$
    The opacity contribution is $\alpha_i G_i(u)$ [S2, unofficial].
4.  **Alpha-Blending:** The final color $C(u)$ is computed via standard alpha-compositing:
    $$ C(u) = \sum_{i=1}^{M} c_i(u) \alpha_i G_i(u) \prod_{j=1}^{i-1} (1 - \alpha_j G_j(u)) $$
    where $c_i(u)$ is the color of Gaussian $i$ at viewing direction $u$, retrieved from the SH coefficients [S2, S5, unofficial].

**Optimization (Backward Pass):**
The parameters are optimized using stochastic gradient descent (typically Adam) to minimize a loss function $L$ between the rendered image $C(u)$ and the ground truth image $I(u)$:
$$ L = (1 - \lambda) L_1(C(u), I(u)) + \lambda L_{D-SSIM}(C(u), I(u)) $$
where $L_1$ is the L1 loss and $L_{D-SSIM}$ is the differentiable SSIM loss [S5, unofficial].

**Densification and Pruning:**
To handle varying scene complexity, 3DGS employs a dynamic densification strategy [S2, unofficial]:
1.  **Tracking:** Accumulate positional gradients for each Gaussian over training steps [S2, unofficial].
2.  **Densification:** If a Gaussian has a high gradient magnitude and is small (scale below a threshold), it is split into two new Gaussians. If it is large and has low gradient, it is cloned [S2, unofficial].
3.  **Pruning:** If a Gaussian has low opacity and is small, it is removed [S2, unofficial].
This process is repeated periodically during training [S2, unofficial]. Optimization begins by optimizing only the zero-order spherical harmonic component to ensure correct diffuse coloring, introducing new SH bands every 1,000 iterations to prevent premature fitting of higher-order view-dependent components [S2, unofficial].

**Pseudocode:**
```python
import math
import numpy as np

def quaternion_to_rotation_matrix(q):
    """Converts a quaternion (w, x, y, z) to a 3x3 rotation matrix."""
    w, x, y, z = q
    return np.array([
        [1 - 2*(y*y + z*z), 2*(x*y - w*z),     2*(x*z + w*y)],
        [2*(x*y + w*z),     1 - 2*(x*x + z*z), 2*(y*z - w*x)],
        [2*(x*z - w*y),     2*(y*z + w*x),     1 - 2*(x*x + y*y)]
    ])

def compute_projection_jacobian(mu, camera):
    """Computes the 2x3 Jacobian of the perspective projection at mu."""
    fx, fy = camera.fx, camera.fy
    z = mu[2]
    return np.array([
        [fx / z, 0, -fx * mu[0] / (z * z)],
        [0, fy / z, -fy * mu[1] / (z * z)]
    ])

def project_point(mu, camera):
    """Projects a 3D point to 2D screen coordinates."""
    fx, fy = camera.fx, camera.fy
    cx, cy = camera.cx, camera.cy
    z = mu[2]
    return np.array([fx * mu[0] / z + cx, fy * mu[1] / z + cy])

def get_bounding_box(mu_2d, sigma_2d, margin=3):
    """Computes integer pixel bounds for a 2D Gaussian."""
    std_x = math.sqrt(sigma_2d[0, 0])
    std_y = math.sqrt(sigma_2d[1, 1])
    min_x = int(math.floor(mu_2d[0] - margin * std_x))
    max_x = int(math.ceil(mu_2d[0] + margin * std_x))
    min_y = int(math.floor(mu_2d[1] - margin * std_y))
    max_y = int(math.ceil(mu_2d[1] + margin * std_y))
    return min_x, max_x, min_y, max_y

def evaluate_sh(sh_coeffs, view_dir):
    """Evaluates spherical harmonics coefficients for a given view direction."""
    return sh_coeffs[0]

def render_3dgs(gaussians, camera, image_size):
    H, W = image_size
    image = np.zeros((H, W, 3))
    transmittance = np.ones((H, W))

    projected_gaussians = []
    for g in gaussians:
        R = quaternion_to_rotation_matrix(g.q)
        S = np.diag(g.s)
        Sigma_3d = R @ S @ S.T @ R.T

        J = compute_projection_jacobian(g.mu, camera)
        W_mat = camera.view_matrix
        Sigma_2d = J @ W_mat @ Sigma_3d @ W_mat.T @ J.T

        mu_2d = project_point(g.mu, camera)
        projected_gaussians.append({
            'mu_2d': mu_2d,
            'Sigma_2d': Sigma_2d,
            'alpha': g.alpha,
            'sh_coeffs': g.sh_coeffs,
            'mu_3d': g.mu
        })

    projected_gaussians.sort(key=lambda g: g['mu_3d'][2])

    for g in projected_gaussians:
        mu_2d = g['mu_2d']
        Sigma_2d = g['Sigma_2d']
        alpha = g['alpha']
        sh_coeffs = g['sh_coeffs']

        min_x, max_x, min_y, max_y = get_bounding_box(mu_2d, Sigma_2d)
        min_x, max_x = max(0, min_x), min(W, max_x)
        min_y, max_y = max(0, min_y), min(H, max_y)

        for y in range(min_y, max_y):
            for x in range(min_x, max_x):
                dist = (x - mu_2d[0])**2 / Sigma_2d[0,0] + (y - mu_2d[1])**2 / Sigma_2d[1,1]
                G = math.exp(-0.5 * dist)
                color = evaluate_sh(sh_coeffs, np.array([x, y]))
                T = transmittance[y, x]
                image[y, x] += color * alpha * G * T
                transmittance[y, x] *= (1 - alpha * G)

    return image

def optimize_3dgs(gaussians, images, cameras, num_steps):
    for step in range(num_steps):
        cam_idx = step % len(cameras)
        camera = cameras[cam_idx]
        gt_image = images[cam_idx]
        rendered_image = render_3dgs(gaussians, camera, image_size=gt_image.shape)
        loss = np.mean(np.abs(rendered_image - gt_image))
        # Backpropagation and optimizer step omitted for brevity
        if step % 100 == 0:
            gaussians.densify_and_prune()
```

## Subtopics

### [3DGS Initialization Policy](1398-3dgs-initialization-policy.md)
The 3DGS Initialization Policy defines the deterministic starting configuration for the set of 3D Gaussian primitives in a scene, solving the problem of arbitrary initial placement by providing a reproducible baseline for optimization. It sets apart from heuristic or random initialization strategies by using a fixed power-law scaling for the initial opacity/OTS weight and a uniform random distribution within a bounding volume.

### [CoR-GS](1486-cor-gs.md)
CoR-GS is a method designed to improve sparse-view reconstruction in 3D Gaussian Splatting by defining two independent reconstructions and comparing them to discard inaccurate Gaussians. It addresses the ambiguity and instability inherent in reconstructing scenes from minimal view overlap, where standard optimization often yields noisy or inconsistent geometry. It differs from feed-forward network approaches by relying on a consistency check between dual optimization paths to prune erroneous primitives.

### [GaussianSet Data Structure](2074-gaussianset-data-structure.md)
The GaussianSet is the primary container for the explicit scene representation in 3D Gaussian Splatting, storing the parametric attributes of millions of anisotropic 3D Gaussian primitives. It solves the problem of efficiently managing and computing with large sets of spatial primitives by organizing means, orientations, scales, opacities, and spherical harmonics (SH) coefficients into fixed-layout tensors. It sets itself apart from the [GaussianList Data Structure](2214-gaussianlist-data-structure-and-initialization.md) by providing the high-level logical grouping and covariance computation logic, whereas the GaussianList exposes the raw memory layout for low-level batch processing.

### [Optical Flow Loss for 3D Gaussian Reconstruction](3303-optical-flow-loss-for-3d-gaussian-reconstruction.md)
This method improves the 3D shape reconstruction of static objects from video sequences by incorporating an optical flow loss term into the optimization objective. It leverages the temporal prior inherent in video data to resolve concavity/convexity ambiguities that are present when relying solely on silhouette and color loss terms. Unlike standard photometric approaches, this technique uses optical flow as a local estimator of surface correspondence, which is robust to long-term lighting changes and autoexposure variations common in user-captured videos.

### [EffGS](3365-effgs.md)
EffGS is an acceleration framework for 3D Gaussian Splatting that improves training and rendering efficiency while maintaining high-fidelity reconstruction in both bounded and large-scale scenes. It sets itself apart from standard 3DGS and other acceleration methods by combining frequency-aware guidance, localized density control, and adaptive primitive scale modulation to prevent quality degradation in complex environments.

### [3D Gaussian Splatting Training](3761-3d-gaussian-splatting-training.md)
3D Gaussian Splatting (3DGS) Training is the iterative optimization process that adjusts the geometric and appearance parameters of a set of 3D Gaussian primitives to minimize the difference between rendered images and ground truth views [3761-3d-gaussian-splatting-training.md]. It solves the problem of reconstructing high-fidelity, real-time renderable scenes from sparse or dense image collections by replacing implicit neural fields with explicit, differentiable volumetric primitives [3761-3d-gaussian-splatting-training.md]. Unlike NeRF-based methods which require expensive volume integration and neural network inference, 3DGS training optimizes a static set of ellipsoids using differentiable rasterization, achieving comparable image quality with significantly faster convergence and rendering speeds [3761-3d-gaussian-splatting-training.md].

### [MaskGaussian](4242-maskgaussian.md)
MaskGaussian is a differentiable pruning method for 3D Gaussian Splatting that models Gaussians as probabilistic entities rather than deterministically removing them based on static importance scores. It solves the problem of sub-optimal reconstruction caused by early pruning by introducing **masked-rasterization**, which allows gradients to flow to "masked-out" (inactive) Gaussians, enabling them to be re-evaluated and potentially reactivated as the scene evolves. Unlike sibling methods like [Compact3DGS](1398-compact3dgs.md) which use deterministic pruning or multiply masks with opacity/scale (blocking gradients), MaskGaussian applies masks during the alpha-blending stage, decoupling Gaussian existence from its geometric attributes.

### [Substitutive LOD with K-wise Moment-Matched Merging](4801-substitutive-lod-with-k-wise-moment-matched-merging.md)
Substitutive LOD with K-wise moment-matched merging is a technique for reducing the number of 3D Gaussians in a scene by merging groups of $K$ splats into a single representative Gaussian, thereby boosting rendering performance and managing memory constraints. It addresses the problem of excessive Gaussian counts and associated aliasing artifacts by replacing small or redundant Gaussians with larger, merged ones. Unlike methods that modify Gaussians during reconstruction or prune based on static importance, this method operates on the final set of Gaussians using cost metrics to guide the merging process, allowing for runtime LOD selection. It sets itself apart from siblings like [CoR-GS](1486-cor-gs.md) and [EffGS](3365-effgs.md) by focusing on substitutive merging via moment matching rather than density control or vector quantization.

### [Gaussian Conditional Probability Formulation](4937-gaussian-conditional-probability-formulation.md)
This method treats the unnormalized 4D Gaussian primitive as a special probability distribution over spatial coordinates $(u, v)$ and time $t$, enabling the factorization of the joint distribution into a temporal marginal and a conditional spatial component. This factorization allows for efficient rendering and optimization by decoupling temporal dynamics from spatial geometry, distinguishing it from static 3D Gaussian Splatting which lacks this probabilistic temporal modeling.

### [Radiative and Tomographic Gaussians](4971-radiative-and-tomographic-gaussians.md)
Radiative and Tomographic Gaussians adapt 3D Gaussian Splatting (3DGS) for X-ray imaging by replacing view-dependent color and opacity with view-independent scalar density or radiation intensity [Radiative Gaussian Splatting](3040-radiative-gaussian-splatting.md). This modification solves the problem of reconstructing volumetric data from 2D attenuation measurements, where radiation depends on the integrated density along the ray path rather than surface appearance [Radiative Gaussian Splatting](3040-radiative-gaussian-splatting.md). Unlike standard 3DGS, which uses spherical harmonics for view-dependent appearance, these methods remove angular dependence to model isotropic density fields [Radiative Gaussian Splatting](3040-radiative-gaussian-splatting.md).

### [Density Control and Densification](5337-density-control-and-densification.md)
Density Control and Densification is the mechanism in 3D Gaussian Splatting that dynamically adjusts the number, position, and scale of Gaussian primitives during optimization to improve reconstruction quality [3034-adaptive-densification.md, unofficial]. It addresses the limitation of standard gradient descent, which can only move, stretch, or fade existing Gaussians but cannot create new ones in empty regions or cleanly remove useless ones [3034-adaptive-densification.md, unofficial]. It differs from its siblings by relying on a simple threshold-based heuristic on accumulated positional gradients and spatial extent, whereas alternatives like [OTS+SAtn Densification](1488-ots-satn-densification.md) use attention mechanisms, and [Loss Accumulation Guided (LAG) Densification](3298-loss-accumulation-guided-lag-densification.md) uses loss accumulation [3034-adaptive-densification.md, unofficial].

### [Domain-Specific Adaptations](5621-domain-specific-adaptations.md)
Domain-Specific Adaptations modify the standard 3D Gaussian Splatting (3DGS) framework to handle non-RGB, non-photometric data such as medical volumes, microscopy stacks, and ultrasound probe intersections [1875-volumetric-gaussian-splatting-avis.md][3301-gaussian-splatting-for-microscopy.md][5170-ultragauss-rendering.md][8498-surface-and-mesh-extraction.md]. While standard 3DGS optimizes for novel-view synthesis of RGB scenes using calibrated camera poses and photometric losses, these adaptations replace the projection target with volumetric supervision, voxel-space rasterization, or 3D geometric intersections [1875-volumetric-gaussian-splatting-avis.md][3301-gaussian-splatting-for-microscopy.md][5170-ultragauss-rendering.md][8498-surface-and-mesh-extraction.md]. They solve the problem of reconstructing and visualizing high-dimensional or physically distinct data fields where traditional camera-based rendering is inapplicable or insufficient [G].

### [Dynamic 3D Gaussian Splatting](5703-dynamic-3d-gaussian-splatting.md)
Dynamic 3D Gaussian Splatting enables real-time novel view synthesis of dynamic scenes by maintaining a persistent set of Gaussian primitives whose parameters evolve over time. Unlike per-frame baselines that suffer from storage explosion and temporal flicker, this method tracks the position and rotation of each Gaussian across frames using local-rigid and As-Rigid-As-Possible (ARAP) or isometry constraints. It distinguishes itself from deformation-field approaches like [4D Gaussian Splatting](7992-4d-gaussian-splatting.md) by avoiding global deformation networks and instead relying on explicit temporal constraints on the primitive parameters themselves [G].

### [Epipolar 3D Gaussian Splatting](6070-epipolar-3d-gaussian-splatting.md)
Epipolar 3D Gaussian Splatting is a method that incorporates an epipolar transformer to generalize features between two views, pairing this with a probabilistic prediction of Gaussians aligned along camera-to-pixel rays. It solves the problem of generating 3D Gaussian Splatting (3DGS) scenes from limited or specific multi-view inputs by leveraging epipolar geometry to constrain feature aggregation, distinguishing itself from global backprojection methods that ignore actual surface geometry. It builds on [3D Gaussian Splatting](1795-3d-gaussian-splatting.md) by replacing or augmenting standard densification with transformer-based feature generalization across epipolar lines.

### [3D Gaussian Splatting with Transformer-based Parameterization](6072-3d-gaussian-splatting-with-transformer-based-parameterizatio.md)
This method reconstructs 3D Gaussian primitives from a small set of input images by tokenizing the images and their camera parameters, concatenating them, and passing them through a Transformer block whose output tokens are decoded into Gaussian parameters. It builds on [3D Gaussian Splatting](1795-3d-gaussian-splatting.md) by replacing iterative optimization with a direct feed-forward Transformer parameterization.

### [SAGA](6154-saga.md)
SAGA is a 2D promptable segmentation method lifted to 3D, leveraging the Segment Anything Model (SAM) for efficient segmentation within 3D Gaussian Splatting (3DGS). It differs from sibling methods like [Gaussian Grouping](2074-gaussianset-data-structure.md), which uses identity encodings for grouping, and [Feature-3DGS](13465-application-specific-extensions.md), which uses CLIP/LSeg language features, by relying on SAM's 2D segmentation capabilities to guide 3D Gaussian assignment.

### [Primitive Geometry and Distribution](6228-primitive-geometry-and-distribution.md)
Primitive Geometry and Distribution defines the mathematical representation of individual splats (primitives) in 3D Gaussian Splatting, specifying how position, orientation, scale, and density are parameterized and projected [G]. It solves the problem of representing complex 3D scenes with a set of differentiable, analytically tractable basis functions that can be efficiently rasterized [G]. It sets itself apart from its siblings by establishing the baseline 3D Gaussian ellipsoid model, whereas alternatives modify the distribution shape (e.g., Student's t, Generalized Exponential), dimensionality (2D disks), or conditioning (Direct Gaussian Splatting) to address specific limitations like geometry accuracy or computational cost [G].

### [Quantile Rendering](7396-quantile-rendering.md)
Quantile Rendering (Q-Render) is a sparse, transmittance-guided sampling strategy designed to efficiently render high-dimensional feature maps from 3D Gaussians. It solves the computational bottleneck of dense volume rendering, where accumulating high-dimensional features along every ray scales poorly with feature dimensionality. Unlike conventional volume rendering, which processes all rasterized Gaussians, Q-Render shifts the Riemann partition from the spatial domain to the transmittance domain, sampling only the most representative "quantile Gaussians" that dominate the ray's transmittance profile. This approach reduces complexity from $O(N C)$ to $O(N + K C)$, enabling real-time rendering of high-dimensional data (e.g., 512-D CLIP embeddings) while maintaining segmentation accuracy.

### [4D Gaussian Splatting](7992-4d-gaussian-splatting.md)
4D Gaussian Splatting (4DGS) extends 3D Gaussian Splatting to model dynamic scenes by treating space and time as a unified 4D continuum, enabling real-time rendering of arbitrary time slices without per-frame optimization. Unlike methods that treat time as an independent dimension or rely on MLP-based deformation fields, 4DGS uses native 4D Gaussian primitives with coherent spatiotemporal covariance, allowing for smooth interpolation of geometry and appearance between discrete keyframes.

### [GauFRe](7994-gaufre.md)
GauFRe is a method for dynamic 3D Gaussian Splatting that decouples static and dynamic scene components to improve optimization stability and reconstruction quality. It addresses the difficulty of jointly optimizing deformation fields and static geometry by initializing the point cloud into separate static and dynamic subsets, optimizing them independently, and rendering them together. Unlike methods that use positional encoding for time, GauFRe employs compact MLPs for different attributes and applies specific normalization operations to scaling and rotation parameters to ensure reasonable optimization.

### [Surface and Mesh Extraction](8498-surface-and-mesh-extraction.md)
This family provides methods to extract explicit 3D geometry (meshes or segmented primitives) from trained 3D Gaussian Splatting (3DGS) models, which are inherently implicit volumetric representations [8498-surface-and-mesh-extraction.md]. Unlike [3D Gaussian Splatting](1795-3d-gaussian-splatting.md) which renders images directly, these methods convert the Gaussian parameters into structured geometric outputs [8498-surface-and-mesh-extraction.md]. [Gaussian Opacity Fields (GOF) Mesh Extraction](3692-gaussian-opacity-fields-gof-mesh-extraction.md) extracts meshes via density field isosurfacing, [Distance-based Gaussian Splatting](7411-distance-based-gaussian-splatting.md) aligns splats to pre-existing meshes, and [2D-Lift-3D Scene Segmentation](11513-2d-lift-3d-scene-segmentation.md) segments primitives using 2D-to-3D label propagation [8498-surface-and-mesh-extraction.md].

### [3D Gaussian Splatting Optimization](15143-3d-gaussian-splatting-optimization.md)
3D Gaussian Splatting Optimization is the training procedure that adjusts the parameters of 3D Gaussian primitives to minimize the difference between rendered images and ground truth observations. It solves the problem of fitting a differentiable radiance field to 2D image data by using gradient-based optimization to update geometry, color, and opacity, while dynamically controlling the number of primitives via adaptive densification. It is distinguished from sibling methods like [CoR-GS](1486-cor-gs.md) and [EffGS](3365-effgs.md) by its reliance on a specific distortion loss formulation and a fixed set of base hyperparameters where the scalar weighting factor $\gamma$ is tuned to align Gaussian counts across datasets, rather than modifying the underlying optimization framework.

### Negative Component Splatting
Negative Component Splatting is a technique using negative density components in a mixture model to enhance representational power and parameter efficiency, allowing subtraction of color/density to capture complex topologies (e.g., holes) with fewer components [S6]. The rendering equation uses signed weights $w \in \mathbb{R}$ (instead of $w > 0$) in the standard alpha-compositing sum: $C(u) = \sum_{i=1}^N c_i o_i T_i^{2D}(u) \prod_{j=1}^{i-1} (1 - o_j T_j^{2D}(u))$, where $o_i$ is opacity and $T_i^{2D}$ is the 2D component function [S6]. Opacity $o$ is constrained by a tanh function during learning so that $o \in [-1, 1]$, allowing positive and negative components to dynamically change signs while being bounded [S6]. Using squared negative components (Eq. 5: $P(x) = (\sum w_i T_i(x))^2$) introduces pairwise interactions between all $K$ components, increasing evaluation complexity to $O(n^2)$, which is significantly slower [S6]. Therefore, the linear sum (Eq. 3) with signed weights is used instead [S6].

### Solid Simulation Decoupling
Solid Simulation Decoupling decouples solid simulation and rendering by using a separate set of sampled particles for simulation (via PBD) and interpolating deformations to trained Gaussian kernels during rendering [S7]. It uses Poisson disk sampling to place simulation particles within the surface mesh explicitly reconstructed using NeuS [S7]. It performs PBD on simulation particles to animate frames [S7]. It interpolates deformation gradients and displacements from simulation particles to trained Gaussian kernels using generalized moving least squares (GMLS) [S7]. It transforms solid Gaussian kernel from rest position $x_p$ to deformed position $x_{tp}$ [S7].

### Distributed 3DGS Training
Distributed 3DGS Training is a distributed training approach that partitions datasets across HPC nodes to overcome single-GPU memory limits (approx. 11.2M Gaussians on A100), using ghost cells at boundaries for smooth transitions and background masks to eliminate artifacts [S8, unofficial]. It partitions datasets across nodes, uses ghost cells at boundaries to ensure smooth transitions, uses background masks to eliminate rendering artifacts, trains Gaussian splats independently per node, and merges for global rendering [S8, unofficial]. Moderate-sized datasets show limited scaling gains when insufficient to fully utilize additional nodes; future challenges include load balancing for uneven distributions and integration with in situ simulation pipelines [S8, unofficial]. Scaling from 4 to 8 nodes on Richtmyer-Meshkov dataset (106.7M Gaussians, 5.3 GB) at 2048×2048 resolution: 3.1× speedup, PSNR 30.04, SSIM 0.97, LPIPS 0.019 [S8, unofficial]. Scaling from 2 to 4 nodes on Rayleigh-Taylor dataset (18.2M Gaussians): 1.4× speedup [S8, unofficial].

### iVR-GS
iVR-GS is a method for real-time editing of transfer functions and lighting during neural volume rendering using editable and composable 3DGS primitives, overcoming the limitation of baked visual parameters [S8, unofficial]. It composes multiple basic models trained on disjoint transfer function ranges, extends Gaussian primitives with normals and shading coefficients, incorporates Blinn-Phong reflection, enables real-time editing of color, opacity, and lighting at inference, and performs automatic optimization to approximate reference images [S8, unofficial]. Model size scales linearly with the number of basic scenes, reaching gigabyte-level for hundreds of transfer functions [S8, unofficial]. Uses uniform viewpoint sampling which may be suboptimal [S8, unofficial]. Requires redesigning lighting representation for models beyond Blinn-Phong [S8, unofficial]. Reconstruction quality: PSNR approximately 32–34 dB for novel view synthesis, 30–33 dB for relighting [S8, unofficial]. Compression: Vector quantization achieved 7.2× compression (6.2 MB vs. 44.8 MB) while maintaining accuracy within 0.06 dB [S8, unofficial].

### 3DGS Radiance Caching
3DGS Radiance Caching is a caching technique for path-traced volume rendering that uses 3DGS primitives to store attenuated radiance at multiple path lengths, optimizing exponentially subsampled Gaussians from noisy path samples to achieve real-time frame rates [S8, unofficial]. Memory footprint: 28 MB for the cache, compared to 272 MB for neural radiance caching [S8, unofficial]. Introduces bias with no guaranteed error bounds and requires re-initialization when transfer functions change [S8, unofficial]. Performance on six scientific datasets at 720p: real-time frame rates achieved with 38–186ms total time [S8, unofficial].

## Operating characteristics
3DGS achieves real-time rendering speeds (e.g., 166 FPS) and minute-level training times for high-fidelity dynamic avatar reconstruction [S1]. It scales to large scenes with millions of Gaussians, though single-GPU memory limits training to approximately 11.2M Gaussians on an A100 [S8, unofficial]. Distributed training can overcome this, achieving 3.1× speedup scaling from 4 to 8 nodes on large datasets [S8, unofficial]. The method is sensitive to initialization and densification parameters, which can lead to artifacts if not tuned correctly [S5, unofficial]. It is particularly effective for static and dynamic scenes with complex geometry and appearance, but may struggle with highly transparent or reflective surfaces without additional modifications [S1][S2, unofficial].

## Background
3D Gaussian Splatting was introduced as a novel approach to radiance field representation, building on the principles of differentiable rendering and explicit scene representation [S2, unofficial]. It has been widely adopted for novel view synthesis, dynamic scene reconstruction, and 3D editing [S1][S2, unofficial][S3][S4, unofficial][S5, unofficial][S6][S7]. The method was published at SIGGRAPH 2023 in the paper '3D Gaussian Splats for Realtime Radiance Field Rendering' [S2, unofficial].
