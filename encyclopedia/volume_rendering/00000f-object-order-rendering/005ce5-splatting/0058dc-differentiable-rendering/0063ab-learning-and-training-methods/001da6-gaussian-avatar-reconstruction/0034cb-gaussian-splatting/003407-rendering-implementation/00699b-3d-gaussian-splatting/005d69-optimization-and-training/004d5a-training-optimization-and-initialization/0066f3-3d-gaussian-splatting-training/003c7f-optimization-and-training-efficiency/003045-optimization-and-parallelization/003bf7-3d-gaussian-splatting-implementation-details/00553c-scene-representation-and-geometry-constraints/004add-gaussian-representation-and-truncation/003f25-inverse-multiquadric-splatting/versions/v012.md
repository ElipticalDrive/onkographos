# Inverse Multiquadric Splatting

Also called: 3DIQS, Inverse Multiquadric

## Overview
Inverse Multiquadric Splatting is a differentiable rendering technique that replaces the standard Gaussian radial basis function with an inverse multiquadric function to define the spatial response of 3D Gaussian primitives. It solves the problem of artifact generation and gradient instability in regions with high opacity or sharp depth discontinuities by providing a slower decay tail than the Gaussian kernel. It differs from the standard Gaussian splatting method [3D Gaussian Splatting](52-3d-gaussian-splatting.md) by altering the functional form of the alpha contribution, and from [Opacity-Independent Gaussian Truncation](10266-opacity-independent-gaussian-truncation.md) by changing the kernel itself rather than just the culling threshold.

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $N$ 3D Gaussian primitives. Each primitive $i$ is defined by mean $\mu_i$, covariance $\Sigma_i$, opacity $\omega_i$, and color coefficients. The primitives are projected to 2D screen space, yielding a 2D mean $\mu'$ and a 2D covariance matrix $\Sigma'_{2 \times 2}$. The conic matrix (inverse covariance) is denoted as $C = (\Sigma'_{2 \times 2})^{-1}$.
*   **Output:** For each pixel covered by a primitive, the alpha value $\alpha$ and the gradients of the loss with respect to the primitive's parameters ($\mu', \Sigma'_{2 \times 2}, \omega$).

**Data Structures:**
The implementation modifies the CUDA rasterizer's forward and backward passes. The core data structures remain those of the parent [Gaussian Representation and Truncation](12855-gaussian-representation-and-truncation.md), but the rasterizer kernel computes specific intermediate values:
*   `con_o`: A struct or vector containing the elements of the 2D conic matrix $C = \begin{bmatrix} a & b \\ b & c \end{bmatrix}$ and the opacity weight $w$ (derived from $\omega$). Specifically, `con_o.x` = $C_{00}$, `con_o.y` = $C_{01}$, `con_o.z` = $C_{11}$, `con_o.w` = $\omega$.
*   `d`: A 2D vector representing the offset from the pixel center to the Gaussian mean: $d = x - \mu'$.

**Parameters:**
*   **Correction Factor ($\xi_{corr}$):** A scalar multiplier applied to the covariance matrices to adjust the spread of the kernel. Value: $1.38$ [S1].
*   **Ellipse Thresholds:** The computation is skipped if the Mahalanobis distance squared ($ellipse$) is $\le 0$ or $\ge 9$ [S1].

**Method Steps:**

1.  **Covariance Scaling:**
    Multiply the 3D covariance matrix $\Sigma$ and the projected 2D covariance matrix $\Sigma'_{2 \times 2}$ by the correction factor $\xi_{corr} = 1.38$ before computing the conic matrix $C = (\Sigma'_{2 \times 2})^{-1}$ [S1]. This effectively scales the inverse covariance used in the dot product.

2.  **Compute Mahalanobis Distance Squared ($ellipse$):**
    Calculate the quadratic form using the conic matrix elements and the pixel offset $d = (d.x, d.y)$:
    $$ ellipse = C_{00} \cdot d.x^2 + C_{11} \cdot d.y^2 + 2 \cdot C_{01} \cdot d.x \cdot d.y $$
    In code: `ellipse = con_o.x * d.x * d.x + con_o.z * d.y * d.y + 2.f * con_o.y * d.x * d.y` [S1].

3.  **Boundary Checks:**
    *   If $ellipse \le 0$, skip the splat (continue) [S1].
    *   If $ellipse \ge 9$, skip the splat (continue) [S1]. This limits the effective 2D ellipse size.

4.  **Compute Inverse Multiquadric Weight ($G$):**
    Calculate the base weight using the inverse multiquadric function. Note that the standard formula involves a parameter $\xi$, but the implementation simplifies this by absorbing $\xi$ into the correction factor or setting it such that the term becomes $1/(ellipse + 1)$ [S1].
    $$ G = \frac{1}{ellipse + 1} $$
    In code: `G = 1.f / (ellipse + 1.f)` [S1].

5.  **Compute Alpha:**
    The final alpha value is the product of the primitive's opacity weight and the spatial weight $G$, capped at 0.99:
    $$ \alpha = \min(0.99, \omega \cdot G) $$
    In code: `alpha = min(0.99f, con_o.w * G)` [S1].

**Backward Pass (Gradients):**
The gradients are computed with respect to the loss $L$. Let $dL_{d\alpha}$ be the gradient of the loss with respect to alpha.

1.  **Gradient w.r.t. $G$:**
    $$ dL_{dG} = \omega \cdot dL_{d\alpha} $$
    In code: `dL_dG = con_o.w * dL_dalpha` [S1].

2.  **Gradient w.r.t. $ellipse$:**
    Since $G = (ellipse + 1)^{-1}$, the derivative is:
    $$ \frac{\partial G}{\partial ellipse} = -\frac{1}{(ellipse + 1)^2} $$
    Thus:
    $$ dL_{d\delta} = dL_{dG} \cdot \frac{-1}{(ellipse + 1)^2} $$
    The code uses a precomputed term `ellipsepow`:
    `ellipsepow = - dL_dG * 2.f / pow(ellipse + 1.f, 2.f)` [S1].
    *Note: The factor of 2 in the code corresponds to the derivative of the quadratic form with respect to the mean components, as shown below.*

3.  **Gradient w.r.t. 2D Mean ($\mu'$):**
    The offset $d = x - \mu'$ implies $\frac{\partial d}{\partial \mu'} = -I$. The gradient flows through $ellipse$.
    $$ \frac{\partial ellipse}{\partial d.x} = 2(C_{00} d.x + C_{01} d.y) $$
    $$ \frac{\partial ellipse}{\partial d.y} = 2(C_{01} d.x + C_{11} d.y) $$
    The gradient w.r.t the mean components (accounting for the chain rule through $d$) is:
    $$ \frac{\partial L}{\partial \mu'_x} = - dL_{dG} \cdot \frac{-2}{(ellipse + 1)^2} \cdot (C_{00} d.x + C_{01} d.y) $$
    $$ \frac{\partial L}{\partial \mu'_y} = - dL_{dG} \cdot \frac{-2}{(ellipse + 1)^2} \cdot (C_{01} d.x + C_{11} d.y) $$
    In code, `halfellipsepow` is defined as `0.5f * ellipsepow`, which equals $- dL_{dG} / (ellipse + 1)^2$.
    `dG_ddelx = ellipsepow * (d.x * con_o.x + d.y * con_o.y)` [S1].
    `dG_ddely = ellipsepow * (d.x * con_o.y + d.y * con_o.z)` [S1].
    These are accumulated into `dL_dmean2D` using the Jacobian of the projection (`ddelx_dx`, `ddely_dy`) [S1].

4.  **Gradient w.r.t. Conic Matrix ($C$):**
    The gradient w.r.t the conic matrix entries ($a=C_{00}, b=C_{01}, c=C_{11}$) is derived from $\frac{\partial ellipse}{\partial C_{ij}}$.
    $$ \frac{\partial ellipse}{\partial C_{00}} = d.x^2 $$
    $$ \frac{\partial ellipse}{\partial C_{11}} = d.y^2 $$
    $$ \frac{\partial ellipse}{\partial C_{01}} = 2 d.x d.y $$
    The gradient w.r.t the conic matrix is:
    $$ \frac{\partial L}{\partial C_{ij}} = dL_{dG} \cdot \frac{-1}{(ellipse + 1)^2} \cdot \frac{\partial ellipse}{\partial C_{ij}} $$
    In code, `halfellipsepow` is used again.
    `atomicAdd(&dL_dconic2D[global_id].x, halfellipsepow * d.x * d.x)` [S1].
    `atomicAdd(&dL_dconic2D[global_id].y, halfellipsepow * d.x * d.y)` [S1].
    `atomicAdd(&dL_dconic2D[global_id].z, halfellipsepow * d.y * d.y)` [S1].
    *Note: The code snippet for conic gradients in Listing 7 of [S1] shows a more complex update involving `denom2inv` and other terms, which suggests the gradient is propagated through the inversion of the 2D covariance to get the conic matrix, or the code snippet provided in the notes is a simplified representation. However, the direct gradient w.r.t the conic matrix elements $a,b,c$ is as derived above. The provided code `dL_da = correctionFactor * ...` in Listing 7 seems to refer to the gradient w.r.t the *elements of the 2D covariance* or a different parameterization. Given the explicit `atomicAdd` lines for `dL_dconic2D` in the backward pass snippet, the direct gradient to the conic matrix is the primary update.*

**Pseudocode:**

```python
def inverse_multiquadric_splat_forward(con_o, d):
    """
    con_o: struct with x, y, z, w corresponding to C00, C01, C11, opacity
    d: 2D vector (dx, dy) offset from mean to pixel
    Returns: alpha
    """
    correction_factor = 1.38
    
    # Compute ellipse = d^T * C * d
    # C = [[con_o.x, con_o.y], [con_o.y, con_o.z]]
    ellipse = (con_o.x * d.x * d.x) + (con_o.z * d.y * d.y) + (2.0 * con_o.y * d.x * d.y)
    
    # Boundary checks
    if ellipse <= 0.0 or ellipse >= 9.0:
        return 0.0
    
    # Compute inverse multiquadric weight
    G = 1.0 / (ellipse + 1.0)
    
    # Compute alpha
    alpha = min(0.99, con_o.w * G)
    
    return alpha

def inverse_multiquadric_splat_backward(con_o, d, dL_dalpha):
    """
    Returns gradients: dL_dmean, dL_dconic, dL_dopacity
    """
    correction_factor = 1.38
    
    # Compute ellipse
    ellipse = (con_o.x * d.x * d.x) + (con_o.z * d.y * d.y) + (2.0 * con_o.y * d.x * d.y)
    
    # If out of bounds, gradients are zero
    if ellipse <= 0.0 or ellipse >= 9.0:
        return (0.0, 0.0, 0.0)
    
    # Gradient w.r.t G
    dL_dG = con_o.w * dL_dalpha
    
    # Gradient w.r.t ellipse
    # dG/d_ellipse = -1 / (ellipse + 1)^2
    # dL/d_ellipse = dL_dG * dG/d_ellipse
    denom_sq = (ellipse + 1.0) ** 2
    dL_d_ellipse = -dL_dG / denom_sq
    
    # Gradient w.r.t mean (d = x - mu, so dL/d_mu = -dL/d_d)
    # d_ellipse/d_dx = 2 * (C00 * dx + C01 * dy)
    # d_ellipse/d_dy = 2 * (C01 * dx + C11 * dy)
    
    dL_d_dx = dL_d_ellipse * 2.0 * (con_o.x * d.x + con_o.y * d.y)
    dL_d_dy = dL_d_ellipse * 2.0 * (con_o.y * d.x + con_o.z * d.y)
    
    # dL_d_mean_x = -dL_d_dx
    # dL_d_mean_y = -dL_d_dy
    dL_d_mean = (-dL_d_dx, -dL_d_dy)
    
    # Gradient w.r.t conic matrix elements
    # d_ellipse/d_C00 = dx^2
    # d_ellipse/d_C01 = 2 * dx * dy
    # d_ellipse/d_C11 = dy^2
    
    dL_d_C00 = dL_d_ellipse * (d.x ** 2)
    dL_d_C01 = dL_d_ellipse * (2.0 * d.x * d.y)
    dL_d_C11 = dL_d_ellipse * (d.y ** 2)
    
    dL_d_conic = (dL_d_C00, dL_d_C01, dL_d_C11)
    
    # Gradient w.r.t opacity
    dL_d_opacity = (1.0 / (ellipse + 1.0)) * dL_dalpha
    
    return dL_d_mean, dL_d_conic, dL_d_opacity
```

## Operating characteristics
*   **Time Complexity:** Same as standard Gaussian splatting, $O(N \cdot K)$ where $N$ is the number of primitives and $K$ is the number of pixels covered per primitive. The inverse multiquadric function involves a division and addition, which is computationally comparable to the exponential function in Gaussians, though potentially slightly faster on some hardware [S1].
*   **Memory Complexity:** No additional memory overhead compared to standard Gaussian splatting. The same data structures are used.
*   **Strengths:** The inverse multiquadric function has a heavier tail than the Gaussian, which can help in reconstructing surfaces with sharp edges or high-frequency details without introducing ringing artifacts. The correction factor of 1.38 helps align the spread with the visual quality of Gaussians [S1].
*   **Limitations:** The slower decay may require more primitives to achieve the same level of detail in smooth regions compared to Gaussians. The truncation threshold of 9 is fixed, which may not be optimal for all scenes.
*   **When to use:** When standard Gaussian splatting produces artifacts in high-contrast regions or when the Gaussian kernel's rapid decay is insufficient to capture the desired geometry.

## Background
Inverse Multiquadric Splatting was introduced in the paper "DARB-Splatting: Generalizing Splatting with Decaying Anisotropic Radial Basis Functions" [S1]. The method generalizes the splatting framework by allowing different radial basis functions, with the inverse multiquadric being one such function. It is part of the broader effort to improve the quality and robustness of 3D Gaussian Splatting.
