# RLSplat

Also called: Resource-Linear Budget Control for Feed-forward 3D Gaussian Splatting

## Overview
RLSplat is a resource-linear, budget-controllable feed-forward 3D Gaussian Splatting (FF3DGS) framework that generates exactly $B$ Gaussians for a given scene, ensuring that inference latency and peak memory scale linearly with the budget $B$ [S1, unofficial]. Unlike sibling methods such as EcoSplat and F4 Splat, which predict a dense set of candidates and subsequently prune or select $B$ Gaussians (resulting in nearly constant inference cost regardless of the budget), RLSplat allocates the budget directly to local scene regions via a learned policy and refines them using a resource-linear decoder [S1, unofficial]. This approach solves the problem of inefficient resource utilization in prior budget-controllable methods, making it suitable for applications with strict latency or memory constraints, such as AR/VR and robotics [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of $V$ uncalibrated context images $\{I_i\}_{i=1}^V$ and a target Gaussian budget $B$ (an integer).
*   **Outputs:** A set of $B$ 3D Gaussians $\mathcal{G} = \{g_b\}_{b=1}^B$ and the context camera parameters $\{P_i\}_{i=1}^V$. Each Gaussian $g_b$ consists of a 3D center, opacity, scale, rotation, and color coefficients [S1, unofficial].

**Data Structures:**
1.  **Anchor Tokens:** The geometry backbone encodes the input images into $N$ anchor tokens $\{a_n\}_{n=1}^N$. Each anchor represents a local 3D region of the scene [S1, unofficial].
2.  **Allocation Vector:** A discrete allocation vector $\mathbf{k} \in \mathbb{Z}_{\ge 0}^N$, where $k_n$ is the number of Gaussians assigned to anchor $n$. The constraint is $\sum_{n=1}^N k_n = B$ [S1, unofficial].
3.  **Gaussian Tokens:** Each anchor $n$ spawns $k_n$ Gaussian tokens. The total number of Gaussian tokens is exactly $B$ [S1, unofficial].
4.  **Hierarchical Neighbor Search Structure:** Used to find the $K_{gs}$ nearest Gaussian neighbors for each token efficiently [S1, unofficial].

**Parameters:**
*   $B$: The target Gaussian budget. Typical evaluation values are 2K (2,048) and 64K. On the ACID dataset with 8 views, $B=8,192$ (1,024 per view) is used. On RE10K, $B=8,000$ is used [S1, unofficial].
*   $K_{gs}$: The number of nearest Gaussian neighbors each token attends to during refinement. Default ablation value is 16. This can be changed at inference without retraining [S1, unofficial].
*   $K_{anc}$: The number of anchor neighbors used in the hierarchical neighbor search. Fixed value in ablations is 16 [S1, unofficial].
*   $C$: The number of rollouts (candidate allocations) drawn per training step for the Group Sequence Policy Optimization (GSPO) [S1, unofficial].

**Algorithm Steps:**

1.  **Encoding:** Given context images $\{I_i\}$, a geometry backbone encodes them into $N$ anchor tokens $\{a_n\}_{n=1}^N$ and predicts camera parameters $\{P_i\}$ [S1, unofficial].
2.  **Gaussian Allocation:** A Gaussian allocation policy $\pi_\psi$ assesses the local significance of each anchor (based on image features like texture complexity) to predict a discrete allocation $\mathbf{k}$. The policy ensures $\sum k_n = B$. This policy is trained using Group Sequence Policy Optimization (GSPO) [S1, unofficial].
    *   During training, $C$ candidate allocations $\mathbf{k}^{(c)} \sim \pi_{old}$ are sampled.
    *   For each rollout, the representation $\mathcal{G}^{(c)}$ is generated, rendered to novel views, and a reconstruction loss $\mathcal{L}_{recon}$ is computed against ground truth images. This loss serves as the reward signal [S1, unofficial].
3.  **Token Spawning:** Each anchor $n$ spawns $k_n$ Gaussian tokens. The total number of Gaussian tokens is exactly $B$ [S1, unofficial].
4.  **Resource-Linear Decoding:**
    *   The decoder instantiates initial Gaussians from the tokens.
    *   It refines them via local cross-attention. For each Gaussian token, the $K_{gs}$ nearest Gaussian neighbors are found using a hierarchical neighbor search.
    *   The decoding cost is $O(B \cdot K_{gs})$, scaling linearly with $B$, compared to global self-attention which costs $O(B^2)$ [S1, unofficial].
5.  **Output:** The final set of $B$ Gaussians $\mathcal{G}$ and camera parameters $\{P_i\}$ are returned [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Training Failure:** Removing the projection loss causes training to fail entirely, as it ties an anchor's Gaussians to the image region it was encoded from [S1, unofficial].
*   **Neighbor Accuracy:** Removing the Voronoi loss causes a significant PSNR drop (2.51 dB) because Gaussians leave their anchor's cell, and the hierarchical search no longer retrieves their true neighbors [S1, unofficial].
*   **Refinement Necessity:** Removing the local refinement module lowers PSNR by 0.96 dB, as Gaussians cannot be made consistent with their neighbors if predicted from their own token alone [S1, unofficial].
*   **Precision:** The allocation policy uses Group Sequence Policy Optimization (GSPO) to handle the non-differentiable discrete allocations [S1, unofficial].

## Subtopics

### Gaussian Allocation Policy
A policy trained with GSPO that distributes the Gaussian budget $B$ across anchors based on local significance (e.g., texture complexity). It concentrates capacity where fine geometric details require it. Choose this when you need adaptive, high-fidelity allocation of a fixed budget. Link: [Gaussian Splatting Initialization and Parameterization](15832-gaussian-splatting-initialization-and-parameterization.md).

### Resource-Linear Decoder
A decoder that refines Gaussians via local cross-attention with a hierarchical neighbor search, ensuring decoding cost scales as $O(B \cdot K_{gs})$. Choose this when inference latency and memory must scale linearly with the output size. Link: [Gaussian Geometry Parameters Prediction](8442-gaussian-geometry-parameters-prediction.md).

## Operating characteristics
*   **Time Complexity:** The decoding cost is $O(B \cdot K_{gs})$, scaling linearly with the Gaussian budget $B$. This is a significant improvement over global self-attention, which costs $O(B^2)$ [S1, unofficial].
*   **Memory Complexity:** Peak memory scales linearly with the Gaussian budget $B$ [S1, unofficial].
*   **Measured Performance:**
    *   At a budget of 2K Gaussians, RLSplat achieves higher PSNR than F4 Splat while using 9.6× less peak memory and running 4.1× faster [S1, unofficial].
    *   On the ACID dataset (8 views, $B=8,192$), RLSplat achieves PSNR 22.84 dB, SSIM 0.643, and LPIPS 0.353 [S1, unofficial].
    *   On the RE10K dataset ($B=8,000$), RLSplat achieves a full-view PSNR of 26.51 dB, compared to 23.42 dB for F4 Splat and 21.82 dB for EcoSplat [S1, unofficial].
    *   In a specific region (stair balusters) on RE10K, RLSplat allocates 5,388 Gaussians (vs. 2,521 for EcoSplat and 3,026 for F4 Splat), achieving a local PSNR of 23.51 dB (vs. 17.79 dB and 20.00 dB, respectively) [S1, unofficial].
*   **Scaling:** Inference cost (latency and peak memory) scales linearly with the Gaussian budget $B$. The parameter $K_{gs}$ can be changed at inference without retraining, allowing further tuning of the speed-quality trade-off [S1, unofficial].
*   **Strengths:**
    *   True resource-linearity: Latency and memory decrease as $B$ decreases.
    *   High fidelity at low budgets: Outperforms prior budget-controllable methods at every tested budget.
    *   Adaptive allocation: Concentrates Gaussians on high-frequency structures (e.g., thin balusters) and spares smooth regions.
*   **Limitations:**
    *   Requires training with GSPO, which involves non-differentiable discrete allocations.
    *   Performance depends on the accuracy of the hierarchical neighbor search; removing Voronoi loss degrades performance significantly [S1, unofficial].
*   **When to use:** Applications requiring limited resource budgets, such as AR/VR, robotics, and digital content creation, where inference latency and memory are critical constraints [S1, unofficial].
*   **When not to use:** When maximum possible quality is required regardless of resource cost, or when the scene has extremely uniform geometry where adaptive allocation provides little benefit over uniform distribution.

## Background
RLSplat was proposed by Bae, Park, and Kim from KAIST [S1, unofficial]. It addresses the limitations of prior budget-controllable FF3DGS methods like EcoSplat and F4 Splat, which predict dense sets of Gaussians and then prune them, resulting in nearly constant inference latency and memory regardless of the target budget [S1, unofficial]. RLSplat introduces a resource-linear approach by learning a Gaussian allocation policy and using a resource-linear decoder with hierarchical neighbor search [S1, unofficial]. The method is used for feed-forward 3D Gaussian Splatting in applications requiring limited resource budgets [S1, unofficial].
