# FlexGS

Also called: Flexible 3D Gaussian Splatting, Elastic Inference for 3DGS

## Overview
FlexGS is an elastic inference method for 3D Gaussian Splatting (3DGS) that enables a single trained model to adapt to varying computational constraints at inference time by selecting and transforming a subset of Gaussians based on a desired model size ratio, without requiring additional fine-tuning [S1]. It solves the problem of standard 3DGS requiring significant GPU memory, which limits deployment on devices with restricted resources like smartphones or VR headsets, by allowing dynamic compression at any ratio [S1]. Unlike post-hoc compression methods that use fixed heuristics to retain Top-K Gaussians and require separate runs for each ratio, FlexGS jointly trains a learnable module to adaptively select points based on attributes and the desired ratio during training [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A pre-trained 3DGS model consisting of $N$ Gaussians, each characterized by position $\mathbf{X} \in \mathbb{R}^3$, scaling vector $\mathbf{s} \in \mathbb{R}^3$, rotation quaternion $\mathbf{q} \in \mathbb{R}^4$ (optimized as vector $\mathbf{q} \in \mathbb{R}^3$ in the source notation, but standard quaternion is 4D; source says "rotation vector q", see [S1]), opacity $\alpha \in \mathbb{R}$, and color $\mathbf{c}$ defined by spherical harmonics coefficients $\mathbf{SH} \in \mathbb{R}^{(d+1)}$ where $d$ is the SH degree [S1]. A target ratio $e \in (0, 1]$ representing the desired percentage of remaining Gaussians.
*   **Output:** A subset of selected Gaussians and their transformed parameters, ready for rendering.

**Data Structures:**
The core data structure is the set of $N$ Gaussians. Each Gaussian $i$ stores:
*   $\mathbf{X}_i$: Mean position.
*   $\mathbf{s}_i$: Scaling vector.
*   $\mathbf{q}_i$: Rotation representation (source denotes as vector, typically quaternion components).
*   $\alpha_i$: Opacity.
*   $\mathbf{SH}_i$: Spherical Harmonics coefficients.
*   $\lambda_i$: Binary selector output (1 if selected, 0 if not).

**Method Steps:**
1.  **Gaussian Definition:** Each Gaussian is defined by mean $\mathbf{X}$ and covariance $\Sigma$. For optimization, $\Sigma$ is decomposed into a scaling matrix $\mathbf{S}$ and rotation matrix $\mathbf{R}$ using vector $\mathbf{s}$ and quaternion $\mathbf{q}$:
    $$ G(\mathbf{X}) = e^{-\frac{1}{2} \mathbf{X} \Sigma^{-1} \mathbf{X}}, \quad \Sigma = \mathbf{R} \mathbf{S} \mathbf{S}^\top \mathbf{R}^\top $$
    [S1]

2.  **Rendering:** Pixel color $C$ is computed by blending ordered Gaussians overlapping the pixel:
    $$ C = \sum_{i \in N} c_i \alpha_i \prod_{j=1}^{i-1} (1 - \alpha_j) $$
    [S1]

3.  **Adaptive Gaussian Selection:**
    *   For a target ratio $e$, the method predicts a binary scaler $\lambda_i$ for each Gaussian $i$.
    *   Constraint: $\sum_{i=1}^{N} \lambda_i = eN$.
    *   Unlike fixed heuristics that rank Gaussians by importance scores $s_i$ and keep Top-$K$ ($K=eN$), FlexGS uses a learnable module.
    *   The selection is trained jointly with the 3DGS model to adapt to evolving Gaussian attributes [S1].
    *   *Note on Implementation:* The source mentions "Adaptive Selection via Gumbel-Softmax" to handle the discrete nature of $\lambda_i$ for gradient descent, but does not provide the explicit formula for the selector network or the Gumbel-Softmax relaxation parameters in the provided text [S1]. [G: Standard Gumbel-Softmax relaxation is typically used: $\tilde{\lambda}_i = \text{softmax}((\log \pi_i + g_i)/\tau)$ where $g_i$ is Gumbel noise, $\pi_i$ is the selector's output probability, and $\tau$ is temperature. The binary $\lambda_i$ is obtained via straight-through estimator or hard selection during inference.]

4.  **Ratio-Dependent Gaussian Transformation:**
    *   A transformation module displaces selected Gaussians to compensate for missing details due to the reduction in the number of Gaussians.
    *   The transformation is dependent on the ratio $e$.
    *   *Note on Implementation:* The source states the existence of this module but does not provide the specific mathematical formulation of the displacement field or how it modifies $\mathbf{X}, \mathbf{s}, \mathbf{q}$ in the provided text [S1]. [G: Typically, this involves a small neural network (MLP) that takes Gaussian attributes and the ratio $e$ as input and outputs displacement/rotation/scale adjustments for the selected Gaussians.]

**Parameters:**
*   $N$: Total number of Gaussians in the base model.
*   $e$: Target ratio (e.g., 0.1 for 10% of Gaussians).
*   $d$: Degree of Spherical Harmonics.

**Edge Cases and Pitfalls:**
*   **Extreme Ratios:** Fixed heuristic selection rules may fail to generalize in extreme cases, such as when selecting only 1% of Gaussians, because importance scores must be frequently re-computed as Gaussian attributes evolve during training [S1]. FlexGS addresses this by joint training.
*   **Discrete Optimization:** Direct optimization over discrete choices $\lambda_i$ is ineffective for gradient descent. A relaxation technique (like Gumbel-Softmax) is required during training [S1].

## Operating characteristics
*   **Time Complexity:** Inference time is proportional to the number of selected Gaussians $eN$. The selection and transformation steps add negligible overhead compared to rendering.
*   **Memory Complexity:** Memory usage is proportional to $eN$ Gaussians. This allows deployment on devices with limited memory by reducing $e$.
*   **Performance:** Experiments on ZipNeRF, MipNeRF, and Tanks&Temples scenes demonstrate effectiveness [S1]. It achieves substantial rendering performance without additional fine-tuning.
*   **Strengths:** Single model deployment for multiple hardware constraints; no re-training required for different ratios; adaptive selection based on attributes.
*   **Limitations:** Requires a learnable selector and transformation module to be trained jointly with the 3DGS model; performance at extreme ratios (e.g., 1%) may still be challenging if the transformation module is not sufficiently expressive.

## Background
FlexGS was introduced by Hengyu Liu, Yuehao Wang, Chenxin Li, et al. from The Chinese University of Hong Kong, University of Texas at Austin, and Nvidia. The paper "FlexGS: Train Once, Deploy Everywhere with Many-in-One Flexible 3D Gaussian Splatting" was published in CVPR 2025 [S1]. It addresses the memory overhead of standard 3DGS, which can involve millions of Gaussians for city-scale scenes, limiting use on smartphones and VR headsets [S1]. Previous approaches focused on pruning less important Gaussians but required fine-tuning and lacked adaptability for specific memory needs [S1].
