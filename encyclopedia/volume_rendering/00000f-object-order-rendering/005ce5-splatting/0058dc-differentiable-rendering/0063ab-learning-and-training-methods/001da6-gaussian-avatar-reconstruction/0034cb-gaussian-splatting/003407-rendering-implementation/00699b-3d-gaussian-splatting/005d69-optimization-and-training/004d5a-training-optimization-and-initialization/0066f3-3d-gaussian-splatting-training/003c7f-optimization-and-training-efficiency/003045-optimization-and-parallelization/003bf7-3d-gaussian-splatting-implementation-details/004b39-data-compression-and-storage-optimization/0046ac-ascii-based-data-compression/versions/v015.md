# ASCII-Based Data Compression

Also called: Anywhere Compression, Base 94 Floating-Point Compression, Base 95 Integer Compression

## Overview
ASCII-Based Data Compression is a method for optimizing data transmission speed during the training of 3D Gaussian Splatting models by encoding numerical attributes into ASCII character strings [S1, unofficial]. It addresses the bottleneck of transferring large volumes of Gaussian parameters (position, scale, rotation, opacity, and spherical harmonic coefficients) between devices or processes during distributed or iterative training [S1, unofficial]. Unlike standard binary serialization, this method maps discrete integer ranges and floating-point components to specific ASCII characters, aiming to reduce overhead and improve throughput, though it yields modest speed improvements (approximately 6% or less) [S1, unofficial].

## How it works
The method operates on the set of $N$ Gaussian primitives $\{G_i\}$, compressing their attributes for transmission. It distinguishes between integer-valued indices and floating-point continuous values, using different base encodings for each.

### Inputs and Outputs
- **Input:** Numerical values representing Gaussian attributes (integers or floats).
- **Output:** A string of ASCII characters representing the compressed data.

### Data Structures
The compression does not use complex binary structures but relies on character mapping.
- **Integer Encoding:** Maps values in $[0, 95]$ to a single ASCII character.
- **Floating-Point Encoding:** Maps the integer part to a single ASCII character and uses a delimiter for the fractional part.

### Steps

1.  **Integer Compression (Base 95):**
    -   Select ASCII characters with codes 32 to 126 (inclusive). There are 95 such characters.
    -   Map each integer value $v \in [0, 95]$ to the character $c$ where $c = \text{chr}(v + 32)$.
    -   To decode, transform the ASCII string directly to decimal integers using $v = \text{ord}(c) - 32$.

2.  **Floating-Point Compression (Base 94):**
    -   Select ASCII characters with codes 32 to 125 (inclusive) for the integer component. There are 94 such characters.
    -   Select ASCII character 126 (`~`) as the delimiter connecting the integer and fractional parts.
    -   For a floating-point number, extract the integer component $I$ and the decimal places $d$.
    -   Encode $I$ using the Base 94 mapping: $c_I = \text{chr}(I + 32)$.
    -   Concatenate $c_I$, the delimiter `~`, and the string representation of $d$.
    -   To decode, split the ASCII string at the delimiter. Let the integer part string be $S_I$ and the decimal part string be $S_d$.
    -   Calculate the final value $f$ using the formula:
        $$ f = I \times 10^{-d} $$
        Where $I$ is the integer value decoded from $S_I$ and $d$ is the integer value representing the number of decimal places (or the decimal value itself, depending on interpretation, but the source formula $f = I 10^{-d}$ implies $d$ is the exponent magnitude or decimal count) [S1, unofficial]. *Note: The source text states "decimal places $d$" and formula $f = I 10^{-d}$. This implies $d$ is the count of decimal digits or the power of 10 scaling factor.*

3.  **Color Matrix Optimization:**
    -   Compress each item of the output color matrix to only one decimal place.
    -   The range is $[0.0, 2.0]$.
    -   This results in 21 alternative numbers ($0.0, 0.1, \dots, 2.0$).
    -   Combine this quantization with ASCII string compression to reduce data size significantly [S1, unofficial].

### Parameters
-   **Integer Base:** 95 (ASCII 32–126).
-   **Floating-Point Integer Base:** 94 (ASCII 32–125).
-   **Delimiter:** ASCII 126 (`~`).
-   **Color Precision:** 1 decimal place.

### Edge Cases and Pitfalls
-   **Matrix Traversal Speed:** Compressing the color matrix into ASCII strings is difficult because traversing a large matrix takes significant processing time [S1, unofficial].
-   **Library Limitations:** Using internal functions like `torch::where` and `torch::index_select` helps replace `for` loops to improve matrix traversal speed, but it is still not fast enough to support full compression replacement [S1, unofficial].
-   **Line Breaks:** Using line break characters adds an extra operator in ASCII string writing and decoding, which should be avoided [S1, unofficial].
-   **Performance Gain:** The method gains about 6% or less improvement in training speed [S1, unofficial].

def compress_integer(value):
    """
    Compress an integer in range [0, 95] to a single ASCII character.
    """
    if not (0 <= value <= 95):
        raise ValueError("Integer value out of range [0, 95]")
    # ASCII 32 is space, 126 is ~
    return chr(value + 32)

def decompress_integer(char):
    """
    Decompress a single ASCII character to an integer in range [0, 95].
    """
    code = ord(char)
    if not (32 <= code <= 126):
        raise ValueError("Invalid ASCII character for integer compression")
    return code - 32

def decompress_float(s):
    """
    Decompress a floating-point ASCII string.
    """
    if "~" not in s:
        raise ValueError("Invalid floating-point format")

def compress_color_value(value):
    """
    Compress a color matrix item to 1 decimal place in [0.0, 2.0].
    Returns the quantized value.
    """
    # Quantize to 1 decimal place
    quantized = round(value * 10) / 10.0
    # Clamp to [0.0, 2.0]
    quantized = max(0.0, min(2.0, quantized))

## Operating characteristics
-   **Time Complexity:** The compression/decompression is $O(1)$ per value, but matrix traversal overhead can be significant [S1, unofficial].
-   **Memory Complexity:** Reduces data size by encoding values as ASCII strings, but the overhead of string manipulation may negate benefits for small datasets [S1, unofficial].
-   **Performance:** Gains approximately 6% or less improvement in training speed [S1, unofficial].
-   **Strengths:** Simple implementation; reduces data size for color matrices with low precision [S1, unofficial].
-   **Limitations:** Slow matrix traversal; not fast enough for full replacement of binary serialization; modest speed gains [S1, unofficial].
-   **When to Use:** When training speed is bottlenecked by data transmission and attributes can be quantized to low precision [S1, unofficial].
-   **When Not to Use:** When high precision is required or when matrix traversal overhead dominates [S1, unofficial].

## Background
The method was introduced in "I3DGS: Improve 3D Gaussian Splatting from Multiple Dimensions" by F. Author et al. in 2024 [S1, unofficial]. It is part of an effort to improve the training speed of 3D Gaussian Splatting models by optimizing data transmission, learning, structure design, and compression [S1, unofficial].
