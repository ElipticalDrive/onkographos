# Completion Framework

Also called: GPN Completion Framework

## Overview
The Completion Framework is a method for repairing and complementing incomplete point clouds derived from RGB or RGB-D frames that only partially capture an object [S1]. It distinguishes itself from standard completion methods by using two separate encoders to produce distinct latent representations for the existing and missing parts of the point cloud, which are then concatenated and decoded to output the weights of a Neural Radiance Field (NeRF) [S1]. This approach allows for the generation of a complete, colored point cloud by enforcing a Gaussian prior on the missing part's latent space while maintaining multi-view consistency with scanned images [S1].

## How it works
The framework operates by mapping an incomplete point cloud to a continuous parameterization of a 3D object space via NeRF weights [S1].

**Inputs and Outputs**
*   **Input:** An incomplete point cloud $P$ obtained from RGB/RGB-D scanning, split into two disjoint subsets: $P_e$ (existing parts) and $P_m$ (missing parts) [S1].
*   **Output:** The weights $\phi$ of a NeRF model $\Phi_\phi$, which can render the complete point cloud and match the input cloud and existing scanning images [S1].

**Data Structures**
*   **Point Cloud Subsets:** $P_e$ and $P_m$ are disjoint subsets of the input point cloud $P$ [S1].
*   **Latent Representations:**
    *   $z_e = \varepsilon_e(P_e)$: Latent code for existing parts [S1].
    *   $z_m = \varepsilon_m(P_m)$: Latent code for missing parts [S1].
    *   Combined Latent: $z = z_e \oplus z_m$, where $\oplus$ denotes concatenation [S1].
*   **NeRF Weights:** $\phi = \Psi_\psi(z)$, where $\Psi_\psi$ is the decoder network [S1].

**Numbered Steps**
1.  **Split Input:** Divide the input point cloud $P$ into disjoint subsets $P_e$ (existing) and $P_m$ (missing) [S1].
2.  **Encode Existing Parts:** Process $P_e$ with encoder $\varepsilon_e$ to produce latent representation $z_e$. This encoder is used only for reconstruction [S1].
3.  **Encode Missing Parts:** Process $P_m$ with encoder $\varepsilon_m$ to produce latent representation $z_m$. This encoder renders a generative model, forcing $z_m$ to follow a Gaussian prior [S1].
4.  **Concatenate Latents:** Combine $z_e$ and $z_m$ into a single latent vector $z = z_e \oplus z_m$ [S1].
5.  **Decode NeRF Weights:** Pass $z$ through decoder $\Psi_\psi$ to output NeRF weights $\phi$ [S1].
6.  **Inference Optimization:** During inference, the encoder predicts an initial latent code and generates a unique NeRF model. Perform latent-based conditional optimization to refine the predicted NeRF model to match the reconstructed cloud and existing scanning images [S1].

**Formulas**
The training loss function combines a color rendering loss and a KL divergence term [S1]:

$$
L_{color} = \sum_{r \in R} ||\Phi_{\phi=\Psi_\psi(\varepsilon_e(P_e) \oplus \varepsilon_m(P_m))}(r) - C(r)||^2
$$

$$
L = L_{color} + D_{KL}(\varepsilon_e(P_e) \oplus \varepsilon_m(P_m), \mathcal{N}(0, I))
$$

Where:
*   $R$ is the set of rays [S1].
*   $\Phi_\phi$ is the NeRF model parameterized by weights $\phi$ [S1].
*   $C(r)$ is the color of ray $r$ from the input data [S1].
*   $D_{KL}$ is the Kullback-Leibler divergence [S1].
*   $\mathcal{N}(0, I)$ is the standard normal distribution, serving as the prior for the latent space [S1].

**Parameters**
*   **Latent Combination:** The operation $\varepsilon_e(P_e) \oplus \varepsilon_m(P_m)$ represents the concatenation of the two latent representations [S1].
*   **Prior:** The latent code for the missing part $z_m$ is forced to follow a Gaussian prior $\mathcal{N}(0, I)$ [S1].

**Pseudocode**

```python
def completion_framework_training(P_e, P_m, R, C):
    """
    P_e: Point cloud subset for existing parts
    P_m: Point cloud subset for missing parts
    R: Set of rays for rendering
    C: Ground truth colors for rays R
    """
    # Step 1: Encode existing parts
    z_e = encoder_e(P_e)
    
    # Step 2: Encode missing parts
    z_m = encoder_m(P_m)
    
    # Step 3: Concatenate latent representations
    z_combined = concatenate(z_e, z_m)
    
    # Step 4: Decode NeRF weights
    phi = decoder(z_combined)
    
    # Step 5: Render colors using NeRF
    rendered_colors = []
    for r in R:
        color = nerf_render(phi, r)
        rendered_colors.append(color)
    
    # Step 6: Calculate Color Loss
    L_color = sum_squared_error(rendered_colors, C)
    
    # Step 7: Calculate KL Divergence Loss
    # Assuming encoder_m outputs mean and log-variance for Gaussian prior
    # D_KL(z_m, N(0, I))
    L_kl = kl_divergence(z_m, mean=0, var=1)
    
    # Step 8: Total Loss
    L = L_color + L_kl
    
    return L

def completion_framework_inference(P_incomplete):
    """
    P_incomplete: Incomplete point cloud to be completed
    """
    # Split into existing and missing parts
    # Note: In practice, P_m might be inferred or sampled based on occlusion/masking
    P_e, P_m = split_point_cloud(P_incomplete)
    
    # Encode
    z_e = encoder_e(P_e)
    z_m = encoder_m(P_m)
    
    # Concatenate and Decode
    z_combined = concatenate(z_e, z_m)
    phi = decoder(z_combined)
    
    # Refine via latent-based conditional optimization
    # This step adjusts the latent code or NeRF weights to match
    # the reconstructed cloud and existing scanning images
    phi_refined = optimize_neural_radiance_field(phi, P_incomplete)
    
    return phi_refined
```

**Edge Cases and Pitfalls**
*   **Missing Part Definition:** The method assumes a predefined split of the point cloud into $P_e$ and $P_m$. Determining $P_m$ for real-world scans where the "missing" geometry is unknown requires careful handling, potentially relying on the generative capability of $\varepsilon_m$ [S1].
*   **Gaussian Prior Enforcement:** The requirement for $z_m$ to follow $\mathcal{N}(0, I)$ is critical for the generative aspect. Failure to enforce this may result in poor generalization to unseen objects [S1].
*   **Optimization Stability:** The latent-based conditional optimization during inference adds complexity. Improper initialization or learning rates may lead to divergence or suboptimal completions [S1].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:** Evaluated on ShapeNet categories (cars and chairs). The framework uniformly samples 16,384 colored points on each 3D model and uses 100 views for rendering [S1].
*   **Strengths:** Lightweight, generalizable, and capable of completing unseen portions of real-world objects with colors, unlike methods that only reconstruct synthetic objects [S1].
*   **Limitations:** Relies on the quality of the initial split between existing and missing parts. Performance depends on the ability of the encoders to disentangle and complement the latent representations [S1].
*   **When to Use:** Suitable for RGB/RGB-D scanning reconstruction applications where objects are partially captured and color completion is required [S1].
*   **When Not to Use:** Not suitable for complete point clouds where no completion is needed, or for applications requiring explicit mesh output rather than implicit NeRF representations [S1].

## Background
The Completion Framework is part of the GPN (Generative Point-Based NeRF) framework, proposed by Haipeng Wang et al. [S1]. It builds upon the "Generation Framework" and is inspired by Hyperpocket [S1]. The method addresses the limitation of existing point cloud completion techniques that rely on learning to reconstruct synthetic objects rather than completing the unseen portions of real-world objects [S1]. It was evaluated on standard shape generation benchmarks, specifically cars and chairs, using the ShapeNet dataset [S1].
