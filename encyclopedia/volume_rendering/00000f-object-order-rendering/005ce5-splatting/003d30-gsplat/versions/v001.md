# gsplat
Also called: gsplat API

## Overview
gsplat is a unified, high-performance software API and rasterization backend designed to accelerate the rendering and training of 3D Gaussian Splatting scenes [S1, unofficial][S2]. Unlike methods that alter the scene representation or compression codecs, gsplat focuses on optimizing the low-level scheduling, memory access patterns, and shader execution to support constrained environments and real-time interactivity [S1, unofficial][S2]. It serves as the foundational engine for subsequent optimizations such as FlashGS and Mobile-GS.

## How it works
**Inputs and Outputs:**
*   **Input:** A set of 3D Gaussians defined by position $\mathbf{p}_k$, covariance $\Sigma_k$, opacity $\alpha_k$, and spherical harmonics coefficients for color.
*   **Output:** A rasterized 2D image (color and depth) and gradients for training.

**Data Structures:**
The method relies on a structured layout of Gaussian attributes to facilitate efficient matrix operations. The core data structure is a matrix $A$ containing the Gaussian attributes (position, scale, rotation, opacity) and a matrix $B$ containing pixel-wise accumulation weights [S1, unofficial].

**Steps:**
1.  **Attribute Loading:** Load Gaussian attributes from global memory into shared memory or registers. For constrained environments, this may involve loading only visible Gaussians from flash storage using quantized integer representations [S1, unofficial].
2.  **Projection:** Transform 3D Gaussian centers to screen space using the Model-View-Projection (MVP) matrix. Compute the 2D covariance matrix $\Sigma_{2D}$ using the Jacobian of the projection transformation [S1, unofficial][S2].
3.  **Splat Rasterization:** For each pixel, determine the contribution of overlapping Gaussians. This involves computing the 2D Gaussian footprint and accumulating weights [S1, unofficial].
4.  **Matrix Multiplication:** Perform a matrix multiplication $C = AB$, where $A$ holds the Gaussian attributes and $B$ holds the pixel-wise accumulation weights [S1, unofficial]. This step efficiently computes the final color and depth values by leveraging GPU tensor cores or optimized shader instructions.
5.  **Compositing:** Accumulate the contributions using alpha blending, typically in a front-to-back order, to handle transparency [S1, unofficial][S2].

**Parameters:**
*   **Tile Size:** The screen is partitioned into tiles (e.g., 16x16 or 32x32 pixels) to optimize cache locality [S1, unofficial].
*   **Quantization:** Positions and colors may be quantized to lower precision (e.g., integers) for memory-constrained deployments [S1, unofficial].

**Edge Cases:**
*   **Precision:** Lower-precision shaders may introduce artifacts in blending; guard against underflow in opacity accumulation [S1, unofficial].
*   **Visibility:** Culling of Gaussians outside the view frustum is critical for performance in constrained environments [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot T)$, where $N$ is the number of Gaussians and $T$ is the number of tiles. The matrix multiplication step is optimized to $O(N \cdot P)$ where $P$ is the number of pixels, leveraging hardware acceleration [S1, unofficial].
*   **Memory Complexity:** $O(N)$ for Gaussian attributes. Quantization can reduce this significantly [S2].
*   **Performance:** Enables real-time rendering on GPUs and mobile devices. Performance is sensitive to memory bandwidth and cache efficiency rather than just the number of Gaussians [S1, unofficial][S2].
*   **Strengths:** High performance, unified API, supports constrained environments, facilitates training acceleration [S1, unofficial][S2].
*   **Limitations:** Does not inherently compress the scene; relies on external compression methods for storage reduction [S2].

## Background
gsplat was introduced as a unified high-performance API to address the computational bottlenecks in 3D Gaussian Splatting rasterization [S1, unofficial]. It has become a standard backend for various optimizations, including FlashGS for multi-GPU pipelines and Mobile-GS for smartphone deployment [S1, unofficial].
