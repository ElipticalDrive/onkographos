# WebGPU 3D Gaussian Splatting Rendering Pipeline

Also called: 3D Gaussian Splatting Rendering Pipeline, Real-Time Radiance Field Rendering, Real-Time Radiance Field Rendering via WebGPU, WebGPU 3DGS, WebGPU Gaussian Splatting

## Overview
This method implements the core rendering loop for 3D Gaussian Splatting on the WebGPU API, serving as the execution engine for the [Web 3D Gaussian Splatting](18045-web-3d-gaussian-splatting.md) system. It solves the problem of efficiently projecting and rasterizing millions of 3D Gaussians into a 2D image by managing the GPU command submission, uniform updates, and depth-sorted indexed drawing. It differs from compute-shader-based accumulation approaches by preparing data structures for standard triangle rasterization, which is leveraged by its child method [WebGPU Gaussian Splatting Rasterization](18925-webgpu-gaussian-splatting-rasterization.md) to achieve higher framerates.

## How it works
**Inputs and Outputs:**
*   **Input:** A set of 3D Gaussians defined by position, log-scale, rotation quaternion, opacity logit, and spherical harmonics coefficients, stored in a GPU buffer. Camera parameters (view matrix, projection matrix, focal lengths, canvas dimensions).
*   **Output:** A color/alpha texture (the current canvas texture) containing the rendered splat image.

**Data Structures:**
The pipeline relies on specific buffer layouts and uniform structures.

1.  **Gaussian Point Input (`PointInput`):**
    *   `position`: `vec3<f32>` (x, y, z)
    *   `log_scale`: `vec3<f32>` (log of scale factors)
    *   `rot`: `vec4<f32>` (quaternion w, x, y, z or similar, see formula)
    *   `opacity_logit`: `f32`
    *   `sh`: Spherical harmonics coefficients (array of `vec3<f32>`, size depends on degree)

2.  **Uniforms (`Uniforms`):**
    *   `viewMatrix`: `mat4<f32>`
    *   `projMatrix`: `mat4<f32>`
    *   `cameraPosition`: `vec3<f32>`
    *   `tanHalfFovX`: `f32`
    *   `tanHalfFovY`: `f32`
    *   `focalX`: `f32`
    *   `focalY`: `f32`
    *   `scaleModifier`: `f32`

3.  **Buffers:**
    *   `uniformBuffer`: Stores the `Uniforms` struct.
    *   `gaussiansBuffer`: Stores the `PointInput` array.
    *   `drawIndexBuffer`: Stores the sorted indices for drawing. Size: `6 * 4 * nUnpadded` bytes (where `nUnpadded` is the number of Gaussians).
    *   `depthSortBuffer`: Temporary buffer for GPU-based sorting (e.g., Bitonic Sort).

**Numbered Steps:**

1.  **Initialization and Culling:**
    *   Call `animate(forceDraw)`. If `destroyCallback` is set, call `destroyImpl()` and return.
    *   If the camera is not dirty and `forceDraw` is false, request the next animation frame and return.

2.  **Camera and Uniform Update:**
    *   Retrieve the camera object and its position.
    *   Calculate `tanHalfFovX = 0.5 * canvas.width / camera.focalX` and `tanHalfFovY = 0.5 * canvas.height / camera.focalY`.
    *   Convert `camera.viewMatrix` to a flat array of arrays (row-major or column-major as required by WebGPU, typically column-major in memory but accessed as 16 floats).
    *   Construct the `uniforms` object with the values listed above.
    *   Write `uniforms` to `uniformBuffer` using `queue.writeBuffer`.

3.  **Depth Sorting:**
    *   Call `depthSorter.sort(depthSortMatrix)` to compute the draw order. This typically involves a GPU-based sort (e.g., Bitonic Sort) on the Gaussian depths projected into view space.
    *   The sorter returns a source buffer `indexBufferSrc` containing the sorted indices.

4.  **Command Encoding:**
    *   Create a `commandEncoder`.
    *   Copy the sorted indices from `indexBufferSrc` to `drawIndexBuffer` using `commandEncoder.copyBufferToBuffer`. The copy size is `6 * 4 * nUnpadded` bytes.
    *   Get the current canvas texture view.
    *   Create a `renderPassDescriptor` with a color attachment: `loadOp: 'clear'`, `storeOp: 'store'`, clear value `{r:0, g:0, b:0, a:0}`.

5.  **Rendering Pass:**
    *   Begin the render pass.
    *   Set the pipeline to `drawPipeline`.
    *   Bind `uniformsBindGroup` to bind group 0.
    *   Bind `pointDataBindGroup` (containing `gaussiansBuffer`) to bind group 1.
    *   Set the index buffer to `drawIndexBuffer` with format `uint32`.
    *   Execute `drawIndexed`:
        *   `count = numGaussians * 6`
        *   `instanceCount = 1`
        *   `firstIndex = 0`
        *   `baseVertex = 0`
        *   `firstInstance = 0`
    *   End the render pass.
    *   Submit the command buffer: `queue.submit([commandEncoder.finish()])`.

6.  **Post-Render:**
    *   Calculate FPS: `1000 / (now - lastDraw)`.
    *   Update `lastDraw` to `now`.
    *   Request the next animation frame.

**Formulas:**

1.  **Rotation Matrix from Quaternion:**
    Given quaternion $(r, x, y, z)$ (where $r$ is the scalar part, often $w$):
    $$
    R = \begin{bmatrix}
    1 - 2(y^2 + z^2) & 2(xy - rz) & 2(xz + ry) \\
    2(xy + rz) & 1 - 2(x^2 + z^2) & 2(yz - rx) \\
    2(xz - ry) & 2(yz + rx) & 1 - 2(x^2 + y^2)
    \end{bmatrix}
    $$
    [S1, unofficial]

2.  **3D Covariance Matrix:**
    Let $S$ be a diagonal matrix with entries $\exp(\text{log\_scale}) \cdot \text{scale\_modifier}$.
    Let $R$ be the rotation matrix derived from the quaternion.
    $$ M = S \cdot R $$
    $$ \Sigma = M \cdot M^T $$
    The upper triangle of $\Sigma$ is extracted: $[\Sigma_{00}, \Sigma_{01}, \Sigma_{02}, \Sigma_{11}, \Sigma_{12}, \Sigma_{22}]$.
    [S1, unofficial]

3.  **2D Covariance Projection:**
    Transform position to view space: $t = \text{viewMatrix} \cdot [x, y, z, 1]^T$.
    Clamp ratios to handle frustum edges:
    $$ l_x = \min(\max(t.x/t.z, -1.3 \cdot \tan(\text{fov}_x)), 1.3 \cdot \tan(\text{fov}_x)) $$
    $$ l_y = \min(\max(t.y/t.z, -1.3 \cdot \tan(\text{fov}_y)), 1.3 \cdot \tan(\text{fov}_y)) $$
    Compute Jacobian $J$:
    $$ J = \begin{bmatrix}
    f_x/t.z & 0 & -f_x \cdot t.x / t.z^2 \\
    0 & f_y/t.z & -f_y \cdot t.y / t.z^2
    \end{bmatrix} $$
    Compute $T = \text{viewMatrix}^T \cdot J$ (taking the relevant 3x2 or 2x3 sub-blocks as appropriate for the dimensionality of the covariance multiplication).
    Compute 2D covariance:
    $$ \Sigma_{2D} = T^T \cdot \Sigma \cdot T $$
    Apply low-pass filter to ensure minimum size:
    $$ \Sigma_{2D}[0][0] += 0.3 $$
    $$ \Sigma_{2D}[1][1] += 0.3 $$
    Return the upper triangle: $[\Sigma_{2D}[0][0], \Sigma_{2D}[0][1], \Sigma_{2D}[1][1]]$.
    [S1, unofficial]

4.  **Conic Matrix and Radius:**
    Let $\Sigma_{2D} = \begin{bmatrix} a & b \\ b & c \end{bmatrix}$.
    $$ \text{det} = a \cdot c - b^2 $$
    $$ \text{det\_inv} = 1.0 / \text{det} $$
    $$ \text{conic} = [c \cdot \text{det\_inv}, -b \cdot \text{det\_inv}, a \cdot \text{det\_inv}] $$
    $$ \text{mid} = 0.5 \cdot (a + c) $$
    $$ \lambda_1 = \text{mid} + \sqrt{\max(0.1, \text{mid}^2 - \text{det})} $$
    $$ \lambda_2 = \text{mid} - \sqrt{\max(0.1, \text{mid}^2 - \text{det})} $$
    $$ \text{radius\_px} = \lceil 3.0 \cdot \sqrt{\max(\lambda_1, \lambda_2)} \rceil $$
    $$ \text{radius\_ndc} = [\text{radius\_px} / \text{canvas\_height}, \text{radius\_px} / \text{canvas\_width}] $$
    [S1, unofficial]

5.  **Fragment Shader Power Function:**
    Let $d = [u, v]$ be the distance from the Gaussian center in UV space.
    Let $\text{conic} = [A, B, C]$ (inverse of 2D covariance upper triangle).
    $$ \text{power} = -0.5 \cdot (A \cdot d.x^2 + C \cdot d.y^2) + B \cdot d.x \cdot d.y $$
    [S1, unofficial]

**Pseudocode:**

```python
def render_pipeline(context, camera, gaussians, canvas):
    # 1. Check if redraw is needed
    if not camera.is_dirty and not force_draw:
        request_animation_frame(lambda: render_pipeline(context, camera, gaussians, canvas))
        return

    # 2. Update Uniforms
    tan_half_fov_x = 0.5 * canvas.width / camera.focal_x
    tan_half_fov_y = 0.5 * canvas.height / camera.focal_y
    
    uniforms = {
        'viewMatrix': mat4_to_array(camera.view_matrix),
        'projMatrix': mat4_to_array(camera.get_proj_matrix()),
        'cameraPosition': camera.position,
        'tanHalfFovX': tan_half_fov_x,
        'tanHalfFovY': tan_half_fov_y,
        'focalX': camera.focal_x,
        'focalY': camera.focal_y,
        'scaleModifier': camera.scale_modifier
    }
    
    context.device.queue.write_buffer(
        context.uniform_buffer, 
        0, 
        uniforms_to_bytes(uniforms)
    )

    # 3. Depth Sort
    # depth_sort_matrix is the view matrix used for sorting depth
    sorted_indices_src = context.depth_sorter.sort(context.depth_sort_matrix)
    
    # 4. Command Encoding
    command_encoder = context.device.create_command_encoder()
    
    # Copy sorted indices to draw buffer
    # 6 indices per gaussian (2 triangles), 4 bytes per index (uint32)
    copy_size = 6 * 4 * context.depth_sorter.n_unpadded
    command_encoder.copy_buffer_to_buffer(
        sorted_indices_src, 
        0, 
        context.draw_index_buffer, 
        0, 
        copy_size
    )
    
    # Render Pass
    current_texture_view = context.context_gpu.get_current_texture().create_view()
    render_pass_descriptor = {
        'color_attachments': [{
            'view': current_texture_view,
            'load_op': 'clear',
            'store_op': 'store',
            'clear_value': {'r': 0.0, 'g': 0.0, 'b': 0.0, 'a': 0.0}
        }]
    }
    
    render_pass = command_encoder.begin_render_pass(render_pass_descriptor)
    render_pass.set_pipeline(context.draw_pipeline)
    render_pass.set_bind_group(0, context.uniforms_bind_group, [], 0)
    render_pass.set_bind_group(1, context.point_data_bind_group, [], 0)
    render_pass.set_index_buffer(context.draw_index_buffer, 'uint32')
    
    # Draw Indexed
    # count = num_gaussians * 6
    render_pass.draw_indexed(
        count=context.num_gaussians * 6,
        instance_count=1,
        first_index=0,
        base_vertex=0,
        first_instance=0
    )
    
    render_pass.end()
    context.device.queue.submit([command_encoder.finish()])
    
    # 5. Post-Render
    now = get_current_time_ms()
    fps = 1000.0 / (now - context.last_draw)
    context.last_draw = now
    update_fps_display(fps)
    
    request_animation_frame(lambda: render_pipeline(context, camera, gaussians, canvas))
```

## Subtopics

### [WebGPU Gaussian Splatting Rasterization](18925-webgpu-gaussian-splatting-rasterization.md)
Renders 3D Gaussian splats by mapping them to standard triangle rasterization, converting each Gaussian into a flat rectangle (quad) facing the camera, and drawing these quads with a fragment shader. It avoids the compute-shader-based pixel accumulation of the original implementation to achieve substantially better framerates on WebGPU. It builds on [WebGPU 3D Gaussian Splatting Rendering Pipeline](18792-webgpu-3d-gaussian-splatting-rendering-pipeline.md).

## Operating characteristics
*   **Time Complexity:** Dominated by the depth sorting step, which is typically $O(N \log N)$ or $O(N)$ depending on the GPU sort implementation (e.g., Bitonic Sort). The rasterization step is $O(N)$ as each Gaussian generates a constant number of vertices (6 indices).
*   **Memory Complexity:** $O(N)$ for storing Gaussian attributes and index buffers.
*   **Performance:** The pipeline is optimized for WebGPU, leveraging hardware-accelerated sorting and standard rasterization. It achieves real-time framerates on modern web browsers with compatible GPUs [S1, unofficial].
*   **Strengths:** Efficient use of WebGPU features (bind groups, command encoders, GPU sorting). Separation of concerns allows for optimized rasterization strategies in child methods.
*   **Limitations:** Requires WebGPU support. Depth sorting on the GPU can be memory-intensive for very large scenes.
*   **When to use:** When rendering 3D Gaussian Splatting scenes on the web with high performance requirements.
*   **When not to use:** When targeting WebGL2 without WebGPU fallbacks, or when the scene size exceeds available GPU memory for sorting buffers.

## Background
The method originates from the "WebGPU Viewer for 3D Gaussian Splatting Real-Time Radiance Field Rendering" project by CVLAB EPFL [S1, unofficial]. It adapts the original 3D Gaussian Splatting algorithm [Kerbl et al., 2023] to the WebGPU API, enabling real-time rendering of radiance fields in web browsers. The implementation handles the specific constraints and capabilities of the WebGPU API, including buffer management, shader compilation, and command submission.
