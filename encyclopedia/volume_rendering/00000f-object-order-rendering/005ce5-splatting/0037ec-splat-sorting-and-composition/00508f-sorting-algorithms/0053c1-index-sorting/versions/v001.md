# Index Sorting

Also called: Key-index pair sorting

## Overview
Index sorting is a variant of sorting that produces a permutation of indices rather than reordering the data values themselves, allowing related information to be traced back to the original array [S1, unofficial]. It solves the problem of maintaining data association during sorting, which is critical in volume rendering splatting where voxel attributes (density, color) must remain linked to their spatial keys [S1, unofficial]. Unlike methods that pack keys and indices into a single register to save memory, index sorting keeps key counting independent from index values, preserving full precision and index range (up to 4 billion pairs on 32-bit hardware) [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: An array of keys $K$ of size $n$, and an initial index array $I$ of size $n$.
- Output: A sorted permutation array $P$ (indices) and optionally a sorted key array $K'$ (if full record sorting is required, though index sorting specifically outputs $P$).

**Data Structures:**
- $K$: Array of keys, typically 32-bit integers or floats.
- $I$: Array of indices, initialized as $I[i] = i$ for $0 \le i < n$.
- $P$: Permutation array, same size as $K$, storing the sorted indices.

**Steps:**
1. **Initialize Index Array:** Generate a companion index array $I$ where $I[i] = i$. This indicates the original position of each value in $K$ [S1, unofficial].
2. **Perform Key Sorting:** Execute the radix sort algorithm on the key array $K$ to generate a permutation array $P$. The sorting logic operates independently on the keys; the indices in $I$ are not involved in the comparison or counting phases [S1, unofficial].
3. **Shuffle Indices:** Apply the permutation $P$ to the index array $I$ to produce the final sorted index array. This step rearranges the indices according to the sorted order of the keys [S1, unofficial].
   - Formula: $I_{sorted}[j] = I[P[j]]$ for $0 \le j < n$.
4. **Access Data:** To retrieve the original data associated with the $j$-th sorted element, use the value $I_{sorted}[j]$ as an offset into the original data arrays [S1, unofficial].

**Pseudocode:**
```python
def index_sort(keys, n):
    # Step 1: Initialize index array
    indices = [i for i in range(n)]
    
    # Step 2: Sort keys to get permutation
    # This function returns the permutation array P such that
    # sorted_keys[j] = keys[P[j]]
    permutation = radix_sort_keys(keys, n)
    
    # Step 3: Shuffle indices with the permutation
    # The sorted index array maps the sorted position to the original index
    sorted_indices = [0] * n
    for j in range(n):
        sorted_indices[j] = indices[permutation[j]]
        
    return sorted_indices
```

**Edge Cases and Pitfalls:**
- **Cache Misses:** Index sorting exacerbates cache misses compared to value sorting because the shuffling step involves non-coalesced memory access patterns when applying the permutation to the indices [S1, unofficial].
- **Memory Bandwidth:** The additional shuffle step increases memory bandwidth requirements [S1, unofficial].
- **Precision:** Combining keys and indices into a single register reduces precision and index range. Index sorting avoids this by keeping them separate, allowing full 32-bit index ranges [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Typically 1.5 to 1.8 times slower than value sorting due to non-coalesced shuffling [S1, unofficial].
- **Optimization:** Using a coalesced radix index sorting scheme reduces the performance penalty to a negligible factor of about 1.1 [S1, unofficial].
- **Memory:** Requires storage for both the key array and the index array, doubling the memory footprint compared to sorting keys alone if the original data is not needed in place.
- **Strengths:** Preserves full precision and index range; simple to implement on top of existing radix sort kernels.
- **Limitations:** Higher memory bandwidth usage; potential for cache thrashing during the shuffle phase if not optimized.

## Background
Index sorting was discussed in the context of GPU-based parallel sorting, specifically highlighting its application in scenarios where data association is crucial [S1, unofficial]. The method was analyzed on NVIDIA GTX 280 hardware, demonstrating that while naive index sorting suffers from performance penalties, optimized coalesced approaches mitigate these issues [S1, unofficial].
