# CPU Radix Sort for Face Centroids

Also called: Floating Point Radix Sort, LSD Radix Sort

## Overview
An out-of-place sorting algorithm used on the CPU to sort face centroids for volume rendering splatting, achieving linear time complexity at the expense of auxiliary memory [S1, unofficial].

## How it works
**Inputs:** Array of $N$ face centroids (floating-point values, typically distances) [S1, unofficial].
**Outputs:** Array of $N$ sorted face centroids (ascending order) [S1, unofficial].
**Auxiliary Data:** An auxiliary array of size $N$ and a count array of size 256 [S1, unofficial].

**Data Structures:**
1. `input`: Array of $N$ 32-bit IEEE 754 floating-point numbers [S1, unofficial].
2. `output`: Array of $N$ 32-bit unsigned integers (sorted keys) [S1, unofficial].
3. `counts`: Array of 256 unsigned integers (histogram for counting sort) [S1, unofficial].

**Steps:**
1. **Transformation:** Convert each floating-point number in `input` to a 32-bit unsigned integer representation that preserves numerical order [S1, unofficial]. This handles the sign bit inversion required for negative numbers in IEEE 754 [S1, unofficial].
2. **Pass 1 (Histogram):** Perform a single pass through `input` to count occurrences of the 8-bit keys for all four blocks simultaneously [S1, unofficial].
3. **Pass 2 (LSD):** Perform a counting sort on bits 0–7 of the transformed integers, writing results to `output` [S1, unofficial].
4. **Pass 3:** Perform a counting sort on bits 8–15, using `output` as input and writing to `input` (swapping roles) [S1, unofficial].
5. **Pass 4:** Perform a counting sort on bits 16–23 [S1, unofficial].
6. **Pass 5 (MSD):** Perform a counting sort on bits 24–31 [S1, unofficial].
7. **Final Output:** The result is in the array written by Pass 5 [S1, unofficial].

**Formulas:**
*   **Float to Int Transformation:**
    $$ f_{int} = f \oplus ((-(f \gg 31)) \mid 0x80000000) $$
    Where $f$ is the bit-cast of the 32-bit float to an unsigned integer [S1, unofficial].
*   **Bit Extraction:**
    For block $k$ (where $k \in \{0, 1, 2, 3\}$), the key for counting sort is:
    $$ key = (f_{int} \gg (8 \times k)) \ \& \ 0xFF $$

**Pseudocode:**
```python
import struct

def float_to_uint32(f_bits):
    """Convert IEEE 754 float bits to sortable uint32 using the source transformation [S1, unofficial]."""
    return f_bits ^ ((-(f_bits >> 31)) | 0x80000000)

def uint32_to_float(u_bits):
    """Convert uint32 back to IEEE 754 float [G]."""
    return struct.unpack('f', struct.pack('I', u_bits))[0]

def cpu_radix_sort_face_centroids(centroids_float):
    """
    Sorts an array of floating-point face centroids using LSD Radix Sort.
    centroids_float: List of floats.
    Returns: List of sorted floats.
    """
    n = len(centroids_float)
    if n == 0:
        return []

    # Step 1: Convert floats to sortable integers
    ints = [float_to_uint32(struct.unpack('I', struct.pack('f', c))[0]) for c in centroids_float]

    # Auxiliary arrays
    output = [0] * n
    counts = [0] * 256

    src = ints
    dst = output

    # Pass 1: Histogram pass (counts occurrences for all 4 blocks in one pass) [S1, unofficial]
    hist = [[0] * 256 for _ in range(4)]
    for i in range(n):
        for k in range(4):
            key = (src[i] >> (8 * k)) & 0xFF
            hist[k][key] += 1

    # Passes 2-5: Sorting passes (4 passes total) [S1, unofficial]
    for k in range(4):
        # Reset counts for current block
        for i in range(256):
            counts[i] = 0
        # Copy histogram for this block
        for i in range(256):
            counts[i] = hist[k][i]

        # Compute prefix sums (cumulative counts) to determine output positions [G]
        total = 0
        for i in range(256):
            temp = counts[i]
            counts[i] = total
            total += temp

        # Distribute elements to dst
        for i in range(n):
            key = (src[i] >> (8 * k)) & 0xFF
            pos = counts[key]
            dst[pos] = src[i]
            counts[key] += 1

        # Swap src and dst for next pass
        src, dst = dst, src

    # Convert back to floats
    sorted_floats = [uint32_to_float(d) for d in src]
    return sorted_floats
```

**Parameters:**
*   Block size: 8 bits [S1, unofficial].
*   Total passes: 5 (1 histogram pass + 4 sorting passes) [S1, unofficial].
*   Count array size: 256 [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **NaN Values:** The transformation and sorting logic exclude NaN values and assume standard IEEE 754 floating-point representation [S1, unofficial].
*   **Memory:** The algorithm is out-of-place, requiring $O(N)$ auxiliary memory [S1, unofficial].

## Subtopics

### [LSD Block Sorting (Radix Sort)](6217-lsd-block-sorting-radix-sort.md)
LSD Block Sorting is a CPU-based radix sort algorithm that sorts 32-bit integers by processing them in 8-bit blocks from least significant to most significant. It solves the problem of ordering face centroids for volume rendering splatting by achieving linear time complexity through five sequential counting sort passes. It differs from its sibling [Logarithmic Distance Bucket Sort](14468-logarithmic-distance-bucket-sort.md) by using exact integer comparison rather than distance-based bucketing, making it suitable for general-purpose sorting where precise ordering is required without depth-peeling assumptions.

## Operating characteristics
*   **Time Complexity:** Linear $O(N)$, where $N$ is the number of faces [S1, unofficial].
*   **Memory Complexity:** $O(N)$ auxiliary space for the output array and $O(1)$ for the count array (size 256) [S1, unofficial].
*   **Performance:** Sorts upwards of 15 million faces per second on the tested hardware [S1, unofficial].
*   **Comparison:** Significantly faster than shellsort (584 ms), heapsort (507 ms), and quicksort (281 ms) for sorting one million floating-point numbers (radixsort took 64 ms) [S1, unofficial].
*   **Strengths:** Much faster than comparison-based sorts for large $N$ [S1, unofficial].
*   **Limitations:** Requires auxiliary memory; not in-place; assumes IEEE 754 format [S1, unofficial].
*   **When to use:** When sorting large numbers of face centroids on the CPU where GPU sorting is unavailable or disabled [S1, unofficial].
*   **When not to use:** When memory is extremely constrained (due to auxiliary array requirement) [S1, unofficial]. The source notes that re-sorting with this fast sort is more efficient in practice than using algorithms optimized for re-sorting previously sorted sequences (like mergesort), because viewing direction changes can significantly alter the ordering from frame to frame [S1, unofficial].

## Background
Used in the K-Buffer implementation for volume rendering [S1, unofficial]. The method was selected over other common sorting algorithms (shellsort, heapsort, quicksort, mergesort) because re-sorting face centroids with a fast sort is more efficient in practice than using an algorithm optimized for re-sorting previously sorted sequences, as the ordering can change significantly from frame to frame due to viewing direction changes [S1, unofficial]. The specific float-to-int transformation is based on established techniques for sorting IEEE 754 floats as integers [S1, unofficial].
