# Logarithmic Distance Bucket Sort

Also called: Back-to-Front Voxel Sorting, DistanceSorter

## Overview
Logarithmic Distance Bucket Sort is a CPU-based sorting algorithm for volume rendering voxels that orders them back-to-front relative to the camera position [S1, unofficial]. It solves the depth-sorting requirement for alpha blending or depth peeling by mapping voxel distances into fixed logarithmic buckets [S1, unofficial]. It differs from Morton-order-based splat sorting (e.g., [SVRaster](52-svraster.md)) by relying solely on radial distance rather than ray-direction-dependent spatial locality [S1, unofficial].

## How it works
**Inputs:**
- `positions`: `Float32Array` of voxel centers, interleaved as `[x1, y1, z1, x2, y2, z2, ...]` [S1, unofficial].
- `cameraPosition`: `[number, number, number]` representing the camera origin [S1, unofficial].
- `outIndices`: Optional pre-allocated `Uint32Array` for output [S1, unofficial].

**Outputs:**
- `Uint32Array` of indices into `positions`, sorted such that voxels with larger distances from the camera appear first (back-to-front) [S1, unofficial].

**Data Structures:**
The implementation maintains static state to avoid reallocation between frames [S1, unofficial]:
- `counts`: `Uint32Array` of size `BUCKET_COUNT` (65536). Stores bucket occupancy during the first pass [S1, unofficial].
- `starts`: `Uint32Array` of size `BUCKET_COUNT`. Allocated for potential reuse, though the algorithm computes bucket positions in a local array during execution [S1, unofficial].
- `lastCameraPosition`: `[number, number, number]` or `null`. Stores the previous camera position for early-exit optimization [S1, unofficial].

**Parameters:**
- `BUCKET_COUNT`: 65536 ($256 \times 256$) [S1, unofficial].

**Formulas:**
- Logarithmic distance: $L_i = \log(d^2)$, where $d^2 = (x - c_x)^2 + (y - c_y)^2 + (z - c_z)^2$ [S1, unofficial].
- Inverse scale factor: $S = \frac{\text{BUCKET\_COUNT} - 1}{\text{logRange} \parallel 1}$, where $\text{logRange} = \max(L) - \min(L)$ [S1, unofficial].
- Bucket index: $b_i = \min(\text{BUCKET\_COUNT} - 1, \lfloor (L_i - \min(L)) \times S \rfloor)$ [S1, unofficial].

**Algorithm Steps:**
1. **Early Exit Check:** If `lastCameraPosition` exists, `outIndices` is provided, and `outIndices.length` equals `numVoxels`, calculate the dot product of `lastCameraPosition` and `cameraPosition`, compute their squared lengths, and evaluate $\cos \theta = \frac{\mathbf{c}_{last} \cdot \mathbf{c}_{curr}}{\|\mathbf{c}_{last}\| \|\mathbf{c}_{curr}\|}$ [S1, unofficial]. If $| \cos \theta - 1 | < 0.01$, return `outIndices` immediately [S1, unofficial].
2. **Initialization:** Determine `numVoxels` as `positions.length / 3` [S1, unofficial]. Allocate or reuse `indices` array of size `numVoxels` [S1, unofficial]. If `counts` or `starts` are null or have incorrect length, allocate them as `Uint32Array` of size `BUCKET_COUNT`; otherwise, clear `counts` by filling with zeros [S1, unofficial].
3. **Log Distance Calculation:** Initialize `minDist` to $\infty$ and `maxDist` to $-\infty$ [S1, unofficial]. For each voxel $i$, extract coordinates $(x, y, z)$, compute squared Euclidean distance $d^2$, compute logarithmic distance $L_i = \log(d^2)$, store it in a temporary `logDistances` array, and update `minDist` and `maxDist` [S1, unofficial].
4. **Bucket Scaling:** Calculate `logRange = maxDist - minDist` [S1, unofficial]. Compute inverse scale factor $S$ using the formula above [S1, unofficial].
5. **First Pass (Counting):** For each voxel $i$, calculate bucket index $b_i$ and increment `counts[b_i]` [S1, unofficial].
6. **Calculate Bucket Starts:** Initialize `position = 0` [S1, unofficial]. Iterate $j$ from `BUCKET_COUNT - 1` down to $0$: set `bucketStarts[j] = position` and update `position += counts[j]` [S1, unofficial]. This ensures back-to-front ordering [S1, unofficial].
7. **Reset Counts:** Clear `counts` array by filling with zeros [S1, unofficial].
8. **Second Pass (Distribution):** For each voxel $i$, calculate bucket index $b_i$ using the same formula as Step 5 [S1, unofficial]. Calculate output position $p = \text{bucketStarts}[b_i] + \text{counts}[b_i]$, set `indices[p] = i`, and increment `counts[b_i]` [S1, unofficial].
9. **State Update:** Store `cameraPosition` in `lastCameraPosition` for the next frame [S1, unofficial].

**Edge Cases and Pitfalls:**
- If `logRange` is 0 (all voxels at the same distance), the denominator in the scale factor defaults to 1 to prevent division by zero, effectively mapping all voxels to bucket 0 [S1, unofficial].
- The early-exit condition assumes sort order remains valid if the camera direction has not changed significantly, but does not account for camera translation [S1, unofficial].

**Pseudocode:**
```python
import math

BUCKET_COUNT = 65536
counts = None
starts = None
last_camera_position = None

def sort_voxels(positions, camera_position, out_indices=None):
    global counts, starts, last_camera_position
    
    num_voxels = len(positions) // 3
    
    # Early exit optimization
    if (last_camera_position is not None and 
        out_indices is not None and 
        len(out_indices) == num_voxels):
        
        lx, ly, lz = last_camera_position
        cx, cy, cz = camera_position
        
        dot = lx * cx + ly * cy + lz * cz
        len_sq1 = lx * lx + ly * ly + lz * lz
        len_sq2 = cx * cx + cy * cy + cz * cz
        
        cos_theta = dot / math.sqrt(len_sq1 * len_sq2)
        if abs(cos_theta - 1.0) < 0.01:
            return out_indices

    # Initialize output
    if out_indices is not None and len(out_indices) == num_voxels:
        indices = out_indices
    else:
        indices = [0] * num_voxels  # Represents Uint32Array

    # Initialize static arrays
    if counts is None or starts is None or len(counts) != BUCKET_COUNT:
        counts = [0] * BUCKET_COUNT
        starts = [0] * BUCKET_COUNT
    else:
        for i in range(BUCKET_COUNT):
            counts[i] = 0

    # Calculate log distances
    log_distances = [0.0] * num_voxels
    min_dist = float('inf')
    max_dist = float('-inf')
    
    cx, cy, cz = camera_position
    
    for i in range(num_voxels):
        x = positions[i * 3]
        y = positions[i * 3 + 1]
        z = positions[i * 3 + 2]
        
        dx = x - cx
        dy = y - cy
        dz = z - cz
        
        dist_sq = dx * dx + dy * dy + dz * dz
        log_dist = math.log(dist_sq)
        
        log_distances[i] = log_dist
        
        if log_dist < min_dist:
            min_dist = log_dist
        if log_dist > max_dist:
            max_dist = log_dist

    # Calculate scaling
    log_range = max_dist - min_dist
    if log_range == 0:
        log_range = 1
        
    dist_inv = (BUCKET_COUNT - 1) / log_range

    # First pass: Count
    for i in range(num_voxels):
        bucket_idx = math.floor((log_distances[i] - min_dist) * dist_inv)
        if bucket_idx >= BUCKET_COUNT:
            bucket_idx = BUCKET_COUNT - 1
        counts[bucket_idx] += 1

    # Calculate bucket starts (back-to-front)
    position = 0
    bucket_starts = [0] * BUCKET_COUNT
    for i in range(BUCKET_COUNT - 1, -1, -1):
        bucket_starts[i] = position
        position += counts[i]

    # Reset counts for second pass
    for i in range(BUCKET_COUNT):
        counts[i] = 0

    # Second pass: Distribute
    for i in range(num_voxels):
        bucket_idx = math.floor((log_distances[i] - min_dist) * dist_inv)
        if bucket_idx >= BUCKET_COUNT:
            bucket_idx = BUCKET_COUNT - 1
            
        pos = bucket_starts[bucket_idx] + counts[bucket_idx]
        indices[pos] = i
        counts[bucket_idx] += 1

    # Update last camera position
    last_camera_position = [cx, cy, cz]
    
    return indices
```

## Operating characteristics
- **Time Complexity:** $O(N + B)$, where $N$ is the number of voxels and $B$ is `BUCKET_COUNT` (65536) [S1, unofficial].
- **Memory Complexity:** $O(N + B)$ [S1, unofficial].
- **Performance:** The use of logarithmic distance mapping compresses the dynamic range of distances, allowing a fixed number of buckets to provide reasonable depth resolution across varying scene scales [S1, unofficial]. The early-exit optimization significantly reduces cost when the camera is static or moving very slightly [S1, unofficial].
- **Strengths:** Simple implementation, low memory overhead compared to full radix sorts, effective early-exit for static scenes [S1, unofficial].
- **Limitations:** Does not account for spatial locality (unlike Morton/Z-order sorting), which may result in poorer cache performance during the subsequent splatting/composition phase compared to spatially coherent sorts [S1, unofficial]. Sorting is strictly based on distance, so voxels at the same distance are not ordered relative to each other [S1, unofficial].

## Background
This method is implemented in the unofficial WebGL port of Nvidia's SVRaster paper, specifically in the `DistanceSorter` class [S1, unofficial]. It is designed as a CPU fallback or primary sorter for 3D Gaussian Splatting rendering in WebGL contexts where GPU-based sorting might be complex or unavailable [S1, unofficial]. It contrasts with the SVRaster paper's primary suggestion of using ray direction-dependent Morton ordering [S1, unofficial].
