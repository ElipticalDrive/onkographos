# Parallel Linear Assignment Sorting (PLAS)
Also called: FLAS, Fast Linear Assignment Sorting, PLAS (Fast Linear Assignment Sorting), PLAS sorting, Self-Organizing Gaussian Grids sorting

## Overview
Parallel Linear Assignment Sorting (PLAS) is a highly parallel 2D sorting algorithm designed to organize millions of high-dimensional Gaussian splat attributes into a 2D grid layout [S1]. It solves the problem of spatial correlation for compression by reordering Gaussian attribute vectors such that similar positions and colors share similar values in other attributes, leveraging the rendering invariance to sequential ordering [S2]. Unlike traditional grid-sorting algorithms like Self-Organizing Maps (SOM) or Linear Assignment Sorting (LAS) which are inadequate for millions of items, PLAS adapts these methods to enable continuous sorting during training without inflating duration [S1]. It sets itself apart by using a block-wise linear assignment approach with random block shifting to avoid local minima and ensure border coverage [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $N$ Gaussian splats, each defined by 59 attributes: 3D position ($x,y,z$), scale ($s_x,s_y,s_z$), rotation ($w,q_x,q_y,q_z$), opacity ($\alpha$), SH-DC coefficients ($f_{dc}$, 3 values), and SH-AC coefficients ($f_{ac}$, 45 values) [S2].
*   **Output:** A permutation index array that reorders the splats into a square 2D grid of size $n_{sidelen} \times n_{sidelen}$, where $n_{sidelen} = \lceil \sqrt{N} \rceil$. If $N$ is not a perfect square, Gaussians with the lowest opacity are pruned to fit the largest square grid [S1].

**Data Structures:**
1.  **Attributes Grid:** A 3D tensor of shape $(n_{sidelen}, n_{sidelen}, 59)$ storing the sorted attributes.
2.  **Target Grid:** A smoothed version of the current grid used as the assignment target.
3.  **Keys for Sorting:** A subset of attributes used to compute the distance metric. Typically, this includes the 3D position and SH-DC coefficients (6 dimensions) [S2]. Other implementations may use all attributes except SH-AC or all attributes [S3, unofficial].

**Parameters:**
*   $\phi$: The radius of the Gaussian blur applied to compute the target grid. Initial value $\phi = w^2 - 1$, where $w$ is the grid width [S1].
*   $\beta$: Block size, set as $\beta = \phi + 1$ [S1]. Minimum $\beta = 16$ to ensure efficient parallelization [S1].
*   `improvement_break`: Threshold for early stopping if improvement is below this value. Default $10^{-4}$ [S3, unofficial].
*   Convergence threshold: $0.01\%$ improvement in mean L2 distance [S1].

**Algorithm Steps:**

1.  **Initialization:**
    *   Determine grid side length $n_{sidelen} = \text{int}(N^{0.5})$. Assert $n_{sidelen}^2 == N$ (prune low-opacity Gaussians if necessary) [S3, unofficial].
    *   Normalize all Gaussian attributes independently to $[0, 1]$ and scale with individual weights. Use activated values (e.g., exponentially activated scale) as seen by the renderer [S1].
    *   Concatenate all parameter tensors (reshaped to $(N, -1)$) along the last dimension to form `params_to_sort` [S3, unofficial].
    *   Generate a random permutation `shuffled_indices` using `torch.randperm(N)` [S3, unofficial].
    *   Map Gaussians to random positions in the grid to avoid local minima [S1].

2.  **Target Construction:**
    *   Perform low-pass filtering (Gaussian blur with radius $\phi$) on the current grid to construct an idealized target grid [S1].

3.  **Block-wise Linear Assignment (Iterative):**
    *   Shift all blocks by a random $\Delta y$ and $\Delta x$ to sort across block borders and cover all grid borders when not aligned at multiples of the current block size [S1].
    *   Divide the grid into non-overlapping blocks of size $\beta \times \beta$ [S1].
    *   For each block, split elements into randomly assigned, non-overlapping groups of 4 [S1].
    *   Iterate through all 24 possible permutations for each group of 4 [S1].
    *   Calculate the total L2 distance between the permuted elements and the target grid values.
    *   Select the permutation with the lowest total distance [S1].
    *   Apply the selected permutations to update the grid.

4.  **Convergence Check:**
    *   Measure the mean L2 distance between the sorted grid and the target grid.
    *   If the improvement is less than $0.01\%$ compared to the previous value, restart the block shifting with new random $\Delta x, \Delta y$ [S1].
    *   If the assignment with new block positions does not improve the distance further (using the same threshold), reduce the radius: $\phi = 0.95 \phi$ [S1].

5.  **Termination:**
    *   Finish when $\phi < 1$ and sorting has converged [S1].
    *   Alternatively, stop if improvement is below `improvement_break` [S3, unofficial].

6.  **Final Permutation Application:**
    *   The sorting is based on a 6D vector (3D position + SH-DC) [S2].
    *   Uniformly apply the final permutation to all 59 attribute grids [S2].
    *   Reshape `params_to_sort` into $(n_{sidelen}, n_{sidelen}, -1)$ [S3, unofficial].
    *   Map sorted indices back to original space: `sorted_indices = shuffled_indices[sorted_indices]` [S3, unofficial].
    *   Reorder all splat parameters in the splats dict according to `sorted_indices` [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** The algorithm is highly parallel on the GPU, sorting millions of Gaussians in seconds [S1]. The complexity is dominated by the block-wise assignment, which is $O(N \cdot \beta^2 \cdot 24)$ per iteration, where $\beta$ is the block size [S1]. The number of iterations depends on the decay of $\phi$.
*   **Memory Complexity:** Requires storing the 2D grid of attributes, which is $O(N \cdot D)$, where $D$ is the number of attributes [S1].
*   **Performance:** Reduces storage size by a factor of 17x to 42x while maintaining high visual quality [S1].
*   **Strengths:** Efficient for large-scale scenes (millions of Gaussians), enables continuous sorting during training, improves compression efficiency by increasing spatial correlation [S1][S2].
*   **Limitations:** Requires perfect square grid size (pruning may be needed), attribute channels cannot be sorted individually [S1].
*   **When to use:** When compressing 3DGS models or requiring cache-coherent rendering of large Gaussian splat sets [S1][S3, unofficial].
*   **When not to use:** When real-time sorting is not required and standard rasterization order is sufficient, or when the number of Gaussians is small (thousands) where traditional sorting methods like LAS are adequate [S1].

## Background
Parallel Linear Assignment Sorting (PLAS) was introduced by Morgenstern et al. in 2024 in the paper "Compact 3D Scene Representation via Self-Organizing Gaussian Grids" [S1]. It is an adaptation of Linear Assignment Sorting (LAS) [2] and Fast Linear Assignment Sorting (FLAS) [2], which were previously used for non-parallel computations [S1]. PLAS extends these methods to handle millions of items on the GPU, addressing the inefficiency of traditional grid-sorting algorithms like SOM and Self-Sorting Map for large data volumes [S1]. It is primarily used in the context of 3D Gaussian Splatting (3DGS) compression, where it reorders Gaussian attributes to improve the efficiency of subsequent compression techniques like HEVC or VQ [S2][S3, unofficial].
