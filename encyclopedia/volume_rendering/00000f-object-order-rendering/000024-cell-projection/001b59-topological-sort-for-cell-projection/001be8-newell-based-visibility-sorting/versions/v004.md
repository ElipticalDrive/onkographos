# Newell-based Visibility Sorting

Also called: Newell, and Sancha (NNS), Newell and Sancha sort, NNS algorithm, Extended Newell, Visibility Sorting (Newell-based)

## Overview
Newell-based Visibility Sorting is an O(n²) algorithm for ordering convex polyhedra back-to-front to enable correct hardware compositing in volume rendering [S2, S3, S6]. It generalizes the Newell, Newell, and Sancha polygon sorting algorithm to 3-D volume elements, specifically handling unstructured meshes where topological adjacency information is unavailable [S6]. Unlike sibling methods that rely on grid topology (e.g., [Topological Sort for Cell Projection](999-topological-sort-for-cell-projection.md)) or exact geometric intersection checks (e.g., [SXMPVO](944-exact-visibility-ordering-for-cell-projection-volume-renderi.md)), this method uses a sequence of increasingly difficult geometric tests to determine occlusion between arbitrary pairs of cells [S1]. It is distinguished by its iterative list-reordering strategy and its explicit handling of visibility cycles through subdivision requirements [S2, S3].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $n$ convex polyhedra (cells) defined by their vertices. A viewpoint $V$.
*   **Output:** A list of cells sorted in back-to-front order (from farthest to nearest relative to $V$).

**Data Structures:**
*   **Cell:** A convex polyhedron. Precomputed data includes:
    *   Vertices: List of 3D coordinates.
    *   Faces: List of polygons (planar faces).
    *   Bounding Box: Extents along x, y, and z axes in screen space [S1].
    *   Bounding Sphere (Optional): Center and radius for alternative tests [S1].
*   **Sort List:** A dynamic list of cell indices.
*   **Moved Flag:** A boolean flag per cell to detect cycles [S2, S3].

**Numbered Steps:**

1.  **Preprocessing:** Apply viewing transformations to all vertices to obtain screen coordinates with perspective-corrected Z values [S6]. Precompute bounding boxes (and optionally bounding spheres) for each cell [S1].

2.  **Initial Sort:** Sort the cells from back to front based on the depth coordinate (Z) of their rear-most (farthest) vertex [S2, S3][S7, unofficial]. Let this list be $L$.

3.  **Iterative Testing:**
    *   Initialize an empty output list $O$.
    *   While $L$ is not empty:
        *   Take the rearmost cell $A$ from $L$ (the cell with the largest Z value in the current list order) [S2, S3][S7, unofficial].
        *   Iterate through the remaining cells in $L$ to find if $A$ occludes any other cell $B$.
        *   **Occlusion Test:** For each candidate cell $B$ in $L$ (excluding $A$), determine if $A$ obscures $B$ from viewpoint $V$. Use the sequence of tests below.
            *   **Test 1 (Z-extent):** Check if the z-extent of $B$ is entirely in front of the z-extent of $A$. If true, $A$ cannot obscure $B$. Terminate search for obscured cells for $A$ early if this test passes for all remaining $B$ [S1][S7, unofficial].
            *   **Test 2 (X-overlap):** Check if the x-extents of $A$ and $B$ do not overlap on the image plane. If true, $A$ cannot obscure $B$ [S1].
            *   **Test 3 (Y-overlap):** Check if the y-extents of $A$ and $B$ do not overlap on the image plane. If true, $A$ cannot obscure $B$ [S1].
            *   **Test 4 (Front-face separation):** Check if all vertices of $B$ lie in front of the plane of one of the front-facing faces of $A$. If true, $A$ cannot obscure $B$ [S1].
            *   **Test 5 (Back-face separation):** Check if all vertices of $A$ lie in back of the plane of one of the back-facing faces of $B$. If true, $A$ cannot obscure $B$ [S1].
            *   **Alternative Tests (Bounding Spheres):** If bounding spheres are available:
                *   **Test 19:** Check if the cones from the viewpoint to the bounding spheres of $A$ and $B$ are disjoint.
                *   **Test 29:** Check if the bounding sphere for $A$ is disjoint from and lies behind the bounding sphere for $B$ [S1].
            *   **Definitive Test:** If none of the above eliminate occlusion, perform a definitive search.
                *   Option A: Search for a separating plane between the cells using linear programming (Newell 1974) [S1].
                *   Option B: Search for an intersection between the projections of an edge of $A$ and an edge of $B$. If an intersection exists, the ray through it passes through both cells; determine which cell is in front by comparing Z values at the intersection point [S1].
        *   **Result Handling:**
            *   If $A$ does **not** occlude any other cell in $L$: Remove $A$ from $L$ and append it to the output list $O$ [S2, S3][S7, unofficial].
            *   If $A$ **does** occlude a cell $B$: Move $B$ to the rearmost position (head) of the initial list $L$ and restart the testing process with $B$ as the new candidate $A$ [S2, S3][S7, unofficial].
            *   **Cycle Detection:** Mark $B$ as "moved". If $B$ is already marked as moved and is about to be moved again, a visibility cycle is detected. No visibility sort is possible without subdivision [S2, S3][S7, unofficial].

4.  **Early Termination Optimization:** To maintain the validity of the Z-sort early termination (Test 1), track the position in list $L$ after which the Z-order is still undisturbed. When a cell is moved to the head, only test against cells up to this undisturbed boundary [S1].

5.  **Window Optimization (Optional):** Divide the image plane into windows. Maintain a farthest-Z-sorted list of cells overlapping each window. For a candidate cell $A$, only check lists for windows that $A$ overlaps [S1].

**Pseudocode:**

```python
def newell_visibility_sort(cells, viewpoint):
    """
    Sorts a list of convex polyhedra back-to-front using Newell-based visibility sorting.
    
    Args:
        cells: List of Cell objects.
        viewpoint: 3D point representing the camera position.
        
    Returns:
        List of Cell objects sorted back-to-front.
    """
    # Stage 1: Preprocessing
    for cell in cells:
        cell.transform(viewpoint)
        cell.compute_bounding_box()
        # Optional: cell.compute_bounding_sphere()

    # Stage 2: Initial Sort
    # Sort by the Z-coordinate of the farthest vertex
    cells.sort(key=lambda c: c.farthest_z, reverse=True)
    
    output_list = []
    moved_flags = {id(c): False for c in cells}
    
    # List of remaining cells to process
    remaining = list(cells)
    
    while remaining:
        # Take the rearmost cell A
        A = remaining[0]
        
        occluded_cell = None
        occluded_index = -1
        
        # Test A against all other cells in remaining
        # Optimization: Track undisturbed Z-order boundary
        # For simplicity, we iterate through the rest of the list
        for i in range(1, len(remaining)):
            B = remaining[i]
            
            # Test if A obscures B
            if does_a_obscure_b(A, B, viewpoint):
                occluded_cell = B
                occluded_index = i
                break # Found an obscured cell, stop searching for A
        
        if occluded_cell is None:
            # A does not obscure any remaining cell
            # Remove A from remaining and add to output
            remaining.pop(0)
            output_list.append(A)
        else:
            # A obscures B. Move B to the front of remaining.
            # Mark B as moved.
            if moved_flags[id(occluded_cell)]:
                # Cycle detected
                raise VisibilityCycleError("Visibility cycle detected. Subdivision required.")
            
            moved_flags[id(occluded_cell)] = True
            
            # Move B to the front (rearmost position in list context)
            b_cell = remaining.pop(occluded_index)
            remaining.insert(0, b_cell)
            
            # Restart testing with B as the new A

    """
    Sequence of tests to determine if cell_a obscures cell_b.
    Returns True if cell_a definitely obscures cell_b.
    Returns False if cell_a definitely does NOT obscure cell_b.
    """
    # Test 1: Z-extent
    if cell_b.z_min > cell_a.z_max:
        return False
    
    # Test 2: X-overlap
    if not intervals_overlap(cell_a.x_min, cell_a.x_max, cell_b.x_min, cell_b.x_max):
        return False
        
    # Test 3: Y-overlap
    if not intervals_overlap(cell_a.y_min, cell_a.y_max, cell_b.y_min, cell_b.y_max):
        return False
        
    # Test 4: Front-face separation
    if all_vertices_in_front_of_plane(cell_b.vertices, cell_a.front_faces):
        return False
        
    # Test 5: Back-face separation
    if all_vertices_in_back_of_plane(cell_a.vertices, cell_b.back_faces):
        return False
        
    # Alternative Tests (if bounding spheres available)
    # if cones_disjoint(viewpoint, cell_a.bounding_sphere, cell_b.bounding_sphere):
    #     return False
    # if sphere_a_disjoint_behind_sphere_b(cell_a.bounding_sphere, cell_b.bounding_sphere):

    # Definitive Test
    # Search for separating plane or edge intersection
    if has_separating_plane(cell_a, cell_b):

    if no_edge_intersection_projections(cell_a, cell_b):

    return True

def intervals_overlap(min1, max1, min2, max2):
    return max1 >= min2 and max2 >= min1

def all_vertices_in_front_of_plane(vertices, faces):
    # Check if all vertices are in front of ANY front-facing face
    for face in faces:
        if is_front_facing(face):
            if all_vertex_in_front(vertex, face.plane) for vertex in vertices:
                return True
    return False

    # Normal points towards viewpoint
    return dot(face.normal, viewpoint - face.centroid) > 0

    # Normal points away from viewpoint
    return dot(face.normal, viewpoint - face.centroid) < 0
```

## Subtopics

### [Polyhedron Sorting with Fine-Tuning](16500-polyhedron-sorting-with-fine-tuning.md)
A three-stage sorting algorithm for rendering convex polyhedra (volume primitives) in correct back-to-front depth order, specifically designed to handle non-planar faces and rendering cycles in unstructured volume data. It extends the Newell-based visibility sorting approach by introducing a rigorous "fine-tuning" stage that uses plane separation tests and edge intersection checks to resolve ambiguities that a simple Z-depth sort cannot handle. Unlike the parent method which relies on Newell's basic plane tests, this method explicitly handles cycles by reordering the list and detecting circular dependencies, ensuring correct hardware compositing for primitives like tetrahedra, pyramids, and bricks.

## Operating characteristics
*   **Time Complexity:** O(n²) in the worst case, as it performs pairwise occlusion tests for $n$ cells [S2, S3, S6][S7, unofficial]. The initial sort is O(n log n) [S1].
*   **Memory Complexity:** O(n) to store the cells and the sort list [S1].
*   **Performance:** The algorithm is slow for large grids due to the quadratic number of tests [S1]. However, early termination tests (Z, X, Y extents) often eliminate pairs quickly, improving average-case performance [S1].
*   **Strengths:**
    *   Handles unstructured meshes without topological adjacency information [S6].
    *   Simple to implement compared to BSP-tree based methods [S5, unofficial].
    *   Provides a clear mechanism for detecting visibility cycles [S2, S3].
*   **Limitations:**
    *   Cannot handle visibility cycles without subdividing cells [S2, S3, S6][S7, unofficial].
    *   Does not handle non-planar faces natively; requires preprocessing or subdivision [S1].
    *   Performance degrades significantly with large numbers of cells [S1].
*   **When to use:** Suitable for small to medium-sized unstructured grids where topological information is unavailable and exact geometric sorting is required [S6].
*   **When not to use:** For large grids, structured grids with topological data, or when real-time performance is critical [S1, S6].

## Background
The Newell, Newell, and Sancha (NNS) algorithm was originally developed for sorting polygons [S5, unofficial]. It was extended to 3-D polyhedra for volume rendering of unstructured grids [S2, S3, S6]. The method is based on the work of Newell, Newell, and Sancha (1972) and Newell (1974) [S1][S5, unofficial]. It serves as a basis for more recent techniques in volume rendering of unstructured data [S5, unofficial]. The algorithm is particularly relevant for visualizing simulation data from curvilinear grids and finite element analysis where cells may be deformed and non-planar [S1, S6].
