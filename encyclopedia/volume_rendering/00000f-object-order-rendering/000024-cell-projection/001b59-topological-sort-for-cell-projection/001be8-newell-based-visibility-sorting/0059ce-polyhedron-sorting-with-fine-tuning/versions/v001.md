# Polyhedron Sorting with Fine-Tuning

Also called: Hidden surface removal for volume primitives, Shirley-Tuckman extension for unstructured data

## Overview
A three-stage sorting algorithm for rendering convex polyhedra (volume primitives) in correct back-to-front depth order, specifically designed to handle non-planar faces and rendering cycles in unstructured volume data [S1]. It extends the Newell-based visibility sorting approach by introducing a rigorous "fine-tuning" stage that uses plane separation tests and edge intersection checks to resolve ambiguities that a simple Z-depth sort cannot handle [S1, Parent]. Unlike the parent method which relies on Newell's basic plane tests, this method explicitly handles cycles by reordering the list and detecting circular dependencies, ensuring correct hardware compositing for primitives like tetrahedra, pyramids, and bricks [S1].

## How it works
The algorithm sorts a list of $N$ convex polyhedra into back-to-front order relative to the viewer. It consists of three stages: viewing transformation, rough sorting, and fine-tuning.

### Inputs and Outputs
*   **Input**: A list $H$ of $N$ convex polyhedra. Each polyhedron $P$ is defined by a set of vertices and faces. Each face is defined by an ordered list of vertices.
*   **Output**: A sorted list $H$ where $P_i$ precedes $P_j$ if $P_i$ is behind $P_j$ (i.e., $P_j$ obscures $P_i$).

### Data Structures
*   **Polyhedron $P$**:
    *   `vertices`: List of 3D points $(x, y, z)$.
    *   `faces`: List of faces.
    *   `face_normals`: Pre-computed average outward normals for each face.
    *   `face_planes`: Pre-computed plane coefficients $(a, b, c, d)$ for each face.
    *   `Z_rearmost`: The maximum $Z$ coordinate of all vertices after viewing transformation (used for rough sort).
*   **Face Plane**: Defined by $ax + by + cz + d = 0$.
*   **Edge**: Defined by two vertices.

### Pre-processing
1.  **Viewing Transformation**: Apply viewing and projection transformations to all vertices. Scale $Z$ such that the eye looks down the $Z$ axis towards negative infinity in a right-handed coordinate system. Sort by increasing $Z$ (smaller $Z$ is further away, larger $Z$ is closer) [S1].
2.  **Face Normal and Plane Calculation**: For each face with $n$ vertices $(x_i, y_i, z_i)$, calculate the average outward normal $(a, b, c)$ using Newell's method [S1]:
    $$ a = \frac{1}{n} \sum_{i=1}^{n} (y_i - y_j)(z_i + z_j) $$
    $$ b = \frac{1}{n} \sum_{i=1}^{n} (z_i - z_j)(x_i + x_j) $$
    $$ c = \frac{1}{n} \sum_{i=1}^{n} (x_i - x_j)(y_i + y_j) $$
    where $j = (i+1) \pmod n$ [S1].
3.  **Plane Coefficient $d$**: Calculate $d$ using the centroid of the face $(\bar{x}, \bar{y}, \bar{z})$ as a point on the plane:
    $$ d = -(a\bar{x} + b\bar{y} + c\bar{z}) $$
    where $\bar{x} = \frac{1}{n}\sum x_i$, etc. [S1].
4.  **Face Classification**: Determine if a face is front-facing or back-facing based on the $Z$ component of its outward normal. In a right-handed system where the eye looks down the $Z$ axis, a positive $Z$ component of the normal indicates a front-facing polygon; a negative or zero component indicates a back-facing polygon [S1].
5.  **Tolerance $\delta$**: For each face, calculate $\delta$ as the maximum deviation of any vertex of that face from its average plane. This tolerance is used to handle non-planar faces and round-off errors [S1].

### Fine-Tuning Sort Algorithm
The fine-tuning stage iterates through the list $H$ to correct the order established by the rough sort. For each pair of adjacent polyhedra $P$ and $Q$ (where $P$ is currently before $Q$ in the list), the algorithm determines if they are in the correct order. If not, $Q$ is moved to the head of the list, and the process repeats with $Q$ as the new $P$ [S1].

**Step 1: Test if $P$ is behind $Q$ (Separating Plane Test)**
Check if all vertices of $P$ lie behind a plane defined by any back-facing polygon of $Q$.
For each back-facing face of $Q$ with plane equation $f(x,y,z) = ax+by+cz+d$:
$$ f(x_j, y_j, z_j) \ge -\delta \quad \forall \text{ vertices } j \in P $$
If this holds for at least one back-facing face of $Q$, then $P$ is behind $Q$. The order is correct. Return `True` [S1].

**Step 2: Test if $Q$ is in front of $P$ (Separating Plane Test)**
Check if all vertices of $Q$ lie in front of a plane defined by any front-facing polygon of $P$.
For each front-facing face of $P$ with plane equation $f(x,y,z) = ax+by+cz+d$:
$$ f(x_j, y_j, z_j) \ge -\delta \quad \forall \text{ vertices } j \in Q $$
If this holds for at least one front-facing face of $P$, then $Q$ is in front of $P$. The order is correct. Return `True` [S1].

**Step 3: Edge Intersection Test**
If Tests 1 and 2 fail, call `EdgeIntersection(P, Q)`.
1.  Project all edges of $P$ and $Q$ onto the screen plane.
2.  Find all intersection points between edges of $P$'s projection and edges of $Q$'s projection.
3.  If no intersections are found:
    *   If the projections are disjoint, the order does not matter. Return `True` [S1].
    *   If the projections overlap but no edges intersect (e.g., one is inside the other), assume the polyhedron with the larger $Z_{rearmost}$ is in front. If $Z_{rearmost}(Q) > Z_{rearmost}(P)$, return `True`. Else, return `False` [S1].
4.  If intersections are found:
    *   For each intersection point, calculate the $Z$ coordinate on the surface of $P$ ($Z_P$) and on the surface of $Q$ ($Z_Q$).
    *   If $Z_P < Z_Q$ for any intersection, $P$ is in front. Return `True` [S1].
    *   If $Z_Q < Z_P$ for any intersection, $Q$ is in front. Return `False` [S1].
    *   If $Z_P = Z_Q$ for all intersections, continue searching for an inequality. If none found, return `False` (ambiguous/cycle) [S1].

**Step 4: Cycle Handling and Resolution**
If `EdgeIntersection` returns `False` (indicating $Q$ obscures $P$ or a cycle exists):
1.  Move $Q$ to the head of the list $H$.
2.  Repeat the fine-tuning process with $Q$ as the new $P$ and the next polyhedron as $Q$.
3.  **Cycle Detection**: Tag polyhedra that have been moved to the head. If a polyhedron $Q$ is already tagged when it becomes the new $P$, a cycle has been detected (e.g., $A$ obscures $B$, $B$ obscures $C$, $C$ obscures $A$) [S1].
4.  **Cycle Resolution**: If a cycle is detected or all tests fail, render the polyhedron whose $Z_{rearmost}$ is further from the eye (smaller $Z$) first [S1].

### Pseudocode

```python
def sort_polyhedra(polyhedra):
    """
    Sorts a list of convex polyhedra back-to-front.
    polyhedra: List of Polyhedron objects.
    Returns: Sorted list.
    """
    # Stage 1: Viewing Transformation
    for P in polyhedra:
        P.transform_view()
        P.calculate_rearmost_z()
        P.calculate_face_normals_and_planes()
        P.calculate_face_tolerances()

    # Stage 2: Rough Sort
    polyhedra.sort(key=lambda P: P.Z_rearmost)

    # Stage 3: Fine-Tuning Sort
    changed = True
    while changed:
        changed = False
        for i in range(len(polyhedra) - 1):
            P = polyhedra[i]
            Q = polyhedra[i+1]
            
            # Check if P is behind Q
            if is_behind(P, Q):
                continue
            
            # Check if Q is in front of P
            if is_in_front(Q, P):
                continue
            
            # Edge Intersection Test
            result = edge_intersection(P, Q)
            if result == "P_in_front":
                continue
            elif result == "Disjoint":
                continue
            else:
                # Q is in front or cycle
                # Move Q to head of list to re-evaluate
                polyhedra.pop(i+1)
                polyhedra.insert(0, Q)
                changed = True
                break # Restart loop from beginning
    
    # Handle any remaining cycles at the end
    for i in range(len(polyhedra) - 1):
        P = polyhedra[i]
        Q = polyhedra[i+1]
        if not is_behind(P, Q) and not is_in_front(Q, P):
            if edge_intersection(P, Q) == "Q_in_front_or_cycle":
                # Resolve cycle by Z_rearmost
                if P.Z_rearmost < Q.Z_rearmost:
                    # P is further, should be first. Order is correct.
                    pass
                else:
                    # Q is further, should be first. Swap.
                    polyhedra[i], polyhedra[i+1] = polyhedra[i+1], polyhedra[i]
    
    return polyhedra

def is_behind(P, Q):
    """
    Returns True if all vertices of P lie behind a back-facing face of Q.
    """
    for face in Q.back_facing_faces:
        all_behind = True
        for vertex in P.vertices:
            val = face.plane_evaluate(vertex)
            if val < -face.tolerance:
                all_behind = False
                break
        if all_behind:
            return True
    return False

def is_in_front(Q, P):
    """
    Returns True if all vertices of Q lie in front of a front-facing face of P.
    """
    for face in P.front_facing_faces:
        all_in_front = True
        for vertex in Q.vertices:
            val = face.plane_evaluate(vertex)
            if val < -face.tolerance:
                all_in_front = False
                break
        if all_in_front:
            return True
    return False

def edge_intersection(P, Q):
    """
    Returns "P_in_front", "Q_in_front", "Disjoint", or "Q_in_front_or_cycle".
    """
    intersections = find_screen_edge_intersections(P, Q)
    
    if not intersections:
        if projections_overlap(P, Q):
            # One inside another or touching
            if P.Z_rearmost > Q.Z_rearmost:
                return "Q_in_front_or_cycle" # Ambiguous, assume Q in front for safety? 
                # Note: Source says if disjoint, order doesn't matter. 
                # If overlapping but no edge intersections, source implies 
                # use Z_rearmost. If Z equal, continue searching. 
                # If no inequality found, return False (Q in front).
            else:
                return "P_in_front"
        else:
            return "Disjoint"
    
    for intersection in intersections:
        Z_P = get_z_on_surface(P, intersection)
        Z_Q = get_z_on_surface(Q, intersection)
        
        if Z_P < Z_Q:
            return "P_in_front"
        elif Z_Q < Z_P:
            return "Q_in_front_or_cycle" # Q is closer, so Q is in front
        # If Z_P == Z_Q, continue searching
    
    return "Q_in_front_or_cycle" # No inequality found, assume Q in front
```

## Operating characteristics
*   **Time Complexity**: The fine-tuning sort is $O(N^2)$ in the worst case, where $N$ is the number of polyhedra. This occurs when all polyhedra have overlapping $Z$ extents, forcing the algorithm to perform the expensive edge intersection tests for many pairs [S1]. Tests 1 and 2 are $O(1)$. Tests 3 and 4 are $O(F_i E_j)$ and $O(E_i F_j)$ respectively, where $F$ is the number of faces and $E$ is the number of vertices/edges. Test 5 (Edge Intersection) is $O(E_i E_j)$ [S1].
*   **Memory Complexity**: $O(N + F + E)$ to store the polyhedra, faces, and pre-computed plane coefficients [S1].
*   **Measured Performance**: On an SGI Indigo2 workstation, a simple QuickSort could interactively sort thousands of elements, but the correct fine-tuning sort slowed down to a few hundred elements [S1].
*   **Strengths**: Correctly handles non-planar faces and cycles, which are common in finite element meshes. More efficient than linear programming methods for hidden surface removal [S1].
*   **Limitations**: Quadratic worst-case time complexity makes it unsuitable for very large datasets without acceleration structures. The tolerance $\delta$ is heuristic and may cause visual artifacts if set incorrectly [S1].

## Background
The algorithm was developed by Peter Shirley and Andrew Tuckman for the SGI Explorer volume visualization system [S1]. It extends the work of Michael E. Newell on procedure models for digital image synthesis . The implementation was used to sort pyramid-type volume primitives (tetrahedra, pyramids, prisms, wedges, and bricks) on the SGI Indigo2 workstation [S1]. The method addresses the limitations of simple Z-sorting by providing a robust hidden surface removal technique for unstructured volume data [S1].
