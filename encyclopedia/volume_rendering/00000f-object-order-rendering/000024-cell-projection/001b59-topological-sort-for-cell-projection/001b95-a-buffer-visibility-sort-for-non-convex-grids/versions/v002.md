# A-buffer visibility sort for non-convex grids

Also called: Visibility sorting for non-convex grids, Topological Sort with A-Buffer for Non-Convex Grids

## Overview
This method extends the Topological Sort for Cell Projection to handle non-convex grids by using a software A-buffer to detect and resolve visibility relations between boundary cells that are separated by gaps in the grid volume [S1][S2, unofficial]. While the parent method assumes convexity and shared faces, this variant handles cases where viewing rays exit the grid through an exterior face, traverse empty space, and re-enter a different cell [S2, unofficial]. It differs from siblings like [Exact Visibility Ordering for Cell Projection Volume Rendering (SXMPVO)](944-exact-visibility-ordering-for-cell-projection-volume-renderi.md) by avoiding expensive pairwise occlusion tests or BSP-tree preprocessing, instead relying on per-pixel fragment lists to extract ordering constraints [S1][S2, unofficial].

## How it works
**Inputs:**
*   A non-convex curvilinear grid consisting of $n$ cells [S1][S2, unofficial].
*   A set of exterior (boundary) faces, with count $b$ [S1][S2, unofficial].
*   Image dimensions $w \times h$ [S1][S2, unofficial].
*   A viewing direction and camera setup defining pixel sample rays [G].

**Outputs:**
*   A topologically sorted list of cells suitable for back-to-front volume rendering [S1][S2, unofficial].

**Data Structures:**
1.  **Exterior Face List:** A list of all exterior faces [S1]. Each face contains its geometric definition and its centroid depth $z_c$ along the viewing direction [S1][S2, unofficial].
2.  **Software A-Buffer:** An array of size $w \times h$ [S1][S2, unofficial]. Each pixel entry contains a pointer to a linked list of fragments [S3, unofficial].
3.  **Fragment:** A structure stored in the A-buffer linked lists, containing:
    *   `face_id`: Identifier of the exterior face intersecting the ray.
    *   `z`: The depth of the intersection point along the viewing ray.
    *   `next`: Pointer to the next fragment in the sorted list.
4.  **Relation Graph:** A directed acyclic graph (DAG) used by the topological sort, containing edges for shared faces and edges extracted from the A-buffer [S1][S2, unofficial].

**Algorithm Steps:**

1.  **Sort Exterior Faces:**
    Sort the list of $b$ exterior faces in descending order of their centroid depth $z_c$. This ensures that when scan-converting, new intersections are likely to be added to the head of the A-buffer lists, minimizing list maintenance cost [S1][S2, unofficial].

2.  **Initialize A-Buffer:**
    Allocate the $w \times h$ A-buffer array. Initialize all pixel entries to null pointers. This step incurs a cost proportional to the number of pixels $wh$ [S1][S2, unofficial].

3.  **Scan-Convert and Populate A-Buffer:**
    For each exterior face $f$ in the sorted list:
    a.  Determine the pixel coverage of face $f$ in the image plane.
    b.  For each covered pixel $(x, y)$:
        i.  Compute the intersection point $P$ of the pixel's viewing ray with the face $f$.
        ii. Calculate the depth $z = P \cdot \vec{v}$, where $\vec{v}$ is the normalized viewing direction.
        iii. Insert a new fragment `{face_id: f.id, z: z}` into the linked list at A-Buffer[$x, y$].
        iv. Maintain the linked list in ascending order of $z$ (front-to-back). Since faces are processed back-to-front, the new fragment will typically be inserted at the head or near the head of the list [S1][S2, unofficial].

4.  **Extract Gap Relations:**
    Iterate through every pixel $(x, y)$ in the A-buffer:
    a.  If the linked list at A-Buffer[$x, y$] contains more than one fragment, iterate through the list from front to back.
    b.  For every consecutive pair of fragments $(F_i, F_{i+1})$ in the list:
        i.  Let $f_{front} = F_i.face\_id$ and $f_{back} = F_{i+1}.face\_id$.
        ii. Add a directed edge $f_{back} \to f_{front}$ to the Relation Graph. This edge signifies that $f_{front}$ is visible in front of $f_{back}$ along this specific ray segment crossing a gap [S1][S2, unofficial].

5.  **Process Shared Face Relations:**
    Add the standard topological edges derived from shared faces between adjacent cells in the grid [S1][S2, unofficial].

6.  **Topological Sort:**
    Process the extracted relations during the topological sort alongside relations across shared faces [S1][S2, unofficial].

**Pseudocode:**

```python
def a_buffer_visibility_sort(grid, image_width, image_height, view_direction, camera_origin):
    # 1. Identify exterior faces and compute centroid depths
    exterior_faces = grid.get_exterior_faces()
    for face in exterior_faces:
        face.centroid_depth = dot(face.centroid, view_direction)
    
    # Sort faces back-to-front by centroid depth
    exterior_faces.sort(key=lambda f: f.centroid_depth, reverse=True)
    
    # 2. Initialize A-Buffer: array of linked lists per pixel
    a_buffer = [None] * (image_width * image_height)
    
    # 3. Scan-convert exterior faces into A-Buffer
    for face in exterior_faces:
        # Determine pixel bounding box of projected face [G]
        min_x, max_x, min_y, max_y = project_face_bbox(face, image_width, image_height)
        for y in range(min_y, max_y + 1):
            for x in range(min_x, max_x + 1):
                # Compute viewing ray for pixel (x, y) [G]
                ray_origin, ray_direction = compute_pixel_ray(x, y, camera_origin, view_direction)
                # Intersect ray with face [G]
                t = intersect_face(ray_origin, ray_direction, face)
                if t > 0:
                    intersection_point = ray_origin + t * ray_direction
                    z = dot(intersection_point, view_direction)
                    fragment = {'face_id': face.id, 'z': z, 'next': None}
                    # Insert into sorted linked list (ascending z)
                    head = a_buffer[y * image_width + x]
                    if head is None or z < head['z']:
                        fragment['next'] = head
                        a_buffer[y * image_width + x] = fragment
                    else:
                        current = head
                        while current['next'] is not None and current['next']['z'] < z:
                            current = current['next']
                        fragment['next'] = current['next']
                        current['next'] = fragment

    # 4. Extract relations from A-Buffer
    relation_graph = {}
    for y in range(image_height):
        for x in range(image_width):
            current = a_buffer[y * image_width + x]
            while current is not None:
                next_frag = current['next']
                if next_frag is not None:
                    # next_frag is behind current along this ray
                    relation_graph.setdefault(next_frag['face_id'], set()).add(current['face_id'])
                current = next_frag

    # 5. Add shared face relations
    shared_relations = grid.get_shared_face_relations(view_direction)
    for u, v in shared_relations:
        relation_graph.setdefault(u, set()).add(v)
    
    # 6. Topological Sort
    sorted_cells = topological_sort(relation_graph)
    return sorted_cells

# Standard helper operations [G]
def project_face_bbox(face, w, h):
    # Project face vertices to screen space and compute bounding box
    return (0, w-1, 0, h-1)

def compute_pixel_ray(x, y, origin, direction):
    # Return ray origin and normalized direction for pixel (x, y)
    return origin, direction

def intersect_face(o, d, face):
    # Return positive t if ray intersects face, else None
    return 1.0

def topological_sort(graph):
    # Kahn's algorithm for DAG topological sort
    in_degree = {u: 0 for u in graph}
    for u in graph:
        for v in graph[u]:
            in_degree[v] = in_degree.get(v, 0) + 1
    queue = [u for u in in_degree if in_degree[u] == 0]
    result = []
    while queue:
        u = queue.pop(0)
        result.append(u)
        for v in graph.get(u, set()):
            in_degree[v] -= 1
            if in_degree[v] == 0:
                queue.append(v)
    return result
```

**Parameters and Typical Values:**
*   $w, h$: Image resolution. Typical values depend on the target display or output size.
*   $b$: Number of exterior faces. Depends on grid complexity.
*   $a$: Projected area of external faces in pixels. Proportional to the number of pixels covered by exterior faces.

**Edge Cases and Pitfalls:**
*   **Non-Planar Faces:** In a curvilinear grid, quadrilateral faces may not be planar. A viewing ray can leave a cell and re-enter it across the same face, making a strict visibility sort impossible for that face [S1][S2, unofficial].
*   **Occlusion Outside Pixel Centers:** The algorithm does not produce a true visibility sort because cells may occlude each other along viewing rays which do not pass through pixel centers. However, since the A-buffer rays are the same as the pixel sample rays used in the final hardware rendering, the image will be correct [S1][S2, unofficial].

## Subtopics

### [ZSWEEP](1280-zsweep.md)
ZSWEEP is an exact, object-order cell projection algorithm for volume rendering on unstructured grids that optimizes for sorting efficiency and memory usage. It solves the problem of correctly ordering cell segments for front-to-back compositing without the high memory overhead of ray-casting or the complexity of true global visibility sorts. It sets itself apart from its parent [A-buffer visibility sort for non-convex grids](1057-a-buffer-visibility-sort-for-non-convex-grids.md) by using a sweep-plane approach that exploits the implicit global ordering induced by vertex z-coordinates, rather than maintaining full A-buffer lists for all pixels simultaneously. Choose it when memory is constrained and vertex-based ordering is sufficient.

### [k*-Buffer Analysis](3932-k-buffer-analysis.md)
k*-Buffer Analysis is a software-based diagnostic method used to determine the optimal fixed buffer size $k$ for the k-buffer visibility sorting algorithm in hardware-assisted volume rendering. It determines the required $k$ size for accurate visibility ordering by recording insertion depth into an ideal A-buffer. Unlike the unbounded A-buffer, which stores all fragments, or conservative sorting schemes like ZSWEEP, the k-buffer limits storage to $k$ entries per pixel, requiring an analysis of how "nearly sorted" the fragment stream is to ensure correct compositing. Choose it when targeting GPU acceleration with fixed memory budgets.

## Operating characteristics
**Time Complexity:**
The algorithm typically takes time $O(b \log b + wh + a + n)$ [S1][S2, unofficial].
*   $b \log b$: Sorting the exterior faces by centroid depth.
*   $wh$: Overhead for setting up and checking the A-buffer lists for all pixels.
*   $a$: Cost of scan-converting exterior faces, extracting relations from A-buffer lists, and processing them during the topological sort. This is proportional to the projected area $a$ of the external faces in pixels.
*   $n$: Processing relations across shared faces, same as in the convex case.

**Memory Complexity:**
Memory usage is dominated by the A-buffer, which requires storage for $wh$ linked lists. The total number of fragments stored is proportional to the total number of intersections between viewing rays and exterior faces, bounded by the projected area $a$ and the maximum overlap per pixel.

**Performance and Scaling:**
The method is faster than pairwise occlusion tests ($O(b^2)$) or BSP-tree based approaches for general non-convex grids [S1][S2, unofficial]. It scales linearly with the number of pixels and the projected area of exterior faces. Sorting exterior faces by centroid depth ensures that new intersections almost always occur at the head of the A-buffer list, keeping maintenance inexpensive [S1][S2, unofficial].

**Strengths:**
*   Avoids complex geometric preprocessing like BSP trees.
*   Handles non-convex grids with gaps between boundary cells.
*   Ensures image correctness by aligning visibility checks with pixel sample rays.

**Limitations:**
*   Not a true geometric visibility sort; relies on pixel-level sampling.
*   Memory intensive for high-resolution images or highly overlapping exterior faces.
*   Performance depends on the projected area $a$; large exterior faces increase cost.

## Background
The A-buffer was introduced by Loren Carpenter in 1984 as a method to resolve visibility and aliasing problems by maintaining multiple fragments per pixel [S3, unofficial]. The application of the A-buffer to visibility sorting for non-convex grids in volume rendering was proposed by Comba, Silva, and others in the early 2000s [S1][S2, unofficial]. This approach was developed to address the limitations of topological sorting methods that assumed convexity, allowing for efficient rendering of complex curvilinear and unstructured grids without the overhead of BSP-tree construction [S1][S2, unofficial].
