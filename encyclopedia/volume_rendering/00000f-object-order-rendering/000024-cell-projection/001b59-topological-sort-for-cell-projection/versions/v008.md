# Topological Sort for Cell Projection

Also called: Exact Meshed Polyhedra Visibility Ordering, Exact Visibility Ordering for Cell Projection, MPVO (Meshed Polyhedra Visibility Ordering), MPVO algorithm, Maximal Polyhedra Visibility Ordering, Meshed Polyhedra Visibility Ordering

## Overview
Topological Sort for Cell Projection (MPVO) is an object-space algorithm that computes a correct back-to-front visibility ordering of convex polyhedral cells in a convex mesh by constructing a directed adjacency graph based on face-sharing topology and viewpoint orientation [S1][S4, unofficial][S5, unofficial]. It relies on local ordering relations between cells sharing a common face to define a partial order, which a topological sort converts to a total order [S2][S3].

## How it works
**Inputs and Outputs:**
*   **Input:** A convex mesh composed of convex polyhedral cells; a viewpoint $V$ (for perspective) or a view direction vector $\vec{d}$ (for orthogonal projection); a precomputed adjacency graph of the mesh [S4, unofficial][S5, unofficial].
*   **Output:** A total ordering sequence of cells $[c_1, c_2, \dots, c_n]$ such that if cell $A$ occludes cell $B$, $B$ precedes $A$ in the list [S1][S9, unofficial].

**Data Structures:**
1.  **Adjacency Graph:** A directed graph $G=(C, E)$ where nodes $C$ are cells and edges $E$ represent shared faces [S1][S3].
2.  **Plane Coefficients:** For each interior face $f$ shared by cells $c_i$ and $c_j$, store the plane equation coefficients $(A_f, B_f, C_f, D_f)$ such that $A_f x + B_f y + C_f z + D_f = 0$ [S4, unofficial][S5, unofficial].
3.  **Cell State:** Each cell $c$ maintains `incount` (integer), `visited` (boolean), and `cycle_detection` (boolean) [S1][S3][S8, unofficial].
4.  **Queue/Sink List/Output List:** Standard FIFO queue and lists for topological sort traversal [G].

**Numbered Steps:**

1.  **Preprocessing (Static):** Construct the undirected adjacency graph of the mesh. For every interior face shared by two cells, compute and store the plane equation coefficients. This step is performed once per static mesh and reused for all viewpoints [S4, unofficial][S5, unofficial].

2.  **Phase I: Partial Ordering (Arrow Assignment):**
    For each interior face $f$ shared by cells $c_1$ and $c_2$:
    *   Evaluate the plane equation of $f$ at the viewpoint $V=(V_x, V_y, V_z)$ (for perspective) or use the view direction $\vec{d}$ (for orthogonal) [S1][S9, unofficial].
    *   Determine the "behind" relation: If $V$ lies in the half-space of $f$ containing $c_1$, then $c_1$ is "behind" $c_2$ relative to the viewer (i.e., $c_2$ occludes $c_1$). We denote this $c_2 <_{vp} c_1$ [S3].
    *   Add a directed edge from $c_1$ to $c_2$ in the graph $G$. This edge represents an "outbound arrow" for $c_1$ and an "inbound arrow" for $c_2$ [S1][S8, unofficial].

3.  **Phase II: Topological Sort (DFS-based):**
    *   **Initialization:**
        *   Set `visited` and `cycle_detection` to `false` for all cells [S9, unofficial].
        *   Set `incount` to 0 for all cells [S3].
        *   For every directed edge $c_i \to c_j$ in $G$, increment `incount` of $c_j$ [S3].
        *   Identify all cells with `incount` == 0. These are "sink cells" (cells that do not occlude any other cell across a shared face). Add them to the `Sink List` [S1][S8, unofficial].
    *   **Traversal:**
        *   While `Sink List` is not empty:
            *   Remove a cell $C$ from `Sink List`.
            *   Call `RECURSIVE-DFS(C)` [S1][S8, unofficial].
    *   **RECURSIVE-DFS(currentCell):**
        1.  Set `currentCell.visited` = `true` and `currentCell.cycle_detection` = `true` [S1].
        2.  Identify all **eligible neighbors** of `currentCell`. An eligible neighbor $N$ is a cell such that there is a directed edge $N \to currentCell$ in $G$ (i.e., $N$ is "in front of" `currentCell` and `currentCell` occludes $N$) [S1][S8, unofficial].
        3.  For each eligible neighbor $N$:
            *   If `N.visited` is `false`:
                *   Call `RECURSIVE-DFS(N)` [S1].
            *   Else if `N.cycle_detection` is `true`:
                *   A visibility cycle is detected. Output a warning/error and terminate. No valid ordering exists without subdividing the cycle [S1][S8, unofficial].
        4.  After processing all eligible neighbors:
            *   Add `currentCell` to the end of the `Output List` [S1][S8, unofficial].
            *   Set `currentCell.cycle_detection` = `false` [S1][S8, unofficial].

4.  **Cycle Handling:**
    *   If the algorithm terminates with cells remaining in the graph (not all cells added to `Output List`), a visibility cycle exists. The standard MPVO algorithm cannot resolve this; the offending cells must be subdivided or a different sorting method (e.g., [XMPVO](1363-xmpvo.md)) must be used [S1][S8, unofficial].

**Pseudocode:**

```python
class VisibilityCycleError(Exception): pass

def mpvo_sort(cells, adjacency_graph, viewpoint):
    """
    cells: List of Cell objects.
    adjacency_graph: Dict mapping cell_id -> list of neighbor_cell_ids (shared faces).
    viewpoint: Tuple (x, y, z) or view direction vector.
    Returns: List of Cell objects in back-to-front order.
    """
    cells_by_id = {c.id: c for c in cells}
    
    # Phase I: Build Directed Graph and Compute In-Counts
    directed_graph = {c.id: [] for c in cells}
    in_counts = {c.id: 0 for c in cells}
    
    for c1 in cells:
        for c2 in adjacency_graph.get(c1.id, []):
            # Compute plane equation for shared face between c1 and c2
            # Sources do not specify the exact geometric routine for plane extraction [G]
            A, B, C, D = get_face_plane(c1, c2)
            
            # Evaluate plane at viewpoint
            val = A * viewpoint[0] + B * viewpoint[1] + C * viewpoint[2] + D
            
            # If val > 0, viewpoint is on the side of the normal (c2's side)
            # This means c2 is in front of c1 relative to viewpoint.
            # Relation: c1 <vp c2. Edge points from back to front: c1 -> c2.
            if val > 0:
                directed_graph[c1.id].append(c2.id)
                in_counts[c2.id] += 1
            else:
                directed_graph[c2.id].append(c1.id)
                in_counts[c1.id] += 1

    # Build reverse graph for DFS eligible neighbor lookup
    reverse_graph = {c.id: [] for c in cells}
    for u in directed_graph:
        for v in directed_graph[u]:
            reverse_graph[v].append(u)

    # Phase II: Topological Sort via DFS
    visited = {c.id: False for c in cells}
    cycle_detection = {c.id: False for c in cells}
    output_list = []
    sink_list = [c.id for c in cells if in_counts[c.id] == 0]

    def recursive_dfs(current_id):
        visited[current_id] = True
        cycle_detection[current_id] = True
        
        # Eligible neighbors are those with an edge TO current_id
        for neighbor_id in reverse_graph.get(current_id, []):
            if not visited[neighbor_id]:
                recursive_dfs(neighbor_id)
            elif cycle_detection[neighbor_id]:
                raise VisibilityCycleError("Cycle detected between cells")
        
        # Output current cell
        output_list.append(current_id)
        cycle_detection[current_id] = False

    while sink_list:
        cell_id = sink_list.pop(0)
        recursive_dfs(cell_id)

    if len(output_list) != len(cells):
        raise VisibilityCycleError("Remaining cells indicate a visibility cycle")

    return [cells_by_id[cid] for cid in output_list]
```

**Parameters:**
*   **Convexity:** The mesh and all individual cells must be convex for the total ordering to be guaranteed correct [S1][S4, unofficial].
*   **Acyclicity:** The directed graph must be acyclic. Cycles imply a visibility loop where cells partially occlude each other [S1][S8, unofficial].

**Edge Cases and Pitfalls:**
*   **Visibility Cycles:** If a cycle exists, the algorithm fails. This occurs in non-convex meshes or meshes with holes where rays exit and re-enter the volume [S1][S8, unofficial].
*   **Non-Convex Meshes:** MPVO does not account for occlusions across empty space (gaps) between boundary cells. It is not correct for non-convex grids without augmentation [S2][S3].
*   **Geometric Degeneracies:** Geometric degeneracies can make the implementation of MPVO complex and require careful handling [S4, unofficial][S5, unofficial].

## Subtopics

### [Exact Visibility Ordering for Cell Projection Volume Rendering (SXMPVO)](944-exact-visibility-ordering-for-cell-projection-volume-renderi.md)
SXMPVO extends MPVO to non-convex meshes by replacing expensive object-precision ray shooting with efficient scan conversion of exterior faces into an A-Buffer to determine occlusion relations (Pseudoneighbor or PN relations) between cells. It guarantees image-precision visibility ordering, matching the rendering resolution, and avoids BSP tree construction.

### [A-buffer visibility sort for non-convex grids](1057-a-buffer-visibility-sort-for-non-convex-grids.md)
This method extends MPVO to handle non-convex grids by resolving visibility gaps between boundary cells using an image-space A-Buffer. It solves the problem where viewing rays exit the grid through an external face, traverse empty space, and re-enter the grid, creating occlusion relationships not captured by shared-face topology alone.

### [Power Distance Sort](1060-power-distance-sort.md)
Power Distance Sort orders primitives back-to-front by comparing the power of the viewpoint with respect to the circumcircles/circumspheres of the primitives. It leverages Delaunay properties to guarantee correct ordering for Delaunay meshes but is not guaranteed for non-Delaunay meshes, unlike MPVO which relies on topology.

### [Per-Pixel Sorting (General Variant)](1061-per-pixel-sorting-general-variant.md)
This image-space method sorts all cell faces projecting onto a specific pixel at render time. It solves visibility cycles by sorting locally per pixel, whereas MPVO requires a global topological sort and fails on cycles.

### [Newell-based Visibility Sorting](1123-newell-based-visibility-sorting.md)
Newell-based Visibility Sorting extends the Newell, Newell, and Sancha polygon sorting method to polyhedra. It sorts cells based on geometric depth and area properties rather than strict topological adjacency, providing an alternative when topological relations are insufficient.

### [XMPVO](1363-xmpvo.md)
XMPVO improves MPVO's runtime for non-convex meshes by using ray shooting queries to discover exterior face relations. It performs these checks in object-space precision, unlike SXMPVO which uses image-space.

### [MPVONC](1377-mpvonc.md)
MPVONC is a heuristic sorting algorithm for non-convex polyhedral cells. It extends MPVO by handling exterior cells lacking transitive "behind" relationships via shared faces. It prioritizes speed over correctness, making it prone to visual artifacts in specific occlusion scenarios.

### [Convex Grid Topological Visibility Sorting](2370-convex-grid-topological-visibility-sorting.md)
This is an $O(n)$ algorithm for convex grids of convex cells. It is essentially the core MPVO algorithm, relying exclusively on local face-sharing topology rather than global geometric tests or distance metrics.

## Operating characteristics
*   **Time Complexity:** $O(n)$, where $n$ is the number of cells. Each cell is processed a constant number of times (twice in initialization, once in the loop), and each edge is processed once [S2][S3].
*   **Space Complexity:** $O(n)$ for storing the adjacency graph, in-counts, and recursion stack [S1][S9, unofficial].
*   **Measured Performance:** Described as "very fast" with low computational overhead for well-behaved (acyclic and convex) meshes [S6, unofficial][S8, unofficial].
*   **Strengths:** Linear time complexity; exact correctness for convex, acyclic meshes; detects visibility cycles; reusable adjacency graph for multiple viewpoints [S1][S4, unofficial].
*   **Limitations:** Fails for non-convex meshes (requires augmentation); fails for meshes with visibility cycles (requires subdivision or alternative sort); geometric degeneracies can complicate implementation [S1][S4, unofficial][S8, unofficial].
*   **When to Use:** Convex, unstructured grids with convex cells where the mesh topology is static and the viewpoint changes [S4, unofficial].
*   **When Not to Use:** Non-convex meshes without augmentation; meshes with holes/cavities causing visibility cycles; real-time rendering of large non-convex datasets where approximate sorting (e.g., MPVONC) is preferred [S6, unofficial][S7, book].

## Background
MPVO was introduced by Peter L. Williams in 1992 [S6, unofficial]. It was developed to provide a fast visibility ordering for direct volume rendering of unstructured grids, particularly finite element meshes [S6, unofficial][S7, book]. A similar algorithm was published by Max et al. [S1][S8, unofficial]. The algorithm is a foundational component in cell projection volume rendering, enabling correct back-to-front compositing for convex volumes [S1][S4, unofficial].
