# MPVONC

Also called: MPVO, MPVO Non-Convex, MPVO with Non-Convexities, MPVONC heuristic

## Overview
MPVONC is a heuristic sorting algorithm used in cell projection volume rendering to order non-convex polyhedral cells back-to-front [S1][S4, unofficial]. It extends the exact MPVO algorithm by handling exterior cells that lack a transitive "behind" relationship via shared faces, which MPVO cannot resolve alone [S1][S4, unofficial]. Unlike exact methods such as SXMPVO or A-buffer sorts, MPVONC prioritizes speed over correctness, making it "accurate enough" for many applications but prone to visual artifacts in specific occlusion scenarios [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A mesh of polyhedral cells defining a volume; a viewpoint position $\mathbf{v}$; the geometric definition of each cell (vertices, faces).
*   **Output:** A total ordering of cells from back to front for rendering.

**Data Structures:**
*   **Cell List:** A list of all cells in the mesh.
*   **Adjacency Graph:** Implicitly or explicitly defined by shared faces. For MPVO, this is a directed graph where an edge $C_j \to C_i$ exists if $C_j$ is "behind" $C_i$ across a shared face [Parent].
*   **Visited Set:** A boolean array or hash set tracking cells included in the DFS traversal to ensure each cell is processed exactly once [G].

**Steps:**
1.  **Identify Exterior Front-Facing Cells:** Iterate over all cells. A cell $C$ is an "exterior front-facing cell" if it has at least one face on the boundary of the mesh and that exterior face is front-facing with respect to the viewpoint $\mathbf{v}$ [S1][S4, unofficial]. Let $E$ be the set of these cells.
2.  **Sort Exterior Cells:** Sort the cells in $E$ by decreasing distance of their centroids to the viewpoint [S1][S4, unofficial]. For two cells $C_a, C_b \in E$, $C_a$ precedes $C_b$ if $\|\mathbf{c}_a - \mathbf{v}\| > \|\mathbf{c}_b - \mathbf{v}\|$.
3.  **Depth-First Search (DFS) Traversal:** Initialize an empty list `ordered_cells` and an empty `visited` set [S1][S4, unofficial]. For each cell $C_{start}$ in the sorted list $E$, if $C_{start}$ is not in `visited`, perform a DFS starting from $C_{start}$ to find all reachable cells via the MPVO "behind" relationships (edges in the directed graph), appending them to `ordered_cells` [S1][S4, unofficial]. The sources state the DFS constructs the total visibility ordering from `<vp` relations [S1][S4, unofficial].

**Pseudocode:**
```python
def mpvonc(cells, viewpoint):
    # Step 1: Identify exterior front-facing cells
    exterior_front_cells = []
    for cell in cells:
        for face in cell.faces:
            if face.is_boundary and dot(viewpoint - cell.centroid, face.normal) > 0:
                exterior_front_cells.append(cell)
                break
                
    # Step 2: Sort by decreasing centroid distance
    exterior_front_cells.sort(key=lambda c: norm(c.centroid - viewpoint), reverse=True)
    
    # Step 3: DFS traversal
    ordered_cells = []
    visited = set()
    
    for start_cell in exterior_front_cells:
        if start_cell.id in visited:
            continue
        dfs_collect(start_cell, visited, ordered_cells)
        
    return ordered_cells

def dfs_collect(cell, visited, ordered_cells):
    visited.add(cell.id)
    # Traverse MPVO edges pointing towards the cell (cells behind it)
    # Precomputed MPVO edges pointing towards the cell [G]
    for neighbor in cell.mpvo_behind_neighbors:
        if neighbor.id not in visited:
            dfs_collect(neighbor, visited, ordered_cells)
    ordered_cells.append(cell)
```

**Parameters:** None. The algorithm is deterministic given the geometry and viewpoint.

**Edge Cases and Pitfalls:**
*   **Ray-Gap Occlusion Failure:** The method may fail when one cell occludes another across a region where ray-gaps are possible, specifically if the occluding cell's centroid is farther from the viewpoint than the occluded cell's centroid [S1][S4, unofficial].
*   **Non-Exactness:** The sorting is not exact, leading to certain visual artifacts, though it is considered fast and "accurate enough" for most applications [S2, unofficial].

## Subtopics

### Silva et al. Sweep Algorithm
A method that removes the assumption that the mesh is convex by means of a sweep algorithm used in conjunction with the MPVO method [S3, unofficial]. It is substantially faster than previous exact methods for general meshes [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Performance:** Considered "very fast" and "accurate enough" for most applications [S2, unofficial].
*   **Strengths:** Simple to implement, fast, handles non-convex meshes approximately.
*   **Limitations:** Not exact; prone to visual artifacts in cases of complex occlusion or ray-gaps where centroid distance does not correlate with visibility order [S1][S4, unofficial].
*   **When to use:** When rendering speed is critical and minor visual artifacts are acceptable, or for convex/weakly non-convex meshes.
*   **When not to use:** When exact visibility is required, or in scenes with complex interpenetrating non-convex geometry where ray-gaps are likely.

## Background
MPVONC was proposed by Peter L. Williams [S2, unofficial][S1][S4, unofficial]. It was developed to extend the MPVO algorithm, which works for convex meshes, to non-convex meshes [S1][S4, unofficial]. It is commonly used in combination with the Projected Tetrahedra (PT) technique for volume rendering of unstructured grids [S2, unofficial].
