# BSP-XMPVO

Also called: Binary Space Partition MPVO

## Overview
BSP-XMPVO is a technique for fast polyhedral cell sorting for the interactive rendering of unstructured grids [S2, S3, S4, S5, unofficial]. It solves the problem of computing a correct global visibility ordering for cell projection volume rendering by augmenting the approximate ordering produced by Maximal Polyhedra Visibility Ordering (MPVO) with a view-independent Binary Space Partition (BSP) tree of the mesh's exterior faces [S2, S3, S4, S5, unofficial]. Unlike MPVO, which only computes an approximate ordering in general datasets resulting in visual artifacts, BSP-XMPVO provides exact sorting [S2, S4, unofficial]. It sets itself apart from its parent method, SXMPVO, by using a precomputed view-independent BSP structure to reduce the number of ray-shooting queries needed, whereas SXMPVO relies on image-precision ray shooting via scan conversion for every query [S4, S5, unofficial].

## How it works
**Inputs and outputs:**
*   **Input:** An unstructured mesh composed of polyhedral cells. The mesh must be acyclic to guarantee a valid topological sort [Parent].
*   **Output:** A global visibility ordering of the cells suitable for back-to-front compositing in volume rendering [S2, S3, unofficial].

**Data structures:**
1.  **BSP Tree:** A binary space partition tree constructed from the exterior faces of the mesh.
    *   **Node Layout:** Each node contains a splitting plane defined by the exterior face it represents. It has two children pointers (left and right) and potentially a list of cells or faces contained in the node's region.
    *   **Construction:** Built once during preprocessing. The splitting planes are determined by the geometry of the exterior faces [S1][S4, S5, unofficial].
2.  **MPVO Ordering:** An initial approximate ordering of cells generated by the MPVO algorithm [S2, S4, unofficial].

**Algorithm Steps:**
1.  **Preprocessing (View-Independent):**
    *   Identify all exterior faces of the unstructured mesh.
    *   Build a BSP tree using these exterior faces as splitting planes [S1][S4, S5, unofficial].
    *   *Note:* This step is performed once and is view-independent [S4, S5, unofficial].

2.  **Initial Ordering:**
    *   Compute an initial cell ordering using the MPVO algorithm [S2, S4, unofficial]. MPVO assumes the mesh is "well-behaved" (acyclic and convex) for exactness, but provides a fast baseline for general meshes [S2, unofficial].

3.  **Augmentation via BSP Tree:**
    *   For each cell or group of cells, use the BSP tree to resolve visibility conflicts that MPVO could not handle due to non-convex boundaries or complex topology [S2, S4, unofficial].
    *   The BSP tree allows for efficient spatial queries to determine which exterior faces occlude others [S4, unofficial].
    *   The algorithm effectively shoots query rays through pixel centers, using polygon scan conversion of the exterior faces to add exterior face relations only at the precision necessary for the current image [S1][S5, unofficial].
    *   The BSP structure augments the MPVO ordering by providing exact visibility relationships between cells that are separated by exterior faces [S2, S4, unofficial].

**Parameters:**
*   $n$: Number of cells in the mesh.
*   $b$: Number of exterior faces in the mesh.
*   $p$: Size of a small subset of exterior cells [S1][S4, S5, unofficial].

def build_bsp_tree(exterior_faces):
    """
    Builds a Binary Space Partition tree from a list of exterior faces.
    Each face defines a splitting plane.
    """
    if not exterior_faces:
        return None
    
    # Select a pivot face to split the space
    pivot_face = exterior_faces[0]
    splitting_plane = pivot_face.plane
    
    # Partition remaining faces into those in front and behind the plane
    faces_in_front = []
    faces_behind = []
    
    for face in exterior_faces[1:]:
        if face.is_in_front_of(splitting_plane):
            faces_in_front.append(face)
        elif face.is_behind(splitting_plane):
            faces_behind.append(face)
        else:

            faces_in_front.append(face)

def query_bsp_tree(node, cell):
    """
    Queries the BSP tree to find exterior faces that occlude a given cell.
    """
    if node is None:
        return []
    
    # Determine which side of the splitting plane the cell is on
    if cell.is_in_front_of(node.plane):
        front_occlusions = query_bsp_tree(node.left, cell)
        # Check if the node's face itself occludes the cell
        if node.plane.face.occludes(cell):
            return front_occlusions + [node.plane.face]
        return front_occlusions
    else:
        back_occlusions = query_bsp_tree(node.right, cell)
        if node.plane.face.occludes(cell):
            return back_occlusions + [node.plane.face]
        return back_occlusions

**Edge cases and pitfalls:**
*   **BSP Tree Depth:** The BSP tree can become deep and unbalanced, leading to increased processing overhead [S1][S4, S5, unofficial].
*   **Preprocessing Cost:** Building the BSP structure is a very slow step [S1][S4, S5, unofficial].
*   **Runtime Overhead:** If the tree is unbalanced, searches can take $O(b)$ time, leading to an $O(b^2)$ flavor in the worst case [S1][S4, S5, unofficial].

## Subtopics

### SXMPVO (Exact Visibility Ordering for Cell Projection Volume Rendering)
The parent method that uses image-precision ray shooting via scan conversion. It does not use a precomputed view-independent BSP tree but instead performs ray shooting queries dynamically. Choose SXMPVO when view-dependent precision is preferred over the preprocessing cost of BSP-XMPVO. [Parent](944-exact-visibility-ordering-for-cell-projection-volume-renderi.md)

### MPVO (Maximal Polyhedra Visibility Ordering)
The base sorting algorithm that BSP-XMPVO augments. MPVO is fast but only provides an approximate ordering for general (non-convex) meshes, leading to visual artifacts. Choose MPVO for well-behaved (convex and acyclic) meshes where speed is critical and exactness is not required. [S2, S4, unofficial]

## Operating characteristics
**Time and memory complexity:**
*   The time complexity is $O(n + bp)$, where $n$ is the number of cells, $b$ is the number of exterior faces, and $p$ is the size of a small subset of exterior cells [S1][S4, S5, unofficial].
*   Memory complexity is dominated by the storage of the BSP tree, which is proportional to the number of exterior faces $b$ [S4, S5, unofficial].

**Measured performance:**
*   BSP-XMPVO results are orders of magnitude better than previous exact methods of sorting cells [S2, S3, S4, unofficial].
*   It leads to an order of magnitude improvement in sorting times over XMPVO [S1][S4, S5, unofficial].

**Scaling:**
*   The performance depends on the number of exterior faces $b$. If the BSP tree becomes deep and unbalanced, the cost per search can degrade to $O(b)$, leading to an overall $O(b^2)$ flavor in practical cases [S1][S4, S5, unofficial].

**Strengths and limitations:**
*   **Strengths:** Provides exact visibility ordering for general unstructured meshes, significantly faster than previous exact methods, and reduces the number of ray-shooting queries compared to image-space methods like SXMPVO by using a precomputed structure [S2, S4, S5, unofficial].
*   **Limitations:** The preprocessing step (building the BSP tree) is very slow and can add considerable processing overhead. The algorithm can become sluggish if the BSP tree becomes deep and unbalanced [S1][S4, S5, unofficial].

**When to use it and when not:**
*   Use BSP-XMPVO when rendering unstructured grids with non-convex boundaries where exact visibility is required and the preprocessing cost can be amortized over multiple frames or views.
*   Do not use it if the mesh has a very large number of exterior faces that lead to an unbalanced BSP tree, or if interactive performance is critical and the preprocessing time is prohibitive. In such cases, approximate methods like MPVO or image-space methods like SXMPVO might be preferred [S1][S2, S4, S5, unofficial].

## Background
BSP-XMPVO was proposed by João Luiz Dihl Comba, James T. Klosowski, Nelson Max, and Peter L. Williams in 1999 [S2, S3, S5, unofficial]. It was introduced as an improvement on the XMPVO method by Silva et al., which itself was an extension of MPVO by Williams [S2, S3, S4, S5, unofficial]. The method was published in the journal *Computers & Graphics* (or *Computer Graphics Forum*, as indicated by the source title) in September 1999 [S2, S3, unofficial]. It addresses the limitations of MPVO, which only provides approximate ordering for general datasets, and XMPVO, which, while exact, can be slower due to dynamic ray shooting [S2, S4, S5, unofficial].
