# BSP-XMPVO

Also called: Binary Space Partition - Extended Monotone Polygon Visibility Ordering, Binary Space Partition MPVO, Fast Polyhedral Cell Sorting

## Overview
BSP-XMPVO is a visibility sorting algorithm for unstructured and curvilinear grids that combines a Binary Space Partition (BSP) tree of exterior faces with the adjacency-based ordering of MPVO to handle non-convex meshes [S1, S5][S7, unofficial]. It augments the partial order from MPVO with dependencies derived from the BSP tree to resolve occlusions between non-adjacent cells, achieving exact sorting with linear time complexity relative to the number of cells, $O(n + bp)$, where $n$ is the total cells, $b$ is the boundary cells, and $p$ is the small number of partially projected cells [S1, S5][S7, unofficial]. Unlike MPVO, which assumes convexity and produces artifacts on non-convex meshes, BSP-XMPVO provides exact ordering for general acyclic meshes [S3, unofficial][S5].

## How it works
**Inputs and Outputs:**
*   **Input:** An unstructured mesh $S$ with convex cells (e.g., tetrahedra, hexahedra). The mesh must be acyclic. The data structure must support cell-to-cell adjacency (e.g., a facet-edge structure) [S5].
*   **Output:** A total visibility ordering of the cells in $S$ for a given viewpoint $v$ [S5].

**Data Structures:**
1.  **Adjacency Graph $G$:** Undirected graph where nodes are cells. Edges connect adjacent cells [S5].
2.  **BSP Tree $T$:** Built from the set of boundary facets $B$. Internal nodes store a plane equation (from a boundary facet). Leaves contain fragments of boundary facets [S5].
3.  **Dependency Counters:** For each cell $C_i$, three integer counters track unresolved dependencies:
    *   `num_inbound(C_i)`: Count of `<ADJ` dependencies (neighbors behind $C_i$) [S5].
    *   `bsp_dep_count(C_i)`: Count of `<BSP` dependencies (boundary fragments of $C_i$ not yet projected) [S5].
    *   `ppc_dep_count(C_i)`: Count of `<PPC` dependencies (partially projected cells behind $C_i$) [S5].
4.  **PPC-List:** A list of cells that are "partially projected" (some fragments projected, some not) [S5].

**Preprocessing (View-Independent):**
1.  **Adjacency Graph Construction:** Build $G$ from mesh topology. If raw data lacks topology, compute it using hashing in $O(n \log n)$ worst-case time [S5].
2.  **BSP Tree Construction:**
    *   Let $B$ be the set of boundary facets (facets incident to only one cell) [S5].
    *   Recursively partition $B$ using a plane passing through one of the facets in $B$ [S5].
    *   **Heuristic:** At each node, select a small number of candidate cuts (e.g., 10) at random from the facets in the current region. Choose the cut that minimizes the number of split elements [S5].
    *   Split facets into fragments if they intersect the cutting plane. Store fragments in leaves [S5].
    *   The tree size $b'$ (number of fragments) is $\Theta(b^2)$ worst-case but near-linear $O(b)$ in practice [S5].

**Runtime Algorithm (Per Viewpoint $v$):**
The algorithm runs a BSP-tree traversal and an MPVO-like topological sort in lockstep. It maintains a queue of projectable cells (counters all zero) [S5].

```python
def BSP_XMPVO(viewpoint):
    # 1. Orient adjacency graph G for viewpoint
    for edge (C_prev, C_curr) in G.edges:
        if C_prev_behind_C_curr(C_prev, C_curr, viewpoint):
            orient_edge(C_prev, C_curr)
        else:
            orient_edge(C_curr, C_prev)
    # 2. Initialize counters
    for C in Cells:
        num_inbound[C] = in_degree(C)
        bsp_dep_count[C] = num_boundary_facets(C)
        ppc_dep_count[C] = 0
    ppc_list = []
    queue = PriorityQueue()
    for C in Cells:
        if num_inbound[C] == 0 and bsp_dep_count[C] == 0 and ppc_dep_count[C] == 0:
            queue.enqueue(C)

    # 3. BSP Traversal
    BSP_XMPVO_traversal(root_node, viewpoint)

    # 4. MPVO Traverse
    while not queue.empty():
        C = queue.dequeue()
        output(C)
        for i in range(num_faces(C)):
            if arrow(i, C) == INBOUND:
                neighbor = get_neighbor(C, i)
                num_inbound[neighbor] -= 1
                if num_inbound[neighbor] == 0 and bsp_dep_count[neighbor] == 0 and ppc_dep_count[neighbor] == 0:
                    queue.enqueue(neighbor)

def BSP_XMPVO_traversal(node, viewpoint):
    if node.is_leaf():
        BSP_XMPVO_update_dep(node)
        return
    # Traverse child not containing viewpoint first
    BSP_XMPVO_traversal(node.child_not_containing(viewpoint), viewpoint)
    BSP_XMPVO_update_dep(node)
    BSP_XMPVO_traversal(node.child_containing(viewpoint), viewpoint)

def BSP_XMPVO_update_dep(node):
    cut_cells = get_cells_on_plane(node.plane)
    # Check PPC dependencies
    for C_j in ppc_list:
        for C_i in cut_cells:
            if C_j_behind_C_i(C_j, C_i, viewpoint):
                ppc_dep_count[C_i] += 1
    # Update PPC list and decrement BSP deps
    for C_i in cut_cells:
        bsp_dep_count[C_i] -= 1
        if bsp_dep_count[C_i] == 1:
            ppc_list.append(C_i)
        elif bsp_dep_count[C_i] == 0:
            ppc_list.remove(C_i)
    # Enqueue projectable cells
    for C_i in cut_cells:
        if num_inbound[C_i] == 0 and bsp_dep_count[C_i] == 0 and ppc_dep_count[C_i] == 0:
            queue.enqueue(C_i)
```

**Parameters:**
*   **Candidate Cuts:** Number of random candidate planes considered during BSP construction. Default is 10 [S5].
*   **n:** Total number of cells [S5].
*   **b:** Number of boundary cells (or boundary facets) [S5].
*   **p:** Size of the PPC-list. Typically 0.1–0.3% of total cells [S2, S5].

**Edge Cases and Pitfalls:**
*   **BSP Tree Depth:** The BSP tree can become deep and unbalanced, leading to $O(b)$ cost per search and potentially $O(b^2)$ overall flavor if not balanced [S1][S7, unofficial].
*   **PPC List Growth:** If mesh elements "spike in" behind others, the PPC list can grow. In practice it remains small (avg 0.1%, max 0.3% of elements) because most mesh elements are well-shaped [S5].
*   **Topological Data:** If the input lacks adjacency pointers, preprocessing takes $O(n \log n)$ [S5].

## Operating characteristics
*   **Time Complexity:** $O(n + bp)$ per viewpoint, where $n$ is total cells, $b$ is boundary cells, and $p$ is the number of partially projected cells [S1, S5][S7, unofficial]. This is an improvement over XMPVO's $O(b^2 + n)$ [S5].
*   **Preprocessing Time:** Building the BSP tree is slow. For a 13,000 cell dataset, it took 3.0 seconds; for 190,000 cells, 6.4 seconds; for 240,000 cells, 5.8 seconds [S5].
*   **Memory Complexity:** Linear in the number of cells and boundary facets. The BSP tree size is $\Theta(b^2)$ worst-case but near-linear $O(b)$ in practice [S5].
*   **Performance:** On a 13,000 cell dataset, BSP-XMPVO took 0.37 seconds (vs 3.5s for XMPVO, 0.07s for MPVONC). On 190,000 cells, 2.5s (vs 25s for XMPVO). On 240,000 cells, 2.9s (vs 48s for XMPVO) [S5].
*   **Strengths:** Exact sorting for non-convex meshes; significantly faster than XMPVO; near-linear runtime for typical meshes [S7, unofficial].
*   **Limitations:** Slow preprocessing; BSP tree can be unbalanced; PPC dependencies add overhead if the mesh has many non-convex interlocking structures [S1, S5][S7, unofficial].
*   **When to Use:** Interactive rendering of unstructured grids where exact visibility is required for non-convex meshes and preprocessing cost is acceptable [S5].
*   **When Not to Use:** If the mesh is convex (use MPVO for speed); if preprocessing time is prohibitive; if the mesh has extreme non-convexities causing large PPC lists or deep BSP trees [S5].

## Background
BSP-XMPVO was proposed by Comba et al. in 1999 [S5]. It builds on MPVO by Williams (1992) and XMPVO by Silva et al. [S5]. It is used for interactive rendering of unstructured grids, aiming to close the gap between rendering regular and irregular grids [S5].
