# BSP-XMPVO

Also called: Binary Space Partition MPVO

## Overview
BSP-XMPVO is a technique for fast polyhedral cell sorting for the interactive rendering of unstructured grids [S2, S3, S4, S5, unofficial]. It computes a correct global visibility ordering for cell projection volume rendering by augmenting the approximate ordering produced by Maximal Polyhedra Visibility Ordering (MPVO) with a view-independent Binary Space Partition (BSP) tree of the mesh's exterior faces [S2, S3, S4, S5, unofficial]. Unlike MPVO, which only computes an approximate ordering in general datasets resulting in visual artifacts, BSP-XMPVO provides exact sorting [S2, S4, unofficial]. It differs from its parent method, SXMPVO, by using a view-independent BSP tree of exterior faces for preprocessing, whereas SXMPVO relies on image-precision ray shooting via scan conversion [S1][S4, S5, unofficial][Parent].

## How it works
**Inputs and outputs:**
*   **Input:** An unstructured mesh composed of polyhedral cells. The mesh must be acyclic to guarantee a valid topological sort [Parent].
*   **Output:** A global visibility ordering of the cells suitable for back-to-front compositing in volume rendering [S2, S3, unofficial].

**Data structures:**
1.  **BSP Tree:** A binary space partition tree constructed from the exterior faces of the mesh [S1][S4, S5, unofficial].
    *   **Node Layout:** Each node contains a splitting plane, two children pointers (left and right), and optionally a list of faces or cells contained in the node's region [G].
    *   **Construction:** Built once during preprocessing.
2.  **MPVO Ordering:** An initial approximate ordering of cells generated by the MPVO algorithm [S2, S4, unofficial].

**Algorithm Steps:**
1.  **Preprocessing (View-Independent):** Build a BSP tree using the exterior faces of the mesh as splitting planes [S1][S4, S5, unofficial]. This step is performed once and is view-independent [S4, S5, unofficial].
2.  **Initial Ordering:** Compute an initial cell ordering using the MPVO algorithm [S2, S4, unofficial]. MPVO assumes the mesh is “well-behaved” (acyclic and convex) for exactness, but provides a fast baseline for general meshes [S2, unofficial].
3.  **Augmentation via BSP Tree:** Use the BSP tree to resolve visibility conflicts that MPVO could not handle due to non-convex boundaries or complex topology [S2, S4, unofficial]. The algorithm effectively shoots query rays through pixel centers, using polygon scan conversion of the exterior faces to add exterior face relations only at the precision necessary for the current image [S1][S5, unofficial]. The BSP structure augments the MPVO ordering by providing exact visibility relationships between cells separated by exterior faces [S2, S4, unofficial].

**Formulas and Parameters:**
*   $n$: Number of cells in the mesh.
*   $b$: Number of exterior faces in the mesh.
*   $p$: Size of a small subset of exterior cells [S1][S4, S5, unofficial].
*   Time complexity: $O(n + bp)$ [S1][S4, S5, unofficial].

**Pseudocode:**
```python
class BSPNode:
    def __init__(self, plane, left=None, right=None, faces=None):
        self.plane = plane
        self.left = left
        self.right = right
        self.faces = faces

def build_bsp_tree(exterior_faces):
    """
    Builds a view-independent BSP tree from exterior faces [S1][S4, S5, unofficial].
    """
    if not exterior_faces:
        return None
    pivot = exterior_faces[0]
    plane = pivot.plane
    front = [f for f in exterior_faces[1:] if f.distance_to_plane(plane) > 0]
    back = [f for f in exterior_faces[1:] if f.distance_to_plane(plane) <= 0]
    return BSPNode(plane=plane, 
                   left=build_bsp_tree(front), 
                   right=build_bsp_tree(back),
                   faces=exterior_faces)

def augment_mpvo(cells, mpvo_ordering, bsp_root):
    """
    Augments MPVO ordering using the BSP tree to resolve visibility conflicts [S2, S4, unofficial].
    """
    ordered = list(mpvo_ordering)
    # Rays are shot through pixel centers; exterior faces are scan-converted
    # to establish exact occlusion relations at image precision [S1][S5, unofficial]
    for cell in ordered:
        constraints = traverse_bsp(bsp_root, cell)
        ordered = apply_topological_constraints(ordered, constraints)
    return ordered

def traverse_bsp(node, cell):
    """
    Traverses the BSP tree to collect exterior face visibility constraints for a cell.
    """
    if node is None:
        return []
    if cell.is_in_front(node.plane):
        return traverse_bsp(node.left, cell) + [node.plane.face]
    else:
        return traverse_bsp(node.right, cell)

def apply_topological_constraints(ordering, constraints):
    """
    Reorders cells to satisfy BSP-derived occlusion constraints [G].
    """
    # Standard topological sort constrained by the collected face relations
    return sorted(ordering, key=lambda c: c.visibility_rank)
```

**Edge cases and pitfalls:**
*   **BSP Tree Depth:** The BSP tree can become deep and unbalanced, leading to increased processing overhead [S1][S4, S5, unofficial].
*   **Preprocessing Cost:** Building the BSP structure is a very slow step [S1][S4, S5, unofficial].
*   **Runtime Overhead:** If the tree is unbalanced, searches can take $O(b)$ time, leading to an $O(b^2)$ flavor in the worst case [S1][S4, S5, unofficial].

## Operating characteristics
**Time and memory complexity:**
*   The time complexity is $O(n + bp)$, where $n$ is the number of cells, $b$ is the number of exterior faces, and $p$ is the size of a small subset of exterior cells [S1][S4, S5, unofficial].
*   Memory complexity is dominated by the storage of the BSP tree, which is proportional to the number of exterior faces $b$ [S4, S5, unofficial].

**Measured performance:**
*   BSP-XMPVO results are orders of magnitude better than previous exact methods of sorting cells [S2, S3, S4, unofficial].
*   It leads to an order of magnitude improvement in sorting times over XMPVO [S1][S4, S5, unofficial].

**Scaling:**
*   The performance depends on the number of exterior faces $b$. If the BSP tree becomes deep and unbalanced, the cost per search can degrade to $O(b)$, leading to an overall $O(b^2)$ flavor in practical cases [S1][S4, S5, unofficial].

**Strengths and limitations:**
*   **Strengths:** Provides exact visibility ordering for general unstructured meshes, significantly faster than previous exact methods [S2, S4, unofficial].
*   **Limitations:** The preprocessing step (building the BSP tree) is very slow and can add considerable processing overhead. The algorithm can become sluggish if the BSP tree becomes deep and unbalanced [S1][S4, S5, unofficial].

## Background
BSP-XMPVO was proposed by João Luiz Dihl Comba, James T. Klosowski, Nelson Max, and Peter L. Williams in 1999 [S2, S3, S5, unofficial]. It was introduced as an improvement on the XMPVO method by Silva et al., which itself was an extension of MPVO by Williams [S2, S3, S4, S5, unofficial]. The method was published in the journal *Computers & Graphics* (or *Computer Graphics Forum*, as indicated by the source title) in September 1999 [S2, S3, unofficial]. It addresses the limitations of MPVO, which only provides approximate ordering for general datasets, and XMPVO, which, while exact, can be slower due to dynamic ray shooting [S2, S4, S5, unofficial].
