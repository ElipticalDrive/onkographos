# Kraus and Ertl Method
## Overview
The Kraus and Ertl method handles visibility cycles in convex meshes during cell projection volume rendering [S1, unofficial][S2, unofficial]. It addresses cases where a global topological sort of cells is impossible due to cyclic visibility dependencies, while a local sort still exists for each pixel center [S1, unofficial][S2, unofficial].
## How it works
**Inputs and Outputs:**
- Input: MPVO sorting results identifying cyclic visibility dependencies [S1, unofficial][S2, unofficial].
- Output: Scan-converted cycle regions resolved via hardware compositing [S1, unofficial][S2, unofficial].
**Data Structures:**
Not given in the sources.
**Steps:**
1. Apply the basic MPVO sorting algorithm to detect and isolate pixels where cell ordering forms a cycle [S1, unofficial][S2, unofficial].
2. Use special hardware compositing methods to scan-convert each isolated cycle [S1, unofficial][S2, unofficial].
**Pseudocode:**
```python
def kraus_and_ertl_method(mpvo_sort_results):
    output_buffer = {}
    cycle_pixels = []
    for pixel, sort_data in mpvo_sort_results.items():
        if sort_data.has_cycle:
            cycle_pixels.append(pixel)
    for pixel in cycle_pixels:
        cycle_cells = sort_data.cycle_cells
        # [G] The source does not specify the exact hardware compositing
        # or scan-conversion algorithm used to resolve the cycle.
        output_buffer[pixel] = cycle_cells
    return output_buffer
```

Not given in the sources.
**Edge Cases and Pitfalls:**
- Rendering costs per cycle increase quadratically in the number of cells involved in the cycle [S1, unofficial][S2, unofficial].
- The method is designed for convex meshes [S1, unofficial][S2, unofficial].
## Operating characteristics
- **Time Complexity:** Rendering costs per cycle increase quadratically in the number of cells involved in the cycle [S1, unofficial][S2, unofficial].
- **Memory Complexity:** Not given in the sources.
- **Strengths:** Handles visibility cycles gracefully for convex non-overlapping cells [S1, unofficial][S2, unofficial]. For convex non-overlapping cells, there is always a visibility sort for each pixel center even if there is no global visibility sort of the cells [S1, unofficial][S2, unofficial].
- **Limitations:** Quadratic cost per cycle [S1, unofficial][S2, unofficial]. Limited to convex meshes in its original form [S1, unofficial][S2, unofficial].
- **When to use:** When rendering convex meshes with potential visibility cycles where standard MPVO fails [S1, unofficial].
- **When not to use:** Rendering non-convex meshes without extension to SXMPVO [S1, unofficial][S2, unofficial].
## Background
The method was introduced by Kraus and Ertl [S1, unofficial][S2, unofficial]. The method could be extended to nonconvex meshes using the SXMPVO algorithm [S1, unofficial][S2, unofficial].
