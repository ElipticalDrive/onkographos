# Kraus and Ertl Method
## Overview
The Kraus and Ertl method handles visibility cycles in convex meshes during cell projection volume rendering [S1, S2]. It addresses cases where a global topological sort of cells is impossible due to cyclic visibility dependencies, while a local sort still exists for each pixel center [S1, S2].
## How it works
**Inputs and Outputs:**
- Input: Projected images of convex, non-overlapping cells on the screen [S1, S2].
- Output: A correctly sorted and composited image that resolves visibility cycles [S1, S2].
**Data Structures:**
The method relies on the output of the basic MPVO sorting algorithm to identify cycle pixels [S2]. Not given in the sources [S1, S2].
**Steps:**
1. Apply the basic MPVO sorting algorithm to detect pixels where the cell ordering forms a cycle [S1, S2].
2. Isolate these pixels and their associated cells [S1, S2].
3. Use special hardware compositing methods to scan-convert each isolated cycle [S1, S2].
**Pseudocode:**
```python
def kraus_and_ertl_method(mpvo_sort_results):
    output_buffer = {}
    cycle_pixels = []
    # Step 1 & 2: Detect and isolate cycles using MPVO output
    for pixel, sort_data in mpvo_sort_results.items():
        if sort_data.has_cycle:
            cycle_pixels.append(pixel)
    # Step 3: Hardware compositing for each cycle
    for pixel in cycle_pixels:
        cycle_cells = sort_data.cycle_cells
        # [G] The source does not specify the exact hardware compositing
        # or scan-conversion algorithm used to resolve the cycle.
        output_buffer[pixel] = cycle_cells
    return output_buffer
```
**Parameters:**
Not given in the sources [S1, S2].
**Edge Cases and Pitfalls:**
- Rendering costs per cycle increase quadratically in the number of cells involved in the cycle [S1, S2].
- The method is designed for convex meshes [S1, S2].
## Operating characteristics
- **Time Complexity:** Rendering costs per cycle increase quadratically in the number of cells involved in the cycle [S1, S2].
- **Memory Complexity:** Not given in the sources [S1, S2].
- **Strengths:** Handles visibility cycles gracefully for convex non-overlapping cells [S1, S2]. For convex non-overlapping cells, there is always a visibility sort for each pixel center even if there is no global visibility sort of the cells [S1, S2].
- **Limitations:** Quadratic cost per cycle [S1, S2]. Limited to convex meshes in its original form [S1, S2].
- **When to use:** When rendering convex meshes with potential visibility cycles where standard MPVO fails [S1].
- **When not to use:** When rendering non-convex meshes without extension [S1].
## Background
The method was introduced by Kraus and Ertl [S1, S2]. The method could be extended to nonconvex meshes using the SXMPVO algorithm [S1, S2].
