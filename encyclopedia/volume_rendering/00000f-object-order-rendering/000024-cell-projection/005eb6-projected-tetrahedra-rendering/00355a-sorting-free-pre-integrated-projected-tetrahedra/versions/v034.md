# Sorting-free Pre-integrated Projected Tetrahedra

Also called: Pre-integrated Projected Tetrahedra, Sorting-free approach that controls the fragment rendering by using the opacity value, Sorting-free technique for volume rendering of an irregular volume dataset

## Overview
Sorting-free Pre-integrated Projected Tetrahedra (PBVR) is a sorting-free volume rendering technique for irregular volume datasets that employs projected tetrahedra with pre-integration [S1]. It solves the problem of low image quality in particle-based methods (visible footprints) and the scalability/visibility-sorting requirements of conventional methods by treating volume rendering as a stochastic process where sampling points occur along a viewing ray with probability equal to opacity [S1]. Unlike conventional Projected Tetrahedra, it does not require visibility sorting of tetrahedral cells from back to front [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** An irregular volume dataset represented as a set of tetrahedral cells, each associated with a scalar value (density) and color/emissivity. A viewing ray defined by origin and direction.
*   **Output:** A rendered image pixel value (brightness/color) for each pixel.

**Data Structures:**
*   **Tetrahedral Mesh:** A collection of tetrahedra. Each tetrahedron $T_i$ has vertices, a density value $\rho$, and a luminosity/color value $c$.
*   **Ray Segments:** The viewing ray is subdivided into segments where particle luminosity ($c_k$) and density ($\rho_k$) are constant [S1].
*   **Pre-integration Table:** A 3D texture or lookup table used for pre-integrated classification, constructed based on the transfer function [S1].

**Core Optical Model:**
The method uses the density emitter model, where the 3D scalar field is characterized as a varying density emitter with a single level of scattering [S1]. The opacity is derived from the number of particles in a unit volume, assuming the number of particles follows a Poisson distribution [S1].

**Formulas:**
1.  **Opacity:** The opacity $\tau$ for a ray segment of length $\Delta t$ with particle density $\rho$ is given by:
    $$ \tau = 1 - e^{-\rho \cdot \pi r^2 \cdot \Delta t} $$
    where $\pi r^2 \rho \Delta t$ expresses the expected number of particles in the ray segment [S1]. Note: The source text implies $\pi r^2$ is a cross-sectional area factor, though the exact definition of $r$ is not explicitly detailed beyond "particle luminosity" context. In the context of projected tetrahedra, this opacity controls the probability of rendering.

2.  **Brightness (Deterministic):** The brightness $B_k$ for a segment $k$ with constant luminosity $c_k$ and opacity $\tau_k$ is:
    $$ B_k = c_k \times (1 - e^{-\rho \cdot \text{area} \cdot \text{length}}) $$
    or more generally, the contribution is weighted by the opacity [S1]. The computational complexity of this equation is $O(n^2)$ if intermediate brightness values are considered [S1].

3.  **Stochastic Probability:** The possibility that the $k$-th luminosity is equal to the brightness value is defined by the probability that there are no particles from the first to the $(k-1)$-th ray segments and more than one particle in the $k$-th ray segment [S1].

**Algorithm Steps:**
The rendering calculation is repeated multiple times to achieve semi-transparency without alpha-blending [S1]. The process is as follows:

1.  **Subdivision:** Subdivide the viewing ray into segments where particle luminosity ($c_k$) and density ($\rho_k$) are constant [S1].
2.  **Opacity Calculation:** Calculate the opacity $\tau_k$ for each segment based on the Poisson distribution assumption [S1].
3.  **Stochastic Sampling (Per Repetition):**
    a. For each fragment generated by rasterizing the projected tetrahedron:
    b. Generate a random number $r \in [0, 1]$.
    c. Compare $r$ with the opacity $\tau$. If $r > \tau$, discard the fragment [S1].
    d. If $r \le \tau$, render the fragment with its luminosity/color value [S1].
4.  **Accumulation:** Repeat steps 1-3 for $N$ repetitions (where $N$ is the repetition level) [S1].
5.  **Averaging:** Calculate the final pixel value by averaging the brightness values from all $N$ repetitions [S1].

**Pseudocode:**

```python
def render_pixel_stochastic(ray, tetrahedra, transfer_function, num_repetitions):
    """
    Renders a single pixel using the sorting-free pre-integrated projected tetrahedra method.
    
    Args:
        ray: Ray object with origin and direction.
        tetrahedra: List of tetrahedra intersecting the ray.
        transfer_function: Function mapping density to opacity and color.
        num_repetitions: Number of stochastic repetitions N.
        
    Returns:
        float: Average brightness/color for the pixel.
    """
    total_brightness = 0.0
    
    # Pre-calculate intersections and segments
    # Note: In object-order rendering, this is handled by rasterization.
    # Here we simulate the ray-casting logic described for the stochastic model.
    segments = get_ray_segments(ray, tetrahedra)
    
    for rep in range(num_repetitions):
        current_brightness = 0.0
        accumulated_opacity = 0.0
        
        for segment in segments:
            density = segment.density
            length = segment.length
            luminosity = segment.luminosity # c_k
            
            # Calculate opacity based on Poisson distribution model
            # tau = 1 - exp(-rho * area * length)
            # Assuming area factor is incorporated or normalized in transfer function
            opacity = 1.0 - math.exp(-density * length) 
            
            # Stochastic sampling: render with probability equal to opacity
            random_val = random.uniform(0.0, 1.0)
            
            if random_val <= opacity:
                # Fragment is "hit"
                # Add luminosity contribution
                # In the density emitter model, brightness is c_k * (1 - exp(...))
                # But since we are sampling the presence of the particle,
                # we add the luminosity if the particle is present.
                current_brightness += luminosity * (1.0 - accumulated_opacity)
                accumulated_opacity += opacity * (1.0 - accumulated_opacity) # Simplified accumulation for stochastic hit
                
        total_brightness += current_brightness
        
    return total_brightness / num_repetitions

def render_object_order(tetrahedra, image_width, image_height, num_repetitions):
    """
    Object-order rendering loop.
    """
    image = zeros((image_height, image_width, 3))
    
    for rep in range(num_repetitions):
        # Create a temporary buffer for this repetition
        rep_image = zeros((image_height, image_width, 3))
        
        for tet in tetrahedra:
            # Project tetrahedron to screen
            screen_coords = project_to_screen(tet)
            
            # Rasterize
            for fragment in screen_coords:
                # Evaluate density at fragment center or via barycentric interpolation
                density = evaluate_density(tet, fragment.uv)
                
                # Get opacity and color from pre-integrated table or transfer function
                opacity, color = transfer_function(density)
                
                # Stochastic discard
                if random.uniform(0.0, 1.0) > opacity:
                    continue
                
                # Add to buffer (no alpha blending, just overwrite or accumulate depending on implementation)
                # The source says "controls the fragment rendering by using the opacity value"
                # and "repetition makes the resulting image semi-transparent without alpha-blending"
                rep_image[fragment.y, fragment.x] += color
                
        # Accumulate into final image
        image += rep_image
        
    return image / num_repetitions
```

**Parameters:**
*   **Repetition Level ($N$):** The number of times the rendering calculation is repeated. Higher $N$ reduces error but increases computation time [S1]. Typical values tested: 1, 25, 100, 144 [S1].
*   **Resolution:** Image resolution (e.g., 1024x1024) [S1].

**Edge Cases and Pitfalls:**
*   **Drastic Density Changes:** PBVR generates an insufficient number of particles when the density function changes drastically, leading to artifacts [S1].
*   **Performance Scaling:** Performance is greatly influenced by the number of pixels. It is memory-consuming since the increase in image resolution affects the number of particles [S1].
*   **Complexity:** The computational complexity of the basic brightness calculation is $O(n^2)$ if intermediate brightness values are considered [S1].

## Operating characteristics
*   **Time Complexity:** $O(n^2)$ for basic brightness calculation if intermediate values are considered [S1]. The overall performance is influenced by the number of repetitions $N$ and the number of pixels [S1].
*   **Memory Complexity:** Memory-consuming as image resolution increases the number of particles [S1]. Avoids the memory overhead of HAVS, which requires memory space for sorting cell faces about twice that for tetrahedral cells [S1].
*   **Measured Performance:** On NVIDIA GeForce 9600GT, ~10 million particles rendered at 25.7 milliseconds per repetition with 1024x1024 resolution [S1]. On Intel Core 2 Quad 2.83 GHz with Nvidia GeForce GTX 280, PBVR is faster than SPT for large numbers of cells but is greatly influenced by the number of pixels [S1].
*   **Strengths:** Sorting-free, scalable to large-scale irregular volumes distributed across multiple computing nodes, avoids visible footprints of particles when viewpoint is inside the volume, avoids artifacts from insufficient k-buffer size in HAVS [S1].
*   **Limitations:** Low image quality when density changes drastically (insufficient particles), performance heavily dependent on pixel count, requires multiple repetitions for high quality [S1].
*   **When to Use:** Large-scale irregular volumes where visibility sorting is impractical or impossible (e.g., distributed computing), and when particle footprints are undesirable.
*   **When Not to Use:** When density functions change precipitously (SPT handles this better), or when memory is extremely constrained and pixel count is high [S1].

## Background
Sorting-free Pre-integrated Projected Tetrahedra (PBVR) was developed to address the scalability issues of conventional volume rendering techniques that require visibility sorting, which is difficult for large-scale irregular volumes distributed across multiple computing nodes [S1]. It was proposed as an improvement over Particle-based Volume Rendering (PBVR) which suffers from low image quality and visible footprints, and over Projected Tetrahedra (PT) which requires sorting [S1]. The method treats volume rendering as a stochastic process, allowing it to be applied to object-order techniques like cell-by-cell rendering without explicit visibility sorting [S1].
