# Sorting-free Pre-integrated Projected Tetrahedra

Also called: Pre-integrated Projected Tetrahedra, Sorting-free approach that controls the fragment rendering by using the opacity value, Sorting-free technique for volume rendering of an irregular volume dataset

## Overview
Sorting-free Pre-integrated Projected Tetrahedra (PBVR) is a volume rendering technique for irregular datasets that eliminates the need for explicit back-to-front visibility sorting [S1]. It solves the scalability bottlenecks of conventional projected tetrahedra and the visible footprint artifacts of particle-based methods by treating rendering as a stochastic process where fragments are rendered with a probability equal to their opacity [S1]. Unlike [Projected Tetrahedra](877-projected-tetrahedra.md), which requires sorting, and [Particle-based Volume Rendering](877-projected-tetrahedra.md) (PBVR in the context of Anderson et al.), which suffers from low quality at close range, PBVR achieves semi-transparency through repeated stochastic sampling without alpha-blending [S1].

## How it works
**Inputs:** Irregular volume dataset decomposed into tetrahedral cells; vertex scalar values; transfer function mapping scalar to color/extinction; camera parameters.
**Outputs:** Rendered image (brightness/color per pixel).

**Data Structures:**
The method relies on the standard tetrahedral representation defined in [Tetrahedral representation and traversal](4396-tetrahedral-representation-and-traversal.md). Each tetrahedron is defined by 4 vertices with associated scalar values. The projection maps these 3D vertices to 2D screen coordinates. The subdivision of the image plane into polygons is performed as described in the parent article [S1, S2, unofficial][S4].

**Optical Model:**
The method uses a density emitter model where the scalar field is characterized as a varying density emitter with single-level scattering [S1]. The opacity is derived from the number of particles in a unit volume, assuming the particle count follows a Poisson distribution [S1].

**Parameters:**
*   $N$: Repetition level (number of stochastic passes). Typical values range from 1 to 144 for visual verification, with higher values reducing error [S1].
*   $\rho$: Particle density (number of particles in a unit volume), derived from the scalar field [S1].
*   $c_k$: Particle luminosity for the $k$-th segment [S1].
*   $\Delta t$: Ray-segment length [S1].

**Algorithm Steps:**
The rendering calculation is repeated $N$ times. In each repetition, the image is composited using a stochastic discard mechanism rather than alpha blending.

1.  **Subdivision:** Subdivide the viewing ray into segments where particle luminosity ($c_k$) and density ($\rho_k$) are constant [S1].
2.  **Opacity Calculation:** Calculate the opacity for each segment based on the Poisson distribution assumption. The opacity $\tau$ for a segment of length $\Delta t$ is:
    $$ \tau = 1 - e^{-\rho \pi r^2 \Delta t} $$
    where $\rho$ is the number of particles in a unit volume and $\pi r^2 \rho \Delta t$ expresses the expected number of particles in the ray segment [S1]. Note: In the context of projected tetrahedra, this opacity is evaluated per fragment/polygon corresponding to the tetrahedron's projection.
3.  **Stochastic Fragment Rendering:** For each fragment generated by rasterizing the projected tetrahedra:
    a. Generate a random number $r \in [0, 1]$.
    b. Compare $r$ with the fragment's opacity $\alpha$ (derived from $\tau$).
    c. If $r > \alpha$, discard the fragment.
    d. If $r \le \alpha$, render the fragment with its full luminosity/color [S1].
4.  **Accumulation:** Repeat steps 1-3 for $N$ repetitions.
5.  **Averaging:** Calculate the final pixel value by averaging the results from all $N$ repetitions [S1].

**Pseudocode:**
The following pseudocode implements the stochastic fragment rendering step for a single repetition. It assumes the fragment shader receives the opacity $\alpha$ for the current fragment.

```python
def stochastic_render_fragment(opacity: float, luminosity: float) -> float:
    """
    Renders a single fragment stochastically.
    
    Args:
        opacity: The calculated opacity alpha for the fragment (0.0 to 1.0).
        luminosity: The color/brightness value if the fragment is visible.
        
    Returns:
        The rendered value (luminosity if visible, 0.0 if discarded).
    """
    # Generate a uniform random number in [0, 1]
    r = random_uniform(0.0, 1.0)
    
    # Compare random number with opacity
    if r > opacity:
        # Discard fragment
        return 0.0
    else:
        # Render fragment with full luminosity
        return luminosity

def pbvr_render_volume(tetrahedra: List[Tetrahedron], camera: Camera, 
                       transfer_function: TransferFunction, 
                       repetition_level: int, image_width: int, 
                       image_height: int) -> Image:
    """
    Renders the volume using the Sorting-free Pre-integrated Projected Tetrahedra method.
    
    Args:
        tetrahedra: List of tetrahedral cells with vertex positions and scalar values.
        camera: Camera parameters for projection.
        transfer_function: Maps scalar values to color and extinction.
        repetition_level: Number of stochastic passes (N).
        image_width: Width of the output image.
        image_height: Height of the output image.
        
    Returns:
        The final averaged image.
    """
    # Initialize accumulator for averaging
    accumulator = Image.zeros(image_width, image_height)
    
    # Repeat the rendering process N times
    for _ in range(repetition_level):
        # Create a temporary image for this repetition
        current_frame = Image.zeros(image_width, image_height)
        
        # Project and rasterize each tetrahedron
        # This step involves the subdivision logic from the parent article
        # [Tetrahedral representation and traversal](4396-tetrahedral-representation-and-traversal.md)
        for tet in tetrahedra:
            # 1. Project 3D vertices to 2D screen space
            projected_vertices = [camera.project(v) for v in tet.vertices]
            
            # 2. Subdivide the image plane into polygons based on projected edges
            # [S1, S2, unofficial][S4]
            polygons = subdivide_image_plane(projected_vertices, tet)
            
            # 3. For each polygon, evaluate opacity and color
            for poly in polygons:
                # Calculate average scalar value for the polygon/segment
                # Linear interpolation from vertex scalars [S1][S2, unofficial]
                scalar_val = interpolate_scalar(tet, poly.center)
                
                # Map scalar to color and extinction using transfer function
                color, extinction = transfer_function(scalar_val)
                
                # Calculate opacity from extinction
                # Using the density emitter model opacity formula [S1]
                # alpha = 1 - exp(-extinction * length)
                # Note: In the stochastic approach, 'extinction' effectively 
                # drives the probability of visibility.
                alpha = 1.0 - math.exp(-extinction)
                
                # Clamp alpha to [0, 1]
                alpha = max(0.0, min(1.0, alpha))
                
                # Perform stochastic rendering for the polygon's pixels
                # [S1]
                for pixel in poly.pixels:
                    # Get fragment luminosity/color
                    frag_luminosity = color
                    
                    # Stochastic test
                    rendered_value = stochastic_render_fragment(alpha, frag_luminosity)
                    
                    # Add to current frame (no alpha blending, just accumulation of visible values)
                    current_frame.add(pixel, rendered_value)
        
        # Accumulate the current frame into the total accumulator
        accumulator.add(current_frame)
    
    # Average the results over N repetitions
    final_image = accumulator.divide(repetition_level)
    
    return final_image
```

**Edge Cases and Pitfalls:**
*   **Precision:** The stochastic nature introduces noise. Low repetition levels ($N$) result in high variance and visible artifacts [S1].
*   **Boundary Conditions:** The opacity calculation assumes constant density within the segment. Sharp changes in density may require smaller segments or higher repetition levels to converge [S1].
*   **Memory:** PBVR is memory-consuming because the number of particles (and thus the computational load) increases with image resolution [S1].

## Operating characteristics
*   **Time Complexity:** The basic brightness calculation has a complexity of $O(n^2)$ if intermediate brightness values are considered [S1]. The total time is proportional to $N \times (\text{number of tetrahedra} + \text{number of pixels})$ [S1].
*   **Memory Complexity:** Memory usage is influenced by the number of pixels and the number of particles. It is more memory-efficient than Hardware-Assisted Visibility Sorting (HAVS), which requires memory space for sorting cell faces about twice that for tetrahedral cells [S1].
*   **Measured Performance:** On an NVIDIA GeForce 9600GT, PBVR rendered ~10 million particles at 25.7 milliseconds per repetition with 1024x1024 resolution [S1]. On an Intel Core 2 Quad 2.83 GHz with NVIDIA GeForce GTX 280, the technique was applied to large-scale CSM and CFD simulation results [S1].
*   **Scaling:** Performance is greatly influenced by the number of pixels. Increasing image resolution affects the number of particles and thus the computational cost [S1].
*   **Strengths:** No visibility sorting required; handles large-scale irregular volumes distributed across multiple nodes; avoids artifacts from insufficient k-buffer size; no visible footprints when viewpoint is inside the volume (unlike PBVR particle method) [S1].
*   **Limitations:** High repetition levels needed for high-quality images; performance degrades with high resolution; may generate insufficient particles when density function changes drastically compared to SPT [S1].
*   **When to use:** Large-scale irregular volumes where visibility sorting is impractical or impossible; when avoiding particle footprint artifacts is critical [S1].
*   **When not to use:** When real-time performance is critical and high repetition levels are prohibitive; when density functions change precipitously and SPT is preferred for better handling of such transfer functions [S1].

## Background
*   **Origin:** The method was introduced in the paper "Sorting-free pre-integrated projected tetrahedra" [S1].
*   **History:** It was developed to address the limitations of particle-based volume rendering (low image quality, visible footprints) and conventional projected tetrahedra (requirement for visibility sorting, scalability issues) [S1]. It builds on the density emitter model and Poisson distribution assumptions for particle counts [S1].
*   **Usage:** Applied to large-scale irregular volumes from CSM (Computational Structural Mechanics) and CFD (Computational Fluid Dynamics) simulations [S1].
