# Sorting-free Pre-integrated Projected Tetrahedra

Also called: Pre-integrated Projected Tetrahedra, Sorting-free approach that controls the fragment rendering by using the opacity value, Sorting-free technique for volume rendering of an irregular volume dataset

## Overview
Sorting-free Pre-integrated Projected Tetrahedra (PBVR) is a sorting-free volume rendering technique for irregular volume datasets that employs projected tetrahedra with pre-integration [S1]. It solves the problem of low image quality in particle-based methods (visible footprints) and the scalability/visibility-sorting requirements of conventional methods by treating volume rendering as a stochastic process where sampling points occur along a viewing ray with probability equal to opacity [S1]. Unlike conventional Projected Tetrahedra (PT), it does not require visibility sorting of tetrahedral cells from back to front [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** An irregular volume dataset decomposed into tetrahedral cells, each defined by four vertices $\{V_0, V_1, V_2, V_3\}$ and associated scalar values (density $\rho$) [S1][S2, unofficial]. A transfer function mapping density to particle luminosity $c$ and opacity parameters [S1].
*   **Output:** A rendered 2D image where pixel brightness is the ensemble average of multiple stochastic rendering passes [S1].

**Data Structures:**
*   **Tetrahedron:** Defined by four vertices and a scalar density value $\rho$ [S1][S2, unofficial].
*   **Ray Segment:** A portion of the viewing ray where particle luminosity $c_k$ and density $\rho_k$ are treated as constant [S1].

**Algorithm Steps:**
The method applies the sorting-free approach to object-order volume rendering (e.g., cell-by-cell) [S1]. The rendering calculation is repeated $N$ times (repetition level) to achieve semi-transparency without alpha-blending [S1].

1.  **Ray Subdivision:** For a given viewing ray, subdivide the ray into segments where particle luminosity $c_k$ and density $\rho_k$ are constant [S1].
2.  **Opacity Calculation:** Calculate the opacity $\tau_k$ for each segment based on the density emitter model, which assumes the number of particles follows a Poisson distribution [S1]. The opacity is derived from the number of particles in a unit volume [S1].
    $$ \tau_k = 1 - e^{-\rho_k \cdot \pi r^2 \cdot \Delta t_k} $$
    Where:
    *   $\rho_k$ is the number of particles in a unit volume (density) [S1].
    *   $\Delta t_k$ is the ray-segment length [S1].
    *   $\pi r^2$ represents the cross-sectional area of the ray segment (implied by the term $\pi r^2 \rho \Delta t$ expressing the number of particles) [S1].
    *   Note: In the context of projected tetrahedra, the "ray segment" corresponds to the intersection of the viewing ray with the tetrahedron, and the area term relates to the geometric projection or effective sampling area [S1].
3.  **Stochastic Fragment Rendering:** For each repetition $n$ from 1 to $N$:
    a.  Rasterize the projected tetrahedra [S1].
    b.  For each fragment generated, evaluate the opacity $\tau$ at the fragment's position [S1].
    c.  Generate a random number $r \in [0, 1]$ [S1].
    d.  If $r > \tau$, discard the fragment [S1].
    e.  If $r \le \tau$, render the fragment with its luminosity/color value [S1].
4.  **Ensemble Averaging:** Accumulate the brightness values from all $N$ repetitions and compute the average to obtain the final pixel brightness [S1].

**Formulas:**
*   **Brightness (Deterministic Reference):** The brightness $B_k$ for a ray segment in a deterministic density emitter model is:
    $$ B_k = c_k \times (1 - e^{-\rho \cdot \text{area} \cdot \Delta t}) $$
    Where $c_k$ is particle luminosity and $\rho$ is particle density [S1].
*   **Probability of Event:** The possibility that the $k$-th luminosity is equal to the brightness value (event where there is no particle from the first to the $(k-1)$-th ray-segments and more than one particle in the $k$-th ray segment) is defined by Equation 5 in the source [S1].
*   **Repetition Level:** The number of members in the ensemble average is denoted as the repetition level $N$ [S1].

**Parameters:**
*   **Repetition Level ($N$):** The number of times the rendering calculation is repeated. Higher $N$ reduces error but increases computation time [S1]. Typical values tested include 1, 25, 100, and 144 [S1].
*   **Resolution:** Performance is heavily influenced by the number of pixels. Experiments used 1024x1024 resolution [S1].

**Edge Cases and Pitfalls:**
*   **Drastic Density Changes:** PBVR may generate an insufficient number of particles when the density function changes drastically, leading to artifacts compared to Sorting-free Projected Tetrahedra (SPT) [S1].
*   **Memory Consumption:** PBVR is memory-consuming because the increase in image resolution affects the number of particles required for accurate stochastic sampling [S1].
*   **Viewpoint Inside Volume:** Unlike particle-based methods, PBVR does not suffer from visible footprints when the viewpoint is inside the volume [S1].

**Pseudocode:**

def render_pbvr(tetrahedra, transfer_function, resolution, repetition_level):
    """
    Renders an irregular volume using Sorting-free Pre-integrated Projected Tetrahedra.
    
    Args:
        tetrahedra: List of tetrahedra, each with vertices and density value.
        transfer_function: Function mapping density to luminosity and opacity parameters.
        resolution: Tuple (width, height) of the output image.
        repetition_level: Integer N, the number of stochastic passes.
        
    Returns:
        Image buffer with accumulated brightness.
    """
    width, height = resolution
    image_buffer = zeros((width, height))
    
    for n in range(repetition_level):
        # Initialize a temporary buffer for this pass
        pass_buffer = zeros((width, height))
        
        # Object-order rendering: process each tetrahedron
        for tet in tetrahedra:
            # Project tetrahedron to screen space and get fragments
            fragments = project_and_rasterize(tet, resolution)
            
            for frag in fragments:
                # Evaluate density at fragment's 3D position
                density = evaluate_density_at(frag.position, tet)
                
                # Map density to luminosity and opacity
                luminosity, opacity = transfer_function(density)
                
                # Stochastic sampling: discard with probability (1 - opacity)
                random_val = random_uniform(0.0, 1.0)
                if random_val <= opacity:
                    # Add luminosity to the fragment's contribution
                    pass_buffer[frag.x, frag.y] += luminosity
                # Else: fragment is discarded (no contribution)
        
        # Accumulate the pass result
        image_buffer += pass_buffer
    
    # Ensemble average
    if repetition_level > 0:
        image_buffer /= repetition_level
        
    return image_buffer

## Subtopics

### Projected Tetrahedra
The base method that projects tetrahedra to the screen and requires visibility sorting. PBVR removes this sorting requirement. See [Projected Tetrahedra](877-projected-tetrahedra.md).

### Parallelized Accurate Sorting for Projected Tetrahedra
A sibling method that uses parallel sorting to handle visibility. PBVR avoids sorting entirely, trading off potential performance for scalability and simplicity. See [Parallelized Accurate Sorting for Projected Tetrahedra](1128-parallelized-accurate-sorting-for-projected-tetrahedra.md).

### Particle-based Volume Rendering (PBVR)
A related stochastic method that uses explicit particles. PBVR avoids visible footprints and sorting by using projected tetrahedra with opacity-based stochastic fragment rendering [S1]. See [Particle-based Volume Rendering](link-to-particle-based-if-exists, otherwise omit).

## Operating characteristics
*   **Time Complexity:** The computational complexity of the basic brightness calculation (Equation 1) is $O(n^2)$ if intermediate brightness values are considered [S1]. The total time is proportional to the number of repetitions $N$ and the number of pixels [S1].
*   **Memory Complexity:** PBVR is memory-consuming because the increase in image resolution affects the number of particles (or stochastic samples) required [S1]. It requires less memory than Hardware-Assisted Visibility Sorting (HAVS), which needs memory space for sorting cell faces about twice that for tetrahedral cells [S1].
*   **Measured Performance:** On an NVIDIA GeForce 9600GT, PBVR rendered ~10 million particles at 25.7 milliseconds per repetition with 1024x1024 resolution [S1]. For 1024x1024 resolution, the estimated computing time is 1.4 seconds per repetition for large datasets [S1].
*   **Scaling:** Performance is greatly influenced by the number of pixels [S1]. It scales well for large-scale irregular volumes distributed across multiple computing nodes because it does not require global visibility sorting [S1].
*   **Strengths:**
    *   Sorting-free, avoiding artifacts from insufficient k-buffer size (as in HAVS) [S1].
    *   No visible footprints when the viewpoint is inside the volume (unlike particle-based methods) [S1].
    *   Scalable to large-scale irregular volumes across multiple nodes [S1].
*   **Limitations:**
    *   Generates insufficient particles when density functions change drastically, leading to lower quality than SPT in such cases [S1].
    *   High memory consumption for high resolutions [S1].
    *   Requires multiple repetitions for high-quality images, increasing computation time [S1].
*   **When to Use:** Suitable for large-scale irregular volumes where visibility sorting is impractical or impossible (e.g., distributed computing) and when the viewpoint may be inside the volume [S1].
*   **When Not to Use:** When the density function changes drastically and high fidelity is required (SPT is preferred) [S1]. When memory is constrained and high resolution is needed [S1].

## Background
*   **Origin:** The method was introduced in the paper "Sorting-free pre-integrated projected tetrahedra" [S1].
*   **History:** It was developed to address the limitations of particle-based volume rendering (low image quality, visible footprints) and conventional projected tetrahedra (visibility sorting bottlenecks, scalability issues) [S1]. It builds on the density emitter model and Poisson distribution assumptions for particle counts [S1].
*   **Usage:** Applied to large-scale irregular volumes from CSM and CFD simulation results [S1].
