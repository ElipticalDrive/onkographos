# Sorting-free Pre-integrated Projected Tetrahedra

Also called: Pre-integrated Projected Tetrahedra, Sorting-free approach that controls the fragment rendering by using the opacity value, Sorting-free technique for volume rendering of an irregular volume dataset

## Overview
Sorting-free Pre-integrated Projected Tetrahedra (PBVR) is a sorting-free volume rendering technique for irregular volume datasets that employs projected tetrahedra with pre-integration [S1]. It solves the problem of low image quality in particle-based methods (visible footprints) and the scalability/visibility-sorting requirements of conventional methods by treating volume rendering as a stochastic process where sampling points occur along a viewing ray with probability equal to opacity [S1]. Unlike conventional Projected Tetrahedra, it does not require visibility sorting of tetrahedral cells from back to front [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** An irregular volume dataset represented as a tetrahedral mesh; a transfer function mapping scalar values to color and opacity; a camera viewpoint and projection matrix.
*   **Output:** A rendered image (brightness/color values for each pixel).

**Data Structures:**
*   **Tetrahedral Mesh:** Defined by vertices and connectivity. Each tetrahedron $T$ has a scalar value (density $\rho$) associated with it, typically interpolated from vertex values or cell-centered.
*   **Pre-integration Table:** A 1D or 2D texture storing pre-computed optical properties (transmittance and accumulated color) based on the transfer function and path length [S1]. *Note: The specific layout of the pre-integration table is not detailed in the provided sources, but it is referenced as a component of the method.* [G: Standard pre-integration for volume rendering uses a texture indexed by path length and scalar value/density].

**Core Optical Model:**
The method uses the **density emitter model**, where the 3D scalar field is characterized as a varying density emitter with a single level of scattering [S1]. The opacity is derived from the number of particles in a unit volume, assuming the number of particles follows a Poisson distribution [S1].

**Numbered Steps:**
1.  **Subdivision:** Subdivide the viewing ray into segments where particle luminosity ($c_k$) and density ($\rho_k$) are constant [S1].
2.  **Opacity Calculation:** Calculate opacity for each segment based on the Poisson distribution assumption [S1].
3.  **Stochastic Rendering (Repetition):** Repeat the rendering calculation $N$ times (repetition level) to achieve semi-transparency without alpha-blending [S1]. In each repetition:
    a.  Rasterize the projected tetrahedra.
    b.  For each fragment generated by a tetrahedron, evaluate the opacity $\tau$ of the corresponding ray segment [S1].
    c.  Generate a random number $r \in [0, 1]$.
    d.  If $r > \tau$, discard the fragment [S1].
    e.  If $r \le \tau$, render the fragment with the luminosity/color associated with that segment [S1].
4.  **Accumulation:** Average the brightness values from all $N$ repetitions to obtain the final pixel value [S1].

**Formulas:**
*   **Brightness Calculation for a Ray Segment:**
    The brightness $B_k$ for the $k$-th segment is given by [S1]:
    $$ B_k = c_k \times (1 - e^{-\rho \times \text{area} \times \text{length}}) $$
    Where:
    *   $c_k$ is the particle luminosity in the $k$-th segment.
    *   $\rho$ is the particle density (number of particles in a unit volume).
    *   $\text{area}$ is the cross-sectional area of the ray segment (implied as $\pi r^2$ in the context of particle count, but for ray casting, it relates to the pixel footprint or ray width). *Note: The source text mentions $\pi r^2 \rho \Delta t$ expresses the number of particles in a ray segment.*
    *   $\text{length}$ (or $\Delta t$) is the ray-segment length.

*   **Opacity in the Density Emitter Model:**
    $$ \tau = 1 - e^{-\rho \times \text{area} \times \text{length}} $$
    This represents the probability that the segment contains some particles, derived from the Poisson distribution [S1].

*   **Probability of Luminosity Event:**
    The possibility that the $k$-th luminosity is equal to the brightness value is defined by [S1]:
    $$ P_k = e^{-\sum_{i=1}^{k-1} \lambda_i} (1 - e^{-\lambda_k}) $$
    Where $\lambda_i$ is the expected number of particles in the $i$-th segment. This represents an event where there is no particle from the first to the $(k-1)$-th ray-segments and more than one particle in the $k$-th ray segment [S1].

**Parameters:**
*   **Repetition Level ($N$):** The number of times the rendering calculation is repeated. Typical values mentioned: 1, 25, 100, 144 [S1]. Higher $N$ reduces error but increases computation time.

**Edge Cases and Pitfalls:**
*   **Drastic Density Changes:** PBVR may generate an insufficient number of particles when the density function changes drastically, leading to artifacts [S1]. Sorting-free Projected Tetrahedra (SPT) handles precipitous transfer functions better [S1].
*   **Memory Consumption:** Performance is greatly influenced by the number of pixels. PBVR is memory-consuming since the increase in image resolution affects the number of particles [S1].
*   **Computational Complexity:** The basic brightness calculation has a complexity of $O(n^2)$ if intermediate brightness values are considered [S1].

def render_pbvr(tetrahedra, transfer_function, camera, num_repetitions):
    """
    Renders an irregular volume using Sorting-free Pre-integrated Projected Tetrahedra.
    
    Args:
        tetrahedra: List of tetrahedra, each with vertices, scalar values, and connectivity.
        transfer_function: Function mapping scalar value and path length to color and opacity.
        camera: Camera parameters (view matrix, projection matrix, resolution).
        num_repetitions: Number of stochastic repetitions (N).
        
    Returns:
        Image buffer with accumulated brightness.
    """
    width, height = camera.resolution
    image = np.zeros((height, width, 3))

        # For each tetrahedron, project to screen and rasterize
        for tet in tetrahedra:
            # Project vertices to screen space
            screen_vertices = project_to_screen(tet.vertices, camera)
            
            # Rasterize the projected triangle(s)
            # Note: A tetrahedron projects to a convex polygon, often decomposed into triangles
            triangles = decompose_into_triangles(screen_vertices)
            
            for tri in triangles:
                # Get fragment coordinates covered by this triangle
                fragments = rasterize_triangle(tri)
                
                for frag in fragments:
                    # Interpolate scalar value (density) at fragment position
                    # This requires back-projecting to 3D or using barycentric coords
                    density = interpolate_density(tet, frag.barycentric_coords)
                    
                    # Calculate path length through the tetrahedron at this fragment
                    # This is complex in object-order; often approximated or pre-integrated
                    path_length = estimate_path_length(tet, frag)
                    
                    # Get opacity and color from transfer function
                    # Using pre-integration table if available
                    opacity, color = transfer_function(density, path_length)
                    
                    # Stochastic test
                    random_val = random.uniform(0, 1)
                    
                    if random_val <= opacity:
                        # Fragment is "visible" (particle present)
                        rep_image[frag.y, frag.x] += color
                    else:
                        # Fragment is discarded (no particle)
                        pass
        
        # Accumulate result from this repetition
        image += rep_image
        
    # Average over all repetitions
    image /= num_repetitions
    
    return image

def project_to_screen(vertices, camera):
    """Projects 3D vertices to 2D screen coordinates."""
    # Standard perspective projection
    projected = []
    for v in vertices:
        clip_space = camera.view_matrix @ v
        if clip_space[3] > 0: # Behind camera
            continue
        ndc = clip_space[:3] / clip_space[3]
        screen = ((ndc[:2] + 1) * 0.5) * camera.resolution
        projected.append(screen)
    return projected

def rasterize_triangle(screen_vertices):
    """Rasterizes a triangle into fragments."""
    # Bounding box
    min_x, max_x = int(min(v[0] for v in screen_vertices)), int(max(v[0] for v in screen_vertices))
    min_y, max_y = int(min(v[1] for v in screen_vertices)), int(max(v[1] for v in screen_vertices))
    
    fragments = []
    for y in range(min_y, max_y + 1):
        for x in range(min_x, max_x + 1):
            if point_in_triangle((x, y), screen_vertices):
                barycentric = compute_barycentric((x, y), screen_vertices)
                fragments.append({'x': x, 'y': y, 'barycentric': barycentric})
    return fragments

def point_in_triangle(p, tri):
    """Checks if point p is inside triangle tri using barycentric coordinates."""
    v0, v1, v2 = tri
    d1 = sign(p, v0, v1)
    d2 = sign(p, v1, v2)
    d3 = sign(p, v2, v0)
    has_neg = (d1 < 0) or (d2 < 0) or (d3 < 0)
    has_pos = (d1 > 0) or (d2 > 0) or (d3 > 0)
    return not (has_neg or has_pos)

def sign(p1, p2, p3):
    return (p1[0] - p3[0]) * (p2[1] - p3[1]) - (p2[0] - p3[0]) * (p1[1] - p3[1])

def compute_barycentric(p, tri):
    v0, v1, v2 = tri
    denom = (v1[1] - v2[1]) * (v0[0] - v2[0]) + (v2[0] - v1[0]) * (v0[1] - v2[1])
    if denom == 0: return (0, 0, 0)
    u = ((v1[1] - v2[1]) * (p[0] - v2[0]) + (v2[0] - v1[0]) * (p[1] - v2[1])) / denom
    v = ((v2[1] - v0[1]) * (p[0] - v2[0]) + (v0[0] - v2[0]) * (p[1] - v2[1])) / denom
    w = 1 - u - v
    return (u, v, w)

    """Returns color and opacity based on density and path length."""

## Operating characteristics
*   **Time Complexity:** The basic brightness calculation has a complexity of $O(n^2)$ if intermediate brightness values are considered [S1]. The overall performance is greatly influenced by the number of pixels and the number of repetitions $N$ [S1].
*   **Memory Complexity:** PBVR is memory-consuming since the increase in image resolution affects the number of particles [S1].
*   **Measured Performance:** On an NVIDIA GeForce 9600GT, PBVR can render ~10 million particles at 25.7 milliseconds per repetition with a 1024x1024 resolution [S1]. For a 1024x1024 resolution, the computing time is estimated at 1.4 seconds per repetition for larger datasets [S1].
*   **Strengths:**
    *   Sorting-free: No visibility sorting required, avoiding artifacts from insufficient k-buffer size (unlike HAVS) [S1].
    *   Scalability: Can handle large-scale irregular volumes distributed across multiple computing nodes, as it does not require the entire dataset to be stored on a single node for visibility calculation [S1].
    *   Image Quality: Avoids visible footprints when the viewpoint is inside the volume (unlike PBVR particle-based methods) [S1].
*   **Limitations:**
    *   Performance is heavily dependent on image resolution and repetition level [S1].
    *   May generate insufficient particles when density functions change drastically, leading to artifacts [S1].
    *   Memory consumption increases with image resolution [S1].
*   **When to Use:** Suitable for large-scale irregular volumes where visibility sorting is a bottleneck or impractical, and when high image quality is needed without the artifacts of particle-based methods. Preferred over PBVR when the number of particles is larger than 24 million [S1].
*   **When Not to Use:** When the density function changes drastically and high fidelity of precipitous transfer functions is required (SPT is better) [S1]. When memory is constrained and image resolution is high [S1].

## Background
*   **Origin:** The method was presented in a paper titled "Sorting-free pre-integrated projected tetrahedra" [S1].
*   **History:** It was developed to address the limitations of particle-based volume rendering (PBVR) and conventional projected tetrahedra (PT) which require visibility sorting. It builds on the density emitter model and Poisson distribution assumptions for particle counts [S1].
*   **Usage:** Applied to large-scale irregular volumes from CSM and CFD simulations [S1].
