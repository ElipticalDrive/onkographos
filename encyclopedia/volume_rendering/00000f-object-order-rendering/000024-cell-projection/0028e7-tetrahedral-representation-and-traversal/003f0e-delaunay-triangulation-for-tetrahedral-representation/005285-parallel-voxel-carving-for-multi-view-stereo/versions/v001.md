# Parallel Voxel Carving for Multi-view Stereo

Also called: GPU-based Scalable Volumetric Reconstruction for Multi-view Stereo

## Overview
Parallel Voxel Carving is a scalable volumetric reconstruction algorithm for multi-view stereo that utilizes a GPU to simultaneously execute a large number of threads, each performing voxel carving to integrate depth maps with images from multiple views [S1, unofficial]. It solves the problem of reconstructing large-scale outdoor scenes by converting semi-dense image correspondences into view-dependent depth maps and then projecting these maps into a 3D voxel grid to carve away photo-inconsistent volumes [S1, unofficial]. Unlike direct mesh integration, which struggles with triangle intersections in parallel environments, this method outputs surface voxels with normals and connectivity, making it suitable for point-based rendering and scalable to high-resolution grids via streaming [S1, unofficial].

## How it works

### Inputs and Outputs
**Inputs:**
1.  A set of input images from multiple views.
2.  Camera poses for each image (estimated prior to reconstruction).
3.  Depth maps for each view, generated from semi-dense correspondences.

**Outputs:**
1.  A set of "surface voxels." Each surface voxel stores a weighted average plane (normal and distance) among several view-dependent planes intersecting the voxel cube, shifted to a point on this plane, along with an optimally interpolated color from all visible images [S1, unofficial].
2.  Alternatively, the full volumetric data (carved, surface, and inner uncarved voxels) [S1, unofficial].

### Data Structures

**Depth Map Structure:**
*   Stored per pixel.
*   Contains depth values representing the distance between the camera viewpoint and the view-dependent surface.
*   Contains plane information (normal vector) at every pixel [S1, unofficial].

**Surface Voxel Structure:**
*   Represents a voxel on the object surface.
*   Stores a weighted average plane derived from intersecting view-dependent planes.
*   The voxel position is shifted to a point on this weighted average plane [S1, unofficial].

**Voxel Grid:**
*   Configurable dimensions based on scene orientation.
*   Typical example for aerial/terrain scenes: $8192 \times 512 \times 8192$ (x, y, z), where x and z are horizontal and y is vertical [S1, unofficial].

### Algorithm Steps

#### 1. Preprocessing
1.  **Camera Pose Estimation and Image Matching:** Perform dense correspondence using a gradient-based warping and coarse-to-fine hierarchical matching algorithm (e.g., Cluff et al.) [S1, unofficial].
2.  **Edge Extraction:** Extract matching points on or near edges using an edge detector [S1, unofficial].
3.  **3D Point Computation and Refinement:** Compute 3D points from pairwise correspondences. Refine camera poses and 3D points via bundle adjustment [S1, unofficial].
4.  **Terrain Alignment (Optional but recommended for aerial scenes):**
    *   Estimate a least-squares plane to align the 3D point cloud onto the x-z plane.
    *   Transform all coordinates and camera projection matrices so that x and z are horizontal and y is vertical.
    *   This allows using a smaller range in the y-axis (e.g., 512 vs 8192) for efficiency [S1, unofficial].

#### 2. Depth Map Generation
1.  **Semi-Dense Correspondences:** Use semi-dense correspondences between two images and their determined 3D points. Semi-dense pairs are sparser than dense matches but sufficient to determine geometry, mitigating errors in textureless or occluded regions [S1, unofficial].
2.  **Delaunay Triangulation:** Generate a depth mesh via Delaunay triangulation of the 2D correspondences [S1, unofficial].
3.  **View-Dependent Surface Creation:** Replace 2D vertices in the mesh with their corresponding 3D points to create a view-dependent 3D surface [S1, unofficial].
4.  **Normal Computation:** Compute each triangle's normal from its 3D vertex coordinates. Choose the sign of the normal to ensure a negative dot product with the viewing direction [S1, unofficial].
5.  **Mesh Simplification (Optional):** If input correspondences are noisy, apply mesh simplification to merge triangles with similar normals [S1, unofficial].
6.  **Projection:** Project the depth mesh onto the image plane to create a dense depth map. The depth map stores depth values and plane normals at every pixel [S1, unofficial].

#### 3. Parallel Voxel Carving
The volume is partitioned into sub-volumes. A parallel GPU kernel is executed for each sub-volume.

**Parallelization Strategy:**
*   The GPU kernel uses $V_W \times V_D$ threads in parallel.
*   Each thread performs $V_H$ voxel carving operations independently.
*   For a $256^3$ voxel sub-volume, $256^2$ threads run in parallel, with each thread carving 256 voxels along the y-axis [S1, unofficial].
*   Carving is done along the y-axis to balance workloads, as urban scenes are often flat in this dimension [S1, unofficial].

**Carving Logic (per thread):**
For each voxel in its assigned range:
1.  **Visibility Check:** Determine if the voxel is visible in the current view.
2.  **Projection:** Project the voxel center into the image plane of the current view.
3.  **Photo-Consistency Test:**
    *   Retrieve the depth value $d_{map}$ and normal $n_{map}$ from the depth map at the projected pixel.
    *   Retrieve the depth value $d_{voxel}$ from the voxel's position relative to the camera.
    *   Check if the voxel is photo-inconsistent. A voxel is carved away if it does not match the depth map/image data. Specifically, if the voxel's depth deviates significantly from the depth map's depth, or if the photo-consistency metric fails [S1, unofficial].
    *   *Note:* Incorrect view-dependent surfaces are carved away when voxel carving is performed with another viewpoint. Correct surfaces remain [S1, unofficial].
4.  **Update State:**
    *   If carved: Mark voxel as "Carved."
    *   If not carved: Mark voxel as "Uncarved" (Inner) or "Surface" (if it is on the boundary of the uncarved region).
5.  **Surface Voxel Calculation (for final output):** For voxels identified as surface voxels, compute a weighted average plane among several view-dependent planes intersecting the voxel cube. Shift the voxel to a point on this plane [S1, unofficial].

### Pseudocode

```python
import math

def preprocess_images(images, poses):
    """
    Step 1: Preprocessing
    """
    # 1.1 Dense Correspondence
    # Use gradient-based warping and coarse-to-fine hierarchical matching
    correspondences = dense_correspondence_algorithm(images)
    
    # 1.2 Edge Extraction
    edge_points = extract_edge_points(correspondences)
    
    # 1.3 3D Point Computation
    # Triangulate 3D points from pairwise correspondences
    points_3d = triangulate(edge_points, poses)
    
    # 1.4 Bundle Adjustment
    poses, points_3d = bundle_adjustment(poses, points_3d)
    
    # 1.5 Terrain Alignment (if aerial/terrain scene)
    # Estimate least squares plane for x-z alignment
    plane = estimate_least_squares_plane(points_3d)
    transform_matrix = compute_alignment_transform(plane)
    
    # Transform coordinates and projection matrices
    points_3d = apply_transform(points_3d, transform_matrix)
    poses = apply_transform_to_poses(poses, transform_matrix)
    
    return poses, points_3d

def generate_depth_maps(images, poses, points_3d):
    """
    Step 2: Depth Map Generation
    """
    depth_maps = []
    
    for i, (image, pose) in enumerate(zip(images, poses)):
        # 2.1 Semi-Dense Correspondences
        # Use semi-dense pairs between image i and other views
        semi_dense_pairs = get_semi_dense_correspondences(image, poses, points_3d)
        
        # 2.2 Delaunay Triangulation of 2D correspondences
        # Project 3D points to 2D image plane for triangulation
        points_2d = project_to_2d(semi_dense_pairs, pose)
        mesh = delaunay_triangulation(points_2d)
        
        # 2.3 View-Dependent Surface
        # Replace 2D vertices with 3D points
        mesh_3d = replace_with_3d(mesh, semi_dense_pairs)
        
        # 2.4 Normal Computation
        for triangle in mesh_3d:
            v0, v1, v2 = triangle.vertices
            normal = compute_normal(v0, v1, v2)
            # Ensure negative dot product with viewing direction
            view_dir = pose.camera_direction
            if dot(normal, view_dir) > 0:
                normal = -normal
            triangle.normal = normal
            
        # 2.5 Mesh Simplification (if noisy)
        if is_noisy(semi_dense_pairs):
            mesh_3d = simplify_mesh(mesh_3d)
            
        # 2.6 Project to Depth Map
        # Project mesh onto image plane to create dense depth map
        depth_map = project_mesh_to_depth_map(mesh_3d, image.resolution)
        depth_maps.append(depth_map)
        
    return depth_maps

def parallel_voxel_carving(depth_maps, poses, grid_dims):
    """
    Step 3: Parallel Voxel Carving
    """
    # Partition volume into sub-volumes
    sub_volumes = partition_volume(grid_dims)
    
    # GPU Kernel Execution
    # Each sub-volume is processed by a parallel GPU kernel
    reconstructed_voxels = []
    
    for sub_vol in sub_volumes:
        # 256^2 threads for 256^3 sub-volume
        # Each thread handles V_H voxels along Y-axis
        threads = 256 * 256
        voxels_per_thread = 256
        
        # Initialize voxel states
        voxel_states = initialize_voxel_states(sub_vol)
        
        # Parallel Execution
        for thread_id in range(threads):
            # Each thread processes its assigned voxels
            for h in range(voxels_per_thread):
                voxel = get_voxel(sub_vol, thread_id, h)
                
                is_surface = False
                weighted_normal = [0, 0, 0]
                weighted_dist = 0
                weight_sum = 0
                
                # Check against all views
                for view_idx, (depth_map, pose) in enumerate(zip(depth_maps, poses)):
                    # 3.1 Visibility Check
                    if not is_visible(voxel, pose):
                        continue
                        
                    # 3.2 Projection
                    proj_u, proj_v = project_voxel_to_image(voxel, pose)
                    
                    # 3.3 Photo-Consistency Test
                    # Get depth from map and voxel
                    d_map = depth_map.get_depth(proj_u, proj_v)
                    d_voxel = distance(voxel.center, pose.camera_origin)
                    
                    # Check consistency
                    # If voxel is photo-inconsistent, carve it away
                    if is_photo_inconsistent(d_map, d_voxel, depth_map.get_normal(proj_u, proj_v), voxel):
                        voxel_states[voxel.id] = "CARVED"
                        continue
                    else:
                        voxel_states[voxel.id] = "UNCARVED"
                        
                        # Accumulate for surface voxel calculation
                        # Weighted average plane from view-dependent planes
                        n_map = depth_map.get_normal(proj_u, proj_v)
                        # Weight could be based on confidence or inverse distance
                        w = 1.0 
                        weighted_normal = weighted_normal + w * n_map
                        weighted_dist += w * d_map
                        weight_sum += w
                
                # 3.4 Surface Voxel Calculation
                if voxel_states[voxel.id] == "UNCARVED":
                    # Check if it's a surface voxel (boundary of uncarved region)
                    if is_boundary(voxel, voxel_states):
                        voxel_states[voxel.id] = "SURFACE"
                        
                        # Compute weighted average plane
                        if weight_sum > 0:
                            avg_normal = normalize(weighted_normal)
                            avg_dist = weighted_dist / weight_sum
                            
                            # Shift voxel to point on weighted average plane
                            voxel.center = shift_voxel_to_plane(voxel.center, avg_normal, avg_dist)
                            
                            # Store surface voxel data
                            reconstructed_voxels.append(SurfaceVoxel(
                                position=voxel.center,
                                normal=avg_normal,
                                color=interpolate_color(voxel, depth_maps, poses)
                            ))
                            
    return reconstructed_voxels

def is_photo_inconsistent(d_map, d_voxel, n_map, voxel):
    """
    Determine if a voxel is photo-inconsistent.
    Simplified logic: if depth difference exceeds threshold or normal mismatch.
    """
    depth_diff = abs(d_map - d_voxel)
    # Threshold depends on resolution and scene scale
    threshold = 1.0 # Placeholder for specific implementation detail
    return depth_diff > threshold
```

### Parameters
*   **Voxel Grid Dimensions:** Configurable. Example: $8192 \times 512 \times 8192$ (x, y, z) for aerial scenes [S1, unofficial].
*   **GPU Thread Configuration:** $256^2$ threads per sub-volume kernel [S1, unofficial].
*   **Sub-Volume Size:** Approximately $256^3$ voxels per kernel to fit GPU memory [S1, unofficial].

### Edge Cases and Pitfalls
*   **Textureless Regions:** Dense correspondence algorithms fail here. The method uses semi-dense correspondences to mitigate this [S1, unofficial].
*   **Occluded Regions:** Pixels in occluded regions cause matching errors. Semi-dense correspondences help mitigate negative influences from interpolation and smoothing [S1, unofficial].
*   **Camera Pose Errors:** Incorrect poses lead to poor reconstruction. The method assumes poses are estimated prior to reconstruction [S1, unofficial].
*   **View-Dependent Surfaces:** Some view-dependent surfaces may be incorrect but remain if the angle between the camera ray and the object's true surface normal is favorable. These are carved away by other viewpoints [S1, unofficial].

## Subtopics

### Local Convex Hull (LCH)
*   **What it is:** A method for surface reconstruction from point clouds using local convex hulls.
*   **Difference:** LCH focuses on mesh generation from points, whereas Parallel Voxel Carving operates directly in voxel space using photo-consistency.
*   **When to choose:** When a polygonal mesh is required directly from points without volumetric representation.
*   **Link:** [Local Convex Hull (LCH)](11862-local-convex-hull-lch.md)

## Operating characteristics

*   **Time Complexity:** Linear with respect to the number of voxels and views, $O(V \cdot N)$, where $V$ is the number of voxels and $N$ is the number of views. Parallelization on GPU makes it effectively linear with respect to the number of threads.
*   **Memory Complexity:** Proportional to the voxel grid size and the number of depth maps. The method uses streaming to handle large volumes, limiting GPU memory usage to sub-volumes ($256^3$ voxels) [S1, unofficial].
*   **Measured Performance:** Achieves high performance for large-scale reconstruction with synthetic and real urban scenes [S1, unofficial].
*   **Scaling:** Scalable via partitioning the volume into sub-volumes and using streaming [S1, unofficial].
*   **Strengths:**
    *   Effective parallelization on GPU.
    *   Handles large-scale outdoor scenes.
    *   Outputs surface voxels with normals and connectivity.
    *   Robust to noise via semi-dense correspondences.
*   **Limitations:**
    *   Requires accurate camera poses.
    *   Struggles with textureless regions without semi-dense matching.
    *   Volumetric representation can be memory-intensive for very large scenes without streaming.
*   **When to use:** Large-scale scene reconstruction in high-resolution voxel grids, specifically for aerial photographs of outdoor scenes and real urban/outdoor scenes [S1, unofficial].
*   **When not to use:** When camera poses are unknown or inaccurate, or when real-time performance on small objects is required without GPU acceleration.

## Background

*   **Origin:** The method was proposed by researchers from Lawrence Livermore National Laboratory and the University of California, Davis [S1, unofficial].
*   **History:** It builds on space carving techniques [11, 12] and integrates concepts from previous work [3] to combine depth maps with images for volumetric integration [S1, unofficial].
*   **Usage:** Used for large-scale scene reconstruction, particularly for aerial photographs and urban scenes [S1, unofficial]. It can be integrated with existing multi-view stereo algorithms like PMVS2 to fill holes in textureless regions [S1, unofficial].
