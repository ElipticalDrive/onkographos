# Tetrahedral Mesh Connectivity Encoding

Also called: Basic Cut-Border Machine, Opcode-based mesh representation, Segment-based mesh encoding

## Overview
Tetrahedral Mesh Connectivity Encoding, commonly known as the Cut-Border Machine (CBM), is a region-growing compression scheme that encodes the connectivity of a tetrahedral mesh by traversing it and generating a stream of opcodes [S1]. It solves the problem of efficiently storing and transmitting mesh topology by describing each new tetrahedron relative to a growing boundary (the cut-border) rather than storing explicit adjacency lists [S1]. Unlike sibling methods that may rely on global indexing or explicit neighbor pointers, CBM uses a local, deterministic traversal order (FIFO) and a fixed set of 11 opcodes to reconstruct the mesh structure sequentially [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A tetrahedral mesh (potentially multi-resolution with segments/patches).
*   **Output:** A binary stream containing vertex indices for the initial tetrahedron, followed by a sequence of 4-bit opcodes and associated parameters (vertex indices), and geometry/attribute data [S1].

**Data Structures:**
*   **Cut-Border:** A triangle mesh representing the boundary between encoded (inner) and unencoded (outer) tetrahedra [S1].
*   **Gate:** A specific triangle face on the cut-border where the next tetrahedron is added [S1].
*   **FIFO Buffer:** Stores vertices in the order they are first encountered to determine the traversal order [S1].
*   **Hash Maps:** Two hash maps are used during decoding to reconstruct face incidencies:
    1.  `In-Patch Hash Map`: Stores pairs of triangles for faces shared within a single patch/segment [S1].
    2.  `Cross-Patch Hash Map`: Stores pairs of triangles for faces shared between different patches or segments [S1].
    *   Keys in hash maps are defined by the unique indices of the triangle vertices [S1].
*   **Non-Manifold Detection:** A hash map storing all incident triangles for every edge on the cut-border, keyed by the edge's two end-vertex indices [S1].

**Numbered Steps:**

1.  **Initialization:**
    *   Select an arbitrary starting tetrahedron $T_0$ with vertices $\{V_0, V_1, V_2, V_3\}$ [S1].
    *   Output the indices of these four vertices [S1].
    *   Initialize the cut-border with the four faces of $T_0$ [S1].
    *   Initialize the FIFO buffer with $\{V_0, V_1, V_2, V_3\}$ [S1].
    *   Initialize the two hash maps as empty [S1].

2.  **Traversal Loop:**
    *   While the outer part of the mesh is not empty:
        *   Dequeue the first vertex $V_{curr}$ from the FIFO buffer [S1].
        *   Fix $V_{curr}$ as the current vertex.
        *   Traverse all tetrahedra incident to $V_{curr}$ that are not yet encoded. For each such tetrahedron:
            *   Identify the **gate**: the face of the current tetrahedron that lies on the cut-border and does not contain $V_{curr}$ (or is the boundary) [S1].
            *   Identify the **free vertex** $V_{free}$: the vertex of the tetrahedron not part of the gate [S1].
            *   Determine the **Opcode** based on the position of $V_{free}$ relative to the gate and the cut-border [S1]:
                *   **Case 1: Border (B)**. The gate is a boundary of the entire mesh (no tetrahedron exists on the other side). No free vertex. Output Opcode `B` [S1].
                *   **Case 2: Free vertex is new (not on cut-border)**.
                    *   Check if $V_{free}$ lies on a segment/patch boundary.
                    *   If yes: Output Opcode `S` (New Shared Vertex) followed by the 16-bit local index of $V_{free}$ and the 32-bit global unique index [S1].
                    *   If no: Output Opcode `N` (New Vertex) followed by the 16-bit local index of $V_{free}$ [S1].
                    *   Add $V_{free}$ to the end of the FIFO buffer [S1].
                *   **Case 3: Free vertex is already on the cut-border**.
                    *   Determine the relationship between $V_{free}$ and the three triangles adjacent to the gate on the cut-border [S1].
                    *   **Flip $i$ ($F_i$)**: $V_{free}$ is incident to exactly one adjacent triangle. $i \in \{0, 1, 2\}$ identifies which triangle [S1]. Output Opcode `F` + $i$ [S1].
                    *   **Top $i$ ($T_i$)**: $V_{free}$ is incident to exactly two adjacent triangles. $i \in \{0, 1, 2\}$ identifies the triangle *not* incident to $V_{free}$ [S1]. Output Opcode `T` + $i$ [S1].
                    *   **Close ($C$)**: $V_{free}$ is incident to all three adjacent triangles [S1]. Output Opcode `C` [S1].
                    *   **Join ($J$)**: $V_{free}$ is incident to none of the adjacent triangles [S1]. Output Opcode `J` [S1].
            *   **Update Cut-Border:**
                *   Remove the gate from the cut-border.
                *   Add the three new faces formed by $V_{free}$ and the edges of the gate to the cut-border [S1].
                *   **Handle Non-Manifold Edges:**
                    *   For each new edge on the cut-border, check if it is non-manifold using the edge-incident-triangle hash map [S1].
                    *   If an edge is incident to more than 4 triangles: Output Opcode `Skip` (12th symbol), discard the current gate, and proceed to the next gate without updating the cut-border for this tetrahedron [S1].
                    *   If an edge is incident to exactly 4 triangles: The adjacency is defined by vertex order; no geometry tests needed [S1].
                    *   Update the hash map with the new incident triangles for the affected edges [S1].
            *   **Relocate Gate:** Select a new face from the updated cut-border to be the next gate [S1].

3.  **Termination:**
    *   The process stops when the FIFO buffer is empty and no unencoded tetrahedra remain [S1].

**Pseudocode:**

```python
def encode_tetrahedral_mesh(mesh):
    # 1. Initialization
    start_tet = mesh.get_arbitrary_tetrahedron()
    vertices = start_tet.vertices # [V0, V1, V2, V3]
    
    # Output initial vertices
    output_stream.write(vertices)
    
    # Initialize cut-border with faces of start_tet
    cut_border_faces = start_tet.faces
    gate = cut_border_faces[0] # Arbitrary initial gate
    
    # FIFO buffer for traversal order
    fifo = Queue()
    for v in vertices:
        fifo.enqueue(v)
        
    # Hash maps for decoding support (stored implicitly or explicitly)
    # edge_incidents: Map<Edge, List<Triangle>>
    edge_incidents = {}
    
    # 2. Traversal
    while not fifo.is_empty():
        v_curr = fifo.dequeue()
        
        # Get all unencoded tetrahedra incident to v_curr
        incident_tets = mesh.get_unencoded_incident_tetrahedra(v_curr)
        
        for tet in incident_tets:
            # Identify gate: face on cut_border not containing v_curr
            # Note: In implementation, gate is maintained from previous step
            # or selected from cut_border_faces. 
            # Here we assume 'gate' is the current face being processed.
            
            # Identify free vertex: vertex in tet not in gate
            gate_vertices = set(gate.vertices)
            free_vertex = [v for v in tet.vertices if v not in gate_vertices][0]
            
            opcode = None
            param = None
            
            # Determine Case
            if gate.is_boundary():
                opcode = 'B' # Border
            elif free_vertex not in cut_border_faces:
                # New Vertex
                if free_vertex.is_on_segment_boundary():
                    opcode = 'S'
                    param = (free_vertex.local_index, free_vertex.global_index)
                else:
                    opcode = 'N'
                    param = free_vertex.local_index
                fifo.enqueue(free_vertex)
            else:
                # Free vertex is on cut-border
                # Find adjacent triangles to gate on cut-border
                adj_triangles = get_adjacent_triangles_on_cut_border(gate)
                
                # Count incidences of free_vertex in adj_triangles
                incident_count = 0
                incident_indices = []
                for idx, tri in enumerate(adj_triangles):
                    if free_vertex in tri.vertices:
                        incident_count += 1
                        incident_indices.append(idx)
                        
                if incident_count == 1:
                    opcode = 'F'
                    param = incident_indices[0] # i
                elif incident_count == 2:
                    # i is the index of the triangle NOT incident
                    missing_idx = [i for i in range(3) if i not in incident_indices][0]
                    opcode = 'T'
                    param = missing_idx
                elif incident_count == 3:
                    opcode = 'C'
                elif incident_count == 0:
                    opcode = 'J'
                else:
                    # Should not happen for valid manifold/non-manifold logic
                    pass

            # Handle Skip for >4 incident triangles
            # Check new edges created by adding tet
            new_edges = get_new_edges_on_cut_border(gate, free_vertex)
            skip_needed = False
            for edge in new_edges:
                if len(edge_incidents.get(edge, [])) > 4:
                    skip_needed = True
                    break
            
            if skip_needed:
                output_stream.write('Skip')
                # Discard gate, do not update cut-border for this tet
                continue
            else:
                output_stream.write(opcode)
                if param is not None:
                    output_stream.write(param)
                
                # Update Cut-Border
                cut_border_faces.remove(gate)
                new_faces = get_new_faces_from_gate_and_free_vertex(gate, free_vertex)
                cut_border_faces.extend(new_faces)
                
                # Update Edge Incidents
                for edge in new_edges:
                    if edge not in edge_incidents:
                        edge_incidents[edge] = []
                    edge_incidents[edge].append(tet)
                    
                # Relocate Gate
                if cut_border_faces:
                    gate = cut_border_faces[0] # Simple selection; real impl may optimize
                else:
                    break # Mesh fully encoded

    return output_stream
```

**Parameters:**
*   **Opcode Size:** 4 bits per opcode [S1].
*   **Vertex Index (N, S, J):** 16 bits per index [S1]. Theoretically $\lceil \log_2(n) \rceil$ bits where $n$ is the number of vertices in the segment [S1].
*   **Shared Vertex Global Index (S):** 32 bits [S1]. Theoretically $\lceil \log_2(m) \rceil$ bits where $m$ is the total number of vertices in the multi-resolution mesh [S1].
*   **Total Opcodes:** 11 (B, N, S, F0, F1, F2, T0, T1, T2, C, J) [S1].

**Edge Cases and Pitfalls:**
*   **Non-Manifold Edges (>4 triangles):** The algorithm outputs a `Skip` opcode, discards the current gate, and proceeds to the next gate without adding the tetrahedron to the inner part or updating the cut-border for that specific step [S1]. This increases the total symbol count to 12 [S1].
*   **Non-Manifold Edges (4 triangles):** Allowed. Adjacency is determined by vertex ordering in the triangles, avoiding geometric tests [S1].
*   **Precision:** Not specified in sources.
*   **Boundaries:** The `Border` (B) opcode handles mesh boundaries explicitly [S1].

## Subtopics

### Extended Cut-Border Machine (CBM) for Multi-Resolution
A variant of CBM designed for multi-resolution meshes consisting of segments and patches [S1]. It supports cross-segment incidencies and respects pre-computed mesh layouts [S1]. Vertices on segment boundaries are copied into each segment they belong to, and an additional unique global index is stored for every border vertex to ensure unique identification across segments [S1]. The encoding process enumerates vertices segment-wise and stores segments sequentially in a binary file [S1]. It uses the same 11 opcodes but distinguishes between in-patch and cross-patch faces using two separate hash maps during decoding [S1].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of tetrahedra and vertices, assuming efficient hash map operations for edge and face lookups [S1]. The traversal order (FIFO) ensures each vertex and tetrahedron is processed a constant number of times [S1].
*   **Memory Complexity:** Proportional to the size of the mesh for storing the cut-border, FIFO buffer, and hash maps during encoding/decoding [S1]. The hash maps store edge and face incidencies, which can be significant for non-manifold meshes [S1].
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Scales well with mesh size due to local operations [S1]. Multi-resolution support allows efficient handling of large datasets by processing segments independently [S1].
*   **Strengths:** High compression ratio for connectivity; deterministic reconstruction; supports non-manifold edges (up to 4 triangles) without complex geometry tests; supports multi-resolution and cross-segment incidencies [S1].
*   **Limitations:** Does not use arithmetic coding for opcodes in the basic implementation, potentially leaving compression gains on the table [S1]. Non-manifold edges with >4 triangles are skipped, potentially losing topological information for those specific edges [S1]. Relies on a specific traversal order for efficiency [S1].
*   **When to use:** When compact storage of tetrahedral mesh connectivity is required, especially for multi-resolution or segment-based meshes where cross-segment consistency is needed [S1].
*   **When not:** When arithmetic coding is critical for maximum compression [S1]. When meshes contain complex non-manifold structures (>4 triangles per edge) that must be fully preserved [S1].

## Background
The Cut-Border Machine was originally proposed by [Gumhold et al. 1999] for triangle meshes [S1]. It was extended to tetrahedral meshes and multi-resolution segment-based meshes in the work cited as [S1] (Segment-based tetrahedral meshing and rendering, 2005/2006). The extension aimed to preserve pre-computed mesh layouts for better rendering performance, addressing the issue that standard CBM destroys existing vertex indexing [S1]. It is used in visualization systems supporting interactive direct volume rendering, isosurface extraction, and vector field visualization [S1].
