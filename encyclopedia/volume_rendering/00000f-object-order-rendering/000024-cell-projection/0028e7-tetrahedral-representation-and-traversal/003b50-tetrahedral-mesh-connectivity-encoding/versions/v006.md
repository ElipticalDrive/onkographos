# Tetrahedral Mesh Connectivity Encoding

Also called: Basic Cut-Border Machine, Opcode-based mesh representation, Segment-based mesh encoding

## Overview
The Cut-Border Machine (CBM) is a region-growing compression scheme for tetrahedral meshes that encodes connectivity by growing a region bounded by a cut-border [S1]. It solves the problem of efficiently storing and transmitting the topology of tetrahedral volumes by generating a stream of opcodes that describe the position of new vertices relative to the current boundary [S1]. Unlike sibling methods that may rely on fixed subdivision patterns or explicit neighbor lists, CBM dynamically adapts its encoding based on the local manifold structure, using 11 distinct opcodes to uniquely identify vertex positions [S1]. It is particularly suited for multi-resolution meshes where segments are encoded sequentially, supporting cross-segment incidencies through shared vertex indexing [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A tetrahedral mesh (potentially part of a multi-resolution segment-based structure).
*   **Output:** A binary stream consisting of connectivity opcodes (4-bit words) and geometry/attribute data (stored in a single table per segment) [S1].

**Data Structures:**
1.  **Cut-Border:** A triangle mesh representing the boundary between encoded (inner) and unencoded (outer) tetrahedra [S1].
2.  **Gate:** A specific triangle face on the cut-border where the next tetrahedron is added [S1].
3.  **Hash Maps:** Two hash maps store face incidencies:
    *   `in_patch_map`: Stores pairs of triangles for faces internal to a patch/segment [S1].
    *   `cross_patch_map`: Stores pairs of triangles for faces shared between different patches or segments [S1].
    *   Entries in these maps are keyed by triangle vertex indices. The value is the incidence information (the adjacent triangle) [S1].
4.  **Edge Incident Map:** A hash map storing, for every edge on the cut-border, the set of all incident triangles. An edge is uniquely defined by the sorted indices of its two end vertices [S1].

**Opcodes (11 total):**
Each opcode is stored as a 4-bit word [S1].
*   **B (Border):** The gate is a border of the whole mesh. No free vertex exists.
*   **N (New Vertex):** The free vertex is new and not on a segment/patch border. Parameter: Vertex index (16 bits).
*   **S (New Shared Vertex):** The free vertex is new but lies on a border between segments/patches. Parameters: Local vertex index (16 bits) and Global unique index (32 bits) [S1].
*   **F*i* (Flip*i*):** The free vertex is already on the cut-border and is incident to exactly one adjacent triangle of the gate. *i* (0-2) identifies which triangle. No index parameter needed.
*   **T*i* (Top*i*):** The free vertex is already on the cut-border and is incident to exactly two adjacent triangles of the gate. *i* (0-2) identifies the triangle *not* incident to the free vertex. No index parameter needed.
*   **C (Close):** The free vertex is incident to all three adjacent triangles of the gate. No index parameter needed.
*   **J (Join):** The free vertex is incident to none of the adjacent triangles of the gate. Parameter: Vertex index (16 bits) [S1].
*   **Skip:** Used only for non-manifold edges incident to >4 triangles. Discards current gate.

**Algorithm Steps:**
1.  **Initialization:** Select an arbitrary starting tetrahedron. Initialize the cut-border with its faces. Initialize the FIFO buffer with the 4 vertex indices of this tetrahedron. Initialize hash maps as empty.
2.  **Traversal Loop:** While the outer part (unencoded tetrahedra) is not empty:
    a.  **Select Gate:** Pick a face from the cut-border as the current gate.
    b.  **Check Non-Manifold:** If the gate contains an edge incident to >4 triangles, output `Skip`, discard the gate, and return to step 2a. If incident to exactly 4 triangles, proceed (adjacency is defined by vertex order) [S1].
    c.  **Identify Free Vertex:** Determine the position of the vertex opposite the gate relative to the cut-border.
        *   If the gate is a mesh boundary, output `B`.
        *   If the free vertex is already on the cut-border, determine the sub-case (F, T, C, J) based on how many gate-adjacent triangles share this vertex. Output the corresponding opcode.
        *   If the free vertex is new, determine if it is shared across segments/patches.
            *   If shared, output `S` with local and global indices.
            *   If not shared, output `N` with the local index.
    d.  **Update Cut-Border:** Add the new tetrahedron to the inner part. Update the cut-border geometry and topology.
        *   Remove the gate from the cut-border.
        *   Add the three new faces formed by the free vertex and the gate edges to the cut-border.
        *   Update edge-neighbor information in the `Edge Incident Map`. For non-manifold edges (detected via the map), ensure correct adjacency updates [S1].
    e.  **Update FIFO:** If the free vertex is new (N, S, J), append its index to the FIFO buffer.
    f.  **Face Registration:** Reconstruct face incidencies for the decoder using the hash maps:
        *   For each new face, determine if it is an `in-patch` or `cross-patch` face.
        *   **In-patch:** Look up `in_patch_map`. If empty, store self. If one entry exists, update incidence for both and delete entry.
        *   **Cross-patch:** Look up `cross_patch_map` using global indices. If empty, store self. If one entry exists, update incidence and store self as second face. If two entries exist, replace the face from the replaced patch (identified by ceiling/floor segment logic) [S1].
    g.  **Process FIFO:** If the FIFO is not empty, fix the first vertex. Traverse all incident tetrahedra of this vertex (adding them to the inner part and updating the cut-border) before removing the vertex from the FIFO. This ensures efficient locality [S1].

**Pseudocode:**

def encode_tetrahedral_mesh(mesh):
    # Initialization
    cut_border = set(mesh.faces) # Faces of the first tetrahedron
    fifo = [mesh.vertices[0], mesh.vertices[1], mesh.vertices[2], mesh.vertices[3]]
    edge_incident_map = {} # Key: (v1, v2) sorted, Value: set of triangle indices
    in_patch_map = {}      # Key: triangle tuple, Value: adjacent triangle or None
    cross_patch_map = {}   # Key: global_triangle_tuple, Value: list of adjacent triangles
    output_stream = []
    
    # Helper to get edge key
    def get_edge_key(v1, v2):
        return tuple(sorted([v1, v2]))

    # Helper to check non-manifold
    def is_non_manifold_edge(v1, v2):
        edge_key = get_edge_key(v1, v2)
        if edge_key in edge_incident_map:
            return len(edge_incident_map[edge_key]) > 4
        return False

    while cut_border:
        # Select gate (simplified: pick first from set)
        gate = next(iter(cut_border))
        cut_border.remove(gate)
        
        v0, v1, v2 = gate # Vertices of the gate
        v3 = get_free_vertex(mesh, gate) # The vertex not in gate
        
        # Check for non-manifold edges on the gate
        if is_non_manifold_edge(v0, v1) or is_non_manifold_edge(v1, v2) or is_non_manifold_edge(v2, v0):
            output_stream.append('Skip')
            continue
            
        # Determine Opcode
        opcode = determine_opcode(v3, gate, cut_border, mesh)
        output_stream.append(opcode)
        
        # Update Cut-Border
        cut_border.remove(gate)
        new_faces = [
            (v0, v1, v3),
            (v1, v2, v3),
            (v2, v0, v3)
        ]
        cut_border.update(new_faces)
        
        # Update Edge Incident Map
        for f in new_faces:
            for i in range(3):
                e_key = get_edge_key(f[i], f[(i+1)%3])
                if e_key not in edge_incident_map:
                    edge_incident_map[e_key] = set()
                edge_incident_map[e_key].add(f)
                
        # Handle FIFO and Vertex Processing
        if opcode in ['N', 'S', 'J']:
            fifo.append(v3)
            
        # Process FIFO if needed (simplified logic: process vertex if it's the head)
        if fifo and fifo[0] == v3:
            fifo.pop(0)
            process_vertex_fifo(mesh, fifo, cut_border, edge_incident_map, output_stream)

    return output_stream

## Subtopics

### Extended Cut-Border Machine (CBM) for Multi-Resolution
A variant that extends the basic CBM to support multi-resolution meshes composed of segments and patches [S1]. It respects pre-computed mesh layouts by enumerating vertices segment-wise and copying boundary vertices into each segment they belong to [S1]. It stores an additional unique global index for every border vertex to identify it across segments, allowing cross-segment incidencies to be reconstructed [S1]. Segments are encoded sequentially in a binary file, with geometry and attributes stored in a single table per segment [S1].

## Operating characteristics
*   **Compression:** Uses 4-bit words for opcodes. Does not implement arithmetic coding in the basic version, relying on the compact opcode set for sufficient file size reduction [S1]. Arithmetic coding could further improve ratios [S1].
*   **Performance:** Traversal order is crucial for efficiency. The FIFO-based point-wise traversal ensures good locality [S1].
*   **Complexity:** Non-manifold detection uses hash maps for O(1) average lookup of edge incidencies, avoiding the set-cutting operations of earlier implementations [S1].
*   **Limitations:** Non-manifold edges incident to exactly 4 triangles are allowed but decrease compression ratio because adjacency is defined by vertex order rather than topology [S1]. Edges with >4 triangles are skipped, potentially losing connectivity information [S1].
*   **Memory:** Requires storage for two hash maps (in-patch and cross-patch) and an edge incident map during encoding/decoding [S1].

## Background
The Cut-Border Machine was originally proposed by Gumhold et al. [S1]. It was extended by Yoon et al. [S1] to support multi-resolution tetrahedral meshes and segment-based rendering. The method is integrated into visualization systems supporting interactive direct volume rendering, isosurface extraction, and vector field visualization [S1].
