# Tetrahedral Mesh Connectivity Encoding

Also called: Basic Cut-Border Machine, Opcode-based mesh representation, Segment-based mesh encoding

## Overview
The Basic Cut-Border Machine (CBM) is a region-growing compression scheme for tetrahedral meshes that encodes connectivity by growing a region bounded by a cut-border [S1]. It solves the problem of efficiently storing and transmitting the topological structure of tetrahedral volumes for rendering, ensuring unique vertex identification across segments [S1]. Unlike sibling methods that may rely on global indexing or explicit neighbor storage, CBM uses a stream of 11 opcodes to describe the position of new vertices relative to a local "gate" on the cut-border, allowing for compact representation without arithmetic coding [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A tetrahedral mesh (potentially part of a multi-resolution segment).
*   **Output:** A binary stream of opcodes (connectivity) and geometry/attribute data.

**Data Structures:**
1.  **Cut-Border:** A triangle mesh dividing the encoded (inner) and unencoded (outer) parts of the tetrahedral mesh. It consists of faces of the tetrahedra.
2.  **Gate:** A specific triangle face on the cut-border where the next tetrahedron is added.
3.  **FIFO Buffer:** Stores vertices in the order of their appearance during traversal.
4.  **Hash Maps:** Two hash maps store pairs of triangles representing face-incidencies:
    *   `InPatchHash`: For faces within the current patch/segment.
    *   `CrossPatchHash`: For faces shared between different patches or segments.
    *   Keys are edges defined by the indices of their two end vertices.
5.  **Geometry Table:** A single table storing geometry and attribute values for vertices in the segment, ordered by traversal.

**Opcodes (11 total):**
Each opcode describes the position of the "free vertex" (the vertex of the new tetrahedron not on the gate) relative to the gate. Opcodes are stored as 4-bit words.

1.  **B (Border):** The gate is a border of the whole tetrahedral mesh. No free vertex exists.
2.  **N (New Vertex):** The free vertex is new and not on a border between segments/patches. Parameter: Vertex index (16 bits).
3.  **S (New Shared Vertex):** The free vertex is new and lies on a border between segments/patches. Parameters: Vertex index (16 bits) + Unique Global Index (32 bits).
4.  **F*i* (Flip*i*):** The free vertex is incident to exactly one adjacent triangle of the gate. *i* (0, 1, or 2) identifies which triangle. No parameter.
5.  **T*i* (Top*i*):** The free vertex is incident to exactly two adjacent triangles of the gate. *i* (0, 1, or 2) identifies the triangle *not* incident to the free vertex. No parameter.
6.  **C (Close):** The free vertex is incident to all three adjacent triangles of the gate. No parameter.
7.  **J (Join):** The free vertex is incident to none of the adjacent triangles of the gate. Parameter: Vertex index (16 bits).

**Algorithm Steps:**

1.  **Initialization:**
    *   Select an arbitrary tetrahedron.
    *   Initialize the cut-border with the faces of this tetrahedron.
    *   Initialize the FIFO buffer with the indices of the four vertices of the first tetrahedron.
    *   Initialize `InPatchHash` and `CrossPatchHash` as empty.
    *   Initialize the geometry table.

2.  **Traversal Loop:**
    *   While the outer part of the mesh is not empty:
        *   Fix the first vertex $v$ in the FIFO buffer.
        *   Traverse all tetrahedra incident to $v$ that are not yet encoded.
        *   For each tetrahedron to be encoded:
            *   Identify the current **gate** (a face on the cut-border).
            *   Determine the case for the free vertex $v_{free}$ relative to the gate.
            *   **Case 1: Gate is a Border (B).**
                *   Output opcode `B`.
                *   Remove the gate from the cut-border.
                *   Relocate the gate to an adjacent face on the cut-border.
            *   **Case 2: Free Vertex is on Cut-Border (Non-Manifold Handling).**
                *   Check if the edge formed by the gate and $v_{free}$ is non-manifold.
                *   Use the hash map to check incident triangles for the edge endpoints.
                *   If the edge is incident to > 4 triangles:
                    *   Output a `Skip` symbol (12th symbol).
                    *   Discard the current gate.
                    *   Proceed to the next gate without adding a tetrahedron.
                *   If the edge is incident to exactly 4 triangles:
                    *   Proceed with standard adjacency updates (geometry tests not required; vertex order defines adjacency).
            *   **Case 3: Free Vertex is New (N, S, J).**
                *   If $v_{free}$ is on a segment/patch border:
                    *   Output opcode `S`.
                    *   Output 16-bit local index and 32-bit global unique index.
                    *   Add $v_{free}$ to geometry table.
                    *   Update `CrossPatchHash` for new faces.
                *   Else:
                    *   Output opcode `N` or `J` (depending on incidence).
                    *   Output 16-bit local index.
                    *   Add $v_{free}$ to geometry table.
                    *   Update `InPatchHash` for new faces.
            *   **Case 4: Free Vertex is Old (F, T, C).**
                *   Output opcode `F*i*`, `T*i*`, or `C`.
                *   No vertex index parameter needed.
                *   Update cut-border and hash maps.
            *   **Update Cut-Border:**
                *   Add the new tetrahedron's faces to the inner part.
                *   Remove the gate from the cut-border.
                *   Add new boundary faces to the cut-border.
                *   Relocate the gate to a new face on the cut-border.
            *   **FIFO Update:**
                *   If a new vertex was added, append its index to the FIFO buffer.
        *   Remove $v$ from the FIFO buffer.

3.  **Face Incidency Reconstruction (Decoder Side):**
    *   **In-Patch Face:** If all three vertices are local to the patch, register with `InPatchHash`.
        *   If empty: Store face.
        *   If one entry: Update incidency for both, delete entry.
    *   **Cross-Patch Face:** If any vertex is shared (identified by global index), register with `CrossPatchHash`.
        *   If empty: Store face.
        *   If one entry: Update incidency, store second face.
        *   If two entries: Replace the face from the patch that was coarsened/refined.

**Pseudocode:**

```python
def encode_tetrahedral_mesh(mesh):
    # Initialization
    fifo = []
    cut_border_faces = set()
    in_patch_hash = {}  # Key: (v1, v2), Value: [face1, face2]
    cross_patch_hash = {} # Key: (v1, v2), Value: [face1, face2]
    geometry_table = []
    opcode_stream = []
    
    # Start with arbitrary tetrahedron t0
    t0 = mesh.get_arbitrary_tetrahedron()
    v_indices = t0.vertices
    
    # Add initial vertices to FIFO and Geometry
    for v in v_indices:
        if v not in geometry_table:
            geometry_table.append(v)
            fifo.append(v)
            
    # Initialize cut border with faces of t0
    for face in t0.faces:
        cut_border_faces.add(face)
        
    # Select initial gate
    gate = cut_border_faces.pop()
    
    while cut_border_faces or fifo:
        if not fifo:
            break
            
        current_vertex = fifo[0]
        
        # Get all unencoded tetrahedra incident to current_vertex
        incident_tets = mesh.get_unencoded_incident_tetrahedra(current_vertex, gate)
        
        for tet in incident_tets:
            # Identify gate and free vertex
            # Gate is the face shared with the already encoded region
            # Free vertex is the one not in the gate
            
            free_vertex = tet.get_free_vertex(gate)
            
            # Determine Opcode
            opcode, params = determine_opcode(free_vertex, gate, cut_border_faces, 
                                              in_patch_hash, cross_patch_hash, mesh)
            
            opcode_stream.append(opcode)
            opcode_stream.extend(params)
            
            # Update Geometry Table if new vertex
            if opcode in ['N', 'S', 'J']:
                if free_vertex not in geometry_table:
                    geometry_table.append(free_vertex)
                    fifo.append(free_vertex)
                    
            # Update Cut Border
            update_cut_border(gate, tet, cut_border_faces)
            
            # Update Hash Maps for Face Incidency
            update_face_hashmaps(tet, in_patch_hash, cross_patch_hash)
            
            # Relocate Gate
            gate = get_next_gate(cut_border_faces)
            
        fifo.pop(0)
        
    return opcode_stream, geometry_table

    # Check if free_vertex is on cut border

        # Check incidence with gate triangles

        # Check for non-manifold edges
        if is_non_manifold_edge(free_vertex, gate, mesh):

        return get_incidence_opcode(free_vertex, gate), []
```

## Subtopics

### Extended Cut-Border Machine (CBM) for Multi-Resolution
A compression scheme extending the CBM to support cross-segment incidencies and respect pre-computed mesh layouts, storing segments sequentially in a binary file [S1]. It differs from the basic CBM by enumerating vertices segment-wise and copying boundary vertices into each segment they belong to, storing an additional unique global index for every border vertex to identify it across segments [S1]. It uses the same 11 opcodes but adds the 32-bit global index parameter for shared vertices (S) to handle cross-segment references [S1].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of tetrahedra, assuming hash map operations are $O(1)$. The traversal order (FIFO) ensures each tetrahedron is processed once.
*   **Memory Complexity:** Proportional to the number of vertices and edges on the cut-border. The hash maps store face incidencies, requiring memory proportional to the surface area of the cut-border.
*   **Performance:** The method does not implement arithmetic coding, relying on 4-bit word storage for opcodes. This simplifies implementation but results in lower compression ratios compared to arithmetic coding [S1].
*   **Strengths:** Simple implementation, no need for global indexing, supports multi-resolution meshes with pre-computed layouts [S1].
*   **Limitations:** Non-manifold edges incident to more than four triangles are skipped, potentially losing data or requiring special handling. The fixed 16-bit index for new vertices may be inefficient for very large segments [S1].
*   **When to use:** When a simple, robust connectivity encoding is needed for tetrahedral meshes, especially in multi-resolution contexts where segment-based processing is beneficial.
*   **When not to use:** When maximum compression ratio is required (use arithmetic coding). When the mesh contains complex non-manifold structures with >4 triangles per edge.

## Background
The Cut-Border Machine was originally proposed by Gumhold et al. [S1]. It was extended by the authors of [S1] to support multi-resolution tetrahedral meshes and segment-based rendering. The method is used in visualization systems supporting interactive direct volume rendering, isosurface extraction, and vector field visualization [S1].
