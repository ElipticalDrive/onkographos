# Alternating Tetrahedral Decomposition

Also called: Alternating C_even/C_odd Decomposition, Checkerboard Tetrahedral Decomposition, Seeding and Decomposition

## Overview
Alternating Tetrahedral Decomposition is a method for converting a structured hexahedral grid into a tetrahedral mesh by partitioning each cubic cell into five tetrahedra. It solves the topological consistency problem inherent in decomposing cubes, where using a single decomposition pattern for all cells creates T-junctions and discontinuities at shared faces [S1, unofficial]. It sets itself apart from non-alternating schemes by ensuring that adjacent cells share common faces, maintaining the manifold topology required for correct ray-primitive traversal and data interpolation [S1, unofficial].

## How it works
**Inputs:** A structured 3D grid of vertices defining hexahedral cells. Each cell $C_i$ is identified by integer grid coordinates $(C_x, C_y, C_z)$.
**Outputs:** A tetrahedral mesh where each hexahedral cell is represented by five tetrahedra.

**Data Structures:**
Each hexahedral cell has 8 corner vertices, indexed $0$ to $7$. The standard indexing for a cubic cell (as per [S1, unofficial]) follows a specific vertex ordering. The decomposition produces:
1.  Four "corner" tetrahedra.
2.  One "center" tetrahedron.

**Decomposition Schemes:**
Two schemes are defined to alternate across the grid:
1.  **$C_{\text{even}}$**: The four corner tetrahedra are formed at vertex IDs 1, 2, 4, and 7.
2.  **$C_{\text{odd}}$**: The four corner tetrahedra are formed at vertex IDs 0, 3, 5, and 6.
In both schemes, the fifth tetrahedron is the central one, formed by the remaining vertices or the cell center geometry, oriented to share faces with the corner tetrahedra [S1, unofficial].

**Algorithm Steps:**
1.  Iterate over every cell $C_i$ in the structured grid with coordinates $(C_x, C_y, C_z)$.
2.  Calculate the parity sum: $S = (C_x + C_y + C_z) \bmod 2$.
3.  If $S = 0$, apply the $C_{\text{even}}$ decomposition scheme.
4.  If $S = 1$, apply the $C_{\text{odd}}$ decomposition scheme.
5.  Generate the five tetrahedra for the cell using the selected scheme.

**Edge Cases and Pitfalls:**
*   **T-Junctions:** Using the same decomposition pattern for all cells leads to T-junctions and discontinuities between adjacent cells, destroying the topology of the tetrahedral mesh [S1, unofficial].
*   **Face Sharing:** Each pair of adjacent cells shares two common faces (one cell quad). The alternating scheme ensures these faces are shared correctly between the center and corner tetrahedra of neighboring cells [S1, unofficial].

## Subtopics

### Five-Tetrahedron Decomposition
A specific instance of the decomposition where a hexahedral cell is split into five tetrahedra. This is used when the renderer supports only tetrahedral meshes, allowing ray-plane intersection traversal [S2]. It is non-congruent and may require multiple local patterns, increasing case distinctions for indexing [S3].

### Twelve-Triangle Decomposition
An alternative decomposition where a hexahedral cell is split into twelve triangles. Barycentric coordinates are used for data interpolation. This method is associated with Williams et al. [S2]. It introduces multiple vertex types with different valence if a Steiner center vertex is used, potentially leading to uneven feature-hit counts [S3].

### Congruent 6-tet Cube Subdivision
A grid design that satisfies two requirements: (1) Efficient Analytic Traversal, allowing identification of the containing tetrahedron and retrieval of a compact neighborhood under a single canonical local pattern; (2) Uniform Vertex Valence, ensuring vertices have the same number of incident tetrahedra to avoid uneven update frequency and gradient variance [S3]. It uses a global preconditioner $A^*$ to address directional bias induced by grid anisotropy [S3].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of cells in the structured grid, as each cell is processed independently with a constant number of tetrahedra (5) generated.
*   **Memory Complexity:** Linear with respect to the number of cells, storing 5 tetrahedra per cell.
*   **Strengths:** Maintains topological consistency across the entire volume, preventing rendering artifacts like T-junctions. Simple to implement on structured grids.
*   **Limitations:** The non-congruent nature of the 5-tet decomposition can complicate neighbor lookups and indexing compared to congruent subdivisions [S3].
*   **When to use:** When rendering structured hexahedral grids (e.g., smoke volumes) using a renderer that requires tetrahedral primitives [S1, unofficial][S2].

## Background
The method originates from the need to render structured volume data (like smoke) using tetrahedral primitives. It was detailed in the context of real-time smoke volume rendering, where vertices are emitted from a seeding surface into a structured grid [S1, unofficial]. The alternating scheme was introduced to solve the ambiguity of cube decomposition, which otherwise leads to topological errors [S1, unofficial]. The concept of decomposing hexahedra into five tetrahedra for ray casting was also explored by Garrity [Gar90] and Williams et al. [WCA* 90] in the context of irregular grids [S2]. More recent work, such as TetraSDF, contrasts this with congruent 6-tet subdivisions for better training stability and traversal efficiency [S3].
