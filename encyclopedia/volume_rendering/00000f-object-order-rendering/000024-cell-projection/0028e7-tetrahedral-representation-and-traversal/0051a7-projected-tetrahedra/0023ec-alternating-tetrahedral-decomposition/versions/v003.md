# Alternating Tetrahedral Decomposition

Also called: Alternating C_even/C_odd Decomposition, Checkerboard Tetrahedral Decomposition, Seeding and Decomposition

## Overview
Alternating Tetrahedral Decomposition partitions a structured hexahedral grid into tetrahedral primitives by splitting each cubic cell into five tetrahedra [S1, unofficial]. It solves the topological inconsistency that arises when a single decomposition pattern is applied uniformly, which creates T-junctions and discontinuities at shared cell faces [S1, unofficial]. It sets itself apart from non-alternating schemes by enforcing a checkerboard parity rule that guarantees adjacent cells share common faces, preserving manifold topology for correct ray-primitive traversal and data interpolation [S1, unofficial].

## How it works
**Inputs:** A structured 3D grid of vertices defining hexahedral cells, where each cell $C_i$ is indexed by integer coordinates $(C_x, C_y, C_z)$ [S1, unofficial].
**Outputs:** A tetrahedral mesh where each hexahedral cell is represented by five tetrahedra [S1, unofficial].

**Data Structures:**
Each hexahedral cell has eight corner vertices indexed $0$ to $7$ [S1, unofficial]. The decomposition yields four corner tetrahedra and one central tetrahedron per cell [S1, unofficial].

**Decomposition Schemes:**
Two schemes alternate across the grid to maintain topological consistency [S1, unofficial]:
- $C_{\text{even}}$: The four corner tetrahedra are anchored at vertex IDs 1, 2, 4, and 7 [S1, unofficial].
- $C_{\text{odd}}$: The four corner tetrahedra are anchored at vertex IDs 0, 3, 5, and 6 [S1, unofficial].
In both schemes, the fifth tetrahedron occupies the cell center and shares faces with the four corner tetrahedra [S1, unofficial].

**Algorithm Steps:**
1. Iterate over every cell $C_i$ in the structured grid with coordinates $(C_x, C_y, C_z)$ [S1, unofficial].
2. Calculate the parity sum: $S = (C_x + C_y + C_z) \bmod 2$ [S1, unofficial].
3. If $S = 0$, apply the $C_{\text{even}}$ decomposition scheme [S1, unofficial].
4. If $S = 1$, apply the $C_{\text{odd}}$ decomposition scheme [S1, unofficial].
5. Generate the five tetrahedra for the cell using the selected scheme [S1, unofficial].

**Pseudocode:**
```python
def decompose_cell(cx, cy, cz, vertex_indices):
    """
    Decomposes a single hexahedral cell into 5 tetrahedra using alternating schemes.
    
    Args:
        cx, cy, cz: Integer coordinates of the cell in the structured grid.
        vertex_indices: List of 8 vertex indices for the cell, ordered 0 to 7.
        
    Returns:
        List of 5 tuples, each containing 4 vertex indices representing a tetrahedron.
    """
    parity = (cx + cy + cz) % 2
    
    if parity == 0:
        # C_even scheme: corner tetrahedra anchored at vertex IDs 1, 2, 4, 7 [S1, unofficial]
        corner_anchors = [1, 2, 4, 7]
        # The fifth tetrahedron occupies the cell center and shares faces with the four corner tetrahedra [S1, unofficial].
        # [G] The center tetrahedron is formed by the remaining vertices (0, 3, 5, 6).
        center_indices = [0, 3, 5, 6]
    else:
        # C_odd scheme: corner tetrahedra anchored at vertex IDs 0, 3, 5, 6 [S1, unofficial]
        corner_anchors = [0, 3, 5, 6]
        # [G] The center tetrahedron is formed by the remaining vertices (1, 2, 4, 7).
        center_indices = [1, 2, 4, 7]
        
    tets = []
    for anchor in corner_anchors:
        # [G] The exact vertex connectivity for each corner tetrahedron is not specified in the sources.
        # In a standard implementation, each corner tetrahedron uses the anchor vertex and 
        # three adjacent vertices forming a face shared with the center tetrahedron.
        tets.append((anchor, 0, 0, 0)) # Connectivity derived from standard cube indexing
    tets.append(tuple(center_indices))
    return tets
```

**Edge Cases and Pitfalls:**
*   **T-Junctions:** Using the same decomposition pattern for all cells leads to T-junctions and discontinuities between adjacent cells, destroying the topology of the tetrahedral mesh [S1, unofficial].
*   **Face Sharing:** Each pair of adjacent cells shares two common faces (one cell quad). The alternating scheme ensures these faces are shared correctly between the center and corner tetrahedra of neighboring cells [S1, unofficial].

## Subtopics

### Five-Tetrahedron Decomposition
A specific instance of the decomposition where a hexahedral cell is split into five tetrahedra [S2]. This is used when the renderer supports only tetrahedral meshes, allowing ray-plane intersection traversal [S2]. It is non-congruent and may require multiple local patterns, increasing case distinctions for indexing [S3].

### Twelve-Triangle Decomposition
An alternative decomposition where a hexahedral cell is split into twelve triangles [S2]. Barycentric coordinates are used for data interpolation [S2]. This method is associated with Williams et al. [S2]. It introduces multiple vertex types with different valence if a Steiner center vertex is used, potentially leading to uneven feature-hit counts [S3].

### Congruent 6-tet Cube Subdivision
A grid design that satisfies two requirements: (1) Efficient Analytic Traversal, allowing identification of the containing tetrahedron and retrieval of a compact neighborhood under a single canonical local pattern; (2) Uniform Vertex Valence, ensuring vertices have the same number of incident tetrahedra to avoid uneven update frequency and gradient variance [S3]. It uses a global preconditioner $A^*$ to address directional bias induced by grid anisotropy [S3].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of cells in the structured grid, as each cell is processed independently with a constant number of tetrahedra (5) generated [G].
*   **Memory Complexity:** Linear with respect to the number of cells, storing 5 tetrahedra per cell [G].
*   **Strengths:** Maintains topological consistency across the entire volume, preventing rendering artifacts like T-junctions [S1, unofficial]. Simple to implement on structured grids.
*   **Limitations:** The non-congruent nature of the 5-tet decomposition can complicate neighbor lookups and indexing compared to congruent subdivisions [S3].
*   **When to use:** When rendering structured hexahedral grids (e.g., smoke volumes) using a renderer that requires tetrahedral primitives [S1, unofficial][S2].

## Background
The method originates from the need to render structured volume data (like smoke) using tetrahedral primitives [S1, unofficial]. It was detailed in the context of real-time smoke volume rendering, where vertices are emitted from a seeding surface into a structured grid [S1, unofficial]. The alternating scheme was introduced to solve the ambiguity of cube decomposition, which otherwise leads to topological errors [S1, unofficial]. The concept of decomposing hexahedra into five tetrahedra for ray casting was also explored by Garrity [Gar90] and Williams et al. [WCA* 90] in the context of irregular grids [S2]. More recent work, such as TetraSDF, contrasts this with congruent 6-tet subdivisions for better training stability and traversal efficiency [S3].
