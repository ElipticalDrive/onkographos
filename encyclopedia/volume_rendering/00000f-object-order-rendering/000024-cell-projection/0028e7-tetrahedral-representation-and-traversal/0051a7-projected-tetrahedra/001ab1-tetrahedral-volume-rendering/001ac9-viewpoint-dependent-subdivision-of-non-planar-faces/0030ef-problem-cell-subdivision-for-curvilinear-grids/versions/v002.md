# Problem Cell Subdivision for Curvilinear Grids

Also called: Problem face detection, Temporary tetrahedral subdivision

## Overview
Problem Cell Subdivision is a viewpoint-dependent strategy for handling non-planar quadrilateral faces in curvilinear grids that cause self-intersection or multiple intersections with a single viewing ray [S1]. It solves the visibility sort failure inherent in projecting distorted hexahedra by temporarily subdividing only the affected "problem cells" into tetrahedra, while leaving other cells as quadrilaterals [S1]. Unlike full tetrahedral subdivision, which significantly increases rasterization overhead, this method limits computational cost by applying subdivision only where the viewing geometry necessitates it [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A curvilinear mesh (hexahedral cells), a viewpoint $V$, and a BSP tree constructed from exterior faces [S1].
*   **Outputs:** A visibility-sorted list of cells ready for compositing, with problem cells temporarily modified into tetrahedral representations [S1].

**Data Structures:**
*   **Faces:** Each quadrilateral face $F$ is associated with two triangular subfaces, $S$ and $T$, determined by a diagonal from a specific vertex (typically the "smallest" vertex) [S1].
    *   Each subface stores:
        1.  Plane equation.
        2.  Two cell pointers (to the adjacent cells sharing the face, or one if exterior) [S1].
*   **Tetrahedra:** When a cell is subdivided, new tetrahedra are created.
    *   Each new tetrahedron has a parent pointer to the original cell [S1].
    *   Subdivisions are stored in memory blocks of size 2, 3, 5, or 6 tetrahedra, allocated from four large arrays with used/unused lists for reuse [S1].
    *   New tetrahedra and their separating interior faces are stored together in blocks to provide memory locality [S1].

**Algorithm Steps:**

1.  **Preprocessing (Static):**
    *   Subdivide all exterior non-planar quadrilaterals into triangles permanently [S1].
    *   Construct the BSP tree using these exterior triangles for accurate visibility sorting [S1].
    *   Determine the two triangular subfaces for every interior quadrilateral face based on mesh topology [S1].

2.  **Viewpoint Update (Dynamic):**
    *   For each cell $A$ and current viewpoint $V$:
        *   Identify the quadrilateral face $F$ of $A$ divided into triangles $S$ and $T$ by a diagonal from vertex $L$ [S1].
        *   Determine if $F$ is a "problem face" by checking three conditions simultaneously:
            1.  The outward normal to $S$ has a positive dot product with the vector $\vec{VL}$ (from $V$ to $L$) [S1].
            2.  The outward normal to $T$ has a negative dot product with the vector $\vec{VL}$ [S1].
            3.  Both the viewpoint $V$ and the interior of triangle $S$ lie on the same side of the plane of triangle $T$ [S1].
        *   If all three conditions are met, $F$ is a problem face and $A$ is a problem cell [S1].

3.  **Temporary Subdivision:**
    *   If $A$ is a problem cell:
        *   Subdivide $A$ into tetrahedra [S1].
        *   Update the cell pointers in the subfaces of $A$ to point to the new tetrahedra [S1].
        *   For the adjacent cell $B$ on the opposite side of the problem face $F$:
            *   Do **not** subdivide $B$'s volume [S1].
            *   Temporarily replace $B$'s quadrilateral face $F$ with the triangles $S$ and $T$ for sorting and projection purposes [S1].
    *   If $B$ is later determined to be a problem cell due to a different face, subdivide the rest of $B$ consistently [S1].
    *   If a previously subdivided cell is no longer a problem cell, restore it to its original quadrilateral state and return its memory block to the unused list [S1].

4.  **Sorting and Rendering:**
    *   Run the BSP-XMPVO visibility sort on the modified data structure [S1].
    *   Composite the cells in the sorted order [S1].

## Subtopics

### View-Dependent Subdivision
A strategy to limit the computational overhead of full tetrahedral subdivision by only subdividing cells that are intersected by a viewing ray in more than one segment [S1]. It relies on the assumption that distortion is mild enough that multiple intersections occur only when the viewing ray intersects a single curved face more than once [S1]. Compared to full subdivision, which increases polygon count from 7 to 22 and vertex count from 41 to 66 for a hexahedron, this method significantly reduces rasterization effort and geometry overhead [S1].

## Operating characteristics
*   **Time Complexity:** The method requires examining all cells for every new viewpoint to identify problem cells [S1]. If the mesh topology changes, the adjacency graph must be rebuilt by searching for adjacent faces [S1]. If the geometry changes, face plane equations and the BSP tree must be recomputed [S1]. If only the viewpoint moves, edge directions in the adjacency graph must be redetermined [S1].
*   **Memory Complexity:** Subdivisions are stored in fixed-size blocks (2, 3, 5, or 6 tetrahedra) allocated from large arrays, with unused blocks recycled [S1]. This provides memory locality and cache coherence [S1].
*   **Performance:** Full subdivision of a hexahedron into six tetrahedra requires 22 polygons and 66 vertices, causing higher rasterization effort because most pixels are covered by at least three triangles (and up to four for certain faces) [S1]. Problem Cell Subdivision reduces this overhead by only subdividing necessary cells [S1].
*   **Strengths:** Handles Lagrangean meshes that deform or remesh; reduces polygon count compared to full tetrahedralization; compatible with hardware-assisted polyhedron projection [S1].
*   **Limitations:** Requires dynamic updates to the BSP tree and adjacency graph when viewpoint or geometry changes; complex data structure management for temporary subdivisions [S1].

## Background
The method was introduced in 2000 as part of an approximate volume rendering technique for curvilinear and unstructured grids using hardware-assisted polyhedron projection [S1]. It addresses the limitations of projecting non-planar quadrilaterals directly, which can lead to incorrect visibility sorting due to self-intersections or multiple ray intersections [S1]. The approach builds on the BSP-XMPVO sorting algorithm published by Comba et al. in 1999 [S1].
