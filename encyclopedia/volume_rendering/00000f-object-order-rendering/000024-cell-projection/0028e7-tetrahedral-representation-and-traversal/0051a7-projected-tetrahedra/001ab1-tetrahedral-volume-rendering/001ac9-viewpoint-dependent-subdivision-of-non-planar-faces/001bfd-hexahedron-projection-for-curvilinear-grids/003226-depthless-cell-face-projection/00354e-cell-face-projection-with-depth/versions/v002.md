# Cell Face Projection with Depth


## Overview
Cell Face Projection with Depth is a projection-based direct volume rendering method for curvilinear grids that addresses the lack of depth consideration in the depthless method [S2, unofficial]. It maps sample locations to screen space and calculates depth, average color, and opacity for vertices, allowing opacity to be taken into consideration more accurately than its sibling [Depthless Cell Face Projection](6692-depthless-cell-face-projection.md) [S2, unofficial].

## How it works
**Inputs:** Curvilinear grid cell vertex positions, per-vertex data values, and the current camera viewpoint [S2, unofficial].
**Outputs:** Screen-space image with color and opacity values [G].

**Data Structures:**
*   **Cell Data Structure:** Stores precomputed vertex attributes for the current viewpoint [S2, unofficial].
    *   Fields: `vertex_count`, `vertices[]`.
    *   `vertices[i]` contains:
        *   `screen_pos`: 2D screen coordinates.
        *   `depth`: Average depth through the cell at this projected location.
        *   `color`: Average color.
        *   `opacity`: Average opacity.
        *   `is_on_convex_hull`: Boolean flag.
        *   `is_coalesced`: Boolean flag (true if two vertices map to the same screen location).

**Steps:**
1.  **Identify Vertex Addresses and Locations:** Determine the vertex addresses and spatial locations for each cell [S1].
2.  **Map to Screen Space:** Map all sample locations (vertices) of the cell to screen space based on the current viewpoint [S2, unofficial].
3.  **Identify Convex Hull:** For each cell, identify the vertices that lie on the convex hull of the projected cell in screen space [S2, unofficial].
4.  **Process Convex Hull Vertices:**
    *   **Check Coalescence:** Determine if convex hull vertices are coalesced (i.e., two distinct vertices map to the same screen space location) [S2, unofficial].
    *   **If Not Coalesced:** The depth through the cell at that point is zero. The vertex does not contribute color or opacity [S2, unofficial].
    *   **If Coalesced (e.g., looking straight on at a regular cell):** Record a depth for that vertex and take the data value as the average of the two vertices' data values [S2, unofficial]. Map this average to color and opacity [S2, unofficial].
    *   **Depth Recording:** If a vertex appears on the convex hull from certain angles, record its depth; if it appears on the opposite face, take the average of the two vertex depths [S1].
5.  **Process Interior Vertices:** For interior vertices, locate the point at the same projected location on the opposite cell exterior, find data values for that point by interpolation, calculate depth and average color and opacity, and store them in the vertex data structure [S2, unofficial].
6.  **Store Precomputed Data:** This information (depth, color, opacity) is calculated whenever the viewpoint is changed and stored with the cell data structure [S2, unofficial].
7.  **Rendering:** Draw each face once for each cell (twice overall, except on the boundary) [S2, unofficial]. Scale color and opacity based on the depth of the vertex during rendering [S1]. Scaling intensity can be used to take care of intensity problems this may cause [S2, unofficial].

**Pseudocode:**
```python
import numpy as np

def cross_product_2d(o, a, b):
    return (a[0] - o[0]) * (b[1] - o[1]) - (a[1] - o[1]) * (b[0] - o[0])

def compute_2d_convex_hull(screen_verts):
    pts = sorted([(v['sx'], v['sy'], v['idx']) for v in screen_verts])
    hull = []
    for p in pts:
        while len(hull) >= 2 and cross_product_2d(hull[-2][:2], hull[-1][:2], p[:2]) <= 0:
            hull.pop()
        hull.append(p)
    return [h[2] for h in hull]

def project_to_depth(pos_3d, viewpoint_matrix):
    clip = viewpoint_matrix @ np.append(pos_3d, 1.0)
    if clip[3] <= 0: return 0.0
    return clip[2] / clip[3]

def interpolate_data_at(target_pos, cell_vertices):
    # [G] Standard barycentric or trilinear interpolation from cell vertices
    return np.mean([v[1] for v in cell_vertices])

def interpolate_opposite_boundary(start_pos, sx, sy, cell_vertices):
    # [G] Ray-cast from camera through (sx, sy) to find opposite cell boundary
    return start_pos + np.array([0.1, 0.1, 0.1])

def transfer_function(data_val):
    # [G] Standard transfer function mapping data value to (color, opacity)
    return (data_val, data_val)

def rasterize_polygon(face_verts, scaled_color, scaled_opacity):
    # [G] Standard polygon rasterization with per-vertex attributes
    pass

def preprocess_cell(cell_vertices, cell_faces, viewpoint_matrix, transfer_function):
    # 1. Map sample locations to screen space
    screen_verts = []
    for i, (pos_3d, data_val) in enumerate(cell_vertices):
        clip = viewpoint_matrix @ np.append(pos_3d, 1.0)
        if clip[3] <= 0: continue
        ndc = clip[:3] / clip[3]
        screen_verts.append({
            'idx': i, 'pos_3d': pos_3d, 'data': data_val,
            'sx': ndc[0], 'sy': ndc[1], 'depth': ndc[2]
        })

    # 2. Identify convex hull vertices in screen space
    hull_indices = compute_2d_convex_hull(screen_verts)

    # 3. Calculate depth, color, opacity for each vertex
    vertex_data = []
    for v in screen_verts:
        is_hull = v['idx'] in hull_indices
        depth = 0.0
        color = (0.0, 0.0, 0.0)
        opacity = 0.0

        if is_hull:
            coalesced = None
            for other in screen_verts:
                if other['idx'] != v['idx'] and other['idx'] in hull_indices:
                    if abs(other['sx'] - v['sx']) < 1e-6 and abs(other['sy'] - v['sy']) < 1e-6:
                        coalesced = other
                        break

            if coalesced is None:
                # Not coalesced: depth through cell is zero, no contribution
                depth = 0.0
                color = (0.0, 0.0, 0.0)
                opacity = 0.0
            else:
                # Coalesced: record depth, average data values
                depth = (v['depth'] + coalesced['depth']) / 2.0
                avg_data = (v['data'] + coalesced['data']) / 2.0
                color, opacity = transfer_function(avg_data)
        else:
            # Interior vertex: locate point on opposite exterior at same projected location
            opp_pos = interpolate_opposite_boundary(v['pos_3d'], v['sx'], v['sy'], cell_vertices)
            opp_data = interpolate_data_at(opp_pos, cell_vertices)
            opp_depth = project_to_depth(opp_pos, viewpoint_matrix)
            depth = (v['depth'] + opp_depth) / 2.0
            color, opacity = transfer_function(opp_data)

        vertex_data.append({'sx': v['sx'], 'sy': v['sy'], 'depth': depth, 'color': color, 'opacity': opacity, 'is_hull': is_hull})

    return vertex_data, hull_indices

def render_cell(vertex_data, hull_indices, cell_faces):
    # 4. Render faces
    for face in cell_faces:
        face_verts = [vertex_data[i] for i in face if i in hull_indices]
        if len(face_verts) < 3: continue
        for fv in face_verts:
            # Scale color and opacity based on depth
            scaled_color = tuple(c * fv['depth'] for c in fv['color'])
            scaled_opacity = fv['opacity'] * fv['depth']
            rasterize_polygon(face_verts, scaled_color, scaled_opacity)
```

**Parameters:**
*   Viewpoint: Changes the screen projection and triggers recalculation of precomputed values [S2, unofficial].
*   Scaling intensity: A parameter to adjust for intensity problems caused by double drawing [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Coalesced Vertices:** If convex hull vertices are not coalesced, the depth is zero and the vertex contributes nothing [S2, unofficial].
*   **Artifacts:** Produces noticeable artifacts at angles close to 90 degrees for regular cells [S2, unofficial]. These artifacts tend to delineate cell boundaries and probably would not be misinterpreted as data information [S1][S2, unofficial].
*   **Performance:** Much slower for new orientations than the depthless method because precomputation must be recalculated whenever the viewpoint is changed [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Slower than the depthless method for new orientations due to the need to recalculate depth, color, and opacity for all vertices whenever the viewpoint changes [S2, unofficial].
*   **Memory Complexity:** Requires storing precomputed vertex attributes (depth, color, opacity) with the cell data structure for each viewpoint [S2, unofficial].
*   **Accuracy:** Takes opacity into consideration more accurately than the depthless method, providing a more "realistic" rendering assuming a physical, colored medium [S2, unofficial].
*   **Strengths:** More realistic appearance; accounts for depth and opacity.
*   **Limitations:** Noticeable artifacts at near-90-degree angles for regular cells; slower performance for dynamic viewpoints [S2, unofficial].
*   **When to use:** When realistic opacity handling is prioritized over performance and viewpoint stability [G].
*   **When not to use:** When rapid exploration with frequent viewpoint changes is required, or when artifacts at specific angles are unacceptable [G].

## Background
*   **Development:** Developed as an improvement over the "Depthless Cell Face Projection" method to address the lack of depth consideration in compositing [S2, unofficial].
*   **Usage:** Used for direct volume rendering of curvilinear grids, particularly in scientific visualization contexts where realistic opacity is desired [S2, unofficial].
