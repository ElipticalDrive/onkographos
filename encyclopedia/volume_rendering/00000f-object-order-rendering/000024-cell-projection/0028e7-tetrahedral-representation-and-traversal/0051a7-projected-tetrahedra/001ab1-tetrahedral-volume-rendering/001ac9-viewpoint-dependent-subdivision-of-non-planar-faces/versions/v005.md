# Viewpoint-dependent subdivision of non-planar faces

Also called: Bow-tie polygon handling, Non-Planar Face Subdivision Strategy, Subdividing Non-Planar Quadrilaterals, Tetrahedral Subdivision for Non-Planar Faces, Tetrahedral subdivision for non-planar quads, Viewpoint-dependent tetrahedral subdivision

## Overview
This method handles non-planar quadrilateral faces in curvilinear or unstructured grids by subdividing only those faces and cells that cause visibility sorting failures or "bow-tie" projections for a specific viewpoint [S1, S2][S4, S5, unofficial]. It solves the problem where a viewing ray intersects the same non-planar face twice, making back-to-front compositing impossible [S1][S4, unofficial]. Unlike view-independent methods that always subdivide all non-planar faces, this approach is viewpoint-dependent, subdividing only "problem" cells to minimize polygon count and rendering overhead [S1][S4, unofficial]. It builds on [Tetrahedral Volume Rendering](820-tetrahedral-volume-rendering.md) by providing the geometric consistency required for cell projection on general grids.

## How it works
**Inputs:**
- Grid vertices: Array of 3D positions $\mathbf{P}_i$ and scalar values $s_i$.
- Cells: List of cells, each defined by an ordered list of vertex indices.
- Transfer functions: Linear or piecewise linear mappings from scalar $s$ to RGB color and differential opacity $\tau$.
- Viewpoint: Camera position $\mathbf{V}$ and projection parameters.

**Outputs:**
- A set of polygons (triangles, quads, or tetrahedral projections) ready for rasterization and compositing.

**Data Structures:**
- **Vertex List:** Stores $\mathbf{P}_i$ and $s_i$.
- **Cell Structure:**
  - `subdivided`: Boolean flag indicating if the cell is currently subdivided into tetrahedra for the current view.
  - `oldsubdivided`: Boolean flag indicating if the cell was subdivided in the previous frame.
  - `numbInbound`: Integer count of incoming edges in the visibility graph.
  - `type`: Enum identifying the cell topology (e.g., hexahedron, tetrahedron).
  - `vertex_indices`: Array of indices pointing to the Vertex List.
- **Face Diagonals:** Implicitly defined by the lowest-index vertex rule; no explicit storage needed if recomputed or cached per face.

**Steps:**

1. **Face Triangulation (Consistent Subdivision):**
   For every quadrilateral face shared by two cells, determine the diagonal. The diagonal must connect the vertex with the lowest index in the face's vertex list to the opposite vertex. This ensures that both adjacent cells agree on the triangulation of the shared face [S1, S2][S4, S5, unofficial].
   - Let the face vertices be $v_0, v_1, v_2, v_3$ with indices $idx_0, idx_1, idx_2, idx_3$.
   - Find $v_{min}$ such that $idx_{min} = \min(idx_0, idx_1, idx_2, idx_3)$.
   - The diagonal connects $v_{min}$ to the vertex opposite it in the quad.
   - This splits the quad into two triangles.

2. **Problem Cell Detection:**
   A cell is a "problem cell" if a viewing ray can intersect it in more than one disjoint segment. This occurs if the ray intersects multiple triangles of the cell's triangulated boundary in a way that implies entering and exiting the cell multiple times [S1, S2][S4, S5, unofficial].
   - For each cell, check if the viewpoint $\mathbf{V}$ and the cell's geometry allow for multiple intersections.
   - This can be tested using the plane equations of the triangulated faces and the relative positions of $\mathbf{V}$ and the cell vertices [S1, S2][S5, unofficial].
   - If the cell contains contour surfaces (scalar values crossing transfer function breakpoints), it is also marked as a problem cell for subdivision purposes [S1, S2][S5, unofficial].

3. **Cell Subdivision (if Problem Cell):**
   If a cell is marked as a problem cell, subdivide it into tetrahedra.
   - Identify the vertex $v_{cell\_min}$ with the lowest index among all vertices of the cell [S1, S2][S5, unofficial].
   - For each face of the cell that does *not* contain $v_{cell\_min}$, the face is already triangulated (from Step 1).
   - Create tetrahedra by connecting $v_{cell\_min}$ to each of these triangles.
   - This decomposition is consistent with the face triangulation because $v_{cell\_min}$ is also the lowest-index vertex for any face sharing it [S1, S2][S5, unofficial].
   - If the cell contains contour surfaces or transfer function breakpoints, further subdivide the resulting tetrahedra into slabs based on the contour planes or breakpoint scalar values [S1, S2][S5, unofficial].

4. **Projection and Polygon Generation:**
   Project the cell (or its tetrahedral subdivisions) onto the image plane.
   - The projected edges divide the image plane into polygons (triangles and quadrilaterals) [S4, unofficial].
   - For non-subdivided cells, the projection is of the original polyhedron.
   - For subdivided cells, the projection is of the constituent tetrahedra.

5. **Attribute Computation:**
   For each polygon, compute vertex attributes: RGB color, integrated opacity $\alpha$, and ray segment length $l$ (or differential opacity $\tau$) at the front and back endpoints of the viewing ray segment through the cell [S3, book][S4, unofficial].
   - **Profile Vertices:** Vertices on the silhouette. Set color from scalar $s$, set integrated opacity $\alpha = 0$ [S3, book].
   - **Thick Vertices:** Internal vertices (e.g., interior to a face).
     - Compute the back endpoint's $z$, color, and $\tau$ by interpolating across the subdivided face (using the diagonal from Step 1) [S3, book][S4, unofficial].
     - Compute integrated opacity $\alpha = 1 - e^{-\tau \cdot l}$, where $\tau = (\tau_f + \tau_b)/2$ and $l$ is the ray segment length [S3, book][S4, unofficial].
     - Compute color: Either as the average of front and back colors [S3, book] or analytically integrated color divided by $\alpha$ [S3, book].
   - **Length Approximation:** In perspective views, $l$ varies nonlinearly. Approximate by computing $l$ at vertices and interpolating linearly across the polygon in screen space [S3, book][S4, unofficial].

6. **Sorting:**
   Sort cells (or tetrahedra) back-to-front using the MPVO (Minimum Perpendicular Volume Order) algorithm or variants [S4, unofficial].
   - Construct a directed graph where edges represent shared faces, directed towards the cell containing the viewpoint relative to the face plane [S4, unofficial].
   - Handle gaps using exterior face sorting or A-buffer accumulation [S4, unofficial].
   - For subdivided cells, the BSP-MPVO algorithm may be used, where exterior triangles point to subface structures [S3, book].

7. **Rendering and Compositing:**
   Render polygons using standard graphics hardware.
   - Interpolate RGB, $\alpha$, and $z$ linearly across polygons in screen space using Gouraud shading [S3, book][S4, unofficial].
   - Composite using the standard alpha blending equation:
     $$ \text{RGB}_{\text{new}} = (1 - \alpha) \times \text{RGB}_{\text{old}} + \alpha \times \text{RGB}_{\text{polygon}} $$
   - For non-linear opacity integration errors (Mach bands), use texture mapping in orthogonal views: specify $z$ and $\tau$ as texture coordinates, interpolate linearly, and extract $\alpha$ from a preloaded 2D texture map with values $1 - e^{-\tau}$ [S3, book]. In perspective views, this is an approximation [S3, book].

**Pseudocode:**

```python
def process_cell(cell, viewpoint, grid):
    # Step 1: Ensure consistent face triangulation
    for face in cell.faces:
        if face.is_quad():
            v_indices = [grid.vertices[idx].index for idx in face.vertex_indices]
            min_idx = min(v_indices)
            # Determine diagonal based on min_idx vertex
            face.diagonal = get_diagonal_for_min_vertex(face, min_idx)
            face.triangulate()

    # Step 2: Detect if cell is a problem cell
    is_problem = False
    if is_problem_cell_for_viewpoint(cell, viewpoint):
        is_problem = True
    
    # Check for contour/breakpoint crossing
    if cell.scalar_range_contains_breakpoints():
        is_problem = True

    # Step 3: Subdivide if necessary
    if is_problem:
        # Find lowest index vertex in the whole cell
        cell_min_vertex_idx = min([grid.vertices[idx].index for idx in cell.vertex_indices])
        cell_min_vertex = grid.vertices[cell_min_vertex_idx]
        
        tetrahedra = []
        for face in cell.faces:
            if cell_min_vertex not in face.vertices:
                # Face is already triangulated
                for tri in face.triangles:
                    tetrahedra.append(Tetrahedron([cell_min_vertex] + tri.vertices))
        
        # Further subdivide tetrahedra for contours/breakpoints if needed
        slabs = subdivide_tetrahedra_for_contours(tetrahedra, cell.scalar_field)
        return slabs
    else:
        return [cell]

def render_polygon(polygon, viewpoint, grid):
    # Step 5: Compute attributes
    front_endpoint = compute_front_endpoint(polygon, viewpoint)
    back_endpoint = compute_back_endpoint(polygon, viewpoint, grid)
    
    # Interpolate attributes at vertices
    for vertex in polygon.vertices:
        vertex.color = interpolate_color(vertex, front_endpoint, back_endpoint)
        vertex.alpha = 1 - exp(-vertex.tau * vertex.length)
        vertex.z = interpolate_z(vertex, front_endpoint, back_endpoint)

    # Step 7: Rasterize and Composite
    rasterize_polygon(polygon)
    composite(polygon.alpha, polygon.color)
```

## Subtopics

### [Hexahedron Projection for Curvilinear Grids](1111-hexahedron-projection-for-curvilinear-grids.md)
Hexahedron Projection is a cell-projection method for direct volume rendering of curvilinear hexahedral grids that classifies the 2D projection of each hexahedron into specific topological cases and renders them as pre-defined triangle fans or strips. It solves the problem of rendering non-planar faces in curvilinear grids without the computational geometry complexity and floating-point robustness issues of general line-sweep subdivision methods. Unlike its sibling [Per-vertex edge classification for view-independent cell projection](1503-per-vertex-edge-classification-for-view-independent-cell-pro.md), which is view-independent, this method is viewpoint-dependent, relying on the specific 2D projection topology to determine the subdivision. It offers a significant speedup over subdividing all cells into tetrahedra by minimizing vertex and fragment operations for the majority of cells.

### [Per-vertex edge classification for view-independent cell projection](1503-per-vertex-edge-classification-for-view-independent-cell-pro.md)
This method avoids defects in per-vertex classification during rasterization by ensuring that at least one vertex on a shared edge carries the correct visibility classification of the adjacent face. It addresses artifacts caused by per-vertex computations where edge visibility is ambiguous, ensuring the correct classification affects the entire edge during rasterization. Unlike [Viewpoint-dependent subdivision of non-planar faces](835-viewpoint-dependent-subdivision-of-non-planar-faces.md), which subdivides non-planar faces based on the viewpoint, this method relies on vertex attributes to propagate visibility information across shared edges in a view-independent manner.

### [Consistent Tetrahedral Subdivision](6378-consistent-tetrahedral-subdivision.md)
A method to subdivide nonconvex problem cells (like hexahedra with nonplanar quadrilateral faces) into tetrahedra with consistent diagonals on shared faces, avoiding gaps or overlaps.

### [Problem Cell Subdivision for Curvilinear Grids](6388-problem-cell-subdivision-for-curvilinear-grids.md)
A strategy to handle non-planar quadrilateral faces in curvilinear grids that cause self-intersection or multiple intersections with a single viewing ray, by temporarily subdividing only the affected 'problem cells' into tetrahedra while leaving other cells as quadrilaterals.

## Operating characteristics
- **Time Complexity:** Detection of problem cells is $O(1)$ per cell (using plane equations). Subdivision is only performed on problem cells. Sorting is $O(N)$ with MPVO. Rendering is proportional to the number of projected polygons.
- **Memory Complexity:** Requires storing grid topology and potentially subdivided cells. The BSP-MPVO variant may require additional memory for the BSP tree [S3, book].
- **Performance:** Faster than subdividing all cells into tetrahedra because only problem cells are subdivided [S1][S4, unofficial]. However, subdividing all quadrilaterals increases polygon count (e.g., 7 to 25 polygons for a hexahedron) and OpenGL data output, though fragment count remains the same [S4, unofficial].
- **Strengths:** Handles general curvilinear and unstructured grids directly without resampling [S4, unofficial]. Avoids visibility cycles and bow-tie artifacts [S1][S4, unofficial]. Consistent face triangulation prevents gaps/overlaps between adjacent cells [S1][S4, unofficial].
- **Limitations:** Approximations in perspective views (linear interpolation of $\tau$ and $l$) can introduce errors like Mach bands [S3, book][S4, unofficial]. Hardware color interpolation is not mathematically equivalent to analytic integration unless strict conditions are met (orthogonal view, planar faces, linear scalar, constant color per cell) [S4, unofficial].
- **When to use:** Curvilinear or unstructured grids with non-planar faces where visibility sorting is critical.
- **When not to use:** Regular grids (use ray casting or texture-based methods) or when high accuracy in perspective views with non-linear transfer functions is required without hardware approximations [S3, book][S4, unofficial].

## Background
The method was developed to address the limitations of cell projection on curvilinear and unstructured grids, where faces are not necessarily planar [S1][S4, unofficial]. It builds on earlier work by Shirley and Tuchman [S3, book] and the MPVO sorting algorithm [S4, unofficial]. The specific viewpoint-dependent subdivision strategy for non-planar faces was introduced in the context of volume rendering for curvilinear grids [S1, S2][S5, unofficial]. It allows for direct rendering of complex geometries like airplane wings or ship hulls without resampling [S4, unofficial].
