# Viewpoint-dependent subdivision of non-planar faces

Also called: Cell Projection with Non-Planar Face Subdivision, Cell Projection with Non-Planar Faces Approximation, HIAC system cell projection, Hardware-based cell projection, Non-Planar Face Subdivision Strategy, Shirley and Tuchman method approximation, Viewpoint-dependent tetrahedral subdivision

## Overview
This method handles non-planar quadrilateral faces in curvilinear or irregular grids by performing view-dependent subdivision of "problem" faces and cells into triangles and tetrahedra, respectively, to prevent visibility sort failures and bow-tie projections [S1][S3, unofficial]. It approximates ray integration by projecting cells onto the screen, computing integrated opacity and color at vertices, and interpolating these values across screen-space polygons using standard graphics hardware [S2, book]. Unlike methods requiring resampling of curvilinear grids, cell projection works directly on the general grid topology [S3, unofficial].

## How it works
**Inputs:**
- A list of vertices with 3D positions and scalar field values $s$ [S1][S3, unofficial].
- A list of cells (hexahedra or other topologies) with index pointers to their vertices [S1][S3, unofficial].
- A viewpoint $V$ [S1][S3, unofficial].
- Transfer functions mapping scalar $s$ to RGB color and differential opacity $\tau$, assumed linear or piecewise linear [S1][S3, unofficial].

**Outputs:**
- A rendered image with integrated color and opacity [S2, book][S3, unofficial].

**Data Structures:**
- **Vertex List:** Array of vertices, each containing 3D position $(x,y,z)$ and scalar value $s$ [S1][S3, unofficial].
- **Cell Structure:**
  - `subdivided`: Boolean flag indicating if the cell is currently subdivided into tetrahedra [S3, unofficial].
  - `oldsubdivided`: Boolean flag indicating if the cell was subdivided in the previous frame [S3, unofficial].
  - `numbInbound`: Integer count of incoming edges in the directed graph used for sorting [S3, unofficial].
  - `type`: Enum or integer identifying the cell topology (e.g., hexahedron, tetrahedron) [S3, unofficial].
  - Vertex indices: Pointers to the vertices defining the cell [S1].
- **Directed Graph:** For sorting, a graph where nodes are cells and edges represent shared faces, directed towards the cell containing the viewpoint relative to the face plane [S3, unofficial].

**Steps:**
1. **Identify Problem Faces and Cells:** A "problem face" is a non-planar quadrilateral where a viewing ray intersects the same face twice, potentially creating a "bow-tie" projection [S1][S3, unofficial]. A "problem cell" is a cell intersected by a viewing ray in disjoint segments [S1][S3, unofficial]. Detection tests if a viewing ray can intersect a triangulated cell in more than one segment using plane equations of the triangles and locations of viewpoint $V$ and relevant vertices [S1].
2. **Subdivide Problem Faces:** Subdivide any non-planar quadrilateral face into two triangles [S1][S3, unofficial]. The diagonal must start from the quadrilateral vertex with the lowest index in the vertex list to ensure consistency for two cells sharing a face, as the choice depends only on vertex indices [S1][S3, unofficial]. Even if a face is not a "problem face" for a specific cell, it may need subdivision if it is part of a "problem cell" or to avoid gaps between adjacent cells [S3, unofficial].
3. **Subdivide Problem Cells:** If a cell is a "problem cell" for the current viewpoint, subdivide it into tetrahedra [S1][S3, unofficial]. Connect the vertex of lowest index in the whole cell to all triangles from faces not sharing this vertex to create a set of tetrahedra with planar faces [S1]. Only problem cells are subdivided; non-problem cells remain intact to preserve performance [S3, unofficial]. Cells containing contour surfaces or scalar breakpoints in piecewise linear transfer functions are also subdivided into tetrahedra and then into slabs [S1].
4. **Project and Sort:** Project the cell (or its tetrahedral subdivisions) onto the image plane. The projected edges divide the plane into polygons (triangles and quadrilaterals) [S3, unofficial]. Sort cells using the MPVO algorithm (or variants like MPVONC/SXMPVO) based on the directed graph of shared faces. Handle gaps with exterior face sorting or A-buffer accumulation [S3, unofficial]. For contour slabs, sort polygons and volume slabs back-to-front based on viewpoint position relative to contour planes [S1].
5. **Compute Vertex Attributes:** For each polygon, compute vertex attributes (RGB, opacity $\tau$, length $l$) at the front and back endpoints of the viewing ray segment through the cell [S3, unofficial]. Profile vertices are vertices on the silhouette (e.g., vertex A) [S2, book]. Set color directly from scalar values $s$ and integrated opacity to zero [S2, book][S3, unofficial]. Thick vertices are internal vertices (e.g., F, D, I, J) where the ray passes through the cell interior [S2, book][S3, unofficial]. Compute the back endpoint's $z$, color, and $\tau$ by subdividing the interior face with the diagonal from the lowest index vertex and interpolating linearly in screen space [S2, book][S3, unofficial]. Compute ray segment length $l$ by interpolating depth $z$ across the back face polygon in screen space to find the back endpoint, then reversing the eye-to-screen transformation. Approximate by computing $l$ at vertices and interpolating linearly across the polygon in screen space [S2, book][S3, unofficial]. For precise color, compute the correct integrated color analytically once per vertex and divide by integrated $\alpha$ to get the polygon color. Alternatively, use the average of front and back colors [S2, book][S3, unofficial].
6. **Interpolate and Composite:** Interpolate integrated opacity $\alpha$, color (R, G, B), and depth $z$ linearly across the polygon in screen space using standard Gouraud shading hardware [S1][S2, book][S3, unofficial]. Composite the interpolated polygons onto the image using the standard alpha blending equation [S2, book][S3, unofficial]. To correct for non-linear opacity integration errors (Mach bands), use texture mapping hardware in orthogonal views. Specify $z$ and $\tau$ as texture coordinates, linearly interpolate them, and extract the correct alpha from a 2D texture map preloaded with values $1 - e^{-\tau}$ [S2, book]. In perspective views, this is an approximation [S2, book].

**Formulas:**
- Integrated opacity: $\alpha = 1 - e^{-\tau \cdot l}$, where $\tau = (\tau_f + \tau_b)/2$ is the average differential opacity, and $l$ is the ray segment length [S2, book][S3, unofficial].
- Alpha blending: $\text{RGB}_{\text{new}} = (1 - \alpha) \times \text{RGB}_{\text{old}} + \alpha \times \text{RGB}_{\text{polygon}}$ [S2, book][S3, unofficial].

**Parameters:**
- Transfer functions: Map scalar value $s$ to RGB and differential opacity $\tau$. Assumed linear in $s$ for the basic method, but piecewise linear is supported by slicing cells [S3, unofficial].

**Edge Cases and Pitfalls:**
- **Precision:** Hardware color interpolation is inconsistent with analytic integration. Condition (d) (color constant per cell, only $\tau$ varies linearly) is required for hardware-based method to be mathematically equivalent to analytic integration [S3, unofficial].
- **Boundaries:** Non-planar faces cause visibility cycles where a ray intersects the same face twice, making back-to-front sorting impossible without subdivision [S3, unofficial].
- **Degenerate Input:** If a cell is not a problem cell but shares a face with a problem cell, the face must still be subdivided to avoid gaps or overlaps [S3, unofficial].
- **Performance:** Subdividing all quadrilaterals increases polygon count (e.g., 7 to 25 polygons) and OpenGL data output, though fragment count remains the same [S3, unofficial].

            if ray_intersects_face_twice(face, viewpoint):

            if ray_intersects_cell_twice(cell, viewpoint):

        if cell_is_problem:
            problem_cells.append(cell)
            
    # Step 2: Subdivide problem faces
    for face in problem_faces:

        # Split quadrilateral into two triangles using diagonal from min_vertex [S1][S3, unofficial]
        face.split_into_triangles(min_vertex)

## Operating characteristics
- **Time Complexity:** Sorting is O(n) for MPVO [S3, unofficial]. Subdivision is view-dependent and may increase polygon count [S3, unofficial]. Detection of problem cells requires plane equation tests [S1].
- **Memory Complexity:** Increased memory usage for storing subdivided cells and tetrahedra. Data structures must track subdivision state [S3, unofficial].
- **Measured Performance:** On a half-cylindrical shell with 19,000 cells, the method handles non-planar faces effectively [S3, unofficial]. Subdividing all quadrilaterals increases polygon count significantly but maintains fragment count [S3, unofficial].
- **Scaling:** Scales with the number of cells and the complexity of the grid topology. View-dependent subdivision adds overhead per frame [S3, unofficial].
- **Strengths:** Works directly on general grid topology without resampling. Handles non-planar faces and visibility cycles [S2, book][S3, unofficial]. Compatible with standard graphics hardware [S1][S3, unofficial].
- **Limitations:** Approximations in perspective views (linear interpolation of $\tau$ and color). Inconsistent with analytic integration unless strict conditions are met [S3, unofficial]. Increased polygon count if all quadrilaterals are subdivided [S2, book][S3, unofficial].
- **When to Use:** Curvilinear or irregular grids with non-planar faces where direct ray tracing is difficult [S3, unofficial].
- **When Not to Use:** When high precision analytic integration is required and hardware approximations are unacceptable [S2, book].

## Background
- **Origin:** Developed for volume rendering of curvilinear and unstructured grids [S1][S3, unofficial]. Based on cell projection methods [S3, unofficial].
- **History:** Extended from methods assuming planar faces to handle non-planar quadrilateral faces [S3, unofficial]. Uses concepts from the Shirley and Tuchman method [S2, book][S3, unofficial] and BSP-MPVO sorting [S2, book][S3, unofficial].
- **Usage:** Used in scientific visualization for data on curvilinear grids, such as fluid dynamics simulations or structural mechanics [S1][S3, unofficial].
