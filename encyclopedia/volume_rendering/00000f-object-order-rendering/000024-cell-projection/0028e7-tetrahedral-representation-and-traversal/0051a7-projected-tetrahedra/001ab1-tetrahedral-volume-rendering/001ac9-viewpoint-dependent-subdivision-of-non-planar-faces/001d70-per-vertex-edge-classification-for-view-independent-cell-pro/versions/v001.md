# Per-vertex edge classification for view-independent cell projection

Also called: Edge classification for cell projection

## Overview
This method resolves rasterization artifacts in view-independent cell projection by ensuring that at least one vertex on a shared edge carries the correct visibility classification of the adjacent face. It addresses defects caused by per-vertex computations where edge visibility might be ambiguous, affecting the entire edge during rasterization. It differs from [Viewpoint-dependent subdivision of non-planar faces](835-viewpoint-dependent-subdivision-of-non-planar-faces.md) by avoiding viewpoint-dependent geometric subdivision, instead relying on vertex attributes to propagate visibility information across shared edges in a view-independent manner.

## How it works
**Inputs:**
- Vertex positions of the tetrahedron faces.
- Normals of the faces.
- Adjacency information (which faces share an edge).
- View direction (for determining "entering" vs "exiting" faces).

**Outputs:**
- Modified texture coordinates (specifically the $r$ component) for each vertex, encoding the visibility classification of adjacent faces.

**Data Structures:**
- Each vertex stores standard attributes (position, normal) plus additional texture coordinates.
- Specifically, the $r$ texture coordinate is used to encode the classification of the adjacent face sharing an edge.

**Steps:**
1. **Define Edge Directions:** Utilize the counterclockwise winding order of each face to define a directed edge for each vertex. For a face with vertices $v_0, v_1, v_2$, each vertex $v_i$ is considered the start of the edge from $v_i$ to $v_{i+1 \pmod 3}$.
2. **Supply Adjacent Face Normal:** For each directed edge starting at vertex $v$, supply the normal of the adjacent face sharing that edge as a vertex attribute to $v$. This allows the vertex shader to access the geometry of the neighboring face.
3. **Check for Entering Face:** In the vertex program, determine if the adjacent face is "potentially entering" relative to the view direction. This is typically done by checking the dot product of the view direction and the adjacent face normal.
4. **Modify Texture Coordinate:** If the adjacent face is potentially entering, set the $r$ texture coordinate of the start vertex to a large positive value. If not, leave it unchanged (or set to 0, depending on the base classification scheme). This ensures that the edge classification is correctly propagated during rasterization.

**Example:**
Consider two adjacent faces $f_0$ and $f_1$ sharing an edge between vertices $v_2$ and $v_3$.
- For face $f_1$, vertex $v_3$ is the start of the edge from $v_3$ to $v_2$. The vertex program checks if $f_1$ is entering. If so, it sets the $r$ coordinate of $v_3$ to a large positive value. The $r$ coordinate of $v_2$ is not modified for $f_1$.
- For face $f_0$, vertex $v_2$ is the start of the edge from $v_2$ to $v_3$. The vertex program checks if $f_1$ (the adjacent face) is entering. If so, it modifies the $r$ component of $v_2$. This ensures that the visibility information from $f_1$ is correctly applied to the edge during rasterization of $f_0$.

**Pitfalls:**
- **Unclassified Endpoint:** One endpoint of the edge may remain unclassified. To fully classify both endpoints, each vertex would need normals of all three remaining faces, requiring more per-vertex parameters. This is considered negligible as it affects at most one pixel per tetrahedron at singular positions.
- **Precision Issues:** Ensure the "large positive value" is sufficiently large to distinguish from valid texture coordinates but not so large as to cause precision issues in rasterization.

## Operating characteristics
- **Time Complexity:** $O(1)$ per vertex, as it involves simple dot products and conditional assignments.
- **Memory Complexity:** $O(1)$ per vertex, requiring only one additional texture coordinate component ($r$) per vertex.
- **Strengths:** View-independent, avoids complex geometric subdivision, minimal additional memory overhead.
- **Limitations:** May result in minor classification errors at singular positions (at most one pixel per tetrahedron).

## Background
This method is part of the hardware-based view-independent cell projection approach, which aims to render curvilinear grids efficiently on modern graphics hardware. It addresses the limitations of per-fragment classification by using per-vertex attributes to propagate visibility information. The technique was introduced by Weiler and Kraus in their work on hardware-based view-independent cell projection.
