# Projected Tetrahedra

Also called: PT algorithm, Shirley and Tuchman, Shirley and Tuchman's algorithm, Shirley and Tuchman's projected tetrahedra, Shirley-Tuchman Method

## Overview
Projected Tetrahedra (PT) is an object-order volume rendering technique that projects volumetric primitives, specifically tetrahedra, onto the 2D image plane to leverage hardware-accelerated rasterization [S1, S2, S3, unofficial][S4, S6, S7][S8, S9, S10, unofficial][S11][S12, unofficial][S14, S16][S17, S18, unofficial]. It solves the problem of rendering unstructured tetrahedral grids by decomposing each 3D cell into a set of partially transparent 2D triangles, which are then composited in back-to-front order [S1, S2, unofficial][S4, S6][S8, S9, S10, unofficial][S11][S12, unofficial][S14, S16][S17, S18, unofficial]. Unlike [Tetrahedral Volume Rendering](820-tetrahedral-volume-rendering.md), which often relies on ray casting, PT uses explicit geometric projection and scan-conversion [S2, unofficial][S4, S6, S7][S12, unofficial][S14, S16]. It differs from [GPU-based Projected Tetrahedra](7484-gpu-based-projected-tetrahedra.md) in that the original PT algorithm performs sorting and projection in software, whereas later variants offload these steps to the GPU [S4, S7][S12, unofficial][S14, S16].

## How it works
**Inputs and Outputs:**
*   **Input:** A tetrahedral mesh $M_T$ where each vertex $V_i$ has a scalar value $s_i$ [S1, S2, unofficial][S4, S6, S7][S8, S12, unofficial][S14, S16].
*   **Output:** A 2D image with color and opacity values for each pixel [S1, S2, unofficial][S4, S6, S7][S8, S9, S10, unofficial][S11][S12, unofficial][S14, S16][S17, S18, unofficial].

**Data Structures:**
*   **Tetrahedron:** Defined by four vertices $\{V_0, V_1, V_2, V_3\}$ [S12, unofficial][S14].
*   **Basis Graph:** A fixed topology of 5 vertices used in GPU implementations to handle all projection classes uniformly: the 4 real vertices plus 1 "phantom" vertex $V_4'$ [S12, unofficial][S14][S17, unofficial]. The topology is drawn as a `GL_TRIANGLE_FAN` starting at $V_4'$ [S12, unofficial][S14].
*   **Classification Texture:** A 1D texture (8 bits per component) mapping test permutations to projection class and vertex order [S7].
*   **Vertex Texture:** Stores vertex coordinates (RGB) and scalar values (A) as RGBA texels [S7].
*   **Tetrahedral Texture:** Stores one tetrahedron per texel, containing four indices to retrieve vertices from the Vertex Texture [S7].

**Steps:**

1.  **Decomposition:** Decompose the volumetric data into tetrahedral cells. For regular volumes (cubes), subdivide each cell into 5 tetrahedra to avoid cracks, ensuring adjacent cells use opposite rotational states [S2, S8, S13, S19, unofficial].
2.  **Sorting:** Sort the tetrahedra in back-to-front visibility order relative to the eyepoint. This is typically done by sorting centroids, which is an approximation [S1, unofficial][S4, S7, S11][S12, unofficial][S14][S17, unofficial]. Exact sorting requires algorithms like MPVO [S7][S10, unofficial].
3.  **Projection and Classification:** For each tetrahedron, project its vertices to screen space. Classify the projection into one of four cases based on the visibility of its faces relative to the viewpoint [S2, unofficial][S6, S7][S8, S12, unofficial][S14][S18, unofficial].
    *   **Class 1:** All 4 faces visible (+ + + +). Decomposes into 3 triangles [S6, S7][S8, S12, unofficial].
    *   **Class 2:** 3 faces visible, 1 hidden (+ + + -). Decomposes into 4 triangles [S6, S7][S8, S12, unofficial].
    *   **Class 3 & 4:** Degenerate cases (2 or 1 face visible) where a vertex projects onto an edge or vertex. Handled by creating zero-area triangles or mapping to Class 1/2 logic [S6, S7][S8, S12, unofficial].
    *   **Classification Logic (GPU):** Compute vectors in screen space: $\vec{vec1} = V_1 - V_0$, $\vec{vec2} = V_2 - V_0$, $\vec{vec3} = V_3 - V_0$. Compute cross products: $cross1.z = (\vec{vec1} \times \vec{vec2})_z$, $cross2.z = (\vec{vec1} \times \vec{vec3})_z$, $cross3.z = (\vec{vec2} \times \vec{vec3})_z$ [S12, unofficial]. Determine boolean tests:
        *   $test1 = (cross1.z \times cross2.z < 0)$ [S12, unofficial]
        *   $test2 = (cross1.z \times cross3.z > 0)$ [S12, unofficial]
        *   $test3 = (\text{distance}(V_0, \text{middle}) - \text{distance}(V_0, I)) > 0$, where $I$ is the intersection point [S12, unofficial]
        *   $test4 = (cross1.z > 0)$ [S12, unofficial]
        These tests map to one of 14 cases (Class 1-4) via a lookup table [S7][S12, unofficial].
4.  **Thick Vertex Calculation:** Identify the "thick vertex," the point on the ray segment traversing the maximum distance through the tetrahedron [S6][S12, unofficial][S14][S18, unofficial].
    *   For Class 2, it is the intersection of front and back edges [S6][S18, unofficial].
    *   For other classes, it is one of the projected vertices [S6].
    *   Calculate the thickness $l$, the distance traversed by the ray segment within the tetrahedron [S6, S7][S8, unofficial][S14, S16].
5.  **Color and Opacity Computation:** Compute scalar values at the ray's entry ($s_f$) and exit ($s_b$) points [S6][S8, unofficial][S16].
    *   Thin vertices have $s_f = s_b = s_v$ (projected scalar value) [S6][S8, unofficial].
    *   Thick vertices require interpolation of $s_f$ and $s_b$ from thin vertices [S6][S8, unofficial].
    *   Compute opacity $\alpha$ and color $C$ using a transfer function [S6, S7, S14].
        *   Opacity: $\alpha = 1 - e^{-\tau_{avg} l}$, where $\tau_{avg}$ is the average extinction coefficient at $s_f$ and $s_b$, and $l$ is the thickness [S6, S7].
        *   Color: Map scalar $s$ to chromaticity $C(s)$ and extinction $\tau(s)$ via a lookup table [S6, S7, S14].
        *   Approximate exit scalar: $s_b = s_f + (\bar{g} \cdot \bar{d})l$, where $\bar{g}$ is the gradient, $\bar{d}$ is the viewing direction, and $l$ is the length [S16].
6.  **Rasterization:** Map the tetrahedron vertices to the basis graph topology. The GPU vertex program transforms vertices, determines the class, calculates the phantom vertex coordinates, and multiplexes results to the correct output vertex [S12, unofficial][S14]. Render the resulting triangles as a fan [S7][S12, unofficial][S14].
7.  **Compositing:** Composite the triangles into the framebuffer in back-to-front order using the Porter-Duff over operator [S1, S2, unofficial][S6, S7][S9, S10, unofficial][S11][S12, unofficial][S14, S16][S17, S18, unofficial].
    *   $I_{new} = \alpha C + (1 - \alpha) I$, where $I$ is the previous framebuffer color, $C$ is the fragment color, and $\alpha$ is the fragment opacity [S6, S7].

**Pseudocode:**

```python
def project_tetrahedra(tetrahedra, view_matrix, projection_matrix, transfer_function):
    # Step 1: Sort tetrahedra by centroid depth (back-to-front)
    sorted_tetrahedra = sort_by_centroid_depth(tetrahedra, view_matrix)
    
    # Initialize framebuffer
    framebuffer = initialize_framebuffer()
    
    for tet in sorted_tetrahedra:
        # Step 2: Project vertices to screen space
        screen_vertices = []
        for v in tet.vertices:
            world_pos = v.position
            clip_pos = projection_matrix * view_matrix * world_pos
            screen_pos = clip_pos.xy / clip_pos.w
            screen_vertices.append({
                'pos': screen_pos,
                'scalar': v.scalar,
                'world_pos': world_pos
            })
            
        # Step 3: Classify projection
        v0, v1, v2, v3 = screen_vertices
        vec1 = v1.pos - v0.pos
        vec2 = v2.pos - v0.pos
        vec3 = v3.pos - v0.pos
        
        cross1_z = cross_product_z(vec1, vec2)
        cross2_z = cross_product_z(vec1, vec3)
        cross3_z = cross_product_z(vec2, vec3)
        
        test1 = (cross1_z * cross2_z < 0)
        test2 = (cross1_z * cross3_z > 0)
        # test3 and test4 require intersection logic, simplified here
        test3 = False 
        test4 = (cross1_z > 0)
        
        class_id = lookup_class(test1, test2, test3, test4)
        
        # Step 4: Determine thick vertex and thickness
        thick_vertex_idx, thickness = compute_thick_vertex_and_thickness(tet, screen_vertices, class_id)
        
        # Step 5: Compute color and opacity for vertices
        # Thin vertices: zero opacity, original color
        # Thick vertex: computed opacity and average color
        vertex_colors = []
        vertex_opacities = []
        
        for i, sv in enumerate(screen_vertices):
            if i == thick_vertex_idx:
                # Interpolate s_f and s_b for thick vertex
                s_f, s_b = interpolate_entry_exit_scalars(tet, sv.world_pos, thickness)
                tau_avg = (transfer_function.tau(s_f) + transfer_function.tau(s_b)) / 2
                alpha = 1.0 - math.exp(-tau_avg * thickness)
                color = transfer_function.color((s_f + s_b) / 2.0)
            else:
                alpha = 0.0
                color = transfer_function.color(sv.scalar)
            
            vertex_colors.append(color)
            vertex_opacities.append(alpha)
            
        # Step 6: Rasterize triangles based on class
        triangles = decompose_into_triangles(class_id, screen_vertices)
        
        for tri in triangles:
            # Interpolate color and opacity across triangle
            # Composite back-to-front
            for fragment in rasterize_triangle(tri, vertex_colors, vertex_opacities):
                framebuffer.composite(fragment.color, fragment.opacity)
                
    return framebuffer.image

def compute_thick_vertex_and_thickness(tet, screen_vertices, class_id):
    # Simplified logic for Class 1 and 2
    if class_id == 1:
        # Thick vertex is one of the projected vertices
        # Find the vertex with max depth or specific geometric property
        return find_thick_vertex_class1(tet, screen_vertices)
    elif class_id == 2:
        # Thick vertex is intersection of front and back edges
        return find_thick_vertex_class2(tet, screen_vertices)
    else:
        # Degenerate cases
        return 0, 0.0
```

## Subtopics

### [Two-Pass GPU Approach](1339-two-pass-gpu-approach.md)
Efficient ray-casting for tetrahedral meshes using fragment shaders and pre-integration, offloading projection and classification to the GPU.

### [Tetrahedral Strips and Fans](1389-tetrahedral-strips-and-fans.md)
Graphics primitives that reduce CPU-GPU bandwidth by minimizing vertices transmitted per tetrahedron, achieving rates near 1.2 vertices/tetrahedron.

### [Cell Projection of Tetrahedral Meshes (Data Transfer Optimization)](1499-cell-projection-of-tetrahedral-meshes-data-transfer-optimiza.md)
Uses view-independent mesh descriptions and preprocessing to optimize data transfer, contrasting with PT's continuous triangle stream.

### [Point-based Projected Tetrahedra](5527-point-based-projected-tetrahedra.md)
Approximates tetrahedra with point primitives, decoupling footprint generation from compositing, robust against malformed tetrahedra.

### [Hardware-Assisted Projection](5625-hardware-assisted-projection.md)
Offloads geometric decomposition and scan conversion to hardware shaders, enabling single-pass rendering and avoiding CPU-side sorting.

### [Sorting-free Projected Tetrahedra](7393-sorting-free-projected-tetrahedra.md)
Uses stochastic color composition to approximate back-to-front accumulation, eliminating explicit visibility sorting.

### Screen Space Area Calculation
Calculates the projected area of a tetrahedron in normalized screen space using cross products to determine refinement criteria or culling. Triangles cover the total area twice, and cross products yield wedge areas (twice triangle area), necessitating division by 4 [S20, unofficial].

### Early Tetrahedron Termination
Reduces processed tetrahedra by leveraging a summed-area table to accumulate and compare opacity on the rendering phase, after sorting into unobstructed layers. Provides >10% performance gain for datasets with >1 million tetrahedra [S17, unofficial].

### Hybrid Screen-Space Projection Ray Casting
Projects tetrahedra to screen space to determine visibility order, then casts rays through the resulting 2D triangle list to fetch scalar values. Assumes linear opacity and intensity contribution. Rendering time is 11s for 256^2 viewport, 100s for 1024^2 on SGI Power Challenge [S1, unofficial].

### Alternating Tetrahedral Decomposition
Uses two alternating decomposition schemes ($C_{even}$ and $C_{odd}$) for cubic cells to prevent T-junctions and discontinuities between adjacent cells. Classifies cells based on $(C_x + C_y + C_z) \bmod 2$ [S19, unofficial].

### Min-Volume Ellipsoid Approximation
Approximates a tetrahedron's projection by finding the enclosing ellipsoid with the smallest volume, used to simplify constrained minimization over integrals. Transforms rays using the tetrahedron's transformation matrix to cull fragments on the GPU [S21].

### Projected Tetrahedra with MPVONC
Combines PT with the MPVO with Non-Convexities (MPVONC) sorting algorithm. MPVONC is not exact but fast and "accurate enough," though PT has accuracy issues with perspective projection and compositing on GPUs [S10, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear in the number of tetrahedra [S12, unofficial]. Sorting is a bottleneck, taking ~2 seconds per viewpoint change [S1, unofficial].
*   **Memory Complexity:** 16 bytes per element of tetrahedral and vertex textures; approx. 20 bytes per tetrahedron (assuming 4 tets per vertex) [S7]. Per-vertex data consists of 15 float values (12 vertices * 15 attributes * 4 bytes = 720 bytes/tetrahedron) [S16].
*   **Performance:** Achieves interactive rates (up to 2.0 M Tets/s) on GPU implementations [S6, S7]. Software implementations are non-interactive [S4].
*   **Strengths:** Efficient for cells projecting to many pixels; leverages hardware rasterization; no topology information storage required [S2, S8, S12, unofficial][S14].
*   **Limitations:** Requires visibility sorting, which is time-consuming and not always possible (cycles) [S5, book][S17, unofficial]. Linear interpolation of opacity causes Mach banding artifacts [S15, book][S18, unofficial]. Edge artifacts (dark seams) occur due to zero interpolation weights at edges [S16]. Sorting centroids is not 100% accurate [S7].
*   **When to use:** Interactive visualization of unstructured tetrahedral meshes where hardware acceleration is available [S2, unofficial][S7][S12, unofficial].
*   **When not to use:** When exact visibility sorting is critical and sorting is too expensive, or when sub-pixel accuracy is required without point-based approximations [S15, book][S21].

## Background
Projected Tetrahedra was proposed by Shirley and Tuchman in 1990 [S1, S2, S3, unofficial][S6, S7, S14]. It was one of the first algorithms for projecting cells of unstructured grids, designed to handle non-uniform grids [S1, S3, unofficial]. The method was later adapted for GPU implementation using vertex shaders (GATOR algorithm) and fragment shaders [S6, S7][S12, unofficial][S14, S16]. It is widely used in volume visualization of medical images, geological data, and fluid simulations [S7].
