# Röttger 3D Texture Mapping

Also called: Hardware-Assisted Projected Tetrahedra with 3D Texture Mapping, Pre-integrated Volume Rendering for Tetrahedra, Röttger et al. 3D Texture Mapping

## Overview
Röttger 3D Texture Mapping is an extension of the projected tetrahedra algorithm that enables hardware-accelerated rendering of volumetric data with arbitrary transfer functions [S1, unofficial][S2, unofficial][S3, book]. It solves the artifact problem inherent in linear opacity interpolation by using a pre-integrated texture lookup to compute the exact transmittance along a ray segment [S2, unofficial][S3, book]. Unlike siblings that rely on linear approximations or unsorted hexahedra, this method requires back-to-front sorting of tetrahedra but provides accurate results for non-linear transfer functions by approximating a 3D lookup table with 2D texture hardware [S1, unofficial][S2, unofficial][S3, book].

## How it works
**Inputs and Outputs**
*   **Input:** A tetrahedral mesh representing the volume data, a camera viewpoint, and an arbitrary scalar-to-color/opacity transfer function $T(\tau)$.
*   **Output:** A 2D image with correct alpha compositing.

**Data Structures**
*   **Pre-integration Texture:** A 2D texture map approximating the 3D integral. The texture stores pre-computed color and opacity values.
*   **Vertex Attributes:** For each projected triangle (face of the tetrahedron), the following attributes are computed and passed to the rasterizer:
    *   Entry scalar value $\tau_{in}$ (at the front face intersection).
    *   Exit scalar value $\tau_{out}$ (at the back face intersection).
    *   Segment length $l$ (distance through the tetrahedron).

**Numbered Steps**
1.  **Sorting:** Sort all tetrahedra in back-to-front order relative to the viewpoint [S2, unofficial][S3, book].
2.  **Projection:** Project the 3D tetrahedra vertices to screen space [S2, unofficial][S3, book].
3.  **Attribute Computation:** For each tetrahedron, determine the entry and exit points of the ray passing through the cell. Compute $\tau_{in}$, $\tau_{out}$, and the path length $l$ [S2, unofficial][S3, book].
4.  **Texture Coordinate Generation:** Generate texture coordinates for the 2D texture lookup. Two coordinates correspond to $\tau_{in}$ and $\tau_{out}$, and the third dimension (mapped to the 2D texture via approximation) corresponds to the distance $l$ [S2, unofficial][S3, book].
5.  **Rasterization and Lookup:** Rasterize the projected triangles. For each fragment, sample the pre-integrated texture using the interpolated $\tau_{in}$, $\tau_{out}$, and $l$ to retrieve the pre-computed color and opacity [S2, unofficial][S3, book].
6.  **Compositing:** Composite the fragments using hardware blending operations in back-to-front order [S2, unofficial][S3, book].

**Formulas**
The pre-integration texture stores the result of the volume rendering integral for a segment of length $l$ with entry value $\tau_{in}$ and exit value $\tau_{out}$:
$$ C(\tau_{in}, \tau_{out}, l) = \int_0^l T(\tau(s)) e^{-\int_0^s \tau(u) du} ds $$
$$ \alpha(\tau_{in}, \tau_{out}, l) = 1 - e^{-\int_0^l \tau(s) ds} $$
Where $T(\tau)$ is the transfer function and $\tau(s)$ is the scalar value along the ray [S2, unofficial][S3, book].

**Parameters**
*   **Texture Resolution:** Not given in the sources.
*   **Approximation:** The 3D texture map is approximated using two-dimensional texture mapping [S2, unofficial][S3, book].

**Edge Cases and Pitfalls**
*   **Sorting:** Incorrect sorting leads to incorrect alpha compositing [S2, unofficial][S3, book].
*   **Approximation Error:** The 2D approximation of the 3D texture may introduce artifacts if the mapping is not carefully designed [S2, unofficial][S3, book].

**Pseudocode**
```python
# Pre-computation phase
def precompute_texture(transfer_function, max_length, num_samples):
    """
    Pre-compute the 2D texture map for arbitrary transfer functions.
    The texture stores (color, opacity) for given (tau_in, tau_out, length).
    """
    texture = empty_2d_texture()
    for tau_in in range(0, max_tau, step):
        for tau_out in range(0, max_tau, step):
            for length in range(0, max_length, step):
                # Compute the integral for this segment
                color, opacity = integrate_segment(transfer_function, tau_in, tau_out, length)
                # Store in texture using mapped coordinates
                texture[map(tau_in), map(tau_out, length)] = (color, opacity)
    return texture

def render_tetrahedra(tetrahedra, camera, precomputed_texture):
    """
    Render tetrahedra using hardware-assisted projection and 3D texture mapping.
    """
    # Sort tetrahedra back-to-front
    sorted_tetrahedra = sort_back_to_front(tetrahedra, camera)
    
    for tet in sorted_tetrahedra:
        # Project vertices to screen space
        screen_vertices = project(tet.vertices, camera)
        
        # Compute entry and exit scalar values and length
        # This requires ray-tetrahedron intersection
        tau_in, tau_out, length = compute_ray_attributes(tet, camera)
        
        # Generate texture coordinates
        # Two coords for tau_in, tau_out; third for length (approximated to 2D)
        tex_coords = generate_tex_coords(tau_in, tau_out, length)
        
        # Rasterize the triangle with these attributes
        rasterize(screen_vertices, tex_coords, precomputed_texture)
```

## Operating characteristics
*   **Time Complexity:** Dominated by sorting ($O(N \log N)$) and rasterization ($O(P)$ where $P$ is pixel count). Texture lookup is $O(1)$.
*   **Memory Complexity:** Requires storage for the pre-integration texture. Size depends on the resolution of $\tau_{in}$, $\tau_{out}$, and $l$.
*   **Strengths:** Supports arbitrary transfer functions; avoids Mach bands and other artifacts from linear interpolation; leverages hardware acceleration.
*   **Limitations:** Requires sorting of tetrahedra; 3D texture approximation may introduce errors; memory usage for the texture can be high.
*   **When to use:** When accurate rendering with arbitrary transfer functions is required and sorting overhead is acceptable.
*   **When not to use:** When real-time performance is critical and sorting is too expensive, or when only linear transfer functions are needed.

## Background
The method was introduced by Röttger et al. [RKE00] as an extension of the projected tetrahedra algorithm [ST90] [S1, unofficial]. It builds on the concept of pre-integrated volume rendering to allow arbitrary transfer functions by creating a 3D texture map for hardware interpolation along the ray [S2, unofficial][S3, book]. The 3D texture map is approximated using two-dimensional texture mapping to leverage existing graphics hardware [S2, unofficial][S3, book].
