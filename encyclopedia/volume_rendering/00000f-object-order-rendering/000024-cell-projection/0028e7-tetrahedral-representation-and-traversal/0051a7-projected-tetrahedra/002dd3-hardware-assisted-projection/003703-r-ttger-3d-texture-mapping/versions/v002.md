# Röttger 3D Texture Mapping

Also called: Hardware-Assisted Projected Tetrahedra with 3D Texture Mapping, Pre-integrated Volume Rendering for Tetrahedra, Röttger et al. 3D Texture Mapping

## Overview
Röttger 3D Texture Mapping is an extension of the projected tetrahedra algorithm that enables hardware-accelerated, accurate rendering of volumetric data using 3D texture mapping [S1, unofficial]. It solves the problem of applying arbitrary, non-linear transfer functions during volume rendering by pre-computing the integration results into a texture map, allowing the graphics hardware to interpolate opacity correctly and avoid artifacts like Mach bands [S2, unofficial]. Unlike siblings that may restrict transfer functions to linear models or require complex software sorting, this method leverages 2D texture hardware to approximate the 3D pre-integration lookup, supporting arbitrary transfer functions with minimal runtime cost [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A tetrahedral mesh representing the volume, scalar field values at vertices, and an arbitrary transfer function mapping scalar values to color and opacity.
*   **Output:** A 2D image with correct per-pixel opacity and color, accounting for the non-linear integration of the volume integral along the ray segment within each tetrahedron.

**Data Structures:**
*   **Pre-integration Texture:** A 3D texture map is created to store the results of the volume integral.
    *   **Layout:** The texture has three coordinates. Two coordinates correspond to the scalar values (extinction coefficients) at the cell entry and exit points. The third coordinate maps to the distance (thickness) through the cell [S2, unofficial].
    *   **Approximation:** To utilize standard 2D texture mapping hardware, the 3D texture map is approximated using two-dimensional texture mapping [S2, unofficial].

**Steps:**
1.  **Pre-computation (Offline):**
    *   For a given transfer function, compute the volume integral analytically or numerically for all combinations of entry value, exit value, and segment length.
    *   Store these results in a 3D texture map where the axes represent: entry value, exit value, and distance through the cell [S2, unofficial].
    *   Approximate this 3D texture for 2D hardware access [S2, unofficial].

2.  **Projection and Rasterization:**
    *   Project the 3D tetrahedra onto the 2D screen space [S1, unofficial].
    *   Rasterize the projected tetrahedra into fragments [S1, unofficial].

3.  **Interpolation and Lookup:**
    *   Interpolate the scalar values (extinction coefficients) at the vertices of the tetrahedron across the fragment [S1, unofficial].
    *   Determine the entry and exit scalar values for the ray segment passing through the tetrahedron.
    *   Determine the geometric thickness (segment length) of the ray within the tetrahedron [S1, unofficial].
    *   Use the entry value, exit value, and thickness as texture coordinates to sample the pre-integrated texture map [S2, unofficial].

4.  **Color and Opacity Calculation:**
    *   The sampled value from the texture map provides the accumulated opacity and color contribution for that segment, effectively performing the non-linear integration [S2, unofficial].
    *   Parts of the volume integral depending on the segment length are linearly approximated by modulating vertex colors [S1, unofficial].
    *   The remaining parts, which depend only on textural coordinates (entry/exit values), are tabulated in the texture map [S1, unofficial].

5.  **Compositing:**
    *   Composite the fragments using alpha blending (Porter-Duff over operation) in back-to-front order to ensure correct accumulation [S1, unofficial].

**Pseudocode:**
```python
# Pre-computation phase (offline)
def precompute_integration(transfer_function, num_entries, num_exits, num_lengths):
    """
    Computes the volume integral for all combinations of entry/exit values and lengths.
    Returns a 3D texture map.
    """
    texture_3d = allocate_3d_texture(num_entries, num_exits, num_lengths)
    for i in range(num_entries):
        entry_val = i / (num_entries - 1)
        for j in range(num_exits):
            exit_val = j / (num_exits - 1)
            for k in range(num_lengths):
                length = k / (num_lengths - 1)
                # Compute integral of transfer_function along ray of length 'length'
                # with extinction varying from entry_val to exit_val
                result = compute_volume_integral(entry_val, exit_val, length, transfer_function)
                texture_3d[i, j, k] = result
    return texture_3d

# Rendering phase (per frame)
def render_tetrahedron(tet, texture_3d_approx, screen_width, screen_height):
    """
    Renders a single tetrahedron using hardware-assisted projection.
    """
    # 1. Project vertices to screen space
    screen_verts = [project_to_screen(v) for v in tet.vertices]
    
    # 2. Rasterize and process fragments
    for fragment in rasterize(screen_verts):
        # 3. Interpolate scalar values at fragment position
        entry_val = interpolate_scalar(fragment, tet.entry_face)
        exit_val = interpolate_scalar(fragment, tet.exit_face)
        
        # 4. Calculate geometric thickness
        thickness = calculate_ray_segment_length(fragment, tet)
        
        # 5. Normalize coordinates for texture lookup
        # Map entry_val, exit_val, thickness to [0, 1] range based on pre-computation bounds
        u = normalize(entry_val)
        v = normalize(exit_val)
        w = normalize(thickness)
        
        # 6. Sample pre-integrated texture
        # Approximate 3D lookup with 2D texture mapping as per [S2, unofficial]
        # The exact mapping depends on the approximation strategy
        color, opacity = texture_3d_approx.sample(u, v, w)
        
        # 7. Modulate vertex colors for linear parts of integral [S1, unofficial]
        # This step handles the linear approximation of length-dependent parts
        final_color = modulate_vertex_colors(color, thickness)
        
        # 8. Output fragment
        write_fragment(fragment.screen_pos, final_color, opacity)
```

**Parameters:**
*   **Texture Resolution:** Not given in the sources.
*   **Transfer Function:** Arbitrary, defined by the user.

**Edge Cases and Pitfalls:**
*   **Approximation Error:** The approximation of the 3D texture map using 2D texture mapping may introduce artifacts if not carefully designed [S2, unofficial].
*   **Sorting:** Correct compositing requires back-to-front sorting of tetrahedra, which can be computationally expensive [S1, unofficial].
*   **Precision:** Linear interpolation of transparency can cause Mach bands if not handled by the pre-integration texture [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Pre-computation is offline and depends on the resolution of the texture map. Runtime complexity is dominated by rasterization and texture lookup, which is efficient on modern hardware.
*   **Memory Complexity:** Requires storage for the pre-integrated 3D texture map. The size depends on the resolution of the entry, exit, and length dimensions.
*   **Strengths:** Supports arbitrary transfer functions; hardware-accelerated; avoids artifacts from linear interpolation of opacity.
*   **Limitations:** Requires pre-computation; 3D texture approximation may have limitations; sorting requirement for correct compositing.
*   **When to use:** When arbitrary transfer functions are needed and hardware acceleration is desired.
*   **When not to use:** When memory is constrained or pre-computation time is prohibitive.

## Background
Röttger 3D Texture Mapping was introduced by Röttger et al. [RKE00] as an extension of the projected tetrahedra algorithm [ST90] for hardware-accelerated and accurate rendering of volumetric data [S1, unofficial]. It builds on the concept of pre-integrated volume rendering, allowing for arbitrary transfer functions by creating a 3D texture map to interpolate along the ray between cell entry and exit points [S2, unofficial]. The method was developed to address the limitations of earlier hardware-assisted techniques that could only handle linear transfer functions without artifacts [S2, unofficial].
