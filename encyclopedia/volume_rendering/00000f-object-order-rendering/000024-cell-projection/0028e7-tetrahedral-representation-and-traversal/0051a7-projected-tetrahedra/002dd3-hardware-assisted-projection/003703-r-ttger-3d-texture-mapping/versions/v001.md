# Röttger 3D Texture Mapping

Also called: Hardware-Assisted Projected Tetrahedra with 3D Texture Mapping, Pre-integrated Volume Rendering for Tetrahedra, Röttger et al. 3D Texture Mapping

## Overview
Röttger 3D Texture Mapping is an extension of the projected tetrahedra algorithm that enables hardware-accelerated, accurate rendering of volumetric data using 3D texture mapping [S1, unofficial]. It solves the problem of applying arbitrary, non-linear transfer functions during volume integration by pre-computing the integration results into a texture map, allowing the graphics hardware to interpolate opacity and color correctly per pixel [S2, unofficial]. Unlike methods restricted to linear transfer functions, this approach supports arbitrary transfer functions without artifacts by leveraging pre-integration [S2, unofficial].

## How it works
**Inputs and Outputs**
*   **Inputs**: A tetrahedral mesh representing the volume; a user-defined transfer function mapping scalar values to color and opacity; vertex attributes (scalar values) at tetrahedron vertices.
*   **Outputs**: A 2D screen image with correct per-pixel opacity and color contributions.

**Data Structures**
*   **Pre-integration Texture**: A 3D texture map is created to store pre-computed integration results.
    *   **Layout**: The texture has three coordinates. Two coordinates correspond to the scalar values at the cell entry and exit points (front and back faces of the tetrahedron). The third coordinate maps to the distance through the cell (segment length) [S2, unofficial].
    *   **Approximation**: Although the conceptual map is 3D, it is approximated and implemented using two-dimensional texture mapping hardware to accelerate opacity interpolation [S2, unofficial].

**Steps**
1.  **Pre-computation**: Generate the pre-integration texture map. For every combination of entry value, exit value, and segment length, compute the accumulated opacity and color contribution according to the transfer function and the volume rendering integral. Store these results in the 3D texture map [S2, unofficial].
2.  **Projection**: Project the 3D tetrahedra onto the 2D screen space using view-projection matrices [S1, unofficial].
3.  **Rasterization**: Rasterize the projected tetrahedra to determine the screen-space coverage and the entry/exit points for each pixel fragment [S1, unofficial].
4.  **Interpolation**: For each fragment, determine the scalar values at the entry and exit points of the ray segment within the tetrahedron.
5.  **Lookup**: Use the entry value, exit value, and segment length as texture coordinates to sample the pre-integration texture map. This retrieves the pre-computed opacity and color contribution for that specific segment [S2, unofficial].
6.  **Modulation**: Linearly approximate parts of the volume integral that depend on the segment length by modulating the vertex colors. The remaining parts, which depend only on textural coordinates, are handled by the texture lookup [S1, unofficial].
7.  **Compositing**: Accumulate the retrieved color and opacity values across all overlapping tetrahedra to produce the final image [S1, unofficial].

**Pseudocode**
```python
# Pre-computation phase
def precompute_integration_texture(entry_values, exit_values, lengths, transfer_function):
    """
    Computes the pre-integration texture map.
    entry_values: array of scalar values at entry points
    exit_values: array of scalar values at exit points
    lengths: array of segment lengths
    transfer_function: function mapping scalar value to (color, opacity)
    """
    texture = empty_3d_texture()
    for e in entry_values:
        for x in exit_values:
            for l in lengths:
                # Compute accumulated opacity and color for the segment
                # This involves integrating the transfer function along the segment
                accumulated_color, accumulated_opacity = integrate_segment(e, x, l, transfer_function)
                texture[e, x, l] = (accumulated_color, accumulated_opacity)
    return texture

# Rendering phase
def render_tetrahedron(tetrahedron, precomputed_texture, transfer_function):
    """
    Renders a single tetrahedron using hardware-accelerated texture lookup.
    """
    # Project vertices to screen space
    screen_vertices = project_to_screen(tetrahedron.vertices)
    
    # Rasterize to find fragments
    fragments = rasterize(screen_vertices)
    
    for fragment in fragments:
        # Determine entry and exit points of the ray through the tetrahedron
        entry_point, exit_point = get_ray_cell_intersections(fragment.ray, tetrahedron)
        
        # Get scalar values at entry and exit points
        entry_value = interpolate_scalar(entry_point, tetrahedron)
        exit_value = interpolate_scalar(exit_point, tetrahedron)
        
        # Calculate segment length
        segment_length = distance(entry_point, exit_point)
        
        # Sample pre-integration texture
        # Note: In practice, the 3D texture is approximated by 2D texture mapping
        # The exact mapping of 3D coordinates to 2D texture coordinates is implementation-specific
        # but relies on the entry, exit, and length values
        color, opacity = precomputed_texture.lookup(entry_value, exit_value, segment_length)
        
        # Modulate vertex colors for linear approximation of length-dependent parts
        # [G] Specific modulation formula not detailed in sources; assumed to be part of the hardware pipeline
        final_color = modulate_vertex_colors(color, segment_length)
        
        # Composite into frame buffer
        composite_fragment(final_color, opacity, fragment)

def integrate_segment(entry_val, exit_val, length, transfer_function):
    """
    Computes the accumulated color and opacity for a segment.
    This is the core of pre-integration.
    """
    # [G] Standard volume rendering integral approximation
    # Assuming linear interpolation of scalar values along the segment
    # and integration of the transfer function
    accumulated_opacity = 0.0
    accumulated_color = (0.0, 0.0, 0.0)
    
    # Discretize the segment for integration
    num_samples = 10 # [G] Arbitrary number for illustration; sources do not specify
    step = length / num_samples
    
    transmittance = 1.0
    for i in range(num_samples):
        t = i * step
        current_val = lerp(entry_val, exit_val, t / length)
        color, opacity = transfer_function(current_val)
        
        # Accumulate color and update transmittance
        # Standard front-to-back compositing
        alpha = 1.0 - exp(-opacity * step) # [G] Approximation; sources do not give exact formula
        accumulated_color += transmittance * color * alpha
        transmittance *= (1.0 - alpha)
        accumulated_opacity += alpha * transmittance # [G] Simplified; sources do not give exact formula
        
    return accumulated_color, accumulated_opacity
```

**Edge Cases and Pitfalls**
*   **Precision**: The accuracy of the pre-integration depends on the resolution of the texture map. Insufficient resolution may lead to artifacts.
*   **Boundary Conditions**: The method assumes linear interpolation of scalar values within the tetrahedron. Non-linear variations may not be captured accurately.
*   **Hardware Limitations**: The approximation of 3D texture mapping with 2D texture hardware may introduce limitations in the range of supported transfer functions or segment lengths.

## Subtopics

### Pre-integrated Volume Rendering
A general technique where integration results are pre-computed and stored in textures. Röttger's method is a specific application of this to tetrahedral meshes. [S2, unofficial]

### Projected Tetrahedra
The base algorithm that Röttger's method extends. It projects tetrahedra to screen space and rasterizes them. [S1, unofficial]

## Operating characteristics
*   **Time Complexity**: Pre-computation is $O(N_{entry} \times N_{exit} \times N_{length})$, where $N$ are the number of discrete values for entry, exit, and length. Rendering is $O(P)$, where $P$ is the number of pixels, with constant-time texture lookups.
*   **Memory Complexity**: $O(N_{entry} \times N_{exit} \times N_{length})$ for the pre-integration texture.
*   **Measured Performance**: Not given in the sources.
*   **Strengths**: Supports arbitrary transfer functions; hardware-accelerated; avoids artifacts associated with linear transfer functions.
*   **Limitations**: Requires pre-computation; memory usage can be high for high-resolution textures; approximation of 3D texture with 2D hardware may have limitations.
*   **When to Use**: When arbitrary transfer functions are required and hardware acceleration is desired.
*   **When Not to Use**: When memory is constrained or transfer functions are simple and linear.

## Background
The method was introduced by Röttger et al. [RKE00] as an extension of the projected tetrahedra algorithm [ST90] for hardware-accelerated rendering of volumetric data [S1, unofficial]. It builds on the concept of pre-integrated volume rendering to allow for arbitrary transfer functions [S2, unofficial].
