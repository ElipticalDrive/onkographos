# Hardware-Assisted Projection

Also called: Hardware-Accelerated Projected Volume Rendering, Texture-Mapped Projected Volume Rendering

## Overview
Hardware-Assisted Projection is a family of volume rendering techniques that project 3D volumetric cells (tetrahedra, polyhedra, or hexahedra) onto the 2D image plane and utilize the graphics hardware's rasterization pipeline for scan conversion and compositing [S1, book]. It solves the problem of efficiently rendering unstructured grids by replacing irregular memory access patterns with global back-to-front sorting and hardware-accelerated interpolation [S1, book]. Unlike raycasting, which requires per-ray traversal, this method relies on the fixed-function or programmable pipeline to handle pixel coverage and blending [S1, book].

## Shared principles
The core mechanism involves projecting 3D cells into screen space, decomposing the projection into rasterizable primitives (typically triangles), and rendering them in back-to-front order [S1, book].

1.  **Sorting**: All cells must be sorted in back-to-front order relative to the viewpoint to ensure correct alpha compositing via the Porter-Duff "over" operator [S1, book].
2.  **Projection**: 3D vertices are transformed to 2D screen coordinates [S1, book].
3.  **Attribute Computation**: For each rasterizable primitive, attributes such as traversal length ($l$), entry/exit scalar values ($\tau_{in}, \tau_{out}$), or attenuation ($A$) are computed at the vertices [S1, book].
4.  **Hardware Interpolation**: The rasterizer interpolates these attributes across the screen-space primitives [S1, book].
5.  **Opacity/Intensity Evaluation**:
    *   **Linear Approximation**: If linear interpolation of transparency is used, Mach bands appear due to the non-linear relationship between thickness and opacity [S1, book].
    *   **Texture Mapping**: To avoid artifacts, hardware texture mapping is used to lookup non-linear opacity values (e.g., $T = \exp(-\int \tau ds)$) based on interpolated thickness and extinction coefficients [S1, book].
    *   **Pre-integration**: For arbitrary transfer functions, pre-integrated color and opacity are stored in texture maps (2D or 3D approximated as 2D) and sampled using interpolated entry/exit values and segment length [S1, book].
6.  **Compositing**: Fragments are composited using hardware blending operations [S1, book].

### Pre-sorted Tetrahedral Rendering
*   **Step**: Sort the cells before they are split into tetrahedra [S1, book]. Utilize 2D texture mapping hardware to accelerate opacity interpolation and provide correct per-pixel opacity values to avoid artifacts [S1, book].
*   **Pitfall**: Can only handle linear transfer functions without artifacts [S1, book].

## Background
The method originated from the need to accelerate volume visualization on unstructured grids. Stein et al. [312] (cited in [S1, book]) sorted cells before splitting into tetrahedra and used 2D texture mapping to accelerate opacity interpolation. Röttger et al. [272] (cited in [S1, book]) introduced pre-integrated volume rendering, creating a 3D texture map (approximated as 2D) to support arbitrary transfer functions by interpolating along the ray between front and back faces of a tetrahedral cell. The approach builds on the projected tetrahedra algorithm [877-projected-tetrahedra.md], which generates triangles for hardware rendering.
