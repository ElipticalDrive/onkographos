# Absorption-Only Radiography via Unsorted Hexahedron Projection

Also called: Unsorted Hexahedron Projection, Absorption-Only Radiography

## Overview
This method simulates X-ray radiographs for curvilinear hexahedral meshes by accumulating optical thickness additively, thereby eliminating the need for a global back-to-front visibility sort [S1, unofficial]. It differs from standard polyhedron projection methods [Hardware-Assisted Polyhedron Projection](1453-hardware-assisted-polyhedron-projection.md) by exploiting the commutative property of addition in the absorption-only regime ($J_\nu = 0$), allowing cells to be rendered in arbitrary order [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A curvilinear hexahedral mesh; extinction coefficients $K_\nu$ (potentially per wavelength band); camera/viewpoint parameters.
*   **Output:** A radiograph image representing the integrated attenuation (optical thickness) per pixel.

**Data Structures:**
*   **P-buffer:** A floating-point off-screen buffer (texture) storing the accumulated optical thickness $\tau_{acc}$ for each pixel. Initialized to zero.
*   **Cell Geometry:** Hexahedral cells defined by 8 vertices. Each vertex $v$ has an associated extinction coefficient $K_v$ and a pre-computed thickness $t_v$ (or segment length) derived from cell geometry.

**Algorithm Steps:**

1.  **Preprocessing (Subdivision):**
    *   For each hexahedral cell, check if it is non-degenerate and if the projection of each of its 6 faces is a convex quadrilateral.
    *   If the cell is degenerate (coinciding vertices) or has non-convex face projections, subdivide it into tetrahedra. Note: If these tetrahedra share non-planar faces with adjacent non-subdivided cells, gaps or overlaps in viewing ray segments may occur, introducing small errors in total absorption [S1, unofficial].
    *   For valid hexahedra, define triangle fans or strips for all projections using the method of Max [12]. For tetrahedra, use the method of Shirley and Tuchman [16] to divide the projection into triangle fans.

2.  **Thickness Computation (Software):**
    *   Compute the thickness $t$ for each vertex of the primitive. This is done in software using the geometry of the cell. The attenuation for a vertex is defined as the product of the extinction coefficient $K_v$ and the thickness $t$.

3.  **Rendering Passes (Unsorted Accumulation):**
    *   Since writes to output buffers are not guaranteed to be in polygon order and texture caching does not account for textures changing on the fly, the accumulated attenuation must be read from a texture [S1, unofficial].
    *   To minimize slow copies from the P-buffer to a texture, render as many non-overlapping cells as possible in a single pass.
    *   Form a logically circular list of pointers to all cells.
    *   For each cell (or group of non-overlapping cells):
        1.  Bind the current accumulated attenuation texture (initially all zeros).
        2.  Rasterize the cell's projection (triangle fans/strips).
        3.  **Fragment Program:**
            *   Interpolate the vertex attenuation values ($A_v = K_v \cdot t_v$) across the primitive.
            *   Sample the accumulated attenuation $\tau_{acc}$ from the input texture at the current pixel.
            *   Compute the new accumulated attenuation: $\tau_{new} = \tau_{acc} + A_{interpolated}$.
            *   Write $\tau_{new}$ to the floating-point P-buffer.
        4.  After rendering the batch of cells, copy the P-buffer to a texture to keep it current for the next iteration [S1, unofficial].

4.  **Final Image Generation:**
    *   After all cells are processed, the P-buffer contains the total optical thickness $\tau_{total}$ for each pixel.
    *   The final intensity $I$ is computed from the initial intensity $I_0$ (source brightness) using the Beer-Lambert law: $I = I_0 e^{-\tau_{total}}$. This step may be done in a final post-processing pass or shader.

**Formulas:**
The recurrence for absorption-only radiography ($J_\nu = 0$) is:
$$I_V[i+1] = e^{-\tau[i]} I_V[i]$$
where $I_V[i]$ is the intensity at cell $i$, and $\tau[i]$ is the optical thickness of cell $i$ [S1, unofficial].
Solving this recurrence results in a simple product of exponential terms, which is equivalent to a sum of optical thicknesses:
$$I_{final} = I_0 \prod_i e^{-\tau[i]} = I_0 e^{-\sum_i \tau[i]}$$
Thus, accumulating $\tau_{sum} = \sum_i \tau[i]$ additively is sufficient [S1, unofficial].

**Parameters:**
*   **Parallelism:** Four different X-ray wavelength bands can be accumulated in parallel using the red, green, blue, and alpha channels of the buffer [S1, unofficial].
*   **Precision:** Floating-point accuracy is required for attenuation computation. Standard framebuffer compositing operations often lack the necessary 32-bit floating-point precision, necessitating the use of a fragment program and a P-buffer [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Degenerate Cells:** Hexahedral cells with coinciding vertices must be subdivided into tetrahedra [S1, unofficial].
*   **Non-Convex Projections:** If the projection of any face is non-convex, the cell must be subdivided [S1, unofficial].
*   **Non-Planar Faces:** Subdivided tetrahedra may share non-planar faces with adjacent non-subdivided cells, leading to gaps or overlaps in viewing ray segments and small errors in total absorption [S1, unofficial].
*   **Texture Update Latency:** Copies from the P-buffer to a texture are slow. Rendering every single cell individually is impractical. Batching non-overlapping cells is necessary to maintain performance [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of cells, plus overhead for batching and texture copies. The cost of sorting is $O(1)$ (no global sort required).
*   **Memory Complexity:** $O(1)$ additional memory per pixel for the P-buffer/texture.
*   **Strengths:** Eliminates the expensive global back-to-front sort required by other polyhedron projection methods. Allows arbitrary rendering order. Supports multiple wavelength bands in parallel.
*   **Limitations:** Requires floating-point P-buffer support. Texture copying overhead can be significant if not batched. Accuracy issues may arise from non-planar faces after subdivision.
*   **When to use:** When simulating X-ray radiographs (absorption-only) for hexahedral meshes and performance is critical, and the scene allows for batching non-overlapping cells.
*   **When not to use:** When emissivity is non-zero (requires proper sorting), or when high precision is required for complex meshes where subdivision artifacts are unacceptable.

## Background
This method was developed for industrial and medical X-ray simulation where self-emission is negligible [S1, unofficial]. It builds on the polyhedron projection method [Hardware-Assisted Polyhedron Projection](1453-hardware-assisted-polyhedron-projection.md) but adapts it for the absorption-only case. The technique of projecting hexahedra directly using Max's method [12] and tetrahedra using Shirley and Tuchman's method [16] allows for efficient hardware rendering without tetrahedralization of the entire mesh, saving storage and rendering time [S1, unofficial].
