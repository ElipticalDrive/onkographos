# Projected Tetrahedra

Also called: Shirley and Tuchman, Shirley-Tuchman Method

## Overview
Projected Tetrahedra (PT) is an object-order volume rendering technique that decomposes a volume into tetrahedral cells, projects them onto the 2D image plane, and rasterizes the resulting triangles using hardware acceleration [S1, S2, S5, S6, unofficial]. It solves the problem of efficiently rendering unstructured or irregular grids (such as finite element meshes) by leveraging the graphics pipeline's scan conversion and compositing capabilities, avoiding the memory bandwidth and cache inefficiencies of ray casting [S2, S6, S11, unofficial]. Unlike [Tetrahedral Volume Rendering](820-tetrahedral-volume-rendering.md), which may use differentiable rasterization or two-pass GPU pipelines for unstructured data, standard PT generates a continuous stream of triangles in software (or via vertex shaders) that are sorted and composited [S1, S12, unofficial]. It differs from [Marching Tetrahedrons Algorithm](940-marching-tetrahedrons-algorithm.md) by rendering the volume interior (opacity/color) rather than extracting an isosurface [S2, unofficial][S14].

## How it works
The method approximates the volume rendering integral by treating each tetrahedron as a set of partially transparent polygons [S12, S13, unofficial].

### Inputs and Outputs
*   **Input:** A tetrahedral mesh $M_T$ where each vertex $V_i$ has a scalar value $s_i$ [S11, unofficial][S19]. For regular grids, cubes are decomposed into 5 or 6 tetrahedra [S2, S11, unofficial].
*   **Output:** A 2D image with color and opacity per pixel.

### Data Structures
*   **Tetrahedron:** Defined by 4 vertices $V_0, V_1, V_2, V_3$ and their scalar values $s_0, s_1, s_2, s_3$ [S17].
*   **Plane Equations:** For each face $f_i$ of the tetrahedron, a plane equation $A_i x + B_i y + C_i z + D_i = 0$ is computed to determine face visibility (front/back) relative to the viewpoint [S6, unofficial][S18, book].
*   **Basis Graph (GPU Variant):** A fixed topology of 5 vertices (4 real + 1 phantom) used to map any projection class to a `GL_TRIANGLE_FAN` [S15, unofficial][S17].

### Numbered Steps

1.  **Decomposition:** If the input is not tetrahedral, decompose each cell (e.g., cube) into tetrahedra. For 5-tetrahedron decomposition, ensure adjacent cells use opposite rotational states to avoid "cracks" (T-junctions) at shared faces [S11, S16, unofficial].
2.  **Visibility Sorting:** Sort all tetrahedra in back-to-front order relative to the viewpoint. This is typically done by sorting centroids or using circumscribing sphere tangential distances [S1, S6, unofficial][S14]. *Note: Sorting is an approximation and may cause artifacts if cells overlap significantly [S10][S13, unofficial].*
3.  **Projection and Classification:** For each tetrahedron:
    *   Transform vertices to screen space [S2, unofficial].
    *   Classify the tetrahedron into one of four projection classes based on the visibility of its faces (front/back) relative to the view vector [S11, S16, unofficial].
        *   **Class 1:** All 4 faces visible (+ + + +).
        *   **Class 2:** 3 faces visible, 1 hidden (+ + + -).
        *   **Class 3:** 2 faces visible, 2 hidden (+ + - - or + - + -). Degenerate cases of Class 1/2 [S11, S16, unofficial].
        *   **Class 4:** 1 face visible, 3 hidden (+ - - -). Degenerate case of Class 2 [S11, S16, unofficial].
    *   *GPU Implementation:* Use cross products of projected edge vectors to determine class. For example, `test1 = (vec1 x vec2).z * (vec1 x vec3).z < 0` [S15, unofficial].
4.  **Decomposition into Triangles:** Decompose the projected outline of the tetrahedron into 1 to 4 triangles based on the class [S5, S12, unofficial].
    *   Class 1 $\rightarrow$ 3 triangles.
    *   Class 2 $\rightarrow$ 4 triangles.
    *   Classes 3/4 $\rightarrow$ Handle as degenerate Class 1/2 (zero-area triangles may be generated) [S11, S15, unofficial].
    *   *GPU Implementation:* Map the 4 vertices and 1 phantom vertex to the Basis Graph topology. The vertex shader computes the phantom vertex position (the "thick vertex") and outputs the triangle fan [S15, unofficial][S17].
5.  **Ray Integration (Color/Opacity Calculation):** Compute the color and opacity for the vertices of the decomposed triangles.
    *   **Thin Vertices:** Vertices that lie on the silhouette or are projected edges. They have zero thickness along the view ray. Set opacity $\alpha = 0$ and color $C$ to the transfer function value of the scalar $s_v$ at that vertex [S2, unofficial][S9].
    *   **Thick Vertex:** The point on the ray segment traversing the maximum distance through the tetrahedron [S9].
        *   For Class 2, it is the intersection of the front and back edges [S9].
        *   For other classes, it is one of the projected vertices (or the phantom vertex in GPU variants) [S9][S15, unofficial].
        *   Compute scalar values at entry ($s_f$) and exit ($s_b$) points of the ray through the tetrahedron.
        *   Compute thickness $l$ (distance traversed) [S9, S19].
        *   Compute average extinction coefficient $\tau_{avg}$ from transfer function lookup at $s_f$ and $s_b$ [S9].
        *   Compute opacity: $\alpha = 1 - \exp(-\tau_{avg} l)$ [S9, S10].
        *   Compute color $C$ from transfer function at average scalar $(s_f + s_b)/2$ [S9, S10].
        *   *Approximation:* The original Shirley-Tuchman method uses an approximate formula for thick vertex color; exact linear interpolation requires more complex calculations [S17].
6.  **Rasterization and Compositing:**
    *   Render the triangles back-to-front using the graphics hardware [S2, S12, unofficial].
    *   Interpolate vertex colors and opacities across the triangle fragments [S19].
    *   Composite fragments using the Porter-Duff over operator:
        $$ I_{new} = \alpha C + (1 - \alpha) I_{old} $$
        where $I_{new}$ is the updated framebuffer color, $\alpha$ is fragment opacity, $C$ is fragment color, and $I_{old}$ is the previous framebuffer color [S9, S10].

### Pseudocode
```python
# Preprocessing (per viewpoint)
def preprocess(tetrahedra, viewpoint):
    # 1. Compute plane equations for each face of each tetrahedron
    for tet in tetrahedra:
        for face in tet.faces:
            face.plane = compute_plane_equation(face.vertices, viewpoint)
    
    # 2. Sort tetrahedra back-to-front (e.g., by centroid depth)
    tetrahedra.sort(key=lambda t: centroid_depth(t, viewpoint))
    return tetrahedra

def render(tetrahedra, framebuffer, transfer_function):
    for tet in tetrahedra:
        # 3. Project vertices to screen space
        screen_verts = [project(v) for v in tet.vertices]
        
        # 4. Classify tetrahedron
        # Determine face visibility (+1 front, -1 back, 0 coplanar)
        face_visibilities = []
        for face in tet.faces:
            # Dot product of view vector and face normal, or plane equation test
            vis = sign(dot(view_vector, face.normal))
            face_visibilities.append(vis)
        
        proj_class = classify(screen_verts, face_visibilities)
        
        # 5. Decompose into triangles
        triangles = decompose_tetrahedron(proj_class, screen_verts)
        
        # 6. Compute vertex attributes for triangles
        for tri in triangles:
            tri_attrs = []
            for v_idx in tri.vertices:
                if is_thick_vertex(v_idx, proj_class):
                    # Compute ray integration for thick vertex
                    s_f, s_b, l = compute_ray_integration(tet, viewpoint)
                    tau_avg = transfer_function.avg_extinction(s_f, s_b)
                    alpha = 1.0 - exp(-tau_avg * l)
                    color = transfer_function.color((s_f + s_b) / 2.0)
                else:
                    # Thin vertex
                    s_v = tet.scalar_values[v_idx]
                    alpha = 0.0
                    color = transfer_function.color(s_v)
                tri_attrs.append((color, alpha))
            
            # 7. Rasterize and composite
            rasterize_triangle(tri, tri_attrs, framebuffer)

def compute_ray_integration(tet, viewpoint):
    # Find entry and exit points of the view ray through the tetrahedron
    # This involves ray-plane intersections for the front and back faces
    entry_point, exit_point = find_ray_intersections(tet, viewpoint)
    s_f = interpolate_scalar(entry_point, tet)
    s_b = interpolate_scalar(exit_point, tet)
    l = distance(entry_point, exit_point)
    return s_f, s_b, l
```

### Parameters and Edge Cases
*   **Transfer Function:** Maps scalar $s$ to color $C(s)$ and extinction $\tau(s)$ [S9]. Pre-integrated lookup tables (e.g., $\psi$ table) can accelerate this [S9, S10].
*   **Degenerate Cases:** Classes 3 and 4 occur when a vertex projects onto an edge or another vertex. These are handled as degenerate Class 1 or 2, potentially generating zero-area triangles [S11, S15, unofficial].
*   **Precision:** Linear interpolation of opacity across polygons is not mathematically equivalent to the exponential integration, causing Mach banding artifacts [S18, book][S22, unofficial].
*   **Sorting Errors:** Centroid sorting is an approximation. Incorrect ordering leads to visual artifacts, especially for elongated cells or complex overlaps [S10, S14].

## Subtopics

### [Tetrahedral Volume Rendering](820-tetrahedral-volume-rendering.md)
A cell-projection technique for unstructured meshes that often uses a two-pass GPU pipeline or differentiable rasterization. It solves the problem of visualizing complex data with high geometric fidelity, avoiding voxel artifacts. Unlike standard PT, it may not generate a continuous stream of triangles but uses a different accumulation strategy.

### [Cell Projection of Tetrahedral Meshes (Data Transfer Optimization)](1499-cell-projection-of-tetrahedral-meshes-data-transfer-optimiza.md)
Addresses CPU-GPU bandwidth bottlenecks by using a view-independent description of the mesh. It builds a fixed set of data in preprocessing for caching, unlike standard PT which produces a continuous stream of triangles that cannot be easily batched.

### [Alternating Tetrahedral Decomposition](3183-alternating-tetrahedral-decomposition.md)
Converts hexahedral grids to tetrahedral meshes by partitioning each cube into five tetrahedra. It solves the topological consistency problem (cracks) by ensuring adjacent cells use opposite rotational states, maintaining manifold topology.

### [Point-based Projected Tetrahedra](5527-point-based-projected-tetrahedra.md)
Approximates each tetrahedron with a single point primitive, decoupling footprint generation from compositing. It avoids connectivity processing and is robust against malformed tetrahedra, unlike PT which requires triangle generation and sorting.

### [Hardware-Assisted Projection](5625-hardware-assisted-projection.md)
Projects 3D primitives to 2D and uses rasterization/texture mapping for the volume integral. It replaces irregular memory access with global sorting and hardware interpolation. It generally requires explicit depth sorting, unlike some stochastic variants.

### [Sorting-free Projected Tetrahedra](7393-sorting-free-projected-tetrahedra.md)
Approximates back-to-front accumulation using stochastic color composition, eliminating explicit visibility sorting. It avoids sorting errors and extra buffer space, advantageous for high-resolution displays where particle methods fail.

### [GPU-based Projected Tetrahedra](7484-gpu-based-projected-tetrahedra.md)
Shifts geometric classification and decomposition from CPU to GPU using vertex shaders. It solves the performance bottleneck of traditional PT by avoiding redundant projections and pre-processing, allowing interactive rates for large datasets.

### [Texture-Encoded Isosurfacing](7682-texture-encoded-isosurfacing.md)
Uses the PT decomposition step to create smaller tetrahedra and projects front/back faces to leverage a checkerboard texture for intersection computation. It sets itself apart by extracting isosurfaces rather than rendering volume opacity.

### Hybrid Screen-Space Projection Ray Casting
A hybrid method that projects tetrahedra to screen space to determine visibility order, then casts rays through the resulting 2D triangle list to fetch scalar values. It reduces intersection tests to 2D but requires updating the triangle list per viewpoint. Rendering time is ~11s for $256^2$ viewport on SGI Power Challenge [S1, unofficial].

### CellFast
A software algorithm that moves order-independent transparency and scan conversion to hardware. It eliminates software sorting but saturates the CPU in steps II-V (sorting, plane testing, projection). It writes an average of 3.4 triangles per tetrahedron [S22, unofficial].

### Min-Volume Ellipsoid Approximation
Approximates a tetrahedron's projection with the smallest enclosing ellipsoid to simplify constrained minimization. It transfers the transformation matrix to the GPU and uses ray-sphere intersection for culling. Sub-pixel tetrahedra do not require reshaping [S24].

### Projected Tetrahedra with MPVONC
Combines PT with the MPVO with Non-Convexities sorting algorithm. It is the most popular technique for unstructured meshes but is not exact, leading to visual artifacts. It is often limited to parallel projections due to implementation limitations [S13, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear in the number of tetrahedra $N$ for the projection and rasterization steps. Sorting is typically $O(N \log N)$ or $O(N)$ with bucket sort [S15, S20, unofficial].
*   **Memory Complexity:** Low compared to ray casting. No need to store topology adjacency or large ray-casting buffers. GPU implementations use textures for vertex data (e.g., 16 bytes per element) [S10][S11, unofficial].
*   **Performance:** Interactive rates (up to 2.0 M Tets/s) achievable on modern GPUs with optimized vertex shaders [S9]. Software implementations are significantly slower (seconds per frame) [S7][S20, unofficial].
*   **Strengths:** Efficient use of graphics hardware for scan conversion and compositing. Good for large datasets where one cell projects to many pixels [S2, unofficial].
*   **Limitations:** Requires visibility sorting, which is a bottleneck and can be inaccurate. Linear interpolation of opacity causes artifacts. Degenerate cases and cracks in decomposition must be handled carefully [S6, unofficial][S18, book][S22, unofficial].
*   **When to Use:** Unstructured tetrahedral meshes where interactive performance is needed and exact geometric fidelity is required.
*   **When Not to Use:** When exact opacity integration is critical (Mach bands), or when sorting is prohibitively expensive or impossible (cycles of overlapping cells) [S8, S18, book].

## Background
Projected Tetrahedra was proposed by Shirley and Tuchman in 1990 [S1, S2, S5, unofficial][S9]. It was one of the first algorithms to project cells of unstructured grids onto the image plane, leveraging the emerging capabilities of graphics hardware for polygon rendering [S1, unofficial]. The method decomposes the volume into tetrahedra, classifies their projection, and rasterizes the resulting triangles. It has been widely adopted and optimized for GPU acceleration, including vertex shader implementations (e.g., GATOR algorithm) and pre-integrated texture mapping [S9, S10][S15, unofficial].
