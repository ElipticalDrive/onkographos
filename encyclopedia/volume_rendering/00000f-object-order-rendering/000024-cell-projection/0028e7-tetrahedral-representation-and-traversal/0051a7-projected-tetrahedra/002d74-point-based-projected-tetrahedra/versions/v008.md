# Point-based Projected Tetrahedra

Also called: Hardware-Assisted Point-Based Volume Rendering, Point-Based Volume Rendering of Tetrahedral Meshes, Point-based footprint rendering

## Overview
Point-based Projected Tetrahedra (PBVR) is a technique for rendering unstructured tetrahedral meshes by approximating each tetrahedron with a single point primitive, using affine transformations to reshape the point footprint and hardware shaders for compositing [S1]. It solves the problem of efficiently visualizing large, unstructured datasets by decoupling footprint generation from compositing, thereby avoiding connectivity processing and convolution operations [S1]. Unlike its sibling [Projected Tetrahedra](877-projected-tetrahedra.md), which generates and sorts triangles, PBVR generates no additional geometry, representing each tetrahedron as a single rasterized square carrying a single scalar value [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** An unstructured tetrahedral mesh with $N$ tetrahedra. Each tetrahedron has 4 vertices. Data is either vertex-centered (scalar value per vertex) or cell-centered (scalar value per tetrahedron) [S1].
*   **Output:** A 2D image of the volume rendered at interactive framerates [S1].

**Data Structures:**
For each tetrahedron $i$ ($0 \le i < N$), the following data is stored:
1.  **Affine Transformation $T_i$:** A $4 \times 4$ matrix (or equivalent representation) that maps the unit tetrahedron $\hat{\sigma}$ to the target tetrahedron $\sigma_i$. This transformation is computed during preprocessing [S1].
2.  **Point Location $v_i$:** The 3D coordinates of the barycenter of the unit tetrahedron $\hat{\sigma}$ transformed by $T_i$. This represents the location of the point primitive [S1].
3.  **Scalar Value $s_i$:**
    *   If vertex-centered: The mean of the scalar values at the 4 vertices of $\sigma_i$ [S1].
    *   If cell-centered: The scalar value assigned to the cell [S1].
4.  **Normal Information (Optional):** Pre-computed gradients from the scalar field to support shading models [S1].

**Numbered Steps:**

1.  **Preprocessing (CPU):**
    For each tetrahedron $\sigma_i$:
    a. Define the unit tetrahedron $\hat{\sigma}$ centered at the origin, inscribed in the unit sphere.
    b. Compute the affine transformation $T_i$ such that $T_i(\hat{\sigma}) = \sigma_i$ [S1].
    c. Compute the point location $v_i = T_i(\text{barycenter}(\hat{\sigma}))$ [S1].
    d. Assign the scalar value $s_i$ based on the data type (mean of vertices or cell value) [S1].
    e. (Optional) Compute gradients for shading [S1].

2.  **Per-Frame CPU (Sorting and LOD):**
    a. Sort the $N$ points front-to-back based on the depth of their locations $v_i$ relative to the current viewpoint [S1].
    b. Determine the Level-of-Detail (LOD) for each point based on the distance from the viewpoint and the size of the tetrahedron [S1].

3.  **Per-Frame GPU (Vertex Shader):**
    a. For each point, use the precomputed transformation $T_i$ to determine the size and shape of the point primitive. The point size is determined by the size of the tetrahedron and the distance from the viewpoint [S1].
    b. Pass the parameters required for footprint reshaping (e.g., center and radius for circular footprints, or ellipsoid parameters) to the fragment shader via texture coordinates [S1].

4.  **Per-Frame GPU (Fragment Shader - Culling):**
    a. Rasterize the point primitive as a square.
    c. Cull fragments that fall outside the desired footprint shape (e.g., circle or ellipsoid) to reduce overdraw [S1].
    *   *Circular Footprint:* Use the passed center and radius to discard fragments where the distance from the center exceeds the radius [S1].
    *   *Ellipsoidal Footprint:* Use the min-volume enclosing ellipsoid of the tetrahedron. The transformation $T_i$ maps the unit sphere (min-volume ellipsoid of $\hat{\sigma}$) to the target ellipsoid. Fragments are culled if they lie outside this ellipsoid [S1].

5.  **Per-Frame GPU (Compositing):**
    a. Keep one fragment in a texture.
    b. Composite the ray-gap between two fragments using a pre-integrated table [S1].
    c. Compositing is performed based on fragment distances, not pre-assigned alpha values, to mitigate over-representation error [S1].

**Formulas:**
*   **Transformation:** $T_i(\hat{\sigma}) = \sigma_i$, where $\hat{\sigma}$ is the unit tetrahedron inscribed in the unit sphere [S1].
*   **Conditional Probability:** The quality of the ellipsoidal approximation is justified by geometric probability. For a convex volume $A$ (tetrahedron) contained in $B$ (ellipsoid), the probability that a random ray hitting $B$ also hits $A$ is:
    $$ p(A|B) = \frac{s_A}{s_B} $$
    where $s_A$ is the surface area of $A$ and $s_B$ is the surface area of $B$. Minimizing $s_B$ maximizes this probability [S1].
*   **Min-Volume Ellipsoid:** The min-volume ellipsoid for the unit tetrahedron $\hat{\sigma}$ is the unit sphere. The transformation $T_i$ maps this unit sphere to the min-volume enclosing ellipsoid of $\sigma_i$ [S1].

**Parameters:**
*   **Point Size:** Determined by the size of the tetrahedron and the distance from the viewpoint [S1].
*   **LOD Strategy:** A global LOD strategy can be pre-computed based on importance sampling, compromising accuracy for speed during interaction and switching to full-quality after interaction stops [S1].

**Edge Cases and Pitfalls:**
*   **Sub-pixel Tetrahedra:** Standard triangular primitives are inefficient for sub-pixel areas due to connectivity overhead. PBVR handles this efficiently by using single points [S1].
*   **Boundary Quality:** The single-point representation lacks scalar interpolation across the tetrahedron, which can degrade boundary quality when depth complexity is low [S1].
*   **Malformed Tetrahedra:** While Hardware-Assisted Visibility Sorting (HAVS) fails on malformed tetrahedra, PBVR remains robust and does not fail under these conditions [S1].
*   **Wide Size Variation:** If tetrahedra sizes vary widely, large tetrahedra generate many fragments unnecessarily. Culling in the fragment shader is expensive due to branching [S1].

## Subtopics

### Circular Footprints
Approximates tetrahedra with circles. Simpler culling than ellipsoids but may generate more overdraw than ellipsoidal footprints [S1].

### Ellipsoidal Footprints
Uses the min-volume enclosing ellipsoid. Reduces overdraw and improves image quality compared to circular footprints by better matching the tetrahedron's shape [S1].

### Exact Projections
Renders the actual projected faces. Highest accuracy but generates excessive fragments and requires complex connectivity processing, unlike PBVR [S1].

## Operating characteristics
*   **Time Complexity:** Preprocessing is $O(N)$ where $N$ is the number of tetrahedra. Per-frame sorting is $O(N \log N)$. Rendering is $O(N)$ plus fragment processing cost.
*   **Memory Complexity:** $O(N)$ to store the point data (transform, location, scalar) [S1].
*   **Performance:** Achieves interactive framerates for large datasets (e.g., Heart, SPX, F16) [S1].
*   **Strengths:**
    *   Eliminates connectivity processing and storage [S1].
    *   Robust to malformed tetrahedra [S1].
    *   Flexible LOD implementation [S1].
    *   Avoids convolution operations [S1].
*   **Limitations:**
    *   Boundary quality degrades due to lack of scalar interpolation [S1].
    *   Fragment culling branching can be expensive if many fragments are generated [S1].
    *   Accuracy scales with approximation complexity; higher fidelity (ellipsoidal) is slower than simpler approximations [S1].
*   **When to Use:** Interactive visualization of large, unstructured tetrahedral meshes, especially when robustness to mesh quality is required or when connectivity processing is a bottleneck [S1].
*   **When Not to Use:** When high-fidelity boundary rendering is critical and depth complexity is low, or when tetrahedra sizes vary widely leading to excessive fragment generation [S1].

## Background
*   **Origin:** The method was introduced in the paper "Hardware-Assisted Point-Based Volume Rendering of Tetrahedral Meshes" [S1].
*   **History:** It was developed to address the limitations of existing methods like HAVS (which fails on malformed meshes) and direct rendering (which is slow for large datasets). It builds on the concept of point-based rendering and hardware-assisted compositing [S1].
*   **Usage:** Applied to large unstructured tetrahedral datasets such as Heart, SPX, fighter, and F16 models for interactive visualization [S1].
