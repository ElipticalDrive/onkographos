# Tetrahedral representation and traversal
Also called: Projected Tetrahedra family, Tetrahedral Volume Rendering family

## Overview
This family encompasses methods that represent volumetric data or scalar fields using tetrahedral meshes, either by decomposing regular grids or using unstructured meshes, and rendering them via projection or surface extraction. It solves the problem of accurately rendering complex, non-convex, or disconnected geometries that are difficult to represent with regular voxel grids, while avoiding the topological ambiguities of cubic decomposition. It is distinguished from [Cell projection](26-cell-projection.md) by its specific use of tetrahedra as the primitive unit, which ensures planar faces and simplifies visibility sorting, and from [Ray casting](10-ray-casting.md) by its object-order rasterization approach (for projection methods) or explicit mesh generation (for marching algorithms).

## Shared principles
The core mechanism involves defining a scalar field $f(x,y,z)$ over a domain partitioned into tetrahedra. Each tetrahedron $T$ is defined by four vertices $V_i$ with associated scalar values $s_i$. The field is assumed to vary linearly within each tetrahedron [G].

For projection-based methods, the tetrahedra are projected onto the 2D image plane. The projection of a tetrahedron is decomposed into a set of triangles (typically 3 or 4) based on the visibility of its faces relative to the camera. This decomposition is determined by cross-product tests of the projected edges [S5, S8]. The "thick vertex" is identified as the point on the ray segment traversing the maximum distance through the tetrahedron, which determines the optical path length $l$ [S4].

Opacity $\alpha$ and color $C$ are computed based on the entry ($s_f$) and exit ($s_b$) scalar values of the ray through the tetrahedron. The differential opacity $\tau$ and color $C$ are mapped from scalar values via a transfer function. The accumulated opacity for a segment of length $l$ with average differential opacity $\tau_{avg}$ is:
$$ \alpha = 1 - e^{-\tau_{avg} l} $$
[S1, S4]

For surface extraction methods (Marching Tetrahedrons), the algorithm classifies each vertex as inside or outside the isosurface based on a threshold $I$. Intersection points are computed via linear interpolation on edges where vertex states differ [G].

## Subtopics

### [Tetrahedral Volume Rendering](820-tetrahedral-volume-rendering.md)
A GPU-based cell-projection method for unstructured tetrahedral grids using a two-pass pipeline (PTINT). It distinguishes itself by using a Ternary Truth Table for projection classification and supporting both volume rendering and isosurface extraction in the same pipeline. It handles degenerate cases by extending Wylie's classes and uses partial pre-integration for color computation.

### [Projected Tetrahedra](877-projected-tetrahedra.md)
The foundational object-order technique for unstructured tetrahedral meshes. It projects tetrahedra into screen-space triangles, sorts them back-to-front, and composites them. It sets itself apart by its reliance on global visibility sorting and the identification of a "thick vertex" to compute accurate optical thickness, avoiding the artifacts of simple alpha blending.

### [Marching Tetrahedrons Algorithm](940-marching-tetrahedrons-algorithm.md)
An iso-surface extraction method that converts a scalar field on a regular grid into a triangular mesh. It decomposes each cubic voxel into tetrahedra and processes them independently. It differs from projection methods by generating an explicit polygonal mesh rather than rendering directly to the screen, and from [Tetrahedral Volume Rendering](820-tetrahedral-volume-rendering.md) by focusing on surface geometry rather than volumetric accumulation.

### [Adaptive Delaunay Update](4923-adaptive-delaunay-update.md)
A strategy for maintaining topological consistency in tetrahedral volume rendering during optimization. It periodically recomputes the Delaunay triangulation to correct geometric invalidity caused by vertex movement, balancing GPU acceleration speed with geometric accuracy.

#### Point Representation via Tetrahedra
Representing data points as small tetrahedra to fit them into the triangular mesh framework for rendering [S1]. The `size` parameter specifies the size of the point tetrahedra relative to the data ranges [S1].

## Background
The concept of projecting tetrahedra was introduced by Wylie et al. in 1996 as a solution for rendering unstructured grids [S1][S4]. The Marching Tetrahedrons algorithm, a variant of Marching Cubes, was developed to handle the directional ambiguities of cubic decomposition by using tetrahedra [S1][G]. The PTINT pipeline was later developed to accelerate these projections on GPUs [S3].
