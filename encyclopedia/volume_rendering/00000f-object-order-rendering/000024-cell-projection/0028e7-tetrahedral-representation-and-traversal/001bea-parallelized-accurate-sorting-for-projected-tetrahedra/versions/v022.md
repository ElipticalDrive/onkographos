# Parallelized Accurate Sorting for Projected Tetrahedra

Also called: Logical partition sorting, Quick and accurate sorting algorithm of tetrahedral datasets

## Overview
Parallelized Accurate Sorting is a view-dependent sorting algorithm for tetrahedral datasets that uses logical partitioning to enable parallel processing, solving the dependency and sequence limitations of neighboring tetrahedra in parallel performance [S1, unofficial][S2, unofficial]. It sets itself apart from standard [Projected Tetrahedra](877-projected-tetrahedra.md) by replacing global topological sorts with a block-based peeling strategy that allows independent parallel sorting of unobstructed layers, thereby enhancing the parallelization of topological sorting and reducing sorting time [S1, unofficial][S2, unofficial].

## How it works
The method operates on a tetrahedral dataset $T$ and a viewing direction $V$. It outputs a sorted list of tetrahedra ready for back-to-front compositing.

**Data Structures:**
*   **Blocks:** A list of spatial blocks $B = \{b_1, b_2, ..., b_k\}$ partitioning the space along the viewing direction. Each block $b_i$ contains a subset of tetrahedra $T_i \subset T$.
*   **Layers:** Within each block, tetrahedra are organized into unobstructed layers $L_{i,j}$, where $j$ is the layer index. A layer is "unobstructed" if no tetrahedron in a previous layer (closer to the viewer) occludes any tetrahedron in the current layer within the same block's projection.
*   **Boundary Tetrahedra:** Tetrahedra that intersect the boundary between adjacent blocks $b_i$ and $b_{i+1}$.

**Steps:**

1.  **Spatial Partitioning:** Divide the space containing tetrahedral datasets into a list of blocks along the viewing direction. Every block contains a subset of tetrahedra [S1, unofficial][S2, unofficial].
2.  **Parallel Peeling Sort:** Sort tetrahedra accurately by peeling tetrahedral subsets into unobstructed layers in parallel. This is performed independently for each block. For a block $b_i$, identify the front-most layer of tetrahedra (those not occluded by others in $b_i$), assign them to layer 0, remove them from the active set, and repeat to find layer 1, and so on. This peeling process is parallelized across blocks [S1, unofficial][S2, unofficial].
3.  **Boundary Partitioning and Optical Contribution:** Partition tetrahedra on the boundary logically. For tetrahedra intersecting block boundaries, their optical contribution is computed using segment integration. The segment integration calculates the opacity $\alpha$ for the portion of the tetrahedron within the block, based on the differential opacity $\tau$ and the path length $l$ within that segment [S1, unofficial][S2, unofficial].
4.  **Accumulation:** Accumulate the optical contribution of each subset along the viewing direction. The results from each block are combined in order (from back to front) to produce the final image. The accumulation respects the global order established by the block partitioning and the internal layer ordering [S1, unofficial][S2, unofficial].

**Pseudocode:**

```python
def parallelized_accurate_sorting(tetrahedra, viewing_direction):
    # Step 1: Divide space into blocks along viewing direction
    blocks = partition_space_along_view(tetrahedra, viewing_direction)
    
    # Step 2: Sort accurately by peeling tetrahedral subsets into unobstructed layers in parallel
    # This step is parallelized across blocks
    block_layers = parallel_map(peel_unobstructed_layers, blocks)
    
    # Step 3: Partition tetrahedra on boundary logically and compute optical contribution
    # Step 4: Accumulate optical contribution of each subset along viewing direction
    # The accumulation order is determined by the block order and layer order within blocks
    
    final_image = accumulate_optical_contributions(block_layers, viewing_direction)
    
    return final_image

def peel_unobstructed_layers(block_tetrahedra):
    layers = []
    active_tetrahedra = block_tetrahedra.copy()
    
    while active_tetrahedra:
        # Identify front-most layer: tetrahedra not occluded by others in active set
        # Occlusion check is done in screen space projection
        front_layer = []
        remaining = []
        
        for tet in active_tetrahedra:
            is_occluded = False
            for other in active_tetrahedra:
                if other is tet:
                    continue
                # Check if 'other' occludes 'tet' in the projected view
                if is_occluding(other, tet):
                    is_occluded = True
                    break
            
            if is_occluded:
                remaining.append(tet)
            else:
                front_layer.append(tet)
        
        layers.append(front_layer)
        active_tetrahedra = remaining
        
    return layers

def is_occluding(tet_a, tet_b):
    # Check if tet_a occludes tet_b in the projected view
    # This involves projecting both tetrahedra to 2D and checking for overlap
    # and depth ordering. If tet_a is closer to the viewer and overlaps tet_b's projection,
    # it occludes it.
    proj_a = project_to_screen(tet_a)
    proj_b = project_to_screen(tet_b)
    
    if not polygons_overlap(proj_a, proj_b):
        return False
    
    # Check depth: if tet_a is closer to the viewer than tet_b at the overlap region
    if depth_closer(tet_a, tet_b):
        return True
    return False

def depth_closer(tet_a, tet_b):
    # Compare the minimum depth (along viewing direction) of tet_a and tet_b
    # If min_depth(tet_a) < min_depth(tet_b), tet_a is potentially closer
    # Note: This is a simplification; accurate occlusion requires more detailed depth testing
    return min_depth(tet_a) < min_depth(tet_b)

def accumulate_optical_contributions(block_layers, viewing_direction):
    # Accumulate contributions from back to front
    # Order: blocks from back to front, layers within each block from back to front
    image = initialize_image()
    
    for block in reversed(block_layers): # Back to front
        for layer in reversed(block.layers): # Back to front within block
            for tet in layer:
                # Compute optical contribution for this tetrahedron
                # Using segment integration for boundary tetrahedra
                alpha = compute_opacity(tet)
                color = compute_color(tet)
                
                # Porter-Duff over compositing
                image = composite_over(image, color, alpha)
                
    return image
```

**Parameters:**
*   **Block Size:** Not given in the sources. The number of blocks is determined by the spatial partitioning along the viewing direction.
*   **Early Termination:** An early tetrahedron termination scheme can be leveraged by using a summed-area table to accumulate and compare opacity of individual tetrahedra during the rendering phase. This provides a gain of more than 10% in rendering performance for datasets with more than a million tetrahedra [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Boundary Tetrahedra:** Tetrahedra intersecting block boundaries require logical partitioning to ensure correct optical contribution calculation. Failure to handle these correctly can lead to artifacts at block interfaces [S1, unofficial][S2, unofficial].
*   **Occlusion Accuracy:** The peeling process relies on accurate occlusion checks. Simplified depth comparisons may lead to incorrect layer assignments, affecting rendering quality [S1, unofficial][S2, unofficial].

## Subtopics

### [Multi-segment and Multi-stage Projected Tetrahedra](1173-multi-segment-and-multi-stage-projected-tetrahedra.md)
Multi-segment and Multi-stage Projected Tetrahedra is a technique designed to solve the time-consuming sorting problem inherent in Projected Tetrahedra rendering by partitioning datasets into multiple spatial segments and dividing the visualization procedure into multiple temporal stages. It sets itself apart from standard Projected Tetrahedra by introducing spatial partitioning to enable parallel sorting without write access violations, and temporal staging to satisfy varying user requirements and increase cognition. It builds on [Parallelized Accurate Sorting for Projected Tetrahedra](1128-parallelized-accurate-sorting-for-projected-tetrahedra.md) by addressing the scalability limits of sorting large datasets through distributed or cloud-based architectures.

### GPU-Accelerated Cell Projection for Tetrahedral Datasets
A volume rendering technique for tetrahedral datasets that enhances parallelization by dividing space into blocks along the viewing direction, sorting tetrahedra by peeling unobstructed layers in parallel, partitioning boundary tetrahedra logically, and accumulating optical contributions via segment integration [S2, unofficial]. The algorithm reduces sorting time largely and improves rendering performance greatly compared to previous methods [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** The parallel peeling sort reduces sorting time largely compared to global topological sorts [S1, unofficial][S2, unofficial]. The GPU implementation achieves 91% acceleration compared with the CPU implementation [S1, unofficial].
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:** For datasets with more than a million tetrahedra, the early tetrahedron termination scheme has a gain of more than 10% in terms of rendering performance [S1, unofficial].
*   **Strengths:** Enhances parallelization of topological sorting, reduces sorting time, and improves rendering performance greatly [S1, unofficial][S2, unofficial].
*   **Limitations:** The algorithm is view-dependent, requiring re-sorting for each frame [S1, unofficial][S2, unofficial]. Boundary handling adds complexity [S1, unofficial][S2, unofficial].
*   **When to Use:** Suitable for large tetrahedral datasets where parallel processing is beneficial and view-dependent sorting is acceptable [S1, unofficial][S2, unofficial].
*   **When Not to Use:** Not suitable for real-time applications requiring very low latency if the sorting overhead is too high, or for datasets where view independence is critical [S1, unofficial][S2, unofficial].

## Background
The method was proposed by Xin Li, W. Chen, X. Wu, and W. Zuo in the paper "Fast projected tetrahedra volume rendering based on parallelized accurate sorting" published in August 2013 [S1, unofficial]. It addresses the limitations of parallel performance in projected tetrahedra rendering caused by the sequence and dependency of neighboring tetrahedra [S1, unofficial][S2, unofficial]. The technique is part of the broader family of cell projection volume rendering methods [S1, unofficial][S2, unofficial].
