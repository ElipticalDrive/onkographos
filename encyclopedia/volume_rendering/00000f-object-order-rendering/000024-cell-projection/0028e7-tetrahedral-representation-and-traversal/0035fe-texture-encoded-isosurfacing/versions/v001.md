# Texture-Encoded Isosurfacing

Also called: Modified HAVS for isosurfaces, Texture-Encoded Isosurface Extraction

## Overview
Texture-Encoded Isosurfacing is a GPU-accelerated method for extracting isosurfaces from unstructured tetrahedral grids by leveraging 2D texturing hardware to compute intersection points [S1, S2, unofficial]. It differs from standard [Marching Tetrahedrons Algorithm](940-marching-tetrahedrons-algorithm.md) by replacing explicit geometric intersection calculations with texture sampling, and from [Projected Tetrahedra](877-projected-tetrahedra.md) by generating smaller tetrahedra rather than triangles for projection [S1, S2, unofficial].

## How it works
**Inputs:**
*   Tetrahedral mesh $T$ with vertices $V_i$ and scalar values $s_i$.
*   Isosurface threshold $I$.
*   Camera projection matrix and viewport dimensions.

**Outputs:**
*   Isosurface geometry (implicitly defined by texture samples) or rendered image.

**Data Structures:**
*   **2D Checkerboard Texture:** A 2D texture map where the spatial coordinates correspond to the projection plane. The texture content encodes the scalar field values at the front and back faces of the projected tetrahedra. For smooth or multiple isosurfaces, the texture domain is partitioned to store shading values [S1, S2, unofficial].

**Steps:**
1.  **Decomposition:** Apply the decomposition step of the [Marching Tetrahedrons Algorithm](940-marching-tetrahedrons-algorithm.md) to each tetrahedron $T$. Instead of generating triangles, this step partitions $T$ into smaller tetrahedra based on the classification of vertices relative to the isosurface threshold $I$ [S1, S2, unofficial].
2.  **Projection:** Project the front and back faces of each smaller tetrahedron onto the 2D image plane [S1, S2, unofficial].
3.  **Projection Analysis:** Determine the projection case for each smaller tetrahedron. The projection of the front and back faces results in one of two simple cases:
    *   A degenerate triangle (if the faces are parallel to the view direction or coincident in projection).
    *   The same triangle (if the front and back faces project to the same footprint) [S1, S2, unofficial].
4.  **Texture Encoding:** Associate a checkerboard texture with the projected footprint. The texture coordinates are mapped such that they correspond to the scalar values of the front and back faces of the smaller tetrahedron [S1, S2, unofficial].
5.  **Rendering/Extraction:** Render the projected smaller tetrahedra using the 2D texture. The intersection with the isosurface is computed by sampling the texture at coordinates corresponding to the front and back face scalar values. The coincidence of the front and back face projections allows the intersection logic to be encoded directly into the texture sampling process [S1, S2, unofficial].
6.  **Stencil Buffer (Optional/Contextual):** In some implementations (e.g., modified HAVS), a stencil buffer may be used in a two-pass process to handle visibility or occlusion, setting the stencil in the first pass [S1, S2, unofficial].

**Parameters:**
*   **Isosurface Threshold ($I$):** The scalar value defining the surface.
*   **Texture Resolution:** Determines the precision of the intersection approximation. Not given in the sources.

**Edge Cases:**
*   **Degenerate Projections:** If the projection results in a degenerate triangle, the intersection computation must handle this case, potentially skipping rendering or using fallback logic. Not given in the sources.
*   **Multiple Isosurfaces:** Requires further partitioning of the texture domain and storage of shading values. Not given in the sources.

## Operating characteristics
*   **Performance:** Renders on average 5 to 7 triangles per tetrahedron in the original HAVS variant; the texture-encoded variant renders fewer faces per tetrahedron [S1, S2, unofficial].
*   **Hardware Dependency:** Relies on 2D texturing hardware and potentially stencil buffers [S1, S2, unofficial].
*   **Strengths:** Efficient use of GPU texturing units for intersection computation; reduces the number of faces rendered compared to standard PT [S1, S2, unofficial].
*   **Limitations:** Limited to isosurface extraction; extensions for smooth/multiple isosurfaces increase complexity [S1, S2, unofficial].

## Background
The method was proposed as an alternate solution to render fewer faces per tetrahedron, revising work by Wylie et al. [72] and Pascucci [52] [S1, S2, unofficial]. It is described as a modified version of the HAVS algorithm [S1, S2, unofficial].
