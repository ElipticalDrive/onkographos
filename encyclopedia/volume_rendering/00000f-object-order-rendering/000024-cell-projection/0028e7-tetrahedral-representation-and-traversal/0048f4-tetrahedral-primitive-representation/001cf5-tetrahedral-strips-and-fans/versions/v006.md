# Tetrahedral Strips and Fans

Also called: Bandwidth reduction for tetrahedral meshes, Rendering Pattern and Stripification, Tetrahedral Fans, Tetrahedral Strips, Tetrahedral primitives

## Overview
Tetrahedral Strips and Fans are specialized graphics primitives designed to reduce the bandwidth bottleneck between main memory and the graphics processor when rendering unstructured tetrahedral meshes [S2, unofficial]. They address the inefficiency of rendering tetrahedra as individual triangles, which requires 50-60% more bandwidth than rendering individual triangles alone [S2, unofficial]. Unlike triangle strips, which can be statically computed for triangle meshes, tetrahedral decomposition is view-dependent, preventing the use of static strips or display lists when changing the viewpoint [S2, unofficial]. These primitives allow performance improvements similar to triangle strips and fans but are tailored for the topological constraints of tetrahedral volume rendering [S1, unofficial].

## How it works
The method operates by grouping tetrahedra into sequences (strips or fans) that share geometric elements (edges or faces), allowing the graphics hardware to reuse vertices and reduce the number of vertex transmissions per tetrahedron.

### Inputs and Outputs
*   **Input:** A tetrahedral mesh (unstructured volume data) and a view direction.
*   **Output:** A sequence of drawing commands (strips/fans) sent to the graphics hardware, along with vertex attributes (position, color, etc.).

### Data Structures
The core data structure is a list of tetrahedra grouped into strips or fans.
*   **Tetrahedral Fan:** A sequence of tetrahedra sharing a common edge.
*   **Tetrahedral Strip:** A sequence of tetrahedra connected by shared faces, where not all necessarily share one common edge.
*   **Vertex Slots:** For generalized strips, the hardware maintains four vertex slots corresponding to the four vertices of the current tetrahedron.

### Algorithm: Stripification
The process of converting a mesh into strips involves identifying adjacent tetrahedra and ordering them to maximize shared geometry.

1.  **Identify Adjacency:** Determine the adjacency graph of the tetrahedral mesh, where nodes are tetrahedra and edges represent shared faces.
2.  **Select Base Edge (for Fans):** Identify a common edge shared by a sequence of tetrahedra. This edge forms the "spine" of the fan.
3.  **Order Vertices (for Fans):** Order the remaining vertices of the tetrahedra in the fan around the common edge. The first two vertices transmitted define the shared edge. The third and fourth vertices complete the first tetrahedron. Subsequent vertices define new tetrahedra by reusing the shared edge and the previous new vertex.
4.  **Order Vertices (for Strips):** For strips, identify a chain of tetrahedra connected by shared faces.
    *   **Sequential Strip:** The new vertex always replaces the least-recently-used (LRU) vertex of the previous tetrahedron.
    *   **Generalized Strip:** There are no constraints on the direction of the next tetrahedron. A flag must be transmitted to indicate which of the four vertex slots is replaced by the new vertex.
5.  **Generate Indices:** Create the vertex index list for each strip/fan.

### API and Transmission Syntax
The primitives are defined via an extension to the OpenGL API [S2, unofficial].

**Tetrahedral Fan:**
1.  Call `glBegin(GL_TET_FAN_EXT)`.
2.  Transmit the first two vertices ($v_1, v_2$). These form the shared edge.
3.  Transmit the third and fourth vertices ($v_3, v_4$). These complete the first tetrahedron ($v_1, v_2, v_3, v_4$).
4.  For each subsequent vertex $k$ (where $k \ge 5$), transmit vertex $v_k$. This defines a new tetrahedron consisting of vertices $v_1, v_2, v_{k-1}, v_k$.
5.  Call `glEnd()`.

**Sequential Tetrahedral Strip:**
1.  Call `glBegin(GL_SEQUENTIAL_TET_STRIP_EXT)`.
2.  Transmit the four vertices of the first tetrahedron ($v_1, v_2, v_3, v_4$).
3.  For each subsequent vertex $k$ (where $k \ge 5$), transmit vertex $v_k$. This defines a new tetrahedron consisting of vertices $v_2, v_3, v_4, v_k$ (replacing $v_1$).
4.  Call `glEnd()`.

**Generalized Tetrahedral Strip:**
1.  Call `glBegin(GL_GENERAL_TET_STRIP_EXT)`.
2.  Transmit the four vertices of the first tetrahedron ($v_1, v_2, v_3, v_4$).
3.  For each subsequent tetrahedron:
    *   Transmit a flag indicating which of the four vertex slots (1, 2, 3, or 4) should be replaced.
    *   Transmit the new vertex $v_k$.
    *   The new vertex replaces the specified slot, forming the new tetrahedron with the remaining three slots.
4.  Call `glEnd()`.

### Pseudocode

```python
def render_tetrahedral_fan(vertices):
    """
    Renders a tetrahedral fan.
    vertices: List of vertex objects.
    The first two vertices form the shared edge.
    """
    if len(vertices) < 4:
        return # Error: Fan requires at least 4 vertices for the first tetrahedron

    glBegin(GL_TET_FAN_EXT)
    
    # Transmit shared edge
    glVertex(vertices[0])
    glVertex(vertices[1])
    
    # Complete first tetrahedron
    glVertex(vertices[2])
    glVertex(vertices[3])
    
    # Subsequent tetrahedra
    for i in range(4, len(vertices)):
        # New tetrahedron uses shared edge (0, 1), previous new vertex (i-1), and new vertex (i)
        glVertex(vertices[i])
        
    glEnd()

def render_sequential_tet_strip(vertices):
    """
    Renders a sequential tetrahedral strip.
    vertices: List of vertex objects.
    """
    if len(vertices) < 4:
        return # Error: Strip requires at least 4 vertices

    glBegin(GL_SEQUENTIAL_TET_STRIP_EXT)
    
    # First tetrahedron
    glVertex(vertices[0])
    glVertex(vertices[1])
    glVertex(vertices[2])
    glVertex(vertices[3])
    
    # Subsequent tetrahedra replace the LRU vertex (index 0)
    for i in range(4, len(vertices)):
        glVertex(vertices[i])
        
    glEnd()

def render_generalized_tet_strip(vertices, replacement_flags):
    """
    Renders a generalized tetrahedral strip.
    vertices: List of vertex objects.
    replacement_flags: List of integers (1, 2, 3, or 4) indicating which slot to replace.
    """
    if len(vertices) < 4:
        return # Error

    glBegin(GL_GENERAL_TET_STRIP_EXT)
    
    # First tetrahedron
    glVertex(vertices[0])
    glVertex(vertices[1])
    glVertex(vertices[2])
    glVertex(vertices[3])
    
    # Subsequent tetrahedra
    for i in range(4, len(vertices)):
        flag = replacement_flags[i - 4]
        glReplaceVertexEXT(flag)
        glVertex(vertices[i])
        
    glEnd()
```

### Parameters and Typical Values
*   **Transmission Rate:** The primitives achieve transmission rates approaching 1.2 vertices per tetrahedron [S2, unofficial].
*   **Strip Lengths:**
    *   Average strip length: 17 tetrahedra on representative datasets [S1, unofficial].
    *   Method 2 (best performing heuristic): Mean strip length of 29.4 on the 'phoenix' dataset and 49.0 on the 'langley' dataset [S2, unofficial].
*   **Bandwidth Cost:** Rendering tetrahedra requires 50-60% more bandwidth than rendering individual triangles even with fans [S2, unofficial].
*   **Generalized Strip Overhead:** Requires 2 bits per vertex to transmit the replacement flag [S2, unofficial].

### Edge Cases and Pitfalls
*   **View Dependency:** Static strips cannot be used because the projection of tetrahedra changes with the viewpoint. Stripification must be performed or updated per frame or view change [S2, unofficial].
*   **Degenerate Input:** Fans require at least 4 vertices. Strips require at least 4 vertices.
*   **Precision:** The linear approximation used in the underlying projected tetrahedra algorithm may introduce inaccuracies [S2, unofficial].

## Operating characteristics
*   **Performance:** The combined effect of the architecture and new primitives results in a 72 to 85 times increase in performance over triangle graphics hardware approaches [S1, unofficial].
*   **Efficiency:** Tetrahedral stripping is inherently more efficient than triangle stripping, with gains greater than expected [S2, unofficial].
*   **Memory:** The primitives allow for compact storage and transmission of unstructured datasets, requiring only local information for stripiﬁcation [S2, unofficial].
*   **Limitations:** The approach suffers from some inaccuracies inherent to the projected tetrahedra algorithm [S2, unofficial].
*   **When to Use:** Interactive tetrahedral volume rendering where bandwidth is a bottleneck and view-dependent decomposition is required [S2, unofficial].
*   **When Not to Use:** Static scenes where triangle strips can be precomputed, or when high geometric accuracy is required beyond linear interpolation.

## Background
Tetrahedral Strips and Fans were introduced to address the bandwidth bottleneck in interactive tetrahedral volume rendering. The method builds on the projected tetrahedra algorithm, which decomposes the volume into tetrahedra and projects them to screen space. The primitives were designed to work with a proposed hardware-rendering system (R-buffer) that handles order-independent transparency and volume scan conversion, making software sorting unnecessary [S1, unofficial]. The techniques were evaluated on datasets ranging from 3,000 to 240,000 tetrahedra, demonstrating significant performance improvements [S2, unofficial].
