# Sorting-free Projected Tetrahedra
## Overview
Sorting-free Projected Tetrahedra (SPT) is a volume rendering technique for irregular tetrahedral datasets that approximates back-to-front accumulation using stochastic color composition, thereby eliminating the need for explicit visibility sorting [S1]. Unlike its parent [Projected Tetrahedra](877-projected-tetrahedra.md), which requires sorting triangles before rendering, SPT avoids sorting errors and extra buffer space by treating brightness as an expected value of luminosity over multiple stochastic repetitions [S1]. It is particularly advantageous for high-resolution displays and datasets with precipitous transfer functions where particle-based methods like [Point-based Projected Tetrahedra](5527-point-based-projected-tetrahedra.md) may fail to generate sufficient particles [S1].

## How it works
### Inputs and Outputs
**Inputs:**
- A tetrahedral mesh representing an irregular volume dataset [S1].
- A transfer function mapping scalar values to color and opacity [S1].
- Camera parameters defining the viewpoint and projection [S1].
- Repetition level $N$ (integer $\ge 1$) controlling the ensemble size [S1].

**Outputs:**
- A rendered image with accumulated brightness values [S1].

### Data Structures
**Pre-integration Lookup Table:**
- A 3D texture mapping three integration parameters to pre-integrated color $C$ and opacity $\alpha$ [S1].
- Dimensions: Discretized ranges for scalar value at the front ($s_f$), scalar value at the back ($s_b$), and segment length ($d$) [S1].
- Values: $C = C(s_f, s_b, d)$ and $\alpha = \alpha(s_f, s_b, d)$ [S1].
- Note: The pre-integrated color is divided by the corresponding opacity, making it opacity-weighted [S1].

**Geometry Shader Outputs:**
- Front scalar ($s_f$) and back scalar ($s_b$) [S1].
- Distance value ($d$) [S1].
- These parameters are passed through the "thickest" vertex of the split triangle to facilitate color compositing in fragment processing [S1].

### Algorithm Steps
The method consists of two main phases: Geometry Processing and Stochastic Color Composition [S1].

#### Phase 1: Geometry Processing (Geometry Shader)
1. **Input:** A single tetrahedron defined by 4 vertices [S1].
2. **Classification:** Classify the tetrahedron into one of 4 classes of projection patterns based on its visibility relative to the viewpoint [S1].
3. **Decomposition:** Decompose the tetrahedron into triangles [S1]. Since triangle fans are not supported by geometry shaders in current-generation GPUs, emit one or two triangle strips instead [S1].
4. **Parameter Calculation:** Calculate $s_f$, $s_b$, and $d$ for the vertices of the resulting triangles [S1].
5. **Emission:** Emit the triangle(s) with the calculated parameters attached to the appropriate vertices [S1].

#### Phase 2: Stochastic Color Composition (Fragment Shader)
For each repetition $i$ from $1$ to $N$:
1. **Fragment Processing:** For each fragment generated by rasterizing the emitted triangles:
   - Retrieve interpolated $s_f$, $s_b$, and $d$ [S1].
   - Look up the pre-integrated color $C$ and opacity $\alpha$ from the 3D texture using $(s_f, s_b, d)$ [S1].
   - Fragments are rendered with a probability equal to the opacity value at each ray-segment along a viewing ray [S1].
   - If the fragment survives, the luminosity of the particle nearest to the viewpoint is assigned to the brightness value [S1].
2. **Accumulation:** After all fragments for the current repetition are processed, the resulting brightness value for the pixel is $B^{(i)}$ [S1].

After $N$ repetitions:
3. **Averaging:** Steps 1 and 2 are repeated $N$ times, and the resulting brightness values are accumulated to obtain the average [S1].

### Formulas
**Probability of Brightness Assignment:**
The probability that the $k$-th luminosity equals the brightness is defined as the event where there is no particle from the first to the $(k-1)$-th ray-segments and more than one particle in the $k$-th ray segment [S1]. This formulation uses opaque and emissive particles [S1].

**Variance and Deviation:**
If particle occurrence is independent for each ensemble member, the average and variance of the brightness value of the $i$-th ensemble are identical [S1].
The variance of the total brightness is:
$$ Var(B_{total}) = \frac{1}{N^2} \sum_{i=1}^{N} Var(B^{(i)}) $$
Since variances are identical and covariance is zero:
$$ Var(B_{total}) = \frac{Var(B^{(i)})}{N} $$
[ S1]

The deviation of the total brightness is:
$$ \sigma_{total} = \sqrt{\frac{Var(B^{(i)})}{N}} $$
[ S1]

**Complexity:**
The computational complexity of the standard stochastic approach is $O(n^2)$ [S1]. With sorting, it reduces to $O(n)$ [S1]. SPT complexity is proportional to the repetition level $N$ and the number of cells [S1].

### Parameters
- **Repetition Level ($N$ or $L_r$):** The number of times Steps 1-2 are repeated [S1]. Controls the level of detail and noise [S1]. Larger deviation allows smaller $N$ [S1]. Typical values tested: 1, 25, 100, 144 [S1].

### Edge Cases and Pitfalls
- **Triangle Fans:** Triangle fans are not supported by geometry shaders in current-generation GPUs [S1]. Workaround: Emit one or two triangle strips instead [S1].
- **Sorting Errors:** Sorting-based methods like HAVS yield remarkable rendering artifacts due to sorting errors [S1]. SPT avoids this by not requiring visibility sorting [S1].
- **Precipitous Transfer Functions:** Methods like PBVR generate an insufficient number of particles when the density function changes drastically [S1]. SPT can visualize a continuous iso-surface of the precipitous function’s value [S1].
- **Construction Time:** It takes about 100 milliseconds to construct the 3D texture for pre-integrated classification and 17.4 seconds to generate particles (if using PBVR comparison) [S1]. These occur when the transfer function is modified or for time-varying datasets [S1].

### Pseudocode
```python
import random

def build_preintegration_texture(tf, grid_size):
    """Build 3D lookup table for pre-integrated color and opacity."""
    texture = [[[None for _ in range(grid_size)] for _ in range(grid_size)] for _ in range(grid_size)]
    for i in range(grid_size):
        for j in range(grid_size):
            for k in range(grid_size):
                sf = i / grid_size
                sb = j / grid_size
                d = k / grid_size
                # Compute pre-integrated color and opacity from transfer function
                C, alpha = tf.integrate(sf, sb, d)
                # Store opacity-weighted color
                texture[i][j][k] = (C / alpha, alpha)
    return texture

def geometry_shader(tetrahedron):
    """Classify, decompose, and emit triangle strips."""
    # Classify into 4 projection patterns based on viewpoint
    pattern = classify_projection(tetrahedron)
    # Decompose into triangles; emit as strips to avoid unsupported triangle fans
    triangles = decompose_into_strips(tetrahedron, pattern)
    emitted = []
    for tri in triangles:
        # Calculate sf, sb, d for vertices
        params = calculate_parameters(tri)
        # Pass parameters through the thickest vertex
        emitted.append((tri, params))
    return emitted

def fragment_shader(params, texture, N):
    """Stochastic color composition for a single fragment."""
    sf, sb, d = params
    # Lookup pre-integrated color and opacity
    C, alpha = texture[sf][sb][d]
    total_brightness = 0.0
    # Repeat stochastic composition N times
    for _ in range(N):
        # Render fragment with probability equal to opacity
        r = random.random()
        if r <= alpha:
            # Luminosity of nearest particle assigned to brightness
            total_brightness += C
    # Average over repetitions
    return total_brightness / N

def render(dataset, camera, texture, N):
    """Main rendering loop."""
    image = {}
    for tet in dataset:
        triangles = geometry_shader(tet)
        for tri, params in triangles:
            # Rasterize and process fragments
            for frag in rasterize(tri, camera):
                brightness = fragment_shader(frag.params, texture, N)
                image[frag.pixel] = brightness
    return image
```

## Operating characteristics
- **Time Complexity:** Proportional to the repetition level $N$ and the number of cells [S1]. Standard stochastic is $O(n^2)$, sorted is $O(n)$, SPT is $O(N \cdot n)$ [S1].
- **Memory Complexity:** Requires VRAM for the 3D texture and storing tetrahedral data [S1]. With 512MB VRAM, max tetrahedral cells is ~24.5 million at 1024x1024 resolution [S1].
- **Measured Performance:** On NVIDIA GeForce 9600GT (512MB), computing time is ~1.4 seconds per repetition for 24.5 million cells at 1024x1024 resolution [S1]. PBVR renders ~10 million particles at 25.7 milliseconds per repetition at 1024x1024 [S1].
- **Strengths:** No visibility sorting artifacts; handles precipitous transfer functions better than PBVR; no extra buffer space for candidate fragments (unlike HAVS) [S1].
- **Limitations:** Noise decreases with $N$, requiring more repetitions for high quality; construction time for pre-integration table (100ms) and particle generation (17.4s for PBVR comparison) if transfer function changes [S1].
- **When to Use:** High-resolution displays, tiled-display walls, datasets with >24 million particles or <24.5 million tetrahedral cells [S1].
- **When Not to Use:** When real-time performance is critical and $N$ must be small, or when the dataset is extremely large (>24.5 million cells) where PBVR might be preferred [S1].

## Background
Sorting-free Projected Tetrahedra (SPT) was introduced as a technique to overcome the drawbacks of sorting-based projected tetrahedra methods, such as HAVS, which suffer from sorting errors and require extra buffer space [S1]. It builds on the concept of projected tetrahedra but replaces explicit sorting with stochastic color composition [S1]. The method was developed to handle irregular tetrahedral datasets efficiently while maintaining high image quality, particularly for precipitous transfer functions [S1].
