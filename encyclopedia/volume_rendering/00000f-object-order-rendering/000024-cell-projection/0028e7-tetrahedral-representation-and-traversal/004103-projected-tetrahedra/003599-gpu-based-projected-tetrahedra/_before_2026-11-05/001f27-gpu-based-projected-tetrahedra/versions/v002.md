# GPU-Based Projected Tetrahedra

Also called: GPU Volume Scan Conversion of Tetrahedra, Tetrahedral Projection using Vertex Shaders, Texture Memory PT, Two-Shader PT, Vertex Shader PT

## Overview
GPU-Based Projected Tetrahedra is a method for interactive volume rendering of unstructured tetrahedral data that leverages programmable graphics hardware to perform volume scan conversion directly on the GPU [S1, unofficial]. It solves the performance bottleneck of traditional CPU-based projected tetrahedra by avoiding redundant projections and pre-processing, achieving interactive rates with a substantially smaller memory footprint than ray-casting approaches [S1, unofficial]. It differs from its siblings by utilizing a specific two-fragment-shader architecture (or vertex-shader-only variants) to handle projection and rasterization, whereas [Parallelized Accurate Sorting for Projected Tetrahedra](3018-sorted-rasterization-of-projected-tetrahedra.md) focuses on sorting algorithms and [Two-Pass GPU Approach](1339-two-pass-gpu-approach.md) separates projection and rendering into distinct passes [S1, unofficial].

## How it works
The method implements the Projected Tetrahedra (PT) algorithm [Parent](5625-hardware-assisted-projection.md) using the graphics pipeline [G]. It requires no pre-processing of the data and no additional data structures beyond those inherent to the GPU pipeline [S1, unofficial].

### Inputs and Outputs
*   **Input:** Unstructured tetrahedral mesh (vertices and connectivity), volume data (scalar values at vertices), camera parameters (view and projection matrices) [G].
*   **Output:** Rendered image (color and opacity) on the frame buffer [G].

### Data Structures
*   **Model Storage:** The tetrahedral mesh and associated volume data are stored in texture memory to allow efficient access by shaders [S1, unofficial].
*   **Vertex Buffer:** Contains the four vertices of each tetrahedron; in strip variants, a buffer holds the four vertices of the current tetrahedron and the additional fifth vertex created by the PT algorithm [S3, unofficial].

### Steps
1.  **Data Loading:** Load the tetrahedral mesh and volume data into GPU texture memory [S1, unofficial].
2.  **Projection:** Employ fragment shaders to compute the tetrahedra projections onto the 2D screen space, avoiding redundant projections [S1, unofficial].
3.  **Rasterization:** The projected tetrahedra are converted into triangles (scan conversion) by the GPU hardware [S1, unofficial].
4.  **Rendering:** Fragment shaders compute the final color and opacity for each pixel covered by the projected triangles, performing volume integration [S1, unofficial].

### Formulas
The specific mathematical formulas for the PT algorithm (e.g., ray-tetrahedron intersection, opacity integration) are defined in [Projected Tetrahedra](877-projected-tetrahedra.md) [G]. The GPU-based implementation relies on these geometric primitives but offloads the computation to the fragment shaders [S1, unofficial].

### Parameters
*   **Texture Memory Size:** Must be sufficient to hold the entire model [G].
*   **Shader Programs:** Two fragment shaders are employed in the Marroquim et al. approach: one for computing tetrahedra projections and another for rendering the elements [S1, unofficial].

### Edge Cases and Pitfalls
*   **Redundant Projections:** Implementations must avoid redundant projections of tetrahedral elements to maintain performance [S1, unofficial].
*   **Square Root Computation:** Computing edge lengths and face areas requires square roots, which impacts running time and complexity [S3, unofficial].

### Pseudocode
```python
def gpu_based_projected_tetrahedra(tetrahedra, volume_data, view_matrix, proj_matrix):
    """
    Renders unstructured tetrahedral data using GPU shaders.
    Based on the two-fragment-shader architecture described in [S1, unofficial].
    """
    # Step 1: Load data into texture memory
    texture_memory = allocate_texture_memory(tetrahedra, volume_data)
    
    # Step 2: Project tetrahedra using fragment shaders
    projected_triangles = []
    for tet in tetrahedra:
        v0, v1, v2, v3 = extract_vertices(tet, volume_data)
        screen_v0 = project_vertex(v0, view_matrix, proj_matrix)
        screen_v1 = project_vertex(v1, view_matrix, proj_matrix)
        screen_v2 = project_vertex(v2, view_matrix, proj_matrix)
        screen_v3 = project_vertex(v3, view_matrix, proj_matrix)
        triangles = generate_pt_triangles(screen_v0, screen_v1, screen_v2, screen_v3)
        projected_triangles.extend(triangles)
        
    # Step 3: Rasterize and render using fragment shaders
    render_triangles(projected_triangles, texture_memory)

def allocate_texture_memory(tetrahedra, volume_data):
    """Allocate GPU texture memory for the model."""
    return {"tetrahedra": tetrahedra, "volume_data": volume_data}

def extract_vertices(tet, volume_data):
    """Extract 3D vertex positions from the tetrahedron indices."""
    return [volume_data[i] for i in tet]

def project_vertex(vertex, view_matrix, proj_matrix):
    """Project a 3D vertex to 2D screen space using standard graphics pipeline math."""
    clip_coords = proj_matrix @ view_matrix @ [vertex[0], vertex[1], vertex[2], 1.0]
    if clip_coords[3] != 0:
        ndc_x = clip_coords[0] / clip_coords[3]
        ndc_y = clip_coords[1] / clip_coords[3]
        return [ndc_x, ndc_y]
    return None

def generate_pt_triangles(v0, v1, v2, v3):
    """
    Generate triangles for a projected tetrahedron.
    The exact classification logic depends on the view direction and is defined in the PT algorithm [G].
    """
    return [(v0, v1, v2), (v0, v2, v3)]

    and blends into the frame buffer.
```

## Subtopics

### [Sorted Rasterization of Projected Tetrahedra](3018-sorted-rasterization-of-projected-tetrahedra.md)
Sorted Rasterization of Projected Tetrahedra is a GPU-based direct volume rendering method for unstructured tetrahedral data that achieves interactive rates by treating each tetrahedron as a distinct primitive and rasterizing them front-to-back. It differs from traditional ray casting by leveraging hardware rasterization and blending operations to compute the final pixel color, avoiding the need for explicit ray-tetrahedron intersection tests per pixel. This approach builds on [GPU-Based Projected Tetrahedra](1951-gpu-based-projected-tetrahedra.md) by optimizing the rendering pipeline for modern programmable graphics cards.

### Cell Projection with 3D/2D Textures
This variant stores color and opacity in a 3D texture map computed during pre-processing, enabling concurrent use of transfer functions encoded in the texture map [S2, unofficial]. It assigns all associated triangles to each vertex of each projected tetrahedron and blends them into the frame buffer using back-to-front compositing [S2, unofficial]. To reduce memory consumption, it can be adapted for 2D texture maps by approximating dependencies of the volume rendering integral with respect to the length between sample points in linear terms and storing them in the first 2D texture map, while storing remaining parts of the integral (dependent only on sample values) in another 2D texture map [S2, unofficial].

### Hardware Caching for Projected Tetrahedra
This variant maintains a buffer holding the four vertices of the current tetrahedron and the additional fifth vertex sometimes created by the PT algorithm [S3, unofficial]. It swaps the vertices in the buffer as necessary to follow the direction of the strip [S3, unofficial]. It caches edge lengths and face areas computed for the current tetrahedron, as these are required by the PT algorithm and are reused by the next tetrahedron in a strip [S3, unofficial]. A pitfall is that computing edge lengths and face areas requires a square root, which impacts running time and complexity [S3, unofficial].

## Operating characteristics
*   **Performance:** Capable of rendering over 2.0 M Tet/s on current graphics hardware [S1, unofficial].
*   **Memory Footprint:** Occupies a substantially smaller memory footprint compared to ray-casting approaches [S1, unofficial].
*   **Interactivity:** Allows interactive viewing of large unstructured datasets on a desktop personal computer [S1, unofficial].
*   **Strengths:** No pre-processing or additional data structures required [S1, unofficial]. Competitive with recent ray-casting approaches [S1, unofficial].
*   **Limitations:** Performance can be impacted by the computation of square roots for edge lengths and face areas [S3, unofficial].

## Background
The method is based on the Projected Tetrahedra (PT) algorithm by Shirley and Tuchman [S1, unofficial]. The GPU-based implementation was presented by Wylie et al. in 2002, who introduced tetrahedral projection using vertex shaders [S1, unofficial]. Marroquim et al. further refined the approach in 2006 with a practical implementation using two fragment shaders [S1, unofficial]. The technique builds on the foundational work of Kajiya and Von Herzen for ray tracing volume densities [S1, unofficial].
