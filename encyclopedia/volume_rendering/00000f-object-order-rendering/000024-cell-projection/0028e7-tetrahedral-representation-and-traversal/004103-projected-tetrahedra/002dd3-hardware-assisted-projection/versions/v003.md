# Hardware-Assisted Projection
## Overview
Hardware-Assisted Projection is a family of volume rendering techniques for unstructured grids that project 3D cells (tetrahedra or polyhedra) into screen space to leverage GPU rasterization pipelines, thereby avoiding the high data transfer overhead of CPU-side triangle generation and sorting required by traditional [Projected Tetrahedra](877-projected-tetrahedra.md). It differs from sibling methods by offloading the geometric decomposition, scan conversion, or integral evaluation to hardware shaders, enabling single-pass or reduced-pass rendering [S1, unofficial][S2, unofficial].
## Shared principles
The family shares the core mechanism of object-order projection: mapping 3D cell vertices to 2D screen coordinates to determine the projection area, followed by scan conversion to identify ray-cell intersections. Unlike pure raycasting, these methods operate in image space, generating depth-sorted ray segments or fragment-level contributions that are composited using hardware acceleration. The primary goal is to minimize CPU-GPU data transfer and eliminate explicit CPU-side triangle sorting by utilizing GPU geometry shaders, fragment shaders, or hardware compositing [S1, unofficial][S2, unofficial][S3, unofficial].
## Subtopics

### [Hardware-Assisted Polyhedron Projection](1453-hardware-assisted-polyhedron-projection.md)
Projects arbitrary convex polyhedral cells to 2D, performs scan conversion to generate depth-sorted ray segments, and composites them using hardware acceleration. It differs from raycasting by operating in image space with object-order projection, allowing flexible data distribution on distributed-memory systems and leveraging standard polygon pipelines for scan conversion. Unlike [Projected Tetrahedra](877-projected-tetrahedra.md), which requires explicit triangle generation and sorting, this method projects cells directly as polygons and relies on hardware compositing or global sorting for depth ordering.

### [Hardware-Assisted Projected Tetrahedra](1729-hardware-assisted-projected-tetrahedra.md)
Projects tetrahedra onto the screen and rasterizes them as triangles, evaluating the volume ray integral per fragment in the fragment shader. It solves the performance bottleneck of explicit isosurface extraction and the data transfer overhead of previous hybrid methods by performing the entire rendering pipeline on the GPU in a single pass. Unlike its sibling [Projected Tetrahedra](877-projected-tetrahedra.md), which requires CPU-side sorting and triangle generation, HAPT streams sorted tetrahedra as point primitives and uses the GPU geometry shader to decompose them into triangles. It differs from [Tetrahedral Projection with Partial Pre-integration](1861-tetrahedral-projection-with-partial-pre-integration.md) (PTINT) by eliminating the need to read data back from the GPU, allowing rendering of volumes with several million tetrahedra that would exceed GPU memory limits.

### Röttger 3D Texture Mapping
An extension of the projected tetrahedra algorithm for hardware-accelerated rendering of volumetric data using 3D texture mapping [S1, unofficial]. Linearly approximate parts of the volume integral depending on segment length by modulating vertex colors. Tabulate remaining parts that depend only on textural coordinates in a 2D texture map [S1, unofficial].

## Background
The concept of hardware-assisted projection for unstructured grids emerged as a response to the limitations of CPU-based projected tetrahedra methods, which suffered from high data transfer costs and sorting bottlenecks. Early work by Röttger et al. extended projected tetrahedra for hardware-accelerated rendering using 3D texture mapping [S1, unofficial]. Later developments, such as Hardware-Assisted Projected Tetrahedra (HAPT), leveraged GPU geometry shaders to decompose tetrahedra into triangles on-the-fly, enabling single-pass rendering without CPU-side triangle generation [S2, unofficial]. Hardware-Assisted Polyhedron Projection generalized this approach to arbitrary convex polyhedra, supporting distributed-memory systems and flexible data distribution [S2][S3, unofficial].
