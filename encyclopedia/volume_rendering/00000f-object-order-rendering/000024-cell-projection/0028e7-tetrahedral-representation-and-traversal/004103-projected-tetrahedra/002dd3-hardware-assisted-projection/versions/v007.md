# Hardware-Assisted Projection
## Overview
Hardware-Assisted Projection is a family of volume rendering techniques that project 3D geometric primitives (tetrahedra, polyhedra, or hexahedra) onto the 2D image plane and utilize the graphics hardware's rasterization and texture mapping pipelines to perform scan conversion and compositing [S1][S4, unofficial]. It solves the problem of efficiently rendering complex, non-unstructured meshes by avoiding the irregular memory access patterns of raycasting, instead relying on global or local sorting of cells and hardware-accelerated interpolation [S1][S4, unofficial]. Unlike sibling methods that may use local sorting or additive accumulation, this family generally requires explicit depth sorting of cells to ensure correct alpha blending, though specific variants like Absorption-Only Radiography bypass this by leveraging the commutativity of addition [S1][S4, unofficial].

## Shared principles
All methods in this family share the core mechanism of projecting 3D cells into screen space and using hardware rasterization to evaluate the volume rendering integral per pixel [S1][S4, unofficial].

1.  **Projection**: 3D vertices are transformed into 2D screen coordinates using view-projection matrices [S2, unofficial].
2.  **Rasterization**: The projected primitives are converted into fragments/pixels by the hardware [S1].
3.  **Interpolation**: Scalar values (extinction coefficients) and geometric attributes (thickness) are interpolated across the primitive [S1].
4.  **Opacity Calculation**: Opacity is a non-linear function of the optical thickness. To avoid Mach bands caused by linear interpolation of transparency, hardware texture mapping is used to perform exponential lookup [S1].
    *   For constant extinction coefficient $\tau$, the transparency is $T = \exp(-l \cdot \tau)$, where $l$ is the ray segment length [S1].
    *   The product $l \cdot \tau$ is used as a 1D texture coordinate, or $(l, \tau)$ as a 2D coordinate for varying $\tau$ [S1].
5.  **Compositing**: Fragments are composited using alpha blending (Porter-Duff over operation) [S2, unofficial]. This requires the cells to be processed in back-to-front order for correct accumulation, unless the rendering regime is absorption-only [S1][S4, unofficial].

## Subtopics

### [Hardware-Assisted Polyhedron Projection](1453-hardware-assisted-polyhedron-projection.md)
Projects arbitrary convex polyhedral cells, subdividing the 2D projection into regions where optical thickness varies linearly. It requires explicit global back-to-front sorting and uses a winged-edge subdivision structure to manage complex projections. Choose this for general unstructured grids with arbitrary convex cells.

### [Hardware-Assisted Projected Tetrahedra](1729-hardware-assisted-projected-tetrahedra.md)
A highly efficient single-pass GPU method that streams sorted tetrahedra as point primitives, decomposing them into triangles in a geometry shader. It uses partial pre-integration tables to handle arbitrary transfer functions. Choose this for high-performance rendering of tetrahedral meshes where GPU memory is a constraint.

### [Röttger 3D Texture Mapping](7896-r-ttger-3d-texture-mapping.md)
Extends projected tetrahedra by pre-computing integration results into a 3D texture map (approximated as 2D). It allows arbitrary non-linear transfer functions without artifacts. Choose this when accurate rendering with complex, non-linear transfer functions is required.

### [Absorption-Only Radiography via Unsorted Hexahedron Projection](10255-absorption-only-radiography-via-unsorted-hexahedron-projecti.md)
Simulates radiographs in the absorption-only regime ($J=0$) for curvilinear hexahedral meshes. It avoids global sorting by accumulating optical thickness additively in a P-buffer. Choose this for X-ray simulation where emissivity is zero and hexahedral meshes are used.

## Background
The family originates from the need to accelerate volume rendering on unstructured grids using available graphics hardware. The foundational concept of projecting tetrahedra was introduced by Shirley and Tuchman [S1]. The specific use of hardware texture mapping to handle the non-linear opacity function (preventing Mach bands) was detailed by Röttger et al. [S1]. Subsequent developments extended these principles to arbitrary polyhedra [S4, unofficial] and optimized them for GPU architectures using geometry shaders and pre-integration [S2, unofficial][S3, unofficial]. The absorption-only variant leverages the commutativity of addition to remove sorting bottlenecks [S1, unofficial].
