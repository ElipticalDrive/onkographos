# Hardware-Assisted Projected Tetrahedra

Also called: CellFast algorithm, Hardware CellFast

## Overview
Hardware-Assisted Projected Tetrahedra (HAPT) is a flexible, highly efficient volume rendering method for unstructured tetrahedral meshes that performs the entire rendering pipeline on the GPU in a single pass [S1, unofficial][S2, unofficial]. It builds on [Hardware-Assisted Projection](5625-hardware-assisted-projection.md) by streaming sorted tetrahedra as point primitives, decomposing them into triangles in a geometry shader, and evaluating the volume ray integral per fragment using partial pre-integration [S1, unofficial][S2, unofficial]. Unlike its sibling [Hardware-Assisted Polyhedron Projection](1453-hardware-assisted-polyhedron-projection.md) which may require auxiliary graph structures, HAPT processes each tetrahedron independently, avoiding GPU memory limits and auxiliary data storage [S1, unofficial][S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Unstructured tetrahedral volume data (vertices, connectivity, scalar values per vertex), a transfer function, and a camera view.
*   **Output:** A 2D image with depth-integrated opacity and color.

**Data Structures:**
*   **Tetrahedron Stream:** Each tetrahedron is represented as a single point primitive sent to the GPU. The point's position is one vertex of the tetrahedron. The other three vertices are passed as texture coordinates (or attributes). The scalar value of the position vertex is passed as the `w` coordinate of the point [S2, unofficial].
*   **Sorting Buffer:** An array of indices representing the visibility order of tetrahedra. This can be stored in a Vertex Buffer Object (VBO) or CPU memory [S2, unofficial].

**Algorithm Steps:**

1.  **Visibility Sorting:**
    Sort the tetrahedra back-to-front relative to the camera. Methods include:
    *   **Centroid Sorting (Approximate):** Sort by the centroid of each tetrahedron. Fast, but introduces ordering errors [S2, unofficial].
    *   **Exact Sorting (e.g., MPVONC):** Uses adjacency lists and face normals. Accurate but requires significant CPU memory (approx. 4x volume size) and may fail in degenerate cases [S2, unofficial].
    *   **GPU Sorting:** CUDA-based Quicksort or Bitonic Sort. Bitonic sort requires power-of-two array sizes [S2, unofficial].

2.  **Streaming and Vertex Shader (VS):**
    *   Stream the sorted tetrahedra indices to the GPU.
    *   For each tetrahedron, the VS receives the point primitive.
    *   **Early Discard (Optional):** If rendering time-varying data, discard tetrahedra where all four vertices map to zero opacity in the transfer function [S2, unofficial].

3.  **Geometry Shader (GS) - Decomposition and Classification:**
    *   Decompose the point primitive into triangles representing the projected tetrahedron.
    *   **Classification:** Determine the projection case (1-4) using PTINT's classification strategy. This involves computing four cross products and a table lookup to identify "thick" and "thin" vertices [S2, unofficial].
        *   **Thick Vertex:** The entry point where the ray traverses the maximum distance $l$. Its scalar value ($s_f, s_b$) may need interpolation, and $l$ may need calculation if it is not an edge length [S2, unofficial].
        *   **Thin Vertices:** The other projected vertices. For these, $s_f = s_b$ (original scalar value) and $l = 0$ [S2, unofficial].
    *   **Attribute Computation:** Compute $l$, $s_f$ (scalar front), and $s_b$ (scalar back) for each vertex of the generated triangles.
    *   **Encoding:** Store $s_f$, $s_b$, and $l$ as RGB color attributes for each vertex to pass to the fragment shader [S2, unofficial].
    *   **Iso-surface Extraction (Optional):** If rendering iso-surfaces, extract the surface within the GS and send it as one or two triangles with face normals [S2, unofficial].

4.  **Rasterization and Fragment Shader (FS) - Ray Integration:**
    *   Rasterize the triangles. Interpolate $s_f$, $s_b$, and $l$ per fragment [S2, unofficial].
    *   **Partial Pre-Integration:** Compute the ray integral using the interpolated values.
        *   Map $s_f$ and $s_b$ to colors using the transfer function.
        *   Use $l$ and the mapped colors as indices to access a pre-computed partial pre-integration table [S2, unofficial].
        *   The table lookup returns the accumulated opacity and color for the fragment [S2, unofficial].
    *   **Compositing:** Fragments are composited using alpha blending (Porter-Duff over operation) in back-to-front order [S1, unofficial].

**Pseudocode:**

```python
# Pre-computation (CPU/Application)
# 1. Sort tetrahedra indices using chosen method (e.g., CUDA Quicksort)
indices = sort_tetrahedra(tetrahedra, camera_view)

# 2. Create VBO with sorted indices
vbo = create_vbo(indices)

# GPU Pipeline Execution (Per Frame)

# Vertex Shader
def vertex_shader(tet_index):
    # Retrieve tetrahedron data from global memory or VBO
    tet = get_tetrahedron(tet_index)
    
    # Early discard for time-varying data
    if all_transfer_function_zero(tet.vertices):
        return discard
    
    # Send as point primitive
    # Position: tet.vertices[0]
    # Texture Coords: tet.vertices[1], tet.vertices[2], tet.vertices[3]
    # W: transfer_function(tet.vertices[0].scalar)
    return point(tet.vertices[0], [tet.vertices[1], tet.vertices[2], tet.vertices[3]], transfer_function(tet.vertices[0].scalar))

# Geometry Shader
def geometry_shader(point):
    # Decompose tetrahedron into triangles
    # Use PTINT classification to determine projection case
    case = classify_projection(point.position, point.texture_coords)
    
    triangles = []
    for vertex in case.vertices:
        # Determine if thick or thin
        if vertex.is_thick:
            # Interpolate scalar and compute length l
            sf, sb = interpolate_scalars(vertex, point)
            l = compute_traversal_length(vertex, point)
        else:
            # Thin vertex
            sf = vertex.scalar
            sb = vertex.scalar
            l = 0.0
            
        # Encode as RGB color
        # R = sf, G = sb, B = l (normalized/scaled appropriately)
        color = encode(sf, sb, l)
        triangles.append(create_triangle(vertex.position, color))
        
    return triangles

# Fragment Shader
def fragment_shader(triangle_color):
    # Interpolate sf, sb, l across the triangle
    sf = triangle_color.r
    sb = triangle_color.g
    l = triangle_color.b
    
    # Map scalars to colors using transfer function
    color_front = transfer_function(sf)
    color_back = transfer_function(sb)
    
    # Partial Pre-Integration Lookup
    # Index 1: l (traversal length)
    # Index 2: combination of color_front and color_back
    opacity, color = lookup_preintegration_table(l, color_front, color_back)
    
    return (color, opacity)

# Rasterizer
# Composites fragments back-to-front using alpha blending
```

## Subtopics

### [Tetrahedral Projection with Partial Pre-integration](1861-tetrahedral-projection-with-partial-pre-integration.md)
A hybrid method that projects tetrahedra and computes fragment colors using pre-integrated optical depth tables. It solves the performance bottleneck of explicit isosurface extraction by computing isosurfaces per fragment within the rendering pipeline. Unlike HAPT, PTINT uses a two-pass approach and requires reading data back from the GPU, whereas HAPT performs the entire algorithm in a single GPU pass.

## Operating characteristics
**Time and Memory Complexity:**
*   **Sorting:** Centroid sorting is $O(N \log N)$ but approximate. Exact sorting (MPVONC) is more expensive and requires $O(N)$ auxiliary memory (adjacency lists, face normals) [S2, unofficial].
*   **Rendering:** Single pass through the GPU pipeline. Each tetrahedron is processed independently, making it scalable with GPU parallelism [S1, unofficial].
*   **Memory:** Low GPU memory consumption. Tetrahedra are streamed, so the entire volume does not need to reside in VRAM. This allows rendering of volumes with several million tetrahedra that would fail in methods like HARC or PTINT which require storing the entire volume in GPU memory [S1, unofficial][S2, unofficial].

**Measured Performance:**
*   Hardware: Intel Xeon E5345 CPU, 4 GB RAM, GeForce 8800 GTX (768 MB VRAM) [S3, unofficial].
*   **Blunt Fin (187K Tet):** 19.2 FPS (Direct Volume Rendering) [S3, unofficial].
*   **Oxygen Post (513K Tet):** 8.1 FPS [S3, unofficial].
*   **Turbulent Jet (1M Tet/frame, 150 frames):** 17.5 FPS [S3, unofficial].
*   **SPX2 (828K Tet):** 6.11 M Tet/s (Quicksort) [S3, unofficial].
*   **Torso (1.08M Tet):** 5.6 FPS (HAPTQ), 6.08 M Tet/s [S3, unofficial].
*   **Fighter (1.40M Tet):** 4.2 FPS (HAPTQ), 5.83 M Tet/s [S3, unofficial].

**Strengths and Limitations:**
*   **Strengths:** High performance (>6 M Tet/s), low GPU memory usage, supports direct and indirect (iso-surface) rendering, handles time-varying data efficiently [S1, unofficial][S2, unofficial].
*   **Limitations:** Centroid sorting introduces visual errors (avg ~1 RGB unit, max 1.2-5.1% depending on dataset) compared to exact sorting [S2, unofficial]. Requires a geometry shader. Flat shading for iso-surfaces unless adjacency info is carried, which impacts performance [S2, unofficial].

## Background
HAPT was introduced by André Maximo, Ricardo Marroquim, and Ricardo Farias in 2010, published in the Journal of Computer Graphics Techniques [S3, unofficial]. It is grounded on the original Projected Tetrahedra (PT) algorithm [ST90] and aims to exploit programmable graphics hardware by replacing software-based rasterization and integration with GPU shaders [S3, unofficial].
