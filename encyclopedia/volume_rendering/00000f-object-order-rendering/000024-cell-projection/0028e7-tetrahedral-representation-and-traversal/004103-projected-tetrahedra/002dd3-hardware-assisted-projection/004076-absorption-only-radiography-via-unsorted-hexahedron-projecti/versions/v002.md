# Absorption-Only Radiography via Unsorted Hexahedron Projection

Also called: Unsorted Hexahedron Projection, Absorption-Only Radiography

## Overview
A hardware-accelerated technique to simulate radiographs in the absorption-only regime (emissivity $J=0$) for curvilinear hexahedral meshes, avoiding the need for a global back-to-front visibility sort by accumulating optical thickness additively [S1, unofficial]. Unlike its siblings [Hardware-Assisted Polyhedron Projection](1453-hardware-assisted-polyhedron-projection.md) and [Hardware-Assisted Projected Tetrahedra](1729-hardware-assisted-projected-tetrahedra.md), which generally require depth sorting to correctly composite transparent volumes using alpha blending, this method exploits the commutative property of addition in the absorption-only recurrence to render cells in any order [S1, unofficial].

## How it works
**Inputs:** A curvilinear hexahedral mesh (or tetrahedral mesh for degenerate cases), extinction coefficients $K_\nu$ for one or more X-ray wavelength bands, and a view-projection matrix.
**Outputs:** A radiograph image representing the accumulated optical thickness (attenuation) per pixel.

**Data Structures:**
1.  **Mesh Data:** Vertices with 3D coordinates; hexahedral cells defined by 8 vertices.
2.  **Pre-computed Cell Data:** For each cell, the "thickness" parameter is computed in software using the cell's geometry. This value represents the path length or geometric factor required to compute attenuation.
3.  **P-Buffer:** A floating-point off-screen buffer (texture) aligned with the image plane, storing the accumulated attenuation sum. Initialized to zero.
4.  **Vertex Attributes:** For each projected vertex, the attenuation value $A_v = K_\nu \times \text{thickness}$.

**Numbered Steps:**

1.  **Cell Classification and Triangulation:**
    For each hexahedral cell in the mesh:
    *   Check if the projection of each of the 6 faces is a convex quadrilateral.
    *   Check if the cell is non-degenerate (no coinciding vertices).
    *   If both conditions are met, define the cell as a "hexahedron" primitive. Use the method of Max [12] to define triangle fans or strips for the projection.
    *   If the cell is degenerate or has non-convex face projections, subdivide it into tetrahedra. Use the method of Shirley and Tuchman [16] to divide the image plane projection of each tetrahedron into triangle fans for hardware rendering. [S1, unofficial]

2.  **Attenuation Calculation (Software):**
    For each vertex $v$ of the cell(s), compute the vertex attenuation $A_v$:
    $$ A_v = K_\nu \times \text{thickness}_v $$
    where $\text{thickness}_v$ is derived from the geometry of the cell in software [S1, unofficial].

3.  **Projection and Rasterization:**
    Project the 3D vertices of the triangulated cell(s) to 2D screen coordinates using the view-projection matrix. Rasterize the resulting triangles.

4.  **Fragment Shader Accumulation:**
    For each fragment generated by the rasterizer:
    *   Interpolate the vertex attenuation values $A_v$ from the triangle's vertices to obtain the local attenuation $A_{frag}$ for the current cell.
    *   Read the current accumulated attenuation $I_{acc}$ from the P-Buffer (image-aligned texture) at the fragment's screen position.
    *   Compute the new accumulated attenuation:
        $$ I_{new} = I_{acc} + A_{frag} $$
    *   Write $I_{new}$ back to the P-Buffer. [S1, unofficial]

5.  **Buffer Management:**
    Because writes to output buffers are not guaranteed to be in polygon order and texture caching does not account for textures changing on the fly, the P-Buffer must be copied to a texture to keep it current for the next iteration or pass. To minimize slow copy operations, render as many non-overlapping cells as possible in a single pass before copying. This may involve multiple passes where non-overlapping subsets of cells are rendered [S1, unofficial].

6.  **Final Image Generation:**
    After all cells are processed, the P-Buffer contains the total optical thickness $\tau_{total}$ for each pixel. The final intensity $I_V$ is computed from the initial intensity $I_0$ (source intensity) using the Beer-Lambert law:
    $$ I_V = I_0 e^{-\tau_{total}} $$
    This step can be performed in a final post-processing pass or by interpreting the P-Buffer values directly if the application handles the exponential mapping [S1, unofficial].

**Formulas:**
The recurrence for absorption-only radiography ($J_\nu = 0$) is:
$$ I_V[i+1] = e^{-\tau[i]} I_V[i] $$
where $I_V[i]$ is the intensity at cell $i$, and $\tau[i]$ is the optical thickness of cell $i$. Solving this recurrence results in a simple product of exponential terms, which is equivalent to a sum of optical thicknesses:
$$ I_V = I_0 \prod_i e^{-\tau[i]} = I_0 e^{-\sum_i \tau[i]} $$
Thus, accumulating $\tau[i]$ additively is sufficient [S1, unofficial].

**Parameters:**
*   **Parallelism:** Four different X-ray wavelength bands can be accumulated in parallel using the red, green, blue, and alpha channels of the P-Buffer [S1, unofficial].
*   **Precision:** 32-bit floating point accuracy is required for the attenuation computation. Standard framebuffer compositing may not support this, necessitating the use of a floating-point P-buffer and fragment program [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Degenerate Cells:** Hexahedral cells with coinciding vertices must be subdivided into tetrahedra [S1, unofficial].
*   **Non-Convex Projections:** If the projection of any face of a hexahedron is non-convex, the cell must be subdivided into tetrahedra [S1, unofficial].
*   **Gaps/Overlaps:** If subdivided tetrahedra share non-planar faces with adjacent non-subdivided cells, gaps or overlaps in viewing ray segments may occur, introducing small errors in total absorption [S1, unofficial].
*   **Performance:** Copying the P-Buffer to a texture is slow. Rendering overlapping cells in a single pass requires careful management to avoid incorrect accumulation due to lack of depth sorting. Multiple passes of non-overlapping cells are recommended to minimize copies [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of cells, $O(N)$, where $N$ is the number of hexahedra/tetrahedra. The cost per cell is dominated by rasterization and fragment shader execution.
*   **Memory Complexity:** $O(N)$ for mesh storage. $O(W \times H)$ for the P-Buffer, where $W, H$ are image dimensions.
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Scales well with parallelism due to the additive nature of the accumulation. Four wavelength bands can be processed in parallel using RGBA channels.
*   **Strengths:** No global depth sorting required. Direct projection of curvilinear hexahedra saves mesh storage and rendering time compared to tetrahedral subdivision. Floating-point accuracy is maintained.
*   **Limitations:** Limited to absorption-only regime ($J=0$). Degenerate or non-convex cells require subdivision, potentially increasing complexity. Texture copying overhead if many overlapping cells are rendered.
*   **When to use:** Industrial and medical X-ray simulation where self-emission is negligible and high performance is needed for large hexahedral meshes.
*   **When not to use:** When emissivity is significant, or when high-fidelity transparency with complex lighting requires depth-sorted compositing.

## Background
This method originates from the work on hardware-accelerated simulated radiography for industrial and medical settings [S1, unofficial]. It builds on the polyhedron projection method and leverages the commutative property of addition to bypass the need for back-to-front sorting, which is typically required for transparent volume rendering. The technique utilizes the method of Max for hexahedron projection and Shirley and Tuchman for tetrahedron projection.
