# Texture-Encoded Isosurfacing

Also called: Modified HAVS for isosurfaces, Texture-Encoded Isosurface Extraction

## Overview
Texture-Encoded Isosurfacing is a GPU-based technique for extracting isosurfaces from unstructured tetrahedral grids by using 2D texturing hardware to compute intersections [S1, unofficial][S2, unofficial]. It sets itself apart from sibling methods like [Projected Tetrahedra](877-projected-tetrahedra.md) by using the decomposition step of the PT algorithm to create smaller tetrahedra instead of triangles, then projecting their front and back faces to leverage a checkerboard texture for intersection computation [S1, unofficial][S2, unofficial].

## How it works
**Inputs:** Unstructured tetrahedral grid, scalar field values at vertices, and an isosurface threshold $T$ [S1, unofficial][S2, unofficial].
**Outputs:** Rasterized image containing the isosurface [S1, unofficial][S2, unofficial].
**Data Structures:** A 2D checkerboard texture initialized with a checkerboard pattern; for smooth or multiple isosurfaces, it stores shading values and requires further partitioning of the texture domain [S1, unofficial][S2, unofficial]. A stencil buffer for visibility management [S1, unofficial][S2, unofficial].
**Parameters:** Isosurface threshold $T$ [S1, unofficial][S2, unofficial]. Texture resolution is not specified in the sources [S1, unofficial][S2, unofficial].
**Formulas:** Not given in the sources.
**Steps:**
1. **Decomposition:** Apply the decomposition step of the PT algorithm to divide tetrahedra into smaller tetrahedra instead of triangles [S1, unofficial][S2, unofficial].
2. **Projection:** Project the front and back faces of each smaller tetrahedron onto screen space, resulting in either a degenerate triangle or the same triangle [S1, unofficial][S2, unofficial].
3. **Texture Encoding:** Associate a checkerboard 2D texture with the projected triangles; the coincidence of the front and back face projections allows intersection computation to proceed using 2D texturing hardware [S1, unofficial][S2, unofficial].
4. **Sampling:** Extract the isosurface by sampling the 2D texture with texture coordinates corresponding to the front and back face scalar values [S1, unofficial][S2, unofficial].
5. **Compositing:** Use the stencil buffer and XOR operations to handle visibility and resolve overlaps in two passes, where the first pass sets the stencil buffer [S1, unofficial][S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Degenerate Triangles:** The projection of front and back faces can result in degenerate triangles, which the GPU rasterizer must handle correctly [S1, unofficial][S2, unofficial].
*   **Precision:** The accuracy of the isosurface extraction depends on the resolution of the checkerboard texture and the precision of the texture sampling [S1, unofficial][S2, unofficial].
*   **Multiple Isosurfaces:** Handling multiple isosurfaces requires further partitioning of the texture domain and storing additional shading values, which increases complexity [S1, unofficial][S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources [S1, unofficial][S2, unofficial].
*   **Memory Complexity:** Depends on the size of the checkerboard texture and the number of tetrahedra [S1, unofficial][S2, unofficial].
*   **Performance:** The algorithm runs in two passes and renders an average of 5 to 7 triangles per tetrahedron [S1, unofficial][S2, unofficial].
*   **Strengths:** Renders fewer faces per tetrahedron and leverages 2D texturing hardware for intersection computation [S1, unofficial][S2, unofficial].
*   **Limitations:** Extensions for smooth shading and multiple isosurfaces require more complex texture setups and domain partitioning [S1, unofficial][S2, unofficial].
*   **When to use:** Suitable for real-time isosurface extraction on unstructured grids where GPU acceleration is available [S1, unofficial][S2, unofficial].

## Background
Texture-Encoded Isosurfacing is a revised version of the HAVS (Hardware-Accelerated Volume Rendering) algorithm adapted for isosurface extraction [S1, unofficial][S2, unofficial]. It was proposed in reference [58] as an alternate solution to render fewer faces per tetrahedron by using the decomposition step of the PT algorithm to create smaller tetrahedra instead of triangles [S1, unofficial][S2, unofficial]. The method is discussed in the survey "A Survey of GPU-Based Volume Rendering of Unstructured Grids" [S1, unofficial][S2, unofficial]. It represents one of the first solutions to map isosurface computation onto the GPU using programmable hardware, sharing the underlying framework with volume rendering visibility computations [S1, unofficial][S2, unofficial].
