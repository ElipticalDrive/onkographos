# High Accuracy Volume Rendering for Unstructured Data

Also called: Exact Volume Rendering for Unstructured Data, HIAC System, High Accuracy Volume Renderer for Unstructured Data

## Overview
High Accuracy Volume Rendering (HIAC) is a software-based cell projection renderer designed for high-quality batch-mode generation of images from unstructured finite element data [S1, unofficial]. It solves the problem of rendering complex, non-convex, or disconnected meshes with mathematical exactness, avoiding the approximations typically introduced for efficiency [S2, unofficial]. Unlike its siblings, which may prioritize interactivity or approximate sampling, HIAC guarantees high accuracy by using exact solutions for radiance integrals and interpolation, extending hardware-assisted projection to arbitrary convex polyhedra [S2, unofficial].

## How it works
**Inputs:** Unstructured mesh data containing cells of type linear or quadratic tetrahedra, bricks, prisms, wedges, or pyramids; scalar or vector field data associated with vertices; camera parameters; and lighting model parameters.
**Outputs:** A high-fidelity 2D image.

**Data Structures:**
The system relies on a visibility ordering algorithm to determine the front-to-back or back-to-front traversal of cells. For mixed cell types, the system internally handles tetrahedra with high accuracy, while other convex polyhedra (bricks, prisms, wedges, pyramids) are projected and composited using hardware acceleration [S2, unofficial].

**Steps:**
1.  **Visibility Ordering:** Compute the exact visibility order of all cells relative to the viewpoint. A revised algorithm is used to correct previous inaccuracies and dramatically increase efficiency [S2, unofficial].
2.  **Load Balancing:** Partition the volumetric data set using a Kd-tree structure to distribute cells across processing nodes, ensuring balanced workload [S1, unofficial].
3.  **Projection:** Project the 3D cells onto the 2D image plane. For tetrahedra, this is done with high accuracy. For arbitrary convex polyhedra, hardware-assisted projection is extended from tetrahedra to these shapes [S2, unofficial].
4.  **Interpolation and Integration:**
    *   For linear tetrahedra, use exact mathematical solutions for interpolation [S2, unofficial].
    *   For quadratic tetrahedra, use exact mathematical solutions for interpolation [S2, unofficial].
    *   Compute radiance integrals using exact mathematical solutions whenever possible [S2, unofficial].
5.  **Subpixel Accumulation:** For cells that project to a size smaller than a pixel, use subpixel accumulation by splatting to avoid sampling errors [S2, unofficial].
6.  **Compositing:** Composite the projected and shaded cells according to the visibility order.
7.  **Isosurface Embedding:** Accurate semi-transparent shaded isosurfaces may be embedded within the volume rendering process [S2, unofficial].
8.  **Parallelization:** Distribute the sorting step of the visibility ordering among several nodes to parallelize the rendering [S1, unofficial].

**Pseudocode:**
```python
def render_hiach(mesh, fields, camera, light_model):
    # 1. Visibility Ordering
    # Uses a revised accurate visibility ordering algorithm
    # Includes correction and efficiency improvements [S2, unofficial]
    ordered_cells = compute_visibility_order(mesh, camera)

    # 2. Load Balancing
    # Kd-partitioning ensures load balancing [S1, unofficial]
    partitions = kd_partition(ordered_cells)

    # 3. Parallel Processing
    # Distribute sorting step among nodes [S1, unofficial]
    # Note: The actual rendering/compositing is done per partition
    results = []
    for partition in partitions:
        partition_image = render_partition(partition, fields, camera, light_model)
        results.append(partition_image)

    # 4. Composite Results
    final_image = composite(results)
    return final_image

def render_partition(cells, fields, camera, light_model):
    image = create_empty_image()
    for cell in cells:
        # 5. Projection
        # Hardware-assisted projection extended to arbitrary convex polyhedra [S2, unofficial]
        projected_cell = project_to_screen(cell, camera)

        # 6. Interpolation and Integration
        # Exact mathematical solutions for radiance integrals and interpolation [S2, unofficial]
        if cell.type == 'linear_tet' or cell.type == 'quadratic_tet':
            radiance = exact_radiance_integral(cell, fields, light_model)
        else:
            # Mixed cell types handled but not with high accuracy [S2, unofficial]
            radiance = approximate_radiance_integral(cell, fields, light_model)

        # 7. Subpixel Accumulation
        # For very small cells, use splatting to avoid sampling error [S2, unofficial]
        if projected_cell.area < threshold:
            splat_subpixel_accumulation(image, projected_cell, radiance)
        else:
            rasterize_and_composite(image, projected_cell, radiance)

    # 8. Isosurface Embedding
    # Accurate semi-transparent shaded isosurfaces embedded [S2, unofficial]
    embed_isosurfaces(image, mesh, fields)

    return image
```

**Parameters:**
*   **Accuracy Mode:** High accuracy is enforced for linear and quadratic tetrahedra. Mixed cell types (bricks, prisms, wedges, pyramids) are supported but not with high accuracy [S2, unofficial].
*   **Subpixel Threshold:** Not given in the sources.

**Edge Cases:**
*   **Non-convex/Disconnected Meshes:** The system handles these, but requires conversion to convex meshes (e.g., via Delaunay triangulation) for accurate processing [S2, unofficial].
*   **Very Small Cells:** Handled via subpixel splatting to prevent sampling error [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** The system is computationally intensive. Rendering a 512x512 viewport takes up to one minute on an SGI Onyx with four processors [S1, unofficial]. Even with 128 processors on an SGI Onyx2, it takes over two seconds [S1, unofficial].
*   **Memory Complexity:** Not given in the sources.
*   **Strengths:** Very high accuracy; exact mathematical solutions for integrals and interpolation; handles complex unstructured meshes (non-convex, disconnected, mixed types).
*   **Limitations:** Not intended for interactive purposes; slow performance even on high-end hardware; approximations are introduced for mixed cell types (not high accuracy).
*   **When to Use:** Batch-mode rendering where image quality is paramount and performance is secondary.
*   **When Not to Use:** Interactive applications or real-time rendering.

## Background
The HIAC system was developed by Williams, Max, and Stein in 1998 [S2, unofficial]. It was designed as a benchmark system for comparison, where all mathematical operations are described in detail [S1, unofficial]. Later, Bennett et al. parallelized the HIAC system by distributing the sorting step of the visibility ordering among several nodes, using Kd-partitioning for load balancing [S1, unofficial]. The system is particularly suited for finite element data [S2, unofficial].
