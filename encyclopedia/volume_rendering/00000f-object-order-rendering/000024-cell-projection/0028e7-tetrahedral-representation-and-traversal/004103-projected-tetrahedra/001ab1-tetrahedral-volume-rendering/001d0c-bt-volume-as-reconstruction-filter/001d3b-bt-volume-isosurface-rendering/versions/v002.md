# BT Volume Isosurface Rendering

Also called: BT Volume Representation, BT Volumes, Bezier Tetrahedra Volume Rendering

## Overview
BT Volume Isosurface Rendering is a real-time technique for rendering exact isosurfaces from volumetric data by representing the volume as a grid of cubic Bezier Tetrahedra (BT) [S1]. It solves the problem of low-quality, faceted surfaces produced by linear reconstruction methods like Marching Cubes, while avoiding the computational cost of generating and rendering explicit triangle meshes [S1]. Unlike its sibling [BT Volume Construction](1421-bt-volume-construction.md), which focuses on generating the BT data structure from a reconstruction filter, this method focuses on the rendering pipeline: performing local ray tracing within each tetrahedron inside a GPU pixel shader to find exact intersections with arbitrary isosurface levels [S1].

## How it works

### Inputs and Outputs
*   **Input:** A BT Volume data structure containing a grid of tetrahedra, where each tetrahedron has an associated set of 20 Bezier weights. The volume space is assumed to be a cuboid with integer dimensions [S1].
*   **Output:** A 2D image where each pixel displays the color of the isosurface intersection, or background if no intersection exists [S1].

### Data Structures
The volume is divided into unit cubes (voxels) [S1]. Each voxel is subdivided into tetrahedra using a canonical mapping $\kappa$ [S1]. The implementation described in the source uses the standard 6-tetrahedron decomposition of a cube [S1].

For each tetrahedron $T$ in the grid, the following data is stored:
1.  **Bounding Tetrahedron Vertices ($T$):** Four points $T = (T_1, T_2, T_3, T_4)$ defining the spatial bounds [S1]. These are typically the integer grid vertices of the voxel [G].
2.  **Bezier Weights ($w_{ijkl}$):** A set of 20 scalar weights [S1]. The indices $i, j, k, l$ are non-negative integers such that $i + j + k + l = 3$ [S1]. These weights define the scalar field value distribution within the tetrahedron [S1].

### Canonical Mapping
The volume space is partitioned into voxels $c_{l,m,n}$ indexed by integer coordinates $(l, m, n)$ [S1]. A canonical mapping function $\kappa$ maps a point's fractional position within a voxel to a specific tetrahedron index $h$ within that voxel [S1].

$$ \kappa : [0, 1]^3 \rightarrow \{h : h \in H\} $$

where $H$ is the set of tetrahedron indices for a single voxel (e.g., $H = \{1, ..., 6\}$ for the standard decomposition) [S1]. The mapping must be shift-invariant, meaning the decomposition pattern is identical for every voxel [S1].

Given a point $Q \in \mathbb{R}^3$, the specific BT $\tau$ containing $Q$ is determined by:

$$ \tau = BT_{[\mathbf{Q}]}(\kappa(\mathbf{Q} - [\mathbf{Q}])) $$

where $[\mathbf{Q}]$ is the integer voxel index containing $Q$ [S1].

### Rendering Algorithm
The rendering is performed via local ray tracing within the GPU pixel shader [S1]. For each pixel, a ray is cast into the volume. The algorithm iterates through the tetrahedra intersected by the ray [S1].

1.  **Ray-Tetrahedron Intersection:** For each tetrahedron $T$ intersected by the ray, compute the intersection points of the ray with the isosurface defined by the BT within $T$ [S1].
2.  **Bezier Evaluation:** The scalar value $b(\mathbf{P})$ at any point $\mathbf{P}$ inside the tetrahedron is calculated using the BT formula [S1].
3.  **Root Finding:** The intersection with the isosurface value $V_{iso}$ is found by solving for the roots of the univariate polynomial equation derived from the BT formula along the ray parameter $t$ [S1].

#### Bezier Tetrahedron Formula
For a point $\mathbf{P} = (x, y, z, 1)$ in projective space, the barycentric coordinates $r = (r, s, t, u)$ are calculated as:

$$ r = (r, s, t, u) = \mathbf{P} \cdot T^{-1} $$

where $T$ is the $4 \times 4$ matrix formed by the homogeneous coordinates of the vertices $T_1, T_2, T_3, T_4$ [S1].

The value of the BT at $\mathbf{P}$ is:

$$ b(\mathbf{P}) = \sum_{i+j+k+l=3} w_{ijkl} \binom{3}{i,j,k,l} r^i s^j t^k u^l $$

where $\binom{3}{i,j,k,l} = \frac{3!}{i!j!k!l!}$ is the multinomial coefficient [S1].

#### Ray Intersection Implementation
Let the ray be defined by origin $\mathbf{O}$ and direction $\mathbf{D}$. A point on the ray is $\mathbf{R}(t) = \mathbf{O} + t\mathbf{D}$.

1.  Substitute $\mathbf{R}(t)$ into the barycentric coordinate formula to express $r, s, t, u$ as linear functions of $t$.
2.  Substitute these linear functions into the BT formula. This results in a cubic polynomial in $t$:
    $$ P(t) = \sum_{i+j+k+l=3} w_{ijkl} \binom{3}{i,j,k,l} r(t)^i s(t)^j t(t)^k u(t)^l - V_{iso} = 0 $$
3.  Solve for the real roots of $P(t)$ within the range of the tetrahedron's intersection with the ray.
4.  The smallest positive root $t$ corresponds to the entry point of the isosurface.

### Edge Cases and Pitfalls
*   **Boundary Points:** Points exactly on the boundary between tetrahedra can be considered as covered by either adjacent BT. The rendering logic must handle this consistently to avoid gaps or double-rendering [S1].

## Operating characteristics

### Time and Memory Complexity
*   **Memory:** The memory footprint is proportional to the number of tetrahedra in the volume. Each tetrahedron stores 4 vertices and 20 weights. This is comparable to standard voxel storage but with higher per-voxel overhead due to the tetrahedral decomposition and Bezier weights [S1].
*   **Time:** The rendering time per pixel depends on the number of tetrahedra the ray intersects. For each intersection, a cubic polynomial must be solved. This is generally faster than marching cubes for high-resolution volumes because it avoids mesh generation and traversal overhead, but it can be slower than simple voxel ray marching if the isosurface is sparse and many tetrahedra are traversed without intersection [S1].

### Measured Performance
*   The method is designed for real-time interactive rendering on graphics hardware [S1].
*   It allows rendering any isosurface level without additional precomputation work [S1].

### Strengths and Limitations
*   **Strengths:**
    *   Renders exact isosurfaces directly in the pixel shader, avoiding triangle mesh generation [S1].
    *   Supports arbitrary isosurface levels without additional work [S1].
    *   Provides high-quality reconstruction filtering with arbitrary footprints and kernels [S1].
    *   Smooth surfaces compared to linear reconstruction methods like Marching Cubes [S1].
*   **Limitations:**
    *   Requires precomputation of the BT Volume from the source data or reconstruction filter [S1].
    *   Cubic polynomial solving can be computationally expensive per tetrahedron compared to linear intersection tests [S1].
    *   The method assumes the volume can be effectively approximated by cubic Bezier Tetrahedra [S1].

## Background

### Origin
Bezier Tetrahedra were originally developed by Loop and Blinn [2006] for rendering on graphics hardware [S1]. This paper extends that work to volume rendering, introducing BT Volumes as a representation for volumetric functions [S1].

### History and Development
The method was presented in 2008 as a solution to the limitations of Marching Cubes, which relies on linear reconstruction and produces faceted surfaces [S1]. The approach leverages the tensor form of BTs to allow efficient transformation and evaluation on GPUs [S1].

### Applications
Applications include hurricane visualization, medical diagnosis and planning, and smoke and particle systems [S1].
