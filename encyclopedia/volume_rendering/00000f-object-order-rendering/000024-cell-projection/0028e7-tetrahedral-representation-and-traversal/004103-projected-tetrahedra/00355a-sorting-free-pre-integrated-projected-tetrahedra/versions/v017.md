# Sorting-free Pre-integrated Projected Tetrahedra

Also called: Pre-integrated Projected Tetrahedra, Sorting-free approach that controls the fragment rendering by using the opacity value, Sorting-free technique for volume rendering of an irregular volume dataset

## Overview
Sorting-free Pre-integrated Projected Tetrahedra (PBVR) is a stochastic volume rendering technique for irregular volume datasets that eliminates the need for explicit back-to-front visibility sorting [S1]. It solves the scalability issues of conventional sorting-based methods and the low image quality (visible footprints) of particle-based methods by treating volume rendering as a stochastic process where sampling points occur along a viewing ray with probability equal to opacity [S1]. Unlike its sibling [Cell projection](26-cell-projection.md), which typically requires sorting, PBVR controls fragment rendering directly via opacity, allowing it to handle large-scale irregular volumes distributed across multiple computing nodes without global visibility calculations [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** An irregular volume dataset decomposed into tetrahedral cells, each with vertex scalar values and associated particle luminosity/density parameters.
*   **Output:** A rendered image representing the ensemble average of brightness values.

**Data Structures:**
The method relies on the standard projected tetrahedra representation defined in [Cell projection](26-cell-projection.md). Each tetrahedron is defined by 4 vertices in 3D space. During projection, these vertices are mapped to 2D screen coordinates. The subdivision of the image plane into polygons is performed as described in the parent article [Cell projection](26-cell-projection.md), where projected edges divide the plane into regions lying within the projection of a single front-facing and single back-facing face [S1, S2].

**Core Optical Model:**
PBVR employs a "density emitter model" where the 3D scalar field is characterized as a varying density emitter with a single level of scattering [S1]. The opacity is derived from the number of particles in a unit volume, assuming the number of particles follows a Poisson distribution [S1].

**Parameters:**
*   $N$: The repetition level (number of stochastic passes).
*   $c_k$: Particle luminosity in the $k$-th ray segment.
*   $\rho$: Particle density (number of particles in a unit volume).
*   $\Delta t$: Ray-segment length.
*   $r$: Effective radius of a particle (used in the Poisson term $\pi r^2 \rho \Delta t$).

**Algorithm Steps:**
The rendering calculation is repeated $N$ times. In each repetition, the image is composited without alpha-blending, relying on stochastic sampling to achieve semi-transparency [S1].

1.  **Subdivision:** Subdivide the viewing ray into segments where particle luminosity ($c_k$) and density ($\rho_k$) are constant [S1].
2.  **Opacity Calculation:** For each segment $k$, calculate the opacity $\tau_k$ based on the Poisson distribution assumption. The term $\pi r^2 \rho \Delta t$ expresses the expected number of particles in the ray segment [S1].
    $$ \tau_k = 1 - e^{-\pi r^2 \rho_k \Delta t} $$
    [S1]
3.  **Stochastic Fragment Rendering:** For each fragment generated by the rasterized projected tetrahedra:
    *   Generate a random number $u$ uniformly distributed in $[0, 1]$.
    *   Compare $u$ with the calculated opacity $\tau_k$ for the corresponding ray segment [S1].
    *   If $u > \tau_k$, discard the fragment (the ray passed through without hitting a "particle") [S1].
    *   If $u \le \tau_k$, render the fragment with its luminosity/color value [S1].
4.  **Accumulation:** Repeat steps 1-3 for $N$ repetitions.
5.  **Ensemble Average:** Calculate the final pixel value by averaging the brightness values accumulated from all $N$ repetitions [S1].

**Pseudocode:**
```python
def render_pbvr(tetrahedra, camera, num_repetitions):
    """
    Renders an irregular volume using Sorting-free Pre-integrated Projected Tetrahedra.
    
    Args:
        tetrahedra: List of tetrahedra, each containing 4 vertices with scalar values.
        camera: Camera object with projection matrix and view direction.
        num_repetitions: N, the number of stochastic passes.
        
    Returns:
        image: 2D array of final averaged brightness values.
    """
    # Initialize image buffer for accumulation
    # Dimensions match the target resolution
    image_buffer = zeros(camera.resolution)
    
    for rep in range(num_repetitions):
        # Create a temporary buffer for this repetition
        # Initialize to 0 or background color
        current_frame = zeros(camera.resolution)
        
        # Process each tetrahedron
        for tet in tetrahedra:
            # 1. Project vertices to screen space
            projected_vertices = [project_to_screen(v, camera) for v in tet.vertices]
            
            # 2. Subdivide the image plane based on projected edges
            # This creates polygons where each polygon lies within the projection
            # of a single front-facing and single back-facing face.
            # See [Cell projection](26-cell-projection.md) for subdivision details.
            polygons = subdivide_image_plane(projected_vertices)
            
            # 3. Rasterize and compute opacity for each polygon
            for poly in polygons:
                # Determine the ray segment length and density for this polygon
                # The density rho and luminosity c are assumed constant within the segment
                # corresponding to this polygon's depth range.
                # In a full implementation, this requires mapping screen coordinates
                # back to 3D ray segments to get rho and c.
                rho, c, segment_length = get_segment_properties(tet, poly, camera)
                
                # Calculate opacity using the density emitter model
                # tau = 1 - exp(-pi * r^2 * rho * delta_t)
                # Note: r is the effective particle radius.
                # If r is not explicitly given, it is absorbed into the density parameter
                # or assumed to be 1 for normalized density.
                # The source uses pi*r^2*rho*Delta_t as the exponent term.
                particle_count_expectation = 3.14159 * (r**2) * rho * segment_length
                opacity = 1.0 - exp(-particle_count_expectation)
                
                # Stochastic sampling
                # Generate random number for each pixel in the polygon
                for pixel in poly.pixels:
                    u = random_uniform(0, 1)
                    
                    # If random number <= opacity, the "particle" is hit
                    if u <= opacity:
                        # Render the fragment with luminosity c
                        # Color is determined by the scalar value at the hit point
                        # mapped via a transfer function.
                        # For simplicity, we assume c represents the final color contribution.
                        current_frame[pixel.x][pixel.y] += c
                    # Else: discard fragment (add 0)
        
        # Accumulate the result of this repetition
        for x in range(camera.resolution[0]):
            for y in range(camera.resolution[1]):
                image_buffer[x][y] += current_frame[x][y]
                
    # Final ensemble average
    final_image = image_buffer / num_repetitions
    
    return final_image
```

**Edge Cases and Pitfalls:**
*   **Precipitous Transfer Functions:** PBVR may generate an insufficient number of particles when the density function changes drastically, leading to artifacts compared to methods like SPT [S1].
*   **Memory Consumption:** Performance is greatly influenced by the number of pixels. Increasing image resolution affects the number of particles processed, making the method memory-consuming [S1].
*   **Convergence:** The error decreases with the number of repetitions $N$. Insufficient $N$ leads to noisy images [S1].

## Operating characteristics
*   **Time Complexity:** The computational complexity of the basic brightness calculation is $O(n^2)$ if intermediate brightness values are considered [S1]. The total time is proportional to $N \times (\text{number of cells} + \text{number of pixels})$ [S1].
*   **Memory Complexity:** Memory usage is influenced by the image resolution and the number of particles. It is more memory-efficient than Hardware-Assisted Visibility Sorting (HAVS), which requires memory space for sorting cell faces about twice that for tetrahedral cells [S1].
*   **Measured Performance:** On an NVIDIA GeForce 9600GT, PBVR rendered ~10 million particles at 25.7 milliseconds per repetition with 1024x1024 resolution [S1]. On an Intel Core 2 Quad 2.83 GHz with an Nvidia GeForce GTX 280, it handled large-scale CSM and CFD simulation results [S1].
*   **Strengths:** No visibility sorting required; scalable to large-scale irregular volumes distributed across multiple nodes; avoids artifacts from insufficient k-buffer sizes associated with HAVS [S1].
*   **Limitations:** High memory consumption at high resolutions; sensitive to drastic changes in density functions; requires multiple repetitions for high-quality images [S1].
*   **When to Use:** Suitable for large-scale irregular volumes where visibility sorting is impractical or impossible (e.g., distributed computing environments) and when particle-based methods produce visible footprints [S1].
*   **When Not to Use:** When real-time performance is critical and $N$ must be small, or when the density function changes drastically and high fidelity is required (SPT may be better) [S1].

## Background
The Sorting-free Pre-integrated Projected Tetrahedra (PBVR) technique was introduced to address the limitations of conventional volume rendering methods that require visibility sorting, which is difficult for large-scale irregular volumes [S1]. It was developed as an improvement over particle-based volume rendering (PBVR) which suffers from low image quality and visible footprints, and over projected tetrahedra methods which require sorting [S1]. The method is based on the density emitter model and the Poisson distribution of particles [S1].
