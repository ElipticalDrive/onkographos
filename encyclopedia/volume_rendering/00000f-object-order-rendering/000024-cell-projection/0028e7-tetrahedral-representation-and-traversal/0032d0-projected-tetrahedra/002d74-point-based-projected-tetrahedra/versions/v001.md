# Point-based Projected Tetrahedra

Also called: Hardware-Assisted Point-Based Volume Rendering, Point-Based Volume Rendering of Tetrahedral Meshes, Point-based footprint rendering

## Overview
Point-based Projected Tetrahedra (PBVR) is a technique for interactively visualizing large, unstructured tetrahedral meshes by approximating each tetrahedron with a single point primitive [S1]. It decouples footprint generation and reshaping from the compositing stage, using hardware shaders to reshape the point into a circle or ellipsoid and composite fragments based on ray-gap distances rather than pre-assigned alpha values [S1]. Unlike [Projected Tetrahedra](877-projected-tetrahedra.md), which generates and sorts triangles, PBVR avoids connectivity processing and convolution operations, making it robust against malformed tetrahedra and efficient for sub-pixel elements [S1].

## How it works
**Inputs and Outputs:**
- Input: An unstructured tetrahedral mesh with vertex-centered or cell-centered scalar data.
- Output: A rendered image of the volume.

**Data Structures:**
For each tetrahedron $i$, the following precomputed data is stored:
1.  **Affine Transformation Matrix $T_i$**: A $4 \times 4$ matrix mapping the unit tetrahedron $\hat{\sigma}$ (inscribed in the unit sphere, centered at the origin) to the target tetrahedron $\sigma_i$.
2.  **Point Location $v_i$**: The 3D position of the point representing the tetrahedron, calculated as the transformed barycenter of the unit tetrahedron: $v_i = T_i \cdot \hat{c}$, where $\hat{c}$ is the barycenter of $\hat{\sigma}$.
3.  **Scalar Value $s_i$**:
    - If vertex-centered: The mean of the scalar values at the tetrahedron's four vertices.
    - If cell-centered: The scalar value assigned to the cell.
4.  **Normal Information (Optional)**: Gradients of the scalar field calculated during preprocessing for shading models [S1].

**Numbered Steps:**

1.  **Preprocessing (CPU):**
    - For each tetrahedron $\sigma_i$:
        - Compute the affine transformation $T_i$ such that $T_i(\hat{\sigma}) = \sigma_i$.
        - Calculate the point location $v_i = T_i \cdot \hat{c}$.
        - Assign the scalar value $s_i$ (mean of vertices or cell value).
        - (Optional) Calculate gradients for normal information [S1].

2.  **Per-Frame CPU (Sorting and LOD):**
    - Sort all points front-to-back based on the depth of their centroids $v_i$ relative to the current viewpoint.
    - Determine the Level-of-Detail (LOD) for the current frame. This may involve compromising accuracy for speed during camera interaction and switching to full-quality after interaction stops [S1].

3.  **Per-Frame GPU (Vertex Shader):**
    - For each point in the sorted list:
        - Use the precomputed transformation $T_i$ to re-size the point primitive. The point size is determined by the size of the tetrahedron and the distance from the viewpoint [S1].
        - Pass the center of the point and the radius (for circular footprints) or ellipsoid parameters to the fragment program via texture coordinates [S1].

4.  **Per-Frame GPU (Fragment Shader - Culling):**
    - For each fragment generated by the rasterized point:
        - If using **Circular Footprints**: Cull fragments that fall outside the specified radius in screen-space [S1].
        - If using **Ellipsoidal Footprints**: Cull fragments based on the shape of the approximating ellipsoid. The ellipsoid is the minimum-volume enclosing ellipsoid of the tetrahedron. The transformation $T$ maps the unit sphere (min-volume ellipsoid of the unit tetrahedron) to this target ellipsoid. Fragments are culled if they lie outside this ellipsoid [S1].

5.  **Per-Frame GPU (Compositing):**
    - Keep one fragment in a texture.
    - Composite the ray-gap between the current fragment and the previous fragment using a pre-integrated table.
    - Compositing is performed using fragment distances, not pre-assigned alpha values, to mitigate over-representation error [S1].

**Formulas:**
- **Transformation**: $T_i(\hat{\sigma}) = \sigma_i$. The unit tetrahedron $\hat{\sigma}$ is inscribed in the unit sphere and centered at the origin [S1].
- **Point Location**: $v_i = T_i \cdot \hat{c}$, where $\hat{c}$ is the barycenter of $\hat{\sigma}$ [S1].
- **Conditional Probability**: For a convex volume $A$ contained in $B$, the probability that a random ray hitting $B$ also hits $A$ is $p(A|B) = \frac{s_A}{s_B}$, where $s_A$ and $s_B$ are the surface areas of $A$ and $B$ respectively. To maximize this probability, $s_B$ (the surface area of the enclosing ellipsoid) must be minimized [S1].
- **Min-Volume Ellipsoid**: The minimum-volume enclosing ellipsoid is used as an approximation for the minimum-surface-area ellipsoid. The volume of any shape is scaled by the determinant of $T$. Since the unit sphere is the min-volume ellipsoid for the unit tetrahedron, $T$ maps the unit sphere to the min-volume ellipsoid of the target tetrahedron [S1].

**Parameters:**
- **Point Size**: Determined by the size of the tetrahedron and the distance from the viewpoint [S1].
- **Circular Footprint Parameters**: Center of the point and radius in screen-space, passed via texture coordinates [S1].
- **LOD Strategy**: Can be global or adaptive. Interaction mode may compromise accuracy for speed [S1].

**Edge Cases and Pitfalls:**
- **Sub-pixel Tetrahedra**: Standard triangular/quadrilateral primitives are not optimal for sub-pixel sized areas due to connectivity overhead. PBVR solves this by using single points [S1].
- **Boundary Quality**: Accuracy degrades at boundaries because the single-point representation lacks scalar interpolation across the tetrahedron. This limits accurate pixel values when depth complexity is low [S1].
- **Malformed Tetrahedra**: While Hardware-Assisted Visibility Sorting (HAVS) fails on malformed tetrahedra, PBVR remains robust and does not fail under these conditions [S1].
- **Wide Size Variation**: If tetrahedra sizes vary widely, large tetrahedra generate many fragments unnecessarily. Testing and branching in the fragment program for culling can be expensive [S1].

**Pseudocode:**

```python
# Preprocessing (CPU)
def preprocess_mesh(tetrahedra):
    points = []
    for tet in tetrahedra:
        # Compute affine transformation T from unit tetrahedron to tet
        T = compute_affine_transform(tet)
        
        # Compute point location (transformed barycenter of unit tetrahedron)
        # Assuming unit tetrahedron barycenter is at origin or known constant c_hat
        c_hat = get_unit_tetrahedron_barycenter()
        v = transform_point(T, c_hat)
        
        # Assign scalar value
        if tet.data_type == 'vertex_centered':
            s = mean(tet.vertex_scalars)
        else:
            s = tet.cell_scalar
        
        # Optional: Compute normal for shading
        normal = compute_gradient_normal(tet)
        
        points.append({
            'T': T,
            'v': v,
            's': s,
            'normal': normal
        })
    return points

# Per-Frame Rendering
def render_frame(points, viewpoint, lod_strategy):
    # Sort points front-to-back based on centroid depth
    sorted_points = sort_points_by_depth(points, viewpoint)
    
    # Determine LOD
    active_points = lod_strategy.select_points(sorted_points)
    
    # GPU Vertex Shader
    for point in active_points:
        # Resize point primitive based on T and distance
        point_size = compute_point_size(point['T'], viewpoint)
        
        # Pass parameters to fragment shader
        # For circular footprint: center and radius
        # For ellipsoidal footprint: ellipsoid parameters derived from T
        pass_to_fragment(point, point_size)
        
    # GPU Fragment Shader
    # Compositing loop
    previous_fragment = None
    for fragment in rasterized_fragments:
        # Cull based on footprint shape (circle or ellipsoid)
        if not is_inside_footprint(fragment, point['footprint_params']):
            continue
            
        # Composite with previous fragment using pre-integrated table
        # Distance-based compositing
        if previous_fragment is not None:
            composite_result = pre_integrated_composite(
                previous_fragment, 
                fragment, 
                fragment.distance_to_previous
            )
            previous_fragment = composite_result
        else:
            previous_fragment = fragment
            
    return previous_fragment
```

## Subtopics

### Circular Footprints
Approximates the tetrahedron with a circle. Simpler culling but may produce more overdraw than ellipsoidal footprints. Choose when computational simplicity is prioritized over minimal overdraw [S1].

### Ellipsoidal Footprints
Approximates the tetrahedron with the minimum-volume enclosing ellipsoid. Reduces overdraw and improves image quality. Choose when higher visual fidelity is required and the cost of ellipsoid culling is acceptable [S1].

## Operating characteristics
- **Time Complexity**: Preprocessing is $O(N)$ where $N$ is the number of tetrahedra. Per-frame sorting is $O(N \log N)$. Rendering is $O(N)$ points, but fragment generation depends on footprint size and LOD.
- **Memory Complexity**: $O(N)$ for storing point data (T, v, s). No connectivity storage required [S1].
- **Measured Performance**: Achieves interactive framerates for large datasets (e.g., Heart, SPX, fighter, F16) [S1].
- **Scaling**: Accuracy scales with approximation complexity. Higher approximation (ellipsoidal) yields better visual fidelity but increases fragment generation and decreases performance compared to circular or unshaped points [S1].
- **Strengths**: Robust to malformed tetrahedra; no connectivity processing; efficient for sub-pixel elements; flexible LOD; decoupled footprint/compositing [S1].
- **Limitations**: Boundary quality degradation due to lack of scalar interpolation; potential for excessive fragment generation if tetrahedra sizes vary widely; culling branching cost [S1].
- **When to Use**: Interactive visualization of large, unstructured tetrahedral meshes, especially those with sub-pixel elements or malformed tetrahedra [S1].
- **When Not to Use**: When exact boundary representation is critical and depth complexity is low; when tetrahedra sizes vary widely and fragment culling cost is prohibitive [S1].
