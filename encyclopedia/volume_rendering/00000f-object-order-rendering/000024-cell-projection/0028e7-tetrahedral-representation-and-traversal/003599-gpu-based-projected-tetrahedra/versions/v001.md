# GPU-based Projected Tetrahedra

Also called: Two-Shader PT, Vertex Shader PT, Tetrahedral Projection using Vertex Shaders

## Overview
GPU-based Projected Tetrahedra (PT) is a direct volume rendering method for unstructured tetrahedral data that achieves interactive rates by leveraging programmable graphics hardware to perform classification, decomposition, and rasterization [S1, S2, S3, unofficial]. It differs from traditional ray casting by avoiding explicit per-pixel ray-tetrahedron intersection tests, instead treating each tetrahedron as a distinct primitive and using hardware rasterization and blending to compute pixel color [S1, unofficial]. It builds on [Cell projection](26-cell-projection.md) by mapping the geometric computations of the PT algorithm directly into the GPU's vertex and fragment shaders, eliminating the need for pre-processing or additional data structures on the CPU [S1, S2, S3, unofficial].

## How it works
The method implements the Projected Tetrahedra algorithm using two primary shader stages: a vertex shader for geometric classification and decomposition, and a fragment shader for rendering [S1, unofficial]. The core challenge is that GPUs cannot dynamically change the topology of graphics primitives; therefore, the method sends a fixed topology for all tetrahedra, known as the "basis graph" [S2, S3, unofficial].

### Inputs and Outputs
*   **Input:** A tetrahedral mesh where each tetrahedron is defined by four vertices. Each vertex carries scalar field values (and potentially other attributes like position).
*   **Output:** A 2D image (framebuffer) with accumulated color and opacity.

### Data Structures
*   **Basis Graph:** A fixed topology consisting of five vertices: the four actual vertices of the tetrahedron ($v_1, v_2, v_3, v_4$) and one "phantom" vertex ($v_p$) [S2, S3, unofficial].
*   **Primitive Type:** Triangle fan [S2, S3, unofficial].
*   **Vertex Attributes:** Position, scalar value, and any other necessary attributes for the four real vertices. The phantom vertex's attributes are computed or interpolated by the vertex shader.

### Numbered Steps

1.  **Data Upload:** Store the tetrahedral model in texture memory or vertex buffers. No pre-processing of the data or additional data structures are required [S1, unofficial].
2.  **Primitive Submission:** For each tetrahedron in the mesh, send the four vertices and an invalid/placeholder phantom vertex to the GPU as a single triangle fan primitive [S2, S3, unofficial].
3.  **Vertex Shader Classification:**
    *   The vertex program receives the four vertices and the phantom vertex.
    *   It performs a series of geometric tests (e.g., determining which faces are front-facing and back-facing relative to the camera) to classify the cell's orientation [S2, S3, unofficial].
    *   Based on the classification, the vertices are mapped to the basis graph topology.
4.  **Phantom Vertex Calculation:**
    *   The vertex shader calculates the position and attributes of the phantom vertex.
    *   The position of the phantom vertex is determined by linearly interpolating the vertices of the tetrahedron to find the "thickness" or depth extent of the cell at the projection center [S2, S3, unofficial].
    *   Specifically, the thickness $l$ at the phantom vertex is derived from the linear interpolation of the vertex depths [S2, S3, unofficial].
5.  **Attribute Assignment:**
    *   Using the calculated thickness $l$ and the scalar values at the vertices, the color and differential opacity ($\kappa$) for the phantom vertex are assigned.
    *   This is typically done via a lookup table or texture lookup based on the thickness and scalar value [S2, S3, unofficial].
    *   The integrated opacity $\alpha$ for the segment is computed per pixel using the formula from [Cell projection](26-cell-projection.md):
        $$ \alpha = 1 - e^{-\kappa_{avg} l} $$
        where $\kappa_{avg}$ and $l$ are interpolated across the polygon [S1, S2, unofficial].
6.  **Rasterization:**
    *   The modified faces (defined by the basis graph) are rasterized [S2, S3, unofficial].
    *   Fragment shaders compute the final color and opacity for each pixel covered by the projected tetrahedron.
    *   The method employs two fragment shaders: one for computing the tetrahedra projections (handling the non-linear opacity integration) and another for rendering the elements (compositing) [S1, unofficial].
7.  **Compositing:**
    *   The rasterized fragments are composited into the framebuffer using back-to-front sorting, which is handled implicitly by the depth buffer and blending operations [S2, S3, unofficial].

```python
# Vertex Shader: GPU-based Projected Tetrahedra
# Input: 4 vertices (v1..v4) with positions and scalar values, 1 phantom vertex (vp)
# Output: Transformed vertices for triangle fan rasterization

def vertex_shader(v1, v2, v3, v4, vp):
    # 1. Geometric Classification
    # Determine front/back facing faces based on camera view vector
    # This determines the "classification" of the tetrahedron
    classification = classify_tetrahedron(v1, v2, v3, v4)
    
    # 2. Map to Basis Graph
    # The basis graph always has 5 vertices: v1, v2, v3, v4, vp
    # The order in the triangle fan is fixed by the hardware requirement
    
    # 3. Calculate Phantom Vertex Position
    # Linearly interpolate to find the thickness/depth at the center
    # The exact interpolation depends on the classification
    # Typically, vp is placed at the centroid or a specific projection point
    vp_pos = interpolate_thickness(v1, v2, v3, v4, classification)
    
    # 4. Calculate Phantom Vertex Attributes
    # Interpolate scalar values to get average scalar at vp
    scalar_vp = interpolate_scalar(v1, v2, v3, v4, classification)
    
    # 5. Assign Color and Opacity to Phantom Vertex
    # Use lookup table or texture based on scalar_vp and thickness
    # Thickness is derived from the depth difference between front and back faces
    thickness = get_thickness(v1, v2, v3, v4, classification)
    
    # Lookup color and differential opacity (kappa)
    color_vp, kappa_vp = lookup_transfer_function(scalar_vp, thickness)
    
    # Return the 5 vertices for the triangle fan
    return [v1, v2, v3, v4, vp_pos]

# Fragment Shader: Rendering
# Input: Interpolated attributes across the triangle
# Output: Final color and opacity

def fragment_shader(interpolated_color, interpolated_kappa, interpolated_thickness):
    # Compute integrated opacity alpha
    # alpha = 1 - exp(-kappa_avg * thickness)
    alpha = 1.0 - exp(-interpolated_kappa * interpolated_thickness)
    
    # Compute color contribution
    # Color is already interpolated, but may need to be weighted by alpha
    color = interpolated_color * alpha
    
    return color, alpha
```

### Edge Cases and Pitfalls
*   **Topology Constraints:** Current GPUs cannot change the topology of graphics primitives. The method must always send the most general topology (the basis graph with 5 vertices) [S2, S3, unofficial].
*   **Data Persistence:** No data can be saved across vertex primitives. Each primitive must be sent with all relevant data structures [S2, S3, unofficial].
*   **Precision:** Linear interpolation of opacity $\alpha$ causes derivative discontinuities due to the nonlinear exponential. The method avoids this by interpolating $\kappa_{avg}$ and $l$ and using a 2D texture lookup for $\alpha$ [S1, S2, unofficial].

## Subtopics

### Cell Projection with 3D/2D Textures
A variant that stores color and opacity in a 3D texture map computed during pre-processing [S4, unofficial]. This allows concurrent use of transfer functions encoded directly in the texture. To reduce memory usage, the approach can be adapted to use 2D texture maps: one 2D texture stores the linear dependencies of the volume rendering integral with respect to length, and another stores the remaining parts depending only on sample values [S4, unofficial].

### Hardware Caching for Projected Tetrahedra
An optimization that maintains a buffer holding the four vertices of the current tetrahedron and the additional fifth vertex [S5, unofficial]. It swaps vertices in the buffer to follow the direction of the strip and caches edge lengths and face areas, which are required by the PT algorithm and reused by the next tetrahedron in a strip [S5, unofficial]. A pitfall is that computing edge lengths and face areas requires a square root, which impacts running time [S5, unofficial].

### Bunyk Tetrahedral Projection
A hybrid approach that projects the complete mesh onto the screen to simplify the problem from 3D to 2D [S6, unofficial]. It uses precomputed adjacency information for correct accumulation order [S6, unofficial].

## Operating characteristics
*   **Performance:** Capable of rendering over 2.0 M Tet/s on current graphics hardware [S1, unofficial]. Allows interactive viewing of large unstructured datasets on a desktop personal computer [S1, unofficial].
*   **Memory Footprint:** Occupies a substantially smaller memory footprint compared to recent ray-casting approaches [S1, unofficial].
*   **Pre-processing:** Requires no pre-processing of the data and no additional data structures [S1, unofficial].
*   **Strengths:** Interactive rates, competitive with ray-casting, smaller memory footprint, no pre-processing.
*   **Limitations:** Dependent on GPU capabilities (fixed topology), potential precision issues with linear interpolation of opacity if not handled via texture lookup.

## Background
The method was introduced by Wylie et al. in 2002 as an extension of the Projected Tetrahedra algorithm by Shirley and Tuchman [S2, S3, unofficial]. It was designed to leverage programmable vertex shaders on commodity graphics cards to perform classification and decomposition on the GPU [S2, S3, unofficial]. The approach was further refined by Marroquim et al. in 2006, who introduced a two-fragment-shader approach to achieve interactive rates [S1, unofficial].
