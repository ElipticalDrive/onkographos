# MTCut

Also called: GPU-based Marching Tetra Cuts

## Overview
MTCut is a real-time volume cutting algorithm that modifies isosurfaces generated by the Marching Tetrahedra algorithm using a user-defined cutting tool [S1, unofficial]. Unlike traditional tetrahedral mesh cutting strategies that require a pre-computed tetrahedrization of the entire volume, MTCut computes the tetrahedrization of only the intersected cells on-the-fly, enabling interactive performance for complex meshes [S1, unofficial]. It produces a watertight manifold model, distinguishing it from approaches like Zachow et al. [ZGSZ03] that yield open surfaces with borders [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A volume dataset, an isovalue for the initial isosurface, and a cutting tool path represented as a sequence of segments tracked via a haptic device [S1, unofficial].
*   **Output:** A modified watertight manifold triangle mesh representing the cut isosurface [S1, unofficial].

**Data Structures:**
*   **Cutting Information:** A structure passed from the haptic thread to the rendering thread containing the cut path and a list of intersected voxels [S1, unofficial].
*   **Voxel Encoding:** Intersected voxels are encoded in a texture for fragment shader access [S1, unofficial].
*   **Voxel Splitting:** Uses a conformal voxel splitting configuration into 5 tetrahedra per voxel, as described in [ABE+03] [S1, unofficial].

**Rendering Pipeline (Three Steps):**
1.  **Encode Intersected Voxels:** The haptic thread samples the cutting tool [S1, unofficial]. Only one stick (segment) is sampled inside each voxel, and coplanarity of every two consecutive sticks is imposed to ensure a voxel is cut by at most two planes [S1, unofficial]. The voxels traversed by this surface are detected and encoded in a texture [S1, unofficial].
2.  **Discard Intersected Fragments:** A surface-based rendering algorithm draws the original isosurface [S1, unofficial]. A shader discards fragments belonging to voxels identified as intersected by the cutting tool [S1, unofficial].
3.  **Generate Cut Geometry:** The GPU MTCut algorithm generates new geometry for the affected voxels [S1, unofficial].

**MTCut Internal Steps (Per Affected Voxel):**
The algorithm processes each affected voxel by splitting it into 5 tetrahedra [S1, unofficial]. For each tetrahedron, it performs:

1.  **Classification:** Classify the four vertices of the tetrahedron with respect to two criteria: the isovalue (isosurface) and the cutting mesh (cutting surface) [S1, unofficial]. At the voxel level, the cutting surface is approximated by at most two planes [S1, unofficial].
2.  **Vertex Reclassification:** Reclassify vertices to determine if they are "inside" the final isosurface (the volume to be kept) [S1, unofficial].
    *   **Single Plane Cut:** A point is classified as inside if it lies inside the isosurface AND in the positive half-space of the cutting plane [S1, unofficial].
    *   **Two Plane Cut:** Classification depends on the concavity/convexity that the two cutting planes form with respect to the cut direction [S1, unofficial].
3.  **Pattern Calculation & Edge Identification:** Determine which edges of the tetrahedron are intersected by the final isosurface based on the reclassified vertex signs [S1, unofficial].
4.  **Vertex Generation:** Determine new vertex positions for triangulation [S1, unofficial].
    *   If an edge is cut *only* by the cutting plane, place the vertex at the intersection of the plane with the edge [S1, unofficial].
    *   If an edge is traversed by *both* the isosurface and the cutting plane, place the new vertex at the more interior intersection point (closer to the inside) [S1, unofficial].
    *   **Exception:** If the edge is shared with a non-cut voxel, keep the intersection with the isosurface [S1, unofficial].

**Formulas:**
*   **Plane Representation:** A cutting plane is defined by $ax + by + cz + d = 0$ [G]. A point $P$ is inside the cut volume if $aP_x + bP_y + cP_z + d > 0$ [G].
*   **Isosurface Classification:** $S_{iso} = 1$ if $V \ge I$, else $-1$, where $V$ is the vertex value and $I$ is the isovalue [S1, unofficial].
*   **Cut Classification:** $S_{cut} = 1$ if the vertex satisfies the positive half-space condition for all cutting planes in the voxel, else $-1$ [S1, unofficial].
*   **Vertex Reclassification:** $S_{final} = 1$ if $S_{iso} = 1 \land S_{cut} = 1$, else $-1$ [S1, unofficial].
*   **Linear Interpolation (Edge Intersection):** $P_{int} = P_1 + \frac{I - V_1}{V_2 - V_1}(P_2 - P_1)$, where $P_1, P_2$ are edge endpoints and $V_1, V_2$ their scalar values [G].
*   **Line-Plane Intersection:** For segment $P_1 \to P_2$ and plane $ax+by+cz+d=0$, $t = -\frac{aP_{1x} + bP_{1y} + cP_{1z} + d}{a(P_{2x}-P_{1x}) + b(P_{2y}-P_{1y}) + c(P_{2z}-P_{1z})}$ [G]. Intersection exists if $0 \le t \le 1$ [G].

**Parameters:**
*   **Isovalue:** Threshold scalar for isosurface extraction. Typical values depend on the volume dataset's normalization [G].
*   **Cutting Tool Representation:** The tool is represented by a segment [S1, unofficial]. The blade path is approximated by a set of quads formed between two consecutive positions (segments) of the tool, creating a piecewise-bilinear surface [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Crack Generation:** Cracks between the newly created surface and the original isosurface are avoided because the classification of vertices shared between cut voxels and non-cut voxels is never changed [S1, unofficial].
*   **Precision:** The algorithm relies on accurate intersection calculations. Precision issues may arise if the cutting plane is nearly parallel to an edge or if the isovalue is very close to a vertex value [G].
*   **Boundary Conditions:** The haptic sampling condition (one stick per voxel, coplanarity) is critical to guarantee that a voxel is cut by at most two planes [S1, unofficial].

        tets = split_voxel_into_5_tets(voxel, volume_data.grid_spacing) # [G]
        for tet in tets:
            v_pos = [tet.v0, tet.v1, tet.v2, tet.v3]

            # 1. Classification
            iso_signs = [1 if v >= isovalue else -1 for v in v_val]
            cut_signs = classify_by_cutting_planes(v_pos, planes)

            # 2. Vertex Reclassification
            final_signs = []
            for i in range(4):
                if len(planes) == 1:
                    # Inside if inside isosurface AND in positive half-space of cutting plane
                    final_signs.append(1 if (iso_signs[i] == 1 and cut_signs[i] == 1) else -1)
                else:
                    # [G] Two-plane classification depends on concavity/convexity of planes w.r.t cut direction
                    final_signs.append(1 if (iso_signs[i] == 1 and cut_signs[i] == 1) else -1)

            # 3. Edge Identification & 4. Vertex Generation
            edges = [(0,1), (0,2), (0,3), (1,2), (1,3), (2,3)]
            generated_vertices = []
            for e0, e1 in edges:
                p_start, p_end = v_pos[e0], v_pos[e1]
                val_start, val_end = v_val[e0], v_val[e1]
                shared_with_non_cut = is_edge_shared_with_non_cut_voxel(e0, e1, intersected_voxels) # [G]

                iso_pt = interpolate_isosurface(p_start, p_end, val_start, val_end, isovalue)
                cut_pts = []
                for plane in planes:
                    pt = intersect_plane_with_segment(plane, p_start, p_end)
                    if pt is not None:
                        cut_pts.append(pt)

                if len(cut_pts) == 0:
                    # Edge cut only by isosurface (or not at all)
                    generated_vertices.append(iso_pt)
                elif len(cut_pts) == 1:
                    # Edge cut only by the cutting plane
                    generated_vertices.append(cut_pts[0])
                else:
                    # Edge traversed by both isosurface and cutting plane
                    if shared_with_non_cut:
                        generated_vertices.append(iso_pt)
                    else:
                        # Place at the more interior intersection point (closer to inside)
                        interior_pt = select_interior_point(iso_pt, cut_pts, planes)
                        generated_vertices.append(interior_pt)

            # Triangulate based on final_signs pattern
            triangles = march_tetrahedra_triangulate(final_signs, generated_vertices) # [G]
            new_triangles.extend(triangles)
    return new_triangles

## Operating characteristics
*   **Time Complexity:** Real-time performance is achieved because tetrahedrization is computed only for intersected cells, not the entire volume [S1, unofficial].
*   **Memory Complexity:** Depends on the number of intersected voxels. The entire volume does not need to be tetrahedrized in memory [S1, unofficial].
*   **Measured Performance:** Runs in real time for complex meshes of up to 1.8 million triangles [S1, unofficial].
*   **Strengths:** Real-time interaction, no pre-computed tetrahedrization, watertight manifold output [S1, unofficial].
*   **Limitations:** Requires a haptic device for input (in the described application), approximation of cutting tool as piecewise-bilinear surface [S1, unofficial].

## Background
MTCut was introduced in the paper "MTCut: GPU-based Marching Tetra Cuts" [S1, unofficial]. It addresses the need for real-time volume cutting in computer-aided medical applications, such as osteotomy planning (e.g., LeFort I surgical operation) [S1, unofficial]. It builds on the Marching Tetrahedra algorithm [DK91, YMDO93] and uses conformal voxel splitting [ABE+03] [S1, unofficial]. It contrasts with previous approaches like Zachow et al. [ZGSZ03] (open surfaces) and Pintilie and McInerney [PM03] (limited to shallow cuts) [S1, unofficial].
