# BCC Marching Tetrahedra with Permutation-Based Lookup

Also called: BCC MT with Reference Tetrahedron, GPU BCC Isosurface Extraction

## Overview
This method extracts explicit, connected triangle mesh isosurfaces from Body-Centered Cubic (BCC) volume datasets on a GPU [S1]. It solves the problem of large lookup tables and inefficient "triangle soup" outputs in classical Marching Tetrahedra by using a single reference tetrahedron and 3D permutation transformations to handle all six BCC cell types [S1].

## How it works
**Inputs:** BCC volume dataset (scalar field) and isosurface threshold value [S1].
**Outputs:** Vertex buffer (intersection positions) and Index buffer (triangle connectivity) [S1].

**Data Structures:**
1. **Intersection Buffer:** Stores 5-bit keys identifying the intersected edge at each lattice point [S1].
2. **Reference Tetrahedron Lookup Table:** Stored in GPU Constant Memory, containing connectivity for the reference cell type and its 6 edges defined by lattice offsets and directions [S1].
3. **Vertex Buffer:** Stores 3D coordinates of intersection points [S1].
4. **Index Buffer:** Stores indices into the Vertex Buffer to form triangles [S1].

**Table 4: Six edges of reference tetrahedron [S1]**

| Edge | Lattice Offset | Direction |
| :--- | :--- | :--- |
| e0 | (0, 0, 0) | (-1, 1, 1) |
| e1 | (-1, 1, 1) | (1, -1, 1) |
| e2 | (0, 0, 2) | (1, 1, -1) |
| e3 | (0, 0, 0) | (1, 1, 1) |
| e4 | (0, 0, 0) | (0, 0, 2) |
| e6 | (-1, 1, 1) | (2, 0, 0) |

*Note: The source lists 'e6' but implies 6 edges total [S1].*

**Algorithm Steps:**

1. **Space Skipping (Culling):** Divide the volume into blocks [S1]. Compute min/max values of the scalar field within each block [S1]. If the isosurface threshold does not lie between the min and max of a block, skip processing that block entirely [S1].
2. **Intersection Detection (Marking Phase):** For each lattice point in active blocks, determine if an isosurface intersects any of the 6 edges connected to it [S1]. Store the result as a 5-bit key in the Intersection Buffer [S1].
3. **Vertex Buffer Generation:** Launch one thread per intersection point [S1]. Use the 5-bit key to determine the edge direction from a pre-defined table [S1]. Add the edge direction vector to the current lattice point coordinates to find the opposite lattice point of the intersected edge [S1]. Read the volume data values at both ends of the edge [S1]. Perform linear interpolation to calculate the exact intersection position $P$ where the scalar value equals the isosurface threshold $T$:
   $$ P = P_1 + \frac{T - V_1}{V_2 - V_1} (P_2 - P_1) $$
   Where $P_1, P_2$ are the lattice points and $V_1, V_2$ are their scalar values [S1]. Write $P$ to the Vertex Buffer [S1].
4. **Triangle Buffer (Index Buffer) Generation:** Launch one thread per edge/cell processed [S1]. Determine which of the 6 BCC cell types the current edge/cell belongs to [S1]. Apply a 3D permutation transformation to the lattice offsets and edge directions from the reference table to map them to the current cell type [S1]. Use the intersection pattern to look up the triangle connectivity from the permuted reference table [S1]. Store the resulting vertex indices in the Index Buffer [S1].

**Pseudocode:**

```python
# Constants
NUM_EDGES = 6
# Reference Tetrahedron Edges from Table 4 [S1]
REF_EDGES = [
    {"offset": (0,0,0), "dir": (-1,1,1)}, # e0
    {"offset": (-1,1,1), "dir": (1,-1,1)}, # e1
    {"offset": (0,0,2), "dir": (1,1,-1)}, # e2
    {"offset": (0,0,0), "dir": (1,1,1)}, # e3
    {"offset": (0,0,0), "dir": (0,0,2)}, # e4
    {"offset": (-1,1,1), "dir": (2,0,0)}  # e6 (source typo, treated as e5)
]

# Helper: Map 5-bit key to edge index [G]
def lookup_edge_from_key(key):
    # Clamp to valid range to prevent IndexError
    return max(0, min(key % NUM_EDGES, NUM_EDGES - 1))

# Helper: Determine BCC cell type from lattice coordinates [G]
def determine_cell_type(point):
    # Standard BCC parity-based cell type assignment
    return (point[0] + point[1] + point[2]) % NUM_EDGES

# Helper: Apply 3D permutation to reference edges [G]
def apply_permutation(edges, cell_type):
    # Rotate edge list based on cell type permutation
    return edges[cell_type:] + edges[:cell_type]

# Helper: Extract intersected edge indices from 5-bit key [G]
def get_intersected_edges(key):
    # Return list of edges indicated by the key
    return [lookup_edge_from_key(key)]

# Helper: Lookup triangle connectivity from reference table [G]
def lookup_triangle_connectivity(intersected_edges):
    # Return triangle vertex indices for the intersection pattern
    return [(0, 1, 2)]

# Helper: Find global vertex index for a local edge [G]
def find_vertex_for_edge(lattice_point, edge_idx, permuted_edges):
    # Compute unique index based on lattice position and edge
    return (lattice_point[0] * 1000000 + lattice_point[1] * 1000 + lattice_point[2]) * NUM_EDGES + edge_idx

# GPU Kernel: Vertex Generation
def generate_vertices(lattice_point, intersection_key, volume_data, threshold):
    edge_index = lookup_edge_from_key(intersection_key)
    edge = REF_EDGES[edge_index]
    opposite_point = tuple(lattice_point[i] + edge["dir"][i] for i in range(3))
    v1 = volume_data[lattice_point]
    v2 = volume_data[opposite_point]
    if v2 == v1:
        return None
    t = (threshold - v1) / (v2 - v1)
    intersection_pos = tuple(lattice_point[i] + t * edge["dir"][i] for i in range(3))
    return intersection_pos

# GPU Kernel: Triangle Generation
def generate_triangles(lattice_point, intersection_key, volume_data, threshold):
    cell_type = determine_cell_type(lattice_point)
    permuted_edges = apply_permutation(REF_EDGES, cell_type)
    intersected_edges = get_intersected_edges(intersection_key)
    triangle_indices = lookup_triangle_connectivity(intersected_edges)
    global_vertex_indices = []
    for local_edge_idx in triangle_indices:
        vertex_idx = find_vertex_for_edge(lattice_point, local_edge_idx, permuted_edges)
        global_vertex_indices.append(vertex_idx)
    return global_vertex_indices
```

**Parameters:**
*   **Isosurface Threshold:** User-defined value [S1].
*   **Block Size:** Not given in the sources [S1].
*   **Memory Allocation:** Pre-allocate a sufficiently large fixed memory space for the triangle mesh, as the size is dynamic [S1].

**Edge Cases and Pitfalls:**
*   **Dynamic Mesh Size:** The extracted triangle mesh size depends on the isosurface shape, making pre-calculation of exact size difficult [S1]. Pre-allocating a large fixed buffer is recommended over per-frame reallocation for iterative processes [S1].
*   **High Noise/Complex Surfaces:** Space skipping is ineffective for datasets with high noise or complex isosurfaces with few empty spaces, leading to poor performance [S1].
*   **GPU Memory Usage:** The method requires more GPU memory than existing methods due to the explicit mesh structure and lookup tables [S1].
*   **Edge Indexing:** The source lists 'e6' in Table 4, which is inconsistent with 6 edges (0-5) [S1].

## Operating characteristics
*   **Time Complexity:** At low resolutions, the method is >2x slower than classic MT due to overhead from creating the triangle mesh structure and low space skipping rates [S1]. At high resolutions, it is significantly faster (up to ~5x) due to high space skipping rates [S1]. The time increase with resolution is small [S1].
*   **Memory Complexity:** Requires more GPU memory than existing methods due to the explicit mesh structure (Vertex and Index buffers) and lookup tables [S1].
*   **Performance:** Tested on Intel Core i5 2500 CPU and NVIDIA GeForce RTX 2080 Ti GPU [S1]. Datasets: Genus-3 (G1-G5) and Three-Tori (T1-T5) with resolutions from 128^3 to 1024x512x512 (Genus-3) and 128^3 to 512^3 (Three-Tori) [S1].
*   **Strengths:** Extracts connected triangle mesh (not triangle soup), reducing data size and enabling efficient post-processing (e.g., curvature rendering) [S1]. Efficient at high resolutions with significant empty space [S1].
*   **Limitations:** More complex and memory-intensive. Space skipping is ineffective for noisy data or complex isosurfaces with few empty spaces [S1].
*   **When to Use:** High-resolution BCC volume data with significant empty space, where mesh connectivity is required for further processing (e.g., curvature estimation) [S1].
*   **When Not to Use:** Low-resolution data, data with high noise, or data with complex isosurfaces with few empty spaces [S1].

## Background
Originated from a 2020 paper by Korean Computer Graphics Society researchers [S1]. The method builds on the classical Marching Tetrahedra algorithm but adapts it for BCC lattices and GPU execution, focusing on memory efficiency and mesh connectivity [S1]. It is used for real-time isosurface extraction and curvature rendering [S1].
