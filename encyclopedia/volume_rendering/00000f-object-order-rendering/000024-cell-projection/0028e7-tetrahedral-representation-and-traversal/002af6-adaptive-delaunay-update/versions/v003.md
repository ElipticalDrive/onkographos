# Adaptive Delaunay Update

Also called: Delaunay Update Frequency

## Overview
Adaptive Delaunay Update is a technique used in differentiable volumetric reconstruction to maintain a valid Delaunay tetrahedralization while optimizing vertex positions. It addresses the problem of topological invalidity that arises when vertices move during gradient-based optimization, potentially violating the empty circumsphere property required for Delaunay triangulations. Unlike methods that recompute the triangulation from scratch at every step, this approach updates the topology selectively to balance rendering speed with geometric accuracy [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A current set of tetrahedra $T$ with vertices $V_i$ and scalar attributes, a small vertex displacement $\epsilon$, and an update frequency parameter $k$.
- **Output:** An updated set of tetrahedra $T'$ that satisfies the Delaunay condition (empty circumsphere) for the new vertex positions.

**Data Structures:**
- **Tetrahedron:** Defined by four vertices $V_0, V_1, V_2, V_3$.
- **Circumsphere:** Defined by the center $C$ and radius $R$ such that all four vertices lie on the surface.
- **Adjacency:** Each tetrahedron stores its neighboring tetrahedra to facilitate local checks.

**Parameters:**
- **Update Frequency ($k$):** The number of optimization iterations between full Delaunay re-evaluations. Typical value: $k=10$ [S1, unofficial].

**Steps:**
1. **Vertex Displacement:** During optimization, vertices are moved by a small amount $\epsilon$.
2. **Validity Check:** For each tetrahedron, check if any vertex has entered the circumsphere of a neighboring tetrahedron. This is done by comparing the power distance of the vertex to the circumcenter of the neighbor.
3. **Topological Flip (Pachner Move):** If a violation is detected, perform a local topological flip. In 3D, this involves replacing the shared face between two tetrahedra with a new edge configuration to restore the Delaunay property.
4. **Frequency Control:** The full Delaunay triangulation is recomputed or updated only every $k$ iterations. Between updates, the topology is assumed stable, and only vertex attributes are interpolated [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Nearly Cospherical Points:** Flips involve sets of points that are nearly cospherical because the vertex was already nearby the circumsphere boundary prior to the move. This can lead to numerical instability [S1, unofficial].
- **Performance:** Recomputing the Delaunay triangulation from scratch is slow. For a scene with 1.2 million tetrahedra, the computation takes approximately 92 ms [S1, unofficial].

## Subtopics

### Delaunay Edge Flipping (Pachner Moves)
A method to form a Delaunay triangulation by flipping edges of triangles that are not Delaunay, specifically those where the circumsphere contains a vertex. In 3D, these edge-flips are called Pachner moves [S1, unofficial]. During optimization, if a vertex enters the circumsphere of a neighboring tetrahedron, a topological flip is triggered. This implies the vertex was already nearby the circumsphere boundary, leading to flips involving nearly cospherical points [S1, unofficial].

## Operating characteristics
- **Time Complexity:** The cost of updating the Delaunay triangulation is significant. For 1.2 million tetrahedra, the Delaunay computation takes 92 ms, while rendering takes 19 ms and the backward pass takes 143 ms [S1, unofficial].
- **Memory Complexity:** Not given in the sources.
- **Performance:** On a scene with 1.2 million tetrahedra, the total timing per iteration includes 19 ms for rendering, 13 ms for instant-NGP query, 143 ms for the backward pass, and 92 ms for Delaunay triangulation computation [S1, unofficial].
- **Strengths:** Balances GPU acceleration speed with accuracy by reducing the frequency of expensive topological updates [S1, unofficial].
- **Limitations:** Recomputing the Delaunay triangulation is slow compared to rendering and query operations [S1, unofficial].

## Background
The method is used in the context of Radiance Meshes for Volumetric Reconstruction, which represent radiance fields using constant density tetrahedral cells produced via Delaunay tetrahedralization [S1, unofficial]. It decouples topology (Delaunay mesh) from attribute parameterization (Instant-NGP) to solve the trade-off between optimization dynamics and rendering speed [S1, unofficial]. The concept of using Delaunay triangulation for visibility sorting and volumetric representation is discussed in the supplementary material of the Radiance Meshes paper [S1, unofficial].
