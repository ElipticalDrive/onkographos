# Sorting-free Pre-integrated Projected Tetrahedra

Also called: Pre-integrated Projected Tetrahedra, Sorting-free approach that controls the fragment rendering by using the opacity value, Sorting-free technique for volume rendering of an irregular volume dataset

## Overview
Sorting-free Pre-integrated Projected Tetrahedra (PBVR) is a stochastic volume rendering technique for irregular volume datasets that eliminates the need for explicit back-to-front visibility sorting of tetrahedral cells [S1]. It solves the scalability bottlenecks of conventional projected tetrahedra methods and the low image quality (visible footprints) of particle-based methods by treating rendering as a stochastic process where fragments are rendered with a probability equal to their opacity [S1]. Unlike [Projected Tetrahedra](877-projected-tetrahedra.md), which requires sorting, and [Parallelized Accurate Sorting for Projected Tetrahedra](1128-parallelized-accurate-sorting-for-projected-tetrahedra.md), which relies on hardware-assisted sorting buffers, PBVR achieves semi-transparency through repeated rasterization passes without alpha-blending [S1].

## How it works
**Inputs:** Irregular volume dataset decomposed into tetrahedral cells; vertex scalar values; transfer function mapping scalar to color/extinction; camera parameters.
**Outputs:** Final rendered image (brightness/color per pixel).

**Data Structures:**
The method operates on the projected tetrahedra primitives. Each tetrahedron is defined by 4 vertices in 3D space. During rendering, these are projected to 2D screen space. The rasterizer generates fragments for the projected faces. No explicit sorting data structures (like k-buffers or linked lists) are maintained for visibility [S1].

**Core Optical Model:**
The method uses a "density emitter model" where the 3D scalar field is characterized as a varying density emitter with a single level of scattering [S1]. The opacity is derived from the number of particles in a unit volume, assuming the number of particles follows a Poisson distribution [S1].

**Parameters:**
*   $N$: The repetition level (number of rendering passes). Typical values range from 1 to 144, with higher values reducing error [S1].
*   $\rho$: Particle density (number of particles in a unit volume).
*   $c_k$: Particle luminosity in the $k$-th ray segment.
*   $\Delta t$: Ray-segment length.

**Algorithm Steps:**
The rendering calculation is repeated $N$ times. In each repetition, the image is composited without alpha-blending by controlling fragment visibility stochastically [S1].

1.  **Subdivision:** Subdivide the viewing ray into segments where particle luminosity ($c_k$) and density ($\rho_k$) are constant [S1].
2.  **Opacity Calculation:** Calculate the opacity for each segment based on the Poisson distribution assumption. The opacity $\tau$ for a segment of length $\Delta t$ is:
    $$ \tau = 1 - e^{-\rho \pi r^2 \Delta t} $$
    where $\pi r^2 \rho \Delta t$ expresses the expected number of particles in the ray segment [S1].
3.  **Stochastic Fragment Rendering:** For each fragment generated by the projected tetrahedra:
    a. Evaluate the opacity $\alpha$ of the fragment based on the scalar value at the fragment's position [S1].
    b. Generate a random number $r \in [0, 1]$ [G].
    c. If $r > \alpha$, discard the fragment [S1].
    d. If $r \le \alpha$, render the fragment with its luminosity/color [S1].
4.  **Accumulation:** Repeat steps 1-3 for $N$ repetitions. The final pixel value is the average of the brightness values accumulated from all $N$ repetitions [S1].

**Pseudocode:**
> **Unverified code.** The code below did not pass a test run against a reference implementation, or no test fits it, so it may contain errors.

```python
def render_pbvr(tetrahedra, camera, transfer_function, repetition_level):
    """
    Renders an irregular volume using Sorting-free Pre-integrated Projected Tetrahedra.
    
    Args:
        tetrahedra: List of tetrahedra, each with 4 vertices and scalar values.
        camera: Camera parameters for projection.
        transfer_function: Function mapping scalar value to color and opacity.
        repetition_level: Number of stochastic passes (N).
        
    Returns:
        Image buffer with averaged brightness.
    """
    # Initialize image buffer to zero
    image_width, image_height = camera.resolution
    image_buffer = zeros((image_height, image_width, 3))
    
    for rep in range(repetition_level):
        # Create a temporary buffer for this repetition
        rep_buffer = zeros((image_height, image_width, 3))
        
        # Project and rasterize each tetrahedron
        for tet in tetrahedra:
            # Project vertices to screen space
            projected_vertices = [project(v, camera) for v in tet.vertices]
            
            # Rasterize the projected tetrahedron faces
            # This generates fragments with screen coordinates and interpolated scalars
            fragments = rasterize(projected_vertices, tet.scalars)
            
            for frag in fragments:
                # Get scalar value at fragment position
                scalar_val = frag.scalar_value
                
                # Map scalar to color and opacity using transfer function
                color, opacity = transfer_function(scalar_val)
                
                # Stochastic visibility test
                # Generate random number in [0, 1]
                random_val = random_uniform(0.0, 1.0)
                
                if random_val <= opacity:
                    # Fragment is visible; add its color to the buffer
                    # Note: No alpha blending is performed here
                    x, y = frag.screen_coords
                    rep_buffer[y, x] += color
        
        # Accumulate the result of this repetition into the main buffer
        image_buffer += rep_buffer
    
    # Average over all repetitions
    if repetition_level > 0:
        image_buffer /= repetition_level
        
    return image_buffer
```

**Edge Cases and Pitfalls:**
*   **Precision:** The stochastic nature introduces noise. Low repetition levels result in high variance [S1].
*   **Boundaries:** The method assumes the volume is decomposed into tetrahedra. Concave sub-volumes that fail visibility-order compositing strategies in other methods are handled naturally by the stochastic approach [S1].
*   **Transfer Functions:** The method may generate an insufficient number of particles (fragments) when the density function changes drastically, leading to artifacts in precipitous transfer functions compared to [Parallel Projected Tetrahedra with KD-Tree Partitioning](8767-parallel-projected-tetrahedra-with-kd-tree-partitioning.md) or other sorting-based methods [S1].

## Operating characteristics
**Time and Memory Complexity:**
The computational complexity of the basic brightness calculation is $O(n^2)$ if intermediate brightness values are considered, where $n$ is the number of ray segments [S1]. The overall performance is greatly influenced by the number of pixels (image resolution) and the number of repetitions $N$ [S1]. Memory usage is lower than hardware-assisted sorting methods like [Parallelized Accurate Sorting for Projected Tetrahedra](1128-parallelized-accurate-sorting-for-projected-tetrahedra.md) (HAVS), which requires memory space for sorting cell faces about twice that for tetrahedral cells [S1]. However, PBVR is memory-consuming because the increase in image resolution affects the number of particles (fragments) generated [S1].

**Measured Performance:**
On an NVIDIA GeForce 9600GT, PBVR rendered ~10 million particles at 25.7 milliseconds per repetition with 1024x1024 resolution [S1]. For a 1024x1024 resolution, the estimated computing time is 1.4 seconds per repetition for larger datasets [S1].

**Strengths and Limitations:**
*   **Strengths:** No visibility sorting required, making it scalable for large-scale irregular volumes distributed across multiple computing nodes [S1]. Avoids artifacts caused by insufficient k-buffer size in HAVS [S1]. Handles concave sub-volumes better than visibility-sorting methods [S1].
*   **Limitations:** Performance is heavily dependent on image resolution and repetition level [S1]. May produce insufficient particle counts for drastic density changes, leading to lower quality in precipitous transfer functions compared to [Parallelized Accurate Sorting for Projected Tetrahedra](1128-parallelized-accurate-sorting-for-projected-tetrahedra.md) [S1].

**When to Use:**
Use PBVR for large-scale irregular volume datasets where visibility sorting is a bottleneck or impractical (e.g., distributed computing environments) and when hardware-assisted sorting memory overhead is a concern [S1]. It is preferred over [Projected Tetrahedra](877-projected-tetrahedra.md) when sorting is too expensive, and over [Parallelized Accurate Sorting for Projected Tetrahedra](1128-parallelized-accurate-sorting-for-projected-tetrahedra.md) when memory is limited and the dataset size exceeds ~24 million cells [S1].

**When Not to Use:**
Avoid PBVR when high-quality visualization of precipitous transfer functions is required, as it may generate insufficient fragments in areas of drastic density change [S1]. Also avoid if low latency per frame is critical and high repetition levels are needed to reduce noise.

## Background
**Origin:**
The method was introduced in the paper "Sorting-free pre-integrated projected tetrahedra" [S1]. It was developed to address the limitations of particle-based volume rendering (PBVR) and conventional projected tetrahedra techniques.

**History and Development:**
The technique was proposed as a solution to the low image quality of particle-based methods, specifically the visible footprints when the viewpoint is inside the volume, and the scalability issues of conventional methods that require visibility sorting [S1]. It builds on the concept of treating volume rendering as a stochastic process [S1].

**Where it is used:**
The technique has been applied to large-scale irregular volumes, such as CSM (Computational Solid Mechanics) and CFD (Computational Fluid Dynamics) simulation results [S1].
