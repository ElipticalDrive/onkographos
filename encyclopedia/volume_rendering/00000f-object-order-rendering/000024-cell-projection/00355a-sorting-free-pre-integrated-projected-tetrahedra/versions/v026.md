# Sorting-free Pre-integrated Projected Tetrahedra

Also called: Pre-integrated Projected Tetrahedra, Sorting-free approach that controls the fragment rendering by using the opacity value, Sorting-free technique for volume rendering of an irregular volume dataset

## Overview
Sorting-free Pre-integrated Projected Tetrahedra (PBVR) is a volume rendering technique for irregular datasets that eliminates the need for explicit back-to-front visibility sorting of tetrahedral cells [S1]. It solves the scalability bottlenecks of conventional sorting methods and the visible footprint artifacts of particle-based methods by treating rendering as a stochastic process where fragments are rendered with a probability equal to their opacity [S1]. Unlike [Cell projection](26-cell-projection.md), which typically requires sorting, PBVR achieves semi-transparency through repeated rasterization passes controlled by opacity probabilities, allowing it to handle large-scale irregular volumes distributed across multiple nodes without global visibility calculations [S1].

## How it works
PBVR builds on the [Cell projection](26-cell-projection.md) framework, specifically using projected tetrahedra [S1]. It replaces deterministic alpha-blending with a stochastic sampling approach applied during the rasterization of projected tetrahedral faces [S1].

### Inputs and Outputs
*   **Inputs:**
    *   Irregular volume dataset decomposed into tetrahedral cells [S1].
    *   Scalar field values at tetrahedron vertices [S1].
    *   Transfer function mapping scalar values to density ($\rho$) and luminosity ($c$) [S1].
    *   Camera parameters for projection [S1].
    *   Repetition level $N$ (number of rendering passes) [S1].
*   **Outputs:**
    *   Final accumulated brightness/color image [S1].

### Data Structures
*   **Tetrahedral Mesh:** Standard tetrahedral representation with vertex positions and scalar values [S1].
*   **Projected Geometry:** 2D screen-space polygons derived from projecting tetrahedron faces [S1].
*   **Accumulation Buffer:** Framebuffer used to accumulate brightness values over $N$ repetitions [S1].

### Method Steps
The method operates in two phases: Pre-integration setup and Stochastic Rendering.

#### 1. Pre-integration Setup
Following [Cell projection](26-cell-projection.md), tetrahedra are projected to screen space. The projected edges subdivide the image plane into polygons [S1]. For each polygon, the scalar field is interpolated linearly across the tetrahedron [S1]. The density $\rho$ and luminosity $c$ are derived from the scalar values using the transfer function [S1].

#### 2. Stochastic Rendering Loop
The rendering is performed by repeating the rasterization process $N$ times. In each repetition, fragments are conditionally rendered based on opacity [S1].

**Step 1: Fragment Probability Check**
For each fragment generated by rasterizing a projected tetrahedron face, calculate its opacity $\alpha$ based on the integrated density along the ray segment passing through the tetrahedron [S1]. The opacity is derived from the density emitter model, assuming a Poisson distribution of particles [S1].

The opacity $\alpha$ for a ray segment of length $\Delta t$ with particle density $\rho$ is:
$$ \alpha = 1 - e^{-\rho \cdot \pi r^2 \cdot \Delta t} $$
where $\pi r^2$ represents the cross-sectional area factor inherent to the density emitter model [S1]. In practice, this is often simplified or pre-integrated into a lookup table based on the integrated optical depth $\tau = \rho \cdot \text{length}$ [S1].

**Step 2: Stochastic Sampling**
Generate a random number $r$ uniformly distributed in $[0, 1]$ [S1].
*   If $r > \alpha$, discard the fragment (do not write to the buffer) [S1].
*   If $r \le \alpha$, render the fragment with its calculated luminosity/color [S1].

This step effectively simulates the stochastic process where a sampling point occurs along the viewing ray with probability equal to the opacity [S1]. The luminosity $c_k$ of the fragment is treated as the expected value of the luminosity from the ray segment [S1].

**Step 3: Accumulation**
Repeat Steps 1 and 2 for $N$ repetitions [S1]. After $N$ repetitions, compute the average pixel value across all repetitions to obtain the final brightness [S1].

$$ B_{final} = \frac{1}{N} \sum_{i=1}^{N} B_i $$
where $B_i$ is the brightness value accumulated in the $i$-th repetition [S1].

### Pseudocode
```python
def render_pbvr(tetrahedra, transfer_function, camera, N):
    """
    Render an irregular volume using Sorting-free Pre-integrated Projected Tetrahedra.
    
    Args:
        tetrahedra: List of tetrahedra, each with 4 vertices and scalar values.
        transfer_function: Function mapping scalar s -> (density rho, luminosity c).
        camera: Camera parameters for projection.
        N: Number of stochastic repetitions.
        
    Returns:
        final_image: Accumulated brightness image.
    """
    # Initialize accumulation buffer
    # Not given in the sources. Typically a float buffer of image dimensions.
    accumulation_buffer = zeros(camera.image_width, camera.image_height)
    
    for repetition in range(N):
        # Create a temporary buffer for this repetition
        # Not given in the sources. Typically a float buffer of image dimensions.
        rep_buffer = zeros(camera.image_width, camera.image_height)
        
        # Project and rasterize each tetrahedron
        for tet in tetrahedra:
            # Project vertices to screen space
            projected_vertices = [camera.project(v) for v in tet.vertices]
            
            # Subdivide projected faces into polygons (as per Cell Projection)
            # Not given in the sources. See [Cell projection](26-cell-projection.md) for subdivision logic.
            polygons = subdivide_projected_tetrahedron(projected_vertices)
            
            for poly in polygons:
                # Rasterize polygon to get fragments
                # Not given in the sources. Standard rasterization.
                fragments = rasterize_polygon(poly)
                
                for frag in fragments:
                    # Interpolate scalar value at fragment's 3D position
                    # Not given in the sources. Linear interpolation within tetrahedron.
                    scalar_value = interpolate_scalar(tet, frag.world_position)
                    
                    # Get density and luminosity from transfer function
                    rho, c = transfer_function(scalar_value)
                    
                    # Calculate opacity based on density emitter model
                    # alpha = 1 - exp(-rho * effective_length)
                    # Not given in the sources. Effective length depends on ray-tetrahedron intersection.
                    alpha = 1.0 - exp(-rho * frag.segment_length)
                    
                    # Stochastic sampling
                    random_val = random_uniform(0.0, 1.0)
                    if random_val <= alpha:
                        # Render fragment with luminosity
                        # Not given in the sources. Color mapping from scalar or luminosity.
                        color = c # Or mapped color from transfer function
                        rep_buffer[frag.screen_x][frag.screen_y] += color
        
        # Accumulate result from this repetition
        accumulation_buffer += rep_buffer
    
    # Average over N repetitions
    final_image = accumulation_buffer / N
    
    return final_image
```

### Parameters
*   **$N$ (Repetition Level):** The number of rendering passes. Higher $N$ reduces noise/error but increases computation time [S1]. Typical values tested: 1, 25, 100, 144 [S1].
*   **Transfer Function:** Maps scalar values to density $\rho$ and luminosity $c$ [S1].

### Edge Cases and Pitfalls
*   **Precipitous Transfer Functions:** PBVR may generate an insufficient number of particles (fragments) when the density function changes drastically, leading to artifacts [S1]. Sorting-free Pre-integrated Projected Tetrahedra (SPT) handles these better [S1].
*   **Memory Consumption:** PBVR is memory-consuming because the number of particles (fragments) increases with image resolution [S1].
*   **Performance Scaling:** Performance is greatly influenced by the number of pixels [S1].

## Operating characteristics
*   **Time Complexity:** The basic brightness calculation without stochastic approximation is $O(n^2)$ if intermediate brightness values are considered [S1]. With stochastic approximation, the cost is proportional to $N \times (\text{number of tetrahedra} + \text{number of pixels})$ [S1].
*   **Memory Complexity:** Memory usage is influenced by the number of pixels and the number of particles (fragments) [S1]. It requires less memory than Hardware-Assisted Visibility Sorting (HAVS), which needs memory space for sorting cell faces about twice that for tetrahedral cells [S1].
*   **Measured Performance:** On an NVIDIA GeForce 9600GT, PBVR rendered ~10 million particles at 25.7 milliseconds per repetition with 1024x1024 resolution [S1]. On an Intel Core 2 Quad 2.83 GHz with NVIDIA GeForce GTX 280, PBVR was compared against HAVS and SPT [S1].
*   **Strengths:**
    *   No visibility sorting required, enabling scalability for large-scale irregular volumes distributed across multiple nodes [S1].
    *   Avoids artifacts from insufficient k-buffer size in HAVS [S1].
    *   Avoids visible footprints of particle-based methods when the viewpoint is inside the volume [S1].
*   **Limitations:**
    *   Performance is heavily influenced by the number of pixels [S1].
    *   May produce artifacts with precipitous transfer functions compared to SPT [S1].
    *   Requires multiple repetitions ($N$) to achieve high-quality images, increasing computation time [S1].
*   **When to Use:** Suitable for large-scale irregular volumes where visibility sorting is impractical or impossible (e.g., distributed computing) and where particle-based methods produce visible artifacts [S1]. Preferred over SPT when the number of particles is larger than 24 million [S1].
*   **When Not to Use:** When high performance is required for small datasets or when transfer functions have precipitous changes (SPT is better) [S1].

## Background
*   **Origin:** The method was introduced in the paper "Sorting-free pre-integrated projected tetrahedra" [S1].
*   **History:** It was developed to address the limitations of particle-based volume rendering (low image quality, visible footprints) and conventional projected tetrahedra (requirement for visibility sorting, scalability issues) [S1]. It applies the concept of stochastic volume rendering to object-order techniques like projected tetrahedra [S1].
*   **Usage:** Applied to large-scale irregular volumes from CSM and CFD simulations [S1].
