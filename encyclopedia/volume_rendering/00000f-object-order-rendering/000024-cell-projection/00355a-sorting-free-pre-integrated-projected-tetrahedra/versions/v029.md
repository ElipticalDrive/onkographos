# Sorting-free Pre-integrated Projected Tetrahedra

Also called: Pre-integrated Projected Tetrahedra, Sorting-free approach that controls the fragment rendering by using the opacity value, Sorting-free technique for volume rendering of an irregular volume dataset

## Overview
Sorting-free Pre-integrated Projected Tetrahedra (PBVR) is a volume rendering technique for irregular datasets that eliminates the need for explicit back-to-front visibility sorting [S1]. It solves the scalability issues of conventional sorting methods and the low image quality (visible footprints) of particle-based methods by treating volume rendering as a stochastic process where sampling points occur along a viewing ray with a probability equal to the local opacity [S1]. Unlike [Cell projection](26-cell-projection.md) which typically requires sorting, PBVR achieves semi-transparency through repeated rasterization passes controlled by opacity probabilities [S1].

## How it works
**Inputs:** Irregular volume dataset decomposed into tetrahedral cells; scalar field values at vertices; transfer function mapping scalar to color/extinction; camera parameters.
**Outputs:** Final rendered image (brightness/color per pixel).

**Data Structures:**
*   **Tetrahedron:** Defined by 4 vertices in 3D space. Each vertex holds a scalar value $s_i$.
*   **Projected Cell:** The 3D tetrahedron is projected to 2D screen space. The projected edges divide the image plane into polygons. Each polygon lies within the projection of a single front-facing face and a single back-facing face of the cell [S1, S2].
*   **Ray Segments:** The viewing ray is subdivided into segments where particle luminosity $c_k$ and density $\rho_k$ are constant [S1].

**Mathematical Model:**
The method uses a density emitter model where the scalar field is characterized as a varying density emitter with single-level scattering [S1]. The opacity is derived from the number of particles in a unit volume, assuming the number of particles follows a Poisson distribution [S1].

The opacity $\tau$ for a ray segment of length $\Delta t$ is given by:
$$ \tau = 1 - e^{-\rho \cdot \pi r^2 \cdot \Delta t} $$
where $\rho$ is the number of particles in a unit volume, and $\pi r^2 \rho \Delta t$ expresses the expected number of particles in the ray segment [S1].

The brightness $B_k$ for a segment is calculated as:
$$ B_k = c_k \times (1 - e^{-\rho \cdot \text{area} \cdot \text{length}}) $$
where $c_k$ is the particle luminosity [S1].

**Algorithm Steps:**
The rendering calculation is repeated $N$ times (repetition level) to achieve semi-transparency without alpha-blending [S1].

1.  **Projection:** Project the 3D tetrahedra to 2D screen space. Subdivide the image plane into polygons based on projected edges [S1, S2].
2.  **Opacity Evaluation:** For each fragment generated by rasterizing the projected polygons, evaluate the local opacity $\alpha$ based on the scalar values and transfer function [S1].
3.  **Stochastic Fragment Rendering (Per Repetition):**
    *   For each fragment, generate a random number $r \in [0, 1]$ [G].
    *   Compare $r$ with the fragment's opacity $\alpha$.
    *   If $r > \alpha$, discard the fragment [S1].
    *   If $r \le \alpha$, render the fragment with its luminosity/color [S1].
    *   This step effectively controls fragment rendering by using the opacity value to determine visibility, making the technique sorting-free [S1].
4.  **Accumulation:** Repeat steps 2-3 for $N$ repetitions.
5.  **Final Image:** Calculate the ensemble average of the pixel values from all $N$ repetitions to obtain the final brightness/color [S1].

**Pseudocode:**

```python
def render_pbvr(tetrahedra, transfer_function, camera, num_repetitions):
    """
    Renders an irregular volume using Sorting-free Pre-integrated Projected Tetrahedra.
    
    Args:
        tetrahedra: List of tetrahedra, each with 4 vertices and scalar values.
        transfer_function: Function mapping scalar value to (color, extinction/density).
        camera: Camera parameters for projection.
        num_repetitions: Number of stochastic passes N.
        
    Returns:
        final_image: 2D array of accumulated brightness/color.
    """
    # Initialize image accumulator
    # Dimensions depend on screen resolution
    image_accumulator = zeros(screen_width, screen_height, 3) 
    
    for rep in range(num_repetitions):
        # Create a temporary image for this repetition
        current_image = zeros(screen_width, screen_height, 3)
        
        # Process each tetrahedron
        for tet in tetrahedra:
            # 1. Project tetrahedron to 2D screen space
            projected_vertices = project_to_screen(tet.vertices, camera)
            
            # 2. Subdivide image plane into polygons based on projected edges
            #    This creates a set of screen-space polygons, each associated with
            #    a specific ray segment through the tetrahedron.
            polygons = subdivide_screen_plane(projected_vertices)
            
            # 3. Rasterize polygons and evaluate opacity
            for poly in polygons:
                # Get the ray segment properties for this polygon
                # In the density emitter model, we need density rho and luminosity c
                # These are derived from the scalar values at the vertices of the 
                # corresponding 3D segment.
                scalar_values = get_scalar_values_for_segment(tet, poly)
                
                # Map scalar to physical properties using transfer function
                # The transfer function provides extinction/density (rho) and color/luminosity (c)
                rho, c = transfer_function(scalar_values)
                
                # Calculate opacity for the segment
                # Formula: tau = 1 - exp(-rho * area * length)
                # Note: 'area' and 'length' refer to the geometric properties of the 
                # ray segment intersecting the tetrahedron face/segment.
                # For a ray segment of length delta_t:
                # tau = 1 - exp(-rho * pi * r^2 * delta_t) 
                # However, in the fragment shader context, we often pre-integrate or 
                # use the opacity directly derived from the scalar field.
                # The source states: "controls the fragment rendering by using the opacity value"
                # So we compute alpha for the fragment.
                
                # Assuming 'alpha' is the pre-computed or interpolated opacity for the fragment
                # based on the scalar field and transfer function.
                alpha = compute_fragment_opacity(scalar_values, rho) 
                
                # 4. Stochastic Visibility Test
                # Generate random number r in [0, 1]
                r = random_float()
                
                if r <= alpha:
                    # Fragment is visible in this repetition
                    # Render with luminosity/color c
                    # The brightness contribution is added to the current image
                    # In a simple stochastic model, we might just add the color
                    # or the brightness value B_k.
                    # Source says: "brightness values can be approximated as the expected value"
                    # and "accumulated to obtain the average".
                    
                    # Add color contribution
                    current_image[poly.screen_coords] += c
                    
        # Accumulate the result of this repetition
        image_accumulator += current_image
        
    # 5. Average over repetitions
    final_image = image_accumulator / num_repetitions
    
    return final_image

def compute_fragment_opacity(scalar_values, rho):
    """
    Computes the opacity alpha for a fragment based on the scalar values and density.
    Uses the density emitter model.
    """
    # The opacity is derived from the number of particles in a unit volume.
    # Assuming linear interpolation of scalar to density rho.
    # The opacity for a segment of length l with average differential opacity tau_avg is:
    # alpha = 1 - exp(-tau_avg * l)
    # In the context of the stochastic approach, alpha is the probability of 
    # a particle being present/visible.
    
    # For implementation, this is typically pre-integrated or looked up.
    # Here we assume a simple calculation based on the segment length and density.
    # Note: The exact geometric length 'l' for a fragment depends on the ray depth 
    # through the tetrahedron at that screen position.
    
    # Placeholder for geometric length calculation based on ray-tet intersection
    segment_length = get_segment_length_at_screen_pos(scalar_values)
    
    alpha = 1.0 - exp(-rho * segment_length)
    return alpha
```

**Parameters:**
*   **Repetition Level ($N$):** The number of times the rendering calculation is repeated. Higher $N$ reduces error but increases computation time. Typical values tested: 1, 25, 100, 144 [S1].
*   **Resolution:** Image resolution (e.g., 1024x1024) [S1].

**Edge Cases and Pitfalls:**
*   **Drastic Density Changes:** PBVR may generate an insufficient number of particles when the density function changes drastically, leading to artifacts. Sorting-free Pre-integrated Projected Tetrahedra (SPT) handles precipitous transfer functions better [S1].
*   **Memory Consumption:** PBVR is memory-consuming because the increase in image resolution affects the number of particles required [S1].
*   **Performance Scaling:** Performance is greatly influenced by the number of pixels [S1].

## Operating characteristics
*   **Time Complexity:** The computational complexity of the basic brightness calculation is $O(n^2)$ if intermediate brightness values are considered [S1]. The total time is proportional to the number of repetitions $N$ and the number of pixels [S1].
*   **Memory Complexity:** PBVR is memory-consuming, as the increase in image resolution affects the number of particles [S1]. It requires less memory than Hardware-Assisted Visibility Sorting (HAVS), which requires memory space for sorting cell faces about twice that for tetrahedral cells [S1].
*   **Measured Performance:** On an NVIDIA GeForce 9600GT, PBVR rendered ~10 million particles at 1024x1024 resolution in 25.7 milliseconds per repetition [S1]. For 1024x1024 resolution, the computing time is estimated at 1.4 seconds per repetition for large datasets [S1].
*   **Strengths:**
    *   No visibility sorting required, making it suitable for large-scale irregular volumes distributed across multiple computing nodes [S1].
    *   Avoids artifacts caused by insufficient k-buffer size (unlike HAVS) [S1].
    *   Avoids visible footprints when the viewpoint is inside the volume (unlike particle-based methods) [S1].
*   **Limitations:**
    *   Performance is greatly influenced by the number of pixels [S1].
    *   May generate insufficient particles when density functions change drastically [S1].
    *   Requires multiple repetitions to achieve high-quality images, increasing computation time [S1].
*   **When to Use:** Suitable for large-scale irregular volume datasets where visibility sorting is impractical or impossible (e.g., distributed computing environments) and where the density function does not change drastically [S1]. Preferred over PBVR if the number of particles is larger than 24 million [S1].
*   **When Not to Use:** Not suitable when the density function changes drastically, as it may produce artifacts [S1]. Not ideal if memory is a critical constraint due to the pixel-dependent particle count [S1].

## Background
Sorting-free Pre-integrated Projected Tetrahedra (PBVR) was introduced as a sorting-free technique for volume rendering of irregular volume datasets [S1]. It addresses the difficulties of conventional techniques that require visibility sorting, which is difficult for large-scale irregular volumes distributed across multiple computing nodes [S1]. The method was developed to solve the low image quality of particle-based volume rendering (PBVR) and the scalability issues of conventional projected tetrahedra methods [S1]. It employs a density emitter model and stochastic sampling to achieve semi-transparency without explicit sorting [S1].
