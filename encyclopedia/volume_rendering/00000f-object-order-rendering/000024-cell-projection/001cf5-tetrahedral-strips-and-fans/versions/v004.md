# Tetrahedral Strips and Fans

Also called: Bandwidth reduction for tetrahedral meshes, Rendering Pattern and Stripification, Tetrahedral Fans, Tetrahedral Fans and Tetrahedral Strips, Tetrahedral Strips, Tetrahedral primitives

## Overview
Tetrahedral Strips and Fans are graphics primitives designed to address the bandwidth bottleneck between main memory and the graphics processor when rendering unstructured tetrahedral meshes [S1, S2, unofficial]. They reduce the number of vertices transmitted per tetrahedron, achieving rates approaching 1.2 vertices per tetrahedron, similar to how triangle strips optimize triangle meshes [S2, unofficial]. Unlike static triangle strips, these primitives are necessary because tetrahedral decomposition is view-dependent, preventing the use of static display lists when changing viewpoints [S2, unofficial]. They enable performance improvements of 72 to 85 times over triangle-based hardware approaches, making interactive volumetric rendering feasible [S1, unofficial].

## How it works
**Inputs:** A tetrahedral mesh (set of tetrahedra defined by vertex indices).
**Outputs:** A sequence of drawing commands (strips/fans) and vertex data optimized for transmission.

**Data Structures:**
The core data structure is a list of tetrahedra grouped into strips or fans. Each tetrahedron is defined by 4 vertices.
*   **Tetrahedral Fan:** A sequence of tetrahedra sharing a common edge.
*   **Tetrahedral Strip:** A sequence of tetrahedra connected by shared faces, not necessarily sharing a single common edge.
*   **Vertex Slots:** For generalized strips, a buffer of 4 vertex slots is maintained.

**Algorithm Steps:**

1.  **Grouping:** Group tetrahedra into fans or strips based on adjacency.
    *   *Fan:* Identify a common edge shared by multiple tetrahedra.
    *   *Strip:* Identify a chain of tetrahedra where each shares a face with the next. This often involves analyzing "edge chains" (unions of common edges shared by sequences of three or more adjacent tetrahedra) [S2, unofficial].
2.  **Ordering:** Determine the order of vertices for transmission to ensure correct geometry reconstruction.
    *   *Fan:* The first two vertices form the shared edge. Subsequent vertices define new tetrahedra using the shared edge and the previous new vertex.
    *   *Strip:* Determine which vertex of the previous tetrahedron is replaced by the new vertex.
3.  **Transmission:** Send vertex data and primitive commands to the GPU.

**Formulas and Definitions:**

*   **Fan Transmission Cost:** For a fan comprising $N$ tetrahedra, only $N+2$ vertices are transmitted [S2, unofficial].
*   **Sequential Strip:** A strip where the new vertex always replaces the least-recently-used (LRU) vertex of the previous tetrahedron [S2, unofficial].
*   **Generalized Strip:** A strip with no constraints on the direction of the next tetrahedron; vertices may be replaced in any order [S2, unofficial].
*   **Generalized Strip Overhead:** Requires a 2-bit flag per vertex to indicate which of the four slots (1, 2, 3, or 4) is replaced [S2, unofficial].

**Pseudocode:**

```python
# Tetrahedral Fan Rendering
def render_tetrahedral_fan(vertices):
    """
    Renders a sequence of tetrahedra sharing a common edge.
    vertices: List of 3D points.
    Assumption: vertices[0] and vertices[1] form the shared edge.
    """
    glBegin(GL_TET_FAN_EXT)
    
    # Transmit the first two vertices (shared edge)
    glVertex(vertices[0])
    glVertex(vertices[1])
    
    # Transmit the third and fourth vertices (complete first tetrahedron)
    # Tet 1: vertices 0, 1, 2, 3
    glVertex(vertices[2])
    glVertex(vertices[3])
    
    # For each subsequent vertex k (k >= 4), define a new tetrahedron
    # Tet k-2: vertices 0, 1, k-1, k
    for k in range(4, len(vertices)):
        glVertex(vertices[k])
        
    glEnd()

# Sequential Tetrahedral Strip Rendering
def render_sequential_tet_strip(vertices):
    """
    Renders a sequential tetrahedral strip.
    vertices: List of 3D points.
    Assumption: Each new vertex replaces the first vertex of the previous tetrahedron.
    """
    glBegin(GL_SEQUENTIAL_TET_STRIP_EXT)
    
    # Transmit the four vertices of the first tetrahedron
    glVertex(vertices[0]) # v1
    glVertex(vertices[1]) # v2
    glVertex(vertices[2]) # v3
    glVertex(vertices[3]) # v4
    
    # Subsequent vertices replace the LRU vertex (v1)
    # Vertex 4 (index 4) replaces v1 -> Tet: v2, v3, v4, v5
    glVertex(vertices[4])
    
    # Vertex 5 (index 5) replaces v2 -> Tet: v3, v4, v5, v6
    glVertex(vertices[5])
    
    # Vertex 6 (index 6) replaces v3 -> Tet: v4, v5, v6, v7
    glVertex(vertices[6])
    
    # Vertex 7 (index 7) replaces v4 -> Tet: v5, v6, v7, v8
    glVertex(vertices[7])
    
    glEnd()

# Generalized Tetrahedral Strip Rendering
def render_generalized_tet_strip(vertices, replacement_flags):
    """
    Renders a generalized tetrahedral strip.
    vertices: List of 3D points.
    replacement_flags: List of integers (1, 2, 3, or 4) indicating which slot is replaced.
    """
    glBegin(GL_GENERAL_TET_STRIP_EXT)
    
    # Transmit the four vertices of the first tetrahedron
    glVertex(vertices[0]) # Slot 1
    glVertex(vertices[1]) # Slot 2
    glVertex(vertices[2]) # Slot 3
    glVertex(vertices[3]) # Slot 4
    
    # For each subsequent vertex, specify which slot to replace
    for i, flag in enumerate(replacement_flags):
        # flag is 1, 2, 3, or 4
        glReplaceVertexEXT(flag)
        glVertex(vertices[4 + i])
        
    glEnd()
```

**Parameters:**
*   `tmean`: Mean number of tetrahedra in each strip [S2, unofficial].
*   `tmed`: Median number of tetrahedra in each strip [S2, unofficial].
*   `tstd`: Standard deviation of the number of tetrahedra in each strip [S2, unofficial].
*   `tmax`: Maximum number of tetrahedra in a strip [S2, unofficial].
*   `vpert`: Number of vertices per tetrahedron (transmission rate) [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **View Dependency:** Static strips cannot be used because the projection of tetrahedra changes with the viewpoint [S2, unofficial].
*   **Bandwidth:** Rendering tetrahedra requires 50-60% more bandwidth than rendering individual triangles, even with fans [S2, unofficial].
*   **Generalized Strip Overhead:** Using generalized strips incurs an added expense of transmitting 2 bits for the flag per vertex [S2, unofficial].

## Subtopics

### [Greedy Strip Generation Algorithm](2626-greedy-strip-generation-algorithm.md)
A method for converting a tetrahedral mesh into a sequence of tetrahedral strips and fans to optimize data transmission. It addresses the bandwidth bottleneck by reducing the number of vertices required to render each tetrahedron. Unlike triangle strips, tetrahedral strips require computing a correctly-ordered list of vertex replacements from the tetrahedra in the strip, often involving edge chain analysis. The baseline algorithm is distinguished by its simplicity: it selects the first available unvisited neighbor without complex heuristics, serving as the foundational reference for more advanced variants.

## Operating characteristics
**Time and Memory Complexity:**
Not given in the sources. The generation of strips involves graph traversal and edge chain analysis, which is computationally intensive but performed on the CPU [S2, unofficial].

**Measured Performance:**
*   Performance improvements of 72 to 85 times over triangle graphics hardware approaches [S1, unofficial].
*   Transmission rates approaching 1.2 vertices per tetrahedron [S2, unofficial].
*   Strip lengths vary by method and dataset:
    *   Method 2 on Phoenix dataset: 441 strips, mean length 29.4, median 10, max 347, vpert 1.10 [S2, unofficial].
    *   Method 2 on Langley dataset: 1432 strips, mean length 49.0, median 13, max 865, vpert 1.06 [S2, unofficial].
    *   Average strip lengths of 17 on representative datasets [S1, unofficial].
    *   Method 2 achieved the best results with mean strip lengths of 29 tetrahedra per strip and median lengths over 10 tetrahedra per strip [S2, unofficial].

**Strengths and Limitations:**
*   **Strengths:** Significantly reduces bandwidth; enables interactive rendering; makes software sorting pass unnecessary by moving computations to hardware [S1, unofficial]. Tetrahedral stripping is inherently more efficient than triangle stripping, with gains greater than expected [S2, unofficial].
*   **Limitations:** Based on projected tetrahedra, it suffers from inaccuracies inherent to that algorithm (e.g., linear approximation errors) [S2, unofficial]. Requires hardware support for the new primitives (or software emulation) [S2, unofficial].

**When to Use:**
*   Use for interactive tetrahedral volume rendering where bandwidth is a bottleneck [S2, unofficial].
*   Use when rendering unstructured volume data on hardware that supports vertex caching and the proposed primitives [S2, unofficial].

**When Not to Use:**
*   Not suitable for static meshes where triangle strips can be precomputed, as tetrahedral decomposition is view-dependent [S2, unofficial].

## Background
Tetrahedral Strips and Fans were introduced to address the bandwidth bottleneck in interactive tetrahedral volume rendering. They build on the Projected Tetrahedra algorithm, which generates triangles for hardware acceleration but suffers from high bandwidth requirements [S2, unofficial]. The primitives were proposed in the context of a new hardware architecture (R-buffer) designed for volume rendering [S1, S2, unofficial]. The work was published by Craig M. Wittenbrink and colleagues [S2, unofficial]. The approach allows performance improvements similar to triangle strips for triangle meshes but adapted for the complexities of tetrahedral meshes [S1, unofficial].
