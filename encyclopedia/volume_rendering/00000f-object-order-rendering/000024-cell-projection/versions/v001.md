# Cell projection

Also called: Projected Tetrahedra, Polyhedron Projection

## Overview
Cell projection is a direct volume rendering technique that projects the 3D cells of an unstructured or curvilinear grid onto the 2D image plane, decomposing each cell's projection into polygons that are scan-converted and composited in back-to-front order [S1][S4, book]. It solves the problem of rendering irregular grids without resampling by leveraging standard graphics hardware for scan-conversion, setting itself apart from ray-casting by avoiding per-pixel ray traversal and from splatting by maintaining explicit geometric connectivity [S3, unofficial][S4, book]. Unlike [Texture slicing](25-texture-slicing.md), which slices cells with parallel planes, cell projection projects the entire cell geometry, requiring a global visibility sort to resolve occlusions correctly [S1].

## Shared principles
The core mechanism of cell projection involves projecting the vertices of each convex polyhedral cell onto the image plane. The projected edges of a single cell divide the image plane into a set of polygons. Each polygon lies within the projection of a single front-facing face and a single back-facing face of the cell [S1, S2].

For orthogonal projection, the length $l$ of the viewing ray segment within the cell varies linearly across the polygon and can be interpolated linearly by hardware [S1, S2]. For perspective projection, the screen-space depth $z_s$ is a linear function of eye-space depth $z_e$ ($z_s = c_i + h_i z_e$), allowing planar surfaces in eye space to remain planar in screen space. However, the segment length $l$ varies nonlinearly with pixel position in perspective view [S4, book].

The scalar field is assumed to vary linearly across the cell, and transfer functions mapping scalar values to color ($RGB$) and differential opacity ($\tau$ or $\kappa$) are assumed linear [S1, S2]. The color at ray segment endpoints is obtained by interpolation across polygons (for rear endpoints) or edges (for other endpoints) [S1].

The integrated opacity $\alpha$ for a ray segment of length $l$ with average differential opacity $\kappa_{avg}$ is given by:
$$ \alpha = 1 - e^{-\kappa_{avg} l} $$
[S1][S4, book]

Linear interpolation of $\alpha$ across polygons causes derivative discontinuities due to the nonlinear exponential, resulting in Mach bands [S1, S2]. To avoid this, the method interpolates the linear parameters $\kappa_{avg}$ and $l$ and uses a 2D texture lookup to compute $\alpha$ per pixel [S1, S2].

Non-planar quadrilateral faces (common in curvilinear grids) can cause "problem faces" where a ray intersects the same face twice, creating "problem cells" with disjoint ray segments that break back-to-front sorting. The standard solution is to subdivide problem cells into tetrahedra with planar faces [S4, book].

## Subtopics

### [Parallel Cell Projection](875-parallel-cell-projection.md)
A distributed-memory and shared-memory strategy that decomposes the pipeline into object-space polygon generation and image-space ray merging/composition. It solves scalability for large unstructured grids by decoupling sending and receiving tasks to hide data transfer overheads, separating projection and global composition to reduce asynchronous communication frequency.

### [Cell Projection with Texture Mapping for Opacity](993-cell-projection-with-texture-mapping-for-opacity.md)
A hardware-accelerated technique that projects cells as polygons and composites them in back-to-front order. It solves Mach bands caused by linear interpolation of non-linear opacity by using a 2D texture lookup to compute the exponential opacity term per pixel, interpolating linear parameters $\kappa_{avg}$ and $l$ instead.

### [Topological Sort for Cell Projection](999-topological-sort-for-cell-projection.md)
An $O(n)$ algorithm (MPVO) for computing a back-to-front visibility ordering of convex polyhedral cells in a convex grid. It solves the occlusion ordering problem by constructing a directed graph of pairwise occlusion relations between adjacent cells and performing a topological sort. It guarantees correct visibility for convex meshes but fails on non-convex meshes due to ignored occlusion across empty space.

### [Parallelized Accurate Sorting for Projected Tetrahedra](1128-parallelized-accurate-sorting-for-projected-tetrahedra.md)
A view-dependent sorting algorithm for tetrahedral datasets using logical partitioning to enable parallel processing. It sets itself apart by replacing global topological sorting with a block-based scheme that allows independent parallel sorting of unobstructed layers, enhancing parallelization and reducing sorting time.

### [GPU-based Cell Projection for Structured Data](1864-gpu-based-cell-projection-for-structured-data.md)
An interactive rendering technique for large, regular volumetric data sets on GPUs that exploits data regularity to eliminate redundant projection and sorting computations. It differs from general Projective Tetrahedra by avoiding expensive visibility sorting via constant-time traversal order and consumes less memory than Hardware-Based Ray Casting.

### [Cell Projection with Scan-line Conversion](1968-cell-projection-with-scan-line-conversion.md)
A software-based direct volume rendering method for irregular and multiple grids using Y-bucket sorting and scanline generation to leverage spatial coherence. It sets itself apart by producing image quality equivalent to ray casting but faster due to coherence, yielding clearer images with fewer artifacts than hardware Gouraud shading, though it is slower.

### [Cell-Projection Rendering](4279-cell-projection-rendering.md)
A parallel direct volume rendering algorithm for unstructured data that projects mesh cells into image space to generate ray segments, which are then merged in image space. Unlike ray-casting, it does not require pre-sorting cells in depth order, offering greater flexibility in data distribution and higher accuracy than slice- or vertex-projected methods.

### [Tetrahedral representation and traversal](4396-tetrahedral-representation-and-traversal.md)

### Pre-integrated classification for cell projection
A method to determine color and opacity contribution by applying pre-integrated classification, using scalar values on front and back faces ($s_f, s_b$) and thickness ($l$) as texture coordinates for a 3D texture map storing volume ray integral values [S5].

### LinPrim Tetrahedron Representation
A scene representation using transparent tetrahedra bounded by triangular faces with homogeneous density [S6]. It defines four basis vectors describing directions from the center on which corners are located, equally spaced to represent regular tetrahedra, and optimizes the distance between the center and each corner independently [S6]. Tetrahedra memory requirement is 12 floats per primitive (omitting color) due to absence of symmetry [S6]. Unlike octahedra, the optimized position (center) can differ from the geometric center of the primitive [S6].

### CellFast
A software algorithm for interactive unstructured volume rendering that moves computations for order-independent transparency and volume scan conversion from CPU to graphics hardware, eliminating the need for a software sorting pass [S7, unofficial]. Steps include: I. Preprocess dataset. II. Visibility sort cells. III. Test plane equations to determine class (1,2,3,4). IV. Project and split cell unique frontback faces. V. Compute color and opacity for thick vertex. VI. (Hardware) Scanconvert new triangles [S7, unofficial]. In original implementations, Steps II-V saturate the host CPU [S7, unofficial]. An average of 3.4 triangles are written per tetrahedron during splitting [S7, unofficial].

## Background
Cell projection was developed at Lawrence Livermore National Laboratory by Max, Williams, Silva, and Cook [S1, S2]. It is one of the four main paradigms of volume rendering, alongside raycasting, splatting, and shear-warp [S3, unofficial]. The method was extended to handle curvilinear and unstructured grids, including non-planar faces, by subdividing problem cells into tetrahedra [S4, book].
