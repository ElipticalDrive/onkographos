# Parallelized Accurate Sorting for Projected Tetrahedra

Also called: Logical partition sorting, Quick and accurate sorting algorithm of tetrahedral datasets

## Overview
Parallelized Accurate Sorting for Projected Tetrahedra is a view-dependent sorting algorithm designed to resolve the dependency and sequence limitations inherent in parallel processing of tetrahedral datasets [S1, unofficial][S2, unofficial]. It solves the problem of topological sorting bottlenecks by using logical partitioning to enable parallel computation of unobstructed layers, thereby enhancing the parallelization of topological sorting and reducing sorting time [S1, unofficial][S2, unofficial]. It sets itself apart from standard Projected Tetrahedra by explicitly addressing the neighbor dependency issues that limit parallel performance, and from [Parallel Projected Tetrahedra with KD-Tree Partitioning](8767-parallel-projected-tetrahedra-with-kd-tree-partitioning.md) by using a view-dependent logical partition rather than a static spatial hierarchy [S1, unofficial][S2, unofficial].

## How it works
The method performs a four-step process to sort tetrahedra and compute optical contributions in parallel.

**Inputs and Outputs:**
*   **Input:** A tetrahedral dataset (mesh) and a camera view direction.
*   **Output:** A back-to-front sorted list of tetrahedra (or subsets thereof) ready for compositing, and the final rendered image.

**Data Structures:**
*   **Blocks:** A list of spatial blocks dividing the dataset along the viewing direction. Each block contains a subset of tetrahedra.
*   **Layers:** Unobstructed subsets of tetrahedra peeled from the blocks during the sorting phase.
*   **Boundary Tetrahedra:** Tetrahedra located at the interface between blocks, requiring logical partitioning.

**Steps:**

1.  **Divide Space into Blocks:**
    Divide the space containing the tetrahedral datasets into a list of blocks along the viewing direction. Each block contains a subset of tetrahedra [S1, unofficial][S2, unofficial]. This partitioning is view-dependent, meaning the blocks are defined relative to the current camera orientation to facilitate parallel processing along the ray path.

2.  **Sort Accurately by Peeling Layers:**
    Sort the tetrahedra accurately by peeling tetrahedral subsets into unobstructed layers in parallel [S1, unofficial][S2, unofficial]. This step resolves the topological dependencies within the blocks. "Peeling" implies identifying tetrahedra that are not occluded by others within the same block or previously processed layers, allowing them to be processed in parallel without write conflicts.

3.  **Logical Partition and Optical Contribution:**
    Partition tetrahedra on the boundary logically and compute the optical contribution of each subset with segment integration [S1, unofficial][S2, unofficial]. Boundary tetrahedra (those crossing block boundaries) are handled via logical partitioning to ensure correct ordering across block interfaces. The optical contribution is computed using segment integration, likely leveraging the summed-area table for opacity accumulation as mentioned in the context of early termination [S1, unofficial].

4.  **Accumulate Optical Contribution:**
    Accumulate the optical contribution of each subset along the viewing direction [S1, unofficial][S2, unofficial]. The results from the parallel blocks are combined to form the final image.

**Pseudocode:**

```python
def parallelized_accurate_sorting(tetrahedra, view_direction):
    """
    Implements the 4-step parallelized accurate sorting for projected tetrahedra.
    """
    # Step 1: Divide space into blocks along viewing direction
    blocks = divide_space_into_blocks(tetrahedra, view_direction)
    
    # Step 2: Sort accurately by peeling unobstructed layers in parallel
    # This step resolves topological dependencies within blocks
    sorted_layers = []
    for block in blocks:
        # Peel unobstructed layers from the block subset
        layers = peel_unobstructed_layers(block.tetrahedra)
        sorted_layers.append(layers)
        
    # Step 3: Partition boundary tetrahedra logically and compute optical contribution
    # Boundary tetrahedra are those at the interface of blocks
    boundary_tetrahedra = identify_boundary_tetrahedra(blocks)
    logical_partitions = partition_boundary_logically(boundary_tetrahedra)
    
    # Compute optical contribution for each subset using segment integration
    # This likely involves opacity accumulation, potentially using a summed-area table
    optical_contributions = []
    for subset in sorted_layers + logical_partitions:
        contribution = compute_optical_contribution_segment_integration(subset)
        optical_contributions.append(contribution)
        
    # Step 4: Accumulate optical contribution along viewing direction
    final_image = accumulate_optical_contributions(optical_contributions, view_direction)
    
    return final_image

def divide_space_into_blocks(tetrahedra, view_direction):
    """
    Divides the space containing tetrahedral datasets into a list of blocks 
    along the viewing direction.
    """
    # Project tetrahedra onto the view axis to determine spatial extent
    # Group tetrahedra into blocks based on their projection ranges
    # The exact partitioning algorithm (e.g., uniform grid, adaptive) is not specified
    # in the sources, but it is view-dependent [S1, unofficial][S2, unofficial].
    blocks = []
    # Implementation detail: Sort tetrahedra by centroid projection along view_direction
    # Then split into contiguous blocks.
    projected_centroids = [project(t.centroid, view_direction) for t in tetrahedra]
    sorted_indices = argsort(projected_centroids)
    sorted_tetrahedra = [tetrahedra[i] for i in sorted_indices]
    
    # Split into N blocks (N is a parameter, e.g., number of GPU threads or blocks)
    block_size = len(sorted_tetrahedra) // N
    for i in range(N):
        start = i * block_size
        end = start + block_size if i < N - 1 else len(sorted_tetrahedra)
        blocks.append(Block(tetrahedra=sorted_tetrahedra[start:end], index=i))
    return blocks

def peel_unobstructed_layers(tetrahedra_subset):
    """
    Sorts tetrahedra by peeling unobstructed layers in parallel.
    This resolves topological dependencies.
    """
    # Identify tetrahedra that are not occluded by others in the subset
    # This is a topological sort problem.
    # "Peeling" suggests an iterative removal of front-most tetrahedra.
    layers = []
    remaining = list(tetrahedra_subset)
    
    while remaining:
        # Find tetrahedra that do not occlude any other remaining tetrahedra
        # along the view direction.
        # In projected tetrahedra, occlusion is determined by the projected polygon overlap.
        unobstructed = []
        obstructed = []
        
        for t in remaining:
            is_unobstructed = True
            for other in remaining:
                if t is other:
                    continue
                # Check if 'other' occludes 't' from the view direction
                # This requires checking if the projection of 'other' overlaps 't'
                # and 'other' is closer to the camera.
                if other.is_closer_and_overlaps(t, view_direction):
                    is_unobstructed = False
                    break
            if is_unobstructed:
                unobstructed.append(t)
            else:
                obstructed.append(other)
        
        if not unobstructed:
            # Degenerate case: cyclic dependency or all mutually occluding
            # Fallback to centroid sort or break to avoid infinite loop
            # [G] In practice, this might be resolved by breaking ties or using a 
            # different partitioning strategy.
            unobstructed = remaining[:1] # Take one to break deadlock
            obstructed = remaining[1:]
            
        layers.append(unobstructed)
        remaining = obstructed
        
    return layers

def identify_boundary_tetrahedra(blocks):
    """
    Identifies tetrahedra that lie on the boundary between blocks.
    """
    boundary_tetrahedra = []
    # Tetrahedra that are close to the block boundaries in the view direction
    # are considered boundary tetrahedra.
    for block in blocks:
        for t in block.tetrahedra:
            if is_near_block_boundary(t, block):
                boundary_tetrahedra.append(t)
    return boundary_tetrahedra

def partition_boundary_logically(boundary_tetrahedra):
    """
    Partitions boundary tetrahedra logically to ensure correct ordering across blocks.
    """
    # Logical partitioning resolves the dependencies between blocks.
    # The exact method is not detailed, but it likely involves a topological sort
    # of the boundary tetrahedra to determine their relative order.
    sorted_boundary = topological_sort(boundary_tetrahedra, view_direction)
    return sorted_boundary

def compute_optical_contribution_segment_integration(subset):
    """
    Computes the optical contribution of a subset of tetrahedra using segment integration.
    """
    # For each ray intersecting the subset, integrate the opacity along the segment.
    # Alpha = 1 - exp(-tau_avg * l)
    # The contribution is accumulated using the Porter-Duff over operator.
    # [S1, unofficial] mentions leveraging a summed-area table for accumulating 
    # and comparing opacity.
    contribution = 0.0
    for ray in rays_intersecting(subset):
        segments = get_intersected_segments(ray, subset)
        alpha_accumulated = 0.0
        for segment in segments:
            tau_avg = get_average_differential_opacity(segment)
            l = segment.length
            alpha = 1 - exp(-tau_avg * l)
            # Porter-Duff over
            alpha_accumulated = alpha + (1 - alpha) * alpha_accumulated
        contribution += alpha_accumulated
    return contribution

def accumulate_optical_contributions(optical_contributions, view_direction):
    """
    Accumulates the optical contribution of each subset along the viewing direction.
    """
    # Combine the contributions from all blocks and boundary partitions.
    # This step ensures the final image is correctly composited.
    final_image = render_image(optical_contributions, view_direction)
    return final_image
```

**Parameters and Typical Values:**
*   **Number of Blocks:** Not given in the sources. Likely related to the number of GPU threads or SMs.
*   **Early Tetrahedron Termination:** Enabled for datasets with more than a million tetrahedra, providing a gain of more than 10% in rendering performance [S1, unofficial]. This likely uses a summed-area table to check opacity thresholds [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Cyclic Dependencies:** If tetrahedra mutually occlude each other in a cycle, the peeling process may deadlock. The pseudocode includes a fallback to break the deadlock [G].
*   **Boundary Ambiguity:** Tetrahedra near block boundaries must be handled carefully to avoid double-counting or gaps. Logical partitioning is used to resolve this [S1, unofficial][S2, unofficial].
*   **Precision:** Floating-point precision in occlusion checks may lead to incorrect sorting. Robust geometric predicates are recommended [G].

## Subtopics

### [Multi-segment and Multi-stage Projected Tetrahedra](1173-multi-segment-and-multi-stage-projected-tetrahedra.md)
Multi-segment and Multi-stage Projected Tetrahedra is a technique designed to solve the time-consuming sorting problem inherent in Projected Tetrahedra rendering by partitioning datasets into multiple spatial segments and dividing the visualization procedure into multiple temporal stages. It sets itself apart from standard Projected Tetrahedra by introducing spatial partitioning to enable parallel sorting without write access violations, and temporal staging to satisfy varying user requirements and increase cognition. It builds on [Parallelized Accurate Sorting for Projected Tetrahedra](1128-parallelized-accurate-sorting-for-projected-tetrahedra.md) by addressing the scalability limits of sorting large datasets through distributed or cloud-based architectures.

### GPU-Accelerated Cell Projection for Tetrahedral Datasets
A volume rendering technique for tetrahedral datasets that enhances parallelization by dividing space into blocks along the viewing direction, sorting tetrahedra by peeling unobstructed layers in parallel, partitioning boundary tetrahedra logically, and accumulating optical contributions via segment integration [S2, unofficial]. The algorithm reduces sorting time largely and improves rendering performance greatly compared to previous methods [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** The algorithm enhances the parallelization of topological sorting, reducing sorting time largely [S1, unofficial][S2, unofficial]. The GPU implementation achieves 91% acceleration compared with the CPU implementation [S1, unofficial].
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:** For datasets with more than a million tetrahedra, the early tetrahedron termination scheme has a gain of more than 10% in terms of rendering performance [S1, unofficial].
*   **Strengths:** High parallelization efficiency, reduced sorting time, and improved rendering performance for large datasets [S1, unofficial][S2, unofficial].
*   **Limitations:** The algorithm is view-dependent, requiring re-sorting for each frame [S1, unofficial][S2, unofficial]. Boundary handling adds complexity [S1, unofficial][S2, unofficial].
*   **When to Use:** Suitable for large tetrahedral datasets where rendering performance is critical and the view changes frequently [S1, unofficial][S2, unofficial].
*   **When Not to Use:** For small datasets where the overhead of partitioning and sorting may outweigh the benefits.

## Background
The method was proposed by Xin Li, W. Chen, X. Wu, and W. Zuo in the paper "Fast projected tetrahedra volume rendering based on parallelized accurate sorting" published in August 2013 [S1, unofficial]. It addresses the limitations of parallel performance in projected tetrahedra rendering caused by the sequence and dependency of neighboring tetrahedra [S1, unofficial][S2, unofficial]. The technique is part of the broader field of cell projection volume rendering, which includes methods like [Projected Tetrahedra](877-projected-tetrahedra.md) and [Marching Tetrahedrons Algorithm](940-marching-tetrahedrons-algorithm.md).
