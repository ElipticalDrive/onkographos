# Viewpoint-dependent subdivision of non-planar faces

Also called: Cell Projection with Non-Planar Face Subdivision, Cell Projection with Non-Planar Faces Approximation, HIAC system cell projection, Hardware-based cell projection, Non-Planar Face Subdivision Strategy, Shirley and Tuchman method approximation, Viewpoint-dependent tetrahedral subdivision

## Overview
This method handles non-planar quadrilateral faces in curvilinear or irregular grids by performing view-dependent subdivision of "problem" faces and cells into triangles and tetrahedra, respectively, to prevent visibility sort failures and bow-tie projections [S1, S3]. It approximates ray integration by projecting cells onto the screen, computing integrated opacity and color at vertices, and interpolating these values across screen-space polygons using standard graphics hardware [S2]. Unlike methods requiring resampling of curvilinear grids, cell projection works directly on the general grid topology [S3].

## How it works
**Inputs:**
- A list of vertices with 3D positions and scalar field values $s$.
- A list of cells (hexahedra or other topologies) with index pointers to their vertices.
- A viewpoint $V$.
- Transfer functions mapping scalar $s$ to RGB color and differential opacity $\tau$. Assumed linear or piecewise linear [S1, S3].

**Outputs:**
- A rendered image with integrated color and opacity.

**Data Structures:**
- **Vertex List:** Array of vertices, each containing 3D position $(x,y,z)$ and scalar value $s$.
- **Cell Structure:**
  - `subdivided`: Boolean flag indicating if the cell is currently subdivided into tetrahedra.
  - `oldsubdivided`: Boolean flag indicating if the cell was subdivided in the previous frame.
  - `numbInbound`: Integer count of incoming edges in the directed graph used for sorting.
  - `type`: Enum or integer identifying the cell topology (e.g., hexahedron, tetrahedron).
  - Vertex indices: Pointers to the vertices defining the cell [S3].
- **Directed Graph:** For sorting, a graph where nodes are cells and edges represent shared faces, directed towards the cell containing the viewpoint relative to the face plane [S3].

**Steps:**

1.  **Identify Problem Faces and Cells:**
    - A "problem face" is a non-planar quadrilateral where a viewing ray intersects the same face twice, potentially creating a "bow-tie" projection [S1, S3].
    - A "problem cell" is a cell intersected by a viewing ray in disjoint segments [S1, S3].
    - Detection: Test if a viewing ray can intersect a triangulated cell in more than one segment using plane equations of the triangles and locations of viewpoint $V$ and relevant vertices [S1, S3].

2.  **Subdivide Problem Faces:**
    - Subdivide any non-planar quadrilateral face into two triangles.
    - **Consistency Rule:** The diagonal must start from the quadrilateral vertex with the lowest index in the vertex list. This ensures consistency for two cells sharing a face, as the choice depends only on vertex indices [S1, S3].
    - Note: Even if a face is not a "problem face" for a specific cell, it may need subdivision if it is part of a "problem cell" or to avoid gaps between adjacent cells [S3].

3.  **Subdivide Problem Cells:**
    - If a cell is a "problem cell" for the current viewpoint, subdivide it into tetrahedra.
    - **Tetrahedralization:** Connect the vertex of lowest index in the whole cell to all triangles from faces not sharing this vertex. This creates a set of tetrahedra with planar faces [S1, S3].
    - Only problem cells are subdivided; non-problem cells remain intact to preserve performance [S3].
    - Cells containing contour surfaces or scalar breakpoints in piecewise linear transfer functions are also subdivided into tetrahedra and then into slabs [S1].

4.  **Project and Sort:**
    - Project the cell (or its tetrahedral subdivisions) onto the image plane. The projected edges divide the plane into polygons (triangles and quadrilaterals) [S3].
    - Sort cells using the MPVO algorithm (or variants like MPVONC/SXMPVO) based on the directed graph of shared faces. Handle gaps with exterior face sorting or A-buffer accumulation [S3].
    - For contour slabs, sort polygons and volume slabs back-to-front based on viewpoint position relative to contour planes [S1].

5.  **Compute Vertex Attributes:**
    - For each polygon, compute vertex attributes (RGB, opacity $\tau$, length $l$) at the front and back endpoints of the viewing ray segment through the cell [S3].
    - **Profile Vertices:** Vertices on the silhouette (e.g., vertex A). Set color directly from scalar values $s$ and integrated opacity to zero [S2, S3].
    - **Thick Vertices:** Internal vertices (e.g., F, D, I, J) where the ray passes through the cell interior.
        - Compute the back endpoint's $z$, color, and $\tau$ by subdividing the interior face with the diagonal from the lowest index vertex and interpolating linearly in screen space [S2, S3].
        - Compute integrated opacity $\alpha$ as:
          $$ \alpha = 1 - e^{-\tau \cdot l} $$
          where $\tau = (\tau_f + \tau_b)/2$ is the average differential opacity, and $l$ is the ray segment length [S2, S3].
        - Compute ray segment length $l$ by interpolating depth $z$ across the back face polygon in screen space to find the back endpoint, then reversing the eye-to-screen transformation. Approximate by computing $l$ at vertices and interpolating linearly across the polygon in screen space [S2, S3].
        - For precise color, compute the correct integrated color analytically once per vertex and divide by integrated $\alpha$ to get the polygon color. Alternatively, use the average of front and back colors [S2, S3].

6.  **Interpolate and Composite:**
    - Interpolate integrated opacity $\alpha$, color (R, G, B), and depth $z$ linearly across the polygon in screen space using standard Gouraud shading hardware [S1, S2, S3].
    - Composite the interpolated polygons onto the image using the standard alpha blending equation:
      $$ \text{RGB}_{\text{new}} = (1 - \alpha) \times \text{RGB}_{\text{old}} + \alpha \times \text{RGB}_{\text{polygon}} $$
      [S2, S3]
    - **Correction for Non-linear Opacity:** To correct for non-linear opacity integration errors (Mach bands), use texture mapping hardware in orthogonal views. Specify $z$ and $\tau$ as texture coordinates, linearly interpolate them, and extract the correct alpha from a 2D texture map preloaded with values $1 - e^{-\tau}$ [S2]. In perspective views, this is an approximation [S2].

**Pseudocode:**

```python
def render_viewpoint_dependent_subdivision(vertices, cells, viewpoint, transfer_function):
    # Step 1: Identify problem faces and cells
    problem_faces = []
    problem_cells = []
    
    for cell in cells:
        # Check if cell is a problem cell
        if is_problem_cell(cell, viewpoint):
            problem_cells.append(cell)
            
        # Check faces for problem faces
        for face in cell.faces:
            if is_problem_face(face, viewpoint):
                problem_faces.append(face)
                
    # Step 2: Subdivide problem faces
    # Ensure consistency: diagonal from lowest index vertex
    for face in problem_faces:
        v_indices = [v.index for v in face.vertices]
        min_idx = min(v_indices)
        min_vertex = face.get_vertex_by_index(min_idx)
        # Split face into two triangles using min_vertex
        face.subdivide(min_vertex)
        
    # Step 3: Subdivide problem cells
    for cell in problem_cells:
        # Tetrahedralize: connect lowest index vertex of cell to non-sharing faces
        min_cell_vertex = cell.get_lowest_index_vertex()
        cell.subdivide_into_tetrahedra(min_cell_vertex)
        
    # Step 4: Sort cells
    sorted_cells = sort_cells_mpvo(cells, viewpoint)
    
    # Step 5 & 6: Project, Compute Attributes, Interpolate, Composite
    for cell in sorted_cells:
        projected_polygons = project_cell_to_screen(cell, viewpoint)
        
        for polygon in projected_polygons:
            # Compute vertex attributes
            for vertex in polygon.vertices:
                if vertex.is_profile():
                    vertex.color = transfer_function(vertex.scalar)
                    vertex.alpha = 0.0
                else:
                    # Thick vertex
                    # Interpolate back endpoint attributes
                    back_endpoint = interpolate_back_endpoint(vertex, polygon, viewpoint)
                    vertex.back_z = back_endpoint.z
                    vertex.back_color = back_endpoint.color
                    vertex.back_tau = back_endpoint.tau
                    
                    # Compute length l
                    vertex.l = compute_ray_length(vertex, back_endpoint, viewpoint)
                    
                    # Compute average tau
                    vertex.avg_tau = (vertex.tau + vertex.back_tau) / 2.0
                    
                    # Compute integrated alpha
                    vertex.alpha = 1.0 - math.exp(-vertex.avg_tau * vertex.l)
                    
                    # Compute color (approximate average)
                    vertex.color = (vertex.color + vertex.back_color) / 2.0
            
            # Interpolate across polygon in screen space
            render_polygon_gouraud(polygon)
```

**Edge Cases and Pitfalls:**
- **Precision:** Hardware color interpolation is inconsistent with analytic integration. Condition (d) (color constant per cell, only $\tau$ varies linearly) is required for hardware-based method to be mathematically equivalent to analytic integration [S3].
- **Boundaries:** Non-planar faces cause visibility cycles where a ray intersects the same face twice, making back-to-front sorting impossible without subdivision [S3].
- **Degenerate Input:** If a cell is not a problem cell but shares a face with a problem cell, the face must still be subdivided to avoid gaps or overlaps [S3].
- **Performance:** Subdividing all quadrilaterals increases polygon count (e.g., 7 to 25 polygons) and OpenGL data output, though fragment count remains the same [S3].

## Operating characteristics
- **Time Complexity:** Sorting is O(n) for MPVO. Subdivision is view-dependent and may increase polygon count. Detection of problem cells requires plane equation tests [S3].
- **Memory Complexity:** Increased memory usage for storing subdivided cells and tetrahedra. Data structures must track subdivision state [S3].
- **Measured Performance:** On a half-cylindrical shell with 19,000 cells, the method handles non-planar faces effectively. Subdividing all quadrilaterals increases polygon count significantly but maintains fragment count [S3].
- **Scaling:** Scales with the number of cells and the complexity of the grid topology. View-dependent subdivision adds overhead per frame [S3].
- **Strengths:** Works directly on general grid topology without resampling. Handles non-planar faces and visibility cycles. Compatible with standard graphics hardware [S1, S3].
- **Limitations:** Approximations in perspective views (linear interpolation of $\tau$ and color). Inconsistent with analytic integration unless strict conditions are met. Increased polygon count if all quadrilaterals are subdivided [S2, S3].
- **When to Use:** Curvilinear or irregular grids with non-planar faces where direct ray tracing is difficult. When hardware acceleration is desired [S1, S3].
- **When Not to Use:** When high precision analytic integration is required and hardware approximations are unacceptable. When grid topology is simple and planar [S3].

## Background
- **Origin:** Developed for volume rendering of curvilinear and unstructured grids [S1, S3]. Based on cell projection methods [7, 8, 9].
- **History:** Extended from methods assuming planar faces to handle non-planar quadrilateral faces [S3]. Uses concepts from the Shirley and Tuchman method [7] and BSP-MPVO sorting [S2, S3].
- **Usage:** Used in scientific visualization for data on curvilinear grids, such as fluid dynamics simulations or structural mechanics [S1, S3].
