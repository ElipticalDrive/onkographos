# Incoherent Projection


## Overview
Incoherent projection is a cell projection method for general convex hexahedra that renders the 2D projection of each cell as an arrangement of polygons by analyzing each cell individually in screen space, thereby avoiding case analysis for the high number of projection topologies [S1, unofficial]. It builds on [Cell projection](26-cell-projection.md) by extending the sweep-line technique to irregular grids where vertex orderings vary per cell, unlike [Parallel Cell Projection](875-parallel-cell-projection.md) which assumes uniform topology.

## How it works
**Inputs and Outputs:**
*   **Input:** A single convex hexahedron defined by 8 vertices in 3D space $(x, y, z)$, and a projection matrix transforming these to screen space $(x_s, y_s, z_s)$.
*   **Output:** A set of non-overlapping 2D polygons in screen space that exactly cover the projection of the hexahedron, along with depth ($z$) information for shading.

**Data Structures:**
1.  **Event Queue:** A priority queue storing vertex events, ordered by minimum $y$-value. The "minimum" is the unprocessed vertex with the smallest $y$.
2.  **Active Edges List:** An $x$-sorted list of edges. An edge is active if it connects a processed vertex (already removed from the event queue) to an unprocessed vertex.
3.  **Current Boundary:** An edge list representing the polygon boundary surrounding the processed vertices and edges. It is maintained as a planar, non-convex, non-simple polygon.

**Algorithm Steps:**
1.  **Initialization:**
    *   Transform all 8 hexahedron vertices to screen space.
    *   Populate the Event Queue with these vertices, sorted by $y$-value.
    *   Initialize the Active Edges List and Current Boundary as empty.

2.  **Sweep Loop:**
    While the Event Queue is not empty:
    1.  Retrieve `nextVertex` = `getMin(Event Queue)`.
    2.  Set `currentY` = $y$-value of `nextVertex`.
    3.  For each `edge` in `ActiveEdges`:
        *   Calculate `currentX[edge]` = the $x$-coordinate of the edge at `currentY`.
        *   Check if `ActiveEdges` remains sorted by `currentX[edge]`.
        
        **Case A: Sorted**
        1.  Identify `remEdges`: edges in `ActiveEdges` that end at `nextVertex`.
        2.  Determine the $z$-distance of `nextVertex` from the face into which it projects (for shading/opacity).
        3.  **Update Current Boundary:**
            *   Insert the first removed edge and its reversal into the Current Boundary edge list. This forms a planar "needle" polygon (no edges cross).
            *   If a second edge is removed, insert it and its reversal similarly. This completes a counterclockwise polygon, which is then "spliced out" (extracted as a final output polygon).
            *   (Note: The last vertex removal may create a second polygon to be spliced out).
        4.  Insert edges that *begin* at `nextVertex` into `ActiveEdges` such that the list remains $x$-ordered for a slight increase in $y$.
        5.  `deleteMin(Event Queue)`.

        **Case B: Not Sorted (Intersection)**
        1.  Find the intersection point $(x, y)$ where two previously adjacent active edges cross.
        2.  Create a new vertex `newVertex` at this intersection.
        3.  Chop off the two intersecting edges so they end at `newVertex`.
        4.  The cut-off segments become new edges starting at `newVertex`.
        5.  Insert these new edges into `ActiveEdges` in correct $x$-order.
        6.  Insert `newVertex` into `Event Queue` (it will be the new minimum).

**Pseudocode:**
```python
def incoherent_projection(hexahedron_vertices, projection_matrix):
    # 1. Transform to screen space
    screen_vertices = [project(v, projection_matrix) for v in hexahedron_vertices]
    
    # 2. Initialize data structures
    # Event Queue: list of (y, vertex_index)
    event_queue = sorted([(v.y, i) for i, v in enumerate(screen_vertices)])
    
    # Active Edges: list of edge objects, sorted by x-intercept at current y
    # An edge connects a processed vertex to an unprocessed one.
    active_edges = []
    
    # Current Boundary: list of edge indices forming the boundary polygon
    current_boundary = []
    
    # Output polygons
    output_polygons = []
    
    processed_vertices = set()
    
    while event_queue:
        y_min, v_idx = event_queue.pop(0) # getMin
        next_vertex = screen_vertices[v_idx]
        current_y = y_min
        
        # Check if active edges are still sorted by x-intercept at current_y
        # Calculate x-intercepts for all active edges at current_y
        edge_intercepts = []
        for edge in active_edges:
            x_int = edge.x_at_y(current_y)
            edge_intercepts.append((x_int, edge))
        
        is_sorted = all(edge_intercepts[i][0] <= edge_intercepts[i+1][0] 
                        for i in range(len(edge_intercepts)-1))
        
        if is_sorted:
            # Case A: No intersections
            # Find edges ending at next_vertex
            rem_edges = [e for e in active_edges if e.end_vertex == next_vertex]
            
            # Determine z-distance for shading [S1, unofficial]
            z_dist = determine_z_distance(next_vertex, hexahedron_vertices)
            
            # Update current boundary
            if len(rem_edges) >= 1:
                e1 = rem_edges[0]
                # Insert e1 and its reversal into boundary to form a needle
                current_boundary.append(e1)
                current_boundary.append(e1.reverse())
            
            if len(rem_edges) >= 2:
                e2 = rem_edges[1]
                # Insert e2 and its reversal
                current_boundary.append(e2)
                current_boundary.append(e2.reverse())
                # Splice out the completed counterclockwise polygon
                polygon = extract_polygon_from_boundary(current_boundary)
                output_polygons.append(polygon)
                # Remove used edges from boundary? 
                # Note: The source implies splicing out the polygon, 
                # effectively removing those edges from the active boundary loop.
                remove_spliced_edges(current_boundary)
            
            # Remove processed edges from active list
            for e in rem_edges:
                active_edges.remove(e)
            
            # Add new edges starting from next_vertex
            new_edges = get_edges_starting_at(next_vertex, hexahedron_vertices, screen_vertices)
            for e in new_edges:
                active_edges.append(e)
            
            # Re-sort active_edges by x-intercept at current_y + epsilon
            active_edges.sort(key=lambda e: e.x_at_y(current_y + 1e-9))
            
            processed_vertices.add(v_idx)
            
        else:
            # Case B: Intersection detected
            # Find two adjacent edges in active_edges that intersect
            # "Previously adjacent" implies they are next to each other in the sorted list
            intersecting_edges = find_intersecting_adjacent_edges(active_edges, current_y)
            e_a, e_b = intersecting_edges
            
            # Find intersection point
            inter_x, inter_y = e_a.intersection(e_b)
            
            # Create new vertex
            new_vertex = Vertex(inter_x, inter_y, interpolate_z(e_a, e_b, inter_y))
            new_vertex_idx = len(screen_vertices) # Temporary index
            screen_vertices.append(new_vertex)
            
            # Chop off edges
            # e_a ends at new_vertex, e_b ends at new_vertex
            e_a.end_vertex = new_vertex
            e_b.end_vertex = new_vertex
            
            # Create new edges starting from new_vertex
            # The "cut-off parts" become new edges
            # This requires reconstructing the edge segments from intersection to original end
            new_e_a = Edge(e_a.start_vertex, new_vertex)
            new_e_b = Edge(e_b.start_vertex, new_vertex)
            
            # Replace old edges with new ones in active list
            active_edges.remove(e_a)
            active_edges.remove(e_b)
            active_edges.append(new_e_a)
            active_edges.append(new_e_b)
            
            # Re-sort
            active_edges.sort(key=lambda e: e.x_at_y(current_y + 1e-9))
            
            # Insert new vertex into event queue
            event_queue.append((inter_y, new_vertex_idx))
            event_queue.sort() # Maintain priority order
            
    return output_polygons, z_distances
```

**Parameters and Edge Cases:**
*   **Degeneracies (Screen Space):** If two vertices share the same $x$ or $y$ value, assume a slight rotation of screen space to resolve the tie without changing non-degenerate topology [S1, unofficial].
*   **Degeneracies (3D Geometry):** If the hexahedron has coincident vertices (zero-length edges):
    *   Assume no two adjacent edges have zero length and no two adjacent faces have zero area [S1, unofficial].
    *   If a zero-length edge is found, perturb the hexahedron to give it length while maintaining convexity.
    *   If the edge connects two faces with positive area, use the intersection line of their planes as the pull-apart direction [S1, unofficial].
    *   If adjacent to a zero-area face, use diagonally opposite edges or intersecting face planes to determine the direction [S1, unofficial].

## Operating characteristics
*   **Complexity:** The method is described as "the most expensive" of the projection methods presented [S1, unofficial]. The sweep-line algorithm runs in $O(V \log V)$ per cell for vertex sorting and edge management, where $V=8$ for a hexahedron. However, the constant factors and per-pixel polygon rasterization overhead are high.
*   **Strengths:** It handles general convex hexahedra without pre-classifying projection topologies. It correctly handles complex topologies that vary from cell to cell.
*   **Limitations:** High computational cost per cell. Requires careful handling of degeneracies. Not suitable for real-time rendering on large volumes due to per-cell overhead.
*   **When to use:** High-quality offline rendering of irregular curvilinear grids where geometric accuracy is critical and performance is secondary.

## Background
Incoherent projection was introduced in a 1993 NASA technical report by the authors of the "coherent projection" technique for rectilinear grids [S1, unofficial]. It was developed to address the limitations of coherent projection when applied to irregular hexahedral grids, where the number of non-degenerate projection topologies is significantly higher and varies per cell [S1, unofficial]. The method is part of the broader effort in rapid exploration of curvilinear grids using direct volume rendering.
