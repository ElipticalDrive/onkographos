# Incoherent Projection


## Overview
Incoherent projection is a cell-based volume rendering method that renders the 2D projection of general convex hexahedra by decomposing each cell's silhouette into an arrangement of planar polygons [S1, unofficial]. It solves the problem of handling the high number of nondegenerate projection topologies inherent in irregular hexahedral grids, where the projection shape varies significantly between cells and viewpoints [S1, unofficial]. Unlike coherent projection methods that assume uniform topology across the volume, incoherent projection analyzes each cell individually in screen space, making it robust for curvilinear grids but computationally more expensive [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A single convex hexahedron defined by 8 vertices in 3D space, transformed into screen space coordinates $(x, y, z)$.
*   **Output:** A set of 2D polygons (with associated $z$-depths) representing the visible projection of the hexahedron, ready for rasterization and compositing [S1, unofficial].

**Data Structures:**
The algorithm maintains three specific data structures during the sweep-line process [S1, unofficial]:
1.  **Event Queue:** A priority queue storing vertex events. The priority is determined by the $y$-coordinate. The "minimum" element is the unprocessed vertex with the lowest $y$-value.
2.  **Active Edges List:** A list of edges currently crossing the sweep line. An edge is "active" if it connects a processed vertex (already passed by the sweep line) to an unprocessed vertex. The list is sorted by the $x$-coordinate of the edge at the current sweep line position ($y = \text{currentY}$).
3.  **Current Boundary:** An edge list representing the polygon formed by the processed portion of the hexahedron's projection. It surrounds the processed vertices and edges.

**Algorithm Steps:**
1.  **Initialization:**
    *   Transform the hexahedron vertices into screen space.
    *   Populate the Event Queue with the 8 vertices, sorted by $y$-value.
    *   Initialize the Active Edges List and Current Boundary as empty.
    *   Identify all edges of the hexahedron. Initially, all edges connect unprocessed vertices, so none are active. As vertices are processed, edges leading to them become active.

2.  **Sweep-Line Processing:**
    While the Event Queue is not empty:
    1.  **Get Next Vertex:** Extract the vertex with the minimum $y$-value from the Event Queue. Let this be `nextVertex` and its $y$-coordinate be `currentY`.
    2.  **Check Edge Order:** For each edge in the Active Edges List, calculate its $x$-coordinate at `currentY`. Verify if the Active Edges List remains sorted by this $x$-coordinate.
    3.  **Case A: Order Preserved:**
        *   Identify all edges in the Active Edges List that terminate at `nextVertex`. Call this set `remEdges`.
        *   Remove `remEdges` from the Active Edges List.
        *   **Update Boundary:**
            *   Insert the first edge in `remEdges` and its reversal into the Current Boundary edge list. This forms a planar "needle" polygon (a degenerate polygon with zero area, effectively a line segment traversed back and forth).
            *   If a second edge is removed (completing a cycle), insert it and its reversal. This completes a counterclockwise polygon. Splice this polygon out of the Current Boundary and output it as a final projection polygon.
            *   (Note: The last vertex removal may create a second polygon to be spliced out).
        *   **Determine Depth:** Calculate the $z$-distance of `nextVertex` from the face into which it projects. This $z$-value is associated with the newly created/updated boundary segments for depth testing/compositing.
        *   **Insert New Edges:** Identify all edges originating from `nextVertex` that lead to unprocessed vertices. Insert these edges into the Active Edges List, maintaining the sort order by $x$-coordinate at `currentY` (or slightly above).
        *   Remove `nextVertex` from the Event Queue.
    4.  **Case B: Order Violated (Edge Intersection):**
        *   Find the intersection point $(x, y)$ of two previously adjacent active edges that have crossed.
        *   Create a new virtual vertex `newVertex` at this intersection.
        *   Chop the two intersecting edges so they end at `newVertex`.
        *   The cut-off segments become new edges starting at `newVertex`.
        *   Insert these new edges into the Active Edges List in the correct $x$-order.
        *   Insert `newVertex` into the Event Queue. It will be the new minimum (or processed immediately depending on implementation details, but the source states it is inserted as the minimum) [S1, unofficial].

**Pseudocode:**

def incoherent_projection(hexahedron_vertices_3d, faces):
    # 1. Transform to screen space (x, y, z)
    vertices = transform_to_screen_space(hexahedron_vertices_3d)
    
    # 2. Initialize Data Structures
    event_queue = PriorityQueue()
    for v in vertices:
        event_queue.push(v, priority=v.y)
        
    active_edges = [] # List of edges, sorted by x at current y
    current_boundary = [] # List of edges forming the current polygon boundary
    
    # Helper to get edges connected to a vertex
    def get_edges_from_vertex(v):
        return [e for e in hexahedron_edges if e.start == v or e.end == v]
        
    # Helper to calculate x-coordinate of an edge at a specific y
    def edge_x_at_y(edge, y):
        # Linear interpolation between edge endpoints
        t = (y - edge.start.y) / (edge.end.y - edge.start.y)
        return edge.start.x + t * (edge.end.x - edge.start.x)

    # Helper to check if active_edges is sorted by x at current y
    def is_sorted(active_edges, current_y):
        xs = [edge_x_at_y(e, current_y) for e in active_edges]
        return all(xs[i] <= xs[i+1] for i in range(len(xs)-1))

    while not event_queue.is_empty():
        next_vertex = event_queue.get_min()
        current_y = next_vertex.y
        
        # Check if active edges are still sorted
        if is_sorted(active_edges, current_y):
            # Case A: Order preserved
            # Find edges ending at next_vertex
            rem_edges = [e for e in active_edges if e.end == next_vertex]
            
            # Remove them from active list
            for e in rem_edges:
                active_edges.remove(e)
                
            # Update current boundary
            if len(rem_edges) >= 1:
                # Insert first removed edge and its reversal
                e1 = rem_edges[0]
                current_boundary.append(e1)
                current_boundary.append(e1.reverse())
                
            if len(rem_edges) >= 2:
                # Insert second removed edge and its reversal
                e2 = rem_edges[1]
                current_boundary.append(e2)
                current_boundary.append(e2.reverse())
                # Splice out the completed counterclockwise polygon
                # The logic implies the boundary forms a closed loop here
                output_polygon = splice_polygon(current_boundary)
                render_polygon(output_polygon, z=next_vertex.z)
                
            # Determine z-distance (depth) for the new boundary segment
            # This is associated with the projection of the vertex
            depth = next_vertex.z 
            
            # Insert new edges starting from next_vertex
            new_edges = [e for e in get_edges_from_vertex(next_vertex) if e.start == next_vertex and not is_processed(e.end)]
            
            # Insert into active_edges maintaining x-order
            for e in new_edges:
                insert_sorted(active_edges, e, key=lambda x: edge_x_at_y(x, current_y))
                
            mark_processed(next_vertex)
            
        else:
            # Case B: Order violated (intersection)
            # Find two adjacent edges in active_edges that intersect
            # Note: "previously adjacent" implies they were neighbors in the list before crossing
            intersecting_edges = find_intersecting_adjacent_edges(active_edges, current_y)
            
            if len(intersecting_edges) == 2:
                e_a, e_b = intersecting_edges
                # Find intersection point
                new_vertex = compute_intersection(e_a, e_b)
                
                # Chop edges
                # e_a ends at new_vertex
                e_a.end = new_vertex
                # e_b ends at new_vertex
                e_b.end = new_vertex
                
                # Create new edges starting at new_vertex
                # The parts of e_a and e_b that were cut off become new edges
                # Original e_a went from start_a to old_end_a. Now start_a to new_vertex.
                # The part from new_vertex to old_end_a is a new edge
                new_edge_a = Edge(new_vertex, e_a.original_end)
                new_edge_b = Edge(new_vertex, e_b.original_end)
                
                # Remove old edges from active list? 
                # The source says "chop off... cut-off parts become new edges... insert new edges"
                # Implicitly, the old edges are replaced or modified.
                # We remove the old versions and add the new ones
                active_edges.remove(e_a)
                active_edges.remove(e_b)
                
                # Insert new edges in correct x-order
                insert_sorted(active_edges, new_edge_a, key=lambda x: edge_x_at_y(x, current_y))
                insert_sorted(active_edges, new_edge_b, key=lambda x: edge_x_at_y(x, current_y))
                
                # Insert new vertex into event queue
                # It will be the minimum (or processed next)
                event_queue.push(new_vertex, priority=new_vertex.y)

**Parameters and Typical Values:**
*   **Screen Space Rotation:** To handle degeneracies where two vertices share an $x$ or $y$ coordinate, a slight rotation of the screen space is assumed. The angle is infinitesimal, sufficient to break ties without altering nondegenerate topology [S1, unofficial].
*   **Degeneracy Handling:** If the hexahedron has coincident vertices (zero-length edges), the algorithm perturbs the geometry. It finds a direction to "pull apart" the coincident vertices based on the intersection of adjacent face planes or diagonally opposite edges, ensuring convexity is maintained [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Projection Degeneracies:** Occur when two projected vertices have identical $x$ or $y$ values. Resolved by assuming a slight screen space rotation [S1, unofficial].
*   **Geometric Degeneracies:** Occur if the input hexahedron has zero-length edges or zero-area faces. The algorithm assumes no two adjacent edges have zero length and no two adjacent faces have zero area. If encountered, the hexahedron is perturbed [S1, unofficial].
*   **Complexity:** The algorithm is described as the "most expensive" of the projection methods presented [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The algorithm follows a sweep-line pattern. For a hexahedron with 8 vertices and 12 edges, the event queue processes 8 vertices plus potential intersection vertices. The active edge list is small (at most 12 edges). Sorting and insertion are $O(E \log E)$ or $O(E)$ depending on implementation, where $E$ is the number of edges. However, the overhead of managing the boundary and handling intersections makes it significantly slower than coherent methods [S1, unofficial].
*   **Memory Complexity:** $O(V + E)$ per cell, where $V=8$ and $E=12$. The data structures are local to each cell.
*   **Strengths:** Handles general convex hexahedra without case analysis for projection topologies. Robust for irregular/curvilinear grids.
*   **Limitations:** Computationally expensive. Requires careful handling of degeneracies. Not suitable for real-time rendering of large volumes compared to coherent methods [S1, unofficial].
*   **When to use:** When rendering curvilinear grids with significant distortion where coherent projection fails due to varying topologies.
*   **When not to use:** When performance is critical and the grid is rectilinear or mildly distorted.

## Background
Incoherent projection was introduced in a 1993 NASA technical report by West et al. [S1, unofficial]. It builds upon the "coherent projection" technique for rectilinear grids [WVG91] and extends it to general convex hexahedra. The method was developed to allow rapid exploration of curvilinear grids using direct volume rendering, addressing the limitations of existing methods that could not efficiently handle the complex projection topologies of irregular cells [S1, unofficial].
