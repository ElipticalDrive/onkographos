# 2D Raycasting with Z-Buffering

Also called: Block Surface Rasterization with Depth Testing, Software 3D Cube Face Projection & Rasterization with Z-Buffering

## Overview
A software rendering method that projects 3D voxel block surfaces onto a 2D screen using perspective projection and resolves depth using a per-pixel Z-buffer [S1, unofficial]. It differs from standard raycasting by rasterizing explicit polygonal faces of blocks rather than casting rays per pixel, and from hardware rasterization by performing all depth testing and pixel writing in software [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A chunk of voxel data (3D grid of blocks), player position $(player.x, player.y, player.z)$, and player view angle.
*   **Output:** A 2D frame buffer containing the rendered image.

**Data Structures:**
*   **Z-buffer:** A 2D array of floats `zBuffer[SCR_WIDTH][SCR_HEIGHT]`, initialized to `INT_MAX` [S1, unofficial].
*   **Frame Buffer:** A 2D array of color structs `frameBuffer[SCR_WIDTH][SCR_HEIGHT]`, initialized to a background color [S1, unofficial].
*   **Block Coordinates:** World coordinates for block corners, transformed into camera-relative space.

**Parameters:**
*   `SCR_WIDTH`: Screen width in pixels. Formula: $200 \times res$ (default $res=1 \rightarrow 200$) [S1, unofficial].
*   `SCR_HEIGHT`: Screen height in pixels. Formula: $150 \times res$ (default $res=1 \rightarrow 150$) [S1, unofficial].
*   `SCR_WIDTH_HALF`: $SCR\_WIDTH / 2$ [S1, unofficial].
*   `SCR_HEIGHT_HALF`: $SCR\_HEIGHT / 2$ [S1, unofficial].
*   `PROJECTION_SCALE`: 200 [S1, unofficial].
*   `BLOCK_SIZE`: Size of a single voxel block in world units [S1, unofficial].
*   `CHUNK_SIZE`: Dimensions of the chunk being rendered [S1, unofficial].

**Steps:**
1.  **Initialize Buffers:** Set all entries in `zBuffer` to `INT_MAX` and all entries in `frameBuffer` to the background color [S1, unofficial].
2.  **Iterate Blocks:** For each block in the chunk at grid coordinates $(x, y, z)$:
    a. Calculate world coordinates for the block's bottom corner:
       $$blockX = chunkX + x \times BLOCK\_SIZE$$
       $$blockY = chunkY + y \times BLOCK\_SIZE$$
       $$blockZ_{bottom} = chunkZ + z \times BLOCK\_SIZE$$
       $$blockZ_{top} = blockZ_{bottom} + BLOCK\_SIZE$$
    b. **Determine Orientation:** Compare player's Z position to the block's Z range to determine which faces are visible:
       *   If $player.z < blockZ_{bottom}$: Top face is visible (Orientation 1).
       *   If $player.z > blockZ_{top}$: Bottom face is visible (Orientation 2).
       *   Otherwise: Side faces are visible (Orientation 0).
    c. **Transform Corners:** For each relevant face, calculate the 2D screen coordinates of its four corners. First, transform world coordinates to camera-relative space using rotation matrix based on `player.angle`:
       $$x_{rel} = worldX - player.x$$
       $$y_{rel} = worldY - player.y$$
       $$x_{rot} = x_{rel} \times \cos(\theta) - y_{rel} \times \sin(\theta)$$
       $$y_{rot} = y_{rel} \times \cos(\theta) + x_{rel} \times \sin(\theta)$$
       where $\theta = player.angle \times \pi / 180$.
    d. **Project to Screen:** Apply perspective projection to get screen coordinates:
       $$screenX = \frac{x_{rot} \times PROJECTION\_SCALE}{y_{rot}} + SCR\_WIDTH\_HALF$$
       $$screenY = \frac{z_{rot} \times PROJECTION\_SCALE}{y_{rot}} + SCR\_HEIGHT\_HALF$$
       *(Note: The source uses `worldY` in the denominator, which corresponds to the depth axis in the camera's local space after rotation, typically `y_rot` in this specific implementation's coordinate system where Y is depth)* [S1, unofficial].
    e. **Clip:** Skip the face if any part of it is behind the player (specifically if the depth $y_{rot} < 1$) [S1, unofficial].
    f. **Rasterize:** Draw the polygon defined by the four projected corners. For each pixel $(sx, sy)$ covered by the polygon:
       i. Calculate the interpolated depth $d$ at $(sx, sy)$ [S1, unofficial].
       ii. If $d < zBuffer[sx][sy]$:
           *   Update `frameBuffer[sx][sy]` with the block's color.
           *   Update `zBuffer[sx][sy] = d`.

**Pseudocode:**
```python
import math

def render_block(block, player, z_buffer, frame_buffer, screen_width, screen_height, block_size, projection_scale):
    # 1. Calculate world coordinates
    block_x = block.chunk_x + block.grid_x * block_size
    block_y = block.chunk_y + block.grid_y * block_size
    block_z_bottom = block.chunk_z + block.grid_z * block_size
    block_z_top = block_z_bottom + block_size

    # 2. Determine orientation
    orientations = []
    if player.z < block_z_bottom:
        orientations.append('top')
    if player.z > block_z_top:
        orientations.append('bottom')
    if block_z_bottom <= player.z <= block_z_top:
        orientations.append('side')

    # 3. Process each orientation
    for orientation in orientations:
        # Define corners based on orientation
        # This part depends on specific face geometry. 
        # For simplicity, we assume a helper `get_face_corners` returns 4 world points.
        corners_world = get_face_corners(block, orientation, block_size)
        
        corners_screen = []
        valid_face = True
        
        for wx, wy, wz in corners_world:
            # Camera relative transform
            dx = wx - player.x
            dy = wy - player.y
            
            # Rotation
            theta = math.radians(player.angle)
            cos_a = math.cos(theta)
            sin_a = math.sin(theta)
            
            x_rot = dx * cos_a - dy * sin_a
            y_rot = dy * cos_a + dx * sin_a
            
            # Clip if behind player
            if y_rot < 1:
                valid_face = False
                break
            
            # Project
            scale = projection_scale
            sx = int(x_rot * scale / y_rot + screen_width / 2)
            sy = int(wz * scale / y_rot + screen_height / 2) # Assuming Z maps to vertical screen Y
            
            corners_screen.append((sx, sy, y_rot)) # Store depth for interpolation
        
        if not valid_face or len(corners_screen) < 3:
            continue
            
        # 4. Rasterize
        # Draw polygon defined by corners_screen
        # For each pixel in bounding box:
        #   Interpolate depth d
        #   if d < z_buffer[x][y]:
        #       z_buffer[x][y] = d
        #       frame_buffer[x][y] = block.color

def render_chunk(chunk, player, z_buffer, frame_buffer, screen_width, screen_height, block_size, projection_scale):
    for x in range(chunk.size_x):
        for y in range(chunk.size_y):
            for z in range(chunk.size_z):
                block = chunk.get_block(x, y, z)
                if block.is_active():
                    render_block(block, player, z_buffer, frame_buffer, screen_width, screen_height, block_size, projection_scale)
```

## Operating characteristics
*   **Time Complexity:** $O(W \times H \times N)$, where $W, H$ are screen dimensions and $N$ is the number of visible block faces. Rasterization is linear in screen pixels.
*   **Memory Complexity:** $O(W \times H)$ for the Z-buffer and Frame Buffer [S1, unofficial].
*   **Performance:** Software-based, so performance is limited by CPU speed. Resolution is typically low (e.g., 200x150) to maintain real-time frame rates [S1, unofficial].
*   **Strengths:** Simple implementation, no hardware dependencies, easy to debug.
*   **Limitations:** Slow for high resolutions, no hardware acceleration, limited to simple block geometries.

## Background
This method is derived from early 3D rendering techniques used in software raycasters and voxel engines, specifically those mimicking the style of 1993-era games [S1, unofficial]. It combines the block-based world representation of voxel engines with the depth-testing mechanism of the Z-buffer algorithm [S1, unofficial].
