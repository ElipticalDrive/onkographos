# 2D Raycasting with Z-Buffering

Also called: Block Surface Rasterization with Depth Testing, Software 3D Cube Face Projection & Rasterization with Z-Buffering

## Overview
A software rendering method that projects 3D voxel block surfaces onto a 2D screen using perspective projection and resolves depth using a per-pixel Z-buffer [S1, unofficial]. It differs from standard raycasting by rasterizing explicit polygonal faces of blocks rather than casting rays per pixel, and from hardware rasterization by performing all depth testing and pixel writing in software [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A chunk of voxel data (3D grid of blocks), player position $(player.x, player.y, player.z)$, and player view angle [S1, unofficial].
*   **Output:** A 2D frame buffer containing the rendered image [S1, unofficial].

**Data Structures:**
*   **Z-buffer:** A 2D array of floats `zBuffer[SCR_WIDTH][SCR_HEIGHT]`, initialized to `INT_MAX` [S1, unofficial].
*   **Frame Buffer:** A 2D array of color structs `frameBuffer[SCR_WIDTH][SCR_HEIGHT]`, initialized to a background color [S1, unofficial].

**Parameters:**
*   `SCR_WIDTH`: Screen width in pixels, calculated as $200 \times res$ (default $res=1 \rightarrow 200$) [S1, unofficial].
*   `SCR_HEIGHT`: Screen height in pixels, calculated as $150 \times res$ (default $res=1 \rightarrow 150$) [S1, unofficial].
*   `SCR_WIDTH_HALF`: $SCR\_WIDTH / 2$ [S1, unofficial].
*   `SCR_HEIGHT_HALF`: $SCR\_HEIGHT / 2$ [S1, unofficial].
*   `PROJECTION_SCALE`: 200 [S1, unofficial].
*   `BLOCK_SIZE`: Size of a single voxel block in world units [S1, unofficial].
*   `CHUNK_SIZE`: Internal grid dimension for chunk iteration [S1, unofficial].

**Steps:**
1.  **Initialize Buffers:** Set all entries in `zBuffer` to `INT_MAX` and all entries in `frameBuffer` to the background color [S1, unofficial].
2.  **Iterate Blocks:** For each block in the chunk at grid coordinates $(x, y, z)$:
    a. Calculate world coordinates for the block's bottom corner:
       $$blockX = chunkX + x \times BLOCK\_SIZE$$
       $$blockY = chunkY + y \times BLOCK\_SIZE$$
       $$blockZ_{bottom} = chunkZ + z \times BLOCK\_SIZE$$
       $$blockZ_{top} = blockZ_{bottom} + BLOCK\_SIZE$$
    b. **Determine Orientation:** Compare player's Z position to the block's Z range to determine which faces are visible:
       *   If $player.z < blockZ_{bottom}$: Top face is visible (Orientation 1) [S1, unofficial].
       *   If $player.z > blockZ_{top}$: Bottom face is visible (Orientation 2) [S1, unofficial].
       *   Otherwise: Side faces are visible (Orientation 0) [S1, unofficial].
    c. **Transform Corners:** For each relevant face, calculate the 2D screen coordinates of its four corners [S1, unofficial]. First, transform world coordinates to camera-relative space using rotation based on `player.angle`:
       $$x_{rel} = worldX - player.x$$
       $$y_{rel} = worldY - player.y$$
       $$x_{rot} = x_{rel} \times \cos(\theta) - y_{rel} \times \sin(\theta)$$
       $$y_{rot} = y_{rel} \times \cos(\theta) + x_{rel} \times \sin(\theta)$$
       where $\theta = player.angle \times \pi / 180$ [S1, unofficial].
    d. **Project to Screen:** Apply perspective projection to get screen coordinates:
       $$screenX = \frac{x_{rot} \times PROJECTION\_SCALE}{y_{rot}} + SCR\_WIDTH\_HALF$$
       $$screenY = \frac{z_{rot} \times PROJECTION\_SCALE}{y_{rot}} + SCR\_HEIGHT\_HALF$$
       *(Note: The source uses `worldY` in the denominator, which corresponds to the depth axis in the camera's local space after rotation, typically `y_rot` in this implementation)* [S1, unofficial].
    e. **Clip:** Skip the face if the depth $y_{rot} < 1$ [S1, unofficial].
    f. **Rasterize:** Draw the surface pixels [S1, unofficial]. For each pixel $(sx, sy)$ covered by the projected face:
       i. Calculate the depth $d$ at $(sx, sy)$ [S1, unofficial].
       ii. If $d < zBuffer[sx][sy]$:
           *   Update `frameBuffer[sx][sy]` with the block's color.
           *   Update `zBuffer[sx][sy] = d` [S1, unofficial].

**Pseudocode:**
```python
import math

def render_chunk(chunk, player, z_buffer, frame_buffer, screen_width, screen_height, block_size, projection_scale, background_color):
    # 1. Initialize buffers
    for x in range(screen_width):
        for y in range(screen_height):
            z_buffer[x][y] = float('inf')  # INT_MAX
            frame_buffer[x][y] = background_color

    # 2. Iterate blocks
    for x in range(chunk.size_x):
        for y in range(chunk.size_y):
            for z in range(chunk.size_z):
                block = chunk.get_block(x, y, z)
                if not block.is_active():
                    continue

                block_x = chunk.x + x * block_size
                block_y = chunk.y + y * block_size
                block_z_bottom = chunk.z + z * block_size
                block_z_top = block_z_bottom + block_size

                # 3. Determine orientations to render
                orientations = []
                if player.z < block_z_bottom:
                    orientations.append('top')
                if player.z > block_z_top:
                    orientations.append('bottom')
                if block_z_bottom <= player.z <= block_z_top:
                    orientations.append('side')

                # 4. Process each orientation
                for orientation in orientations:
                    corners_world = get_face_corners(block_x, block_y, block_z_bottom, block_z_top, orientation, block_size)
                    corners_screen = []
                    valid_face = True

                    for wx, wy, wz in corners_world:
                        dx = wx - player.x
                        dy = wy - player.y

                        theta = math.radians(player.angle)
                        cos_a = math.cos(theta)
                        sin_a = math.sin(theta)

                        x_rot = dx * cos_a - dy * sin_a
                        y_rot = dy * cos_a + dx * sin_a

                        if y_rot < 1:
                            valid_face = False
                            break

                        scale = projection_scale
                        sx = int(x_rot * scale / y_rot + screen_width / 2)
                        sy = int(wz * scale / y_rot + screen_height / 2)

                        corners_screen.append((sx, sy, y_rot))

                    if not valid_face or len(corners_screen) < 3:
                        continue

                    # 5. Rasterize face
                    min_x = max(0, min(c[0] for c in corners_screen))
                    max_x = min(screen_width - 1, max(c[0] for c in corners_screen))
                    min_y = max(0, min(c[1] for c in corners_screen))
                    max_y = min(screen_height - 1, max(c[1] for c in corners_screen))

                    face_depth = corners_screen[0][2]
                    for px in range(min_x, max_x + 1):
                        for py in range(min_y, max_y + 1):
                            if face_depth < z_buffer[px][py]:
                                z_buffer[px][py] = face_depth
                                frame_buffer[px][py] = block.color

def get_face_corners(block_x, block_y, block_z_bottom, block_z_top, orientation, block_size):
    if orientation == 'top':
        return [
            (block_x, block_y, block_z_top),
            (block_x + block_size, block_y, block_z_top),
            (block_x + block_size, block_y + block_size, block_z_top),
            (block_x, block_y + block_size, block_z_top)
        ]
    elif orientation == 'bottom':
        return [
            (block_x, block_y, block_z_bottom),
            (block_x + block_size, block_y, block_z_bottom),
            (block_x + block_size, block_y + block_size, block_z_bottom),
            (block_x, block_y + block_size, block_z_bottom)
        ]
    else:
        return [
            (block_x, block_y, block_z_bottom),
            (block_x + block_size, block_y, block_z_bottom),
            (block_x + block_size, block_y, block_z_top),
            (block_x, block_y, block_z_top)
        ]
```

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** $O(W \times H)$ for the Z-buffer and Frame Buffer [S1, unofficial].
*   **Performance:** Software-based, so performance is limited by CPU speed [S1, unofficial].
*   **Strengths:** Simple implementation, no hardware dependencies, easy to debug [S1, unofficial].
*   **Limitations:** Slow for high resolutions, no hardware acceleration, limited to simple block geometries [S1, unofficial].

## Background
This method originates from a software voxel rendering implementation that combines block-based world representation with a per-pixel Z-buffer depth-testing mechanism [S1, unofficial].
