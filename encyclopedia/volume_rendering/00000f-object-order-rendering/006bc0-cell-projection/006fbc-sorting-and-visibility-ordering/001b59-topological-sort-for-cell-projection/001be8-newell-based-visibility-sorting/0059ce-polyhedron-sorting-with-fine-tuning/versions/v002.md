# Polyhedron Sorting with Fine-Tuning

Also called: Hidden surface removal for volume primitives, Shirley-Tuckman extension for unstructured data

## Overview
A three-stage sorting algorithm for rendering convex polyhedra (volume primitives) in correct back-to-front depth order, specifically designed to handle non-planar faces and rendering cycles [S1]. It extends polygon-based visibility sorting to polyhedra by introducing a fine-tuning stage that uses plane separation tests and edge intersection checks to resolve ambiguities that a simple Z-depth sort cannot handle [S1].

## How it works
The algorithm sorts a list of $N$ convex polyhedra into back-to-front order relative to the viewer [S1]. It consists of three stages: viewing transformation, rough sorting, and fine-tuning [S1].

### Inputs and Outputs
*   **Input**: A list $H$ of $N$ convex polyhedra. Each polyhedron $P$ is defined by a set of vertices and faces [S1].
*   **Output**: A sorted list $H$ where $P_i$ precedes $P_j$ if $P_i$ is behind $P_j$ (i.e., $P_j$ obscures $P_i$) [S1].

### Data Structures
*   **Polyhedron $P$**:
    *   `vertices`: List of 3D points $(x, y, z)$.
    *   `faces`: List of faces.
    *   `face_normals`: Pre-computed average outward normals for each face.
    *   `face_planes`: Pre-computed plane coefficients $(a, b, c, d)$ for each face.
    *   `Z_rearmost`: The maximum $Z$ coordinate of all vertices after viewing transformation (used for rough sort) [S1].
*   **Face Plane**: Defined by $ax + by + cz + d = 0$ [S1].
*   **Edge**: Defined by two vertices [S1].

### Pre-processing
1.  **Viewing Transformation**: Apply viewing transformations to all vertices to obtain screen coordinates with perspective-corrected $Z$. Scale $Z$ such that the eye looks down the $Z$ axis towards negative infinity in a right-handed coordinate system. Sort by increasing $Z$ [S1].
2.  **Face Normal and Plane Calculation**: For each face with $n$ vertices $(x_i, y_i, z_i)$, calculate the average outward normal $(a, b, c)$ using Newell's method [S1]:
    $$ a = \frac{1}{n} \sum_{i=1}^{n} (y_i - y_j)(z_i + z_j) $$
    $$ b = \frac{1}{n} \sum_{i=1}^{n} (z_i - z_j)(x_i + x_j) $$
    $$ c = \frac{1}{n} \sum_{i=1}^{n} (x_i - x_j)(y_i + y_j) $$
    where $j = (i+1) \pmod n$ [S1].
3.  **Plane Coefficient $d$**: Calculate $d$ using the centroid of the face $(\bar{x}, \bar{y}, \bar{z})$ as a point on the plane:
    $$ d = -(a\bar{x} + b\bar{y} + c\bar{z}) $$
    where $\bar{x} = \frac{1}{n}\sum x_i$, etc. [S1].
4.  **Face Classification**: Determine if a face is front-facing or back-facing based on the $Z$ component of its outward normal. In a right-handed system where the eye looks down the $Z$ axis, a positive $Z$ component of the normal indicates a front-facing polygon; otherwise it is back-facing [S1].
5.  **Tolerance $\delta$**: For each face, calculate $\delta$ as the maximum deviation of any vertex of that face from its average plane. This tolerance is used to handle non-planar faces and round-off errors [S1].

### Fine-Tuning Sort Algorithm
The fine-tuning stage iterates through the list $H$ to correct the order established by the rough sort [S1]. For each pair of adjacent polyhedra $P$ and $Q$ (where $P$ is currently before $Q$ in the list), the algorithm determines if they are in the correct order [S1].

**Step 1: Test if $P$ is behind $Q$ (Separating Plane Test)**
Check if all vertices of $P$ lie behind a plane defined by any back-facing polygon of $Q$ [S1]. For each back-facing face of $Q$ with plane equation $f(x,y,z) = ax+by+cz+d$:
$$ f(x_j, y_j, z_j) \ge -\delta \quad \forall \text{ vertices } j \in P $$
If this holds for at least one back-facing face of $Q$, then $P$ is behind $Q$. The order is correct. Return `True` [S1].

**Step 2: Test if $Q$ is in front of $P$ (Separating Plane Test)**
Check if all vertices of $Q$ lie in front of a plane defined by any front-facing polygon of $P$ [S1]. For each front-facing face of $P$ with plane equation $f(x,y,z) = ax+by+cz+d$:
$$ f(x_j, y_j, z_j) \ge -\delta \quad \forall \text{ vertices } j \in Q $$
If this holds for at least one front-facing face of $P$, then $Q$ is in front of $P$. The order is correct. Return `True` [S1].

**Step 3: Edge Intersection Test**
If Tests 1 and 2 fail, call `EdgeIntersection(P, Q)` [S1].
1.  Project all edges of $P$ and $Q$ onto the screen plane [S1].
2.  Find all intersection points between edges of $P$'s projection and edges of $Q$'s projection [S1].
3.  If no intersections are found:
    *   If the projections are disjoint, the order does not matter. Return `True` [S1].
    *   If the projections overlap but no edges intersect, assume the polyhedron with the larger $Z_{rearmost}$ is in front. If $Z_{rearmost}(Q) > Z_{rearmost}(P)$, return `True`. Else, return `False` [S1].
4.  If intersections are found:
    *   For each intersection point, calculate the $Z$ coordinate on the surface of $P$ ($Z_P$) and on the surface of $Q$ ($Z_Q$) [S1].
    *   If $Z_P < Z_Q$ for any intersection, $P$ is in front. Return `True` [S1].
    *   If $Z_Q < Z_P$ for any intersection, $Q$ is in front. Return `False` [S1].
    *   If $Z_P = Z_Q$ for all intersections, continue searching for an inequality. If none found, return `False` (ambiguous/cycle) [S1].

**Step 4: Cycle Handling and Resolution**
If `EdgeIntersection` returns `False` (indicating $Q$ obscures $P$ or a cycle exists):
1.  Move $Q$ to the head of the list $H$ [S1].
2.  Repeat the fine-tuning process with $Q$ as the new $P$ and the next polyhedron as $Q$ [S1].
3.  **Cycle Detection**: Tag polyhedra that have been moved to the head. If a polyhedron $Q$ is already tagged when it becomes the new $P$, a cycle has been detected (e.g., $A$ obscures $B$, $B$ obscures $C$, $C$ obscures $A$) [S1].
4.  **Cycle Resolution**: If a cycle is detected or all tests fail, render the polyhedron whose $Z_{rearmost}$ is further from the eye (smaller $Z$) first [S1].

### Pseudocode

```python
def sort_polyhedra(polyhedra):
    # Stage 1: Viewing Transformation
    for P in polyhedra:
        P.transform_view()
        P.calculate_rearmost_z()
        P.calculate_face_normals_and_planes()
        P.calculate_face_tolerances()

    # Stage 2: Rough Sort
    polyhedra.sort(key=lambda P: P.Z_rearmost)

    # Stage 3: Fine-Tuning Sort
    changed = True
    while changed:
        changed = False
        for i in range(len(polyhedra) - 1):
            P = polyhedra[i]
            Q = polyhedra[i+1]
            P.tagged = False
            Q.tagged = False

            # Test 3: Check if P is behind Q
            if is_behind(P, Q):
                continue
            # Test 4: Check if Q is in front of P
            if is_in_front(Q, P):
                continue
            # Test 5: Edge Intersection Test
            result = edge_intersection(P, Q)
            if result == "P_in_front" or result == "Disjoint":
                continue
            else:
                # Q obscures P or cycle detected
                if Q.tagged:
                    # Cycle resolution: render further polyhedron first
                    if P.Z_rearmost < Q.Z_rearmost:
                        pass # Correct order
                    else:
                        polyhedra[i], polyhedra[i+1] = polyhedra[i+1], polyhedra[i]
                        changed = True
                        break
                else:
                    # Move Q to head, repeat tests
                    polyhedra.pop(i+1)
                    polyhedra.insert(0, Q)
                    changed = True
                    break
    return polyhedra

def is_behind(P, Q):
    for face in Q.back_facing_faces:
        all_behind = True
        for v in P.vertices:
            if face.plane_evaluate(v) < -face.tolerance:
                all_behind = False
                break
        if all_behind:
            return True
    return False

def is_in_front(Q, P):
    for face in P.front_facing_faces:
        all_in_front = True
        for v in Q.vertices:
            if face.plane_evaluate(v) < -face.tolerance:
                all_in_front = False
                break
        if all_in_front:
            return True
    return False

def edge_intersection(P, Q):
    intersections = []
    for eP in P.edges:
        for eQ in Q.edges:
            pt_2d = intersect_2d_segments(eP.screen_proj, eQ.screen_proj)
            if pt_2d is not None:
                zP = interpolate_z_on_surface(P, eP, pt_2d)
                zQ = interpolate_z_on_surface(Q, eQ, pt_2d)
                intersections.append((pt_2d, zP, zQ))

    if not intersections:
        if bounding_boxes_overlap(P.screen_bbox, Q.screen_bbox):
            if P.Z_rearmost > Q.Z_rearmost:
                return "Q_in_front"
            else:
                return "P_in_front"
        else:
            return "Disjoint"

    for pt_2d, zP, zQ in intersections:
        if zP < zQ:
            return "P_in_front"
        elif zQ < zP:
            return "Q_in_front"
    return "Q_in_front" # Equal Z, continue searching -> assume Q in front per source

def intersect_2d_segments(seg1, seg2):
    # Standard 2D line segment intersection returning point or None
    x1, y1 = seg1.p1; x2, y2 = seg1.p2
    x3, y3 = seg2.p1; x4, y4 = seg2.p2
    denom = (x1-x2)*(y3-y4) - (y1-y2)*(x3-x4)
    if abs(denom) < 1e-9: return None
    t = ((x1-x3)*(y3-y4) - (y1-y3)*(x3-x4)) / denom
    u = -((x1-x2)*(y1-y3) - (y1-y2)*(x1-x3)) / denom
    if 0 <= t <= 1 and 0 <= u <= 1:
        return (x1 + t*(x2-x1), y1 + t*(y2-y1))
    return None

def interpolate_z_on_surface(poly, edge, pt_2d):
    # Linear interpolation of Z along the 3D edge based on 2D screen projection
    t = ((pt_2d[0] - edge.p1_screen[0]) / (edge.p2_screen[0] - edge.p1_screen[0])) if edge.p2_screen[0] != edge.p1_screen[0] else 0.5
    return edge.p1_z + t * (edge.p2_z - edge.p1_z)

def bounding_boxes_overlap(bbox1, bbox2):
    return (bbox1.min_x <= bbox2.max_x and bbox1.max_x >= bbox2.min_x and
            bbox1.min_y <= bbox2.max_y and bbox1.max_y >= bbox2.min_y)
```

## Operating characteristics
*   **Time Complexity**: The fine-tuning sort is $O(N^2)$ in the worst case, where $N$ is the number of polyhedra. This occurs when all polyhedra have overlapping $Z$ extents, forcing the algorithm to perform the expensive edge intersection tests for many pairs [S1]. Tests 1 and 2 are $O(1)$. Tests 3 and 4 are $O(F_i E_j)$ and $O(E_i F_j)$ respectively, where $F$ is the number of faces and $E$ is the number of vertices/edges. Test 5 (Edge Intersection) is $O(E_i E_j)$ [S1].
*   **Memory Complexity**: Not given in the sources.
*   **Measured Performance**: On an SGI Indigo2 workstation, a simple QuickSort could interactively sort thousands of elements, but the correct fine-tuning sort slowed down to a few hundred elements [S1].
*   **Strengths**: Correctly handles non-planar faces and cycles, which are common in finite element meshes. More efficient than linear programming methods for hidden surface removal [S1].
*   **Limitations**: Quadratic worst-case time complexity makes it unsuitable for very large datasets without acceleration structures. The tolerance $\delta$ is calculated per face based on the maximum vertex deviation from the average plane to prevent round-off cycles [S1].

## Background
The algorithm was developed for the SGI Explorer volume visualization system to sort pyramid-type volume primitives (tetrahedra, pyramids, prisms, wedges, and bricks) on the SGI Indigo2 workstation [S1]. It extends the work of Michael E. Newell on procedure models for digital image synthesis [S1]. The method addresses the limitations of simple Z-sorting by providing a robust hidden surface removal technique for convex volume primitives [S1].
