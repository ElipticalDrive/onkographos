# Adaptive Delaunay Update

Also called: Delaunay Update Frequency

## Overview
Adaptive Delaunay Update maintains a valid Delaunay tetrahedral mesh during optimization-based volume rendering by periodically recomputing the triangulation as vertex positions change [S1, unofficial]. It sets itself apart from continuous incremental update methods by recomputing the full triangulation at fixed intervals, which balances GPU rendering speed with mesh validity [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A valid Delaunay tetrahedral mesh, current vertex positions, and an iteration counter [S1, unofficial].
- Output: An updated Delaunay tetrahedral mesh with vertex positions and topology synchronized to the current optimization state [S1, unofficial].

**Data Structures:**
- **Mesh:** A collection of tetrahedra, each defined by 4 vertex indices [S1, unofficial].
- **Vertex Attributes:** Position $(x, y, z)$ and optimization parameters (e.g., color, density) [S1, unofficial].
- **Iteration Counter:** Tracks the number of optimization steps [S1, unofficial].

**Steps:**
1. **Vertex Update:** During optimization, update the position of vertices [S1, unofficial].
2. **Periodic Full Update:** To avoid the computational cost of continuous geometric checks, the full Delaunay triangulation is recomputed from scratch at fixed intervals [S1, unofficial].
3. **Update Frequency:** Recompute the Delaunay triangulation every 10 iterations [S1, unofficial].

**Parameters:**
- **Update Frequency:** 10 iterations [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Computational Cost:** Recomputing a Delaunay triangulation from scratch is slow, which is why incremental updates are avoided in favor of periodic full updates [S1, unofficial].
- **Precision:** Floating-point precision errors in circumsphere calculations can cause incorrect flip decisions. Guard clauses or epsilon thresholds may be needed [G].

## Subtopics

### [Radiance Meshes](4929-radiance-meshes.md)
Radiance Meshes represent radiance fields using constant density tetrahedral cells produced via Delaunay tetrahedralization. Unlike Voronoi-based methods (e.g., RadFoam) that require complex polyhedral tessellation, or splatting methods (e.g., 3DGS) that rely on approximate sorting, Radiance Meshes use simple triangles native to hardware rasterizers to enable exact, fast volume rendering. It solves the trade-off between optimization dynamics and rendering speed by decoupling topology (Delaunay mesh) from attribute parameterization (Instant-NGP).

### [Delaunay Triangulation](11773-delaunay-triangulation.md)
Delaunay triangulation constructs a mesh from a set of points $S$ by maximizing the minimum angle of the triangles, producing optimal meshes for a given set of points. It is defined as the straight-line dual of the Voronoi diagram of $S$, assuming no two points are connected by a straight line and no four points are cocircular.

### [Delaunay Cover Refinement](13422-delaunay-cover-refinement.md)
Delaunay Cover Refinement is a mesh generation technique that iteratively subdivides a Delaunay triangulation to ensure all edge lengths are bounded by a user-defined threshold $h$. It solves the problem of generating a uniformly sampled point cloud from an initial point set, which serves as a prerequisite for subsequent voxelization or surface reconstruction steps. Unlike standard Delaunay Triangulation which only optimizes local geometry, this method enforces a global density constraint through recursive splitting.

### [Delaunay Edge Flipping (Pachner Moves)](6368-delaunay-edge-flipping-pachner-moves.md)
Delaunay Edge Flipping is a local topological update method that transforms an arbitrary triangulation into a Delaunay triangulation by iteratively removing non-Delaunay edges [G]. In 3D, these operations are specifically termed Pachner moves [G]. It is chosen when a valid initial triangulation exists but requires refinement to satisfy the empty circumsphere property, particularly in dynamic scenarios where vertex perturbations violate the Delaunay condition [G]. Unlike global reconstruction methods, it operates locally on existing connectivity [G].

### Hybrid Rendering with Multi-Resolution Tetrahedral Mesh
Extends multi triangulation to support multiple visualization techniques simultaneously within a single data structure, allowing independent mesh adaptation per technique [S2]. Store one DAG per technique to control refinement and coarsening [S2]. Store three faceincidency entries per tetrahedron face (one for each technique) [S2]. Triple the cross-patch face hash map [S2]. The renderer adapts the mesh to each technique independently, enabling direct volume rendering to use fewer tetrahedra than isosurface extraction [S2]. Each tetrahedron stores three faceincidency entries per face [S2]. The cross-patch face hash map is tripled [S2]. Three separate DAGs are stored, one per visualization technique [S2].

### [Variational Isotropic Meshing](21467-variational-isotropic-meshing.md)
Variational Isotropic Meshing is a two-phase method for computing high-quality triangular meshes from a given implicit surface $S$ (a 2-manifold) within a domain $\Omega \subset \mathbb{R}^3$ [G]. It solves the problem of generating meshes that are both topologically correct (homeomorphic to $S$) and geometrically accurate (isotropic sampling and optimal approximation) [G]. It sets itself apart from standard Delaunay refinement by incorporating a variational relaxation phase that optimizes vertex positions via Centroidal Voronoi Tessellation (CVT) principles and Quadric Error Metrics (QEM), ensuring uniform normal variation and improved shape approximation.

## Operating characteristics
- **Time Complexity:** Full Delaunay triangulation is $O(N \log N)$ or worse depending on the algorithm, where $N$ is the number of vertices [G]. Incremental updates are local but require checking neighbors [G].
- **Memory Complexity:** $O(N)$ for storing vertices and tetrahedra [G]. Hybrid rendering triples the face hash map and DAG storage [S2].
- **Measured Performance:** On a scene with 1.2 million tetrahedra: 19 ms rendering, 13 ms instant-NGP query, 143 ms backwards pass, 92 ms Delaunay triangulation computation [S1, unofficial].
- **Scaling:** The periodic update strategy (every 10 iterations) allows for efficient GPU acceleration by amortizing the cost of triangulation over multiple rendering steps [S1, unofficial].
- **Strengths:** Maintains geometric validity during optimization [S1, unofficial]. Efficient enough for real-time or near-real-time rendering when updates are periodic [S1, unofficial].
- **Limitations:** Numerical instability due to nearly cospherical points [G]. Full recomputation is expensive [S1, unofficial].
- **When to use:** When optimizing vertex positions in a tetrahedral mesh for volume rendering [S1, unofficial].
- **When not to use:** When static geometry is sufficient, or when real-time performance is critical and periodic updates are too slow [G].

## Background
The concept of adaptive Delaunay update is rooted in the need to maintain mesh quality during dynamic optimization processes in computer graphics [G]. The specific application to volume rendering with Radiance Meshes was introduced in the paper "Radiance Meshes for Volumetric Reconstruction" [S1, unofficial]. The hybrid rendering approach with multi-resolution meshes was proposed in "Segment-based tetrahedral meshing and rendering" [S2].
