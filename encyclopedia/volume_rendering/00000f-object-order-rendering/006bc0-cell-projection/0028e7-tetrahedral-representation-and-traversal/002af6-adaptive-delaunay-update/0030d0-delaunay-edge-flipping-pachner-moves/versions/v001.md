# Delaunay Edge Flipping (Pachner Moves)
Also called: Delaunay triangulation update via edge flipping, Edge flipping, Pachner moves

## Overview
Delaunay Edge Flipping is a local topological update method that transforms an arbitrary triangulation into a Delaunay triangulation by iteratively removing non-Delaunay edges. In 3D, these operations are specifically termed Pachner moves. It is chosen when a valid initial triangulation exists but requires refinement to satisfy the empty circumsphere property, particularly in dynamic scenarios where vertex perturbations violate the Delaunay condition. Unlike global reconstruction methods, it operates locally on existing connectivity.

## How it works
**Inputs and Outputs**
*   **Input:** A valid triangulation (tetrahedral mesh in 3D) where vertices may have been perturbed, potentially violating the Delaunay criterion.
*   **Output:** A Delaunay triangulation satisfying the empty circumsphere property.

**Data Structures**
*   **Mesh Connectivity:** Stores vertices, faces, and tetrahedra.
*   **Priority Queue:** Stores non-Delaunay edges, ordered by a violation metric.

**Steps**
1.  **Initialization:** Start with a valid triangulation. If vertices are moved by a small amount $\epsilon$, check for violations [S1, unofficial].
2.  **Identify Non-Delaunay Edges:** For each internal edge $e$ shared by two adjacent tetrahedra (or triangles in 2D), calculate the sum of the angles opposite to $e$ on the adjacent faces.
3.  **Calculate Priority:** Compute the priority value for edge $e$:
    $$ P(e) = \sum \theta_{\text{opposite}} - \pi $$
    If $P(e) > 0$, the edge is non-Delaunay [S2].
4.  **Flip Edge:** Remove the non-Delaunay edge $e$ and replace the two adjacent tetrahedra with two new tetrahedra connecting the remaining vertices. This is the Pachner move [S1, unofficial].
5.  **Update Priority Queue:** Add newly created edges to the priority queue if they violate the Delaunay condition.
6.  **Iterate:** Repeat steps 2-5 until the priority queue is empty. Convergence is guaranteed [S2].

**Pseudocode**
```python
def delaunay_edge_flipping(mesh):
    # mesh contains vertices, tetrahedra, and adjacency info
    priority_queue = PriorityQueue()
    
    # Initialize: find all non-Delaunay edges
    for edge in mesh.internal_edges:
        opposite_angles = sum_angles_opposite_to_edge(edge, mesh)
        priority = opposite_angles - math.pi
        if priority > 0:
            priority_queue.push(edge, priority)
            
    while not priority_queue.is_empty():
        edge, _ = priority_queue.pop()
        
        # Re-check validity as mesh topology changes
        if not is_edge_valid(edge, mesh):
            continue
            
        opposite_angles = sum_angles_opposite_to_edge(edge, mesh)
        priority = opposite_angles - math.pi
        
        if priority <= 0:
            continue
            
        # Perform Pachner move (flip)
        tet1, tet2 = edge.adjacent_tetrahedra
        new_tets = flip_tetrahedra(tet1, tet2, mesh.vertices)
        
        # Update mesh connectivity
        mesh.remove_tetrahedra([tet1, tet2])
        mesh.add_tetrahedra(new_tets)
        
        # Check new edges for violations
        for new_edge in new_tets.edges:
            if new_edge.is_internal():
                opp_angles = sum_angles_opposite_to_edge(new_edge, mesh)
                p = opp_angles - math.pi
                if p > 0:
                    priority_queue.push(new_edge, p)
                    
    return mesh
```

**Parameters**
*   $\epsilon$: Small vertex perturbation magnitude. Not given in the sources.
*   $\pi$: Mathematical constant pi.

**Edge Cases and Pitfalls**
*   **Nearly Cospherical Points:** Flips often involve points that are nearly cospherical because the vertex was already nearby the circumsphere boundary prior to the move. The geometric configurations before and after the flip share an almost identical circumsphere [S1, unofficial]. This can lead to numerical instability if precision is insufficient.
*   **Convergence:** The process is guaranteed to converge to a Delaunay triangulation [S2].

## Operating characteristics
*   **Time Complexity:** Not given in the sources. Depends on the number of flips and priority queue operations.
*   **Memory Complexity:** Linear in the number of vertices and tetrahedra for storing the mesh and priority queue.
*   **Strengths:** Local updates; guaranteed convergence; suitable for dynamic meshes where vertices move slightly [S1, unofficial].
*   **Limitations:** Requires a valid initial triangulation; numerical precision issues with nearly cospherical points [S1, unofficial].
*   **When to use:** When updating a mesh after vertex perturbation or when refining an existing triangulation locally.
*   **When not to use:** When starting from a set of unconnected points (use Delaunay Cover Refinement [13422-delaunay-cover-refinement.md] or Variational Isotropic Meshing [21467-variational-isotropic-meshing.md] instead).

## Background
The method is based on the principle that a triangulation is Delaunay if and only if no vertex lies inside the circumsphere of any tetrahedron [S1, unofficial]. In 3D, the edge flip operation is referred to as a Pachner move [S1, unofficial]. The specific priority queue implementation for ensuring convergence is described in [S2].
