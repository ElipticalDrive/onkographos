# Delaunay Edge Flipping (Pachner Moves)
Also called: Delaunay triangulation update via edge flipping, Edge flipping, Pachner moves

## Overview
Delaunay Edge Flipping is a method to form a Delaunay triangulation by flipping edges of triangles that are not Delaunay, specifically those where the circumsphere contains a vertex [S1, unofficial]. In 3D, these edge-flips are called Pachner moves [S1, unofficial]. It updates mesh connectivity to locally satisfy the Delaunay criterion by removing non-local Delaunay edges [S2].

## How it works
**Inputs and Outputs**
*   **Input:** A valid triangulation (tetrahedral mesh in 3D) where vertices may have been perturbed by a small amount $\epsilon$, potentially violating the Delaunay criterion [S1, unofficial].
*   **Output:** A Delaunay triangulation satisfying the empty circumsphere property [S2].

**Data Structures**
*   **Mesh Connectivity:** Stores vertices, faces, and tetrahedra with adjacency information [G].
*   **Priority Queue:** Stores non-Delaunay edges, ordered by a violation metric [S2].

**Steps**
1.  **Initialization:** Start with a valid triangulation. If vertices are moved by a small amount $\epsilon$, check for violations [S1, unofficial].
2.  **Identify Non-Delaunay Edges:** For each internal edge $e$ shared by two adjacent tetrahedra (or triangles in 2D), calculate the sum of the angles opposite to $e$ on the adjacent faces [S2].
3.  **Calculate Priority:** Compute the priority value for edge $e$ as the sum of the angles opposite to $e$ minus $\pi$ [S2]. An edge is non-local Delaunay if this sum exceeds $\pi$ [S2].
4.  **Flip Edge:** Remove the non-Delaunay edge $e$ and replace the two adjacent tetrahedra with two new tetrahedra connecting the remaining vertices. This is the Pachner move [S1, unofficial].
5.  **Update Priority Queue:** Add newly created edges to the priority queue if they violate the Delaunay condition [S2].
6.  **Iterate:** Repeat until all edges are Delaunay edges. Convergence is guaranteed [S2].

**Parameters**
*   $\epsilon$: Small vertex perturbation magnitude. Not given in the sources.
*   $\pi$: Mathematical constant pi.

**Edge Cases and Pitfalls**
*   **Nearly Cospherical Points:** Flips often involve points that are nearly cospherical because the vertex was already nearby the circumsphere boundary prior to the move. The geometric configurations before and after the flip share an almost identical circumsphere [S1, unofficial]. This can lead to numerical instability if precision is insufficient [G].
*   **Convergence:** The process is guaranteed to converge to a Delaunay triangulation [S2].

## Operating characteristics
*   **Time Complexity:** Not given in the sources. Depends on the number of flips and priority queue operations [G].
*   **Memory Complexity:** Linear in the number of vertices and tetrahedra for storing the mesh and priority queue [G].
*   **Strengths:** Local updates; guaranteed convergence; suitable for dynamic meshes where vertices move slightly [S1, unofficial].
*   **Limitations:** Requires a valid initial triangulation; numerical precision issues with nearly cospherical points [S1, unofficial].
*   **When to use:** When updating a mesh after vertex perturbation or when refining an existing triangulation locally [S2].
*   **When not to use:** When starting from a set of unconnected points (use Delaunay Cover Refinement [13422-delaunay-cover-refinement.md] or Variational Isotropic Meshing [21467-variational-isotropic-meshing.md] instead) [G].

## Background
The method is based on the principle that a triangulation is Delaunay if and only if no vertex lies inside the circumsphere of any tetrahedron [G]. In 3D, the edge flip operation is referred to as a Pachner move [S1, unofficial]. The specific priority queue implementation for ensuring convergence is described in [S2].
