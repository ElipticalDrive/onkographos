# Tetrahedral Strips and Fans

Also called: Bandwidth reduction for tetrahedral meshes, Rendering Pattern and Stripification, Tetrahedral Fans, Tetrahedral Strips, Tetrahedral primitives

## Overview
Tetrahedral Strips and Fans are specialized graphics primitives designed to address the bandwidth bottleneck between main memory and the graphics processor when rendering unstructured tetrahedral meshes [S1, unofficial][S2, unofficial]. They reduce the number of vertices required to transmit tetrahedra, achieving performance improvements similar to triangle strips and fans for triangle meshes [S1, unofficial][S2, unofficial]. Unlike triangle strips, which can be statically computed, tetrahedral decomposition is view-dependent, preventing the use of static strips or display lists when changing viewpoints [S2, unofficial]. These primitives enable order-independent transparency and volume scan conversion to be handled by graphics hardware, making a software sorting pass unnecessary [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A tetrahedral mesh (unstructured volume data) and a sequence of tetrahedra grouped into strips or fans.
*   **Output:** A stream of vertex data and primitive commands sent to the graphics hardware, resulting in rendered tetrahedra.

**Data Structures**
The method relies on two primary structures defined by the sequence of vertices:
1.  **Tetrahedral Fan:** A sequence of tetrahedra sharing a common edge.
2.  **Tetrahedral Strip:** A sequence of tetrahedra connected by shared faces, not necessarily sharing a single common edge.

**Numbered Steps**

1.  **Grouping:** Group tetrahedra into strips or fans using a stripification algorithm. The goal is to maximize the number of tetrahedra per strip to minimize vertex transmission overhead [S2, unofficial].
2.  **Vertex Transmission (Fan):**
    *   Transmit the first two vertices ($v_1, v_2$). These form the shared edge for the entire fan [S2, unofficial].
    *   Transmit the third and fourth vertices ($v_3, v_4$). These complete the first tetrahedron using vertices $v_1, v_2, v_3, v_4$ [S2, unofficial].
    *   For each subsequent vertex $k$ (where $k \ge 5$), transmit vertex $v_k$. This defines a new tetrahedron consisting of vertices $v_1, v_2, v_{k-1}, v_k$ [S2, unofficial].
3.  **Vertex Transmission (Strip):**
    *   Transmit the four vertices of the first tetrahedron ($v_1, v_2, v_3, v_4$) [S2, unofficial].
    *   For each subsequent tetrahedron, transmit a single vertex $v_k$.
    *   **Sequential Strip:** The new vertex $v_k$ always replaces the least-recently-used (LRU) vertex of the previous tetrahedron. Specifically, $v_k$ replaces $v_{k-4}$, forming the tetrahedron $v_{k-3}, v_{k-2}, v_{k-1}, v_k$ [S2, unofficial].
    *   **Generalized Strip:** There are no constraints on the direction of the next tetrahedron. The application must send a flag indicating which of the four vertices (slots 1, 2, 3, or 4) should be replaced by the following vertex [S2, unofficial]. This incurs an added expense of transmitting 2 bits for the flag per vertex [S2, unofficial].
4.  **Rendering:**
    *   For a fan: Call `glBegin(GL_TET_FAN_EXT)`, issue `glVertex` and `glColor` calls for the vertices, then `glEnd()` [S2, unofficial].
    *   For a sequential strip: Call `glBegin(GL_SEQUENTIAL_TET_STRIP_EXT)`, issue `glVertex` calls, then `glEnd()` [S2, unofficial].
    *   For a generalized strip: Call `glBegin(GL_GENERAL_TET_STRIP_EXT)`. Before each new vertex, call `glReplaceVertexEXT(REPLACE_VERTEX_EXT_N)` where $N \in \{1, 2, 3, 4\}$ specifies the slot to replace, then issue `glVertex` [S2, unofficial].

**Formulas**
*   **Fan Transmission Cost:** For a fan comprising $N$ tetrahedra, only $N+2$ vertices are transmitted [S2, unofficial].
*   **Strip Transmission Cost:** For a strip comprising $N$ tetrahedra, $N+4$ vertices are transmitted (plus 2 bits per vertex for generalized strips) [S2, unofficial].
*   **Transmission Rate:** The primitives achieve transmission rates approaching 1.2 vertices per tetrahedron [S2, unofficial].
*   **Strip Length Metrics:**
    *   $t_{mean}$: Mean number of tetrahedra in each strip.
    *   $t_{med}$: Median number of tetrahedra in each strip.
    *   $t_{std}$: Standard deviation of the number of tetrahedra in each strip.
    *   $t_{max}$: Maximum number of tetrahedra in a strip.
    *   $v_{pert}$: Number of vertices per tetrahedron (average) [S2, unofficial].

**Parameters**
*   **Strip Length:** New techniques for generating tetrahedral strips achieve, on average, strip lengths of 17 on representative datasets [S1, unofficial][S2, unofficial].
*   **Performance:** The combined effect of the architecture and new primitives is a 72 to 85 times increase in performance over triangle graphics hardware approaches [S1, unofficial].
*   **Bandwidth:** Rendering tetrahedra requires 50-60% more bandwidth than rendering individual triangles even with fans [S2, unofficial].

**Edge Cases and Pitfalls**
*   **View Dependency:** Unlike triangle strips, tetrahedral decomposition is view-dependent. Static strips or display lists cannot be used when changing the viewpoint from frame to frame [S2, unofficial].
*   **Generalized Strip Overhead:** Generalized strips require explicit flags for vertex replacement, adding 2 bits per vertex to the transmission cost [S2, unofficial].
*   **Algorithm Complexity:** Generating tetrahedral strips requires computing a correctly-ordered list of vertex replacements, often involving edge chain analysis [S1, unofficial].

**Pseudocode**

```python
# Example: Rendering a Sequential Tetrahedral Strip
def render_sequential_strip(vertices):
    """
    Renders a sequence of tetrahedra using the GL_SEQUENTIAL_TET_STRIP_EXT primitive.
    vertices: List of vertex objects (v1, v2, v3, ...).
    """
    glBegin(GL_SEQUENTIAL_TET_STRIP_EXT)
    
    # First tetrahedron: v1-v2-v3-v4
    glVertex(vertices[0])
    glVertex(vertices[1])
    glVertex(vertices[2])
    glVertex(vertices[3])
    
    # Second tetrahedron: v2-v3-v4-v5 (v5 replaces v1)
    glVertex(vertices[4])
    
    # Third tetrahedron: v3-v4-v5-v6 (v6 replaces v2)
    glVertex(vertices[5])
    
    # Fourth tetrahedron: v4-v5-v6-v7 (v7 replaces v3)
    glVertex(vertices[6])
    
    # Fifth tetrahedron: v5-v6-v7-v8 (v8 replaces v4)
    glVertex(vertices[7])
    
    glEnd()

# Example: Rendering a Generalized Tetrahedral Strip
def render_generalized_strip(vertices, replacement_flags):
    """
    Renders a sequence of tetrahedra using the GL_GENERAL_TET_STRIP_EXT primitive.
    vertices: List of vertex objects.
    replacement_flags: List of integers (1, 2, 3, or 4) indicating which slot 
                       (1-indexed) is replaced by the subsequent vertex.
    """
    glBegin(GL_GENERAL_TET_STRIP_EXT)
    
    # First tetrahedron: v1-v2-v3-v4
    glVertex(vertices[0]) # Stored in slot 1
    glVertex(vertices[1]) # Stored in slot 2
    glVertex(vertices[2]) # Stored in slot 3
    glVertex(vertices[3]) # Stored in slot 4
    
    # Next vertex v5 replaces slot 1
    glReplaceVertexEXT(REPLACE_VERTEX_EXT_1)
    glVertex(vertices[4]) # Goes into slot 1, draws tet v2-v3-v4-v5
    
    # Next vertex v6 replaces slot 1
    glReplaceVertexEXT(REPLACE_VERTEX_EXT_1)
    glVertex(vertices[5]) # Goes into slot 1, draws tet v3-v4-v5-v6
    
    # Next vertex v7 replaces slot 3
    glReplaceVertexEXT(REPLACE_VERTEX_EXT_3)
    glVertex(vertices[6]) # Goes into slot 3 replacing v5, draws v3-v4-v6-v7
    
    glEnd()

# Example: Rendering a Tetrahedral Fan
def render_tetrahedral_fan(vertices):
    """
    Renders a sequence of tetrahedra sharing a common edge (v1, v2).
    vertices: List of vertex objects.
    """
    glBegin(GL_TET_FAN_EXT)
    
    # Shared edge
    glVertex(vertices[0])
    glVertex(vertices[1])
    
    # First tetrahedron: v1-v2-v3-v4
    glVertex(vertices[2])
    glVertex(vertices[3])
    
    # Second tetrahedron: v1-v2-v4-v5
    glVertex(vertices[4])
    
    # Third tetrahedron: v1-v2-v5-v6
    glVertex(vertices[5])
    
    # Fourth tetrahedron: v1-v2-v6-v7
    glVertex(vertices[6])
    
    glEnd()
```

## Subtopics

### [Greedy Strip Generation Algorithm](2626-greedy-strip-generation-algorithm.md)
The Greedy Strip Generation Algorithm converts a tetrahedral mesh into a sequence of tetrahedral strips and fans to optimize data transmission to graphics hardware. It addresses the bandwidth bottleneck between main memory and the GPU by reducing the number of vertices required to render each tetrahedron. Unlike triangle strips, tetrahedral strips require computing a correctly-ordered list of vertex replacements from the tetrahedra in the strip, often involving edge chain analysis. The baseline algorithm is distinguished by its simplicity: it selects the first available unvisited neighbor without complex heuristics, serving as the foundational reference for more advanced variants.

## Operating characteristics
**Time and Memory Complexity**
*   **Stripification Time:** The time complexity depends on the stripification algorithm used. The baseline greedy algorithm is simple, but more advanced variants may involve complex heuristics [S1, unofficial].
*   **Memory:** The method reduces the number of vertices transmitted, thereby reducing memory bandwidth usage. The transmission rate approaches 1.2 vertices per tetrahedron [S2, unofficial].

**Measured Performance**
*   **Strip Lengths:** Method 2 achieves the best results with mean strip lengths of 29 tetrahedra per strip and median lengths over 10 tetrahedra per strip [S2, unofficial].
    *   **Phoenix Dataset (Method 2):** 441 strips, $t_{mean}=29.4$, $t_{med}=10$, $t_{std}=46.4$, $t_{max}=347$, $v_{pert}=1.10$ [S2, unofficial].
    *   **Langley Dataset (Method 2):** 1432 strips, $t_{mean}=49.0$, $t_{med}=13$, $t_{std}=86.8$, $t_{max}=865$, $v_{pert}=1.06$ [S2, unofficial].
*   **Comparison of Methods:**
    *   Method 2: Mean 29.4 (Phoenix), 49.0 (Langley) [S2, unofficial].
    *   Method 4: Mean 15.4 (Phoenix), 18.6 (Langley) [S2, unofficial].
    *   Method 1: Mean 12.9 (Phoenix), 14.8 (Langley) [S2, unofficial].
    *   Method 3: Mean 10.5 (Phoenix), 14.3 (Langley) [S2, unofficial].
*   **Overall Performance:** The combined effect of the architecture and new primitives is a 72 to 85 times increase in performance over triangle graphics hardware approaches [S1, unofficial].

**Scaling**
*   The method scales with the number of tetrahedra, as longer strips reduce the per-tetrahedron overhead. Future work includes performing stripification on culled datasets to get the greatest advantage [S2, unofficial].

**Strengths and Limitations**
*   **Strengths:** Reduces bandwidth bottleneck; enables order-independent transparency and volume scan conversion in hardware; makes software sorting unnecessary; achieves significant performance improvements (72-85x) [S1, unofficial].
*   **Limitations:** View-dependent decomposition prevents static strips; generalized strips incur overhead for vertex replacement flags; based on projected tetrahedra algorithm, inheriting its inaccuracies [S2, unofficial].

**When to Use**
*   Use for interactive tetrahedral volume rendering where bandwidth is a bottleneck [S2, unofficial].
*   Use when order-independent transparency is required and hardware support for the primitives is available [S1, unofficial].

**When Not to Use**
*   Do not use if the graphics hardware does not support the specific extensions (`GL_TET_FAN_EXT`, `GL_SEQUENTIAL_TET_STRIP_EXT`, `GL_GENERAL_TET_STRIP_EXT`) [S2, unofficial].
*   Do not use if static rendering is sufficient and the view does not change, as triangle strips may be more appropriate for triangle meshes [S2, unofficial].

## Background
**Origin**
The primitives were introduced to address the bandwidth bottleneck between main memory and the graphics processor in the context of interactive tetrahedral volume rendering [S1, unofficial][S2, unofficial]. The work is associated with the "An Architecture For Interactive Tetrahedral Volume Rendering" paper [S2, unofficial].

**History and Development**
The method builds on the shared principles of [Tetrahedral representation and traversal](4396-tetrahedral-representation-and-traversal.md). It was developed to provide the same advantages for volume data that triangle-processing hardware provides for surfaces, specifically by moving computations for order-independent transparency and volume scan conversion from the CPU to the graphics hardware [S1, unofficial]. The authors noted that while triangle strips are well-established, tetrahedral meshes require new primitives due to view-dependent decomposition [S2, unofficial].

**Usage**
The primitives are used in the proposed architecture for interactive tetrahedral volume rendering [S2, unofficial]. They are also useful for compressing unstructured datasets for storage and transmission, as stripiﬁcation may improve vertex cache management when rendering on existing graphics cards that support vertex caching and updatable vertex arrays [S2, unofficial].
