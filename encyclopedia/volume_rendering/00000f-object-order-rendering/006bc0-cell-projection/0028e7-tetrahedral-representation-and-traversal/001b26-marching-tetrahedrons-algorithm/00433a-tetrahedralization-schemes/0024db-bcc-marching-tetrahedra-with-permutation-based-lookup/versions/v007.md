# BCC Marching Tetrahedra with Permutation-Based Lookup

Also called: BCC MT with Reference Tetrahedron, GPU BCC Isosurface Extraction

## Overview
This method extracts explicit, connected triangle mesh isosurfaces from Body-Centered Cubic (BCC) volume datasets on a GPU [S1]. It solves the problem of large lookup tables and complex branching in standard Marching Tetrahedra by using a single reference tetrahedron and applying 3D permutation transformations to handle all six cell types [S1]. Unlike the triangle-soup output of classic MT, this method produces a manifold mesh with shared vertices, enabling efficient downstream applications such as curvature rendering [S1]. It builds on [Tetrahedralization Schemes](10948-tetrahedralization-schemes.md) by defining a specific BCC connectivity and GPU-optimized data structures [S1].

## How it works
**Inputs:**
*   A 3D scalar field $S$ defined on a BCC lattice [S1].
*   An isosurface threshold $T$ [S1].
*   The dimensions of the volume grid $(W, H, D)$ [S1].

**Outputs:**
*   A Vertex Buffer containing intersection points $P$ [S1].
*   An Index Buffer defining the connectivity of triangles [S1].

**Data Structures:**
1.  **Intersection Buffer:** Stores 5-bit keys indicating which edges of a cell intersect the isosurface. The size is dynamic, equal to the number of intersecting cells [S1].
2.  **Reference Lookup Tables:** Stored in GPU Constant Memory [S1].
    *   **Table 3 (Connectivity):** Defines which edges form triangles for each of the 16 possible intersection patterns (5-bit key) for the *Reference Tetrahedron* [S1].
    *   **Table 4 (Reference Edges):** Defines the 6 edges of the reference tetrahedron using Lattice Offsets and Directions [S1].

**Reference Tetrahedron Edges (Table 4):**
The reference tetrahedron has 6 edges. Each edge $e_i$ is defined by a lattice offset $(o_x, o_y, o_z)$ and a direction vector $(d_x, d_y, d_z)$:

| Edge | Lattice Offset | Direction |
| :--- | :--- | :--- |
| e0 | $(0, 0, 0)$ | $(-1, 1, 1)$ |
| e1 | $(-1, 1, 1)$ | $(1, -1, 1)$ |
| e2 | $(0, 0, 2)$ | $(1, 1, -1)$ |
| e3 | $(0, 0, 0)$ | $(1, 1, 1)$ |
| e4 | $(0, 0, 0)$ | $(0, 0, 2)$ |
| e6 | $(-1, 1, 1)$ | $(2, 0, 0)$ |

*Note: The source lists 'e6' as the sixth edge, implying indices 0-5 or 0-6 with one missing label, but explicitly lists 6 entries [S1].*

**Algorithm Steps:**

1.  **Cell Classification and Permutation:**
    The BCC lattice contains 6 distinct cell types. Instead of storing lookup tables for all 6 types, the algorithm stores only the Reference Tetrahedron's connectivity [S1]. For any other cell type, the lattice offsets and edge directions from the reference table are transformed using a 3D permutation matrix specific to that cell type [S1]. This permutation aligns the local tetrahedral coordinate system with the global lattice [S1].

2.  **Intersection Detection (Marking Phase):**
    *   Iterate through all BCC cells.
    *   Evaluate the scalar field values at the 4 vertices of the tetrahedron.
    *   Determine the intersection pattern (5-bit key) based on the signs of $(S_i - T)$ for each vertex.
    *   If the pattern indicates intersection, store the 5-bit key in the Intersection Buffer.
    *   *Optimization:* Use space skipping (min/max blocks) to avoid processing empty cells [S1].

3.  **Vertex Buffer Generation:**
    *   Create one thread per entry in the Intersection Buffer.
    *   The thread reads the 5-bit key to determine the specific edge(s) intersecting the isosurface for the reference tetrahedron (using Table 3).
    *   Apply the permutation transformation corresponding to the current cell type to the reference edge's Lattice Offset and Direction [S1].
    *   Calculate the opposite lattice point: $P_{opp} = P_{current} + \text{Transformed Offset} + \text{Transformed Direction}$.
    *   Read scalar values $S_1$ and $S_2$ at the two ends of the intersected edge.
    *   Compute the intersection point $P$ using linear interpolation:
        $$ P = V_1 + \frac{T - S_1}{S_2 - S_1} (V_2 - V_1) $$
        where $V_1, V_2$ are the 3D coordinates of the lattice vertices at the edge endpoints [S1].
    *   Store $P$ in the Vertex Buffer.

4.  **Triangle Buffer (Index) Generation:**
    *   Create one thread per intersecting cell.
    *   Determine the cell type and the 5-bit intersection key.
    *   Use the Reference Lookup Table (Table 3) to identify which edges form the triangles for this pattern.
    *   Apply the cell-specific permutation to the edge indices/offsets to map them to the actual lattice edges [S1].
    *   Generate the indices for the triangle vertices using the positions stored in the Vertex Buffer.
    *   Store the indices in the Index Buffer.

**Pseudocode:**

```python
# Constants
NUM_EDGES_REF = 6
# Table 4: Reference Tetrahedron Edges
# Each entry: (lattice_offset_x, lattice_offset_y, lattice_offset_z, dir_x, dir_y, dir_z)
REF_EDGES = [
    (0, 0, 0, -1, 1, 1),   # e0
    (-1, 1, 1, 1, -1, 1),  # e1
    (0, 0, 2, 1, 1, -1),   # e2
    (0, 0, 0, 1, 1, 1),    # e3
    (0, 0, 0, 0, 0, 2),    # e4
    (-1, 1, 1, 2, 0, 0)    # e6
]

# Table 3: Connectivity for Reference Tetrahedron
# Maps 5-bit key (0-31) to a list of edge indices that form triangles
# Note: Exact mapping depends on the specific reference tetrahedron definition in [S1]
REF_CONNECTIVITY = {
    0: [],
    1: [0],
    2: [1],
    3: [0, 1],
    # ... other keys ...
    31: []
}

# Permutation tables for the 6 BCC cell types
# Each permutation is a tuple of 3 axis indices (0,1,2) representing the new basis
CELL_PERMUTATIONS = [
    (0, 1, 2),  # Cell Type 0: Identity
    (1, 2, 0),  # Cell Type 1: Rotate axes
    (2, 0, 1),  # Cell Type 2: Rotate axes
    (0, 2, 1),  # Cell Type 3: Swap Y/Z
    (1, 0, 2),  # Cell Type 4: Swap X/Y
    (2, 1, 0)   # Cell Type 5: Swap X/Z
]

def apply_permutation(offset, direction, perm_axes):
    """
    Applies 3D permutation to lattice offset and direction vectors.
    perm_axes is a tuple (p0, p1, p2) mapping new axes to old axes.
    """
    new_offset = (offset[perm_axes[0]], offset[perm_axes[1]], offset[perm_axes[2]])
    new_direction = (direction[perm_axes[0]], direction[perm_axes[1]], direction[perm_axes[2]])
    return new_offset, new_direction

def linear_interpolate(v1, v2, s1, s2, threshold):
    """
    Computes intersection point P on edge V1-V2 given scalar values S1, S2 and threshold T.
    """
    denom = s2 - s1
    if abs(denom) < 1e-6:
        return None  # Degenerate edge, skip
    t = (threshold - s1) / denom
    return (v1[0] + t * (v2[0] - v1[0]),
            v1[1] + t * (v2[1] - v1[1]),
            v1[2] + t * (v2[2] - v1[2]))

def mark_and_generate_vertices(grid, threshold, grid_dims):
    """
    Kernel 1: Marks intersecting cells and generates vertex buffer.
    Returns: intersection_buffer (list of keys), vertex_buffer (list of points)
    """
    intersection_buffer = []
    vertex_buffer = []
    
    # Iterate over all cells (excluding boundary to avoid out-of-bounds)
    for z in range(grid_dims[2] - 1):
        for y in range(grid_dims[1] - 1):
            for x in range(grid_dims[0] - 1):
                # Evaluate scalar field at 4 vertices of the tetrahedron
                s0 = grid[x][y][z]
                s1 = grid[x+1][y][z]
                s2 = grid[x][y+1][z]
                s3 = grid[x][y][z+1]
                
                # Determine intersection pattern (5-bit key)
                key = 0
                if s0 < threshold: key |= 1
                if s1 < threshold: key |= 2
                if s2 < threshold: key |= 4
                if s3 < threshold: key |= 8
                
                if key != 0 and key != 15:
                    intersection_buffer.append(key)
                    
                    # Determine cell type (simplified as 0 for reference tetrahedron)
                    cell_type = 0
                    perm = CELL_PERMUTATIONS[cell_type]
                    
                    # Get intersected edges from connectivity table
                    edge_indices = REF_CONNECTIVITY.get(key, [])
                    
                    for idx in edge_indices:
                        if idx < len(REF_EDGES):
                            offset, direction = REF_EDGES[idx][:3], REF_EDGES[idx][3:]
                            new_offset, new_direction = apply_permutation(offset, direction, perm)
                            
                            # Calculate opposite lattice point
                            v1 = (x + new_offset[0], y + new_offset[1], z + new_offset[2])
                            v2 = (v1[0] + new_direction[0], v1[1] + new_direction[1], v1[2] + new_direction[2])
                            
                            # Read scalar values at edge endpoints
                            s_v1 = grid[v1[0]][v1[1]][v1[2]]
                            s_v2 = grid[v2[0]][v2[1]][v2[2]]
                            
                            # Linear interpolation
                            p = linear_interpolate(v1, v2, s_v1, s_v2, threshold)
                            if p is not None:
                                vertex_buffer.append(p)
                                
    return intersection_buffer, vertex_buffer

def generate_triangle_indices(intersection_buffer, grid_dims):
    """
    Kernel 2: Generates index buffer for triangle connectivity.
    Returns: index_buffer (list of vertex indices)
    """
    index_buffer = []
    vertex_offset = 0
    
    for key in intersection_buffer:
        # Determine cell type (simplified as 0 for reference tetrahedron)
        cell_type = 0
        perm = CELL_PERMUTATIONS[cell_type]
        
        # Get connectivity edges for this key in the reference tetrahedron
        ref_edge_indices = REF_CONNECTIVITY.get(key, [])
        
        # Apply permutation to get actual edge indices/offsets
        # In GPU implementation, this maps reference edge indices to vertex buffer positions
        for idx in ref_edge_indices:
            if idx < len(REF_EDGES):
                # Each intersected edge generates one vertex in the vertex buffer
                # The index is calculated based on the order of vertex generation
                vertex_idx = vertex_offset + (idx * 2) # Simplified mapping [G]
                index_buffer.append(vertex_idx)
                
        vertex_offset += len(ref_edge_indices)
        
    return index_buffer
```

**Parameters:**
*   **Isosurface Threshold $T$:** User-defined [S1].
*   **Memory Allocation:** Pre-allocate a sufficiently large fixed memory space for the triangle mesh, as the mesh size is dynamic and depends on the isosurface shape [S1].

**Edge Cases and Pitfalls:**
*   **Dynamic Mesh Size:** The extracted triangle mesh size varies with the isosurface shape. Pre-calculating the exact size is difficult. For iterative processes (e.g., simulations), pre-allocating a large fixed buffer is more efficient than reallocating every frame [S1].
*   **Space Skipping Ineffectiveness:** The method relies on space skipping (empty space culling). This is ineffective for datasets with high noise or complex isosurfaces with few empty spaces [S1].
*   **GPU Memory Usage:** The method is more complex and requires more GPU memory than existing methods due to the index buffer and permutation logic [S1].

## Operating characteristics
**Time and Memory Complexity:**
*   **Time:** At low resolutions, the method is >2x slower than classic MT due to overhead from creating the triangle mesh structure and low space skipping rates [S1]. At high resolutions, it is significantly faster (up to ~5x) due to high space skipping rates. The time increase with resolution is small [S1].
*   **Memory:** Requires more GPU memory than existing methods due to the index buffer and constant memory for lookup tables [S1].

**Measured Performance:**
*   **Hardware:** Intel Core i5 2500 CPU @ 3.30GHz and NVIDIA GeForce RTX 2080 Ti GPU [S1].
*   **Datasets:** Genus-3 (G1-G5) and Three-Tori (T1-T5) with resolutions ranging from $128^3$ to $1024 \times 512 \times 512$ (Genus-3) and $128^3$ to $512^3$ (Three-Tori) [S1].
*   **Results:** At high resolutions (e.g., G5, T5), the method shows up to ~5x speedup over classic MT [S1].

**Strengths and Limitations:**
*   **Strengths:** Produces a connected manifold mesh with shared vertices, reducing data size and enabling efficient indexing. High performance on high-resolution data with significant empty space [S1].
*   **Limitations:** High memory usage. Ineffective on noisy data or data with complex, space-filling isosurfaces lacking empty space. More complex implementation than classic MT [S1].

**When to Use:**
*   High-resolution BCC volume data with significant empty space [S1].
*   Applications requiring manifold meshes (e.g., curvature rendering) [S1].

**When Not to Use:**
*   Low-resolution data where overhead dominates [S1].
*   Noisy data or data with complex, space-filling isosurfaces where space skipping is ineffective [S1].

## Background
**Origin:**
The method was introduced in a 2020 paper on real-time GPU techniques for BCC volume datasets [S1]. It aims to provide a real-time GPU technique for extracting mesh isosurfaces from BCC volume datasets [S1].

**History and Development:**
The method builds on the principles of Marching Tetrahedra, specifically adapting them to the BCC lattice structure [S1]. It addresses the limitation of large lookup tables in standard BCC MT by using permutation transformations [S1]. The extracted mesh can be used for curvature rendering, leveraging Griffin's technique to estimate Gaussian curvature on the shared vertices of the triangle mesh [S1].

**Applications:**
*   Curvature rendering (Gaussian curvature estimation) [S1].
*   Real-time visualization of high-resolution BCC volume data [S1].
